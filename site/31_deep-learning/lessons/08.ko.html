소단원 8.1

잔차연결

새 층이 필요 없을 때 입력을 그대로 통과시키는 길을 둘 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 벡터의 성분별 합

  • 합성함수와 미분

학습 목표

  • 잔차 함수와 최종 출력을 구별한다.

  • 합산 차원과 기울기 경로 조건을 확인한다.

차원을 맞춘 shortcut은 입력의 모든 방향을 보존할까?

앞 본문의 항등 shortcut은 입력을 그대로 더한다. 길이 2에서 길이 3으로 바꾸는 자체 projection P=[[1,0],[0,1],[1,1]]은 다른 함수다. x=(2,−1)이면 Px=(2,−1,1)이고 잔차 F(x)=(1,2,0)을 더한 합산 직후 출력은 (3,1,1)이다. 여기서는 bias가 없는 학습 투영을 가정하므로 P의 원소 여섯 개가 추가 매개변수다. 합산 뒤 활성화는 이 첫 계산에 포함하지 않는다.

차원이 맞는다는 사실만으로 정보 보존이 보장되지는 않는다. 별도 Q=[[1,1],[2,2],[0,0]]도 같은 출력 길이 3을 만들지만 Q(1,−1)=(0,0,0)이다. 잔차를 0으로 고정하면 x와 x+(1,−1)은 같은 출력을 낸다. Q의 첫 두 열이 같은 까닭에 사라지는 입력 방향이 있다. 투영 뒤 잔차가 그 방향을 구별할 가능성과 Q 자체의 손실은 나누어 판단한다.

직접 미분 항도 전체 블록의 크기를 고정하지 않는다. 자체 선형 잔차 F(x1,x2)=(2*x2,0)이면 합산의 미분 A=[[1,2],[0,1]]이다. 입력 방향 (0,1)은 (2,1)로 바뀌어 길이가 1에서 √5로 커진다. 반대로 스칼라 잔차 F(x)=−x/2를 k개 이어 붙이면 전체 미분은 (1/2)^k다. 아래는 유한 선형 모형의 계산이며 실제 깊은 네트워크의 학습 안정성이나 성능을 측정한 결과가 아니다.

먼저 확인할 개념
  • 항등 합산과 projection

    앞 본문의 같은 모양 조건을 만족한 뒤에도 투영 자체의 함수와 잃는 방향을 분석한다.

  • 직접 항과 전체 Jacobian

    앞 본문의 I+JF 식을 행렬 방향과 여러 블록의 곱으로 확장한다.

입력에 보정치를 더한다

잔차 블록은 y=x+F(x)처럼 원래 입력을 합산점으로 보낸다. F는 목표 전체 H가 아니라 H−x라는 보정치를 학습하는 경로다. 잔차라는 말은 훈련 오차값 하나를 더한다는 뜻이 아니다.

F=0이면 합산 직후 y=x다. 하지만 원 논문의 블록은 합산 뒤 ReLU를 두기도 하므로 전체 블록은 ReLU(x)가 된다. 계산할 지점을 명시해야 항등이라는 말을 정확히 쓸 수 있다.

길을 합치려면 모양이 맞아야 한다

성분별 덧셈에는 같은 모양이 필요하다. 채널 수나 공간 크기를 바꾸면 projection S(x)를 사용해 y=S(x)+F(x)로 맞출 수 있다. 학습 projection은 추가 매개변수와 계산을 가진다.

shortcut은 입력의 정보를 직접 전달한다. 그러나 깊게 만들었다고 항상 정확도가 오르는 것은 아니다. 학습률·자료·과적합과 함께 독립 평가해야 한다.

직접 기울기 경로와 그 한계

미분 가능한 합산의 Jacobian은 I+J_F다. 이전 입력으로 가는 직접 항 I가 있지만 J_F가 −I이면 합은0이다. 모든 기울기 소실을 무조건 제거한다는 정리가 아니다.

합산 뒤 활성함수와 여러 블록의 연쇄도 실제 역전파에 포함된다. 아래는 작은 수학 모형이며 신경망 학습을 실행한 성능 결과가 아니다.

소단원 8.2

batch·layer normalization

같은 숫자표를 열별로 정리할 때와 행별로 정리할 때 왜 다를까?

준비 개념과 학습 목표

준비 개념

  • 평균과 분산

  • 배치·특징 축

  • 제곱근

학습 목표

  • BN과 LN의 집계 축을 구별한다.

  • train/eval 통계와 epsilon·affine을 설명한다.

정규화에서 고정되는 축과 움직이는 상태는 무엇인가?

같은 샘플을 다른 배치에 넣는 것부터 비교하자. epsilon=1, gamma=1, beta=0인 2차원 BN의 한 채널에서 배치 [1,5]는 평균 3, forward 분산 4이므로 첫 값은 −2/√5다. 배치 [1,9]의 첫 값은 −4/√17이다. 입력 값 1이 같아도 함께 집계한 자료가 바뀌면 학습 모드 출력은 달라진다. 이 두 배치는 각각 독립된 forward 비교이며 running 통계 갱신과는 따로 계산한다.

축 이름은 shape와 함께 읽는다. (N,C,L)=(1,2,2)의 입력에서 채널 0은 [1,3], 채널 1은 [5,7]이다. BN1d는 각 채널의 N,L 두 칸을 집계한다. LayerNorm(2)는 마지막 L 두 칸을 집계하므로 이 특별한 입력에서는 같은 정규화 값이 나온다. LayerNorm((2,2))는 C,L 네 칸을 함께 집계하여 평균 4와 분산 5를 사용한다. 같은 LN이라는 이름으로 서로 다른 normalized_shape를 섞지 않는다.

running 갱신은 출력에 쓴 분산과도 다르다. 독립 사례의 초기 running_mean=0, running_var=1, momentum=1/4에서 [1,5] 학습 forward를 한 번 처리하자. 평균은 3, biased 분산은 4, unbiased 분산은 8이다. 새 누적 평균은 3/4이고 누적 분산은 11/4이다. 이 상태의 eval에서 x=1은 (1−3/4)/√(11/4+1)=1/(2√15)가 된다. epsilon=1과 momentum=1/4는 손계산 설정이며 라이브러리 기본값이 아니다.

먼저 확인할 개념
  • 집계 축과 forward 분산

    앞 본문의 (N,C) 열과 LN 행 계산을 (N,C,L) 및 마지막 여러 축으로 확장한다.

  • 누적 통계와 eval

    앞 본문의 biased/unbiased 구별과 running momentum을 한 번의 상태 갱신에 적용한다.

어느 축의 평균인가

2차원 (N,C)에서 BN은 특징 열마다 N개 샘플을 집계한다. LN의 normalized_shape=C는 샘플마다 마지막 C개 특징을 집계한다. 이름보다 실제 축을 먼저 표시하자.

일반 LN은 마지막 지정된 여러 축을 쓰며 BN1d의 (N,C,L)은 채널별 N,L을 집계한다. 모든 텐서에서 LN은 행 하나만 본다고 외우면 틀린다.

분산·작은 상수·학습 보정

계산은 (x−평균)/sqrt(분산+epsilon)에 gamma를 곱하고 beta를 더한다. epsilon>0은 0분산에서도 분모를 양수로 만든다. 학습 보정 후 출력이 언제나 평균0·분산1인 것은 아니다.

PyTorch forward 분산은 집계 원소 수로 나누는 biased 추정이다. BN running variance는 unbiased 추정을 사용한다. 아래는 gamma=1,beta=0인 종이 계산이다.

학습과 평가 모드

기본 BN은 학습 배치 통계로 정규화하고 running 통계를 갱신하며 eval에서 누적 통계를 쓴다. track_running_stats=False이면 eval도 배치 통계를 쓴다. BN momentum은 optimizer momentum과 다른 누적 갱신 비율이다.

LN은 train과 eval 모두 입력의 지정 축 통계를 쓴다. 정규화층은 자료 분할을 대신하지 않으며 과적합 방지를 보장하지 않는다. 작은 배치의 변동과 집계 원소 수도 살펴야 한다.

동결한 가중치와 고정된 특징은 같은 조건인가?

고정 특징 추출 목표를 상태별로 적어 보자. 앞 매개변수의 requires_grad=False, optimizer가 실제 보유한 매개변수 객체, BN의 running 통계, dropout의 실행 모드는 서로 다른 항목이다. 앞 가중치를 동결해도 학습 모드 BN이 앞 소단원의 [1,5]를 처리하면 누적 상태는 변한다. epsilon=1, gamma=1, beta=0과 지정 누적 상태를 사용하면 같은 x=1의 eval 특징은 처리 전 1/√2에서 처리 후 1/(2√15)로 바뀐다. 이는 새 가중치를 학습했다는 증거가 아니라 명시된 buffer 상태의 변화다.

새 head를 연결할 때는 이름만 확인하지 않는다. 고정 특징 길이 2에서 클래스 3개인 bias 포함 Linear head의 매개변수는 3×2+3=9개다. 이전 head로 optimizer를 만든 뒤 새 head 객체를 대입하면 optimizer가 보관한 객체와 현재 forward에서 사용한 객체가 달라질 수 있다. 여기서는 optimizer가 자동으로 교체된 속성을 다시 탐색하지 않는다는 소유 목록 조건을 둔다. 새 head 생성 후 그 객체의 매개변수로 optimizer를 구성하고 실제 객체 대응을 확인하는 계획이 필요하다.

eval은 미분 기록을 끄는 명령이 아니다. 고정된 앞부분 뒤의 head를 학습하는 계획에서는 앞부분을 eval로 두면서 head 계산은 gradient를 기록할 수 있다. 반대로 앞부분부터 head와 loss까지 모두 no_grad로 둘러싸면 head 학습에 필요한 기록도 사라진다. 더 앞의 모듈을 학습해야 하는 중간 동결층이라면 그 층을 통과하는 입력 미분 경로도 유지해야 한다. 아래 모든 예제는 작은 수학 모형과 구성 계획이며 실제 optimizer·다운로드·학습은 미수행이다.

먼저 확인할 개념
  • 동결 범위와 optimizer

    앞 본문의 새 head/고정 추출에서 현재 객체 목록과 실행 범위를 더 정밀하게 확인한다.

  • BN buffer와 실행 모드

    앞 본문의 running 통계 변화가 가중치 동결과 독립이라는 점을 구체 수치로 연결한다.

무엇을 가져오는가

다른 과제에서 배운 매개변수나 특징을 새 과제의 시작점으로 쓰는 것이 전이학습이다. 입력 표현·의미의 관련성과 사전학습 자료·사용 조건을 확인하자. 관련이 약하면 성능이 악화되는 음의 전이도 가능하다.

기존1000종 출력은 새3종 레이블과 같지 않다. 특징 추출 부분과 새 head를 구별하고 출력 크기와 레이블 대응을 다시 정의한다.

고정 추출과 미세 조정

고정 특징 추출은 앞 매개변수를 동결하고 새 head만 학습한다. fine tuning은 일부 또는 전체 사전학습 가중치도 새 자료로 갱신한다. 학습 가능한 변수와 optimizer 범위를 함께 확인한다.

requires_grad=False는 해당 매개변수 gradient 계산 제약이다. BN running buffer나 dropout 모드를 자동 고정하지 않는다. 고정 추출 목적에 맞춰 train/eval 상태도 별도로 설계한다.

새 데이터의 증거

기존 입력 크기·범위·정규화 전처리를 확인한다. 새 훈련 자료에서 결정한 변환을 검증·시험에 적용하되 시험 레이블을 보고 모델이나 epoch를 고르면 최종 평가가 오염된다.

head부터 시작해 검증 실패 유형을 보고 갱신 범위를 조정할 수 있다. 아래 산술은 성능 개선 실험이 아니며 실제 다운로드·학습·학생 검증은 미수행이다.

비교할 점

requires_grad=False와 출력 불변을 같은 말로 쓴 보고와 비교한다.

새 head와 낡은 optimizer

optimizer가 옛 head H0의 객체만 보유한 상태에서 새 H1으로 교체했다. forward는 H1을 사용한다. 자동 재탐색은 없다. 무엇을 확인할까?

  1. 현재 head의 매개변수 객체가 optimizer 목록에 포함되는지 본다.

  2. 없다면 H1 생성 후 optimizer를 다시 구성하거나 명시적으로 갱신 범위를 추가한다.

이름이 head인 것만으로 H1이 갱신 대상이라는 보장은 없다.

비교할 점

매개변수 원소 수가 두 head에서 같아도 객체 소유 목록이 같다는 뜻은 아니다.

풀이 보기

A=2,B=4로 선택 B다. 특징이 같아도 head가 바뀌면 결과가 달라진다.

전체 no_grad는 head 학습 계획과 맞지 않는다. 실제 backward 성공은 실행해서 확인해야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

학습 스칼라 a와 입력 x=3 뒤에 가중치가 동결된 선형층 z=2*a*x가 있다. loss=z²일 때 a=1의 dloss/da를 구하고 동결층 전체를 no_grad로 끊은 계획과 비교하라.

힌트 1

동결되는 것은 계수 2이며 a는 학습한다.

힌트 2

z=6*a이므로 loss=36*a²다.

풀이와 답 확인

  1. 손미분은 72*a라서 a=1에서 72다.

  2. 계수 2의 gradient를 누적하지 않아도 a까지 가는 미분 경로는 필요하다.

필요한 a의 미분은 72다. 중간 동결층을 통째로 기록에서 빼면 이 경로를 잃을 수 있다.

흔한 오답에서 다시 생각하기

동결층 뒤에서는 앞 매개변수의 미분도 항상 0이다.

동결된 가중치와 그 연산 입력에 대한 미분은 다른 대상이다.

서로 독립인 네 기록으로 고정 특징 추출 계획을 진단하라. ① P=[[1,0],[0,1],[1,1]], x=(2,−1), F=(1,2,0)의 합산 직후 값과 bias 없는 P의 매개변수를 적는다. ② (1,2,2) 입력의 채널 0은 [1,3], 채널 1은 [5,7]이다. epsilon=1, gamma=1, beta=0으로 LN((2,2))의 출력과 affine 원소 수를 구한다. ③ BN의 초기 running_mean은 0, running_var는 1이다. epsilon=1, gamma=1, beta=0, momentum=1/4로 배치 [1,5]를 한 번 처리한다. 새 running 통계와 그 뒤 x=1의 eval 값을 구한다. ④ 앞 가중치를 동결하고 길이 2에서 클래스 3개로 가는 새 head H1을 연결했지만 optimizer는 옛 H0만 보유한다. 자동 재탐색이 없을 때 문제와 점검 계획을 적는다. 별도 중간 동결층 z=2*a*3 및 loss=z²에서 a=1의 미분도 구한다. 실제 실행과 손계산을 구분하라.

힌트 1

projection의 출력/잔차/활성화, LN의 마지막 두 축, BN의 forward 분산과 누적용 분산을 나누어 적는다.

힌트 2

동결한 객체와 optimizer가 보유한 객체를 이름별로 기록한다. 계수 2의 동결이 입력 a의 미분 경로까지 끊는 것은 아니다.

풀이와 답 확인

  1. ① Px=(2,−1,1)이므로 합산 직후는 (3,1,1)이다. P의 매개변수는 6개다.

  2. ② 평균은 4이고 biased 분산은 5다. 네 출력은 [−3,−1,1,3]/√6이며 gamma/beta 총 원소는 8개다.

  3. ③ 배치 평균은 3, forward 분산은 4, 누적에 넣는 unbiased 분산은 8이다. 새 평균은 3/4, 새 분산은 11/4다. 이후 eval의 x=1 값은 1/(2√15)다.

  4. ④ H1은 현재 optimizer의 갱신 목록에 없다. H1의 9개 매개변수 원소를 보유한 실제 객체로 optimizer 범위를 구성하고 앞 BN 모드/통계 및 head 미분 기록도 확인한다. 별도 loss=36*a²의 a=1 미분은 72다.

  5. 전체는 명시된 유한 모형의 손유도와 실행 전 점검 계획이다. 실제 PyTorch·가중치 다운로드·학습·미세조정·학생 수행은 미수행이다.

합산 직후는 (3,1,1), 투영 원소는 6개다. LN 출력은 [−3,−1,1,3]/√6, affine 원소는 8개다. 새 BN 누적 평균은 3/4, 분산은 11/4이고 eval 값은 1/(2√15)다. 새 head의 원소 수는 9개이지만 현재 optimizer의 소유 객체를 바꾸어야 갱신 범위에 들어간다. 중간 동결층을 통과하는 학습 a의 손미분은 72다.
