학생 표와 수강 표를 합쳐 특정 학년의 수강생 이름을 어떻게 찾을까?

회원에게 사진 두 장과 배지 세 개가 있으면 연결 결과는 몇 행일까?

Member의 M1 한 행, Photo의 M1 사진 P1/P2 두 행, Badge의 M1 배지 B1/B2/B3 세 행을 각각 회원 ID로 연결하자. 결과는 사진·배지의 가능한 쌍 여섯 개다. 사진 두 장이라는 사실을 조인 결과의 행 수로 세면 사진을 세 번씩 반복 계산한다. 어떤 대상을 세려는지와 결과 한 행이 무엇을 나타내는지 먼저 읽는다.

관계대수의 집합 투영으로 photo_id만 남기면 P1/P2 두 값으로 합쳐진다. 반면 일반 SQL의 열 선택은 중복을 남길 수 있어 여섯 행이 유지될 수 있다. 명시한 집합 모형과 SQL의 중복 의미를 혼동하지 않는다. 배지 정보 없이 사진만 필요한 질의에 배지 표를 연결하면 배지가 없는 회원의 사진을 내부 조인에서 잃을 수도 있다.

NATURAL JOIN은 열 이름이 같은 모든 속성을 연결한다. Member.status는 회원 활동 상태, Photo.status는 사진 공개 상태라면 같은 이름이어도 같은 사실이 아니다. member_id로만 연결해야 할 곳에 status까지 같아야 하는 조건을 넣으면 올바른 사진을 누락할 수 있다. 이름 변경이나 명시적 연결 조건이 의도를 보호한다.

표를 집합으로 읽기

이 소단원은 유한한 관계를 튜플의 집합으로 다룬다. 튜플은 속성 이름마다 값을 하나씩 가진 기록이다. 행 순서는 의미가 없으며 같은 튜플을 두 번 적어도 집합의 원소는 하나다. NULL 없이 모든 비교가 참 또는 거짓인 모형을 사용한다. 실제 SQL의 중복 허용 및 NULL 논리는 별도로 확인해야 한다.

Student(sid,name,grade)를 학생 표, Enroll(esid,course)를 수강 표라고 하자. 서로 다른 속성 이름 sid와 esid는 연결 조건을 명시하기 쉽게 만든 것이다. 같은 이름이라고 해서 같은 학생인 것은 아니다. 연결하려는 대상과 데이터의 키를 먼저 정해야 한다.

선택은 행, 투영은 속성

선택 σ_p(R)는 조건 p가 참인 튜플만 남긴다. 스키마는 그대로 유지된다. σ_grade≥2(Student)는 학년을 검사하지만 이름이나 학생 번호를 지우지 않는다. 조건을 만족하는 행이 없으면 같은 스키마의 빈 관계가 된다.

투영 π_A(R)는 속성 집합 A만 남긴다. 남겨진 속성 값이 같은 튜플은 하나로 합쳐진다. 서로 다른 학생도 이름만 투영하면 하나의 이름으로 합쳐질 수 있다. SQL SELECT의 기본 중복 의미와 관계대수 투영은 같지 않으며 집합 투영을 흉내 내는 SQL에서는 보통 DISTINCT가 필요하다.

조인은 조건에 맞는 쌍

곱 R×S는 R의 각 튜플과 S의 각 튜플을 결합한다. 속성 이름이 겹치면 관계 이름으로 구분하거나 이름을 바꾸어야 한다. 조건 조인 R⋈_c S는 σ_c(R×S)로 정의된다. 학생 번호가 일치하는 쌍만 남기면 한 학생의 여러 수강 기록이 각각 결과 튜플을 만든다.

자연 조인은 두 관계에서 이름이 같은 모든 속성을 일치시키고 공통 속성을 한 번만 남긴다. 한 공통 열만 연결하고 싶었는데 이름이 같은 다른 열까지 있으면 의도보다 강한 조건이 된다. 따라서 자연 조인을 자동으로 학생 번호 조인이라고 읽으면 안 된다. 여기서는 명시한 sid=esid 조건의 내부 조인만 사용한다.

각 쌍은 서로 다른 튜플이므로 집합이어도 여섯 개다. 사진만 투영하면 같은 사진 값은 하나가 된다.

중간 과정을 따라가는 예제

Student={(1,가람,2),(2,나래,1),(3,가람,3)}, Enroll={(1,AI),(1,OS),(2,AI),(4,OS)}이다. π_name(σ_grade≥2(Student⋈_sid=esid Enroll))을 구하라. Enroll의 4는 이 예제에서 학생 표에 없는 번호이며 외래키 무결성이 강제된 DB라고 가정하지 않는다.

  1. 학생 3행과 수강 4행의 곱에는 3×4=12개 쌍이 있다.

  2. sid=esid를 만족하는 쌍은 (1,가람,2,1,AI), (1,가람,2,1,OS), (2,나래,1,2,AI) 세 개다. 3은 수강 기록이 없고 4는 학생 기록이 없어 내부 조인에 포함되지 않는다.

  3. grade≥2로 선택하면 가람 학생 1의 AI와 OS 두 튜플만 남는다. 나래 학생은 학년 조건을 만족하지 않는다.

  4. name만 투영하면 두 튜플이 모두 (가람)이 된다. 집합에서 동일 튜플은 하나이므로 결과의 원소 수는 1이다.

결과는 name 속성의 관계 {(가람)}이다. 이는 학생 1명이라는 집계를 수행한 결과가 아니라 이름 값의 집합이다.

조건을 바꾸어 비교하기

서로 다른 일대다 관계의 곱

사진 P1/P2와 배지 B1/B2/B3가 같은 M1을 참조한다. 조인 후 사진 수를 행 수로 보고해도 되는가?

  1. 각 사진은 세 배지와 연결되어 세 행씩 나온다.

  2. 전체는 2×3=6행이지만 고유한 photo_id 값은 2개다.

사진 수는 2장이다. 이 질의의 조인 행 수 6과 같은 것이 아니다.

비교할 점

집합 조인도 서로 다른 사진·배지 쌍을 합치지 않으므로 모든 중복 문제가 SQL만의 문제는 아니다.

같은 열 이름의 다른 뜻

Member=(M1,status=active), Photo=(P1,M1,status=public)이다. member_id만 연결하는 것과 자연 조인의 차이는?

  1. 명시적 member_id 연결은 M1이 같아 P1을 남긴다.

  2. 자연 조인은 member_id와 status 둘 다 같아야 하는데 active≠public이다.

명시적 연결은 한 행, 자연 조인은 빈 결과다.

비교할 점

같은 열 이름만으로 같은 업무 사실이라 추론하지 않는다.

종이와 본문으로 직접 해보기

종이에 같은 표를 적고 조건을 grade≥3으로 바꿔 결과를 구하라. 그 뒤 Enroll에 (3,AI)를 추가한 경우를 다시 구하라. Student에서 name만 투영한 결과도 비교하라.

힌트 보기

학년 선택을 통과한 학생과 연결될 수강 기록이 실제로 있는지 따로 표시하라.

풀이 보기

원래 표에서 grade≥3은 학생 3만 통과하지만 연결 수강이 없어 결과는 빈 관계다. (3,AI)를 추가하면 학생 3과 연결되어 {(가람)}이다. π_name(Student)는 학생 1과 3의 같은 이름을 합쳐 {(가람),(나래)}이며 학생 수 3과 이름 값 수 2는 다르다.

오해와 반례

이름을 투영하면 서로 다른 학생도 모두 구분된다.

학생 1과 3은 sid가 다르지만 name이 가람으로 같다. 이름만 남긴 집합 투영은 두 기록을 하나로 합친다. 학생을 식별하려면 sid를 남겨야 한다.

필요한 두 기술 중 하나를 두 번 하면 두 기술을 모두 가진 것일까?

후보 C={A,B,C}, 필수 기술 S={파이썬,SQL}이라고 하자. 완료 관계는 A/파이썬, A/SQL, B/파이썬, B/웹이다. B의 기록도 두 개지만 SQL이 빠졌다. 모두 충족을 전체 기록 개수와 필수 개수의 같음으로 바꾸면 다른 기술이 누락을 가린다. 필요한 각 쌍의 존재를 확인해야 한다.

M=(C×S)−R은 빠진 요구 쌍이다. 이 예에서는 B/SQL, C/파이썬, C/SQL이 빠진다. 나쁜 후보는 B,C이고 결과는 A다. 요구 외 기술을 더 가진 후보를 금지하려면 별도로 초과 기술을 검사한다. 최소 요구를 모두 만족한다는 조건과 정확히 같은 기술 집합이라는 조건은 서로 다르다.

빈 필수 집합일 때는 실패할 요구가 없어 선언한 후보 C가 모두 통과한다. 하지만 고전 나눗셈은 후보를 R에 등장한 사람으로 정하므로 기록 없는 C는 빠질 수 있다. “전체 가입자 중 모두 충족”이라는 질의의 후보는 가입자 표에서 정해야 한다. 모든 조건의 범위가 비었는지와 후보의 범위가 비었는지를 나누어 읽는다.

합치기와 빼기의 조건

합집합 R∪S는 어느 한쪽에라도 있는 튜플을 남긴다. 교집합 R∩S는 양쪽 모두에 있는 튜플, 차집합 R−S는 R에 있지만 S에는 없는 튜플이다. 차집합은 방향이 중요하다. 이 절에서는 속성 이름과 값의 영역이 같은 관계끼리 연산하며 이름이 다르면 먼저 호환되게 바꾼다.

U={1,2,4}, V={2,3}을 sid 한 속성의 관계로 보자. 합집합은 {1,2,3,4}, 교집합은 {2}, U−V는 {1,4}, V−U는 {3}이다. 튜플의 개수만 보고 뺄셈하지 않는다. 원소를 대조해야 하며 R∩S=R−(R−S)처럼 기본 연산으로 교집합을 구성할 수도 있다.

나눗셈은 모든 요구의 충족

R(X,Y)와 S(Y)의 스키마를 가정하자. X와 Y는 서로 겹치지 않는 속성 집합이다. R÷S는 R에 등장한 X 후보 중에서 S의 모든 Y와 짝을 이루는 X를 반환한다. 후보 C=π_X(R)에 대해 x∈C이며 모든 y∈S에 대하여 (x,y)∈R인지를 검사한다.

수강 R(sid,code)와 필수 S(code)라면 필수 과목을 모두 수강한 학생 번호를 찾는 뜻이다. 필수 과목 외의 과목을 더 수강해도 탈락하지 않는다. 모든 필수 과목을 갖췄는지 검사하는 것이지 수강 과목 집합이 필수 집합과 정확히 같은지 검사하는 연산은 아니다.

빠진 쌍을 빼서 만들기

C×S는 후보가 가져야 할 모든 쌍이다. M=(C×S)−R는 빠진 요구이며 B=π_X(M)는 빠진 요구가 하나라도 있는 후보다. 따라서 R÷S=C−B=π_X(R)−π_X((π_X(R)×S)−R)이다. 바깥 차집합은 나쁜 후보를 제거하여 모든 요구를 만족한 후보만 남긴다.

S가 빈 관계이면 C×S도 비어 있어 나쁜 후보가 없다. 따라서 몫은 C이다. 요구가 없는 모든 조건은 참이지만 이 정의는 후보를 R의 투영으로 제한한다. 수강 기록이 없는 학생까지 대상으로 삼으려면 Student의 번호를 후보 집합으로 따로 정해야 한다. 빈 R에서 몫이 자동으로 모든 세상 학생이 되는 것은 아니다.

보유 기록 두 개라는 수가 같은 A/B도 요구의 실제 값은 다르다. R은 이 표에서 NULL 없는 집합 관계다.

중간 과정을 따라가는 예제

R={(1,A),(1,B),(2,A),(3,B),(3,C),(4,A),(4,B),(4,C)}, S={A,B}이다. R÷S를 차집합 구성으로 계산하라.

  1. C=π_sid(R)={1,2,3,4}이다. 학생 번호를 중복 없이 모은다.

  2. C×S에는 (1,A),(1,B),(2,A),(2,B),(3,A),(3,B),(4,A),(4,B)의 8개 쌍이 있다.

  3. R에 없는 쌍은 M={(2,B),(3,A)}이다. (3,C),(4,C)는 요구 쌍이 아니며 차집합 결과에 추가되지 않는다.

  4. B=π_sid(M)={2,3}이다. 후보에서 이를 빼 C−B={1,4}를 얻는다.

학생 1과 4가 모든 필수 과목을 갖췄다. 학생 4의 추가 C 수강은 결과를 방해하지 않는다.

조건을 바꾸어 비교하기

개수 같음의 반례

B가 파이썬과 웹 두 기술을 완료했고 필수는 파이썬과 SQL이다. 개수 2=2가 충분한가?

  1. 필수 기술 SQL과 짝을 이루는 완료 기록이 없다.

  2. 웹은 요구 밖의 값이므로 SQL을 대신하지 못한다.

충분하지 않다. 빠진 쌍 B/SQL 때문에 탈락한다.

비교할 점

서로 다른 필수 기술의 완료만 중복 없이 세고 정확한 후보 범위·빈 요구 처리를 정한 경우에만 적절한 계수 방식과 비교할 수 있다.

기록 없는 후보와 빈 요구

C는 가입자이나 완료 기록이 없다. S가 비면 외부에서 선언한 후보 집합과 고전 나눗셈 R÷S의 결과를 비교하라.

  1. 외부 후보 집합은 A,B,C다. 실패할 요구가 없어 모두 남는다.

  2. R에 등장한 후보는 A,B뿐이다. 고전 나눗셈은 그 범위에서 출발한다.

외부 후보의 결과는 A, B, C이고, 고전 나눗셈의 몫은 A, B다.

비교할 점

공허하게 참인 모두 조건이 후보 범위를 새로 만들지는 않는다.

종이와 본문으로 직접 해보기

같은 R에서 S={A,B,C}, S=∅일 때의 몫을 각각 구하라. 이어 R=∅인 경우도 계산하고, 수강 없는 학생 5가 결과에 들어가는지 설명하라.

힌트 보기

각 조건에서 먼저 C를 정한 뒤 빠진 쌍을 표시하라. 요구가 비어 있는 것과 후보가 비어 있는 것을 구별하라.

풀이 보기

세 필수 과목이면 1은 C, 2는 B와 C, 3은 A가 빠져 몫은 {4}이다. S가 비면 빠진 쌍이 없어 {1,2,3,4}가 남는다. R이 비면 C도 비므로 S가 비어도 몫은 ∅이다. 학생 5는 R에 등장하지 않아 이 정의의 후보가 아니다.

오해와 반례

필수 과목을 더 많이 수강한 학생은 나눗셈에서 제외된다.

R의 학생 4는 A,B,C를 수강했으며 S={A,B}의 모든 요구를 만족해 포함된다. 정확한 과목 집합 일치를 원하면 필수 밖의 수강 여부를 추가로 검사해야 한다.

완료된 상담만 연결하는 것과 연결한 뒤 미완료를 지우는 것은 같은가?

회원 1,2,3이 있고 상담은 (회원 1,pending),(회원 3,done)뿐이라고 하자. 모든 회원을 보존하며 완료 상담만 붙이려면 회원 ID 일치와 done을 LEFT JOIN의 연결 조건으로 정한다. 회원 1은 미완료 상담이 연결에 실패해 NULL 상담으로 남고 회원 2도 NULL, 회원 3은 done으로 남는다.

먼저 ID로만 LEFT JOIN한 뒤 WHERE status=done을 적용하면 회원 1은 pending이라 거짓, 회원 2는 NULL이라 UNKNOWN이 되어 둘 다 빠진다. WHERE status=done OR 상담 ID IS NULL을 쓰면 회원 2는 살리지만 이미 pending 상담이 연결된 회원 1은 여전히 빠진다. WHERE의 NULL 처리를 추가하는 것만으로 모든 조건이 자동 동치가 되지는 않는다.

내부 조인에서는 순수 조건이 어느 입력의 속성만 보는지 확인한 뒤 선택을 해당 입력으로 이동할 수 있다. 하지만 투영을 이동하면 조인 키와 조건의 속성을 끝까지 남겨야 한다. 동치의 대상은 최종 결과이며 모델·조건·허용 입력을 명시한다. 중간 후보 수를 줄였다고 실제 서버가 같은 방식으로 실행하거나 몇 배 빨라진다는 보장은 없다.

동치는 모든 허용 입력의 같은 결과

관계대수 식 Q와 Q′가 동치라는 말은 이 모형에서 허용되는 모든 입력 관계에 대해 같은 결과 관계를 만든다는 뜻이다. 한 예에서 답이 같다는 사실은 증명이 아니다. 스키마, 집합 또는 중복 모형, NULL과 조건의 논리를 먼저 정해야 한다. 여기서는 이름 있는 속성의 유한 집합 관계와 NULL 없는 순수한 조건을 사용한다.

σ_p∧q(R)=σ_p(σ_q(R))이며 순수한 조건의 두 선택 순서를 바꿀 수 있다. 어떤 튜플이 양쪽 조건을 모두 만족해야 남는다는 사실로 증명한다. 부수 효과나 예외를 일으키는 실제 프로그램의 평가 순서까지 이 수학 법칙으로 보장하는 것은 아니다.

선택과 투영을 옮기는 조건

p가 R 속성만 참조한다면 σ_p(R×S)=σ_p(R)×S이다. 곱의 각 튜플에서 p가 보는 R 부분이 같기 때문이다. 내부 조인에도 해당 입력만 보는 선택을 밀어 넣을 수 있다. 반면 두 입력의 속성을 모두 비교하는 조건을 한쪽에만 옮기면 값이 부족하거나 다른 뜻이 된다. 외부 조인은 미일치 행 보존이라는 별도 의미 때문에 이 규칙을 그대로 쓰지 않는다.

π_A(σ_p(R))에서 p가 참조하는 속성이 모두 A에 있을 때 선택과 투영을 교환할 수 있다. grade를 검사하는데 name만 먼저 남기면 조건을 평가할 수 없다. 조인 전에 속성을 줄이려면 연결 조건에 필요한 속성도 유지해야 한다. 중간 결과가 바뀌더라도 최종 결과가 같을 수 있으며 어떤 관찰 대상을 보존하는지 분명히 해야 한다.

비용과 반례를 따로 보기

필터를 앞당기면 종이 모형에서 생성할 쌍이 줄 수 있다. 그러나 실제 속도는 인덱스, 분포, 알고리즘, 저장장치와 최적화기에 달려 있다. 동치 변환만으로 몇 배 빠르다고 단정하지 않는다. 결과 동일성은 수학적 성질이고 성능은 실행 조건 아래의 측정 문제다.

투영은 차집합에 무조건 분배되지 않는다. R(a,b)={(x,1),(x,2)}, S={(x,1)}이면 π_a(R−S)={x}지만 π_a(R)−π_a(S)=∅이다. 투영이 서로 다른 튜플을 합쳐 버리기 때문이다. 작은 반례를 찾는 일은 그럴듯한 변환을 검증하는 좋은 방법이다.

중간 과정을 따라가는 예제

Student={(1,가람,2),(2,나래,1),(3,가람,3)}, Enroll={(1,AI),(1,OS),(2,AI),(4,OS)}에서 π_name(σ_grade≥2(Student⋈_sid=esid Enroll))의 선택을 학생 입력으로 옮겨 결과와 곱 후보 수를 비교하라.

  1. grade는 Student에만 속하므로 Student′=σ_grade≥2(Student)={(1,가람,2),(3,가람,3)}를 먼저 만들 수 있다.

  2. 원래 곱 후보는 3×4=12개다. 선택을 먼저 하면 Student′×Enroll은 2×4=8개다. 이는 명시한 곱 모형의 후보 수이며 실제 DB가 이 곱을 반드시 물질화한다는 뜻은 아니다.

  3. 학생 1의 AI와 OS 두 쌍만 sid=esid에 맞는다. 학생 3은 수강 기록이 없어 연결되지 않는다.

  4. 두 쌍을 name으로 투영하여 {(가람)}을 얻는다. 원래 식도 조인3행 중 학년 선택2행, 최종 이름1개이므로 같은 결과다.

선택을 Student 입력으로 옮긴 식은 같은 {(가람)}을 주며 곱 후보 수를 12에서 8로 줄인다. 이 예제의 동일 답에 더해 Student 속성만 보는 조건이라는 일반 증명 조건이 동치를 뒷받침한다.

조건을 바꾸어 비교하기

ON과 WHERE의 반례

모든 회원을 보존하는 완료 상담 목록의 세 결과를 구하라. 회원 1 상담은 pending, 회원 2는 상담 없음, 회원 3 상담은 done이다.

  1. ON에서 done까지 요구하면 회원 1과 2는 미일치 확장 행, 회원 3은 실제 상담이다.

  2. ID만 연결한 뒤 WHERE done이면 회원 1은 FALSE, 회원 2는 UNKNOWN, 회원 3은 TRUE다.

  3. WHERE done OR 상담 ID IS NULL은 회원 1 FALSE, 회원 2 TRUE, 회원 3 TRUE다.

ON에 done을 넣으면 회원 {1,2,3}, WHERE done은 회원 {3}, WHERE done OR 상담 ID IS NULL은 회원 {2,3}이다.

비교할 점

미일치 보존 시점이 달라 단순 선택 이동 법칙을 적용할 수 없다.

조인 키를 남겨야 한다

R(a,k)={x/1,y/2}, S(k,b)={1/p,2/q}에서 최종(a,b)를 구하려 한다. R은 a만, S는 b만 먼저 남겨도 같은가?

  1. 원래 k 일치 결과는 (x,p),(y,q)다.

  2. k를 제거하면 연결 조건을 평가할 수 없다.

  3. 조건 없이 곱으로 바꾸면 (x,p),(x,q),(y,p),(y,q)가 나온다.

같지 않다. R에서 (a,k), S에서 (k,b)를 유지한 뒤 연결하고 마지막에 (a,b)를 남긴다.

비교할 점

최종 출력에 없는 속성도 중간의 올바른 판정을 위해 필요할 수 있다.

종이와 본문으로 직접 해보기

차집합 반례 R={(x,1),(x,2)}, S={(x,1)}를 종이에 적어 π_a(R−S)와 π_a(R)−π_a(S)를 계산하라. 두 식이 달라지는 정확한 단계에 표시하라.

힌트 보기

왼쪽은 원래 두 속성 튜플을 먼저 빼고, 오른쪽은 각 표의 b를 먼저 지운다.

풀이 보기

왼쪽은 R−S={(x,2)}를 얻은 후 {x}다. 오른쪽은 R과 S가 모두 {x}로 합쳐져 차집합이 ∅다. 다른 b를 가진 튜플의 구별을 먼저 없애서 차집합의 판단 정보가 손실된다.

오해와 반례

답이 우연히 같으면 모든 입력에서 유효한 동치다.

R={(x,1)}, S=∅에서는 두 투영·차집합 식이 같지만 위의 두 행 R 반례에서는 다르다. 동치는 모든 허용 입력의 같음이므로 하나의 반례로 보편 주장을 반박할 수 있다.

학습 포트폴리오 조회의 의미 검산

회원 M1에 사진 두 장·배지 세 개가 있을 때 조인 행 수와 사진 ID 집합 크기를 계산하라. 후보 A/B/C와 필수 파이썬/SQL, 완료 A의 두 필수와 B의 파이썬·웹에서 빠진 요구를 적고 빈 요구의 후보 범위를 설명하라. 회원 1 pending/회원 2 상담 없음/회원 3 done의 완료 상담 목록에서 모든 회원을 남기는 조건 위치와 다른 두 질의의 반례를 제시하라.

힌트 1

각 결과 한 행이 무엇을 가리키는지 읽는다.

힌트 2

모두 조건의 후보와 외부 조인의 미일치 보존을 명시한다.

풀이와 답 확인

  1. 사진·배지 쌍은 2×3=6이며 사진 ID 집합은 2다.

  2. 빠진 쌍은 B/SQL,C/파이썬,C/SQL이므로 결과는 A다. 빈 요구의 외부 후보는 A/B/C, 고전 R 투영 후보는 A/B다.

  3. LEFT JOIN의 ON에 회원 ID 일치와 done을 넣으면 회원 1과 2는 NULL 상담, 회원 3은 done으로 모두 남는다.

  4. ID만 연결한 뒤 WHERE done은 회원 3만, WHERE done OR 상담 ID IS NULL은 회원 2와 3만 남겨 회원 1 보존에 실패한다.

대상 식별·집합과 중복·후보 범위·조건의 적용 시점을 함께 정해야 같은 질의 의미를 얻는다. 작은 표의 손계산이며 SQL·성능·학습자 시험 결과는 아니다.

해결한 뒤 점검할 것

  • 사진 수와 사진·배지 쌍 수를 구별한다.

  • 기술 총수와 각 필수의 존재를 구별한다.

  • 빈 요구에서 선언한 후보만 반환한다.

  • 외부 조인의 ON과 WHERE의 차이를 반례로 설명한다.

사진·배지 쌍 6개와 사진 ID 2개, 빈 배지의 0쌍, 전체 DISTINCT의 6쌍을 손으로 검산했다. 서로 다른 status 값의 자연 조인은 0행이다. 후보×필수의 6쌍 중 누락은 3쌍이고 결과는 A다. 빈 요구의 후보 범위와 요구 증가의 포함 방향을 확인했다. LEFT JOIN 세 질의의 회원 집합은 각각 {1,2,3}, {3}, {2,3}이다. 키를 유지한 조인은 2쌍, 키 제거 후 곱은 4쌍이며 조건부 유일 참조의 튜플 대응을 손으로 검산했다.
