소단원 8.1

CTE·재귀 질의

질의 안에서 이름을 붙인 중간 결과가 자기 자신을 쓸 수 있을까?

준비 개념과 학습 목표

준비 개념

  • SELECT·WHERE

  • UNION ALL

학습 목표

  • CTE의 범위를 설명한다.

  • 재귀 질의의 초기·반복·종료를 추적한다.

같은 목적지에 두 경로로 도착하면 결과도 두 번 나와야 할까?

유한 그래프의 간선을 A→B,A→C,B→D,C→D로 정하자. 출발 A에서 다음 정점을 반복해서 찾으면 A, 다음 B/C, 다음 D/D가 나온다. UNION ALL과 정점 열만 쓰면 D가 두 번 남는다. 방문 가능한 정점의 종류를 묻는 질문과 가능한 경로의 수를 묻는 질문은 다르다.

정점 열만 사용하는 UNION은 D 중복을 하나로 합친다. 그러나 경로 열까지 출력하면 A-B-D와 A-C-D는 서로 다른 행이다. 경로를 보존하는 것은 정보 손실을 막지만, 정점 기준 중복 제거와 같은 의미가 아니다. 순환 방지용 경로 검사는 같은 경로에서 이미 방문한 정점에 다시 들어가는 것을 막는 선택이다.

CTE 이름은 단계별 의미를 설명하는 데 유용하지만 그 이름만으로 항상 별도 저장이나 실행 순서를 보장하지 않는다. 특히 변경하는 CTE의 결과를 다음 단계에 전달하려면 RETURNING으로 만든 결과를 읽는 경로를 명확히 한다. 기본 표를 다시 읽는 것과 변경 CTE의 반환값을 읽는 것은 같은 문장 안에서도 다른 결과일 수 있다.

먼저 확인할 개념
  • 집합과 중복의 선택

    UNION과 UNION ALL에서 무엇을 한 행으로 비교하는지 읽는다.

  • 기존 값의 갱신

    기본 표에서 기존 값으로 대상 행의 새 값을 계산하는 UPDATE를 먼저 읽고, 새 진입에서 RETURNING 전달을 추가로 배운다.

CTE는 질의 안의 이름이다

WITH는 복잡한 질의를 여러 이름 있는 중간 결과로 나눈다. CTE 이름은 해당 문장 안에서 사용하며 영구 테이블 생성과 다르다. 앞에서 정의한 CTE를 뒤의 CTE나 주 질의가 참조할 수 있다.

CTE를 썼다고 항상 별도 임시 저장이나 속도 향상을 보장하지 않는다. PostgreSQL은 조건에 따라 비재귀·부작용 없는 CTE를 주 질의와 합칠 수 있고 MATERIALIZED 선택은 별도 비용을 가진다.

초기 행 뒤에 반복 행을 붙인다

WITH RECURSIVE의 비재귀 항이 처음 working table을 만든다. 재귀 항은 그 단계 working table에서 다음 행을 만들고 그것을 다음 working table로 바꾼다. 비면 끝난다.

UNION ALL은 중복을 보존한다. UNION은 이전 출력과 중복되는 전체 행을 제거한다. id가 같아도 depth가 늘면 서로 다른 전체 행이라 순환 방지에 실패할 수 있다.

종료와 정렬은 별도다

숫자 상한이나 경로의 방문 여부 등 종료 조건을 설계한다. 그래프 순환에는 경로 기록이나 CYCLE을 고려한다. 부모 LIMIT만으로 무한 재귀를 안전하게 처리한다고 일반화하면 안 된다.

결과 표시 순서는 최종 ORDER BY로 정한다. 재귀 평가가 어떤 순서로 내부 방문하는지와 출력 정렬은 별개다.

중간 과정을 따라가는 예제

PostgreSQL 의미로 WITH RECURSIVE t(n) AS (VALUES (1) UNION ALL SELECT n+1 FROM t WHERE n<4) SELECT n FROM t ORDER BY n; 의 행을 종이에 구하자.

  1. 초기 working table은 {1}이고 결과에 1을 넣는다.

  2. 다음 단계는 {2},{3},{4}이며 각각 결과에 추가한다.

  3. {4}에서는 n<4가 거짓이라 다음 집합이 비고 종료한다. 최종 정렬은 1,2,3,4다.

결과 네 행과 합 10이다. 이는 실제 DB 실행 결과 기록이 아닌 의미론 손계산이다.

조건을 바꾸어 비교하기

정점 수와 경로 수를 나눈다

A→B,A→C,B→D,C→D에서 정점 열만 출력한다. UNION ALL과 UNION의 D 행 수는?

  1. 두 갈래가 각각 D를 만든다.

  2. UNION은 같은 전체 정점 행 D를 합친다.

UNION ALL은 D 두 행, UNION은 D 한 행이다. D까지 단순 경로는 두 개다.

비교할 점

한 정점에 도달하는 여러 경로를 보존할지 질문으로 결정한다.

반환값을 읽는 변경 CTE

기본 가격이 10이다. 한 문장의 CTE에서 가격을 20으로 UPDATE RETURNING price 한다. 주 질의가 기본 표를 읽을 때와 CTE 반환값을 읽을 때를 비교하라.

  1. 변경 CTE와 주 질의는 같은 스냅샷을 사용한다.

  2. RETURNING의 결과는 변경된 값을 전달한다.

기본 표를 읽는 주 질의는 이전 10, CTE의 반환값을 읽으면 20이다. 트리거나 규칙은 없는 단순 모형이다.

비교할 점

CTE를 위에 썼다는 것으로 기본 표의 순차 재조회 의미를 가정하지 않는다.

소단원 8.2

윈도 함수

전체 합계를 각 행 옆에 써도 원래 행은 남을까?

준비 개념과 학습 목표

준비 개념

  • GROUP BY

  • 정렬과 동률

학습 목표

  • 집계와 윈도의 행 수를 구분한다.

  • partition·frame·최종 정렬을 구별한다.

“상위 두 명”과 “상위 두 순위”는 같은 요청일까?

점수 90,90,80,70인 네 학생을 생각하자. 점수 내림차순의 rank는 1,1,3,4이고 dense_rank는 1,1,2,3이다. 상위 두 rank를 고르면 90점 두 명, 상위 두 dense_rank를 고르면 90점 두 명과 80점 한 명이다. 정확히 두 명이 필요하면 동률 선택 기준까지 정한 row_number가 다른 정책이다.

row_number의 결정성을 위해 점수 뒤 ID를 넣을 수 있다. 하지만 rank에도 ID를 넣으면 같은 점수라도 ID가 달라 더 이상 peer가 아니게 된다. 점수 동률은 동률로 유지하면서 명수 선택만 결정하려면 두 함수의 ORDER BY를 서로 다르게 설계한다.

last_value는 이름 때문에 집단의 마지막 값을 뜻한다고 생각하기 쉽지만 실제로는 현재 frame의 마지막 값을 읽는다. 시간 1,2,3에 값 4,7,9가 있으면 기본 정렬 frame의 last_value는 4,7,9이고 전체 frame을 명시하면 모두 9다. lag는 앞 행의 값을 읽으며 앞 행이 NULL인 것과 앞 행이 없는 것을 구별해야 한다.

먼저 확인할 개념
  • 정렬 키와 동률

    유일 보조 키가 선택 결과에 미치는 영향을 확인한다.

  • 윈도 frame 기본

    집단 전체와 현재 frame을 구별한다.

윈도는 원래 행을 보존한다

SUM(v) OVER (...)는 관련 행을 보고 계산하되 각 행의 정체성을 남긴다. GROUP BY의 그룹별 한 행으로 압축하는 집계와 다르다. PARTITION BY는 계산 집단을 정한다. 생략하면 전체가 한 집단이다.

OVER 안 ORDER BY는 윈도 계산 순서다. 화면의 최종 순서까지 보장하지 않으므로 주 질의 ORDER BY가 별도로 필요하다.

ROWS와 기본 frame의 차이

누적 합을 행별로 하려면 유일한 정렬 키와 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW를 명시할 수 있다. 각 위치까지의 행을 포함한다.

PostgreSQL에서 ORDER BY가 있는 기본 frame은 현재 값과 같은 peer도 포함한다. 동률 점수만 정렬하면 두 동률 행이 같은 누적 합을 받는 경우가 있다. row_number의 동률 내부 번호는 보조 키 없이는 확정되지 않는다.

계산 뒤 필터는 바깥에서 한다

윈도는 FROM/WHERE/GROUP BY/HAVING 결과를 본다. 먼저 WHERE로 제거한 행은 윈도에 보이지 않는다. 계산된 row_number를 같은 수준 WHERE에서 바로 쓸 수는 없다.

CTE나 서브질의에서 윈도 값을 만든 뒤 바깥 WHERE에서 rn<=2처럼 필터한다. 원본에서 먼저 필터하는 것과 계산 후 필터하는 것은 다른 의미다.

준비 개념과 학습 목표

준비 개념

  • NULL·COUNT

학습 목표

  • 집계 단위와 조인 배수를 확인한다.

  • NULL과 가중 평균을 검산한다.

항목과 결제 두 표를 붙이면 왜 금액이 서로 다른 배수로 늘어날까?

주문 O1에 항목 두 개가 있고 항목 금액은 10과 20이다. 결제 기록은 세 개이며 5,7,18이다. 주문 ID로 두 자식 표를 동시에 내부 조인하면 항목·결제 조합 여섯 행이 생긴다. 항목 합은 세 번 반복되어 90, 결제 합은 두 번 반복되어 60이 된다. 실제 각각의 합은 30이다.

두 자식의 합을 각자 주문 ID별로 먼저 계산한 뒤 그 요약 표를 주문에 연결하면 주문마다 항목 요약 한 행과 결제 요약 한 행을 읽는다. 이 방법은 원래 자식 기록의 합이라는 질문을 보존한다. 금액 값에 DISTINCT를 쓰면 서로 다른 기록의 같은 금액까지 합치므로 대안이 되지 않는다.

검산은 단순 전체 총액만보다 대상 ID 수와 기록 수, 미상 금액 수, 주문별 합을 함께 확인하는 것이 좋다. 서로 다른 오류가 상쇄되면 전체 합은 우연히 맞을 수도 있다. 자식이 없는 주문도 보고할지, 미상 금액을 0으로 표시할지, 통화와 시간 범위가 같은지도 업무 질문에 포함한다.

먼저 확인할 개념
  • 조인의 결과 행 단위

    여러 일대다 관계의 조합이 행을 늘리는 이유를 확인한다.

  • 집계의 입력과 미상 값

    합과 비NULL 수를 보존하여 요약을 검산한다.

한 행이 무엇인지 먼저 정한다

주문마다 한 행인 orders와 주문 항목마다 한 행인 lines를 결합하면 주문 총액이 항목 수만큼 반복된다. 주문 단위 금액을 그대로 합산하면 조인 배수에 따라 과대 합계가 나온다.

항목 금액을 합할지 주문 금액을 합할지 목표를 정하고 그 단위에서 먼저 집계한다. SUM(DISTINCT amount)는 서로 다른 주문의 우연히 같은 금액을 제거할 수 있어 일반적인 해결이 아니다.

NULL을 0과 구별한다

COUNT(*)는 행 수, COUNT(amount)는 non-null 금액 행 수다. AVG와 SUM도 non-null 값을 본다. 관측되지 않은 금액을 자동으로 0이라고 해석하면 평균 분모가 바뀐다.

빈 입력의 SUM은 PostgreSQL에서 NULL이다. COALESCE로 0을 표시하는 것은 보고서의 별도 정책이며 원래 관측이 존재했다는 증명이 아니다. LEFT JOIN에는 매칭 없는 부모도 남아 COUNT(*)와 자식 id 개수가 다를 수 있다.

그룹 평균을 그대로 평균내지 않는다

집단 크기가 다르면 집단 평균의 단순 평균은 전체 관측 평균과 다르다. 전체 합을 전체 non-null 수로 나누거나 집단 평균을 관측 수로 가중한다.

원본 행 수, non-null 수, 그룹별 합, 전체 합을 나란히 검산하면 오류 위치를 찾기 쉽다. 필터의 시간 범위·통화·중복 id까지 확인해야 실제 보고서 의미가 정해진다.

중간 과정을 따라가는 예제

금액은 반 A의 10,20과 반 B의 30,NULL이다. 실제 관측 전체 평균을 구하자. 별도로 주문 X=100에 항목 2개, Y=50에 항목 1개를 조인한 합도 검산하자.

  1. 금액 행은 4개, non-null 금액은 3개, 합은 60이다. AVG는 60/3=20이고 A 평균은 15, B 평균은 30이다.

  2. 그룹 평균의 단순 평균은 (15+30)/2=22.5다. 관측 수로 가중하면 (15×2+30×1)/3=20이다.

  3. 조인 후 주문 금액은 100,100,50으로 합은 250이다. 주문 단위 원래 합은 150이므로 항목 중복을 제거한 단위에서 합해야 한다.

전체 관측 평균 20, 잘못된 그룹 평균 22.5, 잘못된 조인 합 250과 올바른 주문 합 150이다.

A→B,A→C,B→D,C→D에서 정점 도달과 경로 목록의 D 출력을 비교하라. 점수 90/90/80/70의 상위 두 dense_rank와 정확히 두 row_number 선택을 비교하라. O1의 항목 10/20과 결제 5/7/18을 동시에 조인한 잘못된 두 합을 계산하고 각 자식별 요약 방식으로 수정하라.

힌트 1

행에 담긴 정점·경로·대상의 단위를 적는다.

힌트 2

중복·동률·조합 반복의 정책을 각각 확인한다.

풀이와 답 확인

  1. 정점 열만 UNION이면 D 한 행, UNION ALL이면 D 두 행이며 경로 열을 포함하면 두 다른 경로가 남는다.

  2. dense_rank<=2는 세 명, 유일 ID 보조 키를 둔 row_number<=2는 두 명이다.

  3. 동시 조인 여섯 행의 항목 합은 90, 결제 합은 60이다.

  4. 항목과 결제를 각각 주문별 요약하면 O1의 한 행에서 각 합 30을 읽는다.

같은 SQL 문법이라도 묻는 대상의 단위와 중복·동률 정책을 다르게 정하면 다른 결과가 정답이다. 이 사례는 문서 의미와 작은 자료의 손검산이다.
