소단원 2.1

엔터티·속성·관계

제목이 같은 책 두 권을 어떻게 구별해 기록할까?

준비 개념과 학습 목표

준비 개념

  • 집합은 서로 다른 대상들의 모음이다. 같은 원소를 두 번 적어도 집합에서는 두 대상이 되지 않는다.

  • 식별자는 이름이 같아도 대상을 구별하는 값이다. 모든 허용 상태에서 서로 다른 대상은 다른 식별자를 가져야 한다.

  • 순서쌍 (m,c)는 회원과 실물의 역할을 순서대로 지정한다. 역할 순서를 바꾸면 같은 관계가 아니다.

학습 목표

  • 엔터티 종류·대상·속성을 구별한다.

  • 관계의 역할과 관계 속성을 명시한다.

  • 현재 사실과 이력의 식별 조건을 구분한다.

같은 학생이 같은 강의를 다시 들으면 같은 사실을 덮어써야 할까?

학생 S1이 강의 C1을 봄과 가을에 각각 수강했다. 학생과 강의를 연결하는 관계만 필요하다면 (S1,C1) 한 쌍으로 충분할 수 있다. 그러나 두 번의 수강과 서로 다른 성적을 보존하려면 수강이라는 사건을 구별해야 한다. 무엇을 한 개로 셀 것인가라는 업무 질문이 먼저이고, 식별자 선택은 그 답을 표현한다.

같은 강의는 매년 여러 분반으로 열릴 수 있다. 강의는 과목 설명이고 개설 강의는 학기·분반·강의를 가진 실제 운영 대상이다. 학생과 개설 강의를 연결하면 서로 다른 학기의 수강을 구분할 수 있다. 한 개설 강의를 여러 번 수강하는 것도 허용한다면 시도 번호나 독립 수강 ID가 더 필요하다. 이름이 같은 데이터가 항상 같은 엔터티인 것은 아니다.

독립 수강 ID를 붙였다고 모든 규칙이 보장되지는 않는다. 업무상 학생당 한 개설 강의에 수강은 최대 한 번이라면 (학생 ID,개설 ID)의 유일성도 필요하다. 또 수강 인원을 개설 강의에 저장한다면 실제 수강 행 수와 맞게 변경할 책임이 생긴다. 계산 가능한 속성의 저장은 계산 비용을 줄일 수 있지만 새로운 일치 조건을 만든다.

먼저 확인할 개념
  • 관계와 사건의 기본 구별

    엔터티 식별자와 관계의 대상·속성을 다시 확인한다.

  • 식별자로 연결한 관계형 모델

    학생·개설·수강을 독립 사실과 키로 연결하며 표의 줄 번호나 표시 이름을 식별자로 쓰지 않는다.

대상과 그 설명을 분리하기

엔터티는 구별해 다룰 개별 대상이고 엔터티 집합은 같은 종류의 대상들의 모음이다. 속성은 대상이나 관계를 설명하는 값이다. 설계는 어떤 사실을 구별해 보존할지 결정하는 일이다. 제목 문자열 하나가 현실의 책 한 권을 유일하게 가리키지는 않는다. 어떤 관찰에서 같아야 같은 대상인지 식별 규칙부터 정한다.

자체 도서 모형에서 Book은 서지 항목이고 Copy는 소장 실물이다. Book에는 book_id와 title, Copy에는 전역적으로 유일한 copy_id와 shelf를 둔다. 제목이 모두 별인 b1,b2도 서로 다른 서지일 수 있고 b1의 c1,c2도 서로 다른 실물이다. 예시에서 속성 값이 우연히 다르다고 영구 키 제약을 추론하지 않는다. 키는 모든 허용 상태에 대한 규칙이다.

관계의 역할과 속성

관계는 엔터티 사이의 연관이다. Of(c,b)는 실물 c가 서지 b에 속함을 뜻한다. Member는 member_id로 식별하고 현재 활성 Loan(m,c)는 회원 m이 실물 c를 대출 중이라는 관계다. 관계 역할의 순서를 명시하며 실물과 서지를 혼합하지 않는다. 관계는 해당 엔터티들의 조합 중 실제 존재하는 부분집합이다. 이 자체 모형에서 각 Copy는 정확히 하나의 Book에 속한다. 이 조건은 관계 이름만에서 따라오는 일반 법칙이 아니라 선택한 설계 정책이다.

대출 시작 시각 start는 해당 Loan의 속성이다. 회원 생일이나 책 제목과 달리 어느 회원이 어느 실물을 언제 빌렸는지를 설명한다. 현재 모형은 활성 대출만 저장하고 실물 하나에 활성 Loan은 최대 1개라는 정책을 둔다. start는 정해진 시간대의 논리 시각 기호이며 실측값이 아니다. 반환 뒤 같은 회원과 실물이 다시 만나는 이력을 보존하려면 loan_id 같은 사건 식별과 상태·시각 조건이 필요하다.

기준 사실과 파생 사실

활성 Loan이 기준 사실이면 회원의 대출 수는 그 회원에 연결된 실물 수로 계산한다. 실물의 loaned 표시도 관계 존재에서 유도된다. count나 표시를 별도로 저장할 수 있지만 관계와 다른 값을 갖지 않도록 갱신 계약이 필요하다. 객체 이름이나 화면 표시가 같다는 사실은 자동 동기화의 증거가 아니다.

종이 엔터티 집합에는 NULL 원소를 넣지 않는다. SQL에서는 선택 관계 부재를 NULL 열 또는 관계 행 부재로 표현할 수 있으나 의미를 따로 정한다. 소유자 키와 부분 키로만 식별하는 대상을 약한 엔터티로 모델링할 수 있다. 전역 copy_id를 둔 지금 Copy는 그런 식별 의존을 가정하지 않는다.

중간 과정을 따라가는 예제

Book={(b1,별),(b2,별)}, Copy={c1,c2,c3}, Member={m1,m2}, Of={(c1,b1),(c2,b1),(c3,b2)}다. 활성 Loan={(m1,c1,start=t1),(m2,c3,start=t2)}에서 회원별 대출 수, b1의 실물 수, 미대출 실물을 구하라.

  1. b1/b2는 제목은 같지만 식별자가 달라 서지 2개다. 실물은 3개다.

  2. Of에서 b1의 실물은 c1,c2 두 개이고 b2에는 c3 하나다.

  3. Loan에서 m1에는 c1, m2에는 c3 하나씩 연결되어 회원별 대출 수는 1/1이다.

  4. 활성 실물 집합{c1,c3}을 전체 Copy에서 빼면 미대출 집합{c2}다. start t1/t2는 각 대출 관계의 속성이다.

서지 2/실물 3, b1 실물 2, 회원 대출 수 1/1, 미대출{c2}다. 개념적 사실 계산이며 실제 도서관 기록이 아니다.

조건을 바꾸어 비교하기

덮어쓰기가 사건을 잃게 한다

수강 표의 기본키를 (student_id,course_id)로 정하고 S1의 C1 봄 성적 B, 가을 성적 A를 보존하려 한다. 가능한가?

  1. 두 사건의 키가 모두 (S1,C1)이다.

  2. 유일한 키에 두 행을 넣을 수 없고 갱신하면 봄 성적을 잃는다.

  3. 개설 O봄/O가을을 별도로 식별하면 (S1,O봄),(S1,O가을)을 구별한다.

현재 키로 두 사건을 보존할 수 없다. 업무 범위에 맞게 개설을 식별해야 한다.

비교할 점

학생·강의를 연결하는 현재 관계와 모든 수강 사건의 이력은 서로 다른 요구다.

새 ID가 업무 중복을 막지는 않는다

한 개설에 학생당 수강을 최대 한 번만 허용한다. (E1,S1,O봄),(E9,S1,O봄)의 독립 ID는 다르다. 유효한가?

  1. 수강 ID는 E1/E9로 유일하다.

  2. 업무의 대상 쌍은 두 행 모두 S1/O봄이다.

업무 규칙을 위반한다. 기본키와 별도로 학생·개설 쌍의 유일성 조건이 필요하다.

비교할 점

기술 식별자의 유일성은 모든 업무상 중복의 부재를 뜻하지 않는다.

종이와 본문으로 직접 해보기

Loan의(m1,c1)을 제거하고(m1,c2,start=t3)를 추가하면 대출 수와 미대출 집합은? 같은(m1,c2)의 과거 재대출 사건도 현재 관계만으로 모두 구별 가능한가?

힌트 보기

활성 관계 집합을 적고 실물 존재를 센다. 현재 상태와 과거 여러 사건을 구분한다.

풀이 보기

활성 관계는{(m1,c2),(m2,c3)}라 수는 1/1, 미대출은{c1}이다. 현재 관계만으로 과거 여러 사건을 구별하지 못하므로 사건 식별·이력 스키마가 필요하다.

오해와 반례

제목이 같으면 같은 책 엔터티이고 대출 시작은 회원의 속성이다.

b1/b2는 같은 제목이어도 다른 서지다. 한 회원이 여러 실물을 다른 시각에 빌릴 수 있어 start는 해당 대출 관계나 사건에 붙인다.

연습 1 · 값과 상태 예측

S1이 C1의 O봄과 O가을을 수강했다. 학생·개설 쌍이 키일 때 서로 다른 행인가?

힌트 1

학생은 같지만 개설 ID는 다르다.

힌트 2

쌍의 두 성분을 모두 비교한다.

풀이와 답 확인

  1. (S1,O봄)과 (S1,O가을)은 두 번째 성분이 다르다.

서로 다른 행으로 보존할 수 있다.

엔터티의 ID와 관계 또는 사건의 ID는 같은 역할이 아니다.

힌트 1

인원은 어떤 행 집합에서 계산되는가?

힌트 2

취소는 행과 집계 속성에 동시에 영향을 준다.

풀이와 답 확인

  1. 저장 인원 12와 실제 행 수 11이 다르다.

저장한 파생 속성의 일치 조건이 깨졌다. 재계산 또는 변경 관리가 필요하다.

흔한 오답에서 다시 생각하기

이 업무에서 인원은 수강 행 수로 정의되므로 두 표현의 일치 책임이 생긴다.

연습 3 · 직접 만들어 보기

한 개설을 같은 학생이 두 번 시도할 수 있고 각 시도의 성적을 보존해야 한다. 식별 범위를 정하라.

힌트 1

학생·개설 쌍만으로는 두 사건이 구별되지 않는다.

힌트 2

시도 번호는 어느 쌍 안에서 유일한지 정한다.

풀이와 답 확인

  1. (학생,개설,시도 번호)를 사건 키로 정하거나 독립 수강 ID를 사용한다.

  2. 시도 번호를 쓰면 같은 학생·개설 안에서 번호가 유일해야 한다.

사건별 식별자와 필요한 업무 유일성 조건을 명시한다.

흔한 오답에서 다시 생각하기

성적을 키에 넣으면 항상 안정적인 식별자가 된다.

성적은 정정될 수 있는 속성이며 같은 성적의 시도도 존재하므로 사건 식별에 부적합하다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

직원이 다른 직원을 관리한다. 관리자와 부하 직원 엔터티를 무조건 서로 다른 표로 나누어야 하는가?

힌트 1

동일한 사람이 두 역할을 할 수 있다.

힌트 2

관계의 양 끝 역할을 명시한다.

풀이와 답 확인

소단원 2.2

카디널리티와 참여 제약

부서는 여러 직원을 둘 수 있다는 말이 모든 직원의 소속도 보장할까?

준비 개념과 학습 목표

준비 개념

  • 이항 관계 R⊆E×D는 직원 E와 부서 D 사이의 실제 소속 쌍들의 집합이다.

  • 연결 수 deg_E(e)=|{d:(e,d)∈R}|, deg_D(d)=|{e:(e,d)∈R}|는 방향별 참여 횟수다.

  • (min,max)는 각 대상의 허용 연결 수다. ∞는 정해진 유한 상한이 없다는 표기이며 실제 무한 행이 있다는 뜻이 아니다.

학습 목표

  • 최대 수와 최소 참여를 구별한다.

  • 모든 대상의 연결 수로 유효 상태를 판정한다.

  • 외래키·NULL·유일성을 개념적 조건과 연결한다.

직원 수가 충분하면 모든 부서가 반드시 직원 한 명을 갖는가?

직원 집합 E, 부서 집합 D 사이의 배속 관계 R을 그려 보자. 직원은 정확히 한 부서에 속하고 부서는 한 명 이상 두 명 이하를 가져야 한다. 직원 쪽 관계 수는 1, 부서 쪽 관계 수는 1 또는 2다. 두 쪽에서 센 관계의 총수는 같지만 각 대상의 관계 수까지 자동으로 정해지지는 않는다.

부서가 세 개면 직원 수는 적어도 3, 많아도 6이어야 한다. 직원 네 명이라는 수는 이 범위 안이지만 실제 배속이 (2,2,0)이면 세 번째 부서의 최소 참여를 위반한다. (2,1,1)은 조건을 만족한다. 총수 조건은 가능한지 거르는 조건이며 지금 저장한 관계의 유효성을 증명하는 것은 아니다.

직원마다 부서 ID가 필수이며 유효한 부서를 참조한다고 해도 직원 없는 부서가 남을 수 있다. 또한 부서 ID를 직원 표에서 유일하게 만들면 직원 두 명이 같은 부서에 속하지 못하므로 최대 2라는 의도와 다르다. 최소 참여, 최대 참여, 각 행의 참조 존재를 각각 다른 질문으로 검사한다.

  • 유일한 대응과 존재

최대 수와 최소 수

최대 카디널리티 조건은 얼마나 많이 연결될 수 있는지 정한다. 직원당 부서 최대 1은 deg_E≤1이다. 최소 참여는 반드시 연결되어야 하는지를 정하며 직원 전원 참여는 deg_E≥1이다. 두 조건을 합해야 정확히 1이다. 최대 1만 있으면 소속 없는 직원도 허용한다.

그림마다 화살표나 갈퀴가 어느 쪽의 수를 적는지 다르므로 여기서는 수식과(min,max)를 명시한다. 직원(1,1)/부서(0,∞)는 직원마다 정확히 한 부서, 부서마다 직원 0명 이상이다. E에서 D로 다대일이라고 불러도 부서가 반드시 직원이 있다는 결론은 없다. 일쪽이라는 이름이 최소 1을 자동 뜻하지 않는다.

모든 대상에 대한 조건

유효 관계는 먼저 R⊆E×D여서 양쪽 대상이 존재해야 한다. 다음 모든 e와 d의 연결 수가 지정 범위 안에 있어야 한다. 한 사례가 맞아도 앞으로 모든 삽입·삭제가 조건을 유지하는지는 별도 문제다. 마지막 직원을 옮긴 뒤 빈 부서를 허용할지는 최소 참여 정책에 달려 있다.

E={e1,e2,e3},D={d1,d2},R={(e1,d1),(e2,d1)}에서는 e3 연결 수 0이 최소 1을 어긴다. d2도0이지만 부서 최소0이라 유효하다. (e3,d2)를 추가하면 모든 직원이1이다. 기존(e2,d1)을 남기고(e2,d2)도 추가하면 e2의2가 최대 1을 어긴다. 데이터가 문법상 읽히는 것과 제약을 만족하는 것은 다르다.

선언 제약의 방향

직원 행에 부서 식별자 한 칸을 두고 외래키를 선언하면 참조할 대상의 존재를 검사할 수 있다. NULL 허용은 소속 부재를 허용하며 NOT NULL과 외래키를 함께 쓰면 직원 쪽 정확히 한 참조를 표현한다. 부서 식별자 열까지 UNIQUE를 붙이면 같은 부서의 여러 직원을 막아 원래 다대일 요구와 달라진다.

부서마다 최소 1명이라는 추가 조건은 직원의 외래키만으로 보장되지 않는다. 부서만 있고 직원 0명인 상태도 외래키를 만족하기 때문이다. 부모의 최소 참여는 전체 상태 제약과 갱신 계약이 더 필요하다. 이 단원은 종이의 완료 상태를 판정하며 실제 지연 검사·동시 갱신·잠금이나 트리거를 구현·시험하지 않는다.

준비 개념과 학습 목표

준비 개념

  • 스키마는 표·열·자료형·키·제약 등의 규칙이고 인스턴스는 현재 구체 행들이다.

  • 기본키는 행을 구별하고 외래키는 대상의 식별자를 참조한다. 고유성·부재 금지·참조 존재는 다른 조건이다.

  • NULL은 SQL의 미지정·부재 등을 나타내는 표지이며 빈 문자열·숫자0·엔터티 식별자와 동일하지 않다.

학습 목표

  • 엔터티와 다대다 관계의 표를 구성한다.

  • 1:N·1:1·약한 엔터티의 키 조건을 연결한다.

  • 선언 제약이 보존하지 않는 조건도 반례로 확인한다.

각 ID가 실제 존재해도 서로 다른 캠퍼스의 정보를 섞을 수 있을까?

캠퍼스 A와 B에 같은 학생 번호 S1이 있을 수 있다. 학생의 실제 식별자가 (campus_id,student_id)라면 A/S1과 B/S1은 다른 학생이다. 수강 행의 두 열을 각각 독립적으로 참조하면 캠퍼스 A도 존재하고 번호 S1도 어딘가에 존재한다는 조건만 확인할 수 있다. A/S1이라는 쌍의 존재를 보장하려면 쌍 전체를 참조해야 한다.

ER에서 한 대상의 식별 범위가 다른 엔터티에 달려 있으면 복합 키가 자연스럽다. 건물 안 방 번호, 캠퍼스 안 학생 번호처럼 같은 번호를 여러 범위에서 재사용할 수 있다. 별도 전역 ID로 바꾸는 설계도 가능하지만 기존 범위 안 번호의 유일성이라는 업무 조건은 여전히 표현해야 한다. 모델을 표로 바꾸며 조건을 잃지 않는 것이 목적이다.

제약의 빈값 의미도 읽어야 한다. PostgreSQL 18의 CHECK는 참 또는 NULL이면 통과하므로 score≥0만으로 점수 필수를 보장하지 않는다. 복합 외래 키의 기본 MATCH SIMPLE은 참조 열 중 하나라도 NULL이면 검사를 피할 수 있고 MATCH FULL은 전부 NULL일 때만 피하며 일부 NULL을 거절한다. 필수 관계라면 해당 열들의 NOT NULL이 필요하다. 이 단원은 문서의 규칙으로 작은 상태를 판정하며 서버 실행 증거를 만들지는 않는다.

역할을 키 열로 바꾸기

자체 모형에서 Student는 sid, Course는 cid로 식별하고 Enroll(s,c)의 관계 속성은 grade다. 같은 학생/강좌 쌍은 현재 최대 한 수강 사실이며 재수강 학기 이력은 제외한다. 양쪽 참여는 0개 이상인 다대다다. Student(sid,name), Course(cid,title), Enroll(sid,cid,grade) 세 표에 역할의 엔터티 키를 배치한다.

Enroll의 복합 기본키(sid,cid)는 같은 쌍 중복과 두 키열 NULL을 금지한다. sid/cid는 해당 엔터티키의 외래키다. sid만 UNIQUE면 학생의 여러 강좌, cid만 UNIQUE면 강좌의 여러 학생을 막는다. grade는 수강마다 달라지는 관계 속성이므로 Enroll에 남긴다. 한 엔터티에 붙이면 상대에 따라 달라지는 값을 표현하지 못한다.

최대와 최소에 맞춰 배치하기

직원마다 정확히 한 부서, 부서는0명 이상인 별도1:N 모형은 Department(did PK),Employee(eid PK,did NOT NULL FK→Department)처럼 N쪽 참조로 표현한다. 부서 최소 1명은 따르지 않는다. 1:1을 같은 방식으로 표현하려면 참조열 UNIQUE로 상대 최대 한 번을 제한하고 선택/필수 참여에 맞게 NULL 조건을 따로 둔다. 양쪽 필수 참여는 한쪽 NOT NULL만으로 끝나지 않는다.

Room이 건물키와 건물 안 호수로만 식별되면 PK(building_id,room_no),FK building_id→Building을 둔다. PK의 비NULL성과 쌍 고유성은 소유자 없는 식별과 같은 건물의 호수 중복을 막되 다른 건물의101호를 허용한다. 소유자 삭제 정책과 이력 보존은 별도다. 단순 이항 변환을 세 역할 이상이나 복잡한 재귀 관계에 무조건 적용하지 않는다.

SQL 제약의 보장 범위

PostgreSQL 18 기본 UNIQUE는 NULL끼리 같다고 보지 않아 여러 NULL을 허용한다. 기본 단일 FK의 NULL도 대상 존재를 요구하지 않는다. 일반 복합 FK의 기본 MATCH SIMPLE에서는 참조 열 중 하나라도 NULL이면 참조 존재 검사에서 빠진다. MATCH FULL에서는 전부 NULL일 때만 검사를 피하며, 일부만 NULL인 조합은 거절하고 전부 비NULL이면 대응하는 참조 대상이 있어야 한다. 예를 들어 (a,NULL)은 SIMPLE에서 회피하지만 FULL에서는 거절된다. 필수 복합 역할이라면 참조 열 전체의 NOT NULL로 회피를 막는다. 앞 Enroll의 두 키 열은 이미 PK로 비NULL이다. NULLS NOT DISTINCT 선언은 기본 UNIQUE와 다른 계약이다.

Student/Course만 있고 Enroll이 비어 있어도 앞 스키마는 유효하다. 모든 학생 최소 한 강좌라는 요구를 추가하면 전체 갱신 계약이 더 필요하다. PostgreSQL CHECK를 다른 표의 현재 행 수에 기대는 식으로 써서 지속 보장이라고 주장하지 않는다. 실제 트리거·동시 갱신·지연 검사 구현은 별도 검증 대상이다. 여기서는 지정한 완료 상태의 허용 여부만 판정한다. 또한 CHECK는 결과가 참 또는 NULL이면 통과한다. 따라서 CHECK(score >= 0)만으로 score의 NULL을 금지하지 못하며 필수 값에는 NOT NULL도 필요하다. 이는 다른 행의 존재를 보장하는 문제와 별개의 조건이다.
