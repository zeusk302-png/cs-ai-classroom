소단원 6.1

내부·외부 조인

주문하지 않은 고객까지 보여 주려면 빈 칸을 어디에 붙여야 할까?

준비 개념과 학습 목표

준비 개념

  • 조인은 두 표의 행 쌍을 조건으로 연결한다. 같은 고객의 주문이 여러 개면 여러 결과 행이 생긴다.

  • NULL은 미지정 값이다. = 비교가 NULL을 포함하면 unknown이며 ON과 WHERE에서는 true인 경우만 통과한다.

학습 목표

  • 행·그룹·존재 검사 중 무엇을 반환하는지와 NULL 조건을 설명한다.

  • 가상 표에 질의를 종이로 적용하여 모든 결과 행을 구한다.

내부 조인은 모든 맞는 쌍을 만든다

INNER JOIN은 왼쪽 행마다 조건이 true인 오른쪽 행을 모두 붙인다. 고객당 결과 한 줄이라는 보장은 없고 주문 두 개면 그 고객은 두 줄이다. 아무 대응도 없는 고객은 내부 조인에서 나오지 않는다.

조인 키가 양쪽 모두 NULL이어도 NULL =NULL은 true가 아니다. 값이 비었다는 사실을 동일한 실체라고 추측하지 않는다. CROSS JOIN은 조건 없이 모든 쌍을 만들므로 크기 3과 4인 표의 행 쌍은 12개다.

외부 조인의 보존 방향

LEFT JOIN은 내부 조인의 맞는 쌍을 먼저 만들고 대응 없는 왼쪽 행에 오른쪽 모든 열을 NULL로 채운 한 행을 붙인다. RIGHT는 오른쪽을, FULL은 양쪽의 대응 없는 행을 보존한다. 대응 있는 행에 별도 빈 행을 추가하는 규칙은 아니다.

실제 주문의 amount가 NULL인 경우와 주문 자체가 없어서 모든 오른쪽 열이 NULL인 경우는 다르다. 주문 id가 NULL이 아니라는 가정에서 o.id를 보면 둘을 구분할 수 있다. amount만으로 주문 존재를 판단하면 실제 주문 102를 놓친다.

ON의 후보 제한과 WHERE의 결과 제거

외부 조인에서 ON에 가격 조건을 넣으면 그 조건까지 만족하는 주문의 대응을 찾고, 없으면 고객을 빈 주문 열과 함께 보존한다. WHERE에 같은 가격 조건을 넣으면 조인 이후 만들어진 빈 행도 unknown이라 제거할 수 있다.

원하는 질문이 모든 고객의 고액 주문인지, 고액 주문을 실제 보유한 고객인지 먼저 적는다. 이를 기준으로 조건 위치를 고른다. SQL 최적화기의 물리 실행 순서와 이 논리적 의미의 단계를 혼동하지 않는다.

SELECT c.id, o.id, o.amount
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.id AND o.amount >= 20;

중간 과정을 따라가는 예제

고객 customers(id,name)는 (1,A),(2,B),(3,C), 주문 orders(id,customer_id,amount)는 (101,1,10),(102,1,NULL),(103,2,30),(104,NULL,5)다. 각 id는 서로 다르고 NULL이 아니며 customer_id와 amount는 NULL 가능하다. 아래 결과는 ORDER BY 없는 질의의 출력 순서 보장을 뜻하지 않는다. c.id =o.customer_id 내부/ 왼쪽/ 오른쪽/ 전체 조인의 결과 행 수를 구하자.

  1. 고객 1은 주문101/102와 맞아 2 행, 고객 2는 103과 맞아 1 행이다. 주문 104의 customer_id는 NULL이라 어느 고객과도 true로 맞지 않는다. 내부 조인은 3 행이다.

  2. LEFT는 고객 3에 (3,C,NULL,NULL,NULL)을 추가하여 4 행이다. 고객 1의 주문 102 행에는 주문 id102가 실제로 남고 amount만 NULL이다.

  3. RIGHT는 주문 104에 고객 열 NULL을 붙여 4 행이다. FULL은 고객 3의 빈 주문 행과 104의 빈 고객 행을 모두 더해 5 행이다.

  4. 왼쪽 조인 ON에 amount>=20을 더하면 고객1/3은 빈 주문 행, 고객 2는 103이라 3 행이다. 같은 조건을 WHERE에 넣으면 주문 101은 10으로 false,102/ 빈 행은 unknown,103 만 true라 1 행이다.

내부 3,LEFT4,RIGHT4,FULL5다. 가격 조건을 ON에 넣으면 3 행,WHERE에 넣으면 1 행이다.

종이와 본문으로 직접 해보기

원자료 LEFT 결과에서 o.id IS NULL인 행과 o.amount IS NULL인 행을 각각 찾자.

힌트 보기

주문 102는 실제 행이지만 amount가 NULL이다. 고객 3은 주문 자체가 없다.

풀이 보기

o.id IS NULL은 고객 3 빈 주문 행 1개다. o.amount IS NULL은 고객 1의 주문 102와 고객 3의 빈 행, 총 2개다. 두 조건은 같은 뜻이 아니다.

오해와 반례

LEFT JOIN은 항상 왼쪽 표와 똑같은 행 수이고 오른쪽 조건을 WHERE에 두어도 모두 보존한다.

고객 1의 주문이 두 개라 원자료 LEFT는 고객 3명을 4 행으로 늘린다. WHERE o.amount>=20은 빈 주문 행을 unknown으로 제거하여 1 행만 남긴다.

오른쪽 표에서 customer_id =1인 주문을 하나 더 추가하면 내부와 LEFT의 행 수가 각각 1 증가한다. 고객 수를 세려면 조인 행 COUNT(*)와 고객 id의 COUNT(DISTINCT c.id)를 구별해야 한다. 어떤 집계 단위를 세는지 먼저 적어 보자.

소단원 6.2

GROUP BY와 HAVING

빈 주문을 한 줄로 붙였는데 주문 개수가 1로 보인다면 무엇을 센 걸까?

준비 개념과 학습 목표

준비 개념

  • GROUP BY는 지정 열 값이 같은 입력 행을 묶어 그룹마다 집계한다. WHERE는 그룹 전에 행을, HAVING은 그룹 뒤의 그룹을 고른다.

  • COUNT(*)는 행을, COUNT(x)는 x가 NULL이 아닌 행을 센다. SUM과 AVG는 NULL이 아닌 값을 사용하고 NULL이 아닌 입력이 없으면 NULL이다.

학습 목표

  • 행·그룹·존재 검사 중 무엇을 반환하는지와 NULL 조건을 설명한다.

  • 가상 표에 질의를 종이로 적용하여 모든 결과 행을 구한다.

그룹의 단위와 표현 가능한 열

고객별 요약이면 고객 id를 그룹 키로 삼는다. 조인 결과에서 한 고객의 여러 주문 행이 한 그룹으로 들어간다. GROUP BY는 요약을 만드는 규칙이며 결과를 정렬하는 규칙이 아니므로 표시 순서가 필요하면 ORDER BY를 따로 쓴다.

그룹 안에서 값이 여러 개인 열을 집계 없이 선택하면 어떤 값을 내야 할지 불명확하다. 여기서는 선택하는 고객 id와 name을 모두 그룹에 둔다. PostgreSQL은 그룹 키가 기본키일 때 함수 종속을 인정하는 예외가 있지만 임의 주문 값까지 하나로 확정되는 것은 아니다.

NULL을 제외하는 집계와 빈 입력

LEFT가 만든 빈 주문 행도 COUNT(*)에서는 한 행이다. COUNT(o.id)는 실제 NULL이 아닌 주문 id만 세므로 미주문 고객에 0을 준다. COUNT(o.amount)는 금액이 알려진 주문만 세어 실제 주문 건수와도 다를 수 있다.

SUM/AVG의 NULL은 합계 0이나 평균 0으로 자동 바뀌지 않는다. COALESCE(SUM(...),0)는 표시 정책이다. 누락 금액을 0으로 보는 AVG(COALESCE(amount,0))와 알려진 금액만 평균 내는 AVG(amount)는 질문 자체가 다르다.

행 필터와 그룹 필터를 구별한다

HAVING SUM(amount)>=20은 고객 그룹의 전체 합을 기준으로 남긴다. WHERE amount>=20은 작은 주문을 먼저 버려 집계 입력을 바꾼다. 두 조건은 일반적으로 같지 않다.

두 주문 10과 15는 합 25라 HAVING을 통과하지만 WHERE에서는 둘 다 제거된다. 합계 기준을 개별 주문 기준으로 바꾸면 결과뿐 아니라 평균· 건수도 달라진다. 집계 전에 어떤 입력 행이 남았는지 종이에 표시한다.

SELECT c.id, c.name, COUNT(*) AS joined_rows,
       COUNT(o.id) AS orders_count, COUNT(o.amount) AS known_amounts,
       SUM(o.amount) AS total, AVG(o.amount) AS known_average
FROM customers AS c LEFT JOIN orders AS o ON o.customer_id = c.id
GROUP BY c.id, c.name;

중간 과정을 따라가는 예제

고객 customers(id,name)는 (1,A),(2,B),(3,C), 주문 orders(id,customer_id,amount)는 (101,1,10),(102,1,NULL),(103,2,30),(104,NULL,5)다. 각 id는 서로 다르고 NULL이 아니며 customer_id와 amount는 NULL 가능하다. 아래 결과는 ORDER BY 없는 질의의 출력 순서 보장을 뜻하지 않는다. 제시한 그룹 질의의 고객별 joined_rows/orders_count/known_amounts/total/known_average를 구하자.

  1. 고객 A에는 실제 주문 101의 10과 102의 NULL 두 행이 들어간다. COUNT(*)=2, COUNT(o.id)=2, COUNT(o.amount)=1이다.

  2. A 합은 10, 평균은 알려진 값 한 개10/1=10이다. NULL을 자동 0으로 넣어10/2=5라고 계산하지 않는다.

  3. 고객 B에는 103 하나라 세 count는1/1/1, 합 30, 평균 30이다.

  4. 고객 C에는 빈 주문 열의 한 행이라 count는1/0/0, SUM과 AVG는 NULL이다. 주문 104는 고객 대응이 없어 이 LEFT의 어떤 고객 그룹에도 들어오지 않는다.

A =(2,2,1,10,10), B =(1,1,1,30,30), C =(1,0,0,NULL,NULL)이다.

종이와 본문으로 직접 해보기

원자료 요약 뒤 HAVING COUNT(o.id)>=2와 HAVING SUM(o.amount)>=20은 각각 누구를 남기는가? A에 금액 20 주문 하나를 더하면 합과 알려진 평균은?

힌트 보기

행 count가 아닌 주문 id count와 NULL 제외 평균의 분모를 쓴다.

풀이 보기

건수 조건은 A만, 합 조건은 B만 남긴다. A에 20 추가 후 실제 주문 3개/ 알려진 금액 2개, 합 30, AVG =30/2=15다. NULL 금액 주문까지 평균 분모 3으로 삼지 않는다.

오해와 반례

주문 없는 고객도 LEFT 결과에 1 행이므로 실제 주문 1건이고 빈 합은 0이다.

C의 COUNT(*)=1은 조인에서 보존된 고객 행 수다. NULL이 아닌 주문 id를 세면 0이며 NULL이 아닌 합 입력이 없어 SUM은 NULL이다. 표시상 0을 원하면 COALESCE 정책을 명시한다.

한 단계 더

A의 알려진 금액 10· 누락 NULL에 AVG(COALESCE(o.amount,0))를 적용하면 5다. C의 빈 행에 같은 식을 쓰면 0이 나와 미주문을 0 금액 주문처럼 취급한다. 금액 누락과 주문 부재를 각각 어떤 의미로 보고 싶은지 적은 뒤 집계 정책을 선택하자.

소단원 6.3

상관 부분 질의·EXISTS

주문 여러 줄을 붙이지 않고 주문이 있다는 사실만 확인할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 상관 부분 질의는 안쪽 질의가 바깥 행의 열을 참조한다. 별칭으로 어느 범위의 열인지 명시한다.

  • EXISTS는 안쪽 결과가 한 행 이상이면 true, 없으면 false다. NOT EXISTS는 반대이며 NOT IN은 NULL이 있을 때 3값 논리가 개입한다.

학습 목표

  • 행·그룹·존재 검사 중 무엇을 반환하는지와 NULL 조건을 설명한다.

  • 가상 표에 질의를 종이로 적용하여 모든 결과 행을 구한다.

바깥 고객을 기준으로 안쪽 조건을 읽는다

c는 현재 바깥 고객이고 o.customer_id =c.id는 그 고객과 대응하는 안쪽 주문 조건이다. 논리적으로 각 바깥 행을 기준으로 존재를 판단하지만 DB가 반드시 매번 똑같은 절차로 실행한다고 보장하지는 않는다.

EXISTS 안에 SELECT 1을 써도 주문 개수 1이라는 뜻이 아니다. 여러 행이 만들어져도 존재 true 하나로 바깥 행을 통과시킨다. 출력 값이 NULL이어도 한 행이 존재하면 true다. 성능이나 부수 효과를 평가 횟수 추측에 기대지 않는다.

SELECT c.id FROM customers AS c
WHERE EXISTS (SELECT 1 FROM orders AS o
              WHERE o.customer_id = c.id AND o.amount >= 20);

조인의 증식과 존재 필터의 차이

내부 조인은 대응 주문마다 고객 행을 복제하지만 EXISTS는 바깥 원래 행의 통과 여부만 정한다. 고객 id가 고유라는 가정에서 해당 고객은 한 번 나온다. 바깥 표 자체에 같은 고객 행이 중복이면 EXISTS가 그것까지 자동 DISTINCT하는 것은 아니다.

NOT EXISTS로 주문 없는 고객을 찾을 때도 대응 비교의 NULL은 true가 아니다. customer_id가 NULL인 주문은 모든 고객을 주문 보유자로 만들지 않는다. 조건이 무엇을 동일한 고객이라고 보는지 읽는다.

NOT IN의 미지정 값과 집계의 함정

3 NOT IN(1,1,2,NULL)은 알려진1/2와 다르지만 NULL과의 비교가 unknown이라 전체가 unknown이고 WHERE를 통과하지 않는다. NOT EXISTS의 비존재 true와 다를 수 있다. NOT IN을 쓰려면 양쪽 NULL 정책을 별도 명시한다.

EXISTS(SELECT COUNT(*) FROM orders WHERE...)는 그룹 키 없는 집계가 빈 입력에도 count 0인 한 결과 행을 내므로 true다. 주문을 직접 찾는 EXISTS(SELECT 1 FROM orders WHERE...)와 의미가 다르다. 행의 값 0 과 행의 부재를 구별한다.

중간 과정을 따라가는 예제

고객 customers(id,name)는 (1,A),(2,B),(3,C), 주문 orders(id,customer_id,amount)는 (101,1,10),(102,1,NULL),(103,2,30),(104,NULL,5)다. 각 id는 서로 다르고 NULL이 아니며 customer_id와 amount는 NULL 가능하다. 아래 결과는 ORDER BY 없는 질의의 출력 순서 보장을 뜻하지 않는다. 주문이 하나라도 있는 고객, 금액 20 이상 주문이 있는 고객, 주문 없는 고객을 각각 EXISTS/NOT EXISTS로 판단하자.

  1. 고객 1의 대응 행은101/102라 EXISTS =true, 고객 2는 103으로 true, 고객 3은 0 행이라 false다. 따라서 전체 주문 존재 필터는 A/B다.

  2. 금액 20 조건까지 넣으면 101은 10으로 false,102는 NULL로 unknown,103은 30으로 true다. 금액 20 이상 존재는 B만이다.

  3. NOT EXISTS의 주문 전체 조건은 C만 true다. 주문 104의 NULL customer_id는 어느 고객과도 true로 같지 않아 판단을 바꾸지 않는다.

  4. 고객 3에 대해 3 NOT IN(SELECT customer_id FROM orders)은 목록 1,1,2,NULL의 unknown이다. 그래서 그 WHERE는 C를 남기지 않는다.

주문 존재 A/B, 고액 주문 존재 B, 주문 비존재 C다. NULL 포함 NOT IN은 C를 남기지 않는다.

EXISTS는 SELECT 1이면 항상 true이며 NOT EXISTS와 NOT IN은 항상 동치다.
