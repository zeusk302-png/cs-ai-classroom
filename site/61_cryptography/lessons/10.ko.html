소단원 10.1

이산로그·Diffie–Hellman

각자 숨긴 수를 직접 보내지 않고도 같은 값을 계산할 수 있을까요?

준비 개념과 학습 목표

준비 개념

  • 거듭제곱과나머지
  • 공개값과비밀값
  • 유한순환군의기본뜻

학습 목표

  • 이산로그의 입력과 찾는 값을 구별한다.
  • DH 두 방향의 공유값을 계산한다.
  • 값의 일치와 보안 가정을 구별한다.

나머지 세계의 거듭제곱

소수 p로 나눈 나머지의 곱셈에서0이 아닌 값들은 역원을 가집니다. 이 중 생성원 g의 거듭제곱이 만드는 순환군을 생각합니다. 군의 크기 q이면 지수는 q를 주기로 되풀이됩니다. 공개 g와 A=g^a를 보고 지수 a를 q를 법으로 찾는 문제가 이산로그입니다. 보통 실수 로그로 계산하는 문제가 아닙니다.

자체 종이 예제는 p=29,g=2입니다. 반복 두 배 후29로 나눠0..27 지수의 나머지를 쓰면1,2,4,8,16,3,6,12,24,19,9,18,7,14,28,27,25,21,13,26,23,17,5,10,20,11,22,15입니다. 다음2배는30이라1로 돌아옵니다. 서로 다른28개 값이라 이 예제의 군 크기는28입니다. 작은 전체 표를 만들 수 있어 암호용으로 안전하지 않습니다.

서로 다른 길로 같은 값을 계산

Diffie–Hellman에서A쪽은 비밀 a를 고르고 공개 A=g^a를 보내며,B쪽은 비밀 b를 고르고 공개 B=g^b를 보냅니다. A쪽은 B^a,B쪽은 A^b를 계산합니다. 군에서(B)^a=(g^b)^a=g^(ab)=(g^a)^b라 두 공유값이 같습니다. 처음부터 대칭키를 암호화해 보내는 방식과 다릅니다.

자체 예제 a=3,b=5이면A=8,B=3입니다. A쪽은3³=27,B쪽은8⁵를29로 나눈27을 얻습니다. p,g,A,B는 공개이고a,b와공유값은 비밀로 다루려는 대상입니다. 실제 키에는 적절한 군/지수/입력검증과후속 키유도 등 더 많은 조건이 필요합니다.

역문제와 난도 가정

이산로그를 풀 수 있으면 공개 A에서 a를 얻어 B^a로 공유값을 계산합니다. 공개g,g^a,g^b에서g^(ab)를 계산하는 문제를 CDH라고 부르며 이산로그와 같은 문제라고 단정하지 않습니다. 안전성에는 사용하는 군과 공격자의 계산 능력에 관한 가정이 붙습니다.

두 참가자가 같은 값을 얻었다는 대수적 확인은 도청자가 값을 못 구한다는 보안 증명이 아닙니다. 자체 예제에서는 표를 보고 8의 지수가 3임을 알아 공유값 27을 구할 수 있습니다. 실제 보안 크기나 알고리즘 권장값을 이 작은 예제에서 추정하지 않습니다. 다음 소단원은 값 교체가 가능한 공격자의 경우를 다룹니다.

중간 과정을 따라가는 예제

p=29,g=2,a=3,b=5인 자체 교환의 A,B와 공유값을 계산하라. B쪽의 8⁵는 중간마다 나머지를 줄여라.

  1. A=2³=8,B=2⁵=32≡3 (mod29)다.
  2. B^a=3³=27이다.
  3. 8²=64≡6,8⁴≡6²=36≡7,8⁵≡7×8=56≡27이다. 두방향이같다.

공개A8/B3와 공유값27이다. 종이 계산이며 실제 안전한 키를 만든 것이 아니다.

종이와 본문으로 직접 해보기

a만4로바꾼별도교환에서A와공유값을 계산하라. B=3,b=5는그대로다.

힌트 보기

2⁴=16이다. 3⁴와16⁵를각각29로나눈다.

풀이 보기

A=16,B^a=81≡23이다. 16²=256≡24,16⁴≡24²=576≡25,16⁵≡25×16=400≡23으로 일치한다. 이전 공유값 27을 재사용하는 계산은 아니다.

오해와 반례

두쪽 공유값이 같으면 도청자가 못 구한다는 증명도 끝난다.

작은 표에서A8의 지수3을 찾으면B3에서27을 바로 구합니다. 일치성 증명과 난도 가정은 구별합니다.

소단원 10.2

인증 없는 교환의 한계

서로 같은 수를 만들었는데도 누구와 만든 수인지 틀릴 수 있을까요?

준비 개념과 학습 목표

준비 개념

  • DH공개값과비밀지수
  • 통신중값교체
  • 기밀성과상대인증

학습 목표

  • 중간자두교환의공유값을손계산한다.
  • 공개키를안다는것과그주체를안다는것을구별한다.
  • 인증할교환맥락과신뢰의시작점을설명한다.

값을 바꿀 수 있는 상대

인증 없는 DH는 공개값이 정말 의도한 상대에게서 왔는지 확인하지 않습니다. 중간자가 메시지를 가로채고 다른 공개값을 보내면 A쪽과 B쪽은 각각 중간자와 공유값을 만들 수 있습니다. 큰 수의 이산로그를 푸는 대신 자신이 아는 지수로 두 교환을 이어 붙이는 공격입니다.

자체 예제의 정상 공개값은 A=8,B=3입니다. 중간자는 c=4의 C=16을 A쪽에 B의 값인 척 보내고,d=6의 D=6을 B쪽에 A의 값인 척 보냅니다. 여기서는 중간자가 두 경로의 공개값을 교체할 수 있다고 명시하며 실제 네트워크에 접근하지 않습니다.

서로 다른 두 공유값

A쪽은 C^a=16³≡7을 계산합니다. 중간자는 A^c=8⁴≡7을 계산해 A쪽 공유값을 압니다. B쪽은 D^b=6⁵≡4를 계산하고 중간자는 B^d=3⁶≡4를 계산합니다. A/B의 공유값 7과4는 서로 다르지만 중간자는 둘 다 압니다.

이 두 값에서 통신 키를 유도하여 메시지를 받아 읽고 다른 키로 보내는 가상 흐름을 생각할 수 있습니다. 정확한 라이브러리나 실제 암호문을 계산한 실습은 아닙니다. 자기 키로 태그를 정당하게 만들 수 있는 중간자는 각 구간의 인증암호를 깨뜨릴 필요도 없습니다. 상대 신원과 교환을 연결하는 인증이 빠진 것입니다.

교환과 신원 연결하기

인증된 키교환은 신뢰하는 공개 서명키나 미리 공유한 비밀 등 신뢰의 시작점과 교환의 주체·맥락을 연결합니다. 서명을 쓴다면 단순 공개값뿐 아니라 누가 누구에게 어떤 프로토콜에서 보낸 교환인지도 검토합니다. 인증서가 있다는 사실만으로 어떤 주체 이름도 믿어서는 안 됩니다. 신뢰 경로와 기대 이름 검사 등 프로토콜의 규칙이 함께 필요합니다.

자체 문서로 T=(버전v1,A주체,B주체,A공개값8,B공개값3)를 정해 보세요. A가 B의 신뢰된 서명키로 T를 검증한다고 가정하면,B공개값을16으로 바꾼 T′는 다른 인증 대상입니다. 안전한 서명·명확한 인코딩·기대 주체 검증이라는 가정이 있어야 변경 거절을 주장할 수 있습니다. 이 정리 틀은 TLS 핸드셰이크 전체를 구현한 예제가 아닙니다.

중간 과정을 따라가는 예제

위중간자모형의두공유값을각방향에서검산하라. 정상27과도비교하라.

  1. 16²≡24,16³≡24×16=384≡7,8⁴≡7이므로A/중간자는7이다.
  2. 6²≡7,6⁴≡20,6⁵≡120≡4이고3⁶=729≡4라B/중간자는4다.
  3. 정상A/B교환27과다르며두구간키도7≠4다. 중간자는자기지수4/6으로모두계산한다.

A구간7,B구간4,정상구간27이다. 일치성만따로봐서는정상상대와연결됐는지알수없다.

종이와 본문으로 직접 해보기

힌트 보기

풀이 보기

오해와 반례

DH뒤인증암호만쓰면처음누구와키를교환했는지도자동확인된다.

소단원 10.3

키 유도와 forward secrecy

오늘 인증키가 유출됐을 때 어제의 기록도 반드시 읽히는 것일까요?

준비 개념과 학습 목표

준비 개념

  • 공유군원소와바이트인코딩
  • 키용도분리
  • 장기키와세션키의시간선

학습 목표

  • 키유도의extract/expand역할을구별한다.
  • 출력길이와맥락레이블을계산한다.
  • 전방향안전성의유출대상/시점/삭제조건을설명한다.

공유값을 키 재료로 다루기

DH 결과는 군원소이며 이를 곧바로 모든 암호의 키로 쓰는 것과 키 유도는 다릅니다. HKDF의 extract는 입력 재료 IKM과 salt에서 중간 키 PRK를 만들고 expand는 PRK,맥락 info,요청 길이 L에서 출력 재료를 만듭니다. DH 입력은 extract를 건너뛰지 않는 범위로 생각합니다. 원래 입력에 없던 비밀 엔트로피가 유도로 새로 생기는 것은 아닙니다.

양쪽은 DH 원소를 같은 방식으로 바이트로 표현해야 합니다. 자체 공유값 27을 한쪽은 한 바이트 0x1b,다른 쪽은 문자열27의 두 문자 바이트로 넣으면 다른 입력이 됩니다. 실제 프로토콜의 정해진 인코딩을 따르는 의무를 보여 주는 예이며 HKDF 출력을 계산한 시험 벡터는 아닙니다.

용도와 길이 정하기

자체 설계표의 info는(프로토콜v1,주체A,주체B,용도A→B)입니다. B가 같은 수신 키를 유도하려면 같은 바이트 맥락을 써야 합니다. 반대 방향에는 용도B→A를 쓰며 암호키와 다른 용도의 재료도 레이블로 구분합니다. 다른 info의 키가 수학적으로 절대 충돌하지 않는다는 주장이 아니라 용도 분리와 보안 분석을 위한 입력입니다.

HKDF의 해시 출력 길이를 32바이트로 두고 L=42를 요청하면 expand 블록 두 개가 필요합니다. 첫 32바이트와 둘째 블록의 첫 10바이트로 42를 구성합니다. 각 블록은 이전 블록·info·한 바이트 카운터를 HMAC 입력에 연결하므로 같은 32바이트 출력을 단순 반복하는 것이 아닙니다. 이 절은 길이와 호출 연결만 손으로 검사합니다.

유출의 시간선과 삭제

전방향안전성은 정한 장기 인증키가 나중에 유출돼도 이미 완료한 세션의 키·기록을 보호하려는 성질입니다. 매 세션 새로운 비밀 지수,적절한 인증 교환,난도 및 키 유도 조건과 필요 없는 세션·임시 비밀의 삭제가 연결되어야 합니다. 현재 세션키 자체를 훔친 경우나 앞으로 위조할 수 있는 인증키를 이미 가진 공격까지 같은 보장으로 설명하지 않습니다.

자체 감사표를 t1교환,t2세션 종료,t3장기 서명키 유출로 정합시다. t2 뒤 로그에 비밀 a=3과 공개 B=3을 남겼다면 공유값 27을 계산할 수 있어 삭제 조건을 깨뜨립니다. 임시 지수와 키를 남기지 않는 변경 정책은 필요한 조건의 하나지만 p=29는 공개값만으로도 전수 표를 만들 수 있어 실제 전방향안전성을 보여 주지 못합니다. 안전한 군·전체 프로토콜의 가정과 작은 종이 계산을 끝까지 구별합니다.

중간 과정을 따라가는 예제

해시출력32바이트,L42인expand의블록수와잘라쓸길이를계산하라. 가상로그a3,B3이남은경우의공유값도구하라.

  1. ceil(42/32)=2라T1/T2두블록이필요하다.
  2. T1전체32와T2첫10을써42를얻으며T2입력에는T1/info/카운터02가들어간다.
  3. 로그a3과공개B3에서3³=27을계산한다. 실제HMAC출력이나강한군의비밀역산을수행한것은아니다.

블록2개·첫32+다음10,가상공유27이다. 길이검사와비밀보존위험을각기명시한조건에서확인했다.

종이와 본문으로 직접 해보기

L=64이면몇블록인가? 출력32바이트인HKDF의255블록한도에서최대바이트와8161바이트요청을판정하라. A→B키를받는B는info의방향을B→A로바꾸는가?

힌트 보기

255×32를계산한다. 송신/수신역할보다원래정보흐름의방향을레이블로정했다.

풀이 보기

64는두블록전체다. 최대8160바이트이고8161은그한도를넘는다. A→B의수신B는A→B레이블을같게쓰고B→A는반대통신키의별도info다. 실제HMAC바이트를생성하지않았다.

오해와 반례

키를유도하거나주기적으로바꾸면모든과거와미래기록이자동안전하다.

로그의비밀a3만남아도공유27을다시구합니다. 삭제/인증/새지수/난도가필요하고현재통신비밀유출뒤미래보호는별도성질입니다. 긴키출력도짧은비밀후보수를늘려주지않습니다.
