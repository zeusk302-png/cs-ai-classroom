소단원 10.1

이산로그·Diffie–Hellman

각자 숨긴 수를 직접 보내지 않고도 같은 값을 계산할 수 있을까요?

준비 개념과 학습 목표

준비 개념

  • 거듭제곱과나머지
  • 공개값과비밀값
  • 유한순환군의기본뜻

학습 목표

  • 이산로그의 입력과 찾는 값을 구별한다.
  • DH 두 방향의 공유값을 계산한다.
  • 값의 일치와 보안 가정을 구별한다.

나머지 세계의 거듭제곱

소수 p로 나눈 나머지의 곱셈에서0이 아닌 값들은 역원을 가집니다. 이 중 생성원 g의 거듭제곱이 만드는 순환군을 생각합니다. 군의 크기 q이면 지수는 q를 주기로 되풀이됩니다. 공개 g와 A=g^a를 보고 지수 a를 q를 법으로 찾는 문제가 이산로그입니다. 보통 실수 로그로 계산하는 문제가 아닙니다.

자체 종이 예제는 p=29,g=2입니다. 반복 두 배 후29로 나눠0..27 지수의 나머지를 쓰면1,2,4,8,16,3,6,12,24,19,9,18,7,14,28,27,25,21,13,26,23,17,5,10,20,11,22,15입니다. 다음2배는30이라1로 돌아옵니다. 서로 다른28개 값이라 이 예제의 군 크기는28입니다. 작은 전체 표를 만들 수 있어 암호용으로 안전하지 않습니다.

서로 다른 길로 같은 값을 계산

Diffie–Hellman에서A쪽은 비밀 a를 고르고 공개 A=g^a를 보내며,B쪽은 비밀 b를 고르고 공개 B=g^b를 보냅니다. A쪽은 B^a,B쪽은 A^b를 계산합니다. 군에서(B)^a=(g^b)^a=g^(ab)=(g^a)^b라 두 공유값이 같습니다. 처음부터 대칭키를 암호화해 보내는 방식과 다릅니다.

자체 예제 a=3,b=5이면A=8,B=3입니다. A쪽은3³=27,B쪽은8⁵를29로 나눈27을 얻습니다. p,g,A,B는 공개이고a,b와공유값은 비밀로 다루려는 대상입니다. 실제 키에는 적절한 군/지수/입력검증과후속 키유도 등 더 많은 조건이 필요합니다.

역문제와 난도 가정

이산로그를 풀 수 있으면 공개 A에서 a를 얻어 B^a로 공유값을 계산합니다. 공개g,g^a,g^b에서g^(ab)를 계산하는 문제를 CDH라고 부르며 이산로그와 같은 문제라고 단정하지 않습니다. 안전성에는 사용하는 군과 공격자의 계산 능력에 관한 가정이 붙습니다.

두 참가자가 같은 값을 얻었다는 대수적 확인은 도청자가 값을 못 구한다는 보안 증명이 아닙니다. 자기 예제에서는표를보고8의지수가3임을 알아27을 구할 수 있습니다. 실제 보안 크기나 알고리즘 권장값을 이 작은 예제에서 추정하지 않습니다. 다음 소단원은 값 교체가 가능한 공격자의 경우를 다룹니다.

중간 과정을 따라가는 예제

p29,g2,a3,b5인 자체교환의A,B와공유값을 계산하라. B쪽의8⁵는중간마다 나머지를 줄여라.

  1. A=2³=8,B=2⁵=32≡3 (mod29)다.
  2. B^a=3³=27이다.
  3. 8²=64≡6,8⁴≡6²=36≡7,8⁵≡7×8=56≡27이다. 두방향이같다.

공개A8/B3와 공유값27이다. 종이 계산이며 실제 안전한 키를 만든 것이 아니다.

종이와 본문으로 직접 해보기

a만4로바꾼별도교환에서A와공유값을 계산하라. B=3,b=5는그대로다.

힌트 보기

2⁴=16이다. 3⁴와16⁵를각각29로나눈다.

풀이 보기

A=16,B^a=81≡23이다.16²=256≡24,16⁴≡24²=576≡25,16⁵≡25×16=400≡23으로일치한다. 이전공유27을재사용하는계산은아니다.

오해와 반례

두쪽 공유값이 같으면 도청자가 못 구한다는 증명도 끝난다.

작은 표에서A8의 지수3을 찾으면B3에서27을 바로 구합니다. 일치성 증명과 난도 가정은 구별합니다.

소단원 10.2

인증 없는 교환의 한계

서로 같은 수를 만들었는데도 누구와 만든 수인지 틀릴 수 있을까요?

준비 개념과 학습 목표

준비 개념

  • DH공개값과비밀지수
  • 통신중값교체
  • 기밀성과상대인증

학습 목표

  • 중간자두교환의공유값을손계산한다.
  • 공개키를안다는것과그주체를안다는것을구별한다.
  • 인증할교환맥락과신뢰의시작점을설명한다.

값을 바꿀 수 있는 상대

인증 없는 DH는 공개값이 정말 의도한 상대에게서 왔는지 확인하지 않습니다. 중간자가 메시지를 가로채고 다른공개값을 보내면A쪽과B쪽은각각중간자와공유값을만들 수 있습니다. 큰 수의 이산로그를 푸는 대신자신이아는지수로두교환을이어붙이는공격입니다.

자체예제의정상공개값은A8,B3입니다. 중간자는c=4의C=16을A쪽에B의값인척보내고,d=6의D=6을B쪽에A의값인척보냅니다. 여기서는중간자가두경로의공개값을교체할수있다고명시하며실제네트워크에접근하지않습니다.

서로 다른 두 공유값

A쪽은C^a=16³≡7을계산합니다. 중간자는A^c=8⁴≡7을계산해A쪽공유값을압니다. B쪽은D^b=6⁵≡4를계산하고중간자는B^d=3⁶≡4를계산합니다. A/B의공유값7과4는서로다르지만중간자는둘다압니다.

이 두 값에서통신키를유도하여메시지를받아읽고다른키로보내는가상흐름을생각할수있습니다. 정확한라이브러리나실제암호문을계산한실습은아닙니다. 자기키로태그를정당하게만들수있는중간자는각구간의인증암호를깨뜨릴필요도없습니다. 상대신원과교환을연결하는인증이빠진것입니다.

교환과 신원 연결하기

인증된키교환은신뢰하는공개서명키나미리공유한비밀 등신뢰의시작점과교환의주체/맥락을연결합니다. 서명을쓴다면단순공개값뿐아니라누가누구에게어떤프로토콜에서보낸교환인지도검토합니다. 인증서가있다는사실만으로어떤주체이름도믿어서는안됩니다. 신뢰경로와기대이름검사 등프로토콜의규칙이함께필요합니다.

자체문서로T=(버전v1,A주체,B주체,A공개값8,B공개값3)를정해보세요. A가B의신뢰된서명키로T를검증한다고가정하면,B공개값을16으로바꾼T′는다른인증대상입니다. 안전한서명/명확한인코딩/기대주체검증이라는가정이있어야변경거절을주장할수있습니다. 이정리틀은TLS핸드셰이크전체를구현한예제가아닙니다.

중간 과정을 따라가는 예제

위중간자모형의두공유값을각방향에서검산하라. 정상27과도비교하라.

  1. 16²≡24,16³≡24×16=384≡7,8⁴≡7이므로A/중간자는7이다.
  2. 6²≡7,6⁴≡20,6⁵≡120≡4이고3⁶=729≡4라B/중간자는4다.
  3. 정상A/B교환27과다르며두구간키도7≠4다. 중간자는자기지수4/6으로모두계산한다.

A구간7,B구간4,정상구간27이다. 일치성만따로봐서는정상상대와연결됐는지알수없다.

힌트 보기

풀이 보기

오해와 반례

DH뒤인증암호만쓰면처음누구와키를교환했는지도자동확인된다.

키 유도와 forward secrecy

오늘 인증키가 유출됐을 때 어제의 기록도 반드시 읽히는 것일까요?

준비 개념과 학습 목표

준비 개념

  • 공유군원소와바이트인코딩
  • 키용도분리
  • 장기키와세션키의시간선

학습 목표

  • 키유도의extract/expand역할을구별한다.
  • 출력길이와맥락레이블을계산한다.
  • 전방향안전성의유출대상/시점/삭제조건을설명한다.

공유값을 키 재료로 다루기

DH결과는군원소이며이를곧바로모든암호의키로쓰는것과키유도는다릅니다. HKDF의extract는입력재료IKM과salt에서중간키PRK를만들고expand는PRK,맥락info,요청길이L에서출력재료를만듭니다. DH입력은extract를건너뛰지않는범위로생각합니다. 원래입력에없던비밀엔트로피가유도로새로생기는것은아닙니다.

양쪽은DH원소를같은방식으로바이트로표현해야합니다. 자체공유값27을한쪽은한바이트0x1b,다른쪽은문자열27의두문자바이트로넣으면다른입력이됩니다. 실제프로토콜의정해진인코딩을따르는의무를보여주는예이며HKDF출력을계산한시험벡터는아닙니다.

용도와 길이 정하기

자체설계표의info는(프로토콜v1,주체A,주체B,용도A→B)입니다. B가같은수신키를유도하려면같은바이트맥락을써야합니다. 반대방향에는용도B→A를쓰며암호키와다른용도의재료도레이블로구분합니다. 다른info의키가수학적으로절대충돌하지않는다는주장이아니라용도분리와보안분석을위한입력입니다.

HKDF의해시출력길이를32바이트로두고L=42를요청하면expand블록두개가필요합니다. 첫32바이트와둘째블록의첫10바이트로42를구성합니다. 각블록은이전블록·info·한바이트카운터를HMAC입력에연결하므로같은32바이트출력을단순반복하는것이아닙니다. 이절은길이와호출연결만손으로검사합니다.

유출의 시간선과 삭제

전방향안전성은정한장기인증키가나중에유출돼도이미완료한세션의키/기록을보호하려는성질입니다. 매세션새로운비밀지수,적절한인증교환,난도및키유도조건과필요없는세션/임시비밀의삭제가연결돼야합니다. 현재세션키자체를훔친경우나앞으로위조할수있는인증키를이미가진공격까지같은보장으로설명하지않습니다.

자체감사표를t1교환,t2세션종료,t3장기서명키유출로정합시다. t2뒤로그에비밀a=3과공개B=3을남겼다면공유27을계산할수있어삭제조건을깨뜨립니다. 임시지수와키를남기지않는변경정책은필요한조건의하나지만p29는공개값만으로도전수표를만들수있어실제전방향안전성을보여주지못합니다. 큰안전한군/전체프로토콜의가정과작은종이계산을끝까지구별합니다.

중간 과정을 따라가는 예제

해시출력32바이트,L42인expand의블록수와잘라쓸길이를계산하라. 가상로그a3,B3이남은경우의공유값도구하라.

  1. ceil(42/32)=2라T1/T2두블록이필요하다.
  2. T1전체32와T2첫10을써42를얻으며T2입력에는T1/info/카운터02가들어간다.
  3. 로그a3과공개B3에서3³=27을계산한다. 실제HMAC출력이나강한군의비밀역산을수행한것은아니다.

블록2개·첫32+다음10,가상공유27이다. 길이검사와비밀보존위험을각기명시한조건에서확인했다.

종이와 본문으로 직접 해보기

L=64이면몇블록인가? 출력32바이트인HKDF의255블록한도에서최대바이트와8161바이트요청을판정하라. A→B키를받는B는info의방향을B→A로바꾸는가?

힌트 보기

255×32를계산한다. 송신/수신역할보다원래정보흐름의방향을레이블로정했다.

풀이 보기

64는두블록전체다. 최대8160바이트이고8161은그한도를넘는다. A→B의수신B는A→B레이블을같게쓰고B→A는반대통신키의별도info다. 실제HMAC바이트를생성하지않았다.

오해와 반례

키를유도하거나주기적으로바꾸면모든과거와미래기록이자동안전하다.

로그의비밀a3만남아도공유27을다시구합니다. 삭제/인증/새지수/난도가필요하고현재통신비밀유출뒤미래보호는별도성질입니다. 긴키출력도짧은비밀후보수를늘려주지않습니다.

한 단계 더

RFC8446은PSK만쓰는교환과PSK+(EC)DHE의전방향안전성범위를구별하며0-RTT도같은보장을일괄주장하지않습니다. 프로토콜이름하나만보고판정하지말고실제모드·유출키·삭제시점의조건을찾아보세요. 이단원에서TLS연결이나키삭제검사를실행하지않았습니다.
