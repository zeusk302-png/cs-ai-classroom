소단원 14.1

영지식·양자내성 개요

비밀 자체를 보내지 않으면서, 그 비밀을 안다는 사실을 확인할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 나머지 연산과 역원

  • 대화형 인증

  • 전자서명과 키교환

학습 목표

  • 완전성·건전성·영지식을 구분한다.

  • 양자내성 KEM과 서명의 역할을 구별한다.

보여 주는 명제와 숨기는 증인

영지식은 공개 명제가 맞음을 확인하면서 추가 비밀 정보의 유출을 제한하는 증명 체계의 성질이다. 증인 w가 공개 입력 y와 관계R(y,w)를 만족한다고 생각하자. 정직한 절차가 맞는 명제를 받아들이는 완전성과 잘못된 명제를 속여 받아들이기 어렵게 하는 건전성은 영지식과 별개다. 지식 보유 증명은 증인 추출의 별도 의미도 다루므로 모든 대화형 증명과 같은 말로 쓰지 않는다.

영지식의 근거는 비밀 증인 없이 검증자가 보는 기록을 적절한 분포로 만드는 시뮬레이터다. 정직한 검증자만 다루는 조건과 악의적 검증자까지 다루는 정의를 구분한다. 비밀 숫자를 화면에 쓰지 않았다는 관찰만으로 이 성질을 증명할 수 없다. 공개 명제 자체가 드러내는 정보나 입력·출력의 공개도 없던 일이 되는 것은 아니다.

작은 대화식은 계산 연결만 보여 준다

자체 소수차수 부분군에서 공개 y=gˣ,증명자의 임시 비밀r,첫 메시지t=gʳ라 하자. 검증자가 도전값c를 보내면 응답은s=r+cx modq이고 gˢ=t·yᶜ를 확인한다. x나r를 직접 보내지 않지만 r를 재사용해 서로 다른c에 답하면 비밀이 복원될 수 있다. 아래p23/q11은 손으로 탐색 가능한 작은 공간이어서 실제 안전성을 제공하지 않는다.

정직한 검증자에 대한 개요에서는c와s를 먼저 균등하게 고르고t=gˢy⁻ᶜ로 기록을 만드는 시뮬레이션을 생각할 수 있다. 실제 대화에서 첫t가 도전보다 먼저 고정되는 순서는 건전성에 중요하다. 시뮬레이터가 기록을 만들 수 있다는 사실과 실제 참가자가 도전 뒤에 첫 메시지를 바꿔도 된다는 주장은 다르다.

양자내성은 역할과 가정을 가진다

양자내성 암호는 양자 컴퓨터를 쓰는 공격자까지 고려하는 알고리즘 설계 방향이다. 양자 통신 장비가 있어야만 실행되는 뜻은 아니다. NIST FIPS203의 ML-KEM은 공유 비밀을 확립하는 KEM, FIPS204의 ML-DSA와 FIPS205의 SLH-DSA는 서명이다. 공유 비밀은 후속 대칭 암호 등의 입력으로 사용되며 KEM을 문서 서명으로 바꾸어 부르지 않는다.

표준 이름만 바꿨다고 키 관리·신원 인증·재전송·난수·부채널 문제가 없어지지 않는다. 여기서는 공개 문서의 역할을 비교하며 표준 전체 적합성이나 모든 양자 공격에 대한 무조건적 안전성을 주장하지 않는다. 새 구현을 선택할 때는 최신 정오표·매개변수·프로토콜 조합을 함께 확인한다.

중간 과정을 따라가는 예제

자체 부분군 p=23,q=11,g=2에 x=3,r=4,c=2를 사용한다. y,t,s를 계산하고 검증식 양변을 비교하라. 2¹¹ mod23=1인 비항등 g는 소수11차수임을 사용한다.

  1. y=2³ mod23=8,t=2⁴ mod23=16이다. s=4+2·3 mod11=10이다.

  2. 왼쪽2¹⁰=1024 mod23=12다. 오른쪽16·8² mod23에서8² mod23=18이므로16·18=288 mod23=12다.

  3. 검증식은 일치한다. 이는 정직한 계산 연결의 예이며 작은 군에서 실제 위조 안전성·일반 영지식·양자내성을 증명한 것이 아니다.

y8,t16,s10이며 양변12로 같다. 비밀x를 직접 보내지 않는 식의 구조를 확인했다.

종이와 본문으로 직접 해보기

같은r=4를 다시 써 c=5에 응답했다고 가정하자. s₂와 검증식,이전s₁=10/c₁=2와의 두 기록에서 x=(s₁−s₂)(c₁−c₂)⁻¹ mod11을 계산하라.

힌트 보기

s₂=4+15 mod11이다. −3 mod11은8이며8의 역원은7이다. 이 활동은 재사용 실패의 작은 산술 반례다.

풀이 보기

s₂=8이고2⁸ mod23=3이다. 8⁵ mod23=16이므로16·16 mod23=3으로 검증된다. x=(10−8)·7 mod11=14 mod11=3이 복원된다. 두 다른 도전에 같은 임시 비밀을 재사용하지 않아야 한다.

소단원 14.2

타이밍·부채널·난수 실패

알고리즘의 수학이 안전해도, 실행 시간이나 반복된 난수가 비밀을 보여 줄 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 바이트와 XOR

  • 조건문과 반복

  • 난수와 균등 분포

학습 목표

  • 일정 시간과 상수 시간 복잡도를 구분한다.

  • 난수 예측·편향·nonce 재사용의 다른 실패를 설명한다.

답 이외의 관찰도 공격자의 입력이다

부채널은 출력값 외에 실행 시간·전력·캐시 접근 등의 관찰로 비밀 관련 정보를 추론하는 경로다. 처음 다른 바이트를 찾는 순간 비교를 끝내면 일치한 접두 길이에 따라 비교 횟수가 달라질 수 있다. 네트워크 지연이 섞여 있어도 그런 경로가 자동으로 없다고 결론낼 수 없다.

일정 시간 비교는 같은 길이 입력에서 비밀 데이터에 따라 달라지는 실행을 줄이는 목표다. 길이 n의 모든 바이트를 검사하는 구현은 O(n)일 수 있으므로 알고리즘 복잡도의 O(1)과 다르다. 실제 기계에서는 컴파일러·분기·메모리 접근 등을 함께 살펴야 한다. 이 교재의 반복 횟수 계산은 실제 실행 시간이 일정함을 검증한 측정이 아니다.

균등성과 비예측성을 구별한다

암호 비밀에는 공격자가 예측하기 어려운 난수 생성이 필요하다. 반복 가능한 고정 seed는 테스트 재현에는 유용하지만 모두가 아는 seed로 운영 비밀을 생성하면 숨겨진 정보가 아니다. VM 스냅샷 복구나 상태 복제도 출력 반복 문제를 만들 수 있다. 실패 처리를 무시하거나 약한 대체값으로 진행하는 정책도 검토한다.

작은 정수 범위를 나머지 연산으로 줄이면 균등한 입력조차 출력이 편향될 수 있다. 예를 들어0..7의8가지 값을%3으로 줄이면0과1은각3가지,2는2가지에서 나온다. 균등 출력만으로 비예측성이 보장되는 것도 아니다. 공식 암호 라이브러리의 목적별 난수 API를 읽고 두 성질을 구분한다.

nonce는 비밀과 같은 요구가 아니다

AEAD의 nonce는 공개될 수 있지만 같은 키에서 재사용하면 안 되는 알고리즘 조건이 있다. XChaCha20-Poly1305 문서는192비트 nonce에서 적절한 난수 생성 사용을 설명하고 같은 키에서의 유일성을 요구한다. 다른 알고리즘·짧은 nonce에 이 설명을 그대로 일반화하지 않는다.

스트림 암호 모형에서 같은 키/nonce로 같은 키스트림S가 나오면 C₁=M₁ XOR S,C₂=M₂ XOR S이므로 C₁ XOR C₂=M₁ XOR M₂다. MAC을 붙였다는 이유로 이런 기밀성 노출이 없어지지 않는다. 아래4비트 표는 XOR 항등식 활동이며 실제 AEAD 암호문·태그를 생성한 것이 아니다.

중간 과정을 따라가는 예제

4비트 자체 스트림 모형에서M₁=1010,M₂=0011,S=1100을 두 메시지에 재사용한다. 두 암호문과 XOR 관계를 구하라. 공격자가 M₁을 알 때 M₂를 복원하라.

  1. C₁=1010 XOR1100=0110,C₂=0011 XOR1100=1111이다.

  2. C₁ XOR C₂=1001이고 M₁ XOR M₂도1001이다. 같은S가 서로 상쇄한다.

  3. M₂=M₁ XOR(C₁ XOR C₂)=1010 XOR1001=0011이다. 이 누출은 키스트림 재사용이라는 모형의 전제 아래 나온다.

C₁0110,C₂1111,두 XOR1001이고 알려진M₁에서M₂0011을 복원한다.

비교 조기 종료 경로 하나를 다룬 것이다. 다른 비밀 분기·테이블 접근·길이·난수·컴파일 결과·전력 관찰은 별도다. 실제 일정 시간 함수를 사용해도 호출 주변의 오류 메시지나 처리 흐름까지 자동으로 동일해지지는 않는다.

암호 라이브러리로 복호화가 한 번 됐다면, 안전한 프로그램을 완성한 것일까?

준비 개념과 학습 목표

준비 개념

  • AEAD와 AD

  • 함수 반환값

  • 정상·경계·실패 테스트

학습 목표

  • 라이브러리의 입력·출력·실패 계약을 읽는다.

  • 왕복 테스트와 독립 기준값·실패·상태 테스트를 구분한다.

암호 알고리즘보다 먼저 사용할 계약을 적는다

프로그램의 보호 목적·키 소유자·저장 기간·공개 메타데이터·실패 시 처리 정책을 정한다. 지원되는 라이브러리 버전과 알고리즘·키/nonce/태그 길이·허용 메시지 길이·반환값을 공식 문서에서 확인한다. 직접 블록 암호와 MAC을 임의로 이어 붙이기보다 문서화된 고수준 AEAD 계약을 사용한다.

XChaCha20-Poly1305 combined 모드는 암호문 뒤에 인증 태그를 붙이며 AD도 인증하지만 숨기지는 않는다. decrypt의0은 성공,−1은 검증 실패 계약이다. 실패일 때 검증되지 않은 버퍼를 정상 평문처럼 사용하지 않는다. 실제 상수와 길이는 사용하는 라이브러리에서 확인하고 아래 자체 패킷 계산을 제품 규격처럼 사용하지 않는다.

한 번 되돌리기보다 더 많은 근거가 필요하다

왕복 테스트는 encrypt 후 decrypt 결과가 원문과 같음을 확인한다. 같은 버그가 양쪽에 있으면 왕복만으로 놓칠 수 있으므로 독립된 공식 테스트 벡터나 다른 검증된 구현과의 기준 비교도 필요하다. 암호문·태그·AD·키·nonce를 바꿨을 때 실패를 안전하게 처리하는지, 빈 입력과 잘린 입력의 길이 계약도 확인한다.

각 변경의 인증 실패가 실제로 발생했는지 기록해야 한다. 안전한 인증에서도 유한 태그의 우연 성공 확률은 존재하며 모든 수학적 입력에서 절대 실패라고 주장하지 않는다. 이 절에서는 설계한 기대 결과와 실제 실행 결과를 분리한다. 실제 호출하지 않은 테스트는 계획으로 남긴다.

키·nonce·출력의 상태도 시험한다

한 키의 nonce 유일성은 한 함수 호출의 성공 반환만으로 검증되지 않는다. 동시 작업·프로세스 재시작·VM 복원·백업 복구에서 키와nonce 상태의 관계를 확인한다. 로그에 키나 평문을 그대로 남기지 않으며 인증 실패 후 업무 실행이나 재시도가 어떤 상태를 만들지도 본다.

범용 비교 함수와 오류 계약도 주의한다. sodium_memcmp는 같으면0,다르면−1이고 사전식 정렬 함수가 아니다. 인증 실패를 성공처럼 해석하는 조건문은 좋은 암호 알고리즘을 사용해도 잘못된다. 라이브러리 사용·표준 적합성·부채널 측정·실제 사용자 검증은 각각 다른 확인이다.

중간 과정을 따라가는 예제

자체 저장 형식은 헤더4바이트,공개 nonce24바이트,본문 암호문은 평문과 같은 길이,태그16바이트를 순서대로 저장한다. AD인 헤더도 패킷에 한 번 저장한다. 평문7바이트일 때 총길이와 구조상 최소길이를 계산하고55바이트 입력의 형식을 판정하라. 이는 XChaCha의 실제API 출력 외에 자체 포장한 모형이다.

  1. 총길이는4+24+7+16=51바이트다. AD가 인증된다는 이유로 헤더를 다시 더하지 않는다.

  2. 빈 평문에서는4+24+0+16=44바이트다. 이보다 짧으면 자체 구조를 담지 못하므로 인증 호출 이전 형식 단계에서 거부한다.

  3. 55바이트면 본문 후보 길이55−44=11바이트다. 길이 조건은 맞지만 인증 성공을 증명하지 않는다. decrypt가 성공했다는 실제 결과가 없으므로 유효 평문으로 처리했다고 하지 않는다.

평문7의 패킷은51바이트,최소44바이트,55바이트 입력은 본문 후보11바이트다. 인증 유효성은 별도다.

종이와 본문으로 직접 해보기

새 평문9바이트의 총길이와43바이트 입력의 처리 단계를 구하라. 가상 decrypt 반환값A=0,B=−1에서 어떤 경우만 평문을 사용해야 하는가? 자체 nonce 장부(키K1,N1),(K1,N2),(K1,N1),(K2,N1)의 같은 키 중복도 표시하라.

힌트 보기

포장 오버헤드는44다. 입력 길이,반환값,키와nonce 쌍이라는 세 서로 다른 검사를 한다.

풀이 보기

9+44=53바이트다. 43은 최소 길이보다 짧아 형식 거부다. A의 성공일 때만 해당 API 계약에 따라 평문을 사용하고 B는 거부한다. 세 번째(K1,N1)은 첫 쌍의 재사용이다. (K2,N1)은 다른 키이므로 이 장부의 같은 키 중복이 아니지만 키 생성·파생의 올바름은 별도다.

오해와 반례

왕복이 되고 태그도 붙였으니 모든 보안 테스트를 통과했다.

왕복은 하나의 성공 경로다. 독립 기준값·변조 실패·경계 길이·반환값·nonce 상태·재시작과 업무 실패 처리를 별도로 확인한다. 종이에서 테스트를 계획했다는 사실은 실제로 실행해 통과했다는 증거가 아니다.
