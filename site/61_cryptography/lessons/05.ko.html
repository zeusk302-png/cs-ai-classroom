소단원 5.1

블록 암호의 모델

뒤섞는 표가 역으로 돌아간다고 반드시 비밀을 지켜 줄까?

준비 개념과 학습 목표

준비 개념

  • 키 k는 변환을 고르는 비밀 값, n 비트 블록은 길이가 고정된 입력이다.

  • 순열은 모든 입력과 출력을 일대일로 연결하며 역함수가 있다. PRP는 pseudorandom permutation, PRF는 pseudorandom function이다.

학습 목표

  • 명시한 정의와 적용 조건을 설명한다.

  • 자체 예제를 단계별로 풀고 반례의 원인을 찾는다.

같은 입력을 두 번 물어 나온 같은 출력도 순열과 함수의 차이인가요?

입출력 공간은 여덟 값 {0,…,7}입니다. 무작위 순열은 서로 다른 입력에 서로 다른 출력을 주고, 균등 무작위 함수는 서로 다른 입력에서 독립 균등 출력을 줍니다. 그러나 함수도 이미 물은 입력에는 저장된 같은 답을 돌려줍니다. 질의를 0, 1, 0, 2 순서로 하면 서로 다른 세 입력에서만 새 값을 정합니다.

검사 D는 서로 다른 입력끼리 출력 충돌이 있을 때 1을 냅니다. 순열에서 통과 확률은 0입니다. 함수에서 세 입력의 무충돌 확률은 (7/8)(6/8)=21/32이므로 통과 확률은 11/32입니다. 고정 세계의 절댓값 차 11/32와 공정 세계 추측의 성공률 43/64를 구별합니다. 작은 공간의 원시 함수 모델 비교이며 실제 블록 암호의 보안 공격 결과가 아닙니다.

고정 키는 한 순열을 정한다

블록 암호 E(k,x)는 같은 키와 블록에 같은 결과를 내는 결정적 함수다. 복호 D(k,E(k,x))=x가 모든 블록에서 성립하려면 고정 키의 E는 단사여야 한다. 유한 입력/ 출력 집합이 같으므로 전사이기도 하여 순열이다.

키가 바뀌면 다른 순열이 선택될 수 있지만 서로 다른 모든 키가 반드시 서로 다른 표라는 뜻은 아니다. 암호 설계의 정확한 복호 조건과 공격자가 키 없이 구분하기 어렵다는 보안 조건은 별도다.

무작위 함수와 순열의 차이

PRP 보안 게임은 무작위 키의 E 표와 균등 무작위 순열을 제한된 계산· 질의로 구별하는 실험이다. 알고리즘과 실제 보안 가정을 함께 읽어야 한다. PRF의 비교 대상은 무작위 함수라 서로 다른 입력의 출력 충돌이 가능하다.

무작위 함수도 같은 입력을 다시 물으면 앞과 같은 출력이어야 한다. 매번 새 무작위 출력이면 하나의 함수가 아니다. n 비트 순열은 서로 다른 입력에 충돌하지 않지만, 작은 질의 수에서는 순열과 함수의 차이가 작을 수 있다는 별도 분석이 필요하다.

블록 하나와 메시지 전체를 구별하기

블록을 각각 같은 키로 변환하면 같은 평문 블록은 같은 암호 블록이다. 순열 원시 함수만으로 긴 메시지의 반복 패턴· 무결성· 재전송 문제가 모두 해결되지는 않는다. 동작 모드와 인증 등 다음 설계 층이 필요하다.

아래 네 상태 표는 순열/ 역표 원리만 보인다. 상태가 작아 전체 표를 쉽게 알 수 있으며 실제 보안용 암호나 AES 축소 구현이 아니다. 실제 암호 장비나 메시지 보호를 수행하지 않았다.

중간 과정을 따라가는 예제

X ={0,1,2,3}, 고정 키 표 E:0 →2,1 →0,2 →3,3 →1이다. 역표와 메시지 블록[1,1,3]의 결과를 구하라.

  1. 출력 2의 원본 0이라 D(2)=0, 출력 0의 원본 1이라 D(0)=1이다.

  2. 출력 3의 원본 2 라 D(3)=2, 출력 1의 원본 3이라 D(1)=3이다.

  3. 각 블록을 표에서 찾아[0,0,1]을 얻는다.

  4. 처음 두 암호 블록이 같아 평문 반복이 남는다. 역표 존재만으로 이를 숨기지 않는다.

역표 0 →1,1 →3,2 →0,3 →2; 결과[0,0,1]이다.

조건을 바꾸어 비교하기

세 입력의 무충돌

입력 0, 1, 2의 함수 출력이 모두 다를 확률을 조건부로 구하세요.

  1. 첫 출력은 여덟 값 어느 것이든 됩니다.

  2. 둘째 출력은 첫째와 다른 일곱 값 중 하나여야 하므로 조건부 확률은 7/8입니다.

  3. 앞의 두 출력이 다를 때 셋째 출력은 둘과 다른 여섯 값 중 하나여야 하므로 조건부 확률은 6/8입니다. 두 확률을 곱하면 21/32입니다.

충돌 확률은 1−21/32=11/32입니다.

비교할 점

단순히 독립 사건으로 계산한 1−(7/8)²와는 조건이 다릅니다.

충돌 검사로 세계 추측

공정하게 순열 또는 함수를 고른 뒤 D가 1이면 함수, D가 0이면 순열로 추측하세요.

  1. 순열이면 충돌이 없으므로 항상 맞습니다.

  2. 함수이면 충돌이 발생하는 확률 11/32에서만 맞습니다.

  3. 전체 성공률은 (1+11/32)/2=43/64입니다.

성공률은 43/64이고 성공률 기준 advantage는 11/64입니다. 고정 세계의 확률 차는 11/32입니다.

비교할 점

PRF/PRP의 선택된 정규화와 성공률을 섞지 않습니다.

  2. 공정 추측의 성공률은 (1+1/8)/2=9/16입니다.

연습 2 · 오류 찾아 고치기

질의를 0, 1, 0, 2 순서로 했을 때 첫째와 셋째 답이 같으니 순열에서도 서로 다른 입력의 충돌이 발생했다고 했습니다. 고치세요.

힌트 1

첫째와 셋째의 입력은 같습니다.

힌트 2

충돌 검사는 입력이 다른 쌍만 비교합니다.

풀이와 답 확인

  1. 같은 입력 0에는 함수와 순열 모두 같은 답을 돌려줍니다.

  2. 이는 단사성 위반이 아닙니다. 서로 다른 입력 0, 1, 2의 답 사이에 충돌이 있는지만 검사합니다.

재질의 일관성은 정상이며 다른 입력 충돌과 구별합니다.

흔한 오답에서 다시 생각하기

어떤 두 답이 같으면 단사성이 깨졌다.

단사성은 서로 다른 입력의 답이 같지 않다는 조건입니다.

질의 답 표에서 입력 0의 출력은 3이고 입력 1의 출력은 5이며 입력 2의 출력은 3으로 관측됐습니다. 어떤 모델을 배제하며 그 이유는 무엇인가요?

힌트 1

입력 0과 입력 2는 서로 다릅니다.

힌트 2

고정 키 순열의 복호 정확성을 생각합니다.

풀이와 답 확인

  1. 서로 다른 입력 0과 2가 같은 출력 3으로 가므로 순열 모델과 모순입니다.

  2. 무작위 함수에서는 가능한 관측입니다. 이 일부 표만으로 모든 함수 값을 알아낸 것은 아닙니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

여덟 서로 다른 입력 전부를 물을 때 무작위 함수가 충돌하지 않을 확률은?

힌트 1

함수의 출력 표는 8⁸개이며 모두 같은 확률입니다.

힌트 2

단사 함수의 출력 표는 8!개입니다.

풀이와 답 확인

  1. 무충돌 확률은 8!/8⁸입니다.

  2. 순열의 무충돌 확률은 1이므로 충돌 검사의 확률 차는 1−8!/8⁸입니다. 작은 공간에서 모든 입력을 질의한 조건입니다.

확률 차가 정확히 1인 완벽한 구별은 아닙니다. 무작위 함수가 우연히 순열일 수 있습니다.

일반 함수 집합 안에 순열 표도 포함됩니다.

AES의 구조 개요

AES-256이면 한 번에 256비트 메시지 블록을 처리할까?

준비 개념과 학습 목표

준비 개념

  • 1바이트는 8비트, AES 상태는 16바이트의 4×4 배열이다.

  • XOR ⊕는 같은 비트 0/ 다른 비트 1이며 두 번 같은 값을 XOR 하면 원래 값으로 돌아온다. 라운드 키는 원키에서 확장한 단계별 키다.

학습 목표

  • 명시한 정의와 적용 조건을 설명한다.

  • 자체 예제를 단계별로 풀고 반례의 원인을 찾는다.

ShiftRows와 키 XOR의 순서를 바꾸면 같은 바이트에 키가 더해질까요?

16바이트 입력 X에서 인덱스 6의 값만 16진수 53이고 나머지 값은 00으로 정합니다. AES 상태 배치는 s[r,c]=X[r+4c]이므로 이 바이트는 행 2, 열 1에 있습니다. ShiftRows는 행 2를 왼쪽으로 두 칸 이동하여 이 바이트를 새 열 3, 출력 선형 인덱스 14로 옮깁니다. 값을 치환한 것이 아니라 위치를 바꾼 것입니다.

별도 라운드 키 K도 인덱스 6의 값만 0F입니다. ShiftRows(X⊕K)는 인덱스 14에 값 5C인 한 바이트만 갖습니다. 그러나 ShiftRows(X)⊕K는 인덱스 14에 값 53을, 인덱스 6에 값 0F를 갖습니다. 키에도 같은 위치 변환을 적용해야 두 식이 일치합니다. 이는 두 부분 변환의 추적이며 SubBytes·MixColumns·키 확장을 포함한 실제 AES 결과가 아닙니다.

블록 크기와 키 크기 따로 읽기

AES-128/192/256은 키 길이가128/192/256비트이고 블록은 모두 128 비트다. 라운드는 각각10/12/14다. 숫자 256을 블록 크기로 바꾸면 입력 분할과 구현 계약을 잘못 읽게 된다.

입력 바이트 in[i]를 상태 s[r,c]=in[r +4c]로 넣는다. 열을 먼저 채우는 순서이므로 사람이 종이에 행 순서로 적은 배열과 다를 수 있다. 16진수 표기와 바이트 인덱스도 분리해서 기록한다.

네 변환의 역할 구별하기

SubBytes는 각 바이트의 비선형 가역 치환, ShiftRows는 행 위치 이동, MixColumns는 유한체에서 열의 값을 혼합한다. AddRoundKey는 상태와 라운드 키의 XOR이다. 일반 실수 행렬 곱으로 AES 열 혼합을 계산하지 않는다.

처음 AddRoundKey 뒤 일반 라운드는 SubBytes →ShiftRows →MixColumns →AddRoundKey다. 마지막 라운드는 MixColumns를 생략한다. 키 확장은 암호문을 만드는 라운드와 별도 절차로 여러 라운드 키를 제공한다.

가역 단계와 구현 보안 구분하기

각 단계의 역변환을 역 순서로 적용하여 복호가 가능하다. 이것이 각 단계가 혼자 안전하다는 뜻은 아니다. 구조 설명은 표준 알고리즘의 보안 가정과 구현의 시간/ 전력 누출 검증을 대신하지 않는다.

아래는 바이트 배치/ 행 이동/ 키 XOR 일부만 종이에서 추적한다. S-box· 유한체· 전체 키 확장과 AES 전체 암호 결과를 실행하지 않았다. 계산 결과를 AES 테스트 벡터 통과로 표시하지 않는다.

중간 과정을 따라가는 예제

입력 인덱스 0..15를 바이트 이름으로 사용해 s를 채우고 ShiftRows에서 r 행을 r 칸 왼쪽 순환 이동하라. 별도 바이트 00110101 과 키 00001111의 XOR도 구하라.

  1. 입력 상태 행은[0,4,8,12]/[1,5,9,13]/[2,6,10,14]/[3,7,11,15]다.

  2. 0 행 유지,1 행은[5,9,13,1],2 행은[10,14,2,6]이다.

  3. 3 행은 세 칸 이동해[15,3,7,11]이다. 바이트 값 치환을 한 것은 아니다.

  4. 00110101 ⊕00001111 =00111010이다. 같은 키를 다시 XOR 하면 00110101이 된다.

행 이동 결과[0,4,8,12]/[5,9,13,1]/[10,14,2,6]/[15,3,7,11]; XOR00111010이다.

조건을 바꾸어 비교하기

인덱스를 행·열로 바꾸기

ShiftRows 후 입력 인덱스 6의 도착 위치를 식으로 구하세요.

  1. 6=2+4·1에서 행 인덱스 r은 2이고 열 인덱스 c는 1입니다.

  2. 행 r을 왼쪽으로 r칸 이동하면 원래 열 c의 바이트는 새 열 (c−r) mod 4에 놓입니다.

  3. 새 열은 (1−2) mod 4=3이고 선형 인덱스는 2+4·3=14입니다.

도착 인덱스는 14이며 바이트 값 53은 그대로입니다.

비교할 점

s′[r,c]=s[r,(c+r)mod4]는 새 위치에서 읽는 식입니다. 원래 바이트의 도착 열은 반대 부호입니다.

변환 순서를 바꿀 때 키도 바꾸기

두 위치 추적 결과가 같게 ShiftRows 후 XOR할 키를 구성하세요.

  1. K′=ShiftRows(K)로 정하면 키의 바이트 값 0F도 인덱스 14로 이동합니다.

  2. ShiftRows(X)⊕K′의 인덱스 14에서는 53⊕0F=5C입니다.

  3. 위치 순열은 XOR를 보존해 ShiftRows(X⊕K)=ShiftRows(X)⊕ShiftRows(K)가 성립합니다.

K를 그대로 두지 않고 K′로 표현을 바꾸면 이 부분 식이 일치합니다.

비교할 점

이는 AES 라운드 전체를 임의로 바꿔도 된다는 주장이 아닙니다.

종이와 본문으로 직접 해보기

AES-128의 SubBytes/MixColumns/AddRoundKey 실행 횟수를 구조에서 세고 AES-256과 비교하라.

풀이 보기

AES-128은 SubBytes10/MixColumns9/AddRoundKey11이다. AES-256은14/13/15이며 블록은 둘 다 16바이트다.

오해와 반례

ShiftRows는 바이트 값을 바꾸며 마지막에도 MixColumns가 있다.

ShiftRows는 위치 순환이다. 표준 마지막 라운드는 SubBytes/ShiftRows/AddRoundKey이고 MixColumns는 빠진다.

s′[r,c]=s[r,c+r]를 보고 출발 바이트가 새 열 c+r로 간다고 했습니다. 고치세요.

반복 구조·공격·가정

간단한 변환을 천 번 반복하면 그 자체로 안전해질까?

준비 개념과 학습 목표

준비 개념

  • 라운드는 상태 변환 한 단계이고 키 확장은 원키에서 여러 단계 키를 만든다.

  • 구별 공격은 무작위 대상과 다른 특징을 찾고 키 복구는 비밀 키를 찾는다. 사이드 채널은 출력 이외의 시간· 전력 같은 구현 관측이다.

학습 목표

  • 명시한 정의와 적용 조건을 설명한다.

  • 자체 예제를 단계별로 풀고 반례의 원인을 찾는다.

되돌릴 수 있는 변환을 여러 번 반복하면 무조건 안전할까요?

여덟 값의 작은 공간에서 f(x)=x+1, g(x)=3x를 쓰고 모든 계산을 mod 8로 합니다. 두 함수는 각각 역함수를 가집니다. 그런데 두 단계의 순서를 바꾸면 결과가 달라집니다. 역으로 돌아갈 때도 마지막 단계부터 풀어야 합니다. 이는 정확한 복호 조건이지 공격자가 규칙을 알아낼 수 없다는 보안 조건은 아닙니다.

키 k를 홀수 집합 {1,3,5,7}에서 균등하게 선택하고 E_k(x)=3x+k로 정합니다. 각 키의 함수는 순열이지만 같은 키에서 입력 0과 1의 출력 차는 항상 3입니다. 공격자는 키 값을 몰라도 이 관계를 검사합니다. 이 작은 반례로 반복 횟수·역함수 존재·무작위 순열처럼 보이는 성질을 따로 확인합니다. 실제 AES의 약점을 주장하는 예제가 아닙니다.

  • 블록 암호의 모델

가역 반복의 순서

E =E3 ∘E2 ∘E1이면 x에 E1,E2,E3 순서로 적용한다. 복호는 D3,D2,D1 순서다. 원래 순서로 역변환을 넣으면 일반적으로 원상 복원이 되지 않는다.

라운드 키가 많다고 독립 비밀 키의 총 길이가 늘어나는 것은 아니다. 원키가k비트이면 결정적 키 확장의 가능한 일정은 최대 2^k개다. 각 라운드 키를 독립 균등 표본이라고 가정하려면 별도 근거가 필요하다.

반복만으로 지워지지 않는 구조

비트 벡터 x에 XOR 키 a,b를 차례로 적용하면(x ⊕a)⊕b =x ⊕(a ⊕b)다. 여러 번 해도 하나의 XOR 표와 같다. 알려진 입력/ 출력 한 쌍에서 결합 키를 얻어 다른 입력을 예측할 수 있다.

이 예는 안전하지 않은 자체 장난감이다. AES의 비선형· 혼합· 키 확장을 XOR 두 단계로 동일시하지 않는다. 정해진 공격 모델과 계산량에서 무작위 순열과 구별하기 어렵다는 가정이 보안 설명의 핵심이다.

알고리즘과 장비 관측의 범위

전수 키 탐색, 차분/ 선형 분석 같은 알고리즘 공격과 시간/ 전력/ 결함의 구현 공격은 필요한 관측과 가정이 다르다. 한 모델의 분석만으로 실제 장비의 모든 누출이 제거됐다고 말하지 않는다.

실무에서는 검토된 알고리즘과 구현 및 적절한 모드/ 인증/ 키 관리를 함께 검토한다. 여기서는 소유 시스템 공격이나 전력 실험을 하지 않고 종이에서 약한 구조의 반례만 계산한다.

중간 과정을 따라가는 예제

4비트 x =1010에 a =0011,b =0101을 차례로 XOR한다. y와 결합 키를 구하고 같은 규칙의 x ′=0001 결과를 예측하라.

  1. 첫 단계 1010 ⊕0011 =1001이다.

  2. 둘째 1001 ⊕0101 =1100이다.

  3. 결합 키 0011 ⊕0101 =0110이며 입력/ 출력에서도 1010 ⊕1100 =0110이다.

  4. 새 입력 0001 ⊕0110 =0111이다. 이 예측에는 a/b를 따로 복구할 필요가 없다.

y1100, 결합 키 0110, 새 결과 0111이다.

역함수를 갖는 두 단계도 순서가 중요합니다

E=g∘f일 때 x=2를 암호화하고 올바른 역순·잘못된 같은 순서를 비교하세요.

  1. f(2)=3을 얻은 뒤 g(3)=9 mod 8=1을 얻습니다.

  2. g를 먼저 풀어 3×1=3을 얻고 f를 풀면 3−1=2입니다.

  3. f부터 풀면 0이고 그 뒤 g의 역을 적용해도 0입니다.

올바른 D=f의 역∘g의 역입니다. 두 단계 각각의 역함수 존재만으로 순서 오류가 해결되지 않습니다.

비교할 점

기본 원고의 XOR 반복과 달리 비가환 두 변환을 사용해 역순의 필요성을 드러냅니다.

순열이지만 두 질의로 드러나는 관계

E_k(x)=3x+k이고 k는 균등하게 선택한 홀수입니다. D는 y1−y0≡3이면 1을 출력합니다. 균등 무작위 순열과 비교하세요.

  1. E_k(0)=k이고 E_k(1)=3+k이므로 D는 항상 1입니다.

  2. 무작위 순열에서 첫 출력이 무엇이든 둘째 출력은 나머지 일곱 값 중 균등하게 선택됩니다. 첫 출력에 3을 더한 한 값만 검사 조건을 만족합니다.

  3. 통과 확률은 실제 계열에서 1이고 무작위 순열에서 1/7이므로 절댓값 차는 6/7입니다. 두 세계를 반반 선택하고 통과하면 실제 계열이라고 추측할 때 성공률은 13/14입니다.

정확한 순열 계열이어도 무작위 순열처럼 보이지 않을 수 있습니다. 성공률 13/14와 확률 차 6/7은 서로 다른 정규화입니다.

비교할 점

단순한 출력 충돌이 아닌 두 출력 사이의 관계를 검사합니다. 서로 다른 키로 답을 받으면 이 계산을 그대로 사용할 수 없습니다.

연습 1 · 값과 상태 예측

홀수 k에 대해 E_k를 두 번, 네 번 적용한 식을 구하세요.

힌트 1

두 번 적용할 때 3(3x+k)+k를 전개합니다.

힌트 2

9≡1이고 홀수 k이면 4k≡4입니다.

풀이와 답 확인

  1. E_k²(x)=9x+4k≡x+4입니다.

  2. 두 번짜리 변환을 다시 적용하면 x+8≡x이므로 E_k⁴(x)=x입니다.

홀수 키에서는 두 번이 x+4, 네 번이 항등입니다. 반복 횟수만으로 보안 증가를 결론 내릴 수 없습니다.

다른 문제에 적용하기

여덟 값 공간에서 서로 다른 입력 0과 1을 질의합니다. 출력 충돌 검사와 홀수 키 affine 계열에서 출력 차가 3인지 확인하는 검사를 따로 계산하세요. AES-128의 라운드 변환 횟수와 연결하여 정확성·구별성·반복 횟수가 각각 무엇을 말하는지 설명하세요.

힌트 1

무작위 함수의 둘째 새 출력은 여덟 값 중 선택하고, 무작위 순열은 첫 값을 뺀 일곱 값 중 선택합니다.

힌트 2

AES-128은 10라운드이며 초기 키 덧셈이 있고 마지막 라운드에는 MixColumns가 없습니다.

풀이와 답 확인

  1. 출력 충돌 검사의 통과 확률은 무작위 함수에서 1/8이고 순열에서 0입니다. 공정한 두 세계 추측의 성공률은 9/16입니다.

  2. 출력 차가 3인지 확인하는 검사의 통과 확률은 affine 계열에서 1이고 무작위 순열에서 1/7입니다. 확률 차는 6/7이고 공정 추측의 성공률은 13/14입니다. 실제 계열의 두 답은 같은 키에서 얻는다는 가정을 명시합니다.

  3. AES-128에서는 SubBytes를 10회, MixColumns를 9회, AddRoundKey를 11회 적용합니다. 이 횟수와 작은 반례만으로 AES 보안성을 증명하거나 반박하지 않습니다.

충돌 검사는 함수와 순열 모델의 차이를 확인하고, 출력 차가 3인지 확인하는 검사는 특정 순열 계열의 구조를 확인합니다. AES의 단계 수는 표준 절차에 관한 사실이며 각각의 보안 결론은 별도 분석이 필요합니다.

해결한 뒤 점검할 것

  • 두 검사에서 세계와 통과 사건을 따로 적습니다.

  • 확률 차와 공정 추측 성공률을 혼동하지 않습니다.

  • AES 횟수를 정확히 세고 실제 AES 구현 검증을 주장하지 않습니다.
