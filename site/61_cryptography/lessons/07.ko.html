소단원 7.1

위조 불가능성과 MAC

메시지가 보였더라도 몰래 바뀐 것을 알아낼 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 비밀 키와 공개 정보

  • 확률과 비트

학습 목표

  • MAC 생성·검증과 위조 조건을 구별한다.

  • 재전송과 신선도 확인을 분리한다.

틀렸다고 확인된 태그를 다시 보내면 성공 기회가 늘까요?

이상 모형에서는 새 메시지의 유효 태그 T가 0,…,15 중 균등한 한 값으로 고정됩니다. 실제 안전한 태그 길이가 아니라 확률 계산용 4비트 공간입니다. 검증 응답에서 오직 성공·실패만 보고, 다른 누설은 없다고 둡니다. 서로 다른 값 세 개를 시도하면 성공 확률 3/16입니다. 이미 실패한 값을 다시 시도하면 새로운 값을 덮지 않습니다.

첫 두 서로 다른 시도가 실패했다는 조건 아래에서는 남은 14개 태그가 균등합니다. 세 번째 새 값의 조건부 성공 확률은 1/14입니다. 전체 실험의 세 번째 최초 성공 확률은 (14/16)(1/14)=1/16입니다. 조건부 확률과 전체 확률을 구별해야 합니다. 실제 MAC의 새 메시지 위조 게임과 여러 검증 요청을 허용한 이 작은 시도 모형도 따로 구별합니다.

키를 가진 쪽만 만들 수 있는 표식

MAC은 공유 비밀 키 K로 메시지 m에 태그 t를 만들고 같은 키로 (m,t)를 검증하는 방식이다. 메시지를 숨기는 기능과 다르다. 키 없는 일반 checksum이나 공개 해시만 보내면 공격자도 메시지와 값을 함께 다시 만들 수 있다.

수신자는 태그가 맞으면 이 키를 가진 누군가가 만든 메시지라고 받아들일 수 있다. 공유 키를 가진 수신자도 태그를 만들 수 있으므로 제삼자에게 특정 발신자를 증명하는 전자서명과 동일하지 않다. 키 노출과 권한 관리도 보안 조건이다.

이미 본 태그로 새 메시지를 만들기 어렵게 하기

선택 메시지 공격에서는 공격자가 여러 메시지의 유효 태그를 얻더라도 새 유효 쌍을 만들기 어려워야 한다. 이 단원은 각 메시지에 태그가 유일한 결정적 MAC을 가정하여 이전에 태그를 받지 않은 메시지의 위조를 설명한다.

완전히 같은 (m,t)를 복사하는 재전송은 이 위조 조건의 새 메시지가 아니다. 실제 프로토콜에서 재전송을 막으려면 인증하는 내용에 순서 번호나 유효기간 등을 넣고 수신자가 이미 처리했는지 판단하는 상태/정책이 필요하다.

태그 길이 계산의 가정 지키기

이상적인 t비트 태그에 대해 알려지지 않은 새 메시지 태그를 한 번 균등 추측하면 성공 확률은 2^(−t)다. 여러 번의 시도는 기회를 늘린다. 이는 지정한 이상 모형 계산이지 모든 MAC 구현의 실제 공격 성공률 공식은 아니다.

아래 8비트는 확률을 이해하기 위한 매우 작은 교육 모형이다. 실제 보안 길이나 알고리즘을 추천하는 수치가 아니다. 검증 실패 처리·속도 제한도 중요하지만 짧은 태그를 안전한 구현으로 바꿔 주지는 않는다.

각 행의 성공 확률은 그 실패 조건 아래의 다음 시도입니다. 전체 세 번 성공 확률 3/16과 세 번째 조건부 확률 1/14를 같은 수치라고 쓰지 않습니다.

중간 과정을 따라가는 예제

이상적인 8비트 태그를 한 번 추측할 때 성공 확률과, 같은 미지 태그를 복원 없이 서로 다른 값 4개로 추측할 때 성공 확률을 구하라.

  1. 가능한 태그 수는 2^8=256이다.

  2. 한 값은 1/256≈0.00390625다.

  3. 서로 다른 4개는 256개 중 4개를 덮으므로 4/256=1/64=0.015625다. 복원 추측과 다른 조건이다.

1회 1/256, 서로 다른 4회 1/64다. 이 수치는 이상 모형에만 적용했다.

조건을 바꾸어 비교하기

실패를 확인한 뒤의 조건부 확률

2와 5가 모두 실패했습니다. 다음 값 7의 조건부 성공과 원래 시작점에서 세 번째 최초 성공 확률은?

  1. 두 값을 제외한 14개가 남아 값 7은 그중 한 개입니다. 조건부 확률 1/14입니다.

  2. 앞 두 시도 실패 확률 14/16을 곱하면 세 번째 최초 성공 확률은 1/16입니다.

실패 관측 후의 확률은 1/14, 원래 전체 실험에서의 확률은 1/16입니다.

비교할 점

기본 원고의 여러 서로 다른 추측 총확률에서 한 단계의 조건을 더 명확히 나눕니다.

독립 복원 추측과 서로 다른 추측

같은 미지 태그에 독립 균등 추측을 세 번 복원 허용하면 적어도 한 성공 확률은?

  1. T가 무엇이든 각 추측 실패 확률은 15/16이며 추측 난수는 독립입니다.

  2. 모두 실패할 확률은 (15/16)^3=3375/4096입니다.

  3. 성공할 확률은 1−3375/4096=721/4096이고 서로 다른 세 값을 시도할 때의 확률 3/16=768/4096보다 작습니다.

중복 추측이 기회를 낭비하므로 721/4096<768/4096입니다.

비교할 점

알려진 실패 값까지 무작위로 다시 고르는 전략과 실패 값을 제외하는 전략을 구분합니다.

종이와 본문으로 직접 해보기

유효한 (순서 번호 7,본문,태그)를 그대로 두 번 보내면 MAC 검증만으로 두 번째 처리를 막을 수 있는가?

힌트 보기

메시지 바이트가 같을 때 태그가 달라지는지와 처리 이력을 따로 생각하라.

풀이 보기

유효 태그 검증만으로 막지 못한다. 번호와 본문을 함께 인증하고 수신자가 번호 7의 처리 이력을 확인하여 재처리를 거절하는 정책이 필요하다.

오해와 반례

MAC이 맞으면 내용도 비밀이고 재전송도 자동 차단된다.

MAC은 메시지 인증 기능이다. 기밀성과 재전송 방지는 별도 암호화/프로토콜 조건을 요구한다.

연습 1 · 값과 상태 예측

고정 미지 태그에 2, 2, 5를 순서대로 시도하면 적어도 한 성공 확률은?

힌트 1

서로 다른 시도 값의 집합을 적습니다.

힌트 2

중복된 값 2는 새 가능한 태그를 덮지 않습니다.

풀이와 답 확인

  1. 서로 다른 추측 값의 집합은 {2,5}이며 원소는 두 개입니다.

  2. 균등한 16개 후보 중 2개를 덮으므로 2/16=1/8입니다.

1/8입니다. 세 요청이라는 사실만으로 성공 확률이 3/16은 아닙니다.

흔한 오답에서 다시 생각하기

세 번 보냈으니 성공 확률은 3/16이다.

서로 다른 추측이라는 가정이 빠졌습니다.

연습 2 · 오류 찾아 고치기

두 실패 후 새 추측의 성공 확률 1/14가 처음 세 번의 총성공 확률 3/16보다 작으므로 계산이 모순이라고 했다. 고치세요.

힌트 1

비교하는 사건과 조건이 같은지 봅니다.

힌트 2

다음 한 번과 전체 세 번은 다른 사건입니다.

풀이와 답 확인

  1. 1/14는 두 실패를 알고 난 다음 한 번의 조건부 성공입니다.

  2. 3/16은 시작 전 세 서로 다른 값 중 하나라도 맞을 전체 확률입니다.

조건과 사건이 달라 직접 같은 값이어야 한다고 요구할 수 없습니다.

연습 3 · 직접 만들어 보기

태그 oracle에서 (mA,3)과 (mB,3)을 받았습니다. 이상 무작위 함수 MAC에서 새 mC에 태그 3을 붙이는 한 번의 성공 확률은?

힌트 1

mA,mB,mC는 서로 다릅니다.

힌트 2

서로 다른 메시지의 이상 함수 값은 독립입니다.

풀이와 답 확인

  1. mC의 태그는 다른 두 관측과 독립 균등한 16개입니다.

  2. 3을 고르더라도 성공 확률은 1/16입니다.

1/16입니다. 두 옛 메시지의 태그 충돌만으로 새 메시지 태그가 결정되지는 않습니다.

흔한 오답에서 다시 생각하기

옛 두 태그가 같으니 모든 메시지의 태그도 3이다.

부분 관측의 같은 값과 함수 전체가 상수라는 주장은 다릅니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

이미 MAC 태그 생성 oracle에서 받은 같은 (mA,3)을 제출하는 것과 새 (mC,3)을 제출하는 것을 구분하세요.

힌트 1

단원은 메시지마다 유효 태그 하나인 결정적 MAC입니다.

힌트 2

검증 통과와 위조 게임의 새 메시지 조건을 따로 봅니다.

풀이와 답 확인

  1. 기존 (mA,3)은 유효하지만 기존 쌍 재전송으로 새 메시지 위조가 아닙니다.

  2. 새 mC의 태그가 3이면 유효 새 메시지 위조이며 이상 모형 성공 확률은 1/16입니다.

같은 쌍 재전송은 별도 신선도 정책 문제입니다. 일반 다중 유효 태그 MAC에서는 새 쌍과 새 메시지 조건이 다를 수 있습니다.

흔한 오답에서 다시 생각하기

유효 태그를 제출하면 무조건 새 위조다.

게임이 배제하는 기존 응답 쌍과 실제 서비스의 재처리 정책을 구분합니다.

내 말로 설명하기

실패를 안 뒤에도 다음 시도의 성공 확률이 항상 1/16인가요?

설명 기준 확인

같은 고정 태그에서 서로 다른 실패 값을 제외하면 다음 새 값은 남은 수의 역수입니다. 원래 전체 사건 확률과는 다릅니다.

이 4비트 추측 결과가 실제 MAC의 공격 성공률인가요?

설명 기준 확인

아닙니다. 이상 균등 분포·누설 없음·검증 요청 수와 중복 조건 아래의 교육 계산입니다.

한 단계 더

복원을 허용한 독립 4회 추측의 확률 1−(255/256)^4와 서로 다른 추측을 비교하자. 실제 공격·암호 구현·학생 검증은 하지 않았다.

HMAC의 키가 길면 패드도 그만큼 길어지나요?

절차만 추적하는 모형으로 hash 블록 길이 B=4바이트, digest 길이 L=2바이트를 둡니다. 다섯 바이트 키의 hash 결과가 A1 B2라고 주어지면 긴 키를 이 2바이트 결과로 바꾼 뒤에 00 00을 붙여 K0=A1 B2 00 00을 만듭니다. ipad와 opad도 4바이트입니다. 이러한 작은 hash가 안전하다는 뜻은 아니며 실제 hash나 HMAC 태그를 계산하지 않습니다.

한편 기본 CBC-MAC의 초기값 0을 송신자가 임의 선택하는 IV로 바꾼 잘못된 API를 생각합니다. 한 블록 메시지 m와 IV의 XOR가 같게 m와 IV를 함께 바꾸면 태그를 유지할 수 있습니다. 메시지 길이를 고정해도 이 잘못된 초기값 인터페이스가 별도 위조 경로를 만듭니다. CBC 암호화의 IV 규칙을 MAC 구성에 복사하면 안 되는 이유입니다.

CBC 체인의 마지막 블록을 태그로 보기

기본 CBC-MAC은 C_0=0에서 C_i=E_K(C_(i−1) XOR M_i)를 계산하고 마지막 C_l을 태그로 쓴다. 여기서 초기값 0은 CBC 암호화의 임의 IV와 다르다. 블록 길이·메시지 길이·키 사용 조건을 명시해야 한다.

단순 구성은 정해진 동일 길이 입력 등 제한 아래 분석되며 서로 다른 길이를 그대로 허용하면 위조가 가능하다. 가변 길이에는 검증된 CMAC 같은 별도 구성이 필요하다. 임의 패딩이나 길이 덧붙이기를 설명 없이 고쳐 붙이면 증명이 생기지 않는다.

길이 확장에서 XOR가 만드는 반례

한 블록 M의 태그 T=E_K(M)를 알면 두 블록 M||(M XOR T)에 동일 태그 T를 붙일 수 있다. 첫 상태가 T이고 둘째 입력 T XOR (M XOR T)=M이므로 마지막 암호 출력도 T다.

이 공격은 E_K를 깨지 않고 허용 메시지 길이의 틈을 이용한다. 모든 메시지를 정확히 한 블록으로 제한한 검증기는 두 블록을 거절하므로 동일한 반례의 조건이 사라진다. 단순 CBC-MAC을 가변 길이 인증에 사용하지 말아야 할 이유다.

HMAC의 두 층과 키 패딩

HMAC은 H((K_0 XOR opad)||H((K_0 XOR ipad)||m))이다. H의 블록 길이를 B라 할 때 긴 키는 먼저 hash하고 짧은 키는 0으로 B바이트까지 채운다. ipad는 0x36, opad는 0x5C를 B번 반복한 값이다.

블록 길이와 digest 출력 길이는 같다고 가정하지 않는다. 내부 hash 결과를 외부 hash의 입력으로 넣으며 H(K||m) 하나와 다르다. RFC 2104는 역사적 정의 출처이고 그 안의 옛 hash 목록을 지금 권장으로 쓰지 않는다. 실사용은 검증된 라이브러리의 지원 알고리즘과 규칙을 따른다.

중간 과정을 따라가는 예제

교육용 8비트 블록 표기에서 M=0x31의 태그가 T=0xA6이라고 가정한다. 가변 길이 기본 CBC-MAC 반례의 둘째 블록과 최종 입력을 구하라. 실제 AES 태그가 아니다.

  1. M XOR T=0x31 XOR 0xA6=0x97이다.

  2. 첫 체인 상태는 0xA6이고 다음 암호 입력은 0xA6 XOR 0x97=0x31이다.

  3. E_K(0x31)=0xA6이므로 새 두 블록 메시지에도 태그 0xA6이 검증된다.

둘째 블록 0x97, 최종 입력 0x31, 태그 0xA6이다. 길이 제한 없는 기본 구성의 반례다.

조건을 바꾸어 비교하기

긴 키 정리 뒤의 두 패드

블록 길이가 B=4바이트이고 digest 길이가 L=2바이트인 절차 모형에서 H(K)=A1 B2일 때 두 패드를 구하세요.

  1. K0=A1 B2 00 00으로 4바이트를 맞춥니다.

  2. A1⊕36=97, B2⊕36=84이므로 inner prefix는 97 84 36 36입니다.

  3. A1⊕5C=FD, B2⊕5C=EE이므로 outer prefix는 FD EE 5C 5C입니다.

두 패드는 4바이트이고 digest는 2바이트입니다. 입력 prefix와 최종 태그를 혼동하지 않습니다.

비교할 점

기본 한 바이트 짧은 키 예와 달리 긴 키 해싱 뒤 패딩과 서로 다른 두 길이를 추적합니다.

임의 IV MAC 인터페이스의 반례

잘못된 MAC은 t=E(m⊕IV)를 출력하고 IV도 수신 입력으로 받습니다. m=0x52, IV=0x00, 마스크 0x0F로 새 m′·IV′를 만드세요.

  1. m′=52⊕0F=5D, IV′=00⊕0F=0F입니다.

  2. m′⊕IV′=5D⊕0F=52이므로 기존과 같은 E 입력입니다.

같은 태그를 새 메시지 0x5D에 붙일 수 있습니다. 고정 초기값 0 검증기는 IV′=0x0F라는 요청 자체를 허용하지 않습니다.

비교할 점

기본 가변 길이 확장 반례와 달리 한 블록 고정 길이에서도 인터페이스를 잘못 바꾸면 실패합니다.

종이와 본문으로 직접 해보기

HMAC 키가 한 바이트 0x0B이고 hash 블록 길이 B=64라고 가정한다. K_0의 첫/둘째 바이트에 ipad와 opad를 XOR한 값을 구하라.

힌트 보기

K_0은 0x0B 뒤 63개의 0바이트다. hash 자체의 digest는 구하지 않는다.

풀이 보기

ipad 쪽 첫/둘째는 0x3D/0x36, opad 쪽은 0x57/0x5C다. 이 계산은 키 패드만이며 실제 HMAC 태그 계산은 미수행이다.

오해와 반례

안전한 블록 암호를 쓰면 가변 길이 CBC-MAC도 자동으로 안전하다.

기본 구성의 길이 확장 반례는 블록 암호를 깨지 않아도 성립한다. 구성·입력 도메인·키와 패딩 조건까지 확인해야 한다.

MAC이 맞는 같은 바이트를 서로 다르게 해석하면 무엇이 인증됐나요?

두 ASCII 필드 x와 y를 단순 이어 붙여 MAC을 붙이는 시스템을 생각합니다. (x,y)=(ab,c)와 (a,bc)는 모두 바이트 61 62 63입니다. 같은 바이트에는 같은 유효 태그가 적용되므로 태그가 맞더라도 두 필드의 의미를 구별할 수 없습니다. 이는 서로 다른 MAC 입력의 태그를 위조한 공격과 다릅니다. 인증한 바이트와 애플리케이션이 사용하는 의미 사이에 빈틈이 생긴 것입니다.

자체 형식은 각 필드 앞에 1바이트 길이를 넣고 두 필드를 순서대로 인코딩합니다. (ab,c)는 02 61 62 01 63, (a,bc)는 01 61 02 62 63으로 다릅니다. 길이는 바이트 수이며 각 필드는 0~255바이트로 제한합니다. 두 길이와 값을 모두 인증하고, 정확히 두 필드를 읽은 뒤 남는 바이트가 없는지 확인합니다. 공개 문맥을 AAD에 넣어도 이 경계 조건은 필요합니다.

숨기기와 바뀜 탐지는 다른 목표

기밀성은 권한 없는 쪽에 내용을 숨기는 목표이고 인증/무결성은 허용되지 않은 새 메시지나 변경을 받아들이지 않는 목표다. 암호문이 보이지 않는다는 것만으로 변조를 막았다고 결론 내릴 수 없다.

한 번만 쓰는 균등 키의 XOR one-time pad는 기밀성 설명에 좋은 모형이지만 태그가 없다. 공격자가 원하는 위치의 암호 비트를 뒤집으면 같은 위치의 평문 비트도 뒤집힌다. 원문 내용을 몰라도 변경 자체가 가능하다.

암호문을 인증하고 검증 뒤 사용하기

encrypt-then-MAC은 암호화 키로 암호문을 만들고 별도 인증 키로 그 암호문을 인증한다. 수신자는 태그 검증이 실패하면 거절하며 유효할 때 복호화 결과를 사용한다. 검증 전 평문 일부를 외부에 내보내거나 실행하지 않아야 한다.

키를 같은 바이트로 재사용하거나 IV/nonce 같은 중요한 입력을 인증에서 빼면 구성 보장이 깨질 수 있다. 가변 필드의 경계를 모호하게 이어 붙이지 말고 규정된 인코딩으로 길이와 버전도 다룬다. 실제로는 검증된 authenticated encryption API를 이용하는 것이 적절하다.

공개 문맥도 인증 대상에 포함하기

AEAD는 숨기는 평문 외에 AAD라는 공개 문맥을 인증할 수 있다. 예를 들어 메시지 유형과 순서 번호는 숨기지 않아도 변경되면 처리가 달라지므로 보호해야 한다. AAD를 인증한다고 공개값이 비밀이 되는 것은 아니다.

nonce 조건·키 수명·재전송 이력은 프로토콜에서 정한다. 태그가 유효하다는 것만으로 발신 권한이나 요청의 허용 여부를 모두 결정하지 않는다. 인증된 메시지에도 별도 접근 권한·신선도 확인이 필요하다.

필드 쌍단순 연결길이 포함 바이트

16진수 길이 바이트와 ASCII 값 바이트를 나눠 읽습니다. 길이 필드를 인증 범위에서 빼고 다른 비인증 길이에 따라 파싱하면 이 형식의 가정을 지킨 것이 아닙니다.

중간 과정을 따라가는 예제

m=1010, 일회용 k=0110인 4비트 XOR 모형이다. c=m XOR k를 구하고 공격자가 Δ=0010을 XOR한 c′를 수신자가 복호화하면 무엇을 얻는가?

  1. c=1010 XOR 0110=1100이다.

  2. c′=1100 XOR 0010=1110이다.

  3. c′ XOR k=1110 XOR 0110=1000=m XOR Δ다. 내용 비트가 바뀌지만 태그 없는 모형에는 탐지 절차가 없다.

1100→1110으로 바뀐 암호문은 1000으로 복호화된다. 이 비트 예제는 실제 암호 라이브러리 실행이 아니다.

조건을 바꾸어 비교하기

같은 인증 바이트의 다른 해석

단순 연결 61 62 63을 두 필드로 나누는 세 예를 찾고 위조 게임과 구별하세요.

  1. ab/c, a/bc, 빈 값/abc는 같은 연결 바이트입니다.

  2. 기존 태그를 다시 사용해도 MAC 입력 바이트는 바뀌지 않습니다.

의미 필드가 다르게 처리될 수 있지만 새 바이트 메시지 태그를 위조한 것은 아닙니다. 인코딩이 의미 쌍에 대해 단사여야 합니다.

비교할 점

기본 원고의 모호한 필드 경계 지적을 실제 바이트열로 추적합니다.

두 길이로 경계를 복원하기

02 61 62 01 63을 자체 형식으로 읽으세요.

  1. 첫 길이 바이트 02는 다음 2바이트인 61 62를 첫 필드로 지정합니다.

  2. 다음 길이 바이트 01은 63 한 바이트를 둘째 필드로 지정합니다.

  3. 정확히 5바이트를 소비하고 남는 바이트가 없어 (ab,c)로 복원합니다.

길이와 값이 모두 인증된 동일한 규칙에서 한 쌍으로 복원합니다.

비교할 점

MAC 검증과 형식 유효성 검사는 별개이며 둘 다 통과한 데이터를 사용합니다.

종이와 본문으로 직접 해보기

힌트 보기

IV도 복호화 입력이고 재전송은 바이트를 바꾸지 않는다는 점을 나누어 생각하라.

풀이 보기

IV를 제외하면 IV 변경이 태그에 반영되지 않아 무결성이 깨질 수 있으므로 규정된 전체 입력을 인증한다. 동일 번호 7 재전송은 태그가 유효할 수 있어 처리 이력으로 거절해야 한다.

오해와 반례

MAC을 암호문에 붙이면 필드·순서·키 조건과 무관하게 안전하다.

분리된 키, 전체 암호 입력/AAD 보호, 검증 전 출력 금지와 nonce 조건 등 구성의 가정이 필요하다. 잘못 조합한 자체 구현은 인증 암호 보장을 갖지 않는다.

내 말로 설명하기

MAC이 보호하는 것은 의미인가요, 바이트인가요?

설명 기준 확인

MAC은 지정한 바이트 메시지를 인증합니다. 의미 필드와 바이트 사이의 모호하지 않은 대응은 프로토콜 인코딩이 보장해야 합니다.

공개 AAD 필드도 길이를 정확히 인증해야 하나요?

설명 기준 확인

여러 가변 필드를 합치면 값과 경계를 인증된 정보만으로 복원해야 합니다. AAD는 공개될 수 있지만 임의 변경을 허용한다는 뜻은 아닙니다.

다른 문제에 적용하기

검증 메모를 세 가지 작성하세요. ①미지 4비트 태그에 2, 2, 5를 시도한 총성공 확률 ②블록 길이가 B=4바이트이고 digest 길이가 L=2바이트인 모형에서 H(K)=A1 B2로 주어진 긴 키의 두 패드 ③ASCII 필드 (a,bc)의 길이 포함 인코딩과 길이까지 인증해야 하는 이유.

힌트 1

추측은 서로 다른 값의 수를 셉니다.

힌트 2

긴 키 digest를 B바이트까지 0으로 채우고, 필드 길이는 바이트 수로 적습니다.

풀이와 답 확인

  1. 서로 다른 추측 값은 {2,5}이므로 성공 확률은 2/16=1/8입니다. 실패 관측 후 조건부 확률과 구별합니다.

  2. K0=A1 B2 00 00, inner prefix는 97 84 36 36, outer prefix는 FD EE 5C 5C입니다. 실제 태그는 구하지 않았습니다.

  3. 01 61 02 62 63입니다. 길이를 제외하면 (ab,c)의 연결 값과 같아 의미를 바꿀 수 있습니다.

확률의 가정, HMAC 입력 prefix, 인증된 필드 경계를 각각 분리합니다.
