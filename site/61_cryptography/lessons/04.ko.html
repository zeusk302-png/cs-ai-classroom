소단원 4.1

확장과 구별 불가능성

짧은 무작위 씨앗이 긴 비밀 메시지를 가릴 수 있을까?

준비 개념과 학습 목표

준비 개념

  • XOR 는 같으면 0, 다르면 1 인 비트 연산이다.
  • U_n 은 길이 n 의 모든 비트열에 같은 확률을 주는 분포다.
  • 결정적 함수는 같은 입력에 항상 같은 출력을 낸다.

학습 목표

  • PRG 의 확장과 계산적 안전성을 구별한다.
  • 구별 확률차와 정답 추측 확률을 계산한다.

씨앗을 길게 펼친다

의사난수 생성기 PRG 는 ℓ비트 씨앗을 받아 L 비트 출력을 만들며 L>ℓ인 확장을 요구한다. 씨앗은 균일하고 비밀이어야 하며 생성 절차 자체는 공개되어도 된다. 의사난수는 결정적 계산 결과다. 매번 새 실제 난수 L 비트를 뽑는 장치와 다르다.

길이를 늘려도 정보가 새로 생기지는 않는다. 씨앗 경우의 수가 2^ℓ이면 출력 가능성은 최대 2^ℓ개다. L 비트 균일 분포의 2^L 개 전체를 동일 확률로 만들 수 없다. 따라서 짧은 키를 확장한 암호는 정보론적 완전 비밀성과 계산적 비밀성을 구별해야 한다.

효율적인 검사가 차이를 찾는가

검사 D 는 긴 비트열을 보고 0 또는 1 을 출력한다. PRG 안전성은 비밀 씨앗의 G(U_ℓ)와 독립 균일 U_L 사이에서 효율적인 검사들이 큰 확률 차를 찾지 못한다는 뜻이다. 한 검사에 대해 |Pr[D(G(U_ℓ))=1]−Pr[D(U_L)=1]|를 구별 우위로 정의한다.

정식 정의는 보안 매개변수가 커지는 함수 집합과 허용 계산량·무시 가능한 확률차를 다룬다. 아래 3 비트 예는 안전한 암호가 아니며 정의의 실패를 눈으로 보여 준다. 임의의 작은 한 샘플에서 비트가 절반씩 나왔다고 이 정의가 증명되지 않는다.

길이와 보기 좋은 패턴은 증명이 아니다

많은 비트열이 균형 있게 보이거나 간단한 통계 시험을 통과해도 다음 비트가 앞 비트에서 쉽게 예측되면 안전하지 않을 수 있다. 공격자에게 씨앗을 알려 주면 출력 전체를 계산할 수 있으므로 난수처럼 보이는 성질만으로 비밀이 유지되지 않는다.

모든 씨앗을 나열하고 입력이 가능한 출력인지 검사하면 정보론적으로 분포를 구별할 수 있다. 하지만 ℓ가 커질 때 2^ℓ개 나열은 효율적 계산의 범위를 벗어날 수 있다. 불가능한 출력이 있다는 사실 자체가 큰 매개변수의 계산적 안전성을 바로 반박하는 것은 아니다.

중간 과정을 따라가는 예제

비안전 생성기 G(a,b)=(a,b,a XOR b)에서 씨앗은 균일 2 비트다. 검사 D 는 셋째 비트가 앞 두 비트 XOR 와 같으면 1 을 출력한다. 두 분포의 검사확률과 구별 우위를 구하라.

  1. 씨앗 00,01,10,11 의 출력은 000,011,101,110 이다.
  2. 네 출력 모두 parity 관계를 만족하므로 Pr[D(G(U₂))=1]=1 이다.
  3. 균일 3 비트는 앞 두 비트를 고른 뒤 마지막이 0/1 로 동일하게 나온다. 그 중 하나만 관계를 만족하므로 Pr[D(U₃)=1]=1/2 다.
  4. 구별 우위는|1−1/2|=1/2 다. 검사에 필요한 XOR 와 비교는 매우 적다.
  5. 두 세계를 같은 확률로 고르고 D=1 이면 생성기로 추측하면 성공확률은(1/2)×1+(1/2)×(1/2)=3/4 다.

우위 1/2, 같은 사전확률의 세계 추측 성공 3/4. 서로 다른 두 수를 섞지 않는다.

종이와 본문으로 직접 해보기

비안전 G(s)=(s,s)에서 s 는 균일 2 비트다.4 비트의 앞 두 비트와 뒤 두 비트가 같으면 1 을 출력하는 검사의 우위를 계산하라.

힌트 보기

균일 4 비트 경우 16 개 중 같은 절반인 출력은 4 개다.

풀이 보기

생성기 출력 0000,0101,1010,1111 은 항상 같으므로 확률 1 이다. 균일 4 비트는 4/16=1/4 다. 우위 3/4, 같은 세계 사전확률에서 추측 성공(1+3/4)/2=7/8 이다.

오해와 반례

PRG 출력 길이가 4 비트이면 무작위 정보도 4 비트가 된다.

균일 2 비트 씨앗의 결정적 출력 엔트로피는 최대 2 비트다. 위 G(s)=(s,s)는 네 출력만 낸다. 확장은 길이의 증가이고 정보 엔트로피의 증가가 아니다. 효율적 구별의 어려움은 별도로 검토한다.

한 단계 더

ℓ비트 씨앗에서 L 비트 출력의 지지집합 크기는 최대 2^ℓ다. 가능한 출력인지 완벽히 검사하는 무제한 계산 검사는 생성기에서는 1, 균일에서는 최대 2^(ℓ−L) 확률로 1 을 출력하여 우위가 최소 1−2^(ℓ−L)이다. ℓ=2,L=4 면 최소 3/4 다. 이 검사를 효율적으로 구현할 수 있는지와 집합 크기는 다른 문제다. 작은 예제의 XOR 검사는 효율적이어서 실패가 분명하지만 모든 큰 PRG 에 같은 쉬운 검사가 있다는 뜻은 아니다.

소단원 4.2

키스트림과 nonce

같은 비밀 키로 여러 메시지를 보내려면 어떤 번호를 따로 관리해야 할까?

준비 개념과 학습 목표

준비 개념

  • m XOR S XOR S=m 이다.
  • nonce 는 한 키 아래 호출을 구별하는 값이며 보통 함께 전송해도 된다.
  • 메시지 nonce 와 메시지 내부 블록 counter 는 서로 다른 역할이다.

학습 목표

  • XOR 암복호화와 nonce 유일성 조건을 설명한다.
  • 블록 번호의 고갈과 난수 충돌을 계산한다.

메시지 길이만큼 가림막을 만든다

키스트림 S 는 평문 m 과 같은 길이의 비트열이고 암호문은 c=m XOR S 다. 수신자가 같은 S 를 생성하면 c XOR S=m 이 된다. 짧은 비밀 키를 사용하는 실제 스트림 암호는 검토된 구성으로 키·nonce·블록 번호에서 필요한 스트림을 만든다. 단순히 씨앗에 nonce 를 이어 붙인 어떤 함수라도 안전하다는 뜻은 아니다.

전 단원의 단일 메시지 PRG 암호를 여러 메시지로 확장하려면 재사용을 다뤄야 한다. 키를 그대로 둔다면 그 키 아래 각 메시지 nonce 가 달라야 하는 구성들이 있다. nonce 는 비밀 키를 대신하지 않고 공개되어도 되는 입력이다. 서로 다른 nonce 가 아주 짧은 장난감 출력까지 항상 서로 다른 비트열을 보장하지도 않는다.

블록의 주소가 겹치지 않게 한다

RFC8439 의 ChaCha20 은 256 비트 키,96 비트 nonce,32 비트 counter 와 64 바이트 블록을 정의한다. 한 메시지의 nonce 를 고정한 채 내부 counter 를 증가시켜 연속 블록을 얻는다. 다음 메시지는 nonce 를 새로 배정한다. 블록 counter 의 반복·넘침으로 같은 스트림 구간을 다시 사용하면 안 된다.

키를 공유하는 여러 송신자라면 서로 겹치지 않는 nonce 공간을 배정해야 한다. 재시작 뒤 counter 를 0 으로 초기화하면서 이전 키를 유지하거나 백업에서 옛 counter 를 복원하면 이미 쓴 nonce 가 다시 나타날 수 있다. 지속 상태와 키 교체 정책은 숫자 증가식 자체만큼 중요하다.

유일성과 예측 불가능성 구별

이 구성의 nonce 는 유일성이 핵심이며 순차 번호도 가능하다. 키와 달리 nonce 가 예측 가능하다는 이유만으로 비밀성이 깨지는 것은 아니다. 무작위 nonce 를 뽑으면 반복 확률이 0 이 아니므로 길이·호출 수·충돌 처리 조건을 계산해야 한다. 특정 API 와 프로토콜의 요구를 별도로 확인한다. RFC8439 §2.6은 동일 키 아래 nonce의 유일성을 요구하며 무작위로 생성하지 말라는 MUST NOT을 명시한다. 아래 무작위 4비트 nonce 활동은 충돌 위험을 계산하는 비안전 장난감 모형이며 그 표준을 따르는 생성 방법을 권장하는 예가 아니다.

RFC8439 AEAD 구성은 counter0 을 Poly1305 키 생성에 쓰고 평문 암호화는 counter1 부터 시작한다. 이 배치는 모든 스트림 암호의 보편 규칙이 아니라 그 구성의 규칙이다. 표준 본문을 읽었다고 교육용 라이브러리의 태그 비교·counter 처리·실제 장비 실행을 검증한 것은 아니다.

중간 과정을 따라가는 예제

비안전 4 비트 종이 모형에서 제공된 키스트림 S_N=1010, 평문 m=0110 이다. 다음 nonce 에는 제공된 S_(N+1)=0011, 평문 0101 이다. 각각 암호화·복호화하라.

  1. 첫 메시지는 0110 XOR1010=1100 이다. 비트별 0 XOR1=1,1 XOR0=1,1 XOR1=0,0 XOR0=0 이다.
  2. 복호화 1100 XOR1010=0110 으로 원래 값이 된다.
  3. 다음 메시지는 0101 XOR0011=0110 이다.
  4. 0110 XOR0011=0101 로 두 번째 평문을 복원한다.

첫 암호문 1100, 다음 0110. 이 숫자는 제공된 장난감 스트림의 계산이며 ChaCha20 출력이나 안전성 시험이 아니다.

종이와 본문으로 직접 해보기

16 개 값의 4 비트 nonce 를 독립 균일하게 세 번 뽑는다. 하나라도 반복될 확률을 구하라. 별도로 8 비트 순차 nonce 가 0 부터 255 까지 이미 사용되었다면 다음 호출은 어떻게 해야 하는가?

힌트 보기

무반복 확률은 첫 값 임의, 둘째 15/16, 셋째 14/16 이다.

풀이 보기

반복 확률 1−(15/16)(14/16)=46/256=0.1796875 즉 17.96875%다. 순차 0..255 를 모두 썼다면 같은 키에서 0 으로 돌아가면 재사용이므로 중지하고 허용된 새 키·새 nonce 공간을 설정해야 한다. 두 모형을 섞지 않는다.

오해와 반례

nonce 를 비밀로 감추면 같은 nonce 를 다시 써도 안전하다.

동일 키·nonce·counter 가 같은 스트림을 만들면 두 암호문 XOR 에서 스트림이 소거된다. 공격자가 nonce 값을 몰라도 이 대수 관계는 남는다. 숨김이 유일성 조건을 대신하지 않는다.

소단원 4.3

재사용 공격과 안전 조건

비밀 가림막이 같은 두 암호문을 겹쳐 보면 무엇이 남을까?

준비 개념과 학습 목표

준비 개념

  • XOR 는 교환·결합 가능하고 S XOR S=0 이다.
  • 알려진 평문은 공격자가 이미 아는 메시지 부분이다.
  • 비밀성은 내용 숨김, 무결성·인증은 변조 검출과 관련된다.

학습 목표

  • 재사용 스트림의 평문 관계와 알려진 평문 복구를 계산한다.
  • nonce·인증·재전송 상태의 역할을 구별한다.

같은 가림막이 소거된다

c₁=m₁ XOR S, c₂=m₂ XOR S 이면 c₁ XOR c₂=m₁ XOR m₂다. 공격자가 키나 S 를 몰라도 두 평문의 관계가 드러난다. 관계만으로 언제나 두 평문 전체를 유일하게 복구하는 것은 아니지만 문장 구조·알려진 부분으로 공격을 진행할 단서가 된다.

m₁을 알면 S=c₁ XOR m₁을 얻고 같은 위치의 m₂=c₂ XOR S 로 복구한다. 알려진 부분이 일부라면 그 길이와 겹치는 스트림 위치에 한해 적용한다. 길이가 다른 메시지에서 비교할 수 있는 겹친 부분과 전체 메시지를 구별한다.

재사용이 없어도 변조는 따로 막는다

인증 없는 스트림 XOR 에서 공격자가 c 를 c XOR δ로 바꾸면 복호화 결과는 m XOR δ다. 평문을 몰라도 특정 비트를 뒤집을 수 있다. 따라서 nonce 를 올바르게 관리하여 비밀성을 유지하는 것만으로 변조 검출이 생기지는 않는다.

검토된 AEAD 는 암호문과 추가 인증 데이터에 태그를 만들고 수신자는 일치 여부를 확인한다. 계산 중 얻은 평문이 있어도 인증 실패라면 신뢰 가능한 메시지로 넘겨서는 안 된다. 본문은 단순 태그 생성기를 설계하거나 위조 확률을 실험하지 않는다.

조건은 여러 층에서 지킨다

비밀 키의 적절한 생성·관리, 구성에서 요구하는 nonce 유일성, counter 범위, 올바른 인증 태그 확인이 함께 필요하다. 같은 nonce 를 재사용한 뒤 태그만 붙인다고 앞서 노출된 평문 관계가 사라지지 않는다. RFC8439 AEAD 의 nonce 재사용은 인증용 일회 키도 반복시키는 문제를 갖는다.

정상 태그가 있는 옛 메시지를 공격자가 그대로 재전송하면 태그 검사는 다시 통과할 수 있다. 재전송 방지는 메시지 번호와 이미 처리한 번호의 상태, 프로토콜 조건을 따로 관리한다. 비밀성·변조 검출·재전송 방지를 서로 대신하는 하나의 성질로 묶지 않는다.

중간 과정을 따라가는 예제

같은 S=1010 으로 m₁=0110,m₂=1100 을 암호화했다. 두 암호문 XOR 과 m₁을 아는 공격자의 m₂ 복구를 보여라.

  1. c₁=0110 XOR1010=1100 이고 c₂=1100 XOR1010=0110 이다.
  2. c₁ XOR c₂=1100 XOR0110=1010 이다.
  3. m₁ XOR m₂=0110 XOR1100=1010 으로 관계가 같다.
  4. m₁을 아는 공격자는 c₁ XOR m₁=1100 XOR0110=1010 으로 S 를 얻는다.
  5. c₂ XOR S=0110 XOR1010=1100 으로 m₂를 복구한다.

관계 1010 이 드러나며 알려진 첫 평문으로 두 번째 1100 을 복구한다. 이는 자기 생성 4 비트 예이고 실제 서비스 공격을 실행한 것이 아니다.

종이와 본문으로 직접 해보기

위 첫 암호문 1100 의 마지막 비트를 뒤집어 1101 로 만든다. 인증 없는 복호화 결과를 구하라. 또 관계 m₁ XOR m₂=1010 만 아는 경우 m₁이 0000 또는 1111 이면 가능한 m₂는?

힌트 보기

변조δ=0001 이다. 관계를 알고 한 평문을 가정하면 다른 것은 XOR 로 정해진다.

풀이 보기

1101 XOR1010=0111 로 마지막 평문 비트도 바뀐다. m₁=0000 이면 m₂=1010, m₁=1111 이면 m₂=0101 이다. 두 쌍 모두 관계를 만족하므로 관계만으로 전체 평문 유일 복구는 보장되지 않는다.

오해와 반례

인증 태그가 있으면 nonce 재사용이나 재전송도 자동으로 안전하다.

nonce 재사용은 키스트림 관계와 인증용 키 반복을 만들 수 있다. 유효한 옛 암호문·태그를 그대로 재전송하면 새로 위조한 것이 아니므로 별도 번호 상태가 없으면 다시 받아들일 수 있다. AEAD 사용 조건과 프로토콜 재전송 규칙을 모두 검사해야 한다.

한 단계 더

길이 n 에서 고정 관계 r=m₁ XOR m₂만 알면 각 m₁ 후보 2^n 개마다 m₂=m₁ XOR r 이 하나 정해져 총 2^n 개의 가능한 순서쌍이 있다. 추가 문장 구조나 알려진 비트가 후보를 줄이지만 그 가정을 기록해야 한다. 균일 독립 일회 패드도 같은 가림막을 두 번 쓰면 이 관계를 노출한다. 생성기 품질만의 문제가 아니라 사용 방식의 문제다. 안전 조건 점검과 실제 구현·장비·학생 시험은 별도이며 이 단원에서 후자는 수행하지 않았다.
