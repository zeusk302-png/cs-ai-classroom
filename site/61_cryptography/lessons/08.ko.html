소단원 8.1

충돌·원상·제2원상

같은 해시를 찾는다는 세 질문은 무엇이 먼저 주어졌는지에 따라 어떻게 달라질까?

준비 개념과 학습 목표

준비 개념

  • 함수와 입력·출력

  • 비트 수와 경우의 수

  • 서로 다른 값의 구별

학습 목표

  • 세 찾기 문제의 주어진 값과 목표를 구별한다.

  • 충돌 존재와 충돌 찾기의 어려움을 나눈다.

  • 작은 비보안 대응표로 세 문제를 직접 푼다.

아무 두 출력의 충돌을 찾는 것과 정해진 출력 하나를 맞히는 것은 확률도 같을까요?

이상 무작위 함수의 4비트 출력 공간에는 16개 값이 있습니다. 서로 다른 네 입력을 질의하면 네 출력은 독립 균등입니다. 아무 두 출력이 같은 사건의 확률은 1−(15/16)(14/16)(13/16)=683/2048입니다. 반면 미리 정한 목표 y를 네 출력 중 하나라도 맞히는 확률은 1−(15/16)^4=14911/65536입니다. 문제의 목표와 공격자가 선택할 수 있는 대상이 다릅니다.

이 정확한 소규모 모형은 실제 해시 공격 실행이나 특정 알고리즘의 난도를 측정한 결과가 아닙니다. 충돌의 존재는 출력보다 입력이 많으면 보장되지만 특정 출력의 원상이 존재하는지는 함수의 상에 달려 있습니다. 원상 문제에서 같은 최초 원본을 복원해야 하는 것도 아닙니다.

    먼저 주어진 대상과 답의 서로 다름 조건을 확률 사건으로 옮깁니다.

  • 블록 암호의 모델

짧은 요약과 정보 손실

해시는 입력을 일정 길이의 요약값으로 보내는 함수다. n비트 출력에는 2ⁿ개 값이 있다. 이보다 많은 서로 다른 입력을 보내면 같은 출력으로 가는 쌍이 존재한다. 따라서 충돌 저항성은 충돌이 전혀 없다는 뜻이 아니다. 실용 자원 안에서 충돌을 찾기 어렵다는 보안 성질이다.

같은 바이트와 같은 설정에 대한 해시는 같지만 서로 다른 입력의 해시는 반드시 다르다고 단정할 수 없다. 작은 수를 더해 나머지를 취하는 체크섬은 계산 연습에는 좋지만 암호학적 해시의 보안 성질을 보여 주지 못한다.

무엇을 먼저 주는가

원상 찾기는 출력 y를 주고 H(m)=y인 입력 하나를 찾게 한다. 원래 사용한 입력과 반드시 같은 것을 되찾는 문제가 아니다. 제2원상 찾기는 특정 입력 m을 먼저 주고 m′≠m이면서 H(m′)=H(m)인 다른 입력을 찾게 한다.

충돌 찾기는 두 입력을 모두 선택할 수 있는 상황에서 m≠m′,H(m)=H(m′)인 쌍을 찾는 문제다. 미리 고정된 입력을 대체하는 상황과 아무 두 입력을 고를 수 있는 상황은 공격자의 자유도가 다르다. 세 저항성을 이름이 비슷하다고 동일한 보장으로 취급하지 않는다.

요약값을 어디서 받았는가

자료와 해시를 같은 신뢰하지 않는 곳에서 받으면 둘 다 바뀔 수 있다. 해시 비교는 신뢰할 수 있는 기준 요약을 이미 갖고 있을 때 의미가 있다. 공개 해시 하나는 작성자의 신원이나 메시지 진실성을 자동 인증하는 비밀키가 아니다.

아래 작은 대응표는 약한 함수를 의도적으로 완전히 보여 준다. 이 표에서 쉽게 답을 찾는 것은 보안 해시 공격을 실행한 증거가 아니다. 실제 라이브러리 해시 계산·충돌 탐색·학생 실험은 수행하지 않았다.

첫 함수 값을 계속 반환

독립 네 출력으로 세지 않음

첫 행은 조건부로 남은 출력 수를 줄이고 둘째는 한 고정 목표를 매번 피합니다. 함수 출력이 같은 두 입력은 서로 달라야 충돌 쌍입니다.

중간 과정을 따라가는 예제

자체 대응표 H(a)=00,H(b)=01,H(c)=00,H(d)=10,H(e)=11에서 출력00의 원상 하나, 입력a의 제2원상, 충돌 쌍 하나를 찾자.

  1. 출력00에 대응하는 a 또는c를 고르면 원상이다.

  2. a가 먼저 주어졌으면 다른c가 제2원상이다. a 자신은 허용되지 않는다.

  3. 입력을 자유롭게 고를 수 있으면(a,c)가 충돌 쌍이다.

  4. a와c는 다르고 해시00은 같다.

원상은 a(또는 c), a의 제2원상은 c, 충돌 쌍은 (a,c)다. 요구한 문제에 따라 먼저 주어진 값이 다르다.

아무 충돌의 정확한 확률

서로 다른 네 입력의 4비트 출력이 모두 다른 확률을 구하세요.

  1. 첫 출력은 어떤 값이든 됩니다.

  2. 두 번째 출력이 앞과 다를 조건부 확률은 15/16이고, 세 번째가 앞의 두 값과 다를 확률은 14/16이며, 마지막이 앞의 세 값과 다를 확률은 13/16입니다.

  3. 무충돌 확률은 2730/4096=1365/2048이므로 충돌 확률은 683/2048입니다.

무충돌 확률은 1365/2048이고 충돌 확률은 683/2048입니다. 여섯 입력 쌍의 충돌 확률 1/16을 각각 더한 6/16은 정확값이 아닌 상한입니다.

비교할 점

기본의 비둘기집 존재 증명과 달리 무작위 함수에서 정해진 질의 수의 사건을 계산합니다.

표의 상에 없는 목표

약한 공개 함수의 전체 도메인은 정수 0부터 7까지이며 H(0..7)=(0,1,0,2,3,4,5,6)입니다. 목표 7의 원상, 입력 0의 제2원상, 충돌 쌍을 찾으세요.

  1. 목표 7은 이 전체 표의 출력에 없어 이 제한 도메인에는 원상이 없습니다.

  2. 입력 0의 제2원상은 입력 2입니다.

  3. (0,2)는 서로 다른 입력이 같은 출력 0으로 가므로 충돌 쌍입니다.

충돌이 존재해도 모든 출력 값이 실현되는 것은 아닙니다. 도메인 0부터 7까지의 전체 대응을 주었다는 조건 아래의 부재 판단입니다.

비교할 점

기본 일부 표와 달리 전체 제한 도메인을 명시해 부재와 미관측을 구별합니다.

종이와 본문으로 직접 해보기

같은 표에서 출력01의 원상을 찾고 입력b의 제2원상이 이 표 안에 있는지 확인하자. 입력d와e는 충돌인가?

힌트 보기

입력의 동일성과 출력의 동일성을 따로 검사하자.

풀이 보기

01의 원상은 b다. 표의 다섯 입력 중 b와 같은 01을 갖는 다른 입력은 없어 이 제한된 표 안에서는 제2원상을 찾지 못한다. d와 e의 출력은 각각 10과 11이므로 충돌이 아니다. 표 밖 입력에 대해서는 정보가 없다.

오해와 반례

충돌 저항 해시에는 충돌이 존재하지 않는다.

유한 출력보다 큰 입력 집합이면 비둘기집 원리상 충돌이 존재한다. 저항성은 특정 자원 범위에서 찾기 어렵다는 뜻이다. 약한 공개 표의 충돌과 실제 알고리즘의 찾기 난도를 혼동하면 안 된다.

연습 1 · 값과 상태 예측

같은 4비트 이상 모형에서 서로 다른 두 입력만 질의하면 아무 충돌과 고정 목표 적중 확률은 각각 얼마인가요?

힌트 1

충돌은 두 번째가 첫째와 같을 때입니다.

힌트 2

고정 목표를 두 번 모두 피할 확률은 (15/16)²입니다.

풀이와 답 확인

  1. 충돌 확률은 1/16입니다.

  2. 목표 적중 확률은 1−225/256=31/256입니다.

충돌 확률은 1/16이고 목표 적중 확률은 31/256입니다. 서로 다른 사건입니다.

흔한 오답에서 다시 생각하기

두 번 출력하므로 두 확률은 반드시 같다.

충돌에는 두 출력의 동일성, 목표 적중에는 정해진 값과의 동일성이 필요합니다.

연습 2 · 오류 찾아 고치기

입력 0을 네 번 질의했으므로 아무 충돌 확률이 683/2048이라고 했습니다. 고치세요.

힌트 1

함수는 같은 입력에 같은 답을 합니다.

힌트 2

충돌에는 서로 다른 입력 둘이 필요합니다.

풀이와 답 확인

  1. 새 입력은 하나뿐입니다. 네 독립 출력을 받지 않습니다.

  2. 같은 입력 재질의만으로 서로 다른 입력 충돌 쌍을 만든 것은 아닙니다.

그 계산의 서로 다른 네 입력 가정이 깨졌습니다.

흔한 오답에서 다시 생각하기

중복 출력이면 입력이 같아도 충돌이다.

충돌 정의의 입력 불일치 조건을 먼저 검사합니다.

연습 3 · 직접 만들어 보기

공개 표에서 목표 0의 원상 두 개와 입력 1의 제2원상 부재를 설명하세요.

힌트 1

출력 0은 H(0)와 H(2)의 값입니다.

힌트 2

출력 1을 갖는 다른 입력을 전체 표에서 찾습니다.

풀이와 답 확인

  1. 목표 0의 원상은 입력 0과 입력 2입니다.

  2. 전체 제한 도메인에서는 출력 1의 원상이 입력 1 하나뿐이므로 입력 1의 제2원상이 없습니다.

원상 찾기는 하나를 찾으면 충분하고, 제2원상은 주어진 입력과 달라야 합니다.

흔한 오답에서 다시 생각하기

출력 1의 원상인 입력 1 자체가 제2원상이다.

제2원상은 다른 입력을 요구합니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

네 입력에는 여섯 쌍이 있습니다. 합집합 상한 6/16과 정확한 충돌 확률 683/2048을 비교하세요.

힌트 1

6/16을 분모가 2048인 분수로 바꿉니다.

힌트 2

세 출력이 같은 경우처럼 여러 쌍의 사건이 동시에 일어날 수 있습니다.

풀이와 답 확인

  1. 6/16=768/2048이므로 정확값 683/2048보다 큽니다.

  2. 여러 쌍의 충돌 사건이 겹치므로 개별 확률의 합은 상한입니다. 두 값의 차이는 85/2048입니다.

상한은 768/2048이고 정확한 충돌 확률은 683/2048입니다.

흔한 오답에서 다시 생각하기

충돌 쌍의 수를 더하면 언제나 정확한 성공률이다.

여러 쌍이 동시에 충돌하면 합에서 중복으로 셉니다.

충돌을 찾았으면 고정된 모든 입력의 제2원상도 찾았나요?

설명 기준 확인

아닙니다. 주어진 충돌의 두 입력과 별도로 지정한 입력의 목표는 다릅니다.

이 확률이 실제 해시의 측정 결과인가요?

설명 기준 확인

아닙니다. 서로 다른 입력에 대한 독립 균등 4비트 함수 출력이라는 가정 아래의 손계산입니다.

한 단계 더

2비트 출력에는4개 값만 있다. 다섯 개 서로 다른 입력을 함수에 넣으면 적어도 한 충돌이 있어야 한다. 위 표의 a/c가 실제로 그 쌍이다. 이것은 존재 증명이며 특정 보안 함수에서 효율적으로 쌍을 찾는 방법은 아니다.

  • NIST: Preimage resistance

    공식 정의 본문을 실제 읽어 계산상 어려움이라는 조건과 찾기 문제의 입력을 확인했다.

Merkle 구조

큰 자료 전체를 보내지 않고 그중 한 조각이 어떤 요약에 포함됨을 어떻게 확인할까?

준비 개념과 학습 목표

준비 개념

  • 이진 트리

  • 순서와 연결

다섯 leaf의 포함 증명은 어느 위치든 형제 해시 수가 같을까요?

RFC 9162의 ordered tree 규칙은 leaf 수 n보다 작은 가장 큰 2의 거듭제곱 k에서 목록을 나눕니다. 다섯 leaf에서는 4+1이고, 오른쪽 leaf를 복제해 여덟 leaf로 만드는 규칙이 아닙니다. ℓi=H(00||di), N(x,y)=H(01||x||y), p01=N(ℓ0,ℓ1), p23=N(ℓ2,ℓ3), R4=N(p01,p23)로 두면 R5=N(R4,ℓ4)입니다. 여기서 00과 01은 각각 한 바이트 0x00과 0x01을 뜻하며, ASCII 문자 두 개가 아닙니다.

index 4의 경로는 [R4] 한 개이고 index 2의 경로는 [ℓ3,p01,ℓ4] 세 개입니다. leaf 수와 위치 및 트리 모양에 따라 결합 순서를 정해야 합니다. 기준 root는 인증되어야 하며 계산 일치는 내용의 진실성이나 모든 자료의 공개 여부를 보장하지 않습니다. 실제 hash 값이나 로그 서비스는 실행하지 않습니다.

먼저 확인할 개념
  • Merkle 구조

    네 leaf의 순서·접두표·신뢰 root 설명을 비완전 트리에 확장합니다.

  • 충돌·원상·제2원상

요약을 다시 요약한다

순서 있는 자료 d₀,d₁,d₂,d₃의 leaf를 ℓᵢ=H(0x00||dᵢ)로 만들고 내부 결합을 N(x,y)=H(0x01||x||y)라 하자. ||는 바이트 연결이고 왼쪽·오른쪽 순서가 중요하다. root는 N(N(ℓ₀,ℓ₁),N(ℓ₂,ℓ₃))다. 여기서는 길이가 고정된 해시와 명확한 자료 인코딩을 가정한다.

leaf와 내부 노드의 접두표를 달리하는 domain separation은 자료 자체와 요약 두 개를 결합한 입력을 혼동하지 않게 한다. 모든 Merkle 구현이 같은 트리 모양·인코딩을 쓰는 것은 아니다. 여기서 참고한 RFC9162는 길이에 따라 정해지는 ordered tree 규칙을 갖는다.

형제 요약으로 경로를 채운다

d₂를 검증하려면 ℓ₂를 계산하고 오른쪽 형제 ℓ₃와 결합해 오른쪽 부모를 만든다. 다음에는 왼쪽 부모 p₀₁=N(ℓ₀,ℓ₁)를 받아 root를 재계산한다. 자료 전체 대신 경로에서 빠진 형제 요약을 받으면 된다. leaf index와 전체 tree size도 경로 해석에 필요하다.

기준 root는 별도로 신뢰할 수 있어야 한다. 공격자가 자료·증명·root를 전부 새로 만들어 보내면 내부 계산 일치만으로 원래 자료임을 증명할 수 없다. root의 서명·신뢰하는 배포 경로·기록 시점 같은 인증 조건을 함께 다룬다.

무엇이 증명되었는가

보안 해시와 올바른 인코딩·검증, 인증된 root 가정 아래 포함 증명은 특정 자료가 그 트리에 포함됨을 확인한다. 자료가 사실인지, 모든 필요한 항목이 로그에 들어왔는지, 새 로그가 이전 로그를 보존했는지는 별도 질문이다. RFC의 consistency proof는 이전 leaf들의 append-only 보존을 위한 다른 증명이다.

균형 잡힌2ᵏ leaf에서는 한 포함 경로에 k개 형제 요약이 필요하다. 이 숫자는 네 leaf의 손 구조 계산에 적용한다. 실제 해시 바이트 계산이나 RFC 프로토콜 실행, 공개 로그 서비스 검증은 수행하지 않았다.

Merkle 포함 증명을 통과하면 자료가 현실의 사실임까지 증명된다.

여섯 계정의 후보를 검사할 때 salt가 세 종류면 계산도 꼭 세 묶음인가요?

자체 오프라인 직렬 비용 모형입니다. 같은 알고리즘과 버전 및 출력 길이와 추가 입력을 사용합니다. 설정 P1의 호출 비용은 120 ms이고 P2의 호출 비용은 200 ms로 가정합니다. 계정 1·2·3은 (salt A,P1)이고 계정 4는 (B,P1)이며 계정 5는 (B,P2)이고 계정 6은 (C,P1)입니다. 각 계정에 같은 후보 20개를 비교합니다. 실제 Argon2 성능 측정이 아니며 이 시간은 가정입니다.

같은 후보를 같은 전체 입력 설정에 적용한 결과는 여러 계정의 검증값과 비교할 수 있습니다. 그러나 salt B가 같아도 P1과 P2는 다른 함수 입력이므로 한 결과를 그대로 재사용할 수 없습니다. 네 묶음에 각각 후보 20개를 적용하므로 KDF 호출은 80회입니다. 직렬 시간은 60×0.12+20×0.20=11.2초입니다. salt만 세 종류라고 세 묶음으로 세면 비용 설정 차이를 놓칩니다.

되돌리기 대신 후보를 검사한다

비밀번호 저장은 원문을 그대로 저장하거나 나중에 복호화할 수 있는 형태로 보관하는 문제와 다르다. 비밀번호용 해시/KDF는 비밀번호·salt·비용 설정으로 검증값을 만들고 로그인 후보에도 같은 저장 설정을 적용해 비교한다. 알고리즘·버전·salt·매개변수와 검증값을 함께 관리해야 한다.

공격자가 검증값 파일을 얻으면 후보 비밀번호를 오프라인으로 시험할 수 있다. 그래서 일반적인 빠른 파일 해시 한 번만 쓰는 것과 달리 각 후보의 계산 비용을 늘리도록 설계된 방식이 필요하다. 온라인 로그인 횟수 제한은 서버를 거치지 않는 오프라인 계산을 직접 막지 못한다.

salt는 공개해도 되는 서로 다른 입력

비밀번호별 충분히 큰 무작위 salt는 같은 비밀번호의 입력을 계정마다 다르게 만들고 공통 사전 계산의 재사용을 어렵게 한다. salt는 검증에 필요하므로 해시와 함께 저장할 수 있다. salt를 비밀 비밀번호처럼 감추어야만 작동하는 구조가 아니다.

서로 다른 salt가 출력의 수학적 무충돌을 보장하지는 않는다. 같은 비밀번호라고 반드시 같은 저장값이 되는 성질을 없애려는 입력 분리다. 약한 비밀번호의 후보 수가 자동으로 커지거나 사용자 비밀번호에 entropy가 추가되는 것은 아니다. 한 계정의 후보 추측은 여전히 가능하다.

시간·메모리와 실제 환경

Argon2 같은 memory-hard 함수는 메모리와 passes·parallelism 등을 입력으로 갖는다. 비용은 로그인 지연·서버 부하·공격자의 자원에 영향을 주므로 공식 방식과 신뢰할 수 있는 구현을 사용하고 실제 환경을 측정해 설정한다. 이 단원은 특정 운영 설정을 측정하거나 추천값으로 확정하지 않는다.

아래100ms는 설명용 가정이며 실제 Argon2 속도가 아니다. 후보 계산을 직렬로 하고 모든 호출 시간이 같다고 가정한다. 공격자의 병렬 장비·캐시·메모리 제약과 실패 정책은 포함하지 않았다. 코드를 반복 해시해 자체 보안 방식을 만드는 활동은 요구하지 않는다.

중간 과정을 따라가는 예제

자체 직렬 모형에서 한 KDF 호출이100ms다. 후보100개를 계정 하나에 검사할 때와 서로 다른 salt를 가진 계정10개에 각100개씩 검사할 때 시간은?

  1. 한 계정은100호출×0.1초=10초다.

  2. 계정10개의 서로 다른 salt 입력을 각 검사하면10×100=1000호출이다.

  3. 1000×0.1초=100초다.

  4. salt가 같고 동일 알고리즘·매개변수라면 한 후보 계산 결과를 여러 검증값과 비교하는 재사용이 가능하다는 차이를 본다.

단순 직렬 모형은10초와100초다. 실제 공격 속도나 모든 후보가 정답일 확률을 측정한 것이 아니다.

조건을 바꾸어 비교하기

계정별 반복과 묶음별 공유 비교

여섯 계정을 하나씩 독립 계산했을 때와 같은 후보 결과를 묶음 안에서 공유했을 때 호출과 직렬 시간은?

  1. 계정별 계산은 P1의 다섯 계정에서 100회, P2의 한 계정에서 20회이므로 총 120회입니다. 직렬 시간은 100×0.12+20×0.20=16초입니다.

  2. 묶음별 계산은 P1의 세 묶음에서 60회, P2의 한 묶음에서 20회이므로 총 80회입니다. 직렬 시간은 11.2초입니다.

같은 입력 결과의 공유로 호출 40회와 직렬 시간 4.8초를 줄입니다. 실제 공격 속도나 성공 비율이 아니라 명시한 비용 모형입니다.

비교할 점

기본 모두 다른 salt 예와 달리 salt 중복과 설정 차이가 함께 존재하는 기록을 비교합니다.

저장 설정을 바꿀 때 후보 검증 순서

기존 기록은 (A,P1,검증값 Vold)입니다. 새 목표 설정 P2로 옮기려 할 때 로그인 후보 p를 먼저 어느 설정으로 확인하나요?

  1. 저장된 salt A와 설정 P1 및 기존 알고리즘과 버전으로 후보를 검사합니다.

  2. 실패하면 기존 기록을 새 후보의 해시로 덮지 않습니다.

  3. 성공했다면 확인된 후보로 새 salt와 P2에 대한 새 검증값을 만듭니다. 설정과 값을 하나의 기록으로 일관되게 갱신하는 흐름을 설계합니다.

검증은 기존 설정, 마이그레이션은 검증 성공 뒤 새 설정입니다. 새 salt만 뽑아 기존 값과 비교하면 안 됩니다.

비교할 점

NIST의 설정 저장과 비용 상향 원칙을 적용한 자체 흐름 설계입니다. DB 갱신이나 동시성 및 실제 로그인은 시험하지 않았습니다.

salt가 공개되면 무용하고, salt를 넣으면 짧은 비밀번호도 추측할 수 없다.

한 단계 더

salt를 충분히 큰 무작위 공간에서 독립 생성해도 중복 가능성이 완전히0은 아니다. 실제 구현은 공식 지침의 길이·난수·저장 형식을 따른다. 별도 비밀값을 추가하는 방식은 공개 salt와 역할이 다르며 비밀 관리·회전·복구까지 설계해야 한다. 이 단원에서는 그 운영 체계를 구현하거나 시험하지 않았다.

아무 충돌과 고정 목표 적중은 서로 다른 사건이고, 트리는 4+1입니다.

풀이와 답 확인

  1. 충돌 확률은 683/2048, 목표 적중 확률은 14911/65536입니다. 독립·균등 출력과 서로 다른 입력이라는 조건입니다.

  2. 형제 [R4] 한 개, leaf를 포함한 해시 2회입니다. ordered tree 규칙과 인증된 root 조건을 적습니다.

보강 자료의 출처와 확인 범위
  • NIST CSRC — Collision resistance

    실제정의본문의계산상충돌찾기어려움조건을읽었다. 무충돌존재보장과구별하며4bit확률은자체이상모형손유도다.

  • NIST CSRC — Preimage resistance

    실제주어진digest의원상찾기정의를읽었다. 전체제한도메인표의상밖출력부재와원래원본복원요구를구별했다.

  • NIST CSRC — Second preimage resistance

    실제제2원상저항성정의본문을읽었다. 주어진입력과다른입력이라는조건은기본단원설명과자체표에서손대조했다.

  • RFC 9162 — Ordered Merkle tree

    실제2.1.1의n보다작은최대2거듭제곱분할과접두표,2.1.3의PATH재귀·크기/위치·root대조·sn0이후추가경로거절및2.1.4의일관성과포함구별을읽었다. 다섯/일곱leaf경로는자체기호추적이며실제hash출력·로그서비스는실행하지않았다.

  • NIST SP 800-63B-4 — Password verifiers

    실제3.1.1.2의password/salt/cost입력·저장및알고리즘과비용설정기록·성능을고려한상향원칙을읽었다. 마이그레이션흐름과120/200ms비용은자체설계가정으로운영정책·실측값을주장하지않는다.

  • RFC 9106 — Argon2 inputs

    실제3.1의password/salt/lanes/taglength/memory/passes/version/type및optional입력,3.2초기입력결합식에서설정들이함수입력인점을읽었다. 실제Argon2구현·시간·메모리성능은측정하지않았다.

서로 다른 네 질의의 충돌 확률 683/2048과 고정 목표 적중 확률 14911/65536을 손유도했다. 두 질의에서는 충돌 확률이 1/16이고 고정 목표 적중 확률이 31/256이다. 네 질의의 합집합 상한 768/2048과 정확값의 차이가 85/2048임을 확인했다. 전체 제한 표의 상과 제2원상 부재를 대조했다. 다섯 leaf의 index 4는 경로 형제 1개와 해시 2회가 필요하며 index 0과 2는 형제 3개와 해시 4회가 필요하다. 일곱 leaf의 index 6은 형제 2개와 해시 3회임을 구조로 손대조했다.
