학습 목표

집단별 오류가 줄었는데 전체 오류율은 왜 늘었을까요?

앞 본문은 집단별 분모와 평가 판본을 연결합니다. 새 가상 장부에서 옛 모델 m1의 집단 K는 요청 90개 중 오류 9개이고 집단 J는 요청 10개 중 오류 5개입니다. 새 모델 m2는 K의 요청 20개 중 오류 1개, J의 요청 80개 중 오류 32개입니다. 두 장부의 오류 정의와 집단 분류는 같지만 요청 구성은 다릅니다. 실제 모델 평가나 사람의 자료가 아닙니다.

K의 관측 오류율은 10%에서 5%로, J는 50%에서 40%로 줄었습니다. 하지만 전체 관측 오류율은 m1이 14%, m2가 33%입니다. 오류율이 높은 J의 비중이 커져 집단별 관측 감소와 전체 관측 증가가 동시에 가능합니다. 이 자료만으로 모델 교체가 오류율 변화의 원인이라고 확정하지 않습니다.

비교용 목표 구성에서 K와 J에 각각 1/2의 가중치를 준다고 명시하면 m1의 가중 오류율은 30%, m2는 22.5%입니다. 이는 실제 장부의 14%와 33%를 지우는 계산이 아니라 같은 목표 구성으로 다시 요약한 값입니다. 목표 구성의 타당성이나 실제 공정성 통과도 별도 문제입니다.

공개 후보를 데이터 판본 d2, 모델 m2, 평가 조건 e2, 공개 목적 p2의 묶음으로 고정한다고 가정합니다. 자체 승인 정책은 검토자가 그 묶음을 확인한 기록과 현재 후보가 정확히 같을 때만 공개합니다. d1·m2의 검토 기록으로 d2·m2를 승인했다고 쓰거나, 검토 뒤 후보를 바꾸고 옛 체크 표시를 유지하는 것은 이 정책을 만족하지 않습니다. 법률상 책임이나 실제 승인 시스템 구현을 주장하지 않습니다.

먼저 확인할 개념
  • 데이터·모델·배포 책임

    집단별 분모와 데이터·모델 판본을 연결한 기본 설명을 구성 변화와 승인 묶음의 구별로 확장합니다.

  • 인간 감독과 실패 대응

    실질 권한과 재개 조건을 설명한 기본 본문을 변경 뒤 재검토 정책에 연결합니다.

단계마다 확인해야 할 질문이 다르다

학습 자료 안내 모델을 만든다고 하자. 데이터 단계는 자료의 출처·허용된 사용 목적·제외 기준을 묻고, 모델 단계는 어떤 버전과 평가 조건에서 어떤 오류가 생겼는지 묻는다. 배포 단계는 누구에게 결과를 보여 주며 문제가 생기면 어떻게 바꿀지를 묻는다. 한 단계의 기록으로 나머지 책임을 없앨 수 없다.

데이터 담당 D는 출처와 변경 이력을, 모델 담당 M은 평가 장부를, 운영 담당 O는 공개 범위와 중단 경로를 관리하는 자체 역할표를 둔다. 최종 판단 담당 A는 근거를 확인하고 범위를 승인하며, 별도 검토자 R은 원고와 평가 근거를 확인한다. 이 역할표는 법률상 책임 귀속을 단정한 표가 아니다.

평균을 이유로 작은 집단을 지우지 않는다

교육용 가상 평가에서 언어 집단별로 요청 수와 오류 수를 따로 적는다. 오류율은 오류 수를 해당 요청 수로 나눈 값이다. 전체 비율은 집단 비율의 단순 평균과 다를 수 있으므로 분모를 먼저 확인한다.

평균이 낮아도 특정 집단에 오류가 몰릴 수 있다. 숫자 차이가 생겼다는 관찰과 원인·차별·장래 성능에 대한 결론은 구별한다. 표본의 선정과 오류 정의를 확인하고 그 집단의 사용 경험을 조사할 계획이 필요하다. 여기에는 실제 참여자의 평가 결과가 없다.

증거를 다음 담당자가 쓸 수 있게 넘긴다

기록에는 데이터 버전 d1, 모델 버전 m1, 평가 조건, 발견한 문제와 사용 제한을 연결한다. 데이터 수정 후 이전 평가표가 새 버전에도 그대로 맞는다고 가정하면 안 된다. 영향받는 평가를 다시 확인해야 한다.

해결하지 못한 위험이 있으면 담당자와 다음 확인 조건을 적고 공개 범위를 제한하거나 보류하는 대안을 비교한다. 문서의 체크 표시와 실제 검증 성공을 별도로 남긴다. 담당자가 정해졌다는 사실만으로 책임이 끝나지 않는다.

전체 오류는 14개 / 요청 100개로 14%다.

새 장부 m2

K는 오류 1개 / 요청 20개, J는 오류 32개 / 요청 80개다.

전체 오류는 33개 / 요청 100개로 33%다.

같은 목표 구성

K와 J에 각각 가중치 1/2를 부여한다.

m1의 가중 오류율은 30%, m2는 22.5%다.

승인 묶음

데이터·모델·평가 조건·공개 목적이 검토 기록과 같다.

한 항목이라도 변경되면 옛 기록만으로 승인하지 않는다.

장부의 실제 요청 비중과 별도로 지정한 목표 가중치를 구별합니다. 오류율의 차이는 퍼센트포인트로 보고하고 인과나 승인 성공으로 확대하지 않습니다.

중간 과정을 따라가는 예제

가상 m1 평가에서 집단 K는 80요청 중 오류4, 집단 J는 20요청 중 오류6이다. 전체 오류율, 집단별 오류율, 차이를 구하고 단순 평균과 비교하라.

  1. K는 4/80=5%, J는 6/20=30%다. J와 K의 차이는 25퍼센트포인트다.

  2. 전체는 (4+6)/(80+20)=10/100=10%다. 두 비율의 단순 평균은 (5+30)/2=17.5%로 전체 비율이 아니다.

  3. 가상 팀은 오류 원인과 J의 평가 대표성을 확인하고, D/M/O/A/R의 후속 역할을 기록한다. 이 표만으로 공정성 통과나 실제 배포 승인을 선언하지 않는다.

전체10%와 K5%/J30%를 함께 보고한다. 표본 수가 달라 전체와 단순 평균이 다르며 원인은 추가 근거가 필요하다.

두 모델의 집단별 오류율과 전체 오류율을 계산하세요.

  1. m1의 K 오류율은 9/90 = 10%, J 오류율은 5/10 = 50%입니다.

  2. m2의 K 오류율은 1/20 = 5%, J 오류율은 32/80 = 40%입니다.

  3. m1 전체는 14/100 = 14%이고 m2 전체는 33/100 = 33%입니다.

두 집단의 관측 오류율은 각각 감소했지만 전체 관측 오류율은 19퍼센트포인트 증가했습니다.

비교할 점

구성 비중이 다른 두 전체 비율은 같은 집단 구성의 비교가 아닙니다.

같은 목표로 비교한 값

K와 J가 각각 절반인 목표 구성에서 두 가중 오류율을 구하세요.

  1. m1은 (10% + 50%)/2 = 30%입니다.

  2. m2는 (5% + 40%)/2 = 22.5%입니다.

  3. 가중 오류율은 7.5퍼센트포인트 감소하지만 실제 두 장부의 전체 비율은 그대로 보고합니다.

같은 목표 구성의 요약에서는 m2가 낮습니다. 이 산술만으로 배포 적합성·공정성이나 변화 원인을 확정하지 않습니다.

목표 가중 요약과 관측 장부를 이름 없이 바꿔 쓰지 않습니다.

오해와 반례

모델 공급자가 있으니 사용하는 조직은 결과를 확인할 책임이 없다.

구성요소의 문서와 현재 사용 맥락을 연결해야 한다. 공급자 평가만으로 새로운 사용자·데이터·용도의 위험이 검증되지는 않는다.

연습 1 · 값과 상태 예측

목표 구성의 K 비중이 80%, J 비중이 20%라면 두 모델의 가중 오류율을 구하세요.

힌트 1

각 집단 오류율에 목표 비중을 곱합니다.

힌트 2

장부의 요청 수를 새 실제 평가 결과로 만들어 쓰지 않습니다.

풀이와 답 확인

  1. m1의 가중 오류율은 0.8×10% + 0.2×50% = 18%입니다.

  2. m2의 가중 오류율은 0.8×5% + 0.2×40% = 12%입니다.

m1은 18%, m2는 12%로 가중 차이는 6퍼센트포인트입니다.

흔한 오답에서 다시 생각하기

전체 장부가 각각 100개이므로 목표 가중치도 자동으로 같다.

요청 수가 같아도 집단 구성은 다를 수 있습니다.

연습 2 · 오류 찾아 고치기

검토 기록은 (d1,m2,e2,p2)인데 현재 후보는 (d2,m2,e2,p2)입니다. 모델 이름이 같으므로 검토 완료라고 보고한 문장을 고치세요.

힌트 1

모델 이외의 항목도 비교합니다.

힌트 2

데이터 변경의 영향을 검토하는 상태와 완료한 상태를 구별합니다.

풀이와 답 확인

  1. 데이터 판본 d1과 d2가 다릅니다.

  2. 현재 후보를 고정하고 데이터 변경에 영향을 받는 평가와 공개 조건을 재검토하도록 보류 상태를 기록합니다.

옛 기록은 현재 묶음의 검토 완료 근거가 아닙니다. 재검토가 끝났다는 실제 증거는 아직 없습니다.

흔한 오답에서 다시 생각하기

모델 파일 하나가 같으면 모든 사용 조건도 같다.

평가 결과의 적용 범위에는 데이터·조건·목적도 포함됩니다.

연습 3 · 직접 만들어 보기

현재 후보와 검토 기록의 묶음이 맞을 때만 공개한다는 자체 정책을 종이에 설계하세요. 검토 중 후보 변경도 고려하세요.

힌트 1

검토할 묶음에 고정 ID를 부여합니다.

힌트 2

공개 시점에도 같은 묶음인지 확인하는 규칙을 씁니다.

풀이와 답 확인

  1. 검토 기록에 데이터·모델·평가 조건·목적과 후보 ID를 함께 남깁니다.

  2. 공개 판단은 그 후보를 대상으로 하며 중간에 내용이 바뀌면 새 후보 ID로 재검토합니다.

  3. 같은 후보의 확인과 공개를 하나의 정책 사건으로 정의합니다. 실제 동시성 구현과 법적 승인은 별도 미확인 상태입니다.

묶음의 동일성과 변경 뒤 재검토를 요구하는 설계입니다. 문서 규칙만으로 서버가 이를 원자적으로 구현했다고 주장하지 않습니다.

흔한 오답에서 다시 생각하기

처음 한 번 읽은 후보 ID만 기억하면 뒤의 변경은 상관없다.

문장의 일부가 맞으면 문장 전체도 확인된 것일까요?

앞 본문은 링크 접근과 주장 지지를 구별합니다. 새 가상 생성 문장은 “자료 d2는 공개가 허용됐고, 모든 입력에서 모델 m2의 오류가 0이며, 응답 시간이 1초 이하이고, 오늘의 공개 목적 p2에도 사용할 수 있다”입니다. 이 문장을 따로 확인할 원자 주장 A·B·C·D로 분해합니다. 여기서 A는 자료 공개 허용, B는 모든 입력의 오류 0, C는 응답 시간 1초 이하, D는 오늘의 목적 p2에 대한 사용 허용입니다. 전체 문장은 네 조건이 모두 참이라는 결합이며 네 주장의 통계적 독립성을 가정하지 않습니다.

가상 원문 장부는 A를 지지하고 B를 반박하며 C를 지지하고 D는 아직 확인하지 못했습니다. 원자 주장 네 개 중 지지는 2개, 반박은 1개, 미확인은 1개입니다. 지지 비율 50%를 원래 결합 문장이 절반 참이라는 판정으로 바꾸지 않습니다. B가 반박돼 원래 전체 결합은 지지되지 않습니다. 여기의 원문 상태는 과제 전제이지 실제 모델이나 자료의 검증 결과가 아닙니다.

B를 “지정된 입력 두 개에서는 오류를 관측하지 않았다”라는 새 주장 B′로 바꾸고 실제로 두 입력 장부를 대조했다고 가정합니다. 이 좁은 주장만 지지하며 “모든 입력”은 증명하지 않습니다. D를 공개 후보에서 제외하면 새 후보의 세 주장 A·B′·C는 지지 3개 / 대상 3개로 100%입니다. 옛 네 주장의 지지가 4개로 바뀐 것은 아니며 p2 목적 승인은 여전히 미확인입니다.

동일한 원문을 두 사이트가 그대로 복제했다면 열린 링크는 두 개여도 독립적인 근거 두 개가 아닙니다. 주장과 실제 원문 위치·범위·판본을 연결하고 수정 전후 장부를 따로 보존합니다. 명백한 반박과 확인 부족을 모두 “검색 실패” 하나로 합치지 않습니다.

유창함은 근거의 확인 결과가 아니다

생성 모델은 자연스럽게 읽히는 답을 만들면서 틀린 내용이나 존재하지 않는 인용을 섞을 수 있다. 긴 설명과 논리적인 말투가 붙었다고 사실이 확인된 것은 아니다. 창작한 이야기와 사실 전달용 설명은 목적을 분명히 구별한다.

사실 주장을 문장별로 나누고, 원문을 열어 해당 내용과 조건을 확인한다. 링크가 열리는가, 주제와 관련되는가, 바로 그 주장을 지지하는가는 서로 다른 질문이다. 날짜·대상·예외가 다르면 그 인용을 그대로 근거로 삼을 수 없다.

검증 장부를 작성한다

자체 장부 C1부터 C5는 교육용 생성 설명에 들어간 다섯 사실 주장이다. 각각 확인됨·반박됨·미확인의 상태와 읽은 원문 위치를 남긴다. 미확인은 거짓이라는 결론도, 참이라는 결론도 아니다.

인용이 지지하지 않는 문장은 원문에 맞춰 수정하고 새 문장을 다시 검토하거나 제외한다. 출처를 숨겨 놓고 문장을 고친 사실만으로 확인됨으로 바꾸지 않는다. 출처에 포함된 개인정보나 재사용 제한도 함께 살핀다.

작은 장부를 모델 전체 성능으로 바꾸지 않는다

다섯 문장 검토의 비율은 그 장부에서 확인된 수치다. 모든 질문에 대한 모델 정확도나 안전성을 측정한 값이 아니다. 질문 선정, 분야, 오류 정의와 미확인 처리 방식이 다르면 수치도 달라진다.

AI가 초안을 도왔다는 표시와 사람의 근거 검토는 별개다. 표시만으로 문장이 맞아지지 않고, 사람이 읽었다는 말만으로 실제 원문 확인을 대신할 수도 없다. 공개할 문장과 보류할 문장을 책임 있게 결정한다.

중간 과정을 따라가는 예제

C1/C2는 원문 지지, C3는 원문 반박, C4/C5는 미확인이다. 인용 링크는4개가 열리고 그중3개가 관련되며 그중2개만 해당 주장을 지지한다. 주장 확인율과 링크 단계별 비율을 구하라.

  1. 다섯 주장 중 확인2·반박1·미확인2다. 전체 주장 확인율은2/5=40%다.

  2. 링크 열림4/5=80%, 전체 중 관련3/5=60%, 전체 중 지지2/5=40%다. 열린 링크 중 지지는2/4=50%다.

  3. 미확인을 제외한 판정된 주장3개만 보면 지지2/3≈66.67%다.40%와 분모가 달라 바꿔 쓰면 안 된다.

평균 검토 용량이 충분하면 모든 요청이 제때 확인될까요?

앞 본문은 실질 감독에 시간과 권한이 필요함을 설명합니다. 새 모형에서 검토자 두 명이 있고 한 요청은 30초 동안 한 사람을 독점합니다. 중단이나 병렬 분할은 없고 두 사람은 항상 같은 품질로 검토한다고 가정합니다. 시각 0에 요청 여덟 개가 동시에 도착하며 다른 도착은 없습니다. 각 요청은 도착 후 60초 이내에 검토 완료해야 하는 자체 마감을 가집니다. 대기는 처음에 없고 요청 ID 순서의 FIFO로 시작합니다.

두 검토자는 요청 두 개씩 네 묶음을 처리합니다. 완료 시각은 첫 두 개가 30초, 다음 두 개가 60초, 다음 두 개가 90초, 마지막 두 개가 120초입니다. 60초 등호는 성공에 포함하므로 마감 성공은 4개 / 전체 8개로 50%입니다. 긴 관찰창의 평균 도착량이 낮다는 사실만으로 이 동시 도착의 마감을 지키지는 못합니다.

같은 길이의 요청이라도 실제로 읽을 근거가 없거나 반려·보류 권한이 없으면 처리 완료 표시만으로 감독이 충분하다고 볼 수 없습니다. 이 시간 모형은 품질·피로·개인 능력의 실측이 아닙니다. 사람이 최종 버튼을 눌렀다는 표와 필요한 정보·권한·검토 시간의 확보는 별도로 남깁니다.

별도 복구 장부에서 시각 40초에 잘못된 출력의 공개를 막고 시각 50초에 옛 모델로 되돌렸다고 가정합니다. 시각 20초에 이미 출력받은 요청 U는 공개 중단이나 모델 rollback만으로 정정되지 않습니다. 현재 모델 상태, 앞으로 막는 범위, 과거 출력의 정정, 새 후보의 독립 재검토와 재개 판단을 별개 상태로 추적합니다.

감독은 이름보다 실행 조건이 중요하다

검토자는 판단에 필요한 근거를 볼 수 있어야 하고, 문제를 반려하거나 중단할 권한과 이를 수행할 시간이 있어야 한다. 결과를 거의 읽지 않고 확인 버튼만 누르는 절차는 오류를 막았다는 증거가 아니다.

가상 학습 안내 서비스에서 운영 담당 O는 결과 공개를 멈추고, 내용 검토자 R은 잘못된 안내를 확인하며, 책임 담당 A는 수정과 재개 조건을 결정한다고 정한다. 사용자도 오류를 알리고 이의를 제기할 경로를 가진다. 이 표는 실제 서비스에 적용한 절차가 아니다.

실패에서 복구까지 상태를 나눈다

오류 감지→범위 확인→출력 보류→사용자 안내와 대안 제공→원인 수정→독립 재검토→재개 판단 순의 교육용 상태표를 만든다. 위험이 크면 분석이 끝날 때까지 기다리지 않고 보류할 수 있다.

이전 모델로 되돌렸어도 이미 잘못된 안내를 받은 사람이 자동으로 복구된 것은 아니다. 영향 범위를 기록하고 필요한 정정과 후속 조치를 연결한다. 재개 판단에는 새 버전 근거와 남은 위험을 남기며 권한 없는 사람이 검토 상태를 건너뛰지 않게 한다.

검토 능력을 넘으면 절차를 바꾼다

한 시간에 들어오는 요청 수와 한 사람이 읽을 수 있는 수를 비교한다. 모형은 한 요청마다 같은 시간이 들고 휴식·중복·예외 처리가 없다고 가정한다. 실제 사람의 피로와 처리 품질은 이 계산만으로 검증되지 않는다.

대기열이 늘면 범위 축소·요청 제한·보류·수동 자료 제공 등의 대안을 검토한다. 적게 검토하면서 전부 감독했다고 표시하지 않는다. 위험이 다른 요청을 같은 우선순위로 취급하는 것이 적절한지도 별도로 판단한다.

주장 제외는 분모 변경이며 FIFO 완료 시각은 두 요청씩 묶어 셉니다.

풀이와 답 확인

  1. m1의 K는 5%, J는 40%이며 전체는 12/100 = 12%입니다. m2의 K는 10%, J는 20%이며 전체는 18/100 = 18%입니다.

  2. K와 J가 절반인 목표에서 m1은 22.5%, m2는 15%입니다. K는 악화되고 J는 개선돼 이 전이에서는 모든 집단이 개선됐다는 말은 성립하지 않습니다.

  3. 원래 세 주장은 지지 2/3이고 R은 미확인입니다. R을 제외한 새 후보는 지지 2/2 = 100%지만 R의 상태가 지지로 바뀐 것은 아닙니다.

  4. 요청 1·2는 30초, 요청 3·4는 60초, 요청 5는 90초에 완료합니다. 마감 성공은 4/5 = 80%이고 마지막 완료 시각은 90초입니다.

관측 전체 오류율은 m1이 12%, m2가 18%입니다. 같은 절반 목표의 가중 오류율은 m1이 22.5%, m2가 15%입니다. 새 두 주장 후보의 지지는 100%지만 원래 R은 여전히 미확인입니다. 요청별 마감 성공은 80%이며 전체 완료는 90초입니다. 이 요약으로 실제 배포 적합성·책임 귀속·사람 감독 품질을 확정하지 않습니다.
