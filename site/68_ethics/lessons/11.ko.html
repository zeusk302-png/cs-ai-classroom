소단원 11.1

데이터·모델·배포 책임

데이터를 만든 사람과 모델을 배포한 사람 중 누가 오류를 설명해야 할까?

준비 개념과 학습 목표

준비 개념

  • 데이터와 모델의 구별
  • 분자와 분모
  • 역할과 권한

학습 목표

  • 수명주기 단계별 근거와 담당자를 연결한다.
  • 전체 평균과 집단별 결과를 함께 계산한다.
  • 배포 결정을 검증 기록과 연결한다.

단계마다 확인해야 할 질문이 다르다

학습 자료 안내 모델을 만든다고 하자. 데이터 단계는 자료의 출처·허용된 사용 목적·제외 기준을 묻고, 모델 단계는 어떤 버전과 평가 조건에서 어떤 오류가 생겼는지 묻는다. 배포 단계는 누구에게 결과를 보여 주며 문제가 생기면 어떻게 바꿀지를 묻는다. 한 단계의 기록으로 나머지 책임을 없앨 수 없다.

데이터 담당 D는 출처와 변경 이력을, 모델 담당 M은 평가 장부를, 운영 담당 O는 공개 범위와 중단 경로를 관리하는 자체 역할표를 둔다. 최종 판단 담당 A는 근거를 확인하고 범위를 승인하며, 별도 검토자 R은 원고와 평가 근거를 확인한다. 이 역할표는 법률상 책임 귀속을 단정한 표가 아니다.

평균을 이유로 작은 집단을 지우지 않는다

교육용 가상 평가에서 언어 집단별로 요청 수와 오류 수를 따로 적는다. 오류율은 오류 수를 해당 요청 수로 나눈 값이다. 전체 비율은 집단 비율의 단순 평균과 다를 수 있으므로 분모를 먼저 확인한다.

평균이 낮아도 특정 집단에 오류가 몰릴 수 있다. 숫자 차이가 생겼다는 관찰과 원인·차별·장래 성능에 대한 결론은 구별한다. 표본의 선정과 오류 정의를 확인하고 그 집단의 사용 경험을 조사할 계획이 필요하다. 여기에는 실제 참여자의 평가 결과가 없다.

증거를 다음 담당자가 쓸 수 있게 넘긴다

기록에는 데이터 버전 d1, 모델 버전 m1, 평가 조건, 발견한 문제와 사용 제한을 연결한다. 데이터 수정 후 이전 평가표가 새 버전에도 그대로 맞는다고 가정하면 안 된다. 영향받는 평가를 다시 확인해야 한다.

해결하지 못한 위험이 있으면 담당자와 다음 확인 조건을 적고 공개 범위를 제한하거나 보류하는 대안을 비교한다. 문서의 체크 표시와 실제 검증 성공을 별도로 남긴다. 담당자가 정해졌다는 사실만으로 책임이 끝나지 않는다.

중간 과정을 따라가는 예제

가상 m1 평가에서 집단 K는 80요청 중 오류4, 집단 J는 20요청 중 오류6이다. 전체 오류율, 집단별 오류율, 차이를 구하고 단순 평균과 비교하라.

  1. K는 4/80=5%, J는 6/20=30%다. J와 K의 차이는 25퍼센트포인트다.
  2. 전체는 (4+6)/(80+20)=10/100=10%다. 두 비율의 단순 평균은 (5+30)/2=17.5%로 전체 비율이 아니다.
  3. 가상 팀은 오류 원인과 J의 평가 대표성을 확인하고, D/M/O/A/R의 후속 역할을 기록한다. 이 표만으로 공정성 통과나 실제 배포 승인을 선언하지 않는다.

전체10%와 K5%/J30%를 함께 보고한다. 표본 수가 달라 전체와 단순 평균이 다르며 원인은 추가 근거가 필요하다.

오해와 반례

모델 공급자가 있으니 사용하는 조직은 결과를 확인할 책임이 없다.

구성요소의 문서와 현재 사용 맥락을 연결해야 한다. 공급자 평가만으로 새로운 사용자·데이터·용도의 위험이 검증되지는 않는다.

소단원 11.2

생성물과 신뢰

그럴듯한 인용 링크가 있으면 생성한 설명을 그대로 믿어도 될까?

준비 개념과 학습 목표

준비 개념

  • 사실 주장과 의견
  • 출처와 인용
  • 부분집합

학습 목표

  • 생성 문장과 검증된 사실을 구별한다.
  • 인용의 존재·관련성·내용 지지를 따로 확인한다.
  • 검증 비율의 분모와 한계를 설명한다.

유창함은 근거의 확인 결과가 아니다

생성 모델은 자연스럽게 읽히는 답을 만들면서 틀린 내용이나 존재하지 않는 인용을 섞을 수 있다. 긴 설명과 논리적인 말투가 붙었다고 사실이 확인된 것은 아니다. 창작한 이야기와 사실 전달용 설명은 목적을 분명히 구별한다.

사실 주장을 문장별로 나누고, 원문을 열어 해당 내용과 조건을 확인한다. 링크가 열리는가, 주제와 관련되는가, 바로 그 주장을 지지하는가는 서로 다른 질문이다. 날짜·대상·예외가 다르면 그 인용을 그대로 근거로 삼을 수 없다.

검증 장부를 작성한다

자체 장부 C1부터 C5는 교육용 생성 설명에 들어간 다섯 사실 주장이다. 각각 확인됨·반박됨·미확인의 상태와 읽은 원문 위치를 남긴다. 미확인은 거짓이라는 결론도, 참이라는 결론도 아니다.

인용이 지지하지 않는 문장은 원문에 맞춰 수정하고 새 문장을 다시 검토하거나 제외한다. 출처를 숨겨 놓고 문장을 고친 사실만으로 확인됨으로 바꾸지 않는다. 출처에 포함된 개인정보나 재사용 제한도 함께 살핀다.

작은 장부를 모델 전체 성능으로 바꾸지 않는다

다섯 문장 검토의 비율은 그 장부에서 확인된 수치다. 모든 질문에 대한 모델 정확도나 안전성을 측정한 값이 아니다. 질문 선정, 분야, 오류 정의와 미확인 처리 방식이 다르면 수치도 달라진다.

AI가 초안을 도왔다는 표시와 사람의 근거 검토는 별개다. 표시만으로 문장이 맞아지지 않고, 사람이 읽었다는 말만으로 실제 원문 확인을 대신할 수도 없다. 공개할 문장과 보류할 문장을 책임 있게 결정한다.

중간 과정을 따라가는 예제

C1/C2는 원문 지지, C3는 원문 반박, C4/C5는 미확인이다. 인용 링크는4개가 열리고 그중3개가 관련되며 그중2개만 해당 주장을 지지한다. 주장 확인율과 링크 단계별 비율을 구하라.

  1. 다섯 주장 중 확인2·반박1·미확인2다. 전체 주장 확인율은2/5=40%다.
  2. 링크 열림4/5=80%, 전체 중 관련3/5=60%, 전체 중 지지2/5=40%다. 열린 링크 중 지지는2/4=50%다.
  3. 미확인을 제외한 판정된 주장3개만 보면 지지2/3≈66.67%다.40%와 분모가 달라 바꿔 쓰면 안 된다.

장부의 전체 확인40%, 판정된 주장 중 지지66.67%다. 링크 성공80%는 내용 정확도를 보장하지 않는다.

종이와 본문으로 직접 해보기

힌트 보기

풀이 보기

인간 감독과 실패 대응

사람이 최종 확인 버튼을 누르면 감독이 충분한 걸까?

준비 개념과 학습 목표

준비 개념

  • 대기열과 처리량
  • 역할·권한
  • 상태 전이

학습 목표

  • 감독의 정보·시간·권한 조건을 설명한다.
  • 중단·수동 대안·복구의 증거를 구별한다.
  • 가상 대응 시간과 검토 용량을 계산한다.

감독은 이름보다 실행 조건이 중요하다

검토자는 판단에 필요한 근거를 볼 수 있어야 하고, 문제를 반려하거나 중단할 권한과 이를 수행할 시간이 있어야 한다. 결과를 거의 읽지 않고 확인 버튼만 누르는 절차는 오류를 막았다는 증거가 아니다.

가상 학습 안내 서비스에서 운영 담당 O는 결과 공개를 멈추고, 내용 검토자 R은 잘못된 안내를 확인하며, 책임 담당 A는 수정과 재개 조건을 결정한다고 정한다. 사용자도 오류를 알리고 이의를 제기할 경로를 가진다. 이 표는 실제 서비스에 적용한 절차가 아니다.

실패에서 복구까지 상태를 나눈다

오류 감지→범위 확인→출력 보류→사용자 안내와 대안 제공→원인 수정→독립 재검토→재개 판단 순의 교육용 상태표를 만든다. 위험이 크면 분석이 끝날 때까지 기다리지 않고 보류할 수 있다.

이전 모델로 되돌렸어도 이미 잘못된 안내를 받은 사람이 자동으로 복구된 것은 아니다. 영향 범위를 기록하고 필요한 정정과 후속 조치를 연결한다. 재개 판단에는 새 버전 근거와 남은 위험을 남기며 권한 없는 사람이 검토 상태를 건너뛰지 않게 한다.

검토 능력을 넘으면 절차를 바꾼다

한 시간에 들어오는 요청 수와 한 사람이 읽을 수 있는 수를 비교한다. 모형은 한 요청마다 같은 시간이 들고 휴식·중복·예외 처리가 없다고 가정한다. 실제 사람의 피로와 처리 품질은 이 계산만으로 검증되지 않는다.

대기열이 늘면 범위 축소·요청 제한·보류·수동 자료 제공 등의 대안을 검토한다. 적게 검토하면서 전부 감독했다고 표시하지 않는다. 위험이 다른 요청을 같은 우선순위로 취급하는 것이 적절한지도 별도로 판단한다.
