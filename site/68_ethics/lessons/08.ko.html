설명 가능성과 책임

이유를 그럴듯하게 보여 주면 틀린 결정도 옳아질까?

무엇을 설명할 것인가

설명 가능성은 시스템의 작동 방식을 이해할 수 있게 보여주는 관점이고, 해석은 그 출력이 사용 맥락에서 무엇을 뜻하는지 이해하는 관점이다. 사용자는 점수 숫자보다 어떤 자료와 기준이 사용되었는지 궁금할 수 있다. 개발자는 오류 분기를 추적할 정보가 필요할 수 있다.

설명을 받는 사람의 역할·지식·목적에 맞추어 수준을 정한다. 모든 내부 숫자를 공개하는 것이 항상 쉽고 유용한 설명인 것은 아니다. 설명이 참고하는 모형 버전과 입력 정보를 틀리게 적으면 문장만 유창해도 그 결정을 설명하지 못한다.

설명과 정확성은 별도

모형이 실제로 사용한 규칙을 설명하는 것과 규칙이 좋은지 판단하는 것은 다르다. 잘못 입력된 자료를 정확히 계산해도 결과는 사용자 상황과 어긋날 수 있다. 설명을 이유 없는 안심 문구로 쓰지 않고 확인과 교정에 연결한다.

책임의 설계에는 자료 오류 접수·기준 검토·결정 수정 같은 역할이 필요하다. 이 활동의 역할표는 자체 권고 모형이며 특정 나라의 법적 책임 배분이 아니다. 법적 의무는 실제 관할·제품·계약의 규칙을 별도로 확인해야 한다.

자체 선형 모형을 투명하게

예제는 실제 대출·성적·채용 모형이 아닌 장난감 규칙이다. 점수=2x+y이고 5 이상이면 추천한다고 정의한다. 계수와 임계값을 적으면 숫자 연산의 과정은 검사할 수 있지만 현실적으로 공정한 규칙인지는 아직 모른다.

사용자 설명에는 사용값·기준·결과·자료 교정 방법을 적고 검토자용에는 버전과 계산을 덧붙인다. x 값이 잘못되었을 때 그 값을 고칠 담당 경로가 없으면 계산 설명만으로 문제가 해결되지 않는다.

중간 과정을 따라가는 예제

자체 모형 v1은 score=2x+y, score≥5이면 추천한다. 저장 입력은 x=1, y=2이며, 정정 요청은 x=2, y=2다. 처음 결과와 정정 결과를 계산하고 담당자가 확인할 근거를 설명하자.

  1. 처음 score=2×1+2=4이므로 추천하지 않는다. “규칙 v1 / 저장값 1,2 / 기준 5 / 결과 4”를 설명한다.

  2. 정정값을 검증하여 반영한 뒤 score=2×2+2=6으로 추천한다. 요청자의 주장과 검증 완료를 구별한다.

  3. 자료 담당이 값의 근거, 모형 담당이 규칙, 결정 담당이 수정 결과를 확인하도록 자체 역할표를 작성한다.

계산 4→6은 입력 정정 조건에서 정확하다. 설명만 추가하고 입력을 그대로 두면 4가 6으로 자동 변하지 않는다.

풀이 보기

자동화 의존

추천을 그대로 따르는 사람이 많으면 자동화가 더 정확해진 것일까?

준비 개념과 학습 목표

준비 개념

  • 분류와 정답

  • 비율과 분모

  • 확인과 수정

학습 목표

  • 추천 수용률과 정확도를 구별한다.

  • 확인 권한·시간·대안을 설계한다.

도움과 대신 판단의 경계

자동화는 사람의 수고를 줄일 수 있지만 출력을 늘 그대로 받아들이면 오류 발견 기회를 잃을 수 있다. 이 단원에서 자동화 의존은 맥락 확인 없이 출력을 신뢰하는 행동을 살펴보는 말이다. 특정 실험의 보편적인 발생률을 주장하지 않는다.

사람을 검토 목록에 넣는 것만으로 실질적인 확인이 보장되지 않는다. 자료를 볼 수 있는지·시간이 있는지·다른 판정을 고를 수 있는지·이의 제기가 처리되는지까지 봐야 한다. 형식적인 버튼과 수정 가능한 절차는 다르다.

서로 다른 숫자 세기

추천 수용률은 추천을 그대로 따른 비율이고 정확도는 정답과 일치한 비율이다. 사용자가 잘못된 추천도 따르면 수용률이 올라도 정확도는 오르지 않을 수 있다. 둘의 분자와 분모를 표에 적는다.

모형 정확도와 사람이 수정한 최종 정확도도 구별한다. 실제 도움 효과를 판단하려면 동일 조건의 비교 설계가 필요하다. 아래 네 건의 가상 표는 비율의 차이를 배우는 예시이지 현실의 사용자 성능 실험이 아니다.

확인할 수 있는 절차

모형의 범위·불확실성·원자료를 확인하고 잘못된 출력을 거절하거나 수정할 수 있는 대안을 둔다. 특히 실패가 큰 피해를 주는 분야는 그 분야의 검토 규칙과 현장 검증이 필요하며 장난감 정확도만으로 배포를 결정하지 않는다.

거절 버튼은 사용 가능해야 하고 후속 작업의 담당 경로도 명확해야 한다. 수동 대안도 언제나 옳다는 뜻은 아니다. 자동화와 사람 판단의 각 오류를 기록하고 실제 관측 없이 향상 효과를 약속하지 않는다.

중간 과정을 따라가는 예제

가상 4건의 정답은 [A,B,A,B], 모형 출력은 [A,A,A,B]다. 처음 사람은 4건 모두 따른다. 다음 가상 검토에서는 2번의 원자료를 확인해 B로 교정하고 나머지는 유지한다. 세 비율을 계산하라.

  1. 처음 추천 수용률은 4/4=100%, 모형 정확도는 3/4=75%, 처음 최종 정확도는 75%다.

  2. 다음 검토는 2번만 거절하므로 추천 수용률은 3/4=75%다.

  3. 교정 후 최종 출력 [A,B,A,B]는 정답과 4/4=100% 일치하며 모형 자체 출력과 정확도는 바뀌지 않는다.

이 자체 표에서는 수용률 100→75%, 최종 정확도 75→100%, 모형 정확도 75% 유지다. 실제 사용자 개선 효과의 관측이 아니다.

힌트 보기

최종 출력 [A,A,A,A]를 정답과 대조하고 바꾼 건수를 센다.

풀이 보기

사람이 마지막에 눌렀으면 자동화 오류가 모두 해결된다.

잘못된 4번 교정에서 최종 정확도는 50%다. 사람의 실제 확인 근거와 대안, 오류 추적이 필요하다.

사용자의 선택권

추천 끄기를 눌렀는데 계속 바뀐다면 선택한 것일까?

준비 개념과 학습 목표

준비 개념

  • 상태와 사건

  • 설정과 결과

  • 데이터와 학습

학습 목표

  • 실제 동작하는 제어와 표시를 연결한다.

  • 끄기·수정·초기화의 범위를 구별한다.

선택할 대상과 결과

사용자의 선택권은 기능을 이해하고 필요에 맞게 받아들이거나 바꾸고 그만둘 수 있는 설계를 생각하는 관점이다. 추천 끄기·기록 수집 끄기·기존 기록 삭제는 대상이 다르다. 한 버튼으로 모든 것이 변했다고 설명하면 오해를 만든다.

선택 결과가 언제 어디에 반영되는지 알려준다. 즉시 화면 필터가 바뀌는 것과 다음 모형 학습에 피드백이 반영되는 것은 다른 시간선이다. 실제로 없는 즉시 학습 효과를 약속하지 않는다.

대안이 동작해야 한다

끄기 선택 뒤에도 추천에 따라 필수 화면이 계속 변하면 표시와 동작이 불일치한다. 자체 수동 정렬로 돌아가고 현재 모드를 보여주는 방법을 설계할 수 있다. 다시 켜기와 이전 선택 수정도 사람의 변화한 필요에 연결된다.

모든 서비스에 동일한 법적 선택권이 적용된다는 주장을 하지 않는다. 이 단원은 자체 제품 설계 권고와 상태 검사 활동이다. 개인정보/계약상의 법적 요건을 정하려면 관할과 처리 행위를 별도로 확인해야 한다.

세 상태의 독립성

아래 모형에서 R은 추천 표시, L은 새 행동 로그 수집, P는 기존 개인화 자료 집합이다. 추천 끄기는 R만 바꾸고, 로그 끄기는 L만 바꾸며, 초기화는 P만 빈 집합으로 만든다고 자체 계약을 정한다. 실제 개인정보 서비스를 변경하는 활동이 아니다.

기능 범위를 표시하면 선택의 효과를 검사할 수 있다. P 초기화를 서버 백업까지 모두 삭제한다고 부르면 모형 범위를 벗어난다. 실제 자료 삭제/보존 정책과 기능 설정은 별도로 설명하고 관측해야 한다.

중간 과정을 따라가는 예제

자체 초기 상태 (R,L,P)=(1,1,{a,b})에서 추천 끄기→로그 끄기→개인화 초기화→추천 켜기 순서의 상태를 적어라. L=0에서 새 행동 c는 수집하지 않는다고 정의한다.

  1. 추천 끄기 뒤 (0,1,{a,b}), 로그 끄기 뒤 (0,0,{a,b})다.

  2. 초기화 뒤 (0,0,∅), 추천 켜기 뒤 (1,0,∅)다. 각 명령은 한 항목만 바꾼다.

  3. 이후 행동 c는 L=0이므로 P에 추가되지 않는다. 추천 켜기도 로그 수집을 자동으로 켜지 않는다.

최종 상태는 (1,0,∅)이며 새 행동 수집은 없다. 이 모형은 실제 서버의 자료 삭제나 백업 처리를 뜻하지 않는다.

(0,1,{a,b,c})다. 추천 끄기만으로 로그와 자료도 지워졌다고 말하면 틀리다. R=0에서 추천 정렬을 계속하면 자체 추천 끄기 계약 위반이다.

오해와 반례

추천을 끄면 과거 자료와 백업까지 모두 삭제된다.

추천 끄기 뒤 P는 {a,b} 그대로다. 과거 자료 초기화도 자체 P 범위이며 실제 백업 삭제와 동일하다고 단정하지 않는다.
