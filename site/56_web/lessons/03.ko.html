소단원 3.1

cascade·box model

나중에 쓴 CSS가 항상 이기고 width가 보이는 전체 폭일까?

준비 개념과 학습 목표

준비 개념

  • CSS 선언은 property:value이며 selector는 적용할 요소를 고른다. p는 문단 요소, .card는 class 이름 card, #notice는 id 이름 notice를 고른다. selector가 맞지 않으면 그 선언은 경쟁에 들어오지 않는다.

  • origin은 스타일의 출처로 브라우저 기본(UA), 사용자가 정한 스타일(user), 문서 작성자(author)를 구별한다. 여기서 author는 웹 문서 작성자이며 HTTP origin과는 다른 뜻이다. !important는 중요 선언 표시다.

  • 박스는 content, 안쪽 padding, border, 바깥 margin으로 나눈다. 이 소단원의 폭 계산은 수평 비대체 block, 확정 px 폭, 여백 자동값 없음·min/max 추가 제약 없음이며 모든 수는 CSS px다.

학습 목표

  • 출처·중요도·layer를 먼저 보고 같은 단계에서 specificity와 source order를 비교한다.

  • content-box와 border-box의 전체 폭·내용 폭을 가정에 맞게 계산한다.

주소가 다른 파일에서 온 CSS라서 이기는 걸까, 다른 우선순위 단계라서 이기는 걸까?

경기 규칙을 비교할 때 점수보다 먼저 참가 자격을 확인하듯, CSS도 적용 후보를 고르고 우선순위 단계를 차례로 읽는다. 여기서 스타일 출처는 UA·user·author이며 웹 주소의 HTTP origin과 구별한다. 서로 다른 서버 파일이라는 사실만으로 스타일의 author/user 순위를 정하지 않는다.

이 활동은 기본 원고와 같은 제한 문맥이다. shadow DOM·inline style·전환·애니메이션·특수 selector 없이 같은 요소의 같은 property를 비교한다. @layer foundation,paint; 두 layer를 정하고 각 후보의 적용 여부, 중요도, layer, selector, 순서를 카드로 펼친다. 박스 계산은 확정 px의 비대체 block에 수평 여백 자동값과 추가 min/max 제약이 없다고 가정한다.

먼저 확인할 개념
  • 웹 주소의 origin

    HTTP 출처와 스타일의 출처라는 같은 단어가 가리키는 모델을 구별한다.

  • 구조와 표현

    HTML의 의미 관계와 CSS 표현 선택을 서로 다른 판단으로 둔다.

경쟁하는 선언을 단계별로 고른다

cascade는 같은 요소의 같은 property에 적용 가능한 선언들에서 우선값을 고르는 과정이다. 이 단원은 같은 문서 문맥, shadow DOM 없음·애니메이션/전환 없음·inline style 없음인 모형이다. 일반 선언은 author가 user보다, user가 UA보다 우선한다. 중요 선언은 UA가 user보다, user가 author보다 우선하여 사용자의 중요한 설정을 보호한다. 전환·애니메이션이 있는 전체 규칙을 이 축약으로 대체하지 않는다.

같은 origin과 중요도에서 layer 순서를 비교한다. @layer base,theme;로 정한 일반 선언은 뒤의 theme가 앞 base보다 우선하고, layer 밖의 일반 선언은 layer 안보다 우선한다. 중요 선언에서는 layer 순서가 반대이며 layer 안의 중요 선언은 layer 밖의 중요 선언보다 우선한다. 따라서 앞 layer의 #notice라는 강한 selector라도 뒤 layer의 .card 일반 선언을 이기지 못한다.

@layer base, theme;
@layer base { #notice { color: red; } }
@layer theme {
  .card { color: navy; }
  .card { color: green; }
}
.card { box-sizing: content-box; width: 200px; padding: 10px; border: 2px solid; margin: 5px; }

specificity는 앞 단계가 같은 후보를 비교한다

같은 origin·중요도·layer에서 이 단원의 단순 selector specificity는 (id 수,class 수,요소 수)를 왼쪽부터 비교한다. #notice는 (1,0,0), .card는 (0,1,0), p는 (0,0,1)이다. 숫자를 십진수로 합산하지 않는다. specificity까지 같으면 뒤 source order 선언이 우선한다. 특수 selector :where(), :is() 같은 추가 규칙은 이 예제의 범위 밖이다.

부모의 상속은 해당 요소에 직접 적용되는 선언 경쟁과 별개다. color처럼 상속되는 값은 직접 정할 값이 없을 때 부모에서 오며, 부모 id가 강하다는 이유로 자식의 직접 color 선언을 밀어내지 않는다. 잘못된 선언·거짓 media 조건은 후보에서 제외된다. 적용·우선순위·상속을 한 줄로 뭉개지 않는다.

박스의 폭에 무엇이 들어가는지 정한다

content-box에서 width=200px,padding 좌우 10px,border 좌우 2px이면 content 폭은 200, border 바깥까지의 폭은 200+20+4=224 다. margin 좌우 5px까지 포함한 가로 점유 폭은 234 다. 이 계산은 margin 상쇄나 배치 알고리즘의 크기 조정이 없는 위 가정에서만 쓴다.

border-box에서 같은 width=200px는 padding과 border를 포함하므로 content 폭은 200−20−4=176, margin 포함 점유는 210 이다. 내용 폭은 음수로 만들지 않고 최소 0 이므로 padding+border가 지정 width보다 크면 실제 border box가 지정값보다 커질 수 있다. box-sizing은 margin을 width 안으로 넣거나 긴 내용을 자동 줄바꿈하는 설정이 아니다.

조건을 바꾸어 비교하기

부모의 강한 selector를 자식에 옮기지 않는다

부모 #container에 color:red가 직접 지정됐다. 자식 p에는 color:blue가 직접 지정됐다. 같은 제한 문맥에서 자식 색을 설명하라.

  1. 부모의 red와 자식의 blue는 같은 요소를 대상으로 경쟁하는 두 선언이 아니다.

  2. 자식에 직접 지정할 color가 있으므로 부모 상속으로 이를 덮지 않는다.

  3. 자식의 blue와 부모의 red를 따로 적는다.

자식은 blue다.

심화: 이 제한 문맥의 선언마다 (origin·importance 우선순위, layer 우선순위, specificity의 세 성분, source order)라는 사전식 비교 키를 부여하면, 먼저 다른 성분에서 승자가 결정될 때 뒤 성분은 결론을 바꾸지 않는다. 이것이 높은 specificity로 모든 경쟁을 해결할 수 없는 이유다. 일반/중요 layer의 순위 방향을 각각 다르게 정해야 한다. 전체 CSS에는 전환·애니메이션·encapsulation·element-attached style 등 추가 단계가 있으므로 이 키만으로 모든 브라우저 cascade를 구현했다고 하지 않는다. 폭 식 W_content=max(0,W_requested−P−B)에서는 P+B≤W_requested일 때만 border-box의 실제 폭이 요청값과 같으며, 그 밖에는 P+B가 최소 공간을 정한다.

소단원 3.2

flex·grid

한 줄의 공간 분배와 여러 줄의 정렬을 같은 규칙으로 다룰 수 있을까?

준비 개념과 학습 목표

준비 개념

  • container는 배치를 결정하는 부모 박스, item은 그 배치에 직접 참여하는 자식 박스다. flex/grid는 모든 깊이의 자손을 한꺼번에 item으로 만드는 속성이 아니다.

  • inline 축은 글이 진행하는 축, block 축은 줄이 쌓이는 축이다. 여기서는 writing-mode:horizontal-tb,direction:ltr를 가정하여 inline은 왼쪽→오른쪽, block은 위→아래다. 세로쓰기·RTL에서는 이 대응을 바꿔야 한다.

  • gap은 item 또는 track 사이의 간격이다. 확정된 container content 폭에서 gap·고정 크기를 빼고 남은 공간을 계산한다. 예제 item에는 margin/padding/border가 없고 최소크기 0·최대 제한 없음인 단순 모형을 쓴다.

학습 목표

  • flex의 main/cross 축과 basis·grow·shrink를 명시하여 분배를 계산한다.

  • grid track과 gap을 포함한 fr 분배를 계산하고 시각 순서의 접근성 한계를 설명한다.

카드가 세 장일 때 간격도 세 번 빼야 할까?

책 세 권을 한 줄에 놓고 책 사이 공간을 세어 보자. 양 끝 여백이 없다면 사이 공간은 두 개다. 배치 문제에서는 container의 내용 폭, item의 시작 크기, gap의 개수를 먼저 구별해야 한다. 아래는 실제 CSS 엔진 실험이 아닌 한 줄의 공간 분배 모형이다.

수평 LTR·확정 폭·줄바꿈 없음·margin/padding/border 없음, item 최소 0·최대 제한 없음이라는 조건을 유지한다. 세 카드의 flex-basis는 각각 100px, grow는 1:2:1, shrink는 모두 1이다. grid 비교에서는 고정 120px 열과 최소 0인 1fr·2fr 열을 사용한다. 내용의 고유 최소 크기 때문에 동결되는 실제 상황에는 이 단순 공식을 그대로 적용하지 않는다.

  • 논리 순서와 기능

    시각적 순서가 읽기·키보드 순서와 자동으로 같아지지 않는 경계를 기억한다.

flex는 main 축의 item을 배분한다

display:flex와 flex-direction:row이면 main 축은 inline 축이고 cross 축은 그에 수직이다. column이면 main은 block 축이 된다. justify-content는 main 축, align-items는 cross 축의 정렬을 다룬다. row가 항상 물리적 수평 왼쪽부터라는 일반화는 쓰기 방향과 row-reverse를 빠뜨린다.

flex-basis는 분배를 시작할 주축의 기본 크기이고 grow는 양의 여유를 나눌 비율이다. 확정 폭 600 에서 두 basis100/200, gap20 이면 여유 280 이다. grow1/1 이면 각각 140 씩 받아 240/340 이 된다. basis·최소/최대·auto margin·줄바꿈 때문에 실제 알고리즘은 더 복잡하므로 이 숫자는 위의 제한 조건에서 계산한 것이다.

.row { display: flex; flex-direction: row; width: 600px; gap: 20px; }
.row > .a { flex: 1 1 100px; min-width: 0; }
.row > .b { flex: 1 1 200px; min-width: 0; }
.grid { display: grid; width: 600px; gap: 20px; grid-template-columns: minmax(0, 1fr) minmax(0, 2fr); }

축소와 줄바꿈은 별도 조건이다

여유가 음수이면 shrink factor와 기본 크기의 곱으로 축소 비율을 잡는다. 폭 240,gap0,basis100/200,shrink1/1 이면 부족 60 을 100:200 으로 나누어 20/40 만큼 줄이고 80/160 이 된다. grow의 1:1 과 shrink의 1:2 를 혼동하지 않는다. min-width:auto의 내용 기반 최소나 max 크기가 활성화되면 일부 item을 동결하고 다시 분배하므로 같은 단순 비율을 쓸 수 없다.

flex-wrap:wrap은 공간에 따라 여러 flex line을 만든다. 각 줄의 여유 분배는 독립적이므로 서로 다른 줄의 열이 자동으로 정렬되지 않는다. 긴 단어의 item이 줄어야 하면 min-inline-size:0 을 검토하고, 내용도 overflow-wrap 같은 정책이 필요하다. item 상자만 줄인다고 텍스트의 의미 있는 줄바꿈까지 보장하지 않는다.

grid는 track의 두 축을 함께 정한다

display:grid는 행·열의 track과 배치 칸을 정한다. 두 열 minmax(0,1fr) minmax(0,2fr),gap20,content폭 600 이라면 gap을 뺀 580 을 비율 1:2 로 나눈다. 열은 580/3 과 1160/3 이다. 1fr은 언제나 container의 1/3 이라는 단위가 아니라 고정 track·gap과 최소크기 제약을 반영한 남은 공간의 몫이다. 작은 0~1 미만 fr 비율이나 확정되지 않은 축에서는 추가 규칙이 있으므로 여기서 모든 grid를 해결하지 않는다.

grid는 track끼리 줄을 맞추는 작업에 유리하고 flex는 한 축의 내용 흐름에 유리하다. 둘을 중첩할 수 있다. order·명시적인 grid 위치·reverse로 화면 순서를 바꾸어도 일반 DOM 읽기와 키보드 순서는 자동으로 같은 순서가 되지 않는다. 문서의 의미 있는 원래 순서를 먼저 정하고 시각 재배치가 과제 수행을 혼란스럽게 하지 않는지 실제 접근성 점검을 별도로 한다.

화면크기와 typography

화면을 확대하거나 글자 간격을 늘려도 같은 내용을 읽고 조작할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • viewport는 문서를 배치하는 현재 표시 영역이다. CSS px는 배치의 기준 단위이며 장치의 물리 픽셀 하나와 언제나 같지 않다. width media query는 기기 이름이 아니라 현재 viewport 폭을 조건으로 삼는다.

  • em은 문맥의 글자 크기, rem은 루트 요소의 글자 크기를 기준으로 한 길이 단위다. font-size의 em은 부모의 크기에 의존한다. 아래 예제의 루트 크기는 16 CSS px라는 계산용 가정이다. 실제 사용자의 기본값을 고정했다고 주장하지 않는다.

  • line-height:1.5 같은 단위 없는 수는 해당 요소 글자 크기의 배수다. ch는 폰트의 0 문자 폭에 기초한 단위이므로 60ch가 한국어 60 글자나 정확한 줄 길이 60 문자를 보장하지 않는다.

학습 목표

  • viewport·글자 크기·줄 높이·breakpoint를 가정에 따라 계산한다.

  • 텍스트 확대·reflow·사용자 간격 변경을 실제 시험과 구별하여 설계한다.

두 열을 유지할 숫자가 계산돼도, 글을 읽기 편하다는 결론이 바로 나올까?

서랍에 물건 두 개가 들어간다는 계산과 사람이 쉽게 꺼낸다는 경험은 다르다. 반응형 배치도 열 폭의 기하 조건과 내용 읽기·기능 수행 조건을 따로 점검한다. 이 활동은 CSS px의 제한된 계산과 실제 점검 계획을 나눈다.

가용 폭 V, 좌우 padding 각각 P, 두 열 사이 gap G, 각 열의 설계 최소 m을 정하면 V≥2P+2m+G가 필요하다. m은 자체 설계 기준이고 폰트·한국어·긴 주소·사용자 확대를 시험한 최적값이 아니다. margin0·border없음·최소 0인 확정 균등 grid 모형으로 계산하고, 다른 제약과 실제 환경은 따로 관찰한다.

반응형 조건은 가용 공간을 본다

@media (min-width:640px)는 viewport 폭이 640 CSS px 이상일 때 적용된다. 정확히 640 도 포함한다. 넓은 창에서 두 열, 좁은 창에서 한 열로 바꾸는 이유는 기기의 제품명이 아니라 내용을 담을 공간이다. 같은 노트북도 창 크기나 확대율에 따라 다른 조건을 만족할 수 있다.

확대하면 많은 브라우저에서 같은 물리적 표시 영역이 더 적은 CSS px의 viewport로 보인다. 단순한 이론 모형에서 시작폭 1280 을 400%로 확대하면 320 상당의 폭이다. 실제 scroll bar·브라우저 UI·확대 모드의 관찰은 별도다. 모바일에서 device-width에 맞추는 viewport meta를 쓰되 user-scalable=no 등으로 사용자의 확대를 막는 설계는 피한다.

<meta name="viewport" content="width=device-width, initial-scale=1">
<style>
  body { margin: 0; }
  .page { padding: 1rem; }
  .cards { display: grid; gap: 16px; grid-template-columns: minmax(0, 1fr); }
  .cards > * { min-inline-size: 0; overflow-wrap: anywhere; }
  .reading { font-size: 1rem; line-height: 1.5; max-inline-size: 60ch; }
  @media (min-width: 640px) {
    .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); }
  }
</style>

폰트의 값과 내용 흐름을 함께 정한다

본문 font-size:1rem,line-height:1.5 라면 가정한 루트 16px에서 글자 16px와 줄 높이 24px다. 단위 없는 line-height가 자식으로 상속되면 자식 자신의 글자 크기에 배수가 적용된다. 고정된 작은 박스 높이와 overflow:hidden을 함께 쓰면 글자 확대나 줄 증가 때 내용이 잘릴 수 있다. 적절한 줄바꿈과 자동 높이가 필요한 이유다.

max-inline-size:60ch 같은 읽기 폭 제한은 폰트에 따른 상대 기준이며 모든 언어의 최적 값이라고 선언하지 않는다. 한국어·긴 주소·다국어 문장과 사용자 설정을 확인한다. overflow-wrap:anywhere는 긴 연속 문자열의 박스 넘침을 줄일 수 있지만 원문의 의미·링크 식별·키보드 초점이 유지되는지 실제 확인해야 한다. flex/grid item의 최소 폭 제약도 함께 검토한다.

접근성 수치는 시험 요구와 구별한다

WCAG2.2 의 텍스트 크기 변경 설명은 자막·텍스트 이미지 예외를 제외하여 200% 확대에도 내용과 기능을 잃지 않게 하는 기준을 다룬다. Reflow는 보통 세로로 읽는 콘텐츠를 320 CSS px 폭 상당에서 두 방향 스크롤 없이 제공하는 조건이고, 의미상 두 차원 배치가 필요한 지도·표 등 일부 예외가 있다. “반응형 코드 한 줄”이나 휴대폰 그림만으로 적합성 검증이 끝난 것은 아니다.

Text Spacing의 설명은 사용자가 줄 높이 1.5 배, 문단 뒤 간격 2 배, 글자 간격 0.12 배, 단어 간격 0.16 배를 설정해도 내용·기능 손실이 없는지 다룬다. 작성자가 이 값을 항상 기본값으로 지정하라는 조건과 다르며, 특정 문자체계에 해당하지 않는 간격 속성의 예외도 있다. 이번 원고는 이 요구와 종이 계산만 설명하며 실제 확대·키보드·스크린리더·학습자 시험은 미수행이다.

  4. 루트 글자 크기가 20px이면 page 내용 폭 600px, 열 폭 292px, 카드 내용 폭 264px이다. media 640px 조건은 그대로 충족한다.
