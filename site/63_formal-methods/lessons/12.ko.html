소단원 12.1

명세·증명·반례 비교

안전하다는 결론 옆에는 어떤 근거를 붙여야 할까요?

준비 개념과 학습 목표

준비 개념

  • 정수 범위와 조건 분기

  • 불변식의 초기 성립과 보존

  • 반례 경로

학습 목표

  • 명세를 검사 가능한 성질로 적는다.

  • 불변식 증명과 반례가 지지하는 결론을 구별한다.

  • 한계가 있는 조사 결과를 전체 증명으로 확대하지 않는다.

자체 카운터의 약속을 먼저 적기

자체 모형의 카운터 n은0에서 시작합니다. 외부 입력은 증가 inc 또는 감소 dec입니다. 증가 요청에서 n<2이면1을 더하고, 아니면 유지합니다. 감소 요청에서 n>0이면1을 빼고, 아니면 유지합니다. 명령 한 번을 원자적인 한 단계로 처리하며 동시에 실행하는 작업은 없습니다. 숫자는 오버플로 없는 정수입니다. 조사할 명세 P는 모든 명령 완료 경계에서0≤n≤2입니다.

명세는 무엇을 요구하는지, 모형은 무엇이 일어날 수 있는지를 적습니다. 카운터 범위라는 안전 요구와 요청이 언젠가 받아들여진다는 활성 요구는 다릅니다. n=2에서 증가를 영원히 거절해도 범위 요구는 지킵니다. 이 단원은 요청 수락의 공정성이나 전체 서비스의 응답 시간까지 증명하지 않습니다.

모든 단계를 잇는 증명의 구조

처음 n=0이므로 P가 성립합니다. P인 정수 n에서 증가가 허용되면 n은0 또는1이고 다음 값은1 또는2입니다. 증가가 거절되면 값은 그대로입니다. 감소가 허용되면 n은1 또는2이고 다음 값은0 또는1이며, 거절되면 그대로입니다. 어느 허용 입력에서도 다음 P가 성립하여 임의의 유한 명령 횟수에 대해 P를 보존합니다.

이것은 정한 전이의 수학적 손 증명입니다. 증명기를 실행하여 확인한 결과로 적지 않습니다. 구현이 같은 전이를 수행한다는 연결은 별도입니다. 끝나면 어떤 결과가 성립한다는 부분 정확성과 반드시 끝난다는 종료 보장도 구별합니다. 여기서는 각 명령 전이가 정의되어 있을 때의 경계 범위만 다룹니다.

실패 실행과 조사 한계도 근거로 남기기

증가 조건을 n≤2로 바꾸면 n=2에서도3으로 증가합니다. 초기0에서 inc 세 번으로0→1→2→3이 되어 P를 위반합니다. 반례에는 입력 순서, 각 단계의 조건값, 마지막 위반을 적습니다. 이 실행 하나만으로 모든 실행 경계가 안전하다는 주장을 반박할 수 있지만 모든 요청에서 실패한다고 결론내리지는 않습니다.

변경 모형을 명령 두 번까지만 조사하면 최대값2라 오류가 없습니다. 그러나 세 번째에 반례가 있어 두 번 조사 결과를 전체 안전 증명으로 읽으면 틀립니다. 수정판의 전체 보존 증명, 변경판의 실제 손 반례, 두 단계 조사에서의 무오류는 서로 다른 근거입니다. 보고서에서는 방법과 범위를 결론 바로 옆에 붙입니다.

중간 과정을 따라가는 예제

수정판 카운터에서 inc,inc,inc,dec,dec,dec 입력을 손 추적하고 범위 보존의 각 경우를 확인하라.

  1. 처음0에서 증가 두 번은1,2가 된다. 세 번째 증가 조건2<2는 거짓이라2에 머문다.

  2. 감소 두 번은1,0이 된다. 세 번째 감소 조건0>0은 거짓이라0에 머문다.

  3. 상태열0,1,2,2,1,0,0의 모든 값이0..2다. 이 한 경로 확인과 모든 경우의 보존 증명을 별도 근거로 구별한다.

여섯 입력의 경계 상태는 모두 범위 안이다. 전체 모형의 안전 근거는 앞 절의 초기값과 네 가지 허용/거절 경우에 대한 보존 증명이다.

종이와 본문으로 직접 해보기

초기값을2로 바꾸어 n≤2 변경판에 증가 한 번을 주어라. 수정판과 결과를 비교하라.

힌트 보기

초기값2 자체는 P를 만족한다. 차이는 증가 조건의 등호다.

풀이 보기

변경판은2≤2가 참이라3이 되어 한 단계 반례다. 수정판은2<2가 거짓이라2에 머문다. 반례 길이는 초기 조건도 함께 명시해야 비교할 수 있다.

오해와 반례

한 가지 정상 경로를 보여 주면 모든 실행의 안전 증명이 끝난다.

예제 경로는 그 입력 순서의 결과만 보여 줍니다. 변경판도 두 번 증가까지 정상입니다. 전체 결론에는 모든 허용 전이의 보존 또는 충분한 도달성 조사 같은 근거가 필요합니다.

자기점검

명세 P에 요청 수락의 시간 제한이 포함되는가?

답과 이유 보기

포함되지 않는다.

P는 완료 경계의 정수 범위만 요구한다.

n≤2 변경판 초기0의 가장 짧은 범위 위반 입력은?

답과 이유 보기

inc 세 번이다.

두 단계 안에는 한 단계 최대 증가1로 값3에 이를 수 없다.

반례 하나를 찾으면 모든 실행이 실패하는가?

답과 이유 보기

아니다. 보편 안전 주장이 거짓임을 보인다.

실패하지 않는 감소나 유지 경로도 가능하다.

한 단계 더

감소 조건을 n≥0으로 바꾼 별도 변경판을 조사하세요. 초기0에서 dec 한 번으로−1이 됩니다. 상한 조건만 고쳤다는 사실을 하한까지 확인했다는 결론으로 확대하지 마세요.

소단원 12.2

모델·코드 추적

종이에서 증명한 n과 프로그램 변수는 정말 같은 상태를 뜻할까요?

준비 개념과 학습 목표

준비 개념

  • 상태 전이와 조건식

  • 변수의 읽기와 대입

  • 수정판과 변경판 비교

학습 목표

  • 명세·전이·구현 위치의 대응을 기록한다.

  • 각 명령 경계의 상태를 비교한다.

  • 원자성 가정이 달라지는 동시 실행 반례를 설명한다.

대응표를 문장으로 만들기

자체 구현 설명용 의사코드는 inc 요청이면 n<2일 때 n←n+1, dec 요청이면 n>0일 때 n←n−1입니다. 다른 입력은 이 모형에서 허용하지 않습니다. 의사코드는 특정 언어의 컴파일 가능한 파일이 아니며 실행 결과를 제시하지 않습니다. 추적표에는 초기화 n←0, 증가 조건, 증가 대입, 감소 조건, 감소 대입을 각각 모형의 규칙과 대응시킵니다.

추상 상태 n과 구현 변수 n이 같은 값을 나타내는 것이 이 작은 모형의 대응 관계입니다. 구현의 한 명령 처리가 끝나면 그 값이 모형의 한 전이 결과와 같아야 합니다. 구현이 n≤2를 쓰면 조건 대응이 깨져2→3을 허용합니다. 변수 이름이 같다는 것만으로 의미가 같은 구현이라고 판단하지 않습니다.

중간 명령과 완료 경계 구별하기

모형 한 단계가 구현에서 조건 읽기와 대입의 여러 단계에 해당할 수 있습니다. 단일 작업이며 그 사이에 다른 변경이 없다는 조건 아래에서 명령 시작과 끝의 값은 전이와 대응합니다. 프로그램 위치까지 세밀하게 모델링하면 조건 검사 직전·직후와 대입 직후 상태를 나눌 수 있습니다. 경계 값만 비교한 기록을 모든 중간 동작의 시간·예외까지 검사한 기록으로 확대하지 않습니다.

자체 n=1 증가 추적은 읽기1, 조건1<2 참, 대입2, 명령 완료2입니다. 감소는 읽기2, 조건2>0 참, 대입1, 완료1입니다. 같은 입력과 시작값으로 모형과 의사코드를 나란히 추적합니다. 차이를 발견하면 어느 조건이나 대입에서 달라졌는지 기록하고, 구현 수정 후 같은 비교를 다시 해야 합니다.

동시에 움직이면 모형의 가정을 다시 정하기

두 작업이 공유 n의 조건을 먼저 읽고 나중에 각각 현재 n을 증가시킨다고 가정해 보세요. 처음1에서 A와B가 모두 n<2를 참으로 읽습니다. A가 증가해2, B가 이미 승인된 조건을 믿고 현재2를 증가해3이 될 수 있습니다. 비교와 증가가 한 원자 동작이 아니라는 가정의 자체 인터리빙 반례입니다. 특정 언어나 하드웨어에서 실제 실행한 관찰 결과는 아닙니다.

이 동시 모형을 순차 모형의 증명으로 덮을 수 없습니다. 조건 검사와 갱신을 묶는 동기화, 원자 연산이나 재검사 규칙 등을 구현에 맞게 정의하고 전이를 다시 조사해야 합니다. 정한 동시 의미에서 오래된 값으로 덮어쓰는 경우에는 다른 결과가 생길 수도 있으므로 반례에 읽기·쓰기 규칙을 명시합니다. 단순히 잠금을 언급했다고 수정 구현의 안전성이 확인된 것도 아닙니다.

중간 과정을 따라가는 예제

수정판 모형과 의사코드에 시작1, 입력 inc,inc,dec를 주고 각 완료 경계를 대응시켜라.

  1. 첫 inc에서1<2 참이라2가 된다. 모형 전이와 의사코드 완료값 모두2다.

  2. 둘째 inc에서2<2 거짓이라2를 유지한다. 셋째 dec에서2>0 참이라1이 된다.

  3. 대응 경계열1→2→2→1이다. 둘째 조건만≤로 바꾸면1→2→3→2로 바뀌어 같은 입력에도 대응이 깨진다.

수정판의 세 경계값은2,2,1이다. 변경판의 둘째 완료값3은 범위 명세와 수정판 모형에 모두 어긋난다.

종이와 본문으로 직접 해보기

두 작업의 조건 읽기가 시작1에서 모두 참이고, 각 갱신은 그 순간의 현재 n에1을 더하는 규칙이다. A조건,B조건,A갱신,B갱신 순서를 손 추적하라.

힌트 보기

B갱신에서 조건을 새로 검사하지 않는다. 갱신 값은 오래된 읽기1이 아니라 현재값이다.

풀이 보기

A/B조건은 모두1<2 참이다. A갱신은 현재1을2로 바꾼다. B갱신은 현재2를3으로 바꾼다. 범위 위반은 조건 판단과 갱신이 분리되어 다른 갱신이 끼어든 경우다. 이 네 사건의 허용 의미를 정한 가상 반례다.

오해와 반례

변수 이름과 함수 이름이 같으면 증명한 모형과 구현도 같다.

n<2와 n≤2는 같은 n 이름을 써도 다른 전이를 허용합니다. 상태 표현·초기화·조건·갱신과 실행 사이의 대응 근거가 필요합니다.

소단원 12.3

미검증 경계와 도구가정

완료라고 쓴 보고서에서 무엇이 아직 확인되지 않았는지 찾을 수 있을까요?

준비 개념과 학습 목표

준비 개념

  • 모형과 구현의 대응

  • 한정 조사와 보존 증명

  • 가정의 만족 가능성

학습 목표

  • 수행한 근거와 수행하지 않은 검사를 나누어 기록한다.

  • 가정·진입점·한계와 결과를 함께 읽는다.

  • 버전 변경 뒤 검토 근거의 유효 범위를 판단한다.

결과보다 먼저 대상과 성질 적기

이 단원의 자체 보고서는 대상=수정판 카운터 전이, 초기값=0, 입력=inc/dec, 성질=완료 경계0≤n≤2, 의미=수학적 정수와 순차 원자 명령이라고 적습니다. 근거=초기/전이 보존 손 증명과 예제 손 추적입니다. 도구 실행·컴파일·실장치·학습자 시험은 미수행입니다. 이 조건과 근거를 숨긴 채 시스템 전체 검증 완료라고 쓰지 않습니다.

실제 프로젝트에서는 코드·모형·명세의 정확한 버전, 분석 진입점, 환경 가정, 도구/설정, 조사 한계, 결과와 로그를 함께 남깁니다. 파일 해시를 쓴다면 실제 파일에서 계산하여 저장한 값이어야 합니다. 여기서는 실제 구현 파일을 검사하지 않아 가상의 실행 로그나 해시를 만들어 성공 증거로 제시하지 않습니다.

가정이 실행을 없앴는지 확인하기

입력이나 초기값을 제한하는 가정은 허용 실행을 줄입니다. 초기 n=0과 추가 n=1을 동시에 요구하면 시작 상태가 없습니다. 그런 조건에서 오류가 발견되지 않았다는 결과는 실제 초기0 카운터가 안전하다는 새 증거가 아닙니다. 가정은 서로 만족 가능하고 대상 환경의 요구와 연결되어야 합니다.

분석 도구를 쓴다면 실제 검사한 성질·함수 진입점·환경 함수의 모델·루프 제한·완료 상태를 기록합니다. 제한 안의 반례 없음, 충분한 펼침 조건까지 확인한 결과, 시간 제한으로 미완료라는 상태를 구별합니다. 도구를 실행하지 않았다면 버전이나 성공 메시지를 추정해서 채우지 않고, 필요한 추가 검사로 남깁니다.

수정 뒤에는 근거의 연결도 갱신하기

수정판 n<2의 보존 근거는 n≤2 변경판에 그대로 적용되지 않습니다. 명세 파일만 그대로여도 구현 전이가 달라졌기 때문입니다. 정확한 버전에서 검토한 근거와 현재 파일의 대응을 다시 확인해야 합니다. 문서에 체크 표시가 남아 있다고 현재 구현을 독립 검토한 기록이 되는 것은 아닙니다.

미검증 경계에는 동시 실행, 기계 정수 표현, 외부 입력 해석, 실패/예외 처리, 컴파일된 실행과 장치 연결을 필요에 따라 적습니다. 모든 항목이 이번 명세에 필수라는 뜻은 아닙니다. 무엇을 결론으로 주장하려는지에 맞춰 추가 의무를 정합니다. 완료를 방해하는 모형 내부 오류와 조사하지 않은 다른 성질을 구분하면 다음 확인 작업을 구체적으로 정할 수 있습니다.

중간 과정을 따라가는 예제

보고서 문장「두 번 조사에서 오류가 없었으므로 모든 카운터 코드가 안전하다」를 이 단원의 실제 수행 범위에 맞게 고쳐라.

  1. 대상은 전체 코드가 아니라 명시한 전이 모형이고 조사 횟수는 명령 두 단계임을 적는다.

  2. n≤2 변경 모형도 두 단계까지 오류가 없지만 세 inc에서3에 이르므로 전체 안전 결론을 제거한다.

  3. 수정판에는 별도의 초기/보존 손 증명이 있음을 적고 도구·코드 실행은 하지 않았다는 상태를 함께 기록한다.

「변경 전이 모형은 초기0에서 두 명령까지 손 조사해 범위 위반을 찾지 못했다. 세 inc의0→1→2→3 반례가 있어 전체 안전하지 않다. 수정판은 순차 정수 모형의 범위 보존을 손 증명했으며 실제 코드/도구/장비는 미검증이다」가 근거와 일치한다.

종이와 본문으로 직접 해보기

수정판의 n<2 증명을 검토한 기록이 있는데 현재 의사코드는 n≤2로 바뀌었다. 재검토할 대응과 최소 반례를 적어라.

힌트 보기

초기값0과 성질0≤n≤2는 같아도 증가 조건이 달라졌다.

풀이 보기

증가 조건과 전이의 대응을 다시 확인한다. 초기0에서 inc 세 번으로3이 되어 범위를 위반한다. 기존 증명은 원래 전이에는 유효하지만 현재 조건의 증거로 재사용할 수 없다. 현재 의사코드와 모형을 고치거나 실제 요구 명세를 재검토해야 한다.

오해와 반례

반례 없음이라고 적혔으면 환경 가정이나 실행 제한은 읽을 필요가 없다.

초기0과1을 동시에 요구한 모순 가정은 조사할 실행을 없애고, 두 단계 제한은 세 단계 오류를 보지 못합니다. 결과는 대상·가정·한계·완료 상태와 함께 해석해야 합니다.

자기점검

초기0과 추가 n=1 조건을 동시에 만족할 수 있는가?

없다.
