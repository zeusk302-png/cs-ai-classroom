소단원 8.1

타입규칙

실행하면 숫자가 나오는 식은 모두 같은 타입인가?

준비 개념과 학습 목표

준비 개념

  • 자연수와 참·거짓

  • 조건문

  • 전제와 결론

학습 목표

  • 타입 판단의 전제와 결론을 읽는다

  • 작은 식의 타입 유도 나무를 만든다

  • 실행 결과와 정적 허용 규칙을 구분한다

실행해서 값이 나오는 식과 정적으로 허용하는 식의 집합은 같은가요?

앞 본문의 닫힌 Nat/Bool 언어를 그대로 사용합니다. 숫자 n은 succ를 n번 붙인 0의 약기입니다. pred 0은 0이며 pred의 인수와 succ의 인수는 Nat, iszero의 인수는 Nat이고 결과는 Bool입니다. if는 Bool 조건과 같은 타입인 두 분기를 요구합니다. 모든 실행은 이 규칙에 따른 종이 추적입니다.

새 식 E는 if iszero(pred 0) then pred 2 else succ(pred 3)입니다. 조건은 Bool이며 두 분기는 Nat이므로 E의 타입은 Nat입니다. 조건 안의 pred 0, iszero 0, if 선택, pred 2의 순서로 네 번 줄여 1에 도달합니다. 선택하지 않은 분기를 먼저 계산하는 규칙은 없습니다.

새 식 D는 if true then iszero 0 else pred false입니다. else 분기에서 pred의 요구 타입이 깨져 D는 정적으로 거절됩니다. 실행 규칙만 적용하면 D→iszero 0→true입니다. 마지막 값이 Bool이라는 사실에서 D의 Bool 타입을 거꾸로 복원할 수 없습니다. 타입 보존은 이미 타입이 있는 식에서 앞으로 진행하는 명제입니다.

먼저 확인할 개념
  • 조건과 분기의 타입

    같은 단원에서 정한 Nat/Bool 규칙을 사용합니다.

  • 타입 보존의 전제

    타입이 없는 출발식에는 보존 정리를 적용하지 않습니다.

작은 언어의 약속

설명을 위해 숫자와 참·거짓만 있는 닫힌 식을 쓴다. Nat은 0,1,2,…의 자연수 타입, Bool은 true와 false의 타입이다. 숫자 n은 succ를 n번 붙인 0의 줄임말이다. succ는 하나 증가, pred는 하나 감소하되 pred 0은 0, iszero는 0인지 검사한다. 변수·함수·메모리·외부 입력은 이 모형에 없다.

t : T는 식 t에 타입 T를 줄 수 있다는 판단이다. 0 : Nat, true : Bool, false : Bool은 시작 규칙이다. t : Nat이면 succ t : Nat, pred t : Nat, iszero t : Bool이다. 예를 들어 iszero (pred 2)는 안쪽부터 Nat, Nat, Bool로 판단한다.

조건식의 세 전제

if c then a else b는 c : Bool이고 a : T, b : T로 두 가지의 타입이 같을 때 전체 타입 T를 가진다. 전제를 위에, 결론을 아래에 적는 유도 나무는 규칙을 적용한 근거를 보인다. 타입 이름을 추측해서 붙이는 일이 아니다.

자체 예시 if iszero (pred 2) then succ 0 else pred 3은 조건 Bool, 두 가지 Nat이라 Nat이다. if true then 0 else false는 이 규칙으로 허용되지 않는다. 실행에서는 0을 고를 수 있지만 가지 타입 Nat과 Bool이 같지 않기 때문이다.

숫자 이름이 같아 보여도

succ true에는 true : Nat이라는 전제가 필요하지만 시작 규칙은 true : Bool만 준다. 이 모형은 참을 자동으로 1로 바꾸지 않는다. 실제 언어의 변환 규칙은 별도 정의이므로 Python이나 C 문법으로 이 표를 대체하면 안 된다.

거부된 식이 모두 실제 실행에서 막힌다는 역방향 주장도 하지 않는다. 타입 규칙은 실행 전에 적용하는 허용 기준이다. 이 단원은 종이에 유도를 작성하며 Rocq나 컴파일러의 검사 결과를 보고하지 않는다.

타입을 안쪽부터 쌓기

E의 타입과 네 중간 식을 적으세요.

  1. pred 0은 Nat, 그 iszero는 Bool입니다. pred 2와 succ(pred 3)은 각각 Nat입니다.

  2. E→if iszero 0 then pred 2 else succ(pred 3)→if true then pred 2 else succ(pred 3)→pred 2→1입니다.

모든 중간 식은 Nat이며 종료 값은 1입니다.

비교할 점

숫자 2에서 1로 바뀌어도 타입 Nat은 같습니다.

거절과 막힘의 차이

D와 pred false의 실행을 각각 확인하세요.

  1. D의 else 분기는 타입을 얻지 못합니다.

  2. D는 true 분기만 골라 iszero 0을 거쳐 true가 됩니다. pred false는 인수가 값 false라 더 줄일 수 없고 숫자 규칙도 적용되지 않습니다.

둘 다 타입 거절이지만 D는 값으로 끝나고 pred false는 stuck입니다.

비교할 점

정적 거절은 반드시 실제 막힘을 뜻하지 않습니다.

종이와 본문으로 직접 해보기

위 식의 else를 false로 바꾸면 어느 전제가 실패하는가? 별도로 iszero (succ 0)의 타입을 유도하라.

힌트 보기

if 규칙은 조건뿐 아니라 두 가지의 같은 타입도 요구한다.

풀이 보기

then은 Nat, else는 Bool이므로 같은 T 전제가 실패한다. iszero (succ 0)는 0 : Nat→succ 0 : Nat→Bool이다.

오해와 반례

선택되지 않을 가지는 타입 검사에서 항상 무시한다.

progress·preservation

한 번 계산이 가능하다는 사실로 끝까지 안전하다고 말할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 앞 소단원의 Nat·Bool 규칙

  • 한 단계 계산

학습 목표

  • progress와 preservation을 연결한다

  • 안전성과 종료의 서로 다른 주장을 설명한다

타입 안전성을 유지한 실행 규칙도 기능을 바꿀 수 있나요?

새 언어 M은 타입 규칙과 값 정의를 유지하면서 실행 규칙 iszero 0→true 한 개를 iszero 0→false로 교체합니다. 기존 규칙을 남겨 두고 추가하는 경우와 구별합니다. 두 Bool 값 사이를 바꾸므로 이 변경 자체는 타입 보존을 깨지 않습니다.

진행 증명의 iszero 경우를 살펴봅니다. Nat 인수가 다음 단계로 줄어들면 문맥 규칙을 적용합니다. 인수가 숫자 값이면 0 또는 succ 숫자이며 각각 false로 줄어듭니다. 따라서 이 변경 아래에서도 이 경우는 진행합니다. 다른 규칙은 같으므로 원래 증명의 나머지 경우를 유지할 수 있습니다. 그러나 영 판정이라는 기능은 틀립니다.

별개 언어 N은 실행을 원래대로 두고 iszero의 결과 타입만 Nat으로 잘못 바꿉니다. N에서 iszero 0은 Nat으로 도출되지만 다음 true는 Bool이어서 보존이 실패합니다. pred(iszero 0)도 Nat으로 허용한 뒤 pred true에 도달하여 막힙니다. 새 규칙의 도입에는 정리를 다시 검토해야 합니다.

먼저 확인할 개념
  • 진행과 보존

    값 또는 다음 단계와 한 단계의 타입 유지를 따로 확인합니다.

  • iszero의 입출력 타입

    Nat 인수와 Bool 결과를 구별합니다.

정상 종료와 막힘을 분리

이 작은 언어의 값은 true, false와 자연수 표현이다. t → t′는 정해진 계산 규칙 한 번이다. if true는 then, if false는 else를 고르고, 그 전에 조건을 계산한다. pred 0→0, pred (succ v)→v는 숫자 값 v에 적용한다. iszero 0→true, iszero (succ v)→false도 같다. 안쪽이 한 단계 변하면 바깥 pred·succ·iszero에도 그 변화를 전달한다.

값이면 더 계산하지 않아도 정상 결과다. 값이 아닌데 적용 가능한 단계도 없는 식을 stuck이라고 한다. succ true는 숫자 값도 Bool 값도 아니고 true를 증가시키는 규칙도 없어 stuck이다. 단계가 없다는 사실 하나로 정상 결과와 실패를 혼동하지 않는다.

두 정리가 맡는 역할

progress는 잘 타입 붙은 닫힌 식이 값이거나 한 단계 진행할 수 있다는 성질이다. preservation은 잘 타입 붙은 식이 한 단계 변하면 같은 타입을 유지한다는 성질이다. 첫 성질은 현재 막히지 않음을, 둘째는 다음 식에도 첫 성질의 전제를 전달함을 말한다.

자체 예시 iszero (pred 1)은 Bool이다. iszero 0으로 한 단계 변하고 true로 다시 변한다. 세 식 모두 Bool이다. 처음과 중간은 단계가 있고 마지막은 값이다. 각 단계에서 두 역할을 따로 적으면 안전성이 이어지는 이유를 확인할 수 있다.

정리의 조건과 증명 범위

두 정리를 결합하면 이 모형에서 잘 타입 붙은 식이 유한 번의 계산 뒤 stuck에 도달하지 않는다. 이는 언어의 모든 잘 타입 붙은 식에 대한 증명 주제이며, 예제 몇 개를 계산하는 것만으로 전체 정리를 증명한 것은 아니다. 일반 증명에서는 타입 유도에 대한 귀납과 Nat·Bool 값의 형태를 사용한다.

progress 자체는 반드시 최종 값에 도착한다는 종료 정리가 아니다. 반복·재귀가 있는 다른 언어는 매 단계 가능해도 무한히 계산할 수 있다. 이 작은 모형 밖의 언어에 안전성·종료·메모리 보장을 적용하려면 그 언어의 규칙과 해당 정리를 별도로 확인해야 한다.

같은 Nat 입출력 계약 안에서 어떤 수치 요구를 추가해야 하나요?

이제 작은 식 언어 밖의 별도 교육용 순수 함수 모형을 사용합니다. 모든 값은 무한정밀 Nat입니다. 가격 p의 단위는 원/개, 수량 q의 단위는 개, 결과 금액의 단위는 원입니다. 타입 Nat만으로 이 단위 차이를 구별하지 않는 모형입니다. 계약 R은 결과가 p×q와 같다는 것입니다. 함수 F(p,q)=p×q와 G(p,q)=p+q는 모두 Nat×Nat→Nat이지만 기능 계약은 다릅니다. G는 서로 다른 단위의 숫자를 잘못 더한 구현입니다.

입력 (3,4)에서 F는 12원이고 G는 7원입니다. (2,2)에서는 둘 다 4원이어서 한 시험의 일치가 결함을 숨깁니다. Nat 전역에서 pq=p+q는 (p−1)(q−1)=1로 바꿀 수 있으며 가능한 쌍은 (0,0)과 (2,2)입니다. 음수 중간식은 수학적 정수에서 풀고 최종 입력은 Nat으로 제한합니다.

별도 할인 함수의 계약은 금액 a가 1200원 이상일 때 200원 할인, 그보다 작으면 그대로 반환하는 것입니다. 구현 H는 a>1200이면 a−200을, 아니면 a를 반환합니다. H도 Nat→Nat이며 종료하지만 1200원에서 요구 결과 1000원 대신 1200원을 반환합니다. 타입 안전성·종료와 기능 사후조건을 따로 확인합니다.

무슨 약속을 확인하는가

타입안전성은 정의한 언어와 타입 규칙의 관계에 대한 성질이다. 기능정확성은 특정 프로그램이 특정 요구를 만족하는지 묻는다. 앞의 작은 언어와 달리 여기서는 자연수 두 입력과 덧셈·곱셈을 가진 별도의 교육 함수 모형을 사용한다. Nat 두 개를 받아 Nat을 내는 형태만으로 총액 요구까지 표현되지는 않는다.

가격 p와 수량 q의 상품 소계 요구를 p×q로 정하자. F(p,q)=p+q와 G(p,q)=p×q는 모두 자연수를 반환한다. p=7,q=3에서 F는10,G는21이다. F가 숫자 형태를 지켜도 요구에는 실패하는 직접 반례다. 이는 실제 주문 시스템의 관찰이 아닌 가상 모형 계산이다.

전제와 결과를 명세로 쓰기

기능 명세에는 허용 입력과 기대 관계를 적는다. 여기서는 p,q가 자연수이고 결과 r=p×q라는 요구이다. 유한 사례를 손 계산해 반례를 발견할 수 있지만 모든 자연수에서 맞다는 결론은 더 일반적인 논증이 필요하다. G가 요구를 만족하는 이유는 정의 자체가 같은 곱셈이기 때문이며, 컴파일러 검사나 시험 통과 사실을 대신하지 않는다.

명령형 프로그램은 상태에 대한 전제 P와 결과 Q를 쓰는 Hoare 논리로 논증할 수도 있다. 부분정확성은 P에서 시작해 종료한 경우 Q를 보장한다. 종료까지 보장하려면 별도 근거가 필요하다. 타입, 요구 관계, 종료는 각기 무엇을 주장하는지 적어야 한다.

현실의 경계를 더하기

무료배송 규칙을 소계1000 이상으로 정한 다른 가상 사례에서 소계700과 배송비300을 합친1000으로 비교하면 잘못 무료 처리할 수 있다. 두 수가 모두 정수라는 사실은 비교 기준을 바꾸지 않는다. 소계1000은 경계 포함으로 무료이며, 입력·비교·출력의 의미를 명세에 연결해야 한다.

실제 언어의 유한 정수 범위, 외부 시스템 실패, 시간, 보안, 사용자 표시도 필요하면 별도 조건으로 넣는다. 종이 검산은 해당 수학 모형의 증거다. 학생·기기·서비스 실험이나 완전한 Rocq 증명을 수행하지 않았으므로 그 상태를 미수행으로 남긴다.

  2. G는 0+5=5원입니다. 두 결과 모두 Nat입니다.

타입에 맞아도 G는 기능 요구를 위반합니다.

비교할 점

0원 자체가 항상 오류인 것은 아닙니다.

경계 조건의 한 점

H를 1199,1200,1201원에서 비교하세요.

  1. 1199원은 두 조건 모두 할인하지 않습니다.

  2. 1200원은 ≥ 조건만 할인합니다.

  3. 1201원은 두 조건 모두 할인합니다.

가운데 1200원에서만 결과가 200원 차이 납니다.

비교할 점

경계 옆의 성공 두 번은 경계의 성공을 대체하지 않습니다.

종이와 본문으로 직접 해보기

p=0,q=5와 p=4,q=1에서 요구·F·G를 적어라. 배송 요구는 소계≥1000일 때 무료다. 소계999와1000의 무료 여부도 적어라.

힌트 보기

요구와 실제 후보 계산을 별도 칸에 쓴다. ≥는 경계를 포함한다.

풀이 보기

(0,5)는 요구0,F5,G0; (4,1)은 요구4,F5,G4다. 소계999는 무료 아님,1000은 무료다.

오해와 반례

타입안전성 증명은 모든 사용자 요구의 정확성 증명이다.

안전성 정리가 다루는 언어 성질과 특정 입력·출력 요구는 다르다. F의 Nat 결과10은 타입 형태를 지켜도 요구21과 다르다. 필요한 기능 명세를 별도로 검증한다.

힌트 2

힌트 1

힌트 2

  2. 요구 결과는 1000원이고 H의 결과는 1200원입니다.

연습 3 · 직접 만들어 보기

G를 기능 계약에 맞게 고치고, 할인 H도 조건만 교정하세요.

힌트 2

연산과 비교 관계를 확인합니다.

풀이와 답 확인

  2. H의 조건을 a≥1200으로 바꿉니다. 참일 때 a−200은 a≥1200으로 Nat입니다.

곱셈과 ≥ 경계를 복구하는 계획입니다. 실제 코드 수정·시험 결과는 아닙니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

F와 G의 값이 같은 Nat 입력 쌍을 모두 찾으세요.

힌트 1

힌트 2

풀이와 답 확인

흔한 오답에서 다시 생각하기

Nat에는 0이 포함되어 (0,0)을 따로 유지해야 합니다.

한 단계 더

F가 우연히 요구와 같은 양의 자연수 쌍은 p+q=pq를 만족한다. (p−1)(q−1)=1이므로 양의 정수에서는 (2,2)뿐이다. 0을 허용하면 (0,0)도 일치한다. 이 계산으로 일치 사례를 많이 반복하는 시험보다 명세를 기준으로 다른 입력을 고르는 이유를 설명해 보자.

힌트 2

N은 타입만 바꾸고 실행 규칙은 원래대로 둡니다.

힌트 3

풀이와 답 확인

  1. 고친 E는 두 분기가 Nat입니다. 원래 언어에서는 조건 두 단계·선택 한 단계·pred 2 한 단계로 총 네 단계 뒤 1입니다. M에서는 같은 앞 세 단계 뒤 pred 5를 골라 총 네 단계 뒤 4입니다.

  2. N에서 iszero 0을 Nat으로 잘못 도출하므로 succ 전체도 Nat입니다. 한 단계 뒤 succ true가 되고 값도 다음 단계도 없어 막힙니다.

  4. 1200원의 요구 할인 결과는 1000원이며 H는 1200원을 반환합니다.

동일 타입의 다른 값, 잘못된 도출에서 도달한 stuck, 기능 사후조건의 두 반례를 구별합니다.
