소단원 4.1

작은 명령형 언어

프로그램을 종이 위에서 따라가기 위해 꼭 필요한 규칙은 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 자연수는 여기서 0,1,2,…다. 변수 이름과 그 이름에 저장한 수는 다른 대상이다.

  • 함수 σ는 이름마다 현재 값을 돌려준다. σ[X↦v]는 X만 바꾼 새로운 상태다.

  • :=는 값을 저장하는 명령이고, =는 두 값을 비교하는 식이다.

학습 목표

  • 문법으로 허용되는 프로그램과 의미로 정하는 효과를 구별한다.

  • 순서와 상태를 보존하며 짧은 명령을 추적한다.

언어를 작게 정의하기

이 단원의 자체 언어에는 수, 변수, 덧셈·곱셈·뺄셈으로 만든 산술식 a와 참·거짓, 수 비교, 부정·논리곱으로 만든 조건 b가 있다. 명령 C는 skip, X:=a, (C₁;C₂), if b then C₁ else C₂, while b do C다. 괄호는 문법 나무를 명확히 하며 ;는 왼쪽 명령을 끝낸 다음 오른쪽 명령을 시작하라는 뜻이다.

모든 변수는 전역 자연수이고 언급하지 않은 이름의 초기값은 0이다. 자연수 뺄셈은 max(0,u−v)로 정의한다. 2−5는 0이며 정수 −3이나 컴퓨터 unsigned의 되감기 값이 아니다. 나눗셈·입출력·예외·병렬 실행은 이 언어에 넣지 않았으므로 해당 기능에 관한 결론을 여기서 일반화하지 않는다.

식과 명령의 차이

산술식의 값 ⟦a⟧σ는 현재 상태를 읽어서 계산한다. ⟦X+3⟧σ=σ(X)+3이고 조건 ⟦X>0⟧σ는 참 또는 거짓이다. 식에는 저장 효과가 없어서 같은 상태에서 같은 식을 다시 계산하면 같은 값을 얻는다. 식 평가 자체는 유한한 문법 나무의 재귀 계산이다.

반면 X:=a는 먼저 이전 상태에서 a를 전부 평가하여 v를 얻고 그 다음 σ[X↦v]를 만든다. X:=X+1은 수학 등식 X=X+1을 요구하는 모순이 아니다. 읽은 옛 X에 1을 더해 새로운 X를 저장하는 상태 변화다. skip은 아무 값도 바꾸지 않는 완료 가능한 명령이다.

분기와 반복을 따라가기

if는 현재 상태에서 조건을 한 번 평가해 참 가지 또는 거짓 가지 중 하나만 실행한다. while은 매번 현재 상태로 조건을 다시 검사한다. 참이면 몸체를 마치고 다시 검사하며, 거짓이면 끝난다. 몸체가 상태를 바꾸면 다음 조건의 값도 달라질 수 있다.

문법에 맞는 명령이 모두 끝나는 것은 아니다. while true do skip은 반복 조건이 변하지 않는다. 하지만 X>0 동안 X를 1씩 줄이는 몸체는 자연수 X가 0에 도달한다. 문법 검사, 계산 규칙, 종료 근거를 각각 적어야 한다. 실제 프로그래밍 언어의 메모리 범위나 최적화 시간은 이 종이 모형의 범위 밖이다.

중간 과정을 따라가는 예제

초기 상태 X=2,Y=7에서 C=(X:=X+3;Y:=2*X)를 추적하고 두 명령의 순서를 바꾼 D와 비교하라.

  1. 처음 X+3을 초기 상태에서 읽으면 2+3=5다. 첫 저장 뒤 X=5,Y=7이다.

  2. 두 번째 식 2*X는 갱신된 상태를 읽어 2*5=10이다. C의 최종 상태는 X=5,Y=10이다.

  3. D=(Y:=2*X;X:=X+3)에서는 처음 Y가 2*2=4가 된다. 다음 저장으로 X=5가 된다.

  4. D의 최종 상태 X=5,Y=4는 C와 다르다. 표현식의 모양이 같아도 읽는 시점이 달라졌다.

C는 (5,10), D는 (5,4)다. 상태 쌍의 순서는 (X,Y)이며 나머지 변수는 그대로다.

종이와 본문으로 직접 해보기

X=2,Y=5에서 X:=Y;Y:=X로 두 값을 교환할 수 있는가? 임시 변수 T를 사용한 교환도 종이에 작성하라.

힌트 보기

두 번째 명령이 읽는 X는 첫 저장 뒤의 값이다. T에는 최초 X를 먼저 저장한다.

풀이 보기

직접 두 저장을 하면 첫 단계 (X,Y)=(5,5), 두 번째도 (5,5)로 교환에 실패한다. T:=X;X:=Y;Y:=T라면 T=2, X=5, Y=2가 되어 (5,2)로 교환된다. T의 초기값은 첫 저장이 덮어쓰므로 결과에 영향 없다.

오해와 반례

명령의 나열 순서는 결과에 영향을 주지 않는다.

예제에서 X를 먼저 바꾸면 Y=10, Y를 먼저 바꾸면 Y=4다. 두 명령이 서로의 읽는 값이나 쓰는 이름에 영향을 주는지 확인하지 않고 순서를 바꿀 수 없다.

자기점검

자체 언어에서 2−5의 값은?

답과 이유 보기

0.

자연수 뺄셈을 max(0,2−5)로 정의했다. 정수 계산과 다르다.

X:=X+1의 오른쪽 X는 새 값인가?

답과 이유 보기

저장 전 값이다.

식 평가 뒤에 상태 갱신을 적용하므로 새 값으로 자기 자신을 평가하지 않는다.

문법에 맞으면 반드시 종료하는가?

답과 이유 보기

아니다.

while true do skip은 문법에 맞지만 거짓 조건에 도달하지 않는다.

한 단계 더

독립 변수 갱신의 교환을 증명해 보자. X≠Y이고 a는 Y를 읽지 않으며 b는 X를 읽지 않는 순수 식이라면 X:=a;Y:=b와 Y:=b;X:=a는 같은 최종 상태를 만든다. 첫 갱신이 둘째 식의 읽는 값을 바꾸지 않으며 서로 다른 이름의 갱신은 교환되기 때문이다. a가 X 자신을 읽거나 b가 Y 자신을 읽어도 이 조건에는 문제가 없다. 다만 외부 입출력이나 별칭을 추가한 언어에는 이 증명을 그대로 적용할 수 없다.

소단원 4.2

big·small step

끝난 결과만 기록하는 것과 매 순간의 남은 명령을 기록하는 것은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • 앞 소단원의 자연수 상태와 순수 식 평가를 사용한다.

  • 〈C,σ〉는 남은 명령과 현재 상태를 함께 기록한 구성이다.

  • 유도 규칙은 전제가 맞을 때 결론 관계를 인정하는 방법이다.

학습 목표

  • 큰 단계의 완료 관계와 작은 단계의 전이를 구별한다.

  • 별도 정의한 단계 규칙으로 유한 추적과 무한 순환을 계산한다.

완료를 보여주는 큰 단계

〈C,σ〉⇓σ′는 C가 σ에서 끝나 σ′가 되었다는 관계다. skip은 σ 그대로, 저장은 σ[X↦⟦a⟧σ]다. 순차 C₁;C₂의 유도에는 중간 상태 τ가 필요하다. C₁이 σ에서 τ로 끝나고 C₂가 τ에서 σ′로 끝났을 때 전체가 σ′로 끝난다.

if는 조건에 맞는 가지의 유도를 사용한다. while에서 조건이 거짓이면 σ로 완료된다. 참이면 몸체가 τ로 끝났다는 유도와 같은 while이 τ에서 σ′로 끝났다는 유도를 연결한다. 이 관계의 증명 나무는 유한해야 한다. 무한 반복은 끝난 상태를 갖는 유한 증명 나무가 없다.

한 단계를 별도로 정하기

여기서는 계산 수를 쉽게 추적하기 위해 순수 식을 한꺼번에 계산하는 자체 작은 단계 →를 정의한다. 저장은 한 단계에 skip과 갱신 상태가 된다. C₁이 한 단계 움직이면 C₁;C₂의 왼쪽만 같은 단계로 움직이고, skip;C₂는 한 단계에 C₂가 된다. skip 단독에는 다음 단계가 없다.

if는 현재 조건값에 맞는 가지로 한 단계에 바뀐다. W=while b do C는 한 단계에 if b then (C;W) else skip으로 펼쳐진다. 이 규칙들은 Software Foundations의 명령 구조를 참고했지만 원문의 식 내부 축약 단계는 생략한 별도 모형이다. 아래 단계 수는 이 모형의 수이며 공식 Rocq 추적이나 CPU 명령 수가 아니다.

종료와 계속 움직임 구별

〈C,σ〉→*〈skip,σ′〉는 0회 이상의 유한 전이 후 끝났다는 뜻이다. C가 처음부터 skip이면 0회다. 큰 단계와 작은 단계는 완료 결과를 연결하지만 큰 단계 하나가 작은 단계 하나라는 뜻은 아니다. if와 while 전개, 순차 정리도 작은 전이에 포함된다.

while true do skip을 W라고 하면 W→if true then (skip;W) else skip→skip;W→W가 된다. 상태는 변하지 않아도 남은 명령은 계속 전이하여 끝나지 않는다. 실제 언어에 오류를 추가하면 움직이지 못한 비정상 명령도 생길 수 있으므로 다음 전이가 없다는 사실만으로 정상 종료라고 할 수 없다. 여기서는 최종 명령이 skip인지 확인한다.

중간 과정을 따라가는 예제

X=2,Y=0에서 (X:=X+1;Y:=X*2)의 자체 작은 단계 전체와 큰 단계 중간 상태를 구하라.

  1. 첫 전이: (skip;Y:=X*2), 상태 X=3,Y=0. 왼쪽 저장만 수행했다.

  2. 둘째 전이: Y:=X*2, 상태 X=3,Y=0. skip을 버리는 규칙만 적용했다.

  3. 셋째 전이: skip, 상태 X=3,Y=6. 오른쪽 저장을 수행했다.

  4. 큰 단계는 첫 저장 ⇓(3,0), 다음 저장 ⇓(3,6)을 순차 규칙으로 연결해 전체 ⇓(3,6)이다. 작은 단계 수는 3이다.

큰 단계 완료 상태는 (3,6), 자체 작은 단계는 3회다. 상태가 바뀌지 않는 둘째 전이도 한 단계다.

종이와 본문으로 직접 해보기

W=while X>0 do X:=X−1을 X=1에서 skip까지 추적하라. X=2에서는 전이가 몇 회인지 설명하라.

힌트 보기

참 한 번에는 전개, 분기 선택, 몸체 저장, skip;W 정리가 필요하다. 마지막 거짓 검사에도 전개와 선택이 필요하다.

풀이 보기

X=1이면 W→if…→(X:=X−1;W)→(skip;W,X=0)→(W,X=0)→if…→skip으로 6회다. X=2는 참 순환 4회를 두 번 하고 마지막 거짓 2회를 더해 10회다. 일반 초기 X=m에서는 4m+2회이며 X=0에서도 2회다.

오해와 반례

상태가 안 바뀌는 전이는 실행 단계가 아니다.

skip;C→C와 while 전개는 상태를 유지하지만 남은 명령을 바꾼다. while true do skip은 모든 상태를 유지해도 무한히 움직인다. 진행은 저장 변화만으로 측정할 수 없다.

자기점검

skip의 정상 완료에 필요한 작은 단계는?

답과 이유 보기

0회.

→*는 0회도 허용하며 이미 끝난 구성이다.

큰 단계 ⇓의 유한 증명이 없으면 모든 언어에서 발산인가?

답과 이유 보기

일반적으로 아니다.

오류로 막힌 경우도 있을 수 있다. 이 단원의 총 식 평가 모형과 오류가 있는 확장을 구별한다.

X=0인 W의 전이 수는?

답과 이유 보기

2회.

while을 if로 펼친 다음 거짓 가지 skip을 선택한다.

한 단계 더

종료하는 프로그램에서 두 관계가 일치한다는 증명은 규칙을 맞춰 가며 진행한다. 큰 단계의 순차 유도라면 첫 유도의 작은 추적을 ;C₂ 안으로 옮긴 뒤 skip;C₂를 정리하고 둘째 추적을 붙인다. while 참 유도도 전개와 분기 선택 후 몸체 및 나머지 반복 추적을 붙인다. 역방향에서는 작은 단계 하나가 뒤의 큰 단계 완료를 앞 구성으로 보존한다는 보조명제를 규칙별로 증명하고 유한 추적 길이에 귀납한다. 이 설명은 자체 원자적 식 모형의 증명 개요이며 증명 도구 실행 완료를 주장하지 않는다.

소단원 4.3

실행과 의미의 관계

잠시 멈춘 실행과 영원히 끝나지 않는 실행을 어떻게 구별할까?

준비 개념과 학습 목표

준비 개념

  • 큰 단계 ⇓는 유한 완료 유도이며 →*는 유한 전이 추적이다.

  • 관찰 대상은 최종 상태, 종료 여부, 중간 추적 등 중에서 먼저 정한다.

  • 정해진 횟수만 따라가는 연료는 종료 증명과 다른 정보다.

학습 목표

  • 연료 소진과 발산을 구별한다.

  • 해석기의 구현이 의미 규칙을 보존한다는 주장에 필요한 범위를 설명한다.

규칙과 구현의 연결 계약

앞 소단원의 작은 단계 규칙은 다음 구성을 정하는 수학적 명세다. 해석기를 만들었다면 그 한 번의 처리 결과가 규칙에서 허용한 전이와 일치함을 명령별로 확인해야 한다. 순수 식 평가, 저장 시점, 순차 왼쪽 우선, 조건 선택, while 전개가 모두 검토 대상이다.

완료 결과의 건전성은 해석기가 Done(σ′)를 돌려주면 〈C,σ〉⇓σ′라는 뜻이다. 반대로 의미상 끝나는 모든 명령을 충분한 연료로 해석기가 끝낼 수 있다는 완전성도 별도 주장이다. 몇 예제의 일치는 모든 문법과 상태에 대한 증명을 대신하지 않는다. 이 단원에서는 해석기를 실제 구현·실행하지 않고 계약과 종이 추적만 살핀다.

연료를 써서 유한하게 관찰하기

자체 연료 해석은 먼저 남은 명령이 skip인지 검사해 Done을 반환한다. skip이 아니고 연료가 0이면 Timeout(현재 구성)을 반환한다. 그렇지 않으면 정확히 한 작은 전이를 진행하고 연료를 1 줄여 같은 검사로 돌아간다. 따라서 연료 n은 최대 n회 전이 예산이며 첫 검사나 최종 skip 확인을 별도로 차감하지 않는다.

Timeout은 현재 예산에서 끝을 보지 못했다는 뜻이다. 더 큰 예산으로 끝날 수도 있고 무한히 반복할 수도 있다. 반면 이전 소단원의 W→if→skip;W→W 순환처럼 상태를 포함한 동일 구성이 돌아오고 전이가 결정적이면 그 순환을 영원히 반복한다는 별도 근거가 된다. 유한 Timeout 하나만으로 순환이 있다는 것은 알 수 없다.

동등성은 관찰 범위를 따른다

모든 초기 상태에서 두 명령이 같은 완료 상태와 종료 여부를 보이면 이 단원의 최종 상태 관찰로는 동등하다고 할 수 있다. 중간 전이 수까지 관찰하면 더 세밀한 관계가 필요하다. 예를 들어 X:=1과 (X:=1;skip)은 같은 최종 상태지만 자체 작은 단계 수는 1과 2다.

최종 상태가 한 입력에서 같다는 것만으로 모든 입력 동등성이 증명되지는 않는다. X:=X+1과 X:=1은 초기 X=0에서는 같지만 X=2에서는 각각 3과 1이다. 출력·오류·메모리 접근·병렬 스케줄 같은 기능을 언어에 추가하면 관찰 계약도 넓혀야 한다. 실제 기기 속도나 외부 시스템 효과는 이 상태 모형에 포함되지 않는다.

중간 과정을 따라가는 예제

초기 X=2,Y=0에서 C=(X:=X+1;Y:=X*2)를 자체 연료 2와 3으로 관찰하라. skip과 while true do skip의 연료 0 결과도 구하라.

  1. 첫 전이 뒤 (skip;Y:=X*2), X=3,Y=0, 둘째 뒤 Y:=X*2, X=3,Y=0이다.

  2. 연료 2가 모두 소진되면 아직 명령이 저장이므로 Timeout이다. 완료 상태 (3,6)을 돌려주면 계약 위반이다.

  3. 연료 3이면 셋째 전이로 skip, X=3,Y=6이다. 마지막 검사에서 Done(3,6)이 된다.

  4. 처음부터 skip이면 연료 0에서도 Done(2,0)이다. while true do skip은 skip이 아니므로 연료 0에서 Timeout이지만 발산 근거는 별도로 3전이 순환이다.

C는 연료 2에서 Timeout, 3에서 Done(3,6). Timeout을 실패나 발산의 증명으로 바꾸지 않는다.

종이와 본문으로 직접 해보기

X:=1과 (X:=1;skip)을 임의의 초기 상태에서 추적하라. 연료 1과 2 결과를 비교하고 어떤 관찰에서 같은지 적어라.

힌트 보기

첫 명령은 저장 뒤 바로 skip이다. 둘째는 저장 뒤에도 skip;skip 정리가 남는다.

풀이 보기

X:=1은 한 전이로 Done이므로 연료 1에서도 끝난다. X:=1;skip은 첫 전이로 skip;skip이 되어 연료 1에서는 Timeout, 둘째 전이 뒤 skip이 되어 연료 2에서는 Done이다. 모든 초기 상태에서 최종 X=1이고 다른 이름은 보존되므로 최종 상태·종료 관찰은 같다. 전이 수와 연료 1의 관찰은 다르다.

오해와 반례

시간 제한에 걸린 프로그램은 반드시 무한 반복한다.

C의 연료 2 Timeout은 연료 3에서 종료한다는 명확한 반례다. 실제 시간 제한에는 자원 지연도 들어갈 수 있으므로 단순한 완료 미관측과 수학적 발산 증명을 혼동하지 않는다.

한 단계 더

명령 C와 skip;C의 최종 상태 동등성을 규칙으로 확인하자. 큰 단계 skip은 초기 상태 그대로이고 이후 C를 같은 상태에서 실행한다. 작은 단계에서는 skip;C가 한 번에 C가 된 뒤 완전히 같은 추적을 따른다. 따라서 C의 종료/발산을 보존하고 완료 상태도 같지만, 끝나는 C에 대해서는 전이 수가 1 늘어난다. 단계 수를 비용으로 쓰려면 이 차이도 계약에 넣어야 한다. 결정성과 총 식 평가 가정이 없어진 확장에서는 가능한 추적들의 집합을 비교하는 등 별도 정의가 필요하다.
