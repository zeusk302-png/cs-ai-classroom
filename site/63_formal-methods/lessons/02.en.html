Subtopic 2.1

Propositions, Predicates, and Quantification

Is saying that every request has a server able to handle it the same as saying that one server can handle every request?

Preparation and learning goals

Preparation

  • A set D is the allowed domain of a variable. The notation x∈D means that x is an element of that domain. The empty set ∅ has no elements; it differs from a one-element set such as {0}.
  • A proposition is a statement asserted in logic. A predicate P(x) is a property that becomes a statement once x is specified. A relation R(x,y) is a property of two inputs; here we also specify the domains of x and y separately.
  • P∧Q means both properties, and P∨Q means at least one. The claim P→Q uses evidence or an assumption of P to obtain Q. Read ¬P as saying that P leads to the contradiction False.

Learning goals

  • Specify the domains of free and quantified variables.
  • Check quantifier order and empty-domain truth values using a small table.
  • Distinguish classical truth evaluation from the evidence requirements of constructive logic.

Where do the variables of a specification range?

The statement “x can be handled” alone does not complete a sentence to check. We need the domain and current value of x and the meaning of handling. Let the request set be D={a,b}, the server set S={s₁,s₂}, and R(x,y) mean “server y can handle request x.” Assume only R(a,s₁) and R(b,s₂) are true and the other two table entries are false. This is an original table for practicing logical order, not a measurement of real servers.

The statement ∀x∈D P(x) requires P(x) for every allowed x, whereas ∃x∈D P(x) requires an allowed x and evidence for that property. Within a larger common domain, restricted quantification can be written ∀x(x∈D→P(x)) and ∃x(x∈D∧P(x)). Quantifying only x in P(x,y) leaves y free. Removing assumptions about the free y and reading the statement as a theorem for every y changes the specification.

Quantifier order changes how choices may depend on inputs

The statement ∀x∈D ∃y∈S R(x,y) allows choosing a server suitable for each request after that request is given. The statement ∃y∈S ∀x∈D R(x,y) requires the same server, chosen first, to handle every request. The first is true in the table above, while the second is false. If one server works for every x, it can also be used separately for each request, so the second implies the first. The table is a counterexample to the converse.

When D=∅, ∀x∈D P(x) is vacuously true because there is no violating element, while ∃x∈D P(x) is false because no witness can be supplied. However, ∃y∈S ∀x∈∅ R(x,y) is true when S is nonempty and false when S is also empty. Vacuous satisfaction of an elementwise specification differs from the existence of an actual request or server. If existence is required, state it with an existential proposition or a nonempty-domain assumption.

State the logical system and its evidence

The finite-table decisions in this unit use a classical interpretation with a supplied truth value for each entry. General classical logic permits the law of excluded middle P∨¬P and double-negation elimination ¬¬P→P. Constructive logic does not automatically add these principles for every arbitrary proposition. Evidence of P∧Q consists of evidence for each part; evidence of ∃x P(x) consists of a witness x and evidence of P(x); evidence of P→Q is a construction taking evidence of P to evidence of Q.

Constructively, P→¬¬P can still be proved: given hp:P and hnp:P→False, apply hnp(hp):False. In contrast, obtaining an arbitrary P from ¬¬P generally needs an additional principle, such as a classical one. Being able to decide a fully supplied finite table is not a theorem that every predicate can always be decided algorithmically. Any use of classical principles in a Lean example is identified separately; the small proof later in this unit does not use them.

A worked example, step by step

Let D={a,b}, S={s₁,s₂}, with only (a,s₁),(b,s₂) true in the relation table. Decide A=∀x∈D ∃y∈S R(x,y) and B=∃y∈S ∀x∈D R(x,y), then change only D to ∅ and decide again.

  1. For x=a choose y=s₁, and for x=b choose y=s₂. Each chosen entry is true, so A is true.
  2. The candidate y=s₁ fails at x=b, and y=s₂ fails at x=a. Every candidate fails, so B is false.
  3. If D=∅, A's outer universal quantifier has no x to check, so A is true.
  4. With D=∅ and S still nonempty, choose y=s₁. The inner universal statement is vacuously true, so B is true too.

Originally A is true and B is false. Emptying only the request domain makes both true. This is a specification change removing requests to check, not an observed improvement in server capability.

Try it with paper and the lesson

On paper draw D={a,b}, S={s₁}, and mark only R(a,s₁) true. Decide A and B, then change only S to ∅ and decide again. Finally compare the case D=S=∅.

Show hint

An existential statement needs an actual witness from its domain. Distinguish an empty outer universal domain from an empty outer existential domain.

Show solution

Initially no server handles b, so A is false; s₁ fails for b, so B is false too. Keeping D and making S=∅ makes every request's existential fail, hence A is false, and the outer existential fails, hence B is false. If D=S=∅, A is vacuously true, but B is false because there is no server witness.

Misconception and counterexample

∀x ∃y and ∃y ∀x are the same specification with renamed variables.

In the diagonal table where a different server can be chosen for each request, the first is true and the second false. Collision-free renaming of bound variables preserves meaning; exchanging the order of quantifiers generally does not.

Check your understanding

If ∀x∈∅ P(x) is true, does an element satisfying P exist?

Show answer and reasoning

No.

A universal statement holds vacuously because there is no violating element. Existence must be proved separately.

For each server in the original two-server table, what request refutes ∃y∀x?

Show answer and reasoning

b refutes s₁, and a refutes s₂.

Giving one failing request for each server excludes both possible candidates.

May ¬¬P→P for arbitrary P be silently added to the small constructive proof?

Show answer and reasoning

No.

General double-negation elimination requires stating the classical principle used or providing additional evidence that the proposition is decidable.

Explore further

Further proof: for every pair of domains D,S and relation R, constructively prove (∃y∈S ∀x∈D R(x,y))→(∀x∈D ∃y∈S R(x,y)). From evidence of the premise, obtain a witness y₀∈S and h:∀x∈D R(x,y₀). Given arbitrary x∈D, apply h to x to obtain R(x,y₀), and supply the same y₀ as the existential witness. Since x was arbitrary, the universal conclusion follows. The argument remains valid when D is empty. If S is empty, there is no evidence for the premise; do not interpret the proof as creating a real witness from a false premise. The diagonal table refutes the converse. Separately, ¬∃x∈D P(x)↔∀x∈D ¬P(x) is also constructive. Given evidence for the left side, arbitrary x, and hp:P(x), construct existential evidence (x,hp) to obtain a contradiction. Given evidence for the right side and existential evidence (x,hp), apply the corresponding ¬P(x) to hp to obtain a contradiction. Neither direction needs excluded middle.

Subtopic 2.2

Inductive Definitions

If two claims merely support each other, can both be accepted as true without any starting evidence?

Preparation and learning goals

Preparation

  • Induction on ℕ={0,1,2,…} proves a property of every finite natural number from the case 0 and the step from n to n+1. Observing a few cases differs from proving a general inductive step.
  • A rule obtains a conclusion from already established premises. A rule with no premises supplies starting evidence. A set is closed under rules if it contains a rule's conclusion whenever it contains all that rule's premises.
  • A finite evidence tree places a conclusion at its root and evidence for its immediate premises at its children. Leaves end with rules requiring no premises. Each rule considered here requires only finitely many premises at a time.

Learning goals

  • Distinguish generation rules from the least set closed under those rules.
  • Distinguish cyclic edges from actual finite derivation evidence.
  • Prove an invariant of reachable states by structural induction on evidence trees.

Least excludes unnecessary elements

Define an original state set X={p,q,r,z} and edges E={(p,q),(q,r),(r,r),(z,z)}. There are only two kinds of rule for the predicate Reach: seed gives Reach(p); step obtains Reach(y) from Reach(x) and (x,y)∈E. The state p is reachable by a path of length zero. Starting from p and following finitely many edges gives q and r. This is a paper model defining transition-system reachability.

The inductive Reach set R is the least set that contains p and is closed under following edges. The whole set X is also closed, but the least set is {p,q,r}. Permission to add elements by rules does not allow other elements to be included arbitrarily at the start. In this finite-premise rule model, leastness supports the statement that every element admitted by Reach was generated by an actual finite derivation.

A derivation differs from a cyclic picture

Evidence for r uses seed to obtain Reach(p), step to obtain Reach(q), then step again to obtain Reach(r): a tree of height two. Here a leaf has height zero and a parent has height one plus the maximum height of its children. Appending r→r makes longer evidence, but starting evidence already exists. In contrast, claiming Reach(z) from z→z alone requires Reach(z) again as a premise, with no terminating leaf. This is not a finite evidence tree.

Inductive and coinductive definitions adopt different evidence principles. This unit treats only the least closed set with finite generating evidence. It does not admit a claim of an infinite execution, observations of an infinite stream, or continually self-dependent cyclic evidence under the same principle. Reach(p) holds immediately, but “every execution eventually reaches r” is a liveness claim with different quantifiers and progress conditions.

Induction follows the structure of evidence

Prove that every Reach(x) has x∈G={p,q,r}. The seed conclusion p belongs to G. In the step case, apply the induction hypothesis to the smaller child evidence to obtain x∈G, and check that every edge starting in G—p→q, q→r, r→r—also ends in G. Hence y∈G. Since every evidence tree ends with one of the two rule kinds, structural induction covers every finite derivation.

An induction hypothesis applies only to immediately smaller evidence. Assuming Reach(z) itself to prove Reach(z) is not an induction hypothesis about smaller evidence. If a rule needs two recursive premises, each child supplies its own induction hypothesis. Structural induction on data lists or trees also considers each constructor, but distinguish induction on predicate evidence from induction on an input natural number by stating the object being inducted over.

A worked example, step by step

Use X,E from the main text and compute the Reach set from seed and step. Start at S₀=∅ and use Sₖ₊₁={p}∪Sₖ∪{y: (x,y)∈E for some x∈Sₖ}.

  1. Since S₀=∅, S₁={p}. The seed supplies the first element.
  2. The edge p→q from S₁ gives S₂={p,q}. At this stage r is not an immediate successor of a state in the previous S₁.
  3. Applying q→r from S₂ gives S₃={p,q,r}. The edge r→r from S₃ adds no new element.
  4. Since S₄=S₃, the set is closed. Every closed set must contain seed p and the two step conclusions q,r, so S₃ is least. The element z is not included.

The Reach set is {p,q,r}. The shortest path to r has two edges, while p needs zero. The self-edge at z supplies no initial evidence.

Try it with paper and the lesson

Add the single edge (r,z) and write S₁,… again from the same S₀. Which rule check for the original invariant G={p,q,r} now fails? Separately, if all seed rules are removed, what Reach set do the original edges alone generate?

Show hint

One iteration follows one edge only from elements of the previous set. Check destinations as well as starting states when checking closure.

Show solution

With the new edge, S₁={p}, S₂={p,q}, S₃={p,q,r}, S₄={p,q,r,z}, and S₅=S₄. Although r∈G, the destination of r→z is outside G, so preservation in the step case fails. In the separate model with all seeds removed, the least closed set is ∅. The empty set cannot start a step requiring a premise, and self-cycles alone generate no elements.

Misconception and counterexample

Any set closed under the rules is the inductively defined set.

The original X is closed but not least: z has no finite starting evidence. An inductive definition chooses the least closure. Without an additional axiom, the self-cycle at z cannot be accepted as a finite derivation.

Check your understanding

How many step applications are needed for the Reach evidence of p?

Show answer and reasoning

Zero.

The seed itself supplies starting evidence, and a path of length zero is allowed.

May r already be included in the original S₂?

Show answer and reasoning

Not yet under this iteration definition.

S₂ extends S₁={p} by only one edge. The new q is added at that stage, so r enters at S₃.

After adding r→z, can the structural-induction proof for the old safe set G be used unchanged?

Show answer and reasoning

No.

Closure of G in the step case fails. Not checking the changed rules would give an invalid invariant proof.

Explore further

Further proof: on a general set X, suppose there are positive generating rules with finitely many premises and starting rules with no premises. Positive means that the rules require membership of premises in a set, not nonmembership. The collection C of all rule-closed sets is nonempty because it includes X. Put L=⋂C. If every premise of a rule belongs to L, every premise belongs to each set C∈C, so its conclusion belongs to every such C and hence to L. Thus L is closed and, by definition, is contained in every closed set, making it least. The set D of conclusions obtainable by finite evidence trees is also closed: each rule has finitely many premises, so attaching their finite trees below one parent still gives a finite tree. Therefore L⊆D. Conversely, for each closed set C, structural induction on an evidence tree shows that every derived conclusion belongs to C. Thus D⊆⋂C=L, and L=D. This also explains why the same finite-tree account does not automatically apply to arbitrary infinite-premise rules or rules with negative premises.

Subtopic 2.3

Basic Proof-Assistant Commands

If a goal pane says there is nothing left to do, have the real program and user requirements all been verified?

Preparation and learning goals

Preparation

  • In Lean 4, Prop is the sort in which propositions live, and hp : p denotes evidence hp for p. Distinguish Nat for natural-number data from Prop for propositions. A colon states the type of the expression on its left.
  • A proof goal Γ ⊢ P asks for evidence of P using the variables and assumptions in context Γ. If h : P∧Q is an assumption, h.left is evidence of P and h.right is evidence of Q.
  • A definition gives the meaning of a name; a theorem supplies evidence of a particular proposition. This unit uses language rules from the official public Lean 4 textbook. It does not confirm a local Lean version or successful execution.

Learning goals

  • Explain def/theorem and intro/constructor/exact through changes to goals and assumptions.
  • Trace definition unfolding and logical evidence in a complete small file.
  • Distinguish an expected trace, actual kernel checking, and validity of a real-world specification.

Proof commands construct evidence

The language is fixed to Lean 4. The file below defines Both p q as p∧q in namespace PaperProof and declares swapBoth, which reverses the order, and keepLeft, which obtains the left property for every element. A def registers a meaning; a theorem states a type and supplies evidence for it. Tactics after by are a method of constructing a proof term. The code contains no unfinished sorry hole, new axiom, or classical command requesting classical principles.

When Lean is actually run, parsing, name/type inference, and tactic processing produce evidence that is subject to the kernel's type check. This file was not executed during authorship, however, so no passing result is reported. The trace below is an expected sequence of goals derived on paper from official rules. Notation, names, and diagnostics can differ in an installed version. Merely saving a file is not evidence of kernel verification.

Read a small file goal by goal

The initial context of swapBoth contains p,q:Prop, and its goal is Both p q→Both q p. The command intro h adds evidence h:Both p q to the context and leaves Both q p as the goal. The command change q∧p replaces that goal with a definitionally equal one after unfolding Both. It changes the presentation of the same goal; it does not turn a false proposition into a true one.

To construct evidence of q∧p, constructor creates two subgoals, q and p. In the first bullet block, exact h.right submits the right component, evidence of q, reading h:p∧q after unfolding the definition. The second exact h.left submits evidence of p. The bullet · separates different goal blocks. Hence no goals are expected to remain. Using exact h.left for the first goal would try to prove an arbitrary q from evidence of p and is generally inappropriate.

namespace PaperProof

def Both (p q : Prop) : Prop := p ∧ q

theorem swapBoth (p q : Prop) : Both p q → Both q p := by
  intro h
  change q ∧ p
  constructor
  · exact h.right
  · exact h.left

theorem keepLeft (α : Type) (P Q : α → Prop)
    (h : ∀ x : α, Both (P x) (Q x)) : ∀ x : α, P x := by
  intro x
  exact (h x).left

end PaperProof

Quantified theorems and the limits of verification

In keepLeft, we have α:Type, predicates P,Q:α→Prop, and h:∀x:α, Both (P x) (Q x). Applying intro x to the goal ∀x:α,P x introduces arbitrary x:α and leaves goal P x. Since h x is evidence of Both (P x) (Q x), (h x).left fits the goal. The theorem is valid even if α is an empty type. The code neither creates an element of α nor guarantees ∃x:α,P x.

The command #check investigates an expression's type, #print shows a declaration, and #eval concerns evaluating a computable expression. None was executed here. Do not confuse an existing assumption with a proof. Adding an inconsistent axiom of False lets desired statements be derived, and filling holes with sorry can hide an unfinished proof. Review the proved statement, axioms used, definitions, tool version, and execution record together. The theorem swapBoth does not concern an actual server implementation or user requirements.

A worked example, step by step

Trace swapBoth in the complete file below without executing it. Write the context and goal at every step, and check the types submitted by the two exact commands.

  1. Initially p,q:Prop and the goal is Both p q→Both q p. After intro h, the context also contains h:Both p q and the goal is Both q p.
  2. The command change q∧p unfolds the conclusion to a definitionally equal form. The type of h is also definitionally p∧q through Both.
  3. After constructor, the first goal is q and the second is p. The evidence in exact h.right has type q and fills the first goal.
  4. In the second block, exact h.left has type p and fills the remaining goal. The paper-rule trace closes every goal; no actual Lean log was obtained.

Submit the two components of h in reverse order. The expected proof term has the form fun h => ⟨h.right, h.left⟩. It is not presented as a local execution result or an error-free compilation record.

Try it with paper and the lesson

On paper, write the goals before and after intro x in keepLeft. Explain what would go wrong if the following command were changed to exact (h x).right. Finally write a paper procedure for keepRight, whose conclusion uses Q instead of P.

Show hint

Unfold Both to identify the two properties proved by h x. Introduce an arbitrary element of the type for a universal goal, not a particular number.

Show solution

Before introduction the goal is ∀x:α,P x; afterward it is P x for arbitrary x:α. The expression (h x).right proves Q x, so it does not fit a general P x goal. For keepRight, state the goal ∀x:α,Q x, use intro x, then submit exact (h x).right to solve it constructively. This is a paper procedure; the changed file was not actually executed.

Misconception and counterexample

Removing goals with a short tactic, or inserting sorry, also verifies the correctness of a real system.

First, goals were not actually checked with a tool here. Second, even an actually checked proof supplies evidence only for its stated proposition and assumptions. A sorry is an unfinished hole; adding an inconsistent axiom can yield meaningless conclusions. A simple logical-swap theorem says nothing about the suitability of server, device, or user requirements.

Check your understanding

Does exact h.left generally fit the first goal q?

Show answer and reasoning

No.

The expression h.left is evidence of p. Both p and q belong to Prop, but there is no assumption that the propositions are definitionally equal, so this does not fill a general q goal.

Does keepLeft require an assumption that α is nonempty?

Show answer and reasoning

Not for this universal conclusion.

Given arbitrary x, it returns the left evidence. It requires no existential witness; on an empty type the universal statement holds vacuously.

Does including a complete Lean file in this manuscript constitute a record of passing the Lean kernel?

Show answer and reasoning

No.

Only documentary-rule comparison and a paper trace were recorded. Installation, compilation, and kernel checking are not_executed.

Explore further

Further proof: explain swapBoth fully using typed proof terms. For arbitrary p,q:Prop, take h:Both p q and unfold the definition to obtain h:p∧q. Elimination rules give h.right:q and h.left:p. The introduction rule builds ⟨h.right,h.left⟩:q∧p, which is definitionally equal to Both q p. Making a function that takes h as an assumption gives evidence of Both p q→Both q p. Applying the same construction to q,p also gives the reverse direction; this is not a claim about h having the same computer-memory address. The construction fun x => (h x).left likewise preserves quantification for keepLeft. Neither construction requires excluded middle or arbitrary choice. If actual reproduction is chosen, preserve a separate file, exact Lean version, command, complete diagnostics/exit result, and absence or presence of unfinished holes before updating tool-execution status.
