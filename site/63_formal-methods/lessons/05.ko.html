소단원 5.1

Hoare triple

몇 번 입력해 잘 나왔다는 사실과 모든 조건부 입력에 대한 약속은 같을까?

준비 개념과 학습 목표

준비 개념

  • 상태는 변수 이름을 값에 연결한 표다. assertion은 상태에서 참/ 거짓인 논리식이다.

  • {P} C {Q}에서 P는 시작의 사전조건,Q는 끝의 사후조건이다. 본 자체 예제는 오버플로 없는 수학적 정수의 순차 명령이며 원문 Imp nat와 구별한다.

학습 목표

  • 명시한 정의와 적용 조건을 설명한다.

  • 자체 예제를 단계별로 풀고 반례의 원인을 찾는다.

모든 종료 결과가 맞아도 일부 입력은 영원히 기다릴 수 있나요?

앞 본문의 무한정밀 수학적 정수·순수 식·순차 대입을 사용합니다. 원문 Imp의 자연수 뺄셈과 구별합니다. 새 명령 C는 if x≥0 then y:=2×x else while true do skip입니다. 사전조건 True는 모든 정수 초기 상태를 허용합니다. 사후조건 y≥0은 종료한 상태에서만 평가합니다.

초기 x가 음수이면 거짓 가지가 무한 반복하여 종료 상태가 없습니다. x가 0 이상이면 대입이 끝나 y=2×x≥0입니다. 따라서 {True} C {y≥0}은 부분 정확성에서 유효하지만 모든 입력의 종료는 보장하지 않습니다. 사전조건을 x≥0으로 제한하면 이 추상 명령은 허용된 모든 입력에서 종료합니다. 음수 입력을 실제 시스템에서 기다리거나 실행해 본 결과가 아닙니다.

사후조건을 y>0으로 강화하면 초기 x=0에서 끝 값 y=0이 반례입니다. 반면 사전조건 False이면 허용 시작이 없으므로 부분 triple은 어떤 사후조건에서도 유효합니다. 종료 상태의 부재와 허용 시작의 부재는 서로 다른 이유이며, 둘 다 실제 응답이 생성됐다는 증거가 아닙니다. 논리 상수 a는 최초 값을 기억하는 고정 수이고 실행 중 갱신되는 x와 구별합니다.

먼저 확인할 개념
  • 종료한 경우의 약속

    부분 정확성의 양화 대상과 전후 상태의 시점을 사용합니다.

  • 완료 결과와 유한 예산

    Timeout 하나와 발산 근거, 완료 상태의 의미를 구별합니다.

모든 조건부 시작 상태를 양화하기

유효한 triple은 P를 만족하는 모든 시작 상태에서 C가 종료하면 끝 상태에 Q가 성립한다는 뜻이다. 한 입력의 관측이나 원하는 출력만 쓰는 문서와 다르다. P가 불필요하게 좁으면 매우 적은 상황만 보장한다.

변수 이름은 같아도 P의 x 는 전 상태,Q의 x는 후 상태다. 증가 명령 후 값은 다른 시점이다. 원래 값을 기억하려면 변하지 않는 논리 상수 n을 쓰거나 old(x) 표기 의미를 별도로 정의해야 한다.

부분 정확성과 종료 분리하기

이 논리의 부분 정확성은 종료한 경우를 보장한다. 무한히 도는 명령은 종료 상태가 없어 어떤 Q에 대해서도 이 정의에 반례를 내지 않는다. 이것을 서비스가 응답했다거나 실행에 성공했다는 뜻으로 해석하지 않는다.

전체 정확성은 종료까지 추가로 보장한다. 아래 대입 명령은 이 추상 의미에서 종료하지만 반복문 전체의 종료 증명을 자동으로 얻지는 않는다. 시간 제한· 예외· 동시성도 현재 단순 언어에서 제외한다.

반례와 공허한 참

triple을 깨려면 P가 참인 시작을 찾고 명령이 종료한 뒤 Q가 거짓인 것을 보여야 한다. P 밖 입력의 실패만으로 조건부 계약을 반박하지 않는다.

P =False이면 만족하는 시작 상태가 없어 triple은 공허하게 참이다. 논리적으로 유효해도 사용할 수 있는 입력이 없으므로 유용한 계약인지 별도로 보자. 실제 증명기나 프로그램 실행 검증은 수행하지 않았다.

공허하게 유효

음수 행에 y=0 같은 값을 채우지 않습니다. 종료하지 않은 경우에는 끝 상태의 사후조건을 시험한 것이 아닙니다. 원래 y 값은 종료하는 가지에서 덮어씁니다.

중간 과정을 따라가는 예제

{x ≥0} x:=x +3 {x ≥3}의 유효성을 설명하고 사후조건을 x>3으로 바꾸면 반례를 찾으라.

  1. 시작 값을 n ≥0으로 두면 종료 값은 n +3이다.

  2. n +3 ≥3이라 모든 허용 시작에서 첫 Q가 참이다.

  3. x>3은 n =0을 선택하면 종료 값 3에서 거짓이다.

  4. 이 반례의 시작 0은 P에 속하고 명령은 종료하므로 수정 triple이 무효다.

≥3 계약은 유효,>3 계약은 시작 0의 반례로 무효다.

조건을 바꾸어 비교하기

부분 정확성과 전체 정확성의 입력 범위

C와 사후조건 y≥0에서 사전조건 True 및 x≥0의 종료 보장을 비교하세요.

  1. x≥0인 경우 C는 한 대입 가지를 선택해 종료합니다.

  2. x<0인 경우 거짓 guard가 아니라 참 상수 guard의 무한 반복을 선택합니다.

  3. True는 두 경우를 포함하고 x≥0은 종료하는 경우만 포함합니다.

두 부분 triple은 유효합니다. 전체 정확성은 사전조건 x≥0에서 성립하지만 True에서는 성립하지 않습니다.

비교할 점

무한 반복의 상태 불변은 종료의 근거가 아닙니다.

엄격한 끝 조건의 반례

{True} C {y>0}이 무효임을 보이는 허용 시작 상태를 종이에 만드세요.

  1. 초기 x=0, y=17을 택합니다.

  2. 조건 x≥0이 참이므로 y:=0으로 종료합니다.

  3. 사후조건 0>0이 거짓입니다.

허용 시작 (x,y)=(0,17), 종료 (0,0)이 부분 triple의 반례입니다.

비교할 점

음수 입력의 발산만으로 이 부분 triple을 반박한 것이 아닙니다.

종이와 본문으로 직접 해보기

{x ≥2} x:=x +3 {x ≥5}와 {False} skip {x =100}을 판정하라.

힌트 보기

허용 시작의 집합과 종료 값을 따로 적는다.

풀이 보기

첫 계약은 n ≥2 →n +3 ≥5로 유효다. 둘째는 허용 시작이 없어 공허하게 유효이며 100을 실제로 만든다는 뜻이 아니다.

오해와 반례

부분 정확성이면 모든 명령이 끝나고 원하는 출력이 실제 생성된다.

while true do skip은 끝나지 않아 부분 triple의 종료 사후조건을 깨지 않지만 응답을 보장하지 않는다. False 사전조건도 실제 출력 증거가 아니다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

각각 독립 초기 x=−1,y=9와 x=2,y=9에서 C의 종료 여부와 종료한 경우의 y를 쓰세요.

힌트 1

두 초기 상태는 이어지는 실행이 아닙니다.

힌트 2

무한 반복 행에는 종료 값을 쓰지 않습니다.

풀이와 답 확인

  1. x=−1은 무한 반복 가지이므로 종료 결과가 없습니다.

  2. x=2는 대입 가지로 끝나 y=4입니다.

첫 경우는 발산, 둘째 경우는 종료하여 y=4입니다.

흔한 오답에서 다시 생각하기

첫 경우는 y가 계속 9이므로 최종 y=9로 성공했다.

계속 같은 값인 중간 상태와 존재하는 종료 상태는 다릅니다.

연습 2 · 오류 찾아 고치기

C의 음수 입력이 끝나지 않으므로 {True} C {y≥0}은 부분 정확성에서도 무효라고 썼습니다. 반례 정의의 빠진 조건을 찾으세요.

힌트 1

부분 반례는 허용 시작과 종료 결과가 모두 필요합니다.

힌트 2

종료한 가지에서 y=2×x입니다.

풀이와 답 확인

  1. 음수 입력은 종료하지 않아 종료 사후조건을 깨는 결과를 제공하지 않습니다.

  2. 모든 종료 입력은 x≥0이고 y≥0을 만족합니다.

부분 triple은 유효하며 모든 입력의 종료 요구가 별도로 실패합니다.

흔한 오답에서 다시 생각하기

부분 triple이 유효하니 응답 시간도 제한 안에 든다.

종료와 시간 제한은 이 부분 사후조건에서 따르지 않습니다.

연습 3 · 직접 만들어 보기

임의의 고정 정수 a에서 {x=a} x:=x+2 {x=a+2}를 손논증하고, 후 조건의 a를 실행 변수 x로 바꾸면 생기는 문제를 설명하세요.

힌트 1

a는 명령의 갱신 대상이 아닙니다.

힌트 2

오른쪽 식은 시작 상태의 x를 읽습니다.

풀이와 답 확인

  1. 초기 x=a이면 대입 오른쪽은 a+2입니다.

  2. 갱신 후 x=a+2이고 고정 a는 그대로입니다.

  3. a를 후 상태의 x로 바꾸면 x=x+2라는 모순을 요구합니다.

고정 a를 사용한 triple은 유효합니다. 후 상태 변수로 치환한 x=x+2는 정수에서 불가능합니다.

흔한 오답에서 다시 생각하기

처음 x와 나중 x는 같은 이름이므로 같은 값이다.

변수 이름을 유지해도 상태의 시점은 바뀝니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

C와 끝 조건 y≥0에 대해 전체 정확성을 보장하는 사전조건 P는 왜 P⇒x≥0이어야 하나요? 가장 넓은 허용 입력 집합도 쓰세요.

힌트 1

P가 허용한 음수 상태가 있으면 종료하지 않습니다.

힌트 2

모든 x≥0 상태에서는 종료합니다.

풀이와 답 확인

  1. 종료를 보장하려면 어떤 허용 상태에도 음수 x가 없어야 합니다.

  2. 즉 P⇒x≥0이 필요하고 이 조건이면 종료와 사후조건이 모두 성립합니다.

  3. 가장 넓은 집합은 y의 최초 값에 제한 없는 x≥0입니다.

전체 정확성의 필요충분 조건은 P⇒x≥0이며, 가장 넓은 사전조건은 x≥0입니다.

흔한 오답에서 다시 생각하기

x>0만 가장 넓은 조건이다.

x=0도 종료해 y≥0을 만족하므로 제외할 이유가 없습니다.

내 말로 설명하기

발산과 False 사전조건은 같은 이유인가요?

설명 기준 확인

아닙니다. 앞은 허용 시작 뒤 종료 결과가 없고 뒤는 허용 시작 자체가 없습니다.

논리 상수는 저장 변수인가요?

설명 기준 확인

아닙니다. 최초 값과 끝 값을 연결하기 위해 고정한 수입니다.

할당·합성·조건규칙

원하는 마지막 값을 거꾸로 따라가면 필요한 시작 조건을 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • :=는 값 갱신이고 =는 논리의 같음이다. Q[x ←e]는 Q에 등장하는 자유 변수 x를 식 e로 대체한 논리식이다.

  • ∧는 둘 다 참,¬ 는 부정이다. 본문은 부작용 없는 식/ 무한정밀 정수/ 순차 대입의 추상 언어다.

학습 목표

  • 명시한 정의와 적용 조건을 설명한다.

  • 자체 예제를 단계별로 풀고 반례의 원인을 찾는다.

교환 명령의 마지막 조건을 거꾸로 옮기면 중간 상태까지 복원되나요?

서로 다른 정수 변수 x,y의 새 명령 S는 x:=x+y; y:=x−y; x:=x−y입니다. 고정 논리 상수 a,b를 최초 x,y로 두면 첫 대입 뒤 (a+b,b), 둘째 뒤 (a+b,a), 셋째 뒤 (b,a)입니다. 자연수의 잘린 뺄셈이나 기계 정수 오버플로로 바꾸지 않았습니다. 같은 저장 칸을 두 이름으로 부르는 별칭도 배제합니다.

최종 Q=(x=b∧y=a)에서 마지막 대입을 거꾸로 치환하면 x−y=b∧y=a입니다. 다시 둘째 대입을 치환하면 x−(x−y)=b∧x−y=a, 즉 y=b∧x−y=a입니다. 첫 대입까지 치환하면 y=b∧x=a가 되어 원래 시작 조건과 같습니다. 각 치환은 그 대입 직전 상태를 대상으로 하며, 고정 a,b는 치환하지 않습니다.

다른 새 명령 A는 x:=x+y; y:=x−y입니다. 사후조건 x+y=12의 정확한 시작 조건은 2×x+y=12입니다. 마지막 y 치환으로 중간 조건 2×x−y=12를 만들고, 첫 x 치환으로 2×(x+y)−y=12를 얻기 때문입니다. 명령의 순서를 바꾼 B는 y:=x−y; x:=x+y이고 최종 합은 최초 3×x−2×y입니다. 치환식이나 마지막 숫자만 보고 두 명령을 혼동하지 않습니다.

먼저 확인할 개념
  • 대입과 중간 조건

    사후조건의 자유 변수 치환과 순차 명령의 역방향 순서를 사용합니다.

  • 허용 시작과 고정 논리 상수

    명령 전후 x와 고정된 a를 구별하고 모든 시작 상태를 논증합니다.

할당은 사후조건에서 역으로 치환하기

할당 규칙은{Q[x ←e]} x:=e {Q}다. 시작 시 e의 값을 후 x에 넣으므로 사후조건 x의 자리를 e로 바꾼 식이 시작에서 참이면 된다. 명령문 왼쪽 x를 없애라는 뜻이 아니다.

사후조건 x ≤12와 x:=x +2이면 치환은 x +2 ≤12, 즉 x ≤10이다. 사후조건에만 있는 다른 변수는 대입으로 바뀌지 않는다. 식에 부작용이나 포인터 별칭이 있으면 현재 규칙의 상태 모형을 그대로 사용할 수 없다.

합성에서 중간 조건 연결하기

{P} C1 {M}과{M} C2 {Q}를 보이면{P} C1;C2 {Q}다. C1의 후 상태와 C2의 전 상태가 동일한 중간 조건 M으로 연결된다. 마지막 명령부터 역 치환하면 필요한 M을 찾기 쉽다.

x:=x +2;y:=3 *x 뒤 y ≤18을 원하면 두 번째 앞 M은 3 *x ≤18, 즉 x ≤6이다. 첫 번째 앞 P는 x +2 ≤6, 즉 x ≤4다. 각 단계의 x 시점을 섞으면 잘못된 조건이 나온다.

분기마다 조건을 더 하기

if b then C1 else C2에서는 P ∧b로 첫 가지,P ∧¬b로 둘째 가지를 증명하고 공통 Q를 만든다. 한 가지의 성공을 다른 가지까지 일반화하지 않는다.

if x ≥0 then y:=x else y:=−x 는 수학적 정수에서 y ≥0을 보장한다. 첫 가지 x ≥0, 둘째 x<0이므로 −x>0이다. 음수 최솟값을 부호 반전하는 기계 정수 오버플로는 현재 추상 조건 밖이다.

준비 개념

  • old(n)은 시작 시 n 값을 보존한 논리 표기이며 실행 변수가 아니다. 아래 reserve는 종이에서 정의한 추상 연산이다.

실패 뒤에도 범위 안이면 상태 보존 계약까지 맞는 건가요?

새 순차 연산 R의 상태는 정수 (n,limit,r)입니다. 사전조건은 0≤n≤limit이고 r의 최초 값은 임의입니다. R은 n<limit이면 n:=n+1; r:=1, 그렇지 않으면 r:=0을 수행합니다. limit에는 대입하지 않습니다. 고정 논리 상수 n₀,L을 최초 n,limit로 두어 결과와 처음 값을 연결합니다.

성공은 n₀<L일 때 r=1∧n=n₀+1∧limit=L입니다. 실패는 n₀=L일 때 r=0∧n=n₀∧limit=L입니다. 두 경우 모두 0≤n≤limit이지만 범위 조건만으로 성공의 정확한 증가나 실패의 보존을 알 수 없습니다. 실패가 최초 r까지 보존한다는 계약은 아닙니다. r은 반환 표시이므로 실패에서도 0으로 바뀔 수 있습니다.

기존 triple의 사전조건을 좁히고 사후조건을 약화하면 함의 방향에 따라 새 triple을 얻습니다. 하지만 기존 모든 호출자를 받는 대체 연산이라는 목적이면 더 강한 사전조건은 기존 입력 일부를 제외합니다. 증명 규칙으로 좁은 계약을 만드는 일과 호출자의 기존 약속을 유지하는 대체 가능성은 다릅니다. 언급하지 않은 owner 같은 외부 상태의 보존을 이 세 변수 계약에서 자동 추론하지 않습니다.

호출자와 제공자의 약속

사전조건은 호출자가 충족할 조건, 사후조건은 제공자가 그 시작 조건하에 반환 시 지킬 조건이다. n ≥0인 개수에 하나 더 하는 연산의 Q를 n =old(n)+1로 쓰면 단지 양수보다 정확한 증가 관계가 남는다.

사전조건을 n ≥5로 강화하면 제공자는 처리할 입력이 줄지만 호출자는 더 제약 받는다. 사후조건을 n ≥1로 약화하면 증명하기 쉽지만 정확히 하나 추가됐는지는 알 수 없다. 계약의 강약은 입력/ 출력에서 서로 다른 효과를 낸다.

결과 규칙의 함의 방향

이미{P} C {Q}라면 P ′⇒P와 Q ⇒Q ′를 이용해{P ′} C {Q ′}를 얻는다. 시작은 더 강한 조건으로 좁히고 끝은 더 약한 조건으로 넓힌다. 반대 방향은 추가 증명 없이 안 된다.

n ≥0에서 증가 후 n ≥1이면 n ≥2인 시작으로 좁히고 끝 n ≥0으로 약화할 수 있다. 그런데 사전 n ≥−1로 넓히면서 끝 n ≥1을 유지하면 시작 −1 →0의 반례가 생긴다.

변경 범위와 실패도 계약에 넣기

reserve의 추상 상태(n,limit)에 0 ≤n<limit을 요구하고 성공 후 n ′=n +1,limit ′=limit로 정하면 어느 값이 유지되는지도 보인다. n ≤limit만으로 같은 성공을 약속하면 경계 n =limit에서 한도 초과다.

A의 정확한 시작 조건은 2×x+y=12이고 초기 (3,6)은 (9,3)으로 끝난다. 잘못된 초기 합 조건의 (1,11)은 (12,1)로 끝나 최종 합이 13이다. B의 최종 쌍은 (2×x−y,x−y)이며 A와 같은 쌍이 되는 시작은 (0,0)뿐임을 확인했다. R의 성공/실패 고정 최초 관계와 범위 함의를 손논증했다. F의 (4,4,9)→(3,4,0)은 실패 보존을 깨고 G의 (2,4,9)→(3,5,1)은 limit 보존을 깬다. 전이 A와 B의 끝 쌍은 각각 (10,2)와 (−4,−6)이며 전이 R과 F의 끝 상태는 각각 (5,5,0)과 (4,5,0)이다. 모든 새 수치와 증명은 손유도다. 기본과 최종 저장 보강 전체 및 수동 변경 필드를 재독했다. 같은 05의 세 고유 선수와 04 topic03의 실제 설명, 공식 본문의 지정 범위 및 여섯 HTML 의미 앵커를 확인했다.
