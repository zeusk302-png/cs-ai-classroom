소단원 3.1

리스트·트리 성질

크기가 다른 모든 리스트와 가지 구조를 몇 가지 경우만으로 다룰 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 리스트 []는 빈 순서열이고 x::xs 는 맨 앞 값 x 와 나머지 xs 다. 같은 값의 중복도 별도 위치다.

  • ∀는 주어진 범위의 모든 값이라는 뜻이다. 몇 가지 사례의 확인과 구별한다.

  • 이 단원의 자료는 유한하며 순환 참조·무한 리스트가 없다. 수학적 정수·리스트 계산을 다룬다.

학습 목표

  • 생성자마다 기저와 귀납 단계를 만든다.

  • 리스트 연결의 길이 및 이진 가지 구조의 잎 수를 증명한다.

  • 재귀 호출의 감소와 등식의 올바름을 구별한다.

같은 하위 자료를 두 번 연결하면 잎도 객체도 두 배인가요?

새 종이 모형에서 s=Branch(Leaf(a),Leaf(b))이고 t=Branch(s,s)입니다. 두 자리에 정확히 같은 불변 객체 s의 참조가 들어가되 순환은 없습니다. 구조를 펼친 값의 출현 수 I와 L은 앞 본문의 재귀 정의대로 셉니다. 별도로 U는 루트에서 도달하는 서로 다른 객체의 수입니다. 값의 출현과 객체 정체성은 다른 관찰입니다.

펼친 t에는 내부 출현이 3번, 잎 출현이 4번 있습니다. 그러나 서로 다른 객체는 t, s, Leaf(a), Leaf(b)의 4개입니다. 고유 내부 객체가 2개이고 고유 잎 객체가 2개여서 고유 개수에는 L=I+1이 성립하지 않습니다. 구조 귀납으로 얻은 출현 수 정리를 메모리 객체 개수에 그대로 적용한 것이 문제입니다. 실제 메모리나 GC를 관찰한 결과는 아닙니다.

자료형의 생성자 수도 조건입니다. 별도 세 자식 자료형 Tri는 Leaf 또는 Node(l,m,r)로만 만들며 세 자식이 모두 존재합니다. 출현 수는 잎에서 I=0,L=1이고 Node에서 I=1+I(l)+I(m)+I(r), L=L(l)+L(m)+L(r)입니다. 세 귀납 가정을 더하면 L=2I+1이 됩니다. 두 자식 자료형의 공식과 빈 자리가 허용된 다른 자료형을 섞지 않습니다.

먼저 확인할 개념
  • 생성자와 두 귀납 가정

    앞 본문의 Leaf/Branch 범위와 출현 수 정의를 먼저 확인합니다.

  • 정의·종료·정확성의 구분

    계수 정의를 객체 방문 정책으로 바꾸면 명세도 바뀐다는 점을 연결합니다.

조립 방법이 증명 경우를 정한다

유한 리스트는 [] 또는 x::xs 라는 두 생성 방법으로 정의한다. len([])=0, len(x::xs)=1+len(xs)다. 성질 P(xs)를 모든 리스트에 증명하려면 P([])를 보이고, 임의의 x 와 xs 에 대해 P(xs)를 가정해 P(x::xs)를 보여야 한다. 작은 목록을 여러 개 나열하는 것으로 이 임의성을 대신할 수 없다.

귀납 가정은 지금 증명하려는 큰 목록 자체의 정답을 가정하는 것이 아니다. 생성자 안의 더 작은 자료에만 사용할 수 있다. 유한 구조이므로 꼬리를 반복해서 따라가면 결국 []에 도달한다. 같은 목록으로 다시 재귀하거나 순환 연결을 허용하면 이 정당화는 달라진다.

리스트 연결과 길이

연결 xs++ys 는 []++ys=ys, (x::xs)++ys=x::(xs++ys)로 정의한다. 길이 정리는 모든 유한 xs,ys 에 대해 len(xs++ys)=len(xs)+len(ys)다. xs 에 귀납한다. 빈 경우 왼쪽 len(ys)와 오른쪽 0+len(ys)가 같다. ys 가 빈 목록이라는 가정을 추가할 필요는 없다.

생성자 경우 귀납 가정 len(xs++ys)=len(xs)+len(ys)를 쓰면 len((x::xs)++ys)=1+len(xs++ys)=1+len(xs)+len(ys)=len(x::xs)+len(ys)다. 첫 등식은 연결과 길이 정의, 둘째는 귀납 가정, 마지막은 길이 정의다. 각 줄의 근거를 표시하면 실제로 필요한 가정이 드러난다.

두 자식에는 두 귀납 가정

여기서 트리는 Leaf(v) 또는 Branch(l,r)로만 만드는 유한 자료다. 모든 Branch 에는 두 실제 자식이 있다. I(Leaf)=0, L(Leaf)=1, I(Branch)=1+I(l)+I(r), L(Branch)=L(l)+L(r)로 내부 노드와 잎 수를 정한다. 일반적인 자식 수 0·1·2 트리와 이 자료형은 다르다.

L(t)=I(t)+1 은 잎에서 1=0+1 이다. Branch 에서는 양쪽 귀납 가정 L(l)=I(l)+1, L(r)=I(r)+1 을 써서 L(t)=I(l)+I(r)+2=I(t)+1 을 얻는다. 왼쪽만 증명하고 오른쪽을 생략하면 임의의 오른쪽 하위 트리를 다루지 못한다. 이 정리는 값 v 의 숫자 크기가 아니라 구조에 관한 것이다.

마지막 행은 출현 수가 아닌 고유 객체 수입니다. s의 두 번 출현을 같은 객체 한 개로 합치는 정책을 사용하면 앞의 두 계수와 다른 정의가 됩니다. 객체 이름이 같다는 조건을 명시했으며 같은 값을 가진 서로 다른 복사 객체와 구별합니다.

중간 과정을 따라가는 예제

xs=[2,2], ys=[5]의 연결 길이를 전개하고, t=Branch(Leaf(a),Branch(Leaf(b),Leaf(c)))의 I,L 을 계산해 일반 증명과 비교하라.

  1. [2,2]++[5]=2::([2]++[5])=2::(2::([]++[5]))=[2,2,5]다.

  2. 연결 길이는 3 이고 len(xs)+len(ys)=2+1=3 이다. 두 값 2 의 중복이 길이에서 사라지지 않는다.

  3. 오른쪽 Branch 의 I=1+0+0=1, L=1+1=2 다.

  4. 전체 I=1+0+1=2, L=1+2=3 이므로 L=I+1 이다. 전체 실제 노드는 5 개다.

  5. 이 두 예는 공식을 확인하는 사례다. 모든 유한 입력에 관한 근거는 앞의 기저·귀납 단계에 있다.

연결 길이 3, 트리 내부 2·잎 3·총 5 다. 예제 계산과 보편적인 증명의 역할을 구별한다.

조건을 바꾸어 비교하기

공유를 펼친 뒤의 귀납

t의 출현 수 정리와 고유 객체 정리를 각각 검사하세요.

  1. s의 출현 수는 내부 1번과 잎 2번입니다.

  2. t의 출현 수는 I=1+1+1=3, L=2+2=4입니다.

  3. 고유 객체에는 s와 두 잎을 한 번만 포함하므로 고유 내부 2개, 고유 잎 2개입니다.

출현 수에서는 4=3+1이 참입니다. 고유 객체에서는 2=2+1이 거짓입니다.

비교할 점

동일한 그림에서 어떤 대상을 세는지 바꾸면 적용할 정리도 달라집니다.

세 자식 생성자의 새 계수

Tri의 u=Node(Leaf(a),Leaf(b),Leaf(c))와 v=Node(u,Leaf(d),Leaf(e))를 계산하세요.

  1. u의 내부 출현은 1번이고 잎 출현은 3번입니다.

  2. v의 내부 출현은 2번이고 잎 출현은 5번입니다.

  3. 각 Node 단계에서 세 귀납 가정 L(child)=2I(child)+1을 더하면 L=2(I−1)+3=2I+1입니다.

u는 I=1,L=3이며 v는 I=2,L=5입니다. 총 출현 수는 각각 4번과 7번입니다.

비교할 점

세 자식에는 세 귀납 가정이 필요합니다. 이진 공식 L=I+1을 재사용하지 않습니다.

종이와 본문으로 직접 해보기

xs=[], ys=[7,7,9]에서 길이 정리를 확인하라. t=Branch(Branch(Leaf(a),Leaf(b)),Branch(Leaf(c),Leaf(d)))의 내부·잎 수를 구하고 두 귀납 가정을 적어라.

힌트 보기

빈 연결은 ys 그대로다. Branch 마다 내부 노드 한 개를 더하며 각각의 하위 트리에 정리를 적용한다.

풀이 보기

[]++[7,7,9]=[7,7,9], 길이 0+3=3 이다. 양쪽 하위 트리는 각각 I=1,L=2 이므로 전체 I=3,L=4 다. 왼쪽 L=I+1 과 오른쪽 L=I+1 이 각각 필요하며 2+2=(1+1+1)+1 을 얻는다.

오해와 반례

재귀 함수의 결과 몇 개가 맞으면 모든 리스트·트리에 대한 증명이 끝났다.

유한한 시험은 보편 양화를 대신하지 않는다. 길이 0 부터 10 까지 맞고 길이 11 에서 값을 일부러 잘못 반환하는 함수도 만들 수 있다. 또 자식 하나뿐인 일반 트리의 내부 1·잎 1 은 L=I+1 에 반례지만 이 단원의 Leaf/Branch 생성 범위 밖이다. 정리를 쓰기 전 자료형과 귀납 경우를 확인한다.

연습 1 · 값과 상태 예측

새로 만든 서로 다른 복사 객체 s1과 s2가 각각 Branch(Leaf(a),Leaf(b))의 값과 같습니다. 네 잎 객체도 모두 서로 다릅니다. t2=Branch(s1,s2)의 I,L,U를 구하세요.

힌트 1

이번에는 같은 값이지만 같은 객체가 아닙니다.

힌트 2

전체 출현 수는 공유 t와 같습니다.

풀이와 답 확인

  1. 내부 출현은 루트와 두 가지의 3번입니다.

  2. 잎 출현은 4번이고 모든 객체가 별개이므로 도달 객체는 7개입니다.

I=3,L=4,U=7입니다. 공유 t와 값의 구조는 같지만 U는 4에서 7로 달라집니다.

흔한 오답에서 다시 생각하기

값이 같으므로 U도 4이다.

값의 동일성만으로 객체 정체성이 같다는 전제를 만들 수 없습니다.

연습 2 · 오류 찾아 고치기

한 작성자가 t의 고유 객체 계수 2개/2개를 보고 앞 본문의 L=I+1 구조 귀납이 틀렸다고 주장했습니다. 오류를 고치세요.

힌트 1

정리의 I,L 정의부터 확인합니다.

힌트 2

각 재귀 자리에 같은 객체가 있어도 출현은 두 번입니다.

풀이와 답 확인

  1. 정리는 Leaf/Branch로 펼친 값의 출현 수에 관한 것입니다.

  2. 고유 객체를 한 번만 방문하는 계수는 원래 재귀 합 정의와 다릅니다.

고유 객체에 대한 반례는 출현 수 정리를 반박하지 않습니다. 별도의 그래프 계수 명세가 필요합니다.

흔한 오답에서 다시 생각하기

공유 객체가 있으면 어떤 구조 귀납도 불가능하다.

순환이 없는 공유 그래프를 값으로 펼친 유한 구조에는 구조 귀납을 적용할 수 있습니다.

연습 3 · 직접 만들어 보기

Tri의 모든 유한 값에 대해 L=2I+1을 기저와 세 자식 단계로 증명하세요.

힌트 1

잎의 I,L부터 씁니다.

힌트 2

세 자식 각각의 귀납 가정에서 상수 1이 하나씩 나옵니다.

풀이와 답 확인

  1. Leaf에서 L=1=2×0+1입니다.

  2. Node에서는 L=2I(l)+1+2I(m)+1+2I(r)+1입니다.

  3. 이는 2(I(l)+I(m)+I(r))+3=2I(Node)+1입니다.

세 귀납 가정을 모두 쓰면 모든 유한 Tri 값의 출현 수 정리가 성립합니다.

흔한 오답에서 다시 생각하기

가운데 자식은 양쪽 사이에 있으므로 귀납 가정이 필요 없다.

가운데 자식도 임의의 더 작은 구조이므로 그 잎 수를 바꿀 근거가 필요합니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

고유 객체 정책으로 t를 방문하며 이미 본 객체는 다시 세지 않습니다. t→s→Leaf(a)→Leaf(b) 순서 후 두 번째 s에 도착했을 때 계수 변화와 출현 수 정책의 차이를 설명하세요.

힌트 1

이미 본 객체의 하위도 다시 방문하지 않는 정책입니다.

힌트 2

출현 수 정책은 두 번째 s의 값도 펼칩니다.

풀이와 답 확인

  1. 첫 s를 마친 고유 계수는 내부 2개와 잎 2개입니다.

  2. 두 번째 s에서는 둘 다 추가하지 않습니다.

  3. 출현 정책에서는 두 번째 s가 내부 1번과 잎 2번을 더합니다.

고유 정책의 최종 계수는 2개/2개이고 출현 정책은 3번/4번입니다. 방문 기록은 계산 정책의 일부입니다.

흔한 오답에서 다시 생각하기

두 번째 s를 건너뛰어도 출현 수가 그대로 계산된다.

같은 결과를 원하는 함수라면 생략한 출현의 요약을 더하는 별도 규칙이 필요합니다.

소단원 3.2

보조정리

뒤집은 리스트의 길이를 증명하다 연결 연산에서 막히면 무엇을 따로 알아야 할까?

준비 개념과 학습 목표

준비 개념

  • rev([])=[], rev(x::xs)=rev(xs)++[x]로 뒤집기를 정의한다.

  • 보조정리는 주 정리를 위해 먼저 증명하는 별도의 참인 명제다.

  • 등식을 치환할 때 같은 함수의 인자에 같은 값을 넣으면 결과가 같다는 원리를 쓴다.

학습 목표

  • 막힌 식에서 필요한 보조정리를 찾는다.

  • 연결 길이 정리를 먼저 증명하고 뒤집기 길이에 적용한다.

  • 보조정리·귀납 가정·주 정리의 의존을 순환 없이 기록한다.

원소를 걸러 낸 뒤 뒤집기와 뒤집은 뒤 걸러 내기는 언제 같나요?

새 함수 F는 순수하고 고정된 술어 p를 사용합니다. F([])=[]이며 F(x::xs)는 p(x)가 참이면 x::F(xs), 거짓이면 F(xs)입니다. 각 원소의 위치를 보존하면서 통과한 원소만 남깁니다. 같은 x에는 언제 평가하든 같은 Boolean을 돌려주며 부작용·예외가 없는 유한 목록 모형입니다.

목표는 F(rev(xs))=rev(F(xs))입니다. 필요한 보조정리는 F(u++v)=F(u)++F(v)입니다. u에 귀납하고 생성자에서 p(x)의 참/거짓을 나눕니다. 참이면 양쪽에 x가 남고, 거짓이면 양쪽에서 x가 사라집니다. 그 뒤 더 작은 u의 귀납 가정으로 연결을 분리합니다. 이 보조정리는 뒤집기 교환 목표를 사용하지 않고 먼저 증명합니다.

주 정리의 생성자 단계는 F(rev(xs)++[x])=F(rev(xs))++F([x])입니다. 귀납 가정으로 첫 항을 rev(F(xs))로 바꿉니다. p(x)가 참이면 오른쪽에 [x]가 붙어 rev(x::F(xs))와 같고, 거짓이면 빈 목록이 붙어 rev(F(xs))입니다. 판정이 호출 횟수에 따라 달라지는 술어라면 이 순수 명세를 적용할 수 없습니다.

먼저 확인할 개념
  • 보조정리의 독립 증명

    연결을 분리한 뒤 주 정리의 귀납 가정을 적용하는 순서를 새 F에 사용합니다.

  • 유한 목록의 구조 귀납

    빈 목록과 첫 원소·꼬리의 두 경우를 새 술어 분기와 함께 확인합니다.

막힌 식을 읽기

목표는 모든 xs 에서 len(rev(xs))=len(xs)다. []에서는 바로 0=0 이다. x::xs 에서는 정의를 펼치면 len(rev(xs)++[x])가 나온다. 귀납 가정은 len(rev(xs))=len(xs)라서 연결 전체의 길이에 곧바로 적용할 수 없다. 식의 모양을 먼저 비교하자.

필요한 정보는 연결이 길이를 더한다는 사실이다. len(u++v)=len(u)+len(v)를 먼저 보이면 u=rev(xs),v=[x]를 대입할 수 있다. 더 좁은 len(rev(xs)++[x]) 명제를 별도로 만들기보다 임의의 u,v 를 다루는 정리가 재귀 정의와 맞아 귀납하기 쉬울 수 있다. 강한 명제가 때로 더 쉬운 증명을 준다.

보조정리는 이름만 붙인 가정이 아니다

연결 길이 보조정리를 u 에 귀납해 증명한다. []에서는 len(v)=0+len(v)다. u=h::us 에서는 len((h::us)++v)=1+len(us++v)=1+len(us)+len(v)=len(h::us)+len(v)다. 중간 치환은 더 작은 us 에 대한 귀납 가정이며 v 는 임의의 유한 목록이다.

이 보조정리는 rev 길이 정리를 사용하지 않고 완성했다. 이후 주 정리에서 사용하므로 의존 방향은 연결 길이→뒤집기 길이다. 보조정리를 증명하면서 주 정리를 다시 근거로 쓰면 서로 기대는 순환 증명이 된다. 증명 보조기의 Admitted 는 미완성 가정을 넣는 표시이므로 그것만으로 검증되었다고 보고하지 않는다.

주 정리에 정확하게 대입하기

이제 len(rev(x::xs))=len(rev(xs)++[x])=len(rev(xs))+len([x])=len(xs)+1=len(x::xs)다. 첫 줄은 rev 정의, 둘째는 보조정리, 셋째는 귀납 가정과 한 원소 목록의 길이 1, 마지막은 정수 덧셈과 len 정의다. 뒤집기가 정렬인지 판단할 필요는 없다.

기저와 단계가 전부 연결되어 유한 목록 전체의 길이 보존이 증명된다. 그러나 길이 보존만으로 올바른 뒤집기라는 전체 명세를 증명한 것은 아니다. 입력을 그대로 반환하는 함수도 길이를 보존한다. 원하는 동작이 값 순서 반전이라면 더 강한 명세를 따로 증명해야 한다.

화살표는 필터 연결 보조정리에서 뒤집기 교환 정리로 향합니다. 뒤집기 교환을 근거로 연결 보조정리를 증명하지 않습니다. 시험의 길이·합계가 같다는 사실은 원소 순서의 등식보다 약합니다.

중간 과정을 따라가는 예제

xs=[4,9]의 rev 와 길이를 전개하고, 마지막 생성자 귀납 단계에서 보조정리의 두 인자를 적어라.

  1. rev([4,9])=rev([9])++[4]다. rev([9])=rev([])++[9]=[9]다.

  2. 따라서 결과는 [9]++[4]=[9,4]로 길이 2 다.

  3. 마지막 단계 u=rev([9])=[9], v=[4]를 연결 길이 정리에 대입해 len([9]++[4])=1+1=2 다.

  4. 귀납 가정은 len(rev([9]))=len([9])=1 을 연결 길이를 펼친 뒤에 사용한다.

  5. 증명에서 u 는 뒤집힌 목록이라는 추가 가정 없이 보조정리의 임의 목록 자리에 들어간다.

뒤집기 [9,4], 길이 2. 연결 길이를 먼저 분리해야 기존 귀납 가정과 식이 일치한다.

조건을 바꾸어 비교하기

중복을 가진 순수 필터

p(x)는 x가 짝수라는 조건입니다. xs=[2,5,2,8]의 두 경로를 손으로 계산하세요.

  1. rev(xs)=[8,2,5,2]이므로 F(rev(xs))=[8,2,2]입니다.

  2. F(xs)=[2,2,8]이고 이를 뒤집으면 [8,2,2]입니다.

  3. 두 값 2는 별도 위치로 남습니다.

두 경로 모두 [8,2,2]입니다. 길이는 3이고 합은 12입니다.

비교할 점

길이와 합만 비교하면 [2,8,2]처럼 다른 순서를 놓칠 수 있습니다.

호출 횟수에 의존하는 새 반례

별도 p*는 각 경로를 새 카운터 0에서 시작해 첫 호출만 참, 뒤 호출은 거짓입니다. 이 반례의 필터는 목록의 앞에서 뒤로 한 원소씩 술어를 먼저 평가한 뒤 꼬리를 처리합니다. xs=[2,5]에서 두 경로를 계산하세요.

  1. 뒤집은 [5,2]를 걸러 내면 첫 호출의 5만 남습니다.

  2. 원래 [2,5]를 걸러 내면 첫 호출의 2만 남고 뒤집어도 [2]입니다.

  3. 두 경로의 카운터는 각각 독립적으로 0부터 시작합니다.

결과는 [5]와 [2]로 다릅니다. 순수 고정 술어 전제를 바꾼 반례입니다.

비교할 점

정리에 사용한 같은 기호 p가 호출별 고정 판정까지 자동으로 보장하지는 않습니다.

종이와 본문으로 직접 해보기

rev([1,1,2])의 값과 길이를 전개하라. 길이 보존을 통과하지만 뒤집기가 아닌 f(xs)=xs 를 [3,8]로 반박하고 보조정리의 증명 순서를 적어라.

힌트 보기

반복값도 각 위치를 유지한다. 보조정리의 의존은 연결 길이에서 시작한다.

풀이 보기

오해와 반례

주 정리가 참일 것 같으니 보조정리는 증명 없이 써도 되고, 길이가 맞으면 전체 프로그램이 올바르다.

보조정리는 증명되거나 명시된 전제여야 한다. 연결 길이를 뒤집기 길이로 정당화하고 뒤집기 길이를 다시 연결 길이로 정당화하는 방식은 순환이다. 또한 그대로 반환하는 함수는 길이 정리를 만족하지만 순서 반전 명세를 만족하지 않는다. 증명한 성질의 범위를 프로그램 전체로 확대하지 않는다.

힌트 2

풀이와 답 확인

  2. 참이면 rev(F(xs))++[x]=rev(x::F(xs))입니다.

누적 숫자가 바뀌는 재귀에서 초기값 0만 아는 가정으로 충분한가요?

새 함수 T는 수학적 정수와 유한 목록에서 T([],a)=a, T(x::xs,a)=T(xs,2a+x)로 정의합니다. 별도 가중 값 W는 W([])=0, W(x::xs)=2^len(xs)×x+W(xs)입니다. 원소는 비트에 한정하지 않으며 음수 정수도 허용합니다. T는 순수 종이 모형이고 실제 고정 폭 정수의 랩이나 오버플로를 가정하지 않습니다.

정확성 명세는 모든 정수 a에 대해 T(xs,a)=2^len(xs)×a+W(xs)입니다. 초기값 0의 결과 T(xs,0)=W(xs)는 그 특수 경우입니다. xs의 길이는 감소하지만 a는 바뀌므로 귀납 가정에서 a를 0으로 고정하면 다음 호출의 2a+x에 적용하지 못합니다. 감소 측도와 귀납 명제의 양화 범위는 따로 정합니다.

꼬리 길이를 m이라 하면 귀납 가정을 2a+x에 대입해 T(xs,2a+x)=2^m(2a+x)+W(xs)를 얻습니다. 분배하면 2^(m+1)a+2^m x+W(xs)이고 W의 정의로 원하는 생성자 결과가 됩니다. 기저에서는 a=2^0a+0입니다. 처음 원소의 가중치가 마지막 원소보다 크며, 뒤집기나 합계만으로 이 명세를 바꿀 수 없습니다.

먼저 확인할 개념
  • 변하는 누적 인자의 일반화

    앞 본문의 임의 acc 가정을 임의 정수 a에 대한 새 가중 명세로 옮깁니다.

  • 정의와 보조 근거의 분리

    W의 재귀 정의와 지수 분배를 각각 명시해 귀납 단계의 등식 근거를 추적합니다.

정의·명세·종료의 세 줄

누적 뒤집기 A([],acc)=acc, A(x::xs,acc)=A(xs,x::acc)로 정의한다. xs 는 처리 전 남은 목록, acc 는 앞에서 처리한 부분을 거꾸로 모아 놓은 목록이다. 입력은 유한 목록이고 원소에 연산 부작용이 없는 수학적 모형이다. 실제 메모리 배치나 특정 언어의 꼬리 호출 최적화는 가정하지 않는다.

각 호출에서 xs 의 길이가 1 감소하므로 비음수 정수 측도 len(xs)에 의해 종료한다. 종료했다고 결과가 원하는 값이라는 뜻은 아니다. 정확성 명세로 모든 xs,acc 에 대해 A(xs,acc)=rev(xs)++acc 를 따로 정한다. 원하는 외부 함수 A(xs,[])의 올바름은 이 더 일반적인 정리의 특수 경우다.

가정을 충분히 일반화하기

A(xs,[])만을 귀납 가정으로 두면 다음 호출 A(xs,x::[])를 다루지 못한다. 증명 시작부터 임의 acc 를 남겨 A(xs,acc)=rev(xs)++acc 가 모든 acc 에 참이라는 귀납 가정을 둔다. xs 는 작아지지만 acc 는 커지므로 두 인자를 동시에 더 작은 것으로 생각해서도 안 된다. 감소 측도와 양화 범위는 서로 다른 역할이다.

기저는 A([],acc)=acc=[]++acc=rev([])++acc 다. 생성자에서 A(x::xs,acc)=A(xs,x::acc)=rev(xs)++(x::acc)다. 여기서 둘째 줄은 귀납 가정을 acc 대신 x::acc 에 대입한 결과다. acc 를 []에 고정한 약한 가정으로는 이 대입이 허용되지 않는다.

어떤 정의와 정리로 끝내는가

x::acc=[x]++acc 이므로 rev(xs)++(x::acc)=rev(xs)++([x]++acc)=(rev(xs)++[x])++acc=rev(x::xs)++acc 다. 가운데는 이미 따로 증명한 연결 결합법칙이며 마지막은 rev 정의다. 모든 등식의 방향과 괄호를 기록하면 결합법칙을 교환법칙으로 오인하지 않는다. 연결은 순서를 보존하므로 일반적으로 u++v=v++u 가 아니다.

acc=[]를 대입하고 오른쪽 단위 정리 u++[]=u 를 쓰면 A(xs,[])=rev(xs)다. 이 종이 증명은 함수의 수학적 정의에 대한 보장이다. 특정 언어 번역의 문법·정수 제한·예외·메모리 실패·실제 성능이나 Rocq 인증 파일의 성공 실행까지 검증한 것으로 표시하지 않는다.
