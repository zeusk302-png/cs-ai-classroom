소단원 6.1

UART·SPI·I2C

직렬 선 몇 개만 이어 놓으면 세 통신 방식이 서로 바뀌어 쓰일까?

준비 개념과 학습 목표

준비 개념

  • 직렬 전송은 비트를 시간 순서대로 보낸다. 비트율과 유효 데이터율은 다르다.

  • clock은 비트를 언제 읽는 지 정하는 기준이다. 주소와 장치 선택은 받는 대상을 정한다.

학습 목표

  • 세 방식의 시간 기준과 대상 선택을 구별한다.

  • 일반 8N1 UART· 8 비트 SPI·7 비트 I2C의 자체 시간을 계산한다.

데이터 두 바이트를 읽으면 선로에서도 두 바이트만 오갈까요?

새 I2C 종이 장치는 7비트 주소 0x35에 있으며, 한 바이트 레지스터 번호를 쓴 뒤 반복 START와 읽기 주소를 보내면 연속 레지스터 자료를 돌려준다. 자료를 하나 읽을 때마다 내부 번호가 하나 증가한다고 별도로 지정한다. 두 바이트 읽기는 쓰기 주소·레지스터 번호·읽기 주소·자료 두 개로 총 다섯 바이트다. 각 바이트의 아홉 번째 클록에는 ACK 또는 NACK이 있으며, 마지막 자료의 NACK도 클록을 차지한다. 자동 증가와 레지스터 형식은 이 가상 장치의 규칙이며 모든 I2C 장치의 기본 기능이 아니다.

SCL을 400 kHz로 고정하고 START·반복 START·STOP의 별도 시간, clock stretching, 버스 대기와 소프트웨어 비용을 제외한 클록 부분만 계산한다. 한 번에 두 바이트를 읽으면 5×9=45클록으로 112.5 µs다. 각 레지스터를 독립적인 한 바이트 읽기로 처리하면 한 번마다 주소 두 개·번호 한 개·자료 한 개로 36클록이며 두 번 합은 72클록, 180 µs다. 자료 수가 같아도 거래를 나누는 방식에 따라 주소와 명령의 반복 비용이 달라진다.

별도 SPI 종이 장치는 CS가 내려갈 때 바이트 위치를 0으로 초기화한다. 한 번 CS를 유지한 네 바이트 전송에서 위치 0은 명령, 위치 1은 dummy, 위치 2와 3은 자료 읽기다. MISO의 처음 두 바이트는 유효 자료가 아니라고 지정한다. 1 MHz에서 총 32클록, 32 µs를 사용하여 자료 두 바이트를 얻는다. 동시에 MOSI와 MISO가 움직인다고 명령·dummy가 사라지지 않는다. 바이트마다 CS를 올렸다 내리면 각 바이트가 모두 위치 0이 되어 이 장치의 두 자료를 얻지 못한다.

  • 마지막 NACK와 기다림

UART는 시작과 약속된 속도에 의존한다

UART의 비동기 전송은 보통 데이터 선과 별도 공유 clock 선 없이 시작 비트로 프레임을 맞춘다. 양쪽 baud와 데이터 길이· 패리티· 정지 비트 약속이 맞아야한다. 이 예는 payload8 비트, parity 없음, stop1의 8N1이고 LSB 먼저 보낸다고 정한다.

idle은 1, start는 0이다. byte의 8 데이터와 stop1을 더하면 총 10 비트다. UART 그 자체가 네트워크 주소나 메시지 길이를 정의해 주지는 않는다. 상위 규칙에서 어느 명령인지, 몇 byte인지와 오류 후 재동기화를 정할 수 있다.

SPI는 clock과 선택 신호를 공유한다

자체 SPI 예는 controller가 clock을 만들고 하나의 chip-select로 target을 고르는 4 선 full-duplex 구성이다. 8clock 동안 한 쪽이 8 비트를 보낼 때 다른 쪽에서도 8 비트를 받을 수 있다. 일반적으로 전송 방향당 시간이 따로 두 배로 드는 것은 아니다.

CPOL은 clock의 쉬는 수준, CPHA는 샘플링 edge 선택과 관련된다. 데이터 순서와 select 유지 범위도 장치 약속에 맞춘다. SPI 일반형의 전송에 UART start/stop이나 I2C ACK가 자동으로 붙는다고 가정하지 않는다. 장치별 추가 명령· 대기 시간이 있을 수 있다.

I2C는 공유 clock과 주소를 쓴다

이 예의 I2C는 일반 7 비트 주소 Standard/Fast 모드다. SDA 데이터와 SCL clock을 공유하고 START 뒤 주소 7 비트와 R/W1 비트를 보낸다. 각 8 비트 뒤 9번째 clock은 ACK/NACK다. 여러 장치는 서로 다른 주소 등 구별 방안이 필요하다.

데이터는 일반 비트 전송의 SCL 높은 동안 안정되어야한다. 그동안 SDA가 변하는 START/STOP은 별도 신호다. pull-up과 전압 조건·clock stretch 가능성까지 고려해야하므로 선의 이름만 보고 같은 전기 인터페이스라고 간주하지 않는다.

CS를 유지하는 지정 거래가 필요하다.

각 거래에서 실제 선로에 나가는 바이트를 순서대로 쓰고, 각 I2C 바이트마다 아홉 번째 클록을 포함한다. SPI에서는 동시에 받은 바이트 중 무엇이 유효한 자료인지 장치 규칙으로 표시한다.

중간 과정을 따라가는 예제

4 payload byte의 전송 시간을 비교하라. UART8N1 9600bit/s, SPI1MHz8 비트 연속 4byte, I2C100kHz 주소 1byte +데이터 4byte이며 stretch/START/STOP 추가 시간은 제외한다.

  1. UART는 4×10 =40비트이고40/9600초 =25/6ms ≈4.167ms다.

  2. SPI는 4×8 =32clock이고32/10⁶초 =32 μs다. 동시에 받는 데이터가 있어도 해당 32clock을 공유한다.

  3. I2C는 주소 포함 5byte마다 9clock으로 45clock이다.

  4. 45/100000초 =450 μs다. 이는 부가 시간과 대기/clock stretch를 뺀 전송 부분 계산이다.

UART 약 4.167ms, SPI32 μs, I2C450 μs. 조건을 뺀 원시 전송 시간이며 실측이 아니다.

같은 자료 수와 다른 주소 반복

지정 I2C 장치에서 연속 두 바이트 읽기와 독립 한 바이트 읽기 두 번의 클록 수와 클록 부분 시간을 비교하라.

  1. 연속 읽기는 주소·번호·주소·자료 두 개의 다섯 바이트에 각각 9클록을 쓴다.

  2. 독립 읽기는 한 번에 네 바이트로 36클록이며 두 번 합은 72클록이다. 400 kHz의 한 클록은 2.5 µs다.

연속 읽기는 112.5 µs, 독립 두 번은 180 µs로 클록 부분의 차이는 67.5 µs다.

이 값은 START·STOP·대기 비용을 뺀 모형이며 실제 응답 시간이나 모든 장치의 burst 지원을 인증하지 않는다.

네 바이트를 받았지만 자료는 두 바이트

SPI 장치가 한 번 CS를 내린 네 바이트 거래의 MISO를 [0xEE,0xFF,0x12,0x34]로 보낸다. 자료와 시간, 바이트별 CS 재시작의 결과를 구하라.

  1. 유효 위치는 2와 3이므로 0x12와 0x34를 채택한다. 처음 두 값은 버린다.

  2. 8비트 네 번은 32클록이며 1 MHz에서 32 µs다. 바이트마다 재시작하면 네 바이트 모두 명령 위치가 된다.

유효 자료는 [0x12,0x34]이고 거래의 클록 시간은 32 µs다. 지정 바이트별 CS 재시작으로는 이 자료를 얻지 못한다.

비교할 점

전이중은 방향의 동시성을 나타내며 응용 명령 형식과 CS 경계를 대신 정하지 않는다.

연습 1 · 값과 상태 예측

지정 I2C 장치에서 연속 자료 수만 세 바이트로 바꾼다. 400 kHz에서 클록 수와 클록 부분 시간, 마지막 자료의 응답을 구하라.

힌트 1

주소 두 개와 레지스터 번호 한 개를 유지한다.

힌트 2

자료 세 개에도 각각 ACK 또는 NACK의 아홉 번째 클록을 센다.

풀이와 답 확인

  1. 총 바이트 수는 2+1+3=6개다. 따라서 클록 수는 54개다.

  2. 54×2.5 µs는 135 µs이며 마지막 자료에는 읽기를 끝내는 NACK을 보낸다.

클록 수는 54개, 클록 부분 시간은 135 µs다. 마지막 자료의 NACK 클록을 포함한다.

흔한 오답에서 다시 생각하기

마지막 NACK은 오류이므로 해당 바이트와 클록을 빼야 한다.

정상 마지막 읽기의 NACK도 아홉 번째 클록에서 전달된다.

연습 2 · 오류 찾아 고치기

API A는 7비트 주소를 받으며 내부에서 방향 비트를 붙인다고 지정한다. 장치 주소 0x35 대신 쓰기 주소 바이트 0x6A를 API A에 넘긴 오류를 고쳐라.

힌트 1

주소 값과 선로의 주소 바이트를 구별한다.

힌트 2

이 API의 입력 계약을 먼저 적용한다.

풀이와 답 확인

  1. API A의 입력은 0x35여야 한다. 선로의 쓰기 바이트는 0x35를 왼쪽으로 한 칸 옮긴 0x6A다.

  2. 0x6A를 넘기면 이 API는 그것을 다른 7비트 주소로 해석한다. 읽기에는 별도 방향 비트를 붙여 0x6B를 만든다.

API A에 0x35를 넘긴다. 쓰기 0x6A와 읽기 0x6B는 선로 표현이며 API 입력과 다르다.

흔한 오답에서 다시 생각하기

모든 라이브러리는 주소를 반드시 한 번 이동한 값으로 받는다.

API마다 입력 표현이 다를 수 있으므로 지정 계약이나 실제 문서를 확인해야 한다.

연습 3 · 직접 만들어 보기

지정 SPI 장치의 자료 두 바이트를 얻는 거래를 만들어라. CS의 경계, 네 바이트의 역할, MISO 채택 위치를 적되 dummy 값을 장치 공통 규칙이라고 주장하지 마라.

힌트 1

CS를 한 번 내리고 네 바이트 동안 유지한다.

힌트 2

위치 0과 1의 응답은 유효 자료가 아니다.

풀이와 답 확인

  1. CS를 내린 뒤 지정 명령 한 바이트와 이 장치가 허용하는 dummy 한 바이트를 보내고 이어 두 바이트를 클록한다.

  2. 네 바이트 뒤 CS를 올린다. MISO의 위치 2와 3만 자료로 채택한다.

한 거래의 역할은 명령·dummy·자료 읽기·자료 읽기다. 32클록을 쓰며 유효 응답은 마지막 두 바이트다.

흔한 오답에서 다시 생각하기

MISO가 매번 나오므로 첫 두 바이트도 같은 레지스터 자료다.

이 장치의 응답 위치 계약에서 처음 두 바이트는 유효 자료가 아니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 비용 모형에서 I2C 거래 한 번마다 클록 외 비용이 h µs이며 h≥0이다. 두 바이트 연속 읽기는 한 거래, 독립 읽기는 두 거래다. 전체 비용 차이와 연속 읽기가 더 빠른 조건을 구하라.

힌트 1

각 정책의 거래 수에 h를 곱한다.

힌트 2

준비 개념과 학습 목표

준비 개념

  • 짝수 패리티는 데이터와 parity bit에 있는 1의 총 수를 짝수로 만든다.

  • 프레임 오류와 수신 버퍼 overrun은 서로 다른 실패다.

학습 목표

  • 프레임 길이· 샘플 시각을 계산한다.

  • 패리티의 검출 한계와 ACK/NACK 의미를 구별한다.

표본 시각이 조금씩 밀리면 마지막 비트에서 어떤 조건이 필요할까요?

새 이상 수신 모형은 송신 8N1 한 프레임의 시작을 0, 송신 비트 주기를 T로 둔다. start는 [0,T), 데이터 여덟 개는 [T,9T), stop은 [9T,10T)다. 수신 비트 주기는 αT이며 α>0이다. 시작 검출 시각의 오차를 δT로 두면 stop 표본 시각은 (δ+9.5α)T다. 각 비트의 가운데를 한 번만 읽고 비트 경계에서의 판정은 보장하지 않는다고 지정한다. 실제 USART의 oversampling·다수결·동기화·전기적 여유와 다르다.

시작 오차가 0이면 stop 내부 조건은 9<9.5α<10이므로 18/19<α<20/19다. 시작 오차를 −0.1≤δ≤0.1로 허용하면서 모든 δ에서 stop 내부를 보장하려면 가장 이른 표본과 늦은 표본을 함께 검사한다. −0.1+9.5α>9이고 0.1+9.5α<10이어야 하므로 91/95<α<99/95다. 경계 값은 제외한다. 이는 주기의 비율 범위다. 수신 baud 비율은 1/α이므로 같은 숫자의 대칭 범위로 바꾸어 쓰지 않는다.

시간 조건과 오류 검출 조건은 따로 본다. 별도 짝수 parity 프레임은 자료 0x01과 parity 1을 보낸다. 자료의 1인 최하위 비트와 parity 비트가 모두 반전되면 자료는 0x00, parity는 0이며 짝수 검사를 통과해도 자료가 달라진다. 별도 두 바이트 XOR 검사는 [0x12,0x34]의 검사값이 0x26이다. 양쪽 자료의 같은 비트 0x01을 뒤집은 [0x13,0x35]도 검사값이 0x26이다. 이 검사는 특정 오류를 검출하며 모든 손상·누락·재전송 중복을 보장하지 않는다.

먼저 확인할 개념
  • 표본 시각과 parity의 경계

    비트 가운데 표본의 전제와 검출하지 못하는 다중 오류를 분리한다.

  • 8N1과 baud의 시간 단위

    송신 비트 주기와 수신 비트 주기, 자료와 프레임 길이를 연결한다.

프레임 경계를 먼저 계산한다

자체 일반 8E1은 payload8· 짝수 parity1·start1·stop1이라 11 비트다. 실제 STM32의 word length 설정에서는 parity를 데이터 길이에 포함하는 규칙이 있으므로 8E1 payload를 원하면 해당 장치 설정 의미를 확인한다. 이름을 register 값과 즉시 동일시하지 않는다.

0x35는 이진 00110101로 1이 4개다. LSB부터 10101100을 보내고 짝수 parity는 0이다. start0과 stop1은 데이터의 1 개수에 넣지 않는다. parity는 데이터 8과 parity1 사이의 규칙이다.

속도 오차와 샘플링

baud B의 한 비트 길이는 1/B다. 수신자가 start edge를 기준으로 각 비트 중앙을 읽는 단순 모형에서는 첫 데이터 중앙이 1.5/B에 있다. 실제 주변 장치의 oversampling은 더 복잡하므로 이 그림은 시간 오차의 직관이다.

양쪽 clock이 다르면 뒤쪽 샘플일수록 중심에서 벗어난다. 반면 frame이 끝날 때 새로운 start에 다시 맞출 수 있다. 특정 칩의 허용 오차를 이 단순 그림으로 확정하지 말고 baud·oversampling· 프레임 길이 규격을 확인한다.

실패 종류와 메시지 검증

짝수 parity는 홀수 개 비트 반전을 검출하지만 데이터 두 비트가 뒤집히면 1의 총수 홀짝이 유지될 수 있다. stop 위치가 기대한 1이 아니면 framing 오류, 새 데이터가 오는 데 이전 데이터 보관 여유가 없으면 overrun이다. 각각 복구 원인이 다르다.

I2C NACK도 항상 잡음 오류를 뜻하지 않는다. 주소 대상 부재· 수신 준비 안 됨 외에 controller가 읽기 마지막 byte를 NACK하여 정상 종료할 수 있다. 전송 완료와 응용 명령의 유효성은 길이· 검사합· 순번 등 상위 규칙으로 따로 판단한다.

두 반전 뒤 통과하는 검사

0x01과 parity 1의 짝수 프레임에서 자료의 1인 비트와 parity를 모두 뒤집는다. 별도 XOR 자료 [0x12,0x34]에는 두 바이트 모두 0x01을 XOR한다. 검사와 자료를 비교하라.

  1. 짝수 parity 사례의 원래 전체 1 수는 2개이며 바뀐 전체 1 수는 0개다. 두 경우 모두 짝수다.

두 검사 모두 통과하지만 parity 자료는 0x00으로, XOR 자료는 [0x13,0x35]로 바뀌었다.

수신 함수가 2byte를 돌려주면 그것이 한 명령의 끝이라는 뜻일까?

준비 개념과 학습 목표

준비 개념

  • FIFO는 먼저 들어 온 데이터를 먼저 꺼낸다. 부분 반환은 요청보다 적게 처리할 수 있다는 뜻이다.

  • 비동기 요청의 버퍼는 장치가 사용하는 동안 유효하게 유지해야 한다.

학습 목표

  • 생산· 소비와 수신 분할을 종이로 추적한다.

  • 복사 완료· 송신 완료· 메시지 완료를 구별한다.

빈 공간을 확보한 순간부터 다른 쪽이 그 자료를 읽어도 될까요?

새 원형 버퍼는 바이트를 하나씩 담는 여섯 칸이며 읽기 위치 r=2, 쓰기 위치 w=5, 공개된 자료 수 count=3이다. 칸 2,3,4에는 B,C,D가 있다. 총 빈 공간은 세 칸이지만 쓰기 위치 5부터 배열 끝까지 이어진 빈 구간은 한 칸뿐이다. 생산자는 연속 구간을 예약하고 쓰며, commit이라는 지정 공개 단계 뒤에만 소비자가 읽을 수 있다. 이는 소유권을 배우는 추상 계약이며 실제 Zephyr 함수 호출이나 동시에 바뀌는 공유 count 구현이 아니다.

첫 예약 한 칸에 X를 써도 공개 전 count는 3으로 소비자는 B,C,D만 읽을 수 있다. 한 칸을 공개하면 w=0, count=4가 되고 다음 연속 빈 두 칸에 Y,Z를 쓸 수 있다. 이를 공개하면 w=2, r=2, count=6이며 논리 FIFO는 B,C,D,X,Y,Z다. 쓰기와 읽기 위치가 같다는 사실만으로 비었다고 판단하지 않는다. 예약한 비공개 자료를 읽게 하거나 배열 끝을 넘어 총 빈 공간만큼 연속 DMA를 허용하면 서로 다른 오류를 만든다.

별도 비동기 송신 모형은 호출 때 복사하지 않으며 DMA가 1 ms와 2 ms에 버퍼의 첫째·둘째 바이트를 읽는다. 초기 버퍼는 A,B이고 호출은 0 ms에 돌아온다. 0.5 ms에 X,Y로 덮으면 DMA는 X,Y를 읽는다. 1.5 ms의 송신 레지스터 빈 표시도 둘째 바이트를 아직 읽지 않은 시각이므로 버퍼 반환 근거가 아니다. 이 모형의 버퍼 읽기 완료 알림은 2 ms, 마지막 stop 종료는 3 ms, 상대 응용 확인은 5 ms라고 따로 지정한다. 메모리 반환·선로 완료·상대 처리 완료는 각각 다른 조건이다.

byte 스트림과 응용 메시지

드라이버 수신 결과의 경계는 상위 메시지 경계와 같지 않을 수 있다. 길이와 payload를 읽는 parser는 한 호출에 완전한 메시지가 오지 않아도 상태를 유지해야 한다. 두 메시지가 한 번에 올 수도 있으므로 초과 byte도 보존한다.

자체 메시지 규칙은 첫 byte가 다음 payload 길이 0..3이고 그 길이만큼 모은 뒤 하나의 메시지를 내놓는 것이다. 이런 작은 규칙조차 길이 검증· 중단· 재동기화 정책이 필요하다. 실제 통신 프로토콜과 같다고 주장하지 않는다.

고정 용량의 순환 큐

자체 4 칸 큐는 read/write 인덱스와 별도 count를 쓴다. 쓰면 write를(mod4) 이동하고 count를 늘리며, 읽으면 read를 이동하고 count를 줄인다. count0은 빈 큐,count4는 가득 찬 큐다. 칸 하나를 비워 두는 다른 구현과 용량 공식을 혼동하지 않는다.

가득 찼을 때 여기서는 새 byte를 거부하고 오류를 남긴다. 오래된 byte를 덮어 쓰는 정책도 가능하지만 수신 메시지를 손상할 수 있어 선택을 명시해야 한다. 부분 put/get의 실제 반환 수를 확인하여 받은 수와 저장한 수의 차이를 처리한다.

소유권과 동기화

Zephyr 문서의 단일 생산자· 단일 소비자 조건과 다른 CPU에서 가시성을 보장하는 동기화를 확인한다. 여러 생산자/ 소비자에는 외부 직렬화가 필요할 수 있다. 자체 count는 둘이 함께 수정하므로 Zephyr의 분리 인덱스 구현을 근거로 그대로 lock-free라고 선언하지 않는다.

비동기 송신에서 함수 반환은 요청을 맡겼다는 뜻일 수 있어 버퍼를 바로 재사용하면 안 된다. STM32의 TX register empty와 transmission complete도 구별된다. 선에서 마지막 stop가 나간 완료· 드라이버가 메모리를 놓는 시점· 상대 응용의 처리 완료는 서로 다를 수 있다.

거래 클록·수신 표본·버퍼 소유권 연결하기

서로 독립인 세 모형을 분석하라. 첫째는 위 I2C 장치에서 두 바이트 연속 읽기를 수행하며 SCL은 400 kHz다. 클록 수와 클록 부분 시간을 구하고 마지막 NACK을 포함하라. 둘째는 8N1 단일 표본 모형의 α=1.04, 시작 오차 δ∈[−0.1,0.1]이다. stop의 가장 이른 시각과 늦은 시각, 내부 보장 여부를 구하라. 셋째는 여섯 칸 버퍼의 r=2,w=5,count=3에 B,C,D가 있으며 X,Y,Z를 소비 없이 두 연속 구간으로 쓰고 공개한다. 각 공개 뒤의 위치·count와 최종 FIFO를 적어라. 어떤 버스·USART·DMA 프로그램도 실행하지 않는다.

힌트 1

주소·명령·자료의 클록을 모두 세되 추가 지연을 전체 시간으로 숨기지 않는다.

힌트 2

표본 범위와 예약·공개의 최악 경우를 각각 계산한다.

풀이와 답 확인

  1. I2C는 주소 두 개·번호 한 개·자료 두 개의 다섯 바이트에 각각 9클록을 써서 45클록이다. 400 kHz의 클록 부분 시간은 112.5 µs다.

  2. stop 중심 항은 9.5×1.04=9.88이다. 가장 이른 표본은 9.78T, 가장 늦은 표본은 9.98T로 둘 다 (9T,10T) 내부다.

  3. 칸 5에 X를 쓰고 한 칸을 공개하면 r=2, w=0, count=4다. 다음 칸 0과 1에 Y,Z를 쓰고 공개하면 r=2, w=2, count=6이다.

  4. 최종 FIFO는 B,C,D,X,Y,Z다. 같은 읽기·쓰기 위치는 여기서 빈 상태가 아니며 count=6인 가득 찬 상태다.

I2C는 45클록으로 클록 부분 112.5 µs다. stop 표본 범위는 [9.78T,9.98T]로 지정 비트 내부다. 첫 공개 뒤 쓰기 위치는 0이고 count는 4, 둘째 공개 뒤 쓰기 위치는 2이고 count는 6이며 FIFO는 B,C,D,X,Y,Z다.

  • 마지막 NACK 클록과 반복 주소를 포함하고 START·STOP 등의 추가 시간을 제외한 범위를 명시한다.

  • 주기와 baud의 비율을 구별하고 경계 표본 성공을 주장하지 않는다.

  • 예약 구간의 길이 1과 2, 공개 단계와 최종 count를 각각 기록한다.

  • 손으로 만든 장부와 실제 버스·DMA·드라이버·학생 실행 미수행을 구별한다.
