소단원 3.1

툴체인·빌드·플래시

노트북에서 만든 프로그램을 작은 보드에 넣으면 왜 그대로 실행되지 않을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 기계어는 CPU가 해석하는 명령 표현이며 아키텍처와 ABI가 맞아야 한다.

  • 16진수 주소의 마지막 위치는 시작+길이−1이다.

  • 코드·초깃값 있는 데이터·영 초기화 데이터가 차지하는 공간을 구분한다.

학습 목표

  • 교차 툴체인의 역할과 산출물을 연결한다.

  • 메모리 배치와 장치 기록을 서로 다른 검증 단계로 설명한다.

새 이미지 바이트가 모두 맞아도 옆의 설정값은 사라질 수 있을까요?

기본의 빌드·링크·기록 구분을 새 가상 NOR 배치에 적용한다. 뱅크 안의 주소는 뱅크 시작에서 센 바이트 오프셋이고 삭제 블록은 0x400 바이트, 즉 1 KiB다. 새 이미지의 시작은 0x380이고 길이는 0x500 바이트, 즉 1,280바이트다. 따라서 이미지 구간은 [0x380,0x880)이다. 여기서는 이 구간과 겹친 블록 전체만 삭제한 뒤 이미지 바이트만 쓰는 절차를 지정한다. 삭제는 블록의 모든 비트를 1로 만들고 쓰기는 1을 0으로 바꿀 수 있는 종이 모형이다. 실제 장치의 보호·쓰기 정렬·전원 실패 계약은 이 모형에 포함하지 않는다. 모든 삭제·쓰기의 완료와 읽기 성공, 다른 주체의 변경 없음은 지정 조건이다.

겹친 블록은 [0,0x400), [0x400,0x800), [0x800,0xC00)의 세 개다. 총 3,072바이트가 삭제되어 이미지 밖의 1,792바이트도 영향을 받는다. 오프셋 0x100과 0x900에 각각 0x12와 0x34라는 보존 설정이 있었다면 둘 다 0xFF가 된다. 이미지의 1,280바이트를 다시 읽어 새 파일과 비교하면 전부 맞을 수 있지만 이 검사는 두 설정 위치를 포함하지 않는다. 부분 비교의 성공을 보존 영역의 성공으로 확장하지 않는다.

이 모형에서 보존하려면 삭제 전 세 블록의 원래 3,072바이트를 보관하고, 그 복사본의 이미지 구간만 새 바이트로 바꾼 뒤, 세 블록을 삭제하고 패치된 전체 내용을 다시 쓴다. 이미지 밖의 데이터가 처음 저장되어 있어야 이 복원이 가능하다. 삭제 이후 0xFF만 읽어서 원래 0x12와 0x34를 알아낼 수는 없다. 또한 올바른 이미지 기록과 올바른 디버그 정보 사용은 별도 조건이다. 같은 파일 이름이라도 다른 빌드의 심볼 지도를 붙이면 소스 줄 해석은 잘못될 수 있다. 빌드 식별자와 내용 해시, 기록 범위 및 보존 범위를 함께 기록한다.

먼저 확인할 개념
  • 이미지 영역과 기록 절차

    바이트 비교가 검사한 주소 범위와 삭제 단위의 영향을 구별한다.

  • 실행 이미지와 디버그 정보

    소스 줄의 해석에는 같은 빌드의 바이너리와 디버그 정보가 필요하다.

누가 도구를 실행하고 누가 결과를 실행하는가

펌웨어 개발 PC는 컴파일러를 실행하고 타깃 보드는 컴파일러가 만든 기계어를 실행한다. PC용 실행 파일을 MCU에 복사한다고 MCU용 명령이 되지는 않는다. CPU 명령 집합, 부동소수점 ABI, 라이브러리, 보드의 시작 코드와 메모리 지도가 함께 맞아야 한다. 타깃 이름이 같은 제품 계열이라고 모든 보드 설정이 같은 것은 아니다.

GCC 자체를 구성하는 공식 용어에서 build는 GCC를 빌드하는 머신, host는 그 GCC 실행 파일이 돌아가는 머신, target은 GCC가 코드를 생성할 머신이다. 일상적인 펌웨어 개발에서 개발 PC를 host라고도 부르지만 이 두 문맥을 섞지 않는다. 예를 들어 PC에서 돌아가는 ARM용 컴파일러는 PC에서 실행되면서 ARM 코드를 만들 수 있다.

단계를 나누면 오류 위치가 보인다

전처리는 include와 매크로 등을 처리하고 컴파일은 소스를 어셈블리 수준으로 변환하며 어셈블은 객체 파일을 만든다. 링크는 객체·라이브러리의 심볼을 연결하고 주소를 배치한다. GCC의 -E,-S,-c는 각각 다른 단계에서 멈추는 옵션이다. 객체 파일에 함수 코드가 있어도 다른 객체의 함수 주소가 아직 해결되지 않을 수 있다.

링커 스크립트는 입력 섹션을 출력 메모리에 배치한다. .text나 읽기 전용 값, RAM에서 사용할 .data와 .bss의 역할을 보드 시작 코드와 함께 정해야 한다. .data의 RAM 초기값을 flash에 보관한 뒤 시작 코드가 복사하는 설계에서는 실행 주소와 보관 주소가 다르다. .bss도 실행할 때 RAM을 차지하며 파일에 영값 전체를 그대로 저장하지 않는 보통 설계와 구별한다.

이미지 기록과 실행 성공은 별도다

ELF는 섹션·주소·심볼·디버그 정보를 가진 형식이며 raw binary에는 대체로 그러한 메타정보가 없어 기록 시작 주소를 별도로 알아야 한다. flash 기록에는 보드 설정, 지우기 단위, 기록할 영역과 주소가 필요하다. NOR flash의 지우기와 쓰기는 RAM 대입과 다르게 동작하므로 링크 배치가 맞아도 기록 절차를 검증해야 한다.

빌드 성공은 문법·링크 조건을 통과했다는 증거다. 기록 후 read-back 비교는 해당 영역의 바이트 일치를 확인하지만 전원·리셋·벡터 테이블·주변장치·스택·실시간 동작이 올바른지까지 증명하지 않는다. 아래 활동은 메모리 수용 여부만 계산하며 실제 장치 기록 명령은 실행하지 않는다.

새 이미지 바이트가 모두 맞아도 옆의 설정값은 사라질 수 있을까요?
지정 조건추적 결과판정 범위

이미지 [0x380,0x880)

길이는 1,280바이트다.

끝 주소 0x880은 포함하지 않는다.

겹친 삭제 블록 세 개

삭제 구간은 [0,0xC00)이며 3,072바이트다.

이미지 밖의 영향은 1,792바이트다.

설정 오프셋 0x100·0x900

이미지만 다시 쓰면 두 설정은 0xFF다.

이미지 비교에는 두 설정이 없다.

삭제 전 전체 블록 복사본

이미지 구간만 패치하고 전체를 복원한다.

전원 실패 안전성까지 증명한 절차는 아니다.

반열린 이미지 범위를 먼저 쓰고, 그 범위를 덮는 삭제 블록의 합집합을 그린다. 이미지 비교 범위와 원래 값의 보존 범위를 각각 표시한다.

중간 과정을 따라가는 예제

가상 보드 flash 64KiB, RAM 16KiB다. .text·rodata 합40KiB, .data 4KiB는 flash 초기값과 RAM 복사본 모두 필요하다. .bss 6KiB, 예약 stack 3KiB, heap 2KiB다. 정렬·추가 영역은0으로 가정하고 수용 여부를 계산하라.

  1. flash에는40+4=44KiB가 필요해 여유64−44=20KiB다. .data를 RAM만 계산하면 초기값 보관을 빠뜨린다.

  2. RAM에는4+6+3+2=15KiB가 필요해 여유1KiB다. .bss는 파일 기록 크기가 작아도 RAM에서6KiB를 차지한다.

  3. stack 예약을5KiB로 바꾸면 RAM4+6+5+2=17KiB라1KiB 초과한다.

  4. 현재15KiB는 가정한 정적 배치가 들어간다는 뜻이며 실제 stack 최고 사용량·heap 파편화·추가 런타임 자료까지 충분하다는 증명은 아니다.

가정한 원래 배치는 flash44/RAM15KiB로 수용 가능하고 stack5KiB 변경은 RAM 초과다.

조건을 바꾸어 비교하기

두 설정은 이미지 밖이지만 삭제 안이다

지정 세 블록을 삭제한 뒤 [0x380,0x880)의 이미지 바이트만 썼다. 원래 0x100의 0x12와 0x900의 0x34는 어떻게 되는가?

  1. 두 위치 모두 삭제 구간 [0,0xC00)에 들어간다.

  2. 이미지 밖이므로 다시 쓰지 않아 두 값 모두 0xFF다.

두 설정값이 사라지며 이미지 바이트 비교는 성공할 수 있다.

비교할 점

쓰기 범위 밖이라는 사실은 삭제 영향 밖이라는 뜻이 아니다.

경계 정렬은 초과 삭제를 줄인다

같은 길이 0x500 바이트의 이미지를 오프셋 0x400에서 시작하면 삭제량과 이미지 밖 영향량은?

  1. 이미지 구간은 [0x400,0x900)이며 블록 [0x400,0x800), [0x800,0xC00)와 겹친다.

  2. 삭제량은 2,048바이트이고 이미지 밖 영향량은 2,048−1,280=768바이트다.

삭제 블록은 두 개지만 마지막 블록의 이미지 밖 768바이트는 여전히 영향받는다.

비교할 점

시작 경계 정렬만으로 마지막 블록의 보존 문제가 모두 없어지지는 않는다.

종이와 본문으로 직접 해보기

flash 시작0x08000000, 길이64KiB인 가상 영역의 끝 주소를 적어라. 다른 모든 바이트를 덮지 않는다고 가정할 때 0x08001000에서 크기0x3000인 이미지는 어디까지인가? .data 초기값을 빼면 왜 판단이 달라지는가?

힌트 보기

64KiB=0x10000이다. 끝 주소에는 길이에서1을 뺀 값을 더한다.

풀이 보기

flash 끝은0x0800FFFF, 이미지 끝은0x08003FFF다. 해당 이미지 주소 범위는 영역 안이다. 하지만 시작 코드·벡터·다른 예약 영역과 충돌 여부는 별도다. .data 초기값4KiB를 빼고40KiB로만 계산하면 실제 flash 요구44KiB를4KiB 과소평가한다.

오해와 반례

컴파일과 플래시 기록이 성공하면 보드에서 정상 동작이 검증된 것이다.

잘못된 시작 주소나 RAM 배치를 가진 이미지도 파일로 생성할 수 있다. 기록된 바이트가 맞아도 리셋 뒤 올바른 명령에서 시작하거나 주변장치를 올바르게 설정하는지는 실행 검증이 필요하다.

연습 1 · 값과 상태 예측

원래 이미지 [0x380,0x880)의 마지막 포함 바이트와 겹친 삭제 블록 수를 구하라.

힌트 1

반열린 끝 주소에서 1을 뺀다.

힌트 2

첫 블록과 마지막 블록의 번호를 구한다.

풀이와 답 확인

  1. 마지막 포함 오프셋은 0x87F다.

  2. 처음 블록 번호는 0이고 마지막은 2이므로 세 블록이다.

마지막 바이트는 0x87F이며 삭제 블록은 세 개다.

흔한 오답에서 다시 생각하기

끝 0x880 자체가 마지막 포함 바이트다.

끝 주소는 제외된다. 다만 0x87F와 0x880은 이 사례에서 같은 블록이어서 블록 수만 확인하면 오류를 놓친다.

연습 2 · 오류 찾아 고치기

이미지의 1,280바이트 read-back 비교가 성공했으므로 보존 설정도 맞다는 보고를 고쳐라.

힌트 1

힌트 2

0x100과 0x900이 그 범위에 있는지 확인한다.

풀이와 답 확인

  1. 보고의 비교 범위는 [0x380,0x880)이다.

  2. 두 설정 위치는 범위 밖이므로 따로 보존값과 대조해야 한다.

이미지 바이트 일치만 확인했다. 설정 보존과 실제 부팅은 별도 미확인 항목이다.

흔한 오답에서 다시 생각하기

파일 비교가 성공하면 뱅크 전체와 실행도 성공이다.

검사하지 않은 주소와 실행 조건까지 결론을 확장했다.

연습 3 · 직접 만들어 보기

삭제 전에 보존 설정을 포함한 세 블록을 읽을 수 있다. 지정 모형에서 이미지와 나머지 원래 바이트를 모두 남기는 계획을 설계하라.

힌트 1

블록 전체 복사본을 먼저 보관한다.

힌트 2

복사본의 이미지 구간만 수정한다.

준비 개념과 학습 목표

준비 개념

  • PC는 현재 실행할 기계 명령 주소를 나타내는 레지스터다.

  • 실행 파일의 심볼·디버그 정보는 주소와 소스 위치의 대응을 돕는다.

  • 관찰할 조건과 정상 동작의 시간표를 분리한다.

학습 목표

  • 디버그 연결 프로토콜과 중단점 동작을 구별한다.

  • 하드웨어 자원·최적화·주변장치 정지의 조건을 설명한다.

한 소스 중단점이 한 하드웨어 슬롯만 사용한다는 보장은 있을까요?

기본의 유한 비교 자원을 새 주소 해석 모형으로 확장한다. 한 소스 위치 요청이 서로 다른 명령 주소 A, B, C의 세 위치로 해석되었다고 지정한다. 이 타깃은 활성 명령 주소 하나당 하드웨어 슬롯 하나를 쓰며 총 두 슬롯만 있고, 소프트웨어 중단점과 다른 슬롯 공유는 없다. 따라서 논리 요청은 하나여도 세 주소를 동시에 활성화할 수 없다. 이 수치는 특정 MCU나 모든 GDB 타깃의 규칙이 아니라 자체 지정 계약이다. 주소 두 개만 선택하면 설치 가능하지만 선택하지 않은 위치도 감시한다고 보고하면 안 된다.

최적화로 원래 변수의 관찰 위치가 없어졌다면 optimized out은 값 0의 관측이 아니다. 이때 실제 값이 0인 이력과 7인 이력이 같은 관찰 불가 표시를 남길 수 있다는 별도 모형을 생각한다. 화면의 관찰 불가 표시만으로 두 이력을 구별할 수 없다. 디버그 정보와 프로그램이 같은 빌드인지, 해당 값이 관찰 가능한 위치에 존재하는지, 어느 기계 주소에서 정지했는지를 순서대로 확인한다. 주소가 아직 해결되지 않은 pending 상태도 이미 해당 주소에서 정지했거나 관찰에 성공했다는 증거가 아니다.

중단의 외부 영향은 별도 시간선으로 확인한다. 새 가상 센서는 2, 4, 6, 8 ms에 ID 1, 2, 3, 4를 차례로 빈 FIFO에 넣는다. FIFO 용량은 세 항목이고 가득 차면 새 항목을 버린다. CPU는 0 ms부터 9 ms 직전까지 멈춰 소비하지 않지만 센서는 계속 동작한다고 지정한다. 따라서 ID 1, 2, 3은 남고 ID 4는 유실된다. CPU만 정지한다는 조건을 센서 전체 정지로 바꾸면 관측 실험도 달라진다. 실제 프로브의 halt 동작은 해당 칩·주변장치 설정을 따로 확인해야 한다.

연결 경로와 디버거 역할

개발 PC의 디버거는 adapter를 통해 타깃의 디버그 기능과 통신한다. JTAG는 TAP 체인을, SWD는 ARM 계열의 DAP 접근을 사용하는 디버그 transport다. 대표 신호는 JTAG의 TCK/TMS/TDI/TDO와 SWD의 SWCLK/SWDIO다. reset·전원·접지 등 보드 연결까지 포함한 실제 핀 수가 이 이름 개수와 같다는 뜻은 아니다.

JTAG가 지원하는 boundary scan은 CPU 명령 중단점과 다른 기능이다. SWD는 신호 선을 줄인 디버그 지향 transport이며 JTAG의 모든 기능을 대체한다고 일반화하지 않는다. 프로브·드라이버·칩·보드 배선이 해당 transport를 모두 지원해야 한다. protocol 이름만 맞아도 아무 MCU에 붙는다는 보장은 없다.

어떻게 특정 주소에서 멈추는가

소프트웨어 중단점은 일반적으로 명령을 trap 명령 등으로 바꾸는 방법을 쓴다. 하드웨어 중단점은 비교 자원으로 지정 주소의 실행을 감지할 수 있어 읽기 전용 코드에서 유용하다. 실제 선택은 타깃 메모리 맵과 debugger 지원에 달려 있다. flash를 수정할 수 있는 특수 구현도 있으므로 모든 flash에서 software breakpoint가 불가능하다고 단정하지 않는다.

하드웨어 비교 자원은 유한하고 칩마다 슬롯 수와 지원 조건이 다르다. 데이터 watchpoint는 읽기·쓰기 접근을 관찰하는 기능이며 명령 주소 breakpoint와 자원을 공유하는지 별도 자료가 필요하다. 임시 중단점은 한 번 멈춘 뒤 제거하도록 정의할 수 있지만 그 순간의 점유 자원까지0이 되는 것은 아니다.

소스 줄과 시간의 함정

최적화는 명령을 제거·병합·재배치하거나 함수를 inline할 수 있다. 소스의 한 줄이 여러 주소에 대응하거나 변수 값이 optimized out으로 보일 수 있다. 이것만으로 프로그램 값이 실제로0이었다고 판단하지 않는다. 디버그 정보와 flash된 바이너리가 같은 빌드인지 먼저 확인한다.

CPU halt 때 timer·DMA·watchdog·외부 장치가 함께 멈추는지는 타깃 설정에 달려 있다. CPU만 멈추면 수신 버퍼가 차거나 watchdog이 reset할 수 있다. 한 명령씩 step하면 정상 실행과 다른 인터럽트·시간 상태가 생긴다. 중단점에서 본 값은 그 중단 실험 조건의 값이며 원래 시스템 시간표의 값을 그대로 증명하지 않는다.

같은 tick 합과 같은 네 표본은 같은 경과 시간을 뜻할까요?

기본의 주파수 환산에 새 두 구간을 둔다. 카운터는 CPU 시계마다 한 tick 증가하고 감김·읽기 비용은 없다고 지정한다. 첫 120 tick은 60 MHz, 다음 120 tick은 30 MHz에서 발생한다. 첫 구간은 2 μs이고 둘째는 4 μs이므로 총 시간은 6 μs다. 총 240 tick을 처음 주파수 60 MHz로 한 번에 나누면 4 μs가 되어 실제 지정 시간보다 2 μs 작다. tick 합을 시간으로 바꾸려면 어느 주파수에서 나온 tick인지 알아야 한다. 전체가 30 MHz였다는 별도 이력은 같은 240 tick으로 8 μs를 만든다.

별도 이상 표본 모형은 정확한 시각 1, 2, 3, 4 μs에서 한 번의 직사각형 펄스를 읽어 낮음, 높음, 높음, 낮음이라는 네 값을 얻는다. 펄스는 상승 시각 r부터 하강 시각 f 직전까지 높으며 한 번만 상승·하강한다고 지정한다. 그러면 r은 (1,2] μs 안에 있고 f는 (3,4] μs 안에 있다. 폭 f−r은 1 μs보다 크고 3 μs보다 작다. 두 높은 표본의 개수를 1 μs 간격과 곱해 폭을 정확히 2 μs라고 정할 수는 없다. 예를 들어 r=1.9 μs, f=3.1 μs의 폭 1.2 μs와 r=1.1 μs, f=3.9 μs의 폭 2.8 μs가 같은 네 표본을 만든다.

이 열린 폭 범위는 표본 시각 오차·잡음이 없고 펄스 하나라는 새 계약에서만 얻는다. 펄스 사이에 추가 전환이 있거나 표본 시각이 흔들리면 이 식을 그대로 쓸 수 없다. 더 촘촘한 표본 간격을 선택하는 것과 실제 시각 오차를 작게 인증하는 것도 별도다. 빠른 trace를 사용해 CPU를 오래 멈추지 않아도 수집·전송·버퍼 비용과 유실 조건을 조사해야 한다. 문서의 기능 지원과 이 종이 관측 모형의 판정을 실제 장비의 성공으로 옮기지 않는다.

어떤 도구가 무엇을 보는가

CPU cycle counter는 명령 구간의 tick 차이를, timer는 시간 기반 카운트를 관찰한다. 시작·끝에 GPIO를 토글하고 논리분석기나 오실로스코프로 펄스 폭을 볼 수도 있다. UART 로그는 메시지와 순서를 남긴다. 전압·아날로그 파형·디지털 논리·소프트웨어 상태가 서로 같은 관찰 대상은 아니다.

주파수·분해능·overflow·시작/끝 위치를 정해야 한다. cycle counter가 CPU 주파수에 연동되면 동적 주파수 변경을 단순히 고정 MHz로 나눌 수 없다. 샘플링 장비는 두 표본 사이의 짧은 펄스를 놓칠 수 있고 시간 폭의 양쪽 경계가 양자화될 수 있다. 데이터시트의 허용오차와 장비 설정 없이 눈으로 본 파형을 정확한 시간으로 선언하지 않는다.

관찰자가 시간을 사용한다

타이머 읽기, GPIO 쓰기, 문자열 포맷, 전송은 각각 비용을 갖는다. 동기식 printf가 느린 UART를 기다리면 원래 task의 실행시간을 크게 늘릴 수 있다. 비동기 링 버퍼 로그도 복사·큐 동기화·버퍼 넘침 비용과 유실 가능성이 있다. 빠른 trace나 DMA 전송도 버스 경합 등 영향을 모두0으로 만들지는 않는다.

정지를 오래 요구하는 디버거는 시간에 의존한 오류를 바꿀 수 있다. 관찰 장치를 넣어 오류가 사라졌다는 사실은 가설의 단서다. 락이나 우연한 지연이 race를 숨겼을 수도 있어 원래 코드가 올바른 증거로 사용하지 않는다. 측정 구간과 instrumentation 버전을 기록하면 서로 다른 실험을 섞는 실수를 줄일 수 있다.

보정은 모형 안에서만 가능하다

추가 측정 비용이 항상 고정이고 프로그램의 경로·캐시·스케줄을 바꾸지 않는 모형에서는 관측값에서 그 비용을 뺄 수 있다. 하지만 실제 시스템의 간섭은 입력이나 하드웨어 상태에 따라 변하며, 빼기만으로 원래 최악값을 복원할 수는 없다. 대조 실험은 같은 빌드·조건과 다른 관찰 강도에서 차이를 조사하는 방법이지 간섭이 없다는 자동 증명이 아니다.

실험 기록에는 장치/펌웨어 revision, 시계/샘플률, 이벤트 정의, 시작과 끝 위치, 로그 유실, 입력과 반복 수를 적는다. 측정 성공·기능 성공·마감 성공·초심자 학습 성공을 별도로 표시한다. 여기서는 가상 시간 계산만 하고 타이머나 파형 장비로 실제 신호를 수집하지 않는다.

풀이와 답 확인

  1. ① 삭제 구간은 [0,0xC00)이며 삭제량은 3,072바이트다. 이미지 길이는 1,280바이트이므로 이미지 밖 영향은 1,792바이트다. 두 설정은 0xFF가 된다. 삭제 전 전체 블록 복사본에 이미지만 패치하여 전체를 복원하고 보존 구간도 확인해야 한다.

  2. ② 전체 세 주소에는 세 슬롯이 필요하여 설치할 수 없다. A와 B만 선택하면 두 슬롯에 맞지만 C는 감시하지 않는다. 별도 FIFO는 ID 1, 2, 3을 수용하고 ID 4를 버린다. 수용 항목은 3개이고 유실은 1개이며 소비는 0개다. 끝 FIFO는 [1,2,3]이다.

  3. ③ 두 구간은 2 μs와 4 μs이므로 총 6 μs다. 고정 60 MHz로 구한 4 μs는 2 μs 작다.

  4. ④ 상승 시각 r은 (1,2] μs, 하강 시각 f는 (3,4] μs 안이므로 폭은 열린 범위 (1,3) μs다. 상승 1.9 μs와 하강 3.1 μs의 폭 1.2 μs, 상승 1.1 μs와 하강 3.9 μs의 폭 2.8 μs가 같은 표본을 만든다.
