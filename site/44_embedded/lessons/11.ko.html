소단원 11.1

Flash·EEPROM·SD

전원을 껐다 켜도 설정과 측정 기록이 남게 하려면 어디에 저장할까?

준비 개념과 학습 목표

준비 개념

  • RAM과 비휘발성 저장
  • 바이트와 배열
  • 정수 나눗셈

학습 목표

  • 저장 매체·접근 단위·파일 시스템을 구별한다.
  • 기록 용량과 갱신 횟수를 계산하고 마모 가정을 명시한다.

지속되는 데이터에도 사용 조건이 있다

RAM의 작업 데이터는 일반적으로 전원을 잃으면 유지되지 않는다. Flash와 EEPROM은 비휘발성 저장에 쓰이지만 이것이 무제한 쓰기나 쓰기 중 전원 차단 안전을 뜻하지는 않는다. 저장할 값의 크기·갱신 빈도·기록을 잃어도 되는 범위를 먼저 적어야 한다.

Flash는 보통 지우기 단위와 쓰기 단위가 다르며 작은 값 하나를 바꾸는 비용도 주변 블록 관리에 영향을 받는다. EEPROM은 작은 설정 갱신에 자주 쓰이지만 제품마다 byte/page 쓰기·내부 쓰기 시간·내구성이 다르다. 모든 부품에 한 가지 단위나 횟수를 적용하지 말고 실제 자료표를 확인한다.

매체와 저장 소프트웨어는 서로 다른 층이다

SD 카드는 카드 인터페이스로 접근하는 저장 장치다. MCU의 SDMMC 또는 지원되는 SPI 호스트 드라이버가 카드와 명령·데이터를 주고받는다. 파일 이름으로 읽고 쓰는 동작은 그 위의 파일 시스템이 제공한다. SPI가 있다고 자동으로 FAT 파일 구조까지 해석되는 것은 아니다.

센서의 긴 기록은 SD와 파일 시스템을 사용할 수 있고 작은 설정은 키·값 저장 계층을 사용할 수 있다. 예를 들어 Espressif NVS는 작은 값에 적합하도록 로그에 새 값을 추가하고 Flash 마모를 분산한다. NVS의 특정 페이지 크기는 해당 구현의 조건이며 모든 Flash나 EEPROM의 공통 규격이 아니다.

마모 분산과 기록 간격을 함께 결정한다

같은 셀이나 블록만 반복 갱신하면 쓰기·지우기 내구성을 집중해서 사용한다. 기록 위치를 여러 슬롯에 나누는 방법은 마모를 분산하지만 인덱스·복구·공간 회수도 필요하다. RAM에 잠시 모아 쓰면 갱신 횟수를 줄일 수 있으나 마지막 저장 이후 데이터가 전원 차단 때 사라질 수 있다.

내구성 횟수로 계산한 시간은 교육 모형의 예산이다. 온도·전압·보존 기간·Flash의 지우기 증폭·불량 블록·메타데이터 갱신을 빼고 계산했다면 제품 수명이라고 표시하지 않는다. 기록량과 저장 성공 여부를 따로 확인하는 계획이 필요하다.

중간 과정을 따라가는 예제

자체 저장 모형은 4096바이트 영역에 32바이트 고정 레코드를 놓는다. 모든 바이트를 레코드에 쓰며 헤더·인덱스는 없다고 가정한다. 10초마다 하나를 저장할 때 영역을 한 번 채우는 시간과 하루 기록량을 구하라.

  1. 슬롯 수는 4096/32=128개다. 실제 NVS의 내부 레이아웃을 그대로 계산한 값은 아니다.
  2. 영역을 채우는 128회 기록의 간격 예산은 128×10=1280초, 21분 20초다. 시각 10초에 첫 기록, 1280초에 128번째 기록이라고 정한다.
  3. 하루는 86400초이므로 86400/10=8640레코드다. 자료량은 8640×32=276480바이트다.
  4. 이 영역을 순환 사용하면 옛 기록을 덮기 전에 어느 범위를 보존할지 결정해야 한다. 슬롯 수 계산만으로 지우기·쓰기의 원자성이 보장되지는 않는다.

128슬롯이고 이 시작 규칙에서 21분 20초에 차며 하루 자료량은 276480바이트다.

종이와 본문으로 직접 해보기

한 저장 위치가 가정상 100000회 갱신 가능하고 매분 같은 위치를 갱신한다. 이 예산의 시간과 매시간 갱신할 때의 시간을 일·년 단위로 비교하라. 1년은 365일로 놓는다.

힌트 보기

100000분은 1440으로 나누고 100000시간은 24로 나눈다.

풀이 보기

매분 갱신이면 100000/1440≈69.44일이다. 매시간이면 100000/24≈4166.67일, 약 11.42년이다. 이 숫자는 가정된 한 위치의 갱신 예산이며 실제 EEPROM 제품 수명 보증이 아니다. 갱신 간격을 늘리면 저장 직전까지 잃을 수 있는 최근 기록도 늘어난다.

오해와 반례

SD 카드에 파일로 쓰면 무한히 쓰고 언제 뽑아도 최신 파일이 남는다.

파일 시스템은 파일 이름과 공간을 관리하지만 물리 저장 내구성·쓰기 캐시·전원 차단 조건을 없애지 않는다. 쓰기 중 제거하면 최신 데이터나 파일 구조가 손상될 수 있으므로 완료와 안전한 제거 조건을 장치·소프트웨어별로 확인한다.

소단원 11.2

CAN·Ethernet·무선 개요

작은 센서의 제어 메시지와 카메라의 큰 파일은 같은 연결이 적합할까?

준비 개념과 학습 목표

준비 개념

  • 이진수와 비교
  • 비트와 바이트
  • 송신·수신·프로토콜

학습 목표

  • CAN의 메시지 식별·중재를 제한 조건 안에서 추적한다.
  • 연결 방식의 전송량·지연·전원·환경 조건을 함께 비교한다.

CAN은 메시지의 우선순위를 정한다

CAN은 여러 노드가 공유 버스에서 메시지를 주고받는 통신에 쓰인다. MCU의 CAN 제어기와 실제 버스 신호를 다루는 transceiver의 역할을 구별한다. 메시지 식별자는 흔히 자료 종류와 우선순위를 나타내며 IP 주소처럼 특정 수신 장치 하나를 자동 지정한다고 생각하지 않는다. 각 노드는 관심 있는 ID를 수신 필터로 고를 수 있다.

동시에 시작한 같은 형식의 데이터 프레임은 식별자 비트를 비교하는 중재를 한다. 표준 11비트 데이터 프레임끼리 다른 조건이 같은 비교에서는 dominant 0이 recessive 1에 우선하여 낮은 ID가 먼저 전송된다. 패자는 중재에서 물러나 다시 기회를 기다린다. 표준·확장·원격 프레임을 섞은 모든 상황을 단순 정수 비교 하나로 일반화하지 않는다.

Ethernet은 하드웨어와 상위 계층을 함께 본다

Ethernet을 MCU에서 쓰려면 프레임 처리의 MAC과 물리 신호의 PHY, 또는 그것을 통합한 모듈을 확인해야 한다. IP나 TCP는 그 위의 계층이므로 Ethernet 연결 성공이 원격 서버의 응용 저장 완료와 같은 뜻은 아니다. 실제 응용에는 연결 끊김·재시도·메시지 중복 처리도 필요하다.

빠른 링크라도 전송 시간은 자료 비트 수, overhead, 혼잡과 서버 처리에 따라 달라진다. 현대 full-duplex switched Ethernet을 오래된 공유 half-duplex 충돌 모형과 혼동하지 않는다. 이 소단원의 수치 예제는 주어진 유효 payload 처리율로만 계산하고 특정 보드의 성능을 주장하지 않는다.

무선은 이동성과 전파 환경을 교환한다

Wi-Fi나 Bluetooth 같은 무선 방식은 케이블 없이 연결하지만 거리·장애물·간섭·안테나·송신 전력의 영향을 받는다. Bluetooth SIG의 설명도 유효 범위를 하나의 고정 거리로 정하지 않고 여러 조건으로 설명한다. 같은 이름의 기술이라도 PHY와 운용 조건이 다르면 결과가 달라진다.

제어에는 최악 지연과 실패 처리, 영상에는 지속 처리량, 배터리 센서에는 깨어 있는 시간과 재전송 에너지가 중요하다. 무선이라 항상 느리거나 유선이라 항상 무고장이라는 순위를 정하기보다 이 조건을 표로 비교한다. 실제 현장 검증 없이 안전 제어의 응답을 보장했다고 표시하지 않는다.

중간 과정을 따라가는 예제

표준 11비트 CAN 데이터 프레임 두 개가 같은 버스에서 동시에 시작한다. ID는 0x120과 0x128이며 다른 중재 조건은 같다. 어느 메시지가 먼저 버스 사용권을 얻는지 비트를 비교하라.

  1. 0x120=288, 0x128=296이다. 11비트 표기는 각각 00100100000과 00100101000이다.
  2. 앞에서 일치하는 비트를 지나 처음 다른 자리를 찾으면 첫 ID는 0, 둘째 ID는 1이다. 이 자리는 값 8에 해당한다.
  3. 0이 dominant이므로 0x120 메시지가 중재에서 이긴다. 0x128 송신자는 물러나 버스가 비면 다시 시도한다.
  4. 이 비교로 전체 전달 마감이나 수신 응용 처리 시간을 보장하지는 않는다. 반복되는 고우선순위 부하와 오류도 고려해야 한다.

이 제한 조건에서 0x120이 먼저 전송한다. 중재 패배는 메시지 내용이 부서졌다는 뜻이 아니다.

종이와 본문으로 직접 해보기

1 MiB 파일을 응용 payload 유효 처리율 20 Mbit/s인 연결로 보낸다. 1 MiB=1048576바이트라 두고 최소 자료 전송 시간을 계산하라. 8바이트 제어값을 classic CAN의 자료 최대 8바이트 프레임 하나에 담으면 전체 버스 전송도 64비트뿐인가?

힌트 보기

파일 바이트를 8배 하고 20000000으로 나눈다. 프레임에는 자료 외 필드가 있다.

풀이 보기

8388608/20000000=0.4194304초다. 여기서 처리율은 유효 payload 기준이며 대기나 응용 저장을 추가하지 않았다. CAN 자료는 64비트지만 식별자·CRC·ACK 등과 경우에 따른 stuffing 등 overhead가 더해져 전체 전송은 64비트만이 아니다.

오해와 반례

낮은 CAN ID면 언제나 일정 시간 안에 응용 동작까지 끝난다.

같은 비교 조건에서 중재 우선권을 정하지만 실제 지연에는 이미 진행 중인 프레임·오류·버스 부하·소프트웨어 처리가 포함된다. 우선순위와 전체 deadline의 증명을 구별한다.

소단원 11.3

전원 상실과 데이터 보존

저장 버튼을 누르는 순간 전원이 끊어지면 이전 설정이라도 복구할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 비휘발성 저장
  • 순번과 검사값
  • 단계별 상태 추적

학습 목표

  • 쓰기 시작·완료·영구 반영을 구별한다.
  • 제한된 장애 모형에서 두 슬롯 갱신과 복구를 추적한다.

저장 요청 뒤에도 중간 상태가 있다

저장 함수가 무엇을 보장하는지는 저장 계층과 장치의 계약에 달려 있다. RAM 버퍼만 바뀐 시점, 쓰기 명령이 전달된 시점, 장치 쓰기가 끝난 시점, 파일 시스템의 commit이 끝난 시점을 구별하자. 전원이 끊겨도 이미 확정된 값이 유지되는지와 진행 중인 새 값이 유지되는지는 서로 다른 요구다.

Microchip AN1029는 해당 serial EEPROM의 쓰기 동안 최소 동작 전압을 유지해야 한다고 설명한다. 비휘발성이라는 말이 저전압 중 쓰기를 안전하게 완성한다는 말은 아니다. 저전압 감지와 reset은 잘못된 새 동작을 막는 데 도움이 되지만 이미 시작한 모든 쓰기의 성공을 보장하는 만능 장치는 아니다.

이전 값을 남겨 놓고 새 값을 만든다

두 슬롯 모형에서는 정상 슬롯 A를 보존하고 다른 슬롯 B에 새 순번·값·검사값을 먼저 쓴 뒤 마지막에 유효 표시를 확정한다. 재시작은 유효 표시와 검사값이 맞는 후보 가운데 최신 순번을 선택한다. 새 슬롯이 준비되기 전에 이전 슬롯을 지우면 복구 근거도 사라진다.

이 교육 모형은 슬롯들이 독립된 지우기 영역이고 전원 차단이 쓰는 슬롯만 손상시키며, 유효 표시 쓰기는 원자적이고 저장 순서가 실제 매체에서도 지켜진다고 가정한다. 실제 Flash에 구현할 때는 지우기 단위·쓰기 재정렬·캐시 flush·순번 넘침·검사값 충돌을 확인해야 한다. 검사값은 오류 탐지이지 악의적 변경의 인증이 아니다.

소프트웨어 복구와 전원 설계를 연결한다

littlefs는 전원 장애 복구를 위한 파일 시스템이지만 block driver의 sync가 캐시 내용을 실제 저장에 반영해야 한다. 파일 갱신도 sync 또는 close를 통해 확정하는 조건을 확인해야 한다. 라이브러리 이름만 붙이고 잘못된 하위 드라이버를 쓰면 같은 보장을 기대할 수 없다.

일부 시스템은 전원 차단을 감지한 뒤 축전 에너지로 마지막 저장을 시도한다. 필요한 에너지는 부하와 저장 시간에 맞춰 계산하고 부품 오차와 변환 효율을 검증한다. 단순 계산만으로 성공을 주장하지 않는다. 복구가 불가능하면 기본값으로 시작할지, 기록을 남기고 사용을 제한할지도 요구사항에 포함한다.

중간 과정을 따라가는 예제

자체 두 슬롯 모형: A는 순번 7·값 40·검사 통과·유효, B는 비유효다. 순번 넘침은 없고 B는 A와 독립된 지우기 영역이다. B를 비유효 상태로 지운 뒤 순번 8·값 41·검사값을 쓰고 읽어 확인하여 마지막 원자 유효 표시를 쓴다. 각 단계 사이 전원 차단의 복구 후보를 구하라.

  1. B를 지우거나 새 자료를 쓰는 중에는 B가 비유효이며 A의 순번 7·값 40이 유지된다는 장애 가정을 적용한다. 따라서 A를 선택한다.
  2. B 본문과 검사값을 다 썼어도 아직 유효 표시 전이라면 B를 선택하지 않는다. 새 값이 완성돼 보인다는 이유만으로 commit을 추측하지 않는다.
  3. 검사와 읽기 확인을 통과하고 마지막 원자 표시가 확정되면 A와 B 모두 유효다. 순번 8이 더 크므로 B의 값 41을 선택한다.
  4. 유효 표시의 원자성 가정을 없애거나 두 슬롯을 같은 지우기 영역에 놓으면 이 증명은 성립하지 않을 수 있다. 실제 부품 조건을 추가 검증해야 한다.

commit 전에는 값 40, commit 후에는 값 41을 선택하는 제한 모형이다. 장치에서 실제 정전 시험을 한 결과는 아니다.

종이와 본문으로 직접 해보기

A가 순번 7·값 40·유효·검사 통과이고 B가 순번 8·값 99·유효라고 적혔지만 검사 실패다. 무엇을 선택할까? 또 이상적 커패시터 C=0.01F가 3.3V에서 2.7V까지 내려가는 에너지와 부하 0.3W로 20ms 저장할 때 필요한 에너지를 비교하라.

힌트 보기

복구는 유효 표시와 검사 모두 통과한 후보만 쓴다. 에너지는 C(V1²−V2²)/2, 부하 에너지는 P×t다.

풀이 보기

B는 검사 실패로 제외하여 A의 값 40을 선택한다. 이상 저장 에너지는 0.01×(10.89−7.29)/2=0.018J이고 부하 요구는 0.3×0.020=0.006J다. 모형 에너지 비는 3이지만 효율·ESR·최소전압·검출 지연·저장 시간 분포를 빼고 계산했으므로 실제 저장 성공을 확정할 수 없다.

오해와 반례

CRC와 두 복사본이 있으면 어떤 전원 장애에서도 반드시 최신 데이터가 남는다.

검사값은 오류를 탐지하고 복사본은 복구 후보를 늘리지만 최신 진행 중 쓰기는 잃을 수 있다. 두 복사본이 함께 지워지는 배치나 거짓 flush, 검사값 충돌도 보장 조건 밖이다. 보존해야 하는 마지막 commit과 진행 중 요청을 구별한다.

한 단계 더

종이에 쓰기·확인·commit 단계 사이마다 전원을 끊는 표를 만들고 예상 복구 값을 적어라. 다음 장비 실습에서는 단계 중간 차단·캐시·반복 brownout까지 시험해야 한다. 현재는 종이 장애 모형이며 실제 정전 시험·전기 안전 평가·학습자 검토는 미수행이다.
