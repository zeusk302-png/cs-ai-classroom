시연 시나리오

한 번 잘 보인 기능이 다음 사람에게도 재현될까?

준비 개념과 학습 목표

준비 개념

  • 입력과 출력

  • 버전

  • 예상 결과와 실제 결과

학습 목표

  • 시연의 조건·절차·기대 결과를 연결한다.

  • 정상·오류·복구 상황을 계획한다.

  • 시연 관찰과 전체 품질 주장을 구별한다.

검색 결과는 비었는데 이미 열린 항목이 남으면 무엇을 시연한 걸까요?

앞 본문은 초기 상태·자료 판본·입력·기대 결과를 고정합니다. 새 종이 목록 r5에는 이름 선형대수의 ID 17과 29 두 항목이 있습니다. 검색은 일치 ID 목록만 바꾸며 열린 항목은 바꾸지 않습니다. 일치 항목이 없으면 빈 목록과 결과 없음 안내를 보여 주지만 이미 열린 항목은 유지합니다. 열기는 현재 목록에서 지정한 ID를 고를 때만 바뀝니다. 이 정책은 실제 제품의 동작 관찰이 아닙니다.

초기 열린 ID는 8이고 초기 일치 목록은 빈 목록이라고 정합니다. S1은 선형대수 검색 뒤 목록 [17,29]를 확인합니다. S2는 목록에서 ID 29를 열어 열린 ID를 29로 바꿉니다. S3은 없는이름을 검색하여 빈 목록과 안내, 열린 ID 29의 유지 여부를 함께 확인합니다. S4는 선형대수를 다시 검색하고 ID 17을 열어 복구를 확인합니다. S2만 초기 상태에서 실행하면 현재 빈 목록에 ID 29가 없어 열기 조건을 실패합니다. 재현할 때는 선행 S1까지 함께 기록합니다.

별도 시간 계획은 준비 25초, S1 35초, S2 25초, S3 40초, S4 30초, 설명 20초와 네 시나리오 사이 전환 세 번의 5초를 둡니다. 총 한도는 210초이며 다른 전환 비용은 0이라고 정합니다. 합계는 190초라 여유는 20초입니다. 실제 진행 시간을 측정하지 않았습니다. 네 개 중 세 개를 실행하여 둘은 기대 조건에 맞고 하나는 실패했다는 별도 가상 장부에서는 실행 범위와 실행 기준 통과 비율을 구별합니다.

보여 줄 질문을 먼저 정한다

시연은 프로그램을 켜 두는 행위가 아니라 관찰자가 확인할 질문을 정하고 입력부터 결과까지 따라가게 하는 과정이다. 가상 학습 목록이라면 과목을 찾아 열 수 있는가, 존재하지 않는 이름에 안내가 나오는가, 다시 유효한 이름을 넣어 복구되는가를 질문으로 정할 수 있다.

시작 화면과 자료 버전, 입력값, 실행 순서, 예상 결과를 적으면 다른 사람이 같은 장면을 준비하기 쉽다. 초기 상태가 달라 이전 검색 결과가 남아 있으면 같은 입력에도 다르게 보일 수 있다. 실제 시연을 하지 않은 계획은 성공 관찰로 기록하지 않는다.

정상 흐름과 문제 흐름을 나란히 둔다

자체 시나리오 S1은 자료 r2에서 선형대수를 검색해 목록 한 개를 연다. S2는 없는이름을 검색해 결과 없음 안내를 본다. S3은 S2 뒤에 선형대수를 다시 넣어 목록을 연다. 이 세 흐름은 찾기·빈 결과·복구를 구별하지만 모든 과목과 모든 기기 검증을 대신하지 않는다.

문제가 생겼을 때 화면이 멈추는지, 입력이 남는지, 설명을 받을 수 있는지 관찰할 항목을 정한다. 녹화된 결과를 대안으로 보여 주면 녹화 당시의 버전과 실제 실행 대신 재생했다는 사실을 밝힌다. 오류를 감춘 채 성공한 구간만 보여 주면 확인 범위가 왜곡된다.

시간과 증거를 같이 준비한다

총 시연 시간을 180초로 정하고 준비 20초·S1 40초·S2 30초·S3 40초·설명 20초를 배정하면 합계는 150초다. 남는 30초는 전환과 질문 여유이며 실제 측정 시간이 아니다. S3 설명을 20초 늘리면 총 170초로 여유는 10초가 된다.

시연 기록에는 실행한 시나리오 번호와 실제 결과, 미실행 항목을 둔다. S1·S2만 실행했다는 가상 기록에서는 실행 범위가 2/3 = 약 66.7%이며 S3은 성공도 실패도 아니다. 짧은 시연 통과를 전체 운영 준비 완료로 확장하지 않는다.

검색 결과는 비었는데 이미 열린 항목이 남으면 무엇을 시연한 걸까요?
대상 또는 단계상태 또는 계산확인 범위

일치 목록 [17,29], 열린 ID 29

빈 결과와 옛 열린 항목은 다른 상태다

S4 뒤

일치 목록 [17,29], 열린 ID 17

실제 측정이 아니다

각 행은 이전 행의 상태를 이어받습니다. 검색 목록과 열린 항목을 각각 읽고 S4는 재검색과 열기의 두 사건으로 구별합니다.

중간 과정을 따라가는 예제

180초 안에 준비 20초·S1 40초·S2 30초·S3 40초·설명 20초를 계획한다. S3 설명을 20초 추가했을 때 여유와 실행 범위 2/3의 뜻을 구한다.

  1. 기본 합계는 20 + 40 + 30 + 40 + 20 = 150초다.

  2. 추가한 뒤에는 170초이며 180 − 170 = 10초가 남는다.

  3. 2/3 × 100 ≈ 66.7%는 실행 범위이며 미실행 S3의 통과 여부는 모른다.

계획 여유는 10초다. 두 시나리오 실행은 세 번째 성공을 뜻하지 않는다.

조건을 바꾸어 비교하기

빈 검색 뒤에도 남는 열린 항목

초기 상태에서 S1→S2→S3의 목록과 열린 ID를 추적하세요.

  1. S1은 목록을 [17,29]로 바꾸고 열린 ID 8을 유지합니다.

  2. S2는 ID 29를 선택하여 엽니다.

  3. S3은 목록을 비우지만 열린 ID 29를 보존합니다.

S3의 빈 목록만 보고 열린 항목도 없다고 보고하지 않습니다.

비교할 점

옛 자료가 남는다는 사실은 이번 빈 검색이 성공적으로 열었다는 뜻이 아닙니다.

실행 범위와 통과 분모

별도 네 시나리오 장부의 실행 세 개, 통과 두 개, 실패 한 개, 미실행 한 개를 보고하세요.

  1. 실행 범위는 3/4 = 75%입니다.

  2. 실행한 시나리오 기준 통과 비율은 2/3입니다.

  3. 전체 계획 기준 확인된 통과는 2/4 = 50%이며 미실행 하나의 결과는 모릅니다.

세 비율의 분모 이름을 함께 씁니다.

비교할 점

미실행을 관찰 실패로 합치거나 통과로 채우지 않습니다.

종이와 본문으로 직접 해보기

S2의 결과 없음 안내 뒤 S3을 시험하지 않았다. 발표 문장 ‘모두 복구된다’를 수정하고, S3 시간을 30초로 바꾸면 추가 설명 20초를 유지한 전체 시간을 계산하라.

힌트 보기

미실행 범위를 남기고 기존 170초에서 S3의 감소분 10초를 뺀다.

풀이 보기

S1과 S2 결과만 확인했고 빈 결과 뒤 재검색 복구 S3은 미확인이라고 쓴다. 전체는 160초이며 여유는 20초다.

오해와 반례

정상 검색 한 번이 성공하면 오류 안내와 복구도 성공한 것이다.

정상 결과와 빈 결과 상태는 다른 경로다. 가상 S1 성공만으로 S2·S3 결과를 알 수 없어 각각 확인해야 한다.

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

초기 상태에서 S1→S2→S3→S4 뒤 목록과 열린 ID는?

힌트 1

S4에서 검색 뒤 열기도 합니다.

힌트 2

초기 열린 ID는 8입니다.

풀이와 답 확인

  1. S3 뒤 목록은 빈 목록, 열린 ID는 29입니다.

  2. S4의 재검색 뒤 목록은 [17,29]이며 ID 17을 열어 최종 열린 ID 17이 됩니다.

최종 목록은 [17,29], 열린 ID는 17입니다.

흔한 오답에서 다시 생각하기

재검색만으로 ID 17이 자동 열린다.

S4의 명시적 열기 행동을 생략하면 열린 ID 29가 유지됩니다.

연습 2 · 오류 찾아 고치기

r4에서는 일치 목록이 [17]이었다는 옛 녹화를 r5의 실시간 시연 결과라고 썼습니다.

힌트 1

판본과 재생 여부를 표시합니다.

힌트 2

r5의 일치 목록에는 두 ID가 있습니다.

풀이와 답 확인

  1. 녹화를 r4 기록의 재생이라고 표시합니다.

  2. r5 기대 목록 [17,29]와 실제 r5 미수행을 별도 기록합니다.

옛 녹화는 r5 실행 근거가 아닙니다.

흔한 오답에서 다시 생각하기

같은 검색어이면 판본이 달라도 같은 증거다.

자료 판본에 따라 일치 결과가 달라집니다.

연습 3 · 직접 만들어 보기

S4에 15초를 추가하고 전환 세 번을 각각 7초로 바꾼 계획의 총시간과 여유를 구하세요.

힌트 1

원래 총시간은 190초입니다.

힌트 2

전환 증가분은 세 번의 2초입니다.

풀이와 답 확인

  1. 총시간은 190+15+3×2 = 211초입니다.

  2. 한도 210초를 1초 초과하므로 적어도 1초를 줄이는 별도 계획이 필요합니다.

계획은 1초 초과하며 현재 성공 수행으로 보고하지 않습니다.

흔한 오답에서 다시 생각하기

전환은 기능 실행이 아니므로 한도에서 제외한다.

같은 시연 한도가 전환도 포함한다고 명시했습니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

S2를 초기 상태에서 단독 실행한 실패를 ID 29 자료 자체가 없다는 원인으로 확정해도 될까요?

힌트 1

초기 목록은 빈 목록입니다.

힌트 2

r5 저장 자료에는 ID 29가 있습니다.

풀이와 답 확인

  1. 현재 목록에 없는 ID를 여는 조건을 실패한 것입니다.

  2. S1 뒤 목록을 준비하여 재확인할 계획을 세우되 실제 재실행은 미수행으로 둡니다.

자료 부재와 선행 상태 부재를 구별합니다.

흔한 오답에서 다시 생각하기

실패 하나로 자료 손상을 확정한다.

관찰된 조건과 원인 가설을 분리해야 합니다.

존재 비율은 5/7이고 현재 판본 문서 비율은 4/7이며 받는 사람의 확인 비율은 3/7입니다. 설정 문서를 현재 판본으로 고치면 두 번째 비율만 5/7로 바뀝니다. 복구와 자료 형식 안내를 작성하면 존재는 7/7이지만 받는 사람의 새 확인을 자동 추가하지 않습니다. 항목의 절차와 확인 범위는 장부에 명시하고 실제 계정·비밀·저장소 전달은 수행하지 않습니다.

별도 복구 계약에서 새 프로그램 P2는 자료 형식 F2를 만들고 옛 프로그램 P1은 F1만 읽습니다. P1 실행 파일로 바꾸는 행동만으로 F2 자료를 복구하지 못합니다. 자체 안전 계획은 원본 F2를 보존하고 별도 F1 후보로 변환·검증한 뒤에만 프로그램과 사용할 자료의 참조를 함께 바꿉니다. 이 동시 반영은 명시된 종이 정책이며 실제 운영 도구의 자동 원자성을 주장하지 않습니다. 후보가 실패하면 두 참조와 원본을 그대로 보존합니다.

다음 사람의 첫 질문에 답한다

인수인계는 파일을 많이 보내는 것보다 다음 담당자가 무엇을 보고 시작할지 분명히 하는 과정이다. 목적과 폴더 위치, 필요한 환경, 시작 순서, 기대 결과, 도움을 요청할 담당자를 안내한다. 초보 담당자가 어디서 파일을 열고 어떤 입력으로 확인할지 따라갈 수 있도록 쓴다.

README는 시작 안내를 담고 긴 운영 절차는 별도 문서로 연결할 수 있다. 비밀 키나 개인 비밀번호를 안내 파일에 적어 배포하지 않는다. 필요한 접근 권한을 누가 관리하는지와 안전한 전달 절차는 구별해서 계획하며 이 수업은 실제 권한을 만들거나 전달하지 않는다.

문제 보고와 복구 조건을 연결한다

문제 기록에는 예상과 실제 결과, 자료·버전·입력·재현 순서를 둔다. 화면이 느리다만 적는 대신 어떤 입력에서 어떤 결과를 기다렸고 무엇을 관찰했는지 적으면 담당자가 가설을 세우기 쉽다. 관찰이 원인 확정은 아니므로 최근 변경과 동시에 발생했다는 이유만으로 원인을 단정하지 않는다.

복구 문서는 이전 버전으로 돌아가는 조건과 보존할 자료, 확인할 결과를 포함한다. 이전 프로그램이 새 자료 형식을 읽지 못할 수 있어 파일을 돌려놓으면 모두 복구된다는 가정은 위험하다. 여기서는 실제 복구를 수행하지 않고 새 형식과 이전 형식의 호환 확인을 미완료 항목으로 남긴다.

받는 사람의 확인을 따로 기록한다

자체 인수인계 기준을 시작·설정·문제 보고·복구·담당자·제한의 여섯 항목으로 정한다. 문서가 5개 있고 복구 문서가 없으면 존재 비율은 5/6 ≈ 83.3%다. 다음 담당자가 실제 따라 해 본 항목이 시작과 문제 보고 두 개라면 재현 확인은 2/6 ≈ 33.3%다.

전체 미응답 비율이 줄어도 각 난도의 결과는 나빠질 수 있나요?

앞 본문은 제안 채택·수행·효과 확인을 분리하고 질문 난도와 분모를 함께 비교합니다. 새 가상 장부는 제안 다섯 개 중 세 개를 채택하고 두 개를 수행했으며 수행한 것 중 한 개만 비교 조건을 점검했다고 정합니다. 점검은 효과의 방향이나 인과 성공을 자동 뜻하지 않습니다. 전체 제안 기준 수행은 2/5이고 채택 기준 수행은 2/3, 수행 기준 효과 점검은 1/2입니다.

별도 질문 장부의 이전 구간은 쉬운 질문 8개 중 미응답 1개, 어려운 질문 8개 중 미응답 6개입니다. 다음 구간은 쉬운 질문 16개 중 미응답 3개, 어려운 질문 2개 중 미응답 2개입니다. 전체 미응답 비율은 이전 7/16에서 다음 5/18로 줄지만 쉬운 질문은 1/8에서 3/16으로, 어려운 질문은 6/8에서 2/2로 각각 증가합니다. 질문 구성 변화가 전체 비교에 섞인 것입니다. 실제 팀 관측이 아닌 자체 분수 계산입니다.

두 난도를 각각 절반으로 고정해 비교하는 별도 표준화 지표를 정의하면 이전 비율은 7/16이고 다음은 (3/16+1)/2 = 19/32입니다. 이 지표는 5/32, 즉 15.625퍼센트포인트 증가합니다. 표준화의 가중치를 누가 어떤 목적에 정했는지 밝힙니다. 이 비교도 두 구간의 난도 분류나 배정·관측 조건까지 동일함을 증명하지 않으며 개선 행동의 인과 효과로 보고하지 않습니다.

기억을 관찰과 연결한다

회고는 작업 뒤 잘된 점과 어려웠던 점을 돌아보고 다음 작업을 개선하는 대화다. 누가 게으르다는 평가는 상황을 설명하지 못한다. 질문에 답할 담당자가 정해지지 않아 세 질문이 다음 날까지 남았다는 관찰은 배정 방식과 응답 경로를 검토할 출발점이 된다.

의견을 말하기 어려운 사람이 참여할 수 있도록 적기나 순서별 발언을 계획한다. 기록이 누구에게 공유되는지도 알린다. 익명 의견만으로 누구의 실수인지 추적하려는 방식은 회고의 개선 목적과 어긋날 수 있다. 실제 팀 회의나 익명 수집은 이 자료에서 수행하지 않았다.

행동·담당·기한·확인 기준을 둔다

문서를 잘 쓰자는 의견은 어떤 변경을 할지 모호하다. 다음 주 시연 전에 시작 안내의 입력과 기대 결과를 추가하고 다른 담당자가 따라가게 한다는 행동은 확인 대상을 드러낸다. 담당자와 기한, 완료 근거를 붙이고 채택하지 않거나 보류한 의견의 이유도 남긴다.

모든 의견을 한꺼번에 실행하기보다 영향과 필요한 자원, 다음 작업과의 관련성을 보고 선택한다. 이것은 특정 도구나 유료 서비스를 요구하지 않으며 종이 장부로도 수행할 수 있다. 기한을 정했다고 실제 개선이 일어난 것은 아니므로 수행과 효과 확인을 나누어 기록한다.

효과를 확인할 비교 조건을 정한다

자체 가상 회고에서 제안 4개 중 2개를 채택했고 1개를 수행했으며 효과 확인은 0개라고 정한다. 채택 비율은 2/4 = 50%, 채택한 행동의 수행 비율은 1/2 = 50%, 전체 제안 기준 수행 비율은 1/4 = 25%다. 분모를 말하지 않은 ‘50% 완료’는 어느 상태인지 알 수 없다.

미응답 질문이 이전 8개 중 4개, 다음 8개 중 2개인 가상 기록에서는 비율이 50%에서 25%로 줄어 25퍼센트포인트 감소한다. 그러나 질문의 어려움과 팀 조건이 다를 수 있어 특정 행동 하나가 감소의 원인이라고 확정할 수 없다. 효과 확인 기준과 남은 가설을 같이 남긴다.

중간 과정을 따라가는 예제

회고 제안 4개 중 2개 채택, 1개 수행, 0개 효과 확인이다. 각 상태를 표현하고 가상 미응답 비율 4/8 → 2/8의 차이를 구한다.

  1. 채택 비율은 2/4 = 50%, 채택 기준 수행 비율은 1/2 = 50%, 전체 기준 수행 비율은 1/4 = 25%다.
