소단원 1.1

역할과 책임

셋이 모두 “앱 담당”이면 누가 마지막으로 확인해야 할까?

준비 개념과 학습 목표

준비 개념

  • 산출물은 작업 뒤 다른 사람이 확인할 수 있는 결과다. 화면 설계도·소스 파일·검토 기록이 예다.

  • 권한은 어떤 결정을 할 수 있는 범위이고 책임은 맡은 결과를 설명하고 미완료를 알릴 의무다.

  • 의존성은 한 작업이 다른 작업의 결과를 필요로 하는 관계다. 문제 형식이 정해져야 채점 화면을 만들 수 있다.

학습 목표

  • 수행·검토·결정·연락 역할을 산출물별로 구분한다.

  • 권한과 의존성을 포함해 역할 누락을 찾는다.

담당자를 바꾸면 이전 검토 결과도 새 파일에 따라갈까요?

앞 본문의 역할 분담을 버전이 있는 인수인계로 확장합니다. 자체 팀에서 문제 표 v1은 서가 작성하고 준이 검토하며 서가 내용 승인을 맡습니다. 민은 승인된 표만 구현합니다. 검토 결과는 사람 이름이 아니라 산출물 ID, 버전, 확인한 범위와 연결합니다. 버전이 바뀌면 이전 결과가 무엇을 계속 뒷받침하는지 따로 확인합니다.

이번 팀은 내용이 달라진 행과 그 행에 의존한 설명을 새로 검토한다고 합의합니다. 이는 자체 재검토 정책이며 모든 조직의 의무가 아닙니다. 작성·독립 검토·승인·구현을 각각 기록합니다. 이름을 표에 넣는 일과 필요한 입력·권한을 실제 전달하는 일을 구분합니다. 아래 인물과 기록은 가상이며 실제 동료에게 연락하거나 일을 배정하지 않았습니다.

먼저 확인할 개념
  • 역할과 책임

    앞 본문의 수행·검토·내용 승인·구현 역할과 입력 전달 계약을 확인합니다.

  • 연락·응답·기록 규칙

    수신 확인과 버전별 검토 완료 기록이 서로 다른 사건임을 연결합니다.

직함보다 결과와 행동을 먼저 적는다

가상 세 사람 민·서·준이 퀴즈 앱을 만든다. “민은 개발”만 쓰면 화면 오류를 누가 고치고 누가 받아들일지 알기 어렵다. 역할은 특정 결과에 대해 수행할 행동의 묶음이다. 작업 수행자는 만들고, 검토자는 기준과 비교하며, 결정자는 허용된 범위의 승인이나 변경을 정한다. 연락 창구는 필요한 정보를 전달한다. 한 사람이 여러 역할을 맡을 수 있지만 역할들이 같은 뜻은 아니다.

책임을 맡겼다면 필요한 권한·정보·시간도 연결해야 한다. 서에게 문제 품질 책임을 주면서 정답표를 볼 수 없게 하면 확인이 불가능하다. 검토를 요청한 사람이 자동으로 최종 결정자가 되는 것도 아니다. 이 예에서는 산출물마다 결정자 한 명을 지정하되 다른 사람의 반론과 전문 검토를 받아야 한다고 합의한다. 모든 팀이 반드시 한 명의 결정자를 가져야 한다는 보편 규칙은 아니다.

경계에는 전달할 계약이 필요하다

민이 화면, 서가 문제와 정답, 준이 검토를 맡는다면 “문제 목록 완성”의 형식도 정해야 한다. 여기서는 문제 ID, 질문, 선택지 네 개, 정답 번호를 표 한 행으로 전달한다. 민은 정답 번호가 1–4인지 확인하고, 준은 선택지와 정답의 내용이 일치하는지 따로 확인한다. 형식 검사와 내용 검토를 서로 떠넘기지 않는다.

작업표의 각 행에는 결과·수행자·검토자·결정자·필요 입력·기한을 적는다. 필요한 입력의 제공자가 비어 있으면 맡은 사람이 있어도 시작할 수 없다. 수정 요청은 누가 무엇을 언제 바꿀지 새 행이나 변경 기록으로 연결한다. “누군가 알아서”라는 표현은 책임이 정의되었다는 근거가 아니다.

책임 분담은 잘못을 한 사람에게 몰아주는 표가 아니다

검토자는 오류가 있을 수 있다는 전제로 결과를 비교한다. 검토에서 오류를 발견하면 재작업 경로를 사용하고, 발견하지 못했다면 검토 기준과 자료의 부족도 돌아본다. 구현자의 실수 가능성과 팀의 검토 체계 문제는 함께 존재할 수 있다. 작업표만으로 모든 도덕적·법적 책임이 결정되지는 않는다.

독립 검토가 필요한 중요한 산출물은 수행자와 검토자를 다르게 둘 수 있다. 혼자 작업한다면 이를 독립 검토라고 부르지 말고 자기 검토로 표시한다. 사람이 빠졌을 때는 대체자를 기록하고 정보에 접근할 수 있게 인수인계한다. 명단만 바꾸고 이전 결정을 전달하지 않으면 같은 역할이어도 같은 일을 할 수 없다.

자체 문제 표 v2에서 변경된 내용과 인수인계 상태입니다.
항목현재 사실남은 행동

정답 번호가 v1의 2에서 v2의 3으로 변경됨

Q3의 질문·선택지·정답·연결 해설을 내용 검토함

준의 이전 검토

v1의 Q1–Q5만 검토 완료

v2 전체를 검토했다고 확대하지 않음

대체 검토자 하

이름은 등록했으나 v2 접근 권한 없음

접근과 필요한 자료를 전달한 뒤 검토 시작을 확인함

민의 구현

v1이 구현되어 있음

v2 내용 승인 뒤 해당 구현과 연결 해설을 갱신함

번호 3이 허용 범위 안이라는 형식 확인은 내용 정답의 근거가 아닙니다. 하의 이름이 등록되었어도 현재 입력에 접근할 수 없으므로 검토가 시작되었다고 기록하지 않습니다.

중간 과정을 따라가는 예제

가상 퀴즈 앱의 문제 표는 서가 작성하고 준이 검토하며 민이 정해진 형식으로 구현한다. 정답 내용 승인자는 서다. 문제 3의 정답 번호가 5로 전달되었다. 각 역할의 다음 행동을 추적하라.

  1. 민은 1–4 형식 조건 위반을 발견하고 승인된 값처럼 사용하지 않는다.

  2. 서에게 문제 ID와 위반 조건을 기록하여 수정 요청한다.

  3. 서는 정답 내용을 확인해 번호 2로 수정하고 변경 이유를 적는다.

  4. 준은 수정한 표의 질문·선택지·번호 2가 일치하는지 검토한다. 서의 승인 뒤 민이 새 표를 구현한다.

수행·검토·내용 결정·구현을 구분했다. “개발 담당이니 알아서 고쳐라”로 정답의 전문 결정을 넘기지 않는다.

조건을 바꾸어 비교하기

새 버전의 내용 검토를 분리합니다

v1의 Q3 정답은 2였고 v2에서는 3입니다. 민이 번호 범위 1–4를 확인했습니다. 준의 v1 검토만으로 v2를 승인할 수 있는지 판정하세요.

  1. 번호 3은 형식 범위 안에 있습니다.

  2. 준의 기록은 v1이므로 바뀐 v2 정답의 내용 일치를 확인하지 않았습니다.

  3. 새 검토자는 v2의 Q3 및 연결 해설을 확인하고, 서는 그 결과를 받아 내용 승인 여부를 기록합니다.

형식은 통과했지만 v2 내용 승인 근거는 아직 부족합니다. 민의 다음 행동은 내용 정답을 임의 선택하는 것이 아니라 새 검토와 승인 상태를 확인하는 것입니다.

비교할 점

같은 담당자와 같은 문제 ID가 있어도 버전이 다르면 기존 검토의 범위를 그대로 확대하지 않습니다.

대체자 이름과 실행 가능성을 나눕니다

준이 부재하여 하를 대체 검토자로 지정했습니다. 하는 v1만 볼 수 있습니다. v2 검토를 시작할 수 있는지와 최소 인수인계를 적으세요.

  1. 현재 필요한 입력은 v2의 변경 행과 연결 해설입니다.

  2. 하에게 v2 접근 권한, 변경 이유와 확인 기준을 전달합니다.

  3. 하가 자료를 받을 수 있음을 확인하고 검토·승인 담당과 기한을 기록합니다.

현재는 v2 검토를 시작할 입력이 없습니다. 자료와 접근을 확보한 뒤 시작 상태를 갱신합니다.

비교할 점

이름 변경은 수행 능력·자료 전달·검토 완료를 자동으로 만들지 않습니다.

연습 1 · 값과 상태 예측

v2에서 Q3만 바뀌었습니다. 하가 작성자는 아니며 v2의 Q3를 확인했지만 연결 해설을 읽지 않았습니다. 변경 행과 의존 해설을 함께 검토한다는 규약 아래 독립성 및 범위 완료를 판정하세요.

힌트 1

작성자와 검토자가 다른지 먼저 봅니다.

힌트 2

독립 여부와 확인한 대상 범위는 별도 조건입니다.

풀이와 답 확인

  1. 하와 작성자 서는 다른 사람이라 이 사례의 독립 검토 담당 조건을 만족합니다.

  2. 연결 해설은 미확인이므로 지정 범위의 검토 완료는 아닙니다.

독립 담당 조건은 만족하지만 전체 지정 검토 범위는 아직 완료되지 않았습니다.

흔한 오답에서 다시 생각하기

다른 사람이 봤으니 필요한 모든 범위도 통과했습니다.

독립성이 있어도 보지 않은 해설의 내용까지 확인된 것은 아닙니다.

연습 2 · 오류 찾아 고치기

민은 Q3 번호가 3이므로 유효하다는 이유로 서의 내용 승인 없이 v2 정답을 확정했습니다. 역할 경계의 오류와 다음 행동을 적으세요.

힌트 1

민의 권한은 형식 구현과 범위 확인입니다.

힌트 2

내용 승인자의 역할을 확인합니다.

풀이와 답 확인

  1. 형식 적합과 내용 정답을 분리합니다.

  2. 현재 v2의 내용 확인과 승인을 요청하고 미승인 상태를 기록합니다.

민이 확인한 것은 번호 범위입니다. 내용 승인은 서의 지정 권한과 검토 근거를 통해 따로 결정합니다.

흔한 오답에서 다시 생각하기

구현자가 값을 볼 수 있으면 승인 권한도 있습니다.

자료 접근과 결정 권한은 같지 않습니다.

연습 3 · 직접 만들어 보기

문제 표 v3의 Q4와 그 해설을 새로 작성합니다. 수행자 서·검토자 하·결정자 서·구현자 민을 유지하며 인수인계 기록 한 항목을 구성하세요.

힌트 1

산출물 ID와 버전을 먼저 적습니다.

힌트 2

필요 입력·기한·미완료 상태를 포함합니다.

풀이와 답 확인

  1. 산출물은 문제 표 v3의 Q4와 연결 해설로 지정합니다.

통과한 증거가 많아도 서로 다른 버전이면 하나의 완료가 될까요?

앞 본문의 네 완료 조건을 버전이 있는 증거 표로 확장합니다. 자체 기준 v1은 C1 제출, C2 채점, C3 해설, C4 초기화를 모두 요구합니다. 각 증거에는 확인한 산출물 버전과 입력 범위를 적습니다. 같은 기능 이름이어도 다른 버전에서 얻은 결과를 현재 버전의 통과로 바로 합치지 않습니다.

가상 목표를 “학습자가 다섯 문제를 풀고 틀린 문제의 이유를 확인한다”로 정한다. 화면 세 개 제작은 작업량이고 이 목표의 사용 결과는 아니다. 목표에는 대상·행동·사용 상황을 적어 팀원들이 다른 성공을 상상하지 않도록 한다. 시험 성적 향상은 이 예에서 측정하지 않으므로 앱 기능 완료만으로 성적 효과가 검증됐다고 말하지 않는다.

범위도 적는다. 이 첫 버전은 고정 다섯 문제, 오프라인, 개인 연습만 다룬다. 계정·반별 순위·실제 학습자 성과 측정은 포함하지 않는다. 범위 밖의 제안을 무조건 나쁜 아이디어로 판단하는 것이 아니라 현재 목표와 기한에서 별도 결정한다.

완료 기준은 판정할 수 있는 조건과 근거다

완료 조건 C1은 다섯 문제를 각각 한 번 제출 가능, C2는 고정 정답표로 채점 정확, C3는 틀린 답에 설명 표시, C4는 새로 시작 시 점수 초기화라고 합의하자. 전체 완료 D=C1∧C2∧C3∧C4다. C1–C3만 확인했다면 확인된 범위의 완료이지 D는 확인되지 않았다. 알 수 없음은 거짓으로 확정할 수 없지만 승인에 필요한 증거가 없다는 뜻이다.

각 조건 옆에 누가 어떤 입력으로 확인할지 적는다. 고정 정답표와 실제 반환값의 비교는 채점 근거이고 “보기 좋다”는 그 조건의 근거가 아니다. 실행 전 예상값, 실제 실행 기록, 독립 검토, 학습자 관찰은 서로 다른 근거다. 여기의 활동 표는 가상 확인 결과이므로 실제 실행 기록으로 사용할 수 없다.

기준 변경은 버전과 재확인 범위를 남긴다

기준을 작업 뒤 임의로 낮추면 “완료”의 뜻이 바뀐다. 설명 표시를 제외하려면 목표에 미치는 영향·동의한 결정자·새 버전의 조건을 기록한다. 새로운 C3를 충족했다고 옛 C3도 충족한 것은 아니다. 반대로 목표에 필요 없는 장식 요구가 끝없이 추가되면 완료할 수 없으므로 추가 기준의 근거도 검토한다.

조건이 모두 통과해도 기준 밖의 오류가 없다는 보장은 아니다. 입력 범위나 운영 조건을 바꾸면 다시 확인해야 한다. 좁은 기능 완료를 신뢰성·보안·교육 효과 전체로 확대하지 않는 것이 팀의 정확한 상태 공유다.

  2. C4의 요구는 초기 점수 0이고 관측값은 3이므로 불일치다.

  3. 최종 내용 승인이 필요한 경우 지정 승인자의 결정은 별도로 연결합니다.

예정 응답과 실제 완료 기록을 별도 상태로 둡니다. 아직 완료하지 않은 범위의 결과는 첫 응답에 쓰지 않습니다.

거부 의도는 확정하지 않습니다. 미응답 기록을 보존하고 합의한 경로로 상태와 다음 일정을 확인합니다.

한 단계 더

응답 창이 서로 다른 시간대에 있다면 날짜·시간대·휴일·응답 창 계산 관례를 명시하라. 달력 시간 2시간과 업무 창 2시간은 같지 않다. 중요한 결정은 전달됨·이해됨·승인됨을 따로 확인할 수 있으며, 모든 일상 메시지에 같은 무거운 승인 절차를 적용할 필요는 없다.
