소단원 7.1

이슈와 작업 분할

작업 파일 네 개를 만들면 네 작업이 끝난 걸까?

준비 개념과 학습 목표

준비 개념

  • 작업과 결과

  • 의존 관계

학습 목표

  • 작업 목표·담당·수락 기준을 적는다.

  • 부모 작업과 의존 관계를 분리해 추적한다.

자식 작업을 나누면 원래 완료 기준과 작업량도 사라질까요?

앞 본문은 부모의 포함 관계와 시작을 막는 의존성을 구별합니다. 새 종이 일정은 A 준비 1일, B 집필 4일, C 예제 점검 2일, D 통합 검토 2일입니다. B와 C는 A 뒤에 시작하고 D는 둘 다 끝난 뒤 시작합니다. 두 작업자가 필요할 때 모두 가용하며 작업을 중간에 나누지 않고 전달 비용과 자원 충돌은 없다고 정합니다.

부모 P의 결과 조건에는 A부터 D까지의 수락뿐 아니라 공개 확인 E가 필요합니다. E는 D 뒤에 1일을 사용합니다. A부터 D까지 완료해도 P가 완료된 것은 아닙니다. 자식 목록이 원래 목표의 필요한 결과를 모두 덮는지 별도로 확인해야 합니다. 이 조건은 자체 모형이며 GitHub가 모든 부모를 자동 판정한다는 뜻이 아닙니다.

B를 B1과 B2로 나눌 때 두 작업은 순차이고 기간을 각각 2일로 정합니다. 두 칸이 생겼어도 B의 총 기간 4일은 유지됩니다. 독립 검토 1일을 새로 추가하면 범위와 작업량이 늘며, 원래 날짜를 유지하려면 자원과 의존성을 다시 계산합니다.

이슈는 완료할 결과를 가리킨다

이슈는 팀이 문제와 할 일을 함께 확인할 기록이다. 자체 이슈 I 의 목표는 강의자료 공개다. 담당자, 현재 상태, 완료 판정, 관련 파일 버전을 적으면 “진행 중”이라는 말보다 검토할 대상이 분명해진다.

완료 기준은 결과로 적는다. A 목차 확정, B 본문 집필 및 내용 검토, C 예제 점검, D 공개 버전 확인처럼 정하자. 파일 생성과 내용 확인은 다른 판정이며 이 종이 활동에서 실제 저장소 이슈를 등록하지 않는다.

포함 관계와 막는 관계를 나눈다

I 에 A/B/C/D 가 포함된다는 관계는 작업 분할이다. B/C 는 A 이후에 시작하고 D 는 B 와 C 가 모두 끝나야 시작한다는 관계는 의존성이다. 같은 부모 아래 있다고 서로 반드시 순서대로 실행해야 하는 것은 아니다.

작업을 나눌 때 모든 자식의 책임과 경계가 부모 목표를 덮는지 확인한다. B 와 C 모두 같은 예제의 수정권을 주장하면 충돌할 수 있어 담당 범위를 정한다. 작은 조각을 많이 만들었다고 실제 작업량이 사라지는 것은 아니다.

병렬 가능성과 총 작업량을 구별한다

자체 기간은 A2 일/B3 일/C4 일/D1 일이다. B/C 를 서로 다른 두 작업자가 동시에 처리할 수 있고 자원 충돌과 전달 비용을 없다고 정하면 A→C→D 의 7 일이 가장 긴 경로다. 총 사람 작업량은 10 일이다.

한 사람이 겹침 없이 순서대로 처리하면 총 10 일이 된다. 병렬 7 일은 실제 약속이 아니라 명시한 모형의 최소 일정이다. 작업 범위·검토자 가용 시간·외부 승인 같은 조건이 달라지면 일정을 다시 계산한다.

공개 버전 확인

시작 시각은 0일입니다. 각 기간의 끝에서 선행 수락이 완료되며 바로 다음 작업을 시작할 수 있습니다. 날짜 계산은 실측이나 실제 팀 약속이 아닙니다.

중간 과정을 따라가는 예제

A2 일 후 B3 일/C4 일 병렬, 둘 종료 뒤 D1 일이다. 시작시각 0 에서 시작/종료와 총작업량을 구하라.

  1. A 는 0→2 다.

  2. B 는 2→5,C 는 2→6 이다.

  3. D 는 max(5,6)=6 에 시작해 7 에 끝난다. 총작업량 2+3+4+1=10 이다.

병렬 종료 7 일/총작업량 10 일이다.

조건을 바꾸어 비교하기

전체 목표의 누락된 마지막 조건을 찾습니다

두 작업자로 A부터 E까지 가장 이른 종료와 총 작업량을 계산하세요.

  1. A는 0일부터 1일까지입니다. B는 1일부터 5일까지, C는 1일부터 3일까지입니다.

  2. D는 두 선행이 끝난 5일에 시작해 7일에 끝나며 E는 7일부터 8일까지입니다.

  3. 총 작업량은 1 + 4 + 2 + 2 + 1 = 10인·일입니다.

가장 이른 공개 확인 완료는 8일이고 총 작업량은 10인·일입니다.

비교할 점

A부터 D까지만 세면 7일이지만 부모 P의 공개 확인은 남습니다.

순차 분할과 새 검토를 구별합니다

B를 순차 작업 B1과 B2로 나누며 각각 2일을 배정합니다. 별도 안에서는 B2 뒤에 검토 R 1일도 요구하고 D는 R과 C가 모두 끝난 뒤 시작합니다.

  1. 분할만 한 안은 B1이 1–3일, B2가 3–5일로 원래 B의 끝 5일을 유지합니다.

  2. R을 추가한 안은 R이 5–6일, D가 6–8일, E가 8–9일입니다.

  3. 추가 검토가 있는 안의 총 작업량은 11인·일입니다.

분할만 하면 종료 8일이고 새 검토를 추가하면 종료 9일 및 작업량 11인·일입니다.

비교할 점

기록 칸 수와 완료해야 하는 결과 수를 혼동하지 않습니다.

연습 1 · 값과 상태 예측

원래 A–E 일정에서 C 기간만 5일로 바꾸세요. 두 작업자는 그대로 가용합니다. 종료와 작업량을 구하세요.

힌트 1

C는 A 뒤에 시작합니다.

힌트 2

D는 B와 C 중 늦게 끝나는 작업을 기다립니다.

풀이와 답 확인

  1. B는 5일, C는 6일에 끝납니다.

  2. D는 6–8일, E는 8–9일입니다.

  3. 총 작업량은 1 + 4 + 5 + 2 + 1 = 13인·일입니다.

종료는 9일, 총 작업량은 13인·일입니다.

흔한 오답에서 다시 생각하기

C 기간이 3일 늘면 종료도 반드시 3일 늘어난다.

원래 C의 여유와 가장 긴 선행 경로를 다시 계산합니다.

연습 2 · 오류 찾아 고치기

A부터 D까지 수락되어 자식 네 개가 모두 닫혔으므로 부모 P 공개 완료라고 적었습니다. E는 아직 수행하지 않았습니다.

힌트 1

부모의 원래 완료 조건을 다시 읽습니다.

힌트 2

닫힌 기록과 공개 관찰을 구별합니다.

풀이와 답 확인

  1. A부터 D까지 완료 사실은 유지합니다.

  2. 공개 확인 E는 미수행이라 부모 P 전체 완료를 보류합니다.

  3. 누락된 E의 담당·기간·수락 근거를 자식 계획에 연결합니다.

네 자식 수락은 공개 확인 E의 완료 증거가 아닙니다.

흔한 오답에서 다시 생각하기

모든 현재 자식이 닫히면 원래 목표도 언제나 완성된다.

자식 목록이 필요한 결과를 빠뜨렸을 수 있습니다.

연습 3 · 직접 만들어 보기

원래 A–E 작업을 한 작업자만 겹침 없이 맡습니다. 선행을 지킨 일정과 종료를 구성하세요.

힌트 1

B와 C의 순서는 바꿀 수 있습니다.

힌트 2

한 작업자의 시간은 중복 배정하지 않습니다.

풀이와 답 확인

  1. A 0–1일, B 1–5일, C 5–7일로 배정합니다.

  2. D 7–9일과 E 9–10일을 배정합니다.

  3. 총 작업량 10인·일과 한 작업자 종료 10일이 일치합니다.

이 배정은 10일에 끝납니다. 두 작업자의 8일 일정을 그대로 약속하지 않습니다.

흔한 오답에서 다시 생각하기

의존 간선이 없으면 같은 사람도 두 작업을 동시에 수행한다.

의존 가능성과 자원 가용성은 다른 조건입니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

D가 B를 기다리면서 동시에 B가 D의 최종 확인 뒤에만 끝날 수 있도록 의존을 추가했습니다. 시간을 늘리면 해결되나요?

힌트 1

B와 D 사이의 순환을 찾습니다.

힌트 2

시작 가능한 조건을 누가 먼저 만들어야 하는지 봅니다.

풀이와 답 확인

  1. B 완료를 위해 D 완료가 필요하고 D 완료를 위해 B 완료가 필요합니다.

  2. 기간을 늘려도 이 순환 선행 조건은 해소되지 않습니다.

  3. 초안 확인과 최종 검토를 다른 작업으로 분리하거나 조건을 재설계합니다.

날짜 연장만으로 순환 의존을 해결하지 않습니다.

흔한 오답에서 다시 생각하기

긴 기간을 잡으면 모든 의존 순환도 자연히 끝난다.

기다리는 조건이 영원히 서로에게 남을 수 있습니다.

같은 총 작업량이라도 겹칠 수 있는 단계가 다르면 날짜 범위가 바뀔까요?

새 보고 시점은 10일이며 약속은 15일입니다. 남은 검토 V는 2일, 외부 확인 X의 기간은 1–4일, 공개 확인 E는 1일입니다. X는 기존 초안을 확인하므로 V와 동시에 시작할 수 있고 E는 V와 X 둘 다 끝난 뒤 시작합니다. 이는 확인한 계획 조건이며 외부 기간의 확률 분포나 실제 응답 약속은 없습니다.

병렬 잔여 기간은 max(2, X의 기간) + 1일입니다. 만약 X가 검토 결과물을 필요로 해 V 뒤에만 시작해야 한다면 잔여 기간은 2 + X의 기간 + 1일입니다. 같은 작업 이름과 기간 목록만으로 두 날짜를 같다고 보고하지 않습니다.

15일에 끝나는 경로가 존재해도 그 날짜를 보장하지 않습니다. 새 외부 확인이 들어오면 완료 근거와 남은 단계를 갱신합니다. 이미 발생한 초과, 앞으로의 위험, 모형의 조건부 범위를 이름별로 적고 다음 확인 시점과 결정 요청을 남깁니다.

먼저 확인할 개념
  • 위험·지연 보고

    위험과 이미 발생한 지연, 사실과 기간 가정을 구별합니다.

  • 이슈와 작업 분할

    외부 확인의 선행 조건과 병렬 가능성을 명시합니다.

사실과 가정을 따로 적는다

자체 보고 시점은 day5 이며 약속은 day8 공개다. 사실은 본문 파일이 있고 독립 검토를 아직 못 했다는 것이다. 검토 1 일·외부 확인 1~3 일·배포 1 일은 순차라는 계획 가정이다. 실제 관찰 시간이나 통계적 예측이 아니다.

위험은 앞으로 조건이 충족되지 않을 가능성과 영향이다. 지연은 이미 약속한 시점을 넘긴 관찰이다. day5 에서는 day8 을 아직 넘기지 않았지만 계획 경로가 day8~10 이면 완료 날짜 위험을 보고할 근거가 된다.

도움을 요청할 결정을 구체화한다

보고를 “잘 안 됩니다”로 끝내지 말고 막는 조건과 누가 무엇을 결정하면 달라지는지 적는다. 외부 확인을 앞당길 수 있는지, 공개 범위를 줄여도 목표를 충족하는지, 날짜를 조정할지 선택지를 제시한다.

품질 확인을 생략해 숫자만 맞추는 것은 다른 완료 기준이다. 범위를 줄이면 빠진 항목을 기록하고 합의된 목표를 다시 확인한다. 다음 확인 시점을 day6 으로 정했다면 그때 새 사실이 없어도 확인한 상태와 남은 불확실성을 구별해 기록할 수 있다.

예상 날짜를 보장으로 쓰지 않는다

외부 시간이 1 일이면 day5+1+1+1=8, 3 일이면 10 이다. 이것은 각 단계가 즉시 이어지고 재작업이 없다는 모형의 범위다. 외부 답변이 더 늦어질 수 있다면 상한 10 도 보장이라고 쓰지 않는다.

보고 문장은 “day5 현재 검토 미수행, 순차 모형상 day8~10, 외부 1~3 일 가정 확인 필요, day6 다시 확인”처럼 조건을 포함한다. 안전이나 실제 사용자 피해가 있는 경우의 대응은 별도 운영 정책에 따라 정하며 이 단원은 법적 의무를 단정하지 않는다.

소단원 7.3

진척의 근거

진행률 75%라는 숫자는 무엇의 75%일까?

준비 개념과 학습 목표

준비 개념

  • 가중 평균

  • 완료 기준

학습 목표

  • 분자·분모와 완료 규칙을 공개한다.

  • 집필·검토·배포 상태를 혼동하지 않는다.

완료한 큰 작업 하나를 네 칸으로 나누면 진척이 네 배인가요?

새 보드의 작업 A, B, C의 가중치는 각각 6, 3, 3으로 합이 12입니다. A만 현재 버전의 수락 기준을 충족했습니다. 작업 개수 완료율은 1/3이지만 완료 가중치 비율은 6/12 = 50%입니다. 두 비율은 다른 질문이며 가중치가 실제 기간·가치·성실도를 측정한 것은 아닙니다.

A를 가중치 1, 1, 2, 2의 순차 자식 A1부터 A4까지로 분할하며 원래 수락 근거가 각 자식을 덮는다고 확인했습니다. B와 C는 그대로입니다. 완료한 잎 작업은 네 개, 전체 잎 작업은 여섯 개이므로 개수 비율은 4/6이 됩니다. 가중치 합과 완료 가중치는 그대로이므로 가중 진척은 50%로 유지됩니다. 부모 A와 자식들을 동시에 더하지 않습니다.

현재 자료가 바뀌면 과거 수락을 자동 승계하지 않습니다. B의 v1 검토가 있어도 현재 v2에 영향을 주는 변경이 있으면 현재 검토는 보류입니다. 보류는 실패 관찰이 아니며 무엇을 확인해야 수락할지 기록합니다. 공개와 학습자 확인은 이 보드의 가중 진척과 별도 상태입니다.

먼저 확인할 개념
  • 진척의 근거

    진척의 분자·분모·현재 버전 근거를 고정합니다.

  • 이슈와 작업 분할

    부모와 자식을 동시에 세지 않고 결과 범위의 보존을 확인합니다.

완료라고 셀 조건을 먼저 정한다

자체 보드는 A 가중 2/B3/C4/D1 이다. 단위 가중치는 비교를 위한 미리 정한 작업값이며 사람의 성실도나 실제 걸린 시간이 아니다. 완료는 해당 결과의 수락 기준을 만족하고 근거 버전이 확인된 경우만 인정한다.

현재 A/B 는 완료, C 는 파일만 있고 검토 미수행, D 는 선행 작업 대기다. 완료 가중치는 5, 전체 10 이다. 파일 존재 3/4=75%와 완료 가중치 5/10=50%는 서로 다른 숫자이므로 같은 이름으로 표시하지 않는다.

근거가 바뀌면 판정을 다시 연결한다

B 의 검토가 버전 v1 에만 적용됐는데 본문이 v2 로 바뀌었다면 현재 원고 검토를 확인해야 한다. 예전 통과 기록을 새 파일에 자동 붙이면 정확한 상태를 잃는다. 결과 ID·버전·검토 상태·미수행 검사를 연결한다.

변경이 검토 범위에 영향을 주는지 판단하더라도 판단 근거를 남긴다. 파일명이나 전체 개수만 같다는 사실은 내용 동일성을 입증하지 않는다. 이 종이 표에는 실제 원고 해시나 서비스 배포 성공이 없다.

범위 변화 때문에 퍼센트가 내려갈 수도 있다

새 E 가중 5 를 추가하고 기존 완료 5 를 유지하면 전체 15 라 진척은 33.3%가 된다. 완료량이 줄지 않아도 분모가 커져 비율이 내려간다. 업무가 퇴보했다고 단정하기 전에 범위를 함께 보고한다.

C 의 검토가 끝나 수락되면 완료 9/10=90%지만 D 공개 확인이 남아 전체 공개 완료는 아니다. 여러 단계에 필요한 근거를 각각 보고하면 사용자는 준비된 내용과 남은 검증을 구별할 수 있다.

중간 과정을 따라가는 예제

A/B 완료,C 파일만,D 대기인 보드의 완료 가중치와 파일 존재 비율을 계산하라. 새 E5 를 추가하면?

조건을 바꾸어 비교하기

개수 진척 변화와 실제 완료량을 분리합니다

A만 완료인 원래 보드와 분할 보드의 두 비율을 계산하세요.

  1. 원래 작업 개수 완료율은 1/3로 약 33.3%입니다.

  2. 분할 보드 잎 개수 완료율은 4/6로 약 66.7%입니다.

  3. 두 보드 모두 완료 가중치는 6, 전체는 12로 가중 진척 50%입니다.

개수 비율은 달라져도 이 모형의 가중 완료량과 진척은 그대로입니다.

비교할 점

가중치의 합 보존이 모든 실제 작업의 품질 동등성 증명은 아닙니다.

진척 분모와 근거 버전을 함께 갱신합니다

분할 보드에 미완료 E 가중치 4를 추가합니다. 그 뒤 B가 현재 v2에서 수락되어 가중치 3을 더합니다.

  1. E 추가 직후는 완료 6/전체 16으로 37.5%입니다.

  2. B의 현재 수락 뒤 완료 가중치는 9입니다.

  3. 현재 가중 진척은 9/16 = 56.25%입니다.

범위 추가는 37.5%, B 현재 수락 뒤는 56.25%입니다.

비교할 점

B의 v1 통과 기록만으로 현재 v2를 수락한 사건을 만들어 넣지 않습니다.
