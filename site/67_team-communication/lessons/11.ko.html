새 파일에서 오류가 나도 화면의 옛 합계가 새 결과일까요?

앞 본문은 준비 조건·정확한 입력 계약·행동 뒤 결과·복구를 연결합니다. 새 가상 앱 v3은 UTF-8 텍스트의 첫 물리 줄에 points라는 헤더를 요구합니다. 뒤의 각 물리 줄은 정수 한 개이며 빈 줄과 비정수는 오류입니다. 데이터가 하나도 없어도 오류입니다. 물리 줄은 헤더를 포함해 1부터 세며 데이터 행은 헤더를 제외해 1부터 셉니다. 이 보강은 일반 CSV의 모든 인용 규칙을 설명하는 실제 앱이 아닙니다.

종이 인터페이스의 “입력 선택”은 후보 파일만 바꾸고, “검증 후 계산”은 전체 후보가 유효할 때만 건수·합계·평균과 결과 출처 파일을 함께 바꿉니다. 실패하면 오류를 보여 주며 이전 성공 결과와 그 출처는 보존합니다. 화면에 수가 남아 있다는 사실만으로 현재 후보의 성공이라고 읽지 않습니다.

후보 F의 헤더 points 뒤 값은 4, 6, 8이며 모두 유효합니다. 별도 후보 G는 둘째 데이터 행을 six로 바꾼 파일입니다. 먼저 F에서 성공한 뒤 G를 선택·검증하면 데이터 2행, 물리 3줄 오류이고 결과 출처는 F로 남습니다. 복구는 G의 복사본에서 해당 값을 고친 뒤 다시 전체 검증하는 종이 계획입니다. 실제 파일 수정이나 UI 수행은 하지 않았습니다.

시작 전에 필요한 조건을 밝힌다

설치 안내는 제품과 문서 버전, 지원 환경, 필요한 권한과 준비 파일을 먼저 알려 준다. 이미 설치되어 있다는 가정을 숨기면 첫 단계부터 막힐 수 있다. 이 절의 도구는 종이로 설계한 가상 점수 요약 앱이며 실제 다운로드 링크나 설치 파일은 없다.

가상 앱 v1은 브라우저에서 열고 UTF-8 CSV를 선택한다는 계약을 둔다. UTF-8은 글자를 바이트로 표현하는 문자 인코딩 이름이고 CSV는 열을 쉼표로 구분하는 텍스트 형식이다. 필요한 개념 설명을 준비 목록과 연결한다.

행동과 확인 결과를 함께 쓴다

사용 절차는 준비→입력 선택→실행→결과 확인 순으로 적는다. 버튼의 정확한 이름과 어느 화면에서 행동하는지 쓰며 그 다음 어떤 결과가 나타나야 하는지 밝힌다. 예제 파일의 값과 기대 결과는 따로 제공한다.

가상 계약은 첫 행 score 헤더 다음에 정수 점수를 한 줄씩 받는다. 빈 데이터와 정수가 아닌 값은 계산하지 않고 오류로 표시한다. 문서에 넣은 기대 출력은 이 계약의 손 계산 결과이며 실제 앱을 실행해서 본 화면은 아니다.

복구를 검증 가능한 행동으로 쓴다

문제 해결은 오류 문구와 조건을 연결한다. score 열 없음이라면 헤더 철자와 파일 버전을 확인하고, 정수 아님이라면 안내된 데이터 행의 값을 확인한다. 이유 없이 재설치만 반복하도록 쓰지 않는다.

입력 파일을 수정할 때 원본을 보존하고 복사본을 사용한다. 복구 후 같은 예제를 다시 확인할 계획을 둔다. 계속 실패하면 버전·환경·재현 단계·기대/실제 결과를 보고하되 비밀번호나 개인 점수를 공개 보고서에 넣지 않는다.

선택된 파일과 결과가 계산된 파일을 각각 읽습니다. 이 표의 성공·실패는 자체 계약의 상태 추적이며 실제 화면 관찰 기록이 아닙니다.

중간 과정을 따라가는 예제

가상 입력은 헤더 score 뒤 데이터8,10,12다. 사용 안내에 넣을 기대 합계·평균과 확인 단계를 적어라.

  1. 헤더score와 데이터3개인지 확인한다.

  2. 합8+10+12=30, 평균30/3=10을 계산한다.

  3. 입력 선택→실행→결과에서 건수3/합30/평균10을 확인하도록 안내한다.

예상 결과는3/30/10이다. 이는 가상 계약의 손 계산이며 실제 화면 검증은 미수행이다.

연습 1 · 값과 상태 예측

별도 후보 H는 헤더 points 뒤 값 4, 빈 줄, 8입니다. 오류 위치와 새 평균은?

힌트 1

빈 줄도 데이터 행을 차지합니다.

힌트 2

풀이와 답 확인

  2. 전체 후보가 실패하므로 H의 새 평균은 반영하지 않습니다.

  3. 이전 성공 결과가 있으면 그 결과와 출처를 보존합니다.

소단원 11.2

독자 수준과 접근성

전공자에게 익숙한 짧은 표현을 처음 온 학생도 이해할까?

준비 개념과 학습 목표

준비 개념

  • 문서 제목과 링크

  • 대상 독자

  • 키보드와 화면 읽기

학습 목표

  • 독자의 현재 지식을 구체적으로 가정한다.

  • 제목·링크·이미지의 의미를 글로 전달한다.

  • 내용 검토와 실제 접근성 검증을 분리한다.

두 독자가 같은 수의 용어를 알아도 같은 설명만 주면 될까요?

앞 본문은 필요한 지식과 독자의 현재 지식 차이를 구체적으로 정합니다. 새 설계의 필요 집합은 {파일 선택, CSV, UTF-8, 헤더, 판본 확인}입니다. CSV는 쉼표로 열을 나누는 텍스트 형식, UTF-8은 문자 인코딩, 헤더는 열 이름, 판본 확인은 제품과 문서 버전을 대조하는 행동입니다. 독자 A는 파일 선택과 헤더를 알고 독자 B는 파일 선택과 UTF-8을 안다고 가정합니다. 실제 조사 결과는 아닙니다.

A에게 필요한 새 설명은 CSV·UTF-8·판본 확인이고 B에게 필요한 새 설명은 CSV·헤더·판본 확인입니다. 같은 개수의 기존 지식이 같은 내용을 뜻하지 않습니다. 두 기존 집합의 합집합은 파일 선택·헤더·UTF-8 세 항목이며 서로 가르쳤다는 증거도 없습니다. 개인별 빈 부분을 확인합니다.

별도 자체 글 점검의 대상은 의미적 제목·목적 링크·입력/오류 설명·그림 대체 정보 네 항목입니다. 이 네 항목이 모두 확인되어도 키보드 조작, 실제 화면 읽기, 전체 WCAG 준수나 초보자의 과제 완료를 자동 확인하지 않습니다. 본문의 정보 그림은 points 헤더와 세 값 4, 6, 8을 전달하므로 같은 정보를 글로 제공할 초안을 작성합니다.

먼저 확인할 개념
  • 독자 수준과 접근성

    필요 지식·설계 가정과 의미적 제목/링크/대체 정보를 연결합니다.

  • 설치·사용·문제 해결

    용어 설명 뒤에도 정확한 입력·오류·기대 결과 조건을 유지합니다.

나이와 직함만으로 지식을 판단하지 않는다

독자가 학교에 다니거나 개발자라는 이유만으로 모든 기술을 안다고 가정하지 않는다. 문서의 작업에 필요한 지식과 현재 아는 내용을 비교한다. 자체 교육 계획은 파일 선택은 알고 CSV·UTF-8·헤더는 모르는 독자를 가정한다. 이는 설계 가정이며 실제 조사 결과가 아니다.

처음 나온 용어에 뜻과 작은 예를 붙이고 준비 학습 링크를 제공한다. 쉬운 단어를 써도 기술 조건을 지우지 않는다. 다른 언어 독자를 위해 지역적 농담이나 관용구보다 뜻이 직접 드러나는 문장을 쓴다.

찾고 해석할 수 있는 구조를 만든다

설치 준비·첫 사용·오류 해결처럼 구역의 역할을 드러내는 제목을 사용한다. 큰 글자 모양만으로 제목을 흉내 내는 대신 실제 heading 구조를 사용해야 화면 읽기 도구도 탐색 의미를 얻는다. 문서 자체의 제목도 다른 페이지와 구별한다.

여기를 누르세요 대신 CSV 예제 파일 받기처럼 링크의 목적을 드러낸다. 기능을 설명하는 그림은 그 정보가 텍스트에도 전달되게 하고 장식 그림은 불필요한 설명을 늘리지 않는다. 그림의 대체텍스트는 파일 이름을 읽어 주는 것으로 충분하지 않을 수 있다.

색과 위치만으로 안내하지 않는다

오른쪽 빨간 버튼만 누르라는 문장은 화면 크기·언어·색 구분 방식이 달라지면 모호하다. 버튼 이름 실행을 쓰고 입력 위치와 결과를 함께 설명한다. 실제 제품이 키보드로 동작하는지는 문서의 표현만으로 확정할 수 없다.

자체 점검표는 제목 의미, 링크 의미, 입력/오류 설명, 그림 대체 정보 네 항목이다. 이 네 항목의 내용 점검을 통과해도 전체 접근성 표준 준수나 실제 보조기술 사용성을 증명하지 않는다. 렌더·키보드·화면 읽기 시험과 학습자 실험은 별도 수행이 필요하다.

독자가 파일 선택은 알고 CSV/UTF-8/헤더는 모른다고 가정한다. 필요한 네 지식 항목 중 설명할 항목 수와, 여기를 눌러요 링크의 개선 문장을 제시하라.

페이지를 다 고쳐도 연결된 예제와 공개 판본까지 확인됐을까요?

앞 본문은 변경 신호의 영향 집합과 문서 담당·검토·반영 책임을 정합니다. 새 자체 자료 목록은 준비 페이지 D1, 사용 페이지 D2, 오류 페이지 D3, 예제 E, 예제 링크 L의 다섯 개입니다. 헤더 변경의 직접 대상은 {D1,D3,E}이고 버튼 변경의 직접 대상은 {D2}입니다. 예제 E가 바뀌면 이를 인용하는 D2와 이를 가리키는 L도 재검토해야 한다는 명시적 연결을 둡니다.

두 변경의 직접 대상 합집합은 {D1,D2,D3,E} 네 개입니다. 연결을 따라 영향 범위를 확장하면 L이 추가되어 다섯 개가 됩니다. 이 목록과 연결은 자체 조사 모형이며 실제 저장소 전체의 완전한 의존 관계를 보장하지 않습니다. 목록 밖의 이미지나 검색 요약도 발견되면 범위를 갱신합니다.

종이 상태는 제품 v4에 맞춰 다섯 자료를 수정하고 저장 검토를 끝냈지만 공개 경로가 아직 v3이라고 정합니다. 저장 검토의 5/5와 공개 반영 확인은 서로 다릅니다. 두 변경이 없는 v3에 대한 옛 검토를 v4 근거로 복사하거나 날짜만 바꾸어 완료 표시하지 않습니다. 보고 양식의 빈칸이 없다는 사실도 재현 성공이 아닙니다.

역할과 변경 신호를 정한다

문서 소유자는 제안과 오류를 받아 상태를 관리하는 담당이다. 제품의 기술 사실을 확인하는 검토자, 초보자의 표현을 살피는 검토자, 승인된 안내를 반영하는 담당의 책임도 정한다. 담당자가 모든 기술을 혼자 증명한다는 뜻은 아니다.

자체 계획은 버튼 이름 변경, 입력 형식 변경, 지원 환경 변경을 문서 검토 신호로 삼는다. 문서만 달력대로 보다가 제품 변경을 놓치지 않도록 기능 변경과 연결한다. 담당이 바뀌면 열린 항목과 근거를 넘긴다.

영향 집합에서 점검 대상을 찾는다

자체 페이지 D1 준비/D2 첫 사용/D3 오류/D4 참고를 둔다. 버튼 변경은{D2}, 헤더 변경은{D1,D2,D3}에 영향을 준다고 기록한다. 두 변경이 함께 있으면 중복 없이 합집합으로 범위를 정한다.

영향 표는 조사 출발점이며 표시된 페이지 밖에도 연결이나 검색 요약이 영향받을 수 있다. 예제 파일, 이미지, 기대 결과와 버전 표시까지 확인한다. 검토 범위를 좁혔다는 이유로 다른 관련 증거를 보지 않는 것은 위험하다.

정보를 받아 실제 확인으로 닫는다

보고 양식에 제품/문서 버전, 발생 위치, 재현 단계, 기대/실제 결과를 요청하면 담당자가 문제를 좁히기 쉽다. 구조화 양식이 채워졌다고 사실 확인이 끝난 것은 아니다. 개인정보와 비밀 키를 포함하지 않도록 안내한다.

자체 상태는 접수→재현 계획→수정→독립 확인→반영 확인으로 정한다. 마지막 검토 날짜만 새로 바꾸지 말고 어떤 버전과 절차를 실제 확인했는지 적는다. 이 자료는 가상 관리 계획이며 실제 앱 재현·외부 보고·배포는 수행하지 않았다.

다른 문제에 적용하기

세 별도 종이 문서 검토를 합니다. ① 가상 v3의 F 성공 뒤 후보 G를 선택합니다. G는 헤더 points 뒤 2, bad, 10입니다. 오류의 데이터 행/물리 줄과 남는 결과 출처를 적고 복사본 G2의 bad를 6으로 고친 뒤 기대 건수·합계·평균을 구하세요. 실제 수정은 하지 않습니다. ② 필요 지식 다섯 항목 중 독자 C는 파일 선택·CSV·UTF-8을 안다고 가정합니다. 필요한 설명 수와 내용을 적으세요. 자체 글 항목 네 개 중 세 개만 확인했을 때 비율과 실제 접근성 시험 상태를 적으세요. ③ 헤더 변경 직접 대상 {D1,D3,E}, 버튼 변경 직접 대상 {D2}이며 E가 바뀌면 D2와 L도 재검토하는 연결입니다. 최종 대상 수를 구하세요. 현재 v4에서 D1과 E만 저장 검토했고 나머지는 미확인, 공개 경로는 v3입니다. 저장 확인률과 공개 완료 여부를 보고하세요.

힌트 1

① 헤더를 포함하면 물리 줄 번호가 1 늘어납니다.

힌트 2

② 필요한 집합에서 기존 집합을 뺍니다. 글 점검과 도구 수행을 분리합니다.

힌트 3

③ 직접 합집합 뒤 연결을 따라 누락을 추가하고 중복은 제거합니다.

풀이와 답 확인

  1. ① bad는 데이터 2행/물리 3줄입니다. G 실패 뒤 이전 성공 결과 출처 F를 보존합니다. 복구한 G2의 예상 값 2,6,10은 건수 3·합계 18·평균 6이며 실제 복구는 미수행입니다.

  2. ② C에게 필요한 설명은 헤더와 판본 확인 두 항목입니다. 자체 글 확인률은 3/4 = 75%이며 실제 키보드·화면 읽기·전체 표준·학습자 시험은 미수행입니다.

  3. ③ 직접 대상 네 개에 E→L 연결의 새 원소를 추가하여 최종 다섯 개입니다. v4 저장 확인은 D1과 E 두 개로 2/5 = 40%이고 공개 경로는 v3라 v4 공개 반영 완료가 아닙니다.

오류 위치는 데이터 2행/물리 3줄이며 남는 결과 출처는 F입니다. G2의 기대 건수는 3, 합계는 18, 평균은 6입니다. C의 설명 대상은 두 항목이고 자체 글 확인률은 75%입니다. 최종 영향 범위는 5개, v4 저장 확인률은 40%이며 공개 v3의 불일치를 남깁니다. 실제 복구·UI·도구·배포·학생 수행은 미수행입니다.
