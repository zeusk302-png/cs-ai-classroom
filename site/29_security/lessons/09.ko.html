소단원 9.1

스푸핑·중간자·DNS

메시지에 적힌 발신 주소만으로 누가 보냈는지 믿어도 될까?

준비 개념과 학습 목표

준비 개념

  • IP 주소와 포트는 통신의 목적지를 나타낸다.

  • DNS 질의에는 이름·종류와 질의 식별자가 있다.

학습 목표

  • 주소 위장과 통신 경로 개입을 구별한다.

  • DNS 응답 대응 검사와 암호학적 인증의 차이를 설명한다.

질문표가 맞으면 응답의 내용까지 믿어도 될까요?

학교 안내문을 받았을 때 내가 보낸 질문과 연결되는지 확인하는 일과 누가 내용을 보증했는지 확인하는 일은 다르다. DNS에서도 이름·종류·클래스와 주소·포트·ID를 맞추는 대응 검사는 신뢰 결론의 한 단계이다. 기다리는 질의가 있어야 한다는 조건도 빠뜨리지 않는다.

여기서는 실제 패킷을 보내지 않고 표의 항목만 비교한다. DNSSEC는 신뢰 관계에 따른 DNS 데이터의 서명을 검증하는 계층이고, TLS의 올바른 상대 확인은 애플리케이션 연결의 상대를 확인한다. 둘 중 하나가 다른 모든 보호와 서비스 가용성을 대신한다고 판단하지 않는다.

먼저 확인할 개념
  • 스푸핑·중간자·DNS

    질의의 이름·종류·클래스와 주소·포트·ID를 비교하는 기본 조건을 확인한다.

  • 방화벽·탐지·분할

    DNS 응답이 방화벽을 통과하더라도 질의 대응과 데이터 인증 질문이 남는 이유를 연결한다.

주장된 주소와 확인된 신원

스푸핑은 주소나 이름 같은 표시를 위장하는 것이다. 패킷 출발지 주소는 메시지의 주장이지 그 주소 소유자의 서명 그 자체가 아니다. 출발지 위조 패킷을 보낼 수 있는 환경과 그렇지 않은 환경은 다르며 네트워크가 모든 위조를 허용한다고 가정하지 않는다.

중간자는 두 통신자 사이에서 메시지를 관찰하거나 바꾸는 위치에 개입한다. 출발지 위조와 중간자 위치 확보는 같은 조건이 아니다. 로컬 주소 해석을 속이는 등 다른 원인이 경로 개입으로 이어질 수 있지만, 여기서는 실제 네트워크에 그런 동작을 실행하지 않고 신뢰 조건을 비교한다.

DNS 응답은 질문과 대응해야 한다

DNS 해석기는 아직 기다리는 질의와 들어온 응답을 대응시킨다. RFC5452의 규칙은 응답 출발 주소/도착 주소·도착 포트·질의 ID·이름·클래스·종류를 원래 질의와 대조하도록 요구한다. ID 하나만 맞다고 다른 이름의 답을 받아들이면 안 된다.

대응 검사에 맞는다는 사실은 암호학적 서명 검증과 다르다. 예측하기 어려운 포트와 ID는 맹목적인 응답 추측을 어렵게 하지만 신뢰 관계를 자동 생성하지 않는다. DNSSEC는 신뢰한 키와 서명을 통해 DNS 데이터 출처와 무결성을 검증하는 별도 계층이며 채널 암호화 자체와 구별한다.

기밀성·무결성·상대 확인

TLS의 목표는 통신 상대 인증, 기밀성과 무결성이다. 이를 얻으려면 애플리케이션이 기대하는 상대 신원을 검증하는 규칙을 제대로 적용해야 한다. 잘못된 인증서 경고를 무시하거나 기대한 사이트와 다른 상대를 허용하면 암호화된 연결만으로 원래 상대를 만났다고 보장할 수 없다.

TLS가 데이터 변조를 검출하도록 설계되었다고 해서 정상 서버 자체의 거짓말·악성 코드·서비스 중단까지 해결하지는 않는다. DNS 데이터 검증과 서버 신원 확인은 보호 대상이 다르다. 어느 표시를 어떤 근거로 신뢰하는지 나누어 설명해야 한다.

질의 대응 검사와 신뢰 결론
조건 또는 단계종이 모형의 판정결론의 범위

대기 질의 있음·항목 모두 일치

대응 검사 통과

내용의 서명이나 무해성을 별도로 증명하지 않음

같은 ID·다른 질문 종류

대응 검사 실패

ID 일치만으로 덮지 않음

서명·신뢰 체인 검증 성공이라는 별도 전제

DNS 데이터 인증 근거

채널 기밀성이나 무중단 서비스의 근거는 아님

먼저 표의 판정을 읽고 마지막 열의 남은 질문을 말해 보자. 이 표는 실제 해석기의 전체 캐시·위임·신뢰 처리 구현이 아니다.

중간 과정을 따라가는 예제

종이 질의는 해석기 192.0.2.10:53000→서버 198.51.100.53:53, ID37, 이름 lesson.test, 종류 A, 클래스 IN이다. 응답은 그 역방향 주소·포트이며 ID37이다. 응답 R1의 질문은 lesson.test/A/IN, R2는 other.test/A/IN, R3는 lesson.test/AAAA/IN이다. 주소·포트와 기타 항목은 동일하다고 두고 질문 대응을 검사하라.

  1. 응답 목적지는 해석기의 원래 출발 주소192.0.2.10과 포트53000에 맞아야 한다. 응답 출발 주소는 원래 질의 목적지198.51.100.53이다.

  2. R1은 ID·이름·종류·클래스가 모두 맞아 이 대응 검사를 통과한다.

  3. R2는 이름이 달라 실패, R3는 종류가 A가 아닌 AAAA라 실패한다. ID37 일치가 이를 덮지 않는다.

  4. R1 통과만으로 서명이 검증되었다거나 악의 없는 응답이라는 결론은 내리지 않는다. 그 검사는 이 문제에 주어지지 않았다.

R1만 질문 대응 검사를 통과한다. 이는 질의-응답 연결 검사 결과이며 DNSSEC 인증 결과가 아니다.

조건을 바꾸어 비교하기

대기 목록에서 질의를 지운 뒤

질의 Q는 ID 12, note.test/A/IN이며 다른 주소·포트 항목은 모두 맞는다. Q가 대기 중일 때 온 R과, Q 처리가 끝나 대기 목록에서 사라진 뒤 도착한 같은 R을 비교하라. 이 모형은 대기 질의만 대응시킨다.

  1. 첫 경우에는 대기 Q가 있으므로 이름·종류·클래스·ID와 주소·포트를 대조한다.

  2. 모두 맞는다는 전제에서 첫 R은 대응 검사를 통과한다.

  3. 둘째에는 대조할 대기 Q가 없어 이 검사를 통과하지 않는다. 실제 중복 응답 처리 구현 전체를 주장하지 않는다.

첫 경우 통과, 둘째 경우 대기 질의 없음으로 실패이다.

비교할 점

값의 일치와 현재 대기 상태라는 두 조건을 구별한다.

독립이라는 가정이 사라진 선택

가상 ID는 0~3, 포트 이름은 P0~P3이다. 모형 A는 두 항목을 독립 균등 선택한다. 모형 B는 ID i를 균등 선택하고 반드시 포트 Pi를 쓴다. 한 정답쌍을 눈감고 맞힐 때 가능한 쌍 수를 비교하라.

  1. A의 가능한 쌍은 4×4=16개이며 각각 확률 1/16이다.

  2. B의 가능한 쌍은 (0,P0),(1,P1),(2,P2),(3,P3) 네 개이며 각각 1/4이다.

  3. B에서 (0,P1)은 발생하지 않는다. 두 목록의 크기를 곱하려면 독립 조건이 필요하다.

A에서 한 고정 쌍의 확률 1/16, B에서 가능한 한 고정 쌍의 확률 1/4이다.

비교할 점

실제 ID·포트 범위나 공격 성공률 대신 상관관계의 효과를 보는 작은 모형이다.

종이와 본문으로 직접 해보기

나머지 항목이 맞더라도 도착 포트가53001인 R4와 ID38인 R5를 판정하라. 별도 가상 모형에서 ID8가지·포트4가지가 독립 균등하고 한 질의가 대기 중이라면 한 번의 맹목적인 정확쌍 추측 확률은?

힌트 보기

R4는 질의의 출발 포트를 비교한다. 가상 경우 수는8×4다.

풀이 보기

R4와 R5는 각각 포트·ID 불일치로 실패한다. 가상 모형의 가능한 쌍은 32개라 한 추측은 1/32이다. 실제 DNS ID 범위나 실제 공격 성공률을 이 장난감 수치로 대체하지 않는다.

오해와 반례

암호화된 연결이면 상대 신원은 검사하지 않아도 된다.

다른 상대와도 암호화된 연결을 만들 수 있다. 기대한 서버 신원의 올바른 검증이 있어야 상대 인증 목표를 적용할 수 있다.

자기점검

DNS 응답 ID가 맞아도 이름이 다르면 대응 검사를 통과하는가?

답과 이유 보기

통과하지 않는다.

질의 이름도 필수 대응 항목이다.

DNSSEC 데이터 서명은 DNS 채널 암호화와 같은가?

답과 이유 보기

다르다.

DNSSEC는 데이터의 출처·무결성 검증이고 채널 보호는 별도다.

위 가상32쌍에서 서로 다른5쌍을 한 번씩 추측하면 정확쌍을 포함할 확률은?

답과 이유 보기

5/32다.

균등한 한 정답쌍과 겹치지 않는5추측 조건이다. 실제 네트워크 타이밍·경쟁 조건은 모형에 없다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

대기 Q는 note.test/A/IN, ID12이다. R1은 같은 질문·ID, R2는 note.test/AAAA/IN·ID12, R3은 note.test/A/CH·ID12이다. 다른 대응 항목은 모두 맞는다. 판정하라.

힌트 1

종류와 클래스도 항목이다.

힌트 2

A와 AAAA, IN과 CH를 따로 비교한다.

풀이와 답 확인

  1. R1은 모두 일치한다.

  2. R2는 종류, R3는 클래스가 다르다.

R1만 대응 검사 통과, R2와 R3 실패이다.

흔한 오답에서 다시 생각하기

ID12가 같으므로 모두 통과한다.

ID는 비교 항목 중 하나이다. 질문의 종류·클래스 불일치는 그대로 남는다.

연습 2 · 오류 찾아 고치기

검토자가 “ID와 포트가 일치했으므로 DNSSEC 서명이 검증되었다”고 적었다. 실제 기록에는 서명·키·신뢰 체인 검증 결과가 없다. 결론을 고쳐라.

힌트 1

검사한 항목과 결론을 연결한다.

힌트 2

서명 검증에 필요한 기록이 주어졌는지 찾는다.

풀이와 답 확인

  1. ID·포트 대응만 기록되었다. 다른 대응 항목도 확인 여부를 따로 적는다.

  2. DNSSEC 검증은 기록이 없으므로 수행 결과를 결론에 추가하지 않는다.

ID·포트가 일치한다는 제한된 관찰만 남기고, 전체 대응 및 DNSSEC 검증은 추가 확인 사항으로 적는다.

흔한 오답에서 다시 생각하기

DNS 응답이 왔으니 서명도 검사되었을 것이다.

응답 도착은 서명 검사 실행의 증거가 아니다. 확인한 항목까지만 결론을 줄인다.

연습 3 · 직접 만들어 보기

같은 ID12의 질의 Q1 note.test/A/IN과 Q2 note.test/AAAA/IN이 동시에 대기한다. R의 질문은 Q2와 같고 나머지 항목도 Q2와 일치한다. 어느 질의에 연결할지 비교표를 만들어라.

힌트 1

Q1과 Q2를 별도 행으로 둔다.

힌트 2

ID 외에 질문 종류를 확인한다.

풀이와 답 확인

  1. Q1 행은 ID 일치·종류 불일치이다.

  2. Q2 행은 ID와 질문 및 나머지 항목 일치이다.

Q2에만 대응한다. ID만을 목록의 유일한 키로 쓰는 모형의 오류를 설명한다.

흔한 오답에서 다시 생각하기

ID가 같아 Q1부터 처리한다.

종류까지 포함한 대응이 필요하다. 이 문제는 실제 해석기의 자료구조 구현을 지정하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

독립 균등한 가상 16쌍 중 한 쌍이 정답이다. 서로 다른 두 고정 쌍을 검사할 때와 같은 쌍을 두 번 검사할 때 정답을 포함할 확률을 비교하라.

힌트 1

정답이 포함될 후보 집합 크기를 센다.

힌트 2

반복 검사로 새 후보가 늘어나는지 본다.

풀이와 답 확인

  1. 서로 다른 두 쌍의 집합 크기는 2이다.

  2. 같은 쌍 두 번의 집합 크기는 1이다.

각각 2/16=1/8과 1/16이다. 고정된 한 정답·타이밍 없는 집합 모형이다.

흔한 오답에서 다시 생각하기

검사를 두 번 하면 항상 2/16이다.

준비 개념과 학습 목표

준비 개념

  • 주소·포트·프로토콜을 조건으로 비교한다.

  • 기본값과 먼저 맞는 조건 규칙을 읽는다.

학습 목표

  • 패킷 필터·상태 추적·탐지 역할을 구별한다.

  • 서비스 구역 사이의 최소 허용 규칙을 손 추적한다.

방화벽을 통과한 응답과 새 연결을 어떻게 구별할까요?

기본 본문의 I·W·D·M은 인터넷·웹·데이터베이스·관리 구역이다. 신규 연결을 여는 규칙과 이미 허용된 세션의 응답 규칙은 다르다. 이 보강에서는 두 경우를 별도 입력으로 적고, 제품의 상태 처리 전체를 간단한 표로 대체했다고 명시한다.

경보도 또 다른 정보이다. 탐지 결과와 실제 공격 여부를 각각 알고 있는 가상 표에서만 오탐·미탐을 계산한다. 실제 현장에서는 정답 판정 자체가 어려울 수 있다. 경보가 적다는 이유로 탐지가 좋다고, 경보가 많다는 이유로 모두 차단해야 한다고 단정하지 않는다.

먼저 확인할 개념
  • 방화벽·탐지·분할

    신규 연결 규칙과 상태표에 기록된 응답을 구별하는 기준을 확인한다.

  • DoS·증폭·가용성

    필터의 위치가 링크 과부하에 미치는 영향을 경계 정책과 연결한다.

통과 정책과 세션 기억

방화벽은 네트워크 경계를 지나는 통신을 정책에 따라 허용·차단한다. 패킷 필터는 출발/도착 주소·포트·프로토콜 같은 항목을 비교한다. 상태 추적 방화벽은 앞서 시작한 연결 정보를 기억하고 후속 패킷이 그 세션의 예상 상태와 맞는지 추가로 검사한다.

TCP 플래그에 연결된 것처럼 표시되었다고 실제 상태표에도 연결이 있다고 단정하지 않는다. UDP에는 TCP 같은 연결 수립 절차가 없어 상태 추적은 요청/응답 주소·포트와 시간 제한을 이용하는 방식 등으로 구현될 수 있다. 제품마다 세부 규칙은 다르다.

탐지는 근거와 오류를 함께 보기

침입 탐지는 의심스러운 패턴이나 평소와 다른 통신을 관찰해 알린다. 탐지 경보만으로 모든 경우의 공격이 확정되는 것은 아니며 정상 통신을 잘못 알리거나 공격을 놓칠 수 있다. 차단 기능을 가진 예방 장치와 관찰·경보만 하는 구성을 구별한다.

허용된 웹 포트 안에도 취약한 요청이 있을 수 있다. 암호화된 내용은 경계 장치가 직접 읽지 못할 수 있고 관찰 위치·복호화 정책·호스트 로그 등의 조건을 고려해야 한다. 따라서 하나의 장치가 모든 문제를 검사했다는 결론보다 어떤 통신과 내용을 실제 보았는지 확인한다.

구역 분리와 필요한 길만 열기

공개 웹 서버 구역과 내부 데이터베이스 구역을 나누고 필요한 경로만 열면 공개 서버가 외부에 노출되어도 내부 전체에 자유롭게 접근하는 길을 줄일 수 있다. 구역 이름만 붙이고 실제 경계를 우회하는 통신이 가능하면 이 효과를 주장하기 어렵다.

자체 예제는 먼저 맞는 규칙을 적용하고 마지막에 기본 거부한다. 인터넷→웹의443, 웹→DB의5432, 관리→웹의22만 허용한다. 이들은 교육용 신규 연결 정책이며 실제 서비스 설정이나 연결의 응답 처리 전체를 구현한 규칙이 아니다. 되돌아오는 트래픽에는 별도의 상태 추적 규칙이 필요하다.

중간 과정을 따라가는 예제

가상 구역은 인터넷 I, 웹 W, DB D, 관리 M이다. 신규 TCP 연결만 검사한다. 규칙1 I→W:443허용,2 W→D:5432허용,3 M→W:22허용,4 그외거부다. 흐름 a I→D:5432,b I→W:443,c W→D:22,d M→W:22를 판정하라.

  1. a는 규칙 1의 목적지가 W와 달라 실패하고 2/3의 출발 구역도 달라 기본 거부다.

  2. b는 규칙 1에 맞아 허용이다. c는 규칙 2의 포트 5432와 달라 기본 거부다.

  3. d는 규칙 3에 맞아 허용이다. 네 흐름 중 허용 2/거부 2다.

  4. 허용 b의 요청이 애플리케이션 취약점을 악용하는지는 이 주소·포트 규칙만으로 판정하지 않았다.

허용은 b,d 두 개다. 신규 연결의 경로 제한만 검토했으며 요청 내용의 무해성을 증명하지 않았다.

조건을 바꾸어 비교하기

맨 앞의 거부가 뒤의 허용을 가리기

신규 TCP만 검사한다. 순서 A는 I→전체 거부, I→W443 허용, 그외 거부이다. 순서 B는 I→W443 허용, I→전체 거부, 그외 거부이다. 먼저 맞는 규칙을 적용하며 I→W443와 I→D443을 비교하라.

  1. A의 두 입력은 맨 앞 I 출발 거부에 맞는다.

  2. B의 I→W443는 첫 허용에 맞고, I→D443는 첫 규칙 목적지 불일치 뒤 둘째 거부에 맞는다.

  3. 의도한 예외를 넓은 거부 앞에 놓았는지 확인한다.

A는 두 입력 모두 거부, B는 웹443만 허용하고 DB443은 거부이다.

규칙 집합의 구성뿐 아니라 순서가 정책을 바꾼다.

경보 수가 같은 두 탐지기

가상 100건 중 실제 공격 10·정상 90건이다. 탐지기 P는 공격 8·정상 9건에 경보, Q는 공격 4·정상 13건에 경보한다. 정답 표는 문제에 주어져 있다.

  1. P는 경보 17건, 놓친 공격 2건, 경보 중 실제 공격 8/17이다.

  2. Q도 경보 17건, 놓친 공격 6건, 경보 중 실제 공격 4/17이다.

  3. 공격 탐지 비율은 P 8/10, Q 4/10이고 정상 오경보 비율은 9/90,13/90이다.

경보 총수가 같아도 오류 구성과 탐지 비율이 다르다.

경보 개수만 비교하지 않고 분모와 정답 범주를 함께 적는다.

연습 1 · 값과 상태 예측

신규 TCP 규칙은 I→W443, W→D5432, M→W22만 허용하고 그외 거부다. M→D22, W→D5432, D→W5432 신규 연결을 판정하라.

힌트 1

힌트 2

풀이와 답 확인

  1. M→D는 관리 규칙의 목적지 W와 다르다.

  2. W→D5432만 두 번째 허용과 일치한다. D→W는 반대 방향 신규이다.

차례로 거부·허용·거부이다.

연습 2 · 오류 찾아 고치기

종이 상태표에는 W:50000→D:5432 세션 S만 있다. 기록 P는 D:5432→W:50000이며 S의 예상 응답이라는 전제, Q는 D:5432→W:50001이며 기존 연결 같다는 플래그만 있다. “둘 다 플래그가 있어 통과”를 고쳐라.

힌트 1

포트가 상태표의 역방향과 맞는지 비교한다.

힌트 2

플래그 주장과 기억된 세션을 구별한다.

풀이와 답 확인

  1. P는 주어진 세션과 예상 응답 조건에 맞는다.

  2. Q의 W 목적지 포트50001은 상태표50000과 다르다.

이 간단한 응답 모형에서는 P만 통과, Q는 상태 불일치다. 실제 제품의 나머지 검사는 별도다.

흔한 오답에서 다시 생각하기

플래그가 기존 연결이면 상태표는 필요 없다.

플래그는 패킷의 값이다. 실제 기억된 세션과 대응하는지 확인해야 한다.

미경보 공격은5−3, 미경보 정상은45−6이다.

  2. 미경보 행은 공격2·정상39이며 총50이다.

소단원 9.3

DoS·증폭·가용성

답을 위조하지 않고도 서비스를 쓰지 못하게 할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 바이트 수와 초당 전송량을 구별한다.

  • 제한된 처리 용량과 대기열의 초과를 계산한다.

학습 목표

  • 기밀성과 별도로 가용성 위협을 설명한다.

  • 반사·증폭과 병목 위치를 구별하여 대응을 비교한다.

대기열이 유한하면 초과 유입은 어디로 갈까요?

초당 유입량과 저장된 양은 단위가 다르다. 기본 본문의 무한 대기열은 초과율에 시간을 곱해 누적량을 계산한다. 실제 유한 버퍼를 이해하려면 담을 공간을 먼저 정하고, 공간이 다 차면 이 모형에서 초과 바이트가 버려진다고 추가한다.

아래 계산은 1초 간격의 유체 모형이다. 각 구간 동안 일정한 유입과 용량을 가정하고 패킷 경계·재전송·우선순위를 제외한다. 자체 수치와 필터 비율은 실제 서비스의 성능이나 공격 시험 결과가 아니다. 정상 요청도 과부하와 제한의 영향을 받을 수 있음을 함께 본다.

먼저 확인할 개념
  • DoS·증폭·가용성

    초당 유입량과 링크 용량 및 무한 대기열 가정을 먼저 확인한다.

  • 스푸핑·중간자·DNS

    주소 위조와 상대 인증의 경계를 가용성 보호 범위와 비교한다.

무엇이 먼저 가득 차는가

서비스 거부 DoS는 정상 사용자가 유용한 서비스를 받지 못하게 자원을 압박하거나 기능을 방해하는 공격이다. 링크 대역폭·CPU·메모리·연결 상태·외부 의존 서비스 등 병목은 다양하다. 여러 출처가 관여하는 분산 DoS는 하나의 출발지 차단만으로 다루기 어려울 수 있다.

비슷한 과부하가 인기 행사처럼 정상 사용자의 집중 접속에서도 발생할 수 있다. 트래픽 증가만 보고 모든 사용자를 공격자로 단정하지 않는다. 평소 기준선·오류·요청 특성·여러 관찰 지점을 같이 보며, 용량 계획과 공격 대응은 일부 수단을 공유한다.

반사와 증폭은 다른 관점

반사는 요청을 받은 중간 서비스가 지정된 주소로 응답하며 피해 쪽에 트래픽이 도착하는 구조다. 증폭은 작은 유발량보다 큰 응답·작업이 생기는 양적 효과다. 일부 네트워크 반사 공격은 요청 출발지를 피해 주소로 위조할 수 있다는 조건이 필요하다. 여기서는 패킷 생성 방법 없이 가상 바이트 관계만 계산한다.

출발지 주소가 소속 네트워크의 허용 범위를 벗어나면 걸러내는 필터는 이런 위조 조건을 줄이는 수단이다. 그렇지만 올바른 주소를 사용하는 대량 요청까지 사라지지는 않는다. 인증, 요청 제한, 서비스 구성, 상위 네트워크 협조와 여러 보호 지점을 함께 고려한다.

혼잡 지점보다 앞에서 줄이기

접속 링크가 먼저 가득 찼다면 서버에서 뒤늦게 패킷을 버려도 이미 그 링크를 지나온 바이트는 돌아오지 않는다. 상위 위치에서 불필요한 유입을 줄이는 대응이 필요한 이유다. 반대로 링크는 여유지만 비싼 애플리케이션 연산이 병목이면 요청 처리와 작업 예산을 제한하는 방안이 맞을 수 있다.

요청 제한도 정상 사용자에게 영향을 줄 수 있다. 한 IP가 여러 정상 사용자를 대표할 수 있으므로 주소 하나당 제한을 모두에게 같은 품질로 이어지는 해결책이라고 주장하지 않는다. 장애 관찰·우회·복구·정상 사용자 영향까지 함께 평가해야 가용성 대응의 결과를 판단할 수 있다.

중간 과정을 따라가는 예제

완전히 가상인 응답 서비스에서 요청 한 건은 80바이트, 응답은 1200바이트다. 초당 1000요청에 모두 응답하며 피해 링크 용량은 초당 1,000,000바이트, 정상 유입은 초당 200,000바이트라고 가정한다. 헤더와 손실은 제외한다. 응답/요청 바이트 비와 피해 쪽 총유입을 계산하라.

  1. 한 건의 비는 1200/80=15다. 초당 요청 바이트는 80×1000=80,000이다.

  2. 초당 응답 바이트는 1200×1000=1,200,000으로 가정된 15배다.

  3. 정상 유입을 더하면 1,400,000바이트/초다. 링크 용량 1,000,000보다 400,000바이트/초 초과다.

  4. 같은 초과가 5초 이어지고 무한 대기열이라는 별도 가정이면 400,000×5=2,000,000바이트가 쌓인다. 실제 유한 대기열은 손실이 생길 수 있어 이 값을 실측 대기량이라고 부르지 않는다.

바이트 비15, 총유입1.4MB/초, 용량초과0.4MB/초다. 여기의 MB는10⁶바이트다.

버퍼가 차는 시점과 손실

빈 버퍼 용량600,000바이트다. 3초 동안 유입1,400,000·서비스1,000,000바이트/초로 일정하며 초과만 저장하고 가득 차면 버린다. 각 초 끝의 저장량과 누적 손실을 구하라.

  1. 초과 유입량은 초당 400,000바이트다. 1초 끝에는 버퍼에 400,000바이트가 저장되고 누적 손실은 0바이트다.

  2. 2초까지 누적 초과량은 800,000바이트다. 이 중 버퍼 한도인 600,000바이트가 저장되고 누적 손실은 200,000바이트다.

  3. 3초까지 누적 초과량은 1,200,000바이트다. 버퍼 저장량은 600,000바이트이고 누적 손실은 600,000바이트다.

1초 끝의 저장량은 400,000바이트, 누적 손실은 0바이트다. 2초 끝의 저장량은 600,000바이트, 누적 손실은 200,000바이트다. 3초 끝의 저장량은 600,000바이트, 누적 손실은 600,000바이트다.

비교할 점

유한 버퍼는 저장량을 제한하며 누적 초과량 전체를 저장했다고 주장할 수 없다.

같은 유입 감소의 다른 위치

응답1,200,000·정상200,000바이트/초, 링크 용량1,000,000이다. 정상 유입은 그대로 두고 응답만 50% 줄이는 필터를 링크 이전 또는 이후에 둔다.

  1. 링크 이전은 응답600,000+정상200,000=800,000바이트/초가 링크에 도착한다.

  2. 링크 이후라면 링크 유입은 그대로1,400,000이다. 서버에서 남는 양의 계산과 링크 혼잡은 구별한다.

  3. 이미 쌓인 버퍼가 있다면 링크 유입800,000은 여유200,000바이트/초를 만들어 이상화 모형에서 버퍼를 비울 수 있다.

이전 필터는 링크 용량 안, 이후 필터는 링크 유입 초과가 남는다.

비교할 점

필터 비율 외에 자원의 병목 위치를 반드시 적는다.

연습 3 · 직접 만들어 보기

정상0.2MB/초·추가 응답1.2MB/초·링크1MB/초다. MB=1,000,000바이트다. 링크 이전에서 응답만 비율 x만큼 제거할 때 용량 이내가 되는 최소 x를 식과 함께 구하라.

힌트 1

남은 응답은1.2(1−x)이다.

힌트 2

0.2+1.2(1−x)≤1을 푼다.

풀이와 답 확인

  1. 1.4−1.2x≤1이므로1.2x≥0.4이다.

  2. x≥1/3이며 x는0부터1까지의 제거 비율이다.

최소1/3이다. 정확히1/3이면1MB/초로 남는 여유는0이며 실제 운용 안전 여유를 증명하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

가상1초 구간의 IP별 제한은 각 IP당 최대10요청이며 남는 요청을 버린다. 같은 공용 IP를 쓰는 정상 사용자4명이 각3요청을 보내면, 서로 다른 IP를 쓸 때와 받아들인 총량을 비교하라. 누가 버려지는지는 순서가 주어지지 않았다.

힌트 1

공유 IP에서는4×3을 한 제한과 비교한다.

힌트 2

독립 IP에서는 각각3이10보다 작다.

풀이와 답 확인

  1. 공유 IP 총12 중최대10만 받아들여2개가 버려진다.

  2. 서로 다른 IP에서는12개 모두 제한 안이다. 누구의 요청이 버려지는지는 순서 없이 결정하지 않는다.

공유10·독립12요청이다. IP별 제한은 정상 사용자에게도 영향을 줄 수 있다.

흔한 오답에서 다시 생각하기

각 사용자3개이므로 공유 IP도 모두 통과한다.

제한의 집계 키는 사용자 이름이 아니라 IP라는 조건이다. 여러 정상 사용자가 같은 키를 공유할 수 있다.

유한 버퍼의 초과율×시간은 무엇을 뜻하는가?

설명 기준 확인

누적 초과량이며 전부 저장되었다는 뜻은 아니다. 저장 한도와 손실을 따로 계산해야 한다.

출발지 위조 방지와 모든 DoS 방지는 같은가?

설명 기준 확인

주소 범위 검사로 위조 조건을 줄여도 유효 주소의 대량 요청과 다른 병목은 남는다.

동일 15배라도 요청 빈도가 초당 100이면 응답 120,000+정상 200,000=320,000바이트/초다. 비율만으로 장애를 판정하지 말고 절대량과 병목 용량을 비교하라. 모든 수치는 자체 가정이며 실제 반사 서비스·공격·부하 시험은 수행하지 않았다.

다른 문제에 적용하기

학교 자료실의 세 보호 계층 연결하기

서로 다른 보호 계층을 연결하는 자체 종이 모형이다. DNS에는 note.test/A/IN·ID 12 질의가 대기한다. 응답의 모든 주소·포트·ID는 맞지만 질문 종류는 AAAA다. 신규 TCP 규칙은 I→W의 443번 포트와 W→D의 5432번 포트만 허용하고 나머지는 거부한다. I→D의 5432번 포트 신규 연결을 판정하라. 링크에는 정상 200,000바이트/초와 추가 1,200,000바이트/초가 들어온다. 링크 용량은 1,000,000바이트/초이고 빈 버퍼의 한도는 600,000바이트다. 2초 동안 일정한 유체 모형에서 저장량과 누적 손실을 구하라. 링크 이전에서 추가 유입량만 50% 제거하는 대안의 유입량도 계산하고 세 보호 계층의 판정을 구별하라.

힌트 1

DNS 종류와 방화벽 목적지를 각자 비교한다.

힌트 2

버퍼에는 누적 초과 중600,000까지만 저장한다.

풀이와 답 확인

  1. DNS 응답의 질문 종류가 A와 AAAA로 달라 대응 검사는 실패한다. I→D의 5432번 포트 신규 연결은 어느 허용 규칙에도 맞지 않아 거부된다.

  2. 전체 링크 유입량은 1,400,000바이트/초다. 링크 용량을 빼면 초과량은 400,000바이트/초이고, 2초 동안 누적 초과량은 800,000바이트다.

  3. 2초 끝의 버퍼 저장량은 600,000바이트다. 누적 손실은 200,000바이트다. 링크 이전 필터는 추가 유입을 600,000바이트/초로 줄이므로 정상 유입을 포함한 총유입은 800,000바이트/초다.

  4. 각 계산은 별도 경계의 종이 판정이다. 실제 DNS 질의·패킷·방화벽·부하 시험의 수행 결과로 주장하지 않는다.

DNS 대응 검사는 실패하고 신규 연결은 거부된다. 2초 끝의 저장량은 600,000바이트, 누적 손실은 200,000바이트다. 링크 이전의 50% 필터를 적용하면 총유입은 800,000바이트/초로 링크 용량 안이다.

해결한 뒤 점검할 것

  • 질문 종류·규칙 방향·병목 위치를 구별한다.

  • 저장량과 누적 손실을 바이트 단위로 나눈다.

  • 가상 수치와 실제 서비스 검증을 혼동하지 않는다.

DNS 대응 항목을 손대조했다. 독립 선택의 가능한 쌍은 16개, 연동 선택은 4개다. 서로 다른 두 후보의 정답 포함 확률은 1/8이고 같은 후보 반복은 1/16이다. 신규 연결의 첫 일치 규칙을 대조했다. 각 17건의 경보 중 공격 비율은 P의 8/17과 Q의 4/17이다. 별도 50건 표에서는 경보 중 공격 3/9, 공격 탐지 3/5, 정상 오경보 6/45다. 초과 유입량 400,000바이트/초를 누적하면 1초 끝의 저장량은 400,000바이트이고 손실은 0바이트다. 2초 끝의 저장량은 600,000바이트이고 누적 손실은 200,000바이트다. 3초 끝의 저장량은 600,000바이트이고 누적 손실은 600,000바이트다. 유입을 800,000바이트/초로 줄이면 3초에 버퍼가 비워진다. 별도 증폭 사례의 총유입 45,000바이트/초는 용량 100,000바이트/초보다 작다. 추가 유입의 최소 제거 비율은 1/3이다. 공유 IP의 수락량은 10요청이고 독립 IP의 수락량은 12요청이다. 이 수동 명료화 부분과 기존 수치·조건을 저장 전 다시 대조했으며 실제 서비스·패킷·방화벽·학생 실행은 수행하지 않았다.
