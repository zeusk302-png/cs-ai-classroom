소단원 3.1

버퍼·정수·use-after-free

길이는 양수인데 왜 저장 공간이 부족할까? free 뒤 보이던 값이 남아 있으면 읽어도 될까?

준비 개념과 학습 목표

준비 개념

  • 버퍼는 정해진 수의 원소를 담는 저장 공간이다. 용량 C와 현재 사용량 n은 다르다. C=4 인 배열의 원소 인덱스는 0,1,2,3 이다. 자가진단: 내용 세 글자와 종료 문자 한 칸은 합 네 칸이다.
  • 정수 표현 범위는 타입이 표현할 수 있는 값의 집합이다. 계산 전 정수 승격·통상 산술 변환으로 실제 연산 타입이 결정된다. 작은 타입의 저장 폭을 곧바로 연산 폭으로 사용하지 않는다.
  • 객체 수명은 프로그램이 그 객체에 접근할 수 있도록 저장이 보장되는 기간이다. 별칭은 서로 다른 이름/포인터가 같은 객체를 가리키는 관계다. 한 별칭을 지워도 나머지 별칭이 자동 갱신되지는 않는다.

학습 목표

  • 읽기·쓰기 경계와 종료 문자 공간을 판정한다.
  • 연산 타입과 길이 곱의 표현 가능성을 먼저 확인한다.
  • 해제 전후 객체 수명과 모든 별칭의 접근 권한을 구별한다.

경계 안의 원소와 끝 다음 위치

공간 안전성은 읽거나 쓰는 위치가 살아 있는 해당 객체의 유효 범위에 있는 성질이다. C11 에서 a가 N개 원소 배열이고 0≤i<N이면 a+i로 해당 원소를 가리킬 수 있다. a+N은 끝 다음 포인터로 형성할 수 있지만 그 위치를 원소처럼 역참조할 수 없다. 같은 주소 주변에 다른 자료가 있다는 관찰은 배열 경계 밖 접근을 합법으로 만들지 않는다.

문자열 내용 길이 L을 종료 문자까지 복사하려면 L+1 칸이 필요하다. 목적 버퍼 용량 C에 대해 C>0 이며 L≤C−1 을 확인하면 종료 칸도 확보된다. 이 조건은 원본이 실제 그 길이의 읽을 수 있는 문자열이고, 목적이 쓰기 가능하며, 선택한 복사 함수의 겹침 계약도 지킨다는 전제와 함께 쓴다. 길이 값 하나가 포인터의 유효성과 수명을 증명하지 않는다.

길이 계산을 수행하기 전에 검사한다

수학에서 원소 n개와 원소 크기 s의 총량은 ns다. 실제 정수 연산에서는 결과 타입 범위 안인지 먼저 확인한다. C11 의 연산 결과 타입이 unsigned이면 최댓값 M을 넘는 산술 결과는 M+1 을 법으로 줄어든다. 정의된 모듈러 동작이라도 할당 크기로 쓰려던 수학적 길이를 잃을 수 있다. signed 결과 타입의 표현 불가능한 산술 결과는 UB이며 작은 음수 결과나 반드시 크래시라는 예상값을 주지 않는다.

양의 s와 0≤n≤M에서 n≤floor(M/s)를 검사하면 ns≤M을 확보한 뒤 곱할 수 있다. 실제 C에서는 SIZE_MAX/sizeof(element) 검사를 실제 연산 타입·변환 규칙에 맞춰 적용한다. 음수 입력은 크기 타입으로 변환하기 전에 거절하고, 덧셈 n+h도 n≤M−h처럼 계산 전 검사한다. 합법적인 작은 할당 크기가 나왔다는 사실만으로 원래 요청이 작았다고 결론내리지 않는다.

수명이 끝난 객체는 남은 바이트로 복구되지 않는다

시간 안전성은 접근 시 대상 객체의 수명이 계속 유효한 성질이다. 할당 성공한 객체 O를 p,q가 가리키고 free(p)로 해제하면 O의 수명이 끝난다. C11 에서는 O 또는 끝 다음을 가리키던 포인터 값이 indeterminate가 된다. q를 역참조하는 use-after-free뿐 아니라 그러한 값을 다시 읽어 쓰는 행위도 허용된 정상 포인터 연산이라고 가정하지 않는다. free(NULL)는 아무 작업을 하지 않는 별도 규칙이다.

free(p) 뒤 p=NULL을 대입하는 것은 해제된 이전 p값을 읽지 않고 p 객체에 새 값을 쓰지만 q까지 고치지 않는다. 살아 있는 소유권 경로를 설계해 접근이 모두 끝난 뒤 한 번만 해제하거나, 다른 접근자가 남으면 해제를 늦춰야 한다. C++에서도 delete와 객체 수명, 컨테이너 재할당에 따른 무효화 조건을 해당 표준/API로 따로 확인해야 한다. 여기의 free·승격 세부는 C11 조건이며 C++ 전체 규칙으로 복사하지 않는다.

중간 과정을 따라가는 예제

서로 독립된 종이 사례를 판정하라. 문자열 버퍼 C=8 에 L=7 과 L=8 을 종료 문자까지 복사한다. 별도의 가상 unsigned 연산은 결과 범위 0..255 인 것으로 정의하며 n=70,s=4 이다. 성공한 할당 O에 p,q 별칭이 있고 해제 후 p에 NULL을 대입한다.

  1. 첫 복사는 L+1=8 이므로 조건 L≤C−1 을 만족한다. 쓰기 인덱스는 0..7 이고 마지막 칸은 종료 문자다.
  2. 둘째는 L+1=9>8 이므로 거절한다. 검사 없이 복사한 실제 C 프로그램의 마지막 값이나 후속 제어흐름은 예측하지 않는다.
  3. 가상 결과 타입의 수학적 곱은 280, 모듈러 값은 280 mod256=24 다. 사전검사 기준 floor(255/4)=63 이므로 70 은 거절된다. 이는 실제 unsigned char 곱의 승격 결과를 측정한 사례가 아니다.
  4. 해제 전에는 p,q가 O를 가리킨다. 해제 뒤 O의 수명은 종료된다. p에 NULL을 새로 쓰더라도 q의 이전 값 접근은 정상화되지 않는다. q의 출력값은 제시하지 않는다.

첫 복사는 조건부 허용, 둘째는 거절이다. 가상 곱은 24 로 줄지만 할당용 계산은 사전 거절해야 한다. 해제 후 별칭 접근은 허용되지 않으며 UB의 예상 출력은 없다.

종이와 본문으로 직접 해보기

C=6 인 버퍼에 내용 길이 5/6 을 복사할 조건을 판정하라. 같은 0..255 가상 연산에서 n=60,s=4 도 검사하라. p,q 별칭 중 p만 NULL로 대입하고 객체를 아직 해제하지 않았다면 q와 객체 수명은 어떻게 되는가?

힌트 보기

종료 문자 한 칸을 더하고 floor(255/4)=63 과 비교한다. 포인터 변수 변경과 free로 객체 수명을 끝내는 사건을 구별한다.

풀이 보기

길이 5 는 6 칸이라 조건부 허용, 길이 6 은 7 칸이라 거절이다.60≤63 이며 240≤255 라 곱이 보존된다. 해제하지 않았다면 p 재대입만으로 O의 수명이 끝나지 않고 q가 가리키는 살아 있는 O는 유지된다. 이후 유일한 소유 경로를 잃어 누수가 생기는지도 별도 확인한다.

오해와 반례

unsigned를 쓰면 메모리 문제가 없고 free 뒤 같은 값이 보여도 안전하다.

가상 70×4 의 24 는 정의된 값이지만 필요한 280 칸을 대표하지 못한다. 해제된 바이트가 그대로인 한 관측도 객체 수명을 복원하지 않는다. 범위와 수명은 출력이 아니라 언어·객체 계약으로 판정한다.

자기점검

N개 배열의 a+N은 형성 가능하므로 그 원소도 읽어도 되는가?

답과 이유 보기

아니다.

끝 다음 포인터 형성과 그 위치의 역참조는 다른 조건이다.

가상 0..255 unsigned 결과의 70×4 가 24 이면 수학적 280 도 24 와 같은 할당 요구인가?

답과 이유 보기

아니다.

모듈러 결과와 원래 필요한 총량이 달라 사전 길이 검사에서 거절한다.

free 후 p=NULL이면 같은 O를 가리키던 q도 자동으로 NULL인가?

답과 이유 보기

아니다.

포인터 객체 대입은 다른 별칭을 갱신하지 않는다. 해제된 대상의 수명은 끝났다.

한 단계 더

증명: 0≤n≤M, s≥1 인 정수에서 n≤floor(M/s)이면 ns≤M이고, n>floor(M/s)이면 ns>M이다. q=floor(M/s), M=qs+r,0≤r<s로 쓰면 n≥q+1 인 경우 ns≥qs+s>qs+r=M이다. 따라서 이 검사는 이 조건의 곱 표현 가능성에 필요충분이다. 그러나 할당 성공·실제 객체 크기·정렬·쓰기 권한·수명은 추가 전제다. 내용 L칸과 종료 1 칸은 L+1≤C와 L≤C−1 이 C≥1 에서 동치다. 수명 안전성은 모든 접근 사건 e의 시점이 해당 객체의 생존 구간 안에 포함되는 별도 명제이며, 길이 부등식만으로 이를 증명할 수 없다.

소단원 3.2

입력과 제어흐름

내용을 글자로 읽었는데 왜 다음에 실행할 동작까지 바뀔 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 입력은 함수 밖에서 들어오는 값이며 믿을 수 있는 상태라는 뜻은 아니다. 파싱은 바이트/필드를 정해진 자료 구조로 해석하는 단계이고, 검증은 해석된 값이 계약을 만족하는지 확인하는 단계다.
  • 제어흐름은 조건 분기·호출·반환으로 다음 실행 위치가 정해지는 관계다. 데이터는 그 계산에 쓰는 값이다. 조건에 입력을 쓰는 합법적 분기와 제어 자료가 훼손되는 상황을 구별한다.
  • 자가진단: 종이 명령표{0:보기,1:저장}에서 입력 2 는 어느 함수도 자동으로 뜻하지 않는다. 표의 정의역 밖이면 거절하도록 계약을 정한다.

학습 목표

  • 명시한 길이와 실제 입력 크기를 사용 전 대조한다.
  • 유효 명령 종류·수명·권한을 다른 검사 단계로 구분한다.
  • 메모리 안전성·제어흐름 무결성·요청 권한의 보장 차이를 논증한다.

신뢰경계를 넘어온 값은 먼저 해석한다

자체 패킷 모형은 이미 읽을 수 있는 바이트열, 정수로 해석 완료된 필드 h=내용 길이, op=명령, 실제 이용 가능한 내용 r을 받는다. 복사 버퍼 C는 따로 정해진다. h가 선언한 길이라고 h칸이 실제 존재하지 않는다. h≤r과 h≤C를 접근 전에 검사하면 이 모형에서 source와 destination의 범위를 동시에 제한한다. 종료 문자열이라면 h+1 의 칸과 실제 종료 검사는 별도 계약이다.

정수 해석 오류·음수·단위·버전·문자 인코딩을 구분하고 어떤 기준으로 거절했는지 명시한다. 더 긴 원시 입력을 먼저 짧은 타입으로 줄인 뒤 검사하면 원래 크기를 잃을 수 있다. 또 검증한 저장 공간이 사용 사이에 교체·해제·수정될 수 있으면 검증과 사용의 상태가 달라진다. 이 소단원은 입력과 정책이 호출 동안 고정된 순차 모형으로 한정한다.

데이터 접근 오류가 동작을 바꾸는 여러 경로

메모리 오류는 내용 자체를 손상시키거나 제어에 쓰는 값에 영향을 줄 수 있다. 특정 구현에서는 함수 포인터·반환 정보의 손상 또는 조건검사의 자료 손상으로 후속 동작이 달라질 수 있다. 표준 C의 경계 밖 쓰기는 UB이므로 모든 배열 바로 뒤에 반환 주소가 있다는 배치 그림을 일반 규칙으로 삼지 않는다. 읽기 범위 위반도 공개하면 안 되는 자료 노출 위험을 만들 수 있다.

허용된 함수 호출 표를 유지하는 것과 요청자의 저장 권한을 유지하는 것도 다르다. 정상 명령 op=1 이 허용 함수 save로 연결되어도 주체가 그 자료를 저장할 권한이 없을 수 있다. 반대로 모든 입력이 특정 문자로 이루어졌다는 검사는 버퍼 길이·객체 수명·권한을 자동 확보하지 않는다. 각각의 성공 조건을 따로 명시하고 결합해 사용한다.

검사 뒤 성공 사건을 제한한다

자체 검사 순서는 먼저 h의 비음수 정수 계약, 이어 h≤r 및 h≤C, 다음 op∈{0,1}, 마지막 권한이다. op=0 은 보기 가능, op=1 은 can_write가 참일 때만 허용이라고 정한다. 하나라도 실패하면 복사·동작 없이 거절하고, 성공 때만 h칸을 복사한 후 고정 표로 동작한다. 실제 파서의 오류 복구나 여러 요청 동시 상태는 이 계약에 포함하지 않는다.

이 정책을 증명할 때 성공 요청마다 길이 조건·허용 명령·인가가 모두 참이라는 불변식을 사용한다. 하지만 원본이 실제 r칸 살아 있고 목적 C칸이 쓰기 가능하다는 호출자 전제가 없으면 숫자 검사만으로 메모리 안전성을 얻지 못한다. 검증 함수 성공이라는 이름보다 어떤 입력·상태·행동을 보장하는지 기록하는 것이 중요하다.

중간 과정을 따라가는 예제

C=4, 고정 입력/정책, 쓰기 가능한 목적과 살아 있는 원본을 가정한다. 네 요청 (h,r,op,can_write)=(3,3,0,false),(4,3,0,false),(2,2,2,true),(2,2,1,false)을 순서대로 검사한다. 종료 문자가 필요 없는 바이트 복사 모형이다.

  1. 첫 요청은 3≤3 및 3≤4이고 op0이 허용되어 보기 성공이다. 복사 인덱스는 0,1,2이고 can_write는 보기 권한에 필요하지 않다.
  2. 둘째는 4>r3 이라 실제 입력 범위 부족으로 거절한다. 목적에는 들어갈 수 있어도 원본 읽기 조건을 만족하지 않는다.
  3. 셋째는 길이가 통과하지만 op2가 표의 정의역 밖이라 거절한다. 입력값을 임의의 함수 주소로 사용해 실행하지 않는다.
  4. 넷째는 길이와 op1이 통과하지만 can_write=false라 거절한다. 메모리 경계 검사 성공은 쓰기 권한을 대체하지 않는다.

성공은 첫 요청 하나이며 보기·3 칸 복사다. 나머지는 실제 입력 길이, 명령 종류, 권한의 서로 다른 이유로 거절한다. 실제 서비스 응답 관측은 아니다.

증명: 고정 상태에서 검사 모두를 통과한 요청은 0≤h≤min(r,C), op∈{0,1}과 (op=1⇒can_write)를 만족한다. 복사 전 i=0, 반복 조건 i<h, 불변식 0≤i≤h를 둔다. 접근 시 i<h≤r,C이므로 두 범위 안이다. i를 1 늘려도 i≤h가 유지된다. h−i는 음이 아닌 정수이며 매번 감소해 종료한다. h=0은 접근 없이 끝난다. 이 증명은 정의된 산술·살아 있는 객체·고정 입력 전제에 의존하며 실제 C 포인터나 명령 파서의 전체 적합성 증명은 아니다. 성공 뒤 정책이 변경되는 동시 모형을 도입하면 사용 시점의 인가와 원자 경계를 새로 정해야 한다.

격리 실습 환경과 재현

같은 입력에서 한 번 멈췄다는 기록은 원인과 수정 완료를 얼마나 설명할까?

준비 개념과 학습 목표

준비 개념

  • 재현은 정한 조건을 다시 구성해 특정 관측을 반복할 수 있는지 확인하는 과정이다. 소스,입력,도구버전,옵션,실행상태가 조건이고 종료코드·표준출력·오류출력은 관측이다.
  • 격리는 실습의 쓰기·연결·권한 범위를 제한하는 설정이다. 가상머신·컨테이너라는 이름만으로 외부 연결이나 host 파일 접근이 사라지지 않는다. 설치 없이 종이 설정표를 그릴 수 있다.
  • 자가진단: 입력이 같아도 다른 바이너리를 실행하면 같은 실험이라고 할 수 있는가? 소스SHA·빌드옵션·실행파일SHA·runtime을 함께 대조해야 한다.

학습 목표

  • 소유한 자체 코드와 격리·외부연결 차단 조건을 포함한 실습 계획을 작성한다.
  • 원인 논증·예상 결과·실제 관측을 다른 칸에 기록한다.
  • 고정 입력 회귀 결과의 범위와 미수행 시험을 명시한다.

기본 경로는 종이이고 선택 실행은 소유 범위를 고정한다

이 단원의 기본 활동은 객체칸·길이·사건표를 그리는 것으로 실행환경이 필요 없다. 선택 실행을 설계한다면 본인이 작성하고 사용할 권한을 가진 작은 정상 코드, 합성 입력,비밀없는 작업 디렉터리로 한정한다. 기존 서비스·임의 사이트·실제 개인정보·외부 장치는 대상에 포함하지 않는다. 취약 변형을 반드시 실행해야 개념을 이해할 수 있다는 요구도 없다.

선택 실습의 경계표에는 네트워크 어댑터/egress를 비활성화할 방안,host 폴더 공유·clipboard·장치연결을 사용하지 않는 조건,비관리자 실행,시간/메모리 한도,종료/초기화 절차를 적는다. 해당 설정이 실제 적용되었는지 확인하기 전에는 격리 완료라고 기록하지 않는다. 가상머신 snapshot은 복원 상태의 기준일 수 있으나 외부망·host 자산의 피해를 되돌린다는 보장은 아니다.

정확한 코드와 도구 조건을 묶는다

실행 계획에는 전체 소스와 SHA-256,전체 입력 및 해시,컴파일러/표준모드/라이브러리/OS/아키텍처,정확한 명령/작업폴더,빌드된 파일의해시,종료코드/stdout/stderr를 보존한다. sanitizer를 사용하면 버전·계측옵션·runtime·억제목록/비계측모듈도 기록한다. 같은 소스해시만으로 같은 바이너리나 실행 상태를 뜻하지 않는다.

AddressSanitizer는 계측된 실행의 메모리 오류를 탐지하는 도구이고,구성별검사와지원범위가 있다. 보고가 없어도 모든 입력·경로·객체 수명·정수 연산의 안전성을 증명하지 않는다. 문서에서 이 runtime이 생산용 보안 보호 수단이 아니라는 조건도 읽는다. 웹 문서에 나타난 옵션이나 속도를 현재 컴퓨터에 설치·실행한 사양으로 기록하지 않는다.

원인과 관측 그리고 수정의 범위를 구분한다

크래시는 프로세스가 멈춘 관측이고 원인은 별도 논증이다. 경계 위반·수명 종료 뒤 접근을 언어 계약으로 확인하고,그 코드 경로와 보고 위치의 관계를 추적해야 한다. UB에 특정 출력이나 매번 같은 크래시를 예측하지 않는다. 비계측 실행과 계측 실행은 메모리배치·성능을 바꿀 수 있어 관측 조건도 다르다.

수정은 길이 검사 위치나 소유권을 바꾼 구체 변경이고,회귀 시험은 선택한 입력에서 그 변경의관측을 확인하는 별도행위다. 가상 표의n=0,경계값,초과값을 모두다뤘다는기록도전체 C 프로그램의 보안 증명이나 교실 검증은 아니다. 재현 실패도 숨기지 말고 조건 차이·실행 미수행·출처 접근 실패를 각각 기록한다.

중간 과정을 따라가는 예제

아래 자체 종이 기록을 감사하라. A는 소스 S와 입력 I, 옵션 O를 적고 “정상 예상”만 있다. B는 소스 S지만 옵션 O2/실행파일 X2와 “오류 종료를 관측했다고 가정”이다. C는 소스 S의 수정본/입력 I와 정상 예상이다. 실제 실행은 셋 모두 없다.

  1. A의 예상값은 관측이 아니다. 환경·명령·빌드 해시·stdout/stderr·종료코드는 실제 수행 없이 채우지 않고 실행 미수행으로 표시한다.
  2. B는 옵션과 바이너리가 다르므로 A와 동일 환경 반복이라고 묶을 수 없다. 오류 종료도 가상의 기록 문장이며 이번 실제 관측으로 세지 않는다.
  3. C는 코드가 바뀌었으므로 새 source SHA가 필요하다. 예상 정상이라는 문장만으로 I의 회귀 실행 통과나 모든 취약성 제거를 주장하지 않는다.
  4. 원인 란에는 가정한 경계 부등식과 수명 전제를, 관측 란에는 미수행을, 범위 란에는 합성 입력 I의 종이 모형만이라고 적는다. 소스·실행·원인·증명 상태를 분리한다.

A/B/C는 모두 종이 기록이다. B는 A의 동일 환경 재현이 아니고 C는 실제 회귀 통과 증거가 아니다. 실제 크래시·sanitizer 출력은 없다.

종이와 본문으로 직접 해보기

새 종이 계획에서 허용 길이 0..4의 합성 입력을 0,4,5로 고른다. 전체 소스/입력 해시만 있고 OS·컴파일러 옵션·egress·출력 기록이 없다. 채워야 할 조건과 각 입력의 예상 길이 판정을 적고 이 계획을 실제 완료로 쓸 수 있는지 판정하라.

힌트 보기

허용값 두 개와 초과값 하나를 구별한다. 환경과 격리는 설정 계획/실제 확인으로 나누고, 관측을 꾸며서 채우지 않는다.

풀이 보기

0과 4는 길이 조건 허용, 5는 거절 예상이다. OS/아키텍처·compiler/runtime/version·표준 모드/옵션·명령/폴더·binary SHA·권한/egress/host 공유·자원 한도/초기화 절차를 계획한다. 종료코드/stdout/stderr는 실제 수행 뒤에만 채운다. 이 활동은 미실행 계획이므로 실습 완료·통과라고 기록할 수 없다.

오해와 반례

sanitizer 경고가 없고 컨테이너에서 실행하면 모든 입력에 안전하고 완전히 격리된 것이다.

실행되지 않은 경로 또는 비계측 모듈은 관측 범위 밖일 수 있다. 컨테이너에 host 쓰기 권한이나 외부 egress가 있으면 이름만으로 격리되지 않는다. 오류 탐지·구성 격리·전체 안전성 증명은 서로 다른 주장이다.

크래시가 없으면 C의 모든 경계/수명 조건을 만족했다고 증명되는가?

한 단계 더

심화: 명세 P와 유한 시험 집합 T를 정하면 모든 t∈T에서 P의 관측 판정을 통과해도 입력 집합 D 전체의 ∀x∈D:P(x)는 일반적으로 따라오지 않는다. 예를 들어 D={0,1,2,3,4,5}, T={0,4}, Q(x)=(x≤4)라면 T에서는 참이지만 x=5에서 거짓이다. T=D인 경우도 이 모형의 모든 입력을 실제로 검사하고 판정기가 정확하며 숨은 상태 조건도 고정되어야 그 유한 명제를 결론낼 수 있다. source SHA는 바이트 동일성 증거이지 P 증명의 인증서가 아니다. 재현 기록 R=(source,input,build,environment,initialstate,observation)를 두고 관측을 제외한 좌표가 같은지 먼저 대조하면, 변수 하나를 바꾼 원인 추적과 동일 조건 반복을 구별할 수 있다. 이 원고는 R의 계획만 제공하며 실제 R의 관측값을 만들지 않는다.
