소단원 13.1

데이터 최소화·익명성

이름을 지운 학습 기록은 누구의 기록인지 알아낼 수 없는 자료가 될까?

준비 개념과 학습 목표

준비 개념

  • 표의 행과 열

  • 집합과 같은 값 묶기

  • 수집 목적과 공개 대상

학습 목표

  • 업무에 필요한 데이터와 추가 수집을 구별한다.

  • 직접 식별자·준식별자·가명과 재식별을 설명한다.

  • 가상 표의 집합 크기와 민감값 추론 한계를 확인한다.

수집하기 전 목적과 경계를 정한다

데이터 최소화는 일을 수행하는 데 필요한 범위로 수집·이용·공개·보관을 줄이는 설계다. 과목별 이용 횟수만 세려는 기능이라면 실명·정확한 생일·집 주소가 꼭 필요한지 먼저 묻는다. 별도의 본인 확인이나 지원 업무에는 다른 요구가 있을 수 있으므로 모든 목적에 같은 표를 강요하지 않는다.

필드를 줄여도 로그·백업·외부 분석 도구에 원래 값이 남으면 전체 흐름의 수집량은 그대로일 수 있다. 누가 무엇을 얼마나 오래 보관하고 어디로 전달하는지 함께 적는다. 이는 기술 설계 입문이며 지역별 법적 처리 요건이나 공개 승인 여부를 판정하는 단원은 아니다.

이름 삭제와 연결 가능성의 차이

이름처럼 직접 연결하는 열을 지워도 나이·지역·시간의 조합이 외부 자료와 맞으면 한 사람을 좁힐 수 있다. 이처럼 결합에 쓰일 수 있는 열을 준식별자라고 부른다. 위험은 관찰자가 이미 아는 정보와 공개 범위에 따라 달라진다.

가명은 같은 대상의 기록을 묶는 별도 표지다. 대응표를 보호하는 일은 도움이 되지만 대응표가 없다고 다른 조합으로 연결할 가능성까지 없어지지 않는다. 이 단원에서 비식별 처리는 연결 위험을 낮추는 변환을 가리키며 완전하고 영구적인 익명성으로 단정하지 않는다.

같은 준식별자 집합이 숨기는 것과 못 숨기는 것

선택한 준식별자 값이 같은 행들을 동치 집합으로 묶을 수 있다. 모든 집합의 크기가 최소 k라면 그 선택된 열에 대해 k-anonymity 조건을 만족한다고 말한다. 확인하지 않은 열·외부 정보·반복 공개까지 보호한다는 뜻은 아니다.

두 행이 서로 구별되지 않아도 민감한 상태가 두 행 모두 같으면 그 집합 구성원의 상태를 추론할 수 있다. 숫자 하나가 신원 연결과 민감값 추론을 모두 대신하지 못한다. 일반화가 분석 세부를 잃게 하는지도 점검하고 실제 공개에는 별도의 위험 검토가 필요하다.

중간 과정을 따라가는 예제

실제 사람이 없는 자체 4행 표를 만들자. 열은 이름·나이·지역·학습 상태다. 나이/지역/상태는 순서대로 (12,A,도움), (13,A,도움), (14,B,완료), (14,B,도움)이다. 이름을 삭제한 뒤 나이와 지역을 준식별자로 선택한다. 이후 나이를 모두 10–19 구간으로 바꾸면 집합 크기는 어떻게 달라질까?

  1. 원래 나이·지역 조합은 (12,A) 한 행, (13,A) 한 행, (14,B) 두 행이다. 집합 크기는 1,1,2라 최소가 1이다. 이름 삭제만으로 두 단독 행이 사라지지 않았다.

  2. 나이를 10–19로 바꾸면 (10–19,A) 두 행과 (10–19,B) 두 행이다. 이 두 준식별자에 대한 최소 집합 크기는 2다. 순서나 다른 고유 열은 공개하지 않는다고 가정한다.

  3. A 집합의 두 상태는 모두 도움이다. 가상 관찰자가 어떤 대상이 A 집합 구성원이라는 사실을 정확히 안다면 어느 행인지 몰라도 그 대상의 도움 상태를 알 수 있다. B 집합은 두 상태가 달라 이 동일한 추론은 하지 못한다.

선택한 준식별자의 최소 집합 크기는 1에서 2로 늘어난다. 그러나 A 집합의 민감 상태 추론은 남는다. 이 가상 표의 조건 검사는 실제 학생 자료 공개의 안전성 증명이 아니다.

소단원 13.2

부채널·프라이버시

내용이 암호화되어 있으면 처리 시간이나 패킷 크기를 관찰해도 아무것도 알 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 함수의 입력과 결과

  • 반복 비교와 조기 종료

  • 관찰과 추론의 차이

학습 목표

  • 정상 출력 외의 시간·접근·크기 관찰을 부채널과 연결한다.

  • 자체 비교 횟수 모형을 실제 시간 계측과 구별한다.

  • 일정한 비교 횟수와 전체 시스템의 저항성을 구별한다.

기능 결과 밖에 남는 흔적

프로그램은 정해진 반환값 외에도 처리 시간·메모리 접근·전력·통신 크기 같은 흔적을 남길 수 있다. 비밀과 관련된 흔적을 관찰하여 정보를 추론하는 경로가 부채널이다. 관찰 가능한 흔적과 공격자가 실제 얻을 수 있는 측정 정밀도를 함께 생각한다.

암호화는 내용 보호의 중요한 수단이지만 통신의 존재·시점·길이까지 항상 숨기지는 않는다. 두 가상 메시지의 암호문 길이가 다르다는 사실만으로 내용을 확정할 수는 없어도, 후보를 좁힐 추가 정보가 될 수 있다. 관찰자를 무엇을 볼 수 있는 사람으로 정했는지가 핵심이다.

조기 종료를 비교 횟수로만 살펴보기

자체 모형의 비교기는 같은 길이의 네 기호를 왼쪽부터 비교하고 첫 불일치에서 멈춘다. 각 기호 비교의 가상 비용은 1단위이고 다른 비용은 0이다. 내용이 다른 입력이라도 몇 번째에 어긋나는지에 따라 비용이 달라진다.

이 표는 실제 암호 라이브러리나 비밀번호 검증기가 아니다. 1단위는 ms나 CPU cycle이 아닌 계산 규칙이다. 실측에서는 noise·compiler·cache·branch·네트워크 등의 조건을 확인해야 하므로 이 모형에서 계산한 횟수를 특정 장비 지연으로 바꾸지 않는다.

전체 경로와 데이터 접근을 확인한다

모형에서 네 기호를 끝까지 비교하면 불일치 위치에 따른 비교 횟수 차이는 없어질 수 있다. 하지만 길이 검사·오류 출력·비밀에 따라 선택한 주소·호출 함수·생성 코드의 차이가 남을 수 있다. 같은 횟수라는 사실 하나가 전체 부채널 저항성을 증명하지 않는다.

실제 비밀 처리에는 해당 환경에 맞는 검토된 구현과 생성 코드·동작 검증이 필요하다. 단순 sleep을 추가하거나 난수를 섞은 시간 지연만으로 정보 누출이 사라졌다고 보장하지 않는다. 여기서는 원리를 종이에 추적하며 실제 계정이나 공유 장치의 비밀을 시험하지 않는다.

중간 과정을 따라가는 예제

자체 네 기호 기준값은 ABCA다. 실제 비밀번호가 아닌 가상 문자열이다. 첫 불일치에서 멈추는 비교기에 ZXXX, AXXX, ABCZ, ABCA를 넣는다. 한 기호 비교는 1단위이고 다른 비용은 0이며 길이는 모두 4다. 비용과 동일 여부를 적자.

  1. ZXXX는 첫 위치의 A/Z가 달라 비용 1이고 동일하지 않다. AXXX는 첫 A가 같고 둘째 B/X가 달라 비용 2다.

  2. ABCZ는 세 위치가 같고 넷째 A/Z가 달라 비용 4다. ABCA는 네 위치가 모두 같아 비용 4이며 동일하다.

  3. 가상 반환값은 앞 세 입력 모두 false지만 비교 비용은 1/2/4로 다르다. 마지막 두 입력은 비용이 같아도 반환값이 다르므로 비용만으로 동일 여부를 항상 판단하지 못한다.

비용/동일 여부는 (1,false), (2,false), (4,false), (4,true)다. 이는 자체 비교 횟수 표이며 실제 장치 시간이나 공격 성공 결과가 아니다.

종이와 본문으로 직접 해보기

별도 비교기는 길이 4인 모든 입력의 네 위치를 끝까지 검사한다. 위 네 입력의 비교 횟수와 동일 여부는? 길이 3 입력을 검사 전 거절하면 전체 경로도 모두 같은 횟수가 되는가?

힌트 보기

끝까지 비교와 동일하다는 결론은 다르다. 길이 거절은 네 위치 검사 전에 일어난다.

풀이 보기

길이 4인 네 입력은 모두 비교 횟수 4이고 동일 여부는 false/false/false/true다. 길이 3 입력은 위치 비교 0회로 거절된다고 가정하므로 전체 경로는 같지 않다. 이것이 실제 시간 차이의 크기나 비밀 길이 보호를 증명하지는 않는다.

오해와 반례

반복 횟수를 같게 하거나 응답에 고정 sleep을 붙이면 모든 부채널이 없어졌다.

비밀 의존 주소와 분기·길이 경로·compiler 결과·크기 관찰이 남을 수 있다. 전체 관찰 모델과 구현을 따로 검증해야 하며 횟수 표는 일부 경로만 설명한다.

소단원 13.3

AI 시스템 신뢰경계 입문

검색 문서가 관리자 승인 문구를 담고 있으면 AI 도구가 그 문서를 권한 증거로 믿어도 될까?

준비 개념과 학습 목표

준비 개념

  • 사용자·자료·프로그램의 역할

  • 읽기 권한과 실행 권한

  • 신뢰하는 정책과 외부 입력

학습 목표

  • 사용자 의도·검색 자료·모델 제안·도구 실행의 경계를 그린다.

  • 외부 문서의 지시와 실제 권한 근거를 분리한다.

  • 자체 도구 정책의 허용/거절과 답변 정확성을 구별한다.

AI에 들어가는 자료는 권한증이 아니다

문서 요약 서비스는 사용자 요청과 검색 문서·도구 결과를 함께 처리할 수 있다. 외부 문서에 서비스의 행동을 바꾸려는 지시가 들어갈 때 이를 간접 prompt injection 문제로 본다. 사람이 문서 내용을 인용하는 것과 그 문서에 실제 명령 권한을 주는 것은 다른 일이다.

모델이 관리자 승인이라고 적은 문장을 발견하거나 스스로 승인됐다고 답해도 서버의 신원·권한 기록을 새로 만들지는 못한다. 검색 내용·모델 출력은 처리할 데이터이며 실행 승인은 신뢰하는 정책 경로에서 확인한다. 직접 사용자 요청도 해당 사용자의 허용 범위를 넘어서는 권한은 만들 수 없다.

실행 경계에서 대상과 인수를 제한한다

도구를 호출하는 실행기는 신뢰하는 사용자 권한과 원래 요청의 범위에 따라 도구 종류·대상·인수를 검사한다. 공개 강의 요약만 요청받은 자체 모형은 공개 읽기만 허용하고 학생 비공개 기록 읽기와 외부 발송은 허용하지 않는다. 모델이 제안을 만들었다는 이유로 실행을 통과시키지 않는다.

허용 목록에는 실제 자원 식별과 정규화·입력 길이·redirect·외부 연결 범위 등 구현 조건이 따를 수 있다. 아래 표에서는 대상이 이미 신뢰하는 식별자로 결정됐다고 제한한다. 문자열 비교 표 하나를 실제 경로 보안이나 완성된 API 인증 구현이라고 제시하지 않는다.

행동 통제와 요약 품질을 따로 평가한다

자료와 지시를 나누는 표지나 filter는 방어를 돕지만 그 문구 자체가 권한 강제 장치는 아니다. guardrail 모델의 판정도 실행기 정책을 대신하지 못한다. 읽기 전용으로 피해 범위를 줄여도 거짓 요약이나 민감한 문장의 잘못된 노출 같은 출력 문제는 따로 점검한다.

모델로 전달하기 전 필요한 최소 자료를 선택하고 로그에서 실제 비밀과 불필요한 개인정보를 제외한다. 정상 작업이 거절된 사례와 권한을 넘은 작업이 허용된 사례를 구분해 시험한다. 실제 모델·도구·사용자 환경을 시험하지 않은 이 정책표는 해당 시스템의 보안 인증이 아니다.

중간 과정을 따라가는 예제

자체 서비스의 신뢰하는 정책은 read_public 도구, 정규 자원 course_public, 크기 1000단위 이하의 읽기만 허용한다. 단위는 임의 요청 크기이며 비용이 아니다. 비공개 읽기와 외부 발송은 금지다. 모델이 제안한 네 요청은 (read_public,course_public,700), (read_private,student_private,100), (send_mail,external,100), (read_public,course_public,1500)이다. 외부 문서에 관리자 승인 문구가 있다고 해도 실행기 정책은 바뀌지 않는다고 가정한다.

  1. 첫 요청은 도구와 대상이 허용 목록에 있고 700≤1000이라 허용된다. 공개 내용을 읽는 것에 한정된다.

  2. 둘째는 도구와 대상이 비공개 범위라 거절되고 셋째는 외부 발송 도구라 거절된다. 문서의 승인 문구는 이 검사를 바꾸지 않는다.

  3. 넷째는 도구와 대상은 맞지만 크기 1500>1000이라 거절된다. 허용된 첫 읽기의 결과를 모델이 정확히 요약할지는 별도의 평가 항목이다.

자체 정책 판단은 허용/거절/거절/거절이다. 실제 AI 도구를 호출하지 않았으며 이 네 행의 통과가 모든 주입·정보 노출 방지를 증명하지 않는다.

종이와 본문으로 직접 해보기

정책은 그대로 두고 넷째 요청 크기를 900으로 바꾸면? 첫 요청의 대상만 student_private으로 바꾸면? 승인 문구를 삭제한 외부 문서라면 검색 내용의 사실 정확성이 자동으로 증명되는지도 판단하자.

힌트 보기

도구·대상·크기 세 조건이 모두 맞아야 한다. 권한 검사와 사실 확인은 다른 시험이다.

풀이 보기

넷째는 900≤1000이며 다른 조건도 맞아 허용된다. 첫 요청의 대상이 바뀌면 허용 자원이 아니므로 거절된다. 문서의 승인 문구 삭제는 그 문서의 주장이나 모델 요약이 참이라는 증거가 아니다.

오해와 반례

외부 문서 앞에 데이터라고 쓰거나 모델에게 지시를 무시하라고 하면 연결 도구의 권한도 안전하게 강제된다.

표지는 모델 처리 방식을 도울 뿐 실행 권한을 강제하지 않는다. 실행기에서 실제 사용자·도구·대상·인수를 확인하고 출력의 정확성과 민감정보 노출은 별도로 검증한다.
