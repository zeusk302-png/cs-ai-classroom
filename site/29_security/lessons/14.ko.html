소단원 14.1

위협 모델에서 방어로 연결

로그인 화면이 있으면 다른 학생의 과제도 안전할까?

준비 개념과 학습 목표

준비 개념

  • 역할과 인증

  • 요청·서버·저장소 흐름

  • 허용 조건과 경계

학습 목표

  • 보호할 자산·행위자·흐름을 연결한다.

  • 위협에 대응하는 서버 조건과 검증 문항을 작성한다.

  • 위험 점수의 가정과 잔여 위험을 설명한다.

반 배정이 바뀌었는데 어제의 권한을 계속 써도 될까요?

권한 정책은 역할 이름만으로 끝나지 않는다. 누가 어떤 반에 배정되어 있는지, 언제의 자료를 기준으로 읽기를 결정하는지 정해야 한다. 다음 표는 신뢰하는 서버 자료가 주어진 종이 모형이며 브라우저가 보낸 배정 주장은 포함하지 않는다.

기능을 복제하거나 경로를 추가하면 기존 권한 검사가 모든 경로에 적용되는지 다시 연결한다. 화면 경로 하나의 통과를 새 API 경로에도 확인한 결과로 바꾸지 않는다. 실제 변경·공격 도구 실행 없이 조건표로 설계의 빈칸을 찾는다.

먼저 확인할 개념
  • 위협 모델에서 방어로 연결

    학생 소유자·교사 반 배정 정책을 시간에 따른 상태와 새 요청 경로에 연결한다.

  • 수정·시험·잔여 위험 보고

    방어 요구마다 검증 근거와 미수행 경로를 기록하는 방법을 연결한다.

자산과 흐름을 먼저 그린다

위협 모델은 어떤 기능을 만들며 무엇이 잘못될 수 있고 어떻게 대응하고 충분히 확인했는지 묻는 과정이다. 공격 기법의 이름을 모으기 전에 보호할 자산과 정상 동작을 적는다. 가상 과제 서비스의 자산은 과제 본문·작성자 연결·제출 시각이고, 학생·교사·외부 요청자가 행위자다.

브라우저에서 서버로 요청이 들어오고 서버가 저장소의 과제를 읽어 응답하는 흐름을 그리자. 브라우저가 보낸 역할이나 작성자 번호는 주장일 뿐이다. 서버가 이미 확인한 사용자 신원과 저장된 과제 소유자를 비교하는 지점이 필요하다. 도표는 실제 구현과 맞아야 하며 기능이 바뀌면 다시 검토한다.

위협을 방어 조건과 연결한다

로그인한 학생이 요청의 과제 번호를 다른 학생의 번호로 바꿀 수 있다고 가정하자. 인증은 누구인지 확인하는 일이고 권한 검사는 해당 자료를 읽어도 되는지 확인하는 일이다. 과제 번호를 숨기거나 화면 버튼을 없애는 것만으로 서버의 권한 검사를 대신하지 않는다.

자체 정책은 학생이 자기 과제만 읽고 교사는 자신에게 배정된 반의 과제만 읽는 것이다. 서버가 신뢰하는 역할·반 배정·소유자 자료로 이 조건을 판정하고 거절 시 본문을 응답하지 않는다. 로그는 허용·거절과 필요한 식별 정보만 남기며 과제 전문을 복사하지 않도록 별도 설계한다.

점수와 검증의 범위를 정한다

위협 분류에는 신원 사칭·자료 변조·부인·정보 노출·서비스 방해·권한 상승 같은 관점이 있다. 하나의 방어가 모든 위협을 해결하지는 않는다. 소유자 검사는 다른 학생 본문 읽기를 막는 조건이고 저장소 장애나 교사 계정 탈취까지 해결하는 조건은 아니다.

우선순위를 위한 자체 가능성 1–3과 영향 1–3의 곱은 팀의 비교 규칙이다. 곱 6을 실제 발생 확률 60%나 손실액으로 읽지 않는다. 대응 뒤 남은 위험·근거·책임자·다음 검증을 적고, 위험 수용은 권한 있는 운영 책임자의 판단으로 남긴다.

과제 전문이 새지 않는가?

현재 배정은 정책이 정한 시점의 자료다. 캐시를 사용할 때 회수 반영 지연도 요구와 비교한다.

중간 과정을 따라가는 예제

자체 자료 D1은 학생 S1·반 A, D2는 S2·반 A, D3은 S3·반 B의 과제다. 교사 T는 반 A만 배정받았다. 신원과 배정은 서버의 신뢰된 자료이며 동작은 읽기만이다. 요청 S1→D1, S1→D2, T→D2, T→D3을 판정하자.

  1. S1→D1은 학생 신원과 저장된 소유자 S1이 같아 허용한다.

  2. S1→D2는 소유자가 S2라 거절한다. 로그인 성공은 소유자 일치가 아니다.

  3. T→D2는 반 A가 배정에 포함되어 허용하고 T→D3은 반 B가 없어 거절한다. 클라이언트가 교사나 반 B라는 문장을 추가해도 신뢰된 배정은 바뀌지 않는다.

순서대로 허용·거절·허용·거절이다. 본문을 응답하는 것은 허용된 두 요청뿐이라는 정책이다. 실제 서버에서 검증한 결과는 아니다.

조건을 바꾸어 비교하기

회수와 캐시 만료

교사 T의 반 A 배정이 09:00부터 회수된다. 원본 정책은 회수 시점부터 읽기 금지다. 캐시는 08:59에 A 배정을 읽고 09:04부터 만료된다. 구현은 만료 전 캐시만 사용한다고 주어졌다. 09:02 읽기를 정책과 구현으로 따로 판정하라.

  1. 정책의 현재 배정에는 A가 없다.

  2. 구현 캐시는 아직 A를 포함한다.

  3. 정책은 거절하지만 가상 구현은 허용한다.

09:02는 정책 위반 허용이다. 09:00~09:04의 4분 지연이 남는다.

비교할 점

동일 사용자·자료라도 판정 시점과 캐시 조건이 다르면 결과가 바뀐다.

새 경로의 누락

화면 경로 P는 소유자를 검사하지만 새 경로 Q는 로그인 여부만 확인한다고 주어졌다. 로그인 S1이 소유자 S2의 과제 D를 요청한다.

  1. P는 소유자 불일치로 거절한다.

  2. Q는 로그인 조건만 맞아 허용한다.

  3. 두 경로 모두 동일한 서버 권한 요구를 적용해야 한다.

P 거절, Q 허용으로 Q에 정보 노출 조건이 남는다.

비교할 점

기존 화면 확인을 전체 기능 검증으로 확대하지 않는다.

종이와 본문으로 직접 해보기

새 과제 D4는 S1·반 B다. S1→D4와 T→D4를 판정하자. 자체 위협 점수에서 가능성 2·영향 3인 정보 노출과 가능성 3·영향 1인 일시 지연의 우선순위도 비교하자.

힌트 보기

학생 규칙은 소유자이고 교사 규칙은 반 배정이다. 점수는 정해 둔 두 정수의 곱이다.

풀이 보기

S1→D4는 자기 과제라 허용, T→D4는 반 B가 배정되지 않아 거절이다. 자체 점수는 6과 3으로 이 규칙에서는 정보 노출을 먼저 검토한다. 실제 확률이나 전체 운영 위험을 측정한 결과는 아니다.

오해와 반례

인증만 성공하면 과제 번호를 아는 모든 사용자가 읽어도 된다.

인증 뒤 요청 대상에 대한 권한을 따로 확인한다. 번호의 난해함이나 화면 제한은 이 조건을 대신하지 않는다.

스스로 풀어보기

연습 1 · 값과 상태 예측

T의 현재 배정은 {A,C}, 과제 D1의 반은 B, D2의 반은 C다. 교사 읽기를 판정하라.

힌트 1

각 대상 반이 집합에 있는지 본다.

힌트 2

교사 역할 자체가 모든 반 권한은 아니다.

풀이와 답 확인

  1. B는 배정에 없어 D1 거절이다.

  2. C는 배정에 있어 D2 허용이다.

D1 거절·D2 허용이다.

흔한 오답에서 다시 생각하기

교사이므로 둘 다 허용한다.

역할과 배정 조건을 함께 확인한다.

연습 2 · 오류 찾아 고치기

브라우저 owner=S1을 저장된 소유자 대신 비교해 S1 요청을 허용했다. 고쳐라.

힌트 1

요청 값은 사용자가 바꿀 수 있다.

힌트 2

소유자 근거를 서버 저장 자료에서 가져온다.

풀이와 답 확인

  1. 서버가 확인한 신원 S1과 대상에 저장된 소유자를 비교한다.

  2. 요청의 owner 주장이 일치 판단을 바꾸지 못하게 한다.

신뢰된 신원·저장 소유자로 판정하며 다른 소유자의 자료는 본문 없이 거절한다.

흔한 오답에서 다시 생각하기

owner 열이 있으니 믿어도 된다.

입력 열의 존재와 신뢰성은 다르다.

연습 3 · 직접 만들어 보기

새 과제 다운로드 경로의 위협→방어→시험 연결을 한 줄로 만들라.

힌트 1

보호할 것은 다른 학생의 본문이다.

힌트 2

정상 자기 자료도 성공해야 한다.

풀이와 답 확인

  1. 위협은 로그인 학생의 다른 소유자 번호 요청이다.

  2. 방어는 다운로드 서버의 신원·저장 소유자 검사다.

  3. 다른 소유자 거절과 자기 자료 허용을 모두 확인한다.

다른 과제 번호 요청 → 서버 소유자 검사 → 비공개 거절·정상 다운로드 허용 시험이다.

흔한 오답에서 다시 생각하기

번호를 숨기면 시험은 불필요하다.

번호 난해함은 대상별 권한 강제가 아니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

가상 가능성·영향 점수 X=1×3, Y=3×1은 둘 다 3이다. 두 위험이 같은 실제 피해라고 결론내릴 수 있을까?

힌트 1

동일한 곱과 동일한 구성은 다르다.

힌트 2

척도는 확률이나 금액으로 측정된 값이 아니다.

풀이와 답 확인

  1. X는 낮은 가능성·큰 영향, Y는 높은 가능성·작은 영향이다.

  2. 동일 점수에도 구성·근거·책임·검증을 함께 보고한다.

실제 피해 동등성은 결론낼 수 없다.

흔한 오답에서 다시 생각하기

점수 같음은 피해 금액도 같음을 뜻한다.

자체 서열 척도의 곱을 측정된 손실로 바꾸지 않는다.

소단원 14.2

허가된 실습 대상 검증

사이트가 인터넷에 열려 있으면 보안 시험을 해도 될까?

준비 개념과 학습 목표

준비 개념

  • 대상과 범위

  • 시간 구간

  • 읽기와 변경의 차이

학습 목표

  • 대상·시간·행위·데이터의 시험 계약을 구별한다.

  • 모형 요청이 허가 범위에 포함되는지 판정한다.

  • 중단 조건과 재개 승인을 설명한다.

시험 대상이 응답에서 다른 장소로 바뀌면?

이 단원의 LAB 이름은 실제 주소가 없는 가상 대상이다. 승인 범위는 대상뿐 아니라 기간·행위·요청 수·자료 처리와 중단 상태를 함께 정한다. 공개되어 있거나 다른 곳으로 안내한다는 사실로 새 대상의 시험 권한이 생기지 않는다.

중단과 재개는 서로 다른 상태 전환이다. 시간 연장만 승인했다고 중단까지 해제되었다고 추정하지 않는다. 아래 계산은 서면 조건을 비교하는 연습이며 실제 서비스를 호출하거나 계정을 변경하지 않는다.

먼저 확인할 개념
  • 허가된 실습 대상 검증

    ROE의 대상·시간·행위·중단 조건을 재지정과 요청 수 제한에 적용한다.

  • 수정·시험·잔여 위험 보고

    허가 범위와 수행하지 않은 시험을 결과 보고에 분리한다.

접근 가능성과 시험 허가는 다르다

공개 주소가 열리는 것과 시험을 수행할 권한을 받은 것은 다르다. 시험 전에 대상 소유자와 필요한 이해관계자의 허가를 확인하고 목적·정확한 대상·기간·허용 행위·금지 행위·연락 담당자·데이터 취급을 문서로 정한다. 인터넷 전체를 대상으로 탐색하는 것이 이 단원의 활동은 아니다.

NIST의 시험 규칙 ROE는 이런 범위를 사전에 합의하는 문서 예시다. 이 수업의 표는 가상 계약이며 실제 조직이나 서비스에 대한 허가서가 아니다. 주소가 같은 화면으로 보이거나 실습 예시와 이름이 비슷해도 실제 대상 승인 여부를 추정하지 않는다.

모든 조건을 함께 확인한다

자체 가상 시험 환경은 종이 표에서만 존재하는 LAB-A다. 계약 시간은 14:00 이상 14:20 미만이고, 행위는 가상 상태값 읽기만 허용한다. LAB-B·파일 변경·계정 변경·대량 요청은 제외한다. 이 이름을 실제 호스트로 연결하지 않고 모형의 행으로만 취급한다.

대상이 맞아도 시간이 끝났거나 행위가 다르면 범위 밖이다. 승인 시간의 경계·요청 수·허용 데이터와 저장 위치도 적어야 한다. 실제 환경에서는 재지정이나 다른 서버로 이동하는 응답처럼 대상 경계가 바뀌면 새 대상을 자동으로 시험하지 않고 범위를 확인한다.

중단과 증거 처리도 계약이다

자료 손상이나 예상하지 않은 민감 자료를 발견하면 정해 둔 중단 절차를 따른다. 중단 담당자·연락 방법·재개 승인 주체를 시험 전에 정한다. 시험 시간이 아직 남았다는 이유로 중단 조건을 무시하지 않는다.

결과 보고에는 필요한 최소 증거만 보관하고 접근·암호화·보존 기한·삭제 책임을 정한다. 임시 계정이나 파일을 만들었다면 허가된 범위에서 정리하고 원래 설정을 확인한다. 이 활동은 가상 기록 판정이라 실제 민감 정보 수집이나 정리 명령을 실행하지 않는다.

  3. 넷째는 파일 삭제가 허용 행위가 아니라 범위 밖이다. 이 판정은 문서 조건 비교이고 실제 요청을 보내는 활동이 아니다.

정확한 예산 경계

진행 중이고 다른 조건은 모두 충족한다. 10:01에 2회 완료했고 10:02에 1회, 10:03에 1회를 추가 제안한다. 전체 예산 최대 3회다.

  1. 첫 추가는 누적 2+1=3으로 범위 안이다.

  2. 이를 수행했다면 다음 추가는 3+1=4로 예산 밖이다.

  3. 나중 제안이 시간 안이라는 사실은 예산을 늘리지 않는다.

  • 검증 범위와 증거

학습 목표

  • 수정 전후의 동일 조건 시험과 정상 기능 회귀를 구별한다.

  • 결과·한계·잔여 위험·책임자를 보고한다.

  • 시험 통과 개수를 전체 안전성으로 일반화하지 않는다.

고친 뒤 검사 대상까지 바꾸면 무엇이 좋아졌는지 알 수 있을까요?

수정 전후 결과를 비교하려면 같은 요구·대상·입력·설정이 어떤 버전에서 관찰되었는지 연결해야 한다. 더 쉬운 입력으로 바꾸고 통과했다고 기록하면 원래 문제를 고쳤다는 근거가 사라진다. 종이의 가상 관찰은 실제 구현이나 운영 배포 증거와 구별한다.

평균 통과율이 높아도 금지된 본문 반환 하나가 남으면 그 요구는 실패다. 정상 요청의 실패, 미수행, 결과 기록 누락도 구별한다. 한 문장 완료 보고 대신 변경·시험·한계·후속 책임을 연결하는 보고를 만든다.

먼저 확인할 개념
  • 수정·시험·잔여 위험 보고

    동일 조건 재시험·정상 회귀·미수행·잔여 위험의 보고 범위를 새 비교표에 적용한다.

  • 위협 모델에서 방어로 연결

    대상별 권한 요구가 통과율 속에서 사라지지 않도록 위협과 시험을 연결한다.

재현 조건과 기대 결과를 고정한다

보고는 문제 상황·대상 버전·허가 범위·입력 조건·기대 결과·관찰 결과를 연결한다. 정보 노출 사례라면 다른 학생 자료 요청이 거절되어야 한다는 기대와 본문이 반환되었다는 관찰을 분리한다. 확인하지 않은 버전이나 다른 서버까지 같은 문제라고 단정하지 않는다.

수정은 어떤 조건을 어디에서 바꾸었는지 설명하고 같은 시험을 다시 수행해야 한다. 이 단원에서는 실제 취약 서비스를 만들거나 시험하지 않고 자체 결과표를 사용한다. 결과표의 수정 전후는 수업에서 가정한 상태이며 현장 측정 기록이 아니다.

보안 시험과 정상 기능 회귀를 함께 본다

거절해야 하는 요청을 거절하는 것뿐 아니라 허용해야 하는 요청도 계속 성공하는지 확인한다. 모든 요청을 막는 수정은 정보 노출 반례를 없애도 정상 기능 요구를 깨뜨린다. 정상 요청의 실패를 보안 성공으로 숨기지 않는다.

같은 버전·설정·자료 조건을 고정하면 전후 비교가 쉬워진다. 실제 운영 반영은 허가된 변경 절차와 복구 계획을 따르고, 시험 환경 통과와 운영 확인을 별도 기록한다. 한 시험이 포함하지 않은 역할·반 변경·동시 요청·로그 공개 등의 위험도 적는다.

보고는 남은 불확실성까지 담는다

보고서에는 수정 내용·재시험 목록·관찰 결과·미수행 범위·남은 위험과 후속 책임자를 적는다. 처리 상태를 수정 제안, 시험 환경 검증, 운영 반영 확인처럼 구별하면 독자가 근거의 범위를 알 수 있다. 실제로 수행하지 않은 시험은 계획으로 유지한다.

통과 수가 전체 요청 공간의 안전성 증명이 되지는 않는다. 높은 통과율이어도 중요한 거절 조건 하나가 실패하면 그 문제는 남아 있다. 잔여 위험의 수용 여부는 담당 책임자가 판단하고, 새 증거가 생기면 모델과 보고를 갱신한다.

중간 과정을 따라가는 예제

자체 시험표의 네 기대는 S1→D1 허용, S1→D2 거절, T→D2 허용, T→D3 거절이다. 가상 수정 전 관찰은 허용·허용·허용·허용, 수정 A는 허용·거절·허용·거절, 수정 B는 거절·거절·거절·거절이라고 두자. 요구와 일치한 개수 및 정상 기능 실패를 비교하자.

  1. 수정 전에는 첫째·셋째만 기대와 같아 2/4다. 두 금지 요청이 허용되므로 정보 노출 조건이 남는다.

  2. 수정 A는 네 기대와 같아 4/4다. 선택한 정상 두 요청과 금지 두 요청을 이 표에서는 만족한다.

  3. 수정 B는 둘째·넷째만 같아 2/4다. 금지 요청은 막았지만 정상 두 요청도 막아 회귀 두 개가 생긴다.

자체 표의 일치는 전 2/4, A 4/4, B 2/4다. A도 이 네 조건의 표를 통과한 것으로만 보고하며 실제 프로그램·운영·전체 안전성 검증으로 부르지 않는다.

조건을 바꾸어 비교하기

높은 비율에 남은 핵심 실패

표의 일치율과 실패 종류를 보고하라. 모두 시험 환경의 가상 관찰이다.

  1. 첫·셋째·넷째·다섯째가 일치한다.

  2. 둘째는 금지된 요청을 허용한다.

  3. 정상 두 요청은 성공하지만 정보 노출 요구 하나가 남는다.

4/5=80%, 정보 노출 요구 실패 1건이다. 실제 환경 검증이나 안전 인증으로 부르지 않는다.

비교할 점

원문의 정상 기능 실패와 달리 금지 허용 실패를 같은 80% 안에서 구별한다.

입력을 바꾼 재시험

수정 전 S1→S2 소유 과제는 허용되어 문제였다. 수정 뒤에는 S1→S1 소유 과제만 허용 확인했다. 원래 문제가 해결됐는가?

  1. 수정 뒤 시험은 정상 자기 자료 경로다.

  2. 원래 다른 소유자 요청을 재시험하지 않았다.

  3. 새 정상 성공은 필요하지만 원래 거절 요구의 증거를 대신하지 않는다.

원래 정보 노출 수정 효과는 미확인이다. 같은 다른 소유자 조건의 거절과 정상 회귀를 각각 확인해야 한다.

비교할 점

수정 전후 입력 조건 자체가 달라진 비교를 찾아낸다.

종이와 본문으로 직접 해보기

수정 A에 새 정상 요청 S1→D4 허용을 추가했는데 가상 관찰은 거절이다. 전체 일치율과 정상 기능 실패를 구하고, 로그 공개나 배정 회수 시험을 수행했는지 이 표만으로 알 수 있는지 답하자.

힌트 보기

기존 네 개는 그대로 일치하고 다섯째 한 개가 다르다. 표에 없는 항목은 결과가 없다.

풀이 보기

4/5×100=80%이며 새 정상 요청 실패 한 개다. 기존 네 개가 통과해도 이 정상 기능 요구는 해결되지 않았다. 로그·배정 회수 시험 여부는 표만으로 알 수 없으므로 미수행 또는 별도 근거 대기로 기록한다.

오해와 반례

몇 가지 시험을 통과했으면 남은 위험과 미수행 범위는 보고할 필요가 없다.

수행한 시험의 대상·조건·결과를 밝히고 제외한 경로와 잔여 위험을 함께 적어야 검증 범위를 해석할 수 있다.

연습 1 · 값과 상태 예측

총 6개 예정 시험 중 수행 4개가 모두 일치하고 나머지 2개는 미수행이다. 보고의 분자·분모를 적어라.

힌트 1

수행 일치와 계획 완료를 나눈다.

힌트 2

미수행을 통과나 실패로 넣지 않는다.

풀이와 답 확인

  1. 수행 시험 일치는 4/4다.

  2. 계획 수행은 4/6이며 2개 미수행이다.

수행 일치 4/4, 계획 수행 4/6, 미수행 2개이다. 전체 여섯 조건 통과가 아니다.

흔한 오답에서 다시 생각하기

4/4이므로 계획 전부 완료다.

계획에 있지만 수행하지 않은 범위가 남아 있다.

연습 2 · 오류 찾아 고치기

서버 버전 V2 시험 결과로 운영 V1도 수정 완료라고 썼다. 운영 변경 증거는 없다. 고쳐라.

힌트 1

관찰 대상 버전과 운영 버전을 적는다.

힌트 2

시험 환경과 운영 반영은 다른 상태다.

풀이와 답 확인

  1. V2 시험 환경에서 확인한 조건과 결과만 기록한다.

  2. V1 운영 변경·재확인은 미확인으로 남긴다.

시험 환경 V2 검증 범위만 확인; 운영 V1 수정 반영은 근거 없음이다.

흔한 오답에서 다시 생각하기

같은 서비스 이름이면 버전 차이는 중요하지 않다.

실제 시험한 산출물·설정·대상이 다른 경우 결과를 승계하지 않는다.

연습 3 · 직접 만들어 보기

다른 학생 자료 노출 문제의 짧은 보고에 필요한 다섯 칸을 설계하라.

힌트 1

조건과 변경을 먼저 적는다.

힌트 2

수행·미수행·후속 담당자를 연결한다.

풀이와 답 확인

  1. 대상 버전·허가 범위·입력과 기대/관찰을 적는다.

  2. 서버 권한 변경 내용과 동일 조건 재시험·정상 회귀 결과를 적는다.

  3. 로그·동시성 등 미수행과 잔여 위험·담당자·다음 확인을 적는다.

문제 조건 / 변경 내용 / 재시험·회귀 / 한계·잔여 위험 / 후속 담당·확인의 다섯 칸이다. 실제 결과가 없으면 제안·계획으로 표시한다.

흔한 오답에서 다시 생각하기

한 줄 해결 완료만 쓰면 된다.

어느 조건과 버전까지 확인했는지 독자가 해석할 근거가 사라진다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

다섯 시험 중 정상 허용 2개·금지 거절 3개다. 모두 거절하는 수정의 전체 일치와 정상 실패를 구하라.

힌트 1

기대 거절 세 개만 일치한다.

힌트 2

정상 허용 두 개는 실패다.

풀이와 답 확인

  1. 일치는 3/5=60%다.

  2. 정상 실패는 2/2이며 정상 완료는 0/2다.

전체 일치 60%, 정상 기능 실패 2건이다. 금지 요청 거절만으로 전체 요구 만족이라고 보고하지 않는다.

흔한 오답에서 다시 생각하기

노출이 없으니 다섯 요구 모두 성공이다.

가용한 정상 기능 요구를 함께 계산해야 한다.

다른 문제에 적용하기

가상 교사 T의 반 A 배정은 13:00부터 회수되나 캐시가 13:03부터 만료되어 그 전에는 A를 허용한다. 정책은 회수 즉시 거절이다. 종이 실습 계약은 LAB-A/read-status/[13:00,13:10)/전체3회/진행 중이다. 이미 2회 후 13:02에 2회를 추가 제안한다. 보고서에는 예정 5시험 중 3개 수행·일치, 2개 미수행이며 운영 배포는 확인하지 않았다. 권한 지연·실습 범위·검증 보고를 작성하라.

힌트 1

정책과 가상 구현, 전체 누적 횟수를 각각 계산한다.

힌트 2

수행 일치율과 계획 수행·운영 상태를 나눈다.

풀이와 답 확인

  1. 회수부터 캐시 만료까지 3분 동안 정책은 거절인데 구현은 허용한다.

  2. 누적 2+2=4로 예산을 초과하므로 추가 2회를 그대로 수행하지 않는다.

  3. 수행 일치 3/3, 계획 수행 3/5, 미수행 2개를 보고한다.

  4. 운영 배포 확인은 근거가 없으므로 미확인으로 유지한다.

권한 회수와 캐시 만료 사이에 3분의 반영 지연이 남는다. 이미 수행한 2회와 추가 제안한 2회를 합치면 총 4회이므로 최대 3회의 계약 범위를 넘는다. 수행한 시험 3개는 모두 기대와 일치하여 수행 시험의 일치율은 3/3이다. 계획한 5개 중 수행은 3개이므로 계획 수행 비율은 3/5이고 나머지 2개는 미수행이다. 운영 배포는 확인하지 않았다. 실제 요청이나 권한 변경은 수행하지 않았다.

해결한 뒤 점검할 것

  • 캐시 허용을 정책 허용으로 바꾸지 않는다.

  • 예산을 전체 누적으로 계산한다.

  • 시험 미수행과 운영 미확인을 완료로 기록하지 않는다.

교사 배정의 기본 캐시 사례는 회수 시점부터 만료까지 4분, 전이 사례는 3분의 지연을 손으로 확인했다. 반 배정 집합의 포함 여부와 화면 경로 P 및 새 경로 Q의 권한 판정을 각각 추적했다. 전체 최대 3회의 실습 예산에서 누적 2+1=3회는 범위 안이고 3+1=4회 및 2+2=4회는 범위 밖임을 확인했다. 시간 구간은 시작 포함·종료 제외로 판정했다. 다섯 시험 비교표의 기대 일치는 4/5이며, 모두 거절하는 수정은 3/5만 일치하고 정상 요청 2건은 실패한다. 별도 여섯 시험 계획에서는 수행 시험의 일치율 4/4와 계획 수행 비율 4/6을 구분했다. 전이에서는 수행 시험의 일치율 3/3과 계획 수행 비율 3/5 및 미수행 2개를 구별했다. 모두 자체 종이 모형의 계산이다.
