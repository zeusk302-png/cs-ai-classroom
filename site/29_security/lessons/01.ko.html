소단원 1.1

기밀성·무결성·가용성

성적표가 암호화되어 있어도 선생님이 필요한 시간에 열지 못하면 보안 목표를 달성한 것일까?

준비 개념과 학습 목표

준비 개념

  • 파일은 이름으로 다루는 데이터의 묶음이다. 사용자 또는 실행 프로그램처럼 요청을 하는 주체를 principal이라고 부른다.
  • 권한은 특정 주체가 특정 자료에 특정 행동을 해도 되는지 정한 규칙이다. 읽기와 수정은 서로 다른 권한이다.
  • 비율 미니복습: 100번 중 98번 성공은 98/100=0.98이다. 성공의 정의와 관측 기간을 쓰지 않으면 비율만으로 서비스를 평가할 수 없다.

학습 목표

  • 기밀성·무결성·가용성의 보호 대상과 위반을 구분한다.
  • 하나의 사고가 여러 목표를 동시에 해칠 수 있음을 설명한다.
  • 암호화·권한·복구가 제공하는 보장의 범위를 구분한다.

세 목표는 누가 무엇을 할 수 있어야 하는지를 묻는다

기밀성(confidentiality)은 허가되지 않은 주체에게 정보가 드러나지 않도록 보호하는 성질이다. 성적표를 학생 본인과 담당 교사만 읽게 한다면 다른 학생의 열람은 기밀성 위반이다. 파일을 열었는지뿐 아니라 화면 캡처, 로그, 백업, 통신 중의 정보도 보호 범위에 포함하는지 명세해야 한다. 공개 시간표의 기밀성 요구는 성적표와 다를 수 있다.

무결성(integrity)은 부적절하거나 허가되지 않은 수정·파괴로부터 정보를 보호하는 성질이다. 여기서는 성적을 담당 교사만 바꾸며 승인된 변경의 기록을 남긴다는 정책을 둔다. 가용성(availability)은 허가된 주체가 필요한 때 신뢰할 수 있게 자료와 서비스를 이용하는 성질이다. 누구에게나 항상 열어 두는 것과 다르며, 이용 시점·부하·실패 조건을 함께 적어야 한다.

하나의 사건에 한 글자만 붙이지 않는다

다른 학생이 성적을 읽기만 했다면 주된 위반은 기밀성이다. 점수를 바꾸면 무결성, 정당한 이용자가 마감 전에 접속하지 못하면 가용성도 문제다. 파일을 지우는 행위는 부적절한 파괴이므로 무결성을 해치고, 유일한 사본이었다면 가용성도 해친다. 사고 분류는 서로 배타적인 세 상자를 고르는 문제가 아니다.

가용성을 설명할 가상 측정 규칙으로 마감 전 1분 이내 응답한 허가된 요청을 성공으로 정하자. 시험용 기록 100건 중 성공 98건이면 이 기록의 성공률은 98%다. 이 값은 다음 달에도 98%라는 보장이나 최대 지연시간의 증명은 아니다. 성공한 응답이 잘못된 성적을 돌려준다면 응답률은 높아도 무결성이 부족하다.

도구의 기능과 목표를 연결한다

암호화는 적절한 키 관리와 적용 조건 아래 정보 노출을 줄이는 도구다. 암호문만 보관해도 정당한 이용자가 키를 잃으면 이용할 수 없다. 또한 읽을 권한을 가진 사람이 받은 평문을 외부에 복사하는 문제는 저장 암호화만으로 해결되지 않는다. 암호화라는 이름만으로 인증된 상대, 변경 탐지, 복구 가능성을 모두 얻는다고 가정하지 않는다.

수정 권한 검사와 변경 이력은 누가 바꿨는지 확인하는 데 도움을 주고, 격리된 백업과 복원 점검은 사고 뒤 회복에 도움을 준다. 그러나 기록도 공격자가 바꿀 수 있다면 증거가 약해지고 백업도 함께 삭제되면 복구가 어렵다. 정책, 구현, 운영 조건을 함께 확인하는 이유가 여기에 있다.

중간 과정을 따라가는 예제

가상 성적표 정책: 민지는 자기 성적만 읽을 수 있고 교사만 수정한다. 마감 전 100개의 허가된 요청 중 98개가 1분 이내 올바르게 응답했다. 민지가 준호의 점수를 읽고 수정했고, 이후 유일한 파일을 삭제했다고 가정한다.

  1. 준호 성적을 민지가 읽은 것은 명시한 읽기 권한을 벗어나 기밀성 위반이다.
  2. 민지가 점수를 바꾼 것은 수정 권한이 없으므로 무결성 위반이다.
  3. 유일한 파일의 부적절한 삭제는 무결성 위반이며 교사의 이용을 막아 가용성도 해친다.
  4. 삭제 전 측정 기록의 성공률은 98/100=98%이다. 사고 뒤의 이용 가능성이나 장래의 확률까지 이 수치로 결론내리지 않는다.

세 목표가 모두 영향을 받는다. 성공률 98%는 지정한 과거 기록과 성공 정의에 대한 값이다.

한 단계 더

기밀성을 더 엄밀하게 표현하려면 낮은 권한 이용자가 관찰하는 결과에 비밀 값이 영향을 주는지를 비교할 수 있다. 서로 다른 비밀을 가진 두 상태에서 응답 길이·오류·시간이 달라 비밀을 추론할 수 있다면 내용만 암호화해도 누출 경로가 남는다. 이는 정보 흐름과 부채널 문제로 이어진다. 여기서는 실제 시간 측정을 수행하지 않는다.

소단원 1.2

자산·공격자·신뢰경계

로그인한 학생이 요청에 teacher=true라고 써 보내면 교사 권한을 줘도 될까?

준비 개념과 학습 목표

준비 개념

  • 자산은 보호할 가치가 있는 데이터·서비스·키·기록 등이다. 무엇이 중요한지는 시스템 목적에 따라 정한다.
  • 요청은 사용자가 서비스에 전달하는 행동과 입력이다. 네트워크는 여러 컴퓨터가 이 요청과 응답을 교환하는 통로다.
  • 인증은 요청한 주체를 확인하는 일, 인가는 그 주체가 이 객체에 이 행동을 할 권한이 있는지 판단하는 일이다. 서로 다른 질문이다.

학습 목표

  • 자산·목표·공격자 능력·범위로 위협 모델을 작성한다.
  • 신뢰경계를 지나는 값과 서버의 확인 책임을 추적한다.
  • 클라이언트 주장과 인증된 주체·서버 정책을 구분한다.

위협 모델은 공격자의 능력을 포함한 약속이다

위협 모델은 무엇을 보호하며 어떤 상대가 무엇을 할 수 있고 무엇을 가정할지를 쓰는 모형이다. 학교 문서 서비스의 자산으로 비공개 문서 내용, 변경 권한, 로그인 세션, 복구 사본을 둘 수 있다. 목표는 학생이 자기 문서만 읽고 담당 교사만 수정하며, 사고 뒤 지정한 사본을 복원할 수 있다는 식으로 적는다. 목표 없이 공격 목록만 적으면 필요한 방어를 고르기 어렵다.

가상 공격자 A는 일반 학생 계정을 가지고 자기 요청의 문서 ID와 본문을 바꿀 수 있으며 요청을 반복할 수 있다고 하자. 서버 운영체제·인증 검증기·서버 권한표는 이 첫 모형에서 침해되지 않았다고 가정한다. 이는 공격자가 실제로 그런 곳을 공격할 수 없다는 주장이 아니다. 범위를 바꾸어 서버 관리자 계정 탈취를 허용하면 위험과 방어를 다시 분석해야 한다.

신뢰경계는 건물의 벽보다 가정의 변화다

신뢰경계는 데이터나 제어가 서로 다른 신뢰 수준·권한 영역 사이를 지나가는 위치다. 학생의 브라우저→서버, 서버→문서 저장소, 운영자→백업 저장소를 그릴 수 있다. 같은 컴퓨터 안에서도 일반 프로그램과 특권 프로그램 사이에 경계가 있고, 네트워크가 암호화되어도 클라이언트가 보낸 권한 주장이 신뢰할 만해지는 것은 아니다.

브라우저에서 수정 버튼을 숨기는 것은 화면 안내일 뿐이다. 서버는 인증 결과의 주체 U를 얻고 문서 D와 행동 op에 대해 allow(U, D, op)를 판단해야 한다. 요청 본문의 user=교사 또는 teacher=true를 그대로 권한 근거로 삼으면 공격자 능력에 포함된 입력 수정만으로 경계를 넘어간다. 입력 형식이 올바르다는 검사 역시 그 행동의 권한을 입증하지 않는다.

추적 가능한 위협에서 검토 가능한 방어로 간다

위협을 경로로 적으면 확인 지점을 찾기 쉽다. 학생 A가 문서 ID를 B의 것으로 바꿈→서버가 로그인 여부만 확인→다른 학생의 문서를 반환한다면 인증은 성공했지만 객체별 인가가 빠졌다. 방어는 문서마다 소유자·담당 교사 관계를 확인하고 거절 시 비공개 내용을 내보내지 않는 것이다. 다른 API나 다운로드 경로에서도 같은 정책이 필요하다.

안전성 근거를 간단히 쓰면 학생 주체의 모든 성공한 읽기에서 소유자(U, D)가 참이었다는 성질이다. 이를 지키려면 우회 경로가 없고, 검사한 D와 실제 읽는 D가 같고, 검사에 사용한 정책이 유효해야 한다. 검사 뒤 권한이 바뀌는 경우는 갱신과 접근의 동시성 계약도 필요하다. 종이 모형에서 경로를 막았다고 실제 시스템의 모든 경로를 검증한 것은 아니다.

중간 과정을 따라가는 예제

학생 A의 인증된 주체는 A, 문서 7의 소유자는 B다. 학생은 자기 문서만 읽을 수 있다. 공격자는 요청 ID와 teacher 필드를 바꿀 수 있지만 서버의 인증 결과와 권한표는 바꾸지 못한다. 순차 처리 중 권한표는 고정이다.

  1. A가 read(document=7, teacher=true)를 보낸다. 이 두 필드는 경계 밖 입력이다.
  2. 서버 인증 결과는 A이며 teacher=true를 교사 권한으로 받아들이지 않는다.
  3. 문서 7의 소유자 B≠A이고 A는 서버 권한표의 담당 교사도 아니다.
  4. allow(A,7, read)=false이므로 거절하고 문서 내용은 반환하지 않는다.

허용되지 않는다. 인증된 계정이 있다는 사실과 문서 7을 읽을 권한이 있다는 사실은 다르다.

소단원 1.3

최소권한과 심층방어

문서 보기 프로그램에 모든 파일 삭제 권한까지 주면 무엇이 달라질까?

준비 개념과 학습 목표

준비 개념

  • 권한 집합은 허용한 행동들의 모음이다. {read}⊆{read, write, delete}이면 첫 집합의 모든 권한이 둘째에 들어 있다는 뜻이다.
  • 신뢰경계는 데이터나 제어가 서로 다른 권한·신뢰 가정의 영역 사이를 지나는 곳이다. 화면과 서버 정책을 나누어 생각한다.
  • AND는 두 조건이 모두 참일 때 참, OR는 하나 이상 참일 때 참이다. 두 검사 중 하나만 통과해도 허용하는지 둘 다 필요한지 구분한다.

학습 목표

  • 작업·대상·기간에 맞춰 최소권한을 구성한다.
  • 서로 다른 실패 경로를 막는 심층방어를 논리식으로 추적한다.
  • 방어 수와 독립성·운영 가정이 서로 다름을 설명한다.

최소권한은 업무를 할 수 있는 가장 좁은 권한이다

최소권한 원칙은 사용자와 프로그램에게 작업에 필요한 범위만 허용하는 것이다. 문서 미리보기 작업은 특정 문서 읽기와 미리보기 쓰기를 필요로 할 수 있지만 성적 수정이나 전체 백업 삭제는 필요하지 않다. 권한은 행동만이 아니라 대상과 기간도 포함한다. 한 폴더의 한 문서를 잠시 읽는 권한과 모든 사용자의 문서를 계속 읽는 권한은 같지 않다.

필요한 작업을 불가능하게 만들 정도로 모두 막는 것이 최소권한의 목표는 아니다. 필요한 권한 R과 부여한 권한 G에서 R⊆G가 되어야 작업이 가능하다. G에 불필요한 권한이 있으면 사고 시 피해 범위가 커질 수 있다. R=G가 가능한 단순 모형이라도 실제로 필요한 권한 발견과 정책 변경·철회·캐시 만료는 별도 문제다.

각 접근을 검사하고 실패 시 권한을 늘리지 않는다

기본 거부는 정책에서 명확하게 허용하지 않은 행동을 거절하는 원칙이다. 권한표가 없거나 인증 검사가 실패했는데 편의를 위해 관리자 권한으로 통과시키면 실패가 권한 상승 경로가 된다. 완전 매개는 보호할 모든 접근에서 권한이 확인되어야 한다는 원칙이다. 첫 화면만 검사하고 다운로드나 수정 API를 빼먹으면 보호가 완성되지 않는다.

예를 들어 읽기 전용 미리보기 프로세스가 침해되어도 저장소가 그 프로세스의 쓰기를 거절한다면 원본 변경 경로를 줄일 수 있다. 그러나 읽기 권한 안의 데이터 유출이나 많은 읽기로 인한 자원 고갈은 여전히 가능하다. 최소권한은 피해를 제한하는 설계 원칙이며 침해 자체나 모든 보안 목표를 없애는 만능 증명이 아니다.

심층방어는 같은 실수를 여러 번 세는 것이 아니다

심층방어는 하나의 통제가 실패했을 때도 다른 통제가 위험 경로를 막도록 여러 보호 수단을 배치하는 것이다. 미리보기 서비스의 쓰기 거부와 원본의 독립 백업은 서로 다른 역할이다. 전자는 무단 변경을 막고 후자는 일부 사고 뒤 복구를 돕는다. 탐지 로그가 남았다는 사실은 사고를 예방했다는 뜻도 아니므로 예방·탐지·복구를 구분한다.

가상 쓰기 경로에서 서버 인가 B1과 저장소 인가 B2를 둘 다 통과해야 원본을 바꿀 수 있다고 하자. 공격이 성공하려면 두 장벽의 우회가 모두 필요하다는 논리 구조가 된다. 하지만 같은 관리자 계정이 양쪽 정책을 모두 바꿀 수 있으면 한 계정 탈취로 함께 무너질 수 있다. 두 방어의 실패 확률을 곱하려면 실패 사건 독립 같은 추가 모형이 필요하며 장벽 개수만으로 확률을 계산하지 않는다.

중간 과정을 따라가는 예제

미리보기 작업의 필요한 권한 R={문서 7 읽기, 미리보기 쓰기}. 초기 G는 R에 성적 수정과 백업 삭제를 더한 4개 권한이다. 원본 쓰기는 서버 인가 B1과 별도 저장소 인가 B2가 모두 승인해야 하며 두 정책은 순차 추적 동안 고정이라고 하자.

  1. 불필요한 두 권한을 제거하여 G′=R로 만든다. 작업에 필요한 두 권한은 남는다.
  2. 공격자가 미리보기 프로세스를 제어해 성적 수정 요청을 한다면 G′에 해당 권한이 없어 거절된다.
  3. 다른 원본 쓰기 경로에서 B1을 우회했지만 B2가 거절했다면 true AND false=false라 변경되지 않는다.
  4. B1과 B2를 모두 우회한 경우 true AND true=true로 통과하므로 두 정책을 함께 침해하는 공격은 범위에 남는다.

부여 권한은 4개에서 2개로 줄고 작업은 가능하다. 한 장벽만 우회한 쓰기를 막는 모형이며 모든 공격이 불가능하다는 결론은 아니다.

종이와 본문으로 직접 해보기

B1 우회 여부와 B2 우회 여부의 네 조합을 표로 써라. 원본 변경이 가능한 조합을 찾고, 두 장벽을 동일한 관리자 비밀번호로 모두 바꿀 수 있다면 무엇이 달라지는지 적어라.

힌트 보기

쓰기 성공 조건은 두 우회가 모두 참이다. 하나의 원인이 두 참을 함께 만들 수 있는지 검사하라.

풀이 보기

(false, false), (false, true), (true, false)는 변경 불가이고 (true, true)만 가능하다. 같은 비밀번호로 둘 다 관리하면 한 비밀번호 탈취가 두 우회를 동시에 만들 수 있다. 장벽은 둘이어도 실패의 공통 원인을 제거한 것은 아니다.

오해와 반례

보호 장치를 두 개 쓰면 실패 가능성은 무조건 제곱으로 줄어든다.

같은 관리자 자격증명으로 둘을 모두 해제하는 반례가 있다. 독립 가정 없이 확률을 곱할 수 없고, 별도 권한 영역과 운영·복구 책임이 실제로 분리되는지 확인해야 한다.
