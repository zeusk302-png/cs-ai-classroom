ASLR·DEP·stack canary

주소와 실행 권한과 봉인은 같은 검사일까?

자체 종이 프로그램의 페이지 C는 읽기·실행, D는 읽기·쓰기를 허용한다. D에서 명령을 실행할 수 없다는 조건과 D의 자료를 올바르게 썼다는 조건은 다르다. 별도 guard 비교도 지정한 값과 시점에 관한 검사다.

주소 배치를 여섯 가지로 정하는 확률 모형을 추가하자. 매 시행 새로 뽑는지, 한 번 뽑아 유지하는지, 균등한지를 먼저 적는다. 실제 Windows의 주소 엔트로피를 측정한 수치가 아니다.

주소를 바꾸는 ASLR

프로그램은 명령과 자료를 메모리의 주소로 찾아간다. ASLR은 실행 때 주소 배치를 무작위화하여 과거에 알던 위치를 그대로 믿기 어렵게 만드는 방어다. 자료를 올바르게 처리하는지 검사하는 규칙은 아니다.

Windows의 /DYNAMICBASE는 이미지 재배치와 관련 가상 주소 배치에 영향을 준다. 실제 가능한 배치 수와 무작위성은 운영체제·플랫폼·설정에 달려 있다. 이 글의 여덟 배치는 확률을 배우기 위한 가상 모형이며 실제 보안 강도 측정값이 아니다.

실행 권한을 나누는 DEP

종이 위에 두 페이지 C와 D를 그리자. C는 읽기와 실행을 허용하고 D는 읽기와 쓰기를 허용하지만 실행은 허용하지 않는다. D에 자료를 쓰는 것과 D를 명령으로 실행하는 것은 다른 요청이다. DEP가 적용된 비실행 페이지의 실행 요청은 예외를 일으킨다.

DEP가 자료 쓰기 자체를 모두 금지하는 것은 아니다. 따라서 D의 잘못된 자료값이나 허가된 명령에서 일어난 논리 오류는 이 구분만으로 없어지지 않는다. 동적으로 코드를 만드는 프로그램도 실행 권한을 따로 관리해야 한다.

봉인을 비교하는 canary

Stack canary는 보호 대상 함수 진입 때 guard를 두고 반환 과정에서 그 값이 보존되었는지 검사한다. GCC의 기본·strong·all 옵션은 보호 대상으로 삼는 함수 범위가 다르다. 소스에 보이는 모든 지역 변수가 실제 stack에 놓이는 것도 아니다.

Guard가 달라지면 오류를 보고하고 종료하는 방어는 추가 손상을 줄일 수 있지만 서비스 중단은 생길 수 있다. Guard가 그대로라는 결과는 비교 대상 값이 같다는 뜻이다. 모든 메모리 접근과 모든 업무 판단이 올바르다는 증명으로 바꾸면 안 된다.

중간 과정을 따라가는 예제

가상 배치가 여덟 개이고 매번 독립 균등하게 새로 정해진다. 한 번에 한 배치를 맞히는 사건의 두 시행 중 적어도 한 번 성공 확률을 구하라. D는 RW·비실행, guard는 진입 7/반환 9다.

  1. 한 시행의 성공 확률은 1/8, 실패 확률은 7/8이다.

  2. 독립적인 두 시행 모두 실패할 확률은 (7/8)²=49/64다.

  3. 적어도 한 번 성공할 확률은 여사건으로 1−49/64=15/64다.

  4. D 쓰기는 페이지 권한상 허용되고 D 실행은 금지된다. Guard 비교는 7≠9이므로 실패다.

15/64. 독립 재배치 확률, 실행 권한, guard 검사는 서로 다른 질문에 답한다.

재추첨과 고정 배치

여섯 배치에서 한 번에 하나를 추측한다. 세 번 독립 재추첨과 고정 배치에 서로 다른 세 선택을 비교하라.

  1. 재추첨은 모두 실패 (5/6)³=125/216, 적어도 한 번 일치는 91/216이다.

  2. 고정 균등 배치는 서로 다른 세 선택의 성공 확률 3/6=1/2다.

91/216과 1/2는 서로 다른 실험의 결과다.

비교할 점

두 확률을 실제 방어 성능으로 해석하지 않는다.

쓰기를 마친 코드 페이지

자체 순차 권한 정책에서 생성 중 페이지 J는 RW·비실행, 생성 완료 후에는 RX·비쓰기로 바꾼다. 두 상태의 쓰기·실행을 판정하라.

  1. 생성 중 쓰기는 허용되고 실행은 금지된다.

  2. 완료 뒤 쓰기는 금지되고 실행은 허용된다.

상태별 권한을 적고 한꺼번에 RWX라고 기록하지 않는다.

비교할 점

이 계획은 실제 JIT나 권한 변경 API 실행 증거가 아니다.

허용 함수가 사용자의 뜻과 달라도 통과할까?

자체 호출 지점 s의 허용 집합은 {P,L}, 지점 u는 {P}다. 같은 대상 L도 어느 지점에서 호출하는지에 따라 표의 판정이 달라진다. 실제 Clang CFI는 scheme별 동적 타입과 빌드 조건을 사용하며 이 표는 집합 직관만 보여 준다.

별도로 길이 4의 배열 인덱스 범위는 0..3이다. 요청한 업무는 P이고 자료 소유자는 민이라고 정하자. 호출 대상과 인덱스가 허용되어도 다른 사용자의 자료를 보거나 요청한 동작과 다른 동작을 할 수 있다.

허용된 호출 대상

CFI는 특정 간접 호출·형 변환 등이 정해진 제어 흐름 규칙에 맞는지 확인하는 방어다. 호출 지점에서 허용하는 대상 집합을 정하고 실제 대상이 그 집합에 있는지 확인한다고 생각하면 첫 직관을 얻을 수 있다. 실제 Clang의 각 scheme은 동적 타입 등의 구체적인 조건을 사용한다.

모든 CFI 설정이 모든 전송을 검사하는 것은 아니다. Scheme, LTO 및 visibility 등 빌드 조건에 따라 적용 범위가 달라진다. Clang 기본 실패 동작은 중단이지만 진단·복구 설정에 따라 달라질 수 있으므로 제품 보장을 말할 때 설정도 기록해야 한다.

메모리 안전성의 뜻

메모리 안전 언어는 경계 밖 접근이나 유효하지 않은 수명 사용 같은 오류를 언어의 규칙과 검사로 제한한다. 길이 3 배열의 인덱스 집합은 {0,1,2}다. 인덱스 3을 거부하는 종이 모형은 경계 검사의 의미를 보여 주지만 실제 언어의 모든 동작을 재현하지는 않는다.

Rust에서 safe 코드의 보장은 언어·컴파일러뿐 아니라 사용하는 unsafe 구현이 안전한 계약을 지킨다는 신뢰에 기대고 있다. Unsafe는 아무 규칙도 없다는 뜻이 아니라 컴파일러가 모두 검사하지 못하는 의무를 작성자가 부담한다는 뜻이다. 외부 함수와 라이브러리 경계도 함께 확인한다.

규칙과 의도 사이

허용 집합 {작게그리기,크게그리기}에서 크게그리기를 부르는 것은 집합 검사에 맞을 수 있다. 사용자가 작은 그림을 요청했다면 결과는 업무 의도와 다르다. 제어 흐름의 구조적 제약은 화면 요구사항이나 권한 판단을 대신하지 않는다.

반대로 인덱스 1에 접근하면서 다른 사용자의 자료를 보여 주는 일은 경계 안에서 일어날 수 있다. 메모리 안전성은 중요한 기반이지만 개인정보 접근 정책, 입력의 의미, 계산의 정확성을 별도로 검증해야 한다.

준비 개념과 학습 목표

준비 개념

  • 검사 통과와 증명의 차이

실패율을 곱하려면 어떤 정보가 필요할까?

자체 사건 집합 Ω={1,2,3,4,5,6,7,8}은 균등하다. 방어 A의 실패 집합은 {1,2,3,4}, B는 {3,4,5,6}이다. 둘 다 놓치는 사건은 교집합 {3,4}로 직접 계산한다. 이 숫자는 실제 시스템의 잔여 위험 측정이 아니다.

실패율 P(A실패)와 P(B실패)만으로 결합 실패를 결정할 수 없다. 교집합이나 조건부 확률이 필요하다. 방어를 여러 층으로 구성하는 설계와 그 실패들이 독립이라는 수학적 가정을 구별하자.

먼저 확인할 개념

    교집합·독립성·미시험 입력으로 보장 범위를 제한한다.

  • ASLR·DEP·stack canary

    오류 감지 뒤 중단이 가용성과 다른 질문임을 확인한다.

보장 문장을 잘라 읽기

방어 설명에는 무엇을 검사하는지, 어디까지 적용되는지, 실패하면 무엇을 하는지가 함께 들어가야 한다. DEP는 비실행 페이지의 실행을 제한하고 canary는 보호 함수의 guard 변화를 특정 시점에 확인한다. 둘을 모두 켰다는 사실은 모든 종류의 오류를 검사했다는 말이 아니다.

여기서 한계는 실제 시스템을 공격하는 절차가 아니라 보장 밖에 있는 사건의 분류다. 업무 권한 오류, 검사 제외 함수, 허용된 호출 대상에서의 논리 오류를 따로 표시하면 과도한 안전 주장을 피할 수 있다.

겹친 실패의 확률

가상 방어 A와 B가 각각 절반의 사건에서 놓친다고 하자. 둘 다 놓친 사건이 같은 절반이면 함께 놓치는 확률도 1/2다. 개별 실패 확률만 알고 1/2×1/2라고 곱하면 틀릴 수 있다.

독립적인 실패 사건이라는 추가 가정이 있을 때에만 이 예의 결합 실패가 1/4가 된다. 실제 방어는 같은 설정 오류나 같은 검사 제외 경계의 영향을 함께 받을 수 있다. 방어를 여러 층으로 배치하는 장점과 확률 독립성 증명을 구별한다.

검사와 시험의 해석

여덟 입력 0..7 중 0..4만 시험했다면 다섯 개가 통과해도 나머지 세 개의 결과는 아직 모른다. 입력 7에서만 잘못된 권한 판정이 난다는 반례는 시험 성공을 전체 안전성으로 바꾸지 못하게 한다.

오류를 감지한 뒤 종료하는 방어는 손상 확산을 제한하면서 가용성에 비용을 줄 수도 있다. 안전성·가용성·정확성의 요구를 따로 적고, 실제 빌드와 장치에서 확인한 사실과 종이 설명을 구분해 공개한다.

실패율을 곱하려면 어떤 정보가 필요할까?

A={1,2,3,4}, B={3,4,5,6}

A∩B={3,4}

결합 실패 2/8

B=A

A∩B=A

결합 실패 4/8

B={5,6,7,8}

교집합 없음

이 모형의 결합 실패 0

A,B에 C={2,4,6,8} 추가

A∩B∩C={4}

결합 실패 1/8

시험 0..4, 전체 0..7

미시험 5,6,7

나머지 결과 미확인

각 집합은 해당 방어가 놓치는 사건이다. 감지하는 집합과 뒤집어 읽지 않는다.

중간 과정을 따라가는 예제

사건1..8은 균등하다. A가 놓치는 집합은 {1,2,3,4}. B가 놓치는 집합이 같은 경우와 {3,4,5,6}인 경우를 비교하라.

  1. A 실패는4/8=1/2다. 두 B도 각각4/8=1/2다.

  2. 같은 집합이면 교집합이 {1,2,3,4}라 결합 실패는4/8=1/2다.

  3. 다른 집합이면 교집합은 {3,4}라 결합 실패는2/8=1/4다.

  4. 두 번째 표에서는 실패 사건의 곱과 교집합 확률이 같지만 첫 번째 표에서는 다르다. 실제 방어에 어느 표가 맞는지는 별도 근거가 필요하다.

같은 개별 실패율에서도 결합 실패는 1/2 또는 1/4다. 결합 분포가 필요하다.

조건을 바꾸어 비교하기

같은 개별 실패율의 다른 결합

A와 실패율 1/2인 B가 같은 집합일 때와 서로 겹치지 않을 때를 비교하라.

  1. 같으면 교집합 크기 4로 1/2다.

  2. 겹치지 않으면 교집합 크기 0으로 0이다.

개별 실패율만 같아도 결합 실패는 다르다.

비교할 점

두 경우 모두 무조건 1/4라고 곱하지 않는다.

조건부 실패를 이용한다

일반 사건에서 P(A실패)=0.2, P(B실패|A실패)=0.7이다. 둘 다 실패할 확률을 구하라.

  1. 조건부 확률 정의로 P(A∩B)=P(A)P(B|A)다.

  2. 0.2×0.7=0.14다.

결합 실패는 0.14다.

비교할 점

이 정보로 P(B실패) 자체가 0.7이라고 결론낼 수 없다.

종이와 본문으로 직접 해보기

B의 실패 집합을 {5,6,7,8}로 바꿔 결합 실패를 계산하고, 입력0..4 시험이 통과했을 때 입력 7의 보장을 말해 보라.

힌트 보기

교집합을 직접 그린다. 시험하지 않은 입력은 결과를 알 수 없다.

풀이 보기

교집합이 공집합이므로 이 유한 종이 모형의 결합 실패는0이다. 실제 시스템에 같은 결론을 옮기려면 모형의 완전성도 필요하다. 입력 7은 미시험이므로 통과를 보장할 수 없다.

오해와 반례

방어 두 개의 실패율을 곱하면 실제 잔여 위험을 알 수 있다.

동일 네 사건을 둘 다 놓치는 위 예에서 곱 1/4와 실제 1/2가 다르다. 공통 원인·적용 범위·분포가 확인되지 않으면 수치 보장을 주장하지 않는다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

기본 A,B에 C={2,4,6,8}를 추가한 세 결합 실패와 개별 실패율의 곱을 계산하라.

힌트 1

세 집합을 동시에 포함하는 사건을 찾는다.

힌트 2

각 집합은 8개 중 4개다.

풀이와 답 확인

  1. 세 교집합은 {4}로 1/8이다.

  2. 개별 곱도 (1/2)³=1/8이다. 이 표에서는 A∩B={3,4}, A∩C={2,4}, B∩C={4,6}이 각각 2/8=1/4이고 세 교집합은 1/8이어서 모든 비자명한 독립 조건을 만족한다.

이 균등 유한 모형에서는 세 실패 사건이 상호 독립이다. 삼중 등식 하나만 확인하는 것은 충분하지 않으며 실제 방어에 이 분포를 그대로 적용하지 않는다.

흔한 오답에서 다시 생각하기

세 곱이 같기만 하면 모든 세 사건은 항상 독립이다.

단일 삼중 등식만으로 모든 부분집합의 독립 조건을 확보하지 못한다.

연습 2 · 오류 찾아 고치기

P(A실패)=P(B실패)=1/2만으로 결합 실패 1/4라고 적었다. 가능한 범위와 필요한 정보를 적어라.

힌트 1

교집합은 개별 집합보다 클 수 없다.

힌트 2

합집합 확률은 최대 1이다.

풀이와 답 확인

  1. 하한 max(0,1/2+1/2−1)=0, 상한 min(1/2,1/2)=1/2다.

  2. 교집합이나 조건부 실패, 독립성 근거가 더 필요하다.

결합 실패는 정보만으로 0..1/2 범위다.

흔한 오답에서 다시 생각하기

방어가 두 개면 무조건 독립이다.

공통 설정·검사 제외 영역이 실패를 함께 만들 수 있다.

연습 3 · 직접 만들어 보기

전체 입력 0..7에서 시험 0..4를 통과하지만 7에서 실패하는 자체 판정 함수를 만들어라.

힌트 1

시험 집합에 없는 값을 고른다.

힌트 2

결과를 참·거짓으로 정의한다.

풀이와 답 확인

  1. Q(i)=(i≠7)로 정한다.

  2. 시험한 다섯 입력은 참이지만 Q(7)=false다.

유한 시험 통과가 전체 명제의 증명이 아닌 반례다.

흔한 오답에서 다시 생각하기

다섯 번 통과했으므로 7도 통과할 것이다.

미시험 결과를 관측한 것으로 기록하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

요청 100개 중 합성 기록에서 guard 실패로 3개를 중단하고 나머지 97개에 응답했다. 완료 응답 비율과 전체 업무 정확성 보장을 구별하라.

힌트 1

중단과 응답은 가용성 측면의 사건이다.

힌트 2

응답 내용의 정확성 정보는 없다.

풀이와 답 확인

  1. 응답 완료 비율은 97/100=97%다.

  2. 97개의 내용 정확성이나 중단하지 않은 경로의 메모리 안전성은 이 표만으로 알 수 없다.

오류 감지·가용성·정확성의 분모와 조건을 각각 적는다.

흔한 오답에서 다시 생각하기

guard가 멈췄으므로 모든 요청은 안전하게 성공했다.

중단은 성공 응답이 아니며 남은 내용의 정확성은 별도 검사가 필요하다.

교집합이 빈 집합이면 실제 위험도 0인가?

한 단계 더

세 방어의 실패 집합을 여덟 사건 위에 직접 그려 세 겹 교집합을 구하자. 그 뒤 사건의 균등성, 검사 적용 범위, 공통 신뢰 요소라는 세 가정을 한 문장씩 적어 수치와 가정이 떨어지지 않게 연습한다.

다른 문제에 적용하기

자체 D 페이지는 RW·비실행이고 guard는 진입/종료 모두 12다. 요청자는 P와 자신의 자료를 원했지만 지점 s={P,L}에서 L과 길이 4 배열의 인덱스 3에 있는 다른 사용자 자료를 선택했다. A실패율 0.2, B실패의 A실패 조건부 확률 0.7도 주어졌다. 각 보장과 실패, 결합 확률의 범위를 설명하라.

힌트 1

호출 대상·배열 경계·요청 의도·자료 인가를 따로 쓴다.

힌트 2

조건부 확률은 개별 B 실패율과 다르다.

풀이와 답 확인

  1. D의 쓰기는 페이지 권한상 허용되고 실행은 금지다. guard 값 비교는 통과한다.

  2. L은 s의 허용 대상이고 3은 배열 경계 안이지만 요청 P와 다르며 다른 사용자 자료 인가는 실패다.

  3. 둘 다 실패할 확률은 0.2×0.7=0.14이며 P(B실패)나 실제 시스템 성능으로 확대하지 않는다.

  4. 설정·입력·빌드 검증과 학생 시험은 실제 수행 전까지 미수행으로 남긴다.

구조와 값 비교 통과가 업무 의미·인가를 대체하지 않는다. 확률 0.14는 명시한 조건부 종이 모형의 결과다.
