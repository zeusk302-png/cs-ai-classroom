소단원 8.1

연속할당·분할·페이징

하나의 긴 메모리 공간은 물리적으로도 붙어 있어야 할까?

준비 개념과 학습 목표

준비 개념

  • 바이트 주소

  • KiB=1024 바이트

학습 목표

  • 분할과 페이징의 배치 단위를 구별한다.

  • 주소 변환과 내부·외부 낭비를 계산한다.

첫 바이트의 물리 주소를 알면 다음 열다섯 바이트도 그대로 이어질까?

자체 페이징 모형의 page와 frame은 각각 256바이트다. 가상 page 0은 물리 frame 5, 가상 page 1은 물리 frame 2에 대응하며 둘 다 읽기를 허용한다. 가상 주소 250부터 16바이트를 읽으면 대상은 반열린 구간 [250,266), 즉 250부터 265까지다. 가상 공간에서는 연속이지만 page 경계 256에서 물리 변환의 대상 frame이 바뀐다.

첫 조각은 가상 [250,256)의 6바이트이며 물리 [1530,1536)이다. 둘째 조각은 가상 [256,266)의 10바이트이며 물리 [512,522)다. 첫 물리 주소 1530에 길이 16을 더한 [1530,1546)을 읽으면 둘째 page의 데이터를 찾지 못한다. 페이지 내부 offset을 보존한다는 규칙은 page 경계를 넘어 같은 PFN을 유지한다는 뜻이 아니다.

두 page가 모두 매핑돼 있어도 보호는 별도로 확인한다. 이번에 page 0은 쓰기를 허용하고 page 1은 읽기 전용이라고 바꾸자. 전체 쓰기를 시작하기 전에 모든 조각의 매핑과 권한을 검사하는 자체 사전 검사 정책이라면 둘째 조각에서 거절하고 아무 바이트도 쓰지 않는다. 실제 CPU 명령이나 OS 복사 함수가 이 원자적인 정책을 자동 제공한다고 주장하지 않는다. 정책을 정하지 않은 부분 쓰기는 별도 분석이 필요하다.

공간 비용도 할당 단위를 밝혀야 한다. 100바이트 객체 둘에 각자 256바이트 page를 전용 배정하면 512바이트를 확보하고 312바이트가 남는다. 같은 권한과 수명으로 한 page에 함께 놓을 수 있고 정렬 간격을 두지 않는 다른 모형에서는 200바이트를 사용하여 56바이트가 남는다. 객체마다 서로 다른 page 보호가 필요하면 이러한 공동 배치를 그대로 사용할 수 없다.

연속 공간의 경계를 검사한다

단순 연속할당에서는 주소공간 전체를 하나의 물리 구간에 둔다. 상대 주소가 bounds보다 작은지 검사하고 base를 더해 물리 주소로 바꾼다. 비어 있는 가상 구간까지 같이 확보하면 낭비가 크다.

분할은 code/heap/stack 같은 논리 segment마다 base와 bounds를 둔다. 각 segment 안은 연속이지만 segment끼리는 다른 위치에 놓을 수 있다. 아래는 상향 segment만 쓰며 하향 stack의 별도 방향 처리는 생략한다.

고정 page와 frame을 대응시킨다

페이징은 가상 공간을 고정 크기 page, 물리를 같은 크기 frame으로 나눈다. page table은 VPN을 PFN으로 대응시킨다. 프로그램의 연속 가상 page가 물리에서 붙어 있을 필요는 없다.

주소를 VPN과 offset으로 나누고 PFN×page_size+offset으로 변환한다. offset은 그대로다. 주소가 매핑돼 있어도 권한 검사를 통과해야 읽고 쓸 수 있다.

낭비가 생기는 위치를 찾는다

가변 길이 연속 구간 사이의 작은 구멍은 외부 단편화다. 총 빈 공간이 충분해도 필요한 연속 구간이 없을 수 있다. compaction은 복사와 매핑 갱신 비용을 가진다.

고정 page에서는 마지막 할당 page 내부의 미사용 바이트가 내부 낭비가 될 수 있다. page table 공간도 비용이므로 페이징이 모든 메모리 낭비를 없애는 것은 아니다.

반열린 구간의 길이는 끝−시작이다. 가상 조각 길이 6+10=16을 확인하고, 두 물리 구간을 하나의 연속 구간으로 합치지 않는다.

중간 과정을 따라가는 예제

요구량 10 KiB를 page 4 KiB로 할당한다. 가상 주소 5000의 VPN 1이 PFN 7에 매핑돼 있다. 별도 상향 segment base=20000,size=3000에서 offset 2500을 읽는다.

  1. 10 KiB=10240 바이트라 ceil(10240/4096)=3 page를 할당하고 12288−10240=2048 바이트가 내부에 남는다.

  2. 5000=1×4096+904이므로 PFN 7에서 7×4096+904=29576이다.

  3. segment offset 2500<3000이므로 물리 22500이다. offset 3000은 bounds 밖이다.

3 page와 내부 낭비 2048 바이트, page 물리 주소 29576, segment 물리 주소 22500이다. 두 변환은 서로 다른 모델이다.

조건을 바꾸어 비교하기

경계의 양쪽 주소

가상 255와 256을 각각 번역하고 물리 주소 차이를 구하라.

  1. 255는 VPN 0, offset 255이므로 5×256+255=1535다.

  2. 256은 VPN 1, offset 0이므로 2×256=512다.

  3. 두 가상 주소 차이는 1이지만 물리 주소 차이는 512−1535=−1023이다.

물리 주소는 연속하거나 증가할 필요가 없다. 같은 page 안에서만 offset의 연속성이 유지된다.

비교할 점

가상 연속 배치와 물리 연속 배치는 서로 다른 조건이다.

배치와 보호 요구

100바이트 객체 둘을 각각 전용 page 또는 간격 없이 공동 page에 놓는다. 공동 배치가 항상 가능한가?

  1. 전용 배정은 2×256=512바이트이고 미사용량은 512−200=312다.

  2. 공동 배정은 256바이트이고 미사용량은 256−200=56이다.

  3. 한 객체는 쓰기 허용, 다른 객체는 읽기 전용을 page 보호만으로 강제해야 한다면 같은 page의 동일 보호를 나눌 수 없다.

자체 단순 배치에서는 한 page를 절약하지만 독립 page 권한 요구가 있으면 공동 배치를 거절해야 한다.

비교할 점

오브젝트 수준의 다른 보호 기법을 구현했다고 가정하지 않는다.

오해와 반례

페이징을 쓰면 공간 낭비가 완전히 사라진다.

10 KiB 요구에 12 KiB를 배정하는 예에 2048 바이트 내부 낭비가 있고 page table도 공간을 쓴다.

연습 1 · 값과 상태 예측

같은 매핑에서 가상 254부터 4바이트를 읽는다. 두 물리 조각을 구하라.

힌트 1

가상 대상은 [254,258)이다.

힌트 2

256에서 VPN이 바뀐다.

풀이와 답 확인

  1. 가상 [254,256)은 PFN 5의 [1534,1536)이다.

  2. 가상 [256,258)은 PFN 2의 [512,514)이다.

물리 조각은 각각 2바이트이며 전체 4바이트를 보존한다.

흔한 오답에서 다시 생각하기

첫 물리 주소 1534부터 4바이트를 읽으면 된다.

page 경계 뒤의 가상 데이터는 다른 PFN에 있어 연속 물리 주소로 대신할 수 없다.

연습 2 · 오류 찾아 고치기

page 0은 쓰기 가능하고 page 1은 읽기 전용이다. 모든 조각을 먼저 검사하는 자체 정책에서 [250,266) 쓰기를 매핑 성공만 보고 허용한 판정을 고쳐라.

힌트 1

두 page의 매핑 존재는 이미 확인했다.

힌트 2

각 조각에 필요한 W 권한을 따로 검사한다.

풀이와 답 확인

  1. page 0 조각은 쓰기 권한을 통과한다.

  2. page 1 조각은 W=0이라 쓰기를 거절한다.

  3. 사전 검사 정책이므로 전체 검사 실패 뒤 실제 쓰기를 시작하지 않는다.

이 정책에서는 쓰기 전체를 거절한다. 실제 복사 API의 원자적 실패 보장과 혼동하지 않는다.

흔한 오답에서 다시 생각하기

매핑만 있으면 모든 동작을 허용하고 부분 실패 여부도 알 필요 없다.

존재·동작 권한·실패 시 자료 변경 범위는 별도 계약이다.

연습 3 · 직접 만들어 보기

동일한 가상 두 page를 물리에서도 연속 증가시키려면 page 1의 PFN을 어떻게 바꿔야 하는가? page 0의 PFN 5는 유지한다.

힌트 1

frame 한 개의 크기는 256바이트다.

힌트 2

page 0 끝 다음 물리 주소는 1536이다.

풀이와 답 확인

  1. page 1 첫 물리 주소를 1536으로 정한다.

  2. 1536÷256=6이라 page 1의 PFN은 6이어야 한다.

  3. 이 다른 매핑에서는 가상 [250,266)이 물리 [1530,1546)에 대응한다.

PFN 6으로 바꾸면 해당 두 page가 연속된다. 원래 PFN 2 매핑의 결론을 그대로 유지하는 것은 아니다.

흔한 오답에서 다시 생각하기

offset이 유지되니 PFN은 어떤 값이어도 물리 연속이다.

offset 보존과 인접 page의 frame 관계는 따로 정해야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

객체 하나의 요구량이 100바이트이고 전용 page를 배정한다. page 256과 page 64에서 확보량·미사용량·필요 PTE 개수를 비교하라.

힌트 1

64바이트 두 page로 100바이트를 덮을 수 있다.

힌트 2

각 page당 PTE 한 개라고만 정하며 PTE 실제 바이트 폭은 주어지지 않았다.

풀이와 답 확인

  1. page 256에서는 1개를 확보하여 256바이트, 미사용 156바이트, PTE 1개다.

  2. page 64에서는 2개를 확보하여 128바이트, 미사용 28바이트, PTE 2개다.

  3. 미사용량은 줄지만 표 항목은 늘며 실제 표 할당량은 구조와 항목 폭을 더 정해야 한다.

작은 page가 모든 비용을 자동 최소화하는 것은 아니다.

흔한 오답에서 다시 생각하기

page를 줄이면 데이터와 표의 모든 공간 비용이 항상 함께 줄어든다.

이 자체 계산에서는 데이터 확보량은 줄고 필요한 표 항목 수는 늘어난다.

  • 희소·조밀 매핑의 표 공간을 비교한다.

같은 두 page를 매핑했는데 표 공간이 왜 달라질까?

기본 단원과 같은 자체 16비트 가상 주소 모형을 사용한다. page는 256바이트, PTE와 PDE는 각각 4바이트다. leaf 한 page에는 64개 PTE가 들어가므로 VPN의 8비트를 directory 인덱스 2비트와 leaf 인덱스 6비트로 나눈다. directory는 논리 16바이트지만 물리 256바이트 한 page를 항상 확보하고, 매핑이 하나라도 있는 directory 구간마다 leaf 한 page를 확보한다고 정한다.

매핑 VPN이 62와 63이면 둘 다 directory 0에 속해 leaf 하나와 directory 하나, 합계 512바이트다. VPN이 63과 64이면 경계 양쪽의 directory 0과 1을 써서 leaf 두 개와 directory 하나, 합계 768바이트다. 데이터 page는 두 모형 모두 두 개지만 번역 표의 분포가 다르다. 데이터 frame 512바이트는 표 비용에 포함하지 않고 필요하면 별도로 더한다.

표 조회의 물리 주소도 데이터 주소와 구별한다. directory 물리 base를 4096으로 정하자. directory 1의 PDE 위치는 4096+1×4=4100이다. 그 PDE가 leaf의 PFN 20을 가리키면 leaf base는 5120이다. 가상 주소 0x4005는 VPN 64, directory 1, leaf 0, offset 5라서 PTE 주소는 5120이다. 그 PTE의 데이터 PFN이 9이면 최종 물리 주소는 9×256+5=2309다.

매핑이 없는 leaf는 생략한다고 정한 상태에서, 매핑이 존재하는 directory 구간 수를 k라고 쓰면 표 할당량은 256(k+1)바이트다. 이 모형의 선형 표는 256×4=1024바이트다. k가 0,1,2일 때 더 작고, k=3이면 같으며 k=4이면 더 크다. k=0이어도 root를 유지하는 이번 규칙에서 256바이트이며 실제 OS가 빈 주소공간을 반드시 같은 방식으로 배정한다는 주장은 아니다.

먼저 확인할 개념
  • page 단위 할당과 비용

    데이터 frame과 번역 표 page를 별도로 센다.

  • TLB miss의 표 조회

    TLB miss 때 단계별 메타데이터 조회가 생기는 이유를 연결한다.

선형 표는 모든 VPN 자리를 둔다

선형 page table은 VPN으로 바로 PTE 위치를 찾는다. 가상 공간이 커질수록 사용하지 않는 VPN 자리도 표 공간을 차지한다. 예를 들어 32 bit 주소/page 4 KiB/PTE 4 바이트는 2²⁰개 PTE, 4 MiB다.

다단계 표는 PTE들을 page 단위 leaf로 나누고 상위 directory가 그 leaf 위치를 가리킨다. 전혀 매핑 없는 leaf는 만들지 않는다. 실제 ISA의 단계·entry 폭·큰 page 규칙은 별도다.

주소의 비트를 나눠 찾는다

아래 교육용 16 bit 가상 주소에서 page는 256 바이트라 offset 8 bit, VPN 8 bit다. PTE와 PDE는 각각 4 바이트이며 leaf 한 page에 64개 PTE를 둔다. leaf 인덱스 6 bit, directory 인덱스 2 bit가 된다.

directory는 4개 PDE의 논리 16 바이트지만 물리 할당은 256 바이트 한 page로 반올림한다고 정한다. 이런 할당 규칙을 명시하지 않으면 공간 비교가 달라진다.

공간 절약은 조회 단계를 늘린다

가상 page가 한두 leaf 구간만 쓰면 나머지 leaf를 생략할 수 있다. 모든 leaf가 필요하면 directory 비용만큼 선형 표보다 커질 수도 있다. 항상 작다는 보장은 없다.

TLB miss 때 directory와 leaf PTE를 차례로 읽는다. 이 모형은 table 캐시 없는 두 단계라 번역 2회 메모리 읽기와 데이터 1회가 필요하다. TLB hit나 실제 walk 캐시는 비용을 바꾼다.

PDE와 PTE가 가리키는 대상

directory base 4096, PDE 1의 leaf PFN 20, 그 leaf의 PTE 0의 데이터 PFN 9다. 0x4005의 조회 위치를 순서대로 구하라.

  1. 0x4005=64×256+5라 directory 1·leaf 0·offset 5다.

  2. PDE 주소는 4100이며 leaf base는 20×256=5120이다.

  3. PTE 주소는 5120+0×4=5120이고 데이터 주소는 9×256+5=2309다.

4100은 PDE 저장 위치, 5120은 PTE 저장 위치, 2309는 데이터 바이트 위치다.

비교할 점

PDE의 PFN 20을 최종 데이터 PFN으로 사용하지 않는다.

소단원 8.3

TLB와 보호 비트

주소 번역이 캐시에 있다고 아무 쓰기나 허용될까?

준비 개념과 학습 목표

준비 개념

  • page table·권한

  • 적중률과 가중 평균

학습 목표

  • TLB miss와 주소 오류를 구별한다.

  • 적중 상태에서도 보호 검사를 적용한다.

같은 여섯 번 읽기도 순서에 따라 번역 캐시 적중률이 달라질까?

자체 TLB는 번역 두 개를 보관하고 완전 연관 검색과 LRU 대체를 사용한다. 처음 비어 있고, 모든 page의 읽기는 유효하다. 프로그램 데이터의 1바이트 읽기만 세며 명령어 fetch와 다른 접근은 제외한다. page는 256바이트이고 주소 순서는 0,256,1,512,257,2다. VPN 순서는 0,1,0,2,1,0이다.

첫 두 접근은 miss로 0과 1을 채운다. 세 번째 0은 hit라 0이 가장 최근이 된다. 네 번째 2는 miss이며 오래된 1을 내보낸다. 다섯 번째 1은 miss이며 0을, 여섯 번째 0은 miss이며 2를 내보낸다. 결과는 miss,miss,hit,miss,miss,miss로 적중 한 번과 실패 다섯 번이다. frame이 실제 메모리에 없다는 뜻이 아니라 이 TLB에 해당 번역이 없다는 뜻이다.

같은 주소들을 0,1,2,256,257,512 순서로 읽으면 VPN은 0,0,0,1,1,2다. 처음 비어 있는 같은 두 entry TLB에서 miss,hit,hit,miss,hit,miss가 되어 적중 세 번이다. 데이터 접근 횟수와 서로 다른 page 수는 그대로인데 번역의 재사용 순서가 달라진다. 이 종이 추적은 실제 CPU 캐시나 실행 시간을 측정한 결과가 아니다.

TLB에 저장된 번역은 주소공간과 권한도 식별해야 한다. page 256 모형에서 P의 ASID 1·VPN 1은 PFN 7, Q의 ASID 2·VPN 1은 PFN 9라고 정하면 같은 가상 261도 각각 물리 1797과 2309다. VPN만으로 검색하면 다른 프로세스의 번역을 잘못 사용할 수 있다. ASID를 포함한 식별 또는 문맥 전환 시 올바른 무효화 정책이 필요하며, 같은 주소공간의 매핑·권한 변경 뒤 오래된 번역을 처리하는 문제는 별도로 남는다.

먼저 확인할 개념
  • page 경계와 변환

    주소를 VPN·offset으로 분해하여 같은 번역 재사용을 찾는다.

  • 두 단계 표 조회 비용

    miss에서 표 두 번과 데이터 한 번을 세는 자체 지연 모델을 연결한다.

TLB는 데이터가 아니라 번역 캐시다

TLB는 VPN에서 PFN과 권한으로 가는 번역 정보를 캐시한다. 실제 데이터 내용을 저장하는 데이터 cache와 대상이 다르다. 적중이면 표를 매번 읽지 않아도 번역할 수 있다.

miss는 캐시에 번역이 없다는 뜻이다. page table에 유효하고 허용된 매핑이 있으면 채우고 재시도할 수 있다. miss만으로 디스크 page-in이나 프로그램 종료를 단정하지 않는다.

적중에서도 권한을 검사한다

R/W/X 같은 보호 비트가 요청 동작을 허용하는지 본다. 읽기 전용 page의 번역이 TLB에 적중해도 write는 거절해야 한다. 존재 여부와 접근 권한은 다른 조건이다.

프로세스가 바뀌면 같은 VPN이 다른 PFN일 수 있다. 주소공간 식별자나 적절한 invalidate가 필요하며 OS가 매핑·권한을 바꾼 뒤 오래된 TLB entry를 그대로 쓰면 잘못된 접근을 허용할 수 있다.

평균 지연에 포함 범위를 밝힌다

아래 직렬 모델은 TLB lookup 뒤 메모리를 읽는다. hit에는 데이터 1회, miss에는 두 단계 표 2회와 데이터 1회를 더한다. miss 처리 소프트웨어·page fault·데이터 cache·겹침은 제외한다.

현실 TLB 성능은 page 크기·참조 locality·entry 수·프로세스 전환 등에 좌우된다. 평균 공식은 정한 가정의 계산이며 실물 CPU의 측정값이 아니다.

MRU는 가장 최근, LRU는 가장 오래전에 접근한 번역이다. hit도 최근 순서를 갱신하며 매번 접근 전의 상태로 hit 여부를 판단한다.

중간 과정을 따라가는 예제

lookup=2 ns, 각 메모리 접근=100 ns, hit율 0.9, miss는 두 단계 표에서 유효 매핑을 찾는다고 한다. page 크기 256 바이트, VPN 3→PFN 7, R=1/W=0이며 주소 773을 읽거나 쓴다.

  1. hit 지연=2+100=102 ns, miss 지연=2+2×100+100=302 ns다.

  2. 평균 0.9×102+0.1×302=122 ns다. 모든 요청이 유효 읽기인 평균 모형이다.

  3. 773=3×256+5라 읽기 물리 주소 7×256+5=1797이다. write는 TLB hit이어도 W=0이라 거절한다.

평균 122 ns, 읽기 주소 1797이다. 금지된 write는 정상 데이터 접근으로 평균에 섞어 계산하지 않는다.

조건을 바꾸어 비교하기

주소 순서를 바꾼 비교

원래 순서와 page별 묶음 순서에서 적중률을 계산하라.

  1. 원래 순서의 결과는 M,M,H,M,M,M이라 1/6이다.

  2. 묶음 VPN 순서는 0,0,0,1,1,2이며 결과 M,H,H,M,H,M이라 3/6이다.

  3. 두 추적은 모두 초기 빈 TLB에서 별도로 시작한다.

적중률은 각각 1/6과 1/2다. 단순히 page 종류 세 개라는 정보만으로 정확 적중률을 정할 수 없다.

비교할 점

용량·초기 상태·대체 규칙·순서를 모두 명시해야 한다.

자체 직렬 지연의 평균

TLB 조회는 2 ns이고 메모리 한 번 접근은 100 ns다. 두 단계 표에서 모든 miss를 해결하는 자체 모형에서 두 추적의 평균 지연을 구하라.

  1. hit의 지연은 102 ns이고 miss의 지연은 302 ns다. 추가 재시도 lookup과 다른 소프트웨어 비용은 이 자체 모형에서 제외한다.

  2. 원래 추적의 평균은 (102+5×302)/6=806/3 ns다.

  3. 묶음 추적의 평균은 (3×102+3×302)/6=202 ns다.

평균 지연은 원래 추적에서 약 268.67 ns이고 묶음 추적에서 202 ns다. 이는 모형의 합산값이며 CPU 성능 측정이 아니다.

비교할 점

허용되지 않은 접근이나 page-in 지연을 같은 정상 읽기 평균에 섞지 않는다.

연습 1 · 값과 상태 예측

처음 빈 용량 2 TLB에서 VPN 0,1,0,2를 읽은 직후, 다음 VPN 0과 1을 차례로 읽으면 결과와 최종 순서는?

힌트 1

앞 네 접근 뒤 MRU→LRU는 [2,0]이다.

힌트 2

hit에서도 최근 순서를 갱신한다.

풀이와 답 확인

  1. 다음 0은 hit여서 [0,2]가 된다.

  2. 다음 1은 miss여서 오래된 2를 내보내고 [1,0]이 된다.

추가 두 접근은 hit,miss이며 최종 [1,0]이다. 원래 여섯 주소 순서와는 다른 추적이다.

흔한 오답에서 다시 생각하기

0에 hit해도 대체 순서가 그대로라 1 삽입 때 0을 내보낸다.

LRU는 성공 접근에서도 최근 사용 기록을 갱신한다.

연습 2 · 오류 찾아 고치기

ASID 1과 2에서 VPN 1이 각각 PFN 7과 9다. Q의 가상 261에 P의 번역을 사용한 판정을 고쳐라.

힌트 1

261=1×256+5다.

힌트 2

Q의 주소공간 식별자는 2다.

풀이와 답 확인

  1. (ASID 2,VPN 1)에 맞는 PFN 9를 선택한다.

  2. 9×256+5=2309로 변환한다.

  3. PFN 7의 1797은 P의 번역이며 Q의 접근에 대신 쓸 수 없다.

주소공간 식별과 해당 접근 권한도 확인해야 한다.

흔한 오답에서 다시 생각하기

VPN만 같으면 다른 주소공간에서도 같은 번역이다.

VPN은 주소공간 안의 번호라 프로세스 간 동일 PFN을 의미하지 않는다.

연습 3 · 직접 만들어 보기

초기 빈 용량을 3으로 늘리고 같은 VPN 0,1,0,2,1,0을 읽는다. hit·miss 순서와 평균을 구하라.

힌트 1

다른 주소나 접근은 없으며 세 번역을 함께 보관할 수 있다.

힌트 2

지연 모형에서 hit의 102 ns와 miss의 302 ns는 그대로 유지한다.

풀이와 답 확인

  1. 결과는 M,M,H,M,H,H다. 서로 다른 page의 첫 접근 세 번만 miss다.

  2. miss 세 번과 hit 세 번의 평균 지연은 202 ns다.

동일한 원래 순서에서 용량 변경이 miss를 다섯 번에서 세 번으로 줄인다.

흔한 오답에서 다시 생각하기

용량 3이므로 최초 접근도 모두 hit다.

초기 상태가 비어 있어 첫 번역을 채우는 miss는 여전히 필요하다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

용량 2의 원래 여섯 VPN을 한 번 읽은 최종 상태 [0,1]에서 같은 여섯 VPN을 다시 읽는다. 둘째 반복의 적중률을 구하라.

힌트 1

초기 빈 상태로 재설정하지 않는다.

힌트 2

각 hit도 MRU 순서를 갱신한다.

풀이와 답 확인

  1. 0은 H여서 [0,1], 1은 H여서 [1,0], 0은 H여서 [0,1]이다.

  2. 2는 M여서 [2,0], 1은 M여서 [1,2], 0은 M여서 [0,1]이다.

  3. 둘째 반복은 H,H,H,M,M,M으로 3/6이다.

첫 빈 추적의 1/6과 다르다. 최종 상태가 다시 [0,1]이므로 추가 변화가 없으면 이후 반복도 같은 추적을 사용한다.

흔한 오답에서 다시 생각하기

매 반복마다 첫 추적과 같은 1/6이라고 보면 된다.

캐시를 비우지 않는 반복의 초기 번역 상태는 첫 실행과 다르다.

구간·메타데이터·번역 재사용을 함께 점검하기

page와 frame의 크기가 각각 256 바이트이고 VPN 0은 PFN 5, VPN 1은 PFN 2에 매핑된다. 가상 구간 [250,266)을 물리 구간 [1530,1546)으로 계산한 주장을 고쳐라. 이어 같은 16 비트 두 단계 구조에서 VPN 63과 64를 매핑하면 표 확보량이 512 바이트라는 주장을 점검하라. 마지막으로 용량 2이고 초기 상태가 빈 LRU TLB에서 VPN 0,1,0,2,1,0을 읽는다. 서로 다른 page가 세 개이므로 miss도 세 번뿐이라는 주장을 계산으로 고쳐라.

힌트 1

첫 구간은 경계 256에서 두 조각으로 나눈다.

힌트 2

사용 directory 구간 수와 여섯 접근의 MRU 순서를 각각 추적한다.

풀이와 답 확인

  1. 가상 [250,256)은 물리 [1530,1536)에 대응하고 길이는 6 바이트다. 가상 [256,266)은 물리 [512,522)에 대응하고 길이는 10 바이트다. 전체 길이 16 바이트를 보존한다.

  2. VPN 63과 64는 각각 directory 0과 1에 속한다. leaf 두 개와 root 한 개를 확보하므로 표의 총 확보량은 768 바이트다.

  3. 서로 다른 전용 데이터 frame 두 개의 512 바이트까지 포함하면 전체 확보량은 1280 바이트다. 표의 확보량과 구별한다.

  4. TLB 결과는 M,M,H,M,M,M이다. 여섯 접근 중 hit는 한 번이므로 적중률은 1/6이고 miss는 다섯 번이다.

  5. 자체 직렬 지연 모형에서 hit는 102 ns이고 miss는 302 ns다. 여섯 접근의 평균은 806/3 ns다. 주소공간 식별과 권한은 적중 여부와 별도로 확인한다.

가상 연속성·매핑 개수·서로 다른 page 개수만으로 물리 구간, 계층 표 비용과 정확 TLB miss를 결정하지 않는다.

  • 두 물리 조각의 길이와 page 경계 변환을 계산한다.

  • hit도 갱신하는 LRU 여섯 단계와 평균의 가정을 명시한다.

  • 실제 CPU 실행·캐시 성능·학습자 이해 측정과 종이 추적을 구별한다.
