소단원 4.1

응답·대기·반환 시간

버튼을 누른 뒤 처음 반응하는 시간과 작업이 끝나는 시간은 왜 다를까?

준비 개념과 학습 목표

준비 개념

  • 시간선의 [a,b)는 a에서 시작해 b 직전까지이며 길이는 b−a다. 예컨대 [2,5)는 3시간 단위다. 아래 단위는 모두 가상의 ms이고 실제 기기 측정값이 아니다.

  • 도착은 작업이 시스템에 들어오는 사건, 준비는 CPU를 받을 수 있는 상태, 실행은 실제 CPU 사용, 블록은 I/O 같은 사건을 기다리는 상태다. 준비 대기와 블록 시간을 같은 칸에 적지 않는다.

  • 한 CPU를 가정하면 동시에 실행하는 작업은 하나다. 문맥교환 비용을 0으로 둘지, 실제 CPU를 차지하는 별도 시간으로 둘지 먼저 정해야 한다.

학습 목표

  • 도착·첫 실행·종료 시각으로 응답과 반환 시간을 계산한다.

  • 준비 큐 대기와 I/O 대기를 구분한다.

  • 평균만으로 각 작업의 지연을 설명할 수 없는 반례를 만든다.

관찰이 끝났지만 작업이 아직 끝나지 않았다면 반환 시간을 어떻게 적을까?

별도 가상 관찰을 시각 t = 6에서 끝낸다. A는 시각 0에 도착하여 0~2에 실행하고 2~5에 블록되며 5~6에는 준비 상태지만 아직 종료하지 않았다. B는 시각 1에 도착해 1~2에 준비 상태로 기다리고 2~6에 실행한 뒤 시각 6에 종료한다. 교환 비용은 0이다. A의 최초 실행 응답은 0임을 알지만 종료 시각을 모르므로 반환 시간을 6이라고 기록하지 않는다. 관찰 종료까지의 경과 시간 6과 최종 반환 시간은 다른 대상이다.

B의 반환 시간은 6 − 1 = 5이고 응답은 2 − 1 = 1이며 준비 대기는 1이다. 끝난 작업만의 평균 반환 시간 5는 완료 작업 B 한 개의 평균이다. 아직 완료되지 않은 A를 포함한 도착 작업 전체 평균이라고 이름 붙이면 집계 대상을 바꾼다. 보고서에는 관찰 구간, 도착 작업 2개, 완료 작업 1개, 미완료 작업 1개와 집계 대상을 적는다. 모든 미완료 값을 0으로 채우는 것도 값을 만들어 넣는 오류다.

배정 상태를 별도 비용 D로 분류하는 또 다른 단일 작업 C의 시간표를 정한다. C는 시각 0에 도착하여 0~1에는 준비, 1~2에는 배정 처리, 2~4에는 실행, 4~7에는 블록, 7~8에는 준비, 8~9에는 배정 처리, 9~10에는 실행 상태이며 시각 10에 종료한다. 준비 대기 W는 2, 실행 B는 3, 블록 I는 3, 배정 D는 2로 반환 시간 T는 10이다. 이 모형의 W는 배정 처리를 포함하지 않는다. 다른 수집기가 배정을 준비 구간에 포함한다면 그 정의에 맞춰 식을 다시 써야 한다.

C의 첫 CPU 실행 응답은 2이고 최초 준비 큐 대기는 1이다. 배정 처리 1이 그 사이에 있다. 따라서 R = W라는 식은 W가 최초 실행 전 준비 대기만을 가리키고 별도 비용이 없는 등 적용 조건을 확인해야 한다. 응답의 측정 끝점과 상태 구간의 분류를 함께 기록한다.

먼저 확인할 개념
  • 선택과 교환 규칙

    동시 사건 순서 및 교환 비용을 명시한다.

  • 평균과 서비스 보장

    완료 작업만의 집계가 전체 기회를 설명하는지 확인한다.

시각 세 개와 시간 간격 두 개

도착 시각 a, 최초 CPU 실행 시각 f, 종료 시각 c를 기록하자. 이 단원의 응답 시간 R=f−a는 처음 CPU를 받은 때까지의 간격이고, 반환 시간 T=c−a는 완료까지의 전체 간격이다. 반환은 turnaround의 번역이며 함수가 return한 뒤 걸리는 시간이라는 뜻이 아니다. R이 작아도 이후 오래 기다리면 T는 클 수 있다.

웹 서비스의 응답 시간을 측정할 때는 요청을 보낸 뒤 결과를 받은 시점을 끝으로 삼을 수 있다. 여기의 첫 CPU 실행 정의와 끝점이 다르다. 따라서 같은 “응답”이라는 말에 숫자만 비교하지 말고 어떤 사건에서 측정 시작·종료했는지 함께 적는다. 극장 줄 비유에서 처음 직원에게 불리는 때는 f, 처리가 끝나는 때는 c에 대응하지만 실제 컴퓨터의 중단·재개는 줄 서기보다 더 여러 번 일어난다.

대기 시간은 어디서 세는가

CPU 스케줄링에서 대기 시간 W는 작업이 준비 큐에서 CPU를 기다린 구간들의 길이 합이다. 준비 상태에서 기다린 뒤 한 번 실행하는 작업도 있고, 실행·선점·준비 대기를 반복하는 작업도 있다. 블록 상태의 I/O 대기는 W에 넣지 않는다. 대기는 최초 실행 전만이 아니라 실행 중간의 준비 구간도 포함한다.

단순 모형에서 도착부터 종료까지가 준비 대기 W, CPU 사용 B, 블록 I로 빠짐없이 나뉘면 T=W+B+I다. I=0일 때만 W=T−B로 줄일 수 있다. 문맥교환 구간이나 다른 상태가 있다면 그 시간을 어떻게 분류했는지 정해야 한다. 같은 식을 실제 OS의 수집 지표에 적용하기 전에 측정 정의와 상태 누락을 확인한다.

평균과 목적을 함께 읽기

여러 작업의 평균 응답은 R들의 합을 작업 수로 나눈 값이다. 모든 작업에 동일한 CPU 실행량을 주는 정책과 평균 완료 시간을 작게 만드는 정책은 서로 다른 목표를 갖는다. 평균이 좋더라도 한 사용자가 아주 오래 기다릴 수 있으므로 작업별 값이나 최댓값을 함께 살펴보는 것이 도움이 된다.

예를 들어 응답 목록 (0,0,12)와 (4,4,4)의 평균은 모두 4지만 최댓값은 각각 12와 4다. 이 숫자만으로 두 정책의 전체 품질을 단정하지는 않는다. CPU 처리량, 공정성, 필요한 마감 시각, 측정 대상 작업의 선택까지 달라질 수 있다. 아직 도착하지 않은 작업을 평균의 분모에 넣거나 끝나지 않은 작업을 조용히 제외하면 비교가 왜곡된다.

중간 과정을 따라가는 예제

한 CPU, 문맥교환 비용 0. A는 시각 0에 도착해 [0,2) 실행, [2,5) I/O 블록, [5,6) 준비 대기, [6,8) 실행 후 종료한다. B는 시각 1에 도착해 [1,2) 준비 대기, [2,6) 실행 후 종료한다. 두 작업의 R,T,W를 구하라.

  1. A의 a=0,f=0,c=8이므로 R_A=0−0=0,T_A=8−0=8이다.

  2. A의 CPU 사용 B_A=(2−0)+(8−6)=4, 블록 I_A=5−2=3, 준비 대기 W_A=6−5=1이다. 4+3+1=8이므로 전체 간격과 맞는다.

  3. B의 a=1,f=2,c=6이므로 R_B=1,T_B=5다. CPU 사용은 6−2=4이고 W_B=2−1=1이다. 블록은 없다.

  4. 평균 R=(0+1)/2=0.5, 평균 T=(8+5)/2=6.5, 평균 W=(1+1)/2=1이다. A의 T−B=4는 W가 아니라 W+I다.

A:(R,T,W)=(0,8,1), B:(1,5,1). 두 작업 모두 준비 대기는 1이지만 A의 I/O 때문에 반환 시간이 더 크다.

완료 집계의 분모

시각 6에 관찰을 끝냈을 때 도착한 두 작업의 평균 반환 시간이 5라고 결론 내릴 수 있는가?

  1. 완료된 B의 반환 시간 T는 5다.

  2. A의 최종 반환 시간은 미정이다.

  3. 평균 5는 완료 집합 {B}의 평균으로만 이름 붙인다.

전체 도착 집합 {A,B}의 평균 T는 아직 계산할 수 없다.

비교할 점

기본 완료 시간표와 달리 관찰 종료에 미완료가 있다.

배정 시간을 따로 세기

C의 W,B,I,D,R,T를 구하라.

  1. 준비 대기 W = (1 − 0) + (8 − 7) = 2다.

  2. CPU 실행 B = (4 − 2) + (10 − 9) = 3이고 블록 I = 7 − 4 = 3이며 배정 D = 2다.

  3. 응답 R = 2 − 0 = 2이고 반환 T = 10 − 0 = 10이다. 상태별 합 2 + 3 + 3 + 2 = 10도 일치한다.

T=W+B+I+D로 모든 구간을 분할한다.

비교할 점

T − B = 7을 준비 대기 W = 2와 혼동하지 않는다.

종이와 본문으로 직접 해보기

C는 시각 2 도착, [2,4) 준비 대기, [4,5) 실행, [5,7) 블록, [7,9) 준비 대기, [9,10) 실행 후 종료한다. R,T,B,I,W를 적고 T=W+B+I를 확인하라.

힌트 보기

도착 전 [0,2)는 세지 않는다. [2,4)와 [7,9)를 따로 더한다.

풀이 보기

R=4−2=2,T=10−2=8,B=(5−4)+(10−9)=2,I=7−5=2,W=(4−2)+(9−7)=4다. 4+2+2=8이다. 최초 대기 2만 적으면 중간 선점·준비 대기 2를 놓친다.

오해와 반례

반환 시간에서 CPU 시간을 빼면 항상 CPU 대기 시간이 나온다.

I/O 블록이 있으면 T−B에는 블록 시간도 들어간다. 예제 A는 8−4=4지만 준비 큐 대기는 1이다. 이 등식은 상태가 빠짐없이 분할되고 블록 등 다른 시간이 없다는 조건 아래에서만 W=T−B로 쓸 수 있다.

자기점검

CPU 실행 없이 파일 도착을 기다린 블록 4ms는 W인가?

답과 이유 보기

이 단원의 W에는 넣지 않는다.

CPU를 받을 수 있는 준비 상태가 아니라 사건을 기다리는 블록 상태다. 전체 반환에는 들어갈 수 있다.

응답 (0,0,12)와 (4,4,4)는 모든 사용자의 경험이 같은가?

답과 이유 보기

아니다. 평균만 4로 같다.

첫 목록에는 12를 기다리는 작업이 있고 두 번째 최댓값은 4다. 평균은 분포를 모두 설명하지 않는다.

소단원 4.2

FCFS·RR·우선순위·MLFQ

먼저 온 순서, 돌아가며 한 번씩, 중요도 순서는 언제 서로 다른 결과를 만들까?

준비 개념과 학습 목표

준비 개념

  • FCFS는 준비 큐에 들어온 순서로 선택하는 first-come first-served다. 이 단원에서는 실행 시작 후 종료 또는 블록까지 CPU를 내놓지 않는 비선점 형태를 쓴다.

  • RR은 round robin, 양의 시간 할당량 q만큼 실행한 뒤 아직 준비된 작업을 큐 뒤에 놓는 정책이다. 작업이 더 일찍 끝나거나 블록되면 q 전체를 소비하지 않는다.

  • 응답은 첫 실행−도착, 반환은 종료−도착이다. 작업 길이와 도착 시각, 동시 사건의 순서, 교환 비용을 정해야 시간선이 하나로 결정된다.

학습 목표

  • 동일 입력에서 FCFS와 RR 시간선을 손으로 계산한다.

  • 우선순위와 선점 여부를 별도 정책으로 구분한다.

  • MLFQ의 큐, 시간 할당량, 누적 예산 및 강등 규칙을 설명한다.

같은 RR과 같은 작업인데 동시 사건 순서로 결과가 달라질까?

자체 한 CPU의 RR에서 A는 시각 0에 도착해 CPU 시간 4를 요구하고 B는 시각 2에 도착해 CPU 시간 1을 요구한다. 할당량 q는 2이고 교환 비용은 0이다. 시각 2에 A의 차례 만료와 B의 도착이 겹친다. 정책 Ⅰ은 신규 B를 먼저 큐에 넣고 만료 A를 뒤에 넣는다. 큐 [B,A]에서 B는 2~3에 실행한 뒤 종료하고 A는 3~5에 실행한 뒤 종료한다. B의 응답은 0, A의 반환은 5, B의 반환은 1이다.

정책 Ⅱ는 만료 A를 먼저 재등록하고 B를 뒤에 넣는다. 큐 [A,B]에서 A는 2~4에 실행한 뒤 종료하고 B는 4~5에 실행한다. B의 응답은 2, A의 반환은 4, B의 반환은 3이다. 총 CPU 요구량 5와 전체 완료 시각 5는 같아도 평균 반환은 정책 Ⅰ에서 3, 정책 Ⅱ에서 3.5로 다르다. RR이라는 이름만으로 동시 도착의 위치까지 확정하지 않는다.

다른 비용 모형에서 A와 B는 시각 0에 도착해 각각 CPU 시간 2를 요구하며 할당량 q는 1이다. 첫 배정 비용은 0이고 서로 다른 작업으로 바꿀 때만 0.5 ms를 낸다. A 실행 0~1, 교환 1~1.5, B 실행 1.5~2.5, 교환 2.5~3, A 실행 3~4, 교환 4~4.5, B 실행 4.5~5.5가 시간표다. 유효 실행은 4, 교환은 1.5, 전체는 5.5이므로 실행 비율은 8/11이다. 매 차례 무조건 교환비를 붙이는 반복 근사 q/(q+c) = 2/3과 이 유한 모형은 비용 경계가 다르다.

MLFQ도 할당량과 누적 예산을 나누어 계산한다. 자체 Q0의 할당량은 2이고 예산은 3이다. X가 CPU 시간 1을 사용한 뒤 블록되고, 복귀하여 1을 사용한 뒤 다시 블록되며, 다시 복귀하여 1을 사용하면 누적 사용량은 1→2→3으로 예산을 소진한다. 어느 연속 차례도 할당량 2를 넘지 않았다는 사실이 예산 3의 보존을 뜻하지 않는다. 블록 때 초기화하는 잘못된 규칙은 사용량을 계속 1로 기록해 강등 경계를 숨긴다.

FCFS와 RR을 비교하는 방법

FCFS의 선택 순서는 단순하지만 긴 작업이 앞에 있으면 뒤의 짧은 작업도 기다린다. RR은 준비 큐를 순환하면서 q를 넘겨 실행한 작업을 중단할 수 있어 뒤의 작업이 처음 CPU를 얻는 기회를 앞당긴다. RR이 항상 평균 반환 시간을 줄인다고 결론 내리지는 않는다. 먼저 조금씩 실행한 뒤 모두 늦게 끝나는 시간선도 만들 수 있다.

q를 매우 크게 하면 도착이 모두 같은 CPU 전용 작업에서 RR은 FCFS처럼 동작할 수 있다. 반대로 q를 작게 하면 교환이 자주 필요하다. 매 차례 유효 실행 q와 교환 비용 c가 반복되는 이상적인 구간의 유효 실행 비율은 q/(q+c)다. 마지막 종료, 블록, 캐시 효과까지 포함한 실제 전체 활용률은 이 단순 비율과 다를 수 있다.

우선순위는 선택 규칙이고 선점은 중단 규칙

우선순위 정책은 더 높은 중요도를 갖는 준비 작업을 선택한다. 숫자가 클수록 높은지 작을수록 높은지는 구현마다 정해야 한다. 같은 우선순위의 순서도 FCFS나 RR처럼 명시한다. 높은 작업이 새로 들어오자마자 실행 중인 낮은 작업을 중단하면 선점형, 현재 작업이 종료하거나 블록된 뒤에만 바꾸면 비선점형이다.

가령 낮은 작업 L이 [0,5) 동안 CPU를 필요로 하고 높은 H가 시각 1에 도착해 1만큼 필요로 하자. 교환 비용 0이면 선점형은 L[0,1),H[1,2),L[2,6)이고 비선점형은 L[0,5),H[5,6)이다. 우선순위가 있다는 사실만으로 H의 최초 실행 시각을 정할 수 없는 이유다. 운영체제 전체의 우선순위를 주관적인 “좋은 프로그램” 순서와 동일시하지 않는다.

MLFQ에서 피드백과 예산

다단계 피드백 큐 MLFQ는 여러 우선순위 큐를 두고 관찰한 실행 이력에 따라 작업의 위치를 바꾼다. 여기서는 새 작업을 높은 Q0에 넣고, 더 높은 준비 큐를 우선하며, 같은 큐는 RR로 고른다. 한 번에 실행할 q와 그 수준에서 누적해 사용할 수 있는 예산 A는 서로 다른 값일 수 있다. 예산을 모두 사용하면 낮은 큐로 강등한다.

누적 예산을 블록할 때마다 0으로 초기화하면 작업이 예산 만료 직전에 CPU를 내놓아 높은 큐에 계속 남는 허점이 생긴다. 그래서 예산은 같은 수준에서 사용한 CPU 시간을 여러 실행에 걸쳐 더한다. 이 단원의 교육 모형은 주기적 우선순위 상승도 사용할 수 있지만, 큐 수·예산·q·상승 주기·동시 사건 순서를 정해야 구체적인 시간선이 나온다. 모든 현대 OS의 실제 구현을 이 모형 하나로 대신하지 않는다.

종이와 본문으로 직접 해보기

MLFQ 교육 모형: Q0의 q=2, 누적 예산 A0=4이고 Q1은 q=4다. X는 시각 0에 Q0에서 3만큼 실행할 필요가 있고, 별도 Y는 Q0에서 1 실행→I/O→복귀→2 실행→I/O→복귀→1 실행한다. 두 작업을 서로 독립적으로 추적해 최초 예산 소진 시점을 구하라. 예산은 I/O 중 증가하지 않으며 복귀해도 초기화하지 않는다.

힌트 보기

q는 한 번의 최대 실행 길이이고 A0는 여러 번의 실행 합이다. X가 q를 한 번 썼다고 즉시 예산을 모두 쓴 것은 아니다.

풀이 보기

X는 첫 차례 2를 실행하고 남은 CPU 1, 남은 Q0 예산 2다. 다음 1을 실행해 종료하므로 Q0 사용 합 3이며 예산 4를 소진하지 않는다. Y는 누적 합이 1→3→4가 된다. 세 번째 실행 1을 마친 때 예산이 소진된다. 종료가 아닌 추가 CPU 요구가 있다면 다음 실행 위치는 Q1이다. I/O 벽시계 길이가 미지수이므로 절대 시각은 구할 수 없다.

오해와 반례

MLFQ에서 한 번 시간 할당량을 끝내면 항상 낮은 큐로 이동한다.

이 단원은 q와 수준별 예산 A를 구분한다. q=2,A=4에서 2를 실행하면 예산이 2 남아 같은 수준에 머무른다. A=q로 설정한 변형에서는 한 차례 만료와 강등이 겹칠 수 있지만 모든 MLFQ에 공통인 정의는 아니다.

소단원 4.3

공정성과 기아

평균 대기 시간이 낮아져도 어떤 작업이 끝없이 기다릴 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 기아는 실행할 준비가 된 작업이 정책과 다른 작업의 경쟁 때문에 계속 서비스를 못 받는 상황이다. 짧은 관찰 동안 오래 기다렸다는 사실만으로 무한히 기다림을 증명하지는 못한다.

  • 공정성의 대상은 작업, 스레드, 사용자 또는 그룹일 수 있다. 동일 작업 몫과 동일 사용자 몫은 사용자가 여러 작업을 만들 때 달라진다.

  • 유한 작업 수, 양의 q, 유한 교환 비용, 앞에 끼어들기 금지 같은 조건은 기다림의 상한을 계산할 때 쓰는 가정이다. 조건을 빠뜨리면 공정성 보장이 달라진다.

학습 목표

  • 정해진 정책에서 기아를 일으키는 무한 사건열을 구성한다.

  • RR의 제한된 첫 실행 대기 상한을 설명한다.

  • aging과 주기 상승의 역할 및 보장의 조건을 구분한다.

모든 작업에 차례를 주었는데도 긴 작업은 왜 더 기다릴까?

자체 RR에서 앞선 작업은 m = 3개이고 각 작업은 최대 q = 2를 실행하며 서로 다른 작업의 교환 비용은 최대 c = 0.5다. CPU가 빈 선택 경계에서 마지막 작업 D에게 넘기는 교환까지 세 번의 교환을 포함하면 첫 실행 대기 상한은 3(2 + 0.5) = 7.5다. 앞선 작업 수가 유한하고 새 작업이 앞에 끼어들지 않으며 다른 우선 큐가 없다는 조건이다. D가 블록한 뒤 재진입하면 그 순간의 새 큐 위치로 다시 계산한다.

공정성의 단위가 사용자라면 작업을 늘려도 사용자 몫이 늘어나지 않는 정책을 설계할 수 있다. 자체 두 단계 정책에서는 사용자 U와 V가 번갈아 2단위씩 실행하고 V의 차례 안에서는 계속 준비된 V1, V2, V3를 순환한다. 교환 비용은 0이고 모든 작업이 충분한 CPU 시간을 요구한다. U1, V1, U1, V2, U1, V3의 여섯 차례인 12단위에서 U와 V는 각각 6을 얻고 V의 각 작업은 2를 얻는다.

같은 네 작업에 작업별 RR을 q = 2로 적용하여 세 순환의 24단위를 보면 U1, V1, V2, V3는 각각 6을 얻는다. U의 총량은 6이고 V의 총량은 18이다. 동일 사용자 몫과 동일 작업 몫은 다른 목적이다. 두 단계 정책에서는 U1이 6을 얻는 동안 V의 각 작업은 2를 얻으므로 작업별 몫이 동일하지 않다. 공정성을 말할 때는 대상과 목표 비율, 관찰 기간을 붙인다.

누적 서비스량이 비슷해도 긴 공백이 있을 수 있다. 계속 준비된 두 작업의 자체 12단위 시간표를 비교하자. 첫 시간표는 A를 0~6에, B를 6~12에 실행한다. 둘째 시간표는 A를 0~1에, B를 1~2에 실행한 뒤 번갈아 실행하여 A의 마지막 차례는 10~11이고 B의 마지막 차례는 11~12다. 두 시간표 모두 각 작업에 6씩 제공하지만 B의 첫 응답은 각각 6과 1이며 서비스 간격도 다르다. 끝없는 반복을 명시하지 않은 유한 표는 기아 증명이 아니라 짧은 기간의 서비스 편차 비교다.

공정성의 대상과 목표를 명시하기

같은 시간 동안 계속 준비된 작업 두 개가 각각 CPU 8과 2를 사용했다면 동일 작업 몫 기준에서는 편향된 분배다. 그러나 가중치를 4와 1로 정했다면 8:2는 가중 몫에 맞는 분배다. 따라서 “공정하다”는 말에는 대상과 목표 비율, 관찰 기간을 붙인다. 짧은 구간에서는 q의 경계 때문에 한 작업만 실행한 것처럼 보일 수도 있다.

사용자 U가 작업 하나, 사용자 V가 작업 셋을 만든 상태에서 작업별 같은 RR 몫을 주면 총 CPU가 U:V=1:3에 가까워질 수 있다. 이는 동일 작업 몫을 어긴 것이 아니지만 동일 사용자 몫과는 다르다. 작업 수를 늘리는 행동을 막으려면 사용자·그룹 단위 몫을 고려해야 한다. 이 원고의 계산은 한 CPU의 종이 예시이고 실제 사용자 할당 정책을 측정하지 않았다.

기아를 보이는 사건열과 대기 상한

항상 높은 우선순위를 고르는 선점형 정책에서는 낮은 L이 준비되어 있어도 높은 작업이 CPU를 빈틈없이 채우면 L이 선택되지 않는다. 매 정수 시각 n에 CPU 1이 필요한 H_n이 도착하고 H_n을 [n,n+1)에 실행한다고 구성하면 L은 모든 유한 구간에서 실행 0이고 이 사건열이 무한히 이어질 때 기아다. 실제 부하는 이런 사건열과 같다는 뜻이 아니라 보장 부재를 보여주는 반례다.

RR에서는 준비 큐 앞에 계속 새 작업을 끼워 넣지 않고, 어떤 작업 앞에 유한한 m개가 있으며 각 작업이 최대 q 실행과 최대 c 교환만 사용한다면 첫 실행까지의 대기는 적절한 경계에서 m(q+c) 이하로 계산할 수 있다. 아래 예제는 CPU가 비어 선택을 시작하는 시각이며 마지막 자기 작업으로의 교환까지 m번으로 세는 규약을 쓴다. 무한 신규 작업이나 더 높은 큐의 우선 실행은 이 가정을 깨뜨릴 수 있다.

aging과 상승은 조건과 함께 쓰기

aging은 기다린 작업의 우선순위를 시간이 지나며 높이는 방법이고, MLFQ의 주기 상승은 일정 주기로 작업들을 높은 큐에 올리는 방법이다. 오래 낮은 위치에 머문 작업에 다시 기회를 주려는 장치다. 같은 높은 우선순위에서도 선택 규칙이 특정 작업만 반복하면 상승만으로 충분하지 않으므로 RR 등 동률 처리와 신규 도착의 위치도 정한다.

주기 상승 S를 넣었다는 말만으로 모든 작업의 완료 시각에 동일한 상한을 줄 수는 없다. 서비스가 유한 구간 내에 돌아온다는 주장에는 유한 경쟁 작업 수와 유한 차례 길이 등의 가정이 필요하고, 완료에는 작업이 필요한 총 CPU량도 영향을 준다. 기아와 교착은 다르다. 높은 H가 계속 실행되는 위 예제는 자원을 서로 붙잡고 기다리는 순환이 없어도 L이 기아에 빠진다.

사용자 단위로 차례 나누기

총 12단위에서 U1과 V의 각 작업이 얻는 서비스량을 구하라.

  1. U의 차례는 세 번이므로 U1의 서비스량은 6이다.

  2. V의 세 차례를 V1, V2, V3에 하나씩 준다.

  3. V의 각 작업은 2씩 얻으며 V의 총량은 6이다.

사용자 몫은 각각 1/2이다. 작업 몫은 U1이 1/2이고 V의 각 작업이 1/6이다.

비교할 점

작업별 동일 RR에서 사용자 몫이 1:3이 되는 정책과 목적이 다르다.

같은 총량, 다른 첫 응답

두 12단위 시간표에서 B의 총서비스량과 첫 실행 응답을 비교하라.

  1. 긴 묶음에서는 B가 6~12에 실행하므로 서비스량은 6이고 최초 시각은 6이다.

  2. 교대에서는 B가 시각 1에 시작하여 이후 다섯 차례를 더 받아 총 6을 실행한다.

  3. 교대의 최초 실행 시각은 1이다.

총량은 모두 6이지만 첫 응답은 각각 6과 1이다.

비교할 점

장기 총량과 짧은 기간의 실행 기회를 따로 측정한다.

종이와 본문으로 직접 해보기

L은 t=0부터 준비된 낮은 우선순위 작업이다. 정수 n≥0마다 H_n이 도착해 CPU1을 요구하며, 항상 준비된 높은 작업이 우선한다. [0,4)의 시간선을 쓰고, H_4부터 신규 도착을 중단하면 t=4에 무엇이 달라지는지 설명하라. 이어 사용자 U1작업,V3작업의 동일 작업 RR 몫을 비교하라.

힌트 보기

유한한 첫 네 구간과 영원히 반복되는 경우를 구분한다. 몫은 네 작업이 계속 준비된 충분히 긴 기간의 이상적인 비율이다.

풀이 보기

H_0[0,1),H_1[1,2),H_2[2,3),H_3[3,4) 동안 L은 실행0이다. 무한히 H가 이어지면 기아 반례지만 t=4부터 높은 작업이 없으면 L을 실행할 수 있으므로 이 유한 관찰만으로 무한 기아를 결론 내리지 않는다. 네 작업의 동일 몫은 각각1/4이고 U는1/4,V는3/4다. 동일 사용자 몫1/2씩과 다르다.

오해와 반례

CPU가 쉬지 않고 일하면 모든 작업에 공정하고 기아도 없다.

높은 H_n이 계속 실행되면 CPU는 항상 바쁘지만 L의 실행은 0이다. 전체 자원 활용률과 각 작업의 서비스 기회는 별도 지표다. 평균만 낮게 유지하도록 짧은 높은 작업만 보고 L을 분모에서 빼는 측정도 공정성을 보여주지 못한다.

스케줄링 비교 보고서 다시 쓰기

시각 t = 6에 완료한 B만으로 도착 작업 전체의 평균 반환 시간이 5라고 썼다. 도착 시각 0에 CPU 시간 4를 요구하는 A와 도착 시각 2에 CPU 시간 1을 요구하는 B의 RR에서 q = 2라면 동시 사건 순서에 관계없이 B의 응답은 0이라고 적었다. 사용자 교대 정책의 U 총량 6과 V 총량 6을 보고 모든 작업이 동일한 몫을 얻는다고 결론 냈다. 각 계산의 대상과 전제를 고쳐라.

힌트 1

미완료 A와 동시 사건 두 큐 [B,A]/[A,B]를 확인한다.

힌트 2

사용자와 작업의 분모를 따로 세고 교환 비용 규약을 적는다.

풀이와 답 확인

  1. 도착 작업은 두 개이고 완료 작업과 미완료 작업은 각각 하나다. 완료 집합 B의 평균 반환 시간 5와 아직 정해지지 않은 전체 평균을 구별한다.

  2. 도착 사건을 먼저 처리하면 B의 응답은 0이고 반환 시간은 1이며 A의 반환 시간은 5이므로 평균은 3이다. 만료를 먼저 처리하면 B의 응답은 2이고 반환 시간은 3이며 A의 반환 시간은 4이므로 평균은 3.5다.

  3. 사용자 교대 정책의 12단위에서 U1은 6을 얻고 V의 각 작업은 2를 얻는다. 사용자별 총량만 6씩 같다.

  4. 별도 두 작업 시간표에서 유효 실행 시간 4와 교환 시간 1.5의 합은 경과 시간 5.5다. 실행 비율은 8/11이며 반복 근사 2/3과 다르다.

  5. 자체 시간표와 유한 관찰, 지정 정책 조건의 분석이다. 실제 OS 성능 계측과 학생 시험은 수행하지 않았다.
