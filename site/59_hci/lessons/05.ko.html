sketch와 storyboard

잘 그린 첫 화면만으로 사용자가 어떤 일을 끝낼지 알 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 사용자와 과업

  • 입력과 화면 변화

  • 순서와 분기

학습 목표

  • 화면 스케치와 사용 맥락의 스토리보드를 구별한다.

  • 행동·응답·실패 경로가 드러나는 대안을 그린다.

같은 화면 이름을 가진 두 시점이 같은 상태인가?

앞 본문은 화면의 고유 종류와 이야기 속 화면 발생을 나누었다. 새 종이 검색 모형에는 입력 I, 대기 W, 결과 R의 세 화면 종류가 있다. 사용자는 검색어 가를 요청 ID 1로 제출한 뒤 대기 화면에서 취소하고 입력으로 돌아온다. 이어 검색어 나를 ID 2로 제출한다. 서버가 취소를 관측했는지는 모르는 조건이며 ID 1의 응답도 나중에 올 수 있다. 여기서 취소의 자체 화면 정책은 현재 요청을 무효로 표시하는 것이고 서버 작업 중단 보장은 아니다.

자체 표시 규칙은 응답 ID가 현재 활성 ID와 같을 때만 그 응답을 결과 화면에 표시하는 것이다. 검색어 나를 제출한 뒤 활성 ID는 2다. ID 1의 응답은 표시하지 않고 ID 2의 응답만 나의 결과 R로 표시한다. 그러므로 대기 W를 하나의 상자로 그려도 그 상자의 검색어와 활성 ID는 시점마다 다르다. 이 규칙은 종이에 정의한 정책이며 실제 브라우저·서버·검색 성능이나 구현 완료를 주장하지 않는다.

이야기는 I→W→I→W→R의 다섯 화면 발생과 네 전환을 가진다. 고유 화면 종류는 여전히 세 개다. 사용자의 제출·취소·재제출과 두 응답 도착을 모두 사건으로 기록하면 다섯 사건이다. 옛 응답 도착은 표시 상태를 바꾸지 않아 화면 전환 수에 추가하지 않는다. 행동·도착 사건과 화면 전환을 같은 분모로 세면 미표시 응답을 숨기거나 중복 화면을 놓친다.

먼저 확인할 개념
  • 고유 화면과 발생 순서

    앞 본문의 같은 입력 화면 재등장을 새 요청 ID가 다른 대기 화면과 사건 기록에 연결한다.

  • 설계 가정과 미확인 조건

    앞 본문의 가정을 서버 취소 보장과 자체 화면 표시 규칙의 서로 다른 범위에 적용한다.

한 화면과 시간의 흐름

sketch는 아이디어를 빠르게 바깥으로 꺼낸 거친 그림이다. 선이 삐뚤어도 검색창, 결과 목록과 중요한 설명을 알아볼 수 있으면 토론할 수 있다. 예쁘게 완성하는 작업을 먼저 하면 배치와 과업 자체를 바꾸는 비용이 커진다고 느낄 수 있으므로 이 단계에서는 바꿀 여지를 남긴다.

storyboard는 사람이 어떤 상황에서 목적을 갖고 행동하며 어떤 결과를 받는지 순서로 나타낸다. 인터페이스 그림만 이어도 상태 변화는 표현할 수 있지만, 왜 그 사람이 이 기능을 쓰는지와 주변 상황까지 넣으면 설계 가정을 더 쉽게 발견한다. 두 표현은 서로 도우며 한 가지 정해진 그림 스타일만 있는 것은 아니다.

행동과 시스템 응답을 따로 적기

자체 예시는 버스에서 짧게 선형대수 개념을 찾는 학습자다. ①목적과 상황, ②검색어 입력, ③결과 선택, ④개념 설명 읽기, ⑤북마크 확인의 다섯 장면을 그린다. 화면 사이 화살표에는 단순히 다음이라고 쓰지 말고 사용자의 입력과 시스템의 응답을 구별하여 적는다.

검색어를 입력하는 행위와 검색 결과가 보이는 상태는 다르다. 검색 성공만 그려 두면 결과 없음과 연결 끊김에서 무엇을 할지 감춰진다. 오류를 모두 완성할 필요는 없지만 이번 대안의 핵심 가정과 관련된 실패 경로는 별도의 장면이나 가지로 표시한다.

비교를 위한 거친 표현의 범위

같은 찾기 과업을 검색 중심 A, 주제 지도로 탐색하는 B, 추천 질문을 고르는 C로 표현하자. 단추 색만 다르게 그린 세 장은 과업 접근 방법이 같다면 실질적 대안이 약하다. 입력 방식, 정보의 묶음과 결과를 이해하는 경로를 바꾸면 비교할 내용이 생긴다.

종이에서 화면을 바꿔 주는 사람이 있다는 것과 실제 프로그램이 동작한다는 것은 다르다. storyboard의 매끄러운 흐름은 가정한 흐름이며 성공의 증거가 아니다. 화살표를 읽는 자체 종이 추적과 실제 학습자가 도움 없이 과업을 수행한 관찰을 기록에서 분리해야 한다.

중간 과정을 따라가는 예제

위의 다섯 장면을 쓰고 결과 없음 경로를 추가하라. 정상 경로와 오류 후 회복 경로의 화면 전환 수를 세어라. 오류 경로는 검색 입력→결과 없음→검색 입력→결과 목록→설명으로 정의한다.

  1. 정상 경로에서 상황 장면은 화면 밖 맥락이므로 화면 전환 수에 포함하지 않는다.

  2. 검색 입력→결과 목록→설명→북마크 확인은 화면 네 개와 전환 세 개다.

  3. 결과 없음에는 검색어를 수정할 행동을 표시한다.

  4. 오류 후 회복 경로는 제시된 화면 다섯 개의 인접 연결 네 개다.

  5. 화면 수와 전환 수는 다르며 실제 시간이나 성공률을 이 숫자만으로 추정하지 않는다.

정상 화면 전환 3회, 정의한 오류 회복 경로 4회다. 맥락 장면과 화면을 구분했다.

취소 뒤의 완료 응답

  2. 응답 1은 현재 활성 ID와 같지 않으므로 표시하지 않는다.

오해와 반례

화살표가 모두 이어져 있으면 사용성 검증이 끝났다.

연결은 설계자가 경로를 정의했다는 뜻이다. 사용자가 원하는 단추를 찾는지, 말뜻을 이해하는지, 오류에서 회복하는지는 별도 관찰이 필요하다. 막연한 다음 버튼만 연결해도 길은 이어지므로 연결성만으로 성공을 증명할 수 없다.

가중치가 미정이면 하나의 우승 후보를 선언할 수 있는가?

앞 본문은 필수 조건을 먼저 검사하고 그 뒤에 같은 척도의 가중 합을 비교했다. 새 후보 X의 발견 점수는 5, 읽기 점수는 1이고 Y는 각각 3과 4다. 두 후보의 필수 조건은 모두 통과했다고 주어진다. 이 점수는 자체 등간 척도 가정이며 실제 사용자 평가 결과가 아니다. 발견 가중치를 w, 읽기 가중치를 1−w로 두면 X의 점수는 1+4w, Y의 점수는 4−w다.

이해관계자가 w를 [0.4,0.6] 안에서 아직 확정하지 않았다. w=0.4이면 X는 2.6, Y는 3.6이고 w=0.6이면 두 후보 모두 3.4다. 차이 X−Y=5w−3이므로 허용 범위에서 Y가 X보다 낮지는 않지만 상한에서는 동률이다. 따라서 Y가 전 범위에서 엄격히 우수하다는 문장과 Y가 전 범위에서 열등하지 않다는 문장은 다르다.

합 점수가 계산돼도 필수 조건 미확인을 통과로 대체하지 않는다. 별도 후보 Z는 높은 점수가 있더라도 키보드 경로의 필수 조건이 미확인이라면 채택 가능 후보로 인증할 수 없다. 또 순서만 보존하는 점수 변환으로 weighted sum의 결과가 반드시 보존되는 것은 아니다. 각 기준의 등간 척도·변환·정규화와 가중치 해석을 먼저 고정해야 점수 차이가 무엇을 뜻하는지 알 수 있다.

같은 문제를 풀고 있는지 확인하기

대안은 같은 핵심 과업과 대상 상황을 기준으로 비교해야 한다. 찾기 쉬움, 설명 이해와 구현 비용을 기준으로 삼을 수 있지만 편한 느낌이라는 말만으로 채점하면 서로 다른 뜻을 섞기 쉽다. 필요한 도움 횟수나 과업 완료까지의 관찰 같은 측정 정의를 먼저 생각하자.

필수 조건은 다른 장점으로 상쇄하지 않는다. 예를 들어 키보드만으로 핵심 과업을 수행할 수 있어야 한다는 프로젝트 조건을 먼저 확인한다. 이 조건을 실패한 대안은 색이나 속도 점수가 높아도 현재 후보에서 제외하거나 고친 뒤 다시 평가한다. 점수 표가 이 결정을 대신 숨기게 하면 안 된다.

자체 가상 장부의 계산

계산 연습을 위해 찾기와 설명 이해에 각각 1부터 5까지의 가상 비교 점수를 부여한다. 이 숫자들은 실제 참여자를 관찰한 결과가 아니며 간격이 같은 수치로 취급하는 자체 모형이다. A=(5,2), B=(3,4), C=(2,5)이며 모두 필수 조건을 만족한다고 가정한다.

찾기의 비중 .6, 이해의 비중 .4이면 A=.6·5+.4·2=3.8, B=3.4, C=3.2다. 비중 합을 1로 하고 높은 점수가 좋은 방향으로 통일했다. 초 단위 시간과 만족 점수처럼 다른 단위를 그대로 더해서는 안 되며, 척도를 바꾸면 결과가 어떤 뜻인지 다시 정의해야 한다.

순위가 흔들리는 지점

찾기 비중을 w, 이해 비중을 1−w로 두면 A=2+3w, B=4−w, C=5−3w다. w=.5에서는 A=B=C=3.5이며 w=.4에서는 3.2,3.6,3.8로 C가 가장 높다. 숫자로 계산한 순위도 선택한 우선순위에 의존한다.

가상의 점수를 실제 증거처럼 말하지 않는다. 한 항목의 정의가 두 번 들어가면 같은 장점을 중복 가산할 수 있고, 이용자 집단의 중요한 불편을 평균이 숨길 수도 있다. 가까운 순위는 더 나은 자료를 얻거나 대안을 함께 시험할 이유가 된다. 기준과 탈락 이유도 남겨야 다음 사람이 결정을 이해한다.

앞 본문은 선택의 장점·손실·가정과 다음 확인을 연결했다. 새 검색 후보 P에 대해 가정 H1은 안내 용어를 사전 설명 없이 이해한다는 것이고 H2는 포인터 없이 키보드로 과업을 완료한다는 것이다. 두 가정은 서로 다른 관찰 조건이다. 용어를 미리 가르친 뒤 포인터를 허용한 시연 성공은 어느 가정의 직접 확인도 아니다. 여기서 사용자 시험은 계획만 하며 실제 사람을 모집하거나 시연하지 않는다.

자체 계획 비용은 공통 종이 자료 준비 2시간, 용어 질문 세션 하나 1시간, 키보드 과업 세션 하나 2시간이다. 한 번의 공통 준비 뒤 두 종류를 각각 한 번 계획하면 총 5시간이다. 총 예산이 4시간이면 두 종류를 모두 그대로 수행할 수 없다. 용어 세션을 선택하면 계획 비용은 3시간이고 H2는 미확인으로 남긴다. 계획에 포함한 것과 실제로 수행해 조건을 확인한 것도 다르다.

앞 본문의 두 기준에서 D=(2,2)는 A=(5,2)에 지배됐다. 새 별도 설계에서는 비용이 A 8시간, D 2시간이고 예산 상한이 3시간이다. 같은 두 점수 관계를 유지해도 실행 가능한 후보는 D뿐이다. 원래 지배 결론은 다른 조건과 비용이 같다는 범위였으며 새로운 비용 제약이 있는 전체 선택 결론으로 옮길 수 없다. 비용을 세 번째 기준으로 보면 D는 더 낮은 비용에서 우수하여 A가 모든 기준에서 지배하지도 않는다.

한 장점을 얻는 대가

trade-off는 어떤 목적을 개선하는 선택이 다른 목적이나 비용에 영향을 주는 관계다. 목록을 짧게 만들면 한 화면은 간단해져도 생략된 개념을 찾으려면 더 많은 탐색이 필요할 수 있다. 하지만 항상 반비례하는 자연 법칙이라고 단정하면 안 된다. 더 좋은 구조로 두 목적을 함께 개선할 가능성도 있다.

대안 A가 찾기 5, 이해 2이고 C가 찾기 2, 이해 5라는 가상 장부에서는 둘 중 어느 것도 모든 항목에서 더 좋지 않다. 반면 D=(2,2)는 A=(5,2)에 의해 지배된다. 다른 조건과 비용이 동일하고 높은 값이 좋은 두 항목만 고려할 때 A가 모두 나쁘지 않고 하나는 더 좋기 때문이다.

가정 장부를 검증 질문으로 바꾸기

지도 대안이 좋다는 주장을 '처음 온 사람이 그림 노드의 의미를 설명할 수 있다'라는 가정으로 풀어 보자. 장부에는 가정, 현재 근거, 틀렸을 때 영향, 필요한 관찰과 판단 규칙을 적는다. 저자의 예상은 근거 칸에서 가설로 표시한다. 클릭 횟수가 적다는 사실이 용어를 이해했다는 증거는 아니다.

학습 목표는 지도 그림의 해석 장벽을 알아보는 것이다. 종이 화면을 보여 주고 노드의 의미를 자신의 말로 설명하게 하는 계획을 세울 수 있다. 설명을 먼저 가르쳐 주면 첫인상 이해를 관찰한다는 목적과 달라진다. 실제 참여자 모집·윤리와 접근 지원은 따로 검토하며 이 원고의 종이 활동은 사람을 대상으로 실행한 연구가 아니다.

불확실성과 결정의 되돌림

가상 계획에서 설명을 붙인 B의 만들기 비용은 6시간, 그림만 있는 A는 4시간이라고 추정한다. 차이 2시간은 견적 가정이며 실측이 아니다. B가 이해를 실제로 높인다는 가정이 틀리면 추가 비용의 목적을 달성하지 못한다. 숫자에 단위를 붙이고 관찰된 시간과 구별하자.

가정을 줄이는 작은 prototype를 먼저 만들고 결과에 따라 선택을 수정할 수 있다. 큰 영향을 주지만 근거가 약한 가정부터 살피되, 중요도×불확실성 같은 점수도 내부 우선순위 도구다. 실제 실패 확률이나 피해의 기댓값이라고 부르려면 별도의 확률·손실 정의와 근거가 필요하다. 기록은 확정 사항과 미지수를 함께 남긴다.
