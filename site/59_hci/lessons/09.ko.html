소단원 9.1

키보드·보조기술

마우스를 놓고도 강의 다음 단원으로 갈 수 있을까?

준비 개념과 학습 목표

준비 개념

  • HTML 버튼과 링크

  • focus와 이벤트

학습 목표

  • 입력 수단과 기능 접근성을 구분한다.

  • 이름·역할·상태와 키보드 흐름을 함께 설계한다.

대화상자 안에서 키보드가 순환하면 항상 갇힌 것일까요?

앞 본문은 기능 실행과 이름·역할·상태를 나누었다. 이번에는 삭제 확인 대화상자의 초점과 자료 변경을 함께 추적한다. 실제 브라우저를 만들지 않는 자체 상태표이며 APG의 모달 초점·닫기·복귀 안내를 참고한다. 대화상자 안에서 Tab이 순환해도 닫는 키와 닫기 제어가 있어 나올 수 있는 경우와 닫을 방법 자체가 없는 경우를 구별한다.

초기 목록에는 ID 7과 8이 있다. 각 예제와 과제는 별도 초기 상태에서 시작하며 문항 안에서 이어 수행한다고 쓴 사건만 연속이다. 각 삭제 버튼을 O7과 O8이라고 부르고 목록 제목은 L이다. 삭제 확인 모달의 내부 제어 순서는 취소 C, 삭제 D다. O7 또는 O8에서 열면 초점은 C로 간다. Tab은 C에서 D로, D에서 C로 이동하고 Shift+Tab은 반대로 이동한다. Escape 또는 C 활성화는 자료를 보존하며 모달을 닫고 호출 버튼으로 초점을 돌린다. 이 과제에서는 활성화 키를 Enter로 명시한다.

D를 활성화하면 선택한 ID를 삭제한 뒤 모달을 닫는다. 호출 버튼도 사라지므로 다른 기존 삭제 버튼이 있으면 그 버튼에, 없으면 L에 초점을 둔다는 자체 복귀 정책을 정한다. 이는 모든 앱에 강제되는 유일한 복귀 위치가 아니다. 별도 토글 버튼의 접근 가능한 이름은 자막으로 고정하고 눌림 상태만 false/true로 바꾼다. 키로 실행되는 사실만으로 이 이름과 상태가 보조기술에 전달됐다고 판정하지 않는다.

먼저 확인할 개념
  • 초점과 의미를 함께 전달하기

    기본 대화상자 복귀 설명을 삭제 뒤 호출 요소 소멸의 자체 정책으로 확장한다.

  • 복합 제약의 기능 경로

    키보드 경로가 있어도 경고를 이해하고 기능을 식별할 조건을 따로 확인한다.

기능은 여러 입력으로 도달한다

키보드 접근성은 특정 기기를 반드시 쓰게 하는 뜻이 아니라 키보드 인터페이스로 동등한 기능을 수행할 수 있게 하는 것이다. 시각·운동 제약이 있는 사람과 대체 입력 장치도 이 경로를 사용할 수 있다.

일반 버튼은 native button, 이동은 link처럼 의미 있는 요소를 먼저 선택한다. 그림을 클릭하게만 하고 텍스트 이름이나 키보드 동작을 빼면 화면에 보이는 것과 접근 가능한 기능이 달라진다.

초점과 의미를 함께 전달한다

focus는 현재 입력을 받는 대상이다. 논리적인 이동 순서와 볼 수 있는 focus 표시, 읽을 수 있는 이름을 마련한다. 보조기술은 플랫폼의 접근성 정보로 역할·이름·상태를 전달하므로 클릭 동작만 복제해서는 충분하지 않다.

토글이라면 눌림 상태가 바뀌는 것을 프로그램에도 알리고, 대화상자를 닫은 후 이어갈 초점 위치를 정한다. 실제 screen reader와 브라우저 조합별 동작은 나중에 검증해야 한다.

기능의 예외와 검증을 구별한다

WCAG 2.1.1은 키 입력의 특별한 타이밍 없이 기능을 조작하도록 요구하되 자유로운 붓질처럼 기능 자체가 이동 경로에 의존하는 경우를 구별한다. 드래그로 위치를 바꾸는 기능은 끝점 선택 같은 대안이 가능하므로 마우스 동작이라고 곧바로 예외는 아니다.

여기서는 세 제어의 종이 표만 확인한다. 키보드 기능표가 모두 참이어도 이름·상태·초점 표시나 전체 WCAG 준수가 자동 증명되는 것은 아니다. 이 기준은 웹 기술 기준이며 모든 국가 법 적용을 판정하지 않는다.

중간 과정을 따라가는 예제

가상 화면의 제어는 시작/힌트/다음 세 개다. native 시작 버튼과 다음 링크는 keyboard 작동=true, 클릭 전용 힌트 그림은 false다. 검사 기능표를 채우자.

  1. 세 기능 중 키보드 경로가 있는 것은 시작과 다음 두 개다.

  2. 힌트를 의미 있는 버튼으로 바꾸고 동일 기능을 키보드에서도 호출하도록 설계하면 세 기능의 경로를 모두 마련할 수 있다.

  3. 별도로 이름 힌트 보기, 초점 표시, 상태 전달을 검토해야 하므로 3/3 은 전체 접근성 점수가 아니다.

현재 기능 경로는 2/3, 설계 후 3/3 이다. 실제 브라우저·보조기술 검증은 미수행이다.

조건을 바꾸어 비교하기

내부 순환 뒤 취소

초기 O7에서 열기, Tab, Tab, Escape를 수행한다. 초점과 목록을 추적하라.

  1. 초점은 O7에서 C, D, C, O7 순서로 간다. 모달은 마지막에 닫힌다.

  2. 삭제 제어를 활성화하지 않아 목록은 {7,8} 그대로다.

목록 {7,8}을 보존하고 O7로 돌아온다. 두 Tab의 내부 순환만으로 출구가 없다고 판단하지 않는다.

비교할 점

Escape와 취소 제어가 실제로 구현됐는지는 이 종이 추적 밖의 검사다.

호출 버튼이 없어지는 삭제

각 예제는 새 초기 상태에서 시작한다. O7에서 열고 Tab으로 D에 간 뒤 Enter로 삭제한다. 이어 남은 O8에서도 같은 절차로 삭제한다.

  1. 첫 삭제 뒤 목록은 {8}이고 호출 O7은 사라져 O8로 초점을 옮긴다.

  2. 두 번째 삭제 뒤 목록은 비며 기존 삭제 버튼도 없어 L로 초점을 옮긴다.

첫 복귀는 O8, 둘째 복귀는 L이다. 삭제는 총 두 건이다.

연습 1 · 값과 상태 예측

새 초기 O7에서 열고 Shift+Tab, Escape를 수행한다. D에 초점이 간 사실과 삭제 여부를 구별하라.

힌트 1

C에서 역순 이동하면 마지막 D다.

힌트 2

초점과 활성화는 다르다.

풀이와 답 확인

  1. 초점은 C에서 D로 간다. Escape는 닫기이며 삭제 활성화가 아니다.

  2. 목록 {7,8}을 보존하고 O7로 돌아온다.

D에 잠깐 초점이 있어도 삭제하지 않는다.

흔한 오답에서 다시 생각하기

D를 바라봤으니 ID 7은 삭제됐다.

초점을 받은 상태와 제어의 활성화를 혼동했다.

연습 2 · 오류 찾아 고치기

개발자가 aria-modal=true만 붙이고 Tab은 배경 O8로 나가도록 두었다. 종이 정책과 어떤 차이가 있는가?

힌트 1

의미 선언과 실제 이동을 나눈다.

힌트 2

모달 밖 상호작용의 허용을 확인한다.

풀이와 답 확인

  1. 정한 모달 계약은 초점이 C/D 안에서 이동하며 배경 조작을 막는다. O8로 빠지는 실제 행동은 그 계약과 다르다.

  2. 선언만으로 이동·배경 제어가 구현되지는 않는다. 실제 브라우저와 보조기술 검사 계획을 남긴다.

모달 의미와 실제 행동을 함께 맞춰야 한다. 현재 구현은 검사하지 않았다.

흔한 오답에서 다시 생각하기

속성이 있으니 모든 사용자의 배경 접근이 자동 차단됐다.

ARIA의 의미 정보와 실제 입력 제어는 같은 작업이 아니다.

연습 3 · 직접 만들어 보기

자막 토글이 처음 false이고 두 번 활성화된다. 고정 이름과 전달할 상태의 기록표를 만들어라.

힌트 1

기능 이름은 자막이다.

힌트 2

현재 눌림 값은 활성화 때 뒤집는다.

풀이와 답 확인

  1. 처음 이름 자막과 false, 첫 활성화 뒤 같은 이름과 true, 둘째 뒤 같은 이름과 false를 기록한다.

  2. 시각 표시와 프로그램에 전달할 눌림 상태를 함께 점검하고 실제 읽힘은 미확인으로 둔다.

이름은 자막으로 고정하고 상태는 false, true, false다.

흔한 오답에서 다시 생각하기

색이 바뀌면 보조기술도 상태를 정확히 알 것이다.

시각 색 변경은 프로그램 상태 전달의 증거가 아니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

대화상자에 긴 표가 있고 첫 버튼으로 초점을 보내면 표의 시작이 화면 밖으로 나간다. 최초 초점 정책을 바꾸는 방안을 설명하라.

힌트 1

항상 첫 버튼만이 정답인지 본다.

힌트 2

읽을 시작 요소와 Tab 순서를 구분한다.

풀이와 답 확인

  1. 표를 읽을 수 있는 제목 같은 정적 시작 요소에 프로그램으로 초점을 두는 방안을 검토한다.

  2. 그 요소에 tabindex=-1을 쓰는 경우도 이후 C/D의 순차 이동과 닫기·복귀를 별도로 설계한다.

내용과 과업에 맞춘 최초 초점을 선택한다. 실제 읽기·스크롤 동작은 별도 검사다.

작은 표적 둘 사이의 간격과 글자 대비를 한 점수로 합칠 수 있을까요?

앞 본문의 대비비와 CSS 표적 치수를 별도로 사용한다. 새 일반 텍스트의 밝은 상대휘도는 0.8498, 어두운 상대휘도는 0.15다. RGB 원소가 아닌 이미 계산된 휘도이며 로고·비활성 등의 예외는 없다. 표시 반올림과 실제 문턱 비교를 구별한다. 큰 텍스트의 별도 조건을 주지 않았으므로 일반 텍스트 기준을 사용한다.

새 표적은 모두 축에 평행한 실제 클릭 영역인 20×20 CSS px 정사각형이다. 다른 표적은 없고 두 중심의 y는 0이다. A의 중심 x는 0, B의 중심 x는 26이다. 기본 24×24 치수에는 미달하지만 간격 예외를 살펴볼 수 있다. 각 중심의 지름 24인 원이 이웃 표적 또는 이웃의 같은 원과 겹치는지 본다. 이 모형은 명백한 양의 틈과 명백한 겹침만 다루며 접하는 경계 사례는 계산에 넣지 않는다.

같은 원을 이웃 작은 표적의 원과만 비교하면 큰 이웃 표적을 놓칠 수 있다. 별도 큰 표적 Q를 x 구간 [11,35], y 구간 [−12,12]의 정사각형으로 두면 A의 검사 원은 Q의 내부 점 (11.5,0)을 포함한다. 실제 클릭 영역과 표시 아이콘을 구별한다. 별도 200% 페이지 zoom에서 CSS 치수가 그대로인 설정이라면 화면 표시가 커져도 이 치수·간격 계산은 그대로이며 내용·기능 보존도 미확인이다.

먼저 확인할 개념
  • 대비 문턱과 기본 표적 치수

    기본 휘도 식에 반올림 경계와 작은 표적의 간격 조건을 추가한다.

  • 대안의 복합 제약

    확대와 입력 영역 하나의 개선이 다른 장벽을 해결하는지 따로 본다.

대비는 밝기 차이를 본다

WCAG 1.4.3의 일반 텍스트 최소 대비는 4.5:1이며 정의에 맞는 큰 텍스트는 3:1이다. 색 이름만 다르다고 읽기 쉬운 것은 아니다. 장식·비활성 요소·로고 등 예외의 조건도 있다.

대비비는 (밝은 상대휘도+0.05)/(어두운 상대휘도+0.05)다. 아래 예는 상대휘도를 이미 계산해 주며 RGB 값을 그대로 휘도처럼 대입하지 않는다. 이 한 항목의 통과가 모든 UI 색 기준을 대신하지 않는다.

확대 후에도 기능을 유지한다

WCAG 1.4.4는 caption과 이미지 텍스트 예외 아래 일반 텍스트를 보조기술 없이 200%까지 확대해 내용·기능을 잃지 않게 한다. 글씨 크기만 키우고 저장 버튼을 잘라 숨기면 목적을 못 이룬다.

200%는 기본 표시보다 글자가 두 배로 커지는 검토 조건이다. 텍스트 전용 크기 설정과 브라우저 페이지 zoom을 구별하자. 페이지 zoom은 CSS px 값이 유지되어도 표시가 커질 수 있다. 실제 viewport·줄바꿈·확대 방식을 확인해야 하며 숫자 계산만으로 확대 준수를 판정하지 않는다.

눌리는 범위는 가로와 세로를 본다

WCAG 2.5.8의 기본 pointer target은 24×24 CSS pixels 이상이다. 작은 대상의 간격, 동등한 제어, 문장 안 링크, user agent, essential 조건 같은 예외가 있으므로 모든 작은 아이콘이 곧바로 실패라고 단정하지 않는다.

화면 그림의 크기와 실제 클릭 영역이 다를 수 있다. 예외가 없는 독립 버튼은 두 치수 모두 보며 면적 합만 같다고 기준을 대신할 수 없다. 페이지 zoom으로 표시가 커져도 CSS px 기준 표적 치수는 그대로일 수 있으므로 사용자 확대를 근거로 작은 표적을 충족 판정하지 않는다.

중간 과정을 따라가는 예제

가상 일반 본문 상대휘도 밝은 값 0.85, 어두운 값 0.15다. 자체 모형에서 텍스트 전용 크기 설정을 16 CSS px에서 32 CSS px로 바꾼다. 이는 브라우저 페이지 zoom에 따른 CSS 값 변화 모형이 아니다. 예외 없는 버튼 실제 표적은 30×18 CSS px다.

  1. 대비는 (0.85+0.05)/(0.15+0.05)=0.90/0.20=4.5 이므로 일반 텍스트 최소 문턱과 같다.

  2. 이 텍스트 전용 크기 설정 모형에서는 16×2=32 CSS px다. 내용·버튼 접근 여부를 별도 확인해야 하며 브라우저 페이지 zoom에서 CSS font-size가 반드시 두 배가 된다는 뜻은 아니다.

  3. 표적 높이 18<24 이므로 기본 치수 조건은 충족하지 않는다. 면적 540 은 판정 기준을 대신하지 않는다.

소단원 9.3

다양한 능력과 맥락

같은 사람도 조용한 방과 버스에서 필요한 기능이 달라질까?

준비 개념과 학습 목표

준비 개념

  • 사용자 목표와 맥락

  • 대체 표현

학습 목표

  • 개인별 능력과 상황 제약을 함께 설명한다.

  • 한 대안의 한계와 선택권을 찾는다.

필요한 기능이 여기저기 흩어져 있으면 한 사람이 끝까지 사용할 수 있을까요?

다양한 능력과 상황은 같은 과업의 여러 장벽을 함께 만들 수 있다. 새 종이 표의 H는 소리를 듣지 않아도 경고 의미를 확인할 경로, M은 pointer 없이 확인할 경로, V는 필요한 큰 글씨로 내용 전체를 읽을 경로다. 1은 선언한 가정에서 그 경로를 준비했다는 뜻이며 실제 사람의 능력 점수나 성공 확률이 아니다.

후보 경로 A는 (H,M,V)=(1,1,0), B는 (1,0,1), C는 (0,1,1)이다. 각 행은 하나의 과업을 처음부터 끝까지 같은 경로에서 수행하는 안이다. 이 자체 모형에서는 과업 도중 다른 경로로 옮길 기능이 없다. 소리와 pointer 두 제약을 가진 경우에는 H와 M을 같은 행에서 요구하고, 세 제약을 함께 가진 경우에는 H/M/V를 모두 요구한다. 각 열에 1이 하나 이상 있다는 이유만으로 세 제약의 단일 경로가 생기지는 않는다.

세 필요 조합 HM, HV, MV는 각각 A, B, C로 지원하지만 HMV는 어느 행도 지원하지 못한다. 자체 추가 준비 비용은 A에 V를 붙이면 2단위, B에 M을 붙이면 3단위, C에 H를 붙이면 1단위다. 이는 가상 작업량이다. 기능이 준비돼도 경로를 발견하고 선택할 수 있는지, 메시지 의미가 일치하는지 실제 참여 검토는 별도다. 진단명 하나에서 이 표의 필요 조합을 자동 추측하지 않는다.

먼저 확인할 개념
  • 변하는 능력과 복합 제약

    기본 텍스트와 확대의 결합 반례를 같은 행의 여러 조건으로 확장한다.

  • 기능 경로와 식별 조건

    실행할 수 있는 기능과 이름·상태를 이해하고 경로를 찾는 조건을 구별한다.

사람을 한 범주에 고정하지 않는다

청각·시각·운동·인지·말하기 능력은 사람마다 다르고 복합적으로 나타나거나 시간에 따라 변할 수 있다. 진단 이름 하나만으로 선호하는 입력 방식이나 필요한 기능을 모두 추측할 수 없다.

일시적인 손 부상, 피로와 집중 저하, 시끄러운 장소나 햇빛도 이용 조건을 바꾼다. 접근성을 특정 사용자에게만 붙이는 옵션이 아니라 기능에 도달하는 여러 경로로 설계한다.

같은 목표를 여러 표현으로 연결한다

오디오 경고에 텍스트 상태를 함께 주면 듣기 어려운 환경에서도 뜻을 알 수 있다. 하지만 텍스트가 너무 작거나 대비가 낮으면 복합 제약을 해결하지 못한다.

사용자가 자막 크기·색, 입력 경로, 읽기 속도 등을 선택할 수 있도록 하고 설정의 발견 가능성을 본다. 모든 대안을 강제로 동시에 켜기보다 의미가 일치하고 필요한 경로를 선택할 수 있게 한다.

가정 표와 실제 참여를 구별한다

설계 표는 누가 어떤 장벽을 만날 수 있는지 생각하는 출발점이다. 표의 참은 주어진 가정에서 기능 경로가 있다는 뜻이지 실제 사용 편의나 학생 성공이 입증된 것은 아니다.

여러 필요를 가진 사람의 의견을 받고 관찰할 계획을 세우되 아직 참여 검토를 하지 않았다면 미수행으로 남긴다. 특정 국가의 법적 의무나 모든 장애 상황 해결을 이 표만으로 선언하지 않는다.

세 사례는 각각 독립이다. ① 목록 {7,8}의 O7에서 열고 Tab, Enter로 삭제한다. 자료와 닫은 뒤 초점을 쓰라. ② 일반 텍스트 휘도는 0.8498/0.15이고 두 표적은 20×20 CSS px, 중심은 (0,0)/(23,0)이다. 대비와 기본 치수·간격 조건을 따로 판단하라. 다른 표적이나 예외는 없다. ③ A=(1,1,0), B=(1,0,1), C=(0,1,1)의 열은 H/M/V다. 필요 목록 HM/HV/MV/HMV의 지원 비율과 HMV 추가 준비 최소안을 구하라. A의 V 추가는 2단위, B의 M 추가는 3단위, C의 H 추가는 1단위다. 실제 UI·보조기술·참여자 실험은 미수행이다.

힌트 1

① 초점과 활성화를 구별한다. ② 표시 반올림을 실제 비율로 바꾸지 않는다.

힌트 2

③ 같은 행의 결합 조건을 먼저 보고 목록과 사람의 분모를 구별한다.

풀이와 답 확인

  1. ① Tab으로 C에서 D에 간 뒤 Enter로 ID 7을 삭제한다. 목록은 {8}이고 O7이 없어 자체 정책에 따라 O8로 복귀한다.

  2. ② 실제 대비는 0.8998/0.20=4.499라 일반 텍스트 문턱 미달이다. 두 표적은 기본 치수가 미달이고 중심 거리 23이 검사 원 반지름 합 24보다 작아 간격 조건도 미달이다.

  3. ③ HM은 A, HV는 B, MV는 C로 지원하고 HMV는 미지원이라 목록 비율은 3/4다. HMV 추가 준비는 C의 1단위가 최소다.

  4. 이 상태·기하·준비 계산을 실제 초점 동작·전체 WCAG 준수·사용자 성공률·법률 판정으로 확대하지 않는다.

목록은 {8}, 닫은 뒤 초점은 O8이다. 대비 4.499는 일반 텍스트 문턱 미달이고 두 표적의 기본 치수와 간격 조건도 미달이다. 가상 필요 목록 지원은 3/4이며 HMV 준비의 최소 추가 비용은 C의 1단위다. 실제 UI와 사람의 수행 검증은 미수행이다.
