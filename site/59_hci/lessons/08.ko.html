소단원 8.1

종이·디지털 prototype

버튼을 눌렀을 때 다음 화면을 아직 만들지 않았다면 무엇을 확인할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • prototype 은 완제품 전에 질문을 시험하기 위한 시제품이다.

  • 화면 상태와 사용자의 행동을 구별한다.

학습 목표

  • 종이 화면의 상태 전이를 적는다.

  • 디지털 연결과 실제 기능 구현의 차이를 설명한다.

화면보다 행동의 연결을 만든다

과목 찾기 화면 한 장은 목록의 배치를 보여 준다. 하지만 검색어 입력 뒤 무엇을 보여 줄지, 결과를 고른 뒤 어디로 갈지 없으면 탐색 과업을 끝낼 수 없다. 먼저 시작 상태·행동·다음 상태를 세 칸 표로 적는다.

종이 prototype 에서는 사람이 정해 둔 전이표에 맞춰 화면 카드를 교체한다. 참가자의 선택을 대신하거나 정답 버튼을 가리키면 설계의 이해 가능성과 진행자의 도움 효과를 분리할 수 없다. 화면 교체 담당과 관찰 기록 역할을 준비한다.

디지털 화면도 계약을 정한다

같은 그림을 디지털 도구의 클릭 영역과 연결하면 자동으로 다음 화면을 보여 줄 수 있다. 그러나 화면 전환을 만들었다고 서버 검색이나 데이터 저장까지 구현된 것은 아니다. 실제 기능·고정 자료·사람이 대신하는 부분을 구분해 표시한다.

예제의 검색 결과는 미리 만든 단어 세 개만 처리하는 자체 모형이다. 다른 단어를 입력했을 때 진행자가 임의로 결과를 발명하면 원래 설계와 다른 모형을 시험하게 된다. 지원 밖 입력은 지원하지 않는 상태로 기록하고 필요한 경우 다음 판에 추가한다.

반복은 관찰에서 수정으로 간다

막힌 화면에서 문제를 메모하고 설계 가설을 적은 다음 새 판을 만든다. 예컨대 결과 없음에서 검색어를 바꾸는 길이 없다는 문제라면 수정안은 편집으로 돌아가는 연결이다. 색만 바꾸고 이 경로를 그대로 두면 그 문제를 해결한 것이 아니다.

아래 활동은 카드의 논리적 연결만 확인한다. 사람이 카드를 다루는 지연은 실제 앱 응답 성능 측정이 아니며, 만든 경로가 타당하다고 실제 학생이 쉽게 사용할 것이라 검증된 것도 아니다. 사용자 관찰은 별도 수행해야 한다.

중간 과정을 따라가는 예제

자체 카드 A=검색 입력, B=결과 목록, C=과목 소개, D=결과 없음이다. A 에서 알려진 검색어를 제출하면 B, 모르는 검색어는 D, B 에서 과목 선택은 C, C 의 뒤로는 B 다. D 에는 나가는 연결이 없다. 미지 검색어에서 다시 검색하려면 무엇이 부족한가?

  1. A 에서 미지 검색어를 제출하여 D 에 도달한다.

  2. D 의 나가는 연결이 없으므로 검색어 수정이라는 다음 행동을 할 수 없다.

  3. D 의 검색어 수정 행동을 A 로 연결한다. 새 전이는 A→D→A 이며 다음에 알려진 단어를 넣으면 A→B→C 로 진행한다.

D→A 연결이 필요하다. 수정 뒤 두 제출과 선택을 포함한 경로 A,D,A,B,C 의 전이는 4 번이다.

종이와 본문으로 직접 해보기

A 에서 알려진 단어를 제출하고 과목을 선택한 뒤 뒤로 간다. 카드 순서를 적고 B 에서 다른 과목을 고를 때 C 가 고정된 한 과목이면 무엇이 빠졌는지 설명하라.

힌트 보기

한 화면 이름과 그 화면이 담는 과목 자료는 별개다.

풀이 보기

A,B,C,B 의 전이는 3 번이다. 다른 과목의 소개 상태나 자료 바인딩을 준비해야 한다. 같은 C 카드의 제목만 고정해 두면 여러 과목 선택을 검증하지 못한다.

오해와 반례

클릭 가능한 화면이면 검색 기능도 구현됐다.

A→B 의 연결이 고정 결과 카드만 보여 주어도 클릭은 가능하다. 실제 검색 알고리즘·저장소·없는 단어 처리는 각각 별도의 기능이다.

자기점검

D 는 왜 막힌 상태인가?

답과 이유 보기

검색어를 수정하는 나가는 행동이 없다.

현재 전이표에는 D 의 다음 상태가 없다.

A,D,A,B,C 의 전이 수는?

답과 이유 보기

4 번이다.

카드 5 개 사이에 이동 4 개가 있다.

카드 교체 시간으로 서버 성능을 평가해도 되나?

답과 이유 보기

이 모형에서는 안 된다.

사람의 교체 동작을 서버 응답으로 구현하지 않았다.

한 단계 더

실패·취소·빈 결과를 서로 다른 카드로 추가하고 각 카드에서 사용자가 목표를 다시 이어 갈 길을 설계한다. 지원 범위를 문서화하고 실제 사용자 실험과 종이 연결 검사를 별도 기록한다.

소단원 8.2

충실도와 검증목적

예쁜 화면과 실제로 작동하는 화면은 같은 수준의 prototype 일까?

준비 개념과 학습 목표

준비 개념

  • 충실도는 최종 제품과 닮은 정도이며 하나의 점수만으로 설명하기 어렵다.

  • 시험 질문을 먼저 정하면 필요한 자료와 반응을 선택할 수 있다.

학습 목표

  • 시각·상호작용·내용의 충실도를 분리한다.

  • 주장할 수 있는 결론의 범위를 정한다.

어떤 면에서 닮았는지 묻는다

시각 충실도는 배치·색·글꼴 같은 모습, 상호작용 충실도는 입력에 대한 반응, 내용 충실도는 문장·자료의 현실성을 뜻한다. 세 가지를 각각 적으면 화려하지만 클릭이 안 되는 화면과 단순하지만 탐색이 되는 화면을 구별할 수 있다.

이 단원은 낮음/높음이라는 자체 두 수준 표를 쓴다. 실제 설계는 중간 수준도 있으며 모든 차원을 동시에 높여야 한다는 규칙은 아니다. 시험하려는 질문에 꼭 필요한 차원이 무엇인지 먼저 적는다.

질문에 필요한 표현을 남긴다

학습자가 과목 설명을 이해하는지 묻는데 모든 설명이 가짜 한 줄이면 내용 이해를 시험하지 못한다. 반대로 버튼 사이 이동을 확인하는 질문에는 서버 전체가 반드시 필요하지 않을 수 있다. 필요한 자료와 움직임을 골라 작은 시제품으로 시험한다.

색 대비·작은 글자 읽기 같은 질문은 실제 표시 크기와 관련 색이 충분히 표현되어야 한다. 흑백 큰 종이에서 읽힌 결과로 실제 작은 휴대전화의 읽기 쉬움을 확정할 수 없다. 매체와 지원 범위를 결론에 함께 붙인다.

충실도와 성능 증거를 구별한다

입력과 화면 반응이 잘 연결되어도 고정 자료로 만든 프로토타입은 많은 사용자가 접속하는 상황의 성능을 보여 주지 않는다. 실제 저장·통신을 생략한 부분은 해당 결론의 근거가 될 수 없다.

자체 요구표에서 기능이 제공되면 1, 없으면 0 으로 표시한다. 이것은 검증 가능성의 필요조건을 점검하는 도구이지 실제 참가자의 성공을 예측하는 확률은 아니다. 조건을 갖춘 뒤 실제 실험을 해야 효과를 관찰할 수 있다.

중간 과정을 따라가는 예제

시제품 P 는 실제 과목 설명·그림이 있지만 정적 화면이고, Q 는 클릭 경로가 있지만 설명은 모두 lorem ipsum 이다. 질문 X 는 설명을 읽고 선수과목을 고를 수 있는지, Y 는 검색→소개→돌아가기 경로를 끝낼 수 있는지다. 내용/경로 지원을 P=(1,0),Q=(0,1)로 두고 각 질문에 필요한 요소를 판정하라.

  1. X 는 실제 설명을 필요로 하므로 내용 지원이 1 인 P 가 해당 자료 조건을 갖춘다.

  2. Y 는 세 상태의 상호작용을 필요로 하므로 경로 지원이 1 인 Q 가 조건을 갖춘다.

  3. X 와 Y 를 모두 확인하려면 실제 내용을 Q 에 넣거나 P 의 상태 연결을 추가해야 한다. 원래 어느 하나도 두 요구를 모두 충족하지 않는다.

자체 요구표에서 P 는 X 자료, Q 는 Y 경로를 지원한다. 이것은 실험 준비 가능성 판정이며 실제 이해·사용 성공 결과는 아니다.

종이와 본문으로 직접 해보기

Q 에 실제 설명을 넣어 Q′=(1,1)로 만들었다. 데이터베이스나 실제 서버는 여전히 없다. 두 질문 준비와 서버 부하 성능 질문 Z 를 각각 판정하라.

힌트 보기

질문별로 관찰할 기능이 구현됐는지 확인한다.

풀이 보기

Q′는 X 의 내용과 Y 의 경로를 갖춰 두 과업 준비가 가능하다. Z 의 실제 서버가 없어 그 부하 성능은 검증할 수 없다. 1,1 은 모든 종류의 검증 완료를 뜻하지 않는다.

오해와 반례

충실도가 높으면 어떤 질문에도 정답을 얻는다.

고정 결과만 보여 주는 사실적인 화면으로 동시 접속 성능을 증명할 수 없다. 시각·내용·상호작용과 시스템 성능의 증거를 연결해서 판단한다.

자기점검

P 의 경로 지원은?

답과 이유 보기

0 이다.

정적 화면만 있으며 이 모형은 자동 이동을 제공하지 않는다.

Q 의 가짜 설명으로 선수과목 이해를 확정할 수 있나?

답과 이유 보기

할 수 없다.

판단에 필요한 실제 내용을 제공하지 않는다.

Q′=1,1 이면 사용자 검증이 끝났나?

답과 이유 보기

아니다.

시험을 준비할 요소와 실제 관찰 결과는 다르다.

한 단계 더

과목 선택 이유·검색 실패 복구·좁은 화면 읽기·실제 저장의 네 질문을 만들고 각각 필요한 충실도와 제외 기능을 적는다. 숫자 하나로 시제품의 완성도를 평가하지 말고 질문별 근거를 남긴다.

소단원 8.3

참여자 과업 구성

“오른쪽 즐겨찾기 버튼을 누르세요”라고 안내하면 무엇을 알아낼 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 과업은 화면 조작 명령보다 참여자가 달성할 목표로 표현할 수 있다.

  • 성공 기준과 도움 여부를 사전에 정한다.

학습 목표

  • 정답 경로를 유도하지 않는 과업을 쓴다.

  • 가상 사건표에서 독립 성공과 도움 뒤 완료를 구별한다.

맥락과 목표를 주고 경로는 남긴다

공개 강의에서 나중에 다시 볼 과목을 보관하려는 상황을 제시한다. 즐겨찾기라는 버튼명과 위치를 먼저 알려 주면 그 이름을 발견하고 이해하는지 관찰하기 어렵다. 필요한 과목과 목표는 구체적으로 주되 경로 자체를 지시하지 않는다.

애매하게 알아서 해 보라고만 하면 참여자가 목표를 물어야 할 수 있다. 어떤 과목을 찾는지, 어떤 결과가 필요한지를 분명히 적는다. 표준 용어를 억지로 피해서 더 혼란스러운 문장을 만드는 것도 목표가 아니다.

시작 상태와 성공 판정을 고정한다

각 과업에서 계정·저장 목록·검색 상태를 같은 조건으로 준비하고 완료 기준을 적는다. 이 예제의 성공은 특정 과목을 저장하고 나중에 볼 목록에서 확인하는 것이다. 좋아 보인다는 말만으로 완료 판정을 대신하지 않는다.

이 단원은 도움 없이 기준 충족이면 독립 성공, 진행자의 경로 힌트 뒤 충족이면 도움 뒤 완료로 분리하는 자체 기록 규약을 쓴다. 중단·도구 고장·지원 밖 행동도 별도 적어야 사용자의 실패와 시제품 한계를 구별할 수 있다.

기록은 과업과 참여자별로 나눈다

참여자별 시작·행동·막힘·도움·결과를 연결하면 수정할 근거가 남는다. 앞 과업에서 저장 기능을 배웠다면 다음 과업 결과에 학습 효과가 있을 수 있으므로 과업 순서도 기록한다.

아래의 인물과 사건은 모두 만들어 낸 교육용 표다. 실제 참여자를 모집하거나 실험하지 않았으므로 성공 비율을 사이트의 검증 수치로 공개하면 안 된다. 작은 가상 표의 산술과 모집단 추론은 별개다.

중간 과정을 따라가는 예제

자체 가상 로그에서 A 는 도움 없이 과목 저장과 목록 확인, B 는 저장했으나 목록 확인 전에 중단, C 는 위치 힌트 뒤 두 기준 충족, D 는 도움 없이 두 기준 충족했다. 네 과업 기회 모두 유효하며 독립 성공 기준은 두 결과를 도움 없이 충족하는 것이다.

  1. A 와 D 는 두 기준을 도움 없이 충족하여 독립 성공 2 명이다.

  2. C 는 도움 뒤 완료, B 는 이번 기준 미완료다. 저장 한 단계만 끝냈다고 전체 성공으로 바꾸지 않는다.

  3. 독립 성공 비율은 2/4=50%, 도움 포함 완료는 3/4=75%다. 두 수치의 분자 정의가 다르다.

가상 표의 독립 성공 50%, 도움 포함 완료 75%다. 실제 이용자의 성과나 모집단의 확률 추정은 아니다.

종이와 본문으로 직접 해보기

“소개 화면 오른쪽 별 아이콘을 누른 뒤 내 목록 메뉴를 누르세요”를 목표 과업으로 고쳐 쓰고, 실제로 시제품 오류가 난 E 의 결과를 기존 네 명 분모에 넣어도 되는지 설명하라.

힌트 보기

목표 결과는 알려 주되 화면 위치와 버튼명으로 길을 가르치지 않는다. 도구 오류는 참여자 행동과 다르다.

풀이 보기

예: “선형대수학을 다음 주에도 찾아볼 수 있게 보관하고 보관된 과목 목록에서 확인해 주세요.” E 는 시제품 오류로 평가 불가능하다고 별도 기록한다. 산술의 분모를 바꾸려면 평가 규약·대상 기회 정의를 명시하며 실패로 자동 합치지 않는다.
