소단원 6.1

affordance와 mapping

눌러 보라는 모양만 있으면 실제로 눌렀을 때 무슨 일이 생길지도 알 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 행동 가능성은 사용 주체와 대상의 관계다.

  • 시각적 안내와 실제 동작은 다를 수 있다.

  • mapping은 조작과 결과 사이 대응이다.

학습 목표

  • 실제 가능성과 보이는 안내를 구별한다.

  • 공간·이름 대응으로 조작 결과를 설명한다.

  • 사용자가 공유하는 관례를 근거 없이 가정하지 않는다.

배치가 같다는 말에는 어느 방향에서 본다는 조건이 필요한가?

앞 본문은 A B / C D의 조명 위치와 보이는 조작판·실제 연결을 나누었다. 새 종이 모형의 기준 방향은 교사가 교실 앞에서 뒤를 바라보는 방향이다. 이 방향에서 앞줄 왼쪽 A와 오른쪽 B, 뒷줄 왼쪽 C와 오른쪽 D를 고정한다. 조작판의 네 위치는 왼쪽 위·오른쪽 위·왼쪽 아래·오른쪽 아래이며 기본 대응은 각각 A,B,C,D다. 방향과 이름을 함께 기록한 대응표다.

기본 조작판 전체를 180도 돌려 놓으면 같은 기준 방향에서 네 위치의 실제 연결은 D,C,B,A가 된다. 그러나 설치자가 라벨을 다시 A B / C D로 붙였다면 보이는 라벨과 실제 연결 네 개가 모두 다르다. 단추 수 네 개와 사각형 배치는 유지됐어도 같은 조명 대응은 아니다. 오른쪽 아래의 D 라벨을 누르면 실제 A가 켜진다. 실제 조명 실험이나 오조작률 측정은 수행하지 않는다.

이 모형의 수정안은 연결을 A B / C D로 되돌리고 명시한 기준 방향의 안내를 보존하거나, 현재 연결 D C / B A에 맞는 대상 이름을 정확히 표시하는 것이다. 두 안이 실제 사용자에게 똑같이 이해된다는 주장은 별도 관찰 없이는 하지 않는다. 기능 연결 검사, 라벨 대응 검사, 사용자가 의도한 대상을 찾는 검사는 서로 다른 근거다. 화면 버튼의 관례와 실제 행동 가능성도 같은 검사 하나로 합치지 않는다.

먼저 확인할 개념
  • 기준 배치와 실제 연결의 분리

    앞 본문의 반대 연결 사례를 전체 180도 회전과 기준 방향으로 확장한다.

  • 같은 의미의 일관된 표현

    앞 본문의 같은 의미/다른 동작 구별을 라벨·실제 대상·사용자 이해의 별도 검사로 연결한다.

가능한 행동과 알아보는 단서 구분하기

손에 맞는 손잡이는 잡거나 당기는 행동을 가능하게 할 수 있다. 화면의 버튼 그림은 사용자가 선택할 위치와 예상 동작을 알려 주는 시각적 단서다. 단서가 있다고 동작이 구현되는 것은 아니며 실제 선택 기능이 있어도 사용자가 알아보지 못할 수 있다.

Norman은 화면 아이콘·커서의 관례를 실제 물리적 affordance와 혼동하지 말라고 설명한다. 이 절에서는 동작 가능성, 이를 알아보는 정보, 공유된 관례를 나누어 기록한다. 색이나 모양이 모든 문화·연령의 사용자에게 같은 뜻이라는 주장은 실제 관찰 없이 하지 않는다.

조작과 결과를 한눈에 연결하기

자체 강의실 조명은 왼쪽 앞 A, 오른쪽 앞 B, 왼쪽 뒤 C, 오른쪽 뒤 D의 2×2배치다. 스위치를 같은2×2배치로 놓으면 공간 대응을 이용할 수 있다. 일렬 배치 [D,A,C,B]에서는 사용자가 이름표나 별도 그림을 찾아야 한다. 대응은 단순 버튼 수와 다른 정보다.

공간만으로 충분하다고 단정하지 않는다. 조작판 방향이 조명 배치를 보는 방향과 같은지, 이름표가 읽히는지 확인해야 한다. 시각적으로 같은2×2라도 좌우가 반대로 연결되면 기대와 다른 조명이 켜진다. 자체 종이 그림은 대응 후보의 차이를 보이며 실제 오조작률을 측정하지 않는다.

의도·동작·결과를 각각 적기

사용자가 원하는 것은 오른쪽 뒤를 밝히는 것이다. 기대하는 조작은 오른쪽 뒤 스위치이며 실제 결과도 D조명이어야 한다. 조작판의 단서가 D를 가리키지만 연결이 B라면 단서와 구현이 충돌한다. mapping 표를 만들어 기대·실제를 비교하면 문제를 찾기 쉽다.

디지털 과목 카드의 보기와 즐겨찾기도 같은 원칙을 따른다. 카드 전체가 이동하고 별 아이콘만 즐겨찾기라면 각 선택 영역과 설명이 구별되어야 한다. 어디든 눌러 보면 알 수 있다는 설계는 사용자의 시행착오에 기대는 것이다. 적절성은 실제 대상 사용자로 확인할 과제다.

모든 위치는 같은 교사 기준 방향에서 읽는다. 실제 연결 순열과 라벨 순열을 비교하며 사용자가 어떻게 이해했는지는 이 표에 관찰값으로 없다.

중간 과정을 따라가는 예제

2×2스위치가 A B / C D 조명과 같은 위치로 연결된다. 오른쪽 뒤를 밝히려면 무엇을 누르는가? 일렬 [D,A,C,B]에서는 몇 번째인가?

  1. 목표 위치 오른쪽 뒤는 D다.

  2. 같은 공간 배치에서는 오른쪽 뒤 스위치가 D와 연결된다.

  3. 일렬 배치에서는 목록 첫 항목이 D이므로 첫 번째다. 이름표 없이 순서만으로 공간 위치를 알 수 있다는 보장은 없다.

같은2×2에서는 오른쪽 뒤, 주어진 일렬 표에서는 첫 번째다. 두 경우의 동작 수가 같아도 알아내는 부담은 다를 수 있다.

조건을 바꾸어 비교하기

네 개가 모두 어긋나는 회전

전체 180도 회전 뒤 실제 연결은 D C / B A이고 라벨은 A B / C D다. 각 라벨의 결과와 일치 수를 구하라.

  1. A 라벨 위치는 D를, B 라벨은 C를 켠다. C 라벨은 B를, D 라벨은 A를 켠다.

  2. 어느 위치도 보이는 대상과 실제 대상이 같지 않아 일치는 영 개다.

  3. 네 단추 모두 기능을 수행한다는 사실과 라벨이 맞는다는 사실을 구별한다.

일치 수는 0/4이며 D 라벨 선택의 실제 결과는 A다.

비교할 점

동작 가능한 단추가 정확한 대상 안내까지 보장하지는 않는다.

라벨 수정과 익숙한 위치는 다른 조건

실제 연결 D C / B A를 유지하고 라벨도 D C / B A로 고쳤다. 라벨/연결 일치와 기존 오른쪽 아래=D 기대의 충족을 구별하라.

  1. 새 라벨 네 개는 실제 연결과 모두 일치한다.

  2. 오른쪽 아래는 A라 기존 위치 기대와는 다르다. D를 켜려면 왼쪽 위의 D 라벨을 선택한다.

  3. 새 대응의 이해와 기존 학습 전이는 실제 대상 사용자에게 확인할 과제로 남긴다.

라벨/연결은 4/4 일치하지만 기존 위치 기대는 유지되지 않는다.

비교할 점

정확한 이름 안내와 학습된 공간 관례를 하나의 점수로 합치지 않는다.

일관성과 feedback

저장 버튼을 눌렀는데 아무 변화가 없다면 다시 눌러야 할까?

준비 개념과 학습 목표

준비 개념

  • 피드백은 시스템 상태와 동작 결과를 사용자가 알게 하는 정보다.

  • 화면 표시와 서버의 실제 저장 상태는 다를 수 있다.

  • 일관성은 같은 의미에 같은 표현·동작을 사용하는 관계다.

학습 목표

  • 표현·동작의 일관성을 점검한다.

  • 진행 안내와 성공 안내를 구별한다.

  • 불확실한 완료 상태의 재시도 안내를 설계한다.

옛 수정본 저장 성공이 현재 편집 내용의 저장 성공인가?

앞 본문은 빠른 진행 안내와 확인된 완료를 구별했다. 새 메모 편집기는 내용과 수정본 번호를 함께 기록한다. 초기 서버 저장 수정본은 3이다. 사용자가 수정본 4를 만들고 요청 R로 그 복사본을 보낸다. 응답을 기다리는 동안 수정본 5를 계속 편집한다. R은 수정본 4를 정상 저장하고 응답에 요청 ID R과 저장 수정본 4를 담는다. 다른 저장 요청이나 서버 수정은 아직 없다고 가정한다.

R의 성공은 보낸 수정본 4의 저장 증거이지 현재 수정본 5의 저장 증거가 아니다. 편집 내용을 4로 되돌리지 않고 “수정본 4 저장됨, 현재 수정본 5는 미저장”이라고 안내한다. 이 자체 화면 정책의 정상 저장 상태는 현재 수정본 번호와 확인한 저장 수정본 번호가 같은 것이다. 수정본 번호는 실제 SDK나 파일 판본이 아닌 자체 식별 모형이다.

상태 문장을 시각적으로 띄우는 것만으로 모든 사용자에게 전달됐다고 인증하지 않는다. 초점 이동 없는 저장 안내라면 상태 정보의 대상·수정본·다음 행동이 보조 기술에서도 전달될 수 있게 설계해야 한다. 숫자 4만 독립적으로 알리는 것보다 무엇의 수정본 4인지 포함한 문장이 명확하다. 실제 DOM 역할·스크린 리더·브라우저를 시험하지 않으며 전체 WCAG 적합성도 이 종이 설계 하나로 선언하지 않는다.

먼저 확인할 개념
  • 진행·완료·불확실의 사건 근거

    앞 본문의 성공 응답 시점을 현재 편집 수정본과 요청에 실린 수정본의 차이로 확장한다.

  • 입력 보존과 다음 행동

    앞 본문의 오류 뒤 입력 보존을 새 편집 내용을 옛 응답으로 덮지 않는 정책에 연결한다.

같은 뜻을 같은 방식으로 표현하기

자체 앱은 즐겨찾기 추가를 모든 과목에서 같은 별 아이콘과 같은 라벨로 표현한다. 한 화면에서 별이 저장, 다른 화면에서 삭제라면 사용자는 이전 경험을 잘못 적용할 수 있다. 내부 일관성과 플랫폼의 익숙한 관례는 각각 점검할 대상이다.

모든 버튼을 무조건 같은 모양으로 만드는 것이 일관성은 아니다. 위험한 삭제와 일반 조회는 역할이 달라 차이가 필요할 수 있다. 같은 의미는 같게, 다른 의미는 구별되게 표현하면서 색 하나만으로 상태를 전달하지 않도록 텍스트·아이콘을 함께 고려한다.

진행과 결과를 다른 상태로 알리기

자체 메모 저장 흐름은 수정중→저장중→저장완료 또는 저장실패다. 누르자마자 버튼 반응과 저장중을 알리되 서버가 성공 응답을 주기 전에 완료라고 단정하지 않는다. 기다림이 길면 사용자가 현재 무엇을 기다리는지 알아야 한다.

네트워크 타임아웃은 서버 미저장과 같은 사실이 아니다. 서버가 저장한 뒤 응답만 유실되었을 수 있다. 이 경우 완료 여부 확인과 안전한 재시도 정책을 안내한다. 클라이언트 버튼 비활성화만으로 서버 중복 적용 문제까지 해결했다고 주장하지 않는다.

표시를 실제 사건에 연결하기

자체 사건열은 t0버튼선택,t1전송시작,t2서버저장,t3성공응답수신이다. 화면은 t0/t1에 반응·저장중, t3에 저장완료를 보여 준다. t2는 서버 사건으로 클라이언트가 아직 직접 아는 것은 아니다. 알아낸 범위에 맞춰 표현한다.

오류 안내도 고칠 수 있는 다음 행동에 연결한다. 저장 실패라고 알려 주면서 입력을 지우면 사용자가 작업을 다시 만들어야 한다. 입력 보존·상태 확인·재시도 선택을 설계하고 실제 지연·접근성 전달은 사용자와 장비에서 검증할 과제로 남긴다.

오류예방·복구

잘못 누른 삭제를 알리는 메시지만 있으면 충분할까?

준비 개념과 학습 목표

준비 개념

  • slip은 주의가 흐트러져 의도와 다른 조작을 하는 오류다.

  • mistake는 목표나 시스템 이해가 잘못되어 선택하는 오류다.

  • 복구는 원하는 상태로 돌아갈 수 있는 과정이다.

학습 목표

  • 예방·진단·복구를 단계별로 설계한다.

  • 취소와 되돌리기의 적용 시점을 구별한다.

  • 위험과 실제 실행 결과에 맞는 안내를 작성한다.

삭제 성공 수와 되돌릴 수 있는 수가 같은가?

앞 본문의 삭제 전 취소와 삭제 뒤 복원을 유지하되 새 목록은 고유 ID로 대상을 구별한다. 원래 A의 ID는 1이고 이름은 보고서다. B의 ID는 2이고 이름은 메모이며 C의 ID는 3이고 이름은 그림이다. 일괄 삭제 결과 A와 C만 삭제 성공했고 B는 거절되어 남았다. A의 내용은 휴지통에 보존되지만 C의 내용은 이후 제거되어 복원할 수 없다는 별도 상태를 둔다. 실제 파일을 삭제하거나 제거하지 않은 종이 결과다.

원래 위치를 복원하려는 시점에 목록에는 ID가 9이고 이름이 보고서인 새 항목도 있다. 이름은 같지만 원래 A와 다른 객체다. 자체 복원 정책은 원래 ID와 보존 내용을 확인하고 같은 위치·이름의 다른 항목을 조용히 덮어쓰지 않는 것이다. A에는 다른 이름을 제안하고 사용자가 선택하거나, 충돌을 안내하고 기존 항목을 보존하는 경로를 제공한다. C에는 복원 내용이 없어 불가능을 안내한다. B는 삭제되지 않았으므로 복원 대상이 아니다.

세 요청 중 삭제 성공은 두 개이지만 성공한 두 개 중 내용이 보존된 복원 후보는 하나다. 이 상태의 복원 가능 비율은 삭제 성공을 분모로 하면 1/2=50%, 전체 요청을 분모로 하면 1/3이다. 두 지표는 같은 요구를 측정하지 않는다. 아직 A의 이름 충돌 해결과 실제 복원이 수행되지 않았으므로 복원 완료 한 개라고 보고하지 않는다. 예방 안내·실제 결과·복구 후보·최종 복구를 다른 단계로 보존한다.

먼저 확인할 개념
  • 취소·복원과 보존 내용의 전제

    앞 본문의 B 복원 전제를 부분 삭제·내용 제거·이름 충돌의 새 조건으로 확장한다.

  • 표시와 실제 결과의 대응

    앞 본문의 저장 사실에 근거한 안내를 부분 성공과 복구 미완료 상태에 적용한다.

오류를 내기 어려운 조건 만들기

자체 폴더 목록에서 삭제 버튼을 이름 바로 옆에 두면 조회하려다 잘못 누를 수 있다. 위험 동작을 구별하고 대상 이름을 명시해 오조작을 줄이는 설계를 고려한다. 모든 동작에 똑같은 확인창을 반복하면 사용자가 내용 없이 승인할 수 있어 위험에 맞게 사용한다.

숫자 범위·필수 입력처럼 알려진 조건은 제출 전에 확인하고 고칠 위치를 알려 준다. 예방은 모든 값을 금지하는 것이 아니라 필요한 기능을 유지하면서 오류 가능 조건을 줄이는 일이다. 실제 효과를 측정하지 않았으므로 오조작률이 몇 퍼센트 감소했다고 기록하지 않는다.

취소와 되돌리기의 차이 알리기

자체 삭제 전 확인창의 취소는 아직 일어나지 않은 삭제를 실행하지 않는 선택이다. 삭제 후 되돌리기는 이미 변경한 상태를 복원하는 동작이다. 이 모형은 삭제 파일을 휴지통에 보관해 복원 가능하다고 가정한다. 실제 영구 삭제나 외부 전송은 같은 복원 약속을 할 수 없다.

되돌리기 기간·복원 위치·충돌 조건도 알려야 한다. 같은 이름의 새 파일이 생겼을 때 조용히 덮어쓰는 것은 또 다른 손실이 될 수 있다. 원고 활동은 고유 ID와 원래 위치를 기억하는 단순 목록이며 실제 파일시스템 복원 프로그램이 아니다.

오류123 대신 어느 항목이 어떤 조건에 맞지 않는지 사용자 언어로 알려 준다. 자체 학점6이면 “학점은1~5 정수로 입력해 주세요”라고 수정 방법을 준다. 사용자가 입력한 나머지 내용은 가능한 한 보존하고 원인을 고친 뒤 다시 시도할 길을 제공한다.

서버에서 일부 변경만 일어났다면 모두 실패했다고 표시하지 않는다. 무엇이 완료되고 무엇이 남았는지 사실에 맞춰 알려야 한다. 개인정보·비밀 내부정보를 오류문구에 넣는 것과 사용자가 이해할 설명은 다르다. 예방·진단·복구 각각의 책임을 표에 기록한다.

  2. A는 내용 보존과 이름 충돌, C는 내용 제거로 복원 불가임을 따로 안내한다. 이미 성공한 A/C를 새 삭제 요청으로 반복하라고 일괄 안내하지 않는다.

  2. 사용자 선택 뒤 복원을 시도하고 실제 성공을 확인할 때만 복원 완료를 표시한다. 현재는 계획·미수행으로 남긴다.

종이 조작판의 기준 방향은 교사가 교실 앞에서 뒤를 바라보는 방향이다. 라벨은 A B / C D이나 실제 연결은 180도 회전의 D C / B A다. 별도 메모는 서버 저장 수정본 3에서 수정본 4를 요청 R로 보낸 뒤 현재 수정본 5를 편집했고 R이 4 저장 성공을 확인한다. 별도 일괄 삭제의 원래 A/B/C는 ID 1/2/3이며 A 이름은 보고서다. 같은 위치에서 라벨과 연결을 비교한다. 응답이 확인한 수정본과 현재 편집 수정본을 나눈다.

힌트 2

삭제 성공 수와 내용 보존 후보 수를 구별하며 이름만으로 ID 9를 덮지 않는다.

풀이와 답 확인

  1. D 라벨은 오른쪽 아래이고 실제 연결은 A다. 네 라벨 모두 불일치하여 일치는 0/4다.

  2. 현재 수정본은 5를 보존하고 확인 저장 번호는 4다. 수정본 4 저장됨과 현재 5 미저장을 함께 안내한다.

  3. 삭제 성공은 A/C 두 개, 거절은 B다. 내용 보존 후보는 A 하나여서 삭제 성공 기준 후보 비율은 1/2=50%다.

  4. A의 이름 충돌을 안내하고 다른 비어 있는 이름을 사용자에게 제안하거나 기존 ID 9를 보존한 채 중단한다. 아직 복원 완료라고 보고하지 않는다.

D 라벨의 실제 결과는 A이고 라벨과 연결의 일치 수는 0/4다. 현재 편집 수정본 5를 보존하고 확인한 저장 수정본은 4로 기록하며 현재 편집 내용은 미저장이라고 안내한다. 삭제에 성공한 두 항목 중 내용이 보존된 복원 후보는 한 항목이므로 후보 비율은 50%다. 새 ID 9의 자료를 보존하는 이름 충돌 해결을 계획한다. 실제 복원은 미수행이다.
