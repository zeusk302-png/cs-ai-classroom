소단원 7.1

분류·label·navigation

같은 강의가 영상과 글로 있어도 학습자는 두 메뉴를 오가야 할까?

준비 개념과 학습 목표

준비 개념

  • 집합과 관계
  • 경로와 이름
  • IA는 자료의 조직·관계·명칭을 정하는 정보구조, UI는 사용자가 보고 조작하는 화면이다.

학습 목표

  • 콘텐츠 분류와 화면 탐색 장치를 구별한다.
  • 대상 학습자의 말로 label 과 연결을 설계한다.

정보구조는 콘텐츠 사이의 관계다

정보구조는 무엇을 제공하고 어떻게 묶고 이름 붙일지 정하는 바탕이다. navigation 은 그 관계를 사용자가 따라갈 메뉴·링크·필터 같은 화면 장치다. 보기 좋은 메뉴를 먼저 그려도 내용의 위치가 모호하면 필요한 강의를 찾기 어렵다.

우리 콘텐츠 목록은 변수 글 A, 변수 영상 B, 반복문 글 C, 반복문 영상 D 다. 형식 기준과 주제 기준은 각각 가능한 분류 축이다. 어느 축이 목표에 맞는지는 실제 학습자의 과제와 용어를 확인해야 하며 종이 설계만으로 편리함을 입증하지 않는다.

label 은 다음 내용의 약속이다

label 은 메뉴에 붙이는 이름이다. 재미있는 이름이라도 무엇을 담는지 예측할 수 있어야 한다. 학습자가 변수를 찾는데 메뉴가 보물상자·성장의 숲으로만 되어 있으면 설명이나 보조 이름을 검토한다. 한 용어를 서로 다른 의미로 쓰는지도 확인한다.

한 콘텐츠는 고유 ID 로 관리하며 주제와 형식 같은 여러 속성을 가질 수 있다. 여러 탐색 경로가 같은 ID 를 가리키는 것은 본문을 복제하는 것과 다르다. 제목이 같다는 이유만으로 두 자료를 하나라고 판단하지 않고 내용·버전·대상 관계를 기록한다.

현재 위치와 다음 길을 보여 준다

전체 메뉴는 큰 영역, 지역 메뉴는 현재 영역의 하위 내용, breadcrumbs 는 현재 페이지가 놓인 경로를 보여 줄 수 있다. 선수 개념과 관련 자료 링크는 다른 관계를 드러낸다. 모든 관계를 한 계층에 억지로 넣을 필요는 없다.

우리 주제 우선 경로는 홈→프로그래밍→변수→자료다. 직접 링크로 들어온 학습자도 변수 주제와 다른 형식의 자료를 볼 수 있게 설계한다. 경로 깊이만 최소화하려고 모든 항목을 한 메뉴에 넣으면 선택 항목 수가 커지므로 과제별 확인이 필요하다.

중간 과정을 따라가는 예제

A/B/C/D 네 자료를 형식 우선과 주제 우선으로 묶고 변수 공부에서 글과 영상에 접근할 경로를 적어라.

  1. 형식 우선은 글={A,C}, 영상={B,D}다.
  2. 주제 우선은 변수={A,B}, 반복문={C,D}다.
  3. 변수 페이지가 A/B 의 두 형식 링크를 제공하면 주제를 정한 뒤 형식을 고를 수 있다. 각각은 동일한 고유 ID 를 참조한다.

분류 축이 달라질 뿐 네 콘텐츠는 모두 보존한다. 주제 경로가 실제 더 쉬운지는 사용자 과제로 확인해야 한다.

소단원 7.2

검색과 발견

알고 있는 반복문을 찾는 것과 처음 보는 재미있는 주제를 발견하는 것은 같은 일일까?

준비 개념과 학습 목표

준비 개념

  • 문자열과 목록
  • 비율
  • tree test는 화면 장식 없이 범주 이름을 따라 목표를 찾는 조사다.

학습 목표

  • 알고 찾기와 새 정보 발견을 구별한다.
  • 검색 결과와 탐색 성공 지표의 범위를 계산한다.

찾는 목표가 있거나 아직 없거나

findability 는 있다고 예상하는 자료를 찾는 성질이고 discoverability 는 몰랐던 자료나 기능을 접하는 성질이다. 검색어를 아는 학습자는 검색을 쓰고 아직 용어를 모르는 학습자는 주제 소개·예제·관련 링크로 새 길을 발견할 수 있다.

검색과 메뉴는 서로 보완할 수 있다. 검색 결과가 있더라도 제목과 요약이 모호하면 어느 자료를 눌러야 할지 모른다. 우리 자체 예시는 반복문이라는 정해진 과제와 관련 자료 둘러보기라는 별도 과제를 나누며 실제 행동 자료는 수집하지 않았다.

검색 결과의 포함과 누락을 센다

자체 결과 집합의 정밀도는 반환한 항목 중 관련 항목의 비율, 재현율은 실제 관련 항목 중 반환한 비율로 정의한다. 관련성 정답 집합과 집계 단위를 미리 정한다. 반환 0 이나 관련 0 이면 분모 0 의 처리 정책도 별도로 필요하다.

이 비율은 결과 목록의 포함 여부를 본다. 첫 결과가 틀렸는지, 원하는 형식인지, 학습자가 이해했는지는 자동 평가하지 않는다. 검색 질의의 동의어·철자·필터·결과 요약과 순위는 별도의 설계 판단이며 모든 질의에 같은 정답이 있는 것도 아니다.

구조와 화면을 나누어 조사한다

tree test 는 꾸민 화면 없이 범주 이름과 구조를 따라 목표에 도달하는지 볼 수 있다. 성공했어도 되돌아갔는지에 따라 직접 성공과 간접 성공을 구별한다. UI 과제 관찰은 메뉴가 보이는지와 실제 조작도 확인한다.

좋은 구조 결과만으로 화면 성공을 보장하거나 검색 사용률 하나로 구조 실패를 확정하지 않는다. 검색을 선호할 수도 있기 때문이다. 과제·경로·첫 선택·오류·완료를 함께 기록하고 가상 표의 퍼센트를 실제 학생 성공률이라고 바꾸지 않는다.

중간 과정을 따라가는 예제

콘텐츠 A..F 중 관련 정답은 A/C/E 다. 검색 반환 A/B/C/D 의 정밀도·재현율을 구하고 가상 tree test 8 건 중 직접 5/간접 2/실패 1 을 집계하라.

  1. 반환 4 중 관련 A/C 두 개라 정밀도 2/4=50%다.
  2. 관련 3 중 두 개를 찾으므로 재현율 2/3≈66.7%다. E 는 누락이고 B/D 는 이번 과제에서 무관하다.
  3. 전체 성공은(5+2)/8=87.5%, 직접 성공은 5/8=62.5%다. 간접 2 건도 성공이나 직접으로 세지 않는다.

검색 포함 지표와 경로 성공 지표는 다른 질문이다. 표는 계산을 위한 가상 데이터다.

종이와 본문으로 직접 해보기

검색 반환을 A/C/E/F 로 바꾸면 두 비율은? 실패 1 건을 간접 성공으로 바꾸면 tree 지표는?

힌트 보기

관련 집합은 그대로 두고 분자와 분모를 다시 센다.

풀이 보기

관련 3/반환 4 라 정밀도 75%, 재현율 100%다. tree 전체 성공 8/8=100%, 직접은 5/8=62.5%로 그대로다.

오해와 반례

재현율 100%이면 누구나 가장 알맞은 자료를 빨리 찾는다.

A..F 전부 반환해도 재현율 100%지만 정밀도 3/6=50%다. 순위·요약·화면과 목표 이해는 별도로 확인한다.

소단원 7.3

카드소팅 입문

변수와 함수가 같은 묶음이라고 느끼는 사람은 배열과도 꼭 같이 묶을까?

준비 개념과 학습 목표

준비 개념

  • 집합과 빈도
  • 가상 데이터와 실제 조사 구별
  • 유사도는 여기서 같은 그룹에 배치된 카드쌍의 비율이라는 자체 지표다.

학습 목표

  • open/closed 카드소팅을 구별한다.
  • 공동 묶임 빈도와 이유 및 후속 검증의 한계를 설명한다.

무엇을 어떻게 묶는지 묻는다

카드소팅은 콘텐츠 이름이나 설명을 카드로 주고 참여자가 묶는 방식과 이유를 알아보는 방법이다. open 방식은 참여자가 묶음과 이름을 만들고 closed 방식은 준비된 범주에 배치한다. 어떤 방식인지 먼저 선언해야 해석이 맞는다.

카드는 내용이 이해될 만큼 분명하되 원하는 범주를 답처럼 숨겨 넣지 않는다. 모르는 항목은 억지로 아무 곳에 넣기보다 따로 두고 이유를 묻는다. 카드 묶음은 메뉴를 클릭하여 자료에 도달한 행동과 다르다.

쌍별 빈도를 직접 센다

우리 계산에서는 네 장 A 변수/B 함수/C 배열/D 프로세스를 사용한다. 각 가상 참여자가 각 카드를 한 그룹에 정확히 한 번 배치했다고 가정한다. 쌍이 같은 그룹에 놓인 횟수/유효 참여자 4 로 유사도를 정의한다.

그룹 이름이 달라도 같은 카드쌍의 공동 묶임을 셀 수 있다. 반대로 같은 이름을 썼다고 구성 카드가 같다는 뜻은 아니다. 쌍별 높은 빈도가 항상 추이적인 큰 그룹을 만드는 것은 아니므로 임의 기준선으로 모든 연결을 합치기 전에 원 자료를 본다.

빈도와 설명을 함께 읽는다

가상 표의 숫자는 의견 분포를 드러내지만 왜 그렇게 묶었는지는 말해 주지 않는다. 단어를 모른 경우, 특정 활동 기준인 경우, 두 범주에 속한다고 생각한 경우를 이유 질문으로 구별할 수 있다. 참여자가 붙인 이름이 최종 메뉴 이름으로 적합한지도 별도 검토한다.

몇 명의 종이 예로 전 세계 학습자의 선호를 확정하지 않는다. 대상 언어와 준비개념을 고려한 실제 조사 및 이후 tree test·사용자 과제를 계획한다. 이 단원에는 실제 참여자도 동의 절차도 수행 결과도 없으며 가상 계산만 있다.

중간 과정을 따라가는 예제

P1={AB},{C},{D}; P2={AB},{CD}; P3={ABC},{D}; P4={A},{BC},{D}다. AB/AC/BC/CD 공동 묶임 비율을 구하라.

  1. AB 는 P1/P2/P3 으로 3/4=75%다.
  2. AC 는 P3 만으로 1/4=25%다. BC 는 P3/P4 로 2/4=50%다.
  3. CD 는 P2 만으로 1/4=25%다. 같은 그룹 표기를 쌍별로 전부 풀어 세었다.

AB75%, AC25%, BC50%, CD25%다. 50%이상 연결이라는 자체 규칙에서는 AB 와 BC 가 연결돼도 AC 는 기준 미만이다.

종이와 본문으로 직접 해보기

P4 를 {ABC},{D}로 바꾸면 AB/AC/BC 는? closed sort 에서 범주를 정해 준 것과 무엇이 다른가?

힌트 보기

새 공동쌍은 AB/AC 이고 BC 는 원래도 함께였다.

풀이 보기

AB4/4=100%, AC2/4=50%, BC2/4=50%다. open 에서 집단과 이름을 직접 만든다는 계약과 closed 의 주어진 범주 배치는 다르다.

오해와 반례

카드소팅의 가장 흔한 그룹이 최종 메뉴이며 그 메뉴의 검색 성공도 증명한다.

빈도와 이유는 설계 근거다. 실제 경로·화면·용어와 목표 도달은 후속 과제로 확인하며 같은 묶임도 모든 쌍의 관계를 완전히 같게 만들지 않는다.
