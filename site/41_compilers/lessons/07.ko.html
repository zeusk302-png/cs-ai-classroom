소단원 7.1

타입 규칙·변환·서브타입

값을 바꾸는 변환과 같은 값을 더 넓은 타입으로 보는 것은 같을까?

준비 개념과 학습 목표

준비 개념

  • 타입은 어떤 값과 연산을 허용하는지 표현한다.

  • Γ는 변수 이름을 타입에 대응시키는 환경이다.

학습 목표

  • 간단한 타입 판단의 전제를 구성한다.

  • 수치 변환과 서브타입 사용을 구별한다.

두 분기의 타입을 합치는 일과 숫자를 변환하는 일은 같을까?

불변 record의 이름 기반 타입 R={id:Int,pet:Cat}와 S={id:Int,pet:Animal,tag:Bool}를 새로 둔다. Cat <: Animal만 있으며 Int와 Bool 사이 관계나 Int <: Real은 없다. 필요한 필드가 모두 있고 그 필드 타입이 허용 관계를 만족하면 불변 record를 더 넓은 타입 자리에 쓸 수 있다. R과 S의 공통 요구 U={id:Int,pet:Animal}는 두 값 모두 받아들인다. S가 필드 수는 더 많아도 R을 대체하지는 못한다. S.pet이 Animal이어서 Cat 약속을 못 하기 때문이다.

새 조건식 규칙은 Bool 조건과 두 분기의 공통 상위 타입을 요구한다. 위 두 타입에서 U는 각 공통 필드의 가장 정밀한 허용 타입으로 만든 join이다. 조건이 true라는 상수라도 이 보수적 규칙은 두 분기를 모두 검사한다. 숫자 분기의 별도 정책은 Int 쪽에 widen을 삽입한다. 따라서 if true then 2 else 2.9는 Real이며 정한 수학적 변환에서 선택된 값은 2.0이다. 이것을 Int <: Real의 증명으로 쓰지 않는다. 실제 부동소수점이나 표현 범위는 모형에 없다.

함수 대체는 입력과 출력의 방향을 따로 확인한다. A=Animal→Cat은 B=Cat→Animal 자리에서 허용되지만 B를 A 자리에서 쓰면 Cat 아닌 Animal을 받는 약속과 Cat 반환 약속이 모두 깨질 수 있다. 별도 읽고 쓰는 Cell<Cat>을 Cell<Animal> 별칭으로 허용하면 Cat 아닌 Animal인 dog를 써서 원래 Cat 읽기 계약을 깨뜨린다. 따라서 이 작은 칸 모형은 불변 record의 공변 규칙을 쓰기 가능한 칸에 적용하지 않는다.

  • 값 변환과 subsumption의 구별

    분기 join과 숫자 widen은 서로 다른 근거를 요구한다.

  • signature와 정적 안전의 범위

    호출자가 요구하는 인자·반환 약속과 타입 성공의 한계를 대조한다.

판단은 규칙의 나무다

Γ ⊢ e:T는 환경 Γ에서 식 e가 타입 T를 가진다는 판단이다. 규칙의 위쪽은 필요한 전제이고 아래쪽은 결론이다. 예를 들어 자체 언어에서 두 Int를 더하면 Int이고 두 Real을 더하면 Real이다. Bool을 숫자로 보는 규칙은 없다.

상수의 타입, 변수의 환경 조회, 작은 식의 타입을 먼저 결정한 뒤 큰 식의 규칙을 적용한다. 타입 검사는 일반적으로 프로그램을 실제 실행하여 답을 관찰하는 과정이 아니다. 어떤 실행 경로를 택할지 모르더라도 허용해야 할 모든 구문을 규칙으로 검사한다.

변환은 명시한 연산이다

이 모형에서 Int와 Real은 별도 기본 타입이며 Int <: Real 관계를 정의하지 않는다. 대신 widen:Int→Real 변환을 허용한다. 혼합 덧셈에서는 검사기가 Int 쪽에 widen을 삽입하여 두 피연산자를 Real로 맞춘다. 이는 언어가 정한 변환 정책이지 모든 언어의 자동 규칙이 아니다.

Real→Int의 narrow는 명시적으로만 허용하고 이 교육 모형에서는 0 방향으로 잘라 소수를 버린다. 예를 들어 narrow(2.9)=2다. 실제 기계의 표현 범위·부동소수점 반올림·overflow 조건은 별도이므로 이 수학적 모형을 실제 ABI의 정확성으로 일반화하지 않는다.

서브타입은 필요한 약속을 유지한다

Cat <: Animal인 불변 객체 모형에서 Cat 값은 Animal을 요구하는 자리에 쓸 수 있다. Animal이 제공하는 연산을 Cat도 제공한다는 조건이 필요하며 반대 사용은 보장되지 않는다. 값 변환을 실행하는 widen과 타입 사용 권한을 넓히는 subsumption을 구별한다.

함수에서 입력은 반대 방향, 출력은 같은 방향으로 관계를 검사한다. Animal을 받아 Cat을 내는 함수는 Cat을 받아 Animal을 내는 자리에서 안전하게 사용할 수 있다. 더 넓은 입력을 받아들이고 더 강한 출력 약속을 하기 때문이다. 변경 가능한 자료 구조에는 다른 제약이 있어 이 불변 모형의 폭 서브타입 규칙을 무조건 옮기지 않는다.

이 가변 칸 모형에서는 거절

앞 세 행은 불변 필드 선택, 함수 행은 호출 권한, 마지막 행은 같은 저장 칸의 쓰기를 비교한다. 숫자 값과 타입 관계는 다른 열의 정보다.

중간 과정을 따라가는 예제

Γ={x:Int,y:Real,p:Bool}다. 혼합 덧셈은 Int에 widen을 삽입하며 Int+Int→Int, Real+Real→Real만 있다. (x+2)+y와 p+1의 타입 판단을 적는다. Cat <: Animal에서 f:Animal→Cat을 Cat→Animal 자리에 놓을 수 있는지도 판단한다.

  1. x:Int와 2:Int를 합쳐 x+2:Int를 도출한다. 환경 조회와 정수 상수 규칙이 두 전제다.

  2. y:Real과 더할 때 widen(x+2):Real을 삽입한다. 전체는 widen(x+2)+y:Real이다.

  3. p:Bool과 1:Int에는 허용된 숫자 덧셈 규칙이나 Bool 변환이 없어 p+1을 거절한다.

  4. Cat 입력은 Animal을 받는 f에 넣을 수 있고 f의 Cat 출력은 Animal 자리로 전달할 수 있다. 따라서 이 함수 서브타입 사용은 허용한다.

혼합 식은 Real, Bool 덧셈은 오류다. Animal→Cat은 Cat→Animal의 대체 함수로 사용할 수 있다.

조건을 바꾸어 비교하기

필드 수가 많아도 좁은 약속은 얻지 못한다

R/S의 U 대입과 S의 R 대입을 비교하라.

  1. U의 id는 둘 다 Int이고 pet은 R의 Cat 또는 S의 Animal을 Animal로 읽는다.

  2. R을 요구하는 코드는 pet에 Cat 전용 연산을 쓸 수 있지만 S의 pet은 Cat이라고 보장되지 않는다.

두 U 대입은 허용하고 S→R은 거절한다.

비교할 점

필드 개수만 비교하는 폭 규칙과 공통 필드의 깊이 조건을 비교한다.

가변 별칭의 읽기 약속을 깨는 쓰기

Cell<Cat> c에 Cat이 있고 같은 칸을 Cell<Animal> a로 허용한다고 가정한다. a에 dog:Animal을 쓰면?

  1. a의 Animal 쓰기는 그 별칭 계약만 보면 허용된다.

  2. 같은 저장 칸을 c로 읽으면 dog가 나오지만 c는 Cat이라고 약속했다.

읽고 쓰는 같은 칸에서 단순 공변 대체는 안전하지 않다. 실제 프로그램 실행이 아니라 반례 모형이다.

비교할 점

불변 record의 읽기만 가능한 필드와 동일 객체에 쓰는 별칭을 구별한다.

종이와 본문으로 직접 해보기

별도 g:Cat→Animal을 Animal→Cat 자리에 넣으면 어떤 문제가 생기는가? narrow(−2.9)와 Int 변수에 2.9를 자동 대입하는 경우도 판단한다.

힌트 보기

호출자는 Animal 전체를 넣을 권리가 있고 Cat 출력을 기대한다. 변환은 명시된 방향만 허용한다.

풀이 보기

g는 Cat이 아닌 Animal 입력을 받을 수 없고 출력도 Cat이라고 보장하지 않아 대체 불가다. 정한 0 방향 절단에서 narrow(−2.9)=−2다. 명시 narrow 없이 Int 변수에 Real 2.9를 넣는 것은 이 모형에서 오류다.

오해와 반례

Int를 Real로 바꾸므로 Int는 반드시 Real의 서브타입이다.

이 언어는 두 기본 타입 사이의 widen 연산을 정의했지만 서브타입 관계는 정의하지 않았다. 값 변환의 존재만으로 subsumption을 만들 수 없다.

연습 1 · 값과 상태 예측

if false then R값 else S값의 타입과 if true then 2 else 2.9의 타입/선택 값을 구하라. 두 분기는 모두 검사한다.

힌트 1

R/S 공통 필드의 타입을 확인한다.

힌트 2

숫자 혼합은 관계가 아니라 widen 정책이다.

풀이와 답 확인

  1. record 조건식 타입은 U이며 false이면 S값이 선택된다.

  2. 숫자 조건식은 Int 쪽 widen 후 Real이고 true이면 2.0을 선택한다.

선택 분기와 정적 전체 타입을 별도로 적는다.

흔한 오답에서 다시 생각하기

상수 조건이므로 전체 타입은 항상 선택 분기의 원래 타입이다.

이 규칙은 두 분기를 검사하고 join 또는 widen을 적용한다. 상수 접기는 별도 분석이다.

연습 2 · 오류 찾아 고치기

A=Animal→Cat을 B=Cat→Animal 자리에 쓰는 방향이 위험하고 반대가 안전하다는 주장을 고쳐라.

힌트 1

호출자가 줄 수 있는 입력을 먼저 적는다.

힌트 2

결과를 받을 쪽의 약속을 확인한다.

풀이와 답 확인

  1. B 자리는 Cat만 주므로 A가 받는 Animal 범위에 들어간다. A 결과 Cat은 Animal로 받을 수 있다.

  2. 반대 자리는 Cat 아닌 Animal도 줄 수 있고 Cat 결과를 요구해 B가 양쪽 약속을 못 한다.

A→B는 허용, B→A는 거절한다.

연습 3 · 직접 만들어 보기

R/S의 공통 상위 타입 두 개 U와 V를 쓰고 어느 것이 더 정밀한지 설명하라. 새 필드는 만들지 않는다.

힌트 1

공통 id와 pet을 모두 남기는 방법을 쓴다.

힌트 2

pet을 버린 공통 타입도 가능하다.

풀이와 답 확인

  1. U={id:Int,pet:Animal}를 두 값이 만족한다. V={id:Int}도 만족한다.

  2. U는 V의 필드를 포함하므로 U <: V이고 U가 더 많은 읽기 정보를 보존한다.

이 명시한 작은 타입 집합에서 U가 더 정밀하다.

R에 tag가 없어서 그 약속은 공통 상위 타입이 아니다.

dog를 쓰는 권한을 제거하고 Cell<Cat>을 읽기 전용 Read<Animal>로만 보이면 위 반례가 유지되는가? 소유 c의 Cat 쓰기는 계속 허용한다.

한 단계 더

불변 record {name:String,score:Int}를 {name:String} 자리에서 쓰는 폭 서브타입을 생각한다. 이어 name을 쓰는 코드가 요구하는 필드가 남아 있음을 확인한다. 같은 관계를 변경 가능한 필드에 옮길 때 쓰기 동작이 새 위험을 만드는 이유를 따로 설명한다.

소단원 7.2

식·문장·함수 검사

return의 값만 맞으면 함수 안의 모든 문장도 올바를까?

준비 개념과 학습 목표

준비 개념

  • 식은 값을 내고 문장은 상태/제어 흐름을 바꾼다.

  • 블록의 변수 선언은 유효 범위를 가진다.

학습 목표

  • 환경을 전달하며 식·대입·조건·반환을 검사한다.

  • 함수 signature와 몸체 및 모든 경로 반환을 구별한다.

정상 타입의 return이 하나라도 있으면 반환 요약이 참일까?

기본 Int/Bool만 사용하는 별도 문장 언어를 유지한다. must(s)는 기본의 반환 검사 요약이다. 정상적으로 끝까지 내려가는 fall-through 경로를 배제하는 검사이며 모든 실행이 유한 시간에 종료한다는 증명이 아니다. return은 true, 단순 대입은 false, 순차 s1;s2는 must(s1) OR must(s2), if-else는 양쪽 must의 AND, else 없는 if와 일반 while은 false다. 이름·조건·대입·반환 식 타입 검사는 요약과 독립적으로 모든 문장을 방문한다. 따라서 return 1; z:Int=true;는 must가 true여도 뒤 선언의 타입 오류가 남는다. 예를 들어 x:Int가 선언된 환경에서 while(true){x=x+1;} 뒤 return 1이 있으면 이 OR 요약은 true지만 반복문에서 영원히 머물 수 있다. 이때 반환 누락 검사와 종료성은 서로 다른 장부다.

새 f(p:Bool):Int 몸체 F1=if(p){return 1;}else{x:Int=2;}는 true AND false라 반환 요약 false다. F2는 F1 뒤 return 3을 붙여 false OR true라 true다. F3=while(true){return 1;}은 실제 종이 실행에서 첫 반복이 반환하지만 기본 보수 규칙은 while을 false로 둔다. 이 거절이 실제 반환 부재의 증명은 아니다. 반대로 타입 검사 통과만으로 함수 종료나 사용 목적까지 보장하지 않는다.

범위와 반환 문맥도 별도로 전달한다. g(x:Int):Int의 { {x:Bool=true; if(x){x=false;}}; return x+1;}에서 안쪽 x는 Bool이고 밖 return의 x는 Int다. 안쪽 블록을 나올 때 반환 요구 Int가 Bool로 바뀌는 것도 아니다. 환경은 이름의 타입, 함수 반환 문맥은 return의 요구 타입을 보관한다. 이 단원에는 예외·break·continue가 없으며 OR 요약을 그런 제어 흐름이 있는 언어에 그대로 일반화하지 않는다.

먼저 확인할 개념
  • 반환 식의 타입과 모든 경로 반환

    must 요약과 식/문장 검사를 별도 장부로 만든다.

  • 안쪽 선언과 범위 복원

    같은 철자의 서로 다른 선언을 구별해 안쪽 Bool과 바깥 Int를 연결한다.

식에서 문장으로 규칙을 이어 간다

이 단원의 별도 단순 언어는 Int와 Bool만 사용하며 자동 변환은 없다. Int+Int→Int, Int<Int→Bool이다. 대입은 왼쪽에 선언된 변수와 오른쪽 식의 타입이 같아야 하고 if/while의 조건은 Bool이어야 한다. 실제 값이 0인지와 Bool 타입 여부를 혼동하지 않는다.

함수 호출은 이름의 signature, 인자 개수, 각 인자의 타입을 확인하고 반환 타입을 식의 타입으로 쓴다. 함수 몸체에서 return e는 선언된 반환 타입과 e의 타입을 맞춘다. 먼저 signature를 등록하면 함수 몸체가 자신이나 뒤에서 정의할 함수를 참조하는 검사를 구성할 수 있다.

범위와 반환 문맥을 전달한다

블록에 들어갈 때 환경을 확장하고 나올 때 이전 환경을 복원한다. 같은 이름이 안쪽에서 새로 선언되면 가장 가까운 선언을 조회하는 자체 shadowing 규칙을 사용한다. 이 모형은 같은 블록의 중복 선언을 거절한다.

타입이 있는 return이 발견되었다는 사실과 모든 실행 경로가 반환한다는 사실은 별도다. 이 단순 검사에서 return은 반드시 반환, 순차 문장은 앞/뒤에서 반드시 반환함이 보장되면 반환, if-else는 양쪽이 모두 반드시 반환할 때만 반환으로 분류한다. 일반 while은 종료/실행 여부를 증명하지 않아 반환 보장으로 세지 않는다.

정적 안전의 범위를 밝힌다

규칙에 맞는 타입은 정한 종류의 불일치를 배제하려는 도구다. 계산 결과가 사용자의 목표와 맞는지, 시스템 자원이 충분한지, 입력 자료가 적절한지까지 모두 보장하지는 않는다. 여기서는 검사 규칙의 종이 적용만 수행한다.

진행성과 타입 보존 같은 정리는 해당 언어의 구문·평가 규칙·타입 규칙 전체를 대상으로 증명한다. 실제 언어에서 예외·포인터·overflow 등을 추가하면 다시 조건을 세워야 한다. 단순 예제 몇 개를 통과시켜 언어 전체의 soundness를 증명했다고 말할 수 없다.

중간 과정을 따라가는 예제

max(a:Int,b:Int):Int의 몸체가 if(a<b){return b;}else{return a;}다. 또 sum(x:Int):Int의 몸체가 {y:Int=x+1; return y;}다. signature를 미리 등록한 뒤 각 몸체와 max(2,true)를 검사한다.

  1. max의 환경 a:Int,b:Int에서 a<b:Bool이다. 두 return은 각각 Int로 선언 반환 Int와 일치한다.

  2. if의 양쪽 분기가 반드시 return하므로 max는 모든 경로 반환 검사도 통과한다.

  3. sum 환경 x:Int에서 x+1:Int, 선언 y:Int에 맞고 return y:Int도 맞아 통과한다.

  4. max(2,true)는 인자 수 2는 맞지만 둘째 인자가 Bool이고 요구 타입 Int이므로 호출을 거절한다.

두 함수 몸체는 통과하고 max(2,true)는 둘째 인자의 타입 불일치다.

오류 누적과 진단

첫 오타 하나 때문에 오류가 스무 개로 늘면 무엇부터 고쳐야 할까?

준비 개념과 학습 목표

준비 개념

  • AST는 작은 식을 자식으로 갖는 구문 구조다.

  • 오류의 원인과 그 원인에 의존한 후속 실패를 구별한다.

학습 목표

  • 독립 오류와 연쇄 오류를 나눈다.

  • 복구 표지로 계속 검사하되 성공과 혼동하지 않는다.

첫 이름 오류를 고치면 진단 수가 줄어야만 올바른 수정일까?

기본 Error 정책을 유지해 모든 자식/문장을 방문하되 Error 자식의 부모에서 연쇄 타입 진단을 억제한다. 실패한 initializer라도 명시 선언 타입을 환경에 등록한다. 새 f():Int의 L1 a:Int=(u+true)+(v+1); L2 b:Bool=a+1; L3 return b;를 검사한다. 빈 환경에서 u와 v는 각각 미정의여서 L1의 두 자식은 Error다. 안쪽 덧셈과 바깥 덧셈은 추가 진단을 억제하고 a:Int는 등록한다. L2는 Int 초기화 대 Bool 요구 오류이고 L3는 Bool 반환 대 Int 요구 오류다. 전체 진단은 네 개다.

수정 A는 앞에 u:Int=2만 추가한다. L1 왼쪽 u+true는 Int+Bool 오류가 드러나며 오른쪽 v는 계속 미정의다. L2/L3도 유지되어 진단 수는 여전히 네 개다. 수정 B는 u:Int=2와 v:Int=3을 모두 추가한다. 오른쪽 v+1은 Int지만 왼쪽 오류가 남아 바깥은 Error다. L2/L3까지 세 개 진단이다. 수정 C는 B에서 true를 1로 바꾸고 L2의 Bool을 Int로 바꾸면 L1 값 3+4=7, L2 값 8이며 반환 타입도 Int가 되어 진단은 없다. 이 값은 수학 정수의 손추적이지 실제 생성 코드의 결과가 아니다.

진단 4→4→3→0이라는 숫자만 보면 첫 수정의 효과를 놓친다. 원인 위치별 장부에는 미정의 u가 없어지고 그 위치를 포함한 덧셈 타입 오류가 새로 드러난다. a:Int가 환경에 있다고 성공 초기화가 되었다고 보거나 Error를 모든 타입의 정상 서브타입으로 취급하지 않는다. 실제 Clang은 복구 노드의 구문/위치를 보존하고 ContainsErrors를 전파하지만 이 작은 Error 타입과 같은 구현이라고 하지 않는다.

먼저 확인할 개념
  • 모든 자식 방문과 Error 억제

    두 미정의 이름은 독립 수집하며 부모 연쇄만 줄인다.

  • 선언 환경과 반환 문맥

    복구로 등록한 변수 타입과 함수의 반환 요구를 별도로 비교한다.

사람이 고칠 수 있는 정보다

진단에는 위치·오류 종류·기대 타입·관측 타입과 관련 선언 위치가 도움이 된다. 무엇이 잘못되었는지 구체적으로 알려야 하며 오류 수만으로 프로그램 품질이나 독립 원인 수를 판단하지 않는다. 경고와 오류의 수준도 도구 정책에 따라 다르다.

식의 자식 하나에서 이름 조회가 실패하면 부모 덧셈 타입도 결정하기 어렵다. 이를 각각 독립 오류로 표시하면 처음 하나를 고쳤을 때 사라질 진단이 쌓인다. 반대로 다른 문장의 잘못된 return까지 전부 숨기면 중요한 독립 원인을 놓친다.

복구 표지는 성공 타입이 아니다

자체 검사기는 unknown 변수나 실제 타입 불일치가 있으면 진단을 기록하고 해당 식 결과를 Error로 둔다. 자식에 Error가 있으면 부모 타입 검사는 추가 연쇄 오류를 억제하고 Error를 전달한다. 두 자식과 후속 문장은 가능한 범위에서 계속 방문하여 독립 오류는 수집한다.

Error는 실행 가능한 언어 타입이나 모든 타입의 서브타입이 아니다. 검사 결과에 Error 또는 실제 오류가 남으면 성공 판정을 하지 않는다. 실제 Clang의 복구 노드·dependent type 설계는 더 복잡하며 이 모형은 아이디어를 이해하기 위한 별도 규칙이다.

복구 후에도 문맥을 유지한다

선언 y:Int=잘못된식이 나오면 이 모형은 진단을 남기되 이후 환경에 y:Int를 등록한다. 선언된 타입을 이용하면 y를 사용하는 곳에서 unknown-name 연쇄 오류를 피할 수 있다. 이는 y의 값이 올바르게 초기화되었다거나 실행해도 된다는 보장이 아니다.

오류 위치를 원인 노드에 연결하고 독립 후속 오류를 수집하는 목적은 수정을 돕는 것이다. 불확실한 부분을 임의 값으로 바꿔 프로그램을 승인하면 복구와 검증이 섞인다. 실제 도구에서는 너무 심각한 구문 손상으로 안전한 복구가 불가능하면 중단할 수도 있다.

변경은 A→B→C로 누적하며 각 행의 진단 수는 전체 함수 기준이다. L1 두 진단의 종류가 바뀌므로 합계만 비교하지 않는다.

중간 과정을 따라가는 예제

Int/Bool만 있고 +는 Int 두 개만 허용한다. f():Int의 세 문장은 L1 x:Int=unknown+1; L2 b:Bool=2; L3 return true;다. 모든 자식/문장을 방문하고 Error 자식의 부모 진단은 억제한다. 잘못된 initializer여도 선언 타입은 환경에 등록한다.

  1. L1 unknown 조회 실패를 위치와 이름으로 진단한다. unknown:Error이므로 + 결과는 Error이며 덧셈/초기화의 추가 연쇄 오류를 억제한다. x:Int는 환경에 등록하지만 함수 성공으로 표시하지 않는다.

  2. L2의 2:Int는 정상 식이다. 기대 Bool과 관측 Int가 달라 독립 초기화 오류를 기록하고 b:Bool을 등록한다.

  3. L3의 true:Bool은 반환 요구 Int와 달라 독립 반환 오류를 기록한다.

  4. 독립 진단은 세 개다. 문장을 계속 읽었다는 사실은 함수가 통과했다는 뜻이 아니며 전체는 실패다.

unknown 이름, Bool 초기화, Int 반환의 독립 오류 3개를 기록하고 연쇄 오류를 억제한다.

조건을 바꾸어 비교하기

합계가 같은 수정의 원인 장부

원래와 수정 A의 네 진단을 위치별로 적어라.

  1. 원래는 u 미정의, v 미정의, L2 초기화 불일치, L3 반환 불일치다.

  2. A는 왼쪽 Int+Bool, v 미정의, L2 초기화 불일치, L3 반환 불일치다.

u 이름 오류는 고쳐졌지만 새 덧셈 진단이 드러나 합계는 네 개다.

비교할 점

합계 감소만 성공으로 보는 장부와 원인/위치 장부를 비교한다.

진단 없는 수정에도 목적은 별도다

수정 C의 식 타입과 값을 단계별로 적어라.

  1. u+1은 Int 값 3이고 v+1은 Int 값 4여서 a:Int 값 7이다.

  2. a+1은 Int 값 8이고 b:Int와 함수 Int 반환이 맞는다.

이 모형의 진단은 0개이고 손계산 반환 값은 8이다. 사용자 목적을 달성했는지는 별도 계약이다.

비교할 점

오류 제거와 실제 컴파일/실행·기능 요구 검증을 구별한다.

종이와 본문으로 직접 해보기

별도 L1을 x:Int=unknown+true로 바꾸고 L2를 b:Bool=false로 고친다. 모든 자식은 검사하되 Error 부모에서 타입 불일치 진단을 억제한다. 진단 수와 true가 검사에서 읽혔는지를 적는다.

힌트 보기

true 자체는 유효 Bool 상수다. Error가 있는 +에서는 이 모형의 억제 정책을 따른다.

풀이 보기

L1은 unknown 이름 오류 한 개이고 true의 Bool 타입도 읽지만 +의 추가 오류는 억제한다. L2는 정상, L3는 반환 오류여서 총 두 개다. unknown을 Int 변수로 고친 후 다시 검사하면 Int+Bool의 덧셈 오류가 새로 드러날 수 있으므로 현재 진단 목록을 완전한 모든 오류 목록으로 단정하지 않는다.

오해와 반례

진단을 억제했으므로 해당 식은 타입이 맞다.

Error 표지가 부모에 전달된 채 전체 검사는 실패다. 억제는 중복/불확실한 메시지를 줄이는 정책이며 올바른 타입 도출을 새로 제공하지 않는다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

원래 L2만 b:Bool=false로 바꾸면 진단 수와 L3는 어떻게 되는가?

힌트 1

L1은 그대로다.

힌트 2

L3의 b 타입은 Bool이다.

풀이와 답 확인

  1. L1의 u/v 두 진단은 남고 L2는 정상이다.

  2. L3는 여전히 Bool을 Int로 반환하므로 한 진단이 남는다.

전체 세 개이며 성공 판정은 아니다.

흔한 오답에서 다시 생각하기

L2가 정상이라 L3도 자동으로 정상이다.

변수 초기화와 함수 반환의 기대 타입은 서로 다른 문맥이다.

연습 2 · 오류 찾아 고치기

L1의 u 실패를 본 즉시 오른쪽 v+1을 방문하지 않아 원래 진단을 세 개로 보고했다. 기본 정책으로 교정하라.

힌트 1

두 자식 방문은 부모의 성공 여부와 별도다.

힌트 2

v는 별도 이름 위치다.

풀이와 답 확인

  1. 오른쪽도 방문해 v 미정의 진단을 기록한다.

  2. 부모 덧셈의 추가 연쇄 진단만 억제하며 L2/L3는 계속 검사한다.

정한 정책에서 전체 네 개다.

흔한 오답에서 다시 생각하기

Error가 나오면 전체 함수 검사를 중단해야 한다.

이 작은 정책은 독립 오류를 계속 수집한다. 실제 도구의 심각한 구문 손상과 혼동하지 않는다.

연습 3 · 직접 만들어 보기

u:Int=2/v:Int=3을 앞에 선언한 수정 B에서 산술 목적 a=(u+1)+(v+1), b=a+1을 보존하도록 남은 오류를 고쳐라.

힌트 1

왼쪽 Bool 상수를 의도한 Int 상수로 바꾼다.

힌트 2

b의 선언 타입과 반환 요구를 맞춘다.

풀이와 답 확인

  1. true를 1로 바꾸고 b:Int로 선언한다.

  2. a와 b는 각각 Int 값 7과 8이며 return b는 Int다.

타입 장부의 진단 0개와 모형 값 8을 함께 적는다.

흔한 오답에서 다시 생각하기

a를 Bool로 바꿔 덧셈 오류를 숨긴다.

Bool 변경은 숫자 덧셈 목적을 깨며 Error를 정상 값으로 만들지도 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

수정 C의 모든 +를 새 연산 minus로 바꾼 손계산 보고서가 모든 식은 Int이며 반환 값은 0이라고 적었다. 그 값과 원래 목적 8의 보장 여부를 감사하라. minus는 두 Int를 빼는 정상 연산이며 실제 프로그램을 실행하지 않았다.

힌트 1

a=(u−1)+(v−1)로 해석하지 않는다. 이 질문은 모든 +를 minus로 바꾼다.

힌트 2

a=(u−1)−(v−1), b=a−1을 계산한다.

풀이와 답 확인

  1. u−1은 1, v−1은 2여서 a는 −1이다. b=a−1은 −2다.

  2. 따라서 질문의 반환 0 보고 자체도 이 조건과 모순이다. 정상 타입이어도 원래 목적 8은 보장하지 않는다.

정한 변경의 손모형 값은 −2이며 0이라는 보고를 바로잡는다.

흔한 오답에서 다시 생각하기

정상 Int 타입이면 원래 수학 결과도 같다.

타입은 연산의 허용 모양을 검사한다. 연산 교체의 계산 의미는 별도 추적한다.

후속 타입 조회의 선언 약속만 유지한다. 초기화 성공이나 실행 허가는 보장하지 않는다.

한 단계 더

진단 하나에 primary 위치와 관련 선언 위치를 함께 붙이는 종이 표를 설계한다. 변수 이름 오타의 제안은 근거가 있을 때만 제시하고 자동 교정을 실제 사용자 의도와 동일시하지 않는다. Error 전파와 독립 문장 방문 정책을 바꾸면 메시지 수가 달라짐을 비교한다.

다른 문제에 적용하기

세 독립 계약을 감사하라. ① 불변 R/S 조건식의 공통 U와 함수 Animal→Cat을 Cat→Animal 자리에 대체하는 방향을 적고 Cell<Cat> 공변 쓰기 반례를 적어라. ② f(p:Bool):Int가 if(p){return 1;}else{x:Int=2;} 뒤 return 3을 갖는다. 타입 검사와 반환 요약을 적고 뒤에 z:Int=true를 붙인 경우도 비교하라. ③ 진단 모형에서 u:Int=2,v:Int=3을 앞에 두고 a:Int=(u+true)+(v+1); b:Bool=a+1; return b;를 검사한다. 진단 위치와 개수를 적고 산술 목적 a=(u+1)+(v+1), b=a+1을 보존하는 수정을 구성하라. 실제 컴파일러/실행/학생 수행은 하지 않는다.

힌트 1

① 호출자가 줄 수 있는 입력과 받을 결과, 별칭의 쓰기 권한을 분리한다. ② 순차는 OR지만 타입 검사는 뒤 문장도 방문한다.

힌트 2

③ Error 때문에 부모 진단은 억제해도 선언 타입은 등록한다. 왼쪽 상수와 b의 타입을 각각 고친다.

풀이와 답 확인

  1. ① R/S는 U={id:Int,pet:Animal}로 사용할 수 있다. Animal→Cat은 Cat→Animal을 대체한다. Cell<Animal> 별칭이 dog를 쓰면 원래 Cat 읽기 약속을 깨므로 가변 칸의 단순 공변은 거절한다.

  2. ② if 요약은 true AND false라 false지만 뒤 return 3과 OR해 true다. 조건 Bool과 반환 Int가 맞아 통과한다. z:Int=true를 추가하면 요약은 true로 유지되지만 독립 초기화 오류로 전체는 실패다.

  3. ③ L1 왼쪽 Int+Bool, L2 Bool 초기화에 Int, L3 Int 반환에 Bool의 세 진단을 수집한다. true를 1로 바꾸고 b:Int로 선언하면 a의 값은 7, b의 값은 8이며 진단은 없다.

공통 사용 권한·가변 쓰기·반환 요약·식 타입·오류 복구·산술 목적을 각각 다른 근거로 확인한다. 모형 수정의 타입 성공과 값 8은 실제 컴파일/실행이나 사용자 의도의 증거가 아니다.

해결한 뒤 점검할 것

  • U의 필드별 조건과 함수 두 방향의 입력/출력 및 dog 쓰기 반례를 명시한다.

  • if/순차 요약을 계산하고 뒤 타입 오류를 반환 보장과 혼동하지 않는다.

  • 세 진단의 위치와 억제된 부모를 적고 두 수정 뒤 Int/7/8을 재계산한다.

  • 실제 컴파일러·수명·기계 숫자·학생 검증은 미수행으로 남긴다.
