소단원 10.1

명령 선택과 주소 계산

배열에서 값을 하나 읽는 표현을 CPU가 알아듣는 작은 명령들로 어떻게 바꿀까?

준비 개념과 학습 목표

준비 개념

  • 중간 표현과 데이터 흐름
  • 바이트 주소
  • 레지스터와 메모리

학습 목표

  • 대상의 명령으로 표현을 나누는 이유를 설명한다.
  • 원소 크기를 반영한 배열 주소를 계산한다.
  • 명령의 지원 범위와 메모리 조건을 구별한다.

표현의 뜻을 유지하며 대상에 맞추기

중간 표현의 한 연산이 항상 한 기계 명령이 되는 것은 아니다. 명령 선택은 대상이 지원하는 연산과 자료 폭, 피연산자 형식에 맞춰 의미를 표현한다. 지원하지 않는 연산이나 자료형은 다른 연산들로 낮추는 합법화가 필요할 수 있다.

명령을 고른 뒤에도 레지스터 배정과 명령 순서, 스택 프레임 등의 단계가 남는다. 아래 예제는 필요한 물리 레지스터가 이미 주어진 작은 경우다. 실제 최적화 컴파일러가 모든 입력에 이 목록을 그대로 출력한다고 주장하지 않는다.

원소 번호를 바이트 주소로 바꾸기

RV32I는 바이트 주소를 쓰는 load/store 구조다. 정수 덧셈은 레지스터끼리 처리하고 메모리 값은 먼저 load로 읽는다. 아래 배열의 원소가4바이트이면 인덱스 i의 주소는 base+4i다. i를 그냥 base에 더하면 원소 번호를 바이트 수로 착각하게 된다.

LW의 주소는 기반 레지스터와 부호 확장한12비트 오프셋의 합이다. 동적인 인덱스는 레지스터에서 크기 배율을 먼저 계산할 수 있다. 배열의 범위와 메모리 권한은 계산식이 맞다는 이유만으로 확인되지 않는다. 여기서는 올바른 원소, 자연 정렬, 읽기 가능 메모리를 입력 조건으로 둔다.

작은 명령을 읽는 순서

아래는 a0가 배열 주소, a1이 인덱스인 종이 실행이다. slli는 왼쪽으로2비트 밀어4배, add는 기반 주소를 더하고 lw는 계산 주소의32비트 값을 읽는다. 마지막 addi는 값에7을 더해 a0에 둔다.

a0를 결과로 덮어쓰기 전에 기반 주소가 쓰였으므로 이 예제에서는 문제가 없다. t0/t1은 임시 레지스터다. 오버플로·잘못된 인덱스·잘못된 주소를 자동으로 처리하는 프로그램은 아니며, 실제 고수준 언어의 정의되지 않은 동작까지 해결했다는 뜻도 아니다.

slli t0, a1, 2
add  t0, a0, t0
lw   t1, 0(t0)
addi a0, t1, 7

중간 과정을 따라가는 예제

RV32I에서 a0=1000,a1=3이며 주소1012의4바이트 정수 값은20이다. 주소는 유효하고 정렬돼 있으며 연산은 오버플로하지 않는다. 위 네 명령의 값을 추적하라.

  1. slli 뒤 t0=3×4=12다.
  2. add 뒤 t0=1000+12=1012다.
  3. lw는 주소1012의 값20을 t1에 읽는다. 주소1012와 값20을 구분한다.
  4. addi는 a0=20+7=27을 만든다. 명령4개이며 메모리 읽기는1개다.

최종 a0=27, 유효 주소1012다. 연산이 네 명령이라고 실제 네 CPU사이클이라는 의미는 아니다.

종이와 본문으로 직접 해보기

배열 길이는5이고 base=2000이다. i=4의 주소와 i=5의 주소를 계산하고, 어느 인덱스가 허용되는지 판단하라. 또한 고정 원소 i=2를 읽을 때 lw t1, 8(a0)의 오프셋은 무엇을 뜻하는가?

힌트 보기

마지막 허용 인덱스는 길이−1이다. 주소를 계산할 수 있다는 것과 그 원소를 읽어도 된다는 것은 다르다.

풀이 보기

i=4는2000+16=2016으로 허용된다. i=5는2020이지만 길이5의 끝 다음이므로 이 배열 원소로 읽으면 안 된다. 고정 i=2의 오프셋8은8바이트이며 두 번째가 아니라 인덱스2, 즉 세 번째 원소를 뜻한다.

오해와 반례

base+i만 계산해도 배열 원소 주소이고, 주소를 만들었으면 읽어도 된다.

4바이트 원소의 i=3은 base+12인데 base+3은 다른 위치다. 또한 길이5에서 i=5의 주소 계산은 되지만 유효한 원소를 뜻하지 않는다. 주소 산술과 배열 경계·메모리 접근 조건을 따로 검토해야 한다.

자기점검

LW 한 명령으로 메모리 두 값을 더할 수 있는가?

답과 이유 보기

이 예제의 RV32I LW는 그렇게 동작하지 않는다.

LW는 메모리에서 레지스터로 읽으며, 덧셈은 별도 레지스터 연산이다.

부호 있는12비트 오프셋에 +2048을 직접 넣을 수 있는가?

답과 이유 보기

아니요.

범위는−2048부터2047이므로 더 큰 주소 차이는 다른 명령 조합이 필요하다.

a1=0이면 첫 두 명령 뒤 t0는 얼마인가?

답과 이유 보기

1000이다.

0×4+1000으로 첫 원소의 기반 주소가 된다.

한 단계 더

원소 크기를8바이트로 바꾸면 i=3 주소는base+24가 된다. 그러나 RV32I에서 slli 배율만3으로 바꾼다고 8바이트 읽기가 완성되지는 않는다. LW는 여전히4바이트이므로 자료 폭에 맞는 추가 읽기·표현이 필요하다. 주소 계산의 변경과 값 읽기의 변경을 나눠 적어 보자.

소단원 10.2

분기·호출·반환

함수 안에서 다른 함수를 부르면 원래 돌아갈 위치는 어디에 남겨야 할까?

준비 개념과 학습 목표

준비 개념

  • 프로그램 카운터
  • 조건 분기
  • 스택과 함수 인수

학습 목표

  • 분기 조건과 흐름을 직접 추적한다.
  • 호출이 반환 주소를 덮어쓰는 경우를 설명한다.
  • ABI의 저장 책임과 스택 복원을 확인한다.

조건에 따라 다음 명령 고르기

조건 분기는 레지스터 값을 비교하고 조건이 맞으면 레이블 위치로 흐름을 바꾼다. 아래 bge는 부호 있는 비교이며 a0≥0이면 음수 변환을 건너뛴다. bltu/bgeu 같은 부호 없는 비교와 같은 규칙이 아니다.

예제는 최소32비트 부호 정수보다 큰 음수와 범위 안 양수만 사용한다. 가장 작은 부호 정수의 절댓값은 같은 부호 범위로 표현되지 않으므로 이 프로그램을 모든 C int에 안전한 abs 구현이라고 부르지 않는다. 분기 도식에도 산술 조건을 함께 적는다.

호출과 반환 주소의 수명

JAL은 목적지로 이동하면서 다음 명령 주소 pc+4를 지정 레지스터에 쓴다. 표준 호출은 ra를 사용하며, 반환은 jalr zero,0(ra)로 표시할 수 있다. ra는 호출을 넘어 보존되는 레지스터가 아니다.

f가 g를 호출하면 ra에는 f 내부의 복귀 위치가 들어가므로 f의 바깥 호출자 주소를 별도 보존해야 한다. 아래 f는16바이트 스택 공간에 이전 ra를 저장하고 g 뒤에 복구한다. 프레임 크기16은 선택한 기본 정수 ABI의 스택 정렬을 유지하며 임의 모든 ABI의 규칙은 아니다.

저장 책임과 균형 맞추기

인수와 결과는 a0에 두며 g는 a0를 변경한다. s계열 저장 레지스터를 바꾸는 함수는 들어올 때의 값을 복원해야 하지만 아래 함수는 이를 쓰지 않는다. 임시 레지스터에 넣은 값이 다음 호출에도 자동 보존된다고 가정하지 않는다.

프레임은 호출 전 sp를16 줄이고 반환 전16 늘려 균형을 맞춘다. 저장 슬롯은12(sp)이며4바이트 ra를 놓는다. 메모리는 유효한 읽기·쓰기가 가능하고 초기sp=4096은16의 배수라고 가정한다. 아래는 주소를 함께 정한 짧은 종이 목록으로, 재배치·긴 거리 호출은 다루지 않는다.

f:  # 2000부터 각 명령 4바이트
  addi sp, sp, -16
  sw   ra, 12(sp)
  jal  ra, g
  addi a0, a0, 3
  lw   ra, 12(sp)
  addi sp, sp, 16
  jalr zero, 0(ra)
g:  # 3000부터
  bge  a0, zero, done
  sub  a0, zero, a0
done:
  jalr zero, 0(ra)

중간 과정을 따라가는 예제

호출자의1000번지 JAL이 f의2000번지로 이동해 ra=1004를 만들었다. 초기sp=4096,a0=−6이다. f의2008번지 JAL은 g의3000으로 이동하며, g의 done은3008이다. 반환 위치·스택 슬롯·최종 값을 추적하라.

  1. 2000에서sp=4080,2004에서 슬롯4080+12=4092에 ra1004를 저장한다.
  2. 2008의 JAL은 ra=2012로 바꾸고3000으로 간다. −6≥0은 거짓이므로3004의 sub가 a0=6을 만든다.
  3. 3008의 jalr는2012로 돌아온다.2012의 addi가 a0=9를 만든다.
  4. 2016의 lw가 ra1004를 복원한다.2020에서sp4096을 복구하고2024의 jalr는1004로 돌아간다.

결과a0=9, 최종sp=4096, 반환1004다. 저장 슬롯4092에는 바깥 호출자 반환 주소1004가 보존됐다.

종이와 본문으로 직접 해보기

a0=4로 바꾸면 g의 분기는 어디로 가고 f의 결과는 얼마인가? 별도로 ra 저장과 복원 명령을 각각 nop(addi zero,zero,0)으로 바꿔 모든 명령 주소를 그대로 유지한다고 가정하면 f 마지막 반환은1004와2012 중 어디로 가는가?

힌트 보기

양수에서는 sub를 건너뛰며, JAL로 바뀐 ra가 복원되는지 확인하라.

풀이 보기

4≥0이어서3008로 분기하고 g는4를 돌려준다. f는3을 더해7을 반환한다. ra 저장·복원을 같은 크기의 nop으로 바꾸면 주소는 그대로이고 ra2012가 남아 f의 마지막 반환은2012로 가며 호출자1004로 가지 못한다. 두 명령을 실제로 삭제하고 코드를 재배치하면 잘못 남는 복귀 주소의 숫자도 달라지므로, 여기서는 주소를 유지하는 조건을 명시했다.

오해와 반례

ra에 반환 주소가 들어 있으니 중첩 호출에서도 별도 저장은 필요 없다.

f의2008 호출이 원래1004를2012로 덮어쓴다. 이 값은 g가 f로 돌아오는 주소이지 f가 자신의 호출자로 돌아가는 주소가 아니다. leaf 함수와 다른 함수를 호출하는 함수의 저장 필요를 구분해야 한다.

자기점검

초기sp가4096이고 프레임16이면 저장 슬롯12(sp)는 어디인가?

답과 이유 보기

4092이다.

프레임 후sp4080에12를 더하며 슬롯의4바이트는4092부터4095다.

bge a0,zero가 부호 있는 a0=−6에서 분기하는가?

답과 이유 보기

아니요.

−6≥0은 거짓이다. 부호 없는 해석을 섞으면 다른 결과가 된다.

프레임을8바이트만 줄이는 것이 여기서 표준 정렬을 유지하는가?

답과 이유 보기

아니요.

4096−8=4088은16의 배수가 아니다. 이 예제는 기본 정수 ABI의16바이트 정렬을 따른다.

한 단계 더

f가 s0도 변경한다고 가정하고, 들어온s0=77을 보존하는 슬롯을 프레임 안에 추가해 보자. 예를 들어8(sp)에 저장·복원하면 ra의12(sp)와 겹치지 않는다. 두 값의4바이트 범위를4088–4091과4092–4095로 확인하고 모든 반환 경로에서 두 값을 복원해야 함을 적자.

소단원 10.3

대상 ISA와 어셈블 출력

읽을 수 있는 명령 문자열과 CPU가 읽는 바이트는 어떻게 연결될까?

준비 개념과 학습 목표

준비 개념

  • 2진수와16진수
  • RV32I 명령 필드
  • 레이블과 주소

학습 목표

  • ISA·ABI·어셈블·오브젝트를 구분한다.
  • 간단한 I형 명령을 필드에서 구성한다.
  • 출력 목록의 바이트 수와 실행 성능을 구별한다.

ISA와 ABI가 서로 답하는 질문

ISA는 명령과 레지스터, 그 연산의 뜻을 정한다. ABI는 함수가 인수와 결과를 어디에 두고 어떤 값을 보존할지 같은 프로그램 사이의 약속을 정한다. ISA만 맞춘 조각이 다른 함수와 올바르게 연결된다고 보장하지 않는다.

대상에는 레지스터 폭과 선택한 확장, ABI, 오브젝트 형식 등 정보가 필요하다. 이 절은 RV32I, 압축C확장 없음, 기본 ILP32 정수 ABI, 작은 바로 표현 가능한 명령을 선택한다. 다른 대상의 실제 컴파일 결과와 동일하다고 비교하지 않는다.

어셈블 텍스트에서 기계 바이트까지

어셈블 목록은 레이블과 지시문, 읽을 수 있는 명령을 포함한다. 레이블 자체는 위치 이름이며 명령 한 개를 뜻하지 않는다. 의사 명령은 실제 명령 하나 또는 여러 개로 바뀔 수 있으므로 목록의 모든 줄에4를 곱하면 틀릴 수 있다.

어셈블러와 오브젝트 출력은 명령 인코딩뿐 아니라 섹션·기호·아직 확정되지 않은 주소의 재배치 정보 등을 다룬다. 링크 과정은 여러 오브젝트의 기호를 연결할 수 있다. 아래는 주소 참조가 없는 한 I형 명령을 종이에서 인코딩하며 실제 오브젝트 파일을 만든 것이 아니다.

필드와 바이트의 위치

addi a0,zero,7의 I형 필드는 immediate=7,rs1=0,funct3=0,rd=10,opcode=0x13이다. 필드 경계는 immediate[31:20],rs1[19:15],funct3[14:12],rd[11:7],opcode[6:0]으로 둔다. zero는x0이고 a0는x10이라는 별칭이다.

32비트 명령 단어의16진 표기와 메모리의 바이트 순서를 구분한다. 아래는 명시적으로 little-endian을 가정하므로 가장 낮은 바이트가 낮은 주소에 간다. 대상의 메모리 순서를 정하지 않고 모든 플랫폼에 같은 바이트 목록을 붙이지 않는다.

addi a0, zero, 7
# I형 단어 = (7 << 20) | (0 << 15) | (0 << 12) | (10 << 7) | 0x13

중간 과정을 따라가는 예제

위 한 명령의32비트 단어와 little-endian 메모리 바이트를 구하라. 별도 목록 .text / .globl bump / bump: / addi a0,a0,1 / jalr zero,0(ra)에는 실제 명령이 몇 개이며 압축·완화 없이 그 명령들의 총크기는 얼마인가?

  1. 7<<20=0x00700000이고10<<7=0x00000500이다. 나머지 비영 필드는 opcode0x13이다.
  2. 서로 겹치지 않는 필드를 합치면0x00700513이다.
  3. little-endian 바이트는 낮은 주소부터13 05 70 00이다. 이 바이트를 역순으로 읽으면16진 단어00700513을 복원한다.
  4. 별도 bump 목록의 실제 명령은 addi와 jalr 두 개다. 지시문과 레이블은 명령이 아니며, 이 조건에서는 명령 코드 2×4=8바이트다. 전체 오브젝트 파일 크기를8로 결론내리지는 않는다.

명령 단어0x00700513, 바이트13 05 70 00이다. bump의 명령 코드 부분은8바이트이며 오브젝트 헤더·기호·정렬 등은 별도다.

종이와 본문으로 직접 해보기

immediate만8로 바꾸면 단어와 바이트는 어떻게 바뀌는가? 실제 RV32I 명령3개 앞에 레이블2개와 빈줄1개가 있고 추가 데이터나 패딩은 없다면 코드 크기는 얼마인가?

힌트 보기

immediate는20비트 위치에 넣는다. 출력 줄 수와 실제 명령 수를 분리하라.

풀이 보기

단어0x00800513, little-endian 바이트13 05 80 00이다. 명령3개는12바이트이며 레이블과 빈줄은 더하지 않는다. 압축 명령·의사 명령 확장·정렬 패딩을 허용하면 별도 계산이 필요하다.

오해와 반례

어셈블 출력 한 줄은 항상4바이트이고8바이트 코드는 항상8사이클 걸린다.

지시문·레이블·의사 명령·다른 확장 때문에 한 줄의 바이트 수는 일정하지 않다. 여기에 한정한 두 실제 RV32I 명령의8바이트도 실행 사이클과 다르다. 캐시·의존성·분기·CPU 구현 등을 주지 않았으므로 시간은 계산하지 않는다.

한 단계 더

bump의 함수 기호 주소가 아직 확정되지 않은 호출을 다른 파일에 추가한다고 상상하자. 이름을 표시한 어셈블 줄을 읽는 것과 최종 명령의 주소 필드를 확정하는 것은 다르다. 컴파일·어셈블·링크·실행 단계를 종이에 나누고, 실제 도구를 돌리지 않은 이 자료에서는 어느 단계도 실측 결과로 주장할 수 없음을 표시하자.
