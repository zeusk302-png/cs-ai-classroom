소단원 10.1

명령 선택과 주소 계산

배열에서 값을 하나 읽는 표현을 CPU가 알아듣는 작은 명령들로 어떻게 바꿀까?

준비 개념과 학습 목표

준비 개념

  • 중간 표현과 데이터 흐름

  • 바이트 주소

  • 레지스터와 메모리

학습 목표

  • 대상의 명령으로 표현을 나누는 이유를 설명한다.

  • 원소 크기를 반영한 배열 주소를 계산한다.

  • 명령의 지원 범위와 메모리 조건을 구별한다.

인덱스가 하나 늘어 즉시값 범위를 넘으면 주소도 틀릴까?

대상은 RV32I, 압축 확장 없음, 4바이트 원소 배열이다. 처음 a0에는 base = 8192, a1에는 요청 인덱스 i를 둔다. 길이는 600이고 전체 배열 저장소가 읽기 가능하며 자연 정렬이라고 가정한다. i = 511의 바이트 차이는 2044이지만 i = 512의 차이는 2048이다. 두 인덱스 모두 배열 안이어도 LW의 부호 있는 12비트 즉시값으로 직접 표현 가능한지는 다르다.

lw a0,2044(a0)는 i=511을 읽을 수 있다. 그러나 +2048은 즉시값 범위 −2048..2047 밖이다. i=512의 유효 주소 10240을 레지스터로 만든 뒤 lw a0,0(t0)로 읽으면 된다. 지원되는 피연산자 형식과 메모리 유효성을 각각 검사한다.

동적 i=512에서는 slli t0,a1,2; add t0,a0,t0; lw a0,0(t0)의 세 명령을 선택한다. 별도 고정 상수 구성은 lui t0,1; addi t0,t0,−2048; add t0,a0,t0; lw a0,0(t0)의 네 명령이다. 4096−2048=2048을 사용한다. 두 목록의 실제 속도나 최적성을 주장하지 않는다.

  • 대상과 명령 코드 크기

표현의 뜻을 유지하며 대상에 맞추기

중간 표현의 한 연산이 항상 한 기계 명령이 되는 것은 아니다. 명령 선택은 대상이 지원하는 연산과 자료 폭, 피연산자 형식에 맞춰 의미를 표현한다. 지원하지 않는 연산이나 자료형은 다른 연산들로 낮추는 합법화가 필요할 수 있다.

명령을 고른 뒤에도 레지스터 배정과 명령 순서, 스택 프레임 등의 단계가 남는다. 아래 예제는 필요한 물리 레지스터가 이미 주어진 작은 경우다. 실제 최적화 컴파일러가 모든 입력에 이 목록을 그대로 출력한다고 주장하지 않는다.

원소 번호를 바이트 주소로 바꾸기

RV32I는 바이트 주소를 쓰는 load/store 구조다. 정수 덧셈은 레지스터끼리 처리하고 메모리 값은 먼저 load로 읽는다. 아래 배열의 원소가4바이트이면 인덱스 i의 주소는 base+4i다. i를 그냥 base에 더하면 원소 번호를 바이트 수로 착각하게 된다.

LW의 주소는 기반 레지스터와 부호 확장한12비트 오프셋의 합이다. 동적인 인덱스는 레지스터에서 크기 배율을 먼저 계산할 수 있다. 배열의 범위와 메모리 권한은 계산식이 맞다는 이유만으로 확인되지 않는다. 여기서는 올바른 원소, 자연 정렬, 읽기 가능 메모리를 입력 조건으로 둔다.

작은 명령을 읽는 순서

아래는 a0가 배열 주소, a1이 인덱스인 종이 실행이다. slli는 왼쪽으로2비트 밀어4배, add는 기반 주소를 더하고 lw는 계산 주소의32비트 값을 읽는다. 마지막 addi는 값에7을 더해 a0에 둔다.

a0를 결과로 덮어쓰기 전에 기반 주소가 쓰였으므로 이 예제에서는 문제가 없다. t0/t1은 임시 레지스터다. 오버플로·잘못된 인덱스·잘못된 주소를 자동으로 처리하는 프로그램은 아니며, 실제 고수준 언어의 정의되지 않은 동작까지 해결했다는 뜻도 아니다.

slli t0, a1, 2
add  t0, a0, t0
lw   t1, 0(t0)
addi a0, t1, 7

주소는 바이트 위치이고 차이는 기준점에 더할 바이트 수다. 목록에 없던 자동 범위 검사는 가정하지 않는다. 같은 결과와 코드 크기는 주어진 메모리·ISA 조건 아래에서만 비교한다.

중간 과정을 따라가는 예제

RV32I에서 a0=1000,a1=3이며 주소1012의4바이트 정수 값은20이다. 주소는 유효하고 정렬돼 있으며 연산은 오버플로하지 않는다. 위 네 명령의 값을 추적하라.

  1. slli 뒤 t0=3×4=12다.

  2. add 뒤 t0=1000+12=1012다.

  3. lw는 주소1012의 값20을 t1에 읽는다. 주소1012와 값20을 구분한다.

  4. addi는 a0=20+7=27을 만든다. 명령4개이며 메모리 읽기는1개다.

최종 a0=27, 유효 주소1012다. 연산이 네 명령이라고 실제 네 CPU사이클이라는 의미는 아니다.

조건을 바꾸어 비교하기

직접 접근과 큰 오프셋 구성

주소 10236의 값은 13, 주소 10240의 값은 17이다. i=511의 직접 LW와 i=512의 동적 목록을 비교하라.

  1. 직접 목록은 base+2044=10236을 읽어 a0=13을 만든다. 명령은 한 개, 코드 4바이트다.

  2. 동적 목록은 배율 계산 뒤 t0에 2048을 저장한다. 기준 주소를 더하면 t0는 유효 주소 10240이 된다. LW는 그 주소에서 값 17을 읽어 a0에 넣는다. 실제 명령은 세 개이고 코드 크기는 12바이트다.

읽기 횟수는 각각 1회이고 결과는 13과 17이다.

비교할 점

짧은 목록의 결과가 다르다는 것은 서로 다른 원소를 요청했기 때문이며 시간 비교는 아니다.

부호 확장으로 다른 원소를 읽는 오류

학생이 +2048을 12비트 0x800으로 넣어 lw a0,−2048(a0)를 만들었다. 접근 권한을 확인하지 않고 실행했다고 가정하지 말고 주소만 비교하라.

  1. 12비트 0x800은 부호 확장하면 −2048이다. 계산 주소는 8192−2048=6144다.

  2. 의도한 10240보다 4096바이트 앞이며 배열 시작보다도 앞이다. 원하는 원소를 읽는 계약이 성립하지 않는다.

6144와 10240의 차이를 확인하고 큰 상수 구성이나 동적 배율 목록으로 교정한다.

비교할 점

명령 필드에 들어가는 비트 패턴과 원하는 양의 정수는 같은 뜻이 아닐 수 있다.

종이와 본문으로 직접 해보기

배열 길이는5이고 base=2000이다. i=4의 주소와 i=5의 주소를 계산하고, 어느 인덱스가 허용되는지 판단하라. 또한 고정 원소 i=2를 읽을 때 lw t1, 8(a0)의 오프셋은 무엇을 뜻하는가?

힌트 보기

마지막 허용 인덱스는 길이−1이다. 주소를 계산할 수 있다는 것과 그 원소를 읽어도 된다는 것은 다르다.

풀이 보기

i=4는2000+16=2016으로 허용된다. i=5는2020이지만 길이5의 끝 다음이므로 이 배열 원소로 읽으면 안 된다. 고정 i=2의 오프셋8은8바이트이며 두 번째가 아니라 인덱스2, 즉 세 번째 원소를 뜻한다.

오해와 반례

base+i만 계산해도 배열 원소 주소이고, 주소를 만들었으면 읽어도 된다.

4바이트 원소의 i=3은 base+12인데 base+3은 다른 위치다. 또한 길이5에서 i=5의 주소 계산은 되지만 유효한 원소를 뜻하지 않는다. 주소 산술과 배열 경계·메모리 접근 조건을 따로 검토해야 한다.

연습 2 · 오류 찾아 고치기

학생이 i=512의 원소를 lw a0,512(a0)로 읽으려 한다. 즉시값은 유효하므로 맞다는 설명을 교정하라.

힌트 1

512의 단위부터 적는다.

힌트 2

풀이와 답 확인

  1. 즉시값 512는 바이트 차이이며 주소 8704를 만든다.

  2. 이는 인덱스 128의 주소다. i=512의 차이 2048을 만들려면 별도 레지스터 주소 계산이 필요하다.

연습 3 · 직접 만들어 보기

고정 i=512를 읽는 LUI/ADDI/ADD/LW 네 명령과 t0 중간값을 구성하라.

힌트 1

LUI 1은 4096을 만든다.

힌트 2

−2048은 12비트 signed 범위 안이다.

풀이와 답 확인

  1. lui t0,1; addi t0,t0,−2048; add t0,a0,t0; lw a0,0(t0)로 둔다.

  2. LUI 뒤 t0의 값은 4096이다. ADDI로 2048을 빼면 t0는 2048이 된다. 기준 주소 8192를 더하면 t0는 유효 주소 10240이 된다. LW는 그 주소의 값 17을 읽어 a0에 넣는다.

네 명령, 코드 16바이트, 읽기 1회이며 결과 17이다.

흔한 오답에서 다시 생각하기

lui t0,2048은 값 2048을 직접 만든다.

LUI 피연산자는 낮은 12비트가 0인 상위 필드를 지정한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

8바이트 원소 배열로 별도 바꾸어 길이 300, base=8192, i=256을 선택한다. 배율과 값 읽기에서 각각 무엇을 바꿔야 하는가?

힌트 1

차이는 8i다.

힌트 2

RV32I의 LW 한 개는 32비트만 읽는다.

풀이와 답 확인

  1. 배율은 왼쪽 shift 3이며 주소는 8192+2048=10240이다.

  2. 64비트 값을 모두 가져오려면 명시한 저장 순서에 맞춰 주소 10240과 10244의 두 32비트 조각 등을 읽고 표현해야 한다. shift만 바꾼 LW 한 개는 전체 값을 읽지 않는다.

주소 배율 수정과 자료 폭의 낮춤은 별도이며 실제 조각 코드를 실행하지 않는다.

돌아갈 주소만 보존하면 호출 전 값도 살아 있을까?

새 함수 f는 입력 x를 받고 g(x)=2x를 부른 뒤 원래 x를 더해 3x를 반환한다. 입력은 x=5이고 중간값이 signed 32비트 범위 안이라고 가정한다. ra뿐 아니라 호출 뒤 필요한 x도 보존해야 한다. a0와 t0는 호출 뒤 값이 보장되지 않으며 s0를 쓰는 함수는 들어온 s0를 복원한다.

f의 명령 주소를 4000부터 4바이트 간격으로 고정한다: addi sp,sp,−16; sw ra,12(sp); sw s0,8(sp); addi s0,a0,0; jal ra,g; add a0,a0,s0; lw s0,8(sp); lw ra,12(sp); addi sp,sp,16; jalr zero,0(ra). g는 5000의 slli a0,a0,1과 5004의 jalr zero,0(ra)다. 원래 ra=1004,sp=8192,s0=77이다.

f의 호출은 주소 4016에서 ra = 4020을 만든다. g가 반환한 a0 = 10에 보존한 x = 5를 더해 15를 얻는다. 반환 직전에 s0는 77, ra는 1004, sp는 8192로 복원한다. s0에 x를 보존하는 것과 바깥 호출자의 s0를 보존하는 것은 모두 필요하다.

조건에 따라 다음 명령 고르기

조건 분기는 레지스터 값을 비교하고 조건이 맞으면 레이블 위치로 흐름을 바꾼다. 아래 bge는 부호 있는 비교이며 a0≥0이면 음수 변환을 건너뛴다. bltu/bgeu 같은 부호 없는 비교와 같은 규칙이 아니다.

예제는 최소32비트 부호 정수보다 큰 음수와 범위 안 양수만 사용한다. 가장 작은 부호 정수의 절댓값은 같은 부호 범위로 표현되지 않으므로 이 프로그램을 모든 C int에 안전한 abs 구현이라고 부르지 않는다. 분기 도식에도 산술 조건을 함께 적는다.

호출과 반환 주소의 수명

JAL은 목적지로 이동하면서 다음 명령 주소 pc+4를 지정 레지스터에 쓴다. 표준 호출은 ra를 사용하며, 반환은 jalr zero,0(ra)로 표시할 수 있다. ra는 호출을 넘어 보존되는 레지스터가 아니다.

f가 g를 호출하면 ra에는 f 내부의 복귀 위치가 들어가므로 f의 바깥 호출자 주소를 별도 보존해야 한다. 아래 f는16바이트 스택 공간에 이전 ra를 저장하고 g 뒤에 복구한다. 프레임 크기16은 선택한 기본 정수 ABI의 스택 정렬을 유지하며 임의 모든 ABI의 규칙은 아니다.

저장 책임과 균형 맞추기

인수와 결과는 a0에 두며 g는 a0를 변경한다. s계열 저장 레지스터를 바꾸는 함수는 들어올 때의 값을 복원해야 하지만 아래 함수는 이를 쓰지 않는다. 임시 레지스터에 넣은 값이 다음 호출에도 자동 보존된다고 가정하지 않는다.

프레임은 호출 전 sp를16 줄이고 반환 전16 늘려 균형을 맞춘다. 저장 슬롯은12(sp)이며4바이트 ra를 놓는다. 메모리는 유효한 읽기·쓰기가 가능하고 초기sp=4096은16의 배수라고 가정한다. 아래는 주소를 함께 정한 짧은 종이 목록으로, 재배치·긴 거리 호출은 다루지 않는다.

f:  # 2000부터 각 명령 4바이트
  addi sp, sp, -16
  sw   ra, 12(sp)
  jal  ra, g
  addi a0, a0, 3
  lw   ra, 12(sp)
  addi sp, sp, 16
  jalr zero, 0(ra)
g:  # 3000부터
  bge  a0, zero, done
  sub  a0, zero, a0
done:
  jalr zero, 0(ra)

바깥 계약 복구

표의 레지스터 현재값과 슬롯에 보존한 입구값을 별도로 읽는다. 예제의 g가 t0를 안 쓰더라도 다른 ABI 준수 g가 t0를 바꿀 수 있으므로 일반 호출 계약은 더 약하다.

중간 과정을 따라가는 예제

호출자의1000번지 JAL이 f의2000번지로 이동해 ra=1004를 만들었다. 초기sp=4096,a0=−6이다. f의2008번지 JAL은 g의3000으로 이동하며, g의 done은3008이다. 반환 위치·스택 슬롯·최종 값을 추적하라.

  1. 2000에서sp=4080,2004에서 슬롯4080+12=4092에 ra1004를 저장한다.

  2. 2008의 JAL은 ra=2012로 바꾸고3000으로 간다. −6≥0은 거짓이므로3004의 sub가 a0=6을 만든다.

  3. 3008의 jalr는2012로 돌아온다.2012의 addi가 a0=9를 만든다.

  4. 2016의 lw가 ra1004를 복원한다.2020에서sp4096을 복구하고2024의 jalr는1004로 돌아간다.

결과a0=9, 최종sp=4096, 반환1004다. 저장 슬롯4092에는 바깥 호출자 반환 주소1004가 보존됐다.

살아 있는 x와 두 보존 책임

위 고정 목록의 최종 결과와 두 저장 슬롯을 추적하라.

  1. 주소 8184에는 옛 s0의 값 77을 저장한다. 주소 8188에는 바깥 반환 주소 1004를 저장한다. 각각 프레임 sp = 8176에 오프셋 8과 12를 더한 위치다.

  2. s0=5와 g의 a0=10으로 4020에서 a0=15를 만든 뒤 옛 s0와 ra,sp를 복원한다.

결과는 15이며 마지막 s0는 77, ra는 1004, sp는 8192다.

비교할 점

중간에 s0=5로 쓰는 것이 허용되는 이유는 마지막에 입구값 77을 돌려놓기 때문이다.

우연한 임시값 보존은 호출 계약이 아니다

별도 잘못된 f가 x를 t0=5에만 두며, ABI 준수 g가 임시 t0=99로 바꾸고 a0=10을 반환한다. f가 a0+t0를 계산하면?

  1. g는 t0를 보존할 의무가 없어 99로 바꾸어도 이 호출 규약을 위반하지 않는다.

  2. 잘못된 f의 합은 10+99=109이며 요구 결과 15와 다르다.

109라는 반례로 caller가 필요한 값을 보존해야 함을 확인한다.

비교할 점

현재 한 g에서 우연히 남았던 값은 모든 g의 보장으로 확대되지 않는다.

종이와 본문으로 직접 해보기

힌트 보기

양수에서는 sub를 건너뛰며, JAL로 바뀐 ra가 복원되는지 확인하라.

풀이 보기

4≥0이어서3008로 분기하고 g는4를 돌려준다. f는3을 더해7을 반환한다. ra 저장·복원을 같은 크기의 nop으로 바꾸면 주소는 그대로이고 ra2012가 남아 f의 마지막 반환은2012로 가며 호출자1004로 가지 못한다. 두 명령을 실제로 삭제하고 코드를 재배치하면 잘못 남는 복귀 주소의 숫자도 달라지므로, 여기서는 주소를 유지하는 조건을 명시했다.

오해와 반례

ra에 반환 주소가 들어 있으니 중첩 호출에서도 별도 저장은 필요 없다.

f의2008 호출이 원래1004를2012로 덮어쓴다. 이 값은 g가 f로 돌아오는 주소이지 f가 자신의 호출자로 돌아가는 주소가 아니다. leaf 함수와 다른 함수를 호출하는 함수의 저장 필요를 구분해야 한다.

음수 즉시값과 반환 명령을 바이트로 적으면 무엇을 검증할까?

RV32I의 새 명령 addi a0,a0,−1을 직접 구성한다. I형 signed 12비트 즉시값 −1의 비트 패턴은 0xFFF다. 소스 레지스터 필드 rs1과 목적 레지스터 필드 rd에는 모두 a0의 번호 10을 넣는다. funct3 필드는 0이고 opcode 필드는 0x13이다. 단어는 (0xFFF<<20)|(10<<15)|(10<<7)|0x13=0xFFF50513이다.

별도 jalr zero,0(ra)에서는 소스 필드 rs1에 ra의 번호 1을 넣고 목적 필드 rd에 zero의 번호 0을 넣는다. funct3 필드는 0이고 opcode 필드는 0x67이다. 따라서 명령 단어는 0x00008067이다. little-endian으로 명시한 ADDI 저장 바이트는 13 05 F5 FF이고, JALR 저장 바이트는 67 80 00 00이다. 단어 값, signed 즉시값, 바이트 목록을 구별한다.

출력 목록 .text / .globl dec / dec: / addi a0,a0,−1 / jalr zero,0(ra)는 지시문 둘·레이블 하나·실제 명령 둘이다. 추가 패딩이나 데이터, 압축·완화가 없다는 조건에서 코드 8바이트다. 이 단어의 일치만으로 ELF 구조·링크·호출 보존 책임·CPU 시간까지 검증했다고 보고하지 않는다.

ISA와 ABI가 서로 답하는 질문

ISA는 명령과 레지스터, 그 연산의 뜻을 정한다. ABI는 함수가 인수와 결과를 어디에 두고 어떤 값을 보존할지 같은 프로그램 사이의 약속을 정한다. ISA만 맞춘 조각이 다른 함수와 올바르게 연결된다고 보장하지 않는다.

대상에는 레지스터 폭과 선택한 확장, ABI, 오브젝트 형식 등 정보가 필요하다. 이 절은 RV32I, 압축C확장 없음, 기본 ILP32 정수 ABI, 작은 바로 표현 가능한 명령을 선택한다. 다른 대상의 실제 컴파일 결과와 동일하다고 비교하지 않는다.

어셈블 텍스트에서 기계 바이트까지

어셈블 목록은 레이블과 지시문, 읽을 수 있는 명령을 포함한다. 레이블 자체는 위치 이름이며 명령 한 개를 뜻하지 않는다. 의사 명령은 실제 명령 하나 또는 여러 개로 바뀔 수 있으므로 목록의 모든 줄에4를 곱하면 틀릴 수 있다.

어셈블러와 오브젝트 출력은 명령 인코딩뿐 아니라 섹션·기호·아직 확정되지 않은 주소의 재배치 정보 등을 다룬다. 링크 과정은 여러 오브젝트의 기호를 연결할 수 있다. 아래는 주소 참조가 없는 한 I형 명령을 종이에서 인코딩하며 실제 오브젝트 파일을 만든 것이 아니다.

필드와 바이트의 위치

addi a0,zero,7의 I형 필드는 immediate=7,rs1=0,funct3=0,rd=10,opcode=0x13이다. 필드 경계는 immediate[31:20],rs1[19:15],funct3[14:12],rd[11:7],opcode[6:0]으로 둔다. zero는x0이고 a0는x10이라는 별칭이다.

즉시값 범위의 양쪽 경계

addi a0,a0,−2048과 +2047의 단어를 직접 구성하고 +2048의 의미 오류를 비교하라.

풀이와 답 확인

  1. ① 배율 계산 뒤 t0의 값은 2048이고, 기준 주소를 더한 뒤 유효 주소는 10240이다. LW는 값 17을 읽어 a0에 넣는다. 세 실제 명령의 코드 크기는 12바이트이고 읽기는 1회다. +2048을 직접 LW 즉시값으로 표현할 수 없지만 요청한 원소 자체는 유효하다.

  2. ② 프레임의 sp는 8176이다. 옛 s0의 슬롯 범위는 8184..8187, ra 슬롯 범위는 8188..8191이다. 주소 4016의 JAL이 ra = 4020을 만든다. g의 결과 14에 보존한 x = 7을 더해 21을 얻는다. 최종 s0는 77, ra는 1004, sp는 8192다.

  3. ③ ADDI 단어는 0xFFF50513, 바이트 13 05 F5 FF다. JALR 단어는 0x00008067, 바이트 67 80 00 00이다. 두 실제 명령의 코드 부분은 8바이트다.

주소 10240과 읽은 값 17, 코드 12바이트를 구별한다. 호출 결과는 21이고 g가 f로 돌아오는 위치는 4020, f가 바깥으로 돌아오는 위치는 1004다. 옛 s0의 값 77과 sp의 주소 8192를 복원한다. 두 단어와 바이트 목록, 코드 8바이트를 구성하며 ELF 크기·실제 시간·언어 안전성·실행 성공은 미확인이다.
