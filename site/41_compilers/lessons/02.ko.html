소단원 2.1

토큰·정규식·유한기계

이름 x12를 문자 세 개 대신 하나의 토큰으로 묶는 규칙은 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 알파벳 Σ는 허용할 기호의 집합이고 문자열은 그 기호의 유한한 나열이다. ε는 길이 0 문자열이다.

  • 토큰 종류는 ID나 NUM 같은 분류이며 lexeme은 실제 입력 조각이다. ID라는 종류와 x12라는 조각은 구별한다.

  • 함수 δ(q,a)는 상태 q와 기호 a에 대해 하나의 다음 상태를 준다. 전체 함수는 모든 허용 입력쌍에 값이 있다는 뜻이다.

학습 목표

  • 정규식이 나타내는 문자열 집합을 설명한다.

  • 숫자 토큰의 완전한 DFA를 추적하고 불변식을 증명한다.

숫자 12를 읽었을 때 이미 NUM을 반환해도 될까?

기본의 NUM과 ID에서 출발해 이번 소단원만 DEC=[0-9]+[.][0-9]+와 DOT=[.]를 추가한다. 선택 규칙 순서는 DEC, NUM, DOT, ID, WS다. NUM·ID·WS는 기본의 ASCII 정의와 같으며 부호와 지수 표기는 추가하지 않는다. DEC의 점 앞뒤에는 최소 한 숫자가 필요하다.

입력 전체가 DEC인지 묻는 인식기와 현재 위치에서 마지막으로 수용한 접두사를 보관하는 스캐너는 다르다. 12.에서는 NUM의 마지막 수용 끝은 2이고 DEC는 점 뒤 숫자를 기다린다. 다음 기호가 x라면 NUM(12)를 확정하고 점과 x는 다음 토큰에 남긴다.

유한 입력 조각을 받는 별도 인터페이스는 조각 끝을 EOF로 해석하지 않는다. 현재 수용한 조각을 더 긴 토큰으로 연장할 수 있으면 보류한다. 모든 다음 입력에 대해 선택이 변하지 않는 경계 또는 명시적인 최종 EOF에서만 확정한다. 버퍼·토큰 길이의 상한이나 시간 제한은 아직 없으므로 임의 길이 ID를 기다릴 수 있다.

먼저 확인할 개념
  • 전체 인식과 수용 접두사

    기본 NUM DFA의 상태 의미와 마지막 숫자 접두사를 DEC의 미완성 경계에 연결한다.

  • 마지막 수용 위치와 lookahead

    길이 선택 뒤 입력을 남기는 계약을 조각 경계에 적용한다.

문자에서 토큰으로

어휘 분석은 입력을 토큰 종류·입력 조각·위치의 연속으로 바꾼다. 여기의 가상 언어는 ASCII 문자만 쓰며 ID=[A-Za-z_][A-Za-z0-9_]*, NUM=[0-9]+, PLUS=+로 정한다. 연산자 +의 문자와 반복 기호 +는 문맥을 구분하고 정규식에서 문자 +는 이스케이프하거나 문자 클래스로 표시한다.

NUM 토큰 007의 조각은 그대로 007이다. 나중에 숫자 값 7로 해석하는 것은 별도 과정이다. 이 언어는 음수 부호를 NUM에 넣지 않으므로 -7을 허용하려면 MINUS 규칙을 추가한다. 토큰이 모두 있어도 괄호나 식의 문법이 맞는지는 파서가 검사한다.

정규 언어의 연산

정규식 R|S는 두 언어의 합집합, RS는 한 문자열씩 이어 붙인 집합, R*는 0번 이상의 유한 반복이다. R+는 RR*이므로 한 번 이상이다. 따라서 [0-9]*에는 ε가 있지만 [0-9]+에는 없다. 이 스캐너의 소비 규칙은 모두 비어 있지 않은 조각을 요구한다.

반복으로 여러 길이를 표현해도 상태가 문자열 길이만큼 필요하지는 않다. 숫자인지의 판정에는 시작 전, 숫자를 하나 이상 읽은 뒤, 실패한 뒤라는 세 상태면 충분하다. 정규식과 유한기계는 언어의 인식 조건을 표현하며 규칙 여러 개의 토큰 선택에는 추가 정책이 필요하다.

숫자 DFA와 상태 의미

NUM 인식 DFA의 상태는 q0,qN,qD이며 시작 q0, 수용 집합 {qN}이다. 모든 ASCII 기호 a에 대해 q0와 qN에서 a가 숫자이면 qN, 아니면 qD로 간다. qD에서는 모든 a에 qD로 간다. 이 정의는 빠진 전이 없이 전체 함수이다. ε는 q0에서 끝나므로 거부된다.

k개 기호를 읽은 상태의 불변식은 q0는 k=0, qN은 k≥1이고 지금까지 모두 숫자, qD는 비숫자를 한 번 이상 읽었다는 것이다. 시작에서 참이며 다음 기호가 숫자인지 나누면 유지된다. 따라서 끝에서 qN인 것과 입력 전체가 NUM에 속하는 것이 동치이다. 스캐너는 이 전체 문자열 인식기를 접두사 선택에 사용한다.

끝 위치는 0부터 센 반열린 구간의 오른쪽 경계다. 조각 끝에서의 보류와 실제 EOF에서의 선택을 같은 사건으로 취급하지 않는다. 실제 스트림 구현이나 flex 동작 측정은 이 손모형에 포함되지 않는다.

중간 과정을 따라가는 예제

ASCII 입력 007x에 NUM DFA를 적용한다. 전체 문자열 인정과 숫자 접두사 토큰을 구분하라.

  1. 아무 기호도 읽기 전 q0이며 수용하지 않는다.

  2. 0을 읽으면 qN이다. 길이 1의 숫자 접두사 0은 수용된다. 다음 0과 7도 qN을 유지해 접두사 007을 수용한다.

  3. x는 비숫자이므로 qD로 간다. 전체 문자열 007x는 NUM으로 거부된다.

  4. 여러 규칙을 가진 스캐너는 마지막 숫자 수용 위치 뒤로 돌아가 NUM(007)을 내고 x를 ID로 처리할 수 있다. 전체 NUM 인식과 입력 분할은 다른 질문이다.

전체 NUM 인식은 거부, NUM의 최장 접두사는 007이다.

조건을 바꾸어 비교하기

같은 접두사 뒤에서 달라지는 토큰 경계

12.x와 12.3x를 위 확장 규약으로 비교하라.

  1. 12.x에서 DEC는 숫자 12 뒤 점까지 진행하지만 x에서 실패한다. NUM의 마지막 수용 구간 [0,2)를 반환한다.

  2. 남은 점은 DOT [2,3), x는 ID [3,4)다.

  3. 12.3x에서는 DEC의 마지막 수용 [0,4)를 반환하고 x를 ID [4,5)로 둔다.

두 입력에서 첫 토큰 종류·길이가 다르며 lookahead는 다음 처리에 남는다.

비교할 점

NUM만의 전체 문자열 거부를 입력 전체 토큰화 실패로 바꾸지 않는다.

같은 입력의 두 조각과 잘못된 즉시 확정

입력 12.3을 [12.], [3]으로 전달한 뒤 최종 EOF를 보낸다. 조각마다 EOF라 부르는 구현과 비교하라.

  1. 올바른 인터페이스는 첫 조각에서 DEC 연장 가능성을 남기고 토큰 반환을 보류한다.

  2. 두 번째 조각까지 결합한 12.3은 DEC다. 마지막 EOF에서 DEC [0,4)를 확정한다.

  3. 잘못된 구현은 첫 조각에서 NUM(12), DOT(.)를 내고 두 번째 조각에서 NUM(3)을 내므로 한 번에 받은 결과와 다르다.

전달 경계를 언어 경계로 바꾸면 동일 원문도 다른 토큰열이 된다.

비교할 점

입력 수신 방식의 변화가 어휘 의미를 바꾸지 않아야 한다.

종이와 본문으로 직접 해보기

ε,0,12,1a 각각의 끝 상태를 쓰고 [0-9]*와 [0-9]+의 차이를 설명하라.

힌트 보기

처음 상태와 죽은 상태의 전이를 빼먹지 않는다.

풀이 보기

ε→q0, 0→qN, 12→qN, 1a→qD이다. *는 0회 반복을 포함해 ε를 인정하지만 +는 최소 한 숫자가 필요하다.

오해와 반례

정규식에 맞는 접두사를 하나 찾으면 입력 전체가 맞는다.

007은 숫자 접두사지만 007x 전체는 NUM이 아니다. 전체 인식은 끝 상태, 스캐너는 현재 시작점의 접두사와 다음 토큰 경계를 판단한다.

연습 1 · 값과 상태 예측

완전한 입력 .5와 5.를 각각 최종 EOF까지 처리하라. DEC 토큰이 생기는가?

힌트 1

DEC는 점 양쪽 숫자가 필요하다.

힌트 2

DOT은 단일 점을 소비한다.

풀이와 답 확인

  1. .5는 DOT(.) [0,1), NUM(5) [1,2)다.

  2. 5.는 NUM(5) [0,1), DOT(.) [1,2)다.

  3. 두 입력 모두 DEC를 만들지 않는다.

이 확장 규약에서는 점이 한쪽에만 있는 수 표기를 DEC로 허용하지 않는다.

흔한 오답에서 다시 생각하기

흔히 쓰는 실수 표기이므로 둘 다 DEC다.

다른 언어의 숫자 문법을 가져오지 말고 정의한 정규식의 양쪽 + 조건을 확인하라.

연습 2 · 오류 찾아 고치기

12.x의 DEC 탐색이 x에서 실패한 뒤 NUM(12)를 내고 커서를 4로 옮겼다. 고쳐라.

힌트 1

확정 끝은 마지막 수용 위치다.

힌트 2

탐색한 끝과 소비한 끝을 분리한다.

풀이와 답 확인

  1. NUM 구간은 [0,2)여서 확정 커서는 2다.

  2. 점 [2,3)과 x [3,4)를 이후 처리해야 한다.

  3. 커서를 4로 옮기면 유효 DOT과 ID가 사라져 입력 덮임 계약을 깨뜨린다.

탐색 실패 위치를 토큰 소비 끝으로 사용하지 않는다.

흔한 오답에서 다시 생각하기

읽어 본 기호는 이미 소비했으므로 돌아오지 않는다.

lookahead는 선택을 위한 관찰일 뿐 확정 소비가 아니다.

연습 3 · 직접 만들어 보기

12.3의 조각 분할 [1], [2.], [3]에서 한 번 수신한 것과 같은 DEC를 내는 보류 계약을 구성하라.

힌트 1

조각마다 명시적 최종 여부를 받는다.

힌트 2

미확정 접두사와 마지막 수용 위치를 보관한다.

풀이와 답 확인

  1. 세 조각에서 미확정 내용은 차례로 1, 12., 12.3으로 이어진다.

  2. 첫 두 조각은 긴 후보로 연장될 수 있고 세 번째도 뒤 숫자가 더 올 수 있어 최종 여부 없이는 보류한다.

  3. 명시적 EOF에서 DEC [0,4)를 한 번 반환하고 종료한다.

내용·수용 기록과 최종 여부를 함께 유지한다.

흔한 오답에서 다시 생각하기

세 번째 조각이 숫자면 항상 즉시 끝낼 수 있다.

다음 숫자를 더 붙인 DEC가 더 길 수 있으므로 전달 완료와 언어 경계를 구분하라.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

소비 규칙에 [0-9]*를 넣고 길이 0도 성공이라 처리하면 빈 입력에서 어떤 진행 문제가 생기는가?

힌트 1

ε가 수용된다.

힌트 2

빈 소비에서 확정 커서 변화량을 계산한다.

풀이와 답 확인

  1. 길이 0 토큰을 내면 커서는 변하지 않는다.

  2. EOF를 먼저 종료하는 분기가 없고 ε 규칙을 계속 선택하면 동일 상태에서 토큰을 무한히 낸다.

  3. 양의 길이 소비 규칙과 별도 EOF 종료를 유지하거나 빈 규칙을 제한하는 다른 진행 계약이 필요하다.

정규 언어에 ε가 있는 것과 스캐너 소비 규칙으로 안전한 것은 다르다.

상태 수가 유한하므로 토큰 수도 유한하다.

동일 상태의 반복은 유한 상태만으로 배제되지 않는다.

소단원 2.2

최장일치와 우선순위

ifx에서 if가 먼저 보이는데 왜 IF 토큰을 바로 내지 않을까?

준비 개념과 학습 목표

준비 개념

  • 접두사는 문자열 앞부분이다. if는 ifx의 길이 2 접두사이다.

  • 우선순위는 같은 조건에서 선택할 규칙의 순서이다. 여기서는 작은 규칙 번호가 더 높은 우선순위이다.

  • ID=[A-Za-z_][A-Za-z0-9_]*는 영문자/밑줄 뒤 영문자·숫자·밑줄의 0회 이상 반복이다.

학습 목표

  • 길이를 먼저, 동률에서 규칙 번호를 비교한다.

  • 마지막 수용 위치의 저장과 되돌림을 설명한다.

규칙 순서만 바꾸면 긴 이름의 앞부분을 키워드로 떼어낼 수 있을까?

이번 소단원에서는 기본 규칙에 LE=<=와 LT=<를 추가한다. 순서는 IF, ID, LE, LT, EQEQ, EQ, NUM, WS다. 길이를 먼저 비교하고 최대 길이의 동률에만 순서를 적용한다. trailing context는 없고 공백 규칙은 소비 후 버린다.

키워드를 별도 IF 규칙으로 두는 대신 ID를 최장일치로 먼저 완성한 뒤 조각이 정확히 if일 때만 IF로 재분류할 수도 있다. 이 방식의 동치는 키워드가 ID 언어에 포함되고 정확한 전체 조각 조회를 사용한다는 조건 아래에서 비교한다. 접두사 조회로 ifx까지 IF로 바꾸면 다르다.

한 기호의 DFA 전이 비용과 전체 반복의 재탐색 비용을 따로 센다. 별도 규칙 A=a와 AB=a*b, 입력 a가 N개인 단순 재시작 구현은 매번 남은 기호 전부를 읽은 뒤 A 하나만 확정할 수 있다. 실제 EOF 검사·반환·메모리 비용은 제외하고 문자 전이만 세는 자체 비용 모형이다.

먼저 확인할 개념

    추가한 두 부등호와 정확한 키워드 재분류를 기본 정책과 비교한다.

  • 정규 언어의 연결과 반복

    a*b의 긴 실패 접두사와 a의 짧은 수용을 직접 구성한다.

명세는 패턴만으로 끝나지 않는다

이 단원의 순서 있는 규칙은 1 IF=if, 2 ID=[A-Za-z_][A-Za-z0-9_]*, 3 EQEQ는 두 문자 ==, 4 EQ=단일 =, 5 NUM=[0-9]+, 6 WS=공백·탭·LF의 한 번 이상 반복이다. 혼동을 피하면 EQEQ의 입력 조각은 ==이며 이름 EQEQ와 등식 표기를 구별한다. WS는 매칭 후 토큰을 내지 않고 소비한다.

현재 위치에서 맞는 비어 있지 않은 접두사 중 길이가 가장 긴 것을 선택한다. 같은 길이인 후보들만 번호가 가장 작은 규칙을 택한다. ifx에는 IF 길이 2와 ID 길이 3이 있으므로 ID를 고른다. 정확히 if에는 길이 2 동률이 생겨 IF를 고른다.

최장일치의 추적

DFA를 이용할 때 수용 상태를 만나도 더 긴 후보가 있는지 계속 읽는다. 마지막 수용 위치와 그 상태의 우선 규칙을 저장한다. 더 이상 어떤 규칙도 연장할 수 없거나 EOF면 마지막 수용 위치로 입력 커서를 되돌리고 그 조각을 확정한다. 읽어 본 lookahead는 다음 토큰에 남아야 한다.

이 명세에는 trailing context 같은 추가 길이 정책이 없고 ε 소비 규칙도 없다. 후보가 하나도 없으면 현재 위치의 어휘 오류이다. 최장일치는 파서가 좋아할 분할을 찾아 주는 정책이 아니다. 가령 ==를 하나로 읽는 언어는 파서가 두 개의 =를 원한다고 임의로 바꾸지 않는다.

종료와 비용의 조건

매 성공·공백 소비는 길이 ℓ≥1만큼 확정 위치 p를 늘린다. 입력 길이 N이 유한하면 N−p가 감소하므로 성공 경로의 토큰화는 종료한다. 오류에서도 한 기호를 소비하거나 중단하는 계약을 정해야 같은 위치에 계속 머물지 않는다.

DFA의 한 전이는 일정 비용이라고 해도 마지막 수용 뒤 길게 읽고 되돌리는 일을 반복하면 전체 비용이 자동 O(N)은 아니다. 예를 들어 규칙 a와 a*b에 입력 a가 N개이고 b가 없으면 첫 후보를 찾은 후 멀리 실패하고 되돌리는 방식이 재탐색을 반복할 수 있다. 선형 시간 주장은 특정 구현과 되돌림 제한 또는 별도 알고리즘 조건 아래에서 한다.

소단원 2.3

스캐너 구현·오류 위치

스캐너가 @를 만나면 어느 위치를 알려 주고 어떻게 진행해야 할까?

준비 개념과 학습 목표

준비 개념

  • 반열린 구간 [s,e)는 s를 포함하고 e를 제외한다. 길이는 e−s이다.

  • 위치는 여기서 0부터 센 ASCII 기호 offset과 1부터 센 행·열이다. LF는 새 행 시작을 뜻한다.

  • 불변식은 반복 단계에서 계속 유지되는 성질이다. 스캐너의 확정 커서는 다음에 처리할 첫 기호를 가리킨다.

학습 목표

  • 완전한 작은 스캐너 계약과 오류 위치를 추적한다.

  • 탐색 커서와 확정 위치를 분리해 되돌림을 정확히 처리한다.

주석 속의 ==와 @도 바깥 토큰이나 오류로 나와야 할까?

기본 ASCII 스캐너에 별도의 주석 모드를 추가한다. NORMAL에서는 /*를 읽으면 COMMENT로 바뀌고 시작 offset·행·열을 저장한다. COMMENT에서는 첫 */까지 모든 기호를 주석으로 소비하며 일반 IF·ID·연산자·오류 규칙은 적용하지 않는다. 주석 중첩은 허용하지 않고 첫 닫힘에서 NORMAL로 돌아간다.

두 모드 모두 확정 소비한 LF에서 행을 늘리고 열을 1로 만든다. 그 밖의 ASCII 기호는 열을 하나 늘린다. COMMENT에서 최종 EOF를 만나면 저장한 시작 위치에 미종결 주석 진단을 한 번 내고 종료한다. NORMAL의 불법 기호는 기본대로 위치를 기록하고 한 기호를 소비한다. 이 정책은 flex 기본 echo와 다르다.

조각 경계에서는 /* 또는 */의 첫 기호만 보고 모드를 확정하지 않는다. 앞의 / 또는 *가 다음 조각과 결합할 수 있으므로 보관한다. 위치 갱신과 주석 시작 기록은 최종 선택한 구간에만 반영한다. 버퍼 상태와 언어 모드를 유지하는 계약이며 실제 스트림 프로그램을 실행한 증거가 아니다.

먼저 확인할 개념
  • 행·열과 확정 소비 구간

    주석을 버려도 원문 전체 덮임과 다음 토큰 위치를 유지한다.

  • 탐색과 확정 커서의 분리

    조각 사이 두 기호 구분자를 보존하고 실패 lookahead 위치를 복구한다.

입력과 결과의 계약

가상 스캐너는 유한 ASCII 문자열을 받아 토큰(kind,lexeme,[start,end),line,column)의 배열과 오류 배열을 낸다. 규칙은 IF=if, ID=[A-Za-z_][A-Za-z0-9_]*, NUM=[0-9]+, EQEQ는 두 문자 ==, EQ=단일 =, WS=[공백,탭,LF]+이며 이 순서로 동률을 푼다. 탭은 이 종이 모형에서 열을 1 늘린다. CR 및 비ASCII는 정의한 입력 범위 밖이다.

시작 확정 위치는 offset=0, line=1, column=1이다. 토큰의 행·열은 첫 기호의 위치이다. 확정 소비가 LF이면 line을 1 늘리고 column=1로 두며 그 밖은 column을 1 늘린다. byte offset, Unicode 코드포인트, 화면의 표시 열은 다른 척도이므로 실제 Unicode 스캐너에서는 어느 척도인지 명세해야 한다.

하나의 반복을 완성하기

다음 절차를 반복한다: p=N이면 EOF로 끝낸다. 그렇지 않으면 p에서 모든 규칙의 최대 양의 접두사를 찾고 최대 길이/최소 번호를 고른다. 후보가 있으면 현재 행·열을 시작으로 저장하고 WS가 아닌 토큰을 낸 뒤 선택 조각 전체를 확정 소비한다. 후보가 없으면 현재 기호와 위치의 오류를 내고 정확히 한 기호를 소비한다. 이 예제는 오류 후 계속하는 정책이다.

DFA 구현의 탐색 커서 j와 확정 커서 p를 구분한다. 탐색 중 행·열을 바꿨다가 되돌리는 대신 선택한 [p,e)만 최종 위치에 반영한다. 마지막 수용이 없을 때 EOF와 불법 기호를 구분한다. 나중에 문자열 리터럴을 넣는다면 미종결 문자열의 시작 위치와 EOF 진단도 별도 계약으로 추가해야 한다.

오류를 숨기지 않는 진행

확정한 입력 접두사는 토큰 조각·버린 공백·오류 기호로 겹침 없이 나뉜다는 불변식을 사용한다. 한 단계는 다음의 양의 길이 구간만 붙이므로 귀납적으로 덮임과 비중첩이 유지된다. 마지막 p=N이면 전체 입력을 처리한 것이다. 이는 출력 토큰만 이어 붙이면 원문과 같다는 뜻은 아니다. 공백과 오류가 빠져 있기 때문이다.

오류 하나를 소비하는 이 모형은 같은 위치를 반복하지 않는다. 첫 오류에서 즉시 중단하는 정책도 가능하지만 결과가 접두사에 한정됨을 표시해야 한다. flex는 별도 오류 규칙이 없으면 기본 echo 동작을 할 수 있으므로 생성기를 쓰는 것만으로 이 단원의 진단 계약이 구현되었다고 할 수 없다.

입력은 ASCII "a=1 @b"이다. 위 모형으로 토큰과 오류의 위치를 추적하라.

다른 문제에 적용하기

확장 스캐너의 NORMAL 규칙은 IF, ID, LE, LT, EQEQ, EQ, NUM, WS이며 /*는 COMMENT를 연다. 주석은 첫 */에서 닫고 중첩은 없다. 입력은 if_7<=if/*x */@9이고 조각은 [if_7<], [=if/*x *], [/@9]다. 명시적 최종 EOF를 마지막에 보낸다. 토큰 구간·행·열, 주석과 오류 구간, 전체 소비 길이 및 IF와 ID의 순서를 뒤집을 때의 영향을 구하라.

힌트 1

두 기호 <=와 */가 조각 경계에 걸린다. 마지막 <와 *를 다음 조각과 결합할 수 있게 보관한다.

힌트 2

LF의 offset은 11이다. 다음 *의 행·열에서 닫힘과 @를 차례대로 센다.

풀이와 답 확인

  1. ID(if_7)는 [0,4), 행 1 열 1이다. LE(<=)는 [4,6), 행 1 열 5이고 IF(if)는 [6,8), 행 1 열 7이다.

  2. 주석은 [8,14), 시작 행 1 열 9다. LF 뒤 *는 행 2 열 1이고 /는 행 2 열 2다.

  3. @ 오류는 [14,15), 행 2 열 3이다. NUM(9)은 [15,16), 행 2 열 4이며 EOF 위치는 행 2 열 5다.

  4. 소비 길이 합은 4+2+2+6+1+1=16이다. 조각 경계마다 최종 EOF로 처리하지 않고 미완성 구분자를 보존한다.

  5. ID를 IF보다 앞에 두면 [6,8)의 if만 ID로 바뀐다. 긴 if_7과 <=의 경계, 주석·오류 위치는 변하지 않는다.

토큰은 ID(if_7), LE(<=), IF(if), NUM(9)이다. 주석 [8,14)와 @ 오류 [14,15)를 포함해 16기호 전부 소비하며 마지막 위치는 행 2 열 5다. 동률 순서 변경은 마지막 키워드 분류만 바꾼다.

해결한 뒤 점검할 것

  • 전달 경계를 가로지른 <=와 */를 보존하며 한 번 수신한 결과와 같은 토큰을 구성한다.

  • 반열린 구간과 시작 행·열 및 주석 시작 진단 상태를 각각 기록한다.

  • 토큰·스킵·오류의 비중첩 전체 덮임과 동률 순서의 영향 범위를 설명하고 실제 실행과 구별한다.
