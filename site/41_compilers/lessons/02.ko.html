소단원 2.1

토큰·정규식·유한기계

이름 x12를 문자 세 개 대신 하나의 토큰으로 묶는 규칙은 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 알파벳 Σ는 허용할 기호의 집합이고 문자열은 그 기호의 유한한 나열이다. ε는 길이 0 문자열이다.

  • 토큰 종류는 ID나 NUM 같은 분류이며 lexeme은 실제 입력 조각이다. ID라는 종류와 x12라는 조각은 구별한다.

  • 함수 δ(q,a)는 상태 q와 기호 a에 대해 하나의 다음 상태를 준다. 전체 함수는 모든 허용 입력쌍에 값이 있다는 뜻이다.

학습 목표

  • 정규식이 나타내는 문자열 집합을 설명한다.

  • 숫자 토큰의 완전한 DFA를 추적하고 불변식을 증명한다.

문자에서 토큰으로

어휘 분석은 입력을 토큰 종류·입력 조각·위치의 연속으로 바꾼다. 여기의 가상 언어는 ASCII 문자만 쓰며 ID=[A-Za-z_][A-Za-z0-9_]*, NUM=[0-9]+, PLUS=+로 정한다. 연산자 +의 문자와 반복 기호 +는 문맥을 구분하고 정규식에서 문자 +는 이스케이프하거나 문자 클래스로 표시한다.

NUM 토큰 007의 조각은 그대로 007이다. 나중에 숫자 값 7로 해석하는 것은 별도 과정이다. 이 언어는 음수 부호를 NUM에 넣지 않으므로 -7을 허용하려면 MINUS 규칙을 추가한다. 토큰이 모두 있어도 괄호나 식의 문법이 맞는지는 파서가 검사한다.

정규 언어의 연산

정규식 R|S는 두 언어의 합집합, RS는 한 문자열씩 이어 붙인 집합, R*는 0번 이상의 유한 반복이다. R+는 RR*이므로 한 번 이상이다. 따라서 [0-9]*에는 ε가 있지만 [0-9]+에는 없다. 이 스캐너의 소비 규칙은 모두 비어 있지 않은 조각을 요구한다.

반복으로 여러 길이를 표현해도 상태가 문자열 길이만큼 필요하지는 않다. 숫자인지의 판정에는 시작 전, 숫자를 하나 이상 읽은 뒤, 실패한 뒤라는 세 상태면 충분하다. 정규식과 유한기계는 언어의 인식 조건을 표현하며 규칙 여러 개의 토큰 선택에는 추가 정책이 필요하다.

숫자 DFA와 상태 의미

NUM 인식 DFA의 상태는 q0,qN,qD이며 시작 q0, 수용 집합 {qN}이다. 모든 ASCII 기호 a에 대해 q0와 qN에서 a가 숫자이면 qN, 아니면 qD로 간다. qD에서는 모든 a에 qD로 간다. 이 정의는 빠진 전이 없이 전체 함수이다. ε는 q0에서 끝나므로 거부된다.

k개 기호를 읽은 상태의 불변식은 q0는 k=0, qN은 k≥1이고 지금까지 모두 숫자, qD는 비숫자를 한 번 이상 읽었다는 것이다. 시작에서 참이며 다음 기호가 숫자인지 나누면 유지된다. 따라서 끝에서 qN인 것과 입력 전체가 NUM에 속하는 것이 동치이다. 스캐너는 이 전체 문자열 인식기를 접두사 선택에 사용한다.

중간 과정을 따라가는 예제

ASCII 입력 007x에 NUM DFA를 적용한다. 전체 문자열 인정과 숫자 접두사 토큰을 구분하라.

  1. 아무 기호도 읽기 전 q0이며 수용하지 않는다.

  2. 0을 읽으면 qN이다. 길이 1의 숫자 접두사 0은 수용된다. 다음 0과 7도 qN을 유지해 접두사 007을 수용한다.

  3. x는 비숫자이므로 qD로 간다. 전체 문자열 007x는 NUM으로 거부된다.

  4. 여러 규칙을 가진 스캐너는 마지막 숫자 수용 위치 뒤로 돌아가 NUM(007)을 내고 x를 ID로 처리할 수 있다. 전체 NUM 인식과 입력 분할은 다른 질문이다.

전체 NUM 인식은 거부, NUM의 최장 접두사는 007이다.

소단원 2.2

최장일치와 우선순위

ifx에서 if가 먼저 보이는데 왜 IF 토큰을 바로 내지 않을까?

준비 개념과 학습 목표

준비 개념

  • 접두사는 문자열 앞부분이다. if는 ifx의 길이 2 접두사이다.

  • 우선순위는 같은 조건에서 선택할 규칙의 순서이다. 여기서는 작은 규칙 번호가 더 높은 우선순위이다.

  • ID=[A-Za-z_][A-Za-z0-9_]*는 영문자/밑줄 뒤 영문자·숫자·밑줄의 0회 이상 반복이다.

학습 목표

  • 길이를 먼저, 동률에서 규칙 번호를 비교한다.

  • 마지막 수용 위치의 저장과 되돌림을 설명한다.

명세는 패턴만으로 끝나지 않는다

이 단원의 순서 있는 규칙은 1 IF=if, 2 ID=[A-Za-z_][A-Za-z0-9_]*, 3 EQEQ는 두 문자 ==, 4 EQ=단일 =, 5 NUM=[0-9]+, 6 WS=공백·탭·LF의 한 번 이상 반복이다. 혼동을 피하면 EQEQ의 입력 조각은 ==이며 이름 EQEQ와 등식 표기를 구별한다. WS는 매칭 후 토큰을 내지 않고 소비한다.

현재 위치에서 맞는 비어 있지 않은 접두사 중 길이가 가장 긴 것을 선택한다. 같은 길이인 후보들만 번호가 가장 작은 규칙을 택한다. ifx에는 IF 길이 2와 ID 길이 3이 있으므로 ID를 고른다. 정확히 if에는 길이 2 동률이 생겨 IF를 고른다.

최장일치의 추적

DFA를 이용할 때 수용 상태를 만나도 더 긴 후보가 있는지 계속 읽는다. 마지막 수용 위치와 그 상태의 우선 규칙을 저장한다. 더 이상 어떤 규칙도 연장할 수 없거나 EOF면 마지막 수용 위치로 입력 커서를 되돌리고 그 조각을 확정한다. 읽어 본 lookahead는 다음 토큰에 남아야 한다.

이 명세에는 trailing context 같은 추가 길이 정책이 없고 ε 소비 규칙도 없다. 후보가 하나도 없으면 현재 위치의 어휘 오류이다. 최장일치는 파서가 좋아할 분할을 찾아 주는 정책이 아니다. 가령 ==를 하나로 읽는 언어는 파서가 두 개의 =를 원한다고 임의로 바꾸지 않는다.

종료와 비용의 조건

매 성공·공백 소비는 길이 ℓ≥1만큼 확정 위치 p를 늘린다. 입력 길이 N이 유한하면 N−p가 감소하므로 성공 경로의 토큰화는 종료한다. 오류에서도 한 기호를 소비하거나 중단하는 계약을 정해야 같은 위치에 계속 머물지 않는다.

DFA의 한 전이는 일정 비용이라고 해도 마지막 수용 뒤 길게 읽고 되돌리는 일을 반복하면 전체 비용이 자동 O(N)은 아니다. 예를 들어 규칙 a와 a*b에 입력 a가 N개이고 b가 없으면 첫 후보를 찾은 후 멀리 실패하고 되돌리는 방식이 재탐색을 반복할 수 있다. 선형 시간 주장은 특정 구현과 되돌림 제한 또는 별도 알고리즘 조건 아래에서 한다.

중간 과정을 따라가는 예제

위 여섯 규칙으로 ifx==if 7을 분할한다. 규칙의 표기는 EQEQ가 문자열 ==를 의미한다.

  1. 시작 ifx에서 길이 2 IF와 길이 3 ID를 비교해 ID(ifx)를 선택한다. 커서는 3으로 간다.

  2. 위치 3의 ==에서 EQEQ 길이 2가 EQ 길이 1보다 길어 EQEQ(==)를 낸다. 커서는 5가 된다.

  3. 위치 5의 if는 IF와 ID 길이 2 동률이므로 번호 1인 IF를 낸다. 다음 공백은 WS로 소비한다.

  4. 마지막 7은 NUM이다. EOF에서는 빈 토큰을 반복하지 않고 종료한다.

ID(ifx), EQEQ(==), IF(if), NUM(7)이다.

소단원 2.3

스캐너 구현·오류 위치

스캐너가 @를 만나면 어느 위치를 알려 주고 어떻게 진행해야 할까?

준비 개념과 학습 목표

준비 개념

  • 반열린 구간 [s,e)는 s를 포함하고 e를 제외한다. 길이는 e−s이다.

  • 위치는 여기서 0부터 센 ASCII 기호 offset과 1부터 센 행·열이다. LF는 새 행 시작을 뜻한다.

  • 불변식은 반복 단계에서 계속 유지되는 성질이다. 스캐너의 확정 커서는 다음에 처리할 첫 기호를 가리킨다.

학습 목표

  • 완전한 작은 스캐너 계약과 오류 위치를 추적한다.

  • 탐색 커서와 확정 위치를 분리해 되돌림을 정확히 처리한다.

입력과 결과의 계약

가상 스캐너는 유한 ASCII 문자열을 받아 토큰(kind,lexeme,[start,end),line,column)의 배열과 오류 배열을 낸다. 규칙은 IF=if, ID=[A-Za-z_][A-Za-z0-9_]*, NUM=[0-9]+, EQEQ는 두 문자 ==, EQ=단일 =, WS=[공백,탭,LF]+이며 이 순서로 동률을 푼다. 탭은 이 종이 모형에서 열을 1 늘린다. CR 및 비ASCII는 정의한 입력 범위 밖이다.

시작 확정 위치는 offset=0, line=1, column=1이다. 토큰의 행·열은 첫 기호의 위치이다. 확정 소비가 LF이면 line을 1 늘리고 column=1로 두며 그 밖은 column을 1 늘린다. byte offset, Unicode 코드포인트, 화면의 표시 열은 다른 척도이므로 실제 Unicode 스캐너에서는 어느 척도인지 명세해야 한다.

하나의 반복을 완성하기

다음 절차를 반복한다: p=N이면 EOF로 끝낸다. 그렇지 않으면 p에서 모든 규칙의 최대 양의 접두사를 찾고 최대 길이/최소 번호를 고른다. 후보가 있으면 현재 행·열을 시작으로 저장하고 WS가 아닌 토큰을 낸 뒤 선택 조각 전체를 확정 소비한다. 후보가 없으면 현재 기호와 위치의 오류를 내고 정확히 한 기호를 소비한다. 이 예제는 오류 후 계속하는 정책이다.

DFA 구현의 탐색 커서 j와 확정 커서 p를 구분한다. 탐색 중 행·열을 바꿨다가 되돌리는 대신 선택한 [p,e)만 최종 위치에 반영한다. 마지막 수용이 없을 때 EOF와 불법 기호를 구분한다. 나중에 문자열 리터럴을 넣는다면 미종결 문자열의 시작 위치와 EOF 진단도 별도 계약으로 추가해야 한다.

오류를 숨기지 않는 진행

확정한 입력 접두사는 토큰 조각·버린 공백·오류 기호로 겹침 없이 나뉜다는 불변식을 사용한다. 한 단계는 다음의 양의 길이 구간만 붙이므로 귀납적으로 덮임과 비중첩이 유지된다. 마지막 p=N이면 전체 입력을 처리한 것이다. 이는 출력 토큰만 이어 붙이면 원문과 같다는 뜻은 아니다. 공백과 오류가 빠져 있기 때문이다.

오류 하나를 소비하는 이 모형은 같은 위치를 반복하지 않는다. 첫 오류에서 즉시 중단하는 정책도 가능하지만 결과가 접두사에 한정됨을 표시해야 한다. flex는 별도 오류 규칙이 없으면 기본 echo 동작을 할 수 있으므로 생성기를 쓰는 것만으로 이 단원의 진단 계약이 구현되었다고 할 수 없다.

중간 과정을 따라가는 예제

입력은 ASCII "a=1 @b"이다. 위 모형으로 토큰과 오류의 위치를 추적하라.

  1. a는 ID, [0,1), 행 1 열 1이다. =는 EQ, [1,2), 행 1 열 2이다.

  2. 1은 NUM, [2,3), 행 1 열 3이다. LF [3,4)는 WS로 소비하고 다음 위치는 행 2 열 1이다.

  3. @는 어떤 규칙의 양의 접두사도 아니므로 offset 4, 행 2 열 1 오류를 내고 한 기호를 소비한다.

  4. b는 ID, [5,6), 행 2 열 2이다. p=6=N에서 EOF로 끝낸다.

ID(a), EQ(=), NUM(1), ID(b)와 @ 오류 한 개이다. 전체 처리와 구문적 올바름은 별개이다.

종이와 본문으로 직접 해보기

입력 "if @"의 IF 구간과 @ 위치를 써라. 오류 때 커서를 늘리지 않는 구현이 종료하는지도 판단하라.

힌트 보기

LF 뒤 열은 1이고 공백 두 개를 각각 센다.

풀이 보기

IF는 [0,2), 행 1 열 1이다. @는 offset 5, 행 2 열 3이다. 오류 후 같은 커서로 반복하면 같은 @를 다시 만나므로 종료하지 않는다.

오해와 반례

에러를 출력했으니 다음 문자를 이미 처리했다.

출력만 하고 커서를 그대로 두면 같은 입력에 대한 오류가 무한히 반복된다. 오류 처리의 소비량 또는 중단 조건도 계약에 포함해야 한다.

한 단계 더

입력 보관 대신 스트림을 쓰면 lookahead를 돌려놓을 버퍼와 EOF 표시가 필요하다. 토큰 시작·끝의 byte 위치를 보관하고 진단 시 행 정보를 찾는 방식도 가능하다. 구현 선택과 관계없이 소비 구간의 비중첩·정확 위치·오류 진행 계약을 같은 입력 표로 검사할 수 있지만 본 단원은 실행 시험을 수행하지 않았다.
