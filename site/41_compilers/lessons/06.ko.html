소단원 6.1

범위·선언·사용 연결

이름이 같은 두 x 는 반드시 같은 변수일까?

준비 개념과 학습 목표

준비 개념

  • 선언은 이름을 새 대상에 연결하고 사용은 그 연결을 찾는다.

  • lexical scope는 코드의 중첩 위치를 기준으로 이름을 찾는 정적 범위다.

학습 목표

  • 사용 위치를 선언 ID에 연결한다.

  • 차폐와 실행 중 값 변경을 구별한다.

같은 선언의 이름을 바꾸면 바깥 사용까지 그대로 바꿔도 될까?

새 순차 블록 모형은 기본과 같이 초기화식의 이름을 먼저 해석한 뒤 새 선언을 현재 범위에 등록한다. 대소문자를 구별하고 같은 범위 중복은 거부한다. 바깥 let x=4[D1] 뒤 안쪽 {let y=x[D2]; let x=y+1[D3]; use x[U1]; use y[U2];}와 블록 뒤 use x[U3]를 둔다. D2 초기화의 x는 D1, D3 초기화의 y는 D2, U1은 D3, U2는 D2, U3는 D1이다. 수학 정수로 값을 읽으면 D2는 4, D3은 5이며 바깥 D1은 4로 남는다. 값 계산은 실행 로그가 아니라 연결을 설명하는 손모형이다.

D3의 이름만 y로 바꾸고 U1도 y로 바꾸면 같은 안쪽 범위의 D2와 중복된다. 따라서 단순 철자 교체는 유효한 이름 변경이 아니다. D3를 주변에 없는 z로 바꾸고 D3에 연결된 U1만 z로 바꾸면 위 연결 대상 ID와 값이 유지된다. 이때 초기화식의 y와 U2 및 바깥 U3를 바꾸지 않는다. 이름 변경은 문자열의 모든 일치가 아니라 선언과 그 선언에 연결된 사용의 묶음이다.

충돌이 없는 이름도 포획을 일으킬 수 있다. 별도 let x=4[D1]; {let y=x[D2]; use x[U4];}에서 D2를 x로 바꾸면 초기화식 x는 등록 전이라 여전히 D1이지만 뒤 U4는 새 D2로 바뀐다. 지금 두 값이 모두 4여서 결과 숫자만으로 연결 변경을 놓칠 수 있다. 안쪽 선언 뒤 x=9를 넣으면 원래 프로그램은 D1을 바꾸고 변경 프로그램은 D2를 바꾼다. 블록 뒤 바깥 x의 값은 각각 9와 4다. 이 별도 모형에는 함수·클로저·동적 범위가 없다.

  • 동일 범위 중복과 기존 연결

    이름 변경이 문법적으로 가능해도 범위 규약을 위반할 수 있다.

문자열 이름에서 선언 대상으로

문법이 맞는 use x도 x의 선언이 없으면 의미 분석에서 오류가 될 수 있다. 컴파일러는 사용 노드마다 어떤 선언을 가리키는지 연결해 이후 타입 검사와 코드 생성에 사용한다. 같은 철자라도 서로 다른 선언이면 별개의 대상이다.

이 단원 자체 언어는 중첩 블록, 순차 선언, 단일 변수 이름 공간을 가진다. 선언은 초기화식의 이름을 먼저 해석한 뒤 현재 블록에 추가한다. 안쪽 블록의 같은 이름은 바깥 이름을 차폐할 수 있지만 같은 블록의 중복 선언은 금지한다. 모든 C/Java 언어의 규칙으로 일반화하지 않는다.

안쪽에서 바깥으로 찾는다

사용 위치에서 가장 안쪽의 현재 보이는 선언을 찾고 없으면 둘러싼 블록으로 나간다. 내부 x가 보이는 구간에서는 바깥 x도 존재하지만 평범한 x 사용은 내부 선언에 연결된다. 블록을 나오면 내부 선언의 범위가 끝나 바깥 연결이 다시 보인다.

이는 실행 호출 스택에서 가장 최근 값을 찾는 동적 범위와 다른 기준이다. 함수와 클로저를 포함하는 언어라면 함수가 작성된 환경과 값의 생존 기간을 따로 다뤄야 한다. 여기서는 함수 호출을 제외해 선언 연결에 집중한다.

연결 정보와 값 정보를 나눈다

심볼 기록에는 선언 ID· 타입· 위치· 범위 같은 정보가 있을 수 있다. 실행 중 정수 값이 5에서 8로 바뀌어도 해당 사용이 참조하는 선언 ID가 바뀌는 것은 아니다. 이름 해석과 값을 계산하는 실행은 서로 다른 작업이다.

오류 보고에는 사용 위치와 관련 선언 위치를 함께 남기면 이유를 설명하기 쉽다. 범위 밖 이름과 초기화 전에 읽는 문제도 구별해야 한다. 이 자체 예에서는 선언의 초기화식 처리 규칙을 명시하며 모든 definite assignment 분석을 구현했다고 주장하지 않는다.

중간 과정을 따라가는 예제

모형 코드: let x =2[D1]; {use x[U1]; let x =x +1[D2]; use x[U2];} use x[U3]. 각 use와 D2의 초기화식 x 를 선언 ID에 연결하라.

  1. 처음 D1을 바깥 블록에 등록한다.

  2. 안쪽 블록의 U1 시점에는 내부 x가 없어 D1을 찾는다.

  3. D2 초기화식은 등록 전 해석하므로 x는 D1이다. 값 계산 직관은 2 +1 =3이다.

  4. D2를 안쪽에 등록한 뒤 U2는 D2에 연결된다.

  5. 블록 종료 후 D2가 보이지 않아 U3는 D1이다. D1의 값은 이 모형에서 2로 남는다.

U1 →D1, 초기화식 x →D1,U2 →D2,U3 →D1이다.

조건을 바꾸어 비교하기

대상에 연결된 사용만 변경한다

첫 프로그램에서 D3를 z로 바꿀 때 바꿀 사용과 그대로 둘 이름을 적어라.

  1. U1은 D3를 참조하므로 z로 바꾼다. D3 초기화의 y는 D2를 참조해 그대로 둔다.

  2. U2는 D2의 y, U3는 D1의 x이므로 둘 다 그대로 둔다.

새 D3는 let z=y+1이고 U1은 use z다. 다른 연결은 유지된다.

비교할 점

모든 x를 z로 바꾸는 문자 치환과 선언별 이름 변경을 비교한다.

값이 같은 포획을 대입으로 드러낸다

별도 포획 사례에 안쪽 x=9와 블록 뒤 use x를 추가해 원래/변경 프로그램을 비교하라.

  1. 원래 내부에는 y만 새로 등록되어 x=9는 바깥 D1을 바꾼다.

  2. D2를 x로 바꾼 프로그램은 내부 x가 D2를 가리켜 D2만 9가 된다.

블록 뒤 D1 값은 원래 9, 변경 뒤 4다. 처음 값 4의 일치는 이름 연결 보존의 근거가 아니다.

비교할 점

같은 관측값 하나로 의미 보존을 인증하는 실패를 반박한다.

종이와 본문으로 직접 해보기

예제 안쪽 블록에서 D2 선언 뒤, U2 앞에 {let y =x; use y;}를 넣고 그 새 블록 바깥에서 use y를 적으면 각 연결은? U2 전에 x =8이라는 대입을 넣으면 D1/D2 중 어느 대상이 바뀌는가?

힌트 보기

새 y는 그 블록에서만 보인다. x 대입은 현재 가장 안쪽 연결을 따른다.

풀이 보기

y 초기화의 x 는 그 위치에 보이는 D2, 내부 use y는 새 y 선언이다. 블록 밖 use y는 해당 선언을 찾지 못한다. U2 전에 x =8이면 D2의 값만 바뀌며 D1 연결이나 값 2를 바꾸지 않는다.

오해와 반례

변수 이름이 같으면 하나의 표에 덮어 쓰고 블록을 나와도 그 값이 남는다.

D2는 D1을 차폐할 뿐 삭제하지 않는다. 블록 뒤 U3가 D1로 돌아오므로 단일 덮어쓰기 후 복원 없는 구조는 이 범위 규칙을 구현하지 못한다.

연습 1 · 값과 상태 예측

첫 프로그램의 D2 초기화, D3 초기화, U1/U2/U3의 선언 ID와 값을 구하라.

힌트 1

초기화식에는 선언을 아직 등록하지 않는다.

힌트 2

블록을 나오면 D3와 D2의 검색 연결이 제거된다.

풀이와 답 확인

  1. 초기화 연결은 D1과 D2다. D2의 값은 4이고 D3의 값은 5다.

  2. U1은 D3에 연결되어 값이 5다. U2는 D2에 연결되어 값이 4다. U3는 D1에 연결되어 값이 4다.

새 내부 x는 바깥 x의 값을 덮어쓰지 않는다.

풀이와 답 확인

  1. 안쪽 현재 범위에는 D2의 y가 이미 있다. 새 D3의 y는 중복으로 거부된다.

  2. 주변 선언과 사용에 없는 z를 선택하고 D3에 연결된 사용만 바꾼다.

같은 범위 중복을 피해야 한다.

소단원 6.2

심볼 테이블 구조

블록을 나오면서 가려졌던 이름을 어떻게 되살릴까?

준비 개념과 학습 목표

준비 개념

  • 맵은 이름을 심볼 기록으로 대응시키는 자료 구조다.

  • 스택은 마지막에 넣은 범위를 먼저 제거하며 해시 충돌은 서로 다른 이름이 같은 버킷을 쓰는 경우다.

학습 목표

  • 범위별 맵 스택의 lookup/push/pop을 추적한다.

  • 해시 예상 비용과 범위 깊이를 구별한다.

범위를 복원해도 과거 환경의 그림은 그대로 남을까?

새 맵 스택은 아래부터 G={x:D1,w:D0}, B={y:D2}, C={x:D3,z:D4}다. 현재 일반 조회 x/y/w/q는 각각 1/2/3/3개 맵을 검사하며 D3/D2/D0/실패를 얻는다. 중복 검사 lookupCurrent는 C만 검사한다. 따라서 C의 y 선언은 차폐로 허용되지만 z 선언은 중복이다. 검사한 맵 수는 실제 해시 키 비교 횟수나 메모리 해제 비용과 다르다.

동일 범위를 단일 이름별 바인딩 스택과 변경 로그로도 구현한다. 처음 x:[D1], w:[D0]에 B marker를 넣고 y:D2를 추가한다. C marker 뒤 x:D3와 z:D4를 추가한다. C 종료는 역순으로 z와 x의 새 머리를 제거하고 C marker를 제거한다. 그 뒤 x는 D1, y는 D2, z는 실패다. B 종료는 y와 B marker를 제거한다. marker를 넘어 되돌리면 바깥 선언을 잃는다. 총 새 바인딩 세 개는 각각 한 번 추가되고 한 번 제거되어 바인딩 작업 여섯 번이다. marker 추가/제거 네 번은 별도다.

과거 환경을 기록하는 목적도 정한다. 가변 맵 객체를 그대로 저장한 reference는 그 객체를 뒤에서 수정하면 과거 내용도 달라진 것으로 보인다. 복사한 snapshot 또는 불변 persistent 환경은 옛 버전을 보존할 수 있다. 검색용 맵을 제거하는 일과 AST 사용 노드가 참조할 선언 기록 본체를 폐기하는 일도 다르다. 이 자체 모형에서는 기록 본체를 단원 분석이 끝날 때까지 보존하며 실제 포인터 할당/해제는 수행하지 않는다. 균형 트리의 O(log n) 새 경로와 공유는 자료 구조 조건이며 어떤 무균형 트리도 같은 경계를 갖는다는 뜻이 아니다.

먼저 확인할 개념
  • 맵 스택과 변경 로그의 복원

    조회 깊이·현재 범위 검사·marker까지 되돌리는 비용을 비교한다.

  • 선언 ID와 실행 값의 분리

    검색 환경을 제거해도 이미 장식한 사용의 선언 대상은 보존한다.

맵 하나보다 범위의 층이 필요하다

심볼 테이블을 바깥에서 안쪽 순서의 맵 스택으로 구현하자. 블록 진입 때 빈 맵을 push하고 현재 범위 선언을 top에 넣는다. use는 top부터 아래로 찾으며 블록 종료 때 top을 pop한다. 차폐는 서로 다른 맵에 같은 이름이 존재하도록 허용한다.

현재 맵에만 찾는 lookupCurrent와 모든 범위를 찾는 lookup은 다른 작업이다. 중복 선언 검사는 전자로, 일반 이름 사용은 후자로 할 수 있다. 해시 버킷이 같다는 이유로 두 이름을 같은 심볼로 취급하지 않고 실제 키도 비교한다.

찾는 비용에 깊이가 들어간다

각 맵의 해시 조회를 예상 O(1)로 볼 조건이면 d개 범위를 모두 찾는 실패는 예상 O(d)다. 가장 안쪽 성공은 맵 한 번, 바깥 끝 성공은 d 번이다. 해시가 항상 최악 O(1)이라는 뜻은 아니고 충돌 처리 및 분포 조건이 필요하다.

빈 맵 push와 top 참조 제거는 단순 모형에서 O(1)이지만 메모리 해제 비용은 별도다. 불변 균형 트리를 사용하면 확장한 새 환경을 만들고 이전 환경을 유지할 수도 있다. 자료 구조 선택은 저장해야 할 환경 버전과 실제 언어 정책에 따라 달라진다.

다른 구조도 복원 정보를 보존해야 한다

단일 해시 테이블에 이름별 바인딩 스택과 변경 로그를 두는 방법도 있다. 새 선언을 앞에 추가하고 범위 진입 marker까지 변경을 기록한다. 나올 때 이번 범위 변경만 되돌리면 가려졌던 바깥 기록이 다시 보인다.

로그 구조의 종료 비용은 그 범위에 추가한 k 개 바인딩 수에 비례할 수 있다. 모든 종료가 단독 O(1)이라고 하면 잘못이다. 그러나 추가와 제거를 전체로 보면 각 바인딩이 한 번씩 처리되어 분할 상환 관점이 가능하다. 아래 활동은 먼저 이해하기 쉬운 맵 스택을 사용한다.

중간 과정을 따라가는 예제

아래에서 위로 G ={a:D1},B ={b:D2},C ={a:D3,c:D4}인 3 맵 스택이다. a,b,z를 찾을 때 방문 맵 수와 결과를 구하라.

  1. a는 C에서 바로 D3를 찾으므로 1 맵이다.

  2. b는 C에 없어 B의 D2를 찾으므로 2 맵이다.

  3. z는 C/B/G 모두에 없어 3 맵 실패다.

  4. C를 pop하면 스택G/B이며 a는 B 실패/G의 D1로 2 맵, c는 2 맵을 찾고 실패한다.

처음 a →D3/1,b →D2/2,z 실패/3이며 C 종료 후 a →D1/2다.

조건을 바꾸어 비교하기

조회의 깊이와 현재 검사 비용을 나눈다

G/B/C에서 y 일반 조회와 현재 범위 중복 검사 뒤 새 y:D5를 추가하고 C를 종료하라.

  1. 일반 조회는 C 실패/B 성공으로 두 맵이다. 현재 검사 C에는 y가 없어 허용한다.

  2. 추가 뒤 y는 C의 D5를 한 맵에서 찾고 C 종료 뒤 B의 D2를 한 맵에서 찾는다.

차폐를 허용하면서 두 시점의 y 연결을 정확히 복원한다.

비교할 점

바깥까지 중복 검사하여 정상 차폐를 거부하는 구현과 비교한다.

로그 marker 밖을 건드리지 않는다

세 새 바인딩 y/x/z와 두 marker의 추가/제거 작업 수를 구하라.

  1. 새 바인딩 세 개에 각각 추가 한 번/제거 한 번이므로 여섯 번이다.

  2. B와 C의 marker는 각각 추가/제거해 네 번이다.

이 명시한 작업 모형의 합계는 10번이다. 조회·해시 충돌·할당·기본 G 구성은 합계에서 제외한다.

비교할 점

상환 O(1)을 C 종료의 상수 한 번 제거로 오해하지 않는다.

연습 1 · 값과 상태 예측

연습 3 · 직접 만들어 보기

현재 x:D3를 이미 참조하는 AST 사용을 장식한 뒤 C를 나간다. 검색 복원과 기록 수명을 양립하는 소유 정책을 작성하라.

힌트 1

검색 맵과 선언 기록 저장소를 구분한다.

힌트 2

사용 노드에는 안정적인 선언 ID를 둔다.

풀이와 답 확인

  1. 맵/로그의 C 바인딩을 제거하여 다음 조회 x는 D1로 만든다.

  2. 선언 저장소의 D3 기록은 분석 전체가 끝날 때까지 유지하고 기존 사용 노드 ID는 D3로 남긴다.

뒤 조회 D1과 앞 사용 D3가 동시에 올바르다. 실제 메모리 구현은 별도 검증이다.

흔한 오답에서 다시 생각하기

뒤 조회가 D1이므로 모든 AST의 x 연결도 D1로 덮어쓴다.

사용은 자기 위치의 환경에 연결된다. 나중 환경을 소급 적용하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

가변 맵 M={x:D1}의 reference R과 별도 복사 S를 저장한 뒤 M[x]=D3를 수행한다. R/S의 x와 불변 새 환경 대안을 설명하라.

힌트 1

R은 동일 객체, S는 변경 전 사본이다.

힌트 2

불변 대안은 옛 환경을 변경하지 않는다.

풀이와 답 확인

  1. R에서 x는 D3, S에서 x는 D1이다. 이 단순 모형의 복사는 매핑 자체를 복사하며 공유 기록의 가변 내용까지 복제한 것은 아니다.

  2. 불변 E0={x:D1}에서 새 E1={x:D3}를 만들면 E0의 x는 D1로 남는다.

환경 버전 보존과 기록 내부 가변성은 별도 계약이다.

소단원 6.3

미정의·중복 선언 진단

닫는 괄호가 모두 맞아도 프로그램의 이름은 잘못될 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 미정의 사용은 보이는 환경에 이름이 없는 경우다.

  • 자체 언어는 같은 범위 중복을 금지하고 내부 범위 차폐를 허용하며 초기화식은 새 이름 등록 전에 해석한다.

학습 목표

  • 사용 위치와 기존 선언 위치를 포함해 진단한다.

  • 진단 이후 환경을 보존해 불필요한 후속 오류를 줄인다.

실패한 선언을 등록하지 않는 정책은 뒤 오류를 어떻게 바꿀까?

새 진단 모형은 선언의 초기화식을 등록 전에 검사하고 초기화 실패 또는 현재 범위 중복이면 새 선언을 등록하지 않는다. 미정의 사용도 정상 선언을 만들지 않는다. 이는 이 보강에서 명시한 추가 복구 정책이며 기본이 모든 초기화 실패의 등록 방식을 정했다는 뜻은 아니다. 중복 여부와 초기화식의 이름 검사는 둘 다 독립 수행하고, 같은 이름의 기존 유효 기록은 유지한다. 오류는 이름 사용 위치별로 보고해 반복된 미정의 사용을 자동으로 하나로 합치지 않는다.

빈 환경의 행 1 let q=q+1[D1]은 초기화 q 미정의로 실패하며 q를 등록하지 않는다. 행 2 use q[U1]도 미정의다. 행 3 let q=7[D2]은 정상 등록하고 행 4 let q=r[D3]는 현재 q 중복과 초기화 r 미정의 두 진단을 낸다. D3를 등록하지 않아 행 5 use q[U2]는 D2에 연결된다. 전체 진단은 네 개이며 행 1과 행 2의 q는 두 위치의 기록이다. 이 장부는 실제 컴파일러 오류 출력이 아니다.

오류 수의 감소만으로 올바른 복구를 선택할 수 없다. 행 1 뒤 정상 q를 자동 등록하면 행 2의 진단이 사라질 수 있지만 유효 선언 없이 성공 연결을 만든다. 반대로 D3를 덮어써 r 오류를 표시하면 유효 D2를 잃어 뒤의 사용까지 바뀐다. 오류 노드를 별도로 남겨 분석을 계속하는 정책과 잘못된 프로그램을 실행 허용하는 정책은 다르다. 여기서는 정상 실행/코드 생성의 허가를 내리지 않는다.

먼저 확인할 개념
  • 오류 위치와 기존 유효 선언의 보존

    미정의 사용과 중복을 독립 기록하고 후속 연결을 감사한다.

  • 등록 전 초기화와 순차 가시성

    실패 초기화 뒤의 별도 선언은 앞 사용을 소급 복구하지 않는다.

오류의 종류와 기준을 적는다

use q가 문법적으로 올바른 토큰과 AST를 만들어도 현재 보이는 q가 없으면 미정의 사용이다. 중복 선언은 동일 범위의 이름 정책을 위반하는 새 선언이며 다른 블록의 차폐와는 구별된다. 한 규칙을 모든 언어의 overloading·namespace에 그대로 적용하지 않는다.

오류에는 파일/ 행/ 열과 문제 이름을 적고 중복이면 이전 선언 위치도 제시한다. x와 X를 다른 이름으로 보는 이 예제에서는 대소문자 변경이 의도인지 판단하지 않고 명시한 이름 비교를 따른다. 비슷한 철자를 제안하는 기능도 실제 의미 분석을 대체하지 않는다.

진단 뒤에도 무엇을 유지할지 정한다

중복 선언을 발견했을 때 기존 기록을 그대로 남기는 복구 정책을 정하자. 그러면 뒤의 use x는 첫 유효 선언에 연결할 수 있다. 새 기록으로 덮어 쓴다면 원래 타입 정보가 바뀌어 파생 오류가 생길 수 있으므로 복구 선택을 기록한다.

미정의 사용은 오류 표시를 가진 AST 노드로 남겨 다른 독립 오류를 계속 찾을 수 있다. 여기서는 미정의 사용이 임의의 정상 선언을 만들어 주지 않는다고 정한다. 실제 컴파일러의 오류 타입 전파와 최적화 억제는 추가 정책이며 아래 결과는 종이 진단 표다.

등록 시점은 초기화식의 해석을 바꾼다

순차 선언 언어에서 let q =q +1을 만나면 등록 전 보이는 q를 먼저 찾는다. 바깥 q가 있으면 그것을 읽고, 없으면 미정의다. 선언을 미리 등록하고 미초기화 상태를 검사하는 언어에서는 다른 진단이 가능하므로 용어를 혼용하지 않는다.

함수들의 상호 참조는 헤더를 먼저 수집한 뒤 본문을 검사하는 별도 설계로 해결할 수 있다. 그렇다고 모든 지역 변수 선언을 앞당겨 보이게 해야 하는 것은 아니다. 언어가 무엇을 허용하는지 먼저 정하고 심볼 테이블의 순회를 맞춘다.

한 단계 더

미정의 이름 두 번을 하나의 오류로 합칠지 각 위치에서 보고할지 정책을 정해 보자. 실제 프로그램 의미가 잘못된 위치를 놓치지 않되 첫 오류의 파생 메시지가 지나치게 늘지 않도록 원인 연결을 남긴다. 이 단원은 특정 컴파일러의 실제 출력 로그를 제공하지 않는다.

다른 문제에 적용하기

새 분석 장부의 세 부분을 작성하라. ① 바깥 let x=4[D1]; 안쪽 {let y=x[D2]; let x=y+1[D3]; use x[U1]; use y[U2];} 뒤 use x[U3]에서 초기화/사용의 연결 ID를 적고 D3만 z로 안전하게 바꾸라. ② G={x:D1,w:D0}, B={y:D2}, C={x:D3,z:D4}의 x/y/w/q 일반 조회 맵 수와 C 종료 뒤 결과를 적고, 별도 로그 구현의 C/B 종료 작업을 marker와 바인딩별로 세라. ③ 빈 환경의 다섯 행 let q=q+1[D1]; use q[U1]; let q=7[D2]; let q=r[D3]; use q[U2]를 실패 선언 미등록·중복/초기화 독립 검사 정책으로 감사하라. 실제 컴파일러나 메모리 관리 구현은 실행하지 않는다.

힌트 1

① 새 선언 등록 전의 환경과 등록 뒤 환경을 나눈다. 이름 변경은 D3의 사용에만 적용한다.

힌트 2

② 조회는 C/B/G 순서이며 로그는 C marker까지만 되돌린다. ③ 행 1 실패와 행 4 두 원인을 따로 기록한다.

풀이와 답 확인

  1. ① D2의 초기화식 x는 D1에 연결된다. D3의 초기화식 y는 D2에 연결된다. U1은 D3에 연결되어 값이 5이고, U2는 D2에 연결되어 값이 4이며, U3는 D1에 연결되어 값이 4다. D3를 let z=y+1로 바꾸고 U1을 use z로 바꾼다. U2와 U3는 그대로 둔다.

  2. ② C가 활성인 처음 상태에서 x 조회는 맵 1개를 검사하여 D3를 찾는다. y 조회는 맵 2개를 검사하여 D2를 찾고, w 조회는 맵 3개를 검사하여 D0를 찾는다. q 조회는 맵 3개를 검사한 뒤 실패한다. C가 종료되면 x 조회는 맵 2개를 검사하여 D1을 찾고, y 조회는 맵 1개를 검사하여 D2를 찾는다. z 조회는 맵 2개를 검사한 뒤 실패하며, w 조회는 맵 2개를 검사하여 D0를 찾는다.

  3. 로그의 C 종료는 z와 x 바인딩 두 개 및 C marker를 제거한다. B 종료는 y 바인딩 하나와 B marker를 제거한다. 총 추가/제거 바인딩 작업은 6번, marker 작업은 4번으로 별도 모형의 합계 10번이다.

  4. ③ 행 1 초기화 q 미정의와 행 2 U1 미정의, 행 4 q 중복/r 미정의로 네 진단이다. D1/D3를 등록하지 않고 D2를 유지한다. U2는 D2이며 값은 7이다.

이름 변경은 선언별로 수행하고 범위 종료는 해당 범위만 복원한다. U1의 값은 5, U2의 값은 4, U3의 값은 4이며 각각 D3, D2, D1에 연결된다. 조회 깊이와 로그의 바인딩 작업 6번 및 marker 작업 4번, 실패 선언 장부의 네 진단과 최종 D2를 함께 기록한다.

해결한 뒤 점검할 것

  • 등록 시점을 적용해 두 초기화와 세 사용의 ID·값을 맞추고 신선한 z로 D3의 사용만 바꾼다.

  • 현재 검사와 일반 조회를 나누며 모든 성공/실패의 맵 수와 C 종료 복원을 확인한다.

  • 바인딩/marker/검색 맵/선언 본체를 구분하고 별도 작업 모형의 제외 항목을 명시한다.

  • 실패 선언 미등록·두 독립 진단 조건을 유지하고 실제 compiler/API/메모리/학생 미수행을 구별한다.
