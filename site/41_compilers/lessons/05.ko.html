소단원 5.1

shift·reduce와 LR 항목

입력을 왼쪽부터 읽으면서 언제 여러 기호를 하나의 구문으로 묶을까?

준비 개념과 학습 목표

준비 개념

  • 터미널은 입력 토큰, 비터미널은 문법으로 정의한 구문 이름이다.

  • 문법 S→aS|b는 b,ab,aab처럼 a가0번 이상 나온 뒤 b가 한 번 오는 문자열을 만든다. $는 실제 토큰이 아닌 입력 끝 표시다.

학습 목표

  • 항목의 점 위치와 closure를 구한다.

  • 상태 스택에서 shift·reduce·accept를 추적한다.

빈 우변을 줄일 때 상태 stack이 오히려 길어질 수 있을까?

새 문법은 S→A c, A→a A | ε이고 시작 규칙은 S′→S다. 언어는 a가 0번 이상 나온 뒤 c가 한 번 오는 열이다. $는 입력 끝 표시이며 shift 횟수에 넣지 않는다. stack에는 상태 번호만 저장하고 reduce는 우변 기호 수만큼 상태를 제거한 뒤 남은 상태의 좌변 GOTO를 하나 추가한다.

상태를 I0={S′→·S,S→·A c,A→·a A,A→·}, I1={A→a·A,A→·a A,A→·}, I2={S→A·c}, I3={S′→S·}, I4={A→a A·}, I5={S→A c·}로 정한다. 이동은 0/a→1, 1/a→1, 0/A→2, 1/A→4, 0/S→3, 2/c→5다. 빈 항목 A→·는 완료 항목이다.

FOLLOW(A)={c}, FOLLOW(S)={$}를 써서 SLR 행동을 만든다. 0과 1은 a에서 shift 1, c에서 A→ε 축약이다. 2는 c에서 shift 5, 4는 c에서 A→a A 축약, 5는 $에서 S→A c 축약, 3은 $에서 accept다. 다른 칸은 오류다. LR(0)이라면 0/1의 빈 축약을 a에도 넣어 shift와 충돌하지만 이 FOLLOW 제한은 충돌을 피한다.

먼저 확인할 개념
  • 상태를 제거한 뒤 좌변 GOTO

    ε의 길이 0과 일반 길이 2의 축약을 같은 stack 규칙으로 비교한다.

  • SLR의 FOLLOW 열 제한

    완료 항목이 있어도 모든 다음 토큰에서 축약하지 않는 이유를 확인한다.

읽는 행동과 묶는 행동

shift는 다음 입력 토큰을 읽고 스택에 그 기호와 새 상태를 넣는다. reduce는 스택 위의 우변을 해당 규칙의 좌변 비터미널로 묶으며 새 입력을 읽지 않는다. 아래 문법에서 ab를 읽으면 먼저 b를 S로 줄인 뒤 aS를 S로 줄일 수 있다. 순서는 오른쪽 유도 과정을 거꾸로 따라간다.

스택의 기호 열과 상태 열을 함께 기록하면 어느 문맥에서 규칙을 적용하는지 볼 수 있다. 길이 k의 우변을 줄일 때 기호 k개와 대응하는 상태 k개를 제거하고 남은 상태에서 좌변의 GOTO를 찾는다. ε처럼 길이0인 우변은 이 예시에 없지만 k=0일 때 아무 상태도 제거하지 않는다는 규칙은 유지된다.

항목은 규칙의 진행 위치다

증강 규칙 S′→S를 추가한다. S→a·S는 a를 인식했고 다음에 S를 인식해야 한다는 항목이다. 점 뒤가 비터미널이면 그 비터미널의 규칙을 점이 앞에 있는 형태로 예측해 closure에 넣는다. 예를 들어 S→a·S에 S→·aS와 S→·b를 추가한다. 점은 실제 입력 문자나 곱셈 연산이 아니다.

초기 I0={S′→·S,S→·aS,S→·b}다. I1={S→a·S,S→·aS,S→·b}, I2={S→b·}, I3={S′→S·}, I4={S→aS·}로 번호를 정한다. I0에서 a는I1,b는I2,S는I3이고 I1에서 a는I1,b는I2,S는I4다. 이동은 점을 해당 기호 뒤로 옮긴 후 closure를 취한다.

상태표와 수용 조건

이 문법은 완료 항목이 있는 I2/I4에 shift 후보가 없어 LR(0) 표를 만들 수 있다. I2는 S→b로, I4는 S→aS로 줄인다. 증강 완료 I3는 입력 끝에서 accept한다. 남은 입력이 있는데 단지 S를 만들었다고 수용하면 잘못된 문자열까지 통과시킬 수 있다.

표의 빈 행동 칸은 오류다. 스택에 S라는 이름이 있다는 사실만으로 입력 전체가 유효하다는 뜻은 아니다. 예를 들어 ba는 초기 b를 줄여 I3에 가더라도 lookahead a가 남아 accept하지 않는다. 이 단원은 손으로 구성한 작은 표이며 실제 parser generator를 실행한 로그가 아니다.

상태 개수에는 처음의 상태 0도 포함한다. 첫 행의 빈 축약은 입력 c를 소비하지 않고 stack 길이를 3에서 4로 늘린다. 빈 축약과 입력 끝 accept를 서로 다른 행동으로 읽는다.

중간 과정을 따라가는 예제

위5상태 번호로 ab$를 처리하라. 상태 스택은 처음[0]이다.

  1. a를 shift해 기호[a], 상태[0,1], 남은b$다.

  2. b를 shift해 기호[a,b], 상태[0,1,2], 남은$다.

  3. I2에서 S→b로 reduce한다. 상태2를 제거한 뒤 GOTO(1,S)=4라 기호[a,S], 상태[0,1,4]다. 입력$는 그대로다.

  4. I4에서 S→aS로 reduce해 두 상태1,4를 제거한다. GOTO(0,S)=3이라 기호[S], 상태[0,3]이다.

  5. I3에서 입력끝$이므로 accept한다. shift2회/reduce2회다.

ab는 수용된다. reduce는 두 번 모두 새 입력을 소비하지 않는다.

조건을 바꾸어 비교하기

빈 축약 뒤 두 번 이어지는 축약

aac$에서 모든 상태 변화를 추적하고 shift/reduce 및 최대 상태 개수를 구하라.

  1. a를 두 번 shift하면 [0,1,1]이며 lookahead는 c다.

  2. A→ε로 [0,1,1,4], A→a A로 [0,1,4], 다시 A→a A로 [0,2]다. 이 세 축약은 모두 같은 c를 본다.

  3. c를 shift해 [0,2,5], S→A c로 [0,3]이다. $에서 accept하며 $는 shift하지 않는다.

shift는 3번, reduce는 4번이며 최대 상태 개수는 4개다.

비교할 점

기본의 끝 b 축약과 달리 ε가 입력을 읽지 않고 stack을 늘리는 순간을 포함한다.

우연한 수락이 빠진 의미 행동을 숨긴다

별도 잘못된 구현이 [0,1,1]의 ε 축약에서 상태 하나를 제거하고 GOTO를 추가한다. 이후 같은 표를 따르면 aac를 수락할 수 있는지와 의미 노드 수를 감사하라. A→ε의 count는 0, A→a A의 count는 오른쪽 count+1이다.

  1. 잘못 제거하면 [0,1]에서 GOTO(1,A)=4를 넣어 [0,1,4]가 된다. 이는 이미 한 a를 축약한 정상 상태처럼 보인다.

  2. 다음 A→a A 한 번만 수행해 [0,2], c shift/S 축약으로 수락할 수 있다. 하지만 count는 1이다.

  3. 정상 경로는 빈 축약 뒤 a A를 두 번 줄여 count가 2다. 실제 읽은 두 a와 의미 count를 대조한다.

수락 여부만 같아도 읽은 a의 의미 count가 2에서 1로 손실된다. 빈 축약은 상태를 제거하지 않게 고친다.

비교할 점

최종 승인만 대조하는 시험이 중간 stack과 의미 손실을 놓치는 반례다.

종이와 본문으로 직접 해보기

오해와 반례

reduce할 때 다음 입력 토큰도 반드시 하나 읽는다.

ab에서 b→S reduce와 aS→S reduce가 모두 같은 입력끝$을 보고 이어진다. reduce는 스택 구조를 바꾸고 shift가 입력을 소비한다. 둘을 혼동하면 aab에서 필요한 연속 축약이 불가능하다.

연습 1 · 값과 상태 예측

같은 표로 c$와 ac$의 shift/reduce 횟수와 최대 상태 개수를 구하라.

힌트 1

c 직전의 빈 A 축약을 먼저 넣는다.

힌트 2

상태 0을 포함해 가장 긴 stack을 센다.

풀이와 답 확인

  1. c$는 [0]→[0,2]→[0,2,5]→[0,3]이며 shift 1번, reduce 2번, 최대 3개다.

  2. ac$는 [0,1]→[0,1,4]→[0,2]→[0,2,5]→[0,3]이며 shift 2번, reduce 3번, 최대 3개다.

두 입력 모두 수용된다. 빈 A의 축약도 reduce 횟수에 넣는다.

흔한 오답에서 다시 생각하기

빈 규칙은 아무 일도 하지 않아 횟수에서 뺀다.

입력을 읽지 않아도 GOTO와 의미 행동을 수행하는 실제 표 행동이다.

연습 2 · 오류 찾아 고치기

A→ε에서 입력 c도 함께 소비하여 다음 상태 2로 진행하는 구현을 고쳐라.

힌트 1

상태 2에서 요구하는 terminal을 본다.

힌트 2

입력 소비 장부와 규칙의 우변 길이를 비교한다.

풀이와 답 확인

  1. A→ε 뒤 입력은 여전히 c$여야 한다. 상태 2의 c shift가 그 c를 소비한다.

  2. 빈 축약에서 미리 소비하면 상태 2의 lookahead가 $가 되어 오류다.

빈 축약의 입력 위치를 그대로 두고 상태 2에서 c를 읽는다.

흔한 오답에서 다시 생각하기

빈 생산이 c를 생성하므로 소비해도 된다.

ε는 c를 생성하지 않는다. c의 소유 규칙은 S→A c다.

연습 3 · 직접 만들어 보기

SLR 표의 상태 0/1/2/3/4/5와 a,c,$ 열을 모두 구성하고 빈 입력을 처리하라.

힌트 1

진입 문단의 shift와 완료 항목을 옮긴다.

힌트 2

FOLLOW에 없는 완료 행동을 추가하지 않는다.

풀이와 답 확인

  1. 0과 1은 a에서 s1, c에서 A→ε, $에서 오류다. 2는 c에서 s5이며 a/$는 오류다.

  2. 3은 $에서 accept, 4는 c에서 A→a A, 5는 $에서 S→A c다. 이 세 상태의 나머지 열은 오류다.

  3. 빈 입력은 처음 상태 0/$ 오류다. A가 비어도 필수 c는 남는다.

빈 입력은 거부하고 a가 없는 c$는 허용한다. c 뒤에 다른 문법 token이 남으면 전체 끝 조건을 만족하지 않아 거부한다.

흔한 오답에서 다시 생각하기

nullable A가 있으므로 시작 S도 nullable이다.

S에는 필수 terminal c가 있어 빈 문자열을 만들 수 없다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

a가 k개인 a^k c에서 k≥0일 때 shift/reduce 수와 최대 상태 개수의 식을 구하라.

힌트 1

빈 A 1회와 a A의 k회, 마지막 S 1회를 구별한다.

힌트 2

k=0에서는 c shift 뒤 상태가 [0,2,5]인 경계도 확인한다.

풀이와 답 확인

  1. shift는 k+1번, reduce는 k+2번이다.

  2. 빈 축약 직후 상태는 k+2개이고 c shift 직후 상태는 3개다. 최대는 max(k+2,3)개다.

상태 개수 식은 k=0도 포함한다. 실제 메모리 바이트나 성능의 식으로 바꾸지 않는다.

흔한 오답에서 다시 생각하기

최대 상태는 항상 k+2개다.

k=0이면 그 값은 2지만 c를 shift한 stack에는 상태가 3개 있다.

한 단계 더

a가 k개이고 끝에 b가 하나 있는 입력의 shift는 k+1회, reduce는 b규칙1회와 aS규칙k회다. k=0의 b도 이 식을 만족한다. 다만 일반 문법은 ε규칙·오류 처리 등이 있어 이 횟수 공식을 그대로 적용할 수 없다.

SLR·LR·LALR 개요

같은 축약 항목도 어떤 다음 토큰에서만 적용해야 한다면?

준비 개념과 학습 목표

준비 개념

  • FOLLOW(A)는 어떤 완전한 유도 문맥에서 A 다음에 올 수 있는 터미널 집합이다.

  • lookahead는 결정을 위해 보지만 아직 소비하지 않은 다음 입력 토큰이다. LR(1) 항목은 규칙·점·완료 뒤 허용 lookahead를 가진다.

학습 목표

  • SLR의 FOLLOW 제한과 LR(1)의 문맥 정보를 구분한다.

  • LALR 병합이 줄이는 정보와 충돌을 계산한다.

같은 비터미널의 전역 FOLLOW를 현재 상태에서도 모두 써야 할까?

새 대입 문법은 S→L = R | R, L→* R | id, R→L이며 S′→S로 증강한다. 대입 대안에는 =가 한 번 등장하고 S→R 대안에는 없다. 따라서 입력에는 =가 최대 한 번 등장한다. 그리고 *는 이 문법에서 역참조 표기다. 실제 저장장소 접근이나 타입 검사는 하지 않는다. FOLLOW(L)=FOLLOW(R)={=,$}다. L이 S→L = R의 왼쪽에 있어 =가 들어가고 L/R의 서로 다른 사용 문맥이 이 집합에 합쳐진다.

처음 상태에서 L을 인식해 이동한 LR(0) 상태에는 S→L·=R과 R→L·가 함께 있다. SLR은 R의 전역 FOLLOW에서 =에도 reduce를 넣고 동시에 = shift를 넣으므로 한 칸 충돌이다. 반면 이 도달 문맥의 LR(1) 완료 항목은 [R→L·,$]다. =에서는 shift, $에서는 reduce를 선택한다. SLR 충돌을 바로 문법의 두 parse tree 증거라고 부르지 않는다.

LR(1) closure는 [X→α·A β,t]에서 A의 시작 항목에 FIRST(βt)를 전달한다. 별도 X→A B, B→b | ε인 문맥에서 시작 항목의 t=$이면 A의 lookahead는 {b,$}다. β가 비어질 수 없는 terminal b이면 {b}만 전달한다. lookahead는 A가 완료된 뒤의 기호이며 현재 점 뒤의 A와 같은 이름이 아니다.

    전역 FOLLOW의 합집합과 한 항목의 도달 문맥을 분리한다.

  • 항목 이동과 closure

SLR은 문법 전체의 FOLLOW를 쓴다

S→a|ab에서 a를 읽은 상태에는 S→a·와 S→a·b가 함께 있다. LR(0)이 모든 다음 토큰에서 첫 규칙을 줄이면 b에서는 shift와 reduce가 충돌한다. FOLLOW(S)={$}라 SLR은 $에서만 reduce하고 b에서는 shift하여 이 문제를 해결한다.

FOLLOW는 비터미널 전체에 대한 집합이라 서로 다른 도달 문맥을 합칠 수 있다. 어떤 문법에서는 실제 한 상태에서 허용될 토큰보다 넓어져 불필요한 충돌이 남는다. SLR 충돌이 있다고 언어가 모호하다고 즉시 결론 내리면 안 된다. 더 정교한 상태 구성이 해결할 수 있다.

LR(1)은 항목마다 문맥을 남긴다

[A→α·β,t]의 t는 β까지 완성한 A 뒤에 올 수 있는 토큰이다. 점 바로 뒤의 β 첫 토큰과 같다는 뜻이 아니다. 예를 들어 [S→a·b,$]는 다음에 b를 인식하고 그 뒤 S가 완료되면 $를 허용한다. 완료 항목 [S→ab·,$]일 때만 $에서 해당 reduce를 넣는다.

closure에서 [A→α·Bβ,t]를 펼칠 때 B의 규칙에 FIRST(βt)의 lookahead를 전달한다. FIRST는 주어진 열이 처음 생성할 수 있는 터미널들이며 β가 빈 문자열을 만들면 t도 포함될 수 있다. 상태 이동은 lookahead를 보존하여 점을 옮긴다. 아래 예제는 ε규칙이 없어 FIRST 계산이 단순하다.

LALR은 같은 core를 합친다

문법 S→aAd|bAe|aBe|bBd, A→c,B→c를 보자. ac 뒤의 LR(1) 상태에는 [A→c·,d]와 [B→c·,e], bc 뒤에는 [A→c·,e]와 [B→c·,d]가 있다. 각 상태에서 d/e별 reduce는 하나뿐이다. 하지만 lookahead를 뺀 core가 같아 LALR로 합치면 A와 B 모두{d,e}를 갖는다.

병합 뒤 d와 e 각각에 두 reduce가 생긴다. 더 작은 표를 얻는 과정이 문맥 구분을 잃은 사례다. 이 두 상태의 계산은 병합 위험을 보이는 예이며 모든 문법의 LALR이 충돌한다는 뜻은 아니다. canonical LR(1), LALR 등 용어를 구별하고 실제 도구의 선택 옵션과 표를 확인해야 한다.

SLR 충돌의 원인을 상태 문맥에서 찾는다

FOLLOW(L/R)와 처음 L 뒤 상태의 SLR/LR(1) 후보를 설명하라.

  1. S→L = R에서 =가 FOLLOW(L)에 들어간다. S→R의 끝에서 $가 FOLLOW(R)에 들어가고 R→L 및 L→*R가 서로 전달해 둘 다 {=,$}다.

  2. 처음 R을 기대하는 [S→·R,$]는 [R→·L,$]를 예측한다. 그 L을 완성한 뒤 R→L의 완료 lookahead는 $를 유지한다.

  3. S→L·=R는 = shift를 요구하지만 [R→L·,$]는 = reduce를 요구하지 않는다.

선택 상태의 LR(1) = 칸은 단일 shift다. 문법 전체 FOLLOW 집합은 그대로 {=,$}다.

비교할 점

기본 S→a|ab의 FOLLOW 제한으로 해결한 경우보다 전역 FOLLOW 자체가 너무 넓은 경우를 본다.

nullable 꼬리와 terminal 꼬리를 비교한다

별도 [X→·A B,$], B→b|ε와 [Y→·A b,$]에서 A 시작 항목의 lookahead를 비교하라.

  1. 첫 문맥에서 B가 b를 만들면 b가 오고 B가 비면 $가 온다. FIRST(B$)={b,$}다.

  2. 둘째 문맥의 terminal b는 비어질 수 없다. FIRST(b$)={b}다.

첫 전달은 {b,$}, 둘째 전달은 {b}다. ε 자체를 입력 lookahead 열로 넣지 않는다.

비교할 점

한 토큰 뒤를 본다는 표현을 무조건 현재 t만 복사하는 규칙으로 오해하지 않는다.

소단원 5.3

충돌 진단과 파서 도구

충돌 경고 하나를 숨기면 내가 의도한 계산 순서도 확인된 것일까?

준비 개념과 학습 목표

준비 개념

  • shift/reduce 충돌은 한 표 칸에서 입력 소비와 축약이 경쟁하는 경우다.

  • reduce/reduce 충돌은 한 표 칸에서 서로 다른 규칙 축약이 경쟁하는 경우다.

학습 목표

  • 충돌 상태·토큰·후보·예제 입력을 함께 진단한다.

  • 우선순위 선택이 의미를 바꾸는 사례를 계산한다.

같은 충돌 수에서 다른 연산 정책을 선택할 수 있을까?

새 수학적 표현 문법은 E→E ^ E | − E | n이다. n은 양의 정수 리터럴이고 ^는 거듭제곱, −는 별도 단항 token이다. 원하는 정책은 ^가 오른쪽 결합이며 단항 −보다 높은 우선순위라는 것이다. 고정 폭 overflow와 실제 코드 실행은 제외한다.

2^3^2에서는 다음 ^를 shift해 오른쪽 구조 Pow(2,Pow(3,2))를 만들면 512다. reduce로 왼쪽 구조 Pow(Pow(2,3),2)를 만들면 64다. −2^2에서는 낮은 단항 우선순위로 ^를 먼저 묶어 Neg(Pow(2,2))=-4가 된다. 단항을 더 높게 두면 Pow(Neg(2),2)=4다. 선언을 바꾸어 충돌을 해결했다는 사실만으로 원하는 AST를 보장하지 않는다.

별도 비교 문법 E→E < E | n에서 <를 nonassociative로 정하면 1<2<3의 같은 우선순위 충돌을 오류로 정한다. 이 정책은 왼쪽 또는 오른쪽 중 하나를 고르는 것과 다르다. 여기서는 비교 결과를 다른 수의 피연산자로 다시 계산하지 않고 구문 단계에서 거부한다. 괄호 표시는 AST 설명용이며 실제 문법에 괄호 production을 추가한 것은 아니다.

먼저 확인할 개념
  • 상태·토큰·후보와 의미를 함께 진단

    경고 개수가 아닌 구문 나무와 연산 결과의 계약을 기록한다.

  • 충돌 종류와 병합 원인

    문법 자체의 모호한 결합과 표 정보 손실에 의한 충돌을 구분한다.

경고의 개수보다 실제 표 칸

문법 E→E−E|n의 n−n−n은 (n−n)−n과 n−(n−n)의 두 구조를 가진다. 첫 E−E를 스택 위에 만든 뒤 다음 −를 보는 상태에서 지금 reduce할지 −를 shift해 오른쪽 E를 확장할지 경쟁한다. 숫자 n의 실제 값을 붙이면 구조 차이가 결과 차이로 드러난다.

진단 기록에는 상태 항목, 충돌 토큰, 두 후보 행동과 그 상태를 만드는 짧은 입력을 넣는다. 단순 충돌 개수는 위치나 의미를 설명하지 못한다. 표 생성 방식 때문에 생긴 충돌과 문법 자체의 모호함도 구별해야 하므로 이전 소단원의 LALR 병합 예제와 비교한다.

결합법칙을 정책으로 명시한다

왼쪽 결합 −를 원하면 같은 우선순위의 다음 −에서 먼저 reduce한다. 오른쪽 결합을 선택하면 shift해 오른쪽 구조를 만든다. 곱셈이 덧셈보다 높다는 정책은 또 다른 우선순위 관계다. 정책은 언어 설계의 일부이며 임의 선택을 했다는 사실을 문서에서 숨기지 않는다.

E→E+E|E*E|n에서 2+3*4는 *를 먼저 묶으면14, +를 먼저 묶으면20이다. 단지 경고가 없어졌다는 사실만으로 목표14를 얻는지 알 수 없다. 괄호·서로 다른 연산·동일 연산 연속을 포함한 예제를 두고 구조와 의미를 함께 확인한다.

도구 결과와 손 추적의 증거를 구분한다

파서 생성기는 문법에서 표와 충돌 정보를 만들지만 도구마다 표 구성과 정책 선언 구문이 다를 수 있다. 이 단원은 Cornell의 개념 설명을 읽고 종이로 상태 행동을 대조했다. 실제 도구 설치·생성·실행을 하지 않았으므로 “빌드 성공”이나 “경고0”을 기록하지 않는다.

충돌을 기대 개수로 억제하는 설정이 있더라도 그 숫자만으로 같은 충돌이 유지되었다고 증명할 수 없다. 문법 변경 전후의 실제 충돌 상태·반례와 언어의 의도를 비교하는 것이 필요하다. 또한 파싱 구조가 맞아도 어휘 분석·타입 검사·실행 의미까지 자동으로 검증된 것은 아니다.

다른 문제에 적용하기

검사 장부를 세 부분으로 구성하라. ① S→A c, A→a A|ε의 지정 여섯 상태 SLR 표로 aaac$를 처리해 빈 축약 직전/직후 상태, shift/reduce 수, 최대 상태 개수와 count 의미값을 기록한다. ② 별도 대입 문법 S→L=R|R, L→*R|id, R→L의 처음 L 뒤 상태에서 =/$의 SLR 후보와 LR(1) 선택을 비교하고 전역 FOLLOW의 =를 삭제하면 안 되는 이유를 적는다. ③ 별도 E→E^E|−E|n에서 원하는 오른쪽 ^·낮은 단항 정책으로 −2^3^2의 AST와 값을 구하라. 실제 parser generator 설치나 실행은 하지 않는다. 단항을 ^보다 높게 둔 정책의 같은 입력 값도 비교하고, 수치가 우연히 같다면 두 정책을 구별하는 짧은 반례와 AST를 추가하라.

힌트 1

① a를 세 번 shift한 뒤 ε에서는 상태를 제거하지 않는다. 빈 A의 count는 0이고 a A를 줄일 때마다 1을 더한다.

힌트 2

② 전역 FOLLOW와 완료 [R→L·,$]를 구분한다. ③ 3^2를 먼저 묶고 맨 마지막에 단항 부호를 붙인다.

풀이와 답 확인

  1. ① 빈 축약 직전은 [0,1,1,1], 직후는 [0,1,1,1,4]다. a A 축약 세 번으로 [0,1,1,4]→[0,1,4]→[0,2]이며 c를 shift해 [0,2,5], S 축약 뒤 [0,3]에서 $를 확인한다.

  2. shift는 a 세 번과 c 한 번으로 4번, reduce는 ε 한 번·a A 세 번·S 한 번으로 5번이다. 최대 상태 개수는 5개이며 count는 0→1→2→3이다.

  3. ② 전역 FOLLOW(L/R)={=,$}이므로 SLR의 = 칸에는 shift와 R→L reduce가 충돌한다. LR(1) 완료 lookahead는 $뿐이어서 =에서는 shift, $에서는 R→L reduce다. FOLLOW의 =는 다른 유도 문맥의 사실이라 임의 삭제하지 않는다.

  4. ③ AST는 Neg(Pow(2,Pow(3,2)))이며 3^2=9, 2^9=512 뒤 부호를 붙여 −512다. 높은 단항·오른쪽 ^ 정책이라면 Pow(Neg(2),Pow(3,2))의 값도 우연히 −512가 되어 이 입력 하나로 단항 정책을 구분하지 못한다. 단항 차이를 드러내려면 별도 −2^2의 −4 대 4도 함께 검사한다.

① 빈 축약은 상태 개수를 4개에서 5개로 늘린다. shift는 4번, reduce는 5번이며 count의 값은 3이다. ② SLR의 전역 FOLLOW 충돌과 LR(1)의 =에서 shift, $에서 reduce를 구분한다. ③ 원하는 AST의 값은 −512지만 높은 단항 정책도 이 입력에서 같은 값을 내므로 −2^2의 −4 대 4 및 서로 다른 AST를 추가해 확인한다.
