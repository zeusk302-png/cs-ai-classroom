소단원 11.1

상수접기·공통부분식

같은 합을 두 번 구하는 코드에서 한 번만 계산해도 될까?

준비 개념과 학습 목표

준비 개념

  • 중간코드와 기본블록

  • 대입과 재정의

  • 연산자와 피연산자

학습 목표

  • 상수접기와 공통부분식 제거를 구별한다.

  • 현재 값과 변수 이름의 차이를 추적한다.

  • 재정의와 메모리 변경이 재사용을 막는 이유를 설명한다.

현재 변수는 덮였지만 옛 합이 다른 이름에 남아 있다면?

이 소단원은 순수 무한 정수 덧셈만 사용한다. 입력은 x=2, y=5다. a=x+y; keep=a; a=0; b=y+x; x=5; c=x+y; return(keep,b,c,a)를 새로 추적한다. 변수 이름은 저장 칸이고 값 번호는 그 순간의 값이다. 같은 계산의 결과를 어느 살아 있는 이름에서 가져올 수 있는지 따로 기록한다.

첫 합의 값은 7이고 keep이 이를 보존한다. a를 0으로 덮어도 keep은 7이다. 교환 가능한 덧셈의 피연산자 값 번호 쌍을 정렬하면 b의 y+x는 첫 합과 같아 b=keep으로 대체할 수 있다. b=a로 바꾸면 옛 값 대신 현재 0을 읽어 틀린다.

x=5 이후 c의 합은 10이다. 첫 합의 입력 x=2와 현재 x=5는 다르므로 문자 x+y가 같아도 같은 키가 아니다. 타입·연산·피연산자 버전·결과 보관 이름을 함께 확인한다. 산술 감소는 이 손모형의 연산 수이며 실제 시간은 미확인이다.

먼저 확인할 개념
  • 값 번호와 결과 보관

    피연산자 재정의와 결과 이름 덮어쓰기를 별도로 읽는다.

  • 값 복사와 재정의

    keep에 복사된 옛 값이 a 변경 뒤에도 유지되는 조건을 확인한다.

기본블록 안에서 계산을 따라간다

지역 최적화는 하나의 기본블록처럼 좁은 영역의 정보를 사용한다. 기본블록 내부에는 중간으로 들어오는 분기나 중간에서 나가는 분기가 없다고 두며 명령 순서대로 값을 추적한다. 블록 밖에서 어떤 값을 사용하는지는 별도 정보가 필요하다.

이 소단원의 자체 중간코드는 무한 범위 정수와 순수한 덧셈·곱셈을 사용한다. 계산은 메모리를 바꾸거나 예외를 만들지 않는다. 실제 기계 정수와 부동소수점의 의미는 뒤 소단원에서 구별한다. 계산 단계를 줄였다는 사실과 실제 CPU 시간이 줄었다는 주장은 다르다.

상수끼리는 미리 계산한다

상수접기는 4 + 6처럼 피연산자가 이미 확정된 계산을 컴파일 시점에 결과 10으로 바꾸는 변환이다. a가 10임을 알아 a * 3을 10 * 3으로 바꾸는 정보 전달은 상수 전파이며, 그 다음 30을 계산하는 것이 접기다.

입력 x + 6은 x를 모르면 숫자 하나로 접을 수 없다. 일부 입력에서 x가 4였다는 관찰만으로 모든 실행의 x를 4로 바꾸지도 않는다. 나눗셈·오버플로·반올림이 있는 표현은 대상 언어의 규칙에 맞게 계산해야 한다.

같은 현재 값의 계산을 재사용한다

공통부분식 제거는 이미 구한 연산과 피연산자의 현재 값이 같으면 계산 결과를 재사용한다. 값 번호는 변수 이름에 연결된 현재 값을 표시하는 표식이다. x가 다시 대입되면 x의 현재 값 번호는 바뀐다. 문자로 같은 x+y여도 다른 계산이 될 수 있다.

결과 보관 변수도 다시 대입되면 옛 결과를 잃는다. 예를 들어 t=x+y 다음 t=0이면 이후 x+y를 현재 t로 대체할 수 없다. 필요한 옛 결과를 별도 임시 변수에 보존하거나 재사용을 포기한다. load p와 load p 사이에는 다른 포인터를 통한 같은 위치의 저장이 있을 수 있어 메모리 분석이 필요하다.

원래 세 합에서 두 합으로 감소

같은 숫자로 우연히 같아지는 경우와 값 버전이 동일한 경우를 구별한다. 표의 S는 계산 결과 표식이지 프로그램의 실제 메모리 주소가 아니다.

중간 과정을 따라가는 예제

입력 x에 대해 a=4+6; b=x+a; c=x+a; d=b*c; return d를 최적화하라. 이 중간코드는 순수 무한 정수다.

  1. a 계산을 10으로 접고 b = x + 10으로 전파한다.

  2. c의 덧셈은 b와 같은 현재 x와 10을 사용하므로 c = b라는 복사로 바꿀 수 있다.

  3. d = b * c에 복사를 전파하면 d = b * b다. 반환값은 (x + 10)²로 유지한다.

  4. x = 2일 때 원래 a = 10, b = 12, c = 12, d = 144이며 변환 뒤 b = 12, d = 144다. x = −10이면 두 형태 모두 0이다.

  5. 원래 실행 시 산술은 덧셈 3회·곱셈 1회로 총 4회, 변환 뒤 덧셈 1회·곱셈 1회로 총 2회다. 이 추상 코드의 산술 수이며 실제 시간 측정이 아니다.

b=x+10; d=b*b; return d로 단순화할 수 있다. 순수 계산·피연산자 불변 조건에서 반환값을 보존한다.

조건을 바꾸어 비교하기

덮인 대표 이름을 교체하는 장부

위 목록에서 b를 a 또는 keep으로 바꾸는 두 후보를 비교하라.

  1. a는 이미 0이므로 b=a는 반환을 (7,0,10,0)으로 바꾼다. 두 번째 반환값이 요구된 7에서 0으로 달라진다.

  2. keep은 7이므로 b=keep은 (7,7,10,0)을 보존한다. c는 새 x를 사용하여 그대로 계산한다.

보관된 keep으로만 해당 합을 재사용하며 덧셈은 3회에서 2회다.

비교할 점

표에 계산 키가 존재해도 그 결과를 보관한 현재 이름이 없으면 재사용할 수 없다.

입력값이 다시 같아지는 재정의

별도로 x=2,y=5; a=x+y; x=2; b=x+y를 추적하라. 단순 버전 추적과 상수 전파를 구별하라.

  1. 최종 a와 b는 모두 7이다. 단순 새 버전 장부는 재정의된 x를 새 값 번호로 둘 수 있다.

  2. 상수 2라는 사실을 추적하는 확장 분석은 두 x 버전을 같은 상수 값으로 묶어 재사용할 수 있다.

단순 분석이 놓친 기회는 잘못된 변환과 다르다.

비교할 점

모든 재정의가 실제 값 변경을 뜻하지 않지만 근거 없이 같다고 가정할 수도 없다.

종이와 본문으로 직접 해보기

t = x + y; x = x + 1; u = x + y; return(t,u)에서 x = 2, y = 3이면 t와 u는? u = t로 바꿔도 되나? t = x + y; t = 0; u = x + y에서도 u = t가 맞나?

힌트 보기

이름이 같아도 각 줄에서 보관한 값을 별도로 적는다.

풀이 보기

첫 경우 t = 5, x = 3, u = 6이므로 u = t는 틀린다. 둘째는 현재 t가 0이라 옛 합이 5였어도 u를 0으로 바꾸면 틀린다. 입력 값이 바뀌지 않은 경우라도 재사용 결과가 현재 저장되어 있어야 한다.

연습 1 · 값과 상태 예측

첫 목록의 입구 x만 −2로 바꾸고 뒤 x=5는 유지하라. 네 반환값과 덧셈 수를 예측하라.

힌트 1

첫 합은 입구 x와 5다.

힌트 2

뒤의 c는 고정한 x=5를 사용한다.

풀이와 답 확인

  1. 첫 합은 3이다. keep과 b는 각각 3이고 c는 10이며 a는 0이다.

  2. 원래 덧셈은 3회이고 b 재사용 후 2회다.

반환은 (3,3,10,0)이다.

흔한 오답에서 다시 생각하기

입구 x 변경으로 c도 3이다.

c 전에 x를 5로 재정의했다.

연습 2 · 오류 찾아 고치기

최적화 표가 S의 대표를 계속 a로 보관해 b=a를 만들었다. 출력으로 오류를 찾고 장부를 고쳐라.

힌트 1

a가 덮이는 순간을 표시한다.

힌트 2

같은 결과를 보관한 다른 이름을 찾는다.

풀이와 답 확인

  1. 입구 2,5에서 잘못된 두 번째 반환값은 0이다.

  2. 대표를 keep으로 바꾸거나 옛 결과를 새 임시 이름으로 보존한다. 보관 이름이 없으면 재계산한다.

S의 존재와 대표 이름의 현재 내용 둘 다 검사한다.

연습 3 · 직접 만들어 보기

첫 목록의 x 재정의 전 a=x+y를 old_sum이라는 새 이름에 계산하는 안전한 변환을 구성하라.

힌트 1

a의 마지막 관찰값은 0이다.

힌트 2

b와 keep은 첫 합을 사용한다.

풀이와 답 확인

  1. old_sum=x+y; keep=old_sum; a=0; b=old_sum; x=5; c=x+y; return(keep,b,c,a)로 구성한다.

  2. keep과 b의 복사까지 반환에 전파하면 return(old_sum,old_sum,c,0)이다.

두 합과 같은 반환 계약을 보존한다.

흔한 오답에서 다시 생각하기

a=0도 죽었으니 반환의 마지막 값은 삭제한다.

반환 튜플의 네 번째 관찰을 유지해야 한다.

블록 출구의 한 값과 버려진 예외 중 무엇을 남겨야 할까?

새 블록은 a=x; b=a+4; c=b*2; unused=c+1; z=9; print b다. 순수 무한 정수이며 출력과 출구의 z만 관찰한다. live-out={z}로 시작해 역방향 필요한 집합을 추적한다. 제거한 순수 계산의 인수는 필요 집합에 추가하지 않는다.

출구의 필요 집합 {z}에서 역추적을 시작한다. print b를 처리해 그 명령 직전의 필요 집합 {z,b}를 얻는다. z=9를 처리하면 {b}이고 unused와 c를 제거해도 그대로 {b}다. b=a+4를 남기면 {a}, a=x를 남기면 {x}다. 복사를 전파하면 b=x+4; z=9; print b로 표현할 수 있다.

별도 언어에서 divide(1,0)는 관찰되는 예외로 종료한다고 정의하자. 반환값이 안 쓰여도 이 호출을 지우면 종료 행동이 달라진다. 이는 명시한 가상 언어의 계약이며 C의 0 나눗셈이나 LLVM UB에 동일 규칙을 적용했다는 주장이 아니다.

  • 관찰과 언어 의미

    출력·예외·종료가 관찰인지 먼저 정한다.

같은 값을 전달하되 이후 변화와 구별한다

a=x는 그 순간의 값을 a에 복사한다. x를 뒤에서 바꿔도 일반 값 변수 a의 옛 값은 변하지 않는다. 복사 전파는 사용 지점에서 두 이름이 여전히 같은 값을 뜻할 때 a 대신 x를 쓰는 변환이다.

a=x; x=x+1; print a에서는 print x로 대체할 수 없다. 변수 재정의 시 관련 복사 관계를 무효화하거나 새로운 버전 이름을 사용해야 한다. 포인터 값의 복사와 포인터가 가리키는 대상의 변경도 다른 문제다. 여기서는 포인터 없는 값 변수를 먼저 다룬다.

결과가 쓰이지 않아도 효과는 남을 수 있다

죽은 대입은 계산한 값이 후속 관찰에 사용되지 않는 대입이다. 같은 변수에 새 값을 넣기 전에 옛 값을 전혀 읽지 않으면 이전 값은 죽을 수 있다. 그러나 I/O·메모리 쓰기·예외 등 효과가 있는 연산은 결과가 안 쓰인다고 연산 자체를 없애면 안 된다.

지역 범위 안에서 사용이 보이지 않는 변수도 후속 블록에서 읽을 수 있다. 블록 출구에서 살아 있는 변수의 집합 live-out을 전달받거나, 알 수 없는 값은 보수적으로 유지한다. 단일 블록만 보고 모든 마지막 대입을 지우는 규칙은 프로그램 전체 의미를 깨뜨린다.

뒤에서 앞으로 필요한 값을 추적한다

순수 대입 v=op(args)의 역방향 추적에서 v가 필요하면 대입을 남기고 필요한 집합에서 v를 빼고 args를 넣는다. 필요하지 않으며 제거 가능한 순수·실패 없는 계산이면 지운다. 출력은 관찰 효과이므로 유지하고 출력 인수를 필요한 집합에 넣는다.

제거 후에만 다른 값이 죽었다고 드러날 수 있다. 예를 들어 p=5; q=p+1에서 q를 지우면 p도 필요 없어진다. 전체 사용 수 방식은 변화가 없을 때까지 반복하거나 의존성 작업 목록을 사용한다. 역방향 필요한 집합 방식은 같은 블록의 이런 연쇄를 한 번에 포착할 수 있다.

중간 과정을 따라가는 예제

입력 x와 순수 무한 정수에서 a=x; b=a+2; tmp=7*8; c=b; print c를 단순화하라. 블록 출구에서 다른 변수는 사용되지 않는다.

  1. a의 현재 복사 관계가 유지되므로 b=x+2로 바꾸고 c의 사용을 b로 전파해 print b로 만든다.

  2. 현재 형태 a=x; b=x+2; tmp=56; c=b; print b에서 출력부터 역추적하면 b가 필요하다.

  3. c는 필요 없고 복사 자체에 효과가 없으므로 지운다. tmp도 필요 없고 56 계산은 순수하고 실패하지 않으므로 지운다.

  4. b를 남기면 x가 필요하며 a는 후속 사용이 없어 지운다. 결과 b=x+2; print b다.

같은 최종 숫자 뒤에 입력과 로그 순서가 달라져도 성공인가?

새 감사의 관찰은 반환값, 순서 있는 입력 소비와 로그, 정의된 종료 행동이다. 무한 정수와 8비트 모듈러 정수, 세 자리 10진 반올림은 서로 다른 모형이다. 변환마다 선택한 모형을 적는다.

8비트 일반 덧셈에서 253+5는 258 mod 256=2다. LLVM add i8의 일반 규칙과 연결할 수 있지만 nuw가 붙은 오버플로 결과는 poison이다. 이를 정상 결과 2로 보고하거나 즉시 어떤 CPU 예외가 난다고 단정하지 않는다. 실제 C 실행 의미도 별도다.

반올림 반례는 매 연산 유효 숫자 3자리 최근접의 자체 10진 모형으로 구성한다. a=20000, b=−20000, c=3에서 (a+b)+c의 결과는 3이다. a+(b+c)에서는 중간 합 −19997이 −20000으로 반올림되어 최종 결과가 0이다. 실제 IEEE 실행은 하지 않았다. LLVM의 재결합 허가는 관련 flag 조건을 읽어 별도 판단한다.

관찰을 무엇으로 정했는지 먼저 적는다

변환 정확성은 원래 프로그램이 정의된 의미를 갖는 입력에서 허용된 관찰을 보존하는지 따진다. 관찰에는 출력·반환값·외부 메모리 효과와 명세에 따른 예외·종료 행동이 들어갈 수 있다. 앞 예제는 순수 무한 정수와 출력만이라는 제한을 두었다.

최종 값이 같아도 입력을 한 번 덜 읽거나 로그 순서가 바뀌면 같은 행동이 아닐 수 있다. volatile 접근도 일반 중간값과 다르게 의미를 갖는다. LLVM의 volatile 규칙을 Java volatile의 동기화 규칙과 같은 것으로 해석하지 않는다.

정수 폭과 반올림은 수학식 바깥의 조건이다

8비트 모듈러 정수에서 250 + 10은 260을 그대로 저장하지 않고 4가 된다. LLVM의 일반 정수 add는 비트 폭에 따른 규칙을 갖고 no-wrap 표식이 붙으면 오버플로 의미도 달라진다. 소스 언어의 부호 있는 정수 규칙은 별도로 읽어야 한다.

부동소수점의 덧셈은 각 단계에서 반올림하므로 재결합이 일반적으로 결과를 보존하지 않는다. 실제 LLVM은 특정 fast-math 허용 조건을 따로 둔다. NaN·무한대·부호 있는 0·반올림 환경도 관련될 수 있어 단순한 대수 항등식을 모든 수치 연산에 적용하지 않는다.

시험·반례·근거를 함께 관리한다

변환 전후 프로그램에 같은 입력을 넣어 출력과 효과를 비교하는 차등 시험은 구현 실수를 찾는 데 유용하다. 경계값·재정의·메모리 별칭·부작용을 포함한다. 시험 하나의 불일치는 변환의 반례가 될 수 있지만 유한한 성공 사례는 모든 입력에 대한 증명이 아니다.

정확성 논증은 현재 값 불변·결과 보존·연산 의미 같은 전제에서 변환 규칙을 유도한다. 성능은 정확성 확인 후 별도로 동적 명령 수나 시간으로 측정한다. 정적 코드가 짧다고 모든 기계에서 빠르다고 말하지 않는다.

중간 과정을 따라가는 예제

유효 숫자 3자리로 매 연산을 최근접 반올림하는 자체 10진 모형에서 a = 1000, b = −1000, c = 1을 사용하라. (a + b) + c와 a + (b + c)를 비교하라. 실제 IEEE 실행 결과로 보고하지 않는다.

  1. a + b = 0은 정확하며 (a + b) + c = 1이다.

  2. b + c = −999는 3자리로 정확히 표현된다. a + (b + c) = 1이므로 이 첫 선택에서는 반례가 아니다.

  3. 더 큰 a = 10000, b = −10000, c = 1로 바꾼다. a + b = 0이므로 첫 괄호 결과는 1이다.

  4. b + c = −9999를 유효 숫자 3자리로 반올림하면 −10000이다. a + (b + c) = 0이 된다.

  5. 따라서 이 두 번째 선택에서 결과 1과 0이 다르다. 허용 의미나 옵션을 확인하지 않고 재결합하면 값을 바꿀 수 있다.

자체 모형에서 1000 사례는 둘 다 1이지만 10000 사례는 1과 0이다. 한 성공 사례만으로 규칙을 확정할 수 없다.

순수 무한 정수와 순서 있는 로그를 갖는 새 블록 a=x+6; keep=a; a=0; b=x+6; x=x+1; c=x+6; dead=c*3; log keep; log c; return b를 감사하라. 입구 x=4이고 live-out={a}다. ① 반환·출구 a·로그와 원래 산술 수를 적어라. ② b 재사용·dead 제거를 포함한 안전한 목록과 산술 수를 구성하라. ③ 이 블록과 별도의 독립 메모리 블록 m=load p; store q,12; n=load p; return n을 감사하라. p=q이고 처음 저장값은 5다. n=m 치환을 승인할 수 있는지 판단하라. 메모리는 유효하고 일반 비volatile이다. 각 블록의 로그·반환·live-out이 관찰이며 실제 compiler/API/학생 실행은 하지 않는다.

제거한 dead의 입력은 그 계산 때문에만 필요로 만들지 않는다. 별도 메모리 사례에서는 저장 전후 같은 위치의 값을 각각 적는다.

풀이와 답 확인

  1. 입구에서 a의 첫 값은 10이고 keep과 b도 각각 10이다. 이후 a는 0으로 덮인다. x는 5가 되고 c는 11, dead는 33이다. 반환은 10, 출구 a는 0, 로그는 [10,11]이다. 원래 산술은 덧셈 4회와 곱셈 1회로 5회다.

  2. old=x+6; a=0; x=x+1; c=x+6; log old; log c; return old로 구성한다. old는 keep/b 관찰을 대신하며 dead만의 곱셈을 제거한다. 덧셈 3회로 산술은 3회다. a는 live-out이므로 유지한다.

  3. 독립 메모리 블록에서 m은 5이고 저장 후 n과 반환값은 12다. p=q라는 명시 조건에서 n=m은 잘못된 반환값 5를 만들므로 거절한다. 모르는 별칭을 무조건 비공유로 가정할 수도 없다.

관찰 (반환 10, 출구 a=0, 로그 [10,11])을 유지하며 산술 5회에서 3회로 줄인다. b는 옛 합을 보관한 이름에서만 재사용하고 c는 새 x로 계산한다. 메모리 저장 뒤 n은 12이므로 옛 m=5로 대체하지 않는다. 실제 성능이나 구현 실행은 미확인이다.

해결한 뒤 점검할 것

  • 옛 합 10과 새 합 11, live-out a의 0 및 로그 순서를 모두 구별한다.

  • 안전한 새 보관 이름과 dead 제거를 구성하고 원래 산술 5회/변환 산술 3회의 계산 범위를 명시한다.

  • p=q의 두 load 값 5와 12로 잘못된 재사용 반례를 제시한다.

  • 손모형 계산과 실제 compiler/성능/API/학생 미수행을 구별한다.
