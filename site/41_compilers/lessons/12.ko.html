소단원 12.1

도달 정의·생존 분석

합류 지점에서 같은 변수 x를 읽을 때 어느 대입의 값일 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 기본 블록과 제어 흐름 그래프

  • 집합의 합집합·차집합

  • 변수의 읽기와 대입

학습 목표

  • 도달 정의의 전방 may 분석을 설명한다.

  • 생존 변수의 역방향 식을 계산한다.

  • 이름과 대입 위치·실행 경로·분석 근사를 구별한다.

각 변수의 가능한 값을 따로 모으면 존재하지 않는 실행도 만들어질까?

새 분기에서 c가 참이면 L: x=1; y=8, 거짓이면 R: x=8; y=1을 실행한 뒤 J: z=x+y로 합류한다. 모든 값은 무한 정수이고 c는 한 번 읽은 불변 입력이다. 정의 위치는 dxL,dyL,dxR,dyR로 표시한다. J의 도달 정의는 네 위치지만 실제 값 쌍은 (1,8) 또는 (8,1)이다.

x의 후보 {1,8}와 y의 후보 {1,8}를 독립으로 조합하면 (1,1)과 (8,8)이 추가되어 합 2와 16도 가능하다고 근사한다. 실제 합은 두 경로 모두 9다. 도달 정의의 may 합집합은 경로의 가능성을 안전하게 모으지만 변수 사이의 동시 선택 관계까지 보존하지 않는다. 이 분석만으로 두 값이 동시에 존재한다고 해석하지 않는다.

여러 문장을 한 블록으로 묶을 때는 순서도 중요하다. 새 블록 x=x+1; x=4; y=x의 입구 x는 첫 문장이 읽으므로 USE에 포함된다. 하지만 출구 x의 GEN에는 마지막 x=4의 위치만 남는다. 블록에서 DEF에 등장한 이름을 모든 USE에서 일괄 삭제하면 먼저 읽은 입구 x를 잃는다. 메모리 저장은 이 단순 변수 분석에서 이름 대입과 별개다.

대입 위치에 이름을 붙인다

이 단원의 CFG 노드는 각각 한 문장을 나타낸다. 여러 문장을 한 기본 블록으로 묶을 때는 블록 안의 읽기·재대입 순서를 반영해 GEN/KILL과 USE/DEF를 따로 구성해야 한다. 도달 정의는 특정 변수 이름 하나가 아니라 그 값을 정의한 대입 위치를 추적한다. 정의 d가 지점에 도달한다는 것은 d에서 그 지점으로 오는 CFG 경로 중 같은 변수를 다시 대입하지 않는 경로가 있다는 뜻이다. 정의는 정적 위치라 루프가 한 대입을 여러 번 실행해도 위치 이름은 하나다.

노드 n의 입구 집합 IN[n]은 전임 노드들의 OUT을 합집합한다. OUT[n] = GEN[n] ∪ (IN[n] − KILL[n])이다. x 대입이 만드는 GEN은 그 정의 위치이며 KILL은 x의 다른 이전 정의들이다. GEN을 마지막에 합치므로 KILL에 자기 위치를 포함하는 관례를 써도 같은 결과다.

나중에 사용할 값은 어느 쪽으로 전파되는가

생존 변수는 지금 가진 값이 이후 경로에서 재대입 전에 읽힐 수 있는 변수다. OUT[n]은 후임들의 IN 합집합이고 IN[n] = USE[n] ∪ (OUT[n] − DEF[n])이다. USE는 읽는 변수, DEF는 그 노드에서 쓰는 변수다. 생존은 미래의 필요를 뒤로 전파한다.

x = x + 1은 USE = {x}, DEF = {x}다. 새 x가 생겼다고 기존 x의 읽기를 빼면 잘못된다. 또한 *p = x에서 p와 x는 읽지만, 이 단순 변수 생존 모형은 특정 이름 x를 재대입하지 않는다. 메모리 내용 분석은 별칭 등을 포함한 다른 모형이 필요하다.

may 정보를 안전하게 사용한다

합류에서 두 정의가 도달한다는 것은 한 실행이 두 값을 동시에 가지는 뜻이 아니다. 어떤 경로에서 각 정의가 올 수 있다는 근사다. CFG에는 실제 불가능한 경로도 포함될 수 있어 의미적으로 정확한 모든 실행 정보를 일반적으로 완벽히 계산하지 못한다.

생존 가능성이 있는 변수를 누락하면 필요한 값을 잃을 수 있어 may 분석은 보수적으로 과대 추정한다. 반대로 생존하지 않는 대입도 우변의 호출·예외·메모리 쓰기가 관측된다면 문장 전체를 무조건 지워서는 안 된다. 분석 결과를 변환에 쓰려면 언어의 관측 의미를 보존해야 한다.

중간 과정을 따라가는 예제

자체 CFG에서 A: x = 2 다음 C: if c가 B: x = 9 또는 D: nop으로 갈라지고, 둘 다 J: y = x로 합류한 뒤 R: return y로 간다. x의 두 정의를 dA, dB라 부르자. J에 도달하는 x 정의와 J 전후 생존 집합을 구하라. 외부 입력은 c뿐이다.

  1. B 경로에서는 x를 다시 써서 dA가 죽고 dB가 J에 도달한다. D 경로는 재대입하지 않아 dA가 도달한다. 따라서 J 입구의 x 정의는 {dA, dB}다.

  2. R의 USE는 {y}, OUT은 ∅여서 IN[R] = {y}다. 따라서 OUT[J] = {y}다.

  3. J의 USE = {x}, DEF = {y}이므로 IN[J] = {x} ∪ ({y} − {y}) = {x}다. x의 정의 가능성과 변수의 현재 값 필요를 다른 집합으로 계산했다.

J 입구에는 x 정의 {dA, dB}, 생존 집합은 입구 {x}, 출구 {y}다. 실제 한 실행에서는 한 경로의 x 값만 읽는다.

조건을 바꾸어 비교하기

경로 상관관계를 잃은 합류

새 분기의 J에서 도달 정의와 합의 실제 집합 및 독립 근사를 비교하라.

  1. x에는 dxL과 dxR, y에는 dyL과 dyR가 도달한다. 두 경로의 합은 각각 1+8과 8+1로 9다.

  2. 좌표를 독립으로 섞으면 합은 2,9,16이 된다. 근사는 실제 9를 포함하지만 추가 값을 제거할 관계 정보가 없다.

도달 정의 네 위치와 실제 합 하나는 서로 모순되지 않는다.

블록 내부의 읽기와 마지막 정의

B: x=x+1; x=4; y=x의 정의를 d1,d2,d3라 한다. 출구에서 y가 살아 있을 때 USE/DEF, GEN, 입구 생존을 구하라.

  1. 블록 안에서 해당 이름이 처음 정의되기 전에 읽는 입구 변수는 x다. DEF는 {x,y}이고 GEN은 마지막 x 정의 d2와 y 정의 d3다. d1은 블록 안에서 죽는다.

  2. OUT={y}이면 IN={x}∪({y}−{x,y})={x}다. x=4 때문에 최종 y는 4여도 원래 첫 문장은 입구 x를 읽는다.

USE={x}, DEF={x,y}, GEN={d2,d3}, IN={x}다.

비교할 점

원래 CFG 생존과 별도 순수 죽은 계산 제거 뒤 새 CFG의 생존을 구별한다.

힌트 보기

D에서도 이전 x가 재대입된다. 생존 식에서 DEF로 x를 빼고 USE로 다시 넣는다.

풀이 보기

J의 x 도달 정의는 {dB, dD}이며 dA는 양쪽에서 죽는다. 별도 문장 IN = {x} ∪ ({x,z} − {x}) = {x,z}다. 읽히는 이전 x는 필요하다.

오해와 반례

J에 두 정의가 도달하므로 x를 2와 9 두 값의 합으로 바꿔도 된다.

합집합은 가능 경로를 모은 정보다. 실제 값은 경로가 선택한 2 또는 9이며 11이 아니다. 도달 정의를 실제 값들의 산술 결합으로 해석하지 않는다.

연습 1 · 값과 상태 예측

힌트 1

두 실제 쌍을 먼저 사용한다.

힌트 2

추가 쌍 (1,1),(8,8)도 근사에는 포함된다.

풀이와 답 확인

  2. 독립 근사는 −7,0,7이며 0은 실제 두 경로에 없다.

연습 2 · 오류 찾아 고치기

첫 분기 뒤 if c then print x else print y가 온다. c가 불변인데 도달 정의가 두 개라는 이유로 print에 항상 8을 넣었다. 반례와 복구를 적어라.

힌트 1

같은 c를 두 번 분기한다.

힌트 2

c가 참인 경로와 거짓인 경로에서 실제 읽는 값을 각각 적는다.

풀이와 답 확인

  1. 참이면 L의 x=1을 출력하고 거짓이면 R의 y=1을 출력한다. 후보 8은 두 경우 모두 틀린다.

  2. 정의 집합만으로 선택하지 말고 원래 사용을 보존하거나 불변 c의 경로 관계를 증명해 1로 접는다.

실제 출력은 항상 1이며 임의 정의 선택은 거절한다.

흔한 오답에서 다시 생각하기

may 후보 하나면 아무거나 실제값으로 써도 된다.

가능성의 합집합은 대체값 선택 권한이 아니다.

연습 3 · 직접 만들어 보기

블록 x=4; y=x; x=x+1로 순서를 바꾸어 USE/DEF/GEN과 OUT={y}의 IN을 구성하라. 정의 위치는 앞에서 e1,e2,e3다.

힌트 1

입구 x가 처음 읽히기 전에 새로 정의되는지 보라.

힌트 2

출구에는 x의 마지막 위치만 보존한다.

풀이와 답 확인

  1. 입구 변수 읽기는 없으므로 USE=∅, DEF={x,y}다. GEN={e2,e3}이며 e1은 죽는다.

  2. OUT={y}에서 IN=∅다. 최종 y=4, x=5이며 첫 사례와 입구 필요가 달라졌다.

읽기 순서로 USE를 계산하고 마지막 정의로 GEN을 계산한다.

흔한 오답에서 다시 생각하기

x가 식에 한 번 등장하면 항상 USE에 들어간다.

블록 USE는 블록 안에서 먼저 정의되지 않은 입구 값의 읽기다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

원래 첫 분기에서 L 뒤에는 if not c인 간선으로만 R에 가도록 가짜 CFG 경로가 남아 있다고 하자. 불변 c를 유지하면서 L→R 실행과 그 분석 경로를 구별하라.

힌트 1

L 진입은 c가 참이라는 뜻이다.

힌트 2

다음 조건 not c가 참일 수 있는지 검사한다.

풀이와 답 확인

  1. 동일한 불변 c에 대해 c와 not c가 함께 참일 수 없으므로 실제 L→R 경로는 없다.

  2. 조건 관계를 지운 CFG 분석은 그 경로의 정의를 합류에 포함할 수 있다. 이는 과대 근사이며 실제 도달을 주장하지 않는다.

한 단계 더

CFG나 대입 위치를 변환한 뒤에는 분석이 여전히 유효한지 확인해야 한다. 기존 결과를 그대로 붙여 두면 새로운 경로와 정의를 놓친다. SSA는 다른 표현으로 일부 관계를 단순하게 만들지만 지금의 전방·역방향 의미를 이해하는 출발점을 대신하지 않는다.

모든 식이 만족되어도 잘못된 초기 집합의 해일 수 있을까?

새 세 노드는 H: 분기, B: nop, E: return z다. H의 후임은 B와 E이고 B의 후임은 H다. H는 이 분석에서 변수를 읽지 않는 추상 비결정 분기로 정의하여 USE=∅다. B도 USE=DEF=∅이고 E만 USE={z}다. 각 IN의 공집합에서 직전 라운드만 사용하는 동시 갱신을 한다. 이는 정한 CFG의 자료흐름 모형이며 실제 분기 프로그램 실행은 아니다.

첫 라운드는 H=∅, B=∅, E={z}다. 두 번째는 H={z}, B=∅, E={z}, 세 번째는 셋 모두 {z}, 네 번째에 변화가 없다. H→B→H 순환에 값을 전달하는 데 시차가 생긴다. 이것은 분석 갱신 라운드 수이며 프로그램의 실행 반복 수가 아니다.

아무 곳에서도 읽거나 쓰지 않는 ghost를 H와 B에 처음부터 넣으면 순환이 ghost를 서로 전달해 고정점에서도 남길 수 있다. 유한·단조라는 사실만으로 임의 초기화의 해가 가장 작은 생존 해라고 말할 수 없다. 공집합 경계와 적절한 초기화가 해의 의미를 정한다. must 분석의 교집합은 같은 초기화 규칙을 기계적으로 복사하지 않는다.

한 번의 방문은 충분하지 않을 수 있다

루프에는 되돌아가는 간선이 있어 첫 계산 때 후임 정보가 아직 비어 있을 수 있다. 고정점은 현재 집합을 식에 다시 넣어도 결과가 달라지지 않는 상태다. 노드를 한 번씩 읽었다는 뜻이 아니며 식을 모두 만족하는지 점검한다.

이 단원의 유한 변수 생존 분석은 모든 IN을 공집합으로 시작한다. 고정된 USE/DEF와 후임 합집합 식은 입력 집합이 커져도 결과가 작아지지 않는 단조 함수다. 처음 빈 집합에서 공정하게 식을 갱신하면 정보가 추가되는 방향으로 진행한다.

수렴의 근거를 센다

노드 N개와 변수 V개라면 모든 IN 집합에 들어가는 노드·변수 쌍은 N·V개뿐이다. 추가되던 원소를 제거하지 않는 이 반복에서는 엄격한 증가의 횟수가 유한하다. 한 번 갱신에 여러 원소가 추가될 수도 있어 이 수는 집합 변화의 상한 근거다.

일정 횟수만 돌린 뒤 고정점이라고 가정하지 않는다. 집합 연산·간선 수·비트 벡터 표현도 실제 비용을 만든다. 모든 일반 분석이 공집합에서 시작하는 것도 아니다. 모든 경로에서 참인 must 분석에는 교집합과 다른 초기화·경계 조건이 필요하다.

변화한 정보만 다시 전파한다

worklist는 다시 계산할 필요가 있는 노드들의 목록이다. 역방향 생존에서 IN[n]이 변하면 그 값을 쓰는 전임 노드를 다시 넣는다. 전방 분석이라면 영향을 받는 후임으로 전파한다. 목록에 있는 노드는 결국 처리되도록 해야 한다.

목록 밖 노드의 식이 만족되는 상태를 유지하고, 어떤 갱신이 그 식을 깨면 그 노드를 목록에 넣는다. 목록이 비면 모든 식이 만족된다. 적절한 초기화와 단조성·유한 높이 조건 아래 같은 생존 해를 얻을 수 있지만 방문 순서에 따라 갱신 횟수는 다를 수 있다.

중간 과정을 따라가는 예제

자체 세 노드 H: if c, B: x = x + 1, E: return x를 둔다. H의 후임은 B와 E, B는 H로 돌아가고 E는 종료한다. 모두 IN = ∅에서 시작하여 직전 라운드의 IN만 쓰는 동시 갱신을 계산하라.

  1. USE는 H {c}, B {x}, E {x}이고 DEF는 B {x}, 나머지 ∅다. 1라운드 IN은 H {c}, B {x}, E {x}다.

  2. 2라운드에서 H는 후임 B·E의 {x}를 받아 {c,x}가 된다. B는 직전 H {c}에서 x를 제거한 뒤 USE {x}를 더해 {c,x}다. E는 {x} 그대로다.

  3. 3라운드에서 H·B·E가 각각 {c,x}, {c,x}, {x}로 유지된다. 최종 OUT은 H {c,x}, B {c,x}, E ∅다. 종료 후 x를 읽을 가능성이 루프 앞까지 전파됐다.

정보가 변한 라운드는 두 번이며 세 번째 라운드에서 불변을 확인한다. 이는 명시한 동시 갱신 순서의 결과다.

연산 수를 줄인 변환이 마지막 변수와 0회 경로도 지킬까?

새 무한 정수 모형은 t=7; i=0부터 n−1까지 t=4*a; emit(t+i); return t다. a=3이며 출력 목록과 반환 t를 관찰한다. n=0이면 출력은 없고 t는 7이다. 기존 대입을 루프 앞에 t=12로 옮기면 출력이 같아도 0회 반환이 달라진다.

순수 곱셈은 fresh=4*a로 새 임시에 계산하고 루프 안의 t=fresh 대입은 유지할 수 있다. n=2이면 출력은 [12,13]이고 반환은 12이며 곱셈은 두 번에서 한 번이다. n=0에서 새 임시의 순수 계산은 허용 모형상 관찰되지 않는다. 예외·volatile·메모리 효과가 있으면 같은 허가가 아니다.

다른 루프에서 각 출력이 3*i+1이고 i는 0부터 n−1까지다. j=1로 시작해 emit(j); j=j+3로 바꾸면 출력은 같지만 루프 뒤 j=3*n+1이다. 원래 마지막 출력 값을 반환하는 계약이면 이 값을 바로 반환할 수 없다. 불변값·사용 시각·최종값과 산술 폭을 구별한다. 실제 기계 속도와 컴파일러 실행은 측정하지 않는다.

값이 일정한 식을 찾는다

루프 불변 계산은 루프가 돌 때 같은 값을 계산하는 식이다. 사용하는 변수 정의가 루프 밖에서 오거나 이미 불변임을 알아야 한다. 메모리를 읽는 식은 이름이 같아도 다른 저장이 같은 위치를 바꿀 수 있어 별칭 분석이 필요하다.

불변이라는 사실만으로 이동이 안전하지는 않다. 읽기·쓰기·호출·예외·비종료와 실행 경로를 확인한다. 루프가 0번 도는 경우에도 새 위치에서 식이 실행되면 원래 없던 예외나 외부 효과를 만들 수 있다.

새 임시값과 기존 변수 대입을 구별한다

루프 전에 새 임시변수에 순수하고 안전한 불변식을 계산하고 원래 식을 그 값으로 바꿀 수 있다. 하지만 원래 기존 변수 대입을 통째로 이동하면 루프가 0번 돌 때도 그 변수를 바꾸는 문제가 생긴다. 루프 이후의 생존 값과 모든 관련 경로를 확인한다.

예를 들어 시작 t = 9, a = 4에서 루프 안의 t = 3*a를 기존 t에 대해 밖으로 옮기면 0회 루프 뒤 return t가 9에서 12로 변한다. 새 임시 temp = 12만 만들어 두고 원래 대입을 루프 안에 남기면 그 부작용을 구별할 수 있다.

별칭과 산술 의미를 함께 검사한다

*p를 읽고 *q를 쓰는 루프에서 p와 q가 같은 셀을 가리키면 읽는 값이 바뀐다. p의 주소가 루프 동안 일정하다는 사실과 p가 가리키는 값이 일정하다는 사실은 다르다. volatile·원자적 접근·동시 변경에는 더 엄격한 의미 조건이 있다.

유도변수에서 i가 1씩 늘고 j = 5*i + 2라면 j를 2부터 5씩 늘리는 형태로 바꿀 수 있다. 초기값과 각 사용 시점, 마지막 값·오버플로·예외를 보존해야 한다. 루프 펼침도 남은 반복을 처리해야 하며 실제 속도 향상은 기계·자료에서 따로 측정한다.

다른 문제에 적용하기

무한 정수와 순서 있는 출력의 새 프로그램을 감사하라. t=7; if c then a=2 else a=5; for i=0..n−1: t=3*a; emit(t+i); return t다. c는 불변이고 n은 음이 아닌 정수다. ① 루프 입구 a의 도달 정의 두 위치와 가능한 값·각 경로 상수의 차이를 적어라. ② n=0 및 n=2에서 c의 두 값에 따른 출력과 반환을 구하라. ③ 새 임시에 곱셈을 옮기는 변환과 기존 t 대입 이동을 비교하라. ④ 별도 역방향 분석 P→H, H→B/E, B→H, E:return t에서 P와 B는 nop이고 H는 변수를 읽지 않는 추상 비결정 분기라 정의한다. 세 노드 모두 USE=∅다. 정상 공집합 생존 해와 ghost 초기화의 잘못된 추가 해를 구하라. 실제 compiler·학생 실행은 하지 않는다.

힌트 1

a의 합류는 {2,5}지만 선택한 실행의 a는 하나다. n=0은 t=7 정의가 그대로 출구에 도달한다.

힌트 2

새 임시 tmp=3*a와 t=tmp 대입을 분리한다. 별도 생존 CFG의 순환에서는 읽히지 않는 ghost가 서로 전달될 수 있다.

풀이와 답 확인

  1. a에는 참 가지의 da2와 거짓 가지의 da5가 도달한다. 값 후보는 {2,5}이고 전체 경로에 공통인 단일 상수 a는 없다. 각 실행에서는 루프 동안 a가 불변이다.

  2. n=0에서는 두 c 모두 출력 []와 반환 7이다. n=2에서 참이면 [6,7]과 반환 6, 거짓이면 [15,16]과 반환 15다.

  3. t=7; 분기로 a 결정; tmp=3*a; 루프 안 t=tmp; emit(t+i); return t를 구성한다. n=2 곱셈은 2회에서 1회다. 기존 t=3*a를 루프 앞에 대입하면 n=0 반환이 참 6/거짓 15로 바뀌어 실패한다.

  4. 별도 CFG의 정상 IN은 네 노드 모두 {t}다. ghost를 P,H,B에 처음 넣고 E에는 넣지 않으면 H/B의 순환이 이를 유지하고 P도 받아 IN[P/H/B]={t,ghost}, IN[E]={t}인 더 큰 고정점이 가능하다. 식 만족만으로 초기화가 적절했다고 인증할 수 없다.

도달 정의 두 개는 실행 중 a를 동시에 두 값으로 만드는 뜻이 아니다. 0회 반환 7과 두 양수 경로의 출력·반환을 유지하려면 새 tmp만 이동한다. 별도 생존의 최소 해는 모두 {t}이며 ghost가 남은 더 큰 해는 잘못된 초기화의 반례다.

해결한 뒤 점검할 것

  • 정의 위치 {da2,da5}, 값 후보 {2,5}, 실행별 불변과 전체 단일 상수 부재를 구별한다.

  • 반복이 0회이면 출력 목록이 비어 있고 반환값이 7임을 제시한다. 두 번 반복할 때 c가 참이면 출력 목록 [6,7]과 반환값 6을, c가 거짓이면 출력 목록 [15,16]과 반환값 15를 각각 제시한다.

  • 새 임시 변환과 기존 t 이동의 0회 실패를 비교하고 곱셈 감소의 모형 범위를 명시한다.

  • 네 노드 생존 식과 ghost 추가 해를 확인하며 손계산과 실제 compiler/학생 미수행을 구별한다.
