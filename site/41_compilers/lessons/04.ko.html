소단원 4.1

재귀하강·LL

문법의 빈칸을 함수로 채우면 입력의 구조를 읽을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • terminal은 입력 토큰이다

  • 함수가 다른 함수를 호출할 수 있다

학습 목표

  • LL(1)의 세 기호 뜻을 설명한다

  • 좌재귀와 결합법칙 문제를 구별한다

나눗셈 꼬리를 오른쪽 재귀로 바꾸면 계산도 오른쪽으로 바뀌어야 할까?

이번 새 문법은 E→E / P | P, P→num | (E)다. num은 양의 정수 리터럴이고 /는 수학적 유리수 나눗셈이다. 고정 폭 정수의 절단, 0 분모, 부작용은 제외한다. 시작 E를 그대로 순진하게 호출하면 입력 위치를 바꾸지 않고 E를 다시 부른다.

언어를 보존하는 새 문법 E→P R, R→/ P R | ε를 사용한다. R의 파스트리는 오른쪽 꼬리지만 AST는 첫 P를 acc에 저장하고 각 / P마다 Div(acc,P)로 바꾸어 왼쪽 결합을 구현할 수 있다. 문법의 인식과 수학적 의미를 서로 다른 검사로 남긴다.

좌재귀 제거와 좌인수분해는 다른 문제를 해결한다. S→id (id) | id [id]는 첫 id에서 충돌하므로 S→id U, U→(id) | [id]로 공통 접두사를 꺼낸다. 이는 한 단계 선택을 늦추는 변환이며 모든 문법의 LL(1)을 자동 보장하지 않는다.

먼저 확인할 개념
  • 입력을 소비하는 재귀와 왼쪽 누적

    토큰 소비 없이 자기 호출하는 문제와 변환 뒤 AST 결합 방향을 분리한다.

  • 전체 종료 확인

    첫 원자나 접두사 성공만으로 수락하지 않고 남은 입력까지 확인한다.

루트에서 내려가는 읽기

파싱은 토큰 열이 문법이 만드는 구조에 맞는지 알아보는 과정이다. 하향식 파싱은 시작 기호에서 필요한 구조를 펼쳐 입력과 맞춘다. 재귀하강은 비단말마다 함수를 두고 그 비단말이 요구하는 부분을 읽도록 구현하는 방식이다.

LL(1)은 왼쪽부터 입력을 읽고 가장 왼쪽 비단말을 전개하며 한 토큰의 미리보기로 생산 규칙을 고르는 문법 부류다. 재귀하강 전체가 반드시 LL(1)은 아니다. 되돌아가기나 여러 토큰 미리보기를 사용하는 변형과 여기의 예측 파서를 구별한다.

입력을 먹지 않는 재귀

E→E+T|T를 그대로 함수로 옮겨 E가 E를 먼저 부르면 첫 토큰을 소비하기 전에 자신을 다시 호출한다. 이 순진한 하향식 구현에서는 호출만 쌓인다. 문법이 틀렸다는 뜻이 아니라 이 선택 방법에 맞지 않는다는 뜻이다.

좌재귀를 없앤 문법은 E→T R, R→+T R|ε, T→id|(E)이다. 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 이 문법에서는 E가 T를 먼저 읽고 R이 이어지는 +T를 담당한다. R은 +를 보면 그 토큰을 소비한 뒤 T를 읽는다. ε는 아무 토큰도 소비하지 않는 규칙이므로 올바른 뒤따름 상황에서만 선택한다.

인식과 의미를 잇기

문법을 바꾸어 같은 토큰 열을 받아들여도 parse tree 모양이 바뀔 수 있다. 덧셈 꼬리를 오른쪽으로 묶은 문법이 계산의 결합 방향을 자동으로 결정한다고 생각하면 곤란하다. AST를 만들 때 원하는 결합법칙을 따로 구현한다.

예를 들어 뺄셈 목록 8−3−2를 왼쪽 누적하면 (8−3)−2=3이고 오른쪽으로 묶으면 8−(3−2)=7이다. 토큰 수락과 결과 의미가 서로 다른 검증 대상이라는 사실이 이 차이에 드러난다.

나눗셈 꼬리를 오른쪽 재귀로 바꾸면 계산도 오른쪽으로 바뀌어야 할까?

S→id (id) | id [id]

첫 토큰 id가 겹친다

원래 선택 칸은 충돌한다

S→id U

id를 소비한 뒤 ( 또는 [를 본다

두 U 대안의 시작은 서로 다르다

첫 두 행은 같은 토큰열을 서로 다른 의미 행동으로 조립한 비교다. 뒤 두 행은 별도 호출 문법의 선택 위치 비교다. parse tree의 오른쪽 꼬리를 그대로 수치 재귀와 연결하지 않는다.

중간 과정을 따라가는 예제

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 입력 id+id+id$를 E,T,R 호출 관점에서 추적하라. AST는 +를 왼쪽 누적해 만든다고 가정한다.

  1. E는 T를 호출한다. T가 첫 id를 소비하고 첫 원자 노드 a를 반환한다.

  2. 다음 +를 R 또는 대응 반복문이 소비하고 T가 두 번째 id의 노드 b를 만든다. 누적 AST는 Plus(a,b)다.

  3. 다음 +와 세 번째 id의 c를 읽어 누적 AST를 Plus(Plus(a,b),c)로 바꾼다.

  4. 미리보기 $에서 꼬리는 ε로 끝난다. 최상위에서 $인지 확인한 뒤 전체 수락한다.

세 id와 두 +를 소비하고 왼쪽 누적 AST를 만든다. 입력 끝 확인까지 해야 전체 문장의 수락이다.

조건을 바꾸어 비교하기

같은 인식 결과의 다른 값

새 E/R/P에서 36/3/2를 처리할 때 왼쪽 누적과 잘못된 오른쪽 조립을 비교하라.

  1. 첫 P는 Num(36)이다. 첫 /3 뒤 acc=Div(36,3)이며 값은 12다.

  2. 다음 /2 뒤 Div(Div(36,3),2)의 값은 6이다. $에서 R은 ε를 선택하고 최상위 끝을 확인한다.

  3. 오른쪽 조립은 Div(36,Div(3,2))이고 안쪽 3/2에 36을 나누면 24다.

양쪽은 토큰을 끝까지 읽어도 의미가 다르다. 원하는 왼쪽 정책은 값 6이다.

비교할 점

기본 뺄셈의 차이에 더해 나눗셈의 유리수 중간값과 AST 행동을 확인한다.

nullable 접두사 뒤에 숨어 있는 좌재귀

별도 A→B A x | y, B→ε | b를 순진한 하향식 함수로 옮겨 B가 ε를 선택하는 경로를 추적하라. 이 문법이 y를 생성하지 못한다는 결론도 검토하라.

  1. A가 B를 호출하고 B→ε는 입력을 소비하지 않는다.

  2. 그 다음 A를 같은 입력 위치에서 다시 호출하면 이 선택 경로는 진전이 없다. B를 먼저 호출했다는 사실만으로 안전하지 않다.

  3. 하지만 A→y라는 직접 유도가 있으므로 y는 언어에 포함된다. 구현의 순진한 선택 경로와 언어 자체를 구별한다.

nullable 접두사 뒤 자기 호출도 소비 없는 재귀를 만든다. 문법의 y 유도를 부정하지 않는다.

비교할 점

기본의 눈에 보이는 E→E+T에서 nullable 접두사를 거치는 경우로 넓힌다.

종이와 본문으로 직접 해보기

뺄셈용 반복 파서가 먼저 8을 읽고 뒤의 −3, −2를 차례로 왼쪽 누적한다. 각 누적값과 오른쪽 결합값을 계산하라.

힌트 보기

첫 누적값 8에서 한 항씩 뺀다. 오른쪽 묶음은 안쪽 3−2부터 계산한다.

풀이 보기

왼쪽은 8→5→3이다. 오른쪽은 3−2=1,8−1=7이다. 좌재귀 제거 뒤 AST의 결합법칙을 따로 유지해야 한다.

오해와 반례

좌재귀만 없애면 모든 문법은 LL(1)이 된다.

S→id a|id b는 좌재귀가 없지만 id 한 토큰만으로 두 규칙을 구별하지 못한다. 좌인수분해가 필요할 수 있고, 변환 뒤에도 예측표 충돌을 확인해야 한다.

연습 1 · 값과 상태 예측

같은 왼쪽 누적 정책으로 48/4/3을 처리할 때 두 중간값과 오른쪽 조립값을 구하라.

힌트 1

48을 먼저 acc에 저장한다.

힌트 2

오른쪽 비교에서는 4/3을 먼저 계산한다.

풀이와 답 확인

  1. 왼쪽은 48/4=12, 12/3=4다.

  2. 오른쪽은 48/(4/3)=36이다. 두 AST의 오른쪽 자식 형태도 다르다.

왼쪽 값은 4, 오른쪽 값은 36이다.

흔한 오답에서 다시 생각하기

꼬리가 오른쪽 재귀이므로 정답은 언제나 36이다.

문법의 꼬리와 의미 acc 행동을 혼동했다. 원하는 정책을 AST에서 먼저 적는다.

연습 2 · 오류 찾아 고치기

R 함수가 /를 보면 P와 R을 읽고 Div(P,R결과)를 만들며 빈 R의 값을 1로 정한다. 이 방식이 왼쪽 나눗셈을 구현한다는 주장을 수정하라.

힌트 1

36/3/2의 꼬리부터 계산한다.

힌트 2

AST의 누적된 왼쪽 피연산자가 어디에 저장되는지 본다.

풀이와 답 확인

  1. 꼬리 값은 3/(2/1)=3/2가 되고 전체는 36/(3/2)=24다.

  2. 왼쪽 정책은 첫 P를 acc로 받고 반복마다 Div(acc,다음 P)를 만든다. R의 빈 종료에는 acc를 그대로 반환한다.

수치 1을 빈 꼬리의 값으로 두는 오른쪽 접기는 왼쪽 정책을 보존하지 못한다.

흔한 오답에서 다시 생각하기

빈 꼬리 값이 나눗셈 항등원 1이므로 모든 묶임이 같다.

항등원은 마지막 빈 부분만 다룬다. 나눗셈은 결합법칙이 없어 중간 묶임이 중요하다.

연습 3 · 직접 만들어 보기

S→id (id) | id [id]를 좌인수분해하고 두 원래 문장의 유도와 새 선택 위치를 제시하라.

힌트 1

공통 첫 토큰은 id다.

힌트 2

공통 토큰 뒤의 (와 [를 선택 기호로 남긴다.

풀이와 답 확인

  1. S→id U, U→(id) | [id]로 쓴다.

  2. id(id)는 S⇒id U⇒id(id), id[id]도 S⇒id U⇒id[id]로 유도한다.

  3. S에서 id를 소비한 후 U의 미리보기 (/[로 서로 다른 규칙을 선택한다.

두 문장의 언어와 괄호 종류를 보존하고 선택을 id 뒤로 늦춘다.

흔한 오답에서 다시 생각하기

U→id(id)|id[id]로 공통 id를 다시 넣는다.

그러면 원래 접두사 충돌이 U에서 반복된다. 제거한 접두사를 두 번 소비하지 않는다.

한 단계 더

S→id a|id b를 S→id U, U→a|b로 바꾸어 첫 id는 공통으로 읽고 다음 토큰으로 선택해 보자. 문법 변환이 언어를 보존하는지 두 문장 id a/id b를 양쪽에서 유도한다.

소단원 4.2

FIRST·FOLLOW

빈 부분을 선택할 때 다음 기호의 자리는 어떻게 알까?

준비 개념과 학습 목표

준비 개념

  • 집합의 합집합

  • ε는 빈 문자열

학습 목표

  • nullable/FIRST/FOLLOW를 구별한다

  • ε와 입력 끝 표지를 혼동하지 않는다

빈 문자열 정보가 세 번 전달돼야 시작 기호에 도착한다면 한 번의 순회로 끝내도 될까?

새 문법은 S→A B C, A→a | ε, B→D, D→b | ε, C→c | ε다. 시작은 S이며 $는 입력 끝이다. 여기서는 ε를 FIRST에 포함하는 기본 관례를 사용한다. ε는 입력의 문자나 FOLLOW의 원소가 아니다.

NULLABLE 계산은 모든 비단말을 false로 시작하고 이전 라운드의 값만 읽는 동시 갱신을 사용한다. 첫 라운드에 A,D,C가 true이고 두 번째에 B, 세 번째에 S가 true가 된다. 규칙 순서를 따라 즉시 값을 쓰는 방식은 중간 라운드가 달라도 최소 고정점은 같다.

연결열 A B C의 FIRST는 빈 앞부분을 건너뛰어 실제 시작 a,b,c를 모두 모으고 모든 기호가 nullable일 때 ε도 넣는다. FOLLOW(A)는 남은 B C에서 b,c를 얻고 그 꼬리도 nullable이므로 $를 받는다. 이 조건은 다음 기호 하나만 복사하는 방식과 다르다.

먼저 확인할 개념
  • 연결열의 FIRST와 nullable 꼬리의 FOLLOW

    앞부분이 비면 다음 시작을 모으고 비는 뒤꼬리에서는 부모 FOLLOW를 전달한다.

  • 표 칸의 FIRST/FOLLOW 배치

    계산한 집합이 빈 규칙을 어느 실제 토큰 칸에 넣는지 확인한다.

시작할 수 있는 토큰

FIRST(α)는 α가 만들 수 있는 문자열의 맨 앞 토큰을 모은다. 이 단원은 빈 문자열도 만들 수 있으면 ε를 FIRST에 넣는 관례를 쓴다. ε는 실제 입력 토큰이 아니다. 어떤 교재는 FIRST를 토큰만의 집합으로 정하고 nullable을 별도로 두므로 표기 관례부터 확인한다.

연결된 AB에서 A가 비어질 수 없다면 첫 토큰은 A에서 온다. A가 비어질 수 있으면 B의 첫 토큰도 가능하다. 모든 기호가 비어질 때만 전체의 FIRST에 ε가 들어간다. 한 기호의 FIRST를 복사하는 방식만으로는 연결열을 계산할 수 없다.

뒤따를 수 있는 토큰

FOLLOW(A)는 시작 기호에서 유도되는 문장 형태에서 A 뒤에 올 수 있는 토큰을 모은다. A가 문장 맨 끝에 놓일 수 있으면 $도 넣는다. 시작 기호의 FOLLOW에는 $를 먼저 둔다. ε는 뒤따르는 입력 토큰이 아니므로 FOLLOW에 넣지 않는다.

B→αAβ에서 FIRST(β)의 실제 토큰은 FOLLOW(A)에 들어간다. β가 비어질 수 있으면 FOLLOW(B)도 전달한다. 규칙 사이에서 정보가 돌아오기 때문에 집합이 더 바뀌지 않을 때까지 반복해야 한다. 유한 토큰 집합에 새 원소만 더하는 계산이라 종료한다.

빈 꼬리를 끝내는 이유

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. T의 시작은 id 또는 (이고 R은 +로 시작하거나 비어진다. E의 시작은 T의 시작과 같다.

T→(E)에서 )가 E 뒤에 오고 시작 E 뒤에는 $가 온다. E→TR의 R은 비어질 수 있으므로 +뿐 아니라 E 뒤의 )와 $도 T 뒤에 올 수 있다. 이 정보가 R의 ε 선택과 T 이후 경계 판단을 연결한다.

빈 문자열 정보가 세 번 전달돼야 시작 기호에 도착한다면 한 번의 순회로 끝내도 될까?
입력 또는 규칙중간 상태 또는 조건결과와 한계

초기

A,B,C,D,S 모두 false

아직 ε 유도를 확인하지 않았다

동시 갱신 1회

A,D,C는 true, B,S는 false

직접 ε 규칙만 반영했다

동시 갱신 2회

B도 true, S는 false

B→D의 정보가 전달됐다

동시 갱신 3회

S도 true

A B C가 모두 비어질 수 있다

고정점 집합

FIRST(S)={a,b,c,ε}

FOLLOW(A)={b,c,$}, FOLLOW(B)=FOLLOW(D)={c,$}, FOLLOW(C)={$}

표는 이전 라운드 값만 읽는 NULLABLE 계산이다. FIRST/FOLLOW의 계산 라운드 수까지 같다는 뜻이 아니다. true로 바뀐 값을 다음 라운드에 유지하고 거짓으로 되돌리지 않는다.

중간 과정을 따라가는 예제

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 모든 비단말의 FIRST와 FOLLOW를 구하라.

  1. FIRST(T)={id,(}. FIRST(R)={+,ε}. E는 비어지지 않는 T로 시작하므로 FIRST(E)={id,(}.

  2. 시작 E에서 $를, T→(E)에서 )를 FOLLOW(E)에 넣어 {$,)}를 얻는다.

  3. E→TR의 맨 끝 R에 FOLLOW(E)를 전달한다. R→+TR에서도 맨 끝 R은 새 원소를 더하지 않는다. FOLLOW(R)={$,)}다.

  4. E→TR와 R→+TR에서 T 뒤 R의 FIRST 중+를 넣고 R이 비어지므로 E/R의 FOLLOW도 전달한다. FOLLOW(T)={+,),$}로 고정된다.

FIRST(E)=FIRST(T)={id,(}, FIRST(R)={+,ε}; FOLLOW(E)=FOLLOW(R)={),$}, FOLLOW(T)={+,),$}.

조건을 바꾸어 비교하기

세 번의 전달과 실제 빈 유도

S가 첫 라운드에 false라는 사실이 ε를 생성하지 못한다는 뜻인지 판단하고 실제 유도를 쓰라.

  1. 첫 라운드는 증거가 아직 전달되지 않은 중간 근사다.

  2. S⇒A B C⇒B C⇒D C⇒C⇒ε로 빈 규칙을 차례로 적용할 수 있다.

  3. 동시 갱신 두 번째에 B가 true가 되고 세 번째에 S가 true가 되어 이 유도의 정보를 반영한다.

중간 false는 최종 불가능 판정이 아니다. S는 nullable이다.

비교할 점

기본의 짧은 A/B 문법에서 한 단계 더 긴 의존 연쇄와 계산 스케줄을 확인한다.

비는 두 기호를 건너뛴 FOLLOW

FOLLOW(A), FOLLOW(B), FOLLOW(D)를 구하고 B 뒤 C가 c로 시작할 수도 비어질 수도 있음을 반영하라.

  1. A 뒤 B C의 실제 시작은 b와 c다. 둘 다 nullable이므로 FOLLOW(S)의 $도 더한다.

  2. B 뒤 C에서 c를 얻고 C가 nullable이라 $도 얻는다. FOLLOW(B)={c,$}다.

  3. B→D의 D가 맨 끝이므로 FOLLOW(D)에 FOLLOW(B)를 전달해 {c,$}를 얻는다.

FOLLOW(A)={b,c,$}, FOLLOW(B)=FOLLOW(D)={c,$}다. ε는 넣지 않는다.

비교할 점

남은 연결열 전체를 처리하고 비단말 한 개의 FIRST만 복사하는 오류를 피한다.

종이와 본문으로 직접 해보기

새 문법 S→AB, A→a|ε, B→b|ε에서 FIRST(S), FOLLOW(A), FOLLOW(B)를 구하라. 시작은 S다.

힌트 보기

A가 비어지면 B로 시작할 수 있다. B도 비어지면 S 전체가 비어진다.

풀이 보기

FIRST(S)={a,b,ε}. FOLLOW(S)={$}; A 뒤 B에서 b를 넣고 B가 비어지므로 $도 넣어 FOLLOW(A)={b,$}. B는 맨 끝이므로 FOLLOW(B)={$}.

오해와 반례

ε를 FOLLOW에 넣어야 빈 규칙을 선택한다.

빈 규칙은 실제 다음 토큰이 FOLLOW에 있는지 보고 선택한다. 위 R은 ) 또는$에서 ε를 고르며 ε라는 입력을 기다리지 않는다.

빈 규칙을 선택한 뒤 같은 미리보기에서 다시 선택해도 되는가?

새 인식 문법은 S→A B C, A→a | ε, B→b | ε, C→c | ε다. 시작 S 뒤에 $를 둔다. 허용 언어는 순서가 정해진 a,b,c를 각각 0회 또는 1회 선택한 여덟 문자열이다. AST나 오류 복구 없이 첫 오류에서 멈춘다.

기호 stack의 맨 위를 왼쪽으로 표시한다. 비단말 전개는 입력을 소비하지 않고, terminal 일치만 소비하며, ε는 비단말만 제거한다. S가 빈 입력을 생성할 수 있으므로 M[S,$]에도 S→A B C가 들어간다. 생산 규칙 전개 수와 문법 terminal 소비 수를 별도 장부로 센다.

선택 표는 뒤에 올 수 있는 기호를 사용하지만 현재 입력이 반드시 끝까지 맞는다는 뜻은 아니다. A를 ε로 없앤 뒤 같은 b를 B가 다시 보아야 한다. 또한 끝 표지 $와 stack의 $를 동시에 확인하며 문법 terminal 소비 수에는 $를 포함하지 않는다.

  • 왼쪽 맨 위 기호 stack과 끝 조건

  • 빈 대안의 FOLLOW 칸

    연결열과 nullable 꼬리에서 FOLLOW를 전달하는 기본 원리를 새 A/B의 빈 선택 칸에 적용한다.

표의 칸에 규칙 넣기

규칙 A→α마다 FIRST(α)의 실제 토큰 a에 대해 M[A,a]에 그 규칙을 넣는다. α가 비어질 수 있으면 FOLLOW(A)의 각 b에도 같은 규칙을 넣는다. 비어 있는 칸은 오류이며 한 칸에 다른 규칙 두 개가 필요하면 LL(1) 충돌이다.

예제의 E행은 id/(에서 TR, T행은 id에서 id와 (에서 (E), R행은 +에서 +TR와 )/$에서 ε다. 그 밖의 모든 칸은 오류다. 이 단원의 )는 문법의 terminal이고 $는 입력 끝 표지라 역할이 다르다.

명시적인 stack 절차

Stack의 맨 위를 왼쪽에 적고 초기 stack E$와 입력 뒤의 $를 둔다. 맨 위가 terminal이면 미리보기와 같을 때 둘을 소비하고 다르면 오류다. 비단말이면 표의 규칙으로 맨 위를 바꾸되 우변의 첫 기호가 새 맨 위가 되게 넣는다.

ε 규칙은 비단말만 제거하고 입력은 움직이지 않는다. 맨 위 $와 미리보기 $가 동시에 만날 때 전체 수락한다. E부분을 읽었다고 남은 토큰을 무시하면 유효한 접두사 뒤의 잘못된 입력을 놓친다.

stack ← [E, $]  # 맨 위가 왼쪽
repeat:
  X ← top(stack); a ← peek(input)
  if X == $: accept only if a == $; otherwise error
  else if X is terminal: require X == a; pop X; consume a
  else: require unique M[X,a]; pop X; push RHS with first symbol on top
        # RHS ε이면 아무것도 넣지 않는다

R이 )에서 빈 규칙을 선택할 수 있는 이유와 현재 A의 닫는 기호를 수락할 수 없는 이유를 구별한다. 올바른 id [ num , num ] ; $의 전개 수/문법 token 소비 수, 빈 목록 id [ ] ; $의 첫 오류도 제시하라. 실제 파서 실행이나 복구는 수행하지 않는다.

힌트 1

A의 두 선택 시작은 (와 [다. P와 R의 FOLLOW는 A의 두 사용 문맥에서 닫는 기호를 합친다.

힌트 2

잘못된 ) 직전 stack은 R ] ; $다. R→ε는 입력을 그대로 둔 채 부모의 terminal ] 검사를 남긴다.

풀이와 답 확인

  1. FIRST(S)={id}, FIRST(A)={(,[}, FIRST(P)={num}다. FIRST(R)는 쉼표 토큰과 ε의 집합이다. FOLLOW(S)={$}, FOLLOW(A)={;}이며 FOLLOW(P)와 FOLLOW(R)는 닫는 소괄호 )와 닫는 대괄호 ]의 집합이다. R의 쉼표 대안과 FOLLOW의 두 닫는 기호는 겹치지 않아 표 충돌이 없다.

  2. S와 A를 전개하고 id와 [를 소비한다. P→num R 뒤 첫 num을 소비하며 R→, num R에서 쉼표와 둘째 num을 소비한다. 이제 stack은 R ] ; $, 미리보기는 )다.

  3. M[R,)]는 R→ε이므로 R을 제거한다. stack ] ; $와 입력 ) ; $의 terminal 비교에서 ]≠)로 처음 오류다. 전개는 S,A,P,R의 쉼표 규칙,R의 빈 규칙으로 다섯 번이고 오류 전 문법 token 소비는 다섯 번이다.

  4. 정상 ] 입력은 같은 다섯 전개 뒤 ]와 ;를 더 소비해 문법 token 소비 일곱 번으로 stack의 $와 입력의 $가 만난다. 빈 목록에서는 [ 뒤 stack이 P ] ; $이고 미리보기가 ]다. 예측표의 P 행과 ] 열이 오류 칸이므로 그 지점에서 처음 거부한다.

  5. FOLLOW의 합집합은 R이 끝날 수 있는 여러 문맥을 알려준다. 현재 부모의 닫는 기호 검사를 대체하지 않는다. 손모형의 수락/거부는 실제 구현 성능·오류 복구·학생 수행의 증거가 아니다.

표는 LL(1) 충돌이 없다. 잘못된 )에서는 R의 ε 선택 뒤 부모 terminal ]와의 불일치로 거부하며 다섯 전개/다섯 문법 token 소비를 기록한다. 정상 입력은 다섯 전개/일곱 소비로 전체 수락한다. 빈 목록은 P/미리보기 ]에서 거부한다.

해결한 뒤 점검할 것

  • ε를 FIRST에 포함하는 관례와 FOLLOW에서 제외하는 관례를 명시하고 두 닫는 기호의 합집합 근거를 설명한다.

  • R의 빈 전개와 현재 A의 terminal 불일치를 다른 단계로 기록하며 오류 위치를 )에 둔다.

  • 정상/오류 입력의 전개 5와 문법 token 소비 7/5 및 빈 목록의 P 오류를 맞춘다.

  • 전체 종료·첫 오류 중단·모형 기호 수와 실제 구현 실행 범위를 구별한다.

보강 자료의 출처와 확인 범위
  • Cornell Top-down LL parsing

    실제 전체 0–214행을 읽었다. 항목 stack의 SCAN/PREDICT/COMPLETE, NULLABLE/FIRST/FOLLOW의 최소 고정점과 토큰만 FIRST 관례, 빈 칸/충돌, 변환 뒤 AST 누적을 확인했다. 아래 기호 stack은 항목 stack과 별도 표현이고 새 나눗셈·nullable 연쇄·닫는 기호 사례는 자체 모형이다.

  • Columbia Aho Predictive Top-Down Parsers

    실제 전체 0–163행을 읽었다. ε를 FIRST에 넣는 관례, 연결열/nullable 꼬리의 FOLLOW 전달, 두 nullable 대안 및 FIRST/FOLLOW 충돌, 좌재귀 제거·좌인수분해를 확인했다. 연습의 별도 문법과 상태 추적은 자체 손논증이며 실제 파서를 실행하지 않았다.

전체 기본 세 소단원과 보강의 세 표·여섯 예제·12연습의 두 힌트/풀이/답/오답·recap·전이를 독립 손검산했다. 나눗셈 36/3/2의 왼쪽 6 대 오른쪽 24와 48/4/3의 4 대 36, nullable 접두사 재호출, 좌인수분해와 FOLLOW 충돌을 확인했다. 동시 NULLABLE 갱신의 세 변화 라운드와 최소 고정점, 연결열 FIRST/FOLLOW를 확인했다. 기호 stack의 ac/ba/aa/빈 입력·여덟 언어·최대 네 기호를 추적했다. 전이의 FOLLOW 합집합과 terminal 불일치, 생산 전개 다섯 번과 정상/오류 문법 token 소비 일곱/다섯 번을 확인했다. 빈 전개에서 잘못 c를 소비하면 acc를 거짓 수락하는 추가 반례도 손으로 확인했다.
