소단원 4.1

재귀하강·LL

문법의 빈칸을 함수로 채우면 입력의 구조를 읽을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • terminal은 입력 토큰이다

  • 함수가 다른 함수를 호출할 수 있다

학습 목표

  • LL(1)의 세 기호 뜻을 설명한다

  • 좌재귀와 결합법칙 문제를 구별한다

루트에서 내려가는 읽기

파싱은 토큰 열이 문법이 만드는 구조에 맞는지 알아보는 과정이다. 하향식 파싱은 시작 기호에서 필요한 구조를 펼쳐 입력과 맞춘다. 재귀하강은 비단말마다 함수를 두고 그 비단말이 요구하는 부분을 읽도록 구현하는 방식이다.

LL(1)은 왼쪽부터 입력을 읽고 가장 왼쪽 비단말을 전개하며 한 토큰의 미리보기로 생산 규칙을 고르는 문법 부류다. 재귀하강 전체가 반드시 LL(1)은 아니다. 되돌아가기나 여러 토큰 미리보기를 사용하는 변형과 여기의 예측 파서를 구별한다.

입력을 먹지 않는 재귀

E→E+T|T를 그대로 함수로 옮겨 E가 E를 먼저 부르면 첫 토큰을 소비하기 전에 자신을 다시 호출한다. 이 순진한 하향식 구현에서는 호출만 쌓인다. 문법이 틀렸다는 뜻이 아니라 이 선택 방법에 맞지 않는다는 뜻이다.

좌재귀를 없앤 문법은 E→T R, R→+T R|ε, T→id|(E)이다. 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 이 문법에서는 E가 T를 먼저 읽고 R이 이어지는 +T를 담당한다. R은 +를 보면 그 토큰을 소비한 뒤 T를 읽는다. ε는 아무 토큰도 소비하지 않는 규칙이므로 올바른 뒤따름 상황에서만 선택한다.

인식과 의미를 잇기

문법을 바꾸어 같은 토큰 열을 받아들여도 parse tree 모양이 바뀔 수 있다. 덧셈 꼬리를 오른쪽으로 묶은 문법이 계산의 결합 방향을 자동으로 결정한다고 생각하면 곤란하다. AST를 만들 때 원하는 결합법칙을 따로 구현한다.

예를 들어 뺄셈 목록 8−3−2를 왼쪽 누적하면 (8−3)−2=3이고 오른쪽으로 묶으면 8−(3−2)=7이다. 토큰 수락과 결과 의미가 서로 다른 검증 대상이라는 사실이 이 차이에 드러난다.

중간 과정을 따라가는 예제

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 입력 id+id+id$를 E,T,R 호출 관점에서 추적하라. AST는 +를 왼쪽 누적해 만든다고 가정한다.

  1. E는 T를 호출한다. T가 첫 id를 소비하고 첫 원자 노드 a를 반환한다.

  2. 다음 +를 R 또는 대응 반복문이 소비하고 T가 두 번째 id의 노드 b를 만든다. 누적 AST는 Plus(a,b)다.

  3. 다음 +와 세 번째 id의 c를 읽어 누적 AST를 Plus(Plus(a,b),c)로 바꾼다.

  4. 미리보기 $에서 꼬리는 ε로 끝난다. 최상위에서 $인지 확인한 뒤 전체 수락한다.

세 id와 두 +를 소비하고 왼쪽 누적 AST를 만든다. 입력 끝 확인까지 해야 전체 문장의 수락이다.

종이와 본문으로 직접 해보기

뺄셈용 반복 파서가 먼저 8을 읽고 뒤의 −3, −2를 차례로 왼쪽 누적한다. 각 누적값과 오른쪽 결합값을 계산하라.

힌트 보기

첫 누적값 8에서 한 항씩 뺀다. 오른쪽 묶음은 안쪽 3−2부터 계산한다.

풀이 보기

왼쪽은 8→5→3이다. 오른쪽은 3−2=1,8−1=7이다. 좌재귀 제거 뒤 AST의 결합법칙을 따로 유지해야 한다.

오해와 반례

좌재귀만 없애면 모든 문법은 LL(1)이 된다.

S→id a|id b는 좌재귀가 없지만 id 한 토큰만으로 두 규칙을 구별하지 못한다. 좌인수분해가 필요할 수 있고, 변환 뒤에도 예측표 충돌을 확인해야 한다.

한 단계 더

S→id a|id b를 S→id U, U→a|b로 바꾸어 첫 id는 공통으로 읽고 다음 토큰으로 선택해 보자. 문법 변환이 언어를 보존하는지 두 문장 id a/id b를 양쪽에서 유도한다.

소단원 4.2

FIRST·FOLLOW

빈 부분을 선택할 때 다음 기호의 자리는 어떻게 알까?

준비 개념과 학습 목표

준비 개념

  • 집합의 합집합

  • ε는 빈 문자열

학습 목표

  • nullable/FIRST/FOLLOW를 구별한다

  • ε와 입력 끝 표지를 혼동하지 않는다

시작할 수 있는 토큰

FIRST(α)는 α가 만들 수 있는 문자열의 맨 앞 토큰을 모은다. 이 단원은 빈 문자열도 만들 수 있으면 ε를 FIRST에 넣는 관례를 쓴다. ε는 실제 입력 토큰이 아니다. 어떤 교재는 FIRST를 토큰만의 집합으로 정하고 nullable을 별도로 두므로 표기 관례부터 확인한다.

연결된 AB에서 A가 비어질 수 없다면 첫 토큰은 A에서 온다. A가 비어질 수 있으면 B의 첫 토큰도 가능하다. 모든 기호가 비어질 때만 전체의 FIRST에 ε가 들어간다. 한 기호의 FIRST를 복사하는 방식만으로는 연결열을 계산할 수 없다.

뒤따를 수 있는 토큰

FOLLOW(A)는 시작 기호에서 유도되는 문장 형태에서 A 뒤에 올 수 있는 토큰을 모은다. A가 문장 맨 끝에 놓일 수 있으면 $도 넣는다. 시작 기호의 FOLLOW에는 $를 먼저 둔다. ε는 뒤따르는 입력 토큰이 아니므로 FOLLOW에 넣지 않는다.

B→αAβ에서 FIRST(β)의 실제 토큰은 FOLLOW(A)에 들어간다. β가 비어질 수 있으면 FOLLOW(B)도 전달한다. 규칙 사이에서 정보가 돌아오기 때문에 집합이 더 바뀌지 않을 때까지 반복해야 한다. 유한 토큰 집합에 새 원소만 더하는 계산이라 종료한다.

빈 꼬리를 끝내는 이유

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. T의 시작은 id 또는 (이고 R은 +로 시작하거나 비어진다. E의 시작은 T의 시작과 같다.

T→(E)에서 )가 E 뒤에 오고 시작 E 뒤에는 $가 온다. E→TR의 R은 비어질 수 있으므로 +뿐 아니라 E 뒤의 )와 $도 T 뒤에 올 수 있다. 이 정보가 R의 ε 선택과 T 이후 경계 판단을 연결한다.

중간 과정을 따라가는 예제

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 모든 비단말의 FIRST와 FOLLOW를 구하라.

  1. FIRST(T)={id,(}. FIRST(R)={+,ε}. E는 비어지지 않는 T로 시작하므로 FIRST(E)={id,(}.

  2. 시작 E에서 $를, T→(E)에서 )를 FOLLOW(E)에 넣어 {$,)}를 얻는다.

  3. E→TR의 맨 끝 R에 FOLLOW(E)를 전달한다. R→+TR에서도 맨 끝 R은 새 원소를 더하지 않는다. FOLLOW(R)={$,)}다.

  4. E→TR와 R→+TR에서 T 뒤 R의 FIRST 중+를 넣고 R이 비어지므로 E/R의 FOLLOW도 전달한다. FOLLOW(T)={+,),$}로 고정된다.

FIRST(E)=FIRST(T)={id,(}, FIRST(R)={+,ε}; FOLLOW(E)=FOLLOW(R)={),$}, FOLLOW(T)={+,),$}.

종이와 본문으로 직접 해보기

새 문법 S→AB, A→a|ε, B→b|ε에서 FIRST(S), FOLLOW(A), FOLLOW(B)를 구하라. 시작은 S다.

힌트 보기

A가 비어지면 B로 시작할 수 있다. B도 비어지면 S 전체가 비어진다.

풀이 보기

FIRST(S)={a,b,ε}. FOLLOW(S)={$}; A 뒤 B에서 b를 넣고 B가 비어지므로 $도 넣어 FOLLOW(A)={b,$}. B는 맨 끝이므로 FOLLOW(B)={$}.

오해와 반례

ε를 FOLLOW에 넣어야 빈 규칙을 선택한다.

빈 규칙은 실제 다음 토큰이 FOLLOW에 있는지 보고 선택한다. 위 R은 ) 또는$에서 ε를 고르며 ε라는 입력을 기다리지 않는다.

자기점검

답과 이유 보기

A가 비어질 수 있을 때.

답과 이유 보기

ε는 입력 토큰이 아니다.

예제 T 뒤에 +가 가능한 이유는?

답과 이유 보기

T 뒤 R이 +로 시작할 수 있다.

FIRST(R)의 실제 토큰이 FOLLOW(T)에 전달된다.

한 단계 더

S→A, A→B, B→c|ε의 초기 빈 집합에서 정보를 한 번씩 전달해 보자. 규칙을 읽는 순서에 따라 중간 집합이 달라도 고정점의 FIRST(S)={c,ε}와 세 FOLLOW={$}는 같음을 확인한다.

소단원 4.3

예측 파서 구현

표 한 장과 쌓인 기호로 괄호 식을 읽을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • stack의 맨 위

  • 앞 단원의 FIRST와FOLLOW

학습 목표

  • 충돌 없는 예측표를 만든다

  • ε 처리와 전체 입력 수락을 추적한다

표의 칸에 규칙 넣기

규칙 A→α마다 FIRST(α)의 실제 토큰 a에 대해 M[A,a]에 그 규칙을 넣는다. α가 비어질 수 있으면 FOLLOW(A)의 각 b에도 같은 규칙을 넣는다. 비어 있는 칸은 오류이며 한 칸에 다른 규칙 두 개가 필요하면 LL(1) 충돌이다.

예제의 E행은 id/(에서 TR, T행은 id에서 id와 (에서 (E), R행은 +에서 +TR와 )/$에서 ε다. 그 밖의 모든 칸은 오류다. 이 단원의 )는 문법의 terminal이고 $는 입력 끝 표지라 역할이 다르다.

명시적인 stack 절차

Stack의 맨 위를 왼쪽에 적고 초기 stack E$와 입력 뒤의 $를 둔다. 맨 위가 terminal이면 미리보기와 같을 때 둘을 소비하고 다르면 오류다. 비단말이면 표의 규칙으로 맨 위를 바꾸되 우변의 첫 기호가 새 맨 위가 되게 넣는다.

ε 규칙은 비단말만 제거하고 입력은 움직이지 않는다. 맨 위 $와 미리보기 $가 동시에 만날 때 전체 수락한다. E부분을 읽었다고 남은 토큰을 무시하면 유효한 접두사 뒤의 잘못된 입력을 놓친다.

stack ← [E, $]  # 맨 위가 왼쪽
repeat:
  X ← top(stack); a ← peek(input)
  if X == $: accept only if a == $; otherwise error
  else if X is terminal: require X == a; pop X; consume a
  else: require unique M[X,a]; pop X; push RHS with first symbol on top
        # RHS ε이면 아무것도 넣지 않는다

구현할 때 남길 정보

오류 칸에서는 해당 비단말과 현재 토큰, 입력 위치를 기록하면 왜 멈췄는지 설명하기 쉽다. 이 단원은 오류 복구 없이 첫 오류에서 멈추는 인식기를 사용한다. 완전한 컴파일러의 AST·의미 검사·친절한 복구는 별도의 단계다.

재귀하강에서도 같은 표를 조건문으로 옮길 수 있다. E는 T와R을 호출하고 T는 id 또는 괄호를 선택한다. R의 빈 선택을 무조건 else로 처리하지 않고 )/$인지 확인하면 잘못된 토큰에서 오류가 선명해진다.

중간 과정을 따라가는 예제

E→T R, R→+T R|ε, T→id|(E). 시작 기호는 E이고 id는 식별자 토큰, $는 입력 끝 표지다. 위 표로 입력 id+id$를 추적하라. Stack 맨 위는 왼쪽이다.

  1. E$ → TR$ → idR$. 첫 id를 소비하여 stack R$, 입력+id$가 된다.

  2. M[R,+]=R→+TR로 stack +TR$를 만든다. +를 소비하여 TR$, 입력id$다.

  3. T→id로 idR$를 만들고 id를 소비하여 R$, 입력$가 된다.

  4. M[R,$]=ε로 R만 제거한다. Stack$와 입력$가 만나 전체 수락한다.

id+id를 수락한다. 생산 규칙 전개는5회(E1,T2,R2), 실제 문법 토큰 소비는3회다.

종이와 본문으로 직접 해보기

입력 id+$와 id id$를 같은 표에서 추적하여 각각 처음 오류인 stack/미리보기를 적어라.

힌트 보기

+를 읽은 뒤에는 T가 필요하다. 첫 id뒤에는 R이 무엇을 허용하는지 본다.

풀이 보기

id+$는 첫 id 뒤 R→+TR와+소비 후 stack TR$/미리보기$에서 M[T,$]가 없어 오류다. id id$는 첫 id 소비 후 R$/미리보기id에서 M[R,id]가 없어 오류다. 접두사id의 성공으로 전체를 수락하지 않는다.

오해와 반례

빈 규칙은 표에서 선택되면 입력 토큰 하나를 소비한다.

R→ε는 R만 없앤다. id$에서 $까지 소비해 버리면 종료 표지의 동시 확인을 깨뜨린다. ε는 입력에 적힌 문자도 토큰도 아니다.

한 단계 더

손으로 M행과 stack을 그려 (id+id)$를 처리하라. 안쪽 E의 R이 )에서 비어지고 T의 닫는 괄호를 소비한 뒤 바깥 R이 $에서 비어지는 서로 다른 두 종료 지점을 표시한다. 아래 구현 모형은 실행하지 않은 교육용 의사 절차다.
