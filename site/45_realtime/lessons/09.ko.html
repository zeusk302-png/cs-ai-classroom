소단원 9.1

세마포어·mailbox·FIFO

신호가 세 번 왔다는 사실과 세 개의 측정값을 저장했다는 사실은 같을까?

준비 개념과 학습 목표

준비 개념

  • 생산자는 정보를 만들고 소비자는 처리한다.
  • 큐는 데이터와 그 순서를 유지한다.

학습 목표

  • 횟수 통지와 데이터 전달을 구별한다.
  • 자료 구조의 수명·호환성·대기 조건을 비교한다.

세마포어는 횟수와 허가

counting semaphore는 가능한 take 횟수를 count로 유지한다. count가0이면 즉시 take를 할 수 없으며 thread는 대기 여부를 선택한다. give는 limit까지 count를 올린다. limit1이면 여러 give가 처리 전에 합쳐질 수 있다.

세마포어 안에 측정값 자체가 자동 저장되는 것은 아니다. 값10/20/30을 세 번 통지해도 단일 변수에30만 남으면 이전 값은 복구할 수 없다. 값 보존이 필요하면 큐 등 별도 데이터 경로를 설계한다.

FIFO는 항목 순서와 수명

FIFO는 먼저 넣은 항목을 먼저 꺼내는 데이터 순서를 뜻한다. Zephyr FIFO는 연결된 item을 다루며 같은 item을 꺼내기 전에 다시 넣지 않는다. 항목의 메모리가 유효하고 사용 중 덮이지 않도록 해야 한다.

FIFO 데이터 순서와 대기 thread를 어느 우선순위로 깨우는지는 다른 질문이다. 이름만으로 모든 thread가 공정하게 같은 순서로 실행된다고 결론 내리지 않는다. fixed-size copy인 message queue와 item 수명 관리도 다르다.

mailbox의 만남 조건

Zephyr mailbox는 thread 사이에서 상대 조건을 맞추어 메시지를 전달한다. 수신자를B로 지정한 A의 메시지를C가 대신 받지 못한다. 이 API는ISR용 일반 통신수단이 아니다. mailbox란 말의 의미는 RTOS마다 다를 수 있다.

동기 전송에서는 데이터 회수가 끝날 때까지 기다리는 구간을 확인한다. 여기서 수신 대기 timeout이 전체 전송의 최대시간을 보장하지 않을 수 있다. 실시간 설계에서는 API 이름뿐 아니라 완료 조건과 최악 지연을 읽어야 한다.

중간 과정을 따라가는 예제

소비자가 아직 실행되지 않았다. 초기 count0/limit1 세마포어에 give가세 번 발생한다. 매번 공유 변수에10,20,30을 순서대로 써 놓았다. 소비자가 그 뒤 nonblocking take를 두 번 시도하면 결과는? 별도 FIFO에 서로 다른 항목10/20/30을 넣은 경우와 비교하라.

  1. 첫 give 후 count1, 둘째·셋째는limit1을 넘지 않아 count1이다. 공유 변수 최종값은30이다.
  2. 첫 take 성공으로count0, 둘째 take는즉시 실패한다. 값10/20은공유 변수에남아 있지 않다.
  3. FIFO에 유효한 서로 다른 항목을 넣었다면첫세 get 결과는10→20→30이다.
  4. 세마포어의 처리 가능한 통지1개와FIFO의보존 데이터3개는같지 않다.

take 성공1/실패1, 단일변수30이다. 별도 FIFO는항목10/20/30을순서대로보존한다.

종이와 본문으로 직접 해보기

count0/limit3이면give3회후take2회결과와잔여count는? mailbox 메시지를A→B로지정했는데C가A에게서받겠다고대기하면전달되는가?

힌트 보기

limit조건과송신자의대상조건을각각확인한다.

풀이 보기

count는0→1→2→3, take2회모두성공해1이남는다. C는송신자가정한B가아니므로그메시지를받지못한다.

오해와 반례

세마포어count3이면이전측정값3개도항상저장되어있다.

count는통지/허가횟수다. 값의저장은별도다. 단일변수를연속덮으면count가3이어도최종값하나만남을수있다.

소단원 9.2

ISR와 태스크 통신

인터럽트가 측정값을 받았을 때 오래 걸리는 분석까지 그 자리에서 해도 될까?

준비 개념과 학습 목표

준비 개념

  • ISR은하드웨어사건에반응한다.
  • 태스크는스케줄러가실행할시간을배정한다.

학습 목표

  • ISR의짧은처리와태스크의후속처리를구분한다.
  • 비대기통신실패와데이터수명을처리한다.

빨리끝내고정보를남기기

일반ISR에서는원인확인·필요한장치처리·작은정보전달을하고시간이많이드는분석은태스크에넘길수있다. ISR이길어지면다른실행의응답지연에영향을준다.

thread전용API와ISR에서도가능한API를구분한다. 사용할수있는통신API라도빈큐나가득찬큐를ISR에서기다리면안된다. zero-latency ISR같은특수문맥은일반ISR과달리kernel API사용자체가금지될수있다.

복사와포인터전달

고정크기message queue에값을복사하면지역변수에서보낸내용을큐가보존한다. 반대로포인터만전달하면가리키는객체가소비시점까지살아있어야한다. ISR의임시stack객체주소를남기고돌아오는계획은위험하다.

큰데이터는미리확보한버퍼pool에서가져오고소유권을넘기는방식을생각한다. 소비처리와해제가끝날때까지재사용하지않는다. 작은복사도길이·큐용량·실패처리를확인하며복사비용이0이라고가정하지않는다.

통지후언제실행되는가

ISR이태스크를준비상태로만들어도그태스크가즉시실행된다고보장되지않는다. 다른우선순위작업과스케줄규칙때문에늦게시작할수있다. 사건→ISR→큐등록→태스크시작→처리끝시간선을쓴다.

ISR의nonblocking enqueue가실패하면자료를저장하지못했다는사실을남기고손실·장치억제등정책을따른다. 성공처럼통지하거나실패반복을무한루프로만들면시간예산과데이터의미가흐려진다.

중간 과정을 따라가는 예제

자체단일CPU시간선에서하드웨어사건t0에ISR이즉시시작한다. 원인확인4μs, 작은값복사/큐등록3μs, 마무리3μs다. 큐등록은성공하고ISR끝뒤태스크대기20μs, 처리50μs다. 다른비용0이다. ISR점유·태스크시작·완료시간을구하라.

  1. ISR점유는4+3+3=10μs여서t10에끝난다.
  2. 태스크는ISR끝뒤20μs대기하므로t30에시작한다.
  3. 처리에50μs가걸려t80에완료한다.
  4. 사건→처리완료지연은80μs, 태스크CPU처리시간은50μs다. ISR등록완료가처리완료는아니다.

ISR10μs, 태스크시작30μs, 최종완료80μs다. 가상시간이며실측/마감보장아니다.

종이와 본문으로 직접 해보기

큐가이미가득차서ISR의즉시등록이실패했다. 정상예제처럼처리가끝났다고기록해도되는가? 포인터전달버퍼X를태스크가읽기전에다음ISR이덮어쓰는문제도설명하라.

힌트 보기

실패한항목과아직소비하지않은항목의수명을따로생각한다.

풀이 보기

등록실패를분기하여손실/재시도가능여부/장치억제등정책을따른다. 완료로기록하지않는다. X는소비자의해제전까지재사용하지않거나값복사/별도버퍼로전달한다.

오해와 반례

ISR이깨운태스크는항상즉시실행되므로큐가필요없다.

스케줄지연과다음사건도착이있다. 예제도ISR후20μs대기한다. 데이터보존이나통지합침허용을업무조건에맞춰정해야한다.

자기점검

예제에서태스크대기가40μs면완료는?

한 단계 더

소단원 9.3

bounded buffer·backpressure

생산자가 계속 더 빠르면 큐를 크게 만드는 것만으로 해결될까?

준비 개념과 학습 목표

준비 개념

  • 유한큐에는최대항목수가있다.
  • 생산과소비속도가다르면쌓이는양이변한다.

학습 목표

  • 고정용량큐의순서와가득참을추적한다.
  • 대기·거절·손실및생산억제정책을구별한다.

저장가능량에경계두기

bounded buffer는담을수있는항목수에상한을둔다. 개수q와용량K는0≤q≤K를유지한다. 빈큐의소비와가득찬큐의생산을즉시실패/대기/손실정책등으로명확히정한다.

Zephyrmessage queue는최대고정크기항목수를갖는다. ZephyrFIFO그자체를고정용량ring이라고혼동하지않는다. FIFO를제한하려면응용의유한item pool등추가조건을정한다.

역압은앞단의생산을조절

backpressure는소비/저장여유가부족하다는신호를앞단으로돌려생산을늦추는것이다. thread는상황에따라빈자리대기를선택할수있지만ISR에서block하면안된다. 입력장치가멈출수있는지도확인한다.

가득찰때새항목을버리거나옛항목을버리는정책은정보손실정책이다. 손실이허용되지않는업무라면단순삭제를흐름제어의해결이라고부를수없다. 번호·누락량·복구규칙을남긴다.

평균률과급증량

생산률이소비률보다계속높으면유한버퍼는언젠가찬다. 버퍼증가는가득차는시간을늦추지만지속속도차를없애지않는다. 반대로평균생산이낮아도한번의큰burst로가득찰수있다.

실시간평가에는큐에머무는시간과마감도포함한다. 큐크기와성공한전달개수만보면오래된값을늦게처리하는문제를놓칠수있다. 원고의률예제는유체근사이며실제정수사건일정은별도로작성한다.

중간 과정을 따라가는 예제

용량3인값복사FIFO큐가비어있다. 즉시연산을순서대로실행한다: putA,putB,putC,putD,get,putD,get,get,get. 가득찬put은새항목을거절하고기존항목은유지한다. 성공get은head를제거한다. 각큐상태와최종get순서를구하라.

  1. putA/B/C뒤큐는[A]→[A,B]→[A,B,C]이다. 첫putD는거절되어[A,B,C]그대로다.
  2. 첫get은A를꺼내[B,C]다. 다시putD는성공하여[B,C,D]다.
  3. 이어get은B,C,D순서다. 상태[C,D]→[D]→[]다.
  4. D는첫시도실패/두번째성공이다. 성공put4회/get4회, 거절1회이며모든성공get순서는A,B,C,D다.

가득찬D첫시도만거절된다. 출력A/B/C/D, 마지막큐빈상태다.

오해와 반례

큐용량을두배로늘리면지속적으로느린소비자의문제가사라진다.

예제용량800이면가득차기까지4초로늘뿐생산초과200항목/초가계속된다. 생산억제·소비개선·허용손실등정책이필요하다.
