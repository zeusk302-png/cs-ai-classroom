소단원 8.1

탐색·삽입·삭제

정렬된 규칙을 가진 나무에서 값을 지울 때 가지를 어떻게 이어야 할까?

준비 개념과 학습 목표

준비 개념

  • 트리의 루트와 자식

  • 키 비교

학습 목표

  • 서브트리 전체의 BST 순서 불변식을 확인한다.

  • 삭제의 세 경우와 후계자 연결을 추적한다.

후계자 키를 올렸을 때 외부에서 잡은 노드 참조는 무엇을 가리킬까?

키 30의 노드 N에 값 A, 왼쪽 키 10, 오른쪽 키 50이 있다. 50의 왼쪽은 키 40인 노드 S와 값 B이고 S의 오른쪽은 키 45인 노드 U와 값 C다. 50의 오른쪽은 70이다. 루트 30을 지울 때 후계자는 40이다. 원래 S 자리는 50의 왼쪽에 U를 연결하여 정리해야 한다. 삭제된 키뿐 아니라 45의 연결과 키에 대응하는 값 B도 보존해야 한다.

키/값 복사 방식은 기존 N에 (40,B)를 저장하고 S 객체를 제거한다. 외부에서 N을 참조했다면 그 객체는 남아 있지만 이제 키가 40이다. S 객체 자체를 새 루트로 옮기는 방식은 S가 남고 N이 제거된다. 두 방식의 최종 사전은 같아도 외부 노드 참조의 생존과 관찰 내용은 다르다. 여기서는 기본 API가 외부 노드 참조를 안정적으로 보장하지 않는 계약이며 키로 다시 조회한다. 실제 C dangling pointer를 읽어 값을 관측했다고 주장하지 않는다.

전체 BST 검사는 조상이 전달한 열린 하한·상한을 적용한다. 루트 20의 왼쪽 10이 오른쪽 자식 25를 가지면 10<25라는 직계 조건은 맞지만 왼쪽 서브트리의 상한 20을 위반한다. 25가 허용되는 구간은 (10,20)이어야 한다. 값의 비교 관계가 일관된 전순서라는 전제와 연결의 트리 조건을 따로 적는다. 단순히 중위가 정렬됐다는 결과뿐 아니라 원래 항목/값 보존까지 대조한다.

먼저 확인할 개념
  • 후계자의 남은 오른쪽 연결

    후계자 원래 자리와 이동 대상의 두 위치를 추적한다.

  • 노드 정체성과 수명

    같은 키/값 결과와 외부 참조의 생존을 나눈다.

한 비교로 내려갈 가지를 고른다

서로 다른 키의 이진 탐색 트리 BST 는 한 노드의 왼쪽 서브트리 모든 키가 작고 오른쪽 모든 키가 크도록 둔다. 바로 옆 자식만의 비교 조건으로 바꾸면 먼 자손의 순서 오류를 놓칠 수 있다.

찾는 키가 현재 키보다 작으면 왼쪽, 크면 오른쪽으로 가고 같으면 찾았다. 비어 있는 링크에 도착하면 없는 키다. 삽입도 같은 경로를 따라 빈 링크에 새 노드를 연결한다.

삭제는 남은 가지를 보존한다

잎이면 부모의 링크를 비운다. 자식이 하나면 부모 링크를 그 자식으로 이어 나머지 서브트리를 보존한다. 루트 삭제는 부모 대신 전체 트리 루트를 바꾼다.

자식이 둘이면 오른쪽 서브트리의 최솟값인 후계자를 이용할 수 있다. 키와 연결된 값을 함께 옮기거나 후계자 노드 자체를 재연결하며 원래 후계자 자리도 지운다.

후계자는 오른쪽 자식을 가질 수 있다

오른쪽 최소 노드는 왼쪽 자식이 없지만 오른쪽 자식은 있을 수 있다. 그 노드를 떼어 낼 때 오른쪽 자식을 원래 부모에 이어야 한다.

삭제 후 중위 순회로 정렬을 확인하고 키 집합과 개수도 비교한다. 정렬된 출력만으로 값 누락을 놓칠 수 있으므로 두 검사를 함께 한다.

두 정상 방식 모두 최종 키 집합은 {10,40,45,50,70}이다. 제거된 객체를 실제로 역참조하지 않으며 이 표는 API 계약에 대한 종이 모형이다.

중간 과정을 따라가는 예제

키 8,4,12,2,6,10,14,11 을 이 순서로 빈 BST 에 넣는다. 키 11 탐색 경로를 적고 루트 8 을 오른쪽 후계자 방식으로 삭제하자. 이 소단원은 서로 다른 키만 둔다.

  1. 11 탐색은 8→12→10→11 이다. 8 보다 크고 12 보다 작고 10 보다 커서 그 방향으로 간다.

  2. 8 의 오른쪽 최솟값은 10 이다. 루트 키/값을 10 의 것으로 교체한다. 원래 10 은 왼쪽이 없고 오른쪽에 11 이 있다.

  3. 12 의 왼쪽을 11 로 잇는다. 중위 결과는 2,4,6,10,11,12,14 로 삭제 전 8 개에서 7 개가 된다.

후계자 10 을 올리고 원래 자리의 오른쪽 11 을 잇는다. 키 8 만 사라져야 한다.

조건을 바꾸어 비교하기

두 자식 삭제의 값 누락

N의 키만 40으로 바꾸고 값 A는 남겼다.

  1. 후계자 항목은 키 40에 값 B가 연결된 쌍이다.

  2. 키만 옮기면 조회 40의 결과가 B 대신 A다.

  3. 삭제 후 키 집합이 맞아도 항목 대응 검사는 실패한다.

정상 복사 방식은 키와 값을 함께 옮긴다.

비교할 점

중위 키 정렬 검사만으로 값 오류를 찾지 못한다.

직계 비교는 모두 통과한다

루트 20의 왼쪽 자식 10이 오른쪽 자식 25를 갖는 구조를 BST로 승인했다.

  1. 직계 비교 10<20과 25>10은 맞다.

  2. 25는 루트 20의 왼쪽 서브트리에 있으므로 조상 조건 25<20도 필요하다.

  3. 조상 상한 20을 자손까지 전달하면 위반이 드러난다.

키 25는 자신의 허용 범위 (10,20) 밖에 있다.

조상 조건을 잃는 국소 검사 반례다.

정상 루트 30 삭제 후 키 45의 탐색 경로와 남은 항목 수는?

힌트 1

힌트 2

중복키와 순서 통계

같은 점수가 세 번 나오면 몇 번째 값과 키의 순위는 어떻게 세어야 할까?

준비 개념과 학습 목표

준비 개념

  • BST 순서

  • 서브트리 크기

학습 목표

  • 중복 정책과 rank/select 규약을 명시한다.

  • 개수 포함 size 불변식을 갱신한다.

중복 후계자의 count를 옮기고 한 항목만 지우면 얼마나 남을까?

다중집합 BST는 각 키에 노드 하나를 두고 반복 항목 수 count를 저장한다. 루트 30의 count는 1, 왼쪽 10의 count는 2, 오른쪽 50의 count는 1이다. 50의 왼쪽 40의 count는 3이고 오른쪽 70의 count는 1이다. 물리 노드는 5개지만 반복 항목은 8개다. 왼쪽 size는 2, 50 서브트리의 size는 5, 루트의 size는 8이다. 키 40의 세 항목을 별도 노드로 나누면 키마다 노드 하나라는 엄격 순서 계약을 깨뜨린다.

30의 마지막 한 항목을 구조 삭제하면서 후계자 40의 키와 count 3 전체를 루트에 옮긴다면 원래 40 노드를 통째로 제거해야 한다. 새 루트의 count는 3, 왼쪽 10의 count는 2, 오른쪽 50과 그 오른쪽 70의 count는 각각 1이므로 총량은 7이다. 원래 후계자 자리에 remove_one(40)을 호출하면 그곳의 count가 2로 남아 두 노드에 같은 키를 분산하고 총량을 9로 잘못 만든다. 한 항목 제거와 구조적 노드 전체 제거는 서로 다른 내부 연산이어야 한다.

rank(x)는 x보다 엄격히 작은 반복 항목 수이며 select(k)는 0부터 시작하는 항목 인덱스를 받는다. 중복이 있으면 rank(select(k))=k를 항상 요구할 수 없다. 같은 키의 여러 인덱스는 그 키의 첫 순위로 돌아온다. 올바른 포함 조건은 r=rank(x)에 대해 r≤k<r+count(x)다. 조회하는 x가 없으면 count가 0이므로 이 구간은 비어 있다. a≤b일 때 두 경계의 차 rank(b)−rank(a)로 반열린 키 범위 [a,b)의 항목 수를 구한다. a>b인 입력을 허용하는 API라면 빈 범위로 처리하거나 거절하는 정책을 따로 정한다.

먼저 확인할 개념
  • count를 포함하는 size

    물리 노드와 반복 항목의 두 크기를 구별한다.

  • 구조 삭제와 항목 보존

    후계자 원래 자리 제거를 count 감소와 분리한다.

같은 키를 무엇으로 볼지 정한다

키마다 하나의 값만 두는 사전은 같은 키 삽입을 값 교체로 다룰 수 있다. Princeton 의 BST 구현이 이 정책이다. 모든 BST 가 동일 키를 같은 방식으로 처리한다는 뜻은 아니다.

이 소단원은 다중집합을 위해 노드마다 count 를 두고 같은 키가 들어오면 count 를 늘린다. 키 순서는 왼쪽<현재<오른쪽으로 유지한다. 같은 키를 새 노드로 무조건 한쪽에 붙이는 설계와 구별한다.

크기는 반복 개수를 포함한다

size(node)=size(left)+count(node)+size(right), 빈 트리 크기는 0 이다. 여기서 size 는 서로 다른 노드 수가 아니라 저장 항목의 총수다.

rank(x)는 x 보다 엄격히 작은 항목의 개수다. select(k)는 0 부터 센 k 번째 항목이며 0≤k<size 다. 왼쪽 크기 L 이면 L..L+count−1 은 현재 키의 구간이다.

갱신 후 조상까지 크기를 맞춘다

같은 키 삽입으로 count 만 늘어도 지나온 조상의 size 는 바뀐다. 한 항목 삭제는 count>1 이면 하나 줄이고 count=1 일 때 구조 삭제가 필요하다.

후계자 count 가 여러 개일 때 단순히 키만 복사하고 한 번만 삭제하면 중복 개수를 잘못 만들 수 있다. 전체 노드/개수 이동과 원래 노드 제거를 일관되게 구현해야 한다.

편향과 성능 저하

키를 정렬한 뒤 넣으면 탐색 트리도 더 빨라질까?

준비 개념과 학습 목표

준비 개념

  • 트리 높이

  • 비교 횟수

  • log2

학습 목표

  • 높이와 탐색 비용의 관계를 설명한다.

  • 정렬 삽입의 최악 트리와 균형 형태를 비교한다.

가장 자주 찾는 키가 루트면 사슬의 평균도 더 작을 수 있을까?

키 1부터 7까지 증가 삽입한 사슬은 높이 6이고 키 i의 비교 횟수는 i다. 루트 4, 자식 2와 6, 잎 1과 3과 5와 7인 트리는 높이 2다. 키 순서대로 비교 수는 3, 2, 3, 1, 3, 2, 3이다. 모든 키를 같은 비중으로 성공 조회하면 사슬 평균은 4, 작은 높이 트리의 평균은 17/7이다. 최악도 각각 7과 3이다. 여기서는 방문 노드마다 3방향 비교를 한 번 센다.

키 1을 확률 p로 찾고 나머지 여섯 키를 각각 (1−p)/6로 찾는 모형을 선언하자. 사슬 평균은 p+(1−p)·27/6=9/2−7p/2다. 다른 트리 평균은 3p+(1−p)·14/6=7/3+2p/3이다. p=9/10이면 각각 27/20과 44/15로 사슬의 이 분포 평균이 더 작다. 이것은 사슬의 최악 위험이 없다는 뜻이나 모든 모양 중 사슬이 최적이라는 증명이 아니다.

두 평균은 p=13/25에서 같다. 분포가 바뀌면 평균 우열도 바뀔 수 있어 최악 방문과 분포 평균과 실제 시간을 별도로 보고한다. 긴 문자열 비교가 많은 문자를 읽으면 노드 방문 수만으로 실제 비트 비용을 보장하지 못한다. 무작위 입력이나 자동 균형 삽입을 실행하지 않았으며 두 고정 모양의 유한 경로만 손으로 계산한다.

먼저 확인할 개념
  • 높이와 모양

    같은 키 수의 서로 다른 최장 경로를 비교한다.

  • 비용 단위와 입력 조건

    word 비교 모형과 실제 시간/긴 키 비용을 나눈다.

비용은 지나간 길이와 연결된다

키 비교가 일정 비용이면 기본 BST 의 탐색·삽입·삭제는 높이 h 에 따라 O(h+1) 비용이 든다. 여기서 높이는 루트부터 가장 먼 잎까지 에지 수이며 한 노드 트리는 0 이다.

각 노드에 자식이 둘까지 있다는 조건은 높이가 작다는 조건이 아니다. 한쪽 자식만 계속 잇는 트리도 BST 순서를 지킬 수 있다.

정렬 입력은 한쪽 사슬을 만들 수 있다

서로 다른 증가 키를 기본 비균형 BST 에 넣으면 모두 오른쪽으로 내려가 새 노드가 붙는다. n 개면 높이 n−1 이며 마지막 키 탐색은 n 개 노드의 비교를 거친다.

전체 삽입의 기존 노드 비교는 0+1+...+(n−1)=n(n−1)/2 다. 자료가 정렬되어 있다는 편의가 이 삽입 방식에서는 비용을 악화시키는 반례다.

순서 불변식과 균형을 따로 보장한다

균형에 가까운 형태는 같은 키 집합을 더 짧은 경로로 찾게 한다. 하지만 일반 삽입을 계속하면 처음의 좋은 모양을 유지한다고 보장할 수 없다.

높이를 관리하는 균형 트리는 추가 불변식과 재구성을 사용한다. 기본 BST 의 순서 조건만 확인해 모든 경우 O(log n)이라고 보고하면 안 된다. 재귀 구현은 길어진 높이만큼 호출 공간도 고려한다.

중간 과정을 따라가는 예제

기본 BST 에 1..7 을 증가 순서로 넣고 키 7 을 찾는다. 별도 동일 집합을 4,2,6,1,3,5,7 순서로 넣는다. 각 높이와 키 7 의 방문 노드 수를 비교하자.

  1. 증가 삽입은 1→2→3→4→5→6→7 의 사슬이다. 높이 6, 키 7 방문 7 개다.

  2. 두 번째는 루트 4, 자식 2/6, 다음 1/3/5/7 이다. 높이 2 이고 키 7 경로는 4→6→7 로 방문 3 개다.

  3. 첫 방식 전체 삽입 비교는 0+1+2+3+4+5+6=21 이다. 높이가 작은 두 번째 모양의 중위 순회도 1..7 로 같으므로 키 집합과 형태를 분리해서 본다.

같은 키와 정렬 결과라도 높이 6/2, 탐색 방문 7/3 으로 다르다. 기본 삽입이 자동 균형을 보장하지 않는다.

키 1의 비중이 9/10인 분포에서 두 트리 평균을 계산하라.

  1. 사슬은 9/10+(1/10)(27/6)=27/20이다.

  2. 다른 트리는 27/10+(1/10)(14/6)=44/15다.

두 문자열 키가 첫 L−1문자를 공유하고 마지막에만 다르다.

연습 1 · 값과 상태 예측

두 트리에서 키 4를 찾는 비교 수와 없는 키 8을 찾는 기존 노드 방문 수는?

힌트 1

사슬은 오른쪽으로 내려간다.

힌트 2

다른 트리의 8 경로는 4→6→7이다.

풀이와 답 확인

  1. 키 4는 사슬에서 4회, 다른 트리에서 1회다.

  2. 없는 8은 사슬에서 7개, 다른 트리에서 3개를 지난다.

4와 1, 7과 3이다. 끝 null 검사는 따로 센다.

흔한 오답에서 다시 생각하기

못 찾으면 비교는 0회다.

실패를 판정하기까지 지나간 기존 노드를 센다.

연습 2 · 오류 찾아 고치기

균등 성공 조회 평균 17/7을 모든 조회 분포에 썼다.

힌트 1

각 키의 확률을 지정한다.

힌트 2

키 4만 조회하면 비교는 1이다.

풀이와 답 확인

  1. 균등한 일곱 키가 전제인 평균이다.

  2. 키 4에 확률 1을 두면 다른 트리의 평균은 1이다.

모든 분포의 평균으로 일반화할 수 없다.

흔한 오답에서 다시 생각하기

높이가 2면 평균은 항상 17/7이다.

높이는 분포의 가중치를 정하지 않는다.

연습 3 · 직접 만들어 보기

두 고정 트리의 평균이 같은 p를 구하고 우열 구간을 정하라.

힌트 1

9/2−7p/2=7/3+2p/3을 푼다.

힌트 2

풀이와 답 확인

  1. p=13/25다.

  2. p가 그보다 크면 사슬 평균이 작고 작으면 다른 트리 평균이 작다.

흔한 오답에서 다시 생각하기

같은 두 모양에서도 분포에 따라 차의 부호가 바뀐다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

증가 삽입 n개의 기존 노드 비교와 균등 성공 조회 평균을 유도하라.

힌트 1

삽입은 0부터 n−1을 더한다.

힌트 2

성공 조회는 1부터 n을 더하고 n으로 나눈다.

풀이와 답 확인

  1. 삽입 비교는 n(n−1)/2다.

  2. n≥1에서 균등 성공 평균은 (n+1)/2다.

빈 트리 n=0에는 성공 조회 균등 평균을 정의하지 않는다.

흔한 오답에서 다시 생각하기

n=0에도 평균은 1/2이다.

조회 대상 집합이 빈 경우 균등 분포나 0 분모를 만들지 않는다.

다른 문제에 적용하기

중복 삭제·조회 분포의 두 검산

count 방식의 루트 30은 count 1, 왼쪽 10은 count 2, 오른쪽 50은 count 1이다. 50의 왼쪽 40은 count 3, 오른쪽 70은 count 1이다. 30 한 항목을 지운다. 후계자 전체 이동 뒤 count와 size 및 0기준 select(4), rank(50), [40,70) 항목 수를 구하라. 후계자 원래 자리의 한 항목만 삭제하는 오류와 외부 노드 참조 계약을 설명하라. 별도 키 1부터 7까지 두 고정 모양에서 p=9/10 성공 조회 평균과 최악을 비교하라.

힌트 1

키마다 한 노드의 count 전체를 이동하고 원래 후계자 노드를 통째로 제거한다. 정상 총량은 8−1이다.

힌트 2

순위는 반복 목록으로 검산한다. 조회 분포 평균과 최장 경로는 별도로 계산한다.

풀이와 답 확인

  1. 정상 루트 40은 count 3과 size 7, 왼쪽 10은 count 2와 size 2다. 오른쪽 50은 count 1과 size 2이며 그 오른쪽 70은 count 1과 size 1이다. 원래 40 노드는 없다.

  2. 반복 목록 10, 10, 40, 40, 40, 50, 70에서 select(4)=40이고 rank(50)=5다. [40,70)의 항목 수는 rank(70)−rank(40)=6−2=4다.

  3. 원래 40을 한 항목만 줄이면 루트의 3과 원래 자리의 2가 남아 총 9이며 엄격 키 순서도 위반한다. 키/값 복사와 객체 이동은 외부 참조의 생존 대상이 달라 안정 참조를 임의로 보장하지 않는다.

  4. 별도 두 고정 모양에서 평균은 27/20과 44/15, 최악은 7과 3이다. 사슬의 분포 평균이 작아도 최악 보장이나 실제 측정 우위가 아니다.

항목 총량 7, 후계자 중복 전체 보존, 노드 정체성, 반복 순위, 분포 평균과 최악을 각각 보고한다. 실제 BST·할당·포인터 수명·성능·학생 실행은 미수행이다.

해결한 뒤 점검할 것

  • 후계자의 count 3을 보존하고 원래 노드를 제거해 총량 7을 얻는다.

  • 각 size와 반복 인덱스·엄격 rank·반열린 범위를 검산한다.

  • 총량 9의 오류와 같은 키의 두 노드 및 외부 참조 계약을 구별한다.

  • p 분포 평균과 최악 및 실측의 다른 주장을 명시한다.
