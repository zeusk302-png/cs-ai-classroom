소단원 3.1

연속 메모리와 인덱싱

여덟 칸을 확보했는데 다섯 개만 넣었다면 일곱 번째 칸도 읽어도 될까?

준비 개념과 학습 목표

준비 개념

  • 인덱스는 칸의 번호다. 여기서는 첫 원소의 번호가 0이다. 길이 n은 현재 원소 수, 용량 C는 확보한 슬롯 수이며 n,C는 비음수 정수이고 0≤n≤C다.

  • 이 단원의 가상 주소 모형에서는 한 바이트를 8비트로 정한다. 주소는 바이트 위치를 나타내는 수이고, 슬롯 간격 w는 인접 원소의 시작 주소 차인 양의 정수 바이트 수다. C의 일반 규칙에서는 바이트 비트 수 CHAR_BIT가 구현에 따라 달라질 수 있고 적어도 8이다.

  • 유효한 읽기는 주소가 있는 것뿐 아니라 인터페이스 범위, 초기화, 객체 수명 조건도 만족해야 한다.

학습 목표

  • 주소 공식을 단위와 함께 유도한다.

  • 논리 길이와 확보 용량을 구분한다.

  • 상수 비용 모형의 적용 범위를 설명한다.

다섯 칸 책꽂이에 책이 세 권 있으면 네 번째 칸을 읽어도 책을 얻을까?

칸을 확보한 것과 그 칸을 자료 목록에 넣은 것은 다르다. 배열 표현에서 C는 확보한 칸 수, n은 공개 목록의 길이다. 읽기 계약은 0≤i<n이다. n≤i<C인 칸이 물리적으로 존재해도 이 목록의 항목이라고 반환하지 않는다. 빈 칸에 오래된 글자가 보인다는 관찰은 계약을 바꾸지 않는다.

아래 주소는 시작 512바이트, 칸 폭 4바이트라는 자체 정수 모형이다. i번째 칸 시작은 512+4i다. 바이트 주소와 항목 번호의 단위를 구별하고, 실제 언어의 객체 수명이나 정수 범위 검사를 이 산술만으로 통과했다고 주장하지 않는다. 일정 폭의 연속 칸이라는 전제가 있어야 곱셈 한 번으로 위치를 찾는다.

먼저 확인할 개념
  • 인터페이스와 표현 불변식

    추상 목록에 포함되는 값과 사용하지 않는 저장 칸을 구별한다.

  • 시간·공간 복잡도

    칸 접근의 비용 단위와 동시에 확보한 바이트를 별도로 센다.

같은 크기의 칸을 줄 세우기

연속 배열은 같은 타입의 원소들을 빈틈 없는 연속 영역에 놓는 모형이다. 첫 주소를 b, 원소 한 개의 크기를 w바이트라 하면 i번째 주소는 b+iw다. 곱 iw의 단위가 바이트이므로 주소에 더할 수 있다. 여기서는 주소 계산과 한 슬롯 읽기를 각각 상수 비용으로 보는 word RAM 모형을 사용한다.

이 모형은 실제 메모리 지연이 항상 같다는 측정 주장이 아니다. 캐시 미스, 가상 메모리, 객체의 추가 간접 접근은 별도 비용이다. Python list가 참조를 연속 저장할 수 있어도 그 참조가 가리키는 모든 객체가 연속인 것은 아니다.

유효 인덱스의 계약

추상 동적 배열의 get(i)는 정수 i에 대해 0≤i<n에서만 정의한다. n≤i<C는 확보했지만 아직 논리 원소가 아닌 슬롯이다. 음수 번호를 지원하는 언어는 별도의 변환 계약을 가지며 여기의 get과 혼동하지 않는다. n=0이면 유효 읽기 인덱스는 없다.

C 배열 안 포인터 산술은 같은 실제 배열과 그 바로 다음 위치까지라는 언어 조건을 따른다. 실제 C개 객체 배열이라면 i=C의 one-past 포인터는 만들 수 있지만 역참조할 수 없다. 논리 길이 n이 더 작으면 i=n은 추상 배열 읽기에 유효하지 않으나 실제 확보 배열의 one-past와는 다른 개념이다. 계산의 표현 범위, 유효한 할당 및 객체 수명도 필요하다.

주소와 두 가지 크기

가상 시작 주소 b=0x1000, 슬롯 간격 w=8바이트, n=5, C=8을 택한다. i=3은 네 번째 원소이고 주소는 0x1000+24=0x1018이다. 논리 데이터 슬롯은 40바이트, 확보 슬롯은 64바이트다. 이는 설명용 가상 수치이며 어떤 타입의 sizeof가 항상 8이라는 뜻은 아니다.

용량 공간과 실제 객체 전체 메모리는 같지 않다. 별도로 할당한 객체, 배열 관리 정보, 정렬과 할당기 비용은 이 계산에서 제외했다. b+iw를 바로 계산할 수 있다는 사실이 인덱스 유효성 검사나 객체 수명 검사를 생략해도 된다는 근거가 되지는 않는다.

예약 범위 끝 경계

각 행은 한 칸의 시작 또는 끝 경계다. 532는 여섯 번째 저장 칸이 있다는 뜻이 아니다. 사용량 3×4=12바이트, 예약량 5×4=20바이트다. 이 표는 주소 계산 가능성과 공개 읽기 허용 여부를 함께 보게 한다.

중간 과정을 따라가는 예제

b=0x1000, w=8바이트, n=5, C=8이다. get(3)의 주소와 get(5)의 유효성 및 두 슬롯 크기를 구한다.

  1. 0≤3<5이므로 get(3)은 범위 조건을 만족한다.

  2. 오프셋은 3×8=24바이트=0x18이고 주소는 0x1018이다.

  3. get(5)는 5<n을 만족하지 않아 추상 인터페이스에서 거절한다. 확보 공간 안이라는 사실은 충분하지 않다.

  4. 논리 슬롯 크기는 5×8=40바이트, 확보 크기는 8×8=64바이트다.

주소는 0x1018, get(5)는 범위 밖이다. 슬롯 크기는 40/64바이트다.

조건을 바꾸어 비교하기

주소를 계산해도 읽기 계약은 실패한다

위 표에서 get(2), get(3), get(-1)을 판정하라.

  1. get(2)는 0≤2<3이므로 주소 520에서 목록 항목을 읽는다.

  2. get(3)은 주소 524를 계산할 수 있지만 3<3이 거짓이다.

  3. 이 인터페이스는 음수 번호를 허용하지 않는다. Python의 음수 인덱싱 규칙을 가져오지 않는다.

성공은 get(2)뿐이다. 실패한 두 호출은 상태를 유지하고 오류를 알린다.

비교할 점

본문의 주소 예제를 입력 계약 검사로 확장한다. 산술 결과만 반환하는 구현의 빈틈을 찾는다.

평면 배열로 저장한 자리 배치

2행 3열의 표를 행 우선으로 같은 폭 4바이트 배열에 저장한다. b=512에서 (1,0), (0,2), (2,0)의 주소와 허용 여부를 구하라.

  1. 행 번호는 0 또는 1, 열 번호는 0부터 2까지다.

  2. (1,0)의 평면 번호는 1×3+0=3이며 주소 524다. (0,2)는 번호 2, 주소 520이다.

  3. (2,0)은 행 범위 밖이다. 번호 6과 주소 536을 계산해도 읽지 않는다.

(1,0)과 (0,2)만 허용한다. 행별 별도 할당을 쓴 구현에는 이 하나의 연속 주소식을 그대로 적용하지 않는다.

연습 1 · 값과 상태 예측

n=0, C=5인 위 배열에서 get(0)과 예약/사용 바이트를 예측하라.

힌트 1

길이와 용량을 따로 적어 보자.

힌트 2

풀이와 답 확인

  1. 0<0은 거짓이므로 읽기를 거부한다.

  2. 사용 0×4=0, 예약 5×4=20바이트다.

get(0)은 실패하며 목록은 비어 있다. 공간은 20바이트 예약되어 있다.

풀이와 답 확인

  2. 정상 조건 0≤i<n은 i=3을 거부한다.

i≤n으로 바꾸면 충분하다.

마지막 유효 번호는 n−1이다. 등호를 허용하면 같은 경계 결함이 남는다.

소단원 3.2

용량 증가와 재할당

가끔 전체를 옮기는 append가 왜 여러 번 묶으면 저렴해질까?

준비 개념과 학습 목표

준비 개념

  • append는 맨 뒤에 새 원소를 넣는다. 재할당은 더 큰 새 저장 영역을 얻고 기존 원소를 옮기는 작업이다.

  • 상환 비용은 한 연산의 최대 비용이 아니라 정해진 연산열 전체 비용을 길이로 나눈 경계다. 입력 확률분포를 가정하는 평균 비용과 다르다.

  • 여기서는 원소 한 슬롯 복사와 새 값 쓰기가 각각 1이다. 할당 초기화·관리·해제 및 실제 객체의 가변 복사 비용은 이 정확한 계수에서 제외한다.

학습 목표

  • 배증 확장과 상태 갱신을 추적한다.

  • 단일 최악 비용과 전체 상환 경계를 구분한다.

  • 재할당 도중 최대 공간을 계산한다.

책꽂이를 한 칸씩 늘리는 것과 두 배로 늘리는 것 중 이사 횟수는 어떻게 다를까?

확장 때 기존 항목을 새 칸으로 옮기는 비용과 새 항목을 한 번 쓰는 비용을 나누자. 아래 자체 정책은 처음 n=0, C=1이며 꽉 찼을 때 두 배 용량을 확보한다. 한 항목 복사와 새 항목 쓰기를 각각 1로 세고 할당·해제·관리 비용은 정확한 숫자에서 제외한다.

한 번의 이사가 크더라도 이사 사이에 여러 싼 삽입이 끼면 전체 비용을 연산 수로 나눌 수 있다. 이것이 분할상환 관점이다. 매 호출의 시간 상한이나 실제 Python 리스트의 정확한 용량 정책을 약속하는 수치는 아니다. 할당 실패 때는 성공 경로와 다른 상태 계약도 필요하다.

먼저 확인할 개념
  • 최악·평균·분할상환 구분

    확률 평균 없이 전체 연산열 비용을 계산한다.

  • 자료의 소유권과 수명

    재할당 후 저장 칸의 수명과 항목이 가리키는 객체의 수명을 구별한다.

확장 전후의 계약

초기 n=0, C=1인 배열 A를 두고 append(v)를 실행한다. n<C이면 A[n]=v를 쓰고 n을 1 증가시킨다. n=C이면 먼저 2C개의 새 슬롯 B를 확보하고 j=0,…,n−1의 원소를 B[j]로 복사한 뒤 A를 B로 재결합하고 C를 2C로 바꾼다. 그 다음 새 값을 쓰고 n을 늘린다.

C는 양의 정수이며 모든 할당과 모형의 슬롯 복사가 성공한다고 가정한다. 복사할 범위가 빈 경우에는 반복하지 않는다. 할당 실패 시 이전 A,n,C를 그대로 유지하고 실패를 반환하는 경계를 따로 정할 수 있다. 실제 타입의 복사 예외까지 있는 언어 구현에는 별도의 예외 안전 계약이 필요하다.

전체 쓰기의 기하급수 합

값 1부터 9까지 넣으면 확장 시 복사 수는 1,2,4,8로 합 15다. 새 값 쓰기는 9회라 정확한 모형 비용은 24다. 마지막 한 번만 보면 8개 복사와 새 값 쓰기 1회여서 9이고, 따라서 모든 append가 최악 O(1)인 것은 아니다.

m=1이면 확장이 없어 복사 0회와 새 쓰기 1회다. m≥2회 append에서 복사되는 용량은 마지막 확장 크기까지의 1+2+…+2^k다. 마지막 복사 크기 2^k<m이므로 합 2^(k+1)−1<2m이다. 새 쓰기 m을 더하면 총 비용은 3m 미만으로 상환 O(1)이다. 할당 초기화가 용량에 선형 비례해도 전체 O(m)은 유지하지만 정확한 24라는 계수에는 그 비용을 추가해야 한다.

공간과 수명의 변화

9번째 append 도중 이전 8슬롯과 새 16슬롯이 함께 존재하면 최대 24슬롯이다. 완료 후 이전 공간을 해제하면 용량은 16슬롯이다. 슬롯당 8바이트라는 가상 조건에서 도중 192바이트, 완료 128바이트이며 둘 다 관리 정보와 원소가 가리키는 외부 객체를 제외한다.

실제로 저장 위치가 바뀌면 이전 슬롯 주소나 iterator를 계속 써도 되는지 구현 계약을 확인해야 한다. 이전 슬롯의 수명과 참조된 원소 객체의 수명은 별개다. Python 참조 슬롯 모형에서 같은 객체 참조를 복사했다고 그 객체가 자동 파괴되는 것은 아니다. 여기에 저장한 모형은 Python list의 실제 내부 용량이나 할당기 측정이 아니다.

한 칸씩 증가하는 대안과 비교

같은 빈 시작 C=1에서 6번 끝 삽입한다. 대안은 꽉 찰 때 C를 1만 늘린다.

  1. 대안은 2번째부터 6번째까지 각각 1,2,3,4,5개를 복사한다. 합은 15다.

  2. 새 항목 쓰기 6을 더해 21이다. 두 배 정책은 표에서 13이다.

  3. 작은 표의 비율을 실제 성능 향상률로 해석하지 않는다. 대안의 복사 합은 m(m−1)/2로 증가한다.

정의한 비용에서 21 대 13이며, 증가 정책이 전체 복사량의 증가율을 바꾼다.

비교할 점

숫자만 바꾸는 연습이 아니라 고정 증가와 비율 증가라는 다른 정책을 비교한다.

실패한 이사는 공개하지 않는다

n=C=4, A=[a,b,c,d]에서 새 8칸 확보가 실패했다. 잘못된 구현은 먼저 C=8로 공개한다.

  1. 실패 뒤 C=8인데 실제 A는 4칸이면 length(A)=C가 깨진다.

  2. 성공 전에는 A,n,C를 바꾸지 않고 임시 새 저장을 요청한다.

  3. 이 단순 값 복사 모형에서는 확보·복사가 완료된 뒤 새 A와 C를 공개하고 x를 추가한다. 복사 자체가 실패할 수 있는 타입은 별도 복구 계약이 필요하다.

이 사례의 실패 상태는 기존 A, n=4, C=4다. append는 실패하며 x는 추가되지 않는다.

소단원 3.3

삽입·삭제와 비용

배열 가운데 카드를 넣을 때 어느 방향으로 옮겨야 값을 잃지 않을까?

준비 개념과 학습 목표

준비 개념

  • 순서 보존 시퀀스는 원소의 앞뒤 관계가 의미를 갖는다. insert(i,v)는 기존 i번째 원소 앞에 v를 놓는다.

  • 반복 불변식은 반복 중 항상 유지되는 상태 조건이다. 뒤에서 앞으로 옮기면 아직 복사하지 않은 값을 덮지 않을 수 있다.

  • 유효 삽입은 정수 0≤i≤n, 유효 삭제는 정수 0≤i<n이다. 삭제는 n=0에서 정의되지 않는다.

학습 목표

  • 정확한 이동 횟수를 계산한다.

  • 이동 방향과 순서 보존의 근거를 설명한다.

  • 맨 끝 연산과 가운데 연산의 복잡도를 구분한다.

줄 가운데 사람을 끼워 넣을 때 맨 앞 번호를 바로 찾는 능력만으로 이동도 없어질까?

번호로 위치를 찾는 것과 순서를 보존하며 빈칸을 만드는 것은 별개의 작업이다. 삽입은 i부터 뒤 항목들을 오른쪽으로, 삭제는 그 뒤 항목들을 왼쪽으로 움직인다. 원래 값을 덮어쓰기 전에 읽어야 하므로 이동 방향도 정확성의 일부다.

이번 정확 비용은 항목 칸에 쓴 횟수만 센다. 삽입은 이동 n−i회와 새 쓰기 1회, 삭제는 이동 n−i−1회와 마지막 칸 정리 1회다. 배열 확장이 끼면 복사 비용을 별도로 더한다. 순서를 버리고 마지막 항목을 빈 자리로 가져오는 삭제는 더 싸지만 같은 목록 계약이 아니다.

먼저 확인할 개념
  • 인터페이스와 표현 불변식

    순서 보존이 숫자 불변식과 별도로 요구되는 명세임을 확인한다.

  • 시간·공간 복잡도

    인덱스 접근과 여러 칸 쓰기의 비용을 서로 다른 연산으로 센다.

한 칸의 틈 만들기

용량 C≥n+1이고 할당이 필요 없는 상태에서 insert(i,v)를 생각한다. j=n,n−1,…,i+1 순서로 A[j]=A[j−1]을 실행한 뒤 A[i]=v, n=n+1로 바꾼다. 이동은 n−i회이고 새 쓰기는 1회다. i=n이면 이동 범위가 비어 맨 뒤 쓰기만 한다.

이전 원소 A[j−1]을 읽기 전에 덮지 않으려면 큰 인덱스부터 옮겨야 한다. [10,20,30]에서 i=0을 작은 번호부터 오른쪽으로 복사하면 10이 다음 칸을 덮고 그 10이 또 복사된다. 값이 사라지는 이 반례가 방향 선택의 이유다.

한 칸의 빈자리 닫기

delete(i)는 먼저 반환할 A[i]를 보존하고 j=i,…,n−2 순서로 A[j]=A[j+1]을 실행한다. 이동은 n−i−1회다. n을 1 줄인 다음 이전 마지막 슬롯을 비우는 참조 해제 쓰기를 모형에서 한 번 추가한다. 삭제 반환값과 남은 순서를 함께 계약에 포함한다.

이번에는 작은 번호부터 왼쪽으로 옮기므로 아직 읽지 않은 뒤 원소를 덮지 않는다. 빈 슬롯의 참조를 지우면 더 이상 배열이 그 객체를 붙잡지 않게 할 수 있지만 외부 참조가 있다면 객체 자체가 곧바로 소멸한다는 뜻은 아니다. 값 타입의 실제 파괴·이동 비용은 언어와 타입 계약에 따라 추가된다.

정확한 횟수에서 복잡도로

n=4인 [10,20,30,40]에 i=1로 99를 삽입하면 이동 3회와 새 쓰기 1회다. 결과 [10,99,20,30,40]에서 i=2를 삭제하면 20을 반환하고 이동 2회 및 마지막 비우기 1회를 한다. 두 연산은 순서대로 실행한다. 각 연산 직전 길이를 쓰므로 삽입에는 n=4, 그 뒤 삭제에는 n=5를 넣는다.

공간이 충분한 맨 뒤 삽입과 삭제는 이동이 없지만, 가운데의 최악 이동은 Θ(n)이다. 삽입에 확장이 필요하면 기존 n개 재할당 복사도 더해진다. 맨 뒤 append의 상환 O(1)이 모든 위치 insert의 상환 O(1)을 뜻하지 않는다. 출력 순서를 포기하고 마지막 원소로 빈자리를 메우는 인터페이스는 다른 문제다.

오른쪽 이동 방향을 거꾸로 하면

같은 입력을 작은 번호부터 A[2]=A[1], A[3]=A[2]로 옮긴 다음 X를 넣는다.

  1. 첫 쓰기로 배열은 [A,B,B,빈칸]처럼 되며 C를 잃는다.

  2. 다음 쓰기는 이미 바뀐 A[2]의 B를 읽는다.

같은 이동 수라도 순서가 틀리면 결과가 틀리는 반례다. 비용 계산만으로 정확성을 판정하지 않는다.

  1. 순서 보존은 C,D를 왼쪽으로 2회 쓰고 마지막 칸을 정리해 [A,C,D]다.

  2. 대체 방식은 D를 번호 1에 1회 쓰고 마지막 칸을 정리해 [A,D,C]다.

  3. 삭제된 값 B는 같지만 나머지 순서가 다르다.

정한 칸 쓰기는 3 대 2다. 순서가 필요한 목록에는 대체 방식이 올바른 최적화가 아니다.

연습 2 · 오류 찾아 고치기

왼쪽 이동 삭제를 큰 번호부터 A[j]=A[j+1]로 수행한다. [A,B,C,D]에서 번호 0을 삭제하면 왜 잘못되는가?

힌트 1

j=2부터 쓰면 A[2]가 어떤 값이 되는가?

힌트 2

그 뒤 j=1이 읽는 A[2]는 원래 값인가?

풀이와 답 확인

  1. j=2에서 C 자리에 D를 쓴다.

  2. j=1은 변경된 D를 읽고, j=0도 D를 읽는다.

  3. 정리 뒤 [D,D,D]가 되므로 작은 번호부터 옮겨야 한다.

순서 보존 삭제의 왼쪽 이동은 작은 번호부터 진행한다.

원본과 목적지의 상대 방향이 바뀐다. 아직 읽지 않은 값을 어느 쓰기가 덮는지 표시해 복구하자.

연습 3 · 직접 만들어 보기

빈 배열 n=0, C=1에서 insert와 delete의 허용 번호 계약을 만들고 insert(0,Z) 후 delete(0)을 손으로 추적하라.

힌트 1

삽입은 끝 경계 n을 허용한다.

힌트 2

삭제는 이미 있는 항목만 허용한다.

풀이와 답 확인

  1. 삽입 조건은 0≤i≤n, 삭제 조건은 0≤i<n이다.

  2. 빈 상태에서는 삽입 0만 가능하고 삭제는 모두 실패한다.

  3. 삽입으로 [Z], n=1; 삭제는 Z를 반환하고 마지막 칸을 정리해 빈 목록이 된다.

두 조건의 등호가 다르며 실패는 상태를 유지한다.

흔한 오답에서 다시 생각하기

두 연산 모두 0≤i≤n이면 된다.

삭제에서 i=n은 항목이 없는 끝 경계다. 빈 상태에 대입하면 바로 반례가 된다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

n=C=4인 목록 앞에 X를 삽입한다. 두 배 확장과 순서 보존 이동을 따로 수행하는 단순 구현의 칸 쓰기는 얼마인가? 새 배열에 바로 최종 위치로 복사하는 대안을 설명하라.

힌트 1

확장 복사와 삽입 이동을 두 목록으로 세자.

힌트 2

한 번의 새 배열 작성에서 이전 항목의 목적지를 i+1로 정할 수 있다.

풀이와 답 확인

  1. 단순 구현은 확장 복사 4+오른쪽 이동 4+새 쓰기 1=9다.

  2. 대안은 새 배열의 번호 0에 X, 이전 네 항목을 번호 1부터 4에 바로 쓴다.

  3. 대안의 칸 쓰기는 5지만 새 저장 확보 실패와 원래 상태 보존 계약은 그대로 필요하다.

9 대 5다. 이 대안은 순서를 보존하면서 중복 복사를 피한다. 개별 작업은 여전히 n에 선형이다.

흔한 오답에서 다시 생각하기

5회로 줄었으므로 앞 삽입도 O(1)이다.

5는 n=4에서 나온 값이며 일반식은 n+1이다. 상수 계수 개선과 증가율 변화를 구별하자.

내 말로 설명하기

이동 방향은 비용 문제뿐인가?

설명 기준 확인

아니다. 겹치는 칸에서 원래 값을 보존하는 정확성 조건이다.

끝 삽입의 분할상환 결과를 가운데 삽입에도 적용할 수 있는가?

설명 기준 확인

순서 보존 이동이 추가되므로 그대로 적용할 수 없다.

한 단계 더

삽입의 반복 불변식을 원 배열 O로 증명하자. j번째 쓰기 직전에 k>j의 옮긴 슬롯은 O[k−1]이고, i≤k<j의 원 슬롯은 아직 O[k]다. A[j]=A[j−1]은 살아 있는 원 값을 복사하며 조건을 다음 j−1에 유지한다. 종료 후 i+1,…,n은 각각 O[i],…,O[n−1]이므로 v를 쓰면 순서 계약이 성립한다. 삭제는 이미 처리한 i,…,j−1이 O[i+1],…,O[j]이고 뒤 원 슬롯은 살아 있다는 대칭 불변식으로 증명한다. 무순서 delete가 마지막 원소를 i에 쓰면 이동 한 번이지만 [a,b,c]의 첫 삭제 결과 [c,b]는 순서 보존 결과 [b,c]와 달라 동일 인터페이스의 최적화가 아니다.

다른 문제에 적용하기

순서를 보존하는 기록 목록은 [a,b,c], n=3, C=4로 시작한다. 한 칸은 4바이트다. insert(1,X), append(Y), delete(0), get(4)를 차례로 수행한다. 확장은 두 배이며 새 배열에 기존 목록을 먼저 복사하는 단순 구현이다. 항목 이동·복사·새 쓰기·삭제 마지막 칸 정리만 비용 1로 센다. 각 결과, 전체 비용, 완료 사용/예약 공간과 최고 동시 배열 공간, 실패한 읽기를 보고하라. 할당·해제·길이 변경 비용은 제외한다.

힌트 1

매 호출 앞의 n과 C를 갱신하고, 논리 get의 범위를 용량과 구별하자.

힌트 2

두 번째 호출만 꽉 찬 용량 4를 확장한다. 삭제 직전 길이는 5다.

풀이와 답 확인

  1. insert(1,X)는 b,c 두 항목 이동과 X 쓰기로 3회다. 결과 [a,X,b,c], n=4,C=4다.

  2. append(Y)는 기존 네 항목 복사와 Y 쓰기로 5회다. 결과 [a,X,b,c,Y], n=5,C=8이고 기존 4+새 8=12칸이 한때 함께 살아 있다.

  3. delete(0)은 a를 반환하고 네 항목 이동과 마지막 정리로 5회다. 결과 [X,b,c,Y], n=4,C=8이다.

  4. get(4)는 4<4가 거짓이므로 실패하고 상태를 유지한다. 예약 칸이 8개라는 사실은 읽기 허용 근거가 아니다.

  5. 총 3+5+5=13회다. 완료 사용 4×4=16바이트, 예약 8×4=32바이트, 최고 동시 배열 저장 12×4=48바이트다.

최종 [X,b,c,Y], 읽기 실패, 총 칸 쓰기 13, 사용/예약/최고 동시 배열 공간 16/32/48바이트다. 메타데이터와 외부 객체 공간은 이 모형에 포함하지 않는다.
