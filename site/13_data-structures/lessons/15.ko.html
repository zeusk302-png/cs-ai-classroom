소단원 15.1

불변식 검사와 무작위 테스트

원소 개수가 맞으면 스택의 내부 상태도 반드시 정상일까?

준비 개념과 학습 목표

준비 개념

  • 스택의 마지막 삽입/삭제

  • 배열의 인덱스

  • 참과 거짓 조건

학습 목표

  • 표현 불변식과 외부 동작 계약을 나눈다.

  • 연산 전후 상태와 기준 모델을 비교한다.

  • 무작위 테스트의 재현 정보와 한계를 설명한다.

같은 값만 넣는 테스트가 FIFO와 LIFO의 차이를 발견할까?

새 시험은 용량 2인 제한된 스택이다. push가 가득 찼으면 실패하고 상태를 보존한다. 올바른 pop은 마지막 값을 제거하지만 결함 F는 첫 값을 제거한다. 둘 다 원소 수의 범위와 정수 목록 표현은 유지한다. 따라서 표현 검사만 통과하는 구현도 외부 순서 계약을 위반할 수 있다.

초기 빈 상태에서 push(6), push(6), pop만 검사하면 정상 구현과 F 모두 6을 반환하고 [6]을 남긴다. 같은 값을 사용하는 입력이 관찰 차이를 숨긴 것이다. push(6), push(9), pop에서는 정상 반환 9와 남은 [6], F의 반환 6과 남은 [9]로 갈린다. 반환값·순서 있는 전체 내용·오류·상태 보존을 각각 관찰해야 한다.

또 다른 결함 G는 가득 찬 push가 실패한다고 반환하면서 마지막 값을 새 값으로 덮는다. [6,9]에서 push(4)는 둘 다 실패하지만 정상은 [6,9], G는 [6,4]다. 같은 오류 코드와 같은 크기가 내용 보존을 보장하지 않는다. 아래 시험은 손으로 만든 고정 연산열이며 무작위 생성기·실제 구현·메모리 안전 검사·학생 시험을 실행한 것이 아니다.

먼저 확인할 개념
  • 불변식과 기준 모델

    숫자 범위와 공개 연산의 추상 결과를 함께 검사한다.

  • 추상화 함수와 실패 보존

    같은 표현 크기가 같은 추상 목록이나 실패 상태를 보장하는지 구별한다.

어떤 내부 상태를 허용하는가

자체 정수 스택을 배열 a, 원소 수 n, 용량 c로 표현하자. 불변식은 0≤n≤c이고 c>0이면 c개 정수를 저장할 유효한 공간이 있다는 조건이다. 실제 원소는 a[0]부터 a[n−1]까지이며 그 뒤 공간의 값은 스택 내용이 아니다.

외부 계약은 push(x)가 끝에 x를 붙이고 pop이 마지막 원소를 제거해 돌려준다는 것이다. 빈 스택의 pop은 오류 상태를 반환하고 스택을 보존한다고 정한다. 메모리 할당 실패도 오류 반환과 기존 상태 보존으로 정의한다. 내부 공간이 정상이어도 잘못된 위치의 값을 반환하면 외부 계약은 실패한다.

검사는 불변식과 관찰 결과를 함께 본다

repOK는 표현 불변식을 검사하는 내부 함수라는 관례다. 생성 시와 공개 연산 전후를 검사하고 위반한 첫 상태를 기록한다. 검사 자체가 저장 공간의 모든 안전성을 자동 증명하거나 모든 입력을 검증하는 것은 아니다.

기준 모델을 종이에 적은 값 목록으로 두고 동일한 연산을 적용한다. 매 단계의 반환값과 전체 내용·크기를 비교한다. 끝 삭제 대신 첫 원소를 돌려주는 결함은 n≤c 검사만으로 발견되지 않지만 기준 목록과 반환값 비교로 발견된다.

무작위 입력에도 재현 가능한 기록이 필요하다

무작위 테스트는 다양한 값과 연산 순서를 만들어 탐색을 넓힌다. 생성기·초기 상태·시드라는 생성 시작 값·전체 연산열·실패 단계를 기록한다. 같은 시드도 생성기나 호출 순서가 바뀌면 같은 입력을 보장하지 않으므로 실패 연산열 자체를 보존한다.

빈 스택·정확히 가득 찬 상태·용량 경계·할당 실패는 의도한 테스트에도 넣는다. 무작위 입력이 우연히 중요한 경계를 피할 수 있기 때문이다. 통과 횟수를 모든 프로그램 상태의 정확성 증명으로 바꾸지 않는다. 이번 활동은 주어진 연산열의 종이 추적이며 무작위 생성기를 실행하지 않는다.

같은 값만 넣는 테스트가 FIFO와 LIFO의 차이를 발견할까?
초기 목록/연산정상 관찰결함 관찰검사 결론

[]; push 6, push 6, pop

반환 6, [6]

F: 반환 6, [6]

차이 은폐

[]; push 6, push 9, pop

반환 9, [6]

F: 반환 6, [9]

순서 결함 발견

[6,9]; push 4

실패, [6,9]

G: 실패, [6,4]

실패 후 내용 차이

모든 행에서 원소 수는 0부터 2까지의 범위를 지킬 수 있다. 통과/실패는 명시한 관찰에 한정하며 실제 프로그램의 전체 정확성을 증명하지 않는다.

중간 과정을 따라가는 예제

초기 n=0,c=2인 스택에 push(4), push(7), pop, push(9), pop, pop, pop을 적용하라. pop 실패는 상태를 보존한다. 각 반환값과 마지막 상태를 구하라.

  1. 두 삽입 뒤 내용 [4,7], n=2이다. 첫 pop은 7을 반환하고 [4]가 된다.

  2. push(9) 뒤 [4,9]다. 다음 pop은 9, 다음 pop은 4를 반환하여 빈 상태가 된다.

  3. 마지막 pop은 빈 스택 오류이며 []와 n=0,c=2를 보존한다. 매 단계 0≤n≤2가 성립한다.

pop 결과는 7,9,4,빈 스택 오류이며 마지막 내용은 []다. 원소 수 조건뿐 아니라 반환 순서도 확인했다.

조건을 바꾸어 비교하기

중복 값이 숨기는 결함

F에 push(6), push(6), pop을 준 통과 기록으로 F가 정확하다고 결론 낼 수 있는가?

  1. 정상과 F의 반환값 및 남은 목록은 모두 동일하다.

  2. 서로 다른 두 값 6과 9로 교체하면 첫 값 제거와 마지막 값 제거가 다르게 관찰된다.

한 입력에서 차이를 찾지 못했다는 기록만 가능하다. 서로 다른 값의 반례는 순서 오류를 드러낸다.

비교할 점

크기 조건이나 단일 통과와 외부 계약 전체를 구별한다.

실패 반환 뒤 상태 훼손

G의 실패 push 뒤 정상과 같은 오류 코드 및 n=2만 비교했다. 추가 검사를 구성하라.

  1. 연산 전 목록 [6,9]를 기준 모델에 보존한다.

  2. 연산 후 전체 내용 [6,4]를 비교하여 값 9의 손실을 찾는다.

실패 보존 검사에서 G를 거절한다. 다음 정상 pop의 기대값은 여전히 9다.

비교할 점

반환 코드 검사와 상태 보존 검사는 독립적으로 필요하다.

연습 1 · 값과 상태 예측

초기 빈 상태에서 push(6), push(9), pop, pop을 정상과 F에 각각 적용하면 두 반환열과 마지막 목록은?

힌트 1

첫 pop의 서로 다른 제거 위치를 쓴다.

힌트 2

마지막 빈 목록만으로 중간 반환 차이를 복구할 수 없다.

풀이와 답 확인

  1. 정상은 9와 6을 차례로 반환한다.

  2. F는 6과 9를 차례로 반환하고 둘 다 빈 목록이 된다.

정상 반환열은 [9,6], F는 [6,9], 최종 내용은 둘 다 []다.

최종 목록이 같으므로 동일한 스택 구현이다.

순서 있는 반환 이력도 계약의 관찰 결과다.

평균은 더 빠른데 중앙값은 더 느린 가상 결과를 어떻게 보고할까?

동일 과업을 다섯 번 수행한 설명용 시간표를 A=[2,2,2,2,22] ms, B=[5,5,5,5,5] ms로 정한다. 실측값이 아니다. A의 평균은 6 ms, 중앙값은 2 ms이고 B는 둘 다 5 ms다. 중앙값 기준 A가 짧지만 평균 기준 B가 짧다. 사용한 대표값과 모든 반복값을 공개해야 무엇을 비교했는지 알 수 있다.

과업 전체와 핵심 연산만의 범위도 나눈다. A의 준비가 8 ms, 처리 단가가 항목당 1 ms이며 B의 준비가 1 ms, 단가가 2 ms인 새 결정 모형에서 항목 q개 총시간은 A=8+q, B=1+2q다. 처리만 보면 A가 항상 짧지만 총시간은 q<7에서 B가 짧고 q>7에서 A가 짧다. 실제 컴파일러·캐시·장치·동시성의 측정 법칙이 아니라 범위를 드러내는 자체 선형 모형이다.

메모리에서는 사용·예약·이동 중 공존·누적 요청을 별도 지표로 정한다. 원소당 가상 8바이트, n=4에서 용량 4→8→16으로 두 번 별도 할당하고 복사 뒤 이전 배열을 해제한다고 하자. 사용량은 32바이트, 최종 예약량 128바이트, 최고 공존량 192바이트, 세 배열의 누적 요청량 224바이트다. 누적 요청량을 현재 메모리라고 보고하면 수명 정보를 잃는다. 도구를 등록하거나 최적화 방지 보조 함수를 쓰는 것만으로 실측 정확성·모든 최적화 차단이 자동 증명되는 것도 아니다.

무엇을 메모리로 세는지 먼저 정한다

동적 배열의 size는 현재 원소 수이고 capacity는 재할당 없이 담을 수 있는 용량이다. 가상으로 정수 한 개를 4바이트로 정하면 n개 사용 원소의 저장량은 4n, c개 예약 공간은 4c바이트다. 실제 C의 sizeof(int)는 해당 환경에서 확인해야 하며 이 가정을 보편 규칙으로 쓰지 않는다.

관리 구조체·정렬·할당기 메타데이터·다른 객체를 제외한 배열 공간 계산과 전체 프로세스 메모리는 다른 지표다. 확장 중 이전/새 배열이 동시에 존재하는 자체 구현이면 순간 최대 공간도 따로 계산한다. 마지막 상태만 재서 최대 공간을 확정하지 않는다.

이론적 비용과 실제 시간을 나눈다

같은 결과를 만드는 동일 입력과 연산열로 구현을 비교한다. 컴파일러·최적화·장치·라이브러리 버전·할당 포함 여부를 기록하고 초기화 시간과 본 과업 시간을 나눈다. 반복 실행의 각 값과 대표값도 보고한다.

결과를 사용하지 않는 연산은 컴파일러가 줄이거나 없앨 수 있어 의도한 작업을 측정하는지 살펴야 한다. 준비 실행과 캐시 상태도 비교 조건이다. 도구 옵션만 설정했다고 모든 최적화가 막혔다고 결론 내리지 않는다. 측정 전 정확성 검사도 통과해야 한다.

비율에는 같은 분모와 측정 범위가 필요하다

같은 1,000개 연산의 시간을 비교할 때 전체 시간을 연산 수로 나눠 평균 단가를 계산할 수 있다. 일부 실행만 골라 가장 좋은 결과로 보고하면 반복 변동이 숨는다.

메모리도 배열 예약량·할당 횟수·최대 살아 있는 바이트 등 지표를 명시한다. 측정 도구가 실제 수집하지 않은 값은 빈칸 또는 미측정으로 남긴다. 아래 값은 설명을 위해 만든 가상 자료이며 장치나 라이브러리의 성능 결과가 아니다.

시점과 누적을 구별한다

시간 표와 배열 표는 서로 독립적인 가상 사례다. 속도비의 분모에 선택한 대표값을 명시하고 미측정 필드는 미측정으로 남긴다.

중간 과정을 따라가는 예제

가상 4바이트 정수 배열의 n=5,c=8이다. 별도 새 배열을 만들어 복사하는 자체 구현이 c=16으로 확장할 때 이전 배열은 복사 후 해제된다. 배열 공간만의 사용/예약/순간 최대 바이트를 구하라.

  1. 사용 원소 공간은 5×4=20바이트, 기존 예약 공간은 8×4=32바이트다.

  2. 새 예약 공간은 16×4=64바이트다. 복사 중 두 배열이 함께 살아 있으면 32+64=96바이트다.

  3. 이전 배열 해제 후 예약량은 64바이트다. 관리 정보와 프로세스 전체 공간은 이 계산에서 제외한다.

사용 20, 기존 예약 32, 확장 중 최대 96, 확장 후 예약 64바이트다. 실제 realloc 내부의 순간 메모리를 이 모델로 확정하지 않는다.

조건을 바꾸어 비교하기

같은 반복 자료의 두 순위

A/B의 평균 및 중앙값으로 A시간/B시간을 각각 구하라.

  1. 평균 비율은 6/5=1.2다.

  2. 중앙값 비율은 2/5=0.4다.

평균에서는 A 시간이 20% 길고 중앙값에서는 60% 짧다. 실제 구현의 보편 우열은 아니다.

비교할 점

다른 대표값의 분자·분모를 섞어 속도비로 쓰지 않는다.

같은 사용량의 여러 메모리 수치

세 배열의 32/64/128바이트 요청과 수명에서 최댓값을 구하라.

  1. 첫 교체 동안 32+64=96바이트, 두 번째 동안 64+128=192바이트다.

  2. 해제 뒤 최종 128바이트이며 누적 요청은 32+64+128=224바이트다.

피크 192바이트와 누적 224바이트는 다르다. 관리 정보·다른 객체·실제 allocator 내부는 제외했다.

마지막 상태만으로 피크를 확정할 수 없다.

재할당이 없으면 모든 vector 참조도 계속 유효할까?

이번 새 비교는 std::vector<int>의 [10,20,30,40], size=4, capacity=8에서 시작한다. 세 참조를 r0=첫 원소, r2=인덱스 2의 원소, old_end=기존 끝 반복자로 둔다. 인덱스 1에 15를 삽입하면 용량이 충분하여 재할당은 없지만 삽입 위치 이상을 가리키던 r2와 old_end는 무효화된다. 삽입 이전 위치의 r0는 유효하다. 주소가 이동하지 않는다는 조건과 각 연산의 참조 규약은 다르다.

동일한 가상 초기 상태에서 reserve(7)만 수행하면 현재 용량 8을 넘지 않아 재할당하지 않고 size·내용·기존 원소 참조가 유지된다. 그러나 reserve(9)가 성공하면 현재 용량을 넘어서 재할당하며 모든 이전 원소 참조와 끝 반복자가 무효화된다. 새 용량은 9 이상이고 정확히 9라고 보장하지 않는다. 무효 참조를 실제로 역참조해 보는 실험은 수행하지 않는다.

관리 책임을 비교할 때 직접 정수 배열은 인덱스와 이동 방향·실패 보존을 명시해야 한다. vector의 공개 연산도 삽입 위치에 따른 무효화 조건을 지켜야 한다. 값 30이라는 항목의 논리 식별자를 보존하려면 삽입 이후 다시 찾는 등 별도 정책을 둔다. 이전 인덱스 2를 기억하는 것만으로는 값 30을 계속 가리키지 않는다. 정수 원소의 이 사례를 모든 C++ 타입의 예외·생성·파괴 계약으로 확대하지 않는다.

직접 C 구현에서는 실패와 소유권도 계약이다

자체 정수 배열은 포인터·크기·용량을 함께 관리하고 마지막 해제 책임을 정한다. 양의 크기로 realloc을 호출할 때 실패하면 기존 객체는 유지되므로 반환값을 임시 포인터로 확인한 뒤 성공 시 저장 포인터를 갱신한다. 직접 원래 포인터에 실패 반환 NULL을 덮어쓰면 기존 공간의 주소를 잃을 수 있다.

새 바이트를 요청할 때 용량 곱셈이 표현 범위를 넘지 않는지도 확인한다. 성공한 재할당 뒤 기존 원소 포인터를 계속 사용하지 않고 새 포인터와 인덱스로 접근한다. 확장된 부분은 이전 내용처럼 초기화되어 있다고 가정하지 않는다. 여기서는 0바이트 요청과 임의 객체의 생성/파괴를 제외하고 정수 배열만 논의한다.

vector는 저장 관리를 제공하지만 계약을 읽어야 한다

std::vector<int>는 원소를 연속 저장하고 저장 관리를 제공하는 C++ 컨테이너다. size는 원소 수, capacity는 재할당 없이 담는 용량이다. reserve(k)는 여유 공간을 요청하며 원소 수를 k로 만드는 연산이 아니다.

reserve가 현재 용량보다 큰 요청으로 재할당하면 이후 용량은 요청 이상이며 꼭 요청값과 같을 필요는 없다. 재할당은 기존 참조·포인터·반복자를 무효화한다. 특정 성장률이나 항상 같은 주소를 보장한다고 생각하지 않는다. 이 설명의 근거는 열람한 표준 초안이며 특정 구현을 실행한 결과는 아니다.

비교는 관리 책임과 연산 종류를 함께 본다

vector의 끝 삽입은 분할 상환 관점에서 상수 비용이지만 확장이 일어나는 한 번의 삽입은 원소 이동이 필요할 수 있다. 중간 삽입은 선형 비용이다. 직접 C 배열도 선택한 성장 정책과 이동·실패 처리에 따라 비용이 달라진다.

직접 구현은 원리와 제한된 계약을 배우는 데 유용하지만 오류 처리·테스트·관리 작업을 사용자가 맡는다. 표준 컨테이너도 잘못된 인덱스나 무효화된 참조 사용을 자동으로 모두 해결하지 않는다. C가 항상 빠르다거나 C++가 항상 느리다는 결론 대신 동일 과업의 정확성·공간·측정 범위를 비교한다.

중간 과정을 따라가는 예제

가상 vector<int>의 size=3,capacity=4이며 값은 [2,5,8]이다. reserve(6)이 성공하고 구현이 새 capacity=8을 선택했다고 가정한다. size와 내용·기존 원소 참조의 상태를 구하라.

  1. 현재 용량 4보다 요청 6이 크므로 재할당한다. 가상 구현이 고른 8은 요청 이상 조건을 만족한다.

  2. reserve는 size를 바꾸지 않으므로 size=3이며 내용 [2,5,8]이 보존된다.

  3. 재할당이 있었으므로 이전 원소의 참조·포인터·반복자는 무효화된다. 새 접근으로 다시 얻어야 한다.

size=3,capacity=8,내용 [2,5,8]이며 기존 참조는 무효다. 모든 구현이 8을 고른다고 보장하지 않는다.

삽입 대신 용량 요청

reserve(7)과 성공한 reserve(9)의 기존 참조 규약을 비교하라.

  1. 7은 현재 용량 8 이하이므로 재할당이 없다.

  2. 9는 8보다 커서 재할당하며 원소 수는 여전히 4다.

비교할 점

현재 용량을 넘는 요청과 요청한 원소 수를 혼동하지 않는다.

한 단계 더

직접 배열과 vector에 같은 정수 연산열을 주는 비교 계획을 쓰라. 실패 처리·포인터 수명·확장 정책·원소 이동·검사 비용을 함께 기록한다. 직접 C 구현의 정수 저장 계약을 모든 C++ 타입의 생성·파괴·예외 계약으로 확대하지 않는다.

용량 2의 빈 스택에 push(6), push(9), push(4), pop, pop을 적용하여 정상 기대 관찰을 적고 결함 F/G를 구별하는 첫 검사를 정하라. 가상 시간 A=[2,2,2,2,22], B=[5,5,5,5,5] ms의 평균/중앙값과 두 비율을 계산하라. 가상 8바이트 배열의 용량 4→8→16 교체에서 사용 n=4·최종 예약·최대 공존·누적 요청량을 구하라. size=4, capacity=8인 [10,20,30,40]의 위치 1에 15를 넣은 뒤 이전 첫 원소 참조·인덱스 2 참조·끝 반복자의 유효성을 구별하라.

힌트 1

실패 반환의 내용 보존과 뒤 pop의 순서를 따로 비교한다. 시간은 같은 요약 규칙끼리 나눈다.

힌트 2

배열의 공존은 두 교체 시점을 따로 센다. 참조 규약은 재할당 여부와 삽입 위치를 함께 사용한다.

풀이와 답 확인

  1. 정상 세 번째 push는 실패하며 [6,9]를 유지하고 뒤 pop은 9와 6을 반환한다. G는 실패 직후 내용, F는 첫 pop의 반환과 목록에서 갈린다.

  2. 평균은 A가 6 ms, B가 5 ms여서 비율 6/5다. 중앙값은 2 ms와 5 ms여서 비율 2/5다.

  3. 사용은 32바이트, 최종 예약은 128바이트, 두 공존값 96/192 중 최대는 192바이트, 누적 요청은 224바이트다.

  4. 삽입 뒤 [10,15,20,30,40]이며 재할당은 없다. 이전 첫 참조는 유효하지만 이전 인덱스 2 참조와 끝 반복자는 무효다.

정상 반환열 [9,6]·실패 후 보존 목록 [6,9], 시간 평균 비율 1.2와 중앙값 비율 0.4, 배열의 사용/예약/피크/누적 32/128/192/224바이트를 각각 보고한다. 이전 첫 참조만 유효하고 나머지 두 핸들은 다시 얻는다. 실제 실행·측정·학생 실험은 수행하지 않았다.

해결한 뒤 점검할 것

  • 오류 코드만으로 G를 통과시키지 않고 중간 반환까지 비교한다.

  • 시간 대표값과 배열 수명 지표를 이름별로 구별한다.

  • 재할당 없는 중간 삽입의 위치 기반 무효화와 새 접근을 설명한다.
