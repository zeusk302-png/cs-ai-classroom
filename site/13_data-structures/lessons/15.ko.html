소단원 15.1

불변식 검사와 무작위 테스트

원소 개수가 맞으면 스택의 내부 상태도 반드시 정상일까?

준비 개념과 학습 목표

준비 개념

  • 스택의 마지막 삽입/삭제

  • 배열의 인덱스

  • 참과 거짓 조건

학습 목표

  • 표현 불변식과 외부 동작 계약을 나눈다.

  • 연산 전후 상태와 기준 모델을 비교한다.

  • 무작위 테스트의 재현 정보와 한계를 설명한다.

어떤 내부 상태를 허용하는가

자체 정수 스택을 배열 a, 원소 수 n, 용량 c로 표현하자. 불변식은 0≤n≤c이고 c>0이면 c개 정수를 저장할 유효한 공간이 있다는 조건이다. 실제 원소는 a[0]부터 a[n−1]까지이며 그 뒤 공간의 값은 스택 내용이 아니다.

외부 계약은 push(x)가 끝에 x를 붙이고 pop이 마지막 원소를 제거해 돌려준다는 것이다. 빈 스택의 pop은 오류 상태를 반환하고 스택을 보존한다고 정한다. 메모리 할당 실패도 오류 반환과 기존 상태 보존으로 정의한다. 내부 공간이 정상이어도 잘못된 위치의 값을 반환하면 외부 계약은 실패한다.

검사는 불변식과 관찰 결과를 함께 본다

repOK는 표현 불변식을 검사하는 내부 함수라는 관례다. 생성 시와 공개 연산 전후를 검사하고 위반한 첫 상태를 기록한다. 검사 자체가 저장 공간의 모든 안전성을 자동 증명하거나 모든 입력을 검증하는 것은 아니다.

기준 모델을 종이에 적은 값 목록으로 두고 동일한 연산을 적용한다. 매 단계의 반환값과 전체 내용·크기를 비교한다. 끝 삭제 대신 첫 원소를 돌려주는 결함은 n≤c 검사만으로 발견되지 않지만 기준 목록과 반환값 비교로 발견된다.

무작위 입력에도 재현 가능한 기록이 필요하다

무작위 테스트는 다양한 값과 연산 순서를 만들어 탐색을 넓힌다. 생성기·초기 상태·시드라는 생성 시작 값·전체 연산열·실패 단계를 기록한다. 같은 시드도 생성기나 호출 순서가 바뀌면 같은 입력을 보장하지 않으므로 실패 연산열 자체를 보존한다.

빈 스택·정확히 가득 찬 상태·용량 경계·할당 실패는 의도한 테스트에도 넣는다. 무작위 입력이 우연히 중요한 경계를 피할 수 있기 때문이다. 통과 횟수를 모든 프로그램 상태의 정확성 증명으로 바꾸지 않는다. 이번 활동은 주어진 연산열의 종이 추적이며 무작위 생성기를 실행하지 않는다.

중간 과정을 따라가는 예제

초기 n=0,c=2인 스택에 push(4), push(7), pop, push(9), pop, pop, pop을 적용하라. pop 실패는 상태를 보존한다. 각 반환값과 마지막 상태를 구하라.

  1. 두 삽입 뒤 내용 [4,7], n=2이다. 첫 pop은 7을 반환하고 [4]가 된다.

  2. push(9) 뒤 [4,9]다. 다음 pop은 9, 다음 pop은 4를 반환하여 빈 상태가 된다.

  3. 마지막 pop은 빈 스택 오류이며 []와 n=0,c=2를 보존한다. 매 단계 0≤n≤2가 성립한다.

pop 결과는 7,9,4,빈 스택 오류이며 마지막 내용은 []다. 원소 수 조건뿐 아니라 반환 순서도 확인했다.

소단원 15.2

메모리·성능 측정

원소가 5개인데 8개 공간을 잡은 배열은 몇 바이트를 쓴다고 보고해야 할까?

준비 개념과 학습 목표

준비 개념

  • 원소 수와 용량

  • 평균과 중앙값

  • 시간 단위

학습 목표

  • 사용 원소·예약 공간·전체 프로세스 메모리를 구별한다.

  • 가상 비용과 실측 결과를 구별한다.

  • 동일 과업·반복·환경을 갖춘 측정 계획을 작성한다.

무엇을 메모리로 세는지 먼저 정한다

동적 배열의 size는 현재 원소 수이고 capacity는 재할당 없이 담을 수 있는 용량이다. 가상으로 정수 한 개를 4바이트로 정하면 n개 사용 원소의 저장량은 4n, c개 예약 공간은 4c바이트다. 실제 C의 sizeof(int)는 해당 환경에서 확인해야 하며 이 가정을 보편 규칙으로 쓰지 않는다.

관리 구조체·정렬·할당기 메타데이터·다른 객체를 제외한 배열 공간 계산과 전체 프로세스 메모리는 다른 지표다. 확장 중 이전/새 배열이 동시에 존재하는 자체 구현이면 순간 최대 공간도 따로 계산한다. 마지막 상태만 재서 최대 공간을 확정하지 않는다.

이론적 비용과 실제 시간을 나눈다

같은 결과를 만드는 동일 입력과 연산열로 구현을 비교한다. 컴파일러·최적화·장치·라이브러리 버전·할당 포함 여부를 기록하고 초기화 시간과 본 과업 시간을 나눈다. 반복 실행의 각 값과 대표값도 보고한다.

결과를 사용하지 않는 연산은 컴파일러가 줄이거나 없앨 수 있어 의도한 작업을 측정하는지 살펴야 한다. 준비 실행과 캐시 상태도 비교 조건이다. 도구 옵션만 설정했다고 모든 최적화가 막혔다고 결론 내리지 않는다. 측정 전 정확성 검사도 통과해야 한다.

비율에는 같은 분모와 측정 범위가 필요하다

같은 1,000개 연산의 시간을 비교할 때 전체 시간을 연산 수로 나눠 평균 단가를 계산할 수 있다. 일부 실행만 골라 가장 좋은 결과로 보고하면 반복 변동이 숨는다.

메모리도 배열 예약량·할당 횟수·최대 살아 있는 바이트 등 지표를 명시한다. 측정 도구가 실제 수집하지 않은 값은 빈칸 또는 미측정으로 남긴다. 아래 값은 설명을 위해 만든 가상 자료이며 장치나 라이브러리의 성능 결과가 아니다.

중간 과정을 따라가는 예제

가상 4바이트 정수 배열의 n=5,c=8이다. 별도 새 배열을 만들어 복사하는 자체 구현이 c=16으로 확장할 때 이전 배열은 복사 후 해제된다. 배열 공간만의 사용/예약/순간 최대 바이트를 구하라.

  1. 사용 원소 공간은 5×4=20바이트, 기존 예약 공간은 8×4=32바이트다.

  2. 새 예약 공간은 16×4=64바이트다. 복사 중 두 배열이 함께 살아 있으면 32+64=96바이트다.

  3. 이전 배열 해제 후 예약량은 64바이트다. 관리 정보와 프로세스 전체 공간은 이 계산에서 제외한다.

사용 20, 기존 예약 32, 확장 중 최대 96, 확장 후 예약 64바이트다. 실제 realloc 내부의 순간 메모리를 이 모델로 확정하지 않는다.

직접 만든 배열과 std::vector는 같은 일을 해도 관리 책임이 같을까?

직접 C 구현에서는 실패와 소유권도 계약이다

자체 정수 배열은 포인터·크기·용량을 함께 관리하고 마지막 해제 책임을 정한다. 양의 크기로 realloc을 호출할 때 실패하면 기존 객체는 유지되므로 반환값을 임시 포인터로 확인한 뒤 성공 시 저장 포인터를 갱신한다. 직접 원래 포인터에 실패 반환 NULL을 덮어쓰면 기존 공간의 주소를 잃을 수 있다.

새 바이트를 요청할 때 용량 곱셈이 표현 범위를 넘지 않는지도 확인한다. 성공한 재할당 뒤 기존 원소 포인터를 계속 사용하지 않고 새 포인터와 인덱스로 접근한다. 확장된 부분은 이전 내용처럼 초기화되어 있다고 가정하지 않는다. 여기서는 0바이트 요청과 임의 객체의 생성/파괴를 제외하고 정수 배열만 논의한다.

vector는 저장 관리를 제공하지만 계약을 읽어야 한다

std::vector<int>는 원소를 연속 저장하고 저장 관리를 제공하는 C++ 컨테이너다. size는 원소 수, capacity는 재할당 없이 담는 용량이다. reserve(k)는 여유 공간을 요청하며 원소 수를 k로 만드는 연산이 아니다.

reserve가 현재 용량보다 큰 요청으로 재할당하면 이후 용량은 요청 이상이며 꼭 요청값과 같을 필요는 없다. 재할당은 기존 참조·포인터·반복자를 무효화한다. 특정 성장률이나 항상 같은 주소를 보장한다고 생각하지 않는다. 이 설명의 근거는 열람한 표준 초안이며 특정 구현을 실행한 결과는 아니다.

비교는 관리 책임과 연산 종류를 함께 본다

vector의 끝 삽입은 분할 상환 관점에서 상수 비용이지만 확장이 일어나는 한 번의 삽입은 원소 이동이 필요할 수 있다. 중간 삽입은 선형 비용이다. 직접 C 배열도 선택한 성장 정책과 이동·실패 처리에 따라 비용이 달라진다.

직접 구현은 원리와 제한된 계약을 배우는 데 유용하지만 오류 처리·테스트·관리 작업을 사용자가 맡는다. 표준 컨테이너도 잘못된 인덱스나 무효화된 참조 사용을 자동으로 모두 해결하지 않는다. C가 항상 빠르다거나 C++가 항상 느리다는 결론 대신 동일 과업의 정확성·공간·측정 범위를 비교한다.

중간 과정을 따라가는 예제

가상 vector<int>의 size=3,capacity=4이며 값은 [2,5,8]이다. reserve(6)이 성공하고 구현이 새 capacity=8을 선택했다고 가정한다. size와 내용·기존 원소 참조의 상태를 구하라.

  1. 현재 용량 4보다 요청 6이 크므로 재할당한다. 가상 구현이 고른 8은 요청 이상 조건을 만족한다.

  2. reserve는 size를 바꾸지 않으므로 size=3이며 내용 [2,5,8]이 보존된다.

  3. 재할당이 있었으므로 이전 원소의 참조·포인터·반복자는 무효화된다. 새 접근으로 다시 얻어야 한다.

size=3,capacity=8,내용 [2,5,8]이며 기존 참조는 무효다. 모든 구현이 8을 고른다고 보장하지 않는다.

한 단계 더

직접 배열과 vector에 같은 정수 연산열을 주는 비교 계획을 쓰라. 실패 처리·포인터 수명·확장 정책·원소 이동·검사 비용을 함께 기록한다. 직접 C 구현의 정수 저장 계약을 모든 C++ 타입의 생성·파괴·예외 계약으로 확대하지 않는다.
