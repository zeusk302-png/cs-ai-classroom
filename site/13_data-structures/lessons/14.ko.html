분리집합과 경로압축

같은 모둠인지 자주 묻는다면 모둠의 모든 학생을 매번 나열해야 할까?

준비 개념과 학습 목표

준비 개념

  • 트리와 부모 배열

  • 동치 관계

  • 시간 복잡도

학습 목표

  • 분리집합의 find와 union을 설명한다.

  • 크기 기반 합치기와 경로압축을 추적한다.

  • 분할·원소 삭제 및 경로 찾기의 제한을 구별한다.

집합 대표자가 바뀌면 업무에서 쓰는 가장 작은 번호도 바뀌어야 할까?

새 원소는 0부터 5까지다. 크기 기반 합치기에서 같은 크기일 때만 작은 루트를 남기고, 합치기 동안 경로압축은 하지 않는다고 정한다. union(0,1), union(2,3), union(4,5), union(2,4), union(0,2)를 차례로 적용한다. 마지막에는 크기 2인 루트 0이 크기 4인 루트 2 아래로 들어가므로 대표자는 2다. 가장 작은 원소는 여전히 0이다. 같은 크기의 번호 규칙이 모든 합치기에서 작은 번호를 대표자로 만든다는 뜻은 아니다.

업무의 집합 이름이 가장 작은 원소여야 한다면 루트와 별도의 min 정보를 유지할 수 있다. 초기 min[i]=i이고 서로 다른 두 루트를 합칠 때 새 루트의 min은 두 기존 min의 작은 값이다. 최종 루트 2의 size는 6, min은 0이다. 비루트에 남은 size와 min은 현재 집합의 결과로 사용하지 않으며 항상 find가 반환한 루트의 정보를 읽는다.

이 숲은 집합 관계만 나타내고 입력 그래프의 모든 간선을 기록하지 않는다. 같은 다섯 union 간선을 가진 그래프 A와 여기에 (1,5)를 더한 그래프 B는 같은 분할과 같은 부모 배열이 될 수 있다. 이미 같은 집합인 마지막 간선은 union에서 집합 수를 바꾸지 않기 때문이다. 그런데 (0,2)를 삭제하면 A는 두 성분이 되고 B는 (1,5)를 통해 연결을 유지한다. 하나의 부모 배열만으로 삭제 이후 두 답을 구별할 수 없다. 실제 그래프 프로그램이나 메모리 접근 시간은 실행·측정하지 않았다.

겹치지 않는 집합을 대표자로 묻는다

분리집합은 각 원소가 정확히 한 집합에 속하는 분할을 유지한다. 처음에는 각 원소 혼자 집합을 이루고 union은 두 집합을 합친다. find는 원소가 속한 집합의 대표자를 돌려준다. 두 원소의 대표자가 같으면 같은 집합이다.

대표자는 집합의 이름처럼 쓰지만 가장 작은 원소여야 하는 것은 아니다. 구현과 합치기 규칙에 따라 달라질 수 있다. parent 배열에서 루트는 자기 자신을 부모로 갖는다. 루트에 도달할 때까지 부모를 따라가며, 루트를 합칠 때 숲 구조와 집합 관계를 보존한다.

작은 트리를 큰 트리 아래로 붙인다

크기 기반 union은 각 루트의 원소 수를 기록하고 작은 트리의 루트를 큰 트리의 루트 아래에 붙인다. 같은 크기는 이 예제에서 번호가 작은 루트를 남긴다고 정한다. 이미 같은 루트라면 크기와 집합 수를 바꾸지 않는다.

원소의 깊이가 1 늘 때 그 원소가 속한 집합 크기는 적어도 두 배가 된다. 따라서 크기 기반 합치기만으로도 깊이는 log₂ n 이하가 된다. size는 루트에서 집합 크기를 뜻하며 비루트의 남은 값은 현재 부분트리 크기로 해석하지 않는다.

find가 경로를 짧게 만들 수 있다

전체 경로압축은 find에서 방문한 원소의 부모를 최종 루트로 바꾼다. 집합 구성과 대표자는 그대로이고 다음 탐색 경로가 짧아진다. 모든 노드의 부모를 한 번에 바꾸는 작업은 아니며 방문하지 않은 가지는 남는다.

균형 합치기와 적절한 경로압축을 결합하면 연산열의 분할 상환 비용은 역 Ackermann 함수와 관련된 매우 느린 증가를 갖는다. 이것을 모든 개별 연산이 정확히 상수 시간이라는 뜻으로 쓰지 않는다. 기본 분리집합은 집합을 다시 나누거나 삭제한 그래프 간선의 연결성을 복구하는 자료 구조가 아니다.

루트 정보는 그대로

번호가 작은 루트를 택하는 규칙은 크기가 같은 경우에만 적용한다. 마지막 find는 5→4→2의 경로만 압축하므로 1의 부모 0은 그대로다. 표는 손으로 만든 유한 상태 모형이다.

중간 과정을 따라가는 예제

원소 0부터 7까지에 (0,1),(2,3),(0,2),(4,5),(6,7),(4,6),(0,4)를 크기 기반으로 합친다. 같은 크기는 작은 루트가 남고 이 합치기 도중에는 경로압축을 하지 않는다. 이후 find(7)에서 전체 경로압축을 하라.

  1. 첫 두 쌍 뒤 루트 0과 2의 크기는 각각 2다. (0,2) 뒤 루트 0의 크기는 4이고 parent[3]=2는 그대로다.

  2. 뒤 세 쌍에서 루트 4는 크기 4가 되고 parent[7]=6, parent[6]=4다. 마지막 (0,4) 뒤 루트 0의 크기는 8이다.

  3. 합치기 직후 parent=[0,0,0,2,0,4,4,6]이다. 7→6→4→0을 방문하고 7/6/4의 부모를 0으로 바꾼다.

  4. 압축 뒤 parent=[0,0,0,2,0,4,0,0]이다. 방문하지 않은 3과 5는 각각 2와 4를 부모로 유지한다.

find(7)=0이며 집합 수는 1이다. 경로는 짧아지지만 집합의 원소 수 8은 변하지 않는다.

조건을 바꾸어 비교하기

대표자와 최소 원소의 다른 계약

최종 숲에서 find(1), 집합 크기, 최소 원소를 보고하라. find는 여기서 압축 없이 답만 읽는다.

  1. 1→0→2를 따라 대표자 2를 찾는다.

  2. 루트 2의 size=6과 min=0을 사용한다. 비루트 0의 이전 size=2는 현재 집합 크기가 아니다.

대표자 2, 크기 6, 최소 원소 0이다.

비교할 점

대표자를 업무 식별자로 쓰려면 그 식별자가 바뀔 수 있는지 계약을 먼저 정한다.

같은 분할의 다른 삭제 결과

그래프 A의 다섯 합치기 간선과 그래프 B의 추가 간선 (1,5)에서 (0,2)를 각각 삭제하라.

  1. A에서는 {0,1}과 {2,3,4,5}를 잇는 유일한 간선이 사라진다.

  2. B에서는 0–1–5–4–2의 길이 남아 두 집합을 잇는다.

A의 성분 수는 2, B의 성분 수는 1이다.

비교할 점

기본 union-find의 마지막 같은 집합 판정은 입력 간선의 중복 경로를 보존하는 삭제 자료 구조가 아니다.

종이와 본문으로 직접 해보기

위 압축 뒤 find(5)도 전체 경로압축하면 무엇이 바뀌는가? 이어 union(3,7)은 집합 수를 줄이는가?

힌트 보기

5의 부모를 따라가고 두 원소의 루트가 이미 같은지 확인한다.

풀이 보기

5→4→0이므로 parent[5]가 0이 된다. union(3,7)은 두 루트가 모두 0이어서 합칠 새 집합이 없다. 집합 수는 1이고 크기는 8이다.

오해와 반례

경로압축은 모든 원소의 부모를 즉시 루트로 바꾸고 find는 저장 상태를 바꾸지 않는다.

전체 압축은 방문 경로만 바꾼다. 이 구현의 find는 내부 parent를 수정할 수 있지만 외부 집합 관계는 보존한다. 추상적 질의와 내부 최적화의 효과를 구별한다.

연습 1 · 값과 상태 예측

union(0,2) 직후이며 find(5)는 아직 수행하지 않은 상태에서 전체 압축 find(1)을 한 번 수행하면 무엇이 바뀌나?

힌트 1

1→0→2 경로를 읽는다.

힌트 2

방문한 비루트를 최종 루트에 연결한다.

풀이와 답 확인

  1. parent[1]을 2로 바꾼다. parent[0]은 이미 2다.

  2. 5의 부모 4는 이 호출이 방문하지 않았으므로 그대로 남는다.

배열은 [2,2,2,2,2,4]이고 집합 수 1·크기 6·최소 0은 그대로다.

흔한 오답에서 다시 생각하기

find는 모든 노드를 한꺼번에 평탄화한다.

현재 호출의 방문 경로만 압축한다.

연습 2 · 오류 찾아 고치기

같은 크기에서 작은 번호를 남기므로 find(5)는 반드시 0이라고 썼다.

힌트 1

마지막 합치기의 크기를 비교한다.

힌트 2

크기가 다르면 번호보다 크기 조건이 먼저다.

풀이와 답 확인

  1. 크기 4인 루트 2 아래에 크기 2인 루트 0을 붙인다.

  2. 5→4→2의 대표자는 2이며 최소 번호 0과 다르다.

대표자 2로 교정하고 최소 번호가 필요하면 루트 min을 읽는다.

흔한 오답에서 다시 생각하기

root와 min을 두 필드로 두면 집합이 두 개가 된다.

대표자와 업무 요약은 같은 집합에 대한 다른 정보다.

연습 3 · 직접 만들어 보기

대표자와 별도로 최소 번호를 제공하는 갱신 규칙을 구성하라. 이미 같은 집합인 union도 포함하라.

힌트 1

서로 다른 루트의 min만 비교한다.

힌트 2

find로 같은 루트라면 분할과 집합 크기를 바꾸지 않는다.

풀이와 답 확인

  1. 서로 다른 루트면 크기 규칙으로 새 루트를 선택한 뒤 그 루트의 min을 min(min[r],min[s])로 기록한다.

  2. 같은 루트면 크기와 집합 수 및 min을 그대로 둔다. find가 압축할 때도 루트 min은 그대로다.

업무 조회는 min[find(x)]로 한다. 별도 그래프 경로나 간선 삭제 기능은 생기지 않는다.

흔한 오답에서 다시 생각하기

비루트 min도 항상 최신 값으로 갱신해야만 정확하다.

조회가 루트 정보만 읽는 계약이면 비루트의 오래된 요약은 사용하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

find가 부작용 없는 조회라는 가정으로 parent 전체를 검사 시점에 고정해 두었다. 전체 압축 find(5) 후 그 가정은 맞나?

힌트 1

같은 집합 판정과 표현 배열의 일치를 나눈다.

힌트 2

5의 부모는 4에서 2로 바뀐다.

풀이와 답 확인

  2. parent 배열은 [2,0,2,2,2,4]에서 [2,0,2,2,2,2]로 바뀐다.

추상 결과는 같아도 표현은 쓰기로 바뀐다. 이 문장은 순차 모형이며 실제 동시 실행·rollback 구현을 검증하지 않았다.

빈 문자열을 키로 허용하면 루트를 삭제해야 할까?

이번 새 집합 트라이의 계약은 원래 예제와 다르게 빈 문자열도 허용한다. 키는 빈 문자열 또는 ASCII 소문자로만 된 문자열이며 문자 일치는 정확하다. 저장 키가 "", an, ant, ax이면 루트·a·an·ant·ax의 다섯 노드가 있고 종료 표시는 루트, an, ant, ax의 네 곳이다. a 노드는 경로로 존재하지만 키가 아니다.

가장 긴 저장 접두어와 가장 긴 존재 경로도 다르다. anti의 가장 긴 저장 접두어는 ant다. az는 a 노드를 방문하지만 a가 종료 표시를 갖지 않으므로 가장 긴 저장 접두어는 빈 키다. 빈 키가 없었다면 같은 검색은 저장 접두어 없음이다. 결과 문자열이 빈 것만으로 두 상황을 구별할 수 없으므로 (found, prefix)를 사용한다.

삭제는 먼저 종료 표시를 지우고 불필요한 비루트 노드를 정리한다. ant를 지우면 그 잎만 없애고 an은 키로 남긴다. 다음 an을 지워도 ax를 위한 a 노드는 남긴다. 모든 비빈 키를 지우면 루트 한 개와 빈 키만 남는다. 마지막 빈 키 삭제는 루트의 종료 표시만 지우며 루트 구조 자체를 없애지 않는 계약이다. 실제 allocator·문자열 처리 API·트라이 프로그램은 실행하지 않았다.

먼저 확인할 개념
  • 경로와 종료 표시

    접두어 경로의 존재와 키 저장 여부를 별도로 확인한다.

  • 삭제와 남은 가지 보존

    삭제할 때 다른 키의 경로까지 잃지 않도록 구조와 항목을 함께 검사한다.

문자 하나씩 따라가는 경로다

트라이는 문자열을 문자 단위의 경로로 표현하는 트리다. 루트는 빈 접두어를 나타내고 간선의 문자들을 이어 읽으면 노드의 접두어가 된다. 같은 앞부분을 가진 단어들은 경로를 공유한다.

이 예제의 키는 소문자 영어 알파벳 문자열이고 문자 비교는 정확한 일치다. 노드에는 단어 종료 표시가 있다. 경로가 존재해도 종료 표시가 없으면 그 문자열 자체는 저장된 키가 아니다. at과 atom처럼 한 키가 다른 키의 접두어일 수도 있다.

정확 탐색과 접두어 탐색은 질문이 다르다

정확 탐색은 모든 문자를 따라간 뒤 종료 표시를 확인한다. 접두어 열거는 접두어 노드에 도달한 뒤 그 아래 종료 노드를 찾아 단어를 출력한다. 접두어 자체가 키라면 그것도 결과에 포함한다.

각 문자에 대한 자식 접근을 상수 시간으로 제공한다고 가정하면 길이 L의 정확 탐색은 O(L)이다. 접두어로 찾은 모든 문자열을 출력하는 작업은 결과 개수와 문자열 길이의 비용도 든다. 자식 저장 방식과 알파벳 크기에 따라 메모리와 실제 연산 비용이 달라진다.

삭제는 공유한 뒤쪽을 지우면 안 된다

키 삭제는 우선 해당 종료 표시를 지운다. 그 노드가 다른 키의 경로에 필요하면 남겨 둔다. 즉시 삭제 방식에서는 자식도 없고 종료 표시도 없는 불필요한 가지를 위로 정리한다.

at을 지워도 atom의 경로는 보존해야 한다. 키가 아닌 접두어 ato가 보인다는 이유로 ato를 저장한 것으로 취급하면 안 된다. 빈 문자열을 허용할지는 계약으로 정하며 허용한다면 루트의 종료 표시가 빈 키를 나타낸다. 여기서는 빈 키를 저장하지 않는다.

  • 집합의 중복 제거

학습 목표

  • 집합과 사전의 계약을 구별한다.

  • 갱신·삭제·없음 결과를 추적한다.

  • 계약과 구현별 성능을 구별한다.

대소문자를 합치는 사전은 입력을 모은 뒤 이름만 바꾸면 될까?

이번 새 사전은 ASCII 영문자 키를 소문자로 변환한 결과를 동일성 기준으로 사용한다. Unicode 일반 case folding이나 locale 규칙을 구현했다는 뜻은 아니다. 모든 put/lookup/delete에서 같은 변환을 적용한다. put("AB",3), put("ab",0), put("Ax",4)를 순서대로 수행하면 실제 키는 ab와 ax의 두 개이고 값은 0과 4다. 새 값으로 덮어쓰는 사전의 계약이다.

반대로 원래 대소문자 구별 사전에 세 키를 먼저 저장한 뒤 표시 이름만 소문자로 바꾸면 두 행이 ab로 보인다. 이때 어느 값을 남길지는 자동으로 정해지지 않는다. 입력 순서의 마지막 값 정책이면 ab의 값은 0, 첫 값 정책이면 3, 합 정책이면 3이다. 첫 값과 합이 이 입력에서 우연히 같아도 서로 다른 연산이다. put("AB",3), put("ab",2)의 반례에서는 각각 2,3,5로 갈린다.

값 0은 정상 값이므로 lookup("aB")는 (true,0)이다. 없는 키 "az"의 (false,무효 값)와 다르다. 값이 같은 두 키도 사전에서는 두 항목이다. 해시 구조를 선택한다면 동등한 키에 같은 해시를 적용해야 하며 정규화한 비교와 원래 철자의 해시를 섞으면 그 요구를 깨뜨릴 수 있다. 새 정규화 사전과 충돌 병합 정책은 자체 계약 모형이고 실제 라이브러리 실행은 하지 않았다.

먼저 확인할 개념
  • 사전의 키 수와 found

    유효한 값 0과 부재를 구별하고 동일 키의 갱신 정책을 정한다.

  • 해시 후보와 실제 키

    해시 충돌과 동일 키를 나누며 키 비교와 주소 계산의 일관성을 검사한다.

외부 연산을 먼저 정한다

ADT는 추상 자료형으로, 사용자가 수행할 연산과 결과 규칙을 정한다. 집합은 원소가 있는지·추가·삭제·크기를 다룬다. 같은 원소를 다시 추가해도 별도 중복 원소가 생기지 않는다.

사전은 키에 값을 연결한다. 이 단원에서는 같은 키에 새 값을 넣으면 기존 값을 덮어쓴다고 정한다. 키 하나당 값 하나이지만 여러 키가 같은 값을 가질 수 있다. 집합 크기는 원소 수, 사전 크기는 키 수이며 모든 값의 합과 다르다.

없음과 정상 값을 구별한다

자체 사전은 문자열 키와 정수 값을 저장하고 lookup 결과를 (found, value)로 설명한다. 값 0도 정상 값이므로 0만 반환하여 없는 키와 구별하지 못하면 안 된다. found가 거짓일 때 value는 유효한 조회 결과로 해석하지 않는다.

Princeton 교재의 일부 API는 null 값을 금지하고 없는 키에 null을 반환한다. 이는 그 API의 계약이며 모든 언어와 사전이 같은 규약을 쓰는 것은 아니다. 예외·기본값·별도 표시 중 무엇을 사용하는지 실제 API에서 확인해야 한다.

같은 계약도 여러 구조로 구현할 수 있다

연결 리스트·정렬 배열·균형 트리·해시 테이블·문자열 트라이는 사전의 일부 연산을 구현할 수 있다. 탐색·삽입·정렬 순회·접두어 검색의 비용과 제공 연산이 다르다. ADT 이름만 보고 상수 시간이라고 결정하지 않는다.

키의 동등성 규약도 필요하다. 이 예제에서는 대소문자를 구별하는 문자열 일치다. 사전은 순서가 보장된다는 추가 계약이 없으면 정렬된 출력 순서를 약속하지 않는다. 해시 구현이라면 동등한 키의 해시 일치 등 구현 조건을 함께 지켜야 한다.

중간 과정을 따라가는 예제

빈 사전에 put("tomato",2), put("apple",1), put("tomato",5), put("zero",0)를 실행한다. 사전 크기와 tomato/zero/pear 조회를 구하라.

  1. tomato와 apple의 삽입 뒤 키 수는 2다. 같은 tomato에 5를 넣어도 키 수는 2이며 값만 5로 바뀐다.

  2. zero 삽입 뒤 키 수는 3이다. tomato 조회는 (참,5), zero 조회는 (참,0)이다.

  3. pear는 없어 found가 거짓이다. zero의 값 0과 pear의 없음은 다른 결과다.

크기 3, tomato 값 5, zero 값 0이며 pear는 없다. 값 합 6은 크기가 아니다.

조건을 바꾸어 비교하기

정상 0의 존재 검사

세 put 뒤 lookup aB, lookup AZ를 비교하고 aB를 삭제하라.

  1. aB는 ab, AZ는 az로 변환한다. ab의 값 0은 실제 저장 값이다.

  2. ab를 삭제하면 ax만 남고 키 수 1·값 합 4다.

aB는 (true,0), AZ는 found=false다. 삭제 후 aB도 found=false다.

비교할 점

0을 false로 취급하여 삭제하지 않으면 키가 남는 오류다.

늦은 정규화의 세 정책

대소문자 구별 사전에 AB=3, ab=2를 저장한 뒤 한 키 ab로 병합한다. 마지막/첫/합의 결과는?

  1. 두 원래 키가 같은 정규 키로 충돌하므로 명시적인 병합 정책이 필요하다.

  2. 기존 순서가 AB 후 ab이므로 마지막은 2, 첫은 3, 합은 5다.

정규 키 수는 셋 모두 1이지만 연결 값은 2/3/5로 다르다.

비교할 점

키 개수만 같다고 업무 결과도 같아지는 것은 아니다.

힌트 보기

풀이 보기

오해와 반례

사전이라는 이름이면 탐색은 상수 시간이고 키는 정렬되어 나온다.

시간과 순서는 구현 및 계약의 성질이다. 연결 리스트는 탐색에 키 수만큼 비교할 수 있고 정렬 순회는 별도 지원이 필요하다. 해시의 기대 비용도 해시·부하 등 조건을 가진다.

다른 문제에 적용하기

분할·문자열·동일성 계약을 함께 보존하기

여섯 원소에 본문의 다섯 union을 적용한 뒤 대표자·집합 크기·최소 원소와 전체 압축 find(5)의 부모 배열을 보고하라. 그래프 A와 B에서 (0,2)를 삭제한 성분 수도 비교하라. 빈 키를 허용한 트라이의 초기 키 "", an, ant, ax에서 ant와 an을 순서대로 삭제한 키·노드 수와 query az의 최장 저장 접두어를 구하라. ASCII 소문자 동일성 사전에 AB=3, ab=0, Ax=4를 넣고 aB를 조회한 뒤 삭제한 결과를 구하라.

힌트 1

대표자와 루트의 min을 나누며 기본 union-find가 보존하지 않는 대체 간선을 따로 읽는다.

힌트 2

트라이 종료 표시·공유 경로·빈 키의 found와 사전 값 0의 found를 따로 확인한다.

풀이와 답 확인

  1. 최종 대표자는 2, size[2]=6, min[2]=0이다. find(5) 뒤 parent=[2,0,2,2,2,2]이며 A의 삭제 후 성분 수는 2, B는 1이다.

  2. 트라이에서 두 삭제 뒤 키는 빈 키와 ax의 두 개다. 노드는 루트/a/ax의 세 개이고 az의 최장 저장 접두어는 (true, "")다.

  3. 정규 사전은 ab=0과 ax=4의 두 항목이다. aB 조회는 (true,0)이며 삭제 뒤 ax=4만 남아 키 수 1·값 합 4다.

  4. 모든 배열·문자·입력 순서와 갱신 규칙은 자체 순차 모형이다. 실제 그래프 삭제 엔진·allocator·트라이/해시 라이브러리·학생 시험은 수행하지 않았다.

추상 집합·키·값과 구현의 루트·경로·정규화 규칙을 각각 대응한다. 같은 요약이나 같은 반환 문자열만으로 생략한 정보까지 보존되었다고 결론내리지 않는다.

  • 대체 경로가 삭제 결과에 미치는 영향을 입력 그래프에서 확인한다.

  • 트라이의 키 수·노드 수·빈 키의 존재를 별개로 센다.

  • 모든 사전 연산의 동일성 규약과 정상 값 0의 존재 표시를 유지한다.

보강 자료의 출처와 확인 범위
  • Princeton — Union-Find

    web 조회는 403이었지만 urllib로 실제 HTML 전체를 받아 본문 전체를 읽었다. 분할·부모·크기 기반 깊이·압축·비용 모형과 fully dynamic 연결성의 별도 문제를 확인했다. 여섯 원소와 min·삭제 대체 경로 사례는 자체 손설계다.

  • Princeton — Tries

    urllib로 실제 HTML 전체 본문을 읽었다. 정확 키/접두어/최장 접두어·출력 열거·lazy/eager 삭제와 경로 공유의 범위를 확인했다. 빈 키 허용과 노드 수 표는 자체 계약이며 실제 Java를 실행하지 않았다.

  • Princeton — Symbol Tables

    urllib로 실제 HTML 전체 본문을 읽었다. 동일 키 갱신·동등성·null 부재 규약·immutable 키·순서 연산/구현 비용의 조건을 확인했다. ASCII 정규화와 첫/마지막/합 병합 및 found는 자체 새 모형이다.

현재 base 세 소단원과 여섯 선수 설명 전체를 읽고 여섯 원소 union의 부모/크기/min·방문 압축·두 그래프 삭제, 빈 키 트라이 다섯 노드에서 4/3/1/1개로 정리하는 표와 별도 an 직접 삭제의 다섯 노드 보존, 정규 사전의 키 수/값 합/found·첫/마지막/합 정책을 손으로 전부 추적했다. 새 프로그램으로 계산을 실행한 것은 아니다.
