소단원 13.1

비교 정렬과 안정성

점수가 같은 두 카드의 이름 순서가 뒤집혀도 올바른 정렬일까?

준비 개념과 학습 목표

준비 개념

  • 배열

  • 비교 key

  • 삽입·병합 정렬

학습 목표

  • 정렬 순서와 같은 key의 상대 순서를 따로 점검한다.

  • 안정성을 구현의 동률 정책과 연결한다.

  • 비교와 이동 비용을 구별한다.

내림차순으로 바꾸려고 결과 전체를 뒤집으면 같은 점수의 접수 순서도 보존될까?

정렬의 key가 여러 개면 우선순위도 계약이다. 가상 신청 네 건을 접수 순서 A, B, C, D로 놓고 (부서, 점수)는 A=(B,2), B=(A,2), C=(B,1), D=(A,2)로 정한다. 원하는 보고서는 부서 오름차순이 주 기준, 같은 부서의 점수 내림차순이 부 기준이며 두 기준이 모두 같으면 접수 순서를 유지한다. 이름은 identity를 표시할 뿐 비교 key가 아니다.

안정 정렬을 여러 번 수행하면 마지막 정렬의 기준이 가장 중요해진다. 먼저 점수 내림차순으로 안정 정렬하면 A, B, D, C이고, 다음 부서 오름차순으로 안정 정렬하면 B, D, A, C다. 반대로 부서를 먼저 정렬하고 점수를 마지막에 정렬하면 B, D, A, C가 이 입력에서는 우연히 같을 수 있으므로 한 입력의 일치만으로 규칙을 증명하지 않는다. A의 점수를 1, C의 점수를 3으로 바꾼 반례에서는 마지막 기준의 영향이 드러난다.

점수 내림차순이라는 말과 오름차순 결과를 통째로 뒤집는 작업도 다르다. 입력 (2,P),(1,Q),(2,R),(1,S)를 점수 오름차순으로 안정 정렬한 결과는 Q,S,P,R이다. 이것을 뒤집으면 R,P,S,Q가 되어 같은 점수의 P→R과 Q→S도 뒤집힌다. 원하는 안정 내림차순은 P,R,Q,S다. 작은 상태표의 순서와 identity 보존을 확인하며 실제 라이브러리나 처리 시간을 측정한 것은 아니다.

먼저 확인할 개념
  • 같은 key의 상대 순서

    안정성의 대상은 비교 기준이 같은 항목의 입력 순서다.

  • 배열 위치와 항목

    위치가 변해도 항목 identity와 개수를 보존해야 한다.

무엇을 기준으로 정렬하는가

비교 정렬은 두 항목의 key를 비교해 순서를 결정한다. key가 숫자 점수라면 이름은 정렬 판단에 참여하지 않을 수 있다. 정렬 결과는 key가 비감소해야 하고 입력 항목을 빠뜨리거나 새 항목을 만들지 않아야 한다.

안정 정렬은 같은 key인 항목의 입력 상대 순서를 보존한다. 모든 항목이 다른 key라면 안정성 차이를 관찰할 수 없다. 안정성이 필요하지 않은 업무에서도 정렬 자체는 올바를 수 있으므로 요구 조건을 구별한다.

같으면 어떻게 하는지가 중요하다

삽입 정렬에서 새 항목보다 큰 기존 key만 오른쪽으로 옮기면 같은 key의 기존 항목은 앞에 남는다. ≥ 비교로 같은 것까지 옮기면 이 구현의 안정성이 깨질 수 있다.

병합에서는 두 정렬된 부분 배열의 앞 key가 같을 때 왼쪽 항목부터 택해야 입력 순서를 보존할 수 있다. 두 부분이 원래 연속 구간이고 각각 안정 정렬되었다는 조건을 함께 둔다. 병합이라는 이름만으로 동률 정책을 생략하지 않는다.

순서 조건과 비용 조건은 분리한다

단순 삽입 정렬은 역순에서 많은 항목을 이동해 O(n²) 시간이 들고, 이미 정렬된 입력에서는 이동이 없어 선형 비교로 끝날 수 있다. 기본 병합 정렬은 두 부분을 반복 합쳐 O(n log n) 비교 규모를 갖지만 구현에 따라 보조 배열 공간이 필요하다.

안정성은 상대 순서의 계약이고 시간·공간은 자원 계약이다. 같은 점근 비용의 구현도 실제 상수·메모리 접근·key 계산 비용이 다르다. 아래 표는 키 비교와 항목 이동만 센 자체 모형이며 실행 시간 측정이 아니다.

내림차순으로 바꾸려고 결과 전체를 뒤집으면 같은 점수의 접수 순서도 보존될까?
절차첫 단계 결과최종 결과동률 정책

점수↓ 후 부서↑

A,B,D,C

B,D,A,C

같은 부서·점수의 B→D 유지

점수↑ 후 전체 역전

Q,S,P,R

R,P,S,Q

동률도 역전되어 안정 내림 아님

안정 점수↓

P,R,Q,S

P,R,Q,S

P→R 및 Q→S 유지

첫 행과 뒤 두 행은 서로 다른 입력이다. 기호 ↑/↓는 key의 방향이며 identity 문자열을 정렬하는 지시가 아니다. 접수 순서는 최초 배열의 순서로 고정한다.

중간 과정을 따라가는 예제

입력 카드는 (2,A),(1,B),(2,C),(1,D)다. 점수만 기준으로 큰 key만 이동하는 삽입 정렬을 하자. 이동은 기존 항목을 한 칸 오른쪽에 쓰는 횟수이며 마지막 삽입 쓰기는 제외한다.

  1. B를 넣으면 A 하나를 오른쪽으로 옮겨 (1,B),(2,A),(2,C),(1,D)가 된다.

  2. C는 앞의 A와 같은 key라 움직이지 않는다. D를 넣을 때 C와 A 두 항목만 옮기고 같은 key의 B 뒤에 넣는다.

  3. 결과는 (1,B),(1,D),(2,A),(2,C)다. 이동 수는 1+0+2=3이고 같은 key 순서는 B→D, A→C로 보존된다.

이 모형은 안정적이며 기존 항목 오른쪽 이동은 3회다. 정렬 전후 카드 identity의 집합도 같다.

조건을 바꾸어 비교하기

다중 기준의 실제 우선순위

변형 입력 A=(B,1), B=(A,2), C=(B,3), D=(A,2)를 부서↑/점수↓로 정렬하라. 잘못된 두 단계 순서도 비교하라.

  1. 점수↓ 안정 정렬은 C,B,D,A다. 부서↑를 마지막에 적용하면 B,D,C,A다.

  2. 부서↑ 먼저 B,D,A,C로 만든 뒤 점수↓를 적용하면 C,B,D,A다. 부서 B인 C가 부서 A 앞에 와 주 기준을 위반한다.

올바른 결과는 B,D,C,A이며 잘못된 순서는 C,B,D,A다.

비교할 점

두 단계의 순서가 한 입력에서 우연히 같아도 모든 입력의 기준은 같지 않다.

동률 병합의 출처 정보

원래 연속 두 구간 L=[(1,U),(2,V)], R=[(1,W),(2,X)]를 병합한다. 같은 key에서 오른쪽을 먼저 택하면?

  1. 1의 동률에서 W를 먼저 쓰고 다음 U를 쓴다.

  2. 2의 동률에서 X를 먼저 쓰고 다음 V를 쓴다.

결과 W,U,X,V는 key 순서는 맞지만 원래 U→W와 V→X를 뒤집는다. 왼쪽 우선이면 U,W,V,X다.

비교할 점

각 구간의 안정성과 구간의 원래 선후 관계를 함께 사용해야 한다.

종이와 본문으로 직접 해보기

선택 정렬의 첫 단계로 최소 B를 맨 앞 A와 교환하고, 다음 단계 최소 D를 두 번째 A와 교환하자. 이후 점수는 정렬되지만 같은 점수 2의 순서는?

힌트 보기

첫 교환은 B,A,C,D이고 다음 교환은 B,D,C,A다.

풀이 보기

결과는 B,D,C,A, 즉 (1,B),(1,D),(2,C),(2,A)다. key는 정렬되었지만 원래 A→C가 C→A로 뒤집혀 이 swap 기반 선택 정렬은 안정적이지 않다.

오해와 반례

key가 비감소이면 안정성 요구도 자동으로 통과한다.

B,D,C,A는 key 순서가 1/1/2/2지만 같은 key A와 C의 순서가 뒤집힌 반례다. 안정성 요구는 identity와 원래 순서까지 비교해야 한다.

연습 1 · 값과 상태 예측

P,Q,R,S 입력의 점수 내림차순 안정 정렬에서 같은 점수의 순서와 결과는?

힌트 1

원래 P가 R보다 먼저다.

힌트 2

원래 Q가 S보다 먼저다.

풀이와 답 확인

  2. 점수 1의 묶음은 Q,S다.

결과 P,R,Q,S이며 내림차순에서도 두 묶음 안 접수 순서는 같다.

힌트 1

정렬 단계 순서를 바꾸며 B,D의 동률 접수 순서도 보존한다.

연습 3 · 직접 만들어 보기

부서↑/점수↓/접수 순서의 계약을 단일 사전식 정수·문자 key로 표현하라. 점수는 유한 정수다.

힌트 1

힌트 2

풀이와 답 확인

  2. 이 key 오름차순으로 정렬하고 부착 정보를 제거한다.

정렬 key가 접수 순서를 명시한다. 원래 인덱스가 고유하면 비교 key 동률은 없어지며 알고리즘 자체의 안정성과 구별한다.

안정 병합의 왼쪽 우선 규칙에서 두 입력 구간이 원래 연속 구간이 아니면 최초 접수 순서도 항상 보존되나?

힌트 1

원래 U,W,V,X가 모두 같은 key라고 두라.

힌트 2

구간을 L=[U,V], R=[W,X]로 나눈다.

풀이와 답 확인

  1. 왼쪽 우선은 U,V,W,X를 낸다.

이진 탐색과 경계 탐색

같은 값이 세 번 있을 때 하나를 찾는 것과 첫 위치를 찾는 것은 같을까?

준비 개념과 학습 목표

준비 개념

  • 0부터 시작하는 인덱스

학습 목표

점수순으로 만든 배열에서 이름순 비교로 절반을 버려도 될까?

경계 탐색의 불변식은 배열을 정렬한 것과 같은 비교를 전제한다. 가상 레코드 (점수,ID)=[(2,Z),(2,A),(5,M),(8,B)]는 점수만으로는 정렬되었다. 그러나 (점수,ID)의 사전식 순서로는 Z가 A 앞에 있어 정렬되지 않았다. 목표 (2,A)의 사전식 lower를 이 배열에 적용하면 정렬되지 않은 절반을 버릴 수 있다. 비교 기준을 늘리는 것이 언제나 안전한 정밀화는 아니다.

점수만 찾을 때의 경계는 레코드 ID 존재와 다르다. 위 배열의 점수 2 경계는 [0,2)이고 두 레코드가 있다. 찾으려는 ID가 A라면 이 두 항목의 ID를 추가 검사하거나 ID까지 포함한 별도 정렬을 사용해야 한다. 점수 2가 하나 있다는 이유로 ID A가 있다는 결론은 다른 입력 [(2,Z),(2,Y),(5,M),(8,B)]에서 틀린다.

검색용 key 배열을 별도로 만들면 대응도 불변식이다. records의 점수에서 keys=[2,2,5,8]을 만들고 나중에 첫 레코드 점수를 9로 바꾸면서 keys만 그대로 두면 검색은 옛 값을 근거로 한다. 결과가 범위 안이라는 사실만으로 대응은 인증되지 않는다. Python bisect의 key는 배열 항목에는 적용하지만 검색 목표 x에는 적용하지 않으므로 점수 key를 쓰는 검색에서는 숫자 목표를 직접 제공하는 규약을 읽는다. 여기서는 정적이고 총순서를 갖는 유한 정수 자료를 손으로 추적한다.

먼저 확인할 개념
  • 반열린 경계 불변식

    버릴 구간의 모든 값에 같은 비교 규칙을 적용한다.

  • 중복과 rank의 계약

    작은 key 수와 개별 identity의 존재를 구별한다.

정렬과 같은 비교 규칙을 사용한다

이진 탐색은 정렬된 임의 접근 배열에서 중간 key와 목표를 비교하고 필요 없는 절반을 버린다. 정렬 기준과 탐색 기준이 같아야 한다. 정렬하지 않은 배열에 그대로 적용하면 절반을 버릴 근거가 없다.

중복 값 중 아무 한 곳을 반환하는 탐색과 경계를 찾는 탐색은 계약이 다르다. 아래 lower는 목표 x 이상인 첫 인덱스, upper는 x보다 큰 첫 인덱스다. 그런 항목이 없으면 배열 길이 n을 반환한다.

반열린 구간의 불변식을 유지한다

lower 탐색은 lo=0, hi=n으로 시작한다. [0,lo)는 모두 x보다 작고 [hi,n)은 모두 x 이상이라고 유지한다. lo<hi일 때 mid=lo+floor((hi−lo)/2)를 계산한다. a[mid]<x이면 lo=mid+1, 아니면 hi=mid로 줄인다.

mid가 hi보다 작으므로 실제 배열 범위 안이다. 각 반복은 hi−lo를 줄이고 lo=hi일 때 그 위치가 lower다. upper에서는 판단을 a[mid]≤x로 바꿔 같은 값을 왼쪽에 포함시킨다. 비교 관계가 일관되고 탐색 중 배열이 바뀌지 않는다는 조건을 둔다.

삽입 위치는 존재 판정이 아니다

lower가 i라는 것은 그 위치에 넣어도 정렬을 유지한다는 뜻이다. 실제 존재 여부는 i<n인지 먼저 확인하고 a[i]==x인지 비교한다. i=n일 때 배열을 읽으면 범위를 벗어난다.

중복 값의 범위는 [lower(x),upper(x))이고 개수는 둘의 차이다. 범위 질의 [L,R)는 lower(R)−lower(L)로 셀 수 있다. 경계 규칙과 목표가 배열값과 동일한 비교 기준인지 먼저 확인한다.

중간 과정을 따라가는 예제

배열 a=[1,3,3,3,7,9]에서 x=3의 lower와 upper를 위 알고리즘으로 찾자. 인덱스는 0부터 시작한다.

  1. lower는 (lo,hi)=(0,6)에서 mid=3, a[3]=3이므로 hi=3이다. (0,3)의 mid=1, 값 3으로 hi=1이다. (0,1)의 mid=0, 값 1로 lo=1이다. 종료 위치는 1이다.

  2. upper는 (0,6)에서 mid=3, 값 3≤3이라 lo=4다. (4,6)의 mid=5, 값 9로 hi=5다. (4,5)의 mid=4, 값 7로 hi=4다. 종료 위치는 4다.

  3. 같은 값 범위는 [1,4)이며 개수 4−1=3이다. i=1<n이고 a[1]=3이라 실제 존재한다.

lower=1, upper=4, 중복 3개다. 같은 비교 key를 유지한 배열에만 이 결과를 적용한다.

다른 비교의 실패 추적

첫 배열에서 사전식 목표 (2,A)의 lower를 base 알고리즘으로 추적하라.

  1. (lo,hi)=(0,4)의 mid=2 값 (5,M)은 목표보다 크므로 hi=2다.

  2. mid=1 값 (2,A)에서 hi=1, mid=0 값 (2,Z)에서 hi=0이다.

  1. keys=[2,2,5,8]에서 lower(5)=2, upper(5)=3이다.

  2. lower(2)=0, lower(8)=3이므로 구간의 수는 3이다.

삽입 인덱스가 반환되면 그 값이 반드시 배열에 있다.

추가 공간 한도가 넘는 가장 싼 계획을 선택 후보에 넣어도 될까?

가상 정적 레코드 16개에 부재 membership 질의 q개를 수행한다. 계획 U는 정렬 없이 질의당 비교 16회를 하고 추가 레코드 슬롯을 쓰지 않는다. 계획 S는 최초 정렬에 비용 40단위를 예약하고 질의당 6단위를 예약한다. 임시 복사와 정렬 작업을 포함한 추가 슬롯 피크는 이 계획 계약에서 16개다. 여기의 비용은 자체 동일 가중 연산 단위이며 초나 CPU 측정이 아니다.

추가 슬롯 한도가 12개라면 S는 비용식과 무관하게 이 계약대로 실행할 수 없다. 공간 한도를 16개로 올려야 두 계획을 비교할 수 있다. 16q와 40+6q는 q=4에서 모두 64이고 정수 q≥5에서 S의 예약 비용이 작다. 이 비교는 정적 자료·부재 질의·고정된 모형이라는 전제를 쓴다. 실제 검색은 상한보다 적은 비교로 끝날 수 있고 실제 시간의 우열도 따로 측정해야 한다.

다시 갱신을 넣으면 후보의 계약 자체가 바뀐다. 각 갱신은 임의 기존 항목 하나를 같은 크기의 새 항목으로 바꾸며 길이를 16으로 유지한다고 하자. 계획 U의 갱신 예약은 1, 계획 S는 정렬 유지 이동과 검색을 합쳐 17단위를 예약한다. 갱신 u개를 포함한 전체 예약은 16q+u와 40+6q+17u다. 중복 ID가 아닌 같은 점수 레코드들을 모두 보존해야 한다면 unique set으로 교체하는 후보는 같은 업무를 수행하지 못한다. 더 빠른 비용표보다 먼저 요구·자원·결과 계약을 비교한다.

질문 목록이 자료구조를 정한다

위치로 읽기·같은 key 찾기·범위 출력·최솟값 추출·빈번한 갱신은 서로 다른 요구다. List는 위치의 순서를, set은 유일한 항목의 포함을, 정렬 set은 비교 순서를 계약에 포함할 수 있다. 중복을 보관해야 한다면 unique set으로 몰래 바꾸면 안 된다.

인터페이스가 같아도 구현의 연산 비용은 다를 수 있다. 범위 출력 k개에는 출력 자체의 비용도 있다. membership 하나가 빠르다고 범위 순회·위치 접근도 빠르다고 결론내리지 않는다.

전처리와 갱신을 합산한다

정렬 배열은 임의 접근과 이진 경계 탐색에 알맞다. 하지만 정렬되지 않은 입력을 처음 정렬하는 비용이 있고, 가운데 삽입은 뒤 항목들을 이동시켜 O(n)이 될 수 있다. 이진 탐색 O(log n)이 전체 삽입 O(log n)을 뜻하지 않는다.

정렬 배열을 많이 읽고 드물게 바꾸는 경우와, 배열 전체를 한 번만 읽는 경우를 구별한다. 아래 비용 비교는 명시한 연산 수를 합산하는 가상 모형이다. 서로 다른 종류의 연산을 실제 같은 시간이라고 측정한 것은 아니다.

조건과 예외를 표에 남긴다

선형 탐색은 정렬을 요구하지 않지만 최악에는 전체를 확인한다. 정렬 배열의 경계 탐색은 정렬을 유지해야 하고 중간 삽입은 이동한다. 해시 기반 lookup과 균형 탐색 트리는 다른 연산 조합의 후보지만 부하·충돌·균형·메모리 등 구현 조건을 확인해야 한다.

선택 보고에는 자료 수·검색과 갱신 비중·중복·순서 요구·메모리 제한을 쓴다. 점근식은 규모 변화의 설명이며 실제 처리 시간·cache·key 비용·할당 비용을 대체하지 않는다. 요구를 만족하는지 먼저 확인하고 같은 조건에서 측정하는 순서를 지킨다.

중간 과정을 따라가는 예제

가상 자료 8개는 고정이며 갱신이 없다. 부재 질의마다 비정렬 선형 탐색은 비교 8회가 필요하다. 다른 계획은 초기 정렬 비용을 24단위로 가정하고 경계 탐색·존재 판정을 포함한 질의당 상한 5단위를 예약한다. 두 계획의 예산을 q=1과 q=12에서 비교하자. 단위는 이 예제만의 동일 가중 비용이다.

  1. 비정렬 계획 예산은 8q, 정렬 계획 예산은 24+5q다. 후자는 실제 매 질의가 상한을 쓰는 관측이 아니라 예약 예산이다.

  2. q=1이면 8 대 29라 초기 정렬 비용이 크다. q=12이면 96 대 84라 정렬 계획의 예약 예산이 작다.

  3. 8q=24+5q에서 q=8이면 두 예산은 64다. 정수 q>8이면 이 모형의 정렬 예산이 작다. 실제 벽시계 속도 우열은 이 합산만으로 인증하지 않는다.

q=1은 8/29, q=12는 96/84, 경계 q=8이다. 전처리를 빼면 이 비교의 조건을 바꾼 것이다.

비용 우열과 실행 가능성

q=6,u=0이며 추가 슬롯 한도가 12개다. 비용과 후보를 각각 판정하라.

  1. U는 96, S는 40+36=76이다.

  2. S의 추가 슬롯 16은 한도 12보다 크다.

비용만 보면 S가 작지만 현재 가능 후보는 U뿐이다. 한도를 16으로 올리면 S도 비교할 수 있다.

비교할 점

싼 예약값은 자원 제한을 무시하는 허가가 아니다.

갱신으로 바뀐 문턱

q=6,u=2이고 공간 한도는 16이다. 두 전체 예약을 비교하라.

  1. U는 96+2=98이다.

  2. S는 40+36+34=110이다.

갱신 없는 96/76 비교와 달리 갱신을 포함하면 U의 예약 98이 S의 110보다 작다.

종이와 본문으로 직접 해보기

정렬 배열 [1,3,3,3,7,9]에 4를 넣는다. 필요한 삽입 위치와 기존 항목의 오른쪽 이동 수는? 배열 용량은 이미 충분하며 새 값 쓰기와 검색 비용은 이동 수에서 제외한다.

힌트 보기

lower(4)=4이고 뒤의 기존 항목은 7과 9다.

풀이 보기

위치 4에 넣고 기존 인덱스 4의 7과 인덱스 5의 9를 한 칸씩 옮겨 이동 2회다. 결과는 [1,3,3,3,4,7,9]다. 용량 확장 비용이 없는 가정에서의 수이며 최악의 맨 앞 삽입은 기존 6개를 모두 이동한다.

오해와 반례

이진 탐색으로 위치를 찾으니 정렬 배열 삽입도 언제나 로그 시간이다.

삽입 위치 뒤의 항목 이동을 빠뜨렸다. 맨 앞 삽입은 기존 n개를 이동할 수 있고 라이브러리 bisect 문서도 검색과 삽입 비용을 구별한다.

풀이와 답 확인

  1. ① 점수↓는 C,B,D,A이고 부서↑를 마지막에 적용한 결과는 B,D,C,A다. B→D 접수 순서가 유지된다.

  2. ② 점수 lower=0, upper=2이며 두 ID를 검사하면 A는 인덱스 1에 있다. 사전식 비교를 같은 배열에 무조건 적용하지 않는다.

  3. ③ U는 16×6+2=98, S는 40+6×6+17×2=110이다. 추가 공간 12에서는 U만 가능하고 16에서는 둘 다 가능하지만 U의 예약이 작다.

우선순위와 동률 정책, 정렬과 탐색 비교 규칙, identity 출력 및 자원 가능성을 같은 계약으로 기록한다. B,D,C,A·점수 범위 [0,2)/A 위치 1·전체 예약 98/110을 보고하며 실제 라이브러리 성능과 학습자 실험은 미수행이다.

해결한 뒤 점검할 것

  • 정렬의 주·부 기준과 최초 접수 순서를 명시한다.

  • 점수 경계와 개별 ID 판정을 분리하고 범위 밖 항목을 읽지 않는다.

  • 공간 한도와 초기/질의/갱신 비용을 각각 계산한다.

  • 중복 출력·동일 업무·비교 규칙을 유지하고 가상 예약을 실측 성능으로 주장하지 않는다.
