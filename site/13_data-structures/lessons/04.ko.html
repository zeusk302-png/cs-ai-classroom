소단원 4.1

단일·이중·원형 연결

줄 선 카드의 순서는 카드가 놓인 위치로 정할까, 카드에 적힌 다음 화살표로 정할까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 노드는 데이터와 다른 노드를 가리키는 링크를 가진 객체이다. 포인터 복사는 노드 복제가 아니다.

  • head는 첫 데이터 노드를 가리키며 null은 선형 리스트의 끝을 뜻할 수 있다.

  • 자가진단: head→A→B→null에서 데이터가 A=6, B=2라면 순서열은 [6,2]이다. 주소의 크기 순서가 아니다.

학습 목표

  • 단일·이중·원형의 링크와 종료 조건을 비교한다.

  • 삽입 전 기존 연결을 보존하는 순서를 추적한다.

  • 노드 위치 찾기와 링크 변경의 비용을 구분한다.

값이 같은 노드를 다시 만나면 한 바퀴를 다 돈 것일까?

단일 원형 리스트 A→B→C→A에서 A와 B의 값은 모두 7, C의 값은 9라고 하자. 값 7을 다시 보았다고 종료하면 B를 읽기 전에 멈추어 실제 세 원소 중 둘을 놓칠 수 있다. 종료 기준은 값의 동등성이 아니라 시작 노드 A의 정체성이다. 비어 있지 않은 정상 링이라는 전제 아래 현재 노드를 읽고 next를 따라간 뒤 A인지 검사하면 A, B, C를 각각 한 번 읽는다.

노드의 next를 바꾸는 순간 순회 경로도 바뀐다. 단일 선형 A→B→C→null을 뒤집으려면 아직 살아 있는 현재 노드의 옛 next를 먼저 보존한다. prev=null, cur=A에서 saved=cur.next; cur.next=prev; prev=cur; cur=saved를 반복한다. 완료된 앞부분은 역방향 사슬이고 cur는 아직 처리하지 않은 원래 사슬의 머리다. 세 노드 뒤에는 head=C와 C→B→A→null을 얻는다.

이중 연결을 뒤집으면서 next만 바꾸면 역방향 불변식이 자동으로 복원되지 않는다. 원래 A.prev=null, B.prev=A, C.prev=B를 남겨 두고 next만 C→B→A로 만들면 새 머리 C의 prev가 B라 잘못된다. 각 노드의 next와 prev를 서로 바꾸고 head와 tail도 교환해야 한다. 순차적인 완료 상태를 다루는 종이 모형이며 대입 중 다른 스레드의 관찰이나 실제 C 수명 검사를 대신하지 않는다.

먼저 확인할 개념
  • 노드 정체성과 순회 종료

    선형·원형의 다른 종료 계약과 next가 정하는 순서를 복습한다.

  • 정방향과 역방향 불변식

    이중 연결의 두 이웃 대응이 완료 상태에서 모두 성립해야 함을 사용한다.

연결 리스트는 도달 경로로 순서를 표현한다

단일 선형 리스트의 각 노드는 value와 next를 갖는다. head에서 next를 따라가며 유한 개의 서로 다른 노드를 만난 뒤 null에 도달하는 것을 이 단원의 표현 불변식으로 정한다. 빈 리스트는 head=null이다. 데이터 값의 중복은 허용하지만 같은 노드를 순회 중 다시 만나는 순환은 이 선형 표현의 전제에 맞지 않는다.

노드들이 실제 메모리에서 연속해 있어야 할 필요는 없다. 논리 순서는 next가 정한다. 그러나 연결 방식이 항상 떨어진 배치를 강제하는 것도 아니다. 비용 분석에서는 노드 하나의 링크를 따라가는 연산을 한 단위로 잡고 캐시·할당기·실제 시간은 별도로 둔다.

이중과 원형은 유지할 관계가 달라진다

이중 선형 리스트에는 next와 prev가 있다. 인접 A와 B에서 A.next=B이면 B.prev=A가 되어야 한다. 첫 노드의 prev와 마지막의 next는 null로 정할 수 있다. 한 방향 링크만 고치면 역방향 경로는 이전 구조에 남을 수 있어 삽입·삭제 시 양쪽 불변식을 회복해야 한다.

원형 연결에서는 마지막 다음이 첫 노드 또는 센티널로 돌아온다. 원형은 단일/이중과 다른 축이라 단일 원형과 이중 원형을 모두 만들 수 있다. null을 만날 때까지 순회하면 원형에서는 끝나지 않는다. 시작 노드로 돌아오는 조건, 센티널 재도달, 명시한 개수 같은 종료 규칙을 선택해야 한다.

빠른 변경에는 이미 위치를 알고 있다는 조건이 있다

새 노드 U를 단일 리스트의 head 앞에 넣을 때 U.next=old_head를 먼저 정하고 head=U로 바꾼다. 머리를 먼저 잃고 그 값으로 U.next를 정하면 U가 자기 자신을 가리키거나 옛 리스트에 도달할 경로를 잃을 수 있다. 모든 링크는 살아 있는 올바른 노드를 가리킨다는 전제를 둔다.

주어진 선행 노드 P 뒤 삽입은 일정한 링크 대입으로 가능하지만 위치 i의 P를 head부터 찾아오는 비용은 별도이다. 단일 리스트의 임의 노드 삭제에는 선행 노드 연결을 바꿀 정보가 필요하다. 이중 리스트는 삭제할 노드를 이미 알면 양 옆 링크를 직접 고칠 수 있어도 찾기 비용이 자동으로 사라지지는 않는다.

prev와 cur는 살아 있는 노드의 이름 또는 null이다. saved는 해당 행에서 링크를 덮기 전의 next다. 최종 head는 prev로 바꾼다. 노드의 값이 같아도 세 정체성은 합쳐지지 않는다.

중간 과정을 따라가는 예제

head→A(6)→B(2)→null인 단일 리스트에 새 U(9)를 머리 앞에 삽입한다. 이어 단일 원형 A→B→A에서 A부터 데이터 한 바퀴를 읽는 종료 조건도 설명한다.

  1. 기존 head는 A이다. U.next=A로 정하여 원래 두 노드로 가는 경로를 보존한다.

  2. head=U로 바꾸면 U→A→B→null이다. 데이터 순서열은 [9,6,2]이다.

  3. 원형에서는 A의6을 읽고 B의2를 읽으면 다음이 A이다. 다음 노드가 출발점 A이면 한 바퀴를 마친다.

  4. 원형 순회가 null을 기다리면 A와 B를 계속 반복한다. 빈 원형은 별도 head=null 계약으로 시작 자체를 건너뛴다.

단일 머리 삽입은 링크 두 번의 정상 갱신으로 [9,6,2]를 만든다. 원형의 한 바퀴 결과 [6,2]에는 시작 노드를 다시 읽지 않는다.

조건을 바꾸어 비교하기

값 반복과 노드 반복의 차이

A(7)→B(7)→C(9)→A에서 한 바퀴를 읽는다. 값이 처음 값과 같으면 멈추는 방식과 정체성 방식은?

  1. 시작 A를 읽으면 값은 7이다.

  2. 다음 B도 값은 7이지만 B≠A이므로 계속 읽어야 한다.

  3. C를 읽은 뒤 next=A에서 한 바퀴가 끝난다.

정상 결과는 [7,7,9]다. 다음 값 7을 보고 먼저 멈추는 변형은 [7]만 얻는다.

비교할 점

base의 서로 다른 값 예제와 달리 값 비교가 구조 경계를 대신하지 못함을 드러낸다.

옛 next를 잃은 역전

A→B→C→null에서 먼저 A.next=null을 쓰고 cur=A.next로 이동했다. 원래 두 나머지 노드를 처리할 수 있는가?

  1. 대입 후 A.next는 null이다.

  2. 그 필드에서 다음 노드를 읽으면 cur=null이 되어 B에 가는 경로를 잃는다.

  3. 옛 A.next=B를 saved에 먼저 담았으면 처리된 A와 미처리 B를 모두 유지한다.

head 외에 B를 보존한 별도 참조가 없다면 이 절차는 나머지 사슬을 처리하지 못한다.

비교할 점

역전 자체의 값 교환보다 다음 경로 보존이 먼저다.

종이와 본문으로 직접 해보기

head→A→B→C→null에서 이미 P=B를 알고 새 U를 B뒤에 넣어라. 데이터 순서를 적고, P를 위치1로만 알려 주었을 때 추가 작업을 설명하라.

힌트 보기

P.next의 옛값 C를 먼저 U.next에 담는다. 위치 숫자만 있으면 head에서 링크를 따라가야 한다.

풀이 보기

U.next=C 뒤 B.next=U로 A→B→U→C→null이다. head에서 위치1의 B를 찾으려면 A.next 한 번을 따라간다. 일반 위치 i의 탐색 비용과 삽입 링크 변경을 합해서 계산해야 한다.

오해와 반례

연결 리스트이면 모든 삽입·삭제·위치 접근이 O(1)이다.

이미 필요한 노드와 연결 정보를 가진 경우의 링크 변경만 상수 개수이다. 위치 i 접근은 보통 링크를 순차적으로 따라가며, 단일 리스트 끝 삭제는 tail을 알아도 선행 노드를 찾을 수 있다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

n개의 단일 선형 노드를 한 번에 역전하는 것과 매번 head에서 위치 i를 새로 찾는 n번의 접근을 비교하라. 링크 이동만 센다.

힌트 1

한 번 순회는 노드당 다음 링크 하나다.

힌트 2

위치 0부터 n−1까지 찾는 이동 수를 더한다.

풀이와 답 확인

  1. 역전은 옛 next를 n번 보존하고 각 노드 next를 한 번 바꾼다.

  2. 위치별 새 탐색의 이동은 0+1+…+(n−1)=n(n−1)/2다.

정상 n≥1에서 순회 역전은 Θ(n), 위치별 새 탐색은 n≥2에서 Θ(n²)다.

소단원 4.2

센티널과 경계조건

빈 줄에도 표지판 하나를 남기면 첫 사람과 마지막 사람의 연결을 더 단순하게 만들 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 센티널 S는 데이터 원소가 아닌 경계 표지 노드이다. 값이 있어 보여도 사용자 목록에 포함하지 않는다.

  • 이중 원형에서는 각 노드가 next와 prev를 가지며 서로 반대 방향 경로를 유지한다.

  • 자가진단: 빈 이중 원형 센티널은 S.next=S, S.prev=S이고 데이터 개수0이다. S를 데이터 하나로 세지 않는다.

학습 목표

  • 센티널 포함 표현 불변식과 데이터 개수를 구별한다.

  • 빈·하나·여러 노드 삽입과 삭제를 같은 관계로 추적한다.

  • 센티널 제거 금지와 여전히 필요한 유효성 검사를 설명한다.

여러 노드를 옮길 때 링크 여섯 번만 바꾸면 모든 비용이 끝날까?

이중 원형 센티널 S의 데이터 순서는 A,B,C,D이고 센티널 T의 순서는 X,Y다. S의 연속 구간 B,C를 T의 Y 앞에 옮긴다. P=A, W=D, Q=X, V=Y와 구간 양끝 B,C를 모두 살아 있을 때 보존한다. P.next=W; W.prev=P로 원래 링에서 구간을 떼고 B.prev=Q; C.next=V; Q.next=B; V.prev=C로 목표의 인접 이웃 사이에 잇는다. 완료 상태는 S의 A,D와 T의 X,B,C,Y다.

이 여섯 필드 대입은 구간이 실제 연속이고 두 링이 서로 겹치지 않으며 목표 위치가 구간 밖이라는 전제 아래의 변경 비용이다. 구간 길이 k=2를 이미 알고 있으면 nS는 4에서 2, nT는 2에서 4로 고친다. 길이를 모르면 직접 k를 세는 비용이 추가된다. 노드마다 owner 센티널을 저장하는 표현은 B와 C의 owner도 바꿔야 하므로 k개의 갱신이 더 필요하다. 링크가 상수라고 멤버십 검사·길이 계산·소유자 갱신까지 상수라고 말하지 않는다.

센티널이 포함된 구조체를 단순 필드 복사하는 것도 경계를 복제하는 안전한 방법이 아니다. 빈 센티널 S에서 S.next=S, S.prev=S를 새 T의 두 필드로 복사하면 T.next=S, T.prev=S다. T가 자기 자신을 가리키지 않아 독립 빈 링이 아니다. 기존 S의 수명 종료 후 그 링크를 읽는 문제까지 생길 수 있다. 빈 새 링은 T.next=T, T.prev=T로 다시 초기화하고, 비어 있지 않은 링의 복제·이동은 별도 계약으로 설계한다.

먼저 확인할 개념
  • 센티널 포함 표현 불변식

    두 이웃을 이어 붙이고 센티널을 데이터에서 제외하는 계약을 사용한다.

  • 알려진 위치와 탐색 비용

    링크 변경과 구간·목표 위치를 찾는 작업을 분리한다.

센티널은 실제로 존재하는 경계다

이 단원은 S를 포함하는 이중 원형 리스트를 선택한다. S.next는 첫 데이터 또는 S, S.prev는 마지막 데이터 또는 S이다. 전체 링에서 v.next.prev=v, v.prev.next=v가 성립하고 S를 제외한 각 데이터 노드를 한 번씩 만나 다시 S에 돌아오는 것을 불변식으로 정한다.

n은 S를 제외한 데이터 노드 수이다. 비어 있으면 S의 두 링크가 자기 자신으로 간다. 이 때문에 빈 상태도 null 링크를 직접 따라갈 필요가 없다. 다만 S 자체가 살아 있는 올바른 노드여야 하며 다른 리스트의 S를 섞어 쓰면 이 관계의 전제를 위반한다.

삽입은 두 이웃 사이를 연결한다

서로 인접한 살아 있는 노드 P와 W 사이에 새로 준비한 U를 넣는다고 하자. P.next=W와 W.prev=P가 먼저 성립하고 U가 현재 링에 속하지 않는다고 가정한다. U.prev=P; U.next=W; P.next=U; W.prev=U로 네 링크를 바꾸고 n을1 늘린다.

첫 삽입에서는 P와 W가 둘 다 S인 같은 노드이다. 두 대입이 S의 서로 다른 필드 next와 prev를 바꾸므로 결과는 S↔U의 링이다. 중간 단계에서 불변식이 일시적으로 깨질 수 있으므로 이 절차는 외부 동시 관찰이 없는 순차 모형이며 동시 접근 안전성을 보장하지 않는다.

삭제도 두 이웃을 붙이지만 허용 대상을 검사한다

링의 데이터 노드 U를 지울 때 P=U.prev, W=U.next를 아직 U가 살아 있는 동안 얻는다. P.next=W; W.prev=P로 U를 우회하고 n을1 줄인다. U의 메모리를 해제할지는 소유권 계약의 별도 결정이며 다음 소단원에서 다룬다.

데이터 하나를 지우면 P=W=S라 S.next=S, S.prev=S로 빈 상태를 회복한다. 센티널 자체는 삭제 대상이 아니고 빈 상태에서 데이터 삭제 요청은 거절해야 한다. 센티널을 둔다고 노드 멤버십·수명·할당 실패·개수 경계 검사가 없어지는 것은 아니다.

구간 이식의 두 방향 감사

위 이동의 정방향과 역방향 순서를 각각 적어라.

  1. S는 A.next=D와 D.prev=A로 A,D만 남는다.

  2. 목표는 X.next=B, B.prev=X, C.next=Y, Y.prev=C이고 내부 B.next=C와 C.prev=B는 유지된다.

  3. T에서 정방향 X,B,C,Y, 역방향 Y,C,B,X다.

S의 역방향은 D,A이며 nS=2, nT=4다.

노드 소유권·해제

목록에서 연결선을 지웠으면 메모리도 사라진 걸까? 메모리를 지운 뒤 다음 연결선은 어디서 읽을까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 링에서 제외하는 unlink와 동적 저장소를 반납하는 free는 서로 다른 작업이다.

  • malloc이 성공해 준 노드 시작주소만 해당 소유권 계약에 따라 한 번 free한다. 실패는 null로 처리한다.

  • 자가진단: A.next=B라는 링크가 있다고 free(A)가 B까지 자동으로 해제하지는 않는다.

학습 목표

  • 도달 가능성·소유권·별칭의 차이를 구분한다.

  • 해제 전에 next를 저장하는 정상 순서의 이유를 설명한다.

  • 비소유·순환·공유 구조에 일반 해제 루프를 적용할 수 없는 이유를 설명한다.

목록에서 떼어낸 살아 있는 노드를 누가 마지막으로 해제할까?

단독 소유 리스트 A→B→C→null에서 B를 추출하는 API를 정의하자. A.next=C로 우회하고 B.next=null로 분리한 뒤, B의 해제 책임을 호출자에게 넘긴다. B는 사라진 것이 아니라 살아 있는 독립 노드다. 리스트 파괴는 이제 A와 C만 해제하며 호출자가 B를 한 번 해제해야 전체 저장소가 정리된다. 추출과 즉시 파괴를 같은 API로 혼용하면 빌린 참조와 소유 책임을 잘못 판단한다.

외부에 빌린 q=B가 있으면 B가 추출되었다는 사실만으로 q의 대상 수명이 끝나지는 않는다. 새 소유자가 B를 해제하는 순간 대상 수명이 끝난다. C11 초안에서 그 대상 또는 바로 다음을 가리킨 포인터 값은 불확정이 되므로 낡은 q를 비교·출력·역참조해 검증하는 절차를 만들지 않는다. 무효화 통지는 해제 전에 계약으로 해결하고 독립 저장 변수 q=null을 덮어쓰는 것은 다른 별칭을 자동으로 바꾸지 않는다.

독립 복제가 필요하면 링크 주소만 복사하지 말고 새 노드를 준비한다. 원본 A,B,C의 세 int 값을 복제하다 두 번째 할당에서 실패하면 이미 준비한 첫 새 노드 U만 해제하고 실패를 반환한다. 원본 링크·값은 그대로 유지한다. 새 목록을 호출자에게 공개하기 전까지 임시 사슬을 별도로 소유하는 것이 실패 원자성의 근거다. 이 절은 실제 malloc 실패 주입이나 C 실행 없이 저장소 이름과 수명 계약을 손으로 추적한다.

소유권은 포인터 화살표와 별도의 계약이다

이 소단원의 단일 선형 리스트는 리스트가 각 데이터 노드를 단독 소유하고, 각 노드는 따로 성공한 malloc로 할당되었으며, next가 유한한 서로 다른 노드 사슬로 null에 끝난다고 가정한다. 외부 포인터는 빌린 별칭이고 노드 수명 연장 권리가 없다. 노드 안 데이터는 int라 추가 동적 자원이 없다.

이 가정 아래 노드를 지울 책임은 리스트에 있다. 링크에서 빼기만 하면 동적 저장소가 계속 할당되어 누수가 될 수 있다. 반대로 연결을 남기고 먼저 free하면 남은 링크는 수명이 끝난 노드를 가리켜 뒤의 접근을 정당화할 수 없다. 먼저 살아 있는 동안 연결을 갱신하고 해제해야 한다.

전체 해제는 다음 주소를 먼저 읽는다

<stdlib.h>가 포함되고 head와 Node형이 선언된 아래 조각은 계약을 만족하는 리스트 전체를 해제하는 종이 예시이다. next=head->next는 현재 노드가 살아 있을 때 수행하고 free(head) 뒤에는 옛 노드의 필드를 읽지 않는다. 이어 head=next로 다음 살아 있는 노드 또는 null을 넣는다.

free 뒤 head=head->next 순서라면 이미 없어진 객체의 필드를 읽으므로 미정의동작이다. 다음 주소가 자기 자신이거나 이미 해제할 다른 소유 노드를 반복하면 이 루프도 안전하지 않다. 유한 비순환·노드별 한 번 소유 가정이 단순한 해제 루프의 중요한 전제이다.

while (head != NULL) {
    Node *next = head->next;
    free(head);
    head = next;
}

빌린 별칭과 센티널은 따로 처리한다

외부 alias가 해제될 노드를 가리키고 있었다면 그 대상 수명 종료로 값이 불확정이 된다. head를 다음 노드로 옮겨도 alias는 함께 갱신되지 않는다. 삭제 API는 빌린 노드 참조를 언제 무효화하는지 명시해야 한다. 모든 별칭을 찾아 자동 null로 만드는 동작을 C가 제공하지 않는다.

센티널이 자동 지역 또는 리스트 구조체에 포함된 객체라면 malloc가 반환한 독립 저장소가 아니므로 free(S)는 허용되지 않는다. 동적 센티널이라도 데이터와 구분해 수명 끝에 한 번 해제한다. 노드가 문자열 버퍼를 별도로 소유하면 그 자원의 해제 정책도 추가해야 하고, 공유 노드는 단독 소유 가정에 맞지 않는다.

노드 이름은 수명 추적용 종이 식별자다. 마지막 행에서 낡은 C 포인터 값을 실제 읽어 이름을 확인하는 동작을 뜻하지 않는다. 모든 노드는 독립 성공한 동적 할당, int 데이터, 단독 소유라는 전제다.

중간 과정을 따라가는 예제

head→A→B→null인 두 독립 할당 노드를 위 루프로 해제한다. A·B는 단독 소유, 중복링크 없음, int 데이터만 있다. 아직 살아 있는 노드 집합과 head의 다음 값을 적는다.

  1. 처음 살아 있는 집합은 {A,B}이다. 첫 조건은 참이고 next=A.next=B를 A가 살아 있는 동안 저장한다.

  2. free(A)는 A의 수명을 끝낸다. next는 살아 있는 B를 가리킨다. head=next로 B를 넣으며 낡은 A값을 읽지 않는다.

  3. 둘째 조건은 참이고 next=B.next=null을 먼저 저장한 뒤 free(B), head=null을 수행한다.

  4. 조건이 거짓이 되어 종료한다. 살아 있는 데이터 노드 집합은 공집합이고 A·B를 각각 한 번 해제했다.

해제 순서는 A, B이며 최종 head=null이다. 이것은 표준 계약에 따른 종이 증명으로 실제 메모리 진단 결과가 아니다.

  1. A.next=C, B.next=null로 먼저 링크를 분리한다.

  2. 리스트는 살아 있는 next를 보존하며 A와 C를 해제한다.

  3. 호출자가 소유한 B를 한 번 해제한다.

순서는 A,C,B이고 각 노드 한 번, 총 세 번이다.

두 번째 복제 할당의 실패

A,B,C를 독립 복제하다 U 하나를 준비한 뒤 다음 할당이 실패했다. 원본 보존 계약을 만족하는 정리는?

  1. 원본 next를 바꾸지 않고 U를 임시 사슬로 소유한다.

  2. 실패한 할당은 새 노드를 만들지 않는다.

  3. 준비한 U만 한 번 해제하고 공개할 새 목록을 만들지 않는다.

추가 성공 할당 1개와 정리 해제 1개, 원본의 살아 있는 세 노드는 그대로다.

비교할 점

원본의 머리와 임시 복제의 머리를 같은 변수로 덮지 않아 실패 원자성을 지킨다.

종이와 본문으로 직접 해보기

한 노드 A.next=null에 외부 빌린 alias=A가 있다. A를 해제하고 head=null로 바꾼 뒤 alias->value를 읽거나 free(alias)를 다시 호출하는 두 독립 변형을 분류하라.

힌트 보기

head의 새 대입과 alias 저장값은 별도이다. 두 번째 free는 첫 해제 이후라는 시간 조건을 사용한다.

풀이 보기

head=null이 되어도 alias의 대상 수명은 끝났다. alias->value 읽기는 해제 후 접근이므로 허용되지 않고, free(alias)로 같은 저장소를 다시 해제하는 시도도 정상 계약을 위반하여 미정의동작이다. 낡은 alias를 검사·출력·역참조하거나 두 번째 free를 실제 실행하지 않았다.

오해와 반례

free는 노드가 가리킨 모든 노드까지 지우고, head=null이면 다른 별칭도 안전해진다.

free는 해당 할당 저장소 한 개를 반납하며 next 사슬을 순회하지 않는다. 외부 alias는 자동 갱신되지 않는다. 연결 제거·각 저장소 해제·빌린 참조 무효화는 계약에서 각각 설명해야 한다.

노드별 일정 작업 모형에서 O(n)이고 추가 포인터 변수 공간은 O(1)이다.

각 노드를 한 번 방문·해제한다. 할당기 실제 지연이나 외부 소유 데이터 정리 비용은 이 모형에서 별도이다.

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

B 추출 직후 빌린 q=B의 대상은 아직 살아 있다. q로 읽는 것이 자동으로 수명 밖 접근인가?

힌트 1

추출 API는 free하지 않는다고 명시했다.

힌트 2

소유 책임과 읽기 허가를 구별한다.

풀이와 답 확인

  1. 객체 수명은 계속된다.

  2. 새 소유자의 계약이 읽기를 허용하는 동안만 빌린 접근이 가능하며 소유 권한은 생기지 않는다.

추출 자체는 수명 종료가 아니다. 이후 파괴나 계약상 무효화 시점은 별도로 지킨다.

흔한 오답에서 다시 생각하기

링크에서 빠지면 어떤 포인터 접근도 즉시 UB다.

C의 객체 수명과 자료구조의 멤버십은 같은 개념이 아니다.

연습 2 · 오류 찾아 고치기

A가 공유된 사슬의 머리이고 두 소유자가 A→B를 각각 파괴한다. 두 번째 파괴도 next를 먼저 저장하면 안전한가?

힌트 1

첫 파괴가 A와 B의 수명을 끝낸다.

힌트 2

저장 순서 이전에 대상 생존 전제를 검사한다.

풀이와 답 확인

  1. 두 번째 절차의 첫 필드 읽기부터 살아 있는 노드라는 전제가 없다.

  2. next 저장 순서는 중복 소유를 해결하지 못한다.

안전하지 않다. 공유 소유 정책을 새로 설계하거나 단독 소유만 허용해야 한다. 실제 UB를 실행하지 않는다.

흔한 오답에서 다시 생각하기

해제 전 next 저장은 모든 공유 그래프를 안전하게 만든다.

증명은 아직 살아 있는 서로 다른 단독 소유 노드의 사슬에 제한된다.

연습 3 · 직접 만들어 보기

추출 API가 B를 반환한 뒤 호출자가 원래 리스트 파괴와 자신의 B 파괴를 모두 수행할 때 중복 해제를 막는 완료 계약을 적어라.

힌트 1

링크 도달 집합에서 B를 제거한다.

힌트 2

해제 책임을 한 곳으로 옮긴다.

풀이와 답 확인

  1. 리스트의 완료 사슬은 A→C→null이고 소유 집합은 {A,C}다.

  2. B.next=null이며 반환 시 호출자가 B를 단독 소유한다. 리스트 파괴는 B를 방문하지 않는다.

반환된 B의 생존·분리·유일한 새 소유 책임을 함께 명시한다.

흔한 오답에서 다시 생각하기

반환 주소가 있으므로 소유자는 둘이어도 된다.

포인터 수와 해제 책임 수는 같지 않으며 책임은 중복되면 안 된다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

정상 복제의 세 할당이 모두 성공했을 때 원본과 새 사슬을 각각 파괴한다. int 데이터만 있고 원본 3개·새 노드 3개가 독립 저장소다. 총 해제 수와 별칭 계약은?

힌트 1

주소 복사가 아니라 독립 노드 복제다.

힌트 2

각 목록의 소유 집합을 분리한다.

풀이와 답 확인

  1. 각 목록은 세 노드를 한 번씩 해제하여 총 6개 저장소를 해제한다.

  2. 원본 노드에 빌린 참조는 새 노드를 가리키도록 자동 변경되지 않는다. 원본 해제 전에 그 무효화 정책을 정한다.

총 여섯 번이다. 값이 같아도 객체와 별칭 수명은 독립이다.

흔한 오답에서 다시 생각하기

같은 int 값이므로 세 번만 해제해도 된다.

값 동등성은 두 할당 저장소의 정체성이나 소유 책임을 합치지 않는다.

다른 문제에 적용하기

S의 이중 원형 데이터가 A(7),B(7),C(9),D(4), T는 X(2),Y(5)다. 검증된 연속 구간 B,C를 Y 앞에 옮기고 노드별 owner도 갱신한다. 정방향·역방향·개수와 owner 변경 수를 적어라. 이동 뒤 T를 단독 소유 목록으로 파괴하되 B를 먼저 추출하여 호출자에게 넘긴다. 각 소유 집합과 최종 해제 횟수를 적고, T의 빈 자기 링크를 새 R에 필드 복사해도 되는지 설명하라. 모든 연산은 순차 모형이며 각 노드는 독립 동적 할당이고 데이터는 int다.

힌트 1

이동 전 구간의 양끝과 양쪽 이웃을 보존하고 전체 데이터 수를 유지한다.

힌트 2

추출은 free가 아니며 T의 센티널은 구조체에 포함된 객체라 데이터 파괴에서 해제하지 않는다.

풀이와 답 확인

  1. 이동 후 S는 A,D이며 역방향 D,A이고 nS=2다. T는 X,B,C,Y이며 역방향 Y,C,B,X이고 nT=4다. 두 owner 변경은 B와 C에 수행한다.

  2. B 추출 뒤 T는 X,C,Y로 nT=3이고 B.next와 B.prev를 null로 분리한다. T가 소유한 X,C,Y와 호출자가 소유한 B는 겹치지 않는다.

  3. T 파괴는 X,C,Y 세 번, 호출자 B 파괴는 한 번, S 파괴는 A,D 두 번으로 총 데이터 저장소 여섯 개를 한 번씩 해제한다. 각 빌린 별칭은 해당 대상 파괴 전에 정책에 따라 무효화한다.

  4. 빈 T의 자기 링크를 새 R에 복사하면 R의 링크는 T를 가리킨다. 독립 빈 링에는 R.next=R, R.prev=R 초기화가 필요하며 포함 센티널 T/R은 free하지 않는다.

여섯 링크 변경과 두 개수 변경만으로 owner 갱신·멤버십 검사의 비용까지 상수라고 할 수 없다. 값 7을 가진 A와 B도 다른 노드다. 분리·책임 이전·파괴·센티널 초기화를 각각 계약으로 검산한다.

해결한 뒤 점검할 것

  • 두 링의 정역방향과 합계 데이터 수 6을 확인한다.

  • owner 두 필드 갱신과 링크 변경의 비용 범위를 분리한다.

  • 추출 B와 T/S의 데이터 소유 집합이 서로 겹치지 않도록 한다.

  • 데이터 여섯 번 해제와 포함 센티널의 비해제 및 새 자기 링크 초기화를 구별한다.
