소단원 2.1

시간·공간 복잡도

카드가 두 배가 되면 카드끼리 비교하는 일도 두 배일까?

준비 개념과 학습 목표

준비 개념

  • 입력 크기 n: 여기서는 배열에 들어 있는 항목 개수다. 인덱스는 0부터 n−1까지이며 빈 배열은 n=0이다.

  • 비용 단위: 무엇을 한 번으로 셀지 정한 뒤 비교한다. 카드 비교 횟수와 CPU 초는 같은 단위가 아니다.

  • 합 미니복습: 1+2+3+4=10이다. 연속된 정수의 합은 첫째와 마지막을 짝지어 유도할 수 있다.

  • 이 단원의 for i=a..b는 정수 i를 작은 값부터 하나씩 늘리며 양 끝을 포함한다. a>b이면 반복은0회다. 따라서 빈 배열이나 마지막 항목 뒤의 빈 범위를 역순 순회하지 않는다.

학습 목표

  • 입력 크기와 비용 모형을 먼저 명시한다.

  • O·Ω·Θ의 양화 조건을 구별한다.

  • 총 작업량과 동시에 필요한 공간을 따로 센다.

같은 모든 쌍을 출력해도 메모리에 동시에 남는 양은 같을까?

서로 다른 n개 항목의 모든 위치 쌍 (i,j), i<j를 내보낸다. 여기서는 중복 값 탐색처럼 첫 일치에서 반환하지 않는다. 쌍 개수는 n(n−1)/2이고, 인덱스와 항목이 상수 개 워드에 들어간다는 모형에서 각 쌍 생성은 상수 비용이다. 시간은 n≥2에서 Θ(n²)지만 무엇을 저장하는지에 따라 공간은 달라진다.

한 쌍씩 즉시 소비하는 외부 소비자에게 넘기고 소비자가 누적 저장하지 않는 스트리밍 계약은 생산자의 보조 공간이 Θ(1)이다. 모든 쌍을 생산자 배열에 보존하는 계약은 결과 공간만 Θ(n²)이다. 입력 포함 총 공간은 각각 Θ(n)과 Θ(n²)다. 소비자나 통신 큐가 결과를 계속 쌓으면 그 시스템 전체 공간을 상수라고 주장할 수 없다.

비용 표기는 대상 함수와 모든 충분히 큰 입력을 함께 정한다. C(n)이 짝수 n에서는 n, 홀수 n에서는 n²라면 전체 양의 정수 영역에서 O(n²)이고 Ω(n)이지만 Θ(n)도 Θ(n²)도 아니다. 큰 값 몇 개나 한 부분수열만으로 타이트한 양쪽 경계를 확정하지 않는다. 또한 비교 대상이 길이 b인 비트열이면 처음 b−1비트가 같은 비교에서 마지막 비트까지 읽는 모형의 비용 b를 따로 곱해야 한다.

먼저 확인할 개념
  • 대상 비용함수와 Word-RAM

    최선/최악과 O/Ω/Θ를 혼동하지 않고 단위 비용 조건을 선언한다.

  • 공간의 포함 범위

    입력·보조·결과 저장을 분리한 base 정의를 사용한다.

세는 연산을 고정한다

아래 절차는 배열의 같은 값을 가진 서로 다른 두 위치가 존재하는지 검사한다. 각 항목은 한 word에 들어가고 주소 접근·비교·인덱스 연산은 상수 시간이라고 가정한다. 임의 크기 정수나 긴 문자열 비교는 길이에 따라 비싸므로 이 가정을 그대로 적용할 수 없다. 성공하면 즉시 반환하며 서로 다른 값만 있을 때 모든 쌍을 검사한다.

최악 입력에서는 i마다 뒤의 n−1−i개와 비교해 비교 횟수 C(n)=n(n−1)/2다. n=0 또는1이면0이다. 반복 제어·입력 확인 등까지 포함한 총 시간 T(n)은 n≥2에서 Θ(n²)지만 C 자체와 정확한 초 단위 시간을 같다고 부르지 않는다.

has_pair(A,n):
  for i=0..n-1:
    for j=i+1..n-1:
      if A[i]==A[j]: return true
  return false

증가의 상한과 하한

비음수 비용 T와 양의 비교 함수 g에 대해 T∈O(g)는 상수 c>0,n₀가 있어 모든 n≥n₀에서 T(n)≤cg(n)이라는 뜻이다. Ω는 T(n)≥cg(n)인 하한이고 Θ는 두 조건을 모두 만족한다. 유한한 작은 n의 예외와 상수 계수는 허용하지만 어떤 n을 기준으로 하는지 숨기지 않는다.

n≥2에서 n²/4≤n(n−1)/2≤n²/2이므로 C∈Θ(n²)다. Θ(n)인 7n+9도 O(n²)에 속한다. 따라서 O 표기는 항상 가장 타이트한 분류를 의미하지 않는다. 같은 증가율이어도 캐시·할당·상수·입력 구조에 따른 실측 시간은 다를 수 있다.

공간은 동시에 살아 있는 자료로 센다

이 절차는 i,j와 반환값 등 상수 개 word만 추가로 필요하므로 보조 공간은 Θ(1)이다. 입력 배열까지 포함하면 총 공간은 Θ(n)이다. 결과 배열을 만드는 경우 출력 포함 여부도 명시해야 한다. 반복문 안에서 항목을 한 번 읽을 때마다 새 메모리 한 칸이 영구히 생기는 것은 아니다.

word-RAM은 접근할 메모리 주소가 word에 들어가는 크기를 전제한다. 물리 컴퓨터에서 n을 끝없이 늘릴 수 있다는 주장이 아니다. 비트 복잡도나 외부 저장장치 I/O 비용을 분석하려면 다른 단위와 모형을 선택한다.

같은 모든 쌍을 출력해도 메모리에 동시에 남는 양은 같을까?
n=5의 생산자생성 쌍동시에 저장한 결과입력 포함 공간

즉시 소비

10개

한 쌍

입력 5개와 상수 상태

결과 보존

10개

10쌍

입력 5개와 결과 10쌍

쌍 수는 누적 작업량이며 마지막 두 열은 동시에 살아 있는 저장량이다. 행의 저장 계약과 소비자 범위를 먼저 읽는다. 실제 초나 물리 메모리 바이트를 측정한 표가 아니다.

중간 과정을 따라가는 예제

A=[2,5,8,11]에서 값 비교만 한 번당 비용1로 센다. 비교 횟수와 보조 공간을 구하라.

  1. i=0에서 (0,1),(0,2),(0,3)의3회 비교는 모두 다르다.

  2. i=1에서 (1,2),(1,3)의2회, i=2에서 (2,3)의1회가 남는다.

  3. 총3+2+1=6이며 n(n−1)/2=4×3/2와 같다. false를 반환한다.

  4. 두 인덱스와 상수 임시 자료만 동시에 필요하다. 입력4칸과 보조 공간의 계수를 구별한다.

값 비교6회, 반환값 false, 보조 Θ(1) word/입력 포함 Θ(n) word다.

조건을 바꾸어 비교하기

출력 계약이 바꾸는 공간

n=5의 모든 쌍을 즉시 소비하거나 끝에 한꺼번에 반환한다. 생성 수와 생산자 공간을 비교하라.

  1. 쌍 수는 4+3+2+1=10으로 두 방식에서 같다.

  2. 즉시 소비는 현재 쌍과 반복 인덱스만 유지한다.

  3. 끝 반환은 열 쌍의 저장 배열을 유지한다.

생성 수는 같고 결과 보존 방식만 Θ(n²) 결과 공간을 요구한다.

비교할 점

base의 boolean 탐색과 달리 전체 출력 자체가 결과 공간을 요구할 수 있다.

한 부분수열만으로 잡지 못하는 Θ

짝수에서 n, 홀수에서 n²인 C(n)의 전역 성장률을 조사하라.

  1. 항상 n≤C(n)≤n²이므로 Ω(n), O(n²)다.

  2. 홀수에서 C(n)/n=n이 무한히 커져 O(n)이 아니다.

  3. 짝수에서 C(n)/n²=1/n이 0으로 가므로 Ω(n²)이 아니다.

전체 영역에서 Θ(n)도 Θ(n²)도 아니다.

비교할 점

서로 다른 입력 크기의 경계를 하나의 타이트한 표기로 단정하지 않는다.

종이와 본문으로 직접 해보기

A=[4,4,7,9]와 서로 다른8개 항목을 각각 추적하라. 두 경우를 모두 최악 시간의 정확한 횟수라고 부를 수 있는가?

힌트 보기

첫 배열에서는 첫 쌍에서 멈춘다. 둘째 배열에서는7+6+…+1을 센다.

풀이 보기

첫 배열은 (0,1) 한 비교로 true다. 둘째는28회 뒤 false다. 조기 종료 입력의1회는 최악 입력의 횟수가 아니며 n이4에서8로 늘어날 때 최악 비교는6에서28로 변한다.

오해와 반례

반복이 n²회면 메모리도 n²칸이 필요하다.

두 인덱스를 재사용하는 위 절차는 최악 Θ(n²) 시간에 보조 Θ(1) 공간이다. 모든 쌍을 출력 배열에 저장하도록 바꾸면 출력 공간은 Θ(n²)가 되므로 절차와 출력 계약이 중요하다.

자기점검

서로 다른5개 값의 쌍 비교 횟수는?

답과 이유 보기

10회.

4+3+2+1=5×4/2다.

7n+9는 O(n²)인가, Θ(n²)인가?

답과 이유 보기

O(n²)이지만 Θ(n²)는 아니다.

n≥1에 7n+9≤16n≤16n²이나 (7n+9)/n²은0으로 가서 양의 이차 하한은 없다.

입력 배열을 제외하고 공간을 셌다면 무엇을 명시해야 하는가?

답과 이유 보기

보조 공간이라는 기준과 단위 word를 명시한다.

총 공간과 출력 공간의 포함 여부가 바뀌면 같은 절차의 보고값도 달라진다.

연습 2 · 오류 찾아 고치기

즉시 소비 생산자의 Θ(1) 보조 공간에서 외부 소비자가 모든 쌍을 저장한다. 시스템 전체도 Θ(1)인가?

힌트 1

생산자와 소비자의 범위를 구분한다.

힌트 2

결과 저장을 포함한다.

풀이와 답 확인

  1. 소비자 결과는 n(n−1)/2쌍이다.

  2. 전체 입력과 결과를 포함하면 Θ(n²)다.

생산자의 보조 공간만 상수다.

흔한 오답에서 다시 생각하기

호출자가 저장하므로 비용에서 영원히 제외된다.

측정 경계를 선언하지 않은 시스템 전체 주장은 성립하지 않는다.

연습 3 · 직접 만들어 보기

짝수/홀수 C(n)에 대해 O(n²)와 Ω(n)의 구체 상수를 제시하라.

힌트 1

양의 정수 n에서 n≤n²다.

힌트 2

두 가지를 각각 넣는다.

풀이와 답 확인

  1. 모든 n≥1에 C(n)≤1·n²이고 C(n)≥1·n이다.

두 상수 모두 1, 시작 기준은 n₀=1로 잡을 수 있다.

흔한 오답에서 다시 생각하기

O(n²)이면 반드시 Θ(n²)다.

짝수 부분수열의 하한 실패를 별도로 확인한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

모든 쌍의 b비트 값 비교가 각 쌍에서 마지막 비트까지 진행한다고 선언했다. 비트 검사 수는?

힌트 1

쌍마다 b번 읽는다.

힌트 2

한 워드 비교와 다른 모형이다.

풀이와 답 확인

  1. 각 비교는 b번, 쌍은 n(n−1)/2개다.

정확히 b·n(n−1)/2번이며 n≥2에서 Θ(bn²)다.

모든 ==는 입력 길이와 무관하게 상수다.

이 과제는 비트별 검사 모형을 명시했으며 Word-RAM의 상수 개 워드 조건과 다르다.

내 말로 설명하기

공간을 시간처럼 누적해서 세는가?

설명 기준 확인

공간은 동시에 유지되는 자료를 센다. 결과 보존 계약이면 누적 결과가 실제 살아 있다.

부분수열 하나의 Θ가 전체 영역의 Θ인가?

설명 기준 확인

아니다. 모든 충분히 큰 허용 입력 크기의 상한과 하한을 확인해야 한다.

한 단계 더

심화: 앞의 쌍 수를 직접 유도하라. S=(n−1)+(n−2)+…+1을 역순과 더하면 n이 n−1번 나와2S=n(n−1)이다. 중복이 없는 입력에서는 검사 가능한 모든 쌍을 방문하므로 이 절차의 비교 수 하한도 같은 값이다. 이것은 모든 가능한 중복 탐지 알고리즘의 하한 증명이 아니다. 다른 자료구조나 정렬을 선택하면 비용이 바뀐다.

소단원 2.2

최악·평균·분할상환 구분

가끔 길게 멈추는 배열 삽입을 평균적으로 빠르다고 말할 때, 어떤 평균일까?

준비 개념과 학습 목표

준비 개념

  • 연산열: 삽입을1번,2번,…차례로 수행한 전체 기록이다. 한 번의 비용과 여러 번의 총비용은 다르다.

  • 기댓값: 가능한 입력별 비용에 그 입력의 확률을 곱해 더한 값이다. 확률 분포를 지정하지 않으면 평균을 계산할 수 없다.

  • 용량: 실제 항목 수 n보다 크게 확보한 저장칸 cap이다. 이 예제는 처음 n=0,cap=1이며 꽉 차면2배로 늘린다.

  • 저장 배열 A는 cap칸을 갖고 앞의 n칸에 항목을 저장한다. 새 배열을 확보하는 작업은 성공한다고 가정하며, 확장 후 A를 새 배열로 바꾼다. 확보 실패·실제 해제 비용은 이 종이 비용 표의 범위 밖이다.

학습 목표

  • 최악·분포 평균·분할상환의 범위를 구별한다.

  • 동적 배열의 확장 비용을 연산열로 합한다.

  • 확률 없이 성립하는 총비용 상계를 증명한다.

확장 후 곧 축소하면 같은 항목을 몇 번 복사할까?

새 항목 쓰기와 기존 항목 복사만 각각 비용 1로 센다. 빈 배열의 두 배 확장 끝 삽입은 base의 총비용 상계를 갖는다. 그러나 시작 상태가 이미 n=8, cap=8인 배열이면 다음 삽입 한 번의 비용은 9다. m=1이라는 새 구간만 떼어 총비용<3m이라고 말하면 틀린다. 앞의 여덟 항목을 구축한 이력 또는 초기 상태의 준비 비용을 포함해야 한다.

삭제 비용은 마지막 항목 제거 1로 세고, 삭제 후 n=cap/2이면 즉시 cap/2로 축소하여 n개를 복사하는 잘못된 정책을 보자. n=4, cap=4에서 append 후 n=5, cap=8이며 비용 5다. 곧 pop하면 n=4가 되어 다시 cap=4로 축소하고 비용은 제거 1+복사 4=5다. 같은 왕복을 반복하면 매 두 연산마다 10이 든다. 일반 n=N, cap=N에서도 왕복은 2N+2라 연산 수만으로 상수 분할상환을 주장할 수 없다.

축소 기준에 간격을 둔다. 여기서는 n<cap/4일 때만 cap/2로 줄이는 정책을 선언하며 최소 cap=1을 지킨다. n=5, cap=8에서 한 번 pop하여 n=4로 돌아갈 때는 축소하지 않아 비용 1이다. 이후 append도 여유 칸을 사용하여 비용 1이다. 이는 임계값 간격의 효과를 보여 주는 작은 추적이지, 모든 API·할당기·마감 시간의 측정이나 완전한 혼합 연산열 증명은 아니다.

먼저 확인할 개념
  • 분할상환의 시작 상태

    전체 연산열의 초기 조건을 유지해야 총비용 상계를 적용할 수 있다.

  • 상태와 연산 경계

    n과 cap의 유효 상태 및 실패하지 않는 추상 연산 경계를 명시한다.

입력별 최악과 확률 평균

양의 정수 길이 n인 배열을 처음부터 순차 탐색하고 첫 일치에서 멈춘다고 하자. target이 마지막에 있거나 없으면 n번 비교해 최악 Θ(n)이다. 반드시 존재하고 위치가0..n−1에서 균등하다는 별도 모형에서는 비교 수의 기대값이 (1+…+n)/n=(n+1)/2다. 특정 위치가 흔하면 가중치가 달라진다.

평균 시간은 입력 분포 또는 알고리즘의 명시한 난수에 대한 기대값이다. 결과가 균등하지 않은 현실 로그에서 균등 평균을 곧바로 실측 평균이라고 부르면 안 된다. 최악은 가장 비싼 허용 입력을, 평균은 주어진 가중치를 보지만 둘 다 분석 단위를 먼저 정의한다.

append(x):
  if n==cap:
    B=allocate array of 2*cap slots
    for i=0..n-1: B[i]=A[i]
    A=B
    cap=2*cap
  A[n]=x
  n=n+1

확장 배열의 비싼 한 번

자체 배열에서 새 항목 쓰기1, 기존 한 항목 복사1을 비용 단위로 센다. 메모리 확보·해제·고정 관리 비용은 이 정확한 표에서 제외한다. 실제 할당 비용과 실패 계약은 구현에서 따로 필요하며, 용량에 선형인 초기화 비용을 포함해도 아래 점근 총비용은 상수 계수만 변한다. 꽉 찬 cap=k에서 삽입하면 k개를 복사한 후1개를 써 k+1 비용이 든다.

cap을1부터2,4,8,…로 두 배 확장하고 끝 삽입만 양의 정수 m번 한다. m=0이면 비용0이며 아래의 엄격한 부등식 대신 비용0으로 따로 센다. 복사한 개수는1+2+…+최종 확장 전 용량이고 그 합은2m보다 작다. 삽입 쓰기 m을 합해 총비용<3m이다. 이 증명은 입력이 어떤 확률을 따른다고 가정하지 않으며, 처음 상태와 확장 정책이 전제다.

분할상환은 매번의 마감 보장이 아니다

분할상환 O(1)은 허용한 전체 연산열의 총비용이 O(m)이라는 보장이다. 특정 삽입은 여전히 Θ(n)이다. 앞쪽 삽입은 항목 밀기가 있으므로 이 끝 삽입 계약의 결과를 그대로 적용할 수 없다. 이미 큰 배열에서 시작했다면 초기 구축 비용 또는 초기 잠재량도 포함해야 한다.

삭제 때마다 꽉 맞게 줄인 뒤 바로 다시 늘리는 정책은 큰 복사를 반복하게 할 수 있다. 확장과 축소의 임계값에 간격을 두는 이유다. 이 절의<3m은 삭제나 임의 연산을 포함한 무제한 라이브러리 성능 보장이 아니다.

소단원 2.3

재귀 호출과 스택 비용

재귀 함수가 천 번 호출되면 동시에 천 개의 호출이 항상 남아 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수 호출: 입력을 받아 계산하고 값을 반환한다. 재귀는 같은 함수를 더 작은 문제에 다시 호출하는 것이다.

  • 스택: 나중에 올린 항목을 먼저 내리는 구조다. 호출 프레임은 인자·복귀 위치·임시 상태 등을 담는 논리적 기록이다.

  • 기저 사례: 더 호출하지 않고 답을 주는 끝 조건이다. 감소하는 음이 아닌 정수로 종료를 설명할 수 있다.

학습 목표

  • 재귀의 정확성과 종료 조건을 함께 설명한다.

  • 전체 호출 수와 최대 동시 프레임 수를 구분한다.

  • 프레임 크기와 입력 복사·출력 비용 조건을 확인한다.

전체 호출 수가 많아도 현재 살아 있는 복사본은 작을 수 있을까?

음이 아닌 정수 d에 대해 G(d)는 d=0이면 반환하고 아니면 G(d−1)를 두 번 순차 호출한다. 전체 호출 수는 2^(d+1)−1이지만 최대 활성 프레임은 d+1이다. 여기서는 형제 호출을 병렬 실행하지 않으며, 한 자식이 끝난 뒤 다음 자식을 시작한다. 반환값은 필요하지 않아 지수 크기 정수를 저장하는 비용도 넣지 않는다.

공간 모형을 확장해 각 호출이 자기 길이 2^d의 새 버퍼를 만들고 두 자식이 끝날 때까지 유지한다고 정하자. d=0 버퍼도 길이 1이다. 가장 깊은 경로의 버퍼 합은 2^d+2^(d−1)+…+1=2^(d+1)−1이다. 입력 크기 n=2^d로 쓰면 버퍼 피크는 2n−1로 Θ(n)이며 호출 수가 Θ(n)이라도 버퍼 공간을 호출 수×최대 버퍼 크기로 계산하는 Θ(n²) 주장은 과대평가다.

다른 구현에서는 각 활성 호출이 깊이와 관계없이 처음 입력의 길이 n 전체를 복사한다. 같은 호출 트리라도 버퍼 피크는 n(d+1)=n(log₂n+1)이다. 두 구현은 버퍼 정책이 다르므로 비교해야 한다. 모든 노드에서 할당한 누적 버퍼 길이는 첫 구현에서도 각 깊이의 합 n이 d+1번 반복되어 n(d+1)이다. 누적 할당량과 동시에 살아 있는 양은 다르며, 실제 해제 시점이나 최적화는 이 가상 모형의 선언을 따라 계산한다.

먼저 확인할 개념
  • 호출 트리와 활성 경로

    base의 순차 호출과 종료된 형제 프레임 해제를 사용한다.

  • 자료의 소유권과 수명

    현재 호출이 가진 버퍼를 자식 종료까지 유지하고 반환 때 정리하는 모형을 선언한다.

각 호출은 자기 상태를 가진다

아래 S(A,k)는 배열 앞의 k개 합을 반환한다. 0≤k≤배열길이, 모든 중간 합이 선택한 word 정수 범위에 들어가는 조건을 둔다. A는 같은 배열 참조이며 호출마다 전체 배열을 복사하지 않는다. k=0이면0, 아니면 k−1개 합에 A[k−1]을 더한다.

정확성은 k에 대한 귀납으로 보인다. 빈 접두부 합0이 맞고 S(A,k−1)이 첫 k−1개 합이면 마지막 항목을 더한 결과는 k개 합이다. 매 호출에서 k가1 줄어0에 도달하므로 종료한다. 잘못된 음수 입력이나 k가 줄지 않는 변형은 이 증명의 범위 밖이다.

S(A,k):
  if k==0: return 0
  t=S(A,k-1)
  return t+A[k-1]

시간과 스택의 별도 점화식

한 word 덧셈·주소접근과 프레임 생성이 상수 비용이라고 두면 T(k)=T(k−1)+Θ(1), T(0)=Θ(1)이어서 Θ(k+1) 시간이다. 총호출은 k+1이고 덧셈은 k번이다. 아직 반환하지 않은 부모들이 기다리므로 최대 활성 프레임은 k+1, 보조 공간은 Θ(k+1) word다.

프레임당24바이트라고 가정하는 자체 기계에서는 최대24(k+1)바이트지만 이것은 실제 C ABI 측정이 아니다. 실제 컴파일러는 프레임 크기·레지스터·인라이닝·꼬리호출 최적화에 따라 달라진다. 이 S의 호출 뒤 덧셈은 꼬리호출이 아니며 일반 C가 재귀의 일정 깊이나 최적화를 보장하는 것도 아니다.

호출 트리의 총량과 현재 경로

음이 아닌 정수 d에 대해 B(d)는 d=0이면1을 반환하고 그렇지 않으면 B(d−1)를 두 번 순차 호출해 두 값을 더한다고 정의하자. 총호출 C(d)=1+2C(d−1), C(0)=1이라2^(d+1)−1이다. 그러나 깊이 우선 순차 실행에서 최대 활성 프레임은 d+1이다. 먼저 끝난 자식은 프레임이 해제된다. 이 호출 수는 제어 흐름을 센 값이다. 반환값2^d의 비트 길이나 덧셈 비용은 별도로 분석한다. 고정 word 비용/공간을 적용하려면 모든 중간 반환값이 해당 word에 들어가는 d 범위를 가정해야 한다.

형제 호출이 동시에 실행되는 병렬 모형이나 각 호출에서 큰 배열을 복사하는 구현은 공간 계산이 달라진다. 동일 부분문제를 저장하는 메모이제이션도 호출 수를 줄이는 대신 저장 공간을 추가한다. 전체 호출 그림의 모든 노드를 동시에 스택 메모리라고 세지 않는다.

힌트 2

누적 생성량을 마지막까지 유지한다.

2n−1 증명은 종료된 호출의 버퍼를 정리하는 전제를 사용했다.

아니다. 버퍼 길이·수명·순차 스케줄을 선언한 모형이다.

한 단계 더

심화: S를 반복으로 바꾸어 s=0에서 i=0..k−1 동안 s=s+A[i]로 계산하면 불변식 s=이미 읽은 i개 합이 성립한다. 같은 상수 word·범위 가정에서 시간 Θ(k+1), 보조 Θ(1)이다. 그러나 단순 반복 변환이 모든 재귀 트리에 이 공간 이득을 주는 것은 아니다. 일반 깊이 우선 순회는 명시적 스택에 미처리 복귀 상태를 보존해야 한다.

다른 문제에 적용하기

n=4의 모든 위치 쌍을 결과 배열에 보존하는 생산자와 즉시 소비 생산자를 비교하라. 반 채움 즉시 축소와 엄격한 1/4 아래 축소 배열에서 n=4,cap=4부터 append/pop 세 왕복의 항목 비용과 최종 상태를 계산하라. 마지막으로 d=3,n=8의 순차 이진 재귀에서 절반 버퍼와 전체 입력 복사 정책의 호출·프레임·피크·누적량을 비교하여 하나의 공간 수치로 합치면 안 되는 이유를 설명하라.

힌트 1

출력 보존 여부와 초기 상태, 제거 이후의 축소 기준을 먼저 정한다.

힌트 2

재귀 피크는 현재 경로이며 누적량은 완료된 형제까지 포함한다.

풀이와 답 확인

  1. n=4의 쌍은 6개다. 보존 생산자는 여섯 쌍을 유지하고 즉시 소비 생산자는 소비자의 누적 저장이 없다는 범위에서 상수 보조 공간만 쓴다.

  2. 반 채움 즉시 축소는 왕복마다 10이므로 총 30이며 최종 n=4,cap=4다. 간격 정책은 6+2+2=10이고 최종 n=4,cap=8이다.

  3. 두 재귀 정책 모두 호출 15개, 프레임 피크 4개다. 절반 버퍼의 피크 15슬롯·누적 32슬롯과 전체 복사의 피크 32슬롯·누적 120슬롯을 분리한다.

  4. 각 비용은 선언한 모형과 저장 범위의 값이다. 실제 메모리 할당 시간이나 C 스택 바이트, 운영 마감 성능으로 확대하지 않는다.

출력 쌍은 6개, 배열 왕복 비용은 30 대 10, 재귀 버퍼 피크는 15 대 32슬롯이며 누적량은 32 대 120슬롯이다. 저장 계약·초기 상태·수명을 명시해야 비교가 가능하다.

해결한 뒤 점검할 것

  • 생산자와 소비자의 결과 저장 범위를 적는다.

  • 두 배열의 각 왕복 상태와 비용을 복사/쓰기/제거로 분해한다.

  • 두 재귀 정책의 호출·활성 프레임·피크·누적량을 별도 열로 표시한다.

  • 가상 비용과 실제 실행·할당·학생 실험을 구별한다.
