소단원 10.1

배열 기반 이진 힙

가장 작은 수를 빨리 꺼내려면 배열 전체를 항상 정렬해야 할까?

준비 개념과 학습 목표

준비 개념

  • 배열의0기반 인덱스

  • 부모·자식이 있는 이진 트리

학습 목표

  • 완전 이진 트리의 배열 표현을 설명한다.

  • 최소 힙 조건과 전체 정렬을 구별한다.

  • 부모·자식 인덱스를 계산한다.

항목의 키를 바꾸어도 배열 위치와 최솟값 조회는 그대로 믿을 수 있을까?

배열의 논리 길이 n 안에서만 자식 식을 적용한다. 마지막 내부 인덱스는 n≥2에서 floor(n/2)−1이고 이후 인덱스는 모두 리프다. 확보 용량 C가 더 커도 n 이상 슬롯의 옛 값은 현재 힙 항목이 아니다. 힙 순서, 논리 길이, 비교 키의 현재 값은 함께 유지해야 하는 계약이다.

항목 ID가 배열 인덱스와 같다는 계약은 없다. 교환 때 항목이 이동하므로 ID에서 위치를 찾는 보조 표를 사용하면 양쪽 항목의 표도 갱신해야 한다. 같은 우선순위의 항목도 서로 다른 ID다. 순서 검사만 통과한 배열에 낡은 위치 표가 붙어 있으면 갱신 연산이 다른 항목을 고칠 수 있다.

현재 유효한 최소 힙에서 한 항목만 낮추면 자식과의 관계는 안전하지만 부모와의 관계가 깨질 수 있어 올라간다. 한 항목만 높이면 부모와의 관계는 안전하지만 자식 쪽을 내려가며 복구한다. 비교 함수나 여러 키를 동시에 바꾸면 이 한 경로 논증을 그대로 사용할 수 없다. 여기서는 유한 정수 키와 상수 비용 비교를 쓰는 손 모형이다.

먼저 확인할 개념
  • 논리 길이와 확보 용량

    자식 인덱스의 존재 여부를 용량이 아닌 현재 길이로 판정한다.

  • 왼쪽과 오른쪽 위치·간선 높이

    층 순서의 배열 위치와 실제 부모·자식 관계를 연결한다.

모양과 순서 조건을 함께 둔다

이진 힙은 마지막 층을 제외한 층을 채우고 마지막 층도 왼쪽부터 채우는 완전 이진 트리 모양을 사용한다. 여기에 최소 힙은 각 부모 값이 존재하는 자식 값 이하라는 순서 조건을 둔다. 최대 힙은 반대로 부모가 자식 이상이다. 이 단원은 최소 힙으로 통일한다.

최소 힙에서는 루트에서 자식으로 내려갈수록 값이 작아질 수 없으므로 루트가 전체 최솟값이다. 하지만 형제끼리나 서로 다른 가지의 값까지 정렬되어야 하는 것은 아니다. [2,5,3,9,7,8]은 최소 힙이지만5 다음3이 나와 배열은 오름차순 정렬이 아니다. 같은 값도 허용하며 비교의 일관성이 필요하다.

배열 인덱스로 연결을 대신한다

배열 a의 인덱스0을 루트로 하고 층 순서로 저장한다. i의 왼쪽 자식은2i+1, 오른쪽은2i+2이며 해당 인덱스가 크기 n보다 작을 때만 존재한다. i>0의 부모는 floor((i−1)/2)다. 루트에는 부모가 없으므로0에서 이 식을 무조건 쓰지 않는다.

예제 배열 크기6에서 인덱스1의 값5는 인덱스3의9와4의7을 자식으로 가진다. 인덱스2의 값3은 인덱스5의8만 자식으로 가진다. 오른쪽 자식6은 배열 범위 밖이다. 트리 그림과 배열을 한 칸씩 대응시키면 포인터가 없어도 위아래 이동을 계산할 수 있다.

모든 부모 조건을 확인한다

배열이 힙인지 확인하려면 각 존재하는 부모·자식 간 비교를 확인한다. n개 원소에서는 간선이 n−1개이므로 전체 확인은 O(n)이다. 최솟값을 읽는 일은 비어 있지 않을 때 a[0] 한 칸이므로 O(1)이다. 비어 있을 때의 처리는 별도 정책이나 API 오류다.

임의 값이 들어 있는지 찾거나 전체를 정렬된 순서로 읽는 일까지 O(1)이 되는 것은 아니다. 힙은 극값을 반복해서 꺼내고 넣는 우선순위 큐에 유리한 구조다. 같은 목적을 다른 자료구조로도 구현할 수 있으므로 우선순위 큐라는 추상 기능과 이진 힙이라는 구현을 구별한다.

자식 5와 6

각 변경은 원래 배열에서 별도로 시작한다. 표의 위치는 항목의 현재 슬롯이며 우선순위 숫자와 구별한다.

중간 과정을 따라가는 예제

배열[2,5,3,9,7,8]의 최소 힙 여부를 모든 존재 간선으로 검사하고 인덱스5의 부모를 구하라.

  1. 루트 비교는2≤5와2≤3이다.

  2. 인덱스1은5≤9와5≤7,인덱스2는3≤8이다. 나머지는 자식이 없다.

  3. 모두 성립한다. 인덱스5의 부모는 floor((5−1)/2)=2다.

최소 힙이며 부모 인덱스2의 값3이다. 총5개의 간선 비교로 조건을 확인했다.

조건을 바꾸어 비교하기

키 감소와 위치 표의 동시 복구

원래 힙의 키 6인 ID H를 0으로 낮추고 이동을 추적하라.

  1. 인덱스 4의 부모 1에 있는 키 4와 교환한다. 배열은 [1,0,2,9,4,3,8]이다.

  2. 부모 0의 키 1과 교환하여 [0,1,2,9,4,3,8]이다.

  3. H의 위치는 0, 처음 키 1인 항목의 위치는 1, 처음 키 4인 항목의 위치는 4로 갱신한다.

루트의 최솟값은 0이고 ID 위치 표도 세 이동을 반영해야 한다.

비교할 점

값만 교환하면 힙은 맞아도 ID 갱신 기능은 깨질 수 있다.

키 증가가 찾는 반대 경로

원래 배열에서 인덱스 2의 키 2를 10으로 높여라.

  1. 부모 키 1은 10 이하이므로 위쪽 조건은 안전하다.

  2. 자식 키 3과 8 중 작은 3을 선택한다.

  3. 교환 후 [1,4,3,9,6,10,8]이고 새 위치 5는 리프다.

상승이 아니라 한 번의 하강으로 복구한다.

비교할 점

키 변화 방향으로 영향을 받는 간선을 먼저 고른다.

종이와 본문으로 직접 해보기

예제에서 인덱스4의7만1로 바꾸면 어느 간선이 깨지는가? 크기7로 끝에6을 추가했을 때 새로운 부모·자식 조건은?

힌트 보기

인덱스4의 부모는1이다. 새 인덱스6의 부모는2다.

풀이 보기

5≤1이 거짓이므로1→4 간선이 깨진다. 원래 배열 끝에6을 추가하면3≤6이 새 간선 조건이고 성립하므로[2,5,3,9,7,8,6]도 최소 힙이다.

오해와 반례

최소 힙 배열은 모든 원소가 오름차순이다.

유효한 예제에서5>3이므로 인접 배열 값은 내려갈 수 있다. 부모·자식의 부분 순서와 배열 전체의 정렬은 다르다.

연습 1 · 값과 상태 예측

길이 n=7, 용량 C=12인 힙에서 인덱스 3의 자식과 마지막 내부 인덱스를 구하라.

힌트 1

자식 식은 2i+1과 2i+2다.

힌트 2

자식 인덱스가 n보다 작아야 존재한다.

풀이와 답 확인

  1. 인덱스 3의 후보는 7과 8이며 둘 다 논리 범위 밖이다.

  2. 마지막 내부 인덱스는 floor(7/2)−1=2다.

인덱스 3은 리프이며 용량의 남은 다섯 슬롯은 현재 자식이 아니다.

흔한 오답에서 다시 생각하기

용량이 12라서 7과 8은 자식이다.

저장 공간 확보와 논리 원소 존재를 나누어 검사한다.

연습 2 · 오류 찾아 고치기

H를 루트까지 올린 뒤 위치 표가 여전히 H→4라고 한다. 그 표로 H를 삭제해도 될까?

힌트 1

교환 후 슬롯 4에 어떤 항목이 왔는가?

힌트 2

힙 순서와 ID 대응 검사는 다르다.

풀이와 답 확인

  1. 슬롯 4에는 원래 키 4인 항목이 있다.

  2. H의 현재 위치 0을 찾도록 표를 고친 뒤 삭제해야 한다.

낡은 표로 삭제하면 다른 항목을 없애므로 거절한다.

흔한 오답에서 다시 생각하기

루트가 최솟값이면 위치 표도 맞다.

순서 부등식은 외부 ID 대응을 검증하지 않는다.

연습 3 · 직접 만들어 보기

키 6을 0으로 낮춘 결과의 모든 간선을 적어 복구 완료를 인증하라.

힌트 1

배열은 [0,1,2,9,4,3,8]이다.

힌트 2

내부 인덱스 0,1,2만 검사한다.

풀이와 답 확인

  1. 0≤1, 0≤2, 1≤9, 1≤4, 2≤3, 2≤8이다.

  2. 동시에 이동한 세 ID의 현재 인덱스를 확인한다.

여섯 순서 간선과 ID 위치 대응이 모두 맞다.

내부 노드의 모든 간선도 새 비교 규칙을 만족해야 한다.

내 말로 설명하기

힙 순서가 맞으면 ID 위치 표는 생략해도 되는가?

설명 기준 확인

ID 기반 갱신을 제공한다면 표를 쓰거나 실제 위치를 찾는 다른 비용을 명시해야 한다.

키 증가와 감소가 같은 방향으로 움직이는가?

설명 기준 확인

기존 유효 최소 힙의 한 키 감소는 상승, 증가는 하강으로 복구한다.

한 단계 더

위 배열의 모든 부모·자식 부등호를 반대로 하면 최대 힙을 검사할 수 있다. 예제는2≥5가 거짓이라 최대 힙은 아니다. 최소·최대 구현의 비교 방향을 섞지 않는다.

바닥부터 만든 힙은 항상 같은 배열이며 log n 비용을 n번 지불할까?

바닥부터 heapify는 처리할 부모의 두 자식 부분트리가 이미 힙이라는 귀납 조건을 사용한다. 순서를 거꾸로 바꾸면 먼저 고친 루트가 나중의 자식 이동으로 다시 깨질 수 있다. 결과 힙은 유일한 정렬 배열이 아니라 원래 다중집합과 부모 조건을 보존한 표현이다.

길이 7의 완전 트리에는 높이 2인 노드 하나, 높이 1인 노드 둘, 리프 넷이 있다. 한 노드가 하강할 수 있는 최대 간선 수의 합은 2+1+1=4다. 이 손 모형은 두 자식이면 작은 자식 선택 비교 한 번과 부모 비교 한 번을 센다. 따라서 최대 여덟 키 비교다. 실제 비교 비용·배열 복사·언어 실행 시간은 포함하지 않는다.

원소 2^m−1개의 완전 트리에서 하강 높이 합은 Σ(h·2^(m−h−1)), h=1..m−1이며 2^m−m−1이다. m=3이면 4다. O(n)의 높이 합은 모든 노드가 최대 높이만큼 움직인다는 느슨한 O(n log n) 계산을 개선한다. 두 알고리즘의 같은 상한 표현만으로 실제 출력 배열이나 모든 입력의 정확한 비용이 같다고 결론 내리지 않는다.

끝에 넣고 위로 복구한다

삽입은 배열 끝에 새 값을 추가하여 완전 트리 모양을 유지한다. 새 값이 부모보다 작으면 부모와 교환하고 계속 올라간다. 새 값이 부모 이상이거나 루트에 도달하면 멈춘다. 기존 힙 조건은 새 원소에서 루트로 가는 경로 주변만 복구하면 된다.

트리 높이는 O(log n)이므로 상수 시간 비교·교환과 충분한 배열 용량을 가정하면 상승 작업은 O(log n)이다. 동적 배열이 용량 부족으로 한 번에 전체 복사할 수 있으므로 실제 단일 삽입의 비용과 상각 비용은 구별한다. 숫자 비교가 아니라 큰 객체 비교라면 그 비교 비용도 별도다.

마지막 값으로 루트를 메우고 아래로 복구한다

최소 삭제는 반환할 루트를 먼저 보관한 뒤 마지막 값을 루트로 옮기고 배열 크기를 줄인다. 새 루트가 자식보다 크면 존재하는 자식 중 더 작은 자식과 교환한다. 자식이 하나면 그 자식만 비교한다. 같은 자식 값이면 이 단원의 손 모형은 왼쪽을 선택한다.

두 자식 중 큰 쪽을 선택하면 새 부모가 작은 자식보다 큰 상태가 남을 수 있다. 따라서 최소 힙에서는 작은 쪽을 고른다. 하나의 아래 경로를 따라 O(log n)에 복구한다. 빈 힙 삭제는 정상 값이 없으며1원소이면 그 값을 반환하고 빈 배열이 된다. Python heappop은 빈 경우 IndexError를 내지만 자체 자료구조 정책은 따로 정할 수 있다.

전체 구성은 바닥부터 한다

heapify는 정렬되지 않은 배열을 힙으로 만드는 작업이다. 마지막 내부 노드 floor(n/2)−1부터0까지 각각 아래로 복구한다. 이미 처리된 자식 부분 트리는 힙이므로 해당 부모를 내리면서 더 큰 부분 트리도 힙으로 만든다. 여기서 하강은 작은 자식 선택·동률 왼쪽으로 고정한다.

모든 원소를 하나씩 삽입하면 O(n log n) 상한이지만 바닥부터 구성은 O(n)이다. 잎은 움직이지 않고, 높이1 노드가 많으며 높은 노드는 적다. 높이 h의 노드 수가 대략 n/2^(h+1) 이하인 것을 이용하면 비용 합이 n에 상수 배로 묶인다. 모든 노드가 모두 최대 높이만큼 내려간다고 세면 느슨한 상한만 얻는다.

  • 작은 힙으로 상위 k개를 유지한다.

취소된 항목이 루트에 남아 있거나 새 점수가 작으면 어떻게 처리할까?

우선순위가 낮은 숫자일수록 먼저인 큐에 항목 ID, 우선순위, 도착 순번, 버전을 기록한다. 갱신 시 새 버전의 기록을 추가하고 이전 버전은 꺼낼 때 현재 표와 대조하여 버린다. 이번 모형은 갱신해도 최초 도착 순번을 유지한다. 갱신을 새 도착으로 보는 정책은 가능하지만 동률 순서가 달라져 별도 계약이 필요하다. 실제 비교 키는 (우선순위, 도착 순번, 버전)의 정수 튜플로 고정하여 같은 ID의 동일 우선순위 갱신도 업무 객체 자체를 비교하지 않는다. 서로 다른 업무의 도착 순번은 고유하다.

물리 힙 크기와 살아 있는 업무 수는 다르다. A=(2,순번0,v1), B=(1,순번1,v1), C=(1,순번2,v1)에서 B를 우선순위 4의 v2로 바꾸면 물리 기록은 네 개이고 살아 있는 업무는 세 개다. 옛 B가 가장 먼저 물리적으로 나오지만 무효이므로 반환하지 않는다. 이후 C,A,B의 실제 업무 순서다. 누적된 무효 기록을 정리하지 않으면 공간은 현재 살아 있는 수만으로 O(k)라고 말할 수 없다.

상위 k개의 큰 점수 유지에서는 최소 힙을 후보 경계로 사용한다. 후보 [5,6]에 새 3이 오면 무조건 루트를 대체해서 [3,6]으로 만들면 안 된다. Python 문서의 heapreplace는 항상 기존 루트를 내보내지만 heappushpop은 두 동작 후 더 작은 값을 내보낸다. 여기서는 값의 다중집합만 고르고 업무 동률 선택은 별도다. k=0은 어떤 점수도 저장하지 않는 분기로 처리한다.

어떤 비교가 중요한지 먼저 정한다

우선순위 큐는 현재 들어 있는 항목 중 비교 규칙에 따른 가장 우선인 항목을 꺼낸다. 최소 힙에서는 작은 키가 먼저다. 낮은 숫자가 급한 일이라는 정책이면 그대로 사용할 수 있다. 높은 점수가 먼저여야 하는 상황이면 최대 힙을 쓰거나 일관된 비교 변환을 선택한다.

FIFO 큐는 도착 순서를 기준으로 한다. 우선순위 큐는 나중에 온 더 급한 일이 먼저 나갈 수 있으며 덜 급한 일이 계속 미뤄지는 기아도 정책 차원의 문제다. 힙은 주어진 키를 처리할 뿐 업무의 공정성이나 임상·행정적 중요성을 스스로 결정하지 않는다. 여기서는 가상의 학습 작업만 사용한다.

동률과 바뀐 우선순위를 관리한다

같은 우선순위에서 먼저 들어온 일을 먼저 처리하려면 비교 키를(우선순위,고유 도착 순번)으로 정한다. 첫 항목을 비교하고 같을 때 순번을 비교한다. 순번이 중복되지 않으면 비교 불가능한 업무 객체 자체를 비교할 필요도 없다. 힙 기본 성질만으로 동률의 FIFO가 자동 생기는 것은 아니다.

힙 안 항목의 키를 제자리에서 바꾸면 부모·자식 조건이 깨질 수 있다. 갱신 위치를 알고 복구하거나, 옛 항목을 무효로 표시하고 새 항목을 삽입하여 꺼낼 때 무효 항목을 버리는 등의 정책이 필요하다. 두 방식은 자료 구조와 공간 비용이 다르며 키 값만 바꾸고 끝내지 않는다.

큰 점수 몇 개만 남긴다

가장 큰 k개의 값만 필요하다면 크기 k의 최소 힙을 유지할 수 있다. 아직 k개가 안 되면 삽입한다. 꽉 찼을 때 새 값이 루트보다 크면 현재 후보 중 가장 작은 루트를 버리고 새 값을 넣는다. 루트 이하라면 그대로 두어도 상위 k값의 집합을 유지한다.

n개를 순서대로 읽고 후보 수 k를 고정하면 보통 O(n log k) 시간과 후보 O(k) 공간을 쓴다. 힙 안 후보 배열은 정렬된 최종 출력이 아니다. 동점 업무까지 골라야 하면 점수 외 선택 기준을 추가하며 k=0은 별도 처리한다. 이벤트 시간 순서도 우선순위 큐로 표현할 수 있지만 현재보다 과거 이벤트를 넣는 등 시간 의미는 따로 정해야 한다.

힙 상태와 살아 있는 업무의 다른 완료 조건

① [1,4,2,9,6,3,8]의 키 6인 H를 0으로 낮춰 배열·이동 ID 위치를 보고하라. ② [8,6,7,5,3,2,9]를 바닥부터 구성해 교환/키 비교 수를 적고 순차 삽입 결과와 비교하라. ③ A/B/C의 키와 순번은 (2,0)/(1,1)/(1,2)이며 모두 v1이다. B를 (4,1,v2)로 갱신한 뒤 첫 업무와 물리 삭제 수를 구하라. 별도로 점수 5,5,4,6,3의 큰 두 값을 골라 무조건 replace의 오류를 설명하라.

힌트 1

키 변경은 한 경로지만 ID 위치 표는 교환한 모든 항목을 반영한다. heapify는 내부 인덱스 2,1,0이다.

힌트 2

업무 반환 전에 현재 버전을 검사하며 큰 값 후보의 루트는 버려도 되는 최솟값 경계다.

풀이와 답 확인

  1. ① 최종 배열은 [0,1,2,9,4,3,8]이다. H는 4→1→0, 처음 키 1인 항목은 0→1, 처음 키 4인 항목은 1→4로 이동한다.

  2. ② 바닥 결과는 [2,3,7,5,6,8,9]이며 교환 네 번·키 비교 여덟 번이다. 순차 삽입 결과 [2,5,3,8,6,7,9]도 같은 다중집합의 힙이다.

  3. ③ 옛 B/v1을 버리고 C를 반환하므로 물리 삭제 두 번과 업무 반환 한 번이다. 이때 물리 기록과 살아 있는 업무는 각각 두 개다.

  4. 큰 두 값은 {5,6}이며 마지막 3은 거절한다. 무조건 replace는 {3,6}으로 바꾸므로 실패한다.

힙 간선뿐 아니라 이동 ID, 비용 규약, 버전 유효성, 다중집합과 상위 값 교체 조건을 각각 인증한다. 실제 라이브러리·업무 서비스·메모리·성능·학생 시험은 미수행이다.

해결한 뒤 점검할 것

  • 모든 이동 ID의 새 인덱스와 여섯 간선을 확인한다.

  • 교환과 키 비교를 구별하고 다른 배열도 같은 힙 계약을 만족함을 보인다.

  • 물리 두 삭제와 유효 한 반환 및 남은 두 업무를 구별한다.

  • 중복 5를 두 입력으로 취급하고 새 3을 조건 없이 대체하지 않는다.
