소단원 1.1

인터페이스와 표현 불변식

종이 카드를 줄 세우는 방식과 카드에 ‘다음 사람’을 적는 방식은 같은 큐가 될 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 순서가 있는 목록 [A,B]와 [B,A]가 다름을 안다. 첫 항목을 앞이라고 부른다.

  • 배열은 인덱스로 원소를 선택하는 칸들의 묶음이다. 4칸의 인덱스가 0,1,2,3임을 복습한다.

  • 조건을 참/거짓으로 판단할 수 있다. 0≤2≤4는 참, 0≤5≤4는 거짓이다.

학습 목표

  • ADT의 값·연산 명세와 구현의 표현을 분리한다.

  • 원형 큐의 표현 불변식과 추상화 함수를 작성한다.

  • 초기화·연산·경계조건에서 불변식을 확인한다.

배열 칸 수가 같으면 두 제한 큐의 계약도 같을까?

원형 배열의 빈 상태와 꽉 찬 상태는 같은 앞·뒤 위치를 가질 수 있다. 원소 수 n을 저장하는 길이 3의 배열은 세 항목을 모두 사용할 수 있다. 별도 원소 수 없이 head=tail을 빈 상태로 정하고 다음 tail이 head면 가득 찼다고 정하는 다른 구현은 한 칸을 비워 두므로 두 항목만 저장한다. 같은 배열 길이는 같은 외부 용량을 뜻하지 않는다.

이 보강은 두 구현을 각각 계약부터 선언하여 비교한다. n을 쓰는 표현은 base의 AF를 사용한다. 빈 칸을 남기는 표현은 head부터 tail 직전까지 순환한 목록을 AF로 삼는다. head=tail일 때는 빈 목록이고 저장 개수는 (tail−head) mod 3이다. 두 구현 모두 FIFO일 수 있지만 세 번째 enqueue의 성공 여부가 다르면 용량 3 큐라는 같은 명세를 구현한 것은 아니다.

다른 유효 표현으로 옮겨도 논리 목록이 유지될 수 있다. 현재 head에서 활성 항목만 순서대로 새 배열의 0부터 복사하고 새 head를 0으로 정하면 AF는 같다. 오래된 비활성 칸까지 항목으로 복사하거나 반대로 뒤에서부터 꺼내면 불변식 숫자가 맞아도 계약을 어긴다. 공개 연산 경계에서의 RI와 전후 AF 관계를 함께 검사한다.

추상 자료형은 이용자가 관찰하는 약속

추상 자료형(ADT)은 지원하는 값과 연산의 의미를 명세한 것이다. 큐의 추상 값은 순서 있는 항목들의 목록이다. enqueue(x)는 뒤에 x를 붙이고, dequeue는 비어 있지 않을 때 맨 앞 값을 반환하면서 제거한다. 먼저 넣은 항목이 먼저 나오는 FIFO 규칙이 핵심이다. ‘배열로 만들었다’는 설명은 이 추상 규칙이 아니라 구현 표현이다.

실제 유한 저장 구현은 용량 초과와 빈 큐 처리를 정해야 한다. 이 예의 인터페이스는 용량 C의 제한된 큐다. enqueue는 꽉 찼으면 실패하고 상태를 유지하며, dequeue는 비었으면 실패하고 상태를 유지한다. 용량 제한 없는 큐와는 실패 가능성이 다른 계약이다. 두 구현이 같은 ADT라고 말하려면 값과 정상 연산뿐 아니라 경계·오류의 관찰 가능한 의미도 맞아야 한다.

표현 불변식과 추상화 함수

원형 큐를 길이 C인 배열 a, 앞 위치 head, 항목 수 n으로 나타내자. C≥1을 고정하며 0≤head<C와 0≤n≤C를 불변식으로 둔다. 채워진 논리 순서의 k번째 항목은 a[(head+k) mod C]이고 0≤k<n이다. 이 규칙을 표현에서 추상 목록으로 가는 추상화 함수 AF라고 부른다. 사용하지 않는 배열 칸의 오래된 값은 추상 큐의 항목이 아니다.

불변식은 표현이 유효한지, 추상화 함수는 그 표현이 어떤 값을 뜻하는지 설명한다. n=0인 서로 다른 head 값이 같은 빈 큐를 나타낼 수 있다. 따라서 표현과 추상 값은 반드시 일대일일 필요가 없다. 내부에서 순간적으로 갱신 중인 상태까지 항상 같은 불변식이 참이라고 무조건 요구하는 것은 아니다. 여기서는 초기화 완료와 공개 연산의 시작·종료 지점에서 보장하고, 단일 스레드이며 연산 중 재진입이 없다고 가정한다.

연산이 불변식을 보존하는 이유

n<C일 때 enqueue는 뒤 위치 (head+n) mod C에 쓰고 n을 1 늘린다. 이전 항목의 순서는 유지되고 새 항목이 마지막에 온다. n>0일 때 dequeue는 a[head]를 반환하고 head를 (head+1) mod C로, n을 n-1로 바꾼다. 나머지 목록이 한 칸 앞에서 시작하므로 FIFO 명세를 실현한다. 나머지 연산은 C가 양수여야 정의되고, 실제 C 코드에서는 head+n 계산의 정수 범위도 확인해야 한다.

불변식만으로 올바른 큐를 완전히 증명한 것은 아니다. 0≤n≤C를 유지하면서 뒤 항목부터 제거해도 숫자 조건은 만족한다. 그래서 연산 전후 추상 값이 ADT 명세와 일치하는지도 확인해야 한다. 표현을 외부 코드가 직접 바꾸면 head 범위나 순서가 깨질 수 있으므로 인터페이스 뒤에 감춘다. 이 첫 단원에서는 종이 모델로 계약을 세우고 이후 배열·연결 큐 구현에서 검증을 확장한다.

RI: C≥1, length(a)=C, 0≤head<C, 0≤n≤C
AF(a,head,n) = [a[(head+k) mod C] : 0≤k<n]

두 행은 서로 다른 명시 용량 정책이다. 실패한 삽입은 기존 목록을 유지해야 한다. 실제 메모리 바이트 수나 실행 속도를 측정한 표가 아니다.

중간 과정을 따라가는 예제

C=4, head=3, n=2이고 a[3]=A, a[0]=B다. 사용하지 않는 나머지 칸은 읽지 않는다. enqueue(X)를 한 번, dequeue를 한 번 수행한다.

  1. 초기 AF=[A,B]. head=3<4, n=2≤4이므로 RI 참.

  2. 뒤 위치=(3+2) mod4=1. a[1]=X로 쓰고 n=3. AF=[A,B,X].

  3. dequeue는 a[3]=A를 반환한다.

  4. head=(3+1) mod4=0, n=2. 새 AF=[a[0],a[1]]=[B,X].

  5. a[3]에 A가 남아 있어도 n과 head가 가리키는 활성 항목이 아니므로 큐에는 없다.

제거 결과 A, 남은 큐[B,X], 최종 head=0,n=2. 각 연산 경계에서 RI를 유지하고 FIFO도 만족한다.

조건을 바꾸어 비교하기

같은 배열의 다른 경계

두 표현 모두 길이 3이며 빈 상태에서 A,B,C를 삽입한다. 용량 3 명세를 만족하는가?

  1. 원소 수 표현은 n=0,1,2,3으로 세 삽입이 모두 성공한다.

  2. 빈 칸 표현은 두 삽입 뒤 다음 tail이 head가 되어 세 번째를 거절한다.

  3. 두 표현을 용량 3 명세의 동일한 구현이라고 주장할 수 없다.

FIFO 순서와 외부 용량은 따로 맞춰야 한다.

비교할 점

순서가 맞는 두 구현도 경계 동작에서 다를 수 있다.

활성 순서만 재배치

C=4, head=2, n=3이며 배열은 [C,Z,A,B]다. 새 head를 0으로 만드는 복사는?

  1. 활성 위치는 2,3,0이므로 AF는 [A,B,C]다.

  2. 새 배열의 0,1,2에 A,B,C를 복사하고 head=0,n=3으로 둔다.

  3. Z는 비활성 값이므로 네 번째 항목으로 추가하지 않는다.

새 배열 [A,B,C,임의 비활성 값]은 같은 AF를 갖는다.

비교할 점

물리 배열 전체의 동일성 대신 활성 논리 값의 동일성을 검사한다.

종이와 본문으로 직접 해보기

4칸을 그리고 head=0,n=0에서 A,B,C,D를 차례로 넣어라. E 삽입을 시도하고, 두 번 제거한 뒤 E를 다시 넣어 각 단계의 head,n,AF를 적어라.

힌트 보기

꽉 찼는지는 배열 값이 아니라 n=C로 판단한다. 실패는 상태를 바꾸지 않는다.

풀이 보기

A~D 뒤(0,4), AF=[A,B,C,D]. 첫 E는 실패해 그대로다. A 제거 뒤(1,3), B 제거 뒤(2,2), AF=[C,D]. E는(2+2) mod4=0에 저장하고(2,3), AF=[C,D,E]. 비어 있는 칸과 과거 값이 있는 칸을 ‘현재 항목’과 혼동하지 않는다.

오해와 반례

같은 ADT면 내부 표현과 비용도 같고, 불변식만 맞으면 정답이다.

연결 큐와 배열 큐가 같은 순서·오류 계약을 제공할 수 있지만 메모리 배치와 비용은 다르다. 또 숫자 불변식을 지키면서 맨 뒤 값을 제거하는 구현은 큐 명세를 어긴다. 표현 유효성과 추상 연산의 의미를 모두 확인해야 한다.

연습 1 · 값과 상태 예측

C=3, head=2, n=2이고 a=[B,Z,A]다. C를 넣고 두 번 꺼낸 뒤 AF와 head,n은?

힌트 1

삽입 위치는 (head+n) mod C다.

힌트 2

각 제거 뒤 head를 순환시키고 n을 줄인다.

풀이와 답 확인

  1. 삽입 위치는 1이며 목록은 [A,B,C]다.

  2. 첫 제거는 A를 반환하고 head=0,n=2다.

  3. 둘째 제거는 B를 반환하고 head=1,n=1이다.

남은 목록은 [C]이며 head=1,n=1이다.

흔한 오답에서 다시 생각하기

배열 첫 칸 B를 먼저 꺼낸다.

물리 칸 0이 아니라 head부터 논리 순서를 읽는다.

연습 2 · 오류 찾아 고치기

제거가 앞이 아니라 마지막 활성 항목을 반환하고 n만 줄인다. RI가 유지되니 올바른 큐라고 했다. 고쳐라.

힌트 1

[A,B]에서 첫 반환값을 비교한다.

힌트 2

숫자 범위와 추상 연산 결과는 다른 검사다.

풀이와 답 확인

  1. 뒤 항목 B를 꺼내도 n의 범위는 맞는다.

  2. FIFO 명세의 첫 반환은 A다.

RI 보존에 AF 전후 관계와 반환값 일치를 추가한다.

흔한 오답에서 다시 생각하기

RI는 모든 의미 오류까지 포함한다.

여기에 선언한 RI는 범위 조건이며 FIFO는 별도 명세다.

연습 3 · 직접 만들어 보기

빈 칸 정책으로 외부 용량 3을 제공하려면 배열 길이와 빈 상태 판정을 어떻게 정할까?

힌트 1

항상 한 칸을 비워 둔다.

힌트 2

앞과 뒤가 같으면 비었다.

풀이와 답 확인

  1. 배열 길이를 4로 정한다.

  2. 다음 tail이 head면 실패하며 그 외에는 삽입한다.

  3. 활성 개수는 (tail−head) mod 4로 최대 3이다.

길이 4와 한 칸 예약 정책을 함께 명시한다.

흔한 오답에서 다시 생각하기

길이 3에 세 항목을 넣고 head=tail로 둔다.

빈 상태와 가득 찬 상태가 같은 표현이 되어 구별되지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

C=4에서 head=1,n=0과 head=3,n=0의 두 유효 표현은 같은 값인가? 연산 뒤 head까지 같아야 하는가?

힌트 1

AF의 범위 0≤k<n을 본다.

힌트 2

호출자가 관찰할 수 있는 명세를 기준으로 비교한다.

풀이와 답 확인

  1. 두 AF는 모두 빈 목록이다.

  2. 다음 같은 값을 넣어도 물리 위치는 다를 수 있지만 논리 목록은 같다.

  3. head를 외부 반환값으로 공개하지 않는 계약에서는 head의 동일성이 필요하지 않다.

여러 표현이 같은 추상 값을 나타낼 수 있다.

준비 개념과 학습 목표

준비 개념

  • 포인터는 어떤 객체를 가리키는 값이라는 개념을 안다. 이름표와 실제 상자를 별도로 그려 보자.

  • 구조체는 여러 필드를 가진 자료이고 연결 노드는 다음 노드 포인터를 가진다는 그림을 읽을 수 있다.

  • 함수나 블록의 시작·끝을 구별한다. 아직 C 문법이 낯설면 상자·화살표 활동으로 먼저 접근한다.

학습 목표

  • 포인터 복사·값 복사·소유권 이전을 구별한다.

  • 동적 노드와 저장된 항목의 해제 책임을 따로 명세한다.

  • 수명 종료·별칭·오류 경로의 위험을 종이로 추적한다.

두 번의 삽입 중 두 번째가 실패하면 소유권은 어디에 있을까?

성공한 삽입마다 소유권을 넘기는 단일 항목 API와 모든 항목을 한꺼번에 넘기는 원자 배치 API는 다른 계약이다. 현재 남은 자리가 하나인데 서로 다른 살아 있는 동적 항목 X,Y를 차례로 넣으면 X의 성공 뒤 Y가 실패한다. 기본 API에서는 X는 큐 소유이고 Y는 호출자 소유다. 두 반환값을 묶어 전체 실패라고 해도 첫 성공이 취소되는 것은 아니다.

전체 성공 또는 전체 실패를 원하는 새 배치 API라면 상태 복구와 소유권 복구를 모두 설계해야 한다. 여기서는 추가된 꼬리 노드를 되돌려 X를 호출자에게 반환하고, 기존 큐 항목의 순서는 그대로 두는 롤백 계약을 선언한다. 일반 dequeue는 맨 앞 기존 항목을 제거하므로 이 롤백을 대신할 수 없다. 중간 결과를 외부에 공개하지 않는 단일 흐름 가정도 필요하다.

포인터 두 개가 같은 항목을 가리키는 경우에는 두 독립 소유권이 생기지 않는다. 이미 큐에 넘긴 X의 별칭을 다시 성공 삽입한 듯 취급하면 같은 항목을 두 번 해제할 위험이 있다. 이 계약의 입력은 호출자가 단독 소유한 서로 다른 살아 있는 항목이어야 한다. 복사가 필요하면 별도 항목을 새로 만들고 내용과 실패 경로를 정의한다. 실제 C의 수명 종료 후 포인터 접근은 정의되지 않은 동작이며 주소 숫자가 같아 보이는 것으로 안전성을 판단하지 않는다.

  • 소유권과 실패 계약

주소를 안다는 것과 해제 책임을 갖는다는 것

C 포인터를 q=p로 복사하면 두 변수가 같은 객체를 가리키는 별칭이 된다. 객체 내용을 복제하지 않는다. 소유권은 객체를 언제 누가 해제하고 누구에게 접근을 허용하는지 정한 설계 계약이다. C 언어가 일반 포인터에 이 계약을 자동으로 붙여 검사해 주지는 않는다. 그래서 생성·삽입·제거·파괴 연산의 문서와 코드에서 책임을 드러내야 한다.

여기서는 단일 소유자 정책을 채택한다. 살아 있는 동적 노드마다 해제 책임자가 하나 있고, 다른 포인터는 빌린 참조로 취급한다. 빌린 쪽은 해제하지 않으며 소유자가 객체를 파괴하기 전에 접근을 끝내야 한다. 이것이 모든 C 프로그램의 유일한 방식은 아니다. 공유 소유권을 쓰려면 참조 계수나 수명 관리자 등의 별도 규칙이 필요하다. const 포인터만으로 수명을 보장하거나 모든 별칭의 수정을 막는 것도 아니다.

C 객체의 수명과 유효한 접근

객체 수명은 그 저장 공간이 객체를 위해 예약되는 실행 기간이다. 일반적인 블록 안의 비정적 자동 객체는 해당 블록 실행이 끝나면 수명이 끝난다. 동적으로 할당한 객체는 할당부터 해제까지 살아 있다. 블록의 변수 이름이 보이는 범위와 동적 객체의 수명은 다른 개념이다. 이 단원은 보통의 비VLA 자동 객체와 양수 크기 할당을 예로 들며, 정적·스레드 저장기간과 임시 객체는 별도 범위다.

free는 유효한 할당의 시작 포인터 또는 NULL에 적용한다. 중간 원소 주소, 이미 해제된 저장 공간, 자동 객체 주소를 넘기는 것은 허용된 해제가 아니다. 객체 수명 종료 후 그것을 참조하는 동작은 정의되지 않은 동작이다. 해제 뒤에도 메모리 비트가 우연히 남아 출력이 맞아 보이는 실행은 안전성을 증명하지 못한다. C11 초안은 객체 수명이 끝나면 그것을 가리키는 포인터 값이 미정이 된다고 규정하므로, 이 수업에서는 남은 포인터를 사용하지 않고 즉시 책임과 별칭을 정리한다.

노드 소유권과 항목 소유권을 분리하기

정수를 값으로 저장하는 연결 큐는 노드 자체만 해제하면 된다. 정수 값에는 별도 동적 저장을 소유하는 포인터가 없기 때문이다. 그러나 char*나 다른 객체의 포인터를 저장하면 큐 노드와 그 포인터가 가리키는 자료는 별개의 객체다. 큐가 항목을 복사해서 소유하는지, 삽입 성공 때 소유권을 넘겨받는지, 사용자가 소유한 자료를 빌리는지 정해야 한다.

이 본문의 포인터 큐 계약은 성공한 enqueue가 항목 소유권을 큐로 이전하고 실패하면 호출자가 그대로 소유하는 것이다. 성공한 dequeue는 항목 소유권을 호출자에게 돌려주고 노드는 큐가 해제한다. 큐 파괴는 남은 노드와 소유한 항목을 정해진 파괴 함수로 정리한다. 외부에서 빌린 항목을 같은 파괴 함수로 해제하면 안 된다. 삽입 도중 할당 실패가 난 경로에서도 소유권 이전 여부와 기존 상태 보존을 확인해야 한다.

중간 과정을 따라가는 예제

동적 항목 X를 호출자 U가 소유한다. 포인터 큐 Q는 위의 소유권 이전 계약을 사용하고 노드 N의 할당·삽입은 성공한다. 그 뒤 dequeue가 성공한다.

  1. 삽입 전: X의 해제 책임은 U. Q는 비어 있다.

  2. 삽입 성공: 노드 N은 Q가 소유, 항목 X도 Q가 소유한다. U가 보관한 주소는 소유권 없는 별칭이며 이 계약에서 접근하지 않는다.

  3. 제거 성공: Q는 N의 연결을 제거하고 N을 해제한다. X는 해제하지 않고 포인터를 반환한다.

  4. 반환 후: X의 소유자는 U. U가 X의 파괴 함수를 한 번 호출해 수명을 끝낸다.

  5. Q를 파괴할 때는 이미 반환한 X를 다시 해제하지 않는다.

N은 Q가 한 번, X는 최종 소유자 U가 한 번 정리한다. 주소가 복사되었다는 사실만으로 책임이 둘이 되지 않는다.

종이와 본문으로 직접 해보기

상자 X와 화살표 p,q를 그려 q=p라고 하자. p가 소유자, q는 빌린 참조다. ‘q의 사용 끝’, ‘free(p)’, ‘p=NULL’를 올바른 순서로 놓고, p=NULL이 q를 바꾸는지 표시하라. 이어 enqueue 실패 때 X의 소유자를 적어라.

힌트 보기

변수 p와 변수 q는 서로 다른 이름표다. 한 이름표의 값을 바꾸어도 다른 이름표에 대입하지 않았다.

풀이 보기

q의 유효한 사용을 먼저 끝내고 free(p)로 X를 해제한 뒤 p=NULL로 남은 이름표를 정리한다. q도 더 이상 사용하지 않고 필요하면 별도로 NULL을 대입한다. p=NULL은 q를 자동으로 바꾸지 않는다. 삽입 실패 때 계약상 소유자는 여전히 호출자이며 호출자가 X를 정리해야 한다.

오해와 반례

free(p); p=NULL;을 쓰면 그 객체의 모든 포인터가 안전해진다.

p에 대입해도 별칭 q는 자동 갱신되지 않는다. 빌린 참조를 해제 뒤 역참조하면 수명을 어긴다. 원래 객체를 다시 만들었다고 오래된 별칭을 그대로 사용해도 된다는 보장은 없다. NULL 정리는 한 변수의 실수 방지에 도움이 될 뿐 전체 수명 계약을 대체하지 않는다.

준비 개념과 학습 목표

준비 개념

  • C의 구조체·배열·포인터 표기를 읽는 기초가 권장된다. 아직 낯설면 같은 상태를 종이 표로 추적해도 된다.

  • 큐의 enqueue/dequeue와 불변식 0≤n≤C를 복습한다.

  • 실패한 연산이 상태를 바꾸지 않는다는 계약을 이해한다. 예상과 관찰한 결과를 구별한다.

학습 목표

  • 명세에서 정상·경계·실패 테스트를 도출한다.

  • 작은 C 모듈의 선언·구현·테스트 책임을 구별한다.

  • 반환값·추상 상태·불변식과 수명 문제를 별도로 검사한다.

참·거짓만 확인하는 시험이 놓치는 계약은 무엇일까?

용량 2 정수 스택의 반환 bool은 성공 여부이고 출력 int는 항목 값이다. 0은 정상 데이터이므로 두 통로를 섞으면 안 된다. 실패 때 스택과 out을 유지하는 조건은 반환 false만 검사해서는 확인되지 않는다. 같은 입력에서 기대 bool, 활성 목록, n, out을 각각 정한다.

테스트의 입력은 함수의 전제를 지켜야 한다. out이 스택 내부 칸을 가리키지 않는다는 계약을 어긴 호출은 정상 테스트의 실패 사례가 아니다. 경계를 넘어 쓰는 변형도 C에서 임의의 숫자를 예측할 수 있는 정상 실행이 아니다. 정의되지 않은 동작을 발견한 지점에서 언어 수준의 결과 예측을 멈추고 별도의 검사 도구 증거가 있다면 그 실행 범위만 기록한다.

충분한 시험 분할은 빈 상태, 중간 상태, 가득 찬 상태와 0·음수 데이터를 포함한다. 원소 순서가 같은 값을 반복하면 FIFO와 LIFO의 오류를 구별하지 못할 수 있다. 서로 다른 값을 넣고 실패 직후의 상태까지 확인하면 더 강한 경계 사례가 된다. 이 보강에서는 지정한 유한 목록 모델만 계산하며 C 컴파일러나 메모리 검사기를 실행하지 않는다.

코드보다 먼저 실패 의미를 고정하기

이 준비 예제는 동적 할당을 쓰지 않는 용량 2의 정수 스택이다. 스택은 뒤에 넣은 값을 먼저 꺼내는 LIFO이며 큐의 FIFO와 구별한다. 단순한 표현에서 인터페이스와 테스트 연결을 보기 위한 것이지 큐 구현을 스택으로 바꾸는 과제는 아니다. 값 int 두 개와 원소 수 n을 저장하고 RI는 0≤n≤2다. 활성 순서는 a[0]부터 a[n-1]까지다.

push는 꽉 차면 false를 반환하고 상태를 유지한다. pop은 비었으면 false를 반환하고 스택과 출력 객체를 그대로 둔다. 두 함수에는 s가 살아 있는 유효한 Stack을 가리킨다는 전제가 있다. pop의 out은 별도 살아 있는 int 객체이며 s 내부 저장과 별칭이 아니어야 한다. 이 전제를 빼면 출력 쓰기가 스택 상태를 뜻밖에 바꾸어 명세를 어길 수 있다. 초기화하지 않은 n을 읽거나 임의 포인터를 넘기는 호출까지 자동으로 처리하는 예제가 아니다.

선언·표현·구현을 나누기

학습용으로 구조체를 공개하지만 실제 라이브러리는 헤더에 연산 선언을 두고 내부 표현을 감출 수 있다. 헤더는 호출자가 알고 지켜야 할 약속을 제공하고 구현 파일은 상태 변화를 실현한다. C에서 구조체 정의를 감추는 불완전 타입을 사용할 때는 생성·파괴 책임까지 설계해야 하므로 첫 활동에 숨은 동적 할당을 끼워 넣지는 않는다.

아래 코드는 C99 이상에서 stdbool.h가 제공된다는 조건의 작은 발췌다. push는 n==2를 먼저 확인하므로 범위 밖 a[2]에 쓰지 않고, pop은 n==0을 먼저 확인하므로 0에서 감소시키지 않는다. 정상 pop은 먼저 n을 줄여 이전 마지막 원소를 선택하고 그 값을 out에 쓴다. 사전에 RI가 참이며 정해진 포인터 전제를 지킨다면 연산 뒤에도 RI가 참이다. 이 본문은 실제 컴파일·실행을 수행하지 않았다.

#include <stdbool.h>
typedef struct { int a[2]; unsigned n; } Stack;

/* requires: s points to a live initialized Stack, s->n <= 2 */
bool push(Stack *s, int x) {
    if (s->n == 2) return false;
    s->a[s->n] = x;
    s->n += 1;
    return true;
}
/* additionally: out is a live writable int, not aliased with s */
bool pop(Stack *s, int *out) {
    if (s->n == 0) return false;
    s->n -= 1;
    *out = s->a[s->n];
    return true;
}
/* Example initialization: Stack s = { {0, 0}, 0 }; */

명세를 시험 사례로 바꾸기

테스트는 구현 코드를 따라 쓴 답이 아니라 명세에서 기대 결과를 정한다. 빈 초기 상태에서 pop 실패, 용량까지 push 성공, 용량 초과 push 실패, 마지막 값부터 pop하는 순서, 실패 뒤 상태 보존이 중요한 분할이다. 원소 값 0과 음수도 넣어 보면 특정 값을 ‘없음’과 혼동하는 결함을 찾을 수 있다. 성공 여부를 bool로 분리했으므로 0도 정상적인 항목이다.

반환값이 맞아도 불변식이나 내용이 틀릴 수 있다. 그래서 각 연산 뒤 반환값, 활성 값 목록, n 범위, 실패 때 out 보존을 별도로 확인한다. 이후 동적 구현에서는 해제 책임과 메모리 검사도 추가한다. 컴파일러 경고·검사 도구·assert는 근거를 보완하지만 모든 오류가 없다는 증명은 아니다. assert를 사용할 경우 빌드 설정에 따라 사라질 수 있으므로 사용자 입력 오류 처리를 assert에만 맡기지 않는다.

다른 문제에 적용하기

용량 2의 소유 큐는 처음 [A]이며 A는 큐 소유다. 호출자는 서로 다른 살아 있는 X,Y를 단독 소유한다. X 삽입은 성공하고 Y 삽입은 가득 차서 실패한다. 두 호출을 기본 API로 실행한 경우와, 추가된 꼬리를 제거하여 항목을 호출자에게 반환하는 원자 배치 롤백을 선언한 경우의 목록과 소유자를 비교하라. 이후 기본 API의 큐를 dequeue하면 반환 항목과 남은 목록 및 노드·항목의 책임은 무엇인가? 별도로 용량 2 정수 스택에 0,−3,8을 차례로 push한 뒤 세 번 pop하는 시험에서 bool과 out을 기록하라. out의 초기값은 99이며 모든 포인터 전제는 만족한다. 실제 C 실행과 종이·유한 모델 계산을 구별하라.

힌트 1

개별 성공 시점에 소유권을 옮기며 다음 실패가 앞 성공을 자동 취소하지 않는다. 롤백은 기존 앞 항목을 제거하지 않는다.

힌트 2

스택은 큐와 반대 순서이며 0도 정상 항목이다. 실패 pop은 직전 out을 유지한다.

풀이와 답 확인

  1. 기본 API 뒤 목록은 [A,X]이며 A와 X는 큐 소유, Y는 호출자 소유다.

  2. 선언한 원자 배치 실패 뒤에는 [A]를 복구하며 X,Y는 호출자 소유다. 추가된 X 노드만 정리하고 X 자체는 반환한다.

  3. 기본 API 큐에서 dequeue하면 A가 호출자 소유로 반환되고 남은 목록은 [X]다. 제거한 A의 노드는 큐가 정리하며 항목 A는 살아 있다.

  4. 스택의 push bool은 true,true,false이며 실패 뒤 목록은 [0,−3]다. 세 pop의 bool은 true,true,false이고 out은 −3,0,0으로 변한다.

  5. 이 결과는 명시한 계약의 추적이다. 아래 지정한 Python 목록과 정수 모델만 실행했고 실제 C·할당·해제·메모리 도구·학습자 시험은 수행하지 않았다.

기본 호출은 [A,X]와 큐 소유 X를 남기지만 원자 배치 롤백은 [A]와 호출자 소유 X,Y를 복구한다. 기본 큐의 첫 제거는 A를 반환하여 [X]를 남긴다. 별도 스택의 마지막 실패도 out=0을 유지한다. C 실행은 미수행이다.
