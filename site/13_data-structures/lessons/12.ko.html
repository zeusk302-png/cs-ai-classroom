소단원 12.1

인접행렬·인접리스트

지하철역 다섯 개의 연결을 숫자 표와 이웃 명단으로 어떻게 옮길까?

준비 개념과 학습 목표

준비 개념

  • 배열의 인덱스
  • 리스트 순회
  • 정점과 간선

학습 목표

  • 같은 단순 그래프를 행렬과 리스트로 변환한다.
  • 간선 조회와 이웃 순회의 비용을 구별한다.
  • 고립 정점과 무방향 간선의 저장 규칙을 확인한다.

정점 이름과 표의 위치를 고정한다

그래프는 정점 집합 V와 연결인 간선 집합 E로 구성된다. 여기서는 자기 고리와 평행 간선이 없는 단순 무방향 그래프를 먼저 다룬다. 정점 A,B,C,D,E와 간선 AB,AC,BD,CD,DE를 정한다. 무방향 AB는 A에서 B로도 B에서 A로도 이동 가능한 연결 하나다.

인접행렬은 행과 열에 같은 정점 순서를 놓고 연결이 있으면 1, 없으면 0을 쓴다. 이 순서를 바꾸면 숫자 배열도 함께 바뀌므로 이름에서 인덱스로 가는 대응을 보관해야 한다. 무방향 그래프의 행렬은 대각선 기준으로 대칭이며, 현재 예제는 자기 고리가 없어 대각선이 0이다. 모든 그래프의 대각선이 항상 0이라는 뜻은 아니다.

이웃 명단은 실제 연결을 따라 저장한다

인접리스트는 각 정점에 연결된 이웃 명단을 붙인다. 예제에서 A:[B,C], B:[A,D], C:[A,D], D:[B,C,E], E:[D]다. 명단을 보기 좋게 알파벳 순으로 적었지만 그래프 정의 자체에 그 순서가 필수인 것은 아니다. 탐색 순서를 재현하려면 저장 순서도 약속해야 한다.

무방향 연결 하나를 두 끝 정점의 명단에 각각 넣으므로 이웃 항목 수는 2|E|다. 현재 다섯 연결은 열 항목이다. 고립 정점 F를 추가할 때도 F:[]를 따로 보관한다. 간선 목록만 보고 정점 집합을 재구성하면 연결이 없는 정점이 사라질 수 있다. 방향 그래프에서 이웃을 후속 정점으로 정의하면 간선 하나당 항목 하나다.

무엇을 자주 묻는지에 따라 고른다

정점 수를 n, 간선 수를 m이라 쓰자. 고정 크기 행렬은 n²칸을 쓰며 두 정점의 간선 존재를 한 칸에서 O(1)에 확인한다. 하지만 u의 모든 이웃을 찾으려면 행의 n칸을 살펴야 한다. 단순 이웃 배열에서는 간선 존재를 최대 deg(u)개 항목에 대한 비교로 확인하고 이웃 순회도 그 수에 비례한다.

정점 명단까지 포함한 인접리스트의 저장 규모는 O(n+m)이다. 연결이 적은 희소 그래프에 유리하지만 실제 바이트 수는 포인터와 객체의 부가 비용, 행렬의 비트 압축 여부에 따라 달라진다. 해시 집합을 이웃 저장소로 쓰면 평균 조회 특성이 바뀐다. 단순 리스트의 비용을 모든 구현에 적용하지 않는다. 그래프 전체 탐색은 리스트로 O(n+m), 행렬로 O(n²)라는 기본 차이가 있다.

중간 과정을 따라가는 예제

정점 순서를 A,B,C,D,E로 고정하고 간선 AB,AC,BD,CD,DE의 인접행렬과 차수를 구하라.

  1. A행은 B,C에만 1을 넣어 [0,1,1,0,0]이다. B행은 [1,0,0,1,0], C행은 [1,0,0,1,0]이다.
  2. D행은 B,C,E에 연결되어 [0,1,1,0,1], E행은 [0,0,0,1,0]이다. 양방향 칸이 서로 같은지 점검한다.
  3. 각 행의 합은 2,2,2,3,1이다. 자기 고리 없는 단순 무방향 그래프에서 이 값이 차수다.
  4. 차수 합은 10=2×5다. 행렬은 25칸, 이웃 리스트는 다섯 정점 명단에 총 열 항목을 쓴다. 이 수는 객체의 실제 메모리 바이트 수가 아니다.

행렬의 행은 01100,10010,10010,01101,00010이다. 차수는 A2,B2,C2,D3,E1이고 연결은 다섯 개다.

오해와 반례

인접리스트에 같은 무방향 연결이 두 번 나오므로 간선도 두 개다.

AB를 A의 이웃 B와 B의 이웃 A로 저장해도 연결 하나다. 단순 무방향 그래프에서 항목 수를 2로 나누어 간선 수를 얻는다. 자기 고리·방향·다중 간선을 허용하면 저장 규칙부터 따로 정해야 한다.

소단원 12.2

가중치·방향·다중 간선

같은 두 도시 사이에 무료 도로와 유료 도로가 함께 있으면 한 숫자로 기록해도 될까?

준비 개념과 학습 목표

준비 개념

  • 인접행렬과 리스트
  • 순서 있는 쌍
  • 정수와 식별자

학습 목표

  • 방향·가중치·간선 식별자를 각각 보존한다.
  • 0 가중치와 간선 부재를 구별한다.
  • 평행 간선의 축약에서 사라지는 정보를 설명한다.

방향과 가중치는 서로 다른 약속이다

방향 간선 A→B는 출발 A와 도착 B를 가진다. B→A는 별개의 간선이며 자동으로 생기지 않는다. 간선의 가중치는 거리, 비용 또는 시간 같은 수치 속성이다. 의미와 단위를 정해야 서로 더하거나 비교할 수 있다. 가중치가 있다고 반드시 방향성이 있는 것은 아니다.

행을 출발, 열을 도착으로 쓰면 방향 그래프의 행렬은 일반적으로 대칭이 아니다. 0은 유효한 무료 비용일 수 있으므로 가중 행렬에서 0을 무조건 간선 없음으로 사용하면 정보를 잃는다. 예컨대 None을 부재로 정하고 숫자 0은 실제 비용으로 유지할 수 있다. 최단 거리에서 쓰는 무한대 초기값과 연결 정보 자체를 구별한다.

끝점만 같아도 간선은 여러 개일 수 있다

평행 간선은 같은 끝점을 잇는 여러 연결이다. 도로 e1:A→B 비용 0과 e2:A→B 비용 5를 별개로 보관하려면 (간선 ID, 도착점, 가중치) 항목 둘을 쓴다. 끝점만 키로 삼은 단순 딕셔너리에 두 번째 값을 대입하면 첫 도로를 덮어쓸 수 있다.

B→B 같은 자기 고리도 출발과 도착이 같은 실제 간선이다. NetworkX 공식 분류에서 Graph/DiGraph는 평행 간선을 저장하지 않고 MultiGraph/MultiDiGraph가 이를 허용한다. 이 라이브러리는 네 유형 모두 자기 고리를 허용한다. 따라서 이름 Graph가 항상 수학 교재의 단순 그래프를 뜻한다고 가정하지 않는다. 여기서는 라이브러리 설치 없이 간선 표로 모델을 확인한다.

축약은 풀려는 문제에 맞아야 한다

같은 A→B의 비용을 최솟값 0으로 축약하면 가장 싼 직접 이동에 대한 정보만 남는다. 두 도로의 존재와 ID, 용량은 복원할 수 없다. 두 도로가 각각 유량을 보낼 수 있는 독립 통로라면 용량 합산이 필요한 다른 문제다. 비용을 단순 합산하는 것은 최단 이동 비용을 보존하지 않는다.

방향 그래프의 나가는 차수는 출발하는 간선 수, 들어오는 차수는 도착하는 간선 수다. 평행 간선도 각각 센다. 자기 고리 하나는 그 정점의 들어오는 수와 나가는 수에 각각 1을 더한다. 무방향 차수에서 자기 고리를 2로 세는 관례와 혼동하지 않는다. 가중 차수 합은 간선 수와 다른 질문이다.

중간 과정을 따라가는 예제

정점 A,B,C에 e1:A→B(0), e2:A→B(5), e3:B→A(2), e4:B→B(4)를 저장한다. C는 고립 정점이다. 나가는 명단과 in/out 차수를 구하라.

  1. A의 나가는 명단은 [(e1,B,0),(e2,B,5)], B는 [(e3,A,2),(e4,B,4)], C는 []다.
  2. A의 out은 2, in은 e3 하나라 1이다. B의 out은 e3,e4 둘이라 2, in은 e1,e2,e4 셋이라 3이다. C의 두 수는 0이다.
  3. 나가는 차수 합과 들어오는 차수 합은 각각 4로 실제 간선 수와 같다. 자기 고리 e4를 두 간선으로 분리하지 않는다.
  4. 한 숫자씩 담는 최소 비용 행렬은 A행 [None,0,None], B행 [2,4,None], C행 [None,None,None]로 쓸 수 있다. 다만 e2와 두 도로의 구별을 잃은 축약 결과다.

out=(2,2,0), in=(1,3,0)이고 간선은 네 개다. 최소 비용 행렬은 원래 다중 간선의 완전한 저장물이 아니다.

종이와 본문으로 직접 해보기

e2만 삭제한다. 어느 명단·차수가 바뀌는가? A→B 간선 존재와 최소 비용은 바뀌는가?

힌트 보기

삭제 대상은 A→B 전체가 아니라 ID e2 하나다.

풀이 보기

A 명단에서 e2만 빼며 A out은 1, B in은 2가 된다. 다른 차수는 그대로다. e1이 남아 A→B는 존재하고 최소 비용은 0이다. 최소 비용 행렬만으로는 이 삭제 전후를 구별하기 어렵다.

오해와 반례

가중치 0은 이동할 수 없다는 표시다.

부재를 0으로 약속한 이진 행렬과 비용 0을 허용하는 가중 그래프는 다르다. 예제 e1은 비용 없는 실제 이동이다. None 같은 별도 부재 표시와 간선 존재 검사를 사용해야 무료 연결을 지우지 않는다.

자기점검

A→B만 존재하면 B에서 A로 갈 수 있는가?

답과 이유 보기

이 정보만으로는 갈 수 없다.

반대 방향 간선이나 다른 방향 경로가 필요하다.

자기 고리 B→B 하나가 in/out에 미치는 영향은?

답과 이유 보기

in에 1, out에 1을 더한다.

출발도 도착도 B이며 간선 개수는 하나다.

평행 도로 비용 0과 5를 값 0 하나로 줄이면 어떤 정보가 없어지는가?

답과 이유 보기

도로 개수·ID와 두 번째 비용을 잃는다.

최소 직접 비용만 보존하는 집계는 개별 연결을 복원할 수 없다.

한 단계 더

소단원 12.3

BFS·DFS 자료 관리

같은 지도에서 가까운 곳부터 찾는 탐색과 한 길을 끝까지 가는 탐색은 무엇을 다르게 보관할까?

준비 개념과 학습 목표

준비 개념

  • 큐와 스택
  • 인접리스트
  • 집합의 포함 검사

학습 목표

  • 발견 시점에 방문 상태와 부모를 기록한다.
  • BFS 큐와 DFS 호출 흐름을 손으로 추적한다.
  • 최단 간선 수와 가중 비용, 전체 그래프와 도달 부분을 구별한다.

BFS는 발견한 정점을 큐에 한 번 넣는다

BFS는 먼저 들어온 정점을 먼저 꺼내는 FIFO 큐를 사용한다. 시작 정점의 거리는 0이다. u에서 처음 발견한 v의 거리를 distance[u]+1로 기록하고 부모를 u로 저장한다. 발견 표시를 큐에 넣을 때 해야 여러 이웃이 같은 정점을 동시에 다시 넣지 않는다. 부모는 처음 발견한 길의 직전 정점이다.

큐에서 처리하는 순서는 거리 0,1,2처럼 시작점에서 필요한 간선 수가 작은 층부터다. 이 때문에 모든 간선의 길이를 1로 계산할 때 최단 간선 수를 구한다. 이웃 순서에 따라 같은 층의 방문 순서와 부모는 바뀔 수 있지만 최단 간선 수는 그대로다. 가중치가 서로 다르면 이 보장이 비용의 최솟값으로 이어지지 않는다.

DFS는 돌아올 자리를 남긴다

DFS는 한 이웃을 선택해 깊이 들어갔다가 더 갈 곳이 없으면 되돌아온다. 재귀 호출은 다음에 처리할 이웃과 복귀할 위치를 호출 스택에 남긴다. 진입 즉시 방문 표시를 해서 순환 간선이나 무방향 반대쪽 항목으로 무한히 다시 들어가지 않는다. 부모는 처음 들어온 호출의 정점이다.

명시적인 스택으로도 구현할 수 있지만 이웃 삽입 순서와 발견·처리 시점에 따라 재귀 버전과 방문 순서가 달라질 수 있다. 스택으로 바꾸면 항상 같은 순서라고 단정하지 않는다. 현재 코드는 재귀 버전이고 이웃은 미리 알파벳 순으로 저장한다. 아주 긴 경로에서는 Python 재귀 깊이 제한 때문에 반복형과 명시적 프레임이 필요하다.

부분 탐색과 전체 탐색을 구별한다

시작점 하나에서 BFS나 DFS를 하면 그 정점에서 도달 가능한 부분만 방문한다. 고립 정점 F는 결과에 나타나지 않는다. 전체 그래프를 방문하려면 모든 정점을 차례로 보고 아직 방문하지 않은 정점에서 탐색을 시작하는 바깥 반복을 쓴다. 무방향 그래프에서는 이렇게 만들어진 탐색 나무들이 연결 성분과 대응한다. 방향 그래프에서는 단순 반복의 나무 수가 강연결 성분 수를 의미하지 않는다.

인접리스트에서 방문 상태 조회가 일정 시간이라는 모델 아래 전체 탐색은 O(n+m)이다. 각 정점을 한 번 발견하고 이웃 항목을 한 번씩 읽기 때문이다. 방문·부모·거리·큐 또는 스택은 O(n) 추가 공간이다. 간선을 저장하는 입력 공간은 별도다. 아래 함수는 모든 이웃이 adj의 키로 존재하고, start도 존재하며, 탐색 중 입력을 바꾸지 않는다는 약속을 가진다.

from collections import deque

def bfs(adj, start):
    distance = {start: 0}
    parent = {start: None}
    queue = deque([start])
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in adj[u]:
            if v not in distance:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)
    return order, distance, parent

def dfs(adj, start):
    seen = set()
    order = []
    parent = {start: None}
    def visit(u):
        seen.add(u)
        order.append(u)
        for v in adj[u]:
            if v not in seen:
                parent[v] = u
                visit(v)
    visit(start)
    return order, parent

adj = {
    "A": ["B", "C"], "B": ["A", "D"],
    "C": ["A", "D"], "D": ["B", "C", "E"], "E": ["D"]
}
print(bfs(adj, "A")[0])
print(dfs(adj, "A")[0])

중간 과정을 따라가는 예제

앞의 무방향 지도 AB,AC,BD,CD,DE에서 A를 시작하고 이웃을 알파벳 순으로 읽는다. BFS 큐와 DFS의 첫 방문을 추적하라.

  1. BFS는 큐 [A]로 시작한다. A를 꺼내 B,C를 발견해 [B,C], B를 꺼내 D를 발견해 [C,D]가 된다. C에서 D는 이미 발견됐으므로 다시 넣지 않는다.
  2. D를 꺼내 E를 발견하면 [E], E를 꺼내면 []다. 처리 순서는 A,B,C,D,E이며 거리는 A0,B1,C1,D2,E3이다. 부모는 B←A,C←A,D←B,E←D다.
  3. DFS는 A→B→D→C로 들어간다. C의 이웃 A,D가 모두 방문됐으므로 D로 돌아와 E로 간다. 첫 방문은 A,B,D,C,E이고 부모는 B←A,D←B,C←D,E←D다.
  4. 본문 Python 함수를 실제 실행하여 두 순서, BFS 거리·부모와 DFS 부모를 확인했다. BFS로 E의 부모를 거꾸로 따라가면 E,D,B,A라 경로 A→B→D→E를 복원한다.

BFS 순서는 A,B,C,D,E이고 E까지 최단 간선 수는 3이다. DFS 순서는 A,B,D,C,E다. 출력은 이웃 순서 약속을 포함한 결과다.

종이와 본문으로 직접 해보기

고립 정점 F:[]를 추가하고 단독 BFS(F)를 추적한다. 또 방향 간선 A→C 비용 10, A→B 비용 1, B→C 비용 1인 그래프에서 BFS의 C까지 간선 수와 가장 싼 비용을 비교하라.

힌트 보기

F의 큐에는 처음에 F만 있다. 가중 그래프에서는 간선 수와 비용 합을 따로 적는다.

풀이 보기

BFS(F)는 순서 [F], 거리 F0, 부모 F=None이며 다른 정점에는 도달하지 않는다. 두 번째 그래프의 BFS는 A→C 한 간선으로 C를 거리 1에 발견한다. 비용 최소 경로는 A→B→C이며 두 간선의 비용 합 2로 직접 비용 10보다 작다. BFS 거리 1은 비용 1이라는 의미가 아니다.

오해와 반례

큐에서 꺼낸 뒤에만 방문 표시를 하면 같은 정점도 한 번만 삽입된다.

A가 B,C를 발견하고 B,C가 D로 연결돼 있으면 D를 꺼내기 전에 B와 C가 모두 D를 넣을 수 있다. 큐 삽입 때 발견 표시를 하면 두 번째 이웃은 D를 건너뛴다. 꺼낼 때 중복을 걸러내는 다른 구현도 가능하지만 그 공간·시간 및 부모 규칙을 이 코드와 동일하게 가정하지 않는다.

자기점검

본문 BFS에서 D의 부모가 C가 아닌 B인 이유는?

B가 먼저 D를 발견했기 때문이다.

B,C는 같은 거리이고 큐에서 B가 먼저 처리된다. D를 다시 발견해 부모를 덮어쓰지 않는다.

본문 DFS에서 C의 부모와 BFS의 C 부모는?

답과 이유 보기

DFS는 D, BFS는 A다.

DFS가 더 긴 첫 발견 경로를 따라갔다. DFS 부모가 항상 최단 경로를 주지는 않는다.

A에서 탐색했는데 F가 없으면 오류인가?

답과 이유 보기

F가 고립 정점이라면 정상이다.

한 시작점 탐색은 도달 가능한 부분만 반환하며 전체 방문에는 바깥 반복이 필요하다.

한 단계 더

BFS 부모를 따라 경로를 복원할 때 목표가 distance에 있는지 먼저 확인하자. 존재하지 않는 목표를 거리 0으로 처리하면 시작점과 도달 불가능한 정점이 섞인다. DFS의 진입·종료 시간을 추가하면 나무 구조를 더 자세히 기록할 수 있지만 순환 판정은 방향 그래프의 상태 구별 등 추가 규칙이 필요하다.
