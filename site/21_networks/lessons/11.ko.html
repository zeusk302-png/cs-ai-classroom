무선 매체와 충돌 회피

내 자리에서는 조용한데 상대는 왜 두 사람의 목소리를 동시에 들을까?

준비 개념과 학습 목표

준비 개념

  • 프레임과 MAC 계층

  • 전송 시간

  • 공유 매체

학습 목표

  • 송신 위치와 수신 위치의 감지 차이를 설명한다.

  • 가상 백오프 카운터를 추적한다.

  • ACK와 RTS/CTS가 보장하지 않는 것까지 구별한다.

세 단말의 카운터가 다르면 처음 충돌도 반드시 피할까?

새 가상 경쟁에서는 A·B·C가 0·1·2·3 중 하나를 독립적으로 균등하게 뽑는다. 같은 시각에 세기 시작하며 서로 감지할 수 있다고 정한다. 먼저 시작한 교환을 감지한 나머지는 멈춘다. 세 카운터 중 일부가 같다는 사건과 가장 작은 카운터가 둘 이상에게 있다는 사건은 다르다. 처음 시작한 교환의 충돌 가능성을 셀 때는 가장 작은 값의 중복을 확인한다.

세 값이 모두 다른 경우는 4×3×2=24가지이고 전체는 4³=64가지다. 하지만 큰 값만 같고 작은 값이 하나인 경우는 처음 교환이 단독으로 시작한다. 작은 값이 유일한 경우를 세면 3×(3²+2²+1²)=42가지다. 따라서 이 모형의 첫 시작 충돌 사건은 22/64=11/32이다. 실제 장비의 충돌률이나 숨은 단말까지 포함한 확률은 아니다.

시간선에서는 카운터와 매체 점유를 별도로 기록한다. 아래의 고정 카운터 A=1, B=3, C=4에서는 A 교환 중 남은 값을 유지하고, 이어 B 교환 중 C의 값을 다시 유지한다. ACK가 없으면 데이터 자체의 손실과 ACK 손실을 관찰만으로 하나로 단정할 수 없다.

공기를 공유하면 수신 위치도 중요하다

무선에서는 거리·장애물·간섭에 따라 각 단말이 감지하는 신호가 다르다. A와 C는 서로 듣지 못하지만 둘 다 B에 도달할 수 있다. A가 B로 보내는 동안 C가 자기 주변을 조용하다고 판단해 보내면 B에서 두 신호가 겹칠 수 있다. 이것이 숨은 단말 문제다. 송신자 주변의 감지만으로 수신 성공을 확정할 수 없다.

기본적인 반이중 무선 통신에서는 전송하면서 수신 위치의 충돌을 유선 공유 Ethernet처럼 즉시 검출하기 어렵다. 수신 확인과 재시도, 전송 시점 조절이 필요하다. 이 단원은 경쟁 기반 접근의 원리를 다루며 현대 Wi-Fi의 모든 전송이 반드시 한 단말씩 경쟁한다는 설명은 아니다.

랜덤하게 기다리고 바쁜 동안 카운터를 멈춘다

CSMA/CA의 경쟁 접근은 매체를 감지하고 필요한 대기 조건을 지킨 뒤 랜덤 백오프를 적용한다. 비어 있는 슬롯에서 카운터를 줄이고 다른 전송이 시작되면 멈춘다. 다시 필요한 유휴 조건이 충족되면 남은 카운터부터 진행한다. 카운터가 같아 동시에 시작하는 경우도 있으므로 충돌 회피는 충돌 불가능을 뜻하지 않는다.

수신 확인을 못 받으면 재시도를 고려하며 대기 범위를 늘려 반복 경쟁을 줄일 수 있다. ACK가 없다는 사실은 성공을 확인하지 못했다는 뜻이다. 데이터 손실뿐 아니라 ACK 자체의 손실도 가능하다. 아래 예제는 대기 간격·프레임 시간을 실제 표준 수치 대신 별도로 지정한 가상 슬롯 모델이다.

수신자 쪽 소식을 이용해 예약한다

선택적인 RTS/CTS에서는 송신자의 짧은 전송 요청에 수신자가 허가 메시지를 돌려준다. 수신자 근처에서 CTS를 들은 다른 단말은 표시된 기간 동안 전송을 미룬다. 이 정보는 송신자를 듣지 못하는 숨은 단말에도 도움이 될 수 있다. 그러나 제어 프레임도 충돌하거나 손실될 수 있고 예약에 시간이 드므로 항상 유리하지는 않다.

최신 Wi-Fi에는 AP가 여러 단말의 시간·주파수 자원을 배정하는 방식도 있다. RFC 9913은 802.11ax의 AP 기반 OFDMA와 채널 확보를 함께 설명한다. 경쟁 접근의 기본 원리를 배웠다고 모든 최신 자원 배정과 동시 전송을 동일한 모형에 넣으면 안 된다.

숫자는 실제 Wi-Fi 표준 슬롯 길이가 아닌 가상 시간이다. A 교환은 3슬롯, B 교환은 2슬롯이며 매번 교환 뒤 유휴 대기 1슬롯이 필요하다. B는 7, C는 11에 시작한다.

중간 과정을 따라가는 예제

가상 슬롯에서 A의 카운터는 2, B는 5다. 동시에 세기 시작하고 A 전송 교환은 4슬롯 동안 매체를 차지한다. 교환 뒤 재개 전에 필요한 유휴 대기는 1슬롯이다. 다른 전송·오류는 없다. B의 남은 카운터와 시작 시각은?

  1. t=0–2에 두 카운터가 함께 줄어 A=0, B=3이다. A가 t=2에 시작한다.

  2. A 교환은 t=2–6이다. B는 이 구간에서 3을 유지한다.

  3. t=6–7 유휴 대기 뒤 B는 t=7–10에 남은 3슬롯을 센다.

B의 남은 값은 3이고 t=10에 시작한다. 바쁜 시간을 세지 않으며 재시작 때 5를 다시 뽑지 않는 이 모델이다.

조건을 바꾸어 비교하기

두 번 멈추는 남은 카운터

표의 조건에서 C의 시작 시각을 구하고 4를 다시 뽑지 않는 이유를 설명하라.

  1. 처음 1슬롯을 세어 C는 3이 되고 A 교환 1–4 및 대기 4–5에서 유지한다.

  2. 5–7 동안 2를 세어 C는 1이 된다. B 교환 7–9와 대기 9–10 뒤 한 슬롯을 세어 11에 시작한다.

C는 t=11에 시작한다. 성공한 다른 단말의 교환 때문에 자기 카운터를 다시 초기화하지 않는 모형이다.

비교할 점

기본 예제의 한 번 중단을 두 번 중단으로 확장했다.

처음 시작 충돌만 센다

세 독립 추첨의 64가지에서 처음 시작이 겹치는 경우를 구하라.

  1. 유일한 최소값이 0이면 한 단말을 3가지로 고르고 나머지는 1·2·3 중 각각 골라 27가지다. 최소 1은 12가지, 최소 2는 3가지, 최소 3은 0가지다.

  2. 유일한 최소는 42가지이므로 그 반대는 22가지다. 모든 값이 서로 다른 24가지만 빼는 계산은 큰 값의 동점도 섞는다.

첫 시작의 중복은 11/32다. 일부 동점 전체는 40/64=5/8로 더 크며 두 사건은 다르다.

비교할 점

(0,2,2)는 일부 동점이 있지만 처음에는 0인 단말 하나만 시작한다.

종이와 본문으로 직접 해보기

같은 규칙에서 A=1,B=4, A 교환3슬롯, 재개 전 유휴1슬롯이면 B는 언제 시작하는가? 두 카운터가 모두2이면 무슨 가능성이 남는가?

힌트 보기

첫 전송 전 함께 감소한 양을 B에서 빼라.

풀이 보기

A는 t=1에 시작해 t=4에 끝난다. B는 남은3을 유지하고 t=4–5 대기 뒤 t=5–8을 세어 t=8에 시작한다. 모두2라면 같은 슬롯에 시작해 충돌할 수 있다.

오해와 반례

CSMA/CA에서는 충돌이 없어지고 ACK가 없으면 반드시 데이터가 충돌했다.

같은 랜덤 값이나 숨은 단말로 충돌할 수 있다. ACK 자체가 손실되어도 송신자는 성공 확인을 받지 못하므로 손실 원인을 하나로 단정할 수 없다.

연습 1 · 값과 상태 예측

A=1, B=3, C=4 시간선에서 A 교환이 3 대신 5슬롯이고 나머지 조건은 같다면 B·C는 언제 시작하는가?

힌트 1

매체가 길어진 2슬롯을 카운터 감소에 넣지 않는다.

힌트 2

이후 중단과 대기 순서는 유지된다.

풀이와 답 확인

  1. A가 1–6을 점유하고 6–7 대기 뒤 B는 남은 2를 세어 9에 시작한다.

  2. B 교환 9–11, 대기 11–12 뒤 C는 남은 1을 세어 13에 시작한다.

B는 9, C는 13에 시작한다.

흔한 오답에서 다시 생각하기

바쁜 동안도 세어 B가 3에 시작한다.

카운터는 매체 점유 중 멈춘다. A의 점유와 B의 경쟁 카운트를 합쳐 세지 않는다.

연습 2 · 오류 찾아 고치기

세 단말 중 같은 값을 뽑는 확률 5/8을 첫 교환 충돌 확률이라고 보고했다. 반례와 올바른 값을 써라.

힌트 1

큰 값만 같은 추첨을 만들라.

힌트 2

최소값이 유일한 경우 42개를 이용한다.

풀이와 답 확인

  1. 예: (0,2,2)는 A만 먼저 시작한다. B·C의 동점은 그 뒤의 별도 경쟁과 관계된다.

  2. 첫 시작에서 최소가 중복된 사건은 64−42=22개다.

이 모형의 첫 시작 중복 확률은 11/32이며 일부 동점 확률 5/8과 구별한다.

흔한 오답에서 다시 생각하기

모든 동점은 같은 순간의 첫 충돌이다.

동점이 언제의 카운터인지와 먼저 점유한 단말을 확인해야 한다.

연습 3 · 직접 만들어 보기

A가 B에게 데이터를 보냈지만 ACK를 못 받았다. 이 관찰과 양립하는 서로 다른 실패 상황 두 개를 구성하라.

힌트 1

수신 데이터의 성공과 송신 ACK의 도착은 별도다.

힌트 2

한 경우에는 데이터 성공을 유지하라.

풀이와 답 확인

  1. 경우 1: 데이터가 B에게 도달하지 않아 B가 ACK를 보내지 못한다.

  2. 경우 2: B가 데이터를 받고 ACK도 보냈으나 ACK가 A에게 도달하지 않는다.

데이터 실패와 ACK 경로 실패가 모두 가능하다. 송신 관찰만으로 데이터 충돌을 확정할 수 없다.

흔한 오답에서 다시 생각하기

ACK가 없으면 B가 데이터를 못 받았다.

ACK 자체의 손실도 가능한 모형이므로 관찰에서 원인 하나를 유일하게 역추론할 수 없다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 두 단말이 0..7에서 독립 균등 추첨한다. 처음 같은 값일 확률과 한 단말의 평균 카운터는? 세 단말의 11/32와 직접 같다고 해도 되는가?

힌트 1

전체는 8²이고 같은 값은 8개다.

힌트 2

평균은 0부터 7까지의 합을 8로 나눈다.

풀이와 답 확인

  1. 동점 확률은 8/64=1/8이다.

  2. 평균은 28/8=3.5슬롯이다. 단말 수와 선택지 수가 다른 모형이다.

1/8, 3.5슬롯이며 세 단말 네 선택지의 결과와 동일한 실험 조건으로 비교하지 않는다.

흔한 오답에서 다시 생각하기

범위를 늘렸으므로 대기와 충돌 가능성이 함께 감소한다.

동점 가능성은 줄지만 평균 초기 카운터는 1.5에서 3.5로 늘어난다.

이동 절차 두 개가 겹치면 중단 시간도 둘을 더해야 할까?

새 가상 이동은 탐색 24ms, 링크 갱신 8ms, 보안 준비 12ms, IP 준비 18ms, 전달 경로 갱신 4ms다. 링크 갱신이 끝나야 보안과 IP 준비를 시작할 수 있지만 이 문제에서는 두 준비를 동시에 수행할 수 있다고 명시한다. 두 준비가 모두 끝나야 전달 경로를 갱신하고 사용자 데이터를 재개한다.

이때 두 병렬 준비 구간은 12+18이 아니라 max(12,18)=18ms다. 모든 단계를 더하는 것은 절차가 전부 순차인 다른 모형이다. 탐색이 유효하게 미리 끝난 경우에는 중단 구간에서 24ms만 제외한다. 같은 SSID라는 사실만으로 탐색 결과 유효성이나 IP 준비 생략을 결정하지 않는다.

중단 동안에도 애플리케이션 데이터가 도착하면 버퍼가 필요하다. 별도 모형에서 빈 버퍼에 50바이트/ms로 도착하고 중단 중 전송이 전혀 없다고 정한다. 30ms 중단은 1500바이트를 쌓으며 용량 1200바이트이면 초과 300바이트를 버리는 정책이다. 이 수치는 실제 로밍 측정이나 손실률이 아니다.

찾기와 연결은 다른 단계다

AP는 비콘으로 네트워크 이름과 연결 관련 정보를 알린다. 단말은 이를 듣거나 프로브 요청·응답으로 후보를 찾는다. SSID는 네트워크 이름이고 BSSID는 특정 기본 서비스 집합을 구별하는 식별자다. 같은 이름을 표시하는 후보가 여러 개일 수 있으므로 이름이 같다는 것만으로 동일한 접속 지점이나 신뢰 대상을 뜻하지 않는다.

후보를 발견한 뒤 실제 연결을 맺는 과정이 필요하다. 링크 연결, 보안 절차, IP 구성과 경로, 인터넷의 목적지 도달 여부는 구분한다. 화면에서 Wi-Fi에 연결되었다고 표시되어도 주소 설정이나 상위 연결이 실패할 수 있다. 각 단계의 실패를 따로 찾으면 문제를 좁힐 수 있다.

이동은 여러 계층의 상태를 바꿀 수 있다

AP를 바꾸는 링크 계층 이동은 같은 IP 서브넷 안에서 이루어질 수도 있고 다른 서브넷으로 이어질 수도 있다. 같은 서브넷을 제공하는 AP 사이 이동이라면 AP 변경만으로 IP 변경을 반드시 요구하지 않는다. 다른 서브넷으로 간다면 주소·경로와 세션 유지 문제가 추가된다. 같은 SSID라도 두 환경은 다를 수 있다.

탐색과 연결 갱신 중에는 프레임 전달이 지연되거나 끊길 수 있다. 미리 후보를 찾으면 실제 이동 시 탐색을 줄일 여지가 있지만 오래된 후보 정보가 현재 신호 상황을 반영하지 못할 수 있다. RFC 4260의 오래된 구현 지연 수치는 현재 모든 Wi-Fi의 수치가 아니므로 여기서는 자체 가상 시간만 계산한다.

무선 구간 보호와 인터넷 종단 보호를 구별한다

보안 설정에 따라 연결 뒤 또는 연결 과정에서 인증과 키 설정이 이어진다. 802.11의 인증이라는 프레임 이름만으로 신뢰할 상대의 신원이 검증되었다고 판단하지 않는다. RFC 8110은 OWE가 무선 구간을 암호화하지만 상대 신원 인증을 제공하지 않는다는 차이를 설명한다. 이론에서 용어 이름과 실제 보장을 함께 확인한다.

무선 구간의 암호화만으로 인터넷 서버까지 전체 경로가 보호되는 것은 아니다. 링크 보안과 HTTPS 같은 종단 간 보호는 적용 구간이 다르다. 접속 이름만 보고 보호 여부를 추정하는 대신 필요한 보장의 범위를 구분하는 것이 이 단원의 목표다.

중간 과정을 따라가는 예제

가상 이동에서 탐색30ms, 링크 연결 갱신10ms, 보안 단계20ms, 전달 경로 갱신5ms가 순서대로 필요하며 모두 통신 중단 구간에 있다. 같은 IP 서브넷이라 추가 주소 설정은 없다. 총 중단 시간은?

  2. 탐색30ms를 유효한 상태로 미리 끝내고 나머지는 같다면 중단 구간은10+20+5=35ms다.

  3. 미리 탐색했다는 사실만으로 후보가 이동 시에도 유효하다는 보장은 없다.

모델의 중단 시간은65ms, 유효한 사전 탐색 가정에서는35ms다. 실제 Wi-Fi 속도 측정이나 모든 로밍 방식의 시간 보장이 아니다.

병렬 단계의 긴 쪽을 기다린다

새 모형의 일반 중단과 사전 탐색 중단 시간을 구하라.

  1. 일반 경우 24+8+max(12,18)+4=54ms다.

  2. 유효 사전 탐색을 가정하면 8+18+4=30ms다. 전부 순차인 별도 모형은 24+8+12+18+4=66ms다.

이번 병렬 모형은 54ms와 30ms이며 순차 모형 66ms와 구별한다.

비교할 점

단계 숫자만 같아도 의존 관계가 달라지면 중단 시간이 달라진다.

중단 중 데이터가 쌓인다

사전 탐색 모형에서 중단은 30 ms다. 도착률은 50 바이트/ms이고 초기 버퍼는 비어 있다. 버퍼 용량은 1200 바이트이며 초과분은 폐기한다. 보관량과 폐기량은 얼마인가?

  1. 중단 중 서비스가 0이므로 도착량은 30×50=1500바이트다.

  2. 버퍼에는 1200 바이트를 남기고 초과한 300 바이트를 버린다. 이 가정에서 모든 도착 데이터를 보존하려면 최소 1500 바이트의 용량이 필요하다.

보관량은 1200 바이트이고 폐기량은 300 바이트다. 서비스 재개 후의 배출 속도가 주어지지 않았으므로 버퍼를 비우는 시간은 아직 구할 수 없다.

연습 1 · 값과 상태 예측

같은 의존 관계에서 IP 준비가 18에서 6ms로 줄면 사전 탐색 후 중단 길이는?

힌트 1

보안은 여전히 12ms다.

힌트 2

두 준비 중 긴 쪽이 경로 갱신 시작을 결정한다.

풀이와 답 확인

  1. max(12,6)=12ms를 기다린다.

  2. 8+12+4=24ms다.

중단 길이는 24 ms다. IP 준비 시간을 12 ms 줄여도 중단 길이는 30 ms에서 24 ms로 6 ms만 줄어든다.

  2. 사전 스캔을 제외하는 계산에는 후보가 현재에도 유효하다는 별도 가정이 필요하다.

  2. 링크 연결, 필요한 인증·키 설정, IP·경로, 목적지 서버 응답은 각각 별도 확인 항목으로 남긴다.

발견만 확인했으면 나머지 네 항목은 미확인이다. OWE가 사용되어도 상대 신원 인증이나 종단 보호를 자동 완료 처리하지 않는다.

  2. 사전 탐색 모형의 중단 30 ms에서 폐기한 300 바이트보다 1200 바이트를 더 버린다.

일반 모형의 보관량은 1200 바이트이고 폐기량은 1500 바이트다. 사전 탐색 모형보다 폐기량이 1200 바이트 증가한다.

같은 자원 수를 주는 정책이 두 대기열을 모두 비울까?

새 가상 기지국은 1 ms 구간마다 총 10개 자원을 쓰며, 그중 2개는 제어용으로 예약한다. 데이터에는 8개 자원만 남는다. A는 자원당 100 바이트, B는 자원당 50 바이트를 보낸다. 대기 데이터는 A가 300 바이트, B가 250 바이트이며 추가 도착이나 오류는 없다. 실제 NR 자원 단위의 전송량이나 자원 격자를 재현한 것은 아니다.

수요를 모두 처리하려면 A에 3개, B에 5개 자원이 필요하므로 정확히 8개가 든다. 반씩 4개를 주면 A에는 300 바이트의 데이터만 있고, 남는 한 자원은 다른 단말에 재배정하지 않는 모형이다. B는 200 바이트만 보내므로 50 바이트가 남는다. 공평한 자원 개수와 수요의 완료는 서로 다른 목표다.

무선 자원 배정은 gNB의 역할이고, 사용자 데이터의 코어 전달에는 UPF가 관여한다. AMF와 SMF의 제어 역할을 모든 사용자 패킷이 순차로 통과하는 경로와 혼동하지 않는다. 무선 전달이 1 ms에 완료되어도 외부 망이나 서버 응답까지 1 ms에 완료된다는 뜻은 아니다.

무선 접속망 뒤에 코어망이 있다

셀룰러는 공간을 셀로 나누어 무선 접속을 제공하고 이동을 관리한다. 5G 개요에서는 단말 UE가 무선 접속망 RAN의 기지국 gNB와 통신하고 코어망을 통해 외부 데이터망으로 연결된다고 본다. 기지국은 전파를 받을 뿐 아니라 무선 자원 배정과 측정·이동 관련 역할을 가진다.

코어의 주요 기능 중 AMF는 접속과 이동 관련 제어, SMF는 데이터 세션 관리, UPF는 사용자 데이터 전달을 맡는다. 기능 간 제어 정보 흐름과 실제 사용자 패킷 경로를 구별해야 한다. 예컨대 영상 데이터가 모두 AMF를 순서대로 통과한다고 그리는 것은 역할을 혼동한 것이다. 이는 전체 표준의 모든 기능을 생략한 개요다.

무선 링크도 작은 계층들이 협력한다

5G NR의 물리 계층은 비트를 전파 신호로 표현하고 복원한다. 그 위에는 자원 배정·전송 관련 MAC, 분할·재조립 등을 맡는 RLC, 상위 데이터의 순서·보호 등을 담당하는 PDCP, QoS 흐름을 무선 베어러에 연결하는 SDAP 같은 기능이 있다. 모든 모드에서 모든 재전송과 기능이 같은 방식으로 켜져 있다는 뜻은 아니다.

기지국의 스케줄링은 제한된 시간·주파수 자원을 단말과 흐름에 배정한다. 단말의 신호 품질과 데이터 수요가 다르므로 같은 수의 자원이 반드시 같은 바이트 양으로 바뀌지는 않는다. 아래는 한 자원의 전송량을 일정하게 고정하여 역할만 이해하는 가상 모형이다.

신호 측정에서 이동 결정과 전달 갱신으로

연결 상태의 이동에서는 단말이 주변 셀의 신호 품질 등을 보고하고 망이 이를 바탕으로 이동을 제어한다. 대상 기지국 준비와 연결 전환, 데이터 전달 상태 처리가 필요하다. 정확한 절차와 중단 시간은 구성에 따라 달라지며 새 셀의 신호가 조금 강해졌다는 이유만으로 항상 즉시 전환하는 것은 아니다.

전파 조건이 바뀌면 재시도와 지연이 늘고 자원도 더 소비될 수 있다. 자원 배정을 받았다는 사실과 종단 서버 응답 시간이 짧다는 사실은 다르다. 전체 경로에는 코어와 외부 망, 서버도 있기 때문이다. 셀룰러는 주로 망이 관리하는 접속을 배우는 예이며 모든 사용 주파수가 반드시 면허 대역뿐이라는 주장도 하지 않는다.

중간 과정을 따라가는 예제

가상 기지국은1ms마다12개 자원을 배정한다. 한 자원은 두 단말 모두에게100바이트의 유효 데이터를 전달한다고 정한다. A에8개,B에4개를 주고 다른 overhead·오류는 없다. 각 양과 속도는?

  1. A는8×100=800바이트, B는4×100=400바이트다.

  2. 1ms=0.001s이므로 A는800000바이트/s, B는400000바이트/s다.

  3. 8비트/바이트를 적용하면 A6.4Mbit/s, B3.2Mbit/s다. M은10의6승이다.

가정한 합은1200바이트/ms 또는9.6Mbit/s다. 실제5G 제품 속도나 전파 조건과 무관한 보장이 아니다.

조건을 바꾸어 비교하기

같은 개수와 수요 완료를 비교한다

원래 링크 조건에서 A/B에 각각 4/4개를 주는 정책과 3/5개를 주는 정책을 계산하라.

  1. 4/4 배정의 잠재 전송량은 A가 400 바이트, B가 200 바이트다. A의 수요는 300 바이트이므로 유효 전송량의 합은 300+200=500 바이트이며 B에 50 바이트가 남는다.

  2. 3/5 배정은 A의 300 바이트와 B의 250 바이트를 보내므로 유효 전송량의 합이 550 바이트다. 두 대기열이 모두 비워진다.

유효 전송량의 합은 각각 500 바이트와 550 바이트다. 제어용 자원 2개를 데이터 용량에 더하지 않는다.

무선 완료와 종단 응답을 나눈다

가상 요청 경로의 무선 전달은 2 ms, 코어와 외부 망 전달은 3 ms, 서버 처리는 4 ms이며 순차로 진행한다. 응답 방향의 시간은 여기서 제외한다. 서버 처리 완료까지 얼마인가?

  1. 정의된 세 구간을 더하면 2+3+4=9 ms다.

  2. 무선 전달만 1 ms로 줄이고 다른 구간은 같으면 1+3+4=8 ms다.

편도 전달 후 서버 처리 완료까지 9 ms이고 개선 후에는 8 ms다. 왕복 응답 시간은 별도로 주어지지 않았다.

연습 1 · 값과 상태 예측

원래 데이터 자원 8개에서 A에 5개, B에 3개를 주고 재배정하지 않으면 각 유효 전송량과 남은 데이터는 얼마인가?

힌트 1

A에는 300 바이트보다 더 보낼 데이터가 없다.

힌트 2

B의 자원당 전송량은 50 바이트다.

풀이와 답 확인

  1. A는 잠재 전송량 500 바이트 중 300 바이트를 보내고 남은 데이터가 0 바이트다.

  2. B는 150 바이트를 보내고 100 바이트가 남는다.

A는 300 바이트, B는 150 바이트를 보내며 B에 100 바이트가 남는다. A 자원 2개는 이 정책에서 수요를 넘는다.

흔한 오답에서 다시 생각하기

총 잠재 전송량이 650 바이트이므로 대기 데이터 550 바이트를 모두 처리한다.

서로 다른 단말의 용량은 자동으로 섞이지 않는다. 재배정을 허용하지 않은 조건을 적용한다.

풀이와 답 확인

  2. A에 3개, B에 5개를 주면 합이 8개이며 수요 300 바이트와 250 바이트를 모두 보낸다.

역할은 달라도 같은 주어진 자원 예산을 소비한다. 역할 구분과 용량 합산을 함께 해야 한다.

힌트 1

힌트 2

개요는 모든 세부 네트워크 기능을 다 나열하지 않는다.

풀이와 답 확인

  1. 사용자 데이터의 개요 경로는 UE→gNB/RAN→UPF→외부 데이터망이다.

  2. AMF는 접속·이동 관련 제어, SMF는 데이터 세션 제어로 따로 설명한다.

사용자 경로에 AMF·SMF를 직렬 영상 중계기로 넣지 않고 기능의 제어 관계로 구별한다.

흔한 오답에서 다시 생각하기

영상 데이터가 UE→AMF→SMF→UPF 순서로 간다.

주요 제어 기능의 이름을 사용자 데이터가 반드시 통과하는 직렬 경로로 바꾸지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

B의 전송량이 자원당 25 바이트로 바뀌면 원래 수요를 한 구간에 모두 처리할 수 있는가? 제어용 자원 2개와 A의 수요는 그대로다.

힌트 1

A에 필요한 자원 3개를 먼저 계산한다.

힌트 2

B에 필요한 데이터 자원 수는 250/25개다.

풀이와 답 확인

  1. A에는 3개, B에는 10개가 필요하므로 데이터 자원 요구량의 합은 13개다.

  2. 이는 데이터 예산 8개보다 5개 많으며 제어용 자원까지 합하면 총 15개가 필요하다.

한 구간에 모두 처리할 수 없다. 데이터 자원 13개가 필요하지만 8개뿐이다. 전송량 감소로 주어진 수요를 완료하지 못한다.

흔한 오답에서 다시 생각하기

같은 자원 8개를 공평하게 나누면 반드시 모두 완료한다.

배정 목표를 바꾸어도 합계 자원 요구량 13개를 8개로 줄일 수 없다.

내 말로 설명하기

원래 4/4 배정에서 A의 전송량이 400 바이트가 아닌 이유는?

설명 기준 확인

대기 데이터가 300 바이트뿐이다. 잠재 용량과 유효 송신량을 구별하고 남는 용량을 자동으로 재배정하지 않는다.

gNB가 자원을 주면 외부 응답 시간도 정해지는가?

설명 기준 확인

무선 구간뿐 아니라 코어·외부 망·서버와 응답 방향 조건이 필요하다.

한 단계 더

가상 이동에서 대상 준비4ms, 연결 전환6ms, 전달 경로 처리2ms가 순차라면12ms다. 준비4ms를 기존 연결 중 미리 끝내고 나머지 동안만 데이터가 멈춘다고 정하면 중단은8ms다. 실제 핸드오버 방식의 측정값으로 제시하지 않고 준비 비용과 서비스 중단을 구별해 보자.

다른 문제에 적용하기

모형 A는 유효한 사전 탐색 후 링크 갱신에 8 ms가 걸린다. 보안 준비 12 ms와 IP 준비 18 ms는 병렬로 진행하고, 둘 다 완료되면 경로 갱신에 4 ms가 걸린다. 초기 빈 버퍼에 50 바이트/ms로 도착하며 용량은 1200 바이트다. 중단 중 서비스는 0이고 초과분은 폐기한다. 모형 B는 같은 단말이 기지국으로 이동해 총 자원 10개 중 2개를 제어에 쓴다. 데이터 자원당 100 바이트를 얻으며 다음 1 ms 구간에 남은 1200 바이트만 전송한다. 실제 세션 연속성을 보장하지 않는 별도 비교다. A의 중단 길이와 폐기량, B의 한 구간 전송량과 잔량을 구하라. SSID나 강한 신호만으로 추가 보장을 하지 않도록 설명하라.

힌트 1

A의 병렬 준비에서는 긴 쪽이 끝날 때까지 기다린다.

힌트 2

B의 데이터 예산은 제어용 자원을 뺀 8개다.

풀이와 답 확인

  1. A의 중단 길이는 8+max(12,18)+4=30 ms다. 도착량 1500 바이트 중 1200 바이트를 보관하고 300 바이트를 버린다.

  2. B는 한 구간에 8×100=800 바이트를 보내고 1200−800=400 바이트가 남는다.

  3. SSID만으로 서브넷, 상대 인증 또는 세션 유지를 결론내리지 않는다. 강한 신호나 무선 자원만으로 종단 응답 시간을 보장하지 않는다.

A의 중단 길이는 30 ms, 보관량은 1200 바이트, 폐기량은 300 바이트다. B는 한 구간에 800 바이트를 보내고 400 바이트가 남는다. 두 모형은 실제 연결을 연속 시험한 결과가 아니며 외부 서비스 완료 시간에는 추가 조건이 필요하다.

해결한 뒤 점검할 것

  • 병렬 준비와 순차 단계의 의존 관계를 적용한다.

  • 버퍼에 남은 양과 기지국 자원의 유효 송신량을 별도로 계산한다.

  • 무선 연결, 암호화, 인증, IP 및 종단 경로의 보장 범위를 구별한다.
