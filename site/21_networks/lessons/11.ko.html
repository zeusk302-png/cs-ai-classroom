소단원 11.1

무선 매체와 충돌 회피

내 자리에서는 조용한데 상대는 왜 두 사람의 목소리를 동시에 들을까?

준비 개념과 학습 목표

준비 개념

  • 프레임과 MAC 계층
  • 전송 시간
  • 공유 매체

학습 목표

  • 송신 위치와 수신 위치의 감지 차이를 설명한다.
  • 가상 백오프 카운터를 추적한다.
  • ACK와 RTS/CTS가 보장하지 않는 것까지 구별한다.

공기를 공유하면 수신 위치도 중요하다

무선에서는 거리·장애물·간섭에 따라 각 단말이 감지하는 신호가 다르다. A와 C는 서로 듣지 못하지만 둘 다 B에 도달할 수 있다. A가 B로 보내는 동안 C가 자기 주변을 조용하다고 판단해 보내면 B에서 두 신호가 겹칠 수 있다. 이것이 숨은 단말 문제다. 송신자 주변의 감지만으로 수신 성공을 확정할 수 없다.

기본적인 반이중 무선 통신에서는 전송하면서 수신 위치의 충돌을 유선 공유 Ethernet처럼 즉시 검출하기 어렵다. 수신 확인과 재시도, 전송 시점 조절이 필요하다. 이 단원은 경쟁 기반 접근의 원리를 다루며 현대 Wi-Fi의 모든 전송이 반드시 한 단말씩 경쟁한다는 설명은 아니다.

랜덤하게 기다리고 바쁜 동안 카운터를 멈춘다

CSMA/CA의 경쟁 접근은 매체를 감지하고 필요한 대기 조건을 지킨 뒤 랜덤 백오프를 적용한다. 비어 있는 슬롯에서 카운터를 줄이고 다른 전송이 시작되면 멈춘다. 다시 필요한 유휴 조건이 충족되면 남은 카운터부터 진행한다. 카운터가 같아 동시에 시작하는 경우도 있으므로 충돌 회피는 충돌 불가능을 뜻하지 않는다.

수신 확인을 못 받으면 재시도를 고려하며 대기 범위를 늘려 반복 경쟁을 줄일 수 있다. ACK가 없다는 사실은 성공을 확인하지 못했다는 뜻이다. 데이터 손실뿐 아니라 ACK 자체의 손실도 가능하다. 아래 예제는 대기 간격·프레임 시간을 실제 표준 수치 대신 별도로 지정한 가상 슬롯 모델이다.

수신자 쪽 소식을 이용해 예약한다

선택적인 RTS/CTS에서는 송신자의 짧은 전송 요청에 수신자가 허가 메시지를 돌려준다. 수신자 근처에서 CTS를 들은 다른 단말은 표시된 기간 동안 전송을 미룬다. 이 정보는 송신자를 듣지 못하는 숨은 단말에도 도움이 될 수 있다. 그러나 제어 프레임도 충돌하거나 손실될 수 있고 예약에 시간이 드므로 항상 유리하지는 않다.

최신 Wi-Fi에는 AP가 여러 단말의 시간·주파수 자원을 배정하는 방식도 있다. RFC 9913은 802.11ax의 AP 기반 OFDMA와 채널 확보를 함께 설명한다. 경쟁 접근의 기본 원리를 배웠다고 모든 최신 자원 배정과 동시 전송을 동일한 모형에 넣으면 안 된다.

중간 과정을 따라가는 예제

가상 슬롯에서 A의 카운터는 2, B는 5다. 동시에 세기 시작하고 A 전송 교환은 4슬롯 동안 매체를 차지한다. 교환 뒤 재개 전에 필요한 유휴 대기는 1슬롯이다. 다른 전송·오류는 없다. B의 남은 카운터와 시작 시각은?

  1. t=0–2에 두 카운터가 함께 줄어 A=0, B=3이다. A가 t=2에 시작한다.
  2. A 교환은 t=2–6이다. B는 이 구간에서 3을 유지한다.
  3. t=6–7 유휴 대기 뒤 B는 t=7–10에 남은 3슬롯을 센다.

B의 남은 값은 3이고 t=10에 시작한다. 바쁜 시간을 세지 않으며 재시작 때 5를 다시 뽑지 않는 이 모델이다.

종이와 본문으로 직접 해보기

같은 규칙에서 A=1,B=4, A 교환3슬롯, 재개 전 유휴1슬롯이면 B는 언제 시작하는가? 두 카운터가 모두2이면 무슨 가능성이 남는가?

힌트 보기

첫 전송 전 함께 감소한 양을 B에서 빼라.

풀이 보기

A는 t=1에 시작해 t=4에 끝난다. B는 남은3을 유지하고 t=4–5 대기 뒤 t=5–8을 세어 t=8에 시작한다. 모두2라면 같은 슬롯에 시작해 충돌할 수 있다.

오해와 반례

CSMA/CA에서는 충돌이 없어지고 ACK가 없으면 반드시 데이터가 충돌했다.

같은 랜덤 값이나 숨은 단말로 충돌할 수 있다. ACK 자체가 손실되어도 송신자는 성공 확인을 받지 못하므로 손실 원인을 하나로 단정할 수 없다.

한 단계 더

소단원 11.2

Wi-Fi 접속과 이동성

Wi-Fi 이름이 그대로인데 왜 이동 중 통신이 잠깐 멈출까?

준비 개념과 학습 목표

준비 개념

  • AP와 프레임
  • IP 주소와 서브넷
  • 계층별 연결

학습 목표

  • 탐색·연결·보안·IP 구성을 구분한다.
  • SSID와 접속 대상을 구별한다.
  • AP 이동과 IP 이동이 항상 같은 사건이 아님을 설명한다.

찾기와 연결은 다른 단계다

AP는 비콘으로 네트워크 이름과 연결 관련 정보를 알린다. 단말은 이를 듣거나 프로브 요청·응답으로 후보를 찾는다. SSID는 네트워크 이름이고 BSSID는 특정 기본 서비스 집합을 구별하는 식별자다. 같은 이름을 표시하는 후보가 여러 개일 수 있으므로 이름이 같다는 것만으로 동일한 접속 지점이나 신뢰 대상을 뜻하지 않는다.

후보를 발견한 뒤 실제 연결을 맺는 과정이 필요하다. 링크 연결, 보안 절차, IP 구성과 경로, 인터넷의 목적지 도달 여부는 구분한다. 화면에서 Wi-Fi에 연결되었다고 표시되어도 주소 설정이나 상위 연결이 실패할 수 있다. 각 단계의 실패를 따로 찾으면 문제를 좁힐 수 있다.

이동은 여러 계층의 상태를 바꿀 수 있다

AP를 바꾸는 링크 계층 이동은 같은 IP 서브넷 안에서 이루어질 수도 있고 다른 서브넷으로 이어질 수도 있다. 같은 서브넷을 제공하는 AP 사이 이동이라면 AP 변경만으로 IP 변경을 반드시 요구하지 않는다. 다른 서브넷으로 간다면 주소·경로와 세션 유지 문제가 추가된다. 같은 SSID라도 두 환경은 다를 수 있다.

탐색과 연결 갱신 중에는 프레임 전달이 지연되거나 끊길 수 있다. 미리 후보를 찾으면 실제 이동 시 탐색을 줄일 여지가 있지만 오래된 후보 정보가 현재 신호 상황을 반영하지 못할 수 있다. RFC 4260의 오래된 구현 지연 수치는 현재 모든 Wi-Fi의 수치가 아니므로 여기서는 자체 가상 시간만 계산한다.

무선 구간 보호와 인터넷 종단 보호를 구별한다

보안 설정에 따라 연결 뒤 또는 연결 과정에서 인증과 키 설정이 이어진다. 802.11의 인증이라는 프레임 이름만으로 신뢰할 상대의 신원이 검증되었다고 판단하지 않는다. RFC 8110은 OWE가 무선 구간을 암호화하지만 상대 신원 인증을 제공하지 않는다는 차이를 설명한다. 이론에서 용어 이름과 실제 보장을 함께 확인한다.

무선 구간의 암호화만으로 인터넷 서버까지 전체 경로가 보호되는 것은 아니다. 링크 보안과 HTTPS 같은 종단 간 보호는 적용 구간이 다르다. 접속 이름만 보고 보호 여부를 추정하는 대신 필요한 보장의 범위를 구분하는 것이 이 단원의 목표다.

중간 과정을 따라가는 예제

가상 이동에서 탐색30ms, 링크 연결 갱신10ms, 보안 단계20ms, 전달 경로 갱신5ms가 순서대로 필요하며 모두 통신 중단 구간에 있다. 같은 IP 서브넷이라 추가 주소 설정은 없다. 총 중단 시간은?

  1. 순차 단계이므로 30+10+20+5=65ms다.
  2. 탐색30ms를 유효한 상태로 미리 끝내고 나머지는 같다면 중단 구간은10+20+5=35ms다.
  3. 미리 탐색했다는 사실만으로 후보가 이동 시에도 유효하다는 보장은 없다.

모델의 중단 시간은65ms, 유효한 사전 탐색 가정에서는35ms다. 실제 Wi-Fi 속도 측정이나 모든 로밍 방식의 시간 보장이 아니다.

종이와 본문으로 직접 해보기

다른 IP 서브넷으로 이동해 추가 주소·경로 준비가15ms 걸리고 전부 순차라면 위 두 경우 총 시간은? 이름이 같으면 이 추가 단계가 없어지는가?

힌트 보기

같은 SSID와 같은 IP 서브넷은 별개의 조건이다.

풀이 보기

65+15=80ms와35+15=50ms다. 같은 이름이라는 정보만으로 IP 서브넷이 같은지 알 수 없어 추가 작업을 없다고 결론낼 수 없다.

오해와 반례

같은 SSID로 이동하면 IP 주소와 모든 세션이 반드시 그대로 유지된다.

SSID는 이름이다. AP들의 서브넷 구성과 이동 지원, 경로와 상위 세션 조건이 달라질 수 있다. 같은 서브넷의 AP 변경과 다른 서브넷으로의 이동을 따로 판단한다.

자기점검

비콘을 발견하면 바로 인터넷 사용이 보장되는가?

답과 이유 보기

아니다.

연결과 보안·IP·상위 경로를 별도로 확인한다.

OWE의 무선 암호화가 상대 신원 인증도 뜻하는가?

답과 이유 보기

아니다.

RFC 8110은 두 보장을 구별한다.

AP 변경이 항상 IP 서브넷 변경인가?

답과 이유 보기

아니다.

여러 AP가 같은 서브넷을 제공할 수 있다.

한 단계 더

종이에 후보 AP 두 개의 이름은 같은 것으로, BSSID는 다른 것으로 적고 같은 서브넷인 경우와 다른 서브넷인 경우를 각각 그려 보자. 어느 계층의 상태를 확인해야 하는지 설명한다. 실제 접속 변경이나 인증 실험을 요구하지 않는다.

  • 단말·무선 접속망·코어망의 역할을 연결한다.
  • 5G 주요 기능과 사용자 데이터 경로를 구분한다.
  • 자원 배정과 이동성의 조건을 가상 모형으로 해석한다.

무선 접속망 뒤에 코어망이 있다

셀룰러는 공간을 셀로 나누어 무선 접속을 제공하고 이동을 관리한다. 5G 개요에서는 단말 UE가 무선 접속망 RAN의 기지국 gNB와 통신하고 코어망을 통해 외부 데이터망으로 연결된다고 본다. 기지국은 전파를 받을 뿐 아니라 무선 자원 배정과 측정·이동 관련 역할을 가진다.

코어의 주요 기능 중 AMF는 접속과 이동 관련 제어, SMF는 데이터 세션 관리, UPF는 사용자 데이터 전달을 맡는다. 기능 간 제어 정보 흐름과 실제 사용자 패킷 경로를 구별해야 한다. 예컨대 영상 데이터가 모두 AMF를 순서대로 통과한다고 그리는 것은 역할을 혼동한 것이다. 이는 전체 표준의 모든 기능을 생략한 개요다.

무선 링크도 작은 계층들이 협력한다

5G NR의 물리 계층은 비트를 전파 신호로 표현하고 복원한다. 그 위에는 자원 배정·전송 관련 MAC, 분할·재조립 등을 맡는 RLC, 상위 데이터의 순서·보호 등을 담당하는 PDCP, QoS 흐름을 무선 베어러에 연결하는 SDAP 같은 기능이 있다. 모든 모드에서 모든 재전송과 기능이 같은 방식으로 켜져 있다는 뜻은 아니다.

기지국의 스케줄링은 제한된 시간·주파수 자원을 단말과 흐름에 배정한다. 단말의 신호 품질과 데이터 수요가 다르므로 같은 수의 자원이 반드시 같은 바이트 양으로 바뀌지는 않는다. 아래는 한 자원의 전송량을 일정하게 고정하여 역할만 이해하는 가상 모형이다.

신호 측정에서 이동 결정과 전달 갱신으로

연결 상태의 이동에서는 단말이 주변 셀의 신호 품질 등을 보고하고 망이 이를 바탕으로 이동을 제어한다. 대상 기지국 준비와 연결 전환, 데이터 전달 상태 처리가 필요하다. 정확한 절차와 중단 시간은 구성에 따라 달라지며 새 셀의 신호가 조금 강해졌다는 이유만으로 항상 즉시 전환하는 것은 아니다.

전파 조건이 바뀌면 재시도와 지연이 늘고 자원도 더 소비될 수 있다. 자원 배정을 받았다는 사실과 종단 서버 응답 시간이 짧다는 사실은 다르다. 전체 경로에는 코어와 외부 망, 서버도 있기 때문이다. 셀룰러는 주로 망이 관리하는 접속을 배우는 예이며 모든 사용 주파수가 반드시 면허 대역뿐이라는 주장도 하지 않는다.

중간 과정을 따라가는 예제

가상 기지국은1ms마다12개 자원을 배정한다. 한 자원은 두 단말 모두에게100바이트의 유효 데이터를 전달한다고 정한다. A에8개,B에4개를 주고 다른 overhead·오류는 없다. 각 양과 속도는?

  1. A는8×100=800바이트, B는4×100=400바이트다.
  2. 1ms=0.001s이므로 A는800000바이트/s, B는400000바이트/s다.
  3. 8비트/바이트를 적용하면 A6.4Mbit/s, B3.2Mbit/s다. M은10의6승이다.

가정한 합은1200바이트/ms 또는9.6Mbit/s다. 실제5G 제품 속도나 전파 조건과 무관한 보장이 아니다.

종이와 본문으로 직접 해보기

같은12자원을 두 단말에6개씩 주되 A는100바이트/자원, B는50바이트/자원을 전달할 수 있다면 각각 몇 바이트인가? 같게 배정하면 같은 전송량인가?

힌트 보기

자원 수와 자원당 전송량을 따로 곱하라.

풀이 보기

A600바이트,B300바이트이며 합900바이트/ms다. 자원은 같아도 전송량은 다르다. 위 모형과 달리 신호 조건에 따른 차이를 정한 것이다.

오해와 반례

기지국에 자원을 배정받으면 모든 사용자 데이터가 AMF를 지나고 인터넷 응답 시간도 보장된다.

AMF는 접속·이동 제어 기능이며 사용자 데이터 전달에는 UPF가 관여한다. 무선 구간 배정만으로 외부 망과 서버까지의 지연을 결정할 수 없다.

한 단계 더

가상 이동에서 대상 준비4ms, 연결 전환6ms, 전달 경로 처리2ms가 순차라면12ms다. 준비4ms를 기존 연결 중 미리 끝내고 나머지 동안만 데이터가 멈춘다고 정하면 중단은8ms다. 실제 핸드오버 방식의 측정값으로 제시하지 않고 준비 비용과 서비스 중단을 구별해 보자.
