소단원 10.1

프레임·MAC·CRC

봉투의 주소가 맞아도 내용이 손상되었다면 어떻게 알아챌까?

준비 개념과 학습 목표

준비 개념

  • 비트·바이트

  • XOR: 같은 비트끼리는 0, 다른 비트끼리는 1

학습 목표

  • 프레임과 IP 패킷의 범위를 구별한다.

  • MAC 주소와 FCS의 역할을 설명한다.

  • 작은 생성다항식으로 CRC를 직접 계산한다.

나머지가 같은 두 수신열을 정상과 손상으로 구분할 수 있을까?

교육용 생성 비트열 1011을 그대로 쓰되 새 메시지를 10101로 정한다. 차수가 3이므로 검사값은 세 비트다. 10101000을 나누면 나머지는 101이고, 전송열은 10101101이다. 아래 계산은 XOR 다항식 모형이며 실제 Ethernet CRC-32의 초기값이나 비트 순서를 구현한 것은 아니다.

오류열은 뒤집힌 위치에만 1을 둔다. 전송열에 오류열을 XOR하면 수신열이 된다. 정상 전송열의 나머지는 0이므로 수신 나머지는 오류열의 나머지와 같다. 이 관계를 이용하면 메시지를 매번 다시 만들지 않고도 어떤 오류가 검출되는지 설명할 수 있다.

생성 비트열 1011을 옮겨 놓은 오류는 나누어떨어진다. 더 놀랍게도 이 여덟 비트 모형에서 맨 앞과 맨 뒤만 뒤집는 10000001도 나머지가 0이다. 따라서 모든 두 비트 오류가 검출된다는 말은 틀리다. 같은 검사 결과는 같은 내용이나 송신자의 신원을 뜻하지 않는다.

한 링크에서 보내는 봉투

IP 패킷이 여행의 내용물이라면 링크 프레임은 한 구간에서 사용할 봉투다. Ethernet II의 기본 주소는 목적지와 출발지 MAC이며 각각 6바이트다. MAC 48비트는 8비트씩 여섯 묶음이다. 네트워크 계층 주소와 같은 항목이 아니며 MAC 주소만으로 인터넷 경로가 결정되지 않는다.

여기서는 태그 없는 Ethernet II에서 목적지 6, 출발지 6, EtherType 2, 데이터, FCS 4바이트를 센다. 프리앰블과 프레임 사이 간격은 이 계산에서 제외한다. 상위 패킷의 바이트와 링크 헤더를 함께 세는 것은 어느 구간의 크기를 구하는지 먼저 정한 뒤에 한다.

주소와 오류 검사는 다른 질문

MAC 주소는 이 링크에서 어떤 인터페이스에 전달할지를 식별하는 데 쓰인다. FCS는 전송 중 비트 손상을 검사할 중복 정보이며 Ethernet에서는 32비트 CRC를 넣는다. 주소가 맞았다는 사실과 내용이 손상되지 않았다는 판단은 독립적인 질문이다.

CRC의 수학을 보기 위해 아래에서는 Ethernet CRC-32 대신 3비트 나머지를 붙이는 작은 모형을 쓴다. 생성 비트열 1011은 x³+x+1을 나타낸다. 일반 정수 나눗셈과 달리 빼기를 XOR로 수행하고 자리올림이나 빌림을 하지 않는다. 실제 Ethernet의 초기값·비트 처리·최종 변환을 이 모형으로 구현했다고 주장하지 않는다.

검출과 인증의 경계

메시지 뒤에 생성다항식 차수만큼 0을 붙여 나눈 나머지를 그 자리에 넣는다. 이렇게 만든 전송 다항식은 생성다항식으로 나누어떨어진다. 수신 나머지가 0이 아니면 이 모형에서는 오류를 검출한다.

나머지가 0이라고 모든 손상이 없었다고 증명되지는 않는다. 오류 다항식 자체가 생성다항식의 배수이면 변형 후에도 나누어떨어진다. 누구나 새 CRC를 계산할 수도 있으므로 CRC는 비밀 키를 가진 송신자의 인증을 제공하지 않는다. 손상 검출, 재전송, 암호 인증의 목적을 구분해야 한다.

각 행은 독립 실험이다. 첫 번째 수신열에 다음 오류를 누적하지 않는다. 000은 검사가 통과했다는 뜻이며 원래 내용과 같다는 증명은 아니다.

중간 과정을 따라가는 예제

교육 CRC에서 메시지 1101, 생성 비트열 1011을 사용한다. 전송할 7비트와 수신 검사 나머지를 구하라.

  1. 차수는 3이므로 1101000을 만든다.

  2. 왼쪽 1에 맞춰 XOR한다: 1101000 XOR 1011000 = 0110000.

  3. 이어 0110000 XOR 0101100 = 0011100, 0011100 XOR 0010110 = 0001010이다.

  4. 0001010 XOR 0001011 = 0000001이므로 3자리 나머지는 001이다.

  5. 전송열 1101001을 같은 순서로 나누면 마지막 0001011 XOR 0001011 = 0000000이 된다.

1101001을 보낸다. 메시지 4비트 뒤에 나머지 001을 붙였고 수신 검사 나머지는 000이다.

조건을 바꾸어 비교하기

새 메시지의 검사값을 만든다

메시지 10101에 생성 비트열 1011의 교육 CRC를 붙여라.

  1. 10101000 XOR 10110000 = 00011000이다. 다음으로 00011000 XOR 00010110 = 00001110이다.

  2. 00001110 XOR 00001011 = 00000101이므로 나머지는 101이다. 이를 패딩 자리에 넣으면 10101101이다.

  3. 전송열을 나눌 때는 10101101 → 00011101 → 00001011 → 00000000으로 확인한다.

전송열은 10101101이고 검사 나머지는 000이다.

비교할 점

기본의 네 비트 메시지보다 메시지가 길지만 나머지 길이는 여전히 세 비트다.

두 비트 손상도 통과할 수 있다

전송열 10101101의 맨 앞과 맨 뒤를 뒤집는다. 검사가 통과하는 이유를 설명하라.

  1. 오류열은 10000001이고 수신열은 00101100이다. 수신열에서 00101100 XOR 00101100 = 0으로 나눈다.

  2. 오류열도 10000001 → 00110001 → 00011101 → 00001011 → 0으로 나누어떨어진다.

00101100은 원래 전송열과 다르지만 나머지 000이라 이 CRC는 두 비트 손상을 놓친다.

비교할 점

마지막 두 비트의 인접 오류 00000011은 나머지 011로 검출되므로 두 비트라는 개수만으로 판단할 수 없다.

종이와 본문으로 직접 해보기

같은 모형에서 마지막 비트만 뒤집은 1101000을 검사하라. 이어 정상 전송열에 오류열 0001011을 XOR한 1100010도 검사하라.

힌트 보기

첫 번째는 예제의 0 패딩 열과 같다. 두 번째 오류열은 생성 비트열 자체를 오른쪽에 맞춘 것이다.

풀이 보기

1101000의 나머지는 001이어서 검출한다. 1100010은 XOR 1011000 → 0111010, XOR 0101100 → 0010110, XOR 0010110 → 0000000이다. 두 번째는 여러 비트가 달라졌어도 나머지 000이라 검출하지 못한다.

오해와 반례

CRC가 통과하면 내용과 송신자가 모두 확실하다.

활동의 1100010은 원래 전송열과 다르지만 통과한다. 또 공격자가 내용을 바꾸고 검사값을 다시 계산할 수 있다. 인증에는 별도 암호학적 장치와 그 조건이 필요하다.

생성 비트열 1011의 나머지는 몇 비트로 기록하는가?

답과 이유 보기

3비트

생성다항식 차수가 3이고 나머지 차수는 그보다 작다. 값 1도 001로 기록한다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

정상 전송열 10101101에 오류열 00000101을 적용하면 수신열과 나머지는?

힌트 1

같은 비트는 XOR로 0이 된다.

힌트 2

오류열의 차수는 생성다항식의 차수보다 작다.

풀이와 답 확인

  1. 수신열은 10101101 XOR 00000101 = 10101000이다.

  2. 00000101은 더 나눌 수 없는 나머지 101이다.

수신열 10101000, 나머지 101이므로 오류가 검출된다.

흔한 오답에서 다시 생각하기

두 비트 오류는 앞의 반례처럼 모두 누락된다.

반례는 일부 오류가 누락된다는 뜻이다. 이번 오류열의 나머지는 0이 아니므로 검출된다.

연습 2 · 오류 찾아 고치기

검사 나머지가 000인 10100110을 보고 원본 10101101과 같다고 결론 낸 보고서를 고쳐라.

힌트 1

두 열의 XOR로 실제 차이를 찾아라.

힌트 2

그 오류열이 1011의 배수인지 확인하라.

풀이와 답 확인

  1. 두 열의 차이는 00001011로 0이 아니다.

  2. 1011 자체는 생성다항식이므로 나머지 0이다.

내용은 달라졌지만 오류가 검출되지 않았다. 원본 동일성이나 송신자 인증을 주장할 수 없다.

흔한 오답에서 다시 생각하기

CRC가 0이면 오류열도 0이다.

나머지는 오류열 전체를 보존하지 않는다. 00001011이라는 0이 아닌 오류도 나머지 0을 만든다.

연습 3 · 직접 만들어 보기

현재 여덟 비트 전송열에서 다른 누락 오류를 하나 구성하라. 00001011과 10000001은 제외한다.

힌트 1

생성 비트열을 왼쪽으로 옮겨도 배수다.

힌트 2

1011을 네 자리 옮기면 여덟 비트 안에 들어간다.

풀이와 답 확인

  1. 오류열 10110000을 선택한다.

  2. 10101101 XOR 10110000 = 00011101이고, 00011101 → 00001011 → 0이다.

예: 오류열 10110000, 수신열 00011101, 나머지 000이다.

흔한 오답에서 다시 생각하기

전송열과 XOR한 결과가 0이어야 누락된다.

수신열 전체가 0일 필요는 없다. 검사 나머지만 0이면 통과한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

이 여덟 비트 모형의 한 비트 오류는 모두 검출되는가? 오른쪽부터 각 위치의 나머지로 설명하라.

힌트 1

한 비트 오류는 1,10,100처럼 한 항만 있다.

힌트 2

각 항의 나머지를 세 비트로 기록한다.

풀이와 답 확인

  1. 오른쪽부터 나머지는 001,010,100,011,110,111,101,001이다.

  2. 여덟 값 중 000이 없으므로 지정된 범위의 한 비트 오류는 모두 검출된다.

지정된 여덟 위치에서는 모두 검출된다. 이 계산이 실제 Ethernet 구현을 시험한 것은 아니다.

흔한 오답에서 다시 생각하기

끝의 나머지가 처음과 같으므로 한 비트 오류도 누락된다.

검출 여부는 서로 같은 나머지가 있는지가 아니라 각 오류의 나머지가 000인지에 달려 있다.

내 말로 설명하기

검사값이 세 비트인 이유는 메시지 길이인가?

설명 기준 확인

생성다항식의 차수 3이 기준이다. 메시지를 다섯 비트로 바꾸어도 나머지는 세 비트로 기록한다.

손상 검출과 인증은 무엇이 다른가?

설명 기준 확인

이번 CRC는 일부 오류를 검출하지만 내용을 바꾸고 CRC를 재계산하는 사람의 신원을 구별하지 못한다.

한 단계 더

예제의 메시지 1101을 1001로 바꾸고 1001000을 나누어 보라. XOR 1011000 → 0010000, XOR 0010110 → 0000110이므로 나머지는 110, 전송열은 1001110이다. 두 메시지의 CRC가 같아야 할 이유는 없다.

소단원 10.2

Ethernet·스위칭·ARP

스위치는 처음 보는 수신자의 위치를 어떻게 찾고, 컴퓨터는 IP에서 MAC을 어떻게 알아낼까?

준비 개념과 학습 목표

준비 개념

  • MAC 주소·프레임

  • IP 다음 홉

학습 목표

  • 출발지 학습과 목적지 조회를 구분한다.

  • 모르는 유니캐스트와 브로드캐스트의 전달 범위를 추적한다.

  • ARP가 해석할 다음 홉을 결정한다.

ARP 매핑이 있는데도 스위치가 프레임을 여러 포트로 보낼 수 있을까?

새 스위치에는 전달 상태의 포트 1·2·3·4가 있고 한 VLAN만 있다. 포트 1 쪽에는 허브를 통해 A와 D가 함께 연결되어 있다. B는 포트 2, C는 포트 3에 있다. 초기 표는 비었고 정상 프레임, 루프 없음, 손실 없음으로 정한다. 같은 포트 쪽의 두 호스트를 구별하면 학습과 전달을 더 분명하게 볼 수 있다.

출발지 위치를 먼저 학습하고 목적지를 조회한다. 목적지의 포트가 입력과 같다면 다른 스위치 포트로 내보낼 필요가 없으므로 출력을 비운다. 이때 스위치가 추가 복사본을 보내지 않는다는 말과 허브 쪽 호스트가 원래 프레임을 받지 못한다는 말은 다르다.

호스트의 ARP 표는 IPv4→MAC이고 스위치의 표는 VLAN·MAC→포트다. 한 표가 남아 있고 다른 표만 노화되는 모형도 가능하다. 이를 이유로 호스트가 반드시 ARP 요청을 다시 보낸다고 결론 내리면 두 표의 역할을 섞게 된다. 아래 사건에서는 표 삭제를 명시하고 자동 타이머의 실제 시간을 가정하지 않는다.

보낸 곳을 배우고 받을 곳을 찾기

스위치의 전달 표에는 VLAN과 MAC 주소에 대응하는 포트가 들어간다. 들어온 프레임의 출발지 주소를 보고 그 주소가 입력 포트 쪽에 있다고 학습한다. 목적지 주소는 별도로 표에서 조회한다. 수신자의 주소를 보았다고 그 주소가 입력 포트에 있다는 뜻은 아니다.

같은 VLAN에서 목적지 항목을 모르며 모든 포트가 전달 가능한 상태라면 입력 포트를 제외한 해당 VLAN 포트들로 복제한다. 이를 모르는 유니캐스트 플러딩이라고 한다. 이미 배운 다른 포트의 목적지에는 그 포트만 선택한다. 학습 표는 노화나 연결 변화로 달라질 수 있으므로 처음의 표와 사건 순서를 명시해야 한다.

IP 다음 홉의 링크 주소

ARP는 IPv4 주소에 대응하는 Ethernet 주소를 알아내는 데 사용할 수 있다. 먼저 경로 선택이 즉시 보낼 다음 홉을 정한다. 같은 링크의 이웃이면 그 이웃의 IPv4를, 다른 네트워크로 보내면 일반적으로 선택된 게이트웨이의 IPv4를 해석한다. 인터넷 끝의 목적지 MAC을 직접 묻는 절차가 아니다.

매핑이 없으면 대상 프로토콜 주소를 넣은 ARP 요청을 Ethernet 브로드캐스트로 보낸다. 대상은 자신의 정보를 넣은 응답을 돌려줄 수 있다. ARP의 IP→MAC 매핑 표와 스위치의 MAC→포트 전달 표는 서로 다른 표이며, 요청 프레임을 보내는 동안 스위치도 출발지 위치를 배울 수 있다.

모형을 정한 뒤 사건 추적하기

아래 모형은 한 VLAN, 루프 없는 스위치, 전달 상태의 포트 세 개, 정상 프레임, 빈 초기 표를 가정한다. 프레임 손실과 표 노화가 없고 A·B·C가 각각 포트 1·2·3에 연결되어 있다. 이 가정 안에서 학습과 전달을 분리해 쓰면 결과를 재현할 수 있다.

ARP 패킷은 하드웨어 종류·프로토콜 종류·주소 길이·연산 번호와 네 주소를 포함한다. Ethernet/IPv4에서 주소 길이 6과 4를 쓰면 ARP 본문은 28바이트다. 이는 Ethernet 헤더나 패딩까지 모두 센 크기가 아니다. ARP 요청을 받는 모든 호스트가 모든 새 항목을 반드시 저장한다고 가정하지도 않는다.

비교할 점

기본 예제는 각 호스트가 다른 포트에 있었지만 이번에는 같은 포트 뒤에 두 호스트가 있다.

ARP와 전달 표의 수명이 다르다

A의 ARP 표에는 192.0.2.22→MAC B가 남아 있다. 스위치만 B 항목을 삭제했다. A가 그 호스트로 보낸 프레임을 추적하라.

  1. A는 주어진 유효 매핑을 사용하여 목적지 MAC B의 유니캐스트를 만든다.

  2. 스위치는 B의 위치를 모르므로 입력 1을 뺀 {2,3,4}로 복제한다. B가 2에서 답하면 다시 B:2를 배운다.

호스트의 유니캐스트가 스위치에서는 일시적으로 플러딩될 수 있다. 새 ARP 요청을 반드시 보냈다고 주장하지 않는다.

비교할 점

IPv4→MAC의 성공이 MAC→포트 표의 존재를 보장하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

태그 없는 Ethernet/IPv4 ARP 본문 28바이트를 데이터 최소 길이 46바이트까지 패딩하는 모형이다. 헤더 14와 FCS 4를 포함한 크기와 패딩 비율을 구하라. 프리앰블·간격은 제외한다.

힌트 1

본문과 패딩을 별도 항목으로 더한다.

힌트 2

패딩 비율의 분모는 여기서 센 전체 프레임 크기다.

풀이와 답 확인

  1. 패딩은 46−28=18바이트다.

  2. 전체는 14+28+18+4=64바이트이고 패딩 비율은 18/64=28.125%다.

패딩 18바이트, 프레임 64바이트, 그중 패딩 28.125%다. ARP 본문 자체는 여전히 28바이트다.

흔한 오답에서 다시 생각하기

프레임 데이터 영역의 길이와 ARP 형식의 본문 길이는 다르다. 이 문제는 최소 데이터 46을 명시한 태그 없는 모형이다.

두 표는 다른 장치와 기능의 상태다. 이번 모형에서는 호스트 매핑을 유지하고 스위치 항목만 삭제했다.

한 단계 더

A가 연결을 포트 3으로 옮겼고 기존 표에 A:1이 남아 있다고 하자. A→B가 3에 도착하면 A:3으로 갱신하고 B:2를 사용한다. 이어 B→A는 3으로 나간다. 실제 장비의 노화·보안 설정·중복 주소가 이 단순 모형과 다르면 별도로 확인해야 한다.

중간 트렁크 하나에서 VLAN이 빠지면 어느 호스트까지 방송이 도달할까?

루프 없는 세 스위치 S1–S2–S3를 연결한다. S1에는 VLAN 10 호스트 A·B와 VLAN 20 호스트 C가 있다. S2에는 VLAN 10 호스트 D와 VLAN 20 호스트 E가 있고, S3에는 VLAN 10 호스트 F와 VLAN 20 호스트 G가 있다. 각 이름은 별도 액세스 포트의 호스트 하나다.

S1–S2 트렁크 양끝은 10·20을 허용하지만 S2–S3 양끝은 20만 허용한다. 모든 트렁크에서 허용된 두 VLAN은 태그를 붙이고, 입력 VLAN 검사와 허용 목록을 적용하며, 모든 필요한 포트가 전달 상태라고 가정한다. 같은 VLAN 번호를 가진 F도 연결 경로가 끊어져 있으면 A의 방송을 받지 못한다.

방송 수신 호스트 수와 링크 복사본 수는 다르다. 송신자를 빼고 수신자를 세되 트렁크 자체를 호스트로 세지 않는다. 아래의 정책 변경은 한 항목을 고친 가상 비교이며 실제 장비에 설정을 적용한 실험은 아니다.

논리적인 방송 영역 나누기

VLAN은 하나의 물리 스위치 위에 여러 논리 링크 영역을 만들 수 있게 한다. 여기서는 일반적인 포트 기반 모형을 쓴다. 액세스 포트는 들어오는 태그 없는 호스트 프레임을 설정된 VLAN에 연결한다. 같은 기기에 꽂혔다는 사실만으로 같은 방송 영역인 것은 아니다.

방송과 모르는 유니캐스트도 해당 VLAN의 전달 가능한 포트로 제한된다. 서로 다른 VLAN 사이에 패킷을 옮기려면 라우터나 3계층 스위치의 라우팅 기능 및 허용 정책이 필요하다. VLAN 번호만 같다고 서로 떨어진 두 장비가 자동 연결되는 것은 아니며 그 사이 링크도 해당 VLAN을 운반해야 한다.

여러 영역이 함께 쓰는 트렁크

트렁크는 같은 링크에서 여러 VLAN의 프레임을 운반할 수 있다. IEEE 802.1Q는 출발지 MAC 뒤에 4바이트 태그를 넣어 VLAN을 표시하며 변경된 프레임의 FCS를 다시 계산한다. 수신 장비는 태그와 포트 설정으로 프레임의 영역을 해석한다.

모든 실제 트렁크 프레임이 늘 태그를 가진다는 규칙은 아니다. native VLAN을 태그 없이 처리하는 설정 등이 있다. 아래는 혼동을 없애기 위해 VLAN 10과 20 모두 트렁크에서 태그를 붙이고 양끝 허용 목록도 같다고 가정한다. 태그 없는 액세스 호스트가 그 태그를 직접 만들 필요는 없다.

전달 범위를 조건으로 계산하기

포트 1·2는 VLAN 10, 포트 3·4는 VLAN 20의 액세스 포트이고 포트 5는 두 VLAN을 허용하는 트렁크라고 하자. 루프가 없고 포트가 모두 전달 상태라면 VLAN 10의 방송은 1·2·5 범위 안에서 입력 포트를 빼고 복제한다.

태그는 암호화나 사용자 인증이 아니다. 영역 분리는 의미가 있지만 라우팅 허용, 트렁크 잘못 설정, 접속 장비의 권한 등을 별도로 검토해야 한다. 단순 번호만으로 안전성을 보장하지 않는다. 또한 방송을 모든 VLAN으로 복제하면 분리 목적 자체를 깨뜨린다.

조건을 바꾸어 비교하기

중간에서 끊기는 방송

원래 목록에서 A와 C가 각각 방송한다. 수신 호스트와 지나간 트렁크를 구하라.

  1. A의 방송은 B와 S1–S2로 복제되고 S2에서 D에게 전달된다. S2–S3은 10을 허용하지 않아 F까지 가지 못한다.

  2. C의 방송은 S1–S2를 지나 E에게 가며 S2–S3도 지나 G에게 간다. A·B·D·F는 다른 VLAN이라 제외한다.

A의 수신자는 B·D, 지나간 트렁크는 하나다. C의 수신자는 E·G, 지나간 트렁크는 두 개다.

비교할 점

수신 호스트 수는 둘로 같아도 방송의 전달 경로는 다르다.

태그 크기와 내용의 경계

IPv4 패킷 200바이트를 담는 태그 없는 프레임과 단일 802.1Q 태그 프레임의 크기를 비교하라. 패딩·프리앰블·간격은 제외한다.

  1. 태그 없는 Ethernet II는 헤더 14+데이터 200+FCS 4=218바이트다.

  2. 트렁크에서 태그 4를 넣으면 222바이트가 되고 변경된 프레임의 FCS를 다시 계산한다. IPv4 패킷은 200바이트로 유지된다.

218바이트와 222바이트다. 차이 4바이트는 링크 태그이며 IP 패킷 자체의 증가가 아니다.

비교할 점

서로 다른 링크 봉투 크기를 최종 IP 내용 크기와 혼동하지 않는다.

종이와 본문으로 직접 해보기

트렁크 양끝의 허용 목록에서 VLAN 10을 제거하되 액세스 설정은 그대로 두면 포트 1 방송은 어디까지 가는가? 데이터 100바이트의 태그 없는 Ethernet II 프레임에 태그 하나를 추가하면 여기서 센 크기는?

힌트 보기

허용되지 않는 VLAN은 트렁크로 보내지 않는다. 크기는 6+6+2+100+4에 태그 4를 더한다.

풀이 보기

첫 스위치의 포트 2만 받는다. 트렁크 5로 전달되지 않아 6·7은 못 받는다. 데이터 100바이트 프레임은 118+4=122바이트다. 이 예시는 패딩이 필요 없는 크기이며 작은 프레임의 최소 크기 규칙으로 일반화하지 않는다.

오해와 반례

VLAN이 다르면 어떤 조건에서도 통신할 수 없고 안전하다.

라우팅 장치와 허용 정책이 있으면 서로 다른 VLAN의 IP 통신이 가능하다. VLAN은 방송 영역을 나누지만 내용 암호화나 단말 인증을 대신하지 않으며 잘못된 트렁크·라우팅 설정은 별도 문제다.

  1. A 방송은 B·D에게 도달하고 S2가 VLAN 10 복사본을 트렁크로 보낼 수 있다.

  2. S3는 입력 10을 허용하지 않으므로 받아 전달하지 않는다. F는 받지 않는다.

수신자는 여전히 B·D다. 이번 입력 필터 가정에서 한쪽 변경만으로 경로가 열리지 않는다.

흔한 오답에서 다시 생각하기

트렁크에 프레임이 한 번 나갔으므로 F도 받는다.

링크 송신과 다음 스위치의 허용·전달은 별도 단계다. 실제 장비의 정책은 별도로 확인해야 한다.

트렁크를 공유하면 VLAN이 합쳐지는가?

같은 물리 링크를 사용해도 태그와 VLAN별 규칙으로 방송 영역을 구분한다.

VLAN 분리가 곧 암호화인가?

설명 기준 확인

영역을 나누는 전달 조건이며 내용 암호화나 송신자 인증을 제공하는 근거는 아니다.

한 단계 더

반대쪽 포트 7을 VLAN 20으로 옮긴 경우 포트 1 방송의 수신 호스트는 2와 6으로 두 명이다. 포트 7의 물리 연결은 그대로지만 논리 영역이 달라졌다. VLAN 10 태그만 통과시키는 트렁크라면 VLAN 20 방송은 반대편 7·8까지 도달하지 않는다.

다른 문제에 적용하기

새 통합 상황이다. A는 S1의 VLAN 10 호스트, 게이트웨이 R은 S2의 VLAN 10 호스트이고 S1–S2 트렁크 양끝은 10을 허용한다. A의 ARP 표는 192.0.2.1→MAC R을 갖지만 S1의 MAC 표에는 R이 없다. S1에는 A·B(VLAN 10), C(VLAN 20), 트렁크만 있다. A가 원격 203.0.113.70으로 IPv4 패킷 200바이트를 보낸다. S2 표에는 R의 액세스 포트가 있다. 각 링크의 MAC 목적지·IP 목적지·S1 출력·크기를 쓰고 CRC 통과가 무엇을 보장하지 못하는지 설명하라.

힌트 1

ARP, MAC 위치 표, IP 경로를 세 가지 상태로 나눈다.

힌트 2

태그 없는 봉투와 태그 하나인 봉투를 별도로 합산한다.

풀이와 답 확인

  1. A는 유효 ARP 매핑을 사용해 MAC R을 목적지로 한 유니캐스트를 만든다. IP 목적지는 원격 서버를 유지한다.

  2. S1은 R 위치를 몰라 VLAN 10의 B 포트와 트렁크로 복제한다. C나 입력 A 포트로는 보내지 않는다.

  3. S2는 R의 위치를 알고 액세스 포트로 전달한다. 태그 없는 액세스 프레임은 218바이트, 태그 하나인 트렁크 프레임은 222바이트다.

  4. 프레임 변경 시 FCS를 다시 계산한다. CRC 통과만으로 원본 내용 동일성이나 송신자 신원을 보장하지 못한다.

MAC 목적지는 R, IP 목적지는 203.0.113.70이다. S1 출력은 B와 트렁크, S2 출력은 R의 액세스 포트다. 액세스 218바이트·트렁크 222바이트이며 IPv4 내용은 200바이트다. 유효 ARP 매핑이 있어도 일시적인 모르는 유니캐스트가 가능하다.

해결한 뒤 점검할 것

  • 세 표의 역할을 구별하고 새 ARP 요청이 반드시 필요하다고 주장하지 않는다.

  • VLAN 20과 입력 포트를 플러딩 대상에서 제외한다.

  • 링크 크기와 IP 내용 크기를 구별하며 인증을 CRC에 부여하지 않는다.
