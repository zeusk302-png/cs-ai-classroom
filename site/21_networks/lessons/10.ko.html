소단원 10.1

프레임·MAC·CRC

봉투의 주소가 맞아도 내용이 손상되었다면 어떻게 알아챌까?

준비 개념과 학습 목표

준비 개념

  • 비트·바이트

  • XOR: 같은 비트끼리는 0, 다른 비트끼리는 1

학습 목표

  • 프레임과 IP 패킷의 범위를 구별한다.

  • MAC 주소와 FCS의 역할을 설명한다.

  • 작은 생성다항식으로 CRC를 직접 계산한다.

한 링크에서 보내는 봉투

IP 패킷이 여행의 내용물이라면 링크 프레임은 한 구간에서 사용할 봉투다. Ethernet II의 기본 주소는 목적지와 출발지 MAC이며 각각 6바이트다. MAC 48비트는 8비트씩 여섯 묶음이다. 네트워크 계층 주소와 같은 항목이 아니며 MAC 주소만으로 인터넷 경로가 결정되지 않는다.

여기서는 태그 없는 Ethernet II에서 목적지 6, 출발지 6, EtherType 2, 데이터, FCS 4바이트를 센다. 프리앰블과 프레임 사이 간격은 이 계산에서 제외한다. 상위 패킷의 바이트와 링크 헤더를 함께 세는 것은 어느 구간의 크기를 구하는지 먼저 정한 뒤에 한다.

주소와 오류 검사는 다른 질문

MAC 주소는 이 링크에서 어떤 인터페이스에 전달할지를 식별하는 데 쓰인다. FCS는 전송 중 비트 손상을 검사할 중복 정보이며 Ethernet에서는 32비트 CRC를 넣는다. 주소가 맞았다는 사실과 내용이 손상되지 않았다는 판단은 독립적인 질문이다.

CRC의 수학을 보기 위해 아래에서는 Ethernet CRC-32 대신 3비트 나머지를 붙이는 작은 모형을 쓴다. 생성 비트열 1011은 x³+x+1을 나타낸다. 일반 정수 나눗셈과 달리 빼기를 XOR로 수행하고 자리올림이나 빌림을 하지 않는다. 실제 Ethernet의 초기값·비트 처리·최종 변환을 이 모형으로 구현했다고 주장하지 않는다.

검출과 인증의 경계

메시지 뒤에 생성다항식 차수만큼 0을 붙여 나눈 나머지를 그 자리에 넣는다. 이렇게 만든 전송 다항식은 생성다항식으로 나누어떨어진다. 수신 나머지가 0이 아니면 이 모형에서는 오류를 검출한다.

나머지가 0이라고 모든 손상이 없었다고 증명되지는 않는다. 오류 다항식 자체가 생성다항식의 배수이면 변형 후에도 나누어떨어진다. 누구나 새 CRC를 계산할 수도 있으므로 CRC는 비밀 키를 가진 송신자의 인증을 제공하지 않는다. 손상 검출, 재전송, 암호 인증의 목적을 구분해야 한다.

중간 과정을 따라가는 예제

교육 CRC에서 메시지 1101, 생성 비트열 1011을 사용한다. 전송할 7비트와 수신 검사 나머지를 구하라.

  1. 차수는 3이므로 1101000을 만든다.

  2. 왼쪽 1에 맞춰 XOR한다: 1101000 XOR 1011000 = 0110000.

  3. 이어 0110000 XOR 0101100 = 0011100, 0011100 XOR 0010110 = 0001010이다.

  4. 0001010 XOR 0001011 = 0000001이므로 3자리 나머지는 001이다.

  5. 전송열 1101001을 같은 순서로 나누면 마지막 0001011 XOR 0001011 = 0000000이 된다.

1101001을 보낸다. 메시지 4비트 뒤에 나머지 001을 붙였고 수신 검사 나머지는 000이다.

종이와 본문으로 직접 해보기

같은 모형에서 마지막 비트만 뒤집은 1101000을 검사하라. 이어 정상 전송열에 오류열 0001011을 XOR한 1100010도 검사하라.

힌트 보기

첫 번째는 예제의 0 패딩 열과 같다. 두 번째 오류열은 생성 비트열 자체를 오른쪽에 맞춘 것이다.

풀이 보기

1101000의 나머지는 001이어서 검출한다. 1100010은 XOR 1011000 → 0111010, XOR 0101100 → 0010110, XOR 0010110 → 0000000이다. 두 번째는 여러 비트가 달라졌어도 나머지 000이라 검출하지 못한다.

오해와 반례

CRC가 통과하면 내용과 송신자가 모두 확실하다.

활동의 1100010은 원래 전송열과 다르지만 통과한다. 또 공격자가 내용을 바꾸고 검사값을 다시 계산할 수 있다. 인증에는 별도 암호학적 장치와 그 조건이 필요하다.

자기점검

MAC 주소 하나가 48비트라면 몇 바이트인가?

답과 이유 보기

6바이트

48÷8=6이다. 이 길이는 IP 주소 길이를 뜻하지 않는다.

태그 없이 데이터 100바이트를 넣을 때 여기서 정한 헤더와 FCS를 포함한 크기는?

답과 이유 보기

118바이트

6+6+2+100+4=118이다. 프리앰블과 간격은 제외한 계산이다.

생성 비트열 1011의 나머지는 몇 비트로 기록하는가?

답과 이유 보기

3비트

생성다항식 차수가 3이고 나머지 차수는 그보다 작다. 값 1도 001로 기록한다.

한 단계 더

예제의 메시지 1101을 1001로 바꾸고 1001000을 나누어 보라. XOR 1011000 → 0010000, XOR 0010110 → 0000110이므로 나머지는 110, 전송열은 1001110이다. 두 메시지의 CRC가 같아야 할 이유는 없다.

소단원 10.2

Ethernet·스위칭·ARP

스위치는 처음 보는 수신자의 위치를 어떻게 찾고, 컴퓨터는 IP에서 MAC을 어떻게 알아낼까?

준비 개념과 학습 목표

준비 개념

  • MAC 주소·프레임

  • IP 다음 홉

  • 표에서 키로 항목 찾기

학습 목표

  • 출발지 학습과 목적지 조회를 구분한다.

  • 모르는 유니캐스트와 브로드캐스트의 전달 범위를 추적한다.

  • ARP가 해석할 다음 홉을 결정한다.

보낸 곳을 배우고 받을 곳을 찾기

스위치의 전달 표에는 VLAN과 MAC 주소에 대응하는 포트가 들어간다. 들어온 프레임의 출발지 주소를 보고 그 주소가 입력 포트 쪽에 있다고 학습한다. 목적지 주소는 별도로 표에서 조회한다. 수신자의 주소를 보았다고 그 주소가 입력 포트에 있다는 뜻은 아니다.

같은 VLAN에서 목적지 항목을 모르며 모든 포트가 전달 가능한 상태라면 입력 포트를 제외한 해당 VLAN 포트들로 복제한다. 이를 모르는 유니캐스트 플러딩이라고 한다. 이미 배운 다른 포트의 목적지에는 그 포트만 선택한다. 학습 표는 노화나 연결 변화로 달라질 수 있으므로 처음의 표와 사건 순서를 명시해야 한다.

IP 다음 홉의 링크 주소

ARP는 IPv4 주소에 대응하는 Ethernet 주소를 알아내는 데 사용할 수 있다. 먼저 경로 선택이 즉시 보낼 다음 홉을 정한다. 같은 링크의 이웃이면 그 이웃의 IPv4를, 다른 네트워크로 보내면 일반적으로 선택된 게이트웨이의 IPv4를 해석한다. 인터넷 끝의 목적지 MAC을 직접 묻는 절차가 아니다.

매핑이 없으면 대상 프로토콜 주소를 넣은 ARP 요청을 Ethernet 브로드캐스트로 보낸다. 대상은 자신의 정보를 넣은 응답을 돌려줄 수 있다. ARP의 IP→MAC 매핑 표와 스위치의 MAC→포트 전달 표는 서로 다른 표이며, 요청 프레임을 보내는 동안 스위치도 출발지 위치를 배울 수 있다.

모형을 정한 뒤 사건 추적하기

아래 모형은 한 VLAN, 루프 없는 스위치, 전달 상태의 포트 세 개, 정상 프레임, 빈 초기 표를 가정한다. 프레임 손실과 표 노화가 없고 A·B·C가 각각 포트 1·2·3에 연결되어 있다. 이 가정 안에서 학습과 전달을 분리해 쓰면 결과를 재현할 수 있다.

ARP 패킷은 하드웨어 종류·프로토콜 종류·주소 길이·연산 번호와 네 주소를 포함한다. Ethernet/IPv4에서 주소 길이 6과 4를 쓰면 ARP 본문은 28바이트다. 이는 Ethernet 헤더나 패딩까지 모두 센 크기가 아니다. ARP 요청을 받는 모든 호스트가 모든 새 항목을 반드시 저장한다고 가정하지도 않는다.

중간 과정을 따라가는 예제

빈 표인 스위치에서 A→B, B→A, A→B 프레임이 차례로 들어온다. 각 학습 항목과 출력 포트를 구하라.

  1. A→B가 포트 1에 도착하면 A:1을 배운다. B 항목은 없으므로 포트 2와 3으로 전달한다.

  2. B→A가 포트 2에 도착하면 B:2를 배운다. A:1이 있으므로 출력은 포트 1뿐이다.

  3. 다시 A→B가 포트 1에 도착하면 A:1을 유지하고 B:2를 조회해 포트 2만 선택한다.

출력은 {2,3}, {1}, {2}이며 마지막 표는 A:1, B:2다. C는 프레임을 보냈다는 사건이 없어서 새로 학습되지 않았다.

종이와 본문으로 직접 해보기

최종 표에서 A의 브로드캐스트가 포트 1에 들어오면 출력은? 또한 경로 표가 원격 서버 203.0.113.9의 다음 홉을 같은 링크 게이트웨이 192.0.2.1로 정했는데 그 매핑이 없다면 ARP의 대상 IPv4는?

힌트 보기

방송은 알려진 특정 목적지와 다르다. ARP는 이미 결정한 즉시 다음 홉을 해석한다.

풀이 보기

방송 출력은 입력 1을 제외한 {2,3}이다. ARP 대상은 192.0.2.1이며 원격 서버 203.0.113.9가 아니다. 응답으로 얻은 게이트웨이 MAC을 링크 봉투의 목적지로 쓰고 IP 목적지는 원격 서버로 유지한다.

오해와 반례

스위치가 IP→MAC을 알아내고 ARP가 MAC→포트를 알아낸다.

두 표의 방향이 반대다. ARP는 이 링크에서 IPv4→MAC 해석에 사용하고 스위치는 VLAN·목적지 MAC으로 포트를 고른다. 게이트웨이 MAC을 알더라도 스위치 표 항목이 노화되면 잠시 모르는 유니캐스트가 생길 수 있다.

출발지 A, 목적지 B 프레임이 포트 1에 들어오면 어느 주소 위치를 학습하는가?

표에 B가 없으면 프레임을 반드시 버리는가?

같은 VLAN의 전달 포트로 복제하며 입력 포트 1은 제외한다.

Ethernet/IPv4 ARP 본문의 필드 길이 합은?

한 단계 더

A가 연결을 포트 3으로 옮겼고 기존 표에 A:1이 남아 있다고 하자. A→B가 3에 도착하면 A:3으로 갱신하고 B:2를 사용한다. 이어 B→A는 3으로 나간다. 실제 장비의 노화·보안 설정·중복 주소가 이 단순 모형과 다르면 별도로 확인해야 한다.

VLAN과 브로드캐스트

논리적인 방송 영역 나누기

VLAN은 하나의 물리 스위치 위에 여러 논리 링크 영역을 만들 수 있게 한다. 여기서는 일반적인 포트 기반 모형을 쓴다. 액세스 포트는 들어오는 태그 없는 호스트 프레임을 설정된 VLAN에 연결한다. 같은 기기에 꽂혔다는 사실만으로 같은 방송 영역인 것은 아니다.

방송과 모르는 유니캐스트도 해당 VLAN의 전달 가능한 포트로 제한된다. 서로 다른 VLAN 사이에 패킷을 옮기려면 라우터나 3계층 스위치의 라우팅 기능 및 허용 정책이 필요하다. VLAN 번호만 같다고 서로 떨어진 두 장비가 자동 연결되는 것은 아니며 그 사이 링크도 해당 VLAN을 운반해야 한다.

여러 영역이 함께 쓰는 트렁크

트렁크는 같은 링크에서 여러 VLAN의 프레임을 운반할 수 있다. IEEE 802.1Q는 출발지 MAC 뒤에 4바이트 태그를 넣어 VLAN을 표시하며 변경된 프레임의 FCS를 다시 계산한다. 수신 장비는 태그와 포트 설정으로 프레임의 영역을 해석한다.

모든 실제 트렁크 프레임이 늘 태그를 가진다는 규칙은 아니다. native VLAN을 태그 없이 처리하는 설정 등이 있다. 아래는 혼동을 없애기 위해 VLAN 10과 20 모두 트렁크에서 태그를 붙이고 양끝 허용 목록도 같다고 가정한다. 태그 없는 액세스 호스트가 그 태그를 직접 만들 필요는 없다.

전달 범위를 조건으로 계산하기

포트 1·2는 VLAN 10, 포트 3·4는 VLAN 20의 액세스 포트이고 포트 5는 두 VLAN을 허용하는 트렁크라고 하자. 루프가 없고 포트가 모두 전달 상태라면 VLAN 10의 방송은 1·2·5 범위 안에서 입력 포트를 빼고 복제한다.

태그는 암호화나 사용자 인증이 아니다. 영역 분리는 의미가 있지만 라우팅 허용, 트렁크 잘못 설정, 접속 장비의 권한 등을 별도로 검토해야 한다. 단순 번호만으로 안전성을 보장하지 않는다. 또한 방송을 모든 VLAN으로 복제하면 분리 목적 자체를 깨뜨린다.

중간 과정을 따라가는 예제

위 모형의 포트 1에서 VLAN 10 호스트가 방송한다. 트렁크 5 반대쪽 스위치에는 VLAN 10 액세스 포트 6·7, VLAN 20 포트 8이 있다. 출력과 호스트 수를 구하라. 양쪽 스위치에는 이 연결 외 다른 포트가 없다.

  1. 첫 스위치에서 입력 1을 빼면 VLAN 10 출력은 액세스 2와 트렁크 5다. 포트 3·4는 VLAN 20이어서 제외한다.

  2. 트렁크에는 VLAN 10 태그를 붙인 복사본 한 개가 전달된다.

  3. 반대쪽은 트렁크 입력을 제외하고 VLAN 10 액세스 6·7로 복제한다. 포트 8은 제외한다.

  4. 원래 송신자를 빼고 방송을 받는 호스트는 2·6·7의 세 호스트다. 트렁크 포트 자체를 호스트 수에 더하지 않는다.

첫 출력 {2,5}, 반대쪽 액세스 출력 {6,7}, 수신 호스트 3명이다.

종이와 본문으로 직접 해보기

트렁크 양끝의 허용 목록에서 VLAN 10을 제거하되 액세스 설정은 그대로 두면 포트 1 방송은 어디까지 가는가? 데이터 100바이트의 태그 없는 Ethernet II 프레임에 태그 하나를 추가하면 여기서 센 크기는?

힌트 보기

허용되지 않는 VLAN은 트렁크로 보내지 않는다. 크기는 6+6+2+100+4에 태그 4를 더한다.

풀이 보기

첫 스위치의 포트 2만 받는다. 트렁크 5로 전달되지 않아 6·7은 못 받는다. 데이터 100바이트 프레임은 118+4=122바이트다. 이 예시는 패딩이 필요 없는 크기이며 작은 프레임의 최소 크기 규칙으로 일반화하지 않는다.

오해와 반례

VLAN이 다르면 어떤 조건에서도 통신할 수 없고 안전하다.

라우팅 장치와 허용 정책이 있으면 서로 다른 VLAN의 IP 통신이 가능하다. VLAN은 방송 영역을 나누지만 내용 암호화나 단말 인증을 대신하지 않으며 잘못된 트렁크·라우팅 설정은 별도 문제다.

트렁크가 두 VLAN을 운반하면 두 방송 영역이 합쳐지는가?

아니다.

태그와 VLAN별 전달 규칙으로 영역을 구별한다. 같은 물리 링크를 쓰는 것과 같은 영역은 다르다.

한 단계 더

반대쪽 포트 7을 VLAN 20으로 옮긴 경우 포트 1 방송의 수신 호스트는 2와 6으로 두 명이다. 포트 7의 물리 연결은 그대로지만 논리 영역이 달라졌다. VLAN 10 태그만 통과시키는 트렁크라면 VLAN 20 방송은 반대편 7·8까지 도달하지 않는다.
