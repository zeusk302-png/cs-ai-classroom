소단원 13.1

SDN과 제어 분리

같은 목적지의 패킷을 다른 길로 보내려면 누가 결정을 바꾸고 누가 그 결정을 실행할까?

준비 개념과 학습 목표

준비 개념

  • 패킷의 목적지

  • 라우터의 전달 표

  • 그래프의 경로

학습 목표

  • 제어와 전달 역할을 구별한다.

  • 정책 변경 중 서로 다른 규칙이 섞이는 반례를 추적한다.

  • 논리적 제어와 물리적 배치를 구별한다.

세 장치의 새 규칙이 모두 정상이어도 한 개씩 바꾸는 중에는 어떨까?

새 가상 경로의 이전 규칙은 A→B, B→C, C→D이고 새 규칙은 A→D, B→A, C→B다. D에 도착하면 끝난다. 링크는 필요한 방향으로 모두 존재하고 장애·만료는 없으며 세 장치의 설치는 각각 한 번에 완료된다고 정한다. 전달 장치는 현재 설치된 다음 홉만 적용한다.

새 표가 완성되면 A→D, B→A→D, C→B→A→D로 모두 도착한다. 하지만 C부터 바꾸면 B의 옛 다음 홉 C와 C의 새 다음 홉 B가 서로 가리킨다. B부터 바꾸면 A와 B가 순환한다. A부터 바꾸고 그 적용 완료를 확인한 뒤 B, 다음 C를 바꾸는 순서는 이 모형에서 각 중간 상태를 도착 가능하게 유지한다.

설치 메시지를 보낸 것과 장치에 적용된 것은 다르다. 명령을 A, B, C 순서로 보내도 실제 적용 완료가 C, A, B 순서면 첫 중간 상태는 순환할 수 있다. 여기서 안전한 비교는 앞 장치의 적용 완료를 확인한 다음 뒤 장치를 바꾸는 계약을 포함한다. 모든 토폴로지와 모든 장애에 대한 일반 보장을 주장하지 않는다.

결정을 만드는 쪽과 적용하는 쪽

전달 평면은 들어온 패킷에 설치된 규칙을 적용하여 다음 포트를 선택하거나 패킷을 버린다. 제어 평면은 어떤 규칙이 필요한지 결정하고 장치에 전달한다. SDN은 이 관계를 프로그램으로 다루기 쉽게 분리한다. 예를 들어 학교 건물 사이의 영상 트래픽을 특정 경로로 보내라는 정책은 제어 쪽에서 결정하고, 실제 패킷은 각 스위치가 처리한다.

분리는 역할과 인터페이스의 분리다. 반드시 제어기가 한 대의 컴퓨터에만 있어야 한다는 뜻은 아니다. RFC 7426은 구현마다 평면이 함께 놓이거나 물리적으로 떨어질 수 있는 개념 모델을 설명한다. 이 자료는 2015년의 정보성 RFC이므로 특정 제품의 최신 설정법으로 사용하지 않는다.

설치된 규칙은 작은 프로그램이다

이 수업의 가상 장치는 목적지와 다음 장치의 대응표만 가진다. 목적지 D에 대해 S1의 다음 장치가 S2이면 S1은 패킷을 S2로 보낸다. S2의 다음 장치가 D이면 도착한다. 표에 해당 목적지가 없으면 버린다는 기본 규칙도 정한다. 실제 장치는 우선순위·헤더 필드·큐 등 더 많은 조건을 사용한다.

제어기와의 통신이 끊겨도 기존 규칙을 계속 적용하는지, 언제 만료되는지, 새 트래픽은 어떻게 처리하는지는 시스템의 계약에 달려 있다. 제어 장애와 전달 장애를 같은 사건으로 단정하지 말고 기존 표·만료·연결 상태를 각각 확인해야 한다.

좋은 최종 표도 중간에는 실패할 수 있다

여러 장치의 표를 한순간에 바꾸기는 어렵다. 이전 표와 새 표가 각각 정상 경로를 만들더라도 갱신 도중의 조합은 순환이나 손실을 만들 수 있다. 그래서 변경 계획에는 최종 경로뿐 아니라 설치 순서, 적용 확인, 실패 시 되돌리기도 들어간다.

아래 활동은 제어 메시지가 지정한 순서로 성공하고 그 사이에 패킷이 들어오는 자체 모형이다. 실제 SDN의 버전 태그·일관된 갱신 알고리즘을 구현한 실험이 아니다. 다만 최종 상태의 검사만으로 중간 상태의 안전성을 판단할 수 없다는 이유를 보여 준다.

중간 과정을 따라가는 예제

목적지 D의 이전 표는 S1→S2, S2→D이고 새 표는 S1→D, S2→S1이다. D는 도착하면 전달을 끝낸다. S2를 먼저 바꾼 직후 S1에 들어온 패킷을 추적하라. 링크 장애나 표 만료는 없다고 가정한다.

  1. 갱신 전에는 S1→S2→D로 도착한다.

  2. S2만 바꾸면 S1의 옛 규칙은 여전히 S2를 가리키고 S2의 새 규칙은 S1을 가리킨다.

  3. 패킷은 S1→S2→S1→S2로 되돌아간다. 반복을 확인하면 경로 추적을 멈춘다. 실제 IP 패킷은 TTL 같은 제한으로 결국 버려질 수 있다.

  4. S1도 바꾼 최종 상태에서는 S1→D, S2→S1→D로 도착한다.

최종 표는 도착하지만 S2만 먼저 바꾼 중간 상태는 순환한다. 최종 상태만 검사하면 이 문제를 놓친다.

조건을 바꾸어 비교하기

한 장치 변경의 위험을 찾는다

C를 먼저 변경한 경우와 B를 먼저 변경한 경우를 각각 독립 초기 상태에서 평가하라.

  1. C만 변경하면 B→C→B가 반복된다. A도 B로 들어가 그 순환에 합류한다.

  2. B만 변경하면 A→B→A가 반복된다. C의 옛 규칙은 여전히 D를 가리키므로 C 출발은 도착한다.

C를 먼저 변경하면 세 출발 모두 순환한다. B를 먼저 변경하면 A와 B 출발만 순환한다.

비교할 점

기본 두 장치 순환에 세 번째 장치의 영향 범위를 추가했다.

완료 확인을 포함한 적용 순서

A 적용 완료→B 적용 완료→C 적용 완료 순서의 각 중간 상태를 평가하라.

  1. A 적용 완료 직후 A는 D로, B는 C를 거쳐 D로, C는 D로 간다.

  2. B 적용 완료 직후 B는 A를 거쳐 D로 가고 C는 아직 D로 간다. C 적용 완료 뒤 C도 B와 A를 거쳐 D로 간다.

지정한 모형에서는 모든 중간 상태의 경로가 D에 도착한다. 설치 명령 전송 순서로 실제 적용 완료 순서를 대신하지 않는다.

비교할 점

정상인 최종 표뿐 아니라 중간 표의 경로 증거를 추가한다.

종이와 본문으로 직접 해보기

같은 이전/새 표에서 S1을 먼저 바꾸는 경우를 그려 보라. 중간 상태에 S1과 S2 각각에서 시작한 패킷이 어디로 가는가?

힌트 보기

바뀌지 않은 S2의 규칙도 그대로 적어 두어라.

풀이 보기

중간 상태는 S1→D, S2→D다. 두 출발점 모두 D에 도착한다. 이후 S2를 바꾸면 S2→S1→D다. 이 모형에서는 S1 먼저가 순환을 피하지만 모든 토폴로지에서 같은 순서가 통하는 일반 정리는 아니다.

오해와 반례

SDN이면 모든 패킷을 중앙 제어기가 직접 전달한다.

제어기는 규칙을 결정하고 전달 장치는 설치된 규칙을 실행할 수 있다. 예제의 패킷 경로에는 제어기를 넣지 않았다. 일부 미등록 흐름을 제어 쪽에 문의하는 설계도 있으므로 문의와 모든 데이터의 경유를 구별한다.

연습 1 · 값과 상태 예측

C를 먼저 변경한 상태에서 A의 규칙까지 새 A→D로 바꾸었다. 각 출발점의 결과는?

힌트 1

B는 아직 옛 규칙대로 C를 가리킨다.

힌트 2

A의 새 경로가 B와 C의 순환을 직접 고치지는 않는다.

풀이와 답 확인

  1. A는 직접 D로 간다.

  2. B→C→B와 C→B→C의 순환은 그대로다.

A만 도착하고 B와 C 출발은 순환한다.

흔한 오답에서 다시 생각하기

A가 D로 가므로 모든 출발점의 순환이 사라진다.

현재 B와 C는 A를 가리키지 않는다. 각 출발점에 적용되는 경로를 별도로 추적한다.

연습 2 · 오류 찾아 고치기

A, B, C 순서로 명령을 보냈으니 모든 중간 상태도 안전하다고 기록했다. 실제 적용 완료 순서는 C, A, B다. 설명을 고쳐라.

힌트 1

명령 발송과 설치 완료를 구별한다.

힌트 2

첫 완료 직후의 전달 표를 직접 작성한다.

풀이와 답 확인

  1. 첫 완료는 C의 새 규칙이고 A와 B는 옛 규칙이다.

  2. B와 C가 서로 가리켜 순환한다. 이후 A가 완료되면 A 출발만 해결되고 B가 완료될 때까지 B와 C 출발은 순환한다.

명령 발송 순서만으로 안전을 입증할 수 없다. 이번 적용 완료 순서는 순환하는 중간 상태를 포함한다.

흔한 오답에서 다시 생각하기

명령을 보낸 순서가 항상 적용 순서다.

독립 장치의 지연이 주어졌으므로 실제 적용 완료 사건을 사용해야 한다.

연습 3 · 직접 만들어 보기

이 토폴로지에서 다음 설치를 앞 설치의 적용 완료 후에만 시작하는 안전한 일정을 구성하라.

힌트 1

D로 직접 가는 A의 새 규칙부터 검토한다.

힌트 2

뒤 장치가 이미 도착 가능한 장치를 가리키게 한다.

풀이와 답 확인

  1. A의 설치 완료를 확인한다. 그 뒤 B→A의 설치 완료를 확인한다.

  2. 마지막으로 C→B의 설치를 적용한다. 각 완료 확인 직후 세 출발점의 경로를 기록한다.

A 완료 확인→B 완료 확인→C 완료 확인의 순서다. 이 모형 범위의 증거이며 범용 분산 갱신 알고리즘을 구현한 결과는 아니다.

흔한 오답에서 다시 생각하기

C에 명령을 미리 보내도 A와 B가 나중에 완료되니 괜찮다.

미리 보낸 C의 명령이 먼저 적용되면 위반된다. 일정의 핵심은 적용 완료의 의존 관계다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 모형에서 제어 통신은 t=2에 끊기지만 목적지 D의 규칙은 t=20 전까지 유효하고 정확히 20에 만료된다. 미등록 목적지 E의 패킷은 버린다. t=19와 t=20의 D 및 t=5의 E 결과는?

힌트 1

기존 전달 규칙과 새 정책 설치를 나눈다.

힌트 2

20 전이라는 엄격한 만료 조건을 적용한다.

풀이와 답 확인

  1. t=19의 D 패킷은 기존 규칙으로 전달한다. t=20의 D 패킷은 규칙이 만료되어 기본 버림 처리된다.

  2. t=5의 E 패킷은 등록된 규칙이 없어 버린다. 제어 통신 단절만으로 t=19의 D까지 즉시 버린다고 결론짓지 않는다.

D는 t=19에 전달, t=20에 버림이며 E는 t=5에 버림이다. 실제 장치의 만료 계약은 별도로 확인해야 한다.

재검증을 적중으로 세면 원본 조회 횟수도 줄어들까?

새 공개 자료 캐시는 같은 URI에서도 Vary: Accept-Language의 ko/en 조건을 별도로 보관한다. 저장 허용 조건은 충족했다고 정한다. 각 요청은 아래 표의 저장 존재 여부·현재 나이·수명 입력을 독립적으로 평가한다. 실제 Date/Age 계산이나 캐시 시간선을 구현한 것은 아니다.

이번 측정의 순수 적중은 조건이 맞고 신선하여 원본을 조회하지 않는 요청이다. 재검증은 기존 본문을 쓸 수 있어도 원본 확인을 하므로 별도 분류한다. 순수 적중의 전체 응답 시간은 4ms, 미적중은 44ms, 재검증은 24ms로 지정한다. 44ms와 24ms에는 각각 필요한 원본 왕복이 이미 포함되어 있다.

원본 조회 수와 지연을 함께 보고해야 같은 적중률의 다른 결과를 구별할 수 있다. URL만 키로 쓰면 ko의 신선한 본문을 en 요청에 잘못 줄 수 있다. 신선도 조건이 맞아도 언어 조건이 맞지 않으면 그 본문으로 직접 만족시키지 않는다.

요청을 어디에 보낼지 정한다

로드밸런서는 서비스의 여러 서버 중 요청을 받을 대상을 고른다. 돌아가며 고르는 round-robin은 요청 수를 비교적 균등하게 나누지만 각 요청의 처리 비용까지 같게 만들지는 않는다. 적은 활성 연결을 가진 서버를 고르는 방식도 있으나 연결 수 역시 CPU 비용이나 응답 시간을 완전히 나타내지는 않는다.

요청이 다른 서버로 갈 수 있으므로 로그인 상태를 한 서버 메모리에만 보관하면 다음 요청에서 상태를 찾지 못할 수 있다. 공유 저장소나 명시적인 세션 설계가 필요하다. 특정 서버에 붙이는 방식도 서버 장애와 상태 복구를 대신 해결하지 않는다.

CDN은 재사용 가능한 응답을 가까이 둔다

CDN은 여러 위치의 노드를 활용해 콘텐츠를 제공하는 체계다. 이 절에서는 그중 공개 콘텐츠 캐시를 다룬다. 원본 서버에서 받은 응답을 캐시에 보관하고 조건이 맞으면 다음 요청에 재사용한다. 로드밸런싱은 대상을 고르는 문제이고 캐싱은 이전 결과를 재사용하는 문제여서 한 서비스에서 함께 쓸 수 있다.

캐시는 URL만 같다고 언제나 재사용할 수 없다. 언어 등 요청 조건이 달라지면 Vary에 따라 캐시 키를 구별할 수 있다. 공유 캐시에는 private·no-store와 인증 요청의 별도 조건도 있다. 개인의 성적표를 공개 이미지와 같은 규칙으로 저장해서는 안 된다.

적중률과 시간은 서로 다른 수치다

이 수업의 적중률은 캐시에서 그대로 만족시킨 요청 수를 전체 요청 수로 나눈다. 원본을 확인해야 하는 재검증은 여기서는 적중으로 세지 않는다. 실제 운영 지표의 정의는 다를 수 있으므로 분모와 분류를 먼저 적는다.

RFC 9111의 신선도 판단은 freshness_lifetime > current_age다. 남은 시간이 없으면 별도 재검증이나 허용된 stale 제공 조건을 검토해야 한다. 캐시 만료는 원본 변경을 즉시 통지하는 장치가 아니다. 아래 지연값은 합성된 가정이며 실제 CDN 사업자나 네트워크 성능 수치가 아니다.

중간 과정을 따라가는 예제

요청 6개의 가상 처리 비용은 순서대로 8,1,1,1,1,1 작업 단위다. 두 서버 A/B에 A부터 교대로 보낸다. 별도 공개 이미지 요청 6개는 캐시 적중 4개/미적중 2개이며 적중 응답 5 ms, 미적중의 원본 조회를 포함한 전체 응답 45 ms다. 처리 비용과 응답 시간을 각각 계산하라.

  1. A는 1/3/5번을 받아 비용 8+1+1=10, B는 2/4/6번을 받아 1+1+1=3이다. 요청 수는 각각 3개다.

  2. 이미지 적중률은 4/6=2/3이다. 이 모형에서 원본 조회는 2개다.

  3. 평균 전체 응답 시간은 (4×5+2×45)/6=110/6=55/3 ms, 약 18.33 ms다.

  4. 45 ms는 이미 원본 조회를 포함하므로 5 ms를 또 더하지 않는다. 서버 작업 단위와 이미지 응답 ms는 서로 다른 실험 표다.

요청 수는 3/3이지만 작업량은 10/3이다. 별도 캐시 표의 적중률은 약 66.67%, 평균 응답은 약 18.33 ms다. 이 값으로 실제 처리율을 추정하지 않는다.

  2. 전체 응답 시간의 합은 4×4+2×44+2×24=152ms이고 여덟 요청으로 나누면 평균 19ms다.

연습 1 · 값과 상태 예측

재검증 두 개가 모두 원본 변경으로 미적중과 같은 전체 44ms를 썼다면 평균과 원본 조회 수는?

힌트 1

순수 적중 네 개는 그대로 4ms다.

힌트 2

원본을 묻는 요청의 개수는 변하지 않는다.

풀이와 답 확인

  1. 전체 응답 시간의 합은 4×4+4×44=192ms다.

  2. 192/8=24ms이고 원본 조회는 여전히 네 개 요청이다.

평균은 24ms, 원본 조회는 네 개 요청이다. 조회 수가 같아도 응답 시간이 같다는 뜻은 아니다.

흔한 오답에서 다시 생각하기

원본 조회 수가 같으니 평균도 19ms다.

조회 결과의 처리 시간이 달라졌다. 개수와 지연을 별도 측정한다.

연습 2 · 오류 찾아 고치기

재검증에 성공한 두 개를 적중에 넣어 적중률 6/8, 따라서 원본 조회는 두 개라고 보고했다. 설명을 고쳐라.

힌트 1

기존 본문 재사용과 원본 접촉을 나눈다.

힌트 2

측정 정의의 순수 적중에는 재검증을 넣지 않는다.

풀이와 답 확인

  1. 순수 적중률은 4/8이다. 기존 본문 재사용률이라는 다른 정의에서는 6/8로 기록할 수 있지만 지표 이름을 분리한다.

  2. 원본 조회는 미적중 두 개와 재검증 두 개를 합한 네 개 요청이다.

분류 정의와 분모를 명시하고 순수 적중률 1/2, 원본 조회 네 개 요청으로 보고한다.

흔한 오답에서 다시 생각하기

본문을 다시 다운로드하지 않으면 원본과 통신하지 않았다.

재검증은 원본 확인 통신을 포함한다. 본문 크기와 왕복 여부를 동일시하지 않는다.

연습 3 · 직접 만들어 보기

현재 나이 7초인 공유 캐시 응답에 s-maxage=5, max-age=20이 있고 다른 제한은 없다. 공유 캐시와 별도 사설 캐시의 명시 수명 판정을 구성하라.

힌트 1

공유 캐시는 s-maxage가 먼저다.

힌트 2

사설 캐시는 공유 전용 값 대신 max-age를 사용한다.

풀이와 답 확인

  1. 공유 캐시의 수명은 5초다. 5>7이 거짓이므로 신선하지 않다.

두 바이트만 보내는데 연결 흐름 한도를 네 바이트 더 소비할 수 있을까?

새 송신 모형은 이미 보낸 각 스트림의 가장 큰 끝 오프셋을 A는 6, B는 4로 정한다. 끝 오프셋은 반열린 구간의 끝이라 0부터 5까지 보냈다면 끝은 6이다. 스트림 한도는 A가 10, B가 8이고 연결 MAX_DATA는 12다. 누적 합은 6+4=10이므로 연결 허용량은 2가 남아 있다. 이번 문제는 일반 순서 읽기와 누적 송신 한도의 교육 모형이다.

A의 오프셋 8에 길이 2를 보내면 끝이 10이 되어 A의 누적 끝이 6에서 10으로 4 늘어난다. 실제 전송하려는 내용은 2바이트지만 중간 6·7의 구간도 누적 끝 오프셋에 포함된다. 새 합 10+4=14가 연결 한도 12를 넘으므로 보내지 못한다. 받은 고유 바이트 개수만 세면 이 차이를 놓친다.

반대로 기존 끝 6 이내의 빈칸을 채우거나 같은 내용을 재전송하면 가장 큰 끝 오프셋이 늘지 않아 추가 흐름 허용량을 소비하지 않는다. 그 전송도 경로 대역폭·혼잡 제어·패킷 공간을 쓸 수 있으므로 비용이 전혀 없다는 뜻은 아니다. 스트림 내 순서와 연결 전체 한도는 또 다른 조건이다.

UDP가 운반하고 QUIC이 기능을 더한다

RFC 9000의 QUIC 버전 1은 UDP 데이터그램으로 패킷을 운반하지만 그 위에서 연결·신뢰성 있는 스트림·흐름 제어·혼잡 제어와 TLS 통합을 제공한다. UDP만 보내는 프로그램과 QUIC 연결을 만드는 프로그램은 같은 기능을 가진다고 볼 수 없다. HTTP/3는 HTTP의 의미를 QUIC 위에 대응시키는 별도 응용 프로토콜이다.

패킷과 스트림은 다르다. 패킷 하나가 여러 스트림의 데이터를 담을 수 있고, 손실 뒤에는 필요한 데이터를 다시 보내더라도 원래 패킷의 경계가 응용에 보존되는 것은 아니다. 응용 메시지 경계는 여전히 응용 프로토콜이 정해야 한다.

스트림마다 자신의 빈칸을 기다린다

일반적인 순서 있는 스트림 읽기에서 오프셋은 각 스트림의 바이트 위치다. 앞부분이 빠진 스트림은 뒤부분을 받았어도 순서대로 내보내려면 빈칸을 기다린다. 다른 스트림의 완성된 데이터는 그 빈칸 때문에 같은 순서 제약을 받지 않는다. 스트림 사이의 전역 전달 순서도 QUIC이 정해 주지 않는다.

이 특성은 모든 지연을 제거한다는 뜻은 아니다. 스트림들은 연결의 혼잡 제어, 경로 대역폭, 연결 흐름 제어와 응용의 의존성을 공유할 수 있다. 예를 들어 응용이 A의 결과가 있어야 B를 처리한다면 B가 도착했어도 응용 단계에서 기다릴 수 있다.

이동과 속도에는 조건이 있다

연결 ID는 주소가 바뀌는 상황에서도 연결을 식별하는 데 쓰인다. RFC 9000의 이동은 핸드셰이크 확인과 경로 검증·상대의 제한 같은 조건을 따른다. 연결 ID만 안다고 임의 주소에 마음대로 대량 전송할 수 있는 기능이 아니다. 새 경로에서 손실이나 사용 가능 대역폭이 달라질 수도 있다.

0-RTT 역시 이전 통신이나 설정을 필요로 하는 선택 기능이다. 항상 첫 방문부터 왕복이 없거나 항상 TCP보다 빠르다고 판단하지 말라. 이 절의 시간선은 지정한 수신 사건에서 순서 규칙을 비교하는 종이 모형이며 QUIC 구현이나 인터넷 성능 시험이 아니다.

중간 과정을 따라가는 예제

순서 있는 읽기를 제공하는 가상 수신기가 있다. 스트림 A의 오프셋 2에 CD가 시각 2 ms에 도착하지만 오프셋 0의 AB는 8 ms에 도착한다. 스트림 B의 오프셋 0에 XY는 3 ms에 도착한다. A/B 사이 응용 의존성·흐름 제어 제한은 없고 수신 즉시 가능한 데이터를 읽는다고 가정한다.

  1. 2 ms에 A는 오프셋 0/1이 비어 있으므로 CD를 보관하고 순서 있는 읽기에는 내보내지 않는다.

  2. 3 ms에 B의 앞부분은 XY로 완성되므로 B는 XY를 내보낼 수 있다. A가 비었다는 이유로 B의 오프셋까지 비어 있는 것은 아니다.

  3. 8 ms에 AB가 도착하면 A의 0–3이 이어져 ABCD를 내보낸다.

  4. 비교용 단일 TCP 바이트열을 ABCDXY로 정하고 최초 AB만 같은 시각까지 빠졌다면 일반 순서 읽기는 뒤의 XY도 앞 빈칸을 기다린다. 이 비교는 정확한 사건을 고정한 모형이지 두 구현의 처리속도 측정이 아니다.

B는 3 ms, A는 8 ms에 순서 있는 데이터를 읽을 수 있다. 스트림 내부 순서는 유지하면서 서로 다른 스트림의 빈칸은 구별한다.

오해와 반례

QUIC은 UDP 기반이므로 순서나 재전송이 없고 손실이 있어도 다른 작업은 절대 느려지지 않는다.

기존 A의 최대 끝 6과 차이를 비교한다.

풀이와 답 확인

  1. A의 누적 끝 증가는 4다.

  2. 새 연결 합은 A 끝 10+B 끝 4=14다.

연결 한도 12를 2만큼 넘어 실패다. 누락 구간을 빼고 고유 전송 길이만 합산하지 않는다.

흔한 오답에서 다시 생각하기

구멍은 아직 보내지 않았으니 끝 오프셋 합에도 없다.

이번 누적 흐름 제어는 가장 큰 끝 오프셋을 기준으로 하므로 구멍 너머의 끝도 반영한다.

연습 3 · 직접 만들어 보기

초기 A 끝 6, B 끝 4에서 A offset 8, len 2를 허용하려면 최소 MAX_DATA는? A의 스트림 한도 10은 유지한다.

힌트 1

원하는 각 끝은 A가 10, B가 4다.

힌트 2

합계가 한도 경계와 같을 때까지 허용한다.

풀이와 답 확인

  1. 연결 한도 10+4=14를 광고해야 연결 조건에 맞는다.

  2. A의 스트림 한도 10은 이미 끝 10을 허용한다. 이후 MAX_DATA 11 광고는 기존 연결 한도 14를 줄이는 효과가 없다.

최소 연결 한도는 14다. 더 작은 후속 광고는 이미 증가한 한도를 회수하지 않는다.

흔한 오답에서 다시 생각하기

큰 한도 14를 광고한 뒤 11을 보내면 즉시 11로 줄일 수 있다.

RFC9000의 한도 증가는 누적이며 증가시키지 않는 MAX_DATA는 무시한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

같은 offset과 같은 내용을 재전송하면 추가 흐름 허용량의 소비는 0이다. 따라서 대역폭도 0이고 혼잡 제어도 무관하다는 주장을 평가하라.

힌트 1

허용량 회계와 실제 패킷 전송을 나눈다.

힌트 2

같은 내용이 네트워크를 다시 지나간다.

풀이와 답 확인

  1. 누적 끝이 늘지 않으므로 흐름 허용량의 추가 소비는 없다.

  2. 그러나 실제 재전송 패킷은 링크 용량과 전송 시간을 사용하고 공유 연결의 혼잡 조건을 따른다.

추가 흐름 허용량 소비 0은 실제 전송 비용 0이 아니다. 스트림 독립성도 공유 대역폭의 영향을 없애지 않는다.

흔한 오답에서 다시 생각하기

QUIC 스트림이 독립이면 공유 연결 한도는 필요 없다.

각 스트림의 순서와 전체 수신 용량·혼잡 제어는 서로 다른 기능이다.

내 말로 설명하기

스트림 프레임 경계가 응용 메시지 경계인가?

설명 기준 확인

QUIC 스트림은 바이트열이며 메시지 경계는 응용 프로토콜이 정한다.

같은 오프셋으로 재전송할 때 내용도 바꾸어도 되는가?

설명 기준 확인

같은 스트림 오프셋의 데이터는 같아야 한다. 재전송을 그 위치의 내용 수정으로 사용하지 않는다.

한 단계 더

B가 A의 처리 결과를 참조하는 응용이라면 B의 네트워크 도착 3 ms와 응용 처리 가능 8 ms를 별도 열로 적어 보라. 전송 독립성과 응용 의존성을 분리하면 도착 순서만 보고 전체 서비스 완료를 단정하는 실수를 줄일 수 있다.

다른 문제에 적용하기

세 독립 모형의 새 비교표를 작성하라. 제어기는 새 경로 A→D, B→A, C→B의 명령을 모두 보냈으나 현재 적용 완료는 C뿐이고 옛 표는 A→B, B→C, C→D다. 별도 캐시 표는 순수 적중 네 개, 미적중 두 개, 재검증 두 개이며 각 전체 응답 시간은 4ms, 44ms, 24ms다. 별도 QUIC 송신은 초기 끝이 A 6, B 4이고 한도는 A 10, B 8, 연결 12이며 A offset 8, len 2를 제안한다. 각 경로·원본 조회 수와 평균·흐름 조건을 평가하고 명령 수, 본문 재사용, 실제 두 바이트만으로 성공을 세면 안 되는 이유를 설명하라.

힌트 1

제어 메시지 발송과 현재 적용 완료 상태를 나눈다.

힌트 2

캐시의 원본 접촉과 QUIC의 누적 끝 오프셋을 각각 세라.

풀이와 답 확인

  1. C만 새 규칙이면 B↔C가 순환하고 A도 합류한다. 새 정책 명령 세 개의 발송이 세 개의 적용 완료를 뜻하지 않는다.

  2. 원본 조회는 미적중 두 개와 재검증 두 개를 합한 네 개 요청이고 평균 전체 응답 시간은 152/8=19ms다. 재검증은 이 측정의 순수 적중에 넣지 않는다.

  3. A의 새 끝 10과 B의 끝 4를 합한 14가 연결 한도 12를 넘어 흐름 조건에서 실패한다. 실제 내용 2바이트와 누적 끝 증가 4를 구별한다.

현재 경로는 순환하며 캐시 원본 조회는 네 개 요청, 평균 응답 시간은 19ms다. 제안 전송은 연결 한도 초과다. 이는 독립된 세 종이 모형의 평가이며 실제 데이터센터·CDN·QUIC 시험 결과가 아니다.

해결한 뒤 점검할 것

  • 원하는 최종 상태와 현재 설치 완료 상태를 구별한다.

  • 세 캐시 분류와 응답 시간의 분모를 명시한다.

  • 스트림과 연결의 두 한도 및 누적 끝 증가를 모두 적용한다.

세 장치의 현재 표에서 모든 출발 경로와 적용 완료 순서 C, A, B의 중간 순환을 손으로 추적했다. 캐시의 순수 적중 네 개·미적중 두 개·재검증 두 개의 전체 응답 시간 합은 152ms, 평균은 152/8=19ms다. 재검증 시간이 각각 44ms로 바뀌면 합은 192ms, 평균은 24ms이며 원본 조회는 두 경우 모두 네 개 요청이다. 나이 7초와 비교할 때 공유 수명 5초의 5>7은 거짓이고 사설 수명 20초의 20>7은 참이다. 활성 연결 수 A 1개/B 2개와 남은 작업량 A 100단위/B 2단위의 비교 결과가 다름을 확인했다. 초기 QUIC 누적 끝 합은 A 6+B 4=10이다. A offset 8, len 2의 새 끝은 10, 끝 증가는 4, 새 연결 합은 14다. 기존 끝 이내의 빈칸 채움은 끝 증가가 0이다. B의 끝을 6으로 늘리면 연결 합은 12이고 이후 A의 끝을 7로 늘리려면 합이 13이다. 제안한 A 끝 10/B 끝 4에 필요한 최소 연결 한도는 14이며 더 작은 후속 광고로 이 한도를 줄이지 못한다. A의 순서 읽기는 AB 이후 빈칸 CD를 받은 뒤 CDEF로 이어짐을 손검산했다. 실제 장치·CDN·QUIC·학생 실험은 수행하지 않았다.
