최소권한과 요청시점

앱 첫 화면을 보는데 왜 아직 쓰지 않는 기능의 권한까지 물어야 할까?

준비 개념과 학습 목표

준비 개념

  • 앱 기능

  • 허용과 거절

학습 목표

  • 필요한 기능에 권한을 대응한다.

  • 사용 시점 확인과 대체 흐름을 설계한다.

기능과 접근 이유를 연결한다

권한은 사용자가 특정 기기 자원 접근을 허용하는 경계다. Android의 runtime permission 대상인지와 권한 없이 가능한 대안을 먼저 검토한다. 선언만으로 사용자 허용이 완료됐다는 뜻은 아니며 특수 권한에는 별도 절차가 있다.

사용자가 기능을 시작할 때 요청한다

위치 버튼처럼 접근이 필요한 맥락에 짧은 이유를 설명하고 현재 허용 상태를 확인한다. 필요한 동작마다 다시 확인해 과거 승인에만 의존하지 않는다. 묶음으로 모든 기능을 열려는 요청보다 이번 작업에 필요한 범위를 정한다.

거절은 정상적인 경로다

사용자가 설명이나 요청을 취소할 수 있고 기능을 쓰지 않아도 다른 화면은 계속 사용할 수 있게 한다. 거절되면 수동 입력 등 대안을 연결한다. Android 버전·권한 종류에 따라 대화상자와 재요청 정책은 달라 동일한 버튼 순서를 모든 기기에 약속하지 않는다.

중간 과정을 따라가는 예제

교육용 지도 앱의 흐름은 열기→수동 도시 보기이며 위치 버튼에서만 현재 위치 권한을 확인한다. 첫 사용자는 위치를 거절한다. 권한 요청이 필요한 횟수와 사용할 수 있는 기능을 추적하라.

  1. 첫 화면 열기는 수동 도시 보기라 위치 요청 0 회다.

  2. 위치 버튼에서 미허용을 확인하고 이번 요청 1 회를 시작한다.

  3. 거절 뒤 위치 자동 찾기는 중단하고 수동 도시 보기는 유지한다.

이번 흐름은 요청 1 회, 자동 위치 없음, 수동 도시 보기 가능이다.

센서·위치·카메라

같은 센서 기능은 모든 휴대전화에서 같은 값을 줄까?

준비 개념과 학습 목표

준비 개념

  • 값과 단위

  • 권한 확인

학습 목표

  • 지원 여부와 데이터 의미를 확인한다.

  • 수명·정확도·기기 기능의 실패 조건을 구별한다.

지원과 성공은 다르다

Android 센서 framework로 존재와 range·resolution 등을 확인한다. 센서가 없거나 반환이 지연되는 기기도 있어 빈 결과를 처리한다. 권한 허용은 장치 존재·서비스 동작·값 정확도의 증명과 다르다.

좌표·단위·시점을 읽는다

가속도와 위치와 사진은 자료 모양이 다르다. 축·단위·촬영 방향·시각을 연결해 해석하며 예전 위치를 지금의 위치라고 단정하지 않는다. 위치의 foreground/background와 approximate/precise 범위는 따로 정하고 사용자가 근사 위치만 허용한 경우를 지원한다.

사용 수명을 끝낸다

센서 listener는 필요한 화면 수명에 맞게 등록/해제해 불필요한 이벤트와 에너지 사용을 줄인다. 카메라 촬영은 시작·성공·취소·오류를 구별한다. 기기 API·버전별 절차를 확인하며 아래 숫자 벡터는 실제 센서의 좌표 보정이나 중력 제거 실험이 아니다.

중간 과정을 따라가는 예제

자체 센서가 같은 좌표계에서 (3,4,0)과 (0,0,5) m/s²를 반환했다. 각 크기를 구하라. 별도 위치 기능은 근사 위치만 허용됐으며 정확한 거리 안내는 하지 않기로 정했다.

  1. 첫 크기는 sqrt(3²+4²+0²)=sqrt(25)=5 m/s²다.

  2. 둘째도 sqrt(25)=5이지만 방향은 다르다. 같은 크기로 같은 움직임이라 단정하지 않는다.

  3. 근사 위치로 도시 수준 정보만 제공하고 정밀 거리 기능은 이 계약에서 비활성화한다.

두 크기는 5 m/s², 방향은 다르며 정밀 거리 기능은 제공하지 않는다.

오해와 반례

위치 허용이면 항상 정밀 좌표를 받는다.

사용자가 approximate만 허용하면 앱 선언과 무관하게 근사 수준만 받는다. 허용·정확도·현재 측정 성공은 별도다.

거절·취소·개인정보

촬영을 취소했는데도 사진이 서버에 올라가면 어느 경계가 빠졌을까?

준비 개념과 학습 목표

  • 앱 수명

학습 목표

  • 사용 목적과 저장·공유 범위를 명시한다.

한 가지 실패값으로 뭉치지 않는다

권한 거절은 접근 불허, 촬영 취소는 사용자가 작업을 끝내지 않은 결과, 장치 오류는 실행 실패다. 성공 자료가 있는 경우에만 다음 처리를 시작한다. 실제 API의 결과·예외·수명 콜백을 한 교육용 상태표에 대응하고 구체 구현을 확인한다.

철회와 일회 권한을 고려한다

Android 11의 위치·마이크·카메라 일회 권한처럼 허용의 수명이 제한될 수 있다. 다음 사용에 현재 상태를 다시 검사하고 철회나 프로세스 종료를 정상적으로 복구한다. 이전 화면의 허용 사실을 영구 접근 계약으로 저장하지 않는다.

수집과 공유는 다른 결정이다

사진을 화면에 보여 줄 목적과 외부 서버 전송 목적을 구별한다. 필요한 자료만 보관하고 목적·수명·삭제 동작을 설명한다. 권한 승인은 모든 후속 사용에 대한 포괄 동의나 법적 의무 충족의 증명이 아니다. 이 단원은 UX·기술 계약이며 나라별 법률 판단은 수행하지 않는다.

중간 과정을 따라가는 예제

자체 사진 흐름은 권한 허용→촬영→결과 확인→사용자 업로드 확인→전송이다. 허용 뒤 촬영 취소, 촬영 성공 뒤 업로드 거절, 촬영 성공 뒤 업로드 허용의 세 경우를 각각 판단하라. 자동 전송은 없다.

  1. 촬영 취소는 성공 사진이 없어 전송 0 회다.

  2. 촬영 성공이어도 업로드 확인에서 거절하면 전송 0 회다.

  3. 성공 자료와 업로드 허용이 모두 있으면 전송 1 회를 시작한다. 전송 완료 여부는 별도 결과다.

세 경우의 전송 시작 횟수는 0/0/1이다. 시작 1 회를 성공 완료 1 회로 보고하지 않는다.
