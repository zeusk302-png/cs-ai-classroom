소단원 7.1

persistent list·tree

자료를 바꾼 뒤에도 이전 버전을 볼 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 리스트 노드와 꼬리

  • 이진 탐색 트리

  • BST는 왼쪽에 더 작은 값, 오른쪽에 더 큰 값을 두는 이진 탐색 트리다.

학습 목표

  • persistent와 저장 장치 보존을 구별한다.

  • 불변 리스트와 트리의 업데이트 결과를 추적한다.

옛 초안에서 두 갈래로 고쳐도 서로의 수정이 보일까요?

문서 초안의 제목만 바꾼 사본과 본문만 바꾼 사본을 같은 원본에서 만들 수 있다. 여기서는 저장 파일 대신 불변 cons 노드의 연결 그림으로 그 상황을 표현한다. 업데이트는 결과의 루트를 반환하며 원래 루트를 쓰던 계산은 이전 값을 계속 읽는다.

새 사례의 원본 L은 A(1) → B(2) → C(3) → D(4)다. 위치는 1부터 센다. replace는 지정 위치까지 내려가 새 값을 담은 노드와 그 앞 노드를 재구성하고 뒤 꼬리는 공유한다. 모든 위치가 유효하고 값은 불변 정수다. 버전 이름을 바꾸는 것과 노드 필드를 쓰는 것은 다른 동작이다.

예제와 각 연습은 명시된 원본에서 독립적으로 시작한다. 앞 문항의 변형이나 삭제를 다음 문항의 초기 상태로 이어받지 않는다.

먼저 확인할 개념
  • persistent list·tree

    새 결과를 반환하는 갱신과 옛 버전 유지, 리스트 경로 재구성의 전제를 사용한다.

  • 구조공유

    값의 일치와 실제 노드 공유를 식별자로 구별한다.

과거 버전을 유지하는 업데이트

persistent 자료구조는 업데이트 뒤에도 이전 버전을 사용할 수 있게 하는 자료구조다. 여기서는 불변 노드를 사용해 새 결과를 반환하는 함수형 구현을 다룬다. persistent는 파일에 저장해 전원을 꺼도 남는다는 뜻으로 쓰지 않는다.

원래 리스트 L=[2,4,6]에 1을 앞에 붙이면 새 리스트 N=[1,2,4,6]을 얻고 L은 그대로다. 기존 노드의 값을 바꾸지 않으므로 L을 쓰는 다른 계산에도 영향을 주지 않는다. 변수에 새 결과를 대입하는 일과 노드를 변경하는 일을 구별한다.

불변 리스트의 앞과 꼬리

cons 노드는 값 하나와 다음 노드 참조를 가진다. prepend는 새 cons 하나를 만들어 기존 L을 꼬리로 참조한다. 빈 리스트는 이 예제에서 노드가 없는 종료 표식이며 cons 개수에 포함하지 않는다.

N의 첫 노드를 떼고 꼬리를 읽으면 L을 얻는다. 꼬리를 반환하는 pop은 L을 복사하지 않는다. 빈 리스트에서 pop은 실패를 명시적으로 표현해야 한다. 모든 위치의 삭제가 같은 비용은 아니며 중간 노드까지 가려면 앞부분을 탐색한다.

트리는 탐색 경로를 새로 만든다

불변 BST의 삽입은 작은 값은 왼쪽, 큰 값은 오른쪽으로 내려가고 빈 자리에 새 노드를 만든다. 돌아오면서 경로의 조상 노드를 새로 만들어 바뀐 자식을 연결한다. 방문하지 않은 반대쪽 서브트리는 공유한다.

현재 검사한 노드의 값과 같으면 insert는 그 부분트리 t를 그대로 반환한다. 루트와 같은 값을 넣으면 전체 기존 트리를 반환한다. 비루트에서 같은 값을 발견하면 이 재귀 구현은 돌아오는 조상 노드를 새로 재구성할 수 있다. 아래 예제는 회전 없는 단순 BST다. 균형 트리의 회전과 색 변경은 별도 알고리즘이며 이름에 tree가 있다고 자동으로 빠른 탐색을 보장하지 않는다.

M과 N은 각각 L을 입력으로 받는다. N을 M에서 만드는 연속 갱신이 아니다. M의 C1과 N의 C는 다른 노드이며 세 루트에서 도달하는 고유 노드는 4+3+2=9개다.

중간 과정을 따라가는 예제

L=[2,4,6]에서 N=prepend(1,L), P=tail(N)을 구한다. 세 버전의 값과 새 cons 수는?

  1. L의 세 cons는 변경하지 않는다.

  2. 값 1의 새 cons 하나가 L의 첫 cons를 참조하여 N=[1,2,4,6]이다.

  3. tail(N)은 기존 L을 반환하므로 P=[2,4,6]이며 추가 노드는 없다.

L=P=[2,4,6], N=[1,2,4,6], 추가 cons는 1개다.

조건을 바꾸어 비교하기

같은 원본에서 분기한 수정

표의 L/M/N을 모두 보관할 때 세 값과 실제 고유 노드 수를 구하라.

  1. M은 세 번째 값만 9로 바꾸고 N은 두 번째 값만 8로 바꾼다.

  2. L의 네 노드를 고친 적은 없다. M의 새 노드 세 개와 N의 새 노드 두 개는 별도다.

  3. D는 세 버전이 공유하고 C는 L과 N이 공유한다. 루트별 길이 합 12에서 중복 도달을 제거한다.

L은 [1,2,3,4], M은 [1,2,9,4], N은 [1,8,3,4]이며 고유 cons는 9개다.

비교할 점

분기 갱신과 직전 결과를 다시 고치는 연속 갱신을 구별한다.

중간 삭제는 앞부분을 다시 연결한다

새 독립 원본 A → B → C → D에서 첫 값 3을 삭제하는 remove를 설계한다. 앞부분을 경로 복사하며 찾은 노드는 그 꼬리로 대체한다.

  1. C를 발견하면 D를 반환한다. C.next를 덮어쓰지 않는다.

  2. B의 새 사본 B1은 D를 가리키고 A의 새 사본 A1은 B1을 가리킨다.

  3. 새 결과 A1 → B1 → D는 [1,2,4]다. 원본 네 노드와 새 두 노드를 모두 보관한다.

새 cons는 2개, 두 버전 고유 cons는 6개, 공유 cons는 D 한 개다.

비교할 점

대상을 새로 만드는 값 변경과 대상 노드를 생략하는 삭제의 할당 수는 다르다.

종이와 본문으로 직접 해보기

BST 루트2, 왼쪽1, 오른쪽3에서 4를 넣어라. 새 노드와 공유 노드를 적어라.

힌트 보기

경로 2→3→빈 자리를 따라간 뒤 되돌아온다.

풀이 보기

새 4, 새 3, 새 2의 3개를 만들고 기존 1을 공유한다. 옛 트리는 1,2,3을 유지한다.

오해와 반례

persistent는 반드시 디스크에 저장한다는 뜻이다.

여기서는 업데이트 이후 과거 버전 사용 가능성을 뜻한다. 파일 저장 여부는 별도 조건이다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

표의 M에서 tail을 두 번 적용한 T를 구하라. M/L/N은 계속 보관한다.

힌트 1

tail은 첫 cons의 다음 참조를 반환한다.

힌트 2

두 번 뒤에는 C1을 루트로 삼는다.

풀이와 답 확인

  1. T는 C1 → D다.

  2. 추가 노드를 만들지 않아 전체 고유 cons는 여전히 9개다.

T의 값은 [9,4]이고 새 cons는 0개다.

흔한 오답에서 다시 생각하기

tail마다 나머지를 전부 복사하므로 5개가 추가된다.

이 모형의 tail은 참조 반환이다. 깊은 복사 연산을 별도로 요청하지 않았다.

연습 2 · 오류 찾아 고치기

M을 만들려고 기존 C.value를 9로 바꾼 뒤 A를 새 이름 M에 대입했다. 과거 L 보존이 깨지는 이유와 수정을 적어라.

힌트 1

새 변수 이름은 노드 복사가 아니다.

힌트 2

변경 위치와 그 앞 노드가 새로 필요하다.

풀이와 답 확인

  1. L도 기존 C에 도달하므로 [1,2,9,4]를 읽게 된다.

  2. C1(9), B1(2), A1(1)을 새로 만들고 D만 공유해야 한다.

기존 필드 쓰기를 제거하고 세 노드를 경로 복사한다.

흔한 오답에서 다시 생각하기

M이라는 새 이름을 만들었으므로 L의 노드도 보호된다.

이름의 수는 실제 객체의 수를 늘리지 않는다.

연습 3 · 직접 만들어 보기

원본 L에서 첫 값 2를 삭제한 R과 첫 값 1을 삭제한 S를 서로 독립적으로 구성하라. L/R/S를 모두 보관한다.

힌트 1

대상을 찾으면 그 꼬리를 반환한다.

힌트 2

대상 앞부분만 새로 연결한다.

풀이와 답 확인

  1. R은 새 A3(1) → C → D로 [1,3,4]다.

  2. S는 기존 B → C → D로 [2,3,4]다.

  3. 추가 cons는 R의 A3 한 개뿐이며 전체 고유 cons는 5개다.

R과 S는 기존 꼬리를 공유하며 원본 L은 그대로다.

흔한 오답에서 다시 생각하기

S도 길이 3이므로 새 cons 세 개가 필요하다.

첫 노드 삭제는 기존 꼬리를 반환하면 된다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

없는 값 8을 삭제할 때 (가) 매번 앞 노드를 재구성하는 구현과 (나) 자식 결과가 기존 자식과 같은 노드면 기존 부모를 반환하는 구현을 비교하라. 원본 길이는 4다.

힌트 1

두 구현 모두 끝에서 없음으로 끝나고 값은 같다.

힌트 2

새 객체 생성 여부는 돌아오는 경로의 분기에 달린다.

풀이와 답 확인

  1. 가 구현은 빈 꼬리를 반환한 뒤 D/C/B/A를 새로 만들어 cons 네 개를 추가한다.

  2. 나 구현은 각 자식 참조가 그대로임을 확인해 기존 부모를 반환하므로 추가 cons는 없다.

두 결과 값은 [1,2,3,4]다. 가는 새 노드 4개, 나는 0개이며 둘 다 네 노드를 탐색한다.

흔한 오답에서 다시 생각하기

없는 값을 찾으면 탐색과 할당도 모두 0이다.

값이 없음을 확인하려면 끝까지 읽어야 한다. 할당 회피가 탐색 회피는 아니다.

소단원 7.2

구조공유

과거 버전을 남기면 매번 모든 자료를 복사해야 할까?

준비 개념과 학습 목표

준비 개념

  • 불변 노드

  • 참조와 도달 가능성

학습 목표

  • 논리적 자료 수와 실제 고유 노드 수를 구별한다.

  • 경로 복사와 공유의 경계를 계산한다.

불변 상자에 가변 메모를 넣으면 옛 버전의 내용도 고정될까요?

책꽂이의 칸 연결은 바꾸지 않아도 칸 안의 공용 노트를 고치면 여러 사람이 새 내용을 본다. 구조공유의 안전성도 노드 연결과 내부 값의 변경을 구분해야 한다. 여기서는 참조 셀 r의 내용과 리스트 cons의 연결을 별도 그림으로 센다.

새 사례에서 r의 내용은 정수 5다. L의 유일한 cons A는 r을 값으로 담고, N은 새 cons B(r)를 앞에 붙여 B → A가 된다. A와 B의 필드는 불변이지만 r은 가변이다. 각 셀의 현재 내용을 읽는 관찰 readAll과 생성 당시 정수를 별도 저장하는 snapshotAll은 서로 다른 계약이다. 실제 OCaml 실행이나 GC 관찰은 하지 않는다.

이 소단원의 예제와 연습도 각 문항에 적힌 셀 내용과 루트에서 독립적으로 시작한다. 앞 문항에서 수행한 셀 쓰기를 다음 문항에 이어 적용하지 않는다.

먼저 확인할 개념
  • 구조공유

    불변 노드 안의 가변 객체와 도달 가능성, 회수 가능성의 조건을 이어간다.

  • persistent list·tree

    prepend와 tail이 만드는 새 노드 및 공유 꼬리의 연결을 사용한다.

값이 같은 것과 같은 노드를 공유하는 것

구조공유는 여러 버전이 동일한 실제 노드를 참조하는 것이다. 값이 같아도 별도로 만든 노드는 공유가 아니다. 각 노드에 A,B,C 같은 식별자를 붙이면 값만 적은 그림보다 실제 공간을 정확히 셀 수 있다.

L의 노드 A(2)→B(4)→C(6)에서 두 번째 값을 9로 바꾼 새 리스트를 만든다. B를 수정하면 옛 L도 변하므로 새 B2(9)를 만들고 앞의 A도 새 A2(2)로 복사한다. 바뀌지 않은 꼬리 C는 공유한다.

트리에서 바뀐 경로만 복사하기

옛 BST는 루트4, 왼쪽2의 자식1·3, 오른쪽6의 자식5·7인 7노드 트리다. 8 삽입 경로는 4→6→7→빈 자리다. 새8과 새7·6·4를 만들고 옛 왼쪽 서브트리와 노드5를 공유한다.

옛 버전7개와 새 버전8개를 더한 15는 고유 노드 수가 아니다. 공유 노드4개를 한 번만 세면 7+4=11개다. 이 계산은 값 노드만 포함하며 빈 표식과 언어 런타임의 메타데이터 바이트는 제외한다.

공유를 안전하게 유지하는 조건

공유한 노드를 변경하지 않는 것이 핵심이다. 공유 C의 값을 6에서 10으로 직접 바꾸면 두 리스트 모두 영향을 받는다. 따라서 불변 노드와 변경 가능한 내부 객체를 담은 노드는 구별해야 한다. 겉 리스트만 불변이어도 내부 객체의 변경은 별도 문제다.

오래된 버전 참조를 버리면 그 버전만 도달하던 노드는 회수 가능해질 수 있다. 새 버전에서도 도달하는 공유 노드는 계속 필요하다. 회수 가능성은 실제 GC가 그 순간 실행되어 메모리를 회수했다는 관찰과 다르다.

노드 두 개와 참조 셀 한 개를 각각 센다. 리스트 길이는 1과 2로 고정되어도 내부 값을 읽는 결과는 바뀐다. 이 사례는 정수만 담은 앞 소단원의 완전 불변 전제를 확대하지 않는다.

중간 과정을 따라가는 예제

L=[2,4,6]의 중간 값을 9로 바꾼 M을 만든다. L과 M을 모두 보관할 때 고유 cons 수와 공유 cons 수는?

  1. 원래 A,B,C 3개를 유지한다.

  2. 새 B2(9)와 새 A2(2)의 2개를 만든다.

  3. M=A2→B2→C이므로 C 한 개만 공유한다.

고유 cons는 5개, 두 버전의 공유 cons는 1개다.

조건을 바꾸어 비교하기

값을 읽어 만든 스냅샷은 참조 복사와 다르다

r의 내용이 5일 때 snapshotAll(N)이 [5,5]라는 새 정수 리스트 S를 만든다. 그 뒤 r에 8을 쓴다. N과 S의 관찰을 비교하라.

  1. N의 두 요소는 같은 r을 참조하므로 현재 내용을 읽으면 두 번 8을 얻는다.

  2. S의 두 cons에는 이미 읽은 불변 정수 5가 들어 있고 r을 담지 않는다.

  3. N의 연결과 S의 연결은 별개이며 S의 두 cons도 별도로 만든 것으로 가정한다.

readAll(N)은 [8,8]이고 S는 [5,5]다. cons는 A/B와 S의 두 노드로 총 4개이며 셀 r은 별도 한 개다.

비교할 점

불변 정수 값 복사와 가변 셀 참조 복사의 관찰 차이다.

옛 루트를 버려도 외부 꼬리 참조가 남는다

앞 소단원의 L/M/N 세 버전을 보관한다. 추가 참조 E는 L의 세 번째 노드 C를 가리킨다. 먼저 L을 버리고 나중에 N도 버리며 M/E는 유지한다.

  1. 처음 고유 노드는 9개다. L을 버려도 N과 E가 C/D에 도달하고 M은 D에 도달한다.

  2. 기존 A/B 두 개만 다른 경로가 없어 회수 가능하다. 남은 도달 노드는 7개다.

  3. N도 버리면 A2/B2가 회수 가능하다. M의 네 노드와 E의 C/D 중 공유 D를 한 번 세면 5개다.

L 제거 뒤 도달 cons는 7개, N도 제거한 뒤는 5개다. 실제 회수 시각이나 바이트 측정은 아니다.

비교할 점

루트 이름의 삭제와 모든 참조 경로의 제거를 구별한다.

종이와 본문으로 직접 해보기

위 7노드 BST에 8을 삽입하고 옛 루트 참조만 버린다. 새 버전의 도달 노드 수와 옛 버전 전용 노드 수는?

힌트 보기

새 경로와 공유 노드를 따로 센다.

풀이 보기

새 버전은 8개에 도달한다. 옛 경로4·6·7의 3개는 다른 참조가 없다는 조건에서 회수 가능하다. 공유1·2·3·5는 유지된다.

오해와 반례

두 버전의 길이를 더하면 실제 고유 노드 수가 된다.

공유 노드는 중복 계산된다. 리스트 예제 3+3=6에서 공유 C를 한 번 빼면 5다.

힌트 1

힌트 2

풀이와 답 확인

연결 보존만으로 내부 현재값 관찰을 고정할 수 없다.

힌트 1

힌트 2

풀이와 답 확인

  2. K의 두 새 cons가 각각 q1과 q2를 담는다.

힌트 2

소단원 7.3

시간·공간 비용

공유를 하면 모든 연산이 상수 시간일까?

준비 개념과 학습 목표

준비 개념

  • 빅오

  • 경로 길이

  • O는 입력 증가에 따른 비용의 상한 규모를 나타낸다. h는 트리 높이로, 루트에서 가장 깊은 노드까지의 경로 길이 규모다.

학습 목표

  • 연산과 구현 조건별 시간 비용을 설명한다.

  • 전체 버전 보관 조건의 공간을 계산한다.

같은 옛 큐에서 계속 분기하면 역전 비용을 한 번만 낼까요?

앞 본문에서 버전들을 함께 보관할 때 고유 노드를 세었다. 시간 분석에서도 실행이 한 줄로 이어지는지, 과거 버전에서 여러 갈래로 다시 시작하는지 정해야 한다. 한 번 수행한 계산 결과를 저장하지 않은 순수 함수 호출은 같은 입력에서도 계산을 반복할 수 있다.

여기서는 자체 두 리스트 큐 Q=(out,in)을 정한다. 논리 순서는 out 뒤에 reverse(in)을 붙인 것이다. pop은 out이 있으면 그 꼬리를 반환하고, out이 비었으면 in을 새 cons로 역전한 다음 첫 항목을 제거한다. 역전 결과를 옛 Q에 저장하거나 memoize하지 않는다. 비용은 역전에 읽은 항목 수이며 Q=([],[4,3,2,1])을 여러 번 입력으로 주는 분기 사례를 다룬다. out과 in이 모두 비었으면 pop은 Empty 실패를 반환하며 노드를 만들지 않는다. 각 예제와 연습은 표시된 Q 또는 BST에서 독립적으로 시작한다.

먼저 확인할 개념
  • 시간·공간 비용

    연산별 시간 비용과 모든 버전 보관의 공간 조건을 분리한다.

  • 구조공유

    서로 다른 호출의 새 노드와 도달 가능한 공유 노드를 식별자로 센다.

연산마다 탐색량이 다르다

연결 리스트 prepend는 새 cons 하나를 붙이므로 노드 연산 모형에서 O(1) 시간과 추가 공간이다. 길이가 n인 리스트의 마지막 원소 찾기는 앞에서 차례로 가므로 O(n) 시간이다. 구조공유만으로 이 탐색이 사라지지 않는다.

앞에서 k번째 값 변경은 그 위치까지 탐색하고 앞 경로를 재구성한다. 위치를 1부터 세면 새 cons는 k개이고 시간 O(k)다. 실제 바이트 비용이나 GC 시간은 이 단순 노드 수 모형에 포함하지 않는다.

트리의 높이 조건

BST의 탐색과 경로 복사 삽입은 높이 h에 대해 O(h)이다. 값들을 정렬 순서로 회전 없이 넣으면 한 줄 모양이 되어 h가 n까지 커질 수 있으므로 최악 O(n)이다. 모든 BST를 O(log n)이라고 적으면 조건을 빠뜨린다.

균형 유지 규칙을 갖춘 red-black tree 같은 구조에서는 높이가 O(log n)으로 제한된다. 그 규칙을 실제 유지하는 구현에서만 로그 시간 결론을 쓴다. 작은 완전 트리 그림이 있다고 이후 삽입에서도 완전 모양이 유지된다는 뜻은 아니다.

버전을 모두 보관하는 공간

길이3인 리스트에서 세 번 prepend하고 네 버전을 모두 보관한다. 공유 구현은 초기3개+새1개씩3번=6개 고유 cons다. 각 버전을 통째로 별도 복사하는 비교 구현은 3+4+5+6=18개다. 이 비교에서는 각 새 버전에 완전 복사 결과만 보관한다.

초기 길이 n에 m번 prepend한 모든 버전을 공유하면 n+m개다. 완전 복사 방식은 n+Σ(i=1..m)(n+i)=n+mn+m(m+1)/2개다. 최신 버전만 보관하는 경우나 다른 연산의 비용은 이 모든 버전 보관 조건과 구별한다.

초기 길이3에서 3번 prepend한 모든 버전을 보관한다. 공유와 완전 복사의 고유 cons 수를 계산하라.

  1. 공유는 초기3에 각 작업1개를 더해 3+3=6이다.

  2. 별도 완전 복사는 길이3,4,5,6의 네 버전 노드를 서로 공유하지 않는다.

  3. 합은 3+4+5+6=18이며 공유 대비 12개 더 많다.

세 분기에서 같은 역전을 반복한다

옛 Q에서 독립적으로 pop을 세 번 실행하고 Q와 세 결과를 모두 보관한다. 각 역전은 cons 네 개를 만들고 첫 노드는 결과에 남지 않는다.

  1. 각 호출은 같은 in 네 항목을 다시 읽으므로 역전 읽기 합은 12다.

  2. 호출마다 역전한 새 네 cons 중 세 개만 결과에서 도달한다. 결과끼리 새 cons를 공유하지 않는다.

  3. Q의 원래 네 cons와 세 결과의 아홉 cons는 총 13개다. 생성된 총 cons는 원래 4개와 새 12개로 16개다.

역전 읽기 12회, 전체 생성 cons 16개, 최종 도달 cons 13개다. 사라진 역전 첫 노드 세 개의 즉시 GC 실행은 주장하지 않는다.

중복 BST 삽입의 탐색과 할당

회전 없는 BST는 루트 4, 왼쪽 2, 오른쪽 6이다. 기본 insert와 자식 참조가 그대로면 부모도 반환하는 최적화 insert에서 6과 4를 각각 별도 삽입한다.

  1. 6 삽입은 4와 6을 검사한다. 기본 구현은 기존 6을 반환한 뒤 새 루트 4를 만든다. 최적화는 기존 루트도 반환한다.

  2. 4 삽입은 첫 비교에서 기존 전체 트리를 반환해 두 구현 모두 새 노드를 만들지 않는다.

  3. 참조 보존 최적화는 중복 6에서 한 할당을 없애도 두 비교는 그대로 한다.

6 삽입은 검사 2회, 기본 새 노드 1개/최적화 0개다. 4 삽입은 검사 1회이며 두 구현 새 노드 0개다.

다른 문제에 적용하기

분기 이력과 현재 관찰을 함께 검산하기

새 불변 정수 리스트 L은 A(1) → B(2) → C(3) → D(4)다. L에서 M=replace(L,3,9), N=replace(L,2,8)을 서로 독립적으로 만들고 외부 E는 C를 가리킨다. 먼저 L과 N의 루트를 버리되 M/E를 보관하고, 나중에 E도 버린다. 각 단계의 고유 도달 cons를 계산하라. 별도 가변 셀 r의 내용은 5이며 한 cons를 가진 V=[r]와 새 정수 스냅샷 W=[5]를 만든 뒤 r에 8을 쓴다. 두 현재 관찰을 적어라. 마지막으로 별도 Q=([],[4,3,2,1])에서 pop을 네 번 독립 호출한 방식과 pop 결과 P를 한 번 저장해 네 번 재사용한 방식의 역전 항목 읽기 수를 비교하라. cons/셀/역전 읽기 단위와 실제 실행 미수행을 구별하라.

힌트 1

각 루트의 도달 노드를 식별자로 합집합하고 공유 노드는 한 번만 센다.

힌트 2

셀의 현재 내용 관찰과 정수 스냅샷, 같은 입력의 재계산과 결과 재사용을 각각 분리한다.

풀이와 답 확인

  1. L/M/N 모두 유지 때 고유 cons는 9개다. L/N을 버려도 E가 C를 유지하므로 M의 네 노드와 C를 합쳐 5개다. E도 버리면 M의 네 노드만 남는다.

  2. r 쓰기 뒤 V의 내용 관찰은 [8]이고 W는 불변 정수 [5]다. 이 사례는 앞 정수 리스트와 별도 노드/셀 집합이다.

  3. 네 독립 pop은 매번 네 항목을 역전해 전체 읽기 16회다. P를 한 번 계산하고 재사용하면 역전 읽기는 4회다. 재사용 자체는 새 역전이 아니다.

  4. 도달 노드가 줄어도 실제 GC 시각이나 파일 지속성을 측정한 것은 아니다. 입력 노드 공유만으로 동일 호출 결과의 자동 캐시도 가정하지 않는다.

첫 리스트의 고유 도달 cons는 9개에서 5개로, 이어 4개로 줄어든다. 별도 V는 [8], W는 [5]다. 역전 항목 읽기는 독립 네 호출에서 16회, 저장한 P의 네 재사용에서 4회다. 새 자료구조 실행·할당·회수·학생 시험은 미수행이다.
