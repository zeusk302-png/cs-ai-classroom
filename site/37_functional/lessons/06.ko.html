소단원 6.1

parametric polymorphism

숫자도 글자도 그대로 돌려주는 함수는 어떤 타입일까?

준비 개념과 학습 목표

준비 개념

  • 타입은 값과 연산의 허용 범위를 표현한다.

  • OCaml 의 함수 타입 A -> B 는 A 를 받아 B 를 돌려준다.

  • 타입변수는 실행 중 바뀌는 값 변수가 아니다.

학습 목표

  • 타입변수의 일관된 치환을 적용한다.

  • 매개변수 다형성과 임의 타입 혼합을 구분한다.

  • 순수 함수의 일반성 및 적용 한계를 설명한다.

타입을 매개변수로 남겨 두기

자체 OCaml 함수 let identity x = x 는 입력을 그대로 돌려준다. x 의 타입을 α라고 두면 반환도 α여서 α -> α다. int 나 string 을 요구하는 연산이 없으므로 하나로 고정할 이유가 없다. 일반화된 let 함수는 사용 지점마다 타입변수를 적절히 구체화할 수 있다.

identity 8 은 int 로, identity "별"은 string 으로 구체화한다. 하나의 호출 안에서는 입력 α와 반환 α가 같은 타입이어야 한다. 아무 값이나 받았으니 반환도 아무 타입이 된다는 뜻은 아니다. 타입변수 이름을 β로 바꾸어 β -> β라 써도 의미는 같다.

값에 특별한 연산을 요구하지 않기

매개변수 다형성은 타입을 특정하지 않은 채 같은 구조의 함수를 재사용하는 방식이다. identity 는 수를 더하거나 문자열 길이를 읽지 않으므로 그런 기능을 해당 입력에서 요구하지 않는다. 반면 let increment x = x + 1 은 OCaml 의 정수 + 때문에 int -> int 로 제한된다.

이 절은 순수하고 종료하는 단순 함수의 예를 사용한다. 모든 다형 함수가 항상 종료하거나 부작용이 없다는 보장을 타입변수만으로 얻는 것은 아니다. 예외·일반 재귀·가변 상태를 허용하는 언어의 전체 행동과 좁은 예제의 직관을 구분한다.

같은 타입변수와 다른 타입변수

자체 let keepFirst x y = x 는 α -> β -> α다. 두 입력 타입은 서로 달라도 되며 반환만 첫 입력 타입과 같다. 함수 타입의 화살표는 오른쪽으로 묶이므로 α -> (β -> α)다. 이것은 두 입력을 한 튜플로 받는 α*β -> α와 호출 모양이 다르다.

α list 는 같은 타입의 원소를 담는 목록이다. 이 예제에서 [identity 8; identity "별"]은 각 호출은 가능해도 하나의 목록 원소 타입 int 와 string 이 충돌한다. let 다형성과 목록 안의 임의 타입 혼합을 같은 것으로 외우지 않는다.

let identity x = x
let keepFirst x y = x
(* 종이로 추론할 타입: identity : α -> α
   keepFirst : α -> β -> α *)

중간 과정을 따라가는 예제

identity 8, identity "별", keepFirst 8 true 의 결과 타입과 값을 추론하라. OCaml 의 int/string/bool 을 사용한다.

  1. 첫 호출은 α=int 로 치환하므로 입력 8 과 반환 8 이 모두 int 다.

  2. 둘째 호출은 별도 사용 지점에서 α=string 으로 치환하므로 반환 "별"은 string 이다.

  3. keepFirst 는 α=int,β=bool 로 치환해 int -> bool -> int 가 되며 두 번째 입력을 받더라도 결과는 8 이다.

결과는 8:int, "별":string, 8:int 다. 실제 실행 출력이 아니라 자체 함수의 정적 추론과 종이 계산이다.

종이와 본문으로 직접 해보기

keepFirst "달" 3 과 increment "달"을 비교하라. increment 는 x+1 이다.

힌트 보기

서로 다른 변수 α·β는 다른 타입을 허용하지만 +는 정수를 요구한다.

풀이 보기

keepFirst 는 α=string,β=int 로 성립하고 "달":string 을 돌려준다. increment 는 int 입력이 필요해 string 이 충돌하므로 정적 타입 오류다.

오해와 반례

α -> α라면 입력 int 에서 반환 string 으로 마음대로 바꿀 수 있다.

같은 α는 같은 치환을 따라야 한다. identity 8 에서는 α=int 이므로 반환도 int 다. 일반성은 사용 지점의 여러 치환을 허용하는 것이며 호출 내부의 계약을 없애지 않는다.

자기점검

identity 는 int 전용인가?

답과 이유 보기

이 순수 let 예제에서는 아니다.

특정 입력 연산 없이 α -> α로 일반화된다.

α와 β는 꼭 같은 타입인가?

답과 이유 보기

그렇게 요구하지 않는다.

서로 다른 변수이며 추가 제약이 있어야 같아진다.

다형 함수 호출 두 개를 한 혼합 목록에 넣어도 되는가?

답과 이유 보기

int/string 목록은 이 예제에서 오류다.

각 호출 타입과 목록 원소 타입의 일관성은 별도 검사다.

한 단계 더

소단원 6.2

제네릭 함수

서로 다른 두 변환을 연결할 때 중간 타입을 어떻게 맞출까?

준비 개념과 학습 목표

준비 개념

  • 함수 적용에서 인자의 타입은 함수 입력 타입과 같아야 한다.

  • (f x)의 결과는 f 의 반환 타입이다.

  • 괄호는 함수 타입의 묶임을 명확히 한다.

학습 목표

  • 고차 함수에 타입 제약을 세운다.

  • 합성 함수의 세 타입을 일관되게 맞춘다.

  • 제네릭 함수 재사용과 정적 오류의 경계를 설명한다.

함수를 입력으로 받기

자체 let compose after before x = after (before x)를 보자. x 가 α이면 before 는 α -> β로 β를 만든다. after 는 그 β를 받아 γ를 반환하므로 β -> γ다. 전체 타입은 (β -> γ) -> (α -> β) -> α -> γ다.

제네릭 함수는 타입을 구체화해 여러 입력·결과 조합에 쓸 수 있지만 연결되는 중간 β가 맞아야 한다. 타입변수를 아무렇게나 지우는 기능이 아니다. 이 예제는 OCaml 에서 일반화된 순수 let 함수를 사용하며 가변 참조의 일반화 제한은 별도 조건이다.

제약을 안쪽부터 모으기

함수 적용 before x 에서 입력 α를 정하고 결과에 새 β를 둔다. 그 결과가 after 의 입력으로 쓰이므로 after 입력도 β다. 마지막 결과 γ가 전체 함수 반환이 된다. 각 변수를 실제 값과 구분해 적으면 추론 순서를 따라갈 수 있다.

타입이 맞는다는 사실은 함수의 의미가 우리가 기대하는 것이라는 보장이 아니다. before 가 정수를 두 배로 만들고 after 가 세 배로 만들면 타입은 둘 다 int -> int 로 맞아도 의도한 이름이나 단위가 다를 수 있다. 타입 계약과 값 계산을 함께 확인한다.

사용 지점에서 구체화하기

자체 twice n=n*2 와 label n=if n>5 then "큼" else "작음"을 연결한다. before=twice 는 int -> int, after=label 은 int -> string 이므로 α=int,β=int,γ=string 이다. compose label twice 3 의 타입은 string 이다.

연결 순서를 바꿔 compose twice label 3 으로 쓰면 label 의 string 결과를 twice 의 int 입력으로 넘기게 된다. 중간 타입이 충돌하며 함수 이름이나 “제네릭”이라는 표지가 충돌을 해결하지 않는다. 실제 타입 오류 메시지를 실행해서 수집한 것은 아니므로 아래는 계약 기반 분석이다.

let compose after before x = after (before x)
let twice n = n * 2
let label n = if n > 5 then "큼" else "작음"

중간 과정을 따라가는 예제

compose label twice 3 의 중간값·최종값·타입을 구하라. 두 함수는 위 정의를 따른다.

  1. x=3:int 이므로 before 인 twice 가 3*2=6:int 을 돌려준다.

  2. after 인 label 은 6>5 를 참으로 판단해 "큼":string 을 돌려준다.

  3. α=int,β=int,γ=string 이며 전체 적용 결과는 string 이다.

중간 6:int, 최종 "큼":string 이다. 계산과 타입 일치가 각각 확인됐다.

종이와 본문으로 직접 해보기

compose label twice 2 와 compose twice label 2 를 비교하라.

힌트 보기

첫째는 2→4→라벨이다. 둘째는라벨 결과 타입을 두 배 함수 입력과 대조한다.

풀이 보기

첫째는 4≤5 라 "작음":string 이다. 둘째는 label 2 의 string 을 twice 의 int 로 넣으므로 정적 타입 충돌이다. 그 결과를 임의 숫자로 가정해 계속 계산하지 않는다.

오해와 반례

compose 가 제네릭이면 어떤 함수 두 개도 합성할 수 있다.

string 을 반환하는 label 뒤에 int 를 요구하는 twice 는 β를 동시에 string 과 int 로 만들어 충돌한다. 중간 결과·입력 타입이 호환되어야 한다.

자기점검

compose 의 중간 타입은 왜 하나의 β인가?

답과 이유 보기

before 의 결과가 after 의 입력이기 때문이다.

같은 전달값에 같은 타입을 요구한다.

타입 일치가 업무 의미까지 보장하는가?

답과 이유 보기

보장하지 않는다.

단위·목적·계산 내용은 추가 검토한다.

label 을 after 로 쓰면 최종 타입은?

답과 이유 보기

string 이다.

after 의 반환 타입 γ가 전체 반환이다.

한 단계 더

compose 의 합성 규칙을 화살표 그림 α→β→γ로 표현하고, cm 와 m 처럼 같은 int 로 표현된 서로 다른 단위의 오류를 생각해 보자. 별도 단위 타입이 왜 도움 되는지 적는다.

소단원 6.3

타입오류 해석

타입 오류의 위치가 보이면 그 줄만 아무 타입으로 바꾸면 될까?

준비 개념과 학습 목표

준비 개념

  • 타입 추론은 표현식에서 제약을 모아 함께 해결한다.

  • 서로 다른 int 와 string 을 같게 만드는 치환은 없다.

  • 정적 검사와 실행 중 오류는 구별한다.

학습 목표

  • 불일치 제약의 원인을 추적한다.

  • 분기·함수 적용·자기 적용의 오류를 구분한다.

  • 원래 의도에 맞는 수정 대안을 비교한다.

제약이 충돌한 이유를 읽기

자체 let select flag = if flag then 7 else "일곱"에서 flag 는 bool 이고 두 분기는 같은 결과 타입이어야 한다. 첫 분기 int 와 둘째 string 을 같게 하는 치환이 없어 오류다. flag=true 인 호출만 하려고 해도 함수의 다른 분기를 검사하지 않는다는 뜻이 아니다.

오류가 보고된 위치는 충돌이 관측된 곳일 수 있으며 진짜 실수는 더 앞의 입력이나 반환 정의에 있을 수 있다. 무엇이 필요한 타입이고 무엇을 제공했는지, 그 타입을 요구한 연산은 무엇인지 세 질문으로 읽는다. 정확한 컴파일러 메시지 문구는 실행해 수집하지 않았다.

의도에 따라 수정하기

표시할 문자열이 목적이면 두 분기를 "일곱"·"없음" 같은 string 으로 맞출 수 있다. 숫자 계산이 목적이면 7·0 같은 int 를 선택할 수 있다. 서로 다른 종류를 정말 구분해야 하면 명시적인 합타입으로 감싸는 설계도 있다. 단순 캐스팅으로 의미를 잃지 않는다.

함수 적용에서 입력 타입이 충돌하면 호출자가 잘못된 값을 보냈는지 함수 정의가 잘못된 타입을 요구하는지 확인한다. x+1 이 숫자 덧셈을 의도했는지 문자열 붙이기를 의도했는지도 요구사항에 따라 판단한다. 타입 오류를 없애는 여러 코드가 모두 정답은 아니다.

무한 타입을 요구하는 경우

자체 fun x -> x x 에서 x 의 타입을 α라고 하면 첫 x 는 함수여야 하므로 α=α -> β라는 제약이 생긴다. 보통의 유한 HM 타입에서 α의 정의 안에 다시 α가 들어가므로 발생 검사에 걸린다. OCaml 의 기본 유한 타입 모형으로 이 자기 적용을 허용한다고 가정하지 않는다.

이 오류는 실행한 함수가 느리다는 의미가 아니다. 실행 전에 타입을 구성할 수 없다는 뜻이다. 고급 재귀 타입 확장이나 별도 언어의 정책은 이 절의 기본 조건 밖이다. 정적 제약을 읽는 훈련과 실제 런타임 추적을 분리한다.

let select flag = if flag then 7 else "일곱"
(* 분기 제약: int = string — 충돌 *)
(* fun x -> x x의 제약: α = α -> β — 발생 검사 실패 *)

중간 과정을 따라가는 예제

select 의 flag·첫 분기·둘째 분기 타입과 모순 제약을 적고, 숫자형 대안 let choose flag = if flag then 7 else 0 의 타입을 추론하라.

  1. if 조건에서 flag=bool 이다.

  2. 원본은 첫 분기 int, 둘째 string 이므로 결과 타입에 int=string 을 요구해 실패한다.

  3. 수정 choose 는 두 분기가 int 로 같아 bool -> int 다. choose false 는 0 이다.

원본 충돌은 int/string, 숫자형 대안은 bool -> int 이며 false 에 0 이다.

필요 int·제공 string 으로 충돌한다. 숫자 계산이 목적인지 표시 문자열이 목적인지 확인해야 하며 무조건 변환해 오류만 없애면 요구 의미를 바꿀 수 있다.
