소단원 6.1

parametric polymorphism

숫자도 글자도 그대로 돌려주는 함수는 어떤 타입일까?

준비 개념과 학습 목표

준비 개념

  • 타입은 값과 연산의 허용 범위를 표현한다.

  • OCaml 의 함수 타입 A -> B 는 A 를 받아 B 를 돌려준다.

  • 타입변수는 실행 중 바뀌는 값 변수가 아니다.

학습 목표

  • 타입변수의 일관된 치환을 적용한다.

  • 매개변수 다형성과 임의 타입 혼합을 구분한다.

  • 순수 함수의 일반성 및 적용 한계를 설명한다.

항등 함수를 두 번 쓰는 것과 함수 매개변수를 두 타입으로 부르는 것은 같은가?

앞 본문의 identity를 id라고 줄여 let id x=x로 정의한다. 순수 함수의 let 일반화를 사용하는 기본 유한 HM 모형에서 id의 타입은 α→α다. 서로 다른 사용 지점에는 새로운 타입변수를 배정하므로 (id 4, id true)의 첫 호출은 α₁=int, 둘째 호출은 α₂=bool로 치환한다. 튜플의 타입은 int*bool이고 값은 (4,true)다. 두 변수의 아래 첨자는 서로 독립된 치환임을 표시할 뿐 실행 중 타입을 바꾸는 코드가 아니다.

이와 달리 fun f -> (f 4, f true)는 함수 매개변수 f 하나의 타입을 두 사용에서 함께 만족시켜야 한다. 첫 적용은 f의 입력이 int라는 제약, 둘째는 bool이라는 제약을 만든다. 하나의 입력 타입을 int와 bool로 동시에 치환할 수 없어 이 기본 모형에서는 정적 오류다. 일반화된 let id를 이 함수의 인수로 전달하겠다는 계획도 함수 본문의 모순을 자동으로 없애지 않는다. 명시적 고차 다형성 확장은 여기서 다루지 않는다.

let same x y=(x,y)는 α→β→α*β로 두 입력 타입을 독립적으로 남긴다. 반면 let pairSame x=(x,x)는 α→α*α로 반환 두 칸이 같은 타입이라는 정보를 유지한다. 같은 타입이라고 같은 값이어야 하는 것은 아니며 같은 값을 반환한다고 새 독립 객체 두 개를 만든다는 뜻도 아니다. 아래 모든 과제는 독립된 원래 정의에서 시작하며 새 OCaml 실행 대신 타입 방정식과 값의 종이 추적을 사용한다.

먼저 확인할 개념
  • 사용 지점의 타입 치환

    identity의 호출마다 치환하는 규칙과 호출 내부의 일관성을 확장한다.

  • 함수 적용 제약의 충돌

    필요 입력과 제공 타입이 같아야 한다는 규칙을 공유 f에 적용한다.

타입을 매개변수로 남겨 두기

자체 OCaml 함수 let identity x = x 는 입력을 그대로 돌려준다. x 의 타입을 α라고 두면 반환도 α여서 α -> α다. int 나 string 을 요구하는 연산이 없으므로 하나로 고정할 이유가 없다. 일반화된 let 함수는 사용 지점마다 타입변수를 적절히 구체화할 수 있다.

identity 8 은 int 로, identity "별"은 string 으로 구체화한다. 하나의 호출 안에서는 입력 α와 반환 α가 같은 타입이어야 한다. 아무 값이나 받았으니 반환도 아무 타입이 된다는 뜻은 아니다. 타입변수 이름을 β로 바꾸어 β -> β라 써도 의미는 같다.

값에 특별한 연산을 요구하지 않기

매개변수 다형성은 타입을 특정하지 않은 채 같은 구조의 함수를 재사용하는 방식이다. identity 는 수를 더하거나 문자열 길이를 읽지 않으므로 그런 기능을 해당 입력에서 요구하지 않는다. 반면 let increment x = x + 1 은 OCaml 의 정수 + 때문에 int -> int 로 제한된다.

이 절은 순수하고 종료하는 단순 함수의 예를 사용한다. 모든 다형 함수가 항상 종료하거나 부작용이 없다는 보장을 타입변수만으로 얻는 것은 아니다. 예외·일반 재귀·가변 상태를 허용하는 언어의 전체 행동과 좁은 예제의 직관을 구분한다.

같은 타입변수와 다른 타입변수

자체 let keepFirst x y = x 는 α -> β -> α다. 두 입력 타입은 서로 달라도 되며 반환만 첫 입력 타입과 같다. 함수 타입의 화살표는 오른쪽으로 묶이므로 α -> (β -> α)다. 이것은 두 입력을 한 튜플로 받는 α*β -> α와 호출 모양이 다르다.

α list 는 같은 타입의 원소를 담는 목록이다. 이 예제에서 [identity 8; identity "별"]은 각 호출은 가능해도 하나의 목록 원소 타입 int 와 string 이 충돌한다. let 다형성과 목록 안의 임의 타입 혼합을 같은 것으로 외우지 않는다.

let keepFirst x y = x

첫 행은 일반화된 id를 사용 지점마다 새로 구체화한다. 둘째 행은 같은 f의 입력 타입 A를 두 번 제약한다. 행 사이의 A와 α를 섞어 같은 변수처럼 풀지 않는다.

중간 과정을 따라가는 예제

identity 8, identity "별", keepFirst 8 true 의 결과 타입과 값을 추론하라. OCaml 의 int/string/bool 을 사용한다.

  1. 첫 호출은 α=int 로 치환하므로 입력 8 과 반환 8 이 모두 int 다.

  2. 둘째 호출은 별도 사용 지점에서 α=string 으로 치환하므로 반환 "별"은 string 이다.

  3. keepFirst 는 α=int,β=bool 로 치환해 int -> bool -> int 가 되며 두 번째 입력을 받더라도 결과는 8 이다.

결과는 8:int, "별":string, 8:int 다. 실제 실행 출력이 아니라 자체 함수의 정적 추론과 종이 계산이다.

조건을 바꾸어 비교하기

튜플은 다른 타입을 담지만 목록은 하나로 맞춘다

let id x=x에서 (id 4,id true)와 [id 4;id true]를 비교하라.

  1. 튜플의 두 칸은 독립 타입을 가지므로 첫 칸 int, 둘째 bool로 성립한다.

  2. 목록은 모든 원소가 같은 타입이어야 한다. 각 id 호출의 독립 치환 뒤에도 원소 타입 int=bool을 요구한다.

  3. 따라서 튜플은 (4,true)지만 목록은 정적 오류이며 실행 결과를 계산하지 않는다.

let 다형성은 목록의 동질성 제약을 지우지 않는다.

비교할 점

다른 타입을 넣을 자료 표현은 튜플이나 명시적인 합타입으로 설계해야 한다.

동일한 타입의 입력 둘은 같은 값 둘이 아니다

let same x y=(x,y)와 let pairSame x=(x,x)를 사용해 same 4 9, same 4 true, pairSame 4를 비교하라.

  1. same 4 9는 α=int,β=int로 (4,9):int*int다. 두 타입변수가 우연히 같은 타입으로 치환되어도 값은 다르다.

  2. same 4 true는 α=int,β=bool로 (4,true):int*bool다.

  3. pairSame 4는 같은 α=int를 두 반환 칸에 적용하여 (4,4):int*int다.

타입변수의 같음은 값의 같음이나 객체의 독립 소유를 보장하지 않는다.

비교할 점

pairSame에 같은 참조를 넘기면 반환 두 칸은 그 참조를 공유할 수 있다. 여기서는 메모리 실행을 하지 않는다.

종이와 본문으로 직접 해보기

keepFirst "달" 3 과 increment "달"을 비교하라. increment 는 x+1 이다.

힌트 보기

서로 다른 변수 α·β는 다른 타입을 허용하지만 +는 정수를 요구한다.

풀이 보기

keepFirst 는 α=string,β=int 로 성립하고 "달":string 을 돌려준다. increment 는 int 입력이 필요해 string 이 충돌하므로 정적 타입 오류다.

오해와 반례

α -> α라면 입력 int 에서 반환 string 으로 마음대로 바꿀 수 있다.

같은 α는 같은 치환을 따라야 한다. identity 8 에서는 α=int 이므로 반환도 int 다. 일반성은 사용 지점의 여러 치환을 허용하는 것이며 호출 내부의 계약을 없애지 않는다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

let id x=x에서 let a=id 4 in let b=id "빛" in (a,b)를 추론하라. 같은 두 결과를 [a;b]로 바꾸면 어떠한가?

힌트 1

id의 사용마다 새 타입변수를 둔다.

힌트 2

튜플과 목록의 원소 규칙을 따로 적는다.

풀이와 답 확인

  1. a는 int이고 값은 4다. b는 string이고 값은 "빛"이다.

  2. 튜플은 (4,"빛"):int*string으로 성립한다.

  3. 목록은 int와 string의 동일성을 요구해 실패한다.

튜플만 허용되며 목록은 정적 타입 오류다.

흔한 오답에서 다시 생각하기

id가 다형이므로 목록도 다형이다.

함수의 여러 구체화와 하나의 목록의 동질성은 별도 제약이다.

연습 2 · 오류 찾아 고치기

fun f -> (f 4,f true)에 일반화된 id를 전달하면 실행에서 (4,true)가 나오므로 본문이 타입 검사된다고 주장했다. 기본 HM 모형에서 수정하라.

힌트 1

f의 타입을 A→B라고 한 번만 적는다.

힌트 2

첫 입력 4와 둘째 입력 true가 같은 A에 만드는 방정식을 비교한다.

풀이와 답 확인

  1. 첫 적용은 A=int를 만든다. 둘째 적용은 A=bool을 만든다.

  2. int=bool은 풀 수 없으므로 원래 함수가 정적 검사에서 거절된다.

  3. 두 독립 사용이 목적이면 let id x=x in (id 4,id true)로 사용 구조를 바꿀 수 있다.

입력 전달 계획으로 정적 모순이 사라지지 않는다.

흔한 오답에서 다시 생각하기

런타임 id가 무엇이든 받으니 타입 검사를 생략하면 된다.

이 모형은 런타임 호출 전에 본문 전체의 한 f 타입을 검사한다.

연습 3 · 직접 만들어 보기

정수와 문자열을 독립 변환해 튜플을 만드는 함수 let both f g x y=(f x,g y)의 가장 일반적인 타입을 만들고 f n=n+1, g s=s^"!", x=4, y="빛"을 적용하라.

힌트 1

x의 타입 A와 y의 타입 C를 별도로 둔다.

힌트 2

f의 반환 B와 g의 반환 D도 독립적으로 둔다.

풀이와 답 확인

  1. f:A→B, g:C→D, x:A, y:C이므로 both:(A→B)→(C→D)→A→C→B*D다.

  2. 구체 적용은 A=B=int, C=D=string이다.

  3. 두 값은 5와 "빛!"이어서 결과는 (5,"빛!"):int*string이다.

독립 변환 인수 두 개를 받는 계약은 한 f를 다른 입력 타입으로 공유하는 것과 다르다.

흔한 오답에서 다시 생각하기

함수가 둘이므로 모든 A/B/C/D가 꼭 달라야 한다.

다른 타입변수는 서로 다른 타입을 허용할 뿐 같은 치환도 허용한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

pairSame의 타입 α→α*α만 보고 반환 두 칸의 객체가 독립이라고 결론 낼 수 있는가? r이 int ref 하나이고 pairSame r=(r,r)인 사례를 종이로 설명하라.

힌트 1

α를 int ref로 일관되게 치환한다.

힌트 2

새 ref를 만드는 연산이 함수 본문에 있는지 확인한다.

풀이와 답 확인

  1. 반환 타입은 int ref*int ref다. 두 칸은 인수로 받은 같은 r을 돌려준다.

  2. 한 칸을 통해 r의 내용을 바꾸면 다른 칸도 같은 셀의 내용을 읽을 수 있다.

  3. 타입의 구조적 일반성은 복제나 소유권의 독립성을 보장하지 않는다.

여기서는 참조 공유의 계약만 손추적했으며 실제 대입/할당은 하지 않았다.

흔한 오답에서 다시 생각하기

α 두 번이면 객체도 두 번 만들어진다.

같은 타입변수의 반복은 타입 일치 정보다. 객체를 새로 만드는 코드가 아니다.

내 말로 설명하기

let 사용마다 새 치환과 매개변수의 공유 제약은 어떻게 다른가?

설명 기준 확인

일반화된 let은 사용별 구체화를 허용하지만 한 함수 매개변수의 기본 타입은 그 본문 안에서 일관되어야 한다.

다형성을 얻으면 데이터의 혼합과 복제도 자유로운가?

설명 기준 확인

아니다. 목록 원소 일치와 객체 공유/소유는 별도 계약이다.

소단원 6.2

제네릭 함수

서로 다른 두 변환을 연결할 때 중간 타입을 어떻게 맞출까?

준비 개념과 학습 목표

준비 개념

  • 함수 적용에서 인자의 타입은 함수 입력 타입과 같아야 한다.

  • (f x)의 결과는 f 의 반환 타입이다.

  • 괄호는 함수 타입의 묶임을 명확히 한다.

학습 목표

  • 고차 함수에 타입 제약을 세운다.

  • 합성 함수의 세 타입을 일관되게 맞춘다.

  • 제네릭 함수 재사용과 정적 오류의 경계를 설명한다.

입력과 반환이 다른 함수를 합성할 수 있으면 같은 함수를 반복할 수도 있을까?

앞 본문의 compose after before x=after(before x)는 A→B→C의 연결을 허용한다. 새 let twiceApply f x=f(f x)는 같은 f를 두 단계에 쓴다. x의 타입을 A, 첫 f의 반환을 B라고 두면 첫 단계는 f:A→B다. 두 번째 단계에서 같은 f의 입력 A가 첫 반환 B를 받아야 하므로 A=B다. 따라서 twiceApply의 타입은 (A→A)→A→A다.

새 describe n=if n>=3 then "높음" else "낮음"은 int→string이다. 별도 encodeLabel s=if s="높음" then 6 else 2는 string→int다. compose encodeLabel describe는 int→int로 성립하며 입력 4는 "높음"을 거쳐 6, 입력 1은 "낮음"을 거쳐 2를 만든다. 두 함수의 입력/반환 연결이 맞는 것과 코드 6/2가 실제 센서 규격에 맞는 것은 별도 검토다. 아래의 코드 값은 자체 표시 모형이며 실제 센서·라이브러리 실행을 하지 않는다.

별도 mapShape f lst의 계약은 목록 각 원소에 f를 한 번 적용하여 같은 순서로 결과 목록을 만든다는 것이다. 타입은 (A→B)→A list→B list이고 입력과 결과 원소 타입이 달라도 된다. 아래 f는 순수한 함수로 제한해 효과 평가 순서를 가정하지 않는다. 빈 목록은 f 적용이 0회이지만 함수의 정적 타입 요구는 없어지지 않는다.

먼저 확인할 개념
  • 합성의 중간 타입

    before 반환과 after 입력의 한 B를 같은 f 반복의 추가 제약과 비교한다.

  • 타입변수의 일관된 치환

    여러 타입변수가 같은 타입으로 합쳐지는 것과 독립 치환을 구별한다.

함수를 입력으로 받기

자체 let compose after before x = after (before x)를 보자. x 가 α이면 before 는 α -> β로 β를 만든다. after 는 그 β를 받아 γ를 반환하므로 β -> γ다. 전체 타입은 (β -> γ) -> (α -> β) -> α -> γ다.

제네릭 함수는 타입을 구체화해 여러 입력·결과 조합에 쓸 수 있지만 연결되는 중간 β가 맞아야 한다. 타입변수를 아무렇게나 지우는 기능이 아니다. 이 예제는 OCaml 에서 일반화된 순수 let 함수를 사용하며 가변 참조의 일반화 제한은 별도 조건이다.

제약을 안쪽부터 모으기

함수 적용 before x 에서 입력 α를 정하고 결과에 새 β를 둔다. 그 결과가 after 의 입력으로 쓰이므로 after 입력도 β다. 마지막 결과 γ가 전체 함수 반환이 된다. 각 변수를 실제 값과 구분해 적으면 추론 순서를 따라갈 수 있다.

타입이 맞는다는 사실은 함수의 의미가 우리가 기대하는 것이라는 보장이 아니다. before 가 정수를 두 배로 만들고 after 가 세 배로 만들면 타입은 둘 다 int -> int 로 맞아도 의도한 이름이나 단위가 다를 수 있다. 타입 계약과 값 계산을 함께 확인한다.

사용 지점에서 구체화하기

자체 twice n=n*2 와 label n=if n>5 then "큼" else "작음"을 연결한다. before=twice 는 int -> int, after=label 은 int -> string 이므로 α=int,β=int,γ=string 이다. compose label twice 3 의 타입은 string 이다.

연결 순서를 바꿔 compose twice label 3 으로 쓰면 label 의 string 결과를 twice 의 int 입력으로 넘기게 된다. 중간 타입이 충돌하며 함수 이름이나 “제네릭”이라는 표지가 충돌을 해결하지 않는다. 실제 타입 오류 메시지를 실행해서 수집한 것은 아니므로 아래는 계약 기반 분석이다.

let compose after before x = after (before x)
let twice n = n * 2
let label n = if n > 5 then "큼" else "작음"

중간 과정을 따라가는 예제

compose label twice 3 의 중간값·최종값·타입을 구하라. 두 함수는 위 정의를 따른다.

  1. x=3:int 이므로 before 인 twice 가 3*2=6:int 을 돌려준다.

  2. after 인 label 은 6>5 를 참으로 판단해 "큼":string 을 돌려준다.

  3. α=int,β=int,γ=string 이며 전체 적용 결과는 string 이다.

중간 6:int, 최종 "큼":string 이다. 계산과 타입 일치가 각각 확인됐다.

조건을 바꾸어 비교하기

합성은 성립해도 한 함수의 반복은 충돌한다

describe:int→string, encodeLabel:string→int를 위 계약대로 쓰자. compose encodeLabel describe 4와 twiceApply describe 4를 비교하라.

  1. 합성은 4→"높음"→6이고 타입 int→string→int가 이어진다.

  2. 반복은 첫 describe의 string을 같은 describe의 int 입력으로 넘기려고 한다.

  3. 반복 적용은 int=string 충돌로 정적 거절되므로 둘째 값을 계산하지 않는다.

합성 결과는 6:int이고 describe 반복은 타입 오류다.

비교할 점

서로 다른 두 함수를 잇는 것과 같은 한 함수를 되풀이하는 것은 제약이 다르다.

목록의 형태는 유지하면서 원소 타입은 바꾼다

mapShape describe [1;4;2]와 mapShape describe []의 결과·타입·f 적용 수를 구하라.

  1. 세 입력은 int이고 describe는 각각 "낮음","높음","낮음"을 만든다.

  2. 첫 결과는 string list이며 적용 수는 3회다. 입력/결과 목록 길이는 모두 3이다.

  3. 빈 입력에서는 []:string list이고 적용 수는 0회다. describe의 int→string 타입은 그대로 검사한다.

두 결과는 ["낮음";"높음";"낮음"]과 []이며 적용 수는 3회와 0회다.

  • 원래 의도에 맞는 수정 대안을 비교한다.

거절된 식을 어떤 방식으로 고쳐야 원래 정보가 남을까?

앞 본문의 if flag then 7 else "일곱"은 분기 결과 타입 충돌이다. 새 사례 if flag then 4 else false도 flag:bool, 결과 int=bool이라는 모순을 만든다. 항상 flag=true로 호출하겠다는 계획은 두 분기의 정적 검사를 없애지 않는다. 표시 목적이면 두 분기를 string으로, 종류 정보를 보존할 목적이면 type reading=Count of int | Switch of bool 같은 명시 합타입으로 설계할 수 있다.

합타입 대안 let choose flag=if flag then Count 4 else Switch false는 bool→reading이다. Count의 자료는 int, Switch의 자료는 bool이지만 두 생성자의 전체 결과 타입은 reading으로 같다. choose false는 Switch false이지 Count 0이 아니다. 그 뒤 사용하는 함수는 생성자를 구분해야 하며 문자열 "false"로 바꾼 설계와 같은 정보/인터페이스라고 주장하지 않는다.

별도 fun x -> x x는 x:A, 적용을 위한 x:A→B가 동시에 필요해 A=A→B를 만든다. 유한 타입의 발생 검사는 이를 거절한다. 반면 fun x -> (x,x)는 A→A*A로 성립한다. 타입변수가 결과에 두 번 나온다는 이유만으로 발생 검사 실패가 되는 것은 아니다. 제약의 오른쪽에 자기 A를 포함한 타입을 A 자체로 대입하려는지가 기준이다.

  • 함수 입력과 반환의 연결

제약이 충돌한 이유를 읽기

자체 let select flag = if flag then 7 else "일곱"에서 flag 는 bool 이고 두 분기는 같은 결과 타입이어야 한다. 첫 분기 int 와 둘째 string 을 같게 하는 치환이 없어 오류다. flag=true 인 호출만 하려고 해도 함수의 다른 분기를 검사하지 않는다는 뜻이 아니다.

오류가 보고된 위치는 충돌이 관측된 곳일 수 있으며 진짜 실수는 더 앞의 입력이나 반환 정의에 있을 수 있다. 무엇이 필요한 타입이고 무엇을 제공했는지, 그 타입을 요구한 연산은 무엇인지 세 질문으로 읽는다. 정확한 컴파일러 메시지 문구는 실행해 수집하지 않았다.

의도에 따라 수정하기

표시할 문자열이 목적이면 두 분기를 "일곱"·"없음" 같은 string 으로 맞출 수 있다. 숫자 계산이 목적이면 7·0 같은 int 를 선택할 수 있다. 서로 다른 종류를 정말 구분해야 하면 명시적인 합타입으로 감싸는 설계도 있다. 단순 캐스팅으로 의미를 잃지 않는다.

함수 적용에서 입력 타입이 충돌하면 호출자가 잘못된 값을 보냈는지 함수 정의가 잘못된 타입을 요구하는지 확인한다. x+1 이 숫자 덧셈을 의도했는지 문자열 붙이기를 의도했는지도 요구사항에 따라 판단한다. 타입 오류를 없애는 여러 코드가 모두 정답은 아니다.

무한 타입을 요구하는 경우

자체 fun x -> x x 에서 x 의 타입을 α라고 하면 첫 x 는 함수여야 하므로 α=α -> β라는 제약이 생긴다. 보통의 유한 HM 타입에서 α의 정의 안에 다시 α가 들어가므로 발생 검사에 걸린다. OCaml 의 기본 유한 타입 모형으로 이 자기 적용을 허용한다고 가정하지 않는다.

이 오류는 실행한 함수가 느리다는 의미가 아니다. 실행 전에 타입을 구성할 수 없다는 뜻이다. 고급 재귀 타입 확장이나 별도 언어의 정책은 이 절의 기본 조건 밖이다. 정적 제약을 읽는 훈련과 실제 런타임 추적을 분리한다.

중간 과정을 따라가는 예제

select 의 flag·첫 분기·둘째 분기 타입과 모순 제약을 적고, 숫자형 대안 let choose flag = if flag then 7 else 0 의 타입을 추론하라.

  1. if 조건에서 flag=bool 이다.

  2. 원본은 첫 분기 int, 둘째 string 이므로 결과 타입에 int=string 을 요구해 실패한다.

  3. 수정 choose 는 두 분기가 int 로 같아 bool -> int 다. choose false 는 0 이다.

원본 충돌은 int/string, 숫자형 대안은 bool -> int 이며 false 에 0 이다.

조건을 바꾸어 비교하기

합타입은 값 변환이 아니라 종류 정보를 싼다

type reading=Count of int | Switch of bool과 choose를 위 정의대로 둔다. choose true/false의 타입과 값을 구하고, Count n에는 n+1을 반환하고 Switch b에는 if b then 1 else 0을 반환하는 summarize의 타입과 결과를 적어라.

  1. 두 choose 결과는 모두 reading이며 값은 Count 4와 Switch false다.

  2. summarize는 각 생성자의 자료를 올바른 타입으로 사용하고 두 가지에서 int를 반환한다.

  3. summarize의 타입은 reading→int다. 두 결과에 적용하면 5와 0이다.

종류를 보존한 뒤 분기별 처리로 공통 int 결과를 만든다.

비교할 점

처음부터 false를 숫자 0으로 바꾸면 어느 자료 종류에서 왔는지 없어질 수 있다.

반복 출현과 순환 대입을 구별한다

fun x->(x,x)와 fun x->x x에 대해 타입변수 A를 쓰고 방정식을 비교하라.

  1. 첫 식의 결과 타입은 A*A이고 전체 함수 타입은 A→A*A다. A를 자기 포함 타입으로 대입하라는 제약이 없다.

  2. 둘째 식에서 x의 인수 타입 A와 함수 입력 A가 같아 x 자체 타입 A=A→B가 필요하다.

  3. 오른쪽 안에 A가 있어서 기본 유한 타입으로 해결할 수 없다.

튜플 복제는 타입 검사 가능하지만 자기 적용은 발생 검사 실패다.

다른 문제에 적용하기

센서의 지정 두 자료를 다루는 종이 설계다. type reading=Count of int | Switch of bool, choose true=Count 4, choose false=Switch false, summarize(Count n)=n+1, summarize(Switch b)=if b then 1 else 0을 쓴다. 순수 mapShape와 compose는 이 단원 계약을 따른다. (1) let id x=x의 (id 4,id false)와 fun f->(f 4,f false)의 검사 차이를 설명하라. (2) mapShape choose [true;false;true]와 mapShape summarize를 그 결과에 적용한 값·타입·각 단계 적용 수를 적어라. compose (mapShape summarize) (mapShape choose)의 타입도 추론하라. (3) 오류만 없애려고 choose false를 Count 0으로 바꾸면 전체 최종 목록이 어떻게 달라지는가? (4) 전체 최종 목록이 맞아도 실제 센서 수집·함수 실행·학습자 검증을 했다는 뜻인지 답하라.

힌트 1

각 let 사용의 독립 치환과 한 f의 공유 입력 제약을 나누고, choose의 반환 reading이 summarize의 입력인지 연결한다.

힌트 2

자료 생성자 이름과 최종 int 값을 단계별로 보존한다. 변형은 원래 상태를 이어받지 않는 독립 대안이다.

풀이와 답 확인

  1. id 두 사용의 튜플은 (4,false):int*bool이지만 한 f의 입력은 int=bool 충돌을 요구하여 거절된다.

  2. 첫 mapShape는 [Count 4;Switch false;Count 4]:reading list를 만들고 choose 적용 수는 3회다. 둘째는 [5;0;5]:int list를 만들고 summarize 적용 수는 3회다.

  3. mapShape choose는 bool list→reading list이고 mapShape summarize는 reading list→int list다. 두 함수의 compose는 bool list→int list로 중간 목록 타입이 일치한다.

  4. 독립 변형에서는 false 자료가 Count 0으로 바뀌고 최종 목록은 [5;1;5]다. 두 설계는 같은 전체 타입이지만 가운데 후속 관찰 값이 달라 의미 보존이 아니다.

  5. 위 결과는 지정된 타입 규칙·순수 함수 계약의 손추적이다. 실제 센서/OCaml/mapShape/학습자 실행 증거가 없다.

독립 id 사용만 혼합 튜플로 성립하고 공유 f는 거절된다. 정상 두 단계 결과는 reading list의 [Count 4;Switch false;Count 4]와 int list의 [5;0;5]이며 적용 수는 각 3회다. 합성 타입은 bool list→int list다. 오류 제거 변형은 같은 타입에서 [5;1;5]를 만들어 가운데 관찰을 바꾼다.

  • 사용 지점의 일반화와 한 매개변수의 int/bool 모순을 따로 적는다.

  • 두 목록의 원소 타입·생성자 자료·각 적용 수를 이름별로 추적한다.

  • 중간 reading list가 맞는 합성 타입을 유도하고 변형의 가운데 0→1을 확인한다.
