속성과 예제테스트

정렬 결과 한 개가 맞으면 모든 정렬이 맞다고 할 수 있을까?

학습 목표

두 번 적용해도 같다는 속성이 잘못된 정렬을 놓칠 수 있을까요?

책을 한 번 정리한 뒤 다시 정리해도 바뀌지 않는다는 조건은 정리가 안정됐다는 뜻이다. 책을 버리고 빈 선반으로 만드는 절차도 이 조건을 만족한다. 정렬 함수 F의 멱등성 F(F(xs))=F(xs)는 유용한 보조 속성이지만 비내림차순과 값별 중복 횟수 보존을 대신하지 않는다. 여기서는 유한 정수 리스트와 종료하는 순수 후보를 손으로 추적한다.

자체 후보 U는 입력의 서로 다른 값만 남겨 오름차순으로 정렬한다. [2,1,2]에서 [1,2]를 반환하며 U를 다시 적용해도 [1,2]다. 이 후보는 순서와 멱등성을 통과하지만 2를 한 번 버린다. 결과의 속성과 검사하는 속성의 충분함은 서로 다른 질문이다.

작은 영역을 모두 확인했다고 해도 그 영역의 경계를 기록해야 한다. 이번 영역 D는 값 0 또는 1만 쓰고 길이는 0부터 2까지다. 반례를 찾으면 중요한 조건을 유지한 작은 입력으로 줄여 설명할 수 있지만, 실제 자동 생성·축소 도구를 실행한 것은 아니다.

먼저 확인할 개념
  • 순서와 원소 횟수의 동시 검사

    앞 본문의 빈 결과와 0 채움 반례를 멱등성의 빈틈과 연결한다.

  • 순서와 값의 서로 다른 관측

    같은 값 모음과 위치 보존이 별도 조건임을 기록 정렬의 안정성에 적용한다.

한 사례와 모든 허용 입력의 규칙

예제 테스트는 입력 [3,1,3]의 기대 결과 [1,3,3]처럼 구체적인 값을 비교한다. 속성은 허용한 모든 정수 리스트 xs에서 지켜야 할 관계를 적는다. 같은 입력에 같은 출력을 내는 순수 함수는 외부 시각이나 파일 상태를 준비하지 않고 이 관계를 추적하기 쉽다.

속성 기반 테스트 도구는 설정한 입력 영역에서 여러 예제를 생성해 속성을 검사한다. 그 영역을 무한히 모두 실행하는 것은 아니므로 통과를 수학적 증명으로 부르지 않는다. 우리가 아래에서 손으로 보는 세 사례도 세 사례의 근거다.

정렬에는 두 가지 약속이 있다

출력은 비내림차순이어야 하고 입력의 원소와 중복 횟수를 보존해야 한다. 비내림차순은 인접한 모든 쌍에서 앞 값≤뒤 값이라는 뜻이다. 중복 횟수 보존은 값마다 입력과 출력에 등장한 횟수가 같다는 뜻이며 길이 보존도 따라온다.

항상 빈 리스트를 반환하면 비내림차순 조건은 만족하지만 [3,1,3]의 원소를 잃는다. 길이만 보존하는 [0,0,0]도 원소를 잃는다. 원소 보존과 순서를 함께 검사하거나 신뢰할 수 있는 기준 구현과 비교해야 요구를 충분히 표현할 수 있다.

영역과 경계를 먼저 적는다

여기서는 유한 길이의 정수 리스트와 일반적인 정수 비교만 다룬다. 빈 리스트·한 원소·중복·음수를 포함해 보고 예상 답을 독립적으로 계산한다. 부동소수 NaN처럼 일반 비교가 기대와 다르게 동작하는 값은 현재 영역 밖이며 별도 정책이 필요하다.

생성 검사는 사람이 생각하지 못한 사례를 찾는 데 도움을 줄 수 있고 중요한 회귀 사례는 명시한 예제로 남길 수 있다. 두 방식은 함께 사용할 수 있다. 도구를 설치하거나 실행하지 않은 상태에서 자동 검사 통과라고 기록하지 않는다.

같은 출력에 여러 질문을 던진다. 통과한 두 속성을 더 많이 반복해도 누락된 횟수 조건이 생기지 않는다. 실패한 입력과 실제 출력, 위반한 관계를 함께 남긴다.

중간 과정을 따라가는 예제

정렬 후보 F가 []→[], [3,1,3]→[1,3,3], [-1,0,-1]→[-1,0]을 반환한다. 순서와 각 값의 횟수 보존을 손으로 검사하라.

  1. 빈 결과는 비교할 인접 쌍이 없고 원소 횟수도 모두 0이므로 두 조건을 만족한다.

  2. 두 번째는 1≤3≤3이며 입력과 출력 모두 1은 한 번, 3은 두 번이다.

  3. 세 번째는 -1≤0이지만 -1의 횟수가 2에서 1로 줄었고 길이도 3에서 2로 줄었다.

앞 두 사례 통과, 마지막은 원소 보존 실패다. 후보 F가 모든 입력에서 올바르다는 결론은 내리지 않는다.

조건을 바꾸어 비교하기

정렬과 멱등성을 함께 통과하는 중복 삭제

후보 U의 [2,1,2] 결과와 [2,2] 결과를 순서·멱등성·횟수로 검사하라. U는 서로 다른 값만 정렬한다.

  1. 첫 결과는 [1,2]다. 순서가 맞고 두 번째 적용도 같은 결과지만 입력의 2 두 개가 출력 한 개가 됐다.

  2. 둘째 결과는 [2]다. 순서와 멱등성은 맞으나 길이는 2에서 1로, 2의 횟수도 2에서 1로 줄었다.

  3. 중복 하나를 제거하면 [2]에서는 U와 정상 정렬을 구별하지 못하므로 [2,2]가 현재 결함을 보여 주는 더 작은 사례다.

두 입력 모두 횟수 보존에 실패한다. 순서·멱등성의 통과는 정상 정렬의 증명이 아니다.

비교할 점

길이만 검사하는 앞 사례에 새로운 보조 속성을 추가해도 충분 조건은 별도로 필요하다.

영역 전체 통과와 영역 밖 첫 실패

D의 모든 입력은 정상 정렬하고 길이가 3 이상이면 마지막 원소를 버린 뒤 정렬하는 후보 K다. D의 입력 개수와 [1,0,1]의 실패를 계산하라.

  1. 길이 0의 입력은 1개, 길이 1은 2개, 길이 2는 4개라 D는 총 7개다. 이 영역에서는 K가 정상 정렬로 정의되어 있다.

  2. [1,0,1]에서는 마지막 1을 버리고 [1,0]을 정렬해 [0,1]을 만든다.

  3. 출력의 순서는 맞지만 1의 횟수가 2에서 1로 줄었다. 이 입력은 길이 3이라 D 밖이다.

D의 7개를 모두 통과하는 정의와 길이 3의 반례가 함께 성립한다. 실제 7개 자동 실행을 했다는 주장은 아니다.

연습 1 · 값과 상태 예측

U를 [0,0,1]에 적용한다. 순서·길이·0의 횟수·멱등성 결과를 적어라.

힌트 1

서로 다른 값만 남기면 [0,1]이다.

힌트 2

멱등성은 출력에 다시 적용하는 관계다.

풀이와 답 확인

  1. 출력 [0,1]은 비내림차순이다. 입력 길이는 3, 출력 길이는 2다.

  2. 0의 횟수는 입력 2회, 출력 1회로 다르다. U([0,1])도 [0,1]이므로 멱등성은 통과한다.

연습 2 · 오류 찾아 고치기

정렬 후보와 기준 함수가 모두 U다. 두 출력의 일치만 검사해 [2,2]를 정상으로 보고했다. 독립적인 오류 발견 조건을 추가하라.

힌트 1

풀이와 답 확인

  2. 원본 입력의 값별 횟수와 출력 횟수를 독립 비교한다. 입력의 2 두 개와 출력 한 개가 다르다.

  3. 기준 구현의 독립성·검증 상태도 별도로 기록한다.

횟수 보존 검사에서 실패를 보고하며 기준과 일치했다는 관찰을 정확성으로 확대하지 않는다.

연습 3 · 직접 만들어 보기

유한 정수 리스트의 오름차순 정렬 계약을 충분히 검사할 순수 조건 두 개와 중복 결함 회귀 사례를 설계하라. 비교·횟수 계산 자체는 정확하다고 가정한다.

힌트 1

인접 쌍과 값별 개수를 따로 확인한다.

힌트 2

[2,2]의 기대 결과는 두 원소를 모두 가진다.

풀이와 답 확인

  1. 모든 인접 쌍에서 앞 값 ≤ 뒤 값을 검사한다.

  2. 입력과 출력에서 각 정수의 등장 횟수가 같은지 검사한다. 이 조건에는 새 값 삽입과 길이 변화도 포함된다.

  3. [2,2]→[2,2]를 명시한 회귀 사례로 남긴다. 순서와 횟수가 모두 맞으면 이 정수 값 정렬 계약은 만족한다.

순서 조건과 다중집합 보존을 함께 쓰고 중복 사례를 보존한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

기록 [(A,2),(B,1),(C,2)]를 값만 비교해 안정 정렬한다. 후보가 [(B,1),(C,2),(A,2)]를 반환했다. 값의 순서와 기록 다중집합 보존만으로 계약을 만족하는가?

힌트 1

동일 값 2의 원래 ID 순서를 적는다.

힌트 2

안정성은 같은 비교값의 상대 순서를 보존한다.

풀이와 답 확인

  1. 값의 순서는 1,2,2이고 모든 기록도 한 번씩 남았다.

  2. 원래 값 2의 순서는 A 다음 C지만 출력은 C 다음 A라 안정성이 실패했다.

  3. 안정 정렬 요구의 기대 결과는 [(B,1),(A,2),(C,2)]다.

값 정렬 계약은 맞아도 안정 기록 정렬 계약은 실패한다.

하한이 3단위인데 분할할 수 없는 작업은 왜 4단위가 필요할까요?

세 사람이 각자 2분짜리 발표를 하고 발표 자리는 두 개뿐이라고 생각하자. 총량 6분을 두 자리로 나누면 3분이지만 발표 하나를 반으로 나누거나 두 자리를 동시에 써서 빨리 끝낼 수 없다면 한 자리는 발표 두 개를 맡아 4분 걸린다. work·span 하한과 작업 배치의 제약을 연결하는 자체 시간 모형이다.

A·B·C는 서로 독립이고 각각 비용 2다. 작업자는 동일 성능 둘이며 작업은 중단·이동·분할 없이 한 작업자를 점유한다. 시작은 시각 0, 생성·통신·전환 비용은 0이다. W=6, S=2로 하한 max(W/2,S)=3이지만 완료시간 3이 달성된다는 뜻은 아니다.

이 절의 비용 단위는 장비 ms가 아니라 가상 시간 단위다. 작업 정점의 합과 의존 경로, 실제로 제시한 모형 시간표를 따로 계산한다. 코어 수를 늘리는 조건과 정점 자체를 쪼개는 조건은 DAG가 같지 않다는 점도 구별한다.

해야 할 양과 기다려야 할 길

작업 선후 관계를 순환 없는 방향 그래프 DAG로 나타내자. 이 교육 모형에서는 각 정점이 한 작업이며 비용은 양의 시간 단위다. work W는 모든 작업 비용의 합이고 span S는 시작에서 끝까지 선행 관계를 따르는 가장 긴 경로의 비용 합이다.

독립 작업은 함께 할 수 있지만 선행 작업의 결과를 기다리는 작업은 먼저 시작하지 못한다. 한 작업자에게 필요한 이상적인 총 시간은 W, 무한한 작업자가 있어도 의존성을 지키려면 S보다 짧아질 수 없다. 실제 장비 시간은 측정이 필요하다.

둘 중 큰 하한을 본다

동일 성능 작업자 P개가 있으면 총 작업을 나눠도 T(P)≥W/P이며 임계 경로 때문에 T(P)≥S다. 따라서 T(P)≥max(W/P,S)다. 단위 작업을 정수 슬롯으로 배치하는 모형에서는 W/P의 올림도 고려할 수 있다.

이는 반드시 달성하는 시간 공식이 아니다. 작업 배치, 이용하지 못하는 슬롯, 통신과 스케줄링 비용 때문에 더 걸릴 수 있다. W/S는 이상적인 최대 속도 향상의 상한을 설명하는 병렬성이다. 필요한 작업을 늘려 span만 줄이면 work 측면에서 손해가 날 수도 있다.

병렬 sequence와 결정성

작업이 끝나는 순서가 달라도 결과 리스트 순서는 같을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 순수 함수

  • 결합법칙과 인덱스

학습 목표

  • 결과 위치와 완료 시각을 구별한다

  • reduce의 결합법칙과 항등원을 확인한다

  • 공유 효과와 중복 갱신의 비결정성을 찾는다

최댓값뿐 아니라 그 값의 개수도 병렬로 합칠 수 있을까요?

점수표를 두 묶음으로 나누어 각 묶음의 최고 점수와 그 점수의 학생 수를 적으면 전체 최고와 인원을 계산할 수 있다. 자체 순수 요약은 빈 목록에 Empty, 비어 있지 않은 목록에 Pair(m,c)를 쓴다. m은 수학적 정수 최댓값, c는 그 값의 양의 등장 횟수다. 실수·NaN·유한 폭 overflow는 이번 영역 밖이다.

combine은 Empty와 다른 요약을 합치면 다른 요약을 반환한다. 두 Pair의 m이 다르면 더 큰 m의 Pair를, 같으면 Pair(m,c1+c2)를 반환한다. 목록을 이어 붙인 결과의 요약과 같은 의미여서 유효한 요약 영역에서 결합법칙을 만족한다. Empty는 항등원이다. 점수 0을 빈 목록 표지로 쓰면 음수 점수와 실제 0의 의미를 잃는다.

sequence의 위치별 결과와 완료 로그 순서는 별도로 관찰한다. ID를 가진 기록의 filter는 입력에서 조건을 만족하는 기록의 상대 순서를 유지한다. 값 요약이 같아도 로그 순서나 중복 갱신 선택은 다른 계약이다. 인터페이스 의미를 사용한 종이 추적이며 실제 라이브러리나 worker를 실행하지 않는다.

먼저 확인할 개념
  • map·reduce·inject의 계약

    위치 보존·결합법칙·항등원 및 중복 inject의 비결정성을 새 요약에 적용한다.

  • 원소 횟수와 관찰의 범위

    최댓값 하나가 같아도 중복 횟수나 기록 순서까지 보존된 것은 아님을 검사한다.

논리적 위치를 보존한다

sequence는 순서가 있는 원소 모음이다. CMU 인터페이스의 map은 각 위치의 원소에 함수를 적용해 그 위치의 결과를 만드는 의미를 갖는다. 순수한 제곱 함수로 [1,2,3,4]를 변환하면 결과는 [1,4,9,16]이다.

4번 작업이 먼저 끝나도 그 값을 위치4의 결과로 저장하면 앞자리로 이동하지 않는다. 반대로 작업 종료 때 공유 로그에 추가하는 외부 효과는 시각과 스케줄에 의존할 수 있다. 결과 sequence의 인덱스 의미와 로그 순서는 서로 다른 관측이다.

묶는 순서가 달라도 같은가

병렬 reduce는 중간 결과를 묶는 구조가 순차 왼쪽 누적과 다를 수 있다. 두 결과를 같은 것으로 다루려면 연산이 결합법칙을 만족하고 초기값이 항등원이어야 한다. 정수 합과0은 이 조건을 만족하지만 뺄셈은 아니다.

교육 합은 오버플로 없는 수학적 정수다. 유한 폭 정수의 예외나 부동소수 반올림에서는 실제 연산 계약을 다시 확인한다. 순수 함수라고 해도 뺄셈이 결합적으로 바뀌는 것은 아니다. 빈 reduce의 결과는 초기값이고 한 원소 결과는 그 원소라는 현재 인터페이스의 규칙도 확인한다.

결정성을 깨는 조건을 분리한다

공유 누적 변수에 서로 다른 작업이 읽기·계산·쓰기를 하면 갱신이 덮여 결과가 바뀔 수 있다. 각 작업의 값으로 계산한 뒤 적절한 reduce로 모으면 이런 공유 쓰기를 줄일 수 있다. 라이브러리의 허용 입력과 연산 조건을 지켜야 한다.

CMU inject는 같은 인덱스의 중복 갱신에서 어느 하나가 반영될지 비결정적일 수 있다고 명시한다. 영속 자료 구조라는 사실만으로 모든 연산의 계약이 결정적인 것은 아니다. 충돌 인덱스를 없애거나 명시한 합치기 규칙을 먼저 적용한다.

음수 최고값과 두 묶음의 횟수

[-2,-5,-2]를 [-2]와 [-5,-2]로 나눈다. 각 요약과 전체 요약을 계산하고, 초기 Pair(0,0)를 추가한 잘못된 계산과 비교하라.

  1. 첫 묶음은 Pair(−2,1), 둘째도 최고 −2가 한 번이므로 Pair(−2,1)이다.

  2. 두 최고값이 같아 합친 결과는 Pair(−2,2)다. 직접 전체 목록에서도 −2가 두 번 등장한다.

  3. 잘못된 Pair(0,0)를 합치면 0이 −2보다 크다고 선택되어 Pair(0,0)가 남는다. 이 Pair는 원래 유효 요약 영역의 양의 횟수 조건도 위반한다.

정상 최고값은 −2, 그 횟수는 2다. Empty를 숫자 0으로 대체하면 잘못된 최고값을 만든다.

비교할 점

정수 합의 0과 다른 요약 연산의 항등원은 자동으로 같지 않다.

필터 결과의 순서와 완료 로그

입력 기록 [(A,2),(B,−1),(C,2)]에 값 ≥ 0인 filter를 적용한다. 작업 완료 순서는 C→A→B다. 입력 위치를 지키는 결과와 완료 때 추가한 공유 로그를 비교하라.

  1. 조건을 만족하는 기록은 A와 C이며 입력 상대 순서는 A 다음 C다. 정상 filter 결과는 [(A,2),(C,2)]다.

  2. 조건 참인 작업이 완료될 때 기록을 추가하면 이번 로그는 [(C,2),(A,2)]다.

  3. 두 기록의 값은 모두 2라 값만 보면 [2,2]지만 ID 순서는 다르다. 두 경우의 최고 요약은 Pair(2,2)로 같을 수 있다.

정상 sequence와 완료 로그는 ID 순서가 다르며 같은 최고 요약은 순서 보존의 증거가 아니다.

수업 점수 집계의 결과·속성·시간표를 함께 검증하기

새 입력 기록은 [(A,2),(B,0),(C,2)]다. 세 위치별 점수 변환 작업은 각각 2단위이고 서로 독립이며 원래 점수와 ID를 그대로 반환한다. 마지막 집계 작업 D는 세 결과가 모두 끝난 뒤 1단위 수행하고 입력 순서 sequence 및 최고값·횟수 요약을 만든다. 동일한 작업자 둘, 분할·중단 없는 작업, 생성·통신 비용 0인 자체 모형이다. 모형 완료 순서는 C→A→B일 수 있으며 이 순서는 다른 관찰 사례로 사용한다. 정상 결과 sequence와 최고 요약, 값 기준 안정 오름차순 정렬 결과를 계산하라. 잘못된 보고기는 같은 점수의 기록 중 입력에서 처음 등장한 기록만 남긴 뒤 값 기준 안정 정렬한다. 그래서 현재 입력에서는 C를 버리고 [(B,0),(A,2)]를 반환한다. 순서·멱등성·기록 횟수 보존 중 무엇이 이 결함을 찾는지 적어라. 별도로 원래 세 작업과 D의 그래프에서 W, S, 정수 시간 하한과 적합 최적 시간표를 계산하라. 실제 작업자나 테스트 도구 실행은 요구하지 않는다.

힌트 1

최고 점수 2의 기록은 ID가 다른 A와 C 두 개다. 완료 로그 순서가 입력 위치를 바꾸지는 않는다.

힌트 2

두 작업자 중 하나는 비용 2인 앞 작업 두 개를 맡고 D는 그 뒤에만 시작할 수 있다.

풀이와 답 확인

  1. 정상 위치 결과는 [(A,2),(B,0),(C,2)]이고 최고 요약은 Pair(2,2)다. 완료 순서 C→A→B의 로그는 입력 위치 순서와 다른 관찰이다.

  2. 정상 안정 정렬은 [(B,0),(A,2),(C,2)]다. 잘못된 보고기의 결과 [(B,0),(A,2)]는 값 순서가 맞고 다시 보고기에 넣어도 같은 결과라 멱등성도 맞다. 그러나 기록 C의 횟수는 입력 1회에서 출력 0회로 줄고 길이도 3에서 2로 줄어 보존 조건에 실패한다.

  3. 총량 W는 2+2+2+1=7단위이며 span S는 한 앞 작업과 D의 경로 2+1=3단위다. 기본 정수 시간 하한은 ceil(max(7/2,3))=4단위다.

  4. 작업자 1에 A [0,2), C [2,4), D [4,5)를 배치하고 작업자 2에 B [0,2)를 배치하면 시각 5에 완료한다. 두 작업자 중 하나는 앞 작업 두 개를 맡으므로 앞 작업 전체의 완료시각은 최소 4다. 그 뒤 D의 비용 1이 추가되므로 최적 완료시간은 5단위다.

  5. 결과 정확성·기록 순서·최고 요약·검사 범위·가상 배치시간을 별도로 기록한다. 보고기 테스트 통과를 실제 도구 실행이나 장비 성능으로 확대하지 않는다.

정상 sequence는 A/B/C 입력 순서이고 최고값은 2, 그 횟수는 2다. 안정 정렬은 B/A/C다. C를 버리는 후보는 기록 횟수/길이 조건에서 실패하며 최고 요약도 Pair(2,1)로 잘못된다. 원래 그래프의 W는 7, S는 3, 기본 정수 하한은 4, 최적 모형 완료시간은 5단위다.

해결한 뒤 점검할 것

  • ID 상대 순서와 값 요약을 별도로 계산한다.

  • 중복 C의 손실을 기록 횟수와 길이로 발견하고 약한 순서·멱등성 통과를 구별한다.

  • W/S 하한과 분할 불가 작업 배치의 추가 하한 및 적합 시간표를 모두 제시한다.

  • 모든 계산의 정의역·실제 도구/병렬/성능/학생 미수행 범위를 유지한다.
