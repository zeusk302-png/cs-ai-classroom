소단원 1.1

참조투명성

두 번 부르면 둘 다16을 돌려주는 함수는 언제나16으로 바꾸어도 될까?

준비 개념과 학습 목표

준비 개념

  • 수학 함수 f:D→R은 정의역 D의 각 입력에 결과 하나를 대응시킨다. square(n)=n×n에서 정수4의 결과는16이다.

  • 프로그램의 식은 값을 계산하는 표기다. square(4)+1에서 square(4)는 더 큰 식 안의 부분식이다.

  • 외부 상태는 호출 뒤에도 다른 코드가 볼 수 있는 값이다. 전역 counter나 출력 기록을 바꾸는 일도 반환값 밖의 효과다.

학습 목표

  • 순수함수의 입력/결과·효과 조건을 설명한다.

  • 참조투명성을 문맥 속 식의 안전한 치환으로 이해한다.

  • 같은 반환값만으로 치환 가능한지 반례를 찾는다.

입력을 그대로 돌려주어도 몰래 한 번 기록했다면 치환해도 될까?

앞 본문의 제곱 함수에서는 값과 counter를 비교했다. 이제 두 반환이 같은 더 작은 식으로 효과 경계를 살펴본다. 자체 종이 함수 mark(v)는 외부 기록 끝에 v를 한 번 추가한 뒤 v를 반환한다. 정수 계산은 정확하고 기록 추가는 성공한다고 주어진 모형이다. 값·기록 순서·예외·종료를 관찰하고 시간·메모리 비용은 제외한다.

x가 5일 때 mark(x)+mark(x)는 값 10을 만들지만 기록은 [5,5]다. mark(x)를 한 번 평가해 재사용하면 같은 값 10에 기록 [5]가 된다. 두 호출을 x+x로 치환하면 기록은 비어 있다. 반환의 일치가 전체 관찰의 일치는 아니다. 각 비교는 새 빈 기록에서 독립적으로 시작한다.

설정도 입력 값의 일부인지 따진다. 가변 전역 rate를 읽는 charge(price)는 price×rate이며, 명시한 고정 정수 인수를 받는 chargeAt(price,rate)는 그 곱만 계산한다. 이 모형에서 둘 다 읽기 자체로 기록을 남기지 않지만 외부 설정 변경에 대한 의존성이 다르다. 명시 인수로 옮기는 것은 어느 시점의 rate를 보존할지 정해야 하는 계약 변경이다.

먼저 확인할 개념
  • 문맥 속 관찰과 치환

    앞 본문의 반환합과 counter 구별을 순서 있는 기록으로 확장한다.

  • 고정 값과 가변 별칭

    명시 입력도 가변 객체이면 스냅샷 조건이 필요하다는 경계를 연결한다.

함수의 값과 실행의 효과

첫 모델의 square:Z→Z는 모든 수학 정수n에 대해 n×n을 돌려주는 총함수다. 전역 상태를 읽거나 바꾸지 않고 입출력을 하지 않으며 정의역 안에서 종료한다고 가정한다. 같은 입력은 같은 값에 대응한다. 유한 메모리·실행시간·기계정수 오버플로는 이 수학 모형에서 제외한다. 실제 코드에서는 숫자 타입과 자원 조건을 다시 확인한다.

부작용은 호출자가 관찰할 수 있는 상태 변경이나 출력 등 반환값 외의 효과다. 반환16은 같아도 카운터가 늘면 호출을 없앴을 때 다른 프로그램이 볼 결과가 달라진다. 현재 시간·난수·변하는 전역 설정을 암묵적으로 읽는 경우도 입력만으로 결과를 정하기 어렵다. 이를 명시적 인수로 받아 계산하는 핵심과 외부효과 경계를 나눌 수 있다.

치환의 기준은 문맥의 관찰

참조투명성은 같은 뜻을 가진 식을 더 큰 프로그램 문맥 안에서 바꾸어도 정한 관찰 결과가 유지되는 성질이다. 이 단원은 값·외부 상태/출력·종료와 예외를 관찰하며 시간과 메모리 비용은 관찰에서 제외한다. 같은 타입의 순수하고 종료하는 식 square(4)를16으로 바꾸면 이 기준의 동작이 유지된다.

치환은 아무 문자열 복사가 아니다. 동일 타입 문맥과 고정된 자유변수 바인딩 환경에서 변수의 의미가 같아야 하고, 함수 본문에 인수를 넣을 때 내부의 같은 이름이 우연히 다른 변수를 잡지 않도록 범위를 지켜야 한다. 수학적인 동치도 실수 근사/예외/비종료가 있는 실행에 그대로 적용할 수 없다. 타입이 같다는 사실은 치환 동치나 종료의 증명이 아니다.

반환값은 같지만 카운터는 다르다

아래 Python 비교는 기본 int 입력4로 고정하고 counter를0에서 시작한다. square는 제곱을 반환하고 counted_square는 같은 제곱을 반환하지만 counter를 증가시킨다. 이 코드는 개념을 관찰하기 위한 예이며 함수형 언어의 필수 문법이 아니다.

함수형이라는 언어 분류가 모든 함수의 순수성을 자동 보장하지는 않는다. SML의 ref 갱신처럼 상태를 변경하는 기능도 있다. 안전한 치환은 효과를 제외한 순수 부분과 명시한 정의역/평가 조건에서 주장한다.

counter = 0
def square(n):
    return n*n
def counted_square(n):
    global counter
    counter += 1
    return n*n

조건을 바꾸어 비교하기

기록을 제외하는 계약도 범위를 적는다

위 O/M/L에서 반환만 관찰한다면 이 한 입력은 같은가? 모든 기록을 관찰하는 원래 계약과 비교하라.

  1. 세 반환합은 모두 10이다.

  2. 반환만 보는 제한된 문맥에서는 이 입력을 구별하지 못한다.

  3. 기록을 다시 읽는 문맥은 [5,5], [5], []를 구별한다.

반환 계약의 한 입력 일치와 전체 관찰 동치는 다르다.

비교할 점

관찰 계약을 좁힌 사실을 기존 계약의 보존으로 쓰지 않는다.

현재 설정과 고정 인수의 차이

price는 10이다. 첫 계산 전 rate는 2, 둘째 전 3으로 바뀐다. 두 charge 결과의 합과 처음 rate 2를 고정한 chargeAt 두 결과의 합을 구하라.

  1. charge는 20 뒤 30을 만들어 합 50이다.

  2. chargeAt(10,2)를 두 번 계산하면 20과 20으로 합 40이다.

  3. 외부 변경을 막거나 같은 스냅샷을 쓰는 전제를 추가해야 고정 치환의 값을 보존한다.

합은 50과 40으로 다르다.

비교할 점

전역 읽기 의존성과 명시 고정 값은 같은 입력 계약이 아니다.

종이와 본문으로 직접 해보기

square(-3)+square(-3)을 치환해 계산하라. counted_square(4)의 결과를 한 번만 계산해 재사용하면 합과 카운터가 어떻게 되는지도0초기 상태에서 적어라.

힌트 보기

반환값과 호출 횟수/효과를 별도 열로 적는다.

풀이 보기

순수식은9+9=18이다. counted_square를 한 번 계산해 결과16을 두 번 더하면 합32,counter1이며 원래counter2와 다르다. 효과가 있는 호출에 공통 부분식 제거를 무조건 적용하지 않는다.

오해와 반례

동일한 인수에서 반환값만 같으면 순수하다.

counted_square는 매번16을 반환해도 외부 상태를 바꾼다. 반환값 결정성과 무부작용은 각각 확인해야 하며 비종료/예외도 정한 관찰에 포함한다.

연습 1 · 값과 상태 예측

빈 기록에서 mark(2)+mark(7)을 평가한다. 별도 실행에서 두 항의 평가 순서를 바꾸되 덧셈의 값은 같은 두 반환을 사용한다. 값과 기록을 비교하라.

힌트 1

합과 순서 있는 기록을 따로 적는다.

힌트 2

먼저 호출한 인수가 기록의 앞 원소다.

풀이와 답 확인

  2. 오른쪽 먼저는 합 9와 기록 [7,2]다.

순수 계산으로 나누면 실제 읽기 실패도 없어진다.

외부 읽기·기록의 실패 처리는 경계에 여전히 남으며 실제 성공은 시험하지 않았다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

정의역은 0 이상의 정수다. f(0)은 Range 예외, f(n)은 n>0에서 n/n의 정확 값 1이다. f(n)을 항상 1로 치환하는 제안을 반박하고 제한된 치환 조건을 적어라.

힌트 1

정의역 안의 실패도 관찰이다.

힌트 2

n>0으로 좁히면 예외가 발생하는 입력이 제외된다.

풀이와 답 확인

  1. n=0에서 원래는 Range이고 치환은 값 1이므로 다르다.

  2. n>0의 정확 산술 모형과 부작용 없음/종료 조건에서 f(n)의 관찰은 값 1이다.

정의역 전체 치환은 실패하며 양수 제한에서만 정당화한다.

한 단계 더

소단원 1.2

값·식·평가순서

쓰지 않을 인수도 반드시 먼저 계산해야 한다면, 그 인수가 영원히 끝나지 않을 때 어떤 일이 생길까?

준비 개념과 학습 목표

준비 개념

  • 값은 정해진 모형에서 더 계산할 필요가 없는 결과다. 정수5는 값이고2+3은 평가해야5가 되는 식이다.

  • 괄호는 식의 묶음/구조를 정한다. (2+3)*4는 합5를 곱해20이며2+3*4=14와 다르다.

  • 평가는 식에서 결과로 나아가는 규칙이다. 한 번의 계산 단계와 전체 실행이 끝난다는 조건을 구별하자.

학습 목표

  • 함수 자체의 값과 함수 호출 식을 구별한다.

  • 좌우 순서와 인수 평가 전략을 구분한다.

  • 비종료/예외가 있으면 값만으로 순서를 비교할 수 없음을 보인다.

한 인수를 두 번 쓰는 본문은 인수 식도 두 번 계산할까?

종이 언어의 twice(x)=x+x와 인수 식 e=2+3을 사용한다. 값먼저는 인수를 한 번 값으로 만들고 두 x에 값 5를 넣는다. 이름먼저는 두 x 자리에 e를 넣어 각각 계산한다. 필요먼저는 처음 요구 때 e를 계산한 결과를 공유한다. 세 전략 모두 정수 덧셈이 정확하며 이 사례의 e는 순수하게 종료한다.

덧셈 연산 한 번을 한 작업으로 세는 자체 비용 모형에서 값먼저와 필요먼저는 e의 덧셈 한 번과 본문의 덧셈 한 번으로 총 2회다. 이름먼저는 e를 두 번과 본문 한 번으로 총 3회다. 이는 실제 언어의 벽시계나 메모리 비용이 아니다. Haskell의 비엄격 의미가 이 비용 표의 구현 횟수를 자동 보장한다는 뜻도 아니다.

안 쓰는 인수와 안 고른 분기는 구별한다. first(x,y)=x에서 y가 Range를 내는 bad이면 값먼저 호출은 실패한다. 인수를 필요할 때 평가하는 자체 규칙에서는 y를 쓰지 않아 x를 반환한다. 조건문은 선택한 분기만 평가하도록 별도로 정의한다. 아래 전략 표는 Python/Haskell 전체 의미론의 대체가 아니다.

먼저 확인할 개념
  • 인수 전략과 평가 순서

    앞 본문의 first/loop에서 결과뿐 아니라 필요한 계산과 비용을 나눈다.

  • 종료와 예외의 관찰

    값 치환에 실패 관찰을 포함하는 조건을 전략 비교에 적용한다.

값으로 줄여 가는 규칙

이 종이 언어는 수학 정수, +, 함수 square(n)=n*n, first(x,y)=x를 사용한다. 정수는 값이고 함수를 정의한 표현도 함수 값이 될 수 있다. 함수 본문은 적용되기 전까지 실행하지 않는다고 약속한다. 함수 값과 square(5)라는 적용 식을 구별한다.

값먼저(call-by-value) 전략은 함수와 인수 식을 값으로 평가한 다음 함수 본문에 그 값을 넣는다. 좌우 순서는 여러 부분식 중 어느 것을 먼저 계산하는지의 선택이고, 값먼저/비엄격 전략은 쓰지 않는 인수까지 먼저 계산해야 하는지의 선택이다. 서로 다른 질문을 같은 용어로 섞지 않는다.

종료하는 순수식의 치환과 비용

square(2+3)+square(4)를 왼쪽 먼저 값먼저 평가하면2+3→5, square5→25, square4→16, 마지막41이다. 모든 부분식이 순수하게 종료하고 정수 계산이 정확하다는 조건에서 독립된 두 square의 평가순서를 바꾸어도 값41이다. 시간/메모리 사용이 똑같다는 결론은 아니다.

변수를 치환할 때 이름의 범위를 지킨다. square의 형식 인수n에5를 넣으면 n*n→5*5다. 지역의 다른 n이나 자유변수가 우연히 잡히지 않도록 필요한 경우 이름을 바꾼다. 이 첫 예에는 이름 충돌이 없지만 치환을 단순 문자열 찾기/바꾸기로 구현할 수 있다는 뜻은 아니다.

사용하지 않는 계산과 종료 조건

loop를 어떤 값도 내지 않고 영원히 계산하는 순수 식으로 정의하자. 값먼저 전략의 first(7,loop)는 둘째 인수 평가에서 끝나지 않아 first 본문에 도달하지 못한다. 인수를 필요할 때만 평가하는 이 종이 비엄격 전략은 first가 y를 쓰지 않으므로7을 돌려준다. 효과가 없어도 종료 관찰이 달라진다.

조건문은 값먼저 언어에서도 특별한 선택 규칙을 가질 수 있다. 조건을 평가한 뒤 선택한 분기만 실행하는 언어에서는 if true then7 else loop가7이다. 함수 인수 전략과 모든 부분식/분기를 무조건 평가한다는 주장은 다르다. 실제 Python의 eager 인수 평가와 Haskell의 비엄격 언어 규칙은 각 문서의 조건으로 확인하되 본문 toy 규칙을 두 언어의 전체 의미론이라고 부르지 않는다.

중간 과정을 따라가는 예제

고정 정의역의 순수 정수 함수 square와 왼쪽 먼저 값먼저 규칙에서 square(2+3)+square(4)를 추적한다.

  1. 첫 인수의2+3을5로 평가.

  2. n에5를 넣어5*5=25.

  3. 둘째 호출은4*4=16.

  4. 25+16=41. 함수 정의 자체를 값으로 읽을 때는 본문 계산이 시작되지 않는다.

41이며 모든 사용한 인수/산술이 종료한다는 조건을 충족한다.

조건을 바꾸어 비교하기

사용 횟수가 0인 경계

zero(x)=0에 순수한 비종료 loop를 전달한다. 값먼저와 필요먼저의 종료를 비교하라.

  1. 값먼저는 함수 본문 전에 loop의 값을 요구하여 끝나지 않는다.

  2. 필요먼저는 x를 요구하지 않으므로 0을 반환한다.

부작용이 없는 인수도 종료 전략을 바꿀 수 있다.

비교할 점

twice의 종료하는 인수와 다르게 사용하지 않는 비종료 인수를 넣는다.

같은 실패에서 서로 다른 선행 사건

엄격 종이 덧셈의 두 항은 left: 기록 L을 남기고 Range, right: 기록 R을 남기고 값 4다. 왼쪽/오른쪽 먼저 평가를 비교하라.

  1. 왼쪽 먼저는 기록 [L] 뒤 Range여서 오른쪽을 시작하지 않는다.

  2. 오른쪽 먼저는 [R,L] 뒤 Range다.

예외 종류는 같으나 실패까지의 기록이 다르다.

인수 전략을 고정해도 부분식의 좌우 순서는 효과 관찰에 영향을 준다.

소단원 1.3

불변성의 의미

겉의 상자만 고정되어도 그 상자가 가리키는 안쪽 자료까지 변하지 않을까?

준비 개념과 학습 목표

준비 개념

  • 바인딩은 이름과 값/객체를 연결하는 것이다. 이름이 새 값을 가리키게 하는 일과 같은 객체의 내용을 바꾸는 일을 구별하자.

  • 별칭은 두 이름이 같은 객체를 가리키는 관계다. p와q가 같은 리스트를 가리키면 p로 바꾼 내용은q에서도 보인다.

  • 목록은 순서 있는 원소 묶음이다. [20,30]의 앞에10을 붙인 새 목록은[10,20,30]이다.

학습 목표

  • 바인딩/얕은/깊은 불변성을 구분한다.

  • 원본을 유지하는 갱신과 구조 공유를 추적한다.

  • 불변 자료와 프로그램 전체의 순수성을 분리한다.

목록의 중간을 고치면서 모든 옛 버전을 살리려면 어디를 새로 만들까?

자체 불변 Cons 목록 old=[10,20,30,40]의 노드를 A/B/C/D라고 부른다. 각 노드는 불변 정수 head와 불변 tail을 갖는다. 세 번째 값 30을 99로 바꾸는 새 버전 v1에서는 A/B/C에 대응하는 새 노드 A1/B1/C1을 만들고 C1의 tail로 옛 D를 공유한다. 기존 노드를 쓰지 않으므로 old는 그대로다.

이 모형의 위치는 1부터 세고 변경할 위치가 유효하다고 가정한다. 위치 k 갱신은 그 위치까지의 새 노드 k개를 만들며 뒤 노드를 공유한다. 위치를 검사하는 비용과 실제 메모리 할당/GC 실패는 이 그림의 노드 수와 별도다. 처음부터 새 값과 같은 head를 만난 경우에도 여기서는 경로를 새로 만드는 정책을 고정한다.

old와 v1을 모두 유지한 상태에서 v1의 두 번째 값을 88로 바꾸어 v2를 만든다. 새 A2/B2 두 노드의 뒤는 C1/D다. 서로 다른 버전의 참조를 보관하는 슬롯은 별도이고, 노드 하나를 두 번 도달한다고 물리 노드 수를 두 번 세지 않는다. 구조 공유의 안전 조건은 노드와 도달 원소의 불변성이다.

먼저 확인할 개념
  • 불변 목록의 앞붙이기와 공유

    앞 본문의 새 노드 하나를 중간 경로 복사와 여러 버전으로 확장한다.

  • 고정 입력과 관찰 가능한 변경

    공유 원소가 가변이면 입력 값 안정성이 깨지는 이유를 연결한다.

무엇을 바꾸지 못하는지 명시하기

불변 객체는 정해진 인터페이스에서 만들어진 뒤 내용이 바뀌지 않는 객체다. 이름을 재대입하지 못하는 바인딩의 제한과는 다르다. 고정 이름이 가변 리스트를 가리키면 리스트 내용은 여전히 바뀔 수 있다. 반대로 불변 정수2를 가리킨 이름을 정수3에 다시 연결해도 원래 정수2가3으로 변한 것은 아니다.

얕은 불변성은 바깥 구조/참조 슬롯을 바꾸지 않는 조건이다. 깊은 불변성은 의미를 이루는 도달 가능한 내부 자료까지 바뀌지 않는 더 강한 조건이다. 외부에 보이는 추상 값만 불변이며 내부 캐시가 바뀌는 구현도 있을 수 있으므로 어떤 인터페이스/관찰을 기준으로 불변이라 하는지 적어야 한다.

기존 값을 유지하면서 새 값 만들기

Cons(head,tail) 노드의 head와tail을 바꾸지 않고 tail도 불변이라고 가정하자. old=Cons(20,Cons(30,Nil))에10을 앞붙일 때 new=Cons(10,old)를 만든다. old는 여전히[20,30]이고 new는[10,20,30]이다. 새 앞 노드 하나가 old를 tail로 공유한다.

구조 공유는 모든 원소를 매번 복사해야 한다는 오해를 줄인다. 이 모형의 앞붙이기는 노드 하나 생성과 참조 연결로 된다. 그러나 임의 위치 갱신 비용이나 실제 allocator/GC의 시간까지 항상 상수라고 단정할 수는 없다. 공유되는 노드와 원소를 바꿀 수 없다는 조건이 원본 보존의 핵심이다.

겉만 고정된 구조와 외부효과

Python tuple은 참조 슬롯을 바꾸지 않는 불변 컨테이너이지만 내부에 list를 담으면 그 list는 변할 수 있다. 아래에서 outer는 동일 tuple을 유지해도 inner.append(2) 뒤 outer[0]의 내용은[1,2]다. 이는 tuple의 슬롯 대입 제한과 내부 객체의 가변성을 분리하는 반례다.

자료가 불변이라고 함수가 자동 순수한 것도 아니다. 불변 리스트를 받고 로그를 출력하는 함수에는 외부효과가 있다. 불변값을 보관한 공유 변수 자체를 동시에 교체하는 작업에는 경쟁이 남을 수 있다. 불변성은 추론·공유를 돕는 조건이지 전체 I/O·동시성·자원 문제를 한 번에 해결하는 보장은 아니다.

inner = [1]
outer = (inner,)
inner.append(2)
# outer[0]은 [1,2]: tuple 슬롯은 그대로
# outer[0] = [9]는 TypeError

중간 과정을 따라가는 예제

불변 Cons모형으로 old=[20,30]을 만들고 new=Cons(10,old)를 만든다. 원소는 불변 정수이고 모든 노드의 필드 변경을 허용하지 않는다.

  1. old의 앞20 노드는 다음30 노드를 가리킨다.

  2. 앞10인 새 노드 하나를 만들고 tail을old로 연결.

  3. old 순회는20→30→Nil, new 순회는10→20→30→Nil.

  4. 두 경로가20/30 노드를 공유해도 내용을 바꾸는 연산이 없으므로 원본 목록 유지.

old=[20,30],new=[10,20,30]이다. Python tuple쌍으로 이 모형을 구현한 자체 예제에서 new의tail is old도True를 확인했다.

별도 비교에서는 v2를 만들지 않는다. v1 생성 뒤 old의 참조를 버리고 v1만 유지한다. 다른 외부 노드 참조가 없을 때 도달/도달 불가 노드를 세어라.

  1. v1은 A1/B1/C1/D 네 노드에 도달한다.

  1. 노드의 head 참조와 tail은 유지된다.

다른 문제에 적용하기

가상 견적 계산의 입력은 불변 정수 목록 [2,5]와 고정 rate 3이다. pureTotal은 원소 합에 rate를 곱해 반환하며 부작용 없이 종료한다. 기록 함수 audit(v)는 기록에 v를 추가하고 v를 반환한다. 두 audit(pureTotal)의 합을 한 번 감사 후 재사용하는 안과 비교하라. 두 안은 각각 새 빈 기록에서 시작하며 기록 추가는 성공한다고 가정한다. 별도 zero(loop)는 값먼저/필요먼저로 비교한다. 또한 두 노드 목록의 둘째 값 5를 7로 경로 복사하고 두 버전을 모두 보관한다. 값/기록/종료/노드 수를 각 조건에서 설명하라.

힌트 2

마지막 위치 갱신의 새 경로와 보관한 옛 노드를 고유 집합으로 센다.

풀이와 답 확인

  1. pureTotal은 (2+5)×3=21이며 원래 두 감사의 합은 42, 기록 [21,21]이다. 재사용안은 합 42, 기록 [21]이어서 전체 관찰은 다르다.

  2. zero(loop)는 값먼저에서 비종료, 필요먼저에서 0이다. 순수한 loop도 전략 변경의 종료 관찰을 바꾼다.

  3. 새 목록은 [2,7]이며 옛 [2,5]는 유지된다. 마지막 위치까지 새 노드 둘을 만들고 두 버전을 보관하면 고유 노드 4개다.

  4. 이것은 손모형이며 실제 언어/감사 서비스/메모리 실험을 수행한 결과는 아니다.

반환합은 모두 42지만 감사 기록은 두 번과 한 번이다. 종료는 비종료와 값 0으로 다르다. 목록 값은 [2,5]/[2,7]로 나뉘고 고유 노드는 4개다.

  • 같은 반환합과 다른 기록을 각각 적는다.

  • 인수 전략의 요구/비요구로 종료를 설명한다.

  • 두 버전의 원본 보존과 새 경로 두 노드·고유 네 노드를 구별한다.
