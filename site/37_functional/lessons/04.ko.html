소단원 4.1

map·filter·fold

리스트의 원소를 바꾸는 일, 골라내는 일, 하나로 모으는 일은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • 리스트는 순서가 있는 유한 원소열이다. 여기서는 원소를 수정하지 않고 새 결과를 만든다.

  • predicate는 원소 하나를 받아 참 또는 거짓을 반환하는 함수다.

  • 본문의 정수는 수학적 정수다. 실제 언어의 범위 초과·예외·부동소수점 문제는 별도로 확인해야 한다.

학습 목표

  • 세 연산의 입력·출력 형식과 빈 리스트 결과를 구별한다.

  • fold의 누적값과 결합 방향을 중간 단계로 계산한다.

두 묶음의 평균을 다시 평균 내면 전체 평균일까?

앞 본문은 fold의 누산기를 (합, 개수)로 두었다. 이 보강에서는 서로 다른 크기의 묶음 A=[2,8], B=[20]을 비교한다. A의 평균은 5, B의 평균은 20이다. 두 평균만 같은 비중으로 더하면 25/2이지만 세 원소의 전체 평균은 30/3=10이다. 묶음의 수와 관찰된 원소의 수가 다른 분모이기 때문이다.

새 요약 S(xs)는 fold_left로 만든 (s,n)이다. 초기값은 (0,0), step(s,n)x=(s+x,n+1)로 두고, 묶음 요약의 결합은 (s1,n1)⊗(s2,n2)=(s1+s2,n1+n2)로 정한다. 이 요약은 수학적 정수의 유한 리스트와 순수 함수에 관한 자체 모형이다. 평균을 보고할 때에만 n>0을 확인하고 정확한 유리수 s/n을 만든다. 빈 평균은 None이며 실제 평균 0인 Some 0과 다르다.

처리한 접두부에 대한 불변식은 s가 그 접두부의 합이고 n이 원소 수라는 것이다. 다음 원소에서 두 성분을 함께 바꾼다. 결합법칙과 항등원은 이 쌍의 덧셈에 성립한다. 평균 수치만 먼저 만드는 정책에는 같은 결합 규칙을 그대로 적용할 수 없다. 실제 부동소수점이나 정수 범위 초과를 포함한 구현에서는 수학적 결합법칙도 별도 확인한다. 각 문제는 독립된 초기 목록에서 시작한다.

먼저 확인할 개념
  • 쌍 누산기와 빈 평균

    합과 개수를 모두 보존한 뒤 나눗셈 조건을 확인한다.

  • 값 동등성과 실제 비용의 구분

    요약 결합의 증명은 병렬 실행이나 메모리 절약 측정이 아니다.

변환과 선택은 다른 약속이다

map f [x1; x2; …]는 각 원소에 f를 적용한 결과를 같은 순서로 나열한다. 모든 원소에서 f가 정의되고 계산이 끝나면 원소 수는 보존된다. 정수의 두 배를 계산하는 map은 정수 리스트를 만들지만 정수를 문자열로 바꾸는 map은 원소 형식도 바꿀 수 있다. 원래 리스트를 제자리에서 바꾼다는 뜻이 아니다.

filter p xs는 p가 참인 원소만 원래 순서대로 남긴다. 변환이 아니라 선택이므로 원소 수는 같거나 줄어든다. [3; 1; 3]에서 2보다 큰 원소를 고르면 [3; 3]이며 중복을 없애거나 정렬하지 않는다. 빈 리스트에서는 f나 p를 호출할 원소가 없고 두 결과 모두 빈 리스트다.

누적값의 형식과 초깃값을 정한다

fold_left step init [x1; x2; x3]는 step init x1, 그 결과와 x2, 다시 그 결과와 x3을 차례로 계산한다. step은 누적값을 먼저, 현재 원소를 나중에 받는다고 이 단원에서 약속한다. 누적값은 원소와 같은 형식일 필요가 없다. 합과 개수를 함께 모으면 정수 하나 대신 (합, 개수) 쌍이 된다.

빈 리스트의 fold 결과는 init이다. 합계의 0과 곱의 1은 각 연산의 항등원이라 편리하지만 모든 문제에 자동으로 맞는 초깃값은 아니다. 평균은 합계만 누적하면 원소 수를 잃고, 빈 리스트를 0/0으로 나누면 정의되지 않는다. 누적값이 무엇을 뜻하는지 먼저 적고 마지막 처리의 조건도 확인한다.

괄호 방향이 결과를 바꿀 수 있다

fold_right step [x1; x2; x3] init은 step x1 (step x2 (step x3 init))이라는 식을 만든다. 이때 step은 원소를 먼저, 누적값을 나중에 받는다. fold_left의 뺄셈은 ((0−5)−2)−1=−8이고 fold_right의 뺄셈은 5−(2−(1−0))=4다. 이름이 비슷해도 누적 인자의 자리와 괄호를 바꾸면 의미가 달라진다.

덧셈처럼 수학적 정수에서 결합법칙이 성립하는 순수 연산은 여러 괄호가 같은 값을 낼 수 있다. 그렇다고 모든 fold를 자유롭게 뒤집거나 병렬화할 수는 없다. 뺄셈, 문자열 순서, 부동소수점 반올림, 부수 효과에서는 조건을 다시 검토한다. fold로 참/거짓을 누적해도 구현이 모든 원소를 순회한다면 첫 거짓에서 종료하는 전용 함수와 호출 횟수가 다르다.

각 행의 n은 묶음 수가 아니라 원소 수다. 평균은 누산기의 저장 성분이 아니라 두 성분으로 계산한 최종 관찰이다. A의 마지막 행에 B의 (20,1)을 결합한다.

중간 과정을 따라가는 예제

xs=[−2; 1; 3; 4]에서 양수만 선택하고 두 배로 변환한 뒤 fold_left 덧셈으로 합산하라. 함수들은 모든 해당 정수에서 정의되고 부수 효과가 없다.

  1. filter의 판정은 거짓, 참, 참, 참이므로 [1; 3; 4]를 얻는다. −2를 0으로 바꾼 결과가 아니다.

  2. map의 원소별 결과는 2, 6, 8이므로 [2; 6; 8]이다. 선택 후 순서가 보존된다.

  3. fold의 초깃값은 0이다. 첫 원소 후 0+2=2, 두 번째 후 2+6=8이다.

  4. 세 번째 후 8+8=16이다. 순회가 끝나 최종 누적값 16을 반환하며 원래 xs는 그대로다.

중간 리스트 [1; 3; 4], [2; 6; 8], 누적값 0→2→8→16이다.

조건을 바꾸어 비교하기

빈 묶음을 포함해도 원소 분모를 보존한다

A, B와 빈 묶음 C=[]의 요약을 결합하라. A/B 평균만의 평균도 비교하라.

  1. S(A)=(10,2), S(B)=(20,1), S(C)=(0,0)이다.

  2. 세 요약을 결합하면 (30,3)이다. C는 항등 요약이므로 분모를 늘리지 않는다.

  3. 평균만 결합하면 (5+20)/2=25/2다. 이것은 두 비빈 묶음의 동일 비중 평균이다.

전체 원소 평균은 10이고 두 묶음 평균의 평균은 25/2다. C의 평균은 None이다.

비교할 점

빈 묶음을 평균 0으로 대체해 세 묶음 평균을 내는 정책과도 구별한다.

평균 값이 같은 두 요약을 합친다

D=[0], E=[0,0]이다. 두 요약과 평균을 구하고 B와 결합할 때 차이를 설명하라.

  1. S(D)=(0,1), S(E)=(0,2)지만 평균은 둘 다 Some 0이다.

  2. D와 B의 결합은 (20,2)이므로 평균 10이다.

  3. E와 B의 결합은 (20,3)이므로 평균 20/3이다.

평균 0만 저장하면 두 결합 결과를 구별할 정보가 사라진다.

비교할 점

같은 최종 관찰이 같은 중간 요약을 의미하지 않는다.

종이와 본문으로 직접 해보기

[2; 4; 6]의 평균을 (합, 개수) 누적값으로 계산하라. 초깃값 (0,0), step (s,n) x=(s+x,n+1)이다. 빈 리스트도 함께 판정하라.

힌트 보기

각 원소에서 쌍의 두 성분을 모두 갱신한다. 마지막 나눗셈 전에 개수가 0인지 검사한다.

풀이 보기

(0,0)→(2,1)→(6,2)→(12,3)이므로 평균 12/3=4다. 빈 리스트는 (0,0)으로 남는다. 개수 0일 때 평균 없음이라는 별도 결과를 반환하고 나눗셈을 하지 않는다. 빈 평균을 0으로 정하려면 그것이 정책상의 대체값이라고 명시해야 한다.

오해와 반례

fold_left와 fold_right는 언제나 같은 결과다.

뺄셈 [5; 2; 1]과 초깃값 0에서 왼쪽 누적은 −8, 오른쪽 식은 4다. 결합법칙·인자 위치·순서 조건 없이 같은 결과를 기대하면 안 된다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

A=[2,8] 다음 B=[20]을 원소별 fold로 처리한다. 모든 경계의 쌍과, B를 먼저 처리한 뒤 A를 처리할 때 최종 요약을 예측하라.

힌트 1

첫 성분은 합이고 둘째는 처리한 원소 수다.

힌트 2

초기값도 경계에 포함하고 순서 변경은 최종 쌍과 중간 쌍을 구분한다.

풀이와 답 확인

  1. A 다음 B의 경계는 (0,0)→(2,1)→(10,2)→(30,3)이다.

  2. B 다음 A의 경계는 (0,0)→(20,1)→(22,2)→(30,3)이다.

중간 쌍은 다르지만 최종 요약은 (30,3), 평균은 10으로 같다.

흔한 오답에서 다시 생각하기

최종 값이 같으므로 모든 중간 상태도 같다.

첫 원소부터 합 2와 합 20으로 다르다. 최종 결합의 교환 성질을 실행 이력 전체의 동일성으로 확대하지 않는다.

연습 2 · 오류 찾아 고치기

잘못된 step은 x가 0일 때 (s,n)을 그대로 반환한다. [0,20]의 평균과 []의 결과를 진단하고 고쳐라.

힌트 1

값 0도 입력 위치 하나를 차지한다.

힌트 2

합을 바꾸지 않는 것과 개수를 늘리지 않는 것은 다르다.

풀이와 답 확인

  1. 잘못된 누산기는 첫 0을 세지 않아 최종 (20,1), 평균 20이다.

  2. 정상 step은 0에서도 n을 증가시켜 (0,1)→(20,2)를 만든다.

  3. []에서는 (0,0)을 유지하고 None을 반환한다.

[0,20]의 정상 평균은 10이며 빈 평균은 None이다.

흔한 오답에서 다시 생각하기

0은 합의 항등원이므로 평균에서도 무시해도 된다.

평균의 분모는 합에 기여한 비영 값 수가 아니다. 모든 관찰 원소 수를 세어야 한다.

연습 3 · 직접 만들어 보기

요약 결합 ⊗가 S(xs++ys)=S(xs)⊗S(ys)를 만족함을 접두부와 항등 요약으로 설명하고, 빈 요약의 평균 보고 규칙을 설계하라.

힌트 1

연결 뒤의 합과 길이를 각각 두 목록의 합과 길이로 나눈다.

힌트 2

원소를 추가하는 단계에서 합과 개수의 두 성분을 모두 확인한다.

풀이와 답 확인

  1. 빈 xs에서는 S([])=(0,0)이므로 결합 결과는 S(ys)다.

  2. 원소 x를 추가하면 합 성분에 x, 개수 성분에 1을 더한다. 두 목록의 연결도 같은 원소를 같은 횟수만큼 포함한다.

  3. 쌍 결합은 각 성분의 덧셈이므로 항등과 결합법칙이 성립한다.

  4. 보고는 n=0이면 None, n>0이면 Some(s/n)이다.

합과 개수의 연결 성질이 요약 결합을 정당화한다. 이 증명만으로 런타임 병렬 성공은 주장하지 않는다.

흔한 오답에서 다시 생각하기

평균끼리 더하는 연산도 자동으로 같은 항등원과 결합법칙을 갖는다.

평균은 나눗셈 뒤에 개수 정보를 잃는다. 어떤 비중을 쓰는지와 빈 입력 정책을 따로 정해야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

각 비빈 묶음의 크기가 모두 k>0일 때 묶음 평균의 동일 비중 평균과 전체 원소 평균이 왜 같은가? 크기가 다르면 항상 다른지도 판단하라.

힌트 1

묶음 수 m>0과 각 합 s_i를 써 본다.

힌트 2

크기가 다른 A=[0], B=[0,0]도 확인한다.

풀이와 답 확인

  1. 같은 크기에서는 평균의 평균은 (Σ(s_i/k))/m=(Σs_i)/(mk)다. 전체 원소 수도 mk다.

  2. 크기가 다르면 일반 등식을 보장하지 못하지만 두 평균이 우연히 같을 수 있다.

소단원 4.2

함수인자와 반환

함수를 값으로 전달하거나 새 함수를 돌려받으면 어떤 표현을 만들 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수 A→B는 A 형식의 입력을 받아 B 형식의 결과를 만드는 약속이다.

  • 함수를 인자로 받거나 결과로 반환하는 함수를 고차함수라고 부른다.

  • 이 단원의 덧셈은 수학적 정수이며 함수 본문은 호출할 때 계산한다고 정한다.

학습 목표

  • 함수 값과 함수 호출 결과를 구분한다.

  • 반환된 함수의 환경과 반복 적용의 형식 조건을 추적한다.

입출력 타입이 같으면 두 번 적용해도 항상 성공할까?

앞 본문의 twice는 f의 출력이 다시 f의 입력이 되므로 A→A 형식을 요구했다. 그러나 형식만으로 모든 A 값에서 성공을 보장하지 않는다. 새 H는 짝수 정수 x에서만 x/2를 반환하고 홀수에서는 실패한다. 반환값도 정수지만 twice H 2는 2→1 이후 두 번째 호출에서 실패한다. twice H 4는 4→2→1로 정상 완료한다.

순수하고 종료하는 f의 실제 성공 입력 집합을 D라고 하자. twice가 정상 값을 얻는 입력은 x∈D이고 f(x)∈D인 입력들이다. 두 번째 조건은 첫 호출의 출력에 대한 조건이다. 함수 인자를 받은 고차함수가 이러한 범위 검사를 대신 해 준다고 자동으로 가정하지 않는다.

환경을 보존하는 반환 함수도 보존 대상의 종류를 확인한다. 새 불변 환경 shift(k)는 x+k를 계산한다. 별도 상태 모형 live(cell)는 호출 때 공유 셀을 읽어 x+cell.value를 계산한다. captured(cell)는 생성 시 cell.value를 한 번 읽어 그 정수를 보존한다. 다음 표에서는 처음 셀 값이 3이고 두 함수를 만든 뒤 셀을 8로 바꾼다. 실제 언어 실행이나 동시 접근은 요구하지 않는다.

    A→A와 클로저 환경을 실제 성공 범위·공유 대상까지 구분한다.

  • 합성의 중간 유효 범위

행동을 인자로 받는다

apply f x=f x는 어떤 f를 사용할지 호출하는 쪽이 정하도록 한다. f가 입력을 두 배로 만들면 apply도 두 배 결과를, 제곱하면 제곱 결과를 만든다. 고차함수는 반복문·재귀·병렬 실행의 동의어가 아니다. 함수를 다루는 방식에 관한 분류이며 단 한 번만 인자를 호출할 수도 있다.

twice f x=f(f x)는 같은 함수를 두 번 적용한다. 이 모형에서 f는 A→A여야 한다. 첫 호출의 출력이 두 번째 호출의 입력으로 쓰이기 때문이다. 정수→문자열 함수는 두 번째에 문자열을 입력받을 수 없다면 twice에 넣을 수 없다. 결과의 형식이 맞더라도 두 번째 입력에서 f가 정의되는지도 확인한다.

함수를 반환하고 환경을 보존한다

make_shift k는 fun x→x+k라는 새 함수를 반환한다. make_shift 3은 계산 결과 3이나 특정 입력의 합계가 아니라, 앞으로 들어올 수에 3을 더하는 함수 값이다. 반환된 함수가 참조할 k=3이라는 환경을 함께 보존하는 표현을 클로저라고 부른다. 여기서는 k가 변하지 않는 값이라는 조건을 둔다.

a=make_shift 3, b=make_shift 5이면 a 4=7, b 4=9다. 같은 함수 본문 형태라도 보존한 환경이 다르다. 외부의 변경 가능한 참조를 함께 잡는 클로저라면 나중에 상태가 바뀔 때 결과가 달라질 수 있다. 클로저라는 이유만으로 자동으로 순수하거나 복제 가능한 것은 아니다.

반복 적용과 호출 시점을 구별한다

a라는 함수 값을 다른 이름 c에 대입하는 것과 a 4를 계산하는 것은 다르다. 전자는 이 모형에서 아직 덧셈을 수행하지 않고, 후자는 본문에 입력을 주어 결과를 만든다. 부분 적용도 남은 인자를 받을 함수를 만드는 표현으로 이해할 수 있지만 구체 언어의 평가·예외 시점은 문법과 정의를 확인해야 한다.

twice가 f를 두 번 호출한다는 약속은 결과를 두 배 한다는 뜻이 아니다. a x=x+3이면 twice a 4=10이고 2×a 4=14다. f가 화면 출력이나 상태 변경을 한다면 두 호출은 두 효과를 낼 수 있다. 효과를 무시해 수식처럼 바꾸기 전에 함수의 계약을 확인한다.

함수 인자를 받는 고차함수라면 언제나 부수 효과가 없다.

소단원 4.3

pipeline과 조합

읽는 순서와 함수가 연결되는 순서를 어떻게 맞출 수 있을까?

준비 개념과 학습 목표

준비 개념

  • g:A→B, f:B→C이면 g의 출력에 f를 적용하여 A→C 함수를 만들 수 있다.

  • 이 단원에서 compose f g x=f(g x)이고 x |> g |> f는 g 다음 f를 적용한다.

  • 같은 결과를 만든다는 주장에는 순수성·정의역·종료·평가 순서 조건이 필요하다.

학습 목표

  • 합성과 파이프라인의 순서를 형식과 값으로 확인한다.

  • 중간 자료와 부수 효과를 고려하여 합성 변환의 한계를 설명한다.

filter를 map 앞에 옮기려면 선택 기준만 같으면 될까?

앞 본문에서는 짝수 선택과 +1의 순서를 바꾸면 결과가 달랐다. 새 f(x)=x², p(y)는 y>4라는 판정이다. map f 뒤 filter p를 하는 순수·전체 함수 모형에서 선택을 앞당기려면 q(x)=p(f(x))를 쓴다. f를 먼저 적용한 값에 관한 조건을 원래 값에 관한 조건으로 옮긴 것이다. 여기서는 q(x)가 x<−2 또는 x>2라는 비교식과 같다.

모든 정수에서 f와 p가 종료하고 순수하다는 조건에서 filter p (map f xs)=map f (filter q xs)를 각 위치로 보일 수 있다. 왼쪽은 f(x)를 만든 뒤 p(f(x))가 참이면 남긴다. 오른쪽은 바로 그 조건으로 x를 남긴 뒤 같은 f(x)를 만든다. 원래 순서와 중복도 보존된다. q를 실제로 p(f(x))로 구현하면 선택된 원소에서 f를 다시 계산한다. 간단한 비교식으로 정리했다는 사실과 일반 합성 표기만의 비용을 구분한다.

f가 부분 함수이거나 로그를 남기면 이 값 등식만으로 변환을 허용하지 않는다. 새 F는 음수에서 실패하고 나머지에서 제곱한다. 앞에서 음수를 걸러 내는 변환은 원래 map이 관찰하던 실패를 없앨 수 있다. 별도 엄격한 순차 모형에서는 함수 호출을 왼쪽부터 수행하며 실패 즉시 멈춘다고 정한다. 이 순서를 모든 OCaml 식이나 지연 라이브러리의 보장으로 일반화하지 않는다.

먼저 확인할 개념
  • 선택·변환의 순서와 효과 로그

    선택 조건의 이동에는 값뿐 아니라 실패와 호출 관찰을 포함한다.

  • filter의 중복과 순서 보존

    선택은 집합화가 아니므로 위치별 관계로 등식을 증명한다.

합성에서 오른쪽 함수가 먼저다

compose f g는 입력에 g를 먼저 적용하고 그 결과에 f를 적용하는 새 함수다. f가 +1, g가 ×2라면 입력 3에서 g 3=6, f 6=7이다. 순서를 바꾼 compose g f는 3→4→8이므로 결과가 다르다. 함수의 합성은 일반적으로 교환법칙이 성립하지 않는다.

g가 정수를 문자열로, f가 문자열을 길이로 바꾼다면 compose f g는 정수→정수다. 반대 순서가 항상 형식에 맞지는 않는다. 그림으로 A→B→C를 그리고 중간 B가 일치하는지 먼저 확인한다. 형식이 맞아도 중간 결과가 다음 함수의 실제 유효 입력 범위 안에 들어야 한다.

파이프라인은 적용 방향을 읽기 쉽게 쓴다

x |> g는 g x의 적용을 앞으로 읽도록 쓴 표현이다. x |> g |> f는 compose f g x와 같은 연결이다. 함수가 왼쪽에서 오른쪽으로 나열되어 자료가 이동하는 순서를 읽기 쉽다. 이 문법 자체가 여러 CPU를 사용하거나 중간 자료를 없애는 것은 아니다.

리스트를 filter, map, fold 순으로 처리하면 각 단계가 무엇을 받는지 적어야 한다. 엄격한 리스트 모형에서는 filter 결과와 map 결과를 실제 중간 리스트로 만들 수 있다. 비용을 줄이는 구현은 별도 선택이다. 파일 스트림·지연 시퀀스·병렬 라이브러리에도 비슷한 표기가 있지만 평가 시점과 순서 계약까지 같다고 일반화하지 않는다.

결과가 같아도 효과와 비용은 확인한다

순수하고 모든 입력에서 종료하는 f와 g에 대해 map g (map f xs)와 map (compose g f) xs는 같은 위치에 g(f x)를 둔다. 빈 리스트는 둘 다 빈 리스트이고, 각 다음 원소에서도 같은 결과 하나를 붙이므로 유한 리스트의 모든 위치에서 값이 같다. 이것은 자체 원소별 증명이며 실제 컴파일러 최적화 여부를 관찰한 것은 아니다.

이 단원의 별도 엄격한 순차 모형은 각 map의 원소를 왼쪽부터 처리한다. f와 g가 로그를 남기면 두 단계 처리는 f1,f2,g1,g2, 합쳐진 처리는 f1,g1,f2,g2다. 어떤 언어든 이 순서라고 주장하지 않는다. 공유 상태를 읽거나 실패하는 함수에서는 관찰 결과도 달라질 수 있다. 순수한 경우에도 함수 호출은 각각 n회이며, 합쳐진 식이 중간 리스트 하나를 피할 가능성과 실제 메모리 측정 결과는 구별한다.

답과 이유 보기

아니다.

n개 원소 각각에 f와 g를 한 번씩 적용하므로 각 n회다. 중간 리스트 비용과 함수 호출 수는 다르다.

힌트 2

두 반의 관찰 A=[−3,−2], B=[1,3]을 순서대로 연결한다. 전체 f(x)=x²와 p(y):y>4를 사용해 선택된 제곱값의 전체 평균을 구한다. (1) 각 반을 map→filter→요약한 뒤 두 요약을 결합하라. (2) 비교식 q(x):x<−2 또는 x>2로 먼저 선택한 뒤 f와 요약을 한 번의 순회에 묶는 설계를 쓰고 누산기 경계를 적어라.
