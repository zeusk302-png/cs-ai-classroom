소단원 4.1

map·filter·fold

리스트의 원소를 바꾸는 일, 골라내는 일, 하나로 모으는 일은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • 리스트는 순서가 있는 유한 원소열이다. 여기서는 원소를 수정하지 않고 새 결과를 만든다.
  • predicate는 원소 하나를 받아 참 또는 거짓을 반환하는 함수다.
  • 본문의 정수는 수학적 정수다. 실제 언어의 범위 초과·예외·부동소수점 문제는 별도로 확인해야 한다.

학습 목표

  • 세 연산의 입력·출력 형식과 빈 리스트 결과를 구별한다.
  • fold의 누적값과 결합 방향을 중간 단계로 계산한다.

변환과 선택은 다른 약속이다

map f [x1; x2; …]는 각 원소에 f를 적용한 결과를 같은 순서로 나열한다. 모든 원소에서 f가 정의되고 계산이 끝나면 원소 수는 보존된다. 정수의 두 배를 계산하는 map은 정수 리스트를 만들지만 정수를 문자열로 바꾸는 map은 원소 형식도 바꿀 수 있다. 원래 리스트를 제자리에서 바꾼다는 뜻이 아니다.

filter p xs는 p가 참인 원소만 원래 순서대로 남긴다. 변환이 아니라 선택이므로 원소 수는 같거나 줄어든다. [3; 1; 3]에서 2보다 큰 원소를 고르면 [3; 3]이며 중복을 없애거나 정렬하지 않는다. 빈 리스트에서는 f나 p를 호출할 원소가 없고 두 결과 모두 빈 리스트다.

누적값의 형식과 초깃값을 정한다

fold_left step init [x1; x2; x3]는 step init x1, 그 결과와 x2, 다시 그 결과와 x3을 차례로 계산한다. step은 누적값을 먼저, 현재 원소를 나중에 받는다고 이 단원에서 약속한다. 누적값은 원소와 같은 형식일 필요가 없다. 합과 개수를 함께 모으면 정수 하나 대신 (합, 개수) 쌍이 된다.

빈 리스트의 fold 결과는 init이다. 합계의 0과 곱의 1은 각 연산의 항등원이라 편리하지만 모든 문제에 자동으로 맞는 초깃값은 아니다. 평균은 합계만 누적하면 원소 수를 잃고, 빈 리스트를 0/0으로 나누면 정의되지 않는다. 누적값이 무엇을 뜻하는지 먼저 적고 마지막 처리의 조건도 확인한다.

괄호 방향이 결과를 바꿀 수 있다

fold_right step [x1; x2; x3] init은 step x1 (step x2 (step x3 init))이라는 식을 만든다. 이때 step은 원소를 먼저, 누적값을 나중에 받는다. fold_left의 뺄셈은 ((0−5)−2)−1=−8이고 fold_right의 뺄셈은 5−(2−(1−0))=4다. 이름이 비슷해도 누적 인자의 자리와 괄호를 바꾸면 의미가 달라진다.

덧셈처럼 수학적 정수에서 결합법칙이 성립하는 순수 연산은 여러 괄호가 같은 값을 낼 수 있다. 그렇다고 모든 fold를 자유롭게 뒤집거나 병렬화할 수는 없다. 뺄셈, 문자열 순서, 부동소수점 반올림, 부수 효과에서는 조건을 다시 검토한다. fold로 참/거짓을 누적해도 구현이 모든 원소를 순회한다면 첫 거짓에서 종료하는 전용 함수와 호출 횟수가 다르다.

중간 과정을 따라가는 예제

xs=[−2; 1; 3; 4]에서 양수만 선택하고 두 배로 변환한 뒤 fold_left 덧셈으로 합산하라. 함수들은 모든 해당 정수에서 정의되고 부수 효과가 없다.

  1. filter의 판정은 거짓, 참, 참, 참이므로 [1; 3; 4]를 얻는다. −2를 0으로 바꾼 결과가 아니다.
  2. map의 원소별 결과는 2, 6, 8이므로 [2; 6; 8]이다. 선택 후 순서가 보존된다.
  3. fold의 초깃값은 0이다. 첫 원소 후 0+2=2, 두 번째 후 2+6=8이다.
  4. 세 번째 후 8+8=16이다. 순회가 끝나 최종 누적값 16을 반환하며 원래 xs는 그대로다.

중간 리스트 [1; 3; 4], [2; 6; 8], 누적값 0→2→8→16이다.

종이와 본문으로 직접 해보기

[2; 4; 6]의 평균을 (합, 개수) 누적값으로 계산하라. 초깃값 (0,0), step (s,n) x=(s+x,n+1)이다. 빈 리스트도 함께 판정하라.

힌트 보기

각 원소에서 쌍의 두 성분을 모두 갱신한다. 마지막 나눗셈 전에 개수가 0인지 검사한다.

풀이 보기

(0,0)→(2,1)→(6,2)→(12,3)이므로 평균 12/3=4다. 빈 리스트는 (0,0)으로 남는다. 개수 0일 때 평균 없음이라는 별도 결과를 반환하고 나눗셈을 하지 않는다. 빈 평균을 0으로 정하려면 그것이 정책상의 대체값이라고 명시해야 한다.

오해와 반례

fold_left와 fold_right는 언제나 같은 결과다.

뺄셈 [5; 2; 1]과 초깃값 0에서 왼쪽 누적은 −8, 오른쪽 식은 4다. 결합법칙·인자 위치·순서 조건 없이 같은 결과를 기대하면 안 된다.

자기점검

map은 중복 원소를 제거하는가?

답과 이유 보기

아니다.

모든 원소가 처리되면 각 입력 위치마다 결과 하나를 만든다.

filter의 빈 리스트 결과는 무엇인가?

답과 이유 보기

빈 리스트다.

선택할 입력 원소가 없다.

빈 리스트의 fold_left 결과는 무엇인가?

답과 이유 보기

초깃값이다.

step을 적용할 원소가 없으므로 누적값이 바뀌지 않는다.

한 단계 더

step n _=n+1, init=0으로 길이를 구해 보라. 원소를 실제로 소비하므로 길이를 이미 저장하는 자료구조의 조회와 비용이 다를 수 있다. 모든 원소가 조건을 만족하는지 fold로 확인할 때 순회 자체가 중단되는지도 구현 정의에서 따로 살펴본다.

소단원 4.2

함수인자와 반환

함수를 값으로 전달하거나 새 함수를 돌려받으면 어떤 표현을 만들 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수 A→B는 A 형식의 입력을 받아 B 형식의 결과를 만드는 약속이다.
  • 함수를 인자로 받거나 결과로 반환하는 함수를 고차함수라고 부른다.
  • 이 단원의 덧셈은 수학적 정수이며 함수 본문은 호출할 때 계산한다고 정한다.

학습 목표

  • 함수 값과 함수 호출 결과를 구분한다.
  • 반환된 함수의 환경과 반복 적용의 형식 조건을 추적한다.

행동을 인자로 받는다

apply f x=f x는 어떤 f를 사용할지 호출하는 쪽이 정하도록 한다. f가 입력을 두 배로 만들면 apply도 두 배 결과를, 제곱하면 제곱 결과를 만든다. 고차함수는 반복문·재귀·병렬 실행의 동의어가 아니다. 함수를 다루는 방식에 관한 분류이며 단 한 번만 인자를 호출할 수도 있다.

twice f x=f(f x)는 같은 함수를 두 번 적용한다. 이 모형에서 f는 A→A여야 한다. 첫 호출의 출력이 두 번째 호출의 입력으로 쓰이기 때문이다. 정수→문자열 함수는 두 번째에 문자열을 입력받을 수 없다면 twice에 넣을 수 없다. 결과의 형식이 맞더라도 두 번째 입력에서 f가 정의되는지도 확인한다.

함수를 반환하고 환경을 보존한다

make_shift k는 fun x→x+k라는 새 함수를 반환한다. make_shift 3은 계산 결과 3이나 특정 입력의 합계가 아니라, 앞으로 들어올 수에 3을 더하는 함수 값이다. 반환된 함수가 참조할 k=3이라는 환경을 함께 보존하는 표현을 클로저라고 부른다. 여기서는 k가 변하지 않는 값이라는 조건을 둔다.

a=make_shift 3, b=make_shift 5이면 a 4=7, b 4=9다. 같은 함수 본문 형태라도 보존한 환경이 다르다. 외부의 변경 가능한 참조를 함께 잡는 클로저라면 나중에 상태가 바뀔 때 결과가 달라질 수 있다. 클로저라는 이유만으로 자동으로 순수하거나 복제 가능한 것은 아니다.

반복 적용과 호출 시점을 구별한다

a라는 함수 값을 다른 이름 c에 대입하는 것과 a 4를 계산하는 것은 다르다. 전자는 이 모형에서 아직 덧셈을 수행하지 않고, 후자는 본문에 입력을 주어 결과를 만든다. 부분 적용도 남은 인자를 받을 함수를 만드는 표현으로 이해할 수 있지만 구체 언어의 평가·예외 시점은 문법과 정의를 확인해야 한다.

twice가 f를 두 번 호출한다는 약속은 결과를 두 배 한다는 뜻이 아니다. a x=x+3이면 twice a 4=10이고 2×a 4=14다. f가 화면 출력이나 상태 변경을 한다면 두 호출은 두 효과를 낼 수 있다. 효과를 무시해 수식처럼 바꾸기 전에 함수의 계약을 확인한다.

let make_shift k = fun x -> x + k
let twice f x = f (f x)
(* 수학적 정수 모형의 설명 코드; 실행하지 않음 *)

중간 과정을 따라가는 예제

a=make_shift 3, b=make_shift 5라고 하자. a 4, b 4, twice a 4, twice b 4를 계산하고 make_shift가 반환하는 값의 종류를 설명하라.

  1. make_shift 3을 평가하면 k=3을 보존하는 함수 a를 받는다. 이 단계는 입력 4에 대한 계산이 아니다.
  2. a 4는 4+3=7, b 4는 4+5=9다. 두 함수의 환경 값이 다르다.
  3. twice a 4의 안쪽 호출은 a 4=7, 바깥 호출은 a 7=10이다.
  4. twice b 4의 안쪽 호출은 9, 바깥 호출은 b 9=14다. 결과 10과 14는 두 함수의 연속 적용 결과이며 7과 9를 각각 두 배 한 것이 아니다.

a 4=7, b 4=9, twice a 4=10, twice b 4=14. make_shift는 함수를 반환한다.

종이와 본문으로 직접 해보기

h x=x×2라면 twice h 3을 계산하라. 문자열의 길이를 반환하는 len:문자열→정수를 twice의 f로 사용할 수 있는지도 설명하라.

힌트 보기

바깥 호출의 입력은 안쪽 호출의 결과다. 입력·출력 형식 화살표를 연결해 본다.

풀이 보기

h 3=6, h 6=12다. 이 정의의 twice는 같은 f를 다시 호출하므로 len이 만든 정수를 다음 len이 받을 수 없다. 문자열→정수의 len은 해당 twice의 A→A 조건을 만족하지 않는다. 정수→정수 함수와 연결하는 별도 합성은 가능하다.

오해와 반례

함수 인자를 받는 고차함수라면 언제나 부수 효과가 없다.

명시적으로 상태 n을 하나 증가시키고 새 n을 반환하는 next를 twice로 호출하면 상태가 두 번 바뀐다. 처음 n=0이면 두 호출 뒤 n=2다. 고차함수 여부와 순수성 여부는 별도의 성질이다. 이 상태 예는 호출 순서가 정해진 자체 종이 모형이다.

자기점검

make_shift 3의 결과는 정수 3인가?

답과 이유 보기

아니다. 함수다.

나중에 입력받은 수에 3을 더하는 행동을 반환한다.

twice에 A→B이면 모두 가능한가?

답과 이유 보기

아니다. 이 정의는 A→A를 요구한다.

출력이 같은 함수의 다음 입력으로 들어간다.

twice (x→x+1) 5는 12인가?

답과 이유 보기

아니다. 7이다.

5→6→7로 연속 적용한다. 첫 결과를 두 배 하지 않는다.

한 단계 더

함수를 반환하는 방식과 설정 객체를 넘기는 방식을 비교하라. 변하지 않는 환경과 공유 변경 상태를 각각 표시하면 두 클로저가 독립인지 판단하기 쉽다. 함수의 형식이 맞는다는 사실과 모든 입력에서 종료·오류 없음이 보장된다는 사실도 구분한다.

소단원 4.3

pipeline과 조합

읽는 순서와 함수가 연결되는 순서를 어떻게 맞출 수 있을까?

준비 개념과 학습 목표

준비 개념

  • g:A→B, f:B→C이면 g의 출력에 f를 적용하여 A→C 함수를 만들 수 있다.
  • 이 단원에서 compose f g x=f(g x)이고 x |> g |> f는 g 다음 f를 적용한다.
  • 같은 결과를 만든다는 주장에는 순수성·정의역·종료·평가 순서 조건이 필요하다.

학습 목표

  • 합성과 파이프라인의 순서를 형식과 값으로 확인한다.
  • 중간 자료와 부수 효과를 고려하여 합성 변환의 한계를 설명한다.

합성에서 오른쪽 함수가 먼저다

compose f g는 입력에 g를 먼저 적용하고 그 결과에 f를 적용하는 새 함수다. f가 +1, g가 ×2라면 입력 3에서 g 3=6, f 6=7이다. 순서를 바꾼 compose g f는 3→4→8이므로 결과가 다르다. 함수의 합성은 일반적으로 교환법칙이 성립하지 않는다.

g가 정수를 문자열로, f가 문자열을 길이로 바꾼다면 compose f g는 정수→정수다. 반대 순서가 항상 형식에 맞지는 않는다. 그림으로 A→B→C를 그리고 중간 B가 일치하는지 먼저 확인한다. 형식이 맞아도 중간 결과가 다음 함수의 실제 유효 입력 범위 안에 들어야 한다.

파이프라인은 적용 방향을 읽기 쉽게 쓴다

x |> g는 g x의 적용을 앞으로 읽도록 쓴 표현이다. x |> g |> f는 compose f g x와 같은 연결이다. 함수가 왼쪽에서 오른쪽으로 나열되어 자료가 이동하는 순서를 읽기 쉽다. 이 문법 자체가 여러 CPU를 사용하거나 중간 자료를 없애는 것은 아니다.

리스트를 filter, map, fold 순으로 처리하면 각 단계가 무엇을 받는지 적어야 한다. 엄격한 리스트 모형에서는 filter 결과와 map 결과를 실제 중간 리스트로 만들 수 있다. 비용을 줄이는 구현은 별도 선택이다. 파일 스트림·지연 시퀀스·병렬 라이브러리에도 비슷한 표기가 있지만 평가 시점과 순서 계약까지 같다고 일반화하지 않는다.

결과가 같아도 효과와 비용은 확인한다

순수하고 모든 입력에서 종료하는 f와 g에 대해 map g (map f xs)와 map (compose g f) xs는 같은 위치에 g(f x)를 둔다. 빈 리스트는 둘 다 빈 리스트이고, 각 다음 원소에서도 같은 결과 하나를 붙이므로 유한 리스트의 모든 위치에서 값이 같다. 이것은 자체 원소별 증명이며 실제 컴파일러 최적화 여부를 관찰한 것은 아니다.

이 단원의 별도 엄격한 순차 모형은 각 map의 원소를 왼쪽부터 처리한다. f와 g가 로그를 남기면 두 단계 처리는 f1,f2,g1,g2, 합쳐진 처리는 f1,g1,f2,g2다. 어떤 언어든 이 순서라고 주장하지 않는다. 공유 상태를 읽거나 실패하는 함수에서는 관찰 결과도 달라질 수 있다. 순수한 경우에도 함수 호출은 각각 n회이며, 합쳐진 식이 중간 리스트 하나를 피할 가능성과 실제 메모리 측정 결과는 구별한다.

중간 과정을 따라가는 예제

xs=[1;2;3]이다. 짝수를 선택한 뒤 +1을 적용하는 파이프라인과 +1을 적용한 뒤 짝수를 선택하는 파이프라인을 비교하라. predicate는 x가 2로 나누어떨어지는지 판정한다.

  1. 첫 파이프라인의 filter는 1 거짓, 2 참, 3 거짓이므로 [2]를 남긴다.
  2. 여기에 map (+1)을 적용하면 [3]이다. 선택 기준은 원래 값이었다.
  3. 둘째 파이프라인의 map은 [2;3;4]를 만든다. 여기에 filter를 적용하면 [2;4]다.
  4. 결과 [3]과 [2;4]는 값과 길이 모두 다르다. 단계의 순서를 바꾸려면 선택 기준이 변환 전후 어떤 값에 적용되는지 증명해야 한다.

filter→map은 [3], map→filter는 [2;4]다. 임의로 순서를 바꾸면 안 된다.

종이와 본문으로 직접 해보기

f x=x+1, g x=x×2, xs=[1;2]에서 두 단계 map과 합친 map의 값 및 f/g 호출 횟수를 계산하라. 다음으로 f가 F, g가 G를 로그에 붙인다고 정하고 왼쪽부터 처리하는 자체 순차 모형의 로그를 적어라.

힌트 보기

두 단계는 f로 만든 리스트 전체를 얻은 다음 g를 적용한다. 합친 단계는 원소마다 f 다음 g를 수행한다.

풀이 보기

두 단계는 [1;2]→[2;3]→[4;6], 합친 단계도 [4;6]이다. 둘 모두 f 2회와 g 2회다. 단순 로그는 두 단계 FFGG, 합친 단계 FGFG다. 원소 값을 변환하는 함수들이 공유 상태까지 읽으면 값 일치도 별도 확인해야 한다. 실제 OCaml/다른 언어의 일반 평가 순서 보장으로 사용하지 않는다.

오해와 반례

파이프라인 연산자를 쓰면 중간 리스트가 자동으로 없어지고 병렬 실행된다.

엄격한 리스트에서 xs |> filter p |> map f는 filter의 결과 리스트를 만든 뒤 map할 수 있다. 표기만으로 자료 융합·지연 평가·병렬화가 보장되지 않는다. 이를 보장하려면 해당 자료형과 라이브러리의 계약 또는 실제 구현·측정을 확인해야 한다.

자기점검

compose f g에서 먼저 적용되는 함수는?

답과 이유 보기

g다.

정의 f(g x)의 안쪽 결과가 f의 입력이 된다.

x |> g |> f는 compose g f x인가?

답과 이유 보기

아니다. compose f g x다.

자료가 g 다음 f로 이동한다.

순수 map 두 단계를 합치면 f 호출도 절반인가?

답과 이유 보기

아니다.

n개 원소 각각에 f와 g를 한 번씩 적용하므로 각 n회다. 중간 리스트 비용과 함수 호출 수는 다르다.

한 단계 더

빈 리스트와 임의의 원소를 기준으로 순수 map 합성의 위치별 증명을 써 보라. filter/map 교환은 predicate를 변환에 맞게 바꾸는 등의 추가 조건이 있어야 한다. 배열·지연 시퀀스·GPU에서도 같은 수식만 보고 효과·메모리·종료 의미까지 동일하다고 결론내리지 않는다.
