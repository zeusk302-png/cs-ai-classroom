소단원 9.1

signature·structure

모듈의 사용 설명서와 실제 구현은 무엇이 다를까?

준비 개념과 학습 목표

준비 개념

  • 함수 타입

  • 이름 공간

학습 목표

  • 서명의 명세와 구조의 정의를 구별한다.

  • 구현의 타입 일치를 확인한다.

structure는 정의들을 묶는다

OCaml structure는 값·함수·타입·예외 같은 관련 정의를 묶는 구현이다. module 이름을 붙여 M.f처럼 접근한다. 클래스의 인스턴스나 this를 가진 객체라고 해석하지 않는다. 모듈 정의의 앞 이름은 뒤 정의에서 쓸 수 있다.

signature는 공개할 이름과 타입을 적는다

sig ... end는 구현이 제공할 명세의 모음이다. val inc : int -> int는 inc를 실행하는 문장이 아니라 함수 타입을 요구한다. module type은 서명에 이름을 붙이며 module의 : S는 필요한 이름/타입 일치와 외부 공개 범위를 제한한다.

module type S = sig
  val inc : int -> int
  val twice : int -> int
end
module Calc : S = struct
  let inc x = x + 1
  let twice x = inc (inc x)
end

타입 일치와 행동 약속을 구별한다

서명의 int -> int만으로 inc가 반드시 1을 더한다는 의미까지 증명하지는 않는다. 사전조건·결과 약속·예외·복잡도도 문서와 별도 검증으로 정한다. 필요한 값이 빠지거나 int 대신 string을 반환하는 구현은 같은 서명에 맞지 않는다.

중간 과정을 따라가는 예제

아래 모듈의 공개 inc와 twice를 이용해 Calc.twice 3을 구하라. 정수 범위를 넘지 않는다.

  1. inc 3은 3+1=4다.

  2. twice 3은 inc(inc 3)으로 inc 4다.

  3. 4+1=5이며 이름의 twice는 호출을 두 번 한다는 뜻이다.

결과 5다. 숫자를 두 배인 6으로 만드는 함수가 아니다.

힌트 보기

풀이 보기

오해와 반례

함수 타입이 같으면 행동도 항상 같다.

int -> int인 함수라도 x+1과 x−1은 결과가 다르다. 서명에 행동 계약과 예제를 덧붙여야 한다.

소단원 9.2

정보은닉

내부에서 정수로 저장한다고 사용자가 직접 정수를 넣어도 될까?

준비 개념과 학습 목표

준비 개념

  • 모듈 서명

  • 사전조건

학습 목표

  • 추상 타입의 표현 숨김을 설명한다.

  • 공개 연산을 통해 불변식을 보존한다.

표현은 내부의 선택이다

서명에 type t라고만 적으면 이름은 공개하지만 표현의 동일성을 숨긴다. 내부 type t=int여도 외부 코드가 t를 int로 취급할 근거는 없다. 서명에 type t=int를 공개하는 설계와 구별한다. 정보은닉은 암호화나 보안 권한의 자동 보장이 아니다.

유효한 값의 생성 경로를 정한다

아래 Nonneg는 음수가 아닌 정수를 담는다. make는 음수이면 None, 아니면 Some 값을 반환하며 value만 정수 관찰을 허용한다. 사용자에게 임의 표현값을 만드는 연산을 공개하지 않아 불변식 훼손 경로를 줄인다.

module type NONNEG = sig
  type t
  val make : int -> t option
  val value : t -> int
end
module Nonneg : NONNEG = struct
  type t = int
  let make n = if n < 0 then None else Some n
  let value n = n
end

표현 변경과 행동 호환을 함께 본다

내부에 별도 레코드를 쓰더라도 make/value의 관찰 계약이 같으면 사용자는 표현에 덜 의존한다. 표현을 숨긴 사실만으로 구현 오류까지 없어지지는 않는다. 공개 생성자와 연산이 모든 허용 입력에서 불변식을 유지하는지 확인한다.

중간 과정을 따라가는 예제

아래 Nonneg.make(-2), Nonneg.make 3과 성공한 값의 value를 구하라. 외부에서 let x : Nonneg.t = 3을 허용할 수 있는가?

  1. −2<0이므로 첫 결과 None이다.

  2. 3>=0이므로 Some v이고 내부 표현은 3이다.

  3. Nonneg.value v는 3이다. 외부에서는 추상 t와 int의 동일성을 공개하지 않았다.

None/Some v, value v=3이다. 외부에서 정수 3을 t에 직접 넣는 표현은 타입에 맞지 않는다.

종이와 본문으로 직접 해보기

make 0의 결과와 value는?

힌트 보기

조건은 n<0이다.

풀이 보기

Some v이며 value v=0이다. 경계 0은 허용한다.

오해와 반례

추상 타입으로 숨기면 유효성 검사가 필요 없다.

음수를 거르는 make의 구현이 없으면 불변식을 깨는 값도 내부에서 생성할 수 있다. 표현 숨김과 구현의 정확성은 별도다.

소단원 9.3

functor와 재사용

모듈에 다른 정책 모듈을 넣어 새 모듈을 만들면 무엇을 재사용할까?

준비 개념과 학습 목표

준비 개념

  • 모듈과 서명

  • 함수 적용

학습 목표

  • 모듈 매개변수와 값 매개변수를 구별한다.

  • 같은 구조에 다른 구현을 적용한다.

functor는 모듈을 받는 구조다

OCaml functor는 입력 모듈의 서명을 요구하고 그 모듈을 이용한 새 모듈을 만든다. 일반 int -> int 함수와 같은 층의 값 함수가 아니라 모듈 수준의 매개변수화다. 반복되는 구조에서 비교 정책이나 자료 표현의 차이를 입력으로 분리할 수 있다.

요구한 서명에 맞는 입력을 넣는다

아래 MakeScore는 weight : int를 가진 모듈을 받고 score 함수를 만든다. 입력이 weight를 없애거나 string으로 바꾸면 요구 서명에 맞지 않는다. 결과는 입력 P.weight를 쓰지만 입력 모듈을 임의로 바꾸는 명령은 아니다.

module type POLICY = sig val weight : int end
module MakeScore (P : POLICY) = struct
  let score n = P.weight * n
end
module Base = struct let weight = 2 end
module Other = struct let weight = 3 end
module A = MakeScore(Base)
module B = MakeScore(Other)

재사용에도 행동 조건이 있다

타입이 맞더라도 weight가 음수이면 점수의 의미가 달라질 수 있다. 필요한 범위·비교 법칙·예외 조건을 문서로 정한다. 실제 자료구조 functor에서는 입력 타입의 동일성이 외부에 필요한지도 별도로 검토한다. 이 예제는 int만 써 그 복잡한 문제를 피한다.

중간 과정을 따라가는 예제

기본 정책 weight=2와 별도 정책 weight=3을 MakeScore에 적용한다. 입력 n=4의 결과와 원래 weight 값을 구하라. 오버플로는 없다.

  1. 첫 score 4는 2×4=8이다.

  2. 두 번째 score 4는 3×4=12다.

  3. 두 입력 모듈의 정수 weight는 각각 2/3 그대로다. 같은 구조가 정책 값만 다르게 쓴다.

결과 8과 12이며 입력 정책은 변경되지 않는다.

종이와 본문으로 직접 해보기

첫 정책으로 score 5를 계산하면?

힌트 보기

같은 weight=2를 쓴다.

풀이 보기

2×5=10이다. 새로운 입력을 계산해도 정책 값은 2다.

오해와 반례

functor와 일반 함수는 같은 문법으로 서로 바꿔 쓸 수 있다.

개념적으로 입력과 출력이 있지만 모듈과 일반 값의 층이 다르다. MakeScore(Base)는 모듈 적용이고 score 4는 값 함수 적용이다.
