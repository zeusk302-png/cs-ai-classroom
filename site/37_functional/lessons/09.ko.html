소단원 9.1

signature·structure

모듈의 사용 설명서와 실제 구현은 무엇이 다를까?

준비 개념과 학습 목표

준비 개념

  • 함수 타입

  • 이름 공간

학습 목표

  • 서명의 명세와 구조의 정의를 구별한다.

  • 구현의 타입 일치를 확인한다.

함수 이름과 타입이 같으면 계산 규칙도 같을까요?

자체 module type STEP은 val step:int->int와 val twice:int->int를 공개한다. Small 내부는 shift=3, step x=x+shift, twice x=step(step x)로 정의하며 module Small:STEP으로 봉인한다. 이번 작은 정수 입력은 표현 범위를 넘지 않고 함수는 순수하게 종료한다. 기대 행동은 step이 3을 더하고 twice가 이를 두 번 적용하는 것이다.

signature는 공개되는 이름과 타입을 검사하지만 twice의 몸체가 두 번 적용인지 자동 증명하지 않는다. shift는 내부에서 사용할 수 있어도 STEP에 없으므로 Small.shift로 읽을 수 없다. 타입을 만족한다는 판정과 기대 행동을 만족한다는 판정을 별도 장부에 적는다.

open은 보이는 이름을 현재 범위에서 짧게 쓰게 한다. 봉인에 의해 숨은 항목을 다시 공개하지 않는다. 이 단원의 모듈은 클래스 인스턴스가 아니라 관련 정의의 묶음이다. 아래 각 비교는 독립적인 구현 선택이다.

먼저 확인할 개념
  • 구현 정의와 공개 타입 목록

    앞 본문의 Calc와 S를 사용해 정의를 담는 structure와 타입을 적는 signature를 구별한다.

  • 공개 경계와 내부 표현

    Nonneg의 추상 타입처럼 공개 경계가 내부 항목 사용을 제한한다는 원리를 helper 이름에도 적용한다.

structure는 정의들을 묶는다

OCaml structure는 값·함수·타입·예외 같은 관련 정의를 묶는 구현이다. module 이름을 붙여 M.f처럼 접근한다. 클래스의 인스턴스나 this를 가진 객체라고 해석하지 않는다. 모듈 정의의 앞 이름은 뒤 정의에서 쓸 수 있다.

signature는 공개할 이름과 타입을 적는다

sig ... end는 구현이 제공할 명세의 모음이다. val inc : int -> int는 inc를 실행하는 문장이 아니라 함수 타입을 요구한다. module type은 서명에 이름을 붙이며 module의 : S는 필요한 이름/타입 일치와 외부 공개 범위를 제한한다.

module type S = sig
  val inc : int -> int
  val twice : int -> int
end
module Calc : S = struct
  let inc x = x + 1
  let twice x = inc (inc x)
end

타입 일치와 행동 약속을 구별한다

서명의 int -> int만으로 inc가 반드시 1을 더한다는 의미까지 증명하지는 않는다. 사전조건·결과 약속·예외·복잡도도 문서와 별도 검증으로 정한다. 필요한 값이 빠지거나 int 대신 string을 반환하는 구현은 같은 서명에 맞지 않는다.

중간 과정을 따라가는 예제

아래 모듈의 공개 inc와 twice를 이용해 Calc.twice 3을 구하라. 정수 범위를 넘지 않는다.

  1. inc 3은 3+1=4다.

  2. twice 3은 inc(inc 3)으로 inc 4다.

  3. 4+1=5이며 이름의 twice는 호출을 두 번 한다는 뜻이다.

결과 5다. 숫자를 두 배인 6으로 만드는 함수가 아니다.

조건을 바꾸어 비교하기

봉인 뒤에도 내부 helper를 사용하는 계산

Small:STEP의 step과 twice를 위 정의대로 둔다. Small.twice 4, Small.shift와 open Small 뒤 shift의 사용 가능성을 판정하라.

  1. 내부 step 4는 7이고 step 7은 10이다.

  2. STEP에는 shift가 없어 외부 Small.shift는 보이지 않는다.

  3. open Small도 STEP에 보이는 두 함수만 범위에 넣으므로 shift를 복구하지 않는다.

정상 계산 결과는 10이다. 두 외부 shift 접근은 공개 이름이 없어 거절 대상이다.

비교할 점

앞 본문의 S 적합성에서 한 걸음 더 나아가 구현 내부 사용과 봉인 뒤 외부 사용의 범위를 나눈다.

타입 검사에서 살아남는 잘못된 twice

새 독립 후보 B는 step x=x+3이나 twice x=2*x다. 입력 0과 4를 정상 A와 비교하라.

  1. B의 두 함수는 모두 int->int라 STEP 이름/타입 조건을 만족한다.

  2. A는 입력 0에서 6, 입력 4에서 10이다. B는 각각 0과 8이다.

  3. 입출력 비교는 두 번 적용이라는 별도 행동 요구를 검사한다.

타입은 맞아도 두 입력 모두 행동 반례다.

비교할 점

이름 누락/타입 불일치는 signature가 잡지만 적절한 정수 반환의 잘못된 수식은 추가 검사가 필요하다.

연습 1 · 값과 상태 예측

Small:STEP에 공개된 step 1과 twice 1을 손계산한다. 별도 Bad:STEP는 step만 정의하고 twice를 누락한다. 세 결과를 구별하라.

힌트 1

step은 3을 더한다.

힌트 2

누락된 이름은 0을 반환하는 함수가 아니다.

풀이와 답 확인

  1. Small.step 1은 4다. Small.twice 1은 4에 다시 3을 더한 7이다.

  2. Bad는 요구 항목 twice가 없어 signature 적합성에서 거절된다.

정상 값은 4와 7이며 Bad는 모듈 적합성 실패다.

흔한 오답에서 다시 생각하기

Bad.twice는 정의가 없으니 기본값 0이다.

공개 요구를 누락하면 실행을 예측하기 전에 타입 경계에서 실패한다.

연습 2 · 오류 찾아 고치기

sealed Small의 shift를 얻으려고 open Small을 넣었다. 왜 실패하며 shift를 공개하지 않고 외부에서 같은 의미의 두 번 적용을 만드는가?

힌트 1

open은 경계를 통과하는 권한 확대가 아니다.

힌트 2

공개 step을 합성할 수 있다.

풀이와 답 확인

  1. shift는 STEP에 없는 내부 이름이라 open 이후에도 보이지 않는다.

  2. 외부 함수 client_twice x=Small.step(Small.step x)를 사용한다.

  3. 입력 4의 중간 값은 7, 결과는 10이다.

공개 함수 합성으로 목적을 달성하고 내부 항목에 의존하지 않는다.

흔한 오답에서 다시 생각하기

open을 두 번 하면 숨은 이름까지 공개된다.

open 횟수는 signature의 항목 목록을 바꾸지 않는다.

연습 3 · 직접 만들어 보기

타입 검사와 행동 검사를 나눈 검토표를 만든다. 후보 A/B/C에 입력 0의 기대 결과 6을 적용하라.

힌트 1

먼저 두 이름과 int 반환을 검사한다.

힌트 2

적합한 후보에만 행동 결과를 비교한다.

풀이와 답 확인

  1. A/B는 타입 적합, C는 twice의 string 반환 때문에 부적합으로 기록한다.

  2. 행동 검사에서 A의 6은 기대와 같고 B의 0은 다르다.

  3. C를 행동 성공이나 실패의 실행 기록으로 꾸미지 않는다.

A는 두 기준 통과, B는 타입 통과/행동 실패, C는 타입 실패다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

Raw는 shift와 step을 모두 공개한 미봉인 구조다. module Checked: sig val step:int->int end=Raw로 새 이름만 봉인했다. Raw.shift와 Checked.shift는 각각 어떻게 되는가?

힌트 1

새 별칭의 공개 경계와 원래 경계를 따로 본다.

힌트 2

봉인이 과거 이름을 삭제하는지 묻는다.

풀이와 답 확인

  1. Raw의 기존 공개 shift는 계속 사용 가능하다.

  2. Checked.shift는 새 경계에 없어 보이지 않는다.

  3. 전체 프로젝트에서 helper 의존을 막으려면 Raw를 계속 배포하는 문제도 검토해야 한다.

Checked만 봉인해도 Raw 경로의 helper는 사라지지 않는다.

소단원 9.2

정보은닉

내부에서 정수로 저장한다고 사용자가 직접 정수를 넣어도 될까?

준비 개념과 학습 목표

준비 개념

  • 모듈 서명

  • 사전조건

학습 목표

  • 추상 타입의 표현 숨김을 설명한다.

  • 공개 연산을 통해 불변식을 보존한다.

구간을 두 정수로 저장하는 대신 시작과 폭으로 바꿔도 사용자는 같은 답을 얻을까요?

자체 INTERVAL은 type t, make:int->int->t option, contains:t->int->bool를 공개한다. make lo hi는 lo≤hi일 때만 성공하며 양 끝을 포함한 구간을 뜻한다. 내부 표현 A는 (lo,hi), 표현 B는 (lo,width)이고 width=hi−lo다. 이 단원은 폭 계산이 표현 가능하다고 명시한 작은 값만 추적한다.

표현 불변식은 A에서 lo≤hi, B에서 width≥0이다. 추상 의미는 A의 [lo,hi]와 B의 [lo,lo+width]다. type t가 봉인되면 사용자는 마음대로 정수 쌍을 t로 넣거나 패턴 매칭할 수 없으며 공개 make와 contains를 사용한다.

숨김은 올바른 구현을 대신하지 않는다. B가 contains의 상한을 width 자체로 비교하면 타입은 같아도 시작이 0이 아닌 구간에서 틀린다. 거절된 make는 기존 불변 값을 바꾸지 않으며 option의 None은 실패 결과다.

먼저 확인할 개념
  • 추상 타입과 생성자 검증

    Nonneg.make가 음수를 거절하는 원리를 lo≤hi 관계 검사로 확장한다.

  • signature의 타입 적합 범위

    같은 contains 타입을 만족하는 올바른/잘못된 몸체의 차이를 공개 행동 검사로 확인한다.

표현은 내부의 선택이다

서명에 type t라고만 적으면 이름은 공개하지만 표현의 동일성을 숨긴다. 내부 type t=int여도 외부 코드가 t를 int로 취급할 근거는 없다. 서명에 type t=int를 공개하는 설계와 구별한다. 정보은닉은 암호화나 보안 권한의 자동 보장이 아니다.

유효한 값의 생성 경로를 정한다

아래 Nonneg는 음수가 아닌 정수를 담는다. make는 음수이면 None, 아니면 Some 값을 반환하며 value만 정수 관찰을 허용한다. 사용자에게 임의 표현값을 만드는 연산을 공개하지 않아 불변식 훼손 경로를 줄인다.

module type NONNEG = sig
  type t
  val make : int -> t option
  val value : t -> int
end
module Nonneg : NONNEG = struct
  type t = int
  let make n = if n < 0 then None else Some n
  let value n = n
end

표현 변경과 행동 호환을 함께 본다

functor와 재사용

모듈에 다른 정책 모듈을 넣어 새 모듈을 만들면 무엇을 재사용할까?

준비 개념과 학습 목표

준비 개념

  • 모듈과 서명

  • 함수 적용

학습 목표

  • 모듈 매개변수와 값 매개변수를 구별한다.

  • 같은 구조에 다른 구현을 적용한다.

같은 선택기를 다른 순서 정책으로 만들면 자료도 자동 복사되고 비교 법칙도 증명될까요?

자체 ORDER는 val cmp:int->int->int를 공개한다. MakePick(O:ORDER)는 공개 pick:int list->int option만 가진 결과 모듈을 만든다. 빈 목록은 None, 비빈 목록은 첫 값을 현재 후보로 잡고 다음 x마다 O.cmp current x≤0이면 현재 후보를 유지하고, 아니면 x로 바꾼다. 비교가 0이면 먼저 나타난 후보를 유지한다. 작은 정수 비교는 직접 대소 관계를 써서 빼기 overflow를 피한다.

Asc는 수의 오름차순, Desc는 내림차순 비교다. pick은 각 정책상 가장 앞서는 값을 고르므로 Asc에서는 최솟값, Desc에서는 최댓값이 된다. functor 입력/출력은 모듈이며 목록은 결과 모듈의 pick에 주는 값 인수다. 입력 O의 모든 항목이 결과에 자동 공개되는 것은 아니다.

cmp의 타입만으로 자기 비교 0·반대 방향의 부호·추이성이나 문서의 수치 순서를 보장하지 않는다. 아래 Bad는 3이 1보다 앞서고, 1이 2보다 앞서고, 2가 3보다 앞서는 순환 비교를 쓴다. 각 숫자 자기 비교는 0, 역방향은 반대 부호다. 순수하지만 추이성이 깨져 입력 순서에 따른 결과 차이를 손추적한다.

먼저 확인할 개념
  • 모듈 인수와 결과 모듈

    MakeScore의 정책별 재사용을 값 변환 함수가 아닌 모듈 매개화의 층으로 이해한다.

  • 타입 요구와 행동 문서

    cmp 타입 만족만으로 순서 법칙을 증명하지 못함을 STEP의 행동 오류와 연결한다.

functor는 모듈을 받는 구조다

OCaml functor는 입력 모듈의 서명을 요구하고 그 모듈을 이용한 새 모듈을 만든다. 일반 int -> int 함수와 같은 층의 값 함수가 아니라 모듈 수준의 매개변수화다. 반복되는 구조에서 비교 정책이나 자료 표현의 차이를 입력으로 분리할 수 있다.

요구한 서명에 맞는 입력을 넣는다

아래 MakeScore는 weight : int를 가진 모듈을 받고 score 함수를 만든다. 입력이 weight를 없애거나 string으로 바꾸면 요구 서명에 맞지 않는다. 결과는 입력 P.weight를 쓰지만 입력 모듈을 임의로 바꾸는 명령은 아니다.

module type POLICY = sig val weight : int end
module MakeScore (P : POLICY) = struct
  let score n = P.weight * n
end
module Base = struct let weight = 2 end
module Other = struct let weight = 3 end
module A = MakeScore(Base)
module B = MakeScore(Other)

재사용에도 행동 조건이 있다

타입이 맞더라도 weight가 음수이면 점수의 의미가 달라질 수 있다. 필요한 범위·비교 법칙·예외 조건을 문서로 정한다. 실제 자료구조 functor에서는 입력 타입의 동일성이 외부에 필요한지도 별도로 검토한다. 이 예제는 int만 써 그 복잡한 문제를 피한다.

기본 정책 weight=2와 별도 정책 weight=3을 MakeScore에 적용한다. 입력 n=4의 결과와 원래 weight 값을 구하라. 오버플로는 없다.

  1. 첫 score 4는 2×4=8이다.

  2. 두 번째 score 4는 3×4=12다.

  3. 두 입력 모듈의 정수 weight는 각각 2/3 그대로다. 같은 구조가 정책 값만 다르게 쓴다.

결과 8과 12이며 입력 정책은 변경되지 않는다.

조건을 바꾸어 비교하기

코드 하나와 두 순서 정책

A=MakePick(Asc), D=MakePick(Desc)에서 pick [3,1,2]와 pick []를 예측하라.

  1. A는 후보 3→1→1로 Some 1이다.

  2. D는 후보 3→3→3으로 Some 3이다.

  3. 두 결과 모듈의 빈 입력은 비교하지 않고 None이다.

같은 선택 구조지만 정책에 따라 값 1과 3이 선택된다.

비교할 점

앞 본문의 가중치 곱셈에서 제어 흐름에 영향을 주는 비교 정책으로 매개화를 확장한다.

타입은 맞아도 순환하는 비교

Bad의 순서 3≺1,1≺2,2≺3을 사용한다. 목록 [3,1,2]와 [1,2,3]의 pick을 구하라.

  1. 첫 목록은 3이 1보다 앞서 유지되고 2가 3보다 앞서 최종 2다.

  2. 둘째는 1이 2보다 앞서 유지되고 3이 1보다 앞서 최종 3이다.

  3. 같은 세 값의 재배열만으로 결과가 달라지며 비교 타입은 두 경우 모두 int->int->int다.

Some 2와 Some 3으로 달라진다.

연습 1 · 값과 상태 예측

새 Asc/Desc 모듈에서 pick [2,2,1]의 후보 변화와 이 모형의 cmp 호출 수를 예측하라.

힌트 1

첫 값은 비교 없이 후보다.

힌트 2

동률에서 현재 후보를 유지한다.

풀이와 답 확인

  1. Asc는 후보 2→2→1, Desc는 2→2→2다.

  2. 각 목록은 뒤의 두 항목에 각각 한 번씩 cmp를 적용한다.

Asc 결과 Some 1, Desc 결과 Some 2이며 각 비교는 2회다.

흔한 오답에서 다시 생각하기

동률도 탈락이므로 앞의 2가 무조건 삭제된다.

규약은 cmp=0일 때 현재 후보 유지다. 값만으로 동률의 신원을 구별할 수 없으므로 임의 ID 효과도 주장하지 않는다.

연습 2 · 오류 찾아 고치기

MakePick 결과는 pick만 정의한다. A.cmp를 호출해 내부 비교를 시험하려 한다. 왜 실패하며 어디를 검사해야 하는가?

힌트 1

functor 결과 정의에 입력 항목을 복사했는지 확인한다.

힌트 2

입력 Asc와 결과 A의 경계를 구별한다.

풀이와 답 확인

  1. A에는 pick만 정의되어 A.cmp는 공개되지 않는다.

  2. Asc가 cmp를 공개하므로 Asc.cmp 자체의 법칙을 별도 검사할 수 있다.

  3. A.pick의 빈 입력/동률/후보 변화를 그다음 검사한다.

입력 정책의 공개 경로와 출력 모듈의 공개 경로를 구별한다.

흔한 오답에서 다시 생각하기

모듈을 받았으니 입력의 이름이 결과에 모두 상속된다.

functor는 작성된 결과 구조를 만들며 입력 항목 전체를 자동 상속하지 않는다.

연습 3 · 직접 만들어 보기

Bad 비교의 추이성 실패를 숫자 셋으로 쓰고 올바른 Asc의 cmp를 빼기 없이 설계하라.

힌트 1

3≺1과 1≺2를 합치면 무엇이 필요할까?

힌트 2

if a<b then −1 else if a>b then 1 else 0을 사용할 수 있다.

풀이와 답 확인

  1. Bad는 3≺1,1≺2지만 3≺2가 아니라 2≺3이어서 추이성이 실패한다.

  2. Asc는 직접 대소 비교로 음수/양수/0을 반환해 정수 뺄셈 overflow를 피한다.

  3. 입력 목록 처리 코드와 비교 법칙 검토를 각각 보존한다.

세 값 반례와 수치 오름차순 비교 설계를 별도 제시한다.

흔한 오답에서 다시 생각하기

a−b를 쓰면 어떤 int에서도 항상 올바른 부호다.

기계 정수 차이의 overflow 가능성은 타입이나 functor가 없애지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

정상 순서 정책에서 길이 n인 목록의 cmp 호출 수를 구하라. 반환 값 int만 보이는 계약에서 동률 원소의 객체 신원/정렬된 전체 목록도 보장되는가?

힌트 1

첫 후보를 고를 때 비교하지 않는다.

힌트 2

반환 형태는 int option 하나다.

풀이와 답 확인

  1. n=0이면 비교 0회, n>0이면 n−1회다.

  2. 반환 계약은 선택 값 하나이며 전체 정렬 결과를 만들지 않는다.

  3. 동률 유지의 내부 규칙이 있어도 int만 반환하므로 서로 같은 값의 객체 신원은 이 인터페이스의 관찰이 아니다.

비교 횟수와 출력 의미를 분리하고 실제 시간/전체 정렬/객체 신원을 확대 주장하지 않는다.

흔한 오답에서 다시 생각하기

비교 정책 모듈을 쓰면 목록 전체가 정렬된다.

pick은 후보 하나만 갱신한다. 정렬 자료를 출력하는 연산은 정의되지 않았다.

같은 함수 타입의 비교기를 안전하게 교체하려면?

다른 문제에 적용하기

숨은 구간과 공개 선택 정책을 함께 검토하기

새 INTERVAL의 올바른 make/contains만 사용하는 클라이언트다. make 4 9가 Some r일 때 [3,7,10,4] 중 contains r x가 참인 값을 원래 순서대로 모은다. 그 목록을 Asc와 Desc의 MakePick 결과에 각각 전달한다. 내부 표현 A=(lo,hi)를 B=(lo,width)로 바꿔도 같은 관찰인가? 별도 잘못된 B는 contains 상한을 width로 비교한다. 잘못된 B의 필터 목록과 두 선택 값도 구하라. 공개 signature의 이름/타입만으로 어느 오류를 판정할 수 있는지 설명하라. 모든 산술은 작은 정수로 표현 가능하며 실제 OCaml 실행은 요구하지 않는다.

힌트 1

정상 상한은 9이고 잘못된 B의 상한은 폭 5다.

힌트 2

목록의 원래 순서를 유지한 뒤 두 순서 정책을 적용한다.

풀이와 답 확인

  1. 정상 A는 (4,9), 정상 B는 (4,5)이며 두 경우 필터 목록은 [7,4]다.

  2. Asc는 후보 7에서 4로 바뀌어 Some 4, Desc는 7을 유지해 Some 7이다.

  3. 잘못된 B는 4≤x≤5를 검사하므로 목록은 [4]다. 두 정책 모두 Some 4를 반환한다.

  4. 두 구현의 signature 이름과 타입은 모두 맞을 수 있다. 정상 B와 A의 의미 대응은 행동 검사로 확인하고 잘못된 B의 x=7을 반례로 쓴다.

  5. 외부 클라이언트는 봉인된 t를 직접 쌍으로 해체하지 않는다. MakePick 결과의 pick과 입력 정책 cmp의 공개 범위를 나눈다.

정상 두 표현은 [7,4]를 만들며 Asc는 Some 4, Desc는 Some 7이다. 잘못된 B는 [4]를 만들어 두 결과가 Some 4다. 타입 적합성은 상한 행동 오류를 자동 거절하지 않는다. 내부 표현/모듈 경계와 별도 행동 검사를 함께 검토한다.
