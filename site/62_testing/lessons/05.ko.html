소단원 5.1

입력생성

입력을 자동으로 많이 만들면 스스로 무엇이 틀렸는지도 알아낼까?

준비 개념과 학습 목표

준비 개념

  • 함수의 정의역

  • 정수 목록

  • 검사 조건

학습 목표

  • 생성 규칙과 판정 속성의 역할을 구별한다.

  • 경계·중복·제약을 포함하는 입력 집합을 설계한다.

유효한 쌍만 만들면 모든 유효한 쌍을 같은 비중으로 보게 될까?

자체 생성 모형에서 a와 b를 각각 {0,1,2}에서 독립적으로 같은 확률로 고른다. 원래 순서쌍은 아홉 개다. 이를 (min(a,b),max(a,b))로 바꾸면 a≤b를 항상 만족하지만 (0,1)은 원래 (0,1)과 (1,0) 두 경우에서, (0,0)은 한 경우에서 나온다. 결과의 정의역과 선택 비중은 다른 질문이다.

출력 가능한 유효 쌍은 여섯 개다. 대각선 세 쌍의 확률은 각각 1/9, 비대각선 세 쌍은 각각 2/9다. 여섯 쌍을 직접 같은 확률로 고르는 규칙의 1/6과 다르다. 이 계산은 지정한 작은 독립 균등 선택 모형의 결과이며 Hypothesis가 이렇게 표본을 고른다는 주장이 아니다.

생성 후 아무 검사 없이 return한 사례와 제약 때문에 명시적으로 버린 사례도 구별한다. 정상 영역만 시험하려는 계약의 필터와 잘못된 입력의 오류 처리를 확인하는 계약은 별도다. 무한히 많은 실행도 생성기 밖의 반례를 발견할 수는 없다.

먼저 확인할 개념
  • 계약의 정의역과 분할

    유효 입력 전체와 시험한 대표를 구별한다.

  • 검사와 실제 통과의 근거

    조건을 검사하지 않은 방문을 정확성의 근거로 쓰지 않는다.

예제 하나에서 입력의 가족으로

속성 기반 테스트는 입력 생성 규칙과 그 입력에서 만족해야 할 성질을 함께 사용한다. 예를 들어 정수 목록 정렬은 빈 목록, 한 항목, 중복과 음수를 포함해 생각할 수 있다. 생성기가 목록을 만들더라도 어떤 출력이 올바른지는 계약이나 별도의 판정 규칙으로 정해야 한다.

생성기는 난수를 이용할 수도 있고 구조를 조합하거나 경계 사례를 먼저 선택할 수도 있다. 무작위라는 단어가 모든 입력을 같은 확률로 고르거나 모든 입력을 결국 반드시 실행한다는 뜻은 아니다. 실행 횟수와 생성 가능한 집합, 실제로 방문한 사례는 서로 다른 정보다.

작은 정의역을 전부 세어 보기

자체 종이 모형에서는 각 원소가 −1,0,1 이고 길이가 0,1,2 인 목록만 만든다. 길이 0 은 [] 하나, 길이 1 은 3 개, 길이 2 는 3×3=9 개이므로 합 13 개다. [−1,1]과 [1,−1]은 순서가 다르므로 별개이며 [1,1] 같은 중복도 허용한다.

길이 2 중 앞 값이 뒤 값보다 큰 목록은 [0,−1],[1,−1],[1,0]의 3 개다. 이를 거꾸로 된 순서 사례로 기록할 수 있지만 나머지가 모두 충분히 검사되었다는 뜻은 아니다. 빈 목록에서 예외가 생기는 구현과 중복을 잃는 구현은 다른 입력 가족이 필요하다.

정상 입력과 잘못된 입력을 분리하기

정의역이 정수 목록이라면 문자열이나 실수를 생성하지 않는 것이 정상 계약 검사의 조건이다. 잘못된 타입을 받았을 때 정해진 오류를 내는지도 별도 속성으로 검사할 수 있다. 잘못된 입력을 조용히 버리면 정상 검사의 실패 수와 오류 검사의 의미를 섞게 된다.

조건을 만족할 때까지 대량으로 버리는 전략은 실제 유효 사례가 거의 없게 할 수 있다. a≤b인 쌍을 원한다면 두 값을 만든 뒤 작은 것과 큰 것으로 구성하는 방식도 생각할 수 있다. 다만 이는 분포와 중복 확률을 바꾸므로 이 방식이 균일한 유효쌍 선택이라고 주장하지 않는다.

중간 과정을 따라가는 예제

원소 집합 {−1,0,1},길이 0~2 의 모든 목록 수와 길이 2 의 감소쌍을 계산하라. 원소 중복이 금지되면 전체 수는?

  1. 길이 0 은 빈 목록 하나다.

  2. 길이 1 은 원소 3 개를 각각 고르므로 3 개다.

  3. 길이 2 는 독립 선택 3×3=9 개다. 순서를 구분한다.

  4. 전체 13 개이며 감소쌍은 [0,−1],[1,−1],[1,0]의 3 개다.

  5. 중복을 금지하면 길이 2 는 3×2=6 개라 전체 1+3+6=10 개다.

중복 허용 13 개,금지 10 개다. 두 생성 규칙의 범위가 다르다.

소단원 5.2

invariant·metamorphic relation

출력의 정확한 정답을 모를 때도 무엇을 반드시 확인할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 불변식

  • 목록의 다중집합

  • 입력 변환

학습 목표

  • 한 실행의 불변 성질과 여러 실행의 관계를 구별한다.

  • 약한 속성을 통과하는 잘못된 구현을 찾는다.

이동과 순열 관계를 모두 통과해도 평균이 틀릴 수 있을까?

정확한 유리수의 비어 있지 않은 목록에서 평균 M을 정의하자. 자체 잘못된 함수 G(x)=M(x)+1은 모든 원소에 k를 더하면 G(x+k)=G(x)+k를 만족한다. 입력 순서를 바꾸어도 평균이 같아 G도 같다. 두 관계를 모두 통과해도 값에 붙은 상수 오류는 남는다.

[2,6]의 평균은 4인데 G는 5다. 모두 3을 더한 [5,9]의 G는 8이고 8=5+3이라 이동 관계는 맞다. 역순 [6,2]에서도 G는 5라 순열 관계도 맞다. 관계는 출력 사이 일관성을 묻지만 그 일관된 출력의 절대 기준까지 자동 고정하지 않는다.

원소 하나의 목록 [a]에서 결과가 a여야 한다는 계약의 기준점은 G([2])=3을 배제한다. 그렇다고 이 기준점과 두 관계의 표본 통과가 모든 함수의 정확성 증명인 것은 아니다. 정수 정렬에서 길이·순서·값별 개수가 모두 정확하면 계약을 결정할 수 있는 경우와 제한된 표본만 검사한 경우도 나누어 읽는다.

불변 성질을 계약에서 뽑기

이 단원에서 invariant는 모든 허용 사례나 상태 변화에서 유지해야 할 성질을 뜻한다. 정수 정렬 출력은 비감소 순서여야 하고 입력의 각 값의 개수도 보존해야 한다. 길이만 같다고 원소가 같아지는 것은 아니므로 값별 개수를 포함하는 다중집합을 확인한다.

출력=[]을 언제나 돌려주는 잘못된 구현도 비감소 순서 조건은 통과한다. 빈 목록에는 순서를 거스를 이웃이 없기 때문이다. 서로 독립인 성질을 결합하면 이런 허점을 줄일 수 있지만 일부 표본 통과가 모든 입력의 증명이 되는 것은 아니다.

변환한 입력과 결과의 관계

metamorphic relation은 원래 입력과 의미를 보존하거나 예측 가능하게 바꾼 후속 입력의 출력 사이 관계다. 정수 목록의 순서를 섞어도 정렬한 최종 값 목록은 같아야 한다. 모든 원소에 정수 k를 더하면 정렬 출력의 모든 원소에도 k를 더한 것과 같아야 한다.

두 번째 관계는 정수의 정확한 덧셈과 비교라는 자체 모형에서 성립한다. 고정폭 overflow, NaN, 부동소수점 반올림이 있는 경우에는 같은 전제를 그대로 적용하면 안 된다. 입력 변환이 여전히 정의역에 있는지와 계약이 정말 관계를 보장하는지 먼저 따진다.

관계도 모든 오류를 잡지는 못한다

평균 함수에 모든 값을 k만큼 더하면 비어 있지 않은 정확한 수의 목록에서는 평균이 k만큼 증가한다. 예컨대 [1,3,5] 평균 3 과 [3,5,7] 평균 5 의 차이는 2 다. 빈 목록은 평균 정의가 없으므로 별도 오류 계약을 쓴다.

그러나 항상 평균 대신 첫 원소를 반환하는 구현도 모든 원소에 k를 더하는 관계를 통과한다. 관계 하나로 평균임을 확정할 수 없는 반례다. 순열 불변 관계에서는 [1,3,5]와[5,3,1]의 첫 값이 달라 실패한다. 선택한 속성의 발견 범위를 함께 기록해야 한다.

metamorphic relation 하나를 통과하면 함수가 완전히 옳다.

shrinking과 실패재현

길고 복잡한 실패 입력에서 원인을 드러내는 작은 사례를 어떻게 남길까?

준비 개념과 학습 목표

준비 개념

  • 실패 판정

  • 목록 부분 삭제

  • 버전과 실행 조건

학습 목표

  • 실패를 유지하며 입력을 단순화한다.

  • 작은 반례·최소 주장·재현 조건을 구별한다.

한 단계도 줄이지 못한 실패가 전역 최소일까?

자체 정수 실패 판정은 n이 9 또는 4일 때만 실패하고 다른 비음수 정수에서는 통과한다고 정한다. 축소 규칙이 현재 n에서 n−1 하나만 후보로 만든다면 9의 후보 8은 통과한다. 실패만 채택하는 탐색은 9에서 멈추지만 더 작은 실패 4가 존재한다.

이 예는 어떤 실제 shrinker의 알고리즘을 표현하지 않는다. 지정한 후보 그래프의 한 단계에서 막힌 국소 결과와 전체 정의역의 최소를 구별하기 위한 모형이다. 후보를 여러 개 제시하거나 경로를 바꾸면 다른 작은 실패를 찾을 수 있다. 모든 실패가 같은 근본 원인이라는 보장도 없으므로 실패한 속성과 현상을 함께 기록한다.

재현에는 구체 입력·속성·구현과 도구 버전·설정·초기 상태가 필요하다. 명시 example과 임시 재현 blob은 역할과 버전 제약이 다르다. 양의 정수 계약을 줄이다 0에서 예외가 난 것은 원래 정상 영역의 속성 실패를 유지한 증거가 아니다.

    입력 외에 시험 사이 공유 상태도 재현 조건에 넣는다.

실패를 유지하는 단순화

shrinking은 이미 실패한 사례에서 더 단순한 후보를 만들고 같은 실패가 유지되는지 확인하는 과정이다. 목록의 일부를 제거하거나 값을 더 간단하게 바꿀 수 있다. 후보가 통과하면 그 후보를 실패 증거로 대체하지 않는다. 정상 입력의 제약도 유지해야 한다.

어떤 크기 순서를 쓰는지에 따라 단순함이 달라진다. 길이를 먼저 줄이고 값의 절댓값을 줄이는 자체 규칙과 다른 도구의 탐색 순서는 같지 않을 수 있다. 도구가 찾은 작은 반례를 모든 가능한 후보 중 전역 최소라고 무조건 주장하지 않는다.

자체 중복 손실 사례

잘못된 정렬 U는 중복을 하나만 남기고 정렬한다고 정한다. 속성은 입력 다중집합 보존이다. [8,4,8,1]의 출력 [1,4,8]은 8 하나를 잃어 실패한다. 후보[8,8]도 실패하지만[8]은 통과한다. 길이 2 가 중복 손실을 드러내는 데 필요하다는 사실을 알 수 있다.

값을[0,0]으로 바꾸면 U의 출력 [0]이라 여전히 실패한다. 이 사례는 원인을 더 쉽게 설명한다. 하지만 여기서는 제시한 경로를 종이로 판정한 것이며 실제 Hypothesis가 이 입력을 반드시 찾는다고 기록하지 않는다. 버그가 다른 원인으로 바뀌었다면 같은 실패인지도 다시 확인한다.

실패 입력과 주변 조건을 함께 보관하기

저장한 구체 입력 [0,0]과 검사한 속성, 코드 버전·도구 버전·설정·초기 상태를 함께 남긴다. 난수 seed만 기록하면 생성기 변경이나 호출 순서 차이 때문에 같은 입력을 못 만들 수 있다. 외부 파일이나 시간에 의존한 실패는 그 조건도 고정해야 한다.

Hypothesis의 database는 반복 작업을 돕지만 업그레이드나 테스트 변경으로 재사용이 달라질 수 있다. 명시 예제를 회귀 검사로 남기는 방법과 임시 failure blob의 버전 조건을 구별한다. 공식 문서의 명시 example은 자동 shrink 대상이 아니라는 차이도 확인했다. 이 원고에서는 도구를 설치하거나 실제 회귀 테스트를 실행하지 않았다.
