소단원 3.1

statement·branch coverage

모든 실행문을 한 번씩 지나갔는데도, 한 조건의 거짓 방향은 놓칠 수 있을까?

준비 개념과 학습 목표

준비 개념

  • coverage는 정한 대상 집합 중 시험에서 방문한 서로 다른 대상의 비율이다. 같은 대상을 열 번 방문해도 대상 수는 하나다.

  • 제어 흐름은 다음에 어느 지점으로 이동하는지를 나타낸다. if의 참·거짓 결과는 서로 다른 방향이며 입력과 기대 결과도 함께 확인해야 한다.

  • 이 단원의 분모는 교육용으로 지정한 S 실행문과 D의 참·거짓 결과다. 함수 선언·조건 머리·호출 사이트는 S 분모에 넣지 않으며 실제 계측 도구의 line coverage와 구별한다.

학습 목표

  • 실행문과 분기의 분모를 먼저 적는다.

  • 단락이 없는 작은 제어 흐름을 종이로 추적한다.

  • 방문한 것과 결과가 맞는 것을 별도로 기록한다.

시험을 합칠 때 퍼센트를 평균하면 방문한 항목도 맞게 셀까?

자체 판정 모형의 실행문은 S1 초기화, S2 참일 때 대입, S3 반환의 세 개다. 결정 D의 참·거짓 방향 두 개를 별도 분모로 둔다. 참인 입력은 세 문장을, 거짓인 입력은 S1과 S3를 방문한다. 실행문 분모에 조건 머리·함수 선언·호출 사이트는 넣지 않는 교육 정의다.

참 시험의 문장 비율 3/3과 거짓 시험의 2/3을 평균하면 5/6이지만 합친 방문 집합은 세 문장을 모두 포함하므로 3/3이다. 방문 비율은 시험마다 얻은 백분율의 평균이 아니라 같은 버전의 고유 항목 합집합에서 계산한다.

실제 Coverage.py는 줄 사이 이동과 실행 기회를 계측하며 파일의 전체 비율에는 문장과 분기 기회를 함께 반영한다. 이 교육용 S/D 비율을 도구의 실제 보고서 숫자로 대체하지 않는다. 현재 활동은 손 추적이며 계측 실행은 하지 않았다.

먼저 확인할 개념
  • 상태·전이의 고유 항목

    같은 항목의 반복을 분자에 여러 번 넣지 않는다.

  • 결과 판정의 독립 근거

    방문과 요구 결과의 일치를 따로 기록한다.

먼저 무엇을 셀지 약속한다

문장 커버리지는 미리 정한 실행문 중 적어도 한 시험에서 실행한 문장의 비율이다. 여기서는 S1·S2·S3라는 세 실행문만 세므로 분모는 3이다. 여러 줄짜리 문장, 한 줄에 여러 문장, 도구가 제외한 구간이 있는 실제 코드에서는 줄 수와 문장 수가 다를 수 있다. 숫자를 적기 전에 도구·대상·제외 정책을 함께 적는다.

분기 커버리지는 정한 결정 D가 낼 수 있는 참·거짓 방향 중 시험에서 실제로 따른 방향의 비율이다. 아래 D 하나의 분모는 2다. 도구는 줄 사이 이동이나 예외·switch 등의 다른 분기 모델을 사용할 수 있으므로 여기의 단순 비율을 실측 보고서의 총 퍼센트로 바꾸지 않는다.

같은 문장 방문, 다른 조건 결과

자체 함수 flag는 정수 x에 대해 x>0이면 1, 그 밖이면 0을 반환한다. S1에서 y=0으로 초기화하고 D에서 x>0을 검사해 참일 때만 S2의 y=1을 실행하며 S3에서 y를 반환한다. 거짓 방향에 별도 대입문이 없어도 D→S3라는 다른 방향은 존재한다.

x=2 한 사례는 S1/S2/S3를 모두 지나지만 D의 참 방향만 따른다. 따라서 지정 문장 기준 3/3=100%와 분기 기준 1/2=50%가 동시에 가능하다. 문장 한 칸에 방문 표시를 했다는 사실과 그 문장의 모든 진입·출구를 살폈다는 주장을 구분한다.

S1: y = 0
D:  if x > 0:
S2:     y = 1
S3: return y
# 종이 모형의 지점 이름이다. 그대로 실행할 Python 소스가 아니다.

누적 집합과 명세를 함께 확인한다

x=0을 추가하면 S1→D거짓→S3를 지나 결과 0이다. 두 시험의 방문 집합은 S1/S2/S3이고 방향 집합은 D참/D거짓이다. 비율은 각 시험의 퍼센트를 평균하는 대신 방문 집합의 합집합으로 계산한다. 첫 시험 50%, 둘째 50%를 평균해 전체 50%라 하면 서로 다른 방향을 덮은 사실을 잃는다.

본문은 가능한 방문을 종이로 예측한다. 실제 계측을 켜서 프로그램을 실행하지 않았으므로 실측 커버리지를 달성했다고 기록하지 않는다. 실행하더라도 입력별 기대 결과와 실제 결과의 일치, 종료·예외 여부를 함께 남겨야 하며 도구의 방문 색만으로 요구 만족을 판정하지 않는다.

교육용 S/D 대상에서 두 시험의 고유 방문 집합
시험문장 집합방향 집합

참 입력

S1,S2,S3

D참

거짓 입력

S1,S3

D거짓

둘의 합집합

S1,S2,S3

D참,D거짓

S의 분모는 3, 방향의 분모는 2다. 각 집합에는 같은 대상을 한 번만 적는다. 실제 계측 도구의 줄 수나 제외 정책은 이 표에 없다.

중간 과정을 따라가는 예제

위 flag 모형에서 시험 집합 T={2}와 T={2,0}의 문장·분기 집합과 결과를 구하라. D의 두 방향만 분기 분모에 포함한다.

  1. x=2: S1에서 y0, D참, S2에서 y1, S3에서 1 반환이다. 방문 문장은 S1/S2/S3, 방향은 D참이다.

  2. T={2}의 문장 비율은 3/3=100%, 분기 비율은 1/2=50%다. 분모를 서로 바꿔 쓰지 않는다.

  3. x=0: S1에서 y0, D거짓, S2는 생략, S3에서 0 반환이다. 그 시험만 보면 문장2/3, 분기1/2다.

  4. T={2,0}의 합집합은 세 문장과 두 방향이어서 문장3/3=100%, 분기2/2=100%다. 기대 결과 1/0도 요구에 맞는다.

두 집합의 문장 비율은 모두 100%지만 분기 비율은 50%와 100%다. 이 값은 종이 예측이며 실측 결과가 아니다.

조건을 바꾸어 비교하기

평균과 합집합은 다르다

두 시험의 문장 비율이 1과 2/3이다. 평균과 전체 방문 비율을 비교하라.

  1. 평균은 (1+2/3)/2=5/6이다.

  2. 합집합은 S1,S2,S3 세 항목이다.

전체 문장 방문은 3/3이지 5/6이 아니다.

비교할 점

중복과 서로 다른 방문의 관계는 퍼센트 하나에 남아 있지 않다.

소스 변경으로 분모가 늘어난다

옛 모형의 대상은 세 문장이었다. 새 버전에서는 문장 S4도 대상 분모에 포함했지만 아직 방문하지 않았다. 옛 버전의 100%가 유지되는가?

  1. 새 분모에는 S4를 포함한 네 문장이 있다.

  2. 세 기존 문장만 방문했다면 방문 비율은 3 / 4다.

새 모형의 비율은 75%다. 서로 다른 버전에 같은 분모를 가정하지 않는다.

비교할 점

고정 대상에서 시험 추가의 단조성과 코드 변경은 다른 조건이다.

종이와 본문으로 직접 해보기

시험 {-1}의 비율을 구한 뒤 {2,-1}로 늘렸을 때 합집합을 구하라. x=-1이 0을 반환해야 하는 이유도 적어라.

힌트 보기

음수도 D의 거짓 방향을 따른다. 문장 퍼센트 평균이 아니라 서로 다른 방문 지점을 세어라.

풀이 보기

{-1}은 S1/S3 두 문장이라 2/3≈66.7%, 거짓 한 방향이라 1/2=50%다. {2,-1}은 문장 3/3·분기 2/2이며 결과는 1/0이다. -1은 x>0을 만족하지 않아 초기 y0이 유지된다.

오해와 반례

문장 커버리지가 100%면 모든 분기를 지나고 결과도 모두 맞다.

x=2 한 사례가 세 문장을 방문하면서 D거짓은 놓치는 반례다. 또 S2를 y=9로 잘못 쓴 코드도 같은 방문 집합을 가지므로 커버리지와 정답 검사는 별도다. 빈 대상 집합의 0/0을 임의로 100%라 부르지 않고 도구의 해당 없음 정책을 기록한다.

자기점검

D의 거짓 방향에 실행문이 없으면 분모에서도 지우는가?

답과 이유 보기

이 교육 분기 모형에서는 지우지 않는다.

D참·D거짓은 다른 제어 흐름 결과이며 D거짓→S3 이동이 있다.

같은 참 방향을 열 번 시험하면 방문 방향이 열 개인가?

답과 이유 보기

한 개다.

커버리지는 서로 다른 대상 집합의 크기를 센다.

두 시험의 50% 분기 비율을 평균하면 전체 비율인가?

답과 이유 보기

아니다.

참과 거짓을 각각 방문했다면 합집합이 두 방향이라 100%다.

심화: 지정 문장 집합 S와 방향 집합 B에 대해 시험 t의 방문을 V_S(t),V_B(t)로 두면 전체 비율은 |⋃V_S(t)|/|S| 및 |⋃V_B(t)|/|B|다. 대상과 제외 정책이 고정되어 있을 때 시험을 추가하면 합집합 크기는 감소하지 않는다. 코드나 제외 정책을 바꾸면 분모가 달라지므로 이 단조성을 서로 다른 버전에 그대로 적용하지 못한다. 예외·조기 return을 추가한 새 모형의 흐름을 따로 그려 보라.

소단원 3.2

조건·경로

조건을 각각 참·거짓으로 보았으면, 그 조건들이 엮인 모든 경로도 본 걸까?

준비 개념과 학습 목표

준비 개념

  • 순수 bool 값은 True 또는 False다. 이 예제에서 조건은 값 읽기만 하며 부작용·예외가 없다.

  • 결정은 제어 흐름을 정하는 전체 표현식이고, 복합 결정 안에는 여러 원자 조건이 있을 수 있다. 조건이 가진 논리값과 그 조건을 실제 평가했는지를 따로 적는다.

  • 경로는 시작에서 종료까지 따른 결정 결과의 순서다. 입력 제약 때문에 불가능한 순서가 있을 수 있고 반복문의 반복 횟수도 경로를 달라지게 한다.

학습 목표

  • 조건 결과·결정 결과·경로를 구별한다.

  • 단락 평가에서 생략된 값을 실행 방문으로 세지 않는다.

  • 가능한 경로와 불가능한 경로의 이유를 설명한다.

or의 입력 표에서 거짓인 B는 실제로 평가된 거짓일까?

이 활동은 부작용과 예외가 없는 순수 bool A와 B로 Python A or B를 읽는다. A가 참이면 B를 생략하며 A가 거짓일 때만 B를 읽는다. TT·TF는 모두 A참만 평가한다. FT는 A거짓·B참, FF는 A거짓·B거짓을 평가한다.

TT와 FF를 대상으로 하면 전체 결정의 참·거짓은 둘 다 나타나지만 실제 원자 평가 대상은 A참·A거짓·B거짓 세 개다. 입력에 B참이 적혀 있어도 TT에서 B를 읽지 않았으므로 그 평가를 방문했다고 세지 않는다. FT를 추가하면 네 평가 대상을 모두 대상으로 한다.

별도 코드의 두 if가 순서대로 각각 A와 B를 항상 평가한다면 가능한 경로가 네 개라는 다른 모형이다. 하나의 단락 or에서 평가된 원자 조건과 두 독립 if의 경로를 같은 분모로 합치지 않는다. 일반 Python or는 마지막 평가 객체를 반환하므로 순수 bool 제한도 유지한다.

먼저 확인할 개념
  • 조합과 특징별 범위

    조합 입력과 실제 평가 항목을 구별한다.

  • 상태와 입력 순서

    한 경로의 조건 순서와 시작 조건을 보존한다.

전체 결정과 안의 조건을 나눈다

A and B의 전체 결정은 둘 다 참일 때만 참이다. 논리 진리표의 네 행 TT/TF/FT/FF를 적는 일은 입력 조합을 설명하는 방법이다. 실제 Python 평가는 A부터 읽고 거짓이면 B를 읽지 않는다. 따라서 A가 거짓인 행에서 입력 B가 False라고 적어도 B의 거짓 평가를 관측한 것은 아니다.

이 단원의 평가 조건 커버리지는 원자 A/B가 실제 평가되며 낸 참·거짓 네 대상 {A참,A거짓,B참,B거짓} 중 방문 비율이다. 결정 커버리지는 전체 and의 참·거짓 두 대상이다. 순수 bool을 제한했으므로 결과는 bool이지만 일반 Python and/or는 마지막 평가 피연산자를 반환하므로 모든 타입에서 bool 결과라고 일반화하지 않는다.

조건별 방문과 조합 경로는 다르다

별도 모형 score는 score=0에서 시작해 D1:A가 참이면 1을 더하고, 이어 D2:B가 참이면 2를 더해 반환한다. 두 결정은 독립 입력 bool이므로 TT/TF/FT/FF 네 경로가 모두 가능하다. TT와 FF만 고르면 A와 B 각각의 참·거짓 및 두 결정의 방향을 모두 보지만 TF와 FT 경로는 아직 지나지 않는다.

두 독립 이진 결정을 모두 수행하는 모형의 경로 수는 2²=4이고, k개면 2^k다. 이것은 모든 조합이 가능한 고정 길이 모형의 수치다. 첫 결정이 x>0, 두 번째가 x<=0이며 같은 x가 바뀌지 않는 모형에서는 TT와 FF가 불가능하고 TF/FT만 가능하다. 단순 지수식을 실제 모든 코드의 가능한 경로 수로 쓰지 않는다.

score = 0
if A: score = score + 1
if B: score = score + 2
return score
# A/B는 독립 순수 bool, 두 if는 차례로 수행한다.

더 강한 기준도 조건을 써야 한다

모든 가능한 경로를 지나게 하려면 조건 사이 제약과 반복을 분석해야 한다. 예를 들어 횟수 제한 없는 while은 반복0/1/2/...의 경로를 가져 유한한 시험 목록으로 모든 경로를 방문하기 어렵다. 반복 상한을 문서로 제한하면 그 제한된 영역의 경로를 계산할 수 있지만 제한 밖까지 검증했다는 뜻은 아니다.

조건이 결정 결과에 독립적으로 영향을 주는지 살피는 더 강한 기준도 존재한다. 여기서는 MC/DC를 획득했다고 부르지 않는다. 그 기준은 조건 발생 위치·단락 평가·결합 관계와 독립 효과를 보여 주는 시험 쌍 정의가 필요하다. 조건·경로의 비율만 보고 다른 기준의 인증이나 전체 정확성으로 뛰어넘지 않는다.

중간 과정을 따라가는 예제

(1) A and B를 TT와 FF로 종이 평가하라. 실제 평가 조건 비율과 결정 비율을 구하라. (2) 위 score를 같은 두 입력으로 추적하고 가능한 네 경로 중 몇 개를 덮는지 구하라.

  1. and의 TT는 A참/B참을 평가해 전체 참이다. FF는 A거짓을 평가해 전체 거짓이며 B는 생략된다.

  2. 입력 B거짓은 주어졌지만 실제 평가된 B거짓은 없다. 평가 조건 대상은 네 개 중 A참/A거짓/B참 세 개로 3/4=75%다.

  3. and 전체 결정은 참·거짓 둘 다 있으므로 2/2=100%다. B거짓 평가를 더 보려면 TF를 추가할 수 있다.

  4. score는 TT에서 0→1→3, FF에서 0→0→0이다. 두 if가 항상 각각 평가되어 조건·결정 방향은 모두 보지만 경로는 TT/FF 두 개로 2/4=50%다.

단락 and: 평가 조건75%·결정100%. 독립 if score: 각 조건/결정100%·경로50%. 서로 다른 모형의 분모를 혼합하지 않는다.

결정 두 방향과 조건 세 대상

TT와 FF만 대상으로 하면 평가 조건과 결정의 설계 범위는?

  1. TT는 A참만, FF는 A거짓과 B거짓을 평가한다.

  2. 평가 대상은 네 개 중 셋이고 전체 결과는 참·거짓 둘이다.

조건 3/4, 결정 2/2다. B참 평가가 빠졌다.

비교할 점

전체 결정의 100%가 모든 원자 평가의 100%는 아니다.

TF를 추가하는 경우와 FT를 추가하는 경우를 비교하라.

  1. TF에서는 A참만 평가하여 새 대상이 없다.

  2. FT에서는 A거짓과 B참을 평가하여 B참이 새로 추가된다.

풀이 보기

오해와 반례

A/B의 입력값을 모두 적어 보았으면 단락 평가의 조건과 모든 경로도 100%다.

and의 TT/FF는 입력 열 A/B에 참·거짓이 있어도 B거짓을 평가하지 않는다. 독립 두 if의 TT/FF는 각 조건 참·거짓을 실제 평가해도 TF/FT 조합 경로를 놓친다. 어떤 대상으로 100%인지 정의하지 않으면 서로 다른 사실을 한 숫자로 섞게 된다.

심화: 경로를 분기 결과의 단어로 쓰면 독립 두 결정의 가능 집합은 {TT,TF,FT,FF}다. 시험 집합 {TT,FF}의 각 좌표 투영은 {T,F}라 조건 방향을 모두 덮지만 두 좌표의 곱집합을 덮지는 못한다. 경로가 입력 제약을 만족하는지 묻는 일은 별도의 논리 문제이며, 불가능한 경로를 근거 없이 도구 제외로 지워 수치만 높이면 숨긴 가정을 만들 수 있다.

소단원 3.3

coverage의 보장한계

방문할 곳을 모두 방문한 시험이, 경계값 하나의 틀린 답을 놓칠 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 요구에서 만든 기대 결과가 oracle이다. 구현이 낸 답을 그대로 기대 결과로 베끼면 구현과 함께 틀릴 수 있다.

  • 커버리지는 지정한 코드 구조의 방문 증거이며 입력 영역 모든 값의 정답이라는 명제가 아니다.

  • 여기서 fee는 수학적 정수 n에 대해 18<=n<=65이면1000, 그 밖이면1500이라는 가상 계약이다. 실제 연령·가격 정책이 아니다.

학습 목표

  • 100% 구조 방문과 요구 정확성을 구별한다.

  • 독립 기대값과 경계 시험으로 결함을 드러낸다.

  • 보고서의 버전·분모·실행 여부를 정확히 말한다.

두 분기 모두 방문한 절댓값 함수가 음수의 답을 틀릴 수 있을까?

수학적 정수 x의 절댓값 계약은 x≥0이면 x, x<0이면 −x를 반환한다. 가상 결함은 음수 쪽에서 −x+1을 반환한다. x=2와 x=−2는 각각 두 방향을 방문하지만 음수 결과는 3으로 기대값 2와 다르다.

방문을 기록하는 지도는 값의 정확성을 대신하지 않는다. 더구나 구현 결과를 기대값으로 복사하면 음수의 잘못된 3도 통과로 표시할 수 있다. 독립 계약의 기대값과 구조의 방문을 별도 열에 적는다.

테스트를 더 민감하게 만드는 변형 비교에서도 원래 계약과 의미가 같은 변경이 있을 수 있다. 순수 정수 절댓값에서 x≥0을 x>0으로 바꾸되 두 반환식을 그대로 두면 x=0의 반환은 어느 쪽에서도 0이다. 이 모형은 등가지만 모든 언어 타입·부작용·외부 제품까지 등가라고 주장하지 않는다.

먼저 확인할 개념
  • 독립 기대값과 가려진 결함

    방문한 입력에서도 oracle이 잘못될 수 있음을 확인한다.

  • 정의역과 분할

    정수 계약과 다른 타입·환경의 요구를 구별한다.

방문 지도와 올바른 답의 차이

코드의 어느 방을 들어갔는지를 기록하는 지도는 그 방에서 계산한 값이 맞는지까지 말하지 않는다. branch coverage 100%는 정한 분기 방향을 적어도 한 번 따라갔다는 뜻이다. 같은 방향 안에서 다른 입력이 잘못 처리되거나 상태·환경·예외 경로가 달라지는 결함을 놓칠 수 있다.

커버리지가 낮으면 구조 방문의 빈틈을 찾는 데 도움이 되지만 높다고 결함 수가 0이라는 논리적 결론은 나오지 않는다. 포함 범위 밖 파일, 제외 구간, unreachable 가정, 다른 빌드 버전이 분모를 바꿀 수 있다. 95%라는 숫자도 어떤 소스와 기준의 95%인지 없으면 서로 비교하기 어렵다.

요구에서 정답을 만들고 코드와 따로 비교한다

의도적으로 잘못 만든 fee_bad는 조건을 18<n<=65로 써서 18을 빠뜨린다. 시험17/42/66은 각각1500/1000/1500을 반환해 기대와 일치하고, 전체 결정의 참·거짓도 모두 방문한다. 이 시험 집합에 대해 분기2/2라도 입력18의 요구 기대1000과 구현 예측1500은 다르다.

18과65 같은 경계는 명세를 읽어서 선택한다. 구조에 맞춰 참·거짓 대표만 고르거나 실제 구현 조건을 그대로 기대값 식으로 복사하면 틀린 경계가 양쪽에 함께 들어갈 수 있다. 정답 표에는 어느 계약의 어느 범위를 근거로 만들었는지 적고, 구조 방문 표는 별도로 유지한다.

def fee_bad(n):
    if n > 18 and n <= 65:
        return 1000
    return 1500
# 의도적인 > / >= 경계 결함. 실행하지 않고 종이로 추적한다.

한 시험의 결론을 필요한 범위로 제한한다

코드를 조금 바꾸어 결함을 심고 시험이 그것을 잡는지 살피는 mutation testing은 시험의 민감도를 탐구하는 한 방법이다. 아래 활동은 실제 변이 도구 실행이 아니라 자체 두 변이의 결과를 종이로 비교하는 것이다. 같은 의미를 보존하는 변이도 있을 수 있고 변이를 많이 잡아도 모든 결함을 제거했다고 할 수 없다.

보고할 때는 정한 소스 버전·대상 파일·지표·분모·제외·실행 명령과 결과를 함께 적는다. 이 단원에서는 명령을 실행하지 않았으므로 방문 퍼센트는 예측이라고 표시한다. 실제 코드 실행, 독립 내용 검토, 학생의 이해도 확인과 공개 배포 검증도 서로 다른 상태다.

중간 과정을 따라가는 예제

계약 fee와 fee_bad를 시험17/42/66에 대조한 뒤18을 추가하라. 분기 D=(n>18 and n<=65)의 두 방향만 센다. 시험이 모두 통과한 집합에서 계약 전체가 맞는지 판단하라.

  1. 계약상17은 범위 밖1500,42는 안1000,66은 밖1500이다. 기대값은 구현을 읽기 전에 계약에서 정한다.

  2. fee_bad도17→1500,42→1000,66→1500이라 이 세 사례는 일치한다. D의 거짓·참·거짓을 지나 분기 집합은 두 방향이다.

  3. 따라서 이 집합의 분기 예측은2/2=100%다. 여전히 명세의 모든 정수 값을 대조한 것은 아니다.

  4. 18을 넣으면 계약은1000이지만 n>18은 거짓이므로 fee_bad는1500이다. 두 값 차이가 경계 결함의 구체적 반례다.

세 사례는 통과하고 분기 방향도 모두 지나지만 입력18 하나가 요구 위반을 드러낸다. 100% 방문은 정확성 증명이 아니다.

조건을 바꾸어 비교하기

같은 구조와 다른 답

2와 −2를 대상으로 했을 때 방문 방향과 결과 판정은?

  1. 비음수·음수의 두 방향이 모두 나타난다.

  2. −2는 계약 2인데 결함은 3이다.

방향 설계 범위는 2/2지만 값의 계약 위반이 존재한다.

비교할 점

방문과 독립 기대값의 비교가 서로 다른 질문이다.

등가 변경과 탐지되지 않은 결함

올바른 순수 정수 절댓값에서 x≥0을 x>0으로 바꾸고 반환 x와 −x를 유지한다. 0에서 차이가 있는가?

  1. 0은 분기 방향을 바꾸지만 x=0과 −x=0은 같다.

  2. 양수·음수에서는 원래 방향이 유지된다.

이 지정 정수 모형의 반환 계약에는 차이가 없다. 이 변경을 못 구별했다고 테스트가 반드시 나쁜 것은 아니다.

비교할 점

반환 의미가 같은 변경과 요구 위반을 남긴 변경을 구별한다.

종이와 본문으로 직접 해보기

변이 M1은 조건의 n>18을 n>=18로 고친다. 변이 M2는 안쪽 반환1000을900으로 바꾼다. 시험18과42가 각각 어느 결함을 드러내는지 계약 기대값과 비교하라.

힌트 보기

M1/M2는 원래 fee_bad에서 각각 독립적으로 한 곳만 바꾼 프로그램이다. 실제 변이 도구를 돌린 결과가 아니다.

풀이 보기

M1은18→1000,42→1000이라 두 사례에서 계약과 일치하고 이 단순 정수 계약에서는 경계가 고쳐진다. M2는18→1500으로 경계 실패를 유지하고42→900으로 내부 금액 결함도 드러낸다. 원본 fee_bad의42는 통과하지만18은 실패한다. 변이 이름만으로 오류를 뜻하지 않으며 M1은 고치는 변경이다.

오해와 반례

100% coverage를 달성했으면 더 이상 요구나 오류 사례를 볼 필요가 없다.

17/42/66의 두 방향 방문에도18의 경계가 틀린다. 분기 없는 단일 return 식에서도 산술 오타가 있으면 유일 경로 방문100%로 정답을 보장할 수 없다. 코드 방문, 요구 분할·경계·상태 조합, 독립 oracle과 실제 환경 검증을 함께 생각한다.

S1·S2·S3 모형의 참·거짓 두 시험에서 문장 비율을 합집합으로 구하라. 순수 bool A or B의 TT와 FF에 무엇을 추가해야 B참도 평가 대상으로 만드는지 설명하라. 정수 절댓값의 음수 반환을 −x+1로 바꾼 결함과 0에서 분기만 달라지는 등가 변경을 계약으로 비교하라.

힌트 1

고유 항목과 생략된 평가를 먼저 적는다.

힌트 2

방향이 달라도 반환 계약이 같은 경우가 있는지 본다.

풀이와 답 확인

  1. S1,S2,S3 합집합은 세 문장을 모두 대상으로 하므로 3/3이다.

  2. TT·FF는 A참·A거짓·B거짓이며 FT가 B참을 추가한다.

  3. −2에서 계약 2와 결함 3은 다르다.

  4. 올바른 정수 절댓값의 ≥ 대 > 변경은 0에서 방향만 바꾸고 반환값 0은 같다.
