소단원 6.1

mutation·grammar fuzzing

입력을 마구 바꾸는 것과 형식에 맞춰 만드는 것은 무엇이 다를까?

준비 개념과 학습 목표

준비 개념

  • fuzzing은 여러 입력을 자동 생성·변형하여 대상의 행동을 탐색하는 시험 방식이다.

  • seed는 변형의 출발 입력, corpus는 모아 둔 입력 집합이다.

  • 구문 유효성과 업무 규칙 유효성은 다른 조건이다.

학습 목표

  • mutation과 문법 생성의 차이를 설명한다.

  • 작은 문법의 전개를 추적한다.

  • 입력 생성과 오류 판정 규칙을 분리한다.

문법에 맞는 길이 표시가 실제 내용 길이와 다를 수 있을까?

자체 메시지 문법은 H:S다. H는 1 또는 2이고 S는 0,1,00,01,10,11 중 하나다. 콜론과 숫자 문자열만 생성하므로 구문상 문자열은 2×6=12개다. 별도 의미 규칙 H=내용의 문자 수를 적용하면 유효 메시지는 여섯 개다. 문법 규칙에 맞는 2:0도 길이 표시와 실제 한 글자가 달라 의미상 거절 대상이다.

seed 1:0에서 H만 2로 바꾸면 2:0이 된다. 이는 구문을 보존하는 의미 경계 변형이다. 콜론을 세미콜론으로 바꾼 1;0은 문법 밖이다. 둘을 같은 무효 입력이라 묶어도 대상의 구문 거절 경로와 길이 검증 경로는 다를 수 있다.

길이 표시를 실제 길이로 함께 바꾸는 생성 계획은 정상 깊은 처리까지 도달하기 쉽지만 길이 불일치 검사 자체를 탐색하려면 별도 입력 가족이 필요하다. 길이 규칙을 일부러 깨는 활동에서 안전한 거절이 정답이며, 거절을 모두 crash로 세면 판정 기준이 잘못된다.

먼저 확인할 개념
  • 생성 정의역과 비중

    가능한 문자열과 제약을 통과한 문자열을 나눈다.

  • 오류 결과의 계약

    정상 거절과 결함을 판정하는 기준을 먼저 둔다.

기존 입력을 조금씩 바꾸기

mutation은 기존 seed의 바이트를 바꾸거나 넣거나 지우는 방식이다. 자체 seed 12+3에서 +를 /로 바꾸면12/3, +를 지우면123이다. 새로운 입력이 항상 원래 형식을 지키지는 않으며 잘못된 형식도 안전하게 거절하는 경로를 시험할 수 있다.

대상은 빈 입력·큰 입력·잘못된 입력에도 정의한 방식으로 대응해야 한다. 정상 오류 반환과 메모리 오류 같은 실패를 구별할 oracle, 즉 판정 기준을 정한다. 입력을 생성했다는 사실만으로 버그를 발견했다고 표시하지 않는다.

문법으로 구조를 만드는 방식

자체 문법은 E→D+D, D→0|1|2다. 문법 설명의 공백은 실제 생성 문자열에 포함하지 않는다. 시작 E의 두 D를 각각 1, 2로 전개하면 1+2다. 각 D에 3선택이 있으므로 문자열 9개를 만들 수 있다. 실제 산술식 전체 문법이 아니라 한 자리 덧셈만 정의했다.

문법 생성은 정의한 구문을 따르지만 업무 제약까지 자동 만족하지는 않는다. 같은 문법에서 합≤2라는 업무 규칙을 더하면2+2는 구문상 유효하면서 업무상 거절 대상이다. 문법이 정확한지와 추가 의미 조건이 있는지 함께 기록한다.

두 방식과 실행 조건을 연결하기

문법 생성 입력을 seed로 삼아 변형하면 정상 구조와 구조 경계의 오류 처리를 함께 탐색할 수 있다. 필요한 최대길이·시간·메모리 예산을 정하고 대상 상태를 반복 간에 초기화해야 결과를 비교하기 쉽다. 특정 fuzzer의 기본 정책이 이 자체 문법과 같다고 주장하지 않는다.

실제 시험 보고에는 도구/대상 버전·seed·옵션·예산·판정 기준과 관측된 실패가 필요하다. 이 단원은 문자열을 종이에 전개한다. 퍼징 바이너리를 설치·실행하여 실제 crash를 찾은 상태가 아니다.

오해와 반례

2+2는 구문 유효하지만 합≤2를 어긴다. 12 같은 잘못된 구문도 안전한 거절을 확인하는 의미가 있으므로 생성과 oracle을 분리한다.

소단원 6.2

coverage guidance

많은 입력을 시험하는 것과 새로운 코드에 도달하는 것은 같은가?

준비 개념과 학습 목표

준비 개념

  • coverage는 어떤 코드·분기 등을 방문했는지 관측하는 지표다.

  • coverage guidance는 새 관측을 만든 입력을 다음 탐색에 활용하는 방식이다.

  • 아래 분기 ID는 자체 모형이며 실제 LLVM counter 구조가 아니다.

학습 목표

  • 새 방문 집합의 차집합을 계산한다.

  • 보존 입력과 단순 횟수를 구별한다.

  • coverage의 한계와 oracle 역할을 설명한다.

새 방문만 보존하면 가장 작은 corpus나 모든 실패도 보존할까?

자체 방문 특징은 p와 q 두 개다. 입력 A는 {p}, B는 {q}, C는 {p,q}를 만든다. 빈 집합에서 A,B,C 순서로 새 특징을 더한 입력만 남기는 규칙은 A와 B를 남기고 C를 버린다. 같은 합집합을 보존하는 한 파일 C가 있어도 이 순차 규칙은 최소 파일 수를 보장하지 않는다.

순서를 C,A,B로 바꾸면 C 하나만 남는다. 파일 수, 총 바이트 수, 전체 특징 보존, 특정 실패 입력 보존은 각각 다른 목적이다. 같은 특징을 가진 성공 입력과 실패 입력도 있을 수 있으므로 coverage 기준으로 버린 입력이 업무 오류의 회귀 증거로는 중요할 수 있다.

여기의 두 특징 집합은 실제 libFuzzer의 모든 feature를 모델링하지 않는다. 실제 도구는 계측·counter·값 profile 등 더 풍부한 정보를 쓸 수 있다. 소스 버전이나 target 설정이 달라지면 특징표를 다시 확인해야 하며 과거 표만으로 새 대상의 coverage를 주장하지 않는다.

먼저 확인할 개념

    여러 입력의 방문 비율은 집합을 합쳐 구한다.

  • 방문과 업무 정답

    같은 구조 방문이어도 기대 결과와 관찰 결과가 다를 수 있다.

새로 본 부분을 표시하기

자체 target은 empty일 때E, 그 밖에는N을 방문한다. N뒤 첫글자 A면A, A뒤 길이≥3이면L을 추가한다. branch 방문 집합을 입력마다 기록하면 이미 본 입력인지와 별개로 새 코드 도달을 구별할 수 있다. 이 표는 관측된 측정이 아니라 규칙으로 계산한다.

초기 corpus의 B는{N}을 만든다고 하자. A의{N,A}는 A를 새로 더한다. AA의{N,A}는 입력 자체가 달라도 새 방문은 없다. AAA는{N,A,L}로 L을 새로 만든다. 저장 기준을 새 ID가 있으면 보존으로 정한다.

보존한 입력에서 다시 변형하기

LLVM 공식 설명은 새 coverage 경로를 만든 mutation을 corpus에 보존해 후속 변형에 활용한다. 내부 계측은 더 풍부한 feature나 counter를 사용할 수 있어 이 세 ID 집합이 모든 libFuzzer의 정확한 기준은 아니다. 본문은 새 영역을 유도하는 이유를 작은 모형으로 보여 준다.

한 번만 실행한 비결정적 target은 같은 입력의 방문도 달라질 수 있다. 전역 상태·시간·스레드·랜덤 조건이 있으면 재현에 필요한 조건을 기록한다. 입력이 정상 반환했다는 사실과 기대한 업무 결과가 맞다는 사실도 구별한다.

높은 비율은 오류 부재 증명이 아니다

전체 모형 ID가 E,N,A,L 네 개일 때 모두 방문하면 ID coverage는4/4다. 그러나 각 ID 안의 모든 값 조합과 상태를 시험한 것은 아니다. 같은 분기에서 A의 세 번째 글자 값에 따라 잘못된 결과를 낼 수 있으므로 별도 oracle이 필요하다.

탐색 예산을 쓰는 방법은 목표에 따라 달라진다. crash·불변식·참조 구현과 결과 차이 등 무엇을 실패로 볼지 정한다. 실제 coverage 계측·sanitizer 로그 없는 종이 표를 성능이나 안전 인증으로 표시하지 않는다.

소단원 6.3

crash triage와 최소화

오류 입력을 짧게 만들 때 무엇이 그대로 남아야 할까?

준비 개념과 학습 목표

준비 개념

  • triage는 재현된 실패를 분류하고 원인 조사 순서를 정하는 작업이다.

  • 최소화는 입력을 줄이면서 지정한 같은 실패를 보존하는 과정이다.

  • 짧은 실패 입력과 전역적으로 가장 짧은 입력은 다르다.

학습 목표

  • 동일 실패 판정과 재현 조건을 기록한다.

  • 삭제 후보를 유지/복원으로 추적한다.

  • corpus 최소화와 crash 최소화의 목적을 구별한다.

한 글자 삭제가 모두 실패를 없애면 두 글자 삭제도 그럴까?

자체 실패 F는 문자열이 정확히 ABCD 또는 AD일 때만 발생한다. ABCD에서 한 글자를 삭제한 BCD,ACD,ABD,ABC는 모두 F가 아니다. 한 글자 삭제만 시험한 절차는 ABCD에 멈추지만 가운데 BC를 함께 삭제하면 AD가 되어 F를 유지한다.

이 사례는 실패가 삭제에 따라 단조롭게 변하지 않는 경우다. 한 문자라도 지우면 실패가 없어지는 1-minimal과 가능한 모든 삭제 조합 중 가장 짧은 실패는 다르다. 이 특정 판정에서는 길이 0이나 1인 문자열이 실패 집합에 없고 AD가 길이 2이므로 전역 최소 길이는 2임을 별도 근거로 말할 수 있다.

실제 crash 조사에서는 같은 실패 판정·버전·로그·환경을 고정해야 한다. 입력을 줄였더니 timeout이나 다른 sanitizer 오류가 났다면 같은 실패를 유지했다고 자동 인정하지 않는다. 예산 때문에 종료한 최소화, 실패의 재현 성공, 수정 뒤 정상 회귀 결과도 별도 상태로 남긴다.

먼저 확인할 개념
  • 국소 축소와 전역 최소

    정수 후보의 국소 멈춤을 문자 삭제 조합으로 확장한다.

  • 최초 실패와 재시도 기록

    실패 종류와 관찰 순서를 지우지 않는다.

재현 조건과 실패 종류부터 정하기

자체 oracle은 문자열에 연속 AB가 있으면 F라는 특정 실패를 낸다고 정한다. AXB는 AB가 연속하지 않아 F가 아니다. timeout·다른 오류를 F와 같은 것으로 받아들이지 않는다. 실제 target에서는 버전·옵션·환경·원본입력과 로그를 함께 보존한다.

같은 스택 위치라고 항상 같은 원인인 것도 아니고 다른 스택이라고 항상 다른 버그인 것도 아니다. 임시 묶음 기준을 기록하고 원인 확인 전에는 확정 버그 수로 부풀리지 않는다. 이 단원에서 F는 실제 프로그램 crash 관찰이 아닌 종이 판정 규칙이다.

줄여도 같은 실패가 남는지 다시 묻기

원본 xxAByy는 길이6이다. 앞 xx삭제하면 AByy가 F를 유지하므로 받는다. 뒤 yy삭제하면 AB가 F를 유지하므로 받는다. A나 B를 한 글자 지우면 F가 사라져 복원한다. 결과AB는 이 predicate에서 가장 짧은2글자다.

일반 감소기는 시도한 삭제·문법 변형 범위에서 더 줄일 수 없는 결과를 얻을 수 있지만 전역 최소를 항상 보장하지는 않는다. 재현 실패가 불안정하면 삭제가 영향을 준 것인지 환경이 달랐는지 분리해야 한다. 실패를 확인하지 않고 길이만 줄이면 원인까지 지울 수 있다.

다른 최소화 목적을 혼동하지 않기

LLVM의 minimize_crash는 주어진 실패 입력을 줄이는 옵션이며 시도수·시간으로 예산을 제한할 수 있다. merge는 coverage를 유지하면서 corpus를 정리하는 목적이다. 실패 입력2바이트와 corpus 2파일은 단위부터 다르다.

수정 뒤에는 줄인 입력뿐 아니라 원본·관련 변형을 회귀 시험에 남길 수 있다. 정상 기대 결과를 명시하고 실제 수행 로그를 기록해야 고쳤다고 말할 수 있다. 본문은 삭제와 F판정만 손으로 추적하며 sanitizer·바이너리 실행 미수행이다.

F는 정확한 문자열 두 개로 정의한 자체 판정이다. 실제 프로그램 crash나 감소기의 관측 출력이 아니다.

중간 과정을 따라가는 예제

F=연속 AB 존재인 oracle에서 xxAByy를 삭제 최소화하라. 한 글자 삭제 불가와 전역 최소의 근거를 따로 적어라.

  1. xx를 지워 AByy 길이 4이며 AB가 있어 F 유지다.

  2. yy를 지워 AB 길이 2이며 F 유지다.

  3. A 삭제→B,B 삭제→A 모두 AB가 없어 F가 아니다. 두 삭제를 거절한다.

  4. 이 특별한 predicate는2글자 연속문자열을 요구하므로 길이0/1 입력은 모두 불가능하다. 따라서2는 전역 최소다. 일반 알고리즘의 전역 최소 보장으로 확대하지 않는다.

xxAByy(6)→AByy(4)→AB(2), 이 자체 규칙에서 AB가 가장 짧다.

조건을 바꾸어 비교하기

1-minimal이지만 전역 최소가 아니다

ABCD의 단일 삭제 네 개와 BC 삭제를 판정하라.

  1. 단일 삭제 네 후보는 두 실패 문자열 어느 것과도 같지 않다.

  2. BC를 함께 지우면 AD다.

ABCD는 단일 문자 삭제 기준 1-minimal이지만 길이 2인 AD보다 길다.

비교할 점

사용한 변형 범위와 최소 주장의 범위를 같이 적는다.

이 판정에서 최소 길이를 증명한다

AD가 길이 2인 전역 최소 실패임을 보일 수 있는가?

  1. 실패 집합을 정확히 {ABCD,AD}로 정의했다.

  2. 집합의 길이는 각각 4와 2다.

그렇다. 이 명시 집합에서 최소는 2다. 일반 reducer의 보장으로 확대하지 않는다.

비교할 점

탐색 결과와 정의한 전체 집합의 별도 증명을 나눈다.

종이와 본문으로 직접 해보기

xAXBy에서 X만 지우면 무엇이 달라지는가? 원래 F 실패를 줄였다고 말할 수 있는가?

힌트 보기

삭제 전후 연속 AB의 유무를 비교한다.

풀이 보기

원본은 연속 AB가 없어 F가 아니고 X 삭제 후 xABy는 F다. 새 실패를 만들었을 뿐 원래 F 실패의 보존 최소화라고 말할 수 없다.

오해와 반례

다른 crash도 나오기만 하면 같은 실패의 최소화이며 줄인 입력이 항상 전역 최소다.

F 대신 timeout이면 같은 predicate를 보존하지 않았다. 한 글자 삭제가 모두 실패해도 조합 삭제·다른 변형이 가능할 수 있어 일반 1단계 최소와 전역 최소를 구별한다.

자기점검

AB에서 A 삭제를 받는가?

답과 이유 보기

받지 않는다.

B에는 연속 AB가 없어 F를 잃는다.

merge와 minimize_crash 목적은 같은가?

답과 이유 보기

다르다.

하나는 coverage를 보존하는 corpus 정리, 다른 하나는 실패 입력 감소다.

재현 로그 없이 실제 수정 성공이라 할 수 있는가?

답과 이유 보기

없다.

손계산은 바이너리에서 실패·수정 후 결과를 관찰한 증거가 아니다.

다른 문제에 적용하기

퍼징 결과의 세 가지 목적을 분리하기

작은 H:S 문법의 구문 입력 12개 중 길이 의미 규칙을 만족하는 수를 구하고 2:0과 1;0을 분류하라. 특징 A={p},B={q},C={p,q}의 순차 새 특징 보존을 두 순서로 비교하라. 실패 집합 {ABCD,AD}에서 단일 삭제와 BC 동시 삭제를 비교해 최소 주장을 제한하라.

힌트 1

구문·의미·실패 판정은 별도다.

힌트 2

순서·목적·허용 변형의 범위를 보존한다.

풀이와 답 확인

  1. 길이 1 내용 두 개와 길이 2 내용 네 개로 의미 유효는 여섯 개다.

  2. 2:0은 의미 불일치, 1;0은 구문 무효다.

  3. A,B,C 순서는 두 파일, C,A,B 순서는 한 파일로 같은 {p,q}를 덮는다.

  4. ABCD는 단일 삭제로 못 줄여도 BC 동시 삭제의 AD가 실패를 유지한다.

생성 범위, 판정 기준, corpus 목적과 최소화 범위를 분리한다. 자체 문법·집합·정확 문자열의 손 모형이며 실제 crash·계측·수정·회귀 성공의 증거는 아니다.

해결한 뒤 점검할 것

  • 12개와 의미 유효 6개를 구분한다.

  • 특징 집합과 파일 수를 분리한다.

  • 같은 특징의 실패 증거를 보존한다.

  • 1-minimal과 전체 최소의 근거를 나눈다.
