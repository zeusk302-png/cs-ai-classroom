소단원 8.1

매개변수 다형성

정수도 문자열도 그대로 돌려주는 함수는 타입을 몇 번 써야 할까?

준비 개념과 학습 목표

준비 개념

  • 함수와 반환 값

  • int·bool 타입

  • 함수 타입 A→B

학습 목표

  • 타입 변수의 같은 이름이 뜻하는 제약을 설명한다.

  • 매개변수 다형성과 함수 오버로딩을 구별한다.

함수를 따로 사용하면 자유로운데 한 목록에 모으면 왜 묶일까?

이 보강은 순수 Hindley–Milner 모형에 Int, Bool, 쌍과 동종 목록을 추가한다. 자동 숫자 변환·오버로딩·서브타입·재귀 타입은 없다. let으로 일반화한 id의 스키마는 ∀a.a→a다. (id 2, id true)는 각 이름 사용을 새로 인스턴스화하여 Int×Bool이 된다. 한 스키마를 공유한다는 말은 서로 독립인 호출의 타입 변수까지 하나로 묶는다는 뜻이 아니다.

그러나 [id 2; id true]는 동종 목록 규칙을 함께 만족해야 한다. 첫 id 사용은 Int, 둘째 사용은 Bool 결과를 낼 수 있어도 목록 원소 타입 T에 Int와 Bool을 동시에 요구하므로 거부된다. 각 호출의 자유와 호출 결과를 묶는 자료구조의 제약은 서로 다른 층이다. 이 언어에서 이질 목록을 만들려면 명시적인 합 타입 같은 새 표현을 별도로 설계해야 한다.

서로 다른 이름의 타입 변수는 반드시 서로 다른 타입을 뜻하지 않는다. fst의 ∀ab.(a×b)→a를 (2,5)에 적용하면 a와 b 모두 Int다. 같은 변수 a를 반복하는 same의 ∀a.(a×a)→a에는 (2,true)가 맞지 않는다. 이 예제의 fst/same 구현은 첫 값을 반환하는 것으로 고정하지만, 타입의 반복 자체가 두 입력 값의 동일성을 주장하지는 않는다. 아래 계산은 실제 OCaml 실행이 아닌 타입·값의 손모형이다.

먼저 확인할 개념
  • 같은 타입 변수의 반복

    반복 변수의 타입 동일성과 값 동일성을 분리한다.

  • 일반화된 이름의 새 사용

    호출마다 새 변수와 결과를 묶는 추가 제약을 구별한다.

타입을 나중에 정하는 자리

다형성은 하나의 코드나 이름을 여러 타입과 관련하여 사용하는 성질이다. 매개변수 다형성은 구체 타입 대신 타입 변수 α를 사용해 같은 구현을 표현한다. 항등 함수 id x = x의 타입 α→α에서 화살표 왼쪽과 오른쪽 α는 반드시 같은 타입이다.

∀α.α→α는 α를 적절한 타입으로 선택할 수 있다는 타입 스키마다. int를 선택하면 int→int, bool을 선택하면 bool→bool이다. 호출 때 값을 보고 임의로 서로 다른 두 타입을 정한다는 뜻이 아니다. 이 단원은 순수한 기본 Hindley–Milner 모형의 정적 추론을 사용한다.

let id x = x
let const x y = x

같은 타입과 같은 값 구별하기

const의 타입은 ∀αβ.α→β→α이다. x와 결과의 타입은 같고 y의 타입은 독립적으로 선택한다. 두 타입 변수 이름이 다르다고 반드시 서로 다른 타입이어야 하는 것도 아니다. 둘 다 int로 선택해도 된다.

α×α 형태의 쌍은 두 값의 타입이 같다는 제약이다. 값 2와 5는 서로 다르지만 둘 다 int라서 이 모형에 맞는다. 반면 (2,true)는 int×bool이므로 α×α에 맞지 않는다. 타입 제약을 값의 동등성 검사로 바꾸면 안 된다.

무엇을 할 수 있는지 제한하기

아무 α에나 가능한 함수는 타입을 알지 못한 채 int 전용 덧셈을 할 수 없다. id는 값을 그대로 반환하므로 그런 연산이 필요 없다. x+1은 이 모형에서 x:int를 요구해 함수 타입을 int→int로 제한한다.

같은 이름의 +가 타입마다 다른 구현을 선택하는 오버로딩은 여기의 단일 구현 매개변수 다형성과 별개다. 상속 관계를 이용한 서브타입 다형성도 별개다. 언어별 숫자 변환·연산 규칙을 숨겨 두고 모든 다형 함수를 같은 방식으로 해석하지 않는다.

id : ∀α. α→α
const : ∀αβ. α→β→α
독립 인스턴스와 결합 자료구조의 추가 제약
식 또는 적용각 사용의 제약전체 판단

(id 2, id true)

첫 a₁=Int, 둘째 a₂=Bool

Int×Bool 쌍 허용

[id 2; id true]

a₁=Int, a₂=Bool; 원소 T=Int=Bool

동종 목록 불일치

fst (2,5)

a=Int, b=Int

결과 2:Int

same (2,5)

a=Int인 두 자리

결과 2:Int; 값은 달라도 됨

same (2,true)

a=Int와 a=Bool

같은 호출 내부 충돌

각 행은 새 추론에서 시작한다. 아래첨자 변수는 id의 서로 다른 사용이다. 목록 행에서 충돌을 만드는 것은 id 스키마가 아니라 두 결과에 공통 원소 타입을 요구하는 규칙이다.

중간 과정을 따라가는 예제

자체 순수 모형에서 id는 ∀α.α→α, const는 ∀αβ.α→β→α이다. id 7, id true, const 7 false의 타입과 값, (2,5)가 α×α에 맞는지 추론하라.

  1. id 7은 α=int로 선택하므로 결과 int, 값 7이다.

  2. 별도 id true 사용은 α=bool로 선택해 결과 bool, 값 true다.

  3. const 7 false는 α=int, β=bool이다. 결과는 첫 인자인 int 7이다.

  4. (2,5)는 int×int이며 α=int로 두 자리의 타입을 일치시킨다. 값이 같을 필요는 없다.

예상 결과 7:int, true:bool, 7:int. (2,5)는 같은 타입 쌍 조건을 만족한다.

조건을 바꾸어 비교하기

결과를 모으는 방법이 타입을 바꾼다

let id=fun x->x 뒤 (id 2,id true)와 [id 2;id true]를 비교하라. 목록은 동종이고 쌍의 두 타입은 독립이다.

  1. 첫 호출 결과는 Int, 둘째 결과는 Bool이다. 쌍은 이 둘을 Int×Bool로 기록한다.

  2. 목록은 원소 타입 T 하나를 쓰므로 T=Int와 T=Bool을 모두 요구한다. 기본 타입이 달라 단일화가 실패한다.

쌍은 허용되지만 이 동종 목록은 거부된다. 호출 자체와 바깥 결합 규칙의 실패 위치를 나눈다.

비교할 점

다형 함수를 두 번 호출할 수 있다는 사실을 이질 자료구조 허용으로 확대하지 않는다.

독립 변수와 반복 변수는 다른 계약이다

fst:∀ab.(a×b)→a와 same:∀a.(a×a)→a를 (2,5) 및 (2,true)에 각각 적용하라. 두 구현은 첫 값을 반환한다.

  1. fst는 첫 쌍에 a=b=Int, 둘째 쌍에 a=Int와 b=Bool을 선택한다. 두 경우 결과는 2:Int다.

  2. same은 (2,5)에 a=Int를 선택할 수 있으나 (2,true)에서는 하나의 a를 Int와 Bool로 정할 수 없다.

fst의 두 적용과 same의 정수 쌍 적용만 허용된다. 2와 5가 서로 다르다는 것은 same의 타입 거부 이유가 아니다.

비교할 점

타입 변수 이름이 다르다는 것과 반드시 다른 구체 타입이라는 것을 구별한다.

종이와 본문으로 직접 해보기

const true 9와 const 4 8의 타입 변수 선택을 적고, (4,false)가 α×α에 맞는지 판단하라. 숫자 변환·오버로딩은 없다.

힌트 보기

결과는 첫 인자다. 타입 변수끼리 다른 이름이어도 동일한 타입을 골라도 된다.

풀이 보기

첫 호출은 α=bool, β=int로 true:bool이다. 둘째는 α=β=int로 4:int이다. (4,false)는 int와 bool이 달라 α×α에 맞지 않는다.

오해와 반례

α가 두 번 나오면 입력과 출력 값도 같아야 한다는 일반 규칙이다.

반복 α는 타입 동일성을 요구한다. α×α의 (2,5)는 타입은 같고 값은 다르다. id의 값 동일성은 그 함수 구현이 x를 반환하기 때문에 성립한다.

자기점검

id에 int를 선택하면 타입은?

답과 이유 보기

int→int

같은 α 두 곳에 동일한 타입을 치환한다.

const에서 α와 β가 모두 int여도 되는가?

답과 이유 보기

된다.

독립 선택은 서로 다름을 강제하지 않는다.

x+1이 모든 α에 가능한가?

답과 이유 보기

이 모형에서는 아니다.

정수 덧셈이 x:int 제약을 만든다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

let id=fun x->x에서 [id 2;id 5]와 (id true,id false)의 타입과 이론 값을 구하라.

힌트 1

동종 목록에서는 두 결과가 모두 Int다.

힌트 2

쌍의 두 결과는 Bool이며 값은 별도로 추적한다.

풀이와 답 확인

  1. 목록은 [2;5]:Int list다. 별도 사용의 변수가 모두 Int로 선택되어도 문제가 없다.

  2. 쌍은 (true,false):Bool×Bool이다. 같은 타입의 두 값이 서로 같아야 할 규칙은 없다.

각 자료구조의 타입과 값 배열을 따로 보고한다.

흔한 오답에서 다시 생각하기

새 타입 변수는 매번 서로 다른 타입으로 정해야 한다.

새 이름은 독립 선택을 허용할 뿐 차이를 강제하지 않는다.

연습 2 · 오류 찾아 고치기

[id 2;id true]의 거부를 고치려고 모든 id 사용에 하나의 새 변수 a를 공유하게 했다. 이 수정이 문제를 해결할까?

힌트 1

공유하면 첫 호출과 둘째 호출의 제약부터 충돌한다.

힌트 2

목록의 원소 규칙도 여전히 남는다.

풀이와 답 확인

  1. 공유 a에는 첫 호출에서 Int, 둘째에서 Bool이 요구되어 호출 추론 자체가 실패한다.

  2. 정상적인 인스턴스화로 되돌려도 목록 규칙은 이질 결과를 거부하므로 표시 구조를 새로 설계해야 한다.

새 변수를 공유하는 수정은 해결이 아니라 다형 사용을 부당하게 제한한다.

흔한 오답에서 다시 생각하기

목록이 하나이므로 함수 스키마도 한 번만 인스턴스화해야 한다.

이름 사용의 새 변수와 목록의 공통 원소 타입은 서로 다른 규칙이다.

연습 3 · 직접 만들어 보기

동종 목록으로 정수 2와 Bool true를 보존하려고 새 대수 타입 Item=I of Int | B of Bool을 설계한다. [I(id 2);B(id true)]의 제약과 보존되는 의미를 적어라.

힌트 1

각 생성자의 입력 타입을 먼저 검사한다.

힌트 2

목록이 모으는 최종 타입은 Item이다.

풀이와 답 확인

  1. id 2:Int는 I의 Int 입력, id true:Bool은 B의 Bool 입력을 만족한다. 각 생성 결과는 Item이다.

  2. 목록 원소 타입 T=Item 하나로 합쳐지고, 태그 I/B가 각각의 값 종류를 보존한다.

새 표현은 Item list이며 태그를 제거하지 않고 나중에 분기한다. 기존 언어의 임의 자동 변환으로 보지 않는다.

흔한 오답에서 다시 생각하기

Bool을 숫자 1로 바꾸면 원래 의미도 언제나 그대로다.

이 설계는 true와 정수 1을 서로 다른 태그로 유지하므로 합치는 변환과 다르다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

순수·종료하는 언어에서 ∀ab.(a×b)→a의 구현이 a에 Int 덧셈을 적용하려 한다. 모든 인스턴스에 가능한가? 효과·비종료를 더하면 타입만으로 총 반환을 증명할 수 있을까?

힌트 1

a에는 Bool도 선택할 수 있다.

힌트 2

타입의 분류와 종료 보장은 다른 가정이다.

풀이와 답 확인

  1. Int 전용 덧셈은 a=Int를 요구하여 원래 모든 a라는 스키마보다 좁아진다. fst는 첫 값을 그대로 반환하므로 그 제약이 필요 없다.

  2. 비종료나 예외를 허용한 새 언어에서는 해당 타입을 가졌다고 정상 반환이 보장되지는 않는다. 전체 매개변수성 주장은 효과와 종료 가정을 함께 명시해야 한다.

구현의 제약과 타입의 보편 범위를 비교하고 새 효과에 대한 정리를 임의로 복사하지 않는다.

흔한 오답에서 다시 생각하기

반환 타입 a가 있으니 정상 값 a를 반드시 만들어 낸다.

정상 반환 시 타입과 항상 정상 반환한다는 명제는 다르다.

내 말로 설명하기

독립 id 두 사용이 되면 이질 목록도 되는가?

설명 기준 확인

아니다. 동종 목록이 결과 타입을 다시 하나로 묶는다.

a와 b가 다른 이름이면 다른 타입인가?

설명 기준 확인

독립 선택이며 둘 다 Int를 골라도 된다.

한 단계 더

∀α.α→α라는 타입만으로 구현의 행동을 추론하는 매개변수성으로 확장하자. 비종료·예외·가변 상태 같은 효과를 허용하면 어떤 추가 가정이 필요한지 먼저 적는다. 이 단원의 자체 계산은 코드 실행 증거가 아니다.

등식 하나를 해결한 뒤 남은 등식도 바꿨는가?

단일화의 한 치환은 최종 답 목록에 적는 것으로 끝나지 않는다. α=β를 풀고 남은 β=Int를 풀면 α에도 뒤 치환을 합성해 Int를 얻어야 한다. S가 α↦β, T가 β↦Int일 때 S 뒤 T는 α를 Int로 만들지만, 반대로 적용하면 처음 α에는 T가 영향을 주지 못하고 나중 S가 β를 남긴다. 적용 순서와 최종 치환의 정규화 상태를 구별한다.

늦게 발견되는 자기 포함도 검사해야 한다. α=β→Int와 β=α는 처음 등식 하나만 보면 함수 타입으로 치환 가능하다. 그러나 남은 등식에 넣으면 β=β→Int가 되어 occurs check가 실패한다. 입력 제약이 순환인지 검사하지 않고 변수 이름만 서로 바꾸면 유한 타입이라는 전제를 어긴다. 재귀 타입을 갖춘 다른 언어의 허용 규칙은 여기에 가져오지 않는다.

같은 함수 인자 f를 두 번 사용하는 fun f->fun x->(f x,f true)는 두 f의 타입을 공유한다. x:A, 두 결과 R/S로 놓으면 f:A→R와 f:Bool→S의 단일화가 A=Bool과 R=S를 요구한다. 전체 타입은 (Bool→R)→Bool→(R×R)다. 결과가 같은 타입이라고 같은 값이라는 것은 아니다. 함수 정의가 없는 상황에서 구체 값을 추측하지 않는다.

먼저 확인할 개념

    각 해결 단계를 모든 남은 제약과 결과 타입에 적용한다.

    함수 인자 f는 별도 다형 let 스키마와 다르다.

실행 전에 제약 만들기

타입 추론은 프로그램을 실행해 값의 타입을 시험하는 과정이 아니다. 각 부분식에 새 타입 변수를 붙이고 문법과 연산으로 등식을 만든다. f x의 결과를 β라고 하면 f의 타입은 x의 타입 α를 받아 β를 반환하는 α→β여야 한다.

동일한 변수 결합을 읽는 두 위치는 같은 타입을 공유한다. 정수 덧셈은 두 피연산자를 int로 제한한다. 실제 언어의 연산 오버로딩과 재귀 타입 등은 제외한 단순 유한 함수 타입 모형이므로 그 조건을 알고 계산한다.

등식의 구조를 벗겨내기

단일화는 모든 타입 등식을 동시에 참으로 만드는 치환을 찾는 절차다. α→β = int→γ라면 입력끼리 α=int, 결과끼리 β=γ로 나눈다. β=bool을 알면 γ도 bool로 갱신하며 나머지 등식 전체에 치환을 적용한다.

int=bool 같은 서로 다른 기본 타입은 실패한다. α=α→β도 유한 타입 모형에서 실패한다. α 안에 α가 다시 들어가는지 확인하는 occurs check를 생략하면 끝없이 큰 타입을 만들거나 잘못된 결과를 얻는다. 단순히 등식 하나만 지우고 성공 처리할 수 없다.

함수 사용을 연결해 추론하기

fun f -> fun x -> f (f x)에서 x의 타입을 α라고 하자. 안쪽 f x 결과를 β라 하면 f:α→β이다. 바깥 f는 그 β를 입력으로 받으므로 같은 f에 β→γ도 요구된다. 입력을 비교하면 α=β이고 결과를 비교하면 β=γ다.

따라서 f:α→α, 전체 함수는 (α→α)→α→α이다. 화살표는 오른쪽으로 묶는다. int를 선택한 경우에도 숫자 계산을 실행한 것이 아니라 타입 가능성을 확인한 것이다. 잘못된 제약을 만들면 단일화기가 정확해도 잘못된 추론이 된다.

  2. β=bool을 모든 등식에 넣으면 γ=bool이다.

  3. γ=δ에 다시 치환해 δ=bool을 얻는다. 최종 함수 타입은 int→bool이다.

  4. α=α→β는 occurs check, int=bool은 기본 타입 불일치로 각각 실패한다.

치환 α↦int, β↦bool, γ↦bool, δ↦bool. 두 추가 집합은 모두 실패하지만 이유는 서로 다르다.

순서가 다른 합성은 같은 기록이 아니다

S:α↦β와 T:β↦Int를 α와 β에 S 뒤 T, T 뒤 S 순서로 각각 적용하라.

  1. S 뒤 T에서 α는 β를 거쳐 Int가 되고 β도 Int가 된다.

  2. T 뒤 S에서 α는 처음 그대로였다가 β가 되며 β는 처음 Int로 바뀌어 그대로 남는다.

첫 합성은 α와 β 모두 Int다. 역순 합성은 α를 β, β를 Int로 보내는 한 번의 순차 적용이다. 역순 결과에 치환을 다시 적용하는 것은 추가 단계다.

일반화·인스턴스화

id 0과 id true가 함께 되는데 함수 인자 f에는 왜 같은 규칙을 바로 적용하지 않을까?

준비 개념과 학습 목표

준비 개념

  • 타입 변수와 단일화

  • let 결합

  • 함수 인자

학습 목표

  • 환경에 남는 변수를 일반화에서 제외한다.

  • 각 사용의 새 타입 변수와 공유 변수를 추적한다.

환경을 옛날 그대로 두면 무엇을 잘못 자유롭게 만들까?

Γ={h:α}에서 e1=fun y->h y를 추론하자. y:B와 결과 C를 두면 α=B→C 제약이 생기고 e1 타입은 B→C다. 단일화 S를 환경에도 넣으면 h:B→C가 된다. 따라서 새 타입의 B/C는 모두 갱신된 환경에도 나타나므로 일반화할 변수가 없다. 옛 환경의 자유 변수 {α}만 빼면 B/C를 잘못 일반화하여 바깥 h를 서로 다른 함수처럼 사용하게 된다.

fun h->let f=fun y->h y in (f 0,f true)는 그 실수를 드러낸다. f의 입력 B는 h의 입력과 공유되므로 B=Int와 B=Bool을 동시에 요구해 거부된다. 반대로 바깥 h를 사용하지 않는 순수 let f=fun y->y는 환경에 없는 변수를 일반화할 수 있다. 자유롭게 일반화한다는 말은 식이 이미 바깥 객체와 맺은 타입 관계를 끊는다는 뜻이 아니다.

참조를 추가하는 경우는 순수 let 공식의 범위를 더 제한한다. r=ref id 하나를 만들고 s=r로 이름만 추가해도 두 이름은 같은 저장 칸이다. 한 이름으로 Int→Int 함수 succ를 넣고 다른 이름으로 Bool을 적용하는 것을 각각 독립 인스턴스로 허용하면 저장한 함수의 계약과 충돌한다. OCaml의 value restriction은 이런 경우 약한 타입 변수를 하나로 유지한다. 여기서는 이 공유 반례만 설명하며 실제 언어의 완전한 relaxed value restriction을 구현했다고 주장하지 않는다.

먼저 확인할 개념
  • 갱신된 환경을 뺀 일반화

    SΓ에 이미 나타나는 변수는 새 스키마에서 묶지 않는다.

  • 적용이 만드는 함수 제약

    h y의 새 변수들이 기존 h 타입에 연결됨을 도출한다.

타입 스키마로 묶기

순수 Hindley–Milner 모형에서 let의 오른쪽을 추론하고 제약을 먼저 푼다. 얻은 치환 S를 그 타입과 기존 타입 환경 Γ 모두에 적용한다. 새 타입에서 자유롭게 등장하지만 갱신된 환경에는 없는 타입 변수만 ∀로 일반화한다.

기호로 Gen(SΓ,Sτ)=∀(ftv(Sτ)−ftv(SΓ)).Sτ이다. ftv는 자유 타입 변수 집합이다. 환경의 변수는 바깥 코드와 같은 하나의 타입을 뜻하므로 마음대로 복제하면 안 된다. 모든 변수에 무조건 ∀를 붙이는 규칙은 안전하지 않다.

사용할 때 새 이름으로 풀기

∀α.α→α인 id를 사용할 때는 묶인 α를 아직 쓰이지 않은 β로 바꿔 β→β를 얻는다. 다른 사용에는 새 γ→γ를 만든다. id 0은 β=int, id true는 γ=bool이 되어 서로 충돌하지 않는다.

∀β.β→α에서 β는 묶였지만 α는 자유다. 두 사용은 β1→α와 β2→α이며 결과 α를 공유한다. 인스턴스화는 모든 글자를 새로 만드는 작업이 아니다. 무엇이 ∀ 안에 묶였는지 확인해야 한다.

모형의 경계와 가변 상태

함수 인자 f는 이 기본 모형에서 단일 타입을 가진다. fun f -> (f 0, f true)는 같은 입력 타입에 int와 bool을 요구해 실패한다. 순수 let id=fun x->x in (id 0,id true)는 일반화된 사용을 두 번 인스턴스화해 성공한다.

가변 참조를 추가하면 let이라고 모두 일반화할 수 없다. r=ref id에 int→int 함수를 저장하고 r의 값을 bool에 적용하면 위험하다. OCaml의 value restriction과 약한 타입 변수는 이런 공유 상태의 타입을 제한한다. 여기의 기본 공식은 순수 모형에 한정하며 실제 언어의 완전한 제한 규칙은 별도다.

let id = fun x -> x in (id 0, id true)
(* 순수 모형 예상 타입 int×bool *)
같은 함수와 같은 저장 칸을 유지하는 연결

B/C가 새 이름이라는 이유만으로 일반화하지 않는다. 셋째 행에서 두 변수는 이미 h를 통해 바깥 환경에 연결된다. 마지막 행은 이름 둘과 객체 둘을 구별하며 참조의 내용 타입을 일관되게 유지한다.

중간 과정을 따라가는 예제

갱신된 환경 Γ에 y:α가 있고 오른쪽 식의 타입이 β→α이다. 일반화할 변수와 두 번 사용한 타입을 구하라. 첫 사용의 입력을 int, 둘째를 bool로 정한다.

  1. ftv(β→α)={β,α}, ftv(Γ)={α}이다.

  2. 차집합은 {β}이므로 스키마는 ∀β.β→α다.

  3. 각 사용은 새 β1→α, β2→α다. 입력 제약으로 β1=int, β2=bool을 정한다.

  4. 결과 α는 두 사용이 공유한다. 첫 결과가 int로 제한되면 둘째 결과도 int여야 한다.

일반화는 β만, 두 사용은 int→α와 bool→α이며 결과 타입은 공유한다.

조건을 바꾸어 비교하기

환경에 치환을 적용하지 않은 일반화의 반례

Γ={h:α}, e1=fun y->h y에서 올바른 일반화와 옛 환경으로 계산한 잘못된 일반화를 비교하라.

  1. S는 α↦B→C다. 식 타입과 갱신된 환경 h:B→C의 자유 변수 집합은 모두 {B,C}다. 차집합은 빈 집합이다.

  2. 옛 환경의 자유 변수 {α}를 빼면 {B,C}가 남는다고 계산하여 ∀BC.B→C를 잘못 만들 수 있다. 이 스키마는 h의 공유 계약을 지워 버린다.

올바른 f는 B→C라는 단일 타입이다. 갱신된 환경에서만 일반화할 변수를 계산한다.

비교할 점

단순히 모든 새 변수에 ∀를 붙이는 오류보다 환경 갱신 누락의 원인을 구체화한다.

참조의 이름을 늘려도 저장 함수는 하나다

r=ref id; s=r; s:=succ 뒤 !r true를 허용하는 것이 왜 위험한가? succ는 Int→Int다.

  1. r과 s가 같은 저장 칸이라는 참조 관계를 그린다. s를 통한 저장으로 그 칸의 함수 계약은 Int→Int에 맞아야 한다.

  2. !r에서 읽는 것도 같은 함수이므로 true:Bool은 그 입력과 맞지 않는다. 함수 객체 둘을 독립 구성한 사례와 다르다.

현재 공유 저장 계약에서는 거부한다. 실제 실행 오류를 관측한 것이 아니라 타입 조건과 별칭 관계의 이론 반례다.

비교할 점

순수 이름의 인스턴스화와 가변 객체의 내용 타입을 동일 규칙으로 다루지 않는다.

종이와 본문으로 직접 해보기

환경이 비어 있고 τ=α→α이면 스키마는? 반대로 환경 z:α가 있으면? 또한 fun x -> let f=fun y->x in (f 0+1, not(f true))가 기본 정수 +와 bool not 아래 가능한지 판단하라.

힌트 보기

환경 자유변수를 빼고, f가 돌려주는 x의 타입이 두 사용에서 공유되는지 본다.

풀이 보기

빈 환경에서는 ∀α.α→α, z:α가 있으면 α를 일반화하지 않는다. 마지막 식은 x를 첫 결과에서 int, 둘째에서 bool로 동시에 요구해 실패한다. f의 입력 타입만 일반화해도 결과 x의 타입은 공유한다.

오해와 반례

let 이름의 모든 타입 변수는 각 호출에서 자유롭게 바꿔도 된다.

환경 y:α에서 ∀β.β→α의 결과 α는 공유된다. 이를 새 α1,α2로 바꾸면 바깥 y가 동시에 int와 bool인 모순을 숨겨 버린다.

자기점검

일반화 전에 환경에도 S를 적용하는가?

답과 이유 보기

그렇다.

오른쪽 제약이 알려 준 환경 타입 정보를 반영해야 한다.

∀β.β→α의 α도 매번 새로 만드는가?

답과 이유 보기

아니다.

묶인 β만 새로 만들고 자유 α는 공유한다.

가변 참조도 순수 let 규칙으로 늘 일반화하는가?

답과 이유 보기

아니다.

공유 가변 상태에는 value restriction 같은 추가 제한이 필요하다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

갱신된 Γ={z:A}, 식 타입 B→A를 일반화하고 두 사용의 입력을 Int/Bool로 정하라. 첫 결과에 Int 요구도 추가한다.

힌트 1

환경에 있는 A는 묶이지 않는다.

힌트 2

묶인 B만 각각 새 입력 변수로 만든다.

풀이와 답 확인

  1. 스키마는 ∀B.B→A다. 두 사용은 Int→A와 Bool→A가 된다.

  2. 첫 결과를 Int로 제한하면 공유 A=Int이며 둘째 결과도 Int다.

독립 입력 Int/Bool과 공유 결과 Int를 구별한다.

흔한 오답에서 다시 생각하기

둘째 결과 A도 새 변수로 만들어 Bool이어도 된다.

자유 A는 바깥 z와 연결되어 두 사용에서 유지된다.

연습 2 · 오류 찾아 고치기

fun h->let f=fun y->h y in (f 0,f true)의 f를 ∀BC.B→C로 만들었다. 잘못된 일반화 단계와 실제 모순을 적어라.

힌트 1

h 타입에 적용한 치환을 환경에서 확인한다.

힌트 2

두 f의 입력 요구가 같은 h 입력을 제한한다.

풀이와 답 확인

  1. h:α에 S를 적용하면 h:B→C다. B/C를 일반화에서 제외해야 하지만 갱신 전 환경을 써서 놓쳤다.

  2. 올바른 f의 공유 B에 Int와 Bool을 동시에 요구하므로 이 식은 거부된다.

환경 갱신 누락을 고치고 두 입력의 충돌을 드러낸다.

흔한 오답에서 다시 생각하기

바깥 h는 아직 실행되지 않았으니 타입 연결도 없다.

정적 적용 규칙이 실행 전에 그 연결을 이미 만든다.

연습 3 · 직접 만들어 보기

외부 h와 무관한 순수 f를 만들어 (f 0,f true)를 허용하라. 같은 h를 계속 호출하는 함수의 이름만 바꾸어 해결했다고 하지 않는다.

힌트 1

함수 몸체에서 h를 읽지 않는다.

힌트 2

입력 값을 그대로 돌려주는 새 순수 함수로 구성한다.

풀이와 답 확인

  1. let f=fun y->y를 선택한다. 입력 타입 B가 갱신된 외부 환경에 없다면 ∀B.B→B로 일반화한다.

  2. 두 사용을 새 B₁/B₂로 만들면 첫 결과 Int, 둘째 결과 Bool로 쌍 Int×Bool을 얻는다.

이는 기능을 바꾼 새 설계다. 원래 h 호출 의미까지 보존한 수정이라고 주장하지 않는다.

흔한 오답에서 다시 생각하기

타입 검사를 통과하면 h 호출 제거도 원래 동작 보존이다.

타입 허용과 외부 함수의 값·효과 계약 보존은 별도다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

∀B.B→A에서 이름 B가 이미 다른 제약에 쓰였다. 인스턴스화에 그 이름을 재사용하면 어떤 충돌이 생길 수 있을까? A까지 새로 바꾸는 것도 허용되는가?

힌트 1

묶인 변수에 아직 쓰이지 않은 이름을 고른다.

힌트 2

자유 변수 A는 같은 외부 정보를 뜻한다.

풀이와 답 확인

  1. 이미 Int로 제한된 B를 재사용하면 새 Bool 입력 사용이 부당하게 Int=Bool 충돌을 일으킬 수 있다. 새 B₁를 골라야 한다.

  2. A는 새 이름으로 바꾸지 않는다. 이를 A₁로 바꾸면 외부 결과 타입의 공유를 끊어 잘못된 프로그램을 허용할 수 있다.

이름 충돌 방지와 자유 변수 보존을 둘 다 만족해야 한다.

흔한 오답에서 다시 생각하기

인스턴스화는 타입 식의 모든 문자를 무조건 바꾼다.

∀로 묶인 변수와 자유 변수는 다른 역할이다.

내 말로 설명하기

일반화 전에 환경에도 치환을 넣는 이유는?

설명 기준 확인

새 변수와 기존 이름이 연결된 관계를 자유롭게 복제하지 않기 위해서다.

참조 r와 별칭 s는 독립 다형 저장 칸인가?

설명 기준 확인

아니다. 같은 칸의 내용 타입을 일관되게 유지해야 한다.

한 단계 더

r=ref id, r:=succ, !r true를 타입 카드로 추적하자. succ:int→int를 저장한 뒤 참조 안 함수의 입력은 int로 고정된다. true 적용을 정적으로 거절하는 이유를 설명하되 실행 오류를 실제 관측했다고 쓰지 않는다.

다른 문제에 적용하기

독립 사용과 공유 제약의 경계 복원

순수 Int/Bool·쌍·동종 목록 모형에서 새 let id=fun x->x의 (id 2,id true)와 [id 2;id true]를 비교한다. S:α↦β, T:β↦Int의 두 순서 합성을 α/β에 한 번씩 적용하고, α=β→Int 및 β=α의 전체 집합을 판정한다. Γ={h:α}에서 let f=fun y->h y의 SΓ와 일반화 집합을 계산한 뒤 f 0/f true가 충돌하는 이유를 설명한다. 마지막은 별도 가변 참조 확장이다. r=ref id, s=r, s:=succ, !r true를 같은 칸 그림으로 판정한다. 각 비교는 새 환경에서 시작하며 실제 OCaml·추론기·참조 실행·학생 시험은 미수행이다.

힌트 1

호출의 새 변수와 바깥 목록의 공통 원소 변수를 나눈다. 합성은 왼쪽 작업 뒤 오른쪽 작업으로 실제 대입한다.

힌트 2

h에 연결된 B/C를 SΓ에서 찾고, r/s는 이름 둘이어도 같은 저장 칸임을 표시한다.

풀이와 답 확인

  1. 쌍은 Int×Bool로 허용된다. 목록은 두 결과를 공통 원소 타입으로 묶어 Int=Bool 때문에 거부된다.

  2. S 뒤 T는 α/β 모두 Int다. T 뒤 S의 한 순차 적용은 α를 β, β를 Int로 보낸다. 순환 집합은 첫 치환 뒤 β=β→Int가 되어 유한 타입에서 실패한다.

  3. h y는 α=B→C를 요구한다. SΓ={h:B→C}이므로 식의 {B,C}에서 환경의 {B,C}를 빼면 일반화 집합은 빈 집합이다. f의 공유 입력 B가 Int와 Bool을 동시에 요구해 실패한다.

  4. r/s 같은 칸에 succ:Int→Int를 저장한 뒤 Bool true를 입력하면 계약 불일치다. 순수 let의 독립 인스턴스화를 공유 가변 내용에 그대로 적용하지 않는다.

독립 이름 사용, 결합 자료구조, 하나의 함수 인자, 갱신된 환경과 같은 저장 칸 각각에서 무엇을 공유하는지 명시해야 한다.

해결한 뒤 점검할 것

  • 쌍과 목록을 호출 실패와 결합 규칙 실패로 구별한다.

  • 두 합성 결과를 변수별로 적고 늦은 occurs check 위치를 설명한다.

  • SΓ와 빈 일반화 집합을 계산하고 공유 입력 충돌을 기록한다.

  • 참조 별칭·내용 타입을 그림으로 보존하며 실제 언어 실행 및 학생 미수행을 유지한다.
