소단원 9.1

메모리 저장소 모델

같은 이름을 쓰면서 값이 바뀌는 현상을 치환만으로 설명할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 변수와 바인딩

  • 함수와 값

학습 목표

  • 환경과 저장소의 역할을 구별한다.

  • 할당·읽기·갱신을 상태표로 추적한다.

참조를 담은 셀을 복사하면 안쪽 셀도 새로 만들어질까?

이 보강은 앞 본문의 순차 의사 언어를 확장한다. ref(v)는 매번 새 위치를 할당하고 read(r)는 그 셀의 값을, write(r,v)는 셀의 새 내용을 정한다. 값으로 정수 또는 다른 위치를 저장할 수 있다. 환경 바인딩은 불변이며 let p = e는 새 범위의 이름 연결을 만든다. 모든 접근은 유효하고 할당 실패·동시 실행·기계 주소 계산은 제외한다. 각 표와 과제는 명시한 초기 상태에서 독립적으로 시작한다.

a = ref(4), box = ref(a), copy = ref(read(box))를 차례로 만들자. 위치 이름은 a가 ℓ1, box가 ℓ2, copy가 ℓ3를 가리킨다. 저장소는 ℓ1에 정수 4, ℓ2와 ℓ3에 같은 위치 ℓ1을 담는다. 바깥 셀 두 개가 독립이어도 안쪽 정수 셀은 공유한다. write(read(copy),9)는 ℓ1을 바꾸므로 read(read(box))도 9다. 단순히 ref를 한 번 더 썼다고 모든 깊이의 공유가 없어지는 것은 아니다.

앞 갱신을 이어받지 않고 새 a = ref(4), box = ref(a)에서 q = ref(read(read(box)))를 만들면 정수 값을 새 셀에 담는다. 이 독립 사례에서는 q가 새 셀에 정수 4를 담고, q를 9로 바꿔도 a의 값 4는 유지된다. 안쪽 값에 참조가 또 있다면 이 단계도 완전한 깊은 복사가 아닐 수 있다. 여기서는 셀 위치의 동일성과 현재 정수 값의 동일성을 분리하고, 범위를 벗어난 이름이 아니라 살아 있는 연결 경로로 도달 가능성을 묻는다.

먼저 확인할 개념
  • 환경과 저장소의 두 표

    이름이 위치를 가리키는 연결과 셀 내용의 변경을 나눈다.

  • 값 안에 남는 별칭

    바깥 복사가 내부 참조의 공유를 제거하는지 확인한다.

이름표와 보관함을 따로 그리기

변수 이름을 값으로 바꾸어 읽는 치환 모델은 순수 계산을 이해하는 데 유용하다. 상태 변경을 다룰 때는 이름표와 실제 보관함을 나누어 생각하자. 환경 ρ는 이름이 무엇을 가리키는지, 저장소 σ는 위치에 어떤 값이 있는지 기록한다.

이 단원의 작은 언어에서는 참조 이름이 위치 ℓ를 가리키고 σ(ℓ)가 현재 값이다. ρ(x)=ℓ1, σ(ℓ1)=4라면 x의 보관함을 읽을 때 4를 얻는다. ℓ1은 종이 모델의 위치 이름이며 실제 기계 주소 숫자가 아니다.

만들기·읽기·바꾸기를 분리하기

ref(4)는 새 위치를 만들어 초기값 4를 저장하고 그 위치를 반환한다. read(x)는 x가 가리키는 위치의 현재 값을 읽는다. write(x,9)는 그 위치의 내용을 9로 바꾸되 위치를 새로 만들지 않는다. 이 표기는 모델 설명용 의사 언어다.

참조 복사 y=x는 같은 위치를 다른 이름으로 가리킨다. 별도 ref(4)를 만드는 것과 값이 같다는 이유로 혼동하지 않는다. 위치의 동일성과 저장한 값의 동일성은 서로 다른 질문이다.

x = ref(4)
y = x
z = ref(4)
write(y, 9)
read(x), read(z)

결과와 다음 상태를 함께 반환하기

상태를 쓰는 표현식의 평가는 결과뿐 아니라 다음 저장소도 만든다. ⟨e,ρ,σ⟩ ⇓ ⟨v,σ′⟩처럼 적으면 write가 남긴 효과를 이후 read에 전달할 수 있다. 같은 입력처럼 보이는 함수도 숨은 저장소가 다르면 결과가 달라질 수 있다.

환경 바인딩을 바꾸는 일과 보관함의 내용을 바꾸는 일은 언어에 따라 다르게 정의된다. OCaml ref 설명에서는 바인딩이 아니라 셀 내용이 변경된다. 다른 언어의 변수 대입 규칙을 이 모델에 그대로 섞지 않고 사용하는 문법과 상태 규칙을 먼저 정한다.

마지막 행은 앞 행에 이어서 실행한다. 새 ℓ4의 정수는 2다. 바깥 위치 ℓ2와 ℓ3는 끝까지 다르며 둘째 행에서는 내용으로 같은 ℓ1을 담는다. 정수 한 번 읽기와 참조를 따라 두 번 읽기를 구분한다.

중간 과정을 따라가는 예제

의사 코드의 초기 저장소는 비어 있고 할당마다 다른 위치를 얻는다. 마지막 두 읽기와 환경·저장소를 구하라.

  1. x=ref(4)에서 ρ(x)=ℓ1, σ(ℓ1)=4다.

  2. y=x는 ρ(y)=ℓ1을 추가한다. 새 셀은 만들지 않는다.

  3. z=ref(4)는 새 ℓ2를 만들고 σ(ℓ2)=4다.

  4. write(y,9)는 σ(ℓ1)=9로 갱신한다. x와 y의 환경 연결은 유지된다.

환경 x/y→ℓ1,z→ℓ2이며 저장소 ℓ1=9,ℓ2=4다. 두 읽기는 9와 4다.

조건을 바꾸어 비교하기

바깥 셀의 독립성과 안쪽 정수의 공유

초기 a=ref(4), box=ref(a), copy=ref(read(box))에서 write(read(copy),9)를 수행하라.

  1. read(copy)는 정수 4가 아니라 위치 ℓ1을 반환한다.

  2. 그 위치의 셀을 9로 갱신한다. box와 copy의 바깥 내용은 여전히 ℓ1이다.

a의 읽기는 9이고 box와 copy를 각각 두 번 읽어도 9다. 셀은 세 개다.

비교할 점

외부 셀의 정체성이 다르다는 것과 모든 도달 셀이 분리된다는 것은 다르다.

정수까지 읽은 뒤 새 셀을 만든다

앞 예제의 실행을 이어받지 않고 새 a=ref(4), box=ref(a)에서 q=ref(read(read(box))) 뒤 write(q,9)를 수행하라.

  1. 두 번 읽어 얻은 값은 정수 4다. 새 q 셀에는 그 정수를 담는다.

  2. q의 셀만 9로 바뀌고 a의 셀은 4다.

a는 4, q는 9다. box가 가리키는 안쪽 셀도 여전히 a다.

비교할 점

이 정수 사례의 독립 복사는 더 깊은 참조 자료의 일반 깊은 복사 증명이 아니다.

종이와 본문으로 직접 해보기

write(z,2)를 추가한 뒤 read(y)와 read(z)를 계산하라.

힌트 보기

환경 연결은 그대로 두고 어느 저장소 칸을 바꾸는지 표시한다.

풀이 보기

z는 ℓ2를 가리키므로 ℓ2만 2로 바뀐다. y는 ℓ1=9를 읽고 z는 2를 읽는다.

오해와 반례

초기값이 같은 두 ref는 같은 위치다.

새 할당은 새로운 위치를 만든다. x와 z는 모두 처음 4지만 z의 갱신이 x에 영향을 주지 않는 반례다.

힌트 1

힌트 2

풀이와 답 확인

별칭·가변성·순서

두 이름의 값이 함께 바뀌면 복사에 실패한 걸까, 같은 곳을 보고 있는 걸까?

준비 개념과 학습 목표

준비 개념

  • 참조 위치

  • 순차 실행

학습 목표

  • 별칭의 관찰 효과를 설명한다.

  • 효과가 있는 연산의 순서 변경을 평가한다.

서로 다른 셀에 쓰는 두 작업도 언제 순서가 중요할까?

단순히 쓰기 대상이 다르다는 사실만으로 작업을 교환할 수는 없다. 초기 a=ref(1), b=ref(2)에서 A는 write(a,read(b)+1), B는 write(b,read(a)+1)이다. A 뒤 B는 a가 3이 된 후 그 값을 읽어 b를 4로 만든다. B 뒤 A는 b가 2로 다시 쓰인 뒤 a를 3으로 만들어 최종 (3,2)다. 쓰기 위치가 달라도 상대 작업이 읽는 위치와 겹친다.

읽기 집합 R과 쓰기 집합 W를 기록해 효과를 비교하자. 정상 종료하는 결정적 작업, 유효한 셀, 고정 외부 입력, 예외·할당·출력·동시 실행 없음이라는 제한 아래 W_A가 R_B와 W_B에 닿지 않고 W_B가 R_A와 W_A에 닿지 않는 조건은 독립 교환을 설명하는 충분조건이다. 반환값을 모으는 외부 순서도 같은 계약으로 보존해야 한다. 조건이 깨졌다고 모든 상태에서 반드시 결과가 달라진다는 필요조건은 아니다.

예를 들어 A가 a를 3으로, B가 b를 4로 상수 대입하고 두 위치가 다르면 두 순서 모두 (3,4)다. 그러나 이름 a와 b가 같은 셀의 별칭이면 마지막 대입이 남아 A 뒤 B는 4, B 뒤 A는 3이다. 일반 인수 평가 순서가 지정되지 않은 언어에서 효과 함수 둘을 수학적 덧셈처럼 교환하지 않는다. 필요한 순서는 let이나 순차 문장으로 직접 고정하며 아래는 문장 순서가 명시된 자체 모형이다.

같은 보관함으로 가는 두 화살표

별칭은 여러 접근 경로가 같은 저장 위치를 가리키는 관계다. 이름이 다르더라도 한쪽을 통해 변경하면 다른 쪽에서 새 값을 관찰할 수 있다. 이것은 값 복사와 달리 접근 경로가 공유된다는 뜻이다.

가변성은 저장 내용을 바꿀 수 있다는 성질이다. 별칭만 있고 값이 불변이면 관찰이 단순하지만, 별칭과 가변성이 함께 있으면 함수가 어떤 공유 상태를 바꾸는지 알아야 결과를 이해할 수 있다.

순서를 바꾸면 읽는 시점이 달라진다

초기 r의 내용이 3일 때 write(r,8) 다음 read(r)는 8을 읽는다. 반대로 먼저 읽어 old에 저장하고 그 뒤 갱신하면 old는 3이다. 마지막 저장소가 같아도 표현식의 반환값이나 외부 기록은 다를 수 있다.

덧셈이 수학적으로 교환 가능하더라도 그 항을 계산하는 함수가 상태를 바꾸면 호출 순서를 마음대로 바꿀 수 없다. 특정 언어의 인자 평가 순서가 명시되지 않은 경우에는 기대 순서를 문장이나 순차 연산으로 명확하게 만든다. 이 예제는 왼쪽부터 문장 순서대로 실행한다고 정한다.

공유의 범위를 설계하기

함수에 참조를 전달할 때는 읽기만 하는지 쓰기도 하는지 계약에 적는다. 외부에 원본 참조를 내주지 않고 필요한 값만 복사해 반환하면 의도치 않은 변경 경로를 줄일 수 있다. 값 안에 참조가 또 들어 있다면 얕은 복사의 한계도 확인해야 한다.

불변 자료나 새 값 반환 방식은 상태 추적을 단순하게 하지만 비용과 표현의 선택이 따른다. 목적은 모든 가변성을 금지하는 것이 아니라 어디에서 누가 변경할 수 있는지 분명하게 만드는 것이다.

예외를 다시 던질 때 처음 실패 뒤의 변경은 어디에 남을까?

예외 발생은 이미 수행한 write를 자동으로 취소하지 않는다. 초기 r=ref(1)에서 안쪽 try는 write(r,5); raise E; write(r,9)를 수행하고 E 처리기는 write(r,6); raise F를 수행한다고 정한다. 바깥 처리기는 E만 잡는다. E는 안쪽에서 잡히지만 새 F가 바깥 E와 맞지 않아 전파되고 최종 셀은 6이다. 9를 쓰는 문장은 실행되지 않는다.

바깥 처리기를 F로 바꾸어 read(r)+2를 반환하게 하면 정상 결과 8과 셀 6을 얻는다. 예외를 정상 결과로 바꾸는 처리와 저장소 복구는 독립이다. 처리기 본문에서 새로 발생한 예외가 같은 처리기의 E 패턴으로 다시 돌아간다고 가정하지 않는다. 가장 가까운 바깥의 맞는 처리 맥락으로 전파한다. 이 자체 언어에는 finally나 자동 자원 복구 규칙을 추가하지 않았다.

실패 보존을 원하면 무엇을 보존하는지와 어느 실패가 가능한지 정해야 한다. a=ref(10), b=ref(4)의 두 셀 이체에서 a를 7로 쓴 뒤 credit 단계가 E를 내면 합은 11로 줄어든다. 갱신 전 후보 (7,7)를 계산·검증하고, 두 셀 쓰기는 실패 없이 순차 완료한다는 제한 계약이면 검증 실패에서는 둘 다 옛 값이다. 그러나 쓰기 사이에도 실패가 가능하거나 외부 로그를 이미 냈다면 이 설계를 원자 트랜잭션이라고 일반화할 수 없다.

    복구 대상이 셀뿐인지 외부 기록도 포함하는지 확인한다.

실패는 정상 값과 다른 평가 결과다

예외는 정상 계산의 값을 대신하는 제어 흐름이다. 이 단원의 작은 언어는 raise E로 예외 E를 발생시키고 try ... catch E ...로 맞는 종류를 처리한다. 처리되지 않은 예외는 안쪽 표현식이나 함수에서 바깥 처리 맥락으로 전파된다.

실패 뒤의 아직 실행하지 않은 정상 경로 문장은 건너뛴다. 반면 실패 전에 수행한 상태 변경이 자동으로 사라지는 것은 아니다. 예외 처리기와 저장소의 관계도 평가 규칙에 포함해야 한다.

가장 가까운 맞는 처리기를 찾기

try 본문이 정상 값을 내면 처리기는 실행하지 않는다. 예외를 내면 그 종류가 맞는 처리기를 선택하고 처리기 결과로 전체 표현식의 결과를 정한다. 종류가 맞지 않으면 원래 예외를 바깥으로 계속 전달한다.

처리기 안에서 새 예외가 나면 새로운 바깥 처리 맥락이 필요하다. 실패 지점으로 되돌아가서 나머지 본문을 자동으로 실행하는 것으로 해석하지 않는다. 각 언어의 구체 문법과 finally/자원 정리 규칙은 별도로 확인해야 한다.

원자적인 작업과 단순 처리는 다르다

계좌 두 개를 바꾸다가 중간에 실패하면 한쪽만 바뀐 상태가 남을 수 있다. try/catch를 붙였다는 사실만으로 전체 작업이 원자적으로 되돌려지는 것은 아니다. 검증을 갱신 전에 하거나 새 상태를 계산한 뒤 한 번에 적용하는 설계를 고려한다.

자원 정리도 값 복구와 다르다. 파일을 닫았지만 이미 쓴 기록이 남을 수 있다. 상태를 되돌리는 보상 동작이 필요하다면 실패 종류, 복구 실패 가능성, 원래 오류 보존을 함께 계약으로 정한다.

중간 과정을 따라가는 예제

r=ref(1)이다. 의사 코드 try { write(r,5); raise E; write(r,9); } catch E { read(r)+2 }의 최종 값과 셀을 구하라. 처리기는 추가 갱신하지 않는다.

  1. write(r,5)로 셀 1→5를 바꾼다.

  2. raise E가 발생하므로 뒤의 write(r,9)는 생략한다.

  3. 맞는 catch E가 현재 5를 읽어 5+2=7을 계산한다.

  4. 예외 발생 전의 갱신을 되돌리는 규칙은 없으므로 셀은 5다.

표현식 결과 7, 최종 셀 5다. 예외 처리는 이전 상태 1 복원을 의미하지 않는다.

조건을 바꾸어 비교하기

맞은 안쪽 처리기가 다른 실패를 만든다

위 중첩 try에서 바깥은 E만 처리한다. 결과 형태와 셀은?

  1. 첫 write가 5를 남기고 E는 안쪽에서 처리된다.

  2. 그 처리기가 셀을 6으로 바꾸고 F를 내므로 바깥 E는 선택되지 않는다.

정상 값 없이 F가 전파되며 r의 내용은 6이다.

비교할 점

원래 E가 처리되었다는 사실이 전체 계산의 정상 종료를 보장하지 않는다.

검증 전에 쓴 이체와 후보 후 적용

a=10,b=4에서 3을 옮기다 credit 검증 E가 난다. 먼저 a를 쓴 방식과 후보를 먼저 검증한 방식을 비교하라.

  1. 먼저 쓰는 방식은 a=7 뒤 E가 나 b=4가 남아 합11이다.

  2. 후보 (7,7)를 검증하는 방식은 검증 실패 전에 쓰지 않아 a=10,b=4와 합14를 유지한다.

실패 보존 범위는 두 정수 셀이다. 성공 적용 쓰기에는 실패가 없다는 별도 전제가 있다.

비교할 점

후보 계산이라는 이름만으로 모든 실제 부수효과와 장애의 원자성을 보장하지 않는다.

종이와 본문으로 직접 해보기

처리기 종류를 F로만 바꾸고 바깥 처리기가 없다고 하자. 최종 셀과 결과 형태는?

힌트 보기

예외 종류와 이미 수행한 상태 변경을 따로 기록한다.

풀이 보기

E와 F는 맞지 않으므로 정상 결과값 없이 E가 전파된다. 실패 전에 저장한 5는 남아 있으며 뒤의 9 대입은 실행되지 않는다.

오해와 반례

예외를 잡으면 모든 변경이 취소된다.

단순 예외 처리에는 저장소 롤백이 없다. 예제에서 셀 5가 남으며 트랜잭션이나 보상 규칙은 추가로 설계해야 한다.

연습 1 · 값과 상태 예측

바깥 처리기를 F만 잡아 read(r)+2를 반환하도록 바꾼다. 첫 초기 r=1에서 결과·최종 셀은?

힌트 1

안쪽 처리기까지는 r이 6이다.

힌트 2

바깥은 읽고 덧셈해 반환만 한다.

풀이와 답 확인

  1. F가 바깥에서 처리되어 6+2를 계산한다.

  2. 추가 write가 없어 셀 6은 유지된다.

정상 결과 8과 셀 6이다.

흔한 오답에서 다시 생각하기

catch가 반환한 8이 r의 새 내용이다.

반환값과 저장소 갱신을 따로 표시한다.

연습 2 · 오류 찾아 고치기

안쪽 E 처리기에서 F를 냈지만 같은 안쪽 try가 F를 다시 처리한다고 추적했다.

힌트 1

같은 try의 본문과 처리기 실행 맥락을 나눈다.

힌트 2

처리기에서 새 예외가 나면 바깥 처리기를 찾는다.

풀이와 답 확인

  1. F는 안쪽 E 처리기의 결과로 전파된다.

  2. 바깥 패턴이 맞는지 확인하고 없으면 F가 그대로 남는다.

같은 처리기를 자동 재시도하는 규칙은 없다.

흔한 오답에서 다시 생각하기

try 문장 안에 보이는 모든 식은 언제나 그 처리기 자신이 잡는다.

문자열의 포함 위치와 동적 처리 맥락을 혼동하지 않는다.

연습 3 · 직접 만들어 보기

검증 E에서 a=10,b=4를 보존하고 정상 성공에는 (7,7)이 되는 이체 계약을 설계하라.

힌트 1

유효한 서로 다른 셀과 정수 금액 3을 전제한다.

힌트 2

실패 가능한 검증은 실제 쓰기 전에 마친다.

풀이와 답 확인

  1. 옛 a,b를 읽고 두 후보와 금액 조건을 계산·검증한다. 실패면 E를 내고 쓰지 않는다.

  2. 검증 성공 뒤 두 write는 실패·콜백·외부 관찰·동시 실행 없이 완료한다고 제한한다.

이 제한 경로의 검증 실패는 (10,4), 성공은 (7,7)이다. 실제 DB나 원자 하드웨어를 구현한 것은 아니다.

흔한 오답에서 다시 생각하기

try만 감싸면 중간 write도 자동 취소된다.

복구 규칙이나 쓰기 전 검증이라는 추가 설계가 필요하다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

먼저 a=7을 쓴 뒤 E가 나면 보상으로 a=10을 쓰는 방식에서, 보상 쓰기가 F를 낼 수도 있다. 실패 보존을 보장할 수 있나?

힌트 1

복구 자체가 성공하는 조건을 확인한다.

힌트 2

셀 복구와 원래 실패 정보 보존을 나눈다.

풀이와 답 확인

  1. 보상이 F로 실패하면 a=7이 남을 수 있어 두 셀의 원상태 복구를 보장하지 못한다.

  2. 원래 E와 복구 F의 정보를 어떻게 보고할지도 별도 계약으로 정한다.

복구 가능한 실패 범위와 실패 시 보존할 정보가 필요하다. 외부 로그 취소나 실제 장애 복구를 수행하지 않았다.

다른 문제에 적용하기

각 부분은 독립 초기 상태에서 시작한다. (1) a = ref(4), box = ref(a), copy = ref(read(box)) 뒤 write(read(copy),9)를 수행하고, 이어 write(copy,ref(2))를 수행하여 위치 표와 세 경로의 정수를 적어라. (2) 서로 다른 a = ref(1), b = ref(2)의 교차 읽기 A와 B를 두 순서로 비교하라. (3) r = ref(1)의 중첩 try에서 첫 본문이 write(r,5) 뒤 E를 발생시킨다. 안쪽 E 처리기는 write(r,6) 뒤 F를 발생시키고, 바깥 F 처리기는 read(r)+2를 반환한다. 이 경로를 추적하라. (4) 이체의 a = 10, b = 4에서 검증 E가 쓰기 전에 발생하는 후보 방식을 설계하고 적용 중 실패까지 보장하지 않는 경계를 설명하라.

힌트 1

환경→위치와 위치→값을 분리하고, 각 부분의 같은 이름은 새로운 초기 셀임을 확인한다.

힌트 2

제어 결과·최종 셀·읽기 시점·허용한 실패를 서로 다른 열로 기록한다.

풀이와 답 확인

  1. 첫 부분의 ℓ1은 9, ℓ2는 ℓ1, ℓ3는 새 ℓ4, ℓ4는 2다. a와 box의 안쪽 정수는 9, copy의 안쪽 정수는 2며 셀은 네 개다.

  2. 교차 작업은 A 뒤 B에서 (3,4), B 뒤 A에서 (3,2)다. 상대 읽기와 쓰기 집합이 겹친다.

  3. 첫 본문이 셀 r에 5를 저장한 뒤 E를 발생시킨다. 안쪽 E 처리기가 셀에 6을 저장한 뒤 F를 발생시키며, 바깥 F 처리기는 정상 결과 8을 반환한다. 최종 셀의 값은 6이고 write(r,9)는 실행되지 않는다.
