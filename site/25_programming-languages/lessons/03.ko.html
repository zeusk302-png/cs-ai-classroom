소단원 3.1

렉시컬·동적 범위

f의 x는 f를 만든 자리에서 찾을까, 지금 f를 부른 사람에게서 찾을까?

준비 개념과 학습 목표

준비 개념

  • 이름 바인딩은 이름과 대상을 연결한다. 같은 x라는 철자가 다른 바인딩을 가리킬 수 있다. 범위는 바인딩을 코드의 어느 부분에서 사용할 수 있는지 정한다.
  • 함수 호출은 실행 중 사건이며 함수 정의가 놓인 코드 위치와 다르다. g가 f를 호출한다고 f의 정의가 g 안으로 이동하지 않는다.
  • 자가진단: 바깥 x=10과 g의 지역 x=20을 두 상자로 그린다. 이름만 같고 서로 다른 바인딩이다.

학습 목표

  • 정의의 코드 구조와 활성 호출 구조를 구별한다.
  • lexical/dynamic 조회 규칙을 같은 모형으로 대조한다.
  • 바인딩 선택과 현재값·타입·동적 디스패치를 구별한다.

바인딩을 선택하는 기준

렉시컬 범위는 이름이 쓰인 코드의 중첩 구조로 바인딩을 결정한다. 자유변수는 그 함수의 매개변수나 지역 선언으로 묶이지 않은 이름이다. f가 바깥 x를 사용하고 g가 자기 x를 가진 경우, g에서 f를 불러도 f의 바인딩을 g의 x로 바꾸지 않는다. 그렇다고 바인딩의 값까지 컴파일 때 고정한다는 뜻은 아니다.

아래 Python3.12 f의 x는 모듈 바인딩이며 g의 x는 g의 지역 바인딩이다. Python 조회는 임의 호출자의 지역을 따라가지 않는다. global/nonlocal·클래스·주석 범위에는 별도 규칙이 있어 네 글자 LEGB만으로 모든 경우를 완전히 설명하지 않는다. 여기서는 모듈과 일반 함수만 다룬다.

동적 범위를 별도로 정의한다

자체 동적 모형은 현재 함수의 지역 이름을 먼저 찾고, 없으면 지금 활성인 호출자 프레임을 차례로 따라가며 끝에 전역을 찾는다. 전역 x=10, f()=x, g()는 지역 x=20 후 f()라는 구조에서 직접 f는10, g가 부른 f는20이다. 이 결과는 Python을 동적 범위 모드로 실행했다는 주장이 아니다.

호출 경로에 지역 x=30인 h가 직접 f를 부르는 경우 동적 모형은30을 선택한다. 렉시컬 f의 정의환경은 호출자 삽입으로 바뀌지 않는다. 인자의 실행 타입으로 메서드를 고르는 동적 디스패치나 Python이 동적 타입 언어라는 사실은 동적 이름 범위와 다른 개념이다.

선택한 바인딩의 값은 바뀔 수 있다

렉시컬 조회도 선택한 바인딩이 가변이면 나중에 다른 값을 읽을 수 있다. Python 모듈 x를10에서40으로 재결박하면 f는 같은 모듈 바인딩에서 현재40을 읽는다. OCaml의 새로운 let x는 이전 바인딩 변경이 아니라 새 바인딩으로 가리는 사례일 수 있다. 언어의 대입 규칙 없이 결과만 복사하면 안 된다.

종이에서 정의환경 화살표와 호출자 화살표를 다른 색으로 그린다. 렉시컬 호출 프레임은 함수가 보존한 정의환경을 부모로 잇고, 자체 동적 모형은 활성 호출자 환경을 잇는다. 완전 Python 예제는 전자의 사례만 실제 실행하며 동적 결과는 정의한 규칙으로 손으로 도출한다.

x = 10
def f():
    return x
def g():
    x = 20
    return f()
print(f(), g())

중간 과정을 따라가는 예제

전역 x=10, f()는 x 반환, g()는 지역 x=20 후 f()를 호출한다. Python과 자체 동적 모형의 두 호출 결과를 구한다.

  1. 모듈 G에 x=10과 f,g가 있다. f는 G에 정의되어 g 안에 있지 않다.
  2. 직접 f의 지역에 x가 없으므로 두 모형 모두 G의10을 찾는다.
  3. g의 지역에는20이 있다. Python f는 모듈의10, 자체 동적 f는 호출자 g의20을 찾는다.
  4. Python print는10 10이다. 동적 모형의 두 결과10,20은 실제 Python stdout이 아니다.

CPython3.12.7 실제 stdout은 10 10과 줄바꿈이다. 동적 모형10,20은 종이 결과다.

종이와 본문으로 직접 해보기

G:x=4, f()=x, g는 지역 x=7 후 f, h는 지역 x=9 후 g인 모형을 그린다. 직접 f와 h의 반환을 두 조회 규칙으로 구한다.

힌트 보기

h가 g를 부르면 g의 지역 x도 새로 생긴다. 동적 조회도 가장 가까운 활성 바인딩부터 찾는다.

풀이 보기

렉시컬 f는 G에 정의되어 직접 f=4,h=4다. 동적은 직접 f=4,h→g→f에서 가까운 g의7이 먼저여서 h의9는 선택되지 않는다. 결과는4,7이다.

오해와 반례

동적 타입 언어는 호출자의 변수를 찾고 렉시컬 범위는 값을 영원히 고정한다.

Python은 동적 타입이어도 g의20을 f가 읽지 않는다. 모듈 x 재결박으로 f의 값은 바뀔 수 있다. 바인딩 선택과 값·타입·메서드 선택은 다른 축이다.

소단원 3.2

바인딩과 환경 모델

a를 다른 리스트에 연결했는데 왜 b는 이전 리스트를 계속 볼까?

준비 개념과 학습 목표

준비 개념

  • 환경은 이름을 해석하는 바인딩들의 구조이고 프레임은 한 단계의 이름표다. 프레임은 부모 환경을 가질 수 있다. 자체 모형은 한 프레임 안에 같은 이름을 두 번 두지 않는다.
  • 이름 재결박은 이름이 가리키는 대상을 바꾸고 리스트 원소 변경은 공유 객체 내부를 바꾼다. 이름의 저장 장소와 객체를 따로 그린다.
  • 자가진단: a,b에서 O1로 두 화살표를 그린 뒤 a만 O2로 옮긴다. b는 O1에 남는다.

학습 목표

  • 환경ρ와 저장σ를 구별한다.
  • 바인딩·재대입·별칭을 추적한다.
  • 새 호출 프레임과 정의환경 연결을 설명한다.

환경과 저장의 두 표

자체 가변 모형에서 환경ρ는 이름→저장 위치ℓ의 유한 표, 저장σ는 위치→현재 값의 표다. lookup은 현재 프레임에 이름이 있으면 위치를 돌려주고 없으면 부모를 찾는다. 끝에도 없으면 unbound다. 이름 읽기는 찾은 위치의 σ값을 읽는다. 값에는 정수나 별도 객체를 가리키는 참조가 포함될 수 있다.

새 선언은 현재 프레임에 새 위치를 연결하고 초기값을 저장한다. 재대입은 선택한 위치의 값을 바꾼다. 중복 선언 허용·초기화 전 읽기는 실제 언어마다 다르므로 이 모형을 Python 전체 명세로 부르지 않는다. Python 이름은 객체를 참조하며 화살표 그림은 그 재결박/공유 효과의 대응 모형이다.

이름의 자리와 객체 별칭

a=[1]; b=a에서 a,b는 같은 리스트 O1의 참조를 가진다. a=[9]는 새 O2를 만들고 a만 O2에 연결한다. b[0]=2는 b를 새 리스트로 재결박하는 문장이 아니라 O1 내부를 바꾼다. 최종 a=[9],b=[2]다. 같은 객체참조가 있다는 사실이 두 이름 재대입도 연동한다는 뜻은 아니다.

추상 위치 ℓa,ℓb와 리스트 원소 저장을 분리한다. 두 위치는 다르지만 처음 저장값은 같은 O1참조다. O1의 원소 변경은 O1을 보는 다른 이름에서도 관찰된다. 이름의 철자가 같거나 같은 환경에 있다고 반드시 같은 객체를 참조하는 것은 아니다.

함수와 새 프레임

렉시컬 함수 값은 ⟨매개변수,본문,정의환경⟩인 클로저다. 호출은 인자를 평가한 값으로 새 매개변수 위치를 채운 프레임을 만들고 부모를 클로저 환경으로 잇는다. 다른 호출은 새 지역 프레임을 가지지만 캡처 객체를 공유할 수 있다. 객체참조를 인자값으로 전달하면 호출자와 함수가 같은 객체를 볼 수 있다.

모형은 추상 의미를 설명하며 실제 메모리가 이 사전 형태로 구현되거나 모든 이름이 실제 주소를 가진다고 주장하지 않는다. 구현은 환경을 줄여 보존하거나 최적화할 수 있다. 단일 순차 실행·유효한 살아 있는 객체·정의된 조회를 가정한다. 동시 변경·저수준 포인터·실제 할당 실패는 별도 조건이다.

a = [1]
b = a
a = [9]
b[0] = 2
print(a, b)

중간 과정을 따라가는 예제

Python 예제의 a,b와 두 리스트 O1,O2를 그려 재결박과 원소 변경을 추적한다.

  1. a=[1]에서 O1을 만들고 a를 연결한다. O1의 첫 값은1이다.
  2. b=a는 같은 O1참조를 b에 연결한다. 다른 이름이 같은 리스트를 본다.
  3. a=[9]는 O2를 만들고 a만 바꾼다. b는 O1에 남는다.
  4. b[0]=2는 O1 원소를 바꾼다. a는 O2의[9], b는 O1의[2]다.

CPython3.12.7 실제 stdout은 [9] [2]와 줄바꿈이다. 실제 주소나 추상 위치의 숫자를 측정하지 않았다.

종이와 본문으로 직접 해보기

ρ에서 x→ℓ1,y→ℓ2, σ에서 ℓ1→O,ℓ2→O, O=[5]라 둔다. x를 새 P=[8]에 재대입하고 O[0]=6으로 바꾸면 x,y는?

힌트 보기

이름 위치 두 개와 리스트 객체 두 개를 따로 그린다. O 변경은 ℓ2의 참조를 바꾸지 않는다.

풀이 보기

ℓ1값은 P참조라 x=[8]이다. ℓ2는 O참조를 유지해 y=[6]이다. 객체 변경 전 y=[5]였으며 x 재대입만으로 y가 P로 바뀌지 않는다.

오해와 반례

이름을 값으로 한 번 치환하면 대입과 객체 공유도 설명할 수 있다.

가변 상태에서는 같은 이름의 현재값이 달라진다. a 재결박과 b[0] 변경은 다른 곳을 바꾸므로 기계적 값 치환은 별칭 효과를 잃는다. 순수 불변식의 치환 논증과 구별한다.

소단원 3.3

이름 가림·수명·캡처

make가 끝났는데 inc는 왜 이전 x를 계속 증가시킬까?

준비 개념과 학습 목표

준비 개념

  • 가림은 안쪽의 같은 이름이 바깥 바인딩보다 먼저 선택되는 현상이다. 바깥 객체 삭제와 다르다.
  • 범위는 이름을 사용할 코드 구역이고 수명은 실행 시간 동안 대상이 살아 있는 기간이다. 두 축은 같지 않다.
  • 자가진단: make의 x에서 반환된 inc로 선을 긋는다. make 종료와 캡처 상태의 소멸을 분리한다.

학습 목표

  • 가림·재대입·객체 변경을 구별한다.
  • 캡처 상태와 호출 실행 종료를 분리한다.
  • 늦은 조회와 정의시 값 저장의 조건을 대조한다.

가림은 삭제가 아니다

안쪽 프레임이 x를 도입하면 그 구역의 조회는 안쪽 x에서 멈춘다. 바깥 환경에서는 원래 x를 다시 찾는다. 실제 언어의 동일 이름 선언 허용 위치는 다르므로 모든 중첩 블록에 같은 선언을 써도 컴파일된다고 가정하지 않는다. Python for/if는 일반적인 새 지역 함수 범위를 만들지 않는다.

inc의 nonlocal x는 inc에 새 지역 x를 만들지 않고 가장 가까운 외곽 함수 바인딩을 사용하겠다는 Python3.12 선언이다. 이를 빼고 x+=1을 쓰면 x가 inc의 지역 이름으로 판정되어 값이 아직 없는 상태에서 읽는 오류가 생길 수 있다. 이 오류 변형을 정상 예제의 증거로 실행하지 않는다.

호출 뒤에도 필요한 캡처 상태

make(3)은 x에 해당하는 캡처 상태와 inc를 만든다. inc가 그 상태를 계속 참조하면 Python은 나중 호출에서도 해당 바인딩을 사용할 수 있게 한다. make의 실행이 끝났다고 필요한 모든 상태가 즉시 사라지는 것은 아니다. 반대로 C 자동 배열 주소 반환처럼 언어가 수명 연장을 제공하지 않는 참조는 위험하다.

make(10)은 별도 상태를 만든다. c=make(3),d=make(10)에서 c의 반복 호출끼리 상태를 공유하며 d는 별개다. 실제 힙/스택 주소나 수거 시점은 측정하지 않는다. 자유변수 값을 생성시 복사하는지, 위치나 객체를 공유하는지는 언어와 캡처 구문에 따라 밝혀야 한다.

늦은 조회와 포획 없는 변경

Python 루프에서 같은 외곽 i를 참조하는 lambda들을 만들고 루프 뒤 부르면 최종 i를 모두 볼 수 있다. 렉시컬 범위가 각 반복값의 복사를 뜻하지 않기 때문이다. lambda i=i: i는 각 함수 정의시 기본 인자를 평가해 숫자값을 저장하는 별도 방식이다. 가변 객체를 기본 인자로 저장하면 참조 공유일 수 있어 깊은 복사와 다르다.

바인딩 이름을 바꾸려면 연결된 사용 위치도 바꾸고 다른 자유변수를 포획하지 않아야 한다. lambda x: x+y를 lambda y: y+y로 바꾸면 외곽 자유 y를 가려 의미가 달라진다. 아래는 정수 start·순차 호출·Python 임의 정밀도 정수 조건에서 정상 상태변화를 추적하는 완전 예제다.

def make(start):
    x = start
    def inc():
        nonlocal x
        x += 1
        return x
    return inc
c = make(3)
d = make(10)
print(c(), c(), d(), c())

중간 과정을 따라가는 예제

c=make(3),d=make(10) 뒤 c(),c(),d(),c()를 왼쪽부터 계산한다.

  1. C.x=3과 D.x=10을 별도 상자로 그린다. 본문은 같아도 환경은 다르다.
  2. 첫 c는 C.x=4와 반환4, 다음 c는 C.x=5와 반환5를 만든다.
  3. d는 D.x=11과 반환11을 만들고 C.x=5를 바꾸지 않는다.
  4. 마지막 c는 C.x=6과 반환6을 만든다. print 실인자는 Python에서 왼쪽부터 평가된다.

CPython3.12.7 실제 stdout은 4 5 11 6과 줄바꿈이다. 공유는 c와 d 사이가 아니라 각 클로저의 반복 호출 사이에서 일어난다.

종이와 본문으로 직접 해보기

C.x=0의 c와 D.x=5의 d에 c(),d(),c(),d()를 적용한다. lambda x: x+y에서 x를 z 또는 y로 바꾸는 의미도 비교한다.

힌트 보기

반환값과 C,D 최종 상태를 함께 적는다. 자유 y가 그대로 남는지 검사한다.

풀이 보기

반환1,6,2,7, 최종 C.x=2,D.x=7이다. 다른 이름과 충돌하지 않는 문맥의 lambda z: z+y는 바인딩 구조를 보존한다. lambda y: y+y는 자유 y를 포획하여 일반적으로 다른 함수다.

오해와 반례

렉시컬 클로저는 생성시 값을 무조건 복사하고 함수 종료 때 캡처도 사라진다.

Python nonlocal 카운터는 같은 캡처 상태를 바꿔4,5,6을 반환한다. OCaml 새 let의 가림과 가변 배열 공유, C++ 값/참조 캡처도 규칙이 다르다. 코드 범위와 객체 수명을 나누고 무엇을 보존하는지 확인한다.

한 단계 더

심화: start=s인 한 클로저만 k≥0번 순차로 정상 호출하고 외부에서 x를 바꾸지 않으면 귀납으로 호출 뒤 x=s+k다. 초기 s이고 매번 정확히1 증가하기 때문이다. 다른 make는 별도 위치라 영향을 주지 않는다. 이는 부작용 없음이 아니라 정의된 상태변화의 계약이다. 고정폭 정수·동시 호출·예외를 도입하면 표현범위·원자성·완료 조건을 새로 세워야 한다. 포획 없는 이름 변경과 값의 스냅샷은 다른 변환이다.
