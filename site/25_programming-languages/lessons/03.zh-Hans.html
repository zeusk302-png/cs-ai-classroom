小节 3.1

词法作用域与动态作用域

f使用的x是在定义f的位置寻找，还是在当前调用f的人那里寻找？

预备知识与学习目标

预备知识

  • 名称绑定把名称与目标连接起来。相同拼写x可以指向不同绑定。作用域决定代码的哪些部分能够使用绑定。
  • 函数调用是运行中的事件，与函数定义所在代码位置不同。g调用f不会把f的定义移进g。
  • 准备检查：把外层x=10与g的局部x=20画成两个盒子。名称相同，绑定不同。

学习目标

  • 区分定义的代码结构与活动调用结构。
  • 在同一模型中对照词法和动态查找规则。
  • 区分绑定选择与当前值、类型、动态分派。

选择绑定的依据

词法作用域按名称使用位置的代码嵌套结构确定绑定。自由变量是未被该函数参数或局部声明绑定的名称。f使用外层x、g有自己的x时，即使从g调用f，也不会把f的绑定改成g的x。但这不意味着绑定的值在编译时就固定。

下方Python 3.12中，f的x是模块绑定，g的x是g的局部绑定。Python查找不沿任意调用者的局部变量进行。global/nonlocal、类、注解作用域有额外规则，四个字母LEGB不能完整说明全部情况。这里仅讨论模块和普通函数。

另行定义动态作用域

自编动态模型先找当前函数局部名称，找不到就依次沿当前活动调用者帧寻找，最后查全局。全局x=10、f()=x、g()先声明局部x=20再调用f()时，直接f返回10，g调用的f返回20。这不是声称Python在动态作用域模式下执行。

若局部x=30的h直接调用f，动态模型选择30。插入调用者不会改变词法f的定义环境。根据参数运行时类型选择方法的动态分派，以及Python是动态类型语言的事实，都与动态名称作用域不同。

所选绑定的值可能改变

词法查找选中的绑定可变时，也可能后来读到不同值。将Python模块x从10重新绑定为40，f会从同一模块绑定读到当前40。OCaml中新let x可能以新绑定遮蔽旧绑定，而非修改旧绑定。没有语言赋值规则，不能只搬用结果。

在纸上以不同颜色画定义环境箭头和调用者箭头。词法调用帧以函数保留的定义环境为父环境，自编动态模型连接活动调用者环境。完整Python例子实际执行的只是前者，动态结果按所定义规则手工推导。

x = 10
def f():
    return x
def g():
    x = 20
    return f()
print(f(), g())

逐步推导的例题

全局x=10，f()返回x，g()先有局部x=20再调用f()。求Python和自编动态模型中两个调用的结果。

  1. 模块G中有x=10及f,g。f定义于G，而非g内部。
  2. 直接调用f的局部没有x，因此两个模型都找到G的10。
  3. g局部有20。Python的f找到模块10，自编动态f找到调用者g的20。
  4. Python打印10 10。动态模型的两个结果10,20不是实际Python标准输出。

历史实际CPython 3.12.7标准输出为10 10及换行。动态模型10,20是纸面结果。

用纸笔和正文动手试一试

画出G:x=4、f()=x、g先有局部x=7再调用f、h先有局部x=9再调用g的模型。用两种查找规则求直接f与h的返回值。

查看提示

h调用g时，也会新建g的局部x。动态查找同样先找最近的活动绑定。

查看解答

词法f定义于G，因此直接f=4、h=4。动态下直接f=4；h→g→f中较近的g的7先被找到，不选择h的9。结果为4,7。

常见误解与反例

动态类型语言查找调用者变量，词法作用域则永远固定值。

Python虽然动态类型，f也不读取g的20。重新绑定模块x可以改变f的结果。绑定选择、值、类型、方法选择是不同维度。

检查理解

词法自由变量查找以什么为依据？

查看答案与理由

定义的代码嵌套环境。

活动调用者与定义环境是不同关系。

动态h→g→f中，g有x时会选择h的x吗？

查看答案与理由

否，g的x在先。

模型定义为在最近活动绑定处停止。

词法函数是否始终返回同一个值？

查看答案与理由

否。

选中的绑定或对象可以变化，输入也可能不同。

进一步探索

进阶：保持f的代码、定义环境、参数、共享存储不变，只改变调用者局部帧，词法自由变量查找的绑定仍不变，因为查找路径不含该调用者。这不是所有函数结果不变的定理。共享状态变化、异常、发散、参数不同须另设前提。动态模型中新调用者x进入路径，是破坏这种绑定不变性质的反例。

小节 3.2

绑定与环境模型

把a连接到另一列表后，为什么b仍看到原来的列表？

预备知识与学习目标

预备知识

  • 环境是解释名称的绑定结构，帧是一层名称表。帧可以有父环境。自编模型在一个帧内不放两个相同名称。
  • 重新绑定名称改变名称指向的目标，修改列表元素则改变共享对象内部。把名称存储位置与对象分开画。
  • 准备检查：先画a,b到O1的两根箭头，再只把a移到O2。b留在O1。

学习目标

  • 区分环境ρ与存储σ。
  • 追踪绑定、重新赋值和别名。
  • 说明新调用帧与定义环境的连接。

环境与存储两张表

自编可变模型中，环境ρ是名称→存储位置ℓ的有限表，存储σ是位置→当前值的表。lookup在当前帧有名称时返回位置，否则找父帧；到末尾仍没有则unbound。读取名称，就是读取找到位置的σ值。值可以是整数，也可以是指向另一个对象的引用。

新声明在当前帧连接新位置并存初值；重新赋值改变所选位置的值。实际语言对重复声明、初始化前读取的规则不同，因此不能将此模型称为Python完整规范。Python名称引用对象，箭头图是重新绑定和共享效果的对应模型。

名称位置与对象别名

a=[1]; b=a使a,b持有同一列表O1的引用。a=[9]创建新O2，只把a接到O2。b[0]=2不是将b重新绑定到新列表，而是修改O1内部。最后a=[9],b=[2]。共享对象引用不意味着两个名称的重新赋值也联动。

分开抽象位置ℓa,ℓb与列表元素存储。两位置不同，但最初存的值是同一个O1引用。修改O1元素，其他看到O1的名称也能观察到。拼写相同或位于同一环境的名称，不一定引用相同对象。

函数与新帧

词法函数值是闭包⟨参数,主体,定义环境⟩。调用先求实参值，再建立将值放入新参数位置的帧，以闭包环境为父环境。不同调用有新的局部帧，但可共享捕获对象。将对象引用作为实参值传递，可以使调用者与函数看到同一对象。

模型说明抽象语义，不声称实际内存以这种字典实现，也不声称每个名称都有实际地址。实现可缩减保留的环境或进行优化。假设单一顺序执行、有效存活对象、定义明确的查找。并发修改、底层指针、实际分配失败须另设条件。

a = [1]
b = a
a = [9]
b[0] = 2
print(a, b)

逐步推导的例题

画出Python例子的a,b和两个列表O1,O2，追踪重新绑定与元素修改。

  1. a=[1]创建O1并连接a。O1的首个值为1。
  2. b=a把同一O1引用连接给b。不同名称看到同一列表。
  3. a=[9]创建O2，仅改变a。b留在O1。
  4. b[0]=2修改O1元素。a看到O2的[9]，b看到O1的[2]。

历史实际CPython 3.12.7标准输出为[9] [2]及换行。未测量实际地址或抽象位置的数字。

用纸笔和正文动手试一试

ρ中x→ℓ1,y→ℓ2，σ中ℓ1→O,ℓ2→O，O=[5]。把x重新赋为新P=[8]，再令O[0]=6，x,y分别看到什么？

查看提示

把两个名称位置与两个列表对象分开画。修改O不会改变ℓ2的引用。

查看解答

ℓ1的值是P引用，因此x=[8]。ℓ2仍引用O，因此y=[6]。修改对象前y=[5]，只重新赋值x不会让y变成P。

常见误解与反例

一次把名称替换为值，也能说明赋值和对象共享。

可变状态下，同一名称的当前值可以不同。a重新绑定和b[0]修改改变不同位置，机械值替换会丢失别名效果。应与纯不可变表达式的替换论证区分。

检查理解

自编ρ和σ分别连接什么？

查看答案与理由

名称→位置，位置→当前值。

模型允许对象引用也包含在当前值中。

b=a后将a改为新列表，b也会重新绑定吗？

查看答案与理由

否。

名称绑定各自独立，b保留旧对象引用。

词法调用帧的父环境是什么？

查看答案与理由

闭包保存的定义环境。

不同于始终将活动调用者环境作为父环境的动态模型。

进一步探索

进阶：有限且无环的父链接中，lookup每步减少一层帧深度，因此终止。按当前帧没有首个匹配时才找父帧的规则归纳，可得最近绑定的唯一性。只改变σ、保持ρ和父链接，查找位置不变，但读到的当前值可以变化。不要混用不可变环境与允许可变存储的语言前提。

小节 3.3

名称遮蔽、生命周期与捕获

make已经结束，为什么inc还能继续增加原来的x？

预备知识与学习目标

预备知识

  • 遮蔽是内层同名绑定先于外层绑定被选择，与删除外层对象不同。
  • 作用域是名称可用的代码区域，生命周期是运行期间目标存活的时间。两者不是同一维度。
  • 准备检查：从make的x向返回的inc画一条连线。分开make结束与捕获状态消失。

学习目标

  • 区分遮蔽、重新赋值和对象修改。
  • 分开捕获状态与调用执行结束。
  • 对照延迟查找和定义时存值的条件。

遮蔽不是删除

内层帧引入x后，该区域的查找在内层x处停止。在外层环境中仍能找到原x。实际语言允许同名声明的位置不同，不能假设所有嵌套块写同名声明都能编译。Python for/if通常不创建新的局部函数作用域。

inc中的nonlocal x是Python 3.12声明：不在inc创建新局部x，而使用最近外层函数绑定。去掉它却写x+=1，x可能被判断为inc局部名称，并在尚无值时读取而出错。未以执行这种错误变体作为正常例子的证据。

调用后仍需要的捕获状态

make(3)创建对应x的捕获状态及inc。如果inc继续引用该状态，Python使后续调用仍能使用该绑定。make执行结束，不表示全部所需状态立即消失。反之，语言未提供生命周期延长的引用，例如返回C自动数组地址，会有危险。

make(10)创建另一个状态。c=make(3),d=make(10)中，c的重复调用彼此共享状态，d则独立。未测量实际堆/栈地址或回收时刻。自由变量值是在创建时复制，还是共享位置或对象，须按语言与捕获语法明确。

延迟查找与避免捕获的改名

Python循环中创建引用同一外层i的lambda，循环后调用时，可能都看到最终i。词法作用域不等于复制每次迭代的值。lambda i=i: i是另一方法，在每个函数定义时求默认实参值并保存数字值。默认实参若保存可变对象，可能共享引用，不是深复制。

修改绑定名称，必须同时修改它绑定的使用位置，并避免捕获另一个自由变量。将lambda x: x+y改成lambda y: y+y会遮蔽外层自由y，改变含义。下方完整例子在整数start、顺序调用、Python任意精度整数条件下追踪正常状态变化。

def make(start):
    x = start
    def inc():
        nonlocal x
        x += 1
        return x
    return inc
c = make(3)
d = make(10)
print(c(), c(), d(), c())

逐步推导的例题

c=make(3),d=make(10)后，从左到右计算c(),c(),d(),c()。

  1. 把C.x=3和D.x=10画成两个盒子。主体相同，环境不同。
  2. 第一次c使C.x=4并返回4，下一次使C.x=5并返回5。
  3. d使D.x=11并返回11，不修改C.x=5。
  4. 最后c使C.x=6并返回6。Python中print的实参表达式从左到右求值。

历史实际CPython 3.12.7标准输出为4 5 11 6及换行。共享发生在各闭包的重复调用之间，而非c与d之间。

用纸笔和正文动手试一试

对C.x=0的c、D.x=5的d，依次调用c(),d(),c(),d()。比较把lambda x: x+y中的x改为z或y的含义。

查看提示

同时写返回值及C,D最终状态。检查自由y是否仍自由。

查看解答

返回1,6,2,7，最终C.x=2,D.x=7。在名称不冲突的上下文中，lambda z: z+y保留绑定结构；lambda y: y+y捕获自由y，一般是不同函数。

常见误解与反例

词法闭包创建时一定复制值，函数结束时捕获也消失。

Python nonlocal计数器修改同一捕获状态，返回4,5,6。OCaml新let遮蔽、可变数组共享、C++按值或引用捕获也有不同规则。分开代码作用域与对象生命周期，确认保留的内容。

检查理解

inc主体相同，c,d的状态也相同吗？

查看答案与理由

否。

每次make调用创建不同捕获环境。

没有nonlocal而写x+=1，是否自动保证修改外层？

查看答案与理由

否。

局部名称判断可能产生读取初值的错误。

把lambda x: x+y的x改成y，是否始终相同？

查看答案与理由

否。

参数捕获原来的自由y，绑定结构改变。

进一步探索

进阶：start=s的同一闭包顺序正常调用k≥0次，且外部不修改x，归纳可得调用后x=s+k。初值为s，每次恰增1。另一次make有不同位置，不受影响。这是定义明确的状态变化约定，不是没有副作用。引入固定宽度整数、并发调用、异常时，须重新建立表示范围、原子性和完成条件。避免捕获的改名与值快照是不同变换。
