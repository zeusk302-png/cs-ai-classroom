소단원 7.1

정적·동적 타입 구분

문자와 숫자를 더하는 문제는 실행 전에 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 타입은 값에 허용된 연산을 분류한다.
  • 검사 시점과 타입 이름을 직접 쓰는지 여부는 다른 문제다.

학습 목표

  • 검사 시점을 구분한다.
  • 실행 경로와 검사 범위를 비교한다.
  • 타입 추론을 동적 타입과 혼동하지 않는다.

값 계산과 타입 계산

자체 작은 언어에서 정수 덧셈은 정수 두 개만 받는다. 2+3은 값 5를 계산하지만 타입 검사는 Int와 Int로 결과 Int를 판단한다. 정적 검사는 실행 전 프로그램에 규칙을 적용한다.

동적 검사는 실행 중 실제 값의 종류를 확인한다. 2+true는 이 언어에서 타입 오류다. 모든 언어의 +가 같은 규칙은 아니다. 문자열 결합·자동 변환이 있는 언어에는 해당 언어 규칙을 확인해야 한다.

선택하지 않은 분기도 검사하기

if true then 2 else false를 보자. 이 작은 정적 언어의 if는 조건 Bool, 양쪽 결과 같은 타입을 요구하므로 Int와 Bool의 차이를 거부한다. 실행 경로만 보면 2를 얻어도 규칙을 만족하지 않는다.

선택한 분기만 평가하는 자체 동적 모형에서는 이 실행이 2로 끝난다. 다른 입력에서 실패할 수 있는 코드를 한 번 성공한 실행으로 안전하다고 결론내리지 않는다. 정적 검사도 언어가 정한 분석이며 모든 요구사항을 증명하는 장치는 아니다.

추론과 검사 시점은 별개

let x=2 in x+3에 타입 표기를 생략해도 정적 검사기는 x:Int를 알아낼 수 있다. 이를 타입 추론이라고 한다. 표기를 안 썼다는 사실만으로 동적 언어라고 부르지 않는다.

한 언어가 정적·동적 기능을 함께 제공할 수도 있다. 초보자는 언어 이름 암기보다 해당 표현식의 검사 규칙과 시점을 적자. 아래는 작은 모형의 종이 추적이고 실제 컴파일 결과가 아니다.

중간 과정을 따라가는 예제

동적 모형과 정적 모형에서 if true then 2 else false를 비교하라.

  1. 정적 검사는 true:Bool, 2:Int, false:Bool를 구한다.
  2. 두 분기 타입 Int와 Bool이 달라 if 규칙에 실패한다.
  3. 동적 모형은 조건 true를 평가하고 then의 2만 평가한다.
  4. 이 동적 실행의 결과는 2이며 다른 프로그램의 안전성을 보장하지 않는다.

정적 거부, 주어진 동적 실행은 2다.

소단원 7.2

타입 규칙과 오류

규칙을 한 줄씩 적용하면 오류가 난 자리를 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • Γ는 변수 이름과 타입을 묶은 환경이다.
  • Γ⊢e:Int는 환경 Γ에서 식 e의 타입이 Int라는 판단이다.

학습 목표

  • 타입 판단을 읽는다.
  • 덧셈·if·let 규칙을 적용한다.
  • 값 오류와 타입 오류를 구분한다.

잎부터 큰 식으로 올라가기

정수 상수는 Int, true와 false는 Bool이다. 변수 x는 Γ에 적힌 타입을 사용한다. x가 없으면 이 작은 검사기는 이름을 해결할 수 없다. +는 양쪽 Int를 확인한 뒤 결과 Int를 만든다.

Γ={x:Int}에서 x+2는 x:Int와 2:Int라는 두 근거를 가진다. 결과를 먼저 원하는 타입으로 적고 근거를 맞추지 않는다. 규칙의 전제들이 모두 성립해야 결론을 얻는다.

범위와 분기 조건

let x=3 in x+4에서는 3:Int를 확인하고 몸체를 Γ,x:Int에서 검사한다. 몸체 x+4:Int이므로 전체도 Int다. 이 환경 확장은 let의 몸체에 적용하며 모든 곳의 x를 바꾸라는 뜻이 아니다.

if c then a else b는 c:Bool과 a:T,b:T를 요구한다. if 1 then 2 else 3은 두 분기가 Int라도 조건이 Int여서 실패한다. 참처럼 취급하는 숫자 규칙을 다른 언어에서 가져오지 않는다.

오류 메시지의 한계

let x=true in x+4는 이름이 존재하지만 타입이 맞지 않는다. 이름 없음과 연산 타입 불일치를 따로 기록하면 원인을 찾기 쉽다. 검사기가 처음 발견한 위치가 개발자가 의도한 수정 위치와 항상 같지는 않다.

타입을 맞춰도 3−4=-1이 목적에 맞는지는 별도 요구사항이다. 아래는 정확 정수와 단순 타입만 사용하는 자체 연습이다. 오버플로·변환·오버로딩은 이 작은 규칙에 포함하지 않는다.

중간 과정을 따라가는 예제

let x=3 in if x<5 then x+4 else 0을 검사하라. <는 Int 두 개에서 Bool이다.

  1. 3:Int이므로 몸체 환경에 x:Int를 추가한다.
  2. x<5는 Int,Int에서 Bool이다.
  3. x+4:Int이고 0:Int이므로 if:Int이다.
  4. 전체:Int이며 값 추적은 x=3, 조건 true, 3+4=7이다.

타입 Int, 값 7이다.

종이와 본문으로 직접 해보기

let x=true in if x then 1 else x+2를 검사하라.

힌트 보기

조건과 두 분기를 따로 적자.

풀이 보기

x:Bool이므로 조건은 맞다. else의 x+2는 Bool+Int라 실패하여 전체를 승인할 수 없다.

오해와 반례

조건만 Bool이면 if는 언제나 타입 검사를 통과한다.

if true then 1 else false는 분기 타입이 달라 실패한다. 조건과 분기라는 세 전제를 모두 확인한다.

소단원 7.3

타입 안전성의 의미

타입이 맞으면 프로그램이 반드시 종료하고 답도 맞을까?

준비 개념과 학습 목표

준비 개념

  • 작은 단계 e→e′는 계산 한 번이다.
  • stuck은 값도 아니고 다음 규칙도 적용할 수 없는 상태다.

학습 목표

  • progress와 preservation을 설명한다.
  • 안전성과 종료를 구분한다.
  • 정리의 언어 범위를 명시한다.

진행과 보존을 함께 보기

닫힌 잘 타입된 식에 대해 progress는 값이거나 다음 계산 단계가 있음을 말한다. preservation은 e:T이고 e→e′이면 e′도 T라는 약속이다. 각각 진행 가능성과 타입 보존을 다룬다.

2+(3+4)는 Int이며 안쪽을 계산한 2+7도 Int다. 이어 9:Int라는 값에 도달한다. 이 과정은 한 예이고 모든 식의 정리 증명 자체는 아니다. 정리는 언어의 모든 규칙을 대상으로 따로 증명한다.

멈춤과 실패를 구분하기

2+true는 이 작은 언어에서 값이 아니며 정수 덧셈 규칙도 적용할 수 없다. 타입 검사가 거부하는 stuck 반례다. 정상 값 9에서 다음 단계가 없는 것은 완료라서 stuck이 아니다.

지원하는 예외가 있는 언어는 예외를 결과나 전파 단계로 정의할 수 있다. 안전성을 말할 때 어떤 실패를 제외하는지 의미론을 확인한다. 배열 범위 오류나 입출력 실패를 모든 정적 타입 검사가 없앤다고 주장하지 않는다.

안전성과 유용성의 경계

재귀를 추가한 언어에서 정수 함수 loop():Int가 계속 자기 자신을 부르면 매 단계가 정의되어도 종료하지 않을 수 있다. 타입 안전은 일반적으로 종료 정리가 아니다. 원하는 합을 잘못 계산한 정수 결과도 타입은 맞을 수 있다.

정리 밖의 외부 호출·불안전 기능·구현 오류까지 자동 보장하지 않는다. 모형의 연산·변환·메모리 규칙을 명시해야 한다. 우리의 종이 예제는 실제 언어 전체나 컴파일러 구현을 검증했다는 증거가 아니다.

중간 과정을 따라가는 예제

2+(3+4)의 각 상태에서 타입과 완료 여부를 적어라.

  1. 초기 식:Int, 안쪽 덧셈이라는 다음 단계가 있다.
  2. 2+7:Int로 진행하며 타입이 보존된다.
  3. 9:Int로 진행하고 정수 값이므로 완료다.
  4. 두 전이는 보존을 보여 주며 값에서 진행을 요구하지 않는다.

두 전이 모두 Int, 마지막 9는 완료다.

힌트 보기

풀이 보기

오해와 반례

타입 안전이면 정답·종료·보안이 모두 보장된다.

잘못된 산술식이 정수를 반환하거나 타입이 맞는 재귀가 무한 반복할 수 있다. 요구사항과 종료·보안은 별도 속성이다.
