소단원 1.1

구문·의미·실행모형

두 언어에서 똑같이 1+2라고 쓰면 더 큰 코드에서도 뜻이 항상 같을까?

준비 개념과 학습 목표

준비 개념

  • 식은 값을 계산하는 코드이며 1+2는 기본 덧셈 예이다. 문장은 대입·반복처럼 동작을 지정한다.
  • 타입은 값의 종류와 허용되는 연산을 구분한다. 숫자 2와 문자열 '2'를 각각 상자에 적어 구별하라.
  • 자가진단: (1+2)*3은 9이다. 괄호 없는 1+2*3은 곱셈을 먼저 하여 7이다.

학습 목표

  • 구문·정적 의미·동적 의미의 질문을 구분한다.
  • 피연산자 타입과 평가 순서로 같은 + 표기의 의미를 설명한다.
  • 언어 의미와 인터프리터/JIT 같은 구현 방식을 구분한다.

구문은 형태를, 의미는 해석을 정한다

구문(syntax)은 어떤 코드 형태가 언어에서 허용되는지 정하는 규칙이다. 1 + 처럼 피연산자가 빠진 형태는 표현식을 완성하지 못한다. 정적 의미는 실행 전 이름·타입·사용 조건을 검사하는 층이다. Java SE 11에서 int n="two";는 형태를 읽을 수 있어도 문자열을 int에 대입하는 타입 조건을 만족하지 않는다.

동적 의미는 유효한 코드의 실행 상태와 결과를 규정한다. 정수 두 개의 합, 문자열 연결, 예외 발생, 저장 상태 변화가 이에 포함된다. 정적 검사를 통과했다는 것이 0으로 나누는 등 모든 실행 오류가 없어졌다는 뜻은 아니다. 언어를 비교할 때 '문법이 비슷하다'는 주장과 '같은 상태에서 같은 결과를 낸다'는 주장을 나누어 적는다.

타입과 괄호가 +의 해석을 바꾼다

Java SE 11의 +는 두 숫자에 대해서는 숫자 덧셈이며 한쪽이 문자열이면 문자열 연결을 수행한다. +는 좌결합이므로 1+2+"3"은 (1+2)+"3"으로 해석되어 문자열 "33"이 된다. "1"+2+3은 ("1"+2)+3이며 문자열 "123"이다. 서로 다른 중간 타입이 나중의 연산도 바꾼다.

Python 3.12에서 1+2는 3이고 "1"+"2"는 "12"지만 "1"+2는 이 내장 타입 조합에서 TypeError이다. Java의 문자열 변환을 Python에 그대로 가져오면 잘못된 예측을 만든다. 사용자 정의 연산자나 특별한 객체를 추가할 수도 있으므로 현재 비교 범위는 내장 int·str 및 Java int·String의 작은 값으로 한정한다.

Java SE 11 식: 1 + 2 + "3"        // 값은 문자열 "33"
Java SE 11 식: "1" + 2 + 3        // 값은 문자열 "123"
Python 3.12 식: "1" + 2           # TypeError 예상

실행모형과 구현을 분리한다

의미를 설명할 때 상태 σ는 이름과 현재 값의 대응이라고 단순화할 수 있다. 대입 x=x+1은 현재 σ에서 x의 값을 읽고 새 값을 계산한 뒤 다음 상태를 만든다. 이런 단계별 모형은 컴퓨터를 실행하지 않고도 결과를 논증하게 한다. 실제 객체·저장소와 별칭이 필요하면 더 정밀한 모형으로 확장한다.

컴파일, 해석, 바이트코드, JIT는 프로그램을 실행하는 구현 전략이다. 한 언어가 반드시 하나의 전략만 사용하는 것은 아니다. JVM 구현은 해석과 JIT를 함께 사용할 수 있지만 Java의 + 규칙을 임의로 바꾸어서는 안 된다. 성능 비교에는 동일 문제·입력·구현·버전·측정 조건을 추가해야 하며 이 첫 단원의 의미 비교를 속도 순위로 바꾸지 않는다.

중간 과정을 따라가는 예제

Java SE 11에서 문자열이 포함된 1+2+"4"와 "1"+(2+4)의 값을 타입과 함께 추적한다.

  1. 첫 식은 (1+2)+"4"이다. 1과 2는 int이므로 중간값 3이다.
  2. 3과 "4"의 +는 문자열 연결로 문자열 "34"가 된다.
  3. 둘째 식은 괄호 안 2+4=6을 먼저 계산한다.
  4. "1"과 6을 연결하여 문자열 "16"이 된다.

각각 String 값 "34", "16"이다. 화면 결과만 적기보다 중간 타입과 결합 구조를 함께 적어야 근거가 드러난다.

종이와 본문으로 직접 해보기

종이에 Java SE 11 식 2+3+"0", 2+(3+"0"), Python 3.12 식 "2"+"3"을 적어 괄호 구조·중간 타입·최종값을 표시하라.

힌트 보기

Java에서 String이 등장한 +는 연결이며 Python의 두 문자열도 연결이다.

풀이 보기

Java 첫 식 (2+3)+"0"은 5→"50". 둘째 식 3+"0"은 "30", 이어 2+"30"은 "230". Python 식은 문자열 "23"이다.

오해와 반례

연산자 모양과 숫자 모양이 같으면 언어 사이 의미도 같다.

Java "1"+2는 "12"를 만들지만 Python 내장 str과 int 사이 같은 식은 TypeError이다. 타입·변환 규칙·결합 구조를 확인해야 의미를 비교할 수 있다.

소단원 1.2

추상화와 표현력

같은 일을 더 짧게 적으면 언제나 더 강한 언어일까?

준비 개념과 학습 목표

준비 개념

  • 함수는 입력과 반환의 계약을 가진다. 예: square(x)는 x*x를 반환한다.
  • 목록 [1,2,3]은 순서 있는 세 값이다. 반복문은 각 값을 차례로 처리할 수 있다.
  • 자가진단: [1,2,3]의 제곱 목록은 [1,4,9]이다. 원래 목록 길이와 결과 길이는 모두 3이다.

학습 목표

  • 반복되는 처리와 변경 가능한 요소를 분리해 함수 추상화를 설명한다.
  • 고차 함수의 입력 계약과 결과를 추적한다.
  • 계산 가능성·표현 편의·성능을 서로 다른 비교 기준으로 둔다.

추상화는 필요한 계약을 드러내고 세부를 묶는다

추상화는 복잡한 구현을 다 기억하지 않고도 사용할 수 있도록 핵심 개념과 인터페이스를 드러내는 일이다. square(3)이 9를 반환한다는 계약을 알면 호출자는 곱셈 코드의 위치를 몰라도 사용할 수 있다. 하지만 값의 범위, 부작용, 오류 조건처럼 올바른 사용에 필요한 사실까지 숨기는 것은 좋은 추상화가 아니다.

같은 목록의 원소별 처리를 반복해서 쓰면 변하는 요소는 원소 처리 함수이고 고정 부분은 목록 순회라는 것을 찾을 수 있다. 고정 패턴을 모으고 변하는 부분을 매개변수로 주면 하나의 구조를 여러 문제에 적용한다. 추상화의 가치는 글자 수뿐 아니라 계약의 명확성과 변경 영향을 줄이는 데 있다.

함수를 데이터처럼 전달하는 고차 함수

고차 함수는 함수를 인자로 받거나 함수 값을 반환하는 함수이다. map이라는 개념적 연산은 목록 xs와 변환 함수 f를 받아 [f(x) for x in xs]에 해당하는 결과를 만든다. 이를 종이에서 함수 카드 f와 원소 카드 세 장으로 추적할 수 있다.

이 단원의 Python 3.12 코드는 list(map(square,xs))처럼 결과를 list로 모은다. Python의 map 자체는 바로 완성된 리스트를 반환하지 않고 반복자를 반환하므로 list가 소비하는 단계까지 명시한다. 여기서 f는 정수→정수이며 원래 목록을 변경하지 않는 함수라는 조건을 둔다.

def square(x):
    return x * x
xs = [1, 2, 3]
ys = list(map(square, xs))
print(ys)

표현력에는 여러 질문이 있다

계산 가능성의 표현력은 어떤 함수를 계산할 수 있느냐는 질문이다. 작성 편의의 표현력은 같은 문제를 얼마나 자연스럽고 국소적으로 적는지 묻는다. 타입 체계의 표현력은 어떤 계약을 코드에 표현하고 검사할 수 있는지 묻는다. 서로 다른 질문을 단순한 코드 길이 점수 하나로 합치면 비교가 흐려진다.

반복문으로도 위 제곱 목록을 계산할 수 있으므로 map이 있다는 사실만으로 새로운 수학적 함수를 반드시 계산 가능하게 한 것은 아니다. 유한 메모리를 가진 실제 기계와 무한 자원을 가정하는 계산 모형도 구분한다. 더 짧은 표기가 반드시 더 빠른 구현이나 더 적은 메모리를 뜻하지 않으며 결과를 만드는 방식과 구현 비용을 따로 분석해야 한다.

중간 과정을 따라가는 예제

목록 [2,4,5]에 함수 f(x)=x+1을 적용하는 개념적 map을 종이로 계산한다. 함수 호출 횟수와 결과 순서를 적는다.

  1. 첫 원소 2에 f를 적용하여 3을 만든다.
  2. 두 번째 4에 f를 적용하여 5를 만든다.
  3. 세 번째 5에 f를 적용하여 6을 만든다.
  4. 이 개념적 목록 변환은 원래 순서에 맞춰 [3,5,6]을 반환하며 함수 적용은 세 번이다.

결과 [3,5,6], 입력·출력 길이 3. f의 계산이 종료하고 부작용이 없다는 조건에서 원소별 값을 독립적으로 설명할 수 있다.

종이와 본문으로 직접 해보기

목록 [1,3]을 순회하는 상자 두 개를 그린다. 첫 상자에는 square, 둘째에는 x+2 함수 카드를 넣어 결과를 비교한다. 같은 순회 틀에서 무엇이 바뀌고 무엇이 같은지 적어라.

힌트 보기

각 원소를 함수 카드에 한 번 통과시킨다.

풀이 보기

square는 [1,9], x+2는 [3,5]이다. 순서·목록 방문 틀·원소 수는 같고 원소 변환 계약이 바뀐다. 함수 매개변수가 반복 구조를 재사용하게 한다.

오해와 반례

코드가 짧은 언어는 반드시 계산 능력과 실행 속도가 더 크다.

map 표기와 반복문은 이 예제에서 같은 목록 변환을 계산한다. 짧은 표현은 읽기와 재사용에 도움이 될 수 있지만 실제 실행기·할당·입력 크기를 측정하지 않고 속도를 결론 낼 수 없다.

언어 기능과 라이브러리 구분

새 수학 함수를 설치했다고 Python 문법 자체가 바뀌는 것일까?

준비 개념과 학습 목표

준비 개념

  • 함수 호출 f(값)은 이미 정의된 기능을 사용한다. import는 모듈의 이름을 현재 코드에서 사용할 수 있게 하는 문장이다.
  • 문법은 허용되는 코드 형태이고 라이브러리는 재사용 가능한 구현과 인터페이스의 묶음이다.
  • 미니복습: math.sqrt(9)는 제곱근 기능을 호출하는 표기이며 괄호는 일반적인 호출 문법이다.

학습 목표

  • 구문·평가 규칙·표준 라이브러리·외부 도구의 역할을 분류한다.
  • import와 함수 계약을 통해 라이브러리 사용을 추적한다.
  • 코드 모양만으로 언어와 라이브러리의 경계를 단정하지 않는다.

문법 기능과 제공되는 함수

if와 함수 정의 같은 구조의 허용 형태는 언어 구문과 의미 규칙에 해당한다. Python math.sqrt는 math 모듈이 제공하는 함수이며 이를 호출하는 괄호·인자 표기는 일반적인 함수 호출 문법이다. 새로운 라이브러리 함수를 가져와도 언어가 없던 문법을 자동으로 허용하게 되지는 않는다.

표준 라이브러리는 언어 또는 플랫폼과 함께 정의·제공되는 재사용 기능이다. 외부 패키지는 별도 프로젝트의 기능과 배포물을 사용한다. 두 종류 모두 버전·계약·오류 조건을 확인해야 한다. 표준이라는 말이 언제나 내장 구문 또는 모든 Python 구현에서 동일한 내부 코드라는 뜻은 아니다.

모듈은 이름과 의존성을 관리한다

import math 후 math.sqrt(9)를 쓰면 math라는 모듈 이름을 통해 sqrt를 찾는다. 이 코드에는 모듈 탐색·가져오기, 속성 조회, 함수 호출이 참여한다. 결과는 이 예제에서 실수 3.0이다. math.sqrt(-1)는 실수 영역의 계약을 벗어나 ValueError를 일으키므로 함수 이름을 아는 것만으로 모든 입력을 사용할 수 있지는 않다.

모듈화는 구현을 묶고 외부 계약을 정하는 추상화이다. 언어 자체의 모듈 규칙과 모듈 안에 들어가는 수학 기능은 구분한다. 설치나 경로 변경으로 모듈을 찾을 수 없는 문제, 정상 모듈을 호출했지만 잘못된 입력으로 실패하는 문제도 다른 층이다.

import math
value = math.sqrt(9)
print(value)

경계가 겹치는 경우도 조건을 밝힌다

일부 언어에서는 연산자 오버로딩·매크로·확장 체계로 라이브러리가 언어처럼 보이는 표기를 제공할 수 있다. Python의 +가 사용자 객체의 특수 메서드와 연결되는 것도 언어 규칙과 객체 구현이 함께 작동하는 예이다. 따라서 '괄호가 있으니 무조건 외부 라이브러리' 같은 판정은 정확하지 않다.

비교할 때 문법을 누가 정의하는지, 평가 시 무엇을 호출하는지, 배포·버전 의존성이 무엇인지 따로 묻는다. 코드를 빌드하는 도구와 편집기의 자동완성도 언어 의미 자체와 다르다. 기능을 제거해도 문법은 남는지, 기능이 필요한 프로그램만 실패하는지 생각하면 역할을 분리할 수 있다.

중간 과정을 따라가는 예제

Python 3.12에서 import math; value=math.sqrt(9); print(value)를 단계별로 추적한다. 입력을 -1로 바꾸면 실패 층은 무엇인가?

  1. import가 math 모듈을 사용 가능한 이름으로 연결한다.
  2. math.sqrt라는 함수에 정수 9를 전달한다.
  3. 제곱근 계약에 따라 값 3.0을 반환하여 value에 연결한다.
  4. -1을 넣은 변형은 호출 문법은 유효하지만 함수의 실수 영역 조건에서 ValueError가 발생한다.

정상 예상 출력 3.0. 변형의 문제는 괄호나 import 문법이 아니라 호출된 기능의 입력 계약이다.

종이와 본문으로 직접 해보기

풀이 보기

if와 import의 구문·의미는 언어 규칙, sqrt는 표준 라이브러리 기능, 색칠과 설치는 도구/환경이다. import 규칙과 가져오는 라이브러리 구현은 연결되지만 동일한 것은 아니다.

오해와 반례

표준 라이브러리 함수는 언어 문법이므로 입력 조건이나 환경 문제가 없다.

math.sqrt(-1)는 구문은 맞아도 ValueError가 된다. 또 모듈은 구현·배포 환경에서 찾아 사용할 수 있어야 한다. 표준 기능에도 명확한 계약과 조건이 있다.
