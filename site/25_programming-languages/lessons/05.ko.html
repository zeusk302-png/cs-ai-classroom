일급·고차 함수

map 두 번을 합성 한 번으로 바꾸면 호출 장부도 같을까?

함수를 물건처럼 건네는 일은 그 함수가 하는 일을 지우지 않는다. 순수한 u(x)=2x+1과 v(x)=x²에서는 map(u,map(v,L))와 map(compose(u,v),L)가 같은 원소 결과를 만든다. 이 단원의 map은 유한 목록을 왼쪽부터 처리하며 입력 원소마다 콜백을 정확히 한 번 호출하고 새 목록의 순서를 보존한다. compose(u,v)(x)는 v를 먼저, u를 나중에 호출한다. 실제 OCaml 라이브러리의 모든 평가 순서를 이 자체 계약으로 대신하지 않는다.

같은 결과 목록과 같은 효과 장부는 다른 조건이다. 별도 상태 콜백 f(x)는 현재 정수 c를 읽어 x+c를 결과로 정한 뒤 c를 1 늘린다. 처음 c=0이고 L=[1,2]다. 두 map 방식은 첫 목록 전체에 f를 적용한 다음 중간 목록 전체에 적용한다. 합성 map 방식은 한 원소에 f를 연속 두 번 적용한 뒤 다음 원소로 간다. 호출 수가 네 번으로 같아도 각 입력과 당시 c의 짝이 달라 결과가 [3,6]과 [2,7]로 갈린다.

함수 값 자체를 선택하는 비용, 콜백 호출 횟수, 중간 목록 생성과 실제 실행 시간을 따로 적는다. 빈 목록은 두 방식 모두 콜백을 호출하지 않는다. 아래는 손으로 정한 상태 전이이며 실제 map 실행·병렬 최적화·메모리 측정은 하지 않는다.

1. 계산 규칙을 값으로 다루기

일급 함수란 함수를 보통의 값처럼 저장하고, 인자로 전달하고, 결과로 반환할 수 있게 하는 언어의 성질이다. 예를 들어 add2라는 이름이 덧셈 규칙을 가리킨다면 f=add2는 그 규칙을 선택하는 일이고 f(5)는 선택된 규칙을 실행하는 일이다. 함수를 다른 변수에 담는 순간 모든 가능한 입력을 계산하는 것은 아니다.

여기서는 수학적 정수와 순수한 함수만 사용하는 작은 종이 모형으로 시작한다. add2(x)=x+2, triple(x)=3x라고 정의한다. 함수 이름이 있는지, 이름 없는 함수 표현식인지와 일급 값으로 다룰 수 있는지는 별개의 질문이다. 이름이 있는 함수도 인자로 전달할 수 있고 이름 없는 함수도 저장할 수 있다.

2. 함수를 받거나 반환하는 함수

고차 함수는 함수를 인자로 받거나 함수를 결과로 반환하는 함수이다. repeat3(f,x)=f(f(f(x)))는 f라는 계산 규칙을 받아 세 번 적용하므로 고차 함수이다. add2는 정수만 받아 정수만 돌려주므로 이 모형에서는 고차 함수가 아니다. 일급은 값의 지위에 관한 말이고 고차는 특정 함수의 입력·출력에 관한 말이다.

repeat3(add2,1)은 안쪽부터 계산한다. 먼저 add2(1)=3, 다음 add2(3)=5, 마지막 add2(5)=7이다. repeat3(triple,1)은 같은 제어 구조에서 3,9,27을 만든다. 반복 구조를 한 번 적고 계산 규칙을 교체한 것이다. f가 각 호출마다 외부 기록을 남긴다면 그 기록도 세 번 발생할 수 있으므로 결과 값만 보고 모든 동작을 설명했다고 할 수 없다.

3. 자료 처리와 순서의 조건

map(f,[1,4])를 각 원소에 f를 한 번씩 적용하여 새 목록을 만드는 연산으로 정의하면 map(add2,[1,4])=[3,6]이다. 입력 목록의 길이와 순서를 보존한다는 것이 이 모형의 조건이다. filter는 참·거짓 판정으로 원소를 선택하므로 map과 목적이 다르다. 둘 다 고차 함수라는 공통점만으로 결과 모양까지 같아지지는 않는다.

함수 합성 compose(f,g)(x)=f(g(x))에서는 g가 먼저 실행된다. add2(triple(2))=8이고 triple(add2(2))=12이므로 교환할 수 없다. 고차 함수를 썼다는 이유로 자동으로 빠르거나 병렬 안전하거나 부작용이 없는 것도 아니다. 실제 언어에서는 평가 순서, 예외, 입력·출력, 값의 타입과 호출 횟수를 별도로 확인해야 한다.

중간 과정을 따라가는 예제

add2(x)=x+2와 triple(x)=3x를 사용한다. repeat3(add2,1), repeat3(triple,1), compose(add2,triple)(2)를 구하라.

  1. repeat3의 정의를 세 겹의 함수 적용으로 풀어 쓴다. 함수 자체를 숫자처럼 더하지 않는다.

  2. add2 경로의 첫 호출은 1+2=3이다. 이 결과를 다음 입력으로 전달하면 3+2=5이다.

  3. 세 번째 입력은 5이므로 5+2=7이다. triple 경로는 1→3→9→27로 각각 세 번 호출한다.

  4. compose(add2,triple)(2)는 안쪽 triple(2)=6을 먼저 구한 뒤 add2(6)=8을 구한다.

  5. 함수 값을 선택하는 일과 실제 세 번 호출하는 일을 구분하고, 각 중간 값이 다음 호출의 입력인지 확인한다.

두 repeat3 결과는 7과 27이고 합성 결과는 8이다. 이 계산은 순수한 수학적 정수 모형의 종이 추적이며 실제 프로그램 실행이 아니다.

조건을 바꾸어 비교하기

순수 합성은 가능하지만 함수의 순서는 남는다

L=[−2,1], u(x)=2x+1, v(x)=x²다. map(u,map(v,L))와 map(compose(u,v),L), 반대로 map(v,map(u,L))를 비교한다.

  1. v의 결과 [4,1]에 u를 적용하면 [9,3]이다. compose(u,v)는 각 원소를 x² 뒤 2x²+1로 바꾸어 같은 [9,3]을 만든다.

  2. 반대로 u의 결과 [−3,3]에 v를 적용하면 [9,9]다. 첫 원소 결과만 같아 전체 동등성을 판정할 수 없다.

두 일정의 u∘v는 [9,3]으로 같지만 v∘u는 [9,9]다.

비교할 점

순수성은 합성 순서의 교환 법칙을 주지 않는다.

호출 수가 같아도 상태와 입력의 결합이 달라진다

위 표의 f와 L=[1,2]를 사용하며 두 비교는 각각 c=0에서 시작한다.

  1. 두 map은 중간 [1,3]을 만들 때 c=2가 된다. 다음 입력 1에는 c=2, 입력 3에는 c=3이 붙어 [3,6]이다.

  2. 합성 map은 첫 원소 1에 c=0과 1을 연속 적용하여 2를 만들고 둘째 2에 c=2와 3을 적용하여 7을 만든다.

끝 상태는 모두 c=4지만 반환 목록은 [3,6]과 [2,7]이다.

비교할 점

같은 호출 수·끝 카운터만으로 관찰 가능한 결과 전체를 보존했다고 할 수 없다.

종이와 본문으로 직접 해보기

종이에 map(triple,[0,2,5])의 결과를 적고, 그 목록에 map(add2,...)를 적용하라. 반대로 add2를 먼저 적용한 결과와 비교하라. 빈 목록에서는 함수 호출이 몇 번 필요한지도 적어라.

힌트 보기

각 원소마다 두 단계를 화살표로 그린다. 빈 목록에는 처리할 원소가 없다는 조건을 사용한다.

풀이 보기

triple 먼저는 [0,6,15]→[2,8,17]이고 add2 먼저는 [2,4,7]→[6,12,21]이다. 순서가 바뀌면 결과가 달라진다. 빈 목록에는 0번 적용하고 결과도 빈 목록이다.

오해와 반례

함수 인자를 받는 프로그램은 모두 순수하고 계산 순서를 바꾸어도 같다.

함수 인자는 외부 상태를 바꾸거나 예외를 던질 수도 있다. 순수한 add2와 triple조차 합성 순서를 바꾸면 8과 12처럼 값이 달라진다. 고차라는 분류는 순수성·교환 법칙·병렬 실행을 보장하지 않는다.

연습 3 · 직접 만들어 보기

수학적 정수의 total 콜백 f에 대해 transform_if(p,f,L)를 설계하라. p는 각 원소에 한 번 호출하고 참이면 f 결과, 거짓이면 원래 원소를 새 목록에 넣는다. p(x)는 x<0, f(x)=−x, L=[−2,0,3]이다.

힌트 1

filter처럼 원소를 삭제하지 않는다.

힌트 2

거짓 분기에서는 f를 부를 필요가 없다.

풀이와 답 확인

  1. 왼쪽부터 p 결과는 참/거짓/거짓이다. 참인 −2에만 f를 호출해 2를 만든다.

  2. 나머지 0과 3은 원래 값을 넣는다. 입력 목록을 바꾸지 않고 새 목록 [2,0,3]을 만든다.

p는 3회, f는 1회이며 길이와 순서를 보존한다. 빈 목록이면 두 콜백 모두 0회다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

순수한 전체 함수 u,v의 두 map 합성을 원소 인덱스로 증명하라. 두 방식의 콜백 수와 중간 목록을 구별하고 실제 시간 우위를 결론내릴 수 있는지 답하라.

힌트 1

길이 n의 각 인덱스 i 결과를 적는다.

힌트 2

클로저가 같은 이름을 잡으면 숫자와 객체 내용도 그대로일까?

자유변수를 찾을 때 먼저 조사할 표현식의 테두리를 그린다. 전체 식 let z=x+1 in fun x -> x+z+y에서 초기식의 x는 안쪽 fun x가 묶지 못한다. 전체 자유변수는 {x,y}다. 안쪽 함수 fun x -> x+z+y만 떼어 보면 x는 매개변수로 묶여 자유변수가 {z,y}다. 하나의 철자가 위치에 따라 다른 바인더를 가리킬 수 있다.

다음 별도 Python식 손모형은 한 factory 호출의 지역 box 바인딩을 사용한다. 처음 box는 내장 리스트 B=[2]다. f는 호출 때 같은 지역 box 바인딩을 읽어 box[0]을 반환한다. g는 만들 때 box[0]의 정수 2를 별도 인자 값으로 저장한다. h는 만들 때 리스트 B의 참조를 별도 인자 값으로 저장하여 그 객체의 첫 항목을 읽는다. 이후 B[0]을 5로 변경하고 지역 box를 새 리스트 D=[8]로 재결박한 뒤 셋을 반환한다.

나중의 f는 D를 찾아 8, g는 저장한 정수 2, h는 B의 현재 내용 5를 읽는다. 세 함수는 같은 단계에 만들었어도 바인딩 조회·정수 저장·객체 참조 저장이 서로 다르다. 어휘적 범위는 호출자의 임의 box를 찾지 않는 규칙이며 깊은 복사 보장이 아니다. 실제 Python 클로저 생성·기본 인자 실행·수명 측정은 하지 않는다.

먼저 확인할 개념
  • 정의 환경과 호출자 환경

    현재 바인딩의 값 변경과 동적 이름 조회를 분리한다.

  • 자유변수 경계와 캡처

    표현식 경계별 바인더와 코드/환경 쌍을 새 장부로 확장한다.

1. 자유변수는 어디서 값을 찾는가

fun x -> x+bias라는 표현식에서 x는 이 함수의 매개변수로 묶이지만 bias는 이 표현식 안에서 묶이지 않는다. 따라서 자유변수 집합은 {bias}이다. 자유변수라는 말은 전역 변수라는 뜻이 아니다. 바깥 함수의 지역 변수도 안쪽 함수에서는 자유변수일 수 있다. 무엇을 자유변수라고 부르는지에는 조사하는 표현식의 경계가 필요하다.

환경은 이름을 값 또는 저장 위치와 연결하는 대응으로 생각한다. 어휘적 범위에서는 소스 코드에서 함수를 정의한 주변 바인딩을 따른다. 함수 본문과 정의 환경을 함께 가진 값을 클로저라고 한다. 호출할 때는 그 정의 환경에 매개변수와 실제 인자의 대응을 덧붙여 본문을 평가한다. 호출한 장소의 같은 이름을 무조건 선택하는 규칙은 동적 범위이며 다른 규칙이다.

2. 불변 모형에서의 가려짐과 반환

다음은 불변 정수 바인딩을 쓰는 OCaml식 종이 모형이다. bias=4를 묶고 f=fun x -> bias+x를 만든 뒤, 더 안쪽에서 bias=100을 새로 묶고 f 2를 호출한다. f의 정의 환경에는 처음의 bias=4가 있으므로 결과는 6이다. 새 이름이 이전 값을 변경한 것이 아니라 더 안쪽 바인딩으로 가린 것이다.

make n = fun x -> 4+n+x라고 정의하면 make 3은 n=3인 환경과 안쪽 함수를 묶어 반환한다. 반환 후에도 필요한 n을 해석할 수 있어야 하며, 호출한 쪽에 n이라는 이름을 새로 만들 필요가 없다. make 3으로 만든 함수에 2를 주면 9이다. 실제 구현이 모든 환경을 복사할지 필요한 값만 보존할지는 구현 문제이며 이 의미 규칙만으로 저장 방식이나 메모리 비용을 확정하지 않는다.

3. 캡처는 항상 값 복사가 아니다

어휘적 범위는 어느 바인딩을 찾는지 정하는 규칙이다. 그 바인딩이 가리키는 내용이 나중에 바뀔 수 있는지는 별도의 성질이다. Python에서 maker 안에 x=3, f=lambda: x, x=8을 순서대로 두고 f를 반환하는 모형을 생각하자. 나중의 f()는 같은 바깥 지역 바인딩 x를 읽어 8을 얻는다. 호출자의 임의의 x를 찾는 동적 범위라서 8이 되는 것이 아니다.

따라서 모든 클로저가 생성 순간의 숫자를 영구히 복사한다고 가르치면 변경 가능한 언어의 동작을 잘못 예측한다. 공유하는 리스트나 객체의 내용 변경도 별도로 살펴야 한다. 반대로 앞의 불변 모형에서는 새 bias 바인딩이 옛 바인딩을 변경하지 않는다. 언어마다 자유변수 해석, 재할당, 객체 공유, 수명 규칙을 명시한 뒤 예측해야 하며 여기서는 실제 Python 실행이나 메모리 측정을 하지 않았다.

  1. f 본문에서 x는 매개변수이고 bias는 자유변수이므로 정의 시 주변 환경을 확인한다.

  2. f를 만들 때 연결된 bias는 4이다. 뒤의 bias=100은 더 안쪽의 새 바인딩이며 이전 것을 수정하지 않는다.

  3. f 호출 환경에는 x=2를 추가하므로 4+2=6이다. 호출 장소의 bias=100을 대신 고르면 102가 되지만 이는 다른 범위 규칙이다.

  4. make 3을 적용할 때 n=3인 정의 환경을 안쪽 함수와 묶는다. 이 안쪽 함수에서 x만 아직 입력되지 않았다.

  5. g 2는 x=2를 더하여 4+3+2=9가 된다. g를 반환한 다음에도 그 n을 해석하는 의미가 유지된다.

f 2=6, g 2=9이다. 두 계산은 명시한 불변·어휘적 범위 모형의 종이 판정이다. Python의 재할당 예제에는 같은 스냅숏 설명을 적용하지 않는다.

초기식과 함수 본문은 같은 바인더 안에 있지 않다

let z=x+1 in fun x -> x+z+y의 전체와 안쪽 fun x만의 자유변수를 구하라.

  1. let의 z는 자기 초기식 x+1에서 아직 묶이지 않는다. 초기식의 자유 이름은 {x}다.

  2. 본문 fun x는 자기 x를 묶고 z,y를 자유로 둔다. 바깥 let이 z를 묶어 전체에는 초기식 x와 y가 남는다.

전체는 {x,y}, 안쪽 함수만은 {z,y}다.

마지막 인수를 기다리는 동안 기록은 언제 생길까?

커리된 순수 함수 affine a b x=a*x+b의 타입은 int -> (int -> (int -> int))다. affine 2의 결과는 b와 x를 받을 함수이며 affine 2 3의 결과는 x를 받을 함수다. 마지막 입력 4에서 정수 11을 얻는다. 중간 함수 반환은 함수 값의 지위와 정의 환경을 함께 사용한다. 쌍이나 삼중항을 요구하는 함수에 첫 숫자만 주는 것은 부분 적용이 아니다.

별도 효과 모형 build(a)는 기록 A(a)를 붙이고 함수 stage(b)를 반환한다. stage(b)는 기록 B(b)를 붙이고 함수 run(x)를 반환한다. run(x)는 기록 X(x)를 붙이고 a*x+b를 반환한다. 기록은 함수 적용을 할 때만 생기며 단순히 함수 변수를 저장할 때 생기지 않는다. L=[]에서 k=(build 2) 3을 한 번 만든 뒤 k 4, k 5를 순서대로 부르면 A(2),B(3),X(4),X(5)와 정수 11,13을 얻는다.

각 최종 호출마다 ((build 2) 3)를 다시 만들면 A/B 기록도 다시 생긴다. 같은 정수 결과를 내는 순수 커링 대응과 효과가 있는 준비 단계의 관찰 대응을 나눈다. 실제 OCaml 실행 순서 전부를 가정하지 않고 모든 단계 적용을 순서대로 한 문장씩 수행하는 자체 손모형이다.

  • 반환 함수의 정의 환경

1. 쌍을 받기와 함수를 반환하기

두 정수를 한 쌍으로 받는 subPair((x,y))=x-y는 입력 타입이 정수쌍이고 결과는 정수이다. 커링은 이런 함수를 sub x = (fun y -> x-y)처럼 첫 인자를 받으면 둘째 인자를 기다리는 함수를 반환하도록 바꾸는 작업이다. 수학적으로 A×B→C와 A→(B→C)의 관계를 다룬다. 괄호를 없애는 표기 장난이 아니라 중간 결과가 함수라는 점이 핵심이다.

커리된 타입 int -> int -> int는 int -> (int -> int)로 읽는다. 함수 적용 sub 10 3은 (sub 10) 3으로 읽어 먼저 함수를 얻고 그 함수에 3을 준다. 화살표의 결합과 함수 적용의 결합이 반대 방향이므로 괄호로 확인하면 좋다. 실제 언어의 문법은 달라질 수 있으므로 이 단원은 OCaml식 표기와 수학적 정수 모형을 사용한다.

2. 부분 적용은 인자를 일부 정하기

부분 적용은 이미 있는 함수의 인자 중 일부를 고정하여 남은 인자를 받는 함수를 만드는 일이다. sub 10은 첫 인자를 10으로 고정한 함수 g이며 g 3=7이다. 커링은 함수의 입력 형태를 변환하는 작업이고 부분 적용은 특정 값을 넣어 새 함수를 만드는 작업이므로 동일한 정의가 아니다. 커리된 함수는 단계별 반환을 이용해 부분 적용을 쉽게 표현한다.

고정하는 위치가 중요하다. sub 10은 10-y이고 fun x -> sub x 10은 x-10이다. 둘 다 인자 하나만 기다리지만 입력 3에서 7과 -7로 다르다. 쌍을 받는 함수에도 fun y -> subPair((10,y))라는 래퍼를 만들어 부분 적용 효과를 얻을 수 있다. 다만 subPair에 숫자 10 하나만 직접 주는 것은 쌍을 요구하는 타입의 입력 조건을 만족하지 않는다.

3. 여러 단계와 부작용의 경계

scale a b x = a*x+b라는 커리된 함수에서 scale 2는 b와 x를 더 기다리고 scale 2 3은 x만 기다린다. scale 2 3 7의 계산 결과는 17이다. 순수한 모형에서는 마지막 인자를 받기 전에는 a*x+b의 정수 결과를 아직 계산할 수 없다. 앞 단계의 결과를 함수 값으로 표에 표시하면 어느 인자가 남았는지 알 수 있다.

실제 언어에서는 바깥 함수를 호출하는 단계에서 로그를 남기거나 예외를 던질 수 있다. 따라서 커링 전후에 모든 부작용의 시점과 호출 비용이 자동으로 같다고 주장해서는 안 된다. 여기서 쌍 함수와 커리된 함수의 정수 결과 대응은 순수하고 전체 입력이 주어진 경우의 주장이다. 함수 생성이나 환경 보존의 실제 비용은 구현과 최적화에 따라 달라지며 이 종이 계산은 성능 측정이 아니다.

중간 과정을 따라가는 예제

sub x y=x-y, scale a b x=a*x+b이다. g=sub 10, h=fun x -> sub x 10, k=scale 2 3을 만들고 각각 입력 3,3,7에 적용하라.

  2. g 3에는 y=3을 넣어 10-3=7을 얻는다.

  3. h는 x를 기다리는 래퍼이고 h 3은 sub 3 10이므로 3-10=-7이다. 고정 위치가 g와 다르다.

  4. scale 2는 b를 기다리는 함수, scale 2 3은 x를 기다리는 함수이다. k에는 a=2,b=3이 고정되어 있다.

g 3=7, h 3=-7, k 7=17이다. sub 10과 scale 2 3 자체는 함수 값이며 최종 정수 결과가 아니다.
