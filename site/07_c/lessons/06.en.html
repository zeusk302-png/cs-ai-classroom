Subtopic 6.1

Null termination and length

Why can strlen return 1 when an array has six character slots?

Preparation and learning goals

Preparation

  • A char array is an object with character-storage slots. char a[6] has six char elements with valid indices 0 through 5. sizeof(char) is 1 in C, but a C byte is not assumed always to contain eight bits.
  • '\0' is the null character with integer value zero. Its role differs from the character '0' and the pointer macro NULL. A string needs its terminating zero inside the array.
  • Readiness check: in [A,0,B], the string content before the first zero occupies one slot. Checking from the left through that zero reads two slots, A and zero. The entire array contains three slots. Content length, actual reads, and capacity are different quantities.

Learning goals

  • Define the end of a C string and the length returned by strlen.
  • Distinguish storage capacity, logical string length, and data following the first NUL.
  • Explain the access bound, termination, and failure result of a bounded search.

The first NUL defines the string

In C11, a string is a contiguous sequence of characters up to and including its first null character. String length, however, counts the bytes before that null. For char a[6]={'A','\0','B','C','\0','\0'}, the string starting at a has length 1 and the array has capacity 6. B and C remain stored, but strlen(a) does not count them after the first zero.

strlen requires a valid string in which the terminating zero can be found. Calling it on an array with no zero to find a length and checking afterward may already violate its contract. An empty string of length zero has zero in its first slot; it is not a lack of storage or a NULL pointer. A one-slot char empty[1]={0} can hold an empty string.

Check without trusting a string length first

The bounded_length function below requires s to provide cap readable char elements that remain alive and out to point to a writable size_t object. With cap=0, this custom function does not read s, so its contract may allow s=NULL; out must still be valid under the stated contract. A NULL s with cap>0 violates it. Only a return value of 1 writes a new length through out. A return value of 0 means that no terminator was found within the supplied range.

In i<cap && s[i]!='\0', && evaluates its right operand only when the left operand is true. Thus i==cap does not read s[cap]. Before each iteration, 0≤i≤cap and the preceding i slots are all nonzero. The function either finds the first zero or fails at i==cap. Supplying a false cap prevents this check from guaranteeing the actual object boundary.

Byte length is not the number of visible characters

strlen does not decode characters or count displayed symbols. With the additional assumption of UTF-8 using eight-bit bytes, U+AC00 가 is encoded by EA B0 80, three bytes; adding terminating 00 requires at least four slots. The string length is 3. Ordinary C char strings are not automatically UTF-8. The code below uses only basic execution-set characters A,B,C,X,Y,Z.

External files may contain zeros within data. Binary data should carry its actual byte length separately; strlen cannot recover that length. Decoding, normalization, and identifying displayed characters are other layers. The raw array below holds three binary-data slots, not a C string, so it is not passed to strlen or %s.

#include <stdio.h>
#include <stddef.h>
#include <string.h>
static int bounded_length(const char *s, size_t cap, size_t *out) {
    size_t i = 0;
    while (i < cap && s[i] != '\0') {
        ++i;
    }
    if (i == cap) return 0;
    *out = i;
    return 1;
}
int main(void) {
    char a[6] = {'A', '\0', 'B', 'C', '\0', '\0'};
    char raw[3] = {'X', 'Y', 'Z'};
    size_t len = 99;
    int ok = bounded_length(a, sizeof a, &len);
    printf("%zu %zu %d %zu\n", sizeof a, strlen(a), ok, len);
    ok = bounded_length(raw, sizeof raw, &len);
    printf("%d %zu\n", ok, len);
    return 0;
}

A worked example, step by step

Trace the storage, return values, and changes to len for a and raw in the complete example. Assume normal output succeeds; this is not an actual execution.

  1. The capacity of a is 6, with its first zero at index 1. sizeof a=6 and strlen(a)=1; later slots do not contribute to the length.
  2. bounded_length(a,6,&len) checks A at i=0 and stops at i=1. It returns 1 and sets len=1, so the first output arguments are 6,1,1,1.
  3. raw contains X,Y,Z with no zero. The loop increments at i=0,1,2; at i=3 the left condition is false, so it does not read a fourth slot.
  4. On failure, the function returns 0 without assigning through out. The previous len=1 remains. Ignoring the return value could incorrectly suggest that raw has string length 1.

Expected stdout has first line 6 1 1 1 and second line 0 1. The retained len after failure does not describe a string length for raw.

Try it with paper and the lesson

Draw five slots [P,Q,0,R,0] and four slots [P,Q,R,S]. Pass each to bounded_length with its correct cap and initial output value 77. Find the return value, output value, and last index read.

Show hint

Reading the zero itself is also a check. Failure does not assign out, and index cap is not read.

Show solution

The first array reads indices 0,1,2, returns 1, and sets out=2. The second reads 0 through 3, stops at i=4, returns 0, and retains out=77. Neither cap=4 nor the old output value guarantees a string length.

Misconception and counterexample

For any character array, strlen safely tells you its capacity.

strlen(a) is 1 for a[6], while sizeof a is 6. Calling strlen on raw[3] without a zero makes the terminator search exceed the object contract and yields undefined behavior. Do not predict a fixed numeric result for UB.

Check your understanding

What are the length and capacity of char e[1]={0};?

Show answer and reasoning

Length 0, capacity 1.

The terminating zero occupies storage but is excluded from the length.

Can strlen recover the full size of an eight-byte packet containing an internal zero?

Show answer and reasoning

Not in general.

It does not count data after the first zero; preserve the packet length separately.

With cap=3 and i=3, does the code read s[3]?

Show answer and reasoning

No.

The left operand i<cap is false, so && does not evaluate the right operand.

Explore further

Proof: assume before an iteration that 0≤i≤cap and every supplied s[j] with j<i is nonzero. A true condition gives i<cap, so the current slot is valid and nonzero; incrementing preserves the invariant. The natural-number variant cap−i decreases by one each iteration, proving finite termination. Ending with i<cap means s[i]=0 and no earlier zero, so it is the first terminator. Ending with i=cap means the entire range has no zero. Since i<cap before increment, i reaches at most cap, so the final increment does not overflow even in the model cap=SIZE_MAX. The existence of a readable object of that size is a separate precondition.

Subtopic 6.2

Character arrays and literals

Why do a and p, both initialized from "cat", differ in what can be modified?

Preparation and learning goals

Preparation

  • An array is an object containing elements; a pointer is a value pointing to an object location. const char *p disallows changing characters through p; that differs from prohibiting assignment to p itself.
  • Initialization establishes the initial contents of a new object. char a[]="cat" creates a character array, not stored pointer data. char *p="cat" creates a pointer to the first character of a string literal.
  • Readiness check: 'A' is a character constant and "A" is a string literal containing a terminating zero. Their types and storage differ in C.

Learning goals

  • Distinguish character-array initialization from a string literal.
  • Explain terminator storage and the object measured by sizeof.
  • Separate lifetime, const-qualified access, and UB from modifying a literal.

Initialization creates an independent array

An ordinary C11 string literal "cat" is implemented as an array of char with basic characters c,a,t followed by zero, with static storage duration. char a[]="cat" creates a separate array object initialized with those four characters. The a below is alive with automatic storage duration in main; a[0]='b' changes it to "bat". It does not modify the literal.

char b[6]="cat" gives [c,a,t,0,0,0]. C11 also allows the exact-size initialization char raw[3]="cat", but there is no room for the terminating character, leaving [c,a,t]. Valid initialization does not make raw a C string. The code reads each element with %c, never with %s or strlen.

Literal element type and the modification rule differ

Ordinary C literal arrays have element type char, but attempting to modify them is undefined behavior. Do not import the C++ literal-type rule into C11. Even where char *q="cat" is allowed, q[0]='b' is not a safe modification. Using const char *p expresses read-only access in the type and helps prevent mistakes.

In const char *p, const prevents changing the pointed-to character through p. Assigning p="dog" to point to another literal is allowed. Preventing reassignment of the pointer itself requires const in a different position, as in char *const. Whether identical literal storage arrays are merged is unspecified; pointer-address identity is not a general text-equality test.

sizeof and object lifetime

sizeof a is 4 for the four-char array. sizeof p is the pointer object's size, not string length or terminator capacity; do not fix it to a particular number. strlen(a) counts the current three bytes before the first zero, giving 3. In C, the character constant 'A' has type int, while "A" is a two-char array. sizeof('A') is sizeof(int), not assumed to be 1.

A literal has static storage duration, so returning a pointer to it is not by itself a lifetime violation. In contrast, returning a pointer to automatic char tmp[]="cat" in a function leaves the pointed-to array dead after the function exits. Contracts need a living object as well as modifiability and capacity. The example reads all automatic arrays only while they remain alive in main.

#include <stdio.h>
#include <string.h>
int main(void) {
    char a[] = "cat";
    const char *p = "cat";
    char raw[3] = "cat";
    a[0] = 'b';
    printf("%zu %zu %s %s\n", sizeof a, strlen(a), a, p);
    printf("%zu %c%c%c\n", sizeof raw, raw[0], raw[1], raw[2]);
    return 0;
}

A worked example, step by step

Make separate object diagrams for a,p,raw, then find the two expected lines after changing a[0].

  1. a has [c,a,t,0] in four slots; p points to the first slot of a static literal [c,a,t,0]. raw has only [c,a,t].
  2. a[0]='b' changes only the separate modifiable array. The literal read through p retains c.
  3. sizeof a=4 and strlen(a)=3. The two %s conversions read only terminated a and p, displaying bat and cat.
  4. sizeof raw=3. Three %c conversions read its elements individually, without a terminator search, displaying cat.

Expected stdout is first line 4 3 bat cat and second line 3 cat. Replacing raw output with %s is not treated as a safe executable example.

Try it with paper and the lesson

Draw the contents of char x[5]="Hi"; char y[2]="Hi"; const char *z="Hi";. Distinguish valid sizeof and string-length claims, and assess x[0]='B', z="Bye", and z[0]='B'.

Show hint

Two basic characters in Hi are followed by zero. An explicit character-array size can leave no room for the terminator.

Show solution

x=[H,i,0,0,0], sizeof x=5, strlen(x)=2. y=[H,i], sizeof y=2, but it does not meet the strlen precondition. sizeof z is pointer size and strlen(z)=2. Changing x[0] and reassigning z are allowed. Writing z[0] violates const-access constraints and requires a diagnostic; removing const and modifying the literal still gives UB.

Misconception and counterexample

A C literal can be modified because its element type is char, and sizeof a pointer tells its string storage size.

The element-type description and the prohibition on modifying a literal are separate rules. Modifying p[0] through char *p="cat" is UB, and sizeof p measures the pointer object. This differs from sizeof a=4 and valid a[0] modification for independent char a[]="cat".

Check your understanding

Is char s[3]="cat"; necessarily an invalid declaration in C11?

Show answer and reasoning

No. A three-slot initialization without a terminator is allowed.

With no room, the terminating literal character is omitted from initialization; safety of string operations is a separate issue.

Does const char *p also forbid assigning p="dog"?

Show answer and reasoning

No.

const qualifies the pointed-to char, not the pointer object p itself.

Can you return and later use the address of automatic char local[]="ok" from a function?

Show answer and reasoning

No.

The automatic object ends its lifetime on block exit; a terminating zero alone cannot make later access valid.

Explore further

A literal "AB\0CD" contains A,B,0,C,D and an added final zero, forming a six-char array. Initializing char s[] from it gives sizeof s=6 but strlen(s)=2; C and D remain array contents after the first string. Do not assume every literal represents one visible text without internal zeros. With possible literal merging, judge text by appropriate element comparison, rather than treating equality or inequality of two pointers as general proof of full contents from different declarations.

Subtopic 6.3

Standard string functions

Why does strncpy have a length argument yet fail to guarantee a string terminator?

Preparation and learning goals

Preparation

  • Copying writes source contents into destination storage. Check readable source extent, writable destination extent, and object lifetimes separately. A returned pointer is not a successful capacity check.
  • Ranges overlap if they share slots. Within one array, [0,5) and [1,6) overlap. Separate living arrays bytes and copy are distinct objects.
  • Readiness check: copying the string [A,B,0] needs all three slots, including zero. Copying binary data [X,0,Y] must also preserve Y after the internal zero.

Learning goals

  • Compare the termination, padding, and capacity contracts of strcpy and strncpy.
  • Explain explicit byte counts and overlap conditions for memcpy and memmove.
  • Trace examples by combining function choice with separate boundary checks.

Copy a string including its terminator

strcpy(dst,src) copies a valid source string including its terminating zero. For source length L, the destination needs at least L+1 slots, and overlapping ranges give UB. There is no capacity argument, automatic size check, or allocation. dst[5] and "cat" in the code allow a four-slot copy. If another executing agent can change the source between measurement and writing, one length measurement cannot by itself prove safety.

strncpy(dst,src,n) does not copy source characters after its first zero. If the source string is shorter than n, it pads with zeros until n destination slots have been written. If the first n source characters have no zero, it copies only those n and adds no terminator. The destination must support n writes and the source must meet its required readable extent; overlap is not allowed. raw[3] becomes unterminated W,X,Y, never used for string output.

Copy an explicit number of bytes

memcpy(dst,src,n) copies n char-unit bytes without searching for string termination. It also copies data after internal zeros and adds no automatic zero. Both n-slot extents must be valid, and ranges must not overlap. C11 generally still requires valid pointer arguments for standard string-library functions when n=0, unless an explicit exception says otherwise. Do not teach memcpy(NULL,NULL,0) as a generally safe idiom.

memmove requires the same n-slot extents but handles overlap as if copying through a temporary nonoverlapping array. Its implementation need not actually allocate that temporary array. The code shifts five slots A,B,C,D,0 of "ABCD" one place right to make [A,A,B,C,D,0]. Source [0,5) and destination [1,6) are both within a six-slot array. Allowing overlap does not fix out-of-object writes.

Select a contract rather than relying on a function name

strncpy makes pad[5] into Q,0,0,0,0; raw becomes W,X,Y and copy becomes X,0,Y. Their reading methods differ. pad is a terminated string; the three raw characters and Y after the internal zero in copy need separate lengths or individual reads. Assuming that a name means safe without checks misses missing terminators, padding cost, and overlap.

Mark required read and write counts for each call on paper. strcpy reaches the first zero; strncpy searches the source up to n characters or the first zero and writes n slots; memcpy/memmove use the stated n slots. This does not provide destination expansion, allocation-failure handling, or concurrent-access safety. The complete example uses sufficiently large fixed arrays and living sources. UB variants have no supplied output answer.

#include <stdio.h>
#include <string.h>
int main(void) {
    char dst[5];
    char raw[3];
    char pad[5];
    char overlap[6] = "ABCD";
    const char bytes[3] = {'X', '\0', 'Y'};
    char copy[3];
    strcpy(dst, "cat");
    strncpy(raw, "WXYZ", sizeof raw);
    strncpy(pad, "Q", sizeof pad);
    memmove(overlap + 1, overlap, 5);
    memcpy(copy, bytes, sizeof copy);
    printf("%s %c%c%c\n", dst, raw[0], raw[1], raw[2]);
    printf("%d %d %d %d\n", pad[1] == 0, pad[2] == 0,
           pad[3] == 0, pad[4] == 0);
    printf("%s %c %d %c\n", overlap, copy[0], copy[1] == 0, copy[2]);
    return 0;
}

A worked example, step by step

Trace the five copies in order and explain why the output method for unterminated raw is valid.

  1. After strcpy, dst includes c,a,t,0. strncpy writes only W,X,Y into raw without zero. The first line uses %s for dst and three %c conversions for raw.
  2. strncpy writes Q and then four zeros into pad. Each pad[k]==0 comparison yields true as int 1.
  3. memmove preserves the old source A,B,C,D,0 as if placing it at positions1 through5. overlap is A,A,B,C,D,0, the string AABCD.
  4. memcpy copies all three X,0,Y slots into copy. The %c, comparison, %c output displays X,1,Y instead of stopping at the first zero.

Expected stdout has three lines: cat WXY / 1 1 1 1 / AABCD X 1 Y. Slashes here separate lines and are not output characters. No C execution was performed.

Try it with paper and the lesson

For char a[5]="ABCD";, draw the result of memmove(a,a+1,4). For separate char b[4], list all slots after strncpy(b,"Hi",4). Can an overlapping copy changed to memcpy be said to produce the same output?

Show hint

The four source slots from a+1 are B,C,D,0. A short strncpy source is zero-padded to n destination slots.

Show solution

a becomes [B,C,D,0,0], representing BCD; its old last zero is not overwritten. b becomes [H,i,0,0]. The source and destination in a overlap, so substituting memcpy gives UB; predicting BCD is not a valid answer.

Misconception and counterexample

strncpy always adds NUL, and memmove automatically provides space.

Copying "WXYZ" into raw[3] with n=3 gives only WXY, without NUL. If a has only five slots, memmove(a+1,a,5) writes its last destination slot outside the object. Overlap support is not capacity checking.

Check your understanding

How many slots does strncpy(d,"Q",5) write?

Show answer and reasoning

Five.

It writes Q followed by a terminating zero and padding: four zero slots in total.

Does memcpy copy bytes after the first zero?

Show answer and reasoning

Yes, within the stated n-byte range.

It copies bytes without searching for string termination.

If an overlapping memcpy seems to work in an observation, does its standard contract become valid?

Show answer and reasoning

No.

Overlap is a UB condition; one implementation observation cannot create a C11 guarantee.

Explore further

For a one-slot rightward overlapping shift, naive left-to-right assignment copies a[0] into a[1], then the already changed A from a[1] into a[2], losing the original B. Moving from the source end toward the right destination preserves unread source values; this invariant proves that direction. For a leftward move, front-to-back is appropriate. memmove supplies the original n-byte result contract without requiring the caller to implement direction choice. Checking L+1≤cap before strcpy can avoid addition overflow by using L<cap together with a valid, stable source string. Before calculating L+1 as an allocation size, reject L==SIZE_MAX.

Subtopic 6.4

Buffer size and truncation handling

When planet is formatted into five slots, does the return value mean four stored characters or six required characters?

Preparation and learning goals

Preparation

  • Buffer capacity cap counts actual writable char slots. A string needs L content slots and one terminator slot. Holding it requires cap>0 and L<cap.
  • The %s conversion reads a valid source string. snprintf parameter n bounds destination writes; it does not validate the source or its readable boundary.
  • Readiness check: draw five slots and reserve the last one for zero. Only four content slots remain. Mark the desired six and actually stored four in different colors.

Learning goals

  • Distinguish snprintf required-length results from actual stored output.
  • Assess negative errors, n=0, n=1, and exact truncation boundaries.
  • Explain truncation policy, encoding, format-string, and overlap conditions.

The space contract of snprintf

For normal output with n>0, C11 snprintf(s,n,format,...) writes at most n−1 content slots followed by zero. The destination must actually permit n writes. With n=0, nothing is written, and this specific exception permits s=NULL. With n=1 and nonempty content, only a zero in the first slot remains. The function does not expand a string automatically.

A nonnegative normal return r is the number of output characters that would have been written with enough space, excluding the final zero. An encoding error gives a negative result. After checking r≥0, r<n means complete storage and r≥n means truncation. For n=0 even r=0 does not satisfy 0<0; do not claim that an empty string was written. The basic-string examples assume the required count fits int and normal formatting is possible.

Handle errors separately from truncation

Formatting "planet" into out[5] normally returns r=6 and stores p,l,a,n,0. strlen(out)=4. Do not use 6 as a copied-slot count for array reading. In this fixed example sizeof out=5 is representable as int, so comparing with (int)sizeof out is valid. Narrowing an arbitrary size_t capacity to int requires that condition and is not a general pattern.

In a general function, handle r<0 first and compare nonnegative r and cap in a type that preserves both values. For example, uintmax_t from <stdint.h> can represent both size_t and nonnegative int, allowing (uintmax_t)r < (uintmax_t)cap. Converting negative errors to unsigned before checking can make them appear to be large lengths. Do not read the buffer after a negative result as a successfully completed string; follow the error policy.

Storage safety and the meaning of content

Accepting truncation, rejecting input, or retrying with more storage after validation is a program policy. Quietly truncating identifiers or file paths can map distinct originals to the same prefix, so rejecting them may be appropriate. A two-call measure-and-allocate approach also needs extra space, a nonoverflowing length+1, allocation-failure handling, and stable source and formatting arguments between calls.

A terminating zero does not make a sequence valid if truncation splits an eight-bit UTF-8 encoding. The output bound concerns byte storage, not Unicode boundaries or security policy. Use a fixed format such as snprintf(out,cap,"%s",input), rather than using input directly as the format. input still must be a valid string. Overlap in snprintf(buf,cap,"%s",buf) is UB in C11, so the example uses a separate literal source.

#include <stdio.h>
#include <string.h>
int main(void) {
    char out[5];
    int r = snprintf(out, sizeof out, "%s", "planet");
    if (r < 0) {
        puts("encoding error");
        return 1;
    }
    printf("%d %zu %s\n", r, strlen(out), out);
    if (r >= (int)sizeof out) puts("truncated");
    else puts("complete");
    int needed = snprintf(NULL, 0, "%s", "planet");
    if (needed < 0) return 1;
    printf("%d\n", needed);
    return 0;
}

A worked example, step by step

Trace the successful out[5] path and the NULL,0 measuring call on paper. No compilation or output run was performed; the negative-error path is not claimed as an observed execution.

  1. planet has six basic characters and a terminating zero. Enough destination storage would allow six output characters, so normal r=6.
  2. With n=5, the first four characters plan and zero are stored. The r<0 check is false and strlen(out)=4.
  3. sizeof out=5 fits int. Since 6≥5, the branch prints truncated. Being able to print the stored string differs from storing it completely.
  4. snprintf(NULL,0,...) writes nothing to a destination and normally returns the required count6. Do not confuse array-size measurement with output-content measurement.

The expected normal-path stdout has three lines: 6 4 plan / truncated / 6. Truncation is detected. The occurrence or output of a negative encoding-error path was not actually observed.

Try it with paper and the lesson

Format basic-character "Hello" with snprintf into separate destinations of capacity0,1,5,6. Tabulate normal return, stored content, and completeness. For n=0 the destination may be NULL; others are valid arrays of the stated size.

Show hint

The required count5 is unchanged by capacity. When n>0, at most n−1 content slots are stored; completion needs 5<n.

Show solution

All normal returns are5. n=0 writes nothing and stores no string; completion is false. n=1 stores [0], an empty string with truncation. n=5 stores Hell and zero, truncated. n=6 stores Hello and zero, complete. Return equal to capacity at n=5 is the truncation boundary, not completion.

Misconception and counterexample

Because snprintf appends NUL, truncation, security, and Unicode are all safe.

out[5] is terminated as plan but does not fully contain planet. Splitting a multibyte sequence can invalidate UTF-8, and identifier-prefix collisions are a separate problem. A name also cannot justify n beyond actual capacity or overlapping source and destination.

Check your understanding

For normal r=5,n=5, is the full output stored?

Show answer and reasoning

No, it is truncated.

A terminator needs its own slot; completion requires the strict inequality r<n.

If snprintf(NULL,0,...) normally returns6, did it write a zero through NULL?

Show answer and reasoning

No. Nothing is written.

n=0 is the explicit no-write exception that can measure required output length.

May a negative r be converted to size_t and used as a required length without checking?

Show answer and reasoning

No.

A negative error can convert to a large unsigned value; separate the error branch first.

Explore further

Proof: with normal generated count L≥0 and n>0, the stored output-character count is min(L,n−1); including the final terminator gives min(L,n−1)+1≤n writes. Full preservation requires L≤n−1, or L<n. Treat the n=0 no-write case separately. A capacity5 policy can truncate both planet and plank to plan, so the original-to-stored mapping is not injective. Preserve identifier uniqueness by rejecting truncation or handling collisions explicitly. Allocating L+1 also requires that L fit size_t and the addition not overflow; successful measurement does not guarantee a stable source or successful allocation for the next call. Here stored content length means generated output-character count. It equals strlen only if the output has no internal NUL. For example, a normal snprintf(buf,2,"%c",0) into a valid two-slot array returns1 and stores [0,0], so strlen(buf)=0. This counterexample is a paper contract trace, not an execution.
