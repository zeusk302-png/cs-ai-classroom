小节 4.1

函数原型与调用

函数体写在后面时，要在前面安全地调用它，需要先告诉编译器什么？

预备知识与学习目标

预备知识

  • 声明介绍名称和类型，定义提供函数体。int是整数类型，分号标记声明的结束。
  • 实参是调用括号里的表达式，形参是函数接收值时使用的局部名称。2+3是本单元所有C实现都能用int表示的小值。

学习目标

  • 在函数原型中标明返回类型和形参类型。
  • 区分C11中的(void)和空的()声明。
  • 解释类型检查与语义契约的区别。

在调用之前给出类型约定

int add(int a, int b);是一个函数原型，表示接收两个int并返回int。这里的a,b名称用于帮助理解，不必与调用者的名称相同。即使函数体在后面，只要调用位置能看到这个声明，就可以使用类型信息。

下面是除标准库外不依赖其他组件的完整源代码。add的定义也必须与声明兼容。存在声明与定义确实包含在程序中是两回事，因此若把定义移到另一个文件，链接阶段仍要提供该定义。

#include <stdio.h>
int add(int a, int b);
int main(void) { int r=add(2,3); printf("%d\n",r); return 0; }
int add(int a, int b) { return a+b; }

实参转换与检查的范围

在能看到函数原型的调用中，实参个数以及实参和形参类型之间允许的关系受到约束。每个实参的值会像赋值一样转换为对应形参的类型。把double值作为int实参传入并不总是语法错误。有限值2.75转换为int得到2；但若整数部分超出目标类型范围，就不能把它视为安全调用。

类型信息不能证明a+b位于int范围内，也不能证明指针指向仍在生存期内的对象。add的语义契约要求两个输入及其数学和都能用int表示。违反约束时要求给出诊断，但不能因此断言所有编译器都一定拒绝翻译。

固定版本与求值顺序

本单元使用C11。int ping(void);是明确表示没有形参的函数原型。相反，非定义的int ping();声明中的空括号不提供形参个数和类型信息。不要把C++或C23的空括号规则混进这段说明。

函数调用的实参在进入函数体之前求值，但不保证从左到右求值。若修改操作需要固定顺序，就先用独立的语句完成修改，再把结果作为实参传入。本单元不把在未定序的实参表达式中多次修改同一标量的代码当作输出示例。

逐步推导的例题

在完整的add源代码中追踪main的r和预期标准输出。

  1. 进入main后，add声明中的两个int与调用实参2,3对应。
  2. 开始一次形参为a=2,b=3的函数调用。
  3. a+b=5处于int范围内，因此return 5使调用表达式的值为5。
  4. main中的r=5，int值5传给printf的%d。

预期输出是5和换行。没有实际编译或运行记录。

用纸笔和正文动手试一试

在纸上写下int f(void);和int g();，标出哪个声明在C11中明确给出无实参调用的契约。再追踪add(4,5)。

查看提示

始终记住：这里读的是声明，不是定义。

查看解答

f表示没有形参，g表示不提供相关信息。add的形参为4,5，和为9。不能据此断定g能安全地接受任意实参。

常见误解与反例

有了函数原型，就会自动阻止所有错误输入。

即使add(INT_MAX,1)的类型匹配，数学和超出int范围时仍会发生有符号整数溢出，属于未定义行为。必须同时检查类型和关于值的前置条件。

检查理解

函数原型的形参名必须与定义中的名称相同吗？

查看答案与理由

不必。

重要的是对应类型、个数等是否兼容；名称并不是调用契约的类型组成部分。

C11的int f();声明表示没有形参吗？

查看答案与理由

它不提供形参信息。

无形参的函数原型应明确写成int f(void);。

仅靠类型检查就能证明add(2,3)返回5吗？

查看答案与理由

不能。

还必须确认定义中的运算及可表示范围，才能得到语义上的结果。

进一步探索

说明为什么把两个形参的名称改为x,y仍能保持结果。如果一致地替换每个形参的使用，并且不与其他名称冲突，a+b和x+y就是相同传入值的和。相反，若把函数体改为return a-b，虽然类型相同，却破坏了add求和的契约。这是函数类型与规格属于不同层次的反例。

小节 4.2

值传递与返回值

在函数内部改变形参，会同时改变调用者的变量吗？

预备知识与学习目标

预备知识

  • 变量是附着在存储值的对象上的名称。赋值把右侧的值存入左侧对象。
  • &x产生指向x的指针，*p使用p所指向的对象。解引用需要一个有效、仍在生存期内且类型适当的对象。

学习目标

  • 区分值的复制和所指对象的修改。
  • 区分return的结果与输出的作用。
  • 解释返回指针所需的生存期条件。

独立的形参对象

C的实参传递是值传递。把int传给函数时，用该值初始化形参；给形参赋值并不会给调用者的int对象赋值。下面的bump中，n和x是独立对象，n=6和return 6是不同操作。

若不使用返回值，只调用bump(x);，x保持不变。返回表达式的值传给调用表达式，调用者必须把这个值存到y中，才有相应的y值。printf产生输出副作用，并不是把调用者的x替换为函数返回值的语句。

int bump(int n) { n=n+1; return n; }

指针值同样被复制

传递指针也是值传递，但可通过复制的地址修改同一目标对象。set7中p取得&x时，需要满足前置条件：它指向一个在调用期间始终存活且可修改的int x。解引用NULL、已经结束生存期的对象地址或类型不适当的地址，都不在契约范围内。

在函数内部把p改为另一个地址，与修改*p不同。前者修改局部指针的值，后者修改目标对象。写成数组形式的形参声明也会调整为指针类型，因此不要猜测整个数组和长度都会自动复制。

void set7(int *p) { *p=7; }

返回值与仍然存活的目标

返回int值后，即使局部名称的可用范围结束，调用者仍可使用该值。但是，返回局部自动对象的地址并不会延长那个对象的生存期。访问生存期已经结束的目标不存在固定输出。

结构体按值传递时，也不会深复制指针字段所指向的目标。此外，非void函数必须在所有正常返回路径上提供会被使用的结果。本单元不把main到达末尾的特殊规则扩大到一般函数。

逐步推导的例题

从x=5开始，执行y=bump(x)，再执行set7(&x)，追踪之后的x,y。

  1. 进入bump时，把x的值5复制到局部n。
  2. n变为6，但调用者的x仍是5。
  3. 接收return 6的值并存储y=6。
  4. set7的p接收&x这个值并执行*p=7，因此x=7。

预期状态为x=7,y=6。没有测量地址数值或实际运行结果。

用纸笔和正文动手试一试

画出调用者的x=3，假设把&x传给虚构函数void change(int *p)。函数的局部形参p最初指向x。比较在函数内部只执行int z=9; p=&z;与只执行*p=9;时x的值。两个情况分别从初始状态开始。

查看提示

把局部指针的方框与目标x的方框分开。

查看解答

只执行p=&z时x=3；只执行*p=9时x=9。第一种情况下，函数结束后不能返回并使用指向z的指针。

常见误解与反例

因为传入地址，C就是引用传递语言。

只是被复制的值恰好是地址。重新给局部p本身赋值并不会改变调用者的指针对象。要改变那个指针对象，需要合适的指向指针的指针契约等条件。

检查理解

丢弃bump(x)的返回值，x会增加吗？

查看答案与理由

不会。

n的修改发生在独立的形参对象上。

set7(NULL)安全吗？

查看答案与理由

不安全。

代码没有避免解引用NULL的检查，也不满足有效int目标的前置条件。

返回局部int的地址会延长生存期吗？

查看答案与理由

不会。

返回地址值与目标对象的生存期是不同条件。

进一步探索

设计交换函数void swap(int *a,int *b)：int t=*a; *a=*b; *b=t;。若两个指针在整个调用期间都指向存活且可修改的int，在目标不同的情况下，旧值A,B变为B,A。若它们指向同一目标，t保存那个值，两次赋值后仍为原值，所以同样满足交换关系。NULL或生存期已经结束的目标不满足这个证明的前提。交换的是两个目标的值，而不是调用者变量的名称。

小节 4.3

局部·全局·static

连续调用函数两次，哪些内容重新开始，哪些内容会继续保留？

预备知识与学习目标

预备知识

  • 块是{ }之间的区域，内部声明可能遮蔽外层同名声明。
  • 若函数调用写在不同语句中，就先完成前一次调用，再进入下一次。static必须结合它出现的位置解释。

学习目标

  • 区分局部名称与文件作用域名称。
  • 追踪块内static对象的状态保持。
  • 解释可重入性及并发调用的限制。

局部一词描述的是作用域

通常所说的全局变量，是文件作用域的对象名称，能从声明之后使用到翻译单元末尾。函数内部普通局部变量的名称在对应块内使用。内层x遮蔽外层x，并不意味着删除外层对象，也不意味着复制并覆盖其值。

不能仅凭“局部”判断生存期。块内static变量也具有局部名称，但对象不会在每次调用时重新开始。作用域是源代码中可以使用名称的区域，生存期是执行中对象存在的时间段。

两种计数器

下面的next持续使用同一个块内static n=0对象。前两次调用返回1,2。fresh的自动对象n在每次调用的初始化时存入0，所以两次调用都返回1。假设限制调用次数，int的增加不会超出可表示范围。

C11中具有静态存储期的对象在程序开始前初始化一次。不要把这个块内static的初始化解释成C++的首次进入时动态初始化或Java的类初始化。static初始值表达式受到C的单独约束，这里的常量0满足这些约束。

int next(void) { static int n=0; ++n; return n; }
int fresh(void) { int n=0; ++n; return n; }

隐藏共享状态的代价

next即使无实参调用，结果也会随过去的调用而改变。顺序调用时很方便，但若要独立开始测试，就需要状态初始化策略。本单元的计数器并不是并发线程的安全计数器。static关键字不提供递增的原子性或同步。

把依赖全局状态的函数改为以实参和结果为中心的函数，能显露依赖关系。但若输入指针指向共享且可修改的对象，仅使用局部名称的函数也会产生共享副作用。不要只看到局部变量的表面，就判断函数是纯函数或可重入函数。

逐步推导的例题

从初始状态开始，用不同语句执行a=next(); b=next(); c=fresh(); d=fresh();。

  1. 静态n的初始值为0，第一次next将它增加到1，因此a=1。
  2. 第二次next读取同一对象的1并改为2，因此b=2。
  3. 第一次fresh的自动对象n初始化为0，得到c=1。
  4. 第二次fresh的新调用也从n=0的初始化开始，因此d=1。

预期a,b,c,d为1,2,1,1。不把多个函数调用放入printf的实参中再猜测它们的求值顺序。

用纸笔和正文动手试一试

追踪int x=4; { int x=8; x=9; }中的外层x。再写出使用static n而非fresh局部自动n的函数第三次顺序调用的返回值。

查看提示

标出同样拼写的名称是否指向不同对象。

查看解答

只有块内x变为9，外层x仍为4。next第三次返回3。内层作用域结束不是把外层值恢复的赋值操作。

常见误解与反例

static变量就是可以从其他文件访问的全局变量。

块内static名称具有块作用域且没有链接属性；文件作用域的static名称具有内部链接属性。必须区分二者都具有静态存储期这一共同点，以及名称访问规则的差异。

检查理解

块内static对象会在函数结束时消失吗？

查看答案与理由

不会。

本例对象的静态存储期覆盖整个程序执行。

给内层x赋值会改变外层x吗？

查看答案与理由

本例中不会。

名称遮蔽使它们指定不同对象。

static ++n在并发调用下也安全吗？

查看答案与理由

不保证。

static不指定同步或原子操作。

进一步探索

把状态不变式设为顺序调用k次后n=k。初始k=0时，初始化n=0使不变式成立。若k<INT_MAX且没有其他修改，下一次++n有定义，并使n=k+1，因此归纳步骤成立。达到k=INT_MAX之后的调用不属于这个证明。数学中无限的自然数计数器不能无条件移植到有限int程序，原因就在这里。

小节 4.4

存储期与链接属性

不能再使用一个名称，与那个对象已经消失，是同一回事吗？

预备知识与学习目标

预备知识

  • 翻译单元是一个源文件经过预处理后的内容。可以链接多个翻译单元来构成程序。
  • 分别画出名称、对象和声明。同一对象的两个声明，以及同样拼写名称对应的不同对象，都可能存在。

学习目标

  • 用作用域、存储期、链接属性三个维度分类。
  • 解释外部声明与定义的关系。
  • 区分已分配对象和自动对象的生存期风险。

把三个问题分开问

scope（作用域）问的是在这个位置能否使用名称；storage duration（存储期）问的是在执行的哪个时间段保证对象的存储空间；linkage（链接属性）问的是其他声明是否指向同一对象或函数。没有链接属性的局部对象也有生存期，具有内部链接属性的对象也可通过多个声明指定同一目标。

C11的对象存储期分为static、thread、automatic、allocated四类。函数不是对象，因此不能给文件作用域的static函数附上对象存储期。stack/heap这种实现布局的比喻也不能代替这四种语言层面的分类。

完成声明分类表

下面的g是文件作用域、外部链接属性、静态存储期的对象。hidden具有文件作用域、内部链接属性、静态存储期。f的local具有块作用域、无链接属性、自动存储期，memo具有块作用域、无链接属性、静态存储期。函数f自身具有外部链接属性，但对象存储期一栏不适用。

extern int g;在这个情况下声明的是与前面的g相同的目标，不会用新值初始化它。说extern总会产生外部链接属性是错误的。它可能继承前面可见的static声明的链接属性，因此必须确认声明顺序和可见性。

int g=2;
static int hidden=3;
extern int g;
void f(void) { int local=4; static int memo=5; (void)local; (void)memo; }

对象结束与所有权契约

通过malloc成功取得的已分配存储空间，不会仅因为指向它的局部指针变量作用域结束而自动释放。反过来，一旦通过free释放，即使指针变量名还在，也没有访问目标的权利。分配失败检查、大小计算范围、正确的释放目标和所有权，将在后续内存单元中一起讨论。

即使把自动对象的地址保存到外层，块结束仍会结束那个对象的生存期。之后的访问是未定义行为；N1570还规定，生存期结束时有关指针的值也变为indeterminate（不确定值）。不能用地址数值碰巧相同或数据看似留在屏幕上的现象来证明有效性。

逐步推导的例题

按三个维度分类示例中的g,hidden,local,memo,f，并判断调用f两次时memo对象的数量。

  1. g：文件作用域、外部链接属性、静态存储期。extern声明指定同一个g。
  2. hidden：文件作用域、内部链接属性、静态存储期。
  3. local：块作用域、无链接属性、自动存储期，每次调用都有对应对象。memo：块作用域、无链接属性、静态存储期。
  4. f：文件作用域、具有外部链接属性的函数，不属于对象存储期的分类对象。顺序调用两次使用的是同一个memo对象。

这种分类是对C11声明和生存期规则的纸上判断，没有测量实际链接器符号或内存布局。

用纸笔和正文动手试一试

文件作用域的static int x=1;之后有extern int x;。写出x的链接属性和存储期，与函数内部的static int y=2;比较。

查看提示

读extern之前，先查找前面可见的声明。

查看解答

后面的extern x也继承前面static x的内部链接属性，该对象具有静态存储期。y具有块作用域、无链接属性、静态存储期。即使同样具有静态存储期，名称的链接属性也不同。

常见误解与反例

局部指针变量仍然存活，所以它的目标也仍然存活。

指针对象与目标的生存期不同。若目标已被free释放，或自动对象的块已结束，即使指针名称还在，也不能据此正当化访问目标。

检查理解

给函数附上automatic存储期吗？

查看答案与理由

不附。

这里的存储期分类针对对象。

文件作用域的static x之后可见的extern x一定具有外部链接属性吗？

查看答案与理由

不一定。

应适用继承前面内部链接属性声明的规则。

malloc的目标会仅因局部指针作用域结束而释放吗？

查看答案与理由

不会。

已分配存储空间的生存期与指针变量的自动存储期不同。

进一步探索

考虑一种设计：在模块内部放置static int total=0;，只向外提供读取函数和检查范围后才修改的函数。外部不能直接声明名称total来指定同一内部对象，因此可以减少意外的直接名称访问。但若返回地址，外部代码就可能修改该对象；若函数未经检查就发生溢出，链接属性也无法阻止。内部链接属性不是证明所有内存安全性或信息安全性的机制，还必须单独证明所提供接口的契约。
