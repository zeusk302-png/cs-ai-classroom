小节 5.1

数组的大小与下标

为什么五个元素的数组，最后一个下标是 4 而不是 5？

预备知识与学习目标

预备知识

  • 数组将同一元素类型的对象连续存放在一起。int a[5] 中的 a 是包含五个 int 的数组，a[0] 是第一个元素。元素个数和最后一个下标是不同的数。
  • size_t 是用于 sizeof 结果的无符号整数类型。sizeof 用 C 字节表示大小；这里不假定一个字节一定是 8 位，也不假定 int 一定占 4 字节。
  • 准备自测：写出 a[0],a[1],a[2] 三个位置的下标。最大下标是 2，元素个数是 3。分清这两个数，就能开始阅读正文中的示意图。

学习目标

  • 计算数组对象的大小和有效下标。
  • 区分部分初始化与未初始化的自动数组。
  • 说明 sizeof 对数组对象和指针形参的区别，以及 VLA 的条件。

对象大小与有效编号

本单元以公开的 C11 草案 N1570 为依据。int a[5] 的元素个数是 5，从首元素出发可访问的下标满足 0≤i<5。并不存在第六个元素 a[5]。由于元素类型相同，数组总大小等于元素个数乘以单个元素的大小。

在能看到实际数组对象 a 的位置，可以用 sizeof a / sizeof a[0] 求元素个数。分子和分母使用相同的 C 字节单位，因此比值是 5，无须假定 sizeof(int) 的具体值。该声明确定了这个数组对象，多放入元素不会使它自动变大。

初始化提供的值

int a[5]={4,7}; 将前两个元素初始化为 4,7，其余 int 元素初始化为 0。如果省略大小并提供初始值，如 int a[]={4,7};，这个例子中的元素个数就确定为 2。仅在函数内声明具有自动存储期的 int a[5];，不能声称每个元素都会自动变成 0。读取之前必须为各元素存入有效值。

这个固定大小示例中，sizeof 的操作数不被求值，所以 sizeof a[0] 不会读取首元素的值。一般的 C11 VLA 可能在运行时计算大小，因此不能概括为 sizeof 从不涉及运行时求值。VLA 在 C11 中是有条件支持的功能；运行时被求值的长度必须为正，同一数组实例的大小在其生存期内不变。VLA 也不会自动保证大输入所需的存储空间或失败处理。

跨越函数边界时保留长度契约

void f(int a[5]) 中的 a 按函数形参规则调整为 int *。函数内的 sizeof a 是指针类型的大小，不是调用者五元素数组的大小。不能用这个比值恢复调用者的长度。通常应传入指针和单独的 size_t n，并明确要求提供 n 个仍在生存期内的元素。

声明里出现方括号，并不意味着自动进行边界检查。例如形参 int a[static 5] 表达了调用者必须提供至少五个可访问元素的契约，但不会自行检查或扩大较小的数组。下面是一个不依赖形参调整或 VLA 的完整固定数组程序。

#include <stdio.h>
#include <stddef.h>
int main(void) {
    int a[5] = {4, 7};
    size_t n = sizeof a / sizeof a[0];
    a[n - 1] = 9;
    printf("%zu %d %d %d\n", n, a[0], a[2], a[4]);
    return 0;
}

逐步推导的例题

代码从 int a[5]={4,7} 计算 n，然后把最后一个元素改为 9。%zu 显示 size_t。只推求正常输出成功这一假设下的预测值。

  1. 声明后五个元素的值是 [4,7,0,0,0]。部分初始化规则使其余三个 int 为 0。
  2. sizeof a=5*sizeof(int)，sizeof a[0]=sizeof(int)，所以 n=5。不假定具体字节数。
  3. n 为 5，因此 n−1=4；a[4]=9 写入有效的最后一个元素。数组变成 [4,7,0,0,9]。
  4. 输出实参为 n=5,a[0]=4,a[2]=0,a[4]=9。%zu 和三个 %d 分别与相应实参类型一致。

预测 stdout 为 5 4 0 9，后接换行。没有实际编译或运行。

用纸笔和正文动手试一试

画出 int b[4]={8}; 的四个元素。写出元素个数、最大下标和值，计算 sizeof b/sizeof b[0]。判断在 void g(int b[4]) 内，同一个表达式是否也表示长度。

查看提示

把实际数组对象 b 和已调整为指针的形参 b 分别列在两张表中。

查看解答

调用者的数组值为 [8,0,0,0]，元素个数 4，最大下标 3，数组对象的大小比值为 4。g 的形参是 int *，函数内比值为 sizeof(int *)/sizeof(int)，不能据此确定数组长度。即使某实现的值碰巧为 4，也不能成为普遍的长度恢复规则。

常见误解与反例

有 a[5] 这样的声明，所以 a[5] 也在数组内。

声明里的 5 是元素个数，访问式里的 5 是从 0 开始数的第六个位置。有效的最后位置是 4。读取未初始化的自动数组也是一个独立于边界的问题。

检查理解

int a[5]={4,7}; 中 a[3] 的初始值是什么？

查看答案与理由

0

这个 int 数组中省略初始值的其余元素被初始化为 0。

在 int a[5] 形参内部，sizeof a 是原数组整体大小吗？

查看答案与理由

不是，而是调整后指针类型的大小。

函数的数组形参会调整为指针类型，所以长度必须通过单独契约传递。

可以假定 C11 VLA 允许声明时的运行时长度为 0 吗？

查看答案与理由

不可以。相应大小表达式被求值时必须为正。

VLA 是 C11 的有条件功能；需要确认支持情况、正大小和存储资源条件。

进一步探索

拓展：设完整数组对象 a 的元素个数为 N，单个元素类型大小为 S>0，则总大小为 NS，故 sizeof a/sizeof a[0]=NS/S=N。证明只适用于操作数仍保持数组类型的位置。对于调整成指针类型的形参，或本来就是指针的变量，分子为 NS 的前提不存在，因此证明不成立。应区分 N>0 的固定数组声明与逻辑上为空、n=0 的数据。后者可用单独长度契约表示，而非声明大小为 0 的数组对象。

小节 5.2

遍历、查找与排序基础

同样遍历数组，查找函数与改变顺序的函数在契约上有什么区别？

预备知识与学习目标

预备知识

  • for 循环先执行一次初始化，随后反复检查继续条件，在条件为真时执行循环体，再执行递增。检查 i<n 后再读取 a[i]，就能在该访问时使用 i<n 这一依据。
  • 线性查找从左向右逐个检查。排序将值排列成非递减顺序；同一值出现多次时，也必须保留它的出现次数。
  • 准备自测：[4,1,4,2] 中第一个 4 位于 0。排序后 [1,2,4,4] 的第一个 4 位于 2，因此必须说明查找结果来自哪个数组状态。

学习目标

  • 解释返回首个位置或 n 的查找结果契约。
  • 论证查找与选择排序的循环不变式和终止。
  • 区分元素比较次数与实际时间，并检查有符号求和的可表示范围。

只读遍历与首位置查找

first(a,n,key) 的前置条件是：n>0 时，a 指向一个在整个调用期间都仍在生存期内的数组的首元素，并提供至少 n 个已初始化、可读取的 int。n=0 时函数不使用 a，因此契约也允许传入 NULL。结果为第一个等于 key 的元素位置，或用 n 表示未找到。标记 n 不会与有效位置重合。

循环体读取 a[i] 时满足 0≤i<n。取不变式为：每轮开始时，前段 [0,i) 中没有 key。起初这个区间为空，所以成立。当前元素等于 key 时，前方没有同值，故它是首位置；不等于时，可把已检查区间扩大一格。i 增加到 n，所以有限输入上会终止；最后返回 n 表示整个区间中都没有 key。

选择排序具有单独的修改契约

selection 要求 n 个仍在生存期内、已初始化且可修改的 int 元素。在外层位置 i，寻找后缀 [i,n) 中最小值的位置 m，然后交换 a[i] 与 a[m]。比较使用 a[j]<a[m]，而非相减：即使两个操作数都是有效的 int，a[j]-a[m] 也可能发生有符号溢出。

取不变式为：已完成的前段非递减，且其中每个值都不大于剩余区间的任何值。将后缀最小值移到下一格，可把此前段扩展一格。交换不会丢失值，因此也保留元素的多重集。给相同值加上标签后，这种非相邻交换可能改变原顺序，所以不声称该实现是稳定排序。

精确比较次数与算术条件

该实现的元素间 < 比较次数依次为 n−1,n−2,…,1,0，总和是 n(n−1)/2。n=0 或 1 时为 0 次；这里用数学整数计算次数。在 C 的 size_t 中直接计算 n*(n-1)，可能在 n=0 的减法或大值的乘法中发生回绕。这与符号表示的次数是不同的问题。次数不包含循环条件比较、交换和输出成本。

在元素比较具有固定成本的模型中，选择排序对于大的 n 有 Θ(n²) 比较次数，输入已经有序时也一样。这不是实际运行时间或缓存性能测量。如果再添加遍历求和函数，则每个累积中间和都必须可用 int 表示。仅凭最终和较小，不能断言已经避免有符号溢出。

#include <stdio.h>
#include <stddef.h>
size_t first(const int *a, size_t n, int key) {
    for (size_t i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return n;
}
void selection(int *a, size_t n) {
    for (size_t i = 0; i < n; ++i) {
        size_t m = i;
        for (size_t j = i + 1; j < n; ++j)
            if (a[j] < a[m]) m = j;
        if (m != i) { int tmp = a[i]; a[i] = a[m]; a[m] = tmp; }
    }
}
int main(void) {
    int a[] = {4, 1, 4, 2};
    size_t n = sizeof a / sizeof a[0];
    size_t found = first(a, n, 4);
    selection(a, n);
    printf("%zu %d %d %d %d\n", found, a[0], a[1], a[2], a[3]);
    return 0;
}

逐步推导的例题

在 a=[4,1,4,2] 中找到 key=4 的首位置，再用 selection 排序同一个数组。first 只读取，selection 原地修改数组。

  1. first 在 i=0 时发现 a[0]=4 等于 key，返回 0。found=0 是对排序前数组的位置记录。
  2. i=0 时后缀最小值为位置1的 1。交换后得到 [1,4,4,2]，元素比较为 3 次。
  3. i=1 时最小值是位置3的 2，得到 [1,2,4,4]。此阶段比较 2 次，i=2 比较 1 次，i=3 比较 0 次。
  4. 总比较次数为 3+2+1+0=6，最终数组是 [1,2,4,4]。已保存的 found=0 不会自动更新成排序后第一个 4 的位置2。

预测 stdout 为 0 1 2 4 4，后接换行。没有运行 C 程序或测量时间。

用纸笔和正文动手试一试

在纸上写出 [3,1,3] 对 key=3 和 key=9 的 first 结果。求选择排序各阶段后的值和总元素比较次数。再检查 [2a,2b,1] 中只比较数值时，标签顺序是否保留。

查看提示

未找到的标记是长度3。标签 a,b 表示两个值为2的元素原本的顺序。

查看解答

第一个 3 位于0，不存在的 9 返回标记3。排序第一阶段得到 [1,3,3]，之后不需要值交换，比较次数是 2+1+0=3。[2a,2b,1] 的首次交换得到 [1,2b,2a]，破坏稳定性。该实现会在 m=i 时跳过交换。

常见误解与反例

输入已有序时选择排序几乎不比较，而且原查找位置可以直接沿用。

该实现不论输入是否有序，都比较整个后缀，总计 n(n−1)/2 次。元素移动后，排序前的位置可能不再保持同一含义。区分时间测量与比较次数，也区分值存在与值的位置。

检查理解

first(NULL,0,4) 的返回契约是什么？

查看答案与理由

0，也就是 n。

此函数在空输入时跳过循环，不访问元素，也不对 NULL 做指针算术。

长度4时，该选择排序执行几次元素比较？

查看答案与理由

6 次

后缀检查次数为 3+2+1+0，不包括循环条件比较。

仅满足非递减顺序，就足以保证排序正确吗？

查看答案与理由

不够，还必须保留原值的多重集。

把所有输入元素覆盖为 0，也可能得到非递减顺序，却不是原值的排序结果。

进一步探索

拓展：线性查找的终止度量为 n−i，每次未匹配的比较后恰好减少 1。选择排序通过有限的外层/内层循环、前段不变式和交换保留多重集，得到完全正确性。最后一轮 i=n−1 时，i+1=n 仍可用 size_t 表示；只有内层 j<n 时才访问元素。在整数计数模型中，n≥2 时 n(n−1)/2≥n²/4，而所有非负 n 都满足 n(n−1)/2≤n²/2，从而得到 Θ(n²) 的双边界。这不是概率平均，也不是在实际计算机上的测量。

小节 5.3

多维数组

把 2 行 3 列的表传给函数时，为什么列数必须保留在指针类型中？

预备知识与学习目标

预备知识

  • a[2][3] 使用六个 int，但类型是由两个行数组组成的数组，每行包含三个 int。第一下标是行，第二下标是列。
  • 指针 p+1 并非一律移动 1 字节，而是移动一个所指类型对象的大小。int * 和 int (*)[3] 是不同的类型。
  • 准备自测：2 行 3 列的有效坐标由 r=0,1 与 c=0,1,2 组合而成。(1,2) 是最后一格，(0,3) 不是有效坐标。

学习目标

  • 解释行数组组成的数组和行优先存储布局。
  • 区分多维形参调整与指针类型。
  • 同时检查坐标范围和求和的算术条件。

以行为元素的数组

int a[2][3]={{1,2,3},{4,5,6}}; 完整初始化一个外层元素数为2、每行元素数为3的数组。C 数组采用最后一个下标变化最快的行优先顺序，因此存储顺序可描述为 1,2,3,4,5,6。对于坐标 (r,c)，分别检查 0≤r<2 和 0≤c<3。

行和列是数学示意，不是对实际地址数值的测量。总字节大小为 2*3*sizeof(int)，一行为 3*sizeof(int)。抽象存储位置可用 3r+c 编号，但这张图并不允许跨行边界的 int 指针算术或 a[0][3] 访问。

指针保留行宽

表达式 a 通常转换为指向首行的 int (*)[3]。int (*p)[3]=a 中，p+1 指向下一行。a[r] 是一个行数组，在访问行内元素时转换为 int *。指针类型层次不同，所以不能把这个实参改成 int ** 来调用函数。

函数形参 int a[][3] 调整为 int (*a)[3]。外层行数必须通过单独长度契约提供，但内层 3 留在以行为单位移动的类型中。C11 中使用一般的可变列数，需要另行确认 VLA 支持、维度为正等条件。本单元使用列数3的固定类型，不需要安装工具或支持 VLA。

下标与累积值的契约

row_sum 要求传入的 a 实际指向含有所需行的数组，row 小于实际行数，且该行三个 int 已初始化。函数名称或 a[][3] 本身不会自动检查实际行数。const 或类型匹配也不自动保证对象仍在生存期内。

每次加法的中间 total 都必须在 int 范围内，这是另一个算术条件。示例第二行累积为 4→9→15，对所有 C11 int 都是安全的小值。在调用者对象上，sizeof a/sizeof a[0] 得到行数2，sizeof a[0]/sizeof a[0][0] 得到列数3。不能把用于调整后函数形参 a 的第一个比值解释为整体行数。

#include <stdio.h>
#include <stddef.h>
int row_sum(int a[][3], size_t row) {
    int total = 0;
    for (size_t c = 0; c < 3; ++c) total += a[row][c];
    return total;
}
int main(void) {
    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*p)[3] = a;
    printf("%zu %zu %d %d\n", sizeof a / sizeof a[0],
           sizeof a[0] / sizeof a[0][0], p[1][1], row_sum(a, 1));
    return 0;
}

逐步推导的例题

对于 2 行 3 列 a 和行指针 p，求行数、列数、p[1][1] 和 row_sum(a,1) 的预测值。所有中间和都可用 int 表示。

  1. 初始表的首行为 [1,2,3]，第二行为 [4,5,6]。外层元素是行数组，每行三个 int。
  2. 调用者的 sizeof 比值得到行数2、列数3，无须指定 sizeof(int) 的实际值。
  3. p 指向首行。p[1] 是第二行，p[1][1] 是该行第二个元素5。两个下标都有效。
  4. row_sum(a,1) 在 c=0,1,2 时使 total 依次为 4,9,15。c=3 时循环条件为假，不访问元素。

预测 stdout 为 2 3 5 15，后接换行。没有测量实际地址或运行 C 程序。

用纸笔和正文动手试一试

画出 int b[2][2]={{2,4},{6,8}};。写出外层元素类型、通常转换得到的指针类型、b[1][0] 和第二行之和。能否因为它看起来是下一行首格，就读取 b[0][2]？

查看提示

外层数组的元素是含两个 int 的行数组。整体连续存储和每行的下标边界是不同条件。

查看解答

外层元素类型为 int[2]，转换后的指针类型为 int (*)[2]。b[1][0]=6，第二行之和为 6+8=14。b[0][2] 会解引用首行的尾后指针，不能读取。下一行首格必须通过 b[1][0] 访问。

常见误解与反例

多维数组是 int **，只要所有格子连续，就能用任意下标跨过去。

int a[2][3] 是行数组组成的数组，与 int ** 的类型和移动单位不同。a[0][3] 超出首行的访问边界，不能用整体内存连续来证明其合法性。区分坐标图中的线性编号和合法指针访问。

检查理解

int a[2][3] 在普通表达式中通常转换成什么指针类型？

查看答案与理由

int (*)[3]

外层数组的首元素是包含三个 int 的行数组。

int a[][3] 的形参声明会自动记住行数2吗？

查看答案与理由

不会，需要单独的行数契约。

外层数组形参调整为行指针，而列数3保留在行类型中。

用 a[0][3] 代替 a[1][0] 读取是否安全？

查看答案与理由

不安全。

首行的有效列为0,1,2，列3是该行尾后位置。连续布局不允许行外解引用。

进一步探索

拓展：对于 R 行 C 列的固定数组，前 r 行包含 rC 个元素，当前行前方有 c 个元素，所以存储位置编号为 rC+c。R,C>0 且坐标有效时，编号范围为 0 到 RC−1。反过来，对于每个这样的编号 k，r=k/C,c=k%C 给出唯一有效坐标。这个一一对应证明讨论的是图中的编号。C 程序还需要额外契约来检查乘积 RC 是否超出整数类型范围、整个对象是否存在，以及是否遵守逐行指针访问。不能自动混淆另行声明的平坦 int 数组设计和多维数组首行的指针。

小节 5.4

越界访问错误

读到数组外面，某次运行却看起来没问题，能据此认定安全吗？

预备知识与学习目标

预备知识

  • 有效访问不仅要求下标正确，还要求存在合适且仍在生存期内的目标对象，以及已初始化的值。声明的数组大小与调用者声称的长度并不会自动被证明相等。
  • 尾后位置（one-past）标记最后一个元素紧接着的后方位置。把它作为结束边界，和读取或写入该位置的值，是不同的操作。
  • 准备自测：int a[3] 的元素是 a[0],a[1],a[2]。a+3 是结束边界标记，并不存在可读的 a[3] 元素。

学习目标

  • 区分形成指针和解引用的范围条件。
  • 解释长度检查函数的前置条件和失败契约。
  • 区分有符号错误、无符号回绕、实际观察的失败与 UB。

结束边界指针与实际元素

对于指向长度3数组首元素的 a，可以形成作为尾后指针的 a+3。但不能将该指针作为被求值的 * 操作数来读取或写入元素。下标访问 a[3] 就是 *(a+3)，因此有相同问题。a+4 既不在数组内，也不是尾后位置，所以形成它的指针算术本身就超出契约。

&a[3] 这样仅形成地址的表达式，在 C11 的 & 与下标结合规则下等同于 a+3，可以形成有效的结束标记。不能把此例外改成允许读取 a[3] 的值。还必须说明允许位置是以哪个实际数组对象为依据。多维数组整体存储相邻，也不能证明跨越单个行边界的下标访问合法。

先检查条件，再访问

read_at 接收 size_t i，i>=n 时返回 0，不改变 out；i<n 时把 a[i] 复制给 out 并返回 1。可能成功的调用要求 a 提供至少 n 个仍在生存期内、已初始化的 int 元素，且 out 指向仍在生存期内、可修改的 int。n=0 时总是失败，不使用 a 和 out，因此也允许 NULL。

函数不能核实 n 是否是真实长度。给长度3数组传入 n=100,i=4，即使通过比较，也没有对应目标元素。检查本身依赖于访问之前可信的长度契约。负整数转换为 size_t 可能变成大值，超出范围的正数也可能在转换中回绕。因此外部输入必须先检查符号和可表示性，再传给该接口。

同时检查不变式与算术错误

for(size_t i=0;i<n;++i) 这样的形式，先确认 i<n 再访问，是正确的起点。相反，i<=n 会在结束边界 n 多访问一次。n=0 时，将 size_t last = n - 1; 的结果存入 last，会得到 size_t 的最大值。在 size_t 较窄、会提升为 int 的实现上，表达式本身可能先得到 int 的 −1，但存入 size_t 后也转换为同一个最大值。因此求最后位置之前，必须先知道 n>0。无符号回绕在 C 中是已定义的算术，但不会使错误长度或下标的含义变得正确。

有符号 int 表达式 INT_MAX+1 是未定义行为。它与越界访问是不同的 UB 来源，两者都没有固定错误信息或一定立即终止的规则。某次输出碰巧正常，不能证明安全。下面的代码只展示失败时保留原 out 的正常路径，没有将越界解引用作为测试运行。

#include <stdio.h>
#include <stddef.h>
int read_at(const int *a, size_t n, size_t i, int *out) {
    if (i >= n) return 0;
    *out = a[i];
    return 1;
}
int main(void) {
    int a[3] = {6, 7, 8};
    int out = 99;
    int ok = read_at(a, 3, 3, &out);
    printf("%d %d\n", ok, out);
    ok = read_at(a, 3, 2, &out);
    printf("%d %d\n", ok, out);
    return 0;
}

逐步推导的例题

对于长度3的 a=[6,7,8]、out=99，先以 i=3 再以 i=2 调用 read_at。n 是实际元素个数，成功路径的 a,out 都有效。

  1. 第一次调用 i=3,n=3，因此 i>=n 为真。在求值 a[3] 或 *out 之前返回 0。
  2. ok=0，out 保持99，所以首行预测输出是 0 99。失败返回是正常契约结果，不是执行 UB 的结果。
  3. 第二次调用满足 i=2<n，读取 a[2]=8 并复制到有效的 out 对象，返回 1。
  4. ok=1,out=8，所以第二行预测输出是 1 8。两次调用均没有读取数组外的值。

预测 stdout 为 0 99 后接换行，再接 1 8 和换行。没有实际运行 C 程序。

用纸笔和正文动手试一试

对于 int b[4]={1,2,3,4};，分别判断形成 b+4、读取 *(b+4)、形成 b+5、形成 &b[4]。再说明 read_at(b,4,4,&v) 为什么保留原来的 v=20。

查看提示

区分形成允许的结束标记与被求值的解引用。如果在检查之前已发生错误访问，之后的检查不能修复。

查看解答

b+4 和 &b[4] 是允许的尾后指针形成。读取 *(b+4) 和形成 b+5 是 UB。read_at 的 4>=4 检查在访问之前使其失败，因此返回0，v=20。不为两个 UB 表达式给出特定输出或错误。

常见误解与反例

越界时 C 会抛出可捕获的异常，所以可以先读、之后再检查。

C11 的普通数组访问没有自动异常或边界检查契约。越界访问是 UB，不保证特定输出或终止。读取之前要根据实际长度检查条件；之后的 if 不能取消已经发生的 UB。

检查理解

长度3数组的 a+3 指针形成与 *(a+3) 读取具有相同安全性吗？

查看答案与理由

不同。前者允许形成尾后指针，后者不能读取。

结束标记指针不指向实际存在的元素。

给 read_at 的 n 大于实际长度时，仅靠 i<n 检查是否安全？

查看答案与理由

不安全。

前置条件要求检查所用的 n 本身对应实际可访问的元素数。

size_t n=0 时，可以把 n−1 用作最后一个元素的位置吗？

查看答案与理由

不可以。

结果存入 size_t 后为其最大值。不论表达式是否发生整数提升，空数据都没有最后一个元素。

进一步探索

拓展：在 read_at 的失败路径 i≥n 下，不访问元素或 out，因此可以论证 out 保持不变。在成功路径中，把 i<n 与实际 n 个元素的契约结合，可得到 a[i] 有效；有效 out 的契约则使写入合法。返回1时，后置条件为 out 的值等于调用时 a[i] 的值。该论证要求生存期、初始化、目标可修改、没有并发修改等前提，不是自动内存权限检查。不要混淆允许 n=0 失败的契约与大小为0的 C 数组声明。
