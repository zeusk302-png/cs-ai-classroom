소단원 8.1

출력 매개변수

반환값 하나는 성공 여부에 쓰고 계산 결과는 어디로 돌려줄까?

준비 개념과 학습 목표

준비 개념

  • 주소 &

  • 역참조 *

  • 함수와 조건문

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • 복사된 포인터로 호출자 객체를 수정한다.

  • 실패 시 출력 계약을 명시한다.

최솟값과 최댓값을 같은 상자에 넣으면 두 결과가 남을까?

새 API minmax는 살아 있는 입력 [6,2,9]의 최솟값과 최댓값을 각각 호출자 int 객체에 저장하고 성공 1을 반환한다고 설계한다. 두 출력은 초기값 40과 50이다. 입력을 모두 읽어 지역 값 lo=2, hi=9를 만든 뒤 두 출력에 쓴다. 반환 상태 1은 결과값 2나 9와 다른 통로다. 여기서 주소 인수는 값 전달이지만 그 주소를 따라간 쓰기는 호출자 객체에 도달한다.

입력과 길이는 유효하다고 전제한다. 두 출력은 살아 있는 수정 가능한 int 객체여야 하며 NULL이 아니고 서로 달라야 한다. 같은 출력 객체를 받으면 두 다른 결과를 동시에 보존할 수 없으므로 쓰기 전에 실패 0으로 반환하고 기존 값을 보존한다. 입력 원소와 출력의 별칭은 이 설계에서 허용하되 모든 입력을 읽고 지역 결과를 완성한 뒤 쓰는 순서를 요구한다. 실제 C 구현이나 실행을 한 것은 아니다.

먼저 확인할 개념
  • 포인터 값과 쓰기의 대상

    주소 복사와 호출자 객체 변경을 두 사건으로 나눈다.

  • 별칭과 값 복사

    지역 계산 결과가 입력의 후속 쓰기와 분리되는 이유를 설명한다.

주소를 받는 결과 통로

C 함수는 인자값을 매개변수에 전달한다. int *out 에 &result 를 넘기면 포인터 값은 복사되지만 복사된 주소가 같은 result 객체를 가리킨다. *out=값은 그 객체에 쓰므로 호출자가 새 결과를 볼 수 있다. out 자체를 다른 주소로 바꾸는 일과 *out 에 쓰는 일을 구별한다.

상태 반환과 출력 주소를 나누면 성공/실패를 구별하면서 숫자 결과를 돌려줄 수 있다. 아래 자체 계약은 반환 1=성공,0=실패이며 실패에서는 출력 객체를 바꾸지 않는다. 이 값 선택은 C 언어의 모든 함수에 공통인 규칙이 아니라 이 함수의 약속이다.

유효 주소를 먼저 확인하기

out!=NULL 은 필요한 검사지만 충분하지 않다. 가리키는 int 객체가 살아 있고 올바른 정렬과 쓰기 권한을 가지며 함수 수행 중 유효해야 한다. 지역 변수의 주소를 호출 중 빌리는 것은 가능하지만 수명 끝난 객체 주소에 쓰는 것은 허용되지 않는다.

입력값도 계산 전에 검증한다. 자체 divide 는 a>=0,b>0, 유효 out 을 요구하고 위반이면 실패한다. 이 제한 아래 a/b 는정수 몫이며나눗셈 0 과음수/INT_MIN 관련 조건을 피한다. 검사 전에*out 을쓰면실패 시불변 계약을 어길 수 있다.

언제 결과를 확정하는가

모든 검사가 끝나고 임시 계산 결과를 만들고 마지막에*out 에쓴다. 작업 도중 결과를 여러 번 바꾸다가 실패하면 어느 값이 남는지 호출자가 알기 어렵다. 출력 두 개가 별칭이면 한 출력 쓰기가 다른 출력도 바꿀 수 있으므로 별칭 허용 여부도 설계한다.

예제는 입력 두 개를 값으로 먼저 받고출력 하나만 사용하므로 입력 원본과 out 이 같은 int 여도본문의 입력값 복사는 보존된다. 반대로 포인터 입력을 읽으면서 출력을 계속 바꾸는 함수는 같은 별칭 조건을 자동으로 만족한다고 할 수 없다.

int divide_nonneg(int a, int b, int *out) {
    if (out == NULL || a < 0 || b <= 0) return 0;
    int q = a / b;
    *out = q;
    return 1;
}

입력 원소에 결과를 저장한다

새 a=[6,2,9], hi_out=50에서 lo_out=&a[0]을 허용하는 계약이다.

  1. 전체 입력을 먼저 읽어 lo=2, hi=9를 완성한다.

  2. a[0]에 2를 쓰고 hi_out에 9를 쓴다.

  3. 다음 호출은 바뀐 입력 [2,2,9]를 보게 된다.

첫 호출은 원래 입력의 결과 2/9를 정상 저장한다.

비교할 점

입력 보존을 약속하지 않는 API이므로 결과의 정확성과 입력 변경을 따로 기록한다.

두 결과가 우연히 같은 경우

새 입력 [5,5]와 같은 출력 객체 x=40을 전달한다. 계약은 두 출력의 주소가 항상 달라야 한다.

  1. lo와 hi가 모두 5여도 주소 계약을 먼저 검사한다.

  2. 같은 출력이면 0을 반환하고 x=40을 보존한다.

값이 같아도 이번 계약에서는 거절한다.

비교할 점

일부 입력에서 작동하는 관찰로 일반 계약을 완화하지 않는다.

종이와 본문으로 직접 해보기

result=8 에서 divide_nonneg(result,3,&result)는? 이후 a=-1 호출과 NULL out 호출은? NULL 을 *out 보다 먼저 검사한 이유도 적어라.

힌트 보기

입력 result 값 8 은 함수에 값으로 전달된다. 유효 주소 조건을 유지하고 실패 경로에 쓰기가 없는지 본다.

풀이 보기

8/3=2 이므로 1/result 2 다. a=-1 은 0/result 2 불변, NULL 은 0 이며 역참조를 수행하지 않는다. NULL 도 유효 out 을 만드는 것은 아니지만 해당거부 경로에서는 dereference 하지 않는다.

오해와 반례

포인터를 인자로 넘기면 포인터 변수 자체도 호출자와 공유한다.

out 은복사본이다. out=NULL 만으로 호출자의 주소 변수는 바뀌지 않는다. *out 쓰기가같은 객체에 닿는 것과 포인터 이름을 재대입하는 것은 다르다.

힌트 2

상태 1, 결과 0/7이다.

양수만 복사하는 새 filter_positive 계약을 설계한다. 입력은 [-3,2,0,7,-1,4]이고 선택 결과는 [2,7,4]다. 출력 용량 cap은 실제 쓸 수 있는 int 칸 수다. 실패 때 출력과 used를 모두 보존하려면 첫 순회에서 필요한 칸 수 3을 세고 cap과 비교한 뒤 둘째 순회에서 복사한다. cap=2면 처음부터 실패하여 기존 출력 [80,90]과 used=99가 그대로다.

두 순회 사이 입력은 동일해야 하며 다른 접근 경로의 수정이나 동시 쓰기가 없다고 전제한다. 입력/출력은 int 원소 영역이고 결과 개수는 유효한 size_t 객체를 지정하는 size_t *used로 전달한다. 입력 영역과 출력 영역, used 객체는 서로 겹치지 않는다. n과 cap은 size_t 값이며 실제 읽을 입력/쓸 출력의 원소 수에 맞아야 한다. NULL은 길이 0 입력이나 선택 수 0 출력에 한해 API가 명시적으로 허용하고 해당 포인터의 산술과 대상 접근을 모두 생략한다. 함수가 포인터 값만으로 실제 길이를 알아내는 것은 아니다.

배열 표기라도 포인터 매개변수

함수 매개변수 int a[]는 배열 크기를 통째로 전달하는 형식이 아니라 포인터 형식으로 조정된다. 원래 배열이 4 칸인지 40 칸인지 포인터 값만으로 알 수 없으므로 별도 n 을 전달한다. sizeof(a)는 이 함수 안에서 포인터 크기이며 원 배열 바이트 크기라고 쓰면 틀린다.

배열 호출 전 실제 배열 표현식에서 sizeof 배열/sizeof 원소로 칸수를 계산하는 것과 이미 포인터인 값으로 그 식을 쓰는 것은 다르다. 다차원 배열은 행형식과 stride 조건까지 필요하며 int**가 연속 2 차원 배열을 자동 표현하지도 않는다.

읽을 수 있는 n 칸이라는 약속

const int *a,size_t n 은 읽을 입력과 길이 표기다. n>0 이면 a 는 적어도 n 개 int 를 연속으로 읽을 수있어야한다. for i=0;i<n;i++는 0..n-1 을읽는다. i<=n 이면마지막 n 은범위밖이다. 길이를 실제보다 크게 주면 루프 검사만 있어도 안전하지 않다.

우리 자체 count_positive 는 n0 이면 a=NULL 도 허용하고 루프를 전혀 돌지 않는다. 이때먼저 a+n 을만들거나*a 를읽지 않는구현이다. 모든 라이브러리가 NULL,n0 을 허용하는 것은 아니므로 각 API 계약을 읽어야 한다.

길이와 용량, 변경 가능성

입력 길이는 실제 읽을 원소 수, 출력 capacity 는 쓸 수 있는칸수다. filter 함수라면 선택된 개수가 용량을 넘기지 않는지 확인해야 한다. const 입력은 이 포인터 경로에서원소 수정을 금지하지만 다른 별칭으로 바뀌는 일이나 동시 접근 문제를 자동 해결하지 않는다.

count_positive 는 값 합산 대신 개수만 세어 원소 int 덧셈 overflow 를피한다. 반환 count 는최대 n 이라 size_t 범위 안이다. count 로 원소 크기를 곱해 할당할 때는 그 곱의 overflow 를 별도로 검사한다.

size_t count_positive(const int *a, size_t n) {
    size_t count = 0;
    for (size_t i = 0; i < n; ++i) {
        if (a[i] > 0) ++count;
    }
    return count;
}

현재 위치를 옮기는 출력과 다음 값을 담는 출력이 겹치면?

a=[4,9,12]에서 cursor=a, remaining=3, out=-1로 시작한다. base의 consume는 현재 값을 out에 쓰고 호출자 cursor를 한 칸 옮기며 remaining을 하나 줄인다. cursor 객체의 주소를 전달해야 그 객체가 갱신된다. 반면 cursor 값만 받은 지역 포인터를 옮기면 호출자 위치는 바뀌지 않는다. 아래 호출은 정상 저장소와 서로 겹치지 않는 상태/출력 객체를 전제한다.

out이 아직 읽지 않은 입력 원소와 겹치면 현재 값 쓰기가 미래 값을 바꿀 수 있다. 실제 대상 접근 자체가 허용되는 경우라도 읽기 순서의 계약과 데이터 보존을 어길 수 있다. 이 API는 out과 입력, cursor/remaining 상태 객체의 비중첩을 요구한다. 포인터 주소의 NULL 검사만으로 이 관계를 확인했다고 할 수 없다. 실패 때는 위치·남은 수·out을 전부 보존하며 동시 접근의 원자성은 주장하지 않는다.

주소가 저장된 칸의 주소

int *cursor 는 int 원소주소를 저장한다. int **pp 는 cursor 처럼 int*를 저장한 객체의 주소다. pp 를역참조한*pp 는 cursor 칸이고 **pp 는 cursor 가가리키는 int 원소다. 별표 수는 칸을 찾는 단계이며 실제 값의 크기나 2 차원 배열 여부가 아니다.

함수에 cursor 를값으로넘겨 cursor++하면함수의 복사본만 바뀐다. &cursor 를 int**로넘겨(*pp)++하면호출자의 cursor 값을 바꿀 수 있다. pp 자체도 값으로 복사되지만 그 주소를 통해 호출자의 포인터 객체에쓴다.

함께 유지해야 하는 경계 정보

주소만 전진시키고 남은 길이를 안 바꾸면 같은 범위를 과하게 읽을 수있다. 자체 consume 는 cursor 와 remaining 을 함께 갱신한다. remain>0 이면*pp 는같은 배열의 읽을 원소,소모뒤 one-past 는 만들어도 역참조하지 않는다.

pp/n/out 은 유효한 쓰기 가능 객체를 가리키고 각 상태 객체가 겹치지 않는다는 계약을 둔다. n0 에서는실패 불변이며*pp 원소읽기없다. 검사가 NULL 을 걸러도 살아 있는 타입 맞는 객체를 보장하는 것은 호출자 책임이다.

두 단계 쓰기를 안전하게 읽기

int value=**pp 는 현재 원소를 읽어 임시 보관한다. *out=value 는 결과 칸에 쓴다. ++*pp 는(*pp)를전진시키며++pp 와다르다. --*n 은남은개수만 1 줄인다. 괄호를 명시하면 초보자도 대상이 보인다.

포인터를 바꾸는 API 에서기존 주소를 해제하는지 단지 빌린 cursor 인지 추가로 적어야 한다. 여기서는 배열 소유자가 별도로 있고 consume 는할당/해제를 하지 않는다. int**인수에 int(*)[3]를 억지 캐스팅해 맞추는 행동은 주소 저장 객체 형식 차이를 해결하지 않는다.

int consume(int **pp, size_t *n, int *out) {
    if (pp == NULL || n == NULL || out == NULL || *n == 0) return 0;
    int value = **pp;
    *out = value;
    ++(*pp);
    --(*n);
    return 1;
}

소단원 8.4

소유권·빌림·오류 계약

주소를 받은 함수가 free 해도 되는지 누가 정할까?

준비 개념과 학습 목표

준비 개념

  • malloc/free

  • 함수 상태 반환

  • 포인터 수명

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • 해제 책임과 접근 권한을 구별한다.

  • 실패 원자성과 별칭 무효화를 설계한다.

두 번째 할당이 실패하면 첫 번째 블록은 누구의 책임일까?

두 블록을 만드는 새 API는 호출자 소유 포인터 left/right가 모두 NULL이며 서로 다른 포인터 객체라고 전제한다. 후보 블록 P와 Q를 지역 포인터로 관리하고 둘 다 할당/초기화에 성공한 뒤에만 호출자에 전달한다. Q 할당이 실패하면 P를 한 번 해제하고 호출자 left/right는 NULL로 보존한다. P가 아직 호출자에게 전달되지 않았기 때문에 함수가 정리 책임을 갖는다.

양의 크기만 요청하고 개수×sizeof 원소가 size_t에 표현 가능함을 먼저 보장한다. malloc 실패 여부와 실제 주소/가용 메모리는 종이 모형에서 관찰한 실행 사실이 아니다. 성공 후 소유권 전달을 문서로 정하고 빌린 별칭은 독자적으로 free하지 않는다. 양의 크기 realloc 실패는 기존 블록 보존이지만 성공은 옛 블록의 수명을 끝내므로 옛 빌림 포인터를 읽거나 비교하지 않는다. 크기 0의 규칙은 이 계약에서 제외한다.

먼저 확인할 개념
  • 수명 종료 뒤 포인터 값

    해제나 성공한 realloc 뒤 낡은 별칭을 읽지 않는 이유다.

  • 용량 검사 뒤 커밋

    실패 보존을 위해 후보 작업과 소유자 대입을 분리한다.

소유자는 해제 책임을 갖는다

C 의 int*형식만으로 이 주소가 malloc 소유인지 배열 일부 빌림인지 알 수 없다. API 문서가성공 시 누가 해제하고 언제 사용을 끝내는지 정한다. 빌림은 정해진 수명 동안 접근하되 임의 해제 권한은 받지 않는 계약이다.

free 에는할당 함수가 돌려준 유효 주소또는 NULL 이 필요하다. 지역 변수주소·배열 중간주소·이미 해제된 주소를 free 하면 정의되지 않은 동작이다. malloc 실패 NULL 과 성공한 미초기화 공간을 구분하고 쓰기 전에 유효 공간인지 확인한다.

새 결과를 확정하기 전 실패 처리

자체 create_three 는 out 이유효하고*out==NULL 인빈 소유자 칸이어야한다. 검사 뒤 3 개 int 공간을 할당하고 실패면*out 불변,성공이면[2,4,6]초기화 후 주소를 전달한다. 곱 3*sizeof(int)가 size_t 범위에 들어간다는 별도 사전 조건을 명시한다.

이미 *out 에 자원이 있는데 이를 덮어쓰면 기존 해제 통로를 잃어 누수될 수 있다. 따라서 이 함수는 기존 소유자가 비어 있지 않으면 할당 전에 실패한다. 기존 자원을 교체하는 다른 API 는 정리 정책을 따로 설계해야 한다. realloc 은 양의 요청 크기에서 새 공간 할당이 실패하면 원래 자원을 보존하므로, 원 포인터에 바로 덮어쓰기보다 임시 결과를 확인한다. 크기 0 요청은 별도의 구현 조건을 확인해야 한다. 이 예에서는 realloc 을 실행하지 않는다.

해제 뒤에는 별칭도 빌림 종료

성공 뒤 owner 주소와 borrow=owner 가 같은 공간을 가리킨다. free(owner)로공간 수명이끝나면 borrow 로 읽는 것도 안 된다. owner=NULL 만 설정해도 다른 borrow 변수가자동 NULL 로 바뀌거나 다시 유효해지지 않는다. 수명 종료 뒤 주소 사용은 피한다.

계약표에는 입력 수명·쓰기 권한·NULL/빈값·실패 불변·성공 해제 책임을적는다. 실패 코드를 봤다고 출력 주소를무조건 free 하지 않고 그 출력이 언제 유효해지는지 확인한다. C 언어 검사기가 일반적인 소유권 정책을 자동 검증하지 않으므로 호출 경로별종이 상태 추적이 도움 된다.

int create_three(int **out) {
    if (out == NULL || *out != NULL) return 0;
    int *p = malloc(3 * sizeof *p);
    if (p == NULL) return 0;
    p[0] = 2; p[1] = 4; p[2] = 6;
    *out = p;
    return 1;
}

P/Q는 가상 블록 식별자이며 실제 주소가 아니다. 성공 커밋 전에 후보의 정리는 함수 책임, 성공 뒤에는 호출자 책임이다. 같은 포인터 객체를 left/right로 넘기면 두 소유 주소를 별도로 보존하지 못하므로 이 설계는 거부한다.

  1. 요청 바이트 3×4=12,할당 성공주소 p 를얻는다.

  2. 원소 2/4/6 을초기화한뒤 owner 에 p 를전달,성공 1. owner 가해제 책임을진다.

조건을 바꾸어 비교하기

양의 크기 realloc 실패

owner는 살아 있는 동적 블록을 소유하며 tmp=realloc(owner,new_bytes)는 NULL을 반환했다고 가정한다. new_bytes는 양수다.

  1. tmp가 NULL인지 먼저 분기한다.

  2. 실패에서는 owner를 대입/해제하지 않고 기존 내용과 소유권을 유지한다.

owner는 기존 블록을 계속 소유한다.

비교할 점

owner=realloc(...) 직접 대입은 실패 때 유일한 주소를 잃을 수 있다.

realloc 성공 뒤 빌림

borrow=owner로 빌림을 만들고 양의 크기 realloc에 성공했다고 가정한다.

  1. 옛 블록 수명은 끝나 borrow의 옛 포인터 값이 불확정이 된다.

  2. 성공 결과 tmp를 owner에 저장한다.

  3. 필요하면 borrow=owner로 새 유효 포인터를 대입하며 옛 borrow 비교는 하지 않는다.

주소 숫자가 같아 보여도 옛 빌림을 재사용하지 않는다.

실패 보존과 성공 시 옛 수명 종료는 서로 다른 분기다.

다른 문제에 적용하기

종이 설계에서 고정 입력 [-3,2,0,7,-1,4]를 사용한다. 서로 분리된 출력 세 칸과 used=99로 양수 필터를 호출하고, 그 결과를 cursor/remaining/out이 분리된 소비 API로 끝까지 읽는다. 읽은 값으로 서로 다른 min/max 출력에 결과를 저장한다. 각 단계는 위 정상 계약을 만족한다. 별도로 새 left=right=NULL인 두 할당 API에서 P 성공/Q 실패를 가정해 정리를 보고하라. 입력/필터/소비/할당은 실제 구현·실행하지 않는다.

힌트 1

필터의 필요 수를 먼저 세고 성공 출력에서만 소비한다.

힌트 2

소비 종료 뒤의 out과 min/max를 구별하고 후보 할당은 커밋 전에 정리한다.

풀이와 답 확인

  1. 양수 수는 3이므로 용량 3 검사에 통과하고 [2,7,4]/used=3을 얻는다.

  2. 소비 성공 세 번은 2/7/4를 읽으며 remaining은 2→1→0이다. 다음 호출은 실패하며 cursor 끝과 out=4를 보존한다.

  3. 서로 다른 출력에 min=2/max=7을 저장한다. 반환 성공 상태와 마지막 소비 값 4를 별도로 적는다.

  4. 별도 할당 경로에서는 Q 실패 전에 P만 함수가 소유한다. P를 한 번 free하고 left/right를 NULL/NULL로 보존한다.

  5. 실패 보존은 순차 설계의 효과 명세이며 동시 원자성이나 실제 메모리 할당 시험이 아니다.

필터 [2,7,4]/used=3, 소비 2/7/4 뒤 거절, 최솟값 2/최댓값 7이다. P 한 번 정리와 NULL/NULL 보존이며 실제 C와 학생 실행은 미수행이다.

해결한 뒤 점검할 것

  • 실제 용량과 필요 수를 int 개수로 비교한다.

  • 남은 수 0의 거절에서 입력을 더 읽지 않는다.

  • 결과와 상태·출력 별칭 조건을 구별한다.

  • 소유권 커밋 전에 후보를 한 번만 정리한다.
