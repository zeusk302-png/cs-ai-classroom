소단원 8.1

출력 매개변수

반환값 하나는 성공 여부에 쓰고 계산 결과는 어디로 돌려줄까?

준비 개념과 학습 목표

준비 개념

  • 주소 &

  • 역참조 *

  • 함수와 조건문

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • 복사된 포인터로 호출자 객체를 수정한다.

  • 실패 시 출력 계약을 명시한다.

주소를 받는 결과 통로

C 함수는 인자값을 매개변수에 전달한다. int *out 에 &result 를 넘기면 포인터 값은 복사되지만 복사된 주소가 같은 result 객체를 가리킨다. *out=값은 그 객체에 쓰므로 호출자가 새 결과를 볼 수 있다. out 자체를 다른 주소로 바꾸는 일과 *out 에 쓰는 일을 구별한다.

상태 반환과 출력 주소를 나누면 성공/실패를 구별하면서 숫자 결과를 돌려줄 수 있다. 아래 자체 계약은 반환 1=성공,0=실패이며 실패에서는 출력 객체를 바꾸지 않는다. 이 값 선택은 C 언어의 모든 함수에 공통인 규칙이 아니라 이 함수의 약속이다.

유효 주소를 먼저 확인하기

out!=NULL 은 필요한 검사지만 충분하지 않다. 가리키는 int 객체가 살아 있고 올바른 정렬과 쓰기 권한을 가지며 함수 수행 중 유효해야 한다. 지역 변수의 주소를 호출 중 빌리는 것은 가능하지만 수명 끝난 객체 주소에 쓰는 것은 허용되지 않는다.

입력값도 계산 전에 검증한다. 자체 divide 는 a>=0,b>0, 유효 out 을 요구하고 위반이면 실패한다. 이 제한 아래 a/b 는정수 몫이며나눗셈 0 과음수/INT_MIN 관련 조건을 피한다. 검사 전에*out 을쓰면실패 시불변 계약을 어길 수 있다.

언제 결과를 확정하는가

모든 검사가 끝나고 임시 계산 결과를 만들고 마지막에*out 에쓴다. 작업 도중 결과를 여러 번 바꾸다가 실패하면 어느 값이 남는지 호출자가 알기 어렵다. 출력 두 개가 별칭이면 한 출력 쓰기가 다른 출력도 바꿀 수 있으므로 별칭 허용 여부도 설계한다.

예제는 입력 두 개를 값으로 먼저 받고출력 하나만 사용하므로 입력 원본과 out 이 같은 int 여도본문의 입력값 복사는 보존된다. 반대로 포인터 입력을 읽으면서 출력을 계속 바꾸는 함수는 같은 별칭 조건을 자동으로 만족한다고 할 수 없다.

int divide_nonneg(int a, int b, int *out) {
    if (out == NULL || a < 0 || b <= 0) return 0;
    int q = a / b;
    *out = q;
    return 1;
}

소단원 8.2

배열 인자·길이 계약

함수 안 배열 이름만으로 원래 배열 칸 수를 알아낼 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 배열과 인덱스

  • size_t

  • 포인터

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • 포인터와 길이를 함께 전달한다.

  • 경계·빈입력·용량 계약을 구별한다.

배열 표기라도 포인터 매개변수

함수 매개변수 int a[]는 배열 크기를 통째로 전달하는 형식이 아니라 포인터 형식으로 조정된다. 원래 배열이 4 칸인지 40 칸인지 포인터 값만으로 알 수 없으므로 별도 n 을 전달한다. sizeof(a)는 이 함수 안에서 포인터 크기이며 원 배열 바이트 크기라고 쓰면 틀린다.

배열 호출 전 실제 배열 표현식에서 sizeof 배열/sizeof 원소로 칸수를 계산하는 것과 이미 포인터인 값으로 그 식을 쓰는 것은 다르다. 다차원 배열은 행형식과 stride 조건까지 필요하며 int**가 연속 2 차원 배열을 자동 표현하지도 않는다.

읽을 수 있는 n 칸이라는 약속

const int *a,size_t n 은 읽을 입력과 길이 표기다. n>0 이면 a 는 적어도 n 개 int 를 연속으로 읽을 수있어야한다. for i=0;i<n;i++는 0..n-1 을읽는다. i<=n 이면마지막 n 은범위밖이다. 길이를 실제보다 크게 주면 루프 검사만 있어도 안전하지 않다.

우리 자체 count_positive 는 n0 이면 a=NULL 도 허용하고 루프를 전혀 돌지 않는다. 이때먼저 a+n 을만들거나*a 를읽지 않는구현이다. 모든 라이브러리가 NULL,n0 을 허용하는 것은 아니므로 각 API 계약을 읽어야 한다.

길이와 용량, 변경 가능성

입력 길이는 실제 읽을 원소 수, 출력 capacity 는 쓸 수 있는칸수다. filter 함수라면 선택된 개수가 용량을 넘기지 않는지 확인해야 한다. const 입력은 이 포인터 경로에서원소 수정을 금지하지만 다른 별칭으로 바뀌는 일이나 동시 접근 문제를 자동 해결하지 않는다.

count_positive 는 값 합산 대신 개수만 세어 원소 int 덧셈 overflow 를피한다. 반환 count 는최대 n 이라 size_t 범위 안이다. count 로 원소 크기를 곱해 할당할 때는 그 곱의 overflow 를 별도로 검사한다.

size_t count_positive(const int *a, size_t n) {
    size_t count = 0;
    for (size_t i = 0; i < n; ++i) {
        if (a[i] > 0) ++count;
    }
    return count;
}

소단원 8.3

이중포인터

호출자가 가진 주소 자체를 다음 칸으로 바꾸려면?

준비 개념과 학습 목표

준비 개념

  • 포인터 값복사

  • 배열 경계

  • 주소 &

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • int** 두 단계 접근을 추적한다.

  • 포인터와 남은 길이를 함께 갱신한다.

주소가 저장된 칸의 주소

int *cursor 는 int 원소주소를 저장한다. int **pp 는 cursor 처럼 int*를 저장한 객체의 주소다. pp 를역참조한*pp 는 cursor 칸이고 **pp 는 cursor 가가리키는 int 원소다. 별표 수는 칸을 찾는 단계이며 실제 값의 크기나 2 차원 배열 여부가 아니다.

함수에 cursor 를값으로넘겨 cursor++하면함수의 복사본만 바뀐다. &cursor 를 int**로넘겨(*pp)++하면호출자의 cursor 값을 바꿀 수 있다. pp 자체도 값으로 복사되지만 그 주소를 통해 호출자의 포인터 객체에쓴다.

함께 유지해야 하는 경계 정보

주소만 전진시키고 남은 길이를 안 바꾸면 같은 범위를 과하게 읽을 수있다. 자체 consume 는 cursor 와 remaining 을 함께 갱신한다. remain>0 이면*pp 는같은 배열의 읽을 원소,소모뒤 one-past 는 만들어도 역참조하지 않는다.

pp/n/out 은 유효한 쓰기 가능 객체를 가리키고 각 상태 객체가 겹치지 않는다는 계약을 둔다. n0 에서는실패 불변이며*pp 원소읽기없다. 검사가 NULL 을 걸러도 살아 있는 타입 맞는 객체를 보장하는 것은 호출자 책임이다.

두 단계 쓰기를 안전하게 읽기

int value=**pp 는 현재 원소를 읽어 임시 보관한다. *out=value 는 결과 칸에 쓴다. ++*pp 는(*pp)를전진시키며++pp 와다르다. --*n 은남은개수만 1 줄인다. 괄호를 명시하면 초보자도 대상이 보인다.

포인터를 바꾸는 API 에서기존 주소를 해제하는지 단지 빌린 cursor 인지 추가로 적어야 한다. 여기서는 배열 소유자가 별도로 있고 consume 는할당/해제를 하지 않는다. int**인수에 int(*)[3]를 억지 캐스팅해 맞추는 행동은 주소 저장 객체 형식 차이를 해결하지 않는다.

int consume(int **pp, size_t *n, int *out) {
    if (pp == NULL || n == NULL || out == NULL || *n == 0) return 0;
    int value = **pp;
    *out = value;
    ++(*pp);
    --(*n);
    return 1;
}

중간 과정을 따라가는 예제

배열[4,9],cursor 는첫원소,n2,out=-1 이다. 상태 객체는 분리되고 계약이 유효하다. consume(&cursor,&n,&out)를 3 회추론하라.

  1. 첫번째 value4,out4,cursor 둘째원소,n1,반환 1.

  2. 둘째 value9,out9,cursorone-past,n0,반환 1.

  3. 셋째 n0 검사 실패,역참조/주소갱신없음,반환 0/out9/n0 이다.

결과 4,9 를 순서대로 받고 끝에 one-past 를보존한다. 끝 주소 원소를 읽지 않는다.

힌트 보기

소단원 8.4

소유권·빌림·오류 계약

주소를 받은 함수가 free 해도 되는지 누가 정할까?

준비 개념과 학습 목표

준비 개념

  • malloc/free

  • 함수 상태 반환

  • 포인터 수명

  • 코드 조각에서 NULL 과 size_t 에는 <stddef.h>, malloc/free 에는 <stdlib.h> 선언이 필요하다. 코드 조각을 독립 프로그램으로 만들려면 필요한 헤더와 호출부를 함께 둔다.

학습 목표

  • 해제 책임과 접근 권한을 구별한다.

  • 실패 원자성과 별칭 무효화를 설계한다.

소유자는 해제 책임을 갖는다

C 의 int*형식만으로 이 주소가 malloc 소유인지 배열 일부 빌림인지 알 수 없다. API 문서가성공 시 누가 해제하고 언제 사용을 끝내는지 정한다. 빌림은 정해진 수명 동안 접근하되 임의 해제 권한은 받지 않는 계약이다.

free 에는할당 함수가 돌려준 유효 주소또는 NULL 이 필요하다. 지역 변수주소·배열 중간주소·이미 해제된 주소를 free 하면 정의되지 않은 동작이다. malloc 실패 NULL 과 성공한 미초기화 공간을 구분하고 쓰기 전에 유효 공간인지 확인한다.

새 결과를 확정하기 전 실패 처리

자체 create_three 는 out 이유효하고*out==NULL 인빈 소유자 칸이어야한다. 검사 뒤 3 개 int 공간을 할당하고 실패면*out 불변,성공이면[2,4,6]초기화 후 주소를 전달한다. 곱 3*sizeof(int)가 size_t 범위에 들어간다는 별도 사전 조건을 명시한다.

이미 *out 에 자원이 있는데 이를 덮어쓰면 기존 해제 통로를 잃어 누수될 수 있다. 따라서 이 함수는 기존 소유자가 비어 있지 않으면 할당 전에 실패한다. 기존 자원을 교체하는 다른 API 는 정리 정책을 따로 설계해야 한다. realloc 은 양의 요청 크기에서 새 공간 할당이 실패하면 원래 자원을 보존하므로, 원 포인터에 바로 덮어쓰기보다 임시 결과를 확인한다. 크기 0 요청은 별도의 구현 조건을 확인해야 한다. 이 예에서는 realloc 을 실행하지 않는다.

해제 뒤에는 별칭도 빌림 종료

성공 뒤 owner 주소와 borrow=owner 가 같은 공간을 가리킨다. free(owner)로공간 수명이끝나면 borrow 로 읽는 것도 안 된다. owner=NULL 만 설정해도 다른 borrow 변수가자동 NULL 로 바뀌거나 다시 유효해지지 않는다. 수명 종료 뒤 주소 사용은 피한다.

계약표에는 입력 수명·쓰기 권한·NULL/빈값·실패 불변·성공 해제 책임을적는다. 실패 코드를 봤다고 출력 주소를무조건 free 하지 않고 그 출력이 언제 유효해지는지 확인한다. C 언어 검사기가 일반적인 소유권 정책을 자동 검증하지 않으므로 호출 경로별종이 상태 추적이 도움 된다.

int create_three(int **out) {
    if (out == NULL || *out != NULL) return 0;
    int *p = malloc(3 * sizeof *p);
    if (p == NULL) return 0;
    p[0] = 2; p[1] = 4; p[2] = 6;
    *out = p;
    return 1;
}

중간 과정을 따라가는 예제

owner=NULL 에서 create_three(&owner)를추론한다. sizeof(int)=4 인자체 ABI 이고 곱 범위 유효/할당 성공을 가정한다. 이어 borrow=owner,free(owner),owner=NULL 이다.

  1. 요청 바이트 3×4=12,할당 성공주소 p 를얻는다.

  2. 원소 2/4/6 을초기화한뒤 owner 에 p 를전달,성공 1. owner 가해제 책임을진다.

  3. borrow 는읽기 빌림이다. free(owner)뒤대상 수명 끝,owner=NULL 뒤에도 borrow 를다시읽을 수없다.

예상 12 바이트요청/[2,4,6]/해제 1 회다. 실제 할당·실행은 미수행이며 해제 후 borrow 값을 관측하지 않는다.

종이와 본문으로 직접 해보기

처음 owner=NULL 에서할당 실패라면? 처음 owner 가기존 유효 자원을 소유하면? free(NULL),free(owner+1)를 계약으로 분류하라.

힌트 보기

검사와할당 실패 경로에*out 대입이 있는지 보고 free 가능 주소 조건을 찾는다.

풀이 보기

실패면 0/ownerNULL 유지,기존 owner 있으면할당 전거부 0/기존 주소보존이다. free(NULL)은아무동작 없고배열 중간 owner+1 해제는 허용되지 않는다. 기존 owner 가유효 배열이라는 조건에서 분류한다.

오해와 반례

소유자만 NULL 로바꾸면 모든 별칭도 안전해진다.

borrow 는자동 변경되지 않고 가리키던 공간 수명은끝났다. 주소 변수 정리와대상 수명 관리를 구별한다.
