소단원 5.1

배열의 크기·인덱스

다섯 칸짜리 배열의 마지막 번호는 왜 5가 아니라 4일까?

준비 개념과 학습 목표

준비 개념

  • 배열은 같은 원소 타입을 가진 객체를 연속해서 배치한 묶음이다. int a[5]에서 a는 다섯 int의 배열이고 a[0]은 첫 원소이다. 원소 수와 마지막 인덱스는 다른 숫자다.

  • size_t는 sizeof 결과를 담는 부호 없는 정수 타입이다. sizeof는 크기를 C의 바이트 단위로 나타내며 바이트가 반드시 8비트이거나 int가 반드시 4바이트라는 가정은 하지 않는다.

  • 자가진단: a[0],a[1],a[2]라는 세 칸의 번호를 적어 보자. 번호의 최대는 2, 원소 수는 3이다. 이 구별만으로 본문의 그림에 들어갈 수 있다.

학습 목표

  • 배열 객체의 크기와 유효 인덱스를 계산한다.

  • 부분 초기화와 미초기화 자동 배열을 구별한다.

  • sizeof의 배열 객체와 포인터 매개변수 차이 및 VLA 조건을 설명한다.

서랍이 여섯 칸인데 기록이 두 개뿐이면 빈 네 칸도 기록일까?

C11의 고정 배열 객체와 프로그램이 정한 논리 길이를 나눈다. int a[6]={8,3}은 여섯 int 객체를 만들고 값은 [8,3,0,0,0,0]이다. 별도 size_t used=2는 앞 두 칸만 업무 기록이라는 계약이다. 초기값 0인 나머지는 실제 읽을 수 있지만 실제 기록이라고 간주할지는 별도 명세다.

함수에 배열을 넘길 때 여섯 객체가 값으로 복사되는 것이 아니다. 포인터와 used, capacity를 나누어 전달할 수 있다. capacity는 실제 제공된 수정 가능한 객체 수라는 신뢰 계약이고 자동 메모리 검사가 아니다. Python append처럼 크기 자체가 자동으로 늘어나는 것으로 생각하지 않는다. 여기의 sizeof 결과는 C 바이트 단위이며 int의 특정 크기를 가정하지 않는다.

객체 크기와 유효 번호

이 단원은 C11 공개 초안 N1570을 기준으로 한다. int a[5]의 원소 수는 5이고 첫 원소를 기준으로 접근할 수 있는 번호는 0≤i<5이다. a[5]라는 여섯 번째 원소는 없다. 같은 원소 타입의 배치이므로 배열의 전체 크기는 원소 수에 원소 하나의 크기를 곱한 것이다.

실제 배열 객체 a가 보이는 위치에서는 sizeof a / sizeof a[0]으로 원소 수를 구한다. 분자와 분모가 같은 C 바이트 단위라 그 비는 5이며 sizeof(int)의 특정 값을 가정할 필요가 없다. 배열은 이 선언으로 정한 객체이고 원소를 더 넣는다고 자동으로 늘어나지 않는다.

초기화가 제공하는 값

int a[5]={4,7};은 첫 두 칸을 4,7로 초기화하고 남은 int 칸은 0으로 초기화한다. int a[]={4,7};처럼 원소 수를 생략하고 초기값을 주면 이 예에서는 원소 수가 2로 정해진다. int a[5];만 함수 안에서 자동 저장기간으로 선언하면 모든 칸이 자동으로 0이 된다고 말할 수 없다. 읽기 전에 각 칸에 유효한 값을 저장해야 한다.

고정 크기인 이 예제의 sizeof 피연산자는 평가되지 않으므로 sizeof a[0]은 첫 칸의 값 읽기가 아니다. 일반 C11 VLA에서는 크기 계산이 실행 중 이루어질 수 있으므로 sizeof가 항상 실행 중 평가를 하지 않는다고 일반화하지 않는다. VLA 지원은 C11의 조건부 기능이고, 실행 시 평가되는 길이는 양수여야 하며 해당 배열 인스턴스의 크기는 수명 중 바뀌지 않는다. VLA가 큰 입력의 저장공간 확보나 실패 처리를 자동 보장하지도 않는다.

함수 경계에서 길이를 잃지 않기

void f(int a[5])의 a는 함수 매개변수 규칙에 의해 int *로 조정된다. 함수 안의 sizeof a는 호출자의 다섯 원소 배열 크기가 아니라 포인터 타입의 크기다. 이 비율로 호출자의 길이를 복원하면 안 된다. 보통 포인터와 별도 size_t n을 전달하고 n개의 살아 있는 원소가 제공된다는 계약을 명시한다.

선언에 대괄호가 있다는 사실만으로 자동 범위 검사가 생기지 않는다. 예컨대 매개변수 int a[static 5]는 호출자가 최소 다섯 원소에 대한 접근을 제공해야 하는 계약을 나타내지만, 알아서 검사하거나 작은 배열을 확대하는 장치가 아니다. 아래 예제는 함수 경계의 조정과 VLA에 의존하지 않는 완전한 고정 배열 프로그램이다.

#include <stdio.h>
#include <stddef.h>
int main(void) {
    int a[5] = {4, 7};
    size_t n = sizeof a / sizeof a[0];
    a[n - 1] = 9;
    printf("%zu %d %d %d\n", n, a[0], a[2], a[4]);
    return 0;
}

used=2는 소프트웨어 기록의 끝이고 capacity=6은 실제 배열 끝이다. 위치2는 물리 one-past가 아니다. 위치6의 포인터 표지 형성과 값 읽기는 구별한다.

중간 과정을 따라가는 예제

코드의 int a[5]={4,7}에서 n을 계산한 뒤 마지막 칸을 9로 바꾼다. %zu는 size_t를 표시한다. 정상 출력 성공을 가정한 예상값만 구한다.

  1. 선언 직후 다섯 칸의 값은 [4,7,0,0,0]이다. 나머지 세 int는 부분 초기화 규칙으로 0이다.

  2. sizeof a=5*sizeof(int), sizeof a[0]=sizeof(int)이므로 n=5이다. 특정 바이트 수는 가정하지 않는다.

  3. n은 5라서 n−1=4이고 a[4]=9는 유효한 마지막 원소에 쓴다. 배열은 [4,7,0,0,9]가 된다.

  4. 출력 인자는 n=5,a[0]=4,a[2]=0,a[4]=9이다. 형식 지정자 %zu와 세 %d가 각각의 타입과 맞는다.

예상 stdout은 5 4 0 9와 줄바꿈이다. 실제 컴파일·실행은 하지 않았다.

조건을 바꾸어 비교하기

초기화와 등록을 나누기

위 상태에서 a[used]=9; ++used;를 순서대로 수행한다. capacity=6이며 used<capacity를 먼저 확인했다.

  1. used=2<6을 확인한다.

  2. 유효한 a[2]에 9를 저장한 뒤 used=3으로 바꾼다.

  3. 기록은 [8,3,9]이며 뒤 세 실제 칸은 계속 0이다.

배열 객체 수6은 그대로이고 논리 기록 수만3이다.

비교할 점

객체 크기 변화와 기록 수 변화를 분리한다.

sizeof가 정보를 잃는 경계

호출자에서 int a[6]과 int *p=a가 있다. f(int x[6]) 안팎의 sizeof 비율을 비교한다.

  1. 호출자의 sizeof a/sizeof a[0]은6이다.

  2. p는 포인터라 sizeof p/sizeof p[0]은 포인터 크기 대 int 크기의 비다.

  3. x도 조정된 포인터라 같은 비로 여섯 원소를 복원할 수 없다.

실제 배열 타입이 유지되는 식에서만 길이 비율을 쓴다.

비교할 점

우연히 비율이6인 구현도 일반 길이 계산법이 아니다.

종이와 본문으로 직접 해보기

int b[4]={8};의 네 칸을 그린다. 원소 수·최대 인덱스·값을 적고 sizeof b/sizeof b[0]을 구한다. void g(int b[4]) 안에서도 같은 식이 길이를 뜻하는지 판정한다.

힌트 보기

실제 배열 객체인 b와 포인터로 조정된 매개변수 b를 별도의 표에 적는다.

풀이 보기

호출자 배열 값은 [8,0,0,0], 원소 수 4, 최대 인덱스 3, 배열 객체의 비율은 4이다. g의 매개변수는 int *이므로 함수 안 비율은 sizeof(int *)/sizeof(int)이며 배열 길이의 근거가 아니다. 그 구현 값이 우연히 4여도 일반적인 길이 복원 규칙이 되지 않는다.

오해와 반례

a[5]라는 선언이 있으니 a[5]도 그 배열 안이다.

선언의 5는 원소 수이고 접근식의 5는 0부터 센 여섯 번째 위치다. 유효한 마지막 위치는 4이다. 자동 배열을 초기화하지 않은 상태에서 읽는 문제도 범위 문제와 별도로 존재한다.

매개변수 int a[5] 안의 sizeof a는 원래 배열 전체 크기인가?

함수의 배열 매개변수는 포인터 타입으로 조정되므로 길이는 별도 계약으로 전달한다.

C11 VLA를 선언하는 실행 시 길이 0을 허용한다고 가정해도 되는가?

답과 이유 보기

안 된다. 해당 크기 표현식이 평가될 때 양수 조건이 필요하다.

VLA는 C11의 조건부 기능이며 지원 여부·양수 크기·저장 자원 조건을 확인해야 한다.

소단원 5.2

순회·탐색·정렬 기초

같은 배열을 훑더라도 찾는 함수와 순서를 바꾸는 함수의 계약은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • for는 시작·계속 조건·본문·증가를 반복한다. i<n을 검사한 다음 a[i]를 읽으면 그 순간 i<n이라는 근거를 사용할 수 있다.

  • 선형 탐색은 왼쪽부터 순서대로 검사하는 방법이다. 정렬은 값을 비내림차순으로 배치하는 일이며, 같은 값이 여러 번 있으면 개수도 보존해야 한다.

  • 자가진단: [4,1,4,2]에서 4의 첫 위치는 0이다. 정렬 후 [1,2,4,4]의 첫 4는 2이므로 탐색 결과는 어느 상태에서 얻었는지 밝혀야 한다.

학습 목표

  • 첫 위치 또는 n이라는 탐색 결과 계약을 설명한다.

  • 탐색·선택 정렬의 반복 불변조건과 종료를 논증한다.

  • 원소 비교 횟수와 실제 시간, signed 합의 표현 범위를 구별한다.

정렬된 결과가 맞아도 옛 위치 번호는 계속 같은 대상을 뜻할까?

검색 결과 위치는 특정 배열 상태에 붙은 정보다. 자체 배열 [5a,2,5b,1]에서 a,b는 같은 값5의 이름표이며 C int에 이름표를 저장한 코드가 아니다. base의 first는 값5의 첫 위치0을 반환한다. selection은 값만 비교해 순서를 바꾸므로 이름표는 추적 그림에서만 유지한다.

정렬의 계약은 비내림차순과 다중집합 보존이다. 첫 위치 번호의 의미 보존이나 안정성까지 자동 포함하지 않는다. 정확한 비교 수는 원소끼리 < 비교만 세며 조건 검사·주소 계산·실제 시간은 별도로 둔다. 아래 작은 값은 모든 C11 int에서 표현 가능하다.

먼저 확인할 개념
  • 첫 발견과 반복 불변조건

    앞 구간에 key가 없다는 근거를 사용한다.

  • 인덱스와 원소 상태

    위치의 유효성과 원소의 정체성을 분리한다.

읽기만 하는 순회와 첫 위치 탐색

first(a,n,key)의 사전조건은 n>0일 때 a가 호출 전체 동안 살아 있는 배열의 첫 원소를 가리키고, 적어도 n개의 초기화된 int를 읽을 수 있다는 것이다. n=0이면 함수는 a를 사용하지 않으므로 NULL을 전달하는 계약도 허용한다. 결과는 key와 같은 첫 원소의 위치 또는 못 찾았다는 표시 n이다. n은 유효 위치와 겹치지 않는다.

본문이 a[i]를 읽는 순간 0≤i<n이다. 반복 시작 시 앞 구간 [0,i)에 key가 없다는 불변조건을 둔다. 처음에는 빈 구간이므로 참이다. 현재 원소가 key이면 그 앞에 같은 값이 없어서 첫 위치이다. 같지 않으면 검사한 구간을 한 칸 늘릴 수 있다. i는 n까지 증가하므로 유한한 입력에서 종료하며 끝에 n을 반환하면 전 구간에 key가 없다.

선택 정렬은 값을 바꾸는 별도 계약이다

selection은 n개의 살아 있고 초기화된 수정 가능한 int 원소를 요구한다. 바깥 위치 i에서 접미부 [i,n)의 최솟값 위치 m을 찾고 a[i]와 교환한다. 비교는 a[j]<a[m]이며 뺄셈으로 비교하지 않는다. a[j]-a[m]은 두 int가 유효해도 signed overflow를 일으킬 수 있기 때문이다.

완료된 앞 구간은 비내림차순이고 그 원소들은 남은 구간의 모든 값 이하라는 불변조건을 둔다. 접미부 최솟값을 앞 칸으로 옮기면 이를 한 칸 확장한다. 교환은 값을 잃지 않아 원소의 다중집합도 보존한다. 같은 값에 이름표를 붙였을 때 이 비인접 교환은 원래 순서를 바꿀 수 있으므로 이 구현을 안정 정렬이라고 주장하지 않는다.

정확한 비교 수와 산술 조건

이 구현에서 원소끼리의 < 비교는 n−1,n−2,…,1,0번이므로 합은 n(n−1)/2이다. n=0 또는 1이면 0번이며, 이 식은 수학적 정수로 계산한 횟수다. C의 size_t에서 그대로 n*(n-1)을 계산하면 n=0의 뺄셈이나 큰 값의 곱이 순환할 수 있다. 이는 기호로 계산한 횟수와 별개다. 루프 조건 비교·교환·출력 비용은 이 횟수에 포함하지 않는다.

고정 비용 원소 비교 모형에서 선택 정렬의 비교 횟수는 큰 n에 대해 Θ(n²)이며 이미 정렬된 입력에서도 같다. 실제 실행 시간이나 캐시 성능을 측정한 결과가 아니다. 순회로 합을 계산하는 함수를 덧붙인다면 모든 누적 중간 합이 int로 표현 가능해야 한다. 최종 합만 작다는 것으로 signed overflow를 피했다고 할 수 없다.

#include <stdio.h>
#include <stddef.h>
size_t first(const int *a, size_t n, int key) {
    for (size_t i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return n;
}
void selection(int *a, size_t n) {
    for (size_t i = 0; i < n; ++i) {
        size_t m = i;
        for (size_t j = i + 1; j < n; ++j)
            if (a[j] < a[m]) m = j;
        if (m != i) { int tmp = a[i]; a[i] = a[m]; a[m] = tmp; }
    }
}
int main(void) {
    int a[] = {4, 1, 4, 2};
    size_t n = sizeof a / sizeof a[0];
    size_t found = first(a, n, 4);
    selection(a, n);
    printf("%zu %d %d %d %d\n", found, a[0], a[1], a[2], a[3]);
    return 0;
}

소단원 5.3

다차원 배열

2행 3열 표를 함수로 넘길 때 왜 열 수가 포인터 타입에 남아 있어야 할까?

준비 개념과 학습 목표

준비 개념

  • a[2][3]은 int 여섯 개를 쓰지만 타입은 세 int를 가진 행 배열 두 개의 배열이다. 첫 첨자는 행, 둘째 첨자는 열이다.

  • 포인터 p+1은 무조건 1바이트 이동이 아니다. 포인터가 가리키는 타입의 객체 한 개만큼 이동한다. int *와 int (*)[3]은 서로 다른 타입이다.

  • 자가진단: 2행 3열의 유효한 좌표는 r=0,1과 c=0,1,2의 조합이다. (1,2)는 마지막 칸이고 (0,3)은 유효 좌표가 아니다.

학습 목표

  • 행 배열의 배열과 row-major 배치를 설명한다.

  • 다차원 매개변수 조정과 포인터 타입을 구별한다.

  • 좌표의 범위와 합의 산술 조건을 함께 확인한다.

같은 숫자 여섯 개를 표와 줄에 담으면 모든 접근 방법도 같아질까?

고정 int m[2][3]={{2,4},{7}}을 새 예로 쓴다. 중괄호는 행별 초기화를 지정해 m의 값은 [[2,4,0],[7,0,0]]이다. 별도로 int flat[6]={2,4,0,7,0,0}을 선언하면 값 순서는 같지만 타입은 다르다. m은 세 int를 가진 행 두 개의 배열, flat은 int 여섯 개의 배열이다.

좌표의 그림 번호 k=3r+c와 실제 C에서 합법적인 접근식은 구별한다. m의 행 포인터 p+1은 다음 행이고 flat의 원소 포인터 q+1은 다음 int다. 전체 인접 배치가 m[0][3]의 첫 행 밖 읽기를 허용하지 않는다. 합은 작은 초기값에 한정하고 실제 주소는 측정하지 않는다.

먼저 확인할 개념
  • 포인터 전달과 대상

    대상 타입이 이동 단위를 결정한다.

  • 전체와 부분 초기화

    생략된 행 원소의0을 설명한다.

행을 원소로 갖는 배열

int a[2][3]={{1,2,3},{4,5,6}};은 바깥 배열의 원소 수2, 각 행의 원소 수3인 완전한 초기화이다. C 배열은 마지막 첨자가 가장 빨리 바뀌는 row-major 순서로 배치되므로 저장 순서 설명은 1,2,3,4,5,6이다. 좌표 (r,c)에 대해 0≤r<2, 0≤c<3을 각각 확인한다.

배열의 행과 열은 수학적 그림이며 실제 주소 숫자를 측정한 것은 아니다. 전체 바이트 크기는 2*3*sizeof(int), 한 행은 3*sizeof(int)이다. 추상적인 저장 위치 번호는 3r+c로 설명할 수 있지만, 이 그림만으로 행 경계를 벗어나는 int 포인터 산술이나 a[0][3]을 허용하지 않는다.

포인터는 행의 폭을 보존한다

표현식 a는 보통 첫 행을 가리키는 int (*)[3]으로 변환된다. int (*p)[3]=a에서 p+1은 다음 행을 가리킨다. a[r]는 한 행 배열이고 그 행은 원소 접근 시 int *로 변환된다. 포인터 타입의 단계가 서로 다르므로 이를 int **로 바꿔 호출해서는 안 된다.

함수의 int a[][3]은 int (*a)[3]으로 조정된다. 바깥 행 수는 별도 길이 계약에서 제공해야 하지만 안쪽 3은 행 단위 이동의 타입에 남는다. C11에서 일반적인 가변 열 수를 사용하려면 VLA 지원과 양수 차원 등 별도 조건을 확인해야 한다. 이 단원은 열 수3의 고정 타입을 써 설치나 VLA 지원이 필요 없게 한다.

인덱스와 누적값의 계약

row_sum은 전달받은 a가 실제로 필요한 행을 가진 배열을 가리키고 row가 실제 행 수 미만이며, 그 행의 세 int가 초기화되어 있다는 계약을 요구한다. 함수 이름이나 a[][3]만으로 실제 행 수가 검사되지 않는다. const나 타입 일치만으로 대상의 수명도 자동 보장하지 않는다.

각 덧셈의 중간 total이 int 범위 안이라는 산술 조건도 필요하다. 예제 두 번째 행은 4→9→15라 모든 C11 int에서 작고 안전한 값이다. 호출자 객체에서 sizeof a/sizeof a[0]은 행 수2, sizeof a[0]/sizeof a[0][0]은 열 수3이다. 같은 식을 조정된 함수 매개변수 a에 대해 전체 행 수 계산이라고 쓰지 않는다.

#include <stdio.h>
#include <stddef.h>
int row_sum(int a[][3], size_t row) {
    int total = 0;
    for (size_t c = 0; c < 3; ++c) total += a[row][c];
    return total;
}
int main(void) {
    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*p)[3] = a;
    printf("%zu %zu %d %d\n", sizeof a / sizeof a[0],
           sizeof a[0] / sizeof a[0][0], p[1][1], row_sum(a, 1));
    return 0;
}

행 폭이 남는 sizeof

호출자에서 m의 행/열 수와 int p[][3] 매개변수 내부의 sizeof p[0]/sizeof p[0][0]을 비교하라.

  1. 호출자는 sizeof m/sizeof m[0]=2와 행 비율3을 얻는다.

  2. 매개변수 p는 int (*)[3]으로 조정된다.

  3. sizeof p 자체는 포인터 크기이지만 p[0]의 타입은 세 int 배열이라 행 비율은3이다.

풀이 보기

오해와 반례

다차원 배열은 int **이며 모든 칸이 연속이면 어떤 첨자로든 넘어가도 된다.

int a[2][3]은 행 배열의 배열이며 int **와 타입·이동 단위가 다르다. a[0][3]은 첫 행 경계를 벗어난 접근이고 전체 메모리가 연속이라는 사실로 정당화되지 않는다. 가상 좌표의 선형 번호와 합법적인 포인터 접근을 분리한다.

소단원 5.4

범위 밖 접근의 오류

배열 밖을 읽었는데 어떤 실행에서는 멀쩡해 보이면 안전하다고 할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 유효 접근은 인덱스뿐 아니라 살아 있는 적합한 대상과 초기화된 값이 필요하다. 선언된 배열의 크기와 호출자가 주장하는 길이는 같다고 자동 증명되지 않는다.

  • one-past는 마지막 원소 바로 뒤를 표시하는 위치다. 끝 경계 표지로 쓰는 것과 그 자리에 값을 읽거나 쓰는 것은 다르다.

  • 자가진단: int a[3]의 원소는 a[0],a[1],a[2]이다. a+3은 끝 경계 표지이고 a[3]이라는 읽을 원소는 없다.

학습 목표

  • 포인터 형성과 역참조의 범위 조건을 구별한다.

  • 길이 검사 함수의 사전조건과 실패 계약을 설명한다.

  • signed 오류와 unsigned 순환, 실제 실패 관찰과 UB를 구별한다.

자와 숫자로 길이를 검사하면 실제 서랍이 있다는 사실까지 확인될까?

검사는 이미 유효한 대상과 신뢰 가능한 길이라는 전제 위에서 동작한다. 새 실제 int a[6]={8,3,9,0,0,0}, used=3, out=77을 둔다. 업무 read_record는 i<used에서만 반환1과 out 갱신을 허용한다. used≤6은 호출자의 불변조건이고 함수가 포인터에서 여섯 칸을 자동 알아내지는 않는다.

i=3은 실제 a[3]의0을 읽을 수 있는 물리 위치지만 업무 기록 밖이므로 정상 실패다. i=6은 실제 배열의 one-past이며 값 읽기는 금지다. 물리적으로 읽을 수 있음, 업무상 허용됨, 검사 전 대상의 존재를 나눠야 한다. out은 별도의 살아 있고 수정 가능한 int 객체이고 배열과 겹치지 않는다는 계약을 둔다.

먼저 확인할 개념
  • 단락 검사 순서

    접근보다 먼저 경계를 검사한다.

  • 출력 대상과 실패 계약

    출력 포인터의 유효성과 기존 값 보존을 연결한다.

끝 경계 포인터와 존재하는 원소

배열 첫 원소를 가리키는 a에 대해 a+3은 길이3 배열의 one-past로 형성할 수 있다. 그러나 그 포인터를 평가되는 *의 피연산자로 사용해 원소를 읽거나 쓰면 안 된다. a[3]은 *(a+3)이라는 첨자 접근이므로 같은 문제가 있다. a+4는 허용되는 배열 안 또는 one-past 밖이어서 포인터를 만드는 산술 자체가 계약 밖이다.

&a[3]처럼 주소만 만드는 표현은 C11의 &와 첨자 결합 규칙에서 a+3과 같아 유효한 끝 표지를 만들 수 있다. 이 예외를 a[3]의 값 읽기 허용으로 바꾸면 안 된다. 허용 위치는 어떤 실제 배열 객체를 기준으로 하는지도 중요하다. 다차원 배열에서는 전체 저장이 인접해도 각 행의 경계를 넘는 첨자 접근이 정당화되지 않는다.

조건을 먼저 확인하고 접근한다

read_at은 size_t i를 받아 i>=n이면 0을 반환하고 out을 변경하지 않는다. i<n이면 a[i]를 out에 복사하고 1을 반환한다. 성공할 수 있는 호출은 a가 적어도 n개의 살아 있는 초기화된 int 원소를 제공하고 out이 살아 있는 수정 가능한 int를 가리킨다는 사전조건을 요구한다. n=0이면 항상 실패하며 a와 out을 사용하지 않으므로 NULL도 허용한다.

이 함수는 n이 실제 길이인지 검증하지 못한다. 길이3 배열에 n=100,i=4를 보내면 비교를 통과해도 대상은 없다. 검사 자체에 접근보다 앞선 길이 신뢰 계약이 필요하다. 음수 정수를 size_t로 바꾸면 큰 값이 될 수 있고 범위를 넘는 양수도 변환 과정에서 순환할 수 있으므로 외부 입력의 부호·표현 가능성을 먼저 검사한 뒤 이 인터페이스에 넘겨야 한다.

불변조건과 산술 오류를 함께 점검한다

for(size_t i=0;i<n;++i)처럼 n보다 작은지 확인한 뒤 접근하는 모양은 올바른 시작점이다. 반면 i<=n은 끝 경계 n에서 한 번 더 접근한다. n=0에서 size_t last = n - 1;로 저장하면 last는 size_t의 최댓값이 된다. size_t의 폭이 작아 int로 승격되는 구현에서는 식 자체가 먼저 int의 −1일 수 있지만, 이를 size_t에 저장하면 같은 최댓값으로 변환된다. 따라서 마지막 위치를 구하려면 먼저 n>0임을 알아야 한다. unsigned 순환은 C에 정의된 산술이지만 잘못된 길이·인덱스의 의미까지 올바르게 만들지는 않는다.

signed int의 INT_MAX+1은 정의되지 않은 동작이다. 이와 배열 밖 접근은 별개의 UB 원인이고 둘 다 고정된 오류 메시지나 항상 즉시 종료한다는 규칙이 없다. 출력이 우연히 정상처럼 보이는 한 실행으로 안전성을 증명하지 않는다. 아래 코드는 실패 시 기존 out을 보존하는 정상 경로만 보여 주며 범위 밖 역참조를 시험 코드로 실행하지 않는다.

#include <stdio.h>
#include <stddef.h>
int read_at(const int *a, size_t n, size_t i, int *out) {
    if (i >= n) return 0;
    *out = a[i];
    return 1;
}
int main(void) {
    int a[3] = {6, 7, 8};
    int out = 99;
    int ok = read_at(a, 3, 3, &out);
    printf("%d %d\n", ok, out);
    ok = read_at(a, 3, 2, &out);
    printf("%d %d\n", ok, out);
    return 0;
}

검사 함수는 거부한 번호의 주소를 먼저 만들지 않는다. 실패 시 a+i나 a[i],*out을 평가하지 않으면 물리 대상 밖 번호도 정상 거부할 수 있다. 이것은 잘못된 주소를 먼저 만든 뒤 안전하게 되돌리는 기술이 아니다.

길이3의 a=[6,7,8], out=99에서 먼저 i=3, 다음 i=2로 read_at을 호출한다. n은 실제 원소 수이고 성공 경로의 a,out은 유효하다.

보존된 값과 성공 상태를 함께 해석한다.

잘못된 길이는 if로 고쳐지지 않는다

실제 int small[2]={4,5}를 제공하면서 used=3,i=2로 기록 읽기 함수를 호출했다.

  1. 검사2<3은 참이다.

  2. 실제 small[2]는 one-past 읽기라 허용되지 않는다.

  3. 이 호출은 실제 객체 수 계약 위반이며 정상 값이나 오류 메시지를 예측하지 않는다.

검사에 쓰는 길이의 출처도 확인한다.

비교할 점

큰 숫자를 전달하는 것과 실제 객체를 제공하는 것은 다르다.

종이와 본문으로 직접 해보기

int b[4]={1,2,3,4};에서 b+4 형성, *(b+4) 읽기, b+5 형성, &b[4] 형성을 분류한다. 이어 read_at(b,4,4,&v)에서 기존 v=20이 유지되는 이유를 적는다.

힌트 보기

허용되는 끝 표지의 형성과 평가되는 역참조를 구별한다. 검사보다 먼저 잘못된 접근을 했다면 사후 검사로 고칠 수 없다.

풀이 보기

b+4와 &b[4]는 허용된 one-past 형성이다. *(b+4)의 읽기와 b+5 형성은 UB이다. read_at의 4>=4 검사가 접근 전에 실패로 끝나므로 반환0,v=20이다. UB 두 식의 특정 출력이나 오류를 답으로 쓰지 않는다.

오해와 반례

범위를 넘으면 C가 예외를 던져서 잡을 수 있으므로 일단 읽고 나중에 검사해도 된다.

C11의 일반 배열 접근은 자동 예외·범위 검사 계약이 없다. 범위 밖 접근은 UB이며 특정 출력이나 종료를 보장하지 않는다. 읽기 전에 실제 길이에 근거한 조건을 확인해야 하고 이미 일어난 UB를 뒤의 if로 취소할 수 없다.

아니다. 전자는 one-past 형성이 가능하고 후자의 읽기는 불가하다.

다른 문제에 적용하기

새 고정 int slots[6]={8,3}, used=2이다. 네 등록 요청은9/4/7/2이며 각 성공은 used<6 검사 후 slots[used]에 쓰고 used를 증가시킨다. 다섯 번째 요청5는 같은 규칙으로 거부한다. 등록 뒤 read_record(slots,used,5,&out)과 번호6 조회를 out=77부터 순서대로 수행한다. 별도 int grid[2][3]에 유효한 좌표로 slots의 여섯 값을 옮기고, grid 둘째 행을 별도 세 원소 배열에 복사하여 base selection으로 정렬한다. 7의 정렬 전후 첫 위치와 정렬 원소 비교 수를 구하라. 실패 보존·물리/논리 경계·행 타입·옛 위치를 포함한 보고서를 작성하라. 모든 대상은 살아 있고 초기화/수정 계약을 충족하며 실제 C 빌드·실행은 하지 않는다.

힌트 1

등록 검사와 쓰기 후 길이 증가를 분리한다. 여섯 번째 위치는 번호5다.

힌트 2

그림 번호 k의 좌표는 k/3,k%3이다. 복사한 행의 정렬은 원본 grid를 변경하지 않는다.

풀이와 답 확인

  1. 네 성공 뒤 slots=[8,3,9,4,7,2], used=6이다. 다섯 번째5는 used==6이라 실패하고 모든 상태를 보존한다.

  2. 번호5는 유효 기록2라 out2와 반환1이다. 번호6은 조회 실패로 반환0이며 out2를 보존한다. 주소 slots+7이나 값 slots[6]을 먼저 만들지 않는다.

  3. grid는 [[8,3,9],[4,7,2]]이며 int (*)[3]으로 행 이동한다. grid[0][3] 대신 grid[1][0]을 쓴다.

  4. 복사한 행 [4,7,2]에서 첫7의 위치1이다. 첫 교환 뒤 [2,7,4], 둘째 뒤 [2,4,7]이며 비교2+1+0=3이다. 새 첫7은2다.

  6. 실제 C/주소/기억장치/학습자 실행은 미수행이다. 표와 작은 정수 검산은 언어 실행 검증을 대체하지 않는다.

등록4성공/1실패, used6; 조회1/out2 뒤0/out2. grid 둘째 행의 별도 복사본은 [2,4,7], 비교3회, 첫7 위치1→2이며 원본 행은 유지된다.
