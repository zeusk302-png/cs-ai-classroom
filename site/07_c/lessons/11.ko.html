소단원 11.1

재귀의 종료·스택

작은 문제를 계속 부르면 어디에서 멈추고 어떤 순서로 돌아올까?

준비 개념과 학습 목표

준비 개념

  • 함수 인수와 return
  • if조건과 정수

학습 목표

  • 종료조건과 감소량을 연결한다
  • 호출과 반환 순서를 구분한다
  • 개념 스택과 실제 메모리 한계를 구별한다

작아지는 입력과 바닥

재귀는 함수가 자신을 직접 또는 다른 호출을 통해 다시 호출하는 구조다. 종료조건에 도달할 수 있는 입력 범위와 감소량이 필요하다. 바닥 조건을 써 놓았어도 입력이 그쪽으로 움직이지 않으면 종료를 설명할 수 없다.

여기서는 내장 int의0부터100까지만 받는 합계 함수로 범위를 한정한다. 이 범위의 최대 합5050은 C가 보장하는 최소 int최댓값32767 안에 있다. 큰 입력의 signed overflow를 결과 계산으로 정당화하지 않는다.

호출은 기다리고 반환은 돌아온다

sum(3)이3+sum(2)를 계산하려면 안쪽 sum(2)가 값을 줄 때까지 기다린다. 개념 그림에서 호출별 n과 돌아갈 위치를 쌓고 바닥에서 값을 돌려준다. 재귀 진입의 자동 객체는 각 진입에 별도 인스턴스가 있다.

흔히 호출 스택이라고 설명하지만 C언어가 모든 구현에 같은 프레임 바이트나 무한 깊이를 약속하지 않는다. 컴파일러가 호출을 최적화할 수도 있다. 아래 활성호출 수는 소스수준 개념모형이며 실제 메모리측정이 아니다.

범위와 실패를 먼저 처리한다

범위 밖 입력은-1을 오류 표시로 돌려주는 자체 계약을 쓴다. 허용 합은0 이상이므로 이 예제에서는 구별된다. 이 방식이 모든 함수의 오류정책이라는 뜻은 아니다.

종료와 메모리는 별개다. 수학적으로 언젠가 끝나더라도 실행환경의 자원이 먼저 부족할 수 있다. 작은 사례를 손으로 추적한 후 실제 실습에서 입력·컴파일 옵션·실행결과를 따로 기록한다. 본문 코드는 실행하지 않았다.

중간 과정을 따라가는 예제

다음 코드에서 sum(3)의 호출과 반환, 최대 개념 활성호출을 추적하라. 

int sum(int n) {
    if (n < 0 || n > 100) return -1;
    if (n == 0) return 0;
    return n + sum(n - 1);
}
  1. 호출n은3→2→1→0으로 매번1줄어0에 도달한다.
  2. 반환은0→1+0=1→2+1=3→3+3=6이다.
  3. 바닥sum(0)에서 소스수준 활성호출은4개다.

합6,최대4개 개념호출이다. 실제 스택바이트나 컴파일러 실행기록은 아니다.

종이와 본문으로 직접 해보기

sum(0),sum(-1),sum(4)를 각각 추적하라.

힌트 보기

범위검사가 먼저이고0은 허용값이다.

풀이 보기

0→0,-1→오류표시-1,4→4+3+2+1+0=10이며 최대 개념호출5개다.

오해와 반례

종료 if문만 있으면 모든 입력에서 재귀가 안전하다.

종료로 가는 감소량·입력범위·산술범위·실행자원 조건도 필요하다. 음수에서 n-1을 계속하는 설계는0으로 가지 않는다.

소단원 11.2

동적 node와 연결

노드의 값과 다음 노드의 주소는 같은 정보일까?

준비 개념과 학습 목표

준비 개념

  • struct와 포인터
  • malloc 실패와 초기화

학습 목표

  • 자기 포인터를 가진 구조체를 설명한다
  • 실패 때 기존 머리를 보존한다
  • 노드 수명과 호출자 포인터를 구별한다

값과 링크를 나눈다

struct Node에는 value와 next가 있다. next는 다음 노드의 주소이며 값이 같다 해도 같은 노드라는 뜻은 아니다. 마지막next=NULL로 끝나는 표현을 선택한다. NULL은 정상 종료표시이지 읽을 수 있는 노드가 아니다.

자기 구조체 값을 직접 멤버로 넣을 수는 없지만 자기 구조체를 가리키는 포인터는 넣을 수 있다. 동적노드가 주소순서대로 연속 배치된다는 보장은 없으며 숫자주소 대신 A/B같은 라벨로 그려도 연결을 추적할 수 있다.

할당 성공 뒤 초기화한다

malloc(sizeof *p)는 노드 한 개의 필요한 크기를 타입에 맞춰 요청한다. 실패하면NULL을 반환할 수 있고 성공한 객체의 초기값은 indeterminate이므로 value/next를 읽기전에 설정한다. sizeof는 실제 필드 크기·padding을 반영하므로 임의로8바이트라 단정하지 않는다.

prepend는 새노드가 준비되면 기존head를next에 넣고 새주소를 반환한다. malloc실패이면 새노드는 없고 기존head도 변경하지 않는 계약이다. 실패반환을 그대로head에 대입하면 기존목록을 잃을 수 있으므로 임시변수로 확인한다.

누가 머리를 바꾸는가

함수에 포인터 값을 전달하면 함수의 매개변수는 호출자 변수와 별개다. 새 머리를 반환하고 호출자가 받아야 자신의 head가 바뀐다. Node**로 갱신하는 다른 설계도 가능하지만 이 예제에서는 반환 방식을 쓴다.

동적할당 객체는 함수가 끝났다는 이유만으로 사라지지 않는다. 반면 함수의 지역Node주소를 반환하면 그자동객체의 수명종료 뒤 접근할 수 없다. 모든 동적노드의 해제 책임을 하나의 소유자에게 두고 공유별칭은 별도관리한다.

중간 과정을 따라가는 예제

기존 head=A(value7,next=NULL)인 살아있는 동적목록에 아래 prepend(head,3)가 성공했다고 가정한다. 호출자가 결과를 tmp로 받은 뒤 head=tmp로 갱신한다. 

#include <stdlib.h>
struct Node { int value; struct Node *next; };
static struct Node *prepend(struct Node *head, int value) {
    struct Node *p = malloc(sizeof *p);
    if (p == NULL) return NULL;
    p->value = value;
    p->next = head;
    return p;
}
  1. 새노드B가 할당되고 B.value=3이다.
  2. B.next=A이고 반환주소는B다. 기존A의값과next는변경하지않는다.
  3. 호출자가head=B로저장하면 목록값은3→7이다.

B→A→NULL 두노드이며 호출자대입이 새머리를 반영한다. 물리주소와구조체크기는측정하지 않았다.

종이와 본문으로 직접 해보기

같은 호출이NULL을 반환하면 tmp를검사한뒤 기존head를 유지해야하는 이유와코드를적어라.

힌트 보기

새노드없는실패와빈기존목록을구별한다.

풀이 보기

예: struct Node *tmp=prepend(head,3); if(tmp!=NULL) head=tmp; 실패면head=A로유지해기존7노드의소유권을잃지않는다.

오해와 반례

head=prepend(head,3)는 실패해도 기존목록을 보존한다.

이계약의NULL실패를head에직접대입하면기존주소를잃을수있다. 임시반환을 검사하고 기존head를 보존한다.

소단원 11.3

순회·해제의 설계

노드를 먼저 지운 뒤 그 노드의 next를 읽으면 어떤 문제가 생길까?

준비 개념과 학습 목표

준비 개념

  • next와NULL
  • 객체수명과free

학습 목표

  • NULL검사후살아있는노드를순회한다
  • 다음주소를해제전에보존한다
  • 소유권·별칭·순환조건을명시한다

살아있는 유한 사슬을 전제한다

순회는 현재 p가 NULL이 아닌 동안 노드의 값을 확인하고 p=p->next로 이동한다. 모든 링크가 살아있는 노드 또는 NULL이고 사슬이 유한·비순환이라는 조건을 전제한다. 순환이면 NULL을 못 만나며 해제된 링크이면 NULL 검사만으로 안전해지지 않는다.

여기서는 소유자가 유일하고 각 노드를 한 번만 malloc했으며 동시 변경과 외부 별칭이 없는 목록을 쓴다. 이 조건을 벗어난 공유 꼬리·순환·다른 스레드 변경은 별도 소유권과 동기화 설계가 필요하다.

다음을 먼저 저장한다

free(p) 후 p->next를 읽으면 이미 수명이 끝난 객체에 접근한다. 다음 주소를 먼저 next=p->next로 저장하고 free(p), p=next 순으로 진행한다. 다음 노드는 아직 살아있다는 조건이 필요하다.

free는 그 동적 객체의 저장 공간을 회수 가능하게 만든다. 그 객체를 가리키던 포인터 값은 수명 끝 뒤 indeterminate이 되므로 해제된 별칭을 비교·역참조해 확인하지 않는다. 변수에 NULL을 대입하는 것은 다른 별칭까지 자동으로 고치는 것이 아니다.

호출자 머리도 끝상태로 만든다

해제 함수는 새 머리 NULL을 반환하고 호출자가 head=destroy(head)로 저장하도록 한다. 함수 내 로컬 p만 NULL이 되어도 호출자 head를 자동 갱신하는 것은 아니다. 외부에 빌려준 노드 주소는 해제 전에 사용 종료를 합의해야 한다.

빈 목록 해제는 루프가 한 번도 돌지 않고 NULL을 반환한다. 같은 노드를 두 번 free하면 정의되지 않은 동작이며 이미 해제된 head를 재사용해서 확인하는 방법은 안전한 테스트가 아니다. 실제 코드는 도구 검증도 필요하지만 여기서는 종이 추적만 한다.

중간 과정을 따라가는 예제

독점소유·비순환·살아있는 동적목록A2→B5→C8→NULL을 다음코드로 해제한다고가정하고순서를추적하라. 

static struct Node *destroy(struct Node *p) {
    while (p != NULL) {
        struct Node *next = p->next;
        free(p);
        p = next;
    }
    return NULL;
}
/* caller: head = destroy(head); */
  1. p=A에서next=B를보존후A를free,p=B로갱신한다.
  2. B에서C보존후B해제,C에서NULL보존후C해제다.
  3. NULL에서종료하고호출자head에NULL을저장한다. 총3free이며어느해제된노드의next도읽지않는다.

해제A→B→C,호출자head=NULL이다. 노드별칭·순환·동시접근없는계약에서의예측이다.

소단원 11.4

자료구조 과목의 준비

같은 값 목록을 배열과 연결목록으로 만들면 접근비용도 같을까?

준비 개념과 학습 목표

준비 개념

  • 순회·머리삽입
  • 연산계약과소유권

학습 목표

  • 인터페이스와표현을구분한다
  • 비용에위치탐색·할당조건을포함한다
  • 표현불변식과경계사례를적는다

무엇을 할지와 어떻게 담을지

스택은 최근 넣은 값을 먼저 꺼내는 연산 규칙이고 연결 목록은 값과 next의 표현이다. 같은 스택을 배열로도 만들 수 있다. 클라이언트가 내부 next를 마음대로 바꾸면 연산 계약이 깨질 수 있어 인터페이스 뒤에 표현을 숨기는 설계를 배운다.

CMU15-122는 C0 연결 구조로 스택·큐와 표현 불변식을 설명한다. 이 본문의 NULL 종료 C목록·수동 free는 원문의 dummy 노드·자동 회수와 다르다. 개념을 참고하되 코드와 소유권 조건을 섞지 않는다.

연산비용에는 조건을 붙인다

살아있는 목록에서 이미 알고 있는 머리 앞에 노드를 연결하는 포인터 대입 수는 상수다. 하지만 할당자 비용까지 항상 상수라고 보장하거나 임의 위치 검색이 무료라고 가정하지 않는다.

0부터 세는 i번째 값은 앞에서 i번 next 이동해 도달한다. 배열의 유효 인덱스 접근과 달리 순차 위치 탐색이 필요하다. 삭제하려는 노드와 이전 노드를 이미 아는 경우와 값으로 찾아야 하는 경우의 전체 비용도 다르다.

불변식과 작은 반례를 준비한다

NULL 종료 목록의 불변식은 유한·비순환, 각 next가 살아있는 다음 노드 또는 NULL, 각 동적 노드의 독점 소유와 해제 책임이다. 연산 전후 이 조건이 유지되는지 그림으로 확인한다.

빈 목록·한 노드·머리 삭제·없는 값·할당 실패·공유 별칭·순환을 계약의 허용/거절 조건으로 나눈다. 안전성·값 정확성·비용은 다른 검증이다. 자료구조 과목에서는 이 계약과 추론을 더 많은 표현에 적용한다.

중간 과정을 따라가는 예제

유효한A4→B9→C6→D2→NULL에서0기준인덱스3의값을찾는다. 머리부터next이동수를세고새E7을머리앞에연결한후인덱스3도비교하라. E할당은성공했다.

  1. 원래0=A/1=B/2=C/3=D이므로next3번·값2다.
  2. E.next=A,head=E이면값순서7,4,9,6,2다.
  3. 새0=E/1=A/2=B/3=C이므로next3번·값6이다.

같은인덱스3이2→6으로변했다. 머리앞삽입의링크대입과인덱스검색을별도로센다.
