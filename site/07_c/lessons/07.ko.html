소단원 7.1

주소·역참조·null

상자에 들어 있는 숫자와 그 상자를 가리키는 표시는 같은 종류의 값일까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: int x=4는 정수 객체 x의 값을 초기화한다. 주소를 그린 화살표는 x의 정수 값과 별개이다.

  • int *p라는 선언의 *와 식 *p의 역할을 구분한다. 앞은 포인터형 선언, 뒤는 가리킨 객체 지정이다.

  • 자가진단: p=&x 후 *p=9는 p가 아니라 x의 값을 9로 바꾼다. x와 p를 두 상자로 그려라.

학습 목표

  • 객체·주소·포인터 객체·가리킨 값을 구별한다.

  • 주소 취득과 읽기·쓰기 역참조를 추적한다.

  • null 검사와 실제 유효성 계약의 차이를 설명한다.

화살표 자체를 바꾸려면 어느 상자의 주소를 넘겨야 할까?

새 int x=3,y=8; int *p=&x; int **slot=&p;를 둔다. x/y는 int 객체이고 p는 int 포인터 객체, slot은 그 포인터 객체 p를 가리킨다. *slot=&y는 p의 저장 값을 바꾼다. **slot=11은 새 p가 가리키는 y를 바꾼다. 각 *가 한 층을 내려간다고 그림을 그리면 주소와 값의 변경을 분리할 수 있다.

이중 포인터는 특별한 소유권이나 수명 연장 기능이 아니다. slot은 살아 있고 수정 가능한 p를, p는 필요한 순간 살아 있고 수정 가능한 int를 가리켜야 한다. slot!=NULL만 검사해도 *slot이 NULL일 수 있다. 아래는 같은 블록 안의 정상 객체를 사용하며 특정 실제 주소 숫자나 포인터 바이트 수를 가정하지 않는다.

먼저 확인할 개념
  • 값으로 전달한 포인터

    지역 포인터만 바꾸는 함수와 호출자 포인터 객체에 쓰는 함수를 비교한다.

  • 참조와 별도 칸

    대상 공유와 참조를 담는 칸 변경의 차이를 C 객체 그림으로 옮긴다.

주소를 담는 객체도 별도 객체다

int x=4; int *p=&x;에서 x는 정수 객체이고 p는 int를 가리키는 포인터 값을 담는 별도 객체이다. &x는 x의 주소를 얻고 p가 그 값을 담는다. p와 x가 같은 객체가 되는 것도, x의 값 4를 p에 복사하는 것도 아니다. 주소 표시는 그림에서 X라는 기호로 쓰면 충분하다.

표현식 *p는 p가 가리킨 int 객체를 지정한다. int y=*p는 x의 현재 값을 읽어서 새 정수 y를 초기화한다. *p=9는 그 객체에 쓰므로 x가 9가 된다. p=&y는 포인터 p에 새 주소를 대입하며 x는 바뀌지 않는다. 주소값과 가리킨 값을 항상 다른 열에 기록한다.

int x = 4;
int *p = &x;
int y = *p;
*p = 9;
p = &y;
*p = 6;

null은 가리킬 객체가 없다는 표지

헤더 <stddef.h>의 NULL을 포인터 초기화에 사용할 수 있다. int *p=NULL은 초기화하지 않은 포인터와 다르며 p==NULL로 검사할 수 있다. null 포인터는 어떤 유효 객체를 가리키는 주소와도 같지 않도록 언어가 정한 특별한 포인터 값이다.

null을 실제 메모리 주소 숫자 0 또는 모든 비트가 0이라는 표현 보장으로 이해하지 않는다. *p로 null을 읽거나 쓰는 것은 허용되지 않는다. if(p!=NULL) 검사로 null 경로를 막을 수 있지만, p가 이미 수명이 끝난 객체를 가리키거나 엉뚱한 값을 가지면 이 검사만으로 접근을 정당화할 수 없다.

주소 비유의 경계

집 주소 비유는 주소와 집 안 내용을 구분하는 데 도움이 된다. 실제 C에서는 타입에 맞는 살아 있는 객체, 정렬 조건, 범위와 허용된 접근 형이 필요하다. 임의 숫자를 주소로 생각하고 캐스팅한다고 원하는 객체가 생기지 않는다. 이 단원은 그런 변환을 구현하지 않는다.

주소 출력이 필요하면 printf의 %p에 (void *)p를 전달하는 등 형식 계약을 맞춘다. 그러나 출력 모양과 주소 숫자, 포인터 크기, 객체의 실제 배치는 구현에 따라 다를 수 있다. 본문에서는 구체적인 주소값이나 항상 8바이트라는 가정을 쓰지 않는다.

slot의 값은 계속 &p다. 첫 쓰기는 p에 새 주소를 저장하고 둘째 쓰기는 p를 따라간 int에 저장한다. slot 자체의 값이나 x는 이 두 문장으로 변경되지 않는다.

중간 과정을 따라가는 예제

위 정상 코드에서 x, y, p의 마지막 상태를 종이에서 구한다. 모든 객체는 같은 블록 안에서 살아 있고 추가 동시 접근은 없다고 가정한다.

  1. 처음 x는 4이고 p는 X를 가리킨다. y=*p는 값 4를 새 y에 저장한다.

  2. *p=9는 X의 정수 값을 바꾸어 x=9가 된다. y=4는 별도의 복사된 값이다.

  3. p=&y는 화살표를 Y로 옮긴다. 이 대입은 x나 y의 값에 쓰지 않는다.

  4. *p=6은 Y의 값을 바꾸므로 마지막 x=9, y=6, p는 &y이다.

x=9, y=6이다. p는 숫자 6을 담는 정수 변수가 아니라 y를 가리키는 포인터이다. 실제 실행 출력이 아닌 종이 결과이다.

조건을 바꾸어 비교하기

지역 포인터 교체와 호출자 교체

각각 새 p=&x에서 f(int *r){r=&y;}와 g(int **r){*r=&y;}의 본문을 비교하는 종이 모형이다. y는 두 함수에 별도 유효 경로로 보이는 살아 있는 객체이며 실제 코드를 구현하지 않는다.

  1. f에 p를 전달하면 지역 r만 y 주소로 바뀌고 호출자 p는 x다.

  2. g에 &p를 전달하면 *r이 호출자의 p를 지정해 p가 y로 바뀐다.

  3. 두 함수 모두 y의 정수 값을 바꾸는 문장은 없다.

주소를 담는 어떤 객체를 변경했는지가 다르다.

비교할 점

포인터 인수도 값 전달이지만 그 값이 호출자 포인터 객체의 주소일 수 있다.

두 번째 null 검사

살아 있는 int *p=NULL; int **slot=&p;에서 slot!=NULL은 참이다.

  1. slot은 실제 p 객체를 가리킨다.

  2. *slot을 읽으면 초기화된 null 포인터 값이다.

  3. **slot의 int 읽기에는 유효 대상이 없으므로 허용되지 않는다.

outer null 검사만으로 inner 역참조를 허용하지 않는다.

비교할 점

null 검사와 타입/수명/대상 계약은 각 층에 필요하다.

종이와 본문으로 직접 해보기

int a=2, b=5; int *p=&a; int *r=p; p=&b; *r=8;를 종이에 추적한다. a, b와 두 화살표를 적어라.

힌트 보기

r=p는 포인터 값의 복사이다. 이후 p의 재대입이 r의 값을 함께 바꾸지는 않는다.

풀이 보기

r은 계속 &a이고 p는 &b이다. *r=8로 a=8, b=5이다. 포인터 값 복사와 같은 대상의 변경을 분리하면 별칭을 설명할 수 있다.

오해와 반례

포인터가 null이 아니면 언제나 역참조해도 되고, 포인터 복사 후 두 포인터는 하나로 묶인다.

수명이 끝난 객체를 가리키던 포인터를 null 검사로 고칠 수 없다. p의 주소 재대입은 별도 포인터 r을 갱신하지 않는다. 유효성은 null 여부보다 더 많은 조건을 갖는다.

자기점검

p=&x 뒤 *p=3은 어느 객체를 바꾸는가?

답과 이유 보기

x를 바꾼다.

*p가 x를 지정하므로 포인터 p 자체의 저장값에는 대입하지 않는다.

아니다. null로 초기화했다.

보장하지 않는다.

연습 1 · 값과 상태 예측

새 x=3, y=8, p=&x, slot=&p에서 **slot=6; *slot=&y; **slot=9;를 순서대로 추적하라.

힌트 1

첫 문장은 아직 x를 지정한다.

힌트 2

둘째는 포인터 객체를 바꾼다.

풀이와 답 확인

  1. 첫 문장 뒤 x=6, y=8이다.

  2. 둘째 문장 뒤 p=&y이며 마지막 문장 뒤 y=9다.

x=6, y=9, p=&y, slot=&p다.

흔한 오답에서 다시 생각하기

p 주소를 바꾸면 이전 x도 y와 같은 값이 된다.

주소 변경은 두 int 객체를 합치지 않는다.

연습 2 · 오류 찾아 고치기

if(slot!=NULL) **slot=4;가 모든 포인터 상태에서 안전하다고 했다.

힌트 1

slot의 대상이 살아 있는 p인지도 확인한다.

힌트 2

그 p의 현재 대상까지 확인한다.

풀이와 답 확인

  1. 유효 slot이면 *slot의 초기화된 값을 읽을 수 있다.

  2. 그 값이 null인지 분기하고, 실제 수정 가능한 int 대상의 수명/타입 계약을 별도로 요구한다.

한 번의 null 검사는 두 층의 유효성 증명이 아니다.

흔한 오답에서 다시 생각하기

null이 아닌 값은 모두 접근 가능한 주소다.

null과 수명·실제 객체·수정 권한은 다른 조건이다.

연습 3 · 직접 만들어 보기

호출자 p를 y의 주소로 바꾸고 y에는 7을 쓰는 두 단계 설계를 적어라.

힌트 1

포인터 객체 p의 주소를 전달한다.

힌트 2

첫 갱신 뒤 새로운 대상을 쓴다.

풀이와 답 확인

  1. 살아 있는 p의 주소 &p와 살아 있는 수정 가능 y의 주소를 함수에 제공한다.

  2. *slot=&y 후 **slot=7을 수행한다.

호출자는 p=&y와 y=7을 관찰한다. x는 보존된다.

흔한 오답에서 다시 생각하기

int **는 두 int를 담은 배열이다.

두 층의 포인터형은 배열 길이나 복수 int 저장을 선언하지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

int *p=NULL에서 &*p라는 표현 자체와 int v=*p를 비교하라.

힌트 1

C11의 &와 * 결합 예외를 확인한다.

힌트 2

읽기 역참조와 주소 표현식을 구별한다.

풀이와 답 확인

  1. &*p는 두 연산이 평가되지 않는 결합 규칙으로 p의 null 값을 얻는다.

  2. int v=*p는 평가되는 null 역참조라 UB다.

같은 글자 *가 있어도 평가 문맥이 다르다.

&*p가 가능하니 null의 int 값도 읽을 수 있다.

결합 예외는 대상 객체를 만들거나 null 역참조를 일반 허용하지 않는다.

소단원 7.2

포인터형과 const

const가 붙은 포인터는 주소를 바꾸지 못한다는 뜻일까, 숫자를 바꾸지 못한다는 뜻일까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: p=&x는 포인터 객체 p에 쓰고 *p=7은 가리킨 정수 객체에 쓴다.

  • 초기화는 새 객체의 초기 값을 정하는 일이고, 초기화 뒤 대입과 구별한다.

  • 자가진단: int x=2; const int *p=&x에서 p는 x를 읽을 수 있다. x 자체가 const로 선언된 것은 아니다.

학습 목표

  • const int *와 int *const의 변경 층을 구별한다.

  • 읽기 전용 경로와 원래 const 객체를 구분한다.

  • 허용 대입·제약 위반·미정의동작을 종이로 분류한다.

읽기 전용 관찰자는 대상의 옛 값을 기억할까?

새 int value=4; const int *view=&value; int *edit=&value; int snapshot=*view;를 둔다. snapshot은 현재 정수 4를 복사한 별도 객체다. view는 읽기 전용 경로로 현재 value를 관찰한다. *edit=9 후 snapshot은 4이고 *view는 9다. const 접근 경로와 값 복사 스냅샷은 다른 계약이다.

객체 자체가 const로 정의된 경우와 수정 가능한 객체를 const 경로로 읽는 경우도 구별한다. C11에서 원래 const 객체에 cast 후 쓰기는 UB다. 원래 수정 가능한 value라면 const 경로에서 얻은 포인터를 적절히 원래 int *로 바꿔 쓰는 것 자체가 원래 const 객체 수정 규칙을 위반하지는 않는다. 그렇다고 API의 업무상 읽기 전용 의도를 무시해도 된다는 뜻은 아니다.

먼저 확인할 개념
  • const의 변경 층

    포인터 객체와 가리킨 문자의 const를 int 경로로 연결한다.

  • 값 복사와 대상 변경

    별도 정수 반환/복사와 주소를 통한 관찰을 구별한다.

가리킨 형이 접근의 의미를 정한다

int *p는 int 객체를 지정할 포인터형이다. 같은 비트 주소처럼 보여도 double *나 int **는 가리킨 형과 사용 계약이 다르다. 캐스팅은 실제 객체의 형·정렬·수명을 바꾸는 공사가 아니다. 이 단원은 서로 맞는 int 객체와 int 포인터만 정상 예제로 쓴다.

const int *p는 p를 통해 얻은 정수 lvalue가 const인 경로이다. 따라서 *p=7은 허용된 수정 대입이 아니다. p=&y처럼 포인터 자체의 주소는 다시 대입할 수 있다. int const *도 같은 뜻이며 const 위치를 단순 글자 순서 대신 가리킨 형과 포인터 층으로 읽는다.

포인터 자체를 고정할 수도 있다

int *const p=&x에서는 포인터 객체 p 자체가 const이다. 초기화 뒤 p=&y를 할 수 없지만 가리킨 int가 수정 가능한 x이면 *p=7은 가능하다. const int *const p=&x라면 이 경로에서는 주소도 바꾸지 못하고 가리킨 정수에도 쓰지 못한다.

여기서 못 한다는 대입은 C의 수정 가능한 lvalue 조건을 위반하는 제약 위반이다. 적합한 구현은 진단해야 하지만 특정 컴파일러의 메시지나 빌드 실패 방식을 실측한 것은 아니다. 이를 정상 실행 후 어떤 값이 나오는 문제로 처리하지 않는다.

읽기 전용 경로는 모든 별칭을 봉인하지 않는다

int x=2; const int *p=&x; 뒤 x=9는 x 자체가 수정 가능한 객체라 가능하다. p로 읽으면 9를 읽는다. const 경로를 만들었다고 다른 정상 경로에서 x를 바꿀 수 없게 되는 것은 아니다. 동시성이나 불변 스냅샷을 보장하는 기능도 아니다.

반면 const int x=2로 객체 자체를 const로 정의했다면, const를 제거한 형으로 캐스팅해 그 객체에 쓰려는 시도는 미정의동작이다. 캐스팅 문법이 통과하는지와 수정이 적법한지는 별개이다. 이 잘못된 쓰기는 실행하거나 특정 결과를 예상하지 않는다.

중간 과정을 따라가는 예제

같은 블록의 int x=2, y=5; const int *read=&x; int *const fixed=&x;에서 순서대로 x=3; read=&y; *fixed=7;을 추적한다. 정상 문장만 대상으로 한다.

  1. read의 가리킨 형은 const int여서 읽기 경로이고 read 자체는 재대입 가능하다. fixed의 주소는 고정되지만 가리킨 x는 수정 가능하다.

  2. x=3 뒤 read로 x를 읽으면 3이다. 객체 x의 선언에는 const가 없다.

  3. read=&y 뒤 read는 5인 y를 가리킨다. fixed는 여전히 x를 가리킨다.

  4. *fixed=7 뒤 x=7, y=5이다. read의 관찰값은 5, *fixed는 7이다.

read와 fixed의 const가 다른 층에 작용한다. 정상 경로의 종이 결과 x=7, y=5이며 코드 컴파일은 하지 않았다.

조건을 바꾸어 비교하기

원래 객체가 다른 두 cast

각각 독립해서 int x=4; const int *p=&x;와 const int z=4; const int *q=&z;를 둔다. (int *)로 바꾸어 7을 쓰려 한다.

  1. x 자체는 수정 가능 객체이고 p의 const는 접근 경로다.

  2. z 자체는 const로 정의된 객체다.

  3. 둘째 z에 대한 쓰기는 cast 여부와 무관하게 UB다.

첫 경우의 타입 변환과 원래 객체 수정은 가능하나, 둘째의 정상 결과는 예측하지 않는다.

비교할 점

cast 문법 성공과 대상 계약을 분리한다.

서로 다른 고정 층

int x=4,y=9; int *const fixed=&x; const int *moving=&x;를 둔다.

  1. *fixed=6은 수정 가능 x에 쓰므로 허용된다.

  2. moving=&y는 포인터 moving의 재대입이라 허용된다.

  3. fixed=&y와 *moving=7은 각각 const 포인터/const int lvalue 대입 제약 위반이다.

허용된 두 문장 뒤 x=6, y=9다. moving은 y를 가리키고 fixed는 x를 가리킨다.

풀이 보기

오해와 반례

const를 제거하는 cast를 쓰면 const 객체도 정상적으로 바꿀 수 있고 const 포인터는 모든 쓰기를 막는다.

원래 const 객체의 쓰기는 cast로 정당화되지 않는다. int *const의 경우 주소만 고정하고 수정 가능한 대상에 대한 *쓰기는 허용한다. 변경 층과 원래 객체 선언을 확인해야 한다.

소단원 7.3

배열·포인터 산술

포인터에 1을 더하면 메모리의 한 바이트를 옮기는 걸까, 다음 원소를 가리키는 걸까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: int a[3]={10,20,30}은 세 int 원소의 배열이다. 원소 위치는 0,1,2이다.

  • 대부분의 식에서 배열 식은 첫 원소를 가리키는 포인터로 변환되지만 sizeof나 단항 & 등의 예외가 있다.

  • 자가진단: a+1은 두 번째 int 원소를 가리키는 포인터이고 *(a+1)은 그 원소를 지정한다.

학습 목표

  • 원소 단위 포인터 산술과 한 칸 뒤 경계를 구분한다.

  • 같은 배열 안 포인터 차의 조건과 단위를 설명한다.

  • 배열형·첫 원소 포인터·전체 배열 포인터를 구분한다.

배열의 일부만 순회할 때 끝 표지는 실제 배열의 끝과 같아야 할까?

새 int a[5]={2,4,6,8,10}; int *begin=a+1; int *end=a+4;를 둔다. 선택 구간은 [begin,end)이며 값4/6/8 세 개다. end는 이 업무 구간의 끝이지만 실제 배열의 위치4 원소10을 가리킨다. 실제 one-past인 a+5와는 다르다.

begin/end가 같은 실제 배열의 허용 범위에 있고 차 3이 ptrdiff_t에 표현 가능하므로 end−begin은 3이다. 순회는 p!=end를 확인한 뒤 읽고 증가한다. 마지막 읽은 위치 3에서 증가한 p는 4가 되어 종료되며 위치 4의 10은 업무 구간에서 읽지 않는다. 대상 밖 주소를 먼저 만들어 검사하는 방식은 사용하지 않는다.

먼저 확인할 개념
  • 실제 경계와 논리 경계

    구간 끝이 실제 원소일 수 있지만 업무 읽기는 거부한다.

  • 가리킨 형의 이동 단위

    원소 포인터와 행/전체 배열 포인터의 단위를 분리한다.

배열은 포인터 객체와 같은 형이 아니다

배열 a 자체는 세 int를 담은 배열 객체이다. int *p=a에서는 a가 첫 int 원소 포인터로 변환되어 p를 초기화한다. sizeof a는 전체 배열 크기이고 sizeof p는 포인터 객체 크기이다. 두 크기가 우연히 같을 수 있어도 같은 형이라는 근거는 아니다.

&a의 형은 int (*)[3]으로 세 int 배열을 가리키는 포인터이고, &a[0]의 형은 int *이다. 첫 저장 위치를 관련해서 가리키더라도 가리킨 형과 산술의 단위가 다르다. 선언 모양이 어려우면 배열 전체 상자와 원소 상자에 각각 화살표를 그려라.

한 칸은 가리킨 형의 원소 한 개다

p가 a[0]을 가리킬 때 p+1은 a[1]을 가리킨다. int의 크기를 무조건 4바이트로 가정하지 않는다. sizeof(int)를 s바이트라 부르면 인접 원소의 저장 간격은 s이다. 원소 위치로 계산하면 구체적인 s값을 몰라도 결과를 구할 수 있다.

a+3은 마지막 원소 바로 뒤의 one-past 포인터로 만들 수 있고 범위 끝 표지로 쓸 수 있다. 그러나 *(a+3)을 평가해 읽거나 쓰면 허용되지 않는다. a+4는 역참조하지 않아도 이 배열 산술 범위를 벗어난 형성이어서 미정의동작이다. 경계를 넘은 뒤 되돌리는 식도 그 먼저 발생한 위반을 없애지 못한다.

뺄셈은 같은 배열의 위치 차다

q=&a[2], p=&a[0]이면 q−p는 원소 위치 차 2이다. 결과형 ptrdiff_t는 <stddef.h>에 선언된 부호 있는 정수형이며 표현 가능한 결과라는 조건도 필요하다. 바이트 간격 2s와 원소 차 2를 구분한다.

서로 다른 배열의 포인터를 빼서 메모리 거리처럼 사용하는 것은 같은 배열 조건을 위반한다. 실제 배치가 가까워 보이거나 출력 숫자로 차를 계산할 수 있어 보인다고 정당해지지 않는다. 다차원 배열의 한 행 포인터 산술도 그 행 배열의 경계 안에서 검토한다.

중간 과정을 따라가는 예제

<stddef.h>를 포함했다고 가정하고 int a[3]={10,20,30}; int *p=a; int *end=a+3;에서 p+2, end−p, *(end−1), *end의 적법성과 값을 각각 독립적으로 분류한다.

  1. p는 위치 0이고 p+2는 같은 배열 위치 2라 허용된다. 그 위치의 값은 30이다.

  2. end는 허용된 한 칸 뒤 위치 3이고 end−p는 같은 배열 경계끼리의 차 3이다. 이 작은 결과는 ptrdiff_t에 표현 가능하다.

  3. end−1은 위치 2로 되돌아와 *(end−1)은 정상 읽기이며 30이다.

  4. *end는 원소가 없는 한 칸 뒤 포인터의 역참조 평가여서 미정의동작이다. 출력값을 지정하거나 다른 식의 정상 결과와 함께 실행하지 않는다.

허용 포인터 p+2, 정상 차 3, 정상 읽기 30과 미정의동작 *end를 분리한다. 전체 문장을 실행해 관찰한 결과가 아니다.

조건을 바꾸어 비교하기

빈 부분 구간

같은 a에서 begin=end=a+2로 두고 위 순회와 차를 구한다.

  1. 두 포인터는 살아 있는 같은 원소를 지정한다.

  2. 처음 검사부터 같으므로 읽기와 증가가 없다.

  3. end−begin=0이다.

실제 저장 칸이 존재해도 선택 구간은 빈 상태다.

비교할 점

빈 논리 구간이 0길이 C 배열 선언을 요구하지 않는다.

전체 배열 포인터의 한 칸

int (*whole)[5]=&a와 int *element=a를 비교한다.

  1. whole+1은 길이 1 배열처럼 취급한 전체 a 객체의 one-past다.

  2. element+1은 a의 둘째 int 객체다.

  3. whole의 한 칸은 다섯 int 배열, element의 한 칸은 int다.

같은 첫 저장 위치를 관련해서 가리켜도 이동 타입이 다르다.

비교할 점

주소의 겉 숫자만으로 산술 단위를 정하지 않는다.

종이와 본문으로 직접 해보기

int b[2]={4,7};에서 b, b+1, b+2, b+3을 형성하는 경우와 *(b+2)를 읽는 경우를 각각 판정하라. b+2−b의 차도 구한다.

힌트 보기

원소 위치 0·1과 끝 표지 위치 2까지만 허용한다. 형성과 읽기를 두 열로 나눈다.

풀이 보기

b와 b+1은 원소 포인터, b+2는 허용된 한 칸 뒤 포인터이다. b+3 형성은 미정의동작, *(b+2) 읽기도 미정의동작이다. (b+2)−b는 2원소이며 바이트 차가 아니다. 허용하지 않은 식은 실행하지 않았다.

오해와 반례

역참조만 하지 않으면 배열 밖 포인터를 얼마든지 만들어도 된다.

one-past보다 더 멀거나 배열 앞의 포인터를 만드는 산술 자체가 범위 조건을 위반할 수 있다. 안전한 순회는 현재 포인터와 끝 표지가 같은 배열의 허용 범위 안에 있다는 계약을 유지해야 한다.

소단원 7.4

유효 범위와 lifetime

주소를 기억하는 메모지가 남아 있으면, 그 주소의 상자도 계속 살아 있을까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 이름을 사용할 수 있는 범위(scope)와 객체가 존재하는 시간(lifetime)은 다른 개념이다.

  • 블록의 자동 저장기간 int는 블록 실행이 끝나면 수명이 끝난다. 여기서는 가변 길이 배열이나 임시 객체는 제외한다.

  • 자가진단: 내부 블록의 int local=7 주소를 바깥 포인터에 저장해도 local의 수명은 늘어나지 않는다.

학습 목표

  • 이름의 범위와 객체의 수명을 구별한다.

  • 자동·정적 저장기간의 차이를 주소 보존과 연결한다.

  • 수명 종료 뒤 포인터 사용을 종이로 판단한다.

static 주소가 오래 유효하면 반환값도 예전 상태를 보존할까?

새 함수 상태를 static int shared=5로 정하고 첫 호출은 값 6으로 쓴 뒤 주소를 반환, 둘째 호출은 값 7로 쓴 뒤 같은 주소를 반환한다고 하자. int *p와 *r은 같은 살아 있는 객체의 주소다. 첫 호출 뒤 int saved=*p로 6을 복사했다면 둘째 뒤 *p와 *r은 7이지만 saved는 6이다.

정적 수명은 주소의 수명 문제를 해결하지만 값의 불변성·각 호출의 독립 결과·동시 접근 안전성을 제공하지 않는다. 반대로 자동 지역 객체를 가리키는 주소를 보관하면 그 대상의 블록 종료 때 포인터 값은 불확정이 된다. 아래는 일반 비VLA 자동 객체와 순차 호출이며 실제 스레드를 시험하지 않는다.

이름을 볼 수 없는 것과 객체가 없는 것은 다르다

scope는 소스 코드의 어느 위치에서 이름이 선언에 연결되는지를 정한다. lifetime은 실행 중 객체의 저장소가 그 객체를 위해 유지되는 기간이다. 내부 함수 호출에서 호출자의 지역 이름을 직접 쓰지 못해도, 호출자가 살아 있는 객체 주소를 매개변수로 넘겼다면 그 객체에 접근할 수 있다.

자동 저장기간의 일반적인 비가변길이 지역 객체는 연관 블록 실행이 끝날 때 수명이 끝난다. 다른 함수를 호출하는 동안 현재 블록은 중단될 뿐 끝난 것이 아니어서 객체도 살아 있다. 내부 블록이 끝나거나 함수가 반환한 뒤에는 해당 자동 객체가 계속 존재한다고 가정할 수 없다.

포인터가 대상의 시간을 늘려 주지 않는다

int *p=NULL; { int local=7; p=&local; } 형태에서 블록 안의 p는 살아 있는 local을 가리킨다. 블록이 끝나면 local의 수명이 끝나고 그 객체를 가리키거나 바로 뒤를 가리키던 포인터 값은 N1570의 규칙상 불확정(indeterminate)이 된다.

따라서 블록 뒤에 *p를 읽어서 여전히 7인지 시험하지 않는다. p!=NULL 검사도 수명을 되살리는 방법이 아니며 그 불확정 값을 정상 비교 대상으로 기대하지 않는다. p=NULL처럼 새 값을 대입하는 것은 이전 값을 읽지 않는 갱신이지만, 이미 생긴 다른 별칭도 자동으로 바뀌지는 않는다.

수명 계약은 누가 무엇을 유지하는지 명시한다

지역 static int counter=0은 이름 범위가 함수 내부여도 정적 저장기간을 가져 프로그램 실행 동안 존재한다. 반환한 주소가 자동 지역 변수의 주소와 같은 수명 문제를 갖지는 않는다. 그러나 공유 상태 재사용·동시 접근·재진입 문제까지 해결한 것은 아니다.

동적 할당 객체는 이후 malloc·free 단원에서 다룬다. 포인터 저장과 객체 소유권은 별개이므로 주소를 복사했다고 수명을 공동 연장하지 않는다. 이론 활동의 기본 계약은 단일 실행 흐름에서 객체가 살아 있는 동안 적합한 형으로만 읽거나 쓰는 것이다.

두 반환 주소는 같은 대상을 가리키므로 독립 스냅샷이 아니다. p라는 이름이 첫 호출 결과를 담았다는 사실은 공유 객체의 후속 변경을 막지 않는다.

중간 과정을 따라가는 예제

int *p=NULL; int out=0; { int local=7; p=&local; out=*p; } p=NULL;에서 각 시점의 local 수명, out 값, p 상태를 종이에 적는다. 블록 뒤에는 낡은 p값을 읽지 않는다.

  1. 초기 p는 null이고 out은0이다. 내부 블록에 들어와 local=7 객체가 초기화된다.

  2. p=&local 후 p는 살아 있는 local을 가리킨다. out=*p는 수명 안의 정상 읽기여서 out=7이다.

  3. 내부 블록 끝에서 local 수명이 종료된다. p에 저장된 대상 포인터 값은 불확정이 되어 정상 주소로 사용하지 않는다. out은 별개의 살아 있는 객체라 7을 유지한다.

  4. p=NULL은 이전 p값을 읽지 않고 새 null 값을 대입한다. 그 뒤 p는 다시 null로 확정된다.

최종 out=7, p는 null이다. local은 존재하지 않는다. 수명 종료 뒤의 잠깐 불확정 상태를 무시하고 처음부터 null이었다고 설명하면 안 된다.

조건을 바꾸어 비교하기

이름 가림과 살아 있는 바깥 객체

int outer=3; int *p=&outer; 안쪽 블록에서 int outer=8을 새로 선언하고 *p=5를 쓴다.

  1. 안쪽 이름 outer는 새 객체 8을 지정한다.

  2. p는 계속 바깥 객체를 지정하므로 *p=5가 바깥 값을 바꾼다.

  3. 안쪽 종료 뒤 바깥 outer는 5다.

이름이 잠시 보이지 않아도 바깥 객체 수명은 계속된다.

비교할 점

이름 가림은 객체 삭제나 포인터 대상 교체가 아니다.

복사한 int와 수명 종료 포인터

int saved=0; int *p=NULL,*r=NULL; 안쪽 {int local=12;p=&local;r=p;saved=*r;} 뒤 p=NULL;r=NULL;를 순서대로 수행한다.

  1. 블록 안 읽기로 saved=12를 저장한다.

  2. 블록 끝에서 local 수명이 끝나 p/r의 대상 포인터 값은 불확정이다.

  3. 두 대입은 낡은 값을 읽지 않고 새 null을 쓴다.

saved=12는 유효하고 두 포인터는 새 null이 된다.

비교할 점

p만 지워도 r가 자동으로 지워지는 것은 아니다.

포인터를 반환하거나 복사하면 지역 객체가 계속 살아 있고, 주소 숫자가 안 바뀌면 사용해도 된다.

다른 문제에 적용하기

같은 블록의 int a[5]={2,4,6,8,10}; int *cursor=a+1; int **slot=&cursor; const int *view=cursor; int snapshot=*view;를 순서대로 초기화한다. *slot=a+3; **slot=9; 뒤 cursor/view/snapshot과 배열을 보고하라. 별도로 같은 a의 [a+1,a+4) 구간을 p!=end 검사 후 읽고 증가하는 순회로 읽어 합을 구하라. 이어 안쪽 블록 {int local=12; int saved=*(&local);}의 saved를 블록 밖에서 쓰려는 계획을 수정하여 바깥 int result에 호출 중 값을 복사하라. 안쪽 주소를 보관하지 말라. 모든 정상 대상은 살아 있고 타입/수정/초기화 조건을 충족하며 실제 C 실행은 하지 않는다.

힌트 1

view에는 이전 cursor의 주소값을 복사했다. slot이 cursor를 바꿔도 view는 함께 움직이지 않는다.

힌트 2

순회는 위치1/2/3만 읽는다. 블록 안에서 바깥 result에 int를 복사하면 안쪽 주소를 반환할 필요가 없다.

풀이와 답 확인

  1. 초기 cursor/view는 위치 1의 값 4를 지정하고 snapshot=4다.

  2. *slot=a+3은 cursor만 위치 3으로 바꾸며 view는 위치 1을 유지한다. **slot=9는 a[3]을 9로 쓴다.

  3. 배열은 [2,4,6,9,10], cursor 현재값 9 / view 현재값 4 / snapshot 4다.

  4. [a+1,a+4)에서 값 4/6/9를 읽어 합은 4→10→19다. 끝 위치 4의 10은 읽지 않는다.

  5. 바깥 int result=0을 두고 안쪽 local=12가 살아 있는 동안 result=local로 복사한다. 끝난 뒤 result=12만 사용하고 local 주소는 보관하지 않는다.

  6. 포인터 그림·작은 합과 실제 C 주소/컴파일/학습자 실행을 구별한다.

a=[2,4,6,9,10], cursor는 위치 3 / view는 위치 1 / snapshot은 4다. 부분 구간 합은 19다. 바깥 result에 12를 복사하고 안쪽 주소를 보관하지 않는다.

해결한 뒤 점검할 것

  • 포인터 객체 변경과 대상 값 쓰기를 서로 다른 사건으로 적는다.

  • const view의 주소 복사가 cursor 재대입에 묶이지 않음을 설명한다.

  • 부분 구간 끝과 실제 one-past를 나눠 위치별 읽기를 보고한다.

  • 블록 안 값 복사와 블록 뒤 수명 위반 주소 사용을 구별한다.

  • 정상 종이 추적과 실제 C/학생 미수행을 유지한다.
