小節 5.1

配列の大きさと添字

5要素の配列の最後の番号が5ではなく4なのはなぜだろう？

準備する概念と学習目標

準備する概念

  • 配列は同じ要素型のオブジェクトを連続して並べた集まりである。int a[5] の a は5個の int の配列で、a[0] は最初の要素である。要素数と最後の添字は別の数である。
  • size_t は sizeof の結果を表す符号なし整数型である。sizeof は C のバイト単位で大きさを表す。1バイトが必ず8ビット、int が必ず4バイトとは仮定しない。
  • 準備確認：a[0],a[1],a[2] の3箇所の番号を書こう。最大番号は2、要素数は3である。この区別から本文の図を読める。

学習目標

  • 配列オブジェクトの大きさと有効な添字を計算する。
  • 部分初期化と未初期化の自動配列を区別する。
  • sizeof における配列オブジェクトとポインタ仮引数の違い、および VLA の条件を説明する。

オブジェクトの大きさと有効番号

この単元は C11 の公開草案 N1570 に基づく。int a[5] の要素数は5で、先頭要素からアクセスできる番号は0≤i<5である。6番目の要素 a[5] は存在しない。同じ要素型を並べるので、全体の大きさは要素数と1要素の大きさの積である。

実際の配列オブジェクト a が見える場所では sizeof a / sizeof a[0] で要素数を得る。分子と分母は同じ C バイト単位なので比は5であり、sizeof(int) の具体的な値を仮定する必要はない。宣言で定めた配列は要素を追加しようとしても自動で拡大しない。

初期化が与える値

int a[5]={4,7}; は最初の2要素を4、7、残りの int 要素を0に初期化する。int a[]={4,7}; のように要素数を省略して初期値を与えると、この例の要素数は2になる。関数内に自動記憶期間の int a[5]; だけを宣言しても、全要素が自動で0になるとはいえない。読む前に各要素へ有効な値を格納する。

この固定サイズの例では sizeof のオペランドは評価されないので、sizeof a[0] は先頭の値を読む操作ではない。一般の C11 VLA では実行時にサイズ計算が行われうるため、sizeof が常に実行時評価を行わないと一般化しない。VLA は C11 の条件付き機能であり、実行時に評価される長さは正で、同じ配列インスタンスのサイズは生存期間中に変わらない。VLA は大きな入力の記憶領域確保や失敗処理を自動で保証しない。

関数境界で長さの契約を失わない

void f(int a[5]) の a は関数仮引数規則によって int * に調整される。関数内の sizeof a は呼出し側の5要素配列ではなくポインタ型の大きさである。その比から呼出し側の長さを復元してはいけない。通常はポインタと別の size_t n を渡し、生存中の n 要素が提供される契約を明示する。

宣言に角括弧があるだけでは自動境界検査は生じない。例えば仮引数 int a[static 5] は少なくとも5要素へのアクセスを呼出し側が提供する契約であり、自動検査や小配列の拡大装置ではない。下の完全な固定配列プログラムは仮引数調整や VLA に依存しない。

#include <stdio.h>
#include <stddef.h>
int main(void) {
    int a[5] = {4, 7};
    size_t n = sizeof a / sizeof a[0];
    a[n - 1] = 9;
    printf("%zu %d %d %d\n", n, a[0], a[2], a[4]);
    return 0;
}

途中の過程をたどる例題

int a[5]={4,7} から n を計算し、最後の要素を9へ変更する。%zu は size_t を表示する。正常な出力が成功するとの仮定で予想値だけを求める。

  1. 宣言直後の値は[4,7,0,0,0]で、残りの3個の int は部分初期化規則により0である。
  2. sizeof a=5*sizeof(int)、sizeof a[0]=sizeof(int) なので n=5。特定のバイト数は仮定しない。
  3. n=5 より n−1=4。a[4]=9 は有効な最後の要素への書込みで、配列は[4,7,0,0,9]になる。
  4. 出力実引数は n=5,a[0]=4,a[2]=0,a[4]=9。%zu と3個の %d がそれぞれの型に一致する。

予想 stdout は 5 4 0 9 と改行。実際のコンパイル・実行はしていない。

紙と本文で試してみよう

int b[4]={8}; の4要素を描き、要素数、最大添字、値と sizeof b/sizeof b[0] を求めよ。void g(int b[4]) の中でも同じ式が長さを表すか判断せよ。

ヒントを見る

実際の配列オブジェクト b と、ポインタへ調整された仮引数 b を別の表に書く。

解答を見る

呼出し側の値は[8,0,0,0]、要素数4、最大添字3、配列オブジェクトの比は4。g の仮引数は int * なので比は sizeof(int *)/sizeof(int) であり、配列長の根拠ではない。ある実装で偶然4でも、一般的な復元規則にはならない。

よくある誤解と反例

a[5] という宣言があるので a[5] も配列の中にある。

宣言の5は要素数、アクセス式の5は0から数えた6番目の位置である。最後の有効位置は4。自動配列を初期化せずに読む問題も、範囲問題とは別に存在する。

理解を確かめる

int a[5]={4,7}; の a[3] の初期値は？

答えと理由を見る

0。

int 配列で省略された残りの要素は0に初期化される。

int a[5] 仮引数の sizeof a は元の配列全体の大きさか？

答えと理由を見る

違う。調整されたポインタ型の大きさである。

配列仮引数はポインタ型へ調整されるので長さは別契約で渡す。

C11 VLA を宣言する実行時の長さ0を許すと仮定してよいか？

答えと理由を見る

よくない。該当サイズ式が評価されるときは正でなければならない。

VLA は条件付き機能なので、対応、正サイズ、記憶資源を確認する。

もう一歩先へ

発展：完全な配列オブジェクト a の要素数を N、要素型のサイズを S>0 とすると全体は NS、sizeof a/sizeof a[0]=NS/S=N となる。この証明はオペランドの配列型が保たれる場所だけに適用される。調整された仮引数や元からポインタの変数では分子が NS という前提がなく、証明は成立しない。N>0 の固定配列宣言と、論理的に空のデータ n=0 は区別する。後者はサイズ0の配列宣言ではなく別の長さ契約で表せる。

小節 5.2

走査・探索・整列の基礎

同じ配列を走査しても、探す関数と順序を変える関数では契約がどう違うだろう？

準備する概念と学習目標

準備する概念

  • for は初期化を一度実行し、その後、継続条件を検査し、真なら本体を実行して増分へ進む。i<n を検査してから a[i] を読むと、その時点で i<n を根拠にできる。
  • 線形探索は左から順に調べる。整列は値を非減少順に並べることで、同じ値が複数あれば個数も保存する。
  • 準備確認：[4,1,4,2] の最初の4は位置0。整列後の[1,2,4,4]では最初の4は位置2なので、どの状態の探索結果か明示する。

学習目標

  • 最初の位置または n を返す探索契約を説明する。
  • 探索と選択ソートのループ不変条件、終了を論証する。
  • 要素比較数と実時間、符号付き和の表現範囲を区別する。

読取りだけの走査と最初の位置の探索

first(a,n,key) は n>0 のとき、a が呼出し全体を通して生存する配列の先頭を指し、少なくとも n 個の初期化済み int を読める前提を持つ。n=0 なら a を使わないので NULL も契約上許される。結果は key と等しい最初の位置、または見つからない標識 n であり、n は有効位置と重ならない。

a[i] を読む時点で0≤i<n。開始時に前区間[0,i)に key がない不変条件を置く。最初は空で成立する。現在値が key なら前に同じ値がなく最初の位置となる。違えば検査済み区間を一つ拡張できる。i は n まで増え、有限入力で終了する。最後に n を返せば全区間に key がない。

選択ソートは変更のための別契約

selection は生存中、初期化済み、変更可能な n 個の int を要求する。外側位置 i で接尾区間[i,n)の最小値位置 m を探し a[i] と交換する。比較は a[j]<a[m] を使い減算にしない。両 int が有効でも a[j]-a[m] は符号付きオーバーフローを起こしうる。

完成した前区間は非減少で、その全値が残りの全値以下という不変条件を置く。接尾部最小値を次の位置へ移せば前区間を一つ広げられる。交換は値を失わず多重集合も保つ。同値にラベルを付けると非隣接交換で元の順序が変わりうるので、この実装を安定ソートとは呼ばない。

正確な比較数と算術条件

この実装の要素同士の < 比較は n−1,n−2,…,1,0 回、総数 n(n−1)/2。n=0 または1なら0回で、式は数学的整数の計数である。C の size_t で n*(n-1) をそのまま計算すると、n=0 の減算や大きな積が周回しうる。記号で示す回数と別問題である。ループ条件比較、交換、出力費用は数えない。

要素比較の固定費用モデルでは、大きな n の選択ソート比較数は Θ(n²)、すでに整列済みでも同じである。実行時間やキャッシュ性能を測定した結果ではない。走査で和を求める関数を追加するなら全中間累積値が int で表現できなければならず、最終和が小さいだけでは符号付きオーバーフローを回避したとはいえない。

#include <stdio.h>
#include <stddef.h>
size_t first(const int *a, size_t n, int key) {
    for (size_t i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return n;
}
void selection(int *a, size_t n) {
    for (size_t i = 0; i < n; ++i) {
        size_t m = i;
        for (size_t j = i + 1; j < n; ++j)
            if (a[j] < a[m]) m = j;
        if (m != i) { int tmp = a[i]; a[i] = a[m]; a[m] = tmp; }
    }
}
int main(void) {
    int a[] = {4, 1, 4, 2};
    size_t n = sizeof a / sizeof a[0];
    size_t found = first(a, n, 4);
    selection(a, n);
    printf("%zu %d %d %d %d\n", found, a[0], a[1], a[2], a[3]);
    return 0;
}

途中の過程をたどる例題

a=[4,1,4,2] で key=4 の最初の位置を求め、その後同じ配列を selection で整列する。first は読取りのみ、selection はその場で変更する。

  1. first は i=0 で a[0]=4 が key と等しく0を返す。found=0 は整列前の位置である。
  2. i=0 の接尾部最小値は位置1の1。交換後[1,4,4,2]、要素比較は3回。
  3. i=1 の最小値は位置3の2で[1,2,4,4]になる。この段階は2比較、i=2 は1、i=3 は0比較。
  4. 総比較数3+2+1+0=6、最終配列[1,2,4,4]。保存した found=0 は整列後の最初の4の位置2へ自動更新されない。

予想 stdout は 0 1 2 4 4 と改行。C 実行や時間測定はしていない。

紙と本文で試してみよう

紙上で[3,1,3]の key=3 と key=9 の first 結果を書き、選択ソートの各段階と総要素比較数を求めよ。[2a,2b,1]の数値だけを比較するとラベル順序は保存されるか？

ヒントを見る

見つからない標識は長さ3。a、b は同値2の元の順序を示す。

解答を見る

最初の3は位置0、ない9は標識3。最初の整列段階で[1,3,3]となり、後の値交換は不要、比較数2+1+0=3。[2a,2b,1]は最初の交換で[1,2b,2a]となり安定性が壊れる。m=i なら交換を省略する。

よくある誤解と反例

整列済みなら選択ソートはほとんど比較せず、探索結果の位置もそのまま使える。

この実装は入力順に関係なく接尾部全体を比較し n(n−1)/2 回を行う。整列前の位置は要素移動後に同じ意味を保つとは限らない。時間測定と比較数、値の存在と位置を区別する。

理解を確かめる

first(NULL,0,4) の返却契約は？

答えと理由を見る

0、つまり n。

空入力では要素アクセスも NULL ポインタ算術もなくループを飛ばす。

長さ4でこの選択ソートの要素比較は何回か？

答えと理由を見る

6回。

接尾部の検査は3+2+1+0。ループ条件比較を除く。

整列の正しさには非減少順だけで十分か？

答えと理由を見る

十分ではない。元の値の多重集合も保つ必要がある。

全入力を0で上書きしても非減少にはなるが、元の値を整列した結果ではない。

もう一歩先へ

発展：線形探索の終了尺度 n−i は不一致比較の後に1だけ減る。選択ソートは有限の外側・内側ループ、前区間不変条件、交換の多重集合保存によって全体の正しさを得る。最後の i=n−1 でも i+1=n は size_t で表現可能で、アクセスは内側 j<n の場合だけである。整数計数モデルで n≥2 なら n(n−1)/2≥n²/4、全非負 n で ≤n²/2 が成り立ち、Θ(n²) の両側の境界を得る。確率平均や実機の測定ではない。

小節 5.3

多次元配列

2行3列の表を関数へ渡すとき、列数がポインタ型に残る必要があるのはなぜだろう？

準備する概念と学習目標

準備する概念

  • a[2][3] は6個の int を使うが、型は3個の int の行配列を2個持つ配列である。最初の添字は行、次は列。
  • p+1 は必ず1バイト移動とは限らない。指す型のオブジェクト一つ分を移動する。int * と int (*)[3] は異なる型である。
  • 準備確認：2行3列の有効座標は r=0,1 と c=0,1,2 の組合せ。(1,2)が最後で、(0,3)は有効でない。

学習目標

  • 行配列の配列と行優先配置を説明する。
  • 多次元仮引数の調整とポインタ型を区別する。
  • 座標の範囲と和の算術条件を合わせて確認する。

行を要素に持つ配列

int a[2][3]={{1,2,3},{4,5,6}}; は外側要素数2、各行要素数3を完全に初期化する。C 配列は最後の添字が最速で変わる行優先順なので、格納順を1,2,3,4,5,6と説明できる。(r,c) は0≤r<2、0≤c<3をそれぞれ確認する。

行と列は数学的な図であり実アドレス数値を測定したものではない。全バイトサイズは2*3*sizeof(int)、一行は3*sizeof(int)。抽象位置番号3r+cを使えても、その図だけで行境界外の int ポインタ算術や a[0][3] は許されない。

ポインタは行の幅を保つ

式 a は通常、先頭行を指す int (*)[3] に変換される。int (*p)[3]=a の p+1 は次の行を指す。a[r] は一行の配列で、行内アクセスでは int * に変換される。型の段階が違うので int ** に変えて呼び出してはいけない。

関数の int a[][3] は int (*a)[3] に調整される。外側行数は別の長さ契約が必要だが、内側3は行単位移動の型に残る。C11で一般の可変列数を扱うなら VLA 対応、正の次元など別条件を確認する。この単元は固定列数3を使い、インストールや VLA 対応に依存しない。

添字と累積値の契約

row_sum は a が必要な行を実際に持つ配列を指し、row が実際の行数未満で、その行の3個の int が初期化済みである契約を要求する。関数名や a[][3] だけでは実際の行数を検査しない。const や型一致も対象の生存期間を自動で保証しない。

各加算の中間 total が int 範囲内という条件も要る。例の2行目は4→9→15で全 C11 int に安全な小値である。呼出し側では sizeof a/sizeof a[0] が行数2、sizeof a[0]/sizeof a[0][0] が列数3。調整済み関数仮引数 a で最初の比を全行数の計算とは呼ばない。

#include <stdio.h>
#include <stddef.h>
int row_sum(int a[][3], size_t row) {
    int total = 0;
    for (size_t c = 0; c < 3; ++c) total += a[row][c];
    return total;
}
int main(void) {
    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*p)[3] = a;
    printf("%zu %zu %d %d\n", sizeof a / sizeof a[0],
           sizeof a[0] / sizeof a[0][0], p[1][1], row_sum(a, 1));
    return 0;
}

途中の過程をたどる例題

2行3列 a と行ポインタ p の行数、列数、p[1][1]、row_sum(a,1) の予想値を求めよ。全中間和は int で表現できる。

  1. 最初の表は1行目[1,2,3]、2行目[4,5,6]。外側要素は行配列で各行3個の int。
  2. 呼出し側の sizeof 比から行数2、列数3。具体的な sizeof(int) は不要。
  3. p は最初の行を指す。p[1] は2行目、p[1][1] はその2番目の要素5で、両添字が有効。
  4. row_sum(a,1) の c=0,1,2 で total は4,9,15。c=3 では条件が偽なのでアクセスしない。

予想 stdout は 2 3 5 15 と改行。実アドレス測定や C 実行はしていない。

紙と本文で試してみよう

int b[2][2]={{2,4},{6,8}}; を描き、外側要素型、通常変換されるポインタ型、b[1][0] と2行目の和を書け。次の行の先頭だから b[0][2] を読んでよいか？

ヒントを見る

外側要素は2個の int を持つ行配列。全体の連続性と各行の添字境界は別条件。

解答を見る

外側要素型は int[2]、ポインタ型は int (*)[2]。b[1][0]=6、2行目の和は14。b[0][2] は最初の行の one-past を間接参照するため読めない。次の行の先頭は b[1][0] で読む。

よくある誤解と反例

多次元配列は int ** で、全要素が連続ならどんな添字でも行を越えられる。

int a[2][3] は行配列の配列で、int ** と型・移動単位が違う。a[0][3] は最初の行の外で、全メモリが連続でも正当化されない。仮想座標の線形番号と合法なポインタアクセスを区別する。

理解を確かめる

int a[2][3] が通常の式で変換されるポインタ型は？

答えと理由を見る

int (*)[3]。

外側配列の最初の要素は3個の int の行配列だから。

int a[][3] 仮引数は行数2を自動で覚えるか？

答えと理由を見る

覚えない。別の行数契約が必要。

外側配列仮引数は行ポインタに調整され、列数3は行型に残る。

a[1][0] の代わりに a[0][3] を読んでも安全か？

答えと理由を見る

安全ではない。

最初の行の列範囲は0,1,2、列3はその行の one-past。連続配置でも行外参照は許されない。

もう一歩先へ

発展：R行C列の固定配列で前 r 行は rC 要素、現在行の前は c 要素なので位置番号は rC+c。R,C>0 の有効座標では0からRC−1まで。逆にその番号 k に r=k/C,c=k%C を使うと一意な有効座標を得る。この一対一対応は図の番号の証明である。C の整数型で積 RC が表現可能か、全体オブジェクトが存在するか、行ごとのポインタアクセスを守るかは追加契約である。別に宣言した平坦 int 配列の設計と多次元配列の先頭行ポインタを無条件に同一視しない。

小節 5.4

範囲外アクセスの誤り

配列の外を読んだのにある実行では問題なさそうなら、安全といえるだろうか？

準備する概念と学習目標

準備する概念

  • 有効アクセスには添字だけでなく、生存中の適切な対象と初期化済み値が必要。宣言サイズと呼出し側が主張する長さの一致は自動では証明されない。
  • one-past は最後の要素の直後を示す位置。終了境界として使うことと、そこから値を読み書きすることは違う。
  • 準備確認：int a[3] の要素は a[0],a[1],a[2]。a+3 は終了境界標識で、読める a[3] 要素はない。

学習目標

  • ポインタ形成と間接参照の範囲条件を区別する。
  • 長さ検査関数の事前条件と失敗契約を説明する。
  • 符号付き誤り、符号なし周回、実際の失敗観察、UB を区別する。

終了境界ポインタと存在する要素

長さ3の配列の先頭を指す a に対し a+3 は one-past として形成できる。しかしそのポインタを評価される * のオペランドとして使い要素を読む・書くことはできない。a[3] は *(a+3) なので同じ問題がある。a+4 は配列内でも one-past でもなく、形成する算術自体が契約外である。

&a[3] のようにアドレスだけを形成する式は C11 の & と添字の結合規則で a+3 と同じになり、有効な終了標識を作れる。この例外を a[3] の値読取り許可に替えてはいけない。どの実際の配列が許容位置の基準かも重要。多次元配列では記憶が隣接しても各行境界を越えた添字は正当化されない。

条件を先に検査してアクセスする

read_at は size_t i を受け、i>=n なら0を返し out を変更しない。i<n なら a[i] を out にコピーし1を返す。成功しうる呼出しは a が少なくとも n 個の生存中・初期化済み int を提供し、out が生存中で変更可能な int を指す前提が必要。n=0 では必ず失敗し a、out を使わないので NULL も許す。

関数は n が実際の長さか検証できない。長さ3に n=100,i=4 を与えれば比較を通っても対象がない。検査には先に信頼できる長さ契約が必要。負整数を size_t に変えると大値になりうるし、範囲外の正数も変換中に周回しうる。外部入力の符号と表現可能性を先に確認して渡す。

不変条件と算術誤りを合わせて確認する

for(size_t i=0;i<n;++i) のように n 未満を確認してからアクセスするのは正しい出発点。一方 i<=n は終了境界 n で余分にアクセスする。n=0 の size_t last = n - 1; は格納後 size_t の最大値になる。size_t が狭く int へ昇格する実装では式が先に int の−1になることもあるが、size_t への格納で同じ最大値へ変換される。最後の位置を求める前に n>0 が必要。符号なし周回は C で定義された算術でも、誤った長さや添字の意味を正しくはしない。

符号付き int の INT_MAX+1 は未定義動作。配列外アクセスとは別の UB 原因で、どちらも固定エラー表示や必ず即終了という規則はない。偶然正常に見える一実行から安全性を証明しない。下のコードは失敗時に元の out を保存する正常経路だけを示し、範囲外間接参照をテスト実行しない。

#include <stdio.h>
#include <stddef.h>
int read_at(const int *a, size_t n, size_t i, int *out) {
    if (i >= n) return 0;
    *out = a[i];
    return 1;
}
int main(void) {
    int a[3] = {6, 7, 8};
    int out = 99;
    int ok = read_at(a, 3, 3, &out);
    printf("%d %d\n", ok, out);
    ok = read_at(a, 3, 2, &out);
    printf("%d %d\n", ok, out);
    return 0;
}

途中の過程をたどる例題

長さ3の a=[6,7,8]、out=99 で先に i=3、次に i=2 の read_at を呼ぶ。n は実要素数で成功経路の a、out は有効。

  1. 最初は i=3,n=3 で i>=n が真。a[3] や *out を評価する前に0を返す。
  2. ok=0、out=99 が保存され、最初の予想出力は 0 99。失敗返却は正常契約の結果で UB の実行結果ではない。
  3. 次は i=2<n なので a[2]=8 を読み有効な out にコピーし1を返す。
  4. ok=1,out=8 より2行目は 1 8。どちらも配列外値を読まない。

予想 stdout は 0 99 と改行、続いて 1 8 と改行。実際の C 実行はない。

紙と本文で試してみよう

int b[4]={1,2,3,4}; で b+4 形成、*(b+4) 読取り、b+5 形成、&b[4] 形成を分類せよ。read_at(b,4,4,&v) が元の v=20 を保つ理由も書け。

ヒントを見る

許された終了標識形成と、評価される間接参照を区別する。検査前に誤アクセスすれば後の検査で直せない。

解答を見る

b+4、&b[4] は許された one-past 形成。*(b+4) の読取り、b+5 形成は UB。4>=4 の検査がアクセス前に失敗終了するので返却0、v=20。UB の2式に特定の出力やエラーを答えない。

よくある誤解と反例

範囲外なら C が捕捉できる例外を投げるから、先に読み後で検査してよい。

C11 の一般配列アクセスには自動例外・境界検査契約がない。範囲外は UB で特定出力や終了を保証しない。読む前に実長に基づき条件確認し、既に起きた UB を後の if で取り消せない。

理解を確かめる

長さ3で a+3 形成と *(a+3) 読取りは同じ安全性か？

答えと理由を見る

違う。前者は one-past 形成可、後者は読取り不可。

終了標識ポインタは存在する要素を指さない。

実長より大きな n の read_at は i<n だけで安全か？

答えと理由を見る

安全ではない。

検査に使う n 自体が実際のアクセス可能要素数である前提が必要。

size_t n=0 の n−1 を最後の要素位置に使えるか？

答えと理由を見る

使えない。

size_t への格納結果は最大値。昇格の有無と関係なく空データに最後の要素はない。

もう一歩先へ

発展：read_at の i≥n の失敗経路は要素・out にアクセスせず、out 保存を論証できる。成功経路では i<n と実際の n 要素契約を合わせ a[i] の有効性を得て、有効 out 契約で書込みを正当化する。返却1なら out が呼出し時の a[i] と等しいという事後条件を得る。生存期間、初期化、変更可能対象、同時変更なしを前提とし、自動メモリ権限検査ではない。n=0 の失敗契約とサイズ0の C 配列宣言を混同しない。
