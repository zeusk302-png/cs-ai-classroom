Subtopic 5.1

Array Size and Indices

Why is the final index of a five-element array 4 rather than 5?

Preparation and learning goals

Preparation

  • An array groups objects of the same element type in contiguous storage. In int a[5], a is an array of five ints, and a[0] is its first element. The element count and the final index are different numbers.
  • size_t is the unsigned integer type used for sizeof results. sizeof reports size in C bytes; we do not assume that a byte must have 8 bits or that int must occupy 4 bytes.
  • Self-check: Write the indices of three elements a[0],a[1],a[2]. The largest index is 2 and the element count is 3. This distinction is enough to begin reading the diagrams below.

Learning goals

  • Calculate the size and valid indices of an array object.
  • Distinguish partial initialization from an uninitialized automatic array.
  • Explain sizeof for an array object versus a pointer parameter, and state VLA conditions.

Object size and valid indices

This unit uses the public C11 draft N1570. The array int a[5] has 5 elements, accessible from its first element with indices 0≤i<5. There is no sixth element a[5]. Since the elements have the same type, the total array size is its element count multiplied by the size of one element.

Where the actual array object a is visible, sizeof a / sizeof a[0] gives the element count. Both quantities use the same C-byte unit, so the ratio is 5 without assuming a particular sizeof(int). The declaration defines this array object; adding elements does not automatically enlarge it.

Values supplied by initialization

In int a[5]={4,7};, the first two elements are initialized to 4,7 and the remaining int elements to 0. If the size is omitted with an initializer, as in int a[]={4,7};, the element count in this example becomes 2. Simply declaring int a[5]; inside a function with automatic storage duration does not make every element automatically 0. Store valid values in each element before reading it.

For this fixed-size example, the operand of sizeof is not evaluated, so sizeof a[0] does not read the first element’s value. For a general C11 VLA, size calculations may occur at runtime; do not generalize that sizeof never involves runtime evaluation. VLA support is conditional in C11, an evaluated runtime length must be positive, and the size of an array instance does not change during its lifetime. A VLA also does not automatically guarantee storage availability or failure handling for large inputs.

Preserve the length contract at a function boundary

In void f(int a[5]), the parameter a is adjusted to int * by the function-parameter rules. Within the function, sizeof a is the size of the pointer type, not the caller’s five-element array. That ratio cannot recover the caller’s length. Usually, pass a pointer and a separate size_t n, explicitly requiring n live elements to be available.

Brackets in a declaration do not automatically create bounds checking. For example, the parameter int a[static 5] expresses a contract requiring the caller to provide access to at least five elements; it neither checks this automatically nor enlarges a smaller array. The complete fixed-array program below does not depend on parameter adjustment or VLAs.

#include <stdio.h>
#include <stddef.h>
int main(void) {
    int a[5] = {4, 7};
    size_t n = sizeof a / sizeof a[0];
    a[n - 1] = 9;
    printf("%zu %d %d %d\n", n, a[0], a[2], a[4]);
    return 0;
}

A worked example, step by step

In the code, calculate n for int a[5]={4,7}, then change the final element to 9. The format %zu displays size_t. Find expected values only, assuming successful normal output.

  1. Immediately after the declaration, the five values are [4,7,0,0,0]. Partial initialization makes the remaining three ints 0.
  2. Because sizeof a=5*sizeof(int) and sizeof a[0]=sizeof(int), n=5. No particular byte count is assumed.
  3. Since n=5, n−1=4 and a[4]=9 writes to the valid final element. The array becomes [4,7,0,0,9].
  4. The output arguments are n=5,a[0]=4,a[2]=0,a[4]=9. The %zu and three %d specifiers match their respective types.

The expected stdout is 5 4 0 9 followed by a newline. No actual compilation or execution was performed.

Try it with paper and the lesson

Draw the four elements of int b[4]={8};. Write the element count, largest index and values, and calculate sizeof b/sizeof b[0]. Decide whether the same expression also represents the length inside void g(int b[4]).

Show hint

Put the actual array object b and the parameter b adjusted to a pointer in separate tables.

Show solution

The caller’s array is [8,0,0,0], with count 4, largest index 3, and array-object ratio 4. The parameter of g is int *, so its ratio is sizeof(int *)/sizeof(int), which does not establish the array length. Even if its implementation-specific value happens to be 4, it is not a general length-recovery rule.

Misconception and counterexample

A declaration a[5] means that a[5] is also inside the array.

The declaration’s 5 is an element count; the access expression’s 5 is the sixth position when counting from 0. The valid final position is 4. Reading an uninitialized automatic array is a separate issue from bounds.

Check your understanding

What is the initial value of a[3] in int a[5]={4,7};?

Show answer and reasoning

0

The remaining omitted elements of this int array are initialized to 0.

Within an int a[5] parameter, is sizeof a the size of the original whole array?

Show answer and reasoning

No. It is the size of the adjusted pointer type.

An array parameter is adjusted to a pointer type, so the length is supplied through a separate contract.

May we assume that a C11 VLA can be declared with runtime length 0?

Show answer and reasoning

No. The size expression must be positive whenever it is evaluated.

VLA support is conditional in C11; check support, positive size, and storage-resource conditions.

Explore further

Extension: Let a complete array object a have N elements, each of size S>0. Its total size is NS, so sizeof a/sizeof a[0]=NS/S=N. This proof applies only where the operand retains its array type. For a parameter adjusted to a pointer, or a variable already of pointer type, the premise that the numerator equals NS is absent. Distinguish a fixed-array declaration with N>0 from logically empty data with n=0. The latter can be represented by a separate length contract rather than declaring a zero-size array object.

Subtopic 5.2

Basic Traversal, Search, and Sorting

How do the contracts of a search function and an order-changing function differ, even when both traverse the same array?

Preparation and learning goals

Preparation

  • A for loop performs initialization once, then repeatedly checks the continuation condition, runs the body when that condition is true, and performs the increment. If a[i] is read after checking i<n, that condition justifies i<n at the time of access.
  • Linear search checks elements in order from left to right. Sorting arranges values in nondecreasing order; if a value occurs several times, its multiplicity must also be preserved.
  • Self-check: In [4,1,4,2], the first 4 is at position 0. After sorting to [1,2,4,4], the first 4 is at position 2. State which array state a search result refers to.

Learning goals

  • Explain a search result that is either the first position or n.
  • Prove loop invariants and termination for search and selection sort.
  • Distinguish element-comparison counts from actual time, and check representability of signed sums.

Read-only traversal and first-position search

For first(a,n,key), if n>0, a must point to the first element of an array that remains alive throughout the call, with at least n initialized ints available for reading. If n=0, the function does not use a, so its contract also permits NULL. The result is the position of the first element equal to key, or n to indicate not found. The marker n cannot overlap a valid position.

Whenever the body reads a[i], 0≤i<n. Use the invariant that the preceding range [0,i) contains no key at the start of an iteration. Initially this is true for an empty range. If the current element equals key, the absence of key earlier makes this its first position. Otherwise, extend the checked range by one element. Since i increases up to n, finite inputs terminate; returning n at the end means that the whole range contains no key.

Selection sort has a separate modifying contract

selection requires n live, initialized, modifiable int elements. At each outer position i, it finds the minimum’s position m in the suffix [i,n) and swaps a[i] with a[m]. It compares a[j]<a[m], rather than subtracting: a[j]-a[m] can cause signed overflow even if both operands are valid ints.

Maintain the invariant that the completed prefix is nondecreasing and every value in it is no greater than any remaining value. Moving a suffix minimum into the next position extends this prefix by one. Swaps lose no values, so they preserve the multiset of elements. With labels attached to equal values, these nonadjacent swaps may change their original order; this implementation is not claimed to be stable.

Exact comparison counts and arithmetic conditions

This implementation makes n−1,n−2,…,1,0 element comparisons using <, totaling n(n−1)/2. The count is 0 for n=0 or 1; this formula is calculated with mathematical integers. Directly computing n*(n-1) in C size_t can wrap on the subtraction at n=0 or the product for large values. That is separate from the symbolic comparison count. Loop-condition comparisons, swaps, and output are not included.

In a fixed-cost element-comparison model, selection sort uses Θ(n²) comparisons for large n, including already sorted input. This is not a measurement of actual runtime or cache performance. If a summation function is added, every intermediate accumulated sum must be representable as int. A small final sum alone does not establish that signed overflow was avoided.

#include <stdio.h>
#include <stddef.h>
size_t first(const int *a, size_t n, int key) {
    for (size_t i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return n;
}
void selection(int *a, size_t n) {
    for (size_t i = 0; i < n; ++i) {
        size_t m = i;
        for (size_t j = i + 1; j < n; ++j)
            if (a[j] < a[m]) m = j;
        if (m != i) { int tmp = a[i]; a[i] = a[m]; a[m] = tmp; }
    }
}
int main(void) {
    int a[] = {4, 1, 4, 2};
    size_t n = sizeof a / sizeof a[0];
    size_t found = first(a, n, 4);
    selection(a, n);
    printf("%zu %d %d %d %d\n", found, a[0], a[1], a[2], a[3]);
    return 0;
}

A worked example, step by step

Find the first position of key=4 in a=[4,1,4,2], then sort the same array using selection. first only reads; selection changes the array in place.

  1. At i=0, first finds a[0]=4 equal to key and returns 0. found=0 refers to the array before sorting.
  2. At i=0, the suffix minimum is 1 at position 1. Swapping gives [1,4,4,2]. There are 3 element comparisons.
  3. At i=1, the minimum is 2 at position 3, giving [1,2,4,4]. This stage has 2 comparisons; i=2 has 1, and i=3 has 0.
  4. The total is 3+2+1+0=6 comparisons, and the final array is [1,2,4,4]. The saved found=0 does not automatically update to position 2, the first 4 after sorting.

The expected stdout is 0 1 2 4 4 followed by a newline. No C execution or timing measurement was performed.

Try it with paper and the lesson

On paper, write the first results for key=3 and key=9 in [3,1,3]. Find the array after each selection-sort stage and the total element comparisons. Also check whether comparing only the numeric values in [2a,2b,1] preserves label order.

Show hint

The not-found marker is length 3. Labels a,b show the original order of the two value-2 elements.

Show solution

The first 3 is at position 0; missing 9 gives marker 3. The first sorting stage produces [1,3,3]; no further value swaps are needed, and the count is 2+1+0=3. The first swap in [2a,2b,1] gives [1,2b,2a], violating stability. This implementation skips a swap when m=i.

Misconception and counterexample

Selection sort makes almost no comparisons on sorted input, and a prior search position remains usable unchanged.

Regardless of whether the input is sorted, this implementation compares the whole suffix at each stage, totaling n(n−1)/2. A pre-sort position may lose its meaning after elements move. Distinguish timing from comparison counts, and value existence from its position.

Check your understanding

What is the return contract of first(NULL,0,4)?

Show answer and reasoning

0, which is n.

For empty input, this function skips the loop without element access or NULL pointer arithmetic.

How many element comparisons does this selection sort make for length 4?

Show answer and reasoning

6

The suffix counts are 3+2+1+0; loop-condition comparisons are excluded.

Is nondecreasing order alone enough to establish sorting correctness?

Show answer and reasoning

No. The original multiset of values must also be preserved.

Overwriting every input element with 0 can produce nondecreasing order, but does not sort the original values.

Explore further

Extension: The termination measure for linear search is n−i, decreasing by exactly 1 after an unsuccessful comparison. Selection sort obtains total correctness from finite outer and inner loops, the prefix invariant, and multiset preservation by swaps. At the final iteration i=n−1, i+1=n is still representable as size_t; the inner loop accesses an element only while j<n. In the integer-count model, n(n−1)/2≥n²/4 for n≥2 and ≤n²/2 for every nonnegative n, giving both Θ(n²) bounds. These are neither probabilistic averages nor measurements on an actual computer.

Subtopic 5.3

Multidimensional Arrays

When passing a 2-row, 3-column table to a function, why must the column count remain in the pointer type?

Preparation and learning goals

Preparation

  • a[2][3] uses six ints, but its type is an array of two row arrays, each containing three ints. The first subscript is the row; the second is the column.
  • The pointer expression p+1 does not always move by one byte. It moves by one object of the pointed-to type. int * and int (*)[3] are different types.
  • Self-check: Valid coordinates of a 2-row, 3-column table combine r=0,1 with c=0,1,2. Coordinate (1,2) is the final element; (0,3) is not a valid coordinate.

Learning goals

  • Explain an array of row arrays and row-major layout.
  • Distinguish multidimensional parameter adjustment from pointer types.
  • Check both coordinate bounds and arithmetic conditions for a sum.

An array whose elements are rows

The declaration int a[2][3]={{1,2,3},{4,5,6}}; fully initializes an outer array of 2 elements, with 3 elements per row. C arrays use row-major order, with the last subscript varying fastest, so the storage-order description is 1,2,3,4,5,6. Check 0≤r<2 and 0≤c<3 separately for coordinate (r,c).

Rows and columns are mathematical diagrams, not measured numerical addresses. The total byte size is 2*3*sizeof(int), and one row is 3*sizeof(int). Abstract storage positions can be numbered by 3r+c, but that diagram does not permit int-pointer arithmetic across row boundaries or access through a[0][3].

The pointer preserves the row width

The expression a usually converts to int (*)[3], pointing to the first row. With int (*p)[3]=a, p+1 points to the next row. a[r] is one row array, which converts to int * when accessing its elements. These pointer levels differ; do not convert this argument to int ** to call a function.

A function parameter int a[][3] is adjusted to int (*a)[3]. The outer row count must come from a separate length contract, but the inner 3 remains in the type used for row-wise movement. Using a general variable column count in C11 requires checking VLA support, positive dimensions, and other conditions. This unit uses a fixed column count of 3, requiring no installation or VLA support.

Contracts for indices and accumulated values

row_sum requires that the argument a actually refer to an array containing the needed row, that row be below the actual row count, and that the three ints in that row be initialized. Neither the function name nor a[][3] automatically checks the actual row count. const or a matching type also does not automatically ensure the object’s lifetime.

The arithmetic contract also requires each intermediate total to stay within the int range. The example’s second row produces 4→9→15, small safe values for every C11 int. At the caller’s object, sizeof a/sizeof a[0] gives 2 rows, and sizeof a[0]/sizeof a[0][0] gives 3 columns. Do not interpret the first ratio as a whole-array row count when a is an adjusted function parameter.

#include <stdio.h>
#include <stddef.h>
int row_sum(int a[][3], size_t row) {
    int total = 0;
    for (size_t c = 0; c < 3; ++c) total += a[row][c];
    return total;
}
int main(void) {
    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*p)[3] = a;
    printf("%zu %zu %d %d\n", sizeof a / sizeof a[0],
           sizeof a[0] / sizeof a[0][0], p[1][1], row_sum(a, 1));
    return 0;
}

A worked example, step by step

For the 2-row, 3-column a and row pointer p, find the expected row count, column count, p[1][1], and row_sum(a,1). Every intermediate sum is representable as int.

  1. The initial table has first row [1,2,3] and second row [4,5,6]. Each outer element is a row array containing three ints.
  2. The caller’s sizeof ratios give 2 rows and 3 columns. No particular sizeof(int) is needed.
  3. p points to the first row. p[1] is the second row, and p[1][1] is its second element, 5. Both subscripts are valid.
  4. In row_sum(a,1), total becomes 4,9,15 at c=0,1,2. At c=3 the loop condition is false, so no element is accessed.

The expected stdout is 2 3 5 15 followed by a newline. No actual addresses or C execution were measured.

Try it with paper and the lesson

Draw int b[2][2]={{2,4},{6,8}};. State the outer element type, the usual converted pointer type, b[1][0], and the second-row sum. May b[0][2] be read because it appears to be the first element of the next row?

Show hint

The outer array’s element is a row array of two ints. Overall contiguity and each row’s subscript bounds are separate conditions.

Show solution

The outer element type is int[2], and the converted pointer type is int (*)[2]. We have b[1][0]=6 and second-row sum 6+8=14. b[0][2] dereferences the first row’s one-past pointer and must not be read. Access the next row’s first element through b[1][0].

Misconception and counterexample

A multidimensional array is int **, and contiguity allows any subscripts to cross rows.

int a[2][3] is an array of row arrays, with a different type and movement unit from int **. a[0][3] crosses the first row’s access boundary; overall memory contiguity does not justify it. Separate linear numbering in a coordinate diagram from legal pointer access.

Check your understanding

To what pointer type does int a[2][3] usually convert in an expression?

Show answer and reasoning

int (*)[3]

The first element of the outer array is a row array of three ints.

Does a parameter declared int a[][3] automatically remember that there are 2 rows?

Show answer and reasoning

No. A separate row-count contract is required.

The outer array parameter is adjusted to a row pointer, while the column count 3 remains in the row type.

Is it safe to read a[0][3] instead of a[1][0]?

Show answer and reasoning

No.

The first row contains columns 0,1,2; column 3 is one-past that row. Contiguity does not permit dereferencing outside the row.

Explore further

Extension: For a fixed array of R rows and C columns, there are rC elements in the preceding r rows and c preceding elements in the current row, giving storage-position number rC+c. With R,C>0 and valid coordinates, these numbers range from 0 to RC−1. Conversely, r=k/C and c=k%C give unique valid coordinates for each such k. This bijection is a proof about numbering a diagram. In C, additional contracts must check whether RC fits the integer type, whether the whole object exists, and whether row-wise pointer access is respected. Do not automatically confuse a separately declared flat int array design with a pointer to the first row of a multidimensional array.

Subtopic 5.4

Out-of-Bounds Access Errors

If reading outside an array seems harmless in one execution, can we call it safe?

Preparation and learning goals

Preparation

  • Valid access requires not just an index but a suitable live object and initialized values. The declared array size is not automatically proved equal to the length claimed by a caller.
  • One-past marks the position immediately after the final element. Using it as an end boundary differs from reading or writing a value there.
  • Self-check: int a[3] contains a[0],a[1],a[2]. The expression a+3 marks the end boundary; there is no element a[3] available to read.

Learning goals

  • Distinguish bounds conditions for forming a pointer and dereferencing it.
  • Explain preconditions and the failure contract of a length-checking function.
  • Distinguish signed errors from unsigned wraparound, and observed failures from UB.

An end-boundary pointer versus an existing element

For a pointing to the first element of a length-3 array, a+3 can be formed as a one-past pointer. However, it must not be used as the operand of an evaluated unary * to read or write an element. The subscript access a[3] means *(a+3) and has the same issue. The expression a+4 is outside both the array and its one-past position, so the pointer arithmetic itself is outside the contract.

An address-only expression such as &a[3] is equivalent to a+3 under the C11 rules combining & with subscripting, and can form a valid end marker. Do not turn this exception into permission to read the value a[3]. Which actual array object defines the allowed positions also matters. In a multidimensional array, adjoining storage does not justify subscripts crossing an individual row’s boundary.

Check the condition before access

read_at takes a size_t i. If i>=n, it returns 0 without changing out. If i<n, it copies a[i] into out and returns 1. A call that can succeed requires a to provide at least n live, initialized int elements and out to point to a live, modifiable int. With n=0, it always fails and uses neither a nor out, so NULL is also permitted.

This function cannot verify that n is the actual length. Passing n=100,i=4 for a length-3 array passes the comparison but provides no target element. The check itself depends on a trustworthy length contract before access. Converting a negative integer to size_t may produce a large value, and an out-of-range positive value may wrap during conversion. Check the sign and representability of external input before passing it to this interface.

Check invariants together with arithmetic errors

A pattern such as for(size_t i=0;i<n;++i), accessing only after checking i<n, is a sound starting point. In contrast, i<=n accesses once more at the end boundary n. When n=0, storing size_t last = n - 1; makes last the maximum size_t value. On an implementation where a narrow size_t promotes to int, the expression itself may first be int −1; storing it as size_t converts it to the same maximum value. Thus n>0 must be known before finding the final position. Unsigned wraparound is defined arithmetic in C, but does not make an incorrect length or index meaningful.

The signed int expression INT_MAX+1 has undefined behavior. This and out-of-bounds access are distinct sources of UB, neither of which guarantees a fixed error message or immediate termination. One execution whose output happens to look normal does not prove safety. The code below shows only normal paths preserving the old out on failure; it does not execute an out-of-bounds dereference as a test.

#include <stdio.h>
#include <stddef.h>
int read_at(const int *a, size_t n, size_t i, int *out) {
    if (i >= n) return 0;
    *out = a[i];
    return 1;
}
int main(void) {
    int a[3] = {6, 7, 8};
    int out = 99;
    int ok = read_at(a, 3, 3, &out);
    printf("%d %d\n", ok, out);
    ok = read_at(a, 3, 2, &out);
    printf("%d %d\n", ok, out);
    return 0;
}

A worked example, step by step

For length-3 a=[6,7,8] and out=99, call read_at first with i=3 and then with i=2. Here n is the actual element count, and a and out are valid on the successful path.

  1. In the first call, i=3,n=3 makes i>=n true. The function returns 0 before evaluating a[3] or *out.
  2. We have ok=0 and out remains 99, so the first expected output is 0 99. The failure return is a normal contractual result, not a result of executing UB.
  3. The second call has i=2<n, so it reads a[2]=8, copies it into the valid out object, and returns 1.
  4. Now ok=1,out=8, so the second expected output is 1 8. Neither call reads an out-of-bounds value.

The expected stdout is 0 99 followed by a newline, then 1 8 followed by a newline. No actual C execution was performed.

Try it with paper and the lesson

For int b[4]={1,2,3,4};, classify forming b+4, reading *(b+4), forming b+5, and forming &b[4]. Then explain why read_at(b,4,4,&v) preserves the old v=20.

Show hint

Distinguish forming a permitted end marker from an evaluated dereference. If an invalid access occurs before the check, a later check cannot repair it.

Show solution

b+4 and &b[4] are permitted one-past formation. Reading *(b+4) and forming b+5 are UB. Since read_at checks 4>=4 and fails before access, it returns 0 and leaves v=20. Do not assign a specific output or error to the two UB expressions.

Misconception and counterexample

C throws a catchable exception on an out-of-bounds access, so reading first and checking later is fine.

Ordinary C11 array access has no automatic-exception or bounds-checking contract. Out-of-bounds access is UB and guarantees no particular output or termination. Check against the actual length before reading; a later if cannot undo UB that has already occurred.

Check your understanding

Are forming a+3 and reading *(a+3) equally safe for a length-3 array?

Show answer and reasoning

No. One-past formation is permitted; the read is not.

An end-marker pointer does not point to an existing element.

Is the i<n check alone safe if read_at is given n greater than the actual length?

Show answer and reasoning

No.

The precondition requires n itself to describe the number of actually accessible elements.

For size_t n=0, may n−1 be used as the final element position?

Show answer and reasoning

No.

Storing the result as size_t produces its maximum value. Regardless of integer promotions in the expression, empty data have no final element.

Explore further

Extension: On read_at’s failure path with i≥n, there is no element or out access, proving preservation of out. On success, i<n together with the actual-n-elements contract establishes the validity of a[i], and the valid-out contract justifies the write. A return value of 1 therefore has the postcondition that out equals the value of a[i] at the call. This reasoning requires lifetime, initialization, a modifiable target, and no concurrent changes; it is not an automatic memory-permission check. Do not confuse a contract permitting n=0 failure with declaring a zero-size C array.
