小节 6.1

零字符结尾与长度

数组有六个字符位置，为什么 strlen 可能只返回 1？

预备知识与学习目标

预备知识

  • char 数组是容纳字符元素的对象。char a[6] 有六个元素，有效下标为 0 到 5。C 中 sizeof(char)=1，但不能把所有 C 字节都假定为八位。
  • '\0' 是整数值为零的空字符，作用不同于字符 '0' 和指针宏 NULL。字符串的终止零必须位于有效数组内。
  • 准备检查：[A,0,B] 中，首个零之前的字符串内容占一个位置。从左检查直到并包括这个零，实际读取两个位置：A 和零。整个数组有三个位置。内容长度、实际读取数与容量是不同的数量。

学习目标

  • 说明 C 字符串的终点和 strlen 所计的长度。
  • 区分存储容量、逻辑字符串长度和首个零之后的数据。
  • 解释有界搜索的访问边界、终止与失败结果。

第一个零决定字符串的终点

C11 的字符串是直到并包括第一个空字符的连续字符序列；字符串长度却只计算该零之前的字节。对于 char a[6]={'A','\0','B','C','\0','\0'}，从 a 开始的字符串长度为 1，数组容量为 6。B 和 C 仍然存放在数组里，strlen(a) 不会越过首个零把它们计入。

strlen 要求输入已经是能在有效范围内找到终止零的字符串。对没有零的数组先调用 strlen，再检查长度，可能在检查前就已违反约定。长度为零的空字符串在首个位置存有零，不等于没有存储或 NULL 指针。char empty[1]={0} 可以存放空字符串。

先按容量检查，再信任长度

下面的 bounded_length 要求 s 提供 cap 个仍在生命周期内的可读 char 元素，out 指向可写 size_t 对象。cap=0 时这个自定义函数不读取 s，因此可以在其约定中允许 s=NULL，但 out 仍须有效；cap>0 而 s=NULL 则违反约定。只有返回 1 才经 out 写入新长度；返回 0 表示指定范围内未找到终止零。

在 i<cap && s[i]!='\0' 中，仅当左操作数为真，&& 才求值右操作数。i==cap 时不读取 s[cap]。每轮开始有 0≤i≤cap，且前 i 个位置都非零。搜索或者找到首个零，或者到 i==cap 失败。若传入虚假的容量，这个检查不能保证实际对象边界。

字节长度不同于可见字符数

strlen 不解码字符，也不计数显示符号。额外假定采用八位字节的 UTF-8 时，U+AC00 가 编码为 EA B0 80 三个字节；加上终止 00，至少需要四个位置，strlen 为 3。普通 C char 字符串并不自动采用 UTF-8。下面代码只用基本执行字符集中的 A、B、C、X、Y、Z。

外部文件的数据可以包含内部零。二进制数据应另存真实字节长度，strlen 无法恢复它。解码、规范化和显示字符识别属于其他层。例中的 raw 有三个二进制数据位置，并不是 C 字符串，所以不传给 strlen 或 %s。

#include <stdio.h>
#include <stddef.h>
#include <string.h>
static int bounded_length(const char *s, size_t cap, size_t *out) {
    size_t i = 0;
    while (i < cap && s[i] != '\0') {
        ++i;
    }
    if (i == cap) return 0;
    *out = i;
    return 1;
}
int main(void) {
    char a[6] = {'A', '\0', 'B', 'C', '\0', '\0'};
    char raw[3] = {'X', 'Y', 'Z'};
    size_t len = 99;
    int ok = bounded_length(a, sizeof a, &len);
    printf("%zu %zu %d %zu\n", sizeof a, strlen(a), ok, len);
    ok = bounded_length(raw, sizeof raw, &len);
    printf("%d %zu\n", ok, len);
    return 0;
}

逐步推导的例题

逐步追踪完整例子中 a、raw 的存储、返回值与 len 的变化。假设正常输出成功；这只是纸上推演，没有实际运行。

  1. a 容量为 6，首个零在下标 1。sizeof a=6，strlen(a)=1；后面的元素不计入字符串长度。
  2. bounded_length(a,6,&len) 在 i=0 检查 A，在 i=1 停止，返回 1 并设置 len=1。首行输出参数为 6、1、1、1。
  3. raw 存有 X、Y、Z，没有零。循环在 i=0、1、2 递增，到 i=3 时左条件为假，不读取第四个位置。
  4. 失败时返回 0，不经 out 赋值，因此旧 len=1 保留。忽略返回值就可能误认为 raw 的字符串长度为 1。

预期标准输出首行是 6 1 1 1，第二行是 0 1。失败后保留的 len 并不表示 raw 的字符串长度。

用纸笔和正文动手试一试

画五个位置 [P,Q,0,R,0] 和四个位置 [P,Q,R,S]。分别用正确容量和初始输出值 77 调用 bounded_length，求返回值、输出值与最后读取的下标。

查看提示

读取零本身也算一次检查。失败不赋值给 out，也不读取下标 cap。

查看解答

第一个数组读取下标 0、1、2，返回 1，设置 out=2。第二个读取 0 到 3，在 i=4 停止，返回 0，out 仍为 77。cap=4 或旧输出值都不能保证它具有字符串长度。

常见误解与反例

对任意字符数组，strlen 都能安全地告诉我们容量。

a[6] 的 strlen(a)=1，sizeof a=6。对没有零的 raw[3] 调用 strlen，会使终止搜索违反对象边界约定并产生未定义行为。不能为这种行为预测固定数值。

检查理解

char e[1]={0}; 的长度和容量分别是多少？

查看答案与理由

长度 0，容量 1。

终止零占存储位置，但不计入长度。

八字节数据包含有内部零时，strlen 能恢复整个包的大小吗？

查看答案与理由

一般不能。

首个零之后的数据不会被计数，应另存包长度。

cap=3、i=3 时，代码读取 s[3] 吗？

查看答案与理由

不读取。

i<cap 为假，&& 不求值右操作数。

进一步探索

证明：假设每轮之前 0≤i≤cap，且所提供范围中所有 j<i 的 s[j] 非零。条件为真意味着 i<cap，所以当前位置有效且非零；递增后保持不变式。自然数变式 cap−i 每轮减一，保证有限终止。结束时 i<cap，则 s[i]=0 且前面没有零，所以找到了首个终止符；结束时 i=cap，则整个范围没有零。递增前始终 i<cap，i 最多达到 cap，因此即使抽象模型 cap=SIZE_MAX，最后一次递增也不溢出。实际存在如此大的可读对象是另一个前提。

小节 6.2

字符数组与字面量

a 和 p 都用 "cat" 初始化，为什么可以修改的内容不同？

预备知识与学习目标

预备知识

  • 数组是包含元素的对象，指针是指向对象位置的值。const char *p 禁止通过 p 修改字符，与禁止给 p 自身重新赋值不同。
  • 初始化确定新对象的初始内容。char a[]="cat" 创建字符数组；char *p="cat" 创建指向字符串字面量首字符的指针。
  • 准备检查：'A' 是字符常量，"A" 是含终止零的字符串字面量；在 C 中它们的类型和存储不同。

学习目标

  • 区分字符数组初始化与字符串字面量。
  • 说明终止符所占空间和 sizeof 测量的对象。
  • 区分生命周期、const 访问限制与修改字面量的未定义行为。

初始化创建独立数组

普通 C11 字符串字面量 "cat" 由具有静态存储期的 char 数组实现，存有 c、a、t、零。char a[]="cat" 创建另一个数组对象，用这四个字符初始化。下面的 a 在 main 内有自动存储期；a[0]='b' 将它变成 "bat"，没有修改字面量。

char b[6]="cat" 得到 [c,a,t,0,0,0]。C11 也允许恰好三个位置的 char raw[3]="cat"，但没有空间放终止字符，只留下 [c,a,t]。初始化合法不意味着 raw 是字符串。代码用 %c 分别读元素，不用 %s 或 strlen。

元素类型与修改规则是两件事

普通 C 字面量数组的元素类型为 char，但尝试修改其内容是未定义行为。不要把 C++ 的字面量类型规则直接套到 C11。即使允许 char *q="cat"，q[0]='b' 也不是安全修改。const char *p 在类型中表达只读访问，帮助避免错误。

const char *p 中的 const 禁止经 p 修改所指字符，但仍可执行 p="dog"。char *const q 则在不同位置限制指针赋值。类型允许或禁止的访问，与对象是否仍在生命周期内，是不同问题。自动局部数组在函数结束后不能经返回指针继续使用；指向字面量的指针所指对象有静态存储期。

容量、长度与指针大小不能混用

sizeof a 测量整个数组，此处是 4；strlen(a) 计终止零之前的字符，是 3。sizeof p 测量指针对象，其值依实现，不能在纸上擅定为 4 或 8。C 的字符常量 'A' 具有 int 类型，sizeof 'A'=sizeof(int)；字符串 "A" 的数组则有两个 char 元素。

相同内容的字符串字面量是否共享存储是未指定的，不能用指针相等作为通用文本相等测试。下面三个 %c 参数还假定所用基本执行字符值可由 int 表示，使 char 参数提升为 int；这不要求把所有 C 字节定为八位，也不要求具体 ASCII 数值。

#include <stdio.h>
#include <string.h>
int main(void) {
    char a[] = "cat";
    const char *p = "cat";
    char raw[3] = "cat";
    a[0] = 'b';
    printf("%zu %zu %s %s\n", sizeof a, strlen(a), a, p);
    printf("%zu %c%c%c\n", sizeof raw, raw[0], raw[1], raw[2]);
    return 0;
}

逐步推导的例题

追踪完整例子的 a、p、raw，区分合法数组修改、静态字面量与无终止符数组。假定输出正常成功；没有实际执行。

  1. a 初始有四个元素 [c,a,t,0]。a[0]='b' 修改独立数组，变成 [b,a,t,0]；sizeof a=4，strlen(a)=3。
  2. p 指向字面量 [c,a,t,0]，内容仍为 cat。修改 a 没有改变它，%s 的两个实参都满足终止字符串约定。
  3. raw[3]="cat" 合法初始化为 [c,a,t]，不含终止零。sizeof raw=3；代码用三个 %c 分别输出，不把它传给 %s。
  4. 把这些参数组合起来，首行预计为 4 3 bat cat，次行为 3 cat。修改字面量、测量地址或调用 raw 的 strlen 都不在该例中。

预期输出两行为 4 3 bat cat 和 3 cat。a 的内容可改、p 所指字面量不可改、raw 的逐元素读取可行但字符串访问约定不成立。

用纸笔和正文动手试一试

画出 char x[5]="Hi"; char y[2]="Hi"; const char *z="Hi"; 三个声明的内容。区分可说明 sizeof 与字符串长度的对象，并判定 x[0]='B'、z="Bye"、z[0]='B'。

查看提示

Hi 的两个基本字符后还有终止零。明确指定的数组大小不够时，字符数组初始化可以不包括终止元素。

查看解答

x=[H,i,0,0,0]，sizeof x=5，strlen(x)=2。y=[H,i]，sizeof y=2，不满足 strlen(y) 的前提。sizeof z 是指针大小，strlen(z)=2。可以修改 x[0] 并给 z 重新赋值。修改 z[0] 违反 const 访问约束，需要诊断；去掉 const 后修改字面量仍是未定义行为。

常见误解与反例

C 字面量元素类型为 char，所以可以修改；sizeof 指针还能告诉我们字符串所占空间。

元素类型和禁止修改字面量是两条不同规则。char *p="cat" 的 p[0] 修改是未定义行为，sizeof p 是指针对象大小。char a[]="cat" 是独立数组，sizeof a=4 且可以修改 a[0]，应与前述反例区分。

检查理解

char s[3]="cat"; 在 C11 中声明本身一定错误吗？

查看答案与理由

不是。允许初始化三个位置而不存终止零。

没有空间时，字面量的终止元素可以不参与初始化；字符串操作的安全性是另一项条件。

const char *p 是否也禁止 p="dog"？

查看答案与理由

不禁止。

const 在这里修饰所指 char，指针对象 p 本身不是 const。

返回函数的自动数组 char local[]="ok" 的地址后，还能使用它吗？

查看答案与理由

不能。

离开函数块后自动对象的生命周期结束；存在终止零并不足以使访问有效。

进一步探索

进一步分析：字面量 "AB\0CD" 含 A、B、零、C、D 及自动添加的末尾零，共六个 char。用 char s[] 初始化时，sizeof s=6，而 strlen(s)=2。第一个字符串之后的 C、D 仍是数组内容。因此不能概括成每个字符串字面量都是没有内部零的一段可见文本。还应考虑字面量可能合并存储；应通过有效范围内的元素比较判断文本，不能仅凭两个指针相同或不同就证明不同声明的完整内容。

小节 6.3

标准字符串函数

strcpy、strncpy、memcpy 与 memmove 分别需要什么前提？

预备知识与学习目标

预备知识

  • 字符串复制关心终止零，字节复制关心指定的元素数量。目标指针本身并不携带其真实容量。
  • 重叠表示源和目标访问区间有公共位置。应检查完整区间，而不是只看两个起始指针不同。
  • 准备检查：cat 有三个非零字符，但完整 C 字符串复制需要四个位置。

学习目标

  • 分别陈述四种复制函数的读写范围、终止与重叠约定。
  • 逐位置追踪补零与没有终止零的结果。
  • 用容量、不变式和复制方向解释条件为何必要。

strcpy 与 strncpy 的名字不能代替约定

strcpy 的源必须是有效终止字符串。源长度 L 时，目标要有 L+1 个可写元素，复制包括终止零，源目标不得重叠。它没有目标容量参数，也不会自动分配存储。从测量长度到复制期间还要求源内容保持稳定，不能把一次长度检查当成并发修改下的保证。

strncpy(dst,src,n) 写 n 个目标位置。源在 n 以内遇零时，后续目标位置补零；源的前 n 个字符都非零时，只复制 n 个字符，不附终止零。应有相应可读源前缀、n 个可写目标元素并且区间不重叠。名字中有 n 不意味着一定返回完整字符串。

字节复制不自动处理终止符

memcpy(dst,src,n) 复制 n 个字节，包括内部零，不补终止零。源、目标各有真实有效的 n 字节范围，且不能重叠。C11 的一般有效指针条件不会仅因 n=0 就自动取消，不可概括成 memcpy(NULL,NULL,0) 总是允许。

memmove 允许有效源目标区间重叠，其语义如同先复制到不重叠的临时数组再复制回来，但不要求实现真的分配临时数组。向右移动时，从右向左可保护尚未读取的旧值；向左移动时可从左向右。允许重叠不等于忽略容量、生命周期和有效地址。

先明确结果所占空间

代码中的 pad[5] 经 strncpy 成为 Q、零、零、零、零；raw 是 W、X、Y；copy 是 X、零、Y。读取这三种结果的方式不同。pad 可作为终止字符串读取，而 raw 的三个字符以及 copy 内部零之后的 Y，需要另知长度并逐元素读取。若未经检查就把函数名称当作安全保证，会遗漏不终止、补零成本和重叠问题。

逐项在纸上标出写入数量及所需读取数量，才能比较函数：strcpy 到第一个零为止；strncpy 最多读取 n 个源位置，遇零后停止源字符复制，但写满 n 个目标位置；memcpy/memmove 则复制指定的 n 个位置。本文不声称提供目标扩容、分配失败处理或并发安全。完整例子只使用足够大的固定数组和仍在生命周期内的源；不把未定义行为变体的输出列为答案。

#include <stdio.h>
#include <string.h>
int main(void) {
    char dst[5];
    char raw[3];
    char pad[5];
    char overlap[6] = "ABCD";
    const char bytes[3] = {'X', '\0', 'Y'};
    char copy[3];
    strcpy(dst, "cat");
    strncpy(raw, "WXYZ", sizeof raw);
    strncpy(pad, "Q", sizeof pad);
    memmove(overlap + 1, overlap, 5);
    memcpy(copy, bytes, sizeof copy);
    printf("%s %c%c%c\n", dst, raw[0], raw[1], raw[2]);
    printf("%d %d %d %d\n", pad[1] == 0, pad[2] == 0,
           pad[3] == 0, pad[4] == 0);
    printf("%s %c %d %c\n", overlap, copy[0], copy[1] == 0, copy[2]);
    return 0;
}

逐步推导的例题

追踪完整例子中的五次复制，写出每个有效存储结果和预期输出。假设正常输出成功；只在纸上推演。

  1. strcpy 后 dst 的前四个位置是 c、a、t、零；第五个位置没有被初始化或被这次复制写入，不指定其值，%s 也不会读它。strncpy 的 raw 只写入 W、X、Y，不含终止零。首行通过 %s 读取 dst，通过三个 %c 逐项读取 raw。
  2. strncpy(pad,"Q",5) 写 Q 后补四个零。四项零比较都为 1，所以第二行预计为 1 1 1 1。
  3. memmove 的五字节源包括原终止零，右移后 overlap 成为 A、A、B、C、D、零，字符串为 AABCD。
  4. memcpy 保留 X、零、Y。%c 读 X、Y，内部零比较为 1。首行预计 cat WXY，末行预计 AABCD X 1 Y；不读取任何对象外位置。

预期三行依次为 cat WXY、1 1 1 1、AABCD X 1 Y。字节结果与字符串终止条件分别检查，没有真实运行。

用纸笔和正文动手试一试

对 char a[5]="ABCD"; 执行 memmove(a,a+1,4)，画出结果。对另一个 char b[4] 执行 strncpy(b,"Hi",4)，写出四个位置。能说把重叠复制改成 memcpy 后输出仍相同吗？

查看提示

a+1 的四个源位置是 B、C、D、零。strncpy 的短源会触发补零，直到写满 n 个目标位置。

查看解答

a 成为 [B,C,D,0,0]，字符串为 BCD，最后一个原来的零没有被覆盖。b 成为 [H,i,0,0]。a 的源和目标重叠，改成 memcpy 是未定义行为，不能把预测输出 BCD 当作答案。

常见误解与反例

strncpy 总会添加 NUL，memmove 还会自动取得所需空间。

把 "WXYZ" 以 n=3 复制到 raw[3]，结果只有 WXY，没有 NUL。若 a 只有五个位置，memmove(a+1,a,5) 的目标最后一个位置就在对象外。支持重叠不等于检查存储容量。

检查理解

strncpy(d,"Q",5) 写入多少个位置？

查看答案与理由

五个。

Q 后写入终止零和额外补零，共四个零，填满 n 个位置。

memcpy 也复制第一个零之后的字节吗？

查看答案与理由

若在指定的 n 范围内，就会复制。

它是字节复制函数，不搜索字符串终止符。

观察到重叠区间的 memcpy 工作正常，是否就满足标准约定？

查看答案与理由

不是。

重叠是未定义行为的条件；一次实现观察不能建立 C11 保证。

进一步探索

进一步分析：向右重叠移动一个位置时，简单从左向右赋值会在 a[1]=a[0] 后，通过 a[2]=a[1] 再复制已经改成 A 的值，丢失原来的 B。从源末尾往右侧目标复制，可用「不覆盖尚需读取的源」不变式证明该方向的正确性。左移则适合从前向后。memmove 无须由调用者实现方向选择，就按约定提供与原来 n 字节相同的结果。strcpy 前检查 L+1≤cap 时，应结合有效且稳定的源字符串，使用 L<cap 避免加一溢出。将 L+1 用作动态分配大小时，先拒绝 L==SIZE_MAX，并处理分配失败。这些是约定分析与纸上证明，不是地址、速度或未定义行为测量。

小节 6.4

缓冲区大小与截断处理

把 planet 输出到五个位置的缓冲区，返回值是已存的四个字符，还是所需的六个字符？

预备知识与学习目标

预备知识

  • 缓冲区容量 cap 是实际可写的 char 位置数。字符串内容需要 L 个位置，终止符另需一个；要存字符串，须有 cap>0 且 L<cap。
  • 格式化输出的 %s 读取有效源字符串。snprintf 的 n 是目标写入上限，不能代替检查源的有效性和可读边界。
  • 准备检查：画五个位置，最后一个留给终止零，内容最多四个位置。用不同颜色标记所需的六个位置与实际存入的四个。

学习目标

  • 区分 snprintf 返回的所需长度与实际存入量。
  • 判定负错误、n=0、n=1 及准确的截断边界。
  • 说明截断策略以及编码、格式字符串和重叠条件。

返回所需量，而不是已经存入的量

C11 的 snprintf(s,n,format,...) 在 n>0 且输出正常时，最多写 n−1 个内容位置，并在末尾添加零。目标必须真实提供 n 个可写位置。n=0 时不写任何内容，且这个特殊情况允许 s=NULL。n=1 且内容非空时，不存内容，仅在首位置留下零。它不自动扩展字符串空间。

正常返回 r 表示缓冲区足够时本应写入的内容长度，不包括末尾终止零；编码错误返回负值。确认 r≥0 后，r<n 表示完整保存，r≥n 表示截断。n=0 且 r=0 时，0<0 仍为假，不能说已写入空字符串。下面基本字符串的预期分析还假定所需长度可由 int 表示且格式化输出正常成功。

容量边界要严格比较

把 "planet" 输出到五个位置的 out，正常 r=6，存储为 p、l、a、n、零。strlen(out)=4，不能把返回的 6 当作已复制位置数来读取数组。固定例子的 sizeof out=5 可由 int 表示，所以比较 (int)sizeof out 安全；任意 size_t 容量缩成 int，不能未经这一条件就使用。

一般函数先处理 r<0，再用保持数值的类型比较非负 r 和 cap。例如 <stdint.h> 的 uintmax_t 可表示 size_t 值和非负 int 值，因而可使用 (uintmax_t)r<(uintmax_t)cap。若未排除负值便转换成无符号值，错误会看起来像很大的长度。负返回后的缓冲区不能当作成功的完整字符串读取，应转入错误策略。

终止字符串仍可能丢信息

接受截断、拒绝输入，还是验证后取得更大空间再试，是程序策略。静默截断标识符或文件路径，可能把不同原文变成相同前缀，此时可选择报错。调用两次以先测量所需长度再分配，还要分别检查正的额外空间、长度加一的溢出、分配失败，以及两次调用之间源和格式实参的稳定性。

即使有终止零，截在八位字节 UTF-8 多字节序列中间仍可能得到无效文本。输出上限是字节存储规则，不是 Unicode 字符边界或安全策略的保证。不要直接把输入用作格式字符串，应如 snprintf(out,cap,"%s",input) 使用固定格式；它仍要求 input 是有效字符串。snprintf(buf,cap,"%s",buf) 这样的源目标重叠在 C11 中是未定义行为，所以例子使用独立字面量作为源。

#include <stdio.h>
#include <string.h>
int main(void) {
    char out[5];
    int r = snprintf(out, sizeof out, "%s", "planet");
    if (r < 0) {
        puts("encoding error");
        return 1;
    }
    printf("%d %zu %s\n", r, strlen(out), out);
    if (r >= (int)sizeof out) puts("truncated");
    else puts("complete");
    int needed = snprintf(NULL, 0, "%s", "planet");
    if (needed < 0) return 1;
    printf("%d\n", needed);
    return 0;
}

逐步推导的例题

逐步追踪完整例子中 planet 写入 out[5]，并与 NULL、容量 0 的测量调用比较。假设输出正常成功；没有实际运行。

  1. planet 需要生成六个非零字符，正常返回 need=6；out 的实际容量为 5。
  2. 目标最多容纳四个生成字符和一个终止零，所以内容为 plan，strlen(out)=4。首行预期为 6 4 plan。
  3. 先判定 need<0，再比较非负 need 与容量。6≥5，所以判断截断，第二行预期为 truncated。
  4. snprintf(NULL,0,"%s","planet") 不写目标，但测量正常所需量为 6，末行预期为 6。NULL 例外只来自这个函数的 n=0 明文约定。

预期三行为 6 4 plan、truncated、6。返回所需量 6、存入生成字符 4 和容量 5 的含义不同。

用纸笔和正文动手试一试

对 Hello 分别使用容量 0、1、5、6，求正常返回值、写入内容与完整或截断状态。假设目标范围真实有效，容量 0 时使用允许的 NULL。

查看提示

所需量为 5，最多存 n−1 个生成字符，并且完整判定是严格的 r<n。

查看解答

四种容量的正常返回值都为 5。容量 0 不写内容，不能称为已存字符串；容量 1 只存 [0]，截断；容量 5 存 Hell 加零，截断；容量 6 存 Hello 加零，完整。r==n 仍表示空间不足。

常见误解与反例

只要 snprintf 添加 NUL，截断、安全性和 Unicode 就都安全了。

out[5] 虽以 plan 和零结尾，仍没有完整保存 planet。切断多字节编码会破坏有效 UTF-8，标识符前缀碰撞也是另一项问题。传入超过实际空间的 n，或让源目标重叠，都不能因函数名称而得到正当化。

检查理解

正常 r=5、n=5 时，是否已完整保存？

查看答案与理由

没有，是截断。

需要终止符位置，所以完整条件是严格的 r<n。

snprintf(NULL,0,...) 正常返回长度 6，是否向 NULL 写入了终止零？

查看答案与理由

没有。不写任何内容。

n=0 是可以不写目标而仅计算所需长度的明确例外。

不检查 r<0 就转换为 size_t，能把它当所需长度吗？

查看答案与理由

不能。

负错误可能变成很大的无符号值，应先分离错误分支。

进一步探索

证明：正常返回 L≥0 且 n>0 时，存入内容量为 min(L,n−1)，加上终止位置，写入数为 min(L,n−1)+1≤n。要保留全部内容，须有 L≤n−1，即 L<n；这与 n=0 的不写情况分开。容量 5 的截断策略可能将 planet 与 plank 都变成 plan，因此原文到存储结果的映射不是单射。要保持标识符唯一性，须拒绝截断或另行处理碰撞。用 L+1 作分配大小前，检查 L 能否由 size_t 表示及加法溢出；成功的测量也不保证到下一次输出时源保持不变或分配成功。这里内容量指 snprintf 生成的输出字符数，仅在生成输出没有内部 NUL 时才等于 strlen 所计长度。例如对有效两位置数组正常执行 snprintf(buf,2,"%c",0)，返回 1，buf 为 [0,0]，而 strlen(buf)=0。这个反例只按约定在纸上追踪，没有执行。
