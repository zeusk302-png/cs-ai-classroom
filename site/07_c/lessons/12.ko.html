소단원 12.1

함수포인터 문법

같은 두 숫자를 더할지 뺄지를 함수 인자로 고를 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수 원형

  • 포인터와 NULL

  • 정수와 반환값

학습 목표

  • 함수 포인터 선언의 괄호를 읽는다.

  • 함수 주소 선택과 호출을 손 추적한다.

  • 호환 타입과 빈 포인터 검사를 구별한다.

코드도 선택할 대상으로 만든다

int (*op)(int, int)는 int 두 개를 받고 int를 반환하는 함수를 가리키는 포인터 op다. (*op)의 괄호가 중요하다. int *op(int, int)는 int 포인터를 반환하는 함수 op를 선언하므로 뜻이 다르다.

typedef int (*IntOp)(int, int)는 그 포인터 타입에 IntOp라는 이름을 붙인다. typedef는 새 기능이나 실행 중 검사를 추가하지 않는다. 모든 예제는 C11의 명시적인 함수 원형을 사용하고, 입력과 결과가 int에 표현 가능한 작은 값이라는 전제를 둔다.

선택과 호출은 두 단계다

IntOp op = add는 add를 선택하며 이 줄 자체가 덧셈을 수행하지 않는다. op(4, 3)에서 선택한 함수가 실제로 호출되어 값을 반환한다. 평범한 함수 이름은 이런 문맥에서 함수 포인터로 변환된다. &add로 주소를 명시해도 된다.

같은 타입의 sub를 op에 대입하면 다음 호출의 행동을 바꿀 수 있다. op(4, 3)과 (*op)(4, 3)는 유효한 같은 대상 호출 표현이다. 주소를 숫자로 인쇄하거나 포인터의 크기를 가정할 필요는 없다.

빈 값과 잘못된 타입을 막는다

선택한 함수가 없을 때 NULL을 둘 수 있지만 빈 함수 포인터를 호출하면 안 된다. if (op != NULL)처럼 검사하고, 없을 때의 동작을 호출자와 약속한다. 아래 활동의 약속은 호출을 건너뛰는 것이다.

함수 포인터 타입에는 반환 타입과 인자 수·타입이 포함된다. 전혀 다른 함수 타입을 강제 변환한다고 안전해지는 것은 아니다. 호환되지 않는 타입으로 실제 함수를 호출하는 것은 C의 정의되지 않은 동작이므로 예상 결과를 계산하는 예제로 쓰지 않는다.

중간 과정을 따라가는 예제

다음 완전한 예제를 callback_demo.c에 저장하는 후속 실습을 할 수 있다. 여기서는 실행하지 않고 손 추적한다. 

#include <stdio.h>
typedef int (*IntOp)(int, int);
static int add(int a, int b) { return a + b; }
static int sub(int a, int b) { return a - b; }
int main(void) {
    IntOp op = add;
    int x = op(4, 3);
    op = sub;
    int y = (*op)(4, 3);
    printf("%d %d\n", x, y);
    return 0;
}

  1. op는 처음 add를 가리킨다. 첫 호출의 인자는 4와 3이고 반환값은 4+3=7이다.

  2. op = sub 뒤에는 sub를 가리킨다. 이전 x는 바뀌지 않고 새 호출은 4−3=1을 y에 저장한다.

  3. 예상 출력은 7 1이다. 실제 컴파일·실행 로그는 아니다.

x=7, y=1이다. 포인터 대입이 함수 호출을 대신 수행한 것은 아니다.

종이와 본문으로 직접 해보기

예제의 두 호출 뒤 op = NULL로 바꾸고 if (op != NULL) 안에서만 호출한다고 하자. 세 번째 호출이 일어나는가? 별도 입력 8과 2로 sub를 선택한 호출값은?

힌트 보기

포인터 검사와 산술을 독립적으로 추적한다.

풀이 보기

NULL 검사에서 조건이 거짓이라 세 번째 호출은 건너뛴다. 별도 sub(8,2)의 값은 6이며 x와 y는 새로운 대입이 없으면 7과 1을 유지한다.

오해와 반례

함수 포인터에 주소를 넣으면 함수가 즉시 실행되고 모든 함수 주소는 같은 타입이다.

대입은 대상 선택이며 괄호를 붙인 호출이 실행이다. 반환 타입과 인자 타입이 다른 함수는 같은 호출 계약이 아니다.

자기점검

IntOp op = &add와 op = add는 여기서 같은 대상을 고르는가?

답과 이유 보기

그렇다.

함수 이름의 포인터 변환과 명시적인 주소 얻기 모두 add를 선택한다.

int *op(int,int)는 함수 포인터 변수 선언인가?

답과 이유 보기

아니다.

int 포인터를 반환하는 함수 선언이다. 포인터 변수에는 (*op) 괄호가 필요하다.

NULL 함수 포인터 호출에서 결과0을 기대해도 되는가?

답과 이유 보기

안 된다.

함수가 없음을 나타내는 값이며 호출의 정상 반환값이 아니다.

한 단계 더

IntOp ops[2] = {add, sub}처럼 선택표를 설계하라. 입력4/3의 인덱스0은7, 인덱스1은1이다. 인덱스2는 배열 밖이므로 호출 전에 범위0≤index<2를 검사해야 한다. 포인터 타입 검사와 배열 경계 검사는 별도다.

소단원 12.2

qsort와 comparator

정렬 함수가 요소의 타입을 몰라도 순서를 결정할 수 있는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 배열 요소와 sizeof

  • const void*

  • 비교 연산의0/1

학습 목표

  • qsort의 크기와 비교 함수 계약을 설명한다.

  • 비교 결과의 부호를 정확히 만든다.

  • 동일 요소 순서·연산 오버플로 한계를 구별한다.

배열의 모양과 순서 규칙을 따로 전달한다

C11 <stdlib.h>의 qsort는 시작 주소, 요소 개수, 요소 하나의 바이트 크기, 비교 함수 포인터를 받는다. int 배열이면 sizeof values[0]을 요소 크기로 쓴다. 전체 배열의 sizeof를 요소 크기로 쓰지 않는다.

배열이 실제 배열인 문맥에서 sizeof values / sizeof values[0]은 요소 개수를 구한다. 함수의 배열 매개변수는 포인터로 조정되므로 같은 식으로 개수를 얻는다고 일반화하면 안 된다. 이 예제는 main의 실제 배열을 사용한다.

비교 함수가 지켜야 할 약속

int cmp(const void *pa, const void *pb)는 두 요소를 가리키는 포인터를 받는다. 실제 요소가 int라는 계약에 따라 const int*로 바꾸어 읽는다. 첫 값이 작으면 음수, 같으면0, 크면 양수를 반환한다. 정확히−1/0/1만 반환해야 한다는 뜻은 아니지만 아래는 그 세 값으로 구현한다.

같은 객체들을 다시 비교할 때 결과가 일관되어야 하고 배열의 전체 순서를 정의해야 한다. comparator에서 배열 요소를 바꾸거나 무작위로 답하면 규약이 깨진다. 단순히 x > y만 반환하면 작음과 같음이 모두0이 되어 올바른 세 방향 비교가 아니다.

빼기 대신 부호를 계산한다

return x - y는 두 값 자체가 int에 들어가더라도 차이가 범위를 넘을 수 있다. 비교 연산의 결과는0 또는1이므로 (x > y) - (x < y)는−1/0/1 범위를 벗어나지 않는다. 이를 큰 int 경계값에도 쓸 수 있다.

qsort는 배열을 직접 재배열하고 반환값은 void다. 비교상 같은 요소들의 상대 순서는 미지정이므로 안정 정렬을 보장하지 않는다. 이름에서 특정 알고리즘이나 고정 비교 호출 횟수를 약속한다고 해석하지 않는다.

중간 과정을 따라가는 예제

다음 정렬 코드를 손 추적하라. 

#include <stdio.h>
#include <stdlib.h>
static int cmp_int(const void *pa, const void *pb) {
    int x = *(const int *)pa;
    int y = *(const int *)pb;
    return (x > y) - (x < y);
}
int main(void) {
    int values[] = {3, -1, 3, 2};
    size_t n = sizeof values / sizeof values[0];
    qsort(values, n, sizeof values[0], cmp_int);
    for (size_t i = 0; i < n; ++i)
        printf("%d%s", values[i], i + 1 == n ? "\n" : " ");
    return 0;
}

  1. n은 요소 4개다. cmp_int에서 3과 −1이면 1−0=1, −1과 3이면 0−1=−1, 3과 3이면 0−0=0이다.

  2. 오름차순과 비교 규약에 따라 정렬된 값들은 −1, 2, 3, 3이다. 실제 내부 비교 순서나 교환 횟수는 계산하지 않는다.

  3. 예상 표시값은 −1 2 3 3이다. 같은 3 두 개를 구별하는 추가 기록이 있다면 상대 순서를 보장할 수 없다.

정렬값은[-1,2,3,3]이고 qsort가 별도 정렬 배열을 반환한 것은 아니다.

종이와 본문으로 직접 해보기

x=INT_MIN/y=INT_MAX라고 하자. 안전 비교식의 값은? 순서를 내림차순으로 바꾸려면 식을 어떻게 바꾸는가?

힌트 보기

정수값을 서로 빼지 말고 비교의 참/거짓 값을 먼저 적는다.

풀이 보기

첫 경우 0−1=−1이다. 내림차순은 (x < y) - (x > y)로 바꾸며 예제 배열의 값은 [3,3,2,-1]이다. INT_MIN−INT_MAX 자체를 int에서 계산하는 대안은 사용하지 않는다.

오해와 반례

comparator는 크면1, 아니면0을 반환하면 되고 qsort의 같은 값은 입력 순서를 유지한다.

작음/같음/큼의 세 부호와 일관된 순서가 필요하다. 같은 요소 순서는 미지정이라 별도 안정성 보장이 필요하다.

자기점검

qsort의 size에 sizeof values 전체를 넣어도 되는가?

답과 이유 보기

이 예제에서는 안 된다.

size는 요소 하나의 크기이고 n은 요소 개수다.

cmp_int(같은 값,같은 값)의 결과는?

답과 이유 보기

0이다.

두 비교가 모두 거짓이다. 함수 인자는 실제로 요소 주소를 받는다.

n=0이면 비교 함수가 호출되는가?

답과 이유 보기

호출되지 않는다.

C11 정렬 규약은 재배열하지 않으며 포인터 인자 유효성 조건은 여전히 지켜야 한다.

한 단계 더

이름 A/B와 같은 점수3을 가진 두 레코드를 점수만 비교하면 A/B 상대 순서를 보장하지 못한다. 점수 다음 고유 ID를 비교하는 명시적 2차 규칙과 안정 정렬 보장을 구별하라. 2차 규칙은 비교상 동등함 자체를 줄이는 설계다.

소단원 12.3

callback과 context

반복 처리 함수가 사용자별 누적 상태를 전역 변수 없이 바꾸려면 어떻게 할까?

준비 개념과 학습 목표

준비 개념

  • struct와 포인터

  • 배열 길이

  • 동기 함수 호출

학습 목표

  • callback의 호출 주체와 시점을 설명한다.

  • void* context를 올바른 객체 타입으로 복원한다.

  • 타입·수명·호출 보관 조건을 명시한다.

함수에 작업을 맡기고 상태도 함께 넘긴다

callback은 다른 함수가 약속한 시점에 호출하도록 전달하는 함수다. 아래 visit는 각 정수에 cb를 한 번씩 호출한다. 방문 순서와 호출 횟수는 이 자체 visit 코드의 계약이며 모든 callback API가 같은 것은 아니다.

context는 작업에 필요한 객체를 가리키는 값이다. cb(value, ctx)로 전달하면 학생별 합계를 전역 하나에 저장하지 않아도 된다. 같은 함수 add_stat에 다른 Stats 주소를 넘기면 서로 다른 누적 상태를 사용할 수 있다.

void*의 복원에는 실제 타입이 필요하다

C의 void*는 객체 포인터를 전달하고 원래 객체 타입으로 복원하는 통로다. 아무 객체나 Stats로 읽어도 된다는 허가가 아니다. add_stat은 ctx가 실제 유효한 Stats 객체를 가리킨다고 약속하고 Stats*로 복원한다.

함수 포인터와 context 객체 포인터는 별도 인자다. 모든 함수 주소를 void*로 바꾸는 것이 이식 가능한 표준 C 설계라고 가정하지 않는다. 이 예제는 cb를 함수 포인터 타입으로, ctx를 객체 포인터로 각각 전달한다.

동기 계약과 수명을 연결한다

아래 visit는 호출 중 순서대로 실행하고 cb나 ctx를 저장해 나중에 호출하지 않는다. main의 Stats 객체가 visit가 돌아올 때까지 살아 있어 안전하게 사용할 수 있다. 비동기 등록 API라면 나중 호출까지의 객체 수명을 다시 설계해야 한다.

예제의 계약은 a가 n개의 int에 접근 가능하고 cb/ctx가 유효하며 누적값과 count가 int 범위 안이라는 것이다. n=0에서는 배열을 읽지 않지만 이 예제는 여전히 유효한 실제 배열·함수·객체 주소를 전달하는 방식으로 활동한다.

중간 과정을 따라가는 예제

다음 자체 동기 방문 함수의 상태를 손 추적하라. 

#include <stddef.h>
#include <stdio.h>
typedef void (*Visitor)(int, void *);
typedef struct { int sum; int count; } Stats;
static void add_stat(int value, void *ctx) {
    Stats *s = ctx;
    s->sum += value;
    s->count += 1;
}
static void visit(const int *a, size_t n, Visitor cb, void *ctx) {
    for (size_t i = 0; i < n; ++i) cb(a[i], ctx);
}
int main(void) {
    int a[] = {2, 4, 6};
    Stats s = {0, 0};
    visit(a, 3, add_stat, &s);
    printf("%d %d\n", s.sum, s.count);
    return 0;
}

  1. 처음 sum과 count는 0과 0이다. 첫 callback은 2를 받아 2와 1이 된다.

  2. 다음 4 뒤에는 6과 2, 마지막 6 뒤에는 12와 3이다. 세 호출은 같은 &s를 전달받는다.

  3. 예상 표시값 12 3은 함수가 반환한 값이 아니라 가리킨 Stats 객체의 변경 결과다. 실제 코드 실행은 하지 않았다.

s.sum=12, s.count=3이다. visit와 callback 자체의 반환 타입은 void다.

종이와 본문으로 직접 해보기

예제 뒤 같은 a에 대해 새 Stats b={10,1}로 visit(a,2,add_stat,&b)를 호출하면 b는? 별도 Stats z={0,0}에 visit(a,0,add_stat,&z)를 하면?

힌트 보기

앞 2개는 2와 4다. n=0은 반복문 진입 조건부터 확인한다.

풀이 보기

b의 sum은 10+2+4=16, count는 1+2=3이다. z는 callback이 0회라 sum과 count가 0과 0을 유지한다. 기존 s는 새 호출에서 전달하지 않아 12와 3으로 남는다.

오해와 반례

void*를 쓰면 모든 타입과 수명 검사를 자동으로 하고 callback은 항상 비동기다.

실제 객체 타입·수명은 인터페이스 계약으로 지켜야 한다. 이 visit는 동기이며 등록 후 나중 호출하는 API와 구별한다.

자기점검

add_stat이 바꾸는 것은 포인터 변수 복사인가 Stats 객체인가?

답과 이유 보기

Stats 객체다.

ctx와 s 포인터 값은 전달되지만 ->로 가리킨 객체를 변경한다.

ctx가 이미 수명이 끝난 Stats 주소라면?

답과 이유 보기

계약 위반이다.

그 객체를 정상적으로 역참조할 수 없다. 캐스팅이 수명을 늘리지 않는다.

표준 C11 qsort에 ctx 인자가 있는가?

답과 이유 보기

없다.

qsort comparator는 const void* 두 인자다. qsort_r 등은 플랫폼별 계약을 따로 확인해야 한다.

한 단계 더

NULL callback을 허용하는 새 계약을 설계하려면 visit 입구에서 검사하고 어떻게 실패를 알릴지 정하라. 단순히 cb를 NULL로 전달해 기존 visit를 호출하는 활동은 유효하지 않다. API를 바꾸면 반환 상태·호출 횟수 규칙도 문서화한다.

소단원 12.4

인터페이스의 타입 계약

함수 모양이 맞아도 잘못된 입력이나 끝난 객체를 넘기면 안전할까?

준비 개념과 학습 목표

준비 개념

  • 함수 포인터 타입

  • 입력 조건

  • 상태 코드와 출력 포인터

학습 목표

  • 컴파일 시 타입과 실행 시 의미 조건을 나눈다.

  • 실패할 때 출력값의 보존 계약을 추적한다.

  • 호환되지 않는 강제 호출의 위험을 설명한다.

타입은 인터페이스의 일부다

typedef int (*ScaleFn)(int, int*)는 int 입력과 int 출력 객체 포인터를 받고 int 상태를 반환하는 함수 포인터 타입이다. 다른 인자 수나 반환 타입의 함수는 이 계약의 구현이 아니다. 명시적인 prototype은 호출의 타입 점검에 도움이 된다.

그러나 타입만으로 입력이0부터100인지, out이 NULL인지, 가리킨 int가 아직 살아 있는지는 보장되지 않는다. 계약에는 입력 범위·소유권·수명·변경 시점과 반환 상태의 뜻도 필요하다. 정수 상태0이 성공이라는 약속은 이 예제에서 정하는 것이다.

실패와 출력 변경을 함께 정한다

아래 double_checked는 out==NULL 또는 v<0 또는 v>100이면 상태1을 반환하고 출력값을 변경하지 않는다. 성공이면2*v를 저장하고 상태0을 반환한다.0≤v≤100이면 결과≤200이라 표준 C int 최소 범위 안에서 계산할 수 있다.

out이 NULL이 아니어도 쓰기 가능한 살아 있는 int를 가리켜야 한다. 임의 숫자 주소나 수명이 끝난 주소를 전달하면 함수 내부의 NULL 검사만으로 안전을 보장하지 못한다. 실패 출력 보존은 검사 후에만 대입하는 코드 순서로 구현된다.

강제 변환으로 계약을 숨기지 않는다

C에서는 함수 포인터를 다른 함수 포인터 타입으로 바꾸었다가 원래 타입으로 되돌리는 규칙이 있다. 하지만 바뀐 호환되지 않는 타입으로 함수를 호출하면 정의되지 않은 동작이다. 캐스트를 넣어 경고를 없앴다는 사실이 올바른 호출의 증거는 아니다.

반환 타입·인자 타입이 맞는 구현도 의미 계약을 달리할 수 있다. 음수도 허용하거나 실패 때 out을0으로 바꾸는 함수를 대체하려면 호출자의 기대까지 확인해야 한다. 타입과 행동 계약을 각각 검토한다.

중간 과정을 따라가는 예제

다음 완전한 예제의 성공과 실패를 손 추적하라. 

#include <stdio.h>
typedef int (*ScaleFn)(int, int *);
static int double_checked(int v, int *out) {
    if (out == NULL || v < 0 || v > 100) return 1;
    *out = 2 * v;
    return 0;
}
int main(void) {
    ScaleFn f = double_checked;
    int out = 99;
    int ok = f(3, &out);
    printf("%d %d\n", ok, out);
    int bad = f(-1, &out);
    printf("%d %d\n", bad, out);
    return 0;
}

  1. out의 초기값 99와 성공 상태·결과를 나눈다. f(3,&out)는 검사 통과 후 6을 저장하고 0을 반환한다.

  2. 첫 예상 줄은 0 6이다. f(-1,&out)는 v<0으로 대입 전 상태 1을 반환하므로 out은 6을 보존한다.

  3. 두 번째 예상 줄은 1 6이다. 반환 상태 1이 출력값 1이라는 뜻은 아니다.

성공 뒤 상태0/출력6, 실패 뒤 상태1/출력6이다. 실제 컴파일·실행 결과는 아니다.

종이와 본문으로 직접 해보기

별도 살아 있는 int x=7을 두고 f(100,&x), 이어 f(101,&x), 이어 f(2,NULL)을 추적하라.

힌트 보기

100은 경계 안,101은 경계 밖이다. NULL이면 출력 대입 전에 반환한다.

풀이 보기

첫 호출은 상태 0, x=200이다. 두 번째는 상태 1이며 x=200을 유지한다. 세 번째는 상태 1이며 x 주소를 넘기지 않았으므로 x=200을 유지한다. NULL을 정상 출력 객체라고 취급하지 않는다.

오해와 반례

함수 포인터 타입이 같거나 강제 변환이 되면 모든 대체가 안전하다.

같은 타입에도 입력 범위·실패 상태·출력 보존·수명 조건이 다를 수 있다. 호환되지 않는 함수 타입으로 강제 호출하는 것은 UB다.

자기점검

성공 상태0이 계산 결과0을 뜻하는가?

답과 이유 보기

아니다.

상태는 성공/실패를 알리고 결과는 *out에 저장한다.

같은 ScaleFn 타입이 입력 범위까지 자동 검증하는가?

답과 이유 보기

아니다.

prototype은 타입 모양이고0≤v≤100은 별도 의미 조건이다.

out이 NULL이 아니면 항상 안전하게 쓸 수 있는가?

답과 이유 보기

아니다.

살아 있고 쓰기 가능한 정확한 int 객체를 가리켜야 한다.

한 단계 더

같은 ScaleFn 타입의 triple_checked가 같은 실패 계약에서3*v를 저장한다고 정의해 보라. 입력100의 출력300은 int 최소 최대값32767보다 작다. 호출자가 반드시 두 배를 기대한다면 성공 타입이 같아도 대체가 잘못이다. 범위 조건과 행동 기대를 함께 적어라.
