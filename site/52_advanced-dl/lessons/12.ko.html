소단원 12.1

가설·baseline·ablation

새 부품을 두 개 넣어 좋아졌다면 어느 부품 덕분이라고 말할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 정확도와 분모

  • 훈련·검증·평가 분리

  • 평균과 조건 비교

학습 목표

  • 검증 가능한 가설과 비교 기준을 적는다.

  • baseline과 ablation의 서로 다른 질문을 설명한다.

  • 조합 표에서 조건부 차이와 상호작용을 계산한다.

AB가 baseline보다 좋아도 A에 B를 더하는 것이 도움이 될까?

앞 본문은 두 요소의 조합 표에서 단독 차이와 제거 차이를 구별했다. 이번 자체 표는 같은 평가 대상 100개·자료 판본·학습 및 탐색 예산·평가 규약을 고정했다고 가정한다. baseline의 정답 수는 60개, A는 65개, B는 62개, AB는 64개다. 각 값은 실제 학습 결과가 아닌 조건을 부여한 종이 자료다.

A의 단독 차이는 5%p이고 B의 단독 차이는 2%p다. B가 있는 조건에서 A를 넣는 차이는 AB−B=2%p이고, A가 있는 조건에서 B를 넣는 차이는 AB−A=−1%p다. AB는 baseline보다 4%p 높지만 A보다 1%p 낮다. 상호작용 차이 AB−A−B+baseline은 −3%p다. 이 표는 B의 모든 활용이 나쁘다는 보편 결론도 통계적으로 검증한 인과 효과도 아니다.

여러 실행을 비교할 때 같은 조건 번호를 연결한 차이도 보존한다. 별도 가상 두 조건에서 baseline은 70%, 80%이고 A는 각각 73%, 77%다. 두 방법의 평균은 모두 75%지만 짝 차이는 +3%p, −3%p다. A의 행을 뒤집어 baseline과 연결하면 +7%p, −7%p가 된다. 평균 차이는 우연히 그대로 0%p여도 조건별 관찰과 산포는 바뀐다. 숫자 정렬은 실험 조건의 짝을 대신하지 않는다.

비교 조건의 동일성은 표에 적힌 가정이며 실제 seed 하나로 보장되지 않는다. AB만 더 오래 훈련한 표에서는 같은 산술을 계산할 수 있어도 요소만 바뀐 비교라고 해석할 근거가 사라진다. 선택에 쓴 평가 자료를 최종 독립 평가로 다시 이름 붙이지 않고 선택 규칙·조건·미확인 범위를 기록한다.

먼저 질문과 비교 기준을 고정한다

가설은 무엇이 어떤 조건에서 달라질지 확인 가능한 형태로 적는 예상이다. 예를 들어 같은 자료와 학습 예산에서 특징 A를 넣으면 정확도가 높아지는지 묻는다. 모든 자료와 모든 모델에서 우수하다는 주장과 이 한 조건의 질문은 범위가 다르다.

Baseline은 비교의 기준인 기존 방법이다. 약하게 설정한 기준을 이기는 것만으로 좋은 새 방법이라고 판단하기 어렵다. 자료 분할·입력 처리·평가 지표·탐색 예산을 맞추고 기준 방법도 합리적으로 설정한다. 평가 정답을 보고 계속 고른 결과는 독립 최종 평가로 부르지 않는다.

제거 실험의 조건을 밝힌다

Ablation은 제안 방법의 요소를 제거하거나 대체하여 그 조건에서 결과가 얼마나 달라지는지 보는 실험이다. AB에서 A를 빼면 B가 되므로 AB−B가 A의 조건부 차이다. baseline에서 A를 넣은 A−baseline과 같은 숫자라고 미리 가정하지 않는다.

두 요소가 함께 있을 때의 변화가 단독 변화의 합과 다르면 상호작용을 의심할 수 있다. 그러나 다른 하이퍼파라미터나 훈련 예산도 함께 바뀌었다면 그 차이를 요소 하나의 효과로 고립하지 못한다. 실제 인과 해석에는 실험 설계와 변동의 검토가 필요하다.

한 표의 차이를 보편 성질로 바꾸지 않는다

한 번의 실행에서 높은 수치를 얻었다고 모든 무작위 초기값에서도 높다고 할 수 없다. 여러 실행의 결과·평균·변동과 선택 규칙을 함께 보고한다. 오차막대가 표준편차인지 평균의 표준오차인지 신뢰구간인지도 적어야 읽는 사람이 같은 뜻으로 해석한다.

아래 표는 손으로 만든 정확도 표다. 실제 자료나 신경망 실행에서 얻은 결과가 아니다. 작은 자료에 과적합해 보는 디버깅은 코드의 일부 오류를 찾는 데 도움이 될 수 있지만 전체 방법의 일반화 성능을 증명하지 않는다.

중간 과정을 따라가는 예제

같은 조건이라고 가정한 가상 정확도는 baseline 70%, A 74%, B 73%, AB 78%다. 단독 변화, AB에서의 제거 차이와 상호작용 차이를 구하라.

  1. A 단독 변화는 74−70=4%p, B 단독 변화는 73−70=3%p다. %p는 두 백분율을 뺀 퍼센트포인트다.

  2. AB에서 A를 제거하면 B이므로 차이는 78−73=5%p다. B를 제거하면 A이므로 78−74=4%p다.

  3. 상호작용 차이는 78−74−73+70=1%p다. 이는 이 표의 산술이며 통계적으로 검증된 효과가 아니다.

A 단독 4%p, B 단독 3%p, A 제거 5%p, B 제거 4%p, 상호작용 1%p다.

조건을 바꾸어 비교하기

전체 개선과 부품의 조건부 악화를 함께 쓴다

위 네 조건의 단독·제거 차이와 상호작용을 계산하라.

  1. A−baseline은 5%p, B−baseline은 2%p다.

  2. AB−B는 2%p, AB−A는 −1%p다.

  3. 64 − 65 − 62 + 60 = −3%p다.

AB가 baseline보다 높다는 사실과 B가 A에 더해질 때 낮아진다는 사실이 함께 성립한다.

비교할 점

전체 순위만 보고 부품마다 양의 기여를 배분하지 않는다.

평균을 보존해도 조건별 짝은 깨질 수 있다

조건 1의 baseline/A는 70%/73%, 조건 2는 80%/77%다. A의 두 행을 교환한 연결과 비교하라.

  1. 원래 두 차이는 +3%p와 −3%p이며 평균 차이는 0%p다.

  2. 잘못 연결한 차이는 +7%p와 −7%p이며 평균 차이 역시 0%p다.

  3. 조건별 차이의 절댓값 평균은 원래 3%p이고 잘못 연결하면 7%p다.

전체 평균 일치는 올바른 짝 기록의 증거가 아니다.

비교할 점

두 실행만으로 유의성이나 신뢰구간을 선언하지 않는다.

연습 1 · 값과 상태 예측

독립 변형 표에서 AB만 67 / 100으로 바꾸고 baseline 60, A 65, B 62는 유지한다. A와 B의 조합 조건 차이 및 상호작용을 구하라.

힌트 1

A 추가는 AB−B다.

힌트 2

B 추가는 AB−A다.

풀이와 답 확인

  1. A 추가 차이는 5%p이고 B 추가 차이는 2%p다.

  2. 상호작용은 67 − 65 − 62 + 60 = 0%p다.

이 표의 상호작용은 0%p다.

흔한 오답에서 다시 생각하기

상호작용이 0이면 두 요소가 모든 환경에서 독립이다.

하나의 조건 표에서 합이 맞는 산술이 보편 독립성을 증명하지 않는다.

연습 2 · 오류 찾아 고치기

baseline 60과 A 65와 B 62는 학습 1시간인데 AB 64만 2시간 학습했다. 보고서의 ‘B를 추가하는 순수 효과가 −1%p’라는 해석을 고쳐라.

힌트 1

숫자 차이와 요소만 바뀐 비교 조건을 분리한다.

힌트 2

새 맞춤 실험은 아직 하지 않는다.

풀이와 답 확인

  1. 관측된 표 차이 AB−A가 −1%p라는 산술은 유지한다.

  2. 학습 시간도 바뀌었으므로 B만의 비교로 고립하지 못했다고 기록한다. 같은 예산의 AB 조건을 확인할 후속 계획을 별도로 적는다.

현재 표의 차이와 해석 한계를 함께 보고한다.

흔한 오답에서 다시 생각하기

불공정한 비교이면 기존 숫자도 모두 0으로 지운다.

조건 불일치는 숫자의 산술 자체를 0으로 바꾸지 않는다.

연습 3 · 직접 만들어 보기

두 조건의 baseline은 70%, 80%다. A의 평균도 75%지만 한 조건에서는 더 좋고 다른 조건에서는 더 나쁜 자체 표를 만들고 조건 번호를 붙여라.

힌트 1

A를 73%, 77%로 정할 수 있다.

힌트 2

같은 번호끼리 뺀다.

풀이와 답 확인

  1. 조건 1에 A 73%, 조건 2에 A 77%를 적는다.

  2. 두 방법 평균은 75%이고 짝 차이는 +3%p와 −3%p다.

평균 동률은 조건별 동률을 뜻하지 않는다.

흔한 오답에서 다시 생각하기

평균이 같으면 각 짝 차이도 0이다.

양의 차이와 음의 차이가 상쇄될 수 있다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

같은 네 정확도 숫자를 서로 다른 최종 평가 자료에서 골라 가장 좋은 방법을 선택한 뒤 ‘아직 사용하지 않은 독립 test 결과’라고 적었다. 값은 바꾸지 않고 증거 분류와 후속 확인을 설계하라.

힌트 1

선택에 이용한 정보는 사용 이력에 남긴다.

힌트 2

새 test 실행은 계획과 구별한다.

풀이와 답 확인

  1. 현재 수치는 방법 선택에 이용한 평가 결과라고 기록한다.

  2. 선택 규칙을 고정하고 선택에 쓰지 않은 적절한 평가 자료로 확인할 계획을 적되, 그 결과는 아직 미확인으로 둔다.

자료의 이름보다 실제 사용 이력으로 독립 평가 범위를 정한다.

흔한 오답에서 다시 생각하기

파일 이름을 final_test로 바꾸면 독립 평가가 된다.

선택에 유입된 정보는 파일 이름 변경으로 사라지지 않는다.

같은 장치 시간을 써도 보고서가 더 늦게 완성될 수 있을까?

앞 본문은 장치 수×사용 시간과 벽시계 시간을 구별했다. 이번에는 같은 종류 GPU 두 개만 사용할 수 있는 별도 자원 모형이다. A와 B는 각각 이 자원을 단독 사용한다고 비교한다. 각 방법의 모든 탐색 작업은 시각 0시간에 준비되고 중단 없이 가능한 즉시 실행한다. 최종 학습은 자기 방법의 모든 탐색이 끝나야 시작한다. 자원 점유와 이 자료 의존성에 따른 대기 외에 별도 준비·통신·외부 큐 지연은 없다고 정한다.

A는 탐색 세 개가 각각 GPU 한 개를 1시간 사용하고, 별도 최종 학습은 GPU 두 개를 동시에 2시간 사용한다. 탐색 자원은 3 GPU 시간, 최종은 4 GPU 시간으로 총 7 GPU 시간이다. 두 탐색은 0–1시간에 동시에 끝나고 셋째는 1–2시간에 끝난다. 최종 학습은 2–4시간이므로 전체 벽시계는 4시간이다.

B는 탐색 두 개가 각각 GPU 한 개를 2시간 사용하고, 최종은 GPU 한 개로 3시간이다. 탐색 두 개는 0–2시간에 동시에 끝나고 최종은 2–5시간이다. 총 자원은 4+3=7 GPU 시간으로 A와 같지만 벽시계는 5시간이다. 같은 장치 시간은 같은 자원 제약 아래 동일 완료 시간을 강제하지 않는다. 실제 GPU 성능이나 전력 비용은 이 모형에 포함되지 않는다.

실패 작업도 그 가상 기록에서 사용한 자원을 장부에 남긴다. 별도 실패가 GPU 한 개를 1/2시간 썼다면 A의 전체 연구 자원은 7.5 GPU 시간이다. 실패가 일정의 어느 시각에 배치되었는지는 지정하지 않는다. ‘성공 표에 없는 작업’과 ‘사용하지 않은 자원’은 다르다. 배치의 갱신 수도 별도 정책으로 정한다. 표본 10개, 배치 최대 4개, 마지막 배치 유지, 두 배치 누적 뒤 갱신, epoch 끝 잔여 누적을 반드시 갱신·초기화하면 batch 크기는 4개, 4개, 2개이고 갱신은 8개 뒤 및 2개 뒤의 두 번이다.

  • 장치 시간과 완료 시간

    자원 곱과 일정의 의존성을 따로 계산한다.

  • epoch와 실제 갱신

    마지막 배치와 누적 종료 정책을 명시한 뒤 갱신 수를 센다.

자원의 범위와 단위를 정한다

계산 비용은 마지막 한 번의 학습 시간만을 뜻하지 않는다. 하이퍼파라미터 탐색·실패한 실행·예비 실험을 포함한 전체와 최종 선택된 실행을 나누어 적는다. 장치 종류와 수·메모리·시간·소프트웨어 조건이 달라지면 GPU 시간 수만으로 동일한 능력을 비교할 수 없다.

GPU 시간은 장치 수×사용 시간으로 계산하는 한 자원량이다. 두 장치를 한 시간 쓰면 2 GPU 시간이지만 벽시계 시간은 한 시간이다. 이 둘은 비용과 기다림이라는 다른 질문을 나타내며 장치 가격이나 전력의 실제 측정과도 다르다.

같은 질문에 맞는 비교를 한다

같은 계산 예산에서 품질을 비교하거나 같은 목표 품질까지 필요한 자원을 비교할 수 있다. 어느 질문인지 미리 정해야 한쪽에는 더 많은 탐색과 학습을 허용하고 숫자만 나란히 놓는 비교를 피할 수 있다. 데이터와 지표도 맞추어야 한다.

Epoch는 자료 전체를 한 번 훑는 기준이고 갱신 수와 항상 같지 않다. 자료 수·배치 크기·마지막 배치 처리·기울기 누적이 갱신 수를 바꾼다. 학습 시간뿐 아니라 배포 시 지연·처리량·메모리도 다른 목적이므로 하나의 승리라는 말로 합치지 않는다.

타이머가 잰 범위를 확인한다

GPU 호출은 CPU에 작업을 예약하고 완료 전에 돌아올 수 있다. 예약 시간만 재고 전체 연산이 빨라졌다고 말할 수 없다. 실제 측정에서는 필요한 동기화·초기 준비·반복·스레드 수·입력 크기 등을 밝혀야 한다.

아래는 가상 자원 장부와 정수 갱신 계산이다. 실제 GPU나 타이머를 실행하지 않았다. 반복 측정의 평균을 쓰더라도 분산과 측정 구간을 숨기지 않으며 준비 시간 포함 여부도 같은 규칙으로 적용한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 FIFO 단일 GPU 모형에서 CPU는 세 작업을 각각 1 ms 걸려 0–1, 1–2, 2–3 ms에 예약한다. GPU는 해당 예약이 끝나야 4 ms 실행하며 한 번에 하나를 처리한다. 이전 작업 없음·준비 비용 없음일 때 CPU 예약 완료와 GPU 전체 완료를 비교하라.

힌트 1

첫 GPU 작업은 1 ms에 시작한다.

힌트 2

뒤 작업은 예약 완료와 GPU 비어 있음 두 조건이 필요하다.

풀이와 답 확인

  1. GPU 구간은 1–5, 5–9, 9–13 ms다.

  2. CPU 예약은 3 ms에 끝나지만 전체 연산 완료는 13 ms다. 각 4 ms 연산의 합은 12 ms이고 첫 예약 대기 1 ms가 더해진다.

예약 반환 시간과 실제 완료 구간을 구별한다.

흔한 오답에서 다시 생각하기

예약 세 개를 3 ms에 마쳤으므로 GPU 연산도 3 ms다.

앞 본문은 자료가 없어 시작하지 않은 경우를 정확도 0%로 쓰지 않았다. 새 평가 장부에서는 대상 집합, 정답 판본, 예측 대상 ID, 비교 규약, 학습 checkpoint ID와 평가 실행 ID를 함께 적는다. 동일 checkpoint를 두 번 평가한 기록과 별도 학습으로 만든 checkpoint 두 개를 구별한다. ID 표기는 필요한 증거 키의 모형이며 실제 저장이나 신경망 수행은 아니다.

가상 원래 규약의 대상은 고유 ID 여덟 개다. 기준 방법은 여섯 개를 맞혀 6/8=75%다. 재확인 후보는 네 개만 평가하여 세 개를 맞혔다. 이 부분 비율도 75%지만 여덟 대상 중 후보의 정답 수는 미확인 네 개의 결과에 따라 3개부터 7개까지 가능하다. 전체 정확도 범위는 37.5%부터 87.5%다. 부분 대상의 점수가 같다는 사실만으로 원래 전체 규약의 재현을 완료했다고 할 수 없다.

전체 대상 여덟 개를 모두 채운 별도 가상 두 방법도 정확도가 같아 오류가 다를 수 있다. 두 방법 모두 정답인 ID 네 개, 기준만 정답인 두 개, 후보만 정답인 두 개, 둘 다 오답인 ID는 없다고 정한다. 각 방법의 정답 수는 여섯 개로 모두 75%다. 서로 정오 판정이 다른 대상은 네 개다. 두 방법의 정오가 모든 ID에서 같고 함께 정답 여섯 개·함께 오답 두 개인 다른 표도 같은 정확도를 만든다.
