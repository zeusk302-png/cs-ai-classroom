소단원 10.1

혼합정밀도

계산의 모든 자릿수를 줄이면 학습도 더 가볍고 정확해질까?

준비 개념과 학습 목표

준비 개념

  • 부동소수점의 반올림
  • 기울기와 SGD
  • 바이트와 텐서

학습 목표

  • 연산별 정밀도 선택과 전체 저정밀도 변환을 구별한다.
  • 손실 배율을 다시 나누는 이유를 계산한다.
  • 수치 위험과 실제 성능 확인을 나눈다.

정밀도는 연산마다 선택할 수 있다

혼합정밀도는 일부 연산에 낮은 정밀도를 사용하면서 다른 연산이나 저장 상태에는 높은 정밀도를 유지하는 방식이다. PyTorch 2.9의 autocast는 연산별 규칙으로 dtype을 선택하며 보통 순전파와 손실 계산을 감싼다. 모든 모델 값을 무조건 half로 바꾸는 것과 동일하지 않다.

적은 저장 비트는 값의 범위와 구별 가능한 간격을 바꾼다. 가속 여부는 장치와 연산 구현에 달려 있다. 이 절의 십진 격자는 원리를 보여주는 자체 장난감이며 FP16이나 BF16의 실제 비트 표현을 흉내 내지 않는다.

작은 기울기를 배율로 키웠다가 되돌린다

낮은 정밀도에서 작은 기울기가 0으로 반올림될 수 있다. 손실 L에 양의 상수 S를 곱하면 정확한 산술에서 ∂(SL)/∂w=S·∂L/∂w다. 갱신 전에 기울기를 S로 나누면 원래 학습률을 유지한다.

배율을 나누지 않으면 η 대신 ηS만큼 움직인다. 실제 AMP는 비유한 값과 overflow도 처리해야 하며 배율이 무조건 1보다 크거나 어떤 모델에도 안전한 것은 아니다. 배율만으로 이미 잘못된 순전파 값을 복원할 수는 없다.

저장량과 학습 품질을 함께 본다

백만 개 값을 각각 4바이트, 2바이트로 저장하면 순수 값 배열은 4,000,000바이트, 2,000,000바이트다. 그러나 옵티마이저 상태·기울기·활성값·고정밀도 복사본이 있으면 전체 학습 메모리 비율은 이 숫자와 다르다.

정밀도를 바꿀 때는 기준 모델과 같은 입력·평가 규칙으로 손실, 품질, 비유한 값, 최대 메모리와 시간을 비교한다. 아래 계산은 실제 모델이 안정적으로 학습됐거나 GPU 메모리가 절반이 되었다는 실험 결과가 아니다.

중간 과정을 따라가는 예제

자체 저장 격자의 간격을 .01, 가장 가까운 값으로 반올림한다고 하자. 실제 기울기 g=.003, S=100, w=1, η=.1이다. 배율 없는 저장과 배율 후 저장·복원·갱신을 비교하라.

  1. 배율 없이 .003은 가장 가까운 .00으로 반올림된다. 이 저장값으로 갱신하면 w는 1이다.
  2. 정확한 배율 기울기는 100·.003=.3이다. .01 격자에서 .30은 그대로 저장된다.
  3. 저장 후 100으로 나누면 .003이다. 복원한 값을 충분한 정밀도로 유지한다고 가정한다.
  4. SGD 갱신은 1−.1·.003=.9997이다. 복원 뒤 다시 같은 .01 격자에 저장하면 또 0이 되므로 이 가정이 필요하다.
  5. 배율을 나누지 않으면 1−.1·.3=.97이다. 이는 의도한 갱신과 다르다.

자체 격자 예제에서 복원 기울기는 .003, 올바른 새 w는 .9997이다. 배율 미복원은 .97이다.

종이와 본문으로 직접 해보기

같은 격자에서 g=.004, S=10이면 복원 후 w는? 반대로 저장 가능한 절댓값 상한을 1로 정한 별도 장난감에서 g=.2, S=10이면 어떤 문제가 생기는가?

힌트 보기

작은 값은 배율 후 .04가 된다. 큰 값은 배율 후 2가 된다.

풀이 보기

g=.004는 .04를 저장하고 10으로 나누어 .004를 되찾아 w=.9996이 된다. 상한 1인 별도 저장에서는 .2·10=2가 범위를 넘는다. 작은 값 보존을 위한 배율이 큰 값에는 위험을 만들 수 있다.

오해와 반례

혼합정밀도면 모든 텐서가 16비트이고 학습 메모리는 정확히 절반이다.

연산별 선택과 저장 상태는 다르다. 백만 값 배열의 4MB→2MB는 그 배열만의 산술이며 옵티마이저와 활성값까지 포함한 측정이 아니다.

소단원 10.2

양자화·가지치기

숫자를 정수로 저장하거나 연결을 지우면 왜 결과와 속도가 함께 바뀔 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 벡터 내적
  • 반올림과 정수
  • 행렬의 0과 희소성

학습 목표

  • scale와 zero-point로 복원값을 구한다.
  • 가지치기의 출력 오차를 입력과 함께 계산한다.
  • 0을 만드는 것과 실제 압축·가속을 구별한다.

양자화는 제한된 격자로 값을 매핑한다

자체 균일 양자화 규칙을 q=clip(round(x/s)+z,qmin,qmax), 복원값 x̂=s(q−z)로 둔다. s>0은 격자 간격, z는 정수 zero-point다. 반올림 오차와 범위 밖 clipping 오차를 구별해야 한다.

학습 후 양자화에서는 대표 입력으로 범위를 정하는 calibration이 중요하다. 양자화 인식 학습은 학습 중 양자화 영향을 모사한다. 저장 숫자 수를 줄이는 방식과 학습 데이터로 값 자체를 바꾸는 방식은 다르다. 오래된 문서의 구체 API나 지원 장치를 현재 모든 환경의 보장으로 쓰지 않는다.

가지치기는 연결이나 묶음을 없앤다

비구조 가지치기는 개별 가중치를, 구조 가지치기는 채널처럼 묶인 부분을 제거 대상으로 삼는다. 작은 절댓값 가중치만 지워도 큰 입력과 곱하면 출력 영향이 클 수 있다. 제거 후 동일 평가 조건으로 품질을 다시 확인해야 한다.

PyTorch 가지치기 예제는 원래 가중치와 mask를 저장하고 곱하여 0을 만든다. reparameterization을 제거해도 0이 생긴 동일 모양의 텐서가 남을 수 있다. 0의 비율이 높다는 사실만으로 파일 크기나 실행 시간이 그만큼 줄었다고 말할 수 없다.

오차와 실행 형식이 서로 다른 질문이다

양자화는 각 값의 표현을, 가지치기는 유지할 연결을 바꾼다. 두 방법을 조합할 수 있지만 오차가 사라지는 것은 아니다. 실제 희소 저장은 인덱스 같은 부가 정보가 필요하고 실제 가속은 지원 커널·연산 형태에 달려 있다.

100만 FP32 값의 순수 배열은 4MB이고 같은 개수의 8비트 정수 값은 1MB다. scale와 zero-point, 다른 텐서와 저장 형식은 이 값 배열 산술에 포함하지 않았다. 모델 전체 4배 압축이나 4배 속도를 측정했다는 뜻이 아니다.

중간 과정을 따라가는 예제

자체 s=.1,z=0,qmin=−3,qmax=3 규칙으로 x=.26,−.14,.8을 양자화하라. 별도 내적 w=(.04,.9), 입력 v=(100,1)에서 절댓값 .05 미만 가중치를 지우면?

  1. .26/.1=2.6을 반올림해 q=3, x̂=.3이다. 오차 x̂−x=.04다.
  2. −.14/.1=−1.4를 반올림해 q=−1, x̂=−.1이다. 오차 .04다.
  3. .8/.1=8이지만 정수 상한 3으로 자르므로 q=3, x̂=.3이다. 오차 −.5다. clipping이 없을 때의 반올림 오차 상한 s/2=.05를 넘는다.
  4. 원래 내적 .04·100+.9·1=4.9다. 작은 가중치 .04를 0으로 만들면 .9만 남는다.
  5. 출력 차이는 .9−4.9=−4다. 입력 100 때문에 작은 가중치도 영향이 크다.

복원값은 .3,−.1,.3이다. 내적은 4.9에서 .9로 바뀌어 4만큼 작아진다.

종이와 본문으로 직접 해보기

양자화의 s를 .2,z=2,qmin=0,qmax=4로 바꾸어 x=0,.31,−.5를 계산하라. 가지치기 예제의 입력을 (1,1)로 바꾸면 출력 차이는?

힌트 보기

0은 q=z에 대응한다. clip을 반올림 뒤 적용한다. −.5/.2=−2.5의 동률은 짝수 쪽으로 반올림한다고 정한다.

풀이 보기

0→q2→복원0이다. .31/.2=1.55→2이므로 q4→복원.4다. −2.5는 동률 짝수 −2로 반올림해 q0→복원−.4다. 내적은 .94→.9로 차이−.04다. 같은 작은 가중치라도 입력에 따라 영향이 다르다.

오해와 반례

가중치 절반을 0으로 만들면 파일과 실행 시간도 반드시 절반이다.

조밀한 텐서에서 0도 공간을 차지하고 조밀한 곱셈은 그대로 수행될 수 있다. 실제 형식과 장치에서 크기·시간을 확인해야 한다.

한 단계 더

두 값이 들어 있는 채널을 (−.1,.1), (−10,10)으로 두자. 두 채널에 공통 간격 s=1을 사용하면 첫 채널 두 값은 0이 된다. 첫 채널에 s=.1을 따로 사용하면 두 값을 보존한다. 채널별 간격의 효과를 보이지만 어떤 실제 모델의 최적 설정을 증명하지는 않는다.

메모리·지연·처리량

한 요청이 빨라졌는데도 많은 요청을 처리하는 능력은 줄 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 단위 변환과 비율
  • 배치
  • 메모리의 값 배열

학습 목표

  • 요청 지연과 처리량을 다른 단위로 계산한다.
  • 배치와 측정 범위를 명시한다.
  • 동기화·warm-up·반복 측정의 필요성을 설명한다.

메모리에는 여러 이름의 양이 있다

모델 값 배열의 크기, 현재 텐서가 점유한 메모리, 실행 중 최대 점유량, 메모리 관리자가 확보한 캐시 영역은 서로 다르다. PyTorch CUDA 문서는 allocated와 reserved를 구별한다. 캐시 반환은 살아 있는 텐서를 없애는 작업과 다르다.

순수 값 배열은 원소 수×원소당 바이트로 계산할 수 있다. 반면 학습·추론의 최대 메모리는 중간 활성값, 임시 작업 영역과 상태를 포함해 특정 입력·배치·실행 경로에서 확인해야 한다. 파일 크기 하나로 실행 중 최대 메모리를 알 수는 없다.

지연과 처리량은 서로 다른 약속이다

지연 latency는 정한 시작점부터 한 요청의 결과가 준비되는 시점까지의 시간이다. 처리량 throughput은 정한 기간에 완료한 요청 수다. 배치 B가 T초에 끝나면 그 반복 배치의 계산 처리량은 B/T다. 각 요청 지연을 T/B로 단정할 수는 없다.

배치를 모으는 대기, 전처리, 전송, 후처리를 포함할지 먼저 정한다. 배치 처리 시간이 늘어도 한 번에 끝나는 요청 수가 더 크게 늘면 처리량은 증가한다. 그러나 대화형 사용자에게는 긴 대기와 꼬리 지연이 불편할 수 있다.

시간계의 시작과 끝을 실행에 맞춘다

GPU 호출은 비동기일 수 있어서 호출 반환까지 잰 CPU 시간과 GPU 완료 시간이 다르다. 측정 경계에서 완료를 기다리거나 적절한 이벤트를 사용하는 절차가 필요하다. 초기 준비가 섞이지 않도록 warm-up과 반복 측정 조건을 정한다.

같은 장치·입력 모양·배치·정밀도·스레드·동시 요청 조건을 적고 평균과 중앙값 같은 통계를 함께 본다. 아래 시간은 자체 가상 표이며 GPU를 측정한 기록이 아니다. 품질 저하가 없는지도 같은 평가 자료로 별도 확인해야 효율 개선을 판단할 수 있다.

중간 과정을 따라가는 예제

가상 반복 실험에서 배치1 계산은 .020초, 배치8 계산은 .050초다. 각 배치의 요청은 동시에 계산을 시작하고 모두 끝에서 결과를 받는다. 대기·전송은 제외한다. 처리량과 계산 구간의 요청 지연을 비교하라.

  1. 배치 1의 처리량은 1/.020=50요청/초다. 이 구간의 요청 지연은 20ms다.
  2. 배치 8의 처리량은 8/.050=160요청/초다. 각 요청이 끝에서 결과를 받으므로 이 구간의 지연은 50ms다.
  3. 처리량 비율은 160/50=3.2다. 지연은 50/20=2.5배 길어졌다.
  4. .050/8=.00625초는 요청당 평균 계산 시간 몫이다. 각 요청이 6.25ms만 기다렸다는 뜻이 아니다.
  5. 배치 8을 모으는 대기 30ms가 모든 요청에 추가되는 별도 가상 조건이면 요청 지연은 80ms다. 배치 간 중첩 여부를 정하지 않고 전체 서비스 처리량도 160요청/초라고 유지할 수는 없다.

계산 처리량은 50→160요청/초지만 계산 구간의 요청 지연은 20→50ms다. 대기를 포함한 서비스 범위는 따로 계산해야 한다.

종이와 본문으로 직접 해보기

가상 지연 자료 18, 20, 22, 20, 120ms의 평균과 중앙값을 구하라. 값 배열 100만 개 FP32, 활성값 300만 개 FP16일 때 두 배열 합은 몇 바이트인가?

힌트 보기

합계를 5로 나누고, 정렬한 가운데를 본다. FP32는 4바이트, FP16은 2바이트로 가정한다.

풀이 보기

합은 200ms, 평균은 40ms다. 정렬한 자료 18, 20, 20, 22, 120의 중앙값은 20ms다. 두 배열 합은 1,000,000·4+3,000,000·2=10,000,000바이트=십진 10MB다. 옵티마이저 상태와 임시 영역은 포함하지 않았다.

오해와 반례

초당 처리량이 두 배면 모든 요청 지연도 절반이다.

배치를 키워 처리량을 올리면서 개별 요청 대기는 늘 수 있다. 시작점·종료점·대기·동시성을 정한 뒤 각각 측정한다.

한 단계 더

가상 프로그램의 전체 시간이 100ms이고 그중 60ms만 2배 빠르게 만들면 새 시간은 40+30=70ms다. 전체 가속비는 100/70=10/7≈1.43이다. 한 연산의 2배 가속을 전체 서비스의 2배 가속으로 옮길 수 없는 이유를 시간 분해로 설명하자. 이 비율은 실제 장치 측정이 아니다.
