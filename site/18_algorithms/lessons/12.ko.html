소단원 12.1

패턴 매칭의 전처리

여기까지 맞았던 글자를 불일치 뒤에도 활용할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 문자열의 인덱스

  • 접두사와 접미사

  • 반복문과 불변식

학습 목표

  • 가장 긴 proper 접두사·접미사 길이를 계산한다.

  • 실패 함수로 불필요한 비교를 줄인다.

  • 중첩·빈 패턴·문자 단위의 약속을 확인한다.

같은 패턴 안의 겹침을 먼저 찾는다

패턴 앞에서 시작하는 부분이 접두사이고 끝에서 끝나는 부분이 접미사다. proper는 전체 자체를 제외한다는 뜻이다. π[i]는 pattern[0:i+1]에서 서로 같은 가장 긴 proper 접두사와 접미사의 길이다. 값은 글자 위치가 아닌 길이이며 없으면 0이다.

ababaca의 각 앞부분은 a, ab, aba, abab, ababa, ababac, ababaca다. 겹치는 길이는 0, 0, 1, 2, 3, 0, 1이다. 패턴 자체를 답으로 허용하면 매번 전체 길이가 되어 실패 뒤에 어디로 갈지 알려 주지 못한다.

불일치하면 이미 가능한 짧은 겹침으로 돌아간다

검색 중 j는 지금까지 맞은 패턴 앞부분의 길이다. 다음 글자가 다르면 j를 π[j−1]로 줄여 그 길이의 접두사부터 다시 시도한다. 본문 인덱스 i는 뒤로 돌리지 않는다. 실패를 한 번만 처리하지 않고 while로 더 짧은 후보를 계속 확인한다.

전처리와 검색에서 증가한 길이만큼만 되돌아갈 수 있으므로 글자 비교를 상수 시간으로 세는 모형에서 O(m + n)이다. 전처리 배열은 O(m), 발견 위치 k개를 저장하는 출력은 O(k)다. Python 문자열의 글자 인덱스를 쓰며 UTF-8 바이트 위치나 사람이 보는 결합 글자의 위치와 같다고 가정하지 않는다.

모든 중첩 위치를 보고한다

일치를 찾으면 시작 i−m+1을 적고 j를 π[m−1]로 둔다. 그러면 일치한 꼬리가 다음 일치의 시작이 될 수 있다. 빈 패턴은 이 코드의 약속으로 n+1개 경계 모두를 반환한다. 빈 패턴에서 pattern[0]을 읽기 전에 따로 처리한다.

아래를 match.py에 저장하여 Python 3에서 python match.py로 실행하거나 종이에 인덱스 표를 만들자. prefix_table은 전처리, find_all은 검색이며 positions는 시작 위치다. 값만 외우지 말고 while의 j가 어느 글자를 가리키는지 직접 추적한다.

def prefix_table(pattern):
    pi = [0] * len(pattern)
    j = 0
    for i in range(1, len(pattern)):
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j
    return pi

def find_all(text, pattern):
    if not pattern:
        return list(range(len(text) + 1))
    pi = prefix_table(pattern)
    j = 0
    positions = []
    for i, char in enumerate(text):
        while j > 0 and char != pattern[j]:
            j = pi[j - 1]
        if char == pattern[j]:
            j += 1
        if j == len(pattern):
            positions.append(i - len(pattern) + 1)
            j = pi[j - 1]
    return positions

print(prefix_table("ababaca"))
print(find_all("abababaca", "ababaca"))
print(find_all("aaaa", "aa"))

중간 과정을 따라가는 예제

  2. 본문의 처음 다섯 글자 ababa가 맞은 뒤 i = 5의 b는 기대한 c와 다르다. j = 5에서 π[4] = 3으로 돌아가면 pattern[3]의 b와 맞고 j = 4가 된다.

소단원 12.2

문자열 해시와 충돌

문자열의 짧은 숫자가 같다는 것만으로 원문도 같다고 할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 모듈러 연산

  • 문자열 창과 길이

  • 다항식과 충돌

학습 목표

  • 다항 해시의 창 갱신식을 유도한다.

  • 같은 해시인 다른 문자열을 구성한다.

  • 후보와 정확한 확인 및 비용을 구별한다.

문자열을 짧은 나머지로 표현한다

문자 코드 c0부터 c(m−1)까지를 밑 b의 다항식으로 읽고 q로 나눈 나머지를 h로 삼는다. h = (c0 b^(m−1) + … + c(m−1)) mod q다. 비교 전에 길이와 같은 문자 코딩 규칙을 정한다. 서로 다른 문자열이 같은 나머지를 갖는 충돌은 반드시 가능하다.

종이 모델은 숫자 글자를 정수 0–9로 바꾸고 b = 10, q = 11로 고정한다. 12 mod 11 = 1, 23 mod 11 = 1이므로 두 글자 문자열 12와 23은 다르지만 해시가 같다. 작은 수는 충돌을 보여 주려는 선택이며 실제 안전한 해시 설정이라는 추천이 아니다.

앞 글자를 빼고 뒤 글자를 붙인다

길이 m의 창에서 첫 코드 c와 새 코드 d를 알면 h_new = ((h − c b^(m−1)) b + d) mod q다. b^(m−1) mod q를 먼저 계산한다. 원문 숫자를 모두 다시 만드는 대신 작은 나머지를 갱신한다. Python의 양의 q 나머지는 0부터 q−1까지라 중간값이 음수여도 정규화된다.

창 갱신의 상수 개수 산술과 전체 알고리즘 비용을 구별한다. 첫 해시는 O(m), 창마다 산술은 O(1)인 단어 연산 모형이지만 후보마다 실제 m글자를 확인한다. 고정한 작은 q는 충돌이 많아 최악 O(nm)일 수 있다. 무작위 해시와 별도 확률 가정 없이 언제나 선형 기대 시간이라고 주장하지 않는다.

같은 해시는 후보이고 원문으로 확정한다

본문 2312에서 패턴 12를 찾으면 길이 2 창은 23, 31, 12다. 해시 후보는 처음과 마지막이지만 실제 일치는 마지막뿐이다. candidates와 matches를 따로 반환하면 오류가 어디서 생길 수 있는지 보인다.

아래는 숫자 문자열에만 허용하는 교육용 구현이다. 모든 창을 포함하도록 range(n−m+1)을 쓴다. 빈 패턴과 더 긴 패턴도 따로 처리한다. 일반 문자의 코딩이나 비밀번호 저장용 암호 해시와 섞지 않는다.

def digit_hash(s, base=10, modulus=11):
    value = 0
    for char in s:
        if char not in "0123456789":
            raise ValueError("digits only")
        value = (base * value + int(char)) % modulus
    return value

def rolling_find(text, pattern):
    if any(c not in "0123456789" for c in text + pattern):
        raise ValueError("digits only")
    n, m = len(text), len(pattern)
    if m == 0:
        return list(range(n + 1)), list(range(n + 1))
    if m > n:
        return [], []
    base, modulus = 10, 11
    power = pow(base, m - 1, modulus)
    target = digit_hash(pattern)
    value = digit_hash(text[:m])
    candidates, matches = [], []
    for i in range(n - m + 1):
        if value == target:
            candidates.append(i)
            if text[i:i + m] == pattern:
                matches.append(i)
        if i + m < n:
            value = ((value - int(text[i]) * power) * base
                     + int(text[i + m])) % modulus
    return candidates, matches

print(digit_hash("12"), digit_hash("23"))
print(rolling_find("2312", "12"))

중간 과정을 따라가는 예제

본문 2312, 패턴 12, b = 10, q = 11의 해시와 후보·최종 위치를 구하라.

  1. 패턴 해시는 12 mod 11 = 1이다. 첫 창 23도 1이라 시작 0은 후보지만 원문이 달라 거부한다.

  2. 다음 창으로 갈 때 ((1 − 2 × 10) × 10 + 1) mod 11 = −189 mod 11 = 9다. 31 mod 11과 같다.

  3. 마지막 창은 ((9 − 3 × 10) × 10 + 2) mod 11 = −208 mod 11 = 1이다. 시작 2에서 원문 12가 같으므로 확정한다.

  4. 실제 코드 출력은 1 1과 ([0, 2], [2])다. 해시만 보고했다면 잘못된 시작 0을 포함했을 것이다.

창 해시는 1, 9, 1; 후보는 [0, 2], 정확한 일치는 [2]다.

오해와 반례

큰 소수를 쓰거나 해시 두 개가 같으면 충돌이 수학적으로 불가능하다.

  • 지수를 절반으로 줄이며 모듈러 값을 계산한다.

  • 0·음수·역원과 비용 모형의 경계를 명시한다.

나머지를 바꾸어도 공약수는 같다

a = qb + r이면 a와 b를 나누는 수는 b와 r도 나눈다. 반대로 b와 r를 나누는 수는 qb + r = a도 나눈다. 따라서 b ≠ 0일 때 gcd(a,b) = gcd(b,a mod b)다. 절댓값으로 시작하고 양의 나머지가 줄어들어 b = 0에서 멈춘다.

한 수가 0이면 다른 수의 절댓값을 반환한다. 둘 다 0인 경우 최대 양의 공약수라는 수학 정의는 그대로 쓸 수 없지만 이 함수는 프로그래밍 관례로 0을 반환한다. 나머지 연산 횟수와 큰 정수의 비트 비용은 다르며 나눗셈 한 번을 항상 같은 실제 시간으로 세지 않는다.

제곱하면서 지수의 이진 자릿수를 처리한다

a^e mod m에서 e ≥ 0, m > 0인 정수로 범위를 제한한다. 짝수 e = 2k는 (a²)^k, 홀수 e = 2k+1은 a(a²)^k로 바꾼다. 남은 지수 e를 절반으로 줄이며 홀수일 때만 누적 result에 base를 곱한다.

반복 중 result × base^e가 처음 a의 원래 지수 승과 같은 나머지라는 불변식을 유지한다. 매번 나머지를 취하면 거대한 완성 거듭제곱을 먼저 만들지 않는다. 반복 횟수는 양의 지수의 이진 자릿수 O(log e)지만 큰 모듈러 곱의 비트 비용은 별도다. 실제 성능 측정은 하지 않는다.

입력 경계와 역원을 구별한다

초기 result = 1 mod m이라 e = 0이면 이 약속을 반환하고 m = 1이면 0이다. 음의 지수는 여기서 거부한다. 모듈러 역원은 gcd(a,m) = 1 같은 조건이 필요하며 나머지 안에서 일반 나눗셈을 무조건 쓰지 않는다. Python pow는 음의 지수 역원 기능도 있지만 본문 함수는 그 기능을 구현하지 않는다.

아래 코드를 numbers.py로 저장하고 Python 3의 python numbers.py로 실행한다. a,b,exponent,modulus는 정수 입력이라는 전제를 둔다. gcd와 modular_power가 무엇을 반환하는지 종이로 먼저 예측하고 본문 출력과 대조하자.

def gcd_nonnegative(a, b):
    a, b = abs(a), abs(b)
    while b:
        a, b = b, a % b
    return a

def modular_power(a, exponent, modulus):
    if exponent < 0 or modulus <= 0:
        raise ValueError("exponent >= 0 and modulus > 0 required")
    result = 1 % modulus
    base = a % modulus
    while exponent:
        if exponent % 2:
            result = result * base % modulus
        base = base * base % modulus
        exponent //= 2
    return result

print(gcd_nonnegative(252, 105))
print(modular_power(3, 13, 17))
print(modular_power(3, 0, 1))

중간 과정을 따라가는 예제

gcd(252,105)와 3^13 mod 17을 구하고 빠른 거듭제곱의 상태를 추적하라.

  1. 252 = 2 × 105 + 42, 105 = 2 × 42 + 21, 42 = 2 × 21 + 0이므로 gcd는 21이다.

  2. 상태 (result, base, e)는 (1,3,13)에서 (3,9,6), (3,13,3), (5,16,1), (12,1,0)으로 바뀐다. 각 상태의 result × base^e는 같은 나머지를 갖는다.

  3. 예를 들어 두 번째 홀수 단계에서 3 × 13 mod 17 = 5, 마지막에서 5 × 16 mod 17 = 12다. 지수 13은 이진수 1101이며 네 번의 반복으로 처리한다.

  4. 실제 코드 출력은 21, 12, 0의 세 줄이다. 마지막은 지수 0, 모듈러 1의 약속이다.

gcd는 21, 모듈러 거듭제곱은 12다. 줄인 문제에서도 공약수와 나머지 불변식을 유지했다.

종이와 본문으로 직접 해보기

gcd(−48,18)과 2^10 mod 7을 계산하라. 두 함수의 결과에서 부호와 모듈러 범위를 확인하라.

힌트 보기

먼저 절댓값을 취한다. 48 mod 18 = 12, 18 mod 12 = 6이다. 2³ mod 7도 확인하라.

풀이 보기

gcd는 6이다. 2³ mod 7 = 1이므로 2^10 mod 7 = 2다. 나머지는 0부터 6까지이며 이 값은 정수 2^10 자체가 아니다.

오해와 반례

지수가 음수여도 같은 절반 반복을 쓰고 모듈러에서 나누기는 언제나 역원 곱과 같다.

이 함수는 음의 지수를 거부한다. 역원이 존재하려면 서로소 등의 조건이 필요하다. 예를 들어 2는 mod 4에서 곱해 1을 만드는 역원이 없다. 교육용 반복을 안전한 암호 구현이나 상수 시간 구현으로 주장하지 않는다.
