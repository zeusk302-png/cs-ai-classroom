패턴 매칭의 전처리

여기까지 맞았던 글자를 불일치 뒤에도 활용할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 문자열의 인덱스

  • 접두사와 접미사

  • 반복문과 불변식

학습 목표

  • 가장 긴 proper 접두사·접미사 길이를 계산한다.

  • 실패 함수로 불필요한 비교를 줄인다.

  • 중첩·빈 패턴·문자 단위의 약속을 확인한다.

입력이 조각으로 도착해도 같은 일치를 찾을 수 있을까?

패턴 aba를 두 조각 ab와 aba로 나눈 텍스트 ababa에서 찾는다. 첫 조각 끝에서는 두 글자 ab가 맞아 j=2이고, 전역에서 소비한 문자 수는 2다. 두 번째 조각의 첫 a는 0기반 전역 인덱스가 2이므로 첫 일치의 시작 위치는 2−3+1=0이다. 이 a를 처리한 뒤 소비한 문자 수는 3이다. 이때 j를 0으로 지우지 않고 π[2]=1로 되돌린다. 남은 ba를 처리하면 두 번째 시작 위치 2를 얻는다. 조각을 별도 문자열로 검색하면 경계에 걸친 첫 일치를 놓친다.

비어 있지 않은 고정 패턴의 스트림 상태는 전처리 표, 현재 접두 길이 j, 소비한 전체 문자 수다. 원래 텍스트 전체를 저장할 필요는 없지만 정답 위치의 단위와 오프셋은 일관되어야 한다. 여기서는 Python 문자열과 같은 문자 코드 포인트를 추적한다. 바이트로 받은 UTF-8 자료를 조각마다 따로 디코딩하면 한 문자의 중간에서 끊길 수 있다. 디코더 상태와 검색 상태는 별도의 계약이다. 실제 네트워크나 디코더를 실행한 것은 아니다.

실패 전이는 문자 입력을 되돌리는 연산이 아니다. 패턴 ababa의 표는 [0,0,1,2,3]이다. 접두 다섯 글자를 모두 맞춘 뒤의 상태를 겹침 검색 규칙으로 j=3으로 바꿨다면 다음 c에서는 j=3→1→0으로 감소한 후 c도 첫 글자 a와 다르므로 그대로 0이다. 각 단계는 같은 c를 다시 비교한다. j가 감소할 때마다 새 텍스트 글자를 소비하면 검사를 건너뛴다.

빈 패턴은 일치가 문자 사이의 경계라는 별도 규약이다. 길이 5의 텍스트에는 여섯 경계가 있다. 두 조각을 독립 처리하면서 각 조각의 모든 경계를 합치면 조각 사이 경계가 두 번 보고된다. 시작 경계 0을 한 번 내보낸 뒤 새 문자마다 새 경계 하나를 보고하면 중복 없이 0부터 5까지 얻는다. 결과 k개를 모두 저장하는 공간은 검색 상태 O(m)과 따로 O(k)로 계산한다.

먼저 확인할 개념
  • 실패 함수와 겹치는 일치

    이미 확인한 접두 길이를 조각 경계에도 보존하고 완전 일치 뒤의 실패 전이를 사용한다.

  • 검증할 문자열의 단위

    해시 후보나 문자열 비교에서도 동일 길이와 동일 문자 단위가 필요하다.

같은 패턴 안의 겹침을 먼저 찾는다

패턴 앞에서 시작하는 부분이 접두사이고 끝에서 끝나는 부분이 접미사다. proper는 전체 자체를 제외한다는 뜻이다. π[i]는 pattern[0:i+1]에서 서로 같은 가장 긴 proper 접두사와 접미사의 길이다. 값은 글자 위치가 아닌 길이이며 없으면 0이다.

ababaca의 각 앞부분은 a, ab, aba, abab, ababa, ababac, ababaca다. 겹치는 길이는 0, 0, 1, 2, 3, 0, 1이다. 패턴 자체를 답으로 허용하면 매번 전체 길이가 되어 실패 뒤에 어디로 갈지 알려 주지 못한다.

불일치하면 이미 가능한 짧은 겹침으로 돌아간다

검색 중 j는 지금까지 맞은 패턴 앞부분의 길이다. 다음 글자가 다르면 j를 π[j−1]로 줄여 그 길이의 접두사부터 다시 시도한다. 본문 인덱스 i는 뒤로 돌리지 않는다. 실패를 한 번만 처리하지 않고 while로 더 짧은 후보를 계속 확인한다.

전처리와 검색에서 증가한 길이만큼만 되돌아갈 수 있으므로 글자 비교를 상수 시간으로 세는 모형에서 O(m + n)이다. 전처리 배열은 O(m), 발견 위치 k개를 저장하는 출력은 O(k)다. Python 문자열의 글자 인덱스를 쓰며 UTF-8 바이트 위치나 사람이 보는 결합 글자의 위치와 같다고 가정하지 않는다.

모든 중첩 위치를 보고한다

일치를 찾으면 시작 i−m+1을 적고 j를 π[m−1]로 둔다. 그러면 일치한 꼬리가 다음 일치의 시작이 될 수 있다. 빈 패턴은 이 코드의 약속으로 n+1개 경계 모두를 반환한다. 빈 패턴에서 pattern[0]을 읽기 전에 따로 처리한다.

아래를 match.py에 저장하여 Python 3에서 python match.py로 실행하거나 종이에 인덱스 표를 만들자. prefix_table은 전처리, find_all은 검색이며 positions는 시작 위치다. 값만 외우지 말고 while의 j가 어느 글자를 가리키는지 직접 추적한다.

def prefix_table(pattern):
    pi = [0] * len(pattern)
    j = 0
    for i in range(1, len(pattern)):
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j
    return pi

def find_all(text, pattern):
    if not pattern:
        return list(range(len(text) + 1))
    pi = prefix_table(pattern)
    j = 0
    positions = []
    for i, char in enumerate(text):
        while j > 0 and char != pattern[j]:
            j = pi[j - 1]
        if char == pattern[j]:
            j += 1
        if j == len(pattern):
            positions.append(i - len(pattern) + 1)
            j = pi[j - 1]
    return positions

print(prefix_table("ababaca"))
print(find_all("abababaca", "ababaca"))
print(find_all("aaaa", "aa"))

  1. 첫 a 뒤 j=1이고 소비한 문자 수는 1이다.

  2. 다음 b,a에서 시작 위치 0을 보고한 뒤 j=1로 돌아간다. 남은 b,a에서 시작 위치 2를 보고한다.

완전 일치 뒤의 자원 계산

길이 n인 a 반복에서 패턴 aa의 모든 일치를 저장하면 상태 공간과 결과 공간은 어떠한가? n≥2라 하자.

  1. 시작 위치는 0부터 n−2까지 n−1개다. 패턴 표와 현재 상태는 패턴 길이 2에 비례한다.

  2. 출력 위치를 목록에 모두 보관하면 별도 공간이 Θ(n)이다. 즉시 내보내는 방식에서도 출력 자체의 처리 시간은 필요하다.

전처리·검색 상태 O(m)과 저장한 결과 O(k)를 구별한다. 여기서는 k=n−1이다.

비교할 점

입력을 한 번 읽는다는 사실이 전체 반환 목록의 상수 공간을 뜻하지 않는다.

두 해시가 같으면 원문 비교를 없애도 될까?

새 고정 길이 세 자리 숫자 문자열을 십진 다항식으로 읽고 나머지 11과 13을 함께 저장한다. 문자열 012의 정숫값은 12이고 155의 값은 155다. 차이는 143=11×13이므로 두 문자열의 해시 쌍은 모두 (1,12)다. 길이도 같지만 원문은 다르다. 서로 다른 두 소수를 썼다는 사실만으로 모든 입력에서 충돌이 사라지지는 않는다.

고정 기수 10에서 길이 m의 창을 옮기려면 최고 자리 가중치 10^(m−1)를 각 모듈러에서 먼저 구한다. 나가는 숫자 d와 들어오는 숫자 z에 대해 새 h=((h−d×가중치)×10+z) mod q다. 길이 세 창 012→121에서는 q=11의 가중치가 1이고 q=13에서는 9다. 첫 숫자 0이 나가고 1이 들어오므로 새 쌍은 (0,4)다. 다음 단계에도 같은 길이·기수·모듈러를 유지한다.

선행 0은 문자열 길이를 지우지 않는다. 0과 00은 정숫값 및 해시가 모두 0이지만 문자열 길이는 다르다. 서로 다른 길이 자료를 같은 버킷에 보관한다면 길이도 후보 키에 넣고 최종 원문을 비교한다. 고정 길이 패턴 검색에서는 창 길이 검사가 이미 이루어진다. 숫자를 정수로 바꿔 보관하는 것만으로 원래 선행 0을 복원할 수 없다.

충돌 검증을 붙이면 결과의 정확성을 확보할 수 있지만 시간 상한은 후보 수에 달려 있다. 창 수 W=n−m+1, 실제 비교한 후보 수 c라 할 때 초기 해시 O(m), 이동 O(W), 최악 후보 비교 O(cm)이다. 작은 고정 모듈러나 반복 입력에서 c가 W에 비례하면 O(nm)이 가능하다. 모든 일치 위치를 반환하는 비용도 남는다. 이 설명의 상수 시간 이동은 작은 고정 모듈러의 산술 모형이며 임의 정밀도 정수의 전체 비트 비용을 뜻하지 않는다.

  • 롤링 갱신과 원문 검증

    각 창의 해시 쌍은 후보 조건이며 동일 길이 원문 비교가 정답 조건이다.

  • 모듈러 연산과 역원 조건

문자열을 짧은 나머지로 표현한다

문자 코드 c0부터 c(m−1)까지를 밑 b의 다항식으로 읽고 q로 나눈 나머지를 h로 삼는다. h = (c0 b^(m−1) + … + c(m−1)) mod q다. 비교 전에 길이와 같은 문자 코딩 규칙을 정한다. 서로 다른 문자열이 같은 나머지를 갖는 충돌은 반드시 가능하다.

종이 모델은 숫자 글자를 정수 0–9로 바꾸고 b = 10, q = 11로 고정한다. 12 mod 11 = 1, 23 mod 11 = 1이므로 두 글자 문자열 12와 23은 다르지만 해시가 같다. 작은 수는 충돌을 보여 주려는 선택이며 실제 안전한 해시 설정이라는 추천이 아니다.

앞 글자를 빼고 뒤 글자를 붙인다

길이 m의 창에서 첫 코드 c와 새 코드 d를 알면 h_new = ((h − c b^(m−1)) b + d) mod q다. b^(m−1) mod q를 먼저 계산한다. 원문 숫자를 모두 다시 만드는 대신 작은 나머지를 갱신한다. Python의 양의 q 나머지는 0부터 q−1까지라 중간값이 음수여도 정규화된다.

창 갱신의 상수 개수 산술과 전체 알고리즘 비용을 구별한다. 첫 해시는 O(m), 창마다 산술은 O(1)인 단어 연산 모형이지만 후보마다 실제 m글자를 확인한다. 고정한 작은 q는 충돌이 많아 최악 O(nm)일 수 있다. 무작위 해시와 별도 확률 가정 없이 언제나 선형 기대 시간이라고 주장하지 않는다.

같은 해시는 후보이고 원문으로 확정한다

본문 2312에서 패턴 12를 찾으면 길이 2 창은 23, 31, 12다. 해시 후보는 처음과 마지막이지만 실제 일치는 마지막뿐이다. candidates와 matches를 따로 반환하면 오류가 어디서 생길 수 있는지 보인다.

아래는 숫자 문자열에만 허용하는 교육용 구현이다. 모든 창을 포함하도록 range(n−m+1)을 쓴다. 빈 패턴과 더 긴 패턴도 따로 처리한다. 일반 문자의 코딩이나 비밀번호 저장용 암호 해시와 섞지 않는다.

def digit_hash(s, base=10, modulus=11):
    value = 0
    for char in s:
        if char not in "0123456789":
            raise ValueError("digits only")
        value = (base * value + int(char)) % modulus
    return value

def rolling_find(text, pattern):
    if any(c not in "0123456789" for c in text + pattern):
        raise ValueError("digits only")
    n, m = len(text), len(pattern)
    if m == 0:
        return list(range(n + 1)), list(range(n + 1))
    if m > n:
        return [], []
    base, modulus = 10, 11
    power = pow(base, m - 1, modulus)
    target = digit_hash(pattern)
    value = digit_hash(text[:m])
    candidates, matches = [], []
    for i in range(n - m + 1):
        if value == target:
            candidates.append(i)
            if text[i:i + m] == pattern:
                matches.append(i)
        if i + m < n:
            value = ((value - int(text[i]) * power) * base
                     + int(text[i + m])) % modulus
    return candidates, matches

print(digit_hash("12"), digit_hash("23"))
print(rolling_find("2312", "12"))

모듈러에서 나눗셈은 언제 해가 하나일까?

gcd(84,30)은 나머지 24,6,0으로 끝나 6이다. 역대입하면 6=30−24=30−(84−2×30)=−84+3×30이다. 계수 −1과 3은 gcd의 증인이지만 84의 모듈러 30 역원이 아니다. 역원은 ax+my=1의 정수 증인이 있을 때 존재한다. gcd가 6인 이 사례에서는 1을 만들 수 없다.

모듈러 26에서 7은 서로소다. 26=3×7+5, 7=5+2, 5=2×2+1을 역대입하면 1=3×26−11×7이다. 따라서 역원은 −11 mod 26=15다. 음의 지수 7^(−2)를 역원의 제곱으로 정의하면 15² mod 26=17이다. 기본 교육 함수는 음의 지수를 거절하지만 Python의 정수 세 인자 pow는 서로소일 때 음의 지수를 지원한다. 두 함수의 입력 계약을 동일하게 부르지 않는다.

6x≡9 (mod 15)는 6의 역원이 없어도 해가 있다. gcd(6,15)=3이 오른쪽 9를 나누므로 전체 식을 3으로 줄여 2x≡3 (mod 5)로 푼다. 2의 역원 3을 곱하면 x≡4 (mod 5)다. 원래 모듈러 15의 대표 해는 4,9,14 세 개다. 반면 6x≡8 (mod 15)는 오른쪽이 3의 배수가 아니므로 해가 없다. 실수처럼 6으로 나누어 대표 해를 하나만 남기면 안 된다.

빠른 거듭제곱은 매 단계 r×b^e≡원래 밑^원래 지수라는 불변식을 유지한다. 7^11 mod 26에서 (r,b,e)는 (1,7,11)→(7,23,5)→(5,9,2)→(5,3,1)→(15,9,0)이다. 홀수일 때 r에 b를 곱하고 b를 제곱한 뒤 e를 정수 절반으로 바꾼다. 마지막 b의 제곱은 반환값에 쓰이지 않으므로 구현에 따라 생략할 수 있다. 지수의 비트 길이에 비례하는 반복 횟수와 큰 정수 곱셈의 비트 비용을 따로 센다. 암호 구현의 상수 시간이나 안전성을 이 모형으로 인증하지 않는다.

나머지를 바꾸어도 공약수는 같다

a = qb + r이면 a와 b를 나누는 수는 b와 r도 나눈다. 반대로 b와 r를 나누는 수는 qb + r = a도 나눈다. 따라서 b ≠ 0일 때 gcd(a,b) = gcd(b,a mod b)다. 절댓값으로 시작하고 양의 나머지가 줄어들어 b = 0에서 멈춘다.

한 수가 0이면 다른 수의 절댓값을 반환한다. 둘 다 0인 경우 최대 양의 공약수라는 수학 정의는 그대로 쓸 수 없지만 이 함수는 프로그래밍 관례로 0을 반환한다. 나머지 연산 횟수와 큰 정수의 비트 비용은 다르며 나눗셈 한 번을 항상 같은 실제 시간으로 세지 않는다.

제곱하면서 지수의 이진 자릿수를 처리한다

a^e mod m에서 e ≥ 0, m > 0인 정수로 범위를 제한한다. 짝수 e = 2k는 (a²)^k, 홀수 e = 2k+1은 a(a²)^k로 바꾼다. 남은 지수 e를 절반으로 줄이며 홀수일 때만 누적 result에 base를 곱한다.

반복 중 result × base^e가 처음 a의 원래 지수 승과 같은 나머지라는 불변식을 유지한다. 매번 나머지를 취하면 거대한 완성 거듭제곱을 먼저 만들지 않는다. 반복 횟수는 양의 지수의 이진 자릿수 O(log e)지만 큰 모듈러 곱의 비트 비용은 별도다. 실제 성능 측정은 하지 않는다.

입력 경계와 역원을 구별한다

초기 result = 1 mod m이라 e = 0이면 이 약속을 반환하고 m = 1이면 0이다. 음의 지수는 여기서 거부한다. 모듈러 역원은 gcd(a,m) = 1 같은 조건이 필요하며 나머지 안에서 일반 나눗셈을 무조건 쓰지 않는다. Python pow는 음의 지수 역원 기능도 있지만 본문 함수는 그 기능을 구현하지 않는다.

아래 코드를 numbers.py로 저장하고 Python 3의 python numbers.py로 실행한다. a,b,exponent,modulus는 정수 입력이라는 전제를 둔다. gcd와 modular_power가 무엇을 반환하는지 종이로 먼저 예측하고 본문 출력과 대조하자.

def gcd_nonnegative(a, b):
    a, b = abs(a), abs(b)
    while b:
        a, b = b, a % b
    return a

def modular_power(a, exponent, modulus):
    if exponent < 0 or modulus <= 0:
        raise ValueError("exponent >= 0 and modulus > 0 required")
    result = 1 % modulus
    base = a % modulus
    while exponent:
        if exponent % 2:
            result = result * base % modulus
        base = base * base % modulus
        exponent //= 2
    return result

print(gcd_nonnegative(252, 105))
print(modular_power(3, 13, 17))
print(modular_power(3, 0, 1))

여기서는 모듈러 m≥2로 제한한다.

힌트 2

음의 지수이면 먼저 gcd(a,m)=1을 요구한다.

풀이와 답 확인

  1. 정수 밑과 지수, m≥2를 받는다. e≥0이면 반복 제곱하고 e<0이면 역원이 있는지 검사한다.

  2. gcd(6,15)=3이므로 역원이 없어 음의 지수를 거절한다. 이는 양수 6^2 mod 15=6을 계산할 수 없다는 뜻이 아니다.

확장 Euclid는 gcd뿐 아니라 ax + by = gcd(a,b)의 정수 계수도 찾는다. gcd = 1이면 역원을 구하는 데 연결할 수 있다. 실제 암호 체계에는 난수·부채널·표준 라이브러리 등 추가 요구가 있으므로 이 작은 학습 코드를 보안 제품으로 사용했다고 표시하지 않는다.

① 패턴 aba를 조각 ab/aba에서 검색할 때 중간 j와 모든 전역 일치 위치를 구하라. ② 텍스트 012155012의 길이 세 창을 기수 10, 모듈러 11과 13으로 검색한다. 패턴 012의 후보 위치와 원문 검증 뒤 결과를 구하고 마지막 창 포함 여부를 확인하라. ③ 7^(−2) mod 26을 확장 유클리드로 구하되 기본 교육 함수와 음의 지수 확장 계약을 구별하라. 6x≡9 mod 15의 모든 대표 해도 구하라.

힌트 1

① 첫 조각 뒤 j=2를 보존하고 일치 뒤 π[2]=1을 사용한다. ② 155−12=143이며 창 시작 범위는 0부터 6까지다.

힌트 2

③ 1=3×26−11×7을 확인한다. 6x의 식은 gcd 3으로 모듈러까지 약분한다.

풀이와 답 확인

  1. ① 첫 조각 뒤 j=2이며 전체 일치 위치는 [0,2]다. 마지막 j=1이다. 조각별 초기화는 첫 일치를 잃는다.

  2. ② 후보 해시 쌍은 (1,12)다. 일곱 창을 모두 검사하면 후보 위치 [0,3,6]을 얻으며 155를 원문 비교에서 제외해 결과 [0,6]을 반환한다.

  3. ③ 7의 역원은 −11 mod 26=15이고 제곱 나머지는 17이다. 기본 교육 함수는 음의 지수를 거절하며 역원을 먼저 검사하는 확장 계약에서 계산한다.

  4. 6x≡9 mod 15는 2x≡3 mod 5로 줄어 x≡4 mod 5다. 원래 대표는 4,9,14이며 해의 존재를 역원 존재와 혼동하지 않는다.
