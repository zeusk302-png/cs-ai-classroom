소단원 11.1

module·port·signal

HDL의 한 줄은 CPU에게 할 일을 명령하는 것일까, 연결할 회로를 설명하는 것일까?

준비 개념과 학습 목표

준비 개념

  • 입력과 출력은 회로 경계의 신호다.
  • 비트 여러 개로 값을 표현할 수 있다.

학습 목표

  • 모듈·포트·내부 신호의 역할을 구별한다.
  • 폭과 비트 순서를 확인하여 간단한 연결을 추적한다.

module은 재사용할 회로 설명의 경계

HDL은 hardware description language, 하드웨어 기술 언어다. 여기서는 Verilog의 기본 문법으로 회로의 입력·출력·내부 연결을 표현한다. module은 회로 블록의 설명이고, 그 설명을 이름을 붙여 배치한 instance는 실제 설계 안의 사용 지점이다. 같은 module을 두 번 연결하면 두 블록의 동작을 표현할 수 있다.

port는 블록 바깥과 신호를 주고받는 접점이다. input은 들어오는 쪽, output은 나가는 쪽이다. 이 단원은 단일 구동 신호로 한정하고 양방향이나 여러 구동원이 있는 회로는 다루지 않는다. 파일 속 줄 순서만으로 모든 회로가 시간상 차례대로 작동한다고 생각하지 않는다.

signal에는 폭과 표현 규칙이 있다

input [3:0] a는 a[3]부터 a[0]까지 네 비트 입력이다. 이 예제에서는 부호 없는 값 0…15를 나타낸다. 4'b1010은 폭4·이진표현1010인 상수다. 왼쪽 비트부터 8·4·2·1의 자릿값을 사용한다. 폭을 넓히거나 좁힐 때 사라지는 비트와 부호 규칙을 확인해야 한다.

Verilog의 wire는 연결용 net을 선언하고 reg는 절차 블록에서 값을 할당할 변수를 선언한다. reg라는 이름 자체가 실제 플립플롭을 보장하지 않는다. 저장 요소가 필요한지는 할당이 모든 경우에 이루어지는지, 클록 사건에 묶였는지 등 설명 전체에 달려 있다. SystemVerilog의 더 넓은 타입 문법과 혼동하지 않도록 여기서는 Verilog 예제를 사용한다.

이름으로 연결하고 값으로 검산한다

아래 mux4는 sel=0이면 a, sel=1이면 b를 y에 연결하는 4비트 선택 회로다. assign은 오른쪽 입력 관계에 따라 net을 구동하는 continuous assignment다. sel은 네 비트가 아닌 한 비트다. 이 블록에는 저장 상태를 설명하는 클록 블록이 없다.

상위 모듈에서 mux4 u_pick(.a(left),.b(right),.sel(choice),.y(result));처럼 각 포트 이름에 신호를 연결할 수 있다. u_pick은 instance 이름이고 left 등은 상위 신호다. 포트 이름과 instance 이름을 구별하고 각 폭이 맞는지 확인한다. 코드 전체의 문법·도구 지원·실제 동작은 시뮬레이터/합성 도구로 별도 확인해야 하며 여기서는 종이 추적이다.

module mux4(input [3:0] a, input [3:0] b,
            input sel, output [3:0] y);
  assign y = sel ? b : a;
endmodule

중간 과정을 따라가는 예제

mux4 입력 a=4'b1010, b=4'b0011을 고정하고 sel을0과1로 둔다. y의 비트열과 부호 없는 십진값을 구하자.

  1. a는8+2=10, b는2+1=3이다.
  2. sel=0에서는 조건식이 a를 고르므로 y=1010, 십진10이다.
  3. sel=1에서는 b를 골라 y=0011, 십진3이다. 조건식의 참 쪽이 b라는 코드의 실제 배치를 확인한다.

sel0→1010(10), sel1→0011(3)이다. 실제 HDL 실행 결과가 아닌 코드 정의에 따른 예상값이다.

힌트 보기

4비트는8·4·2·1, 하위3비트는4·2·1이다.

풀이 보기

sel0은0110=6, sel1은1101=13이다. 3비트에 상위 비트를 잘라 받으면 하위101=5가 되어13과 다르다. 폭 변경은 원래4비트 목적을 보존하지 않는다.

오해와 반례

reg로 선언하면 언제나 실제 register가 생기고 wire에는 어떤 계산도 쓸 수 없다.

reg는 절차 할당 변수 문법이며 완전한 조합 블록의 결과도 reg로 선언할 수 있다. wire는 assign으로 a+b나 선택식의 출력을 구동할 수 있다. 실제 회로 추론은 사용 패턴까지 살펴야 한다.

한 단계 더

mux4 두 개를 상자 두 개로 그려 각각 sel을0과1로 연결하고 같은 a·b를 공급하자. 두 상자의 출력이10과3으로 동시에 존재할 수 있는 관계임을 설명하고, 파일의 앞 상자가 끝나야 뒤 상자가 시작한다는 소프트웨어식 해석과 비교하자.

소단원 11.2

조합논리 기술

입력이 같은데 이전 입력에 따라 출력이 달라진다면 정말 조합회로일까?

준비 개념과 학습 목표

준비 개념

  • 조합논리는 현재 입력에 대한 출력 관계다.
  • 선택회로와 논리 AND·OR를 안다.

학습 목표

  • 모든 입력 경우에 출력이 정해지는 블록을 작성한다.
  • 미할당 분기가 이전 값을 보존할 수 있음을 설명한다.

continuous와 procedural 표현

assign y = sel ? b : a;는 간단한 선택 관계를 직접 표현한다. 같은 관계를 always @* 절차 블록에서 if/else로 쓸 수도 있다. @*는 그 블록이 사용하는 입력 변화에 반응하도록 하는 Verilog 문법이며 clk의 상승 순간만 기다리는 표현과 다르다.

절차 블록의 문장 순서는 중요하다. 조합 블록에서는 여기의 기본 코딩 규칙으로 blocking =를 사용하고, 먼저 만든 중간값을 다음 식에서 사용할 수 있다. 서로 별개인 continuous assignment는 함수 관계를 함께 표현하며 소프트웨어처럼 파일 위에서 아래로 한 번씩만 수행하는 명령 목록이 아니다.

모든 경로에서 출력을 정한다

아래 sel2는 sel00이면 a,01이면 b,10이면 c, 그 외에는0000을 선택한다. 기본값을 먼저 주고 일부 경우에서 덮어 쓰면 할당이 빠지는 경로를 줄일 수 있다. 본문 계산은 입력이0/1로 정해진 경우에 한정하며 X나Z가 있는 시뮬레이션의 자세한 비교 규칙은 따로 다룬다.

default가 없는 case에서 sel11일 때 y에 어떤 값도 할당하지 않으면 절차 변수의 이전 값이 남을 수 있다. 합성에서는 latch 저장 동작으로 추론될 수 있어 의도한 순수 선택회로와 다르다. 문법 오류가 없다는 사실과 조합회로를 올바르게 설명했다는 사실을 구별한다.

module sel2(input [3:0] a,b,c, input [1:0] sel,
            output reg [3:0] y);
  always @* begin
    y = 4'b0000;
    case (sel)
      2'b00: y = a;
      2'b01: y = b;
      2'b10: y = c;
      default: y = 4'b0000;
    endcase
  end
endmodule

과거가 필요한지 작은 입력열로 확인한다

조합회로는 입력이 정해지고 전파가 안정된 뒤 출력 관계를 확인한다. 이 단원은 이상적인 값 관계 추적이며 실제 전파 지연이나 글리치가 없는 즉시 물리 회로를 주장하지 않는다. 동일 입력의 안정된 출력이 이전 입력에 따라 달라지면 저장 동작이나 잘못된 모델을 의심할 수 있다.

case의 모든 선택값, if의 참/거짓, 중간 신호의 쓰기 전 값 등을 종이에 검사한다. else if의 첫 참 분기는 우선순위를 표현할 수 있으므로 여러 조건이 동시에 참일 때도 의도한 출력을 확인한다. 빠진 분기를 사후 도구 경고로만 찾기보다 필요한 출력 규칙을 먼저 표로 적는 편이 낫다.

중간 과정을 따라가는 예제

sel2에서 a=0001,b=0010,c=0100이다. sel이00→01→11로 바뀌는 순서를 추적하자. 비교용 잘못된 블록은 기본값과 default를 모두 제거했다고 가정한다.

  1. 완전한 블록의 sel00 출력은0001, sel01은0010이다.
  2. sel11은 default로0000이다. 이전에 어느 입력을 선택했는지에 의존하지 않는다.
  3. 미할당 블록은 sel01에서0010을 저장한 뒤 sel11에서는 할당을 하지 않아0010을 유지하는 동작을 설명한다. 먼저sel10이었다면 sel11에서0100을 유지할 수도 있다.

완전한 블록 출력1→2→0, 미할당 블록1→2→2다. 같은sel11의 다른 과거 출력은 조합 선택회로의 의도가 깨진 반례다.

종이와 본문으로 직접 해보기

힌트 보기

풀이 보기

오해와 반례

if나 case 문법만 쓰면 모든 경우가 자동으로 조합논리로 합성된다.

미할당 경로의 이전 값 보존은 저장 동작을 요구할 수 있다. sel11에서2나4가 남는 반례를 확인하자. 완전 할당·감지 대상·의도한 우선순위를 함께 점검한다.

두 선택 신호의00·01·10·11 네 줄 진리표를 쓰고 각 줄의y 할당 문장을 연결하자. 이어 기본값을0000에서1111로 바꾸면11출력만 어떻게 바뀌는지 확인하고, default의 내용도 요구사항의 일부임을 설명하자.

소단원 11.3

clocked process와 할당

두 저장 요소를 같은 클록에 갱신할 때 둘째는 첫째의 새 값과 예전 값 중 무엇을 받아야 할까?

준비 개념과 학습 목표

준비 개념

  • 상승 클록 가장자리와 저장 상태를 안다.
  • 현재 상태와 다음 상태는 다르다.

학습 목표

  • nonblocking 할당으로 예전 상태를 이용한 갱신을 추적한다.
  • 동기 reset과 enable의 우선순위를 설명한다.

클록 사건에 맞춰 상태를 바꾼다

always @(posedge clk)는 clk가 상승 가장자리를 만났을 때 블록을 실행하는 동기식 설명이다. 조합회로는 다음 값 관계를 만들고 저장 요소는 그 값을 클록 사건에 받아 상태를 갱신한다고 생각하자. 여기서는 입력이 클록 전에 안정되고 실제 setup/hold 제약을 만족한다는 이상 모델로 값을 추적한다.

아래 reset은 동기식이다. reset을1로 바꾸었다는 사실만으로 가장자리 사이에 q가 즉시0이 되지는 않는다. 상승 사건에서 reset을 읽어0으로 바꾼다. 실제 외부 입력 동기화나 reset 해제 안전성 등은 별도 문제이며 이 간단한 표만으로 물리 타이밍을 검증하지 않는다.

<=는 상태 갱신을 예약한다

nonblocking <=는 해당 문장이 실행될 때 오른쪽 값을 평가하고 왼쪽 갱신을 예약한다. 아래 같은 블록에서 q1<=d; q2<=q1;이면 q2가 읽는 것은 갱신 전 q1이다. 이 사건 안에 다른 구동이나 지연이 없는 기본 예제에서는 두 단계의 동기 저장 동작을 표현한다.

blocking =는 다음 문장 전에 왼쪽 값을 바꾸므로 q1=d; q2=q1;은 같은 블록 안에서 새 d를 q2에도 전달할 수 있다. 코드의 보기 비슷함으로 두 저장단의 의미를 같다고 판단하지 않는다. 이 단원은 조합 블록 =, 동기 상태 블록 <=를 기본 규칙으로 사용한다.

module delay2(input clk,rst,en,d, output reg q1,q2);
  always @(posedge clk) begin
    if (rst) begin
      q1 <= 1'b0;
      q2 <= 1'b0;
    end else if (en) begin
      q1 <= d;
      q2 <= q1;
    end
  end
endmodule

reset과 enable도 표에 넣는다

if(rst) 다음 else if(en)은 reset이 우선인 관계다. 같은 가장자리에서 둘 다1이면 저장값은0이며 입력d를 받지 않는다. en0이면 이 클록 사건에서 두 저장값을 갱신하지 않아 유지한다. 조합 블록의 미할당과 달리 clocked 블록에서 의도한 유지/enable을 표현할 수 있다.

상태표에는 가장자리 전 상태, 사건에서 읽은 입력, 가장자리 뒤 안정된 상태를 나누어 적는다. 초기 상태를 저절로0이라고 가정하지 말고 예제에서는 reset으로 정한다. 출력 관찰을 같은 시뮬레이션 사건의 갱신 예약 전후 중 언제 했는지도 실제 테스트에서 명확히 해야 한다.

중간 과정을 따라가는 예제

delay2의 첫 상승 사건에서 rst1로 초기화한다. 이후 rst0,en1이며 연속 세 사건의 d가1,0,1이다. 각 사건 뒤(q1,q2)를 적자.

  1. reset 사건 뒤(0,0)이다. 첫 자료 사건은 새q1=1, 새q2=예전q1=0이므로(1,0)이다.
  2. 둘째d0 사건은 q1=0, q2=예전q1=1이라(0,1)이다.
  3. 셋째d1 사건은 q1=1, q2=예전q1=0이라(1,0)이다. 각 가장자리의 오른쪽은 이전 상태에서 계산한다.

reset 뒤00, 자료 사건 뒤10→01→10이다. 두 번째 저장 요소는 첫 번째의 직전 저장값을 받는다.

종이와 본문으로 직접 해보기

상태(q1,q2)=(1,0)에서 rst0,en0,d0인 상승 사건 뒤 상태는? 다음 사건이 rst1,en1,d1이면? 별도로 같은 블록에서 <=를=로 바꾸고 초기00에서 en1,d1을 처리하면 상태는?

힌트 보기

우선순위와 갱신 여부를 먼저 정한다. =의 둘째 문장은 새 q1을 읽는다.

풀이 보기

enable=0이면 (1,0)을 유지하고 다음 reset=1이면 (0,0)이다. blocking으로 바꾼 자료 사건은 q1=1을 즉시 대입하고 q2도 새 q1=1을 받아 (1,1)이므로 원래 nonblocking의 (1,0)과 다르다.

오해와 반례

<=는 느린 대입이고=는 빠른 대입이므로 속도만 다르다.

두 문법은 시뮬레이션 값 갱신 의미가 다르며 위 표에서는 둘째 저장값 자체가 달라진다. 실제 회로 속도는 합성된 경로와 장치·타이밍 조건으로 판단하며 기호만으로 빠른 회로를 보장하지 않는다.

q1의 nonblocking 갱신은 예약되어 있다.

rst1,en1이면 무엇이 우선인가?

소단원 11.4

합성가능 코드와 simulation 코드

시뮬레이션에서 #5 뒤에 값이 바뀌면 실제 회로에도 정확히5시간단위 지연 소자가 생길까?

준비 개념과 학습 목표

준비 개념

  • HDL로 회로를 설명하며 시뮬레이터가 그 동작을 모델링한다.
  • 조합 관계와 클록 상태를 구별한다.

학습 목표

  • 설계 대상 코드와 시험용 자극 코드의 목적을 나눈다.
  • 합성 통과·기능 시뮬레이션·물리 타이밍 확인을 구별한다.

같은 언어라도 목적이 다르다

설계대상DUT, device under test는 구현하려는 회로 블록이다. testbench는 DUT에 입력을 주고 예상 출력과 비교하는 시험 환경이다. 두쪽 모두 HDL로 적을 수 있지만 시험용 시계 생성·시간 지연·출력 표시를 그대로 실제 회로로 구현하는 것은 아니다.

합성은 지원하는 기술 방식에서 하드웨어 연결·저장 요소 등의 더 낮은 표현을 만드는 과정이다. 시뮬레이터가 문법을 받아들였다는 사실만으로 원하는 FPGA/ASIC에 합성 가능하다고 보장되지 않는다. 도구 버전·목표장치·지원부분집합을 확인한다.

시간 지연 표현을 회로 지연과 혼동하지 않는다

아래 작은 자극은 a를 0으로 두고 시뮬레이션 시간 5단위 뒤 1, 다시 5단위 뒤 0으로 바꾸는 의도다. #5는 시험 시간을 이동하는 표현이며 실제 회로에 정확히 5ns의 지연을 만들라는 보편적인 합성 명령이 아니다. 시간 단위 설정을 명시하지 않았으므로 여기서는 ns라고 단정하지 않는다.

실제로 클록 몇 주기 뒤 출력을 바꾸려면 목표 주파수와 상태·카운터 등 하드웨어 설계를 정한다. 지연 문구를 합성 도구가 무시하거나 지원하지 않을 수 있다. initial의 지원도 내용·장치·도구에 달리므로 모든 initial이 항상 합성 불가라는 일괄 규칙으로 바꾸지 않는다.

// 시험용 코드 조각: DUT 모듈의 일부가 아니다.
reg a;
initial begin
  a = 1'b0;
  #5 a = 1'b1;
  #5 a = 1'b0;
end

각 검사가 지지하는 결론을 기록한다

기능 시뮬레이션은 주어진 입력과 시뮬레이션 모형에서의 동작을 확인한다. 합성 결과는 도구가 어떤 회로를 만들었는지를 보여 주고 경고·저장 요소 추론·폭 변경 등을 점검하게 한다. 배치·배선 및 정적 타이밍 분석은 장치와 제약에서 경로 시간을 검토한다. 실제 보드 관찰은 또 다른 단계다.

한 검사를 통과했다고 나머지 검사까지 했다고 보고하지 않는다. 작은 선택 회로의 종이 표는 의도한 관계를 설명하지만 X/Z 값·모든 타이밍·도구 지원·전압 상태를 검증하지 않는다. 코드 버전·입력·기대값·실제 도구 결과와 미수행 검사를 분리하면 초보자도 증거를 읽을 수 있다.

중간 과정을 따라가는 예제

자체 이상적 자극 모형에서 a는 시간 0에 0, 시간 5에 1, 시간 10에 0이다. DUT는 assign y=~a;인 1비트 반전 회로라고 하자. 각 입력이 안정된 뒤 y의 예상값을 쓰고, #5가 실제 회로의 지연 증거인지 판단하자.

  1. 시간 0의 a=0에 대해 반전 y=1이다.
  2. 시간 5의 a=1에 대해 y=0, 시간 10의 a=0에 대해 y=1이다.
  3. 이는 주어진 시험 시간에서 값의 관계를 추적한 것이다. 실제 반전 회로의 전파 지연이나 보드 동작을 측정한 것이 아니다.

예상 y는 1→0→1이다. #5 자극 시간을 실제 하드웨어 지연 5ns의 증거로 사용할 수 없다.

종이와 본문으로 직접 해보기

자극을 시간 0에 a=1, 시간 3에 a=0, 시간 8에 a=1로 바꾸자. 반전 출력의 예상값은? 어떤 팀이 시뮬레이션을 통과했지만 합성·타이밍·보드 검사는 아직 안 했다면 완료 표에 어떻게 적을까?

힌트 보기

각 시점에서 반전한다. 실제 수행 검사만 완료로 적는다.

풀이 보기

안정 뒤 출력은 0→1→0이다. 완료 표는 해당 입력/버전의 기능 시뮬레이션 통과, 합성 미수행, 타이밍 미수행, 보드 미수행으로 나눈다. 여기 집필 예제 자체는 시뮬레이터도 실행하지 않았으므로 그 항목도 종이 예측이다.

오해와 반례

시뮬레이션에서 출력이 나왔으니 그 코드는 합성 가능하고 보드에서 같은 시간에 동작한다.

시험용 시간 제어문은 회로 구현과 다를 수 있고 기능 모형은 물리 경로 지연을 반영하지 않을 수 있다. 합성 지원·결과 추론·타이밍 제약·보드 관찰을 각각 확인해야 한다.

자기점검

실행하지 않은 도구 결과를 주장할 수 없다.

한 단계 더

10MHz 이상적인 클록의 주기는 1/(10⁷)초=100ns이다. 5주기는 500ns다. 반면 #5는 시간 단위 설정에 따르는 시험 표현이다. 클록 주기 기반 기능 지연과 시뮬레이션 시간 표현의 관계를 종이 표에 적고, 실제 카운터 합성이나 클록 오차를 검증한 계산은 아님을 표시하자.
