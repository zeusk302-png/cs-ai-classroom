소단원 14.1

요구사항과 블록도

세 숫자를 더하는 회로도 시작과 완료 규칙이 필요할까?

준비 개념과 학습 목표

준비 개념

  • 이진수와 비트 폭

  • 레지스터

  • 상승 에지

학습 목표

  • 입력 범위와 합의 폭을 정한다.

  • 클록 에지별 입력 계약을 쓴다.

  • 블록도에 자료와 제어 신호를 구별한다.

숫자의 범위와 성공 조건을 적는다

자체 작은 회로는 부호 없는 4비트 값 세 개를 받아 합을 내는 누산기다. 각 값은 0부터 15까지이며 최댓값은 45다. 5비트는 31까지만 표현하므로 합 레지스터와 result 출력은 6비트로 정한다.

포트는 clk, reset, start, valid, value[3:0], ack와 result[5:0], busy, done이다. valid는 현재 값이 유효하다는 표시다. 세 개를 받는 동안 값이 없는 에지는 개수에 넣지 않는다. 입력 범위·수신 횟수·출력 유효 시점을 함께 요구에 쓴다.

같은 에지에서 겹치는 요청을 정한다

모든 입력은 하나의 클록 영역에 있고 상승 에지 주변의 입력 타이밍 조건을 지킨다고 가정한다. reset은 1일 때 활성인 동기 리셋이며 모든 상태에서 가장 높은 우선순위다. 리셋 에지에서 상태는 IDLE, 합과 개수는 0이 된다.

IDLE에서 start가 1이면 합과 개수를 지우고 RUN으로 간다. 같은 에지의 valid는 받지 않는다. RUN에서는 valid가 1인 에지에서만 값을 받으며 start와 ack는 무시한다. 세 번째 수신 뒤 DONE으로 간다. DONE에서는 ack만 IDLE 복귀를 결정하고 start와 valid는 무시한다.

블록의 경계에 계약을 표시한다

자료 경로에는 값의 0 확장기·가산기·합/개수 레지스터·개수 비교기가 있다. 제어기는 상태와 valid 및 마지막 값 여부를 보고 지우기·저장 허용 신호를 낸다. 화살표에는 이름과 폭을 쓰고 공통 clk와 reset도 나타낸다.

busy는 RUN에서만 1이고 done은 DONE에서만 1이다. 결과는 done이 1일 때만 유효하다. DONE에서 ack와 start가 동시에 1이면 IDLE로만 가며 다시 시작하려면 다음 IDLE 에지에 start가 필요하다. IDLE의 합은 이전 결과를 유지할 수 있지만 유효한 새 결과라는 뜻은 아니다.

중간 과정을 따라가는 예제

초기 리셋 뒤 에지 0에 start와 valid가 함께 1이고 값은 9다. 에지 1/2/3에 valid가 1이고 값은 3/15/2다. 최종 합과 유효 시점을 구하라.

  1. 에지 0은 시작만 받아 RUN, 합 0, 개수 0이 된다. 값 9는 제외한다.

  2. 에지 1 뒤 합 3, 개수 1이다. 에지 2 뒤 합 18, 개수 2다.

  3. 에지 3 뒤 합 20, 개수 3, 상태 DONE이 된다. 이후 전파 지연을 거쳐 done이 1이며 result 20이 유효하다.

합은 20이다. 완료 출력은 세 번째 수신 에지 뒤 유효하며 시작 에지의 값은 합에 들어가지 않는다.

종이와 본문으로 직접 해보기

입력이 15/15/15라면 필요한 폭은 무엇인가? 5비트 합을 사용하면 어떤 잘못된 값을 보게 되는가?

힌트 보기

45와 2의 거듭제곱을 비교하고 32로 나눈 나머지를 구한다.

풀이 보기

6비트가 필요하다. 5비트에서 넘친 상위 비트를 버리면 45 mod 32=13이 되어 요구를 위반한다.

오해와 반례

합이 맞으면 포트와 시작 규칙은 나중에 정해도 된다.

동일한 입력 파형이라도 시작 에지 수신 여부에 따라 합이 다르다. 숫자 계산과 프로토콜 계약을 함께 정해야 연결 가능한 회로가 된다.

자기점검

valid가 0인 RUN 에지는 개수를 늘리는가?

답과 이유 보기

아니다.

수신하지 않았으므로 합과 개수를 유지한다.

reset과 valid가 겹치면 더하는가?

답과 이유 보기

아니다.

리셋이 우선하여 합과 개수를 0으로 만든다.

DONE에서 ack와 start가 겹치면 즉시 RUN인가?

답과 이유 보기

아니다.

이 계약에서는 IDLE로만 복귀한다.

한 단계 더

외부 버튼을 start에 연결할 계획이라면 비동기 입력의 동기화와 접점 바운스 제거가 추가로 필요하다. 여기서는 그 회로를 구현하지 않았고 입력이 이미 계약을 지킨다고 가정한다. 단순히 버튼을 연결했다고 타이밍이 보장된다고 쓰지 않는다.

소단원 14.2

datapath·controller 분리

더하기 장치가 언제 더할지까지 스스로 결정해야 할까?

준비 개념과 학습 목표

준비 개념

  • FSM

  • 조합 회로와 순차 회로

  • 이전 상태와 다음 상태

학습 목표

  • 자료 경로와 제어기의 책임을 구별한다.

  • 이전 개수로 마지막 수신을 판정한다.

  • 대기와 리셋에서 상태 보존을 추적한다.

자료 경로는 계산과 저장을 맡는다

datapath는 자료 경로라는 뜻이다. 4비트 값을 앞에 0 두 개를 붙여 6비트로 확장하고 현재 합과 더한다. 합 레지스터의 입력 선택기는 0·현재 합·가산 결과 중 제어 신호가 지시한 값을 고른다.

개수는 0/1/2/3을 표현하는 2비트 레지스터다. 마지막 수신 판정은 에지 직전 개수가 2인지 비교한다. 가산기는 늘 후보 값을 계산할 수 있지만 저장 허용이 없으면 레지스터는 바뀌지 않는다. 계산된 후보와 저장된 결과를 구별한다.

제어기는 저장 시점과 상태를 결정한다

controller는 제어기다. IDLE에서 start를 받으면 지우기를 지시하고 RUN으로 간다. RUN에서 valid를 받으면 합 저장과 개수 증가를 지시한다. 직전 개수가 2이면 같은 에지에 세 번째 값을 저장하고 DONE으로 간다.

RUN에서 valid가 0이면 아무 값도 저장하지 않는다. DONE에서는 합과 개수를 유지하고 ack를 기다린다. done은 현재 상태가 DONE인지에만 의존하는 Moore 출력이다. 실제 레지스터 출력과 상태 해독기의 지연은 0이 아니므로 에지 바로 그 순간 안정한 값이라고 가정하지 않는다.

이전 값으로 동시 갱신을 설명한다

순차 갱신에서는 합의 다음 값과 개수의 다음 값을 에지 직전 값으로 계산한다. SystemVerilog의 nonblocking 대입을 사용할 때 앞 줄의 개수 증가가 뒤 줄의 비교에 즉시 반영된다고 생각하면 마지막 시점을 잘못 고를 수 있다.

RUN에서 k개를 받은 뒤에는 개수가 k이고 합은 그 k개 값의 합이라는 불변 조건을 둔다. k가 0/1/2인 동안 이를 유지하고 다음 valid 수신이 세 번째일 때 DONE에서 세 값의 합을 얻는다. 리셋은 진행 중 작업을 중단하므로 리셋 뒤에는 새 시작이 필요하다.

중간 과정을 따라가는 예제

에지 0에 시작한다. 에지 1에 값 3을 받고 에지 2는 valid=0이다. 에지 3에 15, 에지 4에 2를 받는다. 각 에지 뒤 상태·합·개수를 구하라.

  1. 에지 0 뒤 RUN/0/0, 에지 1 뒤 RUN/3/1이다.

  2. 에지 2 뒤 RUN/3/1을 유지한다. 에지 3 뒤 RUN/18/2다.

  3. 에지 4 직전 개수는 2다. 다음 합 20과 개수 3을 저장하면서 DONE으로 가므로 에지 4 뒤 DONE/20/3이다.

대기 에지를 수신으로 세지 않아 완료는 에지 4 뒤다. 마지막 판정은 갱신 전 개수 2를 사용한다.

종이와 본문으로 직접 해보기

위 흐름에서 에지 3에 reset과 valid를 함께 1로 만들면 에지 3 뒤 결과와 이후 필요한 입력은 무엇인가?

힌트 보기

최우선 리셋 규칙을 적용하고 RUN에 남는지 확인한다.

풀이 보기

IDLE/0/0으로 돌아간다. 값 15를 더하지 않는다. 다음 IDLE 에지에 start를 주고 새 세 값을 받아야 완료한다.

오해와 반례

개수를 증가시킨 줄 다음에 비교하면 항상 새 개수를 비교한다.

순차 nonblocking 갱신의 오른쪽 식은 이전 값을 본다. 여기서는 이전 개수 2로 마지막 수신을 판단한다. 사용 언어의 실행 규약과 회로의 동시 저장을 함께 이해한다.

자기점검

답과 이유 보기

아니다.

저장 허용이나 지우기 조건이 있어야 갱신한다.

세 번째 값에서 이전 개수는 무엇인가?

답과 이유 보기

2다.

두 값을 이미 받았고 이번 수신 뒤 3이 된다.

done은 이 설계에서 valid에 직접 의존하는가?

답과 이유 보기

아니다.

현재 DONE 상태를 해독하는 Moore 출력이다.

한 단계 더

IDLE/RUN/DONE을 2비트로 인코딩하면 남는 인코딩이 하나 있다. 그 상태에서 리셋 상태로 안전하게 복귀하도록 다음 상태와 저장 제어의 기본값을 정하라. 불법 상태 복구 설계와 실제 결함 주입 검증은 별도 작업이다.

소단원 14.3

기능·타이밍 검증

합이 20으로 계산되면 어느 클록 속도에서도 동작할까?

준비 개념과 학습 목표

준비 개념

  • setup과 hold

  • 최대/최소 경로 지연

  • 기능 상태표

학습 목표

  • 기능 검사와 시간 조건을 구별한다.

  • 가상 경로의 setup/hold 여유를 계산한다.

  • 리셋·대기·경계 값을 검사 계획에 넣는다.

기능 검증에는 정상과 경계 흐름이 필요하다

기능 검증은 출력과 상태가 계약을 지키는지 확인한다. 0/0/0과 15/15/15, 시작과 valid 겹침, 수신 중 대기, DONE의 추가 valid, ack와 start 겹침, 도중 리셋을 예상 상태표와 비교한다.

세 값의 조합은 16³=4096개다. 모든 조합의 합을 수학적으로 정의할 수 있지만 그 사실만으로 모든 제어 입력 흐름을 검증한 것은 아니다. 실제 testbench를 실행했다면 입력 생성법·기대값·실패 사례·코드 버전을 남겨야 한다. 이 단원에서는 손으로 모델을 추적한다.

다음 에지까지 충분한 시간이 있어야 한다

하나의 클록과 skew 0을 가정한 레지스터 간 경로에서 최대 clock-to-Q 지연과 최대 조합 지연 및 setup의 합이 클록 주기 이하이어야 한다. 가상 수치 0.8 ns+3.2 ns+0.6 ns=4.6 ns를 사용한다.

주기가 5 ns이면 이 경로의 setup 여유는 0.4 ns다. 주기가 4 ns이면 −0.6 ns로 실패한다. 5 ns의 역수는 200 MHz지만 한 경로의 계산만으로 실제 회로가 200 MHz를 달성했다고 말할 수 없다. 다른 경로·입출력·클록 불확실성과 실제 도구 보고를 확인해야 한다.

너무 빨리 변하는 경로도 실패한다

같은 skew 0 모델에서 최소 clock-to-Q와 최소 조합 지연의 합은 hold 이상이어야 한다. 0.2 ns+0.1 ns=0.3 ns인데 hold가 0.4 ns면 0.1 ns가 부족하다. 클록 주기를 늘려도 같은 에지 뒤의 너무 빠른 변화는 해결되지 않는다.

가상 경로에 최소 0.2 ns의 지연을 더하면 최소 합은 0.5 ns가 된다. 다만 추가 소자가 최대 지연도 늘릴 수 있으므로 setup을 다시 계산해야 한다. FPGA에서는 일반 논리로 임의 지연을 만들기보다 도구의 제약·배치배선·타이밍 수정 결과를 검토한다.

중간 과정을 따라가는 예제

가상 경로의 최대 지연 합은 4.6 ns, 최소 지연 합은 0.3 ns, hold는 0.4 ns다. 주기 5 ns의 두 검사 결과를 구하라.

  1. setup 여유는 5−4.6=0.4 ns이므로 이 조건은 통과한다.

  2. hold 여유는 0.3−0.4=−0.1 ns이므로 실패한다.

  3. 기능 계산과 setup이 맞아도 hold 실패가 남는다. 주기를 10 ns로 늘려도 이 hold 식은 바뀌지 않는다.

setup 통과·hold 실패다. 두 부등식이 모두 만족해야 해당 모델의 시간 조건을 충족한다.

종이와 본문으로 직접 해보기

추가 소자가 최소 지연을 0.2 ns, 최대 지연을 0.7 ns 늘린다고 하자. 주기 5 ns에서 두 여유를 다시 구하라.

힌트 보기

hold에는 최소 증가, setup에는 최대 증가를 각각 적용한다.

풀이 보기

최소 합 0.5 ns이므로 hold 여유 0.1 ns다. 최대 합은 5.3 ns여서 setup 여유 −0.3 ns다. hold를 해결했지만 setup이 실패하므로 다시 설계해야 한다.

오해와 반례

클록을 느리게 하면 모든 타이밍 문제를 고칠 수 있다.

느린 주기는 setup 시간을 늘리지만 같은 에지의 hold 문제를 자동 해결하지 않는다. 비동기 입력·클록 영역 교차도 별도의 조건과 대책이 필요하다.

소단원 14.4

시뮬레이터·FPGA 결과 구분

파형에서 done이 켜진 것과 보드에서 완료한 것은 같은 증거일까?

준비 개념과 학습 목표

준비 개념

  • 기능 검증과 타이밍

  • 합성

  • 가상 모델과 측정

학습 목표

  • 모델·RTL·합성·보드 증거를 구별한다.

  • 재현에 필요한 환경과 제약을 기록한다.

  • 실행하지 않은 단계의 상태를 정확히 표시한다.

같은 이름의 설계도 단계마다 다르다

종이에 그린 상태표는 설계 의도를 보여 준다. RTL 시뮬레이션은 실행한 코드와 입력 자극 아래의 동작을 보여 준다. 기대값을 잘못 쓴 testbench는 오류를 놓칠 수 있으므로 계약과 독립적인 참조 계산을 비교한다.

RTL 기능 시뮬레이션이 모든 물리 지연을 재현하는 것은 아니다. 합성 결과는 코드가 하드웨어 구조로 변환된 것이며 배치배선과 정적 타이밍 분석은 실제 자원과 경로 조건을 더 다룬다. 그 뒤 보드 실행은 연결·입력·클록 환경까지 포함한 관찰이다.

실제 실행을 주장하려면 환경을 남긴다

시뮬레이션 결과에는 도구와 버전·RTL 및 testbench 버전·입력·기대 출력·실패 수·파형 관찰 범위를 남긴다. FPGA 결과에는 장치/보드·클록·핀과 입출력 제약·리셋 방식·타이밍 보고·비트스트림 버전·실제 관측을 추가한다.

LED가 켜진 한 장면은 모든 값을 더했거나 모든 경로의 타이밍을 만족한다는 증거가 아니다. 어떤 입력과 시점에서 무슨 값을 읽었는지 기록한다. 버튼을 직접 사용했다면 동기화와 바운스 처리가 계약을 충족하는지도 확인한다.

이번 단원의 완료와 미수행을 분리한다

이번에는 세 값 누산기의 요구·포트·상태표·비트 폭을 정의하고 정상/대기/리셋 흐름과 가상 시간 조건을 손으로 확인했다. 실제 RTL 파일을 구현하거나 시뮬레이터를 실행한 결과는 제공하지 않는다.

합성·배치배선·타이밍 보고 생성·비트스트림 작성·보드 계측·학생 실험도 미수행이다. 이후 실습에서 각 단계가 실제로 끝나면 그 단계의 증거와 실패 조건을 추가한다. 자체 예제의 숫자와 실제 기기 성능 측정값을 섞지 않는다.

중간 과정을 따라가는 예제

보고서에 종이 상태표의 합 20과 가상 setup 여유 0.4 ns만 있다. “FPGA에서 200 MHz로 검증 완료”라는 문장을 평가하라.

  1. 합 20은 설계 모델의 수신 순서 계산이다. 실제 RTL 출력이 아니다.

  2. 0.4 ns는 가상 단일 경로의 setup 계산이며 hold 실패와 다른 경로 검사도 남는다.

  3. 보드·제약·도구 보고·실측이 없으므로 FPGA 완료 주장은 근거가 없다. 설계와 가상 산술 확인, 실제 구현/보드 미수행으로 고친다.

설계 계산은 확인됐지만 FPGA 실행은 미수행이다. 200 MHz는 주기 5 ns의 환산값일 뿐 실제 달성값이 아니다.

물리 타이밍·제약·핀 연결·외부 입력 등 새로운 조건이 있다. 시뮬레이션과 보드 실행은 연결되지만 서로의 수행 사실을 대신하지 않는다.
