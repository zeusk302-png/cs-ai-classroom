소단원 12.1

stimulus와 기대값

회로에 입력을 넣기 전에 정답을 어디서 가져올까?

준비 개념과 학습 목표

준비 개념

  • 입출력 포트
  • 2진수와 비트 폭
  • 조합회로의 논리식

학습 목표

  • 자극·관측·기대값을 구별한다.
  • 명세에서 독립적으로 기대값을 계산한다.
  • 관측 시점과 입력 범위를 테스트 표에 적는다.

검사할 회로와 검사하는 환경

테스트벤치는 검사 대상 회로 DUT에 입력 자극 stimulus를 주고 출력을 읽는 환경이다. 회로를 실제 칩으로 만들지 않아도 모형의 동작을 검사할 수 있다. 다만 모델에서 성공한 것이 배선·전압·온도·실제 타이밍까지 검증했다는 뜻은 아니다.

기대값은 DUT의 출력을 복사하는 대신 명세나 별도 논리식에서 구한다. 2비트 unsigned 덧셈기라면 A와 B는 각각 0부터 3이고 합은 0부터 6이다. 3비트 출력이 전체 합을 나타낸다는 약속을 먼저 적어야 한다. 2비트로 잘라낸 합과 같은 문제로 읽으면 안 된다.

입력 표와 출력 표를 짝짓는다

각 행에 입력, 적용한 시각, 출력 관측 시각, 기대값을 둔다. 조합회로도 입력을 쓰는 바로 그 순간 모든 출력이 이미 갱신됐다고 가정하면 시뮬레이터의 평가 순서와 충돌할 수 있다. 입력 변경 뒤 평가가 끝난 시점에서 비교한다.

16개 조합을 모두 검사하면 이 작은 2비트 덧셈기의 지정한 이진 입력 공간은 전부 다룬다. 그러나 미정값 X, 다른 파라미터, 추가 포트, 지연이 있는 다른 모형까지 자동으로 포함하지 않는다. 테스트한 범위를 구체적으로 적어야 결과를 재사용할 수 있다.

작은 기준 모델을 독립적으로 유지한다

종이에서는 정수 A+B를 계산하고 3자리 이진수로 바꾸면 된다. HDL에 같은 잘못된 폭 절단을 넣은 뒤 기준 모델에도 복사하면 두 결과가 같이 틀려도 통과할 수 있다. 기준 모델은 약속을 더 단순하게 표현하는 편이 좋다.

실행 도구를 사용한다면 실제 DUT의 신호 값을 읽어 기준 모델과 비교한다. cocotb 문서의 핸들 .value와 핸들 자체의 차이가 이런 읽기 단계에서 중요하다. 이 단원에서는 설치 없이 입력 표·합·비트 표현으로 먼저 검사 계획을 만들고 실제 시뮬레이션은 별도로 수행한다.

중간 과정을 따라가는 예제

2비트 A,B와 3비트 합 Y의 명세 Y=A+B를 검사한다. (A,B)=(0,0),(1,2),(3,3)의 기대값과, 잘못된 Y=(A+B) mod 4의 결과를 적어라.

  1. 정상 합은 0, 3, 6이고 3비트 표현은 000, 011, 110이다.
  2. 잘못된 폭 절단은 0, 3, 2로 000, 011, 010을 낸다. 앞 두 행에서는 오류가 보이지 않는다.
  3. (3,3)의 기대 110과 잘못된 010을 비교하면 최상위 합 비트가 사라진 것을 찾는다.
  4. 이 표는 명세에서 계산한 예상 결과다. 실제 시뮬레이터에서 나온 파형이 아니다.

(3,3)이 합 비트 손실의 반례이며 기대 Y는 6=110이다.

종이와 본문으로 직접 해보기

A와 B가 0..3일 때 전체 16행을 그린다. 합이 4 이상인 행을 표시하고 폭 절단 오류가 드러나는 행 수를 구하라.

힌트 보기

A를 고정하고 가능한 B를 네 개씩 적는다. A+B≥4만 센다.

풀이 보기

A=0에서는 0행, A=1에서는 B=3 한 행, A=2에서는 B=2,3 두 행, A=3에서는 B=1,2,3 세 행이다. 총 6행에서 오류가 드러난다. 나머지 10행만 골랐다면 같은 오류를 놓칠 수 있다.

오해와 반례

DUT가 내놓은 값을 기대값으로 저장하면 자동 검사가 된다.

결과 복사는 같은 오류를 기준에 포함시킨다. 입력과 약속으로 기대값을 먼저 정하고 실제 결과를 별도로 관측해야 비교가 의미 있다.

자기점검

3+3을 보존하는 최소 unsigned 합 폭은?

답과 이유 보기

3비트다.

최대 6이므로 2비트의 최대 3을 넘는다.

16개 정상 이진 입력을 모두 검사하면 X 입력도 검사했나?

답과 이유 보기

아니다.

미정값과 이진값은 별도 입력 범위다.

입력 쓰기 직후 읽기가 위험한 이유는?

답과 이유 보기

회로 평가가 아직 끝나지 않을 수 있다.

관측 시점을 평가 모델에 맞게 정해야 한다.

한 단계 더

A,B 폭을 n으로 늘리면 이진 입력 조합은 2^(2n)개다. n=8이면 65,536개로 늘어난다. 작은 회로의 전체 조합 검사와 큰 회로의 경계·대표·무작위 검사 계획을 구별하자. 무작위 검사는 입력의 전체 정확성을 증명하지 않는다.

출처와 확인 범위
  • cocotb — Writing Testbenches

    실제 Logging, Reading values, Passing and failing tests 절에서 값 읽기, 로그와 실패 판정의 차이 및 assertion 예제를 읽었다. 자체 입력 표와 종이 추적으로 구성하며 도구를 실행했다고 주장하지 않는다.

  • cocotb — The Timing Model

    실제 Time Step의 단계와 RisingEdge/ReadOnly 절에서 같은 시각의 여러 평가 주기, 에지 직후 하류 출력 미갱신 및 최종 값 읽기를 확인했다. Verilator의 에지 처리 차이도 읽었다.

소단원 12.2

assertion과 경계 조건

실패한 파형을 사람이 찾아보기 전에 어떤 약속을 자동으로 확인할까?

준비 개념과 학습 목표

준비 개념

  • 조건식과 참·거짓
  • 명세 기반 기대값
  • unsigned 범위

학습 목표

  • 로그와 assertion 실패를 구별한다.
  • 경계의 양쪽과 조건의 전제를 검사한다.
  • 시간에 따른 속성의 적용 시점을 명시한다.

약속을 참이어야 하는 조건으로 바꾼다

assertion은 정해진 시점의 조건이 참인지 검사하여 거짓이면 실패를 알리는 장치다. 출력과 기대값의 일치, 허용 범위, 상태 전이의 약속을 조건으로 적을 수 있다. 단순히 화면에 “오류”라고 로그를 썼다는 것과 테스트가 실패로 집계되는 것은 다르다.

검사할 대상과 시점이 명확해야 한다. 입력을 바꾼 뒤 평가가 끝났을 때 출력 합을 검사하거나, 다음 에지에 특정 응답이 있어야 한다는 시간 속성을 검사한다. 후자는 현재 한 순간의 비교와 다르므로 지연·reset 동안의 예외를 함께 정한다.

경계와 폭은 오류가 모이는 곳이다

3비트 unsigned 값을 1 증가시키되 최대값 7에서는 7을 유지하는 포화 증가기를 생각하자. 명세는 x<7이면 y=x+1, x=7이면 y=7이다. 그냥 3비트 덧셈을 하면 7+1이 0으로 돌아간다. 경계의 전후인 6과 7이 포화 여부를 구별한다.

본문 검사 계획은 출력이 x 이상이고 7 이하인지, 그리고 명세 값과 같은지 확인한다. 범위 조건만으로는 충분하지 않다. 항상 7을 내는 고장 회로는 출력 범위를 지키지만 x=0에서 기대 1과 다르다. 강한 비교와 보조 속성을 같이 사용한다.

전제가 한 번도 만족되지 않은 통과를 확인한다

enable=1일 때 증가한다는 조건만 검사했는데 모든 자극의 enable이 0이었다면 그 조건을 제대로 시험하지 않았다. 조건부 assertion이 통과했다고 해당 동작을 실행한 사실까지 자동으로 얻지는 않는다. 전제 활성 횟수와 경계 입력을 기록한다.

이상적 이진 표에서의 참·거짓과 HDL의 X/Z 처리도 구별한다. SystemVerilog의 비교 연산·assertion 형식과 시뮬레이터 설정에 따라 검사 의미가 달라질 수 있으므로 미정값이 나오면 무조건 참으로 간주하지 않는다. 여기서는 특정 언어의 모든 assertion 문법보다 명세·전제·관측 시점을 만드는 연습에 집중한다.

중간 과정을 따라가는 예제

포화 증가기의 입력 x=0,6,7을 검사한다. 잘못된 구현 y=(x+1) mod 8과 항상 y=7인 구현을 비교하라.

  1. 명세 기대값은 x=0에서 1, x=6에서 7, x=7에서 7이다.
  2. mod8 구현은 1,7,0이므로 최대 입력 7에서 실패한다. y≥x 속성도 이 행에서 거짓이다.
  3. 항상7 구현은 7,7,7이며 y≥x와 y≤7을 모두 통과한다. 하지만 x=0의 기대 1과 다르다.
  4. 따라서 출력 범위·단조 조건만 보지 말고 지정한 명세와 직접 비교해야 두 오류를 구별한다.

mod8은 경계7에서, 항상7은 입력0에서 명세 비교가 실패한다.

종이와 본문으로 직접 해보기

enable=0이면 유지, enable=1이면 포화 증가라는 약속을 추가한다. (x,en)=(6,0),(6,1),(7,1)의 기대값을 적고 en=0만 넣은 시험의 한계를 설명하라.

힌트 보기

증가는 enable이 켜졌을 때만 적용한다. 최대에서는 켜져도 포화한다.

풀이 보기

기대값은 6,7,7이다. en=0만 넣으면 유지 동작을 볼 수 있지만 증가 및 포화 전제를 한 번도 활성화하지 않아 해당 조건의 성공 근거가 부족하다.

오해와 반례

assertion이 모두 통과하면 입력 계획을 읽을 필요가 없다.

전제를 만족한 자극이 없거나 기대식이 DUT 오류를 복사했을 수 있다. 어떤 입력과 시점에 어떤 속성이 적용됐는지 같이 검토해야 한다.

자기점검

오류 로그 한 줄만 썼으면 테스트는 반드시 실패하나?

답과 이유 보기

그렇지 않다.

실패 판정과 로그 기록은 별도 동작이다.

y≤7만으로 포화 증가를 검증할 수 있나?

답과 이유 보기

부족하다.

항상0 또는 항상7도 범위를 만족할 수 있다.

enable=1 조건을 시험하려면 기록할 것은?

답과 이유 보기

enable=1 자극과 그때의 관측 결과다.

조건이 적용된 횟수와 사례가 있어야 한다.

한 단계 더

reset 중에는 출력0, reset 해제 후 enable에 따라 증가한다는 속성을 추가해 보자. 검사에서 reset을 예외로 둔다면 reset 자체를 검사하는 별도 조건도 둔다. 한 동작의 검사를 끄는 조건을 모든 동작의 검사 면제로 확장하지 않는다.

출처와 확인 범위
  • cocotb — Writing Testbenches

    실제 Logging, Reading values, Passing and failing tests 절에서 값 읽기, 로그와 실패 판정의 차이 및 assertion 예제를 읽었다. 자체 입력 표와 종이 추적으로 구성하며 도구를 실행했다고 주장하지 않는다.

소단원 12.3

클록·reset 테스트

클록이 올라간 시각과 레지스터 값이 안정된 시각은 항상 같은 관측 단계일까?

준비 개념과 학습 목표

준비 개념

  • 상승 에지
  • 레지스터와 enable
  • 동기 reset과 비동기 reset

학습 목표

  • 클록 주기와 관측 에지를 표에 표시한다.
  • 동기 reset의 우선순위와 에지 없는 구간을 추적한다.
  • 동일 시각 평가 순서와 실제 회로 타이밍 검증을 구별한다.

에지에 적용할 규칙을 먼저 정한다

이 절은 2비트 카운터 q, active-high 동기 reset rst, enable en을 선택한다. 상승 에지에서 rst=1이면 q=0, 아니면 en=1일 때 q=(q+1) mod4, 나머지는 유지한다. reset이 enable보다 우선한다. 이 약속은 비동기 reset 회로에 그대로 적용되지 않는다.

클록을 0에서 시작해 5,15,25,35,45 ns에서 상승하도록 잡으면 주기는 10 ns다. 입력은 에지보다 앞서 바꾸고, reset 또는 enable을 에지와 동시에 쓰는 경쟁 상황을 기본 검사에서 피한다. 실제 setup/hold 시간은 이 이상적 규칙만으로 측정되지 않는다.

에지 뒤 평가가 끝난 값을 읽는다

이벤트 기반 시뮬레이션에서는 RisingEdge를 기다린 직후 클록은 이미 바뀌었어도 그 에지에 반응하는 HDL과 레지스터 할당이 모두 끝났다고 할 수 없다. cocotb의 ReadOnly는 현재 시간 단계의 최종 값을 읽는 시점이다. 에지 감지와 출력 평가 완료를 구별하면 이전 q를 새 q로 오인하는 오류를 줄인다.

시뮬레이터별 처리 차이도 있다. cocotb 문서는 Verilator에서 값 변화 트리거가 평가 주기 뒤에 처리되는 차이를 설명한다. 도구를 바꾸면서 에지 직후 우연히 맞던 시험을 그대로 신뢰하지 말고 지원되는 관측 방식을 확인한다. 본문의 시간 표는 특정 실행의 실제 파형이 아니라 명시한 이상적 규칙의 예측이다.

reset을 에지 사이와 동작 중에도 넣는다

동기 reset은 rst가 1로 바뀌는 즉시 q를 바꾸지 않고 다음 상승 에지에서 적용된다. rst를 27 ns에 올렸다면 25 ns 이후의 q는 35 ns 전까지 유지된다. 반대로 비동기 reset은 지정한 reset 에지에 반응하는 약속이므로 별도 검사가 필요하다.

처음 reset, 증가 중 reset, reset과 enable의 동시 활성, enable=0 유지, 최대값에서 wrap을 분리해 시험한다. 실제 비동기 reset 해제의 동기화·recovery/removal 제약은 물리 회로 검증 대상이며 종이 테스트의 통과가 그런 제약을 보장하지 않는다.

중간 과정을 따라가는 예제

q는 최초 미정이라 두고 위 동기 카운터를 추적한다. 0 ns부터 rst=1,en=1; 12 ns에 rst=0; 27 ns에 rst=1; 38 ns에 rst=0,en=0이다. 상승 에지 5,15,25,35,45 ns 뒤 안정된 q와 30 ns의 q를 구하라.

  1. 5 ns는 rst=1이라 enable과 무관하게 q=0이 된다. reset 전 미정 초기값을 정상 카운트로 가정하지 않는다.
  2. 15 ns와 25 ns는 rst=0,en=1이라 q는 1,2다.
  3. 27 ns의 rst 상승은 동기 reset이므로 즉시 q를 바꾸지 않는다. 30 ns의 q는 2다. 35 ns 에지에서 q=0이 된다.
  4. 38 ns 이후 rst=0,en=0이므로45 ns 에지에서도 q=0을 유지한다.

다섯 상승 에지 뒤 q는 0,1,2,0,0이고 30 ns에서는 2다. 주기는 10 ns다.

소단원 12.4

시뮬레이션 결과의 기록

다른 사람이 같은 실패를 재현하려면 파형 사진 외에 무엇이 필요할까?

준비 개념과 학습 목표

준비 개념

  • 입력·기대·관측의 차이
  • 시뮬레이션 시간
  • 파일과 버전

학습 목표

  • 예상·실제·미수행 결과를 분리해 기록한다.
  • 재현 가능한 입력과 도구·설정 근거를 남긴다.
  • 파형과 assertion 결과를 연결하여 원인을 좁힌다.

결론과 근거를 한 줄씩 연결한다

실제 실행 기록에는 회로와 테스트벤치 버전, 실행 명령, 도구 버전·설정, 입력 또는 난수 seed, 테스트한 범위와 종료 상태를 남긴다. 실패마다 입력·기대·실제·시각을 연결한다. 파형은 시간을 따라 신호를 보여주지만 명세의 기대값을 자동으로 설명하지는 않는다.

시뮬레이션 시간과 컴퓨터에서 걸린 실행 시간도 다르다. 45 ns까지 모형을 평가한 실행이 실제로 45 ns만 걸렸다는 뜻은 아니다. 실행하지 않았다면 예상 출력이라고 기록한다. 이 단원의 표와 기록 예시는 모두 가상 상황이지 도구 실행 로그가 아니다.

필요한 신호와 관측 단계를 함께 남긴다

카운터 오류라면 clk,rst,en,q와 비교한 기대 q를 함께 보자. q만 잘라낸 사진은 reset 우선순위나 입력 변경 시점을 설명하기 어렵다. 값의 비트 폭, 표시 진수, 시간 단위와 확대 범위를 적으면 같은 숫자를 다르게 해석하는 실수를 줄인다.

VCD 같은 파일은 값 변화와 시간을 기록하는 형식이다. Verilator 문서에서는 trace 옵션을 켜고 dump를 수행하는 절차를 설명한다. 파형 기록을 켜지 않았거나 필요한 신호를 누락한 실행에서 파일이 없다고 회로가 정상이라는 증거로 삼을 수 없다. 파일 생성과 기능 검사는 별도 결과다.

재현과 원인 수정 뒤 재검사를 분리한다

한 실패가 재현되면 먼저 명세와 관측 시점, 입력 폭을 확인한다. 에지 직후 읽어 이전 값을 본 시험 오류인지 회로 자체의 상태 갱신 오류인지 구별한다. 테스트벤치도 프로그램이므로 오류가 있을 수 있다. DUT를 고치기 전에 기대 모델과 읽기 규칙을 대조한다.

수정 후에는 최소 실패 사례와 관련 정상·경계 사례를 다시 검사하고 새 버전의 결과로 기록한다. 과거 성공을 새 코드의 성공으로 복사하지 않는다. 불필요한 중간 파형을 정리할 때도 결론을 뒷받침하는 원본·명령·입력·실패 기록은 보존해야 한다.

중간 과정을 따라가는 예제

가상 로그의 입력은 상승 에지25 ns에서 rst=0,en=1, 이전 q=1이고 기대 q=2다. 기록A는 에지 감지 직후 q=1, 기록B는 동일 시간 단계 평가 완료 뒤 q=2다. 무엇을 확인할지 적어라.

  1. 명세상 에지 뒤 최종 q는 2다. 입력과 이전 상태를 근거로 계산한다.
  2. 기록A의1은 회로 오류일 수도 있지만 에지 반응 전 값을 읽은 것일 수도 있다. 관측 단계 정보 없이 원인을 확정하지 않는다.
  3. 기록B의2가 실제 최종 관측이라면 이 행의 명세 비교는 통과한다. 다른 시각·입력의 검증까지 확대하지 않는다.
  4. 같은 회로·자극·도구 설정에서 평가 완료 관측으로 재현하고 assertion 결과와 파형을 함께 남긴다. 여기에 제시한A/B는 실제 실행 결과가 아닌 가상 기록이다.

관측 단계와 실제 최종 값을 확인해야 한다. 가상A만으로 회로 결함을 단정하지 않는다.
