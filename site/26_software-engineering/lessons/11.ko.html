소단원 11.1

정적 분석·동적 진단

프로그램을 실행하지 않아도 위험한 경로를 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 조건 분기와 함수 호출

  • 입력에 따라 달라지는 실행 경로

학습 목표

  • 정적 분석과 동적 진단의 관측 근거를 구별한다

  • 경고의 실제 경로와 분석 가정을 확인한다

  • 한 번의 정상 실행으로 전체 안전을 주장하지 않는다

변수마다 가능한 값을 합치면 실제로 없는 오류 경로가 생길 수 있을까?

새 수학적 의사 함수는 정수 n이 0이면 d = 1, 그렇지 않으면 d = n으로 정한 뒤 12/d를 계산한다. 두 분기를 합친 뒤 n과 d의 관계를 지우면 d의 후보에 정수 0이 있는 것처럼 추정할 수 있다. 그러나 실제 두 경로에서는 d = 1 또는 n ≠ 0인 d = n이므로 분모는 항상 0이 아니다. 이 예시는 특정 분석기가 실제 경고했다는 보고가 아니다.

변형은 n이 0이면 d = 0, 아니면 d = n으로 정한다. n = 3에서는 원본과 변형 모두 4지만 n = 0에서 원본은 12, 변형은 정의되지 않는다. 관측한 한 입력과 경로 조건을 보존하는 증명은 다른 근거다. 수학적 나눗셈의 0 분모만 다루며 언어별 정수 반올림이나 다른 오류의 안전성은 이 계약 밖이다.

경고 장부도 집합으로 읽는다. 합성 도구 A가 경고한 결함 ID는 {D1,D2,D3}, B는 {D2,D4}이고 독립 조사에서 D1,D2,D4만 실제 결함이었다고 가정한다. 두 도구의 경고 다섯 건을 다섯 개의 서로 다른 결함으로 세면 D2를 중복 계산한다. 실제 결함의 전체 집합이 주어지지 않았다면 이 표만으로 누락률을 정하지 않는다.

실행 전 경로를 생각한다

정적 분석은 소스나 중간 표현을 대상으로 프로그램의 성질을 추론한다. 단순 문법 검사뿐 아니라 가능한 값과 경로를 추적할 수 있다. Clang Static Analyzer는 경로에 민감한 분석과 함수 간 추적을 제공한다. 모든 정적 도구가 같은 범위와 보장을 갖는 것은 아니다.

정확한 모든 실행을 항상 알아낼 수 있는 도구라고 생각하지 않는다. 분석은 외부 함수의 동작, 입력 범위, 도구가 아는 가정에 영향을 받는다. 경고 위치만 지우기보다 어떤 경로와 가정으로 경고가 나왔는지 확인한다.

실행 중 실제 사건을 관찰한다

동적 진단은 실행 중 생긴 사건을 관찰한다. 로그와 디버거는 특정 시점의 값과 흐름을 확인하게 하고, AddressSanitizer 같은 도구는 컴파일 계측과 런타임 지원으로 특정 메모리 오류를 탐지한다. 모든 오류 종류를 한 도구가 찾는다는 뜻은 아니다.

입력 3에서 정상 실행했다는 사실은 입력 0의 경로까지 확인했다는 뜻이 아니다. 관측한 입력, 빌드 옵션, 환경을 기록한다. ASan의 보고 성질과 일반 정적 분석의 오탐 가능성을 같은 말로 묶지 않는다. 여기서는 도구를 설치하거나 실행하지 않았다.

경고를 판단하는 과정도 분석이다

경고가 실제 결함인지 조건이 도달 가능한지 확인한다. 실제로 불가능한 경로라면 그 불가능성의 근거를 남기고, 도구가 모르는 사용자 assert나 외부 계약은 적절한 모형 정보로 설명할 수 있다. 경고를 숨기는 것 자체가 결함 해결은 아니다.

자체 분류표에서 경고 6건 중 실제 결함 4건과 잘못된 경고 2건이 확인되었다면 확인된 경고의 정밀도는 4/6이다. 누락된 전체 결함 수를 모르면 재현율을 구할 수 없다. 작은 표의 비율을 특정 도구의 성능 측정으로 확대하지 않는다.

중간 과정을 따라가는 예제

자체 수학 의사 함수 f(n)는 정수 n에 대해 n=0이면 0을 반환하고 아니면 12/n을 반환한다. 정상 분모 조건을 경로별로 확인하라. 0 검사 없이 항상 12/n인 g를 입력 3에서만 보았다면 무엇이 남는가?

  1. f의 n=0 경로는 나눗셈을 하지 않고 0이다. n≠0 경로는 분모가 0이 아니므로 해당 위험은 없다.

  2. g(3)=4이지만 g(0)은 이 수학 모형에서 정의되지 않는다. 관측한 3의 결과만으로 0 입력을 안전하다고 할 수 없다.

  3. 정적 추론은 g의 가능한 0 경로를 검토하고 동적 관측은 제공한 입력의 사건을 기록한다. 실제 분석 도구의 보고를 생성한 것은 아니다.

f의 두 경로는 0 분모를 피한다. g의 한 정상 관측은 0 경로를 확인하지 않는다. 정수 나눗셈 언어별 반올림·예외 규칙은 이 모형 밖이다.

조건을 바꾸어 비교하기

관계를 지운 분석의 경고를 조사한다

원본에서 d = n이라는 관계만 보고 d = 0 경고 후보를 만들었다. 실제 경로는?

  1. d = n 대입은 n ≠ 0인 분기에서만 수행한다.

  2. 다른 분기의 d는 1이므로 d = 0인 실행 경로가 없다.

이 지정 모형의 0 분모 경고 후보는 실현되지 않는다. 경고 조사와 실제 도구 실행은 구별한다.

비교할 점

경고를 숨기기 전에 경로 불가능성의 근거를 보존한다.

합친 경고를 중복 제거한다

A와 B의 경고 집합 및 조사 결과에서 결합 경고의 정밀도는?

  1. 합집합은 {D1,D2,D3,D4} 네 ID다.

  2. 실제인 ID는 D1,D2,D4 세 개다.

고유 경고 ID 단위 정밀도는 3/4 = 75%다. 전체 실제 결함 수가 없으므로 재현율은 미정이다.

비교할 점

발생 보고 다섯 건 단위와 고유 ID 네 개 단위를 섞지 않는다.

같은 반환값을 만드는 추출이 외부 조회 횟수도 보존할까?

새 배송 종이 모형은 비음수 정수 소계를 입력받고 외부 threshold 조회를 정확히 한 번 수행한다. 조회 서비스가 순서대로 1000, 2000을 반환하도록 가정한다. 원래 함수는 t = read_threshold() 뒤 소계가 t 이상이면 0, 아니면 300을 반환한다. 추출한 순수 함수 shipping(subtotal, t)는 이 조건만 계산한다.

정상 추출은 한 번 읽은 t를 shipping에 넘긴다. 잘못된 추출은 먼저 t를 읽었는데도 helper가 내부에서 threshold를 다시 조회한다. 소계 1500에서는 원래 조회 1000으로 무료 0, 변형은 둘째 조회 2000으로 300이다. 반환값뿐 아니라 조회 횟수와 어떤 값의 버전을 사용했는지 모두 달라졌다. 실제 서비스나 Python 코드는 실행하지 않는다.

외부 조회가 늘 같은 1000을 반환하면 변형의 결과 0은 같지만 로그에는 조회 두 건이 남는다. 여기 계약이 정확히 한 번 조회라면 이 경우도 동작 보존은 아니다. 단순 숫자 반환 비교와 효과의 관찰 범위를 명시한다. 각 사례는 새 조회 상태에서 독립적으로 시작하며 먼저 한 사례의 두 조회를 소모한 뒤 다음 사례로 이어가지 않는다.

  • 현재 증거와 모형 조건

    손으로 예상한 로그를 실제 특성화 실행이라고 부르지 않는다.

관찰 가능한 약속을 보존한다

리팩터링은 관찰 가능한 동작을 보존하면서 내부 구조를 바꾸는 작업이다. 함수 추출과 이름 변경은 의도를 드러낼 수 있다. 반환값뿐 아니라 오류, 출력 순서, 외부 효과 등 어떤 관측을 보존할지 해당 계약에서 정한다.

같은 변경 묶음에서 경계 조건을 바꾸거나 기능을 추가하면 행동 변경이 섞인다. 그것이 필요한 작업일 수는 있지만 동작 보존 확인과 별도 목적을 기록한다. 단순히 코드를 줄였다는 사실만으로 리팩터링 성공을 판단하지 않는다.

기존 코드를 먼저 이해한다

여기서 레거시는 이미 존재하여 앞으로 유지·변경해야 하는 코드를 가리킨다. 나이가 오래됐다는 사실만으로 잘못된 코드라는 판정을 내리지 않는다. 계약·테스트·외부 의존을 충분히 모르는 상태가 변경을 어렵게 한다.

특성화 테스트는 현재 실제 동작을 발견하고 기록하는 방법이다. 그 기록이 곧 요구사항상 올바름의 증명은 아니다. 기존 이상한 결과를 사용자가 의존할 수도 있으므로 요구 확인 후 행동 변경 여부를 결정한다. 이 원고의 표는 손 추적한 예상값이며 실제 테스트로 발견한 결과가 아니다.

작은 단계로 추출한다

배송 규칙을 total 내부에서 shipping으로 추출하면 상품 합계와 배송 결정의 이름을 나눌 수 있다. 원래 상품 소계가 1000 이상이면 배송 0, 작으면 300이라는 규칙과 호출 순서를 유지한다. 출력이나 상태 변경이 없는 이 작은 순수 함수 범위에서 비교한다.

대표값만 아니라 경계 바로 아래·같은 값·바로 위를 비교한다. 테스트 몇 개 통과가 모든 입력의 증명은 아니므로 추출의 의미와 값 범위도 따진다. 작은 단계마다 확인하면 변화가 생긴 지점을 좁힐 수 있다.

로그는 읽은 값의 순서다. 첫 두 경로는 한 번 읽은 값을 인수로 전달한다. 변형은 첫 값을 버리고 둘째 값으로 조건을 검사한다.

중간 과정을 따라가는 예제

상품 소계는 음이 아닌 정수다. 기존 total은 소계+(소계>=1000이면 0 아니면 300)을 반환했다. 아래 추출 후 소계 999/1000/1001의 배송과 총액을 비교하라. 

def shipping(subtotal):
    return 0 if subtotal >= 1000 else 300

def total(subtotal):
    return subtotal + shipping(subtotal)

  1. 999는 경계 미만이므로 배송 300, 총액 1299다.

  2. 1000은 경계와 같아 배송 0, 총액 1000이다. 1001도 배송 0, 총액 1001이다.

  3. 전후는 동일 조건과 같은 덧셈을 사용하며 순수 계산의 입력과 반환이 같다. 예상값 표이며 실행 출력이 아니다.

전후 배송은 300/0/0, 총액은 1299/1000/1001로 같다. 소계 상승에 총액이 일시 감소하는 원래 규칙을 임의로 고치지 않았다.

변경 영향과 기술부채 관리

작은 규칙 하나를 바꾸었는데 왜 여러 화면을 확인해야 할까?

준비 개념과 학습 목표

준비 개념

  • 의존 관계와 방향 그래프

  • 가상 비용의 합계

학습 목표

  • 역방향 의존을 따라 영향 후보를 찾는다

  • 기술부채의 추가 변경 노력과 정리 비용을 비교한다

  • 추정값과 실제 검증을 구별해 우선순위를 세운다

순환 의존의 영향 후보와 불확실한 정리 비용을 어떻게 함께 기록할까?

새 그래프에서 X → Y는 X가 Y를 사용한다. 간선은 UI → A, A → B, B → A, Report → B, B → C다. C 변경의 영향 후보를 역방향으로 찾으면 C에서 B, 그 뒤 A와 Report, 그 뒤 UI가 나온다. A와 B의 순환에서 이미 방문한 노드를 다시 확장하면 멈추지 않을 수 있다. 방문 집합을 두면 후보는 다섯 개이고 탐색은 끝난다.

A 변경의 후보는 A,B,UI,Report 네 개다. C는 A가 사용하는 하위 대상에 있어 역방향 후보가 아니다. 그러나 이 장부 밖에 설정이나 동적 사용자가 빠졌을 수 있으므로 후보 제외는 실제 안전 인증이 아니다. 영향 후보와 실제 실패한 모듈은 다른 집합이다.

가상 유지 비용을 비교한다. 현 구조의 각 변경은5시간, 정리 비용은8시간이다. 정리 후 비용은 입력 계획에 따라3시간일 수도4시간일 수도 있다고 추정한다. 향후 네 변경에서는 기존20시간, 정리 후20시간 또는24시간이다. 정리 자체를 수행했거나 실제 시간을 측정한 것은 아니며 두 시나리오를 하나의 확정 절감으로 합치지 않는다.

먼저 확인할 개념
  • 역방향 영향 후보와 비용

    순환에서도 중복 방문을 막고 시나리오별 비용을 계산한다.

  • 정리와 기능 변경의 분리

    동작 보존과 비용 추정의 완료 기준을 따로 둔다.

누가 이 값을 사용하는가

의존 화살표 X→Y를 X가 Y를 사용한다는 뜻으로 정한다. Y를 바꾸면 Y를 사용하는 X가 영향을 받을 수 있다. 영향 후보를 찾을 때는 사용자를 향해 화살표의 역방향으로 올라간다. 바뀐 함수가 다른 것을 호출하는 순방향만 보면 사용자가 빠질 수 있다.

정적으로 적은 그래프는 계약 확인과 테스트 대상 선정의 출발점이다. 동적 호출, 설정 파일, 데이터 형식, 다른 저장소의 사용자가 빠졌을 수 있다. 영향 후보 집합이 실제로 모두 실패한다는 뜻도, 집합 밖이 무조건 안전하다는 뜻도 아니다.

추가 노력과 정리 비용을 분리한다

기술부채 비유는 현재 구조 때문에 앞으로 변경할 때 드는 추가 노력을 이자로, 구조를 정리하는 노력을 원금 상환으로 생각한다. 의도적 선택인지, 당시에는 몰랐는지와 선택이 신중했는지를 서로 다른 축으로 본다. 모든 불편한 코드를 한 숫자로 판정하지 않는다.

자주 바꾸는 영역은 같은 추가 노력이 반복될 수 있다. 반대로 앞으로 거의 변경하지 않을 영역은 정리 효과가 작을 수 있다. 변경 빈도와 추가 노력은 추정이며 실제 기록으로 갱신한다. 교육 예제의 시간은 비용 비교 방법을 위한 가상 값이다.

변경 계획으로 연결한다

어떤 계약을 유지할지, 영향 후보에 어떤 검증을 할지, 정리 비용과 예상 효과가 무엇인지 기록한다. 정리 완료 기준도 함수 이름 변경 같은 작업 나열이 아니라 구조와 확인 결과로 적는다. 기능 변경과 정리를 섞을 때는 각각의 목적을 구별한다.

가상 모형에서 매번 2시간을 줄여도 먼저 6시간을 써야 한다면 세 번 변경해야 시간 합계가 같아진다. 그 수는 위험, 불확실성, 실제 업무 우선순위를 모두 대신하지 않는다. 추정이 달라지면 비교도 다시 해야 한다.

중간 과정을 따라가는 예제

의존 그래프 UI→Service, Service→Rule, Report→Rule이며 다른 간선은 없다는 교육 모형이다. Rule을 변경할 때 자기 자신을 포함한 역방향 영향 후보 집합을 구하라.

  1. Rule에서 역방향 사용자인 Service와 Report를 찾는다.

  2. Service를 사용하는 UI도 추가한다. 중복은 제거하고 더 이상의 사용자가 없다.

  3. 자기 Rule까지 {Rule,Service,Report,UI} 네 개다. Rule의 순방향 후속만 보면 이 그래프에서 사용자는 하나도 발견하지 못한다.

네 후보 모두의 계약과 검증 범위를 살핀다. 실제 전부 오류가 났다는 실행 결과는 아니다.

새 n/d 두 분기의 원본과 변형에서 0 분모 경로를 판단하라. A = {D1,D2,D3}, B = {D2,D4}의 실제 결함 ID는 D1,D2,D4이고 전체 실제 결함 ID는 D1,D2,D4,D5,D6이다. 결합 경고의 정밀도와 재현율을 구하라. 각각 새 조회 목록 [1000,2000]에서 소계 1500의 정상 한 번 조회와 helper 재조회 결과·로그를 비교하라. 지정 순환 그래프에서 C와 A 변경의 후보를 찾고 정리 비용 8시간·기존 회당 5시간·정리 후 회당 3시간 또는 4시간의 엄격 절감 경계를 구하라.

힌트 1

경로 조건과 고유 ID를 보존하고 각 조회 사례는 독립 상태에서 시작한다.

힌트 2

역방향 방문 집합과 일회 비용을 사용하며 동률과 엄격 절감을 구별한다.

풀이와 답 확인

  1. 원본의 d는 1 또는 비0인 n이다. 변형은 n = 0에서 d = 0이므로 나눗셈이 정의되지 않는다.

  2. 고유 경고 네 개 중 실제 세 개로 정밀도는 75%다. 전체 실제 다섯 개 중 발견한 세 개로 재현율은 60%다.

  3. 정상은 [1000]을 읽어 배송 0을 반환한다. 재조회는 [1000,2000]을 읽어 배송 300을 반환한다.

  4. C 후보는 {C,B,A,Report,UI}이고 A 후보는 {A,B,UI,Report}다.

  5. 8 + 3n < 5n이면 최소 5회, 8 + 4n < 5n이면 최소 9회다.

조건·고유 표본·외부 효과·방문 집합·비용 시나리오를 함께 기록한다. 모두 자체 손모형이며 실제 도구·서비스·유지보수·학생 실험은 미수행이다.

해결한 뒤 점검할 것

  • 분기 관계로 원본의 0 분모 후보를 배제한다.

  • 중복 D2와 정밀도/재현율 분모를 구별한다.

  • 반환값과 조회 효과의 차이를 각각 설명한다.

  • 순환 탐색과 비용 동률/엄격 경계를 보존하며 미수행을 밝힌다.

보강 자료의 출처와 확인 범위
  • Clang Static Analyzer

    실제148–153행의 path-sensitive/inter-procedural symbolic execution 개요를 읽었다. 관계를 잃은 경고는 자체 추상 모형이고 특정 Clang 실행 결과가 아니다.

  • Clang AddressSanitizer

    실제149–198행의 계측/런타임·탐지범위·빌드 및 첫 오류 종료를 읽었다. 새 원고는 ASan 보고를 생성하지 않는다.

  • Martin Fowler — Refactoring

    실제64–76/86–93행의 외부 동작 보존·작은 변환·빈번한 검사와 구조 변경 구별을 읽었다. 조회 횟수 사례는 자체 계약이다.

  • Martin Fowler — Technical Debt

    실제74–101행의 추가 노력·일회 정리·변경 빈도·추정 불확실성을 읽었다. 비용/확률과 순환 그래프는 자체 값이다.

경로별 d 및 변형의 n = 0과 n = −2를 손검산했다. 보고 건 단위 4/5와 고유 ID 단위 3/4, 전체 실제 ID를 분모로 한 3/5를 대조했다. 독립 threshold 사례에서 소계 1500의 배송 0/300 및 소계 2000의 배송 0/0과 조회 횟수 1/2를 확인했다. C의 다섯 후보와 A의 네 후보, 비용 5n·8 + 3n·8 + 4n의 표 및 엄격 절감 경계 5/9회를 유도했다. 기대 비용 30/26시간과 두 번 변경 시 4시간 손해를 별도로 계산했다.
