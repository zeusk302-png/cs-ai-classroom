소단원 12.1

CI와 품질 게이트

검사 한 개가 초록색이면 바로 모든 사용자에게 공개해도 될까?

준비 개념과 학습 목표

준비 개념

  • 버전관리의 커밋
  • 단위시험과 통합시험
  • 의존성 그래프

학습 목표

  • CI의 반복 통합과 검사 조건을 설명한다.
  • job의 의존성과 가상 소요시간을 추적한다.
  • 통과한 범위와 검증하지 않은 범위를 구분한다.

작은 변경을 자주 통합하고 확인하기

CI는 팀의 변경을 자주 통합하고 자동 빌드와 검사를 통해 문제를 빠르게 찾는 활동이다. 버튼 하나나 특정 제품 이름만으로 성립하는 것은 아니다. 오래 따로 작업한 뒤 큰 충돌을 한번에 합치는 습관은 검사 도구가 있어도 통합 위험을 키울 수 있다.

자동 작업에는 시작조건,고정 소스 버전,실행환경,검사,산출물,결과 기록이 필요하다. GitHub Actions에서는 workflow 안에 job과step을 구성하고 needs로job 의존성을 나타낼 수 있다. 아래는 도구를 실행하지 않는 종이 그래프다.

품질 게이트는 구체적인 수용 조건

게이트는 다음 단계로 넘어가기 전 충족할 조건이다. 빌드 성공,필수시험 통과,형식검사,알려진 보안문제 처리와 같은 조건을 서비스 맥락에 맞게 정한다. 가상의 규칙에서 필수 A,B가 모두 통과해야 하는데 A만 통과했다면 전체 통과가 아니다.

초록색 표시는 실행한 검사에서 실패가 없었다는 증거다. 사용자 이해,접근성,실기기,운영 부하를 검사하지 않았다면 그 범위까지 입증하지 못한다. flaky시험의 재시도 성공도 원인을 숨기지 않도록 첫실패와 재시도를 함께 기록한다.

병렬 실행에도 선행 조건이 있다

가상 파이프라인은 build 뒤 unit/lint가 독립 병렬이고 둘 다 성공하면 package를 만든다. unit이 실패했는데 package가 의존성 없이 실행되면 게이트 설계를 어긴다. 작업을 나란히 배치한 그림과 실제로 병렬 자원이 확보됐다는 것은 다르다.

실제 시간에는 큐대기·checkout·캐시·전송이 추가된다. 아래 숫자는 그런비용0,충분한 runner,각job의 고정시간을 가정한다. 임계 경로를 종이에 계산하는 것과 실제 CI성능 측정 보고를 구별한다.

중간 과정을 따라가는 예제

build2분 뒤 unit5분과lint1분이 병렬이다. 두 성공 뒤package2분,그 뒤deploy1분이다. 큐/전송비용0,충분한 자원일 때 완료시간과unit실패시 가능단계를 구하라.

  1. build는0–2,unit2–7,lint2–3이다.
  2. 두검사 완료는max(7,3)=7이므로package7–9,deploy9–10이다.
  3. unit실패면두성공조건을못채우므로package/deploy를진행하지 않는다.

가상완료10분이다. 모두직렬이면2+5+1+2+1=11분이다. 실제성능1분개선을실측했다는 뜻은 아니다.

종이와 본문으로 직접 해보기

unit을3분으로 줄인 같은가정의 시간과lint가실패했는데unit이통과한 경우배포여부를 판단하라.

힌트 보기

검사둘의 최댓값과AND게이트를 각각 확인한다.

풀이 보기

2+max(3,1)+2+1=8분이다. lint도필수이므로실패시배포불가다. unit단독통과로게이트를대체하지않는다.

오해와 반례

모든자동검사가통과하면모든환경·모든사용자에서도오류가없다.

소단원 12.2

자동 배포·환경 설정

똑같은 파일을 올렸는데 테스트 서버와 공개 서버에서 다른 결과가 나오는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • CI산출물
  • 설정값과비밀값
  • 개발/시험/운영환경

학습 목표

  • 빌드한산출물의동일성과환경설정을나눠기록한다.
  • 환경보호규칙과최소권한을설명한다.
  • 설정오류와코드오류를구별한다.

배포할것을한번정하고추적하기

소스커밋만같아도도구나의존성버전이달라지면산출물이달라질수있다. 빌드환경과입력을고정하고산출물식별자를남긴다. 시험한파일을운영에승격하면운영단계에서몰래다시빌드한파일과의차이를줄일수있다.

산출물의내용해시와릴리스기록은어떤파일을사용했는지찾는근거다. 해시만있다고누가만들었는지인증하거나그파일이안전하다는것은아니다. 배포후실제서비스가가리키는식별자도확인한다.

코드와설정과비밀의각책임

같은코드는시험API와운영API에다른주소로연결할수있다. 주소·기능플래그·제한값의환경차이를검토하고설정버전도기록한다. 잘못된주소가들어가면프로그램파일이맞아도잘못된서비스에접속한다.

인증토큰은공개소스·공개빌드산출물·로그에적지않는다. 특히브라우저에전달하는정적파일에들어간값은방문자가읽을수있으므로비밀저장소에서가져왔다는이유로숨겨지지않는다. 서버측사용과공개클라이언트설정을구별한다.

자동화의권한과사전확인

배포job은배포대상·허용버전·필요권한을가져야한다. 환경보호규칙이나승인단계가있으면통과후에만해당환경secret에접근하도록구성할수있다. 어떤서비스에어떤게이트를둘지는위험과팀규칙에따른선택이다.

아래종이기록은승인·설정검사·대상확인을각각표시한다. 세조건중하나가실패하면중단한다. 자동화파일을작성했다는사실과실제자격증명/환경/네트워크에서배포를수행했다는사실을같게보고하지않는다.

중간 과정을 따라가는 예제

가상산출물A17을시험완료했다. 운영배포기록이artifact=A17,config=C4,target=prod인데C4의API주소가test이다. 승인도완료했다. 코드동일성·설정·대상게이트를판단하라.

  1. 시험산출물과배포산출물은A17로같다. 실내용해시가아닌교육식별자다.
  2. target은prod지만configC4는test주소여서운영주소검사실패다.
  3. 승인완료와산출물일치는설정실패를상쇄하지않으므로배포를보류하고설정을수정/검증한다.

산출물/대상은의도와일치하지만설정게이트실패다. 설정수정후같은산출물과새설정버전의조합을다시검사한다.

종이와 본문으로 직접 해보기

힌트 보기

풀이 보기

A18을시험했다는증거가없으므로A17검증을자동승계하지않는다. HTML토큰은방문자에게전달되므로비밀이아니다. 비밀을필요로하는작업은적절한서버측경계를설계해야한다.

오해와 반례

HTML응답의문자열은사용자가볼수있다. 저장할때비밀관리와배포후공개범위는별개다. 키노출이있었다면삭제만으로끝내지않고회수/교체등실제영향을확인해야한다.

소단원 12.3

릴리스·롤백·관측

새 버전을 되돌렸다는 로그만 있으면 사용자의 문제가 해결됐다고 볼 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 배포산출물식별
  • 오류율과비율
  • 데이터와설정

학습 목표

  • 릴리스기록과사용자관측을연결한다.
  • 가상의canary비율과중단조건을계산한다.
  • 롤백의데이터호환성과재확인을설명한다.

릴리스는변경내용과증거를묶는다

릴리스에는버전,변경내용,산출물/설정,검사,배포대상,알려진제약을남긴다. 일부사용자에게새버전을적용하는canary는영향을제한하며관측할수있지만,다양한사용자군전체를한번에대표한다는보장은없다.

어떤관측값을언제얼마나모아확대/중단할지미리정한다. 오류율·지연·핵심사용흐름과관측누락을함께본다. 아래100요청표는설명을위한가상표이며실제서비스실험이아니다.

비율의분자와분모를확인하기

오류10건이라는숫자만으로서비스상태를판단할수없다. 요청100개중10과10000개중10은다른비율이다. canary와기존그룹의같은기간·정의·분모를확인하고전체평균이작은그룹의악화를가리는지도본다.

자체규칙은canary오류율이2%를초과하면중단한다. 이임계값을모든서비스의보편적기준으로권고하지않는다. 작은표본의우연·사용자구성차이·기존오류원인까지분석하지않은단순판정이다.

되돌릴수있는범위를미리검토하기

롤백은이전코드나설정을다시활성화하는조치다. 새코드가저장한데이터형식을옛코드가읽을수없다면코드교체만으로복구되지않는다. 스키마변경·외부알림·사용자작업과같이되돌리기어려운효과를구분하고호환성이나복구경로를준비한다.

실행명령성공만으로복구완료라하지않는다. 실제버전/설정과사용자핵심흐름,오류관측을다시확인한다. 복구시간을계산할때탐지·결정·교체·검증중어디부터어디까지인지명시한다.

중간 과정을 따라가는 예제

가상canary100요청중오류5,기존900요청중오류9다. canary오류율>2%이면중단하는계약이다. 전체오류율과그룹별비율을계산하라. 탐지14:00,결정14:03,교체완료14:07,사용자검증14:10이다.

  1. canary5/100=5%,기존9/900=1%다. 전체14/1000=1.4%다.
  2. 전체1.4%가작아도canary5%>2%로중단한다.
  3. 탐지부터검증까지10분,결정부터교체까지4분이다. 시간구간이서로다르다.

중단대상은canary다. 이표만으로원인이나유의성을확정하지않는다. 가상복구구간은탐지→검증10분이며실측아니다.

풀이 보기

2/100=2%는초과아니므로이한규칙만으로중단하지않는다. 다른게이트나분석이있으면별도다. 옛코드는name없는새자료를읽지못할수있어호환변환/복구등을준비해야한다.

오해와 반례

옛코드만다시올리면새코드의모든영향이자동으로사라진다.

이미보낸알림은회수되지않을수있고저장형식도남는다. 코드·설정·데이터·외부효과별복구가능성과확인절차를분리해야한다.
