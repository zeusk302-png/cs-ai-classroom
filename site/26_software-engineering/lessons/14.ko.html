추정·지표·위험 재평가

계획의 절반을 했다는 말은 작업 수와 시간과 검증 중 무엇의 절반일까?

준비 개념과 학습 목표

준비 개념

학습 목표

  • 같은 프로젝트의 여러 진행률과 남은 기간을 구별한다.

  • 새 근거에 따라 위험과 일정 추정을 수정한다.

동시에 할 수 있는 작업도 같은 검토자를 기다리면 일정이 늘어나는가?

앞 본문은 순차 작업과 독립 작업의 기간을 구별했다. 새 가상 계획에서는 A가 2시간, B가 5시간, C가 3시간이고 B와 C는 A 완료 뒤 시작한다. D는 4시간이며 B와 C가 모두 검증된 뒤 시작한다. 각 작업의 자체 검증은 주어진 시간에 포함돼 있다. 사람 제한이 없고 인수인계가 없으면 시작 시각은 의존성만 결정한다.

두 가지 자원 계약을 비교한다. 계약 U에서는 B와 C를 서로 다른 사람이 동시에 맡는다. 계약 S에서는 같은 사람이 두 작업을 맡으며 선점이나 겹침이 없다. 작업의 선후 관계가 같아도 자원 계약이 달라지면 달력 기간이 달라진다. 현재 A만 완료된 시각 2에서 B의 추정이 5시간에서 8시간으로 바뀌면 처음 일정의 미완료 시간만 빼지 않고 남은 경로를 다시 계산한다.

위험의 연결도 같은 문제다. 가상 손실 사건 X의 확률은 0.2, Y의 확률은 0.3이고 각각 손실 100만 원과 40만 원이다. 두 손실은 동시에 발생하면 합산한다는 계약이다. 기대 손실의 합은 독립성 없이 구할 수 있지만 둘 중 하나라도 발생할 확률은 교집합에 따라 달라진다. 이 확률들은 교육용 가정이며 실제 팀의 관찰·완화 효과가 아니다.

완료의 기준과 분모부터 고정한다

자체 프로젝트는 작업 A·B·C·D를 수행한다. 각 작업은 코드 작성 후 검증까지 통과해야 완료라고 부른다. 작업 개수로 센 비율과 처음 추정한 노력을 가중치로 센 비율은 다를 수 있다. 검증되지 않은 코드 분량을 완료량에 바로 넣지 않는다.

진행률의 분모가 요구 변경으로 달라졌으면 이전 비율과 현재 비율을 같은 숫자인 것처럼 비교하지 않는다. 원래 범위 기준과 현재 범위 기준을 함께 보관하자. 투입 시간도 결과 완료를 직접 증명하지 않으며 낭비나 재작업 시간이 섞일 수 있다.

작업량과 달력 기간은 다르다

사람 시간은 일한 양이고 달력 기간은 의존성과 병렬성에 좌우된다. 한 사람이 12시간 걸리는 두 작업을 각각 다른 사람이 동시에 하면 이상적으로 12시간에 끝날 수도 있지만, 두 번째가 첫 번째 결과를 필요로 하면 24시간이 필요하다. 인수인계·휴식·검토 대기는 자체 단순 모형에서 따로 표시한다.

새로운 장애나 이해 부족을 발견하면 남은 작업을 다시 추정한다. 처음 값에 이미 쓴 시간을 빼기만 하면 재작업을 놓친다. 가장 가능성 있는 값과 범위, 전제, 언제 다시 볼지를 적는다. 범위는 자동으로 통계적 신뢰구간이 되는 것은 아니다.

위험도 새 근거에 따라 바뀐다

자체 위험표에는 조건·나쁜 결과·가능성 추정·영향·시점·담당·완화·재검토일을 적는다. 확률과 금액을 실제로 해석할 수 있는 가상 모형에서는 기대 손실 p×L을 계산할 수 있지만, '낮음/높음' 순서 점수의 곱을 금액처럼 읽지 않는다.

희귀하지만 감당하기 어려운 손실을 평균만으로 승인할 수 없다. 완화 방안도 비용과 새로운 위험을 만들 수 있다. 대응을 계획했다고 위험이 사라진 것은 아니며 실제 적용과 효과 확인 뒤에 남은 위험을 갱신한다. 아직 일어나지 않은 위험과 이미 발생한 결함도 구분한다.

U 열에서는 B와 C를 겹칠 수 있고 S 열에서는 같은 사람의 두 작업이 겹치지 않는다. 모든 시각은 계획 시작을 0으로 한 시간이다. S의 C 다음 B 순서도 총 14시간이며 사람이 더 있다는 이유로 D의 두 선행 검증을 없애지 않는다.

중간 과정을 따라가는 예제

자체 작업 A/B/C/D의 초기 노력은 2/6/4/8 사람 시간이다. A와 B만 검증 완료했다. C를 마친 뒤 D가 진행되어야 하고, 남은 추정은 C 5시간·D 9시간으로 바뀌었다. 같은 한 사람이 연속 작업하고 대기는 없다고 가정한다.

  1. 작업 개수 완료율은 2/4=50%다.

  2. 초기 가중 노력 합은 20이며 완료 작업의 가중치는 8이므로 8/20=40%다. 이미 쓴 시간의 비율을 계산한 것은 아니다.

  3. 새 남은 작업은 5+9=14시간이다. 초기 미완료 가중치 4+8=12시간만 고집하면 변경을 놓친다.

  4. 현재 범위에 E 4시간을 새로 추가하면 원래 기준은 여전히 2/4이고 현재 작업 수 기준은 2/5=40%다.

개수 50%·초기 노력 가중 40%·새 남은 시간 14시간은 서로 다른 지표다. E 추가 뒤의 분모 변화도 별도 기록한다.

조건을 바꾸어 비교하기

새 추정이 바뀐 경로만 다시 계산한다

시각 2에 A가 완료됐다. B의 남은 시간이 8시간, C는 3시간, D는 4시간이다. U와 S의 남은 기간과 계획 시작부터의 완료 시각을 구하라.

  1. U의 남은 기간은 max(8,3)+4=12시간이며 완료 시각은 14다.

  2. S는 같은 사람의 B와 C를 연속 수행하므로 8+3+4=15시간이 남고 완료 시각은 17이다.

초기 U의 완료 시각 11과 S의 14는 새 추정의 일정이 아니다. 이미 완료한 A의 2시간을 남은 기간에 다시 넣지 않는다.

비교할 점

같은 변경이 두 계약에서 모두 3시간 지연을 만들지만 남은 기간 자체는 다르다.

위험을 더할 때 독립성이 필요한 값은 무엇인가

손실은 X가 발생하면 100만 원, Y가 발생하면 40만 원이며 동시 발생 시 합산한다. P(X)=0.2, P(Y)=0.3만 알려져 있다. 기대 손실과 P(X 또는 Y)의 범위를 구하라.

  1. 기대 손실은 0.2×100+0.3×40=32만 원이다. 기대값의 선형성에는 독립성이 필요하지 않다.

  2. 교집합은 0부터 0.2까지 가능하므로 합집합은 0.5−교집합으로 0.3부터 0.5까지다. 독립일 때에만 교집합 0.06과 합집합 0.44를 쓴다.

기대 손실 32만 원과 사건 발생 확률 30–50%는 서로 다른 값이다. 손실이 중복 계산되거나 상한이 있으면 기대 손실 계약도 바꿔야 한다.

비교할 점

확률 합 0.5를 항상 정확한 합집합으로 쓰는 오류를 드러낸다.

종이와 본문으로 직접 해보기

가상 위험의 손실이 100만원이고 발생 확률 추정이 .2에서 .35로 바뀌었다. 기대 손실 변화를 구하라. 완화 비용 10만원을 쓰면 확률을 .1로 낮춘다는 가정의 총 기대 비용도 계산하라. 이것이 실제 성공 증거인가?

힌트 보기

각 확률에 같은 손실 금액을 곱하고 완화의 확정 비용은 따로 더한다.

풀이 보기

기대 손실은 20만원에서 35만원으로 증가한다. 완화 모형은 확정 비용 10만원+기대 손실 10만원=20만원이다. .1은 가정이며 적용과 효과 시험이 없다면 실제 위험 감소로 기록하지 않는다. 큰 손실 허용 여부도 따로 판단한다.

오해와 반례

작업 절반이 끝났으므로 남은 시간도 처음 예상 시간의 절반이다.

작업별 크기·의존성·재작업이 다르다. 예제에서 개수 50%와 초기 가중 40%가 다르고 새 남은 시간은 14시간이다. 무엇을 센 지표인지 설명해야 한다.

연습 1 · 값과 상태 예측

초기 U에서 C만 3시간에서 6시간으로 늘어나면 전체 기간은 얼마인가? A와 D는 같고 자원 제한은 없다.

힌트 1

B 완료는 시각 7이다.

힌트 2

C 완료와 B 완료 중 늦은 시각에 D를 시작한다.

풀이와 답 확인

  1. C는 시각 2에 시작해 8에 끝난다.

  2. D는 8에 시작해 12에 끝난다.

전체 12시간이며 C의 3시간 증가가 전체 3시간 증가가 되는 것은 아니다.

흔한 오답에서 다시 생각하기

초기 11시간에 C 증가 3시간을 더해 14시간이다.

처음 C에는 B 완료까지 2시간의 여유가 있어 증가 일부를 흡수한다.

연습 2 · 오류 찾아 고치기

새 B 추정 8시간을 반영한 U의 남은 기간을 2+8+3+4=17시간으로 보고했다. 틀린 두 경계를 찾아라.

힌트 1

A는 이미 완료했다.

힌트 2

U에서는 B와 C가 겹친다.

풀이와 답 확인

  1. 완료 A의 2시간을 남은 기간에서 제외한다.

  2. B와 C를 더하지 않고 max(8,3)을 사용해 남은 기간 12시간을 구한다.

17시간은 이 U 계약의 남은 기간이 아니다. 같은 숫자가 S의 전체 완료 시각이라는 사실로 정당화하지 않는다.

흔한 오답에서 다시 생각하기

결과가 다른 표의 값과 같으므로 맞다.

값뿐 아니라 시점과 자원 계약이 같은지 확인해야 한다.

연습 3 · 직접 만들어 보기

X와 Y의 주변 확률은 유지하면서 합집합이 0.3인 경우와 0.5인 경우의 교집합을 구성하라.

힌트 1

X가 Y 안에 포함되는 경우를 생각한다.

힌트 2

두 사건을 겹치지 않게 놓을 수 있는가?

풀이와 답 확인

  1. X⊆Y이면 교집합은 0.2이고 합집합은 0.3이다.

  2. 서로 배반이면 교집합은 0이고 합집합은 0.5다.

같은 주변 확률만으로 정확한 합집합을 고정할 수 없음을 두 분포가 보여준다.

흔한 오답에서 다시 생각하기

상관관계가 달라지면 기대 손실의 합도 반드시 달라진다.

손실을 사건별로 합산하는 현재 계약의 기대값은 주변 확률만으로 32만 원이다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

손실 100만 원과 확률 0.2의 X를 완화 비용 5만 원으로 확률 0.1까지 낮춘다는 가정이 있다. Y는 그대로다. 총 기대 비용과, X 손실이 200만 원 이상이면 불허한다는 별도 한계의 의미를 설명하라.

힌트 1

완화 비용은 확정 비용이다.

힌트 2

평균 비용과 개별 손실 허용 기준은 다른 판단이다.

풀이와 답 확인

  1. 총 기대 비용은 5+0.1×100+0.3×40=27만 원이다.

  2. 평균 개선 5만 원은 가정의 계산이며 개별 중대 손실 한계를 대체하지 않는다. 손실 자체가 200만 원 이상으로 바뀌면 해당 한계를 별도로 재평가한다.

확률 감소가 확인되지 않았다면 실제 위험 감소로 기록하지 않는다.

시험이 모두 성공해도 중요한 요구가 빠져 있을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 설계 구성요소

학습 목표

  • 양방향 추적표에서 미구현·미검증·근거 없는 기능을 찾는다.

시험 이름 세 개가 연결되면 수용 조건도 세 개 확인됐는가?

새 요구 R1은 정수 수량 1부터 12까지 허용하고 그 밖은 거절한다. R2는 거절 때 기존 재고와 기록을 보존한다. R3은 소유자만 수정할 수 있다. 후보는 commit h2와 환경 E2다. 시험 기록에는 요구 이름 외에 조건·commit·환경·실행 여부·기대값과 관찰을 남긴다. 동일한 R1 이름으로 정상 입력만 많이 시험해도 거절과 보존 조건은 자동으로 확인되지 않는다.

다섯 합성 기록을 표로 둔다. V1은 h2/E2에서 입력 12를 허용해 성공, V2는 h1/E2에서 입력 13을 거절해 성공이다. V3은 h2/E2에서 입력 0을 거절하는 기록만 있으며 변경 전후 재고는 관찰하지 않았다. V4는 h2/E1에서 비소유자를 거절했고 V5는 h2/E2에서 같은 비소유자 조건을 계획했지만 실행하지 않았다. 이 표는 실제 실행 결과가 아니라 검증 상태를 판정하는 종이 자료다.

현재 R1의 이 교육 평가 기준은 정상 경계 12와 거절 경계 13의 두 관찰이고 R2는 거절 및 상태 보존, R3은 E2의 비소유자 거절이다. 현재와 다른 commit·환경의 자료를 실패라고 부르지는 않지만 현재 조건 만족의 증거로 셀 수도 없다. 이 제한된 기준을 통과해도 모든 정수나 모든 동시 일정의 요구를 일반 증명한 것은 아니다.

먼저 확인할 개념
  • 요구별 연결과 현재 실행

    링크의 존재와 실제 조건·버전·환경 일치 증거를 구별한다.

  • 완료 기준과 진행률 분모

    시험 개수 대신 요구의 정의된 수용 조건을 기준으로 평가한다.

연결된 파일과 만족한 요구는 다르다

자체 추적표는 요구 R, 설계 D, 구현 C, 검증 V와 실행 기록 E를 연결한다. R에서 내려가면 해당 동작을 어디서 구현하고 어떻게 검증할지 찾으며 E에서 올라가면 성공 기록이 무슨 요구를 뒷받침하는지 찾는다. 시험 문서가 존재하는 것과 실제 실행 성공은 다른 상태다.

각 요구에는 관찰 가능한 수용 조건이 필요하다. '빠르게 동작한다'만 적으면 어떤 입력·부하·장비에서 어느 시간 이하인지 알 수 없다. 시험 이름을 요구에 붙여도 조건을 시험하지 않는다면 유효한 검증 연결이라고 보기 어렵다.

양쪽으로 걸어가며 빈 곳을 찾는다

자체 표의 R1은 D1/C1/V1/E1에, R2는 D2/C2/V2에, R3는 D3에만 연결돼 있다고 하자. R2에는 실행 기록이 없고 R3에는 구현과 시험이 없다. 전체 요구에서 내려가는 검토는 이 빈 곳을 드러낸다.

반대로 C9를 출발점으로 올라갔는데 요구나 승인된 근거가 없다면 불필요한 기능인지 누락된 요구인지 검토한다. 곧바로 코드를 지우라는 뜻은 아니다. 보안·장애 처리 같은 공통 지원 기능도 정당한 설계 근거를 문서화할 수 있다.

변경은 관련 근거를 다시 묻는다

요구가 수정되면 연결된 설계·코드·시험·기록을 따라 영향 후보를 찾는다. 후보 목록은 모든 실제 영향을 완벽히 증명하는 것이 아니므로 공통 모듈이나 데이터 형식의 간접 영향도 검토한다. 시험 실행의 commit, 입력, 환경과 날짜를 함께 남긴다.

R1의 경계가 바뀌었는데 예전 commit의 성공 기록을 현재 검증으로 옮기면 최신 동작을 확인한 셈이 아니다. 시험 재사용 가능성과 재실행 결과를 구별해야 한다. 추적표는 문서 장식이 아니라 어떤 근거가 현재 주장에 맞는지 찾는 도구다.

중간 과정을 따라가는 예제

자체 요구 R1/R2/R3의 검증 연결 V1/V2/없음과 현재 commit h2의 실행 기록 성공/미실행/없음을 평가하라. R1과 R2는 구현되었고 R3는 설계만 있다.

  1. 시험 연결이 존재하는 요구는 R1과 R2라서 연결 비율은 2/3≈66.7%다.

  2. 현재 commit에서 성공 실행으로 확인된 요구는 R1 하나이므로 요구 단위 성공 확인율은 1/3≈33.3%다.

  3. R2는 구현·시험 계획은 있으나 미실행이다. R3는 구현과 시험이 없으므로 두 상태를 같은 '시험 실패'로 표시하지 않는다.

  4. 시험 여러 개가 R1에 몰려 있어도 요구 분모에서 R1을 여러 번 세지 않는다. 조건 일부만 시험했다면 전체 요구 만족의 추가 검토가 필요하다.

연결 66.7%와 현재 실행 성공 33.3%는 다르다. R2 미실행과 R3 미구현도 구별한다.

  2. R1은 13 거절, R2는 보존, R3은 실제 실행이 빠져 완전 확인 요구는 0/3이다.

각 난이도에서는 장애율이 줄었는데 전체 장애율은 늘 수 있는가?

앞 본문은 장애 건수와 변경 수의 분모를 나눴다. 새 가상 회고는 쉬운 변경과 어려운 변경의 구성까지 보관한다. 개선 전 쉬운 변경 90개 중 장애 9개, 어려운 변경 10개 중 장애 5개다. 개선 후 쉬운 변경 10개 중 장애 0개, 어려운 변경 90개 중 장애 36개다. 모든 변경의 장애 유무는 합성 자료이며 실제 팀이나 사용자 기록이 아니다.

쉬운 그룹의 비율은 10%에서 0%, 어려운 그룹은 50%에서 40%로 낮아진다. 그러나 전체는 14%에서 36%로 높아진다. 후반의 어려운 변경 비중이 커졌기 때문이다. 같은 목표 구성으로 재가중한 비율은 구성 효과를 분리하는 계산이지만 표본·다른 환경·선택 방식의 차이를 제거한 인과 실험은 아니다.

회고 조치도 같은 관찰 원칙을 쓴다. 검사 G를 추가하고 정상 입력을 전부 차단하면 위험 입력 차단 사례만으로는 좋은 조치처럼 보일 수 있다. 조치 A의 구현 완료, 정상/위험 입력 동작 확인, 실제 노출 후 재발 관찰은 별도 단계다. 담당과 기한을 명시하되 개인 비난으로 미확인 원인을 대신하지 않는다.

기억 대신 확인 가능한 시간선을 만든다

자체 회고는 사건의 시작·탐지·완화·복구 확인과 영향 범위를 먼저 정리한다. 시계 기준과 증거가 없으면 시각을 추정이라고 표시한다. 변경과 오류가 가까운 시간에 나타났다는 사실만으로 변경이 유일 원인이라고 단정하지 않는다.

보고에는 어떤 로그·시험·설정 비교가 원인 가설을 뒷받침하는지 적는다. 원자료에 사용자의 개인정보가 있으면 교육용 공개 보고에 그대로 옮기지 않는다. 이 단원의 사건은 가상이라 실제 서비스 장애나 사용자의 자료가 포함되지 않는다.

행동을 시스템 조건과 연결한다

'누가 잘못했다'에만 머물면 같은 조건에서 다른 사람도 반복할 수 있다. 어떤 정보·기본값·검토·도구·시간 압박이 행동을 가능하게 했는지 살핀다. 비난하지 않는 회고도 실제 변경과 판단의 책임을 흐리는 문서가 되어서는 안 된다.

자체 조치에는 담당, 기한, 구현 완료 기준, 효과 검증 방법을 적는다. '주의하기' 대신 위험한 기본 설정의 검사·배포 전 차단 같은 구체적 동작을 제안한다. 한 번 성공한 시연과 반복 장애율 감소의 증거는 다르다.

기술 보고는 주장과 제한을 함께 보여 준다

자체 보고의 순서는 문제와 계약, 설계 선택, 근거, 결과, 남은 한계, 다음 조치다. 코드 완성과 시험 성공, 실제 사용성·현장 검증을 따로 적어 독자가 결과의 범위를 알게 한다. 반대 의견과 대안의 비용도 남겨 다음 팀이 판단을 재검토할 수 있게 한다.

개선 전후 숫자를 비교할 때 사건 수뿐 아니라 노출된 변경 수나 요청 수를 분모로 확인한다. 기간·환경·표본 구성이 다르면 직접 인과 효과로 단정하지 않는다. 회고 문서가 작성됐다고 조치가 실행되거나 효과가 입증되는 것은 아니다.

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

전 기간의 쉬운 변경 장애 기록 9건 중 한 건이 중복이었다. 분모는 90개 그대로다. 전체와 목표 50/50 계산을 다시 구하고 정정 이력을 설명하라.

원래 보고와 정정 사유를 함께 보존한다.

풀이와 답 확인

  1. 전 전체는 (8+5)/100=13%, 쉬운 비율은 8/90=4/45다.

  2. 전 목표는 (4/45+1/2)/2=53/180≈29.44%다. 후 목표 20%와 차이는 약 9.44퍼센트포인트다.

중복 수정으로 계산을 갱신하고 원자료 식별·정정 근거를 남긴다. 후 기간 기록까지 임의로 바꾸지 않는다.
