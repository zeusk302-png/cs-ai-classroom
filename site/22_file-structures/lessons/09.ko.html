소단원 9.1

정적 해싱과 오버플로

빈 페이지가 있는데 특정 검색만 느려지는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 나머지 연산 k mod M은 0부터 M−1까지의 값을 만든다.
  • 페이지는 여러 레코드를 담는 고정 크기 저장 단위다.

학습 목표

  • 고정 버킷 수와 충돌 처리 방법을 구별한다.
  • 해시 편향에 따른 페이지 방문과 공간 이용률을 계산한다.

주소 계산과 같은 버킷의 충돌

정적 해싱은 기본 버킷 수 M과 주소 계산 규칙을 고정한다. 여기서는 정수 키 k를 k mod M번 기본 버킷으로 보내고 한 버킷을 한 데이터 페이지로 둔다. 이것은 계산하기 쉬운 교육용 해시 함수이며 실제 시스템의 좋은 해시 함수라고 주장하지 않는다.

서로 다른 키가 같은 주소로 가는 충돌은 오류가 아니다. 기본 페이지가 가득 찼을 때의 정책이 필요하다. 이 소단원은 연결된 오버플로 페이지에 추가 레코드를 저장한다. 메모리 해시 표의 선형 탐사처럼 이웃 기본 슬롯을 찾는 방식과 구별한다.

페이지 사슬을 끝까지 따라가기

동등 조건 검색은 키의 버킷을 계산하고 그 기본 페이지부터 사슬을 읽는다. 찾으면 멈추지만 없는 키라면 해당 사슬을 끝까지 확인해야 한다. 다른 기본 버킷이 비었다고 해서 같은 해시 주소의 사슬이 저절로 짧아지지는 않는다.

균등 분포와 적절한 부하에서 평균 검색이 빠를 수 있어도 모든 입력에서 한 번의 입출력을 보장하지 않는다. 여기의 페이지 방문 수는 캐시가 없고 키와 레코드가 함께 저장된 모형에서만 읽기 횟수와 같다. 포인터 표·로그·동시 접근 비용은 포함하지 않는다.

분포와 공간의 분모

기본 버킷 수는 그대로여도 오버플로 페이지를 할당하므로 전체 데이터 페이지 수는 늘 수 있다. 정적이라는 말은 파일의 물리 크기가 절대 변하지 않는다는 뜻이 아니다.

전체 할당 슬롯 대비 저장 레코드 수와 기본 슬롯 대비 레코드 수는 분모가 다르다. 평균 이용률이 낮아도 한 사슬에 집중될 수 있다. M을 바꾸려면 주소 규칙에 맞춰 기존 레코드를 다시 배치해야 하므로 단순히 빈 페이지 한 장만 추가하는 것과 다르다.

중간 과정을 따라가는 예제

M=4, 페이지당 2레코드, 처음부터 기본 페이지 4장을 할당한다. 키 0,4,8,12,1,5를 순서대로 삽입하고 같은 버킷의 오버플로 사슬을 만든다. 키 12와 없는 키 16 검색, 전체 공간 이용률을 구하라.

  1. 0,4,8,12는 모두 mod 4가 0이다. 기본 0번에 [0,4], 오버플로 한 장에 [8,12]를 담는다.
  2. 1,5는 기본 1번의 [1,5]에 들어간다. 기본 2,3번은 비어 있다.
  3. 총 데이터 페이지는 기본 4장+오버플로 1장=5장이다. 12는 두 번째 페이지에서 발견하고 16은 두 페이지 모두 확인한 후 없다고 판단한다.
  4. 전체 슬롯은 5×2=10개이므로 이용률 6/10=0.6이다. 기본 슬롯 기준 6/8=0.75는 전체 할당 공간 이용률과 다른 값이다.

12와 16은 각각 2페이지 방문이다. 전체 이용률은 60%지만 0번 사슬은 길이가 2다.

종이와 본문으로 직접 해보기

같은 상태에 16을 추가하라. 총 페이지 수와 16 검색 방문 수, 전체 이용률을 구하라.

힌트 보기

기본 0번과 첫 오버플로는 이미 가득 찼다.

풀이 보기

두 번째 오버플로 페이지에 [16]을 둔다. 총 페이지는 6장, 16 검색은 기본부터 3장 방문, 전체 이용률은 7/(6×2)=7/12이다.

오해와 반례

전체 이용률이 절반 정도면 충돌이 없다.

키가 0번으로 집중되어 기본 2,3번이 비어 있는데도 오버플로가 생긴다. 평균 공간 지표와 가장 긴 사슬은 별도로 보아야 한다.

자기점검

기본 버킷 수를 그대로 두면 오버플로도 생길 수 없는가?

답과 이유 보기

아니다.

고정되는 것은 기본 주소 집합이다. 충돌 정책이 추가 페이지를 허용할 수 있다.

예제에서 키 5는 몇 데이터 페이지를 방문하는가?

답과 이유 보기

1장이다.

기본 1번 [1,5]에서 찾고 멈춘다.

없는 키 2를 검색할 때 0번 사슬도 읽는가?

답과 이유 보기

읽지 않는다.

2 mod 4=2이며 올바르게 관리된 빈 2번 기본 페이지만 확인한다.

한 단계 더

M=8로 전체 레코드를 재배치하면 키 0,8은 0번, 4,12는 4번으로 나뉜다. 키 16까지 포함하면 0번에 세 키가 되어 다시 오버플로가 필요하다. 버킷 확대와 분포 개선이 모든 충돌 제거를 뜻하지 않음을 종이에 확인하라.

소단원 9.2

확장 해싱·선형 해싱

파일을 키울 때 모든 레코드를 한꺼번에 다시 옮겨야 할까?

준비 개념과 학습 목표

준비 개념

  • 이진수의 낮은 두 비트는 정수 mod 4와 같다.
  • 한 버킷에 여러 디렉터리 항목이 연결될 수 있다.

학습 목표

  • 전역 깊이와 지역 깊이를 구별해 분할을 추적한다.
  • 선형 해싱의 분할 포인터와 두 주소 함수를 적용한다.

확장 해싱의 두 깊이

확장 해싱은 디렉터리와 버킷을 분리한다. 전역 깊이 g라면 디렉터리 항목 수는 2^g다. 버킷의 지역 깊이 l은 그 버킷을 구별하는 해시 비트 수이며 l≤g다. 균일한 디렉터리에서 같은 버킷을 가리키는 항목 수는 2^(g−l)이다.

여기서는 낮은 비트를 사용하고 디렉터리→버킷의 고전적인 두 단계 교육 모형을 쓴다. CMU 2024 디스크 과제는 고정 헤더까지 있는 세 단계 변형이므로 이 작은 모형을 그 구현 전체와 같다고 부르지 않는다. 또한 예제 키는 고유하다.

넘친 버킷만 나누기

버킷이 넘칠 때 지역 깊이를 한 단계 늘려 새 비트로 레코드를 두 버킷에 재분배한다. l<g라면 기존 디렉터리의 일부 포인터를 바꾸면 된다. l=g라면 먼저 디렉터리를 두 배로 늘려 구별 비트를 확보한다.

디렉터리 두 배는 모든 데이터 버킷 두 배를 뜻하지 않는다. 분할 대상 밖의 버킷은 여러 항목이 계속 공유할 수 있다. 새 비트로도 한쪽에 집중되면 다시 분할해야 하고 최대 깊이 등의 제한에 도달하면 별도 실패 정책이 필요하다.

선형 해싱의 순서 있는 성장

선형 해싱은 디렉터리를 두 배로 만드는 대신 다음 분할 버킷 s를 추적한다. 현재 기본 크기 N에 대해 먼저 b=k mod N을 계산한다. 이미 분할된 b<s라면 k mod (2N)으로 다시 계산하고, 아니면 b를 쓴다. 버킷 수는 N+s다.

분할이 촉발되면 넘친 위치와 관계없이 s번을 나누고 새 s+N번을 만든다. s를 하나 늘리고 s=N에 도달하면 N을 두 배로 바꾸고 s=0으로 다음 라운드를 시작한다. 분할을 촉발하는 부하·사슬 길이 정책은 구현마다 다르며 오버플로가 바로 없어지리라는 보장은 없다.

중간 과정을 따라가는 예제

확장 해싱은 용량 2, g=1이다. 디렉터리 0은 지역 깊이 1인 E=[0,2], 1은 지역 깊이 1인 O=[1]을 가리킨다. 키 4 삽입을 추적하라. 별도로 선형 해싱 N=2,s=0, 버킷 0=[0,2,4], 1=[1,3]에서 한 번의 순서 분할을 추적하라. 선형의 0번 세 키는 용량 2의 오버플로를 포함한다.

  1. 확장: 4 mod 2=0이라 E가 넘친다. l=g=1이므로 g=2, 디렉터리 항목 4개로 만든다.
  2. 낮은 두 비트로 0,4는 00, 2는 10이다. E00=[0,4], E10=[2]의 지역 깊이는 각각 2다. O=[1]은 지역 깊이 1로 01,11이 공유한다. 실제 버킷은 3개다.
  3. 선형: 다음 분할 s=0의 레코드를 mod 4로 나눠 0=[0,4], 새 2=[2]로 만든다. 기존 1=[1,3]은 그대로며 s=1이다.
  4. 키 2는 2 mod 2=0<s이므로 mod 4=2로 다시 보낸다. 키 3은 3 mod 2=1≥s라 1번으로 보낸다.

확장 결과는 g=2·디렉터리 4항목·버킷 3개다. 선형 결과는 N=2,s=1·버킷 3개이며 두 주소 함수로 구분한다.

종이와 본문으로 직접 해보기

확장 결과에 6을 넣고, 선형 결과에서 다음 분할 1번을 실행하라. 두 구조를 서로 독립적으로 계산하라.

힌트 보기

6 mod 4=2다. 선형 분할은 1,3을 mod 4로 나눈다.

풀이 보기

확장 10 버킷은 [2,6]으로 채워지며 g=2 유지다. 선형은 1=[1], 새 3=[3]으로 나누고 s=2가 되므로 N=4,s=0으로 라운드를 전환한다. 최종 버킷 0=[0,4],1=[1],2=[2],3=[3]이다.

오해와 반례

선형 해싱은 넘친 버킷을 반드시 즉시 나눈다.

분할 대상은 포인터 s가 지정한다. 예컨대 N=4,s=0에서 2번이 넘쳐도 선택 정책이 한 번의 분할을 촉발하면 먼저 0번을 나눈다. 2번의 오버플로는 이후 라운드 진행 전까지 남을 수 있다.

자기점검

g=3,l=1인 버킷을 몇 디렉터리 항목이 공유하는가?

답과 이유 보기

4개다.

2^(3−1)=4다. 포인터 수와 레코드 수는 다르다.

확장 예제에서 키 3의 목적지는 어디인가?

답과 이유 보기

O 버킷이다.

낮은 두 비트 11은 O를 가리키며 O의 지역 깊이는 여전히 1이다.

선형 N=4,s=1에서 키 12는 몇 번 버킷인가?

답과 이유 보기

4번이다.

12 mod 4=0<1이므로 12 mod 8=4를 적용한다.

한 단계 더

확장 결과의 E00=[0,4]에 8을 추가하면 세 키가 낮은 두 비트 00으로 충돌한다. g를 3으로 늘리면 mod 8에 의해 0,8은 000, 4는 100으로 나뉜다. 데이터 재분배가 한 버킷에 국한되는 것과 디렉터리 항목 복사는 다른 비용임을 설명하라.

소단원 9.3

분할·축소·공간 비용

버킷 하나가 비면 디렉터리도 바로 절반으로 줄여도 될까?

준비 개념과 학습 목표

준비 개념

  • 전역 깊이는 디렉터리 비트 수, 지역 깊이는 버킷 구별 비트 수다.
  • 메타데이터와 레코드 페이지의 공간을 따로 센다.

학습 목표

  • 병합 정책과 디렉터리 축소 조건을 구별한다.
  • 공유 포인터를 중복 버킷으로 세지 않고 공간을 계산한다.

병합은 정책과 짝을 확인한다

이 소단원은 CMU 2024 과제의 보수적인 규칙처럼 삭제 후 빈 버킷만 병합 후보로 둔다. 같은 지역 깊이의 분할 짝이 있어야 하며 병합하면 깊이를 하나 낮추고 두 포인터 집합을 남은 버킷으로 연결한다.

분할 짝은 마지막 구별 비트만 반대인 버킷이다. 공간이 여유 있다고 임의의 다른 버킷 두 개를 합치면 주소 해석이 깨질 수 있다. 두 비빈 버킷의 합이 용량 이하라면 합치는 적극적인 정책도 가능하지만 여기서 선택한 빈 버킷 정책과는 다르다.

디렉터리 축소는 전체 깊이 검사

병합과 디렉터리 축소는 별도 단계다. 모든 버킷의 지역 깊이가 전역 깊이 g보다 작아야 디렉터리의 구별 비트 하나가 더 이상 필요 없으므로 g를 하나 낮출 수 있다. 일부 버킷이 여전히 l=g면 그 비트를 제거할 수 없다.

한 버킷이 비었어도 짝의 깊이가 다르면 병합을 거부할 수 있고, 병합했어도 다른 버킷의 깊이 때문에 디렉터리를 유지할 수 있다. 최소 깊이·재귀 병합 조건·파일 페이지 반환은 구현 규칙에 따라 따로 결정한다.

포인터 공간과 데이터 이동

디렉터리 공간은 항목 수×포인터 크기로 센다. 같은 버킷을 가리키는 여러 포인터를 여러 데이터 페이지라고 세면 중복이다. 실제 공간은 헤더·깊이 배열·정렬·빈 공간·페이지 할당 단위 등을 추가해야 한다.

분할은 그 버킷의 레코드를 재분배하지만 포인터 갱신, 캐시, 로그와 동시 실행까지 포함한 실측 비용은 여기서 정하지 않는다. 삭제 직후 축소와 다음 삽입 직후 확대를 반복하면 비용이 흔들리므로 실무에서는 임계값을 다르게 두는 정책도 고려할 수 있다.

중간 과정을 따라가는 예제

용량 2,g=2다. 00→A=[0,4],10→B=[2]는 각각 l=2이고 01,11→O=[1]은 l=1이다. 키 2 삭제 후 빈 버킷 병합과 축소를 추적하라. 별도로 g=3, 고유 버킷 5장, 포인터 8바이트·버킷 페이지 4096바이트인 모형의 공간을 계산하라. 그 외 메타데이터는 제외한다.

  1. 2를 지우면 B가 빈다. B의 분할 짝 A는 같은 지역 깊이 2이며 합친 레코드 [0,4]는 용량 2에 맞는다.
  2. 병합 후 A의 지역 깊이는 1이며 00,10이 A를 공유한다. O도 l=1이라 모든 깊이가 g=2보다 작다.
  3. g=1로 축소하면 0→A=[0,4],1→O=[1]이다. 디렉터리는 2항목, 버킷은 2장이다.
  4. 별도 공간 모형에서 디렉터리는 2³×8=64바이트, 고유 버킷은 5×4096=20480바이트다. 합은 20544바이트다.

삭제 모형은 병합 후 g=1로 축소할 수 있다. 공간 모형의 계산상 합은 20544바이트이며 실제 파일 할당 크기 측정값은 아니다.

종이와 본문으로 직접 해보기

힌트 보기

A=[4],B=[2]는 둘 다 비어 있지 않다. 데이터 페이지 수가 그대로인 메타데이터 복사 단계만 센다.

풀이 보기

빈 버킷만 병합한다는 정책에서는 병합하지 않으며 l=2인 버킷이 남아 g=2 유지다. 포인터 공간은 64→128바이트로 64바이트 증가한다. 이후 분할로 추가할 데이터 페이지 비용은 이 단계 계산에 포함하지 않는다.

오해와 반례

디렉터리에 8항목이면 데이터 버킷도 반드시 8장이다.

l<g인 버킷은 여러 항목이 공유한다. 예제처럼 고유 버킷 5장인 g=3 상태가 가능하다. 예컨대 지역 깊이 2인 버킷 세 개와 깊이 3인 두 개는 공유 항목 수 3×2+2×1=8을 채운다.

한 단계 더

삭제와 삽입이 번갈아 일어나는 키 집합을 종이에 만들어 확대·축소 횟수를 세어 보라. 최소 깊이, 빈 버킷 병합 정책, 분할 촉발 조건을 먼저 적어야 같은 입력에 대한 비용을 비교할 수 있다. 실제 디스크 파일 반환·복구 안전성 실험은 수행하지 않았다.
