소단원 9.1

정적 해싱과 오버플로

빈 페이지가 있는데 특정 검색만 느려지는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 나머지 연산 k mod M은 0부터 M−1까지의 값을 만든다.

  • 페이지는 여러 레코드를 담는 고정 크기 저장 단위다.

학습 목표

  • 고정 버킷 수와 충돌 처리 방법을 구별한다.

  • 해시 편향에 따른 페이지 방문과 공간 이용률을 계산한다.

같은 파일도 어떤 키를 자주 찾느냐에 따라 평균 읽기가 달라질까?

기본 본문의 정적 M = 4, 페이지당 두 레코드에서 16까지 넣은 상태를 사용한다. 0번 사슬은 [0,4]→[8,12]→[16], 1번은 [1,5], 2와 3은 빈 기본 페이지다. 캐시 없이 키와 레코드가 함께 있으며 포인터 표 비용은 제외한다. 전체 이용률 7/12는 저장 공간 지표다. 조회할 키의 확률 분포를 나타내지는 않는다.

저장된 일곱 키를 각각 한 번씩 조회하면 키 0, 4, 1, 5는 각각 페이지 읽기 1회, 키 8과 12는 각각 2회, 키 16은 3회가 필요하다. 총 페이지 읽기는 4×1+2×2+3=11회이며 조회당 평균은 11/7회이다. 별도 부재 조회 작업에서는 없는 키 20을 확률 90%, 없는 키 2를 확률 10%로 조회한다고 정한다. 키 20은 0번 사슬의 세 페이지를 끝까지 읽고, 키 2는 빈 기본 2번 페이지 하나만 읽는다. 따라서 평균 페이지 읽기는 0.9×3+0.1×1=2.8회이다. 파일과 공간 이용률이 그대로여도 조회 분포에 따라 평균 비용은 달라진다.

별도 삭제 정책은 지워진 슬롯만 비우고 페이지와 다음 링크를 유지한다. 키 0과 4를 삭제하면 기본 0번 페이지는 비지만 후속 페이지의 키 8, 12, 16은 남는다. 키 16을 찾으려면 빈 기본 페이지, [8,12] 페이지, [16] 페이지를 차례로 읽어야 하므로 총 페이지 읽기는 3회이다. 빈 기본 페이지에서 종료하면 존재하는 키 16을 놓친다. 이 연결 사슬의 종료 조건은 다음 포인터가 없는 상태이며, 선형 탐사 표의 빈 슬롯 종료 규칙과 다르다.

주소 계산과 같은 버킷의 충돌

정적 해싱은 기본 버킷 수 M과 주소 계산 규칙을 고정한다. 여기서는 정수 키 k를 k mod M번 기본 버킷으로 보내고 한 버킷을 한 데이터 페이지로 둔다. 이것은 계산하기 쉬운 교육용 해시 함수이며 실제 시스템의 좋은 해시 함수라고 주장하지 않는다.

서로 다른 키가 같은 주소로 가는 충돌은 오류가 아니다. 기본 페이지가 가득 찼을 때의 정책이 필요하다. 이 소단원은 연결된 오버플로 페이지에 추가 레코드를 저장한다. 메모리 해시 표의 선형 탐사처럼 이웃 기본 슬롯을 찾는 방식과 구별한다.

페이지 사슬을 끝까지 따라가기

동등 조건 검색은 키의 버킷을 계산하고 그 기본 페이지부터 사슬을 읽는다. 찾으면 멈추지만 없는 키라면 해당 사슬을 끝까지 확인해야 한다. 다른 기본 버킷이 비었다고 해서 같은 해시 주소의 사슬이 저절로 짧아지지는 않는다.

균등 분포와 적절한 부하에서 평균 검색이 빠를 수 있어도 모든 입력에서 한 번의 입출력을 보장하지 않는다. 여기의 페이지 방문 수는 캐시가 없고 키와 레코드가 함께 저장된 모형에서만 읽기 횟수와 같다. 포인터 표·로그·동시 접근 비용은 포함하지 않는다.

분포와 공간의 분모

기본 버킷 수는 그대로여도 오버플로 페이지를 할당하므로 전체 데이터 페이지 수는 늘 수 있다. 정적이라는 말은 파일의 물리 크기가 절대 변하지 않는다는 뜻이 아니다.

전체 할당 슬롯 대비 저장 레코드 수와 기본 슬롯 대비 레코드 수는 분모가 다르다. 평균 이용률이 낮아도 한 사슬에 집중될 수 있다. M을 바꾸려면 주소 규칙에 맞춰 기존 레코드를 다시 배치해야 하므로 단순히 빈 페이지 한 장만 추가하는 것과 다르다.

중간 과정을 따라가는 예제

M=4, 페이지당 2레코드, 처음부터 기본 페이지 4장을 할당한다. 키 0,4,8,12,1,5를 순서대로 삽입하고 같은 버킷의 오버플로 사슬을 만든다. 키 12와 없는 키 16 검색, 전체 공간 이용률을 구하라.

  1. 0,4,8,12는 모두 mod 4가 0이다. 기본 0번에 [0,4], 오버플로 한 장에 [8,12]를 담는다.

  2. 1,5는 기본 1번의 [1,5]에 들어간다. 기본 2,3번은 비어 있다.

  3. 총 데이터 페이지는 기본 4장+오버플로 1장=5장이다. 12는 두 번째 페이지에서 발견하고 16은 두 페이지 모두 확인한 후 없다고 판단한다.

  4. 전체 슬롯은 5×2=10개이므로 이용률 6/10=0.6이다. 기본 슬롯 기준 6/8=0.75는 전체 할당 공간 이용률과 다른 값이다.

12와 16은 각각 2페이지 방문이다. 전체 이용률은 60%지만 0번 사슬은 길이가 2다.

조건을 바꾸어 비교하기

성공 조회의 균등 평균

저장 키 일곱 개를 각각 한 번 찾는다. 총 읽기와 평균은?

  1. 키 0, 4, 1, 5의 네 조회는 각각 첫 페이지에서 찾으므로 합계 페이지 읽기 4회가 필요하다.

  2. 키 8과 12의 두 조회는 각각 두 페이지를 읽어 합계 4회가 필요하다. 키 16 조회는 세 페이지를 읽으므로 총 읽기는 4+4+3=11회이다.

일곱 조회의 총 페이지 읽기는 11회이고, 조회당 평균은 11/7회로 약 1.571회이다.

비교할 점

저장 레코드의 공간 이용률7/12를 평균 읽기로 대체하지 않는다.

빈 기본 페이지 뒤의 살아 있는 키

0과4만 삭제하고 사슬 링크와 나머지 레코드는 유지했다. 키16을 찾는 경로는?

  1. 빈 기본0번의 다음 링크를 따라간다.

  2. 오버플로[8,12] 뒤[16]에서 찾는다.

세 페이지를 차례로 읽어 키 16을 찾는다. 빈 기본 페이지에서 멈추면 부재로 잘못 판단한다.

비교할 점

연결 사슬의 종료 조건을 선형 탐사의 빈 슬롯 규칙과 섞지 않는다.

종이와 본문으로 직접 해보기

같은 상태에 16을 추가하라. 총 페이지 수와 16 검색 방문 수, 전체 이용률을 구하라.

힌트 보기

기본 0번과 첫 오버플로는 이미 가득 찼다.

풀이 보기

두 번째 오버플로 페이지에 [16]을 둔다. 총 페이지는 6장, 16 검색은 기본부터 3장 방문, 전체 이용률은 7/(6×2)=7/12이다.

오해와 반례

전체 이용률이 절반 정도면 충돌이 없다.

키가 0번으로 집중되어 기본 2,3번이 비어 있는데도 오버플로가 생긴다. 평균 공간 지표와 가장 긴 사슬은 별도로 보아야 한다.

자기점검

기본 버킷 수를 그대로 두면 오버플로도 생길 수 없는가?

답과 이유 보기

아니다.

고정되는 것은 기본 주소 집합이다. 충돌 정책이 추가 페이지를 허용할 수 있다.

예제에서 키 5는 몇 데이터 페이지를 방문하는가?

답과 이유 보기

1장이다.

기본 1번 [1,5]에서 찾고 멈춘다.

없는 키 2를 검색할 때 0번 사슬도 읽는가?

답과 이유 보기

읽지 않는다.

2 mod 4=2이며 올바르게 관리된 빈 2번 기본 페이지만 확인한다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

없는 20과 없는 2를 각각 50% 찾으면 평균 읽기는?

힌트 1

20은 0번 사슬 3페이지다.

힌트 2

2는 빈 기본 2번 1페이지다.

풀이와 답 확인

  1. 0.5 × 3 + 0.5 × 1을 계산한다.

  2. 합은 2다.

평균 2읽기다. 같은 파일의 90%/10% 작업 평균 2.8과 다르다.

흔한 오답에서 다시 생각하기

파일이 같으면 모든 조회 분포의 평균도 같다.

평균은 각 조회 비용에 그 조회 확률을 곱한 합이다.

연습 2 · 오류 찾아 고치기

기본 0번이 비었다며 16 조회 종료를 부재 성공으로 표시했다. 삭제는 0과 4만이고 링크는 유지됐다.

힌트 1

다음 오버플로의 레코드가 살아 있다.

힌트 2

종료 포인터를 확인한다.

풀이와 답 확인

  1. 기본 0번→[8,12]→[16]을 따라간다.

  2. 16을 찾아 존재로 수정한다.

빈 기본 페이지와 빈 전체 사슬을 구별한다. 실제 파일 삭제는 실행하지 않았다.

흔한 오답에서 다시 생각하기

처음 페이지가 비면 후속 페이지도 반드시 빈다.

이 삭제 정책은 후속 레코드나 링크를 지우지 않는다.

연습 3 · 직접 만들어 보기

M = 4 파일을 M = 8 주소로 바꾸는 계획을 써라. 기존 기본 페이지 번호 0..3만 남긴 채 M값만 고치면 키 12 조회는?

힌트 1

12 mod 8 = 4다.

힌트 2

기존 12는 0번 사슬에 있고 새 4번 기본 페이지도 아직 없다.

풀이와 답 확인

  1. 새 주소별 기본 페이지와 사슬을 구성한다.

  2. 기존 레코드를 새 mod 8 주소로 재배치하고 전체 보존을 검사한다.

  3. 독자는 완료된 같은 주소 규칙과 데이터 상태를 사용하도록 계획한다.

M만 고친 상태의 12→4 조회는 올바른 기존 위치를 찾지 못한다. 실제 원자 전환·복구 구현은 별도다.

흔한 오답에서 다시 생각하기

버킷 수 숫자를 고치면 레코드도 자동으로 새 주소로 이동한다.

주소 계산과 물리 레코드 재배치를 함께 해야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

0과 4 삭제 뒤 페이지 반환 없이 그대로 두면 전체 이용률과 16 조회 읽기는?

힌트 1

저장 레코드는 7에서 5가 된다.

힌트 2

할당 6페이지 × 2슬롯은 유지된다.

풀이와 답 확인

  1. 전체 이용률은 5/12다.

  2. 16은 끝의 오버플로에 있어 3읽기다.

공간 이용률은 낮아져도 긴 사슬의 이 조회는 3읽기 그대로다.

준비 개념과 학습 목표

준비 개념

  • 이진수의 낮은 두 비트는 정수 mod 4와 같다.

  • 한 버킷에 여러 디렉터리 항목이 연결될 수 있다.

학습 목표

  • 전역 깊이와 지역 깊이를 구별해 분할을 추적한다.

  • 선형 해싱의 분할 포인터와 두 주소 함수를 적용한다.

더 쓸 수 있는 해시 비트가 없으면 분할만 반복해도 해결될까?

자체 두 단계 확장 해싱은 hash(k) = k의 낮은 비트를 쓰고 최대 전역 깊이를 3, 버킷 용량을 2로 정한다. 현재 g = 3에서 지역 깊이 3인 000 버킷에 [0,8]이 있다. 새 키 16도 낮은 3비트 000이므로 같은 버킷을 넘친다. 0,8,16은 서로 다른 유일 키이며 전체 해시값도 다르지만 사용 가능한 주소 비트가 같다.

이 사례의 실패 정책은 최대 깊이 3을 넘기지 않고 새 16 삽입을 거부하며 기존 두 레코드와 디렉터리를 보존하는 것이다. 무한히 분할하거나 같은 버킷에 세 레코드를 성공했다고 저장하지 않는다. 실제 구현의 실패 원자성이나 되돌림은 이 정책을 구현하고 검사해야 한다. 별도로 최대 깊이 4를 허용하면 낮은 4비트에서 0,16은 0000, 8은 1000으로 나누어 두 버킷 용량 2에 맞는다.

선형 해싱의 별도 모형은 N = 4, s = 2라 버킷 0..5가 있다. 키 13은 13 mod 4 = 1 < s이므로 13 mod 8 = 5로 보낸다. 키 14는 14 mod 4 = 2로 아직 분할되지 않은 버킷 2에 보낸다. 다음 분할은 s = 2이며 그 버킷의 [2,6,10,14]를 mod 8로 재분배해 2 = [2,10], 새 6 = [6,14]로 만든다. 이후 s = 3이라 14는 6으로 간다. 전부 mod 8을 미리 적용하면 분할 전에는 없는 버킷 6을 가리킨다.

확장 해싱의 두 깊이

확장 해싱은 디렉터리와 버킷을 분리한다. 전역 깊이 g라면 디렉터리 항목 수는 2^g다. 버킷의 지역 깊이 l은 그 버킷을 구별하는 해시 비트 수이며 l≤g다. 균일한 디렉터리에서 같은 버킷을 가리키는 항목 수는 2^(g−l)이다.

여기서는 낮은 비트를 사용하고 디렉터리→버킷의 고전적인 두 단계 교육 모형을 쓴다. CMU 2024 디스크 과제는 고정 헤더까지 있는 세 단계 변형이므로 이 작은 모형을 그 구현 전체와 같다고 부르지 않는다. 또한 예제 키는 고유하다.

넘친 버킷만 나누기

버킷이 넘칠 때 지역 깊이를 한 단계 늘려 새 비트로 레코드를 두 버킷에 재분배한다. l<g라면 기존 디렉터리의 일부 포인터를 바꾸면 된다. l=g라면 먼저 디렉터리를 두 배로 늘려 구별 비트를 확보한다.

디렉터리 두 배는 모든 데이터 버킷 두 배를 뜻하지 않는다. 분할 대상 밖의 버킷은 여러 항목이 계속 공유할 수 있다. 새 비트로도 한쪽에 집중되면 다시 분할해야 하고 최대 깊이 등의 제한에 도달하면 별도 실패 정책이 필요하다.

선형 해싱의 순서 있는 성장

선형 해싱은 디렉터리를 두 배로 만드는 대신 다음 분할 버킷 s를 추적한다. 현재 기본 크기 N에 대해 먼저 b=k mod N을 계산한다. 이미 분할된 b<s라면 k mod (2N)으로 다시 계산하고, 아니면 b를 쓴다. 버킷 수는 N+s다.

분할이 촉발되면 넘친 위치와 관계없이 s번을 나누고 새 s+N번을 만든다. s를 하나 늘리고 s=N에 도달하면 N을 두 배로 바꾸고 s=0으로 다음 라운드를 시작한다. 분할을 촉발하는 부하·사슬 길이 정책은 구현마다 다르며 오버플로가 바로 없어지리라는 보장은 없다.

중간 과정을 따라가는 예제

확장 해싱은 용량 2, g=1이다. 디렉터리 0은 지역 깊이 1인 E=[0,2], 1은 지역 깊이 1인 O=[1]을 가리킨다. 키 4 삽입을 추적하라. 별도로 선형 해싱 N=2,s=0, 버킷 0=[0,2,4], 1=[1,3]에서 한 번의 순서 분할을 추적하라. 선형의 0번 세 키는 용량 2의 오버플로를 포함한다.

  1. 확장: 4 mod 2=0이라 E가 넘친다. l=g=1이므로 g=2, 디렉터리 항목 4개로 만든다.

  2. 낮은 두 비트로 0,4는 00, 2는 10이다. E00=[0,4], E10=[2]의 지역 깊이는 각각 2다. O=[1]은 지역 깊이 1로 01,11이 공유한다. 실제 버킷은 3개다.

  3. 선형: 다음 분할 s=0의 레코드를 mod 4로 나눠 0=[0,4], 새 2=[2]로 만든다. 기존 1=[1,3]은 그대로며 s=1이다.

  4. 키 2는 2 mod 2=0<s이므로 mod 4=2로 다시 보낸다. 키 3은 3 mod 2=1≥s라 1번으로 보낸다.

확장 결과는 g=2·디렉터리 4항목·버킷 3개다. 선형 결과는 N=2,s=1·버킷 3개이며 두 주소 함수로 구분한다.

오해와 반례

선형 해싱은 넘친 버킷을 반드시 즉시 나눈다.

분할 대상은 포인터 s가 지정한다. 예컨대 N=4,s=0에서 2번이 넘쳐도 선택 정책이 한 번의 분할을 촉발하면 먼저 0번을 나눈다. 2번의 오버플로는 이후 라운드 진행 전까지 남을 수 있다.

  • 병합 정책과 디렉터리 축소 조건을 구별한다.

  • 공유 포인터를 중복 버킷으로 세지 않고 공간을 계산한다.

공유 포인터 하나만 고치면 새 버킷의 키를 모두 찾을까?

자체 g = 3 디렉터리에서 지역 깊이 2인 A = [0,4]를 000과 100이 공유하고, 001/101은 C = [1,5], 010/110은 D = [2,6], 011/111은 E = [3,7]을 공유한다. 용량 2에서 8을 A에 삽입하면 l < g라 디렉터리를 키우지 않고 A만 나눈다. 낮은 3비트로 000 버킷 [0,8]과 100 버킷 [4]를 만들며 둘의 지역 깊이는 3이다.

디렉터리 000만 고치고 100을 옛 A 주소로 남기면 키 4가 100에서 [0,8]을 읽어 누락된다. 같은 버킷을 공유하던 모든 항목의 포인터와 깊이를 새 분할 상태에 맞춰 갱신해야 한다. 고유 버킷은 기존 4에서 5개가 되지만 디렉터리는 여전히 8항목이다. 공유 수는 두 깊이 3 버킷의 1 + 1과 나머지 세 깊이 2 버킷의 2 + 2 + 2로 합 8이다.

이후 4를 삭제하면 100 버킷이 비고 000 분할 짝은 같은 지역 깊이 3이다. 빈 버킷만 병합하는 정책에서 [0,8]로 합쳐 l = 2를 만들고 000/100이 공유하게 한다. 모든 버킷의 l = 2가 g = 3보다 작아 g = 2로 축소한다. 분할 직후에는 l = 3이 남아 축소할 수 없다. 실제 페이지 반환·동시 접근·복구 안전성은 이 완료 상태의 종이 검사와 별도로 확인해야 한다.

병합은 정책과 짝을 확인한다

이 소단원은 CMU 2024 과제의 보수적인 규칙처럼 삭제 후 빈 버킷만 병합 후보로 둔다. 같은 지역 깊이의 분할 짝이 있어야 하며 병합하면 깊이를 하나 낮추고 두 포인터 집합을 남은 버킷으로 연결한다.

분할 짝은 마지막 구별 비트만 반대인 버킷이다. 공간이 여유 있다고 임의의 다른 버킷 두 개를 합치면 주소 해석이 깨질 수 있다. 두 비빈 버킷의 합이 용량 이하라면 합치는 적극적인 정책도 가능하지만 여기서 선택한 빈 버킷 정책과는 다르다.

디렉터리 축소는 전체 깊이 검사

병합과 디렉터리 축소는 별도 단계다. 모든 버킷의 지역 깊이가 전역 깊이 g보다 작아야 디렉터리의 구별 비트 하나가 더 이상 필요 없으므로 g를 하나 낮출 수 있다. 일부 버킷이 여전히 l=g면 그 비트를 제거할 수 없다.

한 버킷이 비었어도 짝의 깊이가 다르면 병합을 거부할 수 있고, 병합했어도 다른 버킷의 깊이 때문에 디렉터리를 유지할 수 있다. 최소 깊이·재귀 병합 조건·파일 페이지 반환은 구현 규칙에 따라 따로 결정한다.

포인터 공간과 데이터 이동

디렉터리 공간은 항목 수×포인터 크기로 센다. 같은 버킷을 가리키는 여러 포인터를 여러 데이터 페이지라고 세면 중복이다. 실제 공간은 헤더·깊이 배열·정렬·빈 공간·페이지 할당 단위 등을 추가해야 한다.

분할은 그 버킷의 레코드를 재분배하지만 포인터 갱신, 캐시, 로그와 동시 실행까지 포함한 실측 비용은 여기서 정하지 않는다. 삭제 직후 축소와 다음 삽입 직후 확대를 반복하면 비용이 흔들리므로 실무에서는 임계값을 다르게 두는 정책도 고려할 수 있다.

중간 과정을 따라가는 예제

용량 2,g=2다. 00→A=[0,4],10→B=[2]는 각각 l=2이고 01,11→O=[1]은 l=1이다. 키 2 삭제 후 빈 버킷 병합과 축소를 추적하라. 별도로 g=3, 고유 버킷 5장, 포인터 8바이트·버킷 페이지 4096바이트인 모형의 공간을 계산하라. 그 외 메타데이터는 제외한다.

  1. 2를 지우면 B가 빈다. B의 분할 짝 A는 같은 지역 깊이 2이며 합친 레코드 [0,4]는 용량 2에 맞는다.

  2. 병합 후 A의 지역 깊이는 1이며 00,10이 A를 공유한다. O도 l=1이라 모든 깊이가 g=2보다 작다.

  3. g=1로 축소하면 0→A=[0,4],1→O=[1]이다. 디렉터리는 2항목, 버킷은 2장이다.

  4. 별도 공간 모형에서 디렉터리는 2³×8=64바이트, 고유 버킷은 5×4096=20480바이트다. 합은 20544바이트다.

삭제 모형은 병합 후 g=1로 축소할 수 있다. 공간 모형의 계산상 합은 20544바이트이며 실제 파일 할당 크기 측정값은 아니다.

정적 M = 4·용량 2의 0번 사슬 [0,4]→[8,12]→[16], 1번 [1,5], 빈 2,3번에서 저장 일곱 키의 균등 성공 조회 평균과 부재 20을 90%·부재 2를 10% 찾는 평균을 계산하라. 0과 4 삭제 뒤 빈 기본 페이지와 링크를 유지하면 16은 어떻게 찾나? 별도 확장 g 최대 3·용량 2·000 버킷 [0,8]에 16 삽입 시 기존 상태 보존·새 키 거부 정책을 설명하라. 선형 N = 4, s = 2에서 13,14의 주소와 s = 2 분할 뒤 14 주소는? 별도 g = 3에서 000/100이 공유하는 l = 2 버킷 [0,4]에 8을 넣을 때 디렉터리 두 항목을 어떻게 고쳐야 하나? 페이지 40·헤더 4·항목 9B인 자체 디렉터리 g = 3→4의 할당량 증가도 계산하라.

힌트 1

조회 확률과 사슬 길이, 사용 가능한 비트와 이미 분할된 주소를 나눈다.

힌트 2

모든 별칭과 지역 깊이를 검사하고 포인터 바이트와 페이지 할당량을 구별한다.

풀이와 답 확인

  1. 균등 성공 조회 평균은 11/7, 부재 작업은 0.9 × 3 + 0.1 × 1 = 2.8이다. 삭제 뒤 빈 0번의 링크를 따라 두 오버플로를 읽어 16을 찾으며 3읽기다.

  2. 16 mod 8 = 0으로 기존 0,8과 사용 가능한 비트가 같다. 깊이 제한 3에서 더 분할하지 않고 16을 거부하며 기존 상태를 유지한다는 정책이다. 실제 실패 원자성은 별도 검증 대상이다.

  3. 13 mod 4 = 1 < s = 2라 mod 8 = 5, 14 mod 4 = 2 ≥ s = 2라 2다. s = 2 분할 뒤 s = 3이 되면 14는 mod 8 = 6이다.

  4. 000을 [0,8] 버킷과 l = 3으로, 100을 [4] 버킷과 l = 3으로 고치며 g = 3은 유지한다. 100을 옛 포인터로 두면 4를 누락한다.

  5. 항목은 페이지당 4개다. g = 3의 8항목 2페이지 80B에서 g = 4의 16항목 4페이지 160B로 늘어 80B 증가한다.

자체 종이 해시·분할·할당 모형의 결과다. 실제 DB·해시 파일·실패 원자성·페이지 반환·동시성·장치 성능·학생 실험은 미수행이다.

해결한 뒤 점검할 것

  • 조회 분포를 가중 평균에 반영한다.

  • 빈 기본 페이지와 전체 사슬 종료를 구별한다.

  • 깊이 제한과 선형 주소 선택을 현재 상태에 맞게 적용한다.

  • 모든 디렉터리 별칭과 실제 할당 바이트를 검사한다.

저장 키 일곱 개의 균등 성공 조회에서 총 페이지 읽기는 4×1+2×2+3=11회이며 조회당 평균은 11/7회이다. 부재 키 20과 2의 조회 비중이 90%와 10%이면 평균 읽기는 2.8회이고, 각각 50%이면 2회이다. 키 0과 4를 삭제하되 할당 페이지와 링크를 유지하면 전체 공간 이용률은 5/12이며 키 16 조회는 세 페이지를 읽는다. 최대 깊이 3에서 키 0, 8, 16은 낮은 세 비트가 모두 000이라 새 키 16을 거부한다. 깊이 4를 허용한 별도 조건에서는 0000 버킷에 0과 16, 1000 버킷에 8을 둔다. 선형 N=4, s=2에서 키 13의 목적지는 버킷 5, 키 14는 버킷 2이다. 버킷 2를 분할하면 기존 버킷 2에 2와 10, 새 버킷 6에 6과 14를 두고 s=3으로 갱신한다. 다음 라운드 경계는 N=8, s=0이며 키 14의 목적지는 계속 버킷 6이다. 전역 깊이 3의 A 분할은 지역 깊이 3인 두 버킷과 지역 깊이 2인 세 버킷을 만들어 고유 버킷 수가 5, 디렉터리 공유 항목의 합이 1+1+2+2+2=8이 된다. 키 4 삭제 뒤 빈 버킷 병합은 지역 깊이 2와 전역 깊이 2의 고유 버킷 네 개를 만들며 남은 데이터 레코드 여덟 개를 유지한다. 자체 40B 페이지에서 헤더 4B와 항목 9B를 적용하면 페이지당 항목은 네 개이다. 디렉터리 할당은 전역 깊이 3에서 80B, 깊이 4에서 160B로 80B 증가한다. 고유 버킷 네 개의 합계 512B를 유지하는 별도 모형에서는 전체 할당이 592B에서 672B로 증가한다.
