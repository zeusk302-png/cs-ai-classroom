소단원 5.1

삽입·삭제·자유 공간

책 번호가 정해지지 않은 상자에 새 책을 빨리 넣으려면 빈자리를 어떻게 찾을까?

준비 개념과 학습 목표

준비 개념

  • 레코드는 한 행의 자료, 페이지는 읽고 쓰는 저장 단위다. 아래에서는 고정 크기 레코드를 사용한다.

  • 힙 파일의 힙은 우선순위 큐의 힙 자료구조와 다르며 레코드 순서가 보장되지 않는다는 뜻이다.

학습 목표

  • 빈 슬롯 관리와 레코드 위치 확인을 분리한다.

  • 삭제 표시·압축·자유 공간 정보의 역할을 추적한다.

빈 공간 요약이 충분하다고 했는데 삽입이 안 되면?

자체 가변 레코드 삽입에서는 자료 24바이트와 새 슬롯 4바이트로 연속 공간 28바이트가 필요하다. 데이터 페이지 P1과 P2의 실제 연속 여유는 각각 16과 31바이트다. 작은 디렉터리는 16바이트 단위로 올린 상한을 보관한다고 정한다. P2의 현재 상한은 32다. P1은 이전 여유에 대한 오래된 상한 32가 아직 남아 있다. 두 요약이 모두 32여서 후보로 보이지만 P1의 현재 여유를 정확히 요약한 값은 16이다.

P1을 먼저 읽어 실제 16바이트임을 확인하면 삽입할 수 없다. P2를 읽으면 31바이트라 삽입하고 연속 여유 3바이트가 남는다. 상한은 불가능한 페이지를 후보로 포함할 수 있지만 후보만 보고 쓰기를 승인하지 않는다. 반대로 16바이트 단위로 내린 하한을 충분조건으로만 쓰면 P2도 16으로 보여 가능한 자리를 놓칠 수 있다. 후보의 실제 검증과 못 찾았을 때의 추가 탐색 정책을 구별한다.

별도 냉간 비용은 디렉터리 한 페이지와 데이터 P1/P2가 모두 없고 캐시는 읽은 세 페이지를 유지하며 다른 I/O는 없다고 정한다. 디렉터리 읽기 1회, P1/P2 읽기 2회, P2 쓰기 1회, 변경 디렉터리 쓰기 1회로 총 5회다. 처음부터 정확한 요약으로 P2만 선택하면 같은 모형에서 4회다. 삽입을 찾는 요약과 자료 키를 찾는 인덱스·동시 갱신·장애 복구는 별도의 조건이다.

먼저 확인할 개념
  • 빈 슬롯·디렉터리·삽입 비용

    요약의 후보와 실제 페이지 상태 및 슬롯 비용을 나눈다.

  • 갱신 시점과 검색 대상

    미뤄진 관리 작업과 실제 반영 범위를 확인한다.

빈자리를 아는 것과 찾는 것은 다른 일이다

힙 파일은 정렬 위치를 유지할 필요가 없어 충분한 빈 공간이 있는 페이지에 삽입한다. 하지만 페이지마다 무작정 읽으면 빈자리 탐색 비용이 생긴다. 페이지 디렉터리에 페이지 위치와 남은 공간을 기록하면 데이터 페이지 대신 작은 요약을 먼저 조사할 수 있다.

이 구조가 모든 삽입을 무조건1I/O로 만드는 것은 아니다. 디렉터리도 저장되어 있고 필요한 페이지를 읽고 바꾼 뒤 다시 써야 한다. 캐시된 요약인지, 레코드 크기와 슬롯 추가 비용이 있는지에 따라 비용이 다르다. 레코드 이름으로 찾는 검색 경로는 빈 공간 요약과 별개다.

고정 슬롯에 살아 있는지 표시한다

페이지 안에4개의 고정 슬롯을 두고 비트1을 사용 중,0을 비어 있음으로 정하자. 삭제는 해당 슬롯 비트를0으로 바꾸어 다음 삽입이 재사용할 수 있게 한다. 레코드 ID를 (페이지 번호,슬롯 번호)로 표현하면 어느 자리에 접근할지 알 수 있다.

단순히 뒤 레코드를 한 칸 앞으로 당기는 조밀 배열 방식은 비트맵 방식과 다르다. 이동하면 슬롯 번호로 접근하던 참조의 의미가 바뀔 수 있다. 가변 길이 슬롯 디렉터리에서는 슬롯이 레코드 위치·길이를 가리키게 하여 이동과 논리 식별을 분리할 수 있지만 그 정책도 구현에 따라 확인해야 한다.

남은 바이트의 합만으로 충분한가

가변 길이 자료에서 삭제한 작은 구멍이 여러 개 있으면 총 빈 바이트가 크더라도 한 레코드가 들어갈 연속 공간이 부족할 수 있다. 페이지 내부 압축은 살아 있는 자료를 모아 연속 공간을 만든다. 이것을 파일 전체의 키 정렬 재구성과 혼동하지 않는다.

새 슬롯 항목 자체도 공간을 차지할 수 있고 페이지 헤더·정렬 패딩 등의 비용도 있다. 따라서 본문의 고정4슬롯 계산을 실제 모든 페이지의 바이트 용량 계산으로 그대로 일반화하지 않는다. 레코드 삭제가 저장장치의 원래 바이트를 안전하게 소거했다는 뜻도 아니다.

P1의 표에 나타난 16은 현재 여유의 정확한 올림값이다. 아래 삽입 비교에서는 디렉터리에 이전 상태의 32가 남았다는 별도 조건을 사용한다. 실제 페이지를 읽은 뒤 최신 여유를 확인한다.

중간 과정을 따라가는 예제

페이지P1,P2는 각각4슬롯이다. P1 비트는1101, P2는1010이다. 왼쪽부터 슬롯1..4이며 가장 앞 빈 슬롯을 재사용한다. P1의 슬롯2를 삭제한 뒤 새 레코드R,S를 P1에 차례로 삽입하라.

  1. 처음 P1 사용 슬롯은1,2,4, 빈 슬롯3이다. 사용3/빈1이다.

  2. 슬롯2 삭제 후1001, 사용2/빈2다.

  3. R을 첫 빈 슬롯2에 넣어1101이다. S를 슬롯3에 넣어1111이다.

  4. R의 ID=(P1,2), S=(P1,3)이다. P2는 변하지 않고1010, 빈 슬롯2,4다.

P1은 가득 차고 P2는 두 자리 여유다. 디렉터리의 P1 빈 슬롯 수도2→1→0으로 갱신해야 한다.

조건을 바꾸어 비교하기

낡은 상한의 후보 실패

디렉터리에 P1 상한 32가 오래된 값으로 남아 있다. 실제 여유 16에서 28바이트를 넣을 수 있나?

  1. 요약은 32여도 실제 페이지 검증은 16이다.

  2. 28은 16보다 크므로 삽입을 승인하지 않는다.

실제 검증에서 실패하고 다른 후보를 찾는다.

비교할 점

정확한 올림 16과 오래된 값 32를 같은 상태로 취급하지 않는다.

후보를 두 번 읽은 삽입 비용

낡은 P1 상한 32 때문에 P1을 읽고 실패한 뒤 P2에 넣는다. 냉간 디렉터리 1개, 캐시 유지 조건에서 총 읽기·쓰기는?

  1. 디렉터리·P1·P2 읽기 3회다.

  2. P2와 수정 디렉터리 쓰기 2회다.

총 5 I/O다. 실패 후보 P1은 자료를 바꾸지 않아 쓰지 않는다.

비교할 점

실제 P2만 선택하는 정확한 요약의 4 I/O와 비교한다.

종이와 본문으로 직접 해보기

P1에 새 레코드T를 한 개 더 넣으려 할 때 P2로 옮기는 과정을 써라. 이번에는 삭제한 슬롯의 자료를 실제 지웠다고 볼 수 있는지도 답하라.

힌트 보기

P1 빈 수0, P2 첫 빈 슬롯2를 선택한다.

풀이 보기

T=(P2,2)에 넣어 P2는1110, 여유1이다. 사용 표시를0으로 만들었다는 사실만으로 예전 자료의 모든 복제·물리 바이트가 소거됐다고 결론내릴 수 없다. 이 모형은 공간 재사용만 설명한다.

오해와 반례

삭제로 빈 바이트 합이 충분해지면 어떤 길이의 레코드든 바로 넣을 수 있다.

10바이트 구멍 두 개의 합20은15바이트 연속 자료를 넣을 자리와 다를 수 있다. 압축 또는 다른 페이지가 필요하다. 고정 슬롯에서는 슬롯 하나의 고정 크기 이내라는 별도 조건을 사용한다.

연습 1 · 값과 상태 예측

P2에 자료 24와 새 슬롯 4를 넣으면 실제 연속 여유와 그 16단위 올림 상한은?

힌트 1

남은 값은 31에서 28을 뺀다.

힌트 2

양수 3을 다음 16의 배수로 올린다.

풀이와 답 확인

  1. 실제 여유는 3바이트다.

  2. 올림 상한은 16바이트다.

실제 3, 요약 상한 16이다. 이 상한만으로 10바이트 삽입을 승인하지 않는다.

흔한 오답에서 다시 생각하기

상한 16이면 실제 빈 공간도 항상 16이다.

상한은 실제값보다 클 수 있다.

연습 2 · 오류 찾아 고치기

P2의 내림 하한 16이 28보다 작아 어떤 페이지도 못 넣는다고 확정했다.

힌트 1

실제 P2 여유는 31이다.

힌트 2

하한이 작다는 사실은 실제값도 작다는 뜻이 아니다.

풀이와 답 확인

  1. 하한은 28 이상이면 충분조건이 될 수 있지만 28 미만이면 불가능을 확정하지 못한다.

  2. 다른 정보와 실제 검증·추가 탐색 정책을 사용한다.

가능한 P2를 놓친 결론이다. 요약의 오차 방향을 적는다.

흔한 오답에서 다시 생각하기

하한이 필요량보다 작으면 실제 공간도 반드시 부족하다.

실제값은 하한보다 클 수 있다.

연습 3 · 직접 만들어 보기

자유 공간 후보와 삽입 검증의 장부를 설계하라.

힌트 1

요약이 상한·하한·정확값인지 적는다.

힌트 2

가변 자료는 총량과 연속 공간을 나눈다.

풀이와 답 확인

  1. 요약 판본·오차·후보 순서와 실제 페이지 읽기 결과를 기록한다.

  2. 자료·슬롯·패딩·연속 조건과 동시 갱신의 재검증 정책을 명시한다.

  3. 성공한 데이터·디렉터리 변경과 읽기·쓰기, 미수행 장애·보안 삭제 시험을 분리한다.

설계 계획이다. 실제 힙 파일·DB·동시 삽입·학생 실행은 수행하지 않았다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

새 슬롯이 아니라 이미 빈 슬롯을 재사용하여 추가 슬롯 비용 0이라면 P2의 자료 24 삽입 후 여유는?

힌트 1

필요한 연속 자료는 24바이트다.

힌트 2

다른 조건은 P2 실제 여유 31로 같다.

풀이와 답 확인

  1. 31 − 24 = 7이다.

  2. 슬롯 재사용은 옛 ID의 유효 수명을 따로 관리한다.

여유 7바이트다. 새 슬롯 비용을 계속 더해 3이라고 하면 정책을 섞은 것이다.

흔한 오답에서 다시 생각하기

슬롯 재사용은 비용과 참조 안전성을 동시에 자동 해결한다.

저장 비용이 줄어도 같은 번호를 옛 자료로 읽는 수명 문제가 남는다.

설명 기준 확인

현재 페이지의 실제 상태를 확인하고 변경 요약·실패 후보의 추가 비용을 기록하는 것이다.

한 단계 더

페이지1024바이트에서 헤더32, 슬롯 항목8, 레코드40바이트라고 새로 가정하면 n개 레코드에32+48n≤1024가 필요하다. n≤floor(992/48)=20이며 레코드만 나눠24개라고 하면 슬롯 비용을 누락한다. 빈 슬롯 항목을 재사용하는지 추가하는지도 설계에 적어 보자. 실제 디스크와 DBMS를 실행한 결과가 아닌 용량 모형이다.

소단원 5.2

정렬 파일과 범위 조회

책이 번호순으로 놓여 있다면200번부터300번까지를 어떻게 빠짐없이 찾을까?

준비 개념과 학습 목표

준비 개념

  • 정렬 파일은 특정 검색 키 순으로 페이지와 페이지 안의 레코드를 배치한다.

  • I/O 1회는 페이지 1개 읽기 또는 쓰기다. 헤더·별도 인덱스 비용은 아래 계산 모형에서 제외하며, 캐시 보존 여부는 각 문제의 조건을 따른다. 예제에서는 읽은 페이지를 캐시에 보존한다.

학습 목표

  • 하한 위치 탐색 뒤 범위 스캔을 설명한다.

  • 정렬 키와 다른 조건의 조회 및 중복 키 경계를 구별한다.

페이지 안만 정렬되어 있으면 파일 전체도 이진 탐색할 수 있을까?

자체 파일 P1 = [2,9], P2 = [5,5], P3 = [7,8]에서 각 페이지 내부는 정렬되어 있다. 하지만 전체 페이지를 이어 읽으면 2,9,5,5,7,8이라 키가 내려가는 부분이 있다. 페이지 최대 배열은 [9,5,8]로 단조 증가가 아니다. 페이지 내부 정렬과 파일 전체 정렬은 다른 전제다.

최대 키 배열에서 첫 최대 ≥ 6인 페이지를 이진 탐색하는 절차를 잘못 적용하자. 1기반 lo = 1, hi = 3, mid = floor((lo + hi)/2)다. P2의 최대 5가 6보다 작아 lo를 3으로 올리고 P3의 최대 8로 후보 3을 얻는다. 그 뒤 P3만 스캔해 [6,9]를 조회하면 7,8만 반환하며 P1의 9를 놓친다. 이진 탐색의 절차가 아니라 입력의 정렬 전제가 깨진 반례다.

앞 본문의 올바른 중복 키 파일 P1 = [2,5], P2 = [5,5], P3 = [5,9]는 전체 키 순서도 정렬되어 있다. 최대 배열 [5,5,9]에서 첫 최대 ≥ 5를 찾으면 P1이다. P1부터 키 5를 모아 9에서 멈추면 네 개를 얻는다. 아무 일치 페이지 P2부터 시작하면 P1의 한 개를 누락한다. lower bound와 정렬 전제를 모두 확인해야 한다.

먼저 확인할 개념
  • 정렬 파일·lower bound·중복 경계

    파일 전체 순서와 첫 후보를 찾는 조건을 확인한다.

  • 힙 파일과 검색 경로

    정렬되어 있지 않은 파일의 키 조회를 정렬 탐색과 구별한다.

첫 위치를 찾고 오른쪽으로 진행한다

정렬 키의 범위 [a,b]를 구하려면 먼저 키가 a이상인 첫 레코드 위치를 찾고 b를 넘기 전까지 순서대로 읽는다. 페이지의 최대 키 등을 비교하여 후보 구간을 절반씩 줄이는 이진 탐색은 시작을 찾는 비용을 줄인다. 하지만 출력 레코드를 읽는 비용까지 사라지지는 않는다.

같은 키가 여러 페이지에 걸칠 수 있으면 임의의 일치 레코드 하나를 찾은 것으로 범위 시작이 결정되지 않는다. lower bound, 즉 조건을 만족하는 가장 왼쪽 위치를 찾아야 누락하지 않는다. 끝도 b와 같은 값을 포함하는지 조건을 먼저 확정한다.

페이지 비용을 중복 없이 센다

총 B페이지에서 시작 위치 탐색은 보통 O(log B), 이후 범위에 필요한 페이지를 T개 읽는 비용은 O(T)다. O(log B+T)는 점근 표현이며 특정 작은 예제의 정확한 읽기 횟수와 같지 않다. 이미 탐색 중 읽은 페이지를 스캔 때 다시 디스크에서 읽는지는 캐시 조건을 따져야 한다.

정렬 키가 학생 번호여도 취미가 수영인 모든 학생은 연속 구간을 이루지 않을 수 있다. 그 조건만으로는 번호 정렬의 이진 탐색을 사용할 수 없어 전체를 검사하거나 별도 인덱스가 필요하다. 복합 키도 사전식 순서의 어떤 앞부분이 제한되는지 확인해야 한다.

조회 이득에는 갱신 비용이 붙는다

여유 없이 꽉 찬 정렬 파일의 중간에 새 레코드를 넣으면 뒤 레코드를 밀어 페이지들을 다시 써야 한다. 반복 삽입이 많은 작업에서는 범위 읽기가 빠른 장점만으로 선택하기 어렵다. 여유 공간·오버플로·다른 인덱스 구조는 이 교환을 바꾸는 설계다.

정렬은 논리적인 페이지·레코드 순서의 약속이다. 파일시스템과 장치 내부까지 모든 바이트가 물리적으로 인접한다고 주장하는 것은 아니다. 순차 접근의 실제 시간은 캐시와 저장장치 등 환경에서 측정해야 하며 본문은 페이지 I/O 모형을 다룬다.

중간 과정을 따라가는 예제

P1=[2,5],P2=[7,9],P3=[12,15],P4=[18,21]이다. 최대 키 배열[5,9,15,21]에서 첫 최대≥8인 페이지를 lower-bound로 찾은 뒤 [8,18]을 조회한다. mid=floor((lo+hi)/2),1기반 lo1,hi4,끝포함 탐색이다. 읽은 페이지를 캐시에 보존하라.

  1. mid2인 P2 최대9≥8이므로 후보를2에 기록하고 hi1로 줄인다.

  2. mid1의 최대5<8이므로 lo2가 되어 종료한다. 시작 페이지는P2다.

  3. P2에서7은 제외하고9를 출력한다. P3의12,15, P4의18을 출력하고21>18에서 멈춘다.

  4. 탐색 때P2,P1을 읽었고 스캔 중P2는 캐시다. 새 읽기P3,P4를 합쳐 서로 다른 데이터 페이지4개다.

결과9,12,15,18이며 지정한 절차와 캐시에서 읽기4회다. 어떤 전략에서도 항상4라는 뜻은 아니다.

틀린 전제의 탐색 결과

  1. mid 2의 최대 5가 작아 lo 3으로 바뀐다.

  2. mid 3의 최대 8이 크거나 같아 후보 3이 된다.

절차는 P3을 반환하지만 실제 첫 최대 ≥ 6은 P1이다.

비교할 점

비단조 배열에 lower-bound 이진 탐색의 정확성을 주장하지 않는다.

네 중복 레코드의 시작

올바른 P1 [2,5], P2 [5,5], P3 [5,9]에서 모든 5를 얻으려면?

  1. 첫 최대 ≥ 5인 P1부터 시작한다.

  2. 각 페이지에서 조건을 만족하는 5를 모으고 9에서 멈춘다.

P1 한 개 + P2 두 개 + P3 한 개 = 4개다.

중복 키를 갖는 아무 페이지에서 출발하면 앞쪽 결과를 누락할 수 있다.

오해와 반례

정렬 파일이면 모든 속성 검색이 O(log B)이고 결과가 많아도 읽기 비용은 늘지 않는다.

번호로 정렬한 파일의 취미 조건은 순서와 무관하다. 키 범위 조회도 출력이B페이지에 퍼져 있으면 그 페이지들을 읽어야 한다. 탐색 비용과 결과 스캔 비용을 함께 센다.

준비 개념

  • 본영역은 정렬되어 있고 부영역은 새 레코드를 임시 보관하는 비정렬 오버플로 영역이라고 정한다.

  • 아래에서는 키가 유일하고 갱신은 없으며 삭제 표시는 특정 기존 레코드에 붙인다. 현대 DBMS의 모든 갱신 정책을 설명하는 모형은 아니다.

학습 목표

  • 본영역과 부영역을 함께 조회하여 누락을 막는다.

  • 삭제 제거·정렬·병합의 재구성 과정을 계산한다.

재구성 중 들어온 새 자료를 어디에 남겨야 할까?

자체 단일 부영역 모형에서 정렬 본영역 M은 [10,20]이고 재구성 시작 시점의 부영역 O_old는 [15]다. 이 스냅샷으로 새 본영역 [10,15,20]을 만든다. 그 사이 새 삽입 25가 부영역에 들어왔다고 정한다. 시작 스냅샷에 없는 25까지 무조건 부영역 전체 삭제로 지우면 완성 파일은 25를 잃는다.

이 자체 교정 정책에서는 시작 시점의 O_old와 이후 삽입 O_new를 별도 세대로 구별한다. 새 본영역에는 O_old까지만 반영하고, 새 삽입 25는 O_new에 유지한다. 공개 상태는 새 M [10,15,20]과 O_new [25]이며 두 영역을 함께 조회하면 전체 [10,15,20,25]다. 이것은 정상 순차 장부의 보존 설명이다. 실제 원자 전환·동시 독자·삭제·로그·전원 장애 규약을 구현한 것이 아니다.

별도 손익 모형에서 재구성 비용은 100 I/O이고 다음 60조회 중 첫 50조회만 각 2 I/O를 절약하며 뒤 10조회는 추가 삽입 때문에 절약 0이라고 주어진다. 총 절약은 100 I/O로 비용과 같다. 모든 60조회에 평균 2를 계속 적용해 120을 절약한다고 하면 작업 변화 조건을 빠뜨린다. 이런 합계는 지연·중단·실제 측정 오차를 포함하지 않은 이론 비교다.

먼저 확인할 개념
  • 부영역·스냅샷·재구성 비용

    반영한 삽입의 시점과 남길 부영역을 구별한다.

  • 정렬 본영역과 전체 결과

    새 본영역만으로 이후 삽입 결과를 대표하지 않는다.

삽입 일을 미루면 조회가 더 맡는다

매번 본영역 중간에 자리를 만드는 대신 새 레코드를 부영역 끝에 넣을 수 있다. 대신 조회는 본영역만 살펴서는 안 된다. 없는 키를 확인하려면 정렬 본영역 탐색 뒤 비정렬 부영역도 검사해야 하며, 범위 조회에서도 부영역 안의 조건 만족 레코드를 추가로 찾아야 한다.

이 교육 모형의 부영역은 하나의 비정렬 목록이다. 페이지별 오버플로 사슬을 두고 특정 페이지에 연결하는 방식도 있어 모든 파일 조직이 똑같이 전체 부영역을 스캔한다고 일반화하지 않는다. 설계에 따라 검색의 대상과 순서가 달라진다.

살아 있는 레코드를 다시 순서대로 합친다

재구성은 본영역의 살아 있는 레코드와 부영역의 살아 있는 레코드를 모으고 부영역을 정렬한 뒤 순서대로 병합하여 새 본영역을 만든다. 삭제 표시된 레코드는 출력하지 않는다. 성공한 새 배치가 준비된 뒤 부영역을 비우는 순서를 생각해야 자료를 잃지 않는다.

실제 서비스가 동시에 새 자료를 받는다면 어느 시점까지의 삽입과 삭제를 새 파일에 반영하는지 별도 일관성 정책이 필요하다. 읽는 도중 원본을 없애는 단순 절차를 완전한 서비스 재구성 코드라고 제시하지 않는다. 본문 활동은 갱신이 멈춘 스냅샷으로 고정한다.

언제 재구성할지는 작업량으로 판단한다

부영역이 커질수록 조회에 추가 조사 비용이 붙고 전체 병합·쓰기에도 일이 필요하다. 따라서 늘 즉시 또는 매일 같은 간격이 보편적인 정답은 아니다. 조회·삽입 비중과 허용 지연, 빈 공간, 측정 비용에 따라 선택한다.

재구성은 파일 수준의 정렬 질서를 회복하는 일이며 페이지 안에서 구멍을 모으는 압축과 범위가 다르다. 재구성했다고 역사상 삭제된 바이트까지 안전하게 소거됐다는 보장도 없다. 성능 모형의 읽기·쓰기 횟수와 실제 밀리초 시간을 구별한다.

중간 과정을 따라가는 예제

정렬 본영역[10,20,30,40]에서20은 삭제 표시됐다. 비정렬 부영역[25,5,35]가 있다. [15,35]조회 결과와 재구성한 전체 본영역을 구하라. 현재 삽입·삭제는 멈춘 상태다.

  1. 본영역의 범위 후보20,30 중 삭제20을 제외해30만 남긴다.

  2. 부영역 세 레코드를 모두 검사하여25와35를 더한다. 순서 있는 결과가 필요하면25,30,35로 정렬한다.

  3. 살아 있는 본영역은10,30,40이다. 부영역을5,25,35로 정렬한다.

  4. 두 목록의 작은 앞값을 선택해5→10→25→30→35→40으로 병합한다.20은 넣지 않는다.

조회25,30,35, 새 본영역5,10,25,30,35,40이다. 부영역을 무시하면 두 결과를 누락한다.

조건을 바꾸어 비교하기

너무 넓은 부영역 삭제

새 M [10,15,20] 공개 후 O_old와 O_new를 모두 지우면 무엇을 잃나?

  1. 15는 새 M에 들어 있다.

  2. 25는 스냅샷 뒤 삽입이라 새 M에 없다.

25를 잃는다. 반영된 O_old만 회수하고 O_new는 유지해야 한다.

비교할 점

파일 교체 완료와 모든 부영역 자료의 반영은 같은 사건이 아니다.

변화한 조회 비용의 합계

비용 100, 첫 50조회 절약 2씩, 다음 10조회 절약 0이면?

  1. 절약은 50 × 2 + 10 × 0 = 100 I/O다.

  2. 재구성 비용 100을 뺀 순절약은 0이다.

이 단순 합계에서는 동률이다.

비교할 점

고정 절약 2의 60조회 모형과 전제가 다르다.

종이와 본문으로 직접 해보기

페이지당2레코드, 본영역과 부영역의 입력 페이지는 각각2개다. 둘 다 처음 캐시에 없고 임시 정렬은 메모리 안에서 끝난다. 새6레코드의 빽빽한 본영역을 한 번 쓸 때 최소 이 단순 패스의 읽기·쓰기를 세라.

힌트 보기

삭제20도 들어 있는 원본 페이지는 검사하려고 읽어야 한다.

풀이 보기

읽기는본2+부2=4회, 새 본영역은ceil(6/2)=3페이지라 쓰기3회, 합7I/O다. 이는 입력 단일 패스와 출력쓰기만이며 헤더·로그·임시 디스크정렬·동시 갱신 비용을 제외했다. 입력 레코드 하나 삭제됐다고 해당 페이지 읽기를 생략하지 않는다.

오해와 반례

본영역이 정렬되어 있으므로 오버플로를 붙여도 항상 이진 탐색만 하면 최신 결과가 나온다.

키25가 부영역에 있으면 본영역 이진 탐색은 실패해도 전체 파일에서 없다고 결론낼 수 없다. 부영역이 비정렬이면 그 영역의 단순 이진 탐색 전제도 없다. 재구성이나 별도 검색 경로가 필요하다.

연습 1 · 값과 상태 예측

같은 재구성 중 O_new에 25와 5가 들어왔다. 새 M [10,15,20]과 함께 조회한 전체 정렬 결과는?

힌트 1

두 새 삽입은 시작 스냅샷에 없었다.

힌트 2

둘 다 O_new에 유지한다.

풀이와 답 확인

  1. M과 O_new의 레코드를 모두 모은다.

  2. 키 순으로 정렬하면 5,10,15,20,25다.

전체 결과는 5·10·15·20·25다. M만 조회하면 두 삽입을 놓친다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

추가 삽입 없이 다음 60조회가 모두 2 I/O를 절약하는 별도 모형이면 비용 100 대비 순절약은?

힌트 1

절약은 60 × 2다.

힌트 2

재구성 비용을 뺀다.

  2. 120 − 100 = 20 I/O다.

고정 손익 기준을 다시 계산하는 경우는?

설명 기준 확인

조회별 절약·추가 삽입·재구성 비용이나 관측 범위가 달라지는 경우다.

한 단계 더

한번의 재구성에100I/O, 그 후 각 조회에서 절약되는 비용이 평균2I/O라는 가상 조건을 두자. 추가 삽입과 다른 비용이 없으면50조회에서 절약100I/O로 같아지고51조회부터 단순 합계가 이득이다. 평균 추정의 신뢰도와 운영 중단 비용이 빠졌음을 함께 써라. 실제 실험 없이 계산상 손익 기준만 제시한다.

다른 문제에 적용하기

요약 오차·정렬 전제·재구성 세대

자료 24바이트와 새 슬롯 4바이트 삽입에서 실제 여유 P1 16/P2 31, 디렉터리의 오래된 P1 상한 32와 현재 P2 상한 32가 있다. P1 확인 실패 뒤 P2에 넣으면 잔여와 냉간 I/O를 세어라. 디렉터리는 한 페이지이고 캐시가 읽은 세 페이지를 유지하며 성공한 P2와 디렉터리를 한 번씩 쓴다. 별도 P1 [2,9], P2 [5,5], P3 [7,8]에서 최대 배열 lower-bound를 사용한 [6,9] 누락을 설명하라. 재구성 시작 M [10,20], O_old [15]의 새 M 준비 중 O_new에 25가 들어오면 어떤 상태를 남겨야 하나? 비용 100 I/O와 이후 60조회 중 첫 50만 절약 2, 나머지 절약 0의 순절약도 구하라.

힌트 1

요약과 현재 공간, 페이지 내부와 전체 정렬을 분리한다.

힌트 2

반영된 입력 세대와 이후 삽입 및 조회별 실제 절약을 기록한다.

풀이와 답 확인

  1. 필요량은 28바이트다. P1은 부족하고 P2에 넣으면 여유 3이다. 읽기 디렉터리·P1·P2 3회와 P2·디렉터리 쓰기 2회로 총 5 I/O다.

  2. 최대 [9,5,8]은 단조가 아니며 mid 2의 5에서 앞을 버려 P1의 9를 누락한다. 정확한 전체 조회는 7·8·9다.

  3. 새 M [10,15,20]에 반영된 O_old만 회수하고 O_new [25]를 유지한다. 두 영역을 합쳐 10·15·20·25를 조회한다.

  4. 총 절약 50 × 2 + 10 × 0 = 100이며 재구성 비용 100을 빼 순절약 0이다.

자체 공간 요약·전체 정렬·세대 장부의 손검토다. 실제 힙 파일·DB·동시 재구성·장치·원자 전환·장애 및 학생 실행은 미수행이다.

해결한 뒤 점검할 것

  • 요약만으로 실제 삽입을 승인하지 않는다.

  • 페이지 내부 정렬만으로 파일 전체 이진 탐색을 주장하지 않는다.

  • 미반영 새 삽입을 회수 대상에 넣지 않는다.

  • 조회별 절약의 변화 조건을 합계에 반영한다.

    실제 전체 3–19행의 정렬 순서·삽입 뒤 오버플로·재구성 비용을 읽었다. 본문의 포인터 방식과 다른 단일 부영역·입력 세대 모형을 명시했다. Bilkent PDF 접근은 403으로 실패하여 새 열람으로 기록하지 않는다. 과거 노트를 현재 장치 성능으로 제시하지 않는다.

자료 24바이트와 새 슬롯 4바이트의 삽입 필요량은 28바이트다. 실제 연속 여유가 16바이트인 P1에서는 실패하고 31바이트인 P2에서는 성공하여 여유 3바이트가 남는다. P1의 현재 올림·내림 요약은 모두 16바이트이지만 디렉터리에는 이전 상한 32바이트가 남아 있는 조건이다. P2의 올림 상한은 32바이트, 내림 하한은 16바이트다. 빈 슬롯을 재사용하면 슬롯 추가 비용이 없어 P2의 여유는 7바이트다. 정한 냉간 캐시 조건에서 디렉터리·P1·P2 읽기 3회와 P2·디렉터리 쓰기 2회를 합해 총 5 I/O다. 정확한 요약으로 P2만 후보로 선택하면 읽기 2회와 쓰기 2회로 총 4 I/O다. 비단조 페이지 최대 배열 [9,5,8]에 lower-bound 이진 탐색을 잘못 적용하면 mid가 2에서 3으로 바뀌어 후보 P3을 얻고 P1의 키 9를 누락한다. 전체 검사의 결과는 7·8·9다. 올바른 정렬 파일의 키 5는 총 4개이고 반열린 범위 [5,5)는 빈 결과임을 추적했다. 재구성한 새 M [10,15,20]과 유지한 O_new [25]의 전체 정렬 결과는 [10,15,20,25]다. O_new에 키 5도 추가되면 전체 결과는 [5,10,15,20,25]다. 변화한 비용 조건에서는 첫 50조회가 각각 2 I/O를 절약하고 뒤 10조회는 절약이 없어 총 절약 100 I/O이며, 재구성 비용 100 I/O를 뺀 순절약은 0 I/O다. 별도로 60조회가 모두 2 I/O를 절약하면 총 절약 120 I/O, 순절약 20 I/O다. 모든 값은 명시한 모형의 손계산이며 실제 장치 측정값은 아니다.
