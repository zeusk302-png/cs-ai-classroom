논리 파일과 물리 배치

파일의 앞부분과 뒷부분이 화면에서 이어져 보이면 저장장치에서도 꼭 이웃한 곳에 있을까?

준비 개념과 학습 목표

준비 개념

  • 파일은 순서 있는 바이트 데이터에 이름과 메타데이터로 접근하는 추상화다. 바이트 위치는 0부터 세는 오프셋으로 나타낼 수 있다.

  • 논리 블록 번호는 파일 안의 순서, 장치 블록 주소는 저장장치가 접근하는 위치다. 번호가 같다는 보장은 없다.

  • 영속성은 지정한 완료·동기화·장애 조건 아래 이후에도 데이터를 보존하는 성질이다. RAM 버퍼에 새 값이 있다는 사실과 구별한다.

학습 목표

  • 이름·파일 오프셋·논리 블록·장치 위치를 구별한다.

  • 블록 매핑을 통해 논리 연속성과 물리 비연속성을 설명한다.

  • 쓰기 반환과 영속성·원자성 보장의 범위를 구별한다.

데이터를 옮겼는데 파일의 같은 위치에서 옛 값이 보인다면?

자체 파일 F의 블록 크기는 1024바이트다. 매핑 판본 v1에서는 논리 블록 1이 장치 블록 7을 가리킨다. 오프셋 1500의 내부 위치는 476이다. 장치 블록 7의 그 위치에 값 10이 있다고 정한다. 새 판본 v2에서는 논리 블록 1의 내용을 장치 블록 90으로 옮기고 같은 내부 위치의 값을 20으로 바꾼다. 같은 파일 오프셋이라도 어느 판본의 매핑과 데이터를 읽었는지에 따라 결과가 달라진다.

v2를 제공해야 하는데 옛 매핑 1 → 7을 캐시에서 사용하면 값 10을 읽는다. 새 매핑 1 → 90을 사용해도 데이터 캐시가 논리 블록 1의 옛 값을 그대로 내주면 같은 문제가 생긴다. 이 자체 모형의 교정 정책은 제공할 판본을 정하고 그 판본과 맞는 매핑 및 데이터만 재사용하는 것이다. 키에 판본을 넣는 것만으로 최신 판본 선택이나 모든 캐시 무효화가 자동으로 완료되지는 않는다.

별도 비용 사례에서는 데이터가 없고 매핑을 찾는 메타데이터 블록 두 개도 없다고 정한다. 한 데이터 블록을 읽으려면 메타데이터 2회와 데이터 1회로 총 3회다. 다음 요청에서 필요한 매핑과 데이터가 모두 남아 있다면 추가 읽기는 0회다. 이 숫자는 정의한 블록 전송 수다. 장치 명령 수·경과 시간이나 실제 재배치의 장애 안전성을 측정한 결과는 아니다.

1. 파일은 바이트 순서를 제공한다

일반적인 파일 인터페이스에서 사용자는 이름으로 파일을 열고 오프셋에서 바이트를 읽고 쓴다. 파일 길이·권한·수정 시각 등 메타데이터는 바이트 내용과 다른 관리 정보다. 파일 내부의 레코드 구분은 저장 형식이나 응용이 정한다. 운영체제는 모든 파일의 업무 의미를 자동 해석하지 않는다.

연속된 파일 오프셋이 같은 크기의 논리 블록에 속할 수 있고 여러 논리 블록은 서로 떨어진 장치 블록에 연결될 수 있다. 파일시스템의 매핑이 이 차이를 숨긴다. DB 저장관리자는 그 위에 페이지 ID→파일/오프셋 매핑을 더할 수도 있다. 이름·논리 위치·장치 위치는 서로 다른 주소 수준이다.

2. 매핑은 데이터를 옮길 여지를 준다

가상 파일의 논리 블록 0,1,2를 장치 블록 40,7,81에 각각 배치해도 읽는 바이트 순서는 논리 0→1→2다. 장치 40→7→81의 번호 순으로 데이터가 보이는 것이 아니다. 재배치 후 올바른 매핑을 갱신하면 파일의 같은 오프셋은 같은 내용 의미를 제공할 수 있다.

매핑을 읽는 비용·디렉터리 탐색·간접 블록·DB 인덱스 비용은 데이터 블록 비용과 구별해서 센다. 장치 블록이 연속이어도 SSD 내부 물리 배치가 주소 숫자와 같은 구조라고 단정할 수 없다. 이 단원은 블록 수준의 추상 모형이며 실제 플래시 변환 계층까지 묘사하지 않는다.

3. 저장 완료와 장애의 약속

파일 쓰기가 성공 반환했다고 모든 바이트가 즉시 영속 매체에 도달한 것은 아닐 수 있다. OS·DB·장치의 버퍼와 쓰기 정책을 확인해야 한다. Linux fsync 같은 동기화 API도 호출 결과를 확인하고 파일 내용 외 새 이름을 담은 디렉터리의 영속성 요구를 따로 고려한다. 구현과 저장장치가 약속을 지킨다는 전제 역시 필요하다.

영속성이 있다는 말과 여러 변경이 하나의 원자적 거래라는 말은 다르다. 두 파일 중 하나만 바꾸고 장애가 나면 각각 저장된 데이터가 있어도 전체 업무는 불일치할 수 있다. 복구·거래 원리는 DB/OS 단원으로 연결하고, 여기서는 어떤 논리 데이터가 어느 블록에 있고 어떤 I/O가 필요한지를 계산한다.

중간 과정을 따라가는 예제

블록 크기 1024B인 가상 파일의 논리 블록 0,1,2는 장치 블록 40,7,81에 연결된다. 오프셋 1500의 한 바이트를 읽는다. 매핑은 이미 메모리에 있고 데이터 캐시는 비어 있으며 미리 읽기·다른 I/O는 없다.

  1. 1500=1×1024+476이므로 논리 블록 1의 내부 오프셋 476이다.

  2. 매핑[1]=7이므로 장치 블록 7을 읽어 버퍼에 둔다.

  3. 버퍼 안의 위치 476에서 요청 바이트를 얻는다.

  4. 매핑 메타데이터의 별도 I/O는 문제의 메모리 상주 가정으로 0이다. 데이터 블록 읽기는 1회다.

논리 블록 1→장치 블록 7, 내부 위치 476. 1회는 이 가정의 데이터 전송 수이며 파일 열기부터의 전체 시스템 호출·실제 장치 명령 수가 아니다.

블록·페이지·레코드

학생 한 명의 100바이트 정보만 필요해도 왜 더 큰 덩어리를 읽을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 레코드는 관련 필드 값을 묶은 저장 단위다. 이름·학번 등 값의 의미와 그것을 바이트로 표현하는 형식은 구별한다.

  • 페이지는 저장관리자가 묶어 관리하는 단위이고 블록은 이번 비용 모형에서 한 번 전송하는 단위다. 실제 DB 페이지·OS 메모리 페이지·장치 전송 단위의 크기는 같을 필요가 없다.

  • ⌊x⌋는 x 이하 최대 정수, ⌈x⌉는 x 이상 최소 정수다. 한 페이지에 통째로 들어갈 레코드 수는 버림, 필요한 페이지 수는 올림으로 구한다.

학습 목표

  • 헤더를 뺀 페이지 수용량과 필요한 페이지 수를 계산한다.

  • 고정 길이 레코드의 페이지/내부 위치를 찾는다.

  • 슬롯·가변 길이·페이지 넘침이 단순 위치식을 바꾸는 이유를 설명한다.

총 빈 공간이 충분한데도 긴 레코드를 못 넣는 이유는?

자체 1024바이트 페이지의 헤더는 24바이트이고 기존 슬롯 세 개는 각각 4바이트다. 레코드 A는 [36,156), B는 [156,356), C는 [356,536)에 둔다. 구간 [시작,끝)은 시작을 포함하고 끝을 제외한다. A·B·C의 길이는 각각 120·200·180바이트다. 나머지 [536,1024)는 488바이트의 연속 빈 공간이다. 실제 DB의 표준 배치가 아닌 종이 위의 지정 형식이다.

B를 삭제하되 그 슬롯은 남겨 새 D가 재사용할 수 있다고 정한다. 이제 200바이트 구멍과 488바이트 꼬리로 총 688바이트가 비어 있다. D는 600바이트이고 한 연속 구간에 들어가야 한다. 새 슬롯 비용은 없지만 어느 구간도 600바이트가 아니므로 그대로는 넣지 못한다. 총 여유량과 가장 큰 연속 구간은 다르다.

C를 앞으로 이동하여 [156,336)에 놓으면 꼬리 [336,1024)의 길이는 688바이트다. D를 [336,936)에 넣으면 88바이트가 남는다. C의 슬롯은 시작 156으로 갱신해야 한다. 슬롯 번호로 찾는 현재 독자는 새 위치를 얻을 수 있지만 예전 바이트 오프셋 356을 직접 보관한 독자는 더 이상 C의 시작을 가리키지 않는다. B의 옛 슬롯 ID가 D로 재사용되는 문제도 따로 남는다. 슬롯 간접 접근은 영구 업무 키의 수명 정책을 자동으로 제공하지 않는다.

  • 논리 식별자와 위치 매핑

    같은 식별자가 어떤 현재 위치와 내용에 연결되는지 확인한다.

1. 바이트를 관리 단위로 묶는다

저장관리자는 페이지에 헤더·레코드·빈 공간 등을 둔다. 페이지 헤더는 종류·개수·공간 정보와 같은 메타데이터를 담을 수 있다. 모든 페이지가 사용자 데이터로 꽉 차 있다고 계산하면 실제 레코드 수용량을 과대평가한다.

이번 첫 모형은 페이지 크기 P, 고정 헤더 H, 레코드 길이 r, 페이지를 넘지 않는 레코드를 가정한다. 슬롯 배열·패딩·압축·삭제 빈칸은 없다. 한 페이지 수용량 b=⌊(P−H)/r⌋이고 b≥1일 때 N레코드에 필요한 페이지는⌈N/b⌉다. N=0이면 데이터 페이지 0으로 취급하는 모형이며 실제 시스템의 기본 할당은 별도다.

2. 고정 길이일 때 위치 계산

페이지마다 레코드를 앞에서부터 빈칸 없이 b개씩 채우고 레코드 순서를 유지한다고 가정하면 0부터 센 j의 페이지 번호는⌊j/b⌋, 페이지 안 레코드 번호는 j mod b다. 헤더 다음에 같은 r바이트씩 놓으므로 내부 시작 오프셋은 H+(j mod b)r다. 마지막 페이지는 덜 찰 수 있다.

이 식은 레코드가 삭제·이동되거나 크기가 달라지면 그대로 쓸 수 없다. 논리 키를 직접 바이트 위치로 취급하면 재배치 후 엉뚱한 값을 읽을 수 있다. 인덱스나 레코드 ID와 매핑을 유지하고 그 수명·변경 계약을 정의해야 한다.

3. 슬롯과 가변 길이의 간접 접근

가변 길이 페이지에서는 슬롯 번호→오프셋/길이의 표를 두어 페이지 안에서 레코드가 이동해도 슬롯으로 찾을 수 있게 할 수 있다. 슬롯도 공간을 사용하므로 고정 헤더만 빼는 계산을 다시 해야 한다. 슬롯 재사용 후 예전 ID가 새 레코드를 가리키는 문제는 ID의 유효 수명 정책으로 다룬다. 예를 들어 (페이지7, 슬롯3)이 레코드A를 가리켰다가 A 삭제 후 같은 슬롯에 B가 들어가면 예전 ID로 B를 읽을 수 있다. 위치 기반 ID를 영구 업무 키로 쓰려면 이 재사용을 구별할 세대 번호나 별도 논리 키·매핑 계약이 필요하다.

레코드가 한 페이지보다 큰 경우에는 다른 페이지로 넘기거나 별도 객체를 참조하는 설계가 가능하다. 그래서 “레코드 하나=I/O 하나”는 일반 법칙이 아니다. 여러 레코드가 같은 페이지에 들어가면 한 전송으로 모두 접근할 수도 있고 큰 레코드 하나가 여러 전송을 요구할 수도 있다.

중간 과정을 따라가는 예제

가상 페이지 P=1024 B, 헤더 H=24 B, 고정 레코드 r=100 B, 슬롯/패딩/압축/빈칸 없음, 레코드 페이지 넘침 없음이다. N=100개를 꽉 채우고 0부터 센 레코드 73의 위치를 구한다. 논리 페이지는 파일 앞에서 1024 B 간격이다.

  1. 사용 가능 공간 1024−24=1000 B, b=⌊1000/100⌋=10개다.

  2. 100개에는⌈100/10⌉=10페이지가 필요하다.

  3. 73=7×10+3이므로 논리 페이지 7, 그 안에서 네 번째 레코드다.

  4. 내부 시작은 24+3×100=324 B, 파일 시작 오프셋은 7×1024+324=7492B다.

10페이지, 레코드 73은 페이지 7의 오프셋 324, 파일 오프셋 7492. 페이지가 물리적으로 같은 순서에 있는지는 별도 매핑 문제다.

메모리 비용과 외부기억 비용

레코드 100개를 100번 비교하면 저장장치도 100번 읽어야 할까?

준비 개념과 학습 목표

준비 개념

  • I/O 비용은 이 모형에서 느린 저장 영역과 빠른 메모리 사이 블록 전송 횟수다. 시스템 호출 횟수나 CPU 비교 횟수와 다르다.

  • 버퍼는 이미 읽은 블록을 메모리에 유지하는 공간이다. 캐시 적중은 필요한 블록이 이미 있고, 실패는 가져와야 하는 경우다.

  • 더티 블록은 메모리에서 변경되어 저장 영역에 아직 반영되지 않은 블록이다. 읽기 전송과 쓰기 전송은 별도로 센다.

학습 목표

  • N, B, M과 시작 캐시 조건을 선언해 I/O를 계산한다.

  • 순차 탐색·알려진 위치 접근·반복 접근의 비용을 비교한다.

  • 추상 I/O 수와 실제 디스크/SSD 시간·장애보장을 구별한다.

두 칸 버퍼에 세 블록을 반복하면 첫 세 번만 읽을까?

자체 접근열은 A, B, C, A, B, C다. 시작 버퍼는 비어 있고 읽기 전용이며 미리 읽기와 핀은 없다. 두 칸 버퍼는 가장 오래 사용하지 않은 블록을 교체하는 LRU 정책을 따른다. 각 상태는 가장 최근 사용한 블록부터 적는다. A와 B를 읽으면 [B,A]다. C가 들어오면 A를 내보내 [C,B]가 된다.

다음 A는 이미 없어 B를 내보낸다. 이어 B와 C도 차례로 없다. 여섯 접근 모두 실패하여 읽기는 6회다. 세 칸이면 A·B·C가 모두 남아 처음 세 번만 읽고 나머지는 적중한다. 같은 접근열도 보존 용량이 작업 집합 크기를 넘는지에 따라 비용이 달라진다. 이 비교는 지정한 LRU 모형이며 실제 OS와 장치 캐시를 측정한 결과가 아니다.

별도 한 칸 버퍼에서 읽기 A → 수정 A → 읽기 B → 수정 B를 수행한다. 더티 교체는 즉시 한 블록을 쓴다는 정책이다. A와 B 읽기로 읽기 2회, A 교체로 쓰기 1회다. 종료 때 B가 더티로 남으면 지금까지 3전송이지만 모든 변경을 저장 영역에 반영하는 추가 종료 규칙까지 적용하면 B 쓰기 1회가 더해져 4전송이다. 전송 장부의 쓰기 완료와 실제 장애 영속성·거래 원자성은 별도 계약이다.

  • 페이지와 전송 단위

1. 서로 다른 자원을 서로 다르게 센다

외부기억 모형은 N개 항목이 저장 영역에 있고 한 블록에 B개, 빠른 메모리에 M개가 들어간다고 정한다. 관심 비용은 블록 전송 수이며 메모리 안 연산은 I/O 계산에서 무료로 처리할 수 있다. 실제 CPU 시간이 0이라는 뜻이 아니라 별도 비용 지표로 분리한 것이다.

필요한 데이터 블록이 처음에 하나도 버퍼에 없고 블록 정렬된 연속 배열 전체를 읽으면 적어도 각 블록을 한 번 가져와⌈N/B⌉ 전송이 필요하다. 같은 데이터를 여러 번 읽더라도 버퍼에 남아 있으면 추가 전송이 없다. 예측 읽기·OS 캐시·장치 캐시를 어떤 층까지 포함할지 정해야 계산 의미가 명확해진다.

2. 순차 탐색과 위치를 아는 접근

블록당 10레코드인 100레코드 파일에서 정렬·인덱스가 없고 마지막 레코드를 찾거나 없는 값을 확인하려면 최악에 10블록을 모두 읽는다. 각 블록을 가져온 뒤 10개 비교를 메모리에서 수행하므로 비교 100회와 데이터 읽기 10회가 함께 가능하다.

정확한 위치가 이미 알려져 있고 해당 데이터 블록만 캐시에 없다면 데이터 읽기는 1회다. 하지만 키에서 위치를 찾기 위한 인덱스 비용이 따로 필요할 수 있다. 임의 파일의 직접 접근이 무조건 전체 탐색보다 싸다고 하기 전에 그 위치 정보를 얻는 비용도 포함한다.

3. 버퍼 용량과 쓰기 정책이 결과를 바꾼다

블록 A, B, A, B 접근을 빈 버퍼 1칸에서 수행하면 매번 다른 블록으로 바뀌어 읽기 4회다. 버퍼 2칸이면 처음 두 읽기 뒤 둘 다 남아 읽기 2회다. 같은 논리 접근 횟수라도 캐시 정책·용량·초기 상태가 전송 수를 바꾼다. 핀으로 사용 중인 페이지가 있다면 교체 가능한 용량도 확인해야 한다.

더티 블록을 교체할 때 쓰는 정책이라면 읽기만 세어서는 부족하다. 읽기 A→수정 A→읽기 B에서 버퍼 1칸은 A를 쓰고 B를 읽을 수 있어 읽기 2+쓰기 1이다. 실제 시스템은 쓰기를 묶거나 지연할 수 있고 한 페이지 쓰기가 어떤 장애 원자성을 갖는지는 I/O 개수로 알 수 없다. 장치 종류·요청 크기·병렬성·순차성에 따른 실제 시간은 별도 측정이다.

실제 버퍼가 세 칸이지만 한 칸은 다른 페이지 X에 핀되어 교체 불가능하다. A·B·C 접근에 쓸 두 칸은 처음 비었다. 같은 LRU 정책이면?

힌트 1

X는 A·B·C와 다른 페이지이며 이번에 접근하지 않는다.

힌트 2

교체 가능한 공간만 두 칸이다.

풀이와 답 확인

  1. A·B·C의 상태는 표의 두 칸 LRU와 같다.

  2. 각 요청이 실패하므로 읽기 6회다.

총 칸 수 3이더라도 이 접근에 쓸 수 있는 두 칸에서는 6회다. X의 기존 읽기는 이번 비용에 넣지 않는다.

핀·예약 및 사용 중 페이지가 실제 교체 가능 용량을 줄일 수 있다.

판본·공간 구멍·버퍼 종료 조건을 함께 적기

블록 1024바이트의 파일 F에서 오프셋 1500은 v1의 논리 1 → 장치 7 값 10, v2의 논리 1 → 장치 90 값 20에 대응한다. v2를 제공할 때 옛 매핑 또는 옛 데이터 캐시를 쓰는 오류를 설명하라. 별도 1024바이트 페이지의 헤더와 슬롯 공간은 [0,36)이고 A는 [36,156), B는 [156,356), C는 [356,536)다. B 삭제 뒤 그 슬롯을 유지·재사용하며 D 600바이트는 연속 저장해야 한다. 압축 전후의 삽입 가능성과 남는 공간을 계산하라. 빈 두 칸 LRU의 A,B,C,A,B,C 읽기와 빈 세 칸의 읽기를 비교하라. 별도 빈 한 칸 버퍼에서 읽기 A, 수정 A, 읽기 B, 수정 B 후 더티 교체와 종료 더티 쓰기를 각각 즉시 한 블록 전송으로 세는 경우의 읽기·쓰기 총계를 구하라.

힌트 1

판본 선택과 매핑·데이터 상태 일치를 분리한다. 공간의 총합과 연속 구간을 따로 센다.

힌트 2

LRU의 최근 사용 순서를 매번 갱신하고 종료 때 남은 더티 페이지를 확인한다.

풀이와 답 확인

  1. 1500의 논리 블록은 1이고 내부 위치는 476이다. 옛 매핑이나 옛 데이터 캐시는 v2의 값 20 대신 값 10을 줄 수 있다.

  2. B 삭제 후 빈 공간은 200 + 488 = 688바이트지만 최대 연속 구간은 488이라 D를 바로 넣지 못한다. C를 [156,336)으로 옮기고 슬롯을 갱신하면 D를 [336,936)에 넣고 88바이트가 남는다.

  3. 두 칸 LRU는 모든 요청이 실패하여 읽기 6회다. 세 칸은 첫 세 번만 실패하여 읽기 3회다.

  4. 한 칸 수정 사례는 읽기 2회, 교체 A 쓰기 1회와 종료 B 쓰기 1회로 총 4전송이다. 종료 쓰기 전까지만 세면 3전송이다.
