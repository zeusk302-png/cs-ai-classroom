소단원 7.1

희소·밀집 색인

책의 모든 단어를 적을까, 각 페이지의 첫 단어만 적을까?

준비 개념과 학습 목표

준비 개념

  • 파일은 여러 레코드를 담은 페이지의 순서다.

  • 검색 키와 레코드 식별자/페이지 주소는 서로 다르다.

학습 목표

  • 희소 색인의 정렬 전제를 설명한다.

  • 색인에서 후보 페이지를 찾아 실제 존재를 확인한다.

첫 키가 같은 페이지 중 하나만 읽으면 모든 중복을 찾을까?

자체 정렬 파일은 P1 = [2,5], P2 = [5,5], P3 = [5,9]다. 첫 키 대표는 (2,P1), (5,P2), (5,P3)다. x 이하인 대표 중 가장 오른쪽 하나를 고르는 규칙은 x = 5에서 P3를 선택한다. P3에는 5가 하나 있지만 전체 파일에는 네 개 있다. 기본 본문의 유일 키 조건을 중복 파일로 바꾼 순간 모든 결과를 얻는 규칙도 바뀌어야 한다.

이 작은 파일의 추가 정책은 선택한 후보 P3에서 앞 페이지의 마지막 키가 x 이상인 동안 뒤로 돌아가 시작점을 찾고, 거기부터 앞으로 모든 x를 모으는 것이다. P2의 마지막 5와 P1의 마지막 5를 확인하면 P1부터 읽어야 한다. 앞 페이지를 검사하는 비용도 공짜가 아니다. 이미 읽은 페이지는 캐시에 남아 재사용한다고 정하면 세 데이터 페이지의 냉간 읽기는 총 3회다. 색인 페이지 읽기는 이 작은 데이터 비용 밖이다.

색인의 경계와 데이터는 같은 상태를 나타내야 한다. 별도 유일 키 파일 P1 = [2,5], P2 = [8,11]의 P1 맨 앞에 1을 넣고 첫 대표를 2로 남겼다면 x = 1이 첫 대표보다 작아 없다고 잘못 판단한다. 새 파일 [1,2,5]와 새 대표 1을 같은 세대로 읽는다는 조건이 필요하다. 실제 동시 갱신이나 원자 전환을 구현한 사례는 아니다.

먼저 확인할 개념
  • 유일 키의 희소 대표 규칙

    기존 후보 선택을 중복 조건과 비교한다.

  • 페이지 방문과 캐시

    앞 페이지 확인과 재사용 비용을 실제 경로로 센다.

검색을 안내하는 별도 표

색인은 검색 키에서 레코드 또는 데이터 페이지로 가는 작은 표다. 밀집 색인은 모든 검색 키 값을 나타내며 같은 값의 여러 레코드가 있으면 포인터 목록 등으로 함께 대응할 수 있다. 키 하나당과 레코드 하나당이라는 설계가 항상 같은 것은 아니다.

희소 색인은 일부 대표 키만 기록한다. 이 단원은 검색 키로 정렬된 데이터 페이지마다 첫 키와 페이지 포인터 하나를 저장하는 모형이다. 대표 키 사이 구간이 한 페이지에 대응하므로 색인에 검색 값 자체가 없어도 후보를 찾을 수 있다.

가장 큰 작은 대표 키

찾을 값 x보다 작거나 같은 대표 중 최대를 선택한다. 그 페이지를 실제로 읽어 x를 찾는다. 첫 대표보다 작은 값은 이 정렬 파일에 없으며, 마지막 대표보다 큰 값은 마지막 후보 페이지를 확인해야 한다.

정렬 순서가 보장되지 않으면 대표 사이 구간을 추론할 수 없다. 중복 키가 여러 페이지에 걸치면 첫 키만 따라 한 페이지로 끝내서는 모든 결과를 못 찾을 수 있다. 아래 표는 키가 유일하고 오버플로가 없는 고정 파일이다.

공간을 아끼는 대가

페이지마다4개의 레코드가 있고 전체12개라면 희소 항목3개, 고유 키마다의 밀집 항목12개다. 희소 표는 작지만 대표가 아닌 키의 존재 여부를 데이터에서 확인하는 단계가 필요하다.

삽입으로 페이지 첫 키가 바뀌면 대표 키를 갱신해야 한다. 삭제로 페이지가 비거나 경계가 이동하면 포인터와 범위도 조정한다. 색인 크기만으로 전체 비용을 판단하지 않고 실제 데이터 읽기와 유지 비용을 함께 생각한다.

중간 과정을 따라가는 예제

정렬 파일 P1=[2,5,8,11],P2=[14,17,20,23],P3=[26,29,32,35]이다. 희소 항목(2,P1),(14,P2),(26,P3)에서20과25를 찾는다.

  1. 20보다 작거나 같은 대표2/14 중 최대14를 골라P2를 읽는다. P2의 세 번째20을 찾는다.

  2. 25도 최대 대표 14로P2를 읽지만 [14,17,20,23]에25가 없으므로 없는 값이다.

  3. 색인에20 항목이 없다는 사실은20의 부재를 의미하지 않는다. 반면 밀집 고유 키 표에는20 항목이 있어야 한다.

20은P2에 있고25는 없다. 희소 표3항목/밀집 고유 키 표12항목이다.

조건을 바꾸어 비교하기

오른쪽 대표에서 빠진 결과

x = 5의 가장 오른쪽 대표 P3만 읽으면 몇 개를 찾고 몇 개를 놓치나?

  1. P3의 5는 한 개다.

  2. P1의 한 개와 P2의 두 개를 더하면 전체 네 개다.

한 개만 찾고 세 개를 놓친다.

비교할 점

대표 키가 존재한다는 사실과 그 키의 모든 레코드를 찾는다는 주장은 다르다.

새 첫 키와 옛 대표의 불일치

P1 [2,5]에 1을 앞에 넣었지만 대표는 2다. x = 1을 첫 대표와 비교해 부재 처리하면?

  1. 새 데이터에는 1이 존재한다.

  2. 옛 대표 2보다 1이 작다는 사실은 새 데이터의 부재 근거가 아니다.

존재하는 1을 놓친다. 같은 상태의 대표를 1로 갱신해 읽어야 한다.

비교할 점

갱신 성공과 조회 중 일관된 데이터/색인 세대의 확보를 별도 조건으로 본다.

종이와 본문으로 직접 해보기

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

중복 파일에서 x = 6을 가장 오른쪽 대표 규칙으로 찾으면 후보와 결과는?

힌트 1

6 이하 최대 대표는 5다.

힌트 2

동점 대표 중 오른쪽 P3를 선택하고 실제 키를 확인한다.

풀이와 답 확인

  1. P3 [5,9]를 읽는다.

  2. 6은 없고 정렬 조건상 앞 페이지의 마지막 키 5도 6보다 작다.

후보 P3, 부재다. 후보 페이지 선택만으로 존재가 확정되지는 않는다.

흔한 오답에서 다시 생각하기

대표5를 골랐으니 6도 반드시 있다.

대표는 구간을 안내하며 실제 값을 검사한다.

연습 2 · 오류 찾아 고치기

x = 5에서 첫 대표5인 P2만 읽고 모든 결과라고 했다.

힌트 1

P1의 마지막 값과 P3의 첫 값을 확인한다.

힌트 2

한 페이지 바깥의 중복도 포함해야 한다.

풀이와 답 확인

  1. P1에 5 한 개, P3에도 5 한 개가 있다.

  2. P1부터 P3까지 네 개를 모아야 한다.

P2만 읽으면 두 개를 놓친다. 시작점과 종료점을 모두 중복 경계에 맞춘다.

흔한 오답에서 다시 생각하기

첫 대표5인 페이지가 반드시 첫 레코드5를 가진 페이지다.

앞 페이지의 끝에도 5가 남아 있을 수 있다.

연습 3 · 직접 만들어 보기

P3에서 뒤로 시작점을 찾고 앞으로 모두5를 모으는 페이지 방문 장부를 쓰라. 읽은 페이지는 모두 캐시에 남는다.

힌트 1

P2와 P1의 마지막 키를 검사한다.

힌트 2

뒤로 확인한 페이지를 앞으로 읽을 때 또 디스크 읽기로 세지 않는다.

풀이와 답 확인

  1. P3, P2, P1을 차례로 읽고 시작점을 P1로 정한다.

  2. 캐시에서 P1, P2, P3를 앞으로 검사해 1 + 2 + 1개를 모은다.

데이터 냉간 읽기는 총 3회, 결과는 네 레코드다. 색인 비용과 CPU 검사는 별도로 센다.

흔한 오답에서 다시 생각하기

뒤로3회와 앞으로3회니 언제나 디스크읽기6회다.

이 문제는 읽은 페이지를 모두 유지하는 캐시 조건이다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 P1 첫 키1을 삭제해 첫 키2가 됐지만 대표1을 유지했다. x=1 조회는 앞 예의 삽입 오류와 같은가?

힌트 1

대표1이 후보 P1을 안내한다.

힌트 2

실제 P1에는1이 없는지 확인한다.

풀이와 답 확인

  1. x1이 대표1보다 작지 않아 P1을 읽는다.

  2. 실제 [2,5]에서1의 부재를 확인한다.

이 단건은 추가 확인으로 올바른 부재가 나온다. 그러나 대표가 현재 첫 키라는 규약은 깨져 유지해야 한다. 낡은 경계의 방향과 조회 조건을 구별한다.

흔한 오답에서 다시 생각하기

모든 낡은 대표는 어떤 조회든 같은 방식으로 틀린다.

삽입으로 경계가 작아진 경우와 삭제로 커진 경우의 후보 판정을 각각 추적한다.

내 말로 설명하기

같은 대표 키에서 한 페이지만 읽어도 되나?

설명 기준 확인

모든 중복을 요구한다면 안 된다. 시작과 끝의 페이지 경계를 다뤄야 한다.

첫 대표보다 작은 키의 부재 판정에 필요한 조건은?

설명 기준 확인

대표와 데이터가 같은 정렬 파일 상태를 정확히 나타낸다는 조건이다.

한 단계 더

P1끝에14,P2처음에도14가 있는 중복 파일을 만든다. 대표 14에서 P2만 읽으면 P1의14를 놓친다. 중복 경계를 다루는 탐색/앞 페이지 확인/포인터 목록 중 어떤 추가 설계가 필요한지 제안하되 이를 위 유일 키 모형과 구분한다.

준비 개념과 학습 목표

준비 개념

  • 기본키는 레코드를 유일하게 식별하는 논리 조건이다.

  • 물리 순서는 저장된 데이터 페이지 배열 순서다.

학습 목표

  • 색인 이름과 물리 정렬 가정을 구별한다.

  • 복합 키의 사전식 구간을 추적한다.

복합 키의 한 구간이 두 열 조건의 직사각형과 같을까?

앞 본문의 (학과, 점수, 학번) 표를 그대로 사용한다. 순서는 (CS,70,1), (CS,80,5), (CS,90,3), (EE,60,4), (EE,80,6), (EE,90,2)다. 조건은 학과가 CS 또는 EE이고 점수 80 이상 90 이하라고 정한다. 결과 학번은 5,3,6,2이며 학과별 두 구간이다.

(CS,80)부터 (EE,90)까지 사전식 큰 구간 하나를 잡으면 중간의 (EE,60,4)도 포함된다. 학과가 CS보다 뒤라 첫 학과의 점수 경계와 무관하게 앞 경계를 통과하기 때문이다. 점수 조건을 다시 검사해 학번4를 제외해야 한다. 단순 한 구간이 두 열의 조건을 모두 표현했다고 주장하지 않는다. 실제 PostgreSQL의 탐색·후속 열 검사·skip scan 선택은 공식 문서와 구현 비용으로 구별한다.

결과 학번 5,3,6,2의 데이터 페이지는 각각 P2,P1,P2,P1이다. 별도 냉간 데이터 캐시가 한 페이지이고 매 요청 직후 이전 페이지를 퇴출한다면 네 번 읽는다. ID와 원래 결과 순번을 먼저 모을 충분한 별도 메모리가 있고 실행 중 데이터가 고정되어 있으면 페이지별로 P1,P1,P2,P2를 읽어 두 번으로 줄일 수 있다. 요구된 출력 순서를 맞추려면 원래 순번으로 결과를 다시 배열한다. 데이터 페이지 중복 제거와 결과 레코드 삭제는 다르다.

    앞 열의 범위와 뒤 열의 필터 역할을 구별한다.

  • 경로와 실제 페이지 비용

    항목 개수와 서로 다른 데이터 페이지의 수를 나눈다.

논리 제약과 물리 배치

이 단원에서 기본 색인은 기본키 순으로 정렬된 파일의 색인, 보조 색인은 다른 검색 키를 위한 추가 표라는 고전적인 용어를 사용한다. 실제 DBMS가 같은 단어로 다른 저장 구조를 뜻할 수도 있어 용어의 정의를 먼저 확인한다.

기본키 선언이 모든 제품에서 데이터 파일을 그 순서로 정렬한다는 뜻은 아니다. 기본키의 유일성 조건과 클러스터 배치는 별도다. 한 물리 파일을 두 독립 열의 서로 다른 순서로 동시에 배열할 수 없으므로 보조 색인은 포인터로 찾아간다.

보조 검색의 결과 모으기

학번 정렬 파일에서 학과 색인을 만들면 같은 학과의 학생들이 여러 페이지에 흩어질 수 있다. 그 키를 가진 모든 레코드를 찾으려면 밀집 대응이나 모든 해당 레코드 포인터 목록이 필요하다.

키가 비유일이면 포인터 하나만 저장해 한 레코드로 끝내서는 안 된다. 같은 색인 결과4개라도 물리적으로1페이지에 모였는지4페이지에 흩어졌는지에 따라 데이터 페이지 읽기가 달라진다. 중복 페이지는 버퍼에 있으면 재사용한다.

두 열을 하나의 순서로

복합 B-tree 키 (학과,점수)는 먼저 학과를 비교하고 학과가 같을 때 점수를 비교하는 사전식 순서다. 학과=CS와 점수≥80은 그 학과 안의 연속 구간이 된다.

점수≥80만 있으면 여러 학과에 떨어진 구간이다. 단순 한 구간 스캔으로 앞 열 조건이 있는 경우와 같지 않다. 최신 제품은 skip scan 같은 여러 재탐색을 선택할 수도 있으므로 앞 열 조건 없으면 색인을 절대 못 쓴다는 주장은 하지 않는다.

소단원 7.3

다단계 탐색과 페이지 비용

색인의 색인까지 만들면 디스크를 몇 번 읽을까?

준비 개념과 학습 목표

준비 개념

  • 한 I/O는 버퍼에 없는 페이지 하나를 읽는 비용 단위다.

  • 올림 ceil은 필요한 페이지 수를 남는 항목까지 포함해 센다.

학습 목표

  • 다단계 대표 표의 높이를 계산한다.

  • 캐시와 오버플로 가정을 명시하여 비용을 센다.

세 번의 조회가 공유하는 색인 페이지는 매번 읽을까?

자체 64 데이터 페이지의 3단계 색인에서 조회 경로 세 개를 지정한다. 첫 경로는 R→M1→L1→D1, 둘째 R→M1→L2→D2, 셋째 R→M2→L3→D3다. 루트 R만 처음부터 캐시에 있고 나머지는 없다. 한 번 읽은 모든 페이지를 유지하며 prefetch·퇴출·동시 갱신은 없다고 정한다.

첫 조회는 캐시에 없는 M1, L1, D1을 새로 읽으므로 디스크 페이지 읽기 3회가 필요하다. 둘째 조회는 R과 M1을 재사용하고 L2와 D2만 새로 읽으므로 2회가 필요하다. 셋째 조회는 M2, L3, D3을 새로 읽으므로 3회가 필요하다. 총 읽기는 3+2+3=8회이며, 루트만 캐시된 단건 비용 3회를 세 번 곱한 9회와 다르다. 루트도 처음에 없다면 첫 경로에서 R을 한 번 추가로 읽어 총 9회가 된다. 높이와 조회 횟수에 더해 실제로 공유하는 페이지와 캐시 상태를 장부로 확인한다.

별도 부재 확인에서는 후보 데이터 뒤 오버플로 O1→O2→종료를 따라야 한다고 정한다. 모두 비캐시이고 루트만 캐시인 단건은 기본3 + 추가2 = 5읽기다. 만약 O2가 종료 대신 O1을 가리키면 같은 페이지를 다시 방문해 순환을 발견한다. 순환을 끊는 검사는 구조 오류를 알리는 것이며 정상 종료로 모든 후보를 검사했다는 부재 증명이 아니다. 실제 저장장치나 손상 파일을 실행한 사례는 아니다.

색인이 너무 커지면

정렬 데이터 페이지의 첫 키를 모은 희소 표도 여러 페이지가 될 수 있다. 그 표의 각 페이지 첫 키를 상위 색인으로 만들면 같은 후보 선택을 여러 단계 반복할 수 있다.

이 단원은 고정 파일의 단순 다단계 희소 색인이다. 각 색인 페이지가 포인터를 가진 항목을 4 개 담으며 데이터 페이지는 따로 둔다. B-tree의 분기 포인터 f개/분리 키 f−1개 같은 다른 노드 규칙과 섞지 않는다.

높이보다 구체적인 경로

64개 데이터 페이지면 최하위 색인은64 항목/16페이지다. 그 위는16항목/4페이지, 루트는4 항목/1페이지다. 색인 3 단계와 데이터1페이지를 방문한다.

모두 비캐시이고 결과가 한 데이터 페이지에 있는 유일 키라면4읽기다. 루트가 이미 버퍼에 있으면3읽기다. 경로 전체가 캐시되어도 실제 데이터 페이지가 비캐시면1읽기가 남는다. 높이만으로 실제 읽기를 동일하다고 하지 않는다.

정적 구조의 갱신 비용

ISAM처럼 상위 구간이 고정된 방식은 삽입을 위한 오버플로 페이지가 늘어날 수 있다. 같은 대표 구간을 찾은 뒤 연결된 추가 페이지까지 살피면 경로 길이 밖의 비용이 생긴다.

페이지 비용은 CPU 비교 횟수·바이트·지연과 다른 단위다. 범위 검색은 여러 데이터 페이지, 비클러스터 포인터는 흩어진 페이지를 요구할 수 있다. 캐시·배치 I/O·갱신·장비의 지연을 명시하지 않고 실제 속도를 숫자로 주장하지 않는다.

연습 1 · 값과 상태 예측

루트도 처음부터 없지만 모든 읽은 페이지를 유지하면 같은 세 조회의 총 읽기는?

힌트 1

R은 첫 조회에서만 읽는다.

힌트 2

기존8회에 R1회만 더한다.

풀이와 답 확인

  1. 루트 R도 처음에 없다면 첫 조회의 새 읽기는 R, M1, L1, D1의 4회이다. 이후 둘째 조회는 2회, 셋째 조회는 3회가 필요하다.

  2. 총 디스크 페이지 읽기는 4+2+3=9회이다.

총 디스크 페이지 읽기는 9회이다. 읽은 루트를 유지하므로 매 조회에서 네 페이지를 새로 읽는 12회와 다르다.

냉간 시작이면 뒤의 모든 조회도 냉간이다.

읽은 페이지를 유지하는 조건에서 초기 상태와 후속 상태는 달라진다.

힌트 2

풀이와 답 확인

  2. 조회마다 루트 이외의 세 페이지를 새로 읽으므로 각 조회의 디스크 페이지 읽기는 3회이다.

총 디스크 페이지 읽기는 9회이다. 모든 읽은 페이지를 유지하는 본문의 총 8회와 캐시 조건이 다르다.

단건 경로 R→M1→L1→D1→O1→O2→종료의 페이지 장부를 만들어라. R만 캐시되고 다른 페이지는 없다.

힌트 1

색인 세 단계와 데이터·오버플로를 분리한다.

힌트 2

풀이와 답 확인

  2. O1과 O2도 캐시에 없어 각각 한 번씩, 총 2회 더 읽은 뒤 정상 종료 포인터를 확인한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

둘째 조회도 첫째와 완전히 같은 R→M1→L1→D1이고 셋째는 기존 M2 경로라면? 초기 R캐시와 전체 유지 조건은 같다.

힌트 1

두 번째는 네 페이지가 모두 이미 있다.

힌트 2

세 번째 새 경로에서 M2,L3,D3을 읽는다.

풀이와 답 확인

  1. 첫 조회는 M1, L1, D1을 새로 읽어 3회이다. 완전히 같은 둘째 조회의 네 페이지는 모두 캐시에 있어 새 디스크 읽기가 0회이다. 셋째 조회는 M2, L3, D3을 새로 읽어 3회이다.

  2. 총 디스크 페이지 읽기는 3+0+3=6회이다.

총 디스크 페이지 읽기는 6회이다. 새 디스크 읽기가 0회인 조회에도 CPU 비교와 버퍼 접근은 필요할 수 있다.

P1 [2,5], P2 [5,5], P3 [5,9]의 첫 대표에서 오른쪽5의 P3만 읽은 결과 누락을 설명하라. 뒤로 시작점을 확인한 뒤 앞으로 모두5를 모을 때 모든 읽은 페이지를 유지하면 데이터 읽기는 얼마인가? 별도 복합 표 (CS,70,1),(CS,80,5),(CS,90,3),(EE,60,4),(EE,80,6),(EE,90,2)에서 (CS,80)~(EE,90) 넓은 구간 뒤 점수80~90 필터를 적용하라. 결과의 페이지 순서 P2,P1,P2,P1을 한 페이지 냉간 캐시로 읽는 비용과, 고정 데이터·충분한 별도 메모리·원래 결과 순번을 보존한 페이지별 읽기를 비교하라. 별도 루트만 캐시된 세 경로 R/M1/L1/D1, R/M1/L2/D2, R/M2/L3/D3에서 읽은 모든 페이지를 유지하면 총 읽기는? 오버플로 O1→O2→O1을 발견한 부재 조회를 정상 성공으로 표시해도 되는가?

힌트 1

후보 하나와 모든 중복, 넓은 사전식 구간과 점수 필터를 구별한다.

힌트 2

경로별 새 페이지와 출력 순서를 기록하고 순환은 구조 오류로 판단한다.

풀이와 답 확인

  1. P3만 확인하면 키 5의 레코드 한 개만 찾고 P1과 P2의 세 개를 놓친다. 뒤로 P2와 P1을 읽어 시작점을 확인하고 읽은 세 페이지를 모두 유지하면, 앞으로 다시 검사할 때 캐시를 재사용한다. 데이터 페이지 읽기는 총 3회이고 결과는 키 5의 레코드 네 개이다.

  2. 넓은 사전식 구간의 학번은 5, 3, 4, 6, 2이다. 점수 60인 EE의 학번 4를 잔여 필터로 제외하면 결과 학번은 5, 3, 6, 2이다.

  3. 한 페이지 냉간 캐시에서 원래 요청 P2, P1, P2, P1은 디스크 페이지 읽기 4회가 필요하다. 페이지별 P1, P1, P2, P2 요청은 2회만 필요하다. 충분한 별도 메모리와 고정 데이터 조건에서 원래 결과 순번을 보존하여 학번 5, 3, 6, 2를 복원한다.

  4. 루트만 캐시된 세 경로에서는 M1을 공유하여 첫 조회 3회, 둘째 2회, 셋째 3회로 총 디스크 페이지 읽기 8회이다. 오버플로 O1, O2, O1의 재방문은 구조 순환을 뜻하며 정상 종료에 근거한 부재 성공으로 표시하지 않는다.

자체 색인·페이지·검사 장부의 손검토다. 실제 DB·버퍼·동시 갱신·손상 파일·장치·학생 실행은 미수행이다.

해결한 뒤 점검할 것

  • 앞과 뒤 페이지에 걸친 중복을 보존한다.

  • 사전식 넓은 구간 이후의 잔여 점수 조건을 검사한다.

  • 페이지 읽기 재배치에서 전체 결과와 순서를 유지한다.

  • 공유 경로의 실제 캐시 miss와 구조 오류를 구별한다.
