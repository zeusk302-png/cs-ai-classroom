소단원 7.1

희소·밀집 색인

책의 모든 단어를 적을까, 각 페이지의 첫 단어만 적을까?

준비 개념과 학습 목표

준비 개념

  • 파일은 여러 레코드를 담은 페이지의 순서다.

  • 검색 키와 레코드 식별자/페이지 주소는 서로 다르다.

학습 목표

  • 희소 색인의 정렬 전제를 설명한다.

  • 색인에서 후보 페이지를 찾아 실제 존재를 확인한다.

검색을 안내하는 별도 표

색인은 검색 키에서 레코드 또는 데이터 페이지로 가는 작은 표다. 밀집 색인은 모든 검색 키 값을 나타내며 같은 값의 여러 레코드가 있으면 포인터 목록 등으로 함께 대응할 수 있다. 키 하나당과 레코드 하나당이라는 설계가 항상 같은 것은 아니다.

희소 색인은 일부 대표 키만 기록한다. 이 단원은 검색 키로 정렬된 데이터 페이지마다 첫 키와 페이지 포인터 하나를 저장하는 모형이다. 대표 키 사이 구간이 한 페이지에 대응하므로 색인에 검색 값 자체가 없어도 후보를 찾을 수 있다.

가장 큰 작은 대표 키

찾을 값 x보다 작거나 같은 대표 중 최대를 선택한다. 그 페이지를 실제로 읽어 x를 찾는다. 첫 대표보다 작은 값은 이 정렬 파일에 없으며, 마지막 대표보다 큰 값은 마지막 후보 페이지를 확인해야 한다.

정렬 순서가 보장되지 않으면 대표 사이 구간을 추론할 수 없다. 중복 키가 여러 페이지에 걸치면 첫 키만 따라 한 페이지로 끝내서는 모든 결과를 못 찾을 수 있다. 아래 표는 키가 유일하고 오버플로가 없는 고정 파일이다.

공간을 아끼는 대가

페이지마다4개의 레코드가 있고 전체12개라면 희소 항목3개, 고유 키마다의 밀집 항목12개다. 희소 표는 작지만 대표가 아닌 키의 존재 여부를 데이터에서 확인하는 단계가 필요하다.

삽입으로 페이지 첫 키가 바뀌면 대표 키를 갱신해야 한다. 삭제로 페이지가 비거나 경계가 이동하면 포인터와 범위도 조정한다. 색인 크기만으로 전체 비용을 판단하지 않고 실제 데이터 읽기와 유지 비용을 함께 생각한다.

중간 과정을 따라가는 예제

정렬 파일 P1=[2,5,8,11],P2=[14,17,20,23],P3=[26,29,32,35]이다. 희소 항목(2,P1),(14,P2),(26,P3)에서20과25를 찾는다.

  1. 20보다 작거나 같은 대표2/14 중 최대14를 골라P2를 읽는다. P2의 세 번째20을 찾는다.

  2. 25도 최대 대표 14로P2를 읽지만 [14,17,20,23]에25가 없으므로 없는 값이다.

  3. 색인에20 항목이 없다는 사실은20의 부재를 의미하지 않는다. 반면 밀집 고유 키 표에는20 항목이 있어야 한다.

20은P2에 있고25는 없다. 희소 표3항목/밀집 고유 키 표12항목이다.

종이와 본문으로 직접 해보기

같은 파일에서1/14/36을 찾을 후보와 결과를 적는다. P2 첫 값14를 삭제한 뒤 파일을 재배치하지 않는다면 대표는 어떻게 고칠까?

힌트 보기

첫 대표보다 작은 경우와 마지막 대표보다 큰 경우를 구별한다.

풀이 보기

1은 첫 대표2보다 작아 없다.14는P2에서 발견,36은P3 후보를 읽어 부재 확인한다. 삭제 뒤 P2=[17,20,23]이면 대표 14를17로 바꾸어 첫 키 규약을 보존한다.

오해와 반례

색인에 값이 없으면 파일에도 없다.

희소 표에 20이 없어도 P2에는 있다. 모든 키를 나타내는 완전하고 일관된 밀집 색인에서의 부재 판정을 희소 표에 그대로 적용하지 않는다.

자기점검

20의 희소 후보는?

답과 이유 보기

P2다.

20 이하 최대 대표는14다.

희소 표는 미정렬 파일에도 같은 규칙으로 가능한가?

답과 이유 보기

아니다.

대표 사이 값이 같은 페이지에 있다는 정렬 근거가 사라진다.

P2 첫 값 삭제 후 대표는?

답과 이유 보기

17이다.

재배치 없이 첫 키 규약을 유지한다는 조건이다.

한 단계 더

P1끝에14,P2처음에도14가 있는 중복 파일을 만든다. 대표 14에서 P2만 읽으면 P1의14를 놓친다. 중복 경계를 다루는 탐색/앞 페이지 확인/포인터 목록 중 어떤 추가 설계가 필요한지 제안하되 이를 위 유일 키 모형과 구분한다.

소단원 7.2

기본·보조·복합 색인

같은 학생 목록을 학번과 학과로 동시에 정렬할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 기본키는 레코드를 유일하게 식별하는 논리 조건이다.

  • 물리 순서는 저장된 데이터 페이지 배열 순서다.

학습 목표

  • 색인 이름과 물리 정렬 가정을 구별한다.

  • 복합 키의 사전식 구간을 추적한다.

논리 제약과 물리 배치

이 단원에서 기본 색인은 기본키 순으로 정렬된 파일의 색인, 보조 색인은 다른 검색 키를 위한 추가 표라는 고전적인 용어를 사용한다. 실제 DBMS가 같은 단어로 다른 저장 구조를 뜻할 수도 있어 용어의 정의를 먼저 확인한다.

기본키 선언이 모든 제품에서 데이터 파일을 그 순서로 정렬한다는 뜻은 아니다. 기본키의 유일성 조건과 클러스터 배치는 별도다. 한 물리 파일을 두 독립 열의 서로 다른 순서로 동시에 배열할 수 없으므로 보조 색인은 포인터로 찾아간다.

보조 검색의 결과 모으기

학번 정렬 파일에서 학과 색인을 만들면 같은 학과의 학생들이 여러 페이지에 흩어질 수 있다. 그 키를 가진 모든 레코드를 찾으려면 밀집 대응이나 모든 해당 레코드 포인터 목록이 필요하다.

키가 비유일이면 포인터 하나만 저장해 한 레코드로 끝내서는 안 된다. 같은 색인 결과4개라도 물리적으로1페이지에 모였는지4페이지에 흩어졌는지에 따라 데이터 페이지 읽기가 달라진다. 중복 페이지는 버퍼에 있으면 재사용한다.

두 열을 하나의 순서로

복합 B-tree 키 (학과,점수)는 먼저 학과를 비교하고 학과가 같을 때 점수를 비교하는 사전식 순서다. 학과=CS와 점수≥80은 그 학과 안의 연속 구간이 된다.

점수≥80만 있으면 여러 학과에 떨어진 구간이다. 단순 한 구간 스캔으로 앞 열 조건이 있는 경우와 같지 않다. 최신 제품은 skip scan 같은 여러 재탐색을 선택할 수도 있으므로 앞 열 조건 없으면 색인을 절대 못 쓴다는 주장은 하지 않는다.

중간 과정을 따라가는 예제

학번 순 파일 P1=[(1,CS,70),(2,EE,90),(3,CS,90)],P2=[(4,EE,60),(5,CS,80),(6,EE,80)]다. 학과 보조 표와 (학과,점수,학번) 순서를 만든다.

  1. 보조 CS 포인터는1/3/5,EE는2/4/6이다. CS의 실제 데이터는P1/P2 두 페이지에 걸친다.

  2. 복합 키 정렬은(CS,70,1),(CS,80,5),(CS,90,3),(EE,60,4),(EE,80,6),(EE,90,2)다. 마지막 학번은 동률을 구별하는 규약이다.

  3. CS이고점수≥80은5/3의 연속 두 항목이다. 점수≥80만이면CS의5/3과EE의6/2 두 구간으로 나뉜다.

CS 보조 결과1/3/5, 복합 조건 CS·≥80은5/3이다. 데이터 페이지 읽기와 색인 항목 검사는 별도로 센다.

종이와 본문으로 직접 해보기

같은 복합 표에서 EE이고점수<90,그리고 점수=80만인 결과를 적고 필요한 연속 구간 수를 비교한다.

힌트 보기

먼저 학과가 고정되는지 확인한 뒤 점수 경계를 적용한다.

풀이 보기

EE·<90은4/6의 한 구간이다. 점수80만은CS의5와EE의6으로 두 떨어진 구간이다. 각 구간 재탐색이나 전체 색인 필터 등 실제 전략은 비용에 따라 달라진다.

오해와 반례

기본키가 있으니 그 파일은 언제나 기본키 순서다.

기본키는 유일성 및 NULL 금지 같은 논리 제약이다. 물리 정렬·페이지 구조는 제품과 저장 방식에 따라 달라 고전적인 기본 색인 예제의 가정을 확인해야 한다.

자기점검

CS의 포인터를 하나만 저장해도 모든 학생을 찾나?

답과 이유 보기

못 찾는다.

CS 학생1/3/5를 모두 대응해야 한다.

복합 표에서 EE·<90 결과는?

답과 이유 보기

학번4/6이다.

점수60/80은90보다 작고 같은EE 구간이다.

앞 열 조건 없으면 모든 B-tree 사용이 불가능한가?

답과 이유 보기

아니다.

전체 필터/여러 구간/제품의 skip scan 가능성을 구별해야 한다.

한 단계 더

복합 순서를 (점수,학과,학번)으로 바꾸어 점수≥80과 CS·≥80의 구간을 다시 그린다. 선택한 정렬이 어느 질의에 편리한지 비교하고 갱신 시 여러 색인의 포인터/키를 함께 유지해야 하는 비용도 설명한다.

소단원 7.3

다단계 탐색과 페이지 비용

색인의 색인까지 만들면 디스크를 몇 번 읽을까?

준비 개념과 학습 목표

준비 개념

  • 한 I/O는 버퍼에 없는 페이지 하나를 읽는 비용 단위다.

  • 올림 ceil은 필요한 페이지 수를 남는 항목까지 포함해 센다.

학습 목표

  • 다단계 대표 표의 높이를 계산한다.

  • 캐시와 오버플로 가정을 명시하여 비용을 센다.

색인이 너무 커지면

정렬 데이터 페이지의 첫 키를 모은 희소 표도 여러 페이지가 될 수 있다. 그 표의 각 페이지 첫 키를 상위 색인으로 만들면 같은 후보 선택을 여러 단계 반복할 수 있다.

이 단원은 고정 파일의 단순 다단계 희소 색인이다. 각 색인 페이지가 포인터를 가진 항목을 4 개 담으며 데이터 페이지는 따로 둔다. B-tree의 분기 포인터 f개/분리 키 f−1개 같은 다른 노드 규칙과 섞지 않는다.

높이보다 구체적인 경로

64개 데이터 페이지면 최하위 색인은64 항목/16페이지다. 그 위는16항목/4페이지, 루트는4 항목/1페이지다. 색인 3 단계와 데이터1페이지를 방문한다.

모두 비캐시이고 결과가 한 데이터 페이지에 있는 유일 키라면4읽기다. 루트가 이미 버퍼에 있으면3읽기다. 경로 전체가 캐시되어도 실제 데이터 페이지가 비캐시면1읽기가 남는다. 높이만으로 실제 읽기를 동일하다고 하지 않는다.

정적 구조의 갱신 비용

ISAM처럼 상위 구간이 고정된 방식은 삽입을 위한 오버플로 페이지가 늘어날 수 있다. 같은 대표 구간을 찾은 뒤 연결된 추가 페이지까지 살피면 경로 길이 밖의 비용이 생긴다.

페이지 비용은 CPU 비교 횟수·바이트·지연과 다른 단위다. 범위 검색은 여러 데이터 페이지, 비클러스터 포인터는 흩어진 페이지를 요구할 수 있다. 캐시·배치 I/O·갱신·장비의 지연을 명시하지 않고 실제 속도를 숫자로 주장하지 않는다.

중간 과정을 따라가는 예제

데이터64 페이지, 색인 한 페이지4 항목, 페이지 첫 키 대표 규약이다. 루트→중간→하위→데이터 경로의 유일 키 한 번 탐색 비용을 계산한다.

  1. 하위64 항목을4로 나누어16페이지, 중간16항목은4페이지, 루트4 항목은1페이지다.

  2. 비캐시 경로는루트1+중간1+하위1+데이터1=4페이지 읽기다. 전체 색인21페이지를 전부 읽는 것은 아니다.

  3. 루트 캐시이면3읽기, 루트와중간과하위 경로가 캐시면 데이터만1읽기다.

색인 3 단계/총색인21페이지, 단건 비캐시4읽기다.

종이와 본문으로 직접 해보기

데이터65 페이지로 바꾸면 각 단계 페이지 수와 비캐시 단건 읽기는? 별도로64 페이지 모형에서 후보 데이터 뒤 오버플로2페이지까지 읽어야 부재 확인하면 비용은?

힌트 보기

매 단계 ceil(항목/4)을 적용하여 최상위가1페이지일 때 멈춘다.

풀이 보기

65→하위17페이지→다음5→다음2→루트1이므로 색인4단계/총25페이지다. 단건은색인4+데이터1=5읽기다. 별도64모형의 오버플로 부재 탐색은기본4+2=6읽기,루트 캐시면5다.

오해와 반례

색인 3 단계이면 언제나 3 번 디스크를 읽는다.

비캐시 모형은 실제 데이터를 읽어 4 번이며 캐시는 이를 줄이고 오버플로/범위는 늘린다. 색인 높이와 전체 I/O의 단위를 구별한다.

페이지 항목 용량을8로 바꾸어64데이터 모형을 다시 계산한다. 하위8/루트1로색인2단계,비캐시3읽기다. 더 큰 페이지가 실제로 항상 더 빠른지는 항목 크기·장비·캐시·유지 비용까지 필요하다고 구별한다.
