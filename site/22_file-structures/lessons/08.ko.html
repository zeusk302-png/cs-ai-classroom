소단원 8.1

차수·점유율·균형

한 페이지에 여러 갈림길을 담으면 왜 검색 경로가 짧아질까?

준비 개념과 학습 목표

준비 개념

  • 정렬 키가 검색 구간을 나눈다.

  • 트리 높이는 루트에서 리프까지의 간선 수다.

학습 목표

  • 차수 관례와 루트 예외를 명시한다.

  • 균형과 점유율이 디스크 탐색에 주는 영향을 계산한다.

차수는 먼저 약속한다

이 소단원의 B트리 차수 m은 내부 노드의 최대 자식 수다. 자식이 c개인 내부 노드는 구간 경계 키 c−1개를 갖는다. 루트가 아닌 내부 노드는 ceil(m/2)개 이상 자식을 가지며, 리프의 키 수는 ceil(m/2)−1 이상 m−1 이하다. 비어 있지 않은 루트는 최소 한 키를 갖고 내부 루트라면 자식이 둘 이상이다.

다른 책은 최소 차수 t나 최대 키 수를 차수라고 부른다. 따라서 차수 4라는 이름만 보고 같은 용량이라 단정하지 않는다. B+트리는 내부 노드와 리프의 크기가 다를 수 있어 내부 최대 자식 수 m과 리프 최대 레코드 수 L을 따로 적는다.

모든 리프까지 같은 깊이

B트리와 B+트리는 모든 리프가 같은 깊이에 있도록 갱신한다. 검색이 한쪽으로 긴 사슬을 만들지 않으므로 작은 높이를 유지할 수 있다. 균형이라는 말은 각 노드의 키가 정확히 같은 수라는 뜻은 아니다.

한 노드를 한 디스크 페이지로 가정하면 루트에서 리프까지 높이 h인 경로는 h+1개 페이지를 방문한다. 실제 입출력은 캐시, 상위 노드 메모리 유지, 레코드 별도 저장 여부에 따라 다르므로 방문 수를 그대로 실측 시간이라고 부르지 않는다.

점유율과 갈림길의 효과

페이지를 지나치게 비워 두면 같은 레코드를 담는 페이지가 많아지고 높이가 늘 수 있다. 최소 점유 규칙은 이런 낭비를 제한한다. 하지만 ceil(m/2)−1 키라는 B트리 규칙을 무조건 키 슬롯의 정확한 절반이라고 바꾸면 짝수 m에서 틀린다.

분기 수가 큰 트리는 적은 단계에서 많은 구간을 구별한다. B+트리는 실제 레코드를 리프에 모으고 내부에는 경계 키를 둬 내부 분기 수를 크게 만들 수 있다. 페이지 크기와 키/포인터 크기도 함께 고려해야 한다.

중간 과정을 따라가는 예제

차수 m=4인 B트리를 생각하자. 높이 2이며 내부 루트와 그 자식이 각각 최소 허용 자식 수만 가지는 경우 리프 수와 최소 전체 키 수를 구하라.

  1. 루트 최소 자식은 2개이고 루트 키는 1개다.

  2. 깊이 1의 비루트 내부 노드 둘은 각각 ceil(4/2)=2개 자식과 키 1개를 갖는다.

  3. 리프는 2×2=4개이며 각각 최소 1키다.

  4. 전체 최소 키는 1+2×1+4×1=7이다.

리프 4개, 전체 최소 키 7개다. 최소 상태와 최대 상태를 구분한 계산이다.

종이와 본문으로 직접 해보기

같은 높이에서 모든 노드가 최대 용량이면 리프와 전체 키는 몇 개인가?

힌트 보기

루트와 깊이 1 내부 노드의 자식 수를 각각 4로 둔다.

풀이 보기

리프 4²=16개, 노드 총수 1+4+16=21개, 각 노드 3키이므로 63키다.

오해와 반례

균형 트리는 모든 페이지가 꽉 차 있다.

최소 예제의 각 노드는 1키만 갖지만 모든 리프 깊이가 같아 유효하다. 깊이 조건과 용량 경계는 서로 다른 조건이다.

자기점검

m=4에서 비루트 내부 노드 최소 자식 수는?

답과 이유 보기

2개다.

ceil(4/2)=2다.

내부 노드의 자식이 3개이면 경계 키는?

답과 이유 보기

2개다.

정렬 구간 3개를 나누는 경계는 둘이다.

높이 2의 검색은 캐시 없는 단순 모형에서 몇 노드를 방문하는가?

답과 이유 보기

3개다.

깊이 0,1,2의 노드를 방문한다.

한 단계 더

m=5로 바꿔 비루트 최소 자식 3개와 최소 키 2개를 확인하라. 최소 차수 t 관례와 이 m 관례를 혼합하면 어떤 수가 달라지는지 설명해 보자.

소단원 8.2

삽입·분할·병합

가득 찬 서랍에 새 카드를 넣거나 너무 빈 서랍을 합칠 때 안내표는 어떻게 바뀔까?

준비 개념과 학습 목표

준비 개념

  • B+트리 내부 키는 경계이고 실제 레코드는 리프에 있다.

  • 리프 최소·최대 용량은 별도로 정한다.

학습 목표

  • 분할 시 복사와 이동을 구분한다.

  • 삭제 후 재분배·병합 및 루트 축소를 추적한다.

삽입은 위치 찾기부터

검색과 같은 경로로 새 키가 들어갈 리프를 찾는다. 이 소단원은 중복 없는 키, 내부 최대 자식 m=4, 리프 최대 L=4·최소 2레코드인 B+트리다. 부모의 경계는 오른쪽 자식의 최소 키이며 경계와 같은 값은 오른쪽으로 내려간다.

여유가 있으면 정렬 위치에 삽입한다. 5레코드가 되면 두 리프로 나누어 2개와 3개를 담는 규칙을 사용한다. 새 오른쪽 리프의 최소 키를 부모에 복사한다. 그 키의 실제 레코드는 오른쪽 리프에 그대로 남는다.

부모도 함께 바뀐다

부모에 경계와 새 자식 포인터를 넣으면 내부 최대 자식 수도 검사한다. 넘치면 내부 노드를 분할하며 분리 경계를 위로 이동시킨다. 내부 경계의 이동과 B+리프 경계의 복사는 같은 연산이 아니다.

리프였던 루트가 처음 나뉘면 두 리프를 가리키는 새 루트가 생겨 모든 리프 깊이가 함께 하나 늘어난다. 특정 리프만 깊게 매달면 균형 조건을 어긴다.

삭제로 빈 공간이 많아질 때

레코드 삭제 뒤 최소 점유율 아래로 내려가면 같은 부모 아래 인접 형제에게서 하나를 빌리는 재분배를 시도한다. 경계가 오른쪽 최소 키이므로 이동 결과에 맞춰 부모도 고친다. 형제에게 여유가 없고 합친 내용이 최대 용량 안이면 병합한다.

병합은 리프 연결과 부모의 자식 포인터·경계 하나를 함께 줄인다. 부모도 최소 자식 수를 어기면 처리를 위로 이어 간다. 루트가 내부 노드인데 자식이 하나만 남으면 그 자식을 새 루트로 삼아 높이를 줄인다. 실제 저장장치 갱신의 동시성·장애 복구는 별도 문제다.

중간 과정을 따라가는 예제

단일 루트 리프 [10,20,30,40]에 25를 삽입하라. 위의 2/3 분할 규칙을 사용한 뒤 20을 삭제하고 오른쪽 형제에서 빌려라.

  1. 삽입 정렬 결과는 [10,20,25,30,40]이다.

  2. 왼쪽 [10,20], 오른쪽 [25,30,40]으로 나누고 새 루트 경계 [25]를 만든다. 25는 오른쪽 레코드에도 남는다.

  3. 20 삭제로 왼쪽 [10]이 되어 최소 2개를 못 채운다. 오른쪽은 3개라 하나를 줄 수 있다.

  4. 25를 왼쪽으로 옮겨 [10,25], 오른쪽 [30,40]으로 만들고 부모 경계를 30으로 고친다.

루트 [30], 연결 리프 [10,25]→[30,40]이다. 두 리프 모두 최소 점유율을 만족한다.

종이와 본문으로 직접 해보기

위 최종 상태에서 10을 삭제하라. 오른쪽은 더 빌려 줄 수 없는 경우 병합 결과를 그려라.

힌트 보기

남은 레코드 수 1+2=3은 리프 최대 4 이하다.

풀이 보기

두 리프를 [25,30,40]으로 병합한다. 부모는 자식 하나만 남아 제거되고 병합 리프가 루트가 된다. 깊이가 1에서 0으로 감소한다.

오해와 반례

B+리프 분할 때 부모에 올라간 키는 리프에서 지워야 한다.

25를 지우면 실제 레코드가 없어져 검색 결과가 바뀐다. 이 모형의 부모 25는 안내 복사본이고 리프의 25는 실제 항목이다. 내부 분할의 경계 이동과 구분해야 한다.

자기점검

분할 직후 25의 레코드는 어디 있는가?

답과 이유 보기

오른쪽 리프다.

부모에는 탐색 경계 복사본만 있다.

25를 왼쪽으로 빌린 뒤 경계를 그대로 두어도 되는가?

답과 이유 보기

안 된다.

오른쪽 최소 키가 30으로 바뀐다.

루트 축소 후 균형 조건은 깨지는가?

답과 이유 보기

아니다.

모든 리프 깊이가 함께 감소한다.

한 단계 더

삽입 35 뒤 각 리프와 경계를 다시 쓰고, 30 삭제로 오른쪽 최소 키가 바뀌는 경우 부모 안내값을 유지하는 방법을 설명하라.

소단원 8.3

범위 탐색과 연결 리프

처음 찾은 카드부터 다음 카드를 읽을 때 매번 서랍장을 처음부터 뒤져야 할까?

준비 개념과 학습 목표

준비 개념

  • B+리프는 키 순서대로 연결할 수 있다.

  • 구간 [a,b]는 양 끝을 포함한다.

학습 목표

  • 시작 키 탐색과 순차 스캔을 연결한다.

  • 범위 종료 조건과 페이지 방문 비용을 구분한다.

범위의 시작점 찾기

B+트리의 내부 노드는 구간을 안내하고 리프는 실제 키와 레코드 또는 레코드 포인터를 담는다. 범위 질의 [a,b]는 먼저 a가 들어갈 리프를 찾고 그 리프에서 a 이상인 첫 항목부터 읽는다. a가 정확히 존재할 필요는 없다.

내부 키와 a가 같아도 내부에서 결과를 반환하고 멈추지 않는다. 경계는 복사된 안내값이다. 실제 리프에서 레코드를 확인해야 한다. 중복 키가 있는 실제 색인은 중복 배치와 시작 위치 규칙을 추가해야 하므로 이 예제는 유일 키만 사용한다.

다음 리프로 이어 가기

리프 내부에서 끝까지 읽으면 연결된 다음 리프로 이동한다. 범위보다 큰 키를 처음 만나거나 리프 끝에 다음 포인터가 없으면 종료한다. 정렬되어 있으므로 이미 b보다 큰 값을 본 뒤 더 오른쪽을 찾아도 답이 추가되지 않는다.

연결이 있다는 사실은 반드시 디스크 물리 위치가 연속이라는 뜻은 아니다. 포인터로 순서가 이어지는 논리 연결이다. 실제 읽기 지연은 캐시·저장장치·선읽기 정책에 달려 있다.

높이와 결과 크기를 함께 보기

첫 리프까지는 높이 h에서 h+1개 노드를 방문하고 이어 결과 구간의 리프들을 읽는다. 이 단원은 캐시 없는 페이지 방문 모델이며 마지막 범위 밖 항목 확인 때문에 답을 담지 않은 경계 리프도 읽을 수 있다.

레코드가 다른 파일에 있고 리프가 포인터만 담는 색인이라면 실제 데이터 페이지 접근은 따로 세어야 한다. 범위가 좁을 때 색인 효율이 높지만 거의 모든 레코드를 요구하면 많은 리프와 데이터 페이지를 읽는다. 모든 범위를 같은 고정 비용으로 표현하지 않는다.

중간 과정을 따라가는 예제

루트 경계 [20,40,60], 연결 리프 [5,10,15]→[20,25,30]→[40,45,50]→[60,65,70]이다. [22,47]을 조회하라. 루트·리프 각 한 페이지, 캐시는 없고 데이터 추가 읽기는 없다고 가정한다.

  1. 22는 20 이상 40 미만이므로 두 번째 리프로 내려간다.

  2. [20,25,30]에서 20을 건너뛰고 25,30을 출력한다.

  3. 다음 리프 [40,45,50]에서 40,45를 출력하고 50>47을 보아 멈춘다.

  4. 방문 페이지는 루트 하나와 리프 둘, 총 3개다.

결과 [25,30,40,45], 페이지 방문 3회다. 결과 개수 4와 읽은 페이지 수 3은 다른 양이다.

종이와 본문으로 직접 해보기

같은 구조에서 [31,39]를 찾아라. 리프에 다음 포인터가 있을 때 다음 페이지를 실제로 읽는 모형을 사용한다.

힌트 보기

31이 들어갈 두 번째 리프에는 31 이상이 없다. 다음 리프의 첫 값 40을 확인한다.

풀이 보기

결과는 빈 집합이다. 루트·두 번째 리프·세 번째 리프를 읽어 총 3페이지를 방문한다. 내부 경계 40을 이용한 최적화는 이 스캔 모형에서 적용하지 않았다.

오해와 반례

검색값이 내부 경계와 같으면 그 값을 결과 레코드로 반환하면 된다.

40의 경계는 실제 데이터가 아니다. [40,40]은 세 번째 리프에 가서 40을 확인해야 한다. 안내 키를 반환하면 레코드 포인터 등 실제 내용 없이 잘못된 결과를 만들 수 있다.
