현재 값만 남기는 정리를 스냅샷이 있는 동안 해도 될까?

기본 본문의 여섯 기록에 전역 순번을 붙인다. A=1(seq1), B=2(seq2), A=3(seq3), delete B(seq4), C=4(seq5), A=5(seq6)다. 자체 조회는 지정 순번 이하에서 각 키의 가장 최신 기록을 선택한다. seq2 스냅샷은 A=1,B=2이고 C는 없다. seq4 스냅샷은 A=3,B 없음,C 없음이다. 현재 seq6은 A=5,C=4,B 없음이다.

두 스냅샷과 현재 읽기를 모두 지원하고 다른 파일·복구 의존성은 없다고 정한다. A는 seq1/3/6을 각각 보존해야 하고 B는 seq2의 값과 seq4의 삭제를 모두 보존해야 한다. C는 seq5를 남긴다. 여섯 기록을 모두 보존해야 한다. 기록당 20바이트이므로 출력은 120바이트다. 원본 120바이트와 새 출력 120바이트를 함께 유지하는 동안은 240바이트가 필요하다. 현재 데이터만 남겼던 기본 본문의40/160과 요구 조건이 다르다.

seq2 독자를 해제하고 seq4와 현재만 남으면 A seq3/6과 C seq5가 필요하다. 이 소단원의 보수적 정리 정책은 과거 독자가 한 명이라도 남아 있는 동안 최신 삭제 표식도 유지한다. 따라서 B 삭제 seq4까지 네 기록을 남겨 출력은 80바이트, 원본과 공존하는 공간은 200바이트다. 이는 최소 보존 기록 수를 주장하는 정책이 아니다. B의 옛 값이 다른 곳에 전혀 없으면 표식까지 제거하는 더 적극적인 정책도 가능하다. 모든 과거 독자를 해제하고 모든 옛 기록을 함께 회수하는 마지막 경우에는 현재 A5/C4만 40바이트로 남긴다. 실제 RocksDB의 파일 참조·스냅샷·복구 수명은 이 종이 모형으로 구현하지 않았다.

수정도 새 기록으로 남기기

append-only는 이 모형에서 기존 기록을 덮지 않고 뒤에 새 기록을 붙이는 방식이다. 키 A의 값을 바꾸면 A의 새 값과 순서를 기록한다. 읽을 때는 같은 키의 유효한 최신 기록을 선택한다. 옛 기록은 파일에 남을 수 있어 논리 데이터와 물리 바이트가 다르다.

삭제도 지워졌다는 표식인 tombstone을 새 기록으로 남길 수 있다. 이전 값을 찾았더라도 더 최신 삭제 표식이 있으면 현재 조회는 없음이다. 이 절은 모든 기록의 전역 순서가 알려지고 스냅샷 독자가 없는 작은 자체 모형을 다룬다.

살아 있는 기록만 새 파일로 옮기기

정리 과정에서는 필요한 기록을 읽고 새 파일에 보존할 기록을 쓴다. 모든 오래된 기록을 한 번에 다시 볼 수 있고 과거 읽기·복구 요구가 없다면 현재 값만 남긴 뒤 이전 파일을 제거할 수 있다. 원본을 먼저 삭제하고 새 파일을 쓰다가 실패하는 순서는 안전한 교체가 아니다.

삭제 표식을 버려도 되는지는 옛 값이 다른 파일에 남아 있는지를 포함해 판단한다. 표식을 지웠는데 다른 계층에서 오래된 값이 발견되면 삭제된 키가 되살아날 수 있다. 스냅샷이 과거 버전을 읽는 시스템에서는 최신 값만 남기는 정책도 충분하지 않다.

추가 기록이 곧 영속성은 아니다

메모리나 운영체제 버퍼에 기록했다는 사실과 장애 후 디스크에서 복구할 수 있다는 사실은 다르다. 실제 저장 엔진은 로그 동기화, 파일 설치와 메타데이터 기록, 복구 규칙을 정한다. append-only라는 형식 자체가 모든 쓰기의 장애 내구성을 보장하지 않는다.

RocksDB의 WAL은 memtable 변경을 복구하는 로그이며 선택적으로 비활성화할 수 있다. 동기화 여부도 쓰기 옵션에 달린다. 이 절의 단일 로그 정리 모형은 WAL과 SST의 정확한 수명이나 실제 장애 복구를 구현했다고 주장하지 않는다.

중간 과정을 따라가는 예제

전역 순서대로 A=1, B=2, A=3, delete B, C=4, A=5가 있다. 각 기록은 삭제 표식도 포함해 20바이트다. 모든 관련 기록을 한 번에 정리하고 과거 독자·다른 파일·복구 의존성이 없다고 가정한다. 현재 값과 정리 크기를 구하라.

  1. A의 가장 최신 기록은 여섯 번째 A=5다. B의 최신 기록은 네 번째 삭제 표식이므로 현재 없다. C의 최신 기록은 C=4다.

  2. 입력은 6×20=120바이트다. 모든 관련 옛 기록이 함께 제거되는 조건이므로 삭제 B의 표식도 버릴 수 있다.

  3. 새 파일은 A=5와 C=4의 2×20=40바이트다. 새 파일이 설치되기 전 입력과 출력이 함께 존재하면 120+40=160바이트를 쓴다.

현재 A=5, C=4이며 B는 없다. 정리 후 40바이트, 원본과 출력 공존 시 160바이트다. 파일 헤더·인덱스·여유 공간은 이 모형에서 제외한다.

seq2와 seq4 독자가 살아 있는데 A seq6만 남겼다. 각 독자에게 어떤 문제가 생기나?

  1. 순번 2의 스냅샷에서는 순번 1의 기록을 선택해야 하므로 A의 값은 1이어야 한다.

  2. 순번 4의 스냅샷에서는 순번 3의 기록을 선택해야 하므로 A의 값은 3이어야 한다.

A = 5인 기록의 순번은 6으로, 두 스냅샷 시점보다 뒤에 있다. 이 값을 과거 독자에게 보여서는 안 된다. 값 1과 3인 옛 기록을 제거하면 각 스냅샷이 읽어야 할 값을 복원할 수 없다.

병합 밖에 옛 값이 남으면 삭제 표식을 제거해도 될까?

자체 부분 병합 대상 F1에는 A=9(seq5), delete B(seq6)가 있고 F2에는 A=2(seq1), B=3(seq2), C=4(seq3), D=5(seq4)가 있다. 병합 밖의 더 오래된 F3에는 B=1(seq0)이 있다. 현재 읽기는 전역 seq로 최신을 선택하며 과거 독자는 없다. F1,F2만 병합하면 현재 값인 A = 9, C = 4, D = 5와 B의 삭제 표식을 남긴다. F3의 옛 B를 막는 표식이 필요하다.

병합 대상으로 선택한 파일 안의 B 옛 값은 없어졌어도 F3가 남아 있으므로 삭제 표식을 버리면 현재 B=1이 되살아난다. 모든 관련 파일을 포함한다는 조건과 일부 다음 레벨의 겹치는 파일만 포함한다는 조건은 다르다. 실제 레벨 구조에서는 후보 범위와 파일 설치 메타데이터 및 독자 수명을 함께 관리한다. 이 목록은 자체 두 파일 부분 병합이고 특정 엔진의 전체 알고리즘이 아니다.

seq2 스냅샷이 추가되면 A seq1의 2와 B seq2의 3도 필요하다. 현재 A seq5, B 삭제 seq6, C seq3, D seq4와 함께 총 여섯 기록이다. seq2 독자에게 C,D는 아직 없으며 현재 읽기는 C = 4와 D = 5를 반환한다. 파일이 물리적으로 새로 작성됐다는 사실이 그 안의 모든 버전이 최신이라는 뜻은 아니다. 선택한 스냅샷 순번과 기록 seq를 함께 확인한다.

새 쓰기는 메모리에서 모이기

LSM 구조에서는 쓰기를 메모리 구조에 모으고 정렬된 파일로 내보내며 여러 파일을 병합한다. RocksDB의 기본 구성에는 memtable, SST 파일, WAL이 있다. memtable은 현재 메모리 변경을 담고 WAL은 설정에 따라 복구에 사용되는 순차 로그다. 둘은 같은 객체가 아니다.

가득 찬 memtable을 파일로 내보내는 flush와 기존 파일들을 합치는 compaction은 서로 다른 일이다. flush했다고 모든 옛 버전이 모든 계층에서 사라지는 것은 아니다. 아래에서는 키·값·전역 순서가 명시되어 최신 읽기를 종이로 추적한다.

겹치는 파일과 정렬된 범위

레벨 방식에서 L0에는 flush된 파일들이 있고 키 범위가 겹칠 수 있다. L1 이후의 각 레벨은 일반적으로 키 범위로 나뉜 하나의 정렬 run이다. 모든 LSM 구현이 같은 레벨 정책을 쓰는 것은 아니며 이 설명은 레벨 병합 방식의 큰 틀이다.

찾는 키가 여러 파일에 있으면 현재 조회는 유효한 최신 버전이 결정한다. 최신 tombstone은 옛 값을 반환하지 못하게 한다. 파일 범위와 인덱스는 후보를 줄이지만 오래된 후보에서 값이 있다는 것만으로 바로 정답이 되지는 않는다.

병합으로 읽기와 공간 비용 조절하기

병합은 관련 정렬 파일을 함께 읽어 순서대로 새 파일을 만든다. 레벨 방식에서는 다음 레벨의 겹치는 범위도 병합 대상으로 고려한다. 중복·옛 버전을 제거할 수 있지만 스냅샷이나 정리 밖의 옛 값에 필요한 삭제 표식까지 무조건 버리지는 않는다.

파일을 설치한 메타데이터와 기존 독자의 수명도 관리한다. 새 파일의 작성과 이전 파일 삭제를 같은 순간의 단순 덮어쓰기라고 보지 말자. 계층 수나 겹침이 읽기 비용에 영향을 주고 이를 줄이는 병합에는 쓰기 비용이 든다.

거짓 양성률과 전체 양성 비율은 같은 분모일까?

자체 100회 조회 중 실제 있는 키 조회가 20회, 없는 키가 80회다. 정상 필터는 있는 20회를 모두 양성으로 표시하고 없는 80회 중 10회는 양성·70회는 음성이다. 양성 총 30회 중 거짓은 10회다. 없는 조회 기준 거짓 양성률은 10/80 = 12.5%, 모든 조회 중 거짓 양성 비중은 10/100 = 10%, 양성 중 실제 있는 비율은 20/30이다. 같은 10을 써도 분모가 다르다.

필터의 없음 판정은 그 필터가 요약한 정확한 집합·같은 해시·정상 비트라는 조건에서만 쓴다. 자체 파일 세대 V1은 A만 있고 필터도 A를 요약한다. 파일을 V2의 A,B로 바꿨는데 V1 필터를 붙여 B 조회에서 0비트를 보면 실제 B를 잘못 배제할 수 있다. V1 필터의 정상적인 없음이 V2 파일에 대한 정상 판정은 아니다. 생성한 파일과 필터 세대를 함께 검사한다.

바이트 비용의 별도 모형은 논리 쓰기 1000B, WAL 1000B, 최초 SST의 압축 자료 500 + 비압축 메타 100 = 600B, 병합 출력의 압축 자료 1000 + 메타 200 = 1200B다. 기간 중 새로 기록한 바이트는 WAL 포함 2800으로 쓰기 증폭 2.8, 제외 1800으로 1.8이다. 병합 출력을 설치하기 전 모든 세 파일을 유지하면 공존 공간도 2800B지만 이는 특정 시점의 공간이며 누적 쓰기와 다른 양이다. 이전 SST 600을 회수하고 WAL은 유지하면 공간은 2200B로 줄어도 과거 누적 쓰기 2800은 줄지 않는다.

바이트 압축과 버전 정리는 다른 일

바이트 압축은 데이터 표현을 더 적은 바이트로 저장하는 기법이다. compaction은 파일·버전을 병합해 구조를 정리하는 작업이다. 옛 기록을 남긴 채 압축만 할 수 있고 파일을 병합해도 바이트 압축을 쓰지 않을 수 있다.

RocksDB SST에서는 데이터와 인덱스 블록에 압축을 적용할 수 있으며 필터 블록은 압축하지 않는다. 압축은 공간과 I/O를 줄일 수 있지만 압축·복원에 CPU 비용이 든다. 아래 압축 크기는 주어진 가상 수치이며 실제 파일을 압축해서 얻은 측정값이 아니다.

없는 키를 먼저 배제하는 비트 배열

표준 Bloom filter는 처음0인 배열에 삽입할 키의 여러 해시 위치를1로 만든다. 조회 시 같은 위치 중 하나라도0이면 그 집합에 없다고 말할 수 있다. 모두1이면 있을 수 있다는 뜻이며 원래 데이터에서 다시 확인한다.

정상적으로 삽입한 집합·같은 해시·비트 손상 없음이라는 조건에서 거짓 음성은 없다. 서로 다른 키가 비트를 공유해 거짓 양성은 생긴다. 기본 필터에서 삭제하려고 한 비트를0으로 만들면 다른 키가 공유한 표시도 지워질 수 있다. SST를 병합할 때는 새 집합에 맞는 필터를 다시 만드는 방식도 사용된다.

증폭은 무엇을 얼마나 세는가

쓰기 증폭은 정한 기간·계층에서 기록한 바이트를 애플리케이션 논리 쓰기 바이트로 나눈 값으로 정의할 수 있다. WAL을 포함하는지, 압축 전후인지, 장치 내부 쓰기를 세는지 반드시 적는다. 정의가 다른 숫자를 그대로 비교하면 안 된다.

공간 증폭은 정한 시점의 물리 공간을 필요한 논리 데이터 크기로 나눌 수 있다. 읽기 증폭도 후보 파일·실제 데이터 블록·바이트 등 측정 단위를 정해야 한다. 아래는 작은 후보 파일과 바이트 모델을 선언한다. Bloom filter가 줄이는 것은 불필요한 후보 데이터 확인이며 실제 키의 존재 여부를 대신 결정하지 않는다.

8비트 배열의 위치는0~7이다. 자체 고정 해시 표에서 A는{1,4}, B는{4,6}, 없는 키 C는{1,6}, 없는 키 D는{2,4}에 대응한다. A/B만 넣고 네 키를 검사하라. 한편 논리 쓰기1000바이트, WAL1000, 최초SST1000, 병합출력2000이면 WAL 포함·제외 쓰기 증폭은?

누적 쓰기와 회수 뒤의 현재 공간

없는 키의 조회 80회 중 양성이 20회로 늘었다. 있는 키의 조회 20회는 여전히 모두 양성이다. 거짓 양성률과 전체 양성 수는 얼마인가?

힌트 1

거짓 양성률의 분모인 없는 키의 조회는 여전히 80회다.

힌트 2

전체 양성 수에는 있는 키의 양성 20회와 없는 키의 양성 20회를 더한다.

풀이와 답 확인

  1. 거짓 양성률은 20/80 = 25%다.

  2. 전체 양성은 40회다.

거짓 양성률은 25%, 전체 양성은 40회다. 양성 중 실제 키가 있는 비율은 20/40 = 50%다.

힌트 1

풀이와 답 확인

힌트 1

  2. WAL을 제외한 쓰기는 600 + 1200 = 1800바이트이므로 증폭은 1800/1000 = 1.8이다.

여섯 기록 A1(seq1), B2(seq2), A3(seq3), delete B(seq4), C4(seq5), A5(seq6)은 각각 20바이트다. seq2·seq4 스냅샷과 현재를 지원할 보존 기록, 출력 크기, 원본과 공존하는 공간을 구하라. seq2만 해제한 경우에는 과거 독자가 있으면 최신 삭제 표식을 유지하는 이 소단원의 보수적 정책을 적용하라. 별도 부분 병합에서 F1은 A9(seq5)와 B 삭제(seq6), F2는 A2(seq1), B3(seq2), C4(seq3), D5(seq4)다. 병합 밖 F3의 B1(seq0)이 남으면 B 표식을 버려도 되는가? 조회 100회 중 실제 있음 20회, 없음 80회이고, 필터의 참 양성 20회·거짓 양성 10회·참 음성 70회일 때 거짓 양성률을 구하라. 논리 쓰기 1000바이트에 대해 WAL 1000, 최초 SST 600, 병합 출력 1200바이트를 새로 쓴 뒤 옛 SST만 회수했다. 풀이와 답 확인

  1. 두 스냅샷과 현재에는 A seq1/3/6, B 값 seq2와 삭제 seq4, C seq5의 여섯 기록이 필요하다. 출력은 120바이트, 원본과 공존하는 공간은 240바이트다.

  2. seq2만 해제하면 명시한 보수적 정책에 따라 A seq3/6, B 삭제 seq4, C seq5의 네 기록을 남긴다. 출력은 80바이트, 공존 공간은 200바이트다. 이는 가능한 최소 보존량이라는 주장이 아니다.

  3. 부분 병합 밖 F3의 B seq0이 남으므로 B 삭제 표식을 보존해야 현재 조회에서 옛 값이 부활하지 않는다.

  4. 거짓 양성률은 실제 없는 키의 조회 80회를 분모로 한 10/80 = 12.5%다. 10/100은 전체 조회 중 거짓 양성 비중이다.

  5. 기간의 쓰기 증폭은 WAL 포함 2800/1000 = 2.8, 제외 1800/1000 = 1.8이다. 회수 뒤 공간은 1000 + 1200 = 2200바이트이며 누적 쓰기 2800바이트와 구별한다.
