소단원 2.1

HDD 탐색·회전·전송

작은 파일을 읽는 시간은 왜 바이트 수에만 비례하지 않을까?

준비 개념과 학습 목표

준비 개념

  • HDD는 회전하는 자성 표면에서 데이터를 읽고 쓰는 장치다. 헤드는 필요한 트랙 위치로 이동하고 필요한 구간이 지나올 때 데이터를 전송한다.

  • RPM은 분당 회전 수다. 1분=60초, 1초=1000ms다. 이 단원은 kB=1000바이트, MB=1000000바이트로 정한다.

  • 서비스 시간은 요청 처리를 시작한 뒤 완료할 때까지의 모형 값이고 큐 대기 시간은 시작 전 기다림이다. 둘을 합친 응답 시간과 구별한다.

학습 목표

  • 탐색·회전 대기·전송 항을 구별한다.

  • 회전 주기와 균일 위상 가정의 평균 회전 대기를 계산한다.

  • 장치 서비스 모형의 적용 조건과 실측 범위를 설명한다.

평균 10ms면 열 번 중 아홉 번도 10ms 안에 끝날까?

앞 본문의 자체 HDD는 탐색 4ms, 100kB 전송 1ms, 회전 주기 10ms다. 탐색 뒤 남은 회전 대기 W를 [0,10)ms의 균일 분포로 정하면 서비스 시간 T는 5 + W다. 평균 T는 10ms지만 T가 10ms 이하일 확률은 1/2이다. 평균은 모든 요청이나 높은 비율의 요청에 대한 완료 기한이 아니다.

이 분포에서 90% 분위수는 14ms다. W가 9ms 이하일 확률이 0.9이기 때문이다. 95% 분위수는 14.5ms다. 별도 조건으로 큐 대기가 항상 7ms 추가되면 응답 시간은 12 + W로 평균 17ms, 90% 분위수 21ms가 된다. 가변 큐의 분위수를 단순히 평균 7ms와 더한 결과가 아니라, 고정 큐 대기라고 명시한 모형이다.

전송률만 두 배로 올리는 별도 비교에서는 전송 항이 1ms에서 0.5ms가 된다. 서비스 시간은 4.5 + W로 평균 9.5ms, 90% 분위수 13.5ms다. 평균 개선율은 (10 − 9.5)/10 = 5%다. 탐색과 회전이 남으므로 전체 시간이 절반이 되지 않는다. 제품 사양이나 실측 지연 분포를 인용한 숫자가 아니다.

1. 위치로 이동하고 필요한 구간을 기다린다

HDD의 탐색은 헤드를 목표 트랙에 위치시키는 이동이다. 회전 대기는 목표 구간이 헤드 아래로 올 때까지 기다리는 일이다. 전송은 실제 데이터가 읽히거나 쓰이는 과정이다. 세 항은 서로 다른 원인으로 발생한다. 회전이 빠르다는 조건만으로 탐색 시간까지 정해지지는 않는다.

자체 요청 모형은 캐시 미적중, 단일 요청, 작업 시작 시 큐 대기 없음, 오류·재시도 없음으로 둔다. 서비스 시간을 T=s+r+L/v로 정의한다. s는 탐색 시간, r은 탐색 뒤 남은 회전 대기, L은 전송 바이트, v>0는 바이트/s 전송률이다. 실제 제어기·파일시스템·인터페이스 비용은 제외한다.

2. 평균에는 확률 가정이 필요하다

회전율 ω RPM이면 한 바퀴의 주기는 P=60/ω초다. 탐색을 마친 뒤 목표 구간까지의 회전 위상이 균일하고 독립적으로 분포한다는 단순 가정에서 남은 대기 W는 [0,P)에서 균일하므로 E[W]=P/2다. 이것은 모든 한 요청의 회전 대기가 정확히 반바퀴라는 말이 아니다.

가상 6000RPM이면 초당 100회전, P=0.01s=10ms, 평균 회전 대기는 5ms다. 이미 목표 구간에 맞으면 대기는 작을 수 있고 막 지나갔다면 거의 10ms다. 실제 스케줄러가 요청을 재배열하거나 위상이 관련되면 이 균일 평균을 다시 검토해야 한다.

3. 크기 증가와 응답 시간의 경계를 본다

고정 s+r가 크면 작은 읽기에서 전송 시간보다 위치 대기 비용이 우세하다. 가상 s=4ms, 평균 r=5ms, v=100MB/s, L=100kB라면 본문 전송은 1ms여서 평균 서비스 시간은 10ms다. 이 수치들은 사양을 인용한 값이 아니라 학습을 위해 정한 가정이다.

큐에 다른 요청이 있으면 사용자 응답에는 큐 대기도 추가된다. 캐시에서 답을 얻으면 이 장치 경로 자체를 거치지 않을 수 있다. 따라서 “파일 읽기 한 번은 항상 10ms”라는 결론은 성립하지 않는다. 전송 성공의 관측으로 전원 장애 이후 쓰기 내구성까지 추론해서도 안 된다.

중간 과정을 따라가는 예제

가상 HDD는 6000RPM, 각 요청 탐색 시간 4ms, 남은 회전 위상 균일, 전송률 100MB/s다. 캐시 미적중의 100kB 읽기 하나, 큐 대기·오류·제어기 비용 없음. 평균 서비스 시간을 구하라.

  1. 6000RPM/60=100회전/s이므로 P=1/100s=10ms다.

  2. 균일 위상 가정에서 평균 회전 대기는 P/2=5ms다.

  3. 100kB=100000바이트, 100MB/s=100000000바이트/s이므로 L/v=0.001s=1ms다.

  4. 평균 서비스 시간은 4+5+1=10ms다. 탐색 시간은 상수, 회전은 평균이므로 결과도 평균값이다.

가정한 평균 서비스 시간은 10ms다. 실제 디스크·파일 읽기 지연의 측정값이나 최악 응답 보장은 아니다.

준비 개념과 학습 목표

준비 개념

  • 플래시 페이지는 이 단원의 작은 읽기·프로그램 단위이고 지우기 블록은 여러 페이지를 함께 지우는 더 큰 단위다. DB 페이지·OS 메모리 페이지와 자동으로 같은 크기나 같은 대상이 아니다.

  • 논리 주소는 사용자가 요청한 위치, 물리 페이지는 장치 내부 저장 위치다. 매핑 표 M은 논리 주소를 현재 유효한 물리 페이지에 연결한다.

  • 유효 live 페이지는 현재 논리 데이터로 참조되며 낡은 obsolete 페이지는 이미 새 버전으로 대체되었다. 물리 내용이 남아 있어도 현재 값이라는 뜻은 아니다.

학습 목표

  • 페이지 프로그램과 블록 지우기의 범위를 구별한다.

  • 새 위치 갱신·매핑 변경·낡은 페이지를 추적한다.

  • 수집의 live 이동과 쓰기 증폭을 조건에 맞게 계산한다.

서로 다른 구간의 쓰기 증폭을 단순 평균해도 될까?

자체 동일 크기 페이지 모형에서 구간 A의 호스트 쓰기는 1페이지, 물리 프로그램은 3페이지다. 구간 B의 호스트 쓰기는 9페이지, 물리 프로그램은 9페이지다. 각 비율은 3과 1이지만 두 구간을 합친 비율은 (3 + 9)/(1 + 9) = 1.2다. 비율의 단순 평균 2와 다르다. 분모인 호스트 바이트를 기준으로 합산해야 한다.

별도 4페이지 블록 K에는 live 1페이지와 obsolete 3페이지가 있다. 외부의 지워진 페이지가 하나 있고 모든 이동·매핑 갱신이 성공한다고 정한다. live를 그 외부 페이지에 한 번 프로그램한 뒤 K를 지우면 K의 네 페이지는 지워진 상태가 된다. 하지만 외부 빈 페이지 하나를 소비했으므로 전체 지워진 페이지 수의 순증가는 3이다. 지운 블록의 크기 4와 전체 여유의 증가량 3을 구별한다.

관측 구간에 호스트 쓰기가 없고 수집 이동 프로그램만 1페이지 있다면 물리 작업은 존재하지만 쓰기 증폭 비율의 분모는 0이다. 이 비율을 0이나 1로 임의 기록하지 않는다. 프로그램 바이트·수집 이동·블록 지우기를 별도 장부로 남긴다. 매핑 메타데이터 쓰기·압축·중복 제거·실패·장애는 이 모형에 포함하지 않는다.

1. 읽기·프로그램·지우기를 나눈다

교육용 플래시 모형은 지워진 페이지에 프로그램하고, 이미 프로그램된 내용을 새 값으로 바꾸려면 관련 지우기 블록의 재사용 절차가 필요하다고 정한다. 블록을 지우면 그 안의 모든 페이지 내용이 사라진다. 특정 장치의 제한적 추가 프로그램 규칙 등은 별도 사양이 필요하며 이 단순 모형에 포함하지 않는다.

종이 블록은 페이지 4개로 매우 작게 정한다. 이런 크기는 원리를 보려는 가상 값이다. 다른 live 페이지가 있는 블록을 즉시 지우면 그 데이터도 잃는다. 따라서 다른 유효 데이터를 보존할 위치를 먼저 마련하거나 새로운 페이지에 변경값을 써야 한다.

2. FTL은 논리 위치와 물리 위치를 연결한다

FTL은 호스트의 논리 읽기·쓰기를 내부 플래시 작업으로 연결한다. 자체 모형에서는 logical X의 새 값을 비어 있는 물리 p2에 프로그램한 뒤 M(X)=p2로 바꾸며 이전 p0는 obsolete가 된다. 사용자에게 X의 최신 값은 매핑을 따라 찾는다. 물리 p0에 옛 값이 남아 있어도 최신 데이터가 아니다.

아래 추적은 각 프로그램 성공, 매핑 표 갱신 정상, 동시 접근·전원 손실 없음으로 한정한다. 새 데이터 쓰기와 매핑의 장애 복구·원자성이 실제 장치에서 보장되는지는 별도의 설계와 계약이다. 메모리 속 매핑만 바뀌었다는 그림으로 전원 장애 내구성을 증명하지 않는다.

3. 공간 수집은 아직 필요한 값을 이동한다

지우기 블록을 재사용할 때는 그 안의 live 페이지를 다른 준비된 공간으로 옮기고 매핑을 고친 뒤 블록을 지운다. 이 모형에서는 복사 완료 전에 지우면 보존해야 할 값을 잃는다. 낡은 페이지는 이동하지 않아도 되지만 어떤 페이지가 live인지 판단할 매핑·메타데이터가 정확해야 한다.

쓰기 증폭을 같은 관측 구간의 물리 프로그램 바이트/호스트 쓰기 바이트로 정의한다. 분모는 양수여야 하며 수집으로 옮긴 바이트도 분자에 센다. 아래는 모든 페이지 길이가 같고 매핑 메타데이터 쓰기 등은 제외한다. 지우기 횟수는 프로그램 바이트 수와 다른 지표이며 실제 제품의 쓰기 증폭이나 수명을 측정한 값이 아니다.

중간 과정을 따라가는 예제

가상 블록 K의 p0=X옛값, p1=Y현재값, p2,p3=지워진 빈 페이지다. 다른 블록의 q0도 지워져 있다. 처음 M(X)=p0,M(Y)=p1. 페이지 크기는 동일 B>0바이트. X 새값을 한 번 쓰고 K를 회수한다. q0가 Y 이동용이며 모든 작업 정상, 메타데이터·전원손실은 제외한다.

  1. X 새값을 p2에 프로그램하고 M(X)=p2로 바꾼다. p0는 낡았지만 p1과 p2는 현재 매핑에 쓰이는 live다.

  2. K를 지우려면 Y와 X 모두를 밖으로 옮겨야 한다. q0 하나만으로는 두 live 페이지를 보존할 공간이 부족하다. 즉시 지우지 않는다.

  3. 회수를 가능하게 하려고 다른 지워진 q1도 확보한다고 조건을 추가한다. p1의 Y를 q0로, p2의 X를 q1로 각각 프로그램하고 M(Y)=q0, M(X)=q1로 바꾼다.

  4. 모든 live 매핑이 K 밖으로 옮겨진 뒤 K를 지운다. 관측 구간에서 호스트는 X 한 페이지 B바이트를 썼고 물리 프로그램은 p2,q0,q1의 3B바이트다.

추가 q1 없이는 명시한 회수 절차를 완료할 수 없다. 확보 후 데이터 보존 회수의 쓰기 증폭은 3B/B=3이다. 지우기 한 번의 비용은 이 바이트 비율에 직접 포함하지 않았다.

소단원 2.3

순차·임의 접근 비교

같은 양의 자료를 읽어도 요청 순서와 묶음 크기가 시간을 바꾸는 이유는?

준비 개념과 학습 목표

준비 개념

  • 순차 접근은 이 모형에서 연속된 저장 구간을 순서대로 읽는 접근이고 임의 접근은 떨어진 구간을 독립적으로 선택하는 접근이다. 논리적 연속과 장치의 물리적 연속이 항상 같지는 않다.

  • 캐시 적중은 필요한 데이터가 상위 저장 공간에 이미 있는 경우다. 냉간 조건은 이 단원에서 필요한 데이터가 캐시에 처음부터 없다는 가정이다.

  • 처리율은 완료 바이트 수/경과 시간이고 요청 지연은 한 요청의 완료까지 시간이다. 같은 숫자로 대체할 수 없다.

학습 목표

  • 같은 총 바이트·캐시·동시성 조건으로 접근 비용을 비교한다.

  • 요청 고정 비용과 전송 비용을 구분하여 합산한다.

  • 병합·재정렬의 성능 이득과 의미 보존 조건을 설명한다.

빈 구간까지 읽어 요청을 합치면 언제 이득일까?

자체 직렬 냉간 읽기 모형에서 독립 요청 하나의 고정 비용 H는 5ms이고 전송률은 100MB/s다. MB는 십진 백만 바이트다. 필요한 두 구간은 각각 1MB이고 사이에 필요 없는 간격 G가 있다. 따로 읽으면 고정 비용 두 번과 필요한 2MB 전송으로 10 + 20 = 30ms다.

두 구간을 하나로 합쳐 사이 간격까지 읽으면 고정 비용은 한 번이지만 전송량은 2 + G MB다. 시간은 5 + 10(2 + G) = 25 + 10G ms다. G가 0.2MB이면 27ms로 3ms 짧고 G가 1MB이면 35ms로 5ms 길다. 요청 수를 줄이는 것만으로 이득을 결론짓지 않는다. 이득 조건은 G < 0.5MB이며 같으면 30ms로 동률이다.

일괄 처리를 기다리는 시간도 사용자 응답에 포함한다. 첫 구간 요청이 시각 0ms, 둘째 요청이 8ms에 도착하고 그때 병합 처리를 시작한다고 하자. G = 0.2MB의 서비스는 27ms라 둘 다 시각 35ms에 결과를 받는다. 첫 요청 응답은 35ms, 둘째는 27ms다. 별도 요청은 도착 순서 직렬 처리하고 각 서비스가 15ms이면 첫 완료 15ms, 둘째 완료 30ms라 응답은 15ms와 22ms다. 병합의 서비스 절감이 각 요청의 응답 개선을 보장하지 않는다. 데이터는 변경 없는 독립 읽기이며 실제 제어기·병렬·캐시는 제외한다.

1. 공정한 비교의 입력을 정한다

접근 방식 비교에는 총 데이터량, 블록 크기, 캐시 상태, 큐 깊이와 요청 의존성을 함께 적는다. 장치 종류 이름만으로 모든 읽기·쓰기 패턴의 비용 관계가 정해지지 않는다. 데이터가 캐시에서 나온 경우를 장치에서 읽는 경우와 혼합하면 측정 대상도 달라진다.

아래는 냉간 읽기, 요청 동시성 없음, 오류·쓰기·추가 캐시·미리 읽기 없음인 가상 모형이다. 총 데이터는8MB이고 전송률v=100MB/s, 각 독립 요청의 고정 위치 비용 H=5ms다. 단위는 십진MB이고 요청을 하나로 병합하면 고정 비용을 한 번만 낸다고 명시한다.

2. 전송량과 고정 비용을 따로 더한다

연속 8MB를 한 요청으로 읽으면 고정 비용 5ms와 전송 80ms를 더해 85ms다. 같은 총량을 1MB씩 떨어진 8곳에서 각각 읽으면 요청마다 고정 비용을 내어 40ms+80ms=120ms다. 바이트 수가 같아도 요청 고정 비용 수는 다르다.

순차 8MB 한 요청의 처리율은 8MB/0.085s≈94.12MB/s, 임의 8요청 전체의 처리율은 8MB/0.120s≈66.67MB/s다. 이는 가상 전체 작업 처리율이며 장치 최대 전송률 100MB/s와 다르다. 요청을 동시에 발행하거나 제어기가 재정렬하면 이 직렬 합은 달라질 수 있다.

3. 재정렬은 업무 의미 조건을 지켜야 한다

독립된 읽기 요청이라도 바이트 결과와 원래 요청의 대응을 기억해야 한다. 변경 없는 자료를 읽고 결과를 원래 순서에 돌려놓는 모형에서는 물리 읽기 순서를 바꿔도 사용자 결과를 보존할 수 있다. 동시 쓰기나 시간 의존 조회가 있으면 같은 논증을 자동 적용하지 않는다.

작은 임의 읽기가 캐시에 모두 적중하고 큰 순차 읽기가 장치를 거치면 실제 관측 시간의 대소가 뒤집힐 수 있다. 따라서 “순차는 언제나 빠르다”라는 보편 명제 대신 비교 조건을 적는다. 읽기 성능 이득에서 쓰기 순서·트랜잭션 원자성·장애 후 내구성을 추론하지 않는다.

중간 과정을 따라가는 예제

냉간 읽기 총 8MB, v=100MB/s, H=5ms. 비교 A는 연속 8MB 단일 요청, B는 떨어진 1MB 8개를 직렬 요청한다. 제어기 병렬·캐시·오류·추가 비용은 없다.

  1. 총 전송 시간은 8/100s=0.08s=80ms로 두 방식이 같다.

  2. A는 고정 비용 한 번이므로 5+80=85ms다.

  3. B는 고정 비용 8번이므로 8·5+80=120ms다. 차이는 35ms다.

  4. 전체 처리율은 A의 8/0.085≈94.12MB/s, B의 8/0.120≈66.67MB/s다. 요청 크기·개수와 직렬 조건을 함께 기록한다.

이 모형에서 A가 35ms 짧다. 실제 장치 벤치마크 결과나 모든 임의 접근에 대한 보편 보장은 아니다.
