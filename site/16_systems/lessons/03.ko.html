소단원 3.1

IEEE 754 표현

32개의 비트로 아주 작은 수와 큰 수를 함께 어떻게 적을까?

준비 개념과 학습 목표

준비 개념

  • 이진 소수 0.101₂는 1/2+1/8이다. 2의 정수 거듭제곱을 곱하면 소수점 위치가 이동한다.

  • 유효숫자 significand는 숫자의 세부 자릿값을 담고 지수는 크기 범위를 정한다. 부호 비트 s는 0이면 양, 1이면 음이다.

  • 16진수 한 자리는 4비트다. 여기의 8자리 hex는 32비트 패턴의 큰 자릿수부터 쓴 표기이며 메모리 바이트 순서와 별개다.

학습 목표

  • binary32의 정상·subnormal을 식으로 해석한다.

  • 특수값 분기를 구분한다.

  • 비트 패턴과 수치 비교를 혼동하지 않는다.

최소 정상수 바로 아래의 값도 같은 간격으로 이어질까?

binary32의 작은 양수 격자를 q=2^−149라는 단위로 읽어 보자. 지수 필드 e=0인 양수는 Fq이며 F=1부터 2^23−1까지다. 최소 정상수는 2^−126=2^23q다. 따라서 최대 subnormal (2^23−1)q와 최소 정상수 2^23q 사이에도 차이는 q다. 식이 바뀌는 경계에서 값이 크게 뛰는 것은 아니다.

그러나 고정 간격 q가 상대 오차도 같은 비율로 묶어 주는 것은 아니다. 양수 정확한 대상 q/2를 nearest ties-to-even으로 binary32에 반올림하면 0과 q의 중간이며 짝수 격자 계수 0을 선택한다. 절대 오차는 q/2지만 원래 q/2에 대한 상대 오차는 1이다. 정상수에서 쓰는 작은 상대 오차 모형을 이 작은 값에 그대로 적용하지 않는다.

여기서는 subnormal을 유지하는 명시적 저장·반올림 모형이며 실제 환경의 flush-to-zero 설정이나 모든 IEEE 적합성을 시험하지 않았다. 32비트 hex 표기는 큰 자릿수부터 쓰는 숫자 그림이며 메모리 주소순 바이트와 다르다. v1의 선택 struct 실행 기록은 보존하지만 이번 보강에서는 새 패킹이나 장치 측정을 하지 않았다.

먼저 확인할 개념
  • 정상·subnormal 필드 해석

    e=0에서 숨은 비트 0과 최소 정상수의 식을 사용한다.

  • 격자 중간값과 마지막 비트

    nearest ties-to-even의 격자 계수로 작은 값의 선택을 판정한다.

세 필드의 역할

여기서는 IEEE 754 binary32 저장 형식을 고정한다. 부호 s는 1비트, 저장 지수 e는 8비트, fraction 정수 F는 23비트이며 s∈{0,1}, e,F는 정수이며 0≤e≤255, 0≤F<2^23이다. 정상수 조건 1≤e≤254에서 값은 (−1)^s(1+F/2^23)2^(e−127)이다. 앞의 1은 저장하지 않지만 유효숫자의 일부다.

예를 들어 6.5=110.1₂=1.101₂×2²다. 23개의 fraction 칸에 101 뒤 0을 붙이면 정확히 들어간다. bias 127을 더해 저장 지수는 129다. 음수에서는 s만 1로 바꾼다. 실제 C float가 반드시 이 형식이라는 가정은 언어 규칙만으로 할 수 없으므로 자료형과 환경을 따로 확인한다.

정상 공식 밖의 값

e=0에서는 숨은 앞 비트가 0이고 값은 (−1)^s(F/2^23)2^−126이다. F>0이면 subnormal, F=0이면 signed zero다. e=255에서는 F=0이 부호 있는 무한대이고 F≠0이 NaN이다. 특수값을 정상식에 대입해 큰 유한수라고 해석하면 틀린다.

NaN은 수치 비교에서 자기 자신과도 같지 않다. +0과 −0은 일반 수치 동등 비교에서는 같지만 비트 패턴과 부호 정보를 읽는 연산에서는 구분된다. 언어의 예외 처리도 별도다. Python에서 1.0/0.0을 실행하면 보통 ZeroDivisionError이므로 IEEE 형식의 infinity가 있다는 사실만으로 해당 식이 infinity를 반환한다고 말할 수 없다.

격자와 표현 범위

최소 양의 subnormal은 F=1에서 2^−149, 최소 양의 정상수는 e=1,F=0에서 2^−126이다. 최대 유한 양수는 e=254,F=2^23−1에서 (2−2^−23)2^127이다. 0 근처에서는 subnormal의 일정한 간격이 정상수 범위와 0 사이를 이어 준다.

정상 유효숫자는 숨은 1을 포함해 24비트이며 binary64는 53비트다. 정밀도와 크기 범위는 다른 개념이다. 크기가 커지면 인접한 정상수 간격도 커지므로 표현 범위 안의 모든 정수나 실수가 정확하다는 뜻은 아니다. 이 공식과 선택 패턴을 종이로 계산하고 struct의 지정 패킹으로 대조했다.

중간 과정을 따라가는 예제

−6.5를 binary32로 정확히 표현하고 32비트 hex 패턴을 구한다.

  1. 6.5=1.101₂×2²이므로 부호 s=1이다.

  2. 저장 지수 e=2+127=129=10000001₂다.

  3. fraction은 101 뒤 20개의 0이므로 F=0x500000이다.

  4. (s<<31)|(e<<23)|F를 합치면 0xC0D00000이다. 저장 순서가 지정된 struct >f 결과도 c0d00000이었다.

정확한 값 −6.5의 패턴은 0xC0D00000이다. 이는 바이트 순서를 지정한 표시이며 모든 기계의 메모리 순서를 주장하지 않는다.

조건을 바꾸어 비교하기

공식 변경과 값 연속 연결

007FFFFF와 00800000의 값 차이를 q 단위로 구하라.

  1. 최대 subnormal은 (2^23−1)q다.

  2. 최소 정상수는 2^23q다.

차이는 q다. 숨은 1이 생겨도 이 경계의 한 칸은 이어진다.

비교할 점

두 분기의 공식을 같은 단위로 비교한다.

작은 절대 오차와 큰 상대 오차

정확한 대상 q/2를 nearest ties-to-even으로 저장할 때 오차를 구하라.

  1. 후보 0과 q까지 거리는 각각 q/2다.

  2. 짝수 격자 계수 0으로 보내면 저장값은 0이다.

절대 오차 q/2, 상대 오차 1이다.

비교할 점

작은 절대 단위가 모든 크기의 작은 상대 오차를 보장하지 않는다.

종이와 본문으로 직접 해보기

종이에 s=1,e=0,F=0인 패턴과 s=0,e=0,F=1인 패턴을 해석한다. 두 수를 정상 공식으로 읽으면 왜 안 되는지도 쓴다.

힌트 보기

e=0 분기에 숨은 앞 비트는 0이다.

풀이 보기

첫 값은 −0이고 패턴 0x80000000이다. 두 번째는 최소 양의 subnormal 2^−149로 패턴 0x00000001이다. 정상식의 숨은 1을 쓰면 0을 나타내지 못한다.

오해와 반례

비트가 다르면 수치 비교에서도 반드시 다른 값이다.

+0과 −0의 패턴은 다르지만 == 비교에서는 같다. 반대로 NaN은 동일 패턴을 가진 두 값도 일반 ==로 같다고 판단되지 않는다.

한 단계 더

e=1 정상수의 최솟값은 2^−126이다. 바로 아래 최대 subnormal은 (1−2^−23)2^−126이므로 두 값의 차이는 2^−149다. 이는 subnormal 격자가 최소 정상수에 같은 한 칸 간격으로 연결된다는 증명이다. 일반 정상 구간 [2^E,2^(E+1))의 간격은 2^(E−23)이다. binade 경계에서는 아래쪽 간격과 위쪽 간격이 다를 수 있으므로 한 전역 절대 오차 간격을 가정하면 안 된다.

반올림과 비결합성

같은 세 수를 더했는데 괄호 하나로 결과가 달라질 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 반올림은 정확한 수를 표현 가능한 격자점으로 보내는 규칙이다. nearest ties-to-even은 가장 가까운 값을 고르고 중간이면 저장 유효숫자의 마지막 비트가 0인 쪽을 고른다.

  • ulp는 해당 크기에서 인접 표현값 사이의 간격을 가리키는 척도다. 지수 구간이나 경계의 어느 방향을 보는지 함께 정해야 한다.

  • 실수 덧셈의 결합법칙은 (a+b)+c=a+(b+c)다. 컴퓨터 식에는 중간 반올림이 추가된다.

학습 목표

  • 중간값 반올림을 직접 계산한다.

  • 비결합 반례의 각 단계를 추적한다.

  • 표시 오차·입력 오차·연산 오차를 구분한다.

작은 증가를 두 번 더하는 것과 먼저 묶는 것은 같을까?

a=2^24인 binary32 값을 놓고 각 덧셈 직후 nearest ties-to-even으로 저장하는 모형을 정한다. a 위의 간격은 2다. 첫 a+1은 중간값이어서 a로 돌아간다. 이 저장값에 다시 1을 더해도 같은 중간값이므로 또 a다. 입력 1은 정확하지만 반복 저장에서 두 번 모두 사라진다.

작은 값 둘을 먼저 더하면 1+1=2는 정확하며 a+2도 격자점이다. 따라서 순차 ((a+1)+1)은 a, 묶은 a+(1+1)은 a+2다. 이는 구현의 실제 최적화 관찰이 아니라 지정한 반올림 경계의 손모형이다. Python float의 일반 덧셈이 자동 binary32라는 주장도 하지 않는다.

한 번의 마지막 변환과 여러 중간 변환이 다른 것처럼, 결과 표시 자릿수와 허용 오차도 별도 계약이다. 절대 오차 기준 |x−y|≤1은 가까움 판정에 쓸 수 있지만 추이적 동등 관계가 아니다. 0과 0.75, 0.75와 1.5는 각각 가까워도 0과 1.5는 그 기준 밖이다. 이를 ID 묶음의 무조건적인 같음 규칙으로 사용하면 모순이 생긴다.

명시한 산술 모형

이번 예제는 binary64, 정밀도 p=53, 각 덧셈 직후 nearest ties-to-even 반올림을 가정한다. 추가 정밀도나 식 재결합을 사용하지 않는다. 2^53부터 다음 지수 구간까지 인접 수 간격은 2이므로 2^53+1은 양쪽 표현값의 정확한 중간이다.

중간에서 짝수라는 말은 십진 정수 전체가 짝수라는 뜻이 아니다. 2^53과 2^53+2는 모두 짝수지만 그 구간 유효숫자의 정수 계수는 각각 2^52와 2^52+1이다. 앞의 마지막 비트가 0이므로 2^53+1은 2^53으로 간다. 2^53+3은 반대로 2^53+4로 간다.

괄호의 반례

a=2^53, b=1, c=−2^53은 모두 정확히 표현된다. 왼쪽 묶음은 fl(a+b)=a가 된 뒤 fl(a+c)=0이다. 오른쪽 묶음은 b+c=−(2^53−1)이 정확한 표현값이고 여기에 a를 더하면 1이다. 입력은 같아도 첫 반올림에서 잃은 1을 이후 연산이 되찾지 못한다.

수학적으로 합은 1이다. 이 반례는 지정한 단계별 반올림 모형과 관측한 Python 실행에 대한 것이다. C 컴파일러의 허용된 추가 정밀도, fast-math 또는 재결합 설정에 따라 같은 텍스트 식의 실행 경계가 달라질 수 있다. 실제 C 컴파일러 실행이나 모든 최적화의 결과를 검증하지 않았다.

숫자를 보이는 방식

유한 이진분수는 정수/2^k 형태이므로 1/10의 기약분모 10에는 5가 남아 정확히 표현할 수 없다. 관측한 binary64의 0.1은 3602879701896397/2^55이고 실제 저장값−1/10은 1/180143985094819840이다. 출력이 0.1이라는 짧은 문자열이라고 저장값이 정확한 1/10이 되는 것은 아니다.

오차를 줄이는 방법은 계산 목표에 맞춰 선택한다. 작은 값을 먼저 모으거나 보상 합산을 쓰면 일부 문제에서 좋아지지만 모든 입력의 정확성이 자동 보장되지는 않는다. 허용 오차 비교에는 단위와 절대·상대 허용치를 정해야 한다. 단순히 모든 ==를 느슨한 비교로 바꾸면 정확한 정수 식별자 계약까지 바꿀 수 있다.

소단원 3.3

정수·실수 변환 오류

정수를 실수로 바꿨다가 다시 정수로 바꾸면 언제 원래 값을 잃을까?

준비 개념과 학습 목표

준비 개념

  • 정수 타입의 범위와 실수 타입의 정밀도는 다르다. signed 32비트 정수 모형의 범위는 −2^31부터 2^31−1이다. C의 모든 int가 이 폭이라는 뜻은 아니다.

  • 0 방향 절단은 소수 부분을 버린다. −3.75를 절단하면 −3이고 floor처럼 −4로 내리는 것과 다르다.

  • undefined behavior는 언어가 결과를 보장하지 않는 경우다. 실제 기계에서 한 값을 관측해도 이식 가능한 결과 계약이 생기지 않는다.

학습 목표

  • 변환 방향별 전제와 오류를 구분한다.

  • 정수 round-trip 반례를 계산한다.

  • cast 전에 유한성·범위를 검사하는 충분조건을 만든다.

반올림된 정수가 배열 인덱스 검사를 바꿀 수 있을까?

정수 인덱스 n=16777217을 먼저 binary32 nearest ties-to-even으로 보냈다가 signed 32비트 정수로 돌리면 16777216이다. 길이가 정확히 16777217인 배열의 허용 인덱스 0…16777216 검사에서 원래 n은 범위 밖이지만 바뀐 값은 통과한다. 실제 배열을 할당하거나 접근하지 않는 입력 계약의 손모형이다.

입력 타입이 정수라면 인덱스의 의미와 길이 비교를 정수에서 유지하는 설계가 필요하다. 모든 큰 정수가 실패하는 것은 아니다. n=16777218은 이 구간의 간격 2에 맞아 정확히 들어간다. 연속 구간의 모든 정수 보장과 특정 큰 정수의 정확성은 다른 질문이다.

실수 입력을 정수로 보내는 문제에는 유한성·0 방향 절단·대상 범위를 확인한다. signed 32비트와 binary64 검사 가정에서 −2^31≤x<2^31은 안전한 충분조건이지만 −2^31−0.5의 절단 결과는 −2^31이어서 안전한 값도 거절한다. 정확한 유한 실수 영역에서 필요한 절단 범위는 −2^31−1<x<2^31이며 왼쪽은 엄격한 경계다. 이 넓은 허용 영역을 실제 더 낮은 정밀도 검사에 무조건 복사하지 않는다.

정수에서 실수로

정수→binary32 nearest ties-to-even 환경을 고정하면 2^24+1=16777217은 표현되지 않아 16777216이 된다. 다시 충분한 범위의 정수로 절단해도 16777216이므로 원래 값보다 1 작다. overflow가 없어도 정밀도 손실로 round-trip이 실패한다.

C11 핵심 규칙은 정확히 표현 가능하면 값을 유지하고, 범위 안이지만 부정확하면 가장 가까운 위 또는 아래 표현값 중 구현이 정의한 쪽을 허용한다. 그래서 ties-to-even을 C의 모든 구현에 자동 적용하지 않는다. C 타입, IEEE 추가 계약과 현재 rounding 환경을 확인해야 위 예제의 특정 방향을 주장할 수 있다.

실수에서 정수로

C에서 유한 실수를 _Bool 외 정수 타입으로 변환할 때는 0 방향 절단을 하고, 절단한 정수 부분이 대상 범위에 없으면 UB다. unsigned로 보낸다고 범위 밖 실수를 자동 modulo로 처리하는 것도 아니다. NaN·infinity를 정상적인 정수 변환 입력으로 허용하지 않는 계약을 사용한다.

대상이 범위 [−2^31,2^31−1]인 정확한 정수 타입이고 검사에 쓰는 실수는 binary64라 하자. isfinite(x)와 −2147483648.0≤x<2147483648.0을 검사하면 cast 안전성의 충분조건이다. 상한은 배타적이어야 한다. 이 조건은 필요한 조건 전체가 아니다. −2147483648.75는 절단 후 최솟값이지만 보수적 검사에서 거절한다.

검사 자체의 정밀도

상한 정수 2147483647을 binary32로 바꾸면 nearest 환경에서 2147483648이 될 수 있다. 그래서 x≤float(INT_MAX) 같은 검사는 한계를 둥글려 위험한 값을 통과시킬 수 있다. 비교할 타입과 정확히 표현 가능한 배타적 경계를 함께 정해야 한다.

예시 계약은 먼저 입력이 유한한지 확인하고 범위를 통과했을 때만 cast하여 성공을 반환한다. 실패에서는 결과 슬롯을 바꾸지 않는 정책을 붙일 수 있다. Python의 임의 정밀도 int와 C의 고정 범위 정수 cast는 동일하지 않다. 선택 코드의 guarded_int32는 위 계약의 Python 모형일 뿐 C UB를 실제 실행하거나 C 구현을 시험한 것이 아니다.

중간 과정을 따라가는 예제

정수 n=2^24+1을 binary32 nearest ties-to-even으로 변환한 뒤 32비트 signed 정수로 되돌린다. 별도로 binary64 입력 −3.75와 2^31의 보수적 guard 결과를 구한다.

  1. binary32에서 2^24 이상 구간 간격은 2이므로 n은 두 후보 중간이다.

  2. 짝수 유효숫자 계수의 16777216으로 반올림되며 다시 정수로 보내도 같은 값이다.

  3. −3.75는 유한하고 [−2^31,2^31) 안이므로 통과하여 −3으로 절단한다.

  4. 2^31=2147483648은 배타적 상한과 같으므로 거절하고 cast를 수행하지 않는다.

round-trip은 16777216으로 1을 잃는다. guard는 −3.75를 −3으로 변환하고 2^31을 거절한다.

한 단계 더

p비트 유효숫자를 가진 이진 형식은 지수 범위가 충분할 때 |n|≤2^p인 모든 정수를 정확히 표현한다. 정수 n의 유효 이진 자릿수가 p 이하면 직접 저장할 수 있고, 경계 2^p는 1×2^p이므로 역시 정확하다. 하지만 모든 더 큰 정수가 실패하는 것은 아니다. 2^p+2는 간격 2에 맞아 정확한 반면 2^p+1은 아니다. 따라서 범위 충분함과 실제 정밀도 충분함을 각각 증명해야 한다. C round-trip에는 최초 정수 타입과 마지막 대상 타입의 범위, 중간 실수 환경 및 실제 변환 규칙도 필요하다.

다른 문제에 적용하기

q=2^−149에서 최대 subnormal과 최소 정상수의 q 계수·간격, q/2의 nearest ties-to-even 절대/상대 오차를 구하라. a=2^24부터 1을 두 번 저장하며 더하는 경로와 작은 두 값을 먼저 묶는 경로를 비교하라. 길이 16777217의 인덱스 n=16777217을 binary32 왕복한 뒤 검사하는 문제와 binary64 입력 −2147483648.5의 보수적 guard 거절 의미를 설명하라.

힌트 1

분기 공식을 같은 q 단위로 읽고 반올림을 각 저장 경계마다 적용한다.

힌트 2

입력 정수의 계약은 근사 이전에 검사한다. 충분조건과 필요한 절단 범위를 나눈다.

풀이와 답 확인

  1. 최대 subnormal 계수는 8388607, 최소 정상수는 8388608이며 차이는 q다. q/2는 0으로 가고 절대 오차 q/2, 상대 오차 1이다.

  2. 순차 두 저장은 모두 a=16777216으로 돌아가며 작은 둘을 묶으면 a+2=16777218이다.

  3. 원래 n은 배열 길이와 같아 거절 대상인데 왕복값 16777216은 마지막 허용 인덱스다. 변환값만으로 원래 입력을 허용하지 않는다.

  4. −2147483648.5는 보수적 하한에서 거절하지만 0 방향 절단은 −2147483648로 안전하다. 원래 guard는 충분조건임을 보고하고 실제 cast/접근을 하지 않는다.

작은 값의 절대/상대 오차, 중간 저장의 정보 손실, 원래 정수의 범위 계약과 보수적 실수 guard를 각각 분리한다. 지정 모형의 계산이며 새 struct/C cast/배열 접근/실측·학생 검증은 없다.

해결한 뒤 점검할 것

  • q 계수와 분기 경계 한 칸을 계산한다.

  • q/2의 상대 오차 1을 정상 영역 상계와 혼동하지 않는다.

  • 두 덧셈 경로 및 원래 인덱스 거절을 구별한다.

  • 유한성·절단·충분조건의 한계와 미수행을 설명한다.
