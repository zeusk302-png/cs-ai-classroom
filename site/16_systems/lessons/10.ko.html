같은 재사용 흐름을 LRU와 FIFO가 다르게 기억하는가?

새 읽기 흐름의 블록 번호는 0, 1, 0, 2, 0, 1이다. 처음 빈 완전연관 캐시는 두 블록을 담고 모든 miss에서 요청 블록을 가져온다. 다른 접근과 프리페치는 없다. LRU는 hit에서도 최근 사용 순서를 갱신하지만 FIFO는 들어온 순서를 hit에서 바꾸지 않는다. 재사용을 관찰했다는 사실과 그 정보를 교체 정책이 사용하는 방법은 다르다.

세 번째 접근에서 블록 0을 다시 읽는다. LRU에는 0이 더 최근이고 1이 오래된 블록이므로 다음 2를 가져올 때 1을 버린다. FIFO에서는 먼저 들어온 0이 여전히 가장 오래된 입장이므로 0을 버린다. 캐시 용량과 주소 흐름이 같아도 다음 접근의 hit 여부가 달라진다.

표의 블록 수는 서로 다른 주소 블록의 수이지 요청 횟수가 아니다. 블록을 자주 다시 쓴다는 시간적 지역성만으로 모든 재접근이 hit라고 말할 수 없다. 이 절은 지정된 정책의 손추적이며 실제 CPU 교체 정책·실행 시간·메모리 배치를 관찰하지 않았다.

자주 쓰는 것과 가까운 것을 본다

시간적 지역성은 최근 접근한 정보를 곧 다시 사용하는 경향이다. 합계를 담은 변수를 반복해서 갱신하거나 같은 반복문 명령을 실행하는 경우가 예다. 공간적 지역성은 접근한 주소 근처를 곧 사용하는 경향이다. 배열 원소를 저장 순서대로 방문하는 경우를 생각할 수 있다.

같은 프로그램이 두 종류를 동시에 보일 수 있지만 모든 입력과 실행에서 같은 정도인 것은 아니다. 반복 사용해도 중간에 다른 데이터가 캐시를 밀어내면 재접근은 miss일 수 있다. 이 절은 숫자를 저장하는 주소 모형에서 방문 순서만 종이로 비교한다.

논리적인 표와 실제 저장 순서를 나눈다

자체4×4행렬은 원소당4바이트이며 행 우선으로 주소0부터 빈틈없이 저장한다고 정한다. 행 r,열 c의 주소는4(4r+c)다. 행 번호와 열 번호는0부터3이다. 다른 언어나 자료구조가 반드시 같은 저장 방식을 쓴다고 일반화하지 않는다.

행 우선 방문은0,4,8,12 다음16,20,24,28처럼 진행한다. 열 우선 방문은0,16,32,48 다음4,20,36,52처럼 멀리 건너뛴다. 같은16개 값과 같은 최종 합을 계산해도 메모리의 주소 순서가 다르다. 방문 순서를 바꾸어도 계산의 의미가 유지되는 조건 역시 확인해야 한다.

작업 집합이 남아 있어야 재사용된다

캐시 블록을16바이트로 정하면 한 행은 한 블록이다. 두 블록만 담는 완전 연관 읽기 캐시를 처음 비우고,빈라인 우선·가득 차면 LRU로 교체하며 프리페치와 다른 접근은 없다고 가정한다. 행 방문은 한 블록의4원소를 바로 이용하여 첫 miss 뒤3hit를 만들 수 있다.

열 방문은 네 블록을 차례로 읽어 두 블록 용량을 넘는다. 다음 열에서 같은 블록을 다시 찾아도 이미 교체되어 있을 수 있다. 이 예의 성능 차이는 방문 순서·저장 순서·블록 크기·용량·교체 정책이 함께 만든 결과다. 실제 언어 런타임이나 CPU 측정은 수행하지 않는다.

네 번째 블록 2를 가져올 때 누가 퇴출되는가?

  1. 세 번째 0 hit 뒤 LRU의 오래된 블록은 1이다.

  2. FIFO의 첫 입장 블록은 아직 0이다.

LRU는 1, FIFO는 0을 버린다. 다음 0 접근은 각각 hit와 miss다.

최종 상태가 숨기는 비용

각 정책의 miss 수와 한 블록 용량으로 바꾼 결과를 구하라.

  1. LRU miss 위치는 1, 2, 4, 6이다. FIFO는 1, 2, 4, 5, 6이다.

두 칸 LRU는 4 miss/2 hit, FIFO는 5 miss/1 hit다. 한 칸은 두 정책 모두 6 miss다.

블록을 키우거나 way를 늘리는 변화는 같은 변화인가?

새 직접사상 캐시의 데이터 용량은 32바이트다. 블록 크기 B=16이면 두 라인이고 B=32이면 한 라인이다. 한 바이트 읽기 주소열 0,32,0,32에서 B=16의 블록 0과 2는 두 라인의 같은 index 0으로 간다. B=32의 블록 0과 1도 한 라인으로 간다. 둘 다 네 miss지만 아래에서 가져온 총량은 각각 64와 128바이트다.

별도 주소열 0,16,0,16에서는 B=16의 두 블록이 서로 다른 라인에 들어가 2 miss/2 hit다. B=32에서는 네 주소가 모두 블록 0 안에 있어 1 miss/3 hit다. 큰 블록은 가까운 주소를 함께 가져오는 이익도 있고 다른 흐름의 불필요한 전송도 만들 수 있다. 이 모형은 매 miss마다 전체 블록을 가져오며 다른 통신은 없다고 정한다.

연관도만 비교할 때는 블록 크기와 전체 데이터 용량을 고정한다. B=8, 네 라인에서는 직접사상의 네 index와 2-way의 두 set이 다르다. 주소 0과 32의 블록 0/4는 직접사상 index 0에서 충돌하지만 2-way set 0의 두 자리에 함께 들어간다. tag·valid와 초기 조건은 계속 검사한다.

내용만 아니라 어느 내용인지도 저장한다

캐시 라인은 블록 데이터와 그것이 어떤 주소의 블록인지 나타내는 태그,유효 여부 등의 정보를 가진다. 데이터 비트가 존재해도 valid가0이면 올바른 현재 블록으로 쓰지 않는다. 태그가 맞고 유효한 라인을 찾을 때hit다. 라인 크기와 전체 캐시 데이터 용량을 같은 숫자로 보지 않는다.

읽기 miss에서는 요청 주소를 포함한 블록을 아래 계층에서 가져온다고 가정한다. 블록16바이트면 주소15는블록0의끝,16은블록1의처음이다. 주소가1바이트 차이여도 블록 경계를 넘을 수 있다. 실제 하나의 읽기가 경계를 가로지르면 접근을 분리하는 등 추가 구현 조건도 있지만 아래 예는 한 바이트 읽기다.

총자리가 아니라 허용된 자리를 본다

자체 직접사상 캐시는 4라인,라인 16바이트다. 블록 번호 b는 라인 b mod4로 가고 태그 floor(b/4)를 저장한다. 주소 0과64의 블록 0과4는 둘 다 라인 0을 사용하므로 서로 교체한다. 다른 라인이 비어 있어도 해당 블록을 그곳에 보관할 수 없다.

완전연관 캐시는 허용된 모든 라인 중 하나를 쓸 수 있어 같은 용량으로 두 블록을 함께 담을 수 있다. 그러나 비교 회로와 교체 정책이 달라질 수 있다. cache miss 횟수를 줄이는 구조 변경이 hit 검사 비용까지 항상 같게 유지한다는 보장은 없다.

miss의 이유를 조건과 함께 분류한다

처음 쓰는 블록의 miss는 compulsory 또는 cold miss 관점에서 본다. 작업 집합이 용량을 넘는 경우는 capacity 원인을 살핀다. 같은 용량의 완전연관 비교 모형에서는 남길 수 있는데 배치 제약 때문에 놓치는 경우는 conflict 원인을 구별한다. 단순히 두 번째 miss를 전부 충돌이라고 부르지 않는다.

분류에는 초기 상태·참조 흐름·비교할 용량·교체 정책을 같게 명시하는 것이 중요하다. 프로세서의 프리페치·동시 실행·공유 코어의 간섭이 있으면 추가 현상이 생긴다. 여기서는 읽기만,처음 비어 있음,프리페치 없음의 종이 모형으로 범위를 제한한다.

조건부 miss율과 전체 요청 비율을 섞으면 어떤 비용이 생기는가?

새 직렬 두 계층 모형은 모든 요청에서 L1 검사 1ns를 내고 L1 miss일 때만 L2 검사 5ns를 낸다. L2에서도 miss일 때 메모리 추가 시간은 40ns다. 100개 요청 중 L1 miss가 25개, 그 25개 중 L2 miss가 5개라고 정한다. L2의 지역 miss율은 5/25=0.2이고 전체 요청에 대한 비율은 5/100=0.05다.

직렬 합계는 100×1+25×5+5×40=425ns로 평균 4.25ns다. 식 1+0.25×(5+0.2×40)도 같다. 이미 전체 비율인 0.05를 안쪽 조건부 자리에 또 넣으면 메모리 발생을 한 번 더 줄여 잘못 계산한다. L1과 L2의 rate는 이름보다 분모를 확인한다.

별도 쓰기 모형은 한 16바이트 블록을 write-allocate로 가져온 뒤 같은 4바이트 값을 n번 쓰고 dirty 상태로 명시 퇴출한다. n은 양의 정수이고 매 검사 1ns, 첫 적재 20ns, 아래 쓰기는 호출당 10ns+바이트당 1ns다. write-through는 매번 4바이트를 쓰고 write-back은 퇴출 때 16바이트를 한 번 쓴다. 버퍼·겹침·병합·내구성 보장은 없다.

읽기의 평균과 실제 실행 시간을 나눈다

자체 직렬 읽기 모형에서 캐시 검사 h=2ns를 매번 지불하고 miss의 추가 적재 시간은 p=30ns다. miss율 m이면 평균은 h+mp다. 예를 들어 20읽기 중 4miss는 2+.2×30=8ns다. 전체 160ns는 같은 직렬 모형의 합이며 비용 겹침은 없다.

프로그램 전체 시간에는 명령 실행·여러 요청의 겹침·컴파일러 최적화 등이 더해진다. 따라서 읽기 비용 합을 CPU 실측 시간이라고 쓰지 않는다. 쓰기의 반영 방식이나 dirty 퇴출이 추가되면 같은 읽기식의 p가 모든 상황에서 불변이라고 가정해서도 안 된다.

바로 쓰거나 수정된 라인을 나중에 쓴다

write-through는 캐시 쓰기 때 아래 메모리에도 쓰는 정책이고 write-back은 캐시를 먼저 수정하고 dirty로 표시하여 교체 등에서 반영한다. 수정되지 않은 clean 라인은 불필요한 쓰기 없이 버릴 수 있다. dirty는 아래 복사본과 다를 수 있다는 정보이지 불법 데이터라는 뜻이 아니다.

이 절의 자체 쓰기 모형은 처음 비어 있는 캐시에 write-allocate로 16바이트 블록을 한 번 가져오고,같은 블록의 4바이트 값을 네 번 쓴 뒤 명시적으로 퇴출한다. 각 검사 2ns,처음 적재 추가 30ns,아래 쓰기 한 번은 고정 20ns+전송 바이트당 1ns다. 버퍼·쓰기 병합·병렬 처리·다른 접근은 없다. 이는 특정 CPU나 언어의 동작 측정이 아니다.

횟수와 바이트를 따로 센다

write-through는 네 번 각 4바이트를 쓰므로 아래 쓰기 4회·16바이트다. write-back은 마지막 dirty 라인 퇴출 때 16바이트를 한 번 쓰므로 1회·16바이트다. 이 예에서는 바이트가 같아도 고정 호출 비용 때문에 시간이 다르다. write-back이면 항상 전송 바이트가 더 작다는 말은 성립하지 않는다.

쓰기 한 번만 있었다면 write-through의 아래 4바이트 쓰기와 write-back의 16바이트 전체 블록 쓰기 비용을 비교해야 한다. 또한 캐시에 반영된 값이 저장 장치의 영구 보존까지 완료되었다는 뜻도 아니다. CPU 캐시 정책과 파일의 fsync 같은 내구성 정책은 계층이 다르며 이 모형으로 전원 실패 안전성을 증명하지 않는다.

중간 과정을 따라가는 예제

위네번쓰기후퇴출모형에서각정책의아래쓰기비용및전체비용합을계산하라.

  1. 공통 검사는 4×2=8ns,첫 블록 적재 30ns로 공통 38ns다.

  2. write-through의 아래 쓰기는 4×(20+4)=96ns,전체 134ns다.

  3. write-back의 아래 쓰기는 20+16=36ns,전체 74ns다. clean 교체라면 이 dirty 쓰기 비용이 없다.

write-through는 134ns,write-back은 74ns다. 아래 쓰기 횟수는 4대1이지만 전송 바이트는 둘 다16이며 처음 적재는 둘 다16바이트로 별도다.

조건을 바꾸어 비교하기

지역 rate를 전체 rate로 오독

안쪽에 0.05를 넣은 식의 값과 원인을 구하라.

  1. 1+0.25×(5+0.05×40)=2.75다.

  2. 메모리 부분은 실제 0.05×40=2ns이지만 오식은 0.25×0.05×40=0.5ns다.

평균을 1.5ns 작게 썼다. 지역 miss율 0.2 또는 전체율 0.05의 항을 올바른 위치에 사용한다.

비교할 점

1+0.25×5+0.05×40=4.25도 올바르다.

한 번과 두 번의 정책 역전

위 쓰기 모형에서 n=1과 n=2의 두 전체 비용을 구하라.

  1. 공통 비용은 n+20ns다. WT의 아래 비용은 14n, WB는 26ns다.

  2. n=1이면 WT 35/WB 47, n=2이면 WT 50/WB 48이다.

한 번 쓰기는 WT가 12ns 적고 두 번 쓰기는 WB가 2ns 적다. 바이트는 WT 4n 대 WB 16이다.

비교할 점

적은 전송 바이트와 적은 호출 고정 비용의 경쟁을 분리한다.

한 번 쓰기 예제는 56 대68ns로 순서가 반대다. 또한 write-back의 캐시 수정은 아래 반영과 시점이 다르며 저장 장치 내구성까지 보장하지 않는다.

다른 문제에 적용하기

교체·배치·조건부 비용의 세 장부 감사

처음 빈 두 칸 FA의 블록 0,1,0,2,0,1에서 LRU/FIFO miss 수와 직렬 비용을 구하라. 매 검사 1ns/추가 적재 20ns다. 독립 B8·32바이트 읽기 캐시의 주소 0,32,0,32에서 DM과 2-way 두 set의 miss와 적재량을 구하라. 두 계층의 100/25/5 사건과 같은 블록 두 번 쓰기 모형의 평균/WT/WB를 각각 연결하고 실제 실행 시간 여부를 설명하라.

힌트 1

정책별 상태·index/set을 먼저 추적하고 miss마다 검사 외 추가 적재를 센다.

힌트 2

L2 분모는 25이며 쓰기 모형은 검사·첫 적재·아래 쓰기를 별도로 센다.

풀이와 답 확인

  1. FA LRU는 4 miss/2 hit로 6+4×20=86ns, FIFO는 5 miss/1 hit로 106ns다.

  2. B8 DM은 4 miss·32바이트 적재, 2-way는 2 miss·16바이트 적재다.

  3. 두 계층 평균은 (100+125+200)/100=4.25ns다.

  4. 같은 블록 두 번 쓰기는 공통 22ns에 WT 28ns/WB 26ns를 더해 50/48ns다.

서로 다른 세 모형의 상태·분모·블록 재사용 조건을 보존한다. LRU/FIFO의 최종 내용이 같아도 비용은 다르고 적재 바이트와 miss 횟수도 다른 양이다. 모든 값은 지정 직렬 모형의 계산이며 CPU/캐시/학생 실험 결과가 아니다.

해결한 뒤 점검할 것

  • 각 정책의 hit 갱신 규칙과 상태를 설명한다.

  • 고정 용량의 block/index/set/way를 정확히 나눈다.

  • 조건부와 전체 비율의 분모를 명시한다.

  • 요청 횟수·전송량·직렬 모형 비용과 실제 측정·내구성을 구별한다.
