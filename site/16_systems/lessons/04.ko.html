소단원 4.1

레지스터와 주소지정

상자 번호를 계산하는 것과 그 상자 안의 숫자를 꺼내는 것은 같은 작업일까?

준비 개념과 학습 목표

준비 개념

  • 이 단원은 x86-64의 AT&T 표기 source,destination을 쓴다. %는 레지스터, $는 즉시 상수다. Intel 표기의 피연산자 순서와 섞지 않는다.
  • byte는 8bit다. b/w/l/q 접미사는 각각1/2/4/8byte 폭이며 eax는 rax의 하위32bit다.
  • 자체 종이 예제의 주소는 유효한 단일 스레드 일반 RAM이고 little-endian이다. 실제 OS 권한·장치·동시수정은 포함하지 않는다.

학습 목표

  • 레지스터 값·유효주소·그 주소의 메모리 값을 나누어 추적한다.
  • lea/load/store·부분 레지스터 쓰기·주소식의 scale과 byte 단위를 계산한다.

주소는 물건을 찾는 계산이다

D(base,index,scale)의 유효주소는 D+R[base]+R[index]×scale이다. scale은 1/2/4/8 중 정한다. 예를 들어8(%rdi,%rsi,8)는 rdi 값에 rsi의8배와8byte를 더한다. 괄호는 메모리 참조 표기에 사용되지만 명령 자체가 정말 메모리를 읽는지까지 확인해야 한다.

주소를 사물함 번호, 저장 값을 내용물로 비유할 수 있다. 그러나 실제 주소는 프로그램의 가상주소이며 사물함 번호만 맞으면 접근이 성공하는 것은 아니다. 범위·폭·권한·수명 조건을 별도로 확인해야 한다. 같은 숫자 1024도 어떤 명령에서는 주소이고 다른 명령에서는 계산할 정수일 수 있다.

복사와 주소 계산을 구별한다

movq 8(%rdi,%rsi,8),%rcx는 계산한 주소에서8byte를 읽어 rcx에 복사한다. movq %rcx,8(%rdi,%rsi,8)는 반대로 메모리에 쓴다. source를 지우는 이동이 아니므로 읽은 레지스터나 원래 메모리가 자동으로 비워지지 않는다. 일반 mov의 두 피연산자를 동시에 메모리로 둘 수는 없다.

leaq 8(%rdi,%rsi,8),%rax는 같은 주소 산술을 하되 그 주소의 메모리를 읽지 않는다. 숫자 계산에도 lea를 쓸 수 있다. 따라서 lea 결과와 그 주소에서 읽은 값이 우연히 같다는 이유로 두 명령을 같은 것으로 취급하지 않는다. 오류가 없는 산술과 메모리 접근 성공도 별개다.

폭이 달라지면 남는 bit가 달라진다

rax는 64bit, eax는 하위32bit, ax는 하위16bit, al은 하위8bit다. 일반적인 8/16bit 쓰기는 지정 부분만 바꾸지만32bit 목적 레지스터 쓰기는 해당 64bit 레지스터의 상위 32bit를 0으로 만든다. 이는 한 레지스터의 부분 이름이며 각각 독립 상자 네 개가 아니다.

little-endian 8byte 정수35의 낮은 주소부터 바이트는23/00/00/00/00/00/00/00(16진수)다. 명령의 폭은 C 변수 이름으로 추측하지 말고 접미사·피연산자와 함께 읽는다. 이 단원의 작은 주소와 값은 자체 모형이고 실제 컴퓨터 메모리를 관찰한 결과가 아니다.

중간 과정을 따라가는 예제

rdi=1000,rsi=2,8byte M[1024]=30이다. leaq 8(%rdi,%rsi,8),%rax; movq 8(%rdi,%rsi,8),%rcx; addq $5,%rcx; movq %rcx,8(%rdi,%rsi,8); movl $7,%eax의 상태를 추적하라. 모든 메모리 접근은 성공한다.

  1. 첫 주소는1000+2×8+8=1024다. lea는 rax=1024로 만들며 M[1024]는30 그대로다.
  2. movq는 주소1024의30을 읽어 rcx=30으로 만든다. 주소 값 1024와 내용30을 구별한다.
  3. addq 뒤 rcx=35, 이어 store 뒤 M[1024]=35다. 저장 바이트는23/00/00/00/00/00/00/00이다.
  4. 마지막 movl은 eax=7과 상위32bit0을 만들므로 rax=7이다. rcx=35와 메모리35는 유지된다.

최종 rax7/rcx35/M[1024]35다. 유효주소 계산·load·store·부분 레지스터 쓰기의 변경 집합이 각각 다르다.

종이와 본문으로 직접 해보기

rax=0xFFFFFFFFFFFF1234에서 movb $0x56,%al 뒤 값과, 이어 movl $0x89ABCDEF,%eax 뒤 값을 적어라. 16(%rdi,%rsi,4)를 rdi1000/rsi3에서 계산하라.

힌트 보기

첫 쓰기는 가장 낮은 한 byte만 바꾼다. 둘째는 상위 32bit를 0으로 만든다. 주소 단위는 byte다.

풀이 보기

첫 값은0xFFFFFFFFFFFF1256, 둘째는0x0000000089ABCDEF다. 주소식은1000+3×4+16=1028이다. 이 주소가 유효한지는 주소 계산만으로 보증하지 않는다.

오해와 반례

lea는 괄호 안 주소에서 값을 읽고, eax와 rax는 서로 다른 독립 레지스터다.

예제 lea의 1024와 load의 30은 다르다. movl $7,%eax 뒤 rax도 7로 바뀌므로 부분 이름의 독립성을 반박한다. 비유의 상자와 실제 레지스터 별칭을 구별한다.

한 단계 더

소단원 4.2

산술·분기 명령

똑같은 bit 두 개를 비교해도 부호 있는 수와 없는 수의 대소 결과가 달라질까?

준비 개념과 학습 목표

준비 개념

  • addq/subq의 결과는64bit다. signed와 unsigned 해석을 구별한다.
  • AT&T cmpq src,dst는 dst−src의 조건flag를 설정하고 목적값을 쓰지 않는다.
  • ZF는0 결과, SF는 부호bit, OF는 signed overflow, CF는 unsigned carry/borrow와 관련한다. 분기는 직전 flag를 읽는다.

학습 목표

  • 피연산자 순서와 signed/unsigned 분기 조건을 설명한다.
  • 조건flag를 덮어쓰는 명령을 포함해 경로와 값의 변화를 추적한다.

산술 결과와 해석을 나눈다

addq %rsi,%rax는 rax의 이전 값에 rsi를 더해 rax에 쓰는 두 피연산자 명령이다. 일반 64bit 덧셈은 낮은 64bit 결과와 조건flag를 남긴다. 같은 bit 산술 명령을 signed와 unsigned에 사용할 수 있지만 overflow의 의미와 이후 판단은 다르다. C의 signed overflow를 이 하드웨어 wrap 규칙과 동일시하지 않는다.

cmpq %rsi,%rdi는 rdi−rsi의 bit 결과를 이용해 flag만 갱신하고 rdi/rsi를 그대로 둔다. testq %rax,%rax도 AND 결과를 저장하지 않고0 여부 등을 설정한다. 메모리/레지스터 변화가 없는 비교도 다음 제어흐름에 영향을 준다.

조건은 flag의 조합이다

je는 ZF=1, jne는 ZF=0이다. signed less인 jl은 SF≠OF, signed less-or-equal인 jle는 ZF=1 또는 SF≠OF다. unsigned below인 jb는 CF=1, above인 ja는 CF=0이고 ZF=0일 때다. SF 하나만으로 모든 signed 비교를 판정하면 뺄셈 overflow에서 틀릴 수 있다.

분기는 자신이 원하는 비교 바로 뒤의 flag가 남아 있는지 확인해야 한다. cmp 뒤에 add/xor 같은 명령을 끼우면 그 명령이 flag를 바꿀 수 있다. mov나 lea처럼 이 예에서 flag를 바꾸지 않는 명령과 구별한다. 코드 줄이 가까운 것보다 실제 수행 순서가 중요하다.

작은 조건문을 두 경로로 확인한다

최솟값은 먼저 후보 a를 결과 레지스터에 복사한 뒤 a≤b이면 유지하고, 아니면 b로 바꿀 수 있다. branch가 어느 경로를 고르는지와 그 경로가 반환할 값을 모두 확인한다. 같은 값을 반환하는 다른 명령 배치나 conditional move도 가능하므로 한 모양이 유일한 정답은 아니다.

x86 명령 길이는 일정4byte가 아니므로 이 단원의 label은 주소를 임의로4씩 증가시키는 표가 아니다. 실제 instruction bytes를 역어셈블할 때는 각 명령의 실제 길이와 target을 읽어야 한다. 본문은 명령 의미와 label의 종이 추적이며 compiler/disassembler 로그를 만들지 않았다.

중간 과정을 따라가는 예제

a=9를 rdi,b=2를 rsi에 둔다. movq %rdi,%rax; cmpq %rsi,%rdi; jle Done; movq %rsi,%rax; Done의 signed 최솟값 계산을 추적하라. Done은 결과 관찰 경계다.

  1. 첫 mov 뒤 후보 rax=9다. rdi/rsi는9/2로 유지된다.
  2. cmp는9−2=7이므로 ZF0/SF0/OF0/CF0이다. 목적 레지스터 값 자체는 바뀌지 않는다.
  3. jle 조건 ZF1 또는 SF≠OF가 모두 거짓이어서 b를 복사하는 경로로 간다. rax=2다.
  4. Done에서 결과2를 확인한다. a=−3,b=2라면 비교−5에서 SF1/OF0이므로 분기해 후보−3을 유지한다.

signed 최솟값은9/2에서2, −3/2에서−3이다. branch label의 수행 여부와 결과 복사를 함께 확인했다.

종이와 본문으로 직접 해보기

rdi=0xFFFFFFFFFFFFFFFF,rsi=1에서 cmpq %rsi,%rdi 뒤 jl과 jb의 참거짓을 계산하라. 별도9/2 예제에서 cmp 뒤 jle 앞에 xorl %ecx,%ecx를 넣으면 결과는?

힌트 보기

FFFFFFFFFFFFFFFF는 signed−1/unsigned2⁶⁴−1이다. xor 같은 값은0이며 ZF1·SF0·OF0을 만든다.

풀이 보기

비교−1−1=−2에서 SF1/OF0/CF0/ZF0이므로 jl참,jb거짓이다. 삽입한 xor는 ZF1로 덮어써 jle를 참으로 만들어 잘못된 후보9를 유지한다. 예제의 원래 비교7 flag가 더 이상 남아 있지 않다.

오해와 반례

음수 bit가 보이면 jl은 SF만 확인하면 되고, cmp 뒤 flag는 다음 cmp까지 바뀌지 않는다.

signed 최솟값−2⁶³에서1을 빼면 bit 결과는2⁶³−1이라 SF0이지만 OF1이다. 따라서 jl은 참이다. 또한 위 xor 삽입에서 flag가 바뀌어 최솟값을 잘못 고른다.

한 단계 더

소단원 4.3

C 코드와 어셈블리 대응

원래 변수 이름이 지워진 명령 목록에서 무엇을 알 수 있고 무엇은 되찾을 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 자체 대응 예는 System V AMD64 정수호출 모형, long8byte, p/i/bias를 rdi/rsi/rdx에 받고 rax로 결과를 돌린다. Windows x64 등의 규약과 다르다.
  • p는 살아 있는 길이4 long 배열의 주소, 0≤i<4, 모든 원소와 bias는−100..100이다. 연산·접근·반환이 정의되어 있고 alias 동시변경/volatile은 없다.
  • C→assembly→object→link의 단계와, instruction bytes→assembly를 읽는 역어셈블 단계를 구별한다.

학습 목표

  • 주소식과 산술식의 의미를 C 배열·값 계산에 대응시킨다.
  • 역어셈블에서 가능한 추론과 원본 복원·최적화·실행 증거의 한계를 설명한다.

서로 다른 표현의 같은 효과

C 함수 long pick(const long *p,long i,long bias){ return p[i]+2*bias; }를 생각한다. 이 조건에서 p[i]는 원소 8byte이므로 base+8i에서 읽는다. 명령 표기는 movq (%rdi,%rsi,8),%rax; leaq (%rax,%rdx,2),%rax; ret로 만들 수 있다. 이는 작성한 대응 모형이며 어떤 GCC 버전의 실제 출력이라고 주장하지 않는다.

첫 lea 예제에서 주소를 계산했지만 여기의 lea는 이미 읽은 값과 bias의2배를 더하는 정수 산술이다. 같은 형태가 언제나 pointer라는 뜻은 아니다. 계약의 작은 수 범위에서는 signed C 중간값2*bias와 최종 합이 long 범위 안에 있어 정의된 계산을 비교할 수 있다.

함수 경계와 변수 위치

호출규약의 인자/결과 레지스터는 프로그램의 약속이며 C 표준이 직접 정한 것은 아니다. 위 호출에서는 p/i/bias가 rdi/rsi/rdx이고 결과가 rax다. 다른 ABI·자료형·최적화에 따라 인자 배치와 필요한 load/store가 달라질 수 있다. source 변수 하나가 반드시 고유 stack slot 하나를 갖지는 않는다.

위 함수는 별도 지역 저장 없이 레지스터에서 계산하는 leaf 모형이다. 실제 ret는 호출자가 준비한 유효 반환주소를 stack에서 가져온다고 가정한다. 모든 C 함수가 rbp frame을 만들거나 각 C문장에 같은 개수의 기계 명령을 대응시킨다는 주장은 맞지 않는다. 최적화·인라이닝은 함수 경계도 바꿀 수 있다.

역어셈블은 원본 C의 유일한 복원이 아니다

컴파일은 C 의미를 대상 명령으로 번역하고 assembler는 명령을 bytes로 부호화한다. linker는 파일 사이의 참조를 연결한다. disassembler는 선택한 ISA·모드와 instruction 경계에서 bytes를 명령 표기로 해석한다. 원래 주석·변수 이름·분기 문장 모양을 모두 보존한 역함수는 아니다. 자료 bytes를 code로 잘못 해석하는 일도 경계 정보를 따로 판단해야 한다.

같은 정의역에서 p[i]+2*bias와 p[i]+bias+bias는 같은 결과를 가지며 여러 명령열로 계산할 수 있다. 어떤 입력을 모두 허용해 signed overflow가 생기는 영역까지 같은 C 프로그램이라고 확대하지 않는다. 분석할 때 compiler 버전/target/ABI/옵션·자료형·전제와 예상 의미를 적고 실제 compile/disassembly/실행 증거는 별도로 남긴다.

중간 과정을 따라가는 예제

p의 배열 값은[4,9,−2,7], base=1000,i=1,bias=−2다. 위 movq/lea/ret 모형의 의미를 C 함수와 대조하라. 실제 반환주소는 유효하게 준비되어 있고 메모리 접근은 성공한다.

  1. 주소식은1000+1×8=1008이다. 해당 long 값은9이므로 movq 뒤 rax=9다.
  2. leaq는 메모리를 읽지 않고9+2×(−2)=5를 계산해 rax에 쓴다. 음수 rdx는64bit 표현이지만 낮은 64bit 결과의 signed 해석은5다.
  3. C의 중간2*bias=−4와9+(−4)=5가 모두 허용 범위 안이다. 두 표현의 계산 결과가 같다.
  4. ret는 정상 반환 경계를 이동하고 결과 레지스터 5를 전달한다. 이 계산에서는 메모리 값을 변경하지 않으며 array[1]은 9다.

예상 결과5·배열 변경 없음이다. 자체 대응과 종이 추적이 일치하며 실제 GCC/objdump/CPU 실행은 미수행이다.

종이와 본문으로 직접 해보기

i=2,bias=3으로 바꿔 읽는 주소와 결과를 구하라. lea 대신 addq %rdx,%rax를 두 번 쓰는 모형도 결과가 같은가? i=4도 같은 근거로 비교해도 되는가?

힌트 보기

원소2는−2다. 인덱스4는 길이4 배열에서 끝 다음 위치다.

풀이 보기

주소1016에서−2를 읽고−2+6=4다. 두 add도−2+3=1,1+3=4여서 이 계약의 값 계산은 같다. flag는 달라질 수 있으나 이 C 결과 계약은 flag를 관측하지 않는다. i4는 역참조 범위를 벗어나 정의된 C 접근이 아니므로 주소1032의 숫자를 임의로 읽어 대응을 증명하지 않는다.

오해와 반례

어셈블리 한 개를 보면 원래 C문장과 변수 이름을 유일하게 복원할 수 있고 모든 CPU에서 long은8byte다.

계약 범위의 두 C 산술식과 여러 명령열은 같은 결과를 낼 수 있다. CMU 원문 IA32의 long4와 자체 AMD64 long8도 다르다. target/ABI 없이 변수 폭과 원래 문장 모양을 단정하지 않는다.

한 단계 더

심화: 위 가정에서 p[i]+2*bias의 결과 범위는−300..300이다. 두 add의 중간값도−200..200이어서 long overflow가 없다. 왜 정의역을 정한 뒤 의미 동등성을 말해야 하는지 이 상계로 설명하라. 프로그램의 정의되지 않은 동작을 하드웨어 modulo 결과로 고쳐 읽거나, 명령수가 줄었다고 실제시간이 반드시 줄었다고 결론내리지 않는다.
