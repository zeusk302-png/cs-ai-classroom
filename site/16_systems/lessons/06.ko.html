소단원 6.1

배열과 포인터 산술

int 포인터에 1을 더하면 주소도 항상 1byte만 늘어날까?

준비 개념과 학습 목표

준비 개념

  • 배열은 같은 형식의 원소를 연속 저장한 객체다.

  • 포인터의 형식은 한 번 이동하는 원소의 크기를 결정한다.

  • 본 종이 ABI는 int 크기 4byte, char 크기 1byte이며 주소는 가상 숫자다.

학습 목표

  • 주소 이동과 원소 수 차이를 계산한다.

  • 배열 범위와 one-past의 사용 조건을 구별한다.

배열 전체 크기와 함수가 받은 포인터 크기는 같은가?

자체 ABI에서 int의 크기는 4바이트, int 포인터의 크기는 8바이트다. 호출자에 int a[6]이 있을 때 sizeof(a)는 24지만 함수 매개변수 int v[6]은 포인터 매개변수로 조정된다. 함수 안 sizeof(v)는 이 모형에서 8이다. 선언에 6이 보인다는 이유로 함수가 배열 전체의 크기를 자동으로 알아내지는 않는다.

따라서 함수 안 sizeof(v)/sizeof(v[0])를 원소 수로 쓰면 8/4=2라는 잘못된 수를 얻는다. 호출자가 필요한 길이를 별도로 전달하거나 실제 배열 형식을 유지하는 다른 계약을 정해야 한다. 이 비교는 정해진 크기 모형이며 모든 C 구현의 포인터 크기를 8로 주장하지 않는다.

범위 끝도 별도 장부다. a에서 a+6은 여섯 원소의 끝이고 (a+6)−a는 6이다. 마지막 원소는 (a+6)−1로 구하지만 끝 자체를 읽지 않는다. 서로 다른 배열은 수치 주소가 인접하더라도 이 차이와 산술의 동일 배열 조건을 공유하지 않는다. 잘못된 포인터 접근은 실제로 수행하지 않는다.

먼저 확인할 개념
  • 배열 객체·포인터 변환과 차이 단위

    호출자 sizeof와 조정된 매개변수, 원소 수 차이를 구별한다.

  • 배치 주소와 객체 범위

    연속 주소 그림으로 다른 배열 범위 접근을 정당화하지 않는다.

원소 크기로 이동하는 주소

int a[5]의 시작 주소를 1000으로 놓으면 a[i]의 주소는 1000 +4i다. a +1은 첫 원소 다음을 가리켜 1004가 된다. 주소의 byte 차이 4와 포인터 식의 원소 차이 1은 다른 단위다.

배열 이름은 많은 식에서 첫 원소 포인터로 변환되지만 배열 자체와 포인터 변수는 같은 객체가 아니다. sizeof(a)는 이 배열 전체 크기이며 함수 매개변수로 전달되어 포인터가 된 경우와 구별한다.

차이와 마지막 다음 위치

동일 배열의 p =&a[1],q =&a[4]이면 q −p =3이다. byte 주소 1016 −1004 =12를 원소 크기 4로 나눈 것과 맞는다. 결과는 ptrdiff_t 형식이며 그 형식에 표현 가능한 값이라는 조건도 있다.

a +5는 마지막 원소 다음인 one-past로 만들고 범위 끝을 표시할 수 있다. 하지만 *로 읽거나 쓰면 안 된다. a +6처럼 범위를 더 넘는 산술도 합법이 아니며 가까운 다른 객체를 같은 배열처럼 이어 취급하지 않는다.

주소 계산과 값 읽기를 분리하기

주소 1008을 계산한 것만으로 a[2]의 값이나 초기화 상태를 알지 못한다. 유효한 객체· 수명· 범위· 정렬과 값의 초기화가 필요하다. 접근을 하지 않았으니 어떤 포인터 산술도 안전하다는 주장은 틀리다.

주소는 실행마다 다르고 int 크기도 구현에 따라 달라진다. 이 단원은 명시한 크기의 종이 배치이며 실제 주소를 만들어 역참조하는 실험을 하지 않는다. 모든 C 구현에서 1000이라는 주소가 배열을 담는다고 보장하지 않는다.

sizeof는 객체나 형식의 바이트 크기이고 포인터 차이는 원소 단위다. 두 번째 행의 2는 산술 결과일 뿐 실제 배열 원소 수라는 의미를 갖지 않는다.

중간 과정을 따라가는 예제

가상 int a[5], 시작 1000· 원소 4byte,p =&a[1],q =&a[4]에서 주소·q −p·one-past를 구하라.

  1. p 주소 1000 +1×4 =1004다.

  2. q 주소 1000 +4×4 =1016이다.

  3. q −p =4 −1 =3 원소이며 byte 차이는 12다.

  4. a +5 주소 1020은 끝 표시지만 원소 읽기는 불가다. 전체 크기는 5×4 =20byte다.

p1004,q1016, 차이 3 원소, 끝 1020· 전체 20byte다.

조건을 바꾸어 비교하기

이름은 배열처럼 보여도 조정된 매개변수

int a[6]을 함수 int v[6] 매개변수로 넘긴다. 포인터8/int4 모형의 두 sizeof 비율을 비교하라.

  1. 호출자 배열은 6×4=24바이트다.

  2. 함수의 v는 포인터라 sizeof(v)=8이다.

호출자 비율6, 함수 비율2다. 함수의 실제 입력 길이는 6이며 별도 계약으로 전달한다.

비교할 점

배열 선언 모양과 식에서의 실제 형식을 분리한다.

끝 표시를 역방향 순회에 쓰기

a[6]에서 end=a+6을 두고 뒤에서 여섯 값을 방문하려 한다.

  1. end 그 자체는 읽지 않는다.

  2. 매번 현재 포인터를 먼저 1 줄인 뒤 같은 배열의 원소를 읽는다.

방문 첨자는 5,4,3,2,1,0이다. 시작 전으로 더 줄이지 않는다.

비교할 점

끝을 만드는 것과 끝에서 읽는 것을 서로 다른 단계로 둔다.

종이와 본문으로 직접 해보기

q −2와(a +5)−1은 어디인가? a +6의 산술을 허용할 수 있는가?

힌트 보기

같은 배열 안의 첨자를 먼저 계산한다.

풀이 보기

q −2는 a[2]주소 1008, 끝 −1은 a[4]주소 1016이다. a +6 은 허용 범위를 넘어 정의되지 않은 동작이다. 끝포인터 그 자체와 그 다음의 포인터를 구별한다.

오해와 반례

포인터 차이는 항상 byte 수이고 one-past도 읽을 수 있다.

q −p =3이지 12가 아니다. 끝 1020은 a[5]라는 실제 원소를 할당하지 않아 역참조할 수 없다.

소단원 6.2

구조체 정렬·패딩

char 1byte,int 4byte,char 1byte를 합치면 구조체는 반드시 6byte일까?

준비 개념과 학습 목표

준비 개념

  • 정렬은 객체 주소에 요구되는 배수 조건이다.

  • padding은 멤버 사이 또는 객체 끝의 여분 byte다.

  • 본 자체 ABI는 char 크기/ 정렬 1,int4/4, 구조체 정렬은 최대 멤버 정렬, 크기는 그 배수로 올림한다.

학습 목표

  • 멤버오프셋· 내부/ 끝 padding· 배열 stride를 계산한다.

  • ABI 가정과 C의 일반 조건을 구별한다.

작은 구조체를 큰 구조체 안에 넣으면 빈 바이트도 사라질까?

자체 ABI의 char 크기/정렬은 1/1, int는 4/4이고 구조체 정렬은 멤버 정렬의 최대이며 전체 크기는 그 배수로 올린다. H{char tag; int value;}는 offset0/4에 멤버를 놓고 크기8이다. 중간 세 padding 바이트는 H의 크기에 포함된다.

O{char prefix; H h; char suffix;}에서는 prefix가0, h가4에서 시작해 8바이트를 차지하고 suffix가12다. 끝13을 전체 정렬4로 올리면 sizeof(O)=16이다. h 안 value는 O 기준4+4=8이다. 안쪽 구조체의 크기를 사용자 멤버 합5로 줄여 계산하면 바깥 suffix와 배열 stride도 틀린다.

같은 멤버 값을 가진 두 객체라도 padding의 byte까지 같다는 보장은 없다. 이 모형에서는 padding 위치를 표시하되 그 내용을 미지정으로 둔다. 멤버별 의미 비교와 객체 전체 byte 비교는 서로 다른 계약이며 외부 저장에는 별도 명시 형식이 필요하다. 실제 padding을 읽거나 파일로 저장한 것은 아니다.

먼저 확인할 개념
  • 선언 순서·내부와 끝 padding

    안쪽 크기에도 padding이 포함되고 바깥 offset은 다시 정렬한다.

  • 배열 stride와 원소 크기

    O 배열의 다음 원소를 전체 sizeof(O)로 이동한다.

선언 순서와 다음 정렬 위치

struct S{char c;int i;char d;}에서 c는 offset0에 1byte를 쓴다. i를 4의 배수에 놓으려면 offset1~3을 건너뛰어 offset4에 4byte를 쓴다. d는 offset8에 1byte다. 선언 순서를 바꾸지 않고 배치한다.

정렬을 위한 올림은 ceil(x/K)×K다. 현재 끝 9와 전체 정렬 4라면 끝을 12로 올린다. 따라서 내부 3byte와 끝 3byte가 추가되어 전체 12byte다. padding은 추가 사용자 멤버가 아니다.

배열의 다음 객체도 정렬하기

S 배열의 stride는 sizeof(S)=12다. 시작 1000이라면 두 번째 S는 1012, 그 i는 1016에 놓여 4의 배수 조건을 유지한다. 배열 원소 사이에 추가 별도 padding을 넣는 대신 각 S의 끝 padding이 이미 크기에 들어 있다.

int i;char c;char d; 순서인 T는 i0~3,c4,d5, 끝 6을 8로 올려 크기 8이다. 필드 재배치는 크기를 줄일 수 있지만 외부 파일·ABI· 직렬화와 상호 운용 조건을 바꿀 수 있어 자동 동일 형식이라고 하지 않는다.

저장 형식으로 그대로 보내지 않기

C는 선언 순서와 padding 가능성을 규정하지만 모든 구현에서 int4· 정렬 4·S12를 강제하지 않는다. 실제 값은 sizeof/offsetof와 ABI 문서로 확인해야 한다. packed 확장은 다른 정렬과 접근 조건을 만든다.

구조체 전체 byte를 파일로 복사하면 padding· 정수 표현·byte 순서가 포함되어 다른 환경에서 동일 해석을 보장하지 않는다. 멤버 값이 같아도 padding까지 같다고 단정하지 않는다. 여기서는 구조체 코드· 파일 입출력을 실행하지 않았다.

소단원 6.3

다차원 배열과 별칭

int a[2][3]을 int **로 받아도 같은 방식으로 접근할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 행 우선은 마지막 첨자가 가장 빨리 바뀌는 연속 배치다.

  • a[2][3]은 3int 행 두 개의 배열이다.

  • 별칭 alias는 두 표현이 같은 객체를 가리키는 관계다.

학습 목표

  • 행 포인터의 이동 크기와 주소를 계산한다.

  • 연속 2 차원 배열· 포인터 배열· 별칭 조건을 구별한다.

행을 읽는 형식과 포인터 목록을 읽는 형식은 왜 바꿔 쓸 수 없을까?

int 크기4, 포인터 크기8인 자체 모형에서 int a[2][3]의 전체 크기는24다. a가 변환된 행 포인터의 +1은12바이트 이동한다. 별도 int *rows[2]의 전체 크기는16이고 rows+1은 포인터 슬롯 하나인8바이트 이동한다. rows를 각 a 행의 첫 원소로 설정하면 둘 모두 같은 int를 읽을 수 있지만 첫 번째 메모리 읽기의 대상은 다르다.

a[i][j]는 연속된 행 객체의 위치를 먼저 계산한다. rows[i][j]는 포인터 객체 rows[i]에 저장된 주소를 먼저 읽고 그 주소의 int를 찾는다. rows의 두 포인터를 같은 행으로 설정할 수도 있으므로 rows의 두 인덱스가 서로 다른 행이라는 보장도 자동으로 생기지 않는다.

별칭은 복사 방향에도 영향을 준다. 초기 배열[1,2,3,4]에서 뒤 세 칸으로 앞 세 칸을 한 칸씩 이동하며 낮은 첨자부터 쓰면 방금 쓴 값이 다음 읽기의 입력이 된다. 원래 세 값을 보존하려는 계약이면 높은 첨자부터 쓰거나 별도 보관해야 한다. 여기서는 각각의 읽기/쓰기를 순서대로 정의한 유효 int 접근만 추적하며 memcpy의 겹침 규칙과 실제 실행을 혼동하지 않는다.

먼저 확인할 개념
  • 행 포인터와 int** 및 별칭

    연속 행의 주소 계산과 포인터 슬롯 읽기를 구별한다.

  • 포인터 이동의 원소 단위

    행12/int4/포인터8이라는 서로 다른 한 칸 크기를 사용한다.

행 하나가 바깥 배열의 원소

int a[2][3],int4byte에서 각 행은 12byte다. a가 포인터로 변환되면 첫 행을 가리키는 int (*)[3]형식이다. a +1은 다음 행으로 12byte 이동하고 a[0]+1은 같은 행의 다음 int로 4byte 이동한다.

행우선의 주소 그림은 base +((i×3)+j)×4로 표현할 수 있다. 이는 배치 계산식이며 2 차원 C 객체를 첫 int 포인터로 무제한 일차원 순회해도 된다는 허가는 아니다. 각 행의 범위와 올바른 a[i][j]를 보존한다.

int**는 포인터를 읽는 다른 경로

int **는 먼저 int *포인터 객체를 읽고 그 포인터가 가리키는 원소로 간다. 연속 int 행 안에는 그런 행 주소 포인터 객체가 저장되어 있지 않다. 숫자 배치가 연속이라는 사실만으로 형식 변환을 정당화하지 않는다.

int * rows[2]를 별도로 만들고 각 rows를 유효한 행의 첫 원소로 설정하면 포인터 배열 방식의 접근이 가능하다. 행들이 별도 할당되어 서로 떨어져 있을 수도 있다. 연속 배열과 포인터 배열의 크기· 수명 조건을 따로 적는다.

두 이름이 한 값을 바꾸기

int *p =&a[1][1], *q =&a[1][1]이면 두 포인터는 같은 int의 별칭이다. *p =9 의 쓰기 뒤 *q도 9를 읽는다. 주소 값을 담은 변수를 복사한 것은 원소 전체를 복제한 것과 다르다.

별칭이 없는 것으로 가정한 최적화나 restrict 계약은 실제 겹침 관계와 맞아야 한다. 다른 형식으로 무작정 접근하는 것에는 유효 형식· 정렬 규칙도 있다. 본 예는 유효한 동일 int 별칭이고 동시 스레드· 수명 종료· 잘못된 캐스트를 다루지 않는다.

다른 문제에 적용하기

int의 크기/정렬은 4/4, char는 1/1, 포인터 크기는 8바이트인 자체 ABI다. 시작 주소 2000의 int a[6]과 함수 int v[6] 매개변수의 sizeof 비율을 비교하라. H{char tag;int value;}와 O{char prefix;H h;char suffix;}의 배치를 구하고, O 두 원소가 3000에서 시작할 때 둘째 h.value 주소를 구하라. 별도 int m[2][3]의 시작은 4000, 포인터 배열 rows의 시작은 5000이다. rows[0]=m[1], rows[1]=m[0]이면 rows[0][2] 대상과 rows[1] 슬롯의 주소를 구하라. 마지막으로 초기 [1,2,3,4]의 앞 세 값을 뒤 세 칸으로 보존 이동하는 방향과 중간 상태를 적어라. 실제 C/메모리/API는 실행하지 않는다.

힌트 1

sizeof의 배열과 조정된 매개변수, 중첩 멤버 offset, 포인터 슬롯과 대상 int의 주소를 각각 구별한다.

힌트 2

겹친 이동에서 이전 쓰기가 다음 읽기를 덮는지 상태를 한 단계씩 적는다.

풀이와 답 확인

  1. 호출자 sizeof(a)=24이므로 비율은 6이고 함수 sizeof(v)=8이므로 비율은 2다. 후자는 실제 길이가 아니므로 n=6을 별도 계약으로 전달한다. a의 끝 주소 2024는 읽지 않는다.

  2. H의 offset은 0/4이며 크기는 8이다. O의 offset은 0/4/12이며 크기는 16이고 h.value는 O 기준 offset 8이다. 둘째 O의 시작은 3016이며 h.value 주소는 3024다.

  3. rows[0]은 m의 둘째 행 주소 4012를 저장하므로 rows[0][2]의 대상 주소는 4020이다. rows[1]의 슬롯 주소는 5008이며 그 안의 포인터 값은 4000이다.

  4. x3=x2, x2=x1, x1=x0 순서의 중간 상태는 [1,2,3,3]→[1,2,2,3]→[1,1,2,3]이다. 낮은 첨자부터는 [1,1,1,1]이 되어 원래 자료를 잃는다.

sizeof 비율은 6 대 2다. O의 크기는 16, 둘째 h.value 주소는 3024다. int 대상 주소 4020과 포인터 슬롯 주소 5008을 구별한다. 보존 이동은 뒤에서 시작하여 [1,1,2,3]을 얻는다. 모든 결론은 자체 ABI·유효 객체·순차 대입 모형의 범위다.

해결한 뒤 점검할 것

  • 포인터 크기에서 실제 배열 길이를 추론하지 않는다.

  • 중첩 padding과 전체 stride를 모두 포함한다.

  • 슬롯 주소와 그 안의 주소 값 및 대상 값을 구별한다.

  • 같은 수치 주소로 다른 배열의 포인터 산술을 정당화하지 않는다.

  • 겹친 이동의 모든 중간 상태와 반대 방향 반례를 적는다.

  • 실제 C/UB/메모리/파일/학생 미수행을 유지한다.
