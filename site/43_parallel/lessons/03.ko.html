소단원 3.1

공유메모리·메시지 전달

여러 사람이 같은 종이에 답을 쓰는 것과 각자 답을 우편으로 보내는 것은 어떤 차이가 있을까?

준비 개념과 학습 목표

준비 개념

  • 주소는 자료가 놓인 위치다. 같은 숫자 주소라도 서로 다른 프로세스에서는 같은 객체를 뜻하지 않을 수 있다.

  • 한 번 더하기가 읽기·계산·쓰기 세 단계라면 두 작업이 중간에 섞일 수 있다.

  • 작업별 부분합을 만든 뒤 모두 끝났을 때 합치는 방법을 준비한다.

학습 목표

  • 공유 주소 공간과 명시적 전송의 차이를 설명한다.

  • 프로그래밍 모형과 실제 기계 배치를 구별한다.

모든 메시지가 도착하면 결과의 순서도 자동으로 맞을까요?

새 수집 모형에는 작업 A, B, C가 있고 각 작업의 결과 문자열은 각각 a, b, c다. 문자열 이어 붙이기는 결합적이지만 교환적이지 않다. 결과 계약은 ID 순서 A, B, C의 문자열 abc다. 세 메시지는 손상·유실·중복 없이 각각 한 번 도착하며 실제 도착 순서는 C, A, B라고 정한다. 이것은 기본의 정수 부분합과 다른 결과 연산이다.

도착 즉시 이어 붙이면 cab가 된다. 각 ID의 슬롯에 저장하고 세 ID의 완료를 모두 확인한 뒤 ID 순서로 읽으면 abc가 된다. 공유모형에서도 슬롯 위치와 완료 가시성을 보장해야 같은 결과를 얻는다. 자료 값이 준비되었다는 사실과 누가 어느 순서로 읽는다는 계약을 나누어 적는다.

별도의 오류 감사 모형은 메시지 중복을 허용한다. 이때 도착 횟수 세 번을 완료 조건으로 쓰면 A, A, B만 도착해도 종료하여 C를 누락할 수 있다. 필요한 ID 집합 {A,B,C}와 실제 수신 ID 집합을 비교하고, 같은 ID의 같은 값은 중복으로 처리하며 다른 값이면 충돌로 보고한다. 이 정책은 실제 전송 라이브러리의 보장이나 실행 결과가 아니다.

먼저 확인할 개념
  • 공유 슬롯과 메시지 완료

    자료 전달 방식과 필요한 작업 ID의 완료·가시성 조건을 함께 읽는다.

  • 결과 의존성

    수집 작업이 모든 생산자 결과를 필요로 하는 의존 관계를 확인한다.

공유한다는 말의 정확한 의미

공유메모리 모형에서는 여러 작업이 같은 객체에 접근하도록 정한다. 스레드마다 계산 도중의 지역 변수는 따로 둘 수 있으며, 일부 배열만 공유할 수도 있다. 같은 책상에 앉는 비유보다 중요한 것은 어느 주소가 어느 객체를 가리키고 누가 읽거나 쓸 수 있는가다. 모든 변수가 자동으로 안전하게 공유된다는 뜻은 아니다.

서로 다른 두 작업이 같은 객체를 수정할 때는 동기화와 언어의 메모리 모형을 지켜야 한다. 락·원자 연산·독립 슬롯과 합류 등으로 필요한 순서를 만든다. 캐시 일관성이 있는 기계에서도 고수준 증가 연산이 자동으로 원자적이지는 않다. C/C++에서 동기화 없는 충돌 접근은 data race로 정의되지 않은 동작을 일으킬 수 있어 결과를 두 값 중 하나로 보장할 수 없다.

메시지는 값과 약속을 전달한다

메시지 전달 모형의 각 작업은 자신의 지역 자료를 계산하고 필요한 정보를 명시적으로 전송한다. 한 프로세스가 지역 x를 바꿨다고 다른 프로세스의 지역 x가 바뀌지는 않는다. 송신·수신에는 상대, 자료 표현, 구분 태그, 버퍼 사용 시점 같은 약속이 필요하다. 이 단원의 종이 예제에서는 메시지가 손상·유실 없이 한 번 도착한다고 가정한다.

메시지 전달은 반드시 두 컴퓨터 사이에서만 쓰는 방식이 아니다. 같은 물리 기계의 여러 프로세스도 메시지 API를 사용할 수 있다. 반대로 분산된 기계 위에서 공유 주소 공간처럼 보이게 만드는 구현도 있다. 모형은 프로그램이 자료와 협력을 표현하는 방식이고, 기계 배치는 구현과 비용을 결정하는 또 다른 축이다.

각자 계산하고 마지막에 합친다

부분합 reduction은 여러 값을 정해진 연산으로 모으는 패턴이다. 공유모형에서는 작업별 슬롯을 쓰고 모든 쓰기의 완료가 보장된 join/barrier 뒤 한 작업이 합친다. 메시지모형에서는 각 작업이 부분합을 보내고 수집자가 필요한 수만큼 받아 합친다. 두 방식 모두 누락·중복·완료 전 읽기를 피하는 절차가 필요하다.

정수의 수학적 합은 묶는 순서를 바꿔도 같지만 실제 정수 타입은 넘침을, 부동소수점은 반올림과 결합 순서를 고려해야 한다. 속도만 비교하기 전에 같은 입력에서 의미상 허용되는 결과를 정한다. 공유 슬롯이나 메시지 버퍼 수가 늘어나면 메모리 사용·복사·대기 비용도 달라진다.

문자열 연산은 교환법칙을 가정하지 않는다. 기본의 메시지 한 번 도착 조건과 별도 중복 오류 모형을 섞지 않는다.

중간 과정을 따라가는 예제

입력[2,5,1,4]를 두 작업이 각각 앞 두 개와 뒤 두 개씩 합친다. 정수 넘침이 없고 최종 합은 두 부분합이 완료된 뒤 계산한다. 두 모형의 자료 흐름을 적어라.

  1. 작업A는2+5=7, 작업B는1+4=5를 자기 지역 변수에서 계산한다.

  2. 공유모형은 A가slot[0]=7,B가slot[1]=5를 쓰고 합류가 끝난 뒤 수집자가 두 슬롯을 읽는다. 서로 다른 슬롯에만 쓰며 완료 순서를 보장한다.

  3. 메시지모형은 A가(id=A,부분합7),B가(id=B,부분합5)를 보낸다. 수집자는 각 id의 값을 한 번씩 모아 두 수를 더한다.

  4. 최종 합7+5=12다. 수집자가 B의 도착 전 A만 더하면7로 끝나므로 완료 조건을 문제에 포함해야 한다.

두 모형 모두12를 얻지만 공유 슬롯과 명시적 전송이라는 자료 전달 절차가 다르다.

조건을 바꾸어 비교하기

도착 순서와 계약 순서

C, A, B로 도착한 문자열을 두 수집 방식으로 연결하라.

  1. 즉시 연결은 c 다음 a 다음 b로 cab다.

  2. ID 슬롯 방식은 A의 a, B의 b, C의 c를 읽어 abc다.

결합법칙만으로 도착 순서를 바꾸어도 된다고 주장할 수 없다.

비교할 점

정수 합과 같은 순서 독립 연산으로 자동 일반화하지 않는다.

횟수와 필요한 집합

별도 중복 모형에서 A, A, B가 도착했다. 종료 조건을 검사하라.

  1. 도착 횟수는 세 번이지만 고유 ID 집합은 {A,B}다.

  2. 필요한 C가 없으므로 아직 완료되지 않았다.

고유 ID별 완료를 기록한다.

비교할 점

기본의 한 번 도착 가정에서 벗어난 별도 오류 감사다.

종이와 본문으로 직접 해보기

종이 상태모형에서 공유 count=0이다. A와B가 각각 읽기→+1계산→쓰기 한다. A읽기0,B읽기0,A쓰기1,B쓰기1을 추적하고, 두 증가를 락으로 직렬화했을 때와 비교하라.

힌트 보기

각 작업이 읽었던 지역 사본을 유지한다. 이 사건열은 C++ 실행 결과를 예측하는 코드가 아니라 읽기/쓰기만 있는 별도 모형이다.

풀이 보기

무동기화 종이 모형은 두 작업이 모두 지역값1을 쓰므로 최종1이다. 락으로 A의 전체 증가 뒤 B의 전체 증가를 두면0→1→2다. 실제 C/C++ 무동기화 data race에는 이 모형의1이라는 결과조차 보장되지 않는다.

오해와 반례

같은 컴퓨터라면 메시지 전달이 불가능하고 공유메모리는 통신 비용이 없다.

동일 기계에서도 프로세스들이 메시지를 주고받을 수 있다. 공유 접근도 캐시 이동·메모리 대역폭·동기화 비용이 있으며 원격 NUMA 접근은 더 비쌀 수 있다. 모형 이름만으로 위치와 비용을 결정하지 않는다.

준비 개념과 학습 목표

준비 개념

  • 배열의 위치 i는 처리할 자료를 구분한다.

  • A→B는 B가A의 결과를 필요로 한다는 의존 간선이다.

  • 같은 시간 단위의 작업 길이를 더하고 가장 긴 의존 경로를 찾는다.

학습 목표

  • 자료 분할과 기능 분할을 구별한다.

  • 의존 DAG와 두 작업자의 시간표를 만든다.

서로 다른 출력 구간이라도 경계 입력은 어디서 올까요?

새 정확 정수 스텐실의 입력은 x=[1,3,5,7,9,11]이다. 범위 밖 입력 x[−1]과 x[6]은 0으로 정한다. 결과 계약은 모든 i=0..5에 대해 초기 입력의 두 이웃 합 y[i]=x[i−1]+x[i+1]이다. 출력은 별도 배열에 쓴다. 왼쪽 작업은 i=0,1,2를 맡고 오른쪽 작업은 i=3,4,5를 맡는다.

왼쪽 작업이 자기 입력 x[0:3]만 갖고 있다면 마지막 출력 y[2]를 위해 오른쪽 첫 입력 x[3]=7이 필요하다. 오른쪽은 첫 출력 y[3]를 위해 왼쪽 마지막 입력 x[2]=5가 필요하다. 이 두 halo 값은 같은 초기 입력 판본에서 전달한다. 완성된 출력은 [3,6,10,14,18,9]다. 출력 구간이 비겹친다는 사실은 경계 입력이 이미 지역에 있다는 뜻이 아니다.

다른 저장 계약으로 i 증가 순서에 따라 입력 배열 자체를 덮어쓰면 결과가 달라진다. 각 반복은 이미 덮인 왼쪽 이웃과 아직 덮지 않은 오른쪽 이웃을 읽어 [3,8,15,24,35,35]가 된다. 원래 스텐실을 보존하려면 처음 입력을 유지하는 별도 출력 또는 필요한 사본을 구성한다. 두 계약의 차이는 실제 data race 실행 결과가 아니라 명시된 순차 상태 추적이다.

자료를 나누는 데이터 병렬

데이터 병렬은 자료 집합의 여러 부분에 같은 종류의 연산을 적용하는 방식이다. 배열의 각 x에2x+1을 계산하는 작업을 위치별로 나눌 수 있다. 반복문의 몸이 같다고 무조건 독립은 아니다. x[i]=2*x[i−1]은 앞 반복의 결과를 필요로 하므로 단순히 모든 i를 동시에 실행하는 변환은 의미를 바꾼다.

읽기 자료와 출력 위치를 구분한다. 입력 배열을 읽기 전용으로 두고 작업마다 겹치지 않는 출력 구간을 맡으면 충돌을 줄일 수 있다. 하지만 스텐실처럼 이웃 입력을 읽는 작업은 자료를 나눠도 경계값 전달이 필요하다. GPU의 SIMD/SIMT 하드웨어와 데이터 병렬 프로그래밍은 관련이 있지만 같은 분류는 아니다.

일을 나누는 태스크 병렬

태스크 병렬은 서로 다른 기능이나 작업 단위를 의존 관계에 맞춰 수행한다. 한 작업은 압축하고 다른 작업은 이미 준비된 자료의 통계를 계산할 수 있다. 함수 이름이 다르다는 이유만으로 병렬 실행이 안전한 것은 아니다. 서로 같은 외부 파일이나 상태를 바꾸는지도 확인한다.

의존 DAG에서 노드는 작업, 간선은 결과를 필요로 하는 순서다. 부모 작업이 완료되어야 자식이 준비된다. 준비된 작업 수와 작업자 수가 실제 동시 실행을 제한한다. 데이터 병렬 작업을 하나의 태스크 내부에 넣거나, 여러 태스크가 자료 블록을 나눠 처리하는 결합도 가능하다.

작업량과 가장 긴 경로

총 작업량 W는 모든 작업 시간의 합이며 span S는 가장 긴 의존 경로 길이다. p명의 동일한 작업자가 있고 다른 비용이 없더라도 완료시간 T_p는 W/p와 S보다 작을 수 없다. 따라서 T_p≥max(W/p,S)다. 이 하한은 언제나 달성된다는 뜻이 아니며 작업의 분할 가능성·스케줄·부하불균형을 더 고려한다.

파이프라인은 자료 하나가 여러 단계 A→B→C를 지나고 서로 다른 자료가 다른 단계에 있는 패턴이다. 첫 자료의 지연은 단계 길이 합이고, 정상 상태의 이상적 처리 간격은 가장 느린 단계에 제한된다. 단일 자료가 단계 수만큼 빨라지는 것으로 읽지 않는다. 대기열·버퍼 용량·의존성이 실제 시간표를 결정한다.

중간 과정을 따라가는 예제

두 동일 작업자, 비선점 작업 A길이2,B길이3,C길이4,D길이1이다. A와B는 처음 준비, C는A뒤,D는B와C뒤다. 추가 비용 없이 시간표와 W,S 하한을 계산하라.

  1. W=2+3+4+1=10이다. 경로A→C→D는2+4+1=7, B→D는3+1=4이므로 S=7이다.

  2. 시각0부터 작업자1이A[0,2), 작업자2가B[0,3)를 실행한다. 시각2에A가끝나 C가준비되므로 작업자1은C[2,6)를 실행한다.

  3. 시각3에B가끝나도D는C를 기다려야 한다. 시각6에두 부모가끝나 D[6,7)를 한 작업자가 실행한다.

  4. 완료7은 max(10/2,7)=7 하한을 달성한다. B가끝난 시각3에D를 시작하는 시간표는 의존 조건을 위반한다.

이상적 완료시간7, 작업량10, span7이다. 실제 실행을 측정한 값이 아니다.

  2. 왼쪽 출력은 [3,6,10], 오른쪽 출력은 [14,18,9]다.

준비 개념과 학습 목표

준비 개념

  • 완료시간은 서로 병렬인 길이의 최댓값과 순차 비용의 합으로 계산한다.

  • 전송 시작 비용 α와 바이트당 비용 β를 구분한다.

  • T1/Tp는 speedup이고 이를p로 나누면 efficiency다.

학습 목표

  • 명시한 비용 모형으로 두 설계를 비교한다.

  • 같은 모델 이름보다 자료 위치·입도·의존성을 기준으로 선택한다.

작업을 더 잘게 나누면 어떤 비용 경계에서 순위가 바뀔까요?

새 비용 모형의 독립 비선점 작업 길이는 순서대로 [8,1,1,1,1,1] 시간단위다. 동일한 작업자는 두 명이며 모든 입력은 처음 준비된다. 작업자 사이의 통신과 동기화 비용은 0으로 정한다. 아래 준비 비용과 계산 시간은 겹치지 않으며 그 밖의 비용은 없다. 굵은 설계는 처음 세 작업과 뒤 세 작업을 각각 한 작업자에게 고정 배정하여 계산 구간 길이가 10과 3이다.

잘게 나눈 설계는 여섯 작업을 개별 배정한다. 길이 8인 작업을 한 작업자에게 주고 나머지 다섯 작업을 다른 작업자에게 주면 계산 구간은 8이다. 총 작업량 13의 절반과 가장 긴 작업 길이 8의 최댓값은 8이므로 이 조건에서 최소 계산 시간을 달성한다. 이것은 모든 자동 큐 정책의 보장이 아니라 명시된 배정의 시간표다.

모든 작업을 시작하기 전에 묶음 하나당 준비 비용 α를 직렬로 지불하는 별도 규칙을 추가한다. 굵은 설계는 두 묶음이므로 전체 시간이 2α+10이다. 개별 설계는 여섯 묶음이므로 6α+8이다. α≥0에서 두 값은 α=1/2일 때 11로 같다. α=1/4이면 개별 설계의 19/2가 굵은 설계의 21/2보다 작지만, α=1이면 개별 설계의 14가 굵은 설계의 12보다 크다. 준비와 계산이 겹치는 다른 규칙에는 이 단순 합을 그대로 적용하지 않는다.

  • 분할 불가능 작업의 하계

계산 바깥의 시간

병렬화에는 작업 생성, 동기화, 자료 전송, 결과 모으기, 캐시 이동 등의 비용이 있다. 종이 비용모형을 T_p=직렬 부분+최대 작업자 계산+추가 비용으로 정하면 각 항이 중복되지 않게 범위를 정한다. 통신이 계산과 겹치는 구현이라면 단순 합보다 사건 시간표가 필요하다. 이 단원 비교에서는 겹침이 없다고 명시한다.

메시지 n바이트의 단순 지연모형 t=α+βn은 시작 지연과 전송량 영향을 구별한다. α는 시간, β는 시간/바이트다. 이것은 실제 네트워크의 혼잡·토폴로지·프로토콜을 모두 설명하는 법칙이 아니다. 같은 총 바이트라도 메시지를 잘게 나누면 시작 비용을 여러 번 낸다.

부하와 입도의 균형

공유모형은 명시 전송을 줄일 수 있지만 경합·false sharing·NUMA 위치와 메모리 대역폭 영향을 받는다. 메시지모형은 자료 소유권을 명시해 큰 자료를 여러 노드에 분산하기 좋지만 배치와 경계 전송을 설계해야 한다. 한 노드 안에서는 공유 스레드, 노드 사이에서는 메시지를 쓰는 hybrid도 있다. 어느 쪽이 모든 입력에서 빠르다고 단정하지 않는다.

큰 작업 묶음은 시작 비용을 아끼지만 작업 길이가 달라지면 한 작업자만 오래 남을 수 있다. 작은 묶음은 동적 배분으로 균형을 개선하되 큐·전송 비용을 늘린다. 분석해야 할 것은 작업 개수뿐 아니라 각 작업 시간, 자료 위치와 경계 데이터량이다. 먼저 결과 정확성을 보장하고 나서 모델 비용을 비교한다.

선택의 근거를 쓰는 방법

고정된 문제에서 순차 시간 T1과 병렬 시간 Tp가 같은 일을 한다면 speedup=T1/Tp다. p를 증가시켜도 직렬 부분과 추가 비용이 남아 무한히 빨라지지 않는다. 효율 T1/(pTp)은 실제 전력 효율과 다른 수치이며 p개의 자원을 시간상 얼마나 잘 썼는지 보는 비율이다.

모형의 승자를 실제 벤치마크의 승자라고 표시하지 않는다. 후보를 선택할 때는 입력 규모, 반복 횟수, 전송 묶음, 정수/실수 결과 조건, 하드웨어와 측정 범위를 기록한다. 실제 측정이 없는 경우 아래 숫자는 판단 연습의 가정값이다. 알고리즘이 달라져 총 작업량 자체가 변하면 같은 T1과 공정하게 비교하는지도 점검한다.

  1. 굵은 설계는 한 작업자가 놀아도 최대 계산 시간 10이 남아 전체 2α+10이다.

  2. 개별 설계는 길이 8 작업과 다섯 작은 작업을 나누어 최대 계산 시간 8을 달성하며 전체 6α+8이다.

이 입력과 비선점 조건에서는 세 번째 작업자가 두 설계의 계산 시간을 더 줄이지 않는다.

풀이와 답 확인
