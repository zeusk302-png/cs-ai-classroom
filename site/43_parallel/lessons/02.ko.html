소단원 2.1

코어·벡터·하드웨어 스레드

두 코어에 네 스레드가 보인다면 네 개의 덧셈 장치가 있는가?

준비 개념과 학습 목표

준비 개념

  • 코어는 명령을 해석하고 실행하는 처리 단위다. 레지스터와 PC는 현재 값과 다음 명령 위치를 기억하는 실행 문맥이다. 여러 문맥이 같은 실행 장치를 공유할 수 있다.
  • 벡터는 순서 있는 값 묶음이고 lane은 한 원소 자리다. 128비트 벡터에 32비트 원소를 넣으면 128/32=4 lane이다. 이 폭 계산이 매 사이클 완료량을 자동 보장하지는 않는다.
  • 자가진단: 두 계산 창구가 각각 한 번에 네 항목을 처리하면 최대 여덟 항목이다. 창구별 대기표가 두 장씩 있다고 처리 창구가 네 개가 되지는 않는다.

학습 목표

  • 코어·SIMD lane·하드웨어 문맥을 구별한다.
  • 공유 자원을 명시한 처리량 모형을 계산한다.
  • 지연 숨김과 연산 장치 추가의 차이를 설명한다.

서로 다른 병렬성의 자리

멀티코어는 여러 코어가 서로 다른 명령 흐름을 실행할 수 있는 구조다. SIMD는 한 벡터 명령이 여러 데이터 자리에 같은 종류의 연산을 적용하는 방식이다. 같은 덧셈이어도 lane마다 피연산자와 결과는 다르다. 코어 내부에는 여러 실행 장치가 있을 수도 있어 코어 하나를 덧셈기 하나와 항상 동일시하지 않는다.

하드웨어 스레드는 독립된 실행 문맥을 칩 안에 유지하는 기능이다. 운영체제의 소프트웨어 스레드는 스케줄되는 프로그램 단위이며, 많은 소프트웨어 스레드가 적은 하드웨어 문맥에 번갈아 배정될 수 있다. 운영체제가 보여 주는 논리 CPU 수만으로 물리 코어·벡터 장치 수를 알 수 없다.

문맥을 늘려 기다림을 숨긴다

교차 멀티스레딩에서는 한 문맥이 데이터를 기다릴 때 다른 문맥의 명령을 선택할 수 있다. SMT에서는 같은 사이클에 여러 문맥의 명령을 서로 다른 이용 가능한 실행 자원에 발행할 수도 있다. 어느 경우든 공유 포트·캐시·벡터 장치의 용량은 따로 정해야 한다.

문맥 추가는 메모리 응답 자체를 빨리 오게 만들지 않는다. 준비된 다른 일을 수행해 장치의 빈 시간을 줄이는 것이 지연 숨김이다. 두 문맥이 같은 연산 포트를 모두 요구하면 서로 경쟁하며, 단일 스레드의 완료 지연은 오히려 늘 수도 있다.

가상 처리율의 조건

여기서는 두 코어가 각각 4-lane 벡터 덧셈 하나를 매 사이클 시작하고 완료하는 가상 기계를 정의한다. 각 코어에 두 하드웨어 문맥이 있지만 벡터 장치는 공유한다. 입력은 이미 준비되고 출력 위치는 서로 다르며 의존성·메모리·분기·발행 비용을 제외한다. 한 사이클의 최대 유효 덧셈은 2×4=8이다.

독립 덧셈 24개를 세 벡터 묶음씩 두 코어에 배정하면 세 사이클이다. 문맥 수까지 곱한 16개/사이클은 이 계약과 맞지 않는다. 마지막 묶음의 빈 lane과 준비 안 된 입력은 유효 처리량을 줄이며, 실제 기계의 지연·처리 간격은 ISA와 구현 문서 및 측정을 따로 확인해야 한다.

중간 과정을 따라가는 예제

위 두 코어·4-lane·코어당 공유 벡터 장치 하나에서 독립 덧셈 24개를 처리한다. 각 덧셈은 정확한 정수 모형이고 입력 준비·단위 사이클 완료를 가정한다.

  1. 24개를 네 원소 묶음 여섯 개로 나눈다.
  2. 첫 사이클에 코어 0은 번호 0~3, 코어 1은 4~7을 처리한다.
  3. 둘째는 8~11/12~15, 셋째는 16~19/20~23을 처리한다.
  4. 한 사이클에 최대 8개이므로 최소 ceil(24/8)=3이며 이 배정이 하계를 달성한다.

세 사이클이다. 네 하드웨어 문맥은 네 개 벡터 장치를 뜻하지 않는다.

종이와 본문으로 직접 해보기

같은 기계에서 독립 덧셈 18개를 묶는다. 필요한 사이클, 마지막 사이클의 유효 lane 수, 전체 lane 이용률을 종이에 구한다.

힌트 보기

전체 제공 lane 자리는 사이클 수×8이다. 유효 연산은 정확히 18개이고 범위 밖 원소를 읽는 빈 lane은 허용하지 않는다.

풀이 보기

ceil(18/8)=3 사이클이다. 첫 두 사이클은 8개씩, 마지막은 2개다. 유효 lane 이용률은 18/24=3/4이다. 남은 lane은 마스크하거나 별도 꼬리 처리로 보호해야 한다.

오해와 반례

하드웨어 스레드를 두 배 늘리면 최대 산술 처리량도 두 배가 된다.

두 문맥이 하나의 4-lane 장치를 공유하는 위 모형의 상한은 여전히 코어당 4다. 이미 장치가 매 사이클 바쁘면 문맥 추가로 더 많은 덧셈을 완료할 수 없다.

한 단계 더

심화 증명: 양의 정수 p개의 동일 코어가 각 사이클 양의 정수 v개까지의 유효 독립 연산을 완료한다면 t사이클 동안 완료량은 pvt 이하라 양의 정수 n개에는 t≥ceil(n/(pv))가 필요하다. 모든 입력이 준비되고 임의 분할과 마지막 lane 마스크가 가능하면 이 하계를 달성한다. 하드웨어 문맥 h는 이 자원 계수에 포함되지 않는다. 대신 문맥별 대기 때문에 일부 사이클을 쓰지 못하면 실제 완료량이 줄어든다. 명령의 지연이 여러 사이클이되 매 사이클 발행 가능한 파이프라인에서는 초기/마지막 지연도 포함해야 하므로 위 단위 완료 모형과 구별한다.

소단원 2.2

명령·데이터 병렬성

같은 네 덧셈을 두 개씩 묶어도 의존 화살표 하나가 결과를 바꿀까?

준비 개념과 학습 목표

준비 개념

  • 명령은 입력을 읽어 결과를 만드는 한 단계다. A의 결과를 B가 사용하면 A→B라는 데이터 의존성이 있다. 사이클은 가상 시간 단위이며 실제 초로 환산하려면 주파수·기계 비용이 필요하다.
  • 데이터 병렬성은 여러 원소에 같은 계산을 적용할 수 있는 성질이다. y[i]=x[i]+1의 서로 다른 i는 출력이 별도이고 입력이 변하지 않는다는 조건에서 독립이다.
  • 자가진단: a=x+1, b=y+1, c=a+b에서 a와 b는 먼저 함께 가능하지만 c는 둘의 결과를 기다린다.

학습 목표

  • ILP와 데이터 병렬성의 정의를 의존성으로 설명한다.
  • 단위 비용 DAG의 발행 시간표를 만든다.
  • 재배치·벡터화가 허용되는 의미 조건을 구별한다.

한 흐름 안의 독립 명령

명령 수준 병렬성 ILP는 하나의 명령 흐름 안에서 동시에 진행할 수 있는 독립 명령이 있다는 성질이다. superscalar 구현은 여러 명령을 발행할 수 있지만, 의존 결과를 먼저 읽거나 프로그램에서 관찰할 결과를 바꿀 수 있다는 뜻은 아니다. 프로그램 순서와 내부 실행 순서가 다를 때도 정해진 언어·ISA 의미를 유지해야 한다.

여기서 쓰는 가상 DAG는 부작용 없는 정확한 정수 연산만 가진다. 모든 입력은 처음부터 준비되고 각 노드는 한 사이클이다. 한 사이클에 최대 두 노드를 실행하며 부모가 이전 사이클 끝까지 완료되어야 자식을 시작한다. 분기 예측·메모리 별칭·예외·장치 접근은 이 단순 모형에 들어 있지 않다.

같은 계산을 여러 값에 적용한다

독립 원소의 y[i]=x[i]+1은 데이터 병렬이다. 4-lane 명령은 네 입력에 같은 덧셈을 적용할 수 있다. 그러나 x와 y가 겹치는 뷰이고 이전 출력이 다음 입력을 바꾸거나 누적합처럼 s[i]=s[i−1]+x[i]라면 독립성 증명이 달라진다. 이름이 다른 배열이라는 설명만으로 실제 저장 공간의 비겹침이 보장되지 않는다.

재배치에는 값의 의미도 필요하다. 정확한 정수 덧셈에서 수학적 결합법칙이 성립해도 고정폭의 overflow 계약이나 부동소수점의 반올림은 별도다. 실수 합을 병렬 트리로 바꾸면 순차 합과 비트 결과가 다를 수 있다. 허용 오차·재현 요구 또는 동일 순서를 명시하지 않고 모든 reduce의 결과가 같다고 주장하지 않는다.

의존 그래프로 계산한다

완전한 예제는 a=x+1, b=y+1, c=a+b, d=a−b, e=c+d다. 입력 x=2, y=5이고 다섯 노드 비용이 각각 한 사이클이다. a/b, c/d, e의 세 층을 실행하면 결과 a=3, b=6, c=9, d=−3, e=6이다. 두 실행 장치에 필요한 작업량 하계 ceil(5/2)=3과 길이 3의 의존 사슬 하계가 일치한다.

둘 이상의 독립 원소에 이 그래프를 적용하면 각 원소 내부의 세 층과 원소 사이 병렬성을 함께 이용할 수 있다. 코어·벡터·ILP는 서로 배타적인 분류가 아니다. 하지만 계층별 자원과 의존 관계를 명시해야 하며 벡터 lane 수가 하나의 의존 사슬의 길이를 자동으로 줄이지는 않는다.

중간 과정을 따라가는 예제

x=2, y=5에서 a=x+1, b=y+1, c=a+b, d=a−b, e=c+d를 위 두 장치 가상 DAG로 처리한다.

  1. 입력만 필요한 a와 b를 사이클 1에 수행해 3,6을 얻는다.
  2. a, b가 준비되어 사이클 2에 c=9, d=−3을 수행한다.
  3. 사이클 3에 e=9−3=6을 계산한다.
  4. 다섯 작업의 용량 하계 3과 a→c→e 사슬 3이 있으므로 두 사이클은 불가능하다.

최소 세 사이클, e=6이다. 결과 값과 시간 하계는 다른 검사의 답이다.

종이와 본문으로 직접 해보기

추가 노드 f=x−y를 입력에서 직접 계산하고 e가 c+d+f를 하나의 새 단위 연산으로 읽는 가상 계약으로 바꾼다. 두 장치에서 여섯 노드의 세 사이클 달성이 가능한지 시간표를 만든다.

힌트 보기

e의 세 부모가 준비되어야 한다. 세 입력 노드 a, b, f를 두 자리에 모두 한 사이클에 넣을 수는 없다.

풀이 보기

사이클 1 a, b; 사이클 2 c, d; 사이클 3 f; 사이클 4 e라는 배정은 4다. 더 좋은 배정은 1:a, b, 2:c, f, 3:d, 4:e 또는 1:a, f,2:b,3:c, d,4:e로도 4다. 3에 e를 끝내려면 c, d, f가 2까지 끝나야 하지만 a, b 이후 c, d와 f를 모두 두 번째 사이클의 두 자리에 넣을 수 없어 불가능하다. e=9−3−3=3이다.

오해와 반례

두 장치라면 작업량을 2로 나눈 올림이 언제나 실행시간이다.

활동의 여섯 노드는 작업량 하계 3이지만 의존성과 준비 시각 때문에 4가 필요하다. 하계가 항상 달성 가능한 시간표는 아니다.

소단원 2.3

메모리 대역폭과 병목

코어가 열 배 빨라져도 배열 덧셈 시간이 거의 같을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 대역폭 B는 어떤 경계를 통과하는 바이트 수/시간이다. 지연은 한 요청이 기다리는 시간이다. GB는 10^9 byte, GFLOP은 10^9 부동소수점 연산으로 정한다.
  • FLOP은 연산을 세는 관례다. 여기서는 덧셈 1회=1 FLOP이고 곱셈 뒤 덧셈 2회=2 FLOP이다. 명령 수와 같지 않을 수 있다.
  • 자가진단: 120 byte를 60 byte/s 경계로 옮기는 시간 하계는 2 s다. 빠른 덧셈기만 추가해 이 경계가 넓어지지는 않는다.

학습 목표

  • 트래픽 경계와 산술 집약도 I=F/Q를 정의한다.
  • 처리율 상계 min(P, BI)를 단위로 유도한다.
  • 캐시·write allocation·간섭과 실제 측정 범위를 구별한다.

연산과 데이터가 각각 시간을 요구한다

n개의 32비트 원소를 가진 두 배열을 읽어 세 번째에 더하는 y[i]=a[i]+b[i]를 보자. DRAM 경계에서 각 입력을 한 번씩 읽고 출력을 한 번만 쓰며 추가 전송이 없다는 가상 계약이면 F=n FLOP, Q=12n byte다. 출력의 read-for-ownership나 캐시 라인 여분, 재읽기가 실제로 발생하면 Q가 늘어난다.

전체 시간 T>0 동안 연산 능력이 최대 P FLOP/s, 해당 경계의 이동 능력이 최대 B byte/s라면 T≥F/P와 T≥Q/B다. 겹침 가능한 이상적 상계는 T≥max(F/P, Q/B)다. 직렬로 두 비용을 모두 치르면 더 길어질 수 있다. 상계의 도달은 별도 문제이며 작은 문제의 시작 비용과 의존 지연도 남는다.

Roofline을 단위로 유도한다

F>0, Q>0에서 집약도 I=F/Q는 FLOP/byte다. 처리율 F/T는 P 이하이며 T≥Q/B에서 F/T≤BF/Q=BI다. 따라서 처리율≤min(P, BI)이다. B의 byte/s와 I의 FLOP/byte가 곱해 FLOP/s가 되는지 단위를 검사하면 계산 오류를 줄인다.

같은 알고리즘도 DRAM과 L1 경계에서 Q가 다르므로 집약도와 대역폭을 서로 다른 계층에서 섞으면 안 된다. 캐시 재사용은 DRAM의 Q를 줄일 수 있지만 실제로 필요한 값을 재사용할 수 있는 알고리즘과 공간 조건이 있어야 한다. 코어 추가로 P만 커지고 공유 B가 그대로이면 메모리 경계 상한은 그대로다.

가상 수치와 진단의 한계

n=10^8, P=100 GFLOP/s, B=60 GB/s라는 가상 값을 사용한다. F=0.1 GFLOP, Q=1.2 GB, I=1/12 FLOP/byte다. 계산 하계 0.001 s, 이동 하계 0.02 s라 처리율 상계 5 GFLOP/s이다. 이 숫자는 컴퓨터를 측정한 결과가 아니다.

지연이 길면 많은 독립 요청으로 처리량을 높일 수 있지만 B에 닿은 뒤 요청 수만 늘려서는 상한을 넘지 못한다. 충분한 동시 요청·정렬·지역성이 없으면 B에도 못 미친다. 실제 진단에는 입력 크기·캐시 상태·스레드 배치·자료형·FLOP 세기·쓰기 정책·측정 구간과 간섭을 고정해야 한다.

중간 과정을 따라가는 예제

위 n=10^8 배열 덧셈의 가상 DRAM 모형에서 시간 하계와 처리율 상계를 구한다. P만 200 GFLOP/s로 높이면 어떻게 되는가?

  1. 원소당 두 입력 8 byte와 출력 4 byte로 Q=12×10^8=1.2 GB다.
  2. F=10^8=0.1 GFLOP이고 I=1/12 FLOP/byte다.
  3. F/P=0.001 s, Q/B=0.02 s라 T≥0.02 s 및 F/T≤5 GFLOP/s다.
  4. P를 200으로 높이면 계산 하계 0.0005 s지만 이동 하계 0.02 s는 남는다.

두 경우 모두 시간 하계 20 ms/처리율 상계 5 GFLOP/s다. 실제 시간이 정확히 20 ms라는 보장은 아니다.

종이와 본문으로 직접 해보기

다른 가상 알고리즘은 F=2 GFLOP, Q=1 GB다. P=100 GFLOP/s, B=60 GB/s에서 I, 시간 하계, 두 병목의 상계를 구한다. 같은 F에서 Q를 0.5 GB로 줄이면?

힌트 보기

I는 F/Q이고 시간 하계는 두 몫의 큰 값이다. 단위에 G를 양쪽 동일하게 쓴다.

풀이 보기

처음 I=2 FLOP/byte, 연산 20 ms/이동(1/60)s≈16.67 ms, 처리율 상계min(100,120)=100 GFLOP/s다. Q절반은 I=4/이동≈8.33 ms지만 연산 20 ms 하계가 남아 상계 100은 같다.

오해와 반례

Roofline 아래에 있으면 원인은 무조건 메모리 대역폭 부족이다.

의존 사슬·발행 포트·분기·불균등 작업·시작 비용 때문에 두 상계 모두 못 채울 수 있다. 상계는 가능 성능의 한계이며 원인 하나를 확정하는 측정이 아니다.
