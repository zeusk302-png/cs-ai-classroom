소단원 6.1

reduction·scan·map

여러 숫자를 변환하기, 하나로 합치기, 누적 목록 만들기는 같은 작업일까?

준비 개념과 학습 목표

준비 개념

  • 배열의 인덱스는 0부터 시작한다. map은 각 항목의 함수 값을 별도 출력 위치에 쓴다.

  • 결합법칙은 (a ⊕b)⊕c =a ⊕(b ⊕c), 항등원은 e ⊕a =a ⊕e =a다.

학습 목표

  • 세 패턴의 출력 형태를 구별한다.

  • 결합법칙· 순서 보존 조건을 확인하고 prefix를 손 계산한다.

빈 칸이 생기는 map도 순서를 보존해 압축할 수 있을까요?

새 입력 레코드의 ID는 순서대로 A,B,C,D,E,F이고 선택 표지는 [1,0,1,1,0,1]이다. 선택된 레코드를 원래 순서로 압축한다. 표지의 exclusive 합 [0,1,1,2,3,3]은 각 레코드 앞에 선택된 개수다. 표지가 1인 레코드만 그 위치에 쓰면 A,C,D,F를 얻고 전체 선택 수는 4다. 표지가 0인 B와 E는 출력에 쓰지 않는다. 마지막 exclusive 값 3을 전체 선택 수로 오해하면 마지막 F의 공간을 놓친다.

순서를 보존하는 결합 연산도 덧셈과 다를 수 있다. 새 상태 변환은 f(x)=2x+1, g(x)=3x, h(x)=x−4다. 입력 순서 f,g,h는 먼저 f를 적용하고 이어 g와 h를 적용한다. 두 변환을 합칠 때 왼쪽 변환 다음 오른쪽 변환이라는 순서를 유지한다. 함수 합성은 결합적이어서 괄호를 바꾸어도 전체 6x−1이지만 순서를 g,f,h로 바꾸면 6x−3이다. 결합 법칙과 교환 법칙은 다르다.

분절 합은 새 값 [2,3,5,7,11]과 시작 표지 [1,0,1,0,0]을 사용한다. 시작 표지가 1인 항목에서 누적을 다시 시작하면 inclusive 분절 합은 [2,5,5,12,23]이다. 두 구간 요약 (a,p)와 (b,q)의 결합을 q가 1이면 (b,p∨q), q가 0이면 (a+b,p∨q)로 정의한다. 요약의 표지는 구간 안에 시작점이 하나라도 있었는지 표시하고 값은 마지막 분절의 합이다. 오른쪽 구간에 시작점이 있으면 왼쪽 누적을 버린다는 뜻이다. 항등원은 (0,0)이며 구간 연결의 의미로 결합 법칙을 증명한다. 실제 OpenMP가 이 요약을 실행했다는 주장은 아니다.

먼저 확인할 개념
  • exclusive 위치와 전체 수

    기본의 항목 전 누적 및 별도 total을 선택 표지에 적용한다.

  • 출력 소유권과 정확한 연산

    선택 항목만 쓰는 구간과 정수 범위·순서 조건을 확인한다.

서로 독립인 변환

입력 [3,1,4,2]의 각 수를 제곱하면 map의 출력은 [9,1,16,4]다. 각 출력이 자기 입력만 읽으면 항목별 계산은 독립이다. 여러 작업자가 각기 다른 출력 칸을 맡는 그림으로 생각할 수 있다.

다른 출력 칸에 쓴다는 것만으로 모든 map이 안전한 것은 아니다. 함수가 하나의 공유 카운터를 갱신하거나 다른 항목의 최신 출력 값을 읽으면 추가 의존과 동기화가 생긴다. 여기서는 입력이 변하지 않고 함수에 공유 쓰기 부작용이 없다고 가정한다.

하나의 결과와 모든 접두 결과

reduction은 여러 값을 하나로 합친다. 덧셈으로 (3 +1)+(4 +2)=4 +6 =10이다. 결합 법칙이 성립하면 괄호 모양을 바꾸어 나뭇가지별 부분 합을 동시에 계산할 수 있다. 빈 입력의 합은 항등원 0으로 정의한다.

scan은 각 접두 구간의 합을 모두 돌려준다. inclusive는 현재 항목까지 포함해 [3,4,8,10], exclusive는 현재 항목 전에 멈춰 [0,3,4,8]이다. 출력 길이는 이 정의에서 입력 길이 4와 같다. 전체 합 10을 별도 반환하는 인터페이스도 있으므로 exclusive 마지막 값 8을 전체 합으로 오해하지 않는다.

괄호와 순서는 따로 확인한다

문자열 연결은 결합법칙이 있지만 교환법칙은 없다. 입력 순서를 유지해 괄호만 바꾸면 abc를 얻지만 항목을 재배열하면 bac가 된다. 그래서 결합법칙만으로 임의 순서 섞기까지 허용하지 않는다. OpenMP scan의 논리 반복 순서와 일반 reduction의 결합 선택도 구별한다.

유한 정밀도 실수 덧셈은 정확한 실수 덧셈처럼 항상 결합적이지 않다. 순서가 바뀌는 구현에 비트 단위 동일 결과를 요구하려면 별도 재현성 설계가 필요하다. 이 단원의 작은 정수 합은 표현 범위를 넘지 않는 정확한 산술로 계산한다.

시작점 뒤의 이전 분절 합을 버린다.

표지는 정수 0 또는 1이다. 미선택 항목의 exclusive 위치가 다른 항목과 같아도 실제 쓰기를 수행하지 않는다. 함수 합성은 왼쪽 다음 오른쪽이라는 방향을 고정하고, 분절 요약의 값은 구간 전체 합이 아니라 마지막 분절 합이다.

중간 과정을 따라가는 예제

[3,1,4,2]의 제곱 map, 합 reduction, inclusive/exclusive scan을 구하라.

  1. 각 항목을 제곱해 9,1,16,4를 얻는다.

  2. 첫 두 값의 합 4와 다음 두 값의 합 6을 합쳐 10을 얻는다.

  3. inclusive 누적 상태는 3 →4 →8 →10이다.

  4. exclusive는 더하기 전 상태를 쓰므로 0 →3 →4 →8이다.

표지의 exclusive 합으로 압축 결과를 구성하라.

  1. A,C,D,F의 위치는 각각 0,1,2,3이다. B와 E는 표지가 0이므로 쓰지 않는다.

오른쪽 시작점이 지우는 누적

앞 구간 [2,3]과 뒤 구간 [5,7,11]의 분절 요약을 결합하라.

  1. 앞 구간 요약은 (5,1), 뒤 구간은 첫 항목이 새 분절이라 (23,1)이다.

  2. 오른쪽 표지가 1이므로 결합은 (23,1)이다. 총 입력 합 28과 다르다.

전체 구간 요약의 값은 마지막 분절 합 23이다.

비교할 점

요약의 뜻을 전체 합으로 바꾸면 결합식의 리셋 조건을 잃는다.

종이와 본문으로 직접 해보기

각 항목의 길이가 [2,0,3,1]인 네 묶음을 이어 붙이려 한다. 시작 위치와 전체 저장 길이를 구하라.

힌트 보기

항목 전까지 사용한 길이는 exclusive 합이고 마지막 묶음 길이는 따로 더한다.

풀이 보기

시작 위치는 [0,2,2,5], 총 길이는 6이다. 길이 0 묶음과 다음 묶음은 시작 2를 공유해도 빈 구간이므로 쓰기 겹침이 아니다. 양의 길이 묶음은 [0,2),[2,5),[5,6)에 쓴다.

오해와 반례

scan의 마지막 항목은 언제나 전체 합이다.

현재 항목을 포함하는 inclusive에서는 그렇지만 exclusive [0,3,4,8]의 마지막은 8이다. 현재 마지막 입력 2를 더해야 전체 10이다.

연습 1 · 값과 상태 예측

초기값 x=1에서 f,g,h를 순서대로 적용하라. 괄호를 바꾸거나 g,f,h로 재배열하면 어떤가?

힌트 1

먼저 f(1), 이어 g, 마지막 h를 계산한다.

힌트 2

괄호와 항목 순서 변경을 구별한다.

풀이와 답 확인

  1. 입력 순서에서는 1→3→9→5이며 합성 6x−1에 1을 넣어도 5다.

  2. 순서를 g,f,h로 바꾸면 1→3→7→3이다. 괄호 변경만 하면 원래 5를 유지한다.

괄호만 바꾸면 5이고 순서 변경 사례는 3이다.

힌트 2

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

분절 요약의 항등원과 결합 법칙을 구간 의미로 설명하라. 빈 선택 입력의 압축도 정의하라.

힌트 1

요약은 마지막 시작점 이후의 합과 시작점 존재를 저장한다.

힌트 2

빈 구간은 합 0이고 시작점이 없다.

풀이와 답 확인

  1. 빈 요약 (0,0)을 왼쪽 또는 오른쪽에 결합해도 값과 표지가 그대로다.

  2. 세 구간을 연결한 결과의 마지막 시작점이 어디에 있든 그 뒤 합과 시작점 존재는 괄호에 의존하지 않는다. 따라서 이 결합은 결합적이다.

  3. 빈 선택 입력의 위치 목록과 압축 출력은 모두 빈 목록이며 전체 수는 0이다.

구간 의미를 유지하는 요약은 결합적이며 빈 경우도 정의된다.

흔한 오답에서 다시 생각하기

시작점이 있는 구간 요약은 앞에서 합친 뒤 다시 계산해야 하므로 결합적이지 않다.

요약에 시작점 존재와 마지막 분절 합을 모두 보관하므로 필요한 리셋 정보가 유지된다.

한 단계 더

n 개 접두 합을 각각 처음부터 다시 계산하면 exclusive 덧셈 수는 0 +1 +… +(n −1)=n(n −1)/2로 이차 작업량이다. n =4면 6이다. 트리 기반 scan은 적절한 결합 연산 조건에서 선형 작업량과 로그 임계경로를 달성할 수 있다. 단순히 동시에 시작했다는 이유만으로 작업 효율적이라고 판단하지 말자.

소단원 6.2

병렬 정렬·stencil

양쪽을 동시에 정렬하면 마지막 합치기도 자동으로 빨라질까?

준비 개념과 학습 목표

준비 개념

  • 정렬은 같은 원소들을 순서 있게 재배열한다. merge는 이미 정렬된 두 목록을 합친다.

  • stencil은 가까운 이웃 값을 읽어 새 격자 값을 만드는 규칙이다.

학습 목표

  • 독립 재귀와 합병 의존을 나눈다.

  • 이전 단계와 다음 단계의 배열을 구별하여 stencil을 계산한다.

합병의 동률과 이웃의 세대는 결과에 어떤 흔적을 남길까요?

새 정렬 입력은 [(2,a),(4,c),(4,e),(1,b),(4,d),(5,f)]다. 두 연속 절반을 각각 안정 정렬한 뒤 합병한다. 각 절반의 정렬도 같은 키의 원래 ID 순서를 보존한다. 키가 같을 때 왼쪽 절반을 먼저 선택하면 같은 키 4의 원래 순서 c,e,d를 유지한다. 오른쪽 절반을 먼저 선택하면 d,c,e가 되어 키 정렬은 맞아도 안정성 계약은 깨진다. 입력 절반은 원래 연속 구간이라는 전제를 명시한다.

새 격자는 [0,6,0,3,0]이며 양끝은 매 단계 0으로 고정한다. 내부는 이전 왼쪽·자기·오른쪽의 평균이다. 첫 동시 결과는 [0,2,3,1,0], 둘째는 [0,5/3,2,4/3,0]이다. 원래 입력을 왼쪽부터 같은 배열에 덮어쓰면 첫 내부 2 뒤 가운데가 5/3, 마지막 내부가 14/9가 된다. 쓰기 칸이 서로 달라도 읽는 세대가 바뀌면 다른 규칙이다.

별도 주기 경계 모형은 다섯 칸 모두를 갱신하며 끝 이웃을 반대 끝으로 감싼다. 같은 초기 배열의 첫 결과는 [2,2,3,1,1]이고 합 9를 보존한다. 각 이전 항목이 세 출력에 한 번씩 1/3 가중치로 나타나기 때문이다. 고정 끝 모형의 첫 합은 6으로 줄며, 일반적으로 양끝이 0일 때 한 단계 합은 이전 내부 합에서 (첫 내부+마지막 내부)/3을 뺀 값이다. 경계 계약을 바꾼 두 결과를 같은 알고리즘의 구현 차이로 보고하지 않는다.

  • 결합과 순서 보존

작은 정렬과 마지막 합병

입력 [7,2,5,1]을 둘로 나누면 왼쪽 [7,2]와 오른쪽 [5,1]의 정렬은 서로 독립이다. 둘 다 끝난 뒤 [2,7]과 [1,5]를 합병한다. 한쪽이 아직 정렬되지 않았는데 합병하면 전제부터 깨진다.

합병은 작은 머리 원소를 꺼내고 남은 목록의 머리와 다시 비교한다. 현재의 단순 합병은 순차적이다. 재귀를 병렬로 실행해도 루트 합병이 긴 의존 경로가 될 수 있다. 더 낮은 임계경로를 원하면 합병 자체도 별도로 병렬화해야 한다.

한 단계의 이웃 규칙

자체 1 차원 격자 [0,3,6,9,0]에서 양 끝은 0으로 고정한다. 내부 새값은 이전 왼쪽· 자기· 오른쪽의 평균이다. 새 배열의 각 칸은 동일한 이전 배열만 읽으므로 세 내부 계산을 동시에 해도 같은 결과다.

입력 배열을 읽으면서 같은 배열에 새 값을 덮어쓰면 늦게 계산하는 칸은 이미 바뀐 이웃을 읽는다. 이는 다른 반복 법일 수 있지만 여기서 정의한 동시 갱신 규칙과 같지 않다. 두 배열을 쓰고 전체 한 단계가 끝난 후 역할을 교환한다.

경계와 연결 지점

경계 조건이 주기적 감싸기인지 고정 값인지에 따라 처음과 마지막 이웃이 달라진다. 배열 길이와 접근 범위를 먼저 정한다. 분할 영역 경계에서는 옆 작업자가 보유한 이전 값을 복사한 halo가 필요할 수 있다.

한 단계 내부는 독립이어도 다음 단계는 이전 단계의 완료에 의존한다. 두 단계 사이 장벽이나 동등한 의존 관리를 생략하면 세대가 섞일 수 있다. 정렬 역시 재귀 두 자식의 완료라는 같은 연결 문제를 가진다.

새 단위 비용 DAG G에는 선행자가 없는 A,B,C,D와, 이 네 작업 모두가 끝나야 시작하는 E, E 뒤의 F가 있다. 각 작업은 1 시간단위이며 비선점 실행이고 작업 생성·통신 비용은 0이다. 작업량은 6, span은 3이다. 작업자 두 명의 하한 max(6/2,3)은 3이지만 실제 완료는 최소 4다. 처음 네 작업만 두 칸이 필요하고 그 뒤 E와 F에 두 칸이 더 필요하기 때문이다.

작업량과 의존 경로의 하한

어떤 실행도 W 개의 단위 작업을 p 명에게 맡기면 적어도 W/p 시간이 필요하다. 선행 작업이 끝나야 다음 작업을 할 수 있는 긴 경로는 p가 커져도 S보다 짧아질 수 없다. 따라서 Tp ≥max(W/p,S)다.

이 식은 달성한 실측 시간이 아니라 이상 모델의 하한이다. 실제에는 생성· 장벽· 자료 이동· 캐시· 메모리 대역 폭 비용이 추가된다. 하한만 계산해 최적 실행 시간이라고 선언하면 안 된다. 작은 작업은 관리 비용이 본 계산보다 커질 수도 있다.

힌트 1

미선택 항목은 위치가 같아도 출력에 쓰지 않는다. 경계와 입력 세대는 별도 조건이다.

힌트 2

하한과 구성 일정은 분리하며 scan 마지막 exclusive 값에 마지막 항목을 더해야 total이다.

풀이와 답 확인

  1. ① exclusive 위치는 [0,0,1,2,2]다. 선택된 Q, R, T만 각각 위치 0, 1, 2에 쓴다. 압축 결과는 [Q,R,T]이고 전체 저장 길이는 3이다.

  2. ② 고정 끝의 첫 결과는 [0,2,3,1,0]이고 합은 6이다. 주기 경계의 첫 결과는 [2,2,3,1,1]이고 합은 9다. 고정 끝의 둘째 단계에서 정상 가운데 값은 2다. 오래된 오른 이웃값 3을 읽으면 가운데 값은 8/3이다.

  3. ③ G와 H의 작업량은 각각 6이고 span은 각각 3 시간단위다. 두 작업자의 완료 시간 하한은 각각 3 시간단위다. G에서는 초기 네 작업이 끝난 뒤 E와 F가 이어져 최소 완료 시간이 4 시간단위다. H에서는 A, E, F의 사슬과 B, C, D를 겹쳐 최소 완료 시간 3 시간단위를 달성한다.

  4. ④ exclusive 결과는 [0,1,3,6,10,15,21,28]이고 total은 36이다. 두 단계 트리의 덧셈 횟수는 14회이고 span은 6 시간단위다. 지정된 층별 두 작업자 일정은 upsweep과 downsweep에 각각 4칸을 사용하여 완료 시간이 8 시간단위다. 이 결과는 하한 7 시간단위와 구별한다.
