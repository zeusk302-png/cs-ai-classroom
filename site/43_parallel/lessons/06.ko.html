소단원 6.1

reduction·scan·map

여러 숫자를 변환하기, 하나로 합치기, 누적 목록 만들기는 같은 작업일까?

준비 개념과 학습 목표

준비 개념

  • 배열의 인덱스는 0부터 시작한다. map은 각 항목의 함수 값을 별도 출력 위치에 쓴다.

  • 결합법칙은 (a ⊕b)⊕c =a ⊕(b ⊕c), 항등원은 e ⊕a =a ⊕e =a다.

학습 목표

  • 세 패턴의 출력 형태를 구별한다.

  • 결합법칙· 순서 보존 조건을 확인하고 prefix를 손 계산한다.

서로 독립인 변환

입력 [3,1,4,2]의 각 수를 제곱하면 map의 출력은 [9,1,16,4]다. 각 출력이 자기 입력만 읽으면 항목별 계산은 독립이다. 여러 작업자가 각기 다른 출력 칸을 맡는 그림으로 생각할 수 있다.

다른 출력 칸에 쓴다는 것만으로 모든 map이 안전한 것은 아니다. 함수가 하나의 공유 카운터를 갱신하거나 다른 항목의 최신 출력 값을 읽으면 추가 의존과 동기화가 생긴다. 여기서는 입력이 변하지 않고 함수에 공유 쓰기 부작용이 없다고 가정한다.

하나의 결과와 모든 접두 결과

reduction은 여러 값을 하나로 합친다. 덧셈으로 (3 +1)+(4 +2)=4 +6 =10이다. 결합 법칙이 성립하면 괄호 모양을 바꾸어 나뭇가지별 부분 합을 동시에 계산할 수 있다. 빈 입력의 합은 항등원 0으로 정의한다.

scan은 각 접두 구간의 합을 모두 돌려준다. inclusive는 현재 항목까지 포함해 [3,4,8,10], exclusive는 현재 항목 전에 멈춰 [0,3,4,8]이다. 출력 길이는 이 정의에서 입력 길이 4와 같다. 전체 합 10을 별도 반환하는 인터페이스도 있으므로 exclusive 마지막 값 8을 전체 합으로 오해하지 않는다.

괄호와 순서는 따로 확인한다

문자열 연결은 결합법칙이 있지만 교환법칙은 없다. 입력 순서를 유지해 괄호만 바꾸면 abc를 얻지만 항목을 재배열하면 bac가 된다. 그래서 결합법칙만으로 임의 순서 섞기까지 허용하지 않는다. OpenMP scan의 논리 반복 순서와 일반 reduction의 결합 선택도 구별한다.

유한 정밀도 실수 덧셈은 정확한 실수 덧셈처럼 항상 결합적이지 않다. 순서가 바뀌는 구현에 비트 단위 동일 결과를 요구하려면 별도 재현성 설계가 필요하다. 이 단원의 작은 정수 합은 표현 범위를 넘지 않는 정확한 산술로 계산한다.

중간 과정을 따라가는 예제

[3,1,4,2]의 제곱 map, 합 reduction, inclusive/exclusive scan을 구하라.

  1. 각 항목을 제곱해 9,1,16,4를 얻는다.

  2. 첫 두 값의 합 4와 다음 두 값의 합 6을 합쳐 10을 얻는다.

  3. inclusive 누적 상태는 3 →4 →8 →10이다.

  4. exclusive는 더하기 전 상태를 쓰므로 0 →3 →4 →8이다.

map [9,1,16,4], reduction10, inclusive [3,4,8,10], exclusive [0,3,4,8].

종이와 본문으로 직접 해보기

각 항목의 길이가 [2,0,3,1]인 네 묶음을 이어 붙이려 한다. 시작 위치와 전체 저장 길이를 구하라.

힌트 보기

항목 전까지 사용한 길이는 exclusive 합이고 마지막 묶음 길이는 따로 더한다.

풀이 보기

시작 위치는 [0,2,2,5], 총 길이는 6이다. 길이 0 묶음과 다음 묶음은 시작 2를 공유해도 빈 구간이므로 쓰기 겹침이 아니다. 양의 길이 묶음은 [0,2),[2,5),[5,6)에 쓴다.

오해와 반례

scan의 마지막 항목은 언제나 전체 합이다.

현재 항목을 포함하는 inclusive에서는 그렇지만 exclusive [0,3,4,8]의 마지막은 8이다. 현재 마지막 입력 2를 더해야 전체 10이다.

자기점검

빈 합 reduction의 항등원은?

답과 이유 보기

0 +a =a이므로 빈 목록도 같은 합 규칙에 연결된다.

답과 이유 보기

초기 값 0이다.

첫 항목 이전에는 아직 아무 항목도 포함하지 않았다.

문자 연결은 결합적이면 순서를 바꾸어도 되는가?

답과 이유 보기

아니다.

ab와 ba는 다르므로 순서 보존이 필요하다.

한 단계 더

n 개 접두 합을 각각 처음부터 다시 계산하면 exclusive 덧셈 수는 0 +1 +… +(n −1)=n(n −1)/2로 이차 작업량이다. n =4면 6이다. 트리 기반 scan은 적절한 결합 연산 조건에서 선형 작업량과 로그 임계경로를 달성할 수 있다. 단순히 동시에 시작했다는 이유만으로 작업 효율적이라고 판단하지 말자.

소단원 6.2

병렬 정렬·stencil

양쪽을 동시에 정렬하면 마지막 합치기도 자동으로 빨라질까?

준비 개념과 학습 목표

준비 개념

  • 정렬은 같은 원소들을 순서 있게 재배열한다. merge는 이미 정렬된 두 목록을 합친다.

  • stencil은 가까운 이웃 값을 읽어 새 격자 값을 만드는 규칙이다.

학습 목표

  • 독립 재귀와 합병 의존을 나눈다.

  • 이전 단계와 다음 단계의 배열을 구별하여 stencil을 계산한다.

작은 정렬과 마지막 합병

입력 [7,2,5,1]을 둘로 나누면 왼쪽 [7,2]와 오른쪽 [5,1]의 정렬은 서로 독립이다. 둘 다 끝난 뒤 [2,7]과 [1,5]를 합병한다. 한쪽이 아직 정렬되지 않았는데 합병하면 전제부터 깨진다.

합병은 작은 머리 원소를 꺼내고 남은 목록의 머리와 다시 비교한다. 현재의 단순 합병은 순차적이다. 재귀를 병렬로 실행해도 루트 합병이 긴 의존 경로가 될 수 있다. 더 낮은 임계경로를 원하면 합병 자체도 별도로 병렬화해야 한다.

한 단계의 이웃 규칙

자체 1 차원 격자 [0,3,6,9,0]에서 양 끝은 0으로 고정한다. 내부 새값은 이전 왼쪽· 자기· 오른쪽의 평균이다. 새 배열의 각 칸은 동일한 이전 배열만 읽으므로 세 내부 계산을 동시에 해도 같은 결과다.

입력 배열을 읽으면서 같은 배열에 새 값을 덮어쓰면 늦게 계산하는 칸은 이미 바뀐 이웃을 읽는다. 이는 다른 반복 법일 수 있지만 여기서 정의한 동시 갱신 규칙과 같지 않다. 두 배열을 쓰고 전체 한 단계가 끝난 후 역할을 교환한다.

경계와 연결 지점

경계 조건이 주기적 감싸기인지 고정 값인지에 따라 처음과 마지막 이웃이 달라진다. 배열 길이와 접근 범위를 먼저 정한다. 분할 영역 경계에서는 옆 작업자가 보유한 이전 값을 복사한 halo가 필요할 수 있다.

한 단계 내부는 독립이어도 다음 단계는 이전 단계의 완료에 의존한다. 두 단계 사이 장벽이나 동등한 의존 관리를 생략하면 세대가 섞일 수 있다. 정렬 역시 재귀 두 자식의 완료라는 같은 연결 문제를 가진다.

중간 과정을 따라가는 예제

[7,2,5,1] 합병과 격자 [0,3,6,9,0]의 한 단계 동시 평균을 추적하라.

  1. 두 자식 정렬은 [2,7]과 [1,5]다.

  2. 1<2로 1,2<5로 2,5<7로 5를 꺼내고 남은 7을 붙여 [1,2,5,7]이다.

  3. 격자 첫 내부 평균은(0 +3 +6)/3 =3, 가운데는(3 +6 +9)/3 =6이다.

  4. 마지막 내부 평균은(6 +9 +0)/3 =5 라 새 격자는 [0,3,6,5,0]이다.

정렬 [1,2,5,7], stencil [0,3,6,5,0].

종이와 본문으로 직접 해보기

같은 격자의 두 번째 동시 단계를 계산하라. 첫 입력에 대해 오른쪽부터 in-place 갱신하면 가운데 값은?

힌트 보기

동시 두 번째 단계는 완성된 첫 새 배열만 읽는다. in-place 반례는 바뀐 마지막 내부 5를 가운데가 읽는다.

풀이 보기

두 번째 동시 결과는 [0,3,14/3,11/3,0]이다. 첫 입력을 오른쪽부터 덮어쓰면 마지막 내부 5 다음 가운데는(3 +6 +5)/3 =14/3이 되어 첫 동시 결과의 6과 다르다. 순서 변경이 규칙을 바꾼 것이다.

오해와 반례

서로 다른 출력 칸을 맡으면 in-place 이웃 계산도 항상 같은 결과다.

쓰기 칸은 다르더라도 다른 작업자의 쓰기 칸을 읽으면 순서 의존이 생긴다. 오른쪽부터 계산한 가운데14/3과 동시 6이 반례다.

한 단계 더

순차 merge 비용을 n으로 놓는 교육 재귀는 W(n)=2W(n/2)+n, S(n)=S(n/2)+n이다. 충분히 큰 2의 거듭제곱 n에서 W는 Θ(n log n), S는 Θ(n)이다. 임계경로에는 두 자식 중 긴 하나만 들어간다. 병렬 재귀가 순차 합병을 없애 주는 것은 아니다.

소단원 6.3

패턴의 정확성과 비용

작업자를 여덟 명 붙이면 실행 시간도 꼭 8분의 1이 될까?

준비 개념과 학습 목표

준비 개념

  • 작업량 W는 모든 계산 비용의 합, span S는 가장 긴 의존 경로다.

  • p 개의 작업자는 동시에 최대 p 개의 단위 계산을 수행한다.

학습 목표

  • 작업량과 임계경로 하한을 계산한다.

  • 입력/ 출력 소유권 및 숫자 연산 조건을 정확성 증명에 연결한다.

같은 문제를 푸는지 먼저 본다

정확성은 결과 값뿐 아니라 허용 입력· 출력 길이· 순서· 경계에서 정의된다. reduction의 결합 연산, scan의 포함 여부, stencil의 이전 세대 읽기를 문장으로 고정한다. 빠른 프로그램도 다른 문제를 풀면 정답이 아니다.

자체 덧셈 트리의 각 내부 노드는 자기 잎 구간의 합을 보관한다고 주장한다. 잎에서 참이고 부모는 겹치지 않는 두 구간의 합을 더하므로 귀납적으로 참이다. 빈 입력과 오버플로 가능성도 별도 확인한다.

작업량과 의존 경로의 하한

어떤 실행도 W 개의 단위 작업을 p 명에게 맡기면 적어도 W/p 시간이 필요하다. 선행 작업이 끝나야 다음 작업을 할 수 있는 긴 경로는 p가 커져도 S보다 짧아질 수 없다. 따라서 Tp ≥max(W/p,S)다.

이 식은 달성한 실측 시간이 아니라 이상 모델의 하한이다. 실제에는 생성· 장벽· 자료 이동· 캐시· 메모리 대역 폭 비용이 추가된다. 하한만 계산해 최적 실행 시간이라고 선언하면 안 된다. 작은 작업은 관리 비용이 본 계산보다 커질 수도 있다.

작업 효율과 소유권

같은 답을 얻더라도 모든 prefix를 재계산하는 방법은 중복 작업이 많다. 순차 최선과 작업량 차 수가 같은지 확인한 뒤 병렬성을 본다. 작업량 W가 커지면서 S만 작아지는 설계는 충분한 장비에서조차 손해일 수 있다.

각 작업자가 어떤 출력 칸을 쓰고 어떤 입력 세대를 읽는지 표로 표시한다. 공유 변수 쓰기가 겹치면 단순 독립 패턴으로 볼 수 없다. 순서가 중요하지 않은 연산과 순서를 보존해야하는 연산을 구별하여 비용과 정확성을 함께 판단한다.

중간 과정을 따라가는 예제

8개의 정수를 더하는 균형 트리에서 덧셈만 단위 비용으로 세라. W,S 및 p =2,4,8의 시간 하한은?

  1. 첫 층 4개, 다음 층 2개, 루트 1개로 W =7이다. 입력 읽기/ 생성 비용은 이 계산에서 제외한다.

  2. 한 잎부터 루트까지 덧셈 3번이므로 S =3이다.

  3. p2에서는 max(7/2,3)=3.5이며 정수 시간 칸 모델에서는 적어도 4 칸이다.

  4. p4와 p8에서는 하한 3이다. p4가 있으면 4/2/1 세 층을 3 칸에 계산하는 일정이 실제 구성된다.

W7/S3, 정수 칸 하한 p2는 4, p4/p8은 3. 모델 안에서 p4의 3 칸 일정은 구성 가능하다.

종이와 본문으로 직접 해보기

p2의 실제 단위 덧셈 일정을 그려라. 4 칸 하한은 이 트리에서 달성되는가?

힌트 보기

첫 두 칸에 각각 첫 층의 두 덧셈, 셋째 칸에 두 둘째 층, 넷째에 루트를 놓는다.

풀이 보기

첫 층 4개를 2 칸, 둘째 층 2개를 1 칸, 루트 1개를 1 칸으로 총 4 칸에 끝난다. 하한과 구성 일정이 일치하지만 실제 컴퓨터의 4ns 를 뜻하지 않는다. 자료 이동 비용을 넣으면 모델이 달라진다.

오해와 반례

Tp ≥max(W/p,S)이므로 실제 Tp는 항상 그 값과 같다.

하한은 넘어서는 데 걸리는 최소 제약이다. 통신· 스케줄링이나 작업 구조 때문에 더 걸릴 수 있다. 이 예에서는 별도 일정 구성으로만 4 칸/3 칸의 달성을 보였다.

7개의 덧셈을 완전히 순차 실행하면 7 칸이다. p4 트리 3 칸의 모델 속 speedup은7/3이고 효율은(7/3)/4 =7/12다. 입력 읽기 등 다른 비용을 뺀 비교임을 명시하라. 비트 단위 재현성이 필요한 실수 합에서는 트리 변경에 따른 반올림 차이를 별도로 분석해야 한다.
