Subtopic 2.1

Cores, vectors, and hardware threads

If two cores appear as four threads, are there four addition units?

Preparation and learning goals

Preparation

  • A core is a processing unit that interprets and executes instructions. Registers and the PC form an execution context that remembers current values and the next instruction position. Several contexts can share the same execution units.
  • A vector is an ordered group of values; a lane is one element position. A 128-bit vector containing 32-bit elements has 128/32=4 lanes. This width calculation does not automatically guarantee how many operations complete per cycle.
  • Readiness check: two service desks, each handling four items at a time, can handle at most eight items. Giving each desk two waiting tickets does not create four service desks.

Learning goals

  • Distinguish cores, SIMD lanes, and hardware contexts.
  • Calculate a throughput model with explicitly shared resources.
  • Explain the difference between hiding latency and adding execution units.

Different places for parallelism

A multicore structure allows several cores to execute different instruction streams. SIMD applies the same kind of operation to several data positions with one vector instruction. Even when all lanes add, their operands and results differ. A core can contain several execution units, so one core should not always be equated with one adder.

Hardware threading maintains independent execution contexts on a chip. An operating system’s software thread is a scheduled program unit; many software threads can take turns on fewer hardware contexts. The number of logical CPUs reported by the operating system alone does not reveal the number of physical cores or vector units.

More contexts can hide waiting

Interleaved multithreading can select instructions from another context while one context waits for data. SMT can also issue instructions from several contexts in the same cycle to different available execution resources. In either case, the capacity of shared ports, caches, and vector units must be specified separately.

Adding contexts does not make a memory response itself arrive sooner. Latency hiding reduces idle time by doing other ready work. If two contexts both need the same execution port, they compete, and the completion latency of a single thread can even increase.

Conditions of a hypothetical throughput model

Define a hypothetical machine with two cores, each starting and completing one 4-lane vector addition every cycle. Each core has two hardware contexts, but they share its vector unit. Inputs are already ready, output positions are distinct, and dependency, memory, branch, and issue costs are excluded. At most 2×4=8 useful additions complete in one cycle.

Assigning 24 independent additions as three vector groups to each of the two cores takes three cycles. Multiplying by the number of contexts to obtain 16 additions/cycle violates this contract. Empty lanes in the last group and unready inputs reduce useful throughput. A physical machine’s latency and initiation interval require separate checks of its ISA, implementation documentation, and measurements.

A worked example, step by step

Process 24 independent additions on the two-core, 4-lane machine above, with one shared vector unit per core. Each addition uses an exact-integer model; assume ready inputs and completion in one cycle.

  1. Divide the 24 additions into six groups of four elements.
  2. In cycle 1, core 0 handles indices 0–3 and core 1 handles 4–7.
  3. In cycle 2, they handle 8–11/12–15; in cycle 3, they handle 16–19/20–23.
  4. At most eight additions complete per cycle, so at least ceil(24/8)=3 cycles are needed. This assignment attains the lower bound.

Three cycles. Four hardware contexts do not mean four vector units.

Try it with paper and the lesson

Group 18 independent additions on the same machine. On paper, find the required cycles, the number of useful lanes in the last cycle, and overall lane utilization.

Show hint

The total number of offered lane positions is the cycle count×8. There are exactly 18 useful operations; empty lanes must not read out-of-range elements.

Show solution

ceil(18/8)=3 cycles. The first two cycles each perform eight additions; the last performs two. Useful lane utilization is 18/24=3/4. Protect the remaining lanes with a mask or separate tail processing.

Misconception and counterexample

Doubling the number of hardware threads doubles maximum arithmetic throughput.

In the model above, two contexts share one 4-lane unit, so the ceiling remains four additions per core. If that unit is already busy every cycle, adding contexts cannot complete more additions.

Check your understanding

How many lanes does a 256-bit vector of 64-bit elements have?

Show answer and reasoning

Four.

Divide vector width by element width; this is separate from the instruction initiation interval.

Does latency hiding eliminate the latency of an individual memory request?

Show answer and reasoning

No.

It performs other ready work while waiting.

Do two cores with four lanes and two contexts per core always complete 16 additions/cycle?

Show answer and reasoning

No.

In this model, with one shared vector unit per core, eight is the upper bound.

Explore further

Further proof: suppose p identical cores, where p is a positive integer, each complete at most v useful independent operations per cycle, with v a positive integer. They complete at most pvt operations in t cycles, so a positive integer n operations requires t≥ceil(n/(pv)). If all inputs are ready, arbitrary partitioning is possible, and the last lanes can be masked, this lower bound is attainable. The number h of hardware contexts is not a factor in this resource capacity. Waiting within contexts can instead leave some cycles unused and reduce actual completions. A pipeline with multicycle instruction latency but an instruction issue opportunity every cycle also needs startup and drain latency; distinguish it from the unit-completion model above.

Subtopic 2.2

Instruction and data parallelism

Even if the same four additions are grouped in pairs, can one dependency arrow change the outcome?

Preparation and learning goals

Preparation

  • An instruction is a step that reads inputs and produces a result. If B uses A’s result, there is a data dependency A→B. A cycle is a hypothetical time unit; conversion to physical seconds requires a frequency and machine costs.
  • Data parallelism means that the same computation can be applied to several elements. Different indices i in y[i]=x[i]+1 are independent provided their output positions are separate and inputs do not change.
  • Readiness check: in a=x+1, b=y+1, c=a+b, a and b can run together first, but c must wait for both results.

Learning goals

  • Explain ILP and data parallelism through dependencies.
  • Construct an issue schedule for a unit-cost DAG.
  • Distinguish the semantic conditions that allow reordering and vectorization.

Independent instructions within one stream

Instruction-level parallelism (ILP) is the presence of independent instructions within one instruction stream that can progress simultaneously. A superscalar implementation can issue several instructions, but this does not permit reading a dependency result before it exists or changing the program’s observable results. Internal execution order may differ from program order while preserving the specified language and ISA semantics.

Our hypothetical DAG contains only side-effect-free, exact-integer operations. All inputs are ready initially, and each node costs one cycle. At most two nodes execute per cycle; a parent must finish by the end of the previous cycle before its child starts. Branch prediction, memory aliasing, exceptions, and device accesses are excluded from this simple model.

Apply the same computation to several values

The per-element computation y[i]=x[i]+1 is data parallel when elements are independent. A 4-lane instruction can apply the same addition to four inputs. But the independence proof changes if x and y are overlapping views and an earlier output changes a later input, or if the computation is a prefix sum s[i]=s[i−1]+x[i]. Different array names alone do not guarantee disjoint storage.

Reordering also requires a value-semantics contract. Mathematical associativity holds for exact-integer addition, but fixed-width overflow rules and floating-point rounding are separate matters. Replacing a sequential floating-point sum with a parallel tree can change the result bits. Do not claim that every reduction gives the same result without stating an error tolerance, reproducibility requirement, or identical evaluation order.

Calculate with a dependency graph

The complete example is a=x+1, b=y+1, c=a+b, d=a−b, e=c+d. Inputs are x=2 and y=5, and each of the five nodes costs one cycle. Execute the three layers a/b, c/d, and e to obtain a=3, b=6, c=9, d=−3, e=6. The work-capacity lower bound ceil(5/2)=3 for two execution units agrees with the lower bound from a dependency chain of length three.

Applying this graph to several independent elements allows both the three layers within each element and parallelism across elements to be used. Cores, vectors, and ILP are not mutually exclusive categories. However, resources and dependencies at each level must be specified; the number of vector lanes does not automatically shorten a single dependency chain.

A worked example, step by step

For x=2 and y=5, process a=x+1, b=y+1, c=a+b, d=a−b, e=c+d using the two-unit hypothetical DAG above.

  1. Execute a and b, which need only inputs, in cycle 1 to obtain 3 and 6.
  2. With a and b ready, execute c=9 and d=−3 in cycle 2.
  3. Compute e=9−3=6 in cycle 3.
  4. The work-capacity lower bound for five tasks is three, and the chain a→c→e also has length three, so two cycles are impossible.

The minimum is three cycles, with e=6. The resulting value and the time lower bound answer different checks.

Try it with paper and the lesson

Add a node f=x−y computed directly from the inputs, and change the hypothetical contract so that e reads c+d+f as one new unit-cost operation. With two units, construct a schedule and decide whether six nodes can finish in three cycles.

Show hint

All three parents of e must be ready. The three input nodes a, b, and f cannot all fit into two execution slots in one cycle.

Show solution

The schedule 1:a,b; 2:c,d; 3:f; 4:e takes four cycles. Alternative schedules 1:a,b; 2:c,f; 3:d; 4:e, or 1:a,f; 2:b; 3:c,d; 4:e also take four. To finish e in cycle 3, c, d, and f must all finish by cycle 2. After a and b, c, d, and f cannot all fit into the two slots of cycle 2, so this is impossible. e=9−3−3=3.

Misconception and counterexample

With two units, execution time always equals the ceiling of half the work.

The activity’s six nodes have a work lower bound of three cycles, but dependencies and readiness require four. A lower bound is not always an attainable schedule.

Check your understanding

Can c, which reads a’s result, start in the same unit cycle as a?

Show answer and reasoning

Not in this model.

The parent must finish by the end of the previous cycle.

If output positions for different elements overlap, is the computation automatically data parallel?

Show answer and reasoning

No.

Check read/write dependencies and the language’s concurrent-access contract.

Does reordering a floating-point sum always produce identical result bits?

Show answer and reasoning

No.

Intermediate rounding and operation order can differ.

Explore further

Further reasoning: in any execution of the DAG, p units handle total cost W, so T≥ceil(W/p). The longest dependency chain of length L must be processed in order, so T≥L. Together, T≥max(ceil(W/p), L), but this is not sufficient for attainability. The activity graph is a concrete counterexample: W=6, L=3, p=2, but T=4. Suppose the final node e runs in cycle 3. Then a and b must finish by cycle 1, while c, d, and f must finish by cycle 2. The first cycle’s two slots are occupied by a and b, leaving three required nodes for two slots in the second cycle, a contradiction. This proof applies to the exact contract of unit-cost nodes, nonpreemptive execution, and dependencies between layers.

Subtopic 2.3

Memory bandwidth and bottlenecks

Could array addition take almost the same time even if the cores become ten times faster?

Preparation and learning goals

Preparation

  • Bandwidth B is bytes crossing a specified boundary per unit time. Latency is the waiting time for one request. Define GB as 10^9 bytes and GFLOP as 10^9 floating-point operations.
  • FLOP is a convention for counting operations. Here one addition counts as one FLOP; a multiplication followed by an addition counts as two FLOPs. This need not equal the instruction count.
  • Readiness check: moving 120 bytes through a 60 byte/s boundary takes at least 2 s. Adding a faster adder alone does not widen that boundary.

Learning goals

  • Define the traffic boundary and arithmetic intensity I=F/Q.
  • Derive the throughput upper bound min(P, BI) with units.
  • Distinguish caches, write allocation, interference, and the scope of actual measurements.

Computation and data movement each require time

Consider y[i]=a[i]+b[i], reading two arrays of n 32-bit elements and writing a third. Under a hypothetical DRAM-boundary contract that reads each input once, writes each output once, and performs no additional transfers, F=n FLOP and Q=12n bytes. Read-for-ownership of output, extra cache-line traffic, or rereads increase Q when they occur.

If compute capacity is at most P FLOP/s and movement capacity at that boundary is at most B byte/s during total time T>0, then T≥F/P and T≥Q/B. Even with ideal overlap, T≥max(F/P, Q/B). Paying the two costs serially can take longer. Whether a performance upper bound is attainable is a separate question; startup costs for small problems and dependency latency also remain.

Derive Roofline through units

For F>0 and Q>0, intensity I=F/Q has units FLOP/byte. Throughput F/T is at most P, and T≥Q/B implies F/T≤BF/Q=BI. Therefore throughput≤min(P, BI). Checking that byte/s multiplied by FLOP/byte gives FLOP/s helps prevent calculation errors.

Even the same algorithm has different Q values at DRAM and L1 boundaries, so do not mix intensity and bandwidth from different levels. Cache reuse can reduce DRAM Q, but the algorithm and storage conditions must allow actual reuse of the required values. Adding cores increases only P if shared B remains unchanged; the memory-boundary ceiling then remains unchanged.

Hypothetical numbers and limits of diagnosis

Use hypothetical values n=10^8, P=100 GFLOP/s, and B=60 GB/s. Then F=0.1 GFLOP, Q=1.2 GB, and I=1/12 FLOP/byte. The compute time lower bound is 0.001 s and the transfer time lower bound is 0.02 s, giving a throughput upper bound of 5 GFLOP/s. These numbers are not measurements of a computer.

When latency is long, many independent requests can increase throughput, but once B is reached, adding requests cannot exceed the ceiling. Insufficient concurrent requests, alignment, or locality can prevent even reaching B. Actual diagnosis must fix input size, cache state, thread placement, data type, FLOP-counting convention, write policy, measurement interval, and interference.

A worked example, step by step

Find the time lower bound and throughput upper bound for the hypothetical DRAM model of n=10^8 array additions above. What changes if only P increases to 200 GFLOP/s?

  1. Per element, the two inputs require eight bytes and the output four bytes, so Q=12×10^8=1.2 GB.
  2. F=10^8=0.1 GFLOP, and I=1/12 FLOP/byte.
  3. F/P=0.001 s and Q/B=0.02 s, so T≥0.02 s and F/T≤5 GFLOP/s.
  4. Raising P to 200 reduces the compute lower bound to 0.0005 s, but the transfer lower bound remains 0.02 s.

In both cases, time is at least 20 ms and throughput is at most 5 GFLOP/s. Actual time is not guaranteed to equal exactly 20 ms.

Try it with paper and the lesson

A different hypothetical algorithm has F=2 GFLOP and Q=1 GB. For P=100 GFLOP/s and B=60 GB/s, find I, the time lower bound, and the upper bounds from the two bottlenecks. What if Q decreases to 0.5 GB with F unchanged?

Show hint

I is F/Q, and the time lower bound is the larger of the two quotients. Use the G prefix consistently on both sides.

Show solution

Initially I=2 FLOP/byte. Compute takes at least 20 ms and transfer at least (1/60)s≈16.67 ms; throughput is at most min(100,120)=100 GFLOP/s. Halving Q gives I=4 and a transfer lower bound of approximately 8.33 ms, but the 20 ms compute lower bound remains, so the throughput upper bound stays 100.

Misconception and counterexample

If performance lies below Roofline, insufficient memory bandwidth must be the cause.

Dependency chains, issue ports, branches, uneven work, and startup costs can prevent either ceiling from being filled. An upper bound limits possible performance; it is not a measurement that identifies a single cause.

Check your understanding

If B is DRAM bandwidth, may I be calculated from L1 traffic?

Show answer and reasoning

No.

Pair data movement and bandwidth at the same boundary.

What is the crossover intensity for 100 GFLOP/s and 60 GB/s?

Show answer and reasoning

5/3 FLOP/byte.

P/B=100/60. At or above this value, the compute roof is the lower ceiling in the simple bound.

Does doubling the number of cores always double shared bandwidth?

Show answer and reasoning

No.

Memory channels, placement, and contention require separate resource conditions.

Explore further

Further reasoning: with several boundaries, each traffic amount Qj and upper bound Bj gives T≥Qj/Bj, while T≥F/P still holds. Thus F/T≤min(P, B1F/Q1, B2F/Q2,…). This is a necessary condition when every positive Qj has a fixed boundary definition. Reuse can reduce QDRAM while leaving QL1 unchanged. A theoretical bandwidth upper bound B can be used in a rigorous model, but a maximum observed in some experiments alone proves neither an upper bound for every execution nor a guaranteed minimum bandwidth. Worst-case program latency analysis requires a different kind of condition: a guaranteed lower bound on service.
