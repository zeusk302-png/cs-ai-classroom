그래프·행렬·딥러닝 연산

정점 수를 반씩 나누면 두 작업자의 계산량도 반드시 반씩 나뉠까?

준비 개념과 학습 목표

학습 목표

  • 그래프의 이웃 수와 작업량을 구별한다.

  • 딥러닝 연산의 모양과 데이터 이동을 함께 고려한다.

같은 출력 칸을 나누는 분할과 서로 다른 칸을 나누는 분할은 무엇이 다를까요?

새 정확 정수 행렬 모형에서 A=[[1,2,3],[4,5,6]], B=[[1,0],[0,1],[1,1]]이다. AB의 크기는 2×2이고 결과는 [[4,5],[10,11]]이다. 출력 행을 나누면 두 작업자가 서로 다른 행을 완성한다. 그러나 내부 k축을 첫 항과 나머지 두 항으로 나누면 부분 결과 U=[[1,0],[4,0]], V=[[3,5],[6,11]]을 같은 출력 칸별로 더해야 한다. U와 V를 옆으로 붙인 2×4 배열은 목표 행렬이 아니다. 부분 결과를 서로 다른 버퍼에 쓴 뒤 의존성이 끝난 시점에 합치는 계약을 두며 공유 C에 비원자 덧셈을 동시에 하는 코드의 안전성을 가정하지 않는다.

새 그래프 상태 모형은 세 정점 a,b,c의 옛 값이 (1,2,4)이고 새 값은 각각 옛 c,a,b의 값을 복사한다. 모든 읽기를 옛 버퍼에서 하면 결과는 (4,1,2)다. 같은 버퍼에서 a,b,c 순으로 바꾸면 새 a=4를 b가 읽고 새 b=4를 c가 읽어 (4,4,4)가 된다. 이는 단일 작업자에서도 나타나는 계약 차이다. 동기화로 충돌을 없앴다는 사실만으로 옛 값 기반 한 라운드와 같은 연산이 되지 않는다. GraphLab 원문의 다양한 실행 방식을 이 새 동기 라운드의 하나뿐인 구현으로 일반화하지 않는다.

별도 두 작업자 비용 모형에서 정점별 독립 방문 비용은 8,2,2,0 ms이고 정점 하나는 나눌 수 없다. 가장 큰 정점을 한 작업자에 두고 나머지를 다른 작업자에 두면 완료 시간은 max(8,4)=8 ms다. 총량 12를 둘로 나눈 6 ms는 이 계약에서 달성할 수 없다. 비용 8인 정점을 독립 비용 4 두 조각으로 나눌 수 있도록 계약을 바꾸고 각 작업자에 비용 2 정점을 하나씩 주면 계산 시간은 6 ms다. 두 조각 결과의 결합 비용 2 ms가 모든 계산 뒤에 겹치지 않고 붙으면 총 8 ms이므로 더 잘 나눈 것만으로 시간 이득이 생기지 않는다.

같은 수식에도 다른 분해가 있다

행렬곱 C = AB에서 C의 각 요소는 A의 한 행과 B의 한 열의 곱을 합한 것이다. 입력을 읽기만 하고 서로 다른 출력 위치를 담당하면 출력 간의 쓰기 충돌을 피할 수 있다. 같은 출력의 부분합을 여러 작업자가 쓰면 합치기 규약이 필요하다.

행렬의 행을 나누는 방법과 내부 합 차원을 나누는 방법은 다르다. 내부 차원 분할은 각자의 부분 결과를 합쳐야 한다. 단순히 결과를 옆에 붙이면 행렬곱이 되지 않는다.

그래프의 작업량은 이웃에 달린다

그래프에서는 각 정점의 인접 간선을 읽는 연산을 자주 수행한다. 한 정점은 이웃이 하나인데 다른 정점은 수천이면 정점 수를 같게 나눠도 작업량은 다르다. 이웃 방문 횟수·쓰기 대상·동기화·자료의 위치를 함께 확인한다.

여러 정점의 작업이 같은 이웃 값을 갱신하면 충돌할 수 있다. 한 라운드의 이전 값을 읽고 별도 다음 값을 쓰는 규약과 제자리 갱신은 같지 않다. 알고리즘의 의미가 보존되는 분해인지 먼저 확인한다.

딥러닝도 모양과 배치가 중요하다

선형 계층의 계산은 행렬곱으로 표현할 수 있고 입력 배치가 여러 행으로 묶일 수 있다. 모든 신경망 연산이 행렬곱 하나라는 뜻은 아니다. 비선형 함수·정규화·자료 배치와 중간 결과도 비용에 들어간다.

같은 수의 산술을 하더라도 입력을 반복 전송하면 느릴 수 있다. 타일로 입력을 재사용하는 전략은 메모리와 통신을 고려한다. 실제 부동소수점 합 순서를 바꾸면 반올림 결과가 달라질 수 있으며 아래 정수 예제는 그 문제를 측정하지 않는다.

  1. P는 C00 = 1×5 + 2×7 = 19, C01 = 1×6 + 2×8 = 22를 계산한다.

  2. Q는 C10 = 3×5 + 4×7 = 43, C11 = 3×6 + 4×8 = 50을 계산한다.

  3. 두 작업자는 B를 함께 읽지만 출력 행은 겹치지 않는다. 입력이 고정되고 각자 맡은 행에만 쓰는 조건에서 출력 쓰기 충돌은 없다.

연습 1 · 값과 상태 예측

같은 복사 규칙을 초기 (1,2,4)에서 c,b,a 순서로 제자리 적용하라.

힌트 1

c를 바꾼 뒤 a가 읽을 c를 표시한다.

힌트 2

b는 a를 바꾸기 전에 읽는다.

풀이와 답 확인

  1. c는 옛 b=2, b는 옛 a=1이 된다.

  2. a는 이미 바뀐 c=2를 읽으므로 최종 (a,b,c)=(2,1,2)다.

최종 값은 (2,1,2)다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

비용 8을 두 조각으로 분할해 계산 완료 6 ms를 얻었다. 뒤에 겹치지 않는 결합 비용 r ms가 붙는다. 원래 8 ms보다 엄밀히 빠를 조건은? r≥0이다.

힌트 1

총 시간은 6+r이다.

힌트 2

같은 작업의 원래 시간과 비교한다.

풀이와 답 확인

  1. 6+r<8을 풀면 0≤r<2다.

  2. r=2이면 동률이고 r>2이면 더 느리다.

엄밀한 이득 조건은 0≤r<2 ms다.

작업자 평균과 파이프라인의 짧은 대기가 전체 목표를 보존할까요?

새 같은 파라미터·같은 판본의 정확 기울기 손모형에서 P의 세 사례 기울기는 0,0,6이고 Q의 한 사례 기울기는 10이다. P의 지역 평균은 2, Q의 지역 평균은 10이다. 두 평균을 똑같이 평균하면 6이지만 전체 네 사례의 평균은 4다. 두 작업자의 지역 평균을 평균하는 추상 collective 계약을 사용할 때 P의 값에 2·3/4=3/2, Q의 값에 2·1/4=1/2를 먼저 곱하면 전달 값 3,5의 평균이 4가 된다. 일반적으로 R개 작업자와 전체 사례 수 N에서 지역 사례 수 nᵢ의 지역 평균에 Rnᵢ/N을 곱한다. 모든 nᵢ가 양수이고 목표는 사례별 동일 가중 평균이다. 빈 지역의 평균을 정의하지 않은 채 이 식에 넣지 않으며 실제 DDP의 통신 옵션과 손실 정의를 별도로 확인한다.

같은 좌표와 같은 파라미터 판본도 필요하다. 스칼라 손실 ℓ(w)=w²/2의 기울기는 w다. 한 작업자가 w=0, 다른 작업자가 w=2에서 평가한 값을 평균하면 1이다. 이는 우연히 w=1의 기울기지만 목표 판본 w=0의 기울기 0을 인증하지 않는다. 모델의 다른 층을 소유한 작업자가 서로 다른 좌표의 기울기를 갖는 경우에도 같은 파라미터의 복제본 평균과 구별해야 한다.

별도 순방향 전용 파이프라인은 S1에 3 ms, S2에 5 ms가 걸리는 네 동일 작업을 0 ms에 모두 받는다. 단계마다 작업자 하나, 전송 시간 0, FIFO이고 계산을 중단하지 않는다. S1이 결과를 즉시 외부 대기열에 놓을 수 있으면 S1 완료는 3,6,9,12 ms이고 S2 완료는 8,13,18,23 ms다. 12 ms 직후에는 세 번째와 네 번째 결과 두 개가 외부에서 기다린다. 반대로 외부 대기 칸이 없어서 S1이 완료 결과 하나를 보유한 채 S2에 전달할 때까지 다음 작업을 시작하지 못하면 S1 시작은 0,3,8,13 ms, 전달은 3,8,13,18 ms다. S2 완료는 여전히 8,13,18,23 ms다. 외부 대기는 사라졌지만 내부 보유와 입장 지연이 생긴다. 이는 역전파·활성 저장·통신을 포함한 실제 GPipe 훈련 시간의 인증이 아니다.

무제한 외부 대기 모형에서 S1 시작부터 최종 완료까지의 개별 지연은 8,10,12,14 ms로 평균 11 ms다. 외부 대기 칸이 없는 모형에서는 8,10,10,10 ms로 평균 19/2 ms다. 그러나 두 모형 모두 모든 요청의 접수 시각이 0이므로 접수부터 완료까지의 평균은 (8+13+18+23)/4=31/2 ms다. 시작 시각을 늦추어 계산한 지연 감소를 사용자가 더 빨리 응답을 받았다는 증거로 바꾸지 않는다.

데이터 병렬은 입력을 나누고 모델을 맞춘다

데이터 병렬에서는 모델 복제본마다 다른 입력을 처리하고 기울기 등을 동기화하여 같은 갱신을 적용하도록 한다. 초기 상태·데이터 분배·손실의 합/평균 규약이 맞아야 한다. 입력만 반씩 나누고 각 모델을 영원히 따로 갱신하면 같은 동기 학습 규약이 아니다.

로컬 평균을 다시 평균할 때 로컬 표본 수가 같다는 조건이 중요하다. 수가 다르면 각 표본을 같은 비중으로 세려는 전체 평균과 단순 작업자 평균은 다를 수 있다. 이 수학 모형을 실제 DDP의 모든 설정에 자동 적용하지 않는다.

모델 병렬은 모델의 일부를 나눈다

한 장치에 모델 전체가 들어가지 않으면 층이나 텐서 조각을 나눌 수 있다. 앞 층의 출력 활성값과 뒤 층의 역전파 정보가 경계를 이동한다. 모델 분할은 각 장치의 파라미터를 줄일 수 있지만 통신과 중간 버퍼가 추가된다.

파이프라인은 서로 다른 작은 배치가 다른 모델 구간을 동시에 지나도록 일정을 정한다. 한 작은 배치의 뒤 구간은 앞 구간의 결과를 기다린다. 단계 수만큼 단일 요청이 즉시 빨라지는 것은 아니다.

어떤 일정을 계산했는지 적는다

학습에는 forward와 backward 및 갱신 시점이 있어 실제 일정이 더 복잡하다. 아래 표는 forward 전용 두 단계, 단계별 전용 작업자, 무제한 중간 대기 공간, 전송비 0을 가정한다. GPU 학습의 측정값이나 GPipe 전체 학습 시간으로 보고하지 않는다.

한 번 빠른 후보가 반복 작업과 메모리 제한에서도 최선일까요?

새 후보 비용은 A의 준비 20 ms와 실행당 N ms, B의 준비 4 ms와 실행당 2N ms다. 준비는 해당 후보를 처음 사용할 때 한 번만 들고 매 실행은 같은 판본·같은 N의 정확 결과를 만든다. 한 번 실행하면 A=20+N, B=4+2N이므로 N>16일 때 A가 엄밀히 빠르고 N=16이면 동률이다. N=4를 k회 같은 준비 상태에서 실행하면 A=20+4k, B=4+8k로 k>4일 때 A가 빠르다. k=4는 동률이다. 매번 준비를 다시 수행하거나 자료 판본이 달라 준비 결과를 재사용할 수 없다면 이 식의 계약을 바꿔야 한다.

별도 피크 메모리 모형에서 A는 12 MB, B는 6 MB를 요구하며 한 번에 후보 하나만 실행한다. 상한 8 MB이면 시간 비교 전에 A를 제외해야 한다. 더 빠른 부정확 후보 C의 시간 2+N/2만 추가해도 요구한 정확 결과 검사를 통과하지 못하면 C는 선택 대상이 아니다. 시간 최솟값과 제약을 모두 만족하는 후보 중 최솟값을 구별한다. 피크 메모리를 실행 횟수 k로 곱한 값은 동시 실행을 전제하지 않은 이 모형의 실제 피크가 아니다.

반복 설계도 입력 분포에 의존한다. 같은 준비를 한 번만 수행할 수 있는 서로 다른 크기 N₁,…,Nₖ의 실행에서는 A의 총 시간 20+ΣNᵢ, B의 총 시간 4+2ΣNᵢ를 비교한다. 반대로 준비가 입력 판본마다 무효화되면 각 판본의 준비 비용을 별도로 더한다. 실제 측정에서는 요구한 출력 생성·동기화·전송·준비 범위를 먼저 정하고 완료 사건까지 재야 한다. 지금 수치는 자체 종이 비용 모형이며 실제 런타임이나 GPU의 측정값이 아니다.

어떤 비용이 큰지 먼저 본다

작업 수를 늘리면 계산을 나눌 수 있지만 일정 관리·자료 복사·합치기 비용이 생긴다. 입력이 작으면 추가 비용이 줄인 계산보다 클 수 있다. 병렬화를 정답으로 미리 고정하지 말고 대표 입력의 계산량과 의존 및 자료량을 적는다.

그래프의 큰 차수 정점, 희소 행렬의 비균일 행, 모델의 큰 층은 균등한 개수 배정에서 병목이 될 수 있다. 더 잘게 나누면 균형을 개선할 수 있지만 큐·동기화 비용이 증가한다.

자체 비용 모형은 조건부 예측이다

아래 모형에서 고정 입력의 직렬 계산은 N 시간 단위다. p 작업자에서 계산은 N/p이고 관리·통신 비용 2(p−1)이 겹치지 않고 더해진다. T(p)=N/p+2(p−1)로 정한다. 입력은 p로 나눌 수 있고 부하가 완벽히 균등하며 다른 병목은 없다.

실제에서는 p가 커질수록 메모리 용량·대역폭·네트워크·실행 자원 한계를 만날 수 있다. 이 단순 식의 결과가 모든 장치의 실제 시간은 아니다. 빠르더라도 메모리 제한이나 올바른 결과 조건을 위반하면 선택할 수 없다.

측정은 정확성과 범위를 함께 기록한다

정확한 결과를 순차 기준과 대조한 뒤 같은 입력·자료형·환경에서 시간을 비교한다. 준비/전송/동기화 포함 여부와 반복 및 실패 처리를 적는다. 특히 비동기 장치는 제출 시간만 재면 완료 시간이 아니다.

속도 비율은 T(1)/T(p), 효율은 그 비율/p다. 단일 요청 지연과 여러 요청 처리율도 다르다. 이론 활동의 예상 표를 실제 측정이나 학습자 실행으로 바꾸어 표시하지 않는다.
