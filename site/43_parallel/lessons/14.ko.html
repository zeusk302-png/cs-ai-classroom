소단원 14.1

강한·약한 확장성

친구를 두 배 부르면 같은 숙제를 빨리 하는 것과 숙제를 두 배 더 하는 것은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • speedup과 효율

  • 직렬 구간과 통신 비용

  • 문제 크기의 정의

학습 목표

  • 강한 확장성과 약한 확장성 실험의 작업량을 구분한다.

  • 자체 자료에서 속도 향상·효율을 계산한다.

  • 직렬 비중과 추가 비용의 한계를 설명한다.

구현마다 기준 시간을 바꾸면 가장 빠른 후보가 달라질까요?

새 같은 입력·같은 정확 결과의 종이 시간 모형에서 구현 A의 한 작업자 시간은 96 s, 네 작업자 시간은 32 s다. 구현 B는 각각 64 s, 24 s다. 각 구현의 자기 직렬판에 대한 speedup은 A가 3, B가 8/3이므로 A의 비율이 크다. 그러나 모형의 네 작업자 완료 시간은 B의 24 s가 더 짧다. 공통 기준으로 이 후보 집합의 빠른 직렬판 64 s를 사용하면 A의 비율은 2, B의 비율은 8/3이다. 어떤 기준을 사용했는지 쓰지 않으면 알고리즘 개선과 자원 분할을 한 숫자로 섞게 된다. 이 시간은 지정 모형의 값이며 측정한 실행 자료가 아니다.

자기 기준 효율은 A가 3/4, B가 2/3이다. 네 작업자를 완료까지 모두 예약한다는 별도 과금 모형에서는 예약량이 A의 128 worker·s, B의 96 worker·s다. 예약량 상한 100 worker·s이면 A는 제외하고 B는 허용한다. 예약량은 활성 CPU 시간 합이나 에너지 소비가 아니다. 이 모형에서는 네 작업자가 대기 중에도 예약을 유지한다. 한 작업자 후보까지 포함하면 B의 직렬판도 64 worker·s로 허용되지만 완료 시간은 64 s이므로 허용 후보 중 B의 네 작업자 판이 더 빠르다.

별도 약한 확장성 모형의 작업량은 n³에 비례하고 시작 길이는 n₀, 시작 작업자 수는 1이다. 길이를 2n₀로 바꾸면 총 작업이 8배이므로 작업자당 연산량을 유지하려면 작업자를 8명으로 늘린다. 같은 알고리즘의 입력 저장 크기는 n²에 비례한다. 모든 작업자에 전체 입력을 복제한다는 계약이면 작업자마다 저장 크기가 4배가 된다. 반대로 입력을 작업자별로 균등 분할하여 추가 복제가 없다는 별도 계약이면 작업자당 입력 저장은 원래의 4/8=1/2이다. 연산량을 일정하게 유지했다는 사실만으로 작업자당 메모리도 일정하다고 말할 수 없다.

약한 비교에서 시작 시간 12 s, 여덟 작업자의 커진 작업 완료 시간 15 s이면 약한 효율은 4/5이고 총 처리량 증가율은 32/5이다. 총 작업이 달라졌으므로 같은 작업의 강한 speedup 32/5라고 부르지 않는다. 총 작업을 유지한 네 작업자 비교에서 시간 증가가 나타나면 통신, 균형, 메모리 계층, 시작 비용의 기록을 더 확인해야 한다. 시간 하나로 원인 하나를 지정하지 않는다.

먼저 확인할 개념
  • 기준 작업량과 예약 자원

    강한 비교의 동일 작업 및 약한 비교의 작업자당 몫을 기준 시간 변경과 대조한다.

  • 허용 후보와 완료 범위

    정확성·자원 계약을 만족한 후보끼리 같은 완료 사건을 비교한다.

동일한 문제를 빨리 풀기

강한 확장성은 총 작업량 W를 유지하고 처리 자원 p를 늘리는 비교다. 한 자원 시간 T1과 p자원 시간 Tp로 speedup S=T1/Tp, 효율 E=S/p를 계산한다. 같은 정확성·입력·출력 조건이 필요하다. 작은 데이터로 바꾼 병렬 결과를 원래 큰 데이터의 직렬 시간과 비교하면 자원 효과와 작업량 감소가 섞인다.

p는 이 예제에서 같은 종류의 계산 작업자 수다. 실제 보고에서는 노드, 프로세스, 스레드, 코어를 구별하고 하드웨어 구성을 적는다. 완료까지의 벽시계 시간과 여러 작업자의 CPU 시간 합도 다르다. 빨리 끝났다고 총 자원 사용량까지 줄었다고 단정하지 않는다.

한 작업자 몫을 유지하며 큰 문제 풀기

약한 확장성은 작업자당 일을 일정하게 유지하며 총 작업량을 p배로 키운다. 이상적이면 시간은 일정하다. 한 작업자의 W0 처리 시간 T1과 p작업자의 pW0 처리 시간 Tp로 약한 효율을 T1/Tp라 정의할 수 있다. 이는 같은 W의 speedup과 다른 비율이다. 총 처리량 증가율 pT1/Tp를 같은 문제의 속도 향상이라고 부르지 않는다.

문제 크기는 실제 연산량과 메모리 요구를 기준으로 정한다. 예를 들어 같은 알고리즘에서 밀집 n×n 행렬 연산이 n³에 비례한다면 n을 두 배 늘리는 것이 작업을 두 배로 늘리는 일은 아니다. 격자점 수와 차원 길이를 혼동하지 않고 작업자별 몫을 계산한다. 결과표에는 총 크기와 자원당 크기를 모두 적는다.

직렬 부분과 새 비용을 함께 본다

한 자원 기준 시간의 비중 s가 직렬이고 1−s가 이상적으로 나눠진다면 Tp/T1=s+(1−s)/p다. 실제 통신·동기화·시작 비용은 이 이상 모형에 추가된다. s=0.1이면 무한 자원에서도 이상 speedup의 한계는 10이다. 이 비중은 지정한 입력과 기준 구현의 가정이며 모든 입력에 고정된 물성이 아니다.

작업이 한쪽에 몰리거나 공유 메모리 대역폭이 포화되면 p를 늘려도 좋아지지 않을 수 있다. 큰 p에서 시간이 다시 늘어났다면 오류부터 점검하고, 작업량 분배·통신·대기 시간을 나누어 원인을 찾는다. 효율 숫자만으로 원인을 단정하지 않는다. 약한 확장성의 시간이 일정해도 강한 확장성의 효율이 높다는 결론은 나오지 않는다.

길이 두 배의 약한 비교

작업은 8배이고 복제 입력 저장은 작업자마다 4배다.

분자의 기준 구현과 분모의 완료 범위를 적는다. 시간·효율·예약량의 단위를 구별하고, 약한 비교는 총 작업량도 표시한다.

중간 과정을 따라가는 예제

모두 자체 가상 자료다. 같은 작업 W의 T1=100초, T2=60초, T4=40초이다. 별도 약한 실험은 W0를 한 작업자가 10초, 4W0를 네 작업자가 12초에 처리했다. 강한/약한 계수를 구하라.

  1. 강한 p=2의 S=100/60=5/3, E=(5/3)/2=5/6≈83.33%다.

  2. 강한 p=4의 S=100/40=2.5, E=2.5/4=0.625=62.5%다.

  3. 약한 p=4의 효율은 10/12=5/6≈83.33%다. 총 작업량은 서로 달라 같은 W의 speedup 100/40과 직접 비교하지 않는다.

  4. 약한 처리량 비율은 (4W0/12)/(W0/10)=10/3≈3.333이다. 네 배 이상적 처리량의 5/6에 해당한다.

강한 효율은 p=2에서 83.33%, p=4에서 62.5%이고 별도 약한 효율은 83.33%다. 동일한 83.33%도 분모와 작업량 규약이 다르다.

연산량과 복제 저장의 다른 배수

n을 두 배 키워 작업자당 n³ 연산을 유지한다. 전체 n² 입력을 각 작업자에 복제한다면 작업자 수와 지역 저장 배수는?

  1. 총 연산은 8배라 작업자를 8명으로 늘린다.

  2. 전체 입력은 4배이며 각 작업자가 전체를 복제하므로 지역 입력 저장도 4배다.

작업자는 8배, 작업자당 복제 저장은 4배다.

비교할 점

추가 저장과 통신은 이 단순 모형에 포함하지 않았다.

종이와 본문으로 직접 해보기

s=0.1인 이상 모형에서 p=4와 p=8의 예상 시간을 T1=100초 기준으로 구하라. p=4 실제 가상 시간이 40초라면 이상 시간과의 차이는 얼마인가?

힌트 보기

100×(0.1+0.9/p)를 쓴다.

풀이 보기

p=4는 32.5초, p=8은 21.25초다. 가상 40초와 p=4 이상 시간의 차이는 7.5초지만 이것만으로 통신 한 종류의 비용이라고 특정할 수는 없다. 모형의 분해와 실제 측정을 확인해야 한다.

오해와 반례

약한 효율 100%이면 동일한 문제도 자원 수만큼 빨라진다.

약한 실험은 총 문제를 키운다. 고정 W의 시간과 직렬 부분에 대한 강한 실험을 따로 해야 한다.

같은 kernel의 두 메모리 계층과 늘어난 FLOP/s를 어떻게 읽을까요?

새 roofline 손모형은 필요한 연산 F=2×10⁹ FLOP, DRAM 읽기+쓰기 이동 Q_D=10⁹ byte, DRAM 대역폭 B_D=20×10⁹ byte/s, 계산 지붕 P=100×10⁹ FLOP/s다. DRAM 집약도는 2 FLOP/byte, 지붕은 min(100,20×2)=40 GFLOP/s다. 지정 연산을 끝내는 시간은 적어도 2/40=1/20 s다. 같은 kernel의 L2 이동은 Q_L=4×10⁹ byte이고 해당 계층 대역폭은 200×10⁹ byte/s라고 따로 정한다. L2 집약도는 1/2이고 지붕은 100 GFLOP/s, 시간 하한은 1/50 s다. 두 계층 조건을 동시에 만족하려면 시간은 두 하한 중 큰 1/20 s 이상이어야 한다. L2 바이트와 DRAM 대역폭을 섞은 1/5 s 하한은 이 kernel의 계층 모형이 아니다.

지붕은 시간 하한을 주지만 달성 완료 시간을 주지 않는다. 계산과 이동이 이상적으로 겹칠 수 있는 roofline 해석에서는 각 하한의 최댓값을 쓰며 무조건 더하지 않는다. 반대로 지정한 준비 시간 3/100 s가 kernel과 겹치지 않고 앞에 붙는 별도 모형이면 전체 하한은 3/100+1/20=2/25 s다. 재사용으로 DRAM 이동만 절반으로 줄이고 나머지 모형을 유지하면 DRAM 하한은 1/40 s, L2 하한은 1/50 s로 전체 하한은 11/200 s다. 이 하한끼리의 비율 16/11은 관측한 speedup이 아니며 실제 실행은 더 느릴 수 있다.

별도 가상 완료 표에서 원래 kernel은 필요한 연산 2×10⁹개를 3/50 s에 수행한다. 변경 kernel은 같은 필요한 출력을 만들지만 불필요한 연산을 더해 총 4×10⁹개를 2/25 s에 수행한다. 총 연산 처리율은 원래 100/3 GFLOP/s, 변경 50 GFLOP/s로 높아졌지만 완료 시간은 0.06 s에서 0.08 s로 길어졌다. 필요한 연산량을 공통 2×10⁹으로 놓으면 유용 작업 처리율은 변경에서 25 GFLOP/s로 낮아진다. 출력이 같아도 실행 연산량이 달라졌음을 숨기지 않는다.

실제 프로파일링에서는 각 계층의 읽기와 쓰기, 정밀도, 완료 사건과 계측 부담을 확인해야 한다. 이 단원의 바이트·대역폭·시간은 직접 정한 종이 모형이다. NERSC의 계층별 roofline과 FLOPs/bytes/runtime 정의를 읽었지만 ERT, Nsight 또는 실제 kernel을 실행하여 위 숫자를 측정하지 않았다.

먼저 확인할 개념
  • 계층별 이동량과 성능 지붕

    기본의 F/Q와 min(P,BI)를 다른 계층의 동시 시간 조건으로 확장한다.

  • 필요한 결과와 전체 시간

    연산 처리율 증가를 같은 출력의 완료 속도와 구별한다.

먼저 무엇을 세는지 정한다

산술 집약도 I는 특정 코드 영역의 부동소수점 연산 수 F를 정한 계층을 지나는 읽기+쓰기 바이트 Q로 나눈 F/Q FLOP/byte다. F는 개수이고 F/시간은 처리율이다. L1–L2 이동량과 DRAM 이동량은 다를 수 있으므로 Q의 경계를 적는다. 입력 파일 크기만으로 Q를 대체하면 반복 읽기나 출력 쓰기를 놓친다.

프로파일은 전체 실행과 특정 kernel을 분리한다. 장치 kernel이 빨라져도 호스트 준비, 전송, 동기화가 전체 시간을 지배할 수 있다. 비동기 작업을 enqueue한 시간만 재고 완료 시간을 재지 않으면 빠른 호출 시간을 실행 시간으로 착각한다. 실제 도구의 카운터 의미와 완료 동기화 범위를 읽고, 계측이 실행에 준 영향도 기록한다.

지붕은 달성값이 아니라 가능 범위다

단순 roofline에서는 최대 연산 처리율 P와 해당 계층 대역폭 B로 가능한 처리율의 상한을 min(P,B×I)로 본다. B의 byte/s와 I의 FLOP/byte를 곱하면 FLOP/s가 된다. 두 상한이 만나는 I=P/B가 ridge다. 낮은 I에서는 이동량 감소와 재사용을, 높은 I에서는 계산 사용률을 살펴볼 근거를 준다.

실제 성능은 이 지붕보다 낮을 수 있다. 의존성 지연, 불규칙 접근, 분기, 작업 부족과 동기화가 다른 제한을 만든다. 공급사 최고 수치도 해당 workload에서 달성 가능한 지속 성능과 같지 않을 수 있다. ERT 같은 실험은 상한 추정의 추가 근거이지만 여기서는 실행하지 않는다. 이 단순 모형이 모든 시간 요소를 포함한다고 주장하지 않는다.

연산량을 늘리기보다 필요한 일을 유지한다

메모리 재사용으로 Q를 줄이고 F를 그대로 유지하면 같은 유용 작업에서 I가 높아진다. 필요 없는 계산을 더해 I를 올려도 유용 결과를 빨리 만들었다는 뜻은 아니다. 최적화 전후의 출력 계약을 유지하고 전체 시간, 유용 작업량, 전송량을 함께 비교한다.

타일링과 데이터 배치는 캐시 계층별로 효과가 달라질 수 있다. DRAM Q는 줄고 L1 이동량은 그대로일 수도 있다. 동시 작업자 수를 늘린다고 공유 B가 매번 배수로 커지는 것도 아니다. 어떤 계층과 장치의 roofline인지 명시하고, 서로 다른 정밀도 연산의 처리율을 섞지 않는다.

중간 과정을 따라가는 예제

자체 가상 kernel의 F=2×10⁹ FLOP, DRAM 이동 Q=4×10⁹ byte이다. 가상 상한 P=200 GFLOP/s, B=100 GB/s이고 십진 G=10⁹를 쓴다. 가상 완료 시간은 0.08초다. I, 상한, 달성 처리율을 구하라.

  1. I=(2×10⁹)/(4×10⁹)=0.5 FLOP/byte다.

  2. 대역폭 상한 B×I=100×0.5=50 GFLOP/s다. 계산 상한 200과의 작은 값은 50이다. ridge는 200/100=2 FLOP/byte다.

  3. 달성 처리율은 2 GFLOP/0.08초=25 GFLOP/s다. 단순 지붕의 절반이며, 낮은 수치의 정확한 원인은 이 숫자만으로 알 수 없다.

  4. 같은 F를 유지하며 Q를 1×10⁹ byte로 줄이는 가상 변경이면 I=2, 상한은 200 GFLOP/s가 된다. 단순 이상 최소 시간은 2/200=0.01초지만 실제 달성을 보장하지 않는다.

원래 I=0.5, 상한 50, 달성 25 GFLOP/s다. 재사용 변경의 이상 상한은 200이며 실제 속도 향상은 추가 측정이 필요하다.

합계 하나와 빠른 중앙값만으로 실행을 승인할 수 있을까요?

새 정확 정수 모형의 입력은 고유 ID a,b,c이고 값은 각각 2,2,8이다. 목표는 각 ID를 정확히 한 번 처리하여 합 12를 만드는 것이다. 잘못된 이력 a,a,c도 처리 횟수가 세 번이고 합 12다. 그러나 a는 두 번, b는 영 번 처리했으므로 목표 계약을 실패했다. 합계와 총 개수만 같은 검사는 이 사례의 누락·중복을 잡지 못한다. 고유 ID별 출현 횟수를 검사해야 하며, 이것도 모든 내부 동기화의 증명과 동일하지 않다.

별도 모든 출력이 정확성 검사를 통과한 가상 완료 표에서 A의 다섯 시간은 [4,4,4,4,24] ms, B는 [6,6,6,6,6] ms다. A의 중앙값은 4 ms라 B의 6 ms보다 작지만 A의 산술 평균은 8 ms이고 최대는 24 ms다. B의 평균과 최대는 모두 6 ms다. 중앙값을 목표로 하면 A가, 이 표의 평균 또는 최대를 목표로 하면 B가 유리하다. 이 다섯 표본만으로 미래 확률 분포나 임의의 꼬리 분위수를 인증하지 않는다. 24 ms를 이유 없이 버리면 목표와 원자료를 바꾸게 된다.

실패가 있는 별도 다섯 시도 장부에서 C는 성공한 세 번이 각각 2 ms이고 실패한 두 번이 각각 10 ms다. 모든 시도는 순차이고 겹치지 않는다. 성공률은 3/5, 성공 시도만의 평균 시간은 2 ms, 전체 시도 총 시간은 26 ms다. 지정 장부에서 성공 결과 하나당 전체 소요 시간은 26/3 ms이며 전체 시간당 성공 완료율은 3/26개/ms다. 성공한 빠른 세 번만 골라 B의 모든 시도와 비교하는 것은 같은 분모가 아니다. 실패한 시도 비용과 실패 횟수를 함께 남긴다.

재현 가능한 보고에는 입력 ID·값·순서, 정확성 및 허용 오차, 자원 구성, 시간 시작·끝, 예열과 준비 포함 여부, 각 시도 성공 여부와 원시간을 남긴다. 이 연습에서는 실제 실행 seed나 compiler 정보를 만들어 기록하지 않는다. 모두 손으로 정한 장부이며 실제 계측·학생 실험은 없다.

정수 알고리즘은 오버플로 규약까지 포함해 정확한 결과를 비교할 수 있다. 부동소수점 병렬 합은 순서가 바뀌면 반올림 경로가 달라질 수 있다. bit 단위 동일 결과가 필요한지, 수치 허용 오차를 만족하면 되는지를 명세에서 정한다. 다른 답을 모두 반올림 탓이라고 넘기면 race나 누락 원소를 놓친다.

연습은 실제 IEEE 연산이 아니라 십진 유효 숫자 3자리, 각 덧셈 뒤 반올림하는 자체 모형이다. 1000+1을 먼저 계산하면 1000으로 반올림되고 이후 −1000을 더해 0이다. 1000+(1−1000)은 괄호 안 −999가 정확히 표현되어 결과 1이다. 참값 1과 비교하여 합 순서가 오차를 바꾸는 직관을 얻되 실제 장치의 동작 증거로 부르지 않는다.

허용 오차와 반복 실패를 함께 기록한다

검사 기준을 |y−yref|≤atol+rtol×|yref|처럼 미리 정할 수 있다. 0 근처에는 상대 오차만으로 판단하기 어려워 절대 오차가 필요하다. 기준값도 충분히 정확한 독립 방법으로 구하고 크기·음수·중복·경계 입력을 포함한다. 한 번 맞고 반복 실행에서 달라지면 동기화와 미초기화 상태를 조사한다.

입력 seed, 데이터, 자원 수, compiler·옵션·라이브러리, 정밀도, reduction 순서와 실행 환경을 남긴다. deterministic이라는 주장에는 같은 입력·조건에서 무엇이 동일해야 하는지 범위가 필요하다. 도구 실행이나 사람 실험이 없으면 설계 검토와 수학 검산 상태만 기록한다. 반복 통과가 모든 가능한 interleaving의 증명은 아니다.

자체 가상 시간 표에서 예열과 초기화를 포함하는지 고정하고 여러 번의 원자료를 보관한다. 느린 표본을 이유 없이 버려 개선을 부풀리지 않는다. 중앙값은 한 번의 이상 표본에 덜 민감하지만 꼬리 지연도 따로 필요할 수 있다. 빠른 결과가 정확성 검사에 실패하면 유효한 비교 표에서 실패로 남긴다.

풀이와 답 확인

네 작업자 허용 후보는 B다. kernel 시간 하한은 0.04 s이고 준비를 포함한 전체 하한은 0.06 s다. 이력은 합 15라도 ID 계약을 실패한다. C의 성공률은 3/4이고 성공당 전체 비용은 6 ms다.
