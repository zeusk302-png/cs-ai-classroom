소단원 10.1

MapReduce의 데이터 흐름

여러 사람이 다른 쪽의 글을 읽고도 같은 단어의 전체 횟수를 어떻게 모을까?

준비 개념과 학습 목표

준비 개념

  • 키와 값

  • 합과 평균

  • 파일과 레코드

학습 목표

  • map·같은 키 모으기·reduce를 구별한다.

  • 지역 합계와 전체 합계의 관계를 계산한다.

지역 평균과 지역 분산만 평균내면 전체 통계가 될까요?

자체 정수 자료를 두 조각으로 나눈다. A에는 [0,2,4], B에는 [10]이 있다. 전체 자료는 네 개이며 모집단 분산을 사용한다. 각 조각에서 원소 수 n, 합 s, 제곱합 q를 함께 보존한다. A의 상태는 (3,6,20), B의 상태는 (1,10,100)이다. 병합은 세 좌표를 각각 더하는 연산이다. 빈 조각의 상태는 (0,0,0)이고 항등원이다.

병합한 상태는 (4,16,120)이다. 최종 평균은 s/n=4이며 모집단 분산은 q/n−(s/n)²=120/4−16=14다. 반대로 A의 평균 2와 B의 평균 10을 같은 비중으로 평균내면 6이다. A의 모집단 분산은 8/3이고 B의 분산은 0이므로 지역 분산을 같은 비중으로 평균내면 4/3이다. 두 계산 모두 전체 통계와 다르다. 평균의 불균등 비중과 집단 사이 평균 차이를 빠뜨린 결과다.

이 상태의 병합은 결합법칙과 교환법칙을 만족한다. 다만 평균과 분산의 최종화를 중간 병합 전에 해버리면 필요한 상태가 사라진다. n=0이면 평균과 분산을 정의하지 않는다. 원본 MapReduce의 combiner는 선택 사항이므로 한 번의 지역 병합이 반드시 실행된다는 가정도 필요 없다. 여기서는 정확한 정수·유리수 손계산을 사용하며 실제 부동소수점 합의 순서 오차는 측정하지 않는다.

먼저 확인할 개념
  • map·group·reduce와 중간 집계

    키별 상태를 병합한 뒤 최종화하는 순서를 확인한다.

  • 지역 조각과 선택된 결과

    조각의 자료 수와 실행 시도 수를 구별한다.

나누는 기준과 모으는 기준

입력 문서를 나누는 기준과 결과를 모으는 기준은 같지 않다. map은 입력 레코드에서 중간 키/값들을 만든다. 같은 키의 중간 값들을 모은 뒤 reduce가 그 묶음을 처리한다. 아래에서 문서 이름은 입력을 식별하지만 출력 집계의 키는 단어다.

종이에서는 글을 카드로 나누고 각 단어에 1을 적어 보자. 같은 단어의 카드를 한 봉투에 넣어 더하면 문서가 달라도 전체 횟수가 나온다. 컴퓨터에서도 이런 논리적 흐름을 구현하지만 실제 데이터 이동·실패 처리·파일 배치는 별도 설계다.

키가 같다는 규칙을 먼저 정한다

자체 예제는 공백으로 나눈 한글 단어를 그대로 키로 사용하며 구두점이나 대소문자 정규화가 없다. 따라서 고양이와 고양이!는 다른 키다. 좋은 집계인지 판단하려면 먼저 어떤 입력을 같은 것으로 보는지 결정해야 한다.

동일 키가 같은 reduce 작업으로 가야 전체 집계가 완성된다. 서로 다른 키가 같은 작업에 배정되는 것은 가능하며 그 안에서 다시 키별로 묶는다. 작업 하나와 키 하나를 같은 개념으로 읽으면 작업 수만큼만 단어 종류가 생긴다는 잘못된 결론에 이른다.

부분 집계는 결과를 보존해야 한다

단어의 정수 횟수는 부분 합을 다시 더해도 같은 전체 합이다. 이런 성질을 이용해 이동할 값을 줄일 수 있다. 중간에서 합쳐도 최종 답이 같아야 하며 combiner를 쓰지 않아도 계산의 의미가 유지돼야 한다.

평균을 바로 부분 평균끼리 평균 내는 것은 다른 문제다. 각 묶음의 크기가 다를 수 있으므로 합과 개수를 함께 전달해야 한다. 아래 활동은 이 오류를 작은 숫자로 보여 준다. 부동소수점 합의 순서 오차는 이 절의 정확한 정수 합 모형과도 구별한다.

지역 평균과 지역 분산만 평균내면 전체 통계가 될까요?
단계 또는 자료보존하는 상태판정

A = [0,2,4]

n = 3, s = 6, q = 20

평균은 2, 모집단 분산은 8/3

B = [10]

n = 1, s = 10, q = 100

평균은 10, 모집단 분산은 0

좌표별 합 병합

n = 4, s = 16, q = 120

전체 평균은 4, 모집단 분산은 14

빈 조각

n = 0, s = 0, q = 0

병합 가능하지만 단독 최종화는 불가

괄호의 순서는 항상 원소 수·합·제곱합이다. 분산의 분모는 표본 보정의 n−1이 아니라 모집단의 n이다. 조각 수 두 개를 원소 수 네 개의 분모로 바꾸지 않는다.

중간 과정을 따라가는 예제

자체 입력 D1="고양이 별 고양이", D2="별 달", D3="고양이 달 달"이다. 공백 단어별로 (단어,1)을 내보내 전체 횟수와 각 문서의 부분 합을 구하라.

  1. D1은 고양이1·별1·고양이1, D2는 별1·달1, D3는 고양이1·달1·달1로 총 8개 쌍을 낸다.

  2. 같은 키를 모으면 고양이 [1,1,1], 별 [1,1], 달 [1,1,1]이다. 합은 3,2,3이다.

  3. 문서별 먼저 합치면 D1 고양이2/별1, D2 별1/달1, D3 고양이1/달2로 6개 쌍이다. 다시 키별로 합쳐도 3,2,3이다.

전체는 고양이3·별2·달3, 합 8이다. 이 입력에서는 문서별 부분 합이 중간 쌍을 8→6으로 줄인다.

조건을 바꾸어 비교하기

최종화 전에 보존하는 세 좌표

A와 B를 병합하여 전체 평균과 모집단 분산을 구하라.

  1. 상태를 더하면 (3+1,6+10,20+100)=(4,16,120)이다.

  2. 평균은 16/4=4이고 분산은 120/4−4²=14다.

전체 평균은 4, 모집단 분산은 14다.

비교할 점

지역 평균 두 개의 단순 평균 6은 자료 수를 보존하지 않는다.

부분 분산을 평균낸 결과의 실패

A의 모집단 분산과 B의 모집단 분산을 계산하고 둘의 단순 평균을 전체 분산과 비교하라.

  1. A의 제곱합 평균은 20/3이고 평균 제곱은 4이므로 분산은 8/3이다. B의 분산은 0이다.

  2. 부분 분산의 단순 평균은 4/3이다. 전체 분산 14와 비교하면 집단 사이 차이도 누락했다.

부분 분산의 단순 평균은 4/3이며 전체 분산 14와 다르다.

비교할 점

원소 수로 부분 분산을 가중해도 집단 사이 평균 차이까지 자동 복구되는 것은 아니다.

종이와 본문으로 직접 해보기

묶음 A=[2,4], B=[10]의 부분 평균을 평균 낸 값과 전체 평균을 비교하라. 합/개수 쌍을 전달하면 어떻게 고칠까?

힌트 보기

A와 B의 자료 수는 2와 1이다. 평균을 합칠 때 원래 분모를 보존한다.

풀이 보기

부분 평균은 3과 10이어서 단순 평균은 6.5다. 전체 평균은 (2+4+10)/3=16/3이다. 부분 쌍 (6,2),(10,1)을 합치면 (16,3)으로 올바른 16/3을 얻는다.

오해와 반례

reduce는 어떤 계산이든 각 map의 결과를 평균 내면 된다.

앞 평균 반례처럼 그룹 크기를 잃으면 답이 달라진다. 부분 집계는 최종 계산에 필요한 정보를 보존해야 한다. map 함수가 내보내는 키와 값의 의미부터 명시한다.

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

A를 [0,2]와 [4]로 더 나눠 세 조각으로 처리한다. 병합 상태와 최종 평균·모집단 분산을 구하라.

힌트 1

[0,2]의 상태는 (2,2,4)다.

힌트 2

[4]와 [10]의 상태를 좌표별로 더한다.

풀이와 답 확인

  1. 세 상태는 (2,2,4), (1,4,16), (1,10,100)이다.

  2. 합은 (4,16,120)이므로 평균 4와 분산 14를 유지한다.

전체 평균은 4, 모집단 분산은 14다.

흔한 오답에서 다시 생각하기

조각을 하나 늘리면 평균의 분모도 반드시 하나 늘어난다.

최종 분모는 조각 수가 아니라 자료 수다.

연습 2 · 오류 찾아 고치기

A와 B의 지역 분산을 원소 수로 가중해 (3×8/3+1×0)/4=2를 얻고 전체 분산이라 썼다. 빠진 항을 복구하라.

힌트 1

전체 평균은 4다.

힌트 2

지역 평균 2와 10의 전체 평균으로부터의 차이를 사용한다.

풀이와 답 확인

  1. 집단 내부 분산의 가중 합은 2다.

  2. 집단 사이 항은 (3×(2−4)²+1×(10−4)²)/4=12다. 둘을 더하면 14다.

누락한 집단 사이 항은 12이며 전체 분산은 14다.

흔한 오답에서 다시 생각하기

원소 수로 가중하면 모든 분산 계산이 완성된다.

부분 분산은 각 부분의 평균을 기준으로 하므로 전체 평균과의 차이를 추가해야 한다.

연습 3 · 직접 만들어 보기

이 모형에서 combiner를 쓰지 않거나 여러 단계로 반복 적용해도 같은 최종 결과를 얻는 상태·병합·최종화 계약을 작성하라.

힌트 1

원소 하나의 상태를 먼저 정한다.

힌트 2

빈 상태와 n=0의 처리를 명시한다.

풀이와 답 확인

  1. 값 x 하나를 (1,x,x²)로 바꾸고 세 좌표를 각각 더한다. 빈 상태는 (0,0,0)이다.

  2. 최종 n이 양수일 때만 s/n과 q/n−(s/n)²를 계산한다. 정확 산술 계약에서는 병합 묶음과 순서를 바꿔도 같은 상태다.

중간 단계는 세 좌표를 보존하고 전체 병합 뒤 최종화한다.

흔한 오답에서 다시 생각하기

중간 평균과 분산만 남겨도 항상 같은 병합 연산을 계속할 수 있다.

부분 크기와 평균 차이를 복구할 충분한 상태가 필요하다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

다른 집계에서 A의 고유 ID 집합은 {a,b,c}, B는 {b,c,d}다. 지역 고유 개수의 합과 전체 고유 개수를 비교하고 안전한 병합 상태를 제안하라.

힌트 1

ID의 교집합은 {b,c}다.

힌트 2

숫자 두 개만 보존하면 겹침을 알 수 없다.

풀이와 답 확인

  1. 지역 개수의 합은 3+3=6이지만 전체 합집합은 {a,b,c,d}로 개수 4다.

  2. 정확한 자체 계약에서는 ID 집합을 보존하여 합집합으로 병합한 뒤 개수를 센다.

전체 고유 ID는 4개이며 지역 개수의 합 6과 다르다.

흔한 오답에서 다시 생각하기

합계 집계가 되므로 고유 개수도 같은 숫자 덧셈이면 된다.

키별 집계마다 필요한 병합 상태가 다르다. 근사 sketch의 오차 계약은 여기서 정하지 않았다.

설명 기준 확인

combiner의 실행 횟수를 전제해야 하는가?

설명 기준 확인

이 상태 계약은 생략과 반복 병합에 안전하며 실제 실행 횟수를 가정하지 않는다.

한 단계 더

D2에 달을 한 번 더 넣으면 달4, 전체9다. 중간 쌍은 부분 합 전 9개, 문서별 부분 합 뒤 여전히 6개다. 쌍의 개수와 쌍에 기록된 횟수의 합이 다름을 표로 확인하라. 이 표는 실제 클러스터 출력이 아닌 자체 종이 계산이다.

작업 배정·재실행·shuffle

고장 난 작업을 다시 돌리면 단어 수를 두 번 세게 되지 않을까?

준비 개념과 학습 목표

준비 개념

  • map/reduce 흐름

  • 실패와 재시도

  • 같은 키 집계

학습 목표

  • 작업과 실행 시도를 구분한다.

  • shuffle의 키별 이동과 편중을 계산한다.

  • 출력 확정과 외부 부수효과를 구분한다.

뜨거운 키를 쪼개면 추가 병합 비용까지 줄어들까요?

자체 비용 모형에서 키 h의 값 1이 12개 있고 다른 서로 다른 키의 값 1이 네 개 있다. reducer 네 개는 각 입력 레코드를 처리하는 데 비용 1이 들고 동시에 시작한다. 원래 배치는 h를 R0에 몰고 나머지 네 키를 R1에 하나, R2에 하나, R3에 둘 둔다. 입력 부하는 [12,1,1,2]이며 한 단계의 완료 비용은 최대 부하인 12다. 네 키는 h와 다른 별개 키다.

h에 임시 salt 네 개를 붙여 각각 세 값을 모으고 R0부터 R3까지 한 그룹씩 배치한다. 첫 단계의 부하는 [3,4,4,5]이므로 완료 비용은 5다. 첫 출력은 h의 부분합 네 개와 다른 키의 결과 네 개로 총 여덟 레코드다. 둘째 단계에서 salt를 제거하고 h의 부분합 네 개를 R0에 병합하며 다른 네 결과도 각각 다시 처리한다. 둘째 부하는 [4,1,1,2]이고 완료 비용은 4다. 따라서 두 단계 합은 9다. 추가 단계의 고정 비용 H≥0를 포함하면 9+H이고 원래 방식의 12보다 빠른 조건은 H<3이다.

이 비교는 각 레코드의 동일 비용과 단계별 장벽, 명시한 파티션, 첫 단계의 부분합이 최종 합과 같다는 계약이다. 실제 shuffle 바이트·네트워크·디스크·스케줄러는 측정하지 않았다. 실행 재시도의 출력 선택도 외부 효과와 구별한다. 같은 논리 task의 두 attempt 중 한 출력만 최종 반영해도 두 attempt가 외부 알림을 각각 보냈다면 알림은 두 번 생길 수 있다. 외부 효과에는 논리 업무 ID와 내용 검사를 원자적으로 묶는 별도 계약이 필요하다.

먼저 확인할 개념
  • task·attempt·partition의 구별

    선택된 출력과 실행 횟수 및 키 쏠림을 각각 계산한다.

  • 부분합의 안전한 재병합

    salt를 제거한 둘째 합이 원래 키의 합을 복구해야 한다.

작업 하나가 여러 시도를 가질 수 있다

일감 자체인 task와 실제 한 번 돌린 attempt를 구별하자. 자체 시간선에서 작업 M1의 첫 시도가 실패하면 다른 기계가 같은 입력으로 다시 시도한다. 성공한 시도의 중간 출력을 선택하는 절차가 있어야 두 시도를 무조건 모두 더하는 오류를 피한다.

원 논문의 구현은 로컬 중간 출력이 사라진 완료 map도 다시 계산할 수 있으며, 전역 파일시스템에 확정된 reduce 출력은 다르게 다룬다. 이는 그 구현의 저장 위치와 확정 규칙에 따른 구별이다. 모든 처리 제품에 같은 실패 복구 절차를 일반화하지 않는다.

shuffle은 필요한 조각을 모으는 이동이다

분할 함수는 중간 키가 갈 작업을 정한다. shuffle은 각 map의 관련 조각을 해당 reduce 쪽으로 보내고, 키별 묶음을 만든다. 따라서 데이터 이동량과 키 편중이 계산 시간에 영향을 준다. 입력 분할 수를 늘리는 것만으로 인기 키의 큰 묶음이 저절로 나뉘지는 않는다.

자체 모형에서는 키의 정수값 mod 2로 두 작업을 배정한다. 이는 구현의 기본 해시 함수를 재현하는 코드가 아니라 계산이 보이는 임의 교육 규칙이다. 서로 다른 키가 같은 나머지를 가질 수 있으므로 나머지만을 최종 집계 키로 바꾸면 안 된다.

파일의 확정과 외부 효과는 별도다

재실행에서 같은 입력에 같은 출력을 만드는 결정적 함수는 결과를 비교하기 쉽다. 그러나 외부 계좌에 더하기나 알림 보내기 같은 효과까지 프레임워크의 출력 파일 확정으로 자동 보호되지는 않는다. 같은 시도를 두 번 수행했을 때 외부 효과가 중복될 수 있다.

자체 모형의 외부 카운터가 0에서 시작해 시도마다 +1이면 두 시도로 2가 된다. 하나의 작업을 뜻하는 식별자를 써 중복 처리를 막는 설계와, 단순히 서로 다른 시도 이름의 파일을 만드는 설계를 구별하자. 이름 충돌 방지와 업무 중복 방지는 같은 보장이 아니다.

부하 [4,1,1,2]

부하 배열은 R0·R1·R2·R3 순서다. 단계 안에서는 최대값을 사용하고 단계 사이는 더한다. 둘째 단계의 다른 키 네 레코드도 비용에 넣었으며 h의 원래 합 12를 h의 입력 레코드 수와 혼동하지 않는다.

중간 과정을 따라가는 예제

교육 partition 규칙은 p(k)=k mod 2다. map M1의 쌍은 (1,1),(2,1),(1,1), M2는 (2,1),(3,1)이다. M1 첫 시도 a0는 실패하고 같은 입력의 a1만 선택한다. 작업별 쌍 수와 키별 합을 구하라.

  1. p(1)=1,p(2)=0,p(3)=1이다. reducer0은 M1의 (2,1)과 M2의 (2,1)로 쌍2개를 받는다.

  2. reducer1은 M1의 (1,1) 두 개와 M2의 (3,1) 한 개로 쌍3개다. 다른 키1/3을 따로 묶어 합친다.

  3. 선택한 M1 a1의 출력만 포함하면 키1=2, 키2=2, 키3=1로 총5다. 실패 a0까지 중복 포함한다면 키1=4, 키2=3, 키3=1로 총8이 되어 틀린다.

선택한 시도 기준 reducer0/1의 쌍 수 2/3, 정답 키1/2/3의 합 2/2/1이다.

조건을 바꾸어 비교하기

두 단계의 출력까지 세는 salt 비용

명시한 배치에서 원래 방식과 salt 방식의 단계 부하, 완료 비용, h의 최종 합을 비교하라.

  1. 원래 최대 부하는 12다. salt 첫 단계의 최대 부하는 5이고 h 부분합은 각각 3이다.

  2. 둘째 최대 부하는 4다. 부분합 네 개를 더해 h의 최종 합은 12를 유지한다.

원래 비용은 12, 추가 고정 비용을 빼면 salt 비용은 9다. h의 최종 합은 두 방식 모두 12다.

비교할 점

부하 감소만 보고 둘째 병합과 출력 레코드 비용을 삭제하지 않는다.

출력 선택과 알림 중복의 별도 계약

같은 논리 task T의 attempt A와 B가 각각 같은 외부 알림을 보냈다. 최종 파일에는 B의 출력만 선택됐다. 알림 수와 중복 방지 키를 구별하라.

  1. 파일 선택은 이미 보낸 외부 알림을 취소하지 않는다. 알림 호출은 두 번이다.

  2. attempt ID A와 B를 별도 키로 삼으면 두 효과가 모두 통과한다. 같은 논리 업무 ID와 내용의 원자적 장부가 별도로 필요하다.

선택된 출력은 한 개여도 알림은 두 번일 수 있다. 업무 중복 방지에는 논리 업무 ID를 사용한다.

비교할 점

MapReduce 파일 반영의 의미를 모든 외부 시스템의 exactly-once로 확대하지 않는다.

작업 시도가 한 번만 채택되면 외부 동작도 반드시 한 번만 실행됐다.

결과를 하나 선택해도 실패 시도가 이미 외부 +1을 했을 수 있다. 채택된 출력과 실제 부수효과 횟수를 분리해 기록한다. 순수 계산의 결과 보장과 외부 업무의 중복 방지를 혼동하지 않는다.

추가 고정 비용 H를 2 또는 4로 정한다. 두 경우의 salt 비용을 원래 비용과 비교하라.

힌트 1

두 단계의 순수 비용은 9다.

힌트 2

공통 첫 단계 고정 비용은 비교에서 상쇄한 모형이다.

풀이와 답 확인

  1. H=2이면 비용은 11로 원래 12보다 작다.

  2. H=4이면 비용은 13으로 원래 12보다 크다.

H가 2이면 salt 방식이 유리하고 H가 4이면 원래 방식이 유리하다.

ID만 같고 내용이 다르면 별도 충돌이다.

힌트 2

장부 확인과 효과 반영 사이 경쟁을 막아야 한다.

늦게 도착한 옛 판본이 최신 합을 덮어써도 될까요?

자체 스트림 계약에서 사건 시각으로 창 [0,10)을 만든다. 경계 10의 사건은 다음 창에 속한다. watermark W가 11에 도달하면 첫 누적 결과를 내고, 이후 W<15 동안 이 창의 늦은 사건을 받아 갱신한다. W≥15가 되는 순간 상태를 닫고 이후 이 창의 사건을 버린다. 이 정확한 비교 규칙은 교육용으로 정한 것이며 Beam 모든 runner의 경계 구현을 주장하지 않는다.

A는 사건 시각 2, 값 5이며 첫 결과 전에 들어왔다. 첫 누적 판본 v1의 합은 5다. B는 사건 시각 8, 값 7이며 W=12일 때 도착해 누적 판본 v2의 합 12를 만든다. C는 사건 시각 9, 값 2이며 W=14일 때 도착해 판본 v3의 합 14를 만든다. D는 사건 시각 9, 값 3이며 W=16일 때 도착하므로 버린다. 최종 채택 합은 14이고 버린 값까지 모두 더한 합 17과 다르다.

누적 결과를 받는 저장소에 v1, v3, v2, v3 순서로 전달한다. 수신 순서대로 무조건 교체하면 중간에 v2가 최신 합 14를 옛 합 12로 되돌린다. 창 ID와 판본 번호를 확인하여 가장 큰 판본만 유지하면 14를 보존한다. 누적 합 5·12·14를 모두 더한 31은 사건 값의 합이 아니다. 별도 증분 계약에서는 값 5·7·2를 각각 고유 ID로 한 번만 적용하여 14를 만들 수 있다. 누적 pane과 증분 pane의 수신 연산은 서로 바꿔 쓰지 않는다.

크기와 끝이 있는지는 다른 질문이다

큰 파일도 특정 버전을 고정하면 끝이 있는 입력이다. 반대로 초당 몇 개 안 되는 센서 기록이라도 끝없이 들어오면 전체 자료가 모두 도착할 때까지 기다릴 수 없다. 처리량과 입력의 유한성은 별도 축이다.

메모리에 전부 올리지 않아도 조각을 읽고 중간 결과를 저장하며 처리할 수 있다. 하지만 작은 조각을 쓴다는 사실만으로 상태·정렬·네트워크 비용이 없어지지는 않는다. 정답을 계산하는 방식과 필요한 자원을 구분해 본다.

기록이 일어난 시각과 처리한 시각

event time은 기록에 붙인 사건 시각, processing time은 시스템에서 처리하는 시각이다. 전송 지연 때문에 두 순서가 달라질 수 있다. 자체 표는 사건 시각이 초 단위이며 창 [0,10),[10,20)을 쓴다. 정확히10인 사건은 둘째 창에 속한다.

동일 자료를 사건 시각으로 묶으면 발생 당시의 집계, 도착 시각으로 묶으면 처리 당시의 집계가 된다. 어떤 질문인지 먼저 정해야 한다. 시간대·시계 동기·잘못된 타임스탬프는 실제 시스템에서 별도 확인할 조건이다.

현재 결과와 최종 정책을 나눈다

watermark는 사건 시각 기준 진행 상태를 추정하는 장치이지 모든 지연 기록이 물리적으로 불가능하다는 증명이 아니다. 창을 언제 출력하고 늦게 온 기록을 버릴지, 수정할지를 정해야 한다. 빠른 답과 더 완전한 답 사이의 선택을 표시한다.

아래는 제품 기본 설정을 흉내 내는 것이 아니라 두 정책을 명시한 자체 모형이다. 초기 합계를 발표한 뒤 늦은 값을 누적해 수정하면, 후속 소비자도 수정값인지 추가분인지 알아야 한다. 누적 결과5와 수정 결과12를 둘 다 새 증가분으로 더하면17이라는 중복 집계가 생긴다.

다른 문제에 적용하기

분할 통계·뜨거운 키·늦은 판본의 공동 감사

통계 자료 A=[0,2,4], B=[10]의 상태를 (원소 수,합,제곱합)으로 병합하고 전체 평균·모집단 분산을 구하라. 별도 비용 모형의 원래 reducer 부하는 [12,1,1,2]다. salt 첫 단계는 [3,4,4,5], 둘째 단계는 [4,1,1,2]이고 추가 고정 비용 H=2다. 두 방식 비용과 유리한 조건을 비교하라. 별도 창 [0,10)은 W≥15에서 닫힌다. A의 값 5는 첫 출력 전, 사건 시각 8의 B=7은 W=12, 사건 시각 9의 C=2는 W=14, 사건 시각 9의 D=3은 W=16에 온다. 누적 판본 v1=5, v2=12, v3=14를 v1,v3,v2 순서로 받았을 때 최대 판본 정책의 값과 무조건 교체 값, 버린 사건을 구하라.

힌트 1

부분 평균 대신 세 좌표를 더하고 모집단 분산을 최종화한다. 비용은 단계 안의 최대 부하와 단계 사이 합을 구별한다.

힌트 2

사건 창 귀속과 W 기준 수용 종료를 나눈다. 누적 결과는 합산하지 않고 창별 판본을 확인한다.

풀이와 답 확인

  1. 상태 A는 (3,6,20), B는 (1,10,100)이다. 병합은 (4,16,120)이므로 평균은 4, 모집단 분산은 14다.

  2. 원래 비용은 12다. salt 비용은 5+4+2=11이다. 일반 조건은 9+H<12, 즉 H<3이다.

  3. B와 C는 열린 기간에 도착하여 누적 합을 12와 14로 갱신한다. D는 W=16이라 버린다.

  4. v1,v3,v2 전달에서 최대 판본 정책은 값 14를 유지한다. 무조건 교체는 마지막 옛 판본 v2의 값 12로 퇴행한다.

전체 평균은 4이고 모집단 분산은 14다. 원래 비용은 12, H=2의 salt 비용은 11이며 H<3에서 유리하다. D를 버리고 채택 사건 합은 14다. v1,v3,v2 수신 뒤 최대 판본 정책은 14, 무조건 교체는 12다.

해결한 뒤 점검할 것

  • 원소 수·합·제곱합을 보존한 뒤 모집단 분산을 최종화한다.

  • 두 단계와 추가 비용을 포함하고 키 h의 결과 계약을 유지한다.

  • 늦은 사건 종료와 누적 결과 판본의 두 조건을 따로 검사한다.

  • 정한 정확 산술·비용·watermark 모형을 실제 엔진 성능이나 학생 실행으로 주장하지 않는다.
