소단원 5.1

하트비트·의심·분할

친구의 답장이 늦는다는 사실로 친구가 반드시 자리를 떠났다고 알 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 하트비트는 살아 있는 구성원이 주기적으로 보내는 확인 메시지다.

  • 네트워크 분할은 노드가 실행 중이어도 일부 노드끼리 메시지를 전달하지 못하는 상황이다.

학습 목표

  • 타임아웃과 실제 장애를 구별한다.

  • 고정 구성의 과반수 조건에서 분할의 진전을 판단한다.

늦게 처리한 오래된 하트비트도 타이머를 다시 시작해야 할까?

한 감시자의 단조 증가 시계에서 타임아웃 T=90 ms를 정한다. 감시자는 마지막으로 인정한 하트비트의 도착 시각을 저장하며 현재 시각과의 차이가 90 ms 이상이면 의심한다. 도착 시각은 같은 로컬 시계로 기록되고 처리 순서와 다를 수 있다. 이는 자체 탐지 정책의 종이 모형이며 실제 Raft 구현의 타이머 코드라고 주장하지 않는다.

현재 인정된 sequence 번호가 12이고 그 하트비트의 도착 시각은 40 ms다. 도착 시각 20 ms인 sequence 11의 메시지가 큐에서 늦게 처리되어 100 ms에 검사된다. 이 정책은 번호가 현재보다 큰 하트비트만 인정하므로 sequence 11은 인정하지 않는다. 마지막 인정 시각은 40 ms로 유지하고 130 ms부터 의심한다. 오래된 메시지의 처리 시각 100 ms로 바꾸면 의심을 190 ms까지 미루는 다른 정책이 된다.

이 sequence 번호는 같은 발신자 세대 안에서 증가한다고 가정한다. 발신자가 재시작하여 번호를 다시 0으로 만들면 같은 번호 공간의 비교만으로 새 메시지를 판정할 수 없다. 발신자 세대 식별이나 번호 지속성 같은 추가 계약이 필요하다. 지연 메시지를 인정할지와 노드가 실제 중단했는지를 구별하고, 서로 다른 노드의 벽시계 시각을 직접 빼지 않는다.

먼저 확인할 개념
  • 단조 시계와 미수신 경계

    도착 시각·처리 시각·실제 장애를 구별한다.

  • 고정 구성의 다수 조건

    타이머와 통신 경로 및 선출 가능성을 별도로 검사한다.

보이지 않는 원인은 여러 가지다

노드A가 B의 마지막 하트비트를 받은 뒤 한동안 아무것도 받지 못했다고 하자. B가 중단됐을 수도 있지만 메시지가 지연되거나 네트워크가 끊겼을 수도 있다. 관찰한 것은 미수신 시간이며 B의 실제 상태를 직접 본 것이 아니다. 타임아웃은 복구 행동을 시작하는 의심 기준으로 쓸 수 있다.

이 단원은 정직하게 프로토콜을 따르지만 중단·재시작할 수 있는 노드 모형이다. 거짓 메시지·악의적 투표를 하는 Byzantine 장애는 다루지 않는다. 무한히 긴 지연을 허용하면 짧은 유한 관찰만으로 중단과 느린 응답을 완벽히 구별하기 어렵다는 한계를 유지한다.

측정 기준과 경계 시각을 적는다

마지막 수신 시각을 t_last, 현재 관찰 시각을 t라 하고 t−t_last≥T이면 의심한다고 정하자. 등호를 포함하는지는 이 모형의 명시적 선택이다. 보내는 주기가50ms여도 네트워크·일시 정지·저장 지연이 있으므로50ms 미수신이 바로 중단 증거가 되지는 않는다.

시각은 감시자 자신의 단조 증가 시계를 사용한다고 가정한다. 다른 노드의 벽시계 숫자를 빼려면 시계 차이에 대한 별도 가정이 필요하다. T를 작게 하면 빠르게 반응할 수 있지만 오의심이 늘 수 있고 크게 하면 장애 반응이 늦어진다. 특정 수치를 모든 환경의 적정 설정으로 제안하지 않는다.

분할에서 양쪽이 모두 진행하도록 두지 않는다

고정5노드의 과반수는⌊5/2⌋+1=3이다. 3대와2대로 나뉘면3대 쪽만 새 과반수를 모을 수 있다. 2대 쪽 노드가 자신이 리더라고 계속 믿는 것과 과반수 프로토콜에 따라 새 결정을 확정할 수 있는 것은 다르다.

타임아웃을 짧게 해도 없는 메시지 경로를 만들지 못한다. Raft의 안정적 진전은 선거 시간보다 메시지 왕복이 충분히 빨라지는 환경에 의존한다. 안전한 투표 규칙은 지연 중에도 잘못된 같은 임기 복수 선출을 막는 목표이고, 진전 보장은 별도 통신 조건이 필요하다.

의심 시작

메시지 안의 다른 기계 시계와 감시자의 시계를 섞지 않는다. 인정 규칙을 먼저 적용한 뒤 그 규칙이 선택한 로컬 도착 시각으로 미수신 시간을 계산한다.

중간 과정을 따라가는 예제

T=150ms, 마지막 하트비트 수신0ms, 이후 미수신이다. 120ms/150ms/180ms의 의심 여부를 계산하라. B는 실제로 실행 중이며 지연 메시지가190ms에 도착한다고 추가 가정한다.

  1. 120−0=120<150이므로 아직 의심하지 않는다.

  2. 150−0=150≥150이므로 의심을 시작한다.

  3. 180−0=180≥150으로 계속 의심 상태다.

  4. B실행중과150ms의심은 동시에 가능하다. 190ms 메시지 도착은 지연 가정과 모순되지 않는다. 어떤 메시지를 인정해 의심을 해제할지는 프로토콜·임기 조건도 따로 봐야 한다.

의심X/O/O다. 150ms 의심은 B중단의 증명이 아니다.

조건을 바꾸어 비교하기

큐 처리 순서와 최신성

앞 모형에서 늦게 처리한 sequence 11 뒤 129 ms와 130 ms의 판정을 구하라.

  1. sequence 11은 현재 번호 12보다 작아 마지막 시각 40 ms를 바꾸지 않는다.

  2. 129 ms에서는 미수신 89 ms, 130 ms에서는 90 ms다.

판정은 의심하지 않음/의심이다. 실제 중단 여부는 이 계산으로 결정하지 못한다.

비교할 점

처리 시각이 더 늦다는 이유로 오래된 메시지를 새 증거로 취급하는 정책과 비교한다.

인정 가능한 새 메시지도 실제 도착 시각으로 계산한다

별도 기록에서 초기 인정 상태는 sequence 12와 도착 시각 40 ms다. sequence 13이 125 ms에 도착해 140 ms에 처리된다. 처리 후 214 ms와 215 ms의 판정을 계산하라.

  1. 13>12이므로 인정 시각을 도착 시각 125 ms로 바꾼다.

  2. 214−125=89 ms, 215−125=90 ms다.

처리 후 판정은 의심하지 않음/의심이다. 140 ms를 마지막 도착으로 기록하는 것은 명시 정책과 다르다.

비교할 점

처리 지연을 숨기지 않고 관찰한 시계와 시점을 구별한다.

오해와 반례

실행중 B의 메시지가190ms에 늦게 도착하는 반례가 있다. 과반수가 통신하지 못하는 분할에서는 선거를 반복해도 성공하지 않을 수 있다. 의심·실제상태·진전을 분리한다.

힌트 1

마지막 인정 시각은 40 ms로 그대로다.

소단원 5.2

임기·리더·fencing

오래 멈췄던 옛 리더가 돌아와 이미 준비한 쓰기를 보내면 어떻게 막을까?

준비 개념과 학습 목표

준비 개념

  • 임기는 선거 라운드를 구분하는 증가하는 정수이며 실제 시간 길이가 아니다.

  • fencing token은 권한 세대의 순서를 자원 서버가 검사하도록 요청에 붙이는 값이다.

학습 목표

  • 더 높은 임기 메시지의 의미를 설명한다.

  • 자원 서버에서 오래된 요청을 거부하는 조건을 추적한다.

fencing 검사와 재시도 장부를 어느 순서로 확인할까?

외부 자원 서버의 값을 v=0, 최고 관측 token을 H=20으로 둔다. 모든 변경 경로는 이 서버를 거치며 token 발급은 단조 증가한다. 하나의 원자적 처리에서 먼저 t<H를 거절하고, 그 다음 request_id 장부를 확인한다고 명시한다. ID가 없으면 양의 delta를 적용하고 H=max(H,t) 및 (ID,token,delta,원래 응답값)을 함께 지속 저장한다.

이미 있는 ID는 token과 delta가 모두 일치할 때만 원래 응답값을 반환하고 추가 적용하지 않는다. 다르면 충돌로 거절한다. 이러한 검사 순서는 자체 명시 정책이며 fencing 일반 정의만으로 정해지는 순서는 아니다. 낮은 token의 재시도는 장부가 있어도 첫 fencing 검사에서 거절된다. 이때 원래 요청이 적용되지 않았다는 결론을 내리지 않는다. 두 거절 경로에서는 값·H·기존 장부를 모두 보존한다.

token 21의 p가 +4를 적용하면 값 4와 원래 응답 4를 기록한다. token 22의 q가 +3을 적용하면 현재 값은 7이다. p를 token 21로 재전송하면 낮은 token 때문에 거절하지만 p의 과거 적용 4는 유지된다. token 22의 q를 같은 내용으로 재전송하면 현재 값 7을 그대로 두고 저장 응답 7을 반환한다. 현재 자원값, 처리 장부, 새 권한 세대를 분리한다.

    이미 본 높은 세대 이후의 낮은 요청을 차단한다.

  • fencing과 중복 제거의 차이

    세대 검사와 request_id 장부의 역할을 따로 적용한다.

논리 번호와 역할을 구분한다

Raft 노드는 현재 임기와 투표 대상을 지속 저장하며 높은 임기를 보았을 때 자신의 임기를 갱신하고 follower로 돌아간다. 같은 임기에서 한 노드가 두 후보에게 투표하지 않는 규칙이 중요하다. 임기8이 임기7보다 새롭다는 뜻이지8초가 지났다는 뜻은 아니다.

서로 다른 임기의 두 노드가 잠시 자신이 리더라고 믿을 수 있다. 옛 리더가 분할되어 새 임기를 못 들었기 때문이다. 같은 임기에 과반수로 선출된 리더가 둘 없다는 성질을 “모든 순간 모든 노드의 믿음이 같다”로 확대하면 잘못이다. 역할 믿음과 인정된 결정 권한을 구분한다.

리더의 검사 뒤에도 요청이 늦을 수 있다

외부 파일 서버에 쓰는 리더가 권한 유효성을 확인한 직후 오래 정지했다고 하자. 새 리더가 일을 시작한 뒤 옛 리더가 재개하여 예전 쓰기를 보내면 로컬 사전 확인만으로 막지 못한다. 확인과 실제 자원 사용 사이에 정지·통신 지연이 생길 수 있다.

fencing은 자원을 실제 바꾸는 서버가 요청의 세대 번호를 확인하도록 하는 방식이다. 새 권한마다 단조 증가하는 token을 발급한다는 신뢰 가정이 필요하다. 임기 번호를 token으로 쓸 수 있는지는 발급·권한·자원 경로가 어떻게 결합됐는지 따로 검증해야 하며 아무 리더 변수나 붙인다고 충분하지 않다.

최고 관측 token을 저장한다

자원 서버가 H를 지속 저장하고 요청 token t가 t<H면 거부, t≥H면 원자적으로 검사·쓰기와 H=max(H,t)를 수행한다고 명시하자. 같은 세대의 여러 쓰기를 허용하므로 등호는 허용한다. token12의 쓰기를 처리해 H12가 된 뒤 token11은 거부된다.

새 token13이 발급되었다는 사실을 서버가 아직 모르면 H12인 서버는12를 계속 허용할 수 있다. 이 모형은 이미 더 높은 세대를 관측한 뒤의 오래된 요청을 차단한다. 또한 같은 token의 재시도는 별도 요청ID 검사가 없으면 중복 적용될 수 있다. fencing과 중복 제거는 다른 장치다.

소단원 5.3

선출의 안전 조건

과반수라는 숫자가 두 리더의 동시 선출을 어떻게 막을까?

준비 개념과 학습 목표

준비 개념

  • 고정 구성N의 과반수 q=⌊N/2⌋+1이다.

  • 지속 저장은 프로세스가 중단 후 재시작해도 값을 다시 읽을 수 있도록 기록하는 일이다.

학습 목표

  • 과반수 교집합과1임기1투표로 선출 안전성을 증명한다.

  • 로그 최신성과 구성 변경의 추가 조건을 구별한다.

전체 합집합의 과반수이면 두 구성의 과반수도 만족할까?

구성 전환을 검토하는 자체 집합 모형에서 옛 구성 O={A,B,C,D,E}, 새 구성 N={C,D,E,F,G}를 둔다. 각 구성의 과반수는 3대이며 전환 승인 집합 V는 |V∩O|≥3과 |V∩N|≥3을 모두 만족해야 한다. 같은 노드는 각 소속 구성에서 한 번씩 셀 수 있지만 메시지 재전송은 새 노드가 아니다.

V={A,B,C,F}는 합집합 7대 중 4대지만 옛 구성에서는 A,B,C의 3대, 새 구성에서는 C,F의 2대다. 따라서 두 구성 승인 조건을 만족하지 못한다. V={A,B,C,F,G}는 옛 3대와 새 C,F,G의 3대로 두 조건을 만족한다. 이는 집합 조건만의 성공이며 실제 Raft 구성 로그가 어떤 단계에서 확정됐는지는 별도 프로토콜을 확인해야 한다.

안전한 같은 임기 선출에는 구성 조건뿐 아니라 노드별 지속 투표 기록과 요청 임기 대응이 필요하다. 현재 선거 임기 14에서 수신한 D의 임기 13 찬성과 C의 임기 14 재전송 두 개를 서로 다른 세 표로 세면 안 된다. 후보의 로그 최신성도 마지막 로그 임기부터 비교한다. 최신 로그라는 검사 하나가 투표 가능성·구성 전환·복제 확정 전체를 증명하지 않는다.

먼저 확인할 개념
  • 고정 다수의 교집합과 투표 지속성

    노드 ID·같은 임기·재전송을 구별한다.

  • 로그 최신성과 구성 전환 조건

    마지막 로그 임기와 인덱스 및 두 구성 다수를 따로 확인한다.

두 과반수는 적어도 한 노드를 공유한다

고정5대에서 각3표를 얻은 두 집합은 겹친다. 겹치지 않으면 합집합이6대여야 해서 전체5대보다 크다. 같은 임기에 각 노드가 서로 다른 후보에게 두 번 투표하지 않으면 공통 노드가 두 리더 모두에게 투표했다는 모순이 생긴다. 이것이 같은임기 복수 선출을 막는 핵심이다.

투표는 노드ID별로 세어야 한다. 한 노드의 재전송 응답을 두 표로 세면 과반수 증명이 적용되지 않는다. currentTerm/votedFor를 응답 전에 안정 저장해야 재시작으로 투표를 잊어 같은임기에 다른 후보에게 투표하는 문제를 막을 수 있다. 중단이 있다는 가정과 지속성이 함께 필요하다.

새 리더의 로그도 검사한다

선출 리더의 유일성만으로 이전에 확정한 상태가 보존된다고 증명할 수는 없다. Raft 투표자는 후보 로그가 자신의 로그보다 오래되지 않았는지도 검사한다. 마지막 항목 임기를 먼저 비교하고 같으면 마지막 인덱스를 비교한다. 길이가 길다는 정보 하나로 항상 최신이라고 할 수 없다.

투표자의 끝이(임기4,인덱스8)일 때 후보(5,3)는 더 최신이고(4,7)는 오래됐으며(4,8)는 동등하다. 이는 로그 최신성 검사만의 결과다. 후보의 선거 임기가 적정한지, 이미 다른 후보에게 투표했는지 등 나머지 조건도 만족해야 실제 표를 준다. 로그 합의 전체는 후속 단원의 복제·확정 규칙까지 필요하다.

안전과 진전의 조건을 분리한다

고정구성·정직한노드·1임기1투표를 지키면 통신이 느려도 위 유일성 논증은 유지된다. 하지만 계속 동률이면 선출이 늦어질 수 있다. 무작위 선거 타임아웃은 동시에 출마하는 빈도를 줄이는 진전 전략이며 모든 실행의 즉시 종료를 증명하는 규칙은 아니다.

구성을 바꿀 때는 옛 과반수와 새 과반수가 반드시 겹친다는 단순 고정구성 논증을 그대로 쓰면 안 된다. Raft의 joint consensus는 전환 중 양 구성의 과반수를 각각 요구하는 방식이다. 여기서는 정수N을 임의로 갱신해 새과반수를 세는 것으로 안전한 변경이 완료됐다고 주장하지 않는다.

중간 과정을 따라가는 예제

노드{A,B,C,D,E}에서 X가{A,B,C}, Y가{C,D,E}표를 같은임기9에 받았다고 가정하라. 어떤 규칙이 깨졌는지 증명하라.

  1. 각집합 크기3은 고정5대 과반수다.

  2. 교집합은{C}다. 최소교집합 하한도3+3−5=1이다.

  3. C가 X와Y 양쪽에 임기9투표를 했어야 한다.

  4. 이는1임기1후보투표 규칙과 모순이다. 규칙이 지속적으로 지켜졌다면 두선출은 함께 성립할 수 없다.

공통노드C의 이중투표가 필요하므로 가정이 불가능하다. 재시작으로 투표를 잊으면 이 논증의 전제가 깨진다.

조건을 바꾸어 비교하기

합집합 다수의 실패

앞의 V={A,B,C,F}를 두 구성의 과반수와 비교하라.

  1. 합집합 O∪N은 7대이고 V는 4대다.

  2. V∩O={A,B,C}, V∩N={C,F}라 새 구성에 한 표 부족하다.

합집합 다수만으로 joint 조건을 대신할 수 없다.

비교할 점

단일 구성의 다수 식을 바꾸지 않고 각각의 구성에 적용한다.

로그 길이와 로그 임기를 구별한다

투표자 마지막 로그는 (임기 6,인덱스 10)이다. 후보 P의 끝은 (5,100), Q는 (7,2), R은 (6,10)이다. 선거 임기·미투표 조건은 모두 만족한다고 따로 가정한다.

  1. P는 마지막 로그 임기 5<6이라 길어도 최신성 실패다.

  2. Q는 7>6이라 통과하고 R은 같은 임기에서 10≥10이라 동등하게 통과한다.

최신성 판정은 P 실패, Q/R 통과다. 같은 투표자가 같은 선거 임기에 Q/R 양쪽에 표를 주어도 되는 것은 아니다.

비교할 점

선거 임기와 마지막 로그 항목 임기는 서로 다른 필드다.

종이와 본문으로 직접 해보기

투표자의 마지막로그(4,8)에 대해 후보P(4,9),Q(3,20),R(5,1)의 최신성 조건 통과 여부를 적어라. 모든 후보의 선거 임기·투표가능 조건은 별도로 만족한다고 가정한다.

힌트 보기

비교 순서는 마지막로그 임기, 그다음 인덱스다. 선거 임기와 로그 항목 임기를 혼동하지 않는다.

풀이 보기

P는 같은4에서9≥8로 통과, Q는3<4라 인덱스20이어도 탈락, R은5>4라 인덱스1이어도 통과다. P/R이 각각 조건을 통과한다는 사실은 같은임기에 양쪽에 투표해도 된다는 뜻이 아니다.

오해와 반례

투표 수만 과반수면 재시작 기록·로그 검사·구성 변경은 중요하지 않다.

재시작 후 같은임기 이중투표는 과반수 교집합 증명을 깨며, 오래된 로그의 후보는 유일하게 선출돼도 상태보존 목표와 충돌할 수 있다. 구성변경에도 과반수 교차를 유지하는 별도 절차가 필요하다.

세 독립 종이 모형을 감사하라. ① 마지막 인정 하트비트는 sequence 8, 로컬 도착 시각 50 ms다. T=100 ms이며 새 번호만 인정한다. sequence 7은 도착 30 ms, 처리 140 ms다. 149 ms와 150 ms의 의심 여부를 구하라. ② T2의 원자적 fencing-먼저 정책에서 초기 값 0, H=30이다. p:(31,+5), q:(32,+2), p:(31,+5) 재시도, r:(32,+1), q:(32,+2) 재시도 순서의 현재 값/H 및 마지막 응답을 구하라. ③ O={A,B,C,D,E}, N={C,D,E,F,G}에서 V={A,B,C,F}의 joint 집합 조건과 F 대신 D를 넣은 V′={A,B,C,D}의 조건을 비교하라. 두 승인 집합은 각각 4대이며 O∪N은 7대다.

힌트 1

① 인정 조건을 먼저 적용하고 감시자의 도착 시각을 빼라. ② 낮은 token 거절을 ID 장부보다 먼저 적용한다.

힌트 2

② 새 ID만 값을 갱신하고 재시도는 원래 응답을 찾는다. ③ 두 구성 교집합을 직접 나열한다.

풀이와 답 확인

  1. ① sequence 7은 8보다 작아 무시한다. 마지막 시각은 50 ms다. 149−50=99 ms에서는 의심하지 않고 150−50=100 ms부터 의심한다. 실제 중단 여부는 미결이다.

  2. ② p 적용 뒤 현재 값은 5이고 H는 31이다. q 적용 뒤 현재 값은 7이고 H는 32다. p의 낮은 token 재시도는 거절하며 과거 적용은 유지한다. r 적용 뒤 현재 값은 8이며 H는 32다. 마지막 q 재시도는 추가 적용 없이 저장된 원래 응답 7을 반환한다.

  3. ③ V의 옛 교집합은 {A,B,C} 3대, 새 교집합은 {C,F} 2대로 실패한다. V′의 옛 교집합은 {A,B,C,D} 4대, 새 교집합은 {C,D} 2대로 역시 실패한다. 같은 승인 집합 크기나 옛 표 수 증가는 부족한 새 구성 표를 채우지 못한다.

① 의심하지 않음/의심. ② 최종 값 8, H=32, 마지막 응답 7이다. p의 재시도 거절은 최초 미실행을 뜻하지 않는다. ③ 두 집합 모두 새 구성의 다수 3대에 미달한다. 집합 조건과 실제 선거 로그 단계는 별도로 검사한다.

해결한 뒤 점검할 것

  • 인정된 메시지와 로컬 도착 시각 및 등호 포함 경계를 구별한다.

  • 현재 값·최고 token·과거 ID 응답과 재시도 거절의 의미를 각각 설명한다.

  • 두 구성의 교집합을 나열하여 실패한 조건을 명시하고 새 Raft/저장소/학생 실행을 주장하지 않는다.
