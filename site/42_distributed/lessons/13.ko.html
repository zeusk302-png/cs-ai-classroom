장애·분할·지연 주입

서버가 응답하지 않을 때 전원이 꺼진 것인지 메시지가 늦은 것인지 어떻게 구별할까?

준비 개념과 학습 목표

준비 개념

  • 노드와 메시지

  • 응답 제한 시간

  • 복제와 정족수

학습 목표

  • 중단·지연·분할의 장애 범위를 명시한다.

  • 시험 일정과 요구 조건을 별도로 적는다.

  • 관찰된 실패와 원인 추정을 구별한다.

자료가 두 노드에 도착하면 요청자도 두 확인을 받았을까요?

자체 세 노드 A,B,C에서 요청자는 A다. 새 쓰기를 성공으로 응답하려면 A가 서로 다른 두 노드의 저장 확인을 직접 확보해야 한다. 자신의 저장은 즉시 확인 하나로 센다. 전달 경로는 A→B만 열려 있고 B→A는 차단되며 C는 양쪽 모두 고립되어 있다. 다른 중계 경로도 없다. A의 자료가 B까지 전달되어 두 곳에 저장되어도 B의 확인은 A로 돌아오지 않는다.

이 모형에서 A가 가진 확인은 한 개이므로 성공 응답 조건은 충족되지 않는다. 자료 배치와 응답 증명은 다른 상태다. 양방향 집단으로 그리는 기본 예와 달리 이번 시험 명세에는 화살표 방향을 적어야 한다. 네트워크를 실제 차단하지 않았고 이 표는 메시지 경로를 손으로 추적하는 자체 계약이다.

별도 요청의 관찰 시각은 한 신뢰하는 시계에서 호출 0 ms, 서버 적용 2 ms, 클라이언트 제한 4 ms, 응답 도착 7 ms다. 제한 사건에서 응답은 없지만 적용은 이미 일어났다. 클라이언트는 적용 기록을 추가로 받기 전에는 그 사실을 알지 못한다. 시험자가 적은 적용 사건과 클라이언트가 얻은 관찰을 나누어 기록한다.

  • 요청과 시도 및 관찰 기록

무응답에는 여러 원인이 있다

프로세스 종료는 특정 프로그램의 실행을 멈춘다. 일시 정지는 다시 실행될 수 있다는 점에서 종료와 다르다. 메시지 지연은 처리나 전달을 늦추고, 네트워크 분할은 정한 노드 집합 사이의 통신을 차단한다. 한 방향만 차단되는 경우도 있으므로 양방향 차단 여부를 적는다.

응답 제한 시간 안에 답을 못 받았다는 사실만으로 서버가 종료되었다고 증명할 수 없다. 요청이 적용되었지만 답이 지연되었을 수도 있다. 시험에서는 관찰 결과와 주입한 원인을 각각 기록한다.

어떤 조건을 요구하는가

안전성은 잘못된 상태가 생기지 않는 조건이다. 진행성은 요청이 계속 완료되는 조건이다. 분할 중 일부 노드가 안전성을 지키려고 응답을 거부할 수 있다. 거부 하나를 바로 데이터 손상으로 분류하지 않는다.

자체 모형은 세 노드 A, B, C 중 두 노드의 확인을 받아야 새 값을 성공으로 응답한다. 각 집단 내부는 통신 가능하고 집단 사이는 차단한다고 정한다. 이 조건은 실제 제품 설정을 대신하지 않는다.

다시 실행할 수 있는 시험 명세

초기 데이터·노드 수·버전·주입 대상·시작과 종료 사건·요청 식별자·판정 조건을 함께 남긴다. 랜덤 선택을 썼다면 seed도 기록하지만 seed 하나가 스레드와 네트워크 일정을 모두 재현해 주지는 않는다.

Jepsen의 공개 과거 분석은 분할과 프로세스 중단 등 여러 장애를 결합하여 이력을 검사했다. 우리는 그 시험 설계를 읽었으며 서버나 도구를 실행하지 않았다. 실습은 아래 표를 손으로 비교하는 이론 활동이다.

저장 노드 수와 A가 확보한 확인 수를 따로 센다. 자료 전달과 확인 전달은 서로 반대 화살표다. 별도 시간선의 적용 사건은 시험 명세가 제공한 추가 정보다.

중간 과정을 따라가는 예제

세 노드의 두 확인 모형에서 A | BC로 양방향 분할한다. 다른 경로는 없다. A 또는 B로 제출한 새 쓰기가 성공 확인을 받을 수 있는지 계산하라.

  1. A 쪽 집단에는 한 노드만 있어 필요한 두 확인보다 적다. 정한 계약을 지키면 새 성공을 응답하지 못한다.

  2. B 쪽은 B와 C 두 노드의 확인이 가능하다. 다른 오류가 없고 두 확인을 실제 받았다는 추가 조건에서 성공할 수 있다.

  3. 무응답 관찰은 적용 여부 미확정과 구별한다. A가 혼자 성공했다는 기록이 있다면 이 모형의 확인 계약부터 검사한다.

A 쪽 확인 수는 1, BC 쪽은 2다. 성공 가능성과 실제 성공 관찰은 다르며 분할 중 모든 노드의 성공을 요구하지 않는다.

조건을 바꾸어 비교하기

두 저장과 한 확인의 차이

A→B만 열린 모형에서 자료가 A와 B에 저장된 직후 A의 성공 응답을 판정하라.

  1. A는 자기 저장 확인 하나를 가진다. B에 자료가 있어도 B→A 확인은 전달되지 않는다.

  2. 필요한 두 확인에 한 개가 부족하므로 성공 응답을 하면 계약 위반이다.

자료는 두 곳에 있을 수 있지만 A는 성공을 응답하지 못한다.

비교할 점

최종 저장 수만으로 요청자의 확인 이력을 대신하지 않는다.

제한 사건 뒤 돌아온 응답

별도 시간선에서 호출은 0 ms, 적용은 2 ms, 클라이언트 제한은 4 ms, 응답 도착은 7 ms다. 제한 이후 응답 도착까지의 간격과 적용 상태를 구하라.

  1. 응답은 제한보다 7−4=3 ms 늦다.

  2. 시험 명세의 적용 사건은 2 ms다. 따라서 이번 실제 모형에서는 적용되었으나 제한 시점의 클라이언트 관찰만으로는 미확정이다.

주어진 적용 기록을 포함하면 적용됨, 제한 관찰만 있으면 미확정이다.

비교할 점

알려진 시험 사건과 관찰자가 가진 증거를 구별한다.

종이와 본문으로 직접 해보기

A | B | C로 바꾸면 각 집단의 확인 수는? 차단 대신 모든 왕복 시간이 12 ms이고 클라이언트 제한이 10 ms라면 제한 초과만으로 데이터 손실을 결론 내릴 수 있는가?

힌트 보기

집단 크기와 제한 시간의 비교를 따로 계산한다.

풀이 보기

각 집단은 1로 두 확인 조건을 충족하지 못한다. 12 > 10이므로 응답이 늦지만 요청 적용이나 데이터 손실은 그 부등식만으로 확정하지 못한다.

오해와 반례

시간 초과가 나면 서버 종료와 쓰기 실패가 모두 확정된다.

느린 통신·정지·응답 유실도 가능하다. 응답 실패와 실제 적용 결과를 별도로 확인해야 한다.

연습 1 · 값과 상태 예측

C는 계속 고립된 채 B→A만 복구하고 B의 저장 확인이 실제 도착했다. A의 확인 수는 얼마인가?

힌트 1

A의 자체 확인 하나를 유지한다.

힌트 2

B의 별도 확인 하나가 추가된다.

풀이와 답 확인

  1. A와 B라는 서로 다른 두 확인이 모인다.

  2. 정한 수 기준은 충족된다. 다른 실패가 없고 이 계약 외 조건도 만족하면 성공 응답할 수 있다.

확인 수는 두 개다.

흔한 오답에서 다시 생각하기

복구 노드가 한 개이므로 확인도 한 개다.

이미 확보한 A의 확인을 지우지 않는다.

연습 2 · 오류 찾아 고치기

A→B만 열린 시험을 A|BC라는 양방향 집단 분할로 기록했다. 명세에서 무엇을 고쳐야 하는가?

힌트 1

집단 내부 통신을 가정하면 B와 C도 연결된다.

힌트 2

A에서 B로 가는 실제 경로를 지우면 다른 시험이 된다.

풀이와 답 확인

  1. 허용 간선 A→B와 차단 간선 B→A 및 C의 고립을 각각 기록한다.

  2. 집단 크기만으로 실제 자료·확인 경로를 계산하지 않는다.

방향을 가진 메시지 경로 명세로 고친다.

흔한 오답에서 다시 생각하기

차단된 간선 수만 같으면 두 시험은 같다.

위치와 방향이 달라지면 전달 가능한 사건이 달라진다.

연습 3 · 직접 만들어 보기

별도 시간선의 호출 0 ms와 제한 4 ms를 보존하면서 미적용 설명과 이미 적용 설명을 각각 하나 만들라. 제한 전에는 응답이 없다.

힌트 1

주어진 첫 예제와 달리 적용 시각은 새로 설계한다.

힌트 2

관찰이 같아도 내부 사건은 다를 수 있다.

풀이와 답 확인

  1. 이미 적용 설명은 적용 2 ms, 응답 7 ms다.

  2. 미적용 설명은 요청이 적용 전에 유실되어 응답도 없는 경우다. 둘 다 4 ms까지 클라이언트 응답이 없다.

같은 제한 관찰은 두 내부 설명을 허용한다.

흔한 오답에서 다시 생각하기

첫 예제의 적용 2 ms를 새 미적용 모형에도 반드시 유지한다.

여기서는 적용 사건을 바꾸는 별도 설명을 요청했다. 보존한 것은 호출과 제한의 관찰이다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

종료하지 않고 1 ms부터 8 ms까지 정지한 서버가 0 ms의 요청을 9 ms에 적용하고 11 ms에 응답했다. 클라이언트 제한은 4 ms다. 제한 시점의 서버 종료를 증명할 수 있는가?

힌트 1

프로세스 정지와 종료는 다르다.

힌트 2

나중 사건도 시험 명세에 포함되어 있다.

풀이와 답 확인

  1. 4 ms의 무응답만으로 종료를 증명하지 못한다.

  2. 전체 명세에서는 서버가 다시 실행되어 9 ms 적용과 11 ms 응답을 수행했다.

일시 정지와 늦은 완료이며 종료 증거가 아니다.

최종 값이 맞아도 중간에 완료된 읽기가 틀렸을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 읽기와 쓰기

  • 호출과 응답

  • 사건의 앞뒤

학습 목표

  • 단일 레지스터의 순차 규약을 적는다.

  • 겹침과 실시간 앞뒤를 구별하여 이력을 검사한다.

  • 유한 이력 통과의 한계를 설명한다.

각 읽기가 쓰기와 겹치면 전체 이력도 통과할까요?

초기 값 0인 한 레지스터를 사용한다. 신뢰하는 관찰 시계에서 W=write(1)의 호출과 성공 응답은 0 s와 4 s다. R1=read→1은 1 s에 호출하여 2 s에 완료하고, R0=read→0은 3 s에 호출하여 5 s에 완료한다. 다른 쓰기는 없다. 두 읽기는 각각 W와 겹친다.

R1이 1을 읽으려면 순차 규약에서 W가 R1보다 앞이어야 한다. R1의 완료 2 s가 R0의 호출 3 s보다 앞이므로 R1도 R0보다 앞이어야 한다. R0이 0을 읽으려면 W보다 앞이어야 한다. 그러면 W→R1→R0→W가 되어 하나의 순서가 불가능하다. 쌍별 겹침을 따로 확인하는 것만으로 전체 일관성을 인증할 수 없다.

별도 이력에서 R0의 구간만 [1.5,3] s로 바꾸면 두 읽기도 겹친다. R0의 순차 시점을 1.6 s, W의 순차 시점을 1.7 s, R1의 순차 시점을 1.8 s에 놓으면 각각의 호출·응답 구간을 만족시킬 수 있다. 마지막 값만 고치는 대신 전체 순서를 다시 구성한다.

먼저 확인할 개념
  • 레지스터 규약과 연산 구간

    실시간 앞뒤와 반환 값에 필요한 순서를 함께 검사한다.

  • 미확정 적용과 시험 범위

    미완료 연산을 임의로 삭제하지 않고 가능한 설명을 확인한다.

먼저 허용되는 순차 동작을 정한다

초기 값이 0인 레지스터 하나를 정한다. write(1)은 값을 1로 바꾸고, read는 그 순차 시점의 값을 반환한다. 선형화 가능성은 각 완료 연산을 호출과 응답 사이의 한 시점에서 일어난 것처럼 순서화할 수 있는지를 검사한다.

한 연산의 응답이 다른 연산의 호출보다 먼저라면 그 앞뒤는 지켜야 한다. 서로 겹친 두 연산은 호출 시각만으로 순서를 고정하지 않는다. 여기서는 하나의 객체만 다루며 여러 객체 트랜잭션의 보장과 혼동하지 않는다.

최종 상태만 검사하면 놓치는 것

write(1)이 성공한 뒤 시작한 read가 0을 반환했다면 이후 읽기가 1이어도 앞선 잘못된 관찰은 남는다. 검사에는 요청 ID·호출 사건·응답 사건·반환 값이 필요하다.

비교하는 사건의 앞뒤를 신뢰할 수 있어야 한다. 서로 다른 장비의 동기화되지 않은 시계 숫자만 정렬하여 실시간 순서를 확정하지 않는다. 아래 시간은 하나의 신뢰하는 관찰 시계에서 적은 자체 값이다.

미확정 연산과 검사의 범위

시간 초과로 응답을 받지 못한 쓰기는 적용되지 않았다고 자동 삭제하지 않는다. 가능한 완료나 미적용 경우를 규약에 맞게 검토해야 한다. 이 절의 첫 계산은 모든 연산이 완료된 작은 이력만 다룬다.

한 유한 이력이 통과했다는 말은 지정한 입력과 장애 및 관찰에서 반례를 찾지 못했다는 뜻이다. 모든 미래 실행을 증명했다는 뜻은 아니다. 잘못된 규약이나 누락된 이력으로 검사하면 판정 자체가 부정확해진다.

중간 과정을 따라가는 예제

초기 값 0에서 W=write(1)의 호출/성공 응답이 0/4, R=read의 호출/응답이 5/6이다. R은 0을 반환했다. 순차 규약으로 설명할 수 있는가?

  1. W의 응답 4가 R의 호출 5보다 앞이므로 W를 R보다 먼저 두어야 한다.

  2. 순서 W→R에서 마지막 쓰기는 1이다. R의 반환 값은 1이어야 한다.

  3. 관찰된 0과 충돌한다. R을 W 앞으로 옮기면 실시간 조건을 위반하므로 다른 순서로도 해결되지 않는다.

이 완료 이력은 레지스터의 선형화 가능성 조건에 실패한다. 최종 저장 값만 다시 1로 맞춰도 이 읽기 반례는 사라지지 않는다.

조건을 바꾸어 비교하기

각각의 겹침은 맞지만 전체 순서는 없다

첫 이력의 순서 제약을 모두 적고 순차 설명 가능성을 판정하라.

  1. 반환 1은 W→R1, 반환 0은 R0→W를 요구한다.

  2. 실시간은 R1→R0를 요구한다. 세 간선의 순환 때문에 가능한 순차 설명이 없다.

전체 이력은 선형화 가능하지 않다.

  1. R0를 1.6 s, W를 1.7 s, R1을 1.8 s에 둔다. 각각 자기 구간 안이다.

시계 오차와 누락을 알면 추적 표에서 무엇까지 계산할까요?

자체 한 메시지의 송신 표시 시각은 A에서 106 ms, 수신 표시 시각은 B에서 103 ms다. 각 표시 시계의 실제 시각 대비 오차는 독립적으로 −2 ms부터 +2 ms까지라고 정한다. 그러면 실제 송신은 [104,108] ms, 수신은 [101,105] ms다. 송신이 수신보다 늦을 수 없다는 메시지 인과 조건까지 적용하면 전달 간격은 [0,1] ms다. 정확한 한 값을 계산하는 기본 예와 달리 여기서는 오차 구간만 제공했다.

별도 다섯 논리 요청의 지연 중 수집된 세 값은 2,4,8 ms이고 두 값은 누락되었다. 모든 다섯 요청의 실제 지연이 [0,10] ms 안이라는 추가 계약을 준다. 관측 평균은 14/3 ms지만 전체 평균의 범위는 [14/5,34/5] ms다. 누락을 0으로 확정하지 않고 허용된 범위로 계산한다. 이 경계 계약이 없다면 같은 유한 상계를 얻지 못한다.

요청 ID와 시도 번호도 분리한다. 별도 장부에서 O1 시도 1은 적용 후 응답 유실, O1 시도 2는 동일 내용의 중복으로 성공 응답만 반환한다. O2는 한 시도로 적용·성공, O3는 한 시도로 거절이다. ID별 내용 확인과 효과 반영을 원자적으로 처리한 계약이 있어 업무 효과는 두 번이다. 성공 응답 시도는 네 시도 중 두 개이며 승인된 논리 요청은 세 요청 중 두 개다. trace ID나 로그 번호만으로 이 계약을 만들지는 못한다.

같은 요청을 이어 주는 식별자

분산 추적의 trace는 요청이 여러 구성 요소를 지나는 작업을 연결한다. span은 개별 작업이며 자신의 span ID와 trace ID를 가진다. 자식 span에는 부모 span ID가 있고 root span에는 부모가 없다. 문맥 전달이 있어야 다른 프로세스에서 생성한 작업을 연결할 수 있다.

같은 trace ID라는 사실만으로 모든 작업의 실행 순서가 결정되지는 않는다. 부모·자식, 송신·수신, 작업 의존 관계를 함께 본다. 비동기 작업은 span link로 관련 작업을 연결할 수도 있다.

시계와 로그의 한계

기계마다 시계 오차가 있으면 실제 먼저 보낸 사건의 표시 시각이 나중에 받은 사건보다 클 수 있다. 메시지 송신이 그 메시지 수신보다 먼저라는 인과 관계와 숫자 시각 정렬을 구별한다.

누락·샘플링·수집 실패가 있으면 trace가 전체 이력을 담지 못할 수 있다. 기록이 없다는 사실만으로 작업이 실행되지 않았다고 결론 내리지 않는다. 일반 추적 화면과 일관성 검사에 필요한 완전한 연산 이력은 목적과 범위가 다르다.

다음 사람이 확인할 수 있는 기록

원 요청 식별자는 재시도에도 유지하고 각 시도의 번호는 따로 적는다. 서버의 적용 판정 및 응답 결과를 구별하면 한 요청의 두 시도를 서로 다른 업무로 잘못 세는 일을 줄일 수 있다. 식별자만 적었다고 자동으로 중복 적용이 막히는 것은 아니다.

재현 명세에는 입력·프로그램 버전·초기 상태·노드 구성·실패 일정·기대 조건·실제 관찰·누락 정보를 함께 둔다. 비밀 토큰이나 개인정보를 무작정 로그에 복제하지 않는다. 이 수업의 표는 가상이며 실제 서비스를 수집하지 않았다.

시계 오차의 부호는 표시=실제+오차다. 지연 음수 후보는 메시지 인과 조건으로 제외한다. 누락 지연은 수집 실패의 값이며 실제 지연 0의 증거가 아니다.

중간 과정을 따라가는 예제

같은 trace T의 부모 span P에서 서버 A가 메시지를 송신할 때 표시 시각은 105다. 자식 span Q에서 B가 그 메시지를 수신한 표시 시각은 101이다. 자체 시계 모형에서 A는 실제 시간보다 5만큼 빠르고 B는 2만큼 느리다. 실제 시간과 인과 순서를 계산하라.

  1. A 표시 = 실제 + 5이므로 송신 실제 시간은 105 − 5 = 100이다.

  2. B 표시 = 실제 − 2이므로 수신 실제 시간은 101 + 2 = 103이다. 실제 전달 간격은 3이다.

  3. 표시 숫자만 정렬하면 수신 101이 송신 105보다 먼저처럼 보인다. 보정 모형과 메시지 식별자의 인과 관계는 송신→수신을 지지한다.

  4. 실제 환경에서 오차 값을 모르면 이처럼 정확한 간격을 계산할 수 없다. 같은 trace와 부모 관계는 연결 근거이며 정확한 글로벌 시계의 보장이 아니다.

자체 오차 가정 아래 실제 송신/수신은 100/103이다. 인과 관계와 보정 없는 표시 시각 정렬을 분리해야 한다.

조건을 바꾸어 비교하기

시계 구간에 인과 조건을 더하기

송신 106 ms, 수신 103 ms, 두 오차의 크기 최대 2 ms에서 전달 간격의 범위를 구하라.

  1. 오차만 적용한 차이 범위는 [101−108,105−104]=[−7,1] ms다.

  2. 전달은 음수가 아니므로 가능한 범위는 [0,1] ms다. 끝점 0 ms는 실제 송신과 수신을 둘 다 104 ms로 정하면 달성한다. 끝점 1 ms는 실제 송신을 104 ms, 수신을 105 ms로 정하면 달성한다.

가능한 전달 범위는 [0,1] ms다.

비교할 점

시계 숫자의 차이 −3 ms를 물리 전달 지연으로 쓰지 않는다.

누락 두 값이 바꾸는 전체 평균

세 수집 값과 전체 다섯 지연의 범위 계약으로 전체 평균의 양끝을 구하라.

  1. 수집 값의 합은 14 ms다. 누락된 두 값을 각각 0 ms로 정하면 전체 평균은 14/5 ms다.

  2. 누락된 두 값을 각각 10 ms로 정하면 전체 평균은 34/5 ms다. 관측 평균 14/3 ms는 수집된 세 요청만 분모로 사용한 값이다.

전체 평균은 2.8 ms부터 6.8 ms까지 가능하다.

비교할 점

누락 값은 허용 범위를 갖지만 실제 값은 확정하지 않았다.

연습 1 · 값과 상태 예측

O1/O2/O3의 별도 원자 장부에서 성공 응답 시도 비율과 승인된 논리 요청 비율, 효과 수를 구하라.

힌트 2

풀이와 답 확인

  1. 성공 응답 시도는 O1의 둘째 시도와 O2의 시도로 두 개다. 전체 네 시도에 대한 비율은 2/4 = 50%다.

힌트 1

실제 송신 구간은 [105,107] ms다.

  2. 모든 후보가 인과 조건과 충돌하므로 오차 계약·메시지 연결·기록을 다시 검사해야 한다.

방향·이력·관측 분모의 공동 감사

독립 모형 세 개를 감사하라. 첫째 모형에서는 A→B만 열리고 C는 고립되어 A와 B에 자료가 저장되었다. A는 자신의 확인과 돌아온 별도 확인을 합쳐 두 개를 확보해야 성공한다. A의 확보 확인 수와 성공 조건을 판정하라. 둘째 모형은 초기 값이 0인 레지스터다. W=write(1)의 구간은 [0,4] s, R1의 구간은 [1,2] s이며 반환 값은 1, R0의 구간은 [3,5] s이며 반환 값은 0이다. 다른 쓰기는 없다. 전체 순서의 가능성을 판정하라. 셋째 모형의 송신 표시 시각은 106 ms, 수신 표시 시각은 103 ms다. 각 시계의 오차 크기는 최대 2 ms이며 메시지 인과 조건을 만족한다. 전달 간격의 범위를 구하라. 별도 다섯 지연 중 2 ms, 4 ms, 8 ms만 수집되었고 모든 실제 지연은 [0,10] ms 안이다. 전체 평균 범위도 구하라.

힌트 1

자료 전달과 확인 전달의 방향을 나눈다. 레지스터 반환과 읽기 사이의 실시간 간선을 함께 그린다.

힌트 2

표시=실제+오차를 사용하고 음의 전달 후보를 제외한다. 전체 평균은 다섯 요청의 분모를 유지한다.

풀이와 답 확인

  1. A는 자기 확인 하나만 확보했다. B에 저장되어도 B→A가 차단되어 두 확인 조건을 만족하지 못한다.

  2. 반환 규약은 W→R1과 R0→W를 요구하며 실시간은 R1→R0를 요구한다. 순환 때문에 전체 순차 설명이 없다.

  3. 실제 송신 구간은 [104,108] ms, 수신 구간은 [101,105] ms다. 수신과 송신의 차이 범위 [−7,1] ms에 인과 조건을 적용하면 전달 간격은 [0,1] ms다.

  4. 수집 값의 합 14 ms에 누락된 두 값의 합 범위 [0,20] ms를 더하고 전체 요청 수 5로 나누면 평균 범위는 [2.8,6.8] ms다. 관측 평균 14/3 ms를 전체 평균으로 확정하지 않는다.

A가 확보한 확인은 한 개이므로 성공 조건을 만족하지 못한다. 레지스터의 전체 이력은 순서 제약의 순환 때문에 선형화할 수 없다. 전달 간격은 0 ms부터 1 ms까지, 전체 지연 평균은 2.8 ms부터 6.8 ms까지 가능하다.

해결한 뒤 점검할 것

  • 자료와 확인 경로 및 시험 명세/관찰을 구별한다.

  • 모든 값·실시간 간선을 하나의 순서에 동시에 적용한다.

  • 시계 오차 구간에 인과 조건을 추가하고 불가능한 가정을 구별한다.

  • 누락과 분모를 보존하며 자체 손모형을 실제 장애 주입·검사기·학생 실행으로 주장하지 않는다.

보강 자료의 출처와 확인 범위
  • Jepsen etcd 3.4.3 analysis (2020)

    실제 본문 전체를 열어 특히 26–48행의 장애·register/set/append/lock/watch 시험과 91–103행의 유한 시험 및 제외 장애 범위를 읽었다. 이번 세 노드 방향 그래프·제한 시간·이력은 자체 손모형이며 과거 논문의 결과를 현재 etcd 결함이나 자체 실행으로 쓰지 않는다.

  • Jepsen Linearizability

    실제 전체 23행을 읽어 단일 객체의 SingleOrder/RealTime/RVal와 미완료 연산의 가능한 완료 조건을 대조했다. 자체 세 연산 순환 및 별도 허용 순서를 직접 구성했으며 검사기를 실행하지 않았다.

  • OpenTelemetry Traces

    실제 865–1077행 전체의 root/child/sibling span·문맥 전파·ID·이벤트·비동기 span link 본문을 읽었다. 시계 오차 구간과 누락 평균·요청 장부는 자체 별도 모형이며 실제 추적 수집이나 SDK 실행을 하지 않았다.

모든 새 계산은 손유도다. A→B의 자료 저장 가능성과 B→A의 확인 반환 불가를 구별하여 A가 확보한 확인은 하나임을 계산했다. 반환 경로를 복구하고 실제 확인이 도착하면 두 확인을 확보한다. 적용은 2 ms, 제한은 4 ms, 응답은 7 ms인 별도 시간선에서 제한 뒤 응답까지의 간격은 3 ms다. 전체 레지스터의 W→R1→R0→W 순환을 대조했다. 읽기 구간을 변경한 별도 이력에서는 R0, W, R1의 순차 시점을 각각 1.6 s, 1.7 s, 1.8 s로 구성했다. 반환 값을 변경한 이력에서는 W, R1, R0의 시점을 각각 0.5 s, 1.5 s, 3.5 s로 구성했다. 미완료 쓰기의 가능한 적용 설명도 대조했다. 각 시계의 오차 크기가 최대 2 ms이면 차이 후보는 [−7,1] ms이며 인과 조건을 더하면 [0,1] ms다. 오차 크기가 최대 1 ms라는 별도 가정은 모든 후보에서 인과 조건과 충돌한다. 누락된 두 지연의 허용 범위로 전체 평균은 14/5 ms부터 34/5 ms까지다. 누락 값을 5 ms와 6 ms로 정하면 전체 평균은 5 ms다. 원자 장부에서 전체 시도는 네 개, 성공 응답 시도는 두 개, 논리 요청은 세 개, 승인된 요청은 두 개이며 업무 효과는 두 번임을 구별했다.
