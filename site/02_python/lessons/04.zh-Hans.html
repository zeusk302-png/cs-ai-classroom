小节 4.1

if·elif·else

多个条件同时成立时，计算机会选择哪一种说明？

预备知识与学习目标

预备知识

  • 变量赋值 score=85 是保存值，而 score==85 是比较是否相等的表达式。本单元假定分数是内置 int，不包括 bool、字符串或用户定义对象。
  • 真与假表示条件的判定结果。< 和 <= 对边界的包含方式不同。0<=score<=100 包含两端的边界。
  • 缩进表示属于同一分支的语句块。要区分冒号后下一行开始的语句块与块外的 print。

学习目标

  • 追踪只选择第一个为真条件的 if·elif·else。
  • 说明分数范围、边界与分支顺序如何影响结果。
  • 把假值与短路求值联系到避免错误所需的条件。

按顺序选择的规则

if 检查条件，为真时执行缩进的语句块。elif 只在前面的条件都为假时检查。如果有 else，则在前面的条件都为假时执行。一条分支链最多执行一个语句块；如果没有 else 且所有条件都为假，就不执行任何语句块。

正文示例先把不在 0~100 范围内的分数分类为 invalid。有效分数中，90 及以上为 gold，小于 90 但至少为 80 的为 silver，其余为 practice。范围检查不等于类型转换。这里没有把字符串转换为数字或处理输入错误的代码，也不声称能够安全验证违反整数约定的值。

顺序会改变结果

95 同时满足 >=90 和 >=80。先检查较高边界的分支链会选择 gold，并不再检查 silver 条件。如果先写 >=80，95 也会得到 silver，后面的 >=90 分支就无法到达。必须同时检查区间重叠与首次选择规则。

两个独立的 if 与分支链不同。即使第一个 if 为 95 赋值 gold，后面独立的 if score>=80 仍可能再次赋值 silver。对于需要同时执行两种独立行为的问题，分开的 if 可能适合。应先确定问题要求选择一种类别，还是执行多种行为。

真值判定与安全的检查顺序

内置值 None、False、数值 0 以及空字符串、空列表，在条件中都是假。负数 -1 不为 0，因此为真。“没有值”与“数值为 0”的含义并不相同。and 与 or 不会总把结果转换成 bool，而是返回选中的操作数。例如，0 or 7 的值为 7。

and 的左侧为假时，不对右侧求值。对整数 n，n!=0 and 10//n>=2 在 n=0 时会跳过除法。反过来，先检查除法条件就没有同样的保护。这里仅说明能够避开该除法的零分母，并不保证解决任意对象或其他运算的错误。

逐步推导的例题

追踪把固定整数 score=85 分为四个区间的完整代码。 

score = 85
if not 0 <= score <= 100:
    label = "invalid"
elif score >= 90:
    label = "gold"
elif score >= 80:
    label = "silver"
else:
    label = "practice"
print(label)
  1. 85 满足 0<=85<=100，所以 not 条件为假，跳过 invalid 语句块。
  2. 85>=90 为假，因此跳过 gold 语句块。
  3. 85>=80 为真，把 silver 保存到 label。后面的 else 不执行。
  4. 分支链外的 print(label) 输出 silver 和换行。对这个固定输入，既有实际执行的输出也是 silver。

一行 silver。这是整数输入约定和上述分支顺序下的结果。

用纸笔和正文动手试一试

假定不改动代码，只把 score 分别换成 79、80、90、101，在纸上求 label。另外，如果把 >=80 分支放在 >=90 前面，95 会得到什么？

查看提示

从范围检查开始，按从左到右的顺序检查，在第一个为真的条件处停止选择。

查看解答

79 为 practice，80 为 silver，90 为 gold，101 为 invalid。改变顺序后的 95 为 silver。这五个活动输入都只在纸上追踪。

常见误解与反例

负数是不好的值，因此在条件中总是假。

Python 的内置整数 -1 会判定为真。要拒绝负数，必须明确写出 value<0 等问题条件。数据的允许范围与语言的真值判定是不同规则。

检查理解

在原来的分支中，score=95 的 label 是什么？

查看答案与理由

gold。

分数在范围内，>=90 先为真，所以不再检查 >=80。

没有 else 的分支链中，所有条件都为假时是否会出错？

查看答案与理由

仅凭这一点不会出错。

会跳过所有相关语句块。如果之后读取尚未初始化的名称，则可能出现另一种错误。

n=0 时，n!=0 and 10//n>=2 会执行除法吗？

查看答案与理由

不执行，并返回 False。

左侧比较为 False，所以 and 跳过右侧。

进一步探索

进阶：把全部整数分数分为范围外、[90,100]、[80,89]、[0,79] 四个集合。各集合互不重叠，每个整数恰好属于其中一个。可以逐种情况证明：检查范围外的情况后，首次为真选择会得到对应集合的 label。可是条件 score>=80 与 score>=90 本身有重叠。分支链实际选择的区域还必须包括“前面的条件都为假”这一限制。这是内置整数、正常比较和无异常执行前提下的分类证明；执行部分分数并没有证明所有数据类型的安全性。

小节 4.2

while·for·range

把 2、4、6、8 相加时，循环应该在哪里停止？

预备知识与学习目标

预备知识

  • 累加变量 total+=i 表示把当前 i 加到 total 并保存。必须先把初值设为 0，才有加法的起始状态。
  • 一次迭代是执行一次循环体。while 在循环体之前检查条件，因此起初就为假时，循环体执行 0 次。
  • 列表是按顺序排列的值的集合，for 依次从可迭代对象获取值。range 表示内置整数的规则序列。

学习目标

  • 追踪 while 的检查、循环体与更新顺序。
  • 区分 range 的起点、终点不包含、方向与零步长错误。
  • 在明确条件下说明有限循环的进展与终止。

反复询问条件的 while

while i<9 在当前 i 小于 9 时执行循环体，之后再次检查同一条件。从 i=2 开始，用 i+=2 更新，则检查值依次为 2、4、6、8、10，并在 10 处停止。终止后的 i 是 10，而不是 8。

必须确认某种进展会使条件最终变为假。如果删掉更新，i 会一直为 2，只有总和可能不断增长。while 本身不保证固定次数或终止。实际代码中的异常或外部变化也可能使循环结束，但这里仅讨论固定整数和正常运算。

for 与 range 的约定

for i in range(2,9,2) 从 2 开始，每次增加 2，依次提供小于 9 的 2、4、6、8。stop 不包含在序列中。range(3) 表示 0、1、2，而 range(4,4) 为空。调用 range 不会预先构造并返回包含全部值的列表；得到的是表示整数序列的 range 对象。

步长为负时，值递减，并且必须大于 stop。range(9,1,-2) 为 9、7、5、3。方向不合适的 range(2,9,-1) 为空，而 step=0 会引发 ValueError。本单元把参数限定为内置 int。实际的 range 也接收支持整数索引转换约定的对象，因此这里没有涵盖所有用户定义对象。

比较两种循环的标准

for 的循环变量会被重新赋为下一个提供的值。即使在循环体中设 i=100，也不会仅因这次赋值而改变 range 提供的下一个值。while 则会在下一次条件检查中使用改动后的 i。两种语法对更新的责任不同。

如果有限 range 正常耗尽，而且每次循环体也会结束，for 就会结束。并非所有 for 的对象都是有限的；如果循环体中存在不会结束的循环，有限输入也不足以保证结束。下面两个程序没有外部输入或列表修改，只把四个值相加，因此得到相同总和。但这并不是把所有 while 改成 for 都会保持语义的普遍规律。

逐步推导的例题

追踪分别用 for 和 while 累加同样四个数的完整代码。 

for_total = 0
for i in range(2, 9, 2):
    for_total += i
while_total = 0
i = 2
while i < 9:
    while_total += i
    i += 2
print(for_total, while_total)
  1. for_total=0 时，for 提供的 i 为 2、4、6、8。累加和依次为 2、6、12、20。
  2. 单独初始化 while_total=0、i=2。第一次条件为真，加上 2 后，i=4。
  3. 后续迭代加上 4、6、8，总和成为 6、12、20，i 分别更新为 6、8、10。
  4. i=10 时，10<9 为假。print 输出 20 20 和换行，与保留代码的既有实际输出一致。

两个总和都为 20。要区分 while 的最终 i=10 与 for 最后提供的值 8。

用纸笔和正文动手试一试

在纸上写出 range(9,1,-2) 的值与总和。另外，只把 while 示例的初始 i 改为 9，保留 while_total=0，总和与循环体执行次数是什么？

查看提示

负步长时检查值是否大于 stop。while 在第一次条件检查之前不进行任何加法。

查看解答

9、7、5、3 的和为 24。初始 i=9 时，9<9 为假，所以总和为 0，循环体执行 0 次。活动代码没有执行。

常见误解与反例

终点写了 9，所以 range(2,9,2) 最后会加上 9。

stop 被排除，而且每次增加 2 的序列也不会到达 9。值为 2、4、6、8。必须同时检查终点与步长。

检查理解

range(4,4) 的迭代次数是多少？

查看答案与理由

0 次。

默认步长为正，起点不小于 stop，因此从一开始就是空序列。

把 range 的 step 设为 0，会得到无限循环对象吗？

查看答案与理由

不会。会引发 ValueError。

零步长不允许，不会被当作空序列或自动更新处理。

在 for i in range(3) 的循环体中赋值 i=100，下一个提供的值是什么？

查看答案与理由

第一次迭代之后为 1。

for 把迭代器的下一个值重新赋给循环变量。

进一步探索

进阶：证明 while 示例在正常迭代 k 次之后，i=2+2k，累加和=k(k+1)。k=0 时，2 与 0 符合初始状态。k<4 时，下一个加数为 2+2k，因此 k(k+1)+2+2k=(k+1)(k+2)，i 也增加 2。k=4 时，i=10 使条件为假，所以恰好执行 4 次后，总和为 20。k 从 0 增至 4 的有限进展是终止的依据。如果改变循环体或跳过更新，必须重新证明。这是数学状态与正常内置整数运算的证明，并不保证应对实际资源耗尽，也不保证任意 iterable 的终止。

小节 4.3

break·continue 与循环设计

如何区分跳过负数与遇到 0 就停止这两种规则？

预备知识与学习目标

预备知识

  • continue 跳过当前循环体剩余的语句，进入下一次迭代。break 结束最近的一层循环。
  • 哨兵值 0 在这个问题中被约定为停止信号，并不表示所有问题都应该跳过 0 或在 0 处停止。
  • 循环的 else 与 if 的 else 作用不同。for 没有下一个值而正常耗尽时执行；通过 break 退出时不执行。

学习目标

  • 通过数据追踪区分跳过当前迭代与停止整个循环。
  • 说明循环 else 与空输入的结果。
  • 发现 continue 跳过 while 进展更新而导致的终止错误。

跳过这一轮与停止循环

对列表 [2,-1,4,0,8]，遇到负数不累加，而是看下一个值；0 是停止信号；正数则加入总和。-1 的 continue 跳过后面的 0 检查和累加，但仍有机会检查 4。0 的 break 则让 8 完全不会被访问。

break 与 continue 作用于包含该语句的最内层循环。循环有两层时，内层的 break 不会自动结束外层循环。若要结束多层循环，需要单独设计控制流程。这里仅使用一层循环和固定的有限列表。

用 else 标记耗尽

与 for 对齐的 else 在没有更多值、正常耗尽时执行。示例在此保存 outcome="exhausted"。在 0 分支中，先保存 outcome="stopped"，再通过 break 退出，因此跳过 else。空列表也会立即耗尽，执行 else 并保存 outcome。

仅仅使用 continue 并不会取消 else。即使最后一个值遇到 continue，只要没有下一个值，仍可能到达 else。在包含循环的函数中通过 return 退出，或因未处理的异常退出，都不等于正常耗尽，也不会执行 else。本例有意不加入函数 return 或异常。

每条路径都需要进展

在纸上设想：while i<3 从 i=0 开始，使用 if i==1: continue，而只在其后放 i+=1。i=0 时会更新为 1，但下一次 i=1 时，continue 跳过更新。此后 i 固定为 1，因此无法正常终止。这个无限循环反例不执行。

修正时，必须保证遇到 continue 的路径也有进展。例如，可以先单独保存当前项，再增加索引，然后检查该项是否应排除。移动更新位置也可能改变被检查的项，所以要分开追踪当前值与下一个位置。break 路径当场结束循环，因此不要求下一次更新。

逐步推导的例题

追踪跳过负数并在第一个 0 处停止的完整代码。 

total = 0
for value in [2, -1, 4, 0, 8]:
    if value < 0:
        continue
    if value == 0:
        outcome = "stopped"
        break
    total += value
else:
    outcome = "exhausted"
print(total, outcome)
  1. 从 total=0 开始。value=2 既不是负数也不是 0，所以 total=2。
  2. value=-1 在第一个条件处 continue，保持 total=2。value=4 正常累加，使 total=6。
  3. value=0 的负数条件为假，而零值条件为真。把 stopped 保存到 outcome，然后 break。
  4. 不访问 value=8，也不执行 else。输出 6 stopped 与换行，与保留代码的既有实际输出相同。

总和为 6，outcome 为 stopped。这与求整个列表中全部正数之和 14 的问题不同。

用纸笔和正文动手试一试

假定把列表分别改成 [2,-1,4]、[]、[0]，在纸上求 total 与 outcome。

查看提示

有第一个 0 就 break；没有 0 就正常耗尽，包括空列表。

查看解答

[2,-1,4] 得到 6 exhausted，[] 得到 0 exhausted，[0] 得到 0 stopped。这三项活动没有实际执行，而是按规则追踪。

常见误解与反例

只要用过一次 continue，循环 else 就不会执行。

continue 是继续请求下一个值的操作。如果最终正常耗尽，就会执行 else。要与跳过 else 的 break、return、异常区分。

检查理解

本例会把 0 后面的 8 加入总和吗？

查看答案与理由

不会。

在 0 处 break，因此不访问 8。

空列表会执行 else 吗？

查看答案与理由

在这里的正常执行中会。

迭代器从一开始就已耗尽，也没有发生 break。

内层循环的 break 会自动结束外层循环吗？

查看答案与理由

不会。

规则是仅结束最近的一层循环。

进一步探索

进阶：证明不含 0 的已访问前缀上，total 是其中正数之和这一不变式。空前缀之和为 0。如果下一个值为负，continue 保持总和；如果为正，加上它，仍保持不变式。如果为 0，不改变总和而停止，因此最终值是第一个 0 之前的正数之和。如果没有 0，就耗尽整个列表，得到全部正数之和。列表固定且有限，每次循环体都会结束，所以访问次数不超过列表长度，循环会终止。这个依据不能直接套用到前面跳过更新的错误 while。如果加入列表修改、异常或其他哨兵含义，需要重新确定前提。

小节 4.4

累加、查找与边界情况

如何区分在索引 0 处找到结果与尚未找到的状态？

预备知识与学习目标

预备知识

  • a[i] 读取列表 a 中索引 i 处的值。长度为 n 的正常非负索引从 0 到 n-1。本例在执行过程中不修改列表。
  • None 在这里是“尚未找到”的状态标记，用 first is None 检查。数值 0 是有效的第一个位置；值 0 与索引 0 含义不同。
  • 总和、访问次数与首次匹配位置是不同结果。若要完整计算总和与次数，首次匹配之后仍需访问剩余项。

学习目标

  • 同时追踪累加和、访问次数与首次匹配位置。
  • 说明空列表、重复匹配、无匹配与索引 0 等边界情况。
  • 通过不变式与终止条件区分对整个输入范围的论证与部分执行结果。

分别记录值与位置

对 a=[0,3,0]、target=0，匹配发生在索引 0 和 2，首次位置是 0。从 first=None 开始，仅当 first is None and value==target 时保存当前 i。如果已经保存首次匹配，就不再用后面相同的值覆盖它。

如果用 if not first，first=0 也会判定为假，可能被误认为尚未找到。is None 只检查这个状态标记。target=0 的值是假值，并不表示它不能作为查找目标。比较 value==target 决定是否匹配。

总和与次数承担不同于查找的责任

total 是已访问值之和，count 是访问次数。仅因找到首次匹配就 break，会使总和与总次数无法完成。本例只停止更新匹配位置，for 本身仍耗尽全部位置。对长度 n 的固定列表，range(len(a)) 提供从 0 到 n-1 的索引。

空列表中循环体执行 0 次，因此 total=0、count=0、first=None 保持不变。没有匹配的非空列表也得到 first=None。此时无条件读取 a[first] 并没有正确的索引，应在使用结果前检查是否为 None。即使使用 -1 作为未找到标记，Python 实际的 a[-1] 也表示最后一项，因此未经检查就读取是危险的。

边界情况与证明是不同的依据

分别检查空列表、首位置、末位置、重复与不存在等情况，更容易发现初始化与比较错误。但是，若干列表的输出正确，并没有证明所有列表都正确。必须说明每次迭代保持什么状态。

这里假定列表固定且有限，元素为内置 int，target 也是内置 int，运算正常且执行资源充足。循环体总会结束，索引由 range 限制。用户定义的比较方法、列表的并发修改、资源耗尽，都在约定之外。以后分析查找算法的成本时，也不能自动把访问次数 n 与依赖整数位数的运算成本视为相同。

逐步推导的例题

追踪同时计算总和、总个数与第一个 0 所在位置的完整代码。 

a = [0, 3, 0]
target = 0
total = 0
count = 0
first = None
for i in range(len(a)):
    value = a[i]
    total += value
    count += 1
    if first is None and value == target:
        first = i
print(total, count, first)
  1. 初始状态为 total=0、count=0、first=None。把 i=0 的 value=0 加入后，total=0、count=1；first 为 None 且值匹配，所以 first=0。
  2. i=1 的 value=3 使 total=3、count=2。first 不为 None，因此保存条件为假，保持 first=0。
  3. i=2 的 value=0 使 total=3、count=3。已经找到首次匹配，所以不把 first 改为 2。
  4. range 耗尽，print 输出 3 3 0 与换行。保留代码的既有实际执行也是这个输出。

总和为 3，项数为 3，首次匹配索引为 0。要与最后一个 0 的索引 2 区分。

用纸笔和正文动手试一试

在纸上求 a=[]、target=0，以及 a=[2,2]、target=2 的 total、count、first。在原来的 [0,3,0] 中，首次匹配后立即 break，会给完整结果带来什么问题？

查看提示

初始状态也可能成为结果。不要覆盖首次位置，但总和与次数必须更新到最后。

查看解答

空列表得到 0、0、None。[2,2] 得到 4、2、0。原列表首次匹配后立即 break，会停在 0、1、0，无法得到总和 3 和总个数 3。活动输入未执行。

常见误解与反例

查找结果 0 为假，所以表示没有找到。

0 是有效的第一个索引。这个设计用 None 表示未找到，并通过 first is None 判断。不能仅凭真值判定改变值的业务含义。

检查理解

a=[5,7]、target=2 时，first 是什么？

查看答案与理由

None。

所有比较都为假，因此保持初始的未找到标记。

first=0 时，找到的值一定也是 0 吗？

查看答案与理由

不是。

0 是位置。在 [2,2] 中，target=2 的首次位置也是 0。

需要总和与总个数时，首次匹配后可以 break 吗？

查看答案与理由

一般不可以。

没有访问剩余值和项数，会失去完整的累加结果。

进一步探索

进阶：设定如下不变式：处理 k 个位置之后，total 是 a[0]~a[k-1] 之和，count=k；first 是这个前缀中与 target 匹配的最小索引，没有匹配则为 None。k=0 时，空和 0、个数 0、None 符合初始状态。加上下一个 a[k] 并把个数增加 1，保持两个累加结果。如果已有匹配，保持 first；如果尚无匹配而新值匹配，k 就是首次位置；如果尚无匹配且新值也不匹配，保持 None。归纳可知 k=n 时全部结果正确。range(n) 提供有限的 n 个值，且循环体会结束，这是终止依据。这是在固定列表、正常整数比较前提下的条件性证明，并不是仅凭实际执行的一个列表完成的证明。
