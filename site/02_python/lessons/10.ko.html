소단원 10.1

pathlib와 상대·절대경로

프로그램 파일 옆의 data.txt가 왜 실행 위치에 따라 안 보일까?

준비 개념과 학습 목표

준비 개념

  • 폴더와 파일

  • 문자열과 객체

학습 목표

  • 경로와 파일 내용을 구별한다.

  • 작업 디렉터리를 기준으로 상대경로를 해석한다.

주소를 담는 객체

Path는 파일이나 폴더의 위치를 표현한다. Path("data.txt")를 만든다고 파일이 생성되거나 읽히는 것은 아니다. 실제 읽기·쓰기 메서드를 호출해야 저장장치 접근이 생긴다. PurePath 계열은 경로 표현 계산만 제공한다.

경로 결합은 문자열에 슬래시를 임의로 붙이는 대신 / 연산자를 쓸 수 있다. Path("data") / "scores.csv"는 하위 경로를 만든다. 같은 / 문자가 숫자 나눗셈과 다른 의미인 것은 피연산자 종류에 따른다.

from pathlib import Path
p = Path("data") / "scores.csv"
print(p.name)  # 예상 이름: scores.csv

상대경로의 출발점

상대경로는 현재 작업 디렉터리에서 출발한다. 작업 디렉터리는 스크립트가 있는 폴더와 다를 수 있으므로 실행한 위치를 확인해야 한다. Path.cwd()는 그 출발점을 확인하는 수단이다.

절대경로는 루트부터 위치를 지정한다. Windows에서는 드라이브와 루트를 함께 살핀다. C:notes.txt처럼 드라이브만 있는 표현은 C:/notes.txt와 같은 절대경로가 아니다. 한 컴퓨터의 절대경로를 다른 컴퓨터에서 그대로 쓸 수 있다고 보장하지 않는다.

경로 정리와 존재는 별개

parent는 상위 경로, name은 마지막 이름, suffix는 마지막 확장자를 나타낸다. 확장자는 이름의 일부이며 그 파일의 실제 형식이 맞다는 증거는 아니다. 이름이 .json이어도 내용 검증은 따로 한다.

resolve()는 실제 플랫폼의 경로를 해석하며 심볼릭 링크 등이 개입할 수 있다. ..를 문자 삭제만으로 처리한 결과가 실제 파일 접근과 항상 같지 않다. 여기서는 심볼릭 링크가 없는 단순 폴더 모형을 종이로 추적한다.

중간 과정을 따라가는 예제

  1. 작업 폴더 뒤 data를 붙인다.

  2. 그 아래 scores.csv를 붙여 /home/student/data/scores.csv를 얻는다.

  3. 마지막 이름은 scores.csv이고 확장자는 .csv이다.

/home/student/data/scores.csv, 이름 scores.csv이다. 파일 존재는 확인하지 않았다.

소단원 10.2

text·binary와 encoding

한 글자인 “가”가 파일에서 몇 바이트일까?

준비 개념과 학습 목표

준비 개념

  • 문자와 바이트

  • 파일 열기 모드

학습 목표

  • str와 bytes 반환을 구별한다.

  • 인코딩과 줄바꿈 처리를 명시한다.

파일의 바이트를 문자로 읽기

저장된 바이트를 문자로 해석하는 규칙을 인코딩이라고 한다. text 모드 읽기는 바이트를 해독해 str을 반환하고 binary 모드는 해독 없이 bytes를 반환한다. 사진을 문자 파일처럼 읽으면 잘못된 해독이 생길 수 있다.

UTF-8에서 ASCII 문자 A는1바이트, 한글 음절 가는3바이트로 표현된다. Python len("가")는 문자 코드 포인트 개수1이며 인코딩 뒤의 바이트 수와 다르다. 화면상 한 글자 모양과 코드 포인트 수도 항상 같지는 않다.

text = "가"
raw = text.encode("utf-8")
# 종이 예상: len(text) == 1, len(raw) == 3

모드와 인코딩은 계약

읽기 r, 새로 쓰기 w, 덧붙이기 a, 새 파일 전용 x의 목적을 구별한다. w는 기존 내용을 잘라낼 수 있으므로 입력 원본을 출력 경로로 쓰지 않는다. 예제는 읽기만 보여 주고 실제 사용자 파일은 건드리지 않는다.

text에서 encoding="utf-8"을 명시하면 기본 환경에 의존하지 않는다. binary에는 encoding을 지정하지 않는다. UTF-8 파일을 다른 규칙으로 읽으면 오류나 깨진 문자가 생길 수 있고 errors="ignore"는 잘못된 바이트를 버려 자료 손실을 숨길 수 있다.

with open("sample.txt", "r", encoding="utf-8") as f:
    text = f.read()
# 실제 파일 읽기는 이 집필 과정에서 수행하지 않음

닫기와 줄바꿈

with 블록은 파일을 연 뒤 정상 종료와 예외 경로에서 닫도록 돕는다. 파일 닫기는 문자 해독과 별개 문제다. 줄바꿈 변환도 text 모드의 기능으로, 읽는 문자 수와 원파일 바이트 수를 다르게 만들 수 있다.

바이트 그대로 비교해야 하는 작업에는 binary가 적합하다. 텍스트 해독 뒤 길이를 파일 크기로 단정하지 말고 무엇을 센 수인지 써야 한다. 이 활동에서는 알려진 바이트와 문자만 종이로 계산한다.

중간 과정을 따라가는 예제

줄바꿈 없는 UTF-8 문자열 “A가”의 코드 포인트 수와 바이트 수를 구하라.

  1. A와 가 두 코드 포인트이므로 문자 수는2이다.

  2. A는1바이트, 가는3바이트이다.

  3. 합은1+3=4바이트이다.

코드 포인트2, UTF-8 바이트4이다. 실제 파일 읽기 결과가 아니다.

소단원 10.3

CSV·JSON 읽고 쓰기

이름에 쉼표가 들어가면 CSV 한 줄을 split(",")로 나눠도 될까?

준비 개념과 학습 목표

준비 개념

  • 리스트와 딕셔너리

  • 문자열과 숫자

학습 목표

  • CSV 인용과 JSON 구조를 파서로 처리한다.

  • 파일과 문자열 API 및 저장 형식의 한계를 구별한다.

행과 열을 읽는 CSV

CSV는 행마다 필드를 구분하며 필드 안에 쉼표·줄바꿈이 있으면 인용 규칙이 필요하다. csv.reader는 그 규칙을 해석한다. 단순 split(",")는 따옴표 안의 쉼표까지 나누므로 이름 “Kim, Mina”를 잘못 두 필드로 만들 수 있다.

기본 reader 결과의 필드는 문자열이다. 점수 "80"을 숫자로 계산하려면 검증 뒤 int 변환 등을 해야 한다. DictReader는 헤더 이름으로 필드를 연결하고 DictWriter는 명시한 열 목록 순서로 쓴다. 파일은 encoding과 newline=""을 명시한다.

import csv
with open("scores.csv", encoding="utf-8", newline="") as f:
    rows = list(csv.DictReader(f))
# rows의 점수 필드는 기본적으로 문자열

중첩 구조를 담는 JSON

JSON은 객체·배열·문자열·수·불리언·null을 표현한다. Python에서는 보통 dict·list·str·int/float·bool·None과 대응한다. JSON 객체 키는 문자열이며 집합이나 임의 사용자 객체를 그대로 저장할 수는 없다.

json.load/dump는 파일 객체를, loads/dumps는 문자열을 다룬다. 파일 인코딩은 open 단계에서 명시하고 ensure_ascii=False는 비ASCII 문자를 읽기 쉽게 쓰도록 하는 옵션이다. 이 옵션이 파일 인코딩을 정하는 것은 아니다.

import json
value = json.loads('{"scores": [80, 90], "passed": true}')
text = json.dumps(value, ensure_ascii=False)
# 코드 흐름으로 예상: scores는 list, passed는 True

읽기·쓰기와 검증의 경계

CSV가 행으로 읽히거나 JSON이 파싱되어도 데이터의 의미가 옳다는 보장은 없다. 필요한 키와 범위·자료형을 검사한다. 원자료를 덮어쓰지 않고 새 출력으로 저장하며 파일 쓰기는 실패할 수도 있으므로 오류 경로를 둔다.

같은 파일에 dump를 반복하면 여러 JSON 문서가 이어져 보통 하나의 유효한 JSON 문서가 되지 않는다. Python json 기본값에는 NaN·Infinity 허용 같은 확장이 있어 엄격한 다른 시스템과 교환할 때 규칙을 확인한다. 스키마와 교환 조건을 별도로 합의한다.

중간 과정을 따라가는 예제

CSV 행은 따옴표를 포함해 “"Kim, Mina",80”이고 JSON은 {"scores":[80,90]}이다. 필드와 점수 합을 종이로 구하라.

  1. CSV 인용된 이름 전체가 첫 필드이고80이 두 번째 필드이다.

  2. 기본 CSV 점수는 문자열 "80"이다.

  3. JSON scores 배열의 수80+90=170이다.

CSV2필드: Kim, Mina / 문자열80. JSON 합170이다.

소단원 10.4

파일 부재·잘못된 데이터 처리

없는 파일과 잘못된 점수는 같은 오류 메시지로 처리하면 충분할까?

준비 개념과 학습 목표

준비 개념

  • try·except

  • 딕셔너리 키와 타입

학습 목표

  • 열기·해독·파싱·의미 검증 오류를 구분한다.

  • 좁은 예외 처리와 명확한 실패 결과를 설계한다.

어느 단계가 실패했는가

파일이 없으면 FileNotFoundError, 권한 문제 등은 OSError 계열로 나타날 수 있다. 바이트 해독은 UnicodeDecodeError, JSON 구문 해석은 JSONDecodeError로 실패할 수 있다. 같은 “읽기 실패”라도 사용자가 고쳐야 하는 대상이 다르다.

파일이 존재하는지 먼저 확인했더라도 열기 전에 사라질 수 있으므로 실제 열기 오류를 처리한다. 모든 예외를 잡아 빈 리스트를 반환하면 실제 빈 데이터와 오류가 구별되지 않아 결과를 오해할 수 있다.

문법 뒤에는 의미 검사

{"score":120}은 유효한 JSON이지만0–100점 계약에는 어긋난다. 키가 없거나 루트가 배열이면 기대 객체와 다르다. Python bool은 int의 하위 타입이므로 isinstance(v,int)만으로 True를 숫자 점수로 허용할 수 있다는 점도 계약에 맞게 다룬다.

학습용 예제는 정수 점수만 허용하려고 type(v) is int를 사용한다. 실제 서비스에는 다른 숫자 타입·범위·누락 정책을 명시해야 한다. 오류 메시지는 잘못된 조건을 알려 주되 민감한 원자료를 무조건 출력하지 않는다.

def validate(data):
    if not isinstance(data, dict):
        raise ValueError("객체가 필요합니다")
    score = data.get("score")
    if type(score) is not int or not 0 <= score <= 100:
        raise ValueError("정수 점수 0~100이 필요합니다")
    return score

실패를 숨기지 않는 경로

try 블록은 필요한 작업으로 좁히고 처리 가능한 예외만 잡는다. 알 수 없는 오류를 성공처럼 반환하지 않는다. with로 파일을 닫고 입력이 검증된 뒤 계산하며 출력 성공도 별도로 확인한다.

재시도는 원인에 따라 결정한다. 없던 입력을 사용자가 지정해 다시 읽는 것은 가능하지만 JSON 문법 오류가 그대로라면 같은 재시도만 반복해도 해결되지 않는다. 본문 코드는 예외 흐름 예상이며 실제 파일 실패 실험을 수행하지 않았다.

import json
try:
    with open("input.json", encoding="utf-8") as f:
        data = json.load(f)
    score = validate(data)
except FileNotFoundError:
    print("입력 경로를 확인하세요")
except (UnicodeDecodeError, json.JSONDecodeError, ValueError):
    print("입력 형식과 점수 조건을 확인하세요")
except OSError:
    print("파일 접근에 실패했습니다")

중간 과정을 따라가는 예제

validate에 {"score":80}, {"score":120}, {"score":true}에 대응하는 Python 객체가 들어온다. 경로를 예측하라.

  1. 80은 type int이고 범위 안이므로 반환80이다.

  2. 120은 범위 밖이라 ValueError이다.

  3. JSON true는 Python True이며 type bool이므로 type is int 조건에 실패한다.

80만 허용하며120과True는 검증 실패이다. 실제 실행 결과가 아니다.

출처와 확인 범위
  • Python Built-in Functions: open

    text/binary 반환형, encoding, 쓰기 모드 절단과 예외 조건을 실제 읽었다.

  • Python json — JSON encoder and decoder

    load/dump·loads/dumps 구분, 형변환 표, JSONDecodeError 및 기본 비엄격 수 허용을 실제 읽었다.

  • Python Built-in Exceptions

    독립 검토자가 OSError·FileNotFoundError의 조건과 except의 하위 클래스 처리를 실제 읽었다.

    독립 검토자가 bool의 int 하위 타입 관계를 실제 읽고 type is int의 점수 계약을 대조했다.
