小节 5.1

list·tuple

顺序相同的两组数据，为什么一组能替换位置中的元素，另一组却不能？

预备知识与学习目标

预备知识

  • 小复习：名称 a 是指向对象的标签；a = 表达式先计算右侧，再把标签连接到结果对象。
  • 长度为 n 的序列，其有效非负索引是 0 到 n−1。n>0 时，负索引 −1 表示最后一个位置。空序列没有有效的元素索引。
  • 自我诊断：[3, 1] 的第一个元素是 3，长度是 2。能区分这两个答案，就可以开始。

学习目标

  • 把列表和元组解释为有序的一组引用。
  • 区分 append 的修改与返回值，以及 pop 的删除与返回值。
  • 区分元组自身的不可变性和内部对象的可变性。

两种有序的数据类型

列表 list 是保留元素顺序的可变序列。[3, 1] 和 [1, 3] 的顺序不同，因此不相等。a[0] = 9 替换第一个位置的引用，append 在末尾增加一个位置。元组 tuple 也保留顺序，但创建后不能直接修改各位置的引用或长度。

空元组写成 ()，单元素元组写成 (3,)。(3) 是用括号包围整数 3 的表达式。tuple(a) 创建一个元组，按原顺序保存 a 的元素引用。之后替换列表中的位置，不会替换该元组中的位置。这种转换不会复制内部对象。

方法的效果与返回值

内置列表的 a.append(x) 把 x 加到 a 的末尾，并返回 None。仍然通过 a 访问修改后的列表，而不是从方法的返回值取得列表。a.pop() 删除最后一个元素，同时返回该元素。对空列表调用 pop 会引发 IndexError，因此删除操作的正常契约要求列表非空。

对内容为 S 的序列先 append(x)，再在没有其他修改的情况下正常执行 pop，删除并返回的值是 x，序列内容恢复为 S。依据是最后一个位置恰好是刚加入的 x。这只说明内容和长度恢复，不表示内存分配历史或所有可观察状态都恢复。若发生失败、中途修改或并发修改，就不能直接套用此契约。

不可变性的边界

元组 ([1],) 有一个位置指向列表。不能把这个位置重新赋给其他对象，但可以通过它对内部列表调用 append。例如，在 t = ([1],) 后纸上追踪 t[0].append(2)，t 显示为 ([1, 2],)。元组所指列表的对象身份没有改变。

因此，设计不可修改的记录时，只检查外层元组还不够。本节实际执行的例子以不可变整数为元素，所以可以安全地比较旧元素值。若内部包含文件、自定义对象或嵌套列表，还必须分别考察其修改契约。

逐步推导的例题

只使用内置列表和整数，按顺序正常执行每条语句。求 a、t 的最终内容以及 last。 

a = [3, 1]
t = tuple(a)
a.append(2)
last = a.pop()
a[0] = 9
print(a, t, last)
  1. a 是 [3, 1]，t 是按相同顺序保存两个整数的 (3, 1)。外层列表和元组是不同对象。
  2. append(2) 后，a 为 [3, 1, 2]。这段代码没有使用 append 的返回值 None。
  3. pop() 返回最后的整数 2，并把 last 连接到它；a 恢复为 [3, 1]。
  4. a[0] = 9 只替换列表的第一个位置。因此 a 为 [9, 1]，t 为 (3, 1)，last 为 2。

修改列表不会替换已经创建的元组中的位置。 原韩文例子的实际 stdout： 

[9, 1] (3, 1) 2

用纸笔和正文动手试一试

在纸上追踪 a = [4]; t = tuple(a); r = a.append(6); p = a.pop()。求 a、t、r、p，并比较 (4) 与 (4,) 的类型。不执行代码。

查看提示

在每个方法旁分别写出修改后的状态和返回值。

查看解答

append 后 a 为 [4, 6]，r 为 None。pop 后 a 为 [4]，p 为 6。t 保持为 (4,)。(4) 是 int，(4,) 是单元素 tuple。

常见误解与反例

转换成元组后，所有内部值都会永久固定。

([1],) 内部的列表可以通过 append 改变。元组的不可变性禁止替换其直接保存的引用，并不表示整个引用图都不可变。

检查理解

append 和 pop 返回什么？

查看答案与理由

append 返回 None，正常执行的 pop 返回被删除的元素。

append 原地修改列表；pop 同时执行删除和返回值。对空列表调用 pop 不会正常返回。

若 a = [2]; t = tuple(a); a[0] = 8，t 是什么？

查看答案与理由

是 (2,)。

替换 a 的第一个位置不会替换 t 的位置。整数 2 本身也没有改变。

在 t = ([0],) 中执行 t[0].append(7)，是否违反元组不可变性？

查看答案与理由

不违反。内部列表变为 [0, 7]。

元组的那个位置仍指向同一个列表。修改内部对象与给元组的位置赋值是不同操作。

进一步探索

把序列 S 写成 (s₀, …, sₙ₋₁)，组合 append(x) 后长度为 n+1 与 pop 后长度为 n 的两个契约，证明内容恢复。整数元素例子中的元组保存旧引用。请同时给出内部包含可变对象时，元组不能阻止该对象修改的反例。此证明不能推出性能或内存使用量。

小节 5.2

dict·set

为什么统计名称出现的次数与判断它是否出现，需要不同的数据？

预备知识与学习目标

预备知识

  • 小复习：for label in 列表会逐个把 label 连接到元素。
  • 出现次数包括重复，种类数排除重复。b, a, b 出现 3 次，有 2 种。
  • 键是用于查找值的标签；值是连接到该标签的数据。

学习目标

  • 区分字典的键查询、get、成员判断和集合的去重。
  • 比“不可变”口号更准确地解释键的 hashable 条件。
  • 用归纳不变式证明已处理前缀的出现次数。

字典的查询与插入

内置 dict 把键连接到值。d[key] 在键不存在时引发 KeyError，而 d.get(key, default) 对不存在的键返回 default。get 本身不插入该键。key in d 与 for key in d 针对的是键，并非检查或遍历值。因此在 {"x": 3} 中，3 in d 为 False。

Python 3.12 的 dict 保留键的插入顺序。更新已有键的值不会改变该键的位置；删除后重新插入则放到末尾。set 没有这种插入顺序契约。若要按排序显示结果，需要对可相互比较的值使用 sorted。本例中的键是小写字符串，因此可比较。

可哈希性与集合

字典键和集合元素必须是 hashable（可哈希）的。这意味着对象在生命周期内的哈希值稳定，可以进行相等比较，并且比较相等的两个对象必须有相同哈希值。反过来，仅凭哈希值相同不能认定值相等。允许碰撞的哈希值不是对象身份，也不是唯一编号。

内置 list、dict、set 是可变容器，不能用作键。tuple 只有在所有元素都可哈希时才可哈希，所以 ([1],) 也不能用作键。自定义对象有各自的契约，不能概括为一切可变对象都被禁止。set 不重复保存相同元素，所以 set(["b", "a", "b"]) 只留下两种元素，丢失了次数 2 和 1。空集合是 set()，而 {} 是空字典。

累计次数的不变式

假设输入为有限字符串列表，没有其他代码修改 counts，且每次更新正常完成。处理前 k 个元素后，counts 中各个值等于对应字符串在该前缀中的出现次数。尚未出现的字符串通过 get 解释为次数 0。初始 k=0 时字典为空，所有次数都是 0。

用 get(label, 0) 读取下一个 label 的旧次数，并恰好加 1。其他键保持不变，所以归纳假设在 k+1 时仍成立。每个输入只给一个次数贡献 1，因此所有保存次数之和为 k。本例只用字符串键。对于一般键，1 和 True 等相等的键可能指向同一项，必须另行确认数据区分规范。

逐步推导的例题

计算输入字符串列表 b, a, b 的频数。用 get 读取 z 后，检查 z 是否被插入，并排序输出种类。 

counts = {}
for label in ["b", "a", "b"]:
    counts[label] = counts.get(label, 0) + 1
print(counts["b"], counts.get("z", 0), "z" in counts)
seen = set(counts)
print(sorted(seen))
  1. 在空字典中处理第一个 b，get 返回 0，赋值插入 b: 1。总次数为 1。
  2. 处理 a 时加入 a: 1。处理最后一个 b 时，只把已有 b 的值更新为 2。字典为 b: 2, a: 1，总次数为 3。
  3. counts["b"] 为 2，counts.get("z", 0) 为 0。get 不插入键，因此 "z" in counts 为 False。
  4. set(counts) 是键 b 和 a 的集合。sorted(seen) 生成排序后的列表 ["a", "b"]。原始频数只保存在 counts 中。

分别保存出现频数与种类；仅查询过的 z 不会成为新键。 原韩文例子的实际 stdout： 

2 0 False
['a', 'b']

用纸笔和正文动手试一试

在纸上记录输入 a, b, a, c 的每个前缀所对应的 counts 与次数总和。最后执行 get("z", 0) 的纸上追踪后，比较键数与 set(counts) 的种类数。不执行代码。

查看提示

把空状态的总次数写为 0；每处理一个元素，只给一项加 1。

查看解答

字典依次为 {a: 1}、{a: 1, b: 1}、{a: 2, b: 1}、{a: 2, b: 1, c: 1}，总次数为 1、2、3、4。get 不加入 z，因此键数和集合种类数都是 3。仅凭集合无法恢复 a 出现 2 次。

常见误解与反例

哈希值相同就代表同一个键，而且 set 保留原始出现次数。

哈希碰撞不是相等的证据。此外，["a", "a"] 和 ["a"] 都转换为同一个集合 {"a"}，因此仅凭集合不能区分两份列表的频数。

检查理解

在 d = {"a": 1} 中调用 d.get("z", 0) 后，"z" in d 是什么？

查看答案与理由

是 False。

get 返回默认值 0，但不插入键。

统计输入 a, a, b，次数总和与 set 的元素个数是多少？

查看答案与理由

总和为 3，种类数为 2。

counts 也统计重复出现，而集合中 a 和 b 各保存一次。

不可变元组 ([1],) 能用作 dict 的键吗？

查看答案与理由

不能。

其元素 list 不可哈希，所以该元组也不可哈希。仅有外层不可变性还不够。

进一步探索

把归纳不变式分成两句话来证明：每个键的准确次数，以及所有次数之和 k。总和正确时，个别次数仍可能错误。例如输入 b, a, b，结果 b: 1, a: 2 满足总和 3，却违反规范。正确性证明需要逐键不变式，不包含运行速度或最坏时间保证。

小节 5.3

嵌套结构与复制

复制了外层盒子，为什么原盒子内部的内容仍会改变？

预备知识与学习目标

预备知识

  • 小复习：[[1], [2]] 包含一个外层列表和两个内部列表。
  • a[0].append(9) 修改第一个内部列表的内容；a[0] = [9] 替换外层第一个位置的引用。
  • 两个箭头指向同一个盒子，就存在别名关系。输出外观相同不代表是同一个盒子。

学习目标

  • 比较赋值、浅拷贝和深拷贝的引用图。
  • 解释内部修改与外层位置替换的影响范围。
  • 解释 deepcopy 的 memo 在副本内部保留别名的条件与限制。

赋值与浅拷贝

b = a 不复制外层列表，而是让 b 也连接到 a 所指的同一列表。内置列表的 b = a.copy() 则创建新的外层列表，但原样保存元素引用。a 与 b 的外层对象身份不同，内部列表仍共享。讨论复制深度时，不要只写元素值，还要标出复制的是哪一层对象。

b[0].append(9) 修改共享的内部对象，因此 a[0] 也能看到 9。但是 b[1] = [7] 只把 b 的第二个位置连接到新列表；a 的第二个位置仍指向旧的 [2]。浅拷贝并不表示任何修改都不独立，而是外层和内部的独立范围不同。

深拷贝与 memo

copy.deepcopy 递归复制受支持的复合对象的组成部分。本例使用内置列表与整数，c 的内部列表与原对象分离，因此 c[0].append(5) 不改变 a 或 b。对于不可变整数等共享也无妨的对象，并不要求其对象身份一定是新的。

一次复制过程用 memo 记录已经处理的对象。若 row = [0]; a = [row, row]，则正常复制内置列表得到 c = deepcopy(a) 后，c[0] 与 c[1] 指向同一个复制行。原始 row 与复制行不同。也就是说，副本与原对象分离，同时保留副本内部的共享结构。不能理解为每次遇到同一个对象都创建不同副本。

复制契约的适用限制

memo 也帮助递归处理指向自身的结构。但不能把 deepcopy 当作完全独立复制所有对象的通用契约。自定义类可通过 __deepcopy__ 改变行为，函数和类会返回原对象，文件、套接字等外部资源不属于通常的值复制对象。

因此，本单元的论证只针对正常执行时的内置列表与整数图。把复制引入业务数据前，应先确定哪些资源需要共享、哪些可变状态需要分离。复制不会复制外部文件、冻结远程状态，也不会把并发访问变成原子操作。

逐步推导的例题

对只含内置列表与整数的 a 进行浅拷贝得到 b，进行深拷贝得到 c，然后按顺序追踪不同种类的修改。 

from copy import deepcopy
a = [[1], [2]]
b = a.copy()
c = deepcopy(a)
b[0].append(9)
b[1] = [7]
c[0].append(5)
print(a, b, c)
  1. a 包含外层 A 与内部 [1]、[2]。b 的新外层 B 共享这两个内部对象。c 的新外层 C 拥有另外的内部 [1]、[2]。
  2. b[0].append(9) 把共享的第一个内部对象改成 [1, 9]。a 和 b 的第一个位置都可见该修改，c 的第一个位置仍为 [1]。
  3. b[1] = [7] 只改变 B 的第二个箭头。a 和 c 的第二个位置各自保留 [2]。
  4. c[0].append(5) 只把复制的第一个内部对象改成 [1, 5]。a 为 [[1, 9], [2]]，b 为 [[1, 9], [7]]，c 为 [[1, 5], [2]]。

修改共享内部对象与替换一个外层位置，会沿不同的路径传播。 原韩文例子的实际 stdout： 

[[1, 9], [2]] [[1, 9], [7]] [[1, 5], [2]]

用纸笔和正文动手试一试

在纸上画出 row = [0]; a = [row, row]; b = a.copy(); c = deepcopy(a)，再追踪 b[0].append(4)、c[1].append(6)。求 a、b、c 以及 c[0] is c[1]。不执行这个变式。

查看提示

分别画一个原始行 R 和一个复制行 R′。利用 memo 条件，不要把 c 的两个位置拆成不同的行。

查看解答

a 和 b 通过共享的 R，都显示为 [[0, 4], [0, 4]]。c 两次指向 R′，显示为 [[0, 6], [0, 6]]。c[0] is c[1] 为 True，c[0] is row 为 False。同时满足副本内部的别名与副本和原对象的分离。

常见误解与反例

deepcopy 会把所有引用都变成不同对象，并复制所有资源。

重复行在副本内部仍然共享。函数、类的返回规则以及自定义复制规则也限制了新对象保证。含外部资源的对象需要显式的独立资源契约。

检查理解

b = a.copy() 会让嵌套列表的内部也相互独立吗？

查看答案与理由

不会。只创建新外层列表，内部引用仍共享。

浅拷贝的契约区分外层复合对象与其中已有对象的引用。

若 a = [[1]]; b = a.copy(); b[0] = [8]，a 是什么？

查看答案与理由

是 [[1]]。

只替换 b 的外层第一个位置，原来共享的内部对象以及 a 的位置都不改变。

对 row = [0]; a = [row, row] 进行 deepcopy，副本的两行一定不同吗？

查看答案与理由

不一定；正常复制内置列表时，它们共享同一个复制行。

memo 重用与同一原始对象对应的副本，保持副本内部的别名。

进一步探索

对于有限的内置列表图，可把 memo 理解为给原始对象 R 确定一次对应的复制对象 R′。原图中两个箭头汇合到 R，副本中对应箭头也汇合到 R′。这说明共享结构得以保留。存在环时，要重用已创建副本的引用，避免无穷复制。这不是针对自定义复制钩子或外部资源的通用定理；相应拓展代码没有执行。

小节 5.4

可变性、别名与错误

一条赋值语句与一次内部修改，为什么会以不同方式影响其他名称？

预备知识与学习目标

预备知识

  • 小复习：把写着名称的标签和表示列表的盒子分开。赋值可改变标签的箭头。
  • == 比较值是否相等，is 比较对象身份。内容相同的列表也可以是不同对象。
  • [row] * 3 重复一个单元素序列。不要先假定它会重新创建三次内部 row。

学习目标

  • 追踪重复引用与创建新行的区别。
  • 区分修改对象、重新给名称赋值和替换容器位置。
  • 解释把返回值 None 再次赋给名称所造成的错误。

对象节点与引用箭头

把对象画成节点，把名称和容器位置画成箭头。view = grid 增加一个指向同一外层节点的箭头。grid = 新列表只把名称 grid 的箭头移到新外层节点。仍指向旧节点的 view 不会自动移过去。

view[1].append(8) 沿 view 的第二个位置，修改其所指的内部节点。所有指向该节点的路径都能观察到修改。若写 view[1] = [8]，替换的则是外层一个位置的箭头，而不是旧内部节点。解决共享问题时，必须区分被修改的节点与被替换的箭头。

重复与新对象生成

[row] * 3 是一个新的外层列表，其中包含三个指向 row 的引用。不仅三处内容看起来相同，而且三处指向同一行。沿一条路径修改行后，另外两条路径也看到该修改。序列重复不复制元素自身。

在 [[0] for _ in range(3)] 中，每次迭代都会由 [0] 表达式创建新的内置列表。因此三行内容相同，却是不同对象。[row for _ in range(3)] 则保存三次相同的 row 引用，并不能消除共享。不能仅凭 comprehension（推导式）这一语法名称保证行独立，必须检查重复求值的表达式。

身份检查与返回值错误

内置列表 x = [1]; y = [1] 满足 x == y 为 True，但 x is y 为 False。is 不是内容比较操作。整数、字符串等不可变对象可被实现重用，所以不要习惯用 is 判断值相等。本例只检查显式共享的内置列表身份。

a = a.append(2) 先向旧列表追加 2，再把返回值 None 连接到名称 a。若旧列表还有其他名称指向，则仍可通过这些名称观察到修改。下次调用 a.append 会因 None 没有列表方法而失败。应按目的单独调用 a.append(2)。这里是纸上错误追踪，没有实际执行错误变式的记录。

逐步推导的例题

先让三个位置共享同一行，再只把 grid 名称连接到新结构。比较 view 所指旧结构的修改与新 grid 的内容。 

row = [0]
grid = [row] * 3
grid[0][0] = 7
view = grid
grid = [[1], [2], [3]]
view[1].append(8)
print(view)
print(grid)
print(view[0] is view[2])
  1. row 是内部 R，初始为 [0]。grid 的三个位置都指向 R。grid[0][0] = 7 把 R 改成 [7]，三处都显示 [7]。
  2. view = grid 共享旧外层 G。grid = [[1], [2], [3]] 只把 grid 连接到新外层 H 及三个新内部行。
  3. view[1].append(8) 仍找到 R，把它改成 [7, 8]。G 的三个位置都共享 R，因此 view 为 [[7, 8], [7, 8], [7, 8]]。
  4. H 不共享 R，因此 grid 为 [[1], [2], [3]]。view[0] 与 view[2] 是同一个 R，所以 is 检查为 True。

把名称连接到新对象不会改变已有别名；共享行的修改可从所有共享路径观察到。 原韩文例子的实际 stdout： 

[[7, 8], [7, 8], [7, 8]]
[[1], [2], [3]]
True

用纸笔和正文动手试一试

不执行代码，追踪 row = [0]; a = [row] * 2; b = a; a[0] = [5]; b[1].append(6); a = []。求最终 a、b、row，以及 b[0] is b[1]。

查看提示

初始外层 G 的两个位置共享 R。替换第一个位置后，两条箭头分开。最后一行只移动名称 a。

查看解答

第一个位置指向新的 [5]，第二个位置指向 R。append 后 R 为 [0, 6]。最终 a 为 []，b 为 [[5], [0, 6]]，row 为 [0, 6]。b[0] is b[1] 为 False。指向外层 G 的 b 不受最后一次 a 重新赋值影响。

常见误解与反例

给名称赋新值会同时改变它的所有别名，而且推导式会消除内部共享。

view = grid 后重新赋值 grid，不会移动 view。此外，[row for _ in range(3)] 重复引用 row。应分别检查名称赋值和内部生成表达式。

检查理解

在 x = [1]; y = [1] 中，x == y 与 x is y 分别是什么？

查看答案与理由

分别是 True 和 False。

内容相同，但两次列表表达式创建不同的内置列表对象。

row = [0]; a = [row for _ in range(2)] 中的两行独立吗？

查看答案与理由

不独立。两次引用同一个 row。

重复求值的表达式 row 不创建新列表。要生成独立行，应像 [0] 一样在每次迭代中创建新对象。

a = [1]; b = a; a = a.append(2) 后，a 与 b 是什么？

查看答案与理由

a 为 None，b 为 [1, 2]。

右侧 append 先修改已有列表并返回 None。随后只有 a 连接到 None，b 仍指向修改后的列表。

进一步探索

先写出共享路径集合，就能预测修改的影响范围。当三个位置共享行 R 时，对 R 的 append 改变三条路径的观察值；把一个位置连接到新 R′，则只让该路径分开。程序契约应分别说明能否修改输入列表、返回值是否为新列表、是否共享内部对象。这个引用模型不保证内存地址值、释放时刻或线程安全。
