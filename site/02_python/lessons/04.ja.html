小節 4.1

if·elif·else

複数の条件が同時に成り立つとき、コンピュータはどの説明を選ぶだろう？

準備する概念と学習目標

準備する概念

  • score=85は値を保存する代入で、score==85は等しいかを比較する式だ。この単元ではbool、文字列、ユーザー定義オブジェクトを除き、組み込みintの点数を仮定する。
  • 真と偽は条件の判定である。<と<=は境界を含むかが違う。0<=score<=100は両方の境界を含む。
  • インデントは同じ分岐に属する文のまとまりを示す。コロンの次の行から始まるまとまりと、その外のprintを区別する。

学習目標

  • 最初に真になる条件だけを選ぶif・elif・elseを追跡する。
  • 点数の範囲、境界、分岐の順序が結果に与える影響を説明する。
  • 偽と判定される値と短絡評価を、エラーを防ぐ条件に結び付ける。

一つのまとまりを選ぶ規則

ifは条件を調べ、真ならインデントされた文のまとまりを実行する。elifは前の条件が全て偽の場合にだけ調べる。elseがあれば前の条件が全て偽のとき実行する。一つの連鎖では最大一つのまとまりを実行する。elseがなく全て偽なら、どのまとまりも実行しない。

例ではまず0〜100の範囲外をinvalidとする。有効な点数は90以上ならgold、それ未満で80以上ならsilver、残りはpracticeだ。範囲検査は型変換ではない。文字列を数値へ変える処理や入力エラー処理はなく、整数という契約の外の値まで安全に検証できるとは主張しない。

順序は結果を変える

95は>=90と>=80の両方を満たす。高い境界から調べる連鎖ではgoldを選び、silverの条件は調べない。>=80を先に書くと95もsilverになり、後の>=90分岐へは到達できない。区間の重なりと最初の選択規則を一緒に確認する。

独立した二つのifは連鎖とは違う。score=95のとき最初のifでlabelへgoldを代入しても、次の独立したif score>=80でsilverを再代入できる。二つの独立した動作が必要な問題では別々のifが適切な場合もある。一つに分類するのか、複数の動作を実行するのかを先に決める。

真偽判定と安全な検査順序

組み込み値None、False、数値0、空文字列、空リストは条件で偽と判定される。負数-1は0ではないので真だ。値がないという意味と数値0という意味は同じではない。andとorは常にboolへ変換して返すのではなく、選ばれた被演算子を返す。例えば0 or 7の値は7である。

andは左側が偽なら右側を評価しない。整数nについてn!=0 and 10//n>=2はn=0なら除算を飛ばす。反対に除算の条件を先に置くと同じ保護はない。これはその除算のゼロ分母だけを避ける説明で、任意のオブジェクトや他の演算エラーも解決する保証ではない。

途中の過程をたどる例題

固定整数score=85を四つの領域に分類する全コードを追跡しよう。 

score = 85
if not 0 <= score <= 100:
    label = "invalid"
elif score >= 90:
    label = "gold"
elif score >= 80:
    label = "silver"
else:
    label = "practice"
print(label)
  1. 85は0<=85<=100を満たすのでnotの条件は偽となり、invalidのまとまりを飛ばす。
  2. 85>=90は偽なのでgoldのまとまりを飛ばす。
  3. 85>=80は真なのでlabelへsilverを保存する。後のelseは実行しない。
  4. 連鎖の外のprint(label)はsilverと改行を出力する。固定入力の実際の実行結果もsilverだった。

silverの一行である。整数入力の契約と上記の分岐順序に従う結果だ。

コードを変えずscoreを79、80、90、101へ変えると仮定して、紙上でlabelを求めよう。さらに>=80の分岐を>=90より先に置くと95はどうなる？

ヒントを見る

範囲検査から左から右へ調べ、最初に真になった条件で選択を止める。

解答を見る

79はpractice、80はsilver、90はgold、101はinvalidだ。順序を変えた95はsilverになる。この五つの活動入力は紙上でのみ追跡した。

よくある誤解と反例

負数は悪い値なので条件では常に偽である。

Pythonの組み込み整数-1は真と判定される。負数を拒否するならvalue<0など問題の条件を明示する必要がある。データの許容範囲と言語の真偽判定は別の規則だ。

理解を確かめる

元の分岐でscore=95のlabelは？

答えと理由を見る

gold.

範囲内で>=90が先に真になるので、>=80は調べない。

elseのない連鎖で全条件が偽ならエラーになる？

答えと理由を見る

その理由だけではエラーにならない。

該当するまとまりを全て飛ばす。その後で初期化されていない名前を読むと、別のエラーが起こり得る。

n=0のときn!=0 and 10//n>=2は除算を実行する？

答えと理由を見る

実行せずFalseを返す。

左の比較がFalseなのでandは右側を飛ばす。

もう一歩先へ

発展：整数の点数全体を範囲外、[90,100]、[80,89]、[0,79]の四集合へ分けよう。これらは互いに重ならず、全ての整数はちょうど一つに属する。範囲外検査後の最初の真の選択が、各集合に合うlabelを選ぶことを場合分けで証明できる。一方、条件score>=80とscore>=90自体は重なる。連鎖の実際の選択領域には、前の条件が偽であるという条件も含める必要がある。これは組み込み整数、正常な比較、例外のない実行を前提とした分類の証明であり、一部の点数の実行だけで全ての型の安全性を証明したわけではない。

小節 4.2

while·for·range

2,4,6,8を足すとき、反復はどこで止まるべきだろう？

準備する概念と学習目標

準備する概念

  • 累積変数total+=iは、totalに現在のiを加えて保存する。最初の値を0と定めて加算の開始状態を用意する。
  • 一回の反復は本文を一度実行することだ。whileは本文の前に条件を調べるので、最初から偽なら本文は0回である。
  • リストは順序を持つ値の集まりで、forは反復可能な対象から順に値を受け取る。rangeは組み込み整数の規則的な列を表す。

学習目標

  • whileの検査・本文・更新の順序を追跡する。
  • rangeの開始、終端除外、方向、間隔0のエラーを区別する。
  • 有限反復の進行と終了を条件付きで説明する。

条件を再び問うwhile

while i<9は現在のiが9未満の間、本文を実行する。本文後に同じ条件を再検査する。i=2からi+=2で更新すると検査値は2,4,6,8,10で、10で止まる。終了後のiは8ではなく10である。

条件がいつか偽になる進行を確認する必要がある。更新を除くとiが2に固定され、合計だけが増え続けることがある。while自体は決まった回数や終了を保証しない。実コードの例外や外部変化も終了理由になり得るが、ここでは固定整数と正常な演算だけを扱う。

forとrangeの契約

for i in range(2,9,2)は2から始めて2ずつ増やし、9未満の2,4,6,8を順に提供する。stopは含まない。range(3)は0,1,2を表し、range(4,4)は空である。rangeはリスト全体を先に作って返す関数ではなく、整数列を表す別のオブジェクトだ。

間隔が負なら値は減少し、stopより大きい必要がある。range(9,1,-2)は9,7,5,3だ。方向が合わないrange(2,9,-1)は空で、step=0はValueErrorである。この単元の引数は組み込みintに限定する。実際のrangeは整数インデックス変換の契約を満たすオブジェクトも受け取るので、全てのユーザー定義オブジェクトをここで扱ったわけではない。

二つの反復を比較する基準

forの反復変数には次の提供値が再代入される。本文内でi=100に変えても、その代入だけでrangeの次の提供値は変わらない。一方、whileは変更後のiを次の条件検査で使う。二つの構文では更新の責任が異なる。

有限rangeを正常に使い切り、各本文も終了すればforは終了する。全てのfor対象が有限とは限らず、本文に終わらない反復があれば有限入力だけでは不十分だ。以下の二つのプログラムは外部入力やリスト変更がなく四つの値だけを加えるため同じ合計を得る。同じ合計だからといって、全てのwhileをforへ変えても意味が等しいという一般法則にはならない。

途中の過程をたどる例題

forとwhileで同じ四つの数を累積する全コードを追跡しよう。 

for_total = 0
for i in range(2, 9, 2):
    for_total += i
while_total = 0
i = 2
while i < 9:
    while_total += i
    i += 2
print(for_total, while_total)
  1. for_total=0から始め、forが提供するiは2,4,6,8である。累積合計は2,6,12,20だ。
  2. while_total=0,i=2と別に初期化する。最初の検査は真で、2を加えてからi=4となる。
  3. 次の反復で4,6,8を加え、合計は6,12,20になる。それぞれi=6,8,10へ更新する。
  4. i=10では10<9は偽だ。printは20 20と改行を出力し、保存されたコードの実際の結果と一致した。

二つの合計は共に20である。whileの最終i=10とforの最後の提供値8を区別する。

紙と本文で試してみよう

range(9,1,-2)の値と合計を紙に書こう。別に、while例の初期iだけを9に変え、while_total=0を維持すると合計と本文回数は？

ヒントを見る

解答を見る

よくある誤解と反例

終端値9を書いたのでrange(2,9,2)は最後に9を加える。

stopは除外され、2ずつ増える値も9に到達しない。値は2,4,6,8だ。範囲の終端と間隔の両方を確認する。

理解を確かめる

range(4,4)の反復回数は？

答えと理由を見る

0回。

正の既定間隔では開始値がstop未満でないので、最初から空である。

rangeのstepを0にすると無限反復オブジェクトになる？

答えと理由を見る

ならない。ValueErrorが発生する。

間隔0は許されず、空の列や自動更新として処理されない。

for i in range(3)の本文でi=100と代入すると、次の提供値は？

答えと理由を見る

最初の反復の後は1である。

forはiteratorの次の値を反復変数へ新たに代入する。

もう一歩先へ

発展：while例でk回の正常な反復直後にi=2+2k、累積合計=k(k+1)となることを証明しよう。k=0では2と0が正しい。k<4なら次の値2+2kを加えてk(k+1)+2+2k=(k+1)(k+2)となり、iも2増える。k=4でi10となり条件が偽なので、ちょうど4回後に合計20を得る。kが0から4まで増える有限の進行が終了の根拠だ。本文を変更したり更新を飛ばしたりすれば、証明をやり直す必要がある。これは数学的状態と正常な組み込み整数演算の証明で、実際の資源枯渇や任意のiterableの終了まで保証しない。

小節 4.3

break・continueと反復の設計

負数は飛ばし、0に出会ったら止まるという規則をどう区別するだろう？

準備する概念と学習目標

準備する概念

  • continueは現在の反復本文の残りを飛ばして次の反復へ進む。breakは最も内側の反復一つを終了する。
  • 目印の値0は、この問題で中断の信号として定めた値だ。全ての問題で0を飛ばしたり終了したりする必要があるわけではない。
  • 反復のelseはifのelseと役割が違う。forの次の値がなく正常に使い切ると実行し、breakで抜けると実行しない。

学習目標

  • 一回を飛ばすことと反復全体の中断を、データの追跡で区別する。
  • 反復elseと空入力の結果を説明する。
  • continueがwhileの進行更新を飛ばすことによる終了の誤りを見つける。

今の一回を飛ばすことと止まること

リスト[2,-1,4,0,8]では負数を累積せず次の値を調べ、0を終了信号とし、正数を合計へ加える。-1でのcontinueは後の0検査と累積を飛ばすが、4を調べる機会は残す。0でのbreakは8を全く訪問しないようにする。

breakとcontinueは最も内側の囲む反復に適用される。反復が二重なら内側のbreakが外側まで自動終了するわけではない。複数の反復を終了するには別の制御設計が必要だ。ここでは一重の固定された有限リストだけを使う。

使い切ったことを示すelse

forと同じインデントのelseは、次の値がなく正常に使い切ったときに実行する。その場合、例ではoutcome="exhausted"を保存する。0の分岐ではまずoutcome="stopped"を保存してからbreakで抜けるので、elseを飛ばす。空リストもすぐに使い切った状態となり、elseでoutcomeを保存する。

continueを使っただけでelseがなくなるわけではない。最後の値でcontinueしても、次の値がなければelseへ到達できる。反復を含む関数のreturnや、処理されない例外で抜けることは正常な使い切りとは違い、elseを実行しない。この例では関数returnと例外を意図的に作っていない。

全ての経路に進行が必要

紙上で、while i<3をi=0から始め、if i==1: continueを使い、その後だけにi+=1を置くと考えよう。i0では1へ更新するが、次のi1ではcontinueが更新を飛ばす。その後iは1に固定されるので正常終了しない。この無限反復の反例は実行しない。

修正するときはcontinueを通る経路でも進行を保証する必要がある。例えば現在の項目を別に保存し、先にインデックスを増やしてからその項目の除外条件を調べられる。更新場所を移すと検査する項目も変わり得るので、現在値と次の位置を分けて追跡する。breakの経路はその場で反復を終えるため、次の更新は必須ではない。

途中の過程をたどる例題

負数を除き、最初の0で中断する全コードを追跡しよう。 

total = 0
for value in [2, -1, 4, 0, 8]:
    if value < 0:
        continue
    if value == 0:
        outcome = "stopped"
        break
    total += value
else:
    outcome = "exhausted"
print(total, outcome)
  1. total=0から始める。value2は負数でも0でもないのでtotal2となる。
  2. value-1は最初の条件でcontinueし、total2を維持する。value4は正常に累積してtotal6となる。
  3. value0は負数条件が偽で0条件が真となる。outcomeへstoppedを保存してbreakする。
  4. value8は訪問せずelseも実行しない。6 stoppedと改行の出力は保存されたコードの実際の結果と同じだ。

合計6、outcomeはstoppedである。リスト全体の正数の合計14を求める問題とは違う。

ヒントを見る

解答を見る

[2,-1,4]は6 exhausted、[]は0 exhausted、[0]は0 stoppedだ。この三つの活動は実行せず、規則で追跡した。

よくある誤解と反例

continueを一度使うと反復elseは実行されない。

continueは次の値を求めて進む操作だ。最後まで正常に使い切ればelseを実行する。elseを飛ばすbreak・return・例外と区別する。

理解を確かめる

答えと理由を見る

加えない。

0でbreakして8を訪問しないためである。

空リストはelseを実行する？

答えと理由を見る

この正常な実行では実行する。

iteratorは初めから使い切った状態で、breakも起こらない。

答えと理由を見る

しない。

最も内側の反復だけを終了する規則だ。

小節 4.4

累積・探索・境界の事例

位置0で見つけた結果と、まだ見つかっていない状態をどう区別するだろう？

準備する概念と学習目標

準備する概念

  • a[i]はリストaの位置iの値を読む。長さnの通常の非負インデックスは0からn-1だ。この例では実行中にリストを変えない。
  • Noneはここではまだ見つかっていない状態の目印だ。first is Noneで検査する。数値0は有効な最初の位置であり、値0と位置0は別の意味を持つ。
  • 全体の合計、訪問数、最初の一致位置は別々の結果だ。合計と数を最後まで求めるには、最初の一致後も残りの項目を訪問する必要がある。

学習目標

  • 累積合計、訪問数、最初の一致位置を同時に追跡する。
  • 空リスト、複数の一致、一致なし、インデックス0の境界事例を説明する。
  • 不変条件と終了条件で、全入力範囲の主張と一部の実行を区別する。

値と位置を別々に記録する

a=[0,3,0],target=0では位置0と2が一致する。最初の位置は0だ。first=Noneで始め、first is None and value==targetのときだけ現在のiを保存する。最初の一致を既に保存していれば、後の同じ値で上書きしない。

if not firstを使うとfirst0も偽と判定し、まだ見つかっていないと誤解する場合がある。is Noneはこの状態の目印だけを検査する。target0が偽となる値だからといって探索対象でないわけではない。value==targetの比較が一致を決める。

合計と数は探索とは別の責任

totalは訪問値の合計、countは訪問数だ。最初の一致を見つけたためにbreakすると全体の合計と数は完成しない。例では探索結果の保存条件だけが以後成立しなくなり、for自体は全位置を使い切る。長さnの固定リストでrange(len(a))は0からn-1を提供する。

空リストでは本文0回なのでtotal=0,count=0,first=Noneを維持する。一致のない空でないリストもfirst=Noneだ。この状態で無条件にa[first]を読むと正しいインデックスではない。結果を使う前にNoneかを確認する。未発見の目印を-1にしても、Pythonのa[-1]は最後の要素なので、未検査の参照は危険だ。

境界事例と証明は別の根拠

空リスト、最初の位置、最後の位置、重複、未発見を別々に調べると初期化と比較の誤りを見つけやすい。しかし、いくつかのリストの出力が正しいだけでは全リストの正しさを証明できない。各反復で保たれる状態を説明する必要がある。

ここでは固定された有限の組み込みintのリストと組み込みintのtarget、正常な演算と十分な実行資源を前提とする。本文は必ず終わり、インデックスはrangeで制限される。ユーザー定義の比較メソッド、リストの同時変更、資源枯渇は契約外だ。後に探索アルゴリズムの費用を分析するときも、訪問回数nと整数のビット数に依存する演算費用を自動で同一視しない。

途中の過程をたどる例題

全体の合計と個数、最初の0の位置を同時に求める全コードを追跡しよう。 

a = [0, 3, 0]
target = 0
total = 0
count = 0
first = None
for i in range(len(a)):
    value = a[i]
    total += value
    count += 1
    if first is None and value == target:
        first = i
print(total, count, first)
  1. 初期値はtotal=0,count=0,first=Noneだ。i=0のvalue=0を加えてtotal=0,count1となり、firstがNoneで一致するのでfirst0になる。
  2. i1のvalue3でtotal3,count2となる。firstはNoneでないので保存条件は偽となり、first0を維持する。
  3. i2のvalue0でtotal3,count3となる。最初の一致が既にあるのでfirstを2へ変えない。
  4. rangeを使い切り、printは3 3 0と改行を出力する。保存コードの実際の実行もこの出力だった。

全体の合計3、項目数3、最初の一致インデックス0だ。最後の0のインデックス2と区別する。
