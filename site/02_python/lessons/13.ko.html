소단원 13.1

iterable·iterator protocol

같은 목록을 새로 읽는 일과 소진한 책갈피를 다시 넘기는 일은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • for 반복문
  • 리스트
  • 예외와 객체

학습 목표

  • iterable과 iterator를 구별한다.
  • iter와 next의 위치를 추적한다.
  • 소진과 새 반복자 생성을 나눈다.

반복 대상과 현재 위치를 나눈다

iterable은 반복에 필요한 iterator를 얻을 수 있는 대상이다. 리스트에서 iter(items)를 호출해 반복자를 얻는다. iterator는 next로 다음 값을 반환하고 항목이 없으면 StopIteration 종료 신호를 제공한다. for는 이 절차를 사용해 반복을 마친다.

같은 리스트에서 얻은 별개 반복자 두 개는 같은 요소를 읽어도 위치가 독립적이다. 새 반복자를 얻어 처음부터 읽는 일과 기존 반복자가 현재 위치를 기억하는 일을 구별한다. 이 예제는 반복 중 원본을 바꾸지 않는다.

next는 남은 항목을 소비한다

a와 b는 각각 같은 리스트의 처음에서 시작한다. next(a) 두 번은4와7을 읽어 a는9 앞에 남는다. next(b)는4를 읽어 b는7 앞에 남는다. list(a)는 남은9를 새 리스트에 담으며 a를 끝까지 소비한다.

두 번째 list(a)는 빈 리스트다. list(b)는 남은7과9를 담아 b도 소진된다. iter(b)는 b 자신을 반환해 처음으로 돌아가지 않는다. 아래 예제의 실제 출력과 위치를 대응시킨다.

items = [4, 7, 9]
a = iter(items)
b = iter(items)
print(next(a), next(a), next(b))
print(list(a), list(a), list(b))
print(iter(b) is b)
try:
    next(b)
except StopIteration:
    print("end")

소진 이후의 계약을 지킨다

정상 iterator는 한번 StopIteration을 낸 뒤 이후 next에서도 종료 신호를 내야 한다. 임의로 다시 값을 내면 소비자의 종료 기대를 깨뜨린다. 처음부터 읽으려면 재반복 가능한 원본에서 새 반복자를 얻거나 필요한 자료를 보존한다.

모든 iterable이 여러 번 처음부터 읽히지는 않는다. iterator와 generator도 iterable이지만 같은 객체를 다시 사용하면 남은 값만 읽는다. 파일과 네트워크처럼 외부 자원이 있는 대상은 iter 호출만으로 새 자료를 얻는다는 보장이 없다.

중간 과정을 따라가는 예제

본문의 a와b의 남은 요소와 출력 순서를 추적한다.

  1. 첫 print는 a의4·7과 b의4를 읽어4 7 4다.
  2. 다음은 list(a)=[9], 소진 a의[]와 list(b)=[7,9]다.
  3. iter(b) is b는True, next(b)는 종료 신호여서end다.

실제 출력은4 7 4 / [9] [] [7, 9] / True / end의 네 줄이다.

오해와 반례

iter(iterator)는 항상 처음부터 읽는 새 객체를 만든다.

iterator.__iter__는 자기 자신을 반환한다. 소진 b의 iter(b)도 같은 소진 객체다. 리스트에서 iter(items)를 새로 얻는 것과 다르다.

소단원 13.2

yield와 지연 계산

함수 호출 뒤 함수 안의 출력이 아직 나오지 않을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수와 return
  • range
  • iterator

학습 목표

  • 호출과 본문 실행을 나눈다.
  • yield 중단·재개를 추적한다.
  • 지연 계산의 저장과 오류 한계를 밝힌다.

필요할 때 값을 만든다

yield를 포함하는 이 함수를 호출하면 generator 객체가 생긴다. 호출 직후 본문 전체가 실행되는 대신 next로 요구할 때 시작한다. yield는 값을 전달하고 지역 변수와 다음 실행 위치를 보존하며 중단한다.

다음 next는 중단 지점 다음부터 이어진다. return이 실행을 끝내는 것과 달리 yield 이후 반복을 이어 갈 수 있다. 함수가 끝나면 generator도 소진되며 같은 객체를 list로 다시 읽어도 처음부터 계산하지 않는다.

출력이 발생한 시점을 추적한다

doubled(3) 직후에는 start가 아직 출력되지 않아 created가 먼저 나온다. 첫 next는 start와 make 0을 출력하고0을 넘긴다. 바깥 print가0을 출력한 뒤 둘째 next는 make 1과 값2로 이어진다.

list(g)는 남은 값을 모두 요구한다. make 2 뒤4가 yield되고 다시 재개하면 done 뒤 끝난다. 따라서 done이[4] 출력보다 먼저다. yield 뒤의 코드는 그 재개가 없으면 아직 수행되지 않는다.

def doubled(stop):
    print("start")
    for n in range(stop):
        print("make", n)
        yield 2 * n
    print("done")

g = doubled(3)
print("created")
print(next(g))
print(next(g))
print(list(g))
print(list(g))

지연이 모든 저장을 없애지 않는다

하나씩 값을 넘기면 출력 전체의 중간 목록을 피할 수 있다. 그러나 함수 안에서 큰 리스트를 만들거나 소비자가 list(g)로 모두 모으면 자료가 메모리에 남는다. 입력 참조와 지역 상태도 존재한다.

본문 오류는 객체 생성 대신 소비 중 드러날 수 있다. 파일 같은 자원은 중단된 generator에 남을 수 있어 닫기 범위를 계획해야 한다. 여기서는 작은 range만 실제 실행했으며 큰 자료나 자원 성능은 미수행이다.

중간 과정을 따라가는 예제

created/start/make/done과 값의 순서를 추적한다.

  1. 생성 뒤 created가 먼저다.
  2. 첫 next는start/make 0/0, 둘째는make 1/2다.
  3. list(g)는make 2/done 뒤[4], 다시 list(g)는[]다.

실제 출력은 created / start / make 0 / 0 / make 1 / 2 / make 2 / done / [4] / [] 순서다.

종이와 본문으로 직접 해보기

새 h=doubled(2)의 next(h)를 한 번만 호출하면 make 1과done은 이미 수행되었는가?

힌트 보기

yield 0에서 중단한 위치를 본다.

풀이 보기

start와 make 0이 출력되고0을 전달했다. make 1과done은 아직 수행하지 않았다. 추가 입력은 종이 상태 추적이다.

오해와 반례

yield면 메모리0이고 모든 오류가 호출 때 바로 나온다.

지역 상태와 입력 참조가 있고 결과를 모으면 저장이 필요하다. 지연 본문 오류는 next 중 드러날 수 있어 소비 단계까지 확인해야 한다.

소단원 13.3

list·dict·set comprehension

값을 그대로 담는 일과 중복을 없애거나 이름으로 덮어쓰는 일은 같을까?

준비 개념과 학습 목표

준비 개념

  • for와 if
  • 리스트·dict·set
  • 나머지와 제곱

학습 목표

  • 일반 반복문으로 풀어 읽는다.
  • 각 결과 구조의 중복 규칙을 구별한다.
  • 복잡한 표현의 순서와 가독성을 검토한다.

통과한 입력에 식을 적용한다

list comprehension의[x*x for x in data if x%2==0]은 각x를 읽고 짝수인지 검사한 뒤 통과한 값의 제곱을 새 리스트에 담는다. 입력3,2,3,4에서2와4만 통과해[4,16]이 된다. 원래 data는 그대로다.

두 for가 있으면 앞 for가 바깥 반복이고 뒤 for가 안쪽 반복이다. 들여쓴 일반 반복문으로 먼저 풀어 읽으면 결과 순서와 제외된 값의 이유를 확인하기 쉽다. 앞쪽 결과 식과 뒤쪽 입력·조건을 나누어 읽는다.

중괄호 안의 형태가 규칙을 바꾼다

{x%3 for x in data}는 set으로3→0,2→2,3→0,4→1에서 중복0을 제거한다. set은 순서를 보장하지 않아 코드가 sorted(unique)로[0,1,2]를 출력한다. 정렬한 목록의 출력과 set 자체 순서를 혼동하지 않는다.

dict comprehension의 name:score는 키별 값을 저장한다. a5,b7,a9 순서에서는 마지막 a9가 이전 a5를 덮어쓴다. 같은 이름의 점수를 모두 보존하거나 합산하는 요구에는 이 규칙이 맞지 않아 별도 구조나 누적이 필요하다.

data = [3, 2, 3, 4]
values = [x * x for x in data if x % 2 == 0]
unique = {x % 3 for x in data}
labels = {name: score for name, score in [("a", 5), ("b", 7), ("a", 9)]}
pairs = [(x, y) for x in [1, 2] for y in [2, 3] if x != y]
print(values)
print(sorted(unique))
print(labels)
print(pairs)

짧음보다 추적 가능성을 본다

pairs에서 x=1이면 y=2와3이 모두 통과해(1,2),(1,3)이 생긴다. x=2일 때 y=2는 빠지고 y=3만 통과해(2,3)이 뒤에 붙는다. 두 for를 바꾸면 일반적으로 순서가 달라진다.

변환과 부수효과를 한 줄에 쌓으면 중간 오류를 찾기 어렵다. 그 경우 일반 for로 단계를 이름 붙일 수 있다. list/set/dict comprehension은 결과 구조를 완성해 저장하므로 지연 generator expression과 다르다.

중간 과정을 따라가는 예제

네 출력을 입력 순서와 중복 정책으로 추적한다.

  1. 짝수2와4의 제곱은[4,16]이다.
  2. 나머지0/2/0/1의 집합을 정렬하면[0,1,2]다.
  3. a는5에서9로 갱신되고 pairs는(1,2),(1,3),(2,3)다.

실제 출력은[4, 16] / [0, 1, 2] / {'a': 9, 'b': 7} / [(1, 2), (1, 3), (2, 3)]다.

종이와 본문으로 직접 해보기

data를[2,2,5]로 바꾸면 짝수 제곱 list와 나머지 set은? 본문 dict의a를5+9=14로 해석해도 되는가?

힌트 보기

list는 중복을 유지하고 set은 제거하며 dict는 여기서 합산하지 않는다.

풀이 보기

list는[4,4], 나머지 set은{2}다. 본문 dict의a는9이며14 합산이 아니다. 추가 입력은 종이로 추적했다.

오해와 반례

중괄호면 set과dict도 입력의 모든 중복과 순서를 보존한다.

set은 중복 제거·순서 비보장이고 dict는 같은 키 값을 덮어쓴다. list와 다른 계약이다. 빈{}는dict이며 빈set은set()다.

한 단계 더

소단원 13.4

대용량 파일 순차처리

파일 전체를 한꺼번에 보관하지 않고도 합계를 구할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 텍스트 파일·UTF-8
  • with
  • 반복과 누적

학습 목표

  • 파일 반복과 전체 읽기의 저장 차이를 설명한다.
  • 빈줄·숫자·EOF와 오류를 구별한다.
  • 긴 줄과 집계 상태의 메모리 한계를 밝힌다.

읽으면서 필요한 상태를 누적한다

file 객체를 for로 반복하면 줄을 차례로 읽을 수 있다. 합계와 개수만 필요하면 이전 줄을 모두 목록에 넣을 필요가 없다. 반면 read()와 readlines() 또는 list(file)는 전체 내용이나 줄 목록을 만들어 큰 저장공간이 필요할 수 있다.

텍스트 인코딩을 지정하고 with 안에서 읽으면 정상 종료나 예외 뒤 파일을 닫는다. generator를 with 밖에서 소비하면 이미 닫힌 파일을 읽으려 할 수 있어 자원의 수명과 소비 범위를 함께 정한다. 파일 반복이 숫자 형식을 자동 검증하는 것은 아니다.

작은 파일로 절차를 확인한다

예제는 임시 폴더에4, 빈줄,7, 마지막 개행 없는9를 기록한 작은 UTF-8 파일을 만든다. 기존 파일을 덮어쓰지 않으며 임시 폴더는 with 종료 뒤 자동 정리된다. 실제 실행은 이 작은 파일만 확인했으며 큰 파일 성능 시험은 아니다.

strip 결과가 빈 문자열이면 이 예제는 해당 줄을 건너뛴다. 나머지는 int로 변환해 합계와 개수를 누적한다. 마지막 개행 없는9도 읽고 for는EOF에서 끝난다. readline의 빈줄은 개행 문자를 포함하며 EOF의 빈 문자열과 다르다.

from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "numbers.txt"
    path.write_text("4\n\n7\n9", encoding="utf-8")
    total = 0
    count = 0
    with path.open("r", encoding="utf-8") as file:
        for line_number, line in enumerate(file, start=1):
            text = line.strip()
            if not text:
                continue
            value = int(text)
            total += value
            count += 1
    print(count, total)
    print(total / count if count else "no data")
    print(file.closed)

입력 실패와 저장 한계를 남긴다

세 숫자의 합은20, 개수3으로 평균20/3이다. 전부 빈줄이면 개수0이라 평균을 정의하지 않고 no data를 출력한다. 숫자가 아닌 bad가 있으면 현재 코드는 ValueError로 중단하며 자동으로0으로 세지 않는다.

한 줄씩 읽어도 한 줄이 매우 길면 그 줄의 저장공간이 필요하다. 누적 정수도 값이 커지면 자리수가 늘고 문자열 변환도 저장이 필요하다. 최대 줄 길이L과 집계 상태A를 유지하는 관점으로 보며 모든 파일에 고정 바이트나 빠른 실행을 보장한다고 하지 않는다.

중간 과정을 따라가는 예제

작은 파일의 개수·합계·평균과 닫힘 상태를 구한다.

  1. 첫 숫자 뒤 count1,total4이며 빈줄은 건너뛴다.
  2. 7 뒤 count2,total11,9 뒤 count3,total20이다.
  3. 평균20/3=6.666666666666667이고 file.closed는True다.

실제 출력은3 20 / 6.666666666666667 / True다. 작은 임시 파일은 자동 정리되었으며 큰 파일 실험은 미수행이다.

오해와 반례

for line in file은 모든 크기의 파일을 고정 메모리로 오류 없이 처리한다.

현재 줄 길이와 집계 상태, 변환·인코딩·형식 오류에 영향받는다. 전체 목록을 피하는 것과 모든 자원·입력 문제를 해결하는 일은 다르다.
