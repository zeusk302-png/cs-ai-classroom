Subtopic 1.1

Files, working directories, and run commands

If two files are both named hello.py, which one will the computer run?

Preparation and learning goals

Preparation

  • A file is saved content with a name; a folder is a location that groups files.
  • Preparation check: in the address school/classroom/desk, is the last name enough to locate a desk? When several places have the same name, you need its full location.

Learning goals

  • Distinguish a source file, an interpreter, and a working directory.
  • Combine a relative path with the working directory to identify the file being run.
  • Record both the command and its location when documenting a run.

Text and its interpreter have different roles

hello.py is a text file containing Python statements. The extension is a convention that suggests its purpose; saving a file does not execute its statements automatically. An interpreter is a program that reads the file and processes it according to the language rules. An editor changes text, while a terminal is a window for issuing commands. Keep these three roles separate.

For the paper activity, read the source and input yourself and trace the result. Optional computer practice uses an environment where a Python 3 interpreter is already available. The commands python, python3, and the Windows launcher py can select interpreters differently depending on the environment. Their names alone do not establish that they use the same version.

# Source to save in hello.py
print("Ready")

Relative paths begin at the working directory

The working directory is the directory used as the current command’s reference point. The relative path hello.py refers to a file inside that directory. An absolute path specifies a location from a drive or root. Changing the working directory can therefore make the same command select a different file or fail to find one.

Suppose C:\Study\A and C:\Study\B each contain hello.py. Running python hello.py from C:\Study\A reads the file in A. Having the file in B open in an editor does not, by itself, make B the command’s working directory. Relative paths used to access data from inside a script also generally start at the working directory; they do not automatically start in the source file’s folder.

Break down and record a command

In python hello.py, the first item identifies the interpreter to run; the next is the file argument passed to it. Put a path containing spaces in quotes so that the shell does not split it into several arguments. Shell commands and Python statements follow different grammars, so mixing them in the same input area can fail.

Checking the location with Get-Location in PowerShell and the version with python --version is optional computer practice. Record the location, source content, command, input, and result together so that someone else can reproduce the conditions. A “file not found” message concerns this stage; it does not mean that print calculated an incorrect value.

# Optional practice: enter in PowerShell
Get-Location
python --version
python ".\hello.py"

A worked example, step by step

C:\Study\A\hello.py contains print(2+3), while C:\Study\B\hello.py contains print(9). The working directory is A, and Python 3 is available. Which file does python hello.py read, and what output do you expect?

  1. The file argument is the relative path hello.py.
  2. Combining it with working directory A gives C:\Study\A\hello.py.
  3. That file calculates 2+3=5, and print displays it on one line.

It runs the file in A, with expected output 5. Editing the file in B does not change the path in this command.

Try it with paper and the lesson

On paper, draw folders A and B and their hello.py files. Assume python ../A/hello.py is run from working directory B, and draw arrows showing the path. This question assumes the usual file-path interpretation of / and the parent-directory token '..'.

Show hint

.. moves to the parent folder. Find B’s parent first.

Show solution

The path is B→Study→A→hello.py. The selected file is A’s hello.py, so the expected output is 5. The working directory stays B; only the file path specifies A.

Misconception and counterexample

The file currently open on screen is always the one that runs.

A terminal command selects its target through the file argument. With B open, running python hello.py from A still reads A’s file. An editor’s run button may set the working directory in a tool-specific way, so record the actual command.

Check your understanding

Are a source file and the Python interpreter the same thing?

Show answer and reasoning

No. The source is text to process; the interpreter is the program that processes it.

They have different roles. Having source text is not enough if the interpreter cannot be found.

What output is expected if you change the working directory to B and run python hello.py?

Show answer and reasoning

9

The same relative path now resolves to the file inside B.

Does specifying the source with an absolute path eliminate every environmental issue?

Show answer and reasoning

No.

File selection is clear, but interpreter versions, input, dependent files, and access permissions can still differ.

Explore further

Suppose both folders also contain data.txt. If you run A’s script by absolute path from B and the script uses open('data.txt'), it generally looks for B’s data.txt. Draw the source location and working directory separately. File-reading syntax appears in a later unit.

Subtopic 1.2

The REPL and scripts

Will entering 2+3 interactively and writing 2+3 in a file show the same thing on screen?

Preparation and learning goals

Preparation

  • An expression computes a value. The value of 2+3 is 5.
  • A statement specifies an action. x=2 binds the name x to the value 2.

Learning goals

  • Distinguish interactive expression display from print output.
  • Distinguish name bindings within a session from the state of a fresh script run.
  • Trace assignment as evaluating the right-hand side and then binding a name.

The REPL alternates between input and feedback

REPL stands for Read, Evaluate, Print, Loop: an interactive pattern that reads input, evaluates it, displays a result, and waits for the next input. Python’s basic interactive session uses >>> to indicate that it is ready for new input. The prompt itself is not Python syntax; do not copy it into a source file.

Entering the expression 2+3 interactively normally displays its value, 5. print(2+3) performs an output action that displays 5, but the call itself returns None. The default interactive interpreter does not separately display None. The two inputs can therefore look alike on screen while having different meanings.

>>> 2 + 3
5
>>> print(2 + 3)
5

A script follows saved statements in order

A script executes statements saved in a file. An expression 2+3 by itself in that file does not include an action to display the result; use print for that. Do not generalize interactive automatic value display to every way of running code.

In an ordinary fresh script process, an x created in another process or REPL does not automatically carry over. Within the same REPL session, however, x can be used in later input. Educational notebooks and editors can retain state; this example assumes the basic Python interpreter and a fresh process.

Assignment changes state; it is not an identity

x=x+3 is not a mathematical assertion that both sides remain equal forever. It reads the current value of x, evaluates x+3, and then rebinds x to the new result. If x has not already been defined, evaluating the right-hand side raises NameError.

After x=2, executing y=x binds y to the value 2 as well. Later, x=x+3 rebinds x to 5; it does not rebind y at the same time. In this integer example the final values are x=5 and y=2. Sharing mutable objects is a separate issue, distinguished in later units.

x = 2
y = x
x = x + 3
print(x, y)

A worked example, step by step

Assume a fresh Python 3 script executes x=2; y=x; x=x+3; print(x,y) in order.

  1. x=2: the name x points to value 2.
  2. y=x: y is also bound to the right-hand side’s current value, 2.
  3. x=x+3: evaluate 2+3=5, then rebind x to 5. y remains 2.
  4. print uses a space as its default separator, so it puts a space between the values.

The expected output is 5 2 followed by a newline.

Try it with paper and the lesson

Draw names x and y and value boxes on paper. Trace x=4; y=x; x=1; print(y). Also predict the kind of problem caused by entering y alone after closing and starting a fresh REPL.

Show hint

Reassignment does not move every name label attached to the old value.

Show solution

x=4 gives x→4; y=x gives y→4; x=1 changes x→1 while y→4 remains. The expected output is 4. A fresh basic REPL has no binding for y, so NameError is expected.

Misconception and counterexample

Every value shown in the REPL is also displayed automatically in a script.

A script containing only 2+3 computes a value without displaying it. Explicit output requires an action such as print. Distinguish this from the interactive automatic-display feature.

Check your understanding

Should >>> be included in a script?

Show answer and reasoning

No.

It is the basic REPL’s prompt, not part of the code.

What is the expected output of x=8; y=x; x=9; print(y)?

Show answer and reasoning

8

Rebinding x does not rebind y.

Does x=x+1 on the first line of a fresh script always set x to 1?

Show answer and reasoning

No. Under these assumptions it raises NameError.

The name must already be defined before x can be read on the right-hand side.

Explore further

Compare the orders x=2; y=x; x=x+3 and x=2; x=x+3; y=x. They end at (5,2) and (5,5), respectively. Treat each statement as a transformation of name→value state, and explain why composing these transformations is not commutative.

Subtopic 1.3

Output, input, and error messages

Why might a program reject a 7+1 calculation even when a person entered the number 7?

Preparation and learning goals

Preparation

  • The number 7 and the text '7' look similar but have different types.
  • Statement order and basic addition. Preparation check: joining '7' and '1' produces '71', while numeric addition gives 8.

Learning goals

  • Distinguish input’s string result from conversion with int.
  • Connect syntax errors, NameError, ValueError, and TypeError with their causes.
  • Read a traceback as evidence of where execution failed.

Input begins as text

input('Count? ') displays a prompt, reads one line, removes its trailing newline, and returns a string. Even if the person enters 7, the result is the string '7', not the integer 7. To perform numeric calculation, explicitly convert suitable integer text with int.

int('7') returns 7, whereas int('seven') raises ValueError. Being convertible and being a valid input for the problem are separate properties. For example, int('-2') succeeds, but the problem’s contract must separately decide whether a negative item count is allowed.

text = input("Count? ")
count = int(text)
print(count + 1)

Output effects differ from return values

print displays its arguments as text. By default it separates multiple arguments with spaces and ends with a newline. print('Count:', count) displays a label and value on one line. Inside quotes, count is literal text rather than a name lookup: print('count') displays the word instead of its value.

Output is an external effect, distinct from a returned value used in later calculations. A print call returns None. In n=print(7), 7 appears on screen but n does not hold the integer 7. Separate columns for screen output, input, and name bindings make this distinction easier to see.

Errors reveal how far the program progressed

A syntax error means the code’s form does not satisfy the language rules. An ordinary script is parsed as a whole before execution, so a missing parenthesis later in the file can prevent an earlier print from running. A runtime exception occurs when syntactically valid code fails during execution.

NameError from an undefined name, ValueError from unsuitable integer text, and TypeError from adding a string to an integer provide different clues. A traceback shows the call path and failure location. Read the final exception name and message first, then inspect the source line and input types there. Wording can change between interpreter versions, so these examples predict the exception category and failing stage.

A worked example, step by step

Compare entering 7 and entering seven in the three-line program above.

  1. Input 7: text is the string '7'; int(text) gives integer 7; count+1 gives 8.
  2. print displays 8 and a newline. The prompt 'Count? ' (including its trailing space) is displayed earlier.
  3. Input seven: text is 'seven', and int(text) raises ValueError.
  4. With no exception handler, the final print line does not execute.

For 7, the expected calculation output is 8. For seven, ValueError occurs and no calculation result 8 is displayed. Record the prompt and the user’s typed characters separately from result output.

Try it with paper and the lesson

Assume text='9' instead of calling input. Trace A: print(text+'1'), B: print(int(text)+1), and C: print(text+1) on paper. Distinguish calculation, output, and errors.

Show hint

Write the type of each operand on both sides of +.

Show solution

A concatenates strings and has expected output 91. B adds integers 9+1 and outputs 10. C attempts unsupported addition between str and int, so TypeError is expected. Exact error wording depends on the interpreter version.

Misconception and counterexample

Fixing only the line shown in an error always resolves the root cause.

Even when TypeError appears at text+1, the cause may be an earlier design that never converted input to a number. The failure location and cause location can differ. Check the input contract and intermediate values together.

Check your understanding

What type does input return by default?

Show answer and reasoning

A string, str.

Input that looks numeric is not automatically converted to an integer.

For input '12', what is the value of int(text)+1?

Show answer and reasoning

13

Convert the text to integer 12 before adding.

If int('-2') succeeds, is that a valid item count?

Show answer and reasoning

It depends on the problem’s conditions.

Successful conversion does not enforce semantic constraints such as prohibiting negative counts.

Explore further

For syntactically valid print('start'); int('oops'); print('end'), predict that only start is printed. In contrast, a syntax error at the end of a file may make whole-file parsing fail first. Discuss why the metaphor “read lines in order” does not explain every pre-execution analysis step.

Subtopic 1.4

Problem decomposition and execution records

If you record only that the answer is 9, can a friend reproduce your calculation?

Preparation and learning goals

Preparation

  • Input–processing–output order and basic arithmetic.
  • Preparation check: unit price 3 and quantity 2 give total 6. Write values and units before calculating.

Learning goals

  • Break a small requirement into an input contract, calculation, and output.
  • Preserve reproducibility conditions using a state trace and execution record.
  • Distinguish predictions, observed runs, and verification as different evidence.

Write the contract before writing the program

Before building a program, make its inputs and outputs clear. A coupon total could have the contract “take integer unit price, integer quantity, and integer discount amount; subtract the discount once from the subtotal.” If price could mean either one item’s price or the entire amount, the same code can solve different problems.

In this first exercise, price, quantity, and discount are written directly in the code. Assume they are nonnegative integers and the discount does not exceed the original subtotal. Actual user input, currency fractions, and range validation are later tasks. Stating assumptions does not hide difficult cases; it makes the scope of the current argument explicit.

Decomposition exposes intermediate results

The input stage contains price, count, and discount. Split processing into subtotal=price*count and total=subtotal-discount. Output displays total. Writing subtotal separately makes it possible to compare values before and after the discount and narrow down an error’s location.

Record what each name means and its units. price is money per item, count is a number of items, and subtotal and total are money amounts. Subtracting the discount from the count can be syntactically valid while violating units and requirements. An expression allowed by the computer is not automatically appropriate for the problem.

price = 4
count = 3
discount = 2
subtotal = price * count
total = subtotal - discount
print(total)

A prediction is not an observed execution result

A trace table records the line, newly computed value, current name bindings, and output event. This example proceeds through price=4, count=3, discount=2, subtotal=12, and total=10. A correct hand trace is evidence that you checked a prediction; it is different from evidence that you tested an actual interpreter.

When a run is performed, record the source version, working directory, command, interpreter version, input, actual output, errors, and time. If prediction and observation differ, find the earliest differing intermediate state. One matching result does not prove correctness for every input. Vary conditions such as ordinary quantities, zero items, zero discount, and full discount to check the contract.

A worked example, step by step

Trace the code with price 4, quantity 3, and discount 2. A colleague changes it to total=(price-discount)*count. Check whether that satisfies the same requirement.

  1. Original calculation: subtotal=4*3=12.
  2. One-time discount: total=12-2=10.
  3. Colleague’s calculation: (4-2)*3=6.
  4. The changed expression discounts each item by 2, for a combined discount of 6 rather than the contract’s total discount of 2.

The expected result is 10. The colleague’s 6 implements a different requirement. The first difference is the scope of the discount.

Try it with paper and the lesson

On paper, trace price 5, quantity 2, and discount 10. Compare discount 0 at the same price and quantity. Decide what to enter in the “execution performed” column.

Show hint

The original subtotal is 10; apply the discount once to that subtotal.

Show solution

First case: subtotal=10 and total=0. Second case: subtotal=10 and total=10. Both are hand-calculated predictions. For an activity done without installing or running an interpreter, record not_executed.

Misconception and counterexample

One matching observed example proves the entire program correct.

When discount=0, the correct expression and incorrect (price-discount)*count return the same value. Discount 2 and count 3 distinguish them. Tests can find counterexamples and increase confidence, but general correctness needs an argument covering the requirement and all applicable conditions.

Check your understanding

Is output alone enough for an execution record?

Show answer and reasoning

No.

It does not establish which source, input, command, and environment produced the output.

What is the total for price 2, quantity 4, and discount 3?

Show answer and reasoning

5

Subtract the one-time discount 3 from 2*4=8.

Is discount 20 within the current contract for the worked example?

Show answer and reasoning

No.

It violates the assumption that the discount is at most the original subtotal 12. An additional policy or validation design is needed.

Explore further

For allowed inputs p,c,d, calculate the difference between the correct pc-d and incorrect (p-d)c. It is d(c-1). Tests with only d=0 or c=1 cannot distinguish this defect. Explain how comparing expressions helps design discriminating tests.
