파일·작업폴더·실행 명령

같은 hello.py라는 이름을 가진 두 파일 중 컴퓨터는 어느 것을 실행할까?

준비 개념과 학습 목표

준비 개념

  • 파일은 이름이 있는 저장된 내용이고 폴더는 파일을 묶는 위치이다.

  • 진단: 학교/교실/책상이라는 주소에서 마지막 이름만 알아도 책상을 찾을 수 있을까? 같은 이름이 여러 곳에 있으면 전체 위치가 필요하다.

학습 목표

  • 소스 파일·실행기·작업폴더를 구분한다.

  • 상대경로를 작업폴더와 결합하여 실제 실행할 파일을 결정한다.

  • 실행 기록에 명령과 위치를 함께 남긴다.

숙제 이름은 같지만 교실이 다르다면 어디에 찾아가야 할까?

파일 이름만으로 대상을 정할 수 없는 상황은 같은 이름의 학생을 반과 함께 찾는 상황과 닮았다. 소스의 위치, 명령의 작업폴더, 실행기는 각각 다른 정보다. 경로 예제는 링크나 권한 문제가 없는 종이 폴더 트리로 한정한다.

편집 중인 내용은 아직 저장한 파일과 다를 수 있다. 여기서는 보통의 새 스크립트 실행이 저장된 파일을 읽으며, 편집기가 직접 코드를 전송하는 특수 실행 기능은 쓰지 않는다. 저장과 실행을 같은 사건으로 기록하면 “고쳤는데 왜 그대로지?”의 원인을 놓친다.

먼저 확인할 개념
  • 파일·권한·경로

    현재 위치와 상대 경로, 이름을 따라가는 트리 모형을 복습한다.

  • 터미널과 시스템 자원

    명령 해석기와 명령 인수, 실제 실행 조건을 구별한다.

텍스트와 실행기의 서로 다른 역할

hello.py는 Python 문장을 저장한 텍스트 파일이다. 확장자는 용도를 알려주는 관례이며 파일을 저장했다고 문장이 저절로 실행되지는 않는다. 실행기는 파일을 읽고 언어 규칙에 따라 처리하는 프로그램이다. 편집기는 텍스트를 바꾸고, 터미널은 명령을 전달하는 창이므로 세 역할을 구분해야 한다.

본문의 종이 경로에서는 소스와 입력을 직접 읽으며 실행 결과를 추적하면 된다. 선택 실습을 할 때는 Python 3 실행기가 이미 있는 환경에서 명령을 사용한다. python, python3, Windows의 py는 환경에 따라 실행기를 선택하는 방법이 다르므로 이름만 보고 같은 버전이라고 단정하지 않는다.

# hello.py에 저장할 소스
print("Ready")

작업폴더가 상대경로의 출발점이다

작업폴더는 현재 실행 중인 명령의 기준 디렉터리이다. 상대경로 hello.py는 작업폴더 안의 파일을 가리키며, 절대경로는 드라이브나 루트부터 위치를 지정한다. 따라서 같은 명령도 작업폴더가 달라지면 다른 파일을 선택하거나 파일을 찾지 못할 수 있다.

예를 들어 C:\Study\A와 C:\Study\B에 각각 hello.py가 있다면 C:\Study\A에서 python hello.py는 A의 파일을 읽는다. 편집기에서 B의 파일을 열어 놓았다는 사실만으로 명령의 작업폴더가 B가 되지는 않는다. 파일 안의 상대경로 데이터 접근도 보통 작업폴더를 기준으로 하며, 자동으로 소스 파일 폴더가 되는 것은 아니다.

명령을 분해하여 기록하기

python hello.py에서 첫 항목은 실행할 실행기, 다음 항목은 그 실행기에 넘길 파일 인자이다. 파일 경로에 공백이 있으면 셸이 경로를 여러 인자로 나누지 않도록 따옴표로 묶는다. 셸 명령과 Python 문장을 같은 입력 칸에 혼합하면 서로 다른 문법 때문에 실패할 수 있다.

PowerShell에서 Get-Location으로 위치를 확인하고 python --version으로 버전을 확인하는 것은 선택 실습이다. 다음처럼 위치·소스 내용·명령·입력·결과를 함께 기록해야 다른 사람이 같은 조건을 재현할 수 있다. 파일을 찾지 못한 메시지는 이 단계의 문제이지 print 계산 결과가 틀렸다는 뜻이 아니다.

# 선택 실습: PowerShell에 입력
Get-Location
python --version
python ".\hello.py"

중간 과정을 따라가는 예제

C:\Study\A\hello.py에는 print(2+3), C:\Study\B\hello.py에는 print(9)가 있다. 작업폴더는 A이며 Python 3가 사용 가능하다고 가정한다. python hello.py가 읽을 파일과 예상 출력은?

  1. 명령의 파일 인자는 상대경로 hello.py이다.

  2. 작업폴더 A와 결합하면 C:\Study\A\hello.py가 된다.

  3. 해당 파일의 2+3을 계산하면 5이며 print가 한 줄에 표시한다.

A의 파일이 실행되어 예상 출력은 5이다. B를 편집 중이어도 이 명령의 경로는 바뀌지 않는다.

조건을 바꾸어 비교하기

수정했지만 저장하지 않은 경우

저장된 calc.py는 print(6*2), 편집기 버퍼는 print(6*3)이다. 명령은 저장 파일을 읽는다. 저장 전후 예상값을 비교하라.

  1. 저장 전 실행 대상의 내용은 6*2다. 버퍼의 새 내용은 아직 파일에 없다.

  2. 저장 전 예상 출력은 12, 버퍼를 저장한 뒤에는 18이다.

  3. 버퍼를 되돌리거나 다른 경로에 저장했다면 실행 파일의 내용을 다시 확인해야 한다.

실행 대상과 저장 상태를 함께 기록한다. 이 폴더/편집기 조작은 실제 수행하지 않은 가상 사례다.

비교할 점

본문의 두 폴더 문제에 시간에 따른 저장 상태라는 다른 실패 원인을 추가한다.

소스와 자료의 기준점

run에서 ../src/calc.py를 선택했다. 스크립트가 나중에 상대 경로 values.txt를 읽고, run/src에 서로 다른 파일이 있다고 가정한다. 어디를 읽는가?

  1. 스크립트 선택은 run→Lab→src→calc.py다.

  2. 상대 자료 읽기는 작업폴더가 run인 상태에서 run/values.txt를 찾는다.

  3. 소스를 절대 경로로 바꾸어도 자료 경로의 출발점은 자동으로 src가 되지 않는다.

소스는 src, 상대 자료는 run이다. 파일 읽기 문법은 뒤 단원에서 배우며 지금은 위치 관계만 추적한다.

비교할 점

소스 경로 해결과 프로그램 안의 자료 경로 해결을 별개 요청으로 본다.

종이와 본문으로 직접 해보기

종이에 폴더 A와 B, 각 폴더의 hello.py를 그린다. 작업폴더 B에서 python ../A/hello.py를 실행한다고 가정하고 화살표로 이동을 표시하라. 이 문제의 /와 .. 경로 표기는 일반적인 파일 경로 해석을 가정한다.

힌트 보기

..는 현재 폴더의 상위 폴더로 이동한다. 먼저 B의 부모를 찾는다.

풀이 보기

B→Study→A→hello.py 순서이다. 최종 파일은 A의 hello.py이며 예상 출력 5이다. 작업폴더를 B로 남긴 채 파일 위치만 A로 지정한 것이다.

오해와 반례

화면에서 열어 놓은 파일이 항상 실행된다.

터미널 명령은 파일 인자로 대상을 지정한다. B 파일을 열었어도 A에서 python hello.py를 하면 A 파일을 읽는 반례가 있다. 편집기 실행 버튼이 작업폴더를 설정하는 방식은 도구별로 다르므로 실제 명령을 기록해야 한다.

REPL과 스크립트

계산기처럼 2+3만 쳤을 때와 파일에 2+3을 적었을 때 화면은 같을까?

준비 개념과 학습 목표

준비 개념

  • 표현식은 값을 계산한다. 2+3의 값은 5이다.

  • 문장은 실행할 동작을 지시한다. x=2는 x라는 이름을 값 2에 연결한다.

학습 목표

  • 대화형 표현식 표시와 print 출력을 구분한다.

  • 한 세션의 이름 상태와 새 스크립트 실행의 상태를 구분한다.

  • 대입을 우변 계산 뒤 이름 연결로 추적한다.

계산기 화면에 값이 보인 것과 프린터가 종이를 낸 것은 같은 동작일까?

기본 REPL은 표현식의 결과를 표시한다. print는 표현식 안에서 출력 효과를 내지만 호출 값은 None이다. 그래서 화면만 보면 같은 12여도 값과 효과의 기록은 다를 수 있다. 스크립트에서는 일반 표현식만 적어 두어도 자동 표시하지 않는다.

이 단원은 순차 실행하는 내장 정수와 새 기본 세션을 가정한다. 이전 입력에서 만든 이름은 같은 세션에는 남지만 새 세션에 저절로 전달되지 않는다. 노트북 커널 같은 유지 환경은 별도다. “처음부터 실행”을 시험하려면 현재 이름 상태부터 정해야 한다.

먼저 확인할 개념
  • 변수와 상태

    이름 재연결과 현재 읽은 값을 추적한다.

  • 프로그램과 프로세스

    저장된 코드와 새 실행의 개인 상태가 다름을 확인한다.

REPL은 입력과 결과를 번갈아 확인한다

REPL은 Read, Evaluate, Print, Loop의 머리글자로, 입력을 읽고 평가한 결과를 표시한 뒤 다음 입력을 기다리는 대화형 방식이다. Python의 기본 대화형 세션은 >>> 프롬프트로 새 입력을 알린다. 프롬프트 자체는 언어 문법이 아니므로 파일에 복사하지 않는다.

대화형에서 2+3이라는 표현식을 입력하면 보통 값 5를 표시한다. print(2+3)은 출력 동작을 수행하여 5를 표시하지만 호출 결과 자체는 None이다. 기본 대화형 실행기는 None을 별도로 표시하지 않으므로 두 입력의 화면이 비슷해도 의미는 다르다.

>>> 2 + 3
5
>>> print(2 + 3)
5

스크립트는 저장된 문장 순서를 따른다

스크립트는 파일에 저장한 문장을 실행하는 방식이다. 파일 속의 2+3만으로는 화면에 결과를 표시하는 동작이 없으므로 print를 써야 한다. 대화형에서 자동으로 값이 보이는 행동을 모든 실행 방식에 일반화하면 안 된다.

기본적인 새 스크립트 실행에서는 이전의 다른 프로세스나 REPL에서 만든 x가 자동으로 넘어오지 않는다. 반면 같은 REPL 세션의 x는 다음 입력에서 사용할 수 있다. 교육용 노트북이나 편집기는 상태를 유지할 수 있으므로 여기서는 기본 Python 실행기와 새 프로세스를 가정한다.

대입은 항등식이 아니라 상태 변화이다

x=x+3은 양변이 영원히 같다는 수학 명제가 아니다. 현재 x의 값을 읽어 우변 x+3을 계산한 다음 x를 새 결과에 연결하는 대입문이다. x가 미리 정의되어 있지 않으면 우변 평가에서 NameError가 생긴다.

x=2 다음 y=x를 실행하면 y도 값 2에 연결된다. 이후 x=x+3은 x를 5에 다시 연결하지만 y를 함께 다시 연결하지 않는다. 이 정수 예제에서 최종 값은 x=5, y=2이다. 가변 객체의 공유는 별도의 문제이며 다음 단원들에서 구분한다.

x = 2
y = x
x = x + 3
print(x, y)

중간 과정을 따라가는 예제

새 Python 3 스크립트에서 x=2; y=x; x=x+3; print(x,y)를 순서대로 실행한다고 가정한다.

  1. x=2: 이름표 x가 값 2를 가리킨다.

  2. y=x: 우변의 현재 값 2에 y도 연결된다.

  3. x=x+3: 2+3=5를 계산한 뒤 x를 5로 바꾼다. y는 2이다.

  4. print의 기본 구분자는 공백이므로 두 값 사이에 공백을 넣는다.

예상 출력은 5 2이며 한 줄 뒤 줄바꿈이 붙는다.

  1. 첫 호출은 12를 출력하고 n을 None에 연결한다.

  2. 두 번째 줄은 None+1을 계산할 수 없어 TypeError다.

  3. n=6*2; print(n); print(n+1)로 값 저장과 출력 효과를 나누면 12와 13이다.

화면 12가 보인다고 n=12인 것은 아니다.

실패한 재대입의 이전 이름

같은 세션에서 x=4가 이미 성공했다. 다음 입력 x=int("four")가 실패한 뒤 x를 관찰하면 무엇인가? 새 세션과 비교하라.

  1. 우변 변환이 ValueError를 내므로 x로 결과를 연결하는 단계에 도달하지 않는다.

  2. 같은 세션의 기존 x=4는 남는다.

  3. 새 세션에서 이 실패만 수행했다면 x는 만들어지지 않았고 이후 조회는 NameError다.

실패한 대입은 기존 이름을 새 값으로 바꾸지 않는다. 세션의 이전 상태를 기록해야 한다.

REPL에서 보이는 모든 값은 스크립트에서도 자동 출력된다.

  • 숫자 7과 문자 '7'은 표기가 비슷해도 종류가 다르다.

  • 문장 순서와 기본 덧셈; 진단: '7'과 '1'을 이어 붙이면 '71', 숫자 덧셈은 8이다.

학습 목표

  • input의 문자열 반환과 int 변환을 구분한다.

  • 문법 오류·NameError·ValueError·TypeError를 원인과 연결한다.

  • traceback을 실패 위치의 증거로 읽는다.

입력칸에 03을 넣으면 개수 3과 원래 표기 03 중 무엇이 남을까?

사람의 한 줄 입력은 문자열로 들어온다. 계산에 필요한 정수와 사람이 입력한 표기는 별도 자료다. int("03")의 결과 3은 선행 0의 개수를 보존하지 않는다. 원래 표기가 필요한 작업은 변환 전 문자열도 남겨야 한다.

오류를 찾을 때는 마지막 예외 이름, 실패 줄, 그 줄의 입력 종류를 함께 본다. 문법 오류는 전체 스크립트 분석을 막을 수 있고, 실행 예외는 앞서 수행한 출력 효과를 되돌리지 않는다. 이 단원은 처리하지 않은 예외에서 진행이 멈추는 단순 순차 예다.

먼저 확인할 개념
  • 입력·처리·출력

    받은 자료와 계산값, 표시 결과가 서로 다른 단계임을 복습한다.

  • 변수와 상태

    실패 전후 이름 상태와 아직 수행하지 않은 사건을 구별한다.

입력은 텍스트에서 출발한다

input('Count? ')는 안내문을 표시하고 한 줄의 입력을 받아 끝의 줄바꿈을 제거한 문자열을 반환한다. 사람이 7을 입력해도 반환값은 정수 7이 아닌 문자열 '7'이다. 숫자 계산이 목적이라면 int로 적절한 정수 텍스트를 변환하는 단계를 명시한다.

int('7')은 7이지만 int('seven')은 ValueError를 일으킨다. 변환할 수 있다는 것과 문제의 유효 입력이라는 것은 별개이다. 예를 들어 개수를 받는다면 int('-2')는 성공하지만 음수 개수 허용 여부는 문제 계약에서 별도로 정해야 한다.

text = input("Count? ")
count = int(text)
print(count + 1)

출력 동작과 반환값을 구분한다

print는 인자를 텍스트 형태로 표시하는 함수이다. 기본적으로 여러 인자 사이에는 공백, 끝에는 줄바꿈을 넣는다. print('Count:', count)는 레이블과 값을 한 줄에 표시한다. 따옴표 안의 count는 이름 조회가 아니라 문자 그대로이므로 print('count')는 값 대신 단어를 표시한다.

출력은 외부에 생기는 효과이며 이후 계산에 사용할 반환값과 같지 않다. print 호출의 반환값은 None이다. n=print(7)을 하면 화면에는 7이 보이지만 n에는 정수 7이 저장되지 않는다. 화면·입력·이름 상태를 각각 다른 기록 칸으로 나누면 이를 알아보기 쉽다.

오류는 어디까지 진행했는지 알려준다

문법 오류는 코드 형태가 언어 규칙을 만족하지 않는 경우이다. 일반적인 스크립트는 실행 전에 전체를 구문 분석하므로 뒤쪽에 괄호 누락이 있으면 앞쪽 print도 실행되지 않을 수 있다. 실행 예외는 문법적으로 유효한 코드가 실제로 실행되는 중 실패하는 경우이다.

없는 이름을 읽는 NameError, 잘못된 정수 텍스트의 ValueError, 문자열과 정수의 덧셈 같은 TypeError는 서로 다른 단서이다. traceback에는 호출 경로와 실패 위치가 보인다. 마지막 예외 이름과 메시지를 먼저 읽고 해당 소스 줄, 그 줄의 입력 종류를 확인한다. 메시지 문구는 버전별로 달라질 수 있으므로 아래에서는 종류와 실패 단계를 예측한다.

위 세 줄에서 사용자가 7을 입력하는 경우와 seven을 입력하는 경우를 비교한다.

  2. print는 8과 줄바꿈을 표시한다. 안내문 Count? 는 그보다 앞에 표시된다.

  2. 기본 print는 03과 3 사이에 공백을 넣어 03 3을 표시한다.

  3. "3", "03", "003"이 같은 정수 3으로 바뀌므로 정수만으로 원래 표기를 결정하지 못한다.

문법 실패와 실행 실패의 출력

A는 print("begin"); int("bad"); print("done")이고 B는 마지막 줄의 닫는 괄호가 빠진 일반 스크립트다.

  1. A는 구문 분석이 가능하므로 begin을 출력한 뒤 ValueError로 멈춘다. done은 실행되지 않는다.

  2. B는 전체 구문 분석에서 SyntaxError가 나므로 begin도 실행하지 않는다.

  3. 이 비교는 한 번에 분석하는 보통 스크립트이며 REPL의 앞선 입력까지 되돌린다는 뜻이 아니다.

A에는 begin 출력 효과가 남고 B에는 이 스크립트의 출력 효과가 없다.

계산 결과가 같다는 사실만으로 두 계산법이 같은 일을 했을까?

요구사항을 작은 계약으로 나누면 계산식의 단위를 검사할 수 있다. 이번 문제는 한 개 가격 p, 개수 c, 전체 한 번 할인 d로 총액 pc−d를 구한다. 가격에서 할인을 먼저 빼는 식은 전체 할인이 아닌 개당 할인이라는 다른 뜻이다.

실행 기록은 값 하나의 승인 도장이 아니다. 예상값과 관측값을 나누고 조건이 달라지는 입력을 비교한다. 현재 활동은 정수 p≥0, c≥1, 0≤d≤pc, 순차 실행, 외부 부작용 없음이라는 계약이다. 실제 영수증 시스템이나 통화 규칙을 완성하지 않는다.

  5. 선행 0이 있는 "02"는 정수 2로 바뀌어 계산값은 같지만 원래 표기는 별도 보존해야 한다.
