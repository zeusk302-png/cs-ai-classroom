소단원 4.1

if·elif·else

여러 조건이 동시에 맞을 때 컴퓨터는 어느 설명을 선택할까?

준비 개념과 학습 목표

준비 개념

  • 변수 대입 score=85는 값 저장이고 score==85는 같은지 비교하는 식이다. 이 단원은 bool·문자열·사용자 객체를 제외한 내장 int 점수를 가정한다.

  • 참과 거짓은 조건의 판정이다. <와 <=는 경계 포함이 다르다. 0<=score<=100은 양쪽 경계를 모두 포함한다.

  • 들여쓰기는 같은 분기에 속하는 문장 묶음을 나타낸다. 콜론 다음 줄의 묶음과 묶음 밖 print를 구별한다.

학습 목표

  • 첫 참 조건만 선택하는 if·elif·else를 추적한다.

  • 점수 범위·경계와 분기 순서가 결과에 미치는 영향을 설명한다.

  • 거짓인 값과 단락 평가를 오류 예방 조건과 연결한다.

잔액이 0이면 값이 없는 것일까, 아니면 제대로 조회한 0일까?

잔액 balance의 계약을 None이면 조회 실패, 내장 int 0 이상이면 조회 성공으로 정하자. 두 경우 모두 if balance에서는 거짓이지만 업무 의미는 다르다. if balance is None으로 실패를 먼저 나누고, 성공한 정수에서는 balance==0을 별도로 판정해야 한다.

결과를 하나 고르는 연쇄와 알림 여러 개를 실행하는 독립 if를 구분한다. 경고를 포함한 잔액 분류를 실패/음수/빈 잔액/사용 가능으로 나누면 첫 참 분기는 뒤 조건을 평가하지 않는다. 아래는 순차 고정 값이며 실제 은행·권한 검증은 아니다.

검사 순서는 오류 가능 연산도 결정한다. a가 고정 목록이고 i가 내장 int이면 0<=i<len(a) and a[i]>0은 비음수 범위를 통과한 경우만 항목을 읽는다. Python이 음수 인덱스를 허용한다는 규칙과 이 문제에서 음수 위치를 거절한다는 계약은 별개다.

먼저 확인할 개념
  • bool 판정과 자료 의미

    0의 거짓 판정과 조회 실패를 동일시하지 않는다.

  • 현재 이름의 바인딩

    분기에서 재대입한 label을 이후 줄이 읽는다.

한 줄씩 고르는 규칙

if는 조건을 검사하고 참이면 들여쓴 문장 묶음을 실행한다. elif는 앞 조건들이 거짓일 때만 검사한다. else가 있으면 모든 앞 조건이 거짓일 때 실행한다. 한 연쇄에서는 최대 한 묶음을 실행하며, else가 없고 모두 거짓이면 아무 묶음도 실행하지 않는다.

본문 예시는 먼저 0~100 범위 밖을 invalid로 고른다. 유효한 점수는 90 이상 gold, 그보다 작고 80 이상 silver, 나머지 practice다. 범위 확인은 자료형 변환이 아니다. 문자열을 숫자로 바꾸거나 입력 오류를 처리하는 코드는 여기 없으며 정수라는 계약을 벗어난 값을 안전하게 검증한다고 주장하지 않는다.

순서는 결과를 바꾼다

95는 >=90와 >=80을 모두 만족한다. 높은 경계를 먼저 둔 연쇄는 gold를 고른 뒤 silver 조건을 검사하지 않는다. >=80을 먼저 쓰면 95도 silver가 되고 뒤의 >=90 분기는 도달할 수 없다. 구간의 겹침과 첫 선택 규칙을 함께 확인해야 한다.

독립된 if 두 개는 연쇄와 다르다. 처음에 95에 gold를 대입해도, 다음 독립 if score>=80이 silver를 다시 대입할 수 있다. 독립 행동 둘을 모두 해야 하는 문제에서는 별도 if가 적절할 수 있다. 분류 하나를 고르는 문제인지 행동 여러 개를 실행하는 문제인지 먼저 정한다.

참 판정과 안전한 검사 순서

내장 값 None, False, 수0과 빈 문자열·빈 목록은 조건에서 거짓이다. 음수 -1은 0이 아니므로 참이다. 값이 없다는 의미와 숫자0이라는 의미가 같은 것은 아니다. and와 or는 항상 bool로 변환해 반환하지 않고 선택된 피연산자를 반환한다. 예를 들어 0 or 7의 값은 7이다.

and는 왼쪽이 거짓이면 오른쪽을 평가하지 않는다. 정수 n에 대해 n!=0 and 10//n>=2는 n=0일 때 나눗셈을 건너뛴다. 반대로 나눗셈 조건을 먼저 두면 같은 보호가 없다. 이 설명은 해당 나눗셈의 0분모만 피한다는 뜻이며 임의 객체·다른 연산 오류까지 해결한다는 보장은 아니다.

중간 과정을 따라가는 예제

고정 정수 score=85를 네 구간으로 분류하는 전체 코드를 추적하라. 

score = 85
if not 0 <= score <= 100:
    label = "invalid"
elif score >= 90:
    label = "gold"
elif score >= 80:
    label = "silver"
else:
    label = "practice"
print(label)

  1. 85는 0<=85<=100을 만족하므로 not 조건은 거짓이고 invalid 묶음을 건너뛴다.

  2. 85>=90은 거짓이므로 gold 묶음을 건너뛴다.

  3. 85>=80은 참이므로 label에 silver를 저장한다. 이어지는 else는 실행하지 않는다.

  4. 연쇄 밖 print(label)은 silver와 줄바꿈을 출력한다. 고정 입력의 실제 실행 출력도 silver였다.

silver 한 줄이다. 정수 입력 계약과 위 분기 순서에 따른 결과다.

조건을 바꾸어 비교하기

기본값을 넣는 or가 0을 지운다

balance=0에서 shown=balance or 10과 None일 때만 10을 넣는 설계를 비교하라.

  1. 0은 거짓이므로 or는 10을 반환한다.

  2. 0은 None이 아니므로 if balance is None: shown=10 / else: shown=balance 설계는 0을 보존한다.

  3. balance=None이면 두 설계 모두 10이지만 한 입력의 일치가 동일한 계약을 뜻하지 않는다.

정상 잔액 0을 보존하려면 None을 명시적으로 검사한다.

비교할 점

기본 본문의 점수 경계에서 실제 값의 부재 정책으로 분기 목적을 옮긴다.

항목 읽기보다 범위 검사가 먼저

a=[3], i=1 및 i=−1에서 0<=i<len(a) and a[i]>0을 추적하라.

  1. i=1은 1<1이 거짓이므로 a[1]을 읽지 않는다.

  2. i=−1은 0<=−1이 거짓이므로 a[−1]을 읽지 않는다.

  3. a[i]>0을 먼저 쓰면 i=1에서 IndexError이고 i=−1은 실제 마지막 항목 3을 읽어 계약과 다른 결과가 된다.

두 위치는 False로 거절하고 오류 가능 조회를 건너뛴다.

한 단계 더

심화: 정수 점수 전체를 범위 밖, [90,100], [80,89], [0,79] 네 집합으로 나누자. 각 집합은 서로 겹치지 않으며 모든 정수는 정확히 하나에 속한다. 범위 밖 검사 후 첫 참 선택이 이 집합에 맞는 label을 고르는지 각 경우로 증명할 수 있다. 반면 조건 score>=80과 score>=90 자체는 겹친다. 연쇄의 실제 선택 영역은 앞 조건들이 거짓이라는 조건까지 포함해야 한다. 이는 내장 정수·정상 비교·예외 없는 실행이라는 전제 아래의 분류 증명이며 일부 점수 실행만으로 모든 자료형의 안전성을 증명한 것이 아니다.

2,4,6,8을 더할 때 반복은 어디서 멈춰야 할까?

준비 개념과 학습 목표

준비 개념

  • 누적 변수 total+=i는 total에 현재 i를 더해 저장한다. 처음 값을0으로 정해야 덧셈의 시작 상태가 있다.

  • 한 번의 반복은 본문의 한 차례 수행이다. while은 본문 전 조건을 검사하므로 처음부터 거짓이면 본문0회다.

  • 목록은 순서 있는 값들의 모음이고 for는 반복 가능한 대상에서 차례로 값을 받는다. range는 내장 정수의 규칙적인 순서열을 표현한다.

학습 목표

  • while의 검사·본문·갱신 순서를 추적한다.

  • range의 시작·끝 제외·방향·0간격 오류를 구별한다.

  • 유한 반복의 진행과 종료를 조건 아래 설명한다.

for 안에서 i를 바꾸면 다음 순회 위치도 바뀔까?

종이에 숫자 카드 0,1,2를 놓고 하나씩 받는 사람을 떠올리자. 받은 카드에 100이라고 새로 이름을 붙여도 카드 공급자는 다음 카드 1을 준다. for의 이름 i에 대입하는 일과 iterator가 다음 값을 정하는 일은 구별된다.

while은 검사에 쓰는 상태를 본문이 갱신한다. 따라서 i=100으로 바꾼 값은 다음 i<3 판정에 직접 쓰인다. 두 반복의 끝나기 이유가 다르므로 같은 시작 이름만 보고 교환하지 않는다. 고정 유한 range와 종료하는 본문만 다룬다.

반복 횟수와 최종 이름 값도 다른 관찰이다. 비어 있는 for는 i를 새로 대입하지 않는다. 미리 i=77이었다면 그대로이고, 미리 정의하지 않았다면 그 후 i를 읽는 것은 별도 이름 오류다. while의 최종 i는 실패한 조건 검사 시점의 상태다.

먼저 확인할 개념
  • 이름 재바인딩

    본문 대입과 다음 제공 값의 새 대입을 추적한다.

  • 중간 상태와 실행 기록

    반복 차례마다 검사·합·다음 위치를 따로 기록한다.

조건을 다시 묻는 while

while i<9는 현재 i가9보다 작은 동안 본문을 실행한다. 본문 뒤 다시 같은 조건을 검사한다. i=2에서 i+=2로 갱신하면 검사값은2,4,6,8,10이며10에서 멈춘다. 종료 뒤 i는8이 아니라10이다.

조건이 언젠가 거짓이 되는 진행을 확인해야 한다. 갱신을 빼면 i가2로 고정되어 합만 계속 커질 수 있다. while 자체가 정해진 횟수나 종료를 보장하지 않는다. 실제 코드의 예외·외부 변화도 종료 이유가 될 수 있지만 여기서는 고정 정수·정상 연산만 다룬다.

for와 range의 계약

for i in range(2,9,2)는2에서 시작해2씩 증가하고9보다 작은2,4,6,8을 차례로 제공한다. stop은 포함하지 않는다. range(3)은0,1,2를 나타내며 range(4,4)는 비어 있다. range는 목록 전체를 미리 만들어 반환하는 함수가 아니라 정수 순서열을 표현하는 별도 객체다.

간격이 음수면 값은 감소하며 stop보다 커야 한다. range(9,1,-2)는9,7,5,3이다. 방향이 맞지 않는 range(2,9,-1)는 비어 있고 step=0은 ValueError다. 이 단원 인수는 내장 int로 제한한다. 실제 range는 정수 인덱스 변환 계약을 지원하는 객체도 받으므로 모든 사용자 객체를 여기서 다룬 것은 아니다.

두 반복을 비교하는 기준

for의 반복변수는 다음 제공 값으로 다시 대입된다. 본문 안에서 i=100으로 바꾸어도 그 대입만으로 range의 다음 제공 값이 바뀌지는 않는다. 반면 while은 바꾼 i를 다음 조건 검사에서 사용한다. 두 문법의 갱신 책임이 다르다.

유한 range를 정상 소진하고 매 본문도 끝나면 for가 끝난다. 모든 for 대상이 유한한 것은 아니고 본문 안에 끝나지 않는 반복이 있으면 유한 입력도 충분하지 않다. 아래 두 프로그램은 외부 입력이나 목록 변경 없이 네 값만 더하므로 같은 합을 얻는다. 동일 합이라는 사실만으로 모든 while을 for로 바꾸어도 의미가 같다는 일반 법칙은 아니다.

중간 과정을 따라가는 예제

for와 while로 같은 네 수를 누적하는 전체 코드를 추적하라. 

for_total = 0
for i in range(2, 9, 2):
    for_total += i
while_total = 0
i = 2
while i < 9:
    while_total += i
    i += 2
print(for_total, while_total)

  2. while_total=0,i=2로 별도 초기화한다. 첫 검사 참이며2를 더한 뒤 i=4다.

  3. 다음 반복들에서4,6,8을 더해 합6,12,20이 되고 각각 i=6,8,10으로 갱신된다.

  4. i=10에서10<9는 거짓이다. print는20 20과 줄바꿈을 출력하며 보존 코드의 실제 출력과 일치했다.

두 합은 모두20이다. while의 최종 i=10, for의 마지막 제공 값8을 구별한다.

이름 변경은 for 공급자를 바꾸지 않는다

total=0; for i in range(3): total+=i; i=100을 각 문장이 본문에 있도록 추적하고 같은 갱신의 while과 비교하라.

  1. for는 0/1/2를 받아 합 0/1/3이고 최종 i=100이다.

for는 3회 실행해 합 3, while은 1회 실행해 합 0이다.

소단원 4.3

break·continue와 반복설계

음수는 건너뛰되0을 만나면 멈추는 규칙을 어떻게 구별할까?

준비 개념과 학습 목표

준비 개념

  • continue는 지금 반복 본문의 남은 문장을 건너뛰고 다음 반복으로 진행한다. break는 가장 가까운 반복 하나를 종료한다.

  • 표지값0은 이 문제에서 중단 신호로 정한 값이다. 모든 문제에서0을 건너뛰거나 종료해야 한다는 뜻은 아니다.

  • 반복 else는 if else와 역할이 다르다. for의 다음 값이 없어 정상 소진되면 수행되고 break로 나가면 수행되지 않는다.

학습 목표

  • 건너뛰기와 반복 전체 중단을 자료 추적으로 구별한다.

  • 반복 else와 빈 입력의 결과를 설명한다.

  • continue가 while의 진행 갱신을 건너뛰는 종료 오류를 찾는다.

목록을 다 검사했음을 else로 표시할 때, 못 찾았다는 결론은 언제 정당할까?

for 뒤 else는 소진의 표시이지 if의 거짓 분기가 아니다. 찾으면 break하는 검색에서는 소진했다는 사실과 못 찾았다는 의미가 맞물린다. 하지만 찾은 뒤 continue하면 소진까지 진행하므로 else도 실행한다. 문법의 종료 사건과 문제의 결과를 따로 적자.

아래 탐색은 고정 int 목록, target int, 첫 일치만 필요하다는 계약이다. 일치에서 break하면 else를 미발견 표시로 쓸 수 있다. 전체 합도 필요한 문제라면 이 중단 방식이 그 결과를 버릴 수 있으므로 다음 소단원과 비교한다.

while에서는 continue가 조건 재검사로 돌아간다. 갱신이 그 뒤에만 있으면 특정 값에 갇힐 수 있다. 위험한 반복을 실제 돌려 확인할 필요 없이 같은 상태가 다음 검사에 다시 돌아오는 표로 종료 실패를 설명할 수 있다.

먼저 확인할 개념
  • 조건 재검사와 다음 값 공급

    continue가 돌아가는 지점을 while과 for에서 구별한다.

  • 현재 상태의 덮어쓰기

    진행 갱신을 건너뛴 상태가 다음 검사의 입력이다.

현재 차례를 버리기와 멈추기

목록 [2,-1,4,0,8]에서 음수는 누적하지 않고 다음 값을 보고,0은 종료 신호,양수는 합에 더한다. -1의 continue는 뒤의0검사와 누적을 건너뛰지만4를 살펴볼 기회는 남긴다. 0의 break는8을 전혀 방문하지 않게 한다.

break와 continue는 가장 가까운 둘러싼 반복에 적용된다. 반복이 두 겹이면 안쪽 break가 바깥 반복까지 자동 종료시키지 않는다. 여러 반복을 종료하려면 별도의 제어 설계가 필요하다. 여기서는 한 겹의 고정 유한 목록만 사용한다.

소진을 표시하는 else

for 뒤에 정렬된 else는 값이 더 없어져 정상 소진될 때 실행된다. 예시는 그때 outcome="exhausted"를 저장한다. 0분기에서는 먼저 outcome="stopped"를 저장한 뒤 break로 나가므로 else를 건너뛴다. 빈 목록도 바로 소진되어 else를 수행하고 outcome을 저장한다.

continue만 사용했다고 else가 없어지는 것은 아니다. 마지막 값에서 continue를 만나더라도 다음 값이 없다면 else에 도달할 수 있다. 반복을 포함하는 함수의 return이나 처리되지 않은 예외로 빠져나가는 것은 정상 소진과 다르며 else를 실행하지 않는다. 본 예시에는 함수 return과 예외를 일부러 만들지 않았다.

진행이 모든 길에 있어야 한다

while i<3에서 i=0으로 시작해 if i==1: continue를 쓰고 그 뒤에만 i+=1을 두었다고 종이에 생각해 보자. i0에서는1로 갱신하지만 다음 i1에서는 continue가 갱신을 건너뛴다. 이후 i가1에 고정되므로 정상 종료하지 않는다. 이 무한 반복 반례는 실행하지 않는다.

수정할 때는 continue를 만나는 경로에도 진행을 보장해야 한다. 예컨대 현재 항목을 별도로 저장하고 인덱스를 먼저 증가시킨 뒤 그 항목의 제외 조건을 검사할 수 있다. 갱신 위치를 이동하면 어떤 항목을 검사하는지도 달라질 수 있으므로 현재 값과 다음 위치를 분리해 추적한다. break 경로는 그 자리에서 반복을 끝내므로 다음 갱신이 필수는 아니다.

중간 과정을 따라가는 예제

음수는 제외하고 첫0에서 중단하는 전체 코드를 추적하라. 

total = 0
for value in [2, -1, 4, 0, 8]:
    if value < 0:
        continue
    if value == 0:
        outcome = "stopped"
        break
    total += value
else:
    outcome = "exhausted"
print(total, outcome)

  2. value-1은 첫 조건에서 continue하여 total2를 유지한다. value4는 정상 누적되어 total6다.

  3. value0은 음수 조건이 거짓이고0조건이 참이다. outcome에 stopped를 저장하고 break한다.

  4. value8은 방문하지 않으며 else도 실행하지 않는다. 출력6 stopped와 줄바꿈은 실제 보존 코드의 출력과 같다.

심화: 0이 없는 방문 접두 부분에서 total은 그 부분의 양수만 더한 합이라는 불변식을 증명하라. 빈 접두의 합은0이다. 다음 값이 음수면 continue가 합을 유지하고, 양수면 그 값을 더해 불변식을 유지한다. 0이면 합을 바꾸지 않고 중단하므로 첫0 앞의 양수 합이 최종값이다. 0이 없다면 전체 목록을 소진하여 전체 양수 합을 얻는다. 목록이 고정 유한하고 각 본문이 끝나므로 방문 수는 목록 길이 이하이며 종료한다. 이 근거는 앞의 잘못된 while처럼 갱신을 건너뛰는 구조에 그대로 적용할 수 없다. 목록 변경·예외·다른 표지값 의미를 추가하면 전제를 다시 정한다.

소단원 4.4

누적·탐색·경계 사례

0번 위치에서 찾은 결과와 아직 찾지 못한 상태를 어떻게 구별할까?

준비 개념과 학습 목표

준비 개념

  • a[i]는 목록 a의 위치 i 값을 읽는다. 길이 n의 정상 비음수 인덱스는0부터 n-1이다. 이 예시는 실행 중 목록을 바꾸지 않는다.

  • None은 여기서 아직 찾지 못했다는 상태 표지다. first is None으로 검사한다. 숫자0은 유효한 첫 위치이고 값0과 위치0은 다른 의미다.

  • 전체 합·방문 수·첫 일치 위치는 서로 다른 결과다. 합과 수를 끝까지 계산하려면 첫 일치 이후에도 나머지 항목을 방문해야 한다.

학습 목표

  • 누적합·방문 수·최초 일치 위치를 동시에 추적한다.

  • 빈 목록·중복 일치·일치 없음·인덱스0의 경계 사례를 설명한다.

  • 불변식과 종료 조건으로 전체 입력 범위의 주장과 일부 실행을 구별한다.

찾은 값 하나만 반환하는 함수와 전체 통계를 만드는 함수는 어디서 갈라질까?

주문 목록에서 첫 무료 상품의 위치와 전체 금액을 함께 원한다고 하자. 첫 무료를 발견한 순간 break하면 위치는 맞아도 뒤 상품 금액은 빠진다. 서로 다른 결과마다 어느 입력을 필요로 하는지 따로 판단한다.

first=None은 아직 일치가 없음을 표시하고 위치 0도 정상 결과로 남긴다. 합은 전체 목록, first는 최초 일치 이후 고정이라는 두 갱신 규칙을 동시에 유지한다. 항목 값 0과 위치 0은 같은 숫자여도 역할이 다르다.

처음/중간/마지막/부재/빈 목록은 오류 발견의 서로 다른 기회다. 시험 기록은 어떤 경우를 실제 실행했는지 보여주며 모든 입력의 증명은 접두 불변식으로 따로 세운다. 아래는 고정 유한 내장 int 목록과 정상 연산만 가정한다.

먼저 확인할 개념
  • 출력 계약과 처리 분해

    첫 위치와 전체 합이 서로 다른 출력 책임임을 정한다.

  • 순서열의 위치와 값

    항목 값과 0부터 시작하는 인덱스를 따로 읽는다.

값과 위치를 따로 기록하기

a=[0,3,0],target=0에서 일치는 위치0과2에 있다. 첫 위치는0이다. first=None으로 시작하여 first is None and value==target일 때만 현재 i를 저장한다. 이미 첫 일치를 저장했으면 나중의 같은 값으로 덮어쓰지 않는다.

if not first를 사용하면 first0도 거짓으로 판정하여 아직 못 찾은 상태로 오해할 수 있다. is None은 이 상태 표지만 검사한다. target0의 값이 거짓이라고 해서 검색 대상이 아닌 것은 아니다. 비교 value==target이 일치 여부를 결정한다.

합과 수는 검색과 다른 책임이다

total은 방문 값들의 합,count는 방문 개수다. 첫 일치를 찾았다는 이유로 break하면 전체 합과 개수를 완성하지 못한다. 예시에서는 검색 저장 조건만 멈추고 for 자체는 모든 위치를 소진한다. 길이가 n인 고정 목록에서 range(len(a))는0부터 n-1까지 제공한다.

빈 목록에서는 본문0회이므로 total=0, count=0, first=None이 유지된다. 일치 없는 비어 있지 않은 목록도 first=None이다. 이 상태에서 a[first]를 무조건 읽으면 올바른 인덱스가 아니다. 결과를 쓰기 전 None 여부를 확인한다. -1을 미발견 표지로 쓰더라도 Python의 실제 a[-1]은 마지막 요소를 뜻하므로 무검사 조회는 위험하다.

경계 사례와 증명은 다른 근거다

빈 목록·첫 위치·마지막 위치·중복·부재를 따로 살펴보면 초기화와 비교 오류를 발견하기 쉽다. 그러나 몇 목록의 출력이 맞았다는 사실만으로 모든 목록의 정확성을 증명하지는 않는다. 어떤 상태가 매 반복에서 유지되는지 설명해야 한다.

여기서는 고정 유한 내장 int 목록과 내장 int target,정상 연산과 충분한 실행 자원을 전제한다. 본문은 항상 끝나고 인덱스는 range로 제한된다. 사용자 비교 메서드·목록 동시 변경·자원 고갈은 계약 밖이다. 뒤에서 탐색 알고리즘의 비용을 분석할 때도 방문 횟수 n과 정수 비트 크기에 따른 연산 비용을 자동 동일시하지 않는다.

  1. total=접두 합, count=k, first=접두 최소 일치 위치 또는 None이다.

  2. 새 값을 더하고 count를 1 증가시킨다. 이전 일치가 있으면 유지하며, 없고 새 값이 일치하면 k를 저장한다.

초기 k=0과 갱신을 거쳐 k=n에서 전체 요구를 얻는다.

풀이와 답 확인

  1. i=0의 값 4는 low로 합 4, 개수 1이다. i=1의 값 −2는 제외한다.

  2. i=2의 값 0은 free로 합 4, 개수 2, first=2다. i=3의 값 7은 high로 합 11, 개수 3이다.

  3. i=4의 값 0은 free로 개수 4가 되고 first=2를 유지한다. i=5의 값 5는 high로 합 16, 개수 5다.
