小節 1.1

ファイル・作業フォルダ・実行コマンド

hello.py という名前のファイルが2つあるとき、コンピュータはどちらを実行するでしょうか。

準備する概念と学習目標

準備する概念

  • ファイルは名前を付けて保存した内容で、フォルダはファイルをまとめる場所です。
  • 準備の確認：学校/教室/机という住所で、最後の名前だけで机を探せるでしょうか。同じ名前が複数の場所にあるなら、全体の位置が必要です。

学習目標

  • ソースファイル・インタープリタ・作業フォルダを区別する。
  • 相対パスと作業フォルダを組み合わせ、実行するファイルを決める。
  • 実行記録にコマンドと場所を両方残す。

テキストと実行プログラムの役割は異なる

hello.py は Python の文を保存するテキストファイルです。拡張子は用途を示す慣習であり、保存しただけで文が自動実行されるわけではありません。インタープリタはファイルを読み、言語規則に従って処理するプログラムです。エディタはテキストを変更し、ターミナルはコマンドを渡す窓です。3つの役割を区別します。

紙上の活動ではソースと入力を自分で読み、結果をたどれば十分です。任意のコンピュータ実習では Python 3 がすでに使える環境でコマンドを使います。python、python3、Windows の py は環境によって実行プログラムの選択方法が異なるため、名前だけで同じバージョンと決めつけません。

# hello.py に保存するソース
print("Ready")

相対パスの出発点は作業フォルダ

作業フォルダ、つまりカレントディレクトリは、現在のコマンドの基準になる場所です。相対パス hello.py はその中のファイルを指し、絶対パスはドライブやルートから位置を指定します。作業フォルダが変われば、同じコマンドでも別のファイルを選んだり、見つからなくなったりします。

例えば C:\Study\A と C:\Study\B にそれぞれ hello.py があるなら、C:\Study\A で python hello.py を実行すると A のファイルを読みます。エディタで B のファイルを開いているだけでは、コマンドの作業フォルダは B になりません。スクリプト内部の相対パスによるデータアクセスも通常は作業フォルダが基準で、ソースのフォルダに自動では切り替わりません。

コマンドを分けて記録する

python hello.py の先頭は実行するインタープリタ、次はそこに渡すファイル引数です。パスに空白があるなら引用符で囲み、シェルが複数の引数に分けないようにします。シェルコマンドと Python の文は文法が異なるため、同じ入力欄に混ぜると失敗することがあります。

PowerShell の Get-Location で場所を、python --version でバージョンを調べるのは任意の実習です。場所・ソース内容・コマンド・入力・結果をまとめて記録すれば、他の人が条件を再現できます。ファイルが見つからないという表示はこの段階の問題で、print の計算結果が違うという意味ではありません。

# 任意の実習：PowerShell に入力
Get-Location
python --version
python ".\hello.py"

途中の過程をたどる例題

C:\Study\A\hello.py は print(2+3)、C:\Study\B\hello.py は print(9) を含む。作業フォルダは A で、Python 3 が使えるとする。python hello.py が読むファイルと予想出力は何か。

  1. ファイル引数は相対パス hello.py。
  2. 作業フォルダ A と組み合わせると C:\Study\A\hello.py。
  3. そのファイルでは 2+3=5 を計算し、print が1行に表示する。

A のファイルを実行し、予想出力は 5。B を編集中でも、このコマンドのパスは変わりません。

紙と本文で試してみよう

紙にフォルダ A、B と各 hello.py を描こう。B を作業フォルダとして python ../A/hello.py を実行すると仮定し、パスの移動を矢印で示そう。本問では通常のパス解釈を使い、/ は区切り、.. は親ディレクトリを表す。

ヒントを見る

.. は現在のフォルダの親へ移る。まず B の親を探そう。

解答を見る

B→Study→A→hello.py の順です。最後のファイルは A の hello.py なので予想出力は 5。作業フォルダは B のままで、ファイル位置だけ A と指定しています。

よくある誤解と反例

画面で開いているファイルが必ず実行される。

ターミナルコマンドはファイル引数で対象を選びます。B を開いていても A で python hello.py を使えば A を読みます。エディタの実行ボタンが作業フォルダをどう設定するかはツールによるので、実際のコマンドを記録します。

理解を確かめる

ソースファイルと Python インタープリタは同じものか。

答えと理由を見る

違う。ソースは処理するテキスト、インタープリタはそれを処理するプログラム。

役割が異なるため、ソースがあってもインタープリタがなければ実行できません。

作業フォルダを B に変えて python hello.py を実行したときの予想出力は何か。

答えと理由を見る

9

同じ相対パスが B のファイルを指します。

ソースを絶対パスで指定すると環境の問題はすべて解消するか。

答えと理由を見る

解消しない。

ファイル選択は明確でも、バージョン・入力・依存ファイル・権限は異なる可能性があります。

もう一歩先へ

両方のフォルダに同名の data.txt もあるとします。B から A のスクリプトを絶対パスで実行し、内部で open('data.txt') を使うと、通常は B の data.txt を探します。ソース位置と作業フォルダを分けて描こう。ファイル読み取りの構文は後の単元で学びます。

小節 1.2

REPL とスクリプト

電卓のように 2+3 を直接入力した場合と、ファイルに 2+3 と書いた場合、画面は同じになるでしょうか。

準備する概念と学習目標

準備する概念

  • 式は値を計算します。2+3 の値は 5 です。
  • 文は実行する動作を指示します。x=2 は名前 x を値 2 に結び付けます。

学習目標

  • 対話的な式の表示と print の出力を区別する。
  • 1つのセッションの名前と値の対応と新しいスクリプト実行の状態を区別する。
  • 代入を右辺の計算と名前の結び付けとして追跡する。

REPL は入力と結果を交互に確認する

REPL は Read、Evaluate、Print、Loop の略で、入力を読み、評価結果を表示して次の入力を待つ対話形式です。Python の基本対話セッションは >>> で新しい入力を待っていることを示します。このプロンプトは Python の文法ではなく、ファイルにコピーしません。

対話形式で 2+3 という式を入力すると、通常は値 5 が表示されます。print(2+3) は出力動作で 5 を表示しますが、呼び出し自体の戻り値は None です。既定の対話インタープリタは None を別途表示しないので、画面が似ていても意味は異なります。

>>> 2 + 3
5
>>> print(2 + 3)
5

スクリプトは保存された文の順序に従う

スクリプトはファイルに保存された文を実行します。ファイルに 2+3 だけを書いても結果を表示する動作がないため、print を使います。対話形式の自動表示をすべての実行方法に一般化しません。

通常の新しいスクリプトプロセスには、別のプロセスや REPL で作った x は自動で引き継がれません。一方、同じ REPL セッションの x は次の入力で使えます。学習用ノートブックやエディタは状態を保持する場合がありますが、ここでは基本の Python インタープリタと新規プロセスを仮定します。

代入は恒等式ではなく状態変化

x=x+3 は両辺が永遠に等しいという数学の命題ではありません。現在の x を読み、右辺 x+3 を計算し、x を結果へ結び直す代入文です。x が事前に定義されていなければ、右辺の評価で NameError が起きます。

x=2 の後に y=x を実行すると、y も値 2 に結び付きます。その後 x=x+3 は x を 5 に結び直しますが、y は同時には結び直しません。この整数例では最終的に x=5、y=2。変更可能なオブジェクトの共有は別の問題で、後の単元で区別します。

x = 2
y = x
x = x + 3
print(x, y)

途中の過程をたどる例題

新しい Python 3 スクリプトで x=2; y=x; x=x+3; print(x,y) を順に実行するとする。

  1. x=2：名前 x は値 2 を指す。
  2. y=x：右辺の現在値 2 に y も結び付く。
  3. x=x+3：2+3=5 を計算して x を 5 に変える。y は 2 のまま。
  4. print の既定の区切りは空白なので、2つの値の間に空白を置く。

予想出力は 5 2 で、その後に改行があります。

紙と本文で試してみよう

紙に名前 x、y と値の箱を描き、x=4; y=x; x=1; print(y) をたどろう。REPL を終了して新しく起動し、y だけ入力した場合の問題も予想しよう。

ヒントを見る

再代入で、以前の値に付いたすべての名前を動かすわけではない。

解答を見る

x=4 で x→4、y=x で y→4、x=1 で x→1 となり、y→4 は残ります。予想出力は 4。新しい基本 REPL には y の結び付きがないので NameError が予想されます。

よくある誤解と反例

REPL に見える値はスクリプトでもすべて自動表示される。

2+3 だけのスクリプトは値を計算しても表示しません。明示的な出力は print などの動作で作り、対話形式の自動表示と区別します。

理解を確かめる

スクリプトに >>> を入れる必要があるか。

答えと理由を見る

ない。

基本 REPL のプロンプトであり、コードではありません。

x=8; y=x; x=9; print(y) の予想出力は何か。

答えと理由を見る

8

x の結び直しは y を結び直しません。

新しいスクリプトの最初の行 x=x+1 は必ず x を 1 にするか。

答えと理由を見る

しない。この仮定では NameError。

右辺で x を読む前に名前が定義されている必要があります。

もう一歩先へ

x=2; y=x; x=x+3 と x=2; x=x+3; y=x を比較しよう。結果はそれぞれ (5,2) と (5,5)。文を名前→値の状態変換と考え、変換の合成順序を交換できないことを説明しよう。

小節 1.3

出力・入力・エラーメッセージ

人が数字 7 を入力したのに、プログラムはなぜ 7+1 の計算を拒むことがあるのでしょうか。

準備する概念と学習目標

準備する概念

  • 数値 7 と文字列 '7' は似て見えても型が異なります。
  • 文の順序と基本の足し算。準備の確認：'7' と '1' の連結は '71'、数の加算は 8。

学習目標

  • input の文字列返却と int による変換を区別する。
  • 構文エラー・NameError・ValueError・TypeError を原因と結び付ける。
  • traceback を失敗位置の証拠として読む。

入力はテキストから始まる

input('Count? ') は案内を表示し、1行を受け取り、末尾の改行を除いた文字列を返します。7 を入力しても、戻り値は整数 7 ではなく文字列 '7'。数値計算なら、適切な整数テキストを int で変換する段階を明示します。

int('7') は 7 ですが int('seven') は ValueError を起こします。変換できることと問題の有効な入力であることは別です。例えば int('-2') は成功しますが、負の個数を許すかは問題の約束で別に定めます。

text = input("Count? ")
count = int(text)
print(count + 1)

出力の動作と戻り値を区別する

print は引数をテキストとして表示します。既定では複数引数の間に空白、最後に改行を入れます。print('Count:', count) はラベルと値を1行に表示します。引用符内の count は名前を調べずそのままの文字なので、print('count') は値ではなく単語を表示します。

出力は外部への効果であり、後の計算に使う戻り値とは別です。print の戻り値は None。n=print(7) では画面に 7 が見えますが、n に整数 7 は入りません。画面出力・入力・名前と値の対応を別の記録欄にすると、違いを見つけやすくなります。

エラーはどこまで進んだかを示す

構文エラーはコードの形が言語規則を満たさない場合です。通常のスクリプトは実行前に全体を構文解析するため、後半の括弧不足で前半の print も実行されない場合があります。実行時例外は構文が有効なコードが動作中に失敗する場合です。

未定義の名前の NameError、不適切な整数テキストの ValueError、文字列と整数の加算の TypeError は異なる手掛かりです。traceback は呼び出し経路と失敗位置を示します。まず最後の例外名とメッセージを読み、ソース行と入力の型を確認します。文言はバージョンで変わるため、ここでは種類と失敗段階を予測します。

途中の過程をたどる例題

上の3行で、利用者が 7 と入力する場合と seven と入力する場合を比較する。

  1. 入力 7：text は文字列 '7'、int(text) は整数 7、count+1 は 8。
  2. print は 8 と改行を表示する。案内 Count? はそれより先に表示され、? の後ろにはコードで指定した空白がある。
  3. 入力 seven：text は 'seven' で、int(text) が ValueError。
  4. 例外処理がないので最後の print は実行されない。

7 の場合の計算結果の予想出力は 8。seven の場合は ValueError で、計算結果 8 は表示されません。案内と入力文字は結果出力と別に記録します。

紙と本文で試してみよう

input の代わりに text='9' とする。A: print(text+'1')、B: print(int(text)+1)、C: print(text+1) を紙でたどり、計算・出力・エラーを分けよう。

ヒントを見る

+ の両側のオペランドの型を書く。

解答を見る

A は文字列の連結で予想出力 91。B は整数の 9+1 で 10。C は str と int の加算をサポートしないので TypeError が予想されます。正確な文言はインタープリタのバージョンによります。

よくある誤解と反例

エラーに表示された行だけ直せば根本原因は必ず解決する。

text+1 の TypeError の原因が、前の入力を数に変換しない設計にあるかもしれません。失敗位置と原因位置は異なる場合があります。入力の約束と中間値を一緒に確認します。

理解を確かめる

input が通常返す型は何か。

答えと理由を見る

文字列 str。

数に見える入力も自動では整数になりません。

入力が '12' なら int(text)+1 は何か。

答えと理由を見る

13

テキストを整数 12 に変換してから足します。

int('-2') が成功すれば個数として正しいか。

答えと理由を見る

問題の条件による。

変換成功だけでは負数禁止などの意味条件を確認できません。

もう一歩先へ

構文の有効な print('start'); int('oops'); print('end') では start だけが出力されると予測しよう。一方、ファイル末尾に構文エラーがあれば全体の解析が先に失敗する場合があります。「順番に行を読む」という比喩が実行前の分析をすべて説明できない理由を考えよう。

小節 1.4

問題分解と実行記録

答えは 9 とだけ書いておけば、友達は計算を再現できるでしょうか。

準備する概念と学習目標

準備する概念

  • 入力・処理・出力の順序と四則演算。
  • 準備の確認：単価 3、個数 2 なら合計 6。計算の前に値と単位を書く。

学習目標

  • 小さな要件を入力の約束・計算・出力に分解する。
  • 状態追跡表と実行記録で再現条件を残す。
  • 予想・実行観測・検証を異なる証拠として区別する。

最初に問題の約束を書く

プログラムの前に入力と出力を明確にします。クーポン適用額なら「整数の単価・個数・割引額を受け取り、小計から割引額を1回だけ引く」と書けます。価格が1商品分か全体額か曖昧なら、同じコードでも別の問題を解きます。

最初の練習では price、count、discount をコードに直接書き、すべて非負整数、割引額は元の小計以下とします。実際の利用者入力、通貨の小数、範囲検査は後の課題です。仮定を先に書くのは難しい場合を隠すことではなく、今の議論の適用範囲を示すことです。

分解で中間結果を見えるようにする

入力は price、count、discount、処理は subtotal=price*count と total=subtotal-discount に分け、出力は total の表示です。subtotal を分けて書くと割引前後を比較でき、誤りの場所を絞れます。

名前の意味と単位を記録します。price は1個当たりの金額、count は個数、subtotal と total は金額です。個数から割引額を引く式は構文上有効でも、単位と要件が合いません。コンピュータが許す式と、問題に意味の合う式は区別します。

price = 4
count = 3
discount = 2
subtotal = price * count
total = subtotal - discount
print(total)

予想記録は実行結果ではない

追跡表には行番号、新しい計算値、現在の名前と値の対応、出力イベントを書きます。本例は price=4、count=3、discount=2、subtotal=12、total=10 の順。正しい手計算は予測を確認した証拠で、実際のインタープリタを確認した証拠とは異なります。

実行したならソース版・作業フォルダ・コマンド・実行環境の版・入力・実出力・エラー・時刻を残します。予想と実際が違えば最初に違う中間状態を探します。1つの値の一致ではすべての入力の正しさを証明できません。通常・個数0・割引0・全額割引など条件を変えて約束を調べます。

途中の過程をたどる例題

単価 4、個数 3、割引 2 で上のコードをたどる。同僚が total=(price-discount)*count に変えたとき、同じ要件を満たすか比較する。

  1. 元の計算：subtotal=4*3=12。
  2. 1回の割引：total=12-2=10。
  3. 同僚の計算：(4-2)*3=6。
  4. 同僚の式は各商品で2ずつ引き、合計割引6となる。約束した合計割引2とは違う。

予想結果は 10。同僚の 6 は別の要件を実装しています。最初の違いは割引の適用範囲です。

紙と本文で試してみよう

紙で単価 5、個数 2、割引 10 の追跡表を作ろう。同じ単価と個数で割引 0 の場合も比較し、実行したかの欄に何を書くか決めよう。

ヒントを見る

小計は 10。割引を小計に1回だけ適用する。

解答を見る

最初は subtotal=10、total=0、次は subtotal=10、total=10。どちらも手計算の予想です。インストールや実行なしで行ったなら実行記録は not_executed とします。

よくある誤解と反例

例1つの実出力が合えばプログラム全体が証明される。

discount=0 では正しい式と誤った (price-discount)*count が同じ値になります。割引2、個数3なら違います。テストは反例を見つけ信頼を高めますが、一般の正しさには要件とすべての適用条件を扱う議論が必要です。

単価 2、個数 4、割引 3 なら合計はいくらか。

答えと理由を見る

5

2*4=8 から1回の割引3を引きます。

答えと理由を見る

違う。

もう一歩先へ

許される入力 p,c,d で、正しい pc-d と誤った (p-d)c の差を計算しよう。差は d(c-1) です。d=0 または c=1 のテストだけでは不具合を区別できません。式の差を使ってテストを設計する原理を説明しよう。
