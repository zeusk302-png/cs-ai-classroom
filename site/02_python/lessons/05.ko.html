소단원 5.1

list·tuple

순서가 같은 두 묶음에서 왜 하나는 칸을 바꿀 수 있고 다른 하나는 바꿀 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 이름 a는 객체를 가리키는 표지이고 a = 식은 우변 평가 후 그 표지를 연결한다.
  • 길이 n인 시퀀스의 정상 비음수 인덱스는 0부터 n−1까지이다. n>0일 때 음수 인덱스 −1은 마지막 칸이다. 빈 시퀀스에는 유효한 원소 인덱스가 없다.
  • 자가진단: [3, 1]의 첫 칸은 3, 길이는 2이다. 이 두 답을 구분할 수 있으면 시작할 수 있다.

학습 목표

  • 리스트와 튜플을 순서 있는 참조 묶음으로 설명한다.
  • append의 변경과 반환값, pop의 제거와 반환값을 구분한다.
  • 튜플 자체의 불변성과 내부 객체의 가변성을 구분한다.

순서를 가진 두 자료형

리스트 list는 원소의 순서를 유지하는 가변 시퀀스이다. [3, 1]과 [1, 3]은 순서가 달라 서로 같지 않다. a[0] = 9는 첫 칸의 참조를 바꾸고 append는 뒤에 칸을 추가한다. 튜플 tuple도 순서를 유지하지만 만들어진 뒤 칸의 참조와 길이를 직접 바꿀 수 없다.

빈 튜플은 ()이고 한 원소 튜플은 (3,)이다. (3)은 정수 3을 괄호로 묶은 식이다. tuple(a)는 a의 원소 참조를 같은 순서로 담는 튜플을 만든다. 이후 리스트의 칸을 교체해도 그 튜플의 칸은 교체되지 않는다. 이 변환은 내부 객체까지 복제하는 작업이 아니다.

메서드의 효과와 반환값

내장 리스트의 a.append(x)는 a 끝에 x를 추가하고 None을 반환한다. 변경된 리스트는 여전히 a로 접근하며 메서드의 반환값에서 얻지 않는다. a.pop()은 마지막 원소를 제거하면서 그 원소를 반환한다. 빈 리스트의 pop은 IndexError이므로 제거 계약에는 비어 있지 않다는 전제가 필요하다.

시퀀스 내용 S에 x를 append한 뒤, 다른 변경 없이 정상적으로 pop하면 제거값은 x이고 시퀀스 내용은 S로 돌아간다. 마지막 칸이 방금 추가한 x라는 사실이 근거이다. 이는 내용과 길이의 복원이지 메모리 할당 이력이나 모든 관찰 상태가 복원된다는 주장이 아니다. 실패·중간 변경·동시 변경이 있으면 이 계약을 그대로 적용할 수 없다.

불변성이 닿는 경계

튜플 ([1],)에는 리스트를 가리키는 한 칸이 있다. 그 칸을 다른 객체로 대입할 수는 없지만 그 칸을 통해 내부 리스트에 append할 수는 있다. 예를 들어 t = ([1],) 뒤 t[0].append(2)를 종이로 추적하면 t는 ([1, 2],)처럼 보인다. 튜플이 가리키는 리스트의 정체성은 유지된다.

따라서 변경되지 않을 기록을 설계할 때는 바깥 튜플만 확인하면 부족하다. 여기서 실행하는 예제는 원소가 불변 정수이므로 옛 원소값을 안전하게 비교할 수 있다. 파일·사용자 정의 객체·중첩 리스트가 있으면 각각의 변경 계약을 추가로 조사해야 한다.

중간 과정을 따라가는 예제

내장 리스트와 정수만 사용하고 각 문장을 순서대로 정상 실행한다. a와 t의 최종 내용 및 last를 구하라. 

a = [3, 1]
t = tuple(a)
a.append(2)
last = a.pop()
a[0] = 9
print(a, t, last)
  1. a는 [3, 1]이고 t는 두 정수를 같은 순서로 담은 (3, 1)이다. 바깥 리스트와 튜플은 별개의 객체이다.
  2. append(2) 후 a는 [3, 1, 2]이다. append의 반환값 None은 이 코드에서 사용하지 않는다.
  3. pop()이 마지막 정수 2를 반환하여 last에 연결하고 a는 [3, 1]로 돌아간다.
  4. a[0] = 9는 리스트 첫 칸만 바꾼다. 따라서 a는 [9, 1], t는 (3, 1), last는 2이다.

리스트의 변경은 이미 만들어진 튜플의 칸을 바꾸지 않는다. 실제 stdout: 

[9, 1] (3, 1) 2

종이와 본문으로 직접 해보기

종이에서 a = [4]; t = tuple(a); r = a.append(6); p = a.pop()를 추적하라. a, t, r, p를 구하고 (4)와 (4,)의 자료형도 비교하라. 실행하지 않는다.

힌트 보기

각 메서드 옆에 변경 후 상태와 반환값을 따로 적는다.

풀이 보기

append 후 a는 [4, 6], r은 None이다. pop 후 a는 [4], p는 6이다. t는 (4,)로 유지된다. (4)는 int이고 (4,)는 한 원소 tuple이다.

오해와 반례

튜플로 바꾸면 모든 내부 값이 영원히 고정된다.

([1],)의 내부 리스트는 append로 바뀐다. 튜플 불변성은 직접 담은 참조들의 교체 금지이며 전체 참조 그래프의 불변성을 뜻하지 않는다.

자기점검

append와 pop은 무엇을 반환하는가?

답과 이유 보기

append는 None, 정상 pop은 제거한 원소를 반환한다.

append는 리스트를 제자리 변경하고 pop은 제거와 값 반환을 함께 수행한다. 빈 리스트 pop은 정상 반환하지 않는다.

a = [2]; t = tuple(a); a[0] = 8이면 t는?

답과 이유 보기

(2,)이다.

a의 첫 칸 교체는 t의 칸을 교체하지 않는다. 정수 2 자체도 변경되지 않는다.

t = ([0],)에서 t[0].append(7)가 튜플 불변성을 위반하는가?

답과 이유 보기

위반하지 않는다. 내부 리스트가 [0, 7]로 바뀐다.

튜플의 한 칸은 여전히 같은 리스트를 가리킨다. 내부 객체의 변경과 튜플 칸 대입은 다르다.

한 단계 더

시퀀스 S를 (s₀, …, sₙ₋₁)로 적고 append(x) 후 길이 n+1, pop 후 길이 n이라는 두 계약을 합성해 내용 복원을 증명하라. 정수 원소 예제의 튜플은 옛 참조를 보유한다. 내부 가변 객체가 있으면 그 객체의 변경까지 막아 주지 않는다는 반례를 함께 제시하라. 성능이나 메모리 사용량은 이 증명으로 결론내지 않는다.

소단원 5.2

dict·set

여러 번 등장한 이름의 횟수와 등장 여부는 왜 서로 다른 자료가 필요할까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: for label in 목록은 원소를 하나씩 label에 연결한다.
  • 등장은 중복을 포함해 세고, 종류는 중복을 제거해 센다. b, a, b에는 등장 3회와 종류 2개가 있다.
  • 키는 값을 찾는 표지이고 값은 그 표지에 연결된 자료이다.

학습 목표

  • 사전의 키 조회·get·멤버십과 집합의 중복 제거를 구분한다.
  • 키의 hashable 조건을 단순한 불변성 구호보다 정확하게 설명한다.
  • 처리한 접두부의 등장 횟수를 귀납 불변식으로 증명한다.

사전의 조회와 삽입

내장 dict는 키를 값에 연결한다. d[key]는 키가 없으면 KeyError이지만 d.get(key, default)는 없는 키에 대해 default를 반환한다. get 자체는 그 키를 삽입하지 않는다. key in d와 for key in d는 값을 검사하거나 순회하는 연산이 아니라 키를 대상으로 한다. 따라서 {"x": 3}에서 3 in d는 False이다.

Python 3.12의 dict는 키 삽입 순서를 유지한다. 기존 키의 값을 갱신해도 그 키의 위치는 바뀌지 않는다. 삭제했다가 다시 넣으면 뒤에 놓인다. set에는 이런 삽입 순서 계약이 없다. 결과를 정렬해 보여 주고 싶으면 서로 비교 가능한 값들에 sorted를 적용해야 한다. 이 예제의 키는 소문자 문자열이므로 비교 가능하다.

해시 가능성과 집합

사전 키와 집합 원소는 hashable이어야 한다. 이는 수명 동안 해시값이 안정적이고 동등 비교가 가능하며, 같다고 비교되는 두 객체의 해시값도 같아야 한다는 계약이다. 해시가 같다는 역방향만으로 값이 같다고 결론내릴 수 없다. 충돌이 가능한 해시는 객체 정체성이나 유일 번호가 아니다.

내장 list·dict·set은 가변 컨테이너여서 키로 쓸 수 없다. tuple은 모든 원소가 hashable인 경우에만 hashable이므로 ([1],)도 키로 쓸 수 없다. 사용자 정의 객체에는 별도 계약이 있어 모든 가변 객체가 무조건 금지된다고 일반화하지 않는다. set은 같은 원소를 중복 보관하지 않으므로 set(["b", "a", "b"])는 두 종류만 남기고 횟수 2와 1을 잃는다. 빈 집합은 set()이고 {}는 빈 사전이다.

횟수 누적의 불변식

입력은 유한 문자열 목록이고, 다른 코드가 counts를 바꾸지 않으며 각 갱신이 정상 완료한다고 가정한다. 첫 k개를 처리한 뒤 counts의 각 값은 그 문자열이 해당 접두부에 등장한 횟수이다. 등장하지 않은 문자열의 수는 get으로 0이라 해석한다. 처음 k=0에서는 빈 사전이므로 모든 횟수가 0이다.

다음 label의 이전 횟수를 get(label, 0)로 읽고 정확히 1만 더한다. 다른 키는 유지되므로 귀납 가정이 k+1에서도 성립한다. 각 입력이 한 횟수에만 기여하므로 모든 저장 횟수의 합은 k이다. 이 예제는 문자열 키만 사용한다. 일반 키에서는 1과 True처럼 동등한 키가 같은 항목을 가리킬 수 있으므로 자료 구별 명세를 따로 확인해야 한다.

중간 과정을 따라가는 예제

입력 문자열 목록 b, a, b의 빈도를 계산한다. get으로 z를 읽은 뒤 z가 삽입되는지도 확인하고 종류를 정렬해 출력한다. 

counts = {}
for label in ["b", "a", "b"]:
    counts[label] = counts.get(label, 0) + 1
print(counts["b"], counts.get("z", 0), "z" in counts)
seen = set(counts)
print(sorted(seen))
  1. 빈 사전에서 첫 b를 처리하면 get은 0을 반환하고 대입으로 b: 1을 삽입한다. 합은 1이다.
  2. a를 처리하면 a: 1을 추가한다. 마지막 b를 처리하면 기존 b의 값만 2로 갱신한다. 사전은 b: 2, a: 1이고 합은 3이다.
  3. counts["b"]는 2, counts.get("z", 0)은 0이다. get은 삽입하지 않아 "z" in counts는 False이다.
  4. set(counts)는 키 b와 a의 집합이다. sorted(seen)은 정렬된 리스트 ["a", "b"]를 만든다. 원래 빈도는 counts에만 남아 있다.

등장 빈도와 종류를 분리해 보존하고, 조회만 한 z는 새 키가 되지 않는다. 실제 stdout: 

2 0 False
['a', 'b']

종이와 본문으로 직접 해보기

종이에서 입력 a, b, a, c의 접두부별 counts와 횟수 합을 기록하라. 마지막에 get("z", 0) 뒤 키 수와 set(counts)의 종류 수를 비교하라. 실행하지 않는다.

힌트 보기

빈 상태의 합을 0으로 적고 한 원소를 처리할 때마다 한 항목만 1 늘린다.

풀이 보기

사전은 순서대로 {a: 1}, {a: 1, b: 1}, {a: 2, b: 1}, {a: 2, b: 1, c: 1}이고 합은 1, 2, 3, 4이다. get은 z를 넣지 않아 키 수와 집합 종류 수는 모두 3이다. 집합만으로 a의 등장 횟수 2를 복원할 수 없다.

오해와 반례

해시값이 같으면 같은 키이며 set은 원래 등장 횟수를 보존한다.

해시 충돌은 동등성의 증거가 아니다. 또한 ["a", "a"]와 ["a"]는 같은 집합 {"a"}로 변환되므로 집합만으로 두 목록의 빈도를 구별할 수 없다.

자기점검

d = {"a": 1}에서 d.get("z", 0) 뒤 "z" in d는?

답과 이유 보기

False이다.

get은 기본값 0을 반환하지만 삽입하지 않는다.

입력 a, a, b를 센 횟수 합과 set의 원소 수는?

답과 이유 보기

합은 3, 종류 수는 2이다.

counts는 중복 등장도 세지만 집합에는 a와 b가 한 번씩만 들어간다.

불변 튜플 ([1],)을 dict 키로 쓸 수 있는가?

답과 이유 보기

쓸 수 없다.

그 원소 list가 hashable이 아니므로 튜플도 hashable이 아니다. 바깥 불변성만으로 충분하지 않다.

한 단계 더

귀납 불변식을 두 문장으로 나누어 증명하라: 모든 키의 정확한 횟수, 모든 횟수의 합 k. 합만 맞아도 개별 횟수가 틀릴 수 있다. 예컨대 b, a, b에 b: 1, a: 2는 합 3을 만족하지만 명세를 위반한다. 정확성 증명은 키별 불변식을 필요로 하며 실행 속도나 최악 시간 보장을 포함하지 않는다.

소단원 5.3

중첩구조와 복사

겉 상자를 복사했는데 왜 원래 상자의 안쪽 내용이 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: [[1], [2]]에는 바깥 리스트 하나와 안쪽 리스트 두 개가 있다.
  • a[0].append(9)는 첫 안쪽 리스트의 내용 변경이고 a[0] = [9]는 바깥 첫 칸의 참조 교체이다.
  • 화살표 두 개가 같은 상자를 가리키면 별칭 관계이다. 출력 모양만 같다고 같은 상자는 아니다.

학습 목표

  • 대입·얕은 복사·깊은 복사의 참조 그래프를 비교한다.
  • 안쪽 변경과 바깥 칸 교체의 영향 범위를 설명한다.
  • deepcopy의 memo가 복제 안에서 별칭을 보존하는 조건과 한계를 설명한다.

대입과 얕은 복사

b = a는 바깥 리스트를 복사하지 않고 b도 a와 같은 리스트에 연결한다. 반면 내장 리스트의 b = a.copy()는 새로운 바깥 리스트를 만들되 원소 참조를 그대로 담는다. a와 b의 바깥 정체성은 다르고 안쪽 리스트들은 공유된다. 깊이를 말할 때 원소값만 쓰지 말고 어느 객체 층을 복사했는지 표시해야 한다.

b[0].append(9)는 공유한 안쪽 객체를 바꾸므로 a[0]에서도 9가 보인다. 그러나 b[1] = [7]은 b의 두 번째 칸만 새 리스트에 연결한다. a의 두 번째 칸은 옛 [2]에 남는다. 얕은 복사는 어느 변경도 독립적이지 않다는 뜻이 아니라 바깥과 내부의 독립 범위가 다르다는 뜻이다.

깊은 복사와 memo

copy.deepcopy는 지원되는 복합 객체의 구성 요소를 재귀적으로 복사한다. 이 예제의 내장 리스트와 정수에서는 c의 안쪽 리스트가 원본과 별개이므로 c[0].append(5)는 a나 b를 바꾸지 않는다. 불변 정수처럼 공유해도 문제가 없는 객체는 정체성이 반드시 새로워야 하는 것이 아니다.

하나의 복사 과정은 이미 처리한 객체를 memo에 기록한다. row = [0]; a = [row, row]라면 정상 내장 리스트에 대한 c = deepcopy(a)에서 c[0]과 c[1]은 같은 복제 행을 가리킨다. 원본 row와 그 복제 행은 다르다. 즉 원본과는 분리하지만 복제 내부의 공유 구조를 보존한다. 같은 객체를 볼 때마다 무조건 서로 다른 사본을 만드는 방법으로 이해하면 틀린다.

복사 계약의 적용 한계

memo는 자기 자신을 가리키는 구조의 재귀 처리를 지원하는 역할도 한다. 다만 deepcopy를 모든 객체의 완전 독립 복제라는 보편 계약으로 쓰면 안 된다. 사용자 정의 클래스는 __deepcopy__로 동작을 바꿀 수 있고 함수·클래스는 원본 객체가 반환되며 파일·소켓 등 외부 자원은 일반적인 값 복사 대상이 아니다.

따라서 이 단원의 논증은 정상 실행한 내장 리스트와 정수 그래프를 대상으로 한다. 업무 데이터에 복사를 도입하려면 공유해야 할 자원과 분리할 가변 상태를 먼저 정한다. 복사는 외부 파일을 복제하거나 원격 상태를 고정하거나 동시 접근을 원자적으로 만드는 기능이 아니다.

중간 과정을 따라가는 예제

내장 리스트·정수만 있는 a를 얕게 복사한 b와 깊게 복사한 c를 만든 뒤, 서로 다른 종류의 변경을 순서대로 추적한다. 

from copy import deepcopy
a = [[1], [2]]
b = a.copy()
c = deepcopy(a)
b[0].append(9)
b[1] = [7]
c[0].append(5)
print(a, b, c)
  1. a는 바깥 A와 안쪽 [1], [2]를 가진다. b의 새 바깥 B는 그 두 안쪽을 공유한다. c의 새 바깥 C는 별도의 안쪽 [1], [2]를 가진다.
  2. b[0].append(9)가 공유한 첫 안쪽을 [1, 9]로 만든다. a와 b의 첫 칸에서 모두 보이고 c의 첫 칸은 [1]이다.
  3. b[1] = [7]은 B의 두 번째 화살표만 바꾼다. a의 두 번째 칸과 c의 두 번째 칸은 각각 [2]를 유지한다.
  4. c[0].append(5)는 복제한 첫 안쪽만 [1, 5]로 만든다. a는 [[1, 9], [2]], b는 [[1, 9], [7]], c는 [[1, 5], [2]]이다.

공유한 안쪽의 변경과 한 바깥 칸의 교체는 다른 경로로 전파된다. 실제 stdout: 

[[1, 9], [2]] [[1, 9], [7]] [[1, 5], [2]]

종이와 본문으로 직접 해보기

종이에서 row = [0]; a = [row, row]; b = a.copy(); c = deepcopy(a)를 그린 뒤 b[0].append(4), c[1].append(6)을 추적하라. a, b, c와 c[0] is c[1]을 구한다. 이 변형은 실행하지 않는다.

힌트 보기

원본 행 R과 복제 행 R′을 하나씩 그린다. c의 두 칸이 서로 다른 행으로 갈라지지 않도록 memo 조건을 사용한다.

풀이 보기

a와 b는 공유한 R을 통해 모두 [[0, 4], [0, 4]]로 보인다. c는 R′을 두 번 가리켜 [[0, 6], [0, 6]]이다. c[0] is c[1]은 True이고 c[0] is row는 False이다. 복제 내부 별칭과 원본과의 분리를 동시에 만족한다.

오해와 반례

deepcopy는 모든 참조를 서로 다른 객체로 바꾸고 모든 자원을 복제한다.

반복 행은 복제 안에서도 공유된다. 함수·클래스 반환과 사용자 정의 복사 규칙도 새 객체 보장을 제한한다. 외부 자원을 가진 객체는 명시적인 별도 자원 계약이 필요하다.

자기점검

b = a.copy()가 중첩 리스트의 내부까지 독립적으로 만드는가?

답과 이유 보기

아니다. 바깥 리스트만 새로 만들고 안쪽 참조는 공유한다.

얕은 복사의 계약은 바깥 복합 객체와 그 안의 기존 객체 참조를 구분한다.

a = [[1]]; b = a.copy(); b[0] = [8]이면 a는?

답과 이유 보기

[[1]]이다.

b의 바깥 첫 칸만 교체하므로 공유했던 원본 안쪽 객체나 a의 칸은 바뀌지 않는다.

row = [0]; a = [row, row]를 deepcopy하면 복제의 두 행은 반드시 서로 다른가?

답과 이유 보기

아니다. 내장 리스트의 정상 복사에서는 복제한 같은 행을 공유한다.

memo가 동일 원본 객체에 대응하는 사본을 재사용하여 복제 내부 별칭을 유지한다.

한 단계 더

유한 내장 리스트 그래프에서 원본 객체 R에 대응하는 복제 R′을 memo로 한 번 정한다고 생각하라. 원본에서 두 화살표가 R로 합류하면 복제의 대응 화살표들도 R′로 합류한다. 이는 공유 구조를 보존하는 근거이다. 순환이 있으면 이미 생성한 복제의 참조를 다시 사용해야 끝없는 복제를 피한다. 이 설명은 사용자 정의 복사 훅이나 외부 자원에 대한 보편 정리가 아니며 해당 심화 코드는 실행하지 않았다.

소단원 5.4

가변성·별칭과 오류

한 줄의 대입과 한 번의 내부 변경은 왜 다른 이름들에 서로 다른 영향을 줄까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 이름을 적은 표지와 리스트를 그린 상자를 분리한다. 대입은 표지의 화살표를 바꿀 수 있다.
  • ==는 값의 동등 비교이고 is는 객체 정체성 비교이다. 같은 내용의 별개 리스트를 그릴 수 있다.
  • [row] * 3은 한 원소 시퀀스의 반복이다. 안쪽 row를 세 번 새로 만든다고 먼저 가정하지 않는다.

학습 목표

  • 반복 참조와 새 행 생성의 차이를 추적한다.
  • 객체 변경·이름 재대입·컨테이너 칸 교체를 구분한다.
  • 반환값 None을 다시 대입하는 오류의 원인을 설명한다.

객체 노드와 참조 화살표

객체를 노드, 이름과 컨테이너 칸을 화살표로 그린다. view = grid는 같은 바깥 노드로 화살표를 하나 더 만든다. grid = 새 리스트는 이름 grid의 화살표만 새 바깥 노드로 옮긴다. 옛 노드를 가리키던 view의 화살표는 저절로 옮겨지지 않는다.

view[1].append(8)는 view에서 두 번째 칸을 따라간 안쪽 노드를 변경한다. 그 노드를 가리키는 모든 경로에서 변경을 볼 수 있다. view[1] = [8]이라면 옛 안쪽 노드가 아니라 바깥의 한 칸 화살표를 교체한다. 공유 문제를 해결하려면 바꾼 노드와 바꾼 화살표를 명확히 구별해야 한다.

반복과 새 객체 생성

[row] * 3은 row를 가리키는 참조 세 개를 담은 새 바깥 리스트이다. 세 칸의 내용이 같아 보이는 이유뿐 아니라 세 칸이 동일한 행이라는 사실이 중요하다. 한 경로로 행을 변경하면 다른 두 경로에서도 변경된 행이 보인다. 시퀀스 반복은 원소 자체를 복제하지 않는다.

[[0] for _ in range(3)]에서는 반복할 때마다 [0] 식이 새 내장 리스트를 만든다. 따라서 세 행은 내용은 같지만 서로 다른 객체이다. 반면 [row for _ in range(3)]는 같은 row 참조를 세 번 담으므로 공유를 없애지 못한다. comprehension이라는 문법 이름만으로 독립 행을 보장하지 않고 반복되는 식을 확인해야 한다.

정체성 검사와 반환값 오류

내장 리스트 x = [1]; y = [1]은 x == y가 True여도 x is y는 False이다. is는 내용 비교용이 아니다. 정수·문자열 같은 불변 객체는 구현이 객체를 재사용할 수 있으므로 값이 같은지를 is로 확인하는 습관을 들이면 안 된다. 이 예제에서는 명시적으로 공유한 내장 리스트의 정체성만 검사한다.

a = a.append(2)는 먼저 옛 리스트에 2를 추가하고, 반환값 None을 이름 a에 다시 연결한다. 옛 리스트를 다른 이름이 가리켰다면 그 이름에서는 변경이 보인다. 다음 a.append 호출은 None에 리스트 메서드가 없어 실패한다. 해결은 목적에 맞게 a.append(2)를 단독 호출하는 것이다. 이는 종이 오류 추적이며 오류 변형을 실제 실행한 기록은 없다.

중간 과정을 따라가는 예제

한 행을 세 칸에서 공유한 뒤 grid 이름만 새 구조에 연결한다. 옛 구조를 가리키는 view의 변경과 새 grid의 내용을 비교한다. 

row = [0]
grid = [row] * 3
grid[0][0] = 7
view = grid
grid = [[1], [2], [3]]
view[1].append(8)
print(view)
print(grid)
print(view[0] is view[2])
  1. row는 [0]인 안쪽 R이다. grid의 세 칸은 모두 R을 가리킨다. grid[0][0] = 7은 R을 [7]로 바꾸어 세 칸 모두 [7]로 보인다.
  2. view = grid는 옛 바깥 G를 공유한다. grid = [[1], [2], [3]]은 grid만 새 바깥 H와 새 안쪽 세 행에 연결한다.
  3. view[1].append(8)는 여전히 R을 찾아 [7, 8]로 만든다. G의 세 칸 모두 R을 공유하므로 view는 [[7, 8], [7, 8], [7, 8]]이다.
  4. H는 R을 공유하지 않으므로 grid는 [[1], [2], [3]]이다. view[0]과 view[2]는 같은 R이므로 is 검사는 True이다.

새 이름 연결은 기존 별칭을 바꾸지 않으며 공유 행 변경은 모든 공유 경로에서 보인다. 실제 stdout: 

[[7, 8], [7, 8], [7, 8]]
[[1], [2], [3]]
True

종이와 본문으로 직접 해보기

실행 없이 row = [0]; a = [row] * 2; b = a; a[0] = [5]; b[1].append(6); a = []를 추적하라. 최종 a, b, row와 b[0] is b[1]을 구한다.

힌트 보기

처음 바깥 G의 두 칸은 R을 공유한다. 첫 칸 교체 후 두 칸의 화살표가 갈라진다. 마지막 줄은 이름 a만 옮긴다.

풀이 보기

첫 칸은 새 [5]를, 두 번째 칸은 R을 가리킨다. append 후 R은 [0, 6]이다. 최종 a는 [], b는 [[5], [0, 6]], row는 [0, 6]이다. b[0] is b[1]은 False이다. 바깥 G를 가리키는 b는 마지막 a 재대입의 영향을 받지 않는다.

오해와 반례

새 값을 대입하면 그 이름의 모든 별칭도 함께 바뀌며, comprehension이면 내부 공유도 사라진다.

view = grid 뒤 grid 재대입은 view를 옮기지 않는다. 또한 [row for _ in range(3)]는 row를 반복 참조한다. 이름 대입과 내부 생성 식을 따로 검토해야 한다.

자기점검

x = [1]; y = [1]에서 x == y와 x is y는?

답과 이유 보기

각각 True와 False이다.

내용은 같지만 두 리스트 식이 별개의 내장 리스트 객체를 만든다.

row = [0]; a = [row for _ in range(2)]는 독립된 두 행인가?

답과 이유 보기

아니다. 같은 row를 두 번 참조한다.

반복 식 row는 새 리스트를 만드는 식이 아니다. 독립 행은 [0]처럼 각 반복에서 새 객체를 생성해야 한다.

a = [1]; b = a; a = a.append(2) 뒤 a와 b는?

답과 이유 보기

a는 None, b는 [1, 2]이다.

우변 append가 기존 리스트를 먼저 변경하고 None을 반환한다. 그 뒤 a만 None에 연결되며 b는 변경된 리스트를 계속 가리킨다.

한 단계 더

공유 경로 집합을 먼저 적으면 변경 영향 범위를 예측할 수 있다. 행 R을 세 칸이 공유할 때 R에 append는 세 경로 모두의 관찰값을 바꾸지만 한 칸을 새 R′에 연결하면 그 한 경로만 갈라진다. 프로그램 계약에서 입력 리스트를 변경해도 되는지, 반환값이 새로운 리스트인지, 내부를 공유하는지를 따로 기술하라. 이 참조 모형은 메모리 주소값·해제 시점·스레드 안전성을 보장하지 않는다.
