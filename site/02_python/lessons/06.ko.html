소단원 6.1

인자·반환값

함수 안에서 목록을 바꾸면 바깥 목록도 바뀌는데, 숫자 이름을 바꾸면 왜 바깥 숫자는 그대로일까?

준비 개념과 학습 목표

준비 개념

  • 이름은 객체에 붙이는 표지이다. a = [2]는 새 리스트를 만들고 a를 연결한다. b = a는 같은 객체에 두 번째 표지를 붙이며 리스트를 복사하지 않는다.
  • 가변 리스트의 append는 같은 객체에 원소 참조를 추가한다. 정수는 불변이므로 x + 1은 정수 값을 계산하고 x = x + 1은 이름을 다시 연결한다.
  • 자가진단: a = [2]; b = a; b.append(5) 뒤 a도 [2, 5]이다. b = [99] 뒤 a는 여전히 [2, 5]이다. 종이에 이름 두 개와 객체 두 개를 그려 확인한다.

학습 목표

  • 호출자의 인자 표현식과 함수의 매개변수 이름을 구분한다.
  • 같은 객체의 변경과 매개변수 재결박을 추적한다.
  • 반환값·화면 출력·부작용을 서로 구분한다.

인자는 식이고 매개변수는 지역 이름이다

def change(items, n):의 items와 n은 함수 본문에서 쓰는 매개변수이다. change(a, x)의 a와 x는 호출할 때 평가하는 인자 표현식이다. 정상 호출에서는 인자 표현식을 먼저 평가하고 그 결과 객체를 새 호출의 지역 이름에 연결한다. 여기서는 보통의 Python 함수와 내장 list·int만 사용한다.

객체 참조를 값으로 전달한다고 생각하면 두 현상을 함께 설명할 수 있다. 호출자와 함수가 같은 리스트를 가리킬 수 있지만, 호출자의 이름 자체를 매개변수가 대신 소유하는 것은 아니다. 각 호출은 자기 지역 이름 표를 가진다. 이 규칙은 자료를 전부 깊은 복사한다는 뜻도, 호출자의 변수 이름에 직접 대입한다는 뜻도 아니다.

변경과 재결박의 관찰 위치

items.append(n)은 items가 가리키는 리스트 자체를 바꾼다. a도 그 리스트를 가리키므로 호출 후 변경을 관찰한다. 다음 items = [99]는 함수의 지역 표지만 새 리스트에 붙인다. 호출자의 a는 옛 리스트에 남는다. n = n + 1도 지역 n의 연결만 바꾸며 호출자의 x에 대입하지 않는다.

이 예제에서 입력 리스트에 append한 것은 외부에서 관찰할 수 있는 부작용이다. 반환값이 같은 두 함수도 하나가 입력 리스트를 변경하거나 파일·화면에 쓰면 인터페이스가 다르다. 리스트를 전달받았다는 사실만으로 변경 허가를 얻는 것은 아니다. 함수 설명에 입력 객체를 변경하는지, 변경하지 않는지를 계약으로 적는다.

return과 print가 전달하는 것은 다르다

return 식은 식의 결과를 호출자에게 돌려주고 그 호출을 끝낸다. return items, n은 두 원소 튜플을 반환하며 b, y가 이를 나누어 받는다. 여기서는 정상 반환만 다루며 예외는 일반 반환값이 아니다. return 뒤 같은 호출의 일반 문장은 실행되지 않는다.

print(value)는 화면에 글을 쓰는 부작용이며 내장 print의 반환값은 None이다. display는 7을 출력하지만 return이 없으므로 함수 끝에 도달해 None을 반환한다. None은 반환할 값을 지정하지 않았다는 객체이며 숫자 0이나 빈 리스트와 같은 값이 아니다. 여러 값을 계산한 함수는 print 대신 return으로 결과를 전달하면 호출자가 후속 계산에 사용할 수 있다.

def change(items, n):
    items.append(n)
    items = [99]
    n = n + 1
    return items, n

a = [2]
x = 5
b, y = change(a, x)
print(a, x, b, y)

def display(value):
    print(value)

result = display(7)
print(result)

중간 과정을 따라가는 예제

아래 보존 코드에서 a=[2], x=5를 전달한다. 정상 실행의 이름 연결과 세 출력 줄을 추적한다. 모든 객체는 내장 리스트·정수이다.

  1. 호출 직전 a→L=[2], x→정수 5이다. 지역 items→L, n→5가 생긴다. append 뒤 L=[2, 5]이고 a도 이 상태를 관찰한다.
  2. items=[99]에서 새 M=[99]를 만든다. 지역 items→M으로 바뀌지만 a→L은 유지된다. n=n+1 뒤 지역 n→6, 호출자의 x→5이다.
  3. return items,n으로 (M,6)을 반환한다. 튜플을 풀어 b→M, y→6이 되어 첫 줄은 [2, 5] 5 [99] 6이다.
  4. display(7)는 먼저 7을 출력하고 명시적 return 없이 None을 반환한다. result→None이므로 마지막 출력 줄은 None이다.

호출자 리스트의 변경, 지역 이름의 재결박, 반환 결과, 화면 출력은 각각 다른 관찰이다. 실제 stdout: [2, 5] 5 [99] 6 7 None

종이와 본문으로 직접 해보기

종이에 a=[1]; b=a를 그린다. f(p)가 p.append(3); p=[8]; return p를 수행한다고 할 때 c=f(a) 뒤 a,b,c와 a is b, a is c를 구한다. 코드를 실행할 필요는 없다.

힌트 보기

append는 객체 안을 바꾸고 p=[8]은 지역 화살표만 바꾼다.

풀이 보기

a와 b는 같은 원래 리스트 [1,3]을 가리킨다. c는 반환된 새 리스트 [8]을 가리킨다. 따라서 a is b는 True, a is c는 False이다. 함수 지역 p가 사라져도 반환된 객체는 c가 참조하는 동안 사용할 수 있다.

오해와 반례

함수 인자는 전부 복사되므로 함수 내부 변경은 호출자에게 영향을 주지 않는다.

a=[1]을 받아 p.append(3)을 하면 a도 [1,3]이 된다. 참조의 공유와 객체의 깊은 복사는 다르다. 반대로 p=[8]이 a를 재결박하지는 않는다. 내장 리스트에 대해 두 연산을 구분해야 하며 사용자 정의 객체의 연산은 별도 계약을 확인한다.

자기점검

change의 지역 n이 6이 된 뒤 호출자의 x는 얼마인가?

답과 이유 보기

5

n에 대한 지역 재결박은 호출자의 x 표지를 바꾸지 않는다.

return이 없는 display(7)의 반환값은 무엇인가?

답과 이유 보기

None

7은 print로 보낸 화면 내용이다. 함수 끝에 도달할 때 정상 반환값은 None이다.

b, y = change(a,x)는 리스트 원소와 숫자를 깊은 복사하는가?

답과 이유 보기

아니다. 반환 튜플의 원소를 두 이름에 연결한다.

b는 함수가 반환한 리스트 객체를 참조한다. 이후 b의 리스트 변경은 그 객체를 공유하는 다른 이름에서도 관찰된다.

한 단계 더

심화: 정상 호출에 대해 이름 표와 객체 그래프를 나누어 그리면 공유 여부를 증명할 수 있다. 지역 재결박은 지역 이름에서 나가는 화살표 하나만 바꾸므로 호출자 이름의 화살표를 보존한다. 객체 변경은 노드의 내용을 바꾸므로 그 노드에 도달하는 모든 참조에서 관찰된다. 이 설명의 전제는 예제의 보통 함수·내장 객체 연산이며 사용자 정의 __iadd__ 같은 연산은 다르게 구현할 수 있다. 복사도 얕은 복사이면 내부 가변 객체를 계속 공유할 수 있으므로 내부까지 변경하지 않는 계약을 별도로 확인해야 한다.

소단원 6.2

scope와 부작용

바깥에 x=10이 있는데 함수의 첫 줄 print(x)가 왜 실패할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 블록은 함수 본문처럼 이름을 바인딩하는 코드 범위이다. x = 20은 x를 객체에 연결하는 대입이며 x를 읽는 것과 다르다.
  • 예외는 정상 계산 대신 오류를 알리는 흐름이다. try 안에서 특정 예외를 except로 포착하면 아래 문장을 이어갈 수 있다. 포착하지 않은 예외는 호출자 쪽으로 전파된다.
  • 자가진단: 지역 x와 모듈 x는 철자가 같아도 서로 다른 표지일 수 있다. 이름의 철자만 보고 공유 객체나 같은 저장 장소라고 결론 내리지 않는다.

학습 목표

  • 일반 함수 이름 검색과 지역 이름 판정을 구분한다.
  • UnboundLocalError의 원인을 블록 전체의 바인딩으로 설명한다.
  • global·nonlocal을 구별하고 상태 변경의 관찰 범위를 적는다.

LEGB는 일반 함수 이름 읽기의 출발점이다

이 소단원의 일반 함수 이름은 지역 Local, 둘러싼 함수 Enclosing, 정의된 모듈 Global, 내장 Builtins 범위에서 찾는다고 요약할 수 있다. 함수가 어느 모듈에서 정의되었는지가 중요하며, 호출자의 지역 이름 표를 임의로 검색하지 않는다. 클래스 본문·annotation scope·다른 특별 구문에는 별도 규칙이 있으므로 이 요약을 모든 Python 문맥의 법칙으로 확대하지 않는다.

그런데 검색 전에 해당 이름이 지역 이름인지 판정해야 한다. global·nonlocal 선언이 없는 보통 함수에서 이름에 대입하는 문장이 블록 안에 있으면 그 이름은 블록 전체에서 지역으로 취급된다. 실행 순서상 대입보다 앞의 읽기라고 해서 먼저 모듈 값을 가져오지 않는다. 이 판정은 블록을 분석하는 규칙이며 값을 찾는 실행 단계와 다르다.

읽기 전에 아직 연결되지 않은 지역 이름

bad의 print(x) 다음에는 x=20이 있다. 따라서 x는 bad의 지역 이름이다. 첫 읽기 시 아직 값이 연결되지 않았으므로 UnboundLocalError가 난다. 이 예외는 NameError의 하위 종류이다. 바깥에 x=10이 있어도 이 지역 이름의 미결박 상태를 대신 채워주지 않는다.

global x는 그 함수의 x를 정의된 모듈의 이름으로 취급하게 한다. nonlocal count는 가장 가까운, 이미 그 이름을 바인딩한 둘러싼 함수 범위의 이름을 사용하게 한다. nonlocal은 임의의 모듈 이름을 새로 만드는 문장이 아니다. 알맞은 둘러싼 함수의 바인딩이 없으면 구문 분석 단계의 SyntaxError가 된다. 선언은 그 블록의 해당 이름 사용에 앞서 적어야 한다.

클로저의 상태와 공유 계약

make_counter가 만든 next_count는 둘러싼 count 바인딩을 사용할 수 있는 함수이다. nonlocal로 같은 count를 재결박하므로 두 번 호출하면 1,2를 반환한다. make_counter를 다시 호출하면 별도 count와 새 함수가 생겨 두 카운터의 숫자는 독립적으로 증가한다. 이 예제는 단일 스레드 순차 호출만 다룬다.

모듈 x나 클로저 count를 바꾸면 호출 이전과 이후의 외부 상태가 달라진다. 이를 상태를 가지는 인터페이스라고 명시해야 한다. global 선언 없이도 공유 리스트에 append하는 것은 가능하다. 지역 이름이 리스트를 참조하는 것과 모듈 이름을 재결박하는 것은 다르기 때문이다. 부작용을 피하려면 상태를 인자로 받아 새 값으로 반환하는 설계를 택할 수 있지만, 단순히 global을 없앤 것만으로 순수 함수가 보장되지는 않는다.

x = 10

def bad():
    print(x)
    x = 20

try:
    bad()
except UnboundLocalError:
    print("UnboundLocalError")

def increase_global():
    global x
    x = x + 1

increase_global()
print(x)

def make_counter():
    count = 0
    def next_count():
        nonlocal count
        count = count + 1
        return count
    return next_count

first = make_counter()
second = make_counter()
print(first(), first(), second())

중간 과정을 따라가는 예제

보존 코드를 순서대로 읽는다. 모듈 x=10, 예외 포착, global 변경, 독립된 두 클로저를 가정하며 스레드 경쟁은 없다.

  1. bad의 x=20 때문에 x가 지역으로 판정된다. print(x)에서 지역 x가 미결박이므로 예외가 나고 x=20까지 진행하지 않는다. 포착부가 UnboundLocalError를 출력한다.
  2. increase_global은 모듈 x의 기존 10을 읽고 11로 재결박한다. 다음 print(x)는 11이다.
  3. first=make_counter()와 second=make_counter()는 각각 별도의 count=0 바인딩을 가진다. 두 함수의 코드가 같다는 사실은 상태 공유를 뜻하지 않는다.
  4. print 인자는 왼쪽부터 평가된다. first()가 1, 다음 first()가 2, second()가 1을 반환하여 1 2 1이 출력된다.

지역 이름 오류와 모듈 상태 변경, 둘러싼 함수 상태 변경을 세 출력 줄로 구분한다. 실제 stdout: UnboundLocalError 11 1 2 1

종이와 본문으로 직접 해보기

모듈 total=100이 있다. f는 지역 total=0을 만들고 내부 g는 nonlocal total; total=total+2; return total을 수행한다. f가 g를 반환한다고 할 때 a=f(); b=f(); a(); b(); a()의 각 반환값과 모듈 total을 종이에 구한다.

힌트 보기

a와 b는 서로 다른 f 호출의 total을 잡는다. nonlocal은 모듈 total을 선택하지 않는다.

풀이 보기

반환값은 차례로 2,2,4이다. 모듈 total은 100 그대로이다. a의 상태는 0→2→4, b의 상태는 0→2이고 두 상태와 모듈 표지는 서로 구별된다.

오해와 반례

global을 쓰지 않으면 함수는 외부 상태를 바꿀 수 없다.

모듈 a=[]를 지역 p로 받아 p.append(1)을 하면 외부에서 같은 리스트의 변경을 본다. global은 이름 재결박의 범위를 지정하는 문장이며 모든 객체 변경을 차단하거나 허용하는 권한 장치가 아니다. nonlocal도 동시성 안전을 보장하지 않는다.

심화: 한 카운터만 순차적으로 k번 정상 호출한다고 하자. 초기 count=0이다. k번째 직전 값이 k−1이면 본문이 1을 더해 k를 반환하므로 귀납적으로 k번째 반환값은 k이다. 다른 카운터의 count에 접근하지 않으므로 위 증명은 각각 독립적으로 적용된다. 이는 상태 전이의 논증이며 여러 스레드의 원자성이나 무한 호출의 자원 보장을 증명하지 않는다. 순수한 대안 step(count)=(count+1,count+1)은 상태를 명시적으로 주고받게 하여 시험 입력을 드러내지만, 호출자가 결과 상태를 저장하는 책임은 남는다.

소단원 6.3

default·keyword·가변인자

호출마다 빈 목록으로 시작할 생각이었는데 왜 앞선 호출의 값이 남아 있을까?

준비 개념과 학습 목표

준비 개념

  • 함수 정의 def를 실행하면 함수 객체가 만들어진다. 함수를 호출하는 일과 정의를 실행하는 일은 서로 다르다.
  • 위치 인자는 자리 순서로, 키워드 인자는 이름으로 매개변수에 대응한다. tuple은 순서 있는 묶음이며 dict는 키와 값의 대응이다. 묶음의 새 생성이 내부 객체의 깊은 복사를 뜻하지 않는다.
  • 자가진단: p=[]; q=p 뒤 q.append(1)이 p에도 보이는 것은 같은 리스트를 공유하기 때문이다. 기본값에 같은 현상이 생길 수 있다.

학습 목표

  • 기본 인자의 정의 시 평가와 공유를 추적한다.
  • None 센티넬의 조건과 입력 리스트 변경 계약을 설명한다.
  • /, * 및 *args·**kwargs의 역할과 충돌 오류를 구분한다.

기본값은 정의를 실행할 때 계산한다

def bad_add(item, items=[]):에서 []는 이 def 실행 시 한 번 평가된다. 이후 items를 생략한 호출은 같은 기본값 객체를 사용한다. 호출마다 새 빈 리스트를 만든다는 해석은 틀리다. 함수 정의를 다시 실행해 새 함수 객체를 만들면 그 새 정의의 기본값은 다시 평가된다. 따라서 영원히 프로그램 전체에서 한 번이라는 말도 부정확하다.

bad_add(1)의 반환 리스트를 a가 참조하고 bad_add(2)는 그 같은 리스트에 2를 추가한다. 두 호출 뒤 a,b 모두 [1,2]이고 a is b는 True이다. 이 문제는 기본값 평가 규칙과 가변 객체 변경이 함께 만들어 낸다. 숫자처럼 불변 객체인 기본값을 쓴다는 이유만으로 함수의 다른 부작용까지 사라지는 것은 아니다.

생략 표시와 실제 입력을 구별한다

items=None을 기본값으로 두고 if items is None: items=[]를 실행하면 생략한 호출마다 새 리스트가 생긴다. if not items를 쓰면 호출자가 보낸 빈 리스트도 거짓으로 판정되어 바꿔치기할 수 있다. is None은 생략 표시로 정한 그 한 객체만 검사하므로 전달된 빈 리스트의 정체성을 보존한다.

이 설계는 None을 유효한 리스트 입력으로 취급하지 않고 생략과 같은 뜻으로 사용한다는 계약을 전제로 한다. None 자체도 의미 있는 입력으로 받아야 한다면 별도의 유일한 센티넬 객체를 사용할 수 있다. add(3,e)는 e를 변경하고 같은 e를 반환하는 함수이다. 새 기본 리스트를 만든다는 사실은 명시적으로 전달된 리스트를 복사하거나 변경에서 보호한다는 뜻이 아니다.

호출 모양을 인터페이스로 제한한다

pack(name, /, *items, sep=":", **options)에서 / 앞의 name은 위치로만 받는다. *items는 남은 위치 인자를 튜플에 모으고 그 뒤 sep는 키워드로만 받는다. **options는 남은 키워드를 새 사전에 모은다. 위치 전용 name과 options의 문자열 키 name은 서로 다른 칸이므로 pack("A",name="B")는 허용된다. 튜플·사전의 새 포장이 안의 가변 객체까지 복사하는 것은 아니다.

반면 choose(x,*,scale=1)의 x는 위치 또는 키워드로 받을 수 있다. choose(2,x=3)은 x 자리를 두 번 채워 TypeError가 나며 함수 본문을 시작하지 않는다. 인자 표현식 자체는 호출을 시도하기 전에 평가되므로 본문이 실행되지 않았다고 인자 표현식의 부작용까지 없었다고 할 수는 없다. *seq는 위치 인자를 풀고 **mapping은 키워드 인자를 푼다. **의 키는 문자열이어야 하고 같은 키워드를 중복 공급하면 오류가 난다.

def bad_add(item, items=[]):
    items.append(item)
    return items

a = bad_add(1)
b = bad_add(2)
print(a, b, a is b)

def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

c = add(1)
d = add(2)
print(c, d, c is d)
e = []
print(add(3, e), e)

def pack(name, /, *items, sep=":", **options):
    return name, items, sep, options

print(pack("A", 1, 2, sep="-", name="B"))

def choose(x, *, scale=1):
    return x * scale

try:
    choose(2, x=3)
except TypeError:
    print("TypeError")

중간 과정을 따라가는 예제

세 함수와 pack·choose를 보존 코드 순서로 호출한다. 전달 자료는 내장 list·int·str이며 잡은 TypeError 뒤 실행을 이어간다.

  1. bad_add 정의의 기본 리스트 L에 1을 추가해 a→L이 되고 다음 호출에서 2를 추가해 b→L이 된다. 두 출력 표현식을 평가할 때 둘 다 [1,2]이며 동일 객체이다.
  2. add의 c,d 호출은 각각 None 검사 뒤 새 리스트를 만들어 [1]과 [2]를 반환한다. c is d는 False이다. e=[]를 넘긴 호출은 None이 아니므로 기존 e에 3을 넣어 [3] [3]을 출력한다.
  3. pack 호출에서 name="A", items=(1,2), sep="-", options={"name":"B"}이다. 위치 전용 name과 남는 키워드 name을 구별하여 반환 튜플을 출력한다.
  4. choose(2,x=3)은 x 중복 지정으로 TypeError를 일으킨다. 예외 이름을 포착해 출력한다. choose 본문의 곱셈은 이 호출에서 수행되지 않는다.

기본 인자 공유와 별도 리스트 생성, 위치 전용과 키워드 중복을 실제 출력에서 구별한다. 실제 stdout: [1, 2] [1, 2] True [1] [2] False [3] [3] ('A', (1, 2), '-', {'name': 'B'}) TypeError

종이와 본문으로 직접 해보기

종이 활동: def tag(prefix, /, value=0, *, loud=False, **extra)를 정의했다고 하자. tag("A",value=2,loud=True,prefix="B")의 네 매개변수 값을 적고, tag(prefix="A")가 유효한지 판정한다. 정의는 실제 실행하지 않는다.

힌트 보기

/ 앞의 prefix는 키워드로 채울 수 없다. 그러나 extra 안의 prefix 키는 그 매개변수를 채우는 것과 다르다.

풀이 보기

첫 호출은 prefix="A", value=2, loud=True, extra={"prefix":"B"}이고 유효하다. 네 매개변수는 prefix/value/loud/extra이다. tag(prefix="A")의 키는 extra에 남을 수 있지만 필수 위치 전용 prefix가 채워지지 않아 TypeError이다. 인자 종류와 개수까지 확인하는 것이 활동의 핵심이다.

오해와 반례

기본값 []는 호출할 때마다 새로 만들어지며 **kwargs는 모든 이름 충돌을 해결한다.

생략 호출은 같은 기본 리스트를 공유한다. **kwargs가 있어도 위치/키워드 겸용 매개변수를 두 번 공급하면 TypeError가 난다. 위치 전용 매개변수와 **kwargs 키의 같은 철자가 공존하는 특별 경우를 일반적인 중복 허용으로 확대하지 않는다.

자기점검

bad_add의 a가 나중에 [1,2]가 된 이유는 무엇인가?

답과 이유 보기

두 생략 호출이 같은 기본 리스트를 변경했기 때문이다.

a는 첫 반환 시 리스트의 사진을 저장한 것이 아니라 같은 객체를 계속 참조한다.

전달된 빈 리스트를 유지하려면 if not items와 if items is None 중 무엇을 쓰는가?

답과 이유 보기

이 계약에서는 if items is None이다.

빈 리스트는 거짓이지만 None과 다른 객체이다. 생략 표시만 검사해야 명시적 입력의 정체성을 보존한다.

pack("A",name="B")에서 위치 전용 name의 값은 무엇인가?

답과 이유 보기

"A"이며 options의 name 키 값은 "B"이다.

/가 그 매개변수를 키워드 대응에서 제외하므로 남는 키워드는 **options에 들어간다.

한 단계 더

심화: 함수 객체 F 하나를 정의하고 기본 리스트를 생략한 정상 호출만 k번 수행하며 각 호출이 한 원소를 append한다고 하자. 초기 길이 0이고 매 호출 길이가 정확히 1 증가하므로 k번째 직후 길이는 k이다. 이전 반환값을 참조하는 이름도 그 길이를 본다. 명시적인 items 인자가 있는 호출이나 외부 clear는 이 귀납의 조건 밖이다. None 방식에서는 생략 호출마다 새 리스트를 만들므로 서로 다른 호출의 반환 리스트는 별도 객체이다. 다만 반환 리스트 안에 같은 가변 item을 넣으면 내부 원소는 공유될 수 있어 깊은 독립성까지 보장하지 않는다.

소단원 6.4

문서화와 type hint 입문

n: int라고 적으면 문자열 입력이 실행 전에 자동으로 막힐까?

준비 개념과 학습 목표

준비 개념

  • 인터페이스는 호출자가 알아야 하는 입력·출력·오류·부작용의 약속이다. 코드 내부 구현 전체를 읽지 않고도 이 약속으로 함수를 사용할 수 있어야 한다.
  • 정적 검사는 코드를 실행하지 않고 타입 정보 등을 분석하는 별도 도구의 작업이다. 실행 시 if 검사로 입력을 거절하는 것과 구별한다.
  • 자가진단: print와 return은 다른 관찰이며 None은 정수 0이 아니다. 정수 삼각합은 1+2+…+n이고 n=0일 때 빈 합은 0으로 정의한다.

학습 목표

  • docstring에 계약·오류·부작용을 적는다.
  • 타입 힌트·런타임 검사·수학적 정확성의 보장 범위를 구분한다.
  • help와 __doc__·__annotations__의 역할을 설명한다.

문서는 호출자의 질문에 답한다

docstring은 함수 본문의 첫 문장으로 놓은 문자열 리터럴이며 함수의 __doc__로 읽을 수 있다. 첫 줄은 하는 일을 짧게 설명하고 빈 줄 뒤 입력 조건·반환 의미·오류·부작용을 적는다. 인자 이름의 나열만으로는 n=-1이나 True를 허용하는지, 출력만 하는지 값을 반환하는지 알 수 없다.

triangular의 계약은 내장 int이면서 n≥0인 입력의 1부터 n까지 합을 반환하고 bool은 거절하는 것이다. 다른 타입은 TypeError, 음수 int는 ValueError를 일으킨다. 호출자 객체를 변경하거나 print하지 않는다. bool은 int의 하위 타입이므로 isinstance(n,int)만 검사하면 True도 통과한다. 여기서는 type(n) is int를 택해 하위 타입까지 거절하는 좁은 계약을 실제 코드와 맞춘다.

힌트는 실행 강제 장치가 아니다

n: int와 -> int는 인자·반환값에 관한 타입 annotation이다. 보통 Python 실행기는 이 힌트만 보고 입력을 검사하거나 값의 타입을 바꾸지 않는다. hinted("7")은 문자열 "7"을 그대로 반환한다. 정적 검사기는 이 호출을 진단할 수 있지만 이번 활동에서는 검사기를 실행하지 않았다. 검사 결과와 실행 결과는 다른 증거이다.

코드의 명시적 if 검사는 실제 입력을 거절한다. 하지만 -> int만으로 n≥0, 종료, 정확한 삼각합, 파일 쓰기 없음까지 보장하지 않는다. Python 3.12에서는 별도 future 선언이 없는 이 예제의 annotation 표현식이 함수 정의 때 평가되어 __annotations__에 기록된다. 미래 판본의 annotation 평가 방식이나 문자열로 지연시킨 경우를 이 예제와 섞지 않는다.

문서 관찰과 계산의 검증을 분리한다

help(triangular)는 객체의 도움말을 표시하고 __doc__는 기록된 문자열을 제공한다. 도움말의 서식과 표시되는 부가 정보는 도구 환경에 따라 달라질 수 있다. 보존 예제는 help의 출력을 메모리 문자열로 포착해 계약 문장이 포함되는지만 확인한다. 인자 없이 help()를 호출하는 대화형 모드는 사용하지 않았다.

n*(n+1)//2는 이 계약의 정수 계산이다. 연속한 두 정수 중 하나는 짝수이므로 나눗셈이 정확히 떨어져 //가 원하는 정수 합을 준다. Python int에는 C의 고정 폭 signed overflow와 같은 규칙을 적용하지 않는다. 그렇더라도 극도로 큰 입력의 메모리·시간 자원까지 무조건 보장하는 것은 아니다. 문서가 맞는지, 코드가 조건을 검사하는지, 공식이 정확한지는 각각 별도로 확인한다.

import contextlib
import io

def hinted(n: int) -> int:
    return n

print(hinted("7"), type(hinted("7")).__name__)

def triangular(n: int) -> int:
    """Return the sum of integers from 1 through n.

    Require a built-in int n >= 0; reject bool.
    Raise TypeError for other types and ValueError for negatives.
    Do not print or mutate caller objects.
    """
    if type(n) is not int:
        raise TypeError("n must be a built-in int")
    if n < 0:
        raise ValueError("n must be nonnegative")
    return n * (n + 1) // 2

print(triangular(0), triangular(4))
for value in (True, -1):
    try:
        triangular(value)
    except (TypeError, ValueError) as error:
        print(type(error).__name__)
print(triangular.__annotations__["n"] is int)
print(triangular.__doc__.splitlines()[0])
help_text = io.StringIO()
with contextlib.redirect_stdout(help_text):
    help(triangular)
print("Require a built-in int" in help_text.getvalue())

중간 과정을 따라가는 예제

보존 코드의 hinted, triangular, 도움말 포착을 실행한다. future annotations 없이 Python 3.12를 사용하며 두 잘못된 입력만 명시적으로 포착한다.

  1. hinted("7")의 본문은 그대로 반환한다. print는 7을 표시하지만 type 결과 str가 함께 출력되어 문자열임을 확인한다.
  2. triangular(0)은 0*1//2=0, triangular(4)는 4*5//2=10이다. 내장 정수·비음수 조건을 모두 통과한다.
  3. True는 type(True) is int가 거짓이므로 TypeError이다. -1은 내장 int이지만 음수 검사에서 ValueError이다. 두 예외 이름을 포착하여 출력한다.
  4. __annotations__["n"]이 int인지 확인하고 __doc__ 첫 줄을 출력한다. help(triangular)의 메모리 출력에 계약 문장이 들어 있는지 검사해 True를 출력한다. 함수의 수학적 정확성은 이 도움말 검사만으로 증명되지 않는다.

힌트의 비강제성, 명시적인 오류 검사, 문서 조회를 실제 관찰했다. 실제 stdout: 7 str 0 10 TypeError ValueError True Return the sum of integers from 1 through n. True

오해와 반례

타입 힌트와 help가 있으면 입력 유효성과 결과 정확성이 자동으로 보장된다.

hinted("7")이 str를 반환하는 실제 반례가 있다. help는 작성한 설명을 표시할 뿐 코드가 설명을 지키는지 증명하지 않는다. 반환 타입이 int이어도 n+1을 반환하면 대부분의 n에서 삼각합과 다르다. 계약 검사와 계산 증명, 지정 사례 시험을 구분한다.
