정수·실수·bool

7과 7.0이 같다면 왜 자료형은 다를까?

준비 개념과 학습 목표

준비 개념

  • 값은 계산에 쓰는 데이터이고 자료형은 가능한 값과 지원 연산의 규칙이다. type(x)는 객체의 자료형을 얻는다.

  • 식은 평가하여 값을 얻는 코드다. 2+3은 값 5를 얻고 n<10은 비교 결과를 얻는다.

  • print는 값을 화면에 나타내며 표시 글자만으로 원래 자료형이나 정확한 저장값을 모두 알 수는 없다.

학습 목표

  • int·float·bool의 역할과 값/형 비교를 구분한다.

  • 참값 판정과 숫자 표현의 자원 조건을 설명한다.

물건 한 개와 “허용함”이라는 답을 같은 숫자 1로 받으면 어떻게 구별할까?

Python에서 True==1은 참이고 isinstance(True,int)도 참이다. 하지만 수량 입력과 승인 상태는 문제에서 서로 다른 의미다. “내장 int인 개수만 받고 bool은 거절한다”는 계약을 쓰면 값 비교뿐 아니라 정확한 자료형 검사도 필요하다. 이 정책은 사용자 정의 정수 타입까지 거절한다는 선택이다.

비어 있지 않은 문자열의 참값은 그 안의 단어를 해석한 결과가 아니다. bool("no")는 참이다. 텍스트 승인 입력을 해석하려면 허용할 단어와 공백·대소문자 정책을 별도로 정한다. 참값 변환만으로 의미를 만들지 않는다.

큰 정수를 float로 바꿀 때도 “같은 숫자처럼 보임”과 “정확히 보존함”을 나눈다. 아래 큰 정수 사례는 실제 실행기에서 관찰한 보통 이진64 float를 가정한다. 수학의 무한 실수나 모든 구현의 동일 비트 구조를 주장하지 않는다.

정수와 실수 표현은 서로 다른 계약이다

int는 음수·0·양수 정수를 표현하며 계산 범위가 고정 32비트로 제한되지 않는다. 2**100 같은 큰 정수도 정확히 계산할 수 있지만 메모리·계산 시간은 유한하다. “무제한 정밀도”를 자원이 무한하다는 말로 이해하지 않는다. 아주 긴 십진 문자열 변환에는 구현의 길이 제한도 있을 수 있다.

float는 수학의 모든 실수를 정확히 저장하는 타입이 아니다. 흔히 이진 부동소수점 근삿값을 쓰며 범위와 정밀도가 유한하다. 7.0은 이 예에서 정확하지만 모든 소수점 값이 그렇지는 않다. 7==7.0은 수치 값 비교로 True여도 type(7) is type(7.0)은 False다. 같다는 비교와 같은 자료형이라는 비교는 다르다.

bool은 조건의 결과이며 일반 텍스트와 다르다

bool의 두 값은 True와 False이고 첫 글자의 대소문자가 코드 문법의 일부다. n<10은 비교하여 bool 값을 낸다. bool은 int의 하위 타입이므로 True+2는 3이 된다. 이 규칙이 참/거짓을 수량으로 무조건 취급하라는 설계 권고는 아니다. 어떤 입력이 순수한 수량 정수여야 한다면 bool 허용 여부도 명세할 수 있다.

bool(0)은 False, bool(7)은 True다. 문자열은 빈 문자열만 False이고 bool("False")는 내용이 거짓이라는 영어 단어여도 True다. 숫자 0, 문자열 "0", False는 서로 다른 객체와 규칙을 가진다. 조건식에서 참값을 검사하는 것과 사용자가 입력한 "yes/no"를 해석하는 일은 구분한다.

n = 7
x = 7.0
ok = n < 10
print(type(n).__name__, type(x).__name__, type(ok).__name__)
print(n == x, type(n) is type(x))
print(True + 2, bool(0), bool('False'))

실행의 타입과 문제의 의미를 함께 확인한다

위 코드를 순서대로 읽으면 n은 int 7, x는 float 7.0, ok는 bool True다. 첫 출력은 int float bool, 둘째는 True False, 셋째는 3 False True다. 집필자는 같은 코드를 실제 실행했지만 학습자는 먼저 종이에 예측하고 실행 없이도 이유를 확인할 수 있다.

점수처럼 이산 개수를 다루는 문제와 측정 온도처럼 근사값을 다루는 문제는 다른 타입 선택 이유를 갖는다. 값의 범위·단위·허용오차를 문제 명세에 적어야 한다. 자료형이 float라는 이유로 모든 물리 측정이 옳아지거나 int라는 이유로 음수 입력이 정당해지는 것은 아니다.

bool을 개수로 받는 틈

정확한 내장 int이며 0–9인 개수만 허용한다. 검사 A는 isinstance(x,int)와 범위만 확인하고 B는 type(x) is int와 범위를 확인한다. x=True와 x=0을 비교하라.

  1. A는 True를 int 하위 타입으로 받아 수치 1의 범위까지 통과시킨다.

  2. B는 True의 자료형이 bool이라 거절한다. 두 검사 모두 내장 정수 0은 허용한다.

  3. B도 -1을 허용하지 않으므로 타입 검사와 범위 검사는 별도 문이다.

이번 계약에 맞는 것은 B다. 승인 상태를 물건 개수로 오해하지 않는다.

본문의 하위 타입 설명을 실제 입력 계약의 반례로 연결한다.

서로 다른 큰 정수가 같은 근삿값으로 합쳐짐

N=2**53에서 float(N)과 float(N+1), 두 값을 다시 int로 바꾼 결과를 비교한다.

  1. N은 9007199254740992이고 N+1은 정확한 다른 int다.

  2. 이 실행 환경에서 두 float는 같은 값으로 반올림되어 둘 다 정수로 돌아오면 N이다.

  3. int끼리 N==N+1은 False인데 변환 뒤 비교는 True다. 정밀도를 잃은 뒤 원래 차이를 복원할 수 없다.

정확한 식별번호나 개수를 float로 왕복시키면 작은 1의 차이도 사라질 수 있다.

변수 바인딩과 객체

y=x 뒤에 x를 바꾸면 y도 항상 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 이름은 코드에서 값을 가리키기 위해 쓰는 표지다. 바인딩은 그 이름이 현재 어떤 객체를 가리키는지의 대응이다.

  • 리스트는 [2]처럼 순서 있는 항목을 담는 객체다. a[0]은 첫 항목이며 이 예에서는 값을 바꿀 수 있다.

  • ==는 값의 비교이고 is는 같은 객체인지의 비교다. 두 리스트가 같은 항목을 가져도 같은 객체일 필요는 없다.

학습 목표

  • 이름 재바인딩과 객체 변경을 화살표로 추적한다.

  • 공유 참조·불변성·동일성의 경계를 설명한다.

친구와 같은 노트를 가리키다가 내 이름표를 새 노트로 옮기면 친구 노트도 바뀔까?

이름표를 옮기는 재바인딩과 노트의 내용을 바꾸는 객체 변경은 다르다. 이 단원의 상자 A/B는 설명용 식별자이며 실제 주소 숫자가 아니다. 리스트 안에 다른 리스트가 들어가면 바깥 이름뿐 아니라 안쪽 참조도 그려야 한다.

얕은 복사는 바깥 순서를 담는 새 객체를 만들지만 내부 객체까지 모두 복사한다는 뜻이 아니다. 독립 수정이 목표라면 무엇을 공유할지와 어느 깊이를 바꿀지를 명세한다. 객체가 중첩될 때 바깥 is 검사 한 번만으로 전체 독립성을 판정하지 않는다.

먼저 확인할 개념
  • 이름의 현재 상태

    재대입 전후에 읽는 값을 시간 순서로 추적한다.

  • REPL과 실행 상태

    이전 실행에 있던 이름과 새 실행의 이름을 구별한다.

객체에는 정체성·자료형·값이 있다

Python 데이터는 객체로 다루며 객체의 정체성(identity), 자료형(type), 값(value)을 구분한다. x=2는 이름 x를 정수 객체에 연결한다. 변수 이름 자체에 영구 int 타입이 붙는 것은 아니다. 뒤에 x="two"를 대입하면 이름은 문자열 객체에 재연결되며 기존 정수 객체의 타입을 문자열로 바꾸는 것이 아니다.

대입은 우변을 먼저 평가하고 결과 객체를 이름에 바인딩한다. y=x는 당시 x가 가리키던 객체를 y도 가리키게 한다. x의 미래 바인딩을 자동으로 따라가는 공식이 아니다. 정수는 불변 객체라 x=x+3은 기존 2를 안에서 5로 고치는 대신 계산 결과에 x를 다시 연결한다.

가변 객체를 공유하면 항목 변경이 함께 보인다

리스트는 가변이므로 a=[2]; b=a 뒤 두 이름은 같은 리스트를 가리킨다. a[0]=5는 a라는 이름을 다른 객체로 옮기는 것이 아니라 공유 리스트의 첫 항목을 바꾼다. 따라서 b도 [5]를 보며 a is b는 True다. b가 a의 문자를 복사한 것이라서가 아니라 같은 객체를 공유하기 때문이다.

a=[9]는 새 리스트를 만들고 a만 다시 연결한다. b는 기존 [5]에 남아 a is b는 False다. 위 코드의 출력은 5 2, [5] [5] True, [9] [5] False로 실제 확인했다. 숫자 재바인딩과 리스트 항목 변경을 같은 “변수 변경”이라는 표현 하나로 뭉뚱그리면 이 차이를 놓친다.

x = 2
y = x
x = x + 3
print(x, y)
a = [2]
b = a
a[0] = 5
print(a, b, a is b)
a = [9]
print(a, b, a is b)

동일성과 수명은 구현 세부를 과장하지 않는다

a=[1]; b=[1]은 별도 리스트를 만든다. a==b는 True지만 a is b는 False다. 숫자나 문자열의 같은 값을 구현이 재사용할 수 있으므로 값 비교에 is를 쓰지 않는다. id의 숫자 값을 특정 메모리 주소로 일반화하는 것도 Python 언어 전체의 보장과 CPython 구현 세부를 섞는 것이다.

더 이상 도달할 수 없는 객체는 구현의 메모리 회수 대상이 될 수 있지만 이 예로 즉시 언제 회수되는지 보장하지 않는다. 이름을 지워도 다른 이름이 같은 객체를 가리키면 그 경로는 남는다. 외부 파일·장치 수명은 숫자/리스트의 단순 바인딩만으로 제어된다고 가정하지 않는다.

  • 연산자는 +나 //처럼 값에 적용하는 규칙이다. 지원하는 자료형과 오류 조건도 그 규칙에 포함된다.

  • 형변환은 정해진 규칙으로 다른 타입의 값을 얻는 일이다. int("7")은 문자열을 정수로 해석한다.

  • 예외는 정상 값 대신 실행 중 오류를 알리는 경로다. try/except는 지정한 예외가 생길 때 처리하는 문법이며 뒤 단원에서 자세히 배운다.

학습 목표

  • 우선순위와 괄호, /·//·%·int의 차이를 계산한다.

  • 변환 성공·값 손실·문법 오류를 구분한다.

같은 수직선에서 아래로 내림과 0으로 가까워짐은 언제 다른 방향일까?

//는 정확한 정수 나눗셈의 바닥 몫이다. 음수의 나머지도 제수의 부호를 따라 정한다. a,b가 int이고 b≠0일 때 a=q b+r이라는 관계로 중간 결과를 검산한다. float 반올림까지 섞인 식을 같은 정확성 근거로 쓰지 않는다.

문법 우선순위는 종이에 보이는 기호를 어떻게 묶는지 정한다. -2**2는 -(2**2)이고 (-2)**2는 다른 식이다. 또한 **는 오른쪽으로 묶이므로 2**3**2는 2**(3**2)다. 음수 기호의 위치와 괄호를 먼저 정한 뒤 값을 계산한다.

우선순위는 식을 묶는 언어 규칙이다

2+3*4는 곱셈을 먼저 묶어 14이고 (2+3)*4는 20이다. 우선순위는 계산 결과를 보고 사후 선택하는 것이 아니라 Python의 문법 규칙이다. 복잡한 식은 괄호로 의도를 드러내고 타입도 함께 확인한다. 이 절은 built-in 숫자 연산만을 기본으로 한다. 사용자 정의 객체는 같은 연산자에 다른 동작을 제공할 수 있다.

/는 int 입력 두 개여도 float 몫을 낸다. //는 바닥 나눗셈으로 수학적 몫 이하의 가장 큰 정수 방향으로 간다. 정수 a,b와 b≠0이면 a=(a//b)*b+(a%b)이며 나머지는 0이거나 b와 같은 부호다. 나눗셈의 오른쪽이 0이면 정상 몫이 아니라 ZeroDivisionError가 생긴다.

변환 규칙이 산술 규칙과 같다고 가정하지 않는다

7/2=3.5, 7//2=3, 7%2=1이다. -7//2는 -3.5의 바닥인 -4이고 -7%2는 1이라 -7=(-4)*2+1이다. int(-3.5)는 0 방향 절삭이라 -3이다. //를 소수점 버림이라고만 설명하면 음수 반례를 놓친다. float에서 //도 정의되지만 이 항등식의 정확 계산 활동은 int에 한정한다.

int("7")은 7로 해석되어 +3이면 10이다. "7"+"3"은 문자열 연결로 "73"이고 "7"+3은 자동 숫자 해석이 아니라 TypeError다. int("3.0")은 정수 문자열 문법이 아니라 ValueError다. int(float("3.0"))으로 우회하면 입력 명세를 바꾸고 일반적인 소수 입력을 절삭할 수 있으므로 검증 실패를 감추지 않는다.

print(7 / 2, 7 // 2, 7 % 2)
print(-7 // 2, -7 % 2, int(-3.5))
print(2 + 3 * 4, (2 + 3) * 4)
print(int('7') + 3, '7' + '3')
try:
    int('3.0')
except ValueError:
    print('ValueError')

본문의 try 블록은 int("3.0")을 시도하고 ValueError일 때 문자열 ValueError를 출력한다. 예외가 발생하지 않았다는 뜻이 아니라 예상한 오류 경로를 포착한 것이다. 숫자 형변환은 잘못된 형식·범위 밖 근사값 등에서 실패할 수 있다. 모든 예외를 숨기기보다 어떤 입력이 어떤 오류로 거절되는지 계약을 쓴다.

오차 안에서 가깝다는 비교는 정확한 동일성의 대체 관계가 아니다. 절대 허용오차 0.1에서 0과 0.09, 0.09와 0.18은 각각 가깝지만 0과 0.18은 가깝지 않다. 따라서 “가까운 값은 전부 같은 그룹”이라고 연결하는 정책에는 추가 정의가 필요하다.

아래 허용오차 예는 rel_tol=0.0으로 두고 유한한 값만 비교한다. 오차 단위는 값과 같은 단위이며 장치의 정확도를 실제 측정한 수치가 아니다. 형식/범위 검증에는 별도 고정 규칙을 쓰며 예외를 0이라는 정상값으로 합치지 않는다.

유한 이진 분수와 십진수는 표현 범위가 다르다

0.1=1/10의 분모에는 5가 포함되어 유한 이진 분수로 정확히 표현할 수 없다. 유한 이진 분수는 정수 m과 음이 아닌 정수 k에 대해 m/2**k 꼴이며, 약분 뒤 분모에 5가 남는 1/10과 같을 수 없기 때문이다. 0.5=1/2처럼 분모가 2의 거듭제곱인 값과 대비된다. 설치된 CPython 3.12.7에서 0.1+0.2는 repr로 0.30000000000000004를 표시하고 ==0.3은 False다. 이는 표시 형식만의 문제가 아니라 입력 근사와 연산 반올림의 결과다.

근사 비교에는 목적에 맞는 오차 계약이 필요하다. 유한한 a,b를 비교할 때 math.isclose(a,b)는 |a−b|≤max(rel_tol*max(|a|,|b|),abs_tol)를 검사한다. NaN과 무한대에는 아래에서 설명하는 별도 규칙이 적용된다. 상대 허용오차는 값 규모에 비례하고 절대 허용오차는 0 근처에서도 작동한다. 허용오차를 크게 잡아 틀린 값을 숨기지 않는다. 돈의 정확한 십진 규칙이 필요하면 Decimal에 문자열로 값을 공급하거나 최소 단위의 정수로 표현하는 별도 설계를 검토한다.

근사 비교와 입력 거절은 서로 다른 계약이다

본문의 첫 출력은 False, 0.30000000000000004, True다. 1e-12와 0을 기본 상대 오차만으로 비교하면 False지만 abs_tol=1e-11이면 True다. float('nan')은 자기 자신과 ==로 비교해도 False이고 infinity는 유한 수가 아니다. 실수 입력이 유한해야 한다면 math.isfinite로 조건을 확인한다. isclose가 True인 infinity끼리의 비교도 유한 범위 검증을 대신하지 않는다.

parse_count의 명세는 문자열 raw의 양 끝 공백을 제거한 text가 ASCII 숫자 1–3개이고 값 0–100일 때 int를 돌려주는 것이다. 선행 0은 허용하되 부호·소수점·전각 숫자·빈 문자열은 거절한다. all은 모든 문자 조건의 논리곱이고 len은 길이다. 형식 검사 후 작은 길이만 int로 바꾸므로 이 예에서는 긴 정수 문자열 변환이 발생하지 않는다. raw는 남겨 두고 정규화된 text와 구분한다.

import math
print(0.1 + 0.2 == 0.3)
print(repr(0.1 + 0.2))
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-12, abs_tol=0.0))
print(math.isclose(1e-12, 0.0), math.isclose(1e-12, 0.0, abs_tol=1e-11))
print(math.isfinite(float('nan')), math.isfinite(float('inf')))
def parse_count(raw):
    text = raw.strip()
    if not (1 <= len(text) <= 3 and all('0' <= c <= '9' for c in text)):
        return None
    count = int(text)
    if not 0 <= count <= 100:
        return None
    return count
for raw in [' 7 ', '3.0', '-1', '101', '', '001', '７']:
    print(repr(raw), parse_count(raw))

검증 실패 자료를 몰래 0으로 바꾸면 실제 0과 실패가 섞인다. 원자료를 덮어쓰지 말고 거절 이유와 허용 정책을 추적 가능하게 남기되 개인정보는 필요한 범위만 보관한다. 데이터분석/NLP에서는 이런 입력형 검증과 학습용 전처리를 구분한다. 어휘·평균처럼 자료에서 배우는 전처리 값은 먼저 훈련/검증/시험을 분리한 뒤 훈련 자료에서만 정하고 다른 분할에 적용해야 한다. 여기의 고정 문법 검사는 학습 자료로 통계를 배운 작업이 아니다. 분할 전 고정 규칙으로 중복 그룹을 찾는 일과 전체 자료에서 어휘를 학습하는 일은 같지 않다. 구체적 그룹·시간 분할 조건은 NLP 단원에서 이어 설명한다.

다른 문제에 적용하기

가상 재고 기록의 원본 a=[[4],[5]]를 유지하고 새 기록 b에서 첫 개수를 raw=" 009 "로 갱신하려 한다. 형식은 공백 제거 뒤 1–3 ASCII 숫자, 범위 0–100이다. 얕은 복사 b=a.copy() 뒤 b[0][0]=int(raw.strip())를 쓰면 원본은 어떤가? 원본을 지키는 이번 두 층 복사를 설계하라. 이어 개수 n=9를 묶음 크기 4로 나누어 완전 묶음 수와 남은 수를 구하고, 직접 개수 객체 True를 받으면 exact int 정책에서 어떻게 처리할지 적어라. 근사 센서값의 isclose를 이 개수 검증에 대신 써도 되는가?

힌트 1

안쪽 리스트가 공유되는지 화살표를 그리고 raw/text/int를 별도 칸에 둔다.

힌트 2

두 안쪽 리스트를 각각 복사하고 q=n//4,r=n%4로 검산한다. bool은 int 하위 타입이지만 exact int 계약은 다르다.

풀이와 답 확인

  1. text="009"는 형식 통과, n=9는 범위 통과다. 원문 " 009 "는 그대로 보존한다.

  2. 잘못된 얕은 복사 경로에서는 공유 안쪽 객체가 바뀌어 a와 b 모두 [[9],[5]]가 된다.

  3. 초기 상태에서 b=[a[0].copy(),a[1].copy()]로 만든 뒤 b[0][0]=9를 하면 a=[[4],[5]], b=[[9],[5]]다. 일반 중첩 깊이의 복사 구현은 아니다.

  4. 9=2×4+1이므로 완전 묶음 2, 남은 수 1이다. 제수 4는 0이 아니다.

  5. 직접 입력 True는 exact int가 아니어서 타입 거절한다. 근사 float 관계는 형식/정확 개수/범위/공유 계약을 대신하지 않는다.

원문과 개수 값을 나누고 안쪽 복사 범위를 명시한다. 정상 새 기록 [[9],[5]], 원본 [[4],[5]], 묶음/나머지 (2,1), True는 타입 거절이다.
