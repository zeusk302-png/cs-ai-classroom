소단원 7.1

탐색·정렬의 사고

카드 더미에서 7을 찾는 일과 카드를 작은 순서대로 놓는 일은 무엇이 다를까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 길이 n인 리스트의 위치는 0부터 n−1이다. 빈 리스트에는 합법적인 원소 위치가 없다.

  • ==는 값 비교이고 return은 함수 호출을 끝내 결과를 돌려준다.

  • 자가진단: [7, 2, 7]의 첫 7 위치는 0이다. 정렬하면 [2, 7, 7]이 되어 첫 7 위치는 1이다.

학습 목표

  • 탐색의 결과 계약과 정렬의 결과 계약을 구분한다.

  • 선형 탐색의 첫 일치·부재·빈 입력을 추적한다.

  • 이분 탐색의 정렬 전제와 정렬 전처리 비용을 설명한다.

찾는 숫자가 없는데도 이분 삽입점은 왜 정수 위치를 줄까?

사전에서 새 단어를 넣을 자리는 그 단어가 이미 있다는 증거가 아니다. 정렬된 내장 정수 목록에서 bisect_left는 목표보다 작은 값들의 뒤, 목표 이상 값들의 앞 경계를 준다. 답은 0부터 len(a)까지 가능해 마지막 원소 위치와도 다르다.

같은 목표의 출현 구간을 찾으려면 왼쪽 삽입점 L과 오른쪽 삽입점 R을 나누어 읽는다. bisect_right는 목표 이하 값들의 뒤 경계다. 정렬·고정 입력과 정상 정수 비교 아래에서 목표는 [L,R)에 있고 개수는 R−L이다. L=R이면 일치 원소가 없다.

정렬은 출현 횟수를 보존하지만 원래 순서를 바꿀 수 있다. 이번 문제에서 경계로 구하는 것은 정렬 목록의 같은 값 구간이다. 원래 입력의 첫 위치를 그대로 돌려주는 결과로 해석하지 않는다.

먼저 확인할 개념
  • 인덱스와 슬라이스 경계

    len(a)는 끝 경계이며 읽을 원소 위치가 아니다.

  • 조건의 첫 참과 경계

    존재 검사에는 범위와 값 조건을 함께 확인한다.

먼저 원하는 결과를 정한다

탐색은 무엇을 찾고 무엇을 반환하는지부터 정한다. 여기서는 유한 내장 정수 리스트 a와 정수 target을 받고, 처음 같은 원소의 위치를 반환하며 없으면 None을 반환한다. 첫 위치를 요구했으므로 중복된 값이 있더라도 아무 위치나 반환하면 계약을 만족하지 않는다. 입력 리스트는 변경하지 않는다.

선형 탐색은 왼쪽부터 각 원소를 한 번씩 살펴본다. 위치 i를 검사하기 직전에는 0부터 i−1까지에 target이 없다는 사실이 쌓여 있다. 일치하면 그 앞에 일치가 없으므로 첫 위치이고, 끝까지 일치가 없으면 None이다. 이 불변 사실이 반복의 올바름을 설명한다.

def first_index(a, target):
    for i in range(len(a)):
        if a[i] == target:
            return i
    return None

정렬은 순서와 원소 보존을 함께 요구한다

오름차순 정렬은 결과의 모든 인접 원소가 앞≤뒤이고, 입력의 각 값과 출현 횟수를 그대로 보존해야 한다. [3, 1, 3]을 [1, 3]으로 만들면 순서는 맞아도 3 하나를 잃어서 정렬의 계약을 위반한다. 새 리스트를 반환하는지 원본을 바꾸는지도 인터페이스에 명시한다.

선택 정렬의 한 방법은 매 단계 아직 정리하지 않은 뒷부분의 최솟값을 찾아 첫 미정리 칸과 교환하는 것이다. 이 단원에서는 정수 값만 비교하고, 동일 값의 원래 순서를 유지하는 안정성은 보장하지 않는다. 서로 다른 레코드를 비교할 때 안정성은 별도의 조건이다.

정렬된 순서가 탐색에 주는 정보

이분 탐색은 정렬된 리스트에서 중간 값보다 target이 크면 왼쪽 절반을 버릴 수 있다. 정렬되어 있다는 전제가 버린 구간에는 답이 없음을 보장한다. 무정렬 [9, 1, 5]에서 중간 1을 보고 target=9의 왼쪽을 버리면 실제 답을 잃는다.

선형 탐색은 정렬을 요구하지 않는다. 한 번 찾으려고 먼저 정렬하면 정렬 비용을 추가하고 원래 위치도 바뀐다. 여러 검색을 위해 정렬된 복사본을 준비하는 경우에도 원래 위치와 복사본 위치를 구분한다. bisect의 삽입점 반환은 값의 존재 확인과 다르므로 경계와 값 비교를 추가해야 한다.

중간 과정을 따라가는 예제

정수 리스트 [5, 2, 5, 1]에서 first_index(a, 5)와 first_index(a, 9)를 추적하고, 선택 정렬의 각 단계 결과도 적는다.

  1. 5 탐색은 i=0에서 5==5로 즉시 0을 반환한다. 두 번째 5까지 진행하지 않는다.

  2. 9 탐색은 위치 0, 1, 2, 3의 네 값이 모두 다르므로 반복 뒤 None을 반환한다.

  3. 선택 정렬 첫 단계는 뒷부분 최솟값 1을 위치 0의 5와 교환하여 [1, 2, 5, 5]로 만든다.

  4. 다음 최솟값은 2, 이어 5이므로 배열은 유지된다. 원소 출현 횟수 1 한 개, 2 한 개, 5 두 개가 보존된다.

첫 5의 원래 위치는 0, 9는 부재 None이다. 정렬 결과 [1, 2, 5, 5]의 첫 5 위치 2는 원래 위치와 다르다. 모두 종이 예상이며 코드 실행 결과가 아니다.

비교할 점

기본의 첫 위치 탐색에서 삽입점 계약으로 바뀔 때 필요한 검사를 비교한다.

같은 값들의 원래 순서도 계약이다

값만 비교하는 레코드 [(2,"A"),(1,"X"),(2,"B")]를 안정적으로 정렬하면 어떤 순서인가? set으로 중복 값을 제거하는 것과 비교하라.

  1. 값의 오름차순은 1/2/2다.

  2. 안정성은 동일 값 A/B의 상대 순서를 유지해 [(1,"X"),(2,"A"),(2,"B")]를 준다.

  3. 값의 set은 1/2의 종류만 남겨 발생 수와 이름표를 보존하지 않는다.

정렬의 값/개수와 추가 안정성 조건을 나눈다.

비교할 점

풀이 보기

오해와 반례

탐색하기 전에 항상 정렬해야 하고, 0은 찾지 못했다는 뜻이다.

선형 탐색은 무정렬 입력에도 적용한다. 첫 원소에 답이 있으면 0이 올바른 위치이다. 부재 표지는 None으로 따로 정한다. 정렬 후 위치는 원래 순서의 위치와 다를 수 있다.

선형 탐색의 반복 불변식을 귀납적으로 설명해 보자. i=0에서는 앞부분이 비어 부재가 참이고, a[i]가 다르면 확인한 부재 구간이 한 칸 늘어난다. 정렬은 순서 조건과 값별 개수 보존을 별도로 검사하라. 비교가 일관되지 않는 사용자 객체, NaN, 실행 중 외부 변경은 이 정수·고정 입력 모형의 전제 밖이다.

소단원 7.2

작은 문제로 분해

긴 목록의 합을 구할 때 앞의 한 숫자와 나머지 목록의 합을 합쳐도 될까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 빈 목록의 합은 0으로 정한다. 덧셈의 항등원이라 다른 부분 합과 합쳐도 값이 유지된다.

  • a[lo:hi]는 lo 이상 hi 미만 구간이며 여기서는 실제 슬라이스 대신 경계 숫자로 구간을 표현한다.

  • 자가진단: [2, 4, 1]을 [2]와 [4, 1]로 나누면 2+(4+1)=7이다.

학습 목표

  • 분해·해결·결합 세 단계를 구분한다.

  • 부분 문제의 입력 계약과 전체 문제의 반환 계약을 연결한다.

  • 덮어쓰기·누락·중복 없는 구간 분할을 검사한다.

두 반의 평균을 똑같이 더해 나누면 전체 평균이 될까?

문제 분해에서 결합할 정보가 너무 적으면 답을 복구할 수 없다. 반별 평균만 저장하면 학생 수가 다를 때 전체 평균을 두 평균의 산술평균으로 구할 수 없다. 자체 정수 기록 구간의 (합,개수)를 저장하면 두 부분의 합과 개수를 각각 더해 전체 평균을 마지막에 구할 수 있다.

평평한 정수 목록의 구간 [lo,hi)는 현재 단원 기본과 같이 끝을 제외한다. 빈 구간의 요약은 (0,0), 한 원소 x의 요약은 (x,1), 결합은 (s1+s2,c1+c2)다. 평균 자체는 개수 0에서 정의하지 않고 None으로 정한다.

요약의 중립 원소가 무엇인지도 문제마다 다르다. 합의 0이 최댓값 문제의 빈 구간 값으로 자동 옮겨 가지는 않는다. 모두 음수일 때 빈 최댓값을 0으로 결합하면 없던 값을 답으로 만든다.

먼저 확인할 개념
  • 끝 제외 구간

    분할이 빠짐과 중복 없이 위치를 덮는지 확인한다.

  • 반환 관계와 경계 계약

    개수 0에서 평균 None이라는 반환 정책을 명시한다.

부분 문제에도 계약이 필요하다

큰 문제를 나누는 일은 이름만 여러 함수로 만드는 일이 아니다. 합계 함수 sum_part(a, lo, hi)의 계약을 0≤lo≤hi≤len(a)인 정수 경계에서 a의 [lo, hi) 구간 합을 반환한다고 정한다. 호출 중 a가 바뀌지 않고 원소가 정수라는 가정을 둔다.

구간은 lo를 포함하고 hi는 제외한다. lo=hi이면 빈 구간이어서 0을 반환한다. 길이 hi−lo가 1이면 a[lo]를 반환한다. 큰 입력을 작은 입력으로 바꾸더라도 같은 종류의 계약이 이어져야 작은 결과를 믿고 결합할 수 있다.

분할은 빠짐과 중복을 동시에 막는다

길이가 둘 이상일 때 mid=(lo+hi)//2로 나누면 [lo, mid)와 [mid, hi)가 겹치지 않으면서 원래 구간 전체를 덮는다. mid는 오른쪽 구간에만 속한다. 두 부분 합을 더하는 결합 규칙이 이 분할과 일치한다.

실수로 왼쪽 끝을 mid까지 포함하고 오른쪽도 mid부터 시작하면 가운데 원소를 두 번 더한다. 반대로 왼쪽은 mid 미만, 오른쪽은 mid+1부터 시작하면 가운데가 빠진다. 구간을 눈으로 그려 보는 이유는 이런 오류가 작은 예제에서도 실제 합계를 바꾸기 때문이다.

분해 방법과 구현 방법은 구분된다

작은 구간의 답을 결합하는 생각은 재귀로 구현할 수도, 작은 결과를 표에 저장하거나 명시적 작업 목록으로 처리할 수도 있다. 문제 분해 자체가 곧 자기 호출이라는 뜻은 아니다. 함수로 나누기와 재귀 호출은 서로 다른 설계 선택이다.

정수 합에서는 결합의 정확성을 덧셈과 분할의 성질로 설명할 수 있다. 부동소수점 덧셈은 계산 순서에 따라 반올림 결과가 달라질 수 있으므로 정수 예제의 정확한 결합을 모든 숫자형에 그대로 확장하지 않는다. 외부 입출력의 순서가 중요한 문제도 결합 순서를 따로 검토한다.

  3. [2, 4)는 [2, 3)의 4와 [3, 4)의 2를 결합하여 6이다.

소단원 7.3

재귀의 기저·진행

자기 자신에게 일을 맡기는 함수는 어디서 멈추며, 기다리던 계산은 언제 돌아올까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 0!=1로 정의하고 n≥1에서 n!=n×(n−1)!이다. 여기서 n은 음이 아닌 정수이다.

  • 함수 호출마다 매개변수 이름은 별도로 생긴다. 같은 이름 n이 여러 호출에 있어도 하나의 변수로 합쳐지지 않는다.

  • 자가진단: 3!=3×2×1=6이다. 재귀식의 마지막 0!은 0이 아니라 1이다.

학습 목표

  • 기저 조건·정의역·감소량을 함께 설명한다.

  • 호출과 복귀를 서로 다른 방향으로 추적한다.

  • 수학적 종료와 실제 실행 자원 제한을 구분한다.

중간에서 나눈 두 문제가 작아지려면 길이 1도 나눠야 할까?

분할 합을 직접 구현할 때 빈 구간과 한 원소를 둘 다 기저로 처리해야 한다. 길이 1의 mid=(lo+hi)//2는 lo이므로 기저 없이 나누면 오른쪽 [lo,hi)가 원래 문제와 같다. 자기 호출을 썼다는 것만으로 작아진 문제가 되지는 않는다.

계약 0≤lo≤hi≤len(a), 고정된 내장 정수 목록에서 span_sum은 길이 0에 0, 길이 1에 a[lo], 더 크면 두 반의 합을 더한다. 길이 m≥2에서 mid는 lo와 hi 사이에 있어 두 길이가 각각 m보다 작다. 비음수 정수 길이의 감소가 종료 근거다.

한 호출이 왼쪽 결과를 받은 뒤 오른쪽을 호출한다. 둘의 지역 lo/hi는 서로 다르고 바깥 호출의 경계는 덮어쓰이지 않는다. 이론의 유한 감소와 실제 인터프리터의 깊이/자원 제한은 별개다.

먼저 확인할 개념
  • 호출별 환경

    같은 이름 lo/hi를 각 호출별로 분리한다.

  • 반열린 분할의 결합

    빠짐/중복 없는 구간과 부분 합 계약을 확인한다.

작은 경우의 답을 먼저 확정한다

아래 factorial은 정상적인 Python 내장 int만 허용하고 bool은 허용하지 않는다. Python에서 bool은 int의 하위형이므로 type(n) is int를 써서 이 계약을 명시했다. 잘못된 형과 음수는 ValueError를 발생시켜 정상 결과 경로와 구분한다.

기저 n=0은 직접 1을 반환한다. n>0에서는 factorial(n−1)이 작은 문제이고 반환값에 n을 곱한다. 자기 호출만 있고 직접 답을 주는 기저가 없으면 기다림만 계속된다. 검사 때문에 본문 내부 재귀 호출의 입력도 같은 비음수 정수 계약을 만족한다.

def factorial(n):
    if type(n) is not int or n < 0:
        raise ValueError("nonnegative int required")
    if n == 0:
        return 1
    return n * factorial(n - 1)

진행량이 바닥 있는 곳으로 내려간다

n을 진행량으로 잡으면 재귀 호출마다 1씩 감소하고, 허용된 입력은 비음수 정수이다. 4→3→2→1→0처럼 0에 도달하여 기저를 실행한다. 이 논증은 이상적인 충분한 자원 모형에서 유한 단계 종료를 설명한다.

n==0이라는 기저가 있어도 n+1로 호출하면 양수 입력에서 기저와 멀어진다. 또 n=1.5에서 1씩 빼면 0과 같아지지 않으므로 같은 종료 논증이 성립하지 않는다. 정의역, 기저 도달, 감소를 세 항목으로 함께 검토해야 한다.

돌아오는 순서와 현실의 한계

factorial(3)은 3×factorial(2)의 곱셈을 기다린다. factorial(2)는 2×factorial(1)을 기다린다. 가장 안쪽이 반환한 뒤 기다리던 곱셈이 안쪽에서 바깥쪽 순서로 완료된다. 호출자의 n=3은 작은 호출의 n=2로 덮어써지지 않는다.

수학에서 모든 유한 n에 대해 유한 호출 수가 있다고 해서 실제 Python에서 임의로 큰 n을 재귀로 처리할 수 있다는 뜻은 아니다. 재귀 깊이와 메모리에 한계가 있고 RecursionError 등이 발생할 수 있다. 이 단원은 제한값을 올리지 않으며 입력별 실제 실행 성공도 주장하지 않는다.

비음수 정수에 대한 귀납법으로 올바름을 설명하라. 0은 정의대로 1이고, n−1에서 올바른 값을 반환한다고 가정하면 n에서 n×(n−1)!을 반환한다. 감소 논증과 결합의 올바름은 다른 역할을 한다. 반복 구현과 비교하면 기다리는 호출을 줄일 수 있지만 큰 정수 연산과 결과 저장 비용까지 사라지는 것은 아니다.

실행 추적과 비용

네 번 호출한 프로그램과 네 칸 읽은 프로그램의 비용은 같은 뜻일까?

준비 개념과 학습 목표

준비 개념

  • 미니복습: 입력 크기 n과 입력 값은 다르다. 길이 4의 목록에는 네 칸이 있고 각 칸의 정수 크기는 별도이다.

  • 한 번의 원소 동등 비교를 세는 모형을 먼저 정한다. 초·밀리초를 측정하는 것과 다르다.

  • 자가진단: 첫 위치에서 찾으면 비교 1회, 길이 n에서 부재이면 비교 n회이다. n=0이면 0회이다.

학습 목표

  • 입력·상태·반환·비용을 따로 기록한다.

  • 최선과 최악의 입력 사례를 구분한다.

  • O 표기에서 연산 비용 모형과 시간·공간을 명시한다.

반씩 나눴는데 왜 슬라이스 복사량은 원소 수보다 많을까?

구간을 두 경계 숫자로 넘기면 원본의 칸을 그대로 읽을 수 있다. 반면 매번 a[:mid], a[mid:]를 만들면 새 목록 칸에 원소 참조를 담는 작업이 반복된다. 같은 정수 합 계약도 구현의 복사 횟수는 다를 수 있다.

자체 모형은 복사한 목록 참조 칸 한 개를 한 단위로 센다. 길이 0/1에서는 복사 없이 기저로 끝내고 m≥2이면 두 슬라이스 길이의 합 m을 복사한다. 이 숫자는 전체 자료의 깊은 복사 바이트도 초 단위의 시간도 아니다.

재귀 비용에는 총 호출과 최대 동시 깊이도 따로 기록한다. 서로 다른 작은 문제를 한 번씩 처리하는 분할과 같은 문제를 반복 계산하는 재귀는 다르다. 기법 이름만 보지 말고 실제 호출 트리/복사 위치를 그린다.

추적표의 각 열은 다른 질문에 답한다

실행 추적표에는 현재 위치 i, 확인한 값, 비교 결과, 반환 여부, 누적 비교 수를 적는다. 같은 반환값 None이 나와도 n=0과 n=100의 부재 탐색은 비교 수가 다르다. 결과가 같다는 사실은 비용이 같다는 근거가 아니다.

이 단원은 고정된 유한 내장 정수 리스트를 대상으로 원소와 target의 동등 비교 한 번을 한 단위로 센다. 실제 Python 실행 시간에는 반복·함수 호출·메모리 접근 비용이 더해진다. 매우 큰 정수 비교의 비트 비용도 달라지므로 모든 비교가 실제로 같은 시간이 걸린다고 주장하지 않는다.

최악 입력과 성장률

길이 n에서 선형 탐색은 첫 위치 성공이면 한 번, 마지막 위치 성공이나 부재이면 n번 비교한다. n=0일 때는 비교 없이 None이다. 비교 수 기준 최악은 n이므로 O(n)이며, n≥1에서 최선은 상수 비교 수이다. 평균을 말하려면 성공 위치와 부재의 확률 모형을 추가해야 한다.

선택 정렬에서 매 단계 남은 모든 후보를 검사하면 원소 비교 수는 (n−1)+(n−2)+…+1=n(n−1)/2이다. n을 두 배로 했을 때 비교 수가 대략 네 배가 되는 이차 성장이다. 특정 구현의 교환 횟수나 대입 횟수와 같은 수라고 혼동하지 않는다.

동시에 살아 있는 호출과 큰 수의 비용

앞 소단원의 factorial(n)은 유효 입력에서 n+1번 호출하고, 기저 이외의 n개 호출이 곱셈 한 번씩 수행한다. 최대 동시 호출 깊이도 n+1이다. n번 곱셈이라는 연산 수와 n개 정도의 호출 환경을 기다리는 공간 비용을 구분한다.

곱셈을 단위 비용으로 가정하는 입문 모형에서는 선형 연산 수와 선형 호출 깊이라고 말할 수 있다. 그러나 Python 정수는 결과가 커짐에 따라 저장 비트 수와 곱셈 비용이 커지므로 실제 총 비트 연산 시간이나 총 메모리를 단순 n으로 확정하지 않는다. 재귀의 한계를 실측한 기록도 없다.

다른 문제에 적용하기

내장 정수만 담은 고정 리스트 a=[6,-2,0,5,-1]에서 비음수 항목의 (합,개수)를 구한다. 다음 함수의 경계는 0≤lo≤hi≤len(a)인 내장 정수이며 입력은 변경하지 않는다. [0,5)의 주요 부분 요약과 결과/평균을 쓰라. 0도 허용 항목이다. 잘못된 분할이 [0,3)과 [2,5)를 결합할 때 합이 맞아 보여도 어떤 계약이 깨지는가? 빈 입력과 모두 음수인 입력의 평균 정책도 정하라. 올바른 길이 5의 트리에서 총 호출/최대 깊이를 구하고 슬라이스 복사 구현의 12칸과 경계 전달의 0칸이 실제 메모리 바이트를 뜻하지 않는 이유를 설명하라. 

def selected_summary(a, lo, hi):
    if lo == hi:
        return 0, 0
    if hi - lo == 1:
        x = a[lo]
        return (x, 1) if x >= 0 else (0, 0)
    mid = (lo + hi) // 2
    s, c = selected_summary(a, lo, mid)
    t, d = selected_summary(a, mid, hi)
    return s + t, c + d
힌트 1

잎의 반환은 값뿐 아니라 허용 발생 수다. 0은 (0,1)이고 음수는 (0,0)이다.

힌트 2

중복 위치 2의 0은 합을 바꾸지 않지만 개수는 바꾼다. 개수 0에서 평균 나눗셈을 하지 않는다.

풀이와 답 확인

  1. 올바른 왼쪽 [0,2)는 (6,1), 오른쪽 [2,5)는 (5,2)다. 전체는 (11,3), 평균은 11/3이다.

  2. 잘못된 [0,3)은 (6,2), [2,5)는 (5,2)이므로 전체는 (11,4)다. 합 11은 같지만 위치 2의 0을 두 번 세어 평균 11/4로 틀린다.

  3. 빈 입력 및 모두 음수인 입력은 (0,0)이고 최종 평균을 None으로 정한다. 0 항목 하나는 (0,1), 평균은 0이다.

  4. 올바른 길이 5의 트리에는 잎 5개와 내부 노드 4개가 있다. 총 호출은 9회이고 최대 깊이는 4다. 경계를 전달하면 새 슬라이스의 참조 복사는 0칸이다.

  5. 같은 분할의 슬라이스 복사는 5+2+3+2=12칸이다. 이 값은 누적해서 복사한 참조 칸 수이며 실제 바이트 수, 피크 메모리 또는 성능 측정값은 아니다. 기본 입력 및 다른 외부 상태를 변경하는 코드는 없다.

합 11/개수 3/평균 11/3을 세 성분으로 검사한다. 중복 0은 합 검사만으로 놓치며 빈 평균과 평균 0은 다르다. 총 노드 9/최대 경로 4·복사 칸의 단위를 구분한다.
