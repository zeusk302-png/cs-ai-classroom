小節 5.1

list・tuple

同じ順序の二つのまとまりなのに、一方だけが要素を置き換えられるのはなぜだろう？

準備する概念と学習目標

準備する概念

  • ミニ復習：名前aはオブジェクトを指すラベルで、a = 式は右辺の評価後にラベルを結び付ける。
  • 長さnのシーケンスで有効な非負インデックスは0からn−1だ。n>0の場合、負のインデックス−1は最後の要素を指す。空のシーケンスには有効な要素インデックスがない。
  • 自己診断：[3, 1]の最初の要素は3で、長さは2だ。この二つを区別できれば始められる。

学習目標

  • リストとタプルを、順序のある参照のまとまりとして説明する。
  • appendの変更と戻り値、popの削除と戻り値を区別する。
  • タプル自体の不変性と内部オブジェクトの可変性を区別する。

順序を持つ二つの型

リストlistは要素の順序を保つ可変シーケンスだ。[3, 1]と[1, 3]は順序が異なるので等しくない。a[0] = 9は最初の要素の参照を置き換え、appendは末尾に要素を追加する。タプルtupleも順序を保つが、作成後に要素の参照や長さを直接変更できない。

空のタプルは()、一要素のタプルは(3,)だ。(3)は整数3を括弧で囲んだ式である。tuple(a)はaの要素参照を同じ順序で持つタプルを作る。その後リストの要素を置き換えてもタプルの要素は置き換わらない。これは内部オブジェクトまで複製する操作ではない。

メソッドの効果と戻り値

組み込みリストのa.append(x)はaの末尾にxを追加し、Noneを返す。変更後のリストには引き続きaでアクセスし、メソッドの戻り値から得るわけではない。a.pop()は最後の要素を削除してその要素を返す。空リストのpopはIndexErrorとなるため、正常に削除する契約には空でないという前提が必要だ。

内容Sのシーケンスへxをappendし、他の変更なしに正常にpopすると、削除された値はxで内容はSへ戻る。最後の要素が直前に追加したxであることが根拠だ。これは内容と長さの復元であり、メモリ割り当て履歴や全観察状態の復元ではない。失敗、中間の変更、同時変更があればそのまま適用できない。

不変性が及ぶ範囲

タプル([1],)にはリストを指す要素が一つある。その要素へ別のオブジェクトを代入できなくても、参照先のリストへappendできる。t = ([1],)の後にt[0].append(2)を紙上で追うと、tは([1, 2],)のように表示される。タプルが指すリストの同一性は変わらない。

変更されない記録を設計するなら、外側がタプルかどうかだけでは不十分だ。実行例の要素は不変な整数なので元の要素値を安全に比較できる。ファイル、ユーザー定義オブジェクト、入れ子リストがあれば、それぞれの変更契約を追加で調べる必要がある。

途中の過程をたどる例題

組み込みリストと整数だけを用い、各文を順に正常実行する。aとtの最終内容、およびlastを求めよう。 

a = [3, 1]
t = tuple(a)
a.append(2)
last = a.pop()
a[0] = 9
print(a, t, last)
  1. aは[3, 1]で、tは同じ順序の二整数を持つ(3, 1)だ。外側のリストとタプルは別のオブジェクトである。
  2. append(2)後のaは[3, 1, 2]だ。戻り値Noneはこのコードでは使わない。
  3. pop()が最後の整数2を返してlastへ結び付け、aは[3, 1]へ戻る。
  4. a[0] = 9はリストの最初の要素だけを置き換える。aは[9, 1]、tは(3, 1)、lastは2だ。

リストの変更は、すでに作成したタプルの要素参照を変えない。 韓国語原稿で保存した実際のstdout: 

[9, 1] (3, 1) 2

紙と本文で試してみよう

紙上でa = [4]; t = tuple(a); r = a.append(6); p = a.pop()を追おう。a,t,r,pを求め、(4)と(4,)の型も比べる。実行しない。

ヒントを見る

各メソッドの横に変更後の状態と戻り値を別々に書く。

解答を見る

append後はaが[4, 6]、rがNoneだ。pop後はaが[4]、pが6となる。tは(4,)のままだ。(4)はint、(4,)は一要素のtupleである。

よくある誤解と反例

タプルへ変換すると内部の全ての値が永久に固定される。

([1],)の内部リストはappendで変わる。タプルの不変性は直接保持する参照の置き換え禁止であり、参照グラフ全体の不変性ではない。

理解を確かめる

appendとpopは何を返す？

答えと理由を見る

appendはNone、正常なpopは削除した要素を返す。

appendはリストをその場で変更し、popは削除と値の返却を同時に行う。空リストのpopは正常には返らない。

a = [2]; t = tuple(a); a[0] = 8の後のtは？

答えと理由を見る

(2,)だ。

aの最初の要素の置き換えはtの要素を置き換えない。整数2自体も変わらない。

t = ([0],)でt[0].append(7)を行うとタプルの不変性に違反する？

答えと理由を見る

違反しない。内部リストが[0, 7]へ変わる。

タプルの要素は引き続き同じリストを指す。内部オブジェクトの変更とタプル要素への代入は違う。

もう一歩先へ

発展：シーケンスSを(s₀, …, sₙ₋₁)と書き、append(x)後の長さn+1とpop後の長さnという二つの契約を合成して内容の復元を証明しよう。整数要素の例のタプルは元の参照を保持する。内部に可変オブジェクトがあるとその変更までは防がないという反例も示す。性能やメモリ使用量はこの証明から結論しない。

小節 5.2

dict・set

名前の登場回数と、登場したかどうかに、なぜ別のデータが必要なのだろう？

準備する概念と学習目標

準備する概念

  • ミニ復習：for label in リストは要素を一つずつlabelへ結び付ける。
  • 登場回数には重複を含め、種類数からは重複を除く。b,a,bには登場3回と2種類がある。
  • キーは値を探すラベルで、値はそのラベルへ結び付けたデータだ。

学習目標

  • 辞書のキー検索、get、メンバーシップと集合の重複除去を区別する。
  • キーのhashable条件を単なる不変性という標語より正確に説明する。
  • 処理済み接頭部分の登場回数を帰納的な不変条件で証明する。

辞書の検索と挿入

組み込みdictはキーを値へ結び付ける。d[key]はキーがなければKeyErrorとなるが、d.get(key, default)は存在しないキーにdefaultを返す。get自体はそのキーを挿入しない。key in dやfor key in dは値ではなくキーを対象とする。したがって{"x": 3}で3 in dはFalseだ。

Python 3.12のdictはキーの挿入順を保つ。既存キーの値を更新しても位置は変わらない。削除してから再挿入すると末尾になる。setにはこの挿入順の契約がない。結果を整列して表示するなら、相互に比較できる値へsortedを適用する。この例のキーは小文字文字列なので比較できる。

ハッシュ可能性と集合

辞書キーと集合要素はhashableでなければならない。これは存続中にハッシュ値が安定し、等値比較ができ、等しいと比較される二オブジェクトのハッシュ値も同じであるという契約だ。逆にハッシュ値が同じだけでは等しいと結論できない。衝突し得るハッシュはオブジェクトの同一性や一意の番号ではない。

組み込みlist/dict/setは可変コンテナなのでキーにできない。tupleも全要素がhashableの場合だけhashableとなるため([1],)はキーにできない。ユーザー定義オブジェクトには別の契約があり、全可変オブジェクトが必ず禁止とは一般化しない。set(["b", "a", "b"])は2種類だけを残し、回数2と1を失う。空集合はset()で、{}は空辞書だ。

回数累積の不変条件

入力は有限の文字列リストで、他のコードがcountsを変えず、各更新が正常完了すると仮定する。最初のk要素を処理した後、countsの各値はその文字列が接頭部分に登場した回数だ。登場していない文字列はgetで0と解釈する。初期k=0では空辞書なので全回数は0である。

次のlabelの前の回数をget(label, 0)で読み、正確に1だけ増やす。他のキーはそのままなので帰納仮定がk+1でも成り立つ。各入力は一つの回数だけへ寄与するので保存した全回数の合計はkだ。例は文字列キーだけを使う。一般のキーでは1とTrueのように等しいキーが同じ項目を指し得るため、データを区別する仕様を別途確認する。

途中の過程をたどる例題

文字列リストb,a,bの頻度を数える。getでzを読んだ後に挿入されるかも確認し、種類を整列して表示しよう。 

counts = {}
for label in ["b", "a", "b"]:
    counts[label] = counts.get(label, 0) + 1
print(counts["b"], counts.get("z", 0), "z" in counts)
seen = set(counts)
print(sorted(seen))
  1. 空辞書で最初のbを処理するとgetが0を返し、代入でb: 1を挿入する。合計は1だ。
  2. aを処理するとa: 1を追加する。最後のbでは既存bの値だけを2へ更新する。辞書はb: 2,a: 1で合計3となる。
  3. counts["b"]は2、counts.get("z", 0)は0だ。getは挿入しないため"z" in countsはFalseになる。
  4. set(counts)はキーb,aの集合だ。sorted(seen)は整列したリスト["a", "b"]を作る。元の頻度はcountsだけに残る。

登場頻度と種類を別々に保存し、検索だけしたzは新しいキーにならない。 韓国語原稿で保存した実際のstdout: 

2 0 False
['a', 'b']

紙と本文で試してみよう

紙上で入力a,b,a,cの各接頭部分のcountsと回数合計を書こう。最後にget("z", 0)を行った後のキー数とset(counts)の種類数を比較する。実行しない。

ヒントを見る

空状態の合計0を書き、一要素を処理するたび一項目だけ1増やす。

解答を見る

辞書は順に{a: 1}、{a: 1, b: 1}、{a: 2, b: 1}、{a: 2, b: 1, c: 1}で、合計は1,2,3,4だ。getはzを入れないため、キー数も集合の種類数も3である。集合だけからaの登場回数2を復元できない。

よくある誤解と反例

ハッシュ値が同じなら同じキーで、setは元の登場回数を保持する。

ハッシュ衝突は等値性の証拠ではない。また["a", "a"]と["a"]は同じ集合{"a"}になるので、集合だけでは二リストの頻度を区別できない。

理解を確かめる

d = {"a": 1}でd.get("z", 0)後の"z" in dは？

答えと理由を見る

Falseだ。

getは既定値0を返すが挿入しない。

入力a,a,bの回数合計とsetの要素数は？

答えと理由を見る

合計3、種類数2だ。

countsは重複登場も数えるが、集合にはaとbが一度ずつだけ入る。

不変タプル([1],)をdictキーにできる？

答えと理由を見る

できない。

要素のlistがhashableではないのでタプルもhashableではない。外側の不変性だけでは足りない。

もう一歩先へ

発展：帰納的な不変条件を「全キーの正確な回数」と「全回数の合計k」に分けて証明しよう。合計だけが正しくても個別回数は誤り得る。例えばb,a,bにb: 1,a: 2を記録すると合計3でも仕様に違反する。正しさの証明にはキーごとの不変条件が必要で、実行速度や最悪時間の保証は含まない。

小節 5.3

入れ子構造とコピー

外側の箱をコピーしたのに、なぜ元の箱の内側が変わるのだろう？

準備する概念と学習目標

準備する概念

  • ミニ復習：[[1], [2]]には外側リスト一つと内側リスト二つがある。
  • a[0].append(9)は最初の内側リストの内容変更で、a[0] = [9]は外側の最初の要素の参照置換だ。
  • 二つの矢印が同じ箱を指すと別名参照の関係になる。表示が同じだけでは同じ箱とはいえない。

学習目標

  • 代入、浅いコピー、深いコピーの参照グラフを比べる。
  • 内側の変更と外側の要素置換が及ぶ範囲を説明する。
  • deepcopyのmemoが複製内部の別名参照を保つ条件と限界を説明する。

代入と浅いコピー

b = aは外側リストをコピーせず、bもaと同じリストへ結び付ける。一方、組み込みリストのb = a.copy()は新しい外側リストを作り、要素参照をそのまま保持する。aとbの外側の同一性は異なり、内側リストは共有される。深さを述べるときは値だけでなくコピーしたオブジェクトの層を示す。

b[0].append(9)は共有する内側オブジェクトを変えるのでa[0]にも9が見える。しかしb[1] = [7]はbの二番目の要素だけを新リストへ結び付ける。aの二番目は元の[2]のままだ。浅いコピーとはどの変更も独立しないという意味ではなく、外側と内部で独立する範囲が異なるという意味だ。

深いコピーとmemo

copy.deepcopyはコピーに対応している複合オブジェクトの構成要素を再帰的にコピーする。この組み込みリストと整数の例ではcの内側リストは元と別なのでc[0].append(5)はaやbを変えない。不変整数など共有して問題のないオブジェクトは、必ず新しい同一性を持つ必要はない。

一回のコピー処理は処理済みオブジェクトをmemoへ記録する。row = [0]; a = [row, row]の場合、正常な組み込みリストにc = deepcopy(a)を行うと、c[0]とc[1]は同じ複製行を指す。元のrowと複製行は別だ。元から分離しながら複製内部の共有構造を保つ。同じオブジェクトを見るたび必ず別々のコピーを作ると理解してはいけない。

コピー契約の適用限界

memoは自己参照構造の再帰処理も助ける。ただしdeepcopyを全オブジェクトの完全に独立した複製という普遍的契約にしてはいけない。ユーザー定義クラスは__deepcopy__で動作を変えられ、関数とクラスは元のオブジェクトが返される。ファイルやソケットなど外部資源は一般的な値コピーの対象ではない。

したがって本単元の論証は、正常実行する組み込みリストと整数のグラフを対象とする。業務データへコピーを導入するなら、共有すべき資源と分離すべき可変状態を先に決める。コピーは外部ファイルの複製、遠隔状態の固定、同時アクセスの原子化を行う機能ではない。

途中の過程をたどる例題

組み込みリストと整数だけを含むaから浅いコピーbと深いコピーcを作り、異なる種類の変更を順に追おう。 

from copy import deepcopy
a = [[1], [2]]
b = a.copy()
c = deepcopy(a)
b[0].append(9)
b[1] = [7]
c[0].append(5)
print(a, b, c)
  1. aは外側Aと内側[1],[2]を持つ。bの新しい外側Bはその二つの内側を共有し、cの外側Cは別の内側[1],[2]を持つ。
  2. b[0].append(9)は共有する最初の内側を[1, 9]へ変える。aとbの最初の要素の両方から見え、cの最初は[1]のままだ。
  3. b[1] = [7]はBの二番目の矢印だけを変える。aとcの二番目はそれぞれ[2]を維持する。
  4. c[0].append(5)は複製した最初の内側だけを[1, 5]へ変える。aは[[1, 9], [2]]、bは[[1, 9], [7]]、cは[[1, 5], [2]]だ。

共有する内側の変更と、外側の一要素の置換は、異なる経路へ影響する。 韓国語原稿で保存した実際のstdout: 

[[1, 9], [2]] [[1, 9], [7]] [[1, 5], [2]]

紙と本文で試してみよう

紙上でrow = [0]; a = [row, row]; b = a.copy(); c = deepcopy(a)を描き、b[0].append(4)、c[1].append(6)を追おう。a,b,cとc[0] is c[1]を求める。この変形は実行しない。

ヒントを見る

元の行Rと複製行R′を一つずつ描く。cの二要素を別々の行へ分けないようmemoの条件を使う。

解答を見る

aとbは共有Rにより共に[[0, 4], [0, 4]]となる。cはR′を二度指すので[[0, 6], [0, 6]]だ。c[0] is c[1]はTrue、c[0] is rowはFalseとなる。複製内部の別名参照と元からの分離を同時に満たす。

よくある誤解と反例

deepcopyは全参照を別々のオブジェクトへ変え、全資源を複製する。

繰り返す行は複製内部でも共有される。関数・クラスの返却やユーザー定義コピー規則も新オブジェクトの保証を制限する。外部資源を持つオブジェクトには明示的な別の資源契約が必要だ。

理解を確かめる

b = a.copy()は入れ子リストの内側まで独立させる？

答えと理由を見る

違う。外側だけを新しくし、内側参照は共有する。

浅いコピーの契約は外側の複合オブジェクトと内部の既存オブジェクト参照を区別する。

a = [[1]]; b = a.copy(); b[0] = [8]の後のaは？

答えと理由を見る

[[1]]だ。

bの外側の最初の要素だけを置き換えるので、共有していた元の内側オブジェクトやaの要素は変わらない。

row = [0]; a = [row, row]をdeepcopyすると複製の二行は必ず別々？

答えと理由を見る

違う。正常な組み込みリストのコピーでは同じ複製行を共有する。

memoが同じ元オブジェクトに対応するコピーを再利用し、複製内部の別名参照を保つ。

もう一歩先へ

発展：有限の組み込みリストのグラフで、元オブジェクトRに対応する複製R′をmemoで一度定めると考えよう。元の二つの矢印がRへ合流すれば、複製側の対応する矢印もR′へ合流する。これが共有構造を保つ根拠だ。循環があれば生成済み複製の参照を再利用し、終わらない複製を避ける。この説明はユーザー定義コピーフックや外部資源に関する普遍的定理ではなく、この発展のコードも実行していない。

小節 5.4

可変性・別名参照とエラー

一行の代入と一回の内部変更は、なぜ別の名前へ異なる影響を与えるのだろう？

準備する概念と学習目標

準備する概念

  • ミニ復習：名前のラベルとリストの箱を分けて描く。代入はラベルの矢印を変え得る。
  • ==は値の等値比較、isはオブジェクトの同一性比較だ。同じ内容の別々のリストを描ける。
  • [row] * 3は一要素シーケンスの反復だ。内側rowを三度新しく作ると最初から仮定しない。

学習目標

  • 繰り返す参照と新しい行の生成の違いを追う。
  • オブジェクト変更、名前の再代入、コンテナ要素の置換を区別する。
  • 戻り値Noneを再代入するエラーの原因を説明する。

オブジェクトのノードと参照の矢印

オブジェクトをノード、名前とコンテナ要素を矢印として描く。view = gridは同じ外側ノードへの矢印を一つ増やす。grid = 新しいリストはgridの矢印だけを新しい外側へ移す。元のノードを指すviewの矢印は自動で移らない。

view[1].append(8)はviewから二番目の要素をたどった内側ノードを変更する。そのノードを指す全経路で変更を観察できる。view[1] = [8]なら元の内側ノードではなく外側の一要素の矢印を置き換える。共有の問題を解くには変えたノードと矢印を明確に区別する。

反復と新オブジェクトの生成

[row] * 3はrowを指す参照三つを持つ新しい外側リストだ。三要素の内容が同じに見えるだけでなく、三要素が同じ行であることが重要だ。一経路で行を変更すると他の二経路でも変更後の行が見える。シーケンスの反復は要素自体を複製しない。

[[0] for _ in range(3)]では反復ごとに[0]式が新しい組み込みリストを作る。三行は同じ内容でも別オブジェクトだ。一方[row for _ in range(3)]は同じrow参照を三度入れるので共有はなくならない。内包表記という構文名だけで独立行を保証せず、繰り返す式を確認する。

同一性の検査と戻り値のエラー

組み込みリストx = [1]; y = [1]ではx == yはTrueでもx is yはFalseだ。isは内容比較用ではない。整数や文字列など不変オブジェクトは実装が再利用し得るので、値の等しさをisで確認する習慣を付けない。この例では明示的に共有する組み込みリストの同一性だけを検査する。

a = a.append(2)は先に元リストへ2を追加し、戻り値Noneを名前aへ結び付け直す。別名が元リストを指していれば、その名前から変更が見える。続くa.append呼び出しはNoneにリストのメソッドがないので失敗する。目的に応じてa.append(2)を単独で呼べばよい。これは紙上のエラー追跡で、エラー変形を実行した記録はない。

途中の過程をたどる例題

一行を三要素で共有した後、gridだけを新しい構造へ結び付ける。元構造を指すviewの変更と新gridの内容を比べよう。 

row = [0]
grid = [row] * 3
grid[0][0] = 7
view = grid
grid = [[1], [2], [3]]
view[1].append(8)
print(view)
print(grid)
print(view[0] is view[2])
  1. rowは[0]の内側Rだ。gridの三要素は全てRを指す。grid[0][0] = 7はRを[7]へ変えるので三要素全てが[7]に見える。
  2. view = gridは元の外側Gを共有する。grid = [[1], [2], [3]]はgridだけを新外側Hと新しい内側三行へ結び付ける。
  3. view[1].append(8)は引き続きRを見つけ、[7, 8]へ変える。Gの三要素はRを共有するのでviewは[[7, 8], [7, 8], [7, 8]]だ。
  4. HはRを共有しないのでgridは[[1], [2], [3]]だ。view[0]とview[2]は同じRだからis検査はTrueになる。

名前の新しい結び付けは既存の別名参照を移さず、共有行の変更は全共有経路で見える。 韓国語原稿で保存した実際のstdout: 

[[7, 8], [7, 8], [7, 8]]
[[1], [2], [3]]
True

紙と本文で試してみよう

実行せずrow = [0]; a = [row] * 2; b = a; a[0] = [5]; b[1].append(6); a = []を追おう。最終a,b,rowとb[0] is b[1]を求める。

ヒントを見る

最初の外側Gの二要素はRを共有する。最初の要素を置き換えると二つの矢印が分かれる。最後の行は名前aだけを移す。

解答を見る

最初の要素は新しい[5]を、二番目はRを指す。append後のRは[0, 6]だ。最終aは[]、bは[[5], [0, 6]]、rowは[0, 6]となる。b[0] is b[1]はFalseだ。Gを指すbは最後のa再代入で変わらない。

よくある誤解と反例

新しい値を代入すると全ての別名参照も一緒に変わり、内包表記なら内部共有もなくなる。

view = grid後のgrid再代入はviewを移さない。また[row for _ in range(3)]はrowを繰り返し参照する。名前への代入と内部生成式を別々に確認する必要がある。

理解を確かめる

x = [1]; y = [1]でx == yとx is yは？

答えと理由を見る

それぞれTrueとFalseだ。

内容は同じだが二つのリスト式が別々の組み込みリストを作る。

row = [0]; a = [row for _ in range(2)]は独立した二行？

答えと理由を見る

違う。同じrowを二度参照する。

繰り返す式rowは新リスト生成式ではない。独立行は[0]のように毎回新オブジェクトを作る必要がある。

a = [1]; b = a; a = a.append(2)後のaとbは？

答えと理由を見る

aはNone、bは[1, 2]だ。

右辺appendが先に既存リストを変更してNoneを返す。その後aだけがNoneへ結び付き、bは変更したリストを引き続き指す。

もう一歩先へ

発展：共有経路の集合を先に書けば、変更の影響範囲を予測できる。行Rを三要素が共有すると、Rへのappendは三経路全ての観察値を変えるが、一要素を新R′へ結び付けるとその経路だけが分かれる。契約には入力リストを変えてよいか、戻り値が新リストか、内部を共有するかを別々に書く。この参照モデルはメモリアドレス値、解放時点、スレッド安全性を保証しない。
