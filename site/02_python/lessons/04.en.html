Subtopic 4.1

if, elif, and else

When several conditions hold at once, which description does the computer choose?

Preparation and learning goals

Preparation

  • Assignment score=85 stores a value; score==85 compares for equality. This unit assumes built-in int scores, excluding bool, strings, and user-defined objects.
  • True and false are the results of testing conditions. < and <= differ in whether they include the boundary. 0<=score<=100 includes both endpoints.
  • Indentation identifies the statements in one branch. Distinguish the indented block after the colon from print outside the block.

Learning goals

  • Trace an if/elif/else chain that selects only the first true condition.
  • Explain how the score range, boundaries, and branch order affect the result.
  • Connect false values and short-circuit evaluation with conditions for avoiding errors.

Selecting a branch in order

if tests a condition and executes its indented block when true. An elif condition is tested only if earlier conditions were false. If else is present, it executes when every preceding condition is false. A single chain executes at most one block; with no else and all conditions false, it executes none of those blocks.

The example first classifies scores outside 0–100 as invalid. Valid scores of at least 90 are gold; lower scores of at least 80 are silver; the rest are practice. Checking a range is not type conversion. There is no code here to convert strings or handle input errors, and we do not claim that it safely validates values outside the integer contract.

Order changes the result

95 satisfies both >=90 and >=80. Putting the higher threshold first selects gold and never tests the silver condition. Putting >=80 first classifies 95 as silver and makes the later >=90 branch unreachable. Check overlapping conditions together with the first-selection rule.

Two separate if statements differ from a chain. Even after the first assigns gold for 95, a second independent if score>=80 can overwrite the label with silver. Separate if statements may be appropriate when two independent actions must both happen. First decide whether the problem requires one classification or several actions.

Truth testing and safe test order

Built-in values None, False, numeric zero, and empty strings and lists test as false. The integer −1 tests as true because it is not zero. Absence of a value and the number zero do not have the same meaning. and and or do not always return a bool; they return a selected operand. For example, 0 or 7 has the value 7.

and does not evaluate its right operand when its left operand is false. For an integer n, n!=0 and 10//n>=2 skips the division when n=0. Reversing the tests removes that protection. This avoids a zero denominator in that division; it does not guarantee protection against arbitrary objects or errors in other operations.

A worked example, step by step

Trace the complete code that classifies the fixed integer score=85 into four categories. 

score = 85
if not 0 <= score <= 100:
    label = "invalid"
elif score >= 90:
    label = "gold"
elif score >= 80:
    label = "silver"
else:
    label = "practice"
print(label)
  1. 85 satisfies 0<=85<=100, so the not condition is false and the invalid block is skipped.
  2. 85>=90 is false, so the gold block is skipped.
  3. 85>=80 is true, so label receives silver. The following else does not execute.
  4. print(label), outside the chain, writes silver and a newline. The actual preserved execution for this fixed input also printed silver.

One line: silver. This follows from the integer-input contract and the branch order above.

Try it with paper and the lesson

Without changing the code, suppose score is replaced by 79, 80, 90, or 101. Find label on paper. Also, what happens to 95 if the >=80 branch precedes >=90?

Show hint

Begin with the range check, test branches from left to right, and stop selecting at the first true condition.

Show solution

79 gives practice, 80 silver, 90 gold, and 101 invalid. With the reordered thresholds, 95 gives silver. These five activity inputs were traced only on paper.

Misconception and counterexample

Negative numbers are bad values, so they always test as false.

The built-in Python integer −1 tests as true. To reject negatives, state the problem’s condition explicitly, such as value<0. An allowed data range and the language’s truth-testing rule are different rules.

Show answer and reasoning

All those blocks are skipped. Reading an uninitialized name afterward could cause a separate error.

Show answer and reasoning

The left comparison is False, so and skips its right operand.

Explore further

Extension: partition all integer scores into values outside the range, [90,100], [80,89], and [0,79]. These sets are disjoint, and every integer belongs to exactly one. By cases, prove that the outside-range check followed by first-true selection chooses the corresponding label. The raw conditions score>=80 and score>=90 do overlap; a branch’s actual selection region also includes the falsity of earlier conditions. This classification proof assumes built-in integers, normal comparisons, and exception-free execution. Running a few scores does not prove safety for every data type.

Subtopic 4.2

while, for, and range

When adding 2, 4, 6, and 8, where should the loop stop?

Preparation and learning goals

Preparation

  • The update total+=i adds the current i to total and stores the result. Initializing total to zero supplies the starting state for addition.
  • One iteration is one execution of the body. while tests its condition before the body, so an initially false condition gives zero body executions.
  • A list is an ordered collection of values. for receives successive values from an iterable; range represents a regular sequence of integers.

Learning goals

  • Trace the condition, body, and update of while.
  • Distinguish a range’s start, excluded stop, direction, and zero-step error.
  • Explain progress and termination of a finite loop under stated conditions.

while asks the condition again

while i<9 executes its body while the current i is less than 9. It tests the same condition again after the body. Starting at i=2 and updating i+=2 gives test values 2,4,6,8,10, stopping at 10. After termination i is 10, not 8.

Check the progress that eventually makes the condition false. Without the update, i can remain 2 while the total keeps growing. while itself guarantees neither a fixed iteration count nor termination. Exceptions or external changes can also end real code, but here we consider only fixed integers and normal operations.

The contracts of for and range

for i in range(2,9,2) starts at 2, advances by 2, and provides 2,4,6,8, all less than 9. stop is excluded. range(3) represents 0,1,2, and range(4,4) is empty. range returns a distinct sequence-representing object, not a preconstructed list of every value.

With a negative step, values decrease and must remain greater than stop. range(9,1,-2) gives 9,7,5,3. A mismatched direction, such as range(2,9,-1), gives an empty range; step=0 raises ValueError. This unit restricts arguments to built-in int values. Actual range also accepts objects supporting the integer-index conversion contract, so arbitrary user objects are not covered here.

Comparing the two loops

for reassigns its loop variable to the next provided value. Assigning i=100 inside the body does not by itself change the next value provided by range. while, in contrast, uses the changed i in its next condition test. The two forms place update responsibility differently.

for terminates if it normally exhausts a finite range and each body execution also terminates. Not every iterable is finite; even finite input is insufficient if the body contains a nonterminating loop. The programs below add only four fixed values, without external input or list mutation, and obtain the same sum. Equal sums here do not establish that every while can be replaced by for without changing meaning.

A worked example, step by step

Trace the complete code that accumulates the same four numbers with for and while. 

for_total = 0
for i in range(2, 9, 2):
    for_total += i
while_total = 0
i = 2
while i < 9:
    while_total += i
    i += 2
print(for_total, while_total)
  1. Starting with for_total=0, for provides i values 2,4,6,8. The running totals are 2,6,12,20.
  2. Initialize while_total=0 and i=2 separately. The first test is true; after adding 2, update i to 4.
  3. The next iterations add 4,6,8, producing totals 6,12,20 and updating i to 6,8,10 respectively.
  4. At i=10, 10<9 is false. print writes 20 20 and a newline, matching the actual preserved code output.

Both sums are 20. Distinguish the final while value i=10 from the last value 8 provided by for.

Try it with paper and the lesson

Write the values and sum of range(9,1,-2) on paper. Separately, change only the while example’s initial i to 9 and retain while_total=0. What are the sum and body-execution count?

Show hint

With a negative step, check value>stop. while adds nothing before its first condition test.

Show solution

9,7,5,3 sum to 24. With initial i=9, 9<9 is false, so the sum is 0 and the body runs zero times. The activity code was not executed.

Misconception and counterexample

Because the stop is 9, range(2,9,2) adds 9 at the end.

stop is excluded, and stepping by 2 would not reach 9 anyway. The values are 2,4,6,8. Check both the endpoint and the step.

Check your understanding

Show answer and reasoning

Zero.

With the default positive step, the start is not less than stop, so it is empty from the outset.

Does step=0 create a nonterminating range?

Show answer and reasoning

A zero step is disallowed, not treated as an empty sequence or an automatic update.

If the body of for i in range(3) assigns i=100, what value is provided next?

Show answer and reasoning

for assigns the iterator’s next value to the loop variable anew.

Explore further

Extension: prove that immediately after k normal iterations of the while example, i=2+2k and the accumulated sum is k(k+1). At k=0, i=2 and sum=0 satisfy the statement. For k<4, adding the next value 2+2k gives k(k+1)+2+2k=(k+1)(k+2), and i also increases by 2. At k=4, i=10 makes the condition false, so exactly four iterations produce sum 20. Finite progress from k=0 to k=4 proves termination. Changing the body or skipping an update requires a new proof. This proof concerns mathematical states and normal built-in integer operations, not resource exhaustion or termination of arbitrary iterables.

Subtopic 4.3

break, continue, and loop design

How do you distinguish skipping negatives from stopping at zero?

Preparation and learning goals

Preparation

  • continue skips the remaining statements of the current loop-body execution and proceeds to the next iteration. break terminates the nearest enclosing loop.
  • Zero is a sentinel chosen as a stop signal for this problem. That does not mean zero must be skipped or stop execution in every problem.
  • A loop else differs from an if else. A for loop executes it on normal exhaustion, when no next value remains, but not when it exits through break.

Learning goals

  • Distinguish skipping one iteration from terminating the loop by tracing data.
  • Explain loop else and the result for empty input.
  • Find a termination defect where continue skips a while loop’s progress update.

Skipping this turn versus stopping

In [2,-1,4,0,8], skip negative values, stop at zero, and add positive values. The continue at −1 skips the subsequent zero test and accumulation but leaves an opportunity to examine 4. The break at zero prevents any visit to 8.

break and continue apply to the nearest enclosing loop. In nested loops, an inner break does not automatically terminate the outer loop. Exiting several loops needs a separate control design. Here there is only one loop over a fixed finite list.

else records exhaustion

The else aligned with for executes when no more values remain and the iterator is normally exhausted. The example then stores outcome="exhausted". The zero branch first stores outcome="stopped" and exits with break, skipping else. Even an empty list exhausts immediately, executes else, and sets outcome.

Using continue does not remove the loop else. Even a continue on the last value can be followed by else when no next value remains. Leaving a function containing the loop through return, or escaping through an unhandled exception, is not normal exhaustion and does not execute else. This example intentionally introduces neither a function return nor an exception.

Every continuing path needs progress

On paper, suppose while i<3 starts at i=0, contains if i==1: continue, and puts i+=1 only after that test. At i=0 it updates to 1; at the next i=1, continue skips the update. Thereafter i remains 1, so the loop does not terminate normally. This nonterminating counterexample is not executed.

A correction must ensure progress on paths reaching continue. For example, save the current item separately, advance the index first, and then test whether to exclude that saved item. Moving the update can change which item is tested, so trace the current value separately from the next position. A break path terminates the loop immediately and need not perform a subsequent update.

A worked example, step by step

Trace the complete code that excludes negatives and stops at the first zero. 

total = 0
for value in [2, -1, 4, 0, 8]:
    if value < 0:
        continue
    if value == 0:
        outcome = "stopped"
        break
    total += value
else:
    outcome = "exhausted"
print(total, outcome)
  1. Start with total=0. value=2 is neither negative nor zero, so total becomes 2.
  2. value=−1 reaches continue at the first condition, preserving total=2. value=4 is accumulated normally, making total=6.
  3. For value=0, the negative condition is false and the zero condition true. Store stopped in outcome and break.
  4. value=8 is not visited and else does not execute. The output 6 stopped and a newline matches the actual preserved code output.

The sum is 6 and outcome is stopped. This differs from summing all positive values of the whole list, which would give 14.

Try it with paper and the lesson

Suppose the list is replaced in turn by [2,-1,4], [], and [0]. Find total and outcome on paper.

Show hint

The first zero causes break. Without a zero, even an empty list exhausts normally.

Show solution

[2,-1,4] gives 6 exhausted; [] gives 0 exhausted; [0] gives 0 stopped. These three activities were traced by the rules, not actually executed.

Misconception and counterexample

Using continue once prevents the loop else from executing.

continue makes progress toward requesting the next value. Normal exhaustion at the end still executes else. Distinguish it from break, return, or an exception that bypasses else.

Show answer and reasoning

The iterator is exhausted immediately and no break occurs.

Does break in an inner loop automatically terminate the outer loop too?

Show answer and reasoning

Explore further

Extension: prove the invariant that, in a visited prefix containing no zero, total is the sum of only the positive values in that prefix. The empty-prefix sum is zero. A negative next value uses continue and preserves the sum; a positive value is added and preserves the invariant. Zero stops the loop without changing the sum, so the final value is the positive sum before the first zero. If there is no zero, the whole list is exhausted and gives the whole-list positive sum. The list is fixed and finite and every body execution ends, so visits are bounded by its length and the loop terminates. This argument does not apply unchanged to the faulty while that skips its update. List mutation, exceptions, or different sentinel meanings require restating the assumptions.

Subtopic 4.4

Accumulation, search, and boundary cases

How do you distinguish a match at position zero from no match yet?

Preparation and learning goals

Preparation

  • a[i] reads the value at position i in list a. For length n, valid nonnegative indices run from 0 through n−1. This example does not mutate the list during execution.
  • None is the marker for not yet found in this design. Test it with first is None. Zero is a valid first position; value zero and position zero have different meanings.
  • The whole-list sum, visit count, and first matching position are different results. Completing the sum and count requires visiting the remaining items after the first match.

Learning goals

  • Trace the running sum, visit count, and first matching position together.
  • Explain empty input, duplicate matches, no match, and index-zero boundary cases.
  • Use invariants and termination conditions to distinguish a whole-domain claim from a few executions.

Record values separately from positions

With a=[0,3,0] and target=0, matches occur at positions 0 and 2. The first position is 0. Start with first=None and store the current i only when first is None and value==target. Once the first match is recorded, do not overwrite it with a later equal value.

if not first would also treat first=0 as false, mistaking it for not found yet. is None tests only the chosen state marker. The target value zero is not excluded merely because it tests as false; value==target decides whether there is a match.

Accumulation has responsibilities beyond search

total is the sum of visited values, and count is the number visited. Breaking as soon as a match is found leaves the whole-list sum and count incomplete. The example stops updating only the saved search position; for still exhausts every position. For a fixed list of length n, range(len(a)) provides 0 through n−1.

For an empty list the body runs zero times, leaving total=0, count=0, and first=None. A nonempty list with no match also leaves first=None. Unconditionally reading a[first] in that state uses an invalid index; test for None before using the result. Even if −1 were chosen as the not-found marker, Python a[-1] means the last element, making unchecked lookup dangerous.

Boundary examples and proof provide different evidence

Considering empty input, first and last positions, duplicates, and absence separately helps find initialization and comparison mistakes. Correct output for a few lists does not prove correctness for all lists. Explain which state property is maintained at every iteration.

Assume a fixed finite list of built-in int values, a built-in int target, normal operations, and sufficient execution resources. The body always terminates and range bounds the indices. User-defined comparison methods, concurrent list mutation, and resource exhaustion are outside the contract. Later search-cost analysis must also distinguish n visits from operation costs that depend on integer bit lengths.

A worked example, step by step

Trace the complete code that computes the whole-list sum and count together with the first zero’s position. 

a = [0, 3, 0]
target = 0
total = 0
count = 0
first = None
for i in range(len(a)):
    value = a[i]
    total += value
    count += 1
    if first is None and value == target:
        first = i
print(total, count, first)
  1. Initially total=0, count=0, first=None. At i=0, add value=0, keeping total=0 and making count=1. first is None and the value matches, so first becomes 0.
  2. At i=1, value=3 makes total=3 and count=2. first is not None, so the storage condition is false and first stays 0.
  3. At i=2, value=0 leaves total=3 and makes count=3. A first match already exists, so first is not changed to 2.
  4. range is exhausted and print writes 3 3 0 and a newline. The actual preserved execution produced this output too.

Whole-list sum 3, item count 3, first matching index 0. Distinguish this from the last zero’s index 2.

Try it with paper and the lesson

Find total, count, and first on paper for a=[], target=0 and a=[2,2], target=2. In the original [0,3,0], what goes wrong if break occurs immediately after the first match?

Show hint

The initial state can also be the result. Do not overwrite the first position, but keep updating the sum and count to the end.

Show solution

The empty list gives 0,0,None. [2,2] gives 4,2,0. Breaking just after the first match in the original list stops at 0,1,0 and fails to obtain the whole-list sum 3 and count 3. The activity inputs were not executed.

Misconception and counterexample

A search result of zero is false, so it means not found.

Zero is a valid first index. This design uses None for not found and tests first is None. Truth testing alone does not change a value’s meaning in the problem.

Check your understanding

For a=[5,7], target=2, what is first?

Show answer and reasoning

None.

All comparisons are false, so the initial not-found marker is preserved.

If first=0, must the matched value also be zero?

Show answer and reasoning

No.

Zero is a position. The first position for target=2 in [2,2] is also zero.

May you break after the first match when the whole-list sum and count are required?

Show answer and reasoning

Not in general.

Unvisited values and items are omitted from the complete accumulation.

Explore further

Extension: after processing k positions, use the invariant that total is the sum of a[0] through a[k−1], count=k, and first is the smallest matching index in that prefix, or None if there is none. At k=0 the empty sum zero, count zero, and None satisfy it. Adding a[k] and increasing count by one maintain the accumulated results. If there was an earlier match, preserve first; if not and the new value matches, k is the first position; if not and it does not match, preserve None. Induction gives the complete result at k=n. range(n) provides finitely many values and the body terminates, establishing termination. This is a conditional proof for a fixed list and normal integer comparisons, not a proof derived from the one executed list.
