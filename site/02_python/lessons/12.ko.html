소단원 12.1

상태·메서드·생성자

같은 기능을 가진 두 카운터가 서로 다른 값을 유지하려면 어떻게 할까?

준비 개념과 학습 목표

준비 개념

  • 함수와 인자

  • 대입·정수

  • if와 예외

학습 목표

  • 상태와 메서드를 객체에 연결한다.

  • self와 초기화 인자를 손 추적한다.

  • 생성과 초기화·별칭을 구별한다.

메서드를 변수에 담고 원래 이름을 바꾸면 어느 객체가 변할까?

평범한 Counter에서 a=Counter(2), saved=a.add를 만든다. saved는 원래 객체와 함수를 연결한 메서드다. 그 뒤 a=Counter(10)으로 이름을 새 객체에 붙여도 saved의 대상은 바뀌지 않는다. 이름의 현재 대상과 저장한 메서드의 대상을 따로 그리자.

Counter.add(amount)는 정수 amount가 음수면 변경 전 ValueError, 아니면 self.value+=amount 뒤 새 값을 반환한다는 base 계약을 유지한다. saved(3)은 원래 객체를 5로 바꾸며 새 a의 값 10은 유지한다. 같은 amount라도 어느 객체에 전달했는지가 재현 입력의 일부다.

클래스라는 포장만으로 모든 상태가 유효해지는 것은 아니다. base Counter는 초기 start나 외부 직접 대입을 제한하지 않는다. 생성된 객체의 불변식을 보장하려면 생성 입력 검사와 모든 공개 변경 경로를 따로 검토해야 한다. 이 절은 순차 이론 추적이며 실제 객체/메서드는 실행하지 않는다.

먼저 확인할 개념
  • 지역 이름과 외부 객체

    이름 재대입과 객체 변경을 구별한다.

  • 별칭과 목록

    같은 객체의 다른 이름을 그리는 법을 메서드 대상에도 적용한다.

객체마다 상태를 둔다

클래스는 객체의 상태와 행동을 묶는 정의다. 아래 Counter는 현재 value와 add 행동을 연결한다. Counter(2)와 Counter(10)은 각각 다른 인스턴스이며 value를 각 객체에 저장한다. 점 뒤의 이름은 그 객체의 속성을 찾는다.

class 본문의 def는 메서드를 정의한다. self는 호출한 인스턴스를 받는 첫 인자의 관례적 이름이다. a.add(3)을 호출하면 add의 self가 a의 객체를 가리킨다. 이 예제는 평범한 사용자 클래스와 정수 입력만 다룬다.

생성 표현과 초기화 메서드

Counter(2)는 새 객체를 만들고 __init__으로 초기 상태를 설정하는 생성 표현이다. 엄밀히 객체 생성은 __new__, 초기화는 __init__의 역할이며 여기서는 __new__를 직접 작성하지 않는다. __init__은 새 객체 자체를 return하는 함수가 아니다.

self.value = start는 해당 인스턴스에 속성을 저장한다. __init__의 끝에 return을 생략하면 None이 반환되며 초기화 계약에 맞는다. 메서드 add의 return self.value는 호출자가 사용할 계산 결과이며 초기화의 반환 계약과 다르다.

조건과 별칭을 함께 확인한다

add는 음수 amount를 거부한 다음 값을 변경하도록 설계한다. 검사를 변경 전에 두면 거부된 요청으로 상태가 바뀌지 않는다. 이 검사는 amount가 정수라는 예제 가정 안에서 설명하며 모든 임의 객체의 타입 검사를 제공하지 않는다.

b = a는 새 카운터를 복제하지 않고 같은 객체에 이름을 더 붙인다. b.add를 호출해 상태를 바꾸면 a.value에서도 보인다. 별도 객체를 원하면 새 생성 표현과 어떤 상태를 복사할지의 정책이 필요하다.

중간 과정을 따라가는 예제

아래 코드를 종이로 추적하라. 필요하면 counter_demo.py에 저장하고 Python 3로 실행하는 후속 실습을 할 수 있으나 여기서는 실행하지 않았다. 

class Counter:
    def __init__(self, start):
        self.value = start

    def add(self, amount):
        if amount < 0:
            raise ValueError("amount must be nonnegative")
        self.value += amount
        return self.value

a = Counter(2)
b = Counter(10)
x = a.add(3)
y = b.add(1)
print(x, y, a.value, b.value)

  1. a의 value는2, b는10으로 서로 다른 객체에 초기화된다.

  2. a.add(3)은2+3=5를 저장하고 x에5를 반환한다. b.add(1)은10+1=11을 저장하고 y에11을 반환한다.

  3. 마지막 줄의 예상 문자열은5 11 5 11이다. 이는 실제 실행 로그가 아니라 정의에 따른 손 추적이다.

a.value=5, b.value=11, x=5, y=11이다. 초기화와 add의 반환값은 서로 다른 역할이다.

소단원 12.2

instance·class attribute

한 학생의 목록에 넣은 항목이 다른 학생에게도 보이면 왜 그럴까?

준비 개념과 학습 목표

준비 개념

  • 리스트 변경

  • 객체 별칭

  • 속성 읽기와 대입

학습 목표

  • 클래스와 인스턴스 속성을 구별한다.

  • 공유 mutable 객체의 변화와 가림을 추적한다.

  • 인스턴스별 목록을 초기화한다.

읽고 변경한 뒤 다시 대입하는 +=는 가림과 공유를 어떻게 섞을까?

평범한 Basket.shared=[]를 두 인스턴스 a,b가 읽는다. a.shared += [1]은 리스트의 내부 변경과 인스턴스 속성 대입을 이어 수행할 수 있다. 같은 리스트를 늘린 뒤 a.shared도 그 리스트를 가리켜 이름을 가린다. 가렸다고 목록 내용이 독립된 것은 아니다.

대조하여 a.shared = a.shared + [1]은 새 바깥 리스트를 만들어 a에 대입한다. 새 클래스와 새 a,b에서 시작한 두 비교는 다른 상태다. +=와 +의 차이는 대상 객체/타입에 따라 다르며 이 절은 내장 리스트 및 평범한 사용자 클래스만 다룬다.

공통 정수 속성의 +=는 또 다르다. Count.total=0에서 a.total+=1은 읽은 0에 1을 더한 새 정수를 a에 저장하여 클래스 total=0을 유지한다. 전체 집계를 원하면 클래스 상태를 명시적으로 변경할 정책을 설계한다. 실제 동시 집계나 스레드 안전 보장은 다루지 않는다.

    +=의 내부 변경과 +의 새 바깥 객체를 대조한다.

  • 대입의 대상

    읽은 값과 저장하는 이름 공간을 나누어 추적한다.

기본값을 찾는 곳과 값을 쓰는 곳

평범한 클래스의 인스턴스에서 같은 이름을 읽을 때 인스턴스 속성이 있으면 그것을 먼저 사용하고, 없으면 클래스 쪽 값을 찾을 수 있다. 아래 Basket.shared는 클래스 정의 때 만든 하나의 리스트다. 인스턴스 생성만으로 새 리스트가 생기지 않는다.

a.shared.append(1)은 속성을 읽어 얻은 그 리스트를 변경한다. a.shared = [9]는 a에 별도 속성을 대입해 클래스 속성을 가린다. 읽은 객체의 변경과 속성 이름에 새 객체를 대입하는 일을 나눠 추적한다. property나 descriptor의 복잡한 조회 규칙은 이 단순 클래스의 범위 밖이다.

공유는 목적이 있을 때만 사용한다

공통 문자열 이름이나 명시적인 집계처럼 공유가 목적이면 클래스 속성이 적합할 수 있다. 학생마다 다른 기록이라면 __init__에서 self.items = []로 각 객체에 새 리스트를 만드는 편이 목적에 맞는다.

초기화 시 전달받은 리스트를 그대로 self.items에 저장하면 그 입력 리스트와 별칭을 만들 수 있다. 인스턴스 속성이라는 이름만으로 깊은 복제가 되는 것은 아니다. 독립 목록이 필요하면 복사 범위와 중첩 객체의 공유도 따로 설계한다.

다른 기능을 넣으려면 반드시 기존 클래스의 자식이어야 할까?

준비 개념과 학습 목표

준비 개념

  • 리스트 길이

학습 목표

부모 메서드가 자식의 아직 없는 상태를 읽으면?

단일 상속에서 Base.__init__이 self.describe()를 호출한다고 하자. Child가 describe를 재정의하여 self.tag를 읽지만 tag는 super().__init__ 뒤에 저장한다. 부모 초기화 안의 self도 Child 객체라 재정의가 선택되어 아직 없는 tag에서 AttributeError가 예상된다.

고정 수정은 Child에서 tag를 먼저 저장하고 super().__init__을 호출하는 순서다. 그러나 모든 부모가 어떤 상태를 요구하는지에 따라 순서 정책은 달라질 수 있다. 초기화 중 재정의 호출의 의존성을 제한하는 다른 설계도 있다. 초기화 성공을 클래스 이름만 보고 가정하지 않는다.

합성에서도 내부 객체 별칭과 특수메서드 계약을 확인한다. Shelf가 list(items)로 보유해도 중첩 항목까지 복사하지 않는다. len의 암시적 조회는 평범한 인스턴스에 s.__len__=lambda:99를 넣는 일반 속성 읽기와 같지 않다. 특별 연산은 클래스에 정의하여 계약을 지킨다.

먼저 확인할 개념
  • 호출의 지역 문맥

    부모 메서드의 self가 어느 객체인지 추적한다.

  • 얕은 복사

    합성 내부 목록의 바깥/안쪽 공유를 구별한다.

상속은 기존 타입 행동을 확장한다

class Loud(Label)은 Label을 부모로 두고 text 메서드를 바꿀 수 있다. Label의 show가 self.text()를 호출하면 대상이 Loud일 때 바뀐 text가 선택될 수 있다. 같은 이름의 메서드를 새 클래스에서 정의하는 것을 override라고 한다.

자식이 __init__을 따로 정의하면 부모 __init__이 필요한 초기화를 자동으로 모두 수행해 주는 것은 아니다. 필요한 경우 super().__init__(...)로 연결한다. 다중상속의 호출 순서와 협력 초기화는 별도 고급 주제이며 여기서는 단일상속만 쓴다.

합성은 필요한 객체를 보유한다

합성은 BookShelf가 내부 items 리스트를 가진 것처럼 다른 객체를 속성으로 보유해 일을 맡기는 설계다. BookShelf가 리스트의 모든 행동을 상속받을 필요는 없다. 제공할 연산을 정하고 내부 객체에 위임한다.

상속과 합성은 모두 코드 연결 수단이며 어느 쪽이 항상 더 좋은 것은 아니다. 바꿔 써도 되는 타입 관계인지, 단순히 특정 기능을 사용하려는 것인지 판단한다. 예제는 입력 리스트를 list로 복사해 바깥 리스트 자체의 변경과 분리하지만 중첩 항목은 깊게 복사하지 않는다.

특수메서드는 문법의 계약이다

__len__을 클래스에 정의하면 len(shelf) 같은 기본 연산에 연결한다. 반환은 비음수 정수여야 한다. __str__은 str(shelf)나 print에 사용할 문자열을 반환해야 한다. 특수 이름을 아무 결과나 반환하는 일반 함수처럼 쓰면 안 된다.

이런 암시적 연산의 특수메서드는 일반적인 인스턴스 속성 읽기와 완전히 같은 방식으로 찾는다고 가정하지 않는다. 클래스에 필요한 메서드를 정의하고 계약을 지킨다. 이 절에서는 __len__과 __str__의 작은 두 연산만 구현한다.

중간 과정을 따라가는 예제

다음 합성 예제를 손 추적하라. 

class BookShelf:
    def __init__(self, items):
        self.items = list(items)

    def __len__(self):
        return len(self.items)

    def __str__(self):
        return f"books={len(self)}"

source = ["A", "B"]
shelf = BookShelf(source)
source.append("C")
print(len(shelf), str(shelf))

  1. list(items)는 A/B를 가진 새 바깥 리스트다. source.append("C")는 source만 세 항목으로 만든다.

  2. shelf.items는 A/B 두 항목이라 __len__이2를 반환한다.

  3. __str__이문자열books=2를 반환하므로 예상 출력은2 books=2다. 실제 실행 로그는 아니다.

len(shelf)=2, str(shelf)="books=2"다. source와 shelf.items의 바깥 리스트가 분리되어 있다.

초기화 순서 반례

학습 목표

frozen 기록 두 개가 같은 내부 목록을 보면 어떤 이력이 남을까?

frozen=True인 Record에 name:str, values:list[int]를 넣는다. r1=Record("A",[1]), r2=replace(r1,name="B")는 서로 다른 바깥 객체지만 기본 필드 전달로 같은 values 목록을 보유한다. r2.values.append(2)는 두 기록에 보인다. 필드 재대입 제한과 과거 기록의 깊은 보존은 다르다.

과거 값을 보존하려는 제한된 점수 기록은 정확 int 원소의 tuple을 선택하고 새 tuple로 새 기록을 만든다. 타입 주석은 입력을 자동 변환/검사하지 않으므로 tuple인지와 각 원소 계약은 별도다. list를 주고 tuple이라고 주석만 적으면 불변성이 생기지 않는다.

default_factory=list는 기본값이 필요할 때 새 목록을 만들지만 명시적으로 같은 목록을 넘기면 복제하지 않는다. replace는 같은 타입의 초기화를 다시 거치며 __post_init__도 호출될 수 있다. 검증을 그 단계에 두면 새 변경값도 검사하지만 실제 파일·외부 서비스 같은 부작용을 검증에 넣는 범위는 별도다.

    새 바깥 기록과 동일 내부 목록을 구별한다.

  • 정확 타입과 기대값

    주석 대신 실제 형/원소의 제한 계약을 검사한다.

필드 중심 기록을 정의한다

dataclass는 필드 이름과 타입 주석을 바탕으로 초기화·표시·동등성 메서드 등을 생성하는 표준 라이브러리 도구다. 기본 eq는 동일한 dataclass 타입의 필드를 비교한다. 두 기록의 값이 같다는 판단과 같은 객체라는 is 판단은 다르다.

타입 주석을 적었다고 dataclass가 모든 입력 타입이나 업무 조건을 자동 검사하지 않는다. 범위와 형태의 런타임 검사가 필요하면 별도로 작성한다. 이 예제는 실제 int 두 값과 str 이름을 받는다는 조건을 명시한다.

frozen은 필드 재대입을 제한한다

frozen=True는 일반적인 필드 대입과 삭제를 막는 동작을 생성한다. 재대입을 시도하면 FrozenInstanceError가 생긴다. 내부 값이 리스트라면 리스트 자체의 append까지 막는 깊은 불변은 아니다.

점수를 튜플로 저장하는 예제는 int 원소를 가진 튜플이라는 조건에서 중첩 변경 문제를 줄인다. 튜플 안에 mutable 객체가 들어가면 그 객체는 여전히 바뀔 수 있다. 불변성은 바깥 필드와 내부 값의 성질을 함께 판단한다.

바뀐 값은 새 기록으로 표현한다

replace는 기존 dataclass에서 변경할 필드를 지정해 같은 타입의 새 객체를 만든다. 지정하지 않은 필드의 객체를 무조건 깊게 복제하는 함수는 아니다. 새로운 버전의 기록과 이전 기록을 구별하기 좋다.

mutable 기본값이 필요하면 field(default_factory=list)처럼 필요할 때 새 값을 만드는 방법을 쓴다. 예를 들어 두 빈 Cart()는 각자의 리스트를 얻는다. 그러나 명시적으로 같은 리스트를 두 생성자에 넘기면 자동 복제를 보장하지 않는다.

일반 frozen 대입 거절

마지막 거절이 앞의 append를 취소하지 않는다. 깊은 이력 보존을 요구한다면 내부 값의 종류와 공유를 제한해야 한다.

중간 과정을 따라가는 예제

다음 코드를 손 추적하라. tuple[int, ...] 표기는 Python 3.9 이상을 사용한다. 

from dataclasses import dataclass, replace

@dataclass(frozen=True)
class Result:
    name: str
    scores: tuple[int, ...]

r1 = Result("Ara", (8, 10))
r2 = replace(r1, scores=r1.scores + (12,))
r3 = Result("Ara", (8, 10))
print(sum(r1.scores), sum(r2.scores))
print(r1 == r3, r1 is r3)

  1. r1 점수 합은8+10=18이다. tuple 덧셈은 새(8,10,12)를 만든다.

  2. r2는새 Result이며 점수 합30이다. r1 점수는(8,10)으로 남는다.

  3. r3는같은 타입·동일한 name/scores라 r1==r3은True, 별도 생성 객체라 r1 is r3은False다. 예상 두 줄은18 30 및True False다.

원본18·새 기록30이며 값 동등성True와 객체 동일성False를 구별한다.

조건을 바꾸어 비교하기

새 기록인데 옛 내용도 바뀐다

위 표의 r2.values.append(2) 뒤 원본 r1이 보존됐다는 보고를 평가하라.

  1. name은 A로 남는다.

  2. values는 같은 목록이라 [1,2]로 바뀐다.

  3. 필드 하나의 보존과 전체 내용 이력 보존은 다르다.

r1의 깊은 불변 기록이라고 주장하지 않는다.

base 새 tuple replace와 list의 공유를 비교한다.

replace의 새 검증

frozen Point의 x는 정확 int이고 0 이상이라는 __post_init__ 검사를 둔다. p=Point(2)로 정상 생성하여 p.x가 2인 상태에서 replace(p,x=-1)을 계획한다.

  1. replace는 새 초기화를 거친다.

  2. post_init의 음수 검사로 ValueError다.

  3. 원본 p의 x=2는 유지된다.

새 변경값도 검사하되 실행하지 않은 예측이다.

종이와 본문으로 직접 해보기

풀이 보기

a.items=[4], b.items=[]이며 기본 리스트는 각각 새 객체다. frozen 리스트 필드에 append하는 것은 필드 재대입이 아니라 내부 변경이므로 frozen만으로 막히지 않는다. 이는 Result의 int 튜플 예제와 별도 비교 상황이다.

다른 문제에 적용하기

이론 점수 보관함 Store는 __init__에서 입력 바깥 목록을 list로 복사하고 add는 정확 int/0..100을 변경 전에 검사한 뒤 append한다. a=Store([10]), alias=a, saved=a.add 뒤 a=Store([20])로 이름을 바꾼다. saved(30), a.add(40), saved(-1)을 순서대로 시도하며 마지막 ValueError를 처리한다. 두 객체와 alias의 내용을 추적하라. snapshot은 정확 int 튜플로 값들을 복사한 frozen Report(name:str,scores:tuple[int,...])를 만드는 것으로 정한다. 원래 객체의 snapshot r1을 만든 뒤 saved(50), r2=replace(r1,name="B")를 수행한다. r1/r2 점수·현재 원래 객체·두 기록의 ==와 is를 적고 일반 r1.scores 재대입과 내부 목록을 그대로 저장하는 잘못된 snapshot을 비교하라. 모든 입력은 지정 내장 타입이며 동시 실행/파일/학생은 수행하지 않는다. r1의 name은 A로 정한다.

힌트 1

saved의 대상은 이름 a를 바꾸기 전 원래 객체다. 거절은 앞선 성공을 취소하지 않는다.

힌트 2

snapshot의 int tuple은 현재 목록 내용과 별도의 불변 값이다. replace name B는 새 바깥 객체이며 필드 비교는 name도 포함한다.

풀이와 답 확인

  1. 원래 객체는 [10]→[10,30], 새 a는 [20]→[20,40]다. saved(-1)은 거절하여 이 둘을 보존한다. alias는 원래 객체를 읽는다.

  2. r1의 scores=(10,30)이다. saved(50) 뒤 원래 객체/alias는 [10,30,50]이나 r1은 (10,30)이다.

  3. r2는 이름 B와 점수 (10,30)를 갖는 새 기록이다. r1의 이름을 A로 정하면 name이 달라 r1==r2는 False이고 is도 False다.

  4. 일반 r1.scores 대입은 FrozenInstanceError다. list를 그대로 저장한 snapshot이라면 이후 append가 과거 기록에도 보여 깊은 이력 보존을 어긴다.

  5. 검사는 저장 메서드 대상/거절 후 상태/tuple snapshot/값과 동일성 및 실제 미수행을 각각 확인한다.

원래/alias [10,30,50], 새 a [20,40], r1/r2 점수 (10,30)이다. r1.name=A, r2.name=B일 때 ==/is는 False/False이며 일반 frozen 필드 대입은 거절된다.

해결한 뒤 점검할 것

  • 이름 재대입과 저장한 메서드의 대상 객체를 나눈다.

  • 거절이 앞선 성공을 취소하지 않음을 상태로 보인다.

  • snapshot의 int tuple과 mutable 목록 별칭을 구별한다.

  • 비교에 name도 포함하고 ==와 is를 나눈다.

  • 동시/저장/실행/학생 미수행을 유지한다.
