소단원 8.1

forwarding·stall

아직 레지스터에 쓰지 않은 답을 다음 명령이 먼저 쓸 수 있을까?

준비 개념과 학습 목표

준비 개념

  • IF/ID/EX/MEM/WB

  • 레지스터 읽기·쓰기

학습 목표

  • 생성 시점과 필요 시점을 비교한다.

  • 우회 가능 여부와 stall을 구분한다.

값이 준비되는 경계를 찾는다

RAW 의존은 앞 명령이 쓸 값을 뒤 명령이 읽는 관계다. 이름이 같은지만 보지 말고 앞 명령이 실제로 쓰는지, 뒤 명령이 그 필드를 실제 입력으로 사용하는지 확인한다.

여기서는 단일 발행·순서 실행 IF/ID/EX/MEM/WB의 5 단계를 쓰며 ALU 값은 EX 끝, load 값은 MEM 끝에 준비된다고 정한다. EX 입력은 사이클 시작에 필요하고 단계 간 레지스터에서 EX로 우회할 수 있다.

준비된 최신 값은 우회한다

ALU 결과를 EX/MEM에서 다음 명령 EX 입력으로 주면 WB까지 기다릴 필요가 없다. 우회는 레지스터 파일에 쓰는 작업과 별도 경로다.

같은 레지스터를 여러 앞 명령이 쓰면 프로그램 순서상 가장 가까운 앞 명령을 고른다. 더 오래된 값이 준비되었다고 최신 아직 미준비 값을 건너뛰면 잘못된 결과가 된다.

아직 없는 값은 기다린다

load 바로 뒤 소비자의 EX가 load의 MEM과 같은 사이클이면 소비자 시작 때 데이터가 없다. 이 모델에서는 소비자를 한 사이클 멈추고 EX에 부작용 없는 bubble을 넣는다.

PC와 IF/ID는 유지하지만 앞의 load는 진행시켜야 한다. 모든 단계를 함께 얼리면 필요한 값도 만들어지지 않는다. 실물의 단계·메모리 지연이 달라지면 stall 수도 달라진다.

중간 과정을 따라가는 예제

I1=load r1,[r0], I2=add r2,r1,r3 이다. I1 IF가 c1, r3=4, 읽은 메모리 값=7 이며 앞서 정한 우회 모델을 쓴다.

  1. I1 은 c1 IF, c2 ID, c3 EX, c4 MEM, c5 WB다. I2 는 c2 IF, c3 ID 뒤 원래 c4 EX가 필요하다.

  2. c4 시작에는 load 값이 없어 I2 를 ID에 유지하고 EX bubble을 둔다. c4 끝에 값 7 이 준비된다.

  3. I2 는 c5 EX에서 MEM/WB의 7 을 받아 7+4=11, c6 MEM, c7 WB로 r2 를 쓴다.

한 stall 뒤 r2=11 이고 두 명령 완료는 c7 이다. 이상적 두 명령의 c6 보다 한 사이클 길다.

종이와 본문으로 직접 해보기

I1 을 add r1,r4,r5 로 바꾸고 r4=3,r5=4 면 I2 에 stall이 필요한가?

힌트 보기

I1 EX 끝과 I2 EX 시작을 나란히 놓는다.

풀이 보기

c3 끝의 7 을 c4 EX로 우회할 수 있어 stall이 없다. I2 는 c6 WB에서 11 을 쓴다.

오해와 반례

forwarding이 있으면 모든 의존에서 stall이 없어진다.

load 데이터는 필요한 시작 시점 뒤에 생긴다. 미래 값을 우회할 수는 없으므로 제시 모델의 load-use는 한 stall이 필요하다.

자기점검

bubble은 레지스터를 쓰는가?

답과 이유 보기

쓰지 않는다.

유효 부작용을 막는 빈 작업이다.

stall 중 앞 load도 멈추나?

답과 이유 보기

이 경우 진행한다.

데이터 준비를 위해 MEM까지 가야 한다.

같은 r1 의 두 producer 중 누구를 고르나?

답과 이유 보기

가장 가까운 앞의 유효 writer다.

프로그램 순서의 최신 값을 사용한다.

한 단계 더

메모리 응답을 두 사이클로 늘려 필요한 대기 위치를 다시 그리자. 실제 CPU 실행은 하지 않았다.

소단원 8.2

분기와 flush

틀린 길로 가져온 명령은 이미 실행 목록에 있는데 어떻게 없앨까?

준비 개념과 학습 목표

준비 개념

  • 분기와 PC

  • 파이프라인 유효 비트

학습 목표

  • 분기 판단 시점과 잘못 가져온 수를 연결한다.

  • 추측 명령의 상태 변경을 억제한다.

다음 PC도 의존하는 값이다

분기 방향과 목적지가 알려지기 전에는 다음 명령을 확정할 수 없다. 여기서는 5 단계, EX 끝에서 판단, 순차 주소를 예상하며 branch delay slot은 없다고 정한다.

분기 피연산자의 RAW hazard도 처리해야 한다. 잘못 읽은 비교값으로 빠르게 분기하는 것은 올바른 해결이 아니다.

잘못된 경로는 무효로 만든다

taken이라고 EX 끝에 알게 되면 그때 ID와 IF에 있는 두 younger 명령은 잘못된 경로다. 유효 비트나 쓰기 제어를 막고 다음 사이클 IF를 목적지로 바꾼다.

flush는 이 younger 명령들을 취소하는 것이며 이미 앞선 older 명령의 정상 결과를 지우는 작업이 아니다. stall은 명령을 보존하며 기다리므로 둘을 구별한다.

판단이 늦을수록 낭비가 커진다

분기 판단을 더 뒤로 미루면 잘못 가져온 명령 수가 늘 수 있다. 실제 비용은 폭·예측·단계·동시 stall에 영향을 받는다.

아래 CPI는 긴 실행에서 독립된 오예측 비용만 더한 교육용 평균이다. 시작·종료 채우기 비용과 캐시·데이터 stall은 제외하며 실제 측정으로 보고하지 않는다.

중간 과정을 따라가는 예제

branch가 c1 IF, c2 ID, c3 EX이고 실제 taken이다. c2 에 잘못된 A, c3 에 잘못된 B를 가져온다. EX 끝 판단 후 목적지 T는 언제 IF에 오나?

  1. c3 에는 branch EX, A ID, B IF가 동시에 있다.

  2. c3 끝에 A/B를 무효로 하고 목적지를 PC로 둔다. c4 IF는 T다.

  3. 두 순차 명령 자리를 잃는다. 긴 실행에서 분기 비율 0.2, 그중 오예측 0.25, 벌점 2 라면 추가 CPI=0.2×0.25×2=0.1 이다.

T는 c4 IF, 취소 명령은 두 개다. 이상적 CPI 1 에 다른 비용이 없으면 평균 CPI 1.1 이다.

종이와 본문으로 직접 해보기

판단이 ID 끝으로 앞당겨지고 같은 분포·다른 비용 없음이면 손실과 평균 CPI는?

힌트 보기

그 시점의 younger IF 한 개를 센다.

풀이 보기

벌점 1, 추가 0.2×0.25=0.05 로 평균 CPI 1.05 다. 빠른 판단 회로가 주기까지 바꾸는 현실 효과는 제외했다.

오해와 반례

flush는 앞선 모든 명령 결과도 되돌린다.

이 모델은 분기보다 younger인 잘못된 경로만 취소한다. older의 완료 상태는 보존한다.

자기점검

예상 순차이고 실제 not-taken이면?

답과 이유 보기

이 가정에서는 경로 flush가 없다.

가져온 순차 명령이 맞다.

취소된 store가 메모리를 써도 되나?

답과 이유 보기

안 된다.

잘못된 경로의 부작용을 막는다.

CPI 1.1 은 클록 주기도 알려 주나?

답과 이유 보기

아니다.

시간은 사이클 수와 주기를 함께 봐야 한다.

한 단계 더

분기 조건을 load가 만들 때의 데이터 대기와 경로 취소를 별도 표시하자. 실제 예측기 측정은 미수행이다.

소단원 8.3

정확한 예외

문제 난 명령 앞뒤가 뒤섞이면 운영체제는 어디서 다시 시작할까?

준비 개념과 학습 목표

준비 개념

  • 프로그램 순서

  • architectural state

학습 목표

  • 검출과 처리 시점을 구별한다.

  • fault 경계의 상태를 복원한다.

프로그램 순서의 경계를 만든다

정확한 예외는 명령 순서의 한 경계에서 상태가 설명되는 성질이다. 여기서 재시작 가능한 fault를 다루며 해당 명령 이전은 완료, 해당 및 이후는 정상 프로그램 상태를 변경하지 않은 것으로 정한다.

예외 처리용 PC·원인 레지스터 변화는 정상 명령의 결과와 구별한다. trap처럼 다음 명령을 가리키는 ISA 규약이나 비동기 interrupt 경계를 모든 fault와 같다고 단정하지 않는다.

검출이 먼저여도 처리 순서를 지킨다

older load의 메모리 오류가 younger add의 EX 오류보다 늦게 검출될 수 있다. 검출 시각만으로 먼저 핸들러에 가면 이전 명령 상태가 애매해진다.

각 명령의 PC·예외 정보·유효 여부를 함께 보관하고 순서대로 확정할 때 가장 먼저인 예외를 처리한다. younger 쓰기와 store 부작용도 확정 전에 억제해야 한다.

재시작은 원인을 고친 뒤 한다

주소 변환 fault라면 운영체제가 매핑을 고친 뒤 저장한 fault PC에서 다시 실행할 수 있다. 어떤 fault든 무조건 반복하면 해결된다는 뜻은 아니다.

순서 밖 실행에서도 계산과 commit을 나누는 reorder buffer 같은 방법이 가능하다. 모든 실제 처리기가 하나의 방법이나 모든 예외에 같은 정확성을 쓴다는 주장은 아니다.

중간 과정을 따라가는 예제

초기 r1=0,r2=9,메모리 M=0 이다. PC 100 의 I1 add r1,2,3; PC 104 의 I2 load r2,[bad]가 fault; PC 108 의 I3 store [M],r1 순서다. 정확한 fault 상태는?

  1. older I1 은 완료해 r1=5 다.

  2. I2 결과 쓰기는 없으므로 r2=9 이고 younger I3 도 쓰지 않아 M=0 이다.

  3. 본문 fault 규약의 저장 PC는 104 다. 매핑을 고쳐 I2 를 재시작하며 I1 까지 다시 적용할 필요는 없다.

정상 상태는 r1=5,r2=9,M=0 이며 fault PC 104 를 저장한다.

종이와 본문으로 직접 해보기

I3 가 I2 의 fault 처리 전에 M=5 를 외부에 확정했다면 같은 정확한 경계인가?

힌트 보기

해당 명령 이후의 상태 변경 금지를 확인한다.

풀이 보기

아니다. younger store가 정상 메모리를 바꿨으므로 I2 앞 경계와 다르다. 쓰기 버퍼 등에서 확정 전 보관하는 설계가 필요하다.

오해와 반례

예외를 가장 빨리 검출한 명령을 언제나 먼저 처리하면 정확하다.

older의 늦은 오류가 있을 수 있다. 프로그램 순서의 예외 우선순위와 상태 확정 경계를 보존해야 한다.

자기점검

fault I2 의 r2 쓰기는?

답과 이유 보기

정상 결과로 확정하지 않는다.

재시작 경계의 해당 명령이다.

저장 PC는 모든 ISA에서 104 인가?

답과 이유 보기

아니다.

본문 fault 규약이며 trap·delay slot 규약은 별도다.

정확성은 검출 단계 하나로 결정되나?

답과 이유 보기

아니다.

commit 및 부작용 억제도 필요하다.

한 단계 더

I1 도 fault인 표를 만들어 검출 시각과 프로그램 순서 우선순위를 비교하자. 실제 처리기·OS 실험은 하지 않았다.

소단원 8.4

명령별 의존 추적

같은 레지스터 이름을 여러 번 쓸 때 화살표를 어디로 이어야 할까?

준비 개념과 학습 목표

준비 개념

  • read/write 집합

  • RAW/WAR/WAW

학습 목표

  • 각 read에 최신 이전 writer를 연결한다.

  • 이름 의존과 실제 stall 조건을 구분한다.

입력과 출력을 표로 적는다

I1: r1←r2+r3 은 r2/r3 을 읽고 r1 을 쓴다. store는 주소 계산 레지스터와 저장할 값 모두 읽지만 일반 목적 레지스터를 쓰지 않는다.

즉시값 필드를 레지스터 read라고 세면 가짜 의존이 생긴다. zero 레지스터와 쓰지 않는 명령도 ISA 의미에 따라 제외한다.

읽기는 가장 가까운 앞 쓰기를 따른다

같은 이름을 반복해 썼다면 각 read는 프로그램 순서의 최신 이전 정의에 연결한다. 그 사이 값을 다시 덮는 명령을 건너뛰어 더 오래된 writer와 연결하면 틀린 값이다.

RAW는 값 전달 의존이다. WAR는 이전 읽기보다 뒤 쓰기가 앞서면 안 되는 이름 의존, WAW는 두 쓰기의 마지막 값 순서 의존이다. 단순 순서 실행에서는 이 이름 관계가 모두 stall을 만들지는 않는다.

정적 화살표와 동적 시간을 분리한다

의존 그래프만으로 stall 횟수를 정할 수 없다. 결과 준비 단계, 소비 단계, 우회 경로와 메모리 응답을 함께 주어야 한다.

메모리는 두 주소가 같은지 판단해야 한다. 서로 다른 레지스터 이름으로 주소를 계산해도 같은 위치를 가리킬 수 있다. 여기서는 우선 레지스터 의존만 계산한다.

중간 과정을 따라가는 예제

I1:r1←r2+r3, I2:r4←r1+r5, I3:r1←r6+r7, I4:r8←r1+r4 이다. r2=2,r3=3,r5=4,r6=10,r7=1 이다.

  1. I2 의 r1 read는 I1 에 연결돼 r4=5+4=9 다.

  2. I4 의 r1 read는 I3 에, r4 read는 I2 에 연결된다. r1=11 로 바뀌어 r8=11+9=20 이다.

  3. RAW 간선은 I1→I2, I3→I4, I2→I4 다. I2 read r1 과 I3 write r1 은 WAR, I1/I3 의 r1 쓰기는 WAW다.

r4=9,r8=20 이다. I1→I4 의 r1 직접 RAW로 최신 I3 를 대신하면 안 된다.

종이와 본문으로 직접 해보기

I3 가 r1←r6+r7 대신 r9←r6+r7 이면 I4 의 r1 원천과 r8 은?

힌트 보기

r1 의 마지막 이전 writer를 다시 찾는다.

풀이 보기

I1 이 원천이고 r8=5+9=14 다. I3 가 더 이상 r1 을 덮지 않는다.

오해와 반례

레지스터 이름이 같으면 모두 RAW stall이다.

read/write 방향에 따라 WAR/WAW도 있고 순서 실행이 이미 보존할 수도 있다. RAW도 우회하면 stall이 없을 수 있다.

자기점검

I4 r4 의 writer는?

답과 이유 보기

I2 다.

그 전에 최신 r4 정의다.

I1/I3 의 r1 관계는?

답과 이유 보기

WAW다.

둘 다 쓰므로 마지막 순서가 중요하다.
