소단원 14.1

공유메모리·cache coherence

두 코어가 같은 메모리 주소를 읽는데 각자 캐시에 오래된 복사본이 있으면 어떻게 될까?

준비 개념과 학습 목표

준비 개념

  • 주소와 캐시 라인

  • load/store

  • 멀티코어

학습 목표

  • 공유 주소와 코어별 캐시 복사본을 구별한다.

  • 단순 일관성 상태와 쓰기 소유권을 추적한다.

  • 일관성과 여러 주소의 순서를 구별한다.

같은 주소에도 여러 복사본이 있다

공유메모리는 여러 실행 주체가 같은 저장 위치를 접근할 수 있다는 뜻이다. 모든 접근이 매번 DRAM까지 가는 것은 아니다. 코어 가까운 캐시에 복사본이 있을 수 있어 읽기는 빠르지만 다른 코어의 쓰기를 어떻게 반영할지 규칙이 필요하다. 주소를 공유한다는 말과 모든 코어가 같은 순간에 같은 값을 직접 읽는다는 말은 다르다.

캐시 일관성, cache coherence는 같은 위치에 대한 쓰기와 복사본의 관계를 관리한다. 충돌하는 쓰기에 소유권을 주고 다른 오래된 복사본을 무효화하는 방식이 가능하다. 전달은 캐시 사이에서도 이루어질 수 있으므로 새 값이 DRAM에 즉시 저장되어야 다른 코어가 읽는다는 설명은 지나치게 단순하다.

종이 상태 모형으로 소유권을 본다

이 절은 실제 제품의 전체 MESI 프로토콜을 재현하지 않고 I/S/M 세 상태의 자체 모형을 사용한다. I는 사용할 수 없는 복사본, S는 다른 읽기 복사본과 함께 있는 최신 값, M은 이 모형에서 혼자 쓰기 권한을 가진 최신 값이다. 각 사건이 완료된 뒤의 상태만 비교하며 동시에 전송 중인 중간 상태와 지연은 생략한다.

초기 값이 10인 라인을 C0와 C1이 읽으면 둘 다 S(10)로 둘 수 있다. C0가 11을 쓰는 사건을 완료하려면 C1을 I로 바꾸고 C0만 M(11)이 되게 한다. 이어 C1이 읽으면 최신 소유자의 11을 전달하고 둘을 S(11)로 바꾸는 규칙을 둔다. 이때 DRAM 값은 다시 읽기 시점에 11로 갱신된다고 모형에 명시한다.

보장 범위를 분리한다

같은 라인의 복사본 관리만으로 서로 다른 주소 data와 flag의 관찰 순서가 모두 정해지지는 않는다. 여러 위치의 순서와 동기화는 memory ordering의 질문이다. CPU 사이에 일관된 일반 메모리라는 가정도 장치 DMA나 MMIO에 그대로 옮기지 않는다. 장치 접근에는 별도 API와 소유권·동기화 규칙이 필요할 수 있다.

실제 캐시 프로토콜에는 독점 읽기 상태, 디렉터리, 무효화 확인, 전송 중 상태 등 추가 요소가 있다. 이 표를 통해 단일 쓰기 권한과 최신 값 전달의 이유를 이해한 뒤 실제 ISA와 시스템 문서를 읽는다. 모형 사건이 가능하다는 것과 특정 CPU에서 해당 사이클 수로 실행됐다는 것은 별도 증거다.

중간 과정을 따라가는 예제

자체 I/S/M 모형의 초기 DRAM 값은 10, C0/C1은 I다. 순서대로 C0 읽기, C1 읽기, C0의 11 쓰기 완료, C1 읽기를 적용하라. 읽기 공유는 S, 쓰기는 다른 복사본 I, M 소유자 뒤 읽기는 최신 값 전달과 DRAM 갱신으로 정의한다.

  1. C0 읽기 뒤 C0=S(10), C1=I, DRAM=10이다.

  2. C1 읽기 뒤 C0=S(10), C1=S(10), DRAM=10이다.

  3. C0 쓰기 완료 뒤 C0=M(11), C1=I, DRAM=10이다. 최신 11은 C0가 가진다.

  4. C1 읽기 뒤 소유자로부터 11을 얻는다. 모형 규칙상 C0=S(11), C1=S(11), DRAM=11이다.

C1의 마지막 읽기는 11이다. 쓰기 직후 C1의 옛 10을 유효한 최신 복사본으로 남기지 않는다.

오해와 반례

CPU 캐시가 일관되면 모든 주소의 쓰기는 프로그램 순서대로 모든 장치에 즉시 전달된다.

복사본의 최신성 규칙과 여러 위치의 순서·장치 일관성은 다르다. 캐시 소유자의 최신 값은 DRAM 값과도 잠시 다를 수 있다.

소단원 14.2

원자연산의 하드웨어

두 코어가 각각 카운터를 1씩 늘렸는데 최종 값이 한 번만 늘어난 이유는?

준비 개념과 학습 목표

준비 개념

  • read-modify-write

  • 캐시 소유권

  • 비교와 조건 분기

학습 목표

  • 따로 된 읽기·쓰기에 생기는 갱신 손실을 추적한다.

  • 원자 RMW와 CAS 재시도를 설명한다.

  • 원자성과 진행·순서 보장을 분리한다.

읽기 하나가 원자적이어도 증가 전체는 다르다

증가를 읽기, 더하기, 쓰기로 나누면 중간에 다른 코어가 끼어들 수 있다. 두 코어가 모두 5를 읽고 각자 6을 쓰면 최종 값은 6이다. 캐시 일관성은 두 개의 6 쓰기를 순서대로 처리할 수 있지만 두 증가라는 프로그램 의도를 자동 복구하지 않는다.

원자 read-modify-write, RMW는 한 대상에 대한 읽기와 변경을 다른 경쟁 연산 사이에서 나뉘지 않는 사건으로 다룬다. 두 번의 원자 증가가 성공하고 다른 갱신과 overflow가 없다면 5에서 6, 다음 7이 된다. 이 예제는 순수 사건 모형이며 일반 C/C++ 공유 정수를 동기화 없이 실행해도 된다는 코드 예제가 아니다.

하드웨어와 비교 재시도

하드웨어는 CAS 계열 명령이나 LL/SC 계열 예약·조건부 저장 등으로 원자 연산을 지원할 수 있다. CAS는 현재 값이 기대 값과 같을 때만 새 값을 저장한다. LL/SC는 읽기 후 관련 예약이 유효할 때 조건부 저장하며 실패하면 다시 시도하는 구조가 가능하다. 실제 ISA마다 실패 조건과 명령 규약이 다르다.

원자 연산이 항상 메모리 버스 전체를 잠근다고 단정하지 않는다. 캐시 라인 소유권, 하드웨어 명령, 경우에 따라 소프트웨어 잠금 구현 등 구현 조건을 확인한다. Linux atomic_t 문서는 일반 CPU 메모리 연산을 다루며 이 연산을 MMIO 주소에 그대로 적용하지 말아야 한다.

실패와 순서도 따로 읽는다

CAS로 5를 6으로 바꾸려는데 다른 코어가 이미 6을 만들었다면 기대 5 비교는 실패한다. 최신 6을 받아 목표 7을 다시 계산한 뒤 재시도해야 증가 의미를 보존한다. 실제 인터페이스가 실패 시 어떤 값을 반환하거나 기대 인자를 바꾸는지 확인한다. 실패한 CAS가 메모리를 바꿨다고 표를 쓰지 않는다.

한 변수에 대한 원자성은 다른 주소에 대한 모든 순서나 모든 스레드의 빠른 완료를 뜻하지 않는다. relaxed/acquire/release 규약을 따로 읽고 특정 반복이 굶지 않는다는 진행 보장은 ISA와 알고리즘 조건에서 검토한다. 재시도 횟수가 늘면 비용도 커질 수 있다.

중간 과정을 따라가는 예제

초기 카운터 5다. 분리된 사건은 C0 읽기 5, C1 읽기 5, C0 쓰기 6, C1 쓰기 6이다. 비교용 원자 사건은 C0 증가 완료 뒤 C1 증가 완료다. 별도 CAS 사건에서 C1은 기대 5/목표 6을 준비한 후 C0가 먼저 6으로 바꾼다.

  1. 분리된 두 읽기는 모두 5다. 두 쓰기 모두 6이므로 최종 6, 기대한 두 증가의 7과 다르다.

  2. 두 원자 증가는 현재 값을 연속 갱신해 5→6→7이다.

  3. CAS 시점 현재 6과 C1 기대 5가 다르므로 실패하며 메모리는 6 그대로다.

  4. 최신 6으로 기대 값을 바꾸고 목표를 7로 재계산한다. 다른 경쟁이 없으면 CAS 성공 뒤 7이다.

분리 연산은 6, 두 성공한 원자 증가는 7이다. 실패한 CAS는 저장하지 않고 최신 값에 맞춰 증가 목표를 다시 만든다.

종이와 본문으로 직접 해보기

힌트 보기

실패가 반환한 최신 값을 기준으로 목표를 다시 계산한다.

풀이 보기

현재 8과 기대 6이 달라 실패하며 값은 8이다. 다음 기대는 8, 목표는 9다. 이후 경쟁이 없고 CAS가 성공하면 9다. 이 한 경로만으로 모든 스레드의 종료 상한을 증명하지 않는다.

오해와 반례

원자 증가를 쓰면 다른 모든 데이터 순서와 스레드의 대기 시간까지 해결된다.

대상 변수의 나뉘지 않는 갱신과 다른 위치의 ordering·알고리즘 진행은 별개다. 명시된 순서 규약과 경쟁·반복 조건을 읽어야 한다.

준비 개념

  • 서로 다른 주소

  • 원자 연산

  • 생산자와 소비자

학습 목표

  • 한 위치의 일관성과 여러 위치의 관찰 순서를 구별한다.

  • release/acquire 전달의 연결 조건을 적는다.

  • 장벽과 캐시 flush를 동일시하지 않는다.

밖에서 보이는 순서는 별도 규약이다

명령을 작성한 순서, 컴파일러가 만든 순서, 다른 코어가 효과를 관찰하는 순서를 구별한다. 한 코어 자신의 의미를 보존하면서 다른 위치에 대한 접근의 효과가 다른 순서로 보일 수 있다. 같은 주소에 대한 캐시 일관성만으로 data와 flag 두 주소의 전달 순서를 전부 결정하지 못한다.

이 절의 자체 약한 순서 모형은 data=0/flag=0에서 시작한다. 생산자는 data=42 다음 flag=1을 의도하지만 동기화 규칙이 없으면 소비자에게 flag=1이 먼저 전달되는 경로를 허용한다. 이 모형은 모든 실제 CPU에서 언제나 이런 결과가 나온다는 주장이 아니며 일반 언어의 data race를 실행해 보라는 활동도 아니다.

전달 표시를 release/acquire로 연결한다

단일 생산자가 자료를 준비한 뒤 release로 flag를 저장하고, 소비자가 acquire로 바로 그 release가 저장한 표시를 읽었다는 연결을 둔다. 자료의 수명은 유효하며 그 뒤 생산자가 덮어쓰지 않는다는 조건도 필요하다. 이런 전달 규약에서는 준비 전에 쓴 자료를 표시를 확인한 뒤 읽도록 순서를 연결할 수 있다.

acquire가 0을 읽었다면 준비된 자료라는 결론을 내리지 않는다. 다른 생산자나 이전 회차의 1을 읽었다면 어느 자료를 뜻하는지 다시 명세해야 한다. 반복 사용하는 flag에는 세대 번호, 잠금, 큐와 같은 별도 프로토콜이 필요할 수 있다. 읽은 값만 같다는 사실과 특정 release에서 전달됐다는 관계를 혼동하지 않는다.

장벽의 비보장을 남긴다

acquire와 release는 각각 이후·이전 접근을 연결하는 방향이 다르다. 모든 접근을 전역에서 완전히 직렬화하는 하나의 full barrier와 자동으로 같지는 않다. Linux 자료는 장벽이 모든 이전 접근의 물리적 완료나 다른 CPU에 대한 직접 명령을 보장하지 않는다는 한계도 설명한다.

캐시 flush는 복사본과 메모리 전달을 관리하는 다른 기능이다. 장벽을 넣었다고 저장이 영속 매체에 도달하거나 비일관 DMA 장치까지 최신 자료를 받았다고 말하지 않는다. 여기서는 일반 CPU 간 단일 자료 전달 모형만 검토한다. 언어 원자 타입과 커널 API는 각 명세로 확인해야 한다.

중간 과정을 따라가는 예제

자체 약한 순서 모형에서 초기 data=0, flag=0이다. 생산자 P는 data=42와 flag=1을 준비한다. A 경로는 flag 효과만 먼저 소비자 Q에 보인다. B 경로는 data 쓰기 뒤 release flag=1, Q의 acquire가 그 1을 읽고 data를 읽는다. 단일 P와 유효한 자료 수명·덮어쓰기 없음 조건이다.

  1. A 경로에서 Q는 flag=1을 읽지만 아직 data 효과를 관찰하지 못해 data=0을 읽는 표가 모형상 허용된다.

  2. B 경로에서는 data 쓰기가 release 이전이고, Q의 자료 읽기가 연결된 acquire 이후다.

  3. release가 쓴 1을 acquire가 읽었다는 조건에 따라 자료 전달 순서가 연결되어 Q의 data 값은 42다.

  4. Q가 flag=0을 읽은 별도 경로에는 B의 준비 완료 결론을 적용하지 않는다.

동기화 없는 A 모형은 (1,0)을 허용한다. 연결과 수명 조건을 갖춘 B에서는 (1,42)를 얻는다. 이는 실제 실행 관찰값이 아니다.

종이와 본문으로 직접 해보기

P가 data=73을 준비한 뒤 release로 flag=2를 썼다. Q의 acquire가 그 2를 읽는 경우와 이전 표시 1을 읽는 경우를 구별하라. 같은 표시 값을 반복 사용하는 문제를 설명하라.

힌트 보기

현재 회차의 release를 읽었다는 조건을 확인한다.

풀이 보기

그 2를 읽고 덮어쓰기·수명 문제도 없으면 Q는 준비한 73을 읽을 수 있다. 이전 1은 새 회차 73의 준비 완료 증거가 아니다. 표시를 계속 1로만 쓰면 어느 회차인지 값만으로 구별하기 어려우므로 세대·수명·재사용 프로토콜을 따로 설계한다.

오해와 반례

flag를 읽었거나 장벽 하나를 넣었으면 어떤 자료든 최신이고 디스크에도 저장됐다.

어떤 release와 연결된 acquire인지, 어떤 자료 수명과 덮어쓰기 조건인지 확인한다. 순서 제약은 영속 저장·모든 장치 일관성의 인증이 아니다.

소단원 14.4

bandwidth·false sharing

서로 다른 카운터를 늘리는 코어들이 왜 같은 캐시 라인을 두고 경쟁할까?

준비 개념과 학습 목표

준비 개념

  • 캐시 라인 소유권

  • 바이트와 전송률

  • 비율과 상한

학습 목표

  • 주소 배치로 false sharing을 찾는다.

  • 공간 비용과 소유권 전환 횟수를 비교한다.

  • 자료량·대역폭·산술 집약도 상한을 계산한다.

공유하지 않는 변수도 라인을 공유한다

false sharing은 프로그램 의미상 별개인 데이터가 같은 일관성 관리 단위에 놓여 생기는 간섭이다. 한 코어가 카운터 x를 쓰고 다른 코어가 별개 y를 쓰거나 읽어도 같은 캐시 라인이라면 무효화와 전달이 반복될 수 있다. 단순히 읽기 복사본이 여럿이라는 이유만으로 쓰기 소유권 충돌이 생기는 것은 아니다.

자체 배치 모형은 라인 크기 64 B, 정렬된 시작 주소 0을 가정한다. x는 offset 0, y는 offset 8에 둔 8 B 값이다. 둘 다 floor(address/64)=0인 라인에 들어간다. y를 offset 64로 옮기면 라인 1로 분리된다. 실제 라인 크기와 정렬은 대상 시스템에서 확인해야 한다.

분리는 이득과 비용을 함께 가진다

한 라인을 C0/C1이 번갈아 독점해 쓰면 소유권이 이동한다. 같은 총 쓰기 수라도 코어별 값을 별도 라인에 두거나 작업을 묶으면 이동 횟수를 줄일 수 있다. 라인 분리는 읽기 locality와 저장 공간·TLB 사용 등에 다른 비용을 주므로 모든 구조를 무조건 padding하지 않는다.

Linux 자료의 perf-c2c와 pahole는 실제 실행과 배치 관찰을 돕는 도구다. 이 수업에서는 실행하지 않았으므로 HITM 횟수나 성능 개선을 관찰했다고 기록하지 않는다. 이동 횟수의 가상 표는 측정 시간과 같지 않고, false sharing을 줄여도 다른 병목이 전체 시간을 지배할 수 있다.

대역폭으로 가능한 상한을 따진다

자료량 D 바이트를 해당 경로의 최대 대역폭 B 바이트/초로 옮기는 데 드는 시간은 이상적 모형에서도 D/B보다 작을 수 없다. 실제 전송량은 배열 크기와 다를 수 있다. 읽기·쓰기·write allocation·캐시 재사용을 어떻게 세는지와 어느 메모리 계층의 대역폭인지 명시한다. MiB/GiB는 2의 거듭제곱, MB/GB는 여기서 10의 거듭제곱으로 구별한다.

산술 집약도 I는 해당 경계를 넘는 바이트당 부동소수점 연산 수다. 같은 경계의 대역폭 B와 계산 상한 P를 사용하면 단순 Roofline 상한은 min(P,B×I)다. 상한에 도달한다는 보장은 없으며 지연·경쟁·벡터화·NUMA 배치 등 다른 조건이 결과를 낮출 수 있다. 높은 코어 수만으로 메모리 전송 상한을 없앨 수는 없다.

중간 과정을 따라가는 예제

라인 64 B와 8 B 카운터 x/y다. 공유 배치 x=0/y=8에서 초기 C0가 라인 소유권을 가진다. 완료 쓰기 순서는 C0x,C1y,C0x,C1y,C0x,C1y다. 분리 배치 x=0/y=64에서는 초기 C0가 x 라인, C1이 y 라인을 소유하며 다른 접근은 없다. 따로 32 MiB 전송과 최대 8 GiB/s를 계산하라.

  1. 공유 배치의 첫 C0 쓰기는 초기 소유자 그대로다. 나머지 다섯 번은 직전과 다른 코어가 쓰므로 소유권 전환 5회다.

  2. 분리 배치는 각각 자기 라인만 쓰므로 초기 이후 코어 사이 소유권 전환 0회다. 초기 획득과 실제 전송 지연은 표에서 제외했다.

  3. 두 8 B 값을 16 B에 두던 배치가 각각 64 B 슬롯을 쓰면 총 128 B로 늘어 추가 공간 112 B다.

  4. 32 MiB/(8 GiB/s) = 32/(8×1024) s = 1/256 s = 3.90625 ms다. 같은 경계를 총 64 MiB 넘는다면 7.8125 ms의 이상적 하한이다.

지정한 가상 경로의 소유권 전환은 5회 대 0회, 슬롯 공간은 16 B 대 128 B다. 전송 하한은 3.90625/7.8125 ms이며 실제 시간이나 개선률은 아직 미측정이다.

종이와 본문으로 직접 해보기

공유 라인의 쓰기 순서를 C0,C0,C0,C1,C1,C1로 묶으면 전환은? 별도 십진 단위 모형에서 B=8 GB/s, 계산 상한 P=40 GFLOP/s, 8 FLOP당 전송 8 B일 때 Roofline 상한을 계산하고 전송을 2 B로 줄인 경우와 비교하라.

힌트 보기

초기 소유자는 C0다. 집약도는 FLOP/B이며 같은 전송 경계를 사용한다.

풀이 보기

묶은 순서는 C0에서 C1로 바뀌는 한 번만 전환한다. 첫 집약도는 1 FLOP/B라서 min(40,8×1)=8 GFLOP/s다. 전송 2 B이면 집약도 4, 상한 min(40,8×4)=32 GFLOP/s다. 둘 다 달성 성능이 아니라 이 모형의 상한이며, 바이트를 줄였다는 가정도 실제 경계에서 확인해야 한다.

오해와 반례

padding을 하면 항상 빨라지고 코어를 늘리면 대역폭 제한이 사라진다.

분리는 공간·배치 비용이 있고 다른 병목이 남는다. 공유 메모리 경로의 대역폭과 연산 상한은 실제 조건에서 확인해야 하며 가상 전환 횟수는 실측 속도가 아니다.
