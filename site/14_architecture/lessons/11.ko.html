소단원 11.1

direct·set·fully associative

전체 저장칸이 남아 있는데도 두 메모리 블록이 서로를 계속 밀어낼 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 메모리의 바이트 주소와 블록을 안다.

  • 이진 자릿수와 나머지를 계산한다.

학습 목표

  • 전체 line 수와 set 수와 way 수를 구별한다.

  • 주소의 tag/index/offset을 계산한다.

  • 동일 데이터 용량에서 배치 제약을 비교한다.

같은 tag가 보이는 다른 set의 줄을 반환해도 될까?

자체 캐시는 8비트 바이트 주소, C=16바이트, B=4바이트, 2-way다. 총 네 줄이고 set는 두 개다. 주소 19는 블록 4·offset 3·set 0·tag 2, 주소 23은 블록 5·offset 3·set 1·tag 2다. 두 주소의 tag와 offset은 같지만 set가 다르다.

줄에 보관한 tag만 보고 캐시 전체를 검색하면 서로 다른 set의 tag 2를 혼동할 수 있다. 2-way에서는 주소로 정한 set 안의 두 후보만 살피고 valid와 tag를 확인한다. fully associative로 바꾸면 set가 하나인 대신 tag에 블록 번호 전체를 포함하므로 이 예의 tag는 각각 4와 5로 달라진다.

퇴출하는 줄의 원래 블록 주소도 새 요청 주소와 구별한다. 2-way set 1의 tag 2가 담은 블록 시작은 (2×2+1)×4=20이다. offset은 줄 전체 전송 주소에 포함하지 않는다. 이 계산은 정의한 단순 물리 바이트 주소 모형이며 가상 주소나 실제 캐시 칩을 측정한 것이 아니다.

먼저 확인할 개념
  • 주소의 tag·index·offset

    set가 주소 해석의 일부임을 확인한다.

  • dirty 줄의 퇴출

    반송 주소가 새 요청의 주소와 다른 이유를 확인한다.

배치는 블록이 들어갈 수 있는 자리를 정한다

캐시는 메모리 블록의 사본을 담는 작은 빠른 저장소다. direct-mapped는 각 블록이 한 line에만 들어갈 수 있다. set-associative는 먼저 set 하나를 정하고 그 안의 여러 way 중 하나에 넣는다. fully associative는 전체 line 중 어디든 넣을 수 있다. 여기서 line은 캐시 저장자리, 블록 번호는 메모리 구간을 가리키도록 구별한다.

데이터 용량 C, 블록 바이트 수 B, way 수 W라면 line 수 L=C/B, set 수 S=L/W다. 같은 C와 B에서 way를 늘리면 set 수가 줄어든다. direct는 W=1, fully는 S=1이다. 실제 저장 비용에는 데이터뿐 아니라 tag/valid/dirty/교체 정보도 들어가므로 데이터 용량이 같아도 총 회로 비용까지 같은 것은 아니다.

주소를 블록 번호와 블록 안 위치로 나눈다

비음수 바이트 주소 a에서 block=floor(a/B), offset=a modB다. 이 단원의 단순 배치는 set=block modS, tag=floor(block/S)다. B와 S가 2의 거듭제곱이고 주소 폭이 정해졌을 때 하위 log₂B비트는 offset, 다음 log₂S비트는 index, 나머지가 tag다. fully associative는 index비트가 없다.

조회는 올바른 set에서 valid가 켜진 line의 tag와 비교해야 한다. 같은 index만으로 같은 데이터를 보장하지 않는다. set 내부 way 번호는 메모리 주소에 고정된 추가 index가 아니라 현재 배치와 교체 상태에 의해 정해진다. 주소 비트 분해에서 way 수를 set 수와 혼동하면 tag와 index가 틀어진다.

더 자유로운 배치에는 비교 비용도 있다

direct는 한 후보 tag를 확인하지만 W-way는 해당 set의 후보들을 확인한다. fully는 모든 line을 후보로 다룬다. 구현은 병렬 비교 등 하드웨어를 사용할 수 있으므로 종이의 후보 수를 CPU가 순차적으로 읽는 명령 수와 같다고 하지 않는다. 배치의 자유는 충돌을 줄일 수 있지만 회로·에너지·hit 지연의 절충이 있다.

이 원고의 모델은 초기 모든 line invalid, 단일 처리기의 읽기, 같은 블록 크기와 데이터 용량, miss이면 블록 채움을 가정한다. 가상/물리 주소 혼합·일관성·prefetch 등은 포함하지 않는다. 비교에서 초기 상태나 총 데이터 용량을 바꾸어 놓고 way만의 효과라고 해석하지 않는다.

소단원 11.2

replacement·write policy

자주 쓰던 블록을 내보내는 기준과 새 값을 메모리에 보내는 기준은 같은 문제일까?

준비 개념과 학습 목표

준비 개념

  • set과 way를 안다.

  • 읽기와 저장, 이전 값과 새 값을 구별한다.

학습 목표

  • LRU와 FIFO가 서로 다른 희생자를 고르는 과정을 추적한다.

  • write hit 정책과 write miss 할당 정책을 분리한다.

  • dirty 블록의 퇴출에서 write-back을 추적한다.

한 단어만 저장할 때 같은 블록의 다른 단어는 어떻게 지킬까?

자체 블록 A는 16바이트로 4바이트 단어 네 개 [1,2,3,4]를 담는다. 캐시는 한 줄, 처음 비어 있다. write-back+write-allocate에서 offset 4의 단어를 9, 이어 10으로 바꾸고 다른 블록 B를 읽어 A를 퇴출한다. A 전체를 먼저 채우고 해당 단어만 바꿔 [1,10,3,4]를 유지해야 한다.

write-allocate miss에서 변경한 단어만 넣고 나머지를 0으로 만드는 자체 잘못된 구현은 [0,10,0,0]을 반송해 저장하지 않은 세 단어까지 손상한다. 전체 블록 채움을 생략하려면 부분 valid·부분 쓰기 등 별도 규약이 필요하며 여기의 전체 valid 한 비트 모형에 몰래 섞지 않는다.

전송 크기도 세어 보자. 두 정책 모두 allocate로 A와 B를 16바이트씩 읽는다. write-back은 A 전체 16바이트를 한 번 반송해 총 48바이트다. write-through+allocate는 두 4바이트 저장을 보내 총 40바이트다. 단일 단어 갱신 두 번에서는 요청 수가 적은 write-back이 오히려 더 많은 바이트를 보낸다. 버스 포장·동시성·쓰기 버퍼는 제외한 자체 데이터 양이다.

먼저 확인할 개념
  • write policy와 dirty

    저장 전파·miss 할당·퇴출을 별도 사건으로 센다.

  • block 배치와 주소

    offset가 블록 중 한 단어를 고른다는 것을 확인한다.

교체는 허용된 후보 중 희생자를 고른다

set에 invalid line이 있으면 우선 그 빈자리를 사용할 수 있다. set이 가득 차면 어떤 line을 내보낼지 정한다. LRU는 가장 오래 접근하지 않은 항목을, FIFO는 가장 먼저 채워진 항목을 고른다. LRU는 hit도 최근성을 바꾸지만 FIFO의 채움 순서는 읽기 hit로 바뀌지 않는다는 차이가 있다.

교체 정책은 배치 제약을 넘지 못한다. direct는 그 index의 한line이 유일한 희생자다. 2-way에서도 해당 set의 두line 중 선택하며 다른 set의 빈자리에 마음대로 놓지 않는다. 실제 대용량 캐시는 정확한 LRU 대신 근사 정책을 쓸 수 있어 원고의 정확한 LRU 표를 모든 하드웨어의 실제 동작으로 일반화하지 않는다.

쓰기 전파와 miss 할당은 두 축이다

write-through는 저장을 캐시와 다음 계층에 전파한다. write-back은 캐시 내용을 바꾸고 dirty 상태로 표시한 뒤 퇴출 등에 다음 계층으로 보낸다. 다음 계층을 이 단순 모델에서는 메모리라고 부르지만 실제 계층에서는 다른 캐시일 수 있다. dirty는 다음 계층과 내용이 다를 수 있다는 표시이며 valid와 다른 의미다.

write miss에 write-allocate면 블록을 가져와 캐시에 놓고 저장한다. no-write-allocate면 해당 저장을 다음 계층으로 보내며 이 모델에서는 캐시에 새line을 채우지 않는다. write-through/back 선택과 allocate/no-allocate 선택은 다른 질문이다. 흔한 조합이 있어도 두 용어를 같은 뜻으로 외우지 않는다.

변경한 데이터를 버리지 않는다

write-back line을 채울 때는 clean으로 시작한다. 저장하면 dirty가 되고, dirty line을 내보낼 때 새 내용을 다음 계층에 전달해야 한다. clean line 퇴출에는 그 변경 쓰기가 필요 없다. 여러 번 같은 line을 갱신하면 마지막 내용으로 합쳐 보낼 수 있지만 실제 병합·쓰기 버퍼·동시성은 별도 구현 조건이다.

여기의 횟수 계산은 블록 채움과 다음 계층 쓰기 요청을 나누고 단일line에 한 값이 관심 대상이라고 단순화한다. byte 저장과 전체line 전송은 크기가 다를 수 있으므로 요청 횟수만으로 전송 바이트나 소요 시간을 비교하지 않는다. 실제 다른 처리기의 조회와 일관성, 장애 시 보존도 이 표만으로 보장하지 않는다.

소단원 11.3

miss 유형과 최적화

처음 본 블록을 못 찾은 것과 방금 보았는데 밀려나 다시 못 찾은 것은 같은 원인일까?

준비 개념과 학습 목표

준비 개념

  • 초기 invalid와 캐시 채움을 안다.

  • direct와 fully, LRU를 이해한다.

학습 목표

  • compulsory/conflict/capacity를 정한 기준으로 분류한다.

  • 접근 순서의 공간/시간지역성을 추적한다.

  • 용량 고정 상태의 블록 크기 절충을 설명한다.

기준 캐시가 miss한 요청을 대상 캐시가 hit할 수도 있을까?

자체 3C 분류는 빈 읽기 캐시, 블록 1단위, 대상 direct 두 줄과 같은 두 줄 fully associative exact-LRU 기준을 둔다. 두 모형 모두 모든 요청을 순서대로 처리한다. 최초 메모리 블록 접근은 compulsory이며, 이후 대상 miss에서 기준 hit면 conflict, 기준 miss면 capacity로 분류한다.

블록열은 0,2,0,1,3,0,2다. 대상은 set=block mod 2다. 세 번째 0에서 대상은 2 때문에 miss지만 기준에는 0이 남아 hit라 conflict다. 여섯 번째 0에서는 대상 set 0에 0이 남아 hit지만 기준 LRU는 1/3을 보유해 miss다. 이 요청은 대상 miss가 아니므로 3C miss 수에 넣지 않는다.

마지막 2는 양쪽에서 miss이며 처음 접근이 아니라 capacity다. 대상의 최종 집계는 compulsory 4, conflict 1, capacity 1, hit 1이다. 기준 LRU가 더 자유로운 배치를 가진다는 사실만으로 모든 순간의 보유 블록이 대상의 상위 집합이라고 가정하지 않는다. 일관성 무효화·prefetch·쓰기 miss는 이 분류 모형에 포함하지 않는다.

먼저 확인할 개념
  • miss 유형의 비교 기준

    최초 접근·대상 miss·기준 결과의 순서로 판정한다.

  • 배치와 교체의 차이

    대상 direct와 기준 LRU의 상태 변화를 각각 기록한다.

분류 전에 비교 모형을 정한다

이 단원은 초기 빈 캐시, 읽기 demand 접근, prefetch와 일관성 무효화 없음, 동일 총 데이터 용량과 블록 크기, 기준 fully associative의 정확한 LRU를 가정한다. 최초 메모리 블록 접근에서 생긴 miss는 compulsory다. 나중의 miss가 동일 용량 기준에서도 생기면 capacity, 기준에서는 hit인데 대상에서는 miss라면 conflict로 분류한다.

이 기준은 빈 저장 line 자체가 아니라 메모리 블록의 최초 접근을 센다. 빈 line에 처음 다른 블록을 넣는다고 모두 compulsory가 아니다. 실제 현대 시스템의 miss에는 일관성 무효화나 prefetch 효과 등도 있으므로 이 3C 모형의 범위를 밝힌다.

반복 충돌과 용량 부족을 반례로 나눈다

총 4line direct에서 블록 0,4,0,4는 같은 index 0을 반복 교체한다. 처음 0/4는 compulsory, 뒤 0/4는 4line fully가 둘 다 보유하므로 conflict다. 전체 용량이 둘을 담기에 충분해도 배치가 방해한다.

반대로 2line fully LRU에서 0,1,2,0은 처음 세 블록이 compulsory이고 마지막 0은 capacity다. 셋째 2를 채울 때 0이 퇴출되므로 더 자유로운 배치도 고정된 2line으로 모두 보유할 수 없다. 이 예에서는 한순간에 참조하는 블록 수와 재사용까지의 다른 접근이 관련된다.

순서를 바꾸어 재사용 거리를 줄인다

행렬의 같은 결과를 계산하더라도 주소 방문 순서가 달라질 수 있다. 행을 따라 연속 원소를 읽으면 같은 블록의 이웃 원소를 곧바로 활용한다. 타일링은 작은 부분을 반복해 필요한 데이터를 캐시에 남게 하는 방법이다. 다만 자료의 실제 메모리 배치, 원소 크기, 다른 메모리 접근을 먼저 정해야 효과를 계산할 수 있다.

캐시 데이터 용량을 고정하고 블록을 키우면 이웃 데이터를 더 가져오지만 line 수는 줄어든다. 쓰지 않는 이웃 데이터로 전송량이 늘거나 충돌·용량 문제가 커질 수 있다. associativity도 충돌을 줄일 수 있지만 hit 지연과 비용에 영향을 준다. 특정 최적화가 모든 프로그램에서 항상 빠르다고 하지 않는다.

소단원 11.4

다층cache의 성능 분석

L2의 miss율20%라는 말은 모든 CPU 요청20%가 메모리까지 갔다는 뜻일까?

준비 개념과 학습 목표

준비 개념

  • 평균과 조건부 비율을 안다.

  • hit와 miss 및 추가 penalty를 구별한다.

학습 목표

  • local과 global miss율의 분모를 명시한다.

  • 다층 AMAT를 추가 시간 기준으로 계산한다.

  • hit 지연 증가와 miss 감소의 절충을 비교한다.

dirty 퇴출 비용은 모든 miss에 똑같이 더하면 될까?

자체 직렬 모형에서 전체 읽기 요청 1000회 중 캐시 miss가 100회다. 확인 시간은 모든 요청에 1ns, miss의 새 블록 채움은 추가 50ns다. 그 100 miss 중 정확히 25회에서 dirty 희생자를 내보내며 그때만 추가 20ns를 쓴다. 다른 쓰기나 병렬 전송은 제외한다.

총 비용은 1000×1 + 100×50 + 25×20 = 6500ns로 AMAT 6.5ns다. dirty 비율 25%의 분모는 miss 100이며 전체 요청 기준 반송 비율은 2.5%다. 따라서 1 + 0.1×(50+0.25×20)과 1+0.1×50+0.025×20이 같다.

같은 집계라도 실제 비차단 캐시의 동시 채움·쓰기 버퍼·메모리 병렬성은 이 합에 포함되지 않는다. 프로그램의 실행 시간이나 최악 지연도 별도 질문이다. 이 절의 추가 비용은 계산 연습용이며 실제 DRAM·캐시에서 측정한 수치가 아니다.

먼저 확인할 개념
  • 다층 비율의 분모

    조건부 비율과 전체 비율을 구별한다.

  • dirty 희생자 반송

    clean 퇴출에는 이 모형의 변경 반송 비용이 없는 이유를 확인한다.

시간을 중복해서 더하지 않는다

직렬적인 단순 읽기 모형에서 L1을 먼저 확인하는 시간 t1을 모든 요청에 지불한다. L1 miss이면 L2 확인 추가 시간 t2를 지불하고 L2에서도 miss이면 메모리 추가 시간 tm을 지불한다. 각 시간은 이 정의의 추가 시간이며 총 miss 시간을 다시 penalty에 넣어 L1 시간을 두 번 더하지 않는다.

L1 miss율 r1은 전체 요청 중 비율이다. L2 local miss율 r2는 L2까지 온 요청 중 miss 비율이다. 따라서 메모리까지 가는 전체 요청 비율은 r1r2다. 상위 요청과 하위 요청을 직렬 서비스하는 모형이며 비차단 cache/중첩 miss/prefetch/writeback 대기 등은 포함하지 않는다.

하위 평균을 상위 penalty로 연결한다

AMAT=t1+r1(t2+r2tm)이다. 괄호는 L1 miss일 때부터의 평균 추가 시간이다. 전개하면 t1+r1t2+r1r2tm이므로 L2 시간은 L1 miss에서만, 메모리 시간은 두 miss에서만 가중한다. 단위를 ns 등으로 통일하고 비율 10%는 0.1로 넣는다.

L2 global miss율 g2가 이미 전체 요청 중 메모리 비율이라면 메모리 항은 g2tm이다. 이때 다시 r1을 곱하면 틀린다. local/global이라는 이름만 쓰기보다 전체 100요청 중 몇 건인지와 L2 도착 10건 중 몇 건인지를 같이 적으면 분모 혼동을 줄일 수 있다.

평균 접근시간과 전체 프로그램시간을 나눈다

더 큰 L1이 miss를 줄여도 hit 시간을 늘리면 AMAT가 오히려 커질 수 있다. 하위 계층의 miss율과 penalty도 함께 달라질 수 있어 한 수치만 비교하지 않는다. 블록 전송·dirty 퇴출·쓰기 버퍼 비용을 포함하려면 모형을 확장하고 추가 항의 조건을 명시한다.

AMAT는 이 모형의 메모리 접근 한 건 평균이지 프로그램의 모든 명령 평균이나 최악 지연이 아니다. 명령 계산 시간, 접근 수, 동시 접근, 메모리 수준 병렬성이 프로그램 시간에 영향을 준다. 실제 프로파일이 없으면 자체 수치를 실제 CPU 성능이라고 보고하지 않는다.

다른 문제에 적용하기

옛 주소·부분 저장·3C 기준·조건부 비용

C16/B4/2-way에서 set 1의 dirty tag 2를 내보낼 시작 주소를 구하라. 16바이트 블록 A=[1,2,3,4]의 두 번째 단어를 9·10으로 저장한 뒤 B 읽기 퇴출에서 A값과 WB/WT 데이터 양을 비교하라. 두 줄 direct와 같은 두 줄 FA-LRU의 블록 0,2,0,1,3,0,2에서 대상 3C와 hit를 분류하라. 마지막으로 N1000/M100/D25, h1/p50/w20ns의 직렬 AMAT를 계산하라.

힌트 1

교체할 옛 tag와 새 요청 주소를 따로 둔다.

힌트 2

분류와 비용 모두 대상 사건과 기준·조건부 사건의 분모를 표시한다.

풀이와 답 확인

  1. 옛 블록 번호는 tag × S + set = 2 × 2 + 1 = 5다. 블록 크기는 4바이트이므로 반송할 블록의 시작 바이트 주소는 5 × 4 = 20이다.

  2. A에서 갱신하지 않은 단어까지 보존한 최종 데이터는 [1,10,3,4]다. WB 정책에서는 두 번의 채움으로 32바이트, 반송으로 16바이트를 보내므로 총 전송량은 48바이트다. WT 정책에서는 채움으로 32바이트, 두 번의 단어 쓰기로 8바이트를 보내므로 총 40바이트다.

  3. 대상 direct 캐시의 hit/miss 순서는 MMMMMHM이다. 대상에서 발생한 miss만 분류하면 compulsory miss는 4회, conflict miss는 1회, capacity miss는 1회다. hit는 1회다. 여섯 번째 요청은 FA-LRU 기준 캐시에서 miss지만 대상 캐시에서는 hit이므로 대상의 miss 분류에 넣지 않는다.

  4. 전체 요청 1,000회의 hit 검사 시간은 1,000ns다. miss 100회의 추가 시간은 5,000ns이고, dirty 반송 25회의 추가 시간은 500ns다. 총시간은 6,500ns이므로 AMAT는 6,500 / 1,000 = 6.5ns다. 전체 요청을 분모로 잡으면 dirty 반송 비율은 25 / 1,000 = 2.5%다.

주소·원래 데이터·교체 기준·조건부 횟수와 비용을 별도 장부로 대조한다. 자체 모형 검토이며 실제 캐시·버스·CPU·학습자 실험은 미수행이다.

해결한 뒤 점검할 것

  • 옛 set/tag로 반송 주소를 복원한다.

  • 갱신하지 않은 단어도 보존하고 요청 수와 바이트 수를 나눈다.

  • 같은 trace의 기준을 매 요청 갱신하고 대상 miss만 분류한다.

  • 추가 직렬 비용과 중첩 비용 가정을 구별한다.
