주소는 어느 공간의 번호인지 함께 읽는다

CPU가 프로그램의 명령에서 계산하는 주소를 가상 주소라고 하자. 주소변환이 켜진 현재 실행 문맥에서 MMU라는 변환·보호 장치가 그 주소를 물리 주소로 옮긴다. 프로그램이 보는 번호와 메모리 시스템의 번호 사이에 대응을 놓아 서로 다른 프로그램의 공간을 관리한다. 이 절은 바이트 주소와 기본 페이지 하나 안의 접근을 가정한다.

같은 숫자라도 주소 공간이 다르면 대상은 다를 수 있다. 반대로 다른 가상 주소를 같은 물리 프레임에 연결하여 데이터를 공유할 수도 있다. 가상 주소가 있다고 그만큼 RAM이 실제 할당되어 있거나 모두 접근 가능한 것은 아니다. 물리 주소도 실제 장치의 RAM·메모리 매핑 I/O 구성과 범위를 따로 따른다.

페이지 내부 위치는 보존한다

페이지 크기를 4 KiB=4096바이트로 정하면 가상 주소 VA를 4096으로 나눈 몫이 가상 페이지 번호 VPN, 나머지가 오프셋이다. 오프셋은 0부터 4095라 12비트다. 페이지 표에서 VPN에 해당하는 물리 프레임 번호 PFN을 얻으면 PA=PFN×4096+offset으로 만든다.

이 계산에서 오프셋은 변환하지 않는다. 페이지와 프레임의 크기가 같기 때문에 안쪽의 같은 바이트를 선택한다. 실제 ISA의 큰 페이지, 여러 단계 변환과 주소의 적법성·권한 검사는 추가 조건이다. 64비트 레지스터라고 64비트 가상 주소 전체를 항상 사용할 수 있다고 가정하지 않는다. 예컨대 RISC-V Sv39는 상위 비트의 부호 확장 규칙을 별도로 정한다.

연속 공간은 연속 프레임을 요구하지 않는다

가상 페이지 1이 물리 프레임 7, 가상 페이지 2가 물리 프레임 3에 연결됐다고 하자. 가상 주소 0x1FFF 다음 바이트는 0x2000이지만 물리 주소는 0x7FFF 다음에 0x3000으로 옮겨간다. 페이지 경계를 넘으면 다른 표 항목을 사용하기 때문이다. 배열의 가상 연속성을 곧 물리 연속성으로 해석하지 않는다.

두 프로세스 P,Q의 VPN 1을 각각 프레임 7,9로 연결하면 동일한 가상 주소 0x1234가 서로 다른 물리 주소를 얻는다. 공유 프레임으로 연결할지 분리할지는 OS의 매핑 정책이다. 주소 숫자만 로그에 남기면 공간·프로세스·페이지 크기 없이 의미를 복원하기 어렵다.

중간 과정을 따라가는 예제

페이지는 4096바이트다. P의 VPN 1→PFN 7, VPN 2→PFN 3이고 Q의 VPN 1→PFN 9다. 각 공간의 0x1234와 P의 0x1FFF,0x2000을 변환하라.

  1. 0x1234=4660=1×4096+564다. VPN 1, 오프셋 0x234=564를 얻는다.

  2. P는 PA=7×4096+564=29236=0x7234다. Q는 9×4096+564=37428=0x9234다.

  3. P의 0x1FFF는 VPN 1, 오프셋 4095라 PA=32767=0x7FFF다. 0x2000은 VPN 2, 오프셋 0이라 PA=12288=0x3000이다.

  4. 권한과 유효성이 허용된 매핑이라는 가정에서 구한 주소다. 현재 실제 컴퓨터의 페이지 표를 읽거나 메모리를 접근한 결과는 아니다.

같은 가상 0x1234라도 P는 0x7234, Q는 0x9234다. P의 페이지 경계는 물리적으로 0x7FFF→0x3000으로 이어진다.

종이와 본문으로 직접 해보기

페이지 크기를 1024바이트로 바꾼 별도 모델에서 VA=3500, VPN 3→PFN 6을 변환하라. 기존 4 KiB 결과를 그대로 써도 되는가?

힌트 보기

3500을 1024로 나누어 몫과 나머지를 새로 구한다.

풀이 보기

3500=3×1024+428이다. PA=6×1024+428=6572다. 오프셋은 10비트이며, 페이지 크기가 달라 기존 12비트 분할을 그대로 쓰면 안 된다.

오해와 반례

가상 주소에 고정 상수를 더하면 언제나 물리 주소가 된다.

단일 base 모델에서는 가능하지만 일반 페이징에서는 페이지별 PFN이 다르다. P의 0x1FFF와 0x2000 예제에서 한 상수를 더해 두 변환을 동시에 만들 수 없다.

page table·TLB

준비 개념과 학습 목표

준비 개념

  • 페이지 번호와 오프셋

  • 배열 인덱스

  • 캐시의 적중·미스

학습 목표

  • 페이지 표와 번역 캐시의 역할을 구별한다.

  • TLB 미스와 페이지 fault를 분리한다.

  • 표 크기와 간단한 적중 추적을 계산한다.

페이지 표는 매핑과 상태를 담는다

페이지 표의 항목 PTE에는 매핑 대상과 허용 접근 등의 상태가 들어간다. 간단한 선형 표는 VPN을 인덱스로 사용한다. 모든 VPN에 하나씩 항목을 준비하면 쓰지 않는 주소 공간까지 큰 표가 필요하므로 실제 설계는 여러 단계로 나누어 필요한 아래쪽 표만 만드는 방법도 쓴다.

주소변환 하드웨어는 현재 주소 공간의 표 시작점과 규격을 알아야 한다. 표가 메모리에 있다고 일반 프로그램이 마음대로 고칠 수 있는 것은 아니다. 보호된 커널 관리 자료다. TLB는 그 표 전체와 같은 자료구조가 아니라 최근 번역 결과와 필요한 권한 정보를 빠르게 이용하는 작은 캐시다.

번역이 캐시에 없는 것과 번역 불가능은 다르다

TLB hit이면 저장된 번역과 권한으로 접근을 진행한다. miss이면 표를 따라 번역을 찾는 추가 작업이 필요하다. 표에 유효하고 허용된 매핑이 있으면 캐시를 채워 접근을 끝낼 수 있다. 따라서 miss만으로 디스크를 읽거나 프로세스를 종료하는 것은 아니다.

MMU가 표를 순회하는 하드웨어 refill과 OS가 trap을 받아 번역을 채우는 소프트웨어 refill은 서로 다른 설계다. 현재 RISC-V의 페이지 표 형식은 하드웨어 순회를 지원하며, 모든 RISC가 소프트웨어 refill이라는 규칙은 없다. 데이터 캐시는 메모리 내용, TLB는 주소변환을 저장하므로 두 종류의 hit/miss를 동일하게 세지 않는다.

서로 다른 공간의 같은 번호를 구별한다

P,Q가 같은 VPN을 다른 PFN으로 쓰면 TLB도 어느 주소 공간의 번역인지 알아야 한다. ASID라는 식별자로 구별하거나 문맥 전환 때 적절히 무효화하는 방법이 있다. ASID는 운영체제의 PID와 반드시 같은 번호·너비가 아니며 재사용 시 오래된 번역 관리가 필요하다.

TLB 용량과 교체 정책에 따라 같은 주소열도 적중률이 달라진다. 아래 종이 예제는 두 항목, 완전 연관, LRU, 시작 시 비어 있음, 한 주소 공간과 성공하는 기본 페이지 접근을 명시한다. 실제 CPU의 다단 TLB·캐시·병렬 처리 시간을 이 모델의 숫자로 측정했다고 주장하지 않는다.

중간 과정을 따라가는 예제

12비트 가상 주소, 256바이트 페이지, PTE당 4바이트인 선형 표의 크기를 구하라. 별도로 두 항목 LRU TLB에서 VPN 접근 1,1,2,1,3,2를 추적하라.

  1. 오프셋은 8비트, VPN은 4비트라 총 16개 가상 페이지다. 선형 표는 16×4=64바이트다.

  2. TLB에서 첫 1은 miss, 두 번째 1은 hit, 2는 miss다. 이때 최근 순서가 오래된 1, 새로운 2다.

  3. 다음 1은 hit로 2가 오래된 항목이 된다. 3은 miss라 2를 내보낸다. 마지막 2는 miss라 1을 내보낸다.

  4. 결과 M,H,M,H,M,M이고 hit 2/6=1/3이다. 모든 페이지 표가 성공하므로 fault 수는 0이다.

선형 표는 64바이트이고 주어진 TLB 모델의 적중률은 1/3, 미스는 네 번이다. 미스와 fault가 같은 횟수가 아니다.

종이와 본문으로 직접 해보기

같은 접근열을 세 항목 LRU TLB로 바꾸어 hit 수를 구하라. 32비트 주소·4 KiB 페이지·PTE 4바이트인 단일 선형 표 크기도 계산하라.

힌트 보기

세 VPN을 모두 유지하면 마지막 2가 남아 있다. 큰 표는 VPN 20비트다.

풀이 보기

세 항목에서는 M,H,M,H,M,H이므로 hit 3/6=1/2다. 큰 선형 표는 2^20×4=2^22바이트=4 MiB다. 이 크기는 단일 선형 표 모델이며 다단계 표의 실제 할당량은 사용 매핑에 따라 다르다.

오해와 반례

TLB miss는 필요한 데이터가 디스크에 있다는 뜻이다.

TLB에 번역이 없다는 뜻일 뿐이다. 이미 RAM에 매핑된 페이지의 표를 읽고 성공할 수 있다. 데이터 위치와 페이지 fault의 원인은 별도로 판별한다.

permission와 translation fault

메모리에 페이지가 있어도 읽기·쓰기·명령 실행이 모두 허용될까?

준비 개념과 학습 목표

준비 개념

  • 유효한 매핑

  • 프로세스와 사용자 모드

  • 읽기·쓰기·실행

학습 목표

  • 매핑 유효성·권한·모드를 따로 확인한다.

  • 캐시 hit에서도 권한 실패가 가능함을 설명한다.

  • ISA 예외와 OS의 복구·거부 판단을 구별한다.

주소를 얻는 것만으로 접근이 허용되지 않는다

읽기 R, 쓰기 W, 실행 X 권한은 각기 다른 동작에 대한 허가다. 사용자 모드에서 접근 가능한지도 확인한다. 번역이 성공할 수 있는 페이지라도 사용자가 커널 전용 페이지를 읽거나 읽기 전용 코드에 쓰면 허용되지 않는다. TLB hit은 속도의 사건이지 접근 허가를 대신하는 인증서가 아니다.

실제 표 비트와 예외 이름은 ISA마다 다르다. RISC-V에서는 leaf의 U/R/W/X와 현재 모드·SUM/MXR 등의 규칙을 함께 확인한다. W=1,R=0은 임의의 쓰기 전용 페이지가 아니라 예약된 조합이다. 따라서 모든 3비트 조합을 자유로운 권한으로 해석하지 않는다. 아래 예제는 사용자 모드, 정상 leaf, A/D 상태 정상 및 추가 물리 보호 문제가 없다는 제한 모델이다.

fault는 원인을 전달하고 처리 정책은 OS가 정한다

주소변환 중 유효하지 않은 항목, 허용되지 않은 접근 또는 주소 형식 문제 등이 예외를 만들 수 있다. RISC-V의 load/store/instruction page fault는 접근 종류도 구별한다. 표를 읽는 물리 접근이 보호에 걸리면 access fault가 되는 경우도 있어 모든 실패를 같은 이름으로 부르지 않는다.

OS는 예외 주소와 종류를 읽고 자기 메모리 관리 정보를 살펴본다. 실제로 금지된 주소면 접근을 거부할 수 있고, 허용된 지연 할당이나 COW처럼 복구 가능한 상황이면 표를 바꾸고 다시 실행할 수 있다. 하드웨어 비트 하나만 보고 스왑된 데이터인지, 아직 할당 안 된 합법적 영역인지, 불법 영역인지 모두 판별하지 않는다.

읽기 전용은 오류 탐지와 지연 복사에 쓰인다

MIT xv6 COW 실습은 원래 쓰기 가능했던 공유 페이지를 읽기 전용으로 두어 쓰기에서 예외를 받는 사례다. OS가 COW 표시를 확인하고 새 프레임을 복사하여 쓰기 가능한 독립 매핑을 만든다. 원래부터 읽기 전용인 코드에 대한 쓰기는 같은 방식으로 무조건 허용하지 않는다.

복구가 가능하더라도 메모리 부족이나 잘못된 상태면 성공을 보장할 수 없다. 보호 상태를 바꾸면 번역 캐시가 낡은 권한을 사용하지 않도록 필요한 동기화도 해야 한다. 실제 페이지 fault 실습을 수행하지 않아도 접근 종류·모드·권한 표를 종이에 대조하여 실패 이유를 분석할 수 있다.

중간 과정을 따라가는 예제

사용자 모드에서 P0는 유효 U=1,R=1,W=0,X=1, P1은 유효 U=1,R=1,W=1,X=0, P2는 유효 U=0,R=1,W=1,X=0, P3는 V=0이다. P0 읽기·쓰기·실행, P1 실행, P2 읽기, P3 읽기를 판정하라.

  1. 추가 제약이 없다는 조건에서 P0 읽기와 실행은 허용된다. 쓰기는 W=0이라 store page fault다.

  2. P1은 데이터 읽기·쓰기는 가능하지만 X=0이라 instruction page fault다. R=1이라고 명령 실행까지 허용하지 않는다.

  3. P2는 읽기 비트가 있어도 U=0이라 사용자 모드 load page fault다. 권한 비트만 보고 현재 모드를 빼면 잘못 판정한다.

  4. P3는 유효하지 않아 load page fault다. OS가 복구할지 거부할지는 페이지 관리 정보가 더 필요하다. P0 쓰기가 COW인지도 이 표만으로 알 수 없다.

P0 읽기·실행만 성공하며 나머지 네 요청은 명시한 이유로 page fault다. 이 결과는 실제 ISA 전체 상태를 축약한 조건부 판정이다.

소단원 12.4

하드웨어와 OS 역할

OS가 변환표를 한 칸 고치면 모든 CPU가 즉시 새 주소를 사용하게 될까?

준비 개념과 학습 목표

준비 개념

  • 페이지 표와 TLB

  • 예외 처리

  • 여러 CPU의 실행

학습 목표

  • 정책 설정·빠른 검사·예외 처리를 나누어 설명한다.

  • PTE 변경과 번역 캐시 동기화를 구별한다.

  • COW의 공유·복사·참조 수 과정을 추적한다.

OS는 정책을 만들고 하드웨어는 실행 중 적용한다

OS는 프레임을 할당하고 주소 공간과 페이지 표를 만들며 권한·공유 정책을 설정한다. CPU/MMU는 그 현재 설정에 맞춰 번역과 보호 검사를 적용한다. 예외가 나면 OS 처리기가 상황을 판별한다. 모든 메모리 읽기마다 커널 코드가 함수처럼 호출된다고 생각하면 정상 경로의 역할을 잘못 나눈다.

표 순회를 하드웨어가 하는지 소프트웨어 refill이 필요한지는 설계에 달렸다. 이 차이와 별개로 누가 어떤 프레임을 소유할지, 언제 복구·종료할지 같은 관리 정책은 OS의 책임이다. 페이지 표를 고치는 코드 자체도 특권과 동시 접근 관리가 필요하다.

메모리의 표와 CPU의 번역 상태를 맞춘다

기존 VPN 1→PFN 7 번역을 TLB가 기억할 때 OS가 PTE만 PFN 9로 바꿨다고 하자. 오래된 번역을 사용하면 여전히 PFN 7에 접근할 수 있다. 표의 일반 메모리 쓰기와 번역 캐시의 최신성 확보는 구별되는 일이다. 데이터 캐시를 무효화하는 것과 주소변환 동기화도 같은 명령이라고 단정하지 않는다.

RISC-V SFENCE.VMA는 지정 범위의 로컬 hart 번역 상태와 페이지 표 갱신을 동기화하는 명령이다. satp 쓰기만으로 모든 이전 번역이 자동 무효화된다고 보장되지 않는다. 다른 hart의 상태도 필요한 경우 OS가 별도 통지·동기화·완료 확인을 구성한다. 페이지나 프레임을 다시 쓰기 전에 이전 접근 가능성이 남지 않도록 순서를 설계해야 한다.

간접 매핑으로 복사를 필요한 순간까지 미룬다

COW에서 부모와 자식이 같은 프레임 7을 읽기 전용으로 공유한다고 하자. 자식의 쓰기 fault에서 새 프레임 9에 내용을 복사하고 자식 매핑을 바꾸면 부모는 기존 값을 보며 자식은 독립 값을 쓸 수 있다. 하드웨어는 COW 정책을 추측하지 않고 설정된 권한에 따라 예외를 전달한다.

공유 프레임의 참조 수는 매핑이 사라질 때 줄이고 마지막 참조가 없어질 때만 반환한다. CPU가 오래된 번역을 사용할 수 있는 상태에서 프레임을 재활용하면 다른 데이터에 잘못 접근할 위험이 있다. 원자적인 표 갱신과 필요한 번역 동기화, 자원 부족 처리까지 관리해야 완전한 정책이다. 여기서는 설치 없이 두 매핑과 값의 변화만 추적한다.

중간 과정을 따라가는 예제

4 KiB 페이지에서 부모 P와 자식 Q의 VPN 1이 PFN 7을 COW로 공유하고 오프셋 564의 값은 10이다. 자식이 그 위치에 20을 쓰려 하여 OS가 PFN 9에 복사하는 종이 모델을 추적하라.

  1. 처음 두 가상 주소 0x1234는 PA 0x7234를 가리키며 둘 다 값 10을 읽는다. 공유 프레임 7의 참조 수는 2라고 정한다.

  2. 자식 쓰기는 읽기 전용 매핑 때문에 예외를 만든다. OS는 COW와 원래 쓰기 허용 조건을 확인하고 프레임 9를 할당하여 페이지 내용을 복사한다.

  3. Q의 표를 VPN 1 → PFN 9와 쓰기 허용으로 바꾸고 필요한 번역 동기화를 완료한다. 프레임 7의 참조 수는 1, 프레임 9의 참조 수도 1이다. 프레임 7은 아직 P가 사용하므로 반환하지 않는다.

  4. 다시 시도한 Q 쓰기는 PA 0x9234에 20을 저장한다. P는 PA 0x7234의 10을, Q는 20을 읽는다. 이후 Q가 매핑을 없애면 프레임 9의 참조 수가 0이 되어 반환할 수 있지만 오래된 접근 가능성 제거가 전제다.

공유 읽기 뒤 자식만 독립 복사·쓰기하여 부모는 10, 자식은 20을 얻는다. PFN 7은 부모 참조가 남아 유지한다. 실제 xv6나 하드웨어 실행 결과는 아니다.

종이와 본문으로 직접 해보기

PTE를 PFN 9로 바꿨는데 로컬 TLB에 PFN 7이 남았다. VA 0x1234에 대해 새 표와 오래된 캐시가 내는 주소를 계산하라. 다른 CPU에도 공유 문맥이 있으면 무엇을 확인할지 적어라.

풀이 보기
