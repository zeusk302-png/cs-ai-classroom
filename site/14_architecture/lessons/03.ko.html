소단원 3.1

register·instruction format

같은 32개의 비트가 어떻게 계산할 레지스터와 숫자를 동시에 지정할까?

준비 개념과 학습 목표

준비 개념

  • 비트는 0 또는 1이며, w비트의 부호 없는 값은 0부터 2^w−1이다. 16진수 한 자리는 네 비트를 표시한다. 예를 들어 0xF는 15이다.

  • 레지스터는 ISA가 이름을 부여한 작은 저장 위치다. PC는 현재 명령어의 주소다. ISA는 프로그램이 관찰할 동작을 정하며 파이프라인 구현 방법은 별개다.

  • 12비트 2의 보수 해석은 원시값 r<2048이면 r, 그렇지 않으면 r−4096이다. 마스크는 지정 비트만 남기는 AND 연산이다.

학습 목표

  • RV32I 레지스터 상태와 명령어 필드를 구분한다.

  • ADDI를 인코딩하고 역으로 필드를 추출한다.

  • 즉시값 범위와 산술 결과의 폭을 설명한다.

상태와 이름

RV32I의 XLEN은 32이다. 정수 레지스터 x0부터 x31은 각각 32비트이며 x0를 읽으면 항상 0이다. x0에 계산 결과를 쓰려 해도 저장된 값이 바뀌지 않는다. PC는 별도의 프로그램 카운터다. x1을 반환 주소, x2를 스택 포인터로 쓰는 것은 호출 규약이며 기본 ISA가 이 둘만 특정 계산에 사용할 수 있게 강제하는 것은 아니다.

기계 상태를 레지스터 값, PC, 접근 가능한 메모리로 나누면 명령어는 이 상태의 전이 규칙이 된다. 동일 ISA를 실행하는 서로 다른 CPU는 캐시와 실행 시간을 달리할 수 있다. 따라서 상태 전이를 추적하는 활동은 실제 칩의 성능 시험과 구별된다.

32비트를 나누는 규칙

기본 명령어는 32비트다. ADDI의 I형 필드는 [31:20] 즉시값 12비트, [19:15] rs1, [14:12] funct3, [11:7] rd, [6:0] opcode이다. ADDI는 funct3=000, opcode=0010011을 쓴다. rd와 rs1의 다섯 비트는 각각 32개의 번호를 표현한다. 다른 명령어 형식에서도 같은 레지스터 필드의 위치를 유지하면 디코더 연결이 단순해진다.

즉시값은 명령어 안에 직접 들어 있는 상수다. ADDI의 12비트 상수는 부호 확장하므로 허용 정수는 −2048부터 2047이다. 비트 패턴 0xFFD는 부호 없는 수로 4093이지만 12비트 부호 있는 즉시값으로는 −3이다. 같은 비트도 해석의 폭과 규칙을 먼저 정해야 한다.

계산과 비트 포장의 분리

ADDI rd,rs1,imm는 rs1의 값과 부호 확장한 imm를 더해 낮은 32비트를 rd에 쓴다. 이 연산은 수학적 합이 범위를 넘더라도 정수 산술 예외를 발생시키지 않는다. 예를 들어 0xFFFFFFFF에 1을 더하면 결과 비트는 0이다. 이는 C 언어의 부호 있는 정수 overflow 계약을 설명하는 규칙이 아니다.

허용 필드를 각각 왼쪽으로 이동한 뒤 OR 하면 명령어 단어를 만든다. 여기서는 ((imm & 0xFFF)<<20)|(rs1<<15)|(rd<<7)|0x13이다. 필드가 서로 겹치지 않고 범위 검사가 먼저 이루어지면 역방향 마스크가 원래 필드를 복원한다. 잘못된 레지스터 번호를 그대로 OR 하는 방식은 다른 필드를 오염시킬 수 있다.

중간 과정을 따라가는 예제

RV32I에서 ADDI x5,x6,−3의 명령어 단어를 구한다. x6=10이고 현재 PC=0x100이며 정상적인 명령어 인출이 가능하다고 가정한다.

  1. −3의 12비트 표현은 −3 mod 4096=4093=0xFFD이다. rs1=6, rd=5이며 ADDI의 funct3는 0이다.

  2. 즉시값 기여는 0xFFD00000, rs1 기여는 6×2^15=0x00030000, rd 기여는 5×2^7=0x00000280이다.

  3. opcode 0x13을 OR 하면 0xFFD30293이다. 역추출하면 rd=5, rs1=6, 즉시값의 원시값=4093이며 부호 해석은 −3이다.

  4. 상태 전이는 x5=(10−3) mod 2^32=7, 다음 PC=0x104이다. 다른 정수 레지스터는 그대로다.

명령어 단어는 0xFFD30293이다. 이 단어의 메모리 바이트 순서는 시스템의 endian 규칙을 추가로 정해야 한다.

종이와 본문으로 직접 해보기

종이에 다섯 비트 레지스터 번호와 12비트 즉시값 범위를 적고, ADDI x31,x0,2047과 ADDI x32,x0,2048을 직접 한 명령어로 표현할 수 있는지 판단하라.

힌트 보기

번호와 즉시값의 범위를 각각 검사한다. 큰 상수를 여러 명령어로 만드는 가능성과 한 ADDI에 넣는 가능성은 다르다.

풀이 보기

x31=11111이며 2047=0x7FF이므로 첫 명령어는 허용된다. x32는 다섯 비트 번호 범위를 넘고 2048도 부호 있는 12비트 범위를 넘으므로 두 번째는 이 ADDI 형식으로 표현할 수 없다.

오해와 반례

32비트 명령어이므로 즉시값도 32비트다.

레지스터 번호와 opcode도 같은 32비트를 차지한다. ADDI는 그중 12비트만 상수에 사용하므로 2048을 그대로 넣을 수 없다. 큰 상수를 만드는 별도 명령어 조합은 가능하지만 한 명령어의 즉시값 범위는 바뀌지 않는다.

RV32I ADDI는 합의 낮은 XLEN 비트를 쓰도록 정한다.

한 단계 더

필드 복원 증명: 허용 rs1,rd는 0≤값<32이고 imm의 원시값은 0≤값<4096이다. 각 이동된 값은 서로 다른 비트 집합에만 1을 세운다. 따라서 W>>15 &31은 rs1을, W>>7 &31은 rd를, W>>20 &4095는 imm 원시값을 정확히 복원한다. 마지막 값을 12비트 2의 보수로 해석하면 입력 imm가 돌아온다. 실제 Python 모형은 rd=5, rs1=6에 대해 4096개 허용 즉시값을 전부 확인했다. 다른 opcode나 불법 인코딩의 전체 디코더 검증은 하지 않았다.

소단원 3.2

load/store와 주소지정

주소 1을 더하면 다음 숫자로 갈까, 다음 바이트로 갈까?

준비 개념과 학습 목표

준비 개념

  • 바이트는 8비트이며 byte-addressed 메모리에서는 인접 주소가 다음 바이트를 가리킨다. 32비트 값 하나는 네 바이트를 차지한다.

  • 부호 확장은 작은 부호 있는 수의 값을 유지하며 폭을 늘리고, 0 확장은 작은 부호 없는 수의 값을 유지한다. 낮은 비트는 나머지 mod 2^w와 같다.

  • 정렬은 주소가 접근 크기의 배수인 조건이다. 실행 환경 EEI는 어떤 주소가 읽기 가능한지와 misaligned 접근 처리 등을 정한다.

학습 목표

  • base+offset의 바이트 주소를 계산한다.

  • load의 확장과 store의 낮은 비트 선택을 구분한다.

  • 정렬·endian·접근 가능성을 별도 조건으로 검사한다.

계산할 값과 저장할 위치

RV32I는 load/store ISA이다. 정수 계산 명령어는 레지스터의 값을 사용하고, 일반 메모리와 레지스터 사이의 값 이동은 load와 store가 담당한다. LW rd,imm(rs1)는 주소 rs1+부호 확장한 12비트 imm에서 32비트를 읽는다. SW rs2,imm(rs1)는 rs2의 낮은 32비트를 같은 주소 규칙으로 저장한다. 주소 덧셈은 XLEN 폭의 비트 연산이다.

주소지정의 offset 단위는 바이트다. 네 바이트 원소 배열의 i번째 원소 주소는 base+4i이다. i=3이라고 주소에 3만 더하면 원소 단위와 바이트 단위를 혼동한다. 수학적으로 계산한 주소가 존재하더라도 실제 프로그램의 메모리 매핑과 권한이 허용하는지는 별도 문제다.

endian과 확장

여기서는 읽기 가능한 일반 메모리에 little-endian을 가정한다. 낮은 주소의 바이트가 값의 낮은 비트를 담는다. 0x1000부터 FE FF FF FF가 있으면 LW로 얻은 비트는 0xFFFFFFFE이다. 이 32비트를 부호 있는 수로 해석하면 −2이다. ISA의 실행 환경은 endian을 정하므로 이 예제를 모든 RISC-V 시스템의 유일한 byte order라고 주장하지 않는다.

LB는 한 바이트를 부호 확장하고 LBU는 0 확장한다. 같은 FE를 읽으면 LB의 결과 비트는 0xFFFFFFFE이고 LBU는 0x000000FE이다. LH/LHU도 16비트에서 같은 차이가 난다. SB는 소스 레지스터의 낮은 8비트만 저장한다. store는 그 자체로 소스 레지스터의 부호를 메모리에 표시하지 않는다.

접근 계약의 경계

0x1000은 4의 배수이므로 LW에 자연 정렬된다. 자연 정렬된 접근은 instruction-set 규칙의 misaligned 예외를 일으키지 않지만, 없는 주소나 권한 위반 같은 접근 실패는 여전히 가능하다. 0x1001에서 LW를 하면 misaligned 접근이며 EEI에 따라 처리되거나 예외가 날 수 있다. 처리되더라도 빠르거나 원자적이라고 자동 보장되지 않는다.

목적지가 x0인 load도 메모리를 실제로 접근한다. 읽기 예외나 장치 부수 효과가 존재할 수 있으므로 버리는 값이라는 이유로 접근 계약을 생략하면 안 된다. 이 단원의 주소들은 종이 메모리 표의 가상 주소이며, 운영체제의 가상 메모리 번역이나 실제 장치 레지스터 읽기를 수행한 증거가 아니다.

중간 과정을 따라가는 예제

읽기 가능한 little-endian 일반 메모리의 주소 0x1000~0x1003에 FE FF FF FF가 있다. x10=0x1000일 때 LW x5,0(x10), LB x6,0(x10), LBU x7,0(x10)의 값을 구한다.

  1. 유효 주소는 세 접근 모두 0x1000+0=0x1000이다. LW 주소는 4바이트 자연 정렬이고 LB/LBU는 1바이트 접근이다.

  2. LW 원시값은 0xFE+0xFF×256+0xFF×256²+0xFF×256³=0xFFFFFFFE이다.

  3. LB는 FE의 부호 비트 1을 위쪽으로 복제하여 0xFFFFFFFE를 만든다. LBU는 위쪽을 0으로 채워 0x000000FE를 만든다.

  4. x5와 x6의 비트는 같고, 부호 있는 해석은 −2이다. x7의 값은 254이다. 모두 읽기만 하므로 메모리 바이트는 바뀌지 않는다.

같은 주소를 읽어도 접근 폭과 확장 규칙에 따라 결과가 달라진다.

종이와 본문으로 직접 해보기

네 바이트 원소 배열의 base=0x2000이다. 인덱스 3 원소를 읽는 LW의 offset을 구하고, SB가 0x123456AB를 저장하면 그 주소에 남는 한 바이트를 구하라. 접근은 모두 허용된다고 가정한다.

힌트 보기

원소 크기를 바이트로 곱한다. SB는 낮은 여덟 비트만 선택한다.

풀이 보기

offset=3×4=12이고 주소는 0x200C이다. 12는 부호 있는 12비트 범위에 들어간다. SB의 저장 바이트는 AB이며 나머지 상위 24비트는 이 store로 저장되지 않는다.

오해와 반례

정렬된 주소면 메모리 접근은 반드시 성공한다.

정렬은 조건 하나일 뿐이다. 자연 정렬된 0x2000이라도 매핑이나 읽기 권한이 없으면 접근 실패할 수 있다. 반대로 misaligned 접근의 결과도 모든 실행 환경에서 동일하지 않다.

소단원 3.3

분기·조건과 즉시값

같은 0xFFFFFFFF가 분기 조건에서는 왜 −1이기도 하고 큰 양수이기도 할까?

준비 개념과 학습 목표

준비 개념

  • 조건 분기는 비교 결과에 따라 다음 PC를 선택한다. 현재 명령어 주소 PC와 보통의 다음 명령어 주소 PC+4를 구분한다.

  • 32비트 2의 보수에서는 0xFFFFFFFF가 −1이고, 부호 없는 해석에서는 4294967295다. 같은 비트를 서로 다른 순서 관계로 비교할 수 있다.

  • 2의 배수와 4의 배수는 다르다. 분기 offset의 표현 단위와 명령어 인출 정렬 조건도 다른 제한이다.

학습 목표

  • signed/unsigned 분기를 선택한다.

  • 현재 PC 기준 분기 주소와 즉시값 범위를 계산한다.

  • 표현 가능한 offset과 정렬된 목표를 구분한다.

비교의 계약

BEQ와 BNE는 두 레지스터의 비트 값이 같은지 다른지를 검사한다. BLT/BGE는 부호 있는 비교를, BLTU/BGEU는 부호 없는 비교를 한다. 비교하는 비트 폭은 RV32I에서 32다. 분기는 레지스터의 값을 바꾸는 계산 명령어가 아니라 다음 제어 위치를 정하는 명령어다.

0xFFFFFFFF와 1을 비교하면 BLT는 −1<1이므로 참이지만 BLTU는 4294967295<1이므로 거짓이다. 데이터가 음수를 허용하는지, 주소나 길이처럼 부호 없는 계약을 쓰는지에 따라 선택해야 한다. 레지스터에 signed라는 표지가 따로 붙어 있는 것은 아니다.

현재 PC를 기준으로

B형 즉시값은 부호 있는 2바이트 배수 offset이다. 실제 범위는 −4096부터 4094까지의 짝수다. 분기가 성립하면 목표는 분기 명령어 자신의 PC+offset이며, 성립하지 않으면 PC+4이다. PC+4에 offset을 더하면 잘못된 주소를 얻는다.

즉시값 비트는 연속된 한 덩어리가 아니다. imm[12]는 명령어 bit31, imm[10:5]는 bits30:25, imm[4:1]는 bits11:8, imm[11]은 bit7에 있고 imm[0]=0이다. 이 배치는 하드웨어 비용을 고려한 ISA 설계다. 어셈블러가 이러한 비트 재배치를 해도 offset 의미는 바뀌지 않는다.

표현과 인출 정렬

기본 RV32I는 IALIGN=32, 즉 명령어 주소가 4바이트 경계에 있어야 한다. offset 2는 표현 가능하지만 현재 PC가 4의 배수라면 목표가 4의 배수가 아니다. 그런 분기가 실제로 성립하면 instruction-address-misaligned 예외가 난다. 조건이 거짓인 분기는 그 목표 정렬 때문에 예외를 내지 않는다.

C 확장 등으로 IALIGN=16인 환경에서는 2바이트 경계를 허용한다. 이때 위 정렬 문제는 없어지지만 목표 주소의 인출 권한이나 명령어 유효성까지 보장되는 것은 아니다. 또한 JALR의 12비트 즉시값은 B형과 달리 2배 단위가 아니며, 계산한 목표의 bit0을 0으로 만드는 별도 규칙을 쓴다.

중간 과정을 따라가는 예제

기본 RV32I, 현재 PC=0x100, x5=0xFFFFFFFF, x6=1이다. offset=−8인 BLT와 BLTU를 각각 독립 상태에서 비교한다.

  1. 부호 있는 x5는 −1이고 x6는 1이다. BLT의 조건 −1<1은 참이다.

  2. 목표는 현재 PC 0x100에 −8을 더한 0xF8이다. PC+4−8=0xFC를 쓰면 기준을 잘못 잡은 것이다.

  3. 0xF8은 4의 배수이고 −8은 B형 범위의 짝수이므로 정렬 및 표현 조건을 만족한다. 인출 가능한 목표라는 추가 가정을 둔다.

  4. BLTU에서는 4294967295<1이 거짓이므로 다음 PC는 0x104이다. 두 경우 모두 x5,x6의 값은 변하지 않는다.

BLT는 0xF8로, BLTU는 0x104로 진행한다.

소단원 3.4

RISC 설계의 tradeoff

명령어 수가 줄거나 코드가 작아지면 프로그램도 반드시 빨라질까?

준비 개념과 학습 목표

준비 개념

  • ISA는 명령어의 의미와 인코딩을 정하고 마이크로아키텍처는 이를 실행하는 회로 구조다. RISC라는 이름만으로 한 사이클 실행을 보장하지 않는다.

  • 동적 명령어 수 N은 실제 실행한 개수이고 코드 크기는 저장된 바이트 수다. 반복문에서는 두 값의 관계가 특히 다르다.

  • N>0인 실행에서 평균 CPI는 실행 사이클 수/N이다. 고정 양의 주파수 f에서 시간 T=N×CPI/f이고 1 GHz는 초당 10^9 사이클이다.

학습 목표

  • 인코딩·레지스터·메모리 이동 사이의 설계 절충을 설명한다.

  • 코드 밀도와 실행 시간의 가상 모형을 각각 계산한다.

  • 측정 조건 없이 ISA 성능 순위를 단정하지 않는다.

규칙을 단순하게 만드는 비용

고정 필드와 load/store 분리는 디코딩과 데이터 경로를 규칙적으로 만들 수 있다. 반면 값이 메모리에 있다면 먼저 load하고 계산한 다음 필요한 store를 수행해야 하므로 명령어 수가 늘 수 있다. 레지스터가 부족하면 값을 메모리에 잠시 저장하는 spill도 필요하다. 단순한 개별 명령어와 전체 프로그램의 적은 작업량은 같은 목표가 아니다.

32개의 레지스터 번호에는 다섯 비트가 필요하다. 한 명령어에서 세 레지스터를 명시하면 그것만으로 15비트를 사용한다. opcode와 연산 선택 비트까지 넣으면 즉시값 공간이 줄어든다. RV32I의 12비트 즉시값과 20비트 상위 상수 형식 분리는 이 같은 제약 안에서 선택한 설계다.

코드 밀도는 별도 축

C 확장은 자주 쓰이는 일부 연산을 16비트로 표현한다. 작은 상수와 특정 레지스터 조합 등 조건이 있어 모든 32비트 명령어를 절반 길이로 바꿀 수는 없다. 16비트와 32비트를 혼합하므로 고정 32비트만 처리할 때와 인출·디코딩 조건도 달라진다. C 확장은 기본 ISA 없이 독립적인 전체 ISA로 사용하는 확장이 아니다.

가상 코드 밀도 비교에서 열 개 명령어가 모두 4바이트면 40바이트다. 같은 의미의 열 개 중 여섯 개가 2바이트, 네 개가 4바이트로 표현 가능하다고 가정하면 28바이트다. 감소율은 (40−28)/40=30%다. 이 수치는 지정한 목록의 계산이며 임의의 실제 프로그램에 대한 압축률 측정이나 속도 향상 증거가 아니다.

시간에는 세 변수가 들어간다

별개의 가상 성능 비교에서는 같은 일을 하는 실행 계획 A가 N=10,CPI=1이고 계획 B가 N=8,CPI=2라고 정한다. 두 계획의 주파수가 1 GHz로 같으면 A는 10 ns, B는 16 ns다. B의 명령어 수가 적더라도 더 오래 걸린다. 앞의 코드 밀도 목록과 이 실행 계획은 서로 다른 가상 비교이며 B라는 표기가 같은 실제 프로그램을 뜻하지 않는다.

실제 판단에는 입력, 컴파일러와 옵션, ISA 확장, CPU, 캐시 상태, 메모리 지연, 전력 또는 비용 목표를 명시해야 한다. 여기서 계산한 CPI는 관측한 하드웨어 값이 아니라 가정이다. Python으로 곱셈을 실행해도 CPU의 실제 CPI나 ISA의 실시간 성능을 인증한 것이 아니다.

중간 과정을 따라가는 예제

동일 의미의 코드 밀도 목록은 4바이트 명령어 10개에서 2바이트 6개와 4바이트 4개로 바뀐다. 별도 성능 모형 A=(10개,1 CPI), B=(8개,2 CPI), f=1 GHz의 크기와 시간을 계산한다.

  1. 원래 코드 크기는 10×4=40바이트이고 혼합 크기는 6×2+4×4=28바이트다.

  2. 절약량은 12바이트이며 감소율은 12/40=0.3, 즉 30%다. 이 목록의 명령어 개수는 여전히 10개다.

  3. 별도 성능 계획 A의 사이클은 10×1=10, B는 8×2=16이다. 코드 크기 예제의 정적 목록과 구별한다.

  4. 1 GHz에서 한 사이클은 1 ns이므로 A=10 ns, B=16 ns다. B가 A보다 6 ns 느리다.

가상 목록에서는 코드가 30% 작아졌고, 별도 실행 모형에서는 명령어가 적은 B가 60% 더 오래 걸렸다.

종이와 본문으로 직접 해보기

앞의 성능 계획 A는 1 GHz를 유지하고 B만 2 GHz로 실행한다고 가정하라. 어느 계획이 빠른가? 이 결과가 작은 코드의 속도 증명인지도 판단하라.

힌트 보기

주파수가 다르면 사이클 수만 비교하지 말고 각각 f로 나눈다.

풀이 보기

A는 10/10^9초=10 ns이고 B는 16/(2×10^9)초=8 ns라 B가 빠르다. 주어진 N,CPI,f 조건의 결과이며 작은 코드 때문이라고 원인을 결론 낼 수 없다.

오해와 반례

RISC는 명령어가 단순하므로 어떤 CPU와 입력에서도 더 빠르다.

시간은 N,CPI,f에 함께 의존한다. 동일 주파수의 가상 A=10사이클, B=16사이클은 명령어 수만으로 속도를 결정할 수 없음을 보인다. ISA 명칭만으로 각 항의 값을 알 수 없다.

자기점검

10개 중 4개만 2바이트로 바꾸고 나머지는 4바이트면 크기는?

답과 이유 보기

32바이트

4×2+6×4=32이다. 모두 반으로 줄어든다고 가정하면 안 된다.

N=100,CPI=2,f=2 GHz의 가상 시간은?

답과 이유 보기

100 ns

200사이클/(2×10^9사이클/초)=10^−7초다.

C 확장은 모든 명령어를 16비트로 만드는가?

답과 이유 보기

아니다.

선택된 자주 쓰이는 형식에 조건부로 적용하고 기본 ISA의 32비트 명령어와 혼합한다.

한 단계 더

시간 비교의 필요충분조건: 두 실행이 같은 일을 하고 양의 명령어 수 N, 고정 양의 주파수와 양의 평균 CPI로 표현된다는 모형에서 B가 빠를 조건은 NB×CPIB/fB<NA×CPIA/fA이다. fA=fB이면 정확한 조건은 CPIB/CPIA<NA/NB이다. 예를 들어 NB=(1−p)NA(0≤p<1), CPIB=(1+q)CPIA(q≥0)라면 (1−p)(1+q)<1, 즉 q<p/(1−p)이어야 한다. 따라서 감소율 p와 증가율 q를 그대로 비교하면 일반적으로 정확하지 않다. 더 많은 레지스터는 spill을 줄일 수 있지만 번호 비트와 회로 비용을 늘릴 수 있어 이 부등식의 항들이 어떻게 바뀌는지는 별도 평가가 필요하다. 명세의 설계 근거는 특정 CPU 측정 결과를 대신하지 않는다.
