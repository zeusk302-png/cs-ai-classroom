소단원 6.1

상태기반 제어

같은 ADD 명령인데 어떤 순간에는 읽고 다른 순간에는 쓰는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 상태는 지금 수행할 단계의 기억이다.

  • datapath는 계산· 저장 경로, control은 선택· 쓰기 허용을 정하는 장치다.

  • 여기서는 한 상태가 한 사이클이고 사이클 끝 경계에서 저장한다.

학습 목표

  • 명령 종류와 현재 상태를 함께 사용해 다음 상태를 정한다.

  • 임시 레지스터와 실제 명령 결과 저장을 구별한다.

메모리가 기다리라고 할 때 명령을 여러 번 실행해도 될까?

본문의 F/D/E/W 상태 구분을 대기 가능한 자체 메모리 모형으로 확장한다. 요청 신호 req와 수락 가능 신호 ready가 모두 1인 경계에서만 요청 하나가 처리된다고 정한다. 기다리는 동안 req=1을 유지하더라도 ready=0이면 처리는 없다. 주소와 쓰기 자료는 기다리는 동안 그대로 유지한다.

자체 STORE의 메모리 상태 S에 세 번 머무르고 ready가 0, 0, 1로 관찰되면 세 번째 경계에서 한 번 쓰고 S를 떠난다. 이는 매 경계 무조건 쓰는 장치에서 쓰기 허용을 세 번 켜는 것과 다른 규칙이다. 일반 RAM에 같은 값을 세 번 쓰면 최종 값이 같을 수 있지만, 요청 횟수가 늘어도 모든 장치의 동작이 같다는 결론은 낼 수 없다.

여기서는 처리된 요청마다 카운터가 1 늘어나는 자체 장치를 비교 대상으로 둔다. 올바른 세 경계의 수락 횟수는 1이다. 모든 경계에서 쓰기를 실행하는 오류 모형은 3이다. req/ready는 이 연습을 위해 정의한 규약이며 실제 버스나 장치를 구동한 결과가 아니다.

먼저 확인할 개념
  • 상태와 쓰기 허용

    각 상태의 동작과 다음 상태로 이동하는 조건을 구별한다.

  • STORE의 메모리 단계

    쓰기 요청과 명령 완료가 발생하는 경계를 확인한다.

단계 번호를 기억하는 제어기

다중사이클은 명령 하나를 여러 시간 조각으로 실행한다. ADD도 fetch에서는 명령을 읽고 execute에서는 값을 더하며 writeback에서는 목적 레지스터에 쓴다. opcode만 보고 매 순간 RegWrite를 켜면 중간 값이 결과처럼 저장될 수 있다.

FSM은 현재 상태를 state register에 보관하고 전이 함수로 다음 상태를 만든다. 본 자체 모형은 F 인출, D 해독, E 계산, W 결과 저장이다. D에서 opcode에 따라 ALU 경로 또는 메모리 경로로 갈라지고 완료 뒤 F로 돌아간다.

같은 자원을 시간으로 나누기

한 ALU를 F의 PC 증가와 E의 데이터 덧셈에 재사용할 수 있다. 두 일은 서로 다른 사이클이므로 같은 순간 ALU에 서로 다른 두 연산을 요구하지 않는다. 이 때문에 자원을 줄이려는 설계와 사이클 수의 증가를 함께 본다.

IR은 읽은 명령을 유지하고 A/B는 읽은 피연산자, ALUOut은 계산 결과, MDR은 읽은 데이터를 다음 단계에 넘긴다. 임시 저장은 단계를 잇는 다리다. 여기서는 기억장치가 각 접근 사이클 안에 응답하고 추가 대기· 예외가 없는 조건이다.

출력과 전이의 안전 조건

본 F/D/E/W에서 RegWrite는 W에만 1이다. 나머지 상태에서는 0으로 두어 목적 레지스터를 보존한다. mux는 둘 중 하나의 입력을 고르는 장치로 현재 단계가 쓰는 값만 올바르게 연결해야 한다.

기억장치가 늦게 응답하는 실제 시스템이라면 ready 조건에 따른 대기 상태가 필요하다. 상태 번호는 주소나 프로그램 명령 번호와 같지 않다. 아래 종이 전이는 CPU 회로를 합성하거나 실행한 결과가 아니다.

중간 과정을 따라가는 예제

자체 ADD 모형 F →D →E →W →F, 초기 상태 F, 각 상태 RegWrite는 F/D/E =0,W =1이다. 한 ADD 완료까지 상태와 쓰기 횟수를 세라.

  1. 첫 사이클 F에서 명령을 IR에 보관한다. 목적 레지스터 쓰기는 0회다.

  2. 둘째 D에서 A/B를 읽고 ADD 경로 E를 선택한다.

  3. 셋째 E에서 ALUOut =A +B를 보관하고 W로 간다.

  4. 넷째 W에서 목적 레지스터에 ALUOut을 한 번 쓰고 다음 상태 F다.

4 사이클· 목적 레지스터 쓰기 1회다. IR/A/B/ALUOut 저장은 별도의 임시 저장이다.

소단원 6.2

명령별 micro-operation

LOAD와 STORE가 주소 계산 뒤 서로 다른 일을 하는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • micro-operation은 한 단계에서 수행하는 작은 이동· 계산이다.

  • X ←Y는 사이클 경계에서 X에 Y를 저장한다는 표기다.

  • 본 모형은 byte 주소·4byte 명령·ALU 임시 결과와 한 사이클 메모리 응답을 사용한다.

학습 목표

  • LOAD/STORE/ADD의 단계별 값과 목적지를 추적한다.

  • 주소· 데이터· 즉시값의 단위를 구별한다.

같은 경계에 MDR을 채우고 그 값을 쓸 수 있을까?

자체 LOAD는 메모리 단계 M의 끝에서 MDR을 채우고 다음 W의 끝에서 목적 레지스터를 쓴다. 모든 저장소는 해당 경계 직전의 입력을 읽어 동시에 다음 상태를 저장한다고 정한다. 따라서 M에서 MDR←77과 R2←MDR을 함께 켜면 R2는 새 77이 아니라 이전 MDR을 받는다.

주소 ALUOut=192, M[192]=77, 이전 MDR=55, 이전 R2=9라고 하자. 정상 M 뒤 MDR=77, R2=9이고 정상 W 뒤 R2=77이다. 잘못 합친 경계는 MDR=77, R2=55다. 메모리 출력에서 R2로 직접 연결하는 별도 우회 경로가 없는 모형이므로 두 쓰기를 합칠 수 없다.

메모리의 실제 응답 시간과 setup 조건까지 바꾸어 직접 경로를 설계하는 것은 별도 구현이다. 이 단원에서는 기존 MDR 경로와 경계 규칙을 유지한다. 원문의 다른 교육용 ISA에서 사용하는 PC 증가 단위도 이 연습의 바이트 주소 PC+4와 구별한다.

공통 인출과 해독

자체 모형 F에서는 IR ←Mem[PC], PC ←PC +4를 수행한다. 두 오른쪽 식은 F 시작의 PC를 사용한다. 따라서 PC가 100이면 IR은 100 주소의 명령이고 사이클 끝 PC는 104다.

D에서는 A ←R[rs],B ←R[rt]로 피연산자를 읽는다. LOAD의 rt는 목적지라 읽은 B가 쓰이지 않을 수 있다. 단순한 읽기를 무조건 결과 쓰기로 해석하지 않는다. 명령 형식과 데이터 경로를 먼저 정한다.

주소 계산 뒤 읽기와 쓰기

LOAD와 STORE의 주소 단계 EA는 ALUOut ←A +signext(imm)이다. 여기서는 imm이 byte 오프셋이므로 이를 임의로 4 배 하지 않는다. 다음 메모리 단계에서 LOAD는 MDR ←Mem[ALUOut], STORE는 Mem[ALUOut]←B다.

LOAD는 마지막 W에서 R[rt]←MDR를 수행하고 STORE는 메모리 쓰기 뒤 끝난다. ADD는 E에서 ALUOut ←A +B, W에서 R[rd]←ALUOut이다. 같은 저장 상자를 쓰더라도 주소 결과와 산술 결과의 역할이 다르다.

동시 대입의 시간 약속

A/B,ALUOut,MDR의 새 값은 해당 단계가 끝난 다음 단계에서 사용할 수 있다. 여기서는 메모리 읽기와 레지스터 쓰기를 별도 단계로 정했으므로 MDR에 새로 읽는 순간 이전 MDR을 결과처럼 사용하지 않는다.

연산 결과 범위· 정렬· 주소 접근이 모두 유효하고 예외가 없다는 조건을 둔다. 실제 ISA는 부호 확장 폭, 명령 길이, 분기 규칙이 다를 수 있다. Toronto의 원래 PC +1 모형과 본 PC +4 모형을 섞지 않는다.

소단원 6.3

제어 ROM과 microcode 입문

제어 신호 묶음을 메모리에 저장하면 프로그램 명령과 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • ROM은 주소로 저장된 비트 묶음을 읽는 기억장치다.

  • control word는 한 단계의 제어 신호 묶음이다.

  • micro-PC는 제어 단계 주소이고 일반 PC는 프로그램 명령 주소다.

학습 목표

  • 주소· 신호· 다음 주소 필드를 가진 작은 제어 표를 읽는다.

  • 제어표 수정 가능성과 일반 메모리를 구별한다.

제어 신호가 모두 합법이면 microcode도 끝날까?

본문의 자체 ROM은 8행이며 한 행에 제어 5비트와 고정 다음 행 3비트를 저장한다. 합계 64비트다. 각 행에서 메모리 읽기·쓰기를 동시에 켜지 않는 것과 명령의 제어 순환이 정상 종료하는 것은 별개의 검토 항목이다.

자체 명령의 행 0은 fetch, 1은 준비, 2는 계산, 3은 쓰기 완료라고 정한다. 올바른 다음 행은 0→1→2→3→0이다. 오류 ROM에서 행 2의 다음 행을 1로 바꾸면 0→1→2→1→2…가 된다. 각 행의 제어가 합법이어도 완료 행 3에 도달하지 못한다.

같은 행에서 조건에 따라 두 주소로 갈 수 있도록 새 형식을 정의해 보자. 제어 5비트, 조건 사용 1비트, 기본 주소 3비트, 대체 주소 3비트를 직접 저장하면 행당 12비트, 8행에 96비트다. 조건 입력을 만드는 회로와 목적 레지스터는 이 ROM 저장량에 포함하지 않는다. 이는 실제 CPU microcode 형식이 아닌 자체 확장이다.

  • 상태 이동과 완료

FSM을 제어 단어로 표현하기

제어 ROM의 한 행은 어떤 입력을 선택하고 어떤 레지스터를 쓸지 담는다. state 주소에서 읽은 제어 단어가 datapath를 움직이고 sequencer가 다음 제어 주소를 정한다. sequencer는 주소 순서를 고르는 장치다.

단순히 다음 행으로 증가할 수도 있고 opcode나 조건으로 다른 행에 dispatch할 수도 있다. dispatch는 명령 종류에 맞는 시작 주소를 고르는 분기다. 명령 하나에 여러 microinstruction이 대응할 수 있다.

서로 다른 두 PC

일반 PC는 사용자가 실행하는 명령 주소다. micro-PC는 그 명령을 구현하는 제어 단계 주소다. LOAD의 M과 W 사이에서 micro-PC가 바뀌어도 일반 PC가 다시 다음 명령으로 증가해야 하는 것은 아니다.

제어 ROM은 일반 프로그램의 LOAD가 읽는 데이터 메모리와 개념상 구별된다. microcode가 있다는 설명만으로 모든 CPU가 같은 구현이거나 사용자가 임의로 수정할 수 있다는 결론은 없다. ROM 고정· 쓰기 가능한 제어 저장 등 구현 방식이 다르다.

비트 수와 금지 조합

본 종이 모형은 8 행 ×8bit 제어 저장소를 사용한다. 각 행은 5개의 제어비트와 3bit의 고정 다음 주소다. 총 64bit이며 row 주소에는 3bit가 필요하다. 조건부 dispatch까지 담으려면 추가 필드나 별도 논리가 필요하다.

예를 들어 같은 메모리 포트에 read와 write를 동시에 켜면 이 모형에서는 금지다. 저장 표라고 해서 내용이 자동으로 올바르지 않다. 부적절한 쓰기· 자원 충돌· 도달하지 못하는 주소를 제어 명세와 비교해야 한다.

소단원 6.4

다중사이클 성능 비교

CPI가 작으면 반드시 실행 시간도 짧을까?

준비 개념과 학습 목표

준비 개념

  • CPI는 총 사이클 수/ 완료 명령 수다.

  • 시간 =명령 수 × 평균 CPI× 사이클 시간이다.

  • 본 모형은 순차 실행· 대기 없음· 같은 명령 수/ 비율을 비교한다.

학습 목표

  • 명령 혼합의 가중평균 CPI를 계산한다.

  • 사이클 시간과 실제 측정의 차이를 설명한다.

클록을 줄여도 대기가 늘면 빨라질까?

본문의 자체 100명령 혼합은 기본 400사이클이며 주기 2ns이면 800ns다. 같은 명령 수와 동일한 결과를 전제로, 주기를 1.8ns로 줄이는 새 설계가 메모리 대기 100사이클을 추가한다고 하자. 총 500사이클이므로 시간은 900ns다.

주기만 비교하면 10% 줄었지만 시간은 12.5% 늘었다. 빨라지려면 (400+w)×1.8<400×2여야 한다. w<400/9≈44.44이므로 정수 대기 추가가 44사이클 이하여야 한다. 이 비교는 자체 고정 주기·고정 기본 혼합의 계산이며 실제 프로세서 성능 측정이 아니다.

평균 CPI도 긴 개별 요청을 숨길 수 있다. 기본 경로가 동일한 20개의 LOAD에서 추가 대기를 두 명령에 각각 10사이클 주는 경우와 한 명령에 20사이클 주는 경우는 총 추가 대기 20으로 같다. 전체 시간은 같지만 가장 긴 LOAD는 각각 기본 5+10=15와 5+20=25사이클이다. 전체 처리 시간과 개별 명령 최대 지연을 나눈다.

먼저 확인할 개념
  • 혼합 CPI와 실행 시간

    명령 수·총 사이클·주기의 곱으로 비교한다.

  • LOAD 단계와 대기 추가

    기본 단계 수와 메모리 대기를 따로 센다.

각 명령의 사이클을 세기

한 상태가 한 사이클인 모형에서 LOAD5,STORE4,ALU4,BRANCH3을 사용한다. 단순히 네 숫자를 동일 가중평균하면 명령의 실제 빈도를 무시한다. 각 종류의 명령 수에 사이클을 곱한 뒤 총 명령 수로 나눈다.

명령 혼합은 실행한 동적 명령의 비율이다. 코드에 적힌 명령문 개수와 반복 실행 횟수는 다르다. 같은 프로그램이어도 입력· 분기 방향에 따라 비율이 변할 수 있어 조건을 남긴다.

짧은 시계와 많은 틱

단일 사이클의 CPI1은 긴 조합 경로를 한 사이클에 완료하는 조건이다. 다중사이클은 자원을 나눠 더 짧은 시계를 쓸 수 있지만 명령당 시계 틱이 많아진다. 비교할 값은 CPI만이 아니라 그 곱이다.

같은 명령 수에서는 평균 CPI× 사이클 시간이 평균 명령 시간이다. 속도 비는 기준 실행 시간/ 새 실행 시간으로 정의한다. 1보다 큰 값은 새 모형이 빠름을 뜻하지만 실측 성능이라는 증거는 아니다.

조건 변경을 표에 추가하기

메모리 대기· 캐시· 분기대기· 예외· 운영 체제 간섭이 있으면 이 표 밖의 사이클이 추가될 수 있다. 다중사이클과 여러 명령이 겹치는 파이프라인은 다른 설계이며 이 단원의 순차 모형을 파이프라인 처리량으로 바꾸지 않는다.

다른 ISA가 명령 수 자체를 줄이면 동일 N 가정을 버리고 N도 곱해야 한다. 단위 ns와 ms를 맞춰 보고, 모형 계산과 하드웨어 측정· 학습자 실험을 구분한다. 아래 수치는 모두 자체 가상 값이다.

제어의 안전·경계·진행·시간

req=1이고 ready=0,0,1인 S 상태의 수락 수를 구하라. 이전 MDR=55, 응답=77에서 MDR 쓰기와 R2←MDR을 합친 경계의 결과를 구하라. ROM의 0→1→2→1 경로가 완료 3에 도달하는지 판단하라. 기본 400사이클·2ns를 추가 대기 100·1.8ns와 비교하고 개선 가능한 정수 대기 최대를 구하라.

힌트 1

상태 방문과 실제 수락, 경계 이전과 이후 값을 나눈다.

풀이와 답 확인

  1. 수락은 셋째 경계의 1회다.
