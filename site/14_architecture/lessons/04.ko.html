소단원 4.1

산술·메모리 명령

주소 100에 있는 숫자와 레지스터에 저장된 숫자는 같은 위치에 있을까?

준비 개념과 학습 목표

준비 개념

  • 본 단원은 RV32I, XLEN32, C압축 확장 없음·모든 명령 4바이트를 쓰는 종이 모형이다. x0는 항상 0이다.

  • 레지스터 x1..x31의 32비트 값과 byte주소 메모리는 구별한다. PC는 현재 명령의 주소다.

  • 가상 예제의 메모리는 little-endian·유효한 일반 RAM·자연정렬·예외없음·단일스레드 조건이다. MMIO와 OS주소보호는 별도다.

학습 목표

  • add/addi와 lw/sw의 상태 변화를 구별해 계산한다.

  • 폭·부호확장·byte offset·엔디언과 정렬 조건을 명시한다.

계산과 자료 이동의 역할

add rd,rs1,rs2는 두 레지스터 값을 더해 rd에 쓰고 메모리를 직접 바꾸지 않는다. addi는 두 번째 값 대신 부호확장된 12비트 즉시값을 쓴다. RV32의 결과는 하위 32비트이며 overflow를 자동 산술 예외로 바꾸지 않는다. x0에 결과를 쓰려 해도 x0는 0이다.

레지스터는 기억할 숫자의 작은 작업 공간이고 메모리는 주소로 접근하는 별도 공간이다. 책상/서랍 비유는 분리를 돕지만 실제 레지스터 값이 항상 변수 하나와 1:1 대응하거나 RAM latency가 동일하다는 뜻은 아니다. 고급언어의 변수와 기계 저장 위치는 컴파일러 선택에 따라 달라진다.

주소를 계산하고 그곳을 읽는다

lw rd,k(rs1)는 유효주소 EA=R[rs1]+sign_extend(k)를 구해 32비트 word를 읽는다. sw rs2,k(rs1)는 rs2의 하위 32비트를 그 주소의 4byte에 저장한다. k는 word 개수 아닌 byte 단위다. 주소+4는 다음 32비트 word이며 +1은 다음 byte다.

little-endian에서 word0x12345678의 낮은 주소부터 byte는 78/56/34/12이다. RISC-V 환경은 엔디언을 정하므로 모든 구현이 이 배치를 쓴다고 일반화하지 않는다. 자연정렬 word주소는 4의 배수이고 미정렬 처리/예외는 환경에 따라 다르다. 이 예제는 유효/정렬 접근만 가정한다.

같은 바이트의 부호 해석

LB는 8비트를 부호확장하고 LBU는 0확장한다. 바이트 0xFE에서 LB의 32비트패턴은 0xFFFFFFFE, signed해석−2이며 LBU는 254다. 실제 읽은 byte는 같고 확장 규칙이 다르다. add의 bit결과와 signed/unsigned 해석도 나눠야 한다.

로드 목적지를 x0로 정해 값을 버려도 접근 자체의 예외/부작용까지 사라지는 것은 아니다. 반면 순수 add x0,...의 결과 저장은 버린다. 메모리가 유효하다는 예제 가정을 벗어난 주소를 읽어도 0이 되겠지라고 판단하지 않는다. 실제 어셈블러/CPU실행은 미수행이다.

중간 과정을 따라가는 예제

R[x5]=256, RAM256의 32비트 word=7이다. 순서대로 lw x6,0(x5); addi x7,x6,-3; sw x7,4(x5); add x0,x6,x7을 수행하는 종이 추적에서 레지스터와 word260 및 4byte를 구하라. 초기 PC=0, 각 명령 4byte이고 모든 접근은 성공한다.

  1. PC0의 lw는 EA256+0=256에서 7을 읽어 x6=7,다음 PC4다. x5값 256은 포인터로 유지한다.

  2. PC4의 addi는 즉시값−3을 부호확장해 7−3=4를 x7에 쓴다. 다음 PC8,메모리는 아직 바뀌지 않는다.

  3. PC8의 sw는 EA256+4=260에 word4를 쓴다. little-endian byte260..263은 04/00/00/00,다음 PC12다.

  4. PC12의 add 계산은 7+4=11이지만 rd=x0여서 버린다. x0=0, x6=7,x7=4이고 다음 PC16이다.

x6=7,x7=4,x0=0,word260=4(04/00/00/00),다음 PC16이다. add와 store의 메모리 역할을 구별했다.

종이와 본문으로 직접 해보기

byte300=0xFE일 때 lb x8,0(x9)와 lbu x10,0(x9)를 x9=300에서 각 계산하라. R[x11]=0xFFFFFFFF에 addi x12,x11,1을 적용하면?

힌트 보기

LB의 부호 bit1을 32bit까지 채우고 LBU는 0으로 채운다. ADDI는 하위 32bit를 남긴다.

풀이 보기

x8=0xFFFFFFFE(signed−2),x10=254다. x12=(2³²−1+1)mod2³²=0이다. 실제 오버플로 예외가 발생했다는 주장이 아니며 고급언어 signed산술의 정의와 같다고 추론하지 않는다.

오해와 반례

lw의 offset4는 4번째 word이고 add는 레지스터를 더하면서 원래 메모리도 바꾼다.

offset4는 4byte뒤인 260이다. 예제에서 x7=4를 얻었을 때 word256은 여전히 7이며 sw만 word260을 바꾼다. 주소단위·저장위치·명령의 write집합을 명시해야 한다.

자기점검

답과 이유 보기

아니다.

x0는 항상 0이고 목적지 쓰기 결과를 버린다.

LB와 LBU는 0xFE를 같은 정수로 확장하는가?

답과 이유 보기

아니다.

부호확장−2와 0확장 254의 차이다.

자연정렬이 아닌 lw가 모든 환경에서 항상 성공하는가?

답과 이유 보기

아니다.

미정렬 접근 처리는 실행 환경의 규약에 따른다.

한 단계 더

심화: 길이 n의 32비트 배열 A의 원소 i주소는 base+4i이고 0≤i<n이어야 한다. base256/n3이면 i0/1/2는 256/260/264다. 주소 계산 성공이 그 주소의 권한·유효성까지 증명하지 않는다.0xFFFFFFFF+1의 modulo결과와 C의 signed overflow 의미를 분리해 설명하라. 본 단원에 C실행 증거는 없다.

소단원 4.2

조건문·반복의 변환

반복문의 다음 줄은 항상 코드 바로 아래 줄일까?

준비 개념과 학습 목표

준비 개념

  • RV32I의 일반 명령은 다음 PC를 PC+4로 정한다. 조건 분기가 참이면 표적 주소, 거짓이면 PC+4로 간다. 명령 규약상 delay slot은 없다.

  • BLT/BGE는 signed, BLTU/BGEU는 unsigned 비교다. BEQ/BNE는 비트 값의 동등성을 비교한다.

  • 종이 반복 예제는 0≤n≤1000, 합이 32비트 signed 범위 안, 주소 유효, 예외 없음이라는 조건을 쓴다.

학습 목표

  • 조건부 분기와 무조건 jump로 if/loop 흐름을 구성한다.

  • 경계 검사·불변식·정적/동적 명령수를 구별한다.

조건의 참거짓이 다음 주소를 고른다

if(a<b)의 조건이 참일 때 갈 label과 거짓일 때 계속될 주소를 정한다. blt a,b,L은 signed비교가 참이면 L로 가고 그렇지 않으면 다음 명령이다. then/else배치에 따라 거짓 분기를 먼저 쓸 수도 있으므로 고급언어의 문장 순서를 그대로 CPU순서라고 읽지 않는다.

무조건 분기는 jal x0,L로 쓸 수 있다. 링크값 PC+4는 x0에 버려져 반환 주소를 보존하지 않는다. label은 위치의 이름이고 실제 인코딩은 현재 명령에서 표적까지 byte차이다. 이 단원은 이름/주소를 이미 정해기계어 인코딩을 손으로 만들지는 않는다.

반복은 검사로 돌아가는 경로다

sum=0,i=1에서 i≤n동안 sum+=i;i++를 계산하려면 검사→본문→증가→검사로 돌아간다. 초기 조건이 거짓이면 본문이 한 번도 실행되지 않는 pre-test반복이다. 조건을 본문 뒤에 두면 n=0에서도 한 번 실행될 수 있어 다른 알고리즘이다.

검사 입구의 불변식 sum=1+…+(i−1),i≥1을 쓴다. i≤n이면 sum에 i를 더해 불변식을 다음 i에서도 유지하고,i>n이면 sum=1+…+n이다. n범위와 overflow조건은 이 증명에 필요하며 32bitwrap가 일어나면정수 합 수식 그대로의 값을 보장하지 않는다.

실제로 지나간 명령을 센다

정적 명령수는 코드에 있는 서로 다른 기본 명령의 수이고 동적 명령수는 경로를 따라 수행한 횟수다. 반복은 같은 주소를 여러 번 지나므로 두 수가 다르다. 조건 분기는 참/거짓이어도 검사 명령 한 번을 수행한 것으로 센다.

명령수는 cycle수나 실제 시간이 아니다. 메모리 지연·pipeline·분기예측·실행자원에 따라 시간이 달라진다. pseudo명령은 한 개 이상의 기본 명령으로 확장될 수 있으므로 소스 줄수를 기계 명령수로 바꾸지 않는다. 실제 컴파일러 출력을 관찰한 것이 아닌 자체 RV32I추적이다.

중간 과정을 따라가는 예제

a0=n=3이다. 주소 100:addi t0,x0,0;104:addi t1,x0,1;108:blt a0,t1,124;112:add t0,t0,t1;116:addi t1,t1,1;120:jal x0,108;124:addi a0,t0,0의 결과와 동적 명령수를 구하라.128은 추적 종료 경계이며 실행 명령을 추가하지 않는다. 분기와 jal의 숫자 표적은 이미 결정한 목표 주소를 적은 종이 표기다. 실제 어셈블러의 literal 즉시값 입력 문법이라고 가정하지 않으며 실행 코드에서는 해당 위치의 label과 올바른 PC 상대 변위를 사용해야 한다.

  1. 100/104초기화 뒤 sum0/i1이다.108은 3<1거짓이라 112에서 sum1,116에서 i2,120에서 108로 간다.

  2. 두 번째 108은 3<2거짓,본문 뒤 sum3/i3이다.세 번째 검사 3<3도 거짓이어서 sum6/i4가된다.

  3. 네 번째 108은 3<4참이라 124로 가고 a0=6이다. 다음 PC128에서 종이 추적을 끝낸다. t0=6,t1=4다.

  4. 초기화 2회,조건 검사 4회,본문 add/증가/jump각 3회,마지막 복사 1회라 총 2+4+9+1=16기본 명령이다. 정적 코드는 7명령이다.

n3에서 합 6/i4/a0=6,PC128,동적 16·정적 7명령이다.종이 추적 종료는 OS프로세스 종료 명령과 다르다.

종이와 본문으로 직접 해보기

같은 코드의 n0에서 최종 합과 동적 명령수를 구하라.별도 R[x5]=0xFFFFFFFF,R[x6]=1에서 blt와 bltu의참거짓을 비교하라.

힌트 보기

n0은 초기 i1에서 바로 나간다. FFFFFFFF는 signed−1/unsigned4294967295다.

풀이 보기

초기화 2+첫 검사 1+마지막 복사 1=4명령,합 0이다. signed blt는−1<1참,unsigned bltu는 4294967295<1거짓이다.비트패턴이 같아도 비교 명령의 의미가 다르다.

오해와 반례

코드 7줄이면 입력과 무관하게 7명령이고 조건 분기 뒤 명령은 항상 한 번 수행한다.

n3은주소 108을 4번 지나 16명령,n0은 4명령이다. RV32I에는 architectural delay slot이 없어 참 분기에서 112를 건너뛴다.다른 ISA의 분기 규약을 섞지 않는다.

소단원 4.3

함수호출과 스택의 하드웨어 역할

함수가 다른 함수를 부르면 돌아갈 주소는 어디에 남겨야 할까?

준비 개념과 학습 목표

준비 개념

  • RV32I의 jal ra,L은 ra(x1)에 현재 PC+4를 쓰고 표적으로 이동한다. jalr x0,0(ra)는 ra 값에 즉시값 0을 더한 표적의 최하위 비트를 0으로 만든 뒤 이동한다.

  • 표준 정수 호출 규약에서 a0 등은 인자와 결과, t/a/ra는 caller-saved, s0 등은 callee-saved다. sp(x2)는 반환 시 복원해야 한다.

  • 이번 RV32 예제는 16바이트 정렬 하향 스택, 4바이트 sw/lw, 유효 RAM을 쓴다. Cornell의 RV64 sd/ld 예제와 폭을 구별한다.

학습 목표

  • 명령이 보장하는 링크 동작과 소프트웨어 ABI를 구별한다.

  • 중첩 호출의 ra·보존 레지스터·sp를 명시적으로 저장·복원해 추적한다.

하드웨어가 하는 일과 약속

jal은 목적지 레지스터에 다음 명령 주소를 쓰고 PC를 표적으로 바꾼다. 모든 레지스터를 보존하거나 스택 프레임을 자동 생성하지 않는다. ra를 링크 레지스터로, sp를 스택 포인터로 쓰는 것은 ABI 약속이며 기본 ISA는 범용 x 레지스터를 사용한다.

함수 간 인자·결과·보존 레지스터 약속을 공유해야 다른 파일이나 언어의 호출이 맞물린다. callee는 s 레지스터를 쓰려면 원래 값을 돌려놓아야 하고 caller는 호출 뒤 필요한 t/a 값을 스스로 보존해야 한다. 결과 a0는 의도적으로 바뀌는 것이므로 모든 레지스터의 동일 복원이 목표는 아니다.

중첩 호출이 링크를 덮어쓴다

F가 ra에 자신의 caller 주소를 받은 뒤 G를 jal ra로 부르면 ra는 F 안의 복귀 주소로 바뀐다. F의 원래 복귀 주소를 보존하지 않으면 G 뒤의 ret가 F 안으로 다시 돌아가 잘못된 루프가 될 수 있다. 보통 F의 프레임에 원래 ra를 sw로 남기고 마지막에 lw로 복원한다.

스택은 별도의 하드웨어 상자가 아니라 주소 공간의 메모리 영역이다. sp를 16만큼 빼 프레임을 확보하고 정해진 offset에 저장한다. 스택 영역의 크기·권한·정렬을 실행 환경에서 확인해야 한다. 표준 ABI의 16바이트 정렬은 함수 진입뿐 아니라 procedure 실행 중에도 유지한다.

필요한 것만 보존하고 돌려놓는다

leaf 함수는 다른 call로 ra를 덮어쓰지 않으므로 저장할 다른 것이 없으면 프레임 없이 돌아갈 수 있다. 모든 함수가 항상 모든 값을 스택에 놓아야 하는 것은 아니다. 재귀 호출은 여러 활성 호출의 프레임이 생겨 별도의 ra·지역 값이 필요할 수 있다.

메모리의 저장 값을 load로 읽기 전에 sp를 원상 복귀하면 offset이 원래 프레임을 가리키지 않을 수 있다. save→body→restore→sp 해제→return 순서를 점검한다. 반환 뒤 해제된 프레임 영역의 값이 잠시 남아 있어도 지속성이나 소유권을 가정하지 않는다. 실제 스택 장치 시험과 어셈블러 실행은 미수행이다.

중간 과정을 따라가는 예제

처음 PC100,a0=5,s0=99,sp4096이다.100:jal ra,200. F의 200:addi sp,sp,-16;204:sw ra,12(sp);208:sw s0,8(sp);212:addi s0,a0,0;216:jal ra,300;220:add a0,a0,s0;224:lw s0,8(sp);228:lw ra,12(sp);232:addi sp,sp,16;236:jalr x0,0(ra). G는 300:addi a0,a0,1;304:jalr x0,0(ra)다. PC104복귀까지 값을 추적하라. 분기와 jal의 숫자 표적은 이미 결정한 목표 주소를 적은 종이 표기다. 실제 어셈블러의 literal 즉시값 입력 문법이라고 가정하지 않으며 실행 코드에서는 해당 위치의 label과 올바른 PC 상대 변위를 사용해야 한다.

  1. 100jal뒤 ra104/PC200이다.200에서 sp4080,204의 주소 4092에는 104,208의 주소 4088에는 s0원 값 99를 저장한다.

  2. 212에서 s0=5로 원인자를 보존한다.216jal은 ra220/PC300으로 가므로 원 caller주소 104가 ra에서 덮어 써진다.

  3. G300에서 a0=6,304에서 PC220으로 돌아온다.220의 add는 6+5=11을 a0에 쓴다.

  4. 224에서 s0=99,228에서 ra104를 복원한다.232의 sp4096뒤 236return은 PC104다. 원래 stackpointer와 callee-saved s0는 복원되고 결과 a0=11이다.

최종 PC104/a0=11/s0=99/sp4096/ra104다. frame4080..4095의 word4092=104/4088=99는명시 sw/lw가 관리했다.

종이와 본문으로 직접 해보기

F에서 ra저장/복원만 빼고 나머지는 같다면 236의 표적은? 별도 leaf H가 addi a0,a0,2;jalr x0,0(ra)만 한다면 sp를 항상 바꿔야 하는가?

힌트 보기

216에서 ra=220이 된다. leaf는 새 jal ra를 수행하지 않는다.

풀이 보기

ra가 220으로 남아 236에서 220으로 돌아가 원 caller104로 복귀하지 않는다. 같은 복구·해제 코드도 다시 수행되어 정상 frame과 sp보장이 깨진다. leaf H는 추가 저장/지역 공간이 없으면 frame없이 가능하며 s레지스터도 건드리지 않는다.

오해와 반례

call이 자동으로 모든 레지스터와 반환 주소를 stack에 push하고 ret가 자동 pop한다.

이 RV32I예제에서 jal은 ra에만 링크 값을 쓰며 F가 명시 sw/lw를 빼면 ra220으로 잘못 돌아간다. 다른 ISA의 call 동작이나 컴파일러가 생성한 prologue를 RV32I의 자동 하드웨어 저장으로 혼동하지 않는다.

소단원 4.4

명령 추적과 simulator

화면에 최종 숫자가 맞아도 실제로 어떤 명령을 몇 번 지났는지 알 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 추적 행에는 수행 전 PC·명령·읽은 레지스터/메모리·쓴 값·다음 PC를 적는다. 상태 초기화와 종료 경계를 명시한다.

  • 기능 simulator는 지원 ISA와 환경의 상태 전이를 모사한다. cycle-accurate 모델이나 실제 CPU 속도 측정과 같지 않다.

  • 본문은 RV32I/little-endian/단일 스레드/일반 RAM/유효 정렬의 종이 예제다. 실제 도구 실행과 예상 추적은 별도다.

학습 목표

  • 상태 추적표로 반복의 분기와 load/store를 검산한다.

  • assemble 성공·functional 실행·timing·장비 실험의 증거를 구별한다.

한 번에 한 상태를 바꾼다

PC주소에서 현재 명령을 읽고 명령 규칙에 따라 상태를 바꾼다. add는 레지스터 write,sw는 메모리 write,분기는 다음 PC를 바꾸므로 표의 write칸을 분리한다. 읽는 source와 같은 destination이 있어도 해당 명령의 이전 source 값을 기준으로 결과를 계산한다.

초기 레지스터의 알 수 없는 값을 마음대로 0으로 가정하지 않는다. 예제에서 처음 읽는 값을 모두 정의하거나 사용 전 초기화했는지 확인한다. 메모리접근의 주소·폭·정렬·권한을 기록하고,예외가 나면 그 뒤를 정상 실행처럼 진행하지 않는다.

도구의 모드를 증거와 함께 기록한다

RARS 개발자 문서는 assemble-only a와 simulate, 32/64비트 모드, memory configuration, pseudo 금지 np, step limit, ic 명령 계수를 구별한다. assembler는 문법과 인코딩을 만드는 단계이며 실행 경로의 정답을 보장하지 않는다. pseudo 소스는 확장된 기본 명령과 나란히 읽을 수 있다.

실행 검증에는 실제 도구 버전·모드·명령·입력·초기상태·출력·종료코드·날짜를 남겨야 한다. 이번 단원은 문서만 읽었으므로 그 항목을 가짜 성공으로 채우지 않는다. 표의 기대값은 종이 예상이며 실제 simulator로그나 장비 캡처가 아니다.

일치해도 무엇을 보증했는지 한정한다

기능 모형에서 같은 명령과 초기 상태의 결과가 맞으면 해당 입력의 ISA상태 전이를 확인했다는 범위다. cache/분기예측/파이프라인/OS/다중 thread/장치 부작용은 모형에포함되었는지 따로 점검한다. 실행 명령수나 GUIstep횟수를 실제 CPUcycle로 바꾸지 않는다.

유한 step limit 도중 멈추면 원래 프로그램이 정상 종료했다고 주장하지 않는다. 무한 loop디버깅에서는 PC가 어느 구간을 되풀이하는지,종료 조건의 값이 진전하는지를 본다. 선택 확장으로 도구에서 같은 표를 대조할 수 있지만 설치 없이도 명령 규칙과 종이 표로 본 이론을 학습할 수 있다.

중간 과정을 따라가는 예제

초기 x10=256,word256=9이다.0:addi x5,x0,2;4:addi x6,x0,0;8:add x6,x6,x5;12:addi x5,x5,-1;16:bne x5,x0,8;20:sw x6,0(x10).다음 PC24는 종이 종료 경계다. 실행 PC열·최종 레지스터/메모리·기본 명령수와 분기 참/거짓 횟수를 구하라. 분기와 jal의 숫자 표적은 이미 결정한 목표 주소를 적은 종이 표기다. 실제 어셈블러의 literal 즉시값 입력 문법이라고 가정하지 않으며 실행 코드에서는 해당 위치의 label과 올바른 PC 상대 변위를 사용해야 한다.

  1. PC0에서 x5=2,PC4에서 x6=0이다.8에서 x6=2,12에서 x5=1이된다.

  2. 16의 1≠0은 참이어서 다음 PC8이다.두 번째 8은 x6=2+1=3,12는 x5=0이다.

  3. 두 번째 16은 0≠0은 거짓이라 PC20이다.20의 sw는 word256을 3으로 바꾸고 다음 PC24다.

  4. PC열은 0,4,8,12,16,8,12,16,20으로 9명령이다.분기는 2번 중 참 1/거짓 1,최종 x5=0/x6=3이고 byte256..259=03/00/00/00이다.

9명령 뒤 PC24/x5=0/x6=3/word256=3,분기 참 1·거짓 1이다.종이 예상값이며 실제 simulator실행은 미수행이다.

종이와 본문으로 직접 해보기

PC12의 감소 명령을 addi x5,x5,0으로 바꾸면 PC8/12/16의 첫 두 회차에서 x5/x6는? 9step 제한으로 멈춘 실험을 프로그램 정상 종료로 볼 수 있는가?

힌트 보기

x5가 2로 유지되어 bne가 계속 참이다. 매번 x6에 2를 더한다.

풀이 보기

첫 회차 x5=2/x6=2,두 번째 x5=2/x6=4이며 분기는 계속 참이다. 원래 PC20에 가지 않고 무한 반복하므로 step limit중단은 정상 종료 증거가 아니다. 실제 실험을 수행한 것이 아닌 경로 분석이다.

한 단계 더

심화: 초기 카운터 n을 0≤n≤1000으로 하고 현재 코드를 그대로 쓰면 n≥1에서 기본 명령은 초기 2+반복 3n+store1=3n+3,합 n(n+1)/2다. n3이면 12명령/합 6이다. n0은 본문 앞 검사가 없어서 먼저 0을 더한 뒤 카운터−1이 되고 단순 정수 반복에서는 종료하지 않는다. 실제 32bit에서는 modulo wrap와 매우 긴 유한 경로가 있으므로 무한이라고 동일시하지 말고 0입력 pre-test 조건을 추가하라.
