소단원 10.1

SRAM·DRAM·저장 계층

왜 컴퓨터에는 빠른 저장 장치 하나 대신 여러 종류가 있을까?

준비 개념과 학습 목표

준비 개념

  • 비트·바이트·KiB
  • 지연과 용량

학습 목표

  • SRAM과DRAM의 보존 원리를 구별한다.
  • 휘발성과 속도를 같은 성질로 보지 않는다.
  • 여러 계층의 용량을 계산하고 복사 의미를 설명한다.

기억 방법이 비용을 바꾼다

SRAM은 전원이 있는 동안 안정된 회로 상태로 비트를 유지한다. 일반적인 셀은 피드백 회로를 사용하며 DRAM은 축전기에 저장된 전하로 비트를 나타내고 전하 누설 때문에 주기적인 refresh가 필요하다. SRAM의 static은 전원이 꺼져도 영구 보존한다는 뜻이 아니다.

두 기술 모두 일반적으로 휘발성 메모리다. SRAM은 빠른 접근에 적합하여 캐시에, DRAM은 큰 용량을 비교적 낮은 비용으로 제공하여 주기억장치에 흔히 쓰인다. 실제 지연과 비용은 제품·구조·접근 조건마다 달라진다. 이론의 관계를 특정 최신 제품의 고정 ns 수치로 바꾸지 않는다.

가까운 작은 공간과 큰 공간을 협력시킨다

레지스터·캐시·주기억장치·비휘발성 저장 장치는 서로 다른 속도와 용량을 가진 계층을 이룬다. 자주 쓰는 정보의 복사본을 빠른 계층에 두고 필요할 때 아래 계층에서 가져오면 평균 접근을 줄일 수 있다. 모든 정보를 가장 빠른 계층에 넣는 비용과 면적을 피하려는 설계다.

캐시에 들어 있는 데이터는 보통 아래 계층 데이터의 일부 복사본이므로 각 용량을 더한 숫자를 애플리케이션의 독립 데이터 보관량이라고 부르지 않는다. 수정된 캐시 값과 아래 메모리를 언제 맞추는지는 쓰기 정책의 문제다. 데이터가 여러 계층에 있다는 사실만으로 항상 모든 복사본이 즉시 같은 값인 것은 아니다.

비휘발성도 접근 방식과 나누어 본다

Flash 기반 저장 장치와 HDD는 전원을 꺼도 정보를 유지하는 비휘발성 저장을 제공한다. 하지만 CPU의 모든 읽기가 저장 장치에서 바로 수행되는 것은 아니다. 운영체제와 메모리 계층이 데이터 이동을 관리한다. 저장 용량 증가와 CPU 캐시 증가도 같은 개선이 아니다.

지연은 요청 후 첫 결과까지 걸리는 시간이고 대역폭은 일정 시간에 옮기는 양이다. 큰 순차 전송이 잘 되는 장치도 작은 무작위 접근의 지연이 클 수 있다. 계층을 비교할 때 용량·지연·대역폭·비휘발성·비용을 각각 본다. 이 단원에서는 장치 성능을 실제 측정하지 않는다.

중간 과정을 따라가는 예제

자체 모형의 캐시64KiB와 주메모리8MiB를 바이트로 바꾸고 용량 비를 구하라. 1KiB=1024바이트,1MiB=1024KiB다.

  1. 캐시는64×1024=65536바이트다.
  2. 주메모리는8×1024×1024=8388608바이트다.
  3. 주메모리/캐시=8388608/65536=128이다.

65536바이트와8388608바이트,비128이다. 복사 관계이므로 두 수의 합을 독립 프로그램 데이터 용량으로 해석하지 않는다.

오해와 반례

SRAM은 static이므로 전원을 꺼도 정보가 남는다.

static은 전원이 있는 동안 refresh 없이 상태를 유지하는 원리를 말한다. 일반 SRAM은 휘발성이므로 영구 저장을 대신하지 않는다.

소단원 10.2

시간·공간 locality

방금 읽은 주소와 그 옆 주소를 다시 읽는 행동은 서로 같은 종류일까?

준비 개념과 학습 목표

준비 개념

  • 메모리 주소
  • 블록에 여러 바이트를 담는 모형

학습 목표

  • 시간적·공간적 지역성을 구별한다.
  • 블록 번호와 반복 접근을 손 추적한다.
  • 지역성의 성능 효과에 필요한 캐시 조건을 밝힌다.

다시 쓰는 주소와 가까운 주소

시간적 지역성은 최근 사용한 정보가 가까운 미래에 다시 사용되는 경향이다. 반복문에서 같은 변수나 명령을 자주 접근하는 경우가 예다. 공간적 지역성은 사용한 주소 근처의 주소를 곧 사용하는 경향이다. 배열의 연속 원소를 읽는 경우가 예다. 두 경향은 함께 나타날 수 있다.

지역성은 모든 프로그램이 반드시 따르는 법칙이 아니다. 멀리 떨어진 주소를 불규칙하게 읽거나 현재보다 큰 작업 집합을 순환하면 캐시 효과가 낮을 수 있다. 같은 주소를 반복해도 그 사이 교체가 일어나면 다시 miss일 수 있으므로 시간적 지역성 자체를 hit 보장과 동일시하지 않는다.

블록으로 가까운 데이터를 함께 가져온다

자체 모형은 바이트 주소를 쓰며 블록 크기는16바이트, 블록은16의 배수에서 시작한다. 주소a의 블록 번호는floor(a/16)이고 안의 위치는a mod16이다. 한 miss에서 블록 전체를 가져온다고 가정한다. 주소0,4,8,12는 서로 다른 주소지만 같은 블록0에 있다.

캐시가 처음 비어 있고 블록0을 계속 보관하며 다른 접근·프리페치·쓰기 없이 읽으면0은miss이고4,8,12는hit이다. 이것이 공간적 지역성을 블록 전송으로 활용하는 예다. 블록 크기를 늘리면 가까운 데이터가 더 들어오지만 전송 비용과 수용 가능한 별도 블록 수가 바뀐다.

작업 집합과 교체를 함께 본다

일정 구간에서 반복 사용하는 서로 다른 위치의 집합을 작업 집합 관점에서 살펴볼 수 있다. 자주 쓰는 블록들이 캐시에 함께 들어갈 수 있으면 첫 적재 뒤hit가 많아질 수 있다. 용량이 충분해 보여도 매핑 때문에 서로 쫓아낼 수 있어 배치 조건도 확인한다.

이 절에서는 단 하나의 블록을 담는 읽기 캐시를 비교 모형으로 쓴다. 매 miss는 해당 블록으로 교체하며 다른 동작은 없다. 블록0과4를 교대로 읽으면 두 주소 모두 반복하지만 매번 이전 블록이 사라진다. 지역성 설명을 실제 접근표와 캐시 정책으로 연결하는 이유다.

중간 과정을 따라가는 예제

위 한 블록 캐시가 비어 있다. 주소0,4,8,12,0을 읽으면 블록 번호와hit/miss는?

  1. 다섯 주소의 블록 번호는 모두0이다.
  2. 첫0에서miss로블록0을가져온다.
  3. 뒤4,8,12,0은같은블록이남아있으므로hit다.

블록0/0/0/0/0,miss1회·hit4회로hit비율4/5=80%다. 마지막0은같은주소재사용도포함한다.

종이와 본문으로 직접 해보기

같은 캐시를 다시 비우고 주소0,64,0,64를 읽어라. 주소15와16의 블록·안의 위치도 구하라.

힌트 보기

64/16=4이며한블록만남는다. 경계16에서블록번호가바뀐다.

풀이 보기

블록0/4/0/4로네번모두miss다. 주소15는블록0·위치15,주소16은블록1·위치0이다. 주소재사용이있어도보관되지않는다.

오해와 반례

같은 주소를 두 번 읽으면 둘째는 반드시cache hit다.

한 블록 캐시에서0,64,0은가운데블록4가블록0을교체하여둘째0도miss다. 같은주소반복과실제보관조건은분리한다.

소단원 10.3

cache hit·miss와 AMAT

작은 miss 비율도 평균 대기시간을 크게 바꿀 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 평균과비율
  • 캐시의hit와miss

학습 목표

  • hit time과추가miss penalty를구별한다.
  • AMAT를가중평균에서유도한다.
  • 다단계캐시의지역miss비율조건을설명한다.

추가비용인지 전체시간인지 정한다

hit는원하는블록이유효하게캐시에있는경우이고miss는없어아래계층접근등이필요한경우다. 이절의직렬모형은매접근에서캐시검사시간h를항상지불하고miss에서추가시간p를지불한다. miss한접근의전체시간은h+p다. p를이미전체시간으로준문제와섞지않는다.

miss비율m이면hit비율1−m이다. AMAT는(1−m)h+m(h+p)=h+mp로유도한다. 단위는시간이며m은0부터1사이비율이다. 중첩처리·프리페치·쓰기완료대기등이없는자체모형의평균이다. 이평균이프로그램전체실행시간과항상같다는주장은아니다.

비율은 기준 횟수와 함께 쓴다

1000접근에서miss50번이면m=50/1000=.05다. h=2ns,p=80ns이면평균6ns다. miss접근의82ns를이미포함한가중평균950×2+50×82를1000으로나눠도6ns다. 두방법은같은회계다.

miss비율만줄었다고전체평균이반드시작아지는것은아니다. 구조변경으로hit time이늘거나miss penalty가커질수있다. 서로다른캐시는각각h,m,p를같은조건에서비교한다. 아래수치는실제제품벤치마크나학생측정값이아니다.

다단계의 지역 비율을 적용한다

L1을항상검사하고그miss에서L2를검사한다고정한다. L2miss비율은L2로실제로간접근을기준으로한지역비율m2다. L1h1,m1와L2h2,m2,추가주메모리시간p라면AMAT=h1+m1(h2+m2p)다. L2전체기준miss비율을다시m1으로곱하면비용을중복축소한다.

다단계가항상빠르다는것도아니다. L2에서거의못찾는데검사시간을추가하면손해일수있다. 계산에앞서어느단계가항상실행되고어느단계가조건부인지나무처럼그린다. 실제하드웨어는병렬접근이나대기겹침이있을수있어이직렬평균의한계를기록한다.

중간 과정을 따라가는 예제

h=2ns,p=80ns이고1000읽기중miss50번인직렬캐시의AMAT와총시간합을구하라.

  1. m=.05이므로AMAT=2+.05×80=6ns다.
  2. 950hit는1900ns,50miss는50×82=4100ns다.
  3. 총6000ns,1000으로나눈6ns와일치한다.

평균6ns,총시간합6000ns다. 별도접근끼리시간을겹치지않는모형이다.

종이와 본문으로 직접 해보기

L1h1=1ns,m1=.1,L2h2=5ns,m2=.2,주메모리추가p=50ns일때평균을구하라. L2miss는전체L1접근의몇%인가?

힌트 보기

괄호속L2조건부평균5+.2×50을먼저구한다.

풀이 보기

L2조건부평균15ns,L1포함1+.1×15=2.5ns다. 전체기준L2miss는.1×.2=.02=2%다.

오해와 반례

비교할캐시에서miss비율이더작으면평균도항상더작다.

A:h2ns,m.05,p80은6ns지만B:h5ns,m.02,p80은6.6ns다. B가miss가적어도hit검사가느려이모형평균은더크다.

자기점검

m=0이면AMAT는?

답과 이유 보기

h

miss추가비용이없다.

m=1이면AMAT는?

답과 이유 보기

h+p

모든접근이캐시검사후추가비용을지불한다.

위기본모형에서목표평균4ns를얻는miss비율은?

답과 이유 보기

.025=2.5%

2+80m=4에서m=2/80이다.

한 단계 더

문제에서miss전체시간82ns를주었다면식은(1−m)2+m82다. 이를2+m82로쓰면hit검사시간을miss부분에중복계산한다. m.05일때그잘못된식은6.1ns다.

소단원 10.4

block·capacity·associativity

캐시에빈공간이남아있어도두주소가서로를쫓아낼수있을까?

준비 개념과 학습 목표

준비 개념

  • 블록번호와나머지
  • 용량·상태추적

학습 목표

  • 블록크기·총데이터용량·way·set수를연결한다.
  • 직접사상과집합연관을비교한다.
  • tag/index/offset과valid조건을계산한다.

총용량과배치가능성을나눈다

캐시데이터용량C,블록크기B,way수W이면총라인수C/B,집합수S=C/(BW)다. 이절의용량은태그·valid·교체정보를제외한데이터바이트만센다. 직접사상은W=1이고한블록이갈라인이하나다. W-way에서는선택된집합안W라인중하나에넣을수있다.

자체사상은바이트주소a에서블록번호b=floor(a/B),집합번호b modS,태그floor(b/S),블록안위치a modB다. 동일집합의다른태그는서로다른블록이다. valid=1이며태그가일치해야hit다. 전원후비어있는라인의우연한태그일치만으로hit라고판정하지않는다.

way를늘리면같은집합에여럿담는다

C=64바이트,B=16바이트면4라인이다. 직접사상은4집합·각1라인이고2-way는2집합·각2라인이다. 주소0과64는블록0과4이며두구조모두같은집합0으로간다. 직접사상에서는서로교체하지만2-way에서는둘을함께담을수있다.

2-way도같은집합의블록3개를무한히담지는못한다. 교체정책이필요하며이절은읽기만,빈라인우선,가득차면최근사용이가장오래된LRU를쓴다. 구조가복잡해지면태그비교등의hit time비용도바뀔수있으므로hit비율의이득만으로성능결론을끝내지않는다.

블록크기에도교환조건이있다

용량64바이트를유지하고블록을32바이트로늘리면라인은2개로줄어든다. 가까운주소를함께가져오기쉬워져도서로다른영역을담을자리수는줄어든다. 전송량과miss penalty도달라질수있다. 큰블록이항상좋다는공식은없다.

주소비트분할은보통블록과집합수가2의거듭제곱일때간단하다. 예를들어8비트주소,B16,S4면offset4비트,index2비트,tag2비트다. way를선택하는비트가주소에별도로붙는것은아니며선택집합의여러태그를비교한다. 여기서는현대CPU의주소해시등복잡한구조를모사하지않는다.

중간 과정을 따라가는 예제

두캐시모두처음비어있다. C64바이트,B16바이트이며직접사상과2-way에주소0,64,0,64를읽는다. hit/miss와비율을구하라.

  1. 블록은0/4/0/4다. 직접사상S4에서모두집합0이며태그0/1이번갈아라인을대체한다.
  2. 직접사상은M/M/M/M으로hit0%다.
  3. 2-way S2에서도집합0이지만두빈라인에블록0과4를넣어M/M/H/H가된다.

직접사상hit0%,2-way hit50%다. 둘다같은64바이트데이터용량이지만허용배치가다르다.

종이와 본문으로 직접 해보기

같은2-way LRU에주소0,64,128,0을처음부터읽는다. 또직접사상8비트주소예에서주소83의태그·집합·위치를구하라.

힌트 보기

블록0/4/8은모두2집합의집합0이다. 83=5×16+3이다.

풀이 보기

0과4적재후8은LRU블록0을쫓아낸다. 마지막0은miss며4를쫓아내므로네번모두miss다. 직접사상S4에서블록5→집합1,태그1,위치3다. 비트로83=01|01|0011이다.

오해와 반례

데이터용량이충분하면충돌miss는없다.

0과64두블록은32바이트지만64바이트직접사상에서같은라인을번갈아교체한다. 전체빈공간과그블록에허용된자리수는별개다.

자기점검

답과 이유 보기

64/32=2이며W1이다.

태그가같아도valid0이면hit인가?

답과 이유 보기

아니다.

그라인의유효데이터가없다는조건이다.

C64,B16,W2의집합수는?

답과 이유 보기

64/(16×2)=2다.

한 단계 더

같은2-way에서블록0,4,0,8순서로읽으면세번째0이hit되어4가더오래된값이된다. 8적재때4가교체되며최종0/8이다. FIFO였다면첫적재0을교체할수있어LRU와다르다.
