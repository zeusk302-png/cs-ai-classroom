같은 배열의 이웃 원소를 읽고 쓰는 반복도 독립적인가?

자체 배열 x = [1,2,3,4,5]에 i = 0,1,2,3 순서로 x[i+1] = x[i] + 10을 수행한다. 첫 쓰기의 11을 다음 반복이 읽으므로 결과는 [1,11,21,31,41]이다. 주소를 옆으로 옮겼다는 사실이 원소별 독립성을 뜻하지 않는다.

다른 경로가 네 입력을 쓰기 전에 모두 읽으면 원래 입력 [1,2,3,4]에 각각 10을 더해 [1,11,12,13,14]가 된다. 이 두 경로는 같은 코드의 안전한 벡터화가 아니다. 정확한 정수·유효 주소·overflow 없음의 자체 비교이며 실제 컴파일러 실행은 하지 않았다.

원소별 독립성이 있어도 덧셈의 재결합은 출력 정확성 조건을 확인한다. 별도의 자체 십진 모형에서는 각 덧셈 결과를 유효 숫자 세 자리로 반올림한다. (−1000 + 1000) + 1은 1이지만 −1000 + (1000 + 1)은 안쪽 1001이 1000으로 반올림되어 0이다. 이는 실제 IEEE 형식의 실행 예제가 아니다.

한 명령으로 여러 데이터에 같은 일을 한다

SIMD는 하나의 명령이 여러 데이터 원소에 같은 종류의 연산을 적용하는 방식이다. 여러 처리 자리인 lane이 공통 명령을 받아 서로 다른 값을 계산한다. 독립된 원소끼리 덧셈할 때 명령 관리 비용을 나눌 수 있다.

벡터 처리기는 여러 원소로 구성된 벡터에 연산을 적용한다. 벡터 길이·레지스터 크기·실제 실행 폭과 처리 시간의 관계는 기계마다 다르다. 긴 벡터 명령 하나가 모든 원소를 한 클록에 끝낸다고 가정하지 않는다. 여기서는 폭 4의 단순 모델로 직관을 연습한다.

폭이 맞지 않는 마지막 묶음을 처리한다

원소 수가 폭의 배수가 아니면 마지막 묶음에 유효하지 않은 자리가 생긴다. 남은 원소만 스칼라로 처리하거나 유효 원소를 표시하는 마스크 등을 사용하는 설계를 생각할 수 있다. 범위를 넘는 주소를 읽고 나중에 버리는 방식이 항상 안전한 것은 아니다.

가상 모델에서 폭 4로 10개 원소를 처리하려면 3개 묶음이 필요하고 마지막에는 2개만 유효하다. 전체 12자리 중 유효 연산은 10개다. 이 자리 활용률을 전체 실행시간의 정확한 가속비로 바꾸면 메모리 접근·준비 비용이 빠진다.

같은 코드 모양보다 의존성이 중요하다

각 c[i]=a[i]+b[i]가 서로 다른 출력에 쓰고 입력과 출력의 겹침이 문제를 만들지 않는다면 원소별 독립 처리를 생각할 수 있다. 반면 a[i]=a[i−1]+1에는 앞 단계 결과 의존성이 있어 그대로 같은 묶음에 넣어 동시 처리할 수 없다.

다른 병렬 알고리즘으로 바꾸는 가능성과 원래 순서의 안전한 벡터화는 별도다. 컴파일러·메모리 정렬·명령 지원·대역폭도 실제 결과에 영향을 준다. 이 단원은 독립성과 작은 묶음의 종이 모델이며 실제 벡터 명령을 컴파일하거나 실행하지 않는다.

스레드 수를 모든 블록에서 합쳐 warp 수를 구해도 될까?

NVIDIA CUDA 모델에서 warp 구성은 블록별로 한다. 자체 두 블록이 각각 70개 스레드를 가지면 각 블록은 ceil(70/32) = 3개의 warp이고 전체는 6개다. 총 스레드 140만 보고 ceil(140/32) = 5로 계산하면 서로 다른 블록의 남은 자리를 잘못 합친다.

실제 NVIDIA의 자원 제한 원리를 바탕으로 별도 종이 SM의 자원 예산을 정한다. 이 SM은 register 256개, 공유 메모리 128단위, 최대 4개의 resident warp와 최대 4개의 resident block을 허용한다고 가정한다. 할당 단위의 반올림은 없는 자체 모형이며 실제 GPU 제품 사양이 아니다.

블록 32스레드, 스레드당 register 6개, 블록당 공유 메모리 64단위라면 register 때문에 블록 하나만 머문다. register 4개로 바꾸면 두 블록이 머물 수 있다. 더 많은 resident warp는 자원 수용 조건의 계산이며 실제 처리량이나 스케줄 진행 속도의 측정이 아니다.

    자원 수용 수를 실측 속도로 바꾸지 않는다.

많은 스레드를 묶어 실행한다

NVIDIA CUDA의 스레드는 block이라는 그룹에 속하고 block은 SM이라는 실행 단위의 자원을 사용한다. block의 스레드는 32개 단위인 warp로 구성된다. SIMT는 개별 스레드 동작을 작성하는 모델을 많은 스레드의 공통 명령 실행으로 연결한다.

warp의 스레드는 각자 상태를 가지며 한 공통 명령에서 활성 스레드들이 데이터를 처리한다. warp 수와 실제 한 순간에 실행되는 연산 수는 같지 않다. SM의 레지스터·공유 메모리·스케줄러 및 기계별 제한을 함께 살펴야 한다. 32라는 값은 여기서 읽은 NVIDIA CUDA 모델의 값이다.

분기하면 공통 실행의 빈 자리가 생길 수 있다

한 warp 안에서 일부 스레드만 조건을 만족하면 서로 다른 경로를 수행하며 해당 경로에 없는 스레드는 비활성화될 수 있다. 분기가 존재한다는 것과 모든 warp가 반드시 분기한다는 것은 다르다. 다른 warp의 경로가 다르다는 이유만으로 같은 warp 내부 분기라고 부르지 않는다.

직관을 위해 4자리 가상 묶음이 양수/음수 두 경로를 각각 한 번 실행하는 모델을 쓴다. 이는 실제 warp 폭이나 실제 NVIDIA 명령 시간의 복제가 아니다. 조건·컴파일 방식·세대별 스케줄링에 따라 실제 비용은 달라진다.

동시성에는 자원과 동기화 조건이 있다

더 많은 스레드가 있다고 항상 더 빨리 끝나지는 않는다. block별 자원 사용이 많으면 SM에 함께 머무르는 block 수가 제한될 수 있고 메모리나 의존성도 대기를 만든다.

독립 스레드 스케줄링이 있는 세대에서는 스레드가 항상 묵시적으로 같은 발걸음을 유지한다고 가정하지 않는다. 데이터를 공유하는 알고리즘은 해당 범위의 명시적 동기화와 올바른 메모리 조건이 필요하다. 같은 주소에 동시에 보통 쓰기를 하면 원하는 마지막 값이 보장된다고 가정하지 않는다.

작업이 끝난 뒤의 시간까지 포함하면 에너지 순위가 바뀔까?

자체 같은 작업의 A는 첫 1초 동안 10W, 다음 2초 동안 50W를 사용한다. 작업 시간은 3초이고 에너지는 10×1 + 50×2 = 110J다. 두 전력 숫자의 단순 평균 30W를 3초에 곱한 90J는 구간 길이의 가중치를 빠뜨린 계산이다.

B는 0.8초 동안 80W, 다음 0.2초 동안 5W를 사용해 1초 안에 작업을 끝낸다. 에너지는 64 + 1 = 65J다. 여기서는 같은 작업 출력과 같은 전력 측정 범위라는 자체 조건을 명시한다. 실제 제품이나 계측 결과가 아니다.

공통 관찰 구간을 작업 시작부터 5초로 정하고 완료 뒤 A는 5W, B는 20W로 유휴 상태를 유지한다고 가정하면 A는 120J, B는 145J다. 작업만 보면 B의 에너지가 작지만 유휴까지 포함하면 A가 작다. 다만 완료 기한이 1.2초라면 A는 시간 조건을 만족하지 못한다.

순간 사용률과 전체 사용량은 다르다

전력은 단위 시간당 에너지 사용률이며 W는 J/s다. 전력이 시간에 따라 바뀌면 전체 에너지는 전력을 시간에 걸쳐 누적한 값이다. 일정하거나 해당 구간의 평균 전력 P를 사용할 때 E=P×T로 계산한다.

빠른 장치는 순간 전력이 커도 작업 시간이 짧아 총 에너지가 작을 수 있다. 반대로 빠르다는 이유만으로 에너지가 반드시 작다고도 결론 내리지 않는다. 어떤 장치/부품의 전력이고 준비·전송·유휴 시간이 범위에 포함되는지 정한다.

설계 면적과 성능에는 여러 선택이 있다

칩에는 계산 장치뿐 아니라 제어·레지스터·캐시·연결·메모리 인터페이스 등이 공간을 사용한다. 제한된 면적에 계산 자리를 더 넣는 선택과 데이터를 더 빨리 공급하는 선택은 다른 과업에 다른 효과를 낼 수 있다.

CMU의 전력 장벽 설명은 전압·주파수 등 설계 요인을 연결한다. 이를 모든 칩의 총 전력을 한 식으로 정확히 예측하는 보장으로 쓰지 않는다. 공정·작동 조건·누설과 실제 회로의 활동이 다르면 같은 면적이나 주파수도 다른 전력 결과를 가진다.

워크로드별 병목과 tradeoff

계산 능력을 두 배 늘리면 메모리에서 데이터를 기다리는 작업도 두 배 빨라질까?

준비 개념과 학습 목표

준비 개념

  • 연산 수

  • 데이터 바이트

  • 속도의 상한

학습 목표

  • 연산 집약도와 메모리 대역폭을 연결한다.

  • Roofline 상한을 자체 수치로 계산한다.

  • 병목과 실제 개선 결과의 차이를 설명한다.

재사용 때문에 연산량도 바뀌었다면 I만 비교해도 될까?

자체 원래 과업은 W=20G연산, DRAM 경계의 트래픽 Q=10GB다. 계산 상한 C=40G연산/s, 대역폭 B=10GB/s이면 I=2연산/바이트, 처리량 상한 20G연산/s, 시간 하한 1초다. G와 GB는 모두 10^9 기준이다.

동일한 요구 출력을 만드는 별도 변환은 중복 준비 계산을 포함해 W=24G연산, Q=4GB라고 가정한다. I=6이지만 시간에는 새 W를 써야 한다. 처리량 상한 40G연산/s에서 kernel 시간 하한은 24/40=0.6초다. 원래 W=20을 넣은 0.5초는 변환 뒤의 작업량을 섞은 오류다.

변환에 직렬 준비 시간 0.5초가 추가된다면 전체 시간 하한은 1.1초다. 원래 하한 1초와 비교해도 실제 순위는 확정할 수 없다. 서로 다른 하한만으로 실제 시간의 대소를 판정하지 않는다. 두 kernel이 각각 상한에 정확히 도달한다는 추가 모형을 따로 정했을 때만 예상 전체 1초와 1.1초를 비교할 수 있다.

먼저 확인할 개념
  • Roofline의 경계와 시간 하한

    W와 Q를 같은 변환의 장부에서 읽는다.

  • 동일 출력과 변환 정확성

    다른 연산 경로가 요구 출력을 보존하는지 확인한다.

과업의 데이터 이동을 같은 범위로 센다

워크로드는 장치에 주는 실제 작업과 입력 특성을 뜻한다. 연산 집약도 I=W/Q는 연산 수 W를 해당 메모리 경계에서 이동한 바이트 Q로 나눈 값이다. 원래 Roofline의 DRAM 경계를 쓰면 캐시 안의 모든 접근 횟수를 DRAM 바이트와 혼동하지 않는다.

같은 계산이라도 자료 재사용이나 배치 방식이 DRAM 트래픽을 바꿀 수 있다. 계산 횟수·정확도·메모리 경계가 서로 다른 비율은 그대로 비교하지 않는다. 지연시간과 대역폭도 다르다. 대역폭이 커도 의존된 접근의 대기가 모두 사라지는 것은 아니다.

계산과 공급 능력의 작은 상한을 고른다

단순 Roofline의 처리량 상한은 min(C,B×I)다. C는 연산/s의 계산 상한, B는 바이트/s의 메모리 대역폭이다. B×I의 단위도 연산/s가 된다.

상한은 프로그램이 반드시 그 속도를 달성한다는 예측이 아니다. 분기·병렬성 부족·다른 자원·시작/전송 비용은 그 아래 성능을 만들 수 있다. 상한으로 계산한 W/처리량은 단순 모델에서 시간의 하한이며 실제 완료 시간을 보장하지 않는다.

병목에 맞는 변경을 선택하고 다시 확인한다

메모리 상한이 낮은 작업에는 계산 장치를 늘리는 것만으로 상한이 바뀌지 않을 수 있다. 데이터를 재사용해 I를 올리거나 대역폭을 바꾸는 설계를 고려한다. 계산 상한에 걸린 작업에서는 계산 자원·명령 활용 개선을 살핀다.

더 큰 캐시나 다른 배치도 면적·전력·준비 비용을 요구할 수 있다. CPU/GPU 선택 역시 전체 과업의 데이터 이동과 시작 비용을 포함해 비교한다. 작은 입력에서는 준비 비용이 주요 요인일 수 있어 큰 작업의 상한만으로 전체 우열을 정하지 않는다.
