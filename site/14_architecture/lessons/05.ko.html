소단원 5.1

명령 fetch·decode·execute

숫자가 들어 있는 기억장치가 어떻게 계산을 시키는 기계가 될까요?

준비 개념과 학습 목표

준비 개념

학습 목표

목적지와 입력이 같을 때 한 경계의 값은 언제 바뀔까?

자체 단일사이클 모형에서 레지스터는 시작 경계의 상태를 읽고 다음 경계에서 허용된 값을 쓴다. x5=7에 addi x5,x5,1을 적용하면 입력은 이전 7이고 출력은 8이다. 다음 경계에서 x5=8이 되며 같은 명령의 입력을 새 8로 되돌려 다시 계산하는 것이 아니다.

lw x5,0(x5)에도 같은 원칙을 적용한다. 시작 x5=64, 유효하고 정렬된 일반 RAM의 M[64]=99면 주소 계산은 64+0이고 읽은 99를 다음 경계에 x5로 쓴다. 목적지가 주소 입력과 같아도 읽는 주소가 99로 바뀌지 않는다. 이 모형은 별도 명령/자료 읽기 포트, 대기와 예외 없음으로 정한다.

기능 단계 이름과 상태 갱신 경계를 분리하면 회로의 현재 신호와 저장 상태를 혼동하지 않는다. 실제 회로의 read-during-write 정책과 지연 조건은 이 단순 경계 모형과 별도로 확인해야 한다.

명령을 찾는 주소

책의 페이지 번호처럼 PC는 읽을 명령의 위치를 정한다. 본 단원의 자체 모형은 RISC-V의 add/addi/lw/sw/beq 의미만 지원하며 모든 명령을 32 비트, 4 바이트로 둔다. 압축 명령·예외·캐시 실패·주소 오류는 제외하고 정상 정렬된 접근만 다룬다. 실제 처리기는 더 많은 경우를 처리해야 한다.

Fetch는 PC를 명령 메모리에 보내 비트열을 얻는 일이다. 다음 순차 주소 후보 PC+4 도 계산한다. 명령 메모리와 데이터 메모리는 별도 포트로 읽을 수 있다고 가정한다. 하나의 포트만 있다면 같은 사이클에 명령과 데이터를 모두 읽는 이 모형이 그대로 성립하지 않는다.

읽고 계산하고 필요하면 기억장치를 이용하기

Decode에서는 명령 종류와 rs1·rs2·rd, 즉시값을 해석하고 레지스터 값을 읽는다. Execute의 ALU는 덧셈뿐 아니라 주소 계산과 비교에도 쓰인다. lw x5,8(x2)는 x2 의 값에 8 을 더해 주소를 얻으므로, ALU 결과 자체가 최종으로 x5 에 들어갈 자료는 아니다.

Memory는 lw에서 계산된 주소의 값을 읽고 sw에서 값을 저장한다. add에는 데이터 메모리 접근이 없다. Writeback은 add의 합이나 lw가 읽은 값을 rd에 쓰는 일이다. sw와 beq는 일반 레지스터에 결과를 쓰지 않는다. 단계 이름이 다섯이라고 해서 언제나 다섯 사이클이 걸리는 것은 아니다.

한 경계의 상태 변화

단일사이클은 위의 논리적 일을 한 클록 간격 안에서 마치는 구현이다. 시작 경계 직후의 PC와 레지스터로 회로가 계산하고, 다음 경계에 쓰기 허용된 상태가 바뀐다. 본 모형의 상태 갱신을 동시에 생각하면 같은 명령의 새 rd 값을 거꾸로 입력에 쓰는 실수를 피할 수 있다.

beq의 두 값이 같으면 다음 PC는 현재 PC+부호 있는 분기 바이트 변위이고, 다르면 PC+4 이다. 여기서 변위는 이미 명령을 해석한 수치로 주며 실제 즉시값 비트 배치나 어셈블러 입력 문법을 설명하는 예제가 아니다. 명령의 뜻과 이를 구현한 회로의 시간표를 구별해야 한다.

중간 과정을 따라가는 예제

자체 정상 접근 모형에서 PC=100, x2=40, M[48]=17 이다. lw x5,8(x2) 한 명령의 단계와 다음 상태를 쓰세요. 기존 x5=99 라고 둡니다.

  1. Fetch: 주소 100 의 lw 명령을 읽고 순차 후보 104 를 계산한다.

  2. Decode: rs1=x2 에서 40 을 읽고 즉시값 8, 목적지 x5 를 정한다.

  3. Execute: 주소는 40+8=48 이다.

  4. Memory: M[48]의 값 17 을 읽는다.

  5. Writeback/경계: x5=17, PC=104 로 갱신한다. x2 와 M[48]은 그대로이다.

최종 x5=17, PC=104. ALU가 얻은 48 은 주소이며 읽은 자료 17 과 구별된다.

종이와 본문으로 직접 해보기

종이에 PC=200 에서 x3=x4=6 인 beq의 분기 변위가 −12 인 경우와 x4=7 로 바꾼 경우를 각각 그리세요. 다른 레지스터 쓰기는 없습니다.

힌트 보기

현재 주소에 변위를 더한 후보와 PC+4 후보를 먼저 따로 계산하세요.

풀이 보기

분기 후보는 200−12=188, 순차 후보는 204 이다. 두 값이 6 이면 비교 참이므로 188, 6 과 7 이면 거짓이므로 204 이다. 두 경우 모두 일반 레지스터 값은 바뀌지 않는다.

오해와 반례

다섯 단계가 있으니 단일사이클도 명령마다 다섯 사이클이다.

단계는 기능의 분해이고 사이클은 구현의 시간 경계이다. 단일사이클은 다섯 기능을 한 간격에 놓는다. 다중사이클은 경계를 더 넣고, 파이프라인은 여러 명령의 단계를 겹친다. 기능 수만으로 CPI를 결정할 수 없다.

포트 하나로 명령과 자료를 동시에 읽을 수 있을까?

자체 단일사이클의 load는 한 클록 간격에 명령 읽기와 자료 읽기를 모두 해야 한다. 명령 메모리와 자료 메모리가 별도 포트이면 두 요구를 그 모형대로 처리할 수 있다. 하지만 한 포트가 한 사이클에 한 요청만 받을 수 있는 메모리라면 두 요청을 같은 사이클에 넣을 수 없다.

자체 명령 200개 중 load/store가 50개이고 나머지는 자료 메모리를 쓰지 않는다고 정한다. 명령 인출은 200회, 자료 접근은 50회라 공유 포트 요청은 250회다. 한 사이클에 한 요청이라는 제한 아래 최소 250개의 포트 서비스 사이클이 필요하므로 200사이클 완료 주장과 충돌한다. 이 수는 실제 CPU 사이클의 실측이나 모든 구현의 정확한 CPI가 아니다.

메모리를 두 번 빠른 내부 위상으로 쓰거나 중간 명령·피연산자를 저장해 다중사이클로 바꾸는 것은 가능한 별도 설계다. 그 경우 포트 서비스 규칙·경계·타이밍이 달라지므로 원래의 한 요청/사이클 모형을 그대로 사용했다고 말할 수 없다.

이름이 붙은 작은 작업 공간

Register file은 번호로 고르는 레지스터들의 묶음이다. 본 모형에는 두 조합 읽기 포트와 한 경계 쓰기 포트가 있다. rs1 과 rs2 를 동시에 읽되 rd와 RegWrite가 다음 경계의 변경 대상을 정한다. 실제 회로의 읽기/쓰기 같은 주소 충돌 시점은 설계마다 달라 이 단원에서는 경계 이전 입력을 사용한다.

RISC-V x0 는 항상 0 이다. x0 를 목적지로 지시해도 저장 상태는 바뀌지 않는다. 다른 레지스터는 프로그램이 만든 값을 유지한다. 레지스터 이름 x2 와 그 안의 숫자 40 은 서로 다른 종류의 정보이다. 이름을 주소 2 라고 생각해 데이터 메모리의 M[2]와 섞으면 안 된다.

ALU 입력을 고르는 길

add는 ALU의 두 입력으로 rs1 값과 rs2 값을 고른다. addi와 load/store 주소 계산은 두 번째 입력에 부호 확장된 즉시값을 고른다. 따라서 ALUSrc라는 선택 신호만 바꾸어 같은 덧셈기를 자료 합과 주소 합에 재사용할 수 있다.

sw는 특히 두 갈래를 가진다. rs1 은 기본 주소, rs2 는 저장할 자료이다. 즉시값은 ALU의 두 번째 입력으로 가지만, rs2 자료는 메모리의 쓰기 입력으로 따로 간다. rs2 를 즉시값으로 대체해 버리면 주소는 맞아도 저장하는 값이 틀린 회로가 된다.

메모리는 주소로 자료를 고른다

lw는 유효 주소에서 32 비트 단어를 읽어 writeback 선택기로 보낸다. sw는 주소와 저장할 32 비트 값 및 쓰기 허용 신호를 함께 사용한다. 정상 정렬된 주소, 한 번에 한 단어, 대기 없는 자체 모형을 전제로 한다. 이 가정은 실제 DRAM이나 캐시 성능 측정이 아니다.

계산 결과와 메모리 읽기 결과를 고르는 writeback 선택기를 둔다. add의 ALU 값과 lw의 메모리 값은 같은 rd 쓰기 포트를 공유하지만 어느 쪽을 선택하느냐가 다르다. 그 연결을 손가락으로 따라가면 load와 store를 단순히 반대 명령이라고 외우는 것보다 정확하게 이해할 수 있다.

  1. sw의 읽기는 x1=64, x2=13 이다. ALU의 두 번째 입력은 즉시값 4 이다.

  2. sw 주소 64+4=68 에 rs2 자료 13 을 써 M[68]=13 으로 바꾼다. x2 는 바뀌지 않는다.

  3. lw는 같은 주소 68 을 계산하고 현재 M[68]=13 을 읽어 x4 에 쓴다.

  4. add는 x4=13 과 x3=5 를 읽어 18 을 계산하고 x5 에 쓴다.

M[68]=13, x4=13, x5=18. sw에서 즉시값 4 는 저장 자료가 아니다.

소단원 5.3

제어신호의 유도

같은 회로가 add와 store를 다르게 행동하도록 만드는 것은 무엇일까요?

준비 개념과 학습 목표

준비 개념

  • 10_digital-logic: 진리표는 입력 조합마다 출력을 정한다.

  • 앞 소단원: ALU 입력 선택과 writeback 선택.

  • beq는 같은지 비교하여 PC 후보를 고른다.

학습 목표

  • 명령 의미에서 제어신호 표를 직접 만든다.

  • dont-care와 위험한 쓰기 신호를 구별한다.

선택 무관 X는 쓰기 허용이 바뀌어도 무관할까?

자체 제어 표에서 sw는 RegWrite = 0이므로 writeback 선택 M이 0이든 1이든 일반 레지스터 쓰기는 없다. 이것이 이 행에서 M을 X로 표시하는 근거다. X는 물리적으로 값이 없거나 마음대로 모든 제어 비트를 바꾸어도 된다는 뜻이 아니다.

오류로 RegWrite = 1이 되면 M 선택이 목적지에 도달해 더는 무관하지 않다. 가상 오류 주입에서 잘못 고른 목적지 x9, ALU 주소 값 68, 자료 읽기 선의 값 99를 별도 관측값으로 주면 M = 0은 x9 = 68, M = 1은 x9 = 99를 만든다. sw 형식의 실제 rd를 뜻하지 않으며 원래 모형의 선택 무관 조건을 깨뜨린 자체 회로 반례다.

따라서 제어 검토에는 바뀌어야 할 상태뿐 아니라 보존되어야 할 상태도 포함한다. 이 단원의 지원 다섯 명령 밖 비트열을 처리하는 명령 유효성·예외 설계는 별도다. 쓰기 금지만으로 모든 불법 명령 처리를 완성했다고 주장하지 않는다.

    RegWrite=0이라는 선택 무관의 조건을 확인한다.

  • writeback의 선택 경로

뜻에서 신호로

데이터 경로는 값이 지나가는 연결이고 제어는 어느 연결을 고르고 상태를 쓸지 결정한다. 자체 표에서 R=RegWrite, S=ALUSrc(0 은 rs2,1 은 즉시값), L=MemRead, W=MemWrite, B=Branch, M=MemToReg(0 은 ALU,1 은 읽은 메모리)로 정한다. 이 비트 이름은 단원 자체 설계 약속이며 모든 실제 CPU의 신호 이름이 아니다.

add는 두 레지스터의 합을 rd에 쓴다. 따라서 R1/S0/L0/W0/B0/M0, ALU=ADD이다. lw는 기본 주소+변위를 만들고 자료를 읽어 rd에 쓴다. 따라서 R1/S1/L1/W0/B0/M1, ALU=ADD이다. 표를 외우기 전에 어떤 값이 어디로 가야 하는지부터 설명해야 한다.

쓰기 금지와 선택 무관

sw는 R0/S1/L0/W1/B0 이고 ALU=ADD이다. rd를 쓰지 않으므로 M은 X, 즉 결과에 영향을 주지 않는 선택 무관 값이다. beq는 R0/S0/L0/W0/B1 이며 ALU=SUB를 사용해 결과 0 여부를 두 값이 같음으로 해석한다. beq의 M도 X이다. X는 신호가 물리적으로 아무 값도 없다는 뜻이 아니라 둘 중 어느 값을 주어도 관측 상태가 같다는 뜻이다.

MemWrite와 RegWrite는 신중하게 정해야 한다. 사용하지 않는 명령에서 허용하면 엉뚱한 메모리나 레지스터가 바뀔 수 있다. 반면 이미 RegWrite=0 인 행의 M은 무관해도 된다. 무관 조건은 그 신호가 통제하는 값이 상태에 도달하지 않는다는 근거로 정해야 한다.

분기 선택은 두 조건의 결합

분기 목표를 고르는 신호는 PCSrc=B AND Equal이다. add의 뺄셈/비교 내부 결과가 우연히 0 이어도 B=0 이면 분기하지 않는다. beq인데 비교 거짓이면 PC+4 로 간다. ALU 연산은 opcode만으로 정하지 않고 같은 연산 종류 안의 세부 기능 비트도 고려해야 한다. 본 표는 지원하는 다섯 명령만을 대상으로 한다.

addi 행은 R1/S1/L0/W0/B0/M0, ALU=ADD로 유도된다. 정의하지 않은 비트열은 새 명령이 아니라 이 자체 모형의 범위 밖이다. 실제 구현에서는 불법 명령 처리와 예외도 설계해야 하며, 빈 표의 칸에 임의 쓰기 허용을 넣는 것은 안전한 확장이 아니다.

소단원 5.4

긴 경로와 성능

쉬운 명령이 빨라도 왜 클록은 가장 느린 명령을 기다릴까요?

준비 개념과 학습 목표

준비 개념

  • 시간 단위: 1ns=1000ps, 주파수는 주기 역수이다.

  • 앞 소단원: load가 명령·레지스터·ALU·자료 읽기·writeback을 거친다.

  • CPU 시간=명령 수×CPI×클록 주기.

학습 목표

  • 경로의 직렬 지연과 병렬 계산을 구별한다.

  • 병목 변경 전후의 프로그램 시간과 속도비를 계산한다.

자료보다 선택 제어가 늦게 오면 어느 경로를 기다릴까?

자체 load의 writeback 선택기에 자료 입력이 시작 경계 뒤 700 ps에, 선택 제어가 800 ps에 안정된다고 정한다. 선택기 지연 30 ps와 목적 레지스터 setup 시간 20 ps를 더한다. 다른 모든 상태 경로는 750 ps 이하이며 배선·skew·clock-to-Q 등은 이 도착 시각에 포함되거나 여기서 제외한다.

이 보수적 모형에서는 필요한 자료와 선택 제어가 모두 안정된 뒤 30 ps가 지나야 선택 출력의 안정성을 보장한다. 따라서 주기 하한은 max(700, 800) + 30 + 20 = 850 ps다. 자료 도착 700 ps만 보고 750 ps 경계를 선택하면 제어 경로가 제때 도달한다는 보장이 없다.

자료 경로만 100 ps 줄여 600 ps로 만들어도 제어 도착 시각 800 ps가 그대로라 주기 850 ps의 제한은 변하지 않는다. 반대로 제어 도착 시각만 650 ps로 줄이면 max(700, 650) + 50 = 750 ps다. 어느 구성요소를 개선했는가보다 전체 도착 시각의 최댓값을 다시 확인해야 한다. 지연 수치는 실제 회로 계측이 아닌 자체 가정이다.

먼저 확인할 개념
  • 긴 경로와 병목 이동

    직렬 합과 병렬 도착의 최댓값을 구별한다.

  • 결과 선택을 정하는 제어

    제어 신호도 타이밍 입력이라는 점을 확인한다.

가장 늦게 도착하는 값

Critical path는 다음 경계에 필요한 신호가 가장 늦게 안정되는 경로이다. 본문의 가상 회로는 명령 읽기 200ps, 레지스터 읽기 100ps, ALU150ps, 자료 메모리 250ps, 결과 선택 30ps, 최종 상태 setup20ps로 둔다. 배선·skew·hold 조건과 별도 제어 지연은 이미 이 가정에 흡수되거나 제외했다고 명시한다. 실제 부품 지연 측정값이 아니다.

lw 결과 경로는 200+100+150+250+30+20=750ps이다. 순차 PC 덧셈처럼 병렬로 먼저 끝나는 일을 다시 직렬 합에 넣지 않는다. 이 가상 설계의 다른 모든 상태 경로는 750ps 이하라고 가정하면 최소 안전 주기는 750ps, 최고 주파수는 1/(750×10⁻¹²)≈1.333GHz이다. 실제 설계에서는 다른 경로도 확인해야 한다.

짧은 명령도 같은 경계를 쓴다

단일사이클의 CPI는 정상 명령마다 1 이다. add의 회로가 500ps에 끝나도 주기가 750ps라면 다음 명령은 같은 경계 간격을 따른다. load 비율이 적다는 이유만으로 임의 명령마다 클록을 짧게 바꾸는 것은 여기의 고정 클록 단일사이클 모형과 다르다.

1000 개 명령이면 CPU 시간은 1000×1×750ps=750ns이다. 비교용 다중사이클 설계가 주기 250ps, 같은 프로그램에서 평균 CPI3.6 이면 시간은 900ns이다. 클록이 세 배 빠르다는 한 사실만으로 전체 프로그램이 빠르다고 할 수 없다. 명령 수와 CPI도 함께 비교해야 한다.

개선의 범위를 계산한다

자료 메모리만 250ps에서 150ps로 줄이면 load 경로는 650ps가 된다. 다른 경로가 모두 650ps 이하인 조건에서 1000 개 명령 시간은 650ns이고 속도비는 750/650=15/13≈1.154 이다. 지연 100ps 감소가 프로그램 속도 100% 증가라는 뜻은 아니다.

ALU만 150ps에서 100ps로 줄이는 별도 개선은 load700ps, 프로그램 700ns, 속도비 15/14≈1.071 이다. 어느 경로가 새 병목인지 다시 확인해야 하며 두 개선을 동시에 했다면 다시 합산해야 한다. 전력·면적·메모리 대기와 파이프라인 처리량은 이 단순 계산에서 검증되지 않는다.
