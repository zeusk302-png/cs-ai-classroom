소단원 11.1

피드백 질문

좋아요라는 답 대신 다음 수정에 쓸 수 있는 의견을 어떻게 부탁할까?

준비 개념과 학습 목표

준비 개념

  • 글의 대상 독자
  • 주장과 근거
  • 질문

학습 목표

  • 검토 범위와 원고 버전을 지정한다.
  • 독자의 이해를 확인하는 질문을 만든다.
  • 관측과 수정 제안을 구별한다.

원고의 목적부터 공유한다

검토자에게 대상 독자와 글의 목적, 아직 미완성인 부분을 알려 준다. 초등학생에게 배열을 소개하는 초안과 전공자에게 알고리즘 증명을 제시하는 초안은 필요한 설명이 다르다. 버전과 읽을 범위를 정하면 서로 다른 글을 보고 대화하는 혼선을 줄인다.

좋은가요라는 질문 하나로는 사실 오류와 문장 취향을 구별하기 어렵다. 지금 결정해야 할 항목을 좁혀 질문한다. 예를 들어 두 번째 문단에서 배열의 시작 위치가 무엇인지, 예제에서 주소와 값의 차이가 드러나는지를 묻는다.

독자가 이해한 것을 먼저 듣는다

독자에게 주장을 자신의 말로 요약하고 막힌 위치를 표시하도록 요청할 수 있다. 저자의 의도를 질문에 미리 넣어 정답을 유도하면 실제로 이해한 내용인지 확인하기 어렵다. 답이 기대와 다르면 먼저 어떤 표현을 근거로 읽었는지 확인한다.

관측은 독자가 실제 읽은 뜻이나 멈춘 위치다. 제안은 문단 이동이나 예제 추가 같은 해결안이다. 관측에 동의하면서 제안은 다른 방식으로 반영할 수 있다. 사실 질문은 출처와 계산으로, 이해 질문은 독자의 해석으로 확인한다.

요청과 답변을 대응시킨다

자체 검토 계획은 Q1 주장 요약, Q2 모호한 위치, Q3 수치 검산을 세 항목으로 정한다. 답변 수보다 필요한 항목에 답이 있는지를 확인한다. 같은 항목에 여러 답이 와도 다른 빈 항목이 채워지지는 않는다.

의견이 모호하면 단어의 뜻이나 근거를 추가로 물을 계획을 세운다. 검토자가 답하지 않은 질문은 미응답으로 남긴다. 이 자료의 응답은 가상 장부이며 실제 학습자에게 요청하거나 독자 실험을 수행한 기록이 아니다.

중간 과정을 따라가는 예제

계획 Q1/Q2/Q3에 가상 답변이 Q1 두 개, Q2 한 개, Q3 없음이다. 답변 수와 항목 응답률을 계산하라.

  1. 총 답변은2+1=3개다.
  2. 응답된 서로 다른 질문은Q1/Q2 두 개다.
  3. 항목 응답률은2/3≈66.7%며 Q3 검산은 남아 있다.

답변3개라도 세 항목이 모두 검토된 것은 아니다. Q3에 별도 응답을 요청할 계획이 필요하다.

힌트 보기

이해를 요약하거나 구체적 예제의 해석을 묻는다.

풀이 보기

예: 예제에서 인덱스와 저장 값이 각각 무엇을 뜻하는지 설명해 주세요. Q3 답 추가 후 총 답변4개·응답 항목3개로3/3=100%다. 정확성 통과율은 별도이며 응답률만으로 정할 수 없다.

오해와 반례

의견이 많으면 모든 오류가 발견된 것이다.

응답 수는 검토 범위나 정확성을 보장하지 않는다. Q1 의견만 여러 개일 수 있고 답 자체도 틀릴 수 있다. 질문 대응과 근거를 함께 확인한다.

소단원 11.2

내용·구조·문장 수정

띄어쓰기만 고쳐도 잘못된 결론이 바로잡힐까?

준비 개념과 학습 목표

준비 개념

  • 주장과 근거
  • 문단
  • 백분율

학습 목표

  • 수정 문제를 내용·구조·문장으로 분류한다.
  • 근거와 계산을 먼저 검증한다.
  • 수정 후 논리와 표현을 다시 확인한다.

주장과 근거가 맞는지 검사한다

내용 수정은 사실, 계산, 정의, 조건과 결론을 다룬다. 자체 초안은 기존100건과 새125건을 비교하며 증가율이20%라고 적었다고 하자. 기준값100에서25가 늘었으므로25%이며 문장을 매끈하게 고쳐도 수치 오류는 남는다.

자료가 관측인지 교육 가정인지도 확인한다. 실제 측정하지 않은 값을 실험 결과로 바꾸면 글이 읽기 쉬워져도 근거가 훼손된다. 수정하면서 표의 숫자, 본문의 주장, 단위와 기간이 모두 맞는지 대조한다.

독자의 이해 순서를 다시 짠다

구조 수정은 정보 배치와 문단 역할을 바꾼다. 기준값을 설명하기 전에 증가율 결론을 제시하면 독자가 분모를 모를 수 있다. 자체 예에서는 목적→기준과 새 값→계산→해석과 한계의 순서로 재배치한다.

문단을 옮길 때 연결어와 앞의 예제 같은 지시어도 함께 확인한다. 옮긴 설명의 조건이 결론보다 늦게 나오거나 표 번호가 이전 위치를 가리키면 새 혼선이 생긴다. 모든 글이 이 순서를 따라야 하는 것은 아니며 목적과 독자에 맞게 판단한다.

문장 수정 후 의미를 지킨다

문장 수정은 모호한 주어, 불필요한 반복, 긴 표현과 맞춤법을 다룬다. 예를 들어 그것이 증가했다 대신 처리 건수가 증가했다라고 쓰면 대상이 분명해진다. 짧게 만들기 위해 기준값이나 가정까지 삭제하면 정확성을 잃을 수 있다.

큰 수정 후에는 전체 글을 다시 읽고 마지막에 문장과 표기를 점검한다. 한 번에 모든 문제를 고칠 수 있다고 가정하지 않는다. 이 절에서는 가상 초안을 고칠 뿐 실제 독자의 이해 개선을 측정하지 않는다.

중간 과정을 따라가는 예제

초안의125 대100 증가율20%, 계산 전에 결론이 나온 배치, 그것이 좋아졌다는 표현을 각각 수정하라.

  1. 내용: (125−100)/100=25%로 바꾸고 기준을 명시한다.
  2. 구조: 비교 조건과 두 값을 먼저 보여 준 뒤 계산과 해석을 둔다.
  3. 문장: 처리 건수가25% 늘었다로 대상을 밝히며 좋다는 평가에는 다른 품질 조건도 필요하다고 적는다.

세 수정은 다른 문제를 다룬다. 처리 건수 증가는 오류율이나 학습 효과의 개선까지 증명하지 않는다.

종이와 본문으로 직접 해보기

새 값이100이고 기존값이125라면 감소율을 계산하라. 다시25% 감소라고 쓰면 왜 틀리는가?

힌트 보기

이번 분모는 기존125다.

풀이 보기

(125−100)/125=20% 감소다. 같은 차이25라도 기준이 달라 증가25%와 감소20%가 된다. 문장에 기준125를 남겨 분모를 숨기지 않는다.

오해와 반례

표현을 짧게 만들면 모든 수정이 끝난다.

계산과 주장, 조건, 정보 순서가 틀리면 짧은 문장도 틀리다. 내용과 구조를 확인한 뒤 문장을 다듬고 다시 의미가 보존됐는지 점검한다.

자기점검

100→125의 증가율은?

답과 이유 보기

25%다.

증가량25를 기존100으로 나눈다.

문단 이동 후 표 지시어를 점검하는 이유는?

답과 이유 보기

참조가 잘못된 위치를 가리킬 수 있어서다.

구조 변화가 연결과 참조에도 영향을 준다.

가상 수치를 실측 결과라고 바꾸면 문장 수정인가?

답과 이유 보기

근거를 훼손하는 내용 변경이다.

수행하지 않은 실험을 했다고 주장할 수 없다.

한 단계 더

기존0에서 새5가 된 자체 예의 상대 증가율을 계산할 수 있는지 확인하라. 분모0이라 보통 정의로 계산할 수 없다. 건수5 증가를 보고하되 임의로500%라 쓰지 않는 수정안을 작성하라.

소단원 11.3

변경 이유 기록

나중의 검토자가 무엇을 왜 고쳤는지 어떻게 확인할까?

준비 개념과 학습 목표

준비 개념

  • 원고 버전
  • 검토 의견
  • 근거와 상태

학습 목표

  • 의견별 결정과 근거를 기록한다.
  • 변경 여부와 검증 여부를 구분한다.
  • 새 수정 뒤 재검토 범위를 정한다.

의견에서 결정까지 연결한다

변경 장부에는 의견 식별자, 원고 버전과 위치, 지적 내용, 결정, 실제 변경, 이유와 확인 상태를 적는다. 모든 제안을 그대로 채택하는 대신 대상 독자와 근거를 보고 판단한다. 반영하지 않은 의견도 이유를 남기면 이후 논의를 이어갈 수 있다.

자체 상태는 채택·보류·불채택의 결정과 수정 전·수정됨·확인됨의 작업 상태를 분리한다. 채택했다고 즉시 수정이 완료된 것이 아니며 수정됐다고 검산까지 끝난 것도 아니다. 검토 대화를 닫는 표시는 실제 확인 증거를 대신하지 않는다.

전후 차이와 이유를 보존한다

수치 수정은 이전20%와 이후25%, 이유가 기준100의 계산 오류임을 함께 기록한다. 단순 수정함이라는 한 줄보다 어떤 주장과 근거가 연결되는지 보인다. 문단 이동은 읽기 순서의 이유와 관련 참조 점검을 기록한다.

버전 비교는 변경 위치를 보여 주지만 변경의 정당성을 자동 증명하지 않는다. 원고 v1을 검토한 결과는 변경된 v2의 모든 문장 검토를 뜻하지 않는다. 특히 수치·조건·코드·출처가 달라졌으면 관련 예제와 문답을 다시 확인한다.

완료와 남은 일을 명시한다

자체 장부에서 의견 네 개를 받아 두 개를 채택, 하나를 보류, 하나를 불채택했다면 결정 네 개와 실제 수정 수를 별도로 셀 수 있다. 보류 항목의 필요한 근거와 다음 확인을 적어 숨기지 않는다.

변경 이유는 저자를 변호하기 위한 기록이 아니라 다음 독자가 판단할 근거다. 개인정보나 비공개 자료를 장부에 불필요하게 복사하지 않는다. 이 절에서는 로컬 가상 표만 작성하며 외부 GitHub 댓글이나 원고 제출을 실제 수행하지 않는다.

중간 과정을 따라가는 예제

가상 장부 F1 수치 수정 채택·수정됨, F2 문단 이동 채택·수정됨, F3 새 실험 보류·미수정, F4 정의 삭제 불채택·미수정이다. F1만 재검산 확인됨일 때 결정·수정·확인 수를 구하라.

  1. 의견4개 모두 결정은 기록됐다. 채택2·보류1·불채택1이다.
  2. 실제 수정은 F1/F2 두 개다. 확인 완료는 F1 하나다.
  3. 채택 항목 중 확인 비율은1/2=50%다. 전체 의견 대비 확인1/4=25%와 분모가 다르다.

결정4, 수정2, 확인1이다. F2의 참조 점검은 남아 있으며 F3 실험을 수행했다고 표시하지 않는다.

F1이 원자료의 값125를150으로 잘못 옮긴 새 오류를 발견했다고 하자. 원자료가 여전히125라면 v3에서125와 증가율25%를 복구하고 잘못 옮긴 경위를 기록한다. 별도로 원자료가150으로 갱신됐다는 근거를 확인한 경우에만100→150의 증가율50%로 수정한다. 비교 도구가 바뀐 숫자를 표시하는 것과 그 숫자의 정당성 검증을 구별하라.
