소단원 12.1

벤치마크와 오염

이미 본 시험 문제를 잘 맞힌 성적은 새로운 질문에서도 같은 실력을 뜻할까?

준비 개념과 학습 목표

준비 개념

  • 훈련·검증·평가 자료의 역할

  • 분수와 가중 평균

  • 텍스트 입력과 출력

학습 목표

  • 평가 대상과 조건을 기록한다.

  • 오염 의심 부분과 나머지 성적을 분리한다.

  • 하나의 점수로 모든 능력을 보장할 수 없음을 설명한다.

무엇을 시험하는지 먼저 고정한다

벤치마크는 정해진 자료·과제·평가 규칙으로 시스템을 비교하는 절차다. 질문 답변, 번역, 요약은 요구하는 정답과 지표가 다르다. 같은 과제도 문서 종류·작성 시기·언어가 달라지면 평가 범위가 달라진다.

모델 이름만 적으면 재현이 어렵다. 버전과 평가 시점, 입력 프롬프트, 제공한 참고 자료, 출력 길이 제한, 정답 판정 규약을 함께 기록한다. 검색을 붙인 시스템과 모델 단독 결과도 서로 다른 조건이다. 정확도와 시간·오류 종류 같은 지표를 목적에 맞게 나누어 본다.

평가 자료가 선택이나 학습에 들어갔는지 묻는다

평가 오염은 최종 시험에 사용할 자료가 훈련이나 조정·선택 과정에 노출되어 독립적인 새 문제 평가라는 해석을 약화시키는 문제다. 똑같은 문장뿐 아니라 같은 내용의 변형이나 관련 자료도 영향을 줄 수 있다. 평가 정답을 프롬프트에 넣고 답하게 하는 것도 원래 의도한 조건을 바꾼다.

학습 자료를 알 수 없는 경우에는 미노출이라고 확정할 수 없다. 확인된 중복, 의심, 정보 없음은 다른 상태다. 중복 탐지는 유용하지만 문자열이 다르다는 사실만으로 의미 중복이나 다른 노출 경로가 없다고 증명하지 못한다. 공개 시점과 자료 출처도 기록한다.

점수의 분모와 한계를 공개한다

일부 자료가 노출되었다고 의심되면 전체 점수와 해당 부분 및 나머지 점수를 함께 보고한다. 나머지를 단순히 완전히 깨끗한 자료라고 부르지 않는다. 제외 규칙을 결과를 보기 전에 정하는 것이 선택적인 유리한 제외를 줄인다.

아래 숫자는 직접 만든 가상 정답 표다. 실제 모델이나 공개 벤치마크를 실행하지 않았다. 남은 자료 점수도 그 자료 범위의 관찰값이지 전 세계 학생의 질문이나 모든 언어 능력에 대한 보증이 아니다. 평가가 빠진 영역을 적는 것 역시 결과의 일부다.

중간 과정을 따라가는 예제

자체 가상 시험 100문항 중 노출 확인 20문항에서 19개, 나머지 80문항에서 48개를 맞혔다. 전체와 두 부분 정확도를 구하라.

  1. 전체 정답 수는 19+48=67이므로 67/100=67%다.

  2. 노출 확인 부분은 19/20=95%, 나머지는 48/80=60%다.

  3. 전체 67%는 (20/100)×95%+(80/100)×60%다. 이 표만으로 노출의 인과 효과나 나머지의 미노출을 확정하지 못한다.

전체 67%, 노출 확인 부분 95%, 나머지 60%다. 각 분모와 노출 정보의 한계를 함께 보고한다.

종이와 본문으로 직접 해보기

평가 자료 50개 중 중복 의심 10개에서 9개, 나머지 40개에서 24개를 맞혔다. 전체 성적과 의심 부분을 제외한 성적을 적고 해석의 한계를 쓰라.

힌트 보기

맞힌 수의 합을 먼저 구하고, 제외한 뒤 분모도 바뀌는지 확인한다.

풀이 보기

전체 33/50=66%, 나머지 24/40=60%다. 의심 부분은 9/10=90%다. 의심은 확인된 학습 노출과 다르며 나머지에 다른 오염이 없다는 증명도 아니다.

오해와 반례

중복 검색 결과가 0이면 평가 자료가 훈련에 없었다고 확정한다.

검색 범위와 표현 차이, 비공개 자료를 알 수 없을 수 있다. 확인되지 않음과 존재하지 않음을 구별한다.

자기점검

전체 정답 수를 나머지 80으로 나누어도 되는가?

답과 이유 보기

안 된다.

67개는 100개 전체의 정답 수다. 나머지의 정답 수는 48개다.

평가 자료로 여러 프롬프트를 고른 뒤 같은 자료 성적을 독립 결과라 하는가?

답과 이유 보기

그렇지 않다.

선택에 자료가 쓰였으므로 독립 최종 평가 역할을 구별해야 한다.

번역 점수가 높으면 요약도 잘한다고 확정하는가?

답과 이유 보기

아니다.

과제와 판정 규칙 및 자료 영역이 다르다.

한 단계 더

노출 부분과 나머지의 난도가 다를 수도 있다. 같은 시스템을 노출 유무만 바꾸어 비교한 실험이 아니므로 95%−60%=35 퍼센트포인트(%p)를 노출이 만든 인과 효과라고 부르지 않는다. 새 평가 집합을 만들더라도 이미 알려진 사실·변형 중복·선택 사용 여부를 다시 점검한다.

출처와 확인 범위

    실제 16–33행의 시나리오·다중 지표·불완전성 및 52–54행의 적응 전략과 사람 평가 설명을 읽었다. 2022년 결과를 현재 모델 순위로 사용하지 않았다.

  • Liang et al. — Holistic Evaluation of Language Models

소단원 12.2

편향·환각·개인정보

자연스러운 설명과 진짜 근거가 있는 설명은 어떻게 구별할까?

준비 개념과 학습 목표

준비 개념

  • 주장과 근거의 구별

  • 비율과 집단별 분모

  • 가상 자료와 실제 자료

학습 목표

  • 근거가 지지하는 주장과 모순·미기재를 구별한다.

  • 집단별 오류를 전체 평균과 함께 확인한다.

  • 개인정보를 오류 재현 자료에 그대로 복사하지 않는다.

유창함은 사실의 증명이 아니다

환각이라고 부르는 오류에는 그럴듯하지만 사실과 다르거나 입력 근거에 어긋나는 생성 내용이 포함된다. 사실 안내를 요구하는 과제와 의도적으로 이야기를 만드는 과제는 판정 목적이 다르다. 설명의 말투나 자신감만으로 진위를 판단하지 않는다.

근거 문장을 읽고 주장을 하나씩 대조한다. 근거가 직접 지지함, 근거와 모순됨, 근거에 없음은 서로 다르다. 근거에 없다는 것만으로 세상에서도 거짓이라고 확정하지 않는다. 링크가 있다는 사실보다 실제 내용이 해당 주장을 뒷받침하는지 확인한다.

평균 뒤에 숨는 차이를 본다

전체 정확도가 높아도 언어·문체·사용 조건에 따라 오류가 몰릴 수 있다. 같은 평가 규칙과 각 집단의 표본 수를 적고 결과를 나누어 살핀다. 평가 집단은 사람의 우열을 표시하는 이름이 아니라 시스템이 어떤 조건에서 어려움을 보이는지 조사하는 기준이다.

집단 차이 하나만으로 그 원인이나 모든 차별을 증명하지 못한다. 과제 난도·자료 범위·번역 품질 같은 다른 조건을 함께 점검해야 한다. 반대로 전체 평균이 같다고 모든 집단의 문제가 해결된 것도 아니다. 피해 가능성과 오류 빈도는 관련되지만 같은 숫자는 아니다.

재현 기록도 정보 노출 경로가 될 수 있다

입력·생성 결과·학습 자료·로그에 개인을 알아볼 수 있는 정보가 들어갈 수 있다. 이름을 가렸더라도 다른 세부 내용의 조합이 개인을 드러낼 수 있다. 정확한 추론과 틀린 개인 추론 모두 문제를 일으킬 수 있으므로 오류 보고에 실제 친구의 사적 내용을 쓰지 않는다.

이 단원은 직접 만든 도서관 안내와 가상 표만 사용한다. 공개 기록에는 최소한의 합성 사례를 쓰고 재현에 필요 없는 연락처·계정·사적 문서를 제외한다. 삭제나 가림만으로 완전한 익명성을 인증하지 않으며 실제 사람의 민감 정보를 넣어 모델을 시험하지 않는다.

중간 과정을 따라가는 예제

가상 안내 원문은 “가상 도서관은 월요일에 닫고 화요일에는 10시에 연다”뿐이다. 답변의 세 주장 “월요일 휴관”, “화요일 9시 개관”, “수요일 무료 강좌”를 근거와 대조하라.

  1. “월요일 휴관”은 원문이 지지한다.

  2. “화요일 9시 개관”은 명시된 10시와 모순된다.

  3. “수요일 무료 강좌”는 원문에 없다. 원문만으로 실제 존재나 부재를 확정할 수 없다.

지지 1개, 모순 1개, 미기재 1개다. 세 범주는 본문의 판정 규약이며 실제 모델 출력이 아니다.

종이와 본문으로 직접 해보기

가상 A 조건 80개에서 72개, B 조건 20개에서 10개를 맞혔다. 전체 정확도와 조건별 정확도 및 같은 비중으로 평균한 값을 구하라.

힌트 보기

실제 표본 수로 합한 평균과 두 조건을 같은 비중으로 본 평균을 나눈다.

풀이 보기

전체는 82/100=82%다. A는 90%, B는 50%, 같은 비중 평균은 (90+50)/2=70%다. 분모와 가중 규칙이 달라 값이 다르며 이 차이만으로 원인이나 전체 피해를 확정하지 못한다.

오해와 반례

출처 링크와 자신감 있는 문장이 있으면 사실 확인이 끝난다.

링크 내용이 실제 주장을 지지하는지 확인해야 한다. 생성된 인용이나 설명도 오류가 있을 수 있다.

한 단계 더

가상 답변이 “안내에 수요일 정보가 없어 확인할 수 없다”라고 답하면 미기재 상태를 드러낸다. 하지만 모든 질문에 무조건 모른다고 답하는 시스템도 유용성 문제가 있다. 답변 가능한 수, 그중 맞힌 수, 전체에서 못 답한 수를 별도로 세어 정확도와 답변 범위를 함께 평가하자.

  • 문자 정규화와 의미 판정을 구별한다.

  • 개인정보 없는 한국어 오류 재현 기록을 만든다.

번역된 자료도 대표 범위가 있다

다국어 평가는 언어 이름을 늘리는 것만으로 완성되지 않는다. 같은 의미의 입력과 동등한 평가 기준을 준비하고 번역의 누락·부정·숫자·존댓말 차이를 살핀다. 언어마다 과제 난도나 자료 영역이 다르면 점수 차이를 언어 자체의 원인으로 단정하지 않는다.

FLORES-101의 공개 초록은 영어 Wikipedia에서 뽑은 문장의 전문 번역과 언어 간 정렬을 설명한다. 정렬된 번역 벤치마크는 유용하지만 한국어 대화·교과서·방언·모든 연령의 질문을 대표하지 않는다. 번역 과제의 성적을 일반 질문 답변 성적으로 바꾸지 않는다.

보이는 글자와 저장 표현 및 의미를 구별한다

문자열 일치는 정해진 문자 규칙 아래 비교한다. Unicode에서 같은 한글 음절이 완성형 한 문자와 분해된 자모로 저장될 수 있다. NFC 같은 정규화는 정규적으로 같은 문자 표현을 맞추지만 뜻을 이해하거나 번역하는 방법은 아니다.

“제출하지 않아도 된다”와 “제출해야 한다”는 부정과 의무의 뜻이 다르다. 글자 유사도만으로 이 오류를 통과시키면 안 된다. 반대로 의미 평가에서 자연스러운 다른 표현을 허용할지, 정확히 같은 문자열을 요구할지는 과제의 판정 규칙에 먼저 적는다.

작게 재현하고 조건을 기록한다

오류 보고에는 과제·언어·버전·시점·최소 입력·기대 결과·실제 관찰·판정 이유를 적는다. 모델을 실행하지 않았다면 실제 관찰 대신 자체 가상 사례라고 표시한다. 임의의 예시를 실제 사용자 보고로 꾸미지 않는다.

공개 보고에는 실제 학생의 이름이나 사적 원문을 넣지 않는다. 다른 사람이 따라 해도 같은 문제를 판단하도록 프롬프트와 자료 조건을 남기되 민감한 값을 합성 내용으로 바꾼다. 수정 뒤 같은 사례의 통과와 다른 사례의 회귀 여부는 각각 시험해야 하며 아래는 종이 계산뿐이다.

중간 과정을 따라가는 예제

가상 영어 문제 20개 중 18개, 한국어 문제 10개 중 8개를 맞혔다. 전체 표본 정확도와 언어에 같은 비중을 준 평균을 구하라.

  1. 영어 정확도는 18/20=90%, 한국어는 8/10=80%다.

  2. 전체는 (18+8)/(20+10)=26/30=13/15로 약 86.67%다.

  3. 언어 같은 비중 평균은 (90+80)/2=85%다. 두 평균은 가중 규칙이 다르며 같은 것을 측정하지 않는다.

전체 약 86.67%, 언어 같은 비중 평균 85%다. 언어별 분모와 90%·80%를 함께 기록한다.

종이와 본문으로 직접 해보기

가상 과제는 의무 여부를 예/아니오로 판정한다. 입력은 “초안은 제출하지 않아도 된다”인데 가상 출력이 “예, 반드시 제출해야 한다”다. 공개 오류 보고의 최소 입력·기대·관찰·이유를 쓰라.

힌트 보기

제출이 허용되는지와 제출 의무가 있는지를 구별한다. 실제 모델을 실행한 기록처럼 쓰지 않는다.

풀이 보기

과제: 제출 의무 판정, 언어: 한국어, 최소 입력: 제시 문장, 기대: 아니오(의무 없음), 가상 관찰: 예(반드시 제출), 이유: 부정·의무 의미가 뒤집힘. 모델 버전·시점은 미실행이라 해당 없음이라고 적는다. 제출 금지라는 뜻으로 확대하지 않는다.

오해와 반례

NFC 정규화를 하면 한국어의 부정과 존댓말 뜻도 자동으로 평가된다.

정규화는 문자 표현의 대응이다. 의미 보존과 과제 정답 여부는 별도 기준으로 평가한다.

한 단계 더

완성형 “가”(U+AC00)와 분해 자모 U+1100·U+1161은 원래 코드 포인트 수가 1과 2지만 두 문자열에 NFC를 적용하면 같은 “가”가 된다. 이는 자체 Unicode 함수로만 확인했다. “학교”와 “학교에”, 띄어쓰기 변화나 다른 존댓말은 이 한글 조합 규칙만으로 동등 의미라고 판정할 수 없다. 허용할 정답 표현과 정규화 규칙을 별도로 공개하자.

출처와 확인 범위
  • Goyal et al. — Flores-101

    실제 ACL 초록의 3001개 Wikipedia 문장, 전문 번역 및 101개 언어 정렬 설명을 읽었다. 논문 전체나 데이터셋을 실행하지 않았고 한국어의 모든 용도를 대표한다고 하지 않았다.

  • Python 3.12 — unicodedata

    실제 56–68행의 NFC/NFD와 호환 정규화 설명을 읽었다. 본문의 가/분해 자모 사례는 자체 Unicode 정규화 확인만 수행했으며 NLP 모델을 실행하지 않았다.

  • NIST AI 600-1 — Generative AI Profile

    실제 PDF 물리 10–12쪽의 confabulation, 개인정보 노출·추론, 집단·언어별 성능 차이와 harmful bias 본문을 읽었다. 이론적 위험 구분에 활용했으며 법률 준수 인증이나 실제 모델 평가를 수행하지 않았다.

    실제 16–33행의 시나리오·다중 지표·불완전성 및 52–54행의 적응 전략과 사람 평가 설명을 읽었다. 2022년 결과를 현재 모델 순위로 사용하지 않았다.
