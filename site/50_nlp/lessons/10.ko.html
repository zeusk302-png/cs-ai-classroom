가운데 가중치를 동결하면 앞쪽으로 가는 미분도 사라지나요?

각 예제와 과제는 별도 초기 상태에서 시작한다. 자체 스칼라 연쇄는 z=ca, 예측 ŷ=hz, 목표 y=1, 손실 L=(ŷ−1)²/2다. 처음 a=1, c=3, h=1이고 가운데 c만 동결한다. a와 h는 학습하며, 두 값을 같은 초기 기울기로 동시에 갱신하는 순수 SGD의 학습률은 1/12다. momentum·weight decay·이전 기울기·다른 상태는 없다.

초기 예측은 3이고 오차는 2다. a에 대한 미분은 2hc=6이고 h에 대한 미분은 2ca=6이다. c의 값은 고정되지만 a가 변하면 z도 변하므로, 앞쪽 a를 학습하려면 c를 통과하는 연쇄 미분이 필요하다. 두 학습 값을 동시에 1/2로 바꾸면 예측은 3/4이고 손실은 1/32다. c는 여전히 3이다.

별도 비교에서는 z 계산을 기록하지 않고 그 결과 3을 상수로 취급한다. 이 경우 a로 가는 경로는 끊기며 h만 1/2로 갱신된다. 갱신 후 같은 수식의 순전파 예측은 3/2이고 손실은 1/8이다. 이는 동결과 기록 중단이 다른 학습을 만든다는 종이 계산이다. 이 스칼라 모형에는 dropout·BatchNorm이 없어 평가 모드라는 이름만 붙여도 함수가 바뀌지 않는다. 실제 라이브러리나 optimizer를 실행하지 않는다.

사전학습 가중치에서 새 작업 학습을 시작한다

미세조정은 사전학습된 가중치를 출발점으로 작업 데이터의 손실을 줄이는 추가 학습이다. 문장 분류라면 사전학습 표현 위에 분류 head를 붙일 수 있고, 생성 모델이라면 특정 형식의 다음 토큰을 학습할 수 있다. 처음부터 모든 가중치를 무작위로 다시 학습하는 것과 출발점이 다르다.

전체 미세조정은 선택한 모델의 모든 학습 파라미터를 갱신한다. 부분 미세조정은 일부 층이나 head만 갱신한다. 동결된 가중치도 순전파 계산에는 사용한다. 새 데이터가 작거나 도메인이 다른 상황에서 어느 범위가 좋은지는 검증 자료로 비교해야 한다.

동결은 가중치 업데이트를 막는 설정이다

PyTorch에서 파라미터의 requires_grad_(False)는 그 leaf 파라미터의 기울기 누적을 막는다. 이전 학습의 잔여 기울기를 지우고 optimizer가 갱신할 파라미터 목록도 확인하는 절차가 필요하다. 학습 앞뒤의 동결 가중치가 실제 같은지도 확인한다.

eval()은 dropout이나 BatchNorm처럼 학습/평가에서 다른 동작을 하는 모듈의 모드를 바꾸며 기울기 동결 자체가 아니다. no_grad는 그 구간의 연산 기록을 막는 별도 설정이다. 학습할 head까지 no_grad 안에 넣으면 필요한 기울기를 얻지 못할 수 있다. 동결된 층을 통과해 더 앞의 학습 가능한 파라미터로 가는 기울기가 필요한 구조도 있으므로 모든 동결 연산을 무조건 제거한다고 생각하지 않는다.

파라미터 비율은 성능이나 전체 메모리 비율이 아니다

학습 가능한 파라미터 수를 세면 어떤 부분을 갱신했는지 보고할 수 있다. 그래도 기본 모델 가중치와 활성값, 배치·길이, optimizer 상태 등의 비용이 따로 있어 학습 파라미터 20%라는 말이 GPU 메모리 20%를 뜻하지 않는다.

작업별 검증 성능과 기존 작업 성능을 함께 비교해 새 작업의 개선과 기존 능력 손실을 살핀다. 시험 데이터로 동결 범위·학습률을 반복 선택하면 최종 시험의 의미가 약해진다. 중복 문장이나 같은 문서의 가까운 조각이 학습/시험에 섞이지 않도록 분할 단위를 결정한다.

중간 과정을 따라가는 예제

사전학습 표현기 파라미터 12개를 동결하고 head의 w1,w2,b 세 개만 학습한다. 한 문장의 고정 특징 z=(1,2), 목표 y=1이다. ŷ=w·z+b, L=(ŷ−y)²/2, 초기 w=b=0, 학습률 .1의 한 업데이트를 손으로 계산하라.

  1. 총 파라미터는 12+3=15, 학습 가능한 것은 3이므로 20%다. 이는 자체 작은 모형의 개수다.

  2. 초기 ŷ=0, 오차 ŷ−y=−1이고 L=1/2다.

  3. 기울기는 ∂L/∂w=(−1,−2), ∂L/∂b=−1이다. 표현기는 동결해 갱신하지 않는다.

  4. 새 w=(.1,.2), b=.1이다. 같은 특징에 ŷ=.1·1+.2·2+.1=.6이다.

  5. 새 L=(.6−1)²/2=.08이다. 한 표본 손실 감소를 전체 문장 분류 성능 향상으로 일반화하지 않는다.

head만 한 번 갱신해 예측 .6, 손실 .08이다. 표현기 12개는 그대로이며 학습 파라미터 비율은 20%다.

동결된 가운데를 통과하는 경로

c만 동결했을 때 초기 미분과 한 번의 동시 갱신 결과를 구하라.

  1. 오차는 3−1=2다. ∂L/∂a=2·1·3=6이고 ∂L/∂h=2·3·1=6이다.

  2. a와 h는 각각 1−6/12=1/2가 된다. c는 3으로 유지한다.

같은 응답 데이터도 어떤 위치와 분모를 선택하느냐에 따라 손실이 바뀌나요?

자체 가상 목표 위치는 순서대로 [P,A₁,U,A₂,EOS,PAD]다. P와 A₁과 U는 문맥에 포함된 앞 대화이고 A₂와 EOS가 이번 completion이다. 이미 다음 토큰 예측과 정답을 정렬한 목표 위치이므로 여기서 다시 한 칸 이동하지 않는다. completion 마스크는 [0,0,0,1,1,0], assistant 마스크는 [0,1,0,1,1,0]이다. 유효 문맥 표시에서는 PAD만 제외한다. 이는 실제 tokenizer 출력이 아닌 직접 정의한 위치 모형이다.

주어진 정답 확률은 A₁이 1/2, A₂가 1/4, EOS가 1/2다. completion만 학습하면 손실 합은 3ln2이고 목표 두 개의 평균은 (3/2)ln2다. assistant 위치 전부를 학습하면 앞 응답 A₁도 포함되어 합은 4ln2이고 평균은 (4/3)ln2다. 두 마스크를 함께 요구하는 교집합에서는 이번 completion의 A₂와 EOS만 남는다. 손실 제외는 문맥 삭제를 뜻하지 않는다.

별도 집계 사례 A에는 유효 목표 두 개와 손실 합 3ln2가 있고 B에는 유효 목표 여섯 개와 손실 합 6ln2가 있다. 토큰을 같은 가중으로 두는 전체 평균은 (9/8)ln2다. 두 사례 평균을 같은 가중으로 두면 (5/4)ln2다. optimizer 갱신 없이 같은 주어진 손실을 집계하는 비교이며, 실제 gradient accumulation이나 trainer의 내부 정규화를 측정한 결과가 아니다.

Instruction 데이터는 해야 할 지시, 필요한 입력, 바람직한 응답을 짝짓는다. 자체 예로 지시는 “다음 두 정수의 합을 숫자로 답하라”, 입력은 “2, 3”, 응답은 “5”다. 대화형이면 user·assistant 등의 역할과 순서를 함께 기록한다.

응답이 지시를 실제 만족하는지 내용·형식·근거를 점검한다. “숫자만” 요청에 긴 설명을 붙인 응답이나 계산을 틀린 응답은 데이터 목표와 충돌한다. 많은 양이 이런 불일치를 자동으로 고치지 않는다. 토큰화된 “5”가 항상 한 토큰이라는 보장은 없어 아래는 가상 토큰 예제로 계산한다.

입력 토큰을 주는 것과 손실을 주는 것은 다르다

자기회귀 SFT는 앞 문맥으로 다음 목표 토큰의 로그 확률을 학습한다. 응답 전용 학습에서는 지시/입력도 문맥으로 넣되 그 위치를 손실 계산에서 제외한다. padding도 제외하고 응답의 종료 표시는 템플릿 규약에 맞춰 학습한다.

TRL v0.23.0 문서는 prompt-completion의 completion 전용 손실과 대화형 assistant 전용 손실을 구별한다. assistant 마스크를 반환하는 chat template도 필요하다. 모델용 템플릿·EOS·최대 길이를 확인하고 실제 labels의 유효 위치를 검사해야 한다. 긴 입력 때문에 응답이 모두 잘리면 응답 목표가 0개인 사례를 정상 학습 예제로 그대로 평균내지 않는다.

같은 저랭크 행렬을 두 가지 인수로 표현하면 다음 학습도 같나요?

자체 정확 실수 행렬 모형은 W₀=I₂, r=1, α=1, 입력 x=(1,0)ᵀ, 목표 벡터 y=(0,0)ᵀ다. A=[1,0], B=[1,0]ᵀ를 학습하고 W₀는 동결한다. 출력 h=W₀x+BAx이고 손실은 ‖h−y‖²/2다. 다른 표현 A′=[2,0], B′=[1/2,0]ᵀ도 같은 BA를 만든다. 두 경우는 독립 초기 상태이며 학습률 1/4의 순수 동시 SGD로 A와 B를 갱신한다.

두 초기 출력은 모두 (2,0)이고 손실은 2다. 첫 표현의 기울기는 A에 [2,0], B에 [2,0]ᵀ여서 둘 다 첫 성분이 1/2로 바뀐다. 갱신 BA의 첫 대각 성분은 1/4이고 출력은 (5/4,0)이다. 다른 표현의 기울기는 A′에 [1,0], B′에 [4,0]ᵀ여서 A′ 첫 성분은 7/4, B′ 첫 성분은 −1/2가 된다. 갱신 BA의 첫 대각 성분은 −7/8이고 출력은 (1/8,0)이다. 같은 행렬을 표현했다는 사실이 같은 인수 좌표 SGD를 보장하지 않는다.

이 예제의 학습 값 수는 A 두 개와 B 두 개로 네 개이며, 전체 2×2 행렬의 네 개보다 적지 않다. 초기 갱신 BA의 rank는 1이지만 W₀+BA=diag(2,1)의 rank는 2다. 병합한 행렬에 어댑터를 다시 적용하면 BA를 두 번 더한 다른 함수가 된다. 실제 LoRA 구현·초기화 난수·양자화·GPU 비용을 시험하지 않은 손계산이다.

LoRA는 가중치 자체보다 갱신을 작게 표현한다

W0∈R^(d×k)를 고정하고 ΔW=(α/r)BA로 학습한다. A∈R^(r×k), B∈R^(d×r)이며 입력 x에 출력은 W0x+(α/r)BAx다. ΔW의 rank는 최대 r지만 W0+ΔW 전체가 반드시 저랭크라는 뜻은 아니다.

전체 행렬 갱신은 dk개이고 A,B만 학습하면 r(k+d)개다. r이 충분히 작을 때 개수 이득이 크다. 학습할 층과 bias 등의 선택까지 포함해 실제 개수를 센다. 낮은 rank 제한이 어떤 작업에서 충분한지는 검증 성능으로 비교해야 한다.

0으로 시작하는 갱신과 병합 조건을 확인한다

원 LoRA 설명은 A를 무작위로, B를 0으로 초기화해 시작 출력이 기반 모델과 같도록 한다. 둘을 모두 0으로 놓으면 단순 BA의 두 행렬에 대한 기울기가 모두 0으로 시작해 학습이 막힐 수 있다. 작은 행렬이라고 초기화 규칙을 생략하지 않는다.

고정 작업에서는 같은 기반 가중치에 ΔW를 더해 하나의 W로 병합할 수 있다. 어댑터를 별도 적용하든 병합하든 계산 차원·배율·기반 체크포인트가 같아야 한다. 저장 파일이 작은 것은 기반 모델이 필요 없다는 뜻이 아니다. 토크나이저와 모델 버전도 함께 기록한다.

적은 학습 파라미터가 모든 비용을 없애지는 않는다

기반 가중치 저장과 순전파, 필요한 활성값은 남는다. optimizer 상태 등은 학습 파라미터 감소로 줄 수 있지만 실제 메모리와 시간은 길이·배치·구현·하드웨어에 따라 다르다. LoRA 파라미터 비율을 그대로 전체 GPU 절약률이나 성능 유지율이라고 보고하지 않는다.

기반 가중치를 낮은 비트로 저장하는 양자화는 저랭크 갱신과 다른 선택이다. 수치 표현을 줄이면 오차와 추가 처리 조건이 생길 수 있다. 이 입문 예제는 정확한 작은 실수 행렬의 LoRA만 다루며 양자화 모델을 실제 학습하거나 병합했다고 주장하지 않는다.

풀이와 답 확인
