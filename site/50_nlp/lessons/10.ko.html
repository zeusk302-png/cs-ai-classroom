소단원 10.1

미세조정과 동결

이미 언어를 배운 모델에서 어느 부분을 다시 학습할까?

준비 개념과 학습 목표

준비 개념

  • 사전학습과 특징 표현
  • 손실과 기울기
  • 학습/검증/시험 구분

학습 목표

  • 전체·부분 미세조정의 갱신 범위를 구별한다.
  • 동결과 평가 모드를 나눈다.
  • 업데이트 수와 비용·성능을 구별한다.

사전학습 가중치에서 새 작업 학습을 시작한다

미세조정은 사전학습된 가중치를 출발점으로 작업 데이터의 손실을 줄이는 추가 학습이다. 문장 분류라면 사전학습 표현 위에 분류 head를 붙일 수 있고, 생성 모델이라면 특정 형식의 다음 토큰을 학습할 수 있다. 처음부터 모든 가중치를 무작위로 다시 학습하는 것과 출발점이 다르다.

전체 미세조정은 선택한 모델의 모든 학습 파라미터를 갱신한다. 부분 미세조정은 일부 층이나 head만 갱신한다. 동결된 가중치도 순전파 계산에는 사용한다. 새 데이터가 작거나 도메인이 다른 상황에서 어느 범위가 좋은지는 검증 자료로 비교해야 한다.

동결은 가중치 업데이트를 막는 설정이다

PyTorch에서 파라미터의 requires_grad_(False)는 그 leaf 파라미터의 기울기 누적을 막는다. 이전 학습의 잔여 기울기를 지우고 optimizer가 갱신할 파라미터 목록도 확인하는 절차가 필요하다. 학습 앞뒤의 동결 가중치가 실제 같은지도 확인한다.

eval()은 dropout이나 BatchNorm처럼 학습/평가에서 다른 동작을 하는 모듈의 모드를 바꾸며 기울기 동결 자체가 아니다. no_grad는 그 구간의 연산 기록을 막는 별도 설정이다. 학습할 head까지 no_grad 안에 넣으면 필요한 기울기를 얻지 못할 수 있다. 동결된 층을 통과해 더 앞의 학습 가능한 파라미터로 가는 기울기가 필요한 구조도 있으므로 모든 동결 연산을 무조건 제거한다고 생각하지 않는다.

파라미터 비율은 성능이나 전체 메모리 비율이 아니다

학습 가능한 파라미터 수를 세면 어떤 부분을 갱신했는지 보고할 수 있다. 그래도 기본 모델 가중치와 활성값, 배치·길이, optimizer 상태 등의 비용이 따로 있어 학습 파라미터 20%라는 말이 GPU 메모리 20%를 뜻하지 않는다.

작업별 검증 성능과 기존 작업 성능을 함께 비교해 새 작업의 개선과 기존 능력 손실을 살핀다. 시험 데이터로 동결 범위·학습률을 반복 선택하면 최종 시험의 의미가 약해진다. 중복 문장이나 같은 문서의 가까운 조각이 학습/시험에 섞이지 않도록 분할 단위를 결정한다.

중간 과정을 따라가는 예제

사전학습 표현기 파라미터 12개를 동결하고 head의 w1,w2,b 세 개만 학습한다. 한 문장의 고정 특징 z=(1,2), 목표 y=1이다. ŷ=w·z+b, L=(ŷ−y)²/2, 초기 w=b=0, 학습률 .1의 한 업데이트를 손으로 계산하라.

  1. 총 파라미터는 12+3=15, 학습 가능한 것은 3이므로 20%다. 이는 자체 작은 모형의 개수다.
  2. 초기 ŷ=0, 오차 ŷ−y=−1이고 L=1/2다.
  3. 기울기는 ∂L/∂w=(−1,−2), ∂L/∂b=−1이다. 표현기는 동결해 갱신하지 않는다.
  4. 새 w=(.1,.2), b=.1이다. 같은 특징에 ŷ=.1·1+.2·2+.1=.6이다.
  5. 새 L=(.6−1)²/2=.08이다. 한 표본 손실 감소를 전체 문장 분류 성능 향상으로 일반화하지 않는다.

head만 한 번 갱신해 예측 .6, 손실 .08이다. 표현기 12개는 그대로이며 학습 파라미터 비율은 20%다.

힌트 보기

동결 여부와 모드 설정을 따로 센다.

풀이 보기

head까지 동결하면 가중치가 모두 그대로이고 이 예측은 0, 손실 .5다. 마지막 블록 4개를 풀면 4+3=7개, 총 15개의 7/15를 학습한다. eval()만으로 requires_grad 설정이 자동 동결되는 것은 아니다.

오해와 반례

eval()은 동결이며 일부 파라미터만 학습하면 비용과 성능도 그 비율로 바뀐다.

평가 모드·기울기 추적·optimizer 갱신은 다른 설정이다. 파라미터 수는 정확히 세되 실제 비용과 성능은 별도로 측정한다.

소단원 10.2

instruction 데이터

질문과 답을 이어 붙이면 어느 토큰을 학습시키는지 자동으로 정해질까?

준비 개념과 학습 목표

준비 개념

  • 다음 토큰 예측
  • 교차엔트로피
  • 입력·목표·padding 구별

학습 목표

  • 지시·입력·응답의 역할을 구분한다.
  • 응답 전용 손실 마스크를 확인한다.
  • 데이터 형식과 평가 기준을 함께 설계한다.

작업 요구와 바람직한 응답을 한 사례로 만든다

Instruction 데이터는 해야 할 지시, 필요한 입력, 바람직한 응답을 짝짓는다. 자체 예로 지시는 “다음 두 정수의 합을 숫자로 답하라”, 입력은 “2, 3”, 응답은 “5”다. 대화형이면 user·assistant 등의 역할과 순서를 함께 기록한다.

응답이 지시를 실제 만족하는지 내용·형식·근거를 점검한다. “숫자만” 요청에 긴 설명을 붙인 응답이나 계산을 틀린 응답은 데이터 목표와 충돌한다. 많은 양이 이런 불일치를 자동으로 고치지 않는다. 토큰화된 “5”가 항상 한 토큰이라는 보장은 없어 아래는 가상 토큰 예제로 계산한다.

입력 토큰을 주는 것과 손실을 주는 것은 다르다

자기회귀 SFT는 앞 문맥으로 다음 목표 토큰의 로그 확률을 학습한다. 응답 전용 학습에서는 지시/입력도 문맥으로 넣되 그 위치를 손실 계산에서 제외한다. padding도 제외하고 응답의 종료 표시는 템플릿 규약에 맞춰 학습한다.

TRL v0.23.0 문서는 prompt-completion의 completion 전용 손실과 대화형 assistant 전용 손실을 구별한다. assistant 마스크를 반환하는 chat template도 필요하다. 모델용 템플릿·EOS·최대 길이를 확인하고 실제 labels의 유효 위치를 검사해야 한다. 긴 입력 때문에 응답이 모두 잘리면 응답 목표가 0개인 사례를 정상 학습 예제로 그대로 평균내지 않는다.

정답 예시와 평가 데이터를 구별한다

생성한 응답을 학습 정답으로 쓰면 오류도 배울 수 있다. 한 문제의 바꿔 쓴 지시가 학습과 시험에 나뉘면 새 문제 해결보다 기억한 응답을 측정할 수 있다. 같은 원본 문제·문서의 파생 예시는 한 분할로 묶는 방법을 먼저 정한다.

모델이 텍스트를 잘 이어 쓴다는 목표와 수학 정답·형식 준수·근거의 정확성은 서로 다른 평가다. 교차엔트로피가 낮아도 학습 응답이 잘못되었거나 실제 요청 분포가 다르면 좋은 답변이라고 단정하지 않는다. 아래 손실은 실제 모델 출력이 아니다.

중간 과정을 따라가는 예제

지시/입력 목표 위치 5개, 응답 목표 [R1,R2,EOS] 3개, PAD 2개인 가상 배치를 생각하자. 유효 응답의 정답 확률이 .5,.25,.5일 때 응답 전용 평균 NLL을 계산하라. 제외 위치의 확률은 계산에 넣지 않는다.

  1. 유효 마스크는 지시/입력 5개에 0, 응답 3개에 1, PAD 2개에 0이다. 총 길이 10 중 유효 목표 수는 3이다.
  2. 유효 손실 합은 −ln(.5)−ln(.25)−ln(.5)=ln2+2ln2+ln2=4ln2다.
  3. 응답 전용 평균은 (4/3)ln2≈.9242다.
  4. 합은 응답만 셌는데 분모에 전체 길이 10을 쓰면 .4ln2≈.2773으로 잘못 낮아진다.
  5. 입력 토큰이 손실 0이어도 모델 문맥에서 없어진다는 뜻은 아니다. 다음 응답 확률 계산에 앞의 지시와 입력이 사용된다.

유효 목표 3개로 나눠 평균 NLL=(4/3)ln2다. 문맥 마스크·손실 마스크·padding 처리는 같은 역할이 아니다.

종이와 본문으로 직접 해보기

사례 A는 유효 3토큰의 평균 NLL이 ln2, 사례 B는 9토큰의 평균이 2ln2다. 토큰 전체 평균과 사례별 평균의 평균은? 응답이 모두 잘려 유효 목표가 0이면?

힌트 보기

먼저 각 사례의 손실 합을 만들고 무엇을 같은 가중으로 둘지 정한다.

풀이 보기

토큰 전체 평균은 (3ln2+18ln2)/12=(7/4)ln2다. 사례 평균의 평균은 (ln2+2ln2)/2=(3/2)ln2다. 목적에 따라 가중 방식이 다르다. 유효 목표 0인 사례는 0으로 나눌 수 없으므로 원인을 수정하거나 정해진 제외 정책으로 처리하고 정상 0손실 성공으로 세지 않는다.

오해와 반례

응답 전용 loss는 지시를 입력에서 제거하며 낮은 loss는 지시 수행의 정확성을 보장한다.

손실에서 제외한 지시도 문맥으로 남는다. NLL은 정답 응답 토큰의 확률을 재며 내용·형식·일반화 평가는 따로 수행한다.

저비용 적응 입문

큰 가중치 행렬을 그대로 두고 작은 두 행렬만 학습하면 무엇이 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 행렬 곱과 차원
  • rank
  • 동결·학습 파라미터

학습 목표

  • LoRA의 저랭크 갱신을 계산한다.
  • 학습 파라미터 수와 전체 모델 크기를 나눈다.
  • 어댑터와 기반 모델의 호환 조건을 기록한다.

LoRA는 가중치 자체보다 갱신을 작게 표현한다

W0∈R^(d×k)를 고정하고 ΔW=(α/r)BA로 학습한다. A∈R^(r×k), B∈R^(d×r)이며 입력 x에 출력은 W0x+(α/r)BAx다. ΔW의 rank는 최대 r지만 W0+ΔW 전체가 반드시 저랭크라는 뜻은 아니다.

전체 행렬 갱신은 dk개이고 A,B만 학습하면 r(k+d)개다. r이 충분히 작을 때 개수 이득이 크다. 학습할 층과 bias 등의 선택까지 포함해 실제 개수를 센다. 낮은 rank 제한이 어떤 작업에서 충분한지는 검증 성능으로 비교해야 한다.

0으로 시작하는 갱신과 병합 조건을 확인한다

원 LoRA 설명은 A를 무작위로, B를 0으로 초기화해 시작 출력이 기반 모델과 같도록 한다. 둘을 모두 0으로 놓으면 단순 BA의 두 행렬에 대한 기울기가 모두 0으로 시작해 학습이 막힐 수 있다. 작은 행렬이라고 초기화 규칙을 생략하지 않는다.

고정 작업에서는 같은 기반 가중치에 ΔW를 더해 하나의 W로 병합할 수 있다. 어댑터를 별도 적용하든 병합하든 계산 차원·배율·기반 체크포인트가 같아야 한다. 저장 파일이 작은 것은 기반 모델이 필요 없다는 뜻이 아니다. 토크나이저와 모델 버전도 함께 기록한다.

적은 학습 파라미터가 모든 비용을 없애지는 않는다

기반 가중치 저장과 순전파, 필요한 활성값은 남는다. optimizer 상태 등은 학습 파라미터 감소로 줄 수 있지만 실제 메모리와 시간은 길이·배치·구현·하드웨어에 따라 다르다. LoRA 파라미터 비율을 그대로 전체 GPU 절약률이나 성능 유지율이라고 보고하지 않는다.

기반 가중치를 낮은 비트로 저장하는 양자화는 저랭크 갱신과 다른 선택이다. 수치 표현을 줄이면 오차와 추가 처리 조건이 생길 수 있다. 이 입문 예제는 정확한 작은 실수 행렬의 LoRA만 다루며 양자화 모델을 실제 학습하거나 병합했다고 주장하지 않는다.

중간 과정을 따라가는 예제

W0=[[1,0,0],[0,1,0]], A=[[1,0,−1]], B=[[2],[−1]], r=1, α=1, x=[1,2,3]ᵀ다. ΔW와 출력 h, 학습 파라미터 수를 구하라.

  1. W0는 2×3, A는 1×3, B는 2×1이고 α/r=1이다. BA는 2×3으로 W0에 더할 수 있다.
  2. BA=[[2,0,−2],[−1,0,1]]이다. 두 번째 행은 첫 행의 −1/2배여서 rank는 1이다.
  3. W0x=[1,2]ᵀ, Ax=1−3=−2, B(Ax)=[−4,2]ᵀ다.
  4. h=[1,2]+[−4,2]=[−3,4]ᵀ다. 병합 W=[[3,0,−2],[−1,1,1]]에 x를 곱해도 [−3,4]다.
  5. A의 3개와 B의 2개로 학습 5개다. W0의 6개는 고정되어 있고 별도 저장 시 총 11개의 값이 있다. full 행렬 6개 갱신에 비해 이 작은 예제의 학습 수 감소는 1개뿐이다.

ΔW=[[2,0,−2],[−1,0,1]], h=[−3,4], 학습 5개다. 어댑터 5개와 기반 6개의 역할을 구별한다.

종이와 본문으로 직접 해보기

α만 2로 바꾸면 h는? 1000×1000 행렬에 r=8을 적용하면 학습 수와 full 갱신 대비 비율은? 작은 2×3 예제의 r을 2로 올리면 개수가 더 작은가?

힌트 보기

차원과 α/r 배율을 따로 계산한다. rank 변경에는 A,B 크기도 달라진다.

풀이 보기

α=2면 ΔWx가 2배라 h=[1,2]+[−8,4]=[−7,6]이다. 큰 행렬의 학습 수는 8(1000+1000)=16,000개로 1,000,000개의 1.6%다. 작은 예제에서 r=2이면 A 6개+B 4개=10개로 full 6개보다 많다. 항상 개수가 감소하는 것은 아니다.

오해와 반례

LoRA의 rank가 1이면 전체 모델도 rank 1이고 어댑터만 있으면 기반 모델 없이 실행된다.

저랭크 제한은 해당 ΔW에 걸린다. 전체 모델과 W0의 rank는 별개이며 실행에는 대응하는 기반 가중치와 설정이 필요하다.

한 단계 더

기반 W0 대신 다른 모델 W1을 넣으면 같은 BA라도 총 출력은 W1x+BAx가 된다. W1=W0+I 같은 표현은 직사각형 2×3에서 차원이 맞지 않으므로 자체 차이 행렬 E=[[1,0,0],[0,0,0]]를 더하자. x에서 Ex=[1,0]이므로 출력은 [−2,4]로 달라진다. 어댑터가 같다는 사실만으로 호환 출력을 보장하지 않는다.
