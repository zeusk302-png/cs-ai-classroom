소단원 6.1

구문트리와 의존관계

“민수 책을 읽는다”에서 단어 순서와 단어 사이 역할은 같은 정보일까?

준비 개념과 학습 목표

준비 개념

  • 구문은 문장의 구조, head 는 다른 토큰이 의존하는 중심 토큰이다.

  • 토큰은 분석 단위, root 는 문장 중심에 붙인 관계명이고 0 은 가상 시작 노드다.

학습 목표

  • 구성성분 트리와 의존관계를 구별한다.

  • 약식 문장의 head/관계 표와 트리 조건을 읽는다.

선이 교차하는 그림은 순환하는 트리일까?

앞 본문은 토큰마다 head 하나가 있어도 순환과 연결을 검사해야 함을 보였다. 새 네 토큰의 head 배열 H=(3,4,0,3)을 둔다. 배열의 i번째 값은 토큰 i의 head이고 0은 가상 root다. 간선은 3→1, 4→2, 0→3, 3→4다. 관계명은 실제 언어 분석 대신 root 간선에는 root, 나머지에는 dep로 정한다.

모든 토큰이 3을 거쳐 0에 연결되고 자기 연결과 순환이 없으며 0의 자식은 3 하나다. 따라서 선언한 단일 root basic tree의 조건을 만족한다. 토큰을 번호 순서로 그리면 끝점 1<2<3<4에서 간선 3→1과 4→2가 교차한다. 이 그림의 교차와 방향 간선을 따라 출발점으로 돌아오는 순환은 다른 조건이다.

별도 K=(2,1,0,3)은 토큰 1과 토큰 2가 서로 head여서 1↔2 순환이다. 네 토큰마다 head가 있고 root인 토큰 3도 하나지만, 토큰 1과 토큰 2는 root로 연결되지 않는다. 간선 수가 토큰 수인 4라는 검사만으로 H와 K를 구별하지 못한다. basic과 enhanced를 혼합하여 K를 정상 트리라고 부르지 않는다.

토큰 정체성을 보존한 재번호도 구조 계약의 일부다. 옛 번호 i를 새 번호 p(i)=5−i로 바꾸고 0은 0으로 유지한다. H의 새 배열은 (2,0,1,2)다. 각 dependent뿐 아니라 head 번호도 함께 바꾼다. 배열 칸만 역순으로 두고 옛 head 값을 유지하면 (3,0,4,3)이 되어 3↔4 순환을 새로 만든다.

먼저 확인할 개념
  • head와 basic tree의 조건

    하나의 head·단일 root·연결·순환을 독립 검사한다.

  • 토큰 정렬의 선행 조건

    재번호 전후의 점수를 비교하기 전에 토큰 정체성과 head 대응을 맞춘다.

중첩된 묶음과 단어 사이 화살표

구성성분 트리는 단어를 명사구/동사구 같은 중첩된 묶음으로 조직한다. 의존구조는 head→dependent 화살표로 토큰 사이 관계를 표시한다. 둘은 구조를 표현하는 서로 다른 방식이며 같은 그림에서 노드 의미가 다르다.

자체 문장 “민수 책을 읽는다”의 어절을 1/2/3 으로 고정한다. 약식 구성은 S(NP(1),VP(NP(2),V(3)))다. 한국어 형태소 분할이나 정식 UD 코퍼스의 완전한 분석이라고 주장하지 않고 작은 선언한 규약으로 연습한다.

누가 누구에 의존하는가

자체 의존표는 0→3(root),3→1(nsubj),3→2(obj)다. nsubj 는 명사 주어 관계, obj 는 목적어 관계라는 이 연습의 이름이다. 화살표가 읽는 시간 순서를 뜻하지 않으며 책이 민수보다 나중이라는 관계와 다르다.

각 실제 토큰의 head 는 하나이고,0 을 제외한 토큰이 root 까지 연결되며 순환이 없다. 일반 basic tree 와 더 풍부한 enhanced graph 는 구별한다. 이 단원은 단일 root 를 갖는 basic tree 만 사용한다.

어순만으로 모든 역할을 정하지 않는다

“책을 민수 읽는다”를 토큰 1 책을/2 민수/3 읽는다로 다시 선언하면 자체 역할은 3→2(nsubj),3→1(obj)다. 토큰 번호가 바뀌었다고 목적어를 주어로 고정하는 것은 틀리다. 실제 언어의 생략·조사·문맥은 더 많은 검토가 필요하다.

UD 는 여러 언어에서 관계를 가능한 한 대응시키되 언어별 차이와 표현 한계를 인정한다. 한 한국어 약식 표를 모든 언어의 보편 어순이나 의미의 완전한 해석으로 확대하지 않는다.

중간 과정을 따라가는 예제

첫 문장의 head 배열과 의존 간선 수,3 의 직접 dependent 를 구하라.

  1. 토큰 1 은 head3/관계 nsubj,2 는 head3/obj,3 은 head0/root 다.

  2. head 배열[3,3,0],실제 토큰당 간선 하나라 가상 root 간선 포함 3 개다.

  3. 3 의 실제 dependent 는 1/2 이고 0→3 은 3 을 root 에 연결한다.

heads[3,3,0],간선 3,dependent{1,2}.

조건을 바꾸어 비교하기

교차해도 root에 도달한다

H에서 각 토큰의 head 경로와 간선 수를 적어 트리 조건을 확인하라.

  1. 토큰 1은 1→3→0, 토큰 2는 2→4→3→0으로 head를 따라간다.

  2. 토큰 3은 3→0, 토큰 4는 4→3→0이다.

  3. head 경로에서 반복 토큰이 없으며 root 간선을 포함한 간선은 4개다.

H는 선언한 basic tree이며 교차 그림은 순환의 증거가 아니다.

비교할 점

원래 의존 간선 head→dependent와 확인용 역방향 head 경로를 구별한다.

정체성을 유지한 번호 교환

p(i)=5−i로 모든 토큰을 재번호할 때 H를 변환하라.

  1. 옛 1→새 4의 head는 옛 3→새 2다. 옛 2→새 3의 head는 옛 4→새 1이다.

  2. 옛 3→새 2는 head 0이며 옛 4→새 1의 head는 새 2다.

  3. 새 번호 순서로 읽으면 (2,0,1,2)다.

새 head 배열은 (2,0,1,2)다.

비교할 점

배열 순서와 배열 안 head 번호를 동시에 대응한다.

오해와 반례

구문 화살표는 단어를 읽는 순서이며 토큰당 head 하나면 언제나 올바른 트리다.

3→1 은뒤의 서술어에서앞의 주어로 향한다. [2,1,0]은 head 하나씩 있어도순환/비연결이라 tree 조건에 실패한다.

연습 1 · 값과 상태 예측

별도 H에서 head(4)만 2로 바꾸면 새 배열과 실패 원인은?

힌트 1

토큰 2의 head는 계속 4다.

힌트 2

변경한 두 토큰의 경로를 확인한다.

풀이와 답 확인

  1. 배열은 (3,4,0,2)다.

  2. 2→4→2의 head 순환이 생긴다.

  3. root 간선 하나와 토큰별 head 하나는 여전히 만족하지만 전체 tree는 실패다.

새 배열은 (3,4,0,2)이며 토큰 2↔4의 순환으로 실패한다.

흔한 오답에서 다시 생각하기

root 하나이면 연결과 순환도 자동 통과한다.

이 반례는 root 검사만으로 충분하지 않음을 보인다.

연습 2 · 오류 찾아 고치기

H를 재번호하면서 배열 칸만 역순으로 둔 (3,0,4,3)을 고쳐라.

힌트 1

0은 0으로 유지한다.

힌트 2

옛 head도 p로 변환한다.

풀이와 답 확인

  1. 칸만 역순은 새 토큰 3과 4의 순환을 만든다.

  2. 각 옛 간선의 양 끝을 p로 바꾸어 새 배열 (2,0,1,2)를 만든다.

  3. 평가 비교도 같은 토큰 대응을 사용한다.

양 끝 대응을 적용한 (2,0,1,2)가 올바른 재번호다.

흔한 오답에서 다시 생각하기

예측 배열도 같은 방식으로 잘못 바꾸면 문제가 없다.

두 잘못된 구조가 숫자상 일치해도 정체성과 tree 계약을 보존한 변환은 아니다.

연습 3 · 직접 만들어 보기

n개의 동일 실제 토큰을 받는 basic tree 검증 보고 항목을 구성하라. 정확 언어 해석과는 구별한다.

힌트 1

번호 범위·자기 연결·root를 먼저 확인한다.

힌트 2

모든 토큰에서 head 경로가 어디로 가는지 확인한다.

풀이와 답 확인

  2. 0의 실제 자식 하나와 모든 head 경로의 0 도달/순환 부재를 확인한다.

  3. 통과 후에도 관계 정답과 언어 해석의 일치는 별도 평가한다.

번호/한 head/단일 root/연결/순환과 정답 일치를 다른 보고 항목으로 둔다.

흔한 오답에서 다시 생각하기

간선 개수 n만 확인하면 된다.

K도 간선 4개지만 순환과 연결 검사에 실패한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

번호 순서의 선 교차를 금지하는 별도 입력 규약을 추가하면 H의 판정을 어떻게 보고해야 하나?

힌트 1

현재 tree 조건에 새 제한을 추가한 경우다.

힌트 2

H의 두 끝점 쌍을 적는다.

풀이와 답 확인

  1. H는 단일 root basic tree 조건에는 통과한다.

  2. 끝점 [1,3]과 [2,4]는 1<2<3<4로 교차한다.

  3. 새 교차 금지 규약에는 실패하며 이를 순환 실패라고 바꾸지 않는다.

H는 tree 통과·추가 교차 제한 실패로 보고한다.

흔한 오답에서 다시 생각하기

새 제한 실패이면 앞 tree 검사도 틀렸다.

서로 다른 허용 집합의 판정이다. 추가 제한을 기존 basic 정의에 소급해 넣지 않는다.

소단원 6.2

파싱의 예측문제

각 단어가 가장 높은 점수의 head 를 고르면 문장 전체가 올바른 트리가 될까?

준비 개념과 학습 목표

준비 개념

  • 학습은 모형 추정, 파싱은 고정 모형에서 구조를 예측하는 과정이다.

  • stack 은 마지막 것을 꺼내는 목록, buffer 는 아직 처리하지 않은 토큰 목록이다.

학습 목표

  • 지역 점수와 트리 제약을 구별한다.

  • 전이 기반 파싱의 상태를 종이로 추적한다.

같은 트리를 만들면 전이 이력도 유일할까?

새 arc-standard 모형은 앞 본문의 Shift/LeftArc/RightArc를 사용한다. 시작은 stack [0], buffer [1,2,3], arcs 빈 집합이다. 최종 목표 간선은 2→1, 2→3, 0→2이며 head 배열은 (2,0,2)다. root 간선의 RightArc는 buffer가 비고 stack [0,r]일 때만 허용하는 추가 정책을 명시한다. 각 문항은 지정 상태에서 독립 시작한다.

이력 L은 Shift1, Shift2, LeftArc(2→1), Shift3, RightArc(2→3), RightArc(0→2)다. 이력 R은 Shift1, Shift2, Shift3, RightArc(2→3), LeftArc(2→1), RightArc(0→2)다. 둘 다 실제 토큰을 옮기는 Shift 세 번과 실제 토큰을 하나씩 제거하는 Arc 세 번을 수행하여 같은 최종 트리와 여섯 전이를 얻는다.

Shift1과 Shift2 뒤의 stack [0,1,2], buffer [3]에서는 이력 L의 LeftArc와 이력 R의 Shift가 모두 최종 목표로 이어질 수 있다. 정답 트리 하나에서 모든 상태의 정답 행동이 유일하다고 추론하지 않는다. 한 특정 이력을 교사 행동으로 고정하는 학습 규약과 같은 목표로 이어지는 행동 집합은 다르다.

별도 상태에서 먼저 RightArc(1→2)를 수행하면 토큰 2가 제거된다. 같은 초기 stack [0,1,2], buffer [3]에서 이 선택 뒤에는 목표 head 2가 stack과 buffer에 모두 없으므로 2→3과 0→2를 더 만들 수 없다. 지역 허용 행동과 현재 목표로 완료할 수 있는 행동을 구별한다. 실제 파서·oracle·학습은 실행하지 않는다.

점수와 유효 구조는 별개다

각 후보 head→dependent 에 모형 점수를 매겨 높은 합계 트리를 찾는 자체 문제를 둔다. 점수는 이 연습에서 임의 수치이며 확률/실제 학습 성능이 아니다. 자기 연결 금지·실제 토큰당 head 하나·단일 root·순환 금지 조건을 함께 확인한다.

토큰별 최고 점수를 독립 선택하면 순환이 생길 수 있다. 유효한 여러 전체 구조를 비교하는 탐색과 한 단계 최고를 고르는 greedy 선택은 다르다. 점수 최대라 해도 언어적으로 참이라는 증거는 별도 라벨 평가로 확인한다.

자체 점수 표를 전체로 비교한다

0→1/2/3 점수는 1/1/3,1→2 는 4,2→1 은 4,3→1 은 3,3→2 는 2,1→3/2→3 은 0 이다. 독립 최고는 2→1 과 1→2 와 0→3 으로 합 11 이지만순환이라 제외한다.

root3 이면 나머지 유효 연결은{3→1,3→2} 합 8,{3→1,1→2} 합 10,{3→2,2→1} 합 9 다. root1/2 경우의 최대는각 5 다. 따라서 단일 root 트리의 최고 합 10 을 얻지만 이 점수 모형은 앞 단원의 역할 정답과 다르게토큰 2 를 1 에 붙인다.

다른 방식은 상태 전이를 예측한다

arc-standard의 상태는 (stack,buffer,arcs)다. Shift는 buffer 앞을 stack 위로 옮긴다. LeftArc는 위 토큰이 바로 아래 토큰의 head가 되어 아래를 제거하되 root 0을 dependent로 만들지 않는다. RightArc는 아래가 위의 head가 되어 위를 제거한다.

자체 성공 종료는 buffer가 비고 stack=[0]이며 선언한 tree 조건을 만족하는 상태다. 허용 전이, 이미 head가 있는지, root 정책도 확인한다. greedy 전이의 초기 오류가 뒤 구조를 제한할 수 있어 가능한 전이라고 정답 전이라고 부르지 않는다.

소단원 6.3

구문지표와 오류

중심 단어는 맞지만 주어와 목적어 이름이 틀리면 어떤 점수로 드러날까?

준비 개념과 학습 목표

준비 개념

  • head 는 의존 중심의 번호, label 은 관계 이름이다.

  • 평가 분모와 토큰 정렬을 먼저 정하고 정답 표와 예측 표를 비교한다.

학습 목표

  • UAS 와 LAS 를 직접 계산한다.

  • 토큰 평균·문장 평균·완전 일치와 오류 유형을 구별한다.

토큰 점수가 더 높은 순환 출력이 더 좋은 파서일까?

새 동일 다섯 토큰 모형의 정답 head는 G=(0,1,1,1,1)이며 label은 (root,dep,dep,dep,dep)다. 예측 A는 head (0,3,2,1,1), 예측 B는 (0,1,2,3,4)이고 두 예측의 label 문자열은 G와 같다. 가상 0을 제외한 실제 다섯 토큰 모두를 비교한다. 구두점과 토큰 분할 차이는 없다.

검증 전 진단 비율은 A가 토큰 1, 토큰 4, 토큰 5의 head와 label을 맞추어 UAS와 LAS가 각각 3/5다. 그러나 토큰 2와 토큰 3 사이의 순환으로 basic tree 조건을 만족하지 못한다. B는 토큰 1과 토큰 2만 정답이라 UAS와 LAS가 각각 2/5지만 모든 토큰이 토큰 1을 거쳐 0에 도달하는 정상 트리다. 이 진단 비율과 정상 출력 조건을 함께 보고한다.

이 자체 단위 평가에서는 무효 출력은 진단 값과 별도로 invalid를 기록하고, 유효 출력만 정상 UAS/LAS로 보고한다. 공식 CoNLL 2018은 순환·복수 root 등을 무효로 보아 해당 시험 파일의 점수를 0으로 처리하는 규약을 둔다. 자체 문장 정책과 공식 시험 파일 단위를 혼합하지 않는다.

A를 복구하는 두 별도 변경도 서로 다르다. A에서 head(2)를 1로 바꾸면 (0,1,2,1,1)이고 head(3)를 1로 바꾸면 (0,3,1,1,1)이다. 둘 다 정상 트리이며 진단 UAS=LAS=4/5다. 첫 변경은 토큰 3, 둘째는 토큰 2가 여전히 틀린다. 유효성 복구·점수·오류 위치를 분리하고 복구 전 실패를 지우지 않는다.

동일 토큰 규약에서 비교한다

자체 UAS는 head가 맞은 평가 토큰 수/전체, LAS는 head와 label이 모두 맞은 수/전체다. 토큰은 정답과 예측에서 동일하게 분할되었다고 가정한다. 구두점 제외, root에 붙은 실제 토큰 포함, 가상 0 제외 정책을 명시한다.

공식 CoNLL 2018은 분할과 노드 정렬, 구두점과 label subtype 규칙까지 둔다. 우리의 짧은 표는 그 대회 실행 결과가 아니며 다른 평가 정책의 점수와 바로 비교하지 않는다. 분모 0은 미정의로 표시한다.

머리 오류와 이름 오류를 나눈다

가상 5토큰의 정답 head=[3,3,0,3,4], label=[nsubj,advmod,root,obj,amod]다. 예측 head=[3,3,0,2,4], label=[nsubj,amod,root,obj,amod]다. 토큰 2는 head만 맞고 이름이 틀리며, 4는 이름 문자만 같지만 head가 틀렸다.

UAS는 1/2/3/5의 4개가 맞아 4/5, LAS는 1/3/5의 3개만 맞아 3/5다. LAS는 head와 label의 논리 AND라 같은 평가 토큰에서 LAS≤UAS다. label 문자만 비교한 값을 LAS라 쓰지 않는다.

모든 토큰과 모든 문장의 평균

추가 2토큰 문장은 둘 다 head와 label이 맞는다고 둔다. 합친 LAS는 (3+2)/(5+2)=5/7이다. 문장 LAS 단순 평균은 (.6+1)/2=.8이라 길이에 대한 가중치가 다르다.

문장 전체의 완전 일치는 첫 문장 실패, 둘째 성공이라 1/2다. 같은 평균 점수라도 긴 의존거리, 주어/목적어, 도메인별 오류는 다를 수 있다. 실제 파서나 한국어 학습자 성능을 측정한 표는 아니다.

각 부분은 독립 상태다. ① H=(3,4,0,3)의 head 경로·교차와 순환을 구별하고 p(i)=5−i, p(0)=0의 올바른 재번호 배열을 구한다. 칸만 역순인 (3,0,4,3)과 비교한다. ② 목표 head (2,0,2)에 대한 이력 L/R의 중간 상태와 최종 구조·전이 수를 구한다. 두 Shift 뒤 조기 RightArc(1→2)의 목표 완료 가능성을 판단한다. ③ G=(0,1,1,1,1), A=(0,3,2,1,1), B=(0,1,2,3,4)를 같은 label로 비교한다. 진단 UAS/LAS와 유효성, A의 두 복구 점수/오류 위치, B의 token 2 label만 obj로 바꾼 별도 점수를 구한다.

힌트 1

의존 간선 방향과 검사할 head 경로를 구별하고 재번호의 양 끝을 함께 바꾼다.

힌트 2

상태 제거·같은 목표와 이력·정상 구조와 진단 점수의 다른 조건을 기록한다.

풀이와 답 확인

  1. H의 모든 head 경로는 3을 거쳐 0으로 가고 순환이 없다. 두 끝점 쌍의 그림은 교차하지만 tree다. 양 끝 재번호는 (2,0,1,2)이고 칸만 역순은 3↔4 순환을 만든다.

  2. L은 왼쪽 1을 먼저, R은 오른쪽 3을 먼저 붙인다. 두 이력은 Shift 3번/Arc 3번, 최종 세 간선과 head (2,0,2)가 같다. 조기 1→2는 2를 제거하여 목표의 head 2를 다시 사용할 수 없다.

  3. A의 진단 UAS/LAS는 3/5지만 순환 invalid다. B는 정상이며 두 점수 2/5다. A의 head(2) 또는 head(3) 복구는 각각 정상 4/5지만 오류는 token 3 또는 token 2에 남는다.

  4. B의 label(2)만 바꾸면 UAS는 2/5, LAS는 1/5다. 공식 파일 invalid 규약과 자체 문장 진단을 구별하고 실제 파서/평가 실행이라고 보고하지 않는다.

올바른 재번호는 (2,0,1,2)다. L/R은 같은 목표를 만드는 서로 다른 여섯 전이 이력이다. A는 진단 3/5와 invalid, B는 정상 2/5다. 두 복구는 정상 4/5이지만 오류 위치가 다르고 별도 B label 변경은 LAS 1/5다.

해결한 뒤 점검할 것

  • 한 head·번호·root·연결·순환과 추가 교차 제한을 구별한다.

  • 상태마다 제거된 토큰과 목표로 이어지는 행동 집합을 추적한다.

  • 유효성·진단/정상 점수·복구 판본과 오류 위치를 분리한다.

  • 자체 규약과 공식 파일 평가 단위·실제 실행/학생 미수행을 보존한다.
