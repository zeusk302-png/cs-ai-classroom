소단원 9.1

선택도·히스토그램

백만 행을 읽기 전에 조건에 맞는 행이 몇 개인지 어떻게 짐작할까?

준비 개념과 학습 목표

준비 개념

  • 조건을 만족한 행의 개수와 전체 행의 개수는 다르다.

  • 실행 계획은 같은 결과를 얻기 위한 처리 경로다.

학습 목표

  • 선택도와 결과 행 수의 관계를 계산한다.

  • 균등 분포·히스토그램·빈도 정보의 한계를 구분한다.

나머지 집단의 절반이 통과하면 전체의 절반이 통과한 것일까요?

분포 요약이 대표하는 집단을 먼저 적습니다. 인기값 목록은 그 값들의 빈도를 따로 보관하고, 나머지 히스토그램은 NULL과 인기값을 제외한 집단을 대표합니다. 나머지에서의 조건부 비율을 전체 비율로 바꾸려면 나머지가 전체에서 차지하는 비중을 곱해야 합니다.

아래 숫자는 실제 통계 수집 결과가 아니라 명시한 자체 요약입니다. 범위는 bucket 내부를 연속 균등 보간하고, 인기값이 아닌 동등 조건은 나머지 distinct 값들에 균등 배분합니다. 서로 다른 추정 규약이며 실제 행 목록의 정확한 개수를 주장하지 않습니다.

먼저 확인할 개념
  • Bloom filter와 선택성

    조건부 비율의 분모와 전체 비중을 구별하는 계산을 이어 갑니다.

  • 집합·중복·NULL 처리

    일반 비교 조건의 NULL 행을 다른 집단과 중복해서 세지 않습니다.

선택도는 통과하는 비율

선택도는 조건을 통과하는 행의 비율이다. 전체 행 수 N과 선택도 s가 있으면 출력 행 수를 N×s로 추정할 수 있다. 이는 모든 행을 실제로 검사해서 얻은 정답과 구별되며 통계가 오래되거나 표본이 불완전하면 틀릴 수 있다.

서로 다른 값이 D개라는 정보만으로 특정 값이 N/D번 나온다고 단정할 수는 없다. 균등 분포라는 가정이 추가되어야 한다. 인기 강의 하나에 대부분의 수강 기록이 몰리는 예를 생각하면 값 개수만으로 빈도를 알아내기 어렵다.

히스토그램은 분포를 요약

구간별 분포를 요약하면 단순 전체 균등 가정보다 범위 조건을 세밀하게 추정할 수 있다. PostgreSQL의 해당 예제는 같은 빈도의 bucket을 두고 bucket 내부에서는 선형 분포를 가정해 일부 비율을 계산한다. 같은 너비의 bucket과 같은 빈도의 bucket을 혼동하지 않는다.

경계 두 개 사이의 모든 실제 값을 저장한 것은 아니므로 작은 구간 안의 쏠림은 놓칠 수 있다. 아래는 NULL과 별도 인기값이 없고 연속 분포로 보간하는 축소 히스토그램이다. 정수의 경계 등호를 정확히 세는 표와는 다르다.

인기값과 나머지 집단

자주 나타나는 값 목록은 equality 조건을 추정하는 데 도움을 준다. 알려진 인기값은 그 빈도를 사용하고 그 외 값은 남은 비중을 나누는 가정을 할 수 있다. NULL 비중이 있으면 같은 질량을 중복해서 나누지 않는다.

PostgreSQL은 인기값에 해당하는 집단을 제외한 나머지에 히스토그램을 둘 수 있다. 두 부분을 다시 합칠 때에는 각 집단의 비중을 곱해야 한다. 통계 구조 이름보다 어떤 행을 대표하고 어떤 가정을 사용했는지 이해하는 것이 먼저다.

전체 2400행의 자체 통계 요약입니다. NULL 이외 distinct 값은 총 52개이며 인기값은 두 개입니다.

경계 0,10,30,100의 세 equal-frequency bucket

나머지 bucket은 각각 400행을 대표합니다. 경계 너비는 10,20,70이지만 대표 행 수는 같습니다. 인기값을 다시 히스토그램 집단에 포함하지 않습니다.

중간 과정을 따라가는 예제

전체 1000행, NULL과 별도 인기값 없음, 같은 빈도의 bucket 4개가 각각 250행을 대표한다. 경계는 0·10·20·50·100이고 내부는 연속 균등 보간한다고 가정한다. x<35의 추정 행 수와 선택도를 구하자.

  1. 0에서20까지 첫 두 bucket은 총500행이다.

  2. 20–50 bucket에서35까지의 비율은 (35−20)/(50−20)=1/2이므로125행을 더한다.

  3. 추정은625행이고 선택도625/1000=0.625다. 전체0–100 균등 가정으로 얻은350행과 다르다.

히스토그램 축소 모형의 추정은625행·선택도0.625다. 실제 데이터를 센 결과라는 의미는 아니다.

조건을 바꾸어 비교하기

인기값과 나머지 범위 결과를 합칩니다

표에서 x<20의 추정 행 수와 전체 선택도를 구하세요.

  1. 인기값 5는 통과해 600행, 인기값 50과 NULL은 통과하지 않습니다.

  2. 나머지 첫 bucket은 400행이고 둘째는 (20−10)/(30−10)=1/2만 통과해 200행을 추정합니다.

  3. 나머지 통과 비율은 600/1200=0.5입니다. 전체 비율은 0.25+0.50×0.5=0.50입니다.

추정 결과는 1200행이고 전체 선택도는 0.50입니다. 나머지 조건부 0.5를 전체 행 수에 바로 곱한 뒤 인기값까지 더하면 중복 계산합니다.

비교할 점

인기값 빈도는 이 교육 통계에서 주어진 요약입니다. 실제 PostgreSQL 통계도 표본과 갱신 시점 때문에 정확한 현재 전체를 뜻하지 않을 수 있습니다.

동등 조건에는 나머지 distinct 수를 씁니다

같은 요약에서 x=50과 인기값이 아닌 기존 값 x=7의 추정 행 수를 구하세요. 나머지 값의 빈도는 균등하다고 추가 가정합니다.

  1. 값 50은 인기값 목록에 있으므로 0.15×2400=360행입니다.

  2. 나머지 distinct 값은 52−2=50개입니다.

  3. 나머지 1200행을 50개에 나누면 값 7은 24행입니다.

값 50은 360행, 나머지 값 7은 24행으로 추정합니다. 값 7이 실제 그 빈도를 가진다는 보장은 아닙니다.

비교할 점

전체 distinct 수 52로 전체 2400행을 균등 배분하면 인기값과 NULL 정보를 모두 버리게 됩니다.

종이와 본문으로 직접 해보기

같은 모형에서 x<75를 추정하자. 별도의 범주형 열에서는 전체1000행 중 인기값A가400행이고, NULL은0이며 그 외 값이60개라고 하자. 나머지가 균등하면 인기값이 아닌 B의 추정은?

힌트 보기

세 bucket 전체와 마지막 bucket 일부를 더하고, 범주형 문제는 남은 행만 나누자.

풀이 보기

x<75는750+250×(75−50)/(100−50)=875행이다. B는(1000−400)/60=10행이다. A와 B의 빈도를 똑같이 놓으면 주어진 인기값 정보를 버리는 셈이다.

오해와 반례

히스토그램 경계가 있으면 모든 조건의 정확한 행 수를 안다.

bucket 내부 보간과 통계 표본 때문에 추정 오차가 남는다. 같은 bucket 안에 값이 한쪽으로 몰리는 분포는 같은 경계 요약과 다른 실제 범위 결과를 낼 수 있다.

연습 1 · 값과 상태 예측

같은 범위 요약에서 x<65를 추정하세요. 일반 비교의 NULL 처리를 유지합니다.

힌트 1

인기값 5와 50이 모두 통과합니다.

힌트 2

나머지의 첫 두 bucket과 마지막 일부를 셉니다.

풀이와 답 확인

  1. 인기값은 600+360=960행입니다.

  2. 나머지 첫 두 bucket은 800행이고 마지막은 400×(65−30)/(100−30)=200행입니다.

  3. 합계는 1960행이며 전체 선택도는 1960/2400=49/60입니다.

추정은 1960행, 전체 선택도는 49/60, 약 0.8167입니다. NULL 240행은 통과 수에 더하지 않습니다.

흔한 오답에서 다시 생각하기

같은 빈도 bucket이니 마지막 bucket은 65/100만큼 통과합니다.

해당 bucket의 시작 30과 끝 100을 기준으로 내부 비율을 계산해야 합니다.

연습 2 · 오류 찾아 고치기

x<20의 계산에서 나머지 통과 비율 0.5를 전체 2400행에 곱하고 인기값 5의 600행을 더해 1800행을 보고했습니다. 오류를 고치세요.

힌트 1

0.5의 분모가 어느 집단인지 확인합니다.

힌트 2

전체에서 NULL과 인기값을 먼저 분리합니다.

풀이와 답 확인

  1. 조건부 0.5는 나머지 1200행에 적용됩니다.

  2. 나머지 추정 600행에 통과 인기값 600행을 더합니다.

  3. 최종 1200행이고 전체 선택도는 0.5입니다.

1800이 아니라 1200행입니다. 전체 비중 0.50을 조건부 비율 0.5에 곱하는 단계가 빠졌습니다.

흔한 오답에서 다시 생각하기

히스토그램은 전체 자료라는 이름이니 항상 전체 행 수에 곱합니다.

이 요약은 인기값·NULL을 제외한 집단을 대표합니다. 이름 대신 대표 집단을 확인합니다.

연습 3 · 직접 만들어 보기

인기값과 NULL 비중은 표와 같지만 나머지 distinct 값이 25개라고 새로 확인했습니다. 나머지가 균등할 때 비인기 값 하나의 추정을 만들고 원래 50개 모형과 비교하세요.

힌트 1

나머지 행 수는 1200으로 유지합니다.

힌트 2

distinct 수 변화와 행 수 변화는 다른 정보입니다.

풀이와 답 확인

  1. 새 추정은 1200/25=48행입니다.

  2. 원래 50개 모형은 24행이었습니다.

  3. 새 전체 비NULL distinct 수는 인기값 둘을 더해 27개입니다.

새 비인기 값 추정은 48행으로 원래의 두 배입니다. 나머지 distinct 25와 전체 distinct 27을 구별합니다.

흔한 오답에서 다시 생각하기

전체 행 수가 같으니 값별 추정도 그대로입니다.

같은 질량을 더 적은 값에 나누는 가정이므로 값별 추정은 커집니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

나머지 중 10–30 bucket의 400행이 대부분 11 근처에 몰린 경우와 29 근처에 몰린 경우를 비교합니다. bucket의 경계·질량만 유지한 축소 모형에서 이 bucket의 x<20 실제 가능 결과와 균등 추정을 비교하세요.

힌트 1

두 분포에서 경계는 같은 구간을 대표합니다.

힌트 2

실제 행이 통과하는지와 보간을 구별합니다.

풀이와 답 확인

  1. 400행을 전부 11에 둔 자료는 모두 통과하고 전부 29에 둔 자료는 하나도 통과하지 않습니다.

  2. 이 축소 모형에서 bucket 경계는 구간 표시로 고정한 것이며 새 실제 통계를 만들었다는 뜻이 아닙니다.

  3. 균등 보간은 두 경우 모두 200행을 추정합니다.

실제 가능 값 400 또는 0과 추정 200이 다릅니다. 내부 분포를 요약만으로 정확하게 알 수 없습니다.

흔한 오답에서 다시 생각하기

경계가 동일하면 어떤 내부 범위 결과도 같습니다.

경계와 질량은 내부 위치를 모두 저장하지 않습니다. 두 자체 자료의 실제 비교 결과를 추적합니다.

내 말로 설명하기

나머지 조건부 선택도를 전체로 바꾸는 방법은 무엇인가요?

설명 기준 확인

나머지의 전체 비중을 곱하고, 조건을 통과한 인기값 비중을 따로 더합니다.

통계 요약과 실제 결과 개수의 차이는 무엇인가요?

설명 기준 확인

요약은 표본·시점·분포 가정에 의존한 추정이고 실제 결과는 해당 자료와 조건을 모두 대조한 값입니다.

한 단계 더

같은 20–50 bucket이 대표하는 250행을 모두 21 근처에 모은 모형과 모두 49 근처에 모은 모형을 그려 보자. 첫 모형에서 이 bucket의 x<35 행은 250이고 둘째에서는 0이다. 다른 bucket은 동일하게 유지한다. 동일한 bucket 질량만 알아서는 35보다 작은 실제 행 수를 정확히 결정할 수 없다는 점을 확인하자. 이는 내부 균등 가정을 깨는 분포 반례이며 히스토그램 보간 추정 125행과 구별한다.

소단원 9.2

카디널리티 추정 오류

각 조건의 추정이 맞아도 두 조건을 합친 추정은 틀릴 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 조건을 만족한 행의 개수와 전체 행의 개수는 다르다.

  • 실행 계획은 같은 결과를 얻기 위한 처리 경로다.

학습 목표

  • 독립 가정과 상관된 조건을 구분한다.

  • 초기 추정 오차가 후속 연산에 미치는 영향을 추적한다.

각 조건의 빈도만 알면 두 조건의 교집합도 결정할 수 있을까요?

조건 P와 Q를 각각 만족하는 행 수만 알면 교집합이 유일하게 정해지지 않습니다. 독립 곱셈은 두 조건이 독립이라는 추가 가정입니다. 같은 행의 두 열이 연결되어 있으면 교집합과 독립 추정이 달라질 수 있습니다.

아래는 NULL이 없는 1000행을 네 집단으로 직접 정의한 종이 자료입니다. 따라서 표의 실제 논리 개수는 손으로 확인할 수 있습니다. SQL 실행이나 ANALYZE를 수행한 관찰값이 아닙니다. 여러 열 통계의 종류도 서로 다른 질문을 보완하므로 하나의 설정이 모든 결합을 정확하게 만드는 것으로 말하지 않습니다.

먼저 확인할 개념
  • 중첩루프·hash·merge join

    출력 행 수의 오류가 후속 대응 쌍과 탐색량에 미치는 영향을 연결합니다.

  • 병렬 실행·취소

    출력한 행·작업 횟수·완료 상태를 따로 확인합니다.

행 수는 계획 선택의 입력

카디널리티는 여기서 연산이 내보내는 행의 개수다. 필터 결과가 작다고 추정하면 반복해서 탐색하는 방법을 선택할 수 있지만 실제로 크면 반복 횟수가 많이 늘어날 수 있다. 출력 행 수와 내부에서 검사한 행 수를 구별해야 한다.

정확한 전체 행 수만 있으면 모든 조건의 결과도 정확하다는 뜻은 아니다. 조건별 분포, 여러 열의 관계, 시간에 따른 변경을 알아야 한다. 표본 통계를 늘려도 잘못된 독립 가정 자체는 해결되지 않을 수 있다.

곱셈에는 독립이라는 전제

두 조건의 선택도를 곱하면 각 조건이 서로 독립이라는 가정을 사용한 것이다. 성적 열두 개가 복사본처럼 항상 같으면 첫 열의 특정 값과 둘째 열의 같은 값은 독립 사건이 아니다. 첫 조건을 통과한 행에서 둘째 조건도 반드시 참이 될 수 있다.

반대로 서로 모순되는 두 값은 실제 결과가0일 수 있다. 단순한 열별 빈도만 곱하면 양수 추정이 나온다. PostgreSQL의 다변량 통계에는 dependency, 여러 열의 distinct 수, MCV 정보 등 서로 다른 보완 수단이 있으나 모든 쿼리를 완벽하게 예측한다는 보장은 아니다.

오차를 비교할 때 단위를 유지

추정20행과 실제200행의 비는10배다. 이를10행 차이라고 말하면 안 된다. 비율 비교는0일 때 나눗셈이 정의되지 않으므로 실제0인 예는 따로 보고한다. 어떤 노드에서 처음 오차가 커졌는지도 살펴야 한다.

종이 위 후속 비용을 늘리는 모형과 실제 DB 결과는 구분한다. EXPLAIN ANALYZE는 쿼리를 실제 실행하는 관찰 도구이므로 여기서는 실행하지 않는다. 문서의 actual 값과 우리의 가상 행 수를 같은 실험의 결과처럼 표시하지 않는다.

중간 과정을 따라가는 예제

1000행에서 두 열 a,b가 항상 같으며 값0–9가 각각100행에 나타난다. a=2 AND b=2의 독립 추정을 구하고 실제 논리적 개수와 비교하자. 가상 후속 작업은 출력 행마다7단위 비용을 사용한다.

  1. 각 조건 선택도는100/1000=0.1이다. 독립 곱은0.1×0.1=0.01이고 추정은10행이다.

  2. a=b이므로 a=2를 통과한100행이 모두 b=2도 만족한다. 실제 정의된 데이터의 결과는100행이다.

  3. 실제/추정은100/10=10배, 차이는90행이다. 후속 축소 비용은70단위로 추정하지만700단위가 필요하다.

개별 선택도가 정확해도 독립 가정 때문에10배 과소 추정한다. 후속 비용도 이 가상 선형 모형에서는70→700으로 달라진다.

조건을 바꾸어 비교하기

독립 추정의 오차를 원인과 연결합니다

P AND Q의 독립 추정과 표의 결과를 비교하고 후속 행당 7U인 작업의 비용을 구하세요.

  1. 독립 가정은 1000×0.1×0.2=20행입니다.

  2. 표의 교집합은 80행입니다. 실제 논리 개수는 추정의 네 배이며 차이는 60행입니다.

  3. 후속 비용은 추정 20×7=140U, 정의된 결과에서는 80×7=560U입니다.

교집합의 독립 추정은 20행, 표의 논리 개수는 80행입니다. 개별 빈도 오류가 아니라 결합의 독립 가정이 원인입니다.

비교할 점

후속 선형 비용 차이는 이 문제의 행당 고정 모형입니다. 실제 조인·캐시·재분할 비용은 별도입니다.

반복 노드의 출력은 실행당 평균으로 읽습니다

가상 EXPLAIN 형식에서 한 노드의 예상 rows=2, actual rows=4, loops=3입니다. actual rows는 반올림 오차가 없는 실행당 평균이며 다른 worker는 없습니다. 예상과 실제 총 출력, 노드 실행당 오류를 구하세요.

  1. 세 번의 실제 실행에서 총 출력은 4×3=12행입니다.

  2. 같은 세 실행을 예상 평균 2로 계산하면 총 6행입니다.

  3. 노드 실행당 비교는 예상 2와 실제 평균 4입니다. 총 비교도 6과 12로 두 배입니다.

같은 범위의 예상과 실제는 두 배 차이입니다. 실행당 4를 예상 총 6이나 부모의 총 12와 직접 비교하면 범위가 어긋납니다.

비교할 점

실제 출력에는 표시 반올림이 있을 수 있어 평균×loops의 정밀도를 확인합니다. 이 표는 모형 수치이며 실제 질의를 실행한 로그가 아닙니다.

디스크를 덜 읽는 계획이면 언제나 더 빠를까?

준비 개념과 학습 목표

준비 개념

  • 조건을 만족한 행의 개수와 전체 행의 개수는 다르다.

  • 실행 계획은 같은 결과를 얻기 위한 처리 경로다.

학습 목표

  • 서로 다른 비용 요소를 같은 비교 모형으로 합친다.

  • 메모리 초과와 실제 시간 측정의 차이를 설명한다.

실제 행 수가 커지면 같은 비용 계수에서도 선호 계획이 바뀔까요?

비용 계수와 예상 작업량을 분리해서 봅니다. 계획은 같은 질의 결과를 보존하되 순차·임의 페이지 수와 처리 행 수가 다를 수 있습니다. 계수가 정확해도 예상 행 수가 틀리면 비용 비교가 달라집니다.

아래 U는 자체 상대 비용 단위이고 밀리초가 아닙니다. 페이지와 행 비용을 더하는 단순 식은 캐시·병렬 겹침·장치·출력 전달을 모두 구현하지 않습니다. 메모리 적합성은 별도의 바이트 식으로 확인합니다.

먼저 확인할 개념
  • 캐시·직접 I/O·동시성

    캐시 경로와 실제 실행 시간을 비용의 가상 척도와 구별합니다.

  • 메모리·분할·spill

    관리 공간을 포함한 예산과 재분할·spill 조건을 확인합니다.

비용은 서로 다른 작업의 요약

계획에는 page 읽기, 행 처리, 연산자 평가, 메모리 사용 같은 요소가 있다. PostgreSQL의 planner cost는 상대적인 척도이며 기본 설정은 sequential page 비용을 기준으로 한다. cost 숫자를 그대로 밀리초라고 읽어서는 안 된다.

임의로 순차1·임의4·행0.01 같은 계수를 정하면 비교 모형을 만들 수 있다. 계수는 캐시와 장치 환경에 영향을 받는다. 물리적인 임의 읽기의 지연이 언제나 순차의 정확히4배라는 법칙으로 이해하지 않는다.

덜 읽고 더 계산하는 교환

작은 후보만 index로 찾으면 page 읽기를 줄일 수 있지만 많은 후보를 흩어 읽으면 다른 비용이 늘 수 있다. 반대로 전체 순차 탐색은 후보가 많을 때 단순하게 비교할 수 있다. 출력 결과가 같아도 실행 경로의 작업량은 다르다.

아래 두 계획은 비용 비교를 위한 자체 숫자 모형이다. 실제 PostgreSQL planner의 모든 항목을 구현한 식이 아니다. 실제 시간에는 출력 변환과 전달 등 이 단순 모형에 넣지 않은 비용도 있을 수 있다.

메모리는 성능의 조건

정렬이나 hash 작업이 메모리에 맞는지에 따라 disk 사용과 batch 수가 달라질 수 있다. 필요한 바이트를 행 수×가정한 저장 폭으로 계산하되 실제 구조의 header, pointer, allocator 비용은 별도임을 밝힌다.

메모리 예산만 늘리면 모든 계획이 좋아진다는 결론도 조심해야 한다. 동시 작업이 여러 개이면 전체 사용량이 커질 수 있고 데이터 분포가 바뀌면 계획도 달라진다. 문서의 sort method·memory/disk·hash batch 정보는 이런 판단을 위한 관찰 항목이다.

순차 페이지 계수 1U, 행 처리 계수 0.02U이며 임의 페이지 계수는 rU입니다. 두 계획은 같은 결과를 얻는다고 정합니다.
계획페이지 접근처리한 행자체 총비용

A

순차 120페이지

8000행

120+160=280U

B

임의 60페이지

1500행

60r+30U

처리한 행은 출력한 행과 다를 수 있습니다. B의 후보 처리 1500행과 A의 검사 8000행을 비용 입력으로 각각 사용합니다. CPU 계수와 임의 계수는 공통 비교 척도입니다.

중간 과정을 따라가는 예제

가상 단위로 순차 page=1, 임의 page=4, 처리 행=0.01이다. 계획A는 순차100page·10000행, B는 임의20page·1000행만 처리하며 다른 비용은0이다. 별도 hash 자료는1000행×64바이트로 가정하고 예산은48KiB다. 구조 overhead는 제외한다.

  1. A는100×1+10000×.01=200단위다. B는20×4+1000×.01=90단위다. 이 모형은B를 선호한다.

  2. 임의 page 비용만12로 바꾸면B는240+10=250단위로A200보다 커져 선호가 바뀐다.

  3. 자료 크기는64000바이트다.48KiB는49152바이트로14848바이트 부족하다. 이 가정에서는 모두 메모리에 담을 수 없지만 실제 spill량이나 시간은 이 차이만으로 확정하지 않는다.

가상 비용은 계수4일 때B90<A200, 계수12일 때A200<B250이다. 메모리 자료64000바이트는48KiB 예산을 넘는다.

조건을 바꾸어 비교하기

계수를 바꿀 때의 경계를 구합니다

표에서 r=4와 r=5의 선호를 구하고 B가 A보다 엄격히 작은 조건을 쓰세요.

  1. r=4이면 B는 240+30=270U로 A의 280보다 작습니다.

  2. r=5이면 B는 300+30=330U로 A보다 큽니다.

  3. 60r+30<280에서 r<25/6, 약 4.1667입니다. 경계는 동률입니다.

r=4에서는 B, r=5에서는 A를 선호합니다. B의 엄격한 우위는 r<25/6입니다. 실제 장치의 임의 읽기 배율을 측정한 결론은 아닙니다.

비교할 점

모든 계수를 같은 세 배로 바꾸면 A는 840U, r=4의 B는 810U로 선호가 같습니다. 한 계수만 변경한 경우와 구별합니다.

작업량 추정 오류만으로 선호가 바뀝니다

별도 B 계획에서 후보 k행은 서로 다른 페이지당 최대 25행씩 꽉 차게 놓이며 마지막만 짧습니다. 페이지 수는 ceil(k/25)입니다. r=4, 행 계수 0.02를 유지합니다. 예상 k=250, 실제 정의 k=2000일 때 A의 280U와 비교하세요.

  1. 예상 페이지는 10이고 예상 비용은 10×4+250×0.02=45U입니다.

  2. 실제 정의된 페이지는 80이고 비용은 80×4+2000×0.02=360U입니다.

  3. A의 280U와 비교하면 예상은 B가 작지만 수정된 작업량에서는 A가 작습니다.

계수 변경 없이도 B의 비용이 45U에서 360U로 바뀝니다. 행 수와 페이지 배치의 자체 관계를 명시한 모형입니다.

비교할 점

실제 데이터가 이런 페이지 배치를 갖는지 별도 확인해야 합니다. 출력 2000행만으로 임의 페이지가 언제나 80개라고 말할 수 없습니다.

힌트 보기

1KiB=1024바이트이며 비용과 메모리를 따로 계산하자.

풀이 보기

B는 160+10=170단위로 A200보다 작다. 64KiB=65536바이트여서 가상 64000바이트는 1536바이트 여유로 들어간다. 세 작업의 예산 합은 192KiB=196608바이트다. 실제 구조 overhead를 더하면 들어간다는 판단이 바뀔 수 있다.

오해와 반례

EXPLAIN cost가200이면 실제 실행 시간도200ms다.

cost는 설정된 상대 척도이며 실제 시간과 다르다. 위 200은 자체 계수의 계산값이다. actual 시간은 실제 실행 관찰이고 여기서는 측정하지 않았다.

연습 1 · 값과 상태 예측

해시 상태의 행당 가정 폭은 32바이트이고 행은 2000개입니다. 별도 관리 공간 4KiB를 더하고 예산은 64KiB입니다. 적합 여부와 초과량을 구하세요.

힌트 1

KiB는 1024바이트입니다.

힌트 2

자료와 관리 공간을 합쳐 예산과 비교합니다.

풀이와 답 확인

  1. 행 자료는 64000바이트입니다.

  2. 관리 4096을 더하면 68096바이트입니다.

  3. 예산 65536보다 2560바이트 큽니다.

전체 68096바이트로 예산을 2560바이트 초과합니다. 초과량이 실제 spill 파일 크기라는 뜻은 아닙니다.

행 자료만 비교하고 관리 공간을 누락했습니다.

힌트 1

힌트 2

설정 변경만으로 예약이 이루어지는지 확인합니다.

풀이와 답 확인

  1. 이 설정은 질의가 사용할 수 있다고 추정하는 캐시 크기에 관한 planner 가정입니다.

  2. 공유 메모리 크기를 할당하거나 커널 캐시를 예약하는 설정이 아닙니다.

캐시 추정 가정을 바꾼 것이며 실제 4GiB 확보 증거가 아닙니다. 다른 동시 질의와 캐시 중복 범위도 고려합니다.

  1. ① 나머지 비중은 0.50입니다. 전체 선택도는 0.15+0.50×0.25=0.275이고 추정은 660행입니다.

  2. ② 독립 추정은 20행이지만 표로 정의된 교집합은 80행입니다.

  3. ③ A는 280U, B는 270U로 비용 모형은 B를 선호합니다. 해시 상태는 68096바이트로 예산 65536바이트를 2560바이트 넘습니다.

  4. 값은 통계 수집·실제 SQL·메모리 측정 결과가 아닌 명시한 종이 자료와 비용 모형입니다.

① 추정 660행입니다. ② 독립 추정 20행, 실제 논리 개수 80행입니다. ③ 비용은 B의 270U가 작고 별도 해시 메모리는 2560바이트 초과합니다.

해결한 뒤 점검할 것

  • 전체와 조건부 질량·NULL·인기값·나머지를 중복 없이 결합합니다.

  • 개별 통계의 정확성과 결합 독립 가정의 정확성을 구별합니다.

  • 실행당 rows와 전체 loops 범위를 맞추며 분모 0은 따로 보고합니다.

  • 비용 계수·행 수·페이지 배치를 각각 명시합니다.

  • 상대 비용·실제 시간·메모리 할당·추정 가정을 구별합니다.
