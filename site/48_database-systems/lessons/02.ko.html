소단원 2.1

슬롯 페이지·튜플 식별자

페이지 안에서 내용을 옮겨도 같은 레코드를 찾아갈 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 페이지는 저장 관리가 다루는 고정 크기 바이트 묶음이다. 여기서는 1바이트=8비트, 페이지 128바이트, 주소는 정수 오프셋 0…127인 가상 형식을 쓴다. 실제 제품의 페이지 크기는 다르다.

  • 튜플은 한 행의 값 묶음이고 슬롯은 그 튜플의 시작·길이·상태를 찾는 표의 항목이다. [a,b)는 a부터 b−1까지의 바이트이며 길이는 b−a다.

  • 논리 키는 도서 번호 같은 업무 식별 값이고 물리 ID는 저장 위치를 찾는 식별자다. 같은 위치가 재사용될 수 있으므로 두 식별자를 구분한다.

학습 목표

  • 슬롯과 본체의 바이트 구간을 계산한다.

  • 압축 이동의 참조 유지 조건을 설명한다.

  • 슬롯 재사용의 오래된 ID 문제를 증명한다.

빈 공간을 모두 더하면 긴 레코드를 바로 넣을 수 있을까요?

책장 안에 흩어진 빈 칸의 합과 긴 상자 하나가 들어갈 연속 공간은 다릅니다. 아래 페이지도 삭제된 본체 자리에 구멍이 남을 수 있습니다. 살아 있는 본체를 모으는 압축 이동은 같은 슬롯을 유지한 채 위치를 바꾸는 일이고, 삭제한 슬롯에 새 행을 넣는 재사용은 정체성이 바뀌는 일입니다.

자체 페이지는 160바이트이며 헤더 16바이트와 슬롯당 4바이트를 씁니다. 본체는 끝에서 아래로 배치하고 정렬 패딩과 동시 접근은 제외합니다. A의 길이는 32, B는 24, C는 16바이트이며 순서대로 새 슬롯 0, 1, 2에 넣습니다. 삭제 B의 슬롯 항목은 남기고, 이전 독자는 없으며 삭제 본체 공간은 회수 가능하다고 정합니다. lower와 upper 사이만 현재 연속 빈 공간으로 셉니다.

먼저 확인할 개념
  • 슬롯 페이지와 삭제 표시

    슬롯 항목과 본체를 따로 움직이는 이유를 먼저 확인합니다.

  • 시스템 호출과 페이지 자원

    페이지 크기·유효 내용·사용 중인 참조를 구별하는 조건을 사용합니다.

앞에는 표, 뒤에는 본체

자체 형식은 헤더 [0,16), 슬롯 한 개 4바이트, 튜플 본체를 페이지 끝부터 내려오는 순서로 둔다. 슬롯 수 s일 때 lower=16+4s이며 본체 영역 시작을 upper라 한다. 연속 빈 공간은 [lower,upper)다. 0≤lower≤upper≤128, 활성 본체 구간이 서로 겹치지 않는다는 조건이 유효 페이지의 기본 불변식이다.

새 슬롯이 필요한 길이 L의 삽입은 L≥0인 정수이고 4+L≤upper−lower일 때 허용한다. 헤더·슬롯·본문 이외의 정렬 패딩·행 헤더·NULL 표·로그는 이 형식에서 제외했다. 슬롯 재사용 때는 새 4바이트가 필요 없을 수 있지만 기존 본체·삭제 규칙과 세대 검사를 먼저 확인해야 한다.

이동과 정체성을 분리한다

물리 ID를 (page,slot)으로 정하면 본체가 이동할 때 슬롯의 offset만 바꾸고 slot 번호는 유지할 수 있다. 살아 있는 같은 튜플의 길이와 내용이 보존되고, 이동과 표 갱신이 일관되게 관측될 때 참조는 같은 튜플을 찾는다. 본체의 원시 바이트 주소를 저장한 외부 참조는 이동 후 그대로 사용할 수 없다.

PostgreSQL 공식 설명은 ItemId의 위치와 본체 이동을 분리한다. 그러나 실제 CTID는 영구 업무 키가 아니며 행 버전·업데이트·해제 등 수명 규칙이 있다. 여기서는 동시성 없는 단일 페이지 모형을 쓰고 “압축 중 같은 활성 슬롯 유지”라는 좁은 성질만 논증한다.

삭제 후 같은 번호가 다른 튜플을 가리킨다

슬롯 0의 A를 지우고 B를 같은 슬롯에 넣으면 오래된 (page,0) 참조가 B를 가리키는 문제가 생긴다. 해결 모형 하나는 (page,slot,generation)을 사용하고 재사용 때 세대를 증가시키는 것이다. 조회가 현재 세대와 일치할 때만 성공하면 옛 참조를 거절할 수 있다.

유한 세대가 순환하면 충분히 오래된 참조와 다시 같아질 수 있으므로 이 방식도 수명 제한 또는 넘침 없는 범위가 필요하다. 페이지 자체 재사용 역시 별도 세대/객체 식별을 요구한다. 이 단원은 세대가 넘치지 않고 페이지가 유지되는 기간만 다루며 로그·복구·MVCC나 안전한 동시 조회를 구현하지 않는다.

160바이트 자체 페이지에서 삭제 전후의 구간을 비교합니다.
사건lower와 upper빈 공간과 본체

빈 페이지

lower=16, upper=160입니다.

연속 빈 공간은 144바이트입니다.

A, B, C 삽입

lower=28, upper=88입니다.

A는 [128,160), B는 [104,128), C는 [88,104)입니다. 연속 빈 공간은 60바이트입니다.

B 삭제 표시

lower=28, upper=88을 유지합니다.

연속 빈 공간은 60바이트이고 회수 가능한 별도 구멍은 24바이트입니다.

살아 있는 본체 압축 이동

lower=28, upper=112입니다.

A는 [128,160), C는 [112,128)이며 연속 빈 공간은 84바이트입니다.

삭제 표시만 한 상태와 살아 있는 본체를 실제로 모은 상태를 구별합니다. 삭제 직후 회수 가능한 합계 84바이트가 있어도 [lower,upper)의 연속 공간은 60바이트입니다. C의 슬롯 2 offset을 함께 갱신하고 같은 활성 행의 내용과 길이를 유지한다는 조건이 필요합니다.

중간 과정을 따라가는 예제

빈 128바이트 페이지에 새 슬롯을 사용하여 A 길이 20, B 길이 12를 순서대로 삽입한다. lower/upper와 본체 구간, 빈 공간, 이어 길이 74의 C가 새 슬롯으로 들어갈 수 있는지 구하라.

  1. 초기 lower=16, upper=128이며 빈 공간은 112바이트다.

  2. A 슬롯 0은 [16,20), 본체 [108,128)다. lower=20, upper=108, 빈 공간 88이다.

  3. B 슬롯 1은 [20,24), 본체 [96,108)다. lower=24, upper=96, 빈 공간 72다.

  4. C는 슬롯 4+본문 74=78바이트가 필요하므로 72에 들어가지 않는다. 거절 시 페이지 상태를 유지한다.

A/B 본체는 [108,128), [96,108), 빈 공간 72바이트이며 C는 거절한다.

조건을 바꾸어 비교하기

총 빈 공간과 연속 빈 공간

B 삭제 뒤 길이 70바이트인 D를 새 슬롯으로 넣으려 합니다. 아직 압축하지 않은 경우와 압축 이동을 완료한 경우를 비교하세요.

  1. 새 슬롯과 D 본체에는 4+70=74바이트가 필요합니다.

  2. 압축 전 연속 공간은 60바이트이므로 이 삽입 정책은 거절하고 상태를 유지합니다.

  3. 압축 후 연속 공간은 84바이트여서 삽입 가능합니다.

  4. D를 새 슬롯 3에 넣으면 lower는 32, upper는 42이고 D 본체는 [42,112)입니다.

압축 전에는 거절하지만 압축 후에는 새 슬롯 삽입이 가능하며 남는 연속 공간은 10바이트입니다.

비교할 점

기본의 연속 공간 부족에서 삭제 구멍과 압축 이동이라는 새 상태 전이를 추가합니다.

죽은 슬롯 재사용과 새 슬롯 추가

앞 예제의 새 슬롯 삽입을 아직 하지 않은 별도 압축 완료 상태에서 길이 70바이트인 D를 삭제된 슬롯 1에 넣습니다. 슬롯 1의 이전 세대는 5, 새 세대는 6이며 순환은 없다고 정합니다. 새 슬롯 방식과 빈 공간을 비교하세요.

  1. 슬롯 항목 1이 이미 있으므로 새 슬롯 4바이트를 추가하지 않습니다.

  2. D 본체는 [42,112)이고 lower는 28을 유지해 연속 빈 공간은 14바이트입니다.

  3. 오래된 (page,1,5)는 현재 세대 6과 다르므로 거절하고 새 (page,1,6)는 D를 찾습니다.

재사용 방식은 14바이트가 남아 새 슬롯 방식의 10바이트보다 4바이트 많습니다. 옛 B 참조를 D의 참조로 승인하지 않습니다.

비교할 점

살아 있는 C의 이동에서 세대가 유지되는 상황과 삭제된 B의 정체성이 바뀌는 상황을 분리합니다.

종이와 본문으로 직접 해보기

같은 빈 페이지에 길이 10/30/18의 세 튜플을 새 슬롯으로 넣어 각 본체 구간과 최종 빈 공간을 구하라. 슬롯 1을 삭제하고 같은 번호로 새 튜플을 넣으면 세대 5를 가진 옛 ID를 어떻게 처리해야 하는가?

힌트 보기

upper에서 길이를 차례로 뺀다. 삭제와 세대 증가를 본체 이동과 구별한다.

풀이 보기

본체는 [118,128), [88,118), [70,88)다. lower=16+12=28, upper=70, 빈 공간 42바이트다. 재사용 세대를 6으로 정하면 (page,1,5)는 현재 6과 달라 거절한다. 공간 회수 여부는 별도 압축·배치 정책에 달려 있다.

오해와 반례

(page,slot)은 한 번 부여하면 영원히 같은 업무 행을 뜻한다.

삭제한 A의 슬롯을 B에 재사용하면 오래된 ID는 다른 행을 찾는다. 세대·수명 계약이나 영구 논리 키가 필요하다. 슬롯이 안정적인 압축 이동과 삭제 후 재사용은 다른 사건이다.

자기점검

lower=24, upper=96인 빈 공간의 길이는?

답과 이유 보기

72바이트다.

반열린 구간 [24,96)의 길이는 96−24다.

본체 이동 때 슬롯 번호를 유지하면 무엇을 갱신하는가?

답과 이유 보기

offset과 필요한 길이·상태 정보를 일관되게 갱신한다.

참조는 슬롯을 거쳐 새 위치를 찾아야 한다.

세대가 5→6인 슬롯에서 세대 5 ID는?

답과 이유 보기

거절한다.

현재 튜플과 옛 튜플을 구별하며 세대 넘침이 없다는 전제가 있다.

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

삭제하지 않은 A, B, C 상태에서 길이 56인 D를 새 슬롯으로 넣으면 lower와 upper, 남는 공간은? 별도 동일 초기 상태에서 길이 57이라면 어떻게 되나요?

힌트 1

연속 공간은 60바이트입니다.

힌트 2

슬롯에 필요한 4바이트를 먼저 포함합니다.

풀이와 답 확인

  1. 길이 56의 필요량은 4+56=60바이트로 정확히 맞습니다.

  2. 새 lower는 28+4=32이고 새 upper는 88−56=32여서 남는 공간은 0입니다.

  3. 길이 57은 61바이트를 요구하므로 거절하고 lower=28, upper=88을 유지합니다.

길이 56은 정확히 들어가고 길이 57은 거절합니다. 정확히 맞는 경계와 넘는 경계를 나누어 검사합니다.

흔한 오답에서 다시 생각하기

길이 57은 본체가 60보다 작으므로 들어갑니다.

새 슬롯 비용 4바이트도 같은 빈 공간에서 차감합니다.

연습 2 · 오류 찾아 고치기

C 본체를 [88,104)에서 [112,128)로 옮겼는데 슬롯 2의 offset을 88로 남겼습니다. 기존 (page,2) 참조가 같은 C를 찾도록 무엇을 고쳐야 하나요?

힌트 1

참조는 슬롯을 통해 본체 시작을 찾습니다.

힌트 2

동시성이 없는 모형에서도 두 정보가 서로 맞아야 합니다.

풀이와 답 확인

  1. 슬롯 2의 offset을 112로 바꾸고 길이 16과 활성 상태를 유지합니다.

  2. 이동된 본체의 C 내용을 그대로 보존합니다.

  3. 본체와 슬롯 정보를 일관되게 게시합니다. 원시 주소 88을 보관한 외부 참조에는 슬롯 참조의 보장을 적용하지 않습니다.

슬롯 2가 새 C 본체 [112,128)를 가리키도록 갱신해야 합니다. 이동 전 원시 바이트 주소를 안전한 행 식별자로 계속 쓰지 않습니다.

흔한 오답에서 다시 생각하기

슬롯 번호가 같으므로 offset이 틀려도 같은 내용을 읽습니다.

안정적인 번호는 새 위치로 연결되는 항목이 정확할 때만 의미가 있습니다.

연습 3 · 직접 만들어 보기

압축 뒤 삭제된 슬롯 1을 재사용하는 조회 규칙을 만들고, 이전 세대 5와 새 세대 6의 조회 결과를 적으세요. 페이지 자체는 재사용되지 않고 세대도 순환하지 않습니다.

힌트 1

슬롯 존재와 활성 상태부터 확인합니다.

힌트 2

입력 세대와 현재 세대를 비교한 뒤에만 본체를 읽습니다.

  1. 슬롯이 존재하고 활성인지 확인합니다.

준비 개념과 학습 목표

준비 개념

  • heap 파일은 키 순서를 강제하지 않는 레코드 저장 조직이다. 프로그래밍의 메모리 heap과 이름이 같아도 다른 개념이다. heap/정렬 조직과 행/열 배치는 서로 다른 축이다.

  • 행 배치는 한 행의 여러 필드를 가까이 저장하고 열 배치는 한 필드의 여러 행 값을 가까이 저장한다. 튜플 재구성은 서로 다른 열의 같은 행 값을 다시 묶는 작업이다.

  • ⌈x⌉는 x 이상인 가장 작은 정수다. 필요한 데이터가 캐시에 없고 첫 바이트가 블록 경계에 정렬된 연속 영역의 블록을 전부 읽는 가상 모형에서 바이트 S와 블록 B의 읽기 수는 ⌈S/B⌉다.

조직과 배치는 다른 질문이다

heap은 삽입할 빈 공간을 찾는 방식이나 물리 행의 순서를 다룬다. 행 배치는 id/name/score를 행마다 함께 두고, 열 배치는 id열·name열·score열을 나누는 방식이다. 따라서 heap이라는 말만으로 열을 읽는 비용이나 정렬 여부 이외의 모든 내부 배치를 알 수 없다.

자체 표의 행 ID는 0/1/2, score는 7/2/9, name은 가/나/다다. 열 배열이 공통 행 ID 순서를 유지하면 score[1]과 name[1]은 행 1에 속한다. 각 열을 독립 정렬한다면 배열 위치만으로 결합하지 못하며 원래 행 ID 또는 순열 매핑을 함께 보존해야 한다.

좁은 스캔의 이득에는 조건이 있다

자체 비용 모형은 100행, 행마다 네 개의 4바이트 필드, 64바이트 블록, 메타데이터·패딩·압축·인덱스 없는 정렬된 연속 영역을 둔다. score 합을 위해 행 배치에서 필요한 모든 행 블록을 읽으면 1600/64=25블록이다. 독립 열 영역에서는 score 400바이트만 읽어 ⌈400/64⌉=7블록이다.

이 차이는 해당 스캔과 냉간 캐시 조건의 논리적 블록 수다. 실제 페이지 헤더·압축·read-ahead·캐시 적중·인덱스·장치 요청 병합은 달라질 수 있다. 반대로 한 행의 네 필드만 필요하면 열마다 다른 블록을 요구할 수 있어 행 배치가 유리하다. 저장 모델의 선택은 요청 분포와 업데이트 방식까지 함께 본다.

열 재구성은 같은 행을 묶는 증명이다

score를 값 순서로 정렬하면 (2,행1),(7,행0),(9,행2)가 된다. 첫 score 2에 name 배열의 첫 위치 가를 붙이면 실제 나와 다르므로 틀린 행이 만들어진다. 각 항목의 행 ID 1을 이용해 name[1]=나를 찾아야 한다. 정렬·삭제·압축 후에도 모든 열의 매핑이 같은 논리 행을 뜻하는지 검사한다.

NULL과 삭제 상태도 값과 별도의 정보다. NULL을 정수 0으로 바꾸면 score가 실제 0인 행과 구별하지 못한다. 삭제된 행 위치를 한 열만 제거하면 이후 공통 위치가 어긋난다. 모든 열을 같은 순열로 이동하거나 각 열에 행 ID 매핑을 유지하는 것이 이 모형의 계약이며 실제 DB의 트랜잭션 처리와는 구분한다.

가변길이·압축·삭제

레코드를 삭제 표시만 하면 그 바이트는 바로 다시 써도 될까?

준비 개념과 학습 목표

준비 개념

  • 가변길이 값은 값마다 저장 바이트 수가 다르다. 문자 수와 바이트 수는 인코딩에 따라 다르며 여기서는 이미 인코딩된 바이트 문자열의 길이를 다룬다.

  • 무손실 압축은 복호화하면 원래 바이트를 그대로 얻는 표현이다. 사전 코드는 값을 가리키는 짧은 정수이며 사전·코드 폭·순서 정보도 저장 비용이다.

  • 논리 삭제는 보이지 않도록 상태를 바꾸는 것이고 물리 회수는 저장 공간을 재사용하는 것이다. 오래된 읽기나 참조가 있으면 두 시점이 달라질 수 있다.

학습 목표

  • 가변길이 offset/length 범위를 확인한다.

  • 사전과 코드의 총 크기를 함께 계산한다.

  • 삭제·압축·참조 수명·정보 제거를 구분한다.

사전에서 값 하나를 지우면 나머지 코드는 그대로 사용할 수 있을까요?

자주 반복되는 긴 값을 짧은 번호로 쓰려면 번호의 뜻을 적은 사전이 필요합니다. 번호 자체가 짧아도 사전과 헤더를 함께 저장해야 원래 값을 복원할 수 있습니다. PostgreSQL TOAST 문서는 큰 값의 압축과 외부 저장을 구별하지만 아래 고정 길이 사전은 그 구현을 복제한 형식이 아닙니다.

첫 자체 압축 모형에는 길이 6바이트인 값 여덟 개와 서로 다른 값 두 개가 있습니다. 사전은 두 원값을 그대로 저장하고 행 코드는 고정 1바이트, 추가 헤더는 4바이트입니다. 원문 비교에서는 여덟 원값 48바이트만 세고 두 방식에서 공통인 다른 비용은 제외합니다. 삭제 비트맵을 추가하는 경우에는 그 1바이트도 명시적으로 더합니다. 오래된 독자와 사전 재번호화는 별도 조건입니다.

먼저 확인할 개념
  • 압축과 교집합

    짧은 표현의 비용과 원래 값을 복원하는 계약을 연결합니다.

  • 참조계수와 수명

    삭제된 값을 읽는 오래된 독자가 있을 때 언제 회수할 수 있는지 판단합니다.

길이 정보도 표현의 일부다

길이 3/5/2바이트인 값 세 개를 연속 본문에 저장하면 offset은 0/3/8, 마지막 끝은 10이다. 읽기는 [offset,offset+length)의 범위를 확인하고 페이지·외부 블록 경계를 넘는지 검사한다. 실제 형식에는 길이 헤더, NULL 표시, 정렬과 외부 저장 참조가 더해질 수 있다.

PostgreSQL TOAST는 큰 가변길이 값을 압축하거나 외부 조각으로 보관하는 공식 사례다. 본문의 가상 형식은 이 제품의 포인터 크기를 복제하지 않는다. 외부 저장을 쓰면 주 페이지가 작아져도 필요한 값을 읽을 때 별도 저장과 복호화 비용이 생기므로 주 페이지 바이트 감소를 총 비용 감소로 동일시하지 않는다.

사전 크기까지 더해야 압축률을 안다

자체 바이트 값 여섯 개가 길이 4인 AAAA/BBBB/AAAA/AAAA/BBBB/AAAA라고 하자. 원문은 24바이트다. 사전 두 값 8바이트와 고정 1바이트 코드 여섯 개를 저장하고 그 밖의 헤더·길이 비용은 없다고 정하면 총 14바이트, 절감 10바이트다. 사전 순서와 코드 해석을 고정해야 원래 순서를 복원할 수 있다.

서로 다른 길이 4 값 여섯 개라면 사전 24+코드 6=30바이트로 원문보다 커진다. 동일 데이터에 항상 압축률이 좋다는 주장은 이 반례로 거절한다. 실제 압축에는 사전 메타데이터·NULL·코드 폭·갱신·CPU·전송 비용이 필요하며 문자열 의미 변환이나 반올림을 무손실 압축과 섞지 않는다.

삭제와 회수에는 관측 수명이 있다

자체 단일 버전 모형에서는 슬롯을 DEAD로 바꾸면 새 조회가 거절된다. 본체 바이트를 곧바로 덮어써도 되는 것은 더 읽는 주체와 외부 참조가 없고 회수 계약이 허용할 때다. 오래된 스냅샷이 읽을 수 있는 모형이라면 삭제 표시와 공간 회수 사이에 대기 또는 버전 보존이 필요하다.

압축 이동은 살아 있는 본체를 모으고 offset을 갱신하는 과정이다. 슬롯을 재사용할 때는 ID 세대와 참조 수명을 확인한다. 또한 삭제 표시가 백업·로그·복제본·사전에서 내용을 제거했다는 뜻은 아니다. 보존·보안 정책은 별도 층이며 이 종이 모형으로 실제 데이터의 완전 소거를 판정하지 않는다.

길이 4바이트인 두 값 A/B의 여섯 행 사전 압축을 위 형식으로 저장한다. 행 2 하나를 논리 삭제하되 두 값 모두 나머지 행에도 남아 있다. 코드 6개와 삭제 bitmap 1바이트를 계속 보존할 때 총량과 새 조회 행 수, 나중에 물리 재작성 후 코드 5개/bitmap 1바이트의 총량은?

  1. 사전 8바이트와 코드 6바이트는 그대로며 삭제 bitmap 1바이트를 더해 15바이트다.

  2. bitmap이 행 2를 삭제로 표시하여 새 조회는 6−1=5행을 보인다. 논리 삭제만으로 코드를 줄이지 않는다.

  3. 기존 독자·참조가 더 없다는 조건에서 전체 재작성하며 생존 행 코드 다섯 개를 순서대로 붙인다. 사전의 두 값은 모두 남는다.

  4. 새 저장은 사전 8+코드 5+bitmap 1=14바이트다. 재작성 중 old/new 동시 존재의 최고 사용량은 별도 비용이다.

논리 삭제 후 15바이트/5행, 재작성 후 14바이트다. 삭제 시점과 회수 시점을 분리한다.

조건을 바꾸어 비교하기

삭제 표시와 재작성 최고 공간

여덟 값 모형에서 행 하나를 삭제하고 두 사전 값 모두 생존 행에 남습니다. 삭제 비트맵 1바이트를 추가하고 기존 코드 여덟 개는 유지합니다. 오래된 독자가 사라진 뒤 생존 일곱 행을 재작성하며 새 형식도 비트맵 1바이트를 둡니다. 기존 형식 전체를 유지한 채 새 형식 전체를 먼저 할당한다고 정하면 최고 공간은?

  1. 삭제 표시 직후는 사전 12+코드 8+헤더 4+비트맵 1=25바이트이며 새 조회 행은 일곱 개입니다.

  2. 재작성한 형식은 사전 12+코드 7+헤더 4+비트맵 1=24바이트입니다.

  3. 재작성 도중 두 전체 형식이 함께 있으면 25+24=49바이트입니다.

삭제 표시 직후 25바이트, 재작성 후 24바이트이며 정한 동시 보관 정책의 최고 공간은 49바이트입니다.

비교할 점

기본의 최종 크기 비교에 헤더와 old/new 동시 보관의 최고 공간을 추가합니다.

사전 재번호화는 코드도 함께 바꿉니다.

별도 사전은 코드 0이 AAAAAA, 코드 1이 BBBBBB, 코드 2가 CCCCCC이고 행 코드는 [2,0,2]입니다. 가운데 행을 삭제해 C 값 두 행만 남으며 이전 독자는 없다고 정합니다. 사전에서 C만 남겨 코드 0으로 바꿀 때 생존 코드는?

  1. 원래 세 행의 값은 C, A, C입니다.

  2. 가운데 삭제 뒤 생존 값은 C, C입니다.

  3. 새 사전은 코드 0이 C이므로 생존 코드 둘을 모두 0으로 갱신합니다.

새 코드 목록은 [0,0]입니다. 새 사전에 코드 2가 없으므로 이전 [2,2]를 그대로 두면 복원이 실패합니다.

사전의 값 수를 줄이는 일과 모든 관련 코드의 의미를 일관되게 갱신하는 일을 함께 확인합니다.

종이와 본문으로 직접 해보기

길이 3 값 네 개가 X/Y/X/Y이며 서로 다른 값 두 개, 코드는 1바이트, 추가 헤더 없음으로 정한다. 원문과 압축 크기를 구하라. X의 두 행을 모두 삭제해도 오래된 읽기가 X를 볼 수 있다면 사전 X를 즉시 없애도 되는가?

힌트 보기

원문은 네 값, 사전은 두 값, 코드는 네 개다. 삭제된 행을 볼 수 있는 독자의 계약을 먼저 본다.

풀이 보기

원문 4×3=12바이트, 사전 2×3+코드 4=10바이트다. 오래된 독자가 X 코드로 복원해야 하면 사전 X를 즉시 없애면 안 된다. 독자의 수명 종료나 별도 옛 사전 보존 후 회수할 수 있다. 사전 재번호화는 모든 관련 코드도 함께 갱신해야 한다.

행을 삭제했으므로 공간·사전·백업에서도 그 내용이 즉시 사라진다.

연습 1 · 값과 상태 예측

여덟 값 모형의 서로 다른 값 수를 5, 6, 7로 바꾸세요. 길이 6바이트, 코드 1바이트, 추가 헤더 4바이트는 같습니다. 각각 전체 크기와 원문 48바이트 대비 절약 여부를 구하세요.

힌트 1

사전 크기는 서로 다른 값 수에 6을 곱합니다.

힌트 2

풀이와 답 확인

  2. 서로 다른 값 여섯 개는 6×6+8+4=48바이트로 동일합니다.

  3. 서로 다른 값 일곱 개는 7×6+8+4=54바이트로 6바이트 더 큽니다.

각각 42, 48, 54바이트입니다. 반복이 있어도 추가 표현 비용까지 합하면 절약이 없거나 증가할 수 있습니다.

연습 2 · 오류 찾아 고치기

본문 버퍼 길이는 250바이트, offset은 240, length는 20바이트입니다. 잘못된 검사는 offset+length를 계산한 값을 부호 없는 8비트 저장 칸에 넣어 4로 만든 뒤 4<=250이라 승인합니다. 수학적 범위를 확인하고 안전한 조건을 쓰세요.

힌트 1

실제 끝은 240+20=260입니다.

힌트 2

offset을 확인한 뒤 남은 용량과 length를 비교하면 넘치는 덧셈을 피할 수 있습니다.

풀이와 답 확인

  1. 실제 구간 [240,260)은 버퍼 끝 250을 10바이트 넘습니다.

  2. offset과 length가 비음수이고 offset<=250인지 먼저 검사합니다.

  3. 이 조건을 통과한 뒤 length<=250−offset을 검사합니다. 여기서는 20<=10이 거짓이므로 거절합니다.

이 입력은 범위를 넘으므로 거절합니다. 범위 확인 전 작은 정수 폭의 덧셈 순환을 유효 길이로 해석하지 않습니다.

연습 3 · 직접 만들어 보기

사전 재번호화 예제의 삭제를 새 독자에게는 적용했지만 옛 독자 R이 원래 가운데 A를 읽을 수 있습니다. 새 형식과 옛 형식을 어떻게 유지해야 하나요?

힌트 1

옛 R의 코드 0과 새 코드 0의 뜻이 다릅니다.

힌트 2

독자마다 어느 사전과 코드 버전을 읽는지 정합니다.

풀이와 답 확인

  1. 옛 독자 R에는 옛 코드 [2,0,2]와 사전의 A, B, C 의미를 유지합니다.

  2. 새 독자에는 생존 코드 [0,0]과 C만 있는 새 사전을 연결합니다.

  3. R의 수명이 끝나거나 같은 의미를 유지하는 다른 보존 경로가 마련되기 전에는 옛 형식을 회수하지 않습니다.

새 조회에서 삭제가 보이지 않는 것과 옛 독자의 자료를 회수할 수 있는 시점은 다릅니다. 각 독자에게 일관된 코드와 사전 버전을 제공해야 합니다.

흔한 오답에서 다시 생각하기

새 사전의 코드 0이 있으니 옛 독자의 코드 0도 그대로 읽으면 됩니다.

옛 코드 0은 A였고 새 코드 0은 C입니다. 번호만 같고 의미가 달라 옛 읽기를 깨뜨립니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 모형에 길이 4바이트인 값 600개와 서로 다른 값 300개가 있습니다. 사전에는 원값을 그대로 두고 모든 행의 고정 코드에는 필요한 최소 정수 바이트 수를 쓰며 추가 헤더는 10바이트입니다. 한 바이트가 256개 코드를 표현할 때 코드 폭과 전체 크기를 원문과 비교하세요.

힌트 1

300개 값은 코드 256개로 모두 표현할 수 없습니다.

힌트 2

두 바이트 코드를 600행 모두에 적용합니다.

풀이와 답 확인

  1. 두 바이트는 65536개 코드를 표현하므로 필요한 고정 코드 폭은 2바이트입니다.

  2. 사전은 300×4=1200바이트이고 코드는 600×2=1200바이트입니다.

  3. 전체는 1200+1200+10=2410바이트이며 원문은 600×4=2400바이트입니다.

고정 코드 폭은 2바이트이며 전체는 원문보다 10바이트 큰 2410바이트입니다. 실제 압축 알고리즘의 결과가 아닌 자체 고정 폭 형식입니다.

흔한 오답에서 다시 생각하기

행 코드가 짧으니 서로 다른 값 300개도 한 바이트로 표현합니다.

모든 사전 값을 서로 다른 코드로 찾을 수 있어야 합니다. 표현 가능한 코드 수를 먼저 검사합니다.

한 단계 더

양의 정수 길이 ℓ≥1인 n≥1개 값에 서로 다른 값 1≤d≤n개, 양의 정수 코드 폭 c≥1바이트, 비음수 정수 추가 메타데이터 h≥0바이트인 고정 길이 사전 모형은 원문 nℓ, 압축 dℓ+nc+h다. 절약 조건은 (n−d)ℓ>nc+h다. n=d이면 왼쪽 0, 오른쪽 양수이므로 절약할 수 없다. 코드로 d개 값을 표현할 수 있는 폭과 사전의 전단사 값 매핑·행 순서 보존을 가정하면 복호화는 각 코드의 원값을 찾아 원문을 재구성한다. 추가 NULL이나 가변 길이는 별도 메타데이터를 합산한다.

  1. D의 필요량은 4+80=84바이트로 정확히 맞습니다. 새 lower는 32이고 새 upper도 32라 빈 공간은 0입니다.

  2. 행 배치 평균은 16블록입니다. 열 배치 평균은 0.25×6+0.75×18=15블록입니다.

  3. 사전 형식은 5×6+8+4=42바이트로 원문 48바이트보다 6바이트 작습니다.

  4. 삭제된 값을 읽을 수 있는 옛 독자가 있다면 해당 코드와 사전의 의미를 보존해야 합니다. 같은 슬롯 재사용에서는 옛 세대 참조를 구별해야 합니다.

  5. 모든 결과는 자체 종이 모형이며 실제 DBMS·압축 프로그램·장치·학생 실험은 미수행입니다.

길이 80의 D는 새 슬롯 비용까지 포함해 정확히 들어가며 연속 빈 공간은 0바이트입니다. 지정한 질의 혼합의 평균은 행 배치 16블록, 열 배치 15블록입니다. 사전 전체는 42바이트로 원문보다 6바이트 작습니다. 회수 전에는 옛 독자와 코드·슬롯 식별자의 수명을 확인해야 합니다.

해결한 뒤 점검할 것

  • 슬롯 비용과 연속 공간을 함께 계산한다.

  • 원래 행 ID와 정렬 위치를 구별한다.

  • 질의 비율과 블록 경계를 비교 조건에 포함한다.

  • 사전·코드·헤더와 최고 공간을 누락하지 않는다.

  • 삭제 가시성과 독자의 수명·물리 회수를 나누어 설명한다.
