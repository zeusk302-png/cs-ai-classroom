소단원 7.1

외부정렬·aggregation

공책에 전부 올릴 수 없는 목록은 어떻게 정렬할까?

준비 개념과 학습 목표

준비 개념

  • 정렬

  • 페이지와 버퍼

  • 합과 평균

학습 목표

  • 외부 병합 정렬의 통과 수와 I/O를 계산한다.

  • 그룹 집계의 결합 상태를 설명한다.

작은 정렬 목록을 먼저 만든다

외부 정렬은 메모리에 한 번에 들어오지 않는 자료를 저장 장치와 함께 정렬한다. B페이지를 읽어 내부 정렬한 다음 임시 정렬 목록 run으로 쓰는 초기 단계를 생각하자.

N페이지면 초기 run 수는 ceil(N/B)다. 이후 여러 정렬 목록의 가장 앞 값을 비교하며 한 정렬 목록으로 병합한다. 데이터가 메모리에 들어간다는 내부 정렬 가정과 다르다.

병합 폭과 I/O 조건을 명시한다

한 페이지를 출력 버퍼에 쓰면 최대 B−1 개 입력 run을 동시에 병합할 수 있다. B는 이 연산에 실제 사용할 수 있는 버퍼 수이며 다른 연산의 메모리를 중복 계산하지 않는다.

모든 통과에서 전체를 읽고 전체를 다시 저장하는 단순 모델은 통과당 2N I/O다. 마지막 결과를 다음 연산으로 바로 보내거나 run을 길게 만드는 최적화는 이 계산에 포함하지 않는다.

집계는 그룹별 상태를 줄인다

aggregation은 같은 그룹의 여러 행을 COUNT·SUM·AVG 같은 상태로 줄이는 작업이다. 정렬한 뒤 같은 키를 연속 처리하거나 해시로 그룹별 상태를 찾는 방법을 생각할 수 있다.

부분 평균끼리 무조건 평균 내면 안 된다. 합과 개수를 함께 결합해 최종 평균을 구해야 서로 다른 크기의 부분 집단을 올바르게 반영한다. 그룹 상태가 메모리를 넘으면 외부 처리 조건이 다시 필요하다.

중간 과정을 따라가는 예제

N=20 페이지, B=4 버퍼다. 초기 run 생성과 모든 병합 결과를 디스크에 저장하며 출력 읽기 추가 비용은 제외한다. 필요한 통과 수와 I/O를 계산하자. 별도 그룹 A의 값은 2 와 8, B의 값은 5 다.

  1. 초기 run은 ceil(20/4)=5 개이며 초기 통과에서 40 I/O를 쓴다.

  2. fan-in=3 이므로 병합 뒤 run 수는 5→2→1 이다. 병합 두 번과 초기 한 번을 합쳐 3 통과다.

  3. 총 I/O는 2×20×3=120 이다. 집계는 A: 합 10/개수 2/평균 5, B: 합 5/개수 1/평균 5 다.

정렬은 3 통과·120 페이지 I/O다. 두 그룹 평균이 모두 5 여도 개수와 합은 다르다.

종이와 본문으로 직접 해보기

부분 집단 평균이 2(1 개)와 8(3 개)이면 합친 평균을 계산하자.

힌트 보기

각 평균에 그 집단의 개수를 곱해 합으로 되돌린다.

풀이 보기

(2×1+8×3)/(1+3)=26/4=6.5 다. 단순 평균 (2+8)/2=5 는 틀리다.

오해와 반례

입력 run을 만들었으면 병합은 항상 한 번이면 끝난다.

B=4 에서 run 5 개를 fan-in 3 으로 처리하면 두 병합 통과가 필요하다. 메모리와 run 수를 함께 확인한다.

자기점검

B=6 이면 이 예의 통과 수는?

답과 이유 보기

2 통과다.

초기 ceil(20/6)=4 개를 fan-in5 로 한 번에 병합하므로 총 80 I/O다.

집단 평균의 단순 평균은 항상 정확한가?

답과 이유 보기

아니다.

집단 크기가 다르면 합과 개수를 이용해야 한다.

120 I/O에 마지막 결과의 추가 스캔이 포함되나?

답과 이유 보기

포함되지 않는다.

모든 통과의 쓰기까지 포함하며 소비자의 추가 읽기는 제외했다.

한 단계 더

B를 3,4,6 으로 바꾸고 run 수가 줄어드는 층을 그려 I/O의 계단 변화를 비교하자.

소단원 7.2

중첩루프·hash·merge join

같은 학생 번호를 가진 두 표에서 같은 번호가 여러 번 나오면 몇 쌍이 생길까?

준비 개념과 학습 목표

준비 개념

  • 관계형 테이블

  • 동등 조건

  • 페이지 버퍼

학습 목표

  • 세 조인 방식의 비교 경로와 조건을 구별한다.

  • 중복 키 결과와 블록 중첩루프 비용을 계산한다.

중첩루프는 후보 쌍을 비교한다

중첩루프 조인은 한쪽 행 또는 행 묶음을 잡고 다른 쪽을 확인한다. 인덱스가 없다면 내부 표를 반복 읽는 비용이 커질 수 있다. 블록 방식은 여러 외부 페이지를 한꺼번에 보관해 반복 횟수를 줄인다.

B버퍼 중 내부 입력 하나와 출력 하나를 남기면 외부 묶음은 B−2 페이지다. 이 단순 모델의 입력·중간 I/O는 M+ceil(M/(B−2))N이며 결과 출력 비용은 제외한다.

해시 조인은 같은 키 후보를 찾는다

기본 해시 조인은 build 쪽의 키를 해시 테이블에 넣고 probe 쪽에서 같은 버킷을 찾는다. 기본 형태는 완전한 동등 조인 키에 적용한다. 해시값이 같아도 원래 키가 다를 수 있으므로 실제 동등 비교가 필요하다.

동일 키의 여러 행을 하나로 지우면 조인 결과가 바뀐다. 양쪽에 같은 키가 각각 a개와 b개면 그 키의 짝은 a×b개다. build 자료와 관리 비용이 메모리에 들어오는지 따로 확인한다.

병합 조인은 정렬 순서를 이용한다

정렬 병합은 키가 작은 쪽을 앞으로 옮기며 일치하는 그룹을 만난다. 이미 정렬되어 있는지와 정렬 비용을 함께 고려해야 한다.

중복 키 그룹에서는 모든 조합을 내야 한다. 입력 키가 거의 유일한 상황의 선형 병합 비용을 모든 중복 자료의 최악 비용으로 주장하면 안 된다. 결과 자체가 아주 많을 수도 있다.

중간 과정을 따라가는 예제

표 R은 12 페이지, S는 30 페이지이며 B=5 다. 인덱스 없는 블록 중첩루프의 두 외부 표 선택 비용을 구하자. 별도 작은 표의 R 키는 1,2,2 이고 S 키는 2,2,3 이며 행을 중복 제거하지 않는 inner equijoin을 한다.

  1. 외부 묶음은 5−2=3 페이지다. R 외부는 12+ceil(12/3)×30=12+120=132 I/O다.

  2. S 외부는 30+ceil(30/3)×12=30+120=150 I/O다. 출력 비용과 CPU 비교는 제외한 입력 모델이다.

  3. 키 2 의 R 행 두 개와 S 행 두 개를 각각 구별해 2×2=4 쌍을 낸다. 키 1 과 3 은 상대가 없어 출력하지 않는다.

이 조건에서는 R 외부의 132 I/O가 S 외부 150 보다 작다. 작은 표 조인 결과는 4 행이다.

종이와 본문으로 직접 해보기

R의 키 2 가 세 행, S의 키 2 가 네 행이면 결과 행 수는?

힌트 보기

각 R 행에 S의 네 행이 모두 대응한다.

풀이 보기

3×4=12 행이다. 해시나 병합을 썼다는 이유로 중복 조합을 줄이지 않는다.

오해와 반례

해시값이 같으면 원래 키도 같다.

서로 다른 키가 같은 버킷에 들어가는 충돌이 가능하다. 버킷 후보를 찾은 뒤 원래 조인 키를 비교해야 한다.

자기점검

hash join의 기본 조건이 < 비교에도 그대로 맞나?

답과 이유 보기

아니다.

여기서는 완전한 동등 키 비교의 후보 분할을 가정한다.

정렬 병합의 정렬 비용을 빼도 되나?

답과 이유 보기

입력이 이미 정렬된 등의 근거가 있어야 한다.

그렇지 않으면 정렬도 수행해야 한다.

4 행 결과를 한 키 2 행으로 바꿔도 같은 조인인가?

답과 이유 보기

아니다.

중복 행을 보존하는 조인의 모든 대응 쌍이 사라진다.

한 단계 더

R의 두 키 2 행을 r1/r2, S의 두 행을 s1/s2 로 이름 붙여 해시와 병합에서 동일한 네 쌍이 나오는지 적어 보자.

소단원 7.3

메모리·분할·spill

해시 표가 메모리에 안 들어가면 저장 장치로 옮기는 것만으로 해결될까?

준비 개념과 학습 목표

준비 개념

  • 해시 조인

  • 페이지 I/O

  • 메모리 상한

학습 목표

  • Grace 분할의 보존 조건과 비용을 설명한다.

  • 편향·메모리 관리 비용·동시 실행 한계를 구별한다.

spill은 중간 상태를 밖으로 내보낸다

spill은 연산 중간 자료를 임시 저장 장치에 내보내 메모리 부담을 줄이는 일이다. 읽기·쓰기·임시 용량과 이후 재처리 비용을 함께 부담한다. 원본 테이블을 영구 변경하는 뜻은 아니다.

버퍼 풀 전체가 한 연산의 메모리인 것은 아니다. 해시 테이블의 행·포인터·버킷 같은 관리 공간과 동시에 실행하는 연산을 포함해 실제 사용할 예산을 정한다.

대응 쌍은 같은 파티션으로 보낸다

Grace 해시 조인은 두 입력을 같은 조인 키 해시로 나누어 대응하는 파티션끼리 처리한다. 같은 키가 서로 다른 파티션으로 가면 결과 쌍을 놓치므로 분할 규칙을 양쪽에 맞춘다.

한 단계 분할의 읽기와 쓰기, 뒤 처리의 읽기를 합하면 3(M+N) I/O의 단순 모델을 얻는다. 모든 build 파티션이 허용 메모리에 들어오고 추가 재분할이 없으며 결과 출력은 제외할 때의 식이다.

편향은 평균 파티션 크기로 숨기지 않는다

평균 크기가 작아도 특정 키가 많이 반복되면 한 파티션이 커질 수 있다. 서로 다른 키를 새 해시로 다시 분할하는 것과 동일 키 집단을 줄이는 것은 다르다.

동일 키를 키 해시만으로 재분할하면 여전히 함께 모인다. 큰 동일 키 그룹에는 묶음 처리와 상대 입력 반복 확인 등 별도 전략이 필요하며 모든 대응 쌍을 유지해야 한다.

중간 과정을 따라가는 예제

R=12 페이지, S=30 페이지를 균등하게 네 파티션으로 나눈다. 예제는 각 R 파티션의 해시 표가 관리 비용까지 포함해 3 페이지 상당이며 사용 가능한 build 예산 3 페이지에 들어온다고 가정한다. 분할·재읽기 외 비용과 결과 출력은 제외한다. 별도 호스트의 쿼리 가용 128 MiB에 각 64 MiB가 필요한 네 쿼리를 모두 동시 실행할 수 있는가?

  1. 총 입력은 12+30=42 페이지다. 분할에서 읽기 42+쓰기 42=84 I/O를 쓴다.

  2. 대응 파티션 처리에 총 42 페이지를 다시 읽어 84+42=126 I/O다. 파티션별 S는 평균 7.5 페이지 상당이어도 스트리밍 probe이므로 S 전체 동시 적재를 가정하지 않는다.

  3. 네 쿼리 요구는 4×64=256 MiB로 128 을 넘는다. 추가 비용을 제외한 단순 예산에서는 두 쿼리까지만 동시에 64 MiB를 줄 수 있다.

한 단계 분할 모델은 126 I/O다. 별도 메모리 모델의 동시 실행 상한은 2 개이며 실제 관리 비용이 있으면 더 줄 수 있다.

종이와 본문으로 직접 해보기

R의 12 페이지가 모두 같은 조인 키라면 키 해시를 바꾸어 네 파티션으로 다시 나눌 때 build 크기가 꼭 3 페이지가 되는가?

힌트 보기

같은 입력 키에 같은 함수 결과가 나오는 성질을 보자.

풀이 보기
