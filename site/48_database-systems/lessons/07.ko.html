소단원 7.1

외부정렬·aggregation

공책에 전부 올릴 수 없는 목록은 어떻게 정렬할까?

준비 개념과 학습 목표

준비 개념

  • 정렬

  • 페이지와 버퍼

  • 합과 평균

학습 목표

  • 외부 병합 정렬의 통과 수와 I/O를 계산한다.

  • 그룹 집계의 결합 상태를 설명한다.

버퍼 한 페이지를 더 주었는데 정렬 비용이 그대로인 이유는 무엇일까요?

외부 정렬은 메모리에 들어오는 작은 목록을 먼저 정렬해 임시 저장하고, 여러 목록의 맨 앞 값을 비교해 긴 정렬 목록으로 합칩니다. 이 목록을 run이라고 부릅니다. 입력 목록마다 한 페이지를 읽을 자리와 결과 한 페이지를 모을 자리가 필요합니다.

페이지 I/O 한 번은 페이지 하나를 읽거나 쓰는 것으로 셉니다. 이 단원은 빈 캐시에서 고정된 자료를 처리하는 손모형입니다. CPU 시간·압축·레코드 ID를 나중에 가져오는 비용·추가 헤더·재시도는 비용 식에서 제외합니다. 같은 페이지 수라도 실제 실행 시간은 다를 수 있습니다.

먼저 확인할 개념
  • 교체정책·prefetch

    겹쳐 읽기와 페이지 읽기 횟수의 절감이 서로 다른 효과임을 구별합니다.

  • SELECT·필터·정렬

    정렬이 필요한 질의와 결과를 일부만 원하는 질의를 연결합니다.

작은 정렬 목록을 먼저 만든다

외부 정렬은 메모리에 한 번에 들어오지 않는 자료를 저장 장치와 함께 정렬한다. B페이지를 읽어 내부 정렬한 다음 임시 정렬 목록 run으로 쓰는 초기 단계를 생각하자.

N페이지면 초기 run 수는 ceil(N/B)다. 이후 여러 정렬 목록의 가장 앞 값을 비교하며 한 정렬 목록으로 병합한다. 데이터가 메모리에 들어간다는 내부 정렬 가정과 다르다.

병합 폭과 I/O 조건을 명시한다

한 페이지를 출력 버퍼에 쓰면 최대 B−1 개 입력 run을 동시에 병합할 수 있다. B는 이 연산에 실제 사용할 수 있는 버퍼 수이며 다른 연산의 메모리를 중복 계산하지 않는다.

모든 통과에서 전체를 읽고 전체를 다시 저장하는 단순 모델은 통과당 2N I/O다. 마지막 결과를 다음 연산으로 바로 보내거나 run을 길게 만드는 최적화는 이 계산에 포함하지 않는다.

집계는 그룹별 상태를 줄인다

aggregation은 같은 그룹의 여러 행을 COUNT·SUM·AVG 같은 상태로 줄이는 작업이다. 정렬한 뒤 같은 키를 연속 처리하거나 해시로 그룹별 상태를 찾는 방법을 생각할 수 있다.

부분 평균끼리 무조건 평균 내면 안 된다. 합과 개수를 함께 결합해 최종 평균을 구해야 서로 다른 크기의 부분 집단을 올바르게 반영한다. 그룹 상태가 메모리를 넘으면 외부 처리 조건이 다시 필요하다.

25페이지를 버퍼 4페이지로 정렬합니다. 모든 단계의 결과를 디스크에 저장하는 모형입니다.

초기에는 최대 네 페이지를 정렬하지만 병합에서는 입력 세 자리와 출력 한 자리를 씁니다. 짧은 마지막 run도 실제 페이지 수만큼 셉니다. 병합에서 run 수가 7→3→1로 줄어듭니다.

중간 과정을 따라가는 예제

N=20 페이지, B=4 버퍼다. 초기 run 생성과 모든 병합 결과를 디스크에 저장하며 출력 읽기 추가 비용은 제외한다. 필요한 통과 수와 I/O를 계산하자. 별도 그룹 A의 값은 2 와 8, B의 값은 5 다.

  1. 초기 run은 ceil(20/4)=5 개이며 초기 통과에서 40 I/O를 쓴다.

  2. fan-in=3 이므로 병합 뒤 run 수는 5→2→1 이다. 병합 두 번과 초기 한 번을 합쳐 3 통과다.

  3. 총 I/O는 2×20×3=120 이다. 집계는 A: 합 10/개수 2/평균 5, B: 합 5/개수 1/평균 5 다.

정렬은 3 통과·120 페이지 I/O다. 두 그룹 평균이 모두 5 여도 개수와 합은 다르다.

조건을 바꾸어 비교하기

메모리 증가가 비용을 계단처럼 바꿉니다

같은 25페이지에 B=3,4,5,6을 각각 독립적으로 배정합니다. 모든 통과의 결과를 저장할 때 총 통과 수와 I/O를 구하세요.

  1. B=3이면 초기 run은 9개이고 병합 폭은 2입니다. 9→5→3→2→1이므로 초기 포함 다섯 통과입니다.

  2. B=4이면 7→3→1, B=5이면 5→2→1로 각각 세 통과입니다.

  3. B=6이면 초기 5개를 병합 폭 5로 한 번에 합칩니다. 초기 포함 두 통과입니다. 각 통과는 50 I/O입니다.

B=3,4,5,6의 비용은 차례로 250,150,150,100 페이지 I/O입니다. 버퍼를 4에서 5로 늘려도 통과 수가 같아 비용이 같습니다.

비교할 점

버퍼 2페이지의 병합 폭은 1이라 여러 run을 줄일 수 없습니다. 이 알고리즘의 일반 병합 계산에는 B≥3이 필요합니다. 빈 입력은 별도 종료하며 로그 식에 0을 넣지 않습니다.

평균은 합과 개수로 합칩니다

동일 그룹의 두 부분 상태가 합 12·개수 2와 합 45·개수 5입니다. 빈 부분 상태와 결합하는 경우도 생각하세요. 값은 모두 NULL이 아닌 정확한 수입니다.

  1. 두 부분 평균은 6과 9입니다. 평균끼리만 더해 나누면 7.5가 됩니다.

  2. 합은 12+45=57이고 개수는 2+5=7이므로 최종 평균은 57/7입니다.

  3. 빈 부분의 내부 결합 상태를 (합 0, 개수 0)으로 정하면 기존 상태를 바꾸지 않습니다. 마지막 개수가 0이면 나누지 않습니다.

합친 평균은 57/7, 약 8.142857입니다. 개수가 다른 부분 평균의 단순 평균 7.5는 틀립니다.

비교할 점

내부 누산기 (0,0)는 빈 SQL SUM의 반환값이 0이라는 뜻이 아닙니다. PostgreSQL의 빈 집계 SUM·AVG는 NULL이며 COUNT는 0입니다.

종이와 본문으로 직접 해보기

부분 집단 평균이 2(1 개)와 8(3 개)이면 합친 평균을 계산하자.

힌트 보기

각 평균에 그 집단의 개수를 곱해 합으로 되돌린다.

풀이 보기

(2×1+8×3)/(1+3)=26/4=6.5 다. 단순 평균 (2+8)/2=5 는 틀리다.

오해와 반례

입력 run을 만들었으면 병합은 항상 한 번이면 끝난다.

B=4 에서 run 5 개를 fan-in 3 으로 처리하면 두 병합 통과가 필요하다. 메모리와 run 수를 함께 확인한다.

자기점검

B=6 이면 이 예의 통과 수는?

답과 이유 보기

2 통과다.

초기 ceil(20/6)=4 개를 fan-in5 로 한 번에 병합하므로 총 80 I/O다.

집단 평균의 단순 평균은 항상 정확한가?

답과 이유 보기

아니다.

집단 크기가 다르면 합과 개수를 이용해야 한다.

120 I/O에 마지막 결과의 추가 스캔이 포함되나?

답과 이유 보기

포함되지 않는다.

모든 통과의 쓰기까지 포함하며 소비자의 추가 읽기는 제외했다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

25페이지 정렬에서 B=4입니다. 마지막 병합의 출력은 저장하지 않고 소비자가 바로 받습니다. 앞 단계들은 표처럼 저장하고, 소비자는 추가 디스크 읽기를 하지 않습니다. I/O를 구하세요.

힌트 1

앞 두 통과는 각각 50 I/O입니다.

힌트 2

마지막은 기존 run을 읽지만 최종 25페이지를 디스크에 쓰지 않습니다.

풀이와 답 확인

  1. 앞 두 통과는 100 I/O입니다.

  2. 마지막 입력 읽기 25를 더해 125 I/O입니다.

  3. 모든 결과를 저장한 정렬 150에 소비자의 추가 읽기 25를 더한 경로는 175입니다.

직접 전달은 125 I/O이며 저장 후 소비자가 읽는 175 I/O보다 50이 작습니다. 소비자의 CPU와 자체 출력 쓰기는 제외했습니다.

흔한 오답에서 다시 생각하기

마지막 통과를 생략하므로 100 I/O입니다.

정렬된 하나의 흐름을 만들려면 마지막 입력 run들을 읽고 병합해야 합니다. 생략한 것은 최종 디스크 쓰기입니다.

연습 2 · 오류 찾아 고치기

동일 그룹의 값이 2,NULL,8입니다. PostgreSQL AVG를 구현하려는 프로그램이 NULL을 합에는 넣지 않지만 전체 행 수 3으로 나누어 10/3을 반환합니다. 고치세요.

힌트 1

AVG에 들어가는 값의 개수를 확인합니다.

힌트 2

COUNT(*)와 COUNT(값)의 의미를 구별합니다.

풀이와 답 확인

  1. NULL이 아닌 값의 합은 10, 개수는 2입니다.

  2. 해당 값의 유효 개수를 누산해 10/2를 계산합니다.

  3. 모든 값이 NULL이면 유효 개수가 0이므로 평균을 NULL로 처리하며 0으로 나누지 않습니다.

평균은 5입니다. COUNT(*)는 3이지만 COUNT(값)은 2입니다. 전체 행 수를 AVG의 분모로 쓰지 않습니다.

흔한 오답에서 다시 생각하기

NULL을 숫자 0으로 대체해 같은 평균을 얻습니다.

NULL을 0으로 바꾸면 입력의 의미를 바꿉니다. 그 경우 평균은 10/3이 되어 원래 AVG와 다릅니다.

연습 3 · 직접 만들어 보기

정렬 run A=[1,5,9], B=[2,5,8], C=[0,7]을 중복을 보존해 병합합니다. 각 run의 현재 맨 앞을 비교해 최종 목록을 만드세요.

힌트 1

가장 작은 맨 앞 값의 run에서만 위치를 옮깁니다.

힌트 2

값 5 두 개는 서로 다른 입력 항목입니다.

풀이와 답 확인

  1. 맨 앞 1,2,0에서 0을 내고 C의 다음 값 7을 봅니다.

  2. 다음 1과 2를 낸 뒤 A와 B의 5를 모두 냅니다.

  3. 남은 7,8,9를 순서대로 냅니다.

최종 목록은 [0,1,2,5,5,7,8,9]이며 입력 여덟 항목이 모두 보존됩니다. 같은 값의 내부 순서는 이 문제에서 지정하지 않았습니다.

흔한 오답에서 다시 생각하기

정렬이 끝나면 중복 5를 하나로 지웁니다.

정렬과 중복 제거는 다른 연산입니다. 주어진 정렬은 항목 수를 바꾸지 않습니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

값 [9,2,7,1,8,3]의 작은 값 세 개만 필요합니다. 최대 세 개를 보관하며 그중 최댓값을 비교하는 방식으로 상태를 적으세요. 동점은 없고 최종 결과는 오름차순으로 냅니다.

힌트 1

처음 세 값 이후에는 보관한 최댓값보다 작은 새 값만 교체합니다.

힌트 2

자료가 정렬되어 있다는 보장은 없습니다.

풀이와 답 확인

  1. 처음 세 값을 본 상태는 {9,2,7}입니다.

  2. 1은 9를 교체해 {1,2,7}이 되고 8은 버립니다.

  3. 3은 7을 교체해 {1,2,3}이 됩니다. 여섯 값을 모두 확인한 뒤 정렬합니다.

결과는 [1,2,3]입니다. 보관 크기는 세 항목이지만 모든 입력을 확인해야 합니다. 실제 바이트 예산과 페이지 I/O는 별도입니다.

흔한 오답에서 다시 생각하기

세 값만 필요하므로 처음 세 항목을 읽으면 끝입니다.

뒤에 더 작은 1과 3이 있습니다. 정렬 순서나 안전한 중단 경계가 없으면 앞부분만 읽어서는 답을 보장하지 못합니다.

양쪽 표에 같은 번호가 반복되면 해시 표에 한 줄씩만 남겨도 될까요?

여기서는 중복 행을 보존하는 내부 동등 조인을 합니다. 키가 같아도 행 ID가 다르면 서로 다른 행입니다. 키별로 양쪽 행이 a개와 b개면 a×b개의 대응 쌍을 만들어야 합니다.

중첩루프·해시·병합은 같은 정답을 얻기 위한 후보 탐색 방법입니다. 해시 버킷만 같다는 이유로 대응 쌍을 만들거나, 병합에서 한 쌍을 낸 뒤 양쪽 커서를 모두 옮기면 잘못된 결과가 나올 수 있습니다. 비용 비교보다 먼저 결과의 정확성을 확인합니다.

먼저 확인할 개념
  • 선택·투영·조인

    행의 모든 대응 쌍이라는 논리 연산과 물리 탐색 방법을 구별합니다.

  • B+트리·해시

    해시 충돌 뒤 실제 키 비교와 인덱스 조회 비용을 연결합니다.

중첩루프는 후보 쌍을 비교한다

중첩루프 조인은 한쪽 행 또는 행 묶음을 잡고 다른 쪽을 확인한다. 인덱스가 없다면 내부 표를 반복 읽는 비용이 커질 수 있다. 블록 방식은 여러 외부 페이지를 한꺼번에 보관해 반복 횟수를 줄인다.

B버퍼 중 내부 입력 하나와 출력 하나를 남기면 외부 묶음은 B−2 페이지다. 이 단순 모델의 입력·중간 I/O는 M+ceil(M/(B−2))N이며 결과 출력 비용은 제외한다.

해시 조인은 같은 키 후보를 찾는다

기본 해시 조인은 build 쪽의 키를 해시 테이블에 넣고 probe 쪽에서 같은 버킷을 찾는다. 기본 형태는 완전한 동등 조인 키에 적용한다. 해시값이 같아도 원래 키가 다를 수 있으므로 실제 동등 비교가 필요하다.

동일 키의 여러 행을 하나로 지우면 조인 결과가 바뀐다. 양쪽에 같은 키가 각각 a개와 b개면 그 키의 짝은 a×b개다. build 자료와 관리 비용이 메모리에 들어오는지 따로 확인한다.

병합 조인은 정렬 순서를 이용한다

정렬 병합은 키가 작은 쪽을 앞으로 옮기며 일치하는 그룹을 만난다. 이미 정렬되어 있는지와 정렬 비용을 함께 고려해야 한다.

중복 키 그룹에서는 모든 조합을 내야 한다. 입력 키가 거의 유일한 상황의 선형 병합 비용을 모든 중복 자료의 최악 비용으로 주장하면 안 된다. 결과 자체가 아주 많을 수도 있다.

중간 과정을 따라가는 예제

표 R은 12 페이지, S는 30 페이지이며 B=5 다. 인덱스 없는 블록 중첩루프의 두 외부 표 선택 비용을 구하자. 별도 작은 표의 R 키는 1,2,2 이고 S 키는 2,2,3 이며 행을 중복 제거하지 않는 inner equijoin을 한다.

  1. 외부 묶음은 5−2=3 페이지다. R 외부는 12+ceil(12/3)×30=12+120=132 I/O다.

  3. 키 2 의 R 행 두 개와 S 행 두 개를 각각 구별해 2×2=4 쌍을 낸다. 키 1 과 3 은 상대가 없어 출력하지 않는다.

이 조건에서는 R 외부의 132 I/O가 S 외부 150 보다 작다. 작은 표 조인 결과는 4 행이다.

  1. 총 입력은 12+30=42 페이지다. 분할에서 읽기 42+쓰기 42=84 I/O를 쓴다.

  2. 대응 파티션 처리에 총 42 페이지를 다시 읽어 84+42=126 I/O다. 파티션별 S는 평균 7.5 페이지 상당이어도 스트리밍 probe이므로 S 전체 동시 적재를 가정하지 않는다.

  3. 네 쿼리 요구는 4×64=256 MiB로 128 을 넘는다. 추가 비용을 제외한 단순 예산에서는 두 쿼리까지만 동시에 64 MiB를 줄 수 있다.

한 단계 분할 모델은 126 I/O다. 별도 메모리 모델의 동시 실행 상한은 2 개이며 실제 관리 비용이 있으면 더 줄 수 있다.

  2. 분할 파일의 총 쓰기는 48페이지입니다.

  3. 대응 파티션을 처리하며 두 입력을 합해 48페이지를 다시 읽습니다.
