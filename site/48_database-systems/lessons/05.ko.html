소단원 5.1

B+트리·해시

정확히 한 학생을 찾는 조회와 번호 구간을 찾는 조회에 같은 인덱스가 유리할까?

준비 개념과 학습 목표

준비 개념

  • 인덱스는 검색 키에서 데이터 위치로 가는 보조 구조다. 페이지는 저장·읽기의 묶음이며 leaf는 트리의 맨 아래 노드다.

  • B+트리 내부 키는 자식 선택을 위한 경계이며 실제 레코드 또는 위치 정보는 잎에 있다. 중복 없는 정수 키 예제로 시작한다.

학습 목표

  • 정렬 트리의 분기와 잎 범위 검색을 추적한다.

  • 해시 충돌과 동등·범위 검색의 차이를 설명한다.

한 페이지에서 여러 자식을 고른다

트리의 내부 페이지는 정렬된 분리 키와 자식 포인터를 가진다. 분리 키 25가 있다면 이 예제는 왼쪽이25보다 작고 오른쪽이25 이상이라는 규칙이다. 잎들은 같은 깊이에 있어 검색 경로가 한쪽만 길게 늘어나는 것을 방지한다.

큰 fanout은 한 페이지에서 많은 자식을 구별하는 정도다. 실제 페이지 용량은 바이트 수·키 길이·포인터 크기에 달린다. 여기서는 키 개수로 용량을 정한 종이 모형이며 모든 DB에서 최대 키 수가 동일한 상수라고 말하지 않는다.

잎의 순서를 범위 조회에 사용한다

잎의 키들은 정렬되어 있고 오른쪽 잎으로 이어지는 링크를 사용할 수 있다. 시작 키를 찾은 뒤 다음 잎들을 순서대로 읽으며 종료 경계를 확인한다. 내부 분리 키를 찾았다고 실제 레코드 조회를 끝내지 않고 알맞은 잎까지 내려간다.

범위에 맞는 많은 결과를 내보내면 결과 수만큼의 비용도 필요하다. 인덱스가 있다는 이유로 모든 조회가 한 번의 페이지 읽기로 끝나거나 출력 비용이0이 되는 것은 아니다. 캐시 상태와 데이터 페이지 방문도 실제 비용에 포함한다.

해시는 같은 위치와 같은 키를 구별한다

h(k)=k mod4의 버킷에서는 키2,6,10이 모두2번으로 간다. 이것은 충돌이지 세 키가 같다는 뜻이 아니다. 해당 버킷 안에서 원래 키의 동등 여부를 다시 검사하고 모든 항목을 보존하는 충돌 처리가 필요하다.

해시는 키 순서를 일반적으로 보존하지 않는다. 등호 검색에 맞는 버킷을 빠르게 고를 수 있어도 범위 2..10을 찾는 데 버킷 2만 보면3이나8을 놓친다. 실제 인덱스 선택은 조회 형태·분포·갱신 비용과 함께 판단하며 여기서는 실행 시간을 측정하지 않았다.

중간 과정을 따라가는 예제

내부 분리 키 25, 왼 잎 [10,20], 오른 잎 [25,30]의 트리에서 키 25와 범위 18..28을 찾으라. 별도 해시 h=k mod4에2,6,10을 넣고6을 찾아라.

  1. 25는 경계 이상이므로 오른 잎에서 25의 레코드 위치를 얻는다. 내부 25는 라우팅 사본이다.

  2. 18은 왼 잎에서 찾기 시작하고20을 얻는다. 오른 잎으로 이동하여25를 얻고30>28에서 멈춘다.

  3. 범위 결과는 20,25다. 트리의 잎 정렬과 링크를 함께 사용했다.

  4. 해시2/6/10은 모두 버킷 2다. 그 안에서 원래 키를 비교하여 6을 고르며 2나 10을 6으로 바꾸지 않는다.

트리 점조회25, 범위 20/25, 해시6은 충돌 버킷의 원래 키 비교로 얻는다.

종이와 본문으로 직접 해보기

키1,5,9와2,6을 h=k mod4로 배정하라. 범위 1..6을 버킷 1만 읽으면 무엇을 놓치는가?

힌트 보기

같은 나머지끼리 모으고 실제 범위 조건을 다시 검사한다.

풀이 보기

버킷 1에1,5,9, 버킷 2에2,6이다. 범위 1..6의 결과 1,2,5,6 중 버킷 1만 보면2와6을 놓치고 9는 범위 밖이라 버려야 한다.

오해와 반례

해시가 같으면 같은 레코드이고 B+트리 내부 키에도 실제 레코드가 항상 있다.

2,6,10의 나머지는 같지만 키는 다르다. B+트리 내부 25는 탐색 경계이며 잎 25의 레코드를 대신하지 않는다. 각 구조의 저장 역할을 구분한다.

원래 키 비교가 여전히 필요하다.

한 단계 더

트리 높이 h일 때 루트가 캐시되지 않은 경우와 이미 캐시된 경우의 페이지 읽기를 구별해 적어 보자. 인덱스 구조의 단계 수는 실제 디스크 지연과 다른 값이며, 많은 결과를 반환하는 조회에서는 출력과 데이터 접근 비용이 남는다.

소단원 5.2

분할·병합·복구

한 잎에 공간이 없거나 삭제 뒤 너무 적게 남으면 검색 경계는 어떻게 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 이 단원의 자체 B+트리 잎은 최대 3키, 비루트 최소 2키다. 루트 하나만 남으면 최소 2 예외를 허용한다.

  • 분할은 두 페이지로 나누는 일, 병합은 이웃을 합치는 일이다. WAL은 페이지 변경 전에 복구용 기록을 영구 저장하는 규칙이다.

학습 목표

  • 잎 분할과 삭제 후 병합에서 키와 경계를 보존한다.

  • 동시성 보호와 충돌 후 복구를 별도 문제로 설명한다.

공간 부족은 부모까지 전파될 수 있다

잎 [10,20,30]에 25를 넣으면 정렬한 [10,20,25,30]이 최대 3을 넘는다. 이 모형은 왼 [10,20]과 오른 [25,30]으로 나누고 부모에 오른 첫 키 25를 복사한다. 25는 잎에서 사라지지 않는다. 자식 포인터와 잎 링크도 새 구조에 맞춰 바꾼다.

부모도 꽉 차면 내부 분할이 위로 전파될 수 있고 루트 분할은 새 루트로 높이를 늘린다. 내부 분할은 탐색 경계를 위로 이동하는 규칙이어서 잎 레코드 복사와 구별한다. 구체 분할 위치·최소 개수는 구현마다 다르므로 종이 모형의 3을 실제 DB 페이지 한계로 쓰지 않는다.

점유율 복구와 실제 삭제 정책

위 두 잎에서 10을 지우면 왼 [20]은 최소 2보다 작다. 오른[25,30]도 최소 2라 하나를 빌리면 오른이 부족해진다. 이 모형에서는 [20,25,30]으로 병합하고 부모의 분리 키 25와 한 자식 포인터를 없앤다. 부모가 자식 하나의 루트이면 그 잎을 새 루트로 삼는다.

일반 교재는 빌리기·병합으로 최소 점유율을 유지할 수 있지만 실제 시스템은 다른 정책도 사용한다. Berkeley의 해당 입문 자료는 삭제 후 부족한 잎을 그대로 둘 수 있다고 설명하며 PostgreSQL은 별도 동시 삭제 절차를 쓴다. 여기서 선택한 즉시 병합을 그 시스템들의 실제 동작이라고 바꾸지 않는다.

정상 구조와 충돌 복구는 다른 보장이다

WAL은 데이터 페이지의 변경을 저장하기 전에 그 변경의 로그를 영구 저장한다. 충돌 때 페이지에 아직 반영하지 못한 변경을 REDO할 근거가 생긴다. 메모리 페이지의 latch는 동시 접근을 조절하지만 전원이 꺼진 뒤의 복구 기록을 대신하지 못한다.

실제 분할은 잎·링크·부모 등 여러 변경으로 나뉠 수 있다. PostgreSQL의 문서는 분할과 상위 포인터 삽입을 별도 WAL 단계로 기록하며 복구 중 상위 경로가 덜 갱신된 경우도 다룬다. 로그와 페이지 번호·적용 상태를 확인하는 실제 복구 프로토콜을 생략하고 모든 페이지가 한순간에 저장된다고 가정하지 않는다.

중간 과정을 따라가는 예제

최대 3/min2 잎 [10,20,30]의 단일 루트에 25를 삽입한 뒤 10을 삭제하라. 정렬·잎 키 수·부모 경계·루트 변화를 추적하라.

  1. 삽입 정렬 [10,20,25,30]의 4키는 넘침이다.

  2. 두 잎 [10,20]/[25,30]과 분리 키 25의 새 루트를 만든다. 두 잎은 각 2키로 유효하다.

  3. 10 삭제 뒤 [20]/[25,30]이 되어 왼 1키는 부족하다. 오른은 2키라 빌려줄 수 없다.

  4. 합친 [20,25,30]은 3키로 최대 이내다. 부모에서 분리 키와 포인터를 줄이고 한 자식의 루트를 접어 이 잎을 루트로 삼는다.

  5. 초기 키 10/20/30에 25 추가와 10 삭제를 반영한 최종 집합 20/25/30이 보존되었다.

분할로 높이1이 되었다가 병합 후 단일 잎 루트 높이0으로 돌아간다.

종이와 본문으로 직접 해보기

페이지 변경에 로그 L이 필요하다. 로그 생성→로그 영구 저장→변경 페이지 저장의 순서와 로그 생성→페이지 저장→충돌의 순서를 비교하라.

힌트 보기

메모리의 로그 생성과 영구 저장은 다른 사건이다.

풀이 보기

앞 순서는 페이지에 쓰기 전 복구 근거 L이 영구 저장된다. 뒤 순서는 아직 영구 L이 없는 상태에서 페이지 일부만 남을 수 있어 WAL 규칙을 어긴다. 실제 복구를 실행한 PASS가 아니라 순서 조건 검사다.

오해와 반례

latch로 분할을 보호하면 로그 없이도 충돌 복구가 되고 삭제는 모든 DB가 바로 병합한다.

latch는 살아 있는 실행의 동시 접근 보호다. 영구 로그 없이 충돌하면 잎·부모 일부만 남을 수 있다. 즉시 병합은 이 교육 모형의 정책이며 실제 DB의 삭제 조건은 별도다.

한 단계 더

오른 잎이 [25,30,35]라면 왼 [20]에 25를 빌려[20,25]/[30,35]로 만들 수 있다. 새 부모 경계는 30이다. 병합만 생각하지 말고 인접 잎의 여유·부모 경계·WAL 단계를 함께 그리자. 실제 저장·복구 실험은 미수행이다.

소단원 5.3

페이지 latch와 구조 변경

부모가 가리킨 잎이 검색 도중 둘로 나뉘면 키가 없다고 결론 내도 될까?

준비 개념과 학습 목표

준비 개념

  • latch는 공유 메모리 페이지의 짧은 물리적 접근을 보호한다. 트랜잭션 lock의 논리적 데이터 격리와 목적·유지 시간이 다를 수 있다.

  • high key는 페이지 담당 범위의 상한, right-link는 오른쪽 형제 포인터다. pin은 버퍼 페이지의 교체를 제한하는 수명 관리이며 latch와 구별한다.

학습 목표

  • 중간 분할 상태의 잘못된 검색을 추적한다.

  • 짧은 페이지 보호와 범위 재검사의 역할을 나눈다.

안정된 페이지 한 장을 읽는다

공유 버퍼에서 키 배열과 포인터를 읽는 동안 다른 쓰기가 반만 반영되면 일관된 구조를 해석할 수 없다. read/write latch는 읽기 동안 페이지가 중간 상태로 바뀌지 않도록 보호하는 도구다. 실제 모드와 범위는 구현의 규칙으로 확인한다.

latch를 잡았다고 트랜잭션 전체의 격리가 자동 완성되지는 않는다. 읽은 레코드의 가시성·논리적 잠금은 다른 층의 문제다. 또한 pin이 있어 페이지 교체를 막아도 구조 쓰기를 막는 latch가 없으면 같은 보호라고 할 수 없다.

부모 경로가 오래되면 범위를 재검사한다

분할 후 부모가 아직 새 자식 포인터를 받지 못했다면 기존 왼 잎에 도착할 수 있다. B-link 방식은 페이지 high key를 검사하고 검색키가 담당 범위보다 크면 right-link를 따라 새 오른쪽으로 이동한다. 여러 분할이면 같은 검사를 반복할 수 있다.

이 단원의 단순 정수 모형은 왼 잎 [10,20]의 high key 20, right-link→오른[25,30]으로 정한다. 실제 PostgreSQL의 pivot·중복 정렬·경계 규칙은 더 복잡하다. 여기서는 30 검색이 20보다 커서 오른쪽으로 이동한다는 작은 예만 계산한다.

여러 페이지의 보호 순서도 설계한다

한 작업이 왼 페이지를 잡고 오른쪽을 기다리는 동안 다른 작업이 오른쪽을 잡고 왼쪽을 기다리면 순환 대기가 생긴다. latch가 존재한다는 사실만으로 진행이 보장되지 않는다. 페이지 획득 순서·재시도·해제 조건을 알고리즘에 맞춰 정해야 한다.

초보용 전역 latch로 모든 트리 변경과 검색을 직렬화하는 모형도 구조 중간 관찰을 막을 수 있지만 동시성이 줄어든다. 페이지별 보호나 right-link 설계는 성능과 복잡성의 절충이다. 실제 PostgreSQL을 전역 latch 모형이라고 부르거나 종이 증명으로 DB 부하 측정까지 완료했다고 표시하지 않는다.

중간 과정을 따라가는 예제

부모가 아직 옛 단일 잎P를 가리킨다. P가[10,20],high20,right→Q로, Q가[25,30]으로 유효하게 분할되었다. 검색키 30에서 부모만 신뢰하는 검색과 범위 재검사를 비교하라.각 페이지는 읽는 동안 latch로 안정되어 있다고 정한다.

  1. 옛 부모 포인터로 P에 내려온다. P의 키 배열에는 30이 없다.

  2. right-link를 확인하지 않고 없음으로 끝내면 실제 Q의 30을 놓친다.

  3. high key 20과 검색 30을 비교하면 30>20이라 right-link를 따라 Q로 간다.

  4. Q에서 30을 찾는다. 두 페이지의 안정된 내용과 유효한 right-link가 조건이며 도중 삭제·재사용까지 증명한 것은 아니다.

범위 재검사와 right-link로 옛 상위 경로에서도 Q의 30에 접근한다.

종이와 본문으로 직접 해보기

힌트 보기

대기 화살표가 순환인지, 수명과 수정 금지가 같은지 본다.

풀이 보기

A→B→A의 순환이라 교착 조건이 될 수 있다. 같은 방향 획득·해제 후 재시도 같은 알고리즘별 정책이 필요하다. pin은 교체 수명 조건이며 페이지 수정 latch를 대신하지 않는다.

오해와 반례

페이지 latch 하나만 있으면 오래된 부모·트랜잭션 격리·충돌 복구도 모두 해결된다.

안정된 P만 읽어도 새 Q의 30을 못 찾을 수 있어 범위/링크 검사가 필요하다. 논리적 격리와 WAL 복구도 별도다. 보호할 페이지와 보장할 성질을 정확히 적는다.

한 단계 더

상위 포인터 갱신 전·후의 30 검색을 각각 그리고, 새 부모가 Q를 가리키면 바로 Q로 가지만 옛 부모는 P를 거쳐 Q로 가는 차이를 비교하자. 정확성을 유지하는 우회와 추가 비용을 구별하며 실제 분할·복구·교착 테스트는 수행하지 않았다.
