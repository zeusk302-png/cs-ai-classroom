소단원 1.1

문제·가정·기여·평가

새 스케줄러가 빠르다는 논문에서 먼저 물어야 할 것은 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 운영체제는 프로그램의 실행과 CPU·메모리·장치 사용을 관리한다. 스케줄러는 실행 가능한 작업 중 CPU를 쓸 대상을 고른다.

  • 가정은 논증이 다루는 환경의 조건이다. 기여는 기존 방법과 비교해 새로 제공한 설계·분석·근거다.

  • 응답시간은 요청이 가능해진 시각부터 완료까지의 차이고 평균은 응답 합을 개수로 나눈다. 평균·최대·처리율은 서로 다른 수치다.

학습 목표

  • 논문의 문제·가정·기여·평가를 네 질문으로 추출한다.

  • 가상 스케줄의 성능과 기능 조건을 분리한다.

  • 조건부 계산과 실제 시스템 실험 주장의 범위를 비교한다.

작업이 끝나는 시간이 좋아져도 마감이나 정책 판단 비용 때문에 결론이 바뀔까요?

기본 원고의 단일 CPU와 시각 0에 준비된 세 작업을 유지합니다. 실제 작업 길이는 A가 8ms, B가 1ms, C가 1ms입니다. 응답시간은 이 예에서 준비 시각부터 완료까지이며 첫 실행까지 기다리는 시간과 다릅니다. 기여가 무엇인지 읽을 때 평균 응답·개별 마감·정책 교체 가능성을 서로 다른 주장으로 적습니다.

새 비교에서는 각 작업의 실행을 시작하기 직전에 공통 배치 비용 h=3 ms가 들고 선점·I/O는 없다고 정합니다. 짧은 작업 우선 정책만 전체 시작 전에 추가 판단 비용 p를 한 번 부담하는 경우도 분리합니다. 이 비용은 자체 입력이며 ghOSt의 실제 계측 숫자나 모든 스케줄러 비용으로 사용하지 않습니다.

네 칸으로 주장을 해체한다

문제는 어떤 사용자·부하·기존 제약을 개선하려는지, 가정은 하드웨어·커널·장애·작업 성질이 무엇인지 묻는다. 기여는 새 메커니즘·정책·모형의 차이이며 평가는 그것이 어떤 지표에서 어떤 기준선보다 나은지 확인한다. 추상적인 “빠름”을 완료시간·꼬리 지연·메모리·운영 비용 등 관측 가능한 양으로 바꾼다.

ghOSt 원문은 데이터센터의 스케줄링 정책을 사용자 공간에서 바꿀 수 있게 하는 설계와 Linux 커널 메커니즘의 경계를 다룬다. 공개 본문에는 작업·기준선·환경을 구분한 평가가 있다. 이 설계 설명을 읽었다고 임의의 가정용 컴퓨터에서 성능이 그대로 재현된다는 결론을 내리지 않는다.

작은 작업열에서 정책 차이를 확인한다

자체 가상 단일 CPU 모형은 세 작업 A/B/C가 모두 시각 0에 준비되고 실행시간이 각각 8/1/1 ms이며 선점·스위치 비용·I/O가 없다고 정한다. FIFO 순서 A, B, C에서는 완료시각 8/9/10, 평균 응답 9 ms다. 짧은 작업 먼저 B, C, A에서는 B1/C2/A10, 평균 13/3 ms다.

이 표는 정한 작업열에서 평균이 개선됨을 보인다. 하지만 A의 완료는 8에서 10으로 늦어진다. “평균이 더 작다”와 “모든 작업이 더 빨리 끝난다”는 다르다. 실행시간을 미리 아는 가정이 실제 구현에서 가능한지도 확인해야 하며 잘못 예측한 길이·새 도착·무한 짧은 작업은 다른 문제다.

평가가 주장보다 좁으면 그 차이를 적는다

한 부하의 수치 결과가 전체 부하의 보장을 대신하지 않는다. 처리 실패나 응답 누락을 빼고 평균을 내면 좋은 숫자를 만들 수 있으므로 성공률·완료 정의·관측 기간도 기록한다. 성능 최적화가 메모리 안전·격리·공정성을 깨지 않는지 별도 기능 조건으로 검사한다.

가정 아래 유도한 스케줄과 실제 구현의 실험은 근거 종류가 다르다. 논문의 실험은 그 장치·설정·부하에서 관측한 결과이고 이 수업의 종이 표는 자체 모형 계산이다. 실제 재현 없이 논문 수치를 우리 측정값으로 옮기지 않는다. 불확실한 환경·통계·미검증 기능을 남겨 두는 것도 정확한 평가다.

각 작업 앞에 3 ms를 한 번씩 더합니다. 짧은 작업 우선의 완료 시각은 A/B/C 이름 순서로 표기했으므로 실행 순서와 혼동하지 않습니다. 모든 작업은 시각 0에 준비되어 완료 시각이 응답시간과 같습니다.

중간 과정을 따라가는 예제

가상 A=8/B=1/C=1 ms 작업을 FIFO와 짧은 작업 우선으로 계산하고 “모든 작업 개선” 주장을 판정하라.

  1. FIFO A: 0–8/B: 8–9/C: 9–10에서 응답 8,9,10의 평균은 27/3=9다.

  2. 우선 B: 0–1/C: 1–2/A: 2–10에서 응답 A: 10/B: 1/C: 2의 평균은 13/3이다.

  3. A는 2 ms 늦어졌으므로 모든 작업 개선은 거짓이다. 전체 완료시각 10은 같다.

평균은 9→13/3 ms로 개선되지만 A는 8→10으로 악화된다. 정한 비용 0·길이 사전 지식의 모형 결과다.

조건을 바꾸어 비교하기

공통 비용을 포함해 계산하기

표의 두 실행 시간표와 평균을 계산하세요. 추가 판단 비용 p는 0입니다.

  1. FIFO는 배치 0–3, A 3–11, 배치 11–14, B 14–15, 배치 15–18, C 18–19입니다.

  2. 응답 평균은 (11+15+19)/3=15 ms입니다.

  3. 짧은 작업 우선은 배치 0–3, B 3–4, 배치 4–7, C 7–8, 배치 8–11, A 11–19입니다.

  4. 평균은 (19+4+8)/3=31/3 ms입니다.

두 정책의 평균 차이는 15−31/3=14/3 ms이며 전체 완료는 19 ms로 같습니다.

비교할 점

기본 비용 0의 평균 9와 13/3에 비용을 추가했습니다. 비용을 전체 완료에만 더하고 평균에는 누락하지 않습니다.

추가 판단 비용으로 결론 뒤집기

공통 배치 비용 3 ms는 그대로이고 짧은 작업 우선만 전체 시작 전 p=5 ms를 한 번 부담합니다. FIFO는 추가 비용이 없습니다. 평균을 비교하세요.

  1. 짧은 작업 우선의 모든 완료가 5 ms 늦어집니다.

  2. 작업 A의 완료는 24ms, B는 9ms, C는 13ms입니다. 세 응답의 평균은 46/3 ms입니다.

  3. FIFO 평균은 15=45/3 ms입니다.

후보 평균은 46/3 ms로 FIFO보다 1/3 ms 느립니다.

비교할 점

길이를 미리 아는 비교의 이점과 길이 판단을 위한 추가 비용을 같은 것처럼 숨기지 않습니다.

종이와 본문으로 직접 해보기

모든 작업이 시각 0에 준비된 A=4/B=2에서 두 순서의 평균과 A 응답을 구하고 필요한 가정을 적어라.

힌트 보기

각 작업 완료를 release 0에서 뺀다. 순서만 바꾸고 CPU·작업량은 같게 둔다.

풀이 보기

A, B는 응답 4/6 평균 5, B, A는 B2/A6 평균 4다. A는 4→6으로 늦다. 길이 사전 지식·선점 없음·추가 비용 없음의 가정이 필요하다.

연습 1 · 값과 상태 예측

공통 배치 비용과 추가 판단 비용 모두 0입니다. A의 마감은 완료 시각 9 ms 이하입니다. 기본 FIFO와 짧은 작업 우선에서 A의 마감을 판정하세요.

힌트 1

FIFO의 A 완료는 8 ms입니다.

힌트 2

짧은 작업 우선에서 A 완료는 10 ms입니다.

풀이와 답 확인

  1. FIFO는 8≤9로 마감을 충족합니다.

  2. 짧은 작업 우선은 10>9로 마감을 놓칩니다.

  3. 평균은 개선되지만 A 마감이라는 별도 기능 목표는 악화됩니다.

FIFO는 A 마감 충족, 짧은 작업 우선은 미충족입니다.

흔한 오답에서 다시 생각하기

평균이 낮으므로 모든 마감도 지킨다.

각 작업의 완료와 마감 조건을 직접 비교하세요.

연습 2 · 오류 찾아 고치기

별도 작업열의 실제 길이는 A가 1ms, B가 8ms, C가 1ms입니다. 예측 길이는 A가 8ms, B가 1ms, C가 1ms입니다. 예측상 짧은 순서 B,C,A를 택했습니다. 모든 작업은 시각 0에 준비되며 추가 비용은 0입니다. 실제 응답 평균을 FIFO 순서 A,B,C와 비교하세요.

힌트 1

실행 순서는 예측으로 고르지만 시간은 실제 길이로 계산합니다.

힌트 2

B,C,A 순서의 실제 완료 시각은 B가 8ms, C가 9ms, A가 10ms입니다.

풀이와 답 확인

  1. 예측 순서 평균은 (8+9+10)/3=9 ms입니다.

  2. FIFO에서는 A가 1ms, B가 9ms, C가 10ms에 완료하므로 응답 평균은 20/3 ms입니다.

  3. 잘못 예측한 순서는 FIFO보다 7/3 ms 느립니다.

예측 우선 9 ms, FIFO 20/3 ms이며 실제 길이 최단 순서의 보장을 적용할 수 없습니다.

흔한 오답에서 다시 생각하기

예측된 B 길이 1을 실제 실행시간으로 그대로 쓴다.

예측 입력과 관측 대상인 실제 작업량을 구별하세요.

연습 3 · 직접 만들어 보기

공통 배치 비용 3 ms에서 후보의 추가 판단 비용 p≥0가 한 번 앞에 붙습니다. 후보 평균이 FIFO보다 엄격히 작은 조건을 식으로 쓰세요.

힌트 1

후보 평균은 31/3+p입니다.

힌트 2

FIFO는 15입니다.

풀이와 답 확인

  1. 31/3+p<15를 씁니다.

  2. p<15−31/3=14/3 ms입니다.

  3. p=14/3이면 같고 그보다 크면 후보가 느립니다.

0≤p<14/3 ms에서만 평균이 엄격히 작습니다.

흔한 오답에서 다시 생각하기

p=5도 짧은 작업을 먼저 하므로 항상 빠르다.

정책 결정 비용을 비교식에서 누락하면 안 됩니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

자체 표에서 평균 응답 개선만 계산했습니다. 논문 기여를 정책 교체가 쉽고 격리가 유지된다는 것으로 읽었을 때 필요한 다른 평가를 두 가지 쓰세요.

힌트 1

평균 계산에는 교체 동작과 격리 시험이 없습니다.

힌트 2

주장별 입력·관찰·실패 조건을 적습니다.

풀이와 답 확인

  1. 정책 교체 중 실행 지속과 중단 시간·실패 복구 조건을 별도로 정의합니다.

  2. 다른 작업이나 정책의 자원·상태를 침해하지 않는 범위와 실패 경로를 정의합니다.

  3. 이 단원은 이러한 시험을 실제 수행하지 않았다고 기록합니다.

교체와 격리의 주장마다 별도의 확인 계획과 미수행 범위를 남깁니다.

준비 개념과 학습 목표

준비 개념

  • 기준선은 비교 대상이다. 같은 목표·입력·자원 예산·정확성 조건에서 비교해야 지표 차이를 해석할 수 있다.

  • 측정 반복은 같은 조건에서 실행을 여러 번 관측하는 것이다. 입력 반복과 실험 환경 재설정·캐시 상태는 별도로 정한다.

  • 자료의 공개, 실행 가능, 결과 재현은 다른 확인 범위다. 설치 없는 종이 표 대조는 자료의 계산 확인이다.

학습 목표

  • 비교에서 고정할 조건과 보고할 차이를 목록으로 만든다.

  • 집계 방식·워크로드 비율에 따른 결론 변화를 계산한다.

  • 재현 기록에 필요한 환경·입력·원자료·실패를 구분한다.

기준선에는 긴 요청이 많고 후보에는 짧은 요청이 많았다면 공정한 비교일까요?

기본 원고의 작업 유형 X와 Y를 유지합니다. 기준선 B의 응답은 X 요청에 10ms, Y 요청에 100ms입니다. 후보 N의 응답은 X 요청에 8ms, Y 요청에 120ms입니다. 각 유형의 응답이 혼합 비율에 따라 바뀌지 않는 강한 모형 가정입니다. 후보와 기준선의 요청 비율을 다르게 두면 정책 차이와 입력 차이가 섞입니다. 같은 혼합으로 다시 계산한 결과와 원래 관찰된 집단 구성을 따로 기록합니다.

실행한 반복의 요약도 주장에 맞게 선택합니다. 아래 반복 숫자는 가상 제공 자료이며 실제 벤치마크를 실행한 원자료가 아닙니다. 다운로드·기능 실행·주요 결과 독립 재현은 다른 확인 범위이며 이 수업이 공식 artifact 배지를 받은 것은 아닙니다.

같은 비교의 조건을 정한다

버전·커밋·빌드 옵션·CPU 코어/주파수 정책·메모리·장치·OS·입력·부하·동시성·캐시·계측 범위를 적는다. 기준선도 적절히 설정하고 같은 기능·성공 조건을 제공하는지 확인한다. 보안 기능이 없는 기준선과 있는 후보의 비용을 비교할 수는 있지만 차이를 숨겨 같은 기능이라고 부르면 안 된다.

ghOSt 평가 원문은 비교 시스템의 커널 버전·패치·장치·작업 구성을 명시하고 일부 기준선의 버전 차이 이유를 적는다. 그러한 차이는 실험의 실제 조건으로 남겨야 한다. 우리가 논문을 읽는 목적은 차이를 지우는 것이 아니라 주장의 적용 범위와 가능한 교란을 평가하는 것이다.

집계와 워크로드 비율이 결론을 바꾼다

가상 응답 표에서 작업형 X/Y의 기준선 B는 10/100 ms, 후보 N은 8/120 ms다. 각 형을 한 번씩 가중하면 B 평균 55, N 평균 64로 후보가 느리다. X가 90%, Y가 10%인 요청 혼합에서는 B=0.9×10+0.1×100=19, N=0.9×8+0.1×120=19.2로 역시 조금 느리다.

X가 99%, Y가 1%면 B10.9, N9.12로 후보가 빠르다. 두 형의 개선비 10/8=1.25와 100/120=5/6의 단순 평균을 요청 평균 속도향상으로 쓰면 안 된다. 요청 비율과 집계 목표를 정한 뒤 같은 표를 읽어야 하며 평균만으로 긴 응답의 꼬리나 최악 상계를 결정할 수도 없다.

재현의 범위를 이름 대신 근거로 기록한다

USENIX OSDI2024의 artifact 평가 설명은 공개 가능, 기능 실행 가능, 주요 결과의 독립 재현을 별도 배지로 구분한다. 따라서 파일이 공개되었다는 확인과 실험이 동작했다는 확인은 다르다. 허용 오차와 범위도 평가 조건으로 정한다. 이 원고는 그런 공식 평가를 받은 것이 아니다.

축소 재현 기록은 원 주장·선택한 부분·변경한 환경·기준선·실행 명령·원자료·집계법·오차·미수행 부분을 포함한다. 실패한 설치도 숨기지 않는다. 여기의 표는 자체 가상 숫자를 손으로 계산했으므로 “원 논문 성능 재현”이라고 쓰지 않는다. 학습자는 종이 활동만으로 이러한 구분을 먼저 연습할 수 있다.

학부 OS와 연구 주제의 경계

교재의 작은 커널에서 락이 맞으면 큰 서버 커널의 모든 동시성도 해결될까?

준비 개념과 학습 목표

준비 개념

  • 프로세스는 실행 중인 프로그램의 자원 단위이고 스레드는 실행 흐름이다. 공유 상태를 여러 흐름이 바꾸면 순서에 따라 결과가 달라질 수 있다.

  • 임계구역은 공유 상태를 함께 갱신할 때 보호할 코드 구간이다. 락은 정한 규칙 아래 한 번에 한 흐름만 그 구간에 들어가게 한다.

  • 추상화는 관심 있는 상태와 규칙을 남기는 모형이다. 생략한 인터럽트·메모리 순서·수명·장애 조건이 결론에 영향을 줄 수 있다.

학습 목표

  • 교육용 모형의 핵심 원리와 연구 구현의 추가 조건을 구분한다.

  • 경쟁 반례와 임계구역 보호의 조건부 불변식을 추적한다.

  • 축소 연구 질문의 기능·성능·재현 경계를 명세한다.

락을 사용했다는 사실과 증가 연산 전체를 같은 락으로 보호했다는 사실은 같을까요?

기본의 순차일관성 종이 모형을 유지합니다. 읽기·계산·쓰기 단계는 각 단계 단위로 순서가 있고 실행 결과가 확정됩니다. 실제 C/C++ 비원자 경쟁을 이 모형처럼 정의된 프로그램 실행이라고 주장하지 않습니다. 세 흐름 A/B/C가 각각 한 번 증가하고 다른 쓰기는 없다고 새 범위를 정합니다.

같은 락이 보호하는 상태와 구간, 모든 흐름의 완료·객체 수명 조건을 적어야 최종 값을 말할 수 있습니다. 별도 성능 모형에서는 여섯 요청이 동시에 준비되고 서로 독립적인 구간 5 ms와 한 공유 락 구간 2 ms를 가집니다. 바깥 구간은 충분한 실행 자원으로 동시에 실행하고 락 획득·해제·스위치 추가 비용은 0이라고 가정합니다.

기본 원리가 연구 질문을 읽는 발판이다

MIT의 xv6는 RISC-V 학부 OS 학습을 위한 작은 Unix 계열 교육 커널이다. 교육 모형은 트랩·페이지·락·파일 등 원리를 읽을 수 있게 범위를 단순화한다. 작은 커널 이해가 실제 제품의 모든 장치·메모리 모델·보안·장애 경로를 검증했다는 뜻은 아니다.

연구 질문은 같은 기본 개념에 새로운 제약을 더한다. 예를 들어 락의 정확성을 유지하면서 많은 코어에서 경합을 줄이거나, 정책 교체를 사용자 공간으로 옮기면서 커널 경계를 유지하는 문제다. 기본 정의를 건너뛰는 것이 심화가 아니라 어떤 가정을 확장했는지 보는 것이 심화다.

작은 경쟁 반례도 조건을 적는다

자체 순차일관성 모형에서 공유 c=0이고 A/B가 각각 읽기 r=c, 계산 r+1, 쓰기 c=r+1을 한 번 수행한다. 두 흐름이 모두 0을 읽고 각각 1을 쓰면 최종 c=1이다. 추상적인 c++ 표기만으로 이 세 단계가 원자적이라고 가정하면 반례를 놓친다. 실제 C/C++ 비원자 경쟁의 정의되지 않은 동작을 이 추적의 실제 실행 의미로 주장하지 않는다.

읽기부터 쓰기까지 같은 락으로 보호하고 각 스레드가 정확히 한 번 완료하며 초기 0·다른 쓰기 없음이면 두 구역은 순서대로 실행된다. 첫 구역 후 1, 둘째 후 2이므로 최종 c=2다. 안전한 값이라는 결론은 락의 규칙·초기화·객체 수명·완료 가정에 의존한다. 이 추적만으로 공정한 진행이나 장애 복구까지 증명하지 않는다.

축소 연구는 주장도 축소한다

후속 연구 활동은 “이 공유 카운터의 정한 입력에서 업데이트 유실 방지”처럼 질문을 제한한다. 기능 확인 뒤 경합·대기·메모리·꼬리 지연 지표를 더하고 하나의 요소만 바꾸는 비교를 설계한다. 여러 기능을 동시에 바꾸면 개선 원인을 분리하기 어렵다.

커널 진입·인터럽트·CPU별 데이터·약한 메모리 순서·해제 뒤 접근은 작은 모형 밖의 추가 위험이다. 필요한 수준을 정의하고 자료/실행/학습자 시험의 확인 범위를 각각 기록한다. 종이 경쟁 추적은 설치 없이 가능하며 커널 수정은 이 첫 단원의 필수 활동이 아니다.

힌트 1

정책 비용·입력 비율·보호 구간을 각각 따로 적습니다.

힌트 2

문헌의 원저자 관찰과 이 수업의 종이 계산을 구별합니다.

풀이와 답 확인

  1. 공통 비용만 있으면 FIFO 15 ms, 후보 31/3 ms입니다. 후보 판단 비용 5 ms를 더하면 후보 46/3 ms로 FIFO보다 1/3 ms 느립니다.

  2. 같은 X 비율 90%에서 기준선 B의 평균은 19ms이고 후보 N은 19.2ms입니다. 이 조건에서는 후보가 더 느립니다.

판단 비용을 포함한 후보 평균은 46/3 ms입니다. 동일한 요청 혼합에서 기준선 B의 평균은 19ms, 후보 N은 19.2ms입니다. 쓰기만 보호한 유실 반례의 최종 값은 1이고, 전체 증가를 보호해 모두 완료한 경우는 3입니다. 실제 커널 재현은 미수행입니다.
