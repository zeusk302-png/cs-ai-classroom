소단원 8.1

저널·로그·copy-on-write

파일 이름표와 내용 중 하나만 저장된 순간 전원이 꺼지면 무엇을 읽게 될까?

준비 개념과 학습 목표

준비 개념

  • 파일 데이터와 메타데이터

  • 휘발·영속 저장

학습 목표

  • redo 저널의 영속 순서를 추적한다.

  • 저널과 LFS와 COW의 역할을 구별한다.

서로 맞아야 하는 여러 기록

파일의 데이터 블록, 그 블록을 가리키는 inode, 사용 여부 bitmap을 따로 바꾸면 중간 충돌로 서로 불일치할 수 있다. 메모리에 갱신했다고 장치에 모두 남는 것은 아니다.

redo 저널은 최종 위치를 덮기 전에 재적용할 내용을 기록한다. 이 절의 단순 모델은 저널 본문을 안전하게 남긴 뒤 원자적인 commit 표시를 남기고, 그다음 최종 위치에 checkpoint한다. 장치가 요구한 순서와 영속 완료를 지킨다는 조건이다.

로그라는 같은 단어의 다른 쓰임

저널의 로그는 기존 위치 갱신을 복구하기 위한 추가 기록이다. LFS는 데이터와 메타데이터 자체를 새 위치의 큰 segment로 모아 저장하는 배치를 중심으로 한다. 둘 다 로그를 쓰지만 최종 자료의 위치와 복구 구조는 같지 않다.

copy-on-write는 기존에 참조되는 버전을 바로 덮지 않고 새 내용을 다른 공간에 저장한 뒤 새 버전으로 참조를 연결하는 방식이다. 새 블록·참조·루트의 안전한 갱신과 옛 공간 회수 규칙이 필요하다. COW라는 이름만으로 어떤 다중 갱신도 원자적이라고 결론 내릴 수 없다.

commit 뒤 반복해도 같은 복구

물리 redo는 최종 블록을 새 내용으로 덮어쓴다. 이미 일부가 새 내용이어도 다시 같은 내용을 쓰면 결과가 동일하다. 아직 commit되지 않은 불완전 저널을 적용해서는 안 된다.

데이터까지 저널하는 방식과 메타데이터만 저널하는 방식은 보장 범위가 다르다. 아래는 데이터도 포함한 작은 종이 모델이며 ext4의 모든 모드·실제 전원 차단을 재현한 것이 아니다.

중간 과정을 따라가는 예제

A=0,B=0을 A=1,B=1로 바꾼다. 두 값을 저널에 남겨 영속 완료하고 commit도 영속 완료한 뒤 A만 checkpoint한 때 충돌했다. 재부팅 뒤는?

  1. 최종 위치는 충돌 직전A=1,B=0으로 부분 갱신이다.

  2. 유효한 commit과 본문이 있으므로 두 새 값을 redo한다.

  3. A에1을 다시 쓰고 B에1을 쓰면A=B=1이 된다.

복구 뒤A=1,B=1. A를 다시 써도 결과가 바뀌지 않는다.

소단원 8.2

일관성·스냅샷·복구

어제의 스냅샷이 같은 디스크에 있으면 디스크 파손에서도 어제를 지킬까?

준비 개념과 학습 목표

준비 개념

  • 블록 참조

  • 시점과 백업

학습 목표

  • 공유 블록의 버전 수명을 추적한다.

  • 구조 일관성과 응용 일관성·백업을 구분한다.

일관성에는 대상이 있다

파일시스템 구조 일관성은 참조와 할당 등 내부 규칙이 맞는 상태다. 응용 프로그램이 두 파일에 나눠 저장한 거래의 의미가 완성됐는지는 별도 문제다. 한 파일만 새 값이면 파일시스템은 정상이어도 거래는 미완성일 수 있다.

복구는 유효한 로그나 이전 루트로 일관된 구조를 다시 만든다. 사용자가 원한 모든 최근 입력이 남는다는 뜻과 같지 않다. 언제 완료로 응답했는지와 데이터·메타데이터 영속 계약을 함께 봐야 한다.

스냅샷의 공유와 분기

COW 스냅샷은 생성 순간 기존 블록을 함께 참조하고 이후 변경을 새 블록으로 분기할 수 있다. 처음부터 모든 파일을 물리 복사하지 않으므로 빠르고 공간 효율적일 수 있다.

어느 버전이라도 참조하는 옛 블록은 아직 회수할 수 없다. 스냅샷과 원본이 같은 장치와 같은 블록을 공유하면 장치 실패나 해당 블록 손상에 같이 영향을 받는다. 별도 장애 경계의 백업을 대체하지 못한다.

복원 범위를 정하기

읽기 전용 스냅샷은 그 시점 자료를 고정해 백업을 만들기 쉽게 하지만 실행 중인 DB의 거래 일관성은 응용 절차가 필요할 수 있다. 복원하려는 시점·대상·중첩 저장소를 적는다.

Btrfs의 중첩 subvolume은 부모 스냅샷에 내용까지 자동 재귀 복사되지 않는다. 다른 파일시스템에도 같은 세부 규칙이라고 일반화하지 않는다. 아래 계산은 메타데이터·압축·중복제거를 제외한 동크기 데이터 블록만 센다.

중간 과정을 따라가는 예제

원본이4KiB 블록A,B,C 3개를 사용한다. 스냅샷S를 만들고 원본B를새B2로 바꾼다. 고유 데이터 공간과 두 버전의 블록 목록은?

  1. 초기에는A,B,C 세 블록12KiB를 공유한다.

  2. 변경 후 원본은A,B2,C이고 S는A,B,C다.

  3. 고유 블록A,B,B2,C 네 개이므로16KiB다.

스냅샷은옛B, 원본은B2를 읽는다. 고유 데이터16KiB.

소단원 8.3

SSD·비휘발성 메모리

저장장치에서4KiB를 바꿨는데 내부에서는 더 많이 쓸 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 논리 주소와 물리 주소

  • 캐시와 영속성

학습 목표

  • 페이지·erase block·FTL을 구분한다.

  • 쓰기 증폭과 영속 순서의 조건을 설명한다.

플래시의 두 크기

NAND 플래시는 페이지 단위로 읽고 program하지만 이미 사용한 내용을 바꾸려면 더 큰 erase block의 제약을 고려한다. SSD는 새 위치에 쓰고 논리주소→물리주소 맵을 갱신하는 FTL로 이를 감춘다.

덮어쓴 옛 페이지는 쓰레기 공간이 된다. GC는 아직 유효한 페이지를 다른 곳으로 옮기고 블록을 지운다. 호스트 파일 블록, 가상메모리 페이지, 플래시 페이지가 항상 같은 크기라는 가정은 피한다.

성능 뒤의 추가 쓰기

쓰기 증폭은 같은 범위에서 센 내부 실제 쓰기 바이트를 호스트 쓰기 바이트로 나눈 비율이다. GC 복사와 메타데이터 등 포함 범위를 명시해야 비교할 수 있다. 장치 마모와 지연은 작업량·빈 공간·구현에 따라 다르다.

아래는 메타데이터 제외, 새 호스트 페이지 하나와 GC 복사 페이지 두 개를 세는 교육 예다. 실제 모델명이나 최신 장치 수명·성능으로 이 수치를 일반화하지 않는다.

CPU가 직접 보는 저장소도 계약이 필요하다

일부 비휘발성 메모리는 CPU가 주소로 접근하는 형태를 제공한다. 지원되는 DAX는 페이지 캐시의 불필요한 복사를 피하고 파일을 직접 매핑할 수 있다. 일반 SSD가 모두 이런 형태는 아니다.

저장 매체가 비휘발성이어도 CPU·장치 캐시의 완료와 영속 완료, 여러 필드의 원자적 갱신은 같은 말이 아니다. 정확한 지속 영역과 flush·순서·복구 프로토콜이 필요하다. 여기서는 명령어 실행이나 정전 시험을 하지 않는다.

중간 과정을 따라가는 예제

4KiB 호스트 새 쓰기1개 때문에 GC가 살아 있는4KiB 페이지2개를 복사한다. 세 페이지를 내부에 program했다면 이 범위의 쓰기 증폭은?

  1. 호스트 새 바이트4KiB를 분모로 둔다.

  2. 내부 program은 새1+복사2=3페이지,12KiB다.

  3. 12/4=3이다. erase 횟수와 읽기 바이트는 이 쓰기 비율에 더하지 않는다.

이 명시된 범위의 쓰기 증폭3.
