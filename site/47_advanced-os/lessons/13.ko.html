소단원 13.1

고전 구조와 현대 사례

두 논문이 모두 컨테이너라는 말을 쓰면 같은 문제를 해결한다고 보아도 될까?

준비 개념과 학습 목표

준비 개념

  • 프로세스와 스레드

  • 자원 사용량

  • 격리와 권한

학습 목표

  • 논문의 연구 질문과 추상화를 구별한다.

  • 보호 영역과 자원 계산 단위를 비교한다.

  • 역사적 용어를 현재 제품 이름과 구별한다.

비교는 이름보다 질문에서 시작한다

논문을 읽을 때 먼저 저자가 해결하려는 실패 사례를 적는다. 같은 이름을 썼더라도 계산하려는 비용, 격리하려는 대상, 변경한 계층이 다를 수 있다. 연도·제목·구현·평가 조건을 함께 기록해야 용어만 같은 시스템을 같은 실험으로 착각하지 않는다.

OSDI 1999의 Resource Containers는 보호 영역인 프로세스와 자원 사용을 귀속할 독립 활동이 꼭 일치하지 않는 문제를 다룬다. 요청 하나가 여러 스레드나 커널 처리를 거칠 수 있고 프로세스 하나가 요청 여러 개를 처리할 수 있다. 이 용어는 현대 Linux 컨테이너 이미지 형식의 이름이 아니다.

한 활동의 비용을 여러 실행 문맥에서 모은다

자체 서버 모형에서 요청 A는 워커 1과 워커 2에서 처리되고 요청 B는 워커 1에서 처리된다. 워커별 CPU 총합을 안다고 A와 B의 비용을 알 수 있는 것은 아니다. 활동 식별자와 실행 문맥을 별도 축으로 기록하면 하나의 프로세스 안에서도 요청 비용을 나눌 수 있다.

자원을 어느 활동에 귀속할지 정하는 문제와 그 활동이 다른 파일을 읽지 못하게 막는 권한 문제는 다르다. 정확한 비용 회계만으로 데이터 접근 격리가 자동 생기지 않는다. 1999년 모델 자료는 접근 제어 논의가 생략되었다는 범위도 명시한다.

현대 사례의 권한 경계도 별도로 본다

OSDI 2025의 MettEagle은 L4Re 기반 마이크로커널에서 컨테이너에 대응하는 컴파트먼트를 구성한다. 필요한 서비스에 접근할 권한을 명시적으로 전달하는 capability 구조를 논의한다. 저자들의 보안·성능 주장은 해당 구현과 분석·측정 범위의 주장이다.

두 사례는 자원과 격리를 다루지만 같은 구현이나 단일 발전 계보라고 단정할 근거는 이 비교에 없다. 비교 표에는 연구 질문, 보호 경계, 회계 단위, 인터페이스, 평가 범위를 각각 적는다. 오래된 논문이 무조건 잘못되거나 새 논문이 모든 조건에서 우수하다고 판단하지 않는다.

중간 과정을 따라가는 예제

자체 사건 네 개의 CPU 시간은 A/워커1 = 3 ms, A/워커2 = 2 ms, B/워커1 = 4 ms, A 관련 커널 처리 = 1 ms다. 요청 A와 B의 비용 및 워커 1의 비용을 계산하라. 공유 비용 1 ms가 아니라 A 전용이라고 명시한 모형이다.

  1. 워커 1에만 합치면 A의 3과 B의 4를 더한 7 ms다. 두 요청이 섞인다.

  2. 활동 A에는 3 + 2 + 1 = 6 ms를 귀속한다. 활동 B는 4 ms다.

  3. 워커 2는 2 ms, 별도 커널 처리 문맥은 1 ms다. 실행 문맥 합 7 + 2 + 1과 활동 합 6 + 4는 모두 10 ms다.

  4. A 비용을 3 ms라고 보고하면 다른 워커와 커널의 A 비용 3 ms를 누락한다. 이 표는 실제 커널 계측이 아니다.

A는 6 ms, B는 4 ms, 워커 1은 7 ms다. 활동과 실행 문맥을 별도 축으로 합쳐 총합 보존을 확인한다.

종이와 본문으로 직접 해보기

A 관련이라고 한 커널 1 ms가 사실 A/B 공유 비용이며 배분 근거를 모른다면 A/B 확정 합으로 넣어도 될까? 별도 권한 집합 A={readX}, B={readY}에서 A의 readY 요청을 판정하라.

힌트 보기

귀속 불명과 권한 검사를 따로 둔다.

풀이 보기

확정된 직접 비용은 A 5 ms와 B 4 ms, 공유 미배분은 1 ms로 기록한다. 임의로 A 전용이라고 쓰지 않는다. 권한 모형에서 readY는 A 집합에 없으므로 거절이다. 비용 회계만으로 이 거절이 구현되지는 않는다.

오해와 반례

자원 비용을 활동별로 세면 현대 컨테이너의 모든 보안 격리도 구현한 것이다.

회계 단위와 접근 권한은 별도다. 1999년 용어와 2025년 컴파트먼트 구조도 구별하며 자체 표는 실제 커널 구현이 아니다.

한 단계 더

A에 readX만 허용했는데 비용 상한을 정하지 않으면 A가 허용된 서비스만 반복하여 많은 자원을 쓸 수 있다. 반대로 비용 상한만 있어도 금지된 데이터를 한 번 읽는 문제는 남는다. 권한·회계·상한을 세 열로 비교하라.

소단원 13.2

주장·실험·제약 비교

실험 그래프 하나에서 빨랐다는 결과는 어떤 입력과 환경까지 지지할까?

준비 개념과 학습 목표

준비 개념

  • 평균과 중앙값

  • 비교의 분모

  • 측정 조건

학습 목표

  • 저자의 주장·측정·해석·미검증을 구분한다.

  • 환경이 다른 논문의 수치를 직접 순위로 합치지 않는다.

  • 속도 향상과 지연 감소를 같은 분모로 계산한다.

주장 옆에 근거 종류를 붙인다

논문 초록의 핵심 주장은 설계 원리, 특정 분석, 프로토타입 측정으로 뒷받침될 수 있다. 표에는 주장 문장과 근거의 절·그림, 비교 대상, 반복, 측정 구간, 위협 모형을 붙인다. 저자가 측정한 결과를 자신이 재현한 결과처럼 쓰지 않는다.

MettEagle은 마이크로커널 기반 컴파트먼트의 구현 가능성과 일부 성능 비교를 보고한다. 해당 문서의 평가에서 사용한 환경과 논의의 파일시스템 병목·warm start 및 OCI 이미지 지원 한계도 함께 읽어야 한다. 일부 빠른 시작 결과를 모든 응용이 더 빠르다는 주장으로 넓히지 않는다.

환경 차이는 실험의 일부다

1999년 자료는 수정 Digital UNIX 4.0D, 특정 500 MHz 서버와 128 MB 메모리, 100 Mbps 사설망의 조건을 기록한다. 2025년 자료는 듀얼 소켓 Xeon Platinum 8358 서버와 각 500 GiB 메모리, SMT·TurboBoost 비활성화 등의 조건을 기록한다. 연도 사이 원시 지연 차이는 OS 설계 하나의 원인으로 고정할 수 없다.

2025년 평가에서는 SPAFS에 디스크 backend가 없어 모든 플랫폼에서 메모리 파일시스템을 사용했다고 명시한다. 따라서 그 결과를 실제 디스크 영속성이나 모든 저장 workload 성능의 검증으로 해석하지 않는다. 이 자료의 조건 표는 논문 기록이며 현재 사용자 컴퓨터 사양이 아니다.

합성 수치도 분모를 정직하게 쓴다

두 시스템의 같은 작업 완료 시간이 10 ms와 8 ms라면 기준 A 대비 B의 시간 감소는 (10−8)/10 = 20%다. 고정된 일의 속도 비율은 10/8 = 1.25라서 25% 증가라고 할 수 있다. 서로 다른 분모의 20과 25를 같은 수치라고 쓰지 않는다.

실패한 실행을 빼고 평균을 보고하면 빨라 보일 수 있다. 성공률과 성공한 실행의 지연을 별도 보고하고 실패·timeout의 처리 규칙을 먼저 정한다. 이 절의 표는 논문 원문 값이 아니라 계산을 익히는 가상 자료다.

중간 과정을 따라가는 예제

가상 같은 작업의 성공 지연 세 번은 A=[9,10,11] ms, B=[7,8,9] ms다. 실행 요청 수는 A 4개/B 5개이며 나머지는 실패했다. 성공 지연 중앙값·비율·전체 요청 성공률을 구하라.

  1. 정렬된 성공 지연의 중앙값은 A 10 ms, B 8 ms다.

  2. A 대비 B의 중앙값 감소는 2/10 = 20%, 고정 작업 속도 비율은 10/8 = 1.25다.

  3. 성공률은 A 3/4 = 75%, B 3/5 = 60%다. 성공 지연 세 개라는 분모를 전체 요청 분모로 쓰지 않는다.

  4. B의 성공 지연이 짧아도 성공률은 낮다. 실패 시간과 재시도를 기록하지 않았으므로 전체 서비스 완료 비용을 확정할 수 없다.

성공 중앙값은 10/8 ms, 감소 20%, 속도 비율 1.25, 성공률은 75%/60%다. B가 모든 기준에서 좋다는 결론은 지지되지 않는다.

종이와 본문으로 직접 해보기

실패한 A 한 번이 timeout 30 ms, 실패한 B 두 번이 각각 30 ms였다면 성공 여부와 무관하게 시도당 관찰 종료 시간의 평균은? 이 평균을 성공 응답 지연이라고 이름 붙여도 될까?

힌트 보기

A는 네 시도, B는 다섯 시도다.

풀이 보기

A는 (9+10+11+30)/4 = 15 ms, B는 (7+8+9+30+30)/5 = 16.8 ms다. timeout은 성공 응답이 아니므로 전체 시도 종료 시간이라는 이름을 사용한다. 중앙값 10/8만 보고 판단했던 결과와 다르다.

오해와 반례

새 논문에서 시작이 빠르면 모든 응용과 저장 실험도 더 빠르고 안전하다.

측정 workload·환경·지표에 한정해야 한다. 파일 연산 병목과 메모리 파일시스템 조건을 확인하고 보안 분석은 성능 측정과 별도로 읽는다.

자기점검

10 ms에서 8 ms의 시간 감소율은?

답과 이유 보기

20%다.

기준 10으로 나눈다.

B 세 성공의 전체 성공률은 100%인가?

답과 이유 보기

아니다. 60%다.

전체 다섯 요청 중 세 성공이다.

메모리 파일시스템 측정으로 정전 복구를 검증했는가?

답과 이유 보기

아니다.

측정 환경과 검증 대상이 다르다.

한 단계 더

두 논문을 비교할 때 같은 열을 채울 자료가 없으면 미보고 또는 이 절에서 미확인으로 남겨라. 수치가 없는 칸을 가상 수치로 메운 뒤 원문 결과처럼 보고하지 않는다. 이 단원도 원문의 모든 그림을 읽거나 실행하지 않았으므로 인용 범위를 출처에 적는다.

소단원 13.3

재현 가능한 축소 실험

큰 논문 시스템을 설치하지 못해도 어떤 핵심 가설은 작은 모형으로 검토할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 불변식과 단위 시험

  • 자체 모형의 한계

  • 입력과 출력 기록

학습 목표

  • 논문의 모든 결과와 축소 가설을 구별한다.

  • 활동 회계의 보존 조건을 테스트한다.

  • 재현 정보와 미수행 항목을 분리한다.

작은 가설을 명세로 바꾼다

축소 실험은 원래 시스템을 작게 복사했다고 자동으로 원문 결론을 재현한 것이 아니다. 어떤 관계만 보존하는지 적어야 한다. 이 절은 실행 문맥과 활동을 분리하면 활동별 비용을 보존할 수 있다는 가설을 사건 목록으로 시험한다. 커널 권한이나 실제 지연을 측정하는 가설은 제외된다.

입력 사건은 고유 ID, 활동 ID 또는 미귀속 표시, 비음수 비용을 가진다. 같은 사건을 정확히 한 번 계산하고 활동별 합과 미귀속 합을 더하면 전체 사건 비용과 같아야 한다. 이 불변식과 중복 거절은 작고 명확하게 종이로 검증할 수 있다.

반례를 일부러 넣는다

정상 입력만 쓰지 말고 중복 ID, 음수 비용, 없는 활동 ID, 공유 비용을 넣어 판정 기준을 시험한다. 같은 ID가 다시 왔을 때 단순 합산하는 구현은 비용을 부풀린다. 무조건 무시하는 구현도 서로 다른 실제 사건에 같은 ID를 실수로 붙인 경우 문제를 숨길 수 있으므로 ID 생성 계약과 충돌 오류 처리를 명시한다.

활동 ID가 없는 사건을 임의의 활동에 붙이지 않고 미귀속에 넣는 모형을 정한다. 해당 모형을 고친다면 expected output도 함께 바꾼다. 테스트를 구현 내부의 동작을 복제한 답지로 만들지 말고 명세에서 계산한 합과 비교한다.

재현 기록은 범위와 함께 남긴다

기록에는 가설·모형 버전·입력 사건·중복 정책·예상 합·실제 실행 여부·관찰값·실패 사례·한계를 둔다. 여기서는 사건을 실제 계측하지 않았고 실행 프로그램도 돌리지 않았으므로 관찰값 칸은 미수행이다. 종이 예상값을 실제 OS 로그로 포장하지 않는다.

나중에 작은 Python 함수를 직접 구현해 실행하면 순수 집계 기능의 실행 검증을 추가할 수 있다. 그래도 두 논문의 커널·네트워크·권한·성능 재현은 아니다. 확장한 실험과 원래 축소 실험이 무엇을 다르게 검증하는지 분리한다.

중간 과정을 따라가는 예제

가상 사건은 (ID1,A,2), (ID2,B,3), (ID3,A,1), (ID4,미귀속,4)이며 비용 단위는 가상 작업 단위다. 고유 ID를 한 번씩 센다. 활동별 합과 전체 보존을 검사하라. 이어 ID2를 다시 제출하면 중복 오류로 거절하는 모형이다.

  1. A는 ID1과 ID3의 2+1 = 3, B는 ID2의 3, 미귀속은 ID4의 4다.

  2. 전체 사건 비용은 2+3+1+4 = 10이며 분류 합 3+3+4 = 10과 같다.

  3. ID2가 다시 오면 중복 오류를 기록하고 합계를 추가 변경하지 않는다.

  4. 잘못된 구현이 중복을 더하면 B는 6, 총합은 13이 되어 원래 고유 사건 비용 10과 맞지 않는다.

정상 합은 A 3/B 3/미귀속 4/전체 10이다. 중복 오류 뒤에도 합은 10이며, 단순 추가의 13은 명세 위반이다.

종이와 본문으로 직접 해보기

ID4를 제외하고 (ID5,B,2)를 추가하면 분류와 전체는? 별도 사건 (ID6,A,−1)을 입력할 때 모형의 비음수 조건을 적용하라.

힌트 보기

제거와 추가를 별도 사건 목록 버전으로 기록한다.

풀이 보기

새 목록에서 A 3, B 5, 미귀속 0, 전체 8이다. −1 비용은 입력 조건을 어겨 오류로 거절하며 기존 합 8을 줄이지 않는다. 음수 보정이 필요하다면 별도의 명세와 사건 종류가 필요하다.

오해와 반례

종이 집계나 순수 함수 테스트가 통과하면 두 논문의 성능과 보안도 재현한 것이다.

집계 불변식만 검증한다. 커널 회계의 정확성·권한 격리·실제 부하·네트워크·성능은 모형 밖이다. 실제 실행을 하지 않았으면 그 상태도 유지한다.
