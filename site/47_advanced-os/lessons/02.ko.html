소단원 2.1

모놀리식·마이크로커널

파일을 읽는 코드를 커널 밖으로 옮기면 무엇이 달라질까?

준비 개념과 학습 목표

준비 개념

  • CPU 권한 모드는 실행 코드에 허용되는 동작을 구분한다. 사용자 모드 프로그램은 임의로 다른 주소 공간이나 보호 설정을 바꿀 수 없으며, 커널 진입은 통제된 경로로 요청한다.
  • 주소 공간은 프로그램이 사용할 수 있는 주소와 매핑의 집합이다. 같은 권한 수준의 두 프로세스도 서로 다른 주소 공간을 가질 수 있다. 권한과 메모리 공유 여부는 별도의 축이다.
  • IPC는 프로세스 간 통신이다. 요청과 응답은 각각 메시지이며, 메시지 전달은 성공 여부·수신자·내용을 정한 계약이 필요하다. μs는 10⁻⁶초다.

학습 목표

  • 코드의 위치·권한·통신 경계를 그린다.
  • 모놀리식과 마이크로커널의 정의를 크기와 분리한다.
  • 서버 장애 격리와 서비스 성공 보장을 구별한다.

기능 배치와 권한을 함께 본다

모놀리식 구조는 주요 운영체제 기능을 하나의 커널 프로그램에 배치한다. 내부 모듈은 함수 호출과 공유 자료구조로 협력할 수 있다. 마이크로커널 구조는 특권 기능을 작게 남기고 파일 시스템 같은 기능을 사용자 서버로 분리한다. 구체적으로 무엇을 남기는지는 구현마다 다르므로 이름만으로 스케줄링·드라이버의 위치를 결정하지 않는다.

큰 건물과 작은 건물의 비교보다 출입 권한표가 더 정확하다. 가상 시스템에서 K는 보호와 메시지 전달, F는 파일 관리, D는 장치 처리를 담당한다. 모놀리식 모형은 K/F/D가 특권 주소 공간을 공유하며, 분리 모형은 F/D가 별도 사용자 공간에 있다. 실제 xv6는 모놀리식이고 크기가 작을 수 있으므로 코드 줄 수는 구조의 정의가 아니다.

메시지를 건너도 검사가 사라지지 않는다

가상 읽기 요청은 앱 A가 파일 이름·범위를 보내고 F가 권한과 길이를 확인한 뒤 D에 필요한 자료를 요청하는 순서다. 사용자 서버로 옮겨도 잘못된 길이, 권한 없는 파일, 거짓 응답을 처리해야 한다. 커널은 메시지 경로와 메모리 보호를 담당하고 서버는 서비스의 의미를 담당한다. 동일 프로세스 내부 호출에도 입력 검사는 필요하다.

F가 정지해도 K와 독립된 앱 B가 실행될 수 있도록 권한과 자원을 제한하는 것이 격리의 목표다. 그러나 A의 파일 읽기는 실패하거나 기다릴 수 있다. 서버를 다시 시작하려면 남은 요청 식별자와 상태를 복구하는 별도 계약이 필요하다. 격리는 특정 영향의 제한이지 모든 기능의 연속 성공을 의미하지 않는다.

비교의 조건과 지표를 고정한다

가상 직렬 시간 모형은 파일 계산 6 μs, 장치 대기 20 μs, 경계 한 번 1 μs로 정한다. 모놀리식 경로 A→K→A는 경계 2회이며, 분리 경로 A→K→F→K→D→K→F→K→A는 8회다. 중복 계산·큐 대기·캐시 효과가 없다는 조건에서 총시간은 각각 28 μs와 34 μs다. 경계는 이 모형의 화살표 한 개이며 실제 context switch 수와 자동으로 같지 않다.

이 계산은 분리하면 항상 느리다는 증명이 아니다. 실제 경로는 공유 메모리, 배칭, 직접 전달, 캐시 배치에 따라 달라지고 작은 커널의 검사 비용도 달라진다. 동일 요청·자료·장치·측정 구간과 성공 의미를 고정해야 비교할 수 있다. 신뢰성, 변경 범위, 지연과 처리율은 각각 관측해야 한다.

중간 과정을 따라가는 예제

위 가상 직렬 경로에서 경계 비용만 1 μs에서 0.25 μs로 낮춘다. 계산 6 μs와 장치 대기 20 μs는 그대로이며 겹침은 없다. 두 총시간과 차이는?

  1. 모놀리식 경로의 두 화살표 비용은 2×0.25=0.5 μs다.
  2. 분리 경로의 여덟 화살표 비용은 8×0.25=2 μs다.
  3. 공통 비용 6+20=26 μs를 각각 더하면 26.5 μs와 28 μs다.
  4. 분리 경로와 모놀리식 경로의 차이는 28−26.5=1.5 μs다. 이는 이 비용표의 결과다.

26.5 μs와 28 μs, 차이 1.5 μs다. 화살표 수가 같아지는 최적화나 큐 대기는 계산에 포함하지 않았다.

종이와 본문으로 직접 해보기

종이에 K/F/D/A/B를 그린다. F에 다른 주소 공간 쓰기 권한은 없고 B는 파일 서비스를 사용하지 않는다고 가정한다. F 정지 때 보호해야 할 두 성질과 보장되지 않는 한 성질을 적고, 경계 비용 0인 시간도 계산하라.

힌트 보기

B의 실행과 메모리 보호를 A의 읽기 성공과 구분한다. 0을 곱해도 공통 비용은 남는다.

풀이 보기

K의 보호 상태와 B의 메모리·실행을 F의 직접 손상에서 격리해야 한다. A의 읽기 성공은 보장되지 않는다. 자원 고갈·공유 장치 장애까지 막는다는 전제는 없으므로 별도 분석한다. 경계 비용 0이면 두 시간 모두 26 μs다.

오해와 반례

마이크로커널은 커널이 작으므로 운영체제 전체가 자동으로 안전하다.

사용자 F가 권한 있는 파일 내용을 거짓으로 응답하면 커널 메모리가 안전해도 읽기 결과는 틀린다. 서버·설정·공유 자원의 계약도 서비스 신뢰에 필요하다. 작은 커널은 분석할 경계를 줄일 수 있지만 전체 성공의 충분조건이 아니다.

F 정지 후 B가 계속 실행되면 A의 파일 읽기도 성공했는가?

답과 이유 보기

그렇게 결론 낼 수 없다.

B의 실행 격리와 F에 의존하는 읽기 성공은 서로 다른 성질이다.

한 단계 더

가상 경계 비용 c≥0에서 T_M=26+2c, T_μ=26+8c이므로 T_μ−T_M=6c≥0이다. 이 부등식의 증명은 공통 작업과 직렬 경로를 고정한 모형 안에만 있다. 분리 구현이 파일 계산을 δ μs 줄인다면 차이는 6c−δ가 되어 δ>6c일 때 순서가 뒤집힌다. 비용항이 달라지면 구조 이름만으로 우열을 증명할 수 없다.

소단원 2.2

exokernel·library OS

메모리 교체 정책을 앱이 정하면서 다른 앱의 페이지는 어떻게 보호할까?

준비 개념과 학습 목표

준비 개념

  • 정책은 허용된 선택 중 무엇을 할지 정하는 규칙이고 메커니즘은 그 선택을 실행·제한하는 수단이다. 어떤 페이지를 버릴지는 정책, 허가 없는 매핑 거절은 보호 메커니즘의 예다.
  • library OS는 앱이 이용하는 사용자 수준 운영체제 라이브러리다. 같은 이름을 쓰는 모든 구현이 exokernel 위에 있는 것은 아니며 여기서는 자원 보호 커널 위의 라이브러리를 다룬다.
  • 소유권 표는 자원마다 허용 주체·권한을 기록한다. read 권한과 write 권한은 다르며 소유자가 바뀌면 오래된 허가도 무효화해야 한다. 페이지는 이 모형에서 분할하지 않는 자원 한 개다.

학습 목표

  • 관리와 보호의 분리를 설명한다.
  • 소유권 변경과 오래된 매핑 무효화를 추적한다.
  • 회수·강제 회수와 데이터 보존의 별도 조건을 구분한다.

자원 보호 위에 추상화를 놓는다

exokernel은 하드웨어 자원을 안전하게 나누는 보호층을 중심에 두고, 가상 메모리·파일 같은 고수준 관리를 사용자 library OS에 맡기는 설계다. 앱은 필요에 맞는 관리 정책을 선택할 수 있다. 이것은 모든 특권 검사를 제거한다는 뜻이 아니라, 고수준 정책을 이해하지 않아도 자원 접근을 제한하는 인터페이스를 설계한다는 뜻이다.

자체 가상 시스템은 페이지 P0/P1/P2/P3과 두 앱 A/B를 가진다. 표 O[P]는 소유자 또는 FREE이며, 허가 표는 읽기·쓰기 매핑을 별도로 담는다. 라이브러리는 자기 페이지 중 무엇을 보존할지 고르지만 B의 페이지를 임의로 얻지 못한다. 현실의 페이지 테이블·DMA·캐시 상세를 이 작은 표로 구현했다고 주장하지 않는다.

허가와 사용을 연결하는 안전한 결합

논문은 secure binding으로 복잡한 허가 판단과 이후 자원 사용의 보호 검사를 연결한다. 아래 모형에서는 bind(A,P,write)가 O[P]=A일 때만 성공하며 사용 시 현재 허가가 유효한지 확인한다. 한 번 허가받았다는 사실만으로 영구 접근을 허용하면 자원 재사용 때 보호가 깨진다.

초기 P0/P1은 A, P2는 B, P3은 FREE다. A가 P2의 쓰기 결합을 요청하면 거절하고 표를 유지한다. A가 P3을 배정받으면 O[P3]=A로 바꾸고 허가를 만든다. 라이브러리 내부의 정렬·캐시 정책이 달라도 이 허가 경계는 지켜야 한다. 실제 구현에서는 보호된 매핑 갱신과 접근의 원자성·동기화도 필요하다.

회수는 자원과 내용의 두 문제다

자원이 부족하면 커널은 회수를 요청하고 라이브러리가 반납할 자원을 선택할 수 있다. 자체 모형은 협조적 반납 때 필요한 내용을 다른 허용 자원에 복사한 뒤 이전 매핑을 무효화하고 FREE로 표시한다. 비협조 때는 강제 회수를 허용하지만 오래된 허가를 먼저 제거해야 새 소유자에게 안전하게 넘길 수 있다.

접근 보호와 데이터 보존은 동일하지 않다. 강제 회수 뒤 A의 접근을 차단했다고 A가 저장하지 않은 내용까지 보존된 것은 아니다. 시간 제한, 백업 자원, 회수 통지와 재개 계약을 따로 정한다. 논문의 회수와 abort 논의는 이런 설계 책임을 보여 주며 본문의 종이 상태표는 특정 구현의 회복 실험이 아니다.

중간 과정을 따라가는 예제

초기 O=[A,A,B,FREE]. A의 P2 쓰기 bind를 검사한 뒤 A에 P3을 배정한다. 이어 A가 P1을 반납하고 B에 P1을 재배정한다. 소유권 표와 A의 오래된 P1 쓰기 권한은?

  1. P2 소유자가 B이므로 첫 bind는 거절하며 O=[A,A,B,FREE] 그대로다.
  2. P3 배정 성공으로 O=[A,A,B,A]가 된다. 배정의 성공과 허가 생성은 이 모형에서 한 보호된 연산이다.
  3. P1 반납 전에 A의 관련 매핑·허가를 무효화한다. O=[A,FREE,B,A]로 바꾸며 필요한 내용 보존은 반납 전 별도 작업이다.
  4. B에 P1을 배정하면 O=[A,B,B,A]다. 이후 A의 오래된 P1 쓰기는 거절한다.

최종 O=[A,B,B,A]이며 A의 P1 쓰기는 유효하지 않다. 재배정 전에 이전 접근을 끊는 순서가 필요하다.

종이와 본문으로 직접 해보기

초기 A={P0,P1}, B={P2}, FREE={P3}를 카드로 만든다. A가 P0을 강제로 빼앗긴 뒤 B에게 배정되는 과정을 그려라. 먼저 O만 B로 바꾸고 A의 매핑은 그대로 둔 잘못된 설계에서 어떤 불변식이 깨지는가?

힌트 보기

허용 쓰기 주체가 현재 소유자와 같은지 확인한다. 내용 보존은 표에서 알 수 없다.

풀이 보기

정상 과정은 A의 P0 허가·매핑 무효화→회수 상태/FREE→B 배정 및 B 허가다. 잘못된 설계는 O[P0]=B인데 A가 계속 쓰는 상태를 허용하여 “성공한 쓰기의 주체는 현재 소유자”가 깨진다. A의 내용이 남았는지는 백업·초기화·비밀 지우기 계약 없이는 결론 낼 수 없다.

오해와 반례

exokernel에서는 앱이 자원을 직접 관리하므로 허가 없는 페이지도 사용할 수 있다.

직접 관리의 범위는 허용된 자원이다. O[P2]=B인 표에서 A의 bind를 거절하는 반례처럼 보호 경계는 남는다. 또한 새 소유자에게 내용을 노출하지 않으려면 회수 때 초기화나 적절한 데이터 격리 계약도 필요하다.

한 단계 더

성공 쓰기 불변식 W(A,P)⇒O[P]=A를 귀납한다. 초기 허가는 자기 페이지에만 있다. bind는 소유권 검사로 보존하고, 반납/회수는 관련 허가를 먼저 제거하며, 배정은 FREE에서 새 소유자 허가만 만든다. 모든 접근이 보호 검사를 통과하고 이 전이가 원자적으로 관측된다는 조건에서 보존된다. 우회 DMA, 동시 재배정, 내용 비밀성은 이 표만으로 증명되지 않으며 추가 보호·동기화·초기화 조건이 필요하다.

소단원 2.3

구조별 신뢰·성능 비용

파일의 비밀을 위해 신뢰해야 할 코드는 커널 코드와 같은 집합일까?

준비 개념과 학습 목표

준비 개념

  • TCB(신뢰 계산 기반)는 정한 보안 성질을 지키기 위해 올바른 동작을 믿어야 하는 구성요소 집합이다. 성질을 먼저 정해야 하며 특권 코드의 집합과 항상 같지 않다.
  • 집합의 합집합 S∪T는 어느 쪽에든 있는 원소를 모두 모으고 교집합 S∩T는 양쪽에 있는 원소다. 합집합 크기는 |S|+|T|−|S∩T|이다.
  • 지연은 요청에서 완료까지의 시간, 처리율은 시간당 완료량이다. 한 요청 경계 비용을 μs로 계산한 결과는 큐·병렬성 없는 가상 지연이며 실제 처리율 측정이 아니다.

학습 목표

  • 성질별 TCB를 권한표와 구분한다.
  • 직렬 IPC 비용과 배칭 상환을 계산한다.
  • 검증 속성·설정 범위와 시스템 전체 보장을 구별한다.

신뢰는 어떤 성질을 지킬지에 달린다

가상 앱 A의 비밀 파일 내용을 보호하려면 커널 K, 파일 서버 F, 권한 설정 C가 올바르게 동작해야 한다고 가정한다. F가 사용자 모드라도 정당하게 읽은 내용을 다른 앱에 보내면 비밀성은 깨질 수 있다. 반면 F가 다른 앱의 메모리를 직접 덮어쓰지 못한다는 좁은 성질에는 하드웨어 보호 H와 K의 검사가 핵심이다.

따라서 이 모형의 비밀성 TCB는 {H,K,F,C}, 직접 메모리 격리 TCB는 {H,K,C}로 정한다. 인증 서버를 사용하는 새 서비스라면 집합에 그 서버가 추가될 수 있다. 코드가 작거나 권한이 낮다는 사실만으로 특정 의미의 신뢰가 제거되는 것은 아니다. 독립된 실패 영역도 공유 설정이나 장치가 있으면 공통 원인을 가진다.

비용은 경계뿐 아니라 메시지와 대기다

가상 IPC 총 비용은 고정 왕복 비용 α와 요청당 자료 처리 β를 둔다. m개 요청을 한 왕복으로 배치할 수 있고 합계 βm이며 추가 대기·오류·제한이 없으면 배치당 α+βm, 요청당 상환 비용 α/m+β다. m은 양의 정수다. 이는 배치 완료 후 비용을 나눈 값이지 모든 요청의 개별 응답시간이 아니다.

α=8 μs, β=2 μs이면 m=1의 요청당 비용은 10 μs, m=4의 비용은 4 μs다. 그러나 첫 요청은 나머지 세 요청이 모일 때까지 기다릴 수 있다. 지연 마감이 있거나 큰 메시지 때문에 복사·캐시 비용이 변하면 식의 가정부터 수정한다. 낮은 평균 비용이 모든 요청의 빠른 완료나 장애 격리를 보장하지 않는다.

형식 검증과 실험을 주장에 결박한다

seL4의 공식 검증 표는 아키텍처와 설정에 따라 확인된 속성을 구분한다. 이는 구체적인 커널·명세의 강한 근거지만 임의의 사용자 서버, 드라이버, 권한 정책이 모두 올바르다는 선언은 아니다. 명세가 요구한 성질과 실제 시스템이 필요한 성질 사이도 비교해야 한다.

성능 비교에는 버전·하드웨어·메시지 크기·부하·캐시·동시성·측정 구간과 오류 처리를 기록한다. 평균과 꼬리 지연, 성공률, 메모리 사용을 함께 보면 배칭의 이득과 대가를 구분할 수 있다. 아래 계산은 그 실험을 대체하지 않는 자체 모형이며 논문의 실험 수치를 현재 장치 결과로 사용하지 않는다.

중간 과정을 따라가는 예제

비밀성 집합 S={H,K,F,C}, 별도 네트워크 서비스 집합 T={H,K,N,C}다. 전체 두 서비스 신뢰 집합 크기와 α=8 μs, β=2 μs의 m=4 배치 비용/요청당 비용을 구하라.

  1. 교집합 S∩T={H,K,C}의 크기는 3이다.
  2. 합집합 크기는 4+4−3=5이며 원소는 H,K,F,C,N이다.
  3. m=4 배치 비용은 8+2×4=16 μs다.
  4. 요청당 상환 비용은 16/4=4 μs다. 대기 시간은 이 비용표에 포함하지 않았다.

TCB 합집합은 다섯 구성요소이며 배치 비용 16 μs, 요청당 4 μs다. 실제 검증 코드량이나 지연 실측 수치는 아니다.

종이와 본문으로 직접 해보기

α=12 μs, β=3 μs로 바꾸어 m=1/3/6의 배치 비용과 요청당 비용을 표로 써라. 첫 요청이 15 μs 배치 수집을 기다린다면 m=6의 요청당 5 μs만으로 첫 응답이 5 μs라고 할 수 있는가?

힌트 보기

먼저 α+βm을 계산하고 m으로 나눈다. 수집 대기를 처리 비용과 합치지 않고 구분한다.

풀이 보기

m=1:15/15 μs, m=3:21/7 μs, m=6:30/5 μs(배치/요청당)다. 첫 요청은 수집 대기 15 μs만으로 이미 5 μs를 초과한다. 배치 전체 완료 때 답을 준다는 추가 모형이면 응답은 15+30=45 μs다.

오해와 반례

커널을 형식 검증했으므로 그 위 모든 앱의 성능과 보안도 증명됐다.

검증된 속성과 구성은 한정된다. F가 비밀을 누설하는 반례나 배치 수집의 긴 대기는 올바른 커널과 동시에 발생할 수 있다. 앱의 명세·설정·경계와 실제 측정은 별도로 필요하다.

비밀 파일을 읽는 사용자 서버 F를 비밀성 TCB에서 항상 제외할 수 있는가?

상환 비용 감소가 각 요청의 응답시간 감소를 보장하는가?

답과 이유 보기

아니다.

수집 대기·큐·배치 결과 반환 시점이 개별 지연에 영향을 준다.

한 단계 더

α≥0, β≥0이고 같은 비용표가 유지될 때 m≥1에 대해 c(m)=α/m+β다. c(m)−c(m+1)=α/[m(m+1)]≥0이므로 요청당 상환 비용은 증가하지 않는다. 하지만 수집 대기 d(m)에 제한이 없다면 첫 응답 d(m)+α+βm은 증가할 수 있다. 비용 단조성과 응답 지연 단조성의 대상이 다르다. 검증 범위를 넓힐 때도 TCB 합집합은 중복을 한 번만 세며 구성요소 수를 버그 확률로 해석하지 않는다.
