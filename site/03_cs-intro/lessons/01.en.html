Subtopic 1.1

Input, processing, and output

If a computer is asked to find the highest of three friends’ scores, will it also decide whose name to show when two friends tie?

Preparation and learning goals

Preparation

  • Decide whether 7 > 4 is true. If comparisons are unfamiliar, review the number line: the number farther to the right is larger.
  • Follow rules one line at a time and write the current values on paper. Think of a variable as a name attached to a current value.

Learning goals

  • Specify the input types and allowed values, and state what the output means.
  • Trace a procedure for finding the largest of three numbers and examine ties and negative-number counterexamples.
  • Explain how an intended goal can differ from the computation actually specified.

Turn a goal into a precise computational contract

“Tell me who did best” is ambiguous even for a person. Does “best” mean the highest score or the greatest effort? How should a tie be shown? In this unit, the input is limited to three integers a, b, c, and the output is their largest integer m. Returning a person’s name requires a separate specification. A specification states, before implementation, the relationship that must hold between an input and its result.

Mathematically, the input domain D is Z³: the set of ordered triples (a,b,c) of integers. The output m must be one of a, b, c and must be at least as large as each of them. We assume comparable integers and a representation wide enough for the allowed values. A string such as “missing” or an absent value is outside D. A real product must also specify whether to reject such an input or handle it using a separate result.

Distinguish input, processing, and output

Input is the data supplied to a computation. Processing applies rules to that data and the current state. Output is the result passed to a user or another computation. Supplying the answer at the start does not explain how to find the maximum. Once a procedure is specified, the same input can be traced on paper. Here we start m at a, replace m if b is larger, and then compare c in the same way.

Returning a value is different from displaying it. If a maximum function returns 8 but its caller displays 6, we can investigate the calculation and the display separately. Not every program finishes after one input and one output. Games and servers repeatedly respond to input events and state changes, so their input–processing–output picture also needs a current state and a next state.

Explain correctness with a small invariant

Before the first comparison, m=a is the largest of the one number seen so far. After comparing b, the larger of those two values remains in m. Comparing c leaves the largest of all three. A property maintained at specified points during processing is called an invariant. “m is the largest number seen so far” links initialization, updates, and termination. It gives stronger support than happening to pass a few examples.

A strict comparison > handles ties correctly when the output is only a value. If we also return a winner’s position, however, keeping the earlier position and replacing it with the latest position give different tie policies. Starting m at 0 is also wrong for inputs that are all negative: it can return 0 even though 0 is not an input. Starting with an actual input value removes that counterexample.

m ← a
if b > m: m ← b
if c > m: m ← c
return m  // Pseudocode; not an execution result

A worked example, step by step

Return only the largest of the three integers (-4, -1, -1). Do not return the name of a person tied for the highest score.

  1. Initialize m=-4. The values seen so far are [-4].
  2. Compare b=-1 with m=-4. Since -1>-4, set m=-1, the largest of [-4,-1].
  3. Compare c=-1 with m=-1. Since -1>-1 is false, keep m=-1.
  4. Check that m is an input value and is at least as large as all three inputs.

The maximum is -1. Two inputs share that maximum, but the output is one value. The procedure made two comparisons.

Try it with paper and the lesson

Write 8, 8, 3 on cards and trace the same procedure. Then extend the rules to return the first position of the largest value as well. Count positions from 1 and choose the earlier position in a tie.

Show hint

Remember a position p alongside m. Change both m and p only when you find a strictly larger value.

Show solution

Start at (m,p)=(8,1). The second 8 is not larger, so keep both values; the third value 3 changes nothing either. The result is (8,1). If > is replaced by >= and the position is updated each time, the tie changes p to 2 and violates the specification.

Misconception and counterexample

A computer understands our purpose automatically when we ask it to find “the best.”

The highest score and the greatest effort describe different relationships. If the input contains no information about effort, there is no basis for comparing it. A rule for selecting one person from a tie must also be chosen by people. Learning-based systems still need inputs, objectives, and evaluation criteria; their outputs are not automatically guaranteed to satisfy a specification.

Check your understanding

For the three scores 4,9,2 and the statement “the maximum is 9,” what are the input and the output?

Show answer and reasoning

The input is 4,9,2; the output is 9.

The three numbers are supplied to the rules, and the comparison result is returned.

What goes wrong if m starts at 0 for input -7,-2,-5?

Show answer and reasoning

The procedure incorrectly returns 0. The correct result is -2.

0 is not an input value, and initialization already fails to make m the maximum of the values seen.

Is 6,6,6 an invalid input when the specification returns only a value?

Show answer and reasoning

No. The output is 6.

A tie does not prevent a maximum from existing. Choosing one person is a separate problem.

Explore further

Extend the procedure to n integers. For n≥1, start with the first element and compare each remaining element once: n−1 comparisons. Write an inductive explanation: after processing k elements, m is the largest of those k elements. An empty list has no first element, so the same initialization is impossible. Either forbid empty input or introduce a separate “no result” value.

Subtopic 1.2

Problem decomposition and abstraction

When designing a classroom book-loan service, do we need to record the color of every book cover?

Preparation and learning goals

Preparation

  • Distinguish an input from a result. Identify both in “given a book identifier, report whether the book can be borrowed.”
  • Apply rules in order. Be able to pass the result of one step as input to the next.

Learning goals

  • Distinguish decomposition from abstraction and write a simple module contract.
  • Construct a counterexample that shows what goes wrong when necessary information is discarded.
  • Explain the conditions under which connecting partial specifications achieves the overall goal.

Decomposition divides responsibilities

Treating a book loan as one large task mixes member checking, finding a book, deciding whether it can be borrowed, and saving the record. Problem decomposition divides that task into smaller tasks with clear responsibilities. “Check member” takes a member identifier and returns validity; “find book” takes a book identifier and returns its current state. Recording each task’s input, output, and failure result makes it easier to locate the part that needs changing.

Smaller pieces are not automatically better. If dividing one responsibility makes several places update the same state together, the connections can become harder to manage. This first unit assumes one person processes requests in order, without concurrent loan requests. If two users try to borrow the same book at once in a real service, a separate design must prevent a race between checking availability and updating the record.

Abstraction preserves information needed for a purpose

Abstraction models a situation by preserving distinctions needed for the questions we care about and hiding other details. To decide whether a book can be borrowed, its identifier and on-loan status matter, while its cover color usually does not. Treating differently colored books with the same loan status alike does not change the answer. A cover-color search service, however, cannot discard color. Whether an abstraction is suitable depends on its purpose.

More precisely, let A(r) be a model of a real-world state r. If A(r1)=A(r2) but the answers we need for r1 and r2 differ, no computation using only that model can always return the correct answer. This is a counterexample showing that the model has lost a necessary distinction. The important task is to identify and preserve differences that change the answer, rather than store every detail of reality.

Check the contracts between small tasks

Our example approves a loan only if the member is valid, the book exists, and the book is not already on loan. If memberOK, bookExists, and loaned are Boolean values, approval is memberOK AND bookExists AND NOT loaned. In an implementation where loaned cannot be read for a missing book, the bookExists=false path must end before that read. Distinguish the assumption that every logical input exists from the actual order of data lookup.

Individually correct tasks can still produce an incorrect overall result if their contracts do not fit. For example, a book lookup might return “not found,” while the next task interprets it as “empty, so available.” An interface is a shared contract about meanings and allowed states, not just a function name. Later, the data-structures course separates this contract from internal representation, and software engineering addresses changes and verification across modules.

A worked example, step by step

Member M is valid. Book B17 exists and has loaned=true. Requests are processed sequentially; reservation and overdue-loan policies are excluded. Determine whether this loan is allowed.

  1. Member-check module: M→memberOK=true.
  2. Book-lookup module: B17→bookExists=true, loaned=true.
  3. Decision: true AND true AND NOT true = true AND true AND false = false.
  4. Return a rejection and leave the loan record unchanged.

Reject the loan. A valid member is only one of the conditions and is not sufficient by itself.

Try it with paper and the lesson

Book A exists but is on loan. Book Z does not exist. If the model keeps only one “unavailable” state, can it distinguish the rejection reasons “on loan” and “book not found”? Write a model that preserves the necessary information.

Show hint

Check whether two real-world cases grouped into the same model state require different answers.

Show solution

It cannot distinguish them: the two real states were merged, but their required reasons differ. Keeping NOT_FOUND, ON_LOAN, and AVAILABLE as three states preserves the distinction. Cover color is still unnecessary for deciding these rejection reasons.

Misconception and counterexample

An abstraction is better whenever it discards more detail.

Discarding on-loan status could wrongly approve every existing book. The criterion is whether distinctions needed for the purpose are preserved, not merely whether less information is stored. Decomposition is related to abstraction, but dividing task responsibilities and reducing distinctions in information are different operations.

Check your understanding

What is it called when member checking and book lookup are made into separate tasks?

Show answer and reasoning

Problem decomposition.

Tasks with different responsibilities are separated and connected.

Under this example’s policy, what happens when the member is valid, the book exists, and the book is not on loan?

Show answer and reasoning

The loan is approved.

All three required conditions hold. Do not silently add excluded policies such as overdue loans or reservations.

Is discarding cover color always safe?

Show answer and reasoning

No. It is unsafe for a service that searches by color.

The model would lose a color distinction that changes the answer.

Explore further

Add a borrowing limit of three books per member. Include the current loan count in the model and add count<3 to the approval conditions. If two concurrent requests both read count=2, both may be approved, producing four loans. Explain why correctness of the sequential model does not automatically extend to the concurrent model. Operating systems and databases later address implementation of concurrency control.

Subtopic 1.3

A map of computer-science fields

A book-search button returns results slowly. Can studying one programming language alone explain and fix the problem?

Preparation and learning goals

Preparation

  • Know the meanings of input, processing, and output. Restate the example as book-title input→search→result list.
  • Recognize that a service has several responsibilities. Think separately about its interface and its stored records.

Learning goals

  • Distinguish major computer-science fields by their questions and responsibilities.
  • Trace one service through several layers and state the assumptions.
  • Choose evidence to examine without declaring a cause from a symptom alone.

Languages are tools; fields organize questions

C and Python are tools for expressing and executing procedures. Computer science is more than a collection of language courses. Algorithm analysis asks which procedures are correct and how much work they require. The study of data structures asks how data should be organized and which operations it should support. Computer architecture asks how hardware executes instructions. The study of computer systems asks how programmers can understand that execution and reduce its costs. One language can be used for work in many fields.

The study of operating systems addresses how programs share CPU time, memory, and devices. Networking studies communication between computers. Database study addresses querying stored data and maintaining consistency. Software engineering deals with requirements, changes, testing, and collaboration. Human–computer interaction studies interfaces that help people achieve their goals. These boundaries organize a course’s focus; real problems often span several fields.

Follow one button through the layers

A search interface may take a title string and construct a request. A network carries it to a server, which searches stored data and returns results for the interface to display. This is an illustrative web-search-service model. Not every program has a server: an offline book catalog has no network step. First establish the structure of the situation instead of automatically inserting familiar layers.

A slow result can have several causes. A search procedure may compare too many items; transmission waiting, disk reads, or interface rendering may also take time. Changing languages on the guess “Python is slow” lacks sufficient evidence. Observe the time spent at each stage separately to narrow down the field to investigate next. Label measurements separately from estimates.

Connect theory, implementation, and human judgment

Theoretical fields study computability, logic, correctness, and complexity formally. Artificial intelligence includes learning rules or prediction models from data, and probability and statistics are involved in evaluating performance. Even a model that recommends “books you might like” does not automatically resolve consent, privacy, or accessibility. People still choose requirements and evaluation criteria.

In these courses, choose an entry point that matches your preparation, while keeping the assumptions used to simplify a question visible. Comparing search steps on paper examines one part of an algorithm; measuring the runtime of an actual server provides different evidence. Do not turn a fact established in a small model into a guarantee about an entire product’s performance or security. This first unit supplies a map; later courses develop definitions, proofs, and implementations in depth.

A worked example, step by step

Assume an illustrative sequential search service has request transmission 20ms, server search 70ms, response transmission 20ms, and display 10ms. There is no overlap or retry. These are hypothetical observations.

  1. The total time is 20+70+20+10=120ms.
  2. Assume server search is reduced from 70ms to 35ms while the other stages stay unchanged.
  3. The new total is 20+35+20+10=85ms.
  4. The search stage is twice as fast, but overall speedup is 120/85=24/17≈1.41.

The total drops by 35ms. Improving the search stage, a candidate bottleneck, does not double overall speed. The numbers are hypothetical data, not measurements from an actual service.

Try it with paper and the lesson

For each symptom—“the wrong book is found,” “the server has results but the interface is empty,” and “another user’s loan records are visible”—name one boundary to investigate and one piece of evidence to check.

Show hint

Distinguish query input, server response, interface state, and user permissions. A symptom can have several causes.

Show solution

For the first symptom, compare the input string and server query result to investigate search/data quality. For the second, compare the response content and display state to investigate interface processing. For the third, check the requesting user, access decision, and returned records to investigate security/data boundaries. These are starting points for investigation, not confirmed causes.

Misconception and counterexample

The fields are independent, so a web service needs only web programming.

Incorrect search traversal can involve data structures and algorithms; mixed-up user records can involve databases and security. Conversely, not every small project requires a deep implementation of every specialty. Use the required features and constraints to decide how much depth is needed.

Check your understanding

Which field mainly asks how the number of comparisons in a search grows with input size?

Show answer and reasoning

Algorithm analysis.

It explains a procedure’s cost as a function of input size.

Starting from the original example, what is the total if display time falls from 10ms to 5ms?

Show answer and reasoning

115ms.

With unchanged other stages and no overlap, 120−5=115ms.

Does a long server-search time alone prove that a particular language is the cause?

Show answer and reasoning

No.

Evidence must distinguish other possible causes such as the search method, storage device, and input size.

Explore further

Even reducing search time to 0ms leaves 50ms in this model. The maximum overall speedup is 120/50=2.4. When several requests are processed at once, one request’s latency and requests completed per second are different measures. Computer-systems cost analysis and operating-system resource sharing return to this distinction.
