소단원 7.1

배열과 연결 구조

같은 카드 순서를 저장해도 세 번째 카드를 찾는 경로는 같을까?

준비 개념과 학습 목표

준비 개념

  • 순서열은 값의 순서를 가진다. 길이 n의 유효 위치는 0..n−1이며 빈 순서열에는 유효 위치가 없다.

  • 배열의 용량 c와 실제 길이 n은 비음수 정수이며 0≤n≤c다. 뒤의 빈 칸은 아직 순서열 원소가 아니다.

  • 연결 구조의 노드는 값과 다음 노드 참조를 가진다. head는 첫 노드, None은 다음 노드가 없다는 표시다.

학습 목표

  • 배열 위치 계산과 연결을 따라가는 접근을 구별한다.

  • 삽입의 값 이동/참조 변경을 추적하고 연결 보존 조건을 설명한다.

목록에서 지웠는데도 다른 이름이 그 노드를 기억한다면, 그 값도 사라진 걸까?

순서열의 원소 제거와 저장 객체의 수명은 다른 질문이다. 유한 비순환 단일 연결열 u5→v9→z2→None에서 외부 이름 saved가 v를 가리킨다고 하자. u.next=z로 바꾸면 목록 순서는 [5,2]가 되지만 saved는 여전히 v를 가리킨다. 이번 모형은 노드를 실제 해제하지 않는다.

배열도 길이 n을 줄이면 사용하지 않는 칸의 오래된 값이 논리 원소가 아니다. 삭제 위치 뒤의 값을 왼쪽으로 옮긴 후 n을 줄인다. 칸에 숫자가 남아 있다는 사실만으로 유효 원소를 판단하지 말고, 논리 범위와 별도 참조의 계약을 먼저 읽는다. 실제 메모리 주소·해제·가비지 수집 결과는 관측하지 않았다.

먼저 확인할 개념
  • 대입과 상태

    참조 이름이 무엇을 보존하고 어느 링크를 바꾸는지 추적한다.

  • 위치와 값의 계약

    목록 원소 범위와 값이 남아 있는 칸을 구별한다.

논리 순서와 실제 위치

여기 배열은 같은 양의 크기 w의 원소를 연속 칸에 저장하는 추상 모형이다. 시작 주소 B이면 유효 위치 i의 주소는 B+iw다. B=2000,w=4인 종이 주소표에서 위치 2는 2008이다. 이는 실제 장치 주소를 읽은 결과가 아니다.

단일 연결열은 논리적 순서를 next로 나타낸다. u(값 5)→v(값 9)→z(값 2)→None이라면 세 번째 원소를 찾으려 head에서 next를 두 번 따라간다. 연결 순서와 메모리 주소 순서는 같을 필요가 없다.

배열에 끼우려면 빈 칸으로 이동한다

용량 5, 길이 3의 A=[5,9,2,빈,빈]에서 위치 1 앞에 7을 넣으면 뒤 값들을 오른쪽으로 옮긴다. 위치 2를 3으로 먼저 옮기고 위치 1을 2로 옮겨야 아직 복사하지 않은 값을 덮지 않는다. 삽입 위치 i는 0≤i≤n, 원소 읽기는 0≤i<n로 조건이 다르다.

용량이 충분할 때 뒤 이동 수는 n−i다. 빈 열에 위치 0으로 넣으면 이동 0회다. 용량이 없으면 새 공간 확보/복사 비용과 실패 정책이 추가되므로 삽입 전체를 단순한 칸 쓰기 하나라고 하지 않는다.

참조를 바꾸는 순서에도 이유가 있다

u와 v 사이에 새 노드 p(값 7)를 넣으려면 먼저 p.next=u.next로 기존 v를 보존하고 u.next=p로 연결한다. 앞 노드 u와 기존 연결열에 속하지 않는 사용 가능한 새 p가 이미 주어졌다는 조건이다. u를 찾는 비용은 별도다.

반대로 u.next=p를 먼저 쓰고 그 값을 p.next로 복사하면 p.next=p라는 자기 순환을 만들 수 있다. 다른 참조가 없다면 원래 v/z의 연결도 잃는다. 노드 할당·해제·참조 소유권은 실제 언어에서 따로 검토해야 하며 종이 연결 변경은 그 구현 시험이 아니다.

배열 뒤 칸과 saved는 같은 종류의 현상이 아니다. 각각 범위 밖 저장 흔적과 외부 참조다. 이 삭제는 값 순서 계약을 만족하지만 저장공간 회수나 안전 삭제를 증명하지 않는다.

중간 과정을 따라가는 예제

A=[5,9,2,빈,빈],n=3,c=5와 head=u, u5→v9→z2→None에 두 번째 위치의 새 값 7을 넣어 같은 논리 순서가 되는지 추적하라.

  1. 배열은 삽입 위치i=1이 0≤1≤3이고 n<c임을 확인한다. 연결열은 기존 앞 노드u와 새p7이 주어졌다고 가정한다.

  2. 배열 A[3]=A[2]로 2를 보존하고 A[2]=A[1]로 9를 옮긴다. 뒤에서 앞으로 복사하여 원래 값을 잃지 않는다.

  3. A[1]=7,n=4로 만든다. 앞 네 원소는[5,7,9,2]이며 뒤 이동 2회와 새 값 쓰기 1회다. 빈 마지막 칸은 원소가 아니다.

  4. 연결열은 p.next=v 후 u.next=p로 만들어 u5→p7→v9→z2→None이다. 기존 v→z 연결과 head=u는 그대로다. 둘 다 같은 값 순서다.

두 표현의 논리 결과는[5,7,9,2]다. 배열은 기존 값 2개 이동, 연결열은 새p와 앞u가 주어진 조건에서 참조 2개 설정이다.

조건을 바꾸어 비교하기

배열 삭제는 삽입과 반대 방향으로 복사한다

A=[4,8,1,6,빈], n=4, c=5에서 위치 1을 삭제하고 보존 순서를 추적하라.

  1. 반환할 옛 값 8을 보존한다.

  2. A[1]=A[2]로 1을 옮긴 다음 A[2]=A[3]으로 6을 옮긴다.

  3. n=3으로 줄여 유효 순서 [4,1,6]을 만든다. A[3]의 옛 6은 원소가 아니다.

기존 값 이동 2회, 반환 8이다. 뒤에서 앞으로 옮기면 원래 1을 덮어 잃을 수 있다.

비교할 점

기본 오른쪽 삽입의 뒤→앞과 왼쪽 삭제의 앞→뒤를 비교한다.

참조를 잃기 전에 지울 대상을 보존한다

u5→v9→z2에서 v를 제거하고 그 값도 반환하려 한다. saved는 v를 가리키며 해제는 하지 않는다.

  1. removed=u.next로 v를 보존한다.

  2. u.next=removed.next로 z에 연결한다.

  3. removed.value=9를 반환하며 saved가 보는 v는 여전히 존재한다.

목록은 [5,2], 반환 9다. 외부 참조 및 분리한 v.next를 자동 무효화한다고 주장하지 않는다.

비교할 점

기본 링크 변경에 반환 대상을 보존하는 단계와 외부 관찰 범위를 추가한다.

종이와 본문으로 직접 해보기

결과 배열에서 위치 3을 읽는 주소를 B=2000,칸 크기 4로 계산하라. 결과 연결열에서 그 위치까지 next를 몇 번 따라가는가? 앞u가 주어진 상태에서 p를 제거하는 연결 변경도 적어라.

힌트 보기

위치 0에서 시작하므로 링크 수와 방문 노드 수를 구별한다. 제거 전에 p.next가 가리키는 곳을 확인한다.

풀이 보기

배열 주소는 2000+3·4=2012다. 연결열은u→p→v→z의 next3회/노드 4개 방문이다. p 제거는 u.next=p.next=v로 바꾸어 u→v→z를 되찾는다. p 메모리의 실제 해제나 외부 참조 처리는 이 종이 모형에서 수행하지 않는다.

오해와 반례

연결열 삽입은 언제나 전체 작업이 상수 비용이다.

앞 노드를 찾는 순회나 새 노드 확보 비용이 있을 수 있다. 참조 변경 자체가 일정 개수라는 말은 원하는 앞 노드와 사용 가능한 새 노드가 이미 주어졌다는 조건 아래다.

연습 1 · 값과 상태 예측

A=[4,8,1,6,빈], n=4에서 마지막 위치 3을 삭제하면 이동 수와 새 길이는?

힌트 1

뒤에 원소가 몇 개 남는지 센다.

힌트 2

삭제는 n을 하나 줄인다.

풀이와 답 확인

  1. 뒤 원소 수는 n−i−1=0이다.

  2. 반환 6, 새 n=3이고 논리 순서는 [4,8,1]이다.

이동 0회다. 저장 칸 초기화 비용은 별도다.

흔한 오답에서 다시 생각하기

마지막 칸도 왼쪽으로 복사해야 한다.

뒤 값이 없으므로 복사할 원소도 없다. 읽기 범위와 삭제 반환을 먼저 구별하라.

연습 2 · 오류 찾아 고치기

길이 4 배열의 위치 1 삭제를 A[2]=A[3] 다음 A[1]=A[2]로 했다. 초기 [4,8,1,6]의 실패를 고쳐라.

힌트 1

첫 복사 뒤 원래 1을 읽을 수 있는지 확인한다.

힌트 2

작은 목적지부터 순서대로 옮긴다.

풀이와 답 확인

  1. 첫 작업 뒤 [4,8,6,6], 다음 뒤 [4,6,6,6]이다. n=3이면 [4,6,6]으로 실패한다.

  2. A[1]=A[2] 다음 A[2]=A[3]으로 바꾸면 [4,1,6]이다.

겹치는 복사의 방향을 작업에 맞춘다.

흔한 오답에서 다시 생각하기

삽입도 뒤에서 복사하므로 삭제도 같은 방향이다.

삽입과 삭제는 이동 방향이 반대다. 아직 읽지 않은 원래 원소를 덮는지 확인하라.

연습 3 · 직접 만들어 보기

head=u, u5→v9→None에서 첫 원소를 제거하는 빈 경우 포함 계약을 구성하라. 해제는 하지 않는다.

힌트 1

head가 None이면 EMPTY와 상태 유지다.

힌트 2

옛 head를 보존한 뒤 다음으로 head를 바꾼다.

풀이와 답 확인

  1. 비어 있지 않으면 removed=head, head=removed.next를 수행한다.

  2. 반환값은 removed.value다. 이번 입력의 반환 5, 새 head=v다.

  3. 빈 입력은 EMPTY를 반환하고 head=None을 유지한다.

연결 변경과 저장 객체 해제를 별도 요구로 남긴다.

흔한 오답에서 다시 생각하기

head를 먼저 바꾼 뒤 head.value를 반환한다.

그러면 이번에는 새 첫 값 9를 반환하여 지운 값 5를 잃는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

논리 목록 제거가 실제 개인정보 안전 삭제를 증명하지 못하는 이유를 배열과 saved 예로 설명하라.

힌트 1

유효 원소 범위 밖 칸은 자동 덮어쓰지 않았다.

힌트 2

외부 참조·복사본·저장장치 계약은 별도다.

풀이와 답 확인

  1. 배열은 n만 줄여 뒤 칸의 옛 값이 남을 수 있다.

  2. 연결열은 링크만 우회하고 saved에서 분리 노드에 접근할 수 있다.

  3. 실제 삭제·소유권·외부 복사·저장매체는 이번 종이 모형의 보장 밖이다.

논리 제거의 의미를 과도하게 저장 수명·안전 삭제로 확대하지 않는다.

심화: head에서 순회 k번 후 현재 노드가 원래 순서열의 위치k라는 불변식을 둔다. 기초 k=0은head다. 올바른 next가 위치k+1을 가리키므로 귀납 단계가 성립하고 유효i에서 정확히i번 링크를 따라간다. 배열의 삽입 직전에는 원래 위치j≥i의 값이 새 위치j+1에 같은 순서로 들어가야 한다. 큰j부터 이동하면 아직 읽지 않은 작은 위치를 덮지 않아 이 대응을 보존한다. 주소 계산과 참조 읽기를 단위 비용으로 하는 Word-RAM 모형에서는 배열 접근 Θ(1), 연결 위치i 접근 Θ(i+1)다. 유한·비순환·유효 노드와 고정 크기 원소/워드의 가정이 필요하다.

소단원 7.2

스택·큐·사전

같은 순서로 넣은 카드를 빼는데 왜 어떤 곳은 마지막 카드가 먼저 나올까?

준비 개념과 학습 목표

준비 개념

  • 인터페이스는 허용 연산과 결과의 규칙이고 표현은 그 규칙을 저장/구현하는 방식이다.

  • 스택의 top은 가장 나중에 넣은 쪽, 큐의 front는 가장 먼저 기다리는 쪽이다.

  • 사전은 키마다 하나의 값을 대응시킨다. 키 없음 표시 MISSING은 저장 값 0과 구별하는 별 표식이다.

학습 목표

  • LIFO/FIFO와 키 검색의 서로 다른 계약을 추적한다.

  • 빈/가득 찬 경우의 실패 정책과 원형 큐의 상태 정보를 설명한다.

두 칸짜리 큐가 한 바퀴 돌아 같은 인덱스가 되었을 때, 비었는지 어떻게 알까?

양의 용량 C의 순차 원형 큐는 head·tail·count를 모두 유지한다. 빈 제거는 EMPTY, 가득 찬 추가는 FULL을 반환하며 실패 시 모든 상태를 보존한다. 오래된 buf 값은 count와 논리 순서가 허용할 때에만 원소로 읽는다.

스택은 마지막 대기 항목을, 큐는 첫 대기 항목을 제거하고 사전은 키를 통해 현재 값을 찾는다. 이번에는 같은 종류의 요청을 세 인터페이스에 넣어 결과가 왜 다른지 비교한다. 자료구조 이름이 실패 정책·실제 실행 속도·동시 안전성을 자동 결정하지 않는다.

먼저 확인할 개념
  • 논리 원소와 저장 흔적

    물리 칸에 값이 있어도 현재 논리 항목인지 확인한다.

  • 조건별 상태 보존

    추가·제거 전제 실패 시 갱신하지 않는 경로를 읽는다.

스택과 큐는 무엇을 뺄지 정한다

스택은 push로 마지막에 넣고 pop으로 그 끝 값을 제거해 돌려주는 LIFO 계약이다. 큐는 enqueue로 뒤에 넣고 dequeue로 앞 값을 제거해 돌려주는 FIFO 계약이다. 같은 배열을 사용해도 제거 규칙이 다르면 다른 인터페이스다.

이 단원은 빈 구조에서 제거하면 EMPTY를 반환하고 상태를 그대로 둔다. 용량 제한이 있으면 가득 찼을 때 추가를 거절한다. 이것은 자체 실패 계약이며 모든 언어 라이브러리의 예외/반환값이 이와 같다는 뜻이 아니다.

사전은 위치가 아니라 키로 묻는다

put(k,v)는 없는 키를 추가하거나 기존 키의 값을 덮어쓴다. get(k)는 현재 값을 돌려주며 없으면MISSING이다. 키가 두 번 나와도 두 항목을 중복 추가하는 다중사전은 여기 계약이 아니다.

D={ki:0,mi:2}에서 get(ki)=0은 존재하는 항목이다. put(ki,3) 뒤에도 키 개수는 2이고 get(ki)=3이다. 순서나 정렬 연산은 따로 약속하지 않았으므로 키 검색 인터페이스만으로 저장 순서를 단정하지 않는다.

큐를 원형 배열에 표현한다

양의 정수 용량 C≥1의 원형 배열은 head,tail,count를 가진다. head는 다음 제거 위치, tail은 다음 추가 위치다. count0은 비었고 countC는 가득 찼다. 인덱스 이동은(i+1) mod C다.

추가 전 count<C면 buf[tail]에 쓰고 tail을 이동하여 count를 1 늘린다. 제거 전 count>0이면 buf[head]를 반환하고 head를 이동해 count를 1 줄인다. head=tail은 빈 경우와 가득 찬 경우 모두 가능하므로 이 표현에서는 count도 확인한다. 지운 칸의 오래된 값은 논리 큐 원소가 아니다.

용량 1도 같은 규칙을 따른다

C=1, 초기 head=tail=count=0에서 enqueue X, enqueue Y, dequeue를 추적하라.

  1. X를 buf[0]에 쓰고 tail=(0+1) mod 1=0, count=1이다.

  2. Y는 가득 찬 조건에서 FULL이며 상태를 유지한다.

  3. 제거는 X를 반환하고 head=0, count=0이다.

인덱스는 계속 0이어도 count로 빈/가득을 구별한다.

중복 요청을 보관할지 현재 값만 둘지

요청 (a,0),(b,2),(a,3)을 스택·큐·사전에 차례로 넣고 첫 제거 또는 get(a)를 구하라.

  2. 큐 첫 dequeue는 첫 요청 (a,0)이다.

풀이 보기

A추가 뒤(h,t,c)=(0,1,1), B뒤(0,2,2), 제거는A를 반환해(1,2,1)이다. C뒤(1,0,2), D뒤(1,1,3)으로 가득 찼다. E는 거절해 그대로다. 마지막 제거는B를 반환하고(2,1,2)가 되어 논리 큐[C,D]다. head=tail=1이었던 상태는 빈 것이 아니라 가득 찼다. 종이 추적이며 큐 코드 실행은 아니다.

풀이와 답 확인

  2. 빈 조건을 count=0으로 고치고 count>0이면 정상 제거한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

C≥1의 순차 원형 큐에서 tail=(head+count) mod C가 성공 추가와 제거 뒤 보존됨을 보이라.

힌트 1

추가는 tail와 count를 각각 1 증가시킨다.

힌트 2

제거는 head를 1 늘리고 count를 1 줄인다.

풀이와 답 확인

  1. 추가 뒤 새 tail=(옛 head+옛 count+1) mod C이며 새 count=옛 count+1이다.

  2. 제거 뒤 새 head+새 count는 옛 head+1+옛 count−1과 같아 같은 tail 식이다.

  3. 실패는 모든 상태를 보존하며 0≤count≤C의 조건을 먼저 검사한다.

인덱스 식은 보존되지만 실제 동시 접근의 원자성 증명은 아니다.

흔한 오답에서 다시 생각하기

이 식만 맞으면 데이터 FIFO도 자동 증명된다.

값을 쓰는 칸과 논리 위치 j의 대응도 유지해야 한다. 인덱스 식만으로 잘못된 값을 배제할 수 없다.

자료구조 선택 기준

빠른 읽기, 빠른 삽입, 작은 메모리를 모두 같은 기준으로 비교할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 최악 비용은 같은 크기의 허용 입력/상태 중 큰 비용이다. 분할상환 비용은 여러 연산의 합계로 판단한다.

  • 단위 비용 모형은 원소/참조/인덱스가 일정 개수의 워드에 들어가고 접근/비교/이동을 일정 비용으로 보는 가정이다.

  • 요구 연산은 위치읽기·앞삽입·뒤추가·키검색처럼 구체적으로 정한다. 같은 계약끼리 비교한다.

학습 목표

  • 연산·상태·모형에 따라 표현을 선택한다.

  • 동적 배열 배증의 총비용을 계산하고 최악 한 번/분할상환/확률평균을 구별한다.

공간을 딱 한 칸씩 늘리면 빈 칸은 줄지만 복사 총량도 줄어들까?

초기 용량 1인 빈 배열에서 뒤 추가만 수행한다고 하자. 배증 정책은 가득 차면 두 배로, 한 칸 증가 정책은 용량을 1만 늘려 기존 값을 모두 복사한다. 기존 원소 복사와 새 값 쓰기를 각각 1로 세며 할당·초기화·메타데이터 비용은 제외한다.

두 정책은 같은 순서열 계약을 지원하지만 공간 여유와 복사 합계가 다르다. 완료 후 새 배열 공간과 확장 중 옛·새 배열을 함께 보유하는 최대 공간도 다르다. 실제 메모리 정렬이나 객체 헤더를 이번 바이트 모형에 숨겨 넣지 않는다. 참조가 있는 노드의 공간도 값 칸만으로 비교하면 안 된다.

  • 합계 비용과 성장률

    한 번의 최악·전체 합계·현실 시간을 같은 주장으로 섞지 않는다.

한 연산의 이름만으로 선택하지 않는다

위치 읽기가 잦으면 배열의 직접 접근이 유리한 단위 비용 모형을 사용할 수 있다. 앞 삽입은 여유 공간 배열에서도n개 이동이지만 head를 아는 연결열은 새 노드와 참조를 상수 개수 바꾼다. 노드 확보가 이미 가능한지와 검색 비용도 함께 계산한다.

단일 연결열에tail을 유지하면 뒤 추가의 링크 변경은 빠르지만 뒤 삭제는 앞 노드를 찾아야 할 수 있다. “연결열의 모든 삭제가O(1)”은 아니다. 또한 정렬 연결열에도 이진 탐색 방식의 비교를 설계할 수 있으나 가운데로 이동하는 비용을 무시해 배열과 같은O(log n)시간을 보장해서는 안 된다.

확장 한 번과 전체 합계

동적 배열은 사용량보다 큰 용량을 잡아 뒤 추가마다 새 공간을 만들지 않는다. 이 단원의 모형은 초기용량 1에서 가득 찰 때 용량을 2배로 만들고 기존 모든 원소를 복사한 뒤 새 값을 쓴다. 각 원소 복사와 새 값 쓰기를 각각 1로 센다.

확장 직후의 한 추가는 기존n개 복사 때문에Θ(n)일 수 있다. 그러나 처음부터m개 뒤추가의 총 복사합은 1+2+4+…로 묶인다. 이 합계 분석은 각 입력을 무작위로 골랐다는 평균 가정이 필요 없다. 앞/중간 삽입의 값 이동까지 같은 상수 분할상환 결과를 주장하지 않는다.

키검색의 조건과 전체 시스템

해시 사전의 기대 상수 검색에는 해시/충돌/적재율과 키 비용에 대한 조건이 필요하다. 모든키가 같은 버킷에 들어가면n개를 비교하는 최악이 가능하다. 길이가 커지는 문자열의 해시와 같음 비교까지 언제나 상수는 아니다.

가상 요청 대기열은 순차 FIFO, 최대 2개이며 가득 차면 새 요청을 거절하고 빈 제거는 EMPTY로 정한다. 입력 A, B, C 추가 뒤 한 번 제거하고 C를 다시 추가한 뒤 모두 제거하라. C=2 원형 큐의 상태와 반환을 써서 실패한 요청이 몰래 저장되지 않았음을 확인하라. 별도 저장 보고에서는 2바이트 값의 여섯 항목을 배증 배열 또는 값 2바이트/참조 4바이트 노드로 저장하려 한다. 배열의 최종 용량 8과 확장 4→8의 피크 공간을 20바이트 예산과 비교하고, 노드의 메타데이터 제외 공간도 계산하라. 값이 제거되었다고 실제 개인정보가 안전 삭제되었다는 주장까지 가능한지 구별하라.

힌트 1

처음 C 추가는 FULL이라 상태가 유지된다. A를 제거한 뒤의 C 추가는 새로운 성공 연산이다.

힌트 2

완료 배열과 확장 중 옛·새 배열의 합을 별도 계산한다. 논리 제거와 별도 참조·잔류 저장의 범위를 분리한다.

풀이와 답 확인

  1. A/B 추가 후 (head,tail,count)=(0,0,2), 논리 [A,B]다. C는 FULL로 상태가 같다.

  2. 제거는 A를 반환하고 (1,0,1)이다. C 재추가는 (1,1,2), 논리 [B,C]다.

  3. 다음 제거는 B 뒤 (0,1,1), 다음은 C 뒤 (1,1,0)이다. 추가 제거는 EMPTY다.

  4. 완료 배열은 8×2=16바이트라 예산 20바이트 이내지만 확장 순간 (4+8)×2=24바이트라 초과한다. 노드 6개는 6×6=36바이트로 초과한다.

  5. 이 보고는 선언한 공간 모형에 한정한다. 큐 제거는 논리 원소를 줄일 뿐 오래된 buf 값·외부 참조·실제 저장매체의 안전 삭제는 시험하지 않았다.

첫 C는 거절, 이후 성공한 C만 저장되어 A/B/C 순서로 반환된다. 완료 공간 16바이트만으로 예산 통과를 결론내릴 수 없고 확장 피크 24바이트와 노드 36바이트도 검토해야 한다. 실제 메모리·안전 삭제·학생 시험은 미수행이다.
