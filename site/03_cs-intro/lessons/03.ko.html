소단원 3.1

CPU와 명령 실행

컴퓨터가 덧셈을 했다는 말은, 내부의 어느 값이 어떻게 바뀌었다는 뜻일까?

준비 개념과 학습 목표

준비 개념

  • 상태: 한 순간의 레지스터·메모리·다음 명령 위치처럼 이후 동작에 필요한 값을 묶은 것이다. 이전 이야기를 전부 기억하는 것과는 다르다.
  • 대입 A←x: A의 새 값을 x로 바꾼다는 뜻이다. 오른쪽 값은 변경 전 상태에서 읽는다. A←A+1은 수학적 등식 A=A+1이 아니다.
  • 나머지: 양의 정수 256으로 나눈 나머지 x mod256은 0~255이다. 이 단원 가상 레지스터는 8비트 부호 없는 값만 저장한다.

학습 목표

  • 명령어 집합의 의미와 CPU 구현을 구별한다.
  • PC·레지스터·데이터 메모리의 상태 변화를 표로 추적한다.
  • 순차 명령 의미가 한 명령당 한 클록이나 프로그램 종료를 보장하지 않음을 설명한다.

명령은 상태를 바꾸는 규칙이다

CPU는 명령의 의미에 따라 계산과 제어를 수행한다. 명령어 집합 구조 ISA는 소프트웨어가 의존할 명령과 자료 표현 등의 계약이다. 명령 비트를 가져오는 인출, 의미를 알아내는 해독, 결과를 반영하는 실행으로 순차 의미를 설명할 수 있다. 실제 내부는 파이프라인·복수 실행·순서 변경 등을 사용할 수 있으므로 이 설명을 물리적인 한 명령 한 클록과 동일시하지 않는다.

프로그램 카운터 PC는 다음에 실행할 명령의 위치를 가리킨다. 일반 명령 후에는 다음 위치로 진행하지만 분기 명령은 조건에 따라 PC를 다른 위치로 정한다. 레지스터는 CPU가 계산 중 사용할 값을 보관하는 작은 저장 공간이다. 더하기 명령이 레지스터를 바꿨다고 원래 데이터 메모리까지 자동 갱신된다고 생각하지 않는다.

작은 자체 기계를 완전히 정의하기

종이 모형의 명령표 I와 데이터표 D는 분리한다. I의 각 행은 명령 하나, D는 주소 0~15에 8비트 값 하나씩을 갖는 배열이다. A와 B는 8비트 레지스터, PC는 명령표의 행 번호다. 실제 명령의 바이트 인코딩·물리 클록·예외·외부 입력은 모형에 없다. 프로그램과 데이터가 같은 주기억장치에 놓이는 저장 프로그램 방식도 있지만, 지금의 분리된 두 표를 그 실제 배치라고 주장하지 않는다.

한 단계는 I[PC]를 읽고 PC를 먼저 1 증가시킨 뒤 명령 효과를 적용한다. LOAD R,a는 R∈{A,B}에 대해 R←D[a], STORE A,a는 D[a]←A, ADD A,B는 A←(A+B) mod256이다. JZ A,k는 A=0일 때만 PC←k로 바꾼다. HALT는 정지 상태로 바꾸고 이후 단계가 없다. 실행할 단계에서 유효한 데이터 주소와 유효한 I[PC]만 사용한다. HALT 뒤에는 PC가 마지막 행 다음을 가리켜도 인출하지 않으므로 유효하다. 범위 밖 접근의 실제 언어 규칙은 따로 다룬다.

계산·저장·제어는 다른 효과다

LOAD는 값을 복사해도 원래 D[a]를 지우지 않고, STORE는 지정된 한 데이터 칸을 바꾼다. ADD는 A만 바꾸며 B와 데이터는 그대로다. 분기는 값을 계산하는 작업이 아니라 다음 실행 위치를 선택한다. 같은 명령표라도 초기 데이터가 다르면 상태 경로가 달라진다. 따라서 결과를 주장하려면 프로그램뿐 아니라 초기 상태와 모든 관련 규칙을 지정한다.

실행 횟수와 경과시간은 다른 정보다. 순차 모형에서 6개 명령을 실행했다고 6초 또는 6클록이라는 결론은 나오지 않는다. CPU 클록 빈도만으로 전체 프로그램 시간을 결정할 수도 없다. 메모리·입출력 대기, 명령별 비용과 구현이 영향을 준다. 분기가 되돌아가면 종료하지 않을 수 있으므로 몇 단계만 맞게 계산한 것과 모든 실행이 끝난다는 증명도 구분한다.

중간 과정을 따라가는 예제

초기 A=B=0,PC=0,D[8]=6,D[9]=4,D[10]=0이다. 명령표는 I[0]=LOAD A,8; I[1]=LOAD B,9; I[2]=ADD A,B; I[3]=STORE A,10; I[4]=JZ A,0; I[5]=HALT다. 한 단계마다 PC 증가 후 효과를 적용해 최종 상태를 구하라.

  1. PC0에서 LOAD 후 A=6,B=0,PC=1이다. PC1에서 두 번째 LOAD 후 A=6,B=4,PC=2다. D[8]/D[9]는 변하지 않는다.
  2. PC2의 ADD 후 A=(6+4) mod256=10,B=4,PC=3이다. D[10]은 아직 0이다.
  3. PC3의 STORE 후 D[10]=10,PC=4다. PC4의 JZ는 A=10≠0이므로 증가한 PC=5를 유지한다.
  4. PC5의 HALT는 PC를 6으로 증가시킨 뒤 정지한다. 정지 후에는 I[6]을 읽지 않는다. 실행 명령은 6개이고 마지막 A=10,B=4,D[10]=10이다.

6단계 후 정지한다. PC=6,A=10,B=4,D[10]=10이며 D[8]=6,D[9]=4다. 자체 기계의 의미 추적이며 실제 CPU 측정값이나 TOY 실행 출력이 아니다.

종이와 본문으로 직접 해보기

같은 명령표에서 D[8]=D[9]=0으로 바꾸고 D[10]=0에서 시작한다. 처음 다섯 명령 후 상태와 HALT 도달 여부를 구하라. 외부에서 I/D를 바꾸지 않는다고 가정한다.

힌트 보기

LOAD 두 번과 ADD가 A/B를 무엇으로 만드는지 보고, JZ가 증가된 PC를 다시 바꾸는지 확인한다.

풀이 보기

두 LOAD와 ADD 후 A=B=0,STORE 후 D[10]=0이다. 다섯 번째 JZ에서 PC는 5로 증가했다가 0으로 바뀐다. 전체 관련 상태가 초기 상태와 같으므로 같은 다섯 명령이 계속 반복되고 I[5]의 HALT에는 도달하지 않는다.

오해와 반례

명령이 하나 실행되면 한 클록이 지나고, 명령표의 맨 끝에는 반드시 도착한다.

종이 모형에는 클록 시간이 정의되어 있지 않다. 또한 0+0 입력은 다섯 명령 후 초기 상태로 되돌아가 HALT를 만나지 않는 반례다. ISA 수준의 효과·실제 회로 시간·종료 성질은 서로 다른 질문이다.

자기점검

ADD 직후, STORE 전에 D[10]의 값은?

답과 이유 보기

0이다.

ADD는 A만 바꾸며 데이터 메모리로 쓰는 별도 STORE가 아직 없다.

PC는 실행 횟수를 누적하는 변수인가?

답과 이유 보기

아니다.

다음 명령 위치이며 분기 때문에 이전 위치로 돌아갈 수 있다.

D[8]=250,D[9]=6이면 첫 ADD의 A와 다음 JZ 결과는?

답과 이유 보기

A=0이 되고 JZ에서 PC=0으로 돌아간다.

(250+6) mod256=0이다. 정수 합 256과 저장값 0은 다르며 이 입력도 HALT에 이르지 않는다.

한 단계 더

심화: 이 명령표에서 초기 D[8]=x,D[9]=y를 0~255로 고정하고 D[10]=0이라 하자. s=(x+y) mod256≠0이면 분기가 일어나지 않아 6단계에 정지한다. s=0이면 매 반복 LOAD가 A=x/B=y를 만들고 ADD는 A=0,STORE는 D[10]=0,JZ는 PC=0을 만든다. 첫 반복 이후 경계 상태가 같아 귀납적으로 무한 반복한다. 유한 상태 공간만으로 종료를 결론낼 수 없고, 결정적이며 외부 변화가 없는 기계에서 같은 비정지 상태가 되풀이되면 이후 경로도 되풀이된다는 논증이다.

소단원 3.2

메모리와 저장장치

같은 값을 계산해 화면에 보았는데, 전원을 끈 뒤 다시 열면 왜 사라질 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 주소와 내용: 주소는 칸을 찾는 이름이고 내용은 그 칸의 저장값이다. 칸 4에 52가 있으면 주소 4와 내용 52는 다른 값이다.
  • 바이트와 범위: 여기서는 1바이트=8비트, B개의 연속 칸은 0부터B−1까지다. 주소 범위를 벗어난 접근은 이 종이 모형의 유효 연산이 아니다.
  • 상태의 수명: 계산 중 값이 존재함, 프로그램 종료 뒤 존재함, 전원 중단 뒤 보존됨은 서로 다른 요구다.
  • word는 기계가 다루는 한 묶음의 데이터 단위이며 크기는 기계·계약에 따라 정한다. 여기서 바이트 주소 배열과 첫 소단원의 명령표 행 번호는 주소 단위가 같다는 가정을 하지 않는다.

학습 목표

  • 주소 단위·용량·자료의 바이트 순서를 조건과 함께 해석한다.
  • 작업 중 저장과 지속 저장을 구별한다.
  • 캐시와 저장 완료의 보장 범위를 분리한다.

주소가 가리키는 단위를 먼저 정한다

메모리는 주소로 접근할 저장 칸의 집합으로 모델링할 수 있다. 주소 하나가 1바이트인지 한 word인지 명시해야 용량을 계산할 수 있다. n비트 주소는 2ⁿ개의 서로 다른 주소 패턴을 만들지만, 모두가 실제 RAM에 매핑된다는 뜻은 아니다. 운영체제가 제공하는 가상 주소와 물리 메모리 위치도 같은 층이 아니며, 여기서는 매핑을 생략한 연속 바이트 배열을 쓴다.

16바이트 배열 D에서 주소 0~15가 유효하다. 2바이트 자료를 주소a부터 저장하려면 a와a+1이 모두 범위 안에 있어야 하므로 0≤a≤14다. 4비트 주소라는 표기만 보고 주소 15부터 2바이트를 읽어도 된다고 결론내릴 수 없다. 주소·크기·정렬·권한은 실제 접근에서 별도로 확인할 조건이다.

여러 바이트를 한 값으로 읽는 계약

같은 2바이트를 16비트 부호 없는 정수로 해석할 때, 낮은 주소에 낮은 유효 바이트를 두는 것이 little-endian, 높은 유효 바이트를 두는 것이 big-endian이다. 예를 들어 0x1234는 값 1×4096+2×256+3×16+4=4660이다. little-endian으로 주소 4/5에 0x34/0x12를 놓으면 낮은 바이트 0x34+256×0x12로 복원한다.

바이트 순서는 한 바이트 안의 화면 표기 방향이나 숫자의 부호 규칙과 다르다. 주소 4/5에 같은 0x34/0x12가 있어도 big-endian으로 해석하면 0x3412=13330이다. 파일 형식과 통신 형식도 순서를 따로 정할 수 있다. “주소 4” 자체가 값 4660이라는 뜻은 아니며, 그 주소에서 시작하는 두 바이트와 읽기 계약이 함께 있어야 한다.

접근 속도와 지속성은 서로 다른 축이다

레지스터·캐시·주기억장치·저장장치는 서로 다른 역할을 갖는다. 일반적인 DRAM 주기억장치는 전원 공급을 잃으면 값을 보존하지 못하므로, 실행 중 자료를 오래 남기려면 저장장치와 파일시스템 등 지속 저장 경로가 필요하다. 저장장치에 파일이 있어도 프로그램이 계산하려면 필요한 자료를 적절한 작업 공간으로 읽는다. 모든 메모리가 휘발성이라는 일반 명제는 쓰지 않는다.

캐시는 어떤 자료의 복사본을 가까이 두어 반복 접근을 돕는 전략이다. 읽기 캐시의 적중률과 데이터가 전원 중단 뒤 살아남는지는 다른 문제다. 파일 쓰기 요청을 접수했거나 화면에 저장되었다고 표시했다는 관찰만으로 모든 복사본이 안정적으로 기록되었다고 단정하지 않는다. 지연 쓰기·오류·저장 완료 계약을 확인해야 하며 비휘발성 매체도 영원한 무결성이나 백업을 보장하지 않는다.

중간 과정을 따라가는 예제

자체 연속 16바이트 메모리에 0x1234를 little-endian으로 주소 4부터 저장한다. 읽기 시간 모형은 캐시 적중 접근이 2단위, 미스 접근은 확인 2단위+하위메모리 40단위다. 접근 100개 중 적중 80/미스 20으로 고정하고, 모든 접근은 겹치지 않는다. 바이트와 전체 비용을 구하라.

  1. 주소 4에 0x34=52,주소 5에 0x12=18을 저장한다. 두 주소가 0~15 안에 있으므로 이 모형에서 유효하다.
  2. 복원은 52+256×18=4660이다. 두 바이트를 big-endian으로 읽으면 52×256+18=13330으로 값이 달라진다.
  3. 적중 80개는 80×2=160단위, 미스 20개는 20×(2+40)=840단위다. 미스 비용은 단순 40이 아니라 확인 비용을 포함한 42다.
  4. 합계 1000단위, 접근당 평균 1000/100=10단위다. 이 읽기 비용과 0x1234가 전원 중단 뒤 보존되는지는 별도로 판단한다.

D[4]=52,D[5]=18이며 little-endian 값 4660이다. 비용은 1000단위/평균 10단위이고 가상 읽기 모형의 계산이지 실제 ns 측정이나 지속 저장 실험은 아니다.

소단원 3.3

입출력과 하드웨어 계층

키보드에서 값을 입력하고 파일에 저장하는 동안, CPU는 어떤 일을 직접 하고 어떤 일을 맡길까?

준비 개념과 학습 목표

준비 개념

  • 인터페이스: 다른 구성요소가 사용할 수 있도록 정한 요청·응답과 조건이다. 내부 구현을 모두 보여 주는 것과는 다르다.
  • 완료와 성공: 요청 접수, 작업 완료, 성공, 원하는 사용자 결과는 같은 상태가 아니다. 끝났더라도 오류가 있을 수 있다.
  • 겹치기: 서로 다른 자원을 쓰는 작업이 같은 시간 구간에 진행할 수 있다. 같은 CPU를 동시에 두 작업에 사용할 수 있다는 뜻은 아니다.

학습 목표

  • 응용프로그램·운영체제·드라이버·장치의 책임을 연결한다.
  • 폴링·인터럽트·DMA의 서로 다른 역할을 구분한다.
  • 단계별 경로와 시간 모형의 가정으로 완료/오류와 겹침을 추적한다.

입출력은 여러 계약을 통과한다

입출력은 프로그램과 외부 장치 사이의 자료 이동과 제어다. 파일 저장 요청을 예로 들면 응용프로그램은 파일 인터페이스를 사용하고, 운영체제의 파일/블록 계층은 관련 요청을 구성하며, 장치 드라이버는 특정 장치의 제어 계약을 처리한다. 컨트롤러와 장치는 실제 전송/작업을 수행한다. 모든 장치가 같은 파일 경로를 따르는 것은 아니지만, 각 경계의 책임과 오류를 구별하는 관점은 유용하다.

CPU·메모리·입출력 장치는 연결망을 통해 상호작용한다. 비용과 요구 성능에 따라 계층이나 여러 연결을 쓰며, 교재의 단순한 버스 그림을 모든 실제 컴퓨터의 고정 배치라고 간주하지 않는다. 장치 레지스터를 메모리 주소처럼 접근하는 MMIO에서도 그 주소가 일반 RAM이라는 뜻은 아니다. 접근의 부작용·권한·순서 조건은 장치 계약을 따라야 한다.

상태 확인과 자료 이동은 다른 일이다

자체 장치의 상태를 READY→BUSY→DONE 또는 ERROR로 정의하자. READY일 때 자료/명령을 제출하고 접수되면 BUSY가 된다. BUSY 동안 같은 한 칸의 요청을 덮어쓰지 않는다고 정한다. DONE은 장치 작업의 성공적 완료, ERROR는 실패다. 드라이버가 해당 상태와 요청을 연결해 확인한 뒤 결과를 상위에 전달한다. 이 네 이름과 정책은 종이 장치의 정의이며 실제 장치 공통 표준이 아니다.

폴링은 CPU가 상태를 반복 읽는 방식, 인터럽트는 장치 등이 사건을 알려 CPU의 처리 흐름이 핸들러로 넘어가게 하는 방식이다. 알림이 왔어도 어느 요청인지와 오류를 확인해야 한다. DMA는 장치와 메모리 사이의 자료 복사를 전담하게 하는 방식으로, 완료 알림 방식과 별개의 축이다. CPU의 준비·처리 비용이 0이라는 뜻이 아니며 모든 입출력이 DMA나 인터럽트를 쓰는 것도 아니다.

진행 경로와 시간을 각각 확인한다

상위 코드가 저장 요청을 냈다는 사실은 장치의 DONE을 관측했다는 뜻이 아니다. DONE의 구체적인 보장도 장치와 호출 계약에 의존한다. 종이 예제에서는 외부 전원 장애가 없고 요청 하나가 정해진 시간 후 성공한다고 가정한다. 이 성공을 전원 중단 후의 지속 보존이나 사용자 내용의 정확성까지 자동 확대하지 않는다.

일정한 CPU 확인 비용과 장치 작업시간을 가정하면 폴링으로 바쁜 시간과 독립 계산을 겹칠 수 있는 시간을 비교할 수 있다. 그러나 빠른 장치에서는 인터럽트 준비·처리 비용이 더 클 수도 있다. 인터럽트 알림과 DMA를 쓴다는 이름만으로 항상 빠르다고 증명할 수 없다. 어떤 자원이 점유되는지, 대기 중 할 일이 있는지, 완료 확인의 비용이 얼마인지 함께 정한다.

중간 과정을 따라가는 예제

자체 장치가 READY이고 오류·외부 장애가 없다. CPU 준비는 0~1ms, 접수 후 장치 작업은 1~6ms이다. 완료 확인·처리는 6~7ms에 CPU를 1ms 사용한다. 독립 CPU 계산은 3ms다. 방식 P는 1~6ms 내내 CPU가 폴링하여 다른 계산을 못 한다. 방식 I는 그 구간에 독립 계산을 수행한다. 모든 비용은 고정이며 준비·처리 중에는 독립 계산을 하지 못한다.

  1. 두 방식 모두 CPU 준비가 끝나는 1ms에 READY→BUSY로 요청이 접수된다. 장치는 1~6ms 동안 5ms 작업하고 6ms에 DONE이 된다.
  2. P는 0~1ms 준비, 1~6ms 폴링, 6~7ms 처리, 7~10ms 독립 계산이다. 두 과제가 모두 끝나는 시각은 10ms이고 CPU 점유시간도 10ms다.
  3. I는 0~1ms 준비 뒤 독립 계산을 1~4ms에 수행한다. 4~6ms에는 CPU가 유휴이고 장치만 일한다. 6~7ms 알림 확인·처리 뒤 두 과제는 7ms에 완료한다. CPU 점유는 1+3+1=5ms다.
  4. 장치 작업 5ms는 어느 방식에서도 줄지 않았다. 전체 완료 10→7ms와 CPU 점유 10→5ms는 다른 비교다. 가상 I 모형은 알림·확인의 추가 비용을 정해진 1ms에 모두 포함한다.

주어진 가정에서 P는 10ms/I는 7ms에전체완료한다. CPU 점유는 10ms/5ms다. 실제 장치 성능이나 인터럽트 지연 측정 결과가 아니다.

종이와 본문으로 직접 해보기

장치가 6ms에 DONE 대신 ERROR를 보고하면 성공으로 전달해도 되는가? 별도의 성공 일정 사례에서 독립 계산은 8ms이고 준비·장치·처리 조건은 같다. I의 계산은 6ms에 중단했다가 7ms에 재개할 수 있다고 가정할 때 두 과제의 완료 시각을 구하라.

힌트 보기

1~6ms에 계산 5ms를 수행하고 남은 3ms를 처리 뒤 진행한다. 오류는 완료시각과 별도의 결과 상태다.

풀이 보기

ERROR는 실패이므로 성공으로 전달하지 않고 요청과 오류를 연결해 보고한다. 성공하는 8ms 계산 사례의 I는 0~1ms 준비, 1~6ms 계산 5ms, 6~7ms 처리, 7~10ms 남은 계산 3ms로 10ms에 전체 완료한다. P는 처리 끝 7ms 뒤 8ms를 계산하여 15ms에 완료한다. 오류 사례와 성공 일정 사례는 서로 별도 가정이다.

오해와 반례

인터럽트가 왔으면 성공했고, DMA이면 CPU는 아무 일도 하지 않는다.

ERROR 알림도 인터럽트로 전달될 수 있어 상태와 요청을 확인해야 한다. DMA에도 복사할 위치·크기·권한 등의 준비와 완료/오류 처리가 필요하다. 알림 방식은 결과의 정당성 증명도, CPU 비용 0의 증명도 아니다.

자기점검

한 단계 더

심화: 고정 준비 p≥0, 장치 작업 d≥0, 완료 처리 h≥0, 독립 CPU 계산 c≥0은 모두 같은 시간 단위다. P는 장치 작업 동안 CPU를 독점하고 계산을 뒤에 수행하므로 Tₚ=p+d+h+c다. I는 장치 작업과 계산을 겹치고 완료 처리 시점에 계산을 중단·재개할 수 있어 Tᵢ=p+max(d,c)+h다. c≤d면 계산이 먼저 끝나 장치 완료를 기다린다. c>d면 장치 완료 때 남은 c−d를 처리 뒤 수행하므로 같은 식이다. 차이는 Tₚ−Tᵢ=d+c−max(d,c)=min(d,c)다. I의 추가 구현 비용을 넣거나 계산 중단을 허용하지 않으면 식을 바꾸어야 한다. 이 겹침 모형은 실제 스케줄러·공유 메모리 경쟁·알림 폭주까지 설명하지 않는다.
