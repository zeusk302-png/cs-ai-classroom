소단원 15.1

개인정보와 저작권

공개된 사진을 이름만 적으면 누구나 학습 사이트에 다시 올려도 될까?

준비 개념과 학습 목표

준비 개념

  • 자료의 수집과 공유

  • 권한과 목적

  • 출처

학습 목표

  • 필요한 정보와 불필요한 수집을 구별한다.

  • 공개 열람과 재사용 허락을 구별한다.

  • 자료별 권리 조건과 삭제 계획을 기록한다.

어떤 목적으로 누구의 정보를 다루는가

개인정보를 다루는 설계에서는 이름뿐 아니라 활동 기록·접속 정보와 다른 자료를 결합했을 때 개인과 연결될 가능성도 살핀다. 무엇을 모으고 어디로 보내며 누가 접근하고 언제 지울지 흐름을 적는다.

예를 들어 이어 읽을 단원만 저장하려는 목적에 주소·전화번호·사진이 꼭 필요한지 묻는다. 자료를 적게 모으면 불필요한 처리 범위를 줄일 수 있지만 그 자체로 모든 위험이 없어지거나 법적 의무를 충족하는 것은 아니다. 수집·보유·공유·삭제를 함께 검토한다.

출처 표시와 재사용 권한은 다르다

인터넷에서 볼 수 있다는 사실은 복사·수정·재배포의 모든 허락을 뜻하지 않는다. 저작자·권리자·실제 라이선스·허용 범위·표시 조건을 자료별로 확인한다. 원문을 참고하여 자체 설명을 쓰는 일과 그림 전체를 복사해 배포하는 일을 구별한다.

가상의 CC BY 4.0 그림을 수정해 쓸 때는 제공된 저작자 등 표시 정보·원자료 링크·라이선스 링크·변경 안내를 확인한다. 이름 한 줄만 적고 조건 확인을 끝내지 않는다. CC의 개요는 전체 법률문이 아니며 실제 사용에는 해당 조건과 별도 권리도 확인한다.

서로 다른 권리가 겹칠 수 있다

그림의 저작권 허락이 있어도 사진 속 사람의 개인정보나 다른 권리 문제가 자동 해결되는 것은 아니다. 교육 목적이나 오픈소스 프로젝트라는 이름만으로 제3자 자료의 권리가 바뀌지 않는다.

소스와 자체 저작물의 프로젝트 라이선스와 외부 자료의 라이선스를 구별한다. 자료별 출처와 조건을 보존하고 확인되지 않은 자료는 배포 계획에서 보류한다. 실제 학생 정보나 사진을 실습에 모으지 않고 가상 자료로 흐름을 연습한다.

중간 과정을 따라가는 예제

가상 학습 기록의 후보 필드는 별명·현재 단원·주소·전화번호·사진·생년월일의 6개다. 목적을 별명과 이어 읽을 단원 저장으로 제한하고 120명에게 2개만 저장한다면 필드 값 개수는 어떻게 바뀌는가?

  1. 전체 6개를 저장하면 120×6=720개의 필드 값이다.

  2. 2개만 저장하면 120×2=240개다. 차이는 480개다.

  3. 개수 감소는 처리 범위의 가상 산술이다. 별명과 단원도 결합 상황에 따라 개인과 관련될 수 있어 접근·보유·삭제 검토는 남는다.

720개에서 240개로 줄어 480개를 덜 저장한다. 위험이 정확히 2/3 감소했다고 측정한 것은 아니다.

접근성과 디지털 격차

페이지 주소가 공개되어 있으면 누구에게나 같은 학습 기회가 생길까?

준비 개념과 학습 목표

준비 개념

  • 웹의 입력과 출력

  • 텍스트와 그림

  • 학습 환경

학습 목표

  • 공개 접속과 실제 사용 가능성을 구별한다.

  • 키보드·대체텍스트·텍스트 자료의 역할을 설명한다.

  • 평균 외 환경별 접근 장벽을 비교한다.

사람과 환경이 다르면 장벽도 다르다

접근성은 장애가 있는 사람도 정보를 인지·이해·탐색·조작할 수 있게 설계하는 일과 연결된다. 시각·청각·운동·인지 조건과 사용하는 보조 기술을 고려한다.

작은 화면·느린 연결·소리를 들을 수 없는 장소 같은 상황에서도 장벽이 생긴다. 인터넷 공개와 무료 제공만으로 장치·언어·대역폭·사용 능력의 차이가 모두 사라지는 것은 아니다. 디지털 격차는 접속 가능 여부 외 실제 이용 조건을 포함해 살핀다.

같은 학습 정보를 다른 경로로 제공한다

의미 있는 그림에는 그 정보와 역할에 맞는 대체텍스트를 제공한다. 키보드만으로 기능에 도달하고 조작할 수 있어야 하며 현재 초점도 알 수 있어야 한다. 음성 설명에는 대응하는 텍스트 자료를 제공한다.

긴 코드를 스크린샷으로만 제시하면 읽기·복사·보조 기술 사용이 어려울 수 있다. 선택 가능한 텍스트와 설명·예상 결과를 함께 제공한다. 장식 그림의 처리와 중요한 도식의 설명은 목적이 다르며 파일 이름을 그대로 붙이는 것으로 의미 설명을 대신하지 않는다.

검사는 초기에 여러 방법으로 한다

접근성 검사는 설계 초기부터 반복한다. 자동 도구는 일부 오류를 찾을 수 있지만 실제 기능과 설명의 의미·키보드 흐름을 모두 판정하지 못한다. 사람의 검토와 다양한 이용 환경의 관찰이 필요하다.

가상 환경별 과업 완료 비율을 비교해 특정 환경의 실패가 평균에 가려지는지 살핀다. 한 번의 검사 통과를 전체 지침 적합성이나 모든 학생의 성공으로 확대하지 않는다. 실제 수행하지 않은 사용자·보조 기술 검사는 미수행으로 남긴다.

중간 과정을 따라가는 예제

가상 과업에서 키보드 이용 4명 중 2명, 마우스 이용 6명 중 6명이 완료했다. 전체 및 환경별 비율을 구하고 개선 우선 후보를 설명하라.

  1. 전체 완료는 (2+6)/(4+6)=8/10=80%다.

  2. 키보드는 2/4=50%, 마우스는 6/6=100%다. 전체 평균만으로 키보드 장벽을 알아보기 어렵다.

  3. 어떤 제어에 도달하지 못했는지·초점이 보이는지·조작이 가능한지 관찰 계획을 세운다. 이 가상 숫자만으로 실제 원인을 확정하지 않는다.

전체 80%, 키보드 50%, 마우스 100%다. 환경별 원인 관찰을 추가로 계획한다.

기술 선택의 영향

더 많은 기록을 모으는 추천 기능은 언제나 더 좋은 선택일까?

준비 개념과 학습 목표

준비 개념

  • 목적과 요구사항

  • 자료 흐름

학습 목표

  • 편익과 부담이 누구에게 생기는지 구별한다.

  • 대안의 자료·장치·접근 조건을 비교한다.

  • 계획·실제 영향·검증 상태를 구별한다.

성공 기준에는 영향을 받는 사람도 넣는다

기술 선택은 기능 수나 평균 속도 외에 이용자·운영자·자료 제공자에게 다른 편익과 부담을 만들 수 있다. 쉬운 접근·이해 가능한 설명·개인정보 처리·유지 비용 같은 기준을 목적과 연결한다.

예를 들어 공개 학습 자료를 로그인 없이 읽게 하는 선택과 진행 기록을 서버에 저장하는 선택은 서로 다른 필요를 해결한다. 어떤 기능이 왜 필요한지, 그 기능이 없는 대안이 가능한지 비교한다. 많은 기능을 넣었다는 이유만으로 사회적 책임을 다했다고 결론 내리지 않는다.

대안을 공통 조건으로 비교한다

가상 대안 A는 텍스트 자료를 제공하고 진행 기록을 기기 안에 저장한다. B는 같은 본문과 서버 진행 기록·추천을 제공한다. A는 기기 변경 시 기록 이동이 어렵고 B는 외부 전송·접근·삭제 및 운영 처리가 추가된다.

기기 내 저장도 공유 기기에서 다른 사람이 볼 수 있으며 자동으로 안전한 것은 아니다. 서버 기록도 그 존재만으로 나쁘다고 판정하지 않는다. 목적·자료 최소화·이용자 선택·보유/삭제·실패 처리와 실제 환경을 함께 비교한다.

의도와 실제 영향은 다를 수 있다

설계상 이익은 가설이며 실제 효과를 확인하려면 과업·환경·평가 방법을 정한다. 평균 완료 비율 외 연결 환경이나 입력 방식별 실패를 살피고 불필요한 자료 수집을 추가하지 않는 평가 방법을 계획한다.

추가 기능 도입 뒤 문제가 생기면 되돌림·대체 경로·문의와 수정 흐름을 마련한다. 계획한 측정·실제 측정·원인 분석·수정 후 확인을 구별한다. 이 단원은 가상 대안 비교이며 실제 서비스 변경이나 사람 대상 평가를 수행하지 않았다.

중간 과정을 따라가는 예제

가상 대안 A의 자료 전송은 학습자당 2 MB, B는 같은 본문에 추가 자료 3 MB를 요구한다. 학습자 100명이 한 번 이용할 때 총량과 차이를 구하라. B의 추천 효과는 측정되지 않았다.

  1. A는 100×2=200 MB다. B는 100×(2+3)=500 MB다.

  2. 차이는 300 MB이며 B/A=2.5다. MB는 여기서 같은 단위로 제공된 가상 전송량이다.

  3. 추천 이익은 미측정이다. 전송량만으로 종합 우열을 정하지 않고 느린 연결의 접근과 추천 목적·자료 처리 대안을 비교한다.

가상 전송량 200/500 MB, 차이 300 MB다. 추천 효과나 실제 통신 비용을 측정한 결과는 아니다.
