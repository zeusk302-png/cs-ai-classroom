小节 5.1

变量与状态

先写x=y，再写y=x，就能交换两个值吗？

预备知识与学习目标

预备知识

  • 变量名指向当前值。这里仅使用内置int值；x3/y5表示名称x当前的值为3、名称y当前的值为5。
  • 赋值x=y读取此时y指向的值，再改变x的绑定。它不是数学中对称的等式；x==y才是比较是否相等的表达式。
  • 状态表抽象地记录每条语句前后的名称、当前值和下一执行位置。它不是物理地址表，也不表示全部运行时状态。

学习目标

  • 跟踪右侧读取、左侧绑定和语句顺序。
  • 找出错误交换中丢失的初始值，并用临时保存修正。
  • 区分名称、值和对象修改，说明整数模型的限制。

不要用另一套规则理解相同符号

Python的x=x+1先用右侧当前的x计算加法结果，再把名称x绑定到该值。它不是求数学等式x=x+1的解。如果x尚未定义，读取右侧名称时可能失败。首先确认名称的当前值以及绑定发生的时间。

本例中的整数3不是可变的存储盒。执行x=3,y=x后再以x=4重新赋值，不会自动把y变成4。多个名称可以指向同一对象，但重新绑定名称不同于修改对象本身。列表元素修改与别名将在容器数据单元另讲，不能直接推广这个整数案例。

把当前状态传到下一行

本例从上到下顺序执行；一行的后置状态就是下一行的前置状态。从初始x3/y5执行x=y得到x5/y5。接着y=x读取的是当前x5，而非初始x3，所以最后得到x5/y5，未完成交换。

如果稍后还要用初始x，须在覆盖前用另一名称保存。依次逐行执行temp=x、x=y、y=temp，会得到temp3,x5,y3。Python的x,y=y,x是另一种语法，会先求右侧两个值。不能把它读成两个独立赋值x=y;y=x。

观察范围与输入契约

状态表如果只写所需结果名称，就不能据此声称所有副作用都已检查。实际状态还可能包含打开的文件、共享对象和输出。本例假定两个预先确定的内置整数、顺序执行、无外部输入或并发改变，以及无异常的正常运算。

在纸上分别写下读取前后的值，就能发现同一名称被覆盖。最后的print读取最终值，并不会恢复以前的状态。使用有意义的名称和记录复杂表达式的中间值，有助于定位误读，但可读性本身不能保证全部正确性。

逐步推导的例题

跟踪完整代码，判断它是否交换了两个初始值。 

x = 3
y = 5
x = y
y = x
print(x, y)
  1. 用x=3绑定x，再用y=5绑定y。两个赋值后的状态为x3/y5。
  2. x=y的右侧读取当前y5。把x重新绑定到5，状态变为x5/y5；初始x3不再保存在名称x中。
  3. y=x的右侧读取当前x5。y也成为5，状态保持x5/y5。
  4. print(x,y)输出5 5和换行。保存的实际代码也以相同输出结束。

最终为x5/y5，交换失败。错误在于以为第二个赋值会读取初始x3。

用纸笔和正文动手试一试

从独立的初始x3/y5出发，逐行在纸上跟踪temp=x;x=y;y=temp。另从独立初始x3/y5出发，只执行x=x+1后两个值是什么？

查看提示

每次读取右侧时都使用当时的状态。把temp保存的初始值写进表格。

查看解答

先保存temp3，再得到x5/y3，成功交换。另一个递增案例得到x4/y5，y不变。这两个活动程序均未执行，只在纸上跟踪。

常见误解与反例

x=y把两个变量永久连接，所以以后修改x，y也一定改变。

本整数例中重新绑定名称不会形成这种自动连接。x3,y=x后再令x4，y仍为3。修改共享可变对象的元素是另一种契约。

检查理解

原例第一次x=y后，x的值是什么？

查看答案与理由

5。

读取当前y5，再改变x的绑定。

会像数学等式一样，把x=x+1判定为无解吗？

查看答案与理由

不会。

它按照读取当前值、计算和建立新绑定的执行规则工作。

不使用temp的两个赋值能保存初始x吗？

查看答案与理由

一般不能。

最终x/y都是初始y；如果初始x不同，就丢失了那个值。

进一步探索

拓展：只观察内置整数对(a,b)的名称值时，错误的两个赋值构成F(a,b)=(b,b)。(3,5)与(7,5)都映射到(5,5)，所以只凭最终数对不能恢复初始第一值。使用临时保存的交换，在所观察数对上构成S(a,b)=(b,a)，且S(S(a,b))=(a,b)。在整数赋值正常执行的条件下，逐步跟踪顺序赋值即可论证。这不表示包括temp名称的全部状态、共享对象或外部输出也得到相同恢复。

小节 5.2

分支与循环

只按行顺序读一遍代码就够了吗，还是也要找出返回重读的位置？

预备知识与学习目标

预备知识

  • 分支按照条件选择接下来执行的语句块。循环再次检查条件，可以多次执行同一主体。通过缩进找出主体范围。
  • x%2是内置整数x除以2的余数。本单元的x非负，因此偶数余0、奇数余1；0也是偶数。
  • N是内置整数上限，N≥0。假定从x0,total0开始正常顺序执行，只累加0≤x<N范围中的偶数。

学习目标

  • 找出条件检查、分支主体、共同更新和再次检查的顺序。
  • 解释零次执行主体和不包含终值的边界情况。
  • 用累加不变式和进展量分别论证结果与终止。

画出执行路径再阅读

if为真时执行缩进块，为假时跳过。如果有elif，仅当前面条件全为假时才检查下一个条件；一条链只执行第一个真分支。多个独立if分别检查，不能把它们读成相同的链。

while在进入主体前检查条件。为真时执行主体后回到条件，为假时跳到循环外的下一语句。因此，每行从上到下只读一次得到的表格，不是实际循环的状态表。须记录循环次数和每次的当前值。

检查所有路径上的更新

本例在x<N时检查x%2==0。只有偶数加到total，但x=x+1位于if块之外、while块之内，因此奇数时也执行。这一共同更新使奇偶两条路径都前进到下一个x。只改变一个缩进也可能改变其作用。

如果把x更新只放在偶数if中，处理x0后到达1；奇数1不执行分支，也不更新，所以N5时无法继续前进。continue也可能跳过后续更新，break则终止包含该语句的最内层循环。不必执行错误的无限循环，在纸上就能展示状态固定。

结果与终止是两个问题

total保存已处理前缀中的偶数和，是结果的依据。x每次增加1直到N，是终止的依据。须分别检查，不能只主张其中一个。本例N5访问0,1,2,3,4；条件x<5不包含5。

初始N0时，0<0为假，主体执行零次，保留total0/x0。N1只访问0，和也为0，但x1且主体执行一次。相同的最终和不意味着路径或次数相同。这一静态分析依赖固定整数、正常运算和足够资源、无外部改变的契约，并不统一保证实际设备或所有语言的循环行为。

逐步推导的例题

跟踪完整代码，求从0（包含）到N（不包含）的偶数和。 

N = 5
x = 0
total = 0
while x < N:
    if x % 2 == 0:
        total = total + x
    x = x + 1
print(total, x)
  1. 从N5,x0,total0开始。x0时循环条件和偶数检查都为真，加0后得到x1。x1为奇数，保持和0并更新到x2。
  2. x2时加2得到total2/x3；x3时保留和2，再更新到x4。奇数时也执行共同更新。
  3. x4时加4得到total6/x5。下一次5<5为假，不再进入主体。
  4. 循环外的print输出6 5和换行，与保存代码的实际执行相同。主体执行5次，累加的偶数为0,2,4。

和为6，最终x为5。终值5未在主体内访问。

用纸笔和正文动手试一试

在纸上假设只把同一完整代码的N改为0和1。分别求和、最终x和主体次数。再展示N5时把更新移入偶数if，会在哪里失去进展。

查看提示

区分第一次while检查和if之外的共同更新。即使和都是0，访问次数也可能不同。

查看解答

N0为和0/x0/0次，N1为和0/x1/1次。错误的N5更新先使x0→1；之后x1的偶数条件为假，更新也被跳过，所以一直停在x1。活动及无限循环反例均未执行。

常见误解与反例

只要有正确累加和的不变式，循环一定终止。

更新丢失后若停在x1，该前缀的和0仍可一直正确，但循环不终止。结果保持与终止进展需要不同依据。

检查理解

N5例也会加5吗？

查看答案与理由

不会。

x<N排除边界，到x5时终止。

原例在x1时也更新x吗？

查看答案与理由

会。

x=x+1在if之外、while之内，奇数路径同样执行。

N0时是否先执行一次主体再结束？

查看答案与理由

不是；执行零次。

while在第一次主体前检查0<0，为假所以直接跳过。

进一步探索

拓展：完成k次后，设不变式为x=k，且total为0≤j<k中偶数j的和。k0时空和为0。下一步若k为偶数就加k，否则保持和；共同更新令x=k+1，从而保持不变式。对于固定内置整数N≥0和正常运算，检查为真时N-x为正整数，每次减少1直到0。因此经过N次循环终止并得到全部偶数和。N5的路径是该证明的一个实例，不是通过运行几次证明全部输入。若N受外部改变、主体发生异常或跳过更新，就不能原样使用这一论证。

小节 5.3

函数与调用流程

函数调用另一个函数时，返回位置与局部变量应该记录在哪里？

预备知识与学习目标

预备知识

  • def定义函数，不等于立即调用主体。inc(5)调用函数，将实参的对象引用绑定到形参v。
  • return将计算值返回到调用位置。print显示的字符与返回值是不同观察。没有显式return的正常函数结束返回None。
  • 每次调用都跟踪独立的局部名称。这里使用内置整数和正常顺序调用，不使用共享可变对象、global/nonlocal、递归或异常。

学习目标

  • 区分函数定义、调用顺序和return的返回位置。
  • 分开记录使用同一形参名的两次调用的局部状态。
  • 区分局部整数重新绑定与调用者变量或共享对象修改。

调用时才进入主体

def inc(v)的主体不是在创建函数的定义阶段立即执行。名称inc绑定到函数对象，执行inc(n)之类的调用才进入主体。主体缩进之外的调用从其所在位置继续。若在名称尚未绑定的位置调用，可能产生定义顺序和名称解析问题。

调用前先求实参，再绑定到被调用函数的形参名称。Python中该值是对象引用，不保证深拷贝整个对象。本例整数v=v+1把局部v重新绑定到新整数值，不改变调用者的名称x。修改共享可变列表元素则不同。

把局部表与返回位置一起写下

twice(n)等待a=inc(n)的结果。inc的局部v收到n的整数，加1并返回后，结果存入twice的a。之后return inc(a)等待第二次inc结果，再将该值返回给twice的调用者。两次inc虽都使用名称v，却有各自的局部绑定。

纸面调用表记录函数名、当前形参和局部值、下一位置及返回地点。返回到最近一个正在等待的调用位置，是本例的抽象控制流程。不能据此声称测量了特定CPU的真实栈内存布局、地址或ABI约定。

返回值与副作用的契约

inc与twice在主体内不输出，只返回计算值。最后的print(x,y)读取调用者保留的x和twice返回值。在屏幕显示值不等于自动return该值；return之后，也不会在同一次正常调用中继续执行主体的下一语句。

函数契约可以包含允许的输入、返回值、外部修改和失败。这里规定正常路径接收整数n，返回n+2且不修改调用者名称。并非所有函数都有这一契约。递归会再次调用同一函数并产生新的局部状态，但本例不使用递归，也未测试递归深度或限制。

逐步推导的例题

跟踪两次调用inc的完整代码，说明调用流程与最终输出。 

def inc(v):
    v = v + 1
    return v

def twice(n):
    a = inc(n)
    return inc(a)

x = 5
y = twice(x)
print(x, y)
  1. 两个def把inc/twice绑定到函数。保存x5后调用twice(x)，twice获得局部n5。y尚在等待计算结果。
  2. twice执行a=inc(n)，第一次inc获得局部v5，再绑定为v6。return6回到twice，得到局部a6；调用者x5不变。
  3. twice执行return inc(a)，第二次inc的局部v6变成v7并返回7。twice也把7返回其调用位置，绑定y7。
  4. 最终x5/y7，print写出5 7和换行，与保存的完整代码实际输出一致。用户定义inc调用两次，twice调用一次。

x保持5，y为7。两次局部v与twice的n/a应分别记录在表中。

用纸笔和正文动手试一试

在纸上跟踪同一代码将初始x改为0的情况。另只删去inc的return v，保留v=v+1主体；原twice(5)的第二次inc会得到什么输入，又有什么问题？

查看提示

第一次返回值成为twice的a。没有显式return的正常结束返回None。

查看解答

原函数中x0使第一次inc返回1、第二次返回2，最终x0/y2。删除return的版本中，第一次inc返回None，使a为None；第二次inc尝试给v=None加1，发生TypeError，无法正常到达最后的print。此变形与活动均未执行。

常见误解与反例

给形参重新赋值，总会改变调用者的变量。

整数inc中重新绑定v不改变调用者x5。但函数收到对象引用，所以修改共享列表内容有时能被调用者观察到。须区分名称重新绑定与对象修改。

检查理解

读取本例inc的def时，v=v+1会立即执行吗？

查看答案与理由

在这个定义中不会。

主体在调用inc时执行。

第二次inc会继续使用第一次调用的局部v吗？

查看答案与理由

它建立另一调用的局部v。

第一次返回值6经过twice的a，作为新调用的实参传入。

主体只print后正常结束，会自动返回所打印的值吗？

查看答案与理由

不会；没有显式返回时为None。

向标准输出发送字符的副作用与调用位置收到的返回值不同。

进一步探索

拓展：在内置整数n及正常运算条件下，inc(n)=n+1。twice先获得a=inc(n)=n+1，再返回inc(a)=a+1=n+2，可以通过组合函数契约证明结果。每次inc通过有限赋值和返回结束；twice仅执行两次这样的有限调用，因此在这些条件下终止。主体不重新绑定调用者x，也不修改整数对象，所以保留x。不能把相同的局部状态或终止结论自动用于修改共享对象、重新绑定全局名称、存在异常或无限循环的函数。
