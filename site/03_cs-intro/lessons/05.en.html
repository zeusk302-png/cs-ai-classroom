Subtopic 5.1

Variables and state

Does x=y followed by y=x exchange the two values?

Preparation and learning goals

Preparation

  • A variable name refers to its current value. Here we use only built-in int values: x3/y5 means that name x currently has value 3 and name y has value 5.
  • Assignment x=y reads the value currently referenced by y and changes the binding of x. It differs from a symmetric mathematical equation; x==y tests equality.
  • A state table records each name and current value, and the next execution position, before and after a statement. It is an abstract record, not a table of physical addresses or all runtime state.

Learning goals

  • Trace reading the right side, binding the left side, and statement order.
  • Find the initial value lost in an incorrect swap and repair it using temporary storage.
  • Distinguish a name, a value, and object mutation, and explain the limits of the integer model.

Read the symbol using the right rules

Python x=x+1 computes a sum from the current x on the right, then binds name x to that value. It does not solve the mathematical equation x=x+1. If x has not been defined, reading the right-side name can fail. First check its current value and when it was bound.

The integer 3 is not a mutable storage box in this example. After x=3 and y=x, rebinding x with x=4 does not automatically make y become 4. Several names can refer to the same object, but rebinding a name differs from changing that object. List item mutation and aliases are covered separately; do not generalize this integer case unchanged.

Pass the current state to the next line

In this sequential example, the state after one line becomes the state before the next. From x3/y5, x=y gives x5/y5. The following y=x reads the current x5, not the initial x3. The final x5/y5 therefore fails to swap the values.

To use the initial x later, preserve it under another name before overwriting x. Executing temp=x, x=y, and y=temp on separate lines gives temp3, x5, y3. Python x,y=y,x is a different syntax that evaluates both right-side values first. Do not read it as equivalent to the independent assignments x=y; y=x.

Choose the observed state and input contract

A table containing only the desired result names cannot establish that every side effect was checked. Actual state can include open files, shared objects, and output. This example assumes two predefined built-in integers, sequential execution, no external input or concurrent change, and normal operations without exceptions.

Writing values before and after each read reveals overwriting under the same name. The final print reads final values; it does not restore earlier states. Meaningful names and recorded intermediate values can help locate a misreading, but readability alone does not guarantee correctness.

A worked example, step by step

Trace whether this complete program exchanges its two initial values. 

x = 3
y = 5
x = y
y = x
print(x, y)
  1. Bind x to 3 and y to 5. After both assignments the state is x3/y5.
  2. The right side of x=y reads the current y5. Rebinding x to 5 gives x5/y5; the initial 3 is no longer bound to name x.
  3. The right side of y=x reads the current x5. Thus y is also 5 and the state remains x5/y5.
  4. print(x,y) writes 5 5 and a newline. The preserved program actually terminated with the same output.

The final x5/y5 is a failed swap. The error is expecting the second assignment to read the original x3.

Try it with paper and the lesson

From an independent initial x3/y5, trace temp=x; x=y; y=temp one line at a time on paper. From a separate initial x3/y5, what are both values after only x=x+1?

Show hint

Read each right side from the state at that moment. Record which initial value remains in temp.

Show solution

Preserve temp3, then obtain x5/y3, a correct swap. The separate increment gives x4/y5; y does not change. Neither activity program was executed; both were traced on paper.

Misconception and counterexample

x=y permanently links the variables, so changing x later always changes y.

Rebinding a name in this integer example does not create that automatic link. After x3 and y=x, setting x4 leaves y3. Mutating an item of a shared mutable object requires a different contract.

Check your understanding

What is x immediately after the first x=y in the original example?

Show answer and reasoning

5.

It reads the current y5 and changes the binding of x.

Do we reject x=x+1 as a mathematical equation with no solution?

Show answer and reasoning

No.

Its execution rule computes from the current value and establishes a new binding.

Do the two assignments without temp preserve the initial x?

Show answer and reasoning

Not in general.

Both final names contain the initial y. If the initial x differs, that value is lost.

Explore further

Extension: When observing only the name values of a pair of built-in integers (a,b), the incorrect two assignments implement F(a,b)=(b,b). Both (3,5) and (7,5) map to (5,5), so the final pair cannot recover the original first value. A swap using temporary storage implements S(a,b)=(b,a) on the observed pair, and S(S(a,b))=(a,b). Follow the sequential assignments under normal integer assignment to justify these results. This does not say that the whole state including temp, shared objects, or external output is restored.

Subtopic 5.2

Branches and loops

Is reading each line once enough, or must we locate the points that execution revisits?

Preparation and learning goals

Preparation

  • A branch chooses the next block according to a condition. A loop checks a condition again and can run the same body repeatedly. Use indentation to identify the body.
  • x%2 is the remainder when built-in integer x is divided by 2. Here x is nonnegative, so the remainder is 0 for even values and 1 for odd values; 0 is even too.
  • N is a built-in integer upper bound with N≥0. Assume normal sequential execution beginning with x0,total0 and summing only even values with 0≤x<N.

Learning goals

  • Locate condition tests, branch bodies, the common update, and retesting.
  • Explain zero body executions and exclusion of the end value.
  • Justify the result and termination separately using an accumulation invariant and progress.

Draw the execution paths

if runs its indented block when true and skips it when false. With elif, the next condition is examined only if all previous conditions are false, and only the first true branch of the chain runs. Several independent if statements are tested separately; do not read them as the same chain.

while checks its condition before entering the body. When true, execution returns to the condition after the body; when false, it advances to the next statement outside the loop. Reading each line once from top to bottom therefore does not produce the state table of the actual loop execution. Record the iteration count and current values at each turn.

Check updates on every path

The example tests x%2==0 while x<N. Only even x is added to total, but x=x+1 is outside the if block and inside the while block, so it also runs for odd x. This common update advances to the next x on both paths. Changing just the indentation can change its role.

If the update is placed only inside the even if, processing x0 advances to 1. At odd 1 neither the branch nor the update runs, so progress stops for N5. continue can also skip an update later in the body, whereas break ends the nearest enclosing loop. A fixed state can be demonstrated on paper without executing the incorrect infinite loop.

The result and termination are different questions

The property that total holds the sum of even values in the processed prefix supports the result. The property that x increases by 1 each time until N supports termination. Check both separately. For N5 the visited values are 0,1,2,3,4; x<5 excludes 5.

If N is initially 0, 0<0 is false, so the body runs zero times and total0/x0 remain. N1 visits only 0, so its sum is also 0, but x1 and one body execution differ. Equal final sums do not imply equal paths or counts. This static reasoning assumes fixed integers, normal operations, adequate resources, and no external change; it does not establish behavior for every device or language.

A worked example, step by step

Trace the complete program that adds even values from 0 inclusive to N exclusive. 

N = 5
x = 0
total = 0
while x < N:
    if x % 2 == 0:
        total = total + x
    x = x + 1
print(total, x)
  1. Start with N5,x0,total0. At x0 both the loop and even conditions are true; add 0 and advance to x1. The odd x1 keeps sum 0 and advances to x2.
  2. At x2 add 2, giving total2/x3. At x3 retain sum 2 and advance to x4. The common update also runs on odd values.
  3. At x4 add 4, giving total6/x5. The next test 5<5 is false, so the body is not entered again.
  4. The print outside the loop writes 6 5 and a newline, matching the actual execution of the preserved program. There are five body executions and the added even values are 0,2,4.

The sum is 6 and final x is 5. The end value 5 is not visited in the body.

Try it with paper and the lesson

On paper, change only N in the same program to 0 and then 1. Find each sum, final x, and body count. For N5, show where progress is lost if the update moves into the even if.

Show hint

Distinguish the initial while test from the common update outside if. Equal sums of 0 can still have different visit counts.

Show solution

N0 gives sum0/x0/zero iterations; N1 gives sum0/x1/one iteration. The incorrect N5 update first advances x0→1, then the false even condition at x1 leaves x unchanged forever. Neither the activities nor the infinite-loop counterexample were executed.

Misconception and counterexample

An invariant stating the correct accumulated sum guarantees that the loop terminates.

When the update is lost at x1, the prefix sum 0 can remain correct forever without termination. Preserving a result and making progress toward termination require separate evidence.

Check your understanding

Does the N5 example add 5 too?

Show answer and reasoning

No.

x<N excludes the boundary and execution stops at x5.

Does the original example update x at x1?

Show answer and reasoning

Yes.

x=x+1 is outside if but inside while, so it also runs on the odd path.

For N0, does the body run once before stopping?

Show answer and reasoning

No; zero times.

while tests 0<0 before the first body execution and skips it immediately because the test is false.

Explore further

Extension: After k completed iterations, let the invariant be x=k and total equal to the sum of even j with 0≤j<k. At k0 the empty sum is 0. On the next iteration, add k if even and retain the sum otherwise; the common update makes x=k+1, preserving the invariant. For fixed built-in integer N≥0 and normal operations, N-x is a positive integer whenever the test is true and decreases by 1 each iteration until 0. The loop therefore terminates after N iterations with the full even sum. The N5 trace is one instance of this proof, not a proof of all inputs from a few runs. External changes to N, body exceptions, or skipped updates invalidate the unchanged argument.

Subtopic 5.3

Functions and call flow

When a function calls another, where do we record local variables and the return position?

Preparation and learning goals

Preparation

  • def defines a function rather than immediately calling its body. inc(5) calls it and binds the argument’s object reference to parameter v.
  • return supplies a computed value to the calling position. Characters shown by print and the return value are different observations. A normal function exit without an explicit return yields None.
  • Track separate local names for each call. Here calls are normal and sequential, with built-in integers; there are no shared mutable objects, global/nonlocal declarations, recursion, or exceptions.

Learning goals

  • Distinguish definition, call order, and the position resumed by return.
  • Separate the local states of two calls with the same parameter name.
  • Distinguish rebinding an integer local from changing a caller variable or shared object.

Enter the body when called

The body of def inc(v) does not immediately execute at the definition step that creates the function. Name inc is bound to a function object; calling it as inc(n) enters its body. A call outside the body’s indentation proceeds at its own position. Calling before the function name has been bound can cause definition-order and name-resolution problems.

Arguments are evaluated before the call and bound to parameter names in the called function. In Python these values are object references, not guaranteed deep copies of whole objects. The example v=v+1 rebinds local v to a new integer value without changing the caller’s name x. Mutating an item in a shared mutable list is a different operation.

Record locals and the return position together

twice(n) waits for the result of a=inc(n). The local v in inc receives n’s integer and returns one more; that result is stored as a in twice. Next, return inc(a) waits for a second inc result and returns it to the caller of twice. Each inc call has a separate local binding even though both use the name v.

In a paper call table, record the function name, current parameter and local values, next position, and place to resume. Returning to the most recently waiting call position is the abstract control flow of this example. Such a table does not measure a particular CPU’s actual stack layout, addresses, or ABI conventions.

Contracts for returns and side effects

Neither inc nor twice prints inside its body; both return computed values. The final print(x,y) reads the caller’s unchanged x and the value returned by twice. Displaying a value does not automatically return it, and normal execution of that call does not continue to the following body statement after return.

A function contract can specify permitted inputs, return values, external changes, and failures. Here the normal path takes integer n and returns n+2 without changing the caller’s name. Not every function has that contract. Recursion calls the same function again with new local state, but this example is not recursive and no recursion depth or limit was tested.

A worked example, step by step

Trace the call flow and final output of the complete program that calls inc twice. 

def inc(v):
    v = v + 1
    return v

def twice(n):
    a = inc(n)
    return inc(a)

x = 5
y = twice(x)
print(x, y)
  1. The two def statements bind inc and twice to functions. Store x5 and call twice(x), giving twice a local n5. y is still waiting for the result.
  2. At a=inc(n) inside twice, the first inc receives local v5 and rebinds it to v6. Returning 6 makes the local a in twice equal to 6. The caller’s x5 remains unchanged.
  3. At return inc(a), the second inc receives local v6, rebinds it to v7, and returns 7. twice returns that same 7 to its calling position, binding y7.
  4. The final state is x5/y7; print writes 5 7 and a newline, matching the actual preserved program. The user-defined inc is called twice and twice once.

x remains 5 and y is 7. Track the two local v bindings and twice’s n/a in separate tables.

Try it with paper and the lesson

On paper, change initial x to 0 in the same code. Separately, remove only return v from inc while retaining v=v+1. For the original twice(5), what does the second inc receive, and what fails?

Show hint

The first call’s return becomes a in twice. Normal termination without an explicit return yields None.

Show solution

With the original functions and x0, the first inc returns 1 and the second 2, giving final x0/y2. Without return, the first inc returns None, so a is None. The second inc then tries adding 1 to v=None, causing TypeError; normal execution does not reach the final print. Neither this variant nor the activity was executed.

Misconception and counterexample

Reassigning a parameter always changes the caller’s variable.

Rebinding v in integer inc leaves the caller’s x5 unchanged. However, the function receives an object reference, so mutating a shared list can be visible to its caller. Distinguish rebinding a name from mutating an object.

Check your understanding

Does v=v+1 run immediately when this def inc is evaluated?

Show answer and reasoning

Not in this definition.

The body executes when inc is called.

Does the second inc continue using the first call’s local v?

Show answer and reasoning

It creates a local v for a separate call.

The first return value 6 passes through a in twice into a new call argument.

If a body only prints and exits normally, is the printed value automatically returned?

Show answer and reasoning

No; without an explicit return it yields None.

Sending characters to standard output is a side effect distinct from a value returned to the caller.

Explore further

Extension: For built-in integer n and normal operations, inc(n)=n+1. twice first receives a=inc(n)=n+1, then returns inc(a)=a+1=n+2. Composing the function contracts proves the result. Each inc ends after finite assignment and return, and twice makes only two such finite calls, establishing termination under these conditions. The function bodies do not rebind the caller’s x or mutate integer objects, so x is preserved. Do not automatically extend these conclusions about local states and termination to functions with shared-object mutation, global rebinding, exceptions, or infinite loops.
