Subtopic 4.1

Programs and processes

Why can two copies of the same calculator show different values?

Preparation and learning goals

Preparation

  • A program represents instructions and the data they need. A process is one running instance of that program, with state that changes as execution proceeds.
  • PC is the next instruction position; x is the private integer variable in this unit’s imaginary process. x←x+1 reads the current value and assigns the new one.
  • Scheduling chooses which ready execution gets to use the CPU. Changing saved execution state to resume another process is a context switch; distinguish that mechanism from the selection policy.

Learning goals

  • Distinguish one program from the states of several processes.
  • Trace alternating execution on one CPU using each process’s PC and variable.
  • Explain ready/running/blocked and the limits of the CPU sharing model.

Stored instructions and an execution in progress

Being able to read a program’s instructions does not mean the program is running. The operating system prepares the state and resources needed for execution and manages it. Process state includes an address space, registers and the next instruction position, and input/output information. Opening or copying an executable file is not itself executing its instructions.

One program can give rise to two processes. Even when their code has the same meaning, their inputs, current variables, and positions can differ. Real systems may share read-only code or explicitly shared memory, so this does not require a separate physical copy of every byte. Here we assume that mutable private variables are independent and there are no shared data or threads.

Complete rules for alternating on one CPU

Our own program I has row 0 INC x, row 1 INC x, and row 2 HALT. A starts with x=0, B with x=10, and both with PC=0. INC increases its own x and PC by 1. HALT also increases PC by 1, changes the state to terminated, and executes no further instruction. Values are unbounded mathematical integers. Actual machine instructions, addresses, and overflow are outside the model.

One CPU executes ready A/B alternately, one instruction at a time, starting with A. Each instruction takes one virtual time unit; context switching and creation cost 0, and there are no external inputs or I/O waits. Their lifetimes overlap, so they are concurrent, but only one instruction executes at an instant in this model. This is not a claim about actual multicore parallelism or any OS’s default scheduling.

Waiting is also an execution state

running means executing an instruction on the CPU; ready means able to execute but not yet selected. blocked means waiting for an event and not currently ready to execute. In a simple I/O model, running issues a request and becomes blocked; completion makes it ready, and the scheduler must select it before it becomes running again. Completion does not imply immediate CPU allocation.

A process ID identifies an execution within a system; it is not a program name. ID reuse after termination, permissions, and resource reclamation depend on system rules. Separate address spaces alone do not resolve shared-file conflicts or isolate every failure. Operating systems and concurrency courses examine exactly which states are shared and which guarantees are needed.

A worked example, step by step

A(x=0) and B(x=10) execute I alternately under the defined rules. Find their states after each instruction and the total virtual time.

  1. At time 0→1, A executes row 0: A=(PC=1,x=1), B=(PC=0,x=10). At time 1→2, B executes row 0 and becomes B=(PC=1,x=11).
  2. At time 2→3, A executes row 1 and becomes A=(PC=2,x=2). At time 3→4, B executes row 1 and becomes B=(PC=2,x=12).
  3. At time 4→5, A executes HALT and becomes A=(PC=3,x=2,terminated). B remains ready, with x=12/PC=2.
  4. At time 5→6, B executes HALT and becomes B=(PC=3,x=12,terminated). Neither reads I[3] after termination. Each executes 3 instructions,6 altogether.

A finishes with 2, B with 12, in 6 virtual time units. The same instruction table can accompany different private state. These are not actual CPU seconds or an execution log.

Try it with paper and the lesson

Under the same rules, change both initial x values to 5. What are their final values? Does B’s x also become 6 after A’s first INC? Separately, may the scheduler treat B as ready while it is blocked waiting for unfinished I/O?

Show hint

INC acts only on the selected process’s private variable. Separate the definitions of blocked and ready.

Show solution

Both execute INC twice and finish with 7. Immediately after A’s first INC, A6/B5; B does not change automatically. In this simple model, blocked B is not ready before the completion event, so it must not be selected as though it were ready.

Misconception and counterexample

Running the same program always gives identical variables and instruction positions.

The example uses the same I but initial values 0/10 and alternating progress produce distinct states. Explicit shared memory can make some state change together; specify private and shared state first.

Check your understanding

Is a ready process currently using the CPU?

Show answer and reasoning

No.

The state executing an instruction now is running.

Does I/O completion changing blocked to ready necessarily make it running immediately?

Show answer and reasoning

No.

Moving from ready to running requires the scheduler to select it.

Does the example’s total time 6 reveal the speed of an actual PC?

Show answer and reasoning

No.

Instruction cost 1/switch cost 0/no I/O are model assumptions; actual clocks and costs were not measured.

Explore further

Extension: establish a frame property for INC, which changes only a private variable. An A step preserves B’s x/PC; a B step preserves A’s x/PC. Induction on step count proves that, after exactly k INC instructions in a process, x=initial value+k. Thus changing the interleaving does not change final variable values when there is no shared state, I/O, or exception and every instruction eventually executes. A policy that never selects one process, without fairness, does not guarantee that process’s termination.

Subtopic 4.2

Files, permissions, and paths

Can you open a file you may read if you cannot pass through the route to it?

Preparation and learning goals

Preparation

  • File contents are a sequence of bytes; a path is a sequence of names used to locate them. The name notes.txt in two directories can designate different objects.
  • This unit uses an imaginary tree with Unix separator / and root /. Distinguish a relative path beginning at the current directory from an absolute path beginning at /. Do not apply Windows drive/path or ACL rules unchanged.
  • For a file, r/w/x mean read/write/execute. For a directory they mean reading the name listing/changing name entries/searching and traversing. The limited model excludes links, mounts, ACLs, privileges, sticky bits, read-only filesystems, and concurrent changes.

Learning goals

  • Follow the current directory and path components to locate an object.
  • Check file permissions together with search permissions on directories along the route.
  • Distinguish content writes, name removal, and additional constraints in real filesystems.

Locating an object by following names

A directory contains entries associating names with files or other directories. The absolute path /work/notes.txt finds work in the root and notes.txt inside it. If the current directory is /work/reports, ../notes.txt goes through parent /work to the same object. A dot means the current directory and two dots the parent. The root’s parent is the root in this model.

Each name component must exist, and an object traversed as a directory must be a directory. Search permission is also needed on the preceding directories. Real symbolic links and mounts can change resolution, so deleting a/.. from a string is not a general rule for verifying actual paths or their security. We use only a paper tree whose intermediate entries are followed.

Permissions belong to the route as well as the target

Basic permissions have owner/group/other sets. If the current user is the owner, select the owner set; otherwise, if a member of the file’s group, select group; otherwise select other. Do not add permissions from another set when the applicable set is insufficient. Actual user credentials and additional ACL or privilege rules are outside this limited model.

Directory x permits searching or traversing a known name, while r permits listing entry names. A directory with x but no r can permit access using a known filename if all other conditions hold, but not listing the directory. File r is insufficient to open that file through a new path if a directory along the route lacks x.

Changing contents and changing names are different requests

File w permits writing its contents. Creating or removing a name changes the parent directory’s entries, so the basic model checks parent w and x. Lack of file write permission alone does not imply that its name cannot be removed. Real systems add sticky bits, file flags, read-only mounts, errors, and other constraints.

Removing one name can leave another hard link or an already-open file reference. It does not guarantee immediate disappearance or secure erasure of all bytes. A file descriptor is a process’s reference to an opened file, distinct from a path string. The activity is a paper access judgment, not an exercise changing real account permissions or files.

A worked example, step by step

User Min owns /work/notes.txt. Its permissions are owner r--/group rw-/other ---. Min has x on /, /work, and /work/reports; /work grants r-x. The current directory is /work/reports. Decide whether ../notes.txt may be read, have its contents written, or have its name removed.

  1. Follow .. to /work, then find notes.txt. The given conditions satisfy root/intermediate search permissions and entry existence. The absolute target is /work/notes.txt.
  2. Min is the owner, so select file owner r--. Reading is permitted by r. Do not add group rw-.
  3. Content writing is denied because the selected owner set lacks w. Group w does not supplement the owner set.
  4. Removing the name requires parent /work w+x. Parent r-x lacks w, so removal is denied. This is a separate judgment from file r.

Reading is permitted, content writing denied, and name removal denied. This imaginary result uses the route and the user’s selected permissions together.

Try it with paper and the lesson

Change only Min’s permissions on /work to -wx, keeping the original file permissions. Can Min read notes.txt using its name, list /work, and remove the notes.txt name?

Show hint

Separate search x from listing r, and check the parent for name removal.

Show solution

Reading the known path is possible through directory x and file r. Listing /work is denied without r. Parent w+x permits name removal in the limited model. Content writing remains denied because owner w is absent. Do not actually delete files or change permissions.

Misconception and counterexample

If you know the filename, file r is the only permission needed to read it.

Opening through a new path also requires search x on directories along the route. Without /work x, this new access is denied even if notes.txt still has r. Distinguish later use of an already-open descriptor from a new path lookup.

Check your understanding

Does directory x mean permission to read file contents?

Show answer and reasoning

No.

Directory x is search/traversal; content reading also requires file r and other conditions.

For owner r--/group rw-, may the owner combine both sets to write?

Show answer and reasoning

Not in this basic model.

The owner set is selected first, without adding group permissions.

Does removing one filename immediately securely erase all content?

Show answer and reasoning

There is no such guarantee.

Other names/open references may remain, and space reuse and secure byte erasure are separate guarantees.

Explore further

Extension: separate path existence E, search permission X on every traversed directory, and selected file-read permission R. New reading is allowed exactly when E∧X∧R in this limited model; any false condition denies it. This static argument is insufficient for a real execution where the path can change between a check and a separate opening call. The time between checking and using, opened references, link handling, and extra security policies are topics in systems programming.

Subtopic 4.3

Terminals and system resources

Does an empty screen alone mean a command failed?

Preparation and learning goals

Preparation

  • A terminal is a connection environment for textual input/output; a shell interprets commands. Neither is identical to the OS kernel or every command being run.
  • stdin/stdout/stderr name standard input/output/error channels. Usually connected via descriptors 0/1/2, they can instead lead to terminals, files, pipes, or other targets.
  • Elapsed time runs from start to finish; CPU time accumulates time actually using the CPU. Other resources may work while execution waits. Check units and aggregation scope before interpreting numbers.

Learning goals

  • Distinguish the terminal, shell, and invoked program.
  • Trace standard input/output connections and exit statuses on paper.
  • Interpret CPU/elapsed time and memory indicators under explicit assumptions.

Who does what when you enter text?

A shell interprets command text and executes a specified program or built-in function. Syntax and commands can differ between shells in the same terminal window. The >, >>, | notation here is a paper notation based on basic Unix-style Bash connections, not a request to execute it unchanged in the current Windows PowerShell window.

A command has a name and arguments. Relative paths depend on the execution’s current directory; name lookup and environment variables can also affect its conditions. Seeing input text alone does not prove a particular executable was selected or every condition succeeded. Record the environment, arguments, input data, and actual results together to make executions comparable.

Sending results somewhere other than the screen

Connecting stdout to a file can make normal results invisible on screen. Basic output redirection > first truncates an existing file to length 0 and writes the new output; >> appends. Assume a regular file, successful permissions, noclobber off, no concurrent writer, and no recording failure. Failed connection may also prevent execution; a0-byte result and successful completion are not identical facts.

A | B connects A’s stdout to B’s stdin; | alone does not merge stderr automatically. Exit status 0 is the success indication handled by the shell, but does not guarantee the contents meet the user’s intent. In basic Bash with pipefail off, a pipeline’s status is its final command’s status, so it can be 0 even when an earlier command fails. Check the aggregation policy and program contract.

Read indicator names and scopes first

If elapsed time is 10 seconds, user CPU 2 seconds, and kernel CPU 1 second, accumulated CPU time is 3 seconds. For one execution thread/one CPU with nonoverlapping aggregation intervals, the ratio is 3/10=30%. The other 7 seconds are non-CPU time in this simple model; that number alone cannot identify disk waiting versus ready waiting. Actual multithreaded CPU totals can exceed elapsed time, so do not always assume a100% upper limit.

Memory indicators have different meanings: current usage, maxima, virtual address space, and resident physical pages. Adding two peak resident values can mix peaks from different times and overestimate simultaneous occupancy, or double-count shared pages. File byte count is not memory occupancy. Specify units, time, aggregation targets, and sharing; an unsupported indicator is not zero usage.

A worked example, step by step

Imaginary emit does not use stdin. It sends A plus newline to stdout and check plus newline to stderr, then exits with status 0. out.txt initially contains OLD plus newline. Trace emit > out.txt on paper. Separately interpret imaginary real 10 s/user 2 s/sys 1 s observations.

  1. The successful basic > connection first truncates existing out.txt to length 0, before emit produces output.
  2. emit’s stdout A plus newline goes to out.txt. The final file contains A plus newline; OLD does not remain.
  3. Assume the stderr connection is unchanged. check plus newline goes to the original error channel, here the terminal. Status is the program contract’s0. Absence of normal A on screen does not imply failure.
  4. The separate resource table has CPU 2+1=3 seconds, ratio 3/10=0.3=30%. This interprets a supplied one-thread paper observation, not a measurement of real emit.

File: A+newline. Terminal error channel: check+newline. Status 0. The separate imaginary CPU ratio is 30%; no actual shell or timing-tool output was collected.

Try it with paper and the lesson

Starting independently with OLD+newline, trace emit >> out.txt. Separately, imaginary A sends no stdout and exits 1; B handles the empty stdin and exits 0. What is the status of A | B with pipefail off?

Show hint

Distinguish appending from truncation. The basic pipeline status follows the final command.

Show solution

Appending gives OLD+newline+A+newline, with stderr check still on the terminal. The separate pipeline returns B’s0, but A’s failure 1 remains a fact. Do not interpret it as success of all data processing.

Misconception and counterexample

A program lived for 10 elapsed seconds, so it used the CPU for 10 seconds.

The imaginary table has 3 seconds of CPU time and 7 seconds of non-CPU time. Ready waiting and I/O waiting are possible; identifying the cause needs more state tracing. Check CPU aggregation scope in multithreaded cases.

Check your understanding

Does A | B always send A’s stderr to B too?

Show answer and reasoning

No.

Basic | connects stdout; merging stderr needs a separate connection.

Does status 0 guarantee the written data meet every user requirement?

Show answer and reasoning

Not by itself.

It is the program’s reported success; content, quality, and preservation need their own contracts and checks.

In a one-thread table, real 8 s/user 2 s/sys 2 s gives what CPU ratio?

Show answer and reasoning

50%.

CPU total 4 seconds divided by elapsed 8 seconds is 0.5. Do not automatically apply this to multiple threads or other aggregation scopes.

Explore further

Extension: count only independent physical pages for two processes, with no shared pages. Assume that at every time A≤8 MiB and B≤8 MiB. Suppose resident values at t1 are (A=8 MiB, B=2 MiB), at t2 are (A=2 MiB, B=8 MiB), and their sum at every other time is at most 10 MiB. Each individual maximum is 8 MiB, attained at t1 or t2, so the sum of individual maxima is 16 MiB; the simultaneous maximum sum is 10 MiB. Even without shared pages, those maxima differ. The pointwise individual bounds also make 16 MiB an upper bound on the sum. Including actual shared pages, page units, additional processes, and measurement intervals requires further aggregation definitions.
