小節 5.1

変数と状態

x=yの後にy=xと書けば、二つの値は交換されるだろう？

準備する概念と学習目標

準備する概念

  • 変数名は現在の値を参照する。ここでは組み込みintだけを扱い、x3/y5は名前xの現在値3、名前yの現在値5を表す。
  • 代入x=yは、その時点でyが参照する値を読み、xの束縛を変える。数学の対称な等式とは違い、x==yは等しいかを比較する式だ。
  • 状態表は各文の前後で名前と現在値、次の実行位置を記す抽象的な記録だ。物理アドレスや実行時の全状態を表す表ではない。

学習目標

  • 右辺の読み取り、左辺の束縛、文の順序を追跡する。
  • 誤った交換で失う初期値を見つけ、一時保存で修正する。
  • 名前、値、オブジェクトの変更を区別し、整数モデルの限界を説明する。

同じ記号を別の規則で読まない

Pythonのx=x+1は右側の現在のxから加算値を計算し、名前xをその値に束縛する。数学の等式x=x+1の解を求める操作ではない。xがまだ定義されていなければ、右側の名前を読む時点で失敗する場合がある。まず現在値と束縛された時点を確認する。

整数3は、この例では書き換え可能な箱ではない。x=3,y=xの後でx=4と再代入しても、yが自動で4になるわけではない。同じオブジェクトを参照する名前が複数あっても、名前の再束縛はオブジェクト自体の変更とは違う。リスト要素の変更と別名参照はコレクション単元で扱い、この整数例をそのまま一般化しない。

現在の状態を次の行へ渡す

上から下へ順次実行するこの例では、一行の事後状態が次の行の事前状態になる。初期x3/y5でx=yを実行するとx5/y5だ。続くy=xは初期x3ではなく現在のx5を読む。最終x5/y5となり、交換できない。

初期xを後で使うには、上書き前に別の名前へ保存する。temp=x、x=y、y=tempを別々の行で実行するとtemp3,x5,y3になる。Pythonのx,y=y,xは、右辺の二値を先に評価する別の構文だ。独立した二代入x=y;y=xと同じと読んではいけない。

観察する状態と入力契約

結果として欲しい名前だけの表から、全ての副作用を確認したとは主張できない。実際の状態には開いたファイル、共有オブジェクト、出力なども含まれ得る。この例は決めた二つの組み込み整数、順次実行、外部入力や同時変更の不在、例外のない正常な演算を仮定する。

読み取り前後の値を紙に分けて書けば、同じ名前の上書きを追える。最後のprintは最終値を読み、以前の状態を復元しない。意味の分かる名前と中間値の記録は誤読の場所を探す助けになるが、読みやすさだけで全ての正しさが保証されるわけではない。

途中の過程をたどる例題

全コードが初期の二値を交換するか追跡しよう。 

x = 3
y = 5
x = y
y = x
print(x, y)
  1. x=3でxを、y=5でyを束縛する。二代入後の状態はx3/y5だ。
  2. x=yの右辺は現在のy5を読む。xを5へ再束縛し、状態はx5/y5となる。初期x3は名前xに残らない。
  3. y=xの右辺は現在のx5を読む。yも5となり、x5/y5を維持する。
  4. print(x,y)は5 5と改行を出力する。保存した実コードも同じ出力で終了した。

最終x5/y5で交換は失敗する。二代入目で初期x3を読むと思った点が誤りだ。

紙と本文で試してみよう

独立した初期x3/y5からtemp=x;x=y;y=tempを一行ずつ紙上で追跡しよう。別の初期x3/y5でx=x+1だけを実行すると二値は？

ヒントを見る

右辺はその時点の状態で読む。tempに残る初期値を表に記す。

解答を見る

temp3を保存し、x5/y3へ正しく交換する。別の増加はx4/y5で、yは変わらない。両活動コードは実行せず紙上で追跡した。

よくある誤解と反例

x=yは二変数を永久につなぐので、後でxを変えるとyも変わる。

この整数例の名前の再束縛は、そのような自動的な接続ではない。x3,y=xの後でx4としてもy3を維持する。共有された可変オブジェクトの要素変更は別の契約だ。

理解を確かめる

元の例の最初のx=y直後、xの値は？

答えと理由を見る

5。

現在のy5を読み、xの束縛を変える。

x=x+1を数学の等式として解なしと判定する？

答えと理由を見る

そうは判定しない。

現在値から計算し、新たに束縛する実行規則だ。

tempのない二代入は初期xを保存する？

答えと理由を見る

一般には保存しない。

最終x/yは両方とも初期yだ。初期xが異なればその値を失う。

もう一歩先へ

発展：組み込み整数対(a,b)の名前の値だけを観察すると、誤った二代入はF(a,b)=(b,b)になる。(3,5)と(7,5)は共に(5,5)へ移るため、最終対だけから初期の第一値を復元できない。一時保存による交換は観察する対についてS(a,b)=(b,a)で、S(S(a,b))=(a,b)だ。整数代入の正常実行という条件で順次代入を追って論証する。tempを含む全状態や共有オブジェクト、外部出力まで復元されるという意味ではない。

小節 5.2

分岐と反復

コードを行順に一度読むだけで十分か、それとも戻る位置も探すべきだろう？

準備する概念と学習目標

準備する概念

  • 分岐は条件に応じて次に実行するまとまりを選ぶ。反復は条件を再検査し、同じ本文を複数回実行できる。インデントで本文の範囲を見つける。
  • x%2は組み込み整数xを2で割った余りだ。この単元のxは非負で、偶数なら0、奇数なら1となる。0も偶数だ。
  • Nは組み込み整数N≥0の上限だ。x0,total0から始め、0≤x<Nの値のうち偶数だけを足す正常な順次実行を仮定する。

学習目標

  • 条件検査、分岐本文、共通更新、再検査の順序を見つける。
  • 本文0回と終端除外の境界事例を説明する。
  • 累積の不変条件と進行量で結果と終了を別々に論証する。

実行経路を描いて読む

ifは真ならインデントされたまとまりを実行し、偽なら飛ばす。elifがあれば前の条件が全て偽の場合だけ次の条件を調べ、一つの連鎖で最初の真の分岐だけを実行する。複数の独立ifはそれぞれ調べるので、連鎖と同じに読まない。

whileは本文へ入る前に条件を検査する。真なら本文後に条件へ戻り、偽なら反復外の次の文へ進む。各行を上から下へ一度読んだ結果は、実際の反復実行の状態表ではない。回数と各回の現在値を記録する。

全ての経路の更新を確認する

例ではx<Nならx%2==0を調べる。偶数だけtotalへ足すが、x=x+1はifの外かつwhileの内にあるため、奇数でも実行する。この共通更新が偶数・奇数両経路を次のxへ進める。インデント一つの変更で役割も変わり得る。

もし更新を偶数ifの中だけへ置くと、x0を処理して1へ進み、奇数1では分岐も更新も実行しないためN5で進行が止まる。continueも後の更新を飛ばし得る一方、breakは最も内側の反復を終了する。誤った無限反復を実行せずとも、状態の固定を紙上で示せる。

期待する結果と終了は別の問い

処理済み接頭部分の偶数合計をtotalが持つ性質は結果の根拠だ。xが毎回1増えてNに達する性質は終了の根拠だ。片方だけを主張せず、別々に検査する。N5の訪問値は0,1,2,3,4で、x<5は5を含まない。

最初からN0なら0<0は偽で本文0回、total0/x0だ。N1も0だけを訪問するため合計0だが、x1で本文1回になる。同じ最終合計でも経路や回数は同じではない。この静的分析は固定整数、正常な演算と十分な資源、外部変更なしの契約で成り立ち、実機や全言語の反復を一括保証しない。

途中の過程をたどる例題

0以上N未満の偶数を加える全コードを追跡しよう。 

N = 5
x = 0
total = 0
while x < N:
    if x % 2 == 0:
        total = total + x
    x = x + 1
print(total, x)
  1. N5,x0,total0から始める。x0では条件も偶数検査も真なので0を足してx1となる。奇数x1では合計0を維持してx2へ進む。
  2. x2で2を足してtotal2/x3となる。x3では合計2を維持してx4へ進む。奇数でも共通更新を行う。
  3. x4で4を足してtotal6/x5となる。次の5<5は偽なので本文へ再び入らない。
  4. 反復外のprintが6 5と改行を出力し、保存コードの実際の実行結果とも一致した。本文は5回で、加えた偶数は0,2,4だ。

合計6、最終x5だ。終端値5を本文で訪問しない。

紙と本文で試してみよう

同じコードのNだけを0と1へ変えると紙上で仮定しよう。合計、最終x、本文回数を求め、N5で更新を偶数ifの中へ移すとどこで進行を失うか示そう。

ヒントを見る

最初のwhile検査とif外の共通更新を区別する。合計0でも訪問数は異なり得る。

解答を見る

N0は合計0/x0/0回、N1は合計0/x1/1回だ。誤ったN5更新は最初にx0→1となり、x1で偶数条件が偽になって更新もなく、x1のままになる。活動と無限反復の反例は実行していない。

よくある誤解と反例

累積合計の正しい不変条件があれば反復は必ず終了する。

更新を失ってx1に留まると、その接頭部分の合計0は正しいままでも終了しない。結果の保存と終了への進行は別の根拠だ。

理解を確かめる

N5例で5も足す？

答えと理由を見る

足さない。

x<Nは境界を除外し、x5で終了する。

x1でも元の例のx更新は起こる？

答えと理由を見る

起こる。

x=x+1はif外、while内なので奇数経路でも実行する。

N0なら本文を一回実行してから終わる？

答えと理由を見る

違う。本文0回だ。

whileは最初の本文前に0<0を調べ、偽なので直ちに飛ばす。

もう一歩先へ

発展：k回完了後にx=kで、totalは0≤j<kの偶数jの合計という不変条件を置こう。k0で空の合計は0だ。次のkが偶数ならkを足し、奇数なら維持する。共通更新でx=k+1になり不変条件を保つ。組み込み整数N≥0、正常な演算、固定Nの下で、検査が真ならN-xは正の整数で毎回1減り0になる。したがってN回で終了し、全偶数合計が得られる。N5の経路は証明の一例であって、何回かの実行から全入力を証明したわけではない。外部でNが変わったり、本文の例外や更新省略があれば同じ論証をそのまま使えない。

小節 5.3

関数と呼び出しの流れ

関数が別の関数を呼ぶとき、戻る位置とローカル変数をどこに記録するだろう？

準備する概念と学習目標

準備する概念

  • defは関数を定義し、直ちに本文を呼び出すこととは違う。inc(5)は関数を呼び、引数のオブジェクト参照を仮引数vへ束縛する。
  • returnは計算値を呼び出し位置へ返す。printで表示する文字と戻り値は別の観察だ。明示的なreturnなしの正常終了はNoneを返す。
  • 呼び出しごとに別のローカル名を追跡する。ここでは組み込み整数の正常な順次呼び出しで、共有可変オブジェクト、global/nonlocal、再帰、例外を使わない。

学習目標

  • 定義、呼び出し順、returnの復帰位置を区別する。
  • 同じ仮引数名を使う二呼び出しのローカル状態を分離する。
  • 整数のローカル再束縛と呼び出し側変数や共有オブジェクトの変更を区別する。

呼び出したとき本文へ入る

def inc(v)の本文は、関数を作る定義段階ですぐ実行されるわけではない。名前incが関数オブジェクトに結ばれ、inc(n)などの呼び出しで本文へ入る。本文のインデント外の呼び出しはその位置で進む。名前がまだ束縛されていない位置で呼ぶと、定義順と名前解決の問題が起こり得る。

引数は呼び出し前に評価され、呼び出された関数の仮引数名へ束縛される。Pythonでその値はオブジェクト参照であり、全オブジェクトの深いコピーを保証しない。整数例のv=v+1はローカルvを新たな整数値へ再束縛し、呼び出し側の名前xを変えない。共有可変リストの要素変更は別の操作だ。

ローカル表と戻る場所を一緒に書く

twice(n)はa=inc(n)の結果を待つ。incのローカルvがnの整数を受け取り1増やして返すと、twiceのaへ保存する。次のreturn inc(a)は二回目のincの結果を待ち、その値をtwiceの呼び出し側へ返す。各incは同じ名前vでも別のローカル束縛を持つ。

紙の呼び出し表には関数名、現在の仮引数・ローカル値、次の位置、復帰先を書く。返却後に直近で待つ呼び出し位置へ進むのは、この例の抽象的な制御の流れだ。この表から特定CPUの実スタック配置、アドレス、ABI規約を測定したとは主張しない。

戻り値と副作用の契約

incとtwiceは本文で表示せず計算値だけを返す。最後のprint(x,y)は呼び出し側が保持したxとtwiceの戻り値を読む。値を表示しても自動でreturnしたわけではなく、return後に同じ正常呼び出しの次の本文文へ進むわけでもない。

関数の契約は許す入力、戻り値、外部変更、失敗を含み得る。ここでは整数nを受け取りn+2を返し、呼び出し側の名前を変えない正常経路を定める。全関数がこの契約を持つわけではない。再帰は同じ関数を再び呼んで新しいローカル状態を持つ構造だが、この例は再帰を使わず、深さや限界も試験していない。

途中の過程をたどる例題

incを二回呼ぶ全コードの呼び出しの流れと最終出力を追跡しよう。 

def inc(v):
    v = v + 1
    return v

def twice(n):
    a = inc(n)
    return inc(a)

x = 5
y = twice(x)
print(x, y)
  1. 二つのdefがinc/twiceを関数へ束縛する。x5を保存してtwice(x)を呼ぶとtwiceのローカルn5になる。yはまだ結果を待っている。
  2. twiceのa=inc(n)で最初のincがローカルv5を受け取り、v6へ再束縛する。return6がtwiceへ戻りローカルa6となる。呼び出し側x5はそのままだ。
  3. return inc(a)で二回目のincのローカルv6がv7になり7を返す。twiceも7を自分の呼び出し位置へ返し、y7を束縛する。
  4. 最終x5/y7で、printは5 7と改行を書く。保存全コードの実出力も同じだった。ユーザー定義incは二回、twiceは一回呼ばれた。

xは5を維持し、yは7だ。二回のローカルvとtwiceのn/aを別々の表で追跡する。

紙と本文で試してみよう

同じコードの初期xを0へ変えた場合を紙上で追跡しよう。別にincのreturn vだけを消し、v=v+1本文を残すと、元のtwice(5)の二回目のincは何を受け取り、何が問題になる？

ヒントを見る

最初の戻り値がtwiceのaになる。明示returnなしの正常終了はNoneだ。

解答を見る

元の関数でx0なら最初のinc1、二回目inc2で、最終x0/y2だ。returnなしの変形では最初のincがNoneを返してaNoneとなり、二回目のincでvNoneに1を足せずTypeErrorになる。正常な最終printまで進まない。この変形と活動は実行していない。

よくある誤解と反例

仮引数へ再代入すると常に呼び出し側変数も変わる。

整数incのv再束縛は呼び出し側x5を維持する。ただしオブジェクト参照を受け取るので、共有リスト内容の変更が呼び出し側に見える場合もある。名前の再束縛とオブジェクト変更を区別する。

理解を確かめる

このincのdefを読むとv=v+1も即座に実行する？

答えと理由を見る

この定義では実行しない。

本文はincを呼ぶとき実行する。

二回目のincは最初のローカルvをそのまま使い続ける？

答えと理由を見る

別呼び出しのローカルvを作る。

最初の戻り値6がtwiceのaを経由して新しい引数として渡る。

本文でprintだけして正常終了すると表示値を自動で返す？

答えと理由を見る

違う。明示returnなしならNoneだ。

標準出力へ文字を送る副作用と呼び出し位置の戻り値を区別する。

もう一歩先へ

発展：組み込み整数nと正常な演算の条件でinc(n)=n+1だ。twiceはまずa=inc(n)=n+1を受け、inc(a)=a+1=n+2を返すため、関数契約の合成で結果を証明できる。各incは有限の代入と返却で終わり、twiceはその有限呼び出し二回だけなので、この条件で終了する。本文は呼び出し側xを再束縛せず整数オブジェクトも変更しないためxを保つ。共有オブジェクト変更、グローバル再束縛、例外、無限反復のある関数へ同じローカル状態や終了の結論を自動適用しない。
