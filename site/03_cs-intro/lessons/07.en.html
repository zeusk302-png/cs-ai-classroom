Subtopic 7.1

Arrays and Linked Structures

If two structures store the same card order, do they take the same path to find the third card?

Preparation and learning goals

Preparation

  • A sequence has an order of values. Valid positions for length n are 0..n−1; an empty sequence has no valid position.
  • Array capacity c and actual length n are nonnegative integers with 0≤n≤c. Spare cells at the end are not yet sequence elements.
  • A linked node contains a value and a reference to the next node. head identifies the first node; None marks the absence of a next node.

Learning goals

  • Distinguish calculating an array position from accessing an element by following links.
  • Trace value moves and reference changes during insertion, and explain the conditions for preserving links.

Logical order and actual location

Here an array is an abstract model storing elements of the same positive size w in contiguous cells. For base address B, valid position i has address B+iw. In our paper address table B=2000,w=4 gives address 2008 for position 2. This is not an observed address from a real device.

A singly linked sequence expresses logical order through next. For u(value 5)→v(value 9)→z(value 2)→None, finding the third element means following next twice from head. Linked order need not match memory-address order.

Insertion into an array moves values toward a spare cell

For A=[5,9,2,spare,spare] with capacity 5 and length 3, inserting 7 before position 1 shifts later values right. Move position 2 to 3 before moving position 1 to 2, to avoid overwriting an uncopied value. The insertion condition 0≤i≤n differs from the element-read condition 0≤i<n.

When capacity is sufficient, n−i existing values move. Inserting at position 0 of an empty sequence requires no moves. With no spare capacity, obtaining and copying new storage and a failure policy add costs; an entire insertion is not just one cell write.

The order of reference changes also matters

To insert new node p(value 7) between u and v, first set p.next=u.next to preserve the old v reference, then set u.next=p. Assume predecessor u and an available new p outside the existing linked sequence are already given. Finding u costs separately.

Reversing the order—setting u.next=p first and then copying that reference into p.next—can create a self-cycle p.next=p. Without another reference, the old v/z chain is also lost. Node allocation, freeing and reference ownership require separate consideration in an actual language; changing paper links does not test that implementation.

A worked example, step by step

For A=[5,9,2,spare,spare],n=3,c=5 and head=u with u5→v9→z2→None, insert new value 7 in the second position and trace whether both representations give the same logical order.

  1. For the array, check insertion position i=1 satisfies 0≤1≤3 and n<c. For the linked sequence assume the existing predecessor u and new p7 are given.
  2. Set A[3]=A[2] to preserve 2, then A[2]=A[1] to move 9. Copy from back to front so the original values are not lost.
  3. Set A[1]=7 and n=4. The first four elements are [5,7,9,2], with two moves of existing values and one new-value write. The final spare cell is not an element.
  4. Set p.next=v and then u.next=p, obtaining u5→p7→v9→z2→None. The old v→z connection and head=u remain unchanged. Both have the same value order.

Both logical results are [5,7,9,2]. The array moves two existing values; the linked representation sets two references when new p and predecessor u are already given.

Try it with paper and the lesson

Calculate the address for reading position 3 in the resulting array with B=2000 and cell size 4. How many next links are followed to that position in the resulting linked sequence? Also write the link change that removes p when predecessor u is given.

Show hint

Positions start at 0, so distinguish links followed from nodes visited. Check where p.next points before removal.

Show solution

The array address is 2000+3·4=2012. The linked sequence follows u→p→v→z: three next links and four visited nodes. Removing p sets u.next=p.next=v, restoring u→v→z. Actual freeing of p’s memory and handling external references are not performed in this paper model.

Misconception and counterexample

The entire insertion operation in a linked sequence always costs a constant amount.

Traversing to the predecessor or obtaining a new node may add costs. A fixed number of reference changes assumes the desired predecessor and an available new node are already given.

Check your understanding

For length 3 and capacity 5, is the spare cell at position 4 the fourth element?

Show answer and reasoning

No.

The only valid logical element positions are 0,1,2.

Is shifting from left to right safe for insertion into the middle of an array?

Show answer and reasoning

Generally no.

Writing A[2]=A[1] first loses the old 2 at A[2], which can make subsequent copying incorrect.

With only head, can a singly linked sequence reach position i with one address formula?

Show answer and reasoning

No.

Follow next i times, checking the valid range and references.

Explore further

Extension: Use the invariant that after k traversals from head the current node is at position k of the original sequence. The base k=0 is head. A correct next points to position k+1, establishing induction; valid i requires exactly i link traversals. For array insertion, each original value at j≥i must reach new position j+1 in the same order. Moving from larger j preserves this correspondence because it does not overwrite smaller positions that have not been read. In the Word-RAM model with unit-cost address calculation and reference reads, array access is Θ(1) and access to linked position i is Θ(i+1). The assumptions include a finite, acyclic sequence of valid nodes and fixed-size elements/words.

Subtopic 7.2

Stacks, Queues and Dictionaries

Why does the last card come out first in some structures, even when cards were inserted in the same order?

Preparation and learning goals

Preparation

  • An interface specifies allowed operations and their results; a representation stores or implements those rules.
  • The top of a stack is the most recently added end; the front of a queue is the end that has waited longest.
  • A dictionary associates one value with each key. The missing-key marker MISSING is a separate symbol, distinct from stored value 0.

Learning goals

  • Trace the different contracts of LIFO, FIFO and lookup by key.
  • Explain failure policies for empty/full cases and the state information needed by a circular queue.

Stacks and queues choose which item to remove

A stack has a LIFO contract: push adds at the end and pop removes and returns that end value. A queue has a FIFO contract: enqueue adds at the back and dequeue removes and returns the front value. Even with the same array, different removal rules give different interfaces.

This unit returns EMPTY and leaves the state unchanged when removal is attempted on an empty structure. With a capacity limit, addition is rejected when full. This is our own failure contract, not a claim that every language library has the same exception or return value.

A dictionary asks by key, not position

put(k,v) adds a missing key or replaces the value of an existing key. get(k) returns its current value, or MISSING when absent. Our contract does not add duplicate entries for the same key as a multimap might.

For D={ki:0,mi:2}, get(ki)=0 identifies an existing entry. After put(ki,3), the number of keys remains 2 and get(ki)=3. No ordering or sorting operation was promised, so the key-lookup interface alone does not establish storage order.

Representing a queue with a circular array

A circular array of positive integer capacity C≥1 has head,tail,count. head is the next removal position and tail the next insertion position. count=0 means empty and count=C means full. Advance an index by (i+1) mod C.

Before addition, if count<C, write to buf[tail], advance tail and increase count by 1. Before removal, if count>0, return buf[head], advance head and decrease count by 1. head=tail is possible both when empty and when full, so this representation also checks count. Stale values in removed cells are not logical queue elements.

A worked example, step by step

Start with independent stack [4,8] (bottom→top), queue [4,8] (front→back), and dictionary {ki:0,mi:2}. Apply stack push6/pop, queue enqueue6/dequeue, and dictionary put(ki,3)/get(ki).

  1. Stack push6 produces [4,8,6]. pop returns the last item 6 and leaves [4,8].
  2. Queue enqueue6 produces [4,8,6]. dequeue returns the first item 4 and leaves [8,6].
  3. Dictionary put(ki,3) replaces the old 0 for ki with 3 without adding a key. get(ki) returns 3.
  4. The results 6/4/3 differ. This does not mean 0 was absent: initial get(ki) returned 0. The three structures started with independent states.

Stack pop returns 6 and leaves [4,8]; queue dequeue returns 4 and leaves [8,6]; dictionary get(ki) returns 3 with two keys.

Try it with paper and the lesson

For an initially empty circular queue with C=3 and head=tail=count=0, trace enqueue A,enqueue B,dequeue,enqueue C,enqueue D,enqueue E,dequeue in order. Record failures, returned values and the final logical queue.

Show hint

Reject addition at count=3 without changing any state. Logical order from head/count matters more than stale values in actual array cells.

Show solution

After adding A, (h,t,c)=(0,1,1); after B, (0,2,2). Removal returns A, giving (1,2,1). After C, (1,0,2); after D, (1,1,3), which is full. E is rejected with no state change. The last removal returns B, giving (2,1,2) and logical queue [C,D]. The earlier head=tail=1 state was full, not empty. This is a paper trace, not execution of queue code.

Misconception and counterexample

The names stack, queue and dictionary each determine one storage implementation and its speed.

Stacks and queues specify removal order; dictionaries specify key-value correspondence. Several representations, including arrays and linked structures, support the same contract. Speed depends on the representation and operation assumptions.

Check your understanding

Which values are removed immediately from stack [4,8] and queue [4,8]?

Show answer and reasoning

Stack 8 and queue 4.

They remove the last and first items respectively.

Does receiving dictionary value 0 mean the key is absent?

Show answer and reasoning

No.

0 is a stored value; absence has the separate MISSING marker.

Does head=tail always mean a circular queue is empty?

Show answer and reasoning

Not in this representation.

count=0 and count=C can both give the same indices.

Explore further

Extension: The circular-queue invariant is 0≤count≤C, 0≤head,tail<C, tail=(head+count) mod C, and the value at logical position j (0≤j<count) resides in buf[(head+j) mod C]. It holds in the initial empty state. Addition when count<C writes a new last value at tail, a cell distinct from existing logical elements, and advances tail/count together, preserving the equation. Removal advances head and decreases count, preserving the remaining order and tail equation. Empty removal and full addition leave the state unchanged and preserve the invariant. This paper proof assumes sequential operations, valid cells and sufficient element storage; it does not guarantee atomicity of a concurrent queue.

Subtopic 7.3

Choosing a Data Structure

Can fast reads, fast insertion and small memory use all be compared by one criterion?

Preparation and learning goals

Preparation

  • Worst-case cost is the largest cost among allowed inputs/states of the same size. Amortized cost considers the total across multiple operations.
  • A unit-cost model assumes elements, references and indices occupy a fixed number of words, with fixed costs for access, comparison and movement.
  • Specify required operations concretely, such as reading a position, inserting at the front, appending or finding a key. Compare the same contracts.

Learning goals

  • Choose a representation according to operations, state and model.
  • Calculate total cost of doubling a dynamic array and distinguish one-operation worst case, amortized cost and probabilistic average.

An operation’s name alone does not decide the choice

Frequent position reads may favor direct array access in a unit-cost model. Front insertion moves n values even in an array with spare space; a linked sequence with known head changes only a fixed number of references using a new node. Include whether a new node is already available and any search cost.

Maintaining tail in a singly linked sequence makes link changes for appending fast, but deleting the last node may require finding its predecessor. Not every linked deletion is O(1). One can design binary-search-style comparisons on a sorted linked sequence, but ignoring the cost of reaching the middle does not justify the array’s O(log n) time.

One expansion differs from the entire total

A dynamic array keeps capacity larger than its usage so each append does not require new storage. Our model starts at capacity 1; when full it doubles capacity, copies all existing elements and writes the new value. Count each element copy and each new-value write as 1.

An append that triggers expansion can cost Θ(n) because it copies n existing elements. Yet the total copies for m appends starting empty form 1+2+4+… . This total analysis does not require assuming each input was chosen randomly. It does not give the same constant amortized result for the value shifts of front or middle insertion.

Key-lookup conditions and the whole system

Expected constant lookup in a hash dictionary requires assumptions about hashing, collisions, load factor and key cost. All keys can fall into one bucket, giving a worst case of n comparisons. Hashing and comparing variable-length strings are not always constant-cost either.

First specify handling of empty input, absence, duplicates and allocation failure, along with storage size, input changes and ordering requirements. This unit uses a paper operation model; it does not measure caches, real allocation, external storage, concurrency or wall-clock time. It therefore does not choose one best representation for every task or establish actual speed for a particular language implementation.

A worked example, step by step

An empty dynamic array starts at capacity 1 and doubles when full. For appending values 1..9 in order, calculate capacity, total copies of existing elements and new-value writes.

  1. Write the first value in a spare cell of capacity 1. Before the second, copy 1 existing element to capacity 2; before the third, copy 2 elements to capacity 4.
  2. The fourth fits in spare space. Before the fifth, copy 4 elements to capacity 8; the sixth through eighth append without copying.
  3. Before the ninth, copy 8 elements to capacity 16. This last append alone costs 8 copies plus 1 new write, totaling 9.
  4. Total copies are 1+2+4+8=15; new writes are 9, giving total 24. Final length is 9 and capacity 16; average item work is 24/9=8/3. This is not observed elapsed seconds or a probabilistic average.

There are 15 existing-element copies and 9 new writes, totaling 24, with final capacity 16. Distinguish the last append’s cost 9 from the amortized bound per operation over the entire sequence.

Try it with paper and the lesson

For the same initial-capacity-1 model, find total copies, writes and final capacity for 6 appends. Also find how many existing values move when inserting at the front of an array with length 4 and one spare cell.

Show hint

Six elements require expansion to capacity 8, copying 1/2/4 existing elements. Front insertion is a different operation from append.

Show solution

Six appends give 7 copies plus 6 writes, totaling 13, with final length 6 and capacity 8. Front insertion into the length-4 array shifts four existing elements right and writes one new value. Spare capacity does not eliminate front or middle shifts.

Misconception and counterexample

Amortized O(1) appending means every append has worst-case O(1) cost and constant actual execution time.

The ninth append had to copy eight existing elements. A linear total across many operations differs from each operation’s worst case and actual seconds. No input-probability assumption was used here.

Check your understanding

Does a singly linked sequence with tail always delete the last node by changing only one reference?

Show answer and reasoning

No.

Finding the predecessor that becomes the new tail may cost separately.

Does amortized analysis of doubling appends require random input?

Show answer and reasoning

Not for this total-cost proof.

It calculates total cost of the allowed append sequence starting empty.

Does a dictionary interface itself guarantee worst-case O(1) key lookup?

Show answer and reasoning

No.

Specify representation, collisions and key-cost conditions separately.

Explore further

Extension: Let capacity after m≥1 appends be 2ʳ. If r=0 then m=1 and copies are 0. If r≥1, immediately before the last expansion 2ʳ⁻¹ elements filled the array, so 2ʳ⁻¹<m≤2ʳ. Copies sum to Σ(j=0..r−1)2ʲ=2ʳ−1<2m; adding m new writes gives total item work <3m. Thus this model gives an amortized item-work bound of 3 per operation for every m, not a constant worst-case bound for the last operation. Final array capacity c after appending satisfies m≤c<2m. This bounds element cells, not peak memory while old and new arrays coexist during expansion, nor bytes including metadata. Obtaining/freeing storage and initializing all cells are excluded from this item count; adding such capacity-proportional costs still gives a linear growth sum. More complex allocation, failures, arbitrary deletion sequences and concurrent models need separate analysis.
