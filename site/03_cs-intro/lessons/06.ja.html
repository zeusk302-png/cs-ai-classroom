小節 6.1

疑似コードとフローチャート

同じ番号が二度現れるカード列で、「見つかった」とはどの位置を意味するだろうか？

準備する概念と学習目標

準備する概念

  • 有限の整数カード列 A の長さを n とし、左から位置 0,1,…,n−1 を付ける。空の列は n=0 で、有効な要素位置がない。
  • 代入は状態を変え、比較は条件を判定する。i←i+1 は現在位置を一つ増やす命令であり、数学の等式の解を求める式ではない。
  • None は見つからなかったことを表す別の目印である。有効な位置 0 と区別し、この単元では比較が正常に終了し、途中でカード列が変わらないと仮定する。

学習目標

  • 入力・許容される出力・停止条件を先に定めてから疑似コードを書く。
  • 順序・条件分岐・繰り返しをフローチャートに対応させ、空の入力を追跡する。
  • 読みやすい文章と、意味が明確な実行規則の違いを説明する。

探索問題の契約から書く

問題を単に「数を探す」と書くだけでは、答えの形が決まらない。存在の有無、任意の一致位置、最も左の一致位置は異なる契約である。ここでは入力 A と目標 t に対し、一致位置があれば最小の位置を、なければ None を返す。同じ値のカードが複数あっても、答えは一つに定まる。

例えば A=[8,3,8], t=8 では、2 は一致位置だが、この契約の正しい出力は 0 である。入力条件も併記する。有限のカード列、正常な整数比較、実行中の変更なしという仮定を外すと、同じ手順についての以下の終了・正当性の議論をそのまま適用できない。

人が読む手順にも意味が必要である

疑似コードは特定のプログラミング言語の文法に縛られず、順序と条件を表す記録である。しかし「適当に探す」のように次の行動が定まらない言葉では不十分である。以下で RETURN は値を結果として返し、手順全体を終了させる。WHILE の本体は条件が真である間、繰り返される。

A[i] を読むには、先に i<n を確認しなければならない。n=0 なら本体を一度も実行せずに None を返す。i=n となる最後の検査の後には A[n] を読まない。字下げはどの命令が繰り返しや条件に属するかを示すため、単なる飾りではない。

FIRST(A,t)
  n ← LENGTH(A)
  i ← 0
  WHILE i < n:
    IF A[i] = t: RETURN i
    i ← i + 1
  RETURN None

フローチャートの戻る矢印を読む

フローチャートは同じ手順を箱と矢印で示す。以下の文字図の問いは条件判定であり、二つの結果の行き先をそれぞれ書いている。RETURN に向かう矢印は次の位置に進まず終了する。繰り返しの矢印は i を増やした後、範囲を再検査する場所へ戻る。

図を描いたというだけで正しくなるわけではない。A[i]=t の「いいえ」の経路で増加を抜かすと、最初のカードが異なるときに同じ状態を訪問し続ける。読みやすい文章、明確な状態遷移、すべての経路の処理と停止を、合わせて点検する必要がある。

開始 → n=LENGTH(A), i=0 → [i<n?]
[i<n?] いいえ → RETURN None → 終了
[i<n?] はい → [A[i]=t?]
[A[i]=t?] はい → RETURN i → 終了
[A[i]=t?] いいえ → i=i+1 → [i<n?]

途中の過程をたどる例題

上の FIRST 手順とフローチャートを A=[8,3,8], t=8 に適用せよ。カードの値と位置を別々に記録し、返した後の命令が実行されるか判断せよ。

  1. 長さ n=3、初期位置 i=0 である。有効な位置は 0,1,2 で、最初のカードの値は 8 である。
  2. 0<3 が真なので位置 0 の値を読む。A[0]=8=t が真である。
  3. RETURN i が結果 0 を返し、FIRST 手順全体を終了させる。i=i+1 は実行せず、位置 1,2 も検査しない。
  4. 出力 0 はカードの値 8 と異なる。他の一致位置 2 があっても、最小の位置 0 なので契約を満たす。この記録は紙上の追跡であり、プログラムの実際の出力ではない。

最も左の一致位置 0 を返す。最初の要素で終了し、要素と目標の等値比較は 1 回である。

紙と本文で試してみよう

独立に A=[8,3,8],t=3、同じ A で t=5、そして A=[],t=8 を紙上で追跡せよ。それぞれの結果と要素・目標の等値比較回数を書き、範囲検査はその回数に含めるな。

ヒントを見る

条件 i<n が偽なら要素を読まない。成功の RETURN の後には繰り返しへ戻らない。

解答を見る

t=3 は位置 0 の 8 と比較して不一致となり、i=1 の 3 で成功するので、結果 1、等値比較 2 回である。t=5 は位置 0,1,2 ですべて不一致となった後、i=3 の範囲検査が偽なので None、等値比較 3 回である。空列は最初の 0<0 が偽なので None、等値比較 0 回である。範囲検査の回数はそれぞれ 2,4,1 回と別に数える。すべて紙上の計算である。

よくある誤解と反例

疑似コードには実行用の文法がないので、分岐の行き先や入力条件を正確に書かなくてもよい。

同じ位置で繰り返し続ける図と、次の位置に進む図では、結果と終了が異なる。疑似コードには文法を選ぶ自由があるが、意味の省略が許されるわけではない。例えば A=[8],t=3 で、増加のない不一致の経路は終了しない。

理解を確かめる

A=[8,3,8],t=8 で 2 を返したら、この契約に合うか？

答えと理由を見る

合わない。

存在の有無や任意の一致位置を求める契約と異なり、最小の一致位置 0 を要求する。

空のカード列で None を決めるには A[0] を読む必要があるか？

答えと理由を見る

読まない。

範囲検査 0<0 が先に偽となり、本体へ入らない。

RETURN1 の後で i を増やして残りも調べるか？

答えと理由を見る

調べない。

RETURN はこの手順全体を終了させ、その後の命令はこの呼び出しでは実行されない。

もう一歩先へ

発展：繰り返しの先頭でまだ値を返していなければ、0≤i≤n であり、すべての j<i に対し A[j]≠t であるという不変条件を置く。i=0 では前の要素がなく真である。i<n で A[i]≠t なら、i を一つ増やしても新しい接頭部分のすべての要素が異なるため、条件が保たれる。一致して返す場合は前の位置がすべて不一致なので、i が最初の位置である。i=n で抜ければ全体が不一致なので None が正しい。繰り返しを続ける各回で非負整数 n−i が 1 ずつ減るため終了する。正常な比較・有限の n・変更なしという仮定が必要であり、この議論は紙上の手順の意味についてのもので、実際の言語実装の例外や資源不足によるエラーを検証したものではない。

小節 6.2

探索と整列の直感

カードを順に並べれば探しやすくなるが、その順に並べる作業は無料だろうか？

準備する概念と学習目標

準備する概念

  • 整数カード列が昇順であるとは、隣り合うすべての要素について A[i]≤A[i+1] となる状態であり、同じ値の重複を許す。
  • 整列（ソート）は、入力カードの値と個数を保ちながら順序を変える問題である。結果が昇順だという条件だけでは不十分である。
  • この小単元の二分探索は、昇順の固定列から任意の一致位置または None を返す。前の小単元の最初の位置を求める探索とは契約が異なる。

学習目標

  • 線形探索と、整列を前提とする二分探索を紙上で追跡する。
  • 選択ソートの最小値選択・交換・重複の保存を説明する。
  • 整列コストと探索回数を一緒に考え、アルゴリズムの契約を区別する。

順序がなければ捨てる根拠がない

線形探索は左から目標と比較するため、整列されていなくても使える。二分探索は中央の値より目標が小さければ右側を捨て、大きければ左側を捨てる。捨てた区間に目標がないという結論は、カードが昇順だという条件から導かれる。

A=[9,1,5],t=9 を整列済みのように中央位置 1 で検査すると、値 1 より 9 が大きいため左側の位置 0 を捨ててしまう。この反例では実際に目標を捨てており、半分ずつ縮める動作だけをまねてはならないことを示す。順序条件の確認や整列コストも、目的に応じて考える必要がある。

境界を縮めて探す

探索区間を両端を含む [lo,hi] とし、mid=⌊(lo+hi)/2⌋ を定める。目標が A[mid] と等しければ mid を返し、小さければ hi=mid−1、大きければ lo=mid+1 に変える。lo>hi なら空の区間なので None である。この境界規則では、検査済みの mid を再び含めない。

A=[1,1,3,4],t=3 では lo=0/hi=3/mid=1 の値 1 から右に進み、lo=2/hi=3/mid=2 の値 3 を見つける。t=1 なら最初の mid=1 で 1 を返せる。最初の一致位置 0 を要求するなら、この手順をそのまま使わず、等しい場合にも左の候補をさらに探す別の契約とアルゴリズムが必要である。

整列結果に必要な二つの条件

選択ソートは左の未確定位置を一つずつ確定する。位置 i で、未確定の i..n−1 を走査して最小値を探し、A[i] と交換する。ここでは候補を i から始め、j=i+1..n−1 を順に比較し、厳密に小さい値のときだけ候補を変え、i=0..n−2 まで実行する。

交換は二枚のカードの位置だけを変えるため、同じ値のカードの個数も保つ。逆に入力 [4,1,3,1] を結果 [1,1,1,1] に変えると、昇順でも 4 と 3 を失うため、正しい整列結果ではない。同じ値にラベルが付いているときの相対順序を保つ安定性は別の要求であり、この選択ソートは一般には安定ではない。

途中の過程をたどる例題

固定列 A=[4,1,3,1] に上の選択ソートを適用せよ。候補の比較は厳密な < で、同じ値なら前の候補を保つ。各パスの候補位置、交換後の列、値の比較回数を書け。

  1. i=0、候補 0（値 4）。j=1 の値 1 で候補を 1 に変え、j=2 の値 3 と j=3 の値 1 では保つ。候補 1 と 0 を交換して [1,4,3,1] となり、値の比較は 3 回である。
  2. i=1、候補 1（値 4）。j=2 の値 3 で候補を 2、j=3 の値 1 で候補を 3 に変える。位置 1 と 3 を交換して [1,1,3,4] となり、値の比較は 2 回である。
  3. i=2、候補 2（値 3）。j=3 の値 4 は小さくないので候補 2 を保つ。同じ位置との交換は列を変えず、比較は 1 回である。i=3 のパスは不要である。
  4. 全体の結果 [1,1,3,4] は昇順で、1 を二枚、3 を一枚、4 を一枚保つ。比較回数は 3+2+1=6 である。実際の整列プログラムの実行ではなく、紙上の追跡である。

三パス後に [1,1,3,4] となり、値の比較は 6 回である。昇順と入力の多重集合の保存をともに満たす。

紙と本文で試してみよう

昇順 A=[1,1,3,4] で、上の二分探索によって t=2 を追跡せよ。別に、選択ソートの入力 [1,1,3,4] でも比較が 6 回になるか数えよ。値 2 のカードに左を a、右を b とラベルを付けた [2a,2b,1] が、選択ソート後も 2a/2b の順を保つかも書け。

ヒントを見る

各探索の mid と lo/hi を書く。選択ソートは順序が既に正しくても、残りの区間をすべて走査する。ラベルは値の比較に使わない。

解答を見る

t=2：[0,3] の mid=1 の値 1<2 なので lo=2；[2,3] の mid=2 の値 3>2 なので hi=1；すると lo=2>hi=1 で None となる。目標と中央の値を比較する訪問は 2 回である。既に整列された入力でも選択ソートの残りの比較は 3+2+1=6 回で、候補は各 i にとどまる。[2a,2b,1] は最初のパスで位置 0 と 2 を交換して [1,2b,2a] となり、二番目のパスでは同値の候補を変えないので、相対順序が逆転する。すべて紙上の追跡である。

よくある誤解と反例

整列すれば探索が速くなるので、一回だけの探索でも必ず整列から始める方が速い。

整列作業と整列済みかを確認するコストを除いてはならない。一回の探索は線形探索で終えられる。繰り返しの探索でも入力の変更頻度、整列方法、アクセス構造を考える必要があり、時間単位やデータ構造の異なる測定値を比較回数と混ぜて結論しない。

理解を確かめる

昇順の結果だけを確認すれば正しい整列か？

答えと理由を見る

そうではない。

入力の値と重複個数も保つ必要がある。[1,1,1,1] は元の入力の 3 と 4 を失う。

A=[1,1,3,4],t=1 で mid=1 をすぐ返したら、最初の位置を求める探索の契約を満たすか？

答えと理由を見る

満たさない。

任意の一致位置という契約には合うが、最初の位置は 0 である。アルゴリズムの許容出力を先に確認する。

上の選択ソートで、長さ 4 の整列済み入力は値の比較が 0 回か？

答えと理由を見る

6 回である。

残りの区間の最小値を確認するループは、やはり 3+2+1 回比較する。交換で列が変わる回数と比較回数は異なる。

もう一歩先へ

発展：選択ソートの i 番目のパス開始前には、先頭の i 個が昇順で、前のすべての値が後ろのすべての値以下であり、入力の多重集合が保たれるという不変条件を置く。i=0 では前部分の条件は空虚に真である。後ろの区間の最小値を A[i] に交換すると、既存の接頭部分より小さくなく、残りの値より大きくないため、i+1 個について条件が成立する。交換は多重集合を保ち、n−1 パス後には全体の順序が正しくなる。内部の比較は Σ(i=0..n−2)(n−i−1)=n(n−1)/2 であり、n=0 または n=1 では空の和 0 である。値の組の小さい/等しい/大きいを一度に判定する抽象比較を 1 と数え、整列後は静的配列を維持すると仮定する。このモデルで q 回の探索の単純な比較数の見積もりは、線形探索の最悪で qn、上の選択ソート後の二分探索では n(n−1)/2+q(⌊log₂n⌋+1) が上限（n≥1）となる。二分探索の一回の訪問で = と < を別々に実装して数えると、個々の比較演算数はこの訪問回数の上限とは異なる場合がある。これは実際の秒数、最適な方法、すべての入力での優劣を保証する式ではなく、重複・更新・整列の確認コストやメモリアクセスの仮定に注意する。

小節 6.3

正当性と実行コスト

一つの例題が正しく、速く終われば、すべてのカード列でも正しく速いといえるだろうか？

準備する概念と学習目標

準備する概念

  • 最初の位置を求める探索 FIRST の入力は、固定された有限の整数列 A と目標 t であり、結果は最初の一致位置または None である。
  • 不変条件は、繰り返しの決まった時点ごとに保たれる性質である。返すなら結果が正しいという部分正当性と、必ず終わるという終了性を合わせて確認する。
  • コストを数えるには、数える演算・入力サイズ・コストモデルを定める。この小単元では要素と目標の等値比較を 1 と数え、範囲検査・出力・秒単位の時間を別に区別する。

学習目標

  • 最初の位置を求める探索の初期状態・保存・終了の議論を直接つなぐ。
  • 最良・最悪の入力と比較回数を区別し、O/Ω/Θ を上界/下界/両側の境界として読む。
  • 反例・試験・証明の範囲と単位コストモデルの制限を説明する。

すべての許容入力に対して正しいという意味

正しいとは、選んだ少数の例だけでなく、入力契約に含まれるすべての場合に正しい結果を返すことである。A=[8,3,8],t=8 で 0 を返す手順も、目標が 8 なら無条件に 0 を返す手順も、この一例には合格する。しかし A=[3],t=8 では後者は誤る。一つの反例で普遍的な正当性を否定できるが、一つの合格例は証明ではない。

証明は手順の意味と仮定から結果をつなぐ。例えば前の位置がすべて不一致という不変条件を置き、正常な演算・有限の長さ・変更なしの下で初期状態と保存を確認する。実装の文法・例外・入出力・整数表現の契約が異なれば、追加の検討が必要である。紙上の証明はコード全体に欠陥がないことを自動的に保証しない。

正しく返すことと必ず終わること

FIRST が一致位置を返す時点では、前のすべての要素が確認済みで不一致だったので、最初の位置として正しい。最後まで進んだなら、すべての要素が不一致なので None が正しい。しかし「返すなら正解」だけを示しても、終わらない入力があるかは分からない。

不一致となる回ごとに位置が 1 ずつ増え、残りのカード数 n−i が減る。この値は繰り返しの先頭で非負整数であり、減り続けられる回数は有限である。したがって各正常な比較が終了するという契約では、FIRST も終了する。不一致の経路で増加しない手順は、値を返した成功例が正しくても完全な解決手順ではない。

成長率表記の対象となる関数を定める

長さ n の入力でも、見つかる位置により等値比較回数が異なる。最初の一致位置が j なら j+1 回、なければ n 回である。n≥1 の最良比較数は B(n)=1、最悪は W(n)=n である。O はあるコスト関数の十分大きい n での上界、Ω は下界、Θ は同じ成長率の上界と下界の両方を与える表記である。Ω 自体が最良の場合を意味するわけではない。

このモデルでは W(n)=Θ(n)、B(n)=Θ(1) である。W(n) は O(n²) も満たすが、緩い上界なので最も精密な成長率の説明ではない。全演算時間も最悪で線形と分析するには、値・インデックス・アドレスがそれぞれ O(1) 個のワードに収まり、任意位置へのアクセス・ワード比較・増加が単位コストである計算モデルを定める必要がある。Word-RAM のワード幅 w は、長さ n のアドレスを表せるよう少なくとも log₂n 程度でなければならない。実際の固定 32/64 ビット機械は表現できるアドレス範囲が有限なので、無制限の n を扱う漸近モデルと区別する。長くなる文字列や任意精度整数の比較、遅い外部記憶へのアクセスを無条件に定数コストと仮定しない。

途中の過程をたどる例題

A=[6,2,6,9] の FIRST を、独立の目標 t=6,9,5 について追跡せよ。要素・目標の等値比較だけを数え、各結果が最初の位置という契約を満たす理由を書け。

  1. t=6 は i=0 で A[0]=6 を確認して結果 0 を返す。比較 1 回で、それより前の位置がないので最初の一致である。位置 2 の 6 は検査しない。
  2. t=9 は位置 0 の 6、1 の 2、2 の 6 と不一致になった後、位置 3 の 9 で成功する。結果 3、比較 4 回で、前の三位置はすべて異なる。
  3. t=5 は四位置すべてで不一致となり、i=4 で 4<4 が偽なので None である。比較 4 回で、この結果は全体の不一致に基づく。
  4. 同じ n=4 でもコストは 1/4/4 回である。失敗例の範囲検査は 5 回で、等値比較 4 回と異なる。最悪比較 W(4)=4 が実際に何秒かは、この記録から分からない。

それぞれの（結果、等値比較数）は (0,1),(3,4),(None,4) である。成功位置と、失敗時の全体検査の根拠を別々に確認する。すべて紙上の計算である。

紙と本文で試してみよう

長さ 8 のカード列で、最初の一致位置が 5 の入力と、見つからない入力の等値比較数を計算せよ。別の手順が「要素が目標と等しければ返し、異なれば i を変えずに繰り返す」なら、A=[6],t=2 で終了するか状態を書け。

ヒントを見る

位置は 0 から始まるので、位置 5 までに読んだ要素数は位置番号と同じではない。終了のための量が実際に減るかも確認する。

解答を見る

最初の一致位置 5 では 0..5 までの 6 回、見つからなければ 8 回である。誤った手順は i=0,n=1 の状態で 6≠2 を確認し、再び i=0,n=1 に戻るので同じ比較を無限に繰り返す。n−i=1 は減らない。この反例は紙上で確認したもので、無限ループのプログラムを実際に実行してはいない。

よくある誤解と反例

Ω は最良の場合であり、Θ は最良と最悪が等しいときにだけ使う記号である。

記号はまず指定した関数の境界を表す。例えば最悪比較 W(n)=n 自体が Ω(n) かつ O(n) なので Θ(n) である。この探索の最良 B(n)=1 と最悪 W(n)=n は異なる関数で、互いに等しくなくても各関数に Θ 表記を使える。

理解を確かめる

FIRST で最初の一致位置 7 の等値比較は 7 回か？

答えと理由を見る

8 回である。

位置 0 から 7 まで計 8 個を比較する。

W(n)=n に O(n²) と書くと数学的に誤りか？

答えと理由を見る

誤りではないが、緩い上界である。

n≥1 なら n≤n² である。上界を満たすことと、タイトな Θ(n) の説明は区別する。

長さが常に 4 のカード一組で数えた 1/4 回によって、すべてのサイズの成長率を証明したか？

答えと理由を見る

していない。

固定例の回数と、任意の n に対する一般の不変条件・繰り返し回数の導出は異なる証拠である。

もう一歩先へ

発展：非負のコスト関数 f に対し、f∈O(g) は、ある C>0,N が存在してすべての n≥N で f(n)≤C g(n) となること、f∈Ω(g) は、ある c>0,N が存在して f(n)≥c g(n) となること、Θ(g) は両方が成立することを意味する（ここで g は十分大きい n で正）。W(n)=n には c=C=1,N=1 を使えば、直ちに Θ(n) を示せる。B(n)=1 には同じ定数で Θ(1) となる。入力と目標の分布を新たに定め、必ず成功し、最初の一致位置 J が 0..n−1 に一様に分布すると仮定する n≥1 のモデルでは、平均 E[C]=(1+…+n)/n=(n+1)/2 である。一様性と必ず成功する条件がなければ、この平均式をそのまま使わない。実際に全要素が同じ入力や、見つからない場合との混合などは別の分布であり、計算した平均、実際の経過時間、学習者の理解度はそれぞれ別の測定である。
