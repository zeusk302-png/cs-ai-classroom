Subtopic 6.1

Pseudocode and flowcharts

When the same number appears twice in a row of cards, which position does “found it” mean?

Preparation and learning goals

Preparation

  • Let n be the length of a finite sequence A of integer cards. Number positions from the left as 0,1,…,n−1. An empty sequence has n=0 and no valid element position.
  • Assignment changes state; comparison tests a condition. i←i+1 increases the current position by one rather than solving a mathematical equation.
  • None is a separate not-found marker. Distinguish it from valid position 0. In this unit comparisons terminate normally and the card sequence does not change during the procedure.

Learning goals

  • Specify inputs, allowed outputs and stopping conditions before writing pseudocode.
  • Map sequence, conditional branching and repetition to a flowchart, including the empty input.
  • Explain the difference between readable wording and unambiguous execution rules.

Start with the search contract

Calling a problem “find a number” does not specify the answer’s form. Existence, any matching position and the leftmost matching position are different contracts. Here, given input A and target t, return the smallest matching position if there is one, and None otherwise. Even with multiple cards of the same value, the required answer is unique.

For example, with A=[8,3,8] and t=8, position 2 is a match, but this contract’s correct output is 0. State the input assumptions too. Without a finite sequence, normally terminating integer comparisons and no changes during execution, the correctness and termination argument below cannot simply be reused.

A human-readable procedure still needs meaning

Pseudocode records order and conditions without committing to the grammar of a particular programming language. But an instruction such as “just find it somehow” leaves the next action undefined. Below, RETURN outputs a result and ends the whole procedure; the WHILE body repeats while its condition is true.

Check i<n before reading A[i]. With n=0, no body iteration occurs and the result is None. After the final test at i=n, A[n] is not read. Indentation shows which instructions belong to the loop or conditional and is more than decoration.

FIRST(A,t)
  n ← LENGTH(A)
  i ← 0
  WHILE i < n:
    IF A[i] = t: RETURN i
    i ← i + 1
  RETURN None

Read the arrows that return to a test

A flowchart shows the same procedure with boxes and arrows. In the text diagram below, a question marks a conditional test and each outcome has an explicit destination. An arrow to RETURN ends the procedure instead of moving to another position. The loop arrow returns to the bounds test after increasing i.

Drawing a diagram does not itself establish correctness. If the no branch of A[i]=t omits the increment, a different first card can make the same state repeat forever. Check readable wording, precise state transitions, treatment of every branch and termination together.

Start → n=LENGTH(A), i=0 → [i<n?]
[i<n?] no → RETURN None → End
[i<n?] yes → [A[i]=t?]
[A[i]=t?] yes → RETURN i → End
[A[i]=t?] no → i=i+1 → [i<n?]

A worked example, step by step

Apply FIRST and its flowchart to A=[8,3,8], t=8. Record card values and positions separately, and decide whether instructions after the return execute.

  1. The length is n=3 and the initial position is i=0. Valid positions are 0,1,2; the first card’s value is 8.
  2. Since 0<3 is true, read the value at position 0. The condition A[0]=8=t is true.
  3. RETURN i produces result 0 and ends the whole FIRST procedure. The increment i=i+1 is not executed and positions 1 and 2 are not checked.
  4. Output position 0 differs from card value 8. Although position 2 also matches, position 0 is the smallest match and satisfies the contract. This is a paper trace, not an actual program output.

Return leftmost matching position 0. The procedure ends at the first element, after one element-target equality comparison.

Try it with paper and the lesson

Trace independent cases A=[8,3,8],t=3; the same A with t=5; and A=[],t=8 on paper. Give each result and number of element-target equality comparisons, excluding bounds tests from that count.

Show hint

Do not read an element when i<n is false. After a successful RETURN, do not go back to the loop.

Show solution

For t=3, value 8 at position 0 fails, then value 3 at i=1 succeeds: result 1, two equality comparisons. For t=5, positions 0,1,2 all fail, then the bounds test fails at i=3: None, three equality comparisons. The empty sequence immediately fails 0<0: None, zero equality comparisons. The separate bounds-test counts are 2,4,1 respectively. These are paper calculations.

Misconception and counterexample

Because pseudocode is not executable syntax, branch destinations and input conditions need not be precise.

A diagram that repeats the same position and one that advances have different results and termination behaviour. Pseudocode permits a choice of notation, not missing meaning. For example, with A=[8],t=3, a failure branch with no increment never terminates.

Check your understanding

For A=[8,3,8],t=8, does returning 2 satisfy this contract?

Show answer and reasoning

No.

Unlike existence or any-match search, this contract requires smallest matching position 0.

Must A[0] be read to decide None for an empty sequence?

Show answer and reasoning

No.

The bounds test 0<0 is false before entry into the body.

After RETURN 1, is i increased to inspect the remaining cards?

Show answer and reasoning

No.

RETURN ends the whole procedure, so later instructions do not execute in this invocation.

Explore further

Further study: at the loop head, if no return has occurred, maintain 0≤i≤n and A[j]≠t for every j<i. At i=0 there are no preceding elements, so this holds. If i<n and A[i]≠t, increasing i by one preserves it for the enlarged prefix. A matching return therefore gives the first position, because every earlier position failed. Exiting at i=n means all elements failed, so None is correct. On each continuing iteration the nonnegative integer n−i decreases by one, establishing termination. Normally terminating comparisons, finite n and no changes are required. This is an argument about the paper procedure’s meaning, not verification of exceptions or resource errors in an actual language implementation.

Subtopic 6.2

Intuition for searching and sorting

Ordering the cards makes searching easier, but is putting them in order free?

Preparation and learning goals

Preparation

  • An integer sequence is in ascending order when A[i]≤A[i+1] for each neighbouring pair. Equal values and duplicates are allowed.
  • Sorting rearranges the input cards while preserving their values and counts. An ascending output alone is insufficient.
  • Binary search in this subtopic returns any matching position or None in a fixed ascending sequence. This differs from the preceding subtopic’s first-match contract.

Learning goals

  • Trace linear search and binary search with its sorting precondition on paper.
  • Explain selection sort’s minimum selection, swapping and preservation of duplicates.
  • Consider sorting costs and the number of searches together, and distinguish algorithm contracts.

Without order, there is no basis for discarding a half

Linear search compares from left to right and can be used without sorting. Binary search discards the right part when the target is smaller than the middle value, or the left part when larger. The conclusion that the discarded part contains no target relies on ascending order.

If A=[9,1,5],t=9 is treated as sorted, the middle position 1 contains value 1. Since 9 is larger, the procedure discards position 0 on the left, where the target actually is. This counterexample shows why merely imitating repeated halving is insufficient. Consider the cost of checking order or sorting when deciding how to search.

Find the target by shrinking boundaries

Use a search interval [lo,hi] with both ends included, and choose mid=⌊(lo+hi)/2⌋. If the target equals A[mid], return mid; if smaller, set hi=mid−1; if larger, set lo=mid+1. When lo>hi the interval is empty and the result is None. These rules exclude the already checked midpoint from the next interval.

For A=[1,1,3,4],t=3, lo=0,hi=3,mid=1 has value 1, so move right to lo=2,hi=3,mid=2 and find value 3. For t=1 the first mid=1 may immediately return position 1. If the required answer is first matching position 0, use a different contract and algorithm that continues searching left on equality.

Two conditions for a valid sorting result

Selection sort fixes one left-hand position at a time. At position i, scan the unfixed region i..n−1 for its smallest value and swap that card with A[i]. Here, start the candidate at i, compare j=i+1..n−1 in order, change the candidate only for a strictly smaller value, and perform passes i=0..n−2.

A swap changes only two card positions and preserves the count of each value. By contrast, converting input [4,1,3,1] into [1,1,1,1] gives ascending order but loses 4 and 3, so it is not a sorting solution. Stability, preserving the relative order of labelled cards with equal values, is a separate requirement; this selection sort is generally unstable.

A worked example, step by step

Apply this selection sort to fixed A=[4,1,3,1]. Use strict < for candidate comparisons and keep the earlier candidate on equality. Record candidate positions, the sequence after each swap and the number of value comparisons.

  1. At i=0, candidate 0 has value 4. Value 1 at j=1 changes the candidate to 1; values 3 at j=2 and 1 at j=3 leave it there. Swap positions 1 and 0: [1,4,3,1], three comparisons.
  2. At i=1, candidate 1 has value 4. Value 3 at j=2 changes it to 2, then value 1 at j=3 changes it to 3. Swap positions 1 and 3: [1,1,3,4], two comparisons.
  3. At i=2, candidate 2 has value 3. Value 4 at j=3 is not smaller, so candidate 2 remains. Swapping a position with itself leaves the sequence unchanged: one comparison. No i=3 pass is needed.
  4. The final [1,1,3,4] is ascending and preserves two cards of value 1, one of value 3 and one of value 4. The comparison total is 3+2+1=6. This is a paper trace, not an executed sorting program.

After three passes: [1,1,3,4], with six value comparisons. Both ascending order and the input multiset are preserved.

Try it with paper and the lesson

Trace binary search for t=2 in ascending A=[1,1,3,4]. Separately count whether selection sort still makes six comparisons on input [1,1,3,4]. Label the left and right cards of value 2 as a and b in [2a,2b,1], then check whether selection sort preserves their relative order.

Show hint

Record mid and lo/hi for each search step. Selection sort scans every remaining region even if the sequence is already ordered. Labels are not used in value comparisons.

Show solution

For t=2: in [0,3], mid=1 has value 1<2, giving lo=2; in [2,3], mid=2 has value 3>2, giving hi=1; now lo=2>hi=1, so return None. There are two middle-value comparison visits. On the already sorted input, selection sort still compares 3+2+1=6 times, keeping candidate i on each pass. In [2a,2b,1], the first pass swaps positions 0 and 2 to give [1,2b,2a]. The second pass does not change equal values, so their relative order is reversed. All are paper traces.

Misconception and counterexample

Sorting makes searching faster, so sorting first is always faster even for one search.

Do not omit the work of sorting or checking order. One search can finish with linear search alone. Even with repeated queries, consider input changes, the sorting method and access structure. Do not mix comparison counts with timings measured in different units or on different data structures.

Check your understanding

Is ascending order alone enough to establish correct sorting?

Show answer and reasoning

No.

The original values and duplicate counts must also be preserved. [1,1,1,1] loses the input’s 3 and 4.

For A=[1,1,3,4],t=1, does immediately returning mid=1 satisfy first-match search?

Show answer and reasoning

No.

It satisfies any-match search, but the first position is 0. Check the algorithm’s allowed outputs first.

Does this selection sort make zero value comparisons on an already sorted length-four input?

Show answer and reasoning

It makes six.

The loops still check remaining minima 3+2+1 times. The number of comparisons differs from the number of swaps that change the sequence.

Explore further

Further study: at the start of pass i, maintain that the first i values are ascending, every prefix value is at most every remaining value, and the input multiset is preserved. At i=0 the prefix conditions are vacuously true. Swapping the remaining minimum into A[i] makes it no smaller than the existing prefix and no larger than any remaining value, establishing the i+1 condition. Swaps preserve the multiset; after n−1 passes the whole sequence is ordered. The internal comparison count is Σ(i=0..n−2)(n−i−1)=n(n−1)/2; for n=0 or n=1 the empty sum is 0. Count an abstract comparison that determines smaller/equal/larger as one operation and assume a static array after sorting. In this model, q searches have a simple worst-case linear count qn; selection sort followed by binary searches has upper bound n(n−1)/2+q(⌊log₂n⌋+1), for n≥1. Implementing equality and less-than as separate comparisons during one binary-search visit may yield a different count of individual operations. This estimate does not guarantee elapsed seconds, an optimal method or superiority on every input. Keep duplicates, updates, order-checking costs and memory-access assumptions in view.

Subtopic 6.3

Correctness and execution cost

If one example is correct and finishes quickly, can we conclude that every card sequence is handled correctly and quickly?

Preparation and learning goals

Preparation

  • FIRST takes a fixed finite integer sequence A and target t, returning the first matching position or None.
  • An invariant is a property maintained at a specified point in a loop. Check both partial correctness, giving the right result if it returns, and termination, which guarantees that it finishes.
  • To count costs, specify the operation, input size and cost model. This subtopic counts each element-target equality comparison as one, distinguishing bounds tests, output and elapsed seconds.

Learning goals

  • Connect initialization, preservation and termination arguments for first-match search.
  • Distinguish best and worst inputs and comparison counts, reading O/Ω/Θ as upper/lower/two-sided bounds.
  • Explain the scope of counterexamples, tests and proofs and the limits of a unit-cost model.

Correct for every allowed input

Correctness means producing a valid result for every input within the contract, not just a few selected examples. For A=[8,3,8],t=8, both the proper search and a procedure that always returns 0 whenever the target is 8 pass this single case. But the latter is wrong for A=[3],t=8. One counterexample can refute universal correctness; one passing case is not a proof.

A proof connects assumptions and the procedure’s meaning to the result. For example, establish the invariant that every preceding position failed and check initialization and preservation under normal operations, finite length and no changes. An implementation with different syntax, exceptions, input/output or integer representation needs further review. A paper proof does not automatically establish that the whole program is free of defects.

Returning correctly and necessarily finishing

When FIRST returns a match, all earlier elements have already failed, so this is the first position. If it reaches the end, every element failed and None is correct. But establishing only “if it returns, the result is correct” does not exclude nonterminating inputs.

Each failure iteration increases the position by one and decreases the remaining card count n−i. At the loop head this is a nonnegative integer and can decrease only finitely often. Thus FIRST terminates under the contract that every comparison terminates normally. A procedure without an increment on failure is not a complete solution even if its successful returns are correct.

Specify the function whose growth is bounded

Even at the same length n, equality counts depend on the matching position. If the first match is at j, the count is j+1; with no match, it is n. For n≥1 the best count is B(n)=1 and worst is W(n)=n. O bounds a specified cost function from above for sufficiently large n; Ω bounds it from below; Θ gives both bounds at the same growth rate. Ω does not itself mean best case.

Here W(n)=Θ(n) and B(n)=Θ(1). W(n) also belongs to O(n²), but that is a loose upper bound rather than the tightest description. To analyze total operations as linear in the worst case, specify a model in which values, indices and addresses each fit in O(1) words, and random access, word comparisons and increments have unit cost. A Word-RAM word width w must be at least about log₂n to represent addresses for length n. Actual fixed-width 32/64-bit machines have finite address ranges, unlike an asymptotic model with unbounded n. Do not automatically give constant cost to comparisons of growing strings or arbitrary-size integers, or slow external-storage accesses.

A worked example, step by step

Trace independent FIRST searches for t=6,9,5 in A=[6,2,6,9]. Count only element-target equality comparisons and explain why each result meets the first-match contract.

  1. For t=6, at i=0 the condition A[0]=6 gives result 0 after one comparison. With no earlier position it is the first match; value 6 at position 2 is not checked.
  2. For t=9, values 6,2,6 at positions 0,1,2 fail, then value 9 at position 3 succeeds. Result 3, four comparisons; all preceding positions differ.
  3. For t=5, all four positions fail. At i=4 the test 4<4 is false, giving None after four equality comparisons, justified by failure at every element.
  4. The same n=4 gives counts 1/4/4. The failed search has five bounds tests, distinct from four equality comparisons. This record cannot tell how many seconds worst count W(4)=4 takes.

The (result, equality count) pairs are (0,1),(3,4),(None,4). Check the justification for first success and complete failure separately. These are paper calculations.

Try it with paper and the lesson

For a length-eight sequence, calculate equality counts for first match at position 5 and for no match. In a different procedure that returns on equality but repeats without changing i on failure, does A=[6],t=2 terminate? Record its state.

Show hint

Positions start at 0, so the number of elements read through position 5 differs from its position number. Check whether the termination measure actually decreases.

Show solution

First match at position 5 compares positions 0..5, six times; absence compares eight times. The incorrect procedure checks 6≠2 at i=0,n=1, then returns to the same i=0,n=1 state, repeating forever. The measure n−i=1 never decreases. This counterexample was checked on paper; no infinite-loop program was actually run.

Misconception and counterexample

Ω means best case, and Θ can be used only when best and worst cases are equal.

These notations bound a function specified beforehand. For example, worst count W(n)=n itself is both Ω(n) and O(n), hence Θ(n). Best B(n)=1 and worst W(n)=n are different functions and each can have a Θ bound even though they differ.

Check your understanding

If FIRST’s first match is at position 7, does it make seven equality comparisons?

Show answer and reasoning

Eight.

Positions 0 through 7 contain eight elements.

Is writing O(n²) for W(n)=n mathematically false?

Show answer and reasoning

No, but it is a loose upper bound.

For n≥1, n≤n². Satisfying an upper bound differs from a tight Θ(n) description.

Do counts of one or four comparisons on one always-length-four card sequence prove a growth rate for every size?

Show answer and reasoning

No.

A fixed instance’s count differs from a general invariant and iteration-count derivation for arbitrary n.

Explore further

Further study: for nonnegative cost function f, f∈O(g) means that some C>0 and N give f(n)≤C g(n) for all n≥N. Membership in Ω(g) means that some c>0 and N give f(n)≥c g(n). Θ(g) means both hold; here g is positive for sufficiently large n. For W(n)=n, choosing c=C=1,N=1 immediately gives Θ(n). For B(n)=1 the same constants give Θ(1). In a new input-target distribution model with n≥1, assume searches always succeed and the first matching position J is uniform over 0..n−1. Then the mean is E[C]=(1+…+n)/n=(n+1)/2. Without uniformity or guaranteed success, do not reuse this formula. Inputs where every element is identical, or distributions mixing unsuccessful searches, are different distributions. Computed means, elapsed time and learner understanding are separate measurements.
