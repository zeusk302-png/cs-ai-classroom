소단원 1.1

입력·처리·출력

세 친구의 점수 중 가장 큰 점수를 고르라고 했을 때, 컴퓨터는 공동 1등의 이름까지 알아서 고를까?

준비 개념과 학습 목표

준비 개념

  • 7 > 4가 참인지 판단할 수 있다. 비교가 낯설다면 수직선에서 오른쪽 숫자가 더 크다고 복습한다.
  • 규칙을 한 줄씩 따라가며 현재 값을 종이에 적을 수 있다. 변수는 현재 값을 붙여 놓는 이름이라고 생각한다.

학습 목표

  • 입력의 종류와 허용 범위, 출력의 의미를 명세한다.
  • 세 수의 최댓값 절차를 추적하고 동점·음수 반례를 검토한다.
  • 원하는 목적과 실제로 정의한 계산이 다를 수 있음을 설명한다.

목적을 계산 가능한 약속으로 바꾸기

‘가장 잘한 사람을 알려 줘’는 사람에게도 모호하다. 점수만 비교하는지, 노력까지 평가하는지, 공동 1등을 어떻게 표시하는지 정해야 한다. 이 단원에서는 입력을 세 정수 a, b, c, 출력을 그중 가장 큰 정수 m으로 제한한다. 이름을 반환하는 문제는 별도의 명세가 필요하다. 명세는 구현 전에 입력과 결과 사이에 지켜야 할 관계를 적은 약속이다.

수학적으로 입력 영역 D는 정수 세 개의 순서 있는 묶음 (a,b,c)들의 집합 Z³이고, 출력은 m이 a, b, c 중 하나이며 세 입력 모두보다 크거나 같은 값이라는 조건을 만족해야 한다. 여기서 비교 가능한 정수와 충분한 표현 범위를 가정한다. 문자 ‘없음’이나 결측치는 D에 속하지 않는다. 입력을 거절할지 별도 표시로 처리할지도 실제 제품에서는 명세에 포함해야 한다.

입력·처리·출력의 구분

입력은 계산에 제공되는 자료, 처리는 그 자료와 현재 상태에 규칙을 적용하는 과정, 출력은 사용자나 다른 계산에 전달되는 결과다. 처음부터 정답을 입력하는 것은 최댓값을 찾는 처리의 설명이 아니다. 처리 방법을 정하면 같은 입력을 종이로도 따라갈 수 있다. 이 예에서는 m을 a로 시작하고 b가 더 크면 m을 바꾸며 c도 같은 방식으로 비교한다.

값을 반환하는 것과 화면에 쓰는 것은 구별된다. 최대값 함수가 8을 반환했지만 호출자가 화면에 6을 표시하면 계산과 표시 중 어디에서 오류가 생겼는지 각각 조사할 수 있다. 모든 프로그램이 한 번의 입력과 출력으로 끝나지는 않는다. 게임·서버는 입력 사건과 상태 변화가 반복되므로, 입력·처리·출력 그림에 현재 상태와 다음 상태를 추가해야 한다.

규칙이 맞는 이유를 작은 불변식으로 설명하기

첫 비교 전 m=a이므로 지금까지 본 한 수의 최댓값이다. b를 비교한 뒤에는 둘 중 큰 값이 m에 남는다. c를 비교하면 세 수의 최댓값이 남는다. 이처럼 처리 중 특정 지점에서 계속 유지하는 성질을 불변식이라고 한다. ‘지금까지 본 수의 최댓값’이라는 성질이 초기화·갱신·종료를 연결하므로, 몇 가지 예시를 우연히 통과했다는 것보다 강한 근거가 된다.

엄격한 비교 >를 사용해도 출력이 값이면 동점에서 문제가 없다. 그러나 우승자의 위치까지 반환한다면 동점에서 기존 위치를 유지하는지 마지막 위치로 바꾸는지가 달라진다. 또 m을 0으로 시작하면 음수 입력만 있는 경우 0이 입력에 없는데 반환된다. 처음 값을 실제 입력에서 고르는 이유는 이 반례를 제거하기 위해서다.

m ← a
if b > m: m ← b
if c > m: m ← c
return m  // 의사코드이며 실행 결과가 아님

중간 과정을 따라가는 예제

세 정수 (-4, -1, -1)의 최댓값만 반환한다. 동점의 사람 이름은 반환하지 않는다.

  1. 초기화: m=-4. 지금까지 본 값은 [-4].
  2. b=-1과 m=-4 비교: -1>-4이므로 m=-1. 본 값 [-4,-1]의 최댓값이다.
  3. c=-1과 m=-1 비교: -1>-1은 거짓이므로 m=-1 유지.
  4. m이 입력 중 하나인지, 세 입력보다 모두 크거나 같은지 확인한다.

최댓값은 -1이다. 공동 최댓값이 둘이어도 출력값은 하나다. 비교는 두 번 수행했다.

종이와 본문으로 직접 해보기

카드에 8, 8, 3을 쓰고 같은 절차를 따라가라. 이어서 ‘가장 큰 수의 첫 번째 위치’도 출력하도록 규칙을 보완하라. 위치는 1부터 세고 동점이면 앞쪽을 선택한다.

힌트 보기

m과 함께 위치 p를 기억한다. 더 큰 수를 발견했을 때만 m과 p를 함께 바꾼다.

풀이 보기

시작 (m,p)=(8,1). 두 번째 8은 더 크지 않으므로 유지하고 세 번째 3도 유지한다. 결과는 (8,1). >를 >=로 바꾸고 매번 위치를 갱신하면 동점 때 2가 되어 명세를 어긴다.

오해와 반례

컴퓨터는 ‘최고’를 구하라는 말을 들으면 우리의 목적을 알아서 이해한다.

점수 최대와 노력 최대는 다른 관계다. 입력에 노력 정보가 없으면 그것을 비교할 근거도 없다. 공동 1등을 한 명으로 줄이는 규칙 역시 사람이 정해야 한다. 학습 기반 시스템도 입력·목표·평가 기준이 필요하며, 그 출력이 명세를 항상 만족한다고 자동으로 보장되지는 않는다.

자기점검

세 점수 4,9,2와 ‘최댓값은 9’ 중 입력과 출력은 무엇인가?

답과 이유 보기

4,9,2가 입력, 9가 출력이다.

세 수가 규칙에 제공되고, 비교 결과가 반환된다.

입력이 -7,-2,-5일 때 m을 0으로 시작하면 무엇이 잘못되는가?

답과 이유 보기

0을 반환해 잘못된다. 올바른 결과는 -2다.

0은 입력 중 하나도 아니며, 초기화 때부터 ‘본 수의 최댓값’ 성질을 만족하지 않는다.

값만 반환하는 명세에서 6,6,6은 오류 입력인가?

답과 이유 보기

아니다. 출력은 6이다.

동점은 최댓값 존재를 막지 않는다. 사람을 한 명 선택하는 규칙은 별도 문제다.

한 단계 더

n개의 정수로 확장해 보자. n≥1일 때 첫 원소로 시작하고 나머지를 한 번씩 비교하면 n-1회 비교한다. ‘k개를 처리한 뒤 m은 그 k개의 최댓값’이라는 귀납적 설명을 써 보라. 빈 목록은 첫 원소가 없으므로 같은 초기화가 불가능하다. 빈 입력을 금지하거나 별도의 없음 결과를 도입해야 한다.

소단원 1.2

문제 분해와 추상화

학급 도서 대출을 설계할 때 책 표지의 색까지 기록해야 할까?

준비 개념과 학습 목표

준비 개념

  • 입력과 결과를 구별한다. ‘책번호를 주면 대출 가능 여부를 답한다’에서 각각 무엇인지 말해 본다.
  • 순서대로 규칙을 적용한다. 앞 단계의 결과를 다음 단계 입력으로 전달할 수 있어야 한다.

학습 목표

  • 분해와 추상화를 구별하고 간단한 모듈 계약을 작성한다.
  • 필요한 정보를 버렸을 때 생기는 반례를 만든다.
  • 부분 명세의 연결이 전체 목적을 만족하는 조건을 설명한다.

분해는 책임을 나누는 일

도서 대출을 한 덩어리로 생각하면 회원 확인, 책 찾기, 대출 가능 판단, 기록 저장이 섞인다. 문제 분해는 큰 작업을 책임이 명확한 작은 작업으로 나누는 것이다. ‘회원 확인’은 회원번호를 받아 유효 여부를 내고, ‘책 찾기’는 책번호를 받아 현재 상태를 낸다. 단계마다 입력·출력·실패 결과를 적으면 어느 부분을 수정해야 하는지 찾기 쉽다.

단계를 무조건 잘게 자르면 좋은 것은 아니다. 한 책임을 나눴는데 같은 상태를 여러 곳에서 동시에 고쳐야 하면 연결이 더 복잡해질 수 있다. 이 첫 단원에서는 한 사람이 차례대로 처리하고 동시 대출 요청이 없다고 가정한다. 실제 서비스에서 두 사용자가 같은 책을 동시에 빌리면 ‘가능 확인’과 ‘기록 갱신’ 사이의 경쟁을 막는 별도 설계가 필요하다.

추상화는 목적에 맞는 정보를 남기는 일

추상화는 관심 있는 질문에 필요한 차이를 남기고 다른 세부 사항을 감추는 모델링이다. 대출 가능 여부만 판단한다면 책번호와 대출중 여부는 필요하지만 표지 색은 보통 필요하지 않다. 같은 대출 상태를 가진 서로 다른 표지의 책을 동일하게 다루어도 목적에 문제가 없기 때문이다. 반대로 표지 색으로 검색하는 서비스에서는 색을 버릴 수 없다. 추상화의 적합성은 목적에 달려 있다.

엄밀하게 현실 상태 r에서 모델 상태 A(r)를 만든다고 하자. A(r1)=A(r2)인 두 현실 상태에 대해 우리가 원하는 답이 다르면, 그 모델만으로 올바른 답을 낼 수 없다. 이는 모델이 필요한 구별을 잃었다는 반례다. 모든 현실을 그대로 저장하는 것보다, 답을 바꾸는 차이가 무엇인지 찾아 보존하는 것이 중요하다.

작은 계약을 연결할 때 확인할 것

이 예의 정책은 유효한 회원이고 책이 존재하며 대출중이 아닐 때만 대출을 승인하는 것이다. memberOK, bookExists, loaned가 각각 참/거짓이라면 승인=memberOK AND bookExists AND NOT loaned로 표현한다. 책이 없을 때 loaned를 읽을 수 없는 구현에서는 bookExists가 거짓인 경로를 먼저 종료해야 한다. 논리식의 모든 입력이 항상 존재한다는 가정과 실제 데이터 조회 순서는 구별해야 한다.

부분 작업이 각자 맞아도 연결이 틀리면 전체는 틀릴 수 있다. 책 조회는 ‘존재하지 않음’을 돌려주는데 다음 단계가 이를 ‘비어 있으니 대출 가능’으로 해석한다면 계약이 어긋난다. 인터페이스는 함수 이름만이 아니라 값의 의미와 허용 상태를 공유하는 약속이다. 나중에 자료구조에서는 이 약속을 내부 표현과 분리하고, 소프트웨어공학에서는 여러 모듈의 변경과 검증을 다룬다.

중간 과정을 따라가는 예제

회원 M은 유효하다. 책 B17은 존재하며 loaned=true이다. 순차 처리이고 예약·연체 정책은 없다. 대출 가능 여부를 계산한다.

  1. 회원 확인 모듈: M→memberOK=true.
  2. 책 조회 모듈: B17→bookExists=true, loaned=true.
  3. 판단: true AND true AND NOT true=true AND true AND false=false.
  4. 거절 결과를 내고 대출 기록을 바꾸지 않는다.

대출을 거절한다. 회원이 유효하다는 한 조건만으로는 충분하지 않다.

종이와 본문으로 직접 해보기

A책은 존재하지만 대출중이고, Z책은 존재하지 않는다. 모델에 ‘사용 가능하지 않음’이라는 한 상태만 남기면 각각 거절 사유를 ‘대출중’과 ‘책 없음’으로 구분할 수 있는가? 필요한 모델을 다시 써라.

힌트 보기

같은 모델 상태에 묶은 두 경우가 서로 다른 답을 요구하는지 보라.

풀이 보기

불가능하다. 두 현실 상태가 같은 상태로 합쳐졌지만 원하는 사유는 다르다. NOT_FOUND, ON_LOAN, AVAILABLE 세 상태를 남기면 구별 가능하다. 표지 색은 이 사유 결정에는 여전히 필요하지 않다.

오해와 반례

추상화는 세부 정보를 많이 버릴수록 좋은 것이다.

소단원 1.3

컴퓨터공학의 분야 지도

도서 검색 버튼을 눌렀는데 결과가 느리다. 이것은 프로그래밍 언어 한 과목만 공부하면 풀리는 문제일까?

준비 개념과 학습 목표

준비 개념

  • 입력·처리·출력의 뜻을 안다. 책 제목 입력→검색→결과 목록으로 다시 말해 본다.
  • 하나의 서비스에 여러 책임이 있음을 안다. 화면과 저장된 기록을 별도로 생각해 본다.

학습 목표

  • 컴퓨터공학 주요 분야를 질문과 책임으로 구분한다.
  • 한 서비스를 여러 계층으로 추적하고 가정을 적는다.
  • 증상만으로 원인을 단정하지 않고 관찰할 증거를 정한다.

언어는 도구, 분야는 질문의 묶음

C나 Python은 절차를 표현하고 실행시키는 도구다. 컴퓨터공학은 그 도구만 배우는 과목의 모음이 아니다. 알고리즘은 어떤 절차가 맞고 얼마나 많은 일을 하는지, 자료구조는 데이터를 어떤 조직으로 보관하고 연산할지 묻는다. 컴퓨터구조는 명령을 하드웨어가 어떻게 실행하는지, 컴퓨터시스템은 그 실행을 프로그래머가 어떻게 이해하고 비용을 줄일지 묻는다. 같은 언어로 여러 분야의 작업을 할 수 있다.

운영체제는 여러 프로그램이 CPU·메모리·장치를 어떻게 함께 쓰는지 다룬다. 네트워크는 여러 컴퓨터 사이의 전달을, 데이터베이스는 저장된 자료를 질의하고 일관성을 지키는 방법을 다룬다. 소프트웨어공학은 요구사항·변경·테스트·협업을, 인간과 컴퓨터의 상호작용은 사람이 목표를 수행할 수 있는 인터페이스를 다룬다. 경계는 강의의 초점을 정하는 도구이며 실제 문제에는 여러 분야가 겹친다.

버튼 하나를 계층을 따라 보기

검색 버튼을 누르면 화면이 제목 문자열을 받고 요청을 만들 수 있다. 요청이 네트워크를 통해 서버에 도착하면 서버는 저장 자료를 찾아 결과를 만들고 화면은 이를 표시한다. 이 흐름은 설명용 웹 검색 서비스 모델이다. 모든 프로그램이 서버를 쓰는 것은 아니며, 오프라인 도서 목록이라면 네트워크 단계가 없다. 상황의 구조를 확인하기 전 익숙한 계층을 무조건 끼워 넣지 말자.

느림이라는 증상에는 원인이 여러 개다. 검색 절차가 항목을 너무 많이 비교할 수도 있고, 전송 대기·디스크 읽기·화면 렌더링이 오래 걸릴 수도 있다. ‘Python이라 느리다’라는 추측만으로 언어를 바꾸는 것은 근거가 부족하다. 각 단계에 걸린 시간을 따로 관찰해야 다음에 조사할 분야를 좁힐 수 있다. 측정은 추정과 구별해서 기록한다.

이론·구현·사회적 판단을 함께 연결하기

이론 분야는 계산 가능성, 논리, 정확성, 복잡도 같은 질문을 형식적으로 다룬다. 인공지능은 데이터에서 규칙이나 예측 모델을 학습하는 문제를 포함하며, 성능 평가에 확률·통계가 연결된다. 모델이 ‘관심 있어 할 책’을 추천하더라도 사용자 동의, 개인정보 보호, 접근성 문제는 자동으로 해결되지 않는다. 요구사항과 평가의 선택에는 사람의 판단이 남는다.

이 과정에서는 준비개념에 맞춰 입구를 선택하되 질문을 단순화한 가정을 계속 표시한다. 종이의 검색 비교는 알고리즘의 한 부분을 관찰한 것이고, 실제 서버의 실행 시간 측정은 다른 증거다. 작은 모형에서 이해한 사실을 제품의 전체 성능이나 보안 보장으로 확대하지 않아야 한다. 첫 단원은 지도를 제공하고 이후 과목은 정의·증명·구현을 깊게 다룬다.

중간 과정을 따라가는 예제

순차 처리하는 설명용 검색 서비스에서 요청 전송 20ms, 서버 검색 70ms, 응답 전송 20ms, 화면 표시 10ms로 관찰했다고 가정한다. 중첩·재시도는 없다.

  1. 전체 시간은 20+70+20+10=120ms.
  2. 서버 검색을 70ms→35ms로 줄이고 다른 단계는 같다고 가정한다.
  3. 새 시간은 20+35+20+10=85ms.
  4. 검색 단계는 2배 빨라졌지만 전체 배속은 120/85=24/17≈1.41이다.

전체는 35ms 줄어든다. 병목 후보인 검색의 개선을 전체의 2배 개선이라고 말할 수 없다. 수치는 가상 관찰 자료이며 실제 서비스 측정이 아니다.

풀이 보기

첫 증상은 입력 문자열과 서버 질의 결과를 대조해 검색·자료 품질 경계를 조사한다. 둘째는 응답 내용과 화면의 표시 상태를 대조해 화면 처리 경계를 조사한다. 셋째는 요청한 사용자와 접근 권한 판정·반환 레코드를 확인해 보안 및 데이터 경계를 조사한다. 이는 조사 출발점이며 원인을 확정한 결과가 아니다.

오해와 반례

각 분야는 독립적이므로 웹 서비스에는 웹 프로그래밍만 필요하다.

검색이 잘못된 순서로 자료를 읽는 경우 자료구조·알고리즘이, 여러 이용자의 기록이 섞이는 경우 데이터베이스·보안이 연결된다. 반대로 모든 소규모 프로젝트에 모든 전문 분야의 깊은 구현이 필요한 것도 아니다. 기능과 제약을 근거로 필요한 깊이를 정한다.

한 단계 더

위 모델에서 검색 시간을 0ms로 만들어도 남는 시간은 50ms다. 전체 개선의 최대 배속은 120/50=2.4다. 동시에 여러 요청을 처리하면 한 요청의 지연시간과 초당 처리량은 다른 지표가 된다. 컴퓨터시스템의 비용 분석과 운영체제의 자원 공유에서 이 차이를 다시 만난다.
