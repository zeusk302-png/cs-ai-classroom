Subtopic 3.1

CPU and Instruction Execution

When we say that a computer added two numbers, which internal values changed, and how?

Preparation and learning goals

Preparation

  • State: the values needed for subsequent behavior at one moment, such as registers, memory, and the next instruction position. This does not mean remembering every detail of the past.
  • Assignment A←x: replace the value of A with x. Read the right-hand side in the state before the change. A←A+1 is not the mathematical equation A=A+1.
  • Remainder: x mod256 is the remainder on division by the positive integer 256 and lies in 0–255. The fictional registers in this unit store only 8-bit unsigned values.

Learning goals

  • Distinguish the meaning of an instruction set from the implementation of a CPU.
  • Trace changes in the PC, registers, and data memory in a state table.
  • Explain why sequential instruction semantics guarantee neither one clock cycle per instruction nor program termination.

An instruction is a rule for changing state

A CPU performs computation and control according to instruction semantics. An instruction set architecture, or ISA, is a contract about instructions and data representations on which software can rely. We can describe sequential semantics through fetching instruction bits, decoding their meaning, and executing their effects. The actual implementation may use pipelines, multiple execution units, or out-of-order execution, so this description does not imply physically executing one instruction in one clock cycle.

The program counter, PC, indicates the position of the next instruction. An ordinary instruction advances to the next position, whereas a branch selects a different PC according to its condition. Registers are small storage locations that hold values used during CPU computation. Updating a register with an addition does not automatically update the original data memory.

Define a small machine completely

Our paper model separates the instruction table I from the data table D. Each row of I contains one instruction; D is an array with one 8-bit value at each address 0–15. A and B are 8-bit registers, and PC is a row number in I. The model includes no actual instruction-byte encoding, physical clock, exceptions, or external input. Stored-program systems can place programs and data in the same main memory, but our two separate tables do not claim to reproduce that physical arrangement.

One step reads I[PC], first increases PC by 1, and then applies the instruction effect. LOAD R,a means R←D[a] for R∈{A,B}; STORE A,a means D[a]←A; ADD A,B means A←(A+B) mod256. JZ A,k sets PC←k only when A=0. HALT enters the halted state, after which there are no further steps. Each executed step uses valid data addresses and a valid I[PC]. After HALT, PC may point just beyond the last row because no further instruction is fetched. Rules for out-of-range access in actual languages are a separate topic.

Computation, storage, and control have different effects

LOAD copies a value without erasing D[a]; STORE changes the specified data cell. ADD changes only A, leaving B and the data unchanged. A branch selects the next instruction position rather than computing a data value. Different initial data can produce different state paths even with the same instruction table. A claim about a result therefore requires the initial state and all relevant rules, as well as the program.

An instruction count and elapsed time are different information. Executing six instructions in a sequential model does not imply six seconds or six clock cycles. CPU clock frequency alone also does not determine total program time: memory and I/O waits, instruction costs, and implementation matter. A backward branch may prevent termination, so tracing a few steps correctly is different from proving that every execution finishes.

A worked example, step by step

Initially A=B=0, PC=0, D[8]=6, D[9]=4, and D[10]=0. The instruction table is I[0]=LOAD A,8; I[1]=LOAD B,9; I[2]=ADD A,B; I[3]=STORE A,10; I[4]=JZ A,0; I[5]=HALT. Increase PC before applying the effect at every step and find the final state.

  1. After LOAD at PC0, A=6, B=0, PC=1. After the second LOAD at PC1, A=6, B=4, PC=2. D[8] and D[9] do not change.
  2. After ADD at PC2, A=(6+4) mod256=10, B=4, PC=3. D[10] is still 0.
  3. After STORE at PC3, D[10]=10 and PC=4. JZ at PC4 sees A=10≠0, so it keeps the already incremented PC=5.
  4. HALT at PC5 increases PC to 6 and then halts. I[6] is not read after halting. Six instructions have executed, and the final values are A=10, B=4, D[10]=10.

The machine halts after six steps with PC=6, A=10, B=4, D[10]=10, D[8]=6, and D[9]=4. This is a semantic trace of our own machine, not an actual CPU measurement or output from running TOY.

Try it with paper and the lesson

Use the same instruction table, but set D[8]=D[9]=0 and start with D[10]=0. Find the state after the first five instructions and determine whether HALT is reached. Assume no external changes to I or D.

Show hint

Find A and B after the two LOADs and ADD, then check whether JZ changes the already incremented PC again.

Show solution

The two LOADs and ADD give A=B=0, and STORE gives D[10]=0. At the fifth instruction, JZ, PC first increases to 5 and then changes to 0. All relevant state is identical to its initial state, so the same five instructions repeat forever and HALT at I[5] is never reached.

Misconception and counterexample

Each executed instruction takes one clock cycle, and execution must eventually reach the end of the instruction table.

No clock duration is defined in the paper model. Also, the 0+0 input returns to its initial state after five instructions without reaching HALT. ISA-level effects, actual circuit timing, and termination are different questions.

Check your understanding

What is D[10] immediately after ADD, before STORE?

Show answer and reasoning

0.

ADD changes only A; the separate STORE that writes data memory has not yet executed.

Does PC accumulate the number of executed instructions?

Show answer and reasoning

No.

It identifies the next instruction position, and a branch can return to an earlier position.

If D[8]=250 and D[9]=6, what are A after the first ADD and the result of the subsequent JZ?

Show answer and reasoning

A becomes 0, and JZ returns PC to 0.

(250+6) mod256=0. The integer sum 256 differs from the stored value 0, and this input also never reaches HALT.

Explore further

Further study: Fix initial D[8]=x and D[9]=y in 0–255, with D[10]=0. If s=(x+y) mod256≠0, no branch is taken and the machine halts in six steps. If s=0, the LOADs in each iteration set A=x and B=y, ADD sets A=0, STORE sets D[10]=0, and JZ sets PC=0. The boundary state is identical after the first iteration, so induction establishes infinite repetition. A finite state space alone does not imply termination. The argument is that, for a deterministic machine with no external changes, repetition of the same nonhalted state also repeats the subsequent path.

Subtopic 3.2

Memory and Storage

Why might a value that was computed and displayed disappear when you reopen it after turning off the power?

Preparation and learning goals

Preparation

  • Address and contents: an address identifies a cell, while its contents are the value stored there. If cell 4 contains 52, address 4 and contents 52 are different values.
  • Bytes and bounds: here, 1 byte=8 bits, and B consecutive cells have addresses 0 through B−1. An out-of-bounds access is not a valid operation in this paper model.
  • Lifetime of state: existing during computation, existing after program termination, and surviving power loss are different requirements.
  • A word is a unit of data handled as one group by a machine; its size depends on the machine and its contract. We do not assume that addresses in this byte array have the same unit as instruction-table row numbers in the first topic.

Learning goals

  • Interpret address units, capacity, and byte order together with their conditions.
  • Distinguish working storage from persistent storage.
  • Separate cache behavior from the guarantees of completed storage.

Specify what an address identifies

Memory can be modeled as a collection of storage cells accessed by address. To calculate capacity, specify whether one address identifies a byte or a word. An n-bit address gives 2ⁿ distinct address patterns, but this does not mean that every pattern maps to actual RAM. Virtual addresses provided by an operating system and physical memory locations are also different layers. Here we use a contiguous byte array without modeling mappings.

In a 16-byte array D, addresses 0–15 are valid. Storing a two-byte item starting at address a requires both a and a+1 to be in bounds, so 0≤a≤14. A four-bit address label alone does not permit reading two bytes starting at address 15. Address, size, alignment, and permissions are separate conditions to check for actual access.

A contract for reading several bytes as one value

When the same two bytes represent a 16-bit unsigned integer, little-endian places the least significant byte at the lower address, whereas big-endian places the most significant byte there. For example, 0x1234 has value 1×4096+2×256+3×16+4=4660. Placing 0x34 and 0x12 at addresses 4 and 5 in little-endian order reconstructs the value as 0x34+256×0x12.

Byte order differs from the order in which bits are written or displayed within a byte and from the rule for representing signed numbers. With the same 0x34/0x12 at addresses 4/5, big-endian interpretation gives 0x3412=13330. File and communication formats can define their own byte order. Address 4 alone does not mean the value 4660: the two bytes beginning there and the reading contract are also required.

Access speed and persistence are separate dimensions

Registers, caches, main memory, and storage devices have different roles. Ordinary DRAM main memory does not retain values when power is lost, so keeping working data for longer requires a persistent storage path, such as a storage device and file system. Even if a file is on a storage device, a program reads the required data into an appropriate working area to compute with it. We do not assert that all memory is volatile.

A cache keeps a nearby copy of data to help repeated access. A read-cache hit rate and survival after power loss answer different questions. Acceptance of a file-write request or a saved message on screen does not establish that every copy has been durably recorded. Check delayed writes, errors, and the completion contract. Nonvolatile media also guarantee neither everlasting integrity nor a backup.

A worked example, step by step

Store 0x1234 starting at address 4 in little-endian order in our contiguous 16-byte memory. In the read-cost model, a cache hit costs 2 units and a miss costs a 2-unit check plus 40 units for lower-level memory. Fix 100 accesses as 80 hits and 20 misses, with no overlapping accesses. Find the stored bytes and total cost.

  1. Store 0x34=52 at address 4 and 0x12=18 at address 5. Both addresses are within 0–15, so this is valid in the model.
  2. Reconstruction gives 52+256×18=4660. Reading the same bytes as big-endian gives 52×256+18=13330, a different value.
  3. The 80 hits cost 80×2=160 units, and the 20 misses cost 20×(2+40)=840 units. A miss costs 42, including the check, rather than just 40.
  4. The total is 1000 units, averaging 1000/100=10 units per access. Whether 0x1234 survives power loss is a separate question from this read cost.

D[4]=52 and D[5]=18, giving little-endian value 4660. The total cost is 1000 units and the average is 10 units. These are calculations in a fictional read model, not actual nanosecond measurements or a persistent-storage experiment.

Try it with paper and the lesson

Is it valid to read a two-byte item starting at address 15 in the same byte array? If there are 50 hits and 50 misses, what is the average in the same cost model?

Show hint

The last address is starting address+size−1. The miss cost includes the 2-unit check.

Show solution

The required addresses are 15 and 16; address 16 is out of bounds, so the access is invalid. The cost is 50×2+50×42=2200 units, averaging 22 units. A lower hit rate raises this cost but does not itself change the guarantees of persistence.

Misconception and counterexample

Address bit width alone determines physical RAM capacity, and a cached value means storage has completed.

An address pattern may identify a device or an unmapped region rather than RAM, and address units can differ. A value in this read cache carries no contract that it survives power loss. Acceptance of a write, durable recording, and backup are separate requirements.

Check your understanding

Under the additional condition that every 8-bit address pattern maps to a distinct one-byte RAM cell, what is the capacity?

Show answer and reasoning

256 bytes.

2⁸ addresses×1 byte/address. Mapping every address to RAM and specifying the unit are necessary conditions.

If addresses 4/5 hold 34/12 in hexadecimal, what is their big-endian 16-bit unsigned value?

Show answer and reasoning

0x3412=13330.

Reconstruct it as 0x34×256+0x12=52×256+18.

Does an average read cost of 10 units prove that a file survives power loss?

Show answer and reasoning

No.

The read-cache cost model has no contract for durable writes or failure recovery.

Explore further

Further study: With hit fraction h∈[0,1] and the costs above, the average is E=2h+42(1−h)=42−40h. For 100 accesses, only fractions in increments of 0.01 are attainable. E≤12 requires h≥0.75, so at least 75 accesses must hit. Actual parallel access, queueing, or overlap between a miss and other work can invalidate this simple sum as a total-time model. Also, placing an item of positive integer size k bytes at address a in a contiguous B-byte array requires both 0≤a and a+k≤B. These are bounds conditions; they do not automatically guarantee alignment, permission, or initialization.

Subtopic 3.3

Input/Output and Hardware Layers

While you enter a value on a keyboard and save it to a file, which work does the CPU do directly, and which work does it delegate?

Preparation and learning goals

Preparation

  • Interface: specified requests, responses, and conditions that another component can use. An interface need not expose every implementation detail.
  • Completion and success: request acceptance, work completion, success, and the desired user outcome are different states. A completed operation can still have an error.
  • Overlap: work using different resources can progress during the same time interval. This does not mean that two tasks use the same CPU simultaneously.

Learning goals

  • Connect the responsibilities of applications, the operating system, drivers, and devices.
  • Distinguish the different roles of polling, interrupts, and DMA.
  • Trace completion, errors, and overlap using a step-by-step path and explicit timing assumptions.

I/O crosses several contracts

I/O involves data movement and control between programs and external devices. For a file-save request, an application uses a file interface, operating-system file/block layers construct the relevant requests, and a device driver handles a particular device’s control contract. Controllers and devices perform the actual transfers and work. Not every device follows the same file path, but distinguishing responsibility and errors at each boundary is useful.

The CPU, memory, and I/O devices interact through connections. Systems use hierarchies or multiple connections according to cost and performance needs; a simple bus diagram in a textbook is not the fixed layout of every actual computer. Even with memory-mapped I/O, or MMIO, accessing a device register as a memory address does not make that address ordinary RAM. Side effects, permissions, and ordering must follow the device contract.

Checking state and moving data are different work

Define our device states as READY→BUSY→DONE or ERROR. Submit data and a command while READY; acceptance moves it to BUSY. We assume that the single request slot is not overwritten while BUSY. DONE means successful completion of device work; ERROR means failure. The driver associates the state with the request, checks it, and reports the result upward. These four names and policies define a paper device, not a universal standard for actual devices.

Polling repeatedly reads state with the CPU. An interrupt notifies the CPU of an event and transfers its control flow to a handler. Even after notification, the request identity and any error must be checked. Direct memory access, or DMA, delegates data copying between a device and memory; it is a different dimension from the completion-notification method. It does not eliminate CPU setup and handling costs, and not all I/O uses DMA or interrupts.

Check both the path and its timing

Issuing a save request in higher-level code does not establish that the device’s DONE has been observed. The precise guarantee of DONE also depends on the device and call contract. The paper example assumes no external power failure and one request that succeeds after a specified time. We do not automatically extend this success to persistence after power loss or correctness of the user’s contents.

With fixed CPU checking costs and device work durations, we can compare time spent polling with time available to overlap independent computation. For a fast device, however, interrupt setup and handling costs can be higher. The names interrupt notification and DMA alone do not prove that a method is always faster. Specify which resources are occupied, whether there is useful work during the wait, and the cost of checking completion.

A worked example, step by step

Our device is READY, with no errors or external failures. CPU setup occupies 0–1 ms; after acceptance, device work runs during 1–6 ms. Completion checking and handling uses the CPU for 1 ms during 6–7 ms. Independent CPU computation takes 3 ms. Method P polls continuously during 1–6 ms, preventing other computation. Method I performs independent computation in that interval. All costs are fixed, and independent computation cannot run during setup or handling.

  1. In both methods, setup ends at 1 ms and request acceptance changes READY→BUSY. The device works for 5 ms during 1–6 ms and becomes DONE at 6 ms.
  2. P uses 0–1 ms for setup, 1–6 ms for polling, 6–7 ms for handling, and 7–10 ms for independent computation. Both tasks finish at 10 ms, and CPU occupied time is also 10 ms.
  3. I performs setup during 0–1 ms, then independent computation during 1–4 ms. During 4–6 ms the CPU is idle and only the device works. After notification checking and handling during 6–7 ms, both tasks finish at 7 ms. CPU occupied time is 1+3+1=5 ms.
  4. The 5 ms of device work did not decrease in either method. Overall completion changing from 10 to 7 ms and CPU occupancy changing from 10 to 5 ms are different comparisons. The fictional I model includes all additional notification and checking costs in the specified 1 ms.

Under these assumptions, P finishes both tasks at 10 ms and I at 7 ms. CPU occupied times are 10 ms and 5 ms. These are not measurements of actual device performance or interrupt latency.

Try it with paper and the lesson

If the device reports ERROR rather than DONE at 6 ms, may the result be reported as successful? In a separate successful-schedule example, independent computation takes 8 ms, with the same setup, device, and handling conditions. Assume I can pause its computation at 6 ms and resume at 7 ms. Find when both tasks finish.

Show hint

During 1–6 ms, perform 5 ms of computation, then perform the remaining 3 ms after handling. An error is a result state, separate from completion time.

Show solution

ERROR is failure, so associate it with the request and report the error rather than success. In the successful 8 ms computation example, I performs setup during 0–1 ms, 5 ms of computation during 1–6 ms, handling during 6–7 ms, and the remaining 3 ms of computation during 7–10 ms. Both tasks finish at 10 ms. P computes for 8 ms after handling ends at 7 ms, finishing at 15 ms. The error case and the successful schedule are separate assumptions.

Misconception and counterexample

An interrupt means success, and DMA means the CPU does no work.

An ERROR notification can also arrive through an interrupt, so the state and request must be checked. DMA still requires setup of locations, sizes, permissions, and related details, as well as completion/error handling. A notification method proves neither a valid result nor zero CPU cost.

Check your understanding

Does reading an MMIO address always read a byte of ordinary RAM?

Show answer and reasoning

No.

It can refer to a device register, with different side effects, permissions, and ordering rules.

In the 3 ms independent-computation example, how long is the CPU occupied within I’s total 7 ms?

Show answer and reasoning

5 ms.

Setup 1+independent computation 3+handling 1; the CPU is idle during 4–6 ms.

Are polling, interrupts, and DMA all choices along the same dimension?

Show answer and reasoning

No.

The first two concern checking state or events; DMA concerns delegating data movement.

Explore further

Further study: Let fixed setup p≥0, device work d≥0, completion handling h≥0, and independent CPU computation c≥0 all use the same time unit. P monopolizes the CPU while the device works and computes afterward, so Tₚ=p+d+h+c. I overlaps device work and computation and can pause and resume computation at the completion-handling time, so Tᵢ=p+max(d,c)+h. If c≤d, computation finishes first and waits for the device. If c>d, the remaining c−d is performed after handling; the same formula follows. The difference is Tₚ−Tᵢ=d+c−max(d,c)=min(d,c). Include additional implementation costs or disallow computation interruption, and the formula must change. This overlap model does not account for an actual scheduler, shared-memory contention, or a flood of notifications.
