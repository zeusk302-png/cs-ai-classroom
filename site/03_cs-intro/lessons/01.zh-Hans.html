小节 1.1

输入、处理与输出

让计算机找出三个朋友的最高分时，如果两个人并列，它也会自动决定显示谁的名字吗？

预备知识与学习目标

预备知识

  • 判断 7 > 4 是否成立。如果不熟悉大小比较，可以先看数轴：位置越靠右，数越大。
  • 按顺序逐行执行规则，并在纸上写下当前值。可以把变量理解为与当前值关联的名字。

学习目标

  • 说明输入的类型、允许的取值，以及输出代表什么。
  • 逐步追踪三个数取最大值的过程，检查并列情况和负数反例。
  • 解释人们想达到的目的为什么可能不同于实际规定的计算。

把目标写成明确的计算约定

“告诉我谁表现最好”对人来说也不明确。“最好”指分数最高，还是最努力？并列时如何显示？本小节只允许输入三个整数 a、b、c，输出它们的最大整数 m。如果还要返回某个人的名字，就需要另一份规格说明。规格说明在实现之前规定输入与结果之间必须满足的关系。

用数学语言表示，输入域 D 是 Z³，即整数有序三元组 (a,b,c) 的集合。输出 m 必须是 a、b、c 中的一个，并且不小于其中任何一个。我们假定整数可以比较，表示范围足以覆盖允许的值。“missing”这样的字符串或缺失值不属于 D。实际产品还必须说明：遇到这些输入时是拒绝，还是用另一类结果处理。

区分输入、处理与输出

输入是提供给计算的数据。处理按照规则操作数据和当前状态。输出是交给用户或另一项计算的结果。一开始就给出答案，并不能解释如何找到最大值。确定过程以后，可以在纸上追踪同一输入：先令 m=a；如果 b 更大，就更新 m；再以同样方式比较 c。

返回一个值和显示一个值是不同的。如果最大值函数返回 8，而调用它的程序显示 6，就可以分别调查计算过程和显示过程。并非每个程序都在一次输入和输出之后结束。游戏和服务器不断响应输入事件与状态变化，因此它们的输入—处理—输出图还需要当前状态和下一状态。

用一个小的不变式说明正确性

第一次比较前，m=a，是目前看过的一个数中的最大值。比较 b 后，m 保留这两个数中较大的值。再比较 c，m 就保留三个数中的最大值。在处理过程的指定位置始终保持的性质称为不变式。“m 是已经看过的数中的最大值”把初始化、更新和终止联系起来，比碰巧通过几个例子更能说明正确性。

如果输出只是数值，严格比较 > 可以正确处理并列。但如果还要返回最大值的位置，保留较早的位置和改为最后的位置是不同的并列规则。对全是负数的输入，令 m 从 0 开始也不正确：它可能返回并不属于输入的 0。从实际输入值开始，可以避免这个反例。

m ← a
if b > m: m ← b
if c > m: m ← c
return m  // 伪代码，不是执行结果

逐步推导的例题

对三个整数 (-4,-1,-1)，只返回最大值，不返回任何并列最高分者的名字。

  1. 初始化 m=-4。目前看过的值是 [-4]。
  2. 比较 b=-1 和 m=-4。因为 -1>-4，更新 m=-1，它是 [-4,-1] 的最大值。
  3. 比较 c=-1 和 m=-1。-1>-1 不成立，所以保持 m=-1。
  4. 检查 m 确实是一个输入值，而且不小于三个输入中的任何一个。

最大值是 -1。两个输入达到相同的最大值，但输出是一个数值。这个过程进行了两次比较。

用纸笔和正文动手试一试

在卡片上写 8、8、3，追踪同一过程。然后扩充规则，同时返回最大值最早出现的位置。位置从 1 开始计数，并列时选较早的位置。

查看提示

在保存 m 的同时保存位置 p。只有找到严格更大的值时，才一起更新 m 和 p。

查看解答

从 (m,p)=(8,1) 开始。第二个 8 并不更大，因此两者都保持不变；第三个数 3 也不改变它们。结果是 (8,1)。如果把 > 改成 >=，每次都更新位置，并列就会把 p 改为 2，违反约定。

常见误解与反例

只要要求计算机找出“最好的”，它就会自动理解我们的目的。

分数最高和最努力是不同的关系。输入没有努力程度的信息，就没有依据比较努力程度。并列时选择哪一个人的规则，也必须由人决定。基于学习的系统仍然需要输入、目标和评价标准；它们的输出不会自动保证满足规格说明。

检查理解

三个分数 4、9、2 与“最大值是 9”这句话中，输入和输出分别是什么？

查看答案与理由

输入是 4、9、2；输出是 9。

规则接收三个数，返回比较结果。

对输入 -7、-2、-5，如果 m 从 0 开始，会出什么问题？

查看答案与理由

过程会错误地返回 0。正确结果是 -2。

0 不是输入值，而且初始化时 m 就不是已看过的值中的最大值。

规格只返回一个数值时，6、6、6 是无效输入吗？

查看答案与理由

不是。输出是 6。

并列不会阻止最大值存在。选择一个人是另一个问题。

进一步探索

把过程扩展到 n 个整数。对 n≥1，先用第一个元素初始化，再把其余每个元素各比较一次，共 n−1 次比较。写出归纳说明：处理完 k 个元素后，m 是这 k 个元素中的最大值。空列表没有第一个元素，无法沿用同样的初始化。必须禁止空输入，或另行引入“无结果”值。

小节 1.2

问题分解与抽象

设计班级图书借阅服务时，需要记录每本书封面的颜色吗？

预备知识与学习目标

预备知识

  • 区分输入与结果。在“给定图书标识，报告这本书能否借阅”中指出两者。
  • 按顺序应用规则，并能把一个步骤的结果作为下一步骤的输入。

学习目标

  • 区分问题分解与抽象，并写出简单的模块约定。
  • 构造反例，说明丢弃必要信息会导致什么问题。
  • 解释连接各部分的规格说明能实现整体目标所需的条件。

分解划分职责

把图书借阅当成一个大任务，会混合会员检查、图书查找、可借判断和记录保存。问题分解将它划为职责明确的小任务。“检查会员”接收会员标识并返回是否有效；“查找图书”接收图书标识并返回当前状态。记录各任务的输入、输出和失败结果，有助于找到需要修改的部分。

部分越小并不一定越好。如果划分某项职责使多处必须共同更新同一状态，连接关系反而可能更难管理。本单元先假定一个人依次处理请求，没有并发借阅。实际服务中两个用户同时借同一本书时，还需要单独设计，避免可借检查与记录更新之间的竞争。

抽象保留实现目的所需的信息

抽象建立情境模型，保留目标问题需要的区别，隐藏其他细节。判断能否借书时，图书标识和是否已借出重要，封面颜色通常不重要。颜色不同但借阅状态相同的书被同等处理，并不会改变答案。但按封面颜色搜索的服务不能丢弃颜色。抽象是否适用，取决于目的。

更准确地说，令 A(r) 表示现实状态 r 的模型。如果 A(r1)=A(r2)，但 r1 和 r2 所需的答案不同，只使用这个模型的计算就不可能始终给出正确答案。这个反例说明模型丢失了必要区别。关键是识别并保留会改变答案的差异，而不是保存现实中的所有细节。

检查小任务之间的约定

本例只有在会员有效、图书存在且尚未借出时才批准借阅。若 memberOK、bookExists 和 loaned 都是布尔值，批准条件为 memberOK AND bookExists AND NOT loaned。如果具体实现不能读取不存在图书的 loaned 状态，bookExists=false 的路径就必须在读取前结束。要区分“所有逻辑输入都存在”的假设与实际查找数据的顺序。

各任务分别正确，约定不匹配时，整体仍可能出错。例如图书查找返回“未找到”，下一任务却把它解释成“空的，所以可借”。接口是关于含义和允许状态的共同约定，不只是函数名称。后续数据结构课程区分这种约定与内部表示，软件工程课程则处理模块间的变更与验证。

逐步推导的例题

会员 M 有效。图书 B17 存在且 loaned=true。请求依次处理，不考虑预约与逾期规则。判断是否允许借阅。

  1. 会员检查模块：M→memberOK=true。
  2. 图书查找模块：B17→bookExists=true，loaned=true。
  3. 判断：true AND true AND NOT true = true AND true AND false = false。
  4. 返回拒绝，保持借阅记录不变。

拒绝借阅。会员有效只是条件之一，单凭它并不足以批准。

用纸笔和正文动手试一试

图书 A 存在但已借出，图书 Z 不存在。如果模型只保留一个“不可借”状态，能区分拒绝原因“已借出”和“未找到图书”吗？写出保留必要信息的模型。

查看提示

检查合并到同一模型状态的两种现实情况，是否需要不同答案。

查看解答

不能区分：两个现实状态被合并，但要求的原因不同。保留 NOT_FOUND、ON_LOAN、AVAILABLE 三种状态可以保留区别。判断这些拒绝原因仍不需要封面颜色。

常见误解与反例

抽象丢弃的细节越多，就一定越好。

丢弃是否已借出的状态，可能错误地批准每一本存在的图书。标准是目的所需的区别是否保留，而不只是存储的信息是否更少。分解与抽象有关，但划分任务职责和减少信息中的区别，是不同的操作。

检查理解

把会员检查和图书查找分别设为任务，称为什么？

查看答案与理由

问题分解。

把不同职责的任务分开，再连接起来。

按本例规则，会员有效、图书存在且未借出时，结果是什么？

查看答案与理由

批准借阅。

三个必要条件都满足。不能悄悄加入本例已排除的逾期或预约规则。

丢弃封面颜色总是安全的吗？

查看答案与理由

不是。按颜色搜索的服务不能这样做。

模型会丢失影响答案的颜色区别。

进一步探索

增加“每位会员最多借三本书”的限制。在模型中加入当前借阅数，在批准条件中加入 count<3。如果两个并发请求都读到 count=2，可能都获准，导致总共借出四本。解释为什么顺序模型的正确性不会自动适用于并发模型。操作系统与数据库课程将进一步讨论并发控制的实现。

小节 1.3

计算机科学领域地图

点击图书搜索按钮后，结果显示得很慢。只学习一种编程语言，就能解释并解决问题吗？

预备知识与学习目标

预备知识

  • 理解输入、处理和输出，把例子重新表述为：书名输入→搜索→结果列表。
  • 知道一个服务有多项职责，分别考虑它的界面与保存的记录。

学习目标

  • 按研究的问题和职责区分计算机科学的主要领域。
  • 沿多个层次追踪同一个服务，并说明假设。
  • 选择需要检查的证据，避免只凭症状断定原因。

语言是工具，领域围绕问题组织

C 和 Python 是表达并执行过程的工具。计算机科学不只是编程语言课程的集合。算法分析研究哪些过程正确、需要多少工作；数据结构研究如何组织数据以及支持哪些操作；计算机体系结构研究硬件如何执行指令；计算机系统研究程序员如何理解这种执行并降低成本。一种语言可以用于许多领域。

操作系统研究程序如何共享 CPU 时间、内存和设备。网络研究计算机之间的通信。数据库研究存储数据的查询与一致性维护。软件工程处理需求、变更、测试和协作。人机交互研究帮助人实现目标的界面。这些边界用于组织课程重点；现实问题常常横跨多个领域。

跟着一个按钮穿过各层

搜索界面可能接收书名字符串并构造请求，网络将请求送到服务器，服务器搜索存储数据，再返回结果供界面显示。这是示意性的网页搜索服务模型。并非每个程序都有服务器：离线图书目录没有网络步骤。应先确认具体情境的结构，而不是自动加入熟悉的层次。

结果慢可能有多种原因。搜索过程可能比较了过多项目，传输等待、磁盘读取或界面渲染也可能耗时。凭“Python 很慢”的猜测更换语言，证据不足。分别观察各阶段的时间，才能缩小接下来调查的范围。必须区分测量与估计。

连接理论、实现与人的判断

理论领域形式化地研究可计算性、逻辑、正确性和复杂度。人工智能包括从数据中学习规则或预测模型，性能评价也涉及概率与统计。即使模型能推荐“你可能喜欢的书”，也不会自动解决同意、隐私或无障碍问题。需求和评价标准仍由人选择。

在这些课程中，选择适合自己准备程度的入口，同时明确简化问题时使用的假设。在纸上比较搜索步骤，是检查算法的一部分；测量真实服务器的运行时间，则提供不同的证据。不能把小模型中成立的事实变成整个产品性能或安全性的保证。本单元提供地图，后续课程再深入定义、证明与实现。

逐步推导的例题

假定一个示意性的顺序搜索服务中，请求传输 20ms、服务器搜索 70ms、响应传输 20ms、显示 10ms。没有重叠或重试。这些是假想的观测值。

  1. 总时间是 20+70+20+10=120ms。
  2. 假定服务器搜索从 70ms 降至 35ms，其他阶段保持不变。
  3. 新的总时间是 20+35+20+10=85ms。
  4. 搜索阶段的速度提高到原来的两倍，但整体加速比是 120/85=24/17≈1.41。

总时间减少 35ms。改进搜索这一候选瓶颈，并不会让整体速度翻倍。这些数值是假想数据，不是真实服务的测量结果。

用纸笔和正文动手试一试

对“找到了错误的书”“服务器有结果但界面为空”“能看到其他用户的借阅记录”三种症状，分别指出一个调查边界和一项需检查的证据。

查看提示

区分查询输入、服务器响应、界面状态和用户权限。一种症状可能有多种原因。

查看解答

第一种：比较输入字符串与服务器查询结果，调查搜索和数据质量。第二种：比较响应内容与显示状态，调查界面处理。第三种：检查请求用户、访问判定和返回记录，调查安全与数据边界。这些是调查起点，不是已证实的原因。
