소단원 5.1

변수와 상태

x=y 다음에 y=x를 쓰면 두 값이 서로 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 변수 이름은 현재 값을 가리킨다. 여기서는 내장 int 값만 다루며 x3/y5는 이름 x의 현재값 3, 이름 y의 현재값 5를 뜻한다.
  • 대입 x=y는 그때 y가 가리키는 값을 읽고 x의 결박을 바꾼다. 수학의 대칭적인 등식과 다르며 x==y는 같은지 비교하는 식이다.
  • 상태표는 명령을 읽기 전후에 각 이름과 현재값, 다음 수행 위치를 적는 추상 기록이다. 실제 물리 주소나 모든 런타임 상태를 나타내는 표는 아니다.

학습 목표

  • 대입의 우변 읽기/좌변 결박과 명령 순서를 추적한다.
  • 잘못된 교환에서 사라지는 초기값을 찾고 임시 저장으로 수정한다.
  • 이름표·값·객체 변경의 차이와 정수 모형의 한계를 설명한다.

같은 기호를 다른 규칙으로 읽지 않기

Python x=x+1은 오른쪽의 현재 x로 더한 값을 계산한 뒤 이름 x에 그 값을 결박한다. 수학 등식x=x+1의해를 구하는 일이 아니다. x가아직 정의되지 않았다면오른쪽 이름을 읽는 순간 실패할 수 있다. 이름의 현재값과 언제 결박되었는지를 먼저 확인한다.

정수 3은 이 예시에서 가변 저장 상자가 아니다. x=3,y=x 뒤에 x=4로재대입하면y가자동으로 4가 되지 않는다. 같은 객체를 가리키는 이름이 있을 수 있지만이름 재결박은 그 객체 자체를 수정하는 일과 다르다. 목록 항목 수정·별칭은 컬렉션 단원에서 따로 다루며 이 정수 사례를 그대로 일반화하지 않는다.

현재 상태를 다음 줄로 넘기기

코드를 위에서 아래로 순차 실행하는 이 예시에서는 한 줄의 사후 상태가 다음 줄의 사전 상태다. 초기 x3/y5에서x=y를하면 x5/y5다. 이어 y=x는 초기 x3이 아닌 현재 x5를 읽는다. 따라서 x5/y5가 되어 교환하지 못한다.

초기 x값을 나중에 쓰려면 덮어쓰기 전에 다른 이름에 보존한다. temp=x;x=y;y=temp를각각 한 줄로 수행하면temp3,x5,y3이된다. Python의x,y=y,x는우변 두 값을 먼저 평가하는 별 문법이다. 두 독립 대입x=y;y=x와같다고 읽으면 안 된다.

관찰할 상태와 입력 계약

표에 원하는 결과 이름만 적는다면 그 표로 모든 부작용을 확인했다고 주장할 수 없다. 실제 상태에는 열린 파일, 공유 객체, 출력 등도 포함될 수 있다. 이 예시는 미리 정한 내장 정수 두 개, 순차 실행, 외부 입력/동시 변경/예외 없는 정상 연산을 가정한다.

종이에 읽기 전 값과 읽기 후 값을 따로 적으면 같은 이름의 덮어쓰기를 볼 수 있다. 마지막 print는 최종값을 읽으며 이전 상태를 복원해 주지 않는다. 이름을 의미 있게 짓고 복잡한 식의 중간값을 기록하면 잘못 읽은 곳을 더 쉽게 찾을 수 있지만 가독성만으로 모든 정확성이 보장되지는 않는다.

중간 과정을 따라가는 예제

다음 전체 코드가 초기 두 값을 교환하는지 추적하라. 

x = 3
y = 5
x = y
y = x
print(x, y)
  1. x=3으로 x를 결박하고 y=5로 y를 결박한다. 두 대입 후 상태는 x3/y5다.
  2. x=y의 우변은 현재 y5다. x를 5로 재결박하므로 상태는 x5/y5다. 초기 x3은 이름 x에 남지 않는다.
  3. y=x의 우변은 현재 x5다. y도 5가 되어 상태 x5/y5를 유지한다.
  4. print(x,y)는 5 5와 줄바꿈을 출력한다. 보존한 실제 코드도 같은 출력으로 종료했다.

최종 x5/y5로 교환 실패다. 처음 x3을 두 번째 대입 때 읽는다고 생각한 것이 오류다.

오해와 반례

x=y는 두 변수를 영구 연결하므로 나중에 x를 바꾸면 y도 같이 바뀐다.

이 정수 예시의 이름 재결박은 그런 자동 연결이 아니다. x3,y=x 후 x4는 y3을 유지한다. 공유 가변 객체 항목을 바꾸는 경우는 다른 계약이다.

심화: 내장 정수쌍 (a,b)의 이름값만 관찰할 때 잘못된 두 대입의 변환은 F(a,b)=(b,b)다. (3,5)와 (7,5)는 둘 다 (5,5)로 가므로 최종 쌍만으로 초기 첫 값을 복원할 수 없다. 임시 저장 교환은 관찰하는 쌍에 대해 S(a,b)=(b,a)이고 S(S(a,b))=(a,b)다. 정수 대입 정상 실행이라는 조건에서 순차 대입을 따라 논증한다. temp 이름까지 포함한 전체 상태나 공유 객체/외부 출력의 복원이 같다는 뜻은 아니다.

소단원 5.2

분기와 반복

코드는 줄 순서대로만 읽으면 충분할까, 다시 돌아가는 곳도 찾아야 할까?

준비 개념과 학습 목표

준비 개념

  • 분기는 조건에 따라 다음 실행할 묶음을 고른다. 반복은 조건을 다시 검사하여 같은 본문을 여러 번 실행할 수 있다. 들여쓰기로 본문 범위를 찾는다.
  • x%2는 내장 정수 x를 2로 나눈 나머지다. 이 단원 x는 비음수이므로 짝수이면 0, 홀수이면 1이며 0도 짝수다.
  • N은 내장 정수 N≥0인 상한이다. x0,total0으로 시작해 0≤x<N인 값 중 짝수만 더하는 정상 순차 실행을 가정한다.

학습 목표

  • 조건 검사·분기 본문·공통 갱신·재검사 순서를 찾는다.
  • 본문 0회와 끝값 제외의 경계 사례를 설명한다.
  • 누적 불변식과 진행량으로 결과 및 종료를 따로 논증한다.

실행 경로를 그려 읽기

if는 참이면 들여쓴 묶음을 실행하고 거짓이면 그 묶음을 건너뛴다. elif가 있으면 앞 조건이 모두 거짓일 때만 다음 조건을 검사하며 한 연쇄에서 첫 참 분기만 실행한다. 독립 if 여러 개는 각각 검사하므로 연쇄와 같다고 읽지 않는다.

while은 본문에 들어가기 전에 조건을 검사한다. 참이면 본문 후 다시 조건으로 돌아가고 거짓이면 반복 밖 다음 문장으로 간다. 따라서 코드 줄을 한 번씩 위에서 아래로 읽은 결과는 실제 반복 실행의 상태표가 아니다. 반복 횟수와 각 차례의 현재값을 기록한다.

모든 경로의 갱신을 확인하기

예시에서는 x<N이면 x%2==0을 검사한다. 짝수만 total에 더하지만 x=x+1은 if 묶음 밖/while 묶음 안이라 홀수에서도 수행한다. 이 공통 갱신이 짝홀 양쪽 경로에서 다음 x로 진행하게 한다. 들여쓰기 하나를 바꾸면 역할도 달라질 수 있다.

만약 x 갱신을 짝수 if 안에만 넣으면 x0을 처리해 1로 가고, 홀수 1에서는 분기도 갱신도 수행하지 않아 N5에서 진행이 멈춘다. continue도 뒤 갱신을 건너뛸 수 있고 break는 가장 가까운 반복을 종료한다. 잘못된 무한 반복을 실행할 필요 없이 이 상태 고정을 종이로 보일 수 있다.

예상 결과와 종료는 다른 질문이다

처리한 접두의 짝수 합을 total이 보관한다는 성질은 결과의 근거다. x가 매 차례 1 늘어나 N에 이른다는 성질은 종료의 근거다. 어느 하나만 주장하지 말고 둘을 따로 검사한다. 본 예시 N5에서는 방문값 0,1,2,3,4이며 조건 x<5는 5를 포함하지 않는다.

처음 N0이면 0<0이 거짓이므로 본문 0회, total0/x0이다. N1도 0만 방문하므로 합 0이지만 x1이며 본문 1회다. 같은 최종 합이라고 같은 경로/횟수는 아니다. 이 정적 분석은 고정 정수·정상 연산/충분한 자원·외부 변경 없음이라는 계약에서 성립하고 실제 장치나 모든 언어의 반복을 일괄 보장하지 않는다.

중간 과정을 따라가는 예제

0 이상 N 미만의 짝수를 더하는 전체 코드를 추적하라. 

N = 5
x = 0
total = 0
while x < N:
    if x % 2 == 0:
        total = total + x
    x = x + 1
print(total, x)
  1. N5,x0,total0으로 시작한다. x0에서 조건 참/짝수 참이므로 0을 더하고 x1이다. x1은 짝수가 아니라 합 0을 유지하고 x2다.
  2. x2에서 2를 더해 total2/x3다. x3에서는 합 2를 유지하고 x4로 간다. 홀수에도 공통 갱신한다.
  3. x4에서 4를 더해 total6/x5다. 다음 5<5는 거짓이므로 본문에 다시 들어가지 않는다.
  4. 반복 밖 print가 6 5와 줄바꿈을 출력한다. 보존 코드의 실제 실행도 같았다. 반복은 5회이고 짝수 누적은 0,2,4다.

합6, 최종 x5다. 끝값 5는 본문에서 방문하지 않는다.

종이와 본문으로 직접 해보기

같은 전체 코드의 N만 0과 1로 바꾼다고 종이에 가정하라. 각각 합/최종 x/본문 횟수를 구하고, N5에서 갱신을 짝수 if 안으로 옮기면 어디서 진행을 잃는지 보이라.

힌트 보기

첫 while 검사와 if 밖 공통 갱신을 구분한다. 합이 0이어도 방문 수는 다를 수 있다.

풀이 보기

N0은 합0/x0/0회, N1은 합0/x1/1회다. 잘못된 N5 갱신은 첫 x0→1 후 x1에서 짝수 조건 거짓으로 갱신도 없어 계속 x1이다. 활동/무한 반례는 실행하지 않았다.

오해와 반례

누적 합이 맞는 불변식이 있으면 그 반복은 반드시 종료한다.

갱신을 잃고 x1에 머무르면 그 접두의 합 0은 계속 맞을 수 있어도 종료하지 않는다. 결과 보존과 종료 진행은 별도 근거다.

자기점검

N5 예시에서 5도 더하는가?

소단원 5.3

함수와 호출 흐름

함수가 다른 함수를 부르면, 돌아올 위치와 지역 변수는 어디에 기록할까?

준비 개념과 학습 목표

준비 개념

  • def는 함수를 정의하며 본문을 당장 호출하는 것과 다르다. inc(5)는 함수를 호출하고 매개변수 v에 인수의 객체 참조를 결박한다.
  • return은 계산값을 호출자리로 반환한다. print로 화면에 보이는 문자와 반환값은 다른 관찰이다. 명시 return 없는 정상 함수 종료는 None을 반환한다.
  • 호출마다 별도 지역 이름을 추적한다. 여기서는 내장 정수·정상 순차 호출이며 공유 가변 객체/global/nonlocal/재귀/예외를 사용하지 않는다.

학습 목표

  • 함수 정의와 호출 순서 및 return 복귀 위치를 구별한다.
  • 같은 매개변수 이름을 쓰는 두 호출의 지역 상태를 분리한다.
  • 정수 지역 재결박과 호출자 변수/공유 객체 변경을 구별한다.

호출할 때 본문에 들어가기

def inc(v)의 본문은 함수를 만드는 정의 단계에서 바로 실행되지 않는다. 이름 inc가 함수 객체에 연결되고 inc(n)처럼 호출할 때 본문에 들어간다. 본문 들여쓰기 밖의 호출은 해당 위치에서 진행한다. 함수 이름이 아직 결박되지 않은 자리에서 호출하면 정의 순서와 이름 해석 문제가 생길 수 있다.

인수는 호출 전에 평가되고 호출된 함수의 매개변수 이름에 결박된다. Python에서 그 값은 객체 참조이며 전체 객체의 깊은 복사를 보장하지 않는다. 예시 정수 v=v+1은 지역 v를 새 정수값에 재결박하여 호출자의 이름 x를 바꾸지 않는다. 공유 가변 목록의 항목을 수정하는 경우는 다르다.

지역 표와 돌아갈 곳을 함께 쓰기

twice(n)는 a=inc(n)의 결과를 기다린다. inc의 지역 v가 n의 정수를 받고 1 더해 반환하면 twice의 a에 저장한다. 다음 return inc(a)는 두 번째 inc의 결과를 기다렸다가 그 값을 twice의 호출자에게 반환한다. 각 inc 호출은 같은 이름 v라도 별도 지역 결박을 가진다.

종이 호출표에는 함수명, 현재 매개변수/지역값, 다음 위치와 복귀할 자리를 쓴다. 호출 뒤 반환은 가장 최근 기다리는 호출자리로 진행하는 이 예시의 추상 제어 흐름이다. 이 표를 보고 특정 CPU의 실제 스택 메모리 배치·주소·ABI 규약을 측정했다고 주장하지 않는다.

반환과 부작용의 계약

inc와 twice는 본문에서 화면 출력을 하지 않으며 계산값만 반환한다. 최종 print(x,y)는 호출자가 유지한 x와 twice의 반환값을 읽는다. 화면에 값을 썼다고 자동으로 그 값을 return한 것이 아니고, return문 뒤 같은 정상 호출 본문의 다음 문장을 계속 수행하는 것도 아니다.

함수의 계약에는 허용 입력, 반환값, 외부 변경과 실패가 포함될 수 있다. 여기서는 정수 n을 받아 n+2를 반환하며 호출자 이름을 바꾸지 않는 정상 경로를 정한다. 모든 함수가 이 계약을 갖는 것은 아니다. 재귀는 같은 함수가 다시 호출되어 새 지역 상태를 갖는 구조지만 이 예시는 재귀가 없고 재귀 깊이/한계도 시험하지 않는다.

중간 과정을 따라가는 예제

inc를 두 번 호출하는 전체 코드의 호출 흐름과 최종 출력을 추적하라. 

def inc(v):
    v = v + 1
    return v

def twice(n):
    a = inc(n)
    return inc(a)

x = 5
y = twice(x)
print(x, y)
  1. 두 def가 inc/twice 이름을 함수에 결박한다. x5를 저장한 뒤 twice(x)를 호출하면 twice의 지역 n5다. y는 아직 계산 결과를 기다린다.
  2. twice의 a=inc(n)에서 첫 inc의 지역 v5를 받고 v6으로 재결박한다. return6이 twice로 돌아와 지역 a6이 된다. 호출자의 x5는 그대로다.
  3. twice의 return inc(a)에서 두 번째 inc의 지역 v6이 v7이 되어 7을 반환한다. twice도 그 7을 자기 호출자리로 반환하여 y7을 결박한다.
  4. 최종 x5/y7이며 print는 5 7과 줄바꿈을 쓴다. 보존 전체 코드의 실제 출력도 같다. 사용자 정의 inc는 두 번, twice는 한 번 호출됐다.

x는 5를 유지하고 y는 7이다. 두 번의 지역 v와 twice의 n/a를 별도 표로 추적해야 한다.

종이와 본문으로 직접 해보기

같은 코드에서 초기 x를 0으로 바꾼다고 종이에 추적하라. 별도로 inc의 return v만 지우고 같은 v=v+1 본문을 남긴다면 원래 twice(5)의 두 번째 inc는 어떤 입력을 받고 무엇이 문제인가?

힌트 보기

첫 호출 반환이 twice의 a다. 명시 return 없는 정상 종료는 None이다.

풀이 보기

원래 함수에서 x0이면 첫 inc1/둘째 inc2, 최종 x0/y2다. return 없는 변형은 첫 inc가 None을 반환해 aNone이고, 두 번째 inc에서 vNone에 1을 더하는 연산이 맞지 않아 TypeError다. 따라서 정상 최종 print까지 가지 않는다. 이 변형과 활동은 실행하지 않았다.

오해와 반례

함수의 매개변수에 재대입하면 언제나 호출자의 변수도 바뀐다.

정수 inc의 v 재결박은 호출자 x5를 그대로 둔다. 그러나 객체 참조를 받으므로 공유 목록 내용 수정이 호출자에게 보이는 경우도 있다. 이름 재결박과 객체 수정을 구별한다.
