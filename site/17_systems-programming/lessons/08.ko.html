소단원 8.1

익명 파이프와 FIFO

글자를 보낸 쪽이 끝났는데 읽는 쪽은 왜 계속 기다릴까?

준비 개념과 학습 목표

준비 개념

  • 프로세스와 fd

  • read/write

학습 목표

  • 끝점 참조와 EOF를 추적한다.

  • byte stream과 메시지 경계를 구분한다.

작은 쓰기가 원자적이면 같은 크기의 읽기도 메시지 하나일까?

새 Linux 종이 모형에서 서로 다른 writer A와 B가 각각 ABC와 xyz를 한 번의 성공한 write로 보낸다. 각 요청은 PIPE_BUF 이하이고 정상적인 blocking pipe이며 신호·오류·중간 종료가 없다고 정한다. 두 요청의 바이트가 서로 섞이지 않는 원자성은 보장하지만 어느 요청이 먼저인지까지 정하지 않는다. 주어진 순서 A 다음 B에서는 통로가 ABCxyz다.

소비자의 성공 반환 길이를 2,4로 따로 정하면 읽은 조각은 AB와 Cxyz다. 각 write의 원자성은 다른 writer가 중간에 끼어들지 않는 조건이지 read가 ABC와 xyz로 나누어 반환한다는 조건이 아니다. 세 바이트 고정 길이 프레임 규약이라면 조각을 누적하여 ABC와 xyz를 복원한다. 전송 조각의 길이와 응용 메시지의 길이를 다른 장부로 둔다.

같은 통로의 쓰기 끝을 부모 fd4, 자식 A의 fd4와 dup한 fd9가 보유하고 소비자는 이미 자기 쓰기 끝을 닫았다고 정한다. A가 fd4만 닫아도 fd9가 남으며, 부모 fd4도 닫기 전에는 EOF가 아니다. 모든 writer가 사라져도 남은 ABCxyz를 먼저 읽고 통로가 비었을 때 양수 크기 read가 0을 반환한다. 데이터 없음·writer 없음·요청 크기의 조건을 함께 확인한다.

별도 이름 있는 FIFO에서 nonblocking O_WRONLY open은 reader가 없으면 ENXIO로 실패한다. nonblocking O_RDONLY open은 writer가 없어도 성공할 수 있다. open의 연결 조건과 열린 뒤의 read/write 조건은 서로 다른 단계다. Linux의 O_RDWR FIFO 열기를 모든 POSIX 시스템의 해결책으로 일반화하지 않는다.

먼저 확인할 개념

  • dup된 fd와 열린 대상

    같은 쓰기 끝을 가리키는 추가 fd가 생존 조건을 연장함을 확인한다.

두 끝을 가진 바이트 통로

익명 pipe는 읽기와 쓰기의 두 fd를 만들고 fork로 상속된 끝점으로 관련 프로세스가 통신할 수 있다. FIFO는 파일시스템 이름으로 열어 다른 프로세스도 권한 조건 아래 연결할 수 있다.

이름과 생성/열기 방식은 달라도 열린 뒤 pipe/FIFO의 바이트 흐름 의미는 같다. FIFO 경로가 일반 파일처럼 메시지 내용을 영구 저장한다는 뜻은 아니다.

write 호출의 경계는 read 경계가 아니다

통로는 byte stream이다. 두 번 write한 문장이 read 두 번에 그대로 나뉜다고 보장되지 않아 길이·구분자 같은 자체 framing이 필요하다.

blocking 상태에서 빈 통로에 잠재 writer가 있으면 read는 기다리고 가득 찬 통로의 write도 공간을 기다릴 수 있다. 실제 capacity를 고정 상수로 믿지 않는다.

모든 끝점의 생존을 센다

데이터를 다 읽고 모든 쓰기 끝 참조가 닫혀야 EOF로 read가 0 을 반환한다. 생산자만 닫아도 부모나 다른 자식이 쓰기 fd를 보유하면 아직 잠재 writer다.

모든 읽기 끝이 닫힌 뒤 write는 SIGPIPE가 발생할 수 있고 무시하면 EPIPE로 실패한다. 끝점 정리와 오류 처리도 통신의 일부다.

쓰기를 실제 한 횟수와 쓰기 끝을 열어 둔 참조 수는 다르다. 표는 모든 read 끝을 닫지 않은 상태이며, 데이터를 아직 읽지 않았다면 마지막 행에서도 먼저 데이터가 반환된다.

중간 과정을 따라가는 예제

부모가 pipe의 read fd3/write fd4 를 만들고 자식 P와 C가 둘 다 상속했다. P는 ABC 세 바이트를 쓰고 종료한다. C는 읽고, 부모가 fd4 를 계속 보유한다. 다른 writer는 쓰지 않는다.

  1. 처음 write 참조는 부모/P/C에 하나씩이다. C의 불필요 fd4 를 닫고 P가 종료해도 부모 fd4 가 하나 남는다.

  2. C가 ABC를 모두 읽은 뒤 빈 통로를 다시 blocking read하면 EOF가 아니라 기다릴 수 있다.

  3. 부모도 fd4 를 닫으면 남은 writer가 0 이 되고, C의 다음 read는 EOF 0 을 반환한다.

ABC 소진만으로 EOF는 아니다. 전체 write 끝 참조 0 이 종료 판단의 핵심이다.

조건을 바꾸어 비교하기

원자성으로 read 경계를 추론한 오류

ABC와 xyz의 두 원자적 쓰기가 A/B 순서로 완료했고 read 반환은 2,4다. 조각과 고정 길이 프레임을 구하라.

  1. 바이트 흐름 ABCxyz에서 처음 둘은 AB, 다음 넷은 Cxyz다.

  2. AB를 남기고 Cxyz를 이어 ABC와 xyz를 세 바이트씩 꺼낸다.

조각 AB/Cxyz와 응용 프레임 ABC/xyz는 다르다.

비교할 점

같은 write 호출의 비혼합 보장을 수신 호출의 경계 보장으로 바꾸지 않는다.

쓰기 fd 하나만 닫은 생산자

위 표에서 부모 fd4까지 닫았지만 A의 fd9는 살아 있고 데이터가 소진됐다. 다음 양수 blocking read는?

  1. dup된 fd9도 동일한 쓰기 끝을 보유한다.

  2. writer가 남아 빈 통로에서 read는 대기할 수 있다. fd9도 닫고 다른 writer가 없어야 EOF다.

한 생산자의 일부 fd 정리만으로 EOF를 만들지 못한다.

비교할 점

종료라는 말을 실제 프로세스 종료와 부분 fd 폐쇄로 섞지 않는다.

소단원 8.2

dup2와 리다이렉션

프로그램은 stdout에 쓰는데 왜 화면 대신 다른 파일로 갈까?

준비 개념과 학습 목표

준비 개념

  • fd 표와 open file description

  • stdin0/stdout1/stderr2

학습 목표

  • fd 번호 교체와 데이터 복사를 구분한다.

  • dup2 의 동일 번호 조건을 처리한다.

두 복제의 순서만 바꾸면 stderr의 대상도 달라질까?

새 자식의 fd1과 fd2는 터미널 T, fd5는 일반 파일 F의 열린 대상 O를 가리킨다. O는 비 append이고 offset=0이며 모든 호출과 쓰기가 성공하고 다른 접근은 없다고 정한다. 계획 A는 dup2(5,1) 뒤 dup2(1,2), 계획 B는 dup2(1,2) 뒤 dup2(5,1)이다. 복제는 그 순간 oldfd가 가리키는 열린 대상을 새 번호에 연결한다.

A에서는 fd1이 먼저 O로 바뀌고 그 fd1을 fd2로 복제하므로 둘 다 O다. B에서는 옛 fd1의 T를 먼저 fd2에 복제하고 이후 fd1만 O로 바꾸므로 fd2는 T다. fd2가 fd1을 계속 따라가는 화살표를 만든 것이 아니다. 매 호출 경계의 대상 표를 그리면 별도의 셸 구문을 외우지 않고도 순서 효과를 확인할 수 있다.

A에서 fd1에 AB, 이어 fd2에 !를 쓰면 공유 O offset은 0→2→3이고 F는 AB!다. B에서는 F에 AB만 쓰여 offset=2이며 !는 T로 간다. 부모의 fd 표는 이 자식의 복제 호출 때문에 교체되지 않는다. 여기서 터미널 출력과 파일 지속성은 실제 측정하거나 수행한 것이 아니다.

FD_CLOEXEC는 fd별 플래그이고 파일 offset과 구별한다. oldfd5에 close-on-exec가 있어도 유효한 다른 번호 dup2(5,1)의 새 fd1은 이 플래그가 꺼진다. 성공 exec에서 fd5는 닫히고 fd1은 살아 있다. 반대로 처음부터 fd1에 같은 플래그가 있고 dup2(1,1)을 하면 no-op라 플래그도 남아 exec 때 fd1이 닫힌다. 이 대안은 권한 상승 없는 일반 Linux 프로세스에 한정한다.

번호를 같은 열린 대상으로 연결한다

fd는 프로세스 표의 번호이고 open file description은 열린 파일 상태를 나타낸다. dup2(oldfd,newfd)는 newfd가 oldfd와 같은 열린 대상을 가리키게 한다.

같은 대상을 가리키므로 파일 offset과 status flags를 공유한다. 기존 내용을 다른 파일에 복사하거나 파일 경로 이름을 바꾸는 작업이 아니다.

대상을 원자적으로 교체한다

newfd가 이미 열려 있다면 dup2 가 그 연결을 닫고 교체하는 단계를 원자적으로 수행한다. close(newfd) 뒤 dup(oldfd)를 따로 호출하면 중간에 다른 fd 할당이 들어올 수 있다.

호출 실패를 검사해야 하며 invalid oldfd면 대상은 닫히지 않는다. oldfd와 newfd가 같고 유효하면 아무 변화 없이 그 번호를 반환한다.

자식에서 연결 후 불필요 번호를 닫는다

셸의 출력 리다이렉션은 보통 자식의 stdout 번호 1 을 열린 파일이나 pipe write end에 연결한 뒤 프로그램을 exec한다. 자식의 fd 표 변경은 부모 표를 같은 방식으로 교체하지 않는다.

복제 뒤 원래 fd를 닫아도 새 stdout 연결은 남는다. 다만 원래 번호가 이미 1 이면 같은 번호를 무조건 close하면 방금 유지한 stdout을 닫으므로 분기해야 한다.

같은 번호의 close-on-exec 함정

fd1 자체에 CLOEXEC가 켜진 상태에서 dup2(1,1) 성공 뒤 일반 exec가 성공했다. fd1이 반드시 살아 있나?

  1. 같은 유효 번호의 dup2는 no-op다.

  2. 플래그를 바꾸지 않아 exec에서 fd1이 닫힌다. 필요하면 별도로 fd 플래그를 검사·수정한다.

no-op 성공은 exec 뒤 stdout 생존을 증명하지 않는다.

소단원 8.3

파이프라인과 자식 회수

첫 프로그램이 끝날 때까지 기다린 뒤 둘째를 시작하면 항상 작동할까?

준비 개념과 학습 목표

준비 개념

  • fork/exec/waitpid

  • pipe EOF와 capacity

학습 목표

  • 파이프라인을 동시에 시작해야 할 이유를 설명한다.

  • 모든 자식의 종료 상태를 회수한다.

세 프로그램의 연결을 만들다가 마지막 생성이 실패하면 무엇을 회수할까?

새 A|B|C 종이 모형의 P는 A→B 통로, Q는 B→C 통로다. 부모와 세 자식이 두 통로의 끝들을 상속한 성공 대안에서 A는 P쓰기만, B는 P읽기와 Q쓰기만, C는 Q읽기만 유지한다. 표준 번호로 복제한 연결은 그 자체가 끝을 보유하므로 원래 통로 번호만 닫았다고 끝이 없어지는 것은 아니다. 부모는 두 통로의 모든 끝을 닫는다.

P와 Q의 용량이 각각 3바이트인 가상 모형에서 A는 총 6바이트를 쓰고, B는 그대로 전달하며, C는 소비한다. A를 생성한 뒤 종료를 기다리고 B와 C를 아직 만들지 않으면 A는 처음 3바이트를 채운 뒤 남은 3바이트를 쓰면서 막힐 수 있다. B까지 만든 뒤 B의 종료를 기다려도 C가 없으면 Q가 찰 수 있다. 모든 단계를 먼저 시작하고 각 소비자가 실제로 진행하는 성공 사건에서는 두 통로의 backpressure를 해소한다. 이는 실제 Linux 통로 용량이나 스케줄러 공정성을 측정한 결과가 아니다.

실패 대안에서는 A와 B 생성까지 성공했고 C를 만드는 fork가 실패했다고 정한다. B는 자신의 Q 읽기 끝을 닫았고, A에도 Q 읽기 끝이 없도록 정리했다. 부모가 마지막 Q 읽기 끝을 닫으면 열린 읽기 끝의 수는 0이 된다. 이후 B의 write는 SIGPIPE 정책에 따라 종료되거나, 이 신호를 무시한 경우 EPIPE로 실패할 수 있다. 부모가 Q 읽기 끝을 계속 보유하면 읽기 끝이 존재하는 것으로 남아 B가 가득 찬 통로에서 기다리는 원인을 숨긴다.

실패한 C의 PID를 등록해서 wait하지 않는다. 이미 만든 A/B의 PID, 끝점 정리, 종료 요청과 실패 처리·실제 waitable 결과를 장부로 관리한다. 부모의 close만으로 모든 자식의 즉각 종료를 보장하지 않고 필요한 종료 정책을 따로 정한다. 정상 성공 대안에서는 자식401/402/403을 모두 회수해도 반환 파이프라인 상태를 마지막 명령으로 고르는 정책은 별도다.

먼저 확인할 개념
  • 모두 시작한 뒤 전체 자식 회수

    단계별 backpressure와 부분 생성 실패의 PID 장부를 확인한다.

  • 읽기 끝·쓰기 끝의 생존

    부모 잔여 끝이 EOF/EPIPE 조건을 바꾸는 이유를 추적한다.

통로를 연결하고 두 프로그램을 시작한다

A|B는 A stdout을 pipe write end로, B stdin을 read end로 연결한다. 각각 자식에서 dup2 를 검사하고 불필요 끝점을 닫은 뒤 exec한다. 실제 셸은 구문·인용·프로세스 그룹·신호도 처리해야 한다.

부모는 자식을 모두 시작한 후 자신의 pipe 끝점을 닫고 회수한다. 첫 자식 종료를 기다린 뒤 다음 소비자를 시작하면 통로가 찼을 때 생산자가 기다리며 진행하지 못할 수 있다.

실패 경로도 끝점을 정리한다

pipe/fork/dup2/exec가 실패하면 이미 만든 자식과 fd의 소유권을 확인하고 정리해야 한다. exec 실패 자식은 부모 셸 흐름으로 다시 들어가면 안 된다.

이 단원은 성공 경로와 가상 실패 표를 종이에 추적한다. 완전한 셸 구현·job control·신호 처리까지 구현되었다는 뜻은 아니다.

종료와 회수는 별도다

자식 종료 뒤 waitpid로 종료 정보를 얻고 회수해야 기본 정책에서 zombie가 남지 않는다. PID를 지정하면 어느 자식을 회수했는지 분명하다.

waitpid 성공 반환은 PID, WNOHANG에서 아직 종료 없으면 0, 오류는 −1 이다. EINTR는 상황에 따라 재대기하며 WIFEXITED가 참일 때만 WEXITSTATUS를 정상 종료 코드로 읽는다.

중간 과정을 따라가는 예제

교육용 pipe capacity=4 바이트, A는 읽는 쪽이 있으면 4 바이트씩 두 번, 총 8 바이트를 쓰고 종료, B는 전부 읽어 EOF 후 종료한다고 정한다. 셸이 A만 만들고 waitpid(A) 뒤 B를 만들면?

  1. A가 처음 4 바이트를 채우면 소비자가 없어 다음 쓰기가 공간을 기다릴 수 있다. 부모는 A 종료를 기다리므로 B 생성까지 못 간다.

  2. A/B 둘을 먼저 만들면 B가 소비해 공간을 비우고 A가 남은 4 바이트를 쓰고 닫을 수 있다. 모든 불필요 write 끝을 닫아야 B가 EOF를 본다.

  3. 자식 PID 101/102 가 각각 정상 코드 0/2 로 종료했다고 별도 주면 두 PID를 회수하고 WIFEXITED 조건 아래 코드를 읽는다. 마지막 명령 코드 정책을 선택한 셸의 파이프라인 상태는 2 다.

시작 전 대기가 가상 deadlock을 만든다. 모두 시작·끝점 정리·둘 다 회수하고 정한 상태 정책을 적용한다.

조건을 바꾸어 비교하기

두 통로 중간에서 기다린 셸

A와 B만 생성하고 C를 생성하기 전에 waitpid(B)를 호출했다. Q의 용량은 3바이트이고 B의 전달량은 6바이트다. 어떤 이력이 가능한가?

  1. B는 처음 3바이트를 Q에 넣고 남은 3바이트를 쓰려 하지만 소비자가 없다.

  2. 부모가 B 종료를 기다려 C 생성에 도달하지 못한다. A도 P의 상태에 따라 막힐 수 있다.

단순히 A와 B 두 명을 동시에 시작한 것만으로 세 단계 연결의 진행을 보장하지 못한다.

비교할 점

마지막 소비자까지 생성한 뒤 회수하는 구조와 실패 경로를 구별한다.

마지막 정상코드와 중간 신호 종료

성공 대안에서 401은 정상 코드 0, 402는 SIGTERM, 403은 정상 코드 0으로 종료했다. 기본 정책으로 세 PID를 회수하고 마지막 명령 코드 정책을 쓰면?

  1. 401과 403은 WIFEXITED를 확인한 뒤 코드 0을 읽는다. 402는 WIFSIGNALED를 확인한 뒤 SIGTERM을 기록한다.

  2. 모든 PID를 회수하되 선택한 정책의 파이프라인 반환은 403의 정상 코드 0이다.

선택한 반환 코드가 0이어도 모든 단계가 정상 성공했다는 뜻은 아니다. 신호로 종료한 자식에는 WEXITSTATUS를 적용하지 않는다.

힌트 보기

반환 PID와 아직 waitable하지 않은 0 을 구분한다.

풀이 보기

아니다. 아직 종료 상태가 없는 즉시 반환이므로 이후 다시 회수해야 한다. 종료코드 0 이라고 해석하지 않는다.

오해와 반례

마지막 자식만 기다리면 파이프라인 전체 자식은 자동 회수된다.

일반 기본 정책에서는 다른 종료 자식도 회수해야 한다. 반환할 파이프라인 상태를 마지막 명령에서 고르는 것과 회수 대상 전체를 줄이는 것은 다르다.

연습 1 · 값과 상태 예측

부모만 Q읽기 끝을 보유하고 B가 이미 세 바이트를 넣었다. C 생성은 실패했다. B의 다음 쓰기에 곧바로 EPIPE를 확정할 수 있나?

힌트 2

풀이와 답 확인

다른 문제에 적용하기

새 성공 모형 A|B|C에서 A가 ABC와 xyz를 각각 PIPE_BUF 이하의 한 성공 write로 이 순서로 보낸다. C의 read 조각은 AB와 Cxyz다. 중간 B는 바이트를 그대로 전송하며 프레임 길이 규약은 3바이트다. 두 프레임을 복구하고 부모가 P와 Q의 쓰기 복제 끝을 남겨 두면 EOF가 왜 막히는지 설명하라. 별도 출력 계획에서는 자식의 fd 1과 fd 2가 터미널 T를 가리키고, fd 5가 offset 0바이트인 열린 대상 O를 가리킨다. stderr는 원래 T에 두고 stdout만 파일 F로 옮긴다. 두 dup2 호출의 순서를 정하고 AB와 !를 stdout과 stderr로 차례로 쓴 뒤 F의 내용을 구하라. 마지막 단계 C의 생성이 실패하는 별도 대안에서 성공한 A와 B, 미생성 C를 구별한 회수 장부와 읽기 끝 참조 정리를 설계하라.

힌트 1

전송 조각·메시지·끝점 연결을 각각 다른 장부에 둔다.

힌트 2

복제하는 순간의 대상과 성공 생성한 양수 PID를 추적한다.

풀이와 답 확인

  1. AB를 누적하고 Cxyz를 이어 ABC와 xyz 두 프레임을 복원하며 잔여 길이는 0이다. 원자적 write 경계가 read 경계를 정하지 않는다.

  2. 부모의 모든 불필요 쓰기 복제 끝을 닫아야 소진 뒤 EOF 조건을 만족한다. 원본 번호만 닫아도 복제 끝이 남으면 조건이 실패한다.

  3. dup2(1,2)로 옛 T를 먼저 보존하고 dup2(5,1)로 stdout을 O로 바꾼다. 성공 후 원본 fd5를 정리하면 F에는 AB가 기록돼 offset은 2이며, !는 T로 간다.

  4. C 생성 실패는 PID 미등록이다. 부모와 자식의 Q읽기 참조를 점검하고 남은 A/B의 종료 정책과 실제 회수 결과를 기록한다. 부모 close나 선택한 최종 상태를 전체 회수 완료로 대신하지 않는다.

두 프레임은 ABC와 xyz이고, stderr는 T를 유지하며 stdout의 F는 AB, offset은 2다. 미생성 C와 실제 A/B 회수 상태를 구분해야 한다. 실제 pipe/FIFO/dup2/fork/exec/wait/셸/학생 실행은 수행하지 않았다.
