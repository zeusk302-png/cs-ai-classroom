소단원 4.1

stat과 파일 유형

파일 이름이 두 개면 파일 내용도 반드시 두 벌일까?

준비 개념과 학습 목표

준비 개념

  • 메타데이터는 내용 자체가 아니라 유형·논리크기·소유자·권한·시간·파일 식별자 같은 정보다.
  • Linux/POSIX 계열 일반 파일시스템 모형을 쓴다. 아래 표는 mount·동시변경·권한실패 없는 가상 상태다.
  • hardlink 는 같은 파일 객체의 다른 이름이고 symlink 는 다른 경로를 담는 별도 객체다.

학습 목표

  • stat/lstat/fstat 의 대상과 실패 처리를 구별한다.
  • 파일 유형·크기·link 수·시간과 이름/객체의 관계를 계산한다.

상태를 읽을 대상부터 정한다

stat(path)는 보통 마지막 symlink 를 따라간 대상의 상태를 얻는다. lstat(path)는 마지막 구성요소가 symlink 이면 그 링크 자체를 읽는다. fstat(fd)는 이미 열린 descriptor 가 가리키는 객체를 읽는다. fstatat 는 상대 경로의 기준 디렉터리 fd 를 지정할 수 있고 AT_SYMLINK_NOFOLLOW 로 마지막 링크 추적을 막을 수 있다.

성공은 0, 실패는−1 이며 errno 에 이유가 남는다. 실패한 struct stat 의 값을 유효한 상태처럼 사용하지 않는다. 대상 파일 자체의 read 권한 없이도 상태를 얻을 수 있지만 경로 앞의 디렉터리 search 권한은 필요하다. stat 성공만으로 나중 open/read 성공이나 원자적 snapshot 을 보증하지 않는다.

유형과 권한·논리크기를 분리한다

st_mode 에는 파일 유형과 권한이 함께 있으므로 전체값을 일반 파일 상수와 단순 같다고 비교하면 권한 bit 때문에 틀릴 수 있다. S_ISREG/S_ISDIR/S_ISLNK 등의 유형 판정 macro 를 사용하거나 S_IFMT 로 유형 bit 를 분리한다. Linux 의 0o100640 은 일반파일 0o100000 과 권한 0o640 의 합성이다. 숫자는 8 진수이며 파일 형식을 읽기/쓰기 권한으로 대체하지 않는다.

일반파일 st_size 는 논리 byte 길이다. symlink st_size 는 저장한 경로 문자열의 byte 길이이며 끝의 NUL 을 포함하지 않는다. 할당 block 수·디렉터리크기·proc 같은 가상파일의 보고값을 일반파일 내용길이와 똑같이 읽지 않는다. st_mtime 은 내용수정, st_ctime 은 상태변경 시간이고 c 가 creation 을 뜻하지 않는다.

여러 이름과 하나의 객체

같은 파일시스템에서 hardlink 의 st_dev/st_ino 는 같다. inode 번호만은 다른 파일시스템에 다시 있을 수 있으므로 한 번의 안정된 모형에서는 두 값을 묶어 비교한다. st_nlink 는 hardlink 수이며 symlink 나 열린 fd 의 수를 더하는 칸이 아니다. 이름 두 개가 같은 파일을 가리켜도 문자열 이름은 서로 다르다.

이름 하나를 제거해도 다른 hardlink 로 파일에 접근할 수 있다. 마지막 이름이 없어져도 이미 열린 fd 가 있다면 그 참조가 사라질 때까지 객체의 내용이 남을 수 있다. 반대로 특정 경로 이름을 저장한 symlink 는 그 이름이 사라지면 다른 hardlink 가 남아도 dangling 일 수 있다. 아래 변화는 실제 삭제 작업이 아닌 종이 모형이다.

중간 과정을 따라가는 예제

같은 디렉터리에 A/B 는 (dev7,ino42)의 regular 파일을 가리키며 st_size13/st_nlink2/mode0o100640 이다. 링크 L 은 (7,90)의 symlink 이고 문자열 A 를 저장한다. stat(L),lstat(L),stat(A),stat(B)의 객체·크기를 비교하라.

  1. stat(A)와 stat(B)는 모두(7,42)·regular·size13·nlink2 를 읽는다. 이름이 두 개여도 내용 객체는 하나다.
  2. stat(L)은 저장 경로 A 를 따라 같은(7,42)·regular·size13 의 상태를 읽는다.
  3. lstat(L)은(7,90)·symlink 이며 문자열 A 의 1byte 길이를 읽는다. 링크 자체가 대상의 13byte 를 복제하지 않는다.
  4. mode0o100640 에서 유형 0o100000·권한 0o640 을 구별한다. L 을 추가했다고 대상의 nlink 가 3 으로 늘지 않고 2 를 유지한다.

stat(L)과 A/B 는 대상 regular13byte, lstat(L)은 별도 link1byte 다. 대상 hardlink 수는 2 다.

종이와 본문으로 직접 해보기

가상 상태에서 A 이름만 제거하고 B 와 이미 A 를 열었던 fd 는 유지한다. stat(L),stat(B),fstat(fd)의 결과와 nlink 를 설명하라. L 이 저장한 경로를 BB 로 바꾼 별도 link 의 st_size 는?

힌트 보기

L 은 객체가 아니라 문자열 A 를 따라간다. fd 는 열렸던 객체를 참조한다. BB 는 ASCII 두 byte 다.

풀이 보기

stat(L)은 대상 A 가 없어 ENOENT 로 실패하지만 lstat(L)의 링크 객체는 남는다. B 와 fstat(fd)는 regular(7,42)·size13·nlink1 을 읽을 수 있다. 열린 fd 는 hardlink 수가 아니다. BB 를 저장한 별도 link 의 논리크기는 2byte 이며 그 대상 존재 여부와 독립이다.

오해와 반례

stat 성공은 파일읽기 허가이고 ctime 은 생성일이며 모든 이름은 별도내용을 가진다.

stat 는 경로 search 권한과 상태 조회를 판단하며 실제읽기와 별개다. ctime 은 chmod 같은 상태 변화로도 바뀐다. A/B 의 같은(7,42)와 서로 다른 L 객체가 이름·유형·내용을 분리하는 반례다.

심화: 다른 프로세스가 mode 와 uid 를 바꾸면 stat 의 서로 다른 필드가 다른 순간을 반영할 수도 있다. 조회한 경로를 나중에 다시 열면 그 사이에 이름의 대상이 바뀔 수도 있다. 열린 fd 에 fstat 하여 그 fd 의 실제 대상을 확인하는 방식과 단순 path 검사를 구별하되, 이것만으로 모든 동시성·보안 문제가 해결되었다고 확대하지 않는다.

소단원 4.2

디렉터리 순회와 링크

폴더 안 이름들을 따라가면 항상 한 번씩 보고 끝나는 나무가 될까?

준비 개념과 학습 목표

준비 개념

  • 디렉터리는 이름에서 객체로 연결되는 목록이다. 파일 내용 stream 과 디렉터리 entry stream 은 다르다.
  • 상대 경로는 현재 작업 디렉터리 또는 지정된 dirfd 를 기준으로 해석한다. .은 자신, ..은 부모다.
  • 종이 순회는 동시추가/삭제·mount·접근실패가 없고, 실제 파일 트리를 만들거나 순회하지 않는다.

학습 목표

  • entry 읽기·유형확인·재귀/링크정책을 나누어 설계한다.
  • hardlink 중복·symlink 순환·목록순서·오류와 정상끝을 구별한다.

이름 열거에는 순서와 수명 계약이 있다

opendir 로 DIR stream 을 열고 readdir 로 다음 entry 를 얻고 마치면 closedir 로 해제하는 흐름을 사용한다. 반환 이름은 일반적으로 정렬되어 있다고 보장되지 않는다. 보기 좋게 이름순 정렬이 필요하면 별도 수집/정렬 단계가 필요하며 그 비용을 계산한다.

readdir 의 NULL 은 정상끝 또는 오류다. 호출 직전에 errno=0 으로 두고 NULL 때 errno 를 확인하여 두 경우를 구별한다. 반환 dirent 포인터의 자료는 같은 stream 의 다음 호출로 덮어쓰일 수 있어 나중 사용할 이름을 적절히 복사해야 한다. glibc 예시의 d_name[256]을 모든 시스템의 고정계약으로 삼지 않는다.

유형을 확인하고 정책을 선택한다

d_type 은 편리하지만 DT_UNKNOWN 일 수 있고 모든 filesystem 이 제공하지 않는다. 필요한 경우 lstat/fstatat 등으로 유형을 확인한다. 기본 종이정책은 .과 ..를 제외하고, regular 이름은 기록하며 directory 만 내려가고 마지막 symlink 는 추적하지 않는다. 링크의 존재 기록과 대상의 재귀처리를 분리한다.

링크를 따라갈 정책은 cycle 과 중복을 고려해야 한다. 예를 들어 하위 이름 back 이 현재폴더 .을 가리키면 다시 자신으로 들어갈 수 있다. 이미 방문한 directory 의(dev,ino)집합으로 재귀 중복을 막는 모형을 쓸 수 있으나 실제 mount/수명/경로 변경 조건도 따로 필요하다. 경로 문자열이 길어졌다는 것만으로 새 객체라고 판단하지 않는다.

무엇을 세는지 정한다

같은 regular 의 hardlink 가 두 개면 파일이름수는 2 지만 고유객체수는 1 이다. 이름마다 size 를 더하면 복제된 논리길이로 계수될 수 있다. 고유 내용 길이를 합칠 목표라면 안정된 상태의(dev,ino)를 deduplicate 한다. 물리 디스크 사용량·압축·sparse·블록공유는 st_size 합과 다르다.

순회 중 파일이 사라져 상태조회에 실패하면 오류를 기록하거나 명시한 정책으로 건너뛴다. 시작 시점의 완전 snapshot 을 얻었다고 자동 주장하지 않는다. 이름과 상태 확인의 시간차도 있다. 아래 결과는 static 가상 그래프에서의 계산이며 실제 디렉터리/학생 시험의 증거가 아니다.

중간 과정을 따라가는 예제

가상 root 에는 a/b 가 같은 regular(1,42) size10 을 가리키고 d 는 directory(1,20), d/c 는 regular(1,43) size6 이다. root 의 s→d,back→.,missing→ghost 는 symlink 이며 ghost 는 없다. .과..를 제외하고 symlink 를 따라가지 않는 순회의 이름수/고유파일수/논리길이합을 구하라.

  1. root 의 일반 entry 는 a,b,d,s,back,missing 의 6 개다. 실제 directory d 로 내려가 c 하나를 추가로 기록한다. symlink3 개는 대상에 내려가지 않는다.
  2. regular 이름은 a, b, d/c의 3개다. directory는 시작 root와 d의 2개이고 별도 symlink 이름은 3개다.
  3. 이름별 regularsize 합은 10+10+6=26 이다. 고유키(1,42)/(1,43)를 한 번씩만 세면 파일객체 2 개·논리 size 합 16 이다.
  4. 전체 . ..제외 entry 이름은 7 개지만 모든 이름이 regular 은 아니다. missing 을 따라가지 않으므로 대상 ghost 가 없다는 사실이 이 정책의 링크 자체 열거를 실패시키지 않는다.

regular 이름 3/고유 regular2,이름별 26byte/고유논리 16byte 다. root+d directory2,symlink3,일반 entry 이름 7 이다.

readdir 는 이름순서와 d_type 을 항상 보장하고 모든 링크를 따라가도 폴더는 나무다.

비정렬 순서와 DT_UNKNOWN 이 가능하다. back→.은 순환, s→d 는 같은 directory 의 두 경로, a/b 는 hardlink 중복이다. 유형확인·방문정책·계수목표 없이 모두 한 번이라는 보장은 성립하지 않는다.

소단원 4.3

권한·umask·파일 잠금

같은 파일을 읽을 권한과 다른 프로그램의 쓰기를 잠시 기다리게 하는 약속은 같은가?

준비 개념과 학습 목표

준비 개념

  • 8 진수 각 권한 digit 은 r4+w2+x1 이다. owner/group/other 의 세 자리를 쓴다.
  • 아래 권한은 일반사용자·기본 9bit 모형이며 ACL/defaultACL·capability·특수 bit·read-only mount 등은 제외한다. 디렉터리권한은 따로 확인한다.
  • 잠금 예제는 서로 다른 협력프로세스의 전통적인 process-associated fcntl advisory byte-range lock 이다. 모든 fd 는 필요한 read/write 모드로 정상 열렸고 오류없음을 별도로 가정한다.

학습 목표

  • 생성 요청 mode 와 umask 의 bit 제거 및 권한 class 를 계산한다.
  • 겹치는 read/write 범위·nonblocking/waiting·lock 수명의 조건을 구별한다.

권한은 누가 무엇을 허용받는가

owner 와 같은 사용자이면 owner 자리, 아니고 파일 group 에 속하면 group 자리, 둘 다 아니면 other 자리를 사용한다. 세 자리의 허가를 무조건 합쳐 가장 큰 권한을 얻는 방식이 아니다. 일반파일의 r/w/x 는 읽기/쓰기/실행이고 directory 의 x 는 이름을 찾아 경로를 통과하는 search 다. 이름열거의 r 과 구별한다.

파일내용 쓰기와 디렉터리 이름 삭제도 같은 작업이 아니다. 디렉터리의 이름변경/삭제에는 부모 directory 의 조건 등이 중요하고 sticky 같은 특수규칙도 있다. 이 단원의 9bit 예를 모든 권한 판정의 완전 모형으로 확대하지 않는다. 읽기 bit 가 있어도 경로의 directory search 가 막히면 파일을 찾지 못할 수 있다.

umask 는 요청에서 특정 bit 를 지운다

새파일의 기본 permission 은 default ACL 이 없는 가정에서 requested_mode & ~umask 다. requested0666 과 mask0027 에서는 owner110 을 유지, group110 에서 writebit010 을 제거해 100, other110 에서 111 을 제거해 000 이 되어 0640 이다. 뺄셈 0666−0027 이 아니라 자리별 bit AND 다. 요청에 없던 실행 bit 를 새로 켜주지 않는다.

directory 요청 0777 에서는 같은 mask 로 0750 이 된다. umask 는 생성 때의 프로세스 상태이고 이미 존재하는 파일을 자동 chmod 하지 않는다. umask(new)는 이전 mask 를 돌려주며 읽고 복구 두 호출 사이에는 다른 thread 의 생성이 끼어들 수 있다. parent 에 default ACL 이 있으면 상속규칙이 적용되는 예외를 별도로 읽어야 한다.

잠금은 협력자의 겹침을 조정한다

SEEK_SET,l_start=a,l_len=b>0 은 byte a..a+b−1, 즉 반열린[a,a+b)범위다. 다른 프로세스들의 read lock 은 겹쳐 공유할 수 있지만 write lock 은 겹치는 read/write 와 충돌한다. F_SETLK 는 충돌 시−1/EACCES 또는 EAGAIN 으로 즉시 실패하고 F_SETLKW 는 기다리는 종류다. F_GETLK 는 잠금을 얻는 호출이 아니다.

advisory 는 협력하는 프로그램이 같은 규칙을 지킨다는 전제다. 무시하는 writer 를 권한 체계처럼 자동 금지한다고 보장하지 않는다. 전통적 잠금은 프로세스와 연결되어 같은 파일을 가리키는 어떤 fd 든 닫으면 그 프로세스의 해당 파일 잠금 모두가 풀릴 수 있다. OFD 잠금은 별도 수명 규칙이며 flock 과 섞지 않는다. 잠금 성공은 crash 복구·자료원자성·학생/장비시험을 뜻하지 않는다.

중간 과정을 따라가는 예제

defaultACL 없는 생성에서 file 요청 0666/directory 요청 0777 에 umask0027 을 적용하라. 같은 일반 file 에서 프로세스 P 는 read[0,10), Q 는 read[5,10)를 갖는다. R 이 write[8,12)를 F_SETLK 로 요청하면?

  1. owner/group/other bit 를 계산하면 file0640=rw-r-----다. directory 는 0750=rwxr-x---다.
  2. file0640 에서 owner 는 r/w, group 은 r, other 는 없음이다. directory0750 의 group 은 r 와 search 를 갖고 write 는 없다.
  3. R 의[8,12)는 P 와[8,10), Q 와[8,10)에서 겹친다. 다른 프로세스의 read 와 write 는 충돌한다.
  4. F_SETLK 는 R 의 잠금을 얻지 못하고 −1 및 EACCES/EAGAIN 을 반환하는 모형이다. 기다리는 F_SETLKW 와 구별한다. P/Q 의 서로 겹치는 read 자체는 허용된다.

생성 file0640/directory0750, R 의 겹친 write 는 nonblocking 충돌 실패다. 서로 다른 read 는 공유된다.

종이와 본문으로 직접 해보기

R 이 대신 write[10,14)를 요청하면 충돌하는가? 요청 mode0600 에 같은 0027 을 적용하면? P 가 같은 file 의 다른 fd 를 닫는 가상 변화 뒤 P 의 read 잠금은?

힌트 보기

10 은[0,10)/[5,10)에 포함되지 않는다. mask 는 이미 0 인 bit 를 켜지 않는다. 전통적 process 잠금의 anyfd close 규칙을 쓴다.

풀이 보기

write[10,14)는 P/Q 와 byte 겹침이 없어 다른 조건이 정상일 때 허용된다. mode0600 은 0600 이다. P 의 다른 fd close 는 P 의 해당 file 잠금을 풀 수 있고 Q 의 잠금은 다른 프로세스 것이라 유지된다. 실제 fd 를 열거나 닫은 실험이 아닌 수명 규칙 대조다.

오해와 반례

umask 는 mode 에서 수치로 빼면 되고 write 잠금 하나면 비협력 writer 와 파일 손상도 모두 막힌다.

0666−0027 의 8 진수 뺄셈은 0637 이지만 정답 bitmask 는 0640 이다. advisory 를 무시하는 writer 와 잠금과 별개의 crash/flush/transaction 문제는 이 잠금만으로 해결되지 않는다. 읽기 permission 과 read lock 도 다른 규칙이다.

mask 는 요청 bit 를 지우며 새 허가를 만들지 않는다.
