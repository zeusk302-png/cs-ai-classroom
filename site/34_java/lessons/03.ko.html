소단원 3.1

메서드·overload

같은 이름의 메서드를 부르는데 왜 다른 본체로 들어갈까?

준비 개념과 학습 목표

준비 개념

  • 메서드 선언은 이름·매개변수·반환 타입·본체를 정한다. 인수는 호출 쪽 식이고 매개변수는 호출마다 새로 생기는 지역 변수다.
  • int는 원시 정수 타입이고 Integer는 그 값을 감싸는 참조 타입이다. int에서 long으로의 확장과 int에서 Integer로의 boxing은 다른 변환이다.

학습 목표

  • 선언과 호출, return과 출력의 역할을 구별한다.
  • 단순 overload를 정적 인수 타입으로 선택한다.
  • boxing보다 먼저 적용되는 호출 단계를 설명한다.

메서드에 계약 붙이기

static 메서드는 클래스 이름으로 호출할 수 있고 이 예제처럼 같은 클래스 안에서는 이름으로 호출한다. 반환 타입 String은 결과가 문자열 참조값이라는 뜻이다. return은 현재 호출을 끝내고 값을 전달하며 println은 화면 출력이라는 효과를 만든다. 둘을 같은 동작이라고 부르면 호출 결과를 조합할 수 없다.

입력 타입만으로 모든 업무 조건을 표현하지는 않는다. 수량 메서드에 int를 넘길 수 있어도 음수 금지 같은 사전조건은 별도로 검사하거나 문서화해야 한다. 반환 타입이 있는 메서드는 정상 완료 경로에서 값을 반환해야 하며 무한 반복/예외 경로와 정상 return을 구별한다.

오버로드는 이름 공유와 정적 선택

overload는 같은 이름으로 구별되는 매개변수 서명을 제공한다. 여기서는 제네릭 없는 단순 서명만 다룬다. 반환 타입만 다르게 만든 같은 인수 서명 두 개는 overload로 구별할 수 없다. 호출 위치에서 인수 식의 정적 타입과 적용 가능한 변환을 보고 선택한다.

고정 인수 개수의 엄격 호출 단계에서는 boxing/unboxing을 사용하지 않는다. kind(int 값)에는 int→long 확장으로 kind(long)이 적용되어 이후 boxing 단계의 kind(Integer)까지 가지 않는다. 반면 Integer 식은 kind(Integer)에 바로 맞는다. 숫자 값이 같다는 사실은 정적 타입 차이를 없애지 않는다.

실행 객체 타입과 혼동하지 않기

Object text="cat"에서 pick(text)의 인수 정적 타입은 Object이므로 pick(Object)가 선택된다. (String)text는 식 타입을 바꾸어 pick(String)을 고르게 한다. 실제 객체가 String이라는 이유만으로 모든 overload가 실행 시 다시 선택되는 것은 아니다.

이 예제의 pick들은 static이며 상속 overriding을 사용하지 않는다. 인스턴스 메서드 overriding은 컴파일 때 정한 서명 뒤 실행 객체 클래스에 따른 본체 선택과 관련되어 다른 단계다. 아래 네 출력은 Java SE11 규칙으로 선택했고 실제 JDK11 실행으로도 확인했다.

public class Methods03 {
    static String kind(long x) { return "long"; }
    static String kind(Integer x) { return "Integer"; }
    static String pick(Object x) { return "Object"; }
    static String pick(String x) { return "String"; }
    public static void main(String[] args) {
        int n=3; Integer boxed=3; Object text="cat";
        System.out.println(kind(n));
        System.out.println(kind(boxed));
        System.out.println(pick(text));
        System.out.println(pick((String)text));
    }
}

중간 과정을 따라가는 예제

아래 완전 소스의 네 호출에서 선택한 서명과 출력을 추적하라.

  1. n은 int라 kind(long)이 엄격 호출 단계에서 적용되어 long을 반환한다.
  2. boxed는 Integer라 kind(Integer)를 직접 선택하여 Integer를 반환한다.
  3. text 식은 Object라 pick(Object)가 Object를 반환한다.
  4. (String)text는 String 식이고 실제 객체도 호환되어 pick(String)이 String을 반환한다.

실제 stdout 네 줄은 long, Integer, Object, String이다.

힌트 보기

null은 참조 타입에 대입 가능하지만 가장 구체적인 적용 서명이 필요한가를 본다.

풀이 보기

소단원 3.2

값 전달과 참조값

배열 값이 바뀌는데도 왜 Java는 값 전달이라고 할까?

준비 개념과 학습 목표

준비 개념

  • 변수는 값을 저장하는 칸이며 배열 객체는 여러 원소를 저장하는 별도 객체다. 참조값은 객체를 가리키거나 null인 값이다.
  • a[0]=7은 가리킨 배열의 원소를 바꾸고 a=new int[]{8}은 변수 a의 참조값을 바꾼다. 두 대입의 대상이 다르다.

학습 목표

  • 매개변수의 값 복사를 그린다.
  • 참조 재대입과 객체 변경의 효과를 구별한다.
  • 공유 객체의 사전조건을 명시한다.

원시값도 참조값도 복사된다

호출은 인수 값을 계산하여 새 매개변수 칸에 넣는다. int x=3을 넘기면 숫자 3을 복사한다. 배열 변수 a를 넘기면 배열을 가리키는 참조값을 복사한다. 호출자 변수 칸 자체에 대한 별칭을 전달하는 것은 아니다.

복사된 참조값 둘은 같은 객체를 가리킬 수 있다. 따라서 메서드가 매개변수 참조로 배열 원소를 바꾸면 호출자도 같은 원소 변경을 관찰한다. 값 전달이라는 말은 객체 전체를 깊은 복사한다거나 외부 효과가 없다는 뜻이 아니다.

변수 칸과 객체 칸 그리기

change 안의 x=9는 새 지역 매개변수 칸만 바꾼다. a[0]=7은 두 참조가 공유한 기존 배열 원소를 바꾼다. 이후 a=new int[]{8}은 메서드 안의 a만 다른 배열로 이동시켜 호출자의 a에는 영향을 주지 않는다.

새 배열에 a[0]=10을 하면 새 배열만 바뀐다. 이 메서드에는 입력 배열이 null이 아니고 길이가 최소 1이라는 사전조건이 필요하다. null이나 빈 배열에서 같은 호출이 정상 완료한다는 주장을 하지 않으며 해당 예외 경로를 성공 증거로 삼지 않는다.

효과를 계약으로 기록하기

정상 종료 후 호출자의 원시 x는 유지되고 전달했던 배열의 0번 칸은 7이다. 다른 원소가 있다면 이 예제 메서드는 그 원소를 쓰지 않는다. 반환이 void라는 사실은 효과가 없다는 뜻이 아니므로 사후조건에 객체 변경을 적는다.

배열의 변경을 원치 않는 API에서는 필요한 내용을 복사하거나 읽기 계약을 지켜야 한다. final int[] a는 변수의 재대입을 막지만 a[0] 수정을 막지 않는다. 공유 배열에 동시에 접근한다면 이 순차 추적 외에 동기화와 가시성 조건이 추가된다.

public class Values03 {
    static void change(int x, int[] a) {
        x=9;
        a[0]=7;
        a=new int[]{8};
        a[0]=10;
    }
    public static void main(String[] args) {
        int x=3; int[] a={4};
        change(x,a);
        System.out.println(x+" "+a[0]);
    }
}

중간 과정을 따라가는 예제

아래 완전 소스의 x와 두 배열 객체를 호출 전후로 추적하라.

  1. 호출자 x=3, a는 원소 4의 배열 A를 가리킨다. 매개변수 x와 a에 각 값이 복사된다.
  2. 메서드 x=9 뒤 호출자 x는 3이고 a[0]=7로 배열 A만 바뀐다.
  3. 메서드 a는 새 배열 B를 가리키고 B의 원소를 10으로 바꾼다. 호출자 a는 여전히 A다.
  4. 반환 뒤 출력은 호출자의 x=3과 A[0]=7을 읽는다.

실제 출력은 3 7과 개행이다.

종이와 본문으로 직접 해보기

a={4,5}이면 정상 종료 후 호출자 배열은? 매개변수를 재대입하기 전에 a[1]=8도 한다면?

힌트 보기

어느 객체의 어느 칸을 쓰는지 표시한다.

풀이 보기

오해와 반례

참조 타입은 호출자 변수 자체가 참조로 전달된다.

메서드에서 a를 새 배열로 재대입해도 호출자 a는 바뀌지 않는다. 참조값을 복사했기 때문에 객체 공유와 변수 독립이 함께 성립한다.

한 단계 더

순차 정상 종료 계약을 전제 a≠null∧a.length≥1, 사후 old(a)[0]=7로 적고 나머지 원소 유지도 명시해 보자. 객체를 가리킨 참조값의 old와 객체 내용의 old를 구별해야 한다. 반환 참조나 여러 객체의 공유까지 확장하면 별칭 관계가 효과 범위의 핵심이 된다.

소단원 3.3

String의 불변성

문자열을 바꿨는데 이전 이름이 그대로 남는 것은 왜일까?

준비 개념과 학습 목표

준비 개념

  • String 변수의 값은 문자열 객체의 참조값이다. 변수 재대입과 그 객체 내부 변경을 구별한다.
  • Java char는 UTF-16 코드 단위다. 보조 평면의 코드 포인트는 두 char의 surrogate pair로 표현될 수 있다.

학습 목표

  • 불변 객체와 변경 가능한 참조 변수를 구별한다.
  • 문자열 내용 비교와 참조 비교를 구별한다.
  • 코드 단위·코드 포인트·사용자가 보는 글자를 분리한다.

객체 불변성과 변수 재대입

String 객체의 문자열 값은 만들어진 뒤 바뀌지 않는다. replace 같은 처리 결과를 변수에 다시 넣어도 원래 객체가 수정되는 것은 아니다. 다른 변수 alias가 원래 객체를 가리키고 있으면 원래 cat를 유지한다.

반면 s라는 변수를 다른 참조값으로 재대입할 수 있으므로 String s의 내용이 바뀌었다는 일상 표현을 엄밀하게 풀어야 한다. final String s는 s 재대입을 막는다. String 자체의 불변성과 final 변수의 제한은 별개의 근거다.

같음의 두 질문

==는 두 참조값이 같은 객체를 가리키는지 묻는다. equals는 문자열 내용을 비교한다. new String("cat")로 만든 객체는 alias가 가리킨 cat 객체와 구별되므로 ==는 false지만 내용 비교는 true다. 문자열 리터럴 공유로 ==가 우연히 참인 예제를 일반 비교 규칙으로 삼지 않는다.

null 참조에서 인스턴스 메서드를 호출하면 NullPointerException이 날 수 있다. 허용된 null을 함께 비교하는 설계라면 Objects.equals 등 계약이 있는 방법을 쓰거나 먼저 null을 검사한다. null과 빈 문자열은 다른 상태다.

길이의 단위 정하기

String.length()는 char 코드 단위 수다. 예제의 U+1F600은 유효한 두 surrogate를 사용하므로 length=2이고 전체 구간의 codePointCount=1이다. 이것이 화면 폭이나 사용자가 보는 글자 수가 1이라는 모든 경우의 법칙을 만들지는 않는다.

substring의 끝 인덱스는 제외되며 char 경계를 사용한다. surrogate pair 사이를 자르면 코드 포인트의 표현을 나눌 수 있다. 사용자 글자 단위 편집은 결합 문자·이모지 묶음까지 고려해야 하며 codePointCount만으로 모든 grapheme cluster를 센다고 설명하지 않는다.

public class Strings03 {
    public static void main(String[] args) {
        String s="cat", alias=s;
        s=s.replace('c','b');
        String separate=new String("cat");
        String emoji="\uD83D\uDE00";
        System.out.println(s+" "+alias);
        System.out.println((alias==separate)+" "+alias.equals(separate));
        System.out.println(emoji.length()+" "+emoji.codePointCount(0,emoji.length()));
    }
}

소단원 3.4

text 처리와 입력 계약

숫자로 바꿀 수 있다는 것과 우리 서비스가 받아도 된다는 것은 같을까?

준비 개념과 학습 목표

준비 개념

  • 문법 검사는 허용 문자열 모양을 확인하고 의미 검사는 업무 값의 범위를 확인한다. 이 단원은 수량 0…100만 허용한다.
  • 정규식 [0-9]{1,3}은 ASCII 숫자 한 개에서 세 개까지다. String.matches는 문자열 전체가 패턴에 맞는지 검사한다.

학습 목표

  • 명시적인 ASCII 수량 계약을 구현한다.
  • 원자료와 정규화 정책을 구별한다.
  • 빈 필드 보존과 실패 보고를 정한다.

API의 문법과 업무의 문법

Integer.parseInt는 선택 부호 등을 포함하는 정수 문자열을 다루지만 우리 수량 계약은 null 금지, ASCII 숫자 1…3개, 부호/공백 금지, 값 0…100이다. API가 +7을 읽을 수 있어도 업무가 허용할 필요는 없다. 허용 입력 언어를 먼저 적으면 유니코드 숫자나 공백을 우연히 받아들이는 문제를 피할 수 있다.

raw 문자열을 곧바로 trim하여 버리면 앞 공백이 있었는지 확인할 수 없어진다. 계약이 공백 무시라면 원자료와 처리값을 분리하고 그 규칙을 기록한다. 이 예제는 trim하지 않으며 " 7"을 거절한다. 입력 검증은 출처 인증이나 모든 보안 요구를 대신하지 않는다.

단락 평가와 범위 보장

text==null || !text.matches(...)는 null일 때 오른쪽 메서드를 부르지 않는다. 문법을 통과한 길이≤3 ASCII 십진수는 0…999이므로 int 범위에 항상 들어간다. 이 조건 아래 parseInt의 표현 범위 실패를 별도 정상 경로로 기대할 필요가 없다.

그 뒤 n>100이면 업무 범위에서 거절한다. 007은 문법상 허용하고 값 7로 해석하는 정책이다. 문자열 길이만 확인하고 임의 긴 수나 문자를 parseInt에 넣는 일반 코드에서는 NumberFormatException을 명시적으로 처리해야 하며 이 작은 증명의 조건을 확대하면 안 된다.

필드와 오류도 데이터다

split의 첫 인수는 단순 문자 집합이 아니라 정규식이다. A,,를 쉼표로 나눌 때 limit=-1을 두면 뒤 빈 필드도 유지하여 세 필드가 된다. 기본 limit=0은 끝의 빈 필드를 버리므로 자료의 빈 값이 의미 있을 때 계약을 바꿀 수 있다. 이 예제는 따옴표/이스케이프가 있는 일반 CSV 파서가 아니다.

아래 완전 소스는 고정된 아홉 입력과 split 한 사례를 실행한다. catch는 우리가 명시적으로 던진 syntax/range 거절을 보고한다. 예외 관찰은 실패 입력을 정상 성공값으로 취급했다는 뜻이 아니며 실제 사용자 입력·대량 공격·교실 실험을 수행했다는 증거도 아니다.

public class Parse03 {
    static int quantity(String text) {
        if(text==null || !text.matches("[0-9]{1,3}"))
            throw new IllegalArgumentException("syntax");
        int n=Integer.parseInt(text);
        if(n>100) throw new IllegalArgumentException("range");
        return n;
    }
    public static void main(String[] args) {
        String[] tests={"0","007","100","101","+7"," 7","12x","",null};
        for(String text:tests) {
            try { System.out.println(String.valueOf(text)+": "+quantity(text)); }
            catch(IllegalArgumentException e) {
                System.out.println(String.valueOf(text)+": rejected "+e.getMessage());
            }
        }
        System.out.println("split="+"A,,".split(",",-1).length);
    }
}
