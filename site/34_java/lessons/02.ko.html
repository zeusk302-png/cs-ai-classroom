소단원 2.1

primitive·reference

변수 두 개에 같은 배열을 대입하면 배열도 두 개 생길까?

준비 개념과 학습 목표

준비 개념

  • 변수는 이름·타입·현재 값을 구별한다. x=4는 이름 x에 int 값 4를 저장하는 것이고 이름이 숫자 자체인 것은 아니다.

  • 배열은 순서가 있는 여러 칸을 가진 객체다. {4}의 첫 칸은 인덱스 0이며 변수와 배열 칸은 서로 다른 저장 장소다.

  • 자기점검: y=x를 실행한 뒤 y만 바꾸는 것과 b=a 후 b[0]을 바꾸는 것은 같은 대상의 변경인지 종이에 화살표를 그려 판단한다.

학습 목표

  • Java 11 기본형과 참조형 값의 차이를 설명한다.

  • 참조값 복사·객체 변경·변수 재대입을 추적한다.

  • 고정 정수 범위와 객체 동일성의 경계를 구별한다.

바깥 배열을 복제했는데 원본의 두 행이 함께 바뀌는 이유는?

앞 본문의 a와 b는 같은 int 배열을 가리키다가 b의 재대입으로 갈라졌다. 여기서는 참조가 한 층 더 있다. R은 int[] 객체 {2,5}이고 A는 int[][] 객체 {R,R}다. A의 두 원소는 서로 다른 행 복사본이 아니라 같은 R을 가리킨다. B=A.clone()은 바깥 배열 객체만 새로 만들고 각 원소의 참조 값을 복사한다. 이 단원의 A/B/R/S 이름은 설명용 객체 이름이며 자바 변수 a/b/row가 가리키는 대상을 표시한다.

B의 원소를 다른 행으로 재대입하는 것과 B의 원소가 가리키는 행의 정수를 고치는 것은 다르다. 전자는 B의 한 슬롯만 바꾸고 후자는 그 행으로 이어진 모든 경로에서 관찰된다. 표는 한 번 이어지는 사건 이력이며, 별도 예제·연습은 각 문제에 명시한 초기 상태에서 독립적으로 시작한다. 모든 배열 할당이 성공하며 다른 스레드·숨은 변경은 없다고 가정한다.

새 배열을 만들었다는 말만으로 모든 공유가 사라졌다고 결론 낼 수 없다. 반대로 모든 행을 각각 복제하면 원본과의 공유는 끊어지지만 원래 두 슬롯이 같은 행이라는 내부 관계도 바뀔 수 있다. 독립 저장이 필요한지, 공유 구조 자체를 보존해야 하는지 복사 계약을 먼저 정한다.

변수가 저장하는 값

이 단원은 Java SE 11 규칙과 설치된 JDK 11로 작성한다. 기본형은 boolean, byte, short, int, long, char, float, double이다. int는 32비트 부호 있는 정수, char는 16비트 부호 없는 UTF-16 코드 단위다. char 하나가 모든 유니코드 문자를 하나씩 나타내는 것은 아니다. int 범위는 −2147483648..2147483647이다.

클래스·인터페이스·배열 타입은 참조형이다. 변수에는 객체를 가리키는 참조값 또는 null이 들어가며 객체 전체가 대입 때 자동 복사되지 않는다. 참조를 조작 가능한 정수 주소처럼 해석하지 않는다. 기본형/참조형은 논리적 타입 구별이지 모든 변수가 어느 물리 메모리에 배치되는지 확정하는 규칙이 아니다.

복사와 별칭을 구분한다

int y=x는 x의 현재 숫자 값을 복사한다. 이후 y=9는 x에 영향을 주지 않는다. int[] b=a는 참조값을 복사해 두 변수가 같은 배열을 가리킨다. b[0]=9는 공통 객체의 칸을 바꾸므로 a[0]에서도 9를 본다. 별칭은 두 이름이 같은 변경 가능한 객체에 접근하는 관계다.

b=new int[]{2}는 b의 참조값을 새 배열로 바꾼다. 원래 a의 참조값이나 원래 배열을 교체하지 않는다. ==의 두 피연산자가 모두 참조형 또는 null 타입이면 같은 객체를 가리키는지, 또는 둘 다 null인지 비교한다. 내용 비교 방법은 타입마다 다르므로 배열 내용이 같다는 것과 a==b를 혼동하지 않는다.

public class Values {
  public static void main(String[] args) {
    int x=4; int y=x; y=9;
    int[] a={4}; int[] b=a; b[0]=9;
    b=new int[]{2};
    System.out.println(x+" "+y+" "+a[0]+" "+b[0]);
    System.out.println(a==b);
  }
}

타입의 경계가 결과를 정한다

같은 표면상의 덧셈도 타입에 따라 허용 범위와 결과가 달라진다. Java int 범위를 넘는 정수 연산은 C의 signed overflow UB와 다르게 낮은 32비트에 따른 값이 된다. 따라서 Integer.MAX_VALUE+1은 Integer.MIN_VALUE이다. 오류가 필요하면 범위를 직접 확인하거나 Math.addExact 같은 계약을 선택한다. 이 추가 식은 이 단원 코드 실행 대상과 별도 종이 규칙 예다.

참조값을 메서드에 전달해도 Java는 값 전달이다. 복사된 참조로 같은 배열 칸을 바꾸는 것과 호출자 변수의 참조를 다시 바꾸는 것은 다르다. 다음 메서드 단원에서 이를 다룬다. final 참조 변수도 객체의 모든 칸을 불변으로 만드는 규칙은 아니다.

행별 복사는 내부 공유를 끊을 수 있다

  1. 두 clone 호출은 서로 다른 행 객체 U/V를 만든다.

  2. c[0]의 U만 [6,5]가 되고 R과 V는 [2,5]를 유지한다.

연습 1 · 값과 상태 예측

각각 처음 R=[2,5], A=[R,R], B=A.clone()에서 시작한다. b[1]=null을 수행한 뒤 a[1][0]과 b[1][0]의 평가를 비교하라.

힌트 1

b[1] 대입은 바깥 B의 슬롯 하나에만 쓴다.

힌트 2

null 행과 존재하는 정수 0을 구별한다.

풀이와 답 확인

  1. a[1]은 여전히 R이므로 첫 정수 2를 읽는다.

  2. b[1]은 null이므로 그 행을 역참조하는 b[1][0]은 NullPointerException 경로다.

a의 값은 2다. b의 접근은 정상 정수 반환이 아니다. 실제 실행은 미수행이다.

흔한 오답에서 다시 생각하기

두 바깥 배열이 처음 같은 행을 가리켰으므로 a[1]도 null이다.

대상 R에 쓰는 사건과 B의 슬롯에 쓰는 사건을 다시 나눈다.

힌트 1

현재 복제되는 층을 표시한다.

힌트 2

바깥 배열뿐 아니라 각 비null 행의 저장도 분리한다.

풀이와 답 확인

  1. 바깥 clone은 R 참조를 복사하므로 b[0][0]은 R을 수정한다.

  2. 원본에서 독립된 행이 필요하면 각 행의 복제도 수행하고 null 행의 처리 정책을 명시한다.

바깥 객체만 독립이라는 현 계약을 행 저장 독립 계약으로 확장해야 한다. 내부 공유 보존 여부는 별도 선택이다.

연습 3 · 직접 만들어 보기

원본 A의 두 슬롯이 같은 R이라는 관계를 복제본 D에서도 보존하면서 원본 R과는 공유하지 않는 그림을 구성하라. 이 작은 고정 사례만 다룬다.

힌트 1

R의 새 복제 T는 하나만 만든다.

힌트 2

새 바깥 D의 두 슬롯을 같은 T로 연결한다.

풀이와 답 확인

  1. T=R.clone()을 한 번 수행한 것으로 그린다.

  2. D=[T,T]로 새 바깥 배열을 구성한다. T의 수정은 D 두 경로에 보이지만 A의 R에는 보이지 않는다.

A→R/R과 D→T/T를 구별하며 R≠T다. 일반 임의 그래프 복사 알고리즘을 구현한 것은 아니다.

값은 같아도 서로 다른 두 행을 만들면 원래 공유 정체성 관계는 달라진다.

소단원 2.2

변환·boxing

더 넓은 타입으로 바꾸면 언제나 원래 숫자의 모든 자릿수를 유지할까?

준비 개념과 학습 목표

준비 개념

  • 변환은 한 타입의 값을 다른 타입에서 표현하는 규칙이다. 명시적 cast (byte)n은 의도 표시이지 값 보존 보증이 아니다.

  • 이진 정수의 자릿수와 실수 유효 자릿수는 다르다. 2²⁴=16777216이며 float는 이 근처의 모든 연속 정수를 구별하지 못한다.

  • Integer는 int 값을 담는 wrapper 클래스다. int는 객체가 아니며 Integer 변수는 null도 가질 수 있다.

학습 목표

  • widening/narrowing과 정밀도 손실을 구분한다.

  • boxing/unboxing의 타입과 null 예외를 추적한다.

  • wrapper 동일성 비교를 값 비교와 구별한다.

한 번 더한 값이 왜 −128이며 같은 모양의 대입은 번역 오류인가?

앞 본문은 int 130을 byte로 줄여 −126을 예측했다. 새 사례 byte b=127에서 b+=1은 int로 계산한 128을 다시 byte로 줄이는 복합 대입이다. 8비트 10000000은 byte의 부호 있는 값 −128이다. 보통 대입 b=b+1에는 그 축소가 자동으로 붙지 않아 int 결과를 byte에 담으려는 번역 오류다. 아래 판단은 Java SE 11의 타입 규약에 대한 손추적이며 실제 컴파일 결과가 아니다.

복합 대입의 짧은 표기는 읽기·평가 순서도 가진다. 처음 int a=6에서 a+=(a=4)는 왼쪽의 이전 값 6을 보관한 뒤 오른쪽 대입이 만든 값 4를 더해 최종 10을 저장한다. 두 문장 a=4; a+=a;는 처음 값을 먼저 덮어쓰므로 최종 8이다. 이 비교는 수학의 a=a+a라는 문자열 모양이 아닌 사건 순서를 읽는 연습이다.

표현 가능 범위 안의 정수 상수 대입 예외와 임의 변수 값은 구별한다. byte c=127+1의 상수 결과 128은 범위 밖이라 허용되지 않는다. Integer n=null의 n+1은 먼저 unboxing을 필요로 하므로 정수 합을 계산하기 전에 예외 경로다. boxed 객체의 부재를 정수 0으로 바꾸는 자동 규칙은 없다.

확대 변환도 정밀도를 잃을 수 있다

Java 11에서 int→long은 정수값을 보존하지만 int→float는 확대 변환이라도 유효 자릿수를 잃을 수 있다. int n=16777217을 float로 바꾸면 16777216에 반올림된다. 확대라는 명칭은 허용된 타입 변환 분류이며 모든 수의 정보 보존 명제가 아니다.

int→byte 같은 축소 변환은 명시적 cast가 필요하며 낮은 8비트를 남긴다. (byte)130은 10000010₂를 부호 있는 8비트로 읽어 −126이다. cast가 범위 검사를 해 130을 안전하게 보존하는 것은 아니다. 실수→정수의 규칙은 단순 비트 자르기와 다르므로 이 예제와 동일시하지 않는다.

값을 감싸고 다시 꺼낸다

Integer boxed=7은 boxing으로 wrapper 참조값을 만든다. int value=boxed는 unboxing으로 7을 꺼낸다. Integer absent=null에서 int bad=absent는 null에 담긴 정수가 없으므로 NullPointerException이다. 코드에서는 예외를 잡아 식별 문자열만 출력한다. 실제 메시지/스택은 환경에 따라 달라질 수 있다.

두 Integer 피연산자의 ==는 참조 동일성을 비교하므로 숫자 값 비교에 일반적으로 쓰지 않는다. 한쪽이 int이면 다른 Integer를 unboxing하여 숫자 값을 비교하므로, null이면 예외가 발생할 수 있다. 작은 상수의 boxing은 일부 객체 동일성이 보장되지만 이를 모든 정수 값에 일반화하면 안 된다. 값 비교는 null 처리를 포함해 equals나 명시적 unboxing 계약으로 설계한다. 특정 cache 범위를 초심자의 값 동등성 규칙으로 사용하지 않는다.

public class Conversions {
  public static void main(String[] args) {
    int n=16777217; float f=n;
    System.out.println(n== (int)f);
    System.out.println((byte)130);
    Integer boxed=7; int value=boxed;
    System.out.println(value+1);
    Integer absent=null;
    try { int bad=absent; System.out.println(bad); }
    catch (NullPointerException e) { System.out.println("null-unboxing"); }
  }
}

식의 타입과 대입 위치를 확인한다

byte a=1, b=2;에서 a+b의 결과 타입은 int로 승격되므로 byte c=a+b;는 그대로 컴파일되지 않는다. 상수 표현식의 범위 내 대입 같은 특별 규칙과 변수 연산을 구별한다. byte c=3;와 위 식은 같은 표면 결과 3이라도 컴파일 조건이 다르다.

검증이 목적이면 입력의 범위와 허용 형식을 먼저 확인해야 한다. cast를 추가해 컴파일만 통과시키면 범위 밖 입력의 손실을 감춘다. 문자열 파싱·실수 허용오차·정수 narrowing은 서로 다른 계약이며 앞 Python 입력 검증과 같은 논리 경계를 갖는다.

byte b=127의 b+=1과 명시 축소 b=(byte)(b+1)를 독립 비교하고, 결과를 0..127의 업무 점수로 쓰려는 요구도 판단하라.

  1. 두 표현은 int 합 128 뒤 byte 축소를 거쳐 −128을 저장한다.

  2. 언어상 정상 저장이어도 업무 범위 0..127을 위반한다.

둘의 최종 값은 −128이다. 업무 점수는 더하기 전에 더 넓은 타입의 후보와 요구 범위를 검사해야 한다.

비교할 점

번역 가능성과 업무 범위 검증은 서로 다른 조건이다.

같은 변수를 오른쪽에서 먼저 바꾼다

각각 int a=6에서 시작한다. 계획 P는 a+=(a=4)이고 Q는 a=4; a+=a;다.

  1. P는 왼쪽 변수의 옛 값 6을 저장한 후 오른쪽 대입의 값 4를 사용한다.

  2. Q는 첫 문장에서 4를 저장한 뒤 둘째 문장에서 4+4를 계산한다.

P의 최종 값은 10이고 Q는 8이다. 정수 범위 안이므로 이 예에서는 overflow가 없다.

비교할 점

평가 사건을 보존하지 않는 기계적 두 문장 변환은 결과를 바꿀 수 있다.

종이와 본문으로 직접 해보기

오해와 반례

캐스트와 boxing은 값을 항상 보존하고 null도 0으로 바꾼다.

(byte)130=−126은 수치 손실이고 Integer null을 int로 꺼내면 예외다. Integer 값 7 boxing의 값 보존과 범위 밖 정수 cast를 같은 규칙으로 해석하지 않는다.

연습 1 · 값과 상태 예측

각각 새 선언 byte p=100; byte q=20;에서 byte r=p+q와 byte r=100+20의 번역 조건을 비교하라.

힌트 1

변수 두 개의 합은 int로 승격된다.

힌트 2

범위 안의 정수 상수 표현식은 대입의 별도 축소 허용 조건을 가진다.

풀이와 답 확인

  1. p+q는 int 결과이므로 명시 축소 없는 첫 선언은 번역 오류다.

  2. 100+20은 상수 120이며 byte 범위 안이어서 둘째 선언은 허용된다.

실제 컴파일은 미수행이다. 같은 숫자 합 120이라도 표현식의 타입·상수 조건은 다르다.

흔한 오답에서 다시 생각하기

현재 p와 q가 100과 20이므로 compiler는 둘을 상수 선언과 항상 같게 처리한다.

임의 변수의 현재 값과 상수 표현식 규약을 혼동하지 않는다.

연습 2 · 오류 찾아 고치기

Integer n=null에서 n+1의 기대값을 1이라고 쓴 계획을 수정하라. null은 입력 누락이고 누락은 거절한다는 계약이다.

힌트 1

더하기 전에 필요한 변환을 찾는다.

힌트 2

업무 계약이 0 대체인지 거절인지 확인한다.

풀이와 답 확인

  1. n+1은 null 참조의 unboxing에서 NullPointerException 경로다.

  2. 입력 누락을 먼저 확인하고 거절한다. 0으로 대체하는 새 정책을 임의 도입하지 않는다.

정수 합 1이라는 정상 결과를 기대하지 않는다. 거절 전에는 외부 상태를 바꾸지 않는 계획을 둔다.

흔한 오답에서 다시 생각하기

null은 기본 정수 값 0이므로 boxed null도 0이다.

정수 필드의 기본값과 참조 null의 unboxing은 다른 규약이다.

연습 3 · 직접 만들어 보기

byte 점수 b는 0..127이고 증가량 d는 int 0..10이다. 증가가 범위를 넘으면 b를 보존하고 거절하는 종이 절차를 설계하라.

힌트 1

b+=d를 검증보다 먼저 하지 않는다.

힌트 2

후보 합은 이 입력 범위에서 int overflow 없이 계산된다.

풀이와 답 확인

  1. b와 d의 입력 범위를 검사한 뒤 int 후보 b+d를 계산한다. 최대 137로 int 범위 안이다.

  2. 후보가 127을 넘으면 원래 b를 보존하여 거절하고, 아니면 후보를 byte로 축소하여 저장한다.

b=127,d=0은 성공해 127, d=1은 거절해 127을 보존한다. 실제 구현은 미수행이다.

흔한 오답에서 다시 생각하기

먼저 byte로 만든 −128이 127 이하이므로 정상으로 수락한다.

축소로 잃은 원래 범위 정보를 축소 후 검사로 복구할 수 없다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

Java int의 최댓값에서 a+=(a=0)를 계획한다. 최종 값과 두 문장 a=0; a+=a;의 최종 값을 비교하라.

힌트 1

첫 계획은 오른쪽 평가 전에 왼쪽 옛 값을 저장한다.

힌트 2

더할 오른쪽 값은 0이며 이 경우 overflow가 없다.

풀이와 답 확인

  1. 첫 계획은 옛 최댓값에 0을 더하여 최댓값을 저장한다.

  2. 두 문장은 0을 저장한 뒤 0+0이므로 최종 0이다.

첫 계획은 2147483647, 둘째는 0이다. 왼쪽 옛 값 보관의 차이가 경계에서도 유지된다.

흔한 오답에서 다시 생각하기

소단원 2.3

조건·반복·배열

배열 길이가 0이면 반복문은 오류일까, 아니면 아무 것도 하지 않을까?

준비 개념과 학습 목표

준비 개념

  • boolean은 true/false 두 값이다. Java의 if 조건에는 정수 1을 직접 쓰지 않는다. Boolean wrapper는 꺼내는 과정이 필요할 수 있다.

  • 배열 length=n이면 인덱스는 0..n−1이다. 빈 배열 length0은 null 참조와 다르다.

  • 누적값 sum은 처음 0으로 두고 본 요소를 더한다. 종이에서는 반복 전후 인덱스와 sum을 함께 적는다.

학습 목표

  • 조건→본문→갱신의 순서를 추적한다.

  • 배열 범위·빈 배열·continue/break의 차이를 설명한다.

  • 부분합 불변량과 감소하는 남은 길이로 작은 반복을 정당화한다.

반복 변수에 대입한 값은 배열로 되돌아가는가?

앞 본문의 향상된 for는 원소 값을 읽어 합계에 더했다. 읽는 과정에서 만들어지는 반복 변수는 배열 슬롯의 별칭 변수 자체가 아니다. int[] a={2,5}에서 for(int v:a) v=0은 매회 지역 int v만 바꾼다. 원래 배열의 정수 저장은 그대로다. 배열을 바꾸려면 a[i]=0처럼 어떤 슬롯에 쓸지 명시해야 한다.

배열 원소가 int[] 참조이면 반복 변수도 참조 값을 받는다. for(int[] row:matrix) row=new int[]{0}은 지역 참조만 재대입한다. row[0]=0은 그 참조가 가리키는 행의 정수를 변경한다. T1의 공유 행처럼 두 경로가 같은 행을 가리키면 반복 횟수 두 번의 변경이 같은 정수 저장에 누적될 수 있다. null 행과 길이 0인 행에는 [0] 접근을 정당화할 수 없다.

반복 종료의 근거는 제어 경로에도 있다. 기본 for의 continue는 update로 이어지지만, while 본문 안의 continue는 뒤에 적은 i++를 건너뛸 수 있다. 문제의 배열 길이는 고정이고 다른 스레드는 없으며 모든 정상 접근을 먼저 범위·null 조건으로 보장한다. 합계는 별도 명시한 작은 입력에서 int 범위를 넘지 않는다.

조건은 평가된 논리값이다

if는 조건이 true인 분기의 문장을 실행한다. while은 매회 본문 전에 조건을 확인하고, do-while은 먼저 본문을 한 번 실행한다. for(int i=0;i<a.length;i++)는 초기화 1회, 조건, 본문, 갱신 순서다. 예제는 Java 11 기본 for이며 최신 switch 표현식에 의존하지 않는다.

&&는 왼쪽이false면 오른쪽을 평가하지 않는다. a!=null && a.length>0은 null일 때 length 접근을 건너뛴다. boolean &는 두 피연산자를 평가하므로 이를 단순 교환하면 보호가 사라진다. 이 단락의 & 반례는 별도의 미실행 종이 규칙이다.

배열의 칸과 반복의 종료

new int[n]는 고정 길이의 배열을 만든다. 이후 length를 늘리는 대입은 없으며 음수 크기는 허용되지 않는다. a.length 위치는 마지막 칸이 아니라 한 칸 뒤라 접근 시 ArrayIndexOutOfBoundsException이 된다. length0인 배열은 존재하는 객체로 반복이 0번 될 수 있다.

continue는 현재 본문의 남은 일을 건너뛰고 기본 for의 갱신으로 간다. break는 루프를 빠져나온다. 따라서 음수에서 continue하면 음수만 제외하고 뒤 원소를 계속 볼 수 있지만 break하면 뒤의 양수까지 처리하지 않는다.

public class Flow {
  public static void main(String[] args) {
    int[] a={3,-2,4}; int sum=0;
    for(int i=0;i<a.length;i++) {
      if(a[i]<0) continue;
      sum+=a[i];
    }
    System.out.println(sum);
    int[] empty={}; int total=0;
    for(int value:empty) total+=value;
    System.out.println(total);
    int[] absent=null;
    System.out.println(absent!=null && absent.length>0);
  }
}

추적에서 근거로 나아간다

Flow 예제에서 반복 시작의 불변량은 sum이 이미 본 a[0..i−1] 중 음수가 아닌 원소 합이라는 것이다. 초기 i=0에서 빈 합 0이 맞고, a[i]<0이면 더하지 않으며 그렇지 않으면 더하므로 갱신 뒤에도 맞다. 종료 i=length이면 전체의 해당 합이다.

각 갱신에 i가 1 증가하므로 length−i가 0까지 감소한다. 이는 배열이 바뀌지 않고 반복 내부가 정상 끝나며 int 합이 원하는 수학적 범위에 있다는 예제 조건에서 설명한 논증이다. 매우 큰 합의 int overflow나 다른 스레드의 배열 수정은 별도의 계약 문제이며 이 작은 예제의 실행으로 일반 증명이 되지 않는다.

향상된 for의 기본 값 재대입과 인덱스 쓰기

각각 새 a={2,5}에서 표의 첫째/둘째 반복을 계획한다. 원소 합계를 나중에 읽으면 각각 얼마인가?

  1. 첫 반복은 지역 v만 0으로 바꿔 배열 합계는 2+5다.

  2. 둘째 반복은 실제 배열 슬롯을 0으로 써 합계는 0+0이다.

합계는 각각 7과 0이다. 반복 횟수 둘은 같아도 쓰는 대상은 다르다.

비교할 점

반복을 수행했다는 횟수는 의도한 저장 대상 수정의 증거가 아니다.

continue 뒤에 남은 증가가 실행되지 않는다

i=0, a={−1,3}에서 while(i<a.length){if(a[i]<0) continue; i++;}를 계획한다. 기본 for(int i=0;i<a.length;i++){if(a[i]<0) continue;}와 비교하라.

  1. while은 첫 음수에서 continue하므로 i++에 도착하지 않고 같은 i=0을 다시 검사한다.

  2. 기본 for의 continue는 update i++를 거쳐 둘째 원소를 보고 종료한다.

while 변형은 이 입력에서 종료하지 않는다. 기본 for는 두 원소를 검사해 종료한다. 실제 무한 반복을 실행하지 않았다.

i<=a.length로 쓰면 마지막 원소도 정확히 처리한다.

길이 3의 유효 인덱스는 0,1,2이며 i=3에서 a[3]은 범위 밖이다. i<a.length가 예제의 조건이다. 길이 0일 때<=는 바로 잘못된 첫 접근을 시도한다.

소단원 2.4

null과 초기화

필드의 int는 자동으로 0인데 지역변수 int는 왜 읽을 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 필드는 객체/클래스에 속하는 변수, 지역변수는 메서드 안에서 선언한 변수다. 선언 위치가 초기화 규칙을 바꾼다.

  • null은 참조가 객체를 가리키지 않는 값이다. 빈 문자열 ""은 길이 0의 String 객체로 서로 다르다.

  • 정상 실행 경로는 예외 없이 다음 문장까지 도달하는 길이다. if의 양쪽 분기에서 대입되는지 별도로 확인한다.

학습 목표

  • 필드·배열 칸 기본값과 지역변수 확정 대입을 구분한다.

  • null 역참조와 null unboxing의 실패를 설명한다.

  • 초기화됨·null 아님·도메인상 유효함의 차이를 판정한다.

값을 한 번 받았다는 사실만으로 사용 준비가 끝났는가?

앞 본문의 지역 n은 읽기 전에 모든 필요한 경로에서 대입돼야 했다. 새 예에서는 boolean 매개변수 flag가 변하지 않더라도 if(flag) n=1; if(!flag) n=2;의 두 별도 조건문 뒤 n 읽기를 definite assignment 규칙이 허용하지 않는다. 실제 논리상 한 조건이 참이라는 손증명과 언어가 지정한 구조적 번역 규칙을 구별한다. 같은 두 가지를 if/else 하나로 쓰면 두 갈래가 n을 대입하므로 이 조건을 충족한다.

String s=null은 지역 변수의 값이 이미 정해졌으므로 미대입 문제는 없다. 그러나 s.length()를 정상 호출할 객체는 없어서 예외 경로다. int[][] rows=new int[2][]는 바깥 배열과 행 참조 두 개를 만들지만 각 행 참조는 기본 null이다. 바깥 객체를 생성한 사실은 각 행의 정수 저장을 생성한 사실과 다르다.

업무 조건은 한 단계 더 필요하다. 새 작은 주문에서 quantities는 비null·길이 1 이상이며 각 값은 1..5여야 수용한다는 계약을 둔다. new int[2]는 모든 정수가 기본 0으로 초기화돼 메모리 읽기 조건은 만족하지만 업무 수용 조건은 실패한다. 초기화·역참조·도메인 검증을 다른 질문으로 적으면 형식상 정상인 잘못된 입력을 놓치지 않는다.

먼저 확인할 개념
  • 기본 초기화와 definite assignment

    필드/원소 기본값, 지역 변수 대입, 객체 부재와 도메인 검증을 구별한다.

  • 조건 분기·null 단락 검사

    정상 갈래의 구조와 검증 뒤 접근 순서를 구성한다.

자동 기본값의 대상

Java 11의 일반 필드와 배열 칸은 생성 때 기본값을 받는다. int는 0, boolean은 false, 참조형은null이다. new String[2]는 두 문자열 객체를 만드는 것이 아니라 두 참조칸이 null인 배열을 만든다. 따라서 names[0].length()는 객체가 없어 실패한다.

지역변수는 자동 기본값을 읽는 규칙이 없다. int local;은 선언만 했고, 읽기 전에 확정 대입이 필요하다. 이는 쓰레기값을 실행해 관찰하는 문제가 아니라 컴파일러가 읽기 경로를 거부하는 문제다. Unassigned.java는 실제 javac에서 variable x might not have been initialized 오류로 거부됐다.

모든 정상 경로에서 대입했는가

if(args.length==0) local=7; else local=8;은 어느 분기든 local에 값이 들어가므로 이후 읽을 수 있다. else를 없애면 다른 길에서 대입이 없으므로 컴파일되지 않는다. 컴파일러의 확정 대입 규칙은 일반적인 프로그램 의미의 모든 참임을 증명하는 도구가 아니라 정해진 문법/흐름 규칙이다.

참조 변수에 null을 대입해도 확정 대입은 충족한다. 하지만 s.length() 같은 객체 사용은 안전하지 않다. 따라서 초기화 여부와 null 여부를 분리해야 한다. null을 검사한 뒤 안전한 값으로 처리하거나 명시적인 실패/부재 결과를 정하는 계약이 필요하다.

public class Initialization {
  int count; String name;
  public static void main(String[] args) {
    Initialization s=new Initialization();
    String[] names=new String[2];
    int local;
    if(args.length==0) local=7; else local=8;
    System.out.println(s.count+" "+s.name+" "+names[0]+" "+local);
    try { System.out.println(names[0].length()); }
    catch(NullPointerException e) { System.out.println("null-dereference"); }
  }
}

기본값은 유효한 업무 값과 다르다

count 필드가 0으로 초기화되어도 사용자가 제공한 유효한 수량이라는 증거는 아니다. 요구가 1..5를 허용하면 기본 0은 도메인상 부적합하다. 필드 default, 지역변수 대입 여부, null 검사, 숫자 범위 검사는 각각 다른 질문이다.

예제의 try/catch는 실패 종류를 관찰하는 작은 교육용 코드다. NullPointerException을 모두 잡아서 계속하는 것이 일반 복구 정책이라는 뜻은 아니다. 필요한 값이 없을 때 거부·기본값·선택적 부재 중 무엇을 사용할지 요구와 타입에 따라 결정한다. 원인 은폐를 피하려면 입력/버전/실패 근거를 기록한다.

조건을 바꾸어 비교하기

정상 경로를 구조적으로 합친다

int n; if(flag)n=1; if(!flag)n=2; use(n);의 문제를 if/else로 고친다. flag는 boolean 매개변수다.

  1. 두 별도 if 뒤 n 읽기는 definite assignment 규칙을 충족하지 못한다.

  2. if(flag)n=1; else n=2; 뒤에는 어느 정상 갈래든 n이 대입됐다.

수정본의 n은 flag가 true면 1, false면 2다. 이는 번역 규약의 손검토이며 실제 컴파일은 미수행이다.

비교할 점

실제 값 추론과 언어가 명시한 대입 경로 규칙은 항상 같지 않다.

초기값 0이 도메인에서 무효다

주문 입력 계약은 비null·길이 1 이상·각 수량 1..5다. 입력 A=new int[2], 입력 B=new int[0], 입력 C={1,5}를 비교하라.

  1. A는 읽을 수 있는 두 0이 있지만 각 원소 범위를 위반한다. B는 원소가 없지만 최소 길이 계약을 위반한다.

  2. C는 길이 2이고 두 값이 범위 안이다.

A/B는 서로 다른 이유로 거절하고 C는 수용한다. 부재 입력 null도 별도 거절한다.

비교할 점

초기화된 저장과 빈 입력의 안전한 반복이 업무 수용을 자동 뜻하지 않는다.

풀이와 답 확인

  1. P는 같은 row의 첫 정수를 두 번 증가시켜 [4,5]로 만든다. a와 b의 두 행은 모두 그 row를 가리키므로 두 경로에서 [4,5]를 읽는다. 원본 보존 계약을 위반한다.

  2. P의 score+=1은 int 후보 128을 byte로 축소해 −128을 저장한다. 정상 언어 대입이지만 점수 0..127 계약을 위반한다.

  3. Q는 원본 row=[2,5]를 보존하고 별도 두 행 U/V를 각각 [3,5]로 만든다. c의 두 행은 내용이 같아도 다른 객체라 원래의 내부 공유 관계는 보존되지 않는다. 이 계획은 원본 보존을 요구하지만 내부 공유 보존을 요구하지 않는 것으로 명시한다.

  4. Q의 int 후보는 128이므로 범위 검사에서 거절하고 score 127을 보존한다. 각 행 후보의 변경과 score 거절을 하나의 원자적 업무 거래로 제공했다는 주장은 하지 않는다. 여기서 외부 원본과 score 보존만 각각 검사한다.

  5. boolean ok 매개변수 또는 지역 값의 결과를 두 별도 if로 추론해 result를 읽는 계획은 definite assignment 규약상 거절된다. if(ok)result=1; else result=0; use(result);로 두 갈래 대입을 구조화한다. 현재 후보는 거절이므로 ok=false를 저장한 정상 수정 계획의 result는 0이다.

  6. 새 입력에서 바깥 배열 null 정책을 먼저 정하고 각 행의 null·길이 검사를 행 역참조/첫 원소 접근 전에 한다. 바깥만 clone해도 행은 자동 생성되지 않는다. 실제 번역/배열 변경/주문·학생 시험은 수행하지 않았다.

P는 공유 행 [4,5]와 score −128로 두 계약을 위반한다. Q는 원본 [2,5], 서로 다른 복제 행 [3,5] 두 개, 거절 후 score 127을 보존한다. result는 if/else로 대입 경로를 보장하며 수정 계획에서 0이다. 내부 공유·전체 거래 원자성과 실제 수행은 별도 조건이다.
