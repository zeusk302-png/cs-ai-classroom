소단원 9.1

query·method syntax

같은 목록에서 필요한 수를 고르는 코드를 두 문법으로 적으면 결과도 달라질까?

준비 개념과 학습 목표

준비 개념

  • 배열

  • 조건식

  • lambda

학습 목표

  • query와 method 표현을 대응한다.

  • 질의 생성과 결과 열거를 구별한다.

질의는 원하는 결과를 설명한다

LINQ는 여러 자료원에 질의를 표현하는 C# 모델이다. 먼저 자료원을 정하고 질의를 만들고 열거해 결과를 얻는 단계를 나눈다. 이 단원은 메모리 안 정수 목록의 LINQ to Objects를 사용하며 DB의 번역 규칙은 따로 다룬다.

문법을 연산에 대응하기

from은 입력 요소를 이름에 연결하고 where는 조건을 통과한 요소를 남기며 select는 결과를 만든다. 같은 연산을 Where와 Select의 메서드 호출로 표현할 수 있다. 컴파일러는 query 표현을 메서드 호출로 바꾸므로 문법 자체가 다른 알고리즘이나 자동 최적화 보장은 아니다.

int[] nums = { 1, 2, 3, 4 };
var q = from n in nums where n % 2 == 0 select n * 10;
var m = nums.Where(n => n % 2 == 0).Select(n => n * 10);
var a = q.ToArray();
var b = m.ToArray();

중간 요소의 타입을 따라가기

Where 뒤에도 정수 요소가 흐르지만 Select로 문자열을 만들면 결과 요소 타입도 바뀐다. lambda의 입력과 반환을 적어 합성이 가능한지 확인한다. Count처럼 단일 값을 반환하는 연산은 메서드 문법을 섞어 표현한다. using System.Linq가 연산을 사용할 범위를 제공한다.

중간 과정을 따라가는 예제

고정 배열 [1,2,3,4]에서 짝수만 남겨 각각 10배 한다. 두 표현을 ToArray로 열거한 결과를 구하라.

  1. 1과 3은 n%2==0을 만족하지 않는다.

  2. 2와 4를 순서대로 남긴다.

  3. 각각 2×10=20,4×10=40으로 투영한다.

두 표현의 결과는 모두 [20,40]이며 원본은 [1,2,3,4]다.

오해와 반례

query 문법은 method 문법보다 언제나 빠르다.

같은 연산으로 변환되는 표현이다. 자료원·provider·실행 방식이 같다면 문법만으로 속도 순위를 정할 수 없다.

소단원 9.2

filter·projection·group·join

이름을 고르는 일과 학년별로 모으는 일, 같은 번호끼리 붙이는 일은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • 필터와 투영

  • 키와 값

학습 목표

  • 네 연산의 입력과 결과 형태를 구별한다.

  • 중복 키 조인의 결과를 세어 본다.

선별과 변환을 분리하기

Where는 개별 요소의 통과 여부를 정하고 Select는 남은 요소에서 필요한 값이나 새 객체를 만든다. 학생 객체에서 이름만 뽑으면 결과에는 학년 필드가 없을 수 있다. 뒤 연산에 필요한 키를 너무 일찍 버리지 않도록 연산 순서를 설계한다.

그룹은 키와 요소 묶음이다

GroupBy는 같은 키의 요소를 묶는다. 각 IGrouping은 Key와 열거 가능한 요소를 가진다. 그룹을 만들었다고 요소가 자동으로 하나의 합계가 되지는 않는다. 그룹별 Count나 Sum을 이어 계산한다.

조인은 일치하는 모든 짝을 만든다

Enumerable.Join은 키가 같은 양쪽 요소의 inner equijoin이다. 한쪽 키가 두 번이면 각각의 행이 상대의 일치 행과 짝을 이룬다. 일치하지 않는 행은 결과에 없으며 모든 학생을 보존하는 left join과 다르다. 이 예제의 키는 null 없는 정수다.

중간 과정을 따라가는 예제

학생은 (민,1),(서,1),(준,2)이고 반 이름표는 (1, A),(1, B),(3, C)다. 학년별 학생 수와 학년 키 Join의 (이름, 반) 결과를 구하라.

  1. 학년 1은 민/서 두 명, 학년 2는 준 한 명이다.

  2. 민은 A/B 두 이름표와 짝을 이룬다. 서도 A/B와 짝을 이룬다.

  3. 준의 학년 2는 상대 키가 없어 빠진다.

그룹 수는 1→2 명,2→1 명이다. 조인은 (민, A),(민, B),(서, A),(서, B)의 네 쌍이다.

종이와 본문으로 직접 해보기

학생에서 학년 1만 Where한 뒤 이름을 Select하면?

힌트 보기

두 연산을 차례로 적용한다.

풀이 보기

[민, 서]다. 그룹이나 조인 없이 이름만 반환한다.

오해와 반례

Join은 같은 키가 여러 개여도 키당 한 결과만 낸다.

위 예제의 학년 1에서 학생 2×이름표 2=4 쌍이다. Distinct를 따로 하지 않았고 행의 중복을 보존한다.

답과 이유 보기

inner join은 일치 쌍만 낸다.

이름만 먼저 Select하면 학년 조인은?

답과 이유 보기

키를 유지하거나 다시 설계해야 한다.

결과에 없는 학년을 직접 읽을 수 없다.

소단원 9.3

deferred execution·materialization

질의를 만들고 나서 목록에 수를 추가하면 어떤 결과가 바뀔까?

준비 개념과 학습 목표

준비 개념

  • IEnumerable

  • 목록과 반복

학습 목표

  • 지연 실행과 결과 저장의 시점을 추적한다.

  • 스트리밍과 전체 읽기가 필요한 연산을 구별한다.

질의 변수는 결과 저장소가 아닐 수 있다

메모리 목록의 Where/Select는 보통 열거할 때 원본을 읽는 지연 질의다. 생성 시점과 실행 시점을 나누면 원본 갱신이 어느 결과에 영향을 주는지 설명할 수 있다. 반복 열거는 재계산과 부수 효과를 반복할 수 있어 비용과 일관성을 확인한다.

ToList는 그때의 요소를 저장한다

ToList나 ToArray는 질의를 열거해 새 컨테이너에 결과를 저장한다. 이후 원본의 구조 변경과 새 컨테이너는 분리되지만 요소가 가변 객체라면 참조 공유는 남을 수 있다. 깊은 복사나 원본의 영원한 불변성을 자동 보장하지 않는다.

지연과 스트리밍은 같은 말이 아니다

Where는 통과할 요소를 찾아 차례로 내보낼 수 있다. OrderBy나 GroupBy는 열거가 시작된 뒤 전체 자료를 읽어야 첫 결과를 만들 수 있다. 지연 질의라고 무한 입력을 안전하게 정렬하거나 메모리 부담 없이 그룹화할 수 있는 것은 아니다.

중간 과정을 따라가는 예제

xs=[1,2,3]에서 q=Where(짝수)를 만들고 snap=q.ToList()를 실행한다. 그 뒤 xs에 4를 추가하고 q와 snap을 각각 열거한다. 열거 도중 변경은 없다.

  1. snap을 만들 때 짝수는 2라 [2]를 저장한다.

  2. 원본을 [1,2,3,4]로 바꾼다.

  3. q의 새 열거는 2/4를 읽지만 snap은 저장한 2만 가진다.

q는 [2,4], snap은 [2]다.

힌트 보기

풀이 보기

오해와 반례

지연 실행이면 모든 연산이 한 요소씩 즉시 내보낸다.

정렬은 최소 요소를 알려면 전체를 살펴야 한다. 실행 시작을 늦추는 것과 전체 버퍼를 쓰지 않는 것은 다르다.

소단원 9.4

IEnumerable·IQueryable 차이 입문

조건식을 프로그램에서 실행하는 것과 다른 서비스에 질의로 전달하는 것은 같을까?

준비 개념과 학습 목표

준비 개념

  • 질의와 열거

  • lambda

학습 목표

  • 열거 계약과 provider 표현식 계약을 구별한다.

  • 번역과 데이터 이동의 범위를 설명한다.

IEnumerable은 요소를 열거하는 계약이다

IEnumerable<T>는 요소를 차례로 얻는 인터페이스다. 자료가 이미 전부 메모리에 있다는 뜻은 아니며 파일이나 사용자 정의 iterator도 가능하다. Enumerable의 Where는 전달한 함수를 .NET 코드로 적용하는 연산이다.

IQueryable은 질의를 provider에 표현한다

IQueryable은 요소 타입·Expression·Provider를 제공하며 표준 Queryable 연산은 식 트리로 질의를 표현한다. 열거하면 provider가 이를 실행하며 SQL 번역 같은 방식은 provider별로 다르다. 지원하지 않는 C# 함수가 자동으로 다른 언어에 번역되는 것은 아니다.

경계를 옮기면 읽는 양이 달라진다

원격 필터를 번역해 실행하면 필요한 행만 받을 수 있지만 AsEnumerable 이후의 Enumerable 필터는 로컬 실행 경계를 만든다. AsEnumerable 호출 자체가 즉시 전체 자료를 저장하는 것은 아니다. IQueryable이라는 이름만으로 반드시 원격 DB나 빠른 실행을 보장하지 않는다.

중간 과정을 따라가는 예제

교육용 원격 provider의 표는 100 행이고 score>=60을 SQL로 번역할 수 있어 20 행이 맞는다. 필터가 원격에서 수행되는 A와, 먼저 전체 행을 열거해 로컬에서 필터하는 B의 수신량을 비교하라. 캐시·다른 최적화는 없다.

  1. A는 provider가 조건을 원격에 전달하므로 맞는 20 행을 수신한다.

  2. B는 원본 100 행을 수신한 뒤 로컬에서 20 행을 남긴다.

  3. 최종 20 행은 같아도 수신량 차이는 100−20=80 행이다.

A는 20 행, B는 100 행 수신이다. 특정 provider가 조건 번역을 지원한다는 가정이 필요하다.
