소단원 2.1

lvalue·rvalue 입문

이름 있는 int&& 변수를 읽는 식은 왜 lvalue일까?

준비 개념과 학습 목표

준비 개념

  • 객체는 저장 공간과 수명을 가진 실행 대상이고 식은 이를 가리키거나 값을 계산하는 코드다. 객체와 객체를 사용하는 여러 식을 구분한다.

  • int x=3;에서 x라는 식은 이미 있는 객체를 가리킨다. x+1은 덧셈 결과를 계산한다.

  • 이번 단원의 내장 int 연산과 참조는 C++20 기준이다. 클래스 연산자 재정의는 여기의 단순 예와 다를 수 있다.

학습 목표

  • 식의 타입과 값 범주를 별도로 설명한다.

  • lvalue/prvalue/xvalue 및 두 합집합을 구분한다.

  • 이름 있는 rvalue reference와 std::move의 의미를 추적한다.

어느 객체인가와 무슨 값인가

값 범주는 변수에 영구 부착된 이름표가 아니라 식의 성질이다. lvalue는 객체 등 대상의 정체성을 정하는 식이고 xvalue가 아닌 glvalue다. prvalue는 문맥에 맞게 값을 계산하거나 객체를 초기화한다. xvalue는 자원을 재사용할 수 있는 대상을 가리키는 glvalue다. 정의만으로 수명이 끝났거나 자원이 반드시 이동했다고 결론 내리지 않는다.

glvalue는 lvalue 또는 xvalue, rvalue는 prvalue 또는 xvalue다. 각 식은 기본 세 범주 중 하나이고 xvalue가 두 합집합에 속한다. int x=3에서 x는 int lvalue, 3과 x+1은 int prvalue, std::move(x)는 int xvalue다.

대입 왼쪽이라는 이름은 불완전한 비유다

const int c=3;의 c도 객체를 가리키는 lvalue지만 내장 대입으로 수정할 수 없다. lvalue이면 언제나 쓰기 가능이라는 추론은 틀리다. 반대로 x라는 식을 오른쪽에서 사용하여 int y=x;처럼 값을 읽을 수도 있다. lvalue-to-rvalue 변환은 기존 객체의 값을 계산에 사용하는 변환이며 별칭을 자동으로 복사 객체로 바꾸는 모든 문맥의 규칙이 아니다.

일반 int x의 &x는 유효하지만 &(x+1)은 내장 주소 연산의 대상이 아니다. 모든 lvalue에 주소 연산이 된다는 단순 문구도 비트필드 같은 예외가 있다. 이 단원은 보통의 지역 int 객체만 예로 사용한다.

참조 타입과 식 범주를 각각 적는다

int&& rr=7;은 materialize된 임시 int에 rvalue reference를 묶는다. 그러나 rr라는 이름을 쓰는 식은 int lvalue다. int& alias=rr;도 가능하다. 이름으로 반복 사용할 수 있는 대상을 자동 소모하는 식으로 취급하지 않기 때문이다.

std::move는 utility의 캐스트 도구로 rr/x를 xvalue 문맥으로 제시할 뿐 그 자체가 저장값을 바꾸거나 소유권을 옮기는 실행 명령은 아니다. int의 복사/이동 초기화는 값 전달이고, 자원 가진 클래스의 이동 생성은 해당 연산 정의에 달렸다. 수명과 값 범주도 별도 축이다.

#include <utility>
int main() {
    int x = 3;
    const int c = 4;
    int&& rr = 7;
    int& alias = rr;
    alias = x + 1;
    int y = std::move(x);
    // final: x=3, c=4, rr=4, y=3
}

중간 과정을 따라가는 예제

위 코드의 x,c,x+1,rr,std::move(x)를 분류하고 최종값을 구하라.

  1. x와 c는 각각 int/const int lvalue다. c의 const는 범주를 prvalue로 바꾸지 않는다.

  2. x+1은 int prvalue 4다. rr 이름은 lvalue이며 alias가 같은 임시 int를 가리킨다.

  3. alias=4로 rr 대상값이 4가 된다. std::move(x)는 xvalue로 x의 int 값을 y에 초기화하며 x를 지우지 않는다.

x=3,c=4,rr=4,y=3. std::move(x) 호출 자체는 x의 값 변경을 하지 않는다.

종이와 본문으로 직접 해보기

int x=5; int&& rr=8; int& r=rr; r=2;에서 rr와 std::move(rr)의 범주와 최종 rr값을 구하라. c가 const라면 c=2는 가능한지도 답하라.

힌트 보기

선언 타입, 식 범주, 수정 가능성을 세 열로 나눈다.

풀이 보기

rr 이름은 lvalue, std::move(rr)는 xvalue이고 r의 쓰기로 대상값은 2다. const c 대입은 허용되지 않는다.

오해와 반례

rvalue reference로 선언한 변수는 모든 사용에서 rvalue이고 move를 쓰면 원래 값은 0이다.

rr 이름은 lvalue다. std::move(int)를 값으로 초기화한 예에서 원래 int는 그대로다. 클래스의 moved-from 상태도 해당 계약을 읽어야 한다.

자기점검

const int c의 c는 lvalue인가?

답과 이유 보기

그렇다.

const 수정 제한과 대상 정체성은 별개다.

xvalue는 rvalue이며 glvalue인가?

답과 이유 보기

둘 다다.

rvalue=prvalue∪xvalue,glvalue=lvalue∪xvalue다.

std::move(x) 자체가 x를 파괴하는가?

답과 이유 보기

아니다.

값 범주를 제공하는 캐스트이며 파괴/이동 연산은 따로다.

한 단계 더

decltype(x)와 decltype((x))의 차이를 다음 타입 추론 단원에서 조사하라. 괄호 친 lvalue 식은 int&를 얻는 규칙이 있어 선언된 타입과 식 범주를 구분한 표가 유용하다. std::move(const 객체)는 const를 지우지 않아 흔한 이동 생성자에 맞지 않고 복사가 선택될 수 있다.

소단원 2.2

참조와 포인터

참조에 다른 변수를 대입하면 참조가 다른 대상을 가리킬까?

준비 개념과 학습 목표

준비 개념

  • 주소는 객체를 가리키는 포인터 값이다. &x는 주소를 얻고 유효한 int* p의 *p는 int 객체를 가리키는 식이다.

  • 별칭은 같은 객체에 접근하는 다른 경로다. 서로 다른 이름이어도 쓰기 대상이 같을 수 있다.

  • 지역 객체는 블록의 종료에 따라 수명이 끝난다. 남은 주소나 이름이 그 객체를 다시 살리지 않는다.

학습 목표

  • 참조의 초기 결합과 대상에 대한 대입을 구분한다.

  • 포인터의 null/재지정 및 빌린 대상 수명 계약을 설명한다.

  • 일부 임시 객체의 수명 연장과 예외를 찾는다.

참조는 대상의 다른 이름으로 작동한다

int x=3; int& r=x;는 r을 x에 결합한다. 이후 r=9는 x에 9를 저장한다. int y=7; r=y;는 참조를 y로 재결합하는 문장이 아니라 y의 값을 x에 대입하는 문장이다. 참조는 초기화가 필요하며 올바른 일반 객체 참조에는 null 대상이라는 정상 상태가 없다.

int* p=&x;에서는 p 자체가 포인터 객체다. p=&y;로 대상을 바꿀 수 있고 p=nullptr;로 가리키지 않는 상태를 나타낼 수 있다. nullptr를 역참조하거나 수명 끝난 대상을 읽는 것은 허용된 접근이 아니다. 참조가 null 문법을 없애도 dangling 문제까지 막지는 않는다.

포인터와 참조는 소유권을 자동 표현하지 않는다

int&와 int*는 기본적으로 대상의 자동 소유·해제 책임을 정하지 않는다. 함수가 빌려 받는다면 대상의 수명, null 허용 여부, 수정 권한, 호출 후 보관 여부를 계약으로 적는다. 두 별칭이 같은 객체를 가리킬 수도 있다는 점은 계산 순서와 검증에 영향을 준다.

int& bad(){ int local=1; return local; }은 함수 종료 때 local 수명이 끝나 호출자에게 dangling reference를 준다. 이를 읽는 예에는 정상 출력값을 지정할 수 없다. 같은 문제는 &local을 반환하는 포인터에도 있다. 선언을 const reference로 바꿔도 이미 끝난 지역 객체 수명을 늘리지 못한다.

임시 객체 수명 연장은 제한된 규칙이다

블록에서 const int& r=7;처럼 임시 객체를 직접 결합하면 이 경우 임시 int가 r의 수명까지 유지된다. const int& s=r;로 다른 참조를 추가했다고 임시 수명이 또 연장되는 것은 아니다. 첫 결합의 종료 조건을 따라간다.

const int& identity(const int& x){return x;} 뒤 const int& d=identity(7);은 다르다. 함수 인수에 결합한 임시 7은 호출을 포함한 full expression, 여기서는 초기화 문장 끝까지만 유지된다. 문장 뒤 d는 dangling이고 읽으면 UB다. 함수에서 임시를 참조로 반환하거나 수명 끝난 지역을 반환하는 경우를 직접 결합 예와 혼동하지 않는다.

int main() {
    int x=3, y=7;
    int& r=x;
    int* p=&x;
    r=y;
    p=&y;
    *p=10;
    // final: x=7, y=10, r reads 7
}

중간 과정을 따라가는 예제

위 코드에서 r=y와 p=&y를 비교하고 마지막 x/y/r의 값을 구하라.

  1. r은 x에 결합했고 p도 처음에는 x를 가리킨다.

  2. r=y는 y값 7을 x에 저장하여 x=7이 된다.

  3. p=&y는 포인터를 재지정한다. *p=10은 y에 쓰므로 y=10, r은 여전히 x값 7을 읽는다.

x=7,y=10,r이 읽는 값 7. 대상 재지정은 p에만 일어난다.

종이와 본문으로 직접 해보기

x=1,y=2; int& r=x; int* p=&x; r=5; p=&y; *p=6;을 추적하라. 지역 x의 블록이 끝난 뒤, 살아 있을 때 p=&x로 보관했던 포인터를 통해 x의 값을 읽어도 되는가?

힌트 보기

참조 결합 화살표와 포인터 객체의 저장값을 따로 그린다.

풀이 보기

값은 x=5,y=6,r=5다. x 수명이 끝나면 그 객체를 읽는 빌린 포인터도 유효하지 않다. 주소를 보관했다는 사실은 수명 연장이 아니다.

오해와 반례

const reference로 받으면 언제나 임시 객체가 함수 밖에서도 살아 있다.

identity(7)의 참조 인수 임시는 호출 문장의 끝까지만 산다. 반환 참조를 d에 결합해도 다음 문장으로 연장되지 않는다.

자기점검

r=y는 r의 결합 대상을 y로 바꾸는가?

답과 이유 보기

아니다.

현재 참조 대상에 y 값을 대입한다.

p=nullptr 상태를 표현할 수 있는가?

답과 이유 보기

가능하다.

포인터 객체의 유효한 값이나 역참조할 대상은 없다.

지역 변수 참조를 반환한 뒤 읽어도 되는가?

답과 이유 보기

안 된다.

지역 객체 수명이 종료되어 dangling이다.

한 단계 더

참조의 수명과 대상 객체의 수명을 타임라인에 별도로 그려라. 한 함수에서 참조를 반환할 때는 호출자의 객체를 반환하는지, 내부 지역/임시를 반환하는지 확인한다. 컨테이너 재할당에 의한 참조 무효화는 이후 컨테이너 단원에서 다루며 단순 블록 수명만으로 보장하지 않는다.

소단원 2.3

const correctness

읽기 전용 경로가 있으면 다른 이름으로도 절대 바꿀 수 없을까?

준비 개념과 학습 목표

준비 개념

  • 포인터 객체와 포인터가 가리키는 대상은 서로 다른 객체다. const가 어느 쪽을 제한하는지 읽는다.

  • 별칭 x와 r이 같은 객체라면 한 경로의 변화는 다른 경로로 관찰된다.

  • 멤버 함수는 객체를 대상으로 호출하는 함수다. 데이터 멤버가 포인터라면 외부 대상도 있을 수 있다.

학습 목표

  • const T*,T* const,const T&의 수정 권한을 구분한다.

  • 원래 const 객체와 const를 통해 보는 객체를 구분한다.

  • const 멤버의 제한과 깊은 불변성/스레드 안전의 차이를 설명한다.

const의 위치마다 제한 대상이 다르다

const int* p=&x;는 p로 int를 수정할 수 없지만 p=&y로 포인터를 재지정할 수 있다. int* const q=&x;는 q를 재지정할 수 없지만 *q=4로 가리킨 수정 가능한 x를 바꿀 수 있다. const int* const both는 두 제한을 모두 갖는다.

const int& r=x;는 r 경로로 x를 수정하지 못한다. x가 원래 수정 가능한 int라면 x=8이나 다른 int&를 통해 바꾸어 r에서 8을 관찰할 수 있다. 읽기 전용 경로는 한 스냅샷을 복사하거나 객체 전체의 불변성을 자동 보장하는 것이 아니다.

원래 const 객체를 캐스트로 바꾸려 하지 않는다

const int c=3;의 c는 실제 const 객체다. const_cast<int&>(c)=4는 cast 표기가 가능해도 실제 const 객체를 수정하므로 UB다. 반면 원래 non-const x를 const 경로로 보았다가 적절히 const를 제거하면 그 객체의 원래 수정 가능성은 다르다. 그러나 API 계약을 우회하는 설계는 별도로 검토해야 한다.

int**를 const int**로 자동 변환할 수 있다고 생각하면 const 객체를 non-const 포인터에 끼워 넣는 경로가 생긴다. 한 단계 포인터의 const 추가를 무조건 여러 단계로 확장하지 않는다. 복잡한 포인터는 각 단계의 타입과 쓰기를 따로 표시한다.

const 멤버는 얕은 객체 경로의 계약이다

int get() const는 이 함수 안의 this를 const 객체를 가리키는 경로로 사용한다. 일반 비정적 데이터 멤버를 수정하거나 그 경로로 non-const 멤버 함수를 호출할 수 없다. mutable 멤버는 의도된 예외이며 캐시 같은 논리 상태 설계에 쓰인다. const 멤버는 전역 상태나 외부 대상을 전혀 바꾸지 않는 순수 함수라는 뜻도 아니다.

int* p를 데이터 멤버로 가진 객체의 const 멤버에서 *p를 수정할 수 있는 경우가 있다. const는 포인터 멤버 자체의 변경을 제한할 뿐 대상 int까지 const로 바꾸지 않는다. 서로 다른 스레드의 안전성도 자동으로 확보하지 않아 별도 동기화 계약이 필요하다.

int main() {
    int x=3, y=7;
    const int* p=&x;
    int* const q=&x;
    const int& r=x;
    *q=4;
    p=&y;
    // expected: x=4, *p=7, r=4
    // *p=9; q=&y; r=9; // each is ill-formed
}

중간 과정을 따라가는 예제

위 코드의 세 읽기 전용 경로와 주석 문장의 허용 여부를 구하라.

  1. q의 포인터 값은 고정되었지만 x는 수정 가능한 int다. *q=4로 x=4다.

  2. p의 대상 수정은 금지되지만 p 재지정은 가능하여 *p에서 y=7을 읽는다.

  3. r은 x의 별칭이라 4를 읽는다. *p=9와 r=9는 const 경로 쓰기, q=&y는 const 포인터 쓰기라 각각 ill-formed다.

x=4,*p=7,r=4 예상. 주석의 금지 문장은 UB 실행 예와 달리 정상 번역에서 허용되지 않는 코드다.

힌트 보기

읽기 전용 별칭과 실제 const 객체를 구분한다. UB에 결과값을 붙이지 않는다.

풀이 보기

r은 수정 가능한 x의 현재값 5를 읽는다. 실제 const c를 바꾸는 식은 UB이며 정상 출력값을 지정할 수 없다.

오해와 반례

const는 항상 완전한 불변성·순수성·스레드 안전을 뜻한다.

수정 가능한 x에 const reference를 묶고 다른 경로로 x를 바꾸면 관측값도 바뀐다. mutable·외부 포인터 대상·전역 상태는 별도 설계가 필요하다.

자기점검

const int* p는 p=&y를 허용하는가?

답과 이유 보기

허용한다.

가리킨 int의 수정 권한이 제한된 것이며 포인터 자체는 non-const다.

int* const q는 *q를 수정할 수 있는가?

답과 이유 보기

수정 가능한 유효 int 대상이면 가능하다.

q의 재지정만 제한된다.

ill-formed와 UB는 같은가?

답과 이유 보기

아니다.

금지된 const 경로 대입은 번역 규칙 위반이고 실제 const 객체의 cast 후 수정은 실행 UB다.

한 단계 더

논리적 const와 물리적 const의 설계 목적을 비교하라. 결과 캐시를 mutable로 두어도 관찰 가능한 계약이 같아야 논리적으로 읽기 전용이라 설명할 수 있다. 캐시 동시 갱신은 별도 데이터 레이스를 만들 수 있어 const 표지만으로 thread-safe라고 쓰지 않는다.

소단원 2.4

값·참조 매개변수 선택

참조로 바꾸면 모든 함수가 더 빠르고 더 안전해질까?

준비 개념과 학습 목표

준비 개념

  • 매개변수는 호출 때 함수에 전달하는 값을 받는 선언이다. int 값 매개변수는 호출자의 int와 별도 객체다.

  • 빌림은 대상의 소유·수명을 가져오지 않고 정한 동안 접근하는 계약이다.

  • 두 인수가 같은 객체일 수 있음을 aliasing이라 한다. 값의 복사와 주소의 복사를 구분한다.

학습 목표

  • 입력·수정·선택 대상 계약에 맞는 매개변수를 고른다.

  • int by-value/by-reference를 실제 상태 표로 추적한다.

  • 반환·보관 참조의 수명과 별칭 조건을 명시한다.

작은 값은 복사하여 독립 상태를 얻는다

void value(int n){n+=1;}은 int 매개변수 객체 n만 수정한다. 호출자 x는 바뀌지 않는다. 이는 모든 타입에서 무조건 깊은 복사가 된다는 뜻은 아니다. int*를 값으로 받아도 복사된 것은 주소라 같은 대상을 수정할 수 있고 클래스의 복사 의미는 해당 타입이 정한다.

C++ Core Guidelines는 작고 싸게 복사하는 입력을 값으로, 큰 읽기용 입력을 const reference로 받도록 권고한다. 실제 비용은 타입·ABI·최적화·호출 경로에 달렸다. 모든 참조가 더 빠르다는 법칙은 없고 이번 단원은 성능을 측정하지 않았다.

참조는 권한과 보관 여부를 드러내야 한다

void change(int& n){n+=1;}은 호출자 객체에 쓰는 in-out 계약이다. 값이 INT_MAX 미만이라는 사전조건이 필요해 signed overflow를 피한다. const int&는 해당 경로로 쓰지 않는 입력 계약으로 쓸 수 있지만 다른 별칭의 변경이나 임시 수명 종료를 차단하지 않는다.

null이 의미 있는 선택 대상에는 포인터나 별도 optional 모형을 고려한다. int&는 일반 유효 대상의 필수 결합을 표현한다. “함수 안에서만 빌림, 호출 후 참조·주소를 보관하지 않음”을 명시하면 임시 인수를 받는 const reference 함수도 호출 동안 안전하게 사용할 수 있다.

별칭과 반환 수명이 결과를 바꾼다

void steps(int& a,int& b){a=1;b+=a;}를 같은 x로 호출하면 a,b가 한 객체다. x=5에서 첫 쓰기로 x=1, 두 번째로 x=2다. 서로 다른 y=5,z=5로 호출하면 y=1,z=6이다. 두 입력이 서로 다르다는 가정이 필요하다면 사전조건으로 명시해야 한다.

입력 const reference를 반환하는 함수도 호출자의 대상이 충분히 살아 있을 때만 반환 참조를 보관할 수 있다. 임시 인수를 반환하여 문장 뒤 쓰는 경우에는 dangling이다. 독립 결과값을 반환하거나 호출자의 수명 보장을 계약으로 표현하는 선택을 비교한다.

void value(int n) { n += 1; }
void change(int& n) { n += 1; }
void steps(int& a, int& b) { a=1; b+=a; }
int main() {
    int x=5;
    value(x); // x=5
    change(x); // x=6
    steps(x,x); // x=2
}

중간 과정을 따라가는 예제

위 세 호출을 차례로 추적한다. 모든 입력은 작은 int이고 함수는 참조를 보관하지 않는다.

  1. value(x)의 n은 5의 별도 int 복사다. n이 6이어도 반환 후 x=5다.

  2. change(x)의 n은 x의 별칭이라 x=6이다.

  3. steps(x,x)의 두 참조는 동일 x다. a=1 뒤 b+=a는 같은 저장값 1+1이라 x=2다.

호출 후 x는 차례로 5,6,2이다. 코드가 정의되지만 인수 독립성을 가정한 의도와는 다를 수 있다.

종이와 본문으로 직접 해보기

y=5,z=5에서 steps(y,z)를 추적하고 steps(y,y)와 비교하라. const reference로 임시 입력을 받아 주소를 저장해 다음 문장에서 쓰는 설계의 수명 문제를 설명하라.

힌트 보기

이름 개수보다 객체 개수를 세어라. 임시는 호출 full expression의 종료가 중요하다.

풀이 보기

서로 다르면 y=1,z=6, 같은 대상이면 y=2다. 임시 대상의 저장 주소는 호출 문장 뒤 dangling일 수 있어 보관 금지 또는 독립 값 소유가 필요하다.

오해와 반례

값 매개변수는 항상 원본을 전혀 바꾸지 않고 참조는 항상 복사보다 빠르다.

포인터를 값으로 받아도 그 주소의 대상에 쓸 수 있다. int 작은 값 복사는 단순하며 참조는 간접 접근·별칭의 비용을 가질 수 있다. 성능 주장은 같은 환경에서 측정해야 한다.

한 단계 더

입력·출력·in-out·소유 이전을 표로 구분하고 실제 함수 시그니처 옆에 수명/별칭/실패 조건을 적어라. 큰 값 반환은 이동·복사 생략과 연결되므로 비용을 무조건 큰 복사로 세지 않는다. 이 단원은 개념 선택 기준이며 vector/RAII/이동 구현의 실제 비용은 이후 단원에서 측정한다.
