소단원 5.1

표준 algorithm

배열의 모든 값을 직접 반복문으로만 검사해야 할까?

준비 개념과 학습 목표

준비 개념

  • 반복자는 원소 위치를 가리키고 다음으로 이동하는 약속을 가진다.

  • [first,last)는 처음 위치를 포함하고 끝 위치는 포함하지 않는다.

  • 교육 코드는 C++20 콘솔 문맥이며 컴파일·실행하지 않았다. 아래 반환은 종이 예상이다.

학습 목표

  • 문제 목적에 맞게 find/count_if/sort 를 고른다.

  • 반열린 범위와 끝 반복자의 의미를 설명한다.

  • 알고리즘 요구·변경 여부·반환값을 확인한다.

자료와 처리 방법을 나눈다

표준 알고리즘은 반복자로 지정한 범위에서 찾기·세기·정렬 같은 작업을 수행한다. std::find 는 값과 같은 첫 원소 위치를 돌려주고 std::count_if 는 조건이 참인 원소 수를 돌려준다. 같은 vector 에도 원하는 결과에 따라 다른 알고리즘을 선택한다. 함수를 호출했다는 사실만 아니라 입력 범위·조건·반환의 뜻을 읽어야 한다.

알고리즘이 어떤 반복자를 요구하는지도 중요하다. std::sort 는 임의 접근이 가능한 반복자가 필요하고 정렬할 원소를 바꿀 수 있어야 한다. vector 에는 맞지만 std::list 의 반복자를 같은 sort 에 넣을 수는 없다. list 에는 별도 멤버 sort 가 있다. 모든 컨테이너에 모든 표준 알고리즘이 자동으로 적용되는 것은 아니다.

끝은 원소가 아니다

begin 은 시작 위치, end 는 마지막 원소 바로 뒤의 경계다. 값이 없거나 찾지 못하면 end 를 반환할 수 있고 그 위치를 역참조해서 값을 읽으면 안 된다. 빈 범위는 begin 과 end 가 같은 유효한 경계이며 count 결과는 0 이고 find 결과는 끝이다.

std::find(v.begin(),v.end(),4)는 이 범위의 첫 4 를 찾는다. 찾은 위치를 사용하기 전에 v.end()와 비교한다. 배열이 정렬되지 않았어도 선형 find 의 뜻은 유효하다. 이진 탐색처럼 정렬·분할 조건이 필요한 다른 알고리즘과 이름만 비슷하다고 같은 조건으로 읽지 않는다.

바꾸는 작업과 관찰하는 작업

find 와 count_if 는 입력 원소를 바꾸는 작업이 아니다. sort 는 원소의 순서를 바꾸므로 원래 순서가 필요하면 복사한 자료를 정렬하는 선택이 필요하다. 조건 함수도 그 인수로 원소를 변경하지 않아야 한다. 알고리즘의 결과 계약과 원래 자료 보존 요구를 함께 읽는다.

아래 프로그램의 출력은 원소 값을 종이로 대조한 예상이며 컴파일러나 실행 환경으로 확인한 결과가 아니다. 계산한 원소 개수와 실제 걸린 시간도 다른 주장이다. 복잡도 상한을 배웠다고 장비의 시간을 측정한 것은 아니다.

#include <algorithm>
#include <iostream>
#include <vector>
int main() {
    std::vector<int> v{4,1,4,2,7};
    auto p = std::find(v.begin(), v.end(), 4);
    auto n = std::count_if(v.begin(), v.end(), [](int x){ return x % 2 == 0; });
    if (p != v.end()) std::cout << (p - v.begin()) << " ";
    std::cout << n << "\n";
}

중간 과정을 따라가는 예제

위 C++20 코드의 find 위치와 짝수 count 및 예상 출력은 무엇인가? find 가 찾지 못한 경우에도 *p 를 읽을 수 있는가?

  1. 범위는 인덱스 0~4 의 4/1/4/2/7 이며 end 는 인덱스 5 의 경계다.

  2. 첫 4 는 인덱스 0 이므로 p−begin 은 0 이다. 뒤의 4 가 아니라 첫 일치 위치다.

  3. 짝수 조건은 참/거짓/참/참/거짓으로 참 3 개다. count_if 는 위치가 아니라 개수를 반환한다.

  4. if 조건이 참이라 위치 0 뒤 개수 3 을 출력하므로 예상 한 줄은 0 3 이다.

  5. 없는 값 9 를 찾으면 p=end 라 *p 를 읽으면 안 된다. 실제 실행을 하지 않아 출력은 종이 예상으로 기록한다.

예상 출력 0 3. 미일치 끝 반복자는 검사한 뒤 사용하며 역참조하지 않는다.

종이와 본문으로 직접 해보기

범위를 [begin+1,end)로 바꾸어 4 를 찾는 절대 인덱스와 짝수 수를 구하라. 이어 [begin,begin)에서 두 결과를 적어라.

힌트 보기

시작이 1 이면 처음 4 는 제외된다. 끝은 포함하지 않는다.

풀이 보기

인덱스 1~4 에서 첫 4 의 절대 인덱스는 2,짝수는 4 와 2 두 개다. 빈 범위의 find 는 전달된 끝(begin)을 반환하고 count_if 는 0 이다. 빈 범위의 반환 경계도 원소처럼 읽지 않는다.

오해와 반례

end 는 마지막 원소이므로 find 실패 뒤 *end 를 읽으면 된다.

길이 5 의 end 는 인덱스 5 경계다. 마지막 원소 7 은 인덱스 4 이며 end 를 역참조하는 동작과 다르다. 없는 9 탐색이 반례다. 위험한 역참조는 실행하지 않고 종이에서 금지 동작으로 판정한다.

자기점검

count_if 가 돌려주는 것은 조건을 만족한 첫 위치인가?

답과 이유 보기

아니다.

조건이 참인 원소의 수다. 첫 위치를 원하면 find_if 등을 고른다.

std::sort 를 list 반복자에 그대로 적용할 수 있는가?

답과 이유 보기

없다.

sort 의 임의 접근 요구를 list 반복자가 만족하지 않는다. list 의 멤버 sort 는 별도 작업이다.

원래 v 에 4 가 두 개면 find 결과도 두 개인가?

답과 이유 보기

아니다.

find 는 첫 일치 반복자 하나를 반환하고 개수는 count 같은 다른 작업이다.

한 단계 더

같은 자료에서 find_if 로 7 보다 큰 첫 값을 찾는 계약을 적어 보자. 값이 없을 때의 처리와 원래 자료 보존을 먼저 정한다. 비교 횟수의 상한과 실제 실행 시간을 다른 열에 기록하는 계획도 만들어 보되 장비 측정 결과를 만들어 쓰지 않는다.

소단원 5.2

lambda와 capture

함수를 만들 때 본 변수 값과 호출할 때 변수 값은 항상 같을까?

준비 개념과 학습 목표

준비 개념

  • lambda 는 짧게 호출 가능한 객체를 만드는 표현이다.

  • 캡처는 바깥 지역 변수에 접근하는 방법을 정한다.

  • 아래는 단일 스레드·변수 수명 내 C++20 종이 추적이며 실제 컴파일·실행이 아니다.

학습 목표

  • 값과 참조 캡처를 생성 시점과 호출 시점으로 구분한다.

  • mutable 의 효과가 외부 변수와 내부 복사본 중 어디에 생기는지 설명한다.

  • 참조 대상의 수명과 호출 가능 기간을 확인한다.

표현이 호출 객체를 만든다

[base](int x){return base+x;}를 평가하면 함수처럼 호출할 수 있는 클로저 객체가 생긴다. x 는 호출할 때 전달하는 인수이고 base 는 바깥에서 캡처한 환경이다. 객체를 만들기만 하면 본문은 아직 실행되지 않는다. auto f=... 뒤 f(2)처럼 호출하는 단계가 따로 있다.

값 캡처[base]는 이 예제의 int 값을 객체 안에 복사해 보관한다. 참조 캡처[&base]는 외부의 살아 있는 base 를 참조한다. [=]와[&]는 캡처 기본 방식을 정하지만 범위를 무작정 넓히기보다 필요한 이름을 명시하면 읽는 사람이 의존성을 찾기 쉽다. 포인터 값 복사는 가리키는 대상까지 깊은 복사를 한다는 뜻이 아니다.

mutable 은 복사본의 상태를 바꾼다

일반 lambda 는 mutable 없으면 호출 연산자가 const 여서 캡처한 int 복사본을 본문에서 증가시킬 수 없다. [n]() mutable {return ++n;}처럼 만들면 객체 안의 n 을 바꿀 수 있다. 이 변화는 같은 이름의 외부 n 을 바꾸지 않는다.

mutable 이 참조 캡처 대상의 수명 연장을 만드는 것은 아니다. 참조한 외부 int 를 바꾸는 lambda 는 그 대상이 살아 있을 때만 사용한다. 같은 클로저의 상태를 여러 스레드가 바꾸는 상황에는 별도 동기화 문제가 생기며 이 단원의 단일 스레드 계산으로 안전성을 일반화하지 않는다.

수명이 끝난 참조는 해결되지 않는다

함수의 지역 int 를 참조 캡처해 반환하고 함수가 끝난 뒤 그 지역 값을 읽는 호출은 이미 끝난 대상에 접근한다. 참조 캡처는 대상의 수명을 연장하지 않는다. 이런 예는 실행해 임의 출력이 나오면 괜찮다고 판단하지 않고 종이에서 잘못된 수명 사용으로 판정한다.

값 캡처는 int 처럼 스스로 값을 가진 대상을 보관하는 경우와 포인터·참조 래퍼처럼 간접 접근을 보관하는 경우를 구분해야 한다. 반환용 클로저를 만들기 전에 캡처하는 값의 소유와 수명을 확인한다. 아래는 외부 base 가 main 의 끝까지 살아 있어 참조 사용이 허용되는 예다.

#include <iostream>
int main() {
    int base = 3;
    auto by_value = [base](int x){ return base + x; };
    auto by_ref = [&base](int x){ return base + x; };
    auto step = [base]() mutable { return ++base; };
    base = 10;
    std::cout << by_value(2) << " " << by_ref(2) << " ";
    std::cout << step() << " " << step() << " " << base << "\n";
}

중간 과정을 따라가는 예제

위 코드에서 클로저 생성 뒤 base=10 을 실행한다. by_value(2),by_ref(2),step 두 번, 마지막 외부 base 의 값을 순서대로 종이 계산하라.

  1. 세 객체를 만들 때 외부 base 는 3 이다. by_value 와 step 은 각자의 int 복사 3 을 보관하고 by_ref 는 외부 base 를 참조한다.

  2. 외부 base=10 은 두 복사본을 바꾸지 않는다. by_value(2)는 3+2=5 다.

  3. by_ref(2)는 살아 있는 외부 값 10 을 읽어 10+2=12 다.

  4. step 은 자신의 복사 3 을 4 로 늘려 4 반환,다음 호출에서 4 를 5 로 늘려 5 반환한다. 두 출력문에서 호출은 순서대로 진행된다.

  5. 외부 base 는 여전히 10 이므로 예상 출력 5 12 4 5 10 이다. 교육 코드는 실제 실행하지 않았다.

종이 예상은 5 12 4 5 10. mutable 은 step 객체의 복사본만 바꾼다.

종이와 본문으로 직접 해보기

step 을 한 번 호출해 내부 값 4 가 된 뒤 auto copy=step 으로 복사한다고 정하자. copy 두 번과 step 한 번을 순서대로 호출할 때 각 반환과 외부 base 를 적어라.

힌트 보기

복사 시점의 상태 4 를 별도 객체가 받는다. 두 내부 값에 다른 이름을 붙여라.

풀이 보기

copy 는 4→5→6 으로 5 와 6 을 반환하고 원래 step 은 4→5 로 5 를 반환한다. 외부 base 는 10 이다. 같은 객체를 두 이름으로 참조한 것이 아니라 이 값 캡처 클로저를 복사한 사례다.

오해와 반례

값 캡처 뒤 mutable 로 값을 바꾸면 외부 변수도 바뀐다.

step 의 두 호출은 내부 3→4→5 지만 외부 base 는 10 이다. 이름이 같아도 저장 장소가 다르다. 반대로 참조 캡처는 외부 대상을 가리키지만 대상의 수명은 늘리지 않는다.

소단원 5.3

predicate·comparator

정렬 비교 함수가 같음까지 참이라고 하면 더 정확한 비교일까?

준비 개념과 학습 목표

준비 개념

  • predicate 는 어떤 조건을 만족하는지 판단하고 comparator 는 앞에 둘 순서 관계를 판단한다.

  • 정렬의 compare(a,b)=true 는 a 를 b 보다 앞에 두는 엄격한 관계를 뜻한다.

  • 잘못된 비교 함수는 실제 sort 에 넣어 실행하지 않고 관계 조건으로 종이 판정한다.

학습 목표

  • 한 원소 조건과 두 원소의 순서를 구분한다.

  • strict weak ordering 의 핵심 조건을 작은 반례로 검사한다.

  • 비교상 동등과 객체의 같음을 구분한다.

조건 검사와 순서 검사는 다르다

x≥3 은 한 원소가 기준을 통과하는지 묻는다. a<b 는 두 원소 중 첫 것을 앞에 둘지 묻는다. count_if 에 쓰는 단항 predicate 와 sort 의 두 인수 comparator 는 입력 수와 뜻이 다르다. 조건에 맞는 원소를 고르는 작업이 자료 전체의 순서를 정하는 작업은 아니다.

원소를 검사하는 함수가 검사 과정에서 그 인수를 바꾸면 알고리즘 요구를 어길 수 있다. 알고리즘은 함수객체를 복사할 수 있으므로 객체 내부 호출 수를 이용해 순서가 매번 바뀌게 만들거나 복사본의 정확한 호출 횟수를 결과로 가정하지 않는다. 여기서는 순수한 정수 비교로 고정된 관계를 만든다.

엄격하고 약한 순서의 조건

정렬 비교는 자기 자신보다 앞이라고 하지 않아야 한다: comp(x,x)=false 다. a 가 b 보다 앞이고 b 가 c 보다 앞이면 a 도 c 보다 앞이라는 추이성도 필요하다. 두 방향 모두 false 이면 비교 기준에서 동등하다고 정하고 이 동등 관계의 추이성도 필요하다. 단지 참거짓을 반환하는 함수라고 요구를 만족하지 않는다.

정수의 <는 여기서 이 조건을 만족하지만 <=는 같은 값 비교에서 true 여서 비반사성을 위반한다. 가위바위보처럼 0 이 1 앞, 1 이 2 앞, 2 가 0 앞이라는 순환도 추이성을 위반한다. 이러한 잘못된 관계를 sort 에 넣어 결과를 관찰하는 활동 대신 작은 입력의 조건 위반을 종이에서 밝힌다.

동등한 기준과 안정성

학습 카드의 점수만 비교하면 서로 다른 카드도 점수가 같을 때 두 방향 비교가 false 가 된다. 이것은 카드의 모든 필드가 같다는 뜻이 아니다. std::sort 는 동등한 원소의 원래 순서를 보존한다고 보장하지 않는다. 그 순서가 필요하면 stable_sort 계약을 확인하거나 두 번째 기준을 명시한다.

점수 오름차순 후 id 오름차순이라는 두 기준은 먼저 점수를 비교하고 같으면 id 를 비교한다. 유효한 동일 기준을 전체 범위에 일관되게 적용해야 한다. 호출 때마다 외부 점수가 변하는 것처럼 관계가 달라지면 초기 순수 모형의 증명이 유효하지 않다. NaN 이 포함된 부동소수점 등은 별도의 정책이 필요하여 여기서는 정수 점수만 쓴다.

중간 과정을 따라가는 예제

카드 A(id 1, 점수 5), B(id 2, 점수 3), C(id 3, 점수 5)를 점수 오름차순으로 비교한다. comp(A,C),comp(C,A),comp(B,A)와 가능한 정렬 순서, 점수 후 id 기준의 순서를 구하라.

  1. 정수 점수만 비교하므로 5<5 는 false 다. comp(A,C)=false 다.

  2. 역방향 comp(C,A)도 false 라 A/C 는 이 비교 기준에서 동등하다. id 는 서로 달라 객체가 완전히 같다는 뜻은 아니다.

  3. comp(B,A)는 3<5=true 여서 B 가 A 보다 앞에 온다. C 와의 비교도 같다.

  4. 점수만으로 std::sort 의 최종 순서는 B,A,C 또는 B,C,A 가 가능하다. 실제 알고리즘이 둘 중 어느 것을 냈다고 주장하지 않는다.

  5. 점수가 같으면 id 를 비교하는 기준은 id 1<3 으로 A 가 C 앞이므로 B,A,C 다.

점수 동등 A/C 두 방향 false, B 앞. 점수만이면 동등 순서 미보장, 점수 후 id 면 B,A,C.

종이와 본문으로 직접 해보기

comp(x,y)=x<=y 에서 x=y=2 를 검사하라. 또 정수 0/1/2 에서 0≺1,1≺2,2≺0 만 참인 관계의 추이성을 검사하라. 어느 함수도 실제 sort 로 시험하지 않는다.

힌트 보기

자기 비교 조건과 연속 두 비교의 결과를 확인한다.

풀이 보기

<=는 2<=2 가 true 여서 비반사성 실패다. 순환 관계는 0≺1 과 1≺2 가 참인데 0≺2 는 거짓이라 추이성 실패다. true/false 반환 타입만 맞아도 정렬 계약을 만족하지 않는 두 반례다.

오해와 반례

comp(a,b)가 false 면 두 원소가 같다.

A 점수 5/B 점수 3 에서 comp(A,B)=false 지만 comp(B,A)=true 다. 동등은 양방향 모두 false 여야 하며 그 경우에도 점수 같음은 객체의 모든 값 같음과 다르다.

자기점검

답과 이유 보기

자기 비교가 true 다.

엄격 관계는 comp(x,x)=false 여야 한다.

std::sort 는 점수 동등 A/C 의 원순서를 항상 보존하는가?

답과 이유 보기

보장하지 않는다.

동등 원소의 순서 보존은 별도 안정성 요구다.

두 인수 comparator 를 단항 count_if 조건에 그대로 넣는가?

답과 이유 보기

아니다.

소단원 5.4

범위 알고리즘 입문

처음과 끝을 직접 넘기는 대신 자료 전체를 넘기면 무엇이 달라질까?

준비 개념과 학습 목표

준비 개념

  • C++20 의 std::ranges 알고리즘은 범위 객체를 받는 형태와 반복자/경계를 받는 형태가 있다.

  • projection 은비교할속성을꺼내는함수이지원소를지우는작업이 아니다.

  • C++20 지원 환경을 가정한 소스 읽기이며 실제 컴파일러 기능 시험은 미수행이다.

학습 목표

  • 범위 전달과 projection 의 의미를 설명한다.

  • 범위 제약이 문법 오류와 실제 의미 조건을 모두 자동 증명하지 않음을 설명한다.

  • 임시 범위의 dangling 과끝 검사를 구별한다.

범위와 요구 조건

std::ranges::find(v,4)는 v 전체의 begin/end 를 통해 찾기를 표현한다. 범위가 있다고 읽기·정렬에 필요한 모든 조건이 자동으로 만족되는 것은 아니다. ranges::sort 는 임의 접근 및 변경 가능한 정렬 요구 등을 제약으로 표현하며 부적합한 범위는 허용되지 않을 수 있다.

제약은 타입과 호출 가능성 등 일부 오류를 일찍 드러내지만 순환하는 비교 관계가 추이적인지 모든 실행 값에서 자동 검사해 주지는 않는다. 같은 범위·동일 관계·원소 수명 조건을 계속 확인해야 한다. 이름에 ranges 가 붙었다고 모든 문제의 안전 검증을 끝낸 것이 아니다.

projection 은 비교할 값을 꺼낸다

카드 전체를 유지하면서 점수로 정렬하려면 std::ranges::sort(cards,{},&Card::score)처럼 점수 멤버를 projection 으로 지정할 수 있다. {}는 여기서 기본 비교 객체를 사용한다는 인수이며 순수 정수 점수만 쓴다. 이름과 id 는 자료에서 사라지지 않고 카드 원소 전체가 새 순서로 이동한다.

projection 은 조건 함수나 비교 앞에 적용해 값을 추출한다. 관계대수 투영처럼 열을 지운 새 표를 만드는 말과 혼동하지 않는다. 같은 점수의 원순서는 ranges::sort 에서도 보장되지 않는다. 아래 count 는 점수 값에 같음 비교를 적용하여 5 점 카드의 수를 센다.

#include <algorithm>
#include <iostream>
#include <vector>
struct Card { int id; int score; };
int main() {
    std::vector<Card> cards{{1,5},{2,3},{3,5}};
    auto n = std::ranges::count(cards, 5, &Card::score);
    std::ranges::sort(cards, {}, &Card::score);
    std::cout << n << " " << cards.front().id << "\n";
}

돌려받은 위치의 수명

이름 있는 vector 를 넘긴 find 결과는 그 자료가 살아 있고 반복자가 무효화되지 않는 동안에만 사용한다. 값을 못 찾으면 끝인지 검사해야 한다. 실제 역참조 허용성은 자료 수명과 위치가 유효한지 둘 다 필요하다.

borrowed range 가 아닌 임시 vector 를 범위 인수로 넘기면 임시 자료가 사라진 뒤 위치를 쓸 위험이 있다. ranges 알고리즘은 이 경우 반환 타입을 std::ranges::dangling 으로 대체할 수 있으며 그것을 반복자처럼 역참조할 수 없다. 이것은 자료를 자동으로 영원히 보관한다는 뜻이 아니다. 타입의 dangling 과 실제 무효화된 반복자를 구별해 읽는다.

중간 과정을 따라가는 예제

위 C++20 카드 코드에서 n, 정렬 뒤 첫 id, 가능한 전체 id 순서를 종이 계산하라. projection 뒤 카드가 점수 int 만 남는가?

  1. 입력 점수는 5/3/5 이고 점수 projection 은 각 카드에서 해당 int 를 비교용으로 꺼낸다.

  2. 5 와 같은 점수의 카드는 id 1/3 두 개라 n=2 다.

  3. 정수 점수 오름차순에서 점수 3 인 id 2 가 유일한 최솟값이라 첫 id 는 2 다.

  4. 동등 5 점의 순서 보장 없으므로 전체 id 는 2/1/3 또는 2/3/1 일 수 있다. 원소는 Card 전체로 남아 id 를 읽을 수 있다.

  5. 예상 출력 2 2 는 이 계약 아래 종이 결과며 실제 컴파일·실행·정렬 내부 순서 측정은 하지 않았다.

n 2/첫 id 2/예상 출력 2 2. 카드 전체가 보존되며 동등 점수의 세부 순서는 미보장이다.

종이와 본문으로 직접 해보기

이름 있는 vector<int> v{2,4,6}에서 ranges::find(v,9)의 위치 사용 조건을 설명하라. 임시 vector<int>{2,4,6}를 직접 넘긴 find 결과의 타입과 수명도 비교하라. 실제 코드는 실행하지 않는다.

힌트 보기

이름 있는 v 의 끝 경계와 임시 범위의 dangling 반환은 다른 질문이다.

풀이 보기

v 에서 9 는 없어 end 위치다. v 가 살아 있어도 그 끝을 역참조할 수 없다. 임시 vector 를 직접 넘긴 range overload 결과는 borrowed 범위가 아니므로 dangling 으로 대체되어 반복자처럼 읽을 수 없다. 이름 있는 범위에서도 vector 파괴·재할당 등으로 위치가 무효화될 수 있다.

오해와 반례

ranges 를 쓰면 어떤 반환 위치도 언제나 안전하게 읽을 수 있다.

이름 있는 v 의 미일치 end 도 역참조할 수 없으며 임시 vector 의 dangling 은 반복자 자체가 아니다. 기존 반복자도 자료 변경으로 무효화될 수 있다. 범위 기능은 이 조건들을 없애지 않는다.

같은 카드 목록을 점수 후 id 기준으로 정렬하는 comparator 와 단일 점수 projection 방식을 비교하라. 필요한 동등 처리·반환 위치·자료 수명 조건을 각각 기록한다. view 와 지연 평가는 별도 기능이며 이번 범위 알고리즘의 즉시 계약과 같다고 단정하지 않는다.
