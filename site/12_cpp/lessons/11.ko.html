operator overload의 규칙

내 좌표 타입의 +를 만들면 +의 우선순위도 바꿀 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 피연산자와 우선순위

학습 목표

  • 작은 값의 연산을 손으로 추적한다

  • 자연스러운 의미와 범위 조건을 명시한다

같은 덧셈이라도 새 값과 별칭을 구별할 수 있을까?

새 작은 값 타입 Amount는 int n을 저장한다. Amount& operator+=(Amount rhs)는 현재 n에 rhs.n을 더하고 return *this를 수행한다. 비멤버 Amount operator+(Amount lhs,Amount rhs)는 lhs+=rhs를 수행한 뒤 lhs를 값으로 반환한다. 여기서는 모든 입력·중간 결과가 -100..100 안에 있고 함수는 예외를 던지지 않는다. 각 비교는 새 객체에서 독립적으로 시작한다.

같은 + 기호를 사용해도 입력을 바꾸는지, 반환값이 새 객체인지, 기존 객체의 별칭인지의 책임은 우리가 만든 함수 본문에 달려 있다. +=의 참조 반환은 연속 호출이 같은 객체를 다시 수정하게 하고 +의 값 반환은 원래 입력을 유지한다. 문법적 결합 규칙과 이 의미 계약이 일치하는지도 별도로 확인한다. 언어가 +와 +=의 관계를 자동으로 생성하거나 증명하지는 않는다.

이 보강의 Amount 사례는 C++17 이상 연산자 표기 규칙을 사용하며 복사는 n을 그대로 복사한다. 복합 대입은 오른쪽 피연산자를 왼쪽보다 먼저 평가한다. 참조 반환으로 연속 수정할 수 있다는 사실만으로 괄호 속 왼쪽이 먼저 계산된다고 가정하지 않는다. 명시적인 두 문장과 하나의 중첩 표현식을 별도로 추적한다.

익숙한 기호에 함수 의미를 준다

연산자 오버로딩은 사용자 타입에 기존 연산자 기호의 동작을 정의하는 기능이다. 아래 C++17 예제는 두 Point의 각 성분을 더해 새 Point를 반환한다. 원래 입력 객체를 바꾸는 +=와 새 값을 만드는 +의 계약을 구분한다.

비멤버 이항 연산자 함수는 두 인수를 받는다. 일반 산술 연산자 오버로드에는 적어도 한 클래스 또는 열거형 타입의 인수가 필요하므로 int와 int의 +를 새로 정의하지 못한다. 메모리 할당 등 별도 규칙이 있는 연산자는 이 예제 범위 밖이다.

기호의 문법은 유지된다

+를 오버로드해도 우선순위, 결합 방향, 피연산자 개수는 바뀌지 않는다. a + b * c는 여전히 곱셈 부분을 먼저 묶는 표현식이다. 새로운 @ 기호를 만들거나 점 접근 . 및 조건 연산자 ?:를 오버로드할 수 없다.

가능한 기호와 적절한 의미는 별개다. 좌표 합을 출력 부작용이나 파일 삭제로 정의하면 읽는 사람이 예측하기 어렵다. ==를 정의한다고 +나 <가 자동으로 따라오는 것도 아니며 수학적 항등식이 자동 보장되지 않는다.

작은 모델의 경계를 쓴다

Point의 int 성분 합은 표현 범위 안에서만 이 예제 계약을 만족한다. 여기서는 각 입력 성분을 -100부터 100으로 제한해 결과 -200부터 200을 손 계산한다. 실제 일반 좌표 클래스라면 입력 제한이나 덧셈 전 범위 검사를 설계해야 한다.

반환한 새 값과 입력 값이 어떻게 달라지는지 확인한다. const 참조로 인수를 받는 설계도 가능하지만 이 작은 구조체는 값 인수로 단순화했다. 복사 비용과 예외 정책은 타입 규모에 따라 별도로 결정한다.

같은 덧셈이라도 새 값과 별칭을 구별할 수 있을까?
표현식 또는 관계관찰할 값·상태설계에서 남는 조건

a.n=2,b.n=3에서 c=a+b

c.n=5 / a.n=2,b.n=3

+는 lhs의 값 복사본을 수정

같은 초기 상태에서 Amount& r=(a+=b)

a.n=5 / r은 a의 별칭

참조는 새 Amount가 아님

같은 초기 상태에서 (a+=b)+=Amount{4}

a.n=9 / b.n=3

첫 결과가 a를 참조

같은 초기 상태에서 Amount r=(a+=b); r+=Amount{4}

a.n=5 / r.n=9

호출자의 값 변수는 복사

각 행은 초기 상태를 다시 만든다. Amount& r과 Amount r의 선언에서 &를 먼저 읽고, 반환 함수의 형식과 호출자 변수의 형식을 따로 표시한다.

중간 과정을 따라가는 예제

아래 함수로 a={2,3}, b={4,-1}의 a+b와 a의 이후 값을 추적하라. 

struct Point { int x; int y; };
Point operator+(Point a, Point b) {
    return {a.x + b.x, a.y + b.y};
}

  1. x 합은 2+4=6이다.

  2. y 합은 3+(-1)=2이다.

  3. 새 객체 {6,2}를 반환하며 값 인수의 a와 b 및 호출자의 입력을 수정하지 않는다.

합은 {6,2}, 원래 a는 {2,3}이다. 실행하지 않고 문장 의미로 추적했다.

조건을 바꾸어 비교하기

새 합과 입력 보존

a.n=2,b.n=3에서 Amount c=a+b; c+=Amount{4};의 세 객체 값을 추적하라.

  1. +의 lhs 복사본은 5가 되어 c의 값이 된다.

  2. c만 추가 4를 받아 9가 된다.

a는 2, b는 3, c는 9다.

비교할 점

base Point의 성분 합을 한 성분 타입으로 바꾸고 후속 변경의 별칭 여부를 추가 검사한다.

참조 결과와 값 변수는 다르다

두 새 비교를 각각 a.n=2,b.n=3에서 시작한다. 첫째는 Amount& r=(a+=b); r+=Amount{4};, 둘째는 Amount r=(a+=b); r+=Amount{4};다.

  1. 두 경우 모두 첫 +=가 a를 5로 만든다.

  2. 첫째 r은 a와 같아 추가 변경이 a를 9로 만든다. 둘째 r은 값 복사본이라 a는 5다.

첫째 a/r은 같은 객체의 9, 둘째 a는 5이고 r은 9다.

비교할 점

함수의 참조 반환을 호출자도 반드시 참조로 받는 것은 아니다.

연습 1 · 값과 상태 예측

새 a.n=2,b.n=3에서 C++17 이상 연산자 표기 (a+=b)+=a를 추적하라. rhs는 값 인수이며 Amount의 복사는 n을 그대로 복사한다.

힌트 1

바깥 복합 대입은 오른쪽 피연산자를 왼쪽보다 먼저 평가한다.

힌트 2

바깥 rhs의 a 값 복사 뒤 왼쪽 (a+=b)가 a를 5로 만든다.

풀이와 답 확인

  1. 바깥 +=의 오른쪽 값 인수 rhs에는 초기 a.n=2를 먼저 복사한다.

  2. 이어 왼쪽 (a+=b)는 b의 3을 더해 a.n=5로 만들고 a의 참조를 반환한다.

  3. 바깥 +=는 그 a의 5에 이미 복사한 rhs.n=2를 더하므로 7이다.

a.n=7,b.n=3이다. 별도의 두 문장 a+=b; a+=a;로 실행하면 두 번째 문장 전 a=5이므로 결과 10이지만 같은 평가 일정이 아니다.

흔한 오답에서 다시 생각하기

괄호 속 a+=b부터 실행하므로 바깥 rhs도 5여서 최종 10이다.

괄호는 결합 구조를 정하지만 바깥 복합 대입의 오른쪽 우선 평가 규칙을 없애지 않는다. 값 인수 2가 먼저 복사된다.

연습 2 · 오류 찾아 고치기

operator+에서 lhs를 const Amount&로 받고 반환을 Amount&로 바꿔 입력 보존과 효율을 동시에 얻겠다고 했다.

힌트 1

입력의 const 권한을 확인한다.

힌트 2

새 계산 결과의 수명도 필요하다.

풀이와 답 확인

  1. const lhs를 직접 +=로 변경할 수 없다.

  2. 지역 결과를 만들면 값으로 반환해야 하며 그 지역의 참조를 반환하면 수명 밖 별칭이 된다.

새 합에는 독립 값 결과를 설계한다.

흔한 오답에서 다시 생각하기

지역 객체 참조는 반환하면 자동 수명이 늘어난다.

함수의 지역 객체를 가리킨 참조는 결과 값 생성의 대안이 아니다.

새 Rational은 분자 p를 -10..10, 분모 q를 1..10으로 제한한 교육 값 타입이다. 값은 유리수 p/q이며 저장 쌍 자체의 동일함을 요구하지 않는다. ==는 a.p*b.q==b.p*a.q, <는 a.p*b.q<b.p*a.q로 정의한다. 모든 곱은 -100..100 안에 들어가므로 이 작은 모형에서는 int 표현 범위를 넘지 않는다.

분모가 양수인 조건 때문에 교차곱 비교가 값 순서를 유지한다. (1,2)와 (2,4)는 다른 저장 쌍이지만 같은 1/2다. 한편 작은 정수 key의 가까움 관계를 정렬 동치로 쓰는 경우에는 두 값이 가깝다는 직관만으로 그룹의 추이성을 만들 수 없다. 엄격한 약순서는 비교와 양방향 비교 거짓으로 만든 동치 모두에 추이성을 요구한다.

먼저 확인할 개념
  • predicate와 comparator

    비교 동치의 추이성을 단순 bool 반환과 구별한다.

  • vector·deque·list

    저장 표현의 위치와 논리적 값·순서를 별도로 다룬다.

무엇을 값으로 보는지 정한다

값 타입은 보통 저장 위치보다 그 타입이 표현하는 내용을 기준으로 비교한다. 이 Point의 값은 순서 있는 두 정수 (x,y)로 정의하고 두 성분이 모두 같을 때 ==가 참이다. 서로 다른 객체 a와 b가 같은 좌표를 담아도 값은 같을 수 있다.

주소 비교 &a == &b는 두 객체의 저장 위치가 같은지를 묻는다. 값 비교 a == b와 질문이 다르다. 자원 핸들이나 식별자 타입은 또 다른 동등성 계약을 가질 수 있으므로 모든 클래스의 멤버 전체를 무조건 비교하는 원칙으로 확대하지 않는다.

정렬을 위한 순서를 만든다

아래 <는 x를 먼저 비교하고 x가 같을 때 y를 비교하는 사전식 순서다. (1,9)는 (2,0)보다 앞서고, (1,2)는 (1,9)보다 앞선다. 두 좌표가 기하학적으로 모든 축에서 작다는 뜻과 다르다.

정렬용 비교는 comp(a,a)가 거짓인 비반사성과 비교의 추이성을 지켜야 한다. 양방향 comp가 모두 거짓인 동치 관계도 추이적이어야 하는 엄격한 약순서가 필요하다. 여기의 정수 쌍 사전식 순서는 이를 만족하지만 몇 사례만 확인했다고 임의 비교 함수의 전체 성질이 증명되지는 않는다.

연산 사이의 일관성을 확인한다

이 예제에서 ==가 참이면 양방향 <가 모두 거짓이다. 일반적인 정렬 비교는 서로 다른 값을 같은 그룹으로 볼 수도 있으므로 비교 동치가 항상 별도 ==와 같아야 한다고 단정하지 않는다. 자료구조가 사용하는 비교 기준을 문서로 확인한다.

C++17 코드에서는 ==와 <를 직접 작성한다. C++20 이후의 기본 비교 생성 기능을 사용하려면 해당 버전과 비교 대상 멤버의 계약을 별도로 확인해야 한다. 이 예제에서 != 등 다른 연산자가 자동 정의됐다고 가정하지 않는다.

변환 constructor·explicit

거리 함수에 정수 5를 넘기는 것과 Metres{5}를 넘기는 것은 왜 다를까?

준비 개념과 학습 목표

준비 개념

  • 생성자

  • 함수 인수 초기화

학습 목표

  • 변환 생성자의 암시적 사용을 설명한다

  • 직접 초기화와 복사 초기화를 구별한다

  • explicit과 축소 변환 검사를 구분한다

중괄호가 언제나 괄호와 같은 생성자를 고를까?

새 Bag은 사용자 생성자 두 개를 갖는다. explicit Bag(int count,int value)는 value를 count개 가진 목록을 만들고, explicit Bag(std::initializer_list<int> values)는 주어진 원소들을 복사해 자기 목록을 만든다. count는 0..10이며 작은 예제의 할당은 성공한다. initializer_list의 임시 저장을 계속 빌리지 않고 복사하여 소유한다.

Bag a(3,7)은 개수/값 생성자를 고르지만 Bag b{3,7}은 목록 생성자를 먼저 고려하여 두 원소 3과 7을 가진다. explicit은 직접 리스트 초기화를 막지 않는다. 목록 후보가 선택된 뒤 축소 변환 오류가 생기더라도 다른 일반 생성자를 골라 조용히 구제한다는 규칙은 없다. 선택과 인수 변환을 순서대로 읽는다.

먼저 확인할 개념
  • constructor와 destructor

    생성자 선택과 임시 인수 저장의 수명 책임을 구별한다.

  • namespace와 overload

    후보가 많은 경우 선택 규칙을 선언 순서로 바꾸지 않는다.

다른 타입에서 새 객체를 만든다

생성자는 기존 값으로 새 객체를 초기화한다. explicit이 없는 한 인수 생성자는 적절한 문맥에서 정수를 클래스 값으로 암시 변환하는 길이 될 수 있다. 숫자에 단위가 담겨 있지 않으면 사용자가 의도하지 않은 변환을 허용할 수 있다.

Metres는 미터 수를 뜻하는 교육 타입이다. 아래 int 인수 생성자를 explicit으로 표시하여 walk(5)를 허용하지 않고 walk(Metres{5})처럼 단위를 선택한 표현을 요구한다. 이 단순 타입은 음수나 상한 검사를 하지 않으므로 물리 거리의 모든 유효성까지 보장한다고 주장하지 않는다.

초기화 모양을 읽는다

Metres a(5)와 Metres b{5}는 직접 초기화라 explicit 생성자를 사용할 수 있다. Metres c = 5는 복사 초기화라 해당 암시 변환이 허용되지 않는다. Metres d = {5}도 복사 리스트 초기화에서 explicit 생성자 선택 때문에 오류다.

Metres e = Metres{5}는 먼저 명시적으로 만든 같은 타입의 값을 사용하므로 앞의 c와 다르다. 생성자에 explicit이 있다는 이유만으로 모든 등호 초기화를 거절한다고 외우지 말고 등호 오른쪽 타입과 초기화 문맥을 확인한다.

인수 내부의 변환은 따로 남는다

explicit은 사용자 타입으로의 암시 변환을 제한하지 모든 기본 숫자 변환을 금지하지는 않는다. Metres f(2.9)는 직접 초기화의 int 인수 변환에서 소수부를 버려 2가 된다. 작은 표현 가능 값이라는 가정에서의 설명이다.

Metres g{2.9}는 리스트 초기화의 실수→정수 축소 변환 때문에 오류다. explicit과 중괄호의 축소 검사는 서로 다른 장치다. 의도적인 변환이 필요하면 반올림·버림·범위 정책을 이름 있는 함수로 밝히고 먼저 값 유효성을 검사한다.

준비 개념과 학습 목표

준비 개념

  • explicit 생성자

  • 조건문 bool

학습 목표

  • 문맥상 bool과 일반 암시변환을 구분한다

  • 단위 혼동을 줄이는 API를 설계한다

참거짓 결과가 같으면 오른쪽 검사도 생략됐을까?

Ready는 bool value와 explicit operator bool() const를 가진다. 첫 모형은 operator&&를 정의하지 않는다. probe()는 정상 종료하며 방문 수를 1 늘리고 Ready{true}를 반환한다. 각 비교는 visits=0과 Ready r{false}에서 새로 시작한다. r&&probe()는 이 모형에서 내장 &&의 문맥상 bool 변환을 사용한다.

둘째 모형은 별도 Ready 타입에 bool operator&&(Ready a,Ready b)를 제공하며 본문에서 a.value&&b.value를 반환한다. 함수 본문 안의 내장 &&가 false 뒤 오른쪽 bool 읽기를 생략해도, 이미 호출 인수로 probe()를 평가하여 Ready b를 만든 뒤다. 함수 본문으로 전달된 인수를 나중에 취소할 수 없다. C++17 이상의 연산자 표기에서는 왼쪽이 오른쪽보다 먼저지만, 사용자 &&는 오른쪽 피연산자를 생략하는 내장 short-circuit을 제공하지 않는다.

밖으로 나가는 변환도 설계한다

생성자는 다른 값에서 클래스 객체를 만들고 operator bool 같은 변환 함수는 클래스 객체에서 다른 타입 값으로 바꾸는 길이다. 비explicit operator int를 쉽게 추가하면 연산자 후보와 숫자 계산에 객체가 참여해 읽는 사람을 놀라게 할 수 있다.

숫자 값을 원한다면 value() 같은 이름 있는 조회 함수를 쓰는 방법이 있다. 단위 있는 정수를 자동으로 일반 int로 바꾸면 이후 단위 검사 기회를 잃으므로 편의만 보고 양방향 암시 변환을 열지 않는다.

조건 확인의 예외를 이해한다

아래 Ready의 explicit operator bool은 if(r)의 문맥상 bool 변환에 사용될 수 있다. 문맥상 bool은 bool t(r) 직접 초기화의 가능성으로 판단하므로 일반적인 bool b=r 복사 초기화와 규칙이 다르다.

r이 Ready{true}이면 if(r)의 조건은 참이다. bool b=r은 explicit 변환으로 암시 복사 초기화를 할 수 없어 오류지만 bool b(r) 또는 static_cast<bool>(r)은 의도한 변환을 표시한다. int n=r이나 r+1은 이 정의만으로 허용되지 않는다.

사용자가 의도를 적게 모호하게 쓰게 한다

미터와 초를 별도 클래스 타입으로 만들고 생성자를 explicit으로 두면 단위가 없는 숫자 전달과 잘못된 타입 전달을 줄일 수 있다. walk(Metres{5})는 어떤 단위를 선택했는지 호출에서 드러낸다. 별도 타입 간 변환 연산자를 제공하지 않았다면 Seconds{5}는 Metres 인수가 아니다.

명시적인 변환도 내용이 틀릴 수 있다. 미터 값을 잘못 선택하거나 음수·범위를 무시하면 타입만으로 해결되지 않는다. 단위 환산 함수의 이름, 유효 범위, 실패 정책과 비교·연산 의미를 함께 문서화하고 정상·거절 사례를 나눠 확인한다.

visits는 실제 실행 로그가 아닌 명시한 함수 효과의 손추적이다. 함수가 호출됐는지와 최종 bool 값을 따로 기록한다. 실제 nullptr 역참조나 실패하는 probe를 실행하는 활동은 하지 않는다.

중간 과정을 따라가는 예제

다음 타입에서 Ready r{true}로 if(r), bool a=r, bool b(r), int n=r, r+1을 분류하라. 

struct Ready {
    bool value;
    explicit operator bool() const { return value; }
};

  1. if(r)는 문맥상 bool 변환이며 조건 참이다.

  2. bool a=r은 암시 복사 초기화라 거절된다. bool b(r)는 직접 초기화라 참 값을 얻는다.

  3. int n=r과 r+1에는 적절한 암시 변환 또는 연산자가 없어 거절된다.

허용: 조건 확인·bool 직접 초기화. 거절: bool 복사 초기화·int 초기화·숫자 덧셈. 이는 실행 로그가 아니다.

조건을 바꾸어 비교하기

조건식의 생략과 함수 인수 평가

두 독립 모형의 r&&probe()를 결과/visits로 비교하라.

  1. 내장 &&는 r을 false로 관찰한 뒤 probe를 평가하지 않는다.

  2. 사용자 &&는 두 피연산자를 인수로 준비하므로 probe가 visits를 1로 만든다.

둘 다 false지만 visits는 각각 0과 1이다.

비교할 점

base의 bool 직접/복사 초기화 분류에 평가 효과의 차이를 추가한다.

직접 함수 호출 표기는 평가 순서도 다르다

사용자 함수 operator&&(Ready,Ready)를 operator&&(left(),right())로 직접 호출한다. 두 함수는 각각 자기 방문 표식만 기록하며 정상 종료한다. 결과는 false다.

  1. 두 인수 모두 평가되어 각 방문 표식이 한 번 생긴다.

  2. 일반 함수 호출의 두 인수 사이에는 어느 것이 먼저인지 이 문장만으로 정하지 않는다.

둘 다 방문하지만 표식의 순서를 고정하지 않는다. C++17 이상의 비겹침 인수 평가 조건에서 판단한다.

각 비교는 새 초기 객체에서 독립적으로 시작한다. (A) 위 Amount의 참조 반환 +=와 값 반환 +에서 a.n=2,b.n=3이며 Amount c=a+b; c+=Amount{4};와 별도 (a+=b)+=a를 추적하라. 힌트 1

A는 값 변수와 참조 반환뿐 아니라 바깥 복합 대입의 오른쪽 우선 평가를 표시하고 B는 저장쌍 대신 값 정의·동치 추이성을 검사한다.

힌트 2

C는 직접/복사 리스트·후보 우선·임시 수명을 나누고 D는 함수 진입 전 인수 평가를 확인한다.

풀이와 답 확인

  1. A의 새 합 경로는 a=2,b=3,c=9다. 별도 (a+=b)+=a는 바깥 rhs에 초기 a의 2를 먼저 값 복사하고 왼쪽 a+=b가 a를 5로 만든 뒤 5+2를 저장해 a=7,b=3이다. 두 문장 a+=b; a+=a;이면 결과 10으로 다른 일정이다.

  2. B의 두 유리수는 교차곱4/4로 같다. 근접 key 비교는0~1,1~2이나0~2는 거짓이므로 동치 추이성이 깨진다.

  3. C의 괄호는[7,7,7], 직접 리스트는[3,7]이고 복사 리스트는 선택된 explicit 생성자 때문에 오류다. 임시 목록 배열 포인터만 보관하면 전체 표현식 뒤의 사용 수명을 보장하지 못한다.

  4. D는 두 결과 모두false이며 내장 visits=0, 사용자 visits=1이다. 사용자 함수 본문 조기 반환은 이미 평가된 probe 효과를 취소하지 않는다.

새 값과 별칭, 저장 표현과 값 동등성, 생성자 선택과 임시 수명, false 결과와 오른쪽 평가 효과는 서로 다른 검사다. 각 모형의 값·오류·효과를 별도 열로 기록한다.
