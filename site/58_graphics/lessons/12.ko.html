keyframe과 보간

두 위치를 정해 두면 중간 움직임은 어떻게 정할까?

준비 개념과 학습 목표

준비 개념

  • 좌표와 벡터

  • 시간

  • 비율

학습 목표

  • 구간 시간으로 보간 계수를 계산한다.

  • 위치 선형 보간과 easing을 구별한다.

  • 표시 보간과 상태 갱신을 구별한다.

같은 끝점을 잇는 세 keyframe에서 전체 재생 비율과 현재 구간 비율은 같을까?

앞 본문은 두 keyframe의 구간 비율과 clamp를 구별했다. 여기서는 새 시각 0,1,4초에 위치 0,8,14m를 지정한다. 시간이 엄격히 증가하는 숫자 위치 목록이며 각 인접 구간을 선형으로 잇는다. 중간 keyframe을 건너뛰고 처음과 끝만 혼합하면 다른 경로가 된다.

시각 2초는 [1,4] 구간에 있으므로 local u=(2−1)/(4−1)=1/3이다. 위치는 8+(14−8)/3=10m다. 전체 4초 중 절반이라는 이유로 위치를 7m로 정하면 1초의 위치 8m도 보존하지 못한다.

끝점과 위치 연속성은 속도 연속성을 보장하지 않는다. 첫 구간 기울기는 8m/s, 둘째는 2m/s다. clamp와 반복 재생은 별도 계약이다. 아래 반복은 r=t−4 floor(t/4)로 [0,4)에 감으며 마지막 위치 14m에서 첫 위치 0m로 뛰는 자체 정책이다. 실제 Web Animations의 속성별 보간을 재현한 결과는 아니다.

먼저 확인할 개념
  • 두 keyframe의 구간 비율

    앞 본문의 u 식과 구간 밖 clamp를 여러 인접 구간에 적용한다.

  • 계산 상태와 화면 상태

    보간으로 만든 값은 권위 있는 계산 상태와 역할을 나눈다.

시간이 있는 기준 상태를 기록한다

keyframe은 특정 시점에 지정한 상태다. 0초에 위치 x=0, 2초에 x=10을 지정하고 그 사이 규칙을 정하면 중간 상태를 계산할 수 있다. 단순히 시작과 끝을 그리는 것만으로 경로·속도·반복·구간 밖 행동이 모두 결정되지는 않는다.

구간 t0<t1에서 비율 u=(t−t0)/(t1−t0)를 계산한다. 구간 안은 0≤u≤1이고 선형 보간은 x=(1−u)x0+ux1이다. 구간 밖에서 이 식을 그대로 쓰면 외삽이다. 여기서는 구간 밖 시간을 끝점으로 고정하는 clamp 규칙을 명시한다. 동일 시각 keyframe은 분모 0이므로 별도 규칙이 필요하다.

보간 규칙이 움직임을 바꾼다

벡터 위치는 성분별로 선형 보간할 수 있다. 같은 u로 각 성분을 혼합하면 두 위치를 잇는 직선 위의 점이 된다. easing은 시간 비율 u를 다른 비율 e(u)로 바꾸어 천천히 시작하거나 끝나게 하는 규칙이다. e(u)=u²는 구간 앞부분 진행을 늦추며 물리적 가속도를 일반적으로 시뮬레이션한다는 뜻은 아니다.

회전 각도 350°에서 10°를 숫자로 단순 혼합하면 180° 중간을 지나 긴 경로로 돌 수 있다. 짧은 회전 경로를 원하면 각도 감김과 표현 규칙을 정해야 한다. 3D quaternion에서는 정규화와 회전 의미를 고려하는 방법이 필요하므로 위치 보간 공식을 무조건 모든 상태에 적용하지 않는다.

기준과 표시용 상태를 분리한다

Web Animations에서는 keyframe과 timing 정보를 분리하며 offset이 구간 비율을 표현하고 duration은 ms로 적는다. API의 실제 interpolation은 속성 종류와 easing 규칙에 따라 달라진다. 아래 자체 수식은 숫자 위치를 학습하기 위한 모델이다.

물리 상태 사이의 표시 보간은 더 매끈한 화면을 위한 중간 표시를 만들 수 있다. 표시용 좌표를 다음 물리 갱신의 실제 상태로 다시 넣으면 원한 수치 모델이 바뀔 수 있다. 어떤 상태가 권위 있는 계산값이고 어떤 값이 화면용인지 기록한다.

중간 과정을 따라가는 예제

t0=0, x0=2, t1=4, x1=10이다. t=1의 선형 위치와 easing u² 위치를 구하라.

  1. u=(1−0)/4=0.25다. 선형 x=0.75×2+0.25×10=4다.

  2. e=0.25²=0.0625이고 x=0.9375×2+0.0625×10=2.5다.

  3. 둘은 같은 끝점을 갖지만 같은 중간 위치가 아니다.

중간 keyframe을 보존하는 시간 선택

새 목록 (0초,0m),(1초,8m),(4초,14m)에서 2초 위치와 잘못된 전체 보간을 비교하라. 각 예제는 원래 목록에서 시작한다.

  1. 2초가 들어 있는 구간은 [1,4]초다. local u는 1/3이다.

  2. 정상 위치는 8+6×1/3=10m다. 처음과 끝만 혼합하면 global u=1/2로 7m다.

  3. 잘못된 규칙은 1초에서도 14×1/4=3.5m로 지정 위치 8m를 놓친다.

정상 위치는 10m이며 두 끝점만 쓰는 규칙의 7m와 다르다.

비교할 점

전체 재생 비율은 현재 구간의 비율을 대신하지 않는다.

같은 경계 위치에서 속도는 달라진다

같은 목록의 각 구간 기울기와 둘째 구간에만 e(u)=u²를 쓰는 2초 위치를 구하라.

  1. 첫 구간 기울기는 (8−0)/(1−0)=8m/s다. 둘째 선형 기울기는 (14−8)/(4−1)=2m/s다.

  2. 두 선형 구간은 1초에서 모두 위치 8m지만 좌우 기울기는 다르다.

  3. 둘째 구간의 u=1/3을 제곱하면 1/9이므로 위치는 8+6/9=26/3m다.

위치는 경계에서 연속이지만 선형 속도는 8m/s에서 2m/s로 바뀐다. easing의 2초 위치는 26/3m다.

비교할 점

끝점 일치는 중간 위치나 미분값의 일치가 아니다.

종이와 본문으로 직접 해보기

연습 1 · 값과 상태 예측

원래 목록에서 0.5초와 3초의 선형 위치를 구하라. 5초는 끝점 clamp일 때와 위 반복 정책일 때를 각각 구하라.

힌트 1

두 시각은 서로 다른 구간이다.

힌트 2

반복의 5초는 r=1초이며 마지막 끝점 clamp와 다르다.

풀이와 답 확인

  1. 0.5초는 첫 구간 비율 1/2이므로 위치 4m다. 3초는 둘째 구간 비율 2/3이므로 위치 12m다.

  2. 5초의 clamp 위치는 14m다. 반복 시각은 1초이므로 반복 위치는 8m다.

선형 위치는 각각 4m와 12m다. 5초의 clamp 위치는 14m이고 반복 위치는 8m다.

5초는 어떤 정책에서도 마지막 위치다.

반복은 시간을 처음 구간으로 되돌린다. clamp의 끝점 유지와 계약이 다르다.

연습 2 · 오류 찾아 고치기

개발자가 목록의 2초 위치를 7m로 계산하면서 세 keyframe을 모두 만족한다고 말한다. 어느 시각의 지정 조건으로 반박할 수 있는가?

힌트 1

전체 구간의 처음과 끝만 사용하는 식을 써 본다.

힌트 2

중간 keyframe인 1초를 그 식에 넣는다.

풀이와 답 확인

  1. 식 x=14t/4는 2초에서 7m를 만들지만 1초에서 3.5m를 만든다.

  2. 지정된 1초 위치는 8m이므로 목록 계약과 충돌한다. [1,4] 구간 식으로 고치면 2초 위치는 10m다.

1초에서 3.5m와 지정 위치 8m가 충돌한다. 구간을 선택한 정상 2초 위치는 10m다.

흔한 오답에서 다시 생각하기

처음과 마지막 위치가 맞으므로 전체 목록도 보존한다.

중간 keyframe은 별도의 제약이다. 두 끝점 시험만으로 이를 검증할 수 없다.

연습 3 · 직접 만들어 보기

입력 keyframe 목록을 공개하기 전에 모든 시각이 유한하고 엄격히 증가하며 위치도 유한한지 검사하는 자체 정책을 설계하라. 새 후보 [(0,0),(1,8),(1,9),(4,14)]가 실패하면 기존 목록을 유지하라.

힌트 1

같은 시각 두 값의 처리 규칙을 여기서 새로 추측하지 않는다.

힌트 2

검사 완료와 기존 목록 교체를 분리한다.

풀이와 답 확인

  1. 후보를 별도 공간에서 검사한다. 모든 시각/위치의 유한성을 확인하고 인접 시각마다 t_next>t_current를 확인한다.

  2. 후보의 둘째와 셋째 시각이 모두 1이므로 거절한다. 기존 목록과 현재 재생 상태를 교체하지 않는다.

  3. 모든 검사가 성공한 후보만 한 번에 공개한다. 이 정책은 중복 시각을 허용하는 별도 API 계약과 구별한다.

중복 시각 후보를 거절하고 기존 목록을 보존한다. 실패 전 부분 교체를 하지 않는다.

흔한 오답에서 다시 생각하기

분모가 0인 구간만 건너뛰고 앞부분은 공개한다.

이는 입력 거절 및 실패 보존 정책을 바꾼다. 하나의 유효 목록 전체를 공개한다는 조건을 지켜야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

반복 정책 r=t−4 floor(t/4)에서 t=−1초와 t=4초의 위치를 구하라. 마지막 끝점과 첫 끝점이 다른 목록을 끊김 없이 반복한다는 주장을 평가하라.

힌트 1

floor(−1/4)=−1이다.

힌트 2

반복의 r 범위는 [0,4)이므로 정확히 4초도 첫 시각으로 간다.

풀이와 답 확인

  1. −1초는 r=−1+4=3초이므로 위치 12m다. 4초는 r=0초이므로 위치 0m다.

  2. 4초 직전의 위치는 14m에 가까워지지만 4초 반복 위치는 0m다. 끝점이 달라 위치가 불연속이다.

  3. 연속 반복이 요구되면 닫힌 경로·되돌아오는 구간 등 별도 설계를 해야 한다. 실제 API의 음수 시각 처리 결과를 주장하지 않는다.

음수 시각의 반복 위치는 12m이고 4초의 반복 위치는 0m다. 현재 목록은 반복 경계에서 끊긴다.

흔한 오답에서 다시 생각하기

floor 대신 정수 절단을 써도 음수 반복 시각은 같다.

−1/4를 0으로 절단하면 r=−1이어서 [0,4) 계약을 위반한다.

간단한 물리적 움직임

한 초마다 조금씩 움직이는 계산은 정확한 운동식과 같을까?

준비 개념과 학습 목표

준비 개념

  • 위치

  • 속도

  • 가속도와 시간 단위

학습 목표

  • 일정 가속도의 정확식과 수치 갱신을 비교한다.

  • Euler 갱신 순서를 명시한다.

  • 물리 dt와 그림 주기를 구별한다.

물리 상태는 0.2m인데 화면은 0.16m를 표시한다면 어느 값을 다음 걸음에 써야 할까?

앞 본문은 explicit와 semi-implicit 순서 및 고정 dt를 설명했다. 새 모형은 가속도가 없고 속도가 일정한 5m/s다. dt는 0.02초이며 각 계산 걸음은 위치를 0.1m 늘린다. 시작 previous와 current는 모두 0m다. 각 걸음 직전에 previous=current를 복사한 다음 current를 갱신한다.

새 화면 간격은 차례로 0.013초, 0.039초, 0.008초다. accumulator에 지난 시간을 더하고 완전한 dt를 소비한다. 남은 시간이 dt보다 작을 때만 alpha=잔여/dt로 previous와 current를 섞는다. 표시값은 이전 계산 시각과 현재 계산 시각 사이의 값이다. 서로 다른 계산 상태가 생긴 뒤에는 현재 실시간보다 한 걸음 이전 시각의 위치를 표시하며, 초기 동일 상태의 첫 화면은 별도로 다룬다.

보충 걸음에 상한을 두면 잔여가 dt보다 작다는 조건이 깨질 수 있다. 이때 alpha가 1보다 크므로 정상 두 상태 사이 보간이라고 보고하지 않는다. backlog를 유지할지, 시간을 버릴지와 표시 정책을 명시한다. 버린 시간은 물리를 계산했다는 뜻이 아니다.

먼저 확인할 개념
  • 갱신 순서와 accumulator

    앞 본문의 옛/새 속도 및 고정 단계·잔여를 여러 화면의 장부로 확장한다.

  • 표시 보간과 계산 상태

    화면용 위치를 다음 계산의 current로 되돌리지 않는 책임 구분을 적용한다.

단위와 힘의 모델을 정한다

1차원에서 위치 x는 m, 속도 v는 m/s, 가속도 a는 m/s², dt는 s로 정한다. 일정 가속도라면 v(t)=v0+at와 x(t)=x0+v0t+at²/2라는 정확식으로 이 예제의 기준값을 구할 수 있다. 힘이 바뀌거나 충돌이 있으면 이 단순식을 전체 시간에 적용하는 조건이 달라진다.

수치 적분은 작은 dt마다 현재 상태에서 다음 상태를 예측하는 계산이다. explicit Euler는 옛 속도로 x를 갱신하고 그다음 v를 갱신한다. semi-implicit Euler는 새 v를 먼저 계산한 뒤 그 v로 x를 갱신한다. 둘의 순서 차이가 위치 결과를 바꾼다.

한 걸음의 오차를 드러낸다

x0=0, v0=0, a=2, dt=1이면 explicit 첫걸음은 x=0, v=2이고 semi-implicit은 x=2, v=2다. 정확 위치는 1이다. 둘 중 하나가 이상식과 항상 동일하다고 말하지 않는다. 이 예제는 일정 가속도의 단순 모형이며 마찰·충돌·3D 회전을 모두 구현한 것이 아니다.

dt를 작게 하면 이 모형의 위치 근사 오차가 줄어든다. 하지만 모든 힘과 상황에서 특정 dt가 안정성을 보장한다는 뜻은 아니다. 강한 스프링이나 충돌 등은 적분 방법·검출 방법·조건을 검토해야 한다. 공식 유도와 손계산을 실제 엔진 검증으로 대신하지 않는다.

계산 주기와 표시 주기를 나눈다

화면 갱신 시간이 변한다고 그 긴 시간을 한 번에 물리 갱신하면 동작이 달라지거나 벽을 건너뛰는 문제가 생길 수 있다. 고정 dt의 accumulator 모형은 지난 실시간을 쌓고 dt만큼의 단계를 여러 번 소비한 뒤 남은 시간을 다음 화면에 이어 쓴다.

dt=0.02초, 쌓인 시간 0.055초라면 2단계로 0.04초를 계산하고 0.015초를 남긴다. 표시 보간 계수는 남은 0.015/0.02=0.75다. 이전·현재 상태를 표시용으로 섞고 실제 상태를 보존한다. 너무 많은 보충 단계가 실시간을 넘는 경우 처리 정책이 필요하며 시간을 버렸으면 그 사실을 기록한다.

  1. 둘째 누적 시간은 0.052초다. 2단계를 소비하고 잔여 0.012초를 남긴다. previous는 0.1m, current는 0.2m다.

  2. 표시는 0.1+0.6×0.1=0.16m다. 속도 5m/s에서 이 위치의 시각은 0.032초이며 현재 실시간 0.052초보다 0.02초 이전이다.

  3. 셋째 누적 시간은 0.06초이고 잔여는 0이다. previous 0.2m를 표시하므로 표시 시각은 0.04초다.

비교할 점

alpha가 0이라고 계산 상태를 0으로 만들거나 current를 표시한다는 뜻은 아니다.

보충 단계 상한 뒤의 잔여를 감사한다

별도 시작 상태 0m에서 accumulator 0.095초, dt 0.02초, 이번 화면 단계 상한 3이다. 잔여와 시간 버리기 정책을 비교하라.

  1. 3단계로 0.06초를 계산한다. previous는 0.2m, current는 0.3m이고 잔여는 0.035초다.

  2. 그대로 alpha를 계산하면 1.75여서 두 상태 사이 보간이 아니다. backlog 유지 정책에서는 최신 계산값 0.3m를 표시하고 잔여를 다음 화면으로 보낸다고 별도 정할 수 있다.

  3. 별도 버리기 정책은 잔여의 완전한 dt 한 번인 0.02초를 버리고 0.015초를 남긴다. alpha=0.75이며 표시 위치는 0.2+0.75×0.1=0.275m다.

  4. 실시간 0.095초 중 받아들인 시간은 0.075초, 계산 완료는 0.06초, 다음 잔여는 0.015초이며 버린 시간은 0.02초다.

상한 뒤 잔여는 0.035초다. backlog 유지의 최신값 표시와 시간 버리기의 0.275m 표시는 서로 다른 정책이다.

비교할 점

정상 accumulator 보간의 잔여<dt 조건을 상한이 있는 경우 자동으로 가정하지 않는다.

연습 1 · 값과 상태 예측

첫 예제의 세 화면 각각의 current 위치와 표시 위치를 구하라. 첫 화면의 초기 상태 특수성도 적어라.

힌트 1

계산이 없으면 previous와 current는 같게 남는다.

힌트 2

셋째 잔여가 0이면 previous를 표시한다.

풀이와 답 확인

  1. 첫 화면의 current와 표시 위치는 모두 0m다. 둘째 화면의 current는 0.2m이고 표시 위치는 0.16m다. 셋째 화면의 current는 0.3m이고 표시 위치는 0.2m다.

첫 화면은 current와 표시 위치 모두 0m인 초기 동일 상태를 사용한다. 둘째 화면은 current 0.2m를 보존하며 0.16m를 표시한다. 셋째 화면은 current 0.3m를 보존하며 0.2m를 표시한다.

흔한 오답에서 다시 생각하기

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 일정 가속도 모형 x0=1m,v0=3m/s,a=−2m/s²에서 dt=0.5초로 총 1초를 explicit와 semi-implicit 각각 두 걸음 계산하라. 정확 위치 및 dt=0.25초의 위치와 비교하라.

힌트 1

explicit는 옛 속도, semi-implicit는 새 속도로 위치를 갱신한다.

힌트 2

정확 위치는 1+3×1−2×1²/2다.

풀이와 답 확인

  1. dt=0.5에서 explicit 위치는 1→2.5→3.5m이고 semi-implicit 위치는 1→2→2.5m다. 두 방법의 최종 속도는 1m/s다. 정확 위치는 3m다.

  2. dt=0.25에서 explicit 증분은 0.75,0.625,0.5,0.375m로 위치 3.25m다. semi-implicit 증분은 0.625,0.5,0.375,0.25m로 위치 2.75m다.

  3. 오차는 dt=0.5에서 각각 +0.5m/−0.5m, dt=0.25에서 +0.25m/−0.25m다. 두 결과 평균 3m는 이 일정 가속도 조건의 대칭 오차에 따른 값이다.

정확 위치는 3m다. dt=0.5초에서 explicit 위치는 3.5m, semi-implicit 위치는 2.5m다. dt=0.25초에서 explicit 위치는 3.25m, semi-implicit 위치는 2.75m다.

흔한 오답에서 다시 생각하기

두 방법의 평균을 쓰면 모든 힘과 충돌에서 정확하다.

평균 일치는 이번 일정 가속도의 대칭 오차 사례다. 상태 의존 힘·충돌·안정성에 일반화하지 않는다.

설명 기준 확인

steady-state 7ms인 파이프라인의 세 프레임 전체 시간도 21ms일까?

앞 본문은 CPU/GPU의 겹침과 실제 계측 경계를 구별했다. 새 종이 모형은 프레임마다 CPU 4ms 뒤 GPU 7ms다. 각 장치는 한 프레임씩 순서대로 처리하지만 CPU는 다음 프레임을 GPU 처리 중 준비할 수 있다. 시작 시 두 장치는 비어 있고 제출 비용·표시 동기화·다른 병목은 없다.

GPU 첫 완료는 11ms, 다음 완료는 18ms, 셋째는 25ms다. steady-state 완료 간격 7ms와 유한 세 프레임의 전체 25ms는 다르다. CPU를 2ms로 줄이면 첫 준비만 짧아져 세 프레임은 23ms지만 steady-state 간격은 여전히 7ms다.

보고의 자원 수는 최종 개수와 공존 피크를 구별한다. 새 단순 RGBA 색 배열 하나를 100×50에서 200×100으로 바꾸되 옛 배열 소비 완료 뒤에만 해제하는 자체 수명 모형이면 최종 80000B와 피크 100000B가 다르다. WebGL handle 삭제는 이미 사용 중인 물체의 즉시 물리 해제 증거가 아니다. 아래 숫자는 논리 색 데이터만이며 depth·MSAA·배치·드라이버 메모리는 포함하지 않는다.

먼저 확인할 개념
  • 관측 경계와 자원 수명

    앞 본문의 CPU/GPU 계측·동기 stall·handle 삭제 조건을 유한 시간선 및 논리 공존 피크로 확장한다.

  • 실시간과 계산 시간

검은 화면을 작은 증거로 나눈다

렌더러는 자원 로드·shader 생성·좌표 변환·가시성·그리기·표시가 이어지는 구조다. 검은 화면 하나만으로 shader 오류를 확정할 수 없다. 먼저 단색 배경만 지우는지, 고정 삼각형이 그려지는지, 카메라와 depth·culling을 넣었을 때 어느 단계에서 사라지는지 최소 장면으로 좁힌다.

shader compile/link 결과와 오류 로그, 버퍼 형식과 정점 속성, viewport 크기 및 카메라 방향을 연결해 확인한다. 자원 경로 실패와 지원되지 않는 extension도 원인이 될 수 있다. 개발 기기에서 가능한 기능과 한계가 모든 방문자 기기와 같다고 가정하지 않는다.

성능 숫자의 경계를 표시한다

CPU가 명령을 보내는 시간과 GPU가 실제로 완료하는 시간은 다르다. CPU 측정만으로 GPU 처리 시간을 확정하면 안 된다. readPixels나 일부 get 함수의 동기 왕복이 기다림을 만들 수 있으므로 검사와 계측 자체 비용도 살핀다.

프레임별 CPU/GPU 시간이 겹치는 파이프라인과 순차 합 모형은 다르다. 아래 숫자는 CPU와 GPU가 완전히 겹치고 다른 병목이 없다는 가상의 steady-state 모형으로 max를 쓴다. 실제 시작 지연이나 프레임 시간은 별도 측정한다. 해상도·장면·빌드·기기·예열 조건을 고정해 비교한다.

자원 수명과 결과를 보고한다

필요 없어진 WebGL 자원의 handle을 해제하고 context 상실을 고려한다. handle 삭제 즉시 그리기에 쓰는 실제 메모리가 무조건 바로 없어진다고 추정하지 않는다. 자원 누수는 반복 장면 전환의 관측과 수명 관계로 확인한다.

보고에는 브라우저·GPU·해상도·장면과 재현 단계, 예상/실제 화면, 오류 로그·측정 범위·산출물 버전과 미수행 대상을 적는다. 실제 GPU 실행이 없으면 손계산과 예상 결과만 적는다. 그림 비교가 같아도 픽셀 동일성·모든 기기 호환성·학습자 이해까지 한꺼번에 증명되지는 않는다.

중간 과정을 따라가는 예제

완전히 겹치는 가상 파이프라인에서 CPU 6ms, GPU 12ms다. CPU를 3ms로 줄인 경우와 GPU를 8ms로 줄인 경우의 steady-state 시간을 구하라.

  1. 기준은 max(6,12)=12ms다.

  2. CPU 3, GPU 12는 max=12로 이 모형의 steady-state 시간은 같다.

  3. CPU 6, GPU 8은 max=8이므로 기준/새 시간=12/8=1.5다.

모형 시간은 12→12 또는 8ms다. 실제 GPU 계측 없이 현장 성능 우위를 주장하지 않는다.

조건을 바꾸어 비교하기

첫 준비 비용과 반복 처리 간격을 나눈다

기준 CPU 4ms/GPU 7ms에서 N≥1 프레임의 전체 시간과 CPU만 2ms로 줄인 세 프레임 시간을 구하라.

  1. GPU가 더 느리므로 첫 CPU 준비 뒤 GPU가 계속 순차 처리한다. 기준 전체 시간은 4+7N ms다.

  2. 세 프레임의 기준은 25ms다. CPU만 2ms이면 전체는 2+7N ms로 세 프레임 23ms다.

  3. 기준/새 전체 시간 비는 25/23이지만 steady-state 완료 간격은 두 경우 모두 7ms다.

세 프레임 전체는 25ms에서 23ms로 줄어든다. 반복 완료 간격은 7ms로 유지된다.

비교할 점

steady-state max만 쓰면 유한 실행의 시작 준비 비용을 놓친다.

동기 읽기와 옛 버퍼의 공존을 기록한다

각 프레임의 CPU 4ms 뒤 GPU 7ms와 동기 읽기 3ms가 끝난 다음에만 다음 프레임의 CPU를 시작하는 별도 순차 모형이다. 이 모형의 세 프레임 시간을 구하라. 별도 색 배열 resize의 최종 및 공존 피크 바이트도 구하라.

  1. 동기 모형은 각 프레임의 CPU 4ms, GPU 7ms, 읽기 3ms가 순차로 이어진다. 프레임당 14ms이며 세 프레임 전체는 42ms다.

  2. 옛 색 배열은 100×50×4=20000B, 새 배열은 200×100×4=80000B다.

  3. 새 배열이 생겼지만 옛 소비가 끝나지 않은 공존 구간의 피크는 100000B이고 옛 배열이 끝난 뒤 최종은 80000B다.

동기 순차 모형의 세 프레임은 42ms다. 논리 색 데이터 피크는 100000B이고 최종은 80000B다.

연습 1 · 값과 상태 예측

CPU는 4ms로 유지하고 GPU만 5ms로 줄이면 세 프레임 전체 시간과 steady-state 완료 간격은 얼마인가?

힌트 1

CPU보다 GPU가 여전히 느리다.

힌트 2

첫 준비 4ms를 따로 더한다.

풀이와 답 확인

  1. 전체 시간은 4+5×3=19ms다. 완료 시각은 9,14,19ms다.

  2. steady-state 간격은 5ms다. 기준 세 프레임 25ms와 비교하는 비는 25/19이고 간격의 비 7/5와는 다르다.

세 프레임 전체는 19ms이고 완료 간격은 5ms다.

7/5는 어떤 유한 프레임 수에서도 전체 시간 비다.

유한 전체 시간에는 두 경우 공통의 첫 CPU 준비 4ms가 포함된다.

연습 2 · 오류 찾아 고치기

종이 최소 재현에서 배경 clear와 변환 없는 clip-space 삼각형은 보이며 카메라 변환을 추가한 삼각형은 보이지 않는다. 텍스처 단계는 아직 넣지 않았다. 텍스처 로드 실패가 확정 원인이라는 보고를 교정하라.

힌트 1

실패가 처음 관찰된 추가 조건을 적는다.

힌트 2

미수행 단계와 실패 관찰 단계를 나눈다.

풀이와 답 확인

  1. 배경과 단순 삼각형 관찰은 앞 단계의 일부 경로가 작동함을 보인다. 카메라 변환을 추가한 뒤 실패가 나타났다고 기록한다.

  2. 변환 행렬·클립 범위·viewport·depth/culling 같은 관련 조건을 분리한 다음 최소 재현을 계획한다. 이 결과만으로 하나의 정확 원인을 확정하지 않는다.

  3. 텍스처는 아직 넣지 않았으므로 텍스처 로드 실패를 관찰했다고 쓰지 않는다. 이 기록은 가상 관찰 표이며 실제 브라우저를 실행한 결과가 아니다.

실패가 처음 나타난 추가 조건은 카메라 변환이다. 정확 원인은 미확정이고 텍스처 단계는 미수행이다.

하나의 최소 경로 성공은 다른 입력·shader·변환·장치 조합의 검증을 대신하지 않는다.

힌트 1

옛 배열은 마지막 소비 전까지 모형의 생존 자원이다.

힌트 2

  1. 5ms부터 12ms의 완료 경계 전까지 옛/새 데이터가 공존해 피크 100000B다. 12ms에 옛 소비 완료 및 해제가 성립하는 자체 정책이면 이후 최종 80000B다.

  2. 6ms handle 삭제 요청만으로 물리 GPU 메모리가 그때 해제됐다고 주장하지 않는다.

  3. 보고에 크기·B 단위·생성/소비 완료 조건과 depth/MSAA/드라이버 제외 범위 및 실제 계측 미수행을 적는다.

논리 공존 구간은 [5,12)ms이며 피크 100000B다. 완료 뒤 최종 80000B이고 실제 GPU 해제 시각은 측정하지 않았다.

흔한 오답에서 다시 생각하기

6ms에 삭제 요청을 보냈으므로 피크는 80000B다.

사용 중인 옛 데이터의 수명 조건을 빠뜨렸다. 삭제 요청과 실제 사용 완료는 별도 사건이다.

다른 문제에 적용하기

새 숫자 keyframe은 (0초,2m),(2초,10m),(5초,13m)이고 인접 구간은 선형이다. 별도 물리 모형은 dt=0.025초, 일정 속도 4m/s, previous=current=0m에서 시작한다. 정확한 누적 실시간 0.065초를 한 화면에서 받아 상한 없이 완전한 dt를 소비한다. 별도 빈 CPU/GPU 파이프라인은 프레임마다 CPU 3ms 뒤 GPU 5ms이고 각 장치는 순서대로 하나씩 처리하며 다음 CPU는 앞 GPU와 겹칠 수 있다. 프레임은 4개다. 별도 resize의 옛 색 데이터는 16000B, 새 데이터는 36000B이고 새 생성 뒤 옛 소비 완료 전 두 데이터가 공존한다. ① keyframe 3초 위치와 처음/끝만 혼합한 잘못값, ② 물리 단계 수·잔여·두 상태·표시 시각/위치, ③ 네 프레임 전체 시간/완료 간격, ④ 색 데이터 피크/최종을 구해 서로 다른 시간·수명 경계를 보고하라. 실제 애니메이션 API·엔진·GPU·학생 실행은 하지 않는다.

힌트 1

3초는 [2,5] 구간에 있다. 물리 0.065초에는 0.025초 두 단계만 완전히 들어간다.

힌트 2

표시는 previous와 current를 잔여/dt로 섞는다. 파이프라인은 첫 CPU 준비 뒤 GPU 네 번이며 색 데이터는 공존 피크를 더한다.

풀이와 답 확인

  1. 3초의 local u는 (3−2)/(5−2)=1/3이므로 위치는 10+3/3=11m다. 처음/끝만 쓰면 global u=3/5로 2+11×3/5=8.6m가 되어 중간 keyframe 계약을 위반한다.

  2. 물리는 2단계로 0.05초를 계산하고 잔여 0.015초를 남긴다. previous는 0.1m, current는 0.2m이며 alpha는 0.6이다. 표시는 0.16m이고 표시 시각은 0.04초다. 현재 실시간 0.065초보다 0.025초 이전 시각의 위치다.

  3. CPU/GPU 전체는 3+4×5=23ms이며 GPU 완료 시각은 8,13,18,23ms다. steady-state 완료 간격은 5ms로 전체를 20ms라 쓰면 첫 준비를 놓친다.

  4. 옛/새 데이터 공존 피크는 16000+36000=52000B다. 옛 소비 완료 뒤 최종은 36000B다. 물리 표시·GPU 완료·논리 수명은 서로 다른 모형이고 실제 측정 결과가 아니다.

keyframe 정상 위치는 11m이고 잘못된 전체 혼합은 8.6m다. 물리는 두 단계로 0.05초를 계산하며 잔여는 0.015초다. current는 0.2m이고 표시 위치는 0.16m, 표시 시각은 0.04초다. 네 GPU 프레임 전체는 23ms이고 완료 간격은 5ms다. 논리 색 데이터 피크는 52000B이고 최종은 36000B다.

해결한 뒤 점검할 것

  • 선택 구간과 local/global 비율을 구별하고 정상 11m와 잘못값 8.6m를 제시한다.

  • 물리 두 단계 및 previous/current·잔여·alpha·표시 시각을 구하고 화면 위치를 실제 current에 다시 넣지 않는다.

  • 시작 준비를 포함한 전체 23ms와 완료 간격 5ms를 별도 지표로 보고한다.

  • 공존 피크 52000B와 최종 36000B의 수명 조건을 명시하며 API/엔진/GPU/학생 미수행을 보존한다.
