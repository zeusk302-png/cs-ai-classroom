소단원 1.1

장면과 렌더러

같은 삼각형도 카메라나 조명을 바꾸면 왜 다른 그림이 될까?

준비 개념과 학습 목표

준비 개념

  • 좌표는 기준 축에 따라 위치를 수로 나타낸다. 벡터는 방향과 크기를 나타내며 점 두 개의 차이는 이동 벡터다. 영상은 위치별 값을 배열로 저장한 표현이며 장면의 물체 자체와 다르다.

학습 목표

  • 장면의 입력과 영상 출력을 구분한다

  • 가시성과 재질·조명의 역할을 설명한다

  • 단순 포함 판정과 실제 렌더링의 경계를 정한다

교차 목록의 첫 항목이 항상 보이는 표면일까요?

앞 본문의 삼각형 중심 판정은 한 표면이 샘플을 덮는지 검사한다. 여러 표면이 같은 광선에 걸리면 덮임만으로는 부족하다. 유효 범위의 교차를 먼저 남긴 뒤 그중 가장 가까운 불투명 표면을 선택한다. 물체 목록의 저장 순서는 공간의 앞뒤 순서가 아니다.

자체 광선은 r(t)=(0,0,2t)이고 허용 매개변수 범위는 1 ≤ t ≤ 5다. 모든 표면은 불투명하고 교차값은 이미 정확하게 주어진다. A의 t는 0.5, B는 2.5, C는 4다. 색은 표면마다 고정하며 조명·반사·투명성은 계산하지 않는다. 각 문제는 이 조건에서 독립적으로 시작한다.

방향 벡터의 길이가 2이므로 t는 물리적 거리와 같지 않다. 원점에서 r(t)까지의 거리는 2t다. 가시 표면 선택과 그 표면에 붙인 색을 읽는 단계도 구별한다. 이 사례는 실제 광선 교차 프로그램이나 렌더링을 실행한 기록이 아니다.

먼저 확인할 개념
  • 가시 표면과 고정 색의 구분

    중심 포함 판정에서 여러 불투명 표면의 앞뒤 선택으로 문제를 확장한다.

  • 점과 방향 벡터의 좌표 의미

    r(t)의 방향 길이와 점 위치를 구별하여 매개변수를 거리로 오인하지 않는다.

장면은 그림을 만드는 입력이다

장면에는 물체의 모양과 위치, 표면의 재질, 광원, 카메라 등이 들어간다. 렌더러는 이 입력과 정해진 규칙으로 영상을 계산하는 프로그램이다. 카메라는 어디에서 어떤 방향과 범위를 보는지 정하므로 같은 장면도 카메라가 달라지면 물체의 화면 위치나 보이는 면이 달라진다.

영상은 유한한 픽셀 배열이다. 장면의 모든 3차원 정보를 한 장에 그대로 저장하는 것은 아니다. 가려진 물체는 같은 카메라의 영상에서 드러나지 않을 수 있다. 출력만 보고 장면을 복원하려는 역문제에는 여러 해가 있을 수 있다.

무엇이 보이는가와 어떤 색인가

래스터화의 입문 모형은 삼각형을 화면에 옮기고 픽셀 샘플이 덮이는지를 판정한다. 깊이 비교는 같은 위치에 겹치는 불투명 표면 중 앞쪽을 선택하는 데 쓰일 수 있다. 이것은 모든 반사·그림자·투명성을 자동 계산한다는 뜻이 아니다.

광선 추적은 카메라에서 나온 광선과 장면의 교차를 구하고 보통 가장 가까운 유효 교차를 가시 표면으로 택한다. 그 지점의 재질·광원·가림과 추가 광 경로가 색을 결정한다. 래스터화와 광선 추적은 서로 다른 계산 접근이고 한 구현에서 함께 사용할 수도 있다.

종이 모형은 규칙을 드러낸다

첫 예제는 2차원 불투명 삼각형 한 개, 일정한 빨강, 조명 없음이라는 자체 모형이다. 좌하단 원점에 x는 오른쪽, y는 위로 증가한다. 4×4 픽셀의 중심은 (i+0.5,j+0.5), i,j는 0부터 3이다. 중심이 삼각형 내부에 있으면 빨강으로 정한다.

변 위의 중심은 이 예제에서 제외한다. 실제 GPU의 공유 변 소유 규칙이나 안티앨리어싱을 흉내낸다는 주장은 아니다. 한 중심 샘플로 셀 전체의 덮임 면적을 나타내면 계단 현상이 생길 수 있으므로 샘플링과 필터링은 뒤에서 필요한 별도 문제다.

행은 저장 목록의 순서다. 둘째 행을 거절하는 이유는 색이나 목록 위치가 아니라 매개변수 하한이다. 셋째 행에서 유효 후보의 t를 비교하여 C를 B로 교체한다. 같은 광선에서 t가 작을수록 앞이지만 거리의 숫자는 2t다.

중간 과정을 따라가는 예제

화면 삼각형 꼭짓점 (0,0),(4,0),(0,4), 4×4 격자, 중심 포함 조건 x>0,y>0,x+y<4로 정한다. 중심이 포함된 셀을 세어라.

  1. 각 중심의 x,y는 양수이므로 x+y<4만 남는다.

  2. 중심 식을 대입하면 i+j+1<4, 즉 정수 i+j<3이다.

  3. j=0에는 i=0,1,2의 3개, j=1에는 i=0,1의 2개, j=2에는 i=0의 1개다.

  4. j=3에는 없다. 대각선 위 i+j=3 중심은 명시한 규칙에 따라 제외한다.

아래에서 위의 행별 수는 3,2,1,0, 합 6개다. 이는 자체 중심 샘플 모형의 결과이며 GPU의 실제 프레임버퍼가 아니다.

조건을 바꾸어 비교하기

첫 교차와 첫 유효 교차도 최종 답은 아니다

표의 목록에서 처음 읽은 교차를 반환하는 방식, 처음 유효 교차를 반환하는 방식, 모든 유효 교차의 최소 t를 택하는 방식을 비교하라.

  1. 첫 교차는 C이고 유효하므로 첫 유효 교차도 C다. 두 조기 반환 방식은 z = 8을 고른다.

  2. B도 유효하고 t = 2.5가 C의 4보다 작다. 전체 최소 방식은 B를 택한다.

  3. A는 더 작은 t를 갖지만 하한을 통과하지 않아 비교 후보에서 제외한다.

정상 선택은 B, 교차점은 (0,0,5), 거리는 5다. 목록의 첫 유효값 C는 최종 최근접을 보장하지 않는다.

비교할 점

앞 본문의 한 표면 포함 여부에 후보 집합과 최소 선택의 조건을 추가한다.

가려진 표면의 색 변경이 영상에 남지 않는 경우

B의 고정 색이 빨강이고 C가 파랑이다. C를 초록으로 바꾸거나 t = 3인 D를 추가하면 이 광선의 색이 달라지는가? 다른 광선은 조사하지 않는다.

  1. B는 두 경우 모두 가장 가까운 유효 불투명 표면이다. C와 D는 B 뒤에 있다.

  2. 고정 색 규칙은 B의 빨강을 반환하므로 이 샘플은 변하지 않는다.

  3. 전체 장면은 달라졌어도 이 관찰 하나는 같다. 다른 카메라·투명성·조명 경로까지 같다는 결론은 낼 수 없다.

두 변경 모두 이 샘플은 빨강이다. 한 출력값으로 가려진 장면을 유일하게 복원할 수 없다.

연습 1 · 값과 상태 예측

별도 표면 E의 t가 1, F의 t가 5이며 목록은 F, E다. 다른 표면은 없다. 선택 표면·점·거리를 적어라.

힌트 1

허용 범위의 양 끝은 포함한다.

힌트 2

목록 순서 대신 유효 t의 최소를 택한다.

풀이와 답 확인

  1. E와 F 모두 범위를 통과한다.

  2. E의 t = 1이 더 작고 r(1)=(0,0,2)다. 원점에서 거리는 2다.

E를 선택하고 점은 (0,0,2), 거리는 2다.

흔한 오답에서 다시 생각하기

하한에 정확히 놓인 표면은 제외하여 F를 선택한다.

이 계약은 1 ≤ t라고 명시했다. 엄격 부등식으로 바꾸면 다른 문제다.

연습 2 · 오류 찾아 고치기

처리기가 A의 t = 0.5를 전체 최소로 택한 뒤 결과의 색만 지운다. B를 반환하려면 어떤 순서를 고쳐야 하는가?

힌트 1

유효성은 최소 선택의 입력 조건이다.

힌트 2

최종 후보 하나를 지워도 차선 후보는 복원되지 않는다.

풀이와 답 확인

  1. 각 교차에서 범위를 먼저 검사하고 실패 항목은 후보에 넣지 않는다.

  2. 유효한 B와 C의 t를 비교하여 B를 유지한다.

  3. 색만 지우는 후처리를 최근접 판정의 수정으로 사용하지 않는다.

범위 필터 뒤 최소 선택으로 바꾸면 B를 반환한다.

흔한 오답에서 다시 생각하기

선택 뒤 A의 색을 검정으로 바꾸면 정상 배경과 같다.

유효 표면 B가 존재하므로 검정 배경을 반환하면 가시성 결과를 잃는다.

연습 3 · 직접 만들어 보기

목록을 한 번 읽는 최근접 처리기의 상태와 불변식을 설계하라. 유효 교차가 없으면 없음으로 반환하고, 같은 최소 t가 있으면 먼저 읽은 항목을 유지한다.

힌트 1

없음과 t = 0을 구별한다.

힌트 2

새 t가 현재 최소보다 엄격히 작을 때만 교체한다.

풀이와 답 확인

  1. 상태는 없음 또는 (표면 ID,t)다. 처음에는 없음이다.

  2. 유효 범위의 항목만 검사하여 상태가 없거나 t가 더 작으면 교체한다. 동점에는 유지한다.

  3. 접두 목록의 유효 최소 t와 첫 동점 항목이 상태에 있다는 불변식을 유지한다.

빈 후보와 첫 동점 정책을 포함한 상태 전이를 제시한다.

흔한 오답에서 다시 생각하기

초기 최소를 0으로 두고 더 작은 양수만 채택한다.

모든 허용 t가 1 이상이므로 아무 후보도 들어가지 않는다. 없음은 숫자 0과 다른 상태다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

동일한 기하 광선을 방향 (0,0,1)로 다시 표현한다. 원래 허용 공간 z ∈ [2,10]과 B의 점 z = 5를 유지하려면 새 t 범위와 B의 t는 무엇인가?

힌트 1

새 식은 z = t다.

힌트 2

기존 1..5를 숫자 그대로 유지하면 공간 구간이 바뀐다.

풀이와 답 확인

  1. 새 t 범위는 2 ≤ t ≤ 10이다.

  2. B의 새 t는 5이며 점과 원점 거리는 모두 기존의 5를 유지한다.

  3. 매개변수만 재표현했으므로 범위도 같은 공간을 나타내게 조정한다.

새 범위는 [2,10], B의 t는 5다.

흔한 오답에서 다시 생각하기

방향만 바꿔도 t 범위 [1,5]가 같은 공간이다.

그 범위는 새 표현에서 z ∈ [1,5]이므로 원래 구간과 다르다.

소단원 1.2

픽셀·색·gamma

검정과 흰색을 반씩 섞을 때 RGB 코드값의 중간을 그대로 쓰면 빛의 중간일까?

준비 개념과 학습 목표

준비 개념

  • 픽셀은 영상 배열의 한 위치에 저장되는 값이다. 채널은 색을 표현하는 성분이다. 평균 (a+b)/2는 두 수의 같은 가중치 합이다. 거듭제곱 함수는 입력에 비례하는 선형 함수와 다른 변화를 만든다.

학습 목표

  • 색 공간과 코드값의 의미를 연결한다

  • sRGB의 코드값과 linear-light 값을 구분한다

  • 조건을 명시해 빛 평균과 저장값을 계산한다

투명한 검정과 흰색 사이를 보간하면 흰색 자체가 어두워져야 할까요?

앞 본문은 불투명 색의 코드값과 linear-light 값을 구별했다. 투명도까지 바뀌면 채널이 어떤 표현인지도 필요하다. 아래는 동일 sRGB 원색의 linear-light 채널 L과 alpha를 사용한 자체 보간·검정 배경 합성 모형이다. CSS의 모든 보간 공간이 이 공간이라는 주장은 아니다.

straight 표현은 (L,alpha), premultiplied 표현은 (C,alpha)이며 C = alpha × L이다. 보간은 두 끝의 C와 alpha를 같은 가중치로 평균한다. alpha > 0일 때 L = C/alpha로 복원한다. 검정 배경 위 결과는 Lout = alpha × L = C다. alpha = 0이면 나눗셈으로 색을 복원하지 않는다.

양자화 사례는 sRGB 코드가 아닌 별도의 선형 저장 채널을 쓴다. Q(L)=floor(255L+0.5), L ∈ [0,1]로 정하고 .5는 올린다. 저장 정수의 평균과 평균한 실수의 저장값은 연산 순서 때문에 다를 수 있다. 새 수치는 손산술이며 화면이나 장치를 관찰하지 않았다.

먼저 확인할 개념
  • 선형 빛 값과 저장 코드의 구별

    보간·양자화에서 지금 평균하는 값이 어느 표현인지 먼저 정한다.

  • 고정 색 모형의 명시 조건

    가시성 이후의 색 계산도 별도 규칙이며 투명도는 앞의 불투명 선택 계약에 자동 포함되지 않는다.

세 숫자만으로 색 의미가 완성되지 않는다

RGB는 빨강·초록·파랑 성분으로 색을 표현하지만 어느 원색과 백색 기준을 쓰는지 정해야 한다. sRGB는 특정 primaries와 D65 백색 기준을 쓰는 색 공간이다. 같은 숫자 (1,0,0)도 다른 원색을 쓰는 공간에서는 같은 색을 뜻하지 않을 수 있다.

8비트 채널의 정수 0..255는 저장 표현이다. 정수를 255로 나눈 코드값 c를 쓰는 것과 빛에 비례하는 성분 L을 쓰는 것은 다른 단계다. alpha가 있으면 불투명도/합성 의미와 premultiplied 여부도 명시해야 한다. 여기서는 alpha=1의 불투명 RGB, [0,1] 범위만 다룬다.

sRGB는 정확히 하나의 gamma 거듭제곱이 아니다

sRGB decode는 c≤0.04045일 때 L=c/12.92, 그보다 크면 L=((c+0.055)/1.055)^2.4다. 역변환은 L≤0.0031308일 때 c=12.92L, 그보다 크면 c=1.055L^(1/2.4)-0.055다. 어두운 부분의 직선 구간과 나머지 곡선이 있으므로 c^2.2만을 정확한 정의로 쓰면 안 된다.

여기서 gamma라는 말은 이런 비선형 전달 관계를 소개하는 관용어다. sRGB 코드값 0.5는 linear-light 값 약 0.214041이다. 인간이 느끼는 밝기가 정확히 0.214배라는 뜻은 아니다. 지각 밝기, 채널 성분, 광도량의 정의를 같은 수로 섞어 쓰지 않는다.

decode(c) = c / 12.92                         if c <= 0.04045
            ((c + 0.055) / 1.055)^2.4         otherwise
encode(L) = 12.92 * L                         if L <= 0.0031308
            1.055 * L^(1/2.4) - 0.055         otherwise

무엇을 평균하는지 먼저 정한다

같은 sRGB primaries/D65에서 불투명 검정과 흰색을 같은 면적 또는 가중치로 radiometric 평균하는 모형이면 먼저 linear-light로 변환해 평균하고 다시 인코딩한다. 검정L=0, 흰색L=1이라 평균L=0.5다. 이를 sRGB로 인코딩하면 c≈0.735357이다.

코드값만 평균하면 c=0.5이고 decode 결과L≈0.214041로 다른 값을 얻는다. 이것은 항상 모든 디자인 보간을 linear-light로 해야 한다는 주장이 아니다. 지각적 보간·미술적 의도·다른 CSS 보간 공간에는 다른 목적과 규칙이 있다. 물리적인 빛 합산 모형의 계산과 화면에 실제 표시된 빛의 측정도 구별한다.

투명 끝의 검정이 흰색을 어둡게 만드는 잘못된 순서

표의 두 보간 절차를 검정 배경에 합성하고 차이를 계산하라.

  1. premultiplied 절차는 C = 0.5, alpha = 0.5이므로 복원 색은 흰색 L = 1이다. 배경 합성 결과는 0.5다.

  2. straight 직접 평균은 L = 0.5, alpha = 0.5이고 합성 결과는 0.25다.

  3. 같은 alpha라도 보간한 채널 표현이 달라 결과가 다르다. alpha를 sRGB decode하는 단계는 없다.

정상 절차의 선형 결과는 0.5, 변형은 0.25다. 실제 화면의 측정값은 아니다.

  1. 먼저 실수 평균하면 L = 0.45/255이며 Q(L)=floor(0.95)=0이다.

  2. 각 값을 저장하면 Q(L1)=0, Q(L2)=1이다. 정수 평균 0.5를 .5 올림하면 1이다.

물체의 점 하나가 어떤 계산을 지나 화면의 위치로 바뀔까?

준비 개념과 학습 목표

준비 개념

  • 좌표는 기준 축에 대한 수다. 같은 점도 기준을 바꾸면 수가 달라진다. 행렬은 입력 성분의 정해진 선형 조합으로 새 성분을 만드는 표이며 동차좌표의 마지막 성분을 더하면 이동도 행렬로 나타낼 수 있다.

학습 목표

  • local/world/view/clip/screen 좌표를 구별한다

  • 정해진 합성 순서로 점을 변환한다

  • 픽셀 중심과 배열 행 방향의 관례를 명시한다

정규화 좌표가 화면 안이면 나누기 전 좌표도 항상 유효할까요?

앞 본문에서 clip 검사와 w 나눗셈을 다른 단계로 두었다. 이번 자체 계약은 w > 0, −w ≤ x ≤ w, −w ≤ y ≤ w, 0 ≤ z ≤ w를 모두 만족할 때만 통과한다. 통과 후 (x/w,y/w,z/w)를 NDC로 둔다. 이는 특정 API의 모든 깊이·클리핑 규칙을 선언한 것이 아니다.

viewport의 좌하단 원점은 (10,20), 너비는 6, 높이는 4다. xscreen = 10 + 3(xndc+1), yscreen = 20 + 2(yndc+1)이다. 셀 인덱스는 i=floor(xscreen−10), j=floor(yscreen−20)이며 화면의 셀 범위는 10 ≤ xscreen < 16, 20 ≤ yscreen < 24다. top-left 배열의 row는 3−j, column은 i다.

clip 경계가 포함돼도 오른쪽·상단 연속 화면 경계는 저장 셀의 반열린 범위에서 제외한다. 점 하나의 셀 판정과 삼각형을 실제 rasterize하는 edge 소유 규칙은 다른 문제다. 아래 표는 변환 손계산이며 GPU 프레임버퍼를 읽은 결과가 아니다.

각 단계의 좌표에는 기준이 있다

local 좌표는 물체 자체 기준, world는 장면 공통 기준, view는 카메라 기준이다. model 변환은 local에서 world로, view 변환은 world에서 카메라 기준으로 바꾼다. projection은 보이는 범위와 투영을 clip 좌표로 표현한다. 이 이름은 계산의 목적이며 특정 수치만 보고 기준을 추측할 수 없다.

열벡터 관례에서는 p_clip=P V M p_local이며 오른쪽 M부터 적용한다. 보통 점은 (x,y,z,1), 방향 벡터는(x,y,z,0)로 표현해 이동의 효과를 구별한다. 행벡터 관례는 표기와 곱 순서가 달라지므로 서로 다른 관례의 식을 섞으면 안 된다.

클리핑과 나눗셈 뒤 화면으로 옮긴다

일반적인 투영에서 clip 공간의 유효 영역을 먼저 판단하고, 유효한 점은 w로 나누어 정규화 좌표를 얻는다. w=0인 점에 단순 나눗셈을 적용할 수 없다. 깊이 범위·좌표 손잡이 방향·y 방향 등은 API와 설정마다 다르므로 한 관례를 모든 플랫폼의 규칙으로 선언하지 않는다.

종이 예제는 평면 z=0,w=1, world/view 범위 x,y∈[0,4], NDC x,y∈[-1,1]인 직교 모형이다. x_ndc=2x/4-1, y_ndc=2y/4-1로 정한다. viewport는 좌하단 원점 4×4로 x_screen=(x_ndc+1)×2, y_screen=(y_ndc+1)×2를 쓴다. 이것은 자체 명시한 모형이지 특정 GPU API 호출 기록이 아니다.

영상 배열은 축 관례까지 기록한다

픽셀 셀(i,j)의 중심은(i+.5,j+.5)다. 정수 인덱스와 연속 화면 좌표는 다른 개념이므로 화면위치(1.5,1.5)는 이 관례에서 셀(1,1)의 중심이다. 오른쪽/상단 경계 4는 마지막 중심 3.5와 같지 않다.

풀이와 답 확인

  1. F는 하한 미만이라 제외한다. B와 A 중 A의 t = 2.5가 더 작고 교차점은 (0,0,5), 거리는 5다. B는 가려진 불투명 표면이므로 고정 색만 바꿔도 이 샘플은 흰색을 유지한다.

  2. P는 clip 조건을 통과하고 NDC (−0.5,0.25,0.5), screen (11.5,22.5)를 얻는다. 상대 셀 i = 1, j = 2이므로 row = 1, column = 1이다. −P는 w < 0이어서 같은 나눗셈 결과와 무관하게 거절한다.

  3. 보간의 두 끝은 (C,alpha)=(1,1),(0,0)이다. 중간 C = 0.5, alpha = 0.5이고 복원 L = 1, 검정 위 선형 결과는 0.5다. straight 직접 평균은 L = 0.5, alpha = 0.5라서 결과 0.25다.

  4. 정상 선형 0.5의 sRGB 코드는 앞 본문의 약 0.735357이며 .5 올림의 8비트 값은 188이다. 이 숫자는 표시 장치나 관찰자의 밝기를 측정한 값이 아니다.

유효 최근접은 A이며 점과 거리는 (0,0,5)와 5다. 배열 주소는 row 1, column 1이다. −P는 clip 거절이다. 정상 배경 합성의 선형 값은 0.5, 변형은 0.25이며 정상 저장 코드는 약 0.735357, 8비트 값은 188이다.
