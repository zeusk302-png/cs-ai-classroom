소단원 2.1

동차좌표

이동은 원점을 옮기는데, 원점을 고정하는 선형 행렬로 어떻게 표현할까?

준비 개념과 학습 목표

준비 개념

  • 열벡터 (x,y)ᵀ는 두 좌표를 세로로 모은 것이다. 행렬곱의 i번째 결과는 행i와 벡터 성분의 곱을 더해 계산한다.

  • 선형 L은 L(αu+βv)=αL(u)+βL(v)를 만족하며 L(0)=0이다. 원점을 t≠0으로 보내는 이동은 2D 선형변환이 아니다.

  • 이 단원의 좌표는 x 오른쪽/y 위, 실수값이다. 모바일 화면의 y 아래 관례나 저장 배열 순서와 구분한다.

학습 목표

  • 점과 방향의 w 성분을 구분한다.

  • affine 행렬과 비영 w의 좌표 복원을 계산한다.

  • 확장 공간 선형성과 원래 공간 affine성을 분리한다.

한 성분을 추가해 affine 계산을 묶는다

2D 점(x,y)을 p=(x,y,1)ᵀ로 표현한다. 선형부분 A와 이동t를 가진 affine F(x)=Ax+t는 M=[A t;0 0 1]이라는 3×3 행렬로 p를 계산하면 된다. 확장 3D 벡터 공간에서 곱은 선형이지만 우리가 관심을 갖는 w=1 평면에 제한한 함수는 일반적으로 affine이다. t≠0인 이동을 원래 2D에서 선형이라고 부르지 않는다.

이동 T(tx,ty)=[[1,0,tx],[0,1,ty],[0,0,1]]이면 결과는(x+tx,y+ty,1)이다. 마지막 성분 1에 곱해진 이동 항 때문에 이 효과가 생긴다. 3D에서는 같은 구성으로 4×4와(x,y,z,1)을 사용한다. 행렬을 메모리에 row-major로 저장하는지는 열벡터 수학 관례와 다른 선택이다.

점과 변위를 구별한다

점 p와 q의 차이는 q−p=(dx,dy,0)ᵀ로 표현된다. 이 방향/변위 d는 위치가 아니라 두 점 사이의 이동량이다. affine M을 적용하면 Md=(Ad,0)이므로 순수 이동이 변위를 바꾸지 않는다. Mq−Mp=M(q−p)라는 확장 공간 선형성에서 이 사실을 다시 얻을 수 있다.

따라서 w=0인 방향에 tx/ty를 더하면 두 점 사이 차이를 보존하는 계약을 깨뜨린다. 영 방향(0,0,0)은 유효한 영 변위로 쓰지만 비영 projective point 대표는 아니다. 이 단원은 affine 방향 계산과 projective 유한점 해석을 구분한다. 표면 normal은 일반 방향과 별도 변환 규칙이 필요함을 둘째 소단원 심화에서 확인한다.

w로 나누는 조건을 명시한다

유한점(x,y)은 비영 λ에 대해(λx,λy,λ)처럼 대표할 수 있다. 일반 대표(X,Y,w)의 유한 Cartesian 좌표는 w≠0일 때(X/w,Y/w)다. 예컨대(4,8,2)는(2,4)를 나타낸다. 마지막 성분이 2라고 점이 두 배 멀리 있다는 해석은 잘못이다.

w=0에는 이 나누기를 적용할 수 없다. affine 마지막행(0,0,1)은 입력 w를 보존하므로 점w1과 방향w0를 유지하지만 일반 projective 행렬은 w를 바꿀 수 있다. 원근 나누기와 clipping은 다음 단원에서 다루며 이곳의 affine 행렬 검산을 실제 렌더러의 전체 파이프라인으로 확대하지 않는다.

중간 과정을 따라가는 예제

T(3,−1)을 점p=(2,4,1), 방향d=(2,4,0), 같은 점의 대표q=(4,8,2)에 적용하라.

  1. p의 첫 행은 2+3×1=5, 둘째는 4−1×1=3, 마지막은 1이다.

  2. d에서는 이동 항이 0에 곱해져(2,4,0)으로 유지된다.

  3. q 결과는(4+3×2,8−1×2,2)=(10,6,2)다.

  4. q의 결과는w2로 나누어(5,3)을 얻으며 p의 결과와 같은 유한점이다.

점(5,3), 방향(2,4), 대표(10,6,2)→(5,3)이다. 비영w 나누기와 affine 방향 계약의 결과다.

오해와 반례

동차 성분은 언제나 1이고 w가 0이면 그냥 0으로 나누면 된다.

방향은w0이며 나눌 유한점이 아니다. (4,8,2)는w2지만 유한점(2,4)다. representative의 값과 Cartesian 좌표를 분리하고 w≠0 조건을 확인해야 한다.

한 단계 더

심화: 가역 affine M은 det A≠0일 때 M⁻¹=[A⁻¹,−A⁻¹t;0 0 1]다. 곱의 좌상단은I, 이동 항은 A(−A⁻¹t)+t=0이므로 MM⁻¹=I이며 반대 곱도 같다. 이 증명은 방향w0까지 적용되지만 A가 특이면 역변환을 보장하지 않는다. 모형의 전체행렬 0벡터와 projective 비영 대표를 혼동하지 않는다.

소단원 2.2

이동·회전·스케일

크기를 바꾸고 돌린 뒤 이동하는 것과 순서를 바꾼 결과는 같을까?

준비 개념과 학습 목표

준비 개념

  • 각도θ는 라디안이며 π/2는 90도다. x 오른쪽/y 위에서 양의 회전은 반시계다.

  • 행렬곱 ABp는 B가 먼저 p에 작용하고 A가 뒤에 작용한다. 결합법칙은 성립하지만 AB=BA는 일반적으로 성립하지 않는다.

  • 스케일은 축마다 배율을 곱한다. 음수는 반전,0은 해당 축 정보를 없애며 비영 배율만이 역수를 갖는다.

학습 목표

  • 이동·회전·스케일의 완전 행렬을 사용한다.

  • 열벡터 합성 순서를 계산으로 확인한다.

  • pivot 및 가역성·normal 변환의 조건을 설명한다.

행렬을 관례와 함께 적는다

S(sx,sy)=[[sx,0,0],[0,sy,0],[0,0,1]], R(θ)=[[cosθ,−sinθ,0],[sinθ,cosθ,0],[0,0,1]], T(tx,ty)=[[1,0,tx],[0,1,ty],[0,0,1]]를 쓴다. 이는 열벡터·y위 관례다. y아래 화면이나 행벡터 문헌에서는 부호·전치·곱 순서가 달라질 수 있으므로 식만 옮기지 않는다.

회전은 원점 기준이다. cos²θ+sin²θ=1에서 RᵀR=I이므로 길이와 내적을 보존한다. 비균일 스케일sx≠sy는 일반적으로 길이·각도를 보존하지 않는다. sx=0이면 서로 다른 x좌표가 같아지는 반례가 있어 원래 점을 하나로 복원할 수 없다.

오른쪽부터 적용하고 기준점을 확인한다

먼저 S, 다음 R, 마지막 T라면 M=TRS다. p를 S에 넣은 뒤 R, T에 순서대로 넣어 계산하면 행렬곱과 같고 오류 위치를 찾기도 쉽다. SR이나 RS의 차이는 비균일 스케일과 회전에서 나타나며 순수 이동과 회전도 일반적으로 교환되지 않는다.

점 c를 기준으로 회전하려면 c를 원점으로 옮기고 회전한 뒤 원래 자리로 옮긴다. 따라서 T(c)RT(−c)다. 이 합성은 c 자체를 고정한다. 원점 회전 R과 pivot 회전은 다른 기능이며 같은 숫자 θ만으로 결과가 정해지지 않는다.

역변환과 normal은 별도 계약이다

모든 배율이 비영이고 회전/이동이 정의되면 (TRS)⁻¹=S⁻¹R⁻¹T⁻¹다. 적용 순서를 반대로 해야 각각의 효과가 지워진다. R⁻¹=Rᵀ, T⁻¹=T(−t)지만 일반 affine 전체행렬의 역이 단순 전치라는 규칙은 성립하지 않는다.

표면 normal n은 접선v와 nᵀv=0인 방향이다. 가역 선형부분 A에서 접선Av에 수직을 보존하려면 n′=A⁻ᵀn을 사용한다. normal n은 비영 벡터로 두며, 필요하면 변환 후 길이로 나누어 다시 정규화한다. 가역 A에서는 변환된 비영 normal의 길이도 0이 아니다. 일반 방향Av와 같은 식을 쓰면 비균일 스케일에서 수직성이 깨질 수 있다. 특이A나 투영에는 이 규칙을 자동 적용하지 않는다.

중간 과정을 따라가는 예제

p=(1,2,1), S=diag(2,3,1), R=R(π/2), T=T(3,−1)이다. M=TRS의 결과와 반대 순서 SRT를 비교하라.

  1. Sp=(2,6,1)이며 아직 이동/회전하지 않았다.

  2. RSp=(−6,2,1)이다.90도 반시계는(x,y)→(−y,x)다.

  3. TRSp=(−3,1,1)이다. 이동은 마지막에(3,−1)을 더한다.

  4. 반대로 Tp=(4,1,1),RTp=(−1,4,1),SRTp=(−2,12,1)이다. (−3,1)과 다르다.

TRS는(−3,1), SRT는(−2,12)로 일반적 교환 불가능성을 보여 준다.

종이와 본문으로 직접 해보기

c=(1,1)을 기준으로 p=(2,1)을 90도 반시계 회전하라. c도 변하는지 확인하라.

힌트 보기

p−c를 먼저 회전하고 c를 다시 더한다.

풀이 보기

p−c=(1,0)→(0,1), c를 더하면(1,2)다. c−c=0은 회전 후에도 0이라 c는(1,1)로 고정된다.

오해와 반례

같은 변환 세 개면 곱의 순서는 상관없고 역행렬은 늘 전치다.

위 TRS/SRT가 다른 반례다. T(3,−1)의 전치는 이동 역행렬이 아니며 마지막행까지 바꾼다. 순서와 가역 조건을 명시해야 한다.

한 단계 더

심화: A=diag(2,1), 접선v=(1,1), normal n=(1,−1)이면 nᵀv=0이다. 같은 A를 normal에 써(2,−1)로 만들면 Av=(2,1)과 내적 3이다. A⁻ᵀn=(1/2,−1)은 Av와 내적 1−1=0이다. 일반 증명은 (A⁻ᵀn)ᵀAv=nᵀA⁻¹Av=nᵀv이며 detA≠0이 필요하다. 이것은 수직 보존이지 GPU 조명 결과의 검증이 아니다.

소단원 2.3

model·world·view 변환

물체가 움직인 것과 같은 장면을 다른 카메라 좌표로 읽는 것은 어떻게 다를까?

준비 개념과 학습 목표

준비 개념

  • 좌표 프레임은 원점과 축을 정한 기준이다. 같은 점을 서로 다른 프레임에서 표현하면 숫자가 달라져도 점 자체는 같을 수 있다.

  • 부모←자식 행렬은 자식 좌표를 부모 좌표로 바꾼다. 화살표의 출발/도착 공간을 먼저 정한다.

  • 가역 행렬의 역은 변환을 되돌린다. 카메라 pose C는 camera→world이며 view V는world→camera=C⁻¹이다.

학습 목표

  • 계층 합성의 공간을 표시한다.

  • model/world/view 좌표를 순차 계산한다.

  • 카메라 pose와 view inverse 및 투영 이전 범위를 구별한다.

물체의 지역 좌표를 장면에 놓는다

model 좌표는 재사용할 물체를 정의하는 지역 좌표다. world 좌표는 장면의 공통 기준이고 model matrix M은 model→world다. 계층에서 자식→부모 행렬 L과 부모→world P라면 M=PL이다. 자식 지역 이동이 부모의 회전 영향을 받을 수 있으므로 좌표 수치만 더하는 것으로 일반화하지 않는다.

같은 model 점을 서로 다른 M으로 배치하면 여러 인스턴스를 만들 수 있다. 점마다 전역 위치를 처음부터 정의하는 방법보다 지역 설계와 배치를 분리할 수 있다. 이 단원은 자체 2D 계층을 사용하고,3D에서는 동일한 역할의 4×4를 사용한다. 그래픽스 API의 저장 순서나 셰이더 곱 관례는 별도로 맞춰야 한다.

카메라 위치를 빼고 축 기준으로 읽는다

카메라 pose C=[R t;0 1]는 카메라 원점을 world의 t로 보내고 카메라 축을 R의 열로 놓는다. R이 직교 회전이면 V=C⁻¹=[Rᵀ,−Rᵀt;0 1]다. world 점 pw의 view 좌표는 Rᵀ(pw−t)다. 카메라와 같은 방향으로 점에C를 한 번 더 곱하는 것이 아니다.

view 변환은 좌표 기준을 바꾸는 단계이며 화면 픽셀·원근·가시성 결정을 끝내지 않는다.3D 카메라가 어느축을 정면으로 보는지와 handedness는 구현 계약에 따라 정한다. 여기서는 x/y만 있는 2D 카메라 축을 정의해 계산하고 특정 API의z/깊이 규칙을 암묵적으로 섞지 않는다.

공간 표기로 합성 오류를 찾는다

pview=V M pmodel이며 오른쪽 model 변환부터 적용한다. 여러 부모가 있다면 M=W←parent·parent←child·child←model처럼 인접 공간이 이어져야 한다. 반대로 화면에서 객체 좌표로 돌아가려면 가역 affine 구간에는 M⁻¹C를 쓸 수 있지만 투영·클리핑·깊이 소실까지 자동 되돌리는 것은 아니다.

부모 스케일 0처럼 M이 특이면 world에서 같은 위치가 된 서로 다른 model 점을 구별할 수 없어 역이 없다. 카메라의 순수 pose R/t는 가역이지만 자료가 오염되거나 회전이 아닌 행렬이면 직교공식 대신 실제 역 조건을 확인한다. 좌표식 계산의 정확성과 장면/GPU 화면에서의 시각적 결과는 별도 증거다.

중간 과정을 따라가는 예제

열벡터 2D 모형에서 자식→부모 L=T(0,2), 부모→world P=T(3,0), model 점p=(1,0,1)이다. camera→world C=T(1,0)R(π/2). world/view 점을 구하라.

  1. Lp=(1,2,1)이다. 자식의 원점을 부모좌표에서 y2에 놓았다.

  2. PLp=(4,2,1)이다. M=PL=T(3,2)로 model→world다.

  3. 카메라 위치(1,0)을 뺀 world 변위는(3,2)다. Rᵀ은 90도 시계회전이므로(2,−3)이다.

  4. V=R(−π/2)T(−1,0)이므로 pview=(2,−3,1). 다시 C를 곱하면 R로(3,2),이동으로(4,2)가 되어 원 world 점을 복원한다.

world=(4,2),view=(2,−3)이며 C V pworld=pworld다. 화면 픽셀이나 실제 카메라 측정값이 아니다.

오해와 반례

view 행렬은 카메라 위치와 회전을 그대로 넣은 C이며 변환이 끝나면 픽셀 좌표다.

C는camera→world, V는반대 방향이다. 위 예제에서 C pworld와 V pworld는 다르다. view 뒤에도 투영·화면 매핑이 남으며 좌표 공간 이름만으로 같은 의미가 되지 않는다.

한 단계 더

심화: 가역 P/L에서(PL)⁻¹=L⁻¹P⁻¹다. 모델→부모→world→camera 경로와 반대 camera→world→부모→model 경로를 이어 곱하면 항들이 순서대로I로 지워진다. 이 공간별 계약 확인은 곱을 잘못 전치하거나 좌표 단위를 섞는 오류를 찾는다. math 담당과 열벡터·normal inverse transpose·비영 스케일 조건을 교차 대조했고, 해당 논증은 affine 구간에 한정한다.

출처와 확인 범위
  • UC Berkeley CS184: Lecture 6 summary (1998)

    실제 전체 본문에서 R inverse=R transpose, 오른쪽부터 합성, 좌표축 열과 프레임의 inverse, object/world/viewer 구별을 읽었다. VRML 예제를 실행하지 않았다.

  • UC Berkeley CS184: Lecture 7 summary (1998)

    실제 homogeneous point 표현과 camera-to-world [R v;0 1] 본문을 읽었다. w=0까지 일반 유한점으로 나누는 잘못된 일반화를 하지 않고 w≠0 조건을 명시한다. 원문의 특정 카메라 기본값/VRML 회전 수치 예제는 복제하지 않는다.
