예순네 배정을 모두 검사하면 예순네 저장칸 묶음이 필요한가?

새 가상 식은 변수 여섯 개를 가지며 읽기 전용 식의 인코딩은 40비트다. 배정 하나는 6비트이고 식 평가 작업칸은 최대 8비트라는 별도 계약을 둔다. 주소·제어·종료 정보는 이 첫 배열 비교에서 제외하고 따로 보고한다. 두 배열을 동시에 보유하는 최대량과 여러 배정을 거치며 누적해서 채운 비트 수를 구별하자.

배정 배열을 덮어쓰며 64개를 검사하면 배정 배열 자체는 계속 6비트다. 평가 작업칸 8비트와 동시 사용하면 두 배열의 피크는 14비트다. 입력을 포함한 배열 피크는 54비트다. 한 배정이 끝날 때 작업칸을 재사용하므로 64×14를 최대 공간이라고 쓰지 않는다. 이 숫자는 전체 기계 공간의 정확한 값이 아니며 빠진 제어 상태를 포함한 점근 분석은 따로 필요하다.

공간 제한은 종료를 자동 보장하지 않는다. 결정적 기계가 입력과 모든 저장칸·헤드·제어 상태까지 같은 구성으로 돌아오면 뒤 행동도 반복된다. 고정된 입력의 유한 구성 상계로 종료하는 기계의 최대 경로를 논증할 수 있지만 단순히 출력이나 카운터가 같다는 관찰은 전체 구성의 반복이 아니다.

먼저 확인할 개념
  • 최대 공간과 입력 포함 규약

    기본의 입력 포함/보조 공간 및 순차 열거 규약을 배열별 예산으로 구체화한다.

  • 항상 종료하는 결정 절차

    작은 공간에서 실행한다는 사실과 모든 입력의 종료·정답 계약을 구별한다.

시간은 누적되고 공간은 재사용된다

시간 복잡도는 입력 길이에 따른 실행 단계 수를 다룬다. 공간 복잡도는 계산 중 필요한 최대 저장 규모를 다룬다. 하나의 저장 칸을 천 번 덮어쓴다고 동시에 천 칸을 사용한 것은 아니다. 길이가 같은 모든 입력의 최악 경우를 기준으로 상한을 설명한다.

무엇을 공간으로 세는지는 모델에 따라 명시한다. MIT 슬라이드는 입력이 놓인 테이프까지 포함한 도달 칸 수를 설명한다. 프로그램 분석에서 읽기 전용 입력을 제외한 보조 공간을 따로 셀 수도 있다. 입력 포함 O(n)과 보조 O(log n)은 서로 다른 계산 규약일 수 있다.

괄호 하나의 종류는 개수로 검사한다

한 종류의 괄호 문자열을 왼쪽부터 읽어 여는 괄호면 개수를 1 늘리고 닫는 괄호면 1 줄인다. 음수가 되면 즉시 거절하고 끝에서 0이면 받아들인다. 저장하는 개수는 최악에 0부터 n까지다.

이진 개수에는 ⌈log₂(n+1)⌉비트가 필요하다. 고정 크기 제어 정보와 필요한 위치 정보도 포함하여 보조 공간을 O(log(n+1))로 설명한다. 입력을 같은 테이프에 저장하는 모델이면 그 입력 n칸도 포함한다. 여러 괄호 종류의 올바른 중첩을 단순 개수 하나로 검사할 수는 없다.

완전 탐색도 공간을 아껴 순서대로 한다

변수 k개의 모든 진리값 배정은 2ᵏ개다. 배정 하나를 k비트로 저장하고 식을 평가한 뒤 다음 배정으로 덮어쓸 수 있다. 전체 배정을 동시에 저장하지 않아도 된다.

식의 길이와 평가 저장 공간까지 포함해 분석해야 한다. 다항 공간이 다항 시간을 자동 뜻하지는 않는다. PSPACE는 다항 공간으로 결정하는 언어들의 집합이다. 결정 계산의 종료와 공간 제한을 함께 요구하며, 실행 중 발견한 작은 사례가 전체 입력의 복잡도 증명은 아니다.

중간 과정을 따라가는 예제

길이 8의 문자열 (()(()))를 개수 방식으로 검사하라. 이 문자열에서 최대 개수와 길이 8의 임의 입력을 위한 개수 비트 폭을 구하라.

  1. 문자마다 갱신한 개수는 1,2,1,2,3,2,1,0이다. 음수가 없고 끝이 0이라 받아들인다.

  2. 이번 입력의 최대 개수는 3이다. 그러나 길이 8의 입력 ((((((((에서는 개수가 8까지 올라간다.

  3. 0부터 8까지 9개 값을 표현해야 하므로 ⌈log₂9⌉=4비트다. 이번 입력만 보고 항상 2비트면 충분하다고 정하면 안 된다.

이번 입력은 올바르고 최대 개수 3이다. 길이 8 전체 입력을 처리할 카운터는 4비트가 필요하다.

조건을 바꾸어 비교하기

순차 재사용과 기록 보존의 차이

배정마다 1비트 결과를 보존하고 앞 배열 계약은 유지하면 보조 배열 피크와 입력 포함 배열 피크는?

  1. 결과 기록 배열은 처음부터 64비트를 할당한다. 마지막 결과를 기록할 때에도 평가 작업칸 8비트를 아직 해제하지 않는다는 계약을 둔다.

  2. 이 시점에 배정 6비트·작업칸 8비트·결과 기록 64비트가 함께 있다.

  3. 보조 배열 피크는 78비트이며 입력 포함 배열 피크는 118비트다.

결과 보존 정책을 추가하면 같은 순차 열거도 배열 피크가 달라진다.

비교할 점

이전 14비트는 모든 결과를 누적 저장하지 않는 정책이었다. 검사 횟수가 같아도 보존 정책이 다르다.

유한 구성 상계에 포함할 것

별도 결정적 한 테이프 모형은 사용 칸 4개, 헤드 위치 4가지, 상태 3개, 테이프 기호 2개다. 입력도 이 네 칸에 포함하며 테이프 바깥 이동을 금지한다. 전체 구성 상계와 반복의 의미를 구하라.

  1. 테이프 내용은 2⁴=16가지다.

  2. 헤드·상태·내용을 곱하면 4×3×16=192가지다. 도달 불가능한 구성도 포함한 상계다.

  3. 같은 전체 구성이 종료 전 두 번 나타나면 결정적 후속 경로가 반복되므로 종료하지 않는다.

  4. 항상 종료하는 이 제한 모형의 한 실행에서는 종료 구성까지 서로 다른 방문 구성이 최대 192개다.

192는 이 제한 모형의 구성 수 상계이며 일반 튜링기계의 고정 시간 제한이 아니다.

풀이와 답 확인

네 말단 경로 중 두 개가 수락하면 수락 확률은 반드시 절반일까?

새 공정 독립 동전 분기 모형은 첫 0에서 수락하고 첫 1이면 계속한다. 10에서 거절, 110에서 수락, 111에서 거절한다. 말단 문자열은 0,10,110,111로 서로의 접두가 아니다. 각 깊이가 달라 말단 경로를 같은 무게로 세면 확률이 틀린다.

특정 경로 확률은 그 경로의 동전 수 k에 대해 2⁻ᵏ이다. 이 모형의 말단 확률은 1/2,1/4,1/8,1/8로 합이 1이다. 수락 말단 두 개의 질량은 5/8이다. 수락 경로 존재와 높은 수락 확률, 그리고 모든 입력에 대한 오류 상계는 각각 다른 조건이다.

오류 증폭은 한 고정 입력에서 같은 정답을 겨냥하는 독립 실행들에 적용한다. 결과가 복사되거나 공통 실패 사건에 묶이면 각 실행의 오류율만으로 다수결 오류를 계산할 수 없다. 또한 이 장의 계산은 가정한 확률의 정확한 손모형이며 난수 구현·실제 정확도를 검증한 결과가 아니다.

  • 누적 시간과 재사용 공간

동전을 던지는 계산에는 확률이 있다

확률적 계산은 무작위 비트에 따라 경로를 선택한다. 독립인 공정한 동전 k번의 특정 결과열은 확률 2⁻ᵏ다. 여러 수락 경로의 확률을 합하여 입력 하나의 수락 확률을 구한다.

비결정적 계산의 수락은 수락 경로가 존재한다는 조건이다. 경로가 존재해도 그 경로를 무작위로 고를 확률은 매우 작을 수 있다. 변수 n개의 정답 배정이 하나뿐이면 공정한 무작위 배정이 그것을 고를 확률은 2⁻ⁿ이다. 이를 높은 확률의 효율적 해결과 동일시하지 않는다.

오류 조건은 각 입력에 적용한다

양쪽 오류의 확률적 결정 알고리즘은 예 입력에서 수락 확률이 높고 아니오 입력에서 거절 확률이 높아야 한다. 흔히 오류 상한 1/3처럼 1/2보다 작은 고정 상수를 사용한다. 전체 자료의 평균 정확도만 높다는 조건과 다르다.

BPP에서는 다항 시간과 각 입력의 제한된 오류 확률을 요구한다. 아래 정답 확률 3/4 사례는 반복 계산을 설명하는 가상 가정이다. 임의 문제의 실제 알고리즘을 구성한 것이 아니다. 항상 정답이지만 실행 시간이 무작위인 방식과 오류를 허용하는 방식도 구별한다.

독립 반복은 같은 오류를 복사하는 일이 아니다

각 실행의 정답 확률이 3/4이고 결과들이 독립이라고 가정하자. 세 번의 다수결은 틀린 실행이 두 번 이상일 때 실패한다. 실패 확률은 3×(1/4)²×(3/4)+(1/4)³=5/32다.

동일한 난수 결과를 그대로 재사용해 세 출력이 항상 같다면 다수결 오류는 1/4에서 줄지 않는다. 반복 증폭에는 독립성과 실행당 오류 상한 같은 조건이 필요하다. 반복 횟수를 늘려도 오류를 정확히 0으로 만든다고 주장하지 않는다.

수락 사건을 다른 프로그램의 표시 사건으로 옮겨도 종료 문제와 같은 질문일까?

새 관찰 언어 MARK는 인코딩된 기계 N이 입력 y에서 특별한 기호 ◇를 한 번이라도 쓰는지를 묻는다. 이 기호는 N을 감싸는 기계의 예약 표지이며 원래 M의 시뮬레이션 데이터는 ◇를 포함하지 않는 별도 인코딩 영역에 저장한다. 관찰 사건과 원래 수락이 정확히 일치하도록 감싼 기계를 만들자.

변환은 M(w)를 먼저 실행하지 않는다. 고정된 코드와 입력을 가진 N의 설명을 생성하고 끝낸다. N은 자기 입력을 무시하고 M(w)를 시뮬레이션한다. M이 수락하면 ◇를 쓰고 종료한다. M이 거절하면 ◇ 없이 종료하고, M이 무한 실행하면 표지 없이 계속한다. 따라서 수락과 표지 쓰기는 동치지만 단순 종료는 동치가 아니다.

인식기는 표지 쓰기를 발견하면 수락할 수 있지만 아직 표지가 없다는 유한 관찰만으로 영원히 안 쓸 것이라 판정할 수 없다. 결정불가능성 환원에는 모든 입력에서 끝나는 코드 변환과 YES/NO 동치가 필요하다. 반대로 두 보완 언어의 적법한 인식기가 있으면 교대로 한 단계씩 실행하여 반드시 끝나는 결정기를 구성할 수 있다.

먼저 확인할 개념
  • 전체 종료하는 many-one 환원

    기본 ATM→HALT의 방향·코드 생성과 실행 구별을 새 표지 사건으로 옮긴다.

  • 존재·확률·확정 보장의 구별

    특정 경로 존재와 유한 관찰이 전체 입력의 결정 보장인지를 분리한다.

무엇을 묻는 분류인지 구별한다

정규·문맥자유 분류는 어떤 언어를 특정 문법이나 자동자로 표현할 수 있는지 다룬다. 결정가능은 모든 입력에서 종료하여 예/아니오를 맞힐 수 있는지 다룬다. 인식가능은 예 입력의 수락을 보장하지만 아니오 입력에서 영원히 실행할 수 있다.

P·NP·PSPACE 같은 분류는 결정가능한 문제의 자원과 계산 조건을 더 구별한다. 빠르지 않음과 결정불가능은 다르다. 2ⁿ개 경우를 전부 검사해 종료하는 알고리즘은 느릴 수 있지만 그 자체로 결정가능성을 보여 준다.

변환은 모든 입력에서 끝나야 한다

A≤mB라는 계산가능 many-one 환원은 모든 입력에서 종료하는 f를 만들고 x∈A와 f(x)∈B가 동치임을 요구한다. B의 판정기 뒤에 변환 f를 붙이면 A의 판정기를 만들 수 있다.

따라서 A가 결정불가능하고 A≤mB라면 B도 결정불가능하다. A가 쉽고 A≤mB라는 사실만으로 B가 쉽다고 결론 내릴 수 없다. 다항 시간의 어려움을 전달하려면 변환도 다항 시간이라는 추가 자원 조건을 확인해야 한다.

수락과 단순 종료를 혼동하지 않는다

ATM은 기계 M이 입력 w를 수락하는지를 묻고 HALTTM은 M이 w에서 종료하는지를 묻는다. M이 거절하고 종료하는 경우 때문에 쌍을 그대로 옮기면 두 조건이 동치가 아니다.

새 기계 N은 자기 입력을 무시하고 고정된 M(w)를 실행한다. M이 수락하면 N은 종료하고, M이 거절하면 N은 계속 반복한다. M이 계속 실행하면 N도 계속 실행한다. N의 설명을 만드는 변환은 M(w)의 완료를 기다리지 않고 코드만 생성하여 끝난다. 잘못된 인코딩은 알려진 무한 반복 기계의 쌍으로 보내 아니오를 보존한다.

중간 과정을 따라가는 예제

ATM의 쌍 (M,w)를 HALTTM의 쌍 (N,빈 입력)으로 바꾼다. M(w)의 수락·거절 종료·무한 실행 세 경우에서 N의 종료 여부를 확인하라.

  1. M이 수락하면 N도 종료한다. 원문제 예와 대상 문제 예가 일치한다.

  2. M이 거절하고 종료하면 N은 그 뒤 무한 반복한다. 원문제 아니오와 대상 문제 아니오가 일치한다.

  3. M이 무한 실행하면 N은 기다리며 무한 실행한다. 잘못된 원인코딩도 무한 반복 기계로 보내 아니오를 보존한다.

  4. 변환은 M의 코드를 실행해 결과를 결정하지 않고 감싼 N의 설명을 만드는 유한 작업이다. 따라서 환원 자체는 모든 입력에서 끝난다.

수락하는 경우에만 N이 종료하므로 ATM≤mHALTTM이다. ATM의 결정불가능성이 이 방향으로 HALTTM에 전달된다.

조건을 바꾸어 비교하기

수락 표시 환원과 잘못된 종료 해석

위 f에서 M이 거절 종료하는 경우와 수락하는 경우를 비교하여 ATM≤mMARK 및 잘못된 ATM≤mHALT 주장을 감사하라.

  1. 수락하면 N은 표지를 쓰므로 MARK가 YES다.

  2. 거절 종료하면 N도 종료하지만 표지를 쓰지 않으므로 MARK는 NO다.

  3. 같은 f의 결과를 HALT에 보내면 거절 종료도 YES라 양방향 동치가 깨진다.

이 f는 MARK로의 환원이며 같은 f가 HALT 환원이라는 주장은 틀리다. MARK가 결정가능하면 ATM도 결정가능해져 모순이므로 MARK는 결정불가능하다.

비교할 점

기본 HALT 환원은 거절한 뒤 무한 반복하는 다른 감싸기다. 대상 질문을 바꾸면 코드를 다시 점검해야 한다.

두 인식기의 공정한 교대

R은 L을, S는 보완 L을 인식하며 각각 YES에만 수락한다. 별도 입력에서 R은 영원히 실행하고 S는 자기 4번째 단계에 수락한다. 교대 판정기를 추적하라.

  1. R 한 단계, S 한 단계로 한 라운드를 구성한다.

  2. 세 라운드 뒤에는 두 기계가 각각 세 단계 실행되었고 판정은 아직 없다.

  3. 넷째 라운드의 S 수락을 관찰하면 입력은 L 밖이므로 거절한다.

  4. L 입력이면 R이 언젠가 수락한다. L 밖이면 S가 언젠가 수락하므로 항상 끝난다.

이 입력은 넷째 라운드에 거절하며 합계 여덟 모형 단계까지 실행한다.

비교할 점

R이 끝날 때까지 먼저 기다리면 S를 영원히 실행하지 못할 수 있다. 인식기의 거절만으로 판정하는 것이 아니다.

  4. 변환은 실행 결과를 기다리지 않으므로 전체 종료하며 수락 iff 두 표지 사건이다.

공간·확률·관찰 계약을 하나의 감사표로 구분한다

공간 장부의 가상 절차는 변수 6개의 64개 배정을 순차 평가한다. 입력은 40비트, 배정 배열은 6비트, 평가 배열은 8비트이며 결과를 보존하지 않는다. 주소와 제어 정보는 제외했다. 이와 별개의 확률 모형에서는 같은 배열 예산을 사용하는 결정 절차의 한 입력에 대한 실행당 오류 확률을 1/4로 가정한다. 다섯 독립 실행을 다수결하고 수락 수를 3비트 카운터에 보존한다. 실행들은 순차이며 한 실행의 두 보조 배열을 재사용한다. 이 확률 절차의 보조 배열 피크와 입력 포함 피크, 다수결 오류를 보고하라. 별도 MARK 환원에서 거절 종료하는 M과 잘못된 인코딩을 YES로 옮긴 보고서를 고쳐라. 이 전체 손모형이 실제 학생·난수·튜링기계 검증인지도 적어라.

힌트 1

한 실행의 배열 14비트와 수락 카운터 3비트가 함께 존재한다. 다섯 작업 배열을 동시에 보유하지 않는다.

힌트 2

다수결 오류에는 3/4/5번 오류가 들어간다. 표지 사건은 단순 종료가 아니라 예약 기호 쓰기다.

풀이와 답 확인

  1. 보조 배열 피크는 6+8+3=17비트다. 입력 포함 배열 피크는 40+17=57비트다. 실행 번호·주소·제어 정보는 제외하므로 전체 기계 공간의 정확한 실측값이 아니다.

  2. 다섯 독립 실행 오류의 세 항은 90/1024,15/1024,1/1024로 합 53/512다. 다섯 출력을 복사한 경우에는 이 계산을 적용하지 않는다.

  3. 거절 종료 M의 감싸기는 예약 표지를 쓰지 않으므로 MARK는 NO다. 단순 종료만 보면 YES지만 대상 질문이 다르다.

  4. 잘못된 인코딩은 표지 없이 거절하는 고정 기계 쌍으로 보내 NO를 보존한다. 코드 생성은 M의 결과를 기다리지 않고 끝낸다.

  5. 이 숫자는 지정 배열·독립 확률·코드 감싸기의 손논증이다. 실제 공간/난수/기계/학생 실행은 수행하지 않았다.
