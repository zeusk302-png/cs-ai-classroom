소단원 2.1

schema와 의미

숫자로 저장된 온도 68은 구조 검사를 통과하면 바로 학습에 써도 될까?

준비 개념과 학습 목표

준비 개념

  • schema는 필드 이름·자료형·필수 여부·허용 값 같은 구조 계약이다. 의미 계약은 값이 나타내는 단위·시점·대상·수집 방식까지 정한다. 같은 number 타입도 단위가 다를 수 있다.
  • 섭씨 C와 화씨 F의 변환은 C=(F−32)×5/9다. 68°F는 20°C다. 이 예제의 값은 실제 센서가 아니라 가상 입력이다.
  • NULL 또는 누락은 관측하지 못했거나 제공되지 않은 상태이며 실제 숫자 0과 다르다. 계약 버전은 어떤 필드와 해석 규칙으로 읽었는지 식별한다.

학습 목표

  • 구조 검사와 의미 검사를 구분한다.
  • 버전·단위·결측·허용 범위를 명시한다.
  • 훈련/서비스 변환 일치와 미래 정보 누수를 구별한다.

필드 모양과 해석을 동시에 계약한다

자체 v1 온도 계약은 event_id(비어 있지 않은 문자열), event_time(정수 초), temp_C(유한 실수, −40≤temp_C≤60)를 필수로 정한다. event_time은 정한 기준 시각부터 지난 사건 시간이고 temp_C는 섭씨다. 필수 키, 자료형, 범위 검사만으로 값이 실제 섭씨였는지는 알 수 없다. 측정·변환 경로도 생산자와 소비자가 합의해야 한다.

소비자마다 알아서 단위를 추정하면 같은 68을 누구는 섭씨, 누구는 화씨로 읽는다. 생산자가 단위가 표시된 v2 {temp,unit}를 보내면 unit=C/F만 허용하고 F는 공식으로 변환한 뒤 v1 의미 범위로 검사하는 어댑터를 정한다. 버전 미표시·알 수 없는 단위는 임의 보정하지 않고 격리할 정책을 둔다.

통과와 진실은 다른 성질이다

TFDV 문서는 schema와 통계 기반 오류 검출을 설명하며 추론한 schema를 도메인 지식으로 검토하라고 안내한다. 관측된 값만으로 허용 계약을 자동 승인하면 잘못된 단위가 정상 범위로 학습될 수도 있다. 형식·분포 검사는 “정한 검사에 맞는다”를 보일 뿐 센서 정확도나 레이블 진실을 증명하지 않는다.

자체 정책은 누락 temp를 0으로 채우지 않고 별도 missing 상태로 격리한다. 측정한 0°C는 허용 값으로 남는다. 여러 오류가 있으면 원인 목록을 기록하되 원문 보존은 접근·보존 정책 아래에서만 한다. 누락의 원인에 따라 제외된 집단이 달라질 수 있어 제거한 데이터가 대표 표본이라는 결론도 자동으로 내리지 않는다.

변환 버전과 예측 시점을 고정한다

훈련과 서비스가 같은 의미를 쓰려면 단위 변환, 결측 정책, 범위, 필드 순서·버전을 함께 고정한다. 평균/분산 같은 학습한 변환 값은 훈련 자료에만 fit하고 검증·서비스는 저장된 값을 적용한다. 레이블은 훈련 환경에서 필요하지만 예측 시점에는 없을 수 있으므로 환경별 필수 조건을 구분한다.

같은 schema라도 예측 시각 뒤에 생긴 결과를 입력 특징으로 사용하면 미래 정보 누수가 생긴다. 사건 시각·처리 시각·자료가 실제 이용 가능해진 시각을 구분하고 예측 시각까지 알 수 있었던 특징만 선택한다. 타입 일치나 변환 코드 공유만으로 이 시간 조건이 증명되지 않으며 출처와 버전 이력이 필요하다.

중간 과정을 따라가는 예제

v2 네 카드가 a:{temp:68,unit:F}, b:{temp:20,unit:C}, c:{temp:0,unit:C}, d:{temp:NULL,unit:C}다. ID와 사건시간은 모두 유효하다고 가정한다. 위 변환·범위·missing 정책으로 분류하고 a를 변환 없이 C로 읽었을 때도 비교하라.

  1. a는 F이므로 (68−32)×5/9=36×5/9=20°C로 바꾼다. 범위 [−40,60] 안이므로 허용한다.
  2. b는 이미 C이며 20°C로 허용한다. a와 같은 의미 값이다.
  3. c의 0은 관측된 유효 숫자여서 0°C로 허용한다. d는 NULL로 missing 격리한다.
  4. a를 변환 없이 C로 읽으면 68>60으로 거절된다. 범위가 더 넓어 통과하더라도 단위 해석 오류는 남는다.

허용 a:20/b:20/c:0°C, 격리 d다. 의미를 보존하는 변환과 구조·범위 판단을 순서대로 적용한다.

종이와 본문으로 직접 해보기

v2에 e:{temp:32,unit:F}, f:{temp:20,unit:K}, g:{temp:61,unit:C}를 추가한다. 각 결과와 거절/격리 이유를 적어라. 학습용 평균을 검증 자료까지 포함해 구하는 변형은 schema가 같아도 왜 문제가 되는가?

힌트 보기

허용 단위는 C/F뿐이다. 평균의 fit 입력 범위는 필드 자료형과 다른 계약이다.

풀이 보기

e는 0°C로 허용한다. f는 K가 계약 밖이어서 격리하고 임의 섭씨 추정은 하지 않는다. g는 유효 실수라도 61>60으로 범위 거절이다. 검증 자료를 평균 fit에 쓰면 검증 정보가 변환에 들어가 독립 평가 경계를 깨며 schema 일치로 정당화되지 않는다.

오해와 반례

schema 검사에 통과하면 의미·레이블·예측 시점도 모두 올바르다.

화씨 값을 섭씨 number로 보내거나 예측 이후 결과를 유효 숫자로 넣으면 타입 검사는 통과할 수 있다. 단위·출처·이용 가능 시각·환경별 계약을 따로 확인해야 한다.

서비스에서 레이블이 없으면 항상 schema 오류인가?

답과 이유 보기

훈련과 서비스 환경의 필수 필드가 다를 수 있으므로 해당 환경 계약으로 판단한다.

한 단계 더

어댑터 A가 C 입력을 그대로, F 입력을 (F−32)5/9로 보낸다고 하자. 두 입력 x_C와 x_F가 같은 온도를 나타내는 조건 x_F=9x_C/5+32이면 A(x_F,F)=((9x_C/5+32)−32)5/9=x_C=A(x_C,C)다. 이 대수적 의미 보존은 단위 표기가 진실이며 유한 수와 명시 범위·정확 산술인 모형에 한정한다. 실제 부동소수점 반올림·센서 오차·오표기까지 없다고 증명하지 않는다.

소단원 2.2

batch·stream

늦게 도착한 같은 사건 두 개를 합계에 두 번 넣으면 어떤 값이 바뀔까?

준비 개념과 학습 목표

준비 개념

  • batch는 경계를 정한 자료 묶음을 처리하고 stream은 계속 도착하는 사건열을 처리한다. 유한 자료의 stream 처리나 작은 micro-batch도 가능하므로 실행 크기만으로 둘을 절대 분류하지 않는다.
  • event-time은 사건에 붙은 발생 시각이고 processing-time은 처리한 시각이다. 시각 순서가 같다는 보장은 없다. [0,10)은 사건시간 0 이상 10 미만인 창이다.
  • watermark W는 자료 도착의 완전성을 추정하는 진행 정보다. 그보다 이른 사건이 절대 다시 오지 않는다는 물리적 보장이 아니다. 중복은 같은 고정 ID/내용 사건이 재전달된 것이다.

학습 목표

  • 사건/처리 시간과 창을 추적한다.
  • watermark·늦은 자료·종료 정책을 명시한다.
  • 중복 제거의 ID·내용·보존 범위를 논증한다.

묶음 경계와 무한 입력을 구별한다

batch 입력은 파일 버전·기간·포함 ID 집합을 고정하여 재처리할 수 있는 스냅샷으로 정할 수 있다. stream은 끝이 없을 수 있어 창별 중간 결과와 수정 규칙을 둔다. Stanford의 이전 공개 노트는 두 경로의 다른 특징 변환이 운영 오류를 만들 수 있음을 다룬다. 본문은 최신 도구 추천 대신 같은 의미 계약을 공유하는 자체 모형을 쓴다.

자체 모형의 사건은 (id,t,value)이고 t/value는 정수, id는 재전달해도 동일 내용을 나타내는 고정 식별자다. 같은 ID에 다른 내용이면 충돌 오류로 격리한다. 창은 [0,10),[10,20)처럼 폭 10초이며 사건 t=10은 두 번째 창에만 속한다. 처리 순서로 창을 배정하면 늦은 자료가 다른 기간 합계에 섞인다.

늦은 자료 정책을 명확하게 쓴다

Apache Beam 문서는 watermark가 완전성 추정이며 늦은 자료와 출력 trigger를 구분한다. 자체 정수 모형에서는 W가 감소하지 않고 한 번 닫은 창은 다시 열지 않는다고 정한다. W≥10에 첫 창 잠정 합계를 내고, W<12인 동안 첫 창의 새 사건을 받아 수정 결과를 낸다. W≥12에는 첫 창을 닫고 이후 그 창 사건을 late 격리한다. 이것은 이 예제의 경계 정책이며 Beam의 최대 timestamp 계산을 그대로 구현한 것이 아니다.

중간 결과를 추가(delta)로 낼지 전체 누적값으로 낼지도 정한다. 본문은 창 ID와 결과 버전을 붙인 전체 누적값을 교체한다. 소비자가 새 전체값을 옛 전체값에 더하면 이중 합계가 된다. 마감 이후 버리는 선택은 속도·비용을 낮출 수 있지만 실제 해당 기간 모든 사건의 완전 합계를 보장하지 않는다.

중복 제거에도 상태 수명이 있다

열린 창에서는 seen ID 집합과 합계 S를 함께 원자적으로 갱신한다고 가정한다. 처음 보는 허용 사건만 S에 더하고 ID를 기록한다. 같은 ID/내용은 다시 더하지 않으며 ID 충돌은 격리한다. 이 조건 안에서 순서가 달라도 같은 받아들인 사건 집합이면 정수 합계가 같지만 실제 실패·재시작 때 원자성과 상태 복구는 별도 구현 과제다.

창 종료 뒤 seen 상태를 없애면 오래된 재전달을 다시 셀 수 있으므로 종료한 창의 사건을 계속 거절할 정보 또는 보존 정책이 필요하다. batch 재처리도 출력 교체·중복 방지 경계가 없으면 두 번 적용될 수 있다. “stream이므로 exactly once”라는 보장은 없고 입력 ID, 처리·출력 원자성, 상태 수명과 실패 계약을 함께 정해야 한다.

중간 과정을 따라가는 예제

첫 창 [0,10)에 a=(a,2,5), b=(b,8,7)가 먼저 온다. W=10으로 잠정 출력한 뒤 W=11에서 a의 동일 재전달과 c=(c,9,3)가 온다. W=12 뒤 d=(d,4,4)가 온다. 위 정책으로 출력과 seen을 추적하라.

  1. a/b는 새 ID이고 첫 창에 속하므로 seen={a,b}, S=5+7=12다.
  2. W=10에서 결과(창0,버전1,합계12)를 잠정 출력한다. 창은 아직 W<12이므로 닫히지 않았다.
  3. W=11의 a는 중복이어서 S를 유지한다. c는 새 ID이고 허용 늦은 사건이므로 seen={a,b,c}, S=15, 버전2 전체값 15로 교체한다.
  4. W=12에서 창을 닫는다. 이후 d는 사건시간4라도 late 격리하고 결과15를 바꾸지 않는다. 전체 네 고유 사건의 합19와 정책 결과15는 다르다.

잠정12→수정15, a의 중복 추가 없음, d 격리다. 수집 정책 결과와 실제 기간 모든 사건 합계19를 혼동하지 않는다.

종이와 본문으로 직접 해보기

준비 개념과 학습 목표

준비 개념

  • 품질 규칙은 필수 값·범위·중복·최신성 등을 판정하는 계약이다. 통과율은 통과 수/명시한 입력 수이며 어떤 검사와 기간을 썼는지 함께 적는다.
  • 직접 식별자는 이름처럼 주체를 직접 지칭하는 정보, 준식별자는 지역·연령·시각처럼 다른 정보와 결합해 구분에 이용될 수 있는 값이다. 위험은 가능한 추가 자료와 공격자 지식에 달린다.
  • 가명은 별도 코드로 주체를 대신 나타내는 방식이다. 코드가 달라도 연결표나 속성으로 다시 연관될 수 있다. 여기서는 실제 사람 자료가 아닌 가상 A/B/C/D 카드만 쓴다.

학습 목표

  • 품질 분모와 중복 규칙을 고정한다.
  • 격리·승인·추적 정책과 대표성 한계를 설명한다.
  • 식별자 제거와 재연결 위험의 반례를 만든다.

품질의 분모와 거절 이유를 먼저 정한다

자체 하루 입력 10건에서 schema 실패2건, 중복1건이 있고 두 집합이 겹치지 않는다고 정한다. 첫 도착 고유 유효 사건만 받아들이면 accepted7, 입력 기준 통과율7/10=70%다. schema만 통과한8건을 분모로 삼은7/8=87.5%는 다른 지표다. 기간·집계 단위·중복 정의·오류 우선순위를 명시해야 비교할 수 있다.

격리한 자료를 조용히 지우면 어떤 사용자·장치 집단이 빠졌는지 알기 어렵다. 원인 코드·계약 버전·필요 최소 출처를 기록하고 허용된 담당자가 수정 여부를 승인하는 흐름을 둔다. 품질 통과는 진실·대표성·학습 성능의 보장이 아니며 결측과 거절이 특정 집단에 집중되면 별도 평가가 필요하다.

내용 최소화와 권한은 별도의 보호다

목적에 필요하지 않은 세밀한 위치·자유 텍스트·지속 식별자를 수집하지 않는 선택을 먼저 검토한다. 필요한 자료에도 접근 주체·목적·보존 기간·전송/저장 보호·삭제 경계를 정한다. 이름 제거는 이러한 여러 보호 중 한 변환일 뿐이며 원문·로그·백업·오류 보고에 식별 내용이 남을 수 있다.

NIST 기술 문서는 직접 식별자와 준식별자의 변환, 연결·조합과 위험 평가를 구분한다. 본문은 특정 관할의 법률이나 법적 익명화 기준을 판정하지 않고 작은 교육 모형의 정보 연결 가능성만 설명한다. 실제 자료 공개 승인이나 재식별 시험 없이 숫자로 개인정보 안전성을 인증하지 않는다.

작은 카드로 연결 반례를 증명한다

가상 카드 A=(지역R,나이11,값2), B=(R,12,값 8), C=(S,11,값5), D=(S,12,값9)에서 이름만 제거해도 (R,12)는 B만 가리킨다. 공격자가 B의 지역과 나이를 알고 있고 대응 자료가 정확하다는 가정이면 값 8을 연결할 수 있다. 각 속성이 혼자 두 후보를 남겨도 두 속성의 교집합은 하나가 될 수 있다.

나이를 [10,19]로 일반화하면 지역R의 A/B가 같은 준식별자 그룹에 들어가 후보가 둘이 된다. 그러나 공격자가 값이나 다른 시각·연결표를 알고 있으면 여전히 구분할 수 있고 후보 수2가 형식적 프라이버시나 법적 적합성을 보장하지 않는다. 추가 공개의 차이·집단 내 민감값 분포·자료 밖 모집단도 함께 고려해야 한다.

중간 과정을 따라가는 예제

위 네 가상 카드의 이름을 지웠다. 공격자는 대상이 지역R,나이12이며 표에 포함됨을 안다고 가정한다. 후보 집합과 연결 값, 나이 일반화 후 후보 수를 구하고 이것이 실제 익명화 인증인지 설명하라.

  1. 지역R 조건 후보는 {A,B}, 나이12 조건 후보는 {B,D}다.
  2. 교집합 {A,B}∩{B,D}={B}이므로 두 조건을 함께 쓰면 후보 한 개다.
  3. B의 값 8을 연결한다. 나이를 [10,19]로 바꾸면 지역R 그룹 후보는 {A,B} 두 개다.
  4. 그룹 두 개는 이 가상 추가 지식만 제한했을 때의 모호성이다. 다른 연결 자료·값 지식·공개 조합이나 실제 관할 정책의 안전성을 인증하지 않는다.

원표 후보 1/값 8, 일반화 표 후보 2다. 식별자 제거만으로 재연결이 불가능하다는 주장은 반례로 거절한다.

오해와 반례

이름 삭제 또는 후보 두 개이면 데이터는 완전히 익명이고 품질도 안전하다.

지역·나이의 교집합으로 B가 한 명으로 좁혀지는 반례가 있고, 후보 둘의 값이 같으면 민감값도 추론된다. 품질 통과율과 프라이버시 위험은 서로 다른 계약이며 수집 목적·권한·보존과 공개 환경을 따로 평가해야 한다.

한 단계 더

공개 자료에서 추가 지식 조건 Q에 맞는 후보 집합 E_Q를 정의한다. |E_Q|=1이면 이 모형에서 행이 유일하게 선택되고, |E_Q|>1이어도 모든 e∈E_Q의 민감값 v(e)=c이면 값 c를 추론할 수 있다. 따라서 후보 수 하한만으로 값 추론을 막는 충분조건은 되지 않는다. 품질 검사 집합 F/D의 거절 수는 |F∪D|=|F|+|D|−|F∩D|이므로 오류 중복을 따로 기록해야 통과 분모를 일관되게 계산할 수 있다. 둘은 자체 유한 집합 증명이며 실제 공격이나 법적 판정이 아니다.
