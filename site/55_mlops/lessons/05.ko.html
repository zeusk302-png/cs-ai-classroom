소단원 5.1

파라미터·지표·로그

정확도 .92만 남겨 두면 어떤 자료와 설정으로 그 숫자가 나왔는지 다시 알 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 파라미터는 학습률처럼 실행에 준 설정, 지표는 정확도처럼 측정해 기록하는 값이다.

  • run은 한 실행의 식별 단위, artifact는 모델·그림 같은 결과 파일이다. 로그는 사건과 맥락을 남기는 기록이다.

학습 목표

  • 실행 ID로 설정·자료·평가·결과를 연결한다.

  • 동일 조건의 지표만 비교하고 미실행 기록을 구분한다.

같은 run의 지표도 집계 분모에 따라 순위가 달라지는가?

새 평가 장부는 서로 겹치지 않는 작은 집합 S의 두 항목과 큰 집합 L의 여덟 항목으로 구성한다. A는 S에서 두 개, L에서 네 개를 맞혔고 B는 S에서 한 개, L에서 여섯 개를 맞혔다. 자료 전체 정확도는 맞은 수를 모두 더해 전체 열 개로 나눈다. 집합 동일 비중 평균은 S와 L의 정확도를 각각 절반씩 반영한다. 이는 두 가지 명시적 평가 목표이며 MLflow가 자동으로 어느 쪽을 정한다는 뜻이 아니다.

A의 집합별 정확도는 1과 1/2여서 동일 비중 평균은 3/4다. B는 1/2와 3/4여서 평균은 5/8이다. 이 목표에서는 A가 앞선다. 전체 항목 목표에서는 A가 6/10, B가 7/10으로 B가 앞선다. 이름 accuracy 하나와 최종 값만 저장하면 이 차이를 복원할 수 없다.

별도 자료 D1의 checkpoint 장부에서 한 run R의 step 1은 validation loss 0.4, step 2는 0.2, step 3은 0.3이며 모델 식별자는 각각 M1,M2,M3다. 최소 지표는 M2에 연결되고 마지막 모델은 M3다. M3 파일에 최소 loss 0.2를 붙이면 실제 존재하지 않은 결과 짝이 된다. 값이 낮다는 이유만으로 생성 시점이나 모델 ID를 바꾸지 않는다.

다른 자료 판본 D2에서 M2의 loss가 0.1이어도 D1에 대한 0.2와 같은 비교 축이 아니다. 기록에는 run, 모델, 자료, step, 단위와 집계 목표를 함께 둔다. 새 수치는 종이 표이며 학습·평가·MLflow API를 실행하지 않았다.

먼저 확인할 개념
  • 지표의 이름·단위·분모

    같은 값 비교의 조건과 다른 집합을 분리한다.

  • 등록 모델과 생성 run

    checkpoint 식별자를 등록 버전의 계보로 연결한다.

숫자에 출처를 붙인다

한 실험 run에는 파라미터와 지표뿐 아니라 코드 버전, 데이터 버전, 평가 분할, 난수 seed, 환경 정보를 연결한다. seed는 무작위 선택의 시작값이며 같은 seed 하나만으로 모든 장치에서 완전 재현된다고 보장하지 않는다. 정확도 .92가 훈련 자료인지 검증 자료인지도 별도 필드다.

지표의 이름·단위·분모를 함께 적는다. latency=12만 적으면 밀리초인지 초인지, 평균인지 95백분위인지 알 수 없다. 학습 중 loss는 step 또는 epoch와 함께 시계열로 남겨 마지막 값과 최소값을 혼동하지 않는다.

실험을 묶되 실행은 분리한다

experiment는 같은 과제의 여러 run을 모으는 이름이다. 두 설정을 시험했다면 서로 다른 run ID로 남겨 좋은 지표만 한 실행에 섞지 않는다. 모델 파일도 어느 run에서 생성되었는지 연결해야 지표와 결과물의 짝을 다시 찾는다.

실패한 실행은 실패 시점과 오류를 남기고 완성 모델의 평가값으로 표시하지 않는다. 교육용 가상 기록은 paper_example 같은 표식으로 실제 train.py 실행 기록과 구분한다. 기록 파일이 존재한다는 사실은 실제 실행이나 성능 검증을 뜻하지 않는다.

비교의 분모와 조건을 맞춘다

모형 표의 A와 B가 같은 검증 집합 100개를 평가했다면 맞은 수 90과 92로 정확도 .90과 .92를 계산한다. 다른 집합 10개에서 맞은 10개는 정확도 1이어도 같은 어려움과 표본 규모가 아니다. 수치만 정렬하기 전 자료의 ID와 평가 규칙을 확인한다.

반복 실행 평균은 각 표본의 값과 집계 방법을 보존해야 의미가 있다. 여러 seed의 차이와 평가 자료의 불확실성은 다른 분석이다. 추적 도구가 그래프를 그렸다고 목표가 공정하거나 배포가 승인되었다는 뜻은 아니다.

중간 과정을 따라가는 예제

자체 기록 A:학습률 .01,평가 집합 D1 100개 중 90정답, B:.02/D1/92정답, C:.02/D2 10개 중 10정답이다. 정확도와 같은 집합 비교를 하라.

  1. A=90/100=.90, B=92/100=.92다. D1이라는 같은 분모를 확인했다.

  2. C=10/10=1이지만 D2이며 표본 수도 다르다. A/B보다 우수하다고 이 표만으로 단정하지 않는다.

  3. B−A는 .02, 즉 2퍼센트포인트다. 상대 증가율은 .02/.90≈2.22%로 다른 값이다.

  4. 각 설정·지표·데이터를 별도 run A/B/C에 연결한다. 이 표는 실제 모델 학습 기록이 아니다.

같은 D1에서 B가 A보다 2퍼센트포인트 높다. C는 조건을 맞춰 재평가해야 한다.

조건을 바꾸어 비교하기

같은 관측의 다른 집계 목표

A/B의 전체 항목 정확도와 집합 동일 비중 평균을 각각 구하고 순위를 비교하라.

  1. A의 전체 정확도는 (2+4)/(2+8)=3/5다. B는 (1+6)/10=7/10이다.

  2. A의 집합 평균은 (1+1/2)/2=3/4다. B는 (1/2+3/4)/2=5/8이다.

  3. 전체 항목에서는 B, 집합 동일 비중에서는 A가 앞선다.

목표와 분모를 명시한 두 지표를 별도로 저장한다.

비교할 점

동일 관측을 사용해도 목표의 가중치가 다르면 순위가 달라진다.

가장 좋은 값과 마지막 파일

run R에서 최소 loss와 마지막 checkpoint의 올바른 모델·자료·step 짝을 적어라.

  1. D1의 최소 loss 0.2는 step 2의 M2에 연결한다.

  2. D1의 마지막 loss 0.3은 step 3의 M3에 연결한다.

  3. D2의 M2 loss 0.1은 자료 판본이 다른 별도 기록이다.

최소는 (R,M2,D1,2,0.2), 마지막은 (R,M3,D1,3,0.3)이다.

비교할 점

모든 좋은 수치를 한 모델의 성능으로 모으면 평가하지 않은 짝이 생긴다.

종이와 본문으로 직접 해보기

한 run의 loss가 step1:.8, step2:.5, step3:.6이다. 최소값과 마지막값을 나누어 적어라.

힌트 보기

시간 위치와 값의 크기를 따로 본다.

풀이 보기

최소 .5는 step2, 마지막 .6은 step3이다. 모델 파일이 어느 checkpoint인지도 연결해야 최소 loss와 마지막 파일을 자동 같은 결과라고 하지 않는다.

오해와 반례

가장 큰 정확도와 가장 작은 loss를 어디서든 모아 한 run의 결과라고 쓰면 된다.

A/B/C의 자료·설정이 달라 그런 결합은 존재하지 않은 실험을 만든다. step2 최소 loss와 step3 파일도 구별한다.

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

S의 같은 두 항목을 새 독립 관측이라고 주장하지 않고 세 번 복사한 자료 장부와 L 한 번을 행별 집계한다. A/B 정확도와 실제 고유 항목 수를 구하라.

힌트 1

S의 행 수와 정답 수는 세 배다.

힌트 2

고유 ID 수는 복사로 증가하지 않는다.

풀이와 답 확인

  1. 전체 행 수는 6+8=14개다. A의 정답 행은 6+4=10개, B는 3+6=9개다.

  2. 행별 정확도는 A 5/7, B 9/14다. 원래 고유 항목은 열 개다.

복사 행 목표에서는 A가 앞서지만 새 독립 열네 관측으로 보고하지 않는다.

흔한 오답에서 다시 생각하기

복사했으므로 표본 수가 독립 열네 개다.

고유 항목은 열 개이며 바뀐 것은 행 가중치다.

연습 2 · 오류 찾아 고치기

M3 파일의 결과표에 D1 최소 loss 0.2와 D2 loss 0.1을 두 검증 반복의 평균 0.15로 적었다. 어떤 연결과 집계 오류인가?

힌트 1

M3의 D1 값은 0.3이다.

힌트 2

D2의 기록은 M2이고 자료도 다르다.

풀이와 답 확인

  1. 0.2는 M2/D1, 0.1은 M2/D2이므로 M3의 두 반복 값이 아니다.

  2. 두 값의 산술 평균 0.15를 구할 수는 있지만 동일 모델·동일 평가 목표의 반복 평균이라는 의미는 성립하지 않는다.

모델 ID·자료 ID·step을 복원하고 현재 표로는 M3 반복 평균을 보고하지 않는다.

흔한 오답에서 다시 생각하기

숫자를 평균할 수 있으므로 평가 목표도 같다.

산술 연산 가능성과 기록 의미의 동일성은 다르다.

연습 3 · 직접 만들어 보기

S의 목표 비중을 λ, L을 1−λ로 정한다. 0≤λ≤1에서 A/B가 동률인 λ와 앞서는 구간을 구하라.

힌트 1

A는 λ+(1−λ)/2다.

힌트 2

B는 λ/2+3(1−λ)/4다.

풀이와 답 확인

  1. A의 목표 정확도는 1/2+λ/2다. B는 3/4−λ/4다.

  2. 차이는 3λ/4−1/4이므로 λ=1/3에서 동률이다.

  3. λ>1/3이면 A, λ<1/3이면 B가 앞선다.

비중을 사전에 정하고 λ=1/3의 등호를 별도 기록한다.

흔한 오답에서 다시 생각하기

전체 항목 가중치 λ=1/5에서 A가 앞선다.

1/5<1/3이므로 그 목표에서는 B가 앞선다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

M2와 M3의 마지막 평가가 둘 다 0.3이라는 별도 조건만 주어졌다. 결과 바이트가 같고 두 checkpoint가 같다고 결론 낼 수 있는가?

힌트 1

한 지표는 전체 함수나 파일을 식별하지 않는다.

힌트 2

ID와 내용 확인은 별도다.

풀이와 답 확인

  1. 같은 최종 지표는 값의 일치만 보여 준다.

  2. 모델 ID와 저장 내용 및 생성 step은 별도 비교가 필요하다.

같은 지표만으로 모델·바이트·과거 이력의 동일성을 인증하지 않는다.

흔한 오답에서 다시 생각하기

지표가 같으면 두 파일의 내용도 같다.

다른 예측의 오류가 같은 개수일 수 있다.

model registry

최신 모델 파일이라는 이름이 바뀌었을 때 어제 서비스한 정확한 모델을 다시 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • registry는 모델 이름 아래 버전과 출처·설명을 관리하는 저장소다.

  • lineage는 결과가 어떤 run·자료·코드에서 왔는지 연결한 계보, alias는 특정 버전을 가리키는 바꿀 수 있는 별명이다.

학습 목표

  • 모델 이름·버전·별명·실행 출처를 구별한다.

  • 서비스와 rollback에서 실제 사용 버전을 기록한다.

한 요청이 별명을 두 번 읽으면 같은 버전이라고 보장되는가?

새 종이 registry에서 Study 버전 1은 모델 M1과 전처리 P1의 묶음 H1, 버전 2는 M2와 P2의 묶음 H2다. H1/H2는 내용 식별 기호이며 실제 hash 계산이 아니다. version 번호는 등록 순서이고, champion은 현재 한 버전을 가리키는 mutable alias다. 모든 등록 내용은 이 모형에서 삭제하거나 바꾸지 않는다고 정한다.

요청 Q는 시각 1에 champion을 해석해 버전 1의 전처리 P1을 읽는다. 시각 2에 alias를 버전 2로 바꾼다. Q가 시각 3에 alias를 다시 해석해 모델 M2를 읽으면 P1/M2라는 혼합 묶음이다. 각 조회가 올바른 현재 alias를 반환해도 요청 전체가 한 버전을 사용했다는 결론은 없다.

호환성 모형을 P1(x)=x, M1(z)=z, P2(x)=2x, M2(z)=z/2로 정한다. 완전한 두 묶음은 모두 x를 출력한다. x=4일 때 P1/M2는 2, P2/M1은 8을 출력한다. 두 완전 묶음의 결과가 같은 점에서 두 부분을 아무렇게나 교환할 수 있다는 뜻은 아니다.

대안 정책은 요청 시작에 alias를 한 번만 해석하고 그 resolved version의 manifest에서 모든 부분을 읽는 것이다. 이미 로드한 서버는 다음 로드 사건 전까지 이전 묶음을 유지한다고 정한다. 실제 서버가 이 정책을 구현했는지나 배포 성공 여부는 관측하지 않았다.

먼저 확인할 개념
  • alias와 실제 로드 사건

    현재 조회와 과거 서버 상태를 분리한다.

  • 모델·자료·지표 연결

    계보 ID만으로 성능 성공을 확대하지 않는다.

등록과 학습은 다른 사건이다

모델을 학습해 로그에 남기는 일과 그 결과를 registry의 이름 아래 새 버전으로 등록하는 일은 다르다. 등록 항목에는 결과물 위치와 생성 run을 연결한다. 버전 번호 3이 버전 2보다 성능이 좋다는 뜻은 아니며 단지 등록 순서를 나타낼 수 있다.

실제 재현에는 모델 가중치 외 전처리·입출력 규격·의존 환경도 필요하다. 파일 이름만 같거나 버전 숫자만 같다는 이유로 결과 바이트와 평가 조건이 같다고 결론 내리지 않는다. 별도 hash로 결과물을 확인할 수 있지만 hash 역시 학습 성능의 증거는 아니다.

버전 참조와 별명 참조

MLflow의 models:/Study/2는 특정 등록 버전, models:/Study@champion은 그 별명이 현재 가리키는 버전이다. champion을 2에서 3으로 바꾸면 이름은 같아도 다음에 별명을 해석한 대상이 달라질 수 있다. 이것이 mutable reference의 뜻이다.

실행 당시 별명을 어떤 버전과 결과물로 해석했는지 남겨야 과거를 복원할 수 있다. 이미 메모리에 모델을 로드한 서버가 별명 변경만으로 즉시 새 모델을 받는다고 가정하지 않는다. 로드·캐시·재시작과 배포 방식은 별도 정책이다.

분류 표식은 승인 증거와 연결한다

버전에 validation_status:approved 같은 tag를 붙일 수 있지만 문자열 하나가 독립 평가와 승인 과정을 자동 증명하지는 않는다. 누가 어떤 결과물과 기준을 확인했는지 증거 ID를 연결한다. OSS와 관리형 환경의 권한·governance 기능도 같은 것으로 단정하지 않는다.

rollback은 이전에 확인한 버전으로 참조나 배포를 되돌리는 선택이다. 그 버전이 현재 입력 규격·자료와 호환되는지 검토해야 한다. registry 기록과 실제 서버의 수신/추론 결과를 별도 확인하는 이유다.

소단원 5.3

승격조건과 승인기록

정확도가 조금 높아졌지만 응답시간이 길어졌다면 새 모델로 바꿀 조건을 누가 어떻게 남겨야 할까?

준비 개념과 학습 목표

준비 개념

  • 승격은 후보 모델을 정한 다음 사용 단계로 옮기는 결정이다. 배포 실행과 구별한다.

  • 승인 기록은 대상 버전·증거·기준·검토자·결정 시각·이유를 연결한다. 미확인은 통과와 다르다.

학습 목표

  • 여러 수치와 증거 조건을 모두 검사한다.

  • 승인 대상 변경 시 이전 승인의 효력을 재검토한다.

반올림된 경계 지표와 과거 승인은 현재 후보를 승인하는가?

새 자체 정책은 원래 정확도 a≥0.92와 원래 p95 지연 ℓ≤50 ms, 규격 PASS 및 독립 검토 완료를 모두 요구한다. 화면은 a를 소수 둘째 자리로 반올림하고, ℓ을 정수 ms로 반올림한다. 양수의 정확한 중간값은 위쪽으로 반올림한다고 별도로 정한다. 따라서 표시 0.92는 원값 구간 [0.915,0.925), 표시 50 ms는 [49.5,50.5) ms를 나타낸다.

두 표시만으로 전체 AND 조건이 통과한다고 확정할 수 없다. a=0.915와 ℓ=50.4 ms도 같은 표시지만 둘 다 원래 경계를 실패한다. a=0.924와 ℓ=49.6 ms도 같은 표시이며 수치 조건은 통과한다. 필요한 것은 원값 또는 판정에 충분한 확실한 범위다. 모든 표시 조합의 끝점 포함 여부는 지정 반올림 규칙에서 결정한다.

별도 후보 장부에서 원값을 소수 셋째 자리로 표시하면 정확도 0.921의 원값 구간은 [0.9205,0.9215)여서 정확도 조건을 인증한다. 정수 지연 표시 49의 원값은 [48.5,49.5) ms이므로 지연 조건을 인증한다. 규격과 검토가 모두 확인됐다는 추가 전제까지 있어야 전체 통과다. 좋은 표시가 누락 증거를 대체하지 않는다.

승인 E는 모델 H2, 전처리 P2, 환경 EnvA, 자료 D1, 규격 S1, 정책 C1의 묶음에 귀속된다고 이 모형에서 정한다. 내용 H2가 그대로여도 EnvB로 바꾸면 E의 전체 대상과 다르다. 이는 여기서 명시한 엄격 재검토 정책이며 registry tag나 MLflow API가 자동으로 강제한다고 주장하지 않는다. 승인 후 alias를 이동하는 중에 다른 후보가 바뀌는 경우도 실제 해석 대상과 E의 묶음을 다시 대조한다.

조건은 비교 전에 정한다

자체 정책은 같은 D1의 정확도≥.92, p95 응답시간≤50ms, 입력 규격 검사 PASS, 독립 검토 완료를 모두 만족해야 승격 후보가 된다고 정한다. p95는 정한 측정 집합에서 95백분위 지연이며 평균과 다르다. 여기서는 숫자가 주어진 종이 표다.

조건의 AND는 하나라도 실패 또는 미확인이면 자동 통과시키지 않는다는 뜻이다. 지표가 반올림된 표시값이라면 경계 판정에는 원값과 반올림 규칙을 확인한다. 예제에서는 표시 소수를 정확한 입력값으로 정한다.

결정은 특정 결과물에 귀속된다

승인자는 기준 버전과 모델 버전/hash, 평가 데이터·코드의 ID, 검토 결과, 결정 이유를 묶는다. 평가 뒤 파일이 바뀌면 같은 파일명이어도 과거 증거가 현재 바이트를 검토했다고 보장하지 못한다. 변경된 대상은 새 평가/검토가 필요할 수 있다.

tag를 approved로 적거나 registry에 등록하는 API 자체가 이 자체 정책을 강제한다고 주장하지 않는다. 실제 권한 제어·감사·승인 절차는 사용 환경별로 구현하고 확인해야 한다. 개인이 자기 지표를 적는 것과 독립 검토를 수행한 것은 구별한다.

승인과 배포후 확인을 분리한다

기준 통과와 승인 기록완료는 배포해도 되는지 판단할 근거다. 실제 배포 성공·서버 버전 확인·장애 없는 실행은 이후 다른 증거다. 실패 시 되돌릴 버전과 입력 호환성·중지 조건도 함께 정한다.

실제로 측정하지 않은 p95나 실행하지 않은 규격 검사를 PASS로 만들지 않는다. 미수행/실패/통과의 구별을 남기면 다음 담당자가 필요한 작업을 알 수 있다. 이 단원은 가상 결정표이며 프로젝트의 실제 배포 승인이나 측정 로그가 아니다.

  2. B는 .92≥.92/45≤50이며 두 증거 조건도 통과라 기준상 승격 후보다.

  3. C의 좋은 두 수치가 미수행 규격 검사를 대신하지 않는다. 아직 통과 아님으로 남긴다.

  4. B도 대상 버전/hash와 승인자/기준/시각/이유를 기록하고 실제 배포 성공은 별도 확인한다.

기준상 후보는 B뿐이다. A실패/C미확인과 B의 실제 배포 미수행을 구별한다.

각 부분은 독립 종이 모형이다. ① A/B의 S와 L 평가 장부에서 S 목표 비중 λ=1/4일 때 두 정확도를 비교하고, S 세 번 복사의 행별 목표와 고유 항목 수를 구별한다. ② 입력 x=6에서 alias 두 번 조회로 P1/M2를 섞은 출력과 버전 2 manifest의 완전 출력을 비교한다. 서버는 시각 0에 버전 1, 시각 5에만 다시 로드하며 alias는 시각 2에 2로 바뀐 뒤 유지된다. 시각 3과 6의 서버 버전을 구한다. ③ 세 자리 정확도 표시 0.920과 정수 지연 표시 49 ms를 원값 구간으로 판정한다. H2/P2는 같고 EnvB로 변경했을 때 EnvA의 승인 E와 전체 대상 일치 여부도 보고한다.

풀이와 답 확인

  1. λ=1/4에서 A는 1/2+1/8=5/8이다. B는 3/4−1/16=11/16이므로 B가 1/16만큼 높다. S 세 번 복사의 행별 정확도는 A 5/7, B 9/14로 A가 앞서며 고유 항목은 열 개다.

  2. 혼합 M2(P1(6))는 3이고 완전 버전 2의 M2(P2(6))는 6이다. 시각 3의 서버는 기존 로드 버전 1, 시각 5 재로드 뒤 시각 6에는 버전 2다.

  3. 정확도 원값은 [0.9195,0.9205)여서 수치 통과 미확정이다. 지연 원값은 [48.5,49.5) ms여서 지연 조건은 통과한다.

  4. EnvB는 승인 E의 EnvA와 다르므로 전체 대상은 일치하지 않는다. 좋은 수치나 같은 tag로 환경에 대한 미수행 검토를 대신하지 않는다.

λ 목표에서는 B, 복사 행 목표에서는 A가 앞선다. 혼합 출력 3과 완전 출력 6, 서버의 버전 1/2를 시점별 구별한다. 정확도는 원값 경계 미확정이고 지연은 통과하나 환경 변경으로 전체 승인 대상은 불일치다.
