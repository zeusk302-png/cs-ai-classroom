소단원 6.1

baseline과 slice 평가

전체 정답률이 올랐는데 특정 학생에게는 더 많이 틀리면 새 모델을 통과시켜도 될까?

준비 개념과 학습 목표

준비 개념

  • 정확도는 평가 대상 중 맞힌 수를 전체 수로 나눈 값이다.
  • slice 는 관심 조건으로 고른 부분집합이며 서로 겹칠 수도 있다.

학습 목표

  • 같은 평가 자료에서 baseline 과 후보를 비교한다.
  • 전체 지표와 중요 부분집합의 회귀를 함께 계산한다.

비교의 출발선

baseline 은 개선 여부를 판단할 기준이다. 직전 운영 모델, 항상 다수 클래스를 고르는 규칙, 간단한 선형 모델처럼 목적에 맞게 정한다. 복잡한 모델이라는 이유만으로 간단한 규칙보다 낫다고 할 수 없으므로 같은 평가 자료와 지표를 적용한다.

비교 시 라벨·예측 시점·전처리·임계값 정책을 고정하고 모델 버전을 기록한다. 정확도 차이가 작아도 시간이나 메모리 비용이 커질 수 있다. 이 단원은 정답률 표만 종이로 분석하며 운영 성공이나 실제 학습 결과를 주장하지 않는다.

전체에서 가려지는 부분집합

중요 slice 는 언어, 입력 길이, 촬영 조건 등 목표에 관련된 조건으로 미리 정한다. 전체 정확도가 다수 집단의 개선에 크게 좌우되면 소수 집단의 악화가 가려질 수 있다. slice 별 표본 수와 정답 수를 함께 보여 분모가 다른 퍼센트를 비교한다.

두 slice 가 겹치면 정답 수를 합쳐 전체 정답 수로 삼을 수 없다. 아래 A/B 는 겹치지 않고 전체를 나누는 특별한 경우다. 미리 중요하다고 정한 집단을 통과 기준에 넣되 평가 후 나쁜 집단을 숨기거나 여러 탐색 중 좋은 결과만 선택하지 않는다.

차이와 불확실성을 읽는다

평가 회귀는 기존보다 품질이 악화되는 변화다. 전체 최소 기준과 slice 별 최소 기준, 허용 변화량을 정할 수 있다. 여러 조건 중 하나라도 실패하면 왜 실패했는지 먼저 분석하며 전체 평균 하나로 다른 실패를 덮지 않는다.

90%와 92%의 차이는 2 퍼센트포인트다. 상대 증가율은 2/90 이므로 약 2.22%로 다른 양이다. 한정된 표본의 값은 모집단 성능의 정확한 증명이 아니며 특히 적은 slice 의 한 건 차이는 크게 보인다. 실제 신뢰 구간 추정은 별도 자료/가정이 필요하다.

중간 과정을 따라가는 예제

같은 100 건을 A 80 건/B 20 건으로 나눈다. baseline 정답은 A72/B16, 후보는 A76/B14 다. 전체 개선, 각 slice 변화, 통과 여부를 구하라. 규칙은 전체≥90%, B≥75%이고 두 조건 모두 필요하다.

  1. baseline 전체(72+16)/100=.88 이다.
  2. 후보 전체(76+14)/100=.90 으로 +2 퍼센트포인트다.
  3. A 는 90%→95%로 +5 퍼센트포인트, B 는 80%→70%로 −10 퍼센트포인트다.
  4. 후보의 전체 조건은 통과하지만 B70%<75%로 탈락이다.

전체가 개선되어도 중요 B 조건 때문에 후보는 통과하지 못한다.

종이와 본문으로 직접 해보기

후보의 B 정답을 15 개로 고치면 전체와 B 조건은? B 의 한 건이 몇 퍼센트포인트인가?

힌트 보기

분모 20 과 전체 100 을 각각 사용한다.

풀이 보기

전체 91/100=91%, B15/20=75%로 둘 다 통과한다. B 한 건은 1/20=5 퍼센트포인트이고 전체 한 건은 1 퍼센트포인트다.

오해와 반례

전체 정확도가 오르면 모든 slice 도 좋아졌다.

현재 예에서 전체+2 지만 B−10 퍼센트포인트다. 전체의 가중합과 부분집합의 변화는 같은 방향일 필요가 없다.

겹치는 slice 의 건수를 합치면 전체인가?

답과 이유 보기

한 단계 더

동일 100 건에서 baseline 만 맞힌 5 건, 후보만 맞힌 7 건이면 순개선 2 건이다. 둘 다 맞힌 83 건/둘 다 틀린 5 건까지 더하면 100 이다. 정확도가 같아도 어떤 사례가 바뀌었는지 paired 오류표가 더 보여 주는 정보를 설명한다.

소단원 6.2

데이터·모델 테스트

숫자 타입과 범위가 맞으면 모델이 문제를 올바르게 푼다고 할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • schema 는 자료의 타입·필수 여부·허용 범위를 표현하는 약속이다.
  • 단위 테스트는 작은 동작, 통합 테스트는 연결된 경로를 확인한다.

학습 목표

  • 자료 검사와 모델 동작 검사의 책임을 구별한다.
  • 스키마 위반과 예측 정답률을 독립 계산한다.

자료 약속을 검사한다

입력 자료에는 이름·타입·범위·결측률·고유성 등의 약속이 있다. 나이가 숫자인지, 필수 값이 빠졌는지, 라벨이 예상 클래스에 속하는지 검사하면 의미 있는 오류를 학습 전에 발견할 수 있다. 자동 schema 추론은 관측 자료의 기본 특성을 추정할 뿐 업무의 올바른 규칙을 모두 알지는 못한다.

학습에는 정답 라벨이 필요해도 실제 예측 입력에는 없어야 할 수 있다. 환경별 schema 로 이 차이를 명시한다. 단순히 같은 열 수를 강요하면 정상적인 serving 입력을 잘못 거절하거나 정답 누출 열을 그대로 허용하는 실수를 한다.

모델의 작은 동작도 확인한다

모델 테스트에는 입력 모양/출력 모양, 유한한 값, 범위·확률합 같은 API 약속 검사가 있다. 이와 별도로 알고리즘이 의미에 맞는 답을 내는지 작은 정답 사례를 검사한다. 출력이 [0,1] 안이라는 사실만으로 분류 정답을 증명하지 못한다.

예를 들어 확률 두 개의 합은 허용 오차 안에서 1 이어야 한다. 같은 입력에 항상 .5/.5 를 반환하는 모델도 이 검사는 통과하지만 유용한 구분은 못 한다. dtype·shape·NaN 검사, 학습/전처리 연결 확인, 품질 평가가 각각 필요한 이유다.

검사 결과를 버전과 묶는다

회귀검사에서는 데이터 버전·schema·모델·변환 코드·평가 설정을 함께 남긴다. seed 를 기록해도 병렬 실행이나 라이브러리 차이로 완전히 동일한 학습이 보장되는 것은 아니다. 가능한 재현 범위와 허용 차이를 구체적으로 정의한다.

통과 기준은 오류 유형에 맞게 정한다. 필수 열이 없으면 즉시 중단할 수 있지만 새 범주나 분포 이동은 조사 대상으로 분류할 수 있다. 검사 목록을 갖춘 것과 실제 검사를 실행해 통과한 것은 다르므로 이 종이 활동은 도구 실행 증거가 아니다.

중간 과정을 따라가는 예제

schema 는 age 가 필수 숫자이며 0≤age≤120, label∈{0,1}이다. 행 a=(20,1), b=(빈 값,0), c=(130,1), d=("old",0), e=(40,2)를 검사하라. 빈 값/범위/타입/라벨 오류를 각각 센다.

  1. a 는 두 값 모두 조건을 만족한다.
  2. b 는 필수 age 결측 1 건이다.
  3. c 는 age 범위 위반 1 건, d 는 숫자 타입 위반 1 건이다.
  4. e 는 허용 label 밖 1 건이다.

정상 1 행, 위반 4 행이며 네 오류 종류는 각각 1 건이다.

종이와 본문으로 직접 해보기

같은 출력 확률 [ .2,.8 ],[ .4,.4 ],[ NaN,.5 ] 중 유한값·[0,1]·합 1(오차 10⁻⁶) 검사를 통과하는 것은? 합 검사는 유한값 확인 뒤 수행한다.

힌트 보기

각 수를 먼저 검사하고 두 수를 더한다.

풀이 보기

첫 출력만 통과한다. 두 번째는 합.8 로 실패, 세 번째는 유한값 검사에서 실패다. 첫 출력이 실제 정답에 맞는지는 라벨과 결정규칙이 따로 필요하다.

오해와 반례

schema 를 통과한 자료면 누출도 없고 예측도 정확하다.

label 을 복사한 정답 누출 feature 가 숫자/범위 검사를 통과할 수 있다. 정상 나이 20 의 사례도 잘못 예측할 수 있어 의미/시점 검사와 품질 평가가 따로 필요하다.

두 클래스 전체 합 1 조건을 어긴다.

자동 schema 면 사용자 검토가 불필요한가?

답과 이유 보기

관측된 오류를 규칙으로 배울 수도 있고 업무 조건은 자동으로 알 수 없다.

한 단계 더

평가 4 건의 정답[0,1,1,0], 예측[0,1,0,0]은 3/4=75%다. 모든 출력 타입이 정상이더라도 1 건 틀린다는 점을 보여 자료/API/품질 결과표를 따로 그린다.

소단원 6.3

누수와 비교가능성

미래 시험 문제를 보고 평균을 정한 뒤 평가하면 공정한 비교일까?

준비 개념과 학습 목표

준비 개념

  • 학습 자료는 모델/전처리를 맞추는 자료이며 평가 자료는 그 밖의 자료다.
  • 날짜와 사용자 ID 는 같은 출처와 미래 정보를 판단하는 단서다.

학습 목표

  • 전처리·출처·시간 누출을 구분한다.
  • 고정 평가셋과 바뀐 평가셋의 비교 한계를 설명한다.

전처리에도 학습이 있다

평균·표준편차·단어 사전·feature 선택은 데이터에서 정보를 학습하는 과정이다. train/test 를 나눈 뒤 train 에서 이 값을 구하고 test 에는 같은 변환을 적용한다. test 를 포함해 평균을 맞추면 시험 자료가 학습 결정에 관여한다.

pipeline 은 교차검증에서 fold 별 전처리 fit 을 올바르게 묶는 데 도움을 준다. 그러나 동일 사용자가 양쪽에 섞였는지, 결과 뒤에 생성된 feature 를 사용했는지까지 모든 업무 의미를 자동 판단하지는 않는다. 그룹과 시간 기준은 자료 수집/예측 목적에 맞게 설계한다.

예측 당시 존재한 정보만 쓴다

시간 누출은 예측 당시 없던 정보를 사용하면서 좋은 결과를 얻는 상황이다. 오늘의 지출 예측에 내일 확정된 월말 합계를 넣으면 미래를 본 셈이다. 값이 실제 자료에 존재해도 예측 시점에 이용 가능한지 별도 검사가 필요하다.

같은 사용자의 비슷한 기록이 train/test 에 섞이면 새로운 사용자 성능을 알고 싶을 때 과도하게 낙관적일 수 있다. 목적이 기존 사용자의 미래 기록이면 시간 분할과 사용자별 역사 조건이 중요해진다. 하나의 분할 방식을 모든 목적의 정답으로 외우지 않는다.

같은 잣대에서 비교한다

두 모델을 비교할 때 평가 사례·라벨·기간·지표·threshold 정책을 일치시킨다. 서로 다른 평가 자료의 정확도 90/95%만으로 새 모델이 좋아졌다고 결론 내릴 수 없다. 표본의 어려움이나 구성 자체가 달라졌을 수 있다.

최종 test 를 여러 후보 선택에 반복 사용하면 선택 정보가 누적된다. validation 으로 선택하고 잠근 test 로 마지막 평가하며 재평가가 필요하면 절차와 범위를 명시한다. 여기서 잠근다는 말은 파일을 읽기 전용으로 만들기만 하는 것이 아니라 모델 선택에 답을 사용하지 않는 규약이다.

중간 과정을 따라가는 예제

train 값 2,4 와 test 값 10 이 있다. 중심화 x−μ에서 train 평균만 쓴 test 결과와 전체 평균을 쓴 결과를 비교하라. 이어 동일 사용자 A 의 원본이 train, 변형 A′가 test 일 때 새 사용자 평가의 문제를 설명하라.

  1. train 평균(2+4)/2=3 이다.
  2. test 변환 10−3=7 이다.
  3. 전체 평균(2+4+10)/3=16/3, test 는 10−16/3=14/3 이다.
  4. A 와 A′는 같은 출처여서 새로운 사용자에 대한 독립 평가라는 목표에 어긋난다.

적절한 train 평균 변환은 7 이며 전체평균 14/3 에는 test 정보가 섞였다. 출처 분리도 별도 필요하다.
