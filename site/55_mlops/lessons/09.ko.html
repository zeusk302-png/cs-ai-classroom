소단원 9.1

지연·오류·분포 지표

서버가 빠르게 응답해도 모델은 엉뚱한 추천을 하고 있을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 모델은 입력으로 예측을 만들고 정답 라벨로 품질을 평가한다.

  • 비율은 분자와 분모 및 관측 기간을 함께 정한다.

학습 목표

  • 응답 성능·요청 실패·예측 품질을 분리한다.

  • 평균과 백분위수 및 분포를 계산한다.

서버별 p95와 버킷만 저장해도 전체 지연을 정확히 복원할 수 있을까?

실제 서버가 아닌 자체 원시 장부다. 서버 A의 완료 지연은 10 ms가 19개, 100 ms가 1개이고 서버 B는 100 ms가 20개다. 각 서버는 20개를 완료했다. 이 원고는 원시 표본의 p95를 정렬 위치 ceil(0.95N)의 값으로 정의한다. A의 위치 19는 10 ms이고 B는 100 ms다. 두 값의 평균 55 ms는 전체 40개의 위치 38에 있는 100 ms와 다르다. 요청 수가 같아도 백분위수 평균은 전체 백분위수가 아니다.

A의 지연 합은 290 ms, B는 2,000 ms다. 전체 평균은 2,290/40=57.25 ms다. 같은 요청 수 때문에 두 서버 평균 14.5 ms와 100 ms의 단순 평균이 이번에는 맞는다. 이 사실을 백분위수로 옮길 수는 없다. 누적 버킷을 10·50·100 ms 경계에 저장하면 전체 누적 수는 각각 19·19·40개다. 원시 p95의 위치 38은 (50,100] ms 버킷 안에 있다. 버킷 내부 값을 저장하지 않았으므로 이 범위만으로 원시 p95를 확정하지 못한다. 자체 선형 보간식은 50+(38−19)/(40−19)×50=2000/21 ms를 내며, 실제 장부의 100 ms와 다르다.

별도 접수 장부에는 위 완료 40개 외에 200 ms에서 시간 초과로 종료한 요청 2개가 있다. 완료 40개 중 100 ms짜리 하나는 HTTP 오류다. 10 ms짜리 19개는 모두 성공이다. 전체 접수 42개 중 실패는 HTTP 오류 1개와 시간 초과 2개를 합친 3개다. 실패율은 3/42=1/14이며 완료 기록만 사용한 1/40과 다르다. 전체 종료 지연에 시간 초과의 200 ms 두 값을 넣는 것은 실제 응답 도착 시간을 알아냈다는 뜻이 아니라, 접수부터 종료까지를 재는 별도 계약이다. Prometheus의 sum/count·누적 버킷·보간 설명과 MLCC의 응답 시간·질의 수 설명을 읽고 이 장부를 구성했다.

먼저 확인할 개념
  • 지연·오류·분포 지표

    측정 시작·종료 위치와 원시 nearest-rank 규약을 사용해 두 지연 장부의 대상을 분리한다.

  • 라벨지연과 경보

    미확인 정답의 품질과 HTTP 종료 상태가 서로 다른 관측이라는 점을 사용한다.

무엇을 관측한 숫자인가

응답 지연은 요청을 받아 결과를 돌려주기까지의 시간이다. 실패율은 정한 기간의 실패 요청 수를 전체 요청 수로 나눈다. 모델 정확도는 라벨이 확인된 예측에서 맞힌 비율이므로 HTTP 성공률과 같은 숫자가 아니다. 빠르고 오류 없이 반환한 잘못된 예측도 가능하다.

측정 시작과 종료 위치를 명시해야 한다. 모델 연산 시간만 잰 값과 큐 대기·전처리·네트워크를 포함한 전체 응답 시간을 섞으면 개선 위치를 잘못 판단한다. 버전과 기간, 표본 크기를 숫자 옆에 함께 적는다.

평균이 가리는 긴 꼬리

평균은 합을 관측 수로 나눈다. 대부분이 빨라도 소수의 긴 지연이 사용자 경험에 영향을 줄 수 있어 백분위수를 함께 본다. 아래는 정렬된 원시 표본에 nearest-rank 방식 ceil(p×n)을 사용하는 자체 계산이고 histogram에서 보간한 추정치와 다르다.

여러 서버의 p95를 그냥 평균하면 전체 요청의 p95가 되지 않는다. 서버별 요청 수와 실제 분포가 필요하다. Prometheus는 count와 sum의 합산 및 histogram bucket의 집계와 quantile의 차이를 설명하므로 자료 종류를 먼저 확인한다.

입력 분포도 품질과 따로 보기

결측 비율, 범주별 입력 빈도와 예측 분포는 모델이 어떤 환경에서 동작하는지 보여 준다. 새 국가의 요청이 늘거나 특정 센서 값이 사라지면 과거 평가 집합과 운영 환경이 달라질 수 있다. 하지만 입력 변화만으로 정확도 하락의 크기를 알아내지는 못한다.

전체 평균에 가려진 소집단도 확인한다. 시간 구간과 집단별 지표를 나누면 어느 요청에 문제가 생겼는지 조사할 수 있다. 모든 작은 집단의 차이를 즉시 장애로 단정하기보다 표본 수와 지속 여부를 함께 읽는다.

완료와 접수의 분모를 먼저 구별한다. 버킷 수는 누적값이므로 19+19+40을 전체 관측 수로 더하지 않는다. 버킷 보간값과 저장된 원시 표본의 정확한 순위값도 구별한다.

중간 과정을 따라가는 예제

가상 완료 요청10개의 지연(ms)이10,10,10,10,10,10,10,10,10,110이다. 이10개 중 실패 요청은1개이며 실패에도 완료 지연을 기록했다. nearest-rank p90,p95와 평균·실패율을 구하자.

  1. 총 지연은9×10+110=200ms이고 평균200/10=20ms다.

  2. p90 위치는ceil(.9×10)=9라10ms, p95 위치는ceil(.95×10)=10이라110ms다.

  3. 실패율은1/10=10%다. 실패한 요청을 지연 표본에서 뺀 계산을 이 정의의 평균과 섞지 않는다.

평균 20ms·p90 10ms·p95 110ms·실패율 10%다. 모델 정확도는 라벨 정보가 없어 계산하지 않는다.

A와 B의 평균 및 p95를 각각 합친 원시 장부와 비교하라.

  1. A의 평균은 290/20=14.5 ms이고 B의 평균은 100 ms다. 두 평균의 평균은 57.25 ms다.

  2. A의 p95는 10 ms이고 B의 p95는 100 ms다. 그 평균은 55 ms다.

  3. 전체 정렬 장부는 10 ms 19개 뒤에 100 ms 21개가 오므로 위치 38의 값은 100 ms다.

평균 집계는 이번 동수 장부에서 맞고 p95 평균은 틀린다.

누적 버킷은 구간을 주고 내부값은 잃는다

누적 수 19·19·40개만으로 원시 p95를 확정할 수 있는가?

  1. 전체 수 40의 p95 위치는 38이다. 50 ms 이하 누적 수 19보다 크고 100 ms 이하 누적 수 40 이하다.

  2. 원시 p95는 (50,100] ms 안에 있다. 선형 보간은 2000/21 ms로 약 95.24 ms다.

  3. 100 ms짜리 21개를 모두 60 ms로 바꿔도 이 세 버킷 수는 같다. 이 별도 장부의 원시 p95는 60 ms다.

같은 버킷 수가 원시 p95가 다른 장부를 허용한다. 보간값은 추정치다.

연습 1 · 값과 상태 예측

접수 42개 모두의 종료 지연에 200 ms 시간 초과 두 개를 포함한다. 원시 p95·p99와 평균을 구하라.

힌트 1

p95 위치는 ceil(39.9)=40이고 p99 위치는 ceil(41.58)=42다.

힌트 2

기존 합 2,290 ms에 400 ms를 더한다.

풀이와 답 확인

  1. 위치 40은 100 ms이고 위치 42는 200 ms다.

  2. 평균은 2690/42=1345/21 ms로 약 64.05 ms다.

종료 지연 p95는 100 ms, p99는 200 ms, 평균은 1345/21 ms다. 실제 성공 응답 시간의 분포와 구별한다.

분석자가 누적 버킷 19·19·40개를 더해 총 78개이며 실패율은 1/40이라고 보고했다. 두 문제를 고쳐라.

힌트 1

힌트 2

접수 장부에는 시간 초과 두 개가 있다.

풀이와 답 확인

  1. 최상위 100 ms 경계가 완료 40개 전체를 포함한다. 버킷 합은 관측 수가 아니다.

  2. 전체 접수 실패율은 3/42=1/14이고 완료 집합의 HTTP 오류율만 1/40이다.

완료 관측 수는 40개다. 전체 실패율과 완료 HTTP 오류율을 이름별로 따로 보고한다.

  2. 고유 요청 ID, 접수 시각, 종료 시각, 성공·HTTP 오류·시간 초과 종류와 버전을 기록한다. 시간 초과 값을 성공 응답으로 바꾸지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

전체 원시 p95가 정확히 50 ms일 수 있는가? 세 누적 버킷만 유지하고 지연 합은 유지할 필요가 없다.

힌트 1

50 ms 이하 관측 수는 19개다.

힌트 2

p95 위치 38이 50 ms 이하에 있으려면 누적 수가 적어도 38개여야 한다.

풀이와 답 확인

  1. 현재 누적 수 19개로 위치 38은 50 ms를 엄격히 초과한다.

  2. 100 ms 경계는 포함되므로 100 ms는 가능하다.

원시 p95=50 ms는 불가능하다. 가능한 구간은 열린 왼쪽 끝을 가진 (50,100] ms다.

소단원 9.2

data·concept drift

입력의 모양이 그대로인데 정답을 만드는 규칙만 바뀔 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 모델은 입력으로 예측을 만들고 정답 라벨로 품질을 평가한다.

  • 비율은 분자와 분모 및 관측 기간을 함께 정한다.

학습 목표

  • 입력분포 P(X)와 조건부 P(Y|X)의 변화를 구별한다.

  • 분포 경보를 성능 저하의 증명으로 오해하지 않는다.

각 특성의 비율과 정답 비율이 같으면 드리프트가 없을까?

두 비트 입력 X=(X₁,X₂)의 자체 분포를 정한다. 과거에는 00과 11이 각각 확률 1/2, 현재에는 01과 10이 각각 확률 1/2다. 각 좌표에서 0과 1의 주변 확률은 모두 1/2로 유지되지만 함께 나타나는 조합은 완전히 바뀐다. 네 조합을 범주로 둔 최대 확률 차이는 1/2다. 이 별도 모형의 정답 규칙은 두 시기 모두 Y=X₁이고 모델도 X₁을 출력한다. 따라서 입력의 공동 분포가 바뀌었어도 정확도는 두 시기 모두 100%다.

별도 한 비트 모형에서는 X=0과 X=1이 각각 확률 1/2이고 입력 분포는 유지된다. 과거 정답은 Y=X, 현재 정답은 Y=1−X다. 정답의 주변 분포도 두 시기 모두 0과 1이 각각 1/2다. 그러나 같은 입력의 조건부 정답은 뒤집혔다. 기존 모델 f(X)=X의 정확도는 100%에서 0%로 바뀐다. 입력과 정답의 주변 통계만 같은 것은 조건부 규칙이 같다는 뜻이 아니다. 첫 모형과 이 모형은 서로 별개다.

범주 A/B 비중의 별도 기준 비교는 학습 집합 (1/2,1/2), 직전 운영 (4/5,1/5), 현재 운영 (7/10,3/10)이다. 최대 절댓값 차이 D를 쓰면 현재 대 학습의 skew는 1/5, 현재 대 직전의 drift는 1/10이다. 자체 엄격 문턱 D>3/20에서는 skew만 초과한다. 이는 모형에서 정한 정확한 분포 비교이며 유한 표본의 통계 유의성 검정이 아니다. Google Model Monitoring의 v1 기준 집합 구분과 arXiv 논문의 virtual/real 정의를 대조했다. 이 교재의 data는 P(X), concept는 P(Y|X)의 변화이며, 논문의 공동 분포 전체를 아우르는 용어 사용과 구별한다.

먼저 확인할 개념
  • data·concept drift

    기본의 P(X)와 P(Y|X) 정의 및 기준 집합 구분을 공동·주변 분포 반례에 사용한다.

  • 지연·오류·분포 지표

    입력 빈도와 모델 정확도가 별도 관측이라는 설명을 두 모형의 품질 비교에 사용한다.

이 교재에서 사용하는 구분

이 소단원에서는 data drift를 입력분포 P(X)의 시간 변화, concept drift를 같은 입력에서 정답이 나오는 조건부 분포 P(Y|X)의 변화로 구분한다. 문헌에서는 joint distribution 변화 전체를 concept drift라 부르고 virtual/real로 다시 나누기도 하므로 용어가 등장한 자료의 정의를 확인한다.

정답 규칙이 같아도 입력 집단 비중이 바뀌면 전체 정확도는 바뀔 수 있다. 반대로 입력 비중이 그대로라도 규칙이 바뀌면 입력 통계만 감시하는 시스템은 이를 알아채지 못할 수 있다. 두 변화는 따로 또는 함께 생길 수 있다.

기준 집합과 비교 기간

운영 입력을 학습 입력과 비교하는 skew와 운영의 이전 기간과 이후 기간을 비교하는 drift는 기준 집합이 다르다. 비교 범주, 결측 처리, 관측 창을 같게 정의해야 의미 있는 차이가 나온다. 다른 기준을 사용한 점수들을 이름이 같다고 바로 비교하지 않는다.

범주형 분포의 간단한 자체 지표로 가장 큰 비율 차이를 사용할 수 있다. 경보 문턱을 넘으면 조사할 신호이지 정답 규칙 변화나 정확도 하락이 확정되는 것은 아니다. 작은 표본 변동과 정상적인 계절 변화도 함께 검토한다.

경보 뒤에는 원인을 조사

입력 수집 오류·새 사용자 비중·특성 계산 코드 변화가 분포를 바꿀 수 있다. 재학습만 하면 잘못된 입력을 해결하지 못하고 문제가 숨겨질 수도 있다. 동일 모델의 품질을 가능한 라벨과 집단별로 대조하고 데이터 경로를 확인한다.

예측 시점과 정답 시점

숙제 제출 여부를 예측하면 제출 마감이 지난 뒤에야 정답을 확정할 수 있다. 라벨은 즉시 또는 고정·변동 지연 후 올 수 있고 끝내 확인되지 않을 수도 있다. 아직 모르는 라벨을 0이나 오답으로 넣으면 품질 측정이 왜곡된다.

예측ID와 모델 버전, 예측 시각, 라벨 시각을 연결해야 한다. 늦게 도착한 정답을 오늘의 예측처럼 섞으면 어느 모델·기간의 품질인지 모호해진다. 관측이 끝난 cohort를 비교하되 최종 미확보 대상도 따로 기록한다.

확보한 라벨 집합의 편향

확보한 라벨 수를 전체 예측 수로 나누면 coverage가 된다. 그 확보 집합에서 맞힌 비율은 라벨이 온 집합의 정확도이며 미확보 집합의 정확도를 자동으로 대표하지 않는다. 빨리 결과가 나오는 쉬운 사례만 먼저 라벨이 올 수 있기 때문이다.

미확보의 실제 정답을 모르면 전체 정확도의 가능한 범위를 구할 수 있다. 미확보 전부 오답/전부정답의 두 극단을 계산하면 확정 가능한 경계를 보인다. 이 경계는 신뢰구간이나 무작위 표본 추정과는 다른 논리적 범위다.

  2. 시각 20초까지 도착한 최신 revision을 연결한 W₀ 스냅샷은 전체 8개, 확인 5개, 정답 4개, 오류 1개다. 이후 도착은 감사용 후속 품질 기록으로 남기며 이미 낸 경보 기록을 이 정책에서는 바꾸지 않는다.
