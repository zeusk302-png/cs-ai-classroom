소단원 1.1

사용자·운영 요구

분류 점수가 좋은 모델이 있어도 사용자는 왜 일을 끝내지 못할까?

준비 개념과 학습 목표

준비 개념

  • 서비스: 입력을 받고 결과를 전달하는 전체 과정이다. 모델 계산은 그중 한 단계다.
  • 요구: 누가 어떤 상황에서 무엇을 할 수 있어야 하는지 적은 조건이다.
  • 비율: 성공 횟수를 대상 전체 횟수로 나눈다. 대상이 0이면 이 비율은 정의하지 않는다.

학습 목표

  • 사용자 목표를 관측 가능한 완료 조건으로 바꾼다.
  • 정상 입력·실패·사람 검토의 경계를 정의한다.
  • 측정 지표와 목표, 실제 보장을 구별한다.

행동과 관측 지점부터 정하기

가상의 도서관 질문 분류 도우미를 생각하자. 사용자는 질문을 보내 적절한 담당 안내를 받고 싶다. 운영자는 오류를 발견했을 때 모델 버전을 되돌리고 싶다. 두 요구는 정확도 한 숫자로 합쳐지지 않는다. 사용자, 작업, 입력 범위, 출력 의미, 실패 시 대안을 각각 적으면 무엇을 측정할지 정할 수 있다.

요구의 관측 지점도 계약에 포함한다. 서버가 응답을 만들었어도 화면에 나타나지 않으면 사용자의 완료는 아니다. 여기서는 유효한 요청 접수부터 사용자가 읽을 수 있는 안내 전달까지를 한 요청으로 센다. 실제 측정에서는 클라이언트와 서버의 시간·식별자를 연결하는 방법과 개인정보 수집 범위를 추가로 정해야 한다.

입출력과 실패 계약

입력 계약은 지원 언어, 최대 길이, 필수 항목과 허용되지 않는 입력을 정한다. 출력 계약은 추천 담당, 모델 버전과 검토 필요 여부의 의미를 정한다. 추천은 담당자의 실제 승인이나 사용자의 권한을 대신하지 않는다. 유효하지 않은 입력을 거절하는 것과 유효한 요청을 처리하지 못하는 것을 별도 결과로 기록한다.

확신이 부족할 때 사람에게 검토를 넘기는 대안은 실패를 숨기는 장치가 아니다. 검토를 의도한 결과로 인정한다면 안내가 전달되고 정해진 검토 경로가 실제 마련되어야 한다. 예제의 성공 조건은 자동 추천 또는 검토 접수 안내가 2초 안에 전달되는 것이다. 최종 질문 해결은 별도 사용자 성과이므로 검토 안내만으로 해결됐다고 세지 않는다.

지표·목표·증거의 차이

SLI는 관측 값을 정량화한 지표이고 SLO는 그 지표에 대해 정한 목표다. SLA는 결과에 따른 계약상 의무나 조치까지 포함하는 개념이다. 여기서는 SLO만 설계하며 실제 계약이나 서비스 보장을 만들지 않는다. 성공 비율의 분모, 시간 창, 포함되는 요청 종류를 적지 않으면 팀마다 다른 숫자를 보고 같은 목표라고 오해할 수 있다.

운영 요구에는 책임자, 변경 승인, 되돌릴 버전, 복구 확인 방법도 필요하다. 관측된 실패와 원인 가설을 구분한다. 느린 응답이라는 사실만으로 모델 자체가 원인이라고 확정할 수 없다. 네트워크, 대기열, 화면 처리도 같은 전체 지연에 영향을 준다.

중간 과정을 따라가는 예제

가상 하루 유효 요청 100개 중 자동 안내 82개, 검토 접수 안내 13개, timeout 5개다. 앞의 95개는 모두 2초 안에 전달됐다고 가정한다. 성공 조건은 2초 안의 자동 또는 검토 접수 안내다.

  1. 분모는 유효 요청 100개이며 timeout도 포함한다.
  2. 성공은 82+13=95개다. 검토 안내는 최종 해결과 다르지만 정의한 안내 성공에는 포함한다.
  3. SLI=95/100=0.95=95%. 목표 97%와 비교하면 2%p 부족하다.
  4. 정상 범위 밖 거절 요청은 이 사례 분모에 없으며 실제 계약에서는 별도 거절 지표를 둔다.

이 가상 창에서 안내 성공 목표 97%를 충족하지 못한다. 모델 정확도나 최종 문제 해결률은 이 기록만으로 계산할 수 없다.

종이와 본문으로 직접 해보기

검토 안내 13개 중 3개가 실제로는 2초 뒤에 전달됐다고 정정한다. 성공 비율을 다시 계산하고 어떤 요구가 깨졌는지 쓰라.

힌트 보기

성공은 결과 종류와 전달 시간 두 조건을 모두 만족해야 한다.

풀이 보기

성공은 82+(13−3)=92개라 92%다. 검토 안내 자체는 전달됐지만 3개가 시간 조건을 위반했다. 최종 해결 여부는 여전히 알 수 없다.

오해와 반례

모델을 배포했으면 사용자 요구가 충족된다.

서버의 분류가 모두 맞아도 화면에 결과가 전달되지 않으면 사용자는 일을 끝내지 못한다. 또한 추천이 정확해도 접근 권한·사람 검토·복구 경로 요구는 별도로 확인해야 한다.

모델지표와 서비스지표

정확도 95%와 응답 성공률 95%는 같은 말일까?

준비 개념과 학습 목표

준비 개념

  • 이진 분류: 두 범주 중 하나를 선택한다. 양성은 이 예제에서 담당 검토가 필요한 질문이다.
  • 정답 라벨: 평가에 쓰는 기준 분류이며 나중에 들어오거나 틀릴 수 있다.
  • 혼동행렬: 실제 양성/음성과 예측 양성/음성의 네 조합을 센다.

학습 목표

  • 모델 오류와 전달 오류를 다른 분모로 정의한다.
  • 혼동행렬에서 정확도·정밀도·재현율을 계산한다.
  • 평가 표본과 운영 분포 차이가 결론을 제한함을 설명한다.

모델의 판단 품질

임계값을 고정한 이진 모델에서 TP는 실제 양성을 양성으로, TN은 실제 음성을 음성으로 예측한 수다. FP는 음성을 양성으로, FN은 양성을 음성으로 예측한 수다. 정확도는 (TP+TN)/N, 정밀도는 TP/(TP+FP), 재현율은 TP/(TP+FN)이다. 각각 분모가 양수일 때 정의하며 분모가 0인 경우 보고 정책을 별도로 정한다.

검토 필요 질문을 놓치는 FN과 불필요하게 검토시키는 FP의 영향은 다를 수 있다. 어느 지표를 높일지는 작업 목적과 비용을 먼저 따져야 한다. 임계값을 바꾸면 네 수가 바뀌므로 서로 다른 임계값의 점수를 같은 설정의 성능처럼 비교하지 않는다.

서비스의 전달 품질

응답 성공률은 정해진 요청에 유효 응답이 전달된 비율이고 지연은 접수부터 관측한 완료까지 걸린 시간이다. HTTP 성공 상태나 응답 전달은 분류 정답을 뜻하지 않는다. 반대로 평가 파일에서 높은 정확도를 보여도 운영 중 timeout이면 그 요청의 결과를 사용자가 이용하지 못한다.

모델 지표의 분모가 라벨 있는 응답만이면 실패 요청이 빠질 수 있다. 전체 유효 요청 수, 전달된 요청 수, 정답 라벨이 연결된 요청 수를 함께 적어 선택 편향을 드러낸다. 아직 라벨이 없는 요청을 정답이라고 가정하지 않으며 서비스 실패와 모델 오분류를 이중 집계하는 방식도 명시해야 한다.

평가와 의사결정의 연결

오프라인 평가는 고정된 데이터와 버전에 대한 증거다. 독립 평가 자료, 학습에 쓰지 않은 라벨, 적절한 사용자·시점 분할이 필요하다. 운영 분포가 같다는 가정 없이 이 점수를 미래의 모든 요청에 대한 보장으로 확장하지 않는다. 사용자 행동 개선을 주장하려면 비교 설계와 교란 요인 통제가 추가로 필요하다.

전체 평균이 좋아도 드문 질문이나 특정 언어에서 실패가 몰릴 수 있다. 범주별 표본 수와 불확실성을 함께 보고, 오류의 중요도를 목적에 맞춰 검토한다. 아래 작은 표의 수치는 계산을 배우는 자료이며 통계적 신뢰구간이나 실제 사용자 성과를 인증하는 실험이 아니다.

중간 과정을 따라가는 예제

가상 라벨 평가 100개에서 TP=18, FN=2, FP=8, TN=72다. 별도 서비스 창의 유효 요청 100개 중 전달 성공은 95개다. 모델 설정과 두 집계 범위를 분리해 지표를 계산하라.

  1. 모델 표의 합은 18+2+8+72=100이다. 실제 양성은 20개다.
  2. 정확도=(18+72)/100=90%, 정밀도=18/26=9/13≈69.23%다.
  3. 재현율=18/20=90%다. FN 2개는 검토 필요 질문의 10%다.
  4. 서비스 전달 성공률은 별도 기록 95/100=95%이며 두 표가 같은 요청의 결합 기록이라는 가정은 없다.

모델 정확도 90%, 정밀도 약 69.23%, 재현율 90%, 별도 전달 성공률 95%다. 이 값들만 곱해 전체 사용자 정답 전달률을 구할 수 없다.

종이와 본문으로 직접 해보기

라벨 표의 실제 양성 20개와 음성 80개를 모두 음성으로 예측하면 정확도와 재현율은? 정밀도의 분모도 확인하라.

힌트 보기

TP=0, FN=20, FP=0, TN=80을 만든다.

풀이 보기

정확도는 80%, 재현율은 0/20=0이다. 양성 예측이 없어 정밀도 0/0은 정의되지 않는다. 구현이 0으로 출력할 수 있어도 그 보고 관례를 수학적 값과 구별한다.

오해와 반례

서비스 응답이 성공하면 모델도 맞았고, 정확도만 높으면 충분하다.

모든 응답을 제시간에 전달하면서 모든 검토 필요 질문을 놓칠 수 있다. 불균형 자료에서 늘 음성인 모델은 높은 정확도를 얻어도 양성 재현율 0이다. 성공 정의와 오류 영향을 함께 봐야 한다.

심화: 같은 요청 모집단에서 S를 전달 성공, C를 분류 정답이라 하자. P(S∩C)=P(S)P(C|S)이지 항상 P(S)P(C)는 아니다. 예를 들어 100개 중 성공 90개, 정답 90개라도 교집합은 80~90개일 수 있다. 두 실패 집합이 겹치는지에 따라 달라진다. 이를 별도 평가표에 임의 적용하지 말고 요청별 연결 근거를 먼저 확보한다.

지연·비용·오류목표

평균 지연이 짧은데도 일부 사용자가 오래 기다리는 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 시간 단위: 1초=1000ms다. 지연은 한 요청의 경과 시간이다.
  • 백분위: 정렬된 표본에서 지정한 누적 비율의 위치를 고르는 값이다. 정의 방식에 따라 작은 표본의 값이 달라진다.
  • 비용: 이 예제에서는 요청당 가상 원화 비용을 합산하며 실제 요금표가 아니다.
  • 올림·내림: ceil(x)는 x 이상인 가장 작은 정수, floor(x)는 x 이하인 가장 큰 정수다. 예를 들어 ceil(9.5)=10, floor(0.6)=0이다.

학습 목표

  • 지연·오류의 관측 범위와 시간 창을 명시한다.
  • 평균·백분위·오류 예산을 계산한다.
  • 품질·시간·비용의 복수 제약으로 후보를 평가한다.

평균과 꼬리 지연

한 요청의 전체 지연에는 통신, 대기, 전처리, 추론, 후처리와 화면 표시가 포함될 수 있다. 추론 시간만 재면 다른 구간의 지연을 놓친다. 각 구간이 순차라는 가정 아래만 구간 시간의 합으로 전체를 계산한다. 병렬 구간은 경로와 겹침을 고려해야 한다.

평균은 모든 값을 합해 개수로 나누지만 느린 소수 요청을 숨길 수 있다. 여기서는 표본 백분위를 nearest-rank 관례로 정의한다: n개를 오름차순 정렬하고 0<p≤1일 때 ceil(pn)번째 값이다. p95는 미래 최대 지연의 보장이 아니며 표본 수·부하·timeout 처리와 함께 보고한다.

좋은 요청과 오류 예산

가상 목표를 한 창의 유효 요청 중 99%가 200ms 이내 유효 응답 전달이라고 정하자. timeout과 유효하지 않은 응답을 나쁜 요청으로 포함한다. 정상 범위 밖 입력 거절의 처리 정책은 별도다. 성공 응답의 지연만 재면 timeout이 많은 서비스의 지표가 오히려 좋아 보일 수 있다.

N은 양의 정수인 전체 요청 수이고 목표 좋은 비율을 0≤s≤1로 두자. 나쁜 요청 수 m에 대해 (N−m)/N≥s이려면 m≤(1−s)N이어야 한다. m은 정수이므로 허용되는 나쁜 요청 수는 최대 floor((1−s)N)이다. 관측 창이 1000개이고 목표가 99%이면 최대 10개다. 이는 운영 선택을 위한 예산이며 장애를 허용해야 한다는 의무나 안전상 피해를 정당화하는 기준은 아니다. 모델 오분류 예산과 전달 실패 예산은 같은 사건인지 별도인지 명시한다.

비용과 복수 목표

총비용을 가상 고정 비용 F와 시도당 비용 c, 총 시도 수 K로 F+cK라 두면 재시도도 비용을 만든다. 최종 성공 요청당 비용을 원하면 이 총액을 성공한 원래 요청 수로 나눈다. 시도 수와 사용자 요청 수를 혼동하지 않는다. 실제 비용은 저장·전송·인력 등 빠진 항목과 가격 조건을 확인해야 한다.

후보 선택은 가장 빠른 하나를 고르는 문제가 아닐 수 있다. 지연·성공 비율·모델 품질·총비용의 최소 조건을 모두 만족하는 후보를 먼저 찾고, 남은 후보의 교환 관계를 비교한다. 표본에서 목표를 만족했다는 사실과 모든 미래 부하에서 보장된다는 주장도 구별한다.

중간 과정을 따라가는 예제

가상 성공 응답 10개의 지연은 정렬 순서로 10,10,10,10,10,10,10,10,10,1000ms다. 별도 1000개 요청 창에서 좋은 요청은 992개다. 가상 비용 F=100원,c=2원,K=1100회,최종 성공 원래 요청=1000개로 둔다.

  1. 지연 합은 9×10+1000=1090ms라 평균은 109ms다.
  2. nearest-rank p95 위치는 ceil(0.95×10)=10이라 p95=1000ms다.
  3. 별도 좋은 요청 비율은 992/1000=99.2%. 나쁜 8개는 예산 10개 이내이며 2개 여유다.
  4. 총비용=100+2×1100=2300원, 최종 성공 원래 요청당 비용=2300/1000=2.3원이다. 서로 다른 기록의 값은 하나의 통합 실측으로 주장하지 않는다.

평균 109ms만 보면 꼬리 1000ms를 숨긴다. 별도 창의 99% 목표는 충족하며 가상 성공 요청당 비용은 2.3원이다.

종이와 본문으로 직접 해보기

같은 1000개 요청 창에서 나쁜 요청이 12개가 되면 좋은 비율과 예산 초과량은? 비용 모형의 K가 1200이면 요청당 비용도 다시 계산하라. 성공 원래 요청 수는 비용 계산에서만 1000으로 가정한다.

힌트 보기

좋은 수는 1000−12, 허용 나쁜 수는 10이며 비용은 F+cK다.

풀이 보기

좋은 비율은 988/1000=98.8%이고 예산을 2개 초과한다. 비용 모형 총액은 100+2×1200=2500원, 성공 원래 요청당 2.5원이다. 좋은 요청 수와 비용 모형의 최종 성공 수는 정의가 다른 가상 가정이다.

오해와 반례

p95가 200ms이면 모든 요청이 200ms 안에 끝난다.

p95는 정의한 표본의 누적 위치다. 100개 중 95개가 100ms이고 5개가 1초이면 nearest-rank p95=100ms이지만 5개는 훨씬 늦다. 평균이나 백분위만으로 최대값이나 미래 hard deadline을 보장하지 않는다.
