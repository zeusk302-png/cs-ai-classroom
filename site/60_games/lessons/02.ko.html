소단원 2.1

update·render

화면을 두 번 그리면 캐릭터도 두 번 움직여야 할까?

준비 개념과 학습 목표

준비 개념

  • 상태 S는 게임 규칙에 필요한 현재 자료다. 여기서는 위치 x 하나이며 단위는 게임 내 길이 단위 u다. 화면의 픽셀과 같은 단위라고 가정하지 않는다.

  • 갱신 U(S,input,dt)는 상태를 다음 상태로 바꾼다. dt는 받아들인 모형 시간의 증가량이며 초 단위의 비음수다. 여기서는 dt가 유한한 값이라고 가정한다.

  • 표시 R(S)는 상태를 읽어 그릴 자료를 만든다. 이 단원의 R은 게임 규칙 상태를 수정하지 않는 순수한 관찰 함수다.

학습 목표

  • 규칙 상태 갱신과 표시를 분리한다.

  • 입력·갱신·표시의 순서를 완전한 모형으로 추적한다.

  • 표시 횟수와 게임 시간·현실 시간의 차이를 설명한다.

상태를 바꾸는 일과 보여 주는 일

update는 이동·점수·규칙 등 모형 상태의 다음 값을 결정하고 render는 그 상태로부터 표시를 만든다. 실제 엔진에서는 표시 과정이 그래픽 명령과 자원을 바꿀 수 있다. 여기서 순수하다는 계약은 그 과정이 게임 규칙 상태 S를 바꾸지 않는다는 뜻이다.

화면을 다시 그려도 상태를 보존하면 창 노출이나 여러 카메라 때문에 그리는 횟수가 바뀌어도 규칙 결과를 바꾸지 않는다. 반대로 render 안에 x+=1을 두면 같은 입력에서도 표시 횟수에 따라 이동한다. 화면이 부드럽다는 관찰은 규칙이 맞다는 증거가 아니다.

자체 루프의 입력과 시간 계약

자체 루프는 입력 u를 한 번 받음→받아들인 dt로 갱신→새 상태 표시 순서다. U(x,u,dt)=x+u·dt, 입력 속도 u의 수치는 −2, 0, 2 중 하나이고 단위는 게임 내 길이 단위/초이며 충돌·가속·화면 경계는 없다. 입력은 해당 시간 구간 내내 유지된 속도이고 순간 클릭 사건이 아니다. dt=0이면 이동하지 않는다.

입력을 표시 횟수마다 다시 소비하거나 고정 갱신 여러 번에 같은 클릭을 반복 적용하면 다른 의미가 된다. 실제 사건의 시각을 어느 tick에 대응시킬지는 별도 정책이다. 이 예시는 주어진 구간 입력만 사용하며 장치 입력 지연과 실시간 스케줄을 측정하지 않는다.

분리로 얻는 보장과 한계

아래 계산은 정확한 실수 연산과 정상 순차 실행을 가정한다. 실제 엔진의 부동소수 반올림, 병렬 갱신, 난수와 충돌을 포함한 결정성은 이 작은 모형만으로 보장하지 않는다. 상태를 기록하면 같은 규칙을 종이로 반복할 수 있지만 엔진의 비트 단위 재생 시험과는 다르다.

초 단위 dt는 갱신이 진행시키기로 선택한 모형 시간이다. 일시정지·시간 배율·큰 지연 제한 정책을 넣으면 현실의 경과시간과 다를 수 있다. Unity 6.0 자료도 scaled/unscaled와 제한을 구별한다. 본 단원의 규칙은 특정 엔진의 모든 콜백 순서를 복제한 것이 아니다.

중간 과정을 따라가는 예제

초기 x=0에서 (u,dt)가 (2,0.1),(0,0.2),(−2,0.1)이다. 각 구간 뒤 표시 R(x)="position="과 x를 연결한 자료를 만든다. 두 번째 상태를 두 번 표시해도 x가 바뀌는가?

  1. 첫 구간 U=0+2·0.1=0.2다. 표시 자료의 위치는 0.2이며 상태도 0.2다.

  2. 두 번째 구간은 속도 0이므로 0.2+0·0.2=0.2다. 표시를 두 번 해도 두 자료 모두 위치 0.2이고 x는 0.2다.

  3. 세 번째 구간은 0.2−2·0.1=0이다. 새 표시 위치도 0이다.

  4. 받아들인 시간은 0.1+0.2+0.1=0.4초이고 갱신은 3회, 표시는 4회다. 이 횟수 차이가 규칙 상태를 바꾸지 않는다.

최종 x=0, 모형 시간 0.4초다. 표시 두 번은 이동 두 번이 아니다.

종이와 본문으로 직접 해보기

힌트 보기

dt를 먼저 계산하고 순수 표시와 상태 변경 표시를 나누어라.

풀이 보기

정상 U는 x=1을 유지하고 순수 R 세 번 뒤에도 1이다. 잘못된 R은 1→2→3→4로 바꾸므로 표시 횟수가 규칙 결과를 바꾼다. 종이 반례이며 렌더링 실행은 아니다.

오해와 반례

표시 프레임이 많으면 같은 시간에 항상 더 멀리 이동해야 한다.

속도와 dt를 사용하는 규칙에서는 같은 입력 구간의 시간 합이 같으면 이 상수속도 모형의 이동도 같다. 표시 자체는 상태를 바꾸지 않는다. 표시마다 1을 더하는 반례는 잘못된 규칙이다.

한 단계 더

심화: 표시가 상태를 보존한다면 U 단계들 사이에 R을 임의의 유한 횟수 삽입해도 U가 읽는 상태열은 같다. 초기 상태가 같고 R이 항등적으로 규칙 상태를 보존하며 U의 입력·dt가 동일하다는 전제에서 단계 수 귀납으로 증명한다. R이 난수를 소비하거나 입력 큐를 바꾸고 U가 그것을 읽는다면 관찰한 x만 같아도 전체 전제가 깨진다. 상태에 포함할 자료의 경계를 먼저 정해야 한다.

소단원 2.2

고정·가변 timestep

시간을 한 번 크게 넘기는 것과 여러 번 작게 넘기는 것은 항상 같을까?

준비 개념과 학습 목표

준비 개념

  • 시간 간격 timestep은 한 갱신이 진행시키는 모형 시간이다. 고정 방식은 매번 h>0, 가변 방식은 받아들인 각 dt≥0를 쓴다. 받아들인 각 dt는 유한한 값으로 제한한다.

  • 누적기 a는 아직 갱신하지 않은 받아들인 시간이다. 프레임 dt를 더한 뒤 a≥h인 동안 h만큼 갱신하고 a에서 h를 뺀다.

  • 상수속도 x←x+v·dt와 가속도 수치근사는 다르다. 명시적 Euler의 한 단계는 이전 v로 x를 먼저 갱신하고 v를 v+g·dt로 갱신한다.

학습 목표

  • 누적기의 0·1·여러 갱신을 추적한다.

  • 상수속도와 가속도 근사의 시간 분할 차이를 설명한다.

  • 따라잡기 비용과 시간 제한 정책의 손실을 구분한다.

간격을 선택하는 두 방식

가변 간격은 각 프레임의 받아들인 dt로 갱신한다. 고정 간격은 프레임마다 같은 횟수의 갱신을 강요하는 것이 아니라 h를 일정하게 둔다. 프레임 시간이 짧으면 0회, 길면 여러 회가 될 수 있다. 갱신 tick 수와 표시 frame 수를 구별한다.

상수 v의 정확한 산술에서는 연속 두 단계의 이동이 v·dt1+v·dt2=v·(dt1+dt2)다. 그러나 가속도·충돌·비선형 규칙은 이런 분할 불변성을 자동 갖지 않는다. 부동소수 실제 덧셈도 비트 단위로 같은 결과를 보장하지 않는다.

고정 간격의 누적 규칙

자체 누적기는 a=0, x=0으로 시작하고 h=0.02초, v=2u/초다. 각 프레임에 dt를 더한 뒤 while a≥h: x←x+v h; a←a−h를 끝까지 수행한다. 시간은 정확한 실수이며 클램프·갱신 횟수 제한·입력 변화·실행 비용은 없다.

초기부터 받아들인 시간 T는 수행한 tick 수 k에 대해 T=k h+a다. while을 끝까지 수행하면 0≤a<h다. 이 식은 시간 보존의 근거이지 현실에 항상 제시간에 따라잡는다는 보장이 아니다. 어떤 시간도 버리지 않는다는 모형 정책이 전제다.

큰 지연과 따라잡기의 비용

실제 갱신에 비용이 들면 따라잡기 자체가 다음 프레임을 늦출 수 있다. 간단한 단일 자원 모형에서 tick마다 비용 c이고 다른 비용도 있다면 c<h는 tick 부하만의 여유 조건이지 전체 마감 보장이 아니다. c≥h라면 지속 입력되는 시간의 따라잡기를 같은 자원에서 유지하기 어렵다.

지연을 제한하거나 한 프레임의 tick 수를 제한하는 구현은 버릴 시간, 남길 누적기, 게임 시간의 지연을 명시해야 한다. Unity의 maximumDeltaTime 정책은 특정 엔진의 선택이다. 큰 dt를 줄였다고 현실 시간까지 모두 시뮬레이션한 것은 아니다. 설치 없이 본문의 다른 정책들을 종이로 비교한다.

중간 과정을 따라가는 예제

h=0.02초,v=2,x=0, a=0에서 프레임 dt가 0.015,0.025,0.010초다. 각 프레임의 tick 수·x·남은 a를 구하라.

  1. 첫 a=0.015<h이므로 tick0회,x=0, a=0.015다.

  2. 둘째는 a=0.015+0.025=0.040이다. 첫 tick 후 x=0.04, a=0.02이고 둘째 후 x=0.08, a=0이다.

  3. 셋째 a=0.010<h이므로 tick0회,x=0.08,a=0.010이다.

  4. 전체 T=0.050=2·0.020+0.010이다. 현재 시뮬레이션은 0.040초까지 진행했고 0.010초는 보류했다.

프레임별 tick0/2/0회, 최종 x=0.08,a=0.01초다. 한 프레임 한 tick이라는 해석은 틀리다.

종이와 본문으로 직접 해보기

상수속도 2에서 가변 dt0.01/0.03의 최종 x는? 별도 가속도 g=2u/초²,x=0, v=0에서 명시적 Euler를 한 번 dt0.04와 두 번 dt0.02로 각각 적용하라.

힌트 보기

Euler의 x는 갱신 전 v를 쓴다. 두 번째 단계에는 첫 단계 뒤 v가 들어간다.

풀이 보기

상수속도는 0.02+0.06=0.08이다. Euler 한 번은 x=0, v=0.08이다. 두 번은 첫 x=0, v=0.04, 다음 x=0.0008, v=0.08로 위치가 다르다. 실제 연속 운동의 x=0.5g t²=0.0016과도 다르다. 정확 산술의 종이 근사 비교다.

오해와 반례

고정 timestep만 선택하면 어떤 게임도 동일 재생과 안전한 충돌을 보장한다.

tick의 입력 배치, 초기 상태, 난수, 갱신 순서, 수치 연산과 충돌 방법도 같아야 한다. 고정 간격에서도 물체가 한 tick에 벽을 넘어가는 이산 검출 문제는 남는다.

다음 단계의 v가 달라 위치 근사가 분할에 의존한다.

한 단계 더

심화: 시간 보존 T=k h+a는 초기 0에서 성립한다. 프레임 dt를 받아들이면 T와 a가 같은 dt만큼 증가한다. 한 tick마다 k가 1 증가하고 a가h 감소해 합은 불변이다. 유한 dt와 h>0, 비용과 수치 오차가 없는 산술 모형에서는 floor(a/h)회로 내부 while이 끝난다. 프레임별 입력이 무한히 계속 들어오는 전체 게임 루프의 종료와는 다른 주장이다. 클램프로 시간을 버리면 버린 시간 d까지 포함해 T_real=k h+a+d로 정책을 기록해야 한다. 마지막 현실 시간 식은 시간 배율이 1이고 일시정지 없이, 현실 경과시간 중 클램프로 버린 부분만 d로 분리하는 정책에 한정한다. 시간 배율이나 일시정지가 있으면 별도의 시간 관계도 기록해야 한다.

소단원 2.3

프레임율과 보간

50회 갱신하고 100회 그리면 중간 화면의 위치는 어디서 얻을까?

준비 개념과 학습 목표

준비 개념

  • FPS는 일정 관찰구간의 표시 프레임 수를 그 구간 초로 나눈 값이다. 각 프레임 간격 Δt>0의 역수와 구간 FPS는 구별한다.

  • 이전·현재 tick 위치를 p_prev,p_curr로 보존하고 남은 시간 a/h=α로 표시 위치를 계산한다.0≤a<h이면 0≤α<1이다.

  • 선형 보간은 p_display=(1−α)p_prev+αp_curr다. 이 단원은 동일한 1차원 좌표계에서 연속 이동하는 위치만 다루며 표시값을 물리 상태에 되돌려 쓰지 않는다.

학습 목표

  • 구간 FPS와 서로 다른 프레임 시간을 계산한다.

  • tick 상태와 보간 표시값을 분리해 추적한다.

  • 보간의 시간 지연과 불연속 이동의 한계를 설명한다.

평균 프레임율이 숨기는 것

프레임 간격 0.01초와 0.03초가 연속이면 2프레임/0.04초=50FPS다. 각 역수 100과약 33.33의 산술평균 약 66.67은 이 구간 FPS가 아니다. 어떤 평균을 썼는지 밝히고 최대 프레임 시간이나 긴 지연도 따로 관찰해야 한다.

50FPS라는 같은 평균에도 매번 0.02초인 경우와 0.01/0.03초가 번갈아 오는 경우의 간격은 다르다. 평균만으로 표시가 일정하거나 입력이 늦지 않음을 보장하지 않는다. 이 숫자는 가상 시간표이며 실제 모니터/CPU/GPU의 측정값이 아니다.

이전 상태와 현재 상태 사이 표시

고정 tick 사이에도 화면을 그릴 수 있다. 자체 모형은 초기 prev=current=x=0이고 tick마다 prev←current 후 current←current+v h를 수행한다. 누적기를 다 처리한 뒤 α=a/h를 구해 prev와 current 사이 위치를 표시한다. 표시 횟수가 늘어도 현재 규칙 위치는 그대로다.

시뮬레이션 현재 시각이 k h일 때 prev는(k−1)h의 상태다. 보간 표시 시각은(k−1)h+αh=(k−1)h+a다. 받아들인 시간은k h+a이므로 이 방식의 표시가 한 tick 과거를 가리킨다. k≥1인 초기화 이후 구간의 설명이며 첫 tick 전에는 두 초기 위치를 같게 두어 시작점을 표시한다. 표시 시각은 현재 tick 시각보다 h−a만큼 과거이고, 받아들인 시간보다 h만큼 과거다. 이 시각 차이는 장치부터 화면까지의 실제 전체 입력 지연을 측정한 값이 아니다.

과거 표시와 미래 추측의 차이

보간은 이미 아는 두 상태 사이를 표시하고 외삽은 현재 속도 등으로 미래를 예측한다. 충돌 직전의 외삽은 벽 안으로 예측했다가 수정될 수 있다. 보간도 실제 경로가 곡선이면 중간 위치가 정확하지 않고 숨겨진 사건을 복원하지 않는다.

순간이동에서 prev=0/current100을 무조건 섞으면 방문하지 않은 중간 장소를 표시한다. 그런 전환에는 두 표시 상태를 새 위치로 리셋하는 정책 등이 필요하다. 회전 각도와 색 공간을 위치처럼 무조건 선형 혼합하지 않는다. 보간을 켰다는 사실은 충돌 정확성·입력 지연 0·실제 부드러움 시험의 증거가 아니다.

중간 과정을 따라가는 예제

이전 소단원과 같은 h=0.02초/v=2 모형에서 dt0.015/0.025/0.010을 적용한다. prev/current를 보존하고 셋째 프레임의 α와 표시 위치·시각을 구하라.

  1. 첫 프레임은 tick이 없으므로 prev=current=0,α=0.015/0.02=0.75이며 시작 위치 0을 표시한다.

  2. 둘째 프레임의 첫 tick은 prev=0/current0.04, 둘째 tick은 prev=0.04/current0.08을 만든다. a=0이므로 α=0, 표시 0.04다.

  3. 셋째는 tick이 없고 a=0.01이다. α=0.5이므로 표시 0.04+0.5·(0.08−0.04)=0.06이다. 현재 규칙 위치 0.08은 바꾸지 않는다.

  4. 현재 tick시각 0.04초와 prev시각 0.02초 사이의 표시시각은 0.03초다. 받아들인 0.05초보다 h=0.02초 과거이며 상수속도 2에서는 2·0.03=0.06이다.

셋째 α=0.5, 표시 위치 0.06, 규칙 위치 0.08이다. 미래 위치 0.10의 예측과 구별한다.

힌트 보기

α를 먼저 구하고 두 위치 차이에 곱한다. 중간값이 실제 이동 경로인지 별도로 판단한다.

풀이 보기

α=0.2, 표시 10+20·0.2=14다. 순간이동의 중간 50은 실제로 방문한 위치라는 보장이 없으므로 전환용 리셋 등 정책이 필요하다. 실제 화면을 그리지 않았다.

오해와 반례

보간 화면의 위치가 곧 최신 시뮬레이션 상태이며 지연은 없다.

예제 표시 0.06은 현재 0.08과 다르다. 해당 정책은 한 tick 과거를 표시하므로 표시의 연속성과 최신성 사이 선택이 생긴다.

한 단계 더

심화: 실수 직선에서 0≤α≤1이면 보간값은 prev와 current 사이에 있다. 두 위치 중 작은 값 m과 큰 값 M에 대해 각각 m≤prev,current≤M이고 비음수 가중치의 합이 1이므로 m≤(1−α)prev+αcurrent≤M이다. 이 볼록성은 순간이동 구간의 모든 중간점이 게임에서 유효하다는 보장은 아니다. 허용 위치 집합이{0,100}이면 α=0.5의 50은 집합 밖이다. 논리적 유효성과 산술상 두 끝 사이임을 분리한다.
