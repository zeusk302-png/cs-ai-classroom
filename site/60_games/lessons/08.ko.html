소단원 8.1

sprite·atlas

여러 동작 그림을 한 이미지에 모으면 어떤 좌표를 잘라야 할까?

준비 개념과 학습 목표

준비 개념

  • sprite 는 장면에 그리는 2D 그림 단위다.

  • atlas 는 여러 그림 영역을 한 이미지에 배치한 자료다.

학습 목표

  • 원본 영역과 화면 영역을 분리한다.

  • 격자 인덱스에서 자르기 좌표를 계산한다.

두 사각형을 따로 적는다

원본 이미지의 어느 부분을 읽을지와 화면의 어디에 얼마나 크게 그릴지는 다른 사각형이다. Canvas drawImage 의 9 인자 형태는 원본 sx,sy,sWidth,sHeight 와 표시 dx,dy,dWidth,dHeight 를 따로 받는다.

원본 32×32 영역을 화면 64×64 로 그리면 가로·세로가 각각 2 배다. 그림 자료가 더 자세해진 것이 아니라 기존 영역을 확대하는 것이다. 자르기 기준은 원본 고유 크기를 쓰며 HTML 표시 크기와 혼동하지 않는다.

격자 번호를 행과 열로 바꾼다

폭 128, 높이 64 이미지에 32×32 칸이 빈틈 없이 놓였다고 가정한다. 한 행은 4 칸, 총 8 칸이며 번호는 왼쪽 위부터 행 우선으로 0~7 이다. 번호 k 의 열은 k mod 4, 행은 floor(k/4)다.

실제 atlas 는 padding·회전·trim 이 있을 수 있어 이 공식만으로 읽으면 틀릴 수 있다. 그런 자료는 각 영역과 원래 기준점의 메타데이터를 사용한다. 이 단원 계산은 회전·공백·잘라낸 가장자리 없는 자체 격자로 한정한다.

그림 기준점과 경계를 확인한다

같은 캐릭터의 프레임마다 발이 놓일 기준점이 다르면 그림 중심을 같은 곳에 그려도 발이 흔들릴 수 있다. 프레임의 크기와 기준점을 함께 관리하면 장면 위치와 그림 영역을 분리할 수 있다.

음수 표시 폭을 넣으면 자동으로 좌우 반전된다고 추정하지 않는다. drawImage 의 음수 크기 규약과 좌표계 scale(-1,1)의 반전은 다르다. 필터링·이웃 영역 누출은 다른 조건이며 atlas 하나가 모든 성능 문제를 자동 해결하지 않는다.

중간 과정을 따라가는 예제

자체 128×64 atlas 의 32×32 격자에서 k=6 을 골라 화면 (10,20)의 64×64 사각형에 표시한다. 원본 사각형과 확대 배율을 구하라.

  1. 열=6 mod 4=2, 행=floor(6/4)=1 이다.

  2. sx=2×32=64, sy=1×32=32 이며 원본 영역은 (64,32,32,32)다.

  3. 표시 영역은 (10,20,64,64)이며 가로·세로 배율은 각각 64/32=2 다.

교육용 호출 인자는 drawImage(image,64,32,32,32,10,20,64,64)다. 원본 오른쪽 128 이 아니라 96 까지 읽으며 아래쪽은 64 다.

종이와 본문으로 직접 해보기

k=3 과 7 의 원본 영역을 계산하고 k=8 이 유효한지 확인하라. 모든 경계는 오른쪽/아래 끝을 포함하지 않는 사각형으로 생각한다.

힌트 보기

3 은 첫 행 마지막, 7 은 둘째 행 마지막이다.

풀이 보기

3:(96,0,32,32), 7:(96,32,32,32)이며 오른쪽끝 128/아래끝 64 이내다. 8 은 세 번째 행 sy64 부터라 이 격자의 유효 번호 0~7 밖이다.

오해와 반례

atlas 의 번호만 알면 모든 파일을 같은 식으로 자를 수 있다.

빈틈 없는 32 칸 규약과 실제 자료의 공백·회전·trim 이 다르면 인덱스 식이 성립하지 않는다. 영역 메타데이터와 기준점을 확인한다.

자기점검

번호 6 의 열은?

답과 이유 보기

2 다.

6 을 4 로 나눈 나머지다.

번호 6 의 sy 는?

답과 이유 보기

32 다.

행 1 에 칸높이 32 를 곱한다.

음수 dWidth 는 자동 좌우 반전인가?

답과 이유 보기

이 API 에서는 아니다.

음수 크기와 좌표계 반전을 같은 연산으로 취급하면 안 된다.

한 단계 더

각 칸 사이에 2 픽셀 간격이 있다면 sx=열×(칸폭+간격) 식이 어떻게 바뀌는지 도출하라. 이미지 전체 폭과 유효 칸 수를 다시 정한 뒤 계산하며 기존 128 폭을 동시에 유지한다고 가정하지 않는다.

소단원 8.2

카메라와 layer

카메라를 오른쪽으로 옮기면 화면 속 나무도 오른쪽으로 갈까?

준비 개념과 학습 목표

준비 개념

  • 월드 좌표는 장면 위치, 화면 좌표는 화면에 그리는 위치다.

  • layer 는 그림을 묶어 그리는 순서를 정하는 층이다.

학습 목표

  • 카메라 이동과 확대를 좌표식으로 계산한다.

  • 그리기 순서와 UI 고정 조건을 구별한다.

관찰 위치를 빼고 표시 배율을 곱한다

회전 없는 자체 모형에서 카메라의 월드 위치 c 를 화면의 기준점 o 에 놓고 배율 z>0 을 사용한다. 월드점 w 의 화면점은 s=o+z(w−c)다. 각 x,y 성분을 별도로 계산한다.

카메라 c 만 오른쪽으로 증가하면 고정 월드점의 w−c 는 감소해 화면에서는 왼쪽으로 움직인다. 입력 화면점을 월드로 바꿀 때는 w=c+(s−o)/z 를 쓴다. 그림의 실제 물리 위치를 카메라 표시 때문에 바꿀 필요는 없다.

뒤 그림부터 앞 그림까지 순서를 정한다

불투명 그림이 겹치면 먼저 그린 그림을 나중 그림이 가린다. 자체 layer 규약을 배경 0·캐릭터 1·전경 2·UI3 의 오름차순으로 정하면 UI 를 마지막에 그린다. 같은 층의 순서는 별도 안정 규약이 필요하다.

이 순서는 게임 엔진마다 기본값이 같다는 주장이 아니다. 투명 혼합과 깊이 검사 규약은 추가로 확인해야 한다. 작은 종이 겹침에서는 불투명한 카드의 마지막 그림을 확인해 순서 효과를 설명한다.

UI 와 배경은 같은 카메라를 쓸 필요가 없다

점수 UI 를 화면 (8,8)에 고정하려면 월드 카메라 변환을 적용한 뒤 그대로 그리지 않는다. Canvas 에서 카메라용 상태를 save 하고 변환한 뒤 월드 그림을 그려 restore 한 후 기본 좌표로 UI 를 그릴 수 있다.

배경의 카메라 이동 효과를 작게 하는 parallax 는 자체 규약에서 s=o+z(w−p c)로 나타낼 수 있다. p=1 은 일반 월드, p=0 은 카메라 이동에 반응하지 않는다. 배경에 필요한 현상만 표현하는 표시식이며 물리 법칙이 아니다.

중간 과정을 따라가는 예제

월드 나무 w=(130,70), 카메라 c=(100,50), 화면 기준 o=(200,100), 배율 z=2 다. 화면 좌표와 카메라만 (110,50)로 바꾼 좌표를 구하라.

  1. 첫 차이는 w−c=(30,20), 2 배하면(60,40)다.

  2. o 를 더해 화면(260,140)이다.

  3. 새 차이(20,20)를 2 배하고 o 를 더하면(240,140), x 는 20 감소한다.

나무는 화면(260,140)→(240,140)로 왼쪽 20 이동한다. 월드 좌표는 그대로다.

종이와 본문으로 직접 해보기

처음 카메라 조건에서 화면(260,140)을 역변환하고, 카메라 x 가 10 증가할 때 p=.5 배경의 x 변화와 UI(8,8)의 변화도 구하라.

힌트 보기

역변환은 배율로 나눈다. parallax 의 카메라 변화는 −z p Δc 다.

풀이 보기

월드=(100,50)+(60,40)/2=(130,70)다. 배경Δsx=−2×.5×10=−10 이다. 카메라 변환을 적용하지 않는 UI 는(8,8) 그대로다.

오해와 반례

카메라 이동은 모든 물체의 월드 위치를 바꾸는 일이다.

고정 나무의 화면은 달라져도 월드 w 는 같다. 점수 UI 에 월드 변환을 적용하지 않으면 카메라 이동과 무관하게 고정할 수 있다.

자기점검

첫 화면 x 는?

답과 이유 보기

260 이다.

200+2×(130−100)이다.

배경 0/캐릭터 1/UI3 은 어떤 순서인가?

답과 이유 보기

0,1,3 이다.

자체 오름차순 layer 규약이다.

restore 는 그림 픽셀을 지우나?

답과 이유 보기

아니다.

여기서는 저장된 변환·스타일 상태를 되돌리는 연산이다.

한 단계 더

translate 와 scale 의 적용 순서를 바꾸면 같은 숫자라도 좌표가 달라질 수 있다. 이 단원의 명시식과 실제 변환 행렬을 대조하고, 화면 선택 입력에는 같은 카메라의 역변환을 써야 함을 설명한다.

소단원 8.3

프레임·시간 애니메이션

120Hz 화면에서 같은 걷기 동작이 두 배 빨라지면 무엇이 잘못됐을까?

준비 개념과 학습 목표

준비 개념

  • 애니메이션 프레임은 동작 그림의 번호이고 표시 프레임은 화면 갱신 기회다.

  • 밀리초 1000 이 1 초이며 주기를 시간으로 정할 수 있다.

학습 목표

  • 시간으로 동작 프레임을 선택한다.

  • 누적 시간의 나머지와 일시정지 규약을 설명한다.

갱신 횟수 대신 경과 시간을 사용한다

그림 4 장을 각 100ms 보여 주는 반복 동작의 주기는 400ms 다. 시작부터 경과시간 t≥0 에서 번호는 floor(t/100) mod4 다. 구간[0,100)은 0,[100,200)은 1 이며 경계의 포함 방향을 명시한다.

표시 콜백마다 번호를 한 칸 올리면 60Hz 와 120Hz 에서 동작 속도가 달라진다. requestAnimationFrame 은 보통 표시 주기를 따르며 한 번 요청한 콜백이므로 다음 갱신도 다시 요청한다. 시간 인자를 이용하면 동작 시간과 갱신 기회를 분리할 수 있다.

큰 시간 간격은 여러 경계를 넘는다

이전 누적값에 새 dt 를 더한 뒤 100ms 를 넘을 때마다 번호를 증가시키고 100 을 뺀다. if 한 번만 사용하면 dt 가 250ms 일 때 넘어간 두 경계를 제대로 처리하지 못한다.

남은 누적값은 다음 그림으로 넘어가기까지 이미 지난 시간이다. 아래 예제는 그리기 그림 선택만 다루며 각 중간 번호를 실제 화면에 표시해야 한다는 뜻은 아니다. 프레임마다 소리/피해 이벤트를 실행한다면 건너뛴 이벤트 처리 규약도 따로 설계한다.

정지 중 시간을 포함할지 정한다

배경 탭에서는 콜백이 멈출 수 있다. 돌아왔을 때 시작 시각부터의 절대 경과시간으로 동작을 맞추는 정책과 정지 기간을 빼는 정책은 다르다. 어느 것이 맞는지는 게임의 시간 계약으로 정한다.

dt 를 임의로 작게 제한하면 긴 정지 뒤 갑작스러운 이동을 줄일 수 있지만 실제 경과시간을 버리는 효과도 있다. 충돌 물리 적분·동작 그림·실제 시계가 같은 목표를 갖는다고 가정하지 않는다. 여기서는 정지 없는 가상 시간표만 계산한다.

중간 과정을 따라가는 예제

번호 0·누적 0 으로 시작한다. 프레임 길이 100ms, 번호 4 개 반복이며 dt=[60,60,250]ms 다. 각 dt 를 더하고 while 누적>=100 이면 누적에서 100 을 빼며 번호=(번호+1) mod4 로 갱신한다.

  1. 첫 60: 누적 60<100 이라 번호 0/누적 60 이다.

  2. 둘째 60: 누적 120 에서 한 번 갱신하여 번호 1/누적 20 이다.

  3. 셋째 250: 누적 270 에서 두 번 갱신하여 번호 3/누적 70 이다. 총시간 370 의 직접식 floor(3.7) mod4=3 과 같다.

세 갱신 뒤 상태는(0,60),(1,20),(3,70)이다. 마지막에는 경계 두 개를 넘는다.

종이와 본문으로 직접 해보기

같은 마지막 상태에 dt=50 을 추가하고, 직접식으로 t=399,400,450ms 의 번호를 계산하라.

힌트 보기

번호 3 뒤는 0 으로 돌아가며 정확 400 은 새 주기의 시작이다.

풀이 보기

누적 70+50=120 에서 한 번 갱신하여 번호 0/누적 20, 총시간 420 이다. t399→3,t400→0,t450→0 이다.

오해와 반례

표시 갱신마다 다음 그림을 한 번씩 고르면 모든 화면에서 같은 속도다.

그림 4 개를 매 콜백 한 장씩 바꾸면 60Hz 에서 약 66.7ms,120Hz 에서 약 33.3ms 마다 한 주기가 된다. 시간 기준의 400ms 계약과 다르다.

한 단계 더

반복하지 않는 4 그림 동작은 min(floor(t/100),3)으로 마지막 그림을 유지할 수 있다. 완료 이벤트를 400ms 에 낼지 마지막 그림 진입 300ms 에 낼지 정하고 재호출에도 이벤트가 중복되지 않는 조건을 설계한다.
