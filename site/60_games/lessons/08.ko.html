소단원 8.1

sprite·atlas

여러 동작 그림을 한 이미지에 모으면 어떤 좌표를 잘라야 할까?

준비 개념과 학습 목표

준비 개념

  • sprite 는 장면에 그리는 2D 그림 단위다.

  • atlas 는 여러 그림 영역을 한 이미지에 배치한 자료다.

학습 목표

  • 원본 영역과 화면 영역을 분리한다.

  • 격자 인덱스에서 자르기 좌표를 계산한다.

투명한 가장자리를 잘라냈는데 발 위치도 함께 움직여야 할까요?

앞 본문은 빈틈 없는 격자의 원본 사각형을 계산했습니다. 새 자체 격자는 칸 폭 24 px, 높이 30 px, 가로 세 칸과 세로 두 칸, 칸 사이 간격 2 px, 바깥 여백 1 px입니다. 전체 고유 크기는 78×64 px입니다. 번호 k는 0부터 5까지이며 열은 k mod 3, 행은 floor(k/3)입니다. 원본 시작은 sx=1+26×열, sy=1+32×행입니다. 표시 배율은 이 원본 좌표를 바꾸지 않습니다.

별도 trim 모형은 회전 없이 투명 가장자리만 제거합니다. 원래 그림의 논리 크기는 40×50 px이고 발 기준점은 원래 좌표 q=(20,45)입니다. 저장된 조각의 원래 그림 안 위치를 r, 조각 크기를 (폭,높이)로 둡니다. 표시할 발 위치 P와 양의 배율 z가 주어지면 조각의 화면 왼쪽 위는 P+z(r−q)입니다. trim 뒤 조각 중심을 새로운 발 기준으로 삼으면 프레임마다 흔들립니다.

좌우 반전은 발 기준의 가로 차이를 부호 반전하는 자체 표시 변환입니다. 원래 x 구간 [rx,rx+폭)이 발의 qx에 대해 반전되면 화면 왼쪽 끝은 Px+z(qx−rx−폭)입니다. 이것을 음수 drawImage 폭의 자동 반전이라고 설명하지 않습니다. 반전·trim·padding 메타데이터가 원본 접근과 화면 배치를 각각 정합니다.

먼저 확인할 개념
  • sprite·atlas

    고유 원본 크기·자르기 사각형과 표시 사각형을 먼저 구별합니다.

  • 카메라와 layer

    그림의 기준점 위치를 화면 변환과 별도로 다룹니다.

두 사각형을 따로 적는다

원본 이미지의 어느 부분을 읽을지와 화면의 어디에 얼마나 크게 그릴지는 다른 사각형이다. Canvas drawImage 의 9 인자 형태는 원본 sx,sy,sWidth,sHeight 와 표시 dx,dy,dWidth,dHeight 를 따로 받는다.

원본 32×32 영역을 화면 64×64 로 그리면 가로·세로가 각각 2 배다. 그림 자료가 더 자세해진 것이 아니라 기존 영역을 확대하는 것이다. 자르기 기준은 원본 고유 크기를 쓰며 HTML 표시 크기와 혼동하지 않는다.

격자 번호를 행과 열로 바꾼다

폭 128, 높이 64 이미지에 32×32 칸이 빈틈 없이 놓였다고 가정한다. 한 행은 4 칸, 총 8 칸이며 번호는 왼쪽 위부터 행 우선으로 0~7 이다. 번호 k 의 열은 k mod 4, 행은 floor(k/4)다.

실제 atlas 는 padding·회전·trim 이 있을 수 있어 이 공식만으로 읽으면 틀릴 수 있다. 그런 자료는 각 영역과 원래 기준점의 메타데이터를 사용한다. 이 단원 계산은 회전·공백·잘라낸 가장자리 없는 자체 격자로 한정한다.

그림 기준점과 경계를 확인한다

같은 캐릭터의 프레임마다 발이 놓일 기준점이 다르면 그림 중심을 같은 곳에 그려도 발이 흔들릴 수 있다. 프레임의 크기와 기준점을 함께 관리하면 장면 위치와 그림 영역을 분리할 수 있다.

음수 표시 폭을 넣으면 자동으로 좌우 반전된다고 추정하지 않는다. drawImage 의 음수 크기 규약과 좌표계 scale(-1,1)의 반전은 다르다. 필터링·이웃 영역 누출은 다른 조건이며 atlas 하나가 모든 성능 문제를 자동 해결하지 않는다.

첫 행은 atlas 원본 좌표이고 뒤 두 행은 별도 조각의 화면 좌표입니다. 두 자료의 좌표를 한 파일의 위치처럼 합치지 않습니다. 모든 오른쪽·아래 끝은 제외합니다.

중간 과정을 따라가는 예제

자체 128×64 atlas 의 32×32 격자에서 k=6 을 골라 화면 (10,20)의 64×64 사각형에 표시한다. 원본 사각형과 확대 배율을 구하라.

  1. 열=6 mod 4=2, 행=floor(6/4)=1 이다.

  2. sx=2×32=64, sy=1×32=32 이며 원본 영역은 (64,32,32,32)다.

  3. 표시 영역은 (10,20,64,64)이며 가로·세로 배율은 각각 64/32=2 다.

교육용 호출 인자는 drawImage(image,64,32,32,32,10,20,64,64)다. 원본 오른쪽 128 이 아니라 96 까지 읽으며 아래쪽은 64 다.

조건을 바꾸어 비교하기

여백과 간격을 포함한 자르기

새 78×64 px 격자에서 번호 4의 사각형과 오른쪽·아래 끝을 구하세요.

  1. 열은 1, 행도 1입니다.

  2. sx는 27 px, sy는 33 px입니다.

  3. 끝은 오른쪽 51 px, 아래 63 px이며 바깥 여백 안에 들어갑니다.

원본 (27,33,24,30)입니다.

비교할 점

앞 본문의 32 px 빈틈 없는 격자 식을 그대로 적용하면 다른 영역을 읽습니다.

trim 조각을 발 위치에 맞추기

논리 크기 40×50 px, 발 q=(20,45), 조각 r=(6,15), 크기 24×30 px입니다. P=(200,100), z=2에서 일반 표시와 반전을 구하세요.

  1. 일반 왼쪽 위는 (200,100)+2×((6,15)−(20,45))=(172,40)입니다.

  2. 가로 반전의 왼쪽 끝은 200+2×(20−6−24)=180 px입니다.

  3. 두 표시 모두 크기는 48×60 px이고 논리 발은 (200,100)에 유지합니다.

일반 왼쪽 위는 (172,40), 반전은 (180,40)입니다.

비교할 점

조각 중심이 논리 발이라는 새 가정을 추가하지 않습니다.

종이와 본문으로 직접 해보기

k=3 과 7 의 원본 영역을 계산하고 k=8 이 유효한지 확인하라. 모든 경계는 오른쪽/아래 끝을 포함하지 않는 사각형으로 생각한다.

힌트 보기

3 은 첫 행 마지막, 7 은 둘째 행 마지막이다.

풀이 보기

3:(96,0,32,32), 7:(96,32,32,32)이며 오른쪽끝 128/아래끝 64 이내다. 8 은 세 번째 행 sy64 부터라 이 격자의 유효 번호 0~7 밖이다.

오해와 반례

atlas 의 번호만 알면 모든 파일을 같은 식으로 자를 수 있다.

빈틈 없는 32 칸 규약과 실제 자료의 공백·회전·trim 이 다르면 인덱스 식이 성립하지 않는다. 영역 메타데이터와 기준점을 확인한다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

새 여백 격자에서 번호 5와 번호 6의 유효성을 판단하고 번호 5의 원본 영역을 구하세요.

힌트 1

번호 범위는 0부터 5입니다.

힌트 2

열과 행에 서로 다른 간격 포함 크기를 곱합니다.

풀이와 답 확인

  1. 번호 5는 열 2, 행 1이어서 원본 (53,33,24,30)입니다.

  2. 오른쪽 끝은 77 px, 아래 끝은 63 px입니다. 번호 6은 세 번째 행이므로 거절합니다.

5는 유효하고 6은 범위 밖입니다.

흔한 오답에서 다시 생각하기

전체 폭 78이므로 sx=78인 번호도 한 칸이다.

시작점이 경계에 있다는 것과 양의 폭을 가진 영역이 내부라는 것은 다릅니다.

연습 2 · 오류 찾아 고치기

별도 trim A를 P=(200,100), z=2에서 조각의 아래 중앙을 발이라고 간주하여 (176,40)에 그렸습니다. 논리 발의 실제 화면 위치와 수정 좌표를 구하세요.

힌트 1

조각 안의 논리 발은 q−r=(14,30)입니다.

힌트 2

조각 아래 중앙의 x는 12 px입니다.

풀이와 답 확인

  1. 잘못된 표시에서 발은 (176,40)+2×(14,30)=(204,100)입니다.

  2. 올바른 왼쪽 위는 (172,40)이므로 발이 (200,100)에 놓입니다.

가로 4 px 흔들림을 원래 발 메타데이터로 고칩니다.

흔한 오답에서 다시 생각하기

trim 조각의 크기만 알면 발 위치도 자동 복원된다.

원래 크기와 offset 및 기준점이 필요합니다. 크기만으로 잃은 위치를 복원하지 못합니다.

연습 3 · 직접 만들어 보기

trim B는 같은 논리 크기와 발 q를 사용하지만 r=(12,10), 크기 18×35 px입니다. 같은 P와 z에서 표시할 왼쪽 위와 크기, 발 위치를 쓰세요.

힌트 1

r−q를 배율로 확대합니다.

힌트 2

발은 조각 안에서 (8,35)입니다.

풀이와 답 확인

  1. 왼쪽 위는 (184,30), 표시 크기는 36×70 px입니다.

  2. 발은 (184,30)+2×(8,35)=(200,100)입니다.

A와 B의 조각 크기는 달라도 논리 발 위치는 같습니다.

흔한 오답에서 다시 생각하기

두 조각 왼쪽 위를 같게 해야 발이 같다.

원래 그림 안의 offset이 다르므로 왼쪽 위가 달라야 기준점이 같습니다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

별도 논리 폭 40 px의 그림에서 발 qx=20, 조각 rx=6, 폭 24 px입니다. 배율 2와 Px=200에서 반전한 원래 점 x=6 및 x=30의 화면 x를 구해 구간 방향을 설명하세요.

힌트 1

점 변환은 s=200−2×(x−20)입니다.

힌트 2

영역의 왼쪽 끝은 두 끝 좌표의 작은 값입니다.

풀이와 답 확인

  1. x=6은 228 px, x=30은 180 px입니다.

  2. 구간 방향이 뒤집혀 왼쪽 끝 180 px, 폭 48 px입니다. 실제 래스터의 끝 포함 규약은 별도이며 여기서는 기하 경계만 계산합니다.

반전은 점 순서를 바꾸며 음수 drawImage 폭과 다른 변환입니다.

흔한 오답에서 다시 생각하기

음수 dWidth를 넣으면 같은 반전 결과가 보장된다.

MDN의 해당 크기 규약은 그림을 자동 뒤집지 않습니다. 좌표 변환을 명시해야 합니다.

원본 위치와 발 위치는 왜 따로 두나요?

설명 기준 확인

trim·padding은 자료 배치이고 발 위치는 장면에 놓는 기준입니다.

두 atlas가 같은 번호를 가지면 같은 좌표인가요?

설명 기준 확인

칸 크기·간격·여백·메타데이터가 같아야 같은 식을 적용합니다.

한 단계 더

각 칸 사이에 2 픽셀 간격이 있다면 sx=열×(칸폭+간격) 식이 어떻게 바뀌는지 도출하라. 이미지 전체 폭과 유효 칸 수를 다시 정한 뒤 계산하며 기존 128 폭을 동시에 유지한다고 가정하지 않는다.

카메라와 layer

카메라를 오른쪽으로 옮기면 화면 속 나무도 오른쪽으로 갈까?

준비 개념과 학습 목표

준비 개념

  • 월드 좌표는 장면 위치, 화면 좌표는 화면에 그리는 위치다.

  • layer 는 그림을 묶어 그리는 순서를 정하는 층이다.

학습 목표

  • 카메라 이동과 확대를 좌표식으로 계산한다.

  • 그리기 순서와 UI 고정 조건을 구별한다.

줌을 바꾸면서 마우스 아래의 월드점을 그대로 유지할 수 있을까요?

앞 본문의 회전 없는 카메라 s=o+z(w−c)를 유지합니다. 화면 입력 m 아래의 월드점은 w*=c+(m−o)/z입니다. 배율을 양의 z새로 바꿀 때 같은 점을 m에 유지하려면 c새=w*−(m−o)/z새로 정합니다. 단순히 z만 바꾸면 관찰 기준점 o 외의 월드점이 움직입니다.

Canvas 변환을 기본 상태에서 시작한다고 가정합니다. translate(o), scale(z), translate(−c)의 순서면 점에 카메라 이동을 먼저 적용한 뒤 확대하고 화면 기준점을 더합니다. 호출을 scale(z), translate(o−c)로 바꾸면 화면 기준점까지 확대되어 같은 식이 아닙니다. 이전 변환이 남아 있는지와 save/restore 쌍도 확인해야 합니다.

표시 순서와 입력 선택 순서도 별도 계약입니다. 새 불투명 카드 A/B가 같은 layer에서 완전히 겹치고 삽입 순서가 A 뒤 B라면 안정 그리기에서 B가 위입니다. 보이는 카드를 선택하는 자체 정책은 실제 그리기 순서의 역순으로 검사합니다. 임의 ID 순서는 표시와 입력의 불일치를 만들 수 있습니다. 투명 픽셀이나 복잡한 모양의 선택은 이 사각형 정책 밖입니다.

    명시 카메라 식·역변환과 자체 layer 순서를 이어 사용합니다.

  • sprite·atlas

    그림 기준점과 표시 영역을 입력 위치와 구별합니다.

관찰 위치를 빼고 표시 배율을 곱한다

회전 없는 자체 모형에서 카메라의 월드 위치 c 를 화면의 기준점 o 에 놓고 배율 z>0 을 사용한다. 월드점 w 의 화면점은 s=o+z(w−c)다. 각 x,y 성분을 별도로 계산한다.

카메라 c 만 오른쪽으로 증가하면 고정 월드점의 w−c 는 감소해 화면에서는 왼쪽으로 움직인다. 입력 화면점을 월드로 바꿀 때는 w=c+(s−o)/z 를 쓴다. 그림의 실제 물리 위치를 카메라 표시 때문에 바꿀 필요는 없다.

뒤 그림부터 앞 그림까지 순서를 정한다

불투명 그림이 겹치면 먼저 그린 그림을 나중 그림이 가린다. 자체 layer 규약을 배경 0·캐릭터 1·전경 2·UI3 의 오름차순으로 정하면 UI 를 마지막에 그린다. 같은 층의 순서는 별도 안정 규약이 필요하다.

이 순서는 게임 엔진마다 기본값이 같다는 주장이 아니다. 투명 혼합과 깊이 검사 규약은 추가로 확인해야 한다. 작은 종이 겹침에서는 불투명한 카드의 마지막 그림을 확인해 순서 효과를 설명한다.

UI 와 배경은 같은 카메라를 쓸 필요가 없다

점수 UI 를 화면 (8,8)에 고정하려면 월드 카메라 변환을 적용한 뒤 그대로 그리지 않는다. Canvas 에서 카메라용 상태를 save 하고 변환한 뒤 월드 그림을 그려 restore 한 후 기본 좌표로 UI 를 그릴 수 있다.

배경의 카메라 이동 효과를 작게 하는 parallax 는 자체 규약에서 s=o+z(w−p c)로 나타낼 수 있다. p=1 은 일반 월드, p=0 은 카메라 이동에 반응하지 않는다. 배경에 필요한 현상만 표현하는 표시식이며 물리 법칙이 아니다.

프레임·시간 애니메이션

120Hz 화면에서 같은 걷기 동작이 두 배 빨라지면 무엇이 잘못됐을까?

준비 개념과 학습 목표

준비 개념

  • 애니메이션 프레임은 동작 그림의 번호이고 표시 프레임은 화면 갱신 기회다.

  • 밀리초 1000 이 1 초이며 주기를 시간으로 정할 수 있다.

학습 목표

  • 시간으로 동작 프레임을 선택한다.

  • 누적 시간의 나머지와 일시정지 규약을 설명한다.

처음과 마지막 그림 번호가 같으면 중간 동작 이벤트도 없었을까요?

앞 본문은 같은 길이 네 그림의 반복 인덱스를 계산했습니다. 새 자체 동작은 세 그림을 각각 80 ms, 120 ms, 50 ms 보여 줍니다. 한 주기는 250 ms입니다. 누적 활성 시간 t≥0의 위상 r=t mod 250에서 [0,80)은 그림 0, [80,200)은 그림 1, [200,250)은 그림 2입니다. floor(t/100) 같은 일정 길이 식을 재사용하지 않습니다.

표시 그림과 경계 진입 이벤트를 나눕니다. 새 계약은 이전 시간 old와 새 시간 new가 단조이고, 이벤트는 (old,new]에 들어가는 모든 경계에서 발생합니다. 그림 1 진입은 80+250k, 그림 2 진입은 200+250k, 그림 0의 다음 주기 진입은 250+250k이며 k는 음수가 아닌 정수입니다. 초기 그림 0의 별도 시작 이벤트는 이 경계 목록에 넣지 않습니다. 각 경계에 안정된 식별값을 붙여 같은 new의 재처리에 중복시키지 않습니다.

활성 시간은 일시정지 기간을 빼는 자체 정책과 시계 전체 기간을 포함하는 정책에서 다릅니다. 예를 들어 70 ms에서 500 ms 정지했다가 돌아오면 전체 시계 정책의 시간은 570 ms, 정지 제외 정책은 70 ms입니다. 두 그림은 모두 0일 수 있지만 지나간 경계 수는 다릅니다. requestAnimationFrame의 재요청·같은 표시의 공통 timestamp는 게임 이벤트의 수명이나 정확히 한 번 저장을 자동 보장하지 않습니다.

갱신 횟수 대신 경과 시간을 사용한다

그림 4 장을 각 100ms 보여 주는 반복 동작의 주기는 400ms 다. 시작부터 경과시간 t≥0 에서 번호는 floor(t/100) mod4 다. 구간[0,100)은 0,[100,200)은 1 이며 경계의 포함 방향을 명시한다.

표시 콜백마다 번호를 한 칸 올리면 60Hz 와 120Hz 에서 동작 속도가 달라진다. requestAnimationFrame 은 보통 표시 주기를 따르며 한 번 요청한 콜백이므로 다음 갱신도 다시 요청한다. 시간 인자를 이용하면 동작 시간과 갱신 기회를 분리할 수 있다.

큰 시간 간격은 여러 경계를 넘는다

이전 누적값에 새 dt 를 더한 뒤 100ms 를 넘을 때마다 번호를 증가시키고 100 을 뺀다. if 한 번만 사용하면 dt 가 250ms 일 때 넘어간 두 경계를 제대로 처리하지 못한다.

남은 누적값은 다음 그림으로 넘어가기까지 이미 지난 시간이다. 아래 예제는 그리기 그림 선택만 다루며 각 중간 번호를 실제 화면에 표시해야 한다는 뜻은 아니다. 프레임마다 소리/피해 이벤트를 실행한다면 건너뛴 이벤트 처리 규약도 따로 설계한다.

정지 중 시간을 포함할지 정한다

배경 탭에서는 콜백이 멈출 수 있다. 돌아왔을 때 시작 시각부터의 절대 경과시간으로 동작을 맞추는 정책과 정지 기간을 빼는 정책은 다르다. 어느 것이 맞는지는 게임의 시간 계약으로 정한다.

dt 를 임의로 작게 제한하면 긴 정지 뒤 갑작스러운 이동을 줄일 수 있지만 실제 경과시간을 버리는 효과도 있다. 충돌 물리 적분·동작 그림·실제 시계가 같은 목표를 갖는다고 가정하지 않는다. 여기서는 정지 없는 가상 시간표만 계산한다.

중간 과정을 따라가는 예제

번호 0·누적 0 으로 시작한다. 프레임 길이 100ms, 번호 4 개 반복이며 dt=[60,60,250]ms 다. 각 dt 를 더하고 while 누적>=100 이면 누적에서 100 을 빼며 번호=(번호+1) mod4 로 갱신한다.

  1. 첫 60: 누적 60<100 이라 번호 0/누적 60 이다.

  2. 둘째 60: 누적 120 에서 한 번 갱신하여 번호 1/누적 20 이다.

  3. 셋째 250: 누적 270 에서 두 번 갱신하여 번호 3/누적 70 이다. 총시간 370 의 직접식 floor(3.7) mod4=3 과 같다.

세 갱신 뒤 상태는(0,60),(1,20),(3,70)이다. 마지막에는 경계 두 개를 넘는다.
