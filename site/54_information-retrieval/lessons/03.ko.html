소단원 3.1

dictionary와 posting

많은 문서를 매번 읽지 않고 “별”이 있는 문서만 어떻게 찾을까?

준비 개념과 학습 목표

준비 개념

  • 문서마다 서로 다른 정수 docID를 붙인다. 이 단원은 문서1..4로 고정한다.

  • 토큰은 정해진 분할 규칙으로 만든 단위다. 여기서는 공백으로 구분한 완성된 단어를 그대로 쓴다.

  • 집합에는 같은 원소가 한 번만 들어간다. 리스트에는 순서와 반복이 있을 수 있다.

학습 목표

  • 토큰 발생 횟수와 문서 빈도를 구별한다.

  • 작은 문서 모음으로 dictionary와 정렬 posting을 직접 구성한다.

서로 다른 조각의 문서번호 1은 같은 문서일까?

새 가상 색인 조각 A는 지역 문서번호 1에 sun, 2에 moon을 저장한다. 조각 B는 지역 번호 1에 moon, 2에 sun을 저장한다. 각 문서는 단어 한 개뿐이다. A의 1과 B의 1은 서로 다른 문서다. 조각 이름을 버리고 sun의 지역 번호 {1,2}, moon의 지역 번호 {1,2}를 합치면 AND가 {1,2}처럼 보이지만 원래 네 문서 어디에도 두 단어가 함께 있지 않다.

올바른 합치기 계약의 하나로 전역 번호 A1→10, A2→20, B1→30, B2→40을 지정한다. 그러면 sun의 목록은 [10,40], moon은 [20,30]이고 AND는 빈 목록이다. 숫자를 새로 붙이는 것은 단어 의미를 바꾸는 것이 아니라 문서의 정체성을 보존하는 과정이다. 목록을 전역 번호 순으로 다시 정렬하고 df도 그 전역 ID의 서로 다른 문서 수로 계산한다.

df만 일치한다고 잘 합쳐졌다는 뜻은 아니다. 잘못 합친 지역 번호 목록도 sun과 moon의 길이가 각각 2여서 올바른 df와 우연히 같다. 그러나 문서 정체성이 뒤섞여 교집합이 잘못된다. 따라서 검사에는 목록 길이 외에 어느 원문 문서가 각 ID에 대응하는지, 조각·문서 버전이 같은지 포함해야 한다. 실제 분산 색인·병합 프로그램은 실행하지 않았다.

먼저 확인할 개념
  • 전역 docID와 중복 없는 posting

    문서 정체성과 단어의 문서 빈도를 함께 확인한다.

  • 교집합의 같은 ID 조건

    두 목록의 같은 숫자가 정말 같은 문서를 가리키는지 검사한다.

문서에서 단어로 방향을 뒤집기

문서가 어떤 단어를 갖는지 적으면 정방향 목록이다. 역색인은 각 term을 열쇠로 두고 그 term을 갖는 문서들을 적는다. 사전 dictionary는 term에서 해당 posting 목록과 통계로 연결한다. posting은 하나의 문서 항목, posting list는 그 항목들을 모은 목록이다. 실제 구현은 문서 위치나 발생 횟수도 함께 저장할 수 있지만 이 첫 모형은 존재 여부만 저장한다.

문서1이 “별 달 별”이고 문서2가 “달 바다”라면 별의 발생은 문서1에서 두 번이다. 그래도 별을 포함한 문서 목록에는 docID1이 한 번만 들어간다. 별의 문서 빈도 df는1, 문서1 내부 term frequency tf는2다. 발생 횟수를 문서 빈도와 혼동하면 질의 계획과 통계의 의미가 달라진다.

구성할 때 유지할 약속

모든 정규화된 토큰 발생에서 (term,docID) 쌍을 만든 뒤 term과 docID 순서로 정렬한다. 같은 문서의 같은 term은 Boolean posting에서 하나로 합친다. 마지막으로 term별 목록을 사전에 연결한다. 여기의 사전은 한국어 단어 뜻 사전이 아니라 검색용 term lookup 구조다. 사전 자체의 구현이 항상 해시나 항상 트리라는 주장은 하지 않는다.

모든 posting은 같은 전역 docID 증가 순으로 중복 없이 저장한다. 사전의 df는 이 목록의 길이와 같다. 존재하지 않는 term의 목록은 빈 목록으로 취급한다. 문서를 삭제하거나 추가하면 목록과 통계도 갱신해야 하며, 옛 목록이 남은 상태에서 얻은 결과는 고정 문서 모음에 대한 약속과 다를 수 있다.

색인이 답하는 범위를 명시하기

“별”을 문자열의 일부로 찾는 것과 term 별의 존재를 찾는 것은 다르다. 공백 분할만 쓰면 “별빛”은 별과 다른 term이다. 대소문자·어간·유니코드·형태소 처리 규칙을 바꾸면 사전에 들어가는 단위도 바뀐다. 질의와 문서에 같은 규칙을 적용해야 의미가 일관된다. 이 단원은 문서와 질의가 이미 같은 정규화를 거쳤다고 가정한다.

색인 구축은 비용이 든다. 원문을 읽고 목록을 만들며 공간도 사용한다. 반복 질의 때 원문 전체를 읽는 일을 줄일 수 있지만 디스크 읽기·압축·사전 조회·결과 출력까지 무료가 되는 것은 아니다. Boolean posting만으로 단어 순서와 서로 가까운지는 알 수 없다. 다음 소단원은 존재 교집합을, 마지막 소단원은 위치를 다룬다.

전역 ID 열을 사용해 term별 목록을 구성한다. 서로 다른 조각의 지역 숫자를 같은 문서로 취급하지 않는다.

중간 과정을 따라가는 예제

문서1 “별 달 별”, 문서2 “달 바다”, 문서3 “별 바다”, 문서4 “구름”을 Boolean 역색인으로 만들고 별의 df와 문서1의 tf를 구하라.

  1. term별 발생 쌍은 별:(1,1,3), 달:(1,2), 바다:(2,3), 구름:(4)이다. 이 표의 숫자는 발생의 문서ID다.

  2. 별의 문서1 반복을 합쳐 별:[1,3]을 만든다. 달:[1,2], 바다:[2,3], 구름:[4]도 전역 ID 증가 순이다.

  3. 사전 df는 별2, 달2, 바다2, 구름1이다. 총 Boolean posting 수는2+2+2+1=7이다.

  4. 문서1에서 별 tf는2지만 전체 모음에서 별 df도 우연히2다. 값이 같아도 서로 다른 양을 세었다. 전체 토큰 발생 수8과 posting 수7을 구별한다.

dictionary는 네 term을 가리키며 posting 총7개다. 별 df2, 문서1 별 tf2는 별개의 정의다.

조건을 바꾸어 비교하기

숫자가 같은 서로 다른 문서

A1=sun, A2=moon, B1=moon, B2=sun을 지역 번호만 합쳤을 때의 오류를 계산하라.

  1. sun의 지역 숫자는 A1의 1과 B2의 2다.

  2. moon의 지역 숫자는 A2의 2와 B1의 1이다.

  3. 조각 구별을 지우면 두 집합 모두 {1,2}가 되어 거짓 교집합이 생긴다.

지역 숫자만의 {1,2}는 실제 AND 결과가 아니다. 원래 네 문서 중 두 단어를 함께 포함한 문서는 없다.

비교할 점

서로 다른 목록에서 값이 같다는 사실은 공통 문서 정체성 계약이 있을 때만 의미가 있다.

전역 ID를 유지한 병합

지정 대응 A1→10, A2→20, B1→30, B2→40으로 dictionary와 Boolean 목록을 구성하라.

  1. sun은 전역 [10,40], moon은 [20,30]이다.

  2. 두 term의 df는 각각 2이며 총 Boolean posting은 4다.

  3. 두 목록의 교집합은 빈 목록이다.

숫자 길이와 함께 원문 문서 정체성을 보존하면 올바른 빈 AND를 얻는다.

비교할 점

잘못된 목록도 df=2를 만족할 수 있으므로 통계만의 검사는 충분하지 않다.

종이와 본문으로 직접 해보기

새 문서5 “별 별 구름”을 추가한다. 별과 구름 posting 및 df, 문서5 별 tf와 전체 posting 수를 계산하라. 없는 term “산”의 결과도 적어라.

힌트 보기

같은 문서의 반복은 합치되 새로운 문서ID는 남긴다. 문서5는 기존 문서와 다른 ID다.

풀이 보기

별:[1,3,5] df3, 구름:[4,5] df2다. 달/바다는 그대로 길이2이므로 전체 posting9개다. 문서5 별 tf2이며 산은 빈 목록이다. 문서5의 세 발생을 모두 별 목록에 넣지 않는다.

오해와 반례

posting list는 단어가 발생한 횟수만큼 docID를 반복 저장한다.

이 Boolean 모형의 문서1 “별 달 별”에서 별:[1,1]이 아니라 [1]이다. 발생 횟수나 위치가 필요하면 별도 tf/위치 항목을 저장한다. Boolean 존재 목록과 상세 posting 구조를 구별한다.

스스로 풀어보기

먼저 답과 이유를 적고, 필요한 만큼 힌트를 한 단계씩 열어 보세요.

연습 1 · 값과 상태 예측

이 네 문서에서 sun OR moon과 sun AND moon을 전역 ID로 구하라.

힌트 1

각 목록은 [10,40]과 [20,30]이다.

힌트 2

합집합은 모든 서로 다른 번호를 증가 순으로 정렬한다.

풀이와 답 확인

  1. OR는 [10,20,30,40]이다.

  2. AND는 빈 목록이다.

OR 네 문서, AND 0문서다.

흔한 오답에서 다시 생각하기

지역 숫자가 둘뿐이므로 OR도 문서 두 개다.

지역 번호의 반복과 전역 문서의 수를 구별한다.

연습 2 · 오류 찾아 고치기

sun과 moon의 df가 각각 2로 맞았으므로 지역 번호를 합친 결과가 정확하다고 보고했다.

힌트 1

틀린 목록의 교집합도 계산한다.

힌트 2

통계가 같은데 정체성이 다른 경우를 비교한다.

풀이와 답 확인

  1. 잘못 합친 목록 모두 {1,2}라 AND가 두 숫자를 반환한다.

  2. 올바른 전역 목록은 교집합이 없다.

df 일치는 필요한 통계 일치일 수 있어도 모든 결과의 정확성을 보장하지 않는다.

흔한 오답에서 다시 생각하기

길이가 같으면 집합 원소도 같다.

원소 수가 같다는 사실은 어떤 원소가 있는지까지 결정하지 않는다.

연습 3 · 직접 만들어 보기

조각 이름을 지우지 않고 전역 정수 번호도 새로 부여하지 않는 문서 식별 방식을 설계하라.

힌트 1

조각 이름과 지역 번호를 한 쌍으로 유지한다.

힌트 2

두 목록에 같은 전역 정렬 규칙을 적용한다.

풀이와 답 확인

  1. 문서 키를 (A,1),(A,2),(B,1),(B,2)로 둔다.

  2. sun=[(A,1),(B,2)], moon=[(A,2),(B,1)]로 저장하고 조각 이름 다음 지역 번호의 순서로 정렬한다.

같은 쌍만 같은 문서이며 두 목록의 교집합은 없다.

흔한 오답에서 다시 생각하기

같은 지역 번호라면 조각 이름은 저장할 필요가 없다.

지역 번호의 유일성 범위가 조각 내부다. 합친 범위의 유일한 키를 유지해야 한다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

전역 문서 50에 sun sun을 추가한다. sun의 df·새 문서 tf·전체 Boolean posting 수는 각각 얼마인가?

힌트 1

전역 ID 50은 기존 네 문서와 다른 문서다.

힌트 2

반복 두 발생을 Boolean 문서 목록에서는 한 번 합친다.

풀이와 답 확인

  1. sun=[10,40,50]로 df 3이다.

  2. 문서 50에서 sun의 tf는 2다. moon 목록 길이는 2다.

  3. 전체 Boolean posting은 3+2=5다.

df 3, tf 2, 총 posting 5다. 전체 토큰 발생은 원래 4개에 2개를 더해 6개다.

흔한 오답에서 다시 생각하기

두 발생을 추가했으므로 df도 4가 된다.

df는 발생 수가 아니라 서로 다른 문서 수다.

내 말로 설명하기

posting 병합 전에 확인할 것은?

설명 기준 확인

같은 ID의 정체성·유일성 범위와 공통 정렬 규칙 및 자료 버전이다.

같은 df로 결과의 정확성을 증명할 수 있는가?

설명 기준 확인

아니다. 같은 길이의 잘못된 ID 목록도 존재한다.

한 단계 더

원래 네 문서 모음에서 문서1을 삭제하면 별:[3], 달:[2]가 되어 해당 df도 각각1로 줄어든다. 원문 삭제와 역색인 갱신이 서로 다른 시점에 일어나면 어떤 문서 집합을 질의했는지 설명할 snapshot 계약이 필요하다. 두 문서가 같은 내용이라도 다른 docID라면 Boolean posting에서는 다른 문서다. 의미 중복 제거는 별도의 작업이다.

소단원 3.2

교집합 질의

두 단어가 모두 있는 문서를 작은 목록 두 개로 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • AND는 두 조건을 모두 만족, OR는 하나 이상, NOT는 지정한 문서 우주에서 제외를 뜻한다.

  • 전역 docID 증가 순의 중복 없는 목록을 가정한다.

  • 포인터는 아직 처리하지 않은 목록의 현재 위치를 가리킨다.

학습 목표

  • 두 포인터 교집합의 이동 근거를 설명한다.

  • Boolean 괄호·부정의 문서 우주와 중간 결과를 계산한다.

가장 짧은 목록부터 계산해도 비교 횟수가 항상 최소일까?

이번 별도 목록은 A=[1,100], B=[1,2,3], C=[50,60,70,80]이다. 모두 같은 전역 ID의 증가 순이며 중복이 없다. 매번 현재 ID 쌍을 한 번 비교하고, 같으면 둘 다·다르면 작은 쪽만 전진한다. 목록 조회·입출력·할당·압축 해제는 세지 않고 현재 ID 비교만 센다. 어떤 교집합이 빈 목록이 되면 나머지 순수 AND는 비교 없이 빈 결과다.

길이 순으로 A와 B를 먼저 처리하면 비교는 (1,1),(100,2),(100,3) 세 번이고 중간 목록은 [1]이다. 그다음 C와 비교하면 (1,50) 한 번 후 종료하므로 총 네 번이다. B와 C를 먼저 처리하면 (1,50),(2,50),(3,50) 세 번 후 빈 결과가 되어 총 세 번으로 끝난다. 최종 집합은 둘 다 비어 있지만 비교 횟수는 다르다.

이 반례는 짧은 목록부터 시작하는 휴리스틱이 언제나 최적이라는 주장만 반박한다. 실제 저장 장치에서는 다른 순서가 더 빠르다는 실측 주장은 아니다. 순수 AND의 교환·결합 법칙은 집합 결과를 보존하지만 중간 결과와 처리 비용은 보존하지 않는다. 잘못 정렬된 입력에서는 작은 값을 건너뛰는 근거 자체가 무너지므로 비용 비교 전에 정렬 전제를 검사해야 한다.

같으면 남기고 작은 쪽은 지나가기

A AND B는 posting 집합의 교집합이다. 현재 docID가 같으면 양쪽에 있으므로 결과에 넣고 둘 다 전진한다. A의 값이 B보다 작으면 A만 전진한다. B의 현재와 이후 값은 모두 그 작은 A보다 크므로 그 A가 B에 나타날 가능성이 없다. 이 근거는 공통 증가 정렬이라는 전제에 의존한다.

어느 한 목록의 끝에 도착하면 종료한다. 반대 목록의 남은 항목은 끝난 쪽에 대응할 항목이 없기 때문이다. 입력을 훼손하지 않는 새 결과 목록 모형을 쓴다. 같은 단어를 두 번 AND해도 집합 결과는 같은 목록이며 문서 내부 발생을 두 개 요구하는 뜻이 아니다.

순서와 비용을 따로 판단하기

길이가 x,y인 두 목록에서 포인터는 뒤로 가지 않고 각 항목을 한 번 지나가므로 비교/전진 작업은 O(x+y)다. 양쪽이 비어 있지 않으면 현재 ID 비교 횟수는 최대 x+y−1이다. 실제 횟수는 값의 배치와 빨리 끝나는 쪽에 따라 다르다. 결과 출력·압축 해제·사전 조회·저장 장치 시간은 이 단순 비교 모형 밖이다.

여러 AND term은 df가 작은 목록부터 시작하는 것이 흔한 휴리스틱이다. 중간 결과가 작아질 가능성이 있지만 모든 저장 방식과 docID 배치에서 항상 최적이라는 정리는 아니다. 어떤 중간 결과가 비면 전체 순수 AND는 바로 빈 결과다. OR나 NOT가 섞이면 괄호 의미를 먼저 정하고 각 중간 집합의 비용을 따로 본다.

부정은 문서 우주를 필요로 한다

고정 문서 우주 U가 있어야 NOT B=U\B를 정의할 수 있다. A AND NOT B는 A\B로 계산하여 U 전체 보수를 먼저 나열하지 않을 수 있다. 반면 A OR NOT B의 결과는 U의 많은 문서를 포함할 수 있어 출력 자체가 크다. “NOT가 언제나 싸다”거나 “결과 없음이 색인 밖 인터넷 전체에 없음”이라고 해석하지 않는다.

Boolean 검색은 정의된 term 조건의 참/거짓을 판정하며 자동으로 유용성 순위를 만들지 않는다. 같은 단어가 있는 문서라도 질문의 뜻과 맞지 않을 수 있다. 결과 docID 정렬은 편의를 위한 순서이지 관련도 점수가 아니다. 실제 서비스 질의 문법의 암묵 AND/OR·우선순위는 별도 확인해야 하므로 이 예는 모두 명시 괄호를 쓴다.

소단원 3.3

구절·위치색인

두 단어가 모두 있다는 사실만으로 “빨간 별”이라는 구절을 찾을 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 문서별 token 위치를1부터 세고 공백 분할 규칙을 유지한다.

  • 구절은 토큰의 순서와 바로 인접한 위치를 요구한다.

  • 문서 교집합은 같은 문서라는 조건이며 위치 교집합은 그 안의 배열 조건이다.

학습 목표

  • Boolean 후보에서 위치 offset으로 구절을 확인한다.

  • 반복 단어와 근접 질의의 별도 조건을 설명한다.

제목 끝과 본문 시작을 붙여도 같은 구절일까?

새 세 문서의 필드를 따로 둔다. a는 제목 [red], 본문 [star]이고, b는 제목 [red,star], 본문 [cloud]이며, c는 제목 [red,large], 본문 [star]다. 문서 전체 어디에든 red와 star가 있으면 Boolean 후보는 a,b,c다. 하지만 같은 필드 안에서 바로 인접한 red star를 찾는 계약이면 제목의 b만 통과한다.

a의 제목과 본문을 경계 표지 없이 단순히 붙이고 위치를 1,2로 매기면 red star가 생긴 것처럼 보인다. 원래 같은 필드의 구절이 아니므로 이 계약에서는 거짓 통과다. 위치 키에 필드 이름을 포함해 a의 red=(title,1), star=(body,1)로 두면 서로 다른 필드임을 구별할 수 있다. 실제 제품에서는 필드·문장·줄바꿈을 어떻게 처리할지 따로 정해야 한다. 이 사례는 같은 필드라는 명시 조건만 사용한다.

반복 단어 구절도 모든 슬롯을 확인한다. 별도 단일 필드 문서 d=[echo,echo,bell,echo,bell]에서 echo 위치는 {1,2,4}, bell은 {3,5}다. echo echo bell은 시작 1에서만 성립한다. echo를 한 번 조회해도 시작·둘째 슬롯의 두 발생은 서로 다른 요구다. 여러 시작 위치가 있더라도 반환 문서 ID의 수와 구절 출현 수를 구별한다.

먼저 확인할 개념
  • 구절의 슬롯별 상대 위치

    같은 필드 안의 인접과 반복 단어의 각 발생을 확인한다.

  • 문서 빈도와 발생 수

    구절 시작 수와 반환 문서 수를 따로 센다.

posting에 위치 목록을 붙이기

위치색인은 term마다 docID와 그 문서에서 발생한 token 위치의 증가 목록을 저장한다. “빨간 별 빨간 달”에서 빨간은 [1,3], 별은 [2], 달은 [4]다. 위치는 이 토큰화 모형의 단위이며 바이트 오프셋·화면 글자 좌표와 같다고 가정하지 않는다. 저장 공간은 단순 Boolean 목록보다 늘 수 있다.

문서에 빨간과 별이 둘 다 있다고 먼저 후보를 좁힌 다음 위치를 검사한다. “빨간 별”은 빨간의 위치 p와 별의 위치 p+1이 같은 문서에 있어야 한다. 별이 먼저 있거나 중간에 다른 token이 있으면 이 정확 구절에 맞지 않는다. 문서 ID가 같다는 검사와 offset이 맞다는 검사를 각각 수행한다.

긴 구절과 반복 단어 검사

q1 q2 … qr이라는 구절은 어떤 시작 위치 p에서 qj가 p+j−1에 존재해야 한다. 단어마다 시작 후보로 이동한 집합 P(qj)−(j−1)를 만들고 그 교집합을 구할 수도 있다. 이 식은 모든 위치를1부터 센 현재 모형에 대한 정의다. 단어가 같아도 구절의 각 offset 요구를 없애면 안 된다.

“별 별”의 문서 후보는 별이 있는 문서다. 하지만 단 한 번 위치2에 있는 별만으로 구절이 성립하지 않는다. 위치 p와 p+1이라는 두 발생이 필요하다. “별 달 별”에서는 시작 별과 끝 별의 offset2를 함께 확인한다. 사전의 distinct term을 한 번 조회해 위치 목록을 공유할 수 있어도 구절 슬롯의 요구는 각자 남는다.

근접과 전처리의 의미를 계약으로 남기기

근접 검색은 정확 구절과 다를 수 있다. 여기에서 “거리2 이내”를 서로 다른 token 위치 p,q에서 |q−p|≤2라고 따로 정의하면 단어 사이에 token 하나가 끼어도 맞고, 순서를 제한하지 않는다. 실제 검색 시스템의 /k 표기나 slop 숫자는 정의가 다를 수 있으므로 같은 숫자를 보고 동일 의미라고 판단하지 않는다.

stop word를 제거한 후 위치를 다시 촘촘하게 매기면 원문에서 떨어진 두 단어가 인접해 보일 수 있다. 원래 token 위치를 보존하면 간격을 유지할 수 있지만 제거한 term을 포함하는 구절은 다른 처리가 필요하다. 줄바꿈·문장 경계·필드 사이 구절 허용도 정해야 한다. 이 단원은 네 짧은 문서를 별개 필드 없이 원래 token 위치로 처리한다.
