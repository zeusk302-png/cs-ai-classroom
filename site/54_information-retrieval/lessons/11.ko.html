소단원 11.1

precision·recall·MAP·nDCG

같은 관련 문서 두 개를 찾았어도 어느 순서에 놓았는지가 중요한 이유는 무엇일까?

준비 개념과 학습 목표

준비 개념

  • 집합과 비율

  • 순위

  • 로그와 가중 합

학습 목표

  • precision과 recall의 분모를 구별한다.

  • AP와 질의 평균 MAP를 계산한다.

  • 등급·cutoff·gain 규약을 정해 nDCG를 계산한다.

찾은 것과 찾아야 할 것을 나눈다

Precision은 가져온 문서 중 관련 문서 비율이고 recall은 전체 관련 문서 중 가져온 비율이다. 상위 k개에 대해 평가하면 P@k의 분모는 k, recall@k의 분모는 전체 관련 문서 수 R이다. 문서는 중복 없이 센다고 정한다.

관련성은 특정 정보 요구에 대한 판정이다. 같은 문서라도 질의가 달라지면 달라질 수 있다. R을 실제로 모르면 완전한 recall도 알 수 없다. 관련 문서가 없거나 결과가 비어 분모가 0인 경우는 평가 규약을 따로 정하고 임의 성공률을 만들지 않는다.

관련 문서의 도달 순위를 반영한다

이 단원의 AP는 AP=(1/R)Σᵢ relᵢ P@i이며 relᵢ는 이진 관련 판정이다. 관련 문서가 나온 순위에서만 precision을 더하고 전체 R로 나눈다. 제공한 순위 목록에서 끝내 찾지 못한 관련 문서는 기여 0이다.

MAP는 질의별 AP의 단순 평균이다. 각 질의가 같은 가중치라 관련 문서가 많다는 이유로 그 질의를 더 크게 반영하지 않는다. cutoff에서 끝나는 목록은 미검색 0 규약을 밝히며 검색한 관련 문서 수만 분모로 써 과대평가하지 않는다.

관련성 등급을 할인하여 정규화한다

등급 rᵢ≥0, gain 2^rᵢ−1, DCG@k=Σᵢ₌₁ᵏ(2^rᵢ−1)/log₂(i+1)로 정한다. IDCG@k는 같은 질의의 완전 판정 문서들을 등급 내림차순으로 놓았을 때의 값이다. nDCG는 DCG/IDCG이며 양의 IDCG가 필요하다.

다른 gain나 할인 정의를 쓰는 구현도 있어 규약을 함께 기록한다. 순서를 바꾼 이진 관련 문서 수가 같아도 AP나 nDCG는 달라질 수 있다. 지표 하나가 사용자 효용·지연·모든 언어 조건을 대신하지 않는다.

중간 과정을 따라가는 예제

전체 관련 문서는 3개다. 반환된 순위 4개의 관련 판정은 [1,0,1,0]이다. P@3, recall@3, 이 목록에서 미검색 기여를 0으로 둔 AP를 구하라.

  1. 상위 3개에서 관련은 2개다. P@3=2/3, recall@3=2/3이다. 같은 값이 나온 것은 이 표에서 분모가 우연히 같기 때문이다.

  2. 관련이 나온 1위의 P@1=1, 3위의 P@3=2/3이다.

  3. AP=(1+2/3+0)/3=5/9다. 찾은 두 개만 분모에 넣은 5/6과 다르다.

P@3=2/3, recall@3=2/3, AP=5/9다.

종이와 본문으로 직접 해보기

두 질의 AP가 5/9와 1/3이면 MAP는? 등급 두 문서 [0,2]에서 nDCG@2를 이 단원 규약으로 구하라.

힌트 보기

질의 평균은 두 수의 합을 2로 나눈다. 등급 2의 gain은 3이며 이상 순서는 [2,0]이다.

풀이 보기

MAP=(5/9+1/3)/2=4/9다. DCG=3/log₂3, IDCG=3이므로 nDCG=1/log₂3≈0.63093이다.

오해와 반례

AP는 찾아온 관련 문서의 precision만 평균내면 된다.

미검색 관련 문서 기여를 0으로 두고 전체 R로 나누는 규약이다. 관련 문서 수와 평가 cutoff를 함께 적는다.

한 단계 더

첫 예의 순서를 [0,1,0,1]로 바꾸면 관련 두 개 수는 같아 P@4=1/2지만 AP=(1/2+2/4+0)/3=1/3이다. 등급 [2,0]이면 DCG=IDCG=3으로 nDCG@2=1이다. 수·순서·등급이 서로 다른 정보를 제공한다.

소단원 11.2

판정집합

평가자가 읽지 않은 문서를 관련 없는 문서라고 불러도 될까?

준비 개념과 학습 목표

준비 개념

  • 질의와 정보 요구

  • 문서 식별자

  • 부분집합과 일치율

학습 목표

  • 판정 문서와 미판정 문서를 구별한다.

  • pooling의 범위와 한계를 설명한다.

  • 판정자 일치와 평가 점수의 조건을 기록한다.

질의 문자열 밖의 요구를 적는다

판정집합은 문서·정보 요구·관련 판정을 연결한 평가 자료다. 정보 요구에는 목적과 포함/제외 조건을 적어야 평가자가 같은 대상을 판정한다. 무작위 단어 조합이 실제 사용자의 요구를 대표한다고 자동 가정하지 않는다.

질의 표현을 바꾸어도 정보 요구가 같은지, 특정 시점이나 언어 조건을 요구하는지 정한다. 판정집합을 보며 규칙을 반복 조정한 뒤 같은 집합을 최종 독립 검증이라고 부르면 안 된다. 개발·검증·최종 평가의 역할을 나눈다.

읽은 일부가 전체 진실은 아니다

큰 문서 집합은 전수 판정이 어려워 여러 시스템의 상위 결과 등을 모아 pool을 만들 수 있다. Pool에 없는 문서는 미판정이다. 어떤 평가 규약이 미판정을 0으로 처리하더라도 그것은 계산 규약이며 실제 비관련 판정을 받았다는 뜻은 아니다.

새 검색 방식이 pool 밖 문서를 잘 찾으면 불완전 판정이 비교에 영향을 줄 수 있다. 판단 범위·검색 참여 시스템·판정 시점과 미판정 처리법을 함께 남긴다. 완전 recall을 안다고 하려면 전체 관련 문서 수를 아는 근거가 필요하다.

사람 사이 차이도 관찰한다

판정자는 정보 요구를 다르게 해석할 수 있다. 구체적 기준과 예를 공유하고 독립 판정 뒤 불일치를 살펴볼 수 있다. 일치율은 같은 판정한 수/공통 판정 수로 계산하지만 우연 일치를 보정한 지표와 같은 것은 아니다.

높은 일치율도 기준 자체의 적절성을 보장하지 않는다. 전체 판정 조건을 읽고 누락이나 애매한 기준을 확인한다. 아래 두 판정자는 가상의 표이며 실제 사람을 모집하거나 판정을 수집하지 않았다.

중간 과정을 따라가는 예제

시스템 A 상위 문서는 [d1,d2], B는 [d2,d3]다. 합집합 pool에서 d1·d3은 관련, d2는 비관련으로 판정했다. d4는 pool 밖이다. Pool과 판정 관련 문서 수, d4 상태를 구하라.

  1. pool은 중복 d2를 한 번 세어 {d1,d2,d3}이며 3개다.

  2. pool 안 판정 관련은 {d1,d3}로 2개다.

  3. d4는 미판정이다. pool 안 관련 2개가 전체 자료의 모든 관련 문서 수라고 결론내리지 않는다.

pool 3개, 판정된 관련 2개, d4는 미판정이다.

종이와 본문으로 직접 해보기

새 시스템의 상위 문서가 [d4,d1]이다. 미판정을 0으로 취급하는 P@2와, d4를 실제 읽어 관련으로 확정한 뒤 P@2를 비교하라.

힌트 보기

계산 규약의 0과 실제 판정을 구별한다.

풀이 보기

규약상 d4=0이면 P@2=1/2다. 실제 추가 관련 판정을 받으면 P@2=2/2=1이다. 새 판정이 없는 상태에서는 후자의 값을 실제 평가 결과라고 적지 않는다.

오해와 반례

판정 파일에 없는 문서는 모두 평가자가 비관련으로 확인했다.

파일 부재는 미판정일 수 있다. 계산상 처리 규약과 실제 판정 사실을 구별한다.

소단원 11.3

지연·클릭·A/B

클릭률이 높아졌다는 숫자 하나만으로 학습 검색이 더 좋아졌다고 말할 수 있을까?

준비 개념과 학습 목표

준비 개념

  • 비율과 퍼센트포인트

  • 평균과 정렬

  • 실험군과 비교군

학습 목표

  • 클릭 분모와 지연 요약을 명시한다.

  • 무작위 배정과 비교 조건을 설명한다.

  • 표본 차이와 확정 효과를 구별한다.

효용과 간접 신호를 나눈다

검색 사용자는 찾으려는 정보를 얻는 과정에서 결과 관련성·속도·화면을 경험한다. 클릭은 간접 피드백이다. 눈에 잘 띄는 위치나 요약 때문에 누를 수 있고 필요한 답이 화면에 이미 보여 누르지 않을 수도 있다.

이 단원의 CTR은 클릭을 포함한 검색 세션 수/전체 해당 검색 세션 수다. 클릭 수/노출 수 같은 다른 정의와 섞지 않는다. 학습 플랫폼의 목적은 클릭 수 자체와 같지 않으며 과제 완료·실패·장벽 같은 질문도 함께 정의한다.

같은 비교에서 한 변경을 살핀다

A/B 실험은 비교군과 한 변경을 적용한 군으로 무작위 배정하고 미리 정의한 결과를 비교하는 설계다. 사용자 단위로 배정했다면 같은 사용자의 반복 방문을 독립 사람으로 세지 않고 배정과 분석 단위를 맞춘다.

기간·대상·노출 조건이 다르면 비교에 다른 원인이 섞일 수 있다. 표본 오차와 여러 지표를 반복 확인한 선택의 문제도 있다. 작은 숫자 차이만 보고 확정 개선이라고 선언하지 않는다. 실제 모집과 배포 실험은 이 단원에서 수행하지 않았다.

지연의 정의와 요약을 남긴다

지연은 여기서 요청 시작부터 결과 표시까지의 경과 시간으로 정한다. 서버 내부 시간만 잰 값과 다르다. 평균 하나 외에 정렬한 값의 중앙값·상위 분위수 등을 함께 볼 수 있고 분위수 계산 규약도 적는다.

실패 요청을 제외하면 느린 실패를 숨길 수 있어 실패 수와 시간 제한 조건을 함께 남긴다. 아래 가상 5개 시간의 중앙값은 세 번째이고 80% 분위수는 nearest-rank의 ceil(0.8×5)=4번째로 정한다. 실제 브라우저나 서버의 응답 시간을 측정하지 않았다.

중간 과정을 따라가는 예제

가상 A군 100세션 중 클릭 포함 20세션, B군 100세션 중 25세션이다. CTR·차이·상대 증가율을 구하라. B의 요청 시간은 [100,100,100,100,600] ms다.

  1. CTR A=20%, B=25%로 차이는 5퍼센트포인트다.

  2. A를 기준으로 상대 증가는 (25−20)/20=25%다. 5% 상대 증가와 다르다.

  3. B 평균은1000/5=200 ms, 중앙값100 ms, nearest-rank 80% 분위수는100 ms다. 최대600 ms도 존재한다.

CTR 차이 5퍼센트포인트·상대 증가25%, 평균200 ms·중앙값100 ms·정한 p80 100 ms다. 확정 효과가 아니다.

평균280 ms, 중앙값100 ms다. 과제 완료를 별도 관찰하지 않았으므로 성공률을 알 수 없다.

오해와 반례

CTR 표에서 B가 높으므로 모든 사용자에게 더 좋고 원인도 확정됐다.
