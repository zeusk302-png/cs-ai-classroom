수집·색인·서빙

페이지를 내려받았다는 사실이 모든 검색어에 그 페이지를 보여 준다는 뜻일까?

준비 개념과 학습 목표

준비 개념

  • 집합과 교집합

  • 문서 식별자

  • 자료와 조회 구분

학습 목표

  • 수집·색인·질의 응답 단계를 구별한다.

  • 작은 역색인과 Boolean 조회를 추적한다.

  • 문서 변경과 삭제의 반영 시점을 설명한다.

문서 ID가 같으면 서로 다른 판본의 단어를 합쳐도 될까?

자체 문서 d의 판본 v1 토큰은 {파이썬}, v2는 {그래프}다. 어느 한 판본에도 두 단어가 함께 있지 않다. 옛 색인에서 파이썬 목록 {d}를 읽고 새 색인에서 그래프 목록 {d}를 읽어 문서 ID만 교집합하면 d가 나온다. 하지만 파이썬 AND 그래프를 만족한 실제 판본은 없다. 단어별 조회가 같은 문서 스냅샷을 뜻하는지 먼저 확인한다.

문서와 판본을 묶어 기록하면 옛 파이썬은 {(d,v1)}, 새 그래프는 {(d,v2)}라 교집합이 비어 있다. 실제 서빙을 v2 전체로 고정하는 별도 정책에서도 파이썬 목록은 비어 있고 그래프 목록은 {d}이므로 AND는 비어 있다. 키에 판본을 넣는 것과 최신 스냅샷을 선택하는 것은 다른 역할이다. 판본별 결과를 얻은 뒤 어느 판본을 보여 줄지도 정해야 한다.

삭제 뒤 늦은 갱신도 장부로 추적한다. 자체 v1 갱신 작업이 먼저 시작됐지만, v2 삭제 표시가 적용된 뒤 v1 작업이 늦게 도착한다고 정한다. 도착 순서만 따르면 v1 자료가 다시 보일 수 있다. 문서별 증가하는 판본을 비교하고 삭제 v2를 유지하는 정책에서는 v1을 거부한다. 이 순서표는 실제 검색 서버의 원자성·복제·삭제 완료를 증명한 시험이 아니다. 수집 성공, 색인 반영, 응답 판본과 캐시 무효화를 각각 확인해야 한다.

문서를 발견하고 가져온다

수집기는 시작 URL에서 페이지를 가져오고 내용과 링크를 읽어 다음 후보 목록을 만든다. 발견한 URL 모두를 반드시 가져오는 것은 아니다. 접근 제한·통신 실패·자원 한도가 있을 수 있으며 실제 수집에서는 대상의 부하를 고려한다.

수집 완료는 내용이 저장됐다는 한 단계다. 색인은 검색할 형태로 정보를 정리하는 단계이고 서빙은 질의를 받아 후보를 찾아 순위를 정하고 응답하는 단계다. 페이지가 수집됐다고 색인이나 모든 질의의 상위 노출까지 자동 완료되지 않는다.

단어에서 문서로 가는 표를 만든다

역색인은 각 단어에서 그 단어가 있는 문서 식별자 목록으로 가는 표다. 문서를 토큰으로 나누고 정규화한 뒤 단어/문서 쌍을 모아 같은 문서의 중복을 병합한다. 한국어의 실제 형태소 처리는 별도 선택이며 아래 단어는 사람이 이미 나눈 것으로 정한다.

AND 질의는 두 단어 목록의 교집합, OR 질의는 합집합을 이용할 수 있다. 이 작은 Boolean 모형은 점수나 의미 유사도를 계산하지 않는다. 실제 시스템은 후보 검색 뒤 순위와 접근 권한 등 추가 계약을 적용할 수 있다.

현재 원문과 조회 판본을 나눈다

문서가 바뀌어도 조회가 이전 색인 판본을 쓰면 이전 내용으로 결과를 낼 수 있다. 새 자료를 보조 색인에 넣고 결과를 병합하거나 새 색인을 완성해 교체하는 방식이 있다. 삭제 문서를 조회 결과에서 거르는 규칙도 필요하다.

원문 수정 시점·수집 시점·색인 반영 시점·응답 시점은 다른 기록이다. 삭제 요청만 적었다고 이미 모든 색인과 캐시에 반영됐다고 단정하지 않는다. 아래는 자체 집합 계산이며 실제 웹 수집·서버·검색 공개 시험을 하지 않았다.

거짓 결합은 문서가 없어서가 아니라 같은 ID의 서로 다른 상태를 한 문서처럼 합친 데서 생긴다.

중간 과정을 따라가는 예제

이미 나눈 토큰은 d1={파이썬,배열}, d2={자바,배열}, d3={파이썬,그래프}다. 역색인과 파이썬 AND 배열, 파이썬 OR 배열 결과를 구하라.

  1. 파이썬→{d1,d3}, 배열→{d1,d2}, 자바→{d2}, 그래프→{d3}다.

  2. 파이썬 AND 배열은 {d1,d3}∩{d1,d2}={d1}이다.

  3. 파이썬 OR 배열은 합집합 {d1,d2,d3}다. 목록 순위는 이 집합 모형에서 정하지 않았다.

AND 결과 {d1}, OR 결과 {d1,d2,d3}다.

조건을 바꾸어 비교하기

판본을 섞은 Boolean 결과

옛 파이썬과 새 그래프 목록을 문서 ID만 교집합하면?

  1. 두 목록의 ID가 모두 d라 교집합은 {d}다.

  2. v1에는 그래프가 없고 v2에는 파이썬이 없다.

ID 교집합은 계산되지만 어느 지정 판본도 AND를 만족하지 않는다.

비교할 점

앞 본문의 정적 한 판본 집합 조건이 깨졌다.

삭제 뒤 도착한 옛 갱신

현재 표시가 삭제 v2인데 갱신 v1이 도착하면 두 정책은?

  1. 도착 순서 덮어쓰기는 v1 내용을 다시 활성화할 수 있다.

  2. 증가 판본 비교 정책은 1<2라 v1을 거부하고 삭제 v2를 유지한다.

지정한 판본 순서 정책에서 늦은 옛 갱신을 적용하지 않는다.

비교할 점

문서별 순서·삭제 표시 보존이라는 추가 계약이며 실제 분산 서비스 보장은 아니다.

종이와 본문으로 직접 해보기

d1을 삭제로 표시했고 아직 기본 목록은 그대로다. 최종 응답에서 삭제 문서를 걸러 낸다면 위 두 결과는?

힌트 보기

먼저 후보를 구한 뒤 삭제 집합 {d1}을 뺀다.

풀이 보기

AND는 공집합, OR는 {d2,d3}다. 실제 시스템의 삭제 완료 여부를 측정한 것이 아니라 이 모형의 필터 규칙을 적용한 결과다.

오해와 반례

수집 성공 또는 색인됨 표시가 모든 질의의 상위 노출을 보장한다.

각 단계와 질의 적합성이 다르다. 수집·색인·응답의 실제 증거와 조회 조건을 각각 확인한다.

연습 1 · 값과 상태 예측

문서 d의 v3 토큰은 {파이썬,그래프}다. v3 전체 스냅샷에서 AND와 두 목록의 판본 키는?

힌트 1

두 단어 모두 v3에 있다.

힌트 2

같은 (d,v3)를 두 목록에 쓴다.

풀이와 답 확인

  1. 두 목록은 각각 {(d,v3)}다.

  2. 교집합 {(d,v3)}이므로 d의 v3를 반환할 수 있다.

이 판본에서는 AND가 실제 내용과 일치한다.

흔한 오답에서 다시 생각하기

판본 키를 쓰면 모든 AND는 비어 있다.

같은 판본에서 두 단어가 있으면 교집합은 정상적으로 남는다.

연습 2 · 오류 찾아 고치기

삭제 v2를 확인한 뒤 옛 캐시의 d를 그대로 응답했다.

힌트 1

색인과 응답 캐시도 별도 상태다.

힌트 2

최종 응답 전에 어떤 삭제 상태를 검사했는지 확인한다.

풀이와 답 확인

  1. 캐시 생성 판본과 삭제/무효화 정책을 확인한다.

  2. 최종 응답이 지정한 삭제 상태를 반영하게 필터·캐시 무효화 또는 재조회 계약을 적용한다.

삭제 요청 기록과 모든 응답 경로의 반영 완료를 구별한다.

흔한 오답에서 다시 생각하기

색인에서 삭제했으면 모든 캐시는 자동으로 같은 상태다.

캐시가 이전 결과를 별도로 보존할 수 있다.

연습 3 · 직접 만들어 보기

수집·색인·서빙의 문서별 갱신 장부를 작성하라.

힌트 1

내용 버전과 처리 도착 순서를 나눈다.

힌트 2

질의가 읽은 스냅샷을 남긴다.

풀이와 답 확인

  1. 문서 ID와 내용/삭제 판본, 수집 시각과 색인 적용 판본을 기록한다.

  2. 서빙 스냅샷 및 각 postings의 판본, 삭제 필터·늦은 작업 처리 규칙을 적는다.

  3. 응답 캐시 키와 생성 판본·무효화 조건 및 실제 확인한 경로를 기록한다.

작업 파일 존재와 서비스 갱신 완료를 같은 증거로 쓰지 않는다.

흔한 오답에서 다시 생각하기

마지막 작업 종료 시각만 알면 전체 응답 내용도 안다.

늦은 옛 작업과 여러 스냅샷·캐시는 종료 순서만으로 판별되지 않는다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

판본 키로 교집합이 비어 있다는 사실만으로 최신 상태 v2를 응답했다고 증명할 수 있는가?

힌트 1

빈 교집합은 여러 판본에서도 생길 수 있다.

힌트 2

어느 스냅샷을 선택했는지 따로 확인한다.

풀이와 답 확인

  1. v1 전체에서도 그래프가 없어 AND는 비어 있다.

  2. v2 전체에서도 파이썬이 없어 비어 있다.

동일한 결과 집합만으로 실제 사용 판본을 식별하지 못한다.

흔한 오답에서 다시 생각하기

정답 집합이 같으면 응답 판본 기록은 필요 없다.

갱신 증거는 결과뿐 아니라 스냅샷과 원문 판본도 확인한다.

설명 기준 확인

서로 다른 판본의 단어를 한 상태처럼 결합할 수 있는 갱신 중 조회다.

삭제 완료 증거를 나누는 이유는?

설명 기준 확인

색인과 늦은 작업·캐시·최종 응답 경로가 별도의 상태를 가질 수 있기 때문이다.

한 단계 더

d2의 토큰을 {자바,그래프}로 갱신하면 새 판본의 배열 목록은 {d1}, 그래프는 {d2,d3}다. d1 삭제 필터도 유지하면 배열 질의 결과는 공집합이다. 원문만 바꾸고 이전 색인을 계속 쓰는 다른 조건에서는 d2가 배열 후보로 남을 수 있으므로 판본을 적자.

같은 검색어를 쓴 두 사람이 다른 자료를 받으면 어느 조건이 달라졌을까?

준비 개념과 학습 목표

학습 목표

선호 숫자의 척도와 캐시 범위도 순위를 바꿀까?

앞 본문의 적합도 (8,7,5), 선호 (0,4,2)에 λ=1이면 a/b/c 점수는 (8,11,7)이다. 선호를 두 배로 기록하고 λ를 유지하면 (8,15,9)가 되어 순서도 b,c,a로 달라진다. 단순히 단위를 바꾼 것이라 같은 효과를 유지하려면 λ를 1/2로 바꿔 원래 선호 기여를 복원해야 한다.

선호를 최대 4로 나누어 (0,1,.5)로 정규화하고 λ=1을 유지하면 점수는 (8,8,5.5)다. 동점은 ID 사전순으로 정해 a,b,c다. λ=4로 바꾸면 원래 (8,11,7)이다. 숫자 척도와 가중치는 한 계약이며 두 값을 따로 비교해 같은 개인화라고 말하지 않는다. 이 식은 실제 검색 서비스의 공식 알고리즘이 아니다.

동일 문자열의 응답 캐시도 문맥을 확인한다. 자체 사용자 U의 선호는 (0,4,2), V는 (4,0,2)이고 같은 적합도와 λ1을 쓴다. U의 1위는 b 점수11, V의 1위는 a 점수12다. 질의 문자열만으로 U의 결과 b를 저장해 V에게 재사용하면 V의 계산과 다르다. 재사용 가능한 조건은 사용자/문맥·표현·후보 판본·점수 계약과 함께 정한다. 개인화 없는 결과도 시각·언어 등 다른 조건이 남을 수 있으며 실제 계정이나 개인정보를 다루지 않은 숫자 모형이다.

먼저 확인할 개념
  • 선호 결합의 가중치

    점수 척도·λ·동점 조건과 context를 읽는다.

  • 서빙 판본과 캐시

    이전 응답을 재사용할 때 후보와 문서 판본을 확인한다.

명시한 질문과 문맥을 읽는다

검색은 사용자가 적은 질의를 중요한 입력으로 삼는다. 추천은 사용자 이력·시간·장치 같은 문맥으로 항목을 제안할 수 있으며 명시 질의가 없는 경우도 있다. 두 서비스는 후보 생성과 점수화 구조를 공유할 수 있으므로 서로 완전히 무관한 기술로 나누지 않는다.

검색에도 위치나 언어·현재 문맥이 쓰일 수 있다. 같은 문자열이라도 어느 지역의 가게를 찾는지에 따라 적합한 문서가 다르다. 서비스에 따라 개인화는 일부 결과의 순위를 바꾸지만 모든 차이가 계정 이력 때문이라고 단정하지 않는다.

기본 적합성과 선호를 결합한다

자체 점수 s=질의 적합도+λ×선호 점수라고 정하면 λ가 선호의 가중치다. 이 식은 교육용이고 실제 검색 서비스의 공식 점수식이 아니다. 점수 스케일·동점 처리·후보 목록을 정해야 계산된 순위를 같은 뜻으로 비교할 수 있다.

선호가 강하면 원래 질의와 덜 맞는 자료가 앞에 갈 수 있다. 사용자의 현재 목적과 이력이 다를 가능성을 생각하고 개인화 없는 보기·조건 설명·다양한 결과 같은 대안을 검토한다. 사용자 개인정보를 실제 수집하지 않아도 가상 선호 표로 이 원리를 배울 수 있다.

비교할 환경을 함께 기록한다

개인화 사용/해제, 언어·위치·시각·후보 판본·평가 지표를 나란히 적는다. 개인화를 껐어도 위치나 언어 같은 context가 남을 수 있다. 서로 다른 시각에 검색한 결과는 새 문서나 색인 갱신의 영향도 받을 수 있다.

랭킹 점수가 높다는 것은 이 식의 순서이며 실제 만족이나 학습 효과가 아니다. 실제 비교는 사용자와 목적에 맞는 판정·불확실성과 미확인 영향을 함께 확인해야 한다. 아래는 점수의 종이 계산으로 계정이나 서비스 설정을 바꾸지 않았다.

중간 과정을 따라가는 예제

후보 a/b/c의 질의 적합도는 8/7/5, 선호 점수는 0/4/2다. s=적합도+λ×선호이며 λ=0과 λ=1의 순위를 구하라. 점수가 같으면 알파벳순으로 정한다.

  1. λ=0이면 점수8/7/5라서 a→b→c다.

  2. λ=1이면 점수8/11/7이라서 b→a→c다.

  3. 선호 항이 b의 점수를 4 높여 a보다 앞으로 갔다. 실제 추천 정확도 변화가 아니라 정한 식의 순위 변화다.

λ=0은 a,b,c이고 λ=1은 b,a,c다.

  2. λ1/2에서는 8,7+4,5+2로 8,11,7이다.

같은 노출 개수와 같은 인용 개수가 같은 품질인가?

자체 순위 [a,b,c]에서 a/b의 제공자는 X, c는 Y이고 세 문서 주제는 서로 다른 P/Q/R이다. 표시 개수는 X2개/Y1개다. 위치 노출 가중치를 1,1/2,1/3으로 정하면 X 노출합은 3/2, Y는 1/3이고 전체는 11/6이다. 정규화된 비율은 X9/11, Y2/11이다. 이 가중치는 자체 정책이며 실제 시선이나 클릭 확률 실측이 아니다.

[a,c,b]로 바꾸면 주제 coverage는 여전히 1이고 제공자 개수도 X2/Y1이다. 하지만 가중 노출합은 X4/3, Y1/2라 비율은 X8/11, Y3/11이다. 항목 수·주제 coverage·위치 노출은 서로 다른 정보다. 어떤 목표가 공정한지는 제공자/사용자 집단의 조건과 관련성·품질·맥락을 별도 검토해야 한다. 이 노출 비율을 분류기의 demographic parity 값이나 전체 공정성 판정으로 동일시하지 않는다.

근거도 주장을 나눠 대조한다. 자체 최신 문서 S는 “도서관 A는 화요일 10시에 개관한다. 화요일 강좌는 유료다.”라고 정한다. 생성 문장 “A는 화요일 10시에 열고 무료 강좌를 연다 [S]”는 시간 절은 지지되지만 무료 절은 반박된다. 하나의 인용이 붙었다고 문장 전체가 지지되는 것은 아니다. “수요일에도 10시에 연다”는 S에 없으므로 정보 부족이다. 주장 단위와 날짜·대상·판본을 보존하고 실제 자동 NLI나 생성기를 실행한 지지 점수라고 부르지 않는다.

먼저 확인할 개념
  • 다양성과 주장별 근거

    주제 폭·공정성·지지/반박/정보 부족을 구별한다.

  • 점수와 사용자 효용

    자체 노출 가중과 실제 만족·선호를 혼용하지 않는다.

순위에 여러 목적이 있다

질의에 맞는 결과를 앞에 두는 것 외에 주제·출처의 다양성과 최신성을 고려할 수 있다. 같은 문서 복제본을 여러 개 보여 주면 항목 수는 늘어도 독립 정보가 늘지 않을 수 있다. 다양성은 정의한 범주의 수나 중복 정도 같은 규약으로 측정한다.

공정성은 어떤 집단이 어떤 기회와 품질을 받는지 묻는 다른 질문이다. 주제 두 개가 포함됐다고 모든 제공자나 사용자 집단이 공정하게 대우받았다고 확정하지 않는다. 노출 수·위치·품질·평가 집단과 지표의 가정을 함께 적는다.

검색과 생성의 증거를 분리한다

RAG는 검색한 문서를 생성의 입력으로 추가하는 방식이다. 문서가 검색됐다는 사실과 생성 문장이 그 문서로 지지된다는 사실은 다르다. 인용 번호가 존재해도 주장에 필요한 정보가 실제 본문에 있는지 대조해야 한다.

출처·판본·시점·범위와 근거 문장을 보존한다. 문서에서 반대 사실이 명시되면 반박이고 관련 정보가 없으면 정보 부족이다. 정보 부족을 세계 전체에서 거짓이라는 결론으로 바꾸지 않는다. 자동 지지 평가도 오류와 조건이 있으므로 원문 확인을 대신하는 완전 보장은 아니다.

더 가져오는 것만으로 해결되지 않는다

한정한 context에 복제본만 많이 넣으면 다른 관점을 담을 공간이 줄 수 있다. 후보 검색과 재정렬·중복 제거·근거 확인·답변 범위의 계약을 나누어 평가한다. 필요한 자료를 찾지 못하면 부족함을 드러내는 답변 정책도 정한다.

검색 다양성·답변 정답성·인용 지지는 별도 지표다. 모든 출처가 독립이거나 참이라는 보장은 없으며 서로 모순하면 조건을 확인한다. 아래는 자체 자료 세 문장과 목록을 사람이 대조한 것으로 실제 검색 모델이나 생성기를 실행하지 않았다.

중간 과정을 따라가는 예제

  1. 원순위의 주제 집합은 {P,Q}로 2개라서 coverage=2/3이다.

  2. 대안은 {P,Q,R}로 3개라서 coverage=1이다.

  3. 이는 주제 폭의 지표다. c/d의 질의 적합도를 주지 않았으므로 대안이 정확성이나 전체 공정성에서도 더 좋다고 단정하지 않는다.

원순위 2/3, 대안 1이다. 서로 다른 주제 수를 분모 3으로 나눈다.

① 같은 문서 ID와 같은 내용 판본을 나눈다. ② 선호와 λ의 곱을 맞춘다.

힌트 2

③ 전체 위치 가중합은 11/6이다. ④ 날짜·요금과 실제 근거의 범위를 대조한다.

풀이와 답 확인

  1. ① ID만 교집합하면 {d}지만 판본 키 {(d,v1)}∩{(d,v2)}는 비어 있다. 삭제 v2 뒤 도착 v1은 1<2라 적용하지 않는다.

  2. ② 두 정책 모두 (8,11,7)이고 순위는 b,a,c다. 선호 척도와 λ를 함께 조정했다.

  3. ③ 앞 순위 X/Y는 9/11·2/11, 뒤 순위는 8/11·3/11이다. 문서 개수와 주제 coverage가 같아도 위치 가중은 달라진다.

  4. ④ 화요일10시 개관은 지지, 화요일 무료는 유료 문장에 반박, 수요일10시는 정보 부족이다. 세 절을 하나의 완전 지지 문장으로 합치지 않는다.

문서 상태, 점수 척도, 위치 노출과 주장별 근거는 별도 계약과 증거가 필요하다. 실제 검색 서버·계정 설정·개인정보·시선/클릭·RAG/NLI·학생 실험은 미수행이다.

해결한 뒤 점검할 것

  • 단일 판본 내용과 혼합 ID 결합을 구별한다.

  • 선호 척도와 λ의 곱을 같은 조건으로 비교한다.

  • 개수·주제·위치 가중과 전체 공정성을 나눈다.

  • 주장별 지지·반박·정보 부족을 실제 지정 문장으로 설명한다.
