소단원 4.1

외부정렬 색인

사전보다 큰 문서 기록을 메모리 밖에서 어떻게 정리할까?

준비 개념과 학습 목표

준비 개념

  • 역색인은 단어에서 그 단어가 있는 문서 ID 목록으로 간다.

  • (termID,docID) 쌍은 단어 번호와 문서 번호를 함께 기록한다.

  • 외부정렬은 모든 레코드가 메모리에 동시에 들어오지 않을 때 파일과 작은 버퍼를 사용한다.

학습 목표

  • 블록 정렬과 여러 정렬 결과의 병합을 종이로 추적한다.

  • 중복 처리와 I/O 비용의 계산 범위를 명시한다.

동시에 읽을 파일 수가 작으면 병합을 몇 번 해야 할까?

새 비용 모형은 중복 없는 (termID,docID) 레코드 20개이며 레코드당 8바이트다. 첫 정렬은 네 레코드씩 모아 다섯 정렬 파일을 만든다. 모든 레코드는 같은 전역 단어·문서 번호 계약을 사용한다. 압축·사전·큐·메타데이터·물리 장치의 블록 크기는 전송량 계산에서 제외한다. 원자료와 각 정렬 단계의 전체 크기는 20×8=160바이트로 같다.

한 번에 최대 두 파일을 합치는 단계별 정책을 정한다. 남은 단독 파일도 새 단계 파일로 전부 복사한다. 따라서 파일 수는 5→3→2→1로 줄고 병합 단계가 세 번이다. 각 단계는 전체 160바이트를 읽고 160바이트를 쓴다. 최초 블록 생성도 원자료 160바이트 읽기와 정렬 파일 160바이트 쓰기가 있어 총 논리 전송량은 320+3×320=1,280바이트다.

한 번에 세 파일을 합치면 5→2→1로 병합 단계가 두 번이어서 같은 복사 정책에서는 960바이트다. 그러나 입력 파일마다 읽기 버퍼와 출력 버퍼가 필요해 동시에 쓰는 버퍼 수는 두 입력의 3개에서 세 입력의 4개로 늘어난다. 단독 파일을 그대로 다음 단계에 넘기는 다른 정책은 전송량이 달라질 수 있다. 이 장부는 정한 모형의 바이트이며 실제 디스크 시간이나 전체 메모리 사용량이 아니다.

먼저 확인할 개념
  • 블록 정렬과 다중 병합

    한 단계의 버퍼 한계가 전체 병합 단계 수에 미치는 영향을 계산한다.

  • 전역 term·문서 ID와 posting

    모든 정렬 파일이 같은 키 계약을 사용하고 중복 없는 레코드를 보존한다.

문서 순서에서 단어 순서로

문서를 읽으면 문서 하나의 여러 단어를 먼저 보게 된다. 역색인은 같은 단어의 문서들을 모아야 하므로 (단어,문서) 쌍을 단어 우선·문서 다음 순서로 정리한다. 단어 문자열을 정수 termID 로 바꾸는 장부는 모든 블록에서 같은 번호를 사용해야 한다. 블록마다 1 을 다른 단어에 붙이면 병합이 틀린다.

여기서는 단어 존재 여부만 담는 Boolean 색인을 만든다. 같은 단어가 같은 문서에 여러 번 나타나도 docID 는 한 번만 넣는다. 빈도와 위치를 담는 색인은 반복을 그냥 버리면 안 되며 빈도를 합치거나 위치 목록을 병합하는 별도 계약이 필요하다.

메모리만큼씩 정리한다

메모리에 들어갈 만큼 쌍을 수집해 단어·문서 순으로 정렬하고 같은 단어를 묶어 문서 목록을 만든다. 이 블록 결과를 파일로 저장한 뒤 버퍼를 비우고 다음 블록을 읽는다. 전체 자료가 메모리보다 커도 각 블록의 정렬은 가능하다. termID 사전과 출력 버퍼도 메모리에 포함해야 한다.

각 블록 파일은 이미 정렬되어 있다. 여러 파일의 현재 맨 앞 레코드 중 가장 작은 것을 꺼내 출력하고 그 파일의 앞을 한 칸 진행한다. 우선순위 큐를 쓰면 어떤 파일이 다음인지 선택할 수 있다. 각 파일의 작은 읽기 버퍼와 출력 쓰기 버퍼로 순차 접근을 유지한다.

경계를 넘는 중복도 검사한다

블록 안에서 중복을 제거해도 같은 쌍이 다른 블록에 남을 수 있다. 최종 병합에서 마지막 출력 쌍과 다음 쌍이 같으면 Boolean 계약에 따라 하나로 합친다. termID 가 바뀌면 이전 단어의 목록을 끝내고 다음 목록을 시작한다. 정렬 결과의 문서 ID 는 증가하도록 남긴다.

작은 파일이 매우 많아 한 번에 모든 버퍼를 둘 수 없다면 몇 개씩 병합하는 여러 단계가 필요하다. 레코드를 읽고 쓴 총바이트와 비교 횟수는 서로 다른 비용이다. 실제 디스크 속도는 접근 방식과 압축·버퍼·하드웨어에 좌우되므로 종이 바이트 수를 실행 시간으로 단정하지 않는다.

중간 과정을 따라가는 예제

Boolean 색인이다. 블록 1=[(2,3),(1,2),(2,1),(1,2)], 블록 2=[(1,4),(2,3),(1,1),(3,2)]를 정렬하고 최종 문서 목록을 만들어라.

  1. 블록 1 정렬은 (1,2),(1,2),(2,1),(2,3)이다. Boolean 중복 제거 후 (1,2),(2,1),(2,3)이다.

  2. 블록 2 정렬은 (1,1),(1,4),(2,3),(3,2)이며 블록 내부 중복은 없다.

  3. 앞 레코드를 비교하여 (1,1),(1,2),(1,4)를 출력한다. 그 다음 단어 2 의 (2,1),(2,3),(2,3)에서 두 파일의 중복도 합친다.

조건을 바꾸어 비교하기

두 파일씩 단계별 병합

다섯 정렬 파일을 두 개씩만 병합한다. 단독 파일도 복사할 때 전체 논리 전송량을 구하라.

  1. 첫 단계에서 두 쌍과 단독 하나가 세 파일이 된다. 다음에는 한 쌍과 단독 하나가 두 파일이 된다. 마지막 두 파일을 합친다.

  2. 매 단계 읽기 160바이트와 쓰기 160바이트로 320바이트다.

  3. 최초 생성 320바이트와 세 병합 단계 960바이트를 합친다.

총 1,280바이트다.

비교할 점

모든 입력 파일이 메모리 밖에 있다고 한 번 병합만으로 끝낼 수 있는 것은 아니다.

버퍼 하나를 더 쓸 수 있는 경우

세 입력 파일을 함께 합칠 수 있으면 파일 수와 전송량은?

  1. 다섯 파일은 세 개와 두 개로 묶여 두 파일이 된다.

  2. 두 파일을 한 파일로 합쳐 병합이 두 단계다.

  3. 최초 생성과 두 병합 단계의 전송량은 3×320=960바이트다.

이 정책에서는 320바이트를 덜 옮기지만 입출력 버퍼는 4개가 필요하다.

비교할 점

전송량을 줄이는 계획에도 다른 자원의 제약이 있다. 실제 시간 우위를 여기서 측정하지 않았다.

종이와 본문으로 직접 해보기

비용만 보는 별도 모형: 중복 없는 쌍 8 개, 쌍당 8 바이트, 한 번 블록 생성 후 한 번 병합, 압축·사전·메타데이터 제외다. 입력 읽기·블록 쓰기·블록 읽기·최종 쓰기의 합을 계산하라.

힌트 보기

연습 1 · 값과 상태 예측

두 입력 상한 모형에서 최초 생성 직후 정렬 파일 크기 합과 한 병합 단계의 읽기·쓰기 합을 구하라.

힌트 1

전체 레코드가 중복 없이 20개다.

힌트 2

각 단계에서 줄어드는 것은 파일 수이지 레코드 수가 아니다.

풀이와 답 확인

  1. 파일 크기 합은 20×8=160바이트다.

  2. 한 단계의 읽기·쓰기 합은 160+160=320바이트다.

160바이트와 320바이트다.

흔한 오답에서 다시 생각하기

파일 수가 절반이 되면 레코드 수도 절반이 된다.

서로 다른 레코드를 병합해 한 파일에 모을 뿐 없애지 않는다.

연습 2 · 오류 찾아 고치기

다섯 파일이 있으니 읽기 버퍼 두 개만으로 한 번에 다섯 방향 병합을 할 수 있다고 주장했다.

힌트 1

동시에 유지할 각 파일의 다음 후보를 확인한다.

힌트 2

현재 제약은 최대 두 파일의 동시 입력이다.

풀이와 답 확인

  1. 주어진 모형의 동시 입력 상한은 2다.

  2. 추가 접근 방식이나 버퍼 정책을 설명하지 않고 다섯 방향 병합으로 바꿀 수 없다.

단계별 5→3→2→1 계획을 사용하거나 다른 자원 정책을 명시해야 한다.

흔한 오답에서 다시 생각하기

병합 파일이 정렬되어 있으니 나머지 세 파일의 후보는 보지 않아도 된다.

보지 않은 파일의 다음 레코드가 전체 최소일 수 있다.

연습 3 · 직접 만들어 보기

한 단계당 읽기 버퍼와 쓰기 버퍼를 포함한 자원 장부를 설계하라.

힌트 1

동시 입력 파일 수와 각 버퍼 크기를 둔다.

힌트 2

사전·큐·정렬 공간을 빠뜨리지 않는다.

풀이와 답 확인

  1. 동시 입력 수 k, 각 읽기 버퍼 크기 r, 출력 버퍼 크기 w를 기록한다.

  2. 병합 버퍼는 k×r+w이며 사전·큐·기타 저장은 별도 항목으로 더한다.

  3. 최초 정렬 단계의 정렬 공간과 병합 단계의 버퍼가 동시에 필요한지도 생명주기를 확인한다.

버퍼 개수와 실제 바이트 사용량 및 단계별 최고 사용량을 구별한다.

흔한 오답에서 다시 생각하기

버퍼 네 개라는 숫자가 메모리 네 바이트를 뜻한다.

버퍼 크기가 따로 필요하다. 개수와 크기는 다른 단위다.

연습 4 · 선택 심화

선택 심화는 기본 연습 뒤 더 탐구하고 싶을 때 풀어 보세요.

힌트 1

힌트 2

한 파일이 될 때까지 반복한다.

풀이와 답 확인

  1. 10→4→2→1이다.

  2. 병합 단계는 세 번이다.

단계 수는 입력 상한과 최초 파일 수 모두에 의존한다.

소단원 4.2

gap encoding

큰 문서 번호들을 작은 차이로 바꾸면 무엇이 달라질까?

준비 개념과 학습 목표

준비 개념

  • 문서 ID 는 여기서 양의 정수이고 목록은 엄밀히 증가한다.

  • 차이는 다음 번호−이전 번호다.

  • 바이트는 8 비트이며 이 코드는 7 비트를 정수 데이터로 사용한다.

학습 목표

  • gap 변환과 역변환을 계산한다.

  • 종료 비트 관례에 맞는 가변 바이트를 해독한다.

압축 목록의 아무 바이트부터 읽어도 문서번호를 알 수 있을까?

새 증가 문서 목록은 [100,101,229,230]이다. 첫 값은 절대 번호이고 다음은 gap이므로 [100,1,128,1]이다. 본문의 높은 비트 1이 마지막이라는 관례에서 16진 바이트는 E4 81 01 80 81이며 길이는 5바이트다. 바이트 위치는 0부터 세며 gap 128은 위치 2와 3의 두 바이트에 걸친다.

위치 3의 80부터 단독 해독하면 정수 0이 나온다. 하지만 그것은 원래 정수 128의 뒷부분이다. 바이트 경계라고 모두 정수 시작 경계는 아니다. 올바른 시작 위치 2의 01 80을 읽어 128을 얻어도 이전 문서번호 101이 있어야 229를 복원한다. 코딩 경계와 누적 기준 번호가 둘 다 필요하다.

별도 체크포인트를 세 번째 문서의 절대 번호 229와 다음 gap의 바이트 위치 4로 정한다. 두 항목을 각각 32비트 무부호 값으로 저장하면 보조 비용이 8바이트다. 문서 데이터 5바이트와 합하면 13바이트라 고정 32비트 네 문서의 16바이트보다 3바이트만 작다. 체크포인트에서 네 번째 gap 1을 읽으면 230이다. 이는 하나의 지정 장부이며 실제 저장 포맷·손상 검출·메모리 배치를 실행하지 않았다.

차이는 앞 번호와 함께 읽는다

[3,130,131,260]을 [3,127,1,129]로 바꿀 수 있다. 첫 값은 절대 번호, 그 다음 값들은 이전 번호와의 양의 차이다. 첫 값부터 누적 합을 하면 원래 목록이 돌아온다. 정렬이 없으면 양수 차이 조건이 깨지므로 문서 목록을 먼저 정리한다.

문서가 자주 나타나는 단어는 번호 사이 간격이 작을 가능성이 있다. 하지만 모든 gap 이 작다고 보장하지 않는다. 희귀한 단어의 문서들이 멀리 떨어지면 큰 gap 이 생긴다. 값을 차이로 바꾼 뒤에도 매 값에 같은 32 비트를 쓰면 바이트 수는 줄지 않는다.

7 비트씩 담고 마지막을 표시한다

여기서는 Stanford 교재 관례를 사용한다. 한 바이트의 높은 비트는 마지막 바이트이면 1, 아직 뒤가 있으면 0 이다. 나머지 7 비트가 payload 다. 정수를 128 진 자리로 분해하여 높은 자리부터 쓰고 마지막 바이트에만 128 을 더한다. 다른 코딩은 종료 비트 방향이나 자리 순서가 다를 수 있다.

127 은 payload1111111 에 마지막 표시를 붙여 11111111 즉 255 다. 128 은 1×128+0 이라 첫 바이트 00000001, 마지막 10000000 으로 두 바이트다. 같은 코드를 해독할 때 payload 를 읽으며 v←128v+payload 를 하고 높은 비트 1 에서 한 정수를 끝낸다.

압축과 접근 비용을 함께 본다

큰 정수일수록 더 많은 바이트가 필요하다. 값 0 도 이 코딩에서는 10000000 으로 표현되지만 현재 엄밀히 증가한 양의 문서 목록의 gap 에는 0 이 나타나지 않는다. 중복을 0 으로 허용하는 계약과 혼용하지 않는다. 파일 끝에서 마지막 표시가 없으면 불완전한 자료다.

gap 만 연속 저장하면 뒤 문서 번호를 알아내려면 앞의 누적 합이 필요하다. 임의 위치부터 읽으려면 절대 번호의 체크포인트와 해당 바이트 경계 같은 보조 정보가 필요하다. 위치·빈도·사전·체크포인트 비용은 문서 ID 압축 비용과 별도로 세어야 한다.

중간 과정을 따라가는 예제

문서 목록 [3,130,131,260]을 gap 으로 바꾼 뒤 이 관례의 가변 바이트로 표현하라. 각 문서 번호를 32 비트 저장한 경우와 비교하라.

  1. gap 은 첫 3, 130−3=127, 131−130=1, 260−131=129 로 [3,127,1,129]다.

  2. 3→10000011(0x83), 127→11111111(0xFF), 1→10000001(0x81)이다.

  3. 129=1×128+1 이므로 00000001,10000001(0x01,0x81)이다.

  4. 전체 바이트는 83 FF 81 01 81(16 진)로 5 개다. 고정 32 비트는 4×4=16 바이트다. 절약 11 바이트이며 11/16=68.75%다.

  5. 해독한 정수 3,127,1,129 의 누적 합은 3,130,131,260 으로 돌아온다.

문서 ID 데이터만 5 바이트 대 16 바이트다. 전체 색인의 68.75% 절약을 뜻하지 않는다.

문서 데이터 5바이트에 절대 ID 229와 다음 바이트 위치 4를 각각 4바이트로 저장한다. 고정 16바이트와 비교하라.

  2. 전체 지정 비용은 5+8=13바이트다.

  3. 절약은 16−13=3바이트다.

이 장부에서 절약률은 3/16=18.75%다. 데이터만 비교한 11/16과 다르다.

소단원 4.3

증분갱신과 저장비용

새 문서 한 개 때문에 거대한 색인을 매번 다시 써야 할까?

준비 개념과 학습 목표

준비 개념

  • 물리 문서 ID 와 사람에게 보이는 논리 문서 ID 를 구별한다.

  • 삭제 표시는 파일에서 즉시 바이트를 없애는 것과 다르다.

  • MiB 는 2²⁰바이트다.

학습 목표

  • 주·보조 색인과 삭제 표시의 검색 결과를 추적한다.

  • 병합 중의 최고 저장량을 계산한다.

최신 삭제표와 옛 색인을 섞으면 최신 검색이 될까?

새 세대 G0의 물리 문서는 10=sun, 20=moon이고 살아 있는 집합은 {10,20}이다. 논리 문서 D의 옛 버전은 20이다. G1에서는 D를 새 물리 버전 30=sun으로 바꾸고 20을 삭제 표시한다. 주 색인의 옛 목록은 그대로 두며 보조 색인에 sun의 30을 추가하고 살아 있는 집합은 {10,30}이다. G0의 moon 결과는 {20}, G1의 moon 결과는 빈 집합이다.

G0의 색인에 G1의 살아 있는 집합만 적용하면 moon은 사라지지만 sun은 {10}으로 남아 새 버전 30을 놓친다. 이 혼합 결과는 G0와도 G1과도 같지 않다. 질의별로 주·보조 파일 목록, 살아 있는 버전, 문서 매핑과 통계를 같은 세대 계약으로 묶어야 한다. 이것은 필요한 일관성의 모형이며 실제 원자 전환·동시성·장애 복구를 구현했다고 주장하지 않는다.

저장량도 읽고 있는 세대의 수명을 고려한다. 별도 크기 모형에서 옛 주 파일 48MiB와 보조 파일 4MiB를 유지하고 완성된 새 파일 45MiB와 계속 보존하는 로그 2MiB를 함께 둔다. 전환 직전 최고량은 99MiB다. 새 파일은 보조와 삭제를 모두 반영했다고 정한다. G0 독자만 옛 주 파일을 계속 읽고 G1 독자는 없으면 보조 4MiB를 제거한 뒤 95MiB지만, 옛 주 48MiB는 G0 독자가 끝날 때까지 보존한다. 그 후 남는 양은 47MiB다.

  • 문서 ID의 정체성과 버전

    논리 문서 D와 서로 다른 물리 버전 20/30을 구별한다.

작은 변화는 보조 색인에 모은다

큰 주 색인을 두고 새 문서의 postings 를 작은 보조 색인에 모은다. 질의는 두 색인의 결과를 합쳐 중복을 제거한다. 삭제된 문서 ID 의 표시는 두 결과에 모두 적용한다. 한쪽만 검색하거나 한쪽에만 삭제 필터를 적용하면 새 문서를 빠뜨리거나 삭제 문서를 되살릴 수 있다.

삭제 표시는 물리 데이터가 남아 있어도 논리적으로 결과에서 제외한다. 문서 수정은 이전 물리 버전을 삭제 표시하고 새 내용을 새 물리 ID 로 색인하는 모형을 사용할 수 있다. 화면의 논리 문서 ID 와 내부 버전 ID 를 혼동하지 않도록 매핑을 유지한다.

병합이 비용을 옮긴다

보조 색인이 커지면 주 색인과 합쳐 새 주 색인을 만든다. 정렬 목록을 병합하면서 삭제 버전과 중복을 걸러낸다. 병합 중 사용자가 읽는 이전 세대는 일관된 채 남겨 두고 완성한 새 세대로 전환한다. 실패 시 불완전한 파일을 정식 색인으로 취급하지 않는 정책이 필요하다.

자주 병합하면 보조 검색이 작아지지만 큰 파일을 반복 읽고 쓴다. 드물게 병합하면 구축 비용을 줄일 수 있지만 질의가 여러 곳을 찾고 삭제 기록도 늘어난다. 로그 크기 계층은 비슷한 크기 파일끼리 합쳐 누적 부담을 나누는 방식이며 모든 검색과 통계 비용이 공짜가 되지는 않는다.

사용량은 작업 중에도 센다

이전 주 색인과 보조 파일을 유지한 상태에서 새 파일을 완성하면 잠시 세 종류가 함께 있다. 새 파일 최종 크기만 보고 필요한 저장 공간을 정하면 병합 중 부족할 수 있다. 임시 파일, 복제본, 사전과 버퍼의 포함 여부도 명시한다.

삭제가 많으면 물리 문서 수와 살아 있는 문서 수가 다르다. 결과 필터뿐 아니라 랭킹의 문서 빈도·전체 문서 수도 어떤 버전의 어떤 집합인지 정해야 한다. 오래된 수치와 최신 postings 를 섞으면 순위가 일관되지 않을 수 있다. 이 단원은 실제 서버 동시성이나 장애 복구 구현을 시험하지 않았다.

중간 과정을 따라가는 예제

주 색인 cat=[1,3], dog=[2]; 보조 cat=[4], dog=[5]; 삭제표시={3}이다. 이후 논리 문서의 옛 물리 버전 2 를 삭제하고 새 물리 버전 6 에 cat 만 있다고 색인한다. 각 단계 검색 결과를 구하라.

  1. 처음 두 cat 목록 합집합은{1,3,4}이며 삭제 3 을 제외해{1,4}다. dog 는{2,5}다.

  2. 수정은 옛 물리 ID2 를 삭제표시에 추가하고 새 물리 ID6 을 보조 cat 에 넣는다. 삭제표시는{2,3}이다.

  3. cat 합집합{1,3,4,6}에서 삭제를 빼면{1,4,6}이다. dog 합집합{2,5}에서 삭제 2 를 빼면{5}다.

  4. 논리 문서는 버전 매핑으로 결과에 표시한다. 옛 ID2 와 새 ID6 을 별개 내용 버전으로 처리했으므로 옛 dog 항목은 남지 않는다.

처음 cat=[1,4], dog=[2,5]; 수정 후 cat=[1,4,6], dog=[5]. 삭제된 버전은 주 색인에 남아 있어도 검색에서 제외된다.

주·보조 파일과 live 및 매핑·통계의 일관된 묶음이 필요하다.

옛 독자를 보존한 저장량

크기 모형의 전환 직전, G0 독자가 남은 뒤, 그 독자까지 끝난 뒤의 사용량을 계산하라.

  1. 전환 직전은 48+4+45+2=99MiB다.

  2. G1 독자가 없고 보조 파일이 새 파일에 반영된 뒤 이를 제거하면 48+45+2=95MiB다.

  3. G0 독자가 끝나 옛 주 파일도 안전하게 회수하면 45+2=47MiB다.

99→95→47MiB다. 로그 2MiB는 이 모형에서 계속 보존한다.

최종 파일이 작다는 사실은 전환 중 최고량과 안전한 회수 시점을 결정하지 않는다.
