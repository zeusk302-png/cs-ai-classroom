크롤링과 중복

주소가 다르면 검색 시스템도 꼭 다른 내용을 저장해야 할까?

준비 개념과 학습 목표

준비 개념

학습 목표

  • 작은 shingle 집합의 Jaccard를 계산한다.

A가 B와 비슷하고 B가 C와 비슷하면 A와 C도 비슷할까?

자체 토큰 문서는 A="red blue green", B="red blue green white", C="blue green white"다. k=2의 연속 토큰 집합은 A={red blue,blue green}, B={red blue,blue green,green white}, C={blue green,green white}다. Jaccard는 A·B=2/3, B·C=2/3, A·C=1/3이다. 근사 중복 조건을 J≥0.6으로 정하면 앞 두 쌍만 통과한다.

통과한 쌍의 연결을 따라 같은 그룹으로 묶으면 A·B·C가 하나의 연결 성분이 된다. 이 그룹화 자체는 가능한 정책이지만 모든 그룹 구성원 쌍이 임계값을 통과한다는 뜻은 아니다. 대표를 A로 고르면 C는 대표와 임계값을 만족하지 않고, B로 고르면 A와 C가 모두 대표와 만족한다. 대표와의 유사성 요구와 모든 쌍의 유사성 요구는 다르다.

중복 제거가 중요한 단어 차이까지 버리는지 확인한다. white나 red 차이를 무시할지는 질의 목적에 따라 달라진다. 원문·URL·수집 버전·토큰화·k·임계값과 그룹 정책을 보존한다. 해시는 후보를 빠르게 찾는 요약일 뿐 정확 동일성이 필요한 경우 실제 내용 비교를 남긴다. 이 집합 계산은 실제 크롤링이나 의미 동일성 판정이 아니다.

주소를 발견하고 내용을 가져오기

크롤러는 시작 URL에서 페이지를 가져오고 텍스트와 링크를 해석한다. 발견한 주소는 앞으로 가져올 frontier에 넣는다. 이미 본 주소 기록과 호스트별 요청 간격을 두면 같은 주소 반복과 과도한 요청을 줄일 수 있다. 링크 발견만으로 실제 가져오기 성공이나 색인 완료를 의미하지 않는다.

크롤링은 수집, 색인은 문서에서 검색 가능한 구조를 구성하는 일, 검색은 질문에 맞는 결과를 고르는 일이다. 주소가 존재해도 권한·오류·지원하지 않는 내용 등으로 문서 내용을 얻지 못할 수 있다. 연속 크롤링은 새 주소 발견과 이전 주소 재방문을 함께 다룬다.

같은 주소와 같은 내용은 다르다

하나의 문서는 여러 주소에 있을 수 있고 같은 주소의 내용은 시간에 따라 바뀔 수 있다. 주소 중복 제거와 내용 중복 제거는 별개다. 문자 내용을 요약한 지문이나 해시는 빠른 후보 탐색에 도움이 되지만 유한 지문의 충돌 가능성을 고려해 정확한 동일성이 필요하면 실제 내용을 확인한다.

날짜 한 줄만 다른 내용은 완전히 같은 바이트는 아니어도 검색 결과 중복일 수 있다. 반대로 비슷한 문구라도 가격·조건·버전 차이는 사용자에게 중요할 수 있다. 어떤 차이를 무시하는 전처리와 대표 문서 선택을 쓰는지 명시해야 한다.

근사 중복을 수치로 보기

k-shingle은 문서의 연속 k개 단어 묶음들의 집합이다. 같은 묶음이 반복되어도 집합에는 한 번만 들어간다. Jaccard는 |S₁∩S₂|/|S₁∪S₂|이고 합집합이 비어 있지 않을 때 정의된다. 두 집합이 빈 경우에는 별도 관례를 정해야 한다.

임계값은 판정 규칙의 선택이다. 비슷한 문자열이 같은 의미라는 증명도, 저작권 판단도 아니다. 이 단원은 공백 토큰이 이미 주어진 짧은 자체 문서와 정확한 집합 계산만 사용한다. 실제 사이트 크롤러나 대규모 중복 탐지를 실행하지 않았다.

A–B–C로 연결되더라도 A·C의 정확 Jaccard가 커지는 것은 아니다. 연결 성분의 의미와 쌍 조건을 구별한다.

중간 과정을 따라가는 예제

토큰 문서 D₁="red blue green yellow", D₂="red blue green white"를 k=2로 묶자. Jaccard와 J≥0.5라는 자체 근사 중복 규칙을 적용하자.

  1. S₁={red blue,blue green,green yellow}다.

  2. S₂={red blue,blue green,green white}다.

  3. 교집합은2개, 합집합은4개이므로 J=2/4=0.5다.

  4. 이번 규칙은 ≥이므로 근사 중복 후보로 분류한다. 완전히 같은 문서는 아니다.

J=0.5로 자체 임계값을 만족한다. yellow와 white 차이가 중요하면 대표 하나만 남기는 선택은 다시 검토해야 한다.

조건을 바꾸어 비교하기

연결 그룹의 한계

통과 쌍을 간선으로 놓으면 그룹과 A·C의 조건은?

  1. A–B와 B–C 간선이 있으므로 세 노드는 같은 연결 성분이다.

  2. A·C의 교집합은 blue green 하나, 합집합은 세 묶음이다.

연결 그룹은 하나지만 A·C의 J=1/3은 조건을 만족하지 않는다.

비교할 점

그룹을 만들었다는 사실만으로 모든 쌍의 조건을 인증하지 않는다.

대표 선택에 따른 조건

모든 구성원이 대표와 J≥0.6이어야 한다면 A와 B 중 어느 대표가 이 그룹에서 맞는가?

  1. A 대표는 C와 1/3이라 요구를 어긴다.

  2. B 대표는 A와 C 각각 2/3이라 요구를 만족한다.

이 모형에서는 B 대표가 지정 대표 조건을 만족한다. 모든 쌍 조건까지 만족하는 것은 아니다.

비교할 점

그룹 정책의 성공 조건을 먼저 명시한다.

종이와 본문으로 직접 해보기

D₃="red blue green yellow"와 D₄="red blue red blue"의 k=2 집합과 J를 구하자. 반복 red blue를 여러 번 세면 되는가?

힌트 보기

D₄의 집합은 두 묶음만 남는다.

풀이 보기

S₃={red blue,blue green,green yellow}, S₄={red blue,blue red}다. 교집합1, 합집합4이므로 J=1/4이다. red blue 반복은 집합에서 한 번만 센다. 앞의 J≥0.5 규칙을 만족하지 않는다.

오해와 반례

서로 다른 URL이면 내용 중복이 아니다.

거울 사이트나 여러 경로가 같은 내용을 제공할 수 있다. 주소 동일성은 내용 동일성을 보장하지 않고 그 반대도 아니다. 시간과 응답 내용을 함께 확인해야 한다.

연습 1 · 값과 상태 예측

임계값을 J≥0.7로 바꾸면 통과 쌍과 연결 그룹은?

힌트 1

2/3≈0.6667이다.

힌트 2

다른 쌍은 1/3이다.

풀이와 답 확인

  1. 세 쌍 모두 0.7 미만이다.

  2. 간선이 없어 A·B·C는 각각 단독 그룹이다.

세 그룹이다. 같은 문서도 임계값 정책에 따라 그룹이 달라진다.

흔한 오답에서 다시 생각하기

0.6에서 연결되었으니 0.7에서도 그대로 연결이다.

임계값을 바꿨으면 쌍 조건을 다시 적용해야 한다.

연습 2 · 오류 찾아 고치기

같은 그룹에 있으므로 A·C도 J≥0.6이라는 보고를 고쳐라.

힌트 1

A·C의 원래 집합을 직접 비교한다.

힌트 2

연결 경로와 직접 간선을 구별한다.

풀이와 답 확인

  1. A·C의 J는 1/3이다.

  2. B를 거친 연결 경로가 있다는 사실은 직접 쌍 조건의 증명이 아니다.

연결 그룹이라는 상태와 임계값 통과 쌍을 별도 기록한다.

흔한 오답에서 다시 생각하기

비슷함이라는 말은 항상 동치관계다.

이 임계값 기반 근사 유사성은 추이적이지 않을 수 있다.

연습 3 · 직접 만들어 보기

대표와의 유사성 조건을 확인할 그룹 장부를 설계하라.

힌트 1

대표 ID와 각 구성원의 원문 버전을 남긴다.

힌트 2

쌍 점수와 전체 그룹 정책을 구별한다.

풀이와 답 확인

  1. 토큰화·k=2·J≥0.6을 고정한다.

  2. 대표 B와 A/B, B/C의 점수 2/3을 기록한다.

  3. A/C=1/3도 남겨 모든 쌍 조건은 만족하지 않음을 표시한다.

원문을 삭제하기 전에 중요한 내용 차이와 복구할 참조를 보존한다. 실제 삭제는 수행하지 않았다.

흔한 오답에서 다시 생각하기

대표가 있으면 구성원의 내용 차이는 검사할 필요 없다.

대표 선택은 정보 손실 가능성을 자동으로 없애지 않는다.

출력 링크 없는 페이지의 확률은 어디로 보낼까?

자체 두 페이지 A→B이고 B에는 출력 링크가 없다. 링크 이동 확률 d=0.8, 균등 순간이동 확률 0.2다. B의 링크 이동 부분도 두 페이지에 균등 분배한다. 행은 현재 페이지, 열은 다음 페이지로 정하면 S의 행은 A=(0,1), B=(0.5,0.5)이고 P=0.8S+0.2U의 행은 A=(0.1,0.9), B=(0.5,0.5)다. 두 행의 합이 모두 1이다.

행 확률 벡터 (a,b)의 한 단계 갱신은 (0.1a+0.5b,0.9a+0.5b)다. 정지 조건 a=0.1a+0.5b와 a+b=1을 풀면 (a,b)=(5/14,9/14)다. 처음 균등 (0.5,0.5)에서 세 번 계산하면 (0.3,0.7)→(0.38,0.62)→(0.348,0.652)다. 첫 갱신 결과가 이미 정지분포라는 뜻은 아니다.

B의 출력 링크가 없다는 이유로 S의 B 행을 (0,0)으로 놓고 나머지 식만 적용하면 잘못된 P의 B 행은 (0.1,0.1)이어서 합이 0.2다. 균등 시작의 다음 값 (0.1,0.5)은 합이 0.6으로 확률 질량을 잃는다. 사후에 합으로 나누어 숫자를 1로 만드는 것도 원래 지정한 dangling 정책의 전이 행렬을 복구하는 것은 아니다. 행/열 규약과 확률 보존을 먼저 검사한다.

먼저 확인할 개념
  • PageRank 행 전이와 정지분포

    행 합1·rP·πP=π의 규약을 유지한다.

  • 수집 그래프와 노드

    출력 링크가 없는 노드를 삭제하는 것과 재분배하는 정책을 구별한다.

링크를 따라 방문하는 모형

페이지가 다른 페이지로 보내는 링크를 방향 간선으로 본다. 한 기본 PageRank 모형은 확률 d로 출력 링크 하나를 균등 선택하고 1−d로 전체 페이지 중 균등 순간이동한다. 여기서0<d<1이며 d는 원문에서 순간이동 alpha라고 부른 값의1−alpha다. 출력 링크 없는 페이지는 링크 이동 부분도 균등 재분배한다고 정한다.

행 확률 행렬 P에서 행벡터 r의 갱신은 rP다. 정지분포 π는 πP=π이고 합1이다. 연결 신호는 단순히 들어오는 간선 수만 세지 않고 출발 페이지의 질량과 출력 링크 수를 반영한다.

정지 방문 질량과 질문별 답

한 고정 그래프와 순간이동 설정의 PageRank는 질문이 바뀌어도 같다. 반면 선형대수 기초와 오늘의 교통 상황이라는 질문이 필요로 하는 문서는 다르다. 따라서 링크 신호를 질문 관련성·내용·다른 특징과 결합하는 검색 시스템의 한 요인으로 이해한다.

아래0.8와0.2 가중치는 설명을 위해 자체로 정한 산식이다. 실제 Google이나 특정 서비스의 순위 공식을 알아냈다는 뜻이 아니다. 결합하려는 값의 척도와 학습·평가 자료가 달라지면 같은 가중치를 그대로 사용할 근거가 없다.

수집 범위와 조작 가능성

페이지나 링크가 빠진 수집 그래프에서 계산한 점수는 전체 웹에서의 점수와 다를 수 있다. 중복 페이지를 그대로 여러 노드로 세거나 인위적인 링크를 넣으면 그래프가 바뀐다. 점수의 의미를 해석할 때 수집 범위·중복 처리·전이 설정을 남긴다.

높은 연결 점수는 사실 확인이나 질문에 대한 정확한 정답의 증거가 아니다. 아래 숫자는 작은 가상 그래프의 대수 계산이며 실제 검색 엔진 접근·색인 상태·순위 성능을 시험한 결과가 아니다.

늦게 끝난 옛 색인 작업이 최신 결과를 덮어쓰면?

자체 시간선 [0,12)에서 처음 원본·색인은 v0다. 원본은 t=3에 v1, t=6에 v2로 바뀌고 다시 되돌아가지 않는다. t=4에 수집한 v1의 색인 작업은 t=9에 끝나며, t=7에 수집한 v2 작업은 t=8에 끝난다. 완료 순서대로 무조건 적용하는 정책이면 t=8에는 v2로 최신이 되지만 t=9에 뒤늦은 v1이 덮어써 다시 오래된다.

지정 오래됨 척도는 원본과 색인 내용 버전이 다른 시간의 비율이다. [3,8)의 5와 [9,12)의 3을 더하면 총8, 비율8/12=2/3이다. v1과 v2를 구별하더라도 [3,6),[6,8)은 서로 이어진 오래된 구간이므로 중복 합산하지 않는다. 작업이 끝났다는 사실과 최신 내용이 반영됐다는 사실은 다르다.

이미 설치한 v2보다 옛 원본 버전 v1의 결과를 적용하지 않는 별도 단조 버전 정책이면 t=9의 결과를 거부해 오래된 시간은 [3,8)의 5만 남고 비율5/12다. 이 사례는 순서가 있는 자체 원본 버전과 시간선을 명시한 설계 모형이다. 실제 웹의 버전·원자 반영·복구를 구현했다고 주장하지 않는다. 표시 수정 날짜만 바꾸는 일도 원본 내용이나 색인 반영 시점을 바꾸지 않는다.

정당한 참고 링크나 학습자에게 펼쳐 보여주는 힌트를 링크 스팸·숨김 스팸으로 자동 분류하지 않는다. 공식 지침은 순위 조작 목적과 사용자에게 제공하는 내용의 맥락을 구별한다. 신선도 계산과 스팸 판단은 서로 다른 근거이며 이 활동은 어떤 사이트에 조작을 시도하거나 신고하지 않는다.

조작을 의도한 신호

검색 스팸은 사용자나 검색 시스템을 속이거나 순위를 조작하려는 방식과 관련된다. Google 공식 지침은 과도한 키워드 채우기, 순위 목적의 인위적 링크, 검색 엔진과 사용자에게 의도적으로 다른 내용을 보여 주는 cloaking 등을 설명한다. 단어 반복이나 링크가 있다는 사실만으로 모든 문서를 스팸이라고 단정하지 않는다.

광고·후원 링크와 실제 참고 링크는 목적과 처리 조건이 다르다. 이 단원은 조작 기법을 서비스에서 시도하는 활동을 요구하지 않는다. 링크 그래프를 계산할 때 모든 간선을 독립적인 신뢰 추천이라고 해석하지 않는다는 분석 원칙을 다룬다.

원본이 바뀌어도 색인은 늦을 수 있다

실제 페이지 변경 시점, 크롤러가 새 내용을 가져온 시점, 색인에 반영한 시점은 다르다. 수집하지 않은 변화는 기존 색인에 나타나지 않는다. 자주 변하는 문서는 자주 재방문할 필요가 있지만 요청·저장 비용과 호스트 부담도 함께 고려해야 한다.

신선도의 한 가상 척도로 일정 기간 중 색인 내용이 원본과 달랐던 시간 비율을 생각할 수 있다. 이것은 이 단원에서 정의한 척도이며 실제 검색 서비스의 점수 공식이 아니다. 아래는 수집 직후 색인이 즉시 반영된다는 단순 조건을 먼저 둔다.

날짜와 사실은 별도로 확인한다

게시 날짜, 마지막 수정 날짜, 문서가 설명하는 사건 날짜는 다르다. 사용자 표시 날짜와 구조화된 날짜가 일치하도록 기록해야 하며 날짜만 바꾸었다고 내용까지 새로워진 것은 아니다. 공식 Google 지침도 날짜를 여러 신호로 추정하고 표시를 보장하지 않는다고 설명한다.

새로운 내용이 모든 질문에 더 적절한 것도 아니다. 역사 원문이나 기본 수학 정의와 현재 시간표는 필요한 최신성이 다르다. 날짜·내용 변화·출처와 질문 목적을 함께 확인하자. 가상 시간선 계산과 실제 웹 수집·색인·스팸 탐지 시험은 구별한다.

내용·그래프·버전의 보존 조건 점검

세 독립 모형을 계산하라. ① A="red blue green", B="red blue green white", C="blue green white"의 k=2 shingle Jaccard를 구하라. J≥0.6인 쌍의 연결 그룹이 모든 쌍의 통과를 보장하는지 설명하라. ② 그래프는 A→B이며 B에는 출력 링크가 없다. 링크 이동 확률은 0.8이고, dangling 재분배와 순간이동은 균등하다. 전이 행렬 P와 정지분포를 구하라. ③ 원본은 t=3에 v1, t=6에 v2로 변한다. t=4에 수집한 v1 작업은 t=9에 완료되고, t=7에 수집한 v2 작업은 t=8에 완료된다. [0,12)에서 완료 순서 적용과 옛 버전 거부 정책의 오래된 시간을 비교하라.

힌트 1

① A·C의 직접 비교를 생략하지 않는다. ② 각 전이 행 합은1이어야 한다.

힌트 2

③ t=8의 최신 구간 뒤 t=9에 옛 결과가 덮어쓰는지 확인한다.

풀이와 답 확인

  1. ① J(A,B)=2/3, J(B,C)=2/3, J(A,C)=1/3이다. 세 노드는 연결되지만 모든 쌍 임계값을 통과하지 않는다.

  2. ② P의 두 행은 (0.1,0.9),(0.5,0.5)이고 정지분포는 (5/14,9/14)다. 합1과 πP=π를 확인한다.

  3. ③ 완료 순서 적용의 오래된 구간은 [3,8)과 [9,12)다. 길이의 합은 8이고 비율은 2/3이다. 옛 v1을 거부하는 정책의 오래된 구간은 [3,8)뿐이며 길이는 5, 비율은 5/12다.

그룹 연결·확률 질량·완료 시각을 각각 내용 동일성·관련성 확률·원본 최신성으로 과장하지 않는다. 실제 크롤링·검색 순위·스팸 탐지·학생 실험은 미수행이다.

해결한 뒤 점검할 것

  • 정확 집합과 대표·그룹 정책을 구별한다.
