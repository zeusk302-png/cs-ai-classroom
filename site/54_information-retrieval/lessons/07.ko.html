소단원 7.1

오타·철자수정

검색어 한 글자가 틀렸다고 전체 뜻을 바꿔도 될까?

준비 개념과 학습 목표

준비 개념

  • 문자열 접두부

  • 최솟값

학습 목표

  • 편집 비용의 조건을 정한다.

  • 동률 후보와 사용자 의도를 구별한다.

문자열을 바꾸는 작은 작업 세기

단위 비용 Levenshtein 거리는 삽입·삭제·치환으로 한 문자열을 다른 문자열로 바꾸는 최소 작업 수다. 전치는 기본 작업에 포함하지 않는다. 두 문자열 길이 차이는 필요한 삽입/삭제의 하한을 준다.

문자 단위를 코드포인트·자소·단어 중 무엇으로 정하는지도 결과에 영향을 준다. 한국어의 화면상 글자와 내부 유니코드 표현을 혼동하지 말자. 이 단원은 ASCII 소문자만 써서 단위가 분명하다.

접두부의 정답을 큰 문제에 쓰기

D(i,j)는 첫 문자열 i글자와 둘째 문자열 j글자의 최소 비용이다. D(i,0)=i, D(0,j)=j다. 셀은 위+1, 왼쪽+1, 대각선+[두 글자가 다르면 1] 중 최소로 채운다.

전체 표는 길이 m,n에 대해 O(mn) 시간으로 계산할 수 있다. 한 쌍의 거리와 거대한 사전에서 좋은 후보를 찾는 비용은 다르다. 실서비스는 후보 인덱스·언어·문맥 정보를 함께 고려한다.

가까운 철자와 맞는 의도 나누기

거리 최소 후보가 여러 개일 수 있다. 드문 고유명사나 새 용어를 흔한 단어로 자동 교체하면 정확한 질의가 사라질 수 있다. 원질의를 보존하고 제안을 보여주는 방식이 필요한 경우가 있다.

거리 외에 문맥과 사용 빈도 등을 쓰더라도 선택 규칙을 설명해야 한다. 아래는 의도를 맞히는 서비스가 아니라 작은 사전에서 동률이 생기는지 확인하는 문제다.

중간 과정을 따라가는 예제

질의 cat, 사전 후보 cut/cart/dog에서 단위 비용 거리와 최소 후보를 구하라.

  1. cat→cut은 a를 u로 치환해 거리 1이다. 서로 다르므로 0은 불가능하다.

  2. cat→cart는 r 한 글자 삽입으로 1이며 길이 차이 1이 하한이다.

  3. cat→dog의 접두부 표에서 마지막 행은 (3,3,3,3), 마지막 셀 3이다. 세 치환으로 달성된다.

거리 (1,1,3), cut과 cart가 동률이다. 철자 거리만으로 의도는 확정되지 않는다.

종이와 본문으로 직접 해보기

cat→at와 cat→act의 거리를 구하라. 전치는 한 번으로 세지 않는다.

힌트 보기

at에는 첫 c 삭제가 가능하다. act는 한 치환으로 두 위치를 모두 고칠 수 없다.

풀이 보기

cat→at는 1이다. cat→act는 c 삭제 후 두 번째 위치에 c 삽입으로 2다. 길이가 같아 한 삽입/삭제로 끝날 수 없고 한 치환도 부족하므로 2가 최소다.

오해와 반례

한 글자 오타와 두 글자 순서 교환은 모두 거리 1이다.

어떤 편집 작업을 허용하는지에 달려 있다. 여기의 Levenshtein은 전치를 따로 허용하지 않아 cat→act가 2다.

자기점검

D(0,3)은?

답과 이유 보기

3이다.

빈 문자열에 세 글자를 삽입한다.

cat→cart의 하한은?

답과 이유 보기

1이다.

길이가 한 글자 다르다.

동률 후보 중 빈도가 큰 후보는 반드시 의도인가?

답과 이유 보기

아니다.

빈도는 추정 근거이지 사용자 의도 관측이 아니다.

한 단계 더

전치 작업을 별도로 허용하는 거리와 비교하는 표를 만들자. 실제 검색어 수집이나 수정 서비스 실험은 하지 않았다.

소단원 7.2

관련성 피드백

찾은 문서에 관련/무관 표시를 하면 다음 검색은 어떻게 달라질까?

준비 개념과 학습 목표

준비 개념

  • 벡터 평균

  • 내적 점수

학습 목표

  • Rocchio 갱신의 세 항을 구분한다.

  • 음수 좌표와 빈 피드백 집합을 처리한다.

표시한 문서의 중심을 구하기

관련성 피드백은 사용자가 원하는 문서와 그렇지 않은 문서를 표시한 정보를 다음 질의에 반영한다. Rocchio는 관련 문서 벡터의 평균 방향으로 이동하고 비관련 평균에서 멀어지는 방식이다. 원질의도 가중치를 붙여 남긴다.

q_new=αq_0+βmean(D_r)−γmean(D_nr)로 계산한다. 두 집합은 실제 판정한 문서 집합이며 상위 순위라고 자동으로 관련이 되는 것은 아니다. 벡터의 어휘·가중치 공간은 질의와 문서 사이에 같아야 한다.

갱신의 조건 명시하기

집합이 비면 그 집합 평균을 0/0으로 계산하지 않는다. 이 단원은 해당 항을 생략하는 규칙을 사용한다. 음수 단어 가중치는 0으로 잘라서 다음 질의에 사용한다. 이 규칙을 식 계산 후 명시적으로 적용하자.

α·β·γ는 원질의와 피드백을 얼마나 믿을지 정하는 값이다. 학습자의 목표가 다중 주제로 나뉘거나 처음 검색이 전혀 엉뚱하면 하나의 중심으로 이동하는 것이 좋은 답을 보장하지 않는다.

질의 변화와 순위 변화를 연결하기

갱신 벡터를 새 문서들과 같은 점수 규칙으로 비교한다. 아래는 단순 내적이며 cosine 순위를 계산하지 않는다. 피드백 문서의 길이와 가중치가 점수에 영향을 주는 정의를 유지한다.

피드백에 쓴 문서만 다시 평가하면 쉽게 좋아 보일 수 있다. 실제 성능은 피드백에 포함하지 않은 문서·다양한 질의에서 평가해야 한다. 계산 예제는 피드백 공식의 작동을 설명하는 데 한정한다.

중간 과정을 따라가는 예제

q_0=(1,0), 관련 문서는 (1,1),(1,3), 비관련은 (4,0)이다. α=1, β=0.5, γ=0.5다. 새 질의와 후보 A=(1,0), B=(0,1)의 내적 순위를 구하라.

  1. 관련 평균은 (1,2), 비관련 평균은 (4,0)이다.

  2. 원질의+관련항−비관련항=(1,0)+(0.5,1)−(2,0)=(−0.5,1)이다.

  3. 음수 좌표를 0으로 만들면 q_new=(0,1)이고 A 점수 0, B 점수 1이다.

클리핑 후 (0,1)이며 B가 앞선다. 원질의의 내적은 A 1, B 0이었다.

종이와 본문으로 직접 해보기

비관련 표시가 없으면 같은 규칙에서 q_new와 A/B 점수는?

힌트 보기

비관련 평균을 나누지 말고 음의 항을 생략한다.

풀이 보기

q_new=(1,0)+(0.5,1)=(1.5,1)이다. A 1.5, B 1이므로 A가 앞선다.

오해와 반례

관련성 피드백을 넣으면 모든 질의의 precision이 올라간다.

초기 어휘와 관련 문서 군집, 사용자 판정과 평가 표본에 좌우된다. 원문도 성능 향상 가능성을 설명하며 보편적 보장을 주지 않는다.

자기점검

관련 평균의 둘째 좌표는?

답과 이유 보기

2다.

(1+3)/2=2다.

음수 좌표 −0.5는 어떻게 처리했나?

답과 이유 보기

0으로 잘랐다.

이 단원에 명시한 Rocchio 규칙이다.

빈 비관련 집합의 평균을 계산하는가?

답과 이유 보기

아니다. 해당 항을 생략한다.

0으로 나누지 않도록 규칙을 정했다.

한 단계 더

두 관련 문서가 서로 다른 주제 군집이면 하나의 평균이 어떤 정보를 놓치는지 그려보자. 실제 검색 평가나 사용자 판정 수집은 미수행이다.

소단원 7.3

질의확장과 실패

검색어를 더 붙이면 항상 원하는 문서를 많이 찾게 될까?

준비 개념과 학습 목표

준비 개념

  • 집합의 교집합

  • precision과 recall

학습 목표

  • 확장의 근거와 query drift를 구별한다.

  • 가상 판정표로 두 지표를 계산한다.

어휘 차이를 연결하기

질의확장은 동의어·관련 용어 등을 추가하여 사용자가 쓴 표현과 문서의 표현 사이 차이를 줄이는 방법이다. 다국어·전문용어·동음이의어에는 단순 사전 덧붙이기가 틀린 뜻을 가져올 수 있다.

추가어를 OR로 쓰면 결과 집합이 넓어질 수 있고 AND로 쓰면 줄어들 수 있다. 가중 벡터에서는 점수와 순위가 달라진다. 어떤 연산으로 확장했는지를 먼저 정해야 개선과 실패를 설명할 수 있다.

상위 문서를 믿는 가정 살펴보기

pseudo relevance feedback은 처음 검색 상위 k개를 관련으로 가정하고 그 문서에서 용어를 얻는다. 사용자가 관련하다고 직접 표시한 피드백과 다르다. 첫 순위가 잘못되면 그 오해가 확장어에 다시 들어간다.

예를 들어 프로그래밍 Java를 찾는데 여행 문서가 상위에 많으면 섬·여행 용어가 늘어 query drift가 생길 수 있다. 이는 자체 가상 상황이다. 원질의 유지, 추가어 확인, 확장 가중치 제한과 실패 시 되돌림을 설계할 수 있다.

더 많이 찾음과 더 정확함을 나누기

관련 집합 G와 검색 집합 S에 대해 precision=|S∩G|/|S|, recall=|S∩G|/|G|다. 분모가 0인 경우에는 평가 규칙이 따로 필요하다. 아래 표는 두 분모가 모두 양수다.

확장으로 recall이 올라가면서 precision이 내려갈 수 있다. 모든 새 문서를 확인할 부담도 늘어난다. 하나의 가상 질의 분수로 일반 품질을 주장하지 말고 여러 의도·언어·표본에서 실패 사례도 비교해야 한다.

중간 과정을 따라가는 예제

관련 문서는 총 6개다. 원검색은 4개 중 관련 3개, OR 확장은 8개 중 관련 4개를 찾았다. 관련 판정은 고정이며 확장 결과는 원결과를 포함한다.

  1. 원검색 precision=3/4=0.75, recall=3/6=0.5다.

  2. 확장은 precision=4/8=0.5, recall=4/6=2/3다.

  3. 새로 추가된 4개 중 관련은 1개, 비관련은 3개다. recall 증가는 precision 하락과 함께 나타났다.

이 표에서 recall은 1/2→2/3, precision은 3/4→1/2다. 더 나아졌는지는 사용 목적에 달려 있다.

종이와 본문으로 직접 해보기

확장에서 더한 문서 4개가 모두 비관련이면 최종 두 지표는?

힌트 보기

원래 관련 3개는 유지하고 전체 결과 수만 8로 늘린다.

풀이 보기

precision=3/8=0.375, recall=3/6=0.5다. 이 변경 표는 recall 이득 없이 확인 부담만 늘렸다.

오해와 반례

상위 결과에서 가져온 확장어는 사용자의 의도와 같다.

pseudo 피드백은 상위 문서 관련성을 가정한다. 동음이의어나 편향된 초기 결과가 잘못된 확장과 query drift를 만들 수 있다.

자기점검

OR 확장은 반드시 precision을 높이는가?

답과 이유 보기

아니다.

새 비관련 문서가 많으면 내려간다.

예제의 추가 관련 문서는 몇 개인가?

답과 이유 보기

1개다.

확장 관련 4에서 원관련 3을 뺀다.

직접 판정과 pseudo 판정의 차이는?

답과 이유 보기

pseudo는 상위 순위를 관련으로 가정한다.

사용자가 실제 관련성을 표시했다는 근거와 다르다.

한 단계 더

원질의와 확장어를 함께 보여주는 검색 화면의 되돌림 규칙을 종이로 설계하자. 실제 검색 시스템 성능·학생 실험은 미수행이다.
